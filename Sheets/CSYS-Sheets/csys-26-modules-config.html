CSS Modules — Config & Tooling

css-loader modules · localIdentName · camelCase · Vite cssModules · PostCSS interop

Tooling Configuration

// ── webpack — css-loader config ──────────────────────────
module.exports = {
  module: {
    rules: [{
      test: /\.module\.css$/,
      use: ['style-loader', {
        loader: 'css-loader',
        options: {
          modules: {
            localIdentName: '[name]__[local]--[hash:base64:5]',
            // dev:  'Button__primary--a1b2c'
            // prod: '[hash:base64:8]' for smaller output
            exportLocalsConvention: 'camelCaseOnly',
            // 'camelCaseOnly' → styles.myButton (not styles['my-button'])
            mode: 'local', // 'global' | 'pure'
          },
        },
      }],
    }],
  },
}

// ── Vite ─────────────────────────────────────────────────
// vite.config.js
export default {
  css: {
    modules: {
      localsConvention: 'camelCaseOnly',
      generateScopedName: '[name]_[local]_[hash:5]',
      // In dev: descriptive; in prod: short hash
    },
  },
}

// ── Next.js ───────────────────────────────────────────────
// Built-in — no config needed; .module.css auto-scoped

// ── TypeScript typings ─────────────────────────────────────
// tsconfig.json — enable path alias for type generation
// Use: css-modules-typescript-loader or
//      typed-css-modules (tcm) CLI

// global.d.ts — manual declaration fallback
declare module '*.module.css' {
  const classes: Record<string, string>
  export default classes
}
declare module '*.module.scss' {
  const classes: Record<string, string>
  export default classes
}

Config Explained

localIdentName — controls the generated class name format
[name] — source filename without extension
[local] — original class name from CSS
[hash:base64:5] — 5-char content hash for uniqueness
exportLocalsConvention: 'camelCaseOnly' — only camelCase keys in JS export
mode: 'local' — all classes local (default); pure disallows :global
localsConvention — Vite equivalent of exportLocalsConvention
Record<string, string> — TypeScript type for the styles object

localIdentName Tokens

TokenExpands to
[name]Source filename (no ext)
[local]Original class name
[path]Relative file path
[folder]Containing folder name
[hash:base64:N]N-char content hash
[contenthash:N]File content hash

⚠ Common Mistakes

  • Using short hashes in development — hard to debug; use descriptive names in dev, short hashes only in production
  • Not configuring exportLocalsConvention — kebab-case classes need bracket access; camelCaseOnly is cleaner
  • Using mode: 'pure' and then needing :global — pure mode disallows global selectors; use local instead

✓ Tips

  • Use [name]__[local]--[hash:5] in dev for BEM-style readable class names with uniqueness guarantee
  • Run tcm src --watch alongside dev server to keep TypeScript types in sync with CSS changes
  • Pair CSS Modules with PostCSS plugins — they run before the scoping transformation

Summary

  • localIdentName — controls generated class name format
  • camelCaseOnly — dot-notation access in JS (styles.myClass)
  • Most modern tools (Vite, Next.js) support CSS Modules with zero config
  • tcm CLI — generate TypeScript types for CSS Module class names
