Tailwind CSS — Setup & Config

tailwind.config.js · @tailwind · content · theme · plugins

What Is Tailwind CSS?

Tailwind CSS is a utility-first CSS framework that generates a large set of single-purpose classes — flex, pt-4, text-center — that you compose directly in HTML. Unlike component frameworks, Tailwind ships no pre-built UI; it provides low-level primitives. At build time, PurgeCSS / content scanning removes unused classes so the final bundle is tiny. Tailwind v3+ uses a JIT (Just-In-Time) engine that generates styles on demand.

Key Facts

  • Current stable: Tailwind CSS v3 (v4 alpha uses CSS-first config)
  • @tailwind base injects Preflight (normalize reset)
  • @tailwind components layer for reusable component classes
  • @tailwind utilities injects all utility classes
  • JIT engine enabled by default in v3 — no mode: 'jit' needed
  • CDN Play CDN for prototyping only — not for production

Installation & Config

# 1. Install
npm install -D tailwindcss postcss autoprefixer
npx tailwindcss init -p          # creates tailwind.config.js + postcss.config.js

# 2. tailwind.config.js
module.exports = {
  content: [
    './src/**/*.{html,js,jsx,ts,tsx,vue}',
    './public/index.html',
  ],
  theme: {
    extend: {
      colors: { brand: '#5c6bc0' },
      spacing: { '18': '4.5rem' },
      fontFamily: { sans: ['Inter', 'sans-serif'] },
    },
  },
  plugins: [],
}

# 3. CSS entry file (e.g. src/input.css)
@tailwind base;
@tailwind components;
@tailwind utilities;

# 4. Build
npx tailwindcss -i src/input.css -o dist/output.css --watch

# CDN (prototyping only)
<script src="https://cdn.tailwindcss.com"></script>

Config Explained

content — glob patterns Tailwind scans to find used class names; unused classes are purged
theme.extend — add to defaults; use bare theme to completely replace defaults
colors — custom color tokens accessible as bg-brand, text-brand
spacing — extends the spacing scale; '18' → p-18, m-18
fontFamily.sans — overrides the default sans stack
plugins — array of Tailwind plugin functions for custom utilities
-i / -o — input / output paths for the CLI build
--watch — rebuilds on file change during development

⚠ Common Mistakes

  • Missing file patterns in content — classes used but not scanned get purged in production builds
  • Using theme instead of theme.extend — replaces entire default scale rather than merging
  • Forgetting postcss.config.js — Tailwind won't process without PostCSS pipeline configured
  • Dynamically constructing class names (e.g. `text-${color}`) — JIT can't scan these; use safelist instead

✓ Tips

  • Use safelist in config for dynamically built class names that can't be statically scanned
  • Run npx tailwindcss init --full to see every default config value
  • Use @apply sparingly — only for truly reusable component patterns, not one-off styles
  • The Tailwind CSS IntelliSense VS Code extension provides autocomplete and hover previews

Summary

  • content — globs telling Tailwind which files to scan for class names
  • theme.extend — add tokens without replacing defaults
  • @tailwind base/components/utilities — three required CSS directives
  • npx tailwindcss -i … -o … --watch — dev build command
