Nesting & BEM Patterns

// Basic nesting
.nav {
  display: flex;
  gap: 1rem;

  a {                          // generates .nav a
    color: inherit;
    text-decoration: none;
  }

  &:hover { opacity: 0.8; }   // generates .nav:hover
}

// BEM with &
.card {
  padding: 1.5rem;
  border-radius: 8px;

  // Elements
  &__title {                   // generates .card__title
    font-size: 1.25rem;
    font-weight: 600;
  }
  &__body { color: #64748b; }
  &__footer { border-top: 1px solid #e2e8f0; }

  // Modifiers
  &--featured {                // generates .card--featured
    border: 2px solid #6366f1;
  }
  &--compact {
    padding: 0.75rem;
  }
}

// Responsive inside component
.hero {
  font-size: 3rem;

  @media (max-width: 640px) {   // generates @media inside .hero
    font-size: 2rem;
  }
}

// @at-root — escape nesting to top level
.theme-dark {
  .card {
    @at-root .card { background: #1e293b; }  // .card (not .theme-dark .card)
  }
}

// Deep selectors (avoid overuse)
.sidebar {
  > ul > li > a { color: #334155; }    // direct children chain
  ~ .content { margin-left: 1rem; }    // sibling combinator
}

Nesting Explained

a {} inside a rule — generates descendant selector
& — substituted with the full parent selector string
&:hover → .card:hover
&__title → .card__title (BEM element)
&--featured → .card--featured (BEM modifier)
@media inside rule — Sass bubbles it up to a top-level media query
@at-root — emits rule at stylesheet root, escaping parent nesting
& .child → .parent .child — child via space
& + & → .item + .item — adjacent sibling

Parent Selector Patterns

SassCSS output
.a { &:hover }.a:hover
.a { &__b }.a__b
.a { &--b }.a--b
.a { .b & }.b .a (reversed)
.a { &-b }.a-b
.a { & + & }.a + .a
.a { &::before }.a::before

BEM with Sass

BEM rolePattern
Block.card { }
Element&__title { } → .card__title
Modifier&--featured { } → .card--featured

State modifier&.is-active { } → .card.is-active

Nesting Best Practices

RuleReason
Max 3 levels deepDeeper = high specificity, hard to override
Use & for pseudo/modifierClear intent; doesn't add specificity
Nest @media inside ruleKeeps component styles together
Avoid tag selectors in nestsCreates fragile selector chains
BEM reduces need for nestingFlat selectors with clear hierarchy

⚠ Common Mistakes

  • Nesting more than 3-4 levels — generates highly specific selectors that are nearly impossible to override
  • Using &__elem inside another BEM element — generates .block__elem1__elem2, which is invalid BEM
  • Nesting unrelated styles together — nesting is for related states/elements only; unrelated components should be separate rules

✓ Tips

  • Keep BEM element classes at the top level in Sass for searchability — don't hide .card__title three levels deep
  • Use .b & {} (reversed parent) for context-dependent overrides like .theme-dark .card
  • Use @at-root with BEM when you need a modifier at the block level but you're inside an element rule

Summary

  • & — parent selector; enables BEM, pseudo-classes, modifiers
  • &__elem / &--mod — BEM elements and modifiers via concatenation
  • @media inside rule — keeps responsive styles co-located with component
  • @at-root — emit selector at stylesheet root, escaping nesting
