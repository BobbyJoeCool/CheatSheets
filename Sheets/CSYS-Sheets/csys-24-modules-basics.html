CSS Modules — Basics & Scoping

styles.className · :local · :global · camelCase · composes · Vite/webpack loader

What Are CSS Modules?

CSS Modules are CSS files where all class names are locally scoped by default. When imported into JavaScript, each class name is transformed to a unique, hashed identifier — eliminating naming collisions globally. The output is plain CSS — no runtime cost. CSS Modules work with any CSS syntax and are supported out-of-the-box by Vite, Next.js, and webpack with css-loader.

Key Facts

  • File naming: Component.module.css (the .module signals the loader)
  • Classes become camelCase JS object properties
  • All selectors local by default; use :global() for exceptions
  • Zero runtime — styles extracted to CSS file at build time
  • Works with Sass: Component.module.scss
  • Vite and Next.js support out of the box — no config needed

Explained

Component.module.css — the .module signals the bundler to scope this file
import styles from './…' — styles is an object mapping class names to hashed strings
styles.button — resolves to a unique class like Button_button__a1b2c
:global() — exempts a selector from local scoping
composes: button — applies all of another local class's rules
composes: … from './other.module.css' — compose across files
clsx(styles.a, {"{[styles.b]: condition}"}) — conditional class joining utility

CSS Modules in Practice

/* Button.module.css */
.button {
  padding: 0.5rem 1rem;
  border-radius: 6px;
  border: none;
  cursor: pointer;
}

.primary {
  background: #6366f1;
  color: white;
}

.primary:hover {
  background: #4f46e5;
}

/* Escape to global scope */
:global(.third-party-class) {
  color: red;
}

/* Compose from another module */
.icon-button {
  composes: button;          /* local compose */
  display: inline-flex;
  align-items: center;
  gap: 0.5rem;
}

/* camelCase recommended for JS access */
.submitButton {
  composes: button primary;
  font-weight: 600;
}
// Button.jsx
import styles from './Button.module.css'

function Button({ primary, children }) {
  return (
    <button className={`${styles.button} ${primary ? styles.primary : ''}`}>
      {children}
    </button>
  )
}

// With clsx / classnames library (recommended)
import clsx from 'clsx'
<button className={clsx(styles.button, { [styles.primary]: primary })}>

⚠ Common Mistakes

  • Using kebab-case class names — they become styles['my-class'] not styles.myClass; prefer camelCase
  • Applying global overrides without :global() — local scoping will hash third-party class names, breaking them
  • Forgetting .module.css extension — regular .css files are global; only .module.css is scoped

✓ Tips

  • Use clsx or classnames library to cleanly combine conditional module classes
  • TypeScript: use typed-css-modules or css-modules-typescript-loader for autocomplete on class names
  • Use composes to share base styles without duplication — avoids the need for a shared utility class file

Summary

  • Component.module.css — scoped CSS; all classes are local by default
  • import styles from './…' — styles is a map of name → hashed class
  • :global() — opt out of scoping for third-party selectors
  • composes: otherClass — inherit styles from another local class
