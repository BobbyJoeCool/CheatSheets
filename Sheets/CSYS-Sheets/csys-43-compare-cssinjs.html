CSS-in-JS Comparison

styled-components vs Emotion vs Vanilla Extract vs CSS Modules · runtime vs zero-runtime

CSS-in-JS Ecosystem

CSS-in-JS approaches range from runtime solutions (styled-components, Emotion) that inject styles dynamically to zero-runtime solutions (Vanilla Extract, Linaria) that extract CSS at build time. CSS Modules occupy a middle ground — scoped CSS at build time with no runtime overhead. The right choice depends on your performance requirements, SSR needs, and how tightly you want styles coupled to component logic.

Quick Verdict

  • Styled Components / Emotion — best DX; runtime cost; great for component libraries
  • Vanilla Extract / Linaria — zero runtime; TypeScript-first; build-time extraction
  • CSS Modules — zero runtime; no JS coupling; works with any CSS syntax
  • RSC (React Server Components) favors zero-runtime or CSS Modules

⚠ Common Mistakes

  • Choosing runtime CSS-in-JS for SSR without ServerStyleSheet/streaming setup — causes flash of unstyled content
  • Vanilla Extract: trying to use runtime values (component props) directly — VE is build-time only; use CSS custom properties for dynamic values
  • CSS Modules: importing without the .module.css extension — regular .css files are global; the .module suffix is required for scoping

✓ Tips

  • For new React projects leaning toward RSC, prefer CSS Modules or Vanilla Extract — they have no runtime overhead
  • Emotion offers a smaller bundle and marginally better performance than styled-components — meaningful at scale
  • Panda CSS and StyleX (Meta) are emerging zero-runtime alternatives worth evaluating for large projects

Summary

  • Runtime (SC/Emotion) — best DX, dynamic props, theming; pay runtime cost
  • Zero-runtime (VE/Linaria) — build-time extraction; TypeScript types; no runtime
  • CSS Modules — simplest migration; scoped classes; works with any CSS
  • Choose based on: SSR needs, TypeScript requirements, and bundle size budget
