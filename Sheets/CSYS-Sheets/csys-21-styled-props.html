Props-Driven Styles

import styled, { css } from 'styled-components'

// Inline prop interpolation
const Button = styled.button`
  background: ${props => props.$primary ? '#6366f1' : '#e2e8f0'};
  color: ${props => props.$primary ? 'white' : '#1e293b'};
  padding: ${props => props.$size === 'lg' ? '0.75rem 1.5rem' : '0.5rem 1rem'};
  border-radius: 6px;
  border: none;
`

// Conditional css block (preferred for complex conditions)
const Card = styled.div`
  padding: 1.5rem;
  border-radius: 8px;
  ${props => props.$elevated && css`
    box-shadow: 0 4px 20px rgba(0,0,0,0.12);
    border: none;
  `}
  ${props => props.$variant === 'outlined' && css`
    border: 2px solid #e2e8f0;
    box-shadow: none;
  `}
`

// .attrs() — default HTML attributes + default props
const Input = styled.input.attrs(props => ({
  type: props.type || 'text',
  placeholder: props.placeholder || 'Enter value…',
}))`
  border: 1px solid #cbd5e1;
  border-radius: 4px;
  padding: 0.5rem 0.75rem;
  outline: none;
  &:focus { border-color: #6366f1; box-shadow: 0 0 0 3px rgba(99,102,241,0.2); }
`

// shouldForwardProp — prevent custom props reaching DOM
const Box = styled.div.withConfig({
  shouldForwardProp: prop => !['$gap', '$stack'].includes(prop)
})`
  display: flex;
  flex-direction: ${p => p.$stack ? 'column' : 'row'};
  gap: ${p => p.$gap ?? '1rem'};
`

// Usage
<Button $primary $size="lg">Save</Button>
<Card $elevated $variant="outlined">Content</Card>
<Box $stack $gap="0.5rem">Items</Box>

Explained

${"{props => …}"} — interpolate any value derived from props
$primary — transient prop ($ prefix) — not forwarded to DOM in v6+
props.$primary — access transient prop in interpolation
css`…` — tag needed when interpolation is inside a conditional block
.attrs(fn) — merge computed HTML attributes / default props
shouldForwardProp — return false to block a prop from reaching DOM
$gap ?? '1rem' — nullish coalescing for prop default values

⚠ Common Mistakes

  • Passing custom props without $ prefix — they reach the DOM, causing React unknown-prop warnings
  • Omitting css`…` when conditionally returning multi-line CSS blocks — interpolation breaks without the tag
  • Using .attrs() for styling — attrs sets HTML attributes only; style goes in the template literal

✓ Tips

  • Use object lookup for variants: const sizes = {"{sm:'0.5rem', lg:'1rem'}"}; padding: ${"{p => sizes[p.$size]}"}
  • Reference another styled component as a selector: ${"{Icon}"} { color: red } inside another component's styles
  • Use .attrs() to avoid repetitive prop-passing: set default type, role, or aria-* attributes

Summary

  • ${"{p => p.$var}"} — prop interpolation in template literal
  • $propName — transient prop; not forwarded to DOM element
  • css`…` — required tag when returning multi-property conditional blocks
  • .attrs(fn) — merge default or computed HTML attributes
