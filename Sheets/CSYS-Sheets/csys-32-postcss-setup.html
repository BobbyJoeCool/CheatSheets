PostCSS — Setup & Config

postcss.config.js · plugins array · CLI · autoprefixer · postcss-preset-env · Vite

What Is PostCSS?

PostCSS is a tool for transforming CSS with JavaScript plugins. Unlike Sass, it is not a preprocessor — it processes valid (or near-valid) CSS through a plugin pipeline. Each plugin reads the CSS AST, transforms it, and passes it on. Common use cases include autoprefixing, future CSS syntax polyfills, linting, minification, and custom transformations. Tailwind CSS and CSS Modules both run through PostCSS.

Key Facts

  • Install: npm install -D postcss postcss-cli
  • Config file: postcss.config.js or postcss.config.cjs
  • Vite, webpack (postcss-loader), and Parcel use PostCSS automatically
  • Plugins run in array order — sequence matters
  • PostCSS itself doesn't transform anything — plugins do all the work
  • autoprefixer is the most-used plugin; used internally by many frameworks

Setup & Config

// Install
// npm install -D postcss postcss-cli autoprefixer postcss-preset-env cssnano

// postcss.config.js
module.exports = {
  plugins: [
    require('postcss-import'),           // resolve @import at build time
    require('postcss-preset-env')({      // future CSS → current CSS
      stage: 2,                          // 0=experimental 4=stable
      features: {
        'nesting-rules': true,           // enable CSS nesting polyfill
        'custom-media-queries': true,
        'color-function': true,
      },
    }),
    require('autoprefixer'),             // add vendor prefixes
    process.env.NODE_ENV === 'production'
      ? require('cssnano')({ preset: 'default' })
      : false,
  ],
}

// Vite — PostCSS config is auto-detected from postcss.config.js
// OR inline in vite.config.js:
import autoprefixer from 'autoprefixer'
export default {
  css: {
    postcss: {
      plugins: [autoprefixer()],
    },
  },
}

// CLI usage
// npx postcss src/main.css -o dist/main.css
// npx postcss src/main.css -o dist/main.css --watch

Config Explained

plugins — ordered array of PostCSS plugin instances
postcss-import — inlines @import statements at build time
postcss-preset-env — polyfills future CSS based on browserslist
stage — CSS spec stage (0 experimental → 4 stable)
autoprefixer — adds -webkit-, -moz- prefixes from browserslist
cssnano — minifies CSS output; run only in production
false in plugins array — PostCSS skips falsy entries (conditional plugins)
Vite auto-detects postcss.config.js in project root

⚠ Common Mistakes

  • Wrong plugin order — postcss-import must be first so other plugins see the fully-inlined CSS
  • Running cssnano in development — minification removes whitespace and makes debugging very hard
  • Missing browserslist config — autoprefixer and preset-env need a target browser list in package.json or .browserslistrc

✓ Tips

  • Add "browserslist": "> 0.5%, last 2 versions, not dead" to package.json to configure autoprefixer and preset-env together
  • Use stage: 2 for preset-env — a good balance of stability and future features
  • PostCSS plugins can be used alongside Sass — Sass compiles first, then PostCSS processes the output

Summary

  • postcss.config.js — array of plugins in processing order
  • autoprefixer — vendor prefixes based on browserslist
  • postcss-preset-env — future CSS syntax polyfills
  • cssnano — minification; production only
