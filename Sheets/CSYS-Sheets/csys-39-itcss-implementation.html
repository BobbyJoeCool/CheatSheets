ITCSS — Implementation Patterns

@layer · layer ordering · objects · components · BEM + ITCSS · main.scss import

ITCSS in Practice

// ── main.scss — import order is the layer order ──────────

// 1. Settings — variables only, no CSS output
@use '1-settings/colors';
@use '1-settings/spacing';
@use '1-settings/typography';

// 2. Tools — mixins/functions, no CSS output
@use '2-tools/mixins';
@use '2-tools/functions';

// 3. Generic — global resets
@use '3-generic/reset';
@use '3-generic/box-sizing';

// 4. Elements — bare HTML elements
@use '4-elements/headings';
@use '4-elements/links';
@use '4-elements/images';

// 5. Objects — abstract layout patterns (no visual styling)
@use '5-objects/media';        // .o-media { display:flex }
@use '5-objects/container';    // .o-container { max-width: }
@use '5-objects/grid';         // .o-grid { display:grid }

// 6. Components — designed UI pieces
@use '6-components/button';
@use '6-components/card';
@use '6-components/navbar';

// 7. Utilities — single-purpose overrides (highest specificity)
@use '7-utilities/visibility'; // .u-hidden { display:none !important }
@use '7-utilities/spacing';    // .u-mt-4 { margin-top: 1rem !important }
@use '7-utilities/text';       // .u-truncate { overflow:hidden ... }

// ── With native CSS @layer ────────────────────────────────
@layer settings, tools, generic, elements, objects, components, utilities;
// @layer order declared upfront; later declarations follow this order

Layer Rules

settings — Sass variables; zero CSS output; used by everything else
tools — mixins and functions; zero CSS output
generic — element selectors only; lowest specificity CSS
elements — styled bare HTML tags (h1, a, img)
objects — prefixed .o-; layout only, no visual styles
components — prefixed .c-; visual UI pieces
utilities — prefixed .u-; use !important intentionally
@layer declaration — upfront order declaration for native cascade layers

⚠ Common Mistakes

  • Adding visual styles (colors, fonts) to Object layer classes — objects are layout only; add a Component skin on top
  • Not declaring @layer order upfront — without the declaration, layers are ordered by first encounter which can be unpredictable
  • Using utility classes in HTML and then overriding them in components — utilities are terminal; if you need to override, move the style to a component

✓ Tips

  • Use native CSS @layer for the Objects/Components/Utilities split — it enforces the ordering at browser level, not just file order
  • Combine ITCSS with BEM — BEM names components within each layer; ITCSS controls where they live in the cascade
  • Keep the js- prefix strictly for JavaScript hooks — never style these classes

Summary

  • o- / c- / u- — namespace prefixes for Objects, Components, Utilities
  • Import order in main.scss defines cascade precedence
  • Objects: layout only; Components: visual UI; Utilities: overrides
  • Native @layer can enforce ITCSS ordering at the browser level
