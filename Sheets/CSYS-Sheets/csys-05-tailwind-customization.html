Tailwind CSS — Customization & Plugins

theme.extend · @layer · @apply · plugin() · arbitrary values · safelist

Customization Patterns

// tailwind.config.js — extending the theme
module.exports = {
  theme: {
    extend: {
      colors: {
        primary: { 50:'#eef2ff', 500:'#6366f1', 900:'#312e81' },
        brand: '#10b981',
      },
      spacing: { '128': '32rem', '144': '36rem' },
      borderRadius: { '4xl': '2rem' },
      screens: { '3xl': '1920px' },
      animation: { 'spin-slow': 'spin 3s linear infinite' },
    },
  },
  safelist: [
    'bg-red-500', 'bg-blue-500',      // always include
    { pattern: /bg-(red|blue)-\d00/ } // regex safelist
  ],
}

// CSS — custom layers and @apply
@layer components {
  .btn-primary {
    @apply px-4 py-2 bg-primary-500 text-white rounded-lg
           hover:bg-primary-600 focus:ring-2 focus:ring-primary-300;
  }
}

@layer utilities {
  .text-balance { text-wrap: balance; }
}

// Plugin — add custom utilities programmatically
const plugin = require('tailwindcss/plugin')
module.exports = {
  plugins: [
    plugin(function({ addUtilities, addComponents, theme }) {
      addUtilities({ '.rotate-y-180': { transform: 'rotateY(180deg)' } })
    }),
    require('@tailwindcss/typography'),
    require('@tailwindcss/forms'),
  ]
}

Explained

theme.extend.colors — adds tokens; primary-500 works as bg-primary-500
safelist — forces classes into output even if not found in content scan
pattern: /regex/ — safelist by regex for dynamic classes
@layer components — groups custom classes at component specificity
@apply — compose utilities into a CSS rule (use sparingly)
@layer utilities — adds custom utilities with same specificity as Tailwind's
addUtilities() — programmatically register utilities in a plugin
addComponents() — register component classes in a plugin
theme() — access config values inside plugin

⚠ Common Mistakes

  • Overusing @apply — defeats the purpose of utility-first; prefer component abstractions in JS frameworks
  • Forgetting underscores in arbitrary values with spaces — grid-cols-[1fr_2fr] not [1fr 2fr]
  • Not using safelist for runtime-generated classes — they won't appear in the production build

✓ Tips

  • Arbitrary properties: [grid-area:header] — any CSS property in square brackets
  • Use theme() inside CSS files to reference config values without duplicating them
  • Custom screens: add '3xl': '1920px' to get 3xl: breakpoint variant

Summary

  • theme.extend — merge new tokens with defaults
  • [arbitrary-value] — one-off CSS values in square brackets
  • @layer components + @apply — reusable patterns in CSS
  • safelist — force classes into output that can't be statically scanned
