ITCSS — Architecture & Layers

What Is ITCSS?

ITCSS (Inverted Triangle CSS) is a CSS architecture methodology by Harry Roberts. It organizes CSS into layers ordered by increasing specificity, from widest reach / lowest specificity (settings, tools) to narrowest reach / highest specificity (utilities). This prevents specificity conflicts and makes overrides predictable. ITCSS is a methodology, not a framework — it works with any preprocessor or plain CSS.

Core Principles

  • Specificity only ever increases down the triangle
  • Layer order = import order in your main CSS file
  • No selector is ever undone by a later selector at the same layer
  • Works with BEM, SMACSS, or any naming convention
  • Pairs naturally with Sass @use/@forward for file organization
  • Utilities layer (highest specificity) is intentionally last

The Seven Layers

#LayerContentsSpecificity
1SettingsVariables, tokens, configNone
2ToolsMixins, functionsNone
3GenericResets, normalize, box-sizingElement
4ElementsBare HTML element stylesElement
5ObjectsLayout patterns (media, pack, etc.)Class
6ComponentsUI components (card, nav, btn)Class
7UtilitiesHelper overrides (hidden, truncate)Class + !important

⚠ Common Mistakes

  • Putting component-specific overrides in the Objects layer — objects should be abstract layout patterns, not visual components
  • Writing high-specificity selectors in early layers — Settings and Tools produce no CSS; Generic and Elements should use only element selectors
  • Skipping layers — even if a layer has few rules, maintain the structure so future additions have a clear home

✓ Tips

  • Combine ITCSS layers with CSS @layer — native cascade layers enforce the ordering at the browser level
  • The Objects layer is for layout patterns only — no colors, no typography; those live in Components
  • Utilities should use !important — they represent intentional, final overrides that shouldn't be defeated by anything

Summary

  • 7 layers: settings → tools → generic → elements → objects → components → utilities
  • Specificity only increases downward — no layer undoes a previous layer
  • Objects = abstract layout; Components = visual UI; Utilities = override helpers
  • Import order in main.scss enforces the specificity triangle
