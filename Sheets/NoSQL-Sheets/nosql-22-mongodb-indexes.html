Index Types

An index is a sorted structure (a B-tree) that lets MongoDB find documents without scanning the collection. Beyond single-field and compound indexes, an index on an array field becomes multikey (one entry per element). Options shape what gets indexed: unique rejects duplicates, partial indexes only matching documents, TTL deletes documents after a time, and wildcard covers fields you can't list in advance.

Notes

  • _id always has a unique index
  • A compound index serves queries on its leading fields (prefixes)
  • The TTL monitor runs about every 60 seconds
  • hideIndex tests removal without dropping

Creating Each Kind

db.products.createIndex({ category: 1 })                    // single field
db.orders.createIndex({ customerId: 1, orderDate: -1 })      // compound
db.products.createIndex({ tags: 1 })                         // multikey (array)

db.customers.createIndex({ email: 1 }, { unique: true })
db.customers.createIndex({ email: 1 },                       // case-insensitive unique
  { unique: true, collation: { locale: "en", strength: 2 }, name: "email_ci" })

db.orders.createIndex({ orderDate: 1 },                      // partial
  { partialFilterExpression: { status: "pending" } })
db.sessions.createIndex({ lastSeen: 1 }, { expireAfterSeconds: 3600 })   // TTL
db.products.createIndex({ "attrs.$**": 1 })                  // wildcard
db.orders.createIndex({ customerId: "hashed" })              // hashed (sharding)
db.stores.createIndex({ location: "2dsphere" })              // geospatial

db.products.getIndexes()
db.products.hideIndex("category_1")
db.products.dropIndex("category_1")

Code Explained

1 and -1 set the sort direction; it matters only for compound sorts
The partial index holds only pending orders, so it's small and fast for that query
TTL deletes a session an hour after its lastSeen date
Default index names join fields and directions: customerId_1_orderDate_-1

SQL Equivalent

  • createIndex ↔ CREATE INDEX · unique ↔ UNIQUE · partial ↔ CREATE INDEX … WHERE
  • TTL has no SQL equivalent; the nearest is a scheduled DELETE · See SQL 71, 72

Across Engines

  • Redis no secondary indexes on keys; build them with sets / sorted sets or FT.CREATE
  • DynamoDB GSIs and LSIs (sheet 45); 20 GSIs per table by default
  • Cassandra SAI secondary indexes (5.0); otherwise a table per query
  • Neo4j range, text, point, full-text and vector indexes on label properties

In Your Code

  • Node await orders.createIndex({ customerId: 1, orderDate: -1 })
  • Python orders.create_index([("customerId", 1), ("orderDate", -1)])
  • Java orders.createIndex(compoundIndex(ascending("customerId"), descending("orderDate")))

⚠ Common Mistakes

  • One index per field instead of one compound index for the query
  • A unique index on a field many documents lack (use partial)
  • Expecting TTL deletes to happen at the exact second

✓ Tips & Best Practices

  • Name indexes explicitly when they carry options
  • Prefer partial over sparse indexes
  • Hide an index for a week before dropping it

Quick Summary
