Paths, Patterns & Aggregation

variable-length *1..3 · shortestPath · quantified path patterns · count · collect · WITH

Multi-Hop Questions

Patterns can chain many hops: "customers who bought what Ada bought" is one MATCH. Variable-length relationships (*1..3) and quantified path patterns ({1,3}) follow a relationship a range of times, and SHORTEST finds the shortest paths. Aggregation is implicit: any non-aggregated value in RETURN or WITH is a grouping key. WITH pipes results to the next part of the query, which also lets you filter after aggregating.

Notes

  • Always bound variable-length patterns (*1..3, not *)
  • collect() builds a list; UNWIND turns a list into rows
  • Quantified path patterns arrived in Neo4j 5.9
  • DISTINCT removes repeated rows from multiple paths

Hops, Paths & Aggregation

// customers who bought what Ada bought
MATCH (:Customer {id: 42})-[:PLACED]->(:Order)-[:CONTAINS]->(p:Product)
      <-[:CONTAINS]-(:Order)<-[:PLACED]-(other:Customer)
WHERE other.id <> 42
RETURN other.name, count(DISTINCT p) AS shared
ORDER BY shared DESC LIMIT 5;

// variable length: 1 to 3 hops
MATCH (a:Customer {id: 42})-[:FOLLOWS*1..3]->(b:Customer)
RETURN DISTINCT b.name;

// quantified path pattern
MATCH (a:Customer {id: 42}) ((x)-[:FOLLOWS]->(y)){1,3} (b:Customer)
RETURN DISTINCT b.name;

// shortest path
MATCH p = SHORTEST 1 (a:Customer {id: 42})-[:FOLLOWS]-+(b:Customer {id: 99})
RETURN length(p), [n IN nodes(p) | n.name];

// grouping: non-aggregated columns are the keys
MATCH (c:Customer)-[:PLACED]->(o:Order)
RETURN c.name, count(o) AS orders, sum(o.total) AS revenue,
       collect(o.id)[..5] AS firstIds;

// WITH: aggregate, then filter (like HAVING)
MATCH (p:Product)<-[r:CONTAINS]-(:Order)
WITH p, sum(r.qty) AS units
WHERE units > 100
RETURN p.name, units ORDER BY units DESC;

Code Explained

The pattern walks out from Ada to products and back to other customers in one statement
*1..3 and {1,3} both mean one to three hops; the quantified form can add conditions inside the group
-+ means one or more hops; SHORTEST 1 returns one shortest path
[n IN nodes(p) | n.name] is a list comprehension

SQL Equivalent

  • Multi-hop patterns ↔ chains of self joins, or a recursive CTE for variable depth
  • collect() ↔ array_agg · WITH … WHERE ↔ HAVING · See SQL 42, 29

Across Engines

  • MongoDB $graphLookup with maxDepth for recursive lookups
  • Redis none; walk sets in the app
  • DynamoDB adjacency lists: one hop per Query
  • Cassandra precompute relationships into tables

In Your Code

⚠ Common Mistakes

  • Unbounded * patterns that explore the whole graph
  • Counting paths when you meant distinct nodes
  • Expecting GROUP BY; grouping comes from the non-aggregated columns

✓ Tips & Best Practices

  • Start traversals from an indexed node
  • Use count(DISTINCT x) across multiple paths
  • Break long queries into WITH steps

Quick Summary

  • Multi-hop patterns in one MATCH
  • *1..3 / {1,3} — variable length
  • SHORTEST — shortest paths
  • Implicit grouping + WITH
