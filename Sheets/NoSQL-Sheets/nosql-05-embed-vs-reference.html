Sheet 05

Embedding vs Referencing

one-to-few · one-to-many · many-to-many · embed · reference · extended reference · document size

Together or Apart

Embed data inside its parent when it's read together, owned by the parent and bounded in size, such as a customer's two addresses. Reference it by id when it grows without limit, is shared by many parents or changes on its own, such as reviews. An extended reference copies just the few fields you display (a customer name on an order) next to the id. Record size limits set the hard ceiling: 16 MB per MongoDB document, 400 KB per DynamoDB item.

Notes

  • One-to-few: embed
  • One-to-many: embed ids, or reference from the child
  • One-to-millions: the child stores the parent's id
  • Many-to-many: arrays of ids, or a link collection

Production Check

  • An array that grows forever (reviews, events) slows every read and eventually hits the 16 MB limit. Move children to their own collection with the parent's id
  • Large documents rewrite and replicate more on each update; keep frequently updated documents small
  • Copied fields go stale; decide who updates the copies and when (sheet 58)

Embed, Reference, Extended Reference

// Embed: one-to-few, read with the parent, owned by it
db.customers.insertOne({
  _id: 42, name: "Ada Lovelace",
  addresses: [ { type: "ship", city: "Des Moines", country: "US" },
               { type: "bill", city: "Ames", country: "US" } ]
})

// Reference: one-to-many that grows; the child points at the parent
db.reviews.insertOne({ productId: 7, customerId: 42, stars: 5,
                       text: "Clear and short", createdAt: new Date() })
db.reviews.createIndex({ productId: 1, createdAt: -1 })

// Extended reference: copy only the fields you display
db.orders.insertOne({
  _id: 1001,
  customer: { id: 42, name: "Ada Lovelace" },
  items: [ { productId: 7, name: "SQL Pocket Guide", qty: 2, unitPrice: 19.99 },
           { productId: 3, name: "USB-C Cable", qty: 1, unitPrice: 9.99 } ]
})

// Many-to-many: arrays of ids on one side
db.products.updateOne({ _id: 7 }, { $addToSet: { categoryIds: 3 } })

Code Explained

Addresses never grow past a handful and are always shown with the customer
Reviews can number in the thousands, so each is its own document with an index on productId
unitPrice is copied on purpose: the order must keep the price paid, even if the product's price changes
The copied customer name may go stale; it's refreshed by whoever changes the name, or accepted as a snapshot

SQL Equivalent

  • Reference ↔ foreign key + JOIN; embed has no direct form (closest: a jsonb column)
  • Many-to-many ↔ a junction table · See SQL 56, 62

Across Engines

  • Redis embed as a JSON value or hash fields; reference with key names like customer:42
  • DynamoDB embed as map / list attributes (400 KB cap); reference with items under one partition key
  • Cassandra embed with collections or UDTs; reference by copying into query tables
  • Neo4j references are relationships; embedded values are properties

In Your Code

  • Node Mongoose: addresses: [addressSchema] vs customer: { type: ObjectId, ref: "Customer" } + .populate()
  • Python Beanie: addresses: list[Address] vs customer: Link[Customer]
  • Java Spring Data: List<Address> addresses vs @DocumentReference Customer customer

Rules of Thumb

RelationshipUsually
One-to-oneEmbed
One-to-fewEmbed
One-to-many (hundreds)Embed ids or reference
One-to-millionsChild stores parent id
Many-to-manyId arrays or link collection

Record Size Limits

EngineLimit
MongoDB16 MB per document
DynamoDB400 KB per item
Redis512 MB per string value
CassandraKeep partitions under ~100 MB
Neo4jNo record limit; keep properties small

⚠ Common Mistakes

  • Embedding a list that grows without bound
  • Referencing everything and then $lookup-ing on every read
  • Copying fields without deciding how they get updated

✓ Tips & Best Practices

  • Ask "is it read together?" and "does it grow?" first
  • Cap embedded arrays with $slice (subset pattern)
  • Copy values that should freeze in time, like prices on orders

Quick Summary

  • Embed — bounded, read together
  • Reference — grows or is shared
  • Extended reference — copy display fields
  • Watch the size limits
