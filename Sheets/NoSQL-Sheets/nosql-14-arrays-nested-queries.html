Sheet 14

Querying Arrays & Nested Fields

dot notation · $elemMatch · $all · $size · array index · positional projection

Reaching Inside Documents

Use dot notation ("address.city", always quoted) to query nested fields and array elements. A plain condition on an array matches if any element matches. For arrays of documents, separate conditions may be met by different elements; $elemMatch requires one element to meet them all. $all and $size test the array as a whole, and projection operators ($, $slice, $elemMatch) return part of an array.

Notes

  • Exact embedded-document matches compare field order too
  • Indexes on array fields are multikey (sheet 22)
  • "tags.0" addresses an element by position

Dot Notation, $elemMatch & Projections

db.customers.find({ "address.city": "Des Moines" })    // nested field
db.products.find({ tags: "sql" })                    // array contains value
db.products.find({ tags: { $all: ["sql", "reference"] } })
db.products.find({ tags: { $size: 2 } })
db.products.find({ "tags.0": "sql" })                // first element

// separate conditions: may match DIFFERENT elements
db.orders.find({ "items.productId": 7, "items.qty": { $gte: 2 } })

// $elemMatch: ONE element must match both
db.orders.find({ items: { $elemMatch: { productId: 7, qty: { $gte: 2 } } } })

// exact embedded document: same fields, same order
db.customers.find({ address: { city: "Ames", country: "US" } })

// return part of an array
db.orders.find({ "items.productId": 7 }, { "items.$": 1 })   // matched element
db.orders.find({}, { items: { $slice: 2 } })                // first 2
db.orders.find({}, { items: { $elemMatch: { qty: { $gte: 2 } } } })

Code Explained

{ tags: "sql" } matches any document whose tags array contains "sql"
Without $elemMatch, an order with product 7 (qty 1) and product 3 (qty 5) still matches
$slice: -2 would return the last two elements
items.$ needs the array in the filter to know which element matched

SQL Equivalent

  • Arrays are child tables in SQL: WHERE EXISTS (SELECT 1 FROM order_items i WHERE i.order_id = o.order_id AND i.product_id = 7 AND i.quantity >= 2)
  • PostgreSQL jsonb @> is the closest in-row form · See SQL 36, 78

Across Engines

  • Redis sets: SISMEMBER product:7:tags sql; RedisJSON paths like $.items[?(@.qty>1)]
  • DynamoDB nested paths items[0].qty in expressions; contains(tags, :t) in filters
  • Cassandra collection CONTAINS needs an index; frozen UDT fields
  • Neo4j list predicates: 'sql' IN p.tags, any(x IN list WHERE …)

In Your Code

  • Node find({ items: { $elemMatch: { productId: 7, qty: { $gte: 2 } } } })
  • Python find({"items": {"$elemMatch": {"productId": 7, "qty": {"$gte": 2}}}})
  • Java find(elemMatch("items", and(eq("productId", 7), gte("qty", 2))))

Array Query Operators

valueAny element equals it

Array Projections

ProjectionReturns
"arr.$": 1First element matched by the filter
{ $slice: n }First n (or last n if negative)
{ $slice: [skip, n] }n elements after skip
{ $elemMatch: … }First element meeting the condition

⚠ Common Mistakes

  • Expecting separate conditions on an array of documents to apply to one element
  • Forgetting quotes around dotted field names
  • Matching whole embedded documents when field order may differ

✓ Tips & Best Practices

  • Use $elemMatch whenever two conditions describe one array element
  • Query nested fields with dot notation, not whole subdocuments
  • Return only the matching array elements to save bandwidth

Quick Summary

  • Dot notation — nested fields
  • Value on array — any element
  • $elemMatch — one element, all conditions
  • $, $slice — partial arrays
