The Graph Model & Neo4j

nodes · relationships · labels · properties · Neo4j Desktop / Aura / Docker · Browser · shop data as a graph

Nodes, Relationships, Properties

A property graph has nodes (things), relationships (directed, typed connections) and properties (key-value data on both). Labels group nodes, such as :Customer or :Product. Relationships are stored as direct pointers, so following them costs the same however big the graph gets, which is where graphs beat joins. Neo4j runs as Aura (managed), Desktop or Docker, and you query it in Cypher from the Browser or a driver.

Notes

  • Neo4j 2025.06+ supports Cypher 25 (prefix a query with CYPHER 25)
  • Every relationship has exactly one type and a direction
  • Browser at port 7474, Bolt protocol on 7687
  • Community is GPLv3; Enterprise adds clustering and RBAC

Shop Data as a Graph

// docker run -p 7474:7474 -p 7687:7687 \
//   -e NEO4J_AUTH=neo4j/shop-pass-123 neo4j:latest
CREATE (ada:Customer {id: 42, name: "Ada Lovelace", city: "Des Moines"})
CREATE (book:Product {id: 7, name: "SQL Pocket Guide", price: 19.99, stock: 10})
CREATE (cable:Product {id: 3, name: "USB-C Cable", price: 9.99, stock: 120})
CREATE (books:Category {name: "Books"}), (elec:Category {name: "Electronics"})
CREATE (o:Order {id: 1001, date: date("2026-11-01"), status: "pending", total: 49.97})
CREATE (ada)-[:PLACED]->(o)
CREATE (o)-[:CONTAINS {qty: 2, unitPrice: 19.99}]->(book)
CREATE (o)-[:CONTAINS {qty: 1, unitPrice: 9.99}]->(cable)
CREATE (book)-[:IN_CATEGORY]->(books), (cable)-[:IN_CATEGORY]->(elec)
CREATE (ada)-[:REVIEWED {stars: 5}]->(book);

// look at what you built
MATCH (c:Customer {id: 42})-[r]->(n) RETURN c, r, n;
CALL db.schema.visualization();

Code Explained

Variables (ada, book) name nodes within one statement
The order_items table becomes CONTAINS relationships carrying qty and unitPrice
Categories become nodes, so "products in Books" is a short traversal
db.schema.visualization() draws labels and relationship types

SQL Equivalent

  • Node ↔ row · label ↔ table · relationship ↔ a foreign key or junction row, stored as a pointer
  • Relationship properties ↔ columns on a junction table (order_items.quantity) · See SQL 62

Across Engines

  • MongoDB references plus $graphLookup for recursive walks
  • Redis no graph engine in Redis Open Source 8
  • DynamoDB adjacency-list pattern (sheet 46); Neptune is AWS's graph database
  • Cassandra no traversals; copy relationships into query tables

In Your Code

  • Node const driver = neo4j.driver("neo4j://localhost:7687", neo4j.auth.basic("neo4j", pw))
  • Python driver = GraphDatabase.driver("neo4j://localhost:7687", auth=("neo4j", pw))
  • Java Driver driver = GraphDatabase.driver(uri, AuthTokens.basic("neo4j", pw));

⚠ Common Mistakes

  • Modeling everything as properties and nothing as relationships
  • Generic relationship types like :RELATED_TO
  • Running CREATE twice and getting duplicate nodes (use MERGE, sheet 53)

✓ Tips & Best Practices

  • Name relationships as verbs in UPPER_SNAKE_CASE
  • Name labels in PascalCase, singular
  • Sketch the graph on paper from your questions first

Quick Summary

  • Nodes + relationships + properties
  • Labels group nodes
  • Traversals instead of joins
  • Cypher from Browser or drivers
