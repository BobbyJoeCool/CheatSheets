Sheet 19

$lookup & $unwind

$lookup · pipeline $lookup · $unwind · preserveNullAndEmptyArrays · joins vs embedding

Joins When You Need Them

$lookup brings in matching documents from another collection as an array field, a left outer join. $unwind turns one document with an array into one document per element. Together they rebuild joined rows. The pipeline form of $lookup adds filters, sorting and limits inside the join. Use joins for occasional or reporting queries; if every read needs one, the data probably belongs embedded.

Notes

  • $lookup always returns an array (empty if no match)
  • $unwind drops documents with empty arrays unless told otherwise
  • from must be in the same database
  • Sharded from collections are supported since 5.1

Production Check

  • $lookup without an index on foreignField scans the other collection once per input document; index the foreign field
  • Joins multiply work on big inputs; $match and $limit before the $lookup
  • If every request needs the same $lookup, embed or copy the fields instead (sheet 05)

$lookup and $unwind

// orders → customers
db.orders.aggregate([
  { $match: { status: "pending" } },
  { $lookup: { from: "customers", localField: "customerId",
               foreignField: "_id", as: "customer" } },
  { $unwind: "$customer" },                       // [ {…} ] → {…}
  { $project: { total: 1, "customer.name": 1, "customer.email": 1 } }
])

// add product names to each order line
db.orders.aggregate([
  { $match: { _id: 1001 } },
  { $unwind: "$items" },
  { $lookup: { from: "products", localField: "items.productId",
               foreignField: "_id", as: "product" } },
  { $set: { "items.name": { $first: "$product.name" } } },
  { $group: { _id: "$_id", items: { $push: "$items" } } }
])

// pipeline form: each customer's 3 newest orders
db.customers.aggregate([
  { $lookup: { from: "orders", localField: "_id", foreignField: "customerId",
               as: "recent",
               pipeline: [ { $sort: { orderDate: -1 } }, { $limit: 3 },
                           { $project: { total: 1, orderDate: 1 } } ] } }
])

// keep orders whose customer is missing
{ $unwind: { path: "$customer", preserveNullAndEmptyArrays: true } }

Code Explained

as names the new array field
Unwinding, looking up and regrouping enriches every line of an order
Inside the lookup pipeline, stages run against the orders collection
preserveNullAndEmptyArrays keeps documents that found no match, like an outer join

SQL Equivalent

  • $lookup ↔ LEFT OUTER JOIN (always left) · $unwind ↔ one row per child
  • Pipeline $lookup with $limit ↔ LATERAL join · See SQL 33, 37

Across Engines

  • Redis no joins: fetch both keys (pipelined) and combine in the app
  • DynamoDB no joins: store related items under one partition key and Query once
  • Cassandra no joins: copy data into a table per query
  • Neo4j joins are traversals: MATCH (c:Customer)-[:PLACED]->(o:Order)

In Your Code

  • Node { $lookup: { from: "customers", localField: "customerId", foreignField: "_id", as: "customer" } } or Mongoose .populate()
  • Python {"$lookup": {"from": "customers", "localField": "customerId", "foreignField": "_id", "as": "customer"}}
  • Java lookup("customers", "customerId", "_id", "customer")

⚠ Common Mistakes

  • No index on the foreign field
  • Running $lookup before $match
  • Unwinding large arrays and regrouping when a projection would do

✓ Tips & Best Practices

  • Index every foreignField you join on
  • Prefer embedding for data read together on every request
  • Use the pipeline form to cap joined arrays

Quick Summary

  • $lookup — left join into an array
  • $unwind — one doc per element
  • Index the foreign field
  • Frequent joins → embed
