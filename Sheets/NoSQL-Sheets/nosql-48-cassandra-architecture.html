Cassandra Architecture

ring · partitioner · replication factor · consistency levels · gossip · cqlsh · Docker

A Ring of Equal Nodes

Cassandra spreads data over a ring of equal nodes with no primary. The partition key is hashed (Murmur3) to a token, which decides which nodes own the row, and each row is copied to replication factor (RF) nodes. Any node can coordinate a request, and the consistency level says how many replicas must answer. Writes go to a commit log and an in-memory table, later flushed to immutable SSTables that compaction merges, which is why writes are fast.

Notes

  • Nodes share cluster state by gossip
  • Datacenters are groups of nodes; replication is set per datacenter
  • This set uses Cassandra 5.0
  • Amazon Keyspaces and Astra offer managed CQL

Run, Inspect and Create the Shop Keyspace

docker run -d --name cass1 -p 9042:9042 cassandra:5.0
docker exec -it cass1 nodetool status        # UN = Up / Normal
docker exec -it cass1 cqlsh

cqlsh> CREATE KEYSPACE shop WITH replication =
         { 'class': 'NetworkTopologyStrategy', 'datacenter1': 1 };   -- 3 in production
cqlsh> USE shop;
cqlsh:shop> CREATE TABLE orders_by_customer (
              customer_id int, order_date date, order_id int,
              status text, total decimal,
              PRIMARY KEY ((customer_id), order_date, order_id)
            ) WITH CLUSTERING ORDER BY (order_date DESC, order_id DESC);
cqlsh:shop> INSERT INTO orders_by_customer
              (customer_id, order_date, order_id, status, total)
              VALUES (42, '2026-11-01', 1001, 'pending', 49.97);
cqlsh:shop> CONSISTENCY QUORUM;
cqlsh:shop> SELECT * FROM orders_by_customer WHERE customer_id = 42 LIMIT 10;
cqlsh:shop> TRACING ON;

Code Explained

nodetool status lists nodes, their load and token ownership
With one node, RF must be 1; production clusters use 3 per datacenter
All of customer 42's orders live in one partition, sorted newest first
TRACING ON shows which replicas served the next query and how long each step took

SQL Equivalent

  • Keyspace ↔ database · table ↔ table, but rows are spread across servers by partition key
  • No joins, no foreign keys, limited WHERE · See SQL 60

Across Engines

  • MongoDB replica sets with one primary, unlike Cassandra's masterless ring
  • Redis Cluster hash slots are a simpler cousin of token ranges
  • DynamoDB same partition + sort key idea, fully managed
  • Neo4j clustered primaries and secondaries; not partitioned by key

In Your Code

  • Node new cassandra.Client({ contactPoints: ["127.0.0.1"], localDataCenter: "datacenter1", keyspace: "shop" })
  • Python session = Cluster(["127.0.0.1"]).connect("shop")
  • Java CqlSession.builder().withLocalDatacenter("datacenter1").withKeyspace("shop").build()

Write & Read Path

StepWhat happens
WriteCommit log + memtable, then ack
FlushMemtable → immutable SSTable
CompactionMerge SSTables, drop old data
ReadMemtable + SSTables, merged by timestamp
Bloom filtersSkip SSTables without the key

⚠ Common Mistakes

  • RF 3 on a single dev node, so QUORUM queries fail
  • Treating CQL as SQL and expecting joins
  • Running Cassandra with too little heap on a laptop

✓ Tips & Best Practices

  • Use NetworkTopologyStrategy even with one datacenter
  • Set localDataCenter in drivers
  • Use Docker or Astra for learning

Quick Summary

  • Masterless ring
  • Partition key → token → nodes
  • Replication factor per datacenter
  • Fast writes, compaction later
