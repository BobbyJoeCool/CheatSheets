Sheet 15

Updating Documents

updateOne · updateMany · $set · $inc · $unset · $push / $pull · $[] / $[elem]

Change Fields, Not Whole Documents

updateOne(filter, update, options) changes the first matching document and updateMany changes every match. The update document is built from operators: $set writes fields, $inc adds to numbers, $unset removes fields, and $push / $pull edit arrays, so only the named fields change. A change to one document is atomic, including all of its nested fields and arrays. The positional operators reach into arrays: $ for the element the filter matched, $[] for every element and $[name] with arrayFilters for the ones that match a condition.

Notes

  • An update without operators is rejected; use replaceOne to swap the whole document (sheet 16)
  • $set creates missing fields and nested paths ("shipping.carrier")
  • An aggregation pipeline [ { $set: … } ] can compute from other fields

Production Check

  • updateMany isn't all-or-nothing: a failure partway leaves some documents changed. Wrap it in a transaction (sheet 27) when that matters
  • $inc and $push double-apply if your code retries after a timeout; retryable writes cover driver retries, but app-level retries need an idempotency check
  • Filter on indexed fields: an unindexed updateMany scans the whole collection

Field, Array & Positional Updates

// $set and $currentDate on one order
db.orders.updateOne(
  { _id: 1001 },
  { $set: { status: "shipped", "shipping.carrier": "UPS" },
    $currentDate: { updatedAt: true } }
)
// { acknowledged: true, matchedCount: 1, modifiedCount: 1, ... }
db.products.updateOne({ _id: 7 }, { $inc: { stock: -2 } })

// arrays: add a line item, tag once, remove a line
db.orders.updateOne({ _id: 1001 }, {
  $push: { items: { productId: 7, qty: 2, unitPrice: 19.99 } },
  $addToSet: { tags: "gift" }
})
db.orders.updateOne({ _id: 1001 }, { $pull: { items: { productId: 3 } } })

// positional: the matched element, then filtered elements
db.orders.updateOne(
  { _id: 1001, "items.productId": 7 },
  { $set: { "items.$.qty": 3 } }
)
db.orders.updateMany(
  { status: "pending" },
  { $set: { "items.$[big].backordered": true } },
  { arrayFilters: [ { "big.qty": { $gt: 5 } } ] }
)

In Your Code

  • Node await orders.updateOne({ _id: 1001 }, { $set: { status: "shipped" } })
  • Python orders.update_one({"_id": 1001}, {"$set": {"status": "shipped"}})
  • Java orders.updateOne(eq("_id", 1001), set("status", "shipped"))

Code Explained

Several operators can share one update as long as they touch different fields
matchedCount is how many matched the filter; modifiedCount is how many actually changed (setting a value to itself counts as matched only)
$addToSet adds only if the value isn't already in the array; $pull removes every element matching the condition
items.$ needs the array in the filter ("items.productId": 7) and updates the first element that matched
$[big] names a placeholder; arrayFilters says which elements it stands for

SQL Equivalent

  • $set ↔ UPDATE orders SET status = 'shipped' WHERE order_id = 1001
  • $inc ↔ SET stock = stock - 2 · $mul ↔ SET price = price * 0.9
  • Arrays have no SQL form: items is the order_items table, so $push ↔ INSERT INTO order_items … · See SQL 51

Across Engines

  • Redis HSET order:1001 status shipped · HINCRBY product:7 stock -2; nested arrays need RedisJSON (JSON.ARRAPPEND)
  • DynamoDB UpdateItem with SET #s = :s, stock = stock - :n; status is reserved, so alias it with #s
  • Cassandra UPDATE orders SET status = 'shipped' WHERE order_id = 1001 — every write is an upsert; lists use items = items + [...]
  • Neo4j MATCH (o:Order {id: 1001}) SET o.status = 'shipped' · SET p.stock = p.stock - 2

Field Operators

OperatorDoes
$setWrite a field (creates it if missing)
$unsetRemove a field
$inc / $mulAdd to / multiply a number
$min / $maxWrite only if lower / higher
$currentDateSet to the current date
$setOnInsertWrite only when an upsert inserts

Array Operators

OperatorDoes
$pushAppend ($each, $slice, $sort, $position)
$addToSetAppend if not present
$pull / $pullAllRemove matching / listed values
$First element the filter matched
$[]Every element
$[name]Elements matching arrayFilters

⚠ Common Mistakes

  • Passing { status: "shipped" } without $set; the update is rejected (or, with replaceOne, the rest of the document is lost)
  • Using updateOne when the filter matches many; only the first document changes
  • $push onto a field that isn't an array, which fails the whole update

✓ Tips & Best Practices

  • Check matchedCount vs modifiedCount to tell "not found" from "already set"
  • Cap growing arrays with $push + $each + $slice to stay far from the 16 MB limit
  • Use findOneAndUpdate when you need the updated document back (sheet 16)

Quick Summary

  • $set / $unset — fields
  • $inc / $mul — numbers
  • $push / $pull — arrays
  • $ · $[] · $[name] — array elements
