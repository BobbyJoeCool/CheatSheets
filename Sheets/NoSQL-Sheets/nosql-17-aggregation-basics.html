Aggregation Pipeline Basics

aggregate · $match · $project · $addFields · $sort · $limit · stage order

Pipelines of Stages

An aggregation pipeline is an array of stages. Documents flow through them top to bottom, and each stage filters, reshapes, groups or sorts what it receives. $match filters (use it first so it can use indexes), $project and $addFields reshape, $sort and $limit order and trim. Unlike SQL's fixed clause order, you choose the order and can repeat stages.

Notes

  • Each stage has a 100 MB memory limit; bigger work spills to disk (default since 6.0)
  • $set is an alias for $addFields
  • Field paths are strings starting with $: "$total"

A First Pipeline

db.orders.aggregate([
  { $match: { status: { $in: ["paid", "shipped"] },
              orderDate: { $gte: ISODate("2026-01-01") } } },
  { $project: { customerId: 1, total: 1,
                lines: { $size: "$items" },
                month: { $month: "$orderDate" } } },
  { $addFields: { big: { $gte: ["$total", 100] } } },
  { $sort: { total: -1 } },
  { $limit: 5 }
])

// count matches
db.orders.aggregate([ { $match: { status: "pending" } }, { $count: "pending" } ])

// sample and unset
db.products.aggregate([ { $sample: { size: 3 } }, { $unset: ["stock"] } ])

// options and the plan
db.orders.aggregate(pipeline, { maxTimeMS: 5000, allowDiskUse: true })
db.orders.explain("executionStats").aggregate(pipeline)

Code Explained

$match at the start uses the same indexes as find
$project keeps customerId and total and computes two new fields
$sort followed by $limit is merged into a top-N sort that keeps only 5 documents in memory
$unset removes fields from the output

SQL Equivalent

  • $match ↔ WHERE · $project ↔ SELECT list · $sort ↔ ORDER BY · $limit ↔ LIMIT
  • SQL runs clauses in a fixed logical order; a pipeline runs exactly in the order written · See SQL 5

Across Engines

  • Redis no pipeline engine; FT.AGGREGATE works on indexed data
  • DynamoDB no aggregation; precompute on write or export to analytics
  • Cassandra simple aggregates (COUNT, SUM) within a partition; Spark for more
  • Neo4j chained clauses: MATCH … WITH … ORDER BY … LIMIT

In Your Code

  • Node await orders.aggregate([{ $match: { status: "paid" } }, { $limit: 5 }]).toArray()
  • Python list(orders.aggregate([{"$match": {"status": "paid"}}, {"$limit": 5}]))
  • Java orders.aggregate(List.of(match(eq("status", "paid")), limit(5)))

Everyday Stages

StageDoes
$matchFilter
$projectChoose and compute fields
$addFields / $setAdd fields, keep the rest
$unsetRemove fields
$sort / $limit / $skipOrder and trim
$countCount documents
$sampleRandom documents

⚠ Common Mistakes

  • Putting $match after $group when it could filter first
  • Forgetting the $ in field paths ("total" is a string literal)
  • Sorting huge streams without an index or a $limit

✓ Tips & Best Practices

  • Build pipelines one stage at a time in Compass's Aggregations tab
  • Store pipelines in code as named functions
  • Add maxTimeMS to user-facing aggregations

Quick Summary

  • Stages run in order
  • $match first
  • $project / $addFields
  • $sort + $limit = top N
