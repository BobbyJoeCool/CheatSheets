Sheet 33

Keys & Strings

SET · GET · NX / XX · INCR · MSET · key naming · SCAN vs KEYS

The Basic Building Block

A string value can hold text, a number or up to 512 MB of bytes. SET and GET read and write it; options on SET make it conditional (NX: only if missing, XX: only if present) or expiring (EX seconds). INCR and friends turn strings into atomic counters. Key commands (EXISTS, TYPE, DEL, RENAME) work on any type, and SCAN walks keys safely in pages.

Notes

  • SET … NX EX is the standard simple lock
  • INCR on a missing key starts at 0
  • UNLINK frees memory in the background
  • SCAN may return a key more than once

Production Check

  • KEYS * walks every key and blocks the server; use SCAN with a cursor
  • Keys without a TTL pile up until memory runs out; give cache and session keys an expiry
  • Multi-megabyte values block the single thread while they're sent; split or compress them

SET Options, Counters & SCAN

> SET product:7:name "SQL Pocket Guide"
OK
> GET product:7:name
"SQL Pocket Guide"
> SET lock:order:1001 worker-3 NX EX 30       # only if missing, 30 s TTL
OK
> SET lock:order:1001 worker-4 NX EX 30
(nil)
> SET product:7:name "SQL Pocket Guide 5e" XX GET   # only if exists; old value
"SQL Pocket Guide"

> INCR counter:orders
(integer) 1002
> INCRBY product:7:views 5
> INCRBYFLOAT product:7:rating 0.5
> MSET product:7:stock 10 product:3:stock 120
> MGET product:7:stock product:3:stock

> EXISTS product:7:name
> TYPE product:7
> RENAME product:7:name product:7:title
> UNLINK big:report
> SCAN 0 MATCH product:* COUNT 100
1) "176"                                      # next cursor; "0" = done
2) 1) "product:7:title"

Code Explained

(nil) from the second SET … NX means another worker holds the lock
GET on SET returns the old value in the same atomic step
Counters are stored as strings but INCR treats them as 64-bit integers
Call SCAN again with the returned cursor until it returns 0

SQL Equivalent

  • SET / GET ↔ INSERT / SELECT by primary key · INCR ↔ UPDATE … SET n = n + 1 or a sequence
  • SET … NX ↔ INSERT … ON CONFLICT DO NOTHING · See SQL 58

Across Engines

  • MongoDB counters: findOneAndUpdate with $inc and upsert: true
  • DynamoDB atomic counters: UpdateItem … ADD views :one
  • Cassandra counter columns: UPDATE … SET views = views + 1
  • Neo4j SET n.views = n.views + 1 inside a transaction

In Your Code

  • Node await r.set("lock:order:1001", "w3", { NX: true, EX: 30 })
  • Python r.set("lock:order:1001", "w3", nx=True, ex=30)
  • Java jedis.set("lock:order:1001", "w3", SetParams.setParams().nx().ex(30))

⚠ Common Mistakes

  • Running KEYS * in production
  • Storing JSON blobs as strings and rewriting them for one field (use a hash or JSON)
  • Locks without an expiry that stay forever if a worker crashes

✓ Tips & Best Practices

  • Prefix keys by app and type: shop:product:7
  • Use SET … NX EX for locks and idempotency keys
  • Use UNLINK for big keys

Quick Summary

  • SET / GET
  • NX / XX / EX options
  • INCR — atomic counters
  • SCAN, never KEYS
