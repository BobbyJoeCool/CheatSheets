Schema Design Patterns

bucket · outlier · subset · computed · extended reference · polymorphic · schema versioning

Patterns for Common Problems

MongoDB's schema design patterns are named answers to recurring problems. Bucket groups many small records into one document. Subset keeps the most-used part of a large list on the parent. Computed stores totals on write instead of calculating them on every read. Outlier handles the rare oversized document. Polymorphic keeps different shapes in one collection, and schema versioning lets old and new shapes live side by side during a migration.

Notes

  • Time series collections now do the bucket pattern for you
  • Extended reference is on sheet 05
  • Patterns combine: subset + computed is common on product pages

Six Patterns

// Bucket: one document per sensor per hour
{ sensor: "s1", hour: ISODate("2026-11-07T10:00Z"), count: 3,
  readings: [ { t: 0, v: 21.4 }, { t: 60, v: 21.6 }, { t: 120, v: 21.5 } ] }

// Subset: newest 10 reviews on the product, the rest in `reviews`
{ _id: 7, name: "SQL Pocket Guide", reviewCount: 214,
  recentReviews: [ { stars: 5, text: "Clear" }, { stars: 4, text: "Handy" } ] }

// Computed: keep totals current on each write
db.products.updateOne({ _id: 7 },
  { $inc: { reviewCount: 1, starSum: 5 },
    $push: { recentReviews: { $each: [newReview], $position: 0, $slice: 10 } } })

// Outlier: flag the rare document that overflows
{ _id: 7, buyers: [ /* first 1000 ids */ ], hasOverflow: true }

// Polymorphic: one collection, a type field, different shapes
{ _id: 21, kind: "book",  name: "SQL Pocket Guide", isbn: "978-0-00-000000-0", pages: 360 }
{ _id: 22, kind: "cable", name: "USB-C Cable", lengthM: 2, connector: "USB-C" }

// Schema versioning: tag each document, upgrade lazily
{ _id: 42, schemaVersion: 2, name: { first: "Ada", last: "Lovelace" } }

Code Explained

Buckets cut document count and index size for high-volume small records
$position: 0 + $slice: 10 keeps the newest 10 reviews at the front
Average rating is starSum / reviewCount, computed without reading reviews
Readers check schemaVersion and convert old shapes (sheet 59)

SQL Equivalent

  • Subset ↔ LIMIT in a query · computed ↔ triggers or materialized views · polymorphic ↔ single-table inheritance
  • Schema versioning ↔ migrations with ALTER TABLE · See SQL 63, 64

Across Engines

  • Redis computed: counters with INCR; subset: capped lists with LTRIM
  • DynamoDB polymorphic items are normal (single-table design); computed with ADD
  • Cassandra bucket partitions by time: PRIMARY KEY ((sensor, day), ts)
  • Neo4j intermediate nodes split huge fans; extra labels give polymorphism

In Your Code

  • Node Mongoose discriminators: Product.discriminator("Book", bookSchema)
  • Python Beanie: class Book(Product) with is_root = True on the base
  • Java Spring Data: @TypeAlias("book") class Book extends Product

⚠ Common Mistakes

  • Applying patterns before measuring a problem
  • Computed values that drift because one write path forgets to update them
  • Polymorphic collections without a type field

✓ Tips & Best Practices

  • Update computed fields in the same operation as the change
  • Index the type field in polymorphic collections
  • Document which patterns each collection uses

Quick Summary

  • Bucket — group small records
  • Subset — keep the top N
  • Computed — totals on write
  • Versioning — evolve safely
