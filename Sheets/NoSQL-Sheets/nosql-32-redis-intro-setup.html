Redis Introduction & Setup

in-memory · single-threaded · Redis Open Source 8 · Valkey · Docker · redis-cli · Redis Insight

Data Structures in Memory

Redis keeps data in RAM as data structures under string keys: strings, hashes, lists, sets, sorted sets, streams, JSON and more. Commands run one at a time on a single thread, so each is atomic and most take microseconds. Redis Open Source 8 bundles JSON, the Query Engine (search and vectors), time series and probabilistic types, and is available under AGPLv3 among other licences. Valkey is the Linux Foundation fork of Redis 7.2 under BSD, command-compatible for the core types.

Notes

  • Default port 6379
  • Name keys type:id:field, such as order:1001:items
  • Persistence is optional (sheet 41)
  • Redis Insight is the official GUI

Run, Connect and Load the Shop Data

docker run -d --name redis -p 6379:6379 redis:8
redis-cli                                    # localhost:6379
redis-cli -h cache.example.com -p 6380 --tls --user app --askpass

> PING
PONG
> HSET product:7 name "SQL Pocket Guide" category Books price 19.99 stock 10
> HSET product:3 name "USB-C Cable" category Electronics price 9.99 stock 120
> HSET customer:42 name "Ada Lovelace" email ada@example.com city "Des Moines"
> HSET order:1001 customerId 42 status pending total 49.97
> RPUSH order:1001:items "7:2:19.99" "3:1:9.99"
> SADD customer:42:orders 1001
> ZADD orders:by_date 1793491200 1001          # score = Unix time
> INFO server                                 # version, mode, uptime
> DBSIZE

Code Explained

Each product, customer and order becomes a hash, like a row
Order lines become a list under their own key
A set links a customer to their orders; a sorted set orders them by date
There are no queries across keys: every lookup starts from a key name you can build

SQL Equivalent

  • No tables: a key is like a primary-key lookup, a hash like one row, a set like a junction table
  • Anything you'd WHERE on needs its own key or a Query Engine index · See SQL 4

Across Engines

  • MongoDB disk-based documents with an in-memory cache; Redis often caches it
  • DynamoDB DAX is DynamoDB's own in-memory cache
  • Cassandra has caches, but Redis usually sits in front for hot keys
  • Neo4j page cache keeps the graph in memory; no key-value API

In Your Code

  • Node const r = await createClient({ url: "redis://localhost:6379" }).connect()
  • Python r = redis.Redis(host="localhost", decode_responses=True)
  • Java JedisPooled jedis = new JedisPooled("localhost", 6379);

⚠ Common Mistakes

  • Treating Redis as the only copy of important data without persistence
  • Key names with no structure, impossible to scan or expire by group
  • Expecting SQL-style queries across keys

✓ Tips & Best Practices

  • Pick a key naming convention and stick to it
  • Keep values small; split big objects into hashes
  • Use Redis Insight to see memory per key
