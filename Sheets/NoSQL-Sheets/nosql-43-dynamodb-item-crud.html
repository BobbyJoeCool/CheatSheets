Item Operations

PutItem · GetItem · UpdateItem · DeleteItem · condition expressions · update expressions

Put, Get, Update, Delete

PutItem writes a whole item, replacing any item with the same key. GetItem reads one item by its full primary key. UpdateItem changes attributes with an update expression and creates the item if it doesn't exist. DeleteItem removes one item. Any write can carry a condition expression; if it's false the write fails with ConditionalCheckFailedException, which gives you insert-only puts and safe decrements.

Notes

  • Attribute names that are reserved words (name, status) need #aliases
  • Values always go through :placeholders
  • ReturnValues returns old or new attributes
  • Writes are billed per 1 KB, reads per 4 KB

Item Operations with Conditions

# insert-only put
aws dynamodb put-item --table-name Shop \
  --item '{"PK":{"S":"PRODUCT#7"},"SK":{"S":"META"},
           "name":{"S":"SQL Pocket Guide"},"stock":{"N":"10"}}' \
  --condition-expression "attribute_not_exists(PK)"

# read one item, two attributes
aws dynamodb get-item --table-name Shop \
  --key '{"PK":{"S":"PRODUCT#7"},"SK":{"S":"META"}}' \
  --projection-expression "#n, stock" \
  --expression-attribute-names '{"#n":"name"}'

# conditional decrement plus other changes
aws dynamodb update-item --table-name Shop \
  --key '{"PK":{"S":"PRODUCT#7"},"SK":{"S":"META"}}' \
  --update-expression "SET stock = stock - :q, updatedAt = :now ADD sold :q REMOVE promo" \
  --condition-expression "stock >= :q" \
  --expression-attribute-values '{":q":{"N":"2"},":now":{"S":"2026-11-07T10:00:00Z"}}' \
  --return-values UPDATED_NEW
# stock < 2 → ConditionalCheckFailedException

# delete only if it exists
aws dynamodb delete-item --table-name Shop \
  --key '{"PK":{"S":"PRODUCT#7"},"SK":{"S":"META"}}' \
  --condition-expression "attribute_exists(PK)"

In Your Code

  • Node new UpdateCommand({ TableName: "Shop", Key, UpdateExpression: "SET stock = stock - :q", ConditionExpression: "stock >= :q", ExpressionAttributeValues: { ":q": 2 } })
  • Python table.update_item(Key=key, UpdateExpression="SET stock = stock - :q", ConditionExpression="stock >= :q", ExpressionAttributeValues={":q": 2})
  • Java table.updateItem(UpdateItemEnhancedRequest.builder(Product.class).item(p).conditionExpression(cond).build())

Code Explained

attribute_not_exists(PK) makes the put fail if the item already exists
#n stands in for name, a reserved word
One update expression can SET, ADD and REMOVE in a single atomic write
UPDATED_NEW returns only the attributes that changed, with new values

SQL Equivalent

  • PutItem ↔ INSERT (or a full replace) · condition ↔ the WHERE of an UPDATE
  • UPDATE products SET stock = stock - 2 WHERE product_id = 7 AND stock >= 2 · See SQL 50, 51

Across Engines

  • MongoDB updateOne({ _id: 7, stock: { $gte: 2 } }, { $inc: { stock: -2 } })
  • Redis Lua or WATCH for a conditional decrement
  • Cassandra UPDATE … IF stock = 10 (lightweight transaction)
  • Neo4j MATCH (p:Product {id: 7}) WHERE p.stock >= 2 SET p.stock = p.stock - 2

⚠ Common Mistakes

  • Using PutItem to change one attribute and wiping the others
  • Read-then-write instead of a condition expression
  • Forgetting reserved words like name, status, date

✓ Tips & Best Practices

  • Use conditions for every "only if" rule
  • Use UpdateItem for partial changes
  • Catch ConditionalCheckFailedException as a normal outcome

Quick Summary

  • PutItem — whole item
  • UpdateItem — expressions, upserts
  • Condition expressions guard writes
  • #name for reserved words
