Finding Documents

find · findOne · projection · sort · limit · skip · countDocuments

Reading Documents

find(filter, projection) returns a cursor over every match and findOne returns the first. A filter is a document of conditions joined by AND; a projection chooses fields with 1 (include) or 0 (exclude). Chain sort, skip and limit to shape the result. countDocuments counts matches with a query; estimatedDocumentCount reads collection metadata and is instant.

Notes

  • Don't mix 1 and 0 in one projection (except _id: 0)
  • Sort runs before skip and limit, whatever order you chain them
  • An empty filter {} matches everything

Production Check

  • A query without a matching index scans every document (COLLSCAN). Check with explain("executionStats") before shipping (sheet 23)
  • Deep skip() pages read and throw away every skipped document; page with a range on an indexed field instead
  • Always limit() user-facing queries and project only the fields you display

find, Projection, Sort & Paging

db.products.find({ category: "Books" })
db.products.find({ category: "Books", price: { $lt: 20 } })   // AND
db.products.findOne({ _id: 7 })

// projection: choose fields
db.products.find({ category: "Books" }, { name: 1, price: 1, _id: 0 })
db.orders.find({}, { items: 0 })                             // all but items

// sort, skip, limit
db.orders.find({ customerId: 42 }).sort({ orderDate: -1 }).limit(10)
db.orders.find().sort({ _id: 1 }).skip(20).limit(10)          // page 3

// range paging: fast at any depth
db.orders.find({ _id: { $gt: lastSeenId } }).sort({ _id: 1 }).limit(10)

// counting and distinct values
db.orders.countDocuments({ status: "pending" })
db.orders.estimatedDocumentCount()
db.products.distinct("category")

Code Explained

Two conditions in one filter must both match
{ items: 0 } returns every field except items
Range paging remembers the last _id shown and asks for the next ones
distinct returns an array of the unique values

SQL Equivalent

  • find({ category: "Books" }, { name: 1 }) ↔ SELECT name FROM products WHERE category = 'Books'
  • sort / skip / limit ↔ ORDER BY / OFFSET / LIMIT · See SQL 13, 16

Across Engines

  • Redis no ad hoc queries; read by key, or add Search (FT.SEARCH)
  • DynamoDB Query needs the partition key; other fields need a GSI or a Scan
  • Cassandra WHERE must include the partition key, or use SAI / ALLOW FILTERING
  • Neo4j MATCH (p:Product {category: "Books"}) RETURN p.name ORDER BY p.price LIMIT 10

In Your Code

  • Node await products.find({ category: "Books" }).project({ name: 1 }).limit(10).toArray()
  • Python list(products.find({"category": "Books"}, {"name": 1}).limit(10))
  • Java products.find(eq("category", "Books")).projection(include("name")).limit(10)

⚠ Common Mistakes

  • Mixing included and excluded fields in a projection
  • Using skip(100000) for deep pages
  • Fetching whole documents when the page shows two fields

✓ Tips & Best Practices

  • Sort on an indexed field
  • Use findOne when you expect one result
  • Add .maxTimeMS() to protect user-facing queries

Quick Summary

  • find — cursor of matches
  • Projection — pick fields
  • sort · skip · limit
  • Range paging beats skip
