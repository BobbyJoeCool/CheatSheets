Sheet 24

Text, Atlas Search & Vector Search

$text · text index · $search · Atlas Search indexes · $vectorSearch · embeddings

Words, Relevance and Meaning

A classic text index supports simple word search with $text. Atlas Search ($search) runs Apache Lucene beside the database for real relevance: fuzzy matching, autocomplete, synonyms and facets. Vector Search ($vectorSearch) finds documents whose embeddings are closest in meaning to a query vector, which is the base for semantic search and RAG. Both started in Atlas; MongoDB 8.2 also offers them in self-managed deployments as a preview.

Notes

  • One text index per collection
  • Search indexes are created with createSearchIndex, not createIndex
  • Search indexes update asynchronously, a little behind writes
  • $search / $vectorSearch must be the first stage

$text, $search & $vectorSearch

// classic text index
db.products.createIndex({ name: "text", description: "text" })
db.products.find({ $text: { $search: "usb cable -lightning" } },
                 { score: { $meta: "textScore" } })
  .sort({ score: { $meta: "textScore" } })

// Atlas Search: Lucene relevance, typo tolerance
db.products.aggregate([
  { $search: { index: "products",
               text: { query: "keybord", path: ["name", "description"],
                       fuzzy: { maxEdits: 1 } } } },
  { $limit: 10 },
  { $project: { name: 1, score: { $meta: "searchScore" } } }
])

// Vector Search: index once, then query by embedding
db.products.createSearchIndex("product_vectors", "vectorSearch", {
  fields: [ { type: "vector", path: "embedding", numDimensions: 384, similarity: "cosine" },
            { type: "filter", path: "category" } ] })

db.products.aggregate([
  { $vectorSearch: { index: "product_vectors", path: "embedding",
                     queryVector: embed("cable for my laptop"),
                     numCandidates: 100, limit: 5,
                     filter: { category: "Electronics" } } },
  { $project: { name: 1, score: { $meta: "vectorSearchScore" } } }
])

In Your Code

  • Node await products.createSearchIndex({ name: "product_vectors", type: "vectorSearch", definition })
  • Python products.create_search_index(SearchIndexModel(definition=d, name="product_vectors", type="vectorSearch"))
  • Java products.createSearchIndexes(List.of(new SearchIndexModel("product_vectors", def, SearchIndexType.vectorSearch())))

Code Explained

-lightning excludes a word; quotes would search a phrase
fuzzy: { maxEdits: 1 } finds "keyboard" from "keybord"
embed() stands for your embedding model call; the vector length must match numDimensions
numCandidates trades accuracy for speed; 10–20× limit is typical

SQL Equivalent

  • $text ↔ to_tsvector(…) @@ to_tsquery(…) with a GIN index
  • $vectorSearch ↔ pgvector ORDER BY embedding <=> $1 LIMIT 5 · See SQL 80

Across Engines

  • Redis FT.CREATE with TEXT and VECTOR fields, then FT.SEARCH (sheet 40)
  • DynamoDB no full-text; zero-ETL integration streams tables into OpenSearch
  • Cassandra SAI vector search: ORDER BY v ANN OF [...] LIMIT 5
  • Neo4j full-text indexes (Lucene) and vector indexes on nodes

⚠ Common Mistakes

  • Using $text and expecting fuzzy matching
  • Embedding queries with a different model than the documents
  • Forgetting the vector filter field in the index definition

✓ Tips & Best Practices

  • Combine $vectorSearch and $search for hybrid ranking
  • Store the model name and version with each embedding
  • Test numCandidates against a set of known good answers
