Sheet 09

Databases, Collections & _id

use · db.createCollection · _id · capped collections · time series collections · naming

Namespaces and the Primary Key

A database groups collections, and both appear the first time you write to them. db.createCollection() is optional except for special kinds: capped collections (fixed size, oldest documents overwritten), time series collections (compressed measurements) and clustered collections (stored in _id order). Every document needs an _id: unique, immutable and indexed. It can be any type except an array.

Notes

  • Names are case-sensitive
  • The system. prefix is reserved
  • Time series collections replace the hand-built bucket pattern
  • A view is a read-only collection defined by a pipeline (sheet 21)

Databases, Collections & _id

show dbs
use shop                                  // created on first write
db.createCollection("orders")             // optional for normal collections
show collections

// capped: fixed size in bytes, insertion order, oldest overwritten
db.createCollection("auditLog", { capped: true, size: 10485760, max: 100000 })

// time series: compressed measurements, auto-expiring
db.createCollection("readings", {
  timeseries: { timeField: "ts", metaField: "sensor", granularity: "minutes" },
  expireAfterSeconds: 2592000              // 30 days
})

db.orders.renameCollection("orders_2025")
db.orders_2025.drop()

// _id: generated, any unique value, or a compound document
db.customers.insertOne({ name: "Grace Hopper" })          // ObjectId
db.customers.insertOne({ _id: "cust-43", name: "Linus" })
db.coupons.insertOne({ _id: { code: "FALL26", region: "US" }, pct: 10 })
db.customers.getIndexes()     // [ { key: { _id: 1 }, name: "_id_" } ]

Code Explained

use only switches context; nothing exists until the first insert
A capped collection is sized in bytes; max also caps the document count
granularity hints how often readings arrive so MongoDB can bucket them well
A compound _id works as a natural composite key, but its field order matters for matching

SQL Equivalent

  • use shop ↔ \c shop · createCollection ↔ CREATE TABLE without columns
  • _id ↔ PRIMARY KEY; ObjectId ↔ identity or UUID · See SQL 55, 58

Across Engines

  • Redis numbered databases 0–15 (SELECT 1); key prefixes act as namespaces
  • DynamoDB no databases: tables per account and region; the key schema is the primary key
  • Cassandra keyspace ↔ database; every table declares a PRIMARY KEY
  • Neo4j several databases in Enterprise; labels group nodes

In Your Code

  • Node await db.createCollection("readings", { timeseries: { timeField: "ts" } })
  • Python db.create_collection("readings", timeseries={"timeField": "ts"})
  • Java db.createCollection("readings", new CreateCollectionOptions().timeSeriesOptions(new TimeSeriesOptions("ts")))

⚠ Common Mistakes

  • A typo in use silently creates a new database on the next write
  • Using a capped collection for data you can't lose
  • Trying to change _id; delete and re-insert instead

✓ Tips & Best Practices

  • Use natural keys as _id when they're stable and unique
  • Prefer time series collections for measurements
  • Script collection setup (options, indexes, validation) in a migration file

Quick Summary

  • _id unique and immutable
  • Any type but an array
