Sheet 08

Documents, BSON & Types

BSON · ObjectId · Date · Decimal128 · arrays · embedded documents · 16 MB limit

JSON With More Types

Documents are stored as BSON, a binary JSON with extra types: ObjectId, Date, Decimal128, 32- and 64-bit integers, binary data and more. Field order is kept, values can nest up to 100 levels deep, and a document can be at most 16 MB. The type matters for queries and sorting: "10" (string) and 10 (number) never match each other.

Notes

  • Use Decimal128 or integer cents for money
  • Dates are stored as UTC milliseconds
  • null and a missing field are different things
  • Use GridFS for files over 16 MB

BSON Types in mongosh

db.products.insertOne({
  _id: ObjectId(),                    // 12 bytes: time + random + counter
  sku: "BK-0007",                     // String
  name: "SQL Pocket Guide",
  price: NumberDecimal("19.99"),       // Decimal128: exact
  stock: NumberInt(10),                // Int32
  views: NumberLong("9000000000"),     // Int64
  rating: 4.5,                         // Double
  active: true,                        // Boolean
  tags: ["sql", "reference"],          // Array
  dims: { w: 11, h: 18, unit: "cm" },  // embedded document
  createdAt: new Date(),               // Date (UTC)
  discontinuedAt: null                 // Null
})

ObjectId("6929a1c2e4b0a1b2c3d4e5f6").getTimestamp()
db.products.find({ price: { $type: "decimal" } })
db.products.find({ discontinuedAt: null })       // null OR missing
db.products.find({ discontinuedAt: { $type: "null" } })   // null only
typeof db.products.findOne().stock

Code Explained

An ObjectId starts with a timestamp, so ids sort roughly by creation time
NumberDecimal("19.99") is exact; 19.99 as a Double can show rounding errors
{ field: null } matches both null and missing fields; $type: "null" matches only real nulls
$type accepts names ("decimal") or numbers

SQL Equivalent

  • ObjectId ↔ identity / UUID · Decimal128 ↔ NUMERIC(10,2) · Date ↔ TIMESTAMPTZ
  • Arrays and embedded documents ↔ child tables or jsonb · See SQL 7, 9, 10

Across Engines

  • Redis values are strings at heart; RedisJSON stores real JSON
  • DynamoDB types S, N, B, BOOL, NULL, M, L, sets; numbers travel as strings
  • Cassandra typed columns: int, decimal, text, timestamp, uuid, collections, UDTs
  • Neo4j properties: numbers, strings, booleans, temporal, point, and lists of these

In Your Code

  • Node import { ObjectId, Decimal128 } from "mongodb"; Decimal128.fromString("19.99")
  • Python from bson import ObjectId, Decimal128; Decimal128("19.99")
  • Java new Decimal128(new BigDecimal("19.99")) · new ObjectId()

⚠ Common Mistakes

  • Storing prices as Doubles and summing them
  • Storing dates as strings, which breaks range queries
  • Mixing types in one field, such as "10" and 10

✓ Tips & Best Practices

  • Pick one type per field and enforce it with validation (sheet 26)
  • Store dates as Date in UTC; format in the app
  • Use short field names only if storage really matters

Quick Summary

  • BSON — JSON plus types
  • Decimal128 for money
  • Date in UTC
  • 16 MB per document
