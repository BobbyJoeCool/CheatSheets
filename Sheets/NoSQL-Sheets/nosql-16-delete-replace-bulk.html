Delete, Replace, Upsert & Bulk

deleteOne · deleteMany · replaceOne · upsert: true · findOneAndUpdate · bulkWrite

Remove, Replace, Upsert, Batch

deleteOne and deleteMany remove matching documents. replaceOne swaps a whole document except its _id. An upsert (upsert: true) updates a match or inserts a new document built from the filter and update. The findOneAnd… methods change one document and return it, before or after the change. bulkWrite sends many operations in one round trip.

Notes

  • $setOnInsert writes fields only when the upsert inserts
  • Concurrent upserts on unindexed filters can create duplicates
  • MongoDB 8.0 adds a client-level bulkWrite across collections
  • Deleting all documents keeps indexes; drop() removes them too

Delete, Replace, Upsert, Find-and-Modify, Bulk

db.orders.deleteOne({ _id: 1001 })
db.orders.deleteMany({ status: "cancelled", orderDate: { $lt: ISODate("2025-01-01") } })

// replace: everything except _id
db.products.replaceOne({ _id: 7 },
  { name: "SQL Pocket Guide, 5th ed.", category: "Books",
    price: NumberDecimal("21.99"), stock: 10 })

// upsert: update if found, insert if not
db.carts.updateOne(
  { customerId: 42 },
  { $push: { items: { productId: 3, qty: 1 } },
    $setOnInsert: { createdAt: new Date() } },
  { upsert: true })

// find-and-modify: returns the document
db.counters.findOneAndUpdate(
  { _id: "orderId" }, { $inc: { seq: 1 } },
  { upsert: true, returnDocument: "after" })
db.jobs.findOneAndDelete({ status: "queued" }, { sort: { createdAt: 1 } })

// bulk: several operations, one round trip
db.products.bulkWrite([
  { updateOne: { filter: { _id: 7 }, update: { $inc: { stock: -2 } } } },
  { insertOne: { document: { _id: 30, name: "Notebook" } } },
  { deleteOne: { filter: { _id: 21 } } }
], { ordered: false })

Code Explained

The upserted cart gets customerId: 42 from the filter, the pushed item, and createdAt
returnDocument: "after" returns the incremented counter; the default is the document before the change
findOneAndDelete with sort takes the oldest queued job, a simple work queue
bulkWrite returns counts per operation type

SQL Equivalent

  • deleteMany ↔ DELETE … WHERE · replaceOne ↔ UPDATE of every column
  • Upsert ↔ INSERT … ON CONFLICT DO UPDATE; findOneAndUpdate ↔ UPDATE … RETURNING · See SQL 52, 53

Across Engines

  • Redis DEL, or UNLINK to free memory in the background; SET always upserts
  • DynamoDB PutItem replaces; UpdateItem upserts; ReturnValues: ALL_NEW; BatchWriteItem takes 25 puts / deletes
  • Cassandra DELETE writes a tombstone; INSERT and UPDATE both upsert
  • Neo4j DETACH DELETE; MERGE … ON CREATE SET … ON MATCH SET

In Your Code

  • Node await counters.findOneAndUpdate(f, u, { upsert: true, returnDocument: "after" })
  • Python find_one_and_update(f, u, upsert=True, return_document=ReturnDocument.AFTER)
  • Java findOneAndUpdate(f, u, new FindOneAndUpdateOptions().upsert(true).returnDocument(ReturnDocument.AFTER))

Upsert Rules

SituationResult
Filter matchesNormal update
No matchInsert: filter fields + update
$setOnInsertApplied only on insert
Filter has operators ($gt)Those fields aren't copied
Concurrent upsertsUse a unique index to prevent duplicates

⚠ Common Mistakes

  • deleteMany({}) when you meant one document
  • Using replaceOne to change one field and losing the rest
  • Upserting on a filter with no unique index

✓ Tips & Best Practices

  • Run the filter with find before a deleteMany
  • Use findOneAndUpdate for counters and queues
  • Group many small writes into a bulkWrite

Quick Summary

  • deleteOne / deleteMany
  • replaceOne — whole document
  • upsert: true — update or insert
  • bulkWrite — one round trip
