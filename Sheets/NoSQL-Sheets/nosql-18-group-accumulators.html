Sheet 18

$group & Accumulators

$group · $sum · $avg · $min / $max · $push · $addToSet · $count

Grouping and Totals

$group collects documents that share an _id expression and computes accumulators for each group: $sum, $avg, $min, $max, $push, $addToSet, $first, $count and the top-N family. Use _id: null for one group over everything, or a document for several grouping fields. $unwind before $group lets you total array elements, such as order lines.

Notes

  • Only _id and accumulator fields come out of $group
  • $sum: 1 counts documents
  • $topN, $bottomN, $firstN arrived in 5.2
  • Filter groups with a $match after $group

$group, Accumulators & Top N

// revenue per customer
db.orders.aggregate([
  { $match: { status: "paid" } },
  { $group: { _id: "$customerId",
              orders: { $sum: 1 },
              revenue: { $sum: "$total" },
              avgOrder: { $avg: "$total" },
              firstOrder: { $min: "$orderDate" } } },
  { $match: { revenue: { $gte: 500 } } },          // like HAVING
  { $sort: { revenue: -1 } }
])

// group by year and status
db.orders.aggregate([
  { $group: { _id: { year: { $year: "$orderDate" }, status: "$status" },
              n: { $count: {} } } }
])

// units sold per product from order lines
db.orders.aggregate([
  { $unwind: "$items" },
  { $group: { _id: "$items.productId",
              units: { $sum: "$items.qty" },
              buyers: { $addToSet: "$customerId" } } }
])

// three most expensive products per category
db.products.aggregate([
  { $group: { _id: "$category",
              top3: { $topN: { n: 3, sortBy: { price: -1 }, output: "$name" } } } }
])

Code Explained

_id: "$customerId" makes one output document per customer
The $match after $group filters on computed totals, like SQL's HAVING
A compound _id groups by several values at once
$addToSet collects unique customer ids; $push would keep duplicates

SQL Equivalent

  • $group ↔ GROUP BY · $sum: 1 ↔ COUNT(*) · $push ↔ array_agg
  • $addToSet ↔ array_agg(DISTINCT …) · $match after $group ↔ HAVING · See SQL 28, 29, 31

Across Engines

  • Redis keep counters on write (HINCRBY) instead of grouping later
  • DynamoDB maintain totals on write (ADD revenue :t) or in a Streams consumer
  • Cassandra GROUP BY only on partition and clustering columns
  • Neo4j implicit grouping: RETURN c.id, count(o), sum(o.total)

In Your Code

  • Node { $group: { _id: "$customerId", revenue: { $sum: "$total" } } }
  • Python {"$group": {"_id": "$customerId", "revenue": {"$sum": "$total"}}}
  • Java group("$customerId", sum("revenue", "$total"), avg("avgOrder", "$total"))

⚠ Common Mistakes

  • Expecting other fields to pass through $group
  • Summing Double prices and getting rounding noise; store Decimal128
  • Using $first without a $sort before the group

✓ Tips & Best Practices

  • $match before $group to shrink the input
  • Name accumulator fields for what they mean (revenue, not total2)
  • Cache heavy group results with $merge (sheet 21)

Quick Summary

  • $group by _id
  • Accumulators compute per group
  • $match after = HAVING
  • $unwind to total arrays
