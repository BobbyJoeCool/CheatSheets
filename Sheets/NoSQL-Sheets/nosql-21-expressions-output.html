Expression Operators & Output

$cond · $switch · $dateTrunc · $concat · $merge · $out · views

Logic Inside Pipelines

Expression operators compute values inside $project, $set, $group and $expr: conditionals ($cond, $switch, $ifNull), strings ($concat, $toUpper), dates ($dateTrunc, $dateToString) and conversions ($toString, $toDecimal). To keep results, $out replaces a collection with the pipeline output and $merge upserts into one, which makes it the tool for incremental summaries. A view saves a pipeline as a read-only collection.

Notes

  • $out and $merge must be the last stage
  • Views run their pipeline on every read; they store nothing
  • $merge into the source collection is allowed
  • "On-demand materialized view" = $merge on a schedule

Expressions, $out, $merge & Views

db.orders.aggregate([
  { $project: {
      total: 1,
      size: { $cond: { if: { $gte: ["$total", 100] }, then: "large", else: "small" } },
      label: { $switch: { branches: [
                 { case: { $eq: ["$status", "pending"] }, then: "Awaiting payment" },
                 { case: { $eq: ["$status", "shipped"] }, then: "On the way" } ],
               default: "Other" } },
      month: { $dateTrunc: { date: "$orderDate", unit: "month" } },
      ref: { $concat: ["ORD-", { $toString: "$_id" }] },
      coupon: { $ifNull: ["$couponCode", "none"] }
  } }
])

// replace a summary collection
db.orders.aggregate([
  { $group: { _id: "$customerId", spent: { $sum: "$total" } } },
  { $out: "customerTotals" }
])

// upsert into it instead (incremental refresh)
db.orders.aggregate([
  { $match: { orderDate: { $gte: ISODate("2026-11-01") } } },
  { $group: { _id: "$customerId", spent: { $sum: "$total" } } },
  { $merge: { into: "customerTotals", on: "_id",
              whenMatched: "replace", whenNotMatched: "insert" } }
])

// view: a saved, read-only pipeline
db.createView("pendingOrders", "orders", [ { $match: { status: "pending" } } ])

Code Explained

$cond is if / then / else; $switch handles several cases
$dateTrunc rounds a date down to the start of the month
$out swaps in the new collection when the pipeline finishes
whenMatched can also be "merge", "keepExisting", "fail" or a pipeline

SQL Equivalent

  • $cond ↔ CASE WHEN · $ifNull ↔ COALESCE · $dateTrunc ↔ date_trunc
  • $out ↔ CREATE TABLE AS · $merge ↔ MERGE · view ↔ CREATE VIEW · See SQL 21, 26, 64

Across Engines

  • Redis logic in Lua or the app; APPLY expressions in FT.AGGREGATE
  • DynamoDB no server-side expressions beyond update and condition expressions
  • Cassandra write to several tables, or materialized views (experimental)
  • Neo4j CASE WHEN, coalesce(), date.truncate('month', d)

In Your Code

  • Node await db.createCollection("pendingOrders", { viewOn: "orders", pipeline: [...] })
  • Python db.create_collection("pendingOrders", viewOn="orders", pipeline=[...])
  • Java db.createView("pendingOrders", "orders", List.of(match(eq("status", "pending"))))

⚠ Common Mistakes

  • Using $out when other code still writes to that collection
  • Treating a view as a cache; it recomputes every time
  • Comparing values of different types inside $cond

✓ Tips & Best Practices

  • Refresh summaries with $merge on a schedule
  • Use $filter / $map to work on arrays without $unwind
  • Keep heavy expressions out of hot read paths
