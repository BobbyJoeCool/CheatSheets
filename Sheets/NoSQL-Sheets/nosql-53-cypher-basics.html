Cypher Basics

MATCH · WHERE · RETURN · CREATE · MERGE · SET · DELETE / DETACH DELETE

Patterns in ASCII Art

Cypher describes graph patterns with ASCII art: (n:Label) is a node, -[:TYPE]-> a relationship. MATCH finds patterns, WHERE filters, RETURN chooses output. CREATE adds data, SET / REMOVE change properties and labels, MERGE matches a whole pattern or creates it, and DELETE removes; DETACH DELETE also removes a node's relationships. Pass values as parameters ($id) rather than building strings.

Notes

  • OPTIONAL MATCH is the left outer join of Cypher
  • MERGE matches the whole pattern; merge nodes first, then relationships
  • Strings use single or double quotes
  • Statements end with ; in Browser multi-statement mode

Read, Create, Update, Merge, Delete

// read
MATCH (p:Product) WHERE p.price < 20
RETURN p.name, p.price ORDER BY p.price LIMIT 10;
MATCH (c:Customer {id: 42})-[:PLACED]->(o:Order)
RETURN o.id, o.total ORDER BY o.date DESC;
MATCH (p:Product) WHERE p.name STARTS WITH "SQL" OR p.name CONTAINS "Cable"
RETURN p;
MATCH (p:Product {id: 7})
OPTIONAL MATCH (p)<-[r:REVIEWED]-(c:Customer)
RETURN p.name, c.name, r.stars;

// create and update
CREATE (:Product {id: 21, name: "Desk Mat", price: 24.50, stock: 40});
MATCH (p:Product {id: 7}) SET p.stock = p.stock - 2, p.updatedAt = datetime();
MATCH (p:Product {id: 21}) SET p:Clearance REMOVE p.promo;
MATCH (p:Product {id: 7}) SET p += {featured: true};

// MERGE: get-or-create
MERGE (c:Customer {id: 43})
  ON CREATE SET c.name = "Grace Hopper", c.createdAt = datetime()
  ON MATCH SET c.lastSeen = datetime();
MATCH (c:Customer {id: 43}), (p:Product {id: 7})
MERGE (c)-[v:VIEWED]->(p) SET v.at = datetime();

// delete
MATCH (p:Product {id: 21}) DETACH DELETE p;
MATCH ()-[v:VIEWED]->() WHERE v.at < datetime() - duration("P90D") DELETE v;

Code Explained

{id: 42} inside a node pattern is shorthand for WHERE c.id = 42
SET p:Clearance adds a label; REMOVE p.promo drops a property
SET p += {…} merges a map into the properties without removing others
Plain DELETE on a node with relationships fails; DETACH DELETE removes them first

SQL Equivalent

  • MATCH ↔ SELECT … FROM … JOIN · CREATE ↔ INSERT · SET ↔ UPDATE · MERGE ↔ upsert
  • OPTIONAL MATCH ↔ LEFT JOIN · DETACH DELETE ↔ DELETE … CASCADE · See SQL 13, 53

Across Engines

  • MongoDB find / insertOne / updateOne / deleteOne; upsert: true is like MERGE
  • Redis commands per data type; no query language
  • DynamoDB Get / Put / Update / Delete; PartiQL for SQL-like syntax
  • Cassandra CQL looks like SQL but WHERE is limited to keys

In Your Code

  • Node await driver.executeQuery("MATCH (p:Product {id: $id}) RETURN p", { id: 7 })
  • Python driver.execute_query("MATCH (p:Product {id: $id}) RETURN p", id=7)
  • Java driver.executableQuery("MATCH (p:Product {id: $id}) RETURN p").withParameters(Map.of("id", 7)).execute()

⚠ Common Mistakes

  • MERGE on a whole pattern when one end already exists, creating duplicate nodes
  • Building Cypher strings from user input
  • Forgetting relationship direction in CREATE

✓ Tips & Best Practices

  • Always use parameters ($id)
  • MERGE nodes on constrained keys, then MERGE relationships
  • Use EXPLAIN before running big writes
