Search Engines: Elasticsearch & OpenSearch

inverted index · mappings · analyzers · match / bool query · relevance scoring · aggregations

Relevance Is the Product

Elasticsearch and its Apache-licensed fork OpenSearch are document stores built around an inverted index (word → documents). Analyzers break text into normalized tokens, mappings set field types, and queries are scored for relevance (BM25 by default). A bool query mixes scored must clauses with unscored filter clauses, and aggregations compute facets in the same request. They're usually a search copy of data whose source of truth lives elsewhere.

Notes

  • text fields are analyzed; keyword fields match exactly
  • Changing a field's mapping means reindexing
  • Elasticsearch offers AGPLv3 among its licences; OpenSearch is Apache 2.0
  • Both also do vector search (kNN)

Mapping, Indexing & a bool Query

PUT /products
{ "mappings": { "properties": {
    "name":     { "type": "text", "analyzer": "english" },
    "category": { "type": "keyword" },
    "price":    { "type": "scaled_float", "scaling_factor": 100 },
    "stock":    { "type": "integer" } } } }

PUT /products/_doc/7
{ "name": "SQL Pocket Guide", "category": "Books", "price": 19.99, "stock": 10 }

GET /products/_search
{ "query": { "bool": {
    "must":   [ { "match": { "name": { "query": "pocket gide",
                                       "fuzziness": "AUTO" } } } ],
    "filter": [ { "term":  { "category": "Books" } },
                { "range": { "price": { "lte": 30 } } } ] } },
  "aggs": { "by_category": { "terms": { "field": "category" } },
            "avg_price":   { "avg":   { "field": "price" } } },
  "size": 10 }

Code Explained

The english analyzer lowercases, removes stop words and stems ("guides" → "guid")
fuzziness: AUTO lets "gide" match "guide"
filter clauses don't affect the score and are cached
aggs return facet counts alongside the hits

SQL Equivalent

  • Inverted index ↔ a GIN index on tsvector · match ↔ @@ to_tsquery · filter ↔ WHERE
  • aggs ↔ GROUP BY; relevance ranking ↔ ts_rank, much simpler · See SQL 80

Across Engines

  • MongoDB Atlas Search runs Lucene beside the database (sheet 24)
  • Redis Query Engine FT.SEARCH, in memory (sheet 40)
  • DynamoDB zero-ETL integration feeds OpenSearch Service

In Your Code

  • Node await es.search({ index: "products", query: { match: { name: "pocket guide" } } })
  • Python es.search(index="products", query={"match": {"name": "pocket guide"}})
  • Java client.search(s -> s.index("products").query(q -> q.match(m -> m.field("name").query("pocket guide"))), Product.class)

⚠ Common Mistakes

  • Mapping categories as text and failing to aggregate them
  • Relying on dynamic mapping in production
  • Using the search engine as the only copy of the data

✓ Tips & Best Practices

  • Define mappings explicitly
  • Put non-scoring conditions in filter
  • Reindex through an alias so you can swap indexes with no downtime

Quick Summary

  • Inverted index + analyzers
  • text vs keyword
  • bool: must + filter
  • A search copy, not the source
