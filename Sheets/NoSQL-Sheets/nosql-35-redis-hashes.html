Hashes

HSET · HGET · HGETALL · HINCRBY · HDEL · objects as hashes · field expiry

Objects as Field Maps

A hash maps fields to string values under one key, so it's the natural home for an object such as a product or a session. Read and write single fields without touching the rest, increment numeric fields atomically with HINCRBY, and fetch everything with HGETALL. Small hashes are stored compactly, which makes many small hashes cheaper than many separate keys. Values are flat: nest with JSON (sheet 40) instead.

Notes

  • HSET takes many field / value pairs
  • All values are strings; numbers are parsed by HINCRBY
  • Field expiry from 7.4; HGETDEL / HSETEX from 8.0
  • HGETALL on a huge hash blocks; use HSCAN

Hash Commands

> HSET product:7 name "SQL Pocket Guide" category Books price 19.99 stock 10
(integer) 4
> HGET product:7 price
"19.99"
> HMGET product:7 name stock
1) "SQL Pocket Guide"
2) "10"
> HGETALL product:7
> HINCRBY product:7 stock -2
(integer) 8
> HINCRBYFLOAT product:7 price 1.00
"20.99"
> HSETNX product:7 createdAt 1793491200        # only if the field is missing
> HEXISTS product:7 discount
(integer) 0
> HDEL product:7 discount
> HLEN product:7
> HKEYS product:7
> HSCAN product:7 0 MATCH s*

# Redis 8: set with expiry, get and delete
> HSETEX product:7 EX 300 FIELDS 1 flashPrice 14.99
> HGETDEL cart:42 FIELDS 1 coupon

Code Explained

HSET returns how many new fields were added
HINCRBY is atomic, so two clients decrementing stock never lose an update
HSETNX sets a field only once, handy for "first seen" timestamps
HSETEX writes a field that disappears after 5 minutes

SQL Equivalent

  • A hash ↔ one row · HINCRBY ↔ UPDATE products SET stock = stock - 2
  • HGETALL ↔ SELECT * for one key; there's no query across hashes · See SQL 51

Across Engines

  • MongoDB a document updated with $set / $inc on fields
  • DynamoDB an item updated with SET / ADD
  • Cassandra a row, or a map<text, text> column
  • Neo4j node properties: SET p.stock = p.stock - 2

In Your Code

  • Node await r.hSet("product:7", { name: "SQL Pocket Guide", stock: 10 })
  • Python r.hset("product:7", mapping={"name": "SQL Pocket Guide", "stock": 10})
  • Java jedis.hset("product:7", Map.of("name", "SQL Pocket Guide", "stock", "10"));

String, Hash or JSON?

Store asWhen
StringOne value, or an opaque blob
HashFlat object; update fields separately
JSONNested object; query by path or index it
Several keysFields need different TTLs (pre-7.4)

⚠ Common Mistakes

  • Storing an object as one JSON string and rewriting it for each field change
  • Calling HGETALL on hashes with thousands of fields
  • Expecting nested values in a hash

✓ Tips & Best Practices

  • Use hashes for objects with flat fields
  • Use HINCRBY for stock and counters
  • Keep hashes small for the compact encoding

Quick Summary

  • Hash — one object per key
  • Field-level reads and writes
  • HINCRBY — atomic
  • Flat only; nest with JSON
