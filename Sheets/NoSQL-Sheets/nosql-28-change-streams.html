Sheet 28

Change Streams

watch() · change events · resume token · fullDocument · pipeline filters · event-driven sync

React to Every Change

A change stream pushes inserts, updates, replaces and deletes to your app as they happen, built on the replication log (oplog). Open one with watch() on a collection, database or whole deployment, filter it with a pipeline, and save each event's resume token so you can continue after a restart without missing events. Use it for event-driven sync: updating caches, search indexes or other services.

Notes

  • Requires a replica set or sharded cluster
  • Resume tokens work while the event is still in the oplog
  • fullDocument: "updateLookup" fetches the current document for updates
  • Events for one document arrive in order

watch(), Filters & Resume Tokens

// inserts and updates on orders, with the full document
const cs = db.orders.watch(
  [ { $match: { operationType: { $in: ["insert", "update"] } } } ],
  { fullDocument: "updateLookup" })

while (!cs.isClosed()) {
  const e = cs.tryNext()
  if (!e) { sleep(500); continue }
  printjson({ op: e.operationType, id: e.documentKey._id,
              status: e.fullDocument?.status })
  saveToken(e._id)                       // resume token
}

// continue after a crash
db.orders.watch([], { resumeAfter: loadToken() })

// start from a moment in time
db.orders.watch([], { startAtOperationTime: Timestamp({ t: 1793491200, i: 0 }) })

// pre-images: the document before the change (6.0+)
db.runCommand({ collMod: "orders", changeStreamPreAndPostImages: { enabled: true } })
db.orders.watch([], { fullDocumentBeforeChange: "whenAvailable" })

// a whole database or deployment
db.watch()
db.getMongo().watch()

Code Explained

documentKey holds the _id (and shard key) of the changed document
An update event carries updateDescription with changed and removed fields
saveToken / loadToken stand for your own storage, such as a small collection
Pre-images must be enabled per collection before you can read them

SQL Equivalent

  • Change streams ↔ logical replication / logical decoding, or LISTEN / NOTIFY for simple cases
  • Triggers run inside the database; change streams run in your app · See SQL 67

Across Engines

  • Redis keyspace notifications (notify-keyspace-events) or Streams
  • DynamoDB DynamoDB Streams (24 h) or Kinesis Data Streams
  • Cassandra CDC commit-log files, usually read by Debezium
  • Neo4j CDC (Enterprise and Aura) via db.cdc.query

In Your Code

  • Node for await (const e of orders.watch(pipeline)) handle(e)
  • Python with orders.watch(pipeline) as s: for e in s: handle(e)
  • Java orders.watch(pipeline).forEach(e -> handle(e));

⚠ Common Mistakes

  • Not saving resume tokens, so a restart misses events
  • Doing slow work inline and falling off the end of the oplog
  • Assuming updateLookup returns the document as of the event (it's the current one)

✓ Tips & Best Practices

  • Store the token after processing each event
  • Make handlers idempotent; events can repeat after a resume
  • Filter with $match on the server, not in the app

Quick Summary

  • watch() — live changes
  • Filter with a pipeline
  • Save resume tokens
  • Replica set required
