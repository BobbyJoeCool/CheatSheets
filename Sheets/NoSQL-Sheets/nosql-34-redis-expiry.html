Sheet 34

Expiry & Eviction

EXPIRE · TTL · SET … EX · PERSIST · maxmemory · eviction policies · HEXPIRE

Data That Cleans Itself Up

Any key can have a TTL: set it with EX on SET or with EXPIRE, read it with TTL, remove it with PERSIST. Since 7.4 individual hash fields can expire too. When memory reaches maxmemory, the eviction policy decides what to drop: nothing (writes fail), least recently used, least frequently used, or keys closest to expiring. Cache-only instances usually run allkeys-lru or allkeys-lfu.

Notes

  • Writing a key with plain SET clears its TTL (use KEEPTTL)
  • TTL returns -1 for no expiry, -2 for no key
  • Expired keys are removed lazily and by a background sweep
  • The default policy is noeviction

TTLs, Field Expiry & Eviction

> SET session:abc123 "{...}" EX 1800        # 30 minutes
> EXPIRE cart:42 86400                       # set or reset the TTL
> EXPIRE cart:42 3600 GT                     # only if longer than now
> TTL cart:42
(integer) 86400
> PTTL cart:42                               # milliseconds
> EXPIREAT promo:fall 1796083200             # at a Unix time
> PERSIST cart:42                            # remove the TTL
> TTL cart:42
(integer) -1
> SET product:7:name "x" KEEPTTL             # keep the existing TTL
> GETEX session:abc123 EX 1800               # read and slide expiry

# hash field expiry (7.4+)
> HSET session:abc123 csrf t0k3n cartId 99
> HEXPIRE session:abc123 600 FIELDS 1 csrf
> HTTL session:abc123 FIELDS 1 csrf

# memory limit and eviction
> CONFIG SET maxmemory 2gb
> CONFIG SET maxmemory-policy allkeys-lru
> INFO memory
> MEMORY USAGE cart:42

Code Explained

GT only extends a TTL, never shortens it (NX, XX, LT also exist)
GETEX makes a sliding session: each read pushes expiry out
HEXPIRE expires just the csrf field; the rest of the hash stays
MEMORY USAGE reports bytes used by one key

SQL Equivalent

  • No SQL equivalent for TTL; the nearest is an expires_at column plus a scheduled DELETE
  • Eviction has no SQL counterpart: databases don't throw data away · See SQL 52

Across Engines

  • MongoDB TTL indexes delete documents, checked about every 60 s
  • DynamoDB TTL attribute (epoch seconds); expired items are deleted within a few days, free
  • Cassandra USING TTL per write or default_time_to_live per table
  • Neo4j no built-in TTL; scheduled deletes or APOC's TTL procedures

In Your Code

  • Node await r.set("session:abc", val, { EX: 1800 }); await r.expire("cart:42", 86400)
  • Python r.set("session:abc", val, ex=1800); r.expire("cart:42", 86400)
  • Java jedis.setex("session:abc", 1800, val); jedis.expire("cart:42", 86400);

Eviction Policies

PolicyEvicts
noevictionNothing; writes fail (default)
allkeys-lruLeast recently used key
allkeys-lfuLeast frequently used key
volatile-lru / -lfuSame, only keys with a TTL
volatile-ttlKeys closest to expiring
allkeys-randomAny key

⚠ Common Mistakes

  • Overwriting a key with SET and losing its TTL
  • Running a cache with noeviction until writes fail
  • Using volatile-* policies when most keys have no TTL

✓ Tips & Best Practices

  • Add a little random jitter to TTLs to avoid mass expiry
  • Set maxmemory below the machine's RAM
  • Watch evicted_keys and expired_keys in INFO stats

Quick Summary

  • EX / EXPIRE — set TTL
  • TTL -1 none, -2 missing
  • HEXPIRE — field TTL
  • maxmemory-policy — eviction
