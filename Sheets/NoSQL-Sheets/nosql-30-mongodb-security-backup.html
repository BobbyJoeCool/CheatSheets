Security & Backup

users & roles · createUser · TLS · network access · mongodump / mongorestore · Atlas backups

Users, Network, Backups

Turn on authentication and give each app its own user with only the roles it needs, scoped to a database. Limit network access with bindIp and firewalls (Atlas: IP access lists or private endpoints) and encrypt traffic with TLS. For backups, mongodump / mongorestore handle small to medium data; larger deployments use filesystem snapshots or Atlas continuous backups with point-in-time restore.

Notes

  • Since 3.6, mongod listens only on localhost by default
  • SCRAM-SHA-256 is the default password mechanism
  • Database Tools are a separate download from the server
  • Test restores, not just backups

Users, Config & Backups

# create users (in mongosh, as an admin)
use admin
db.createUser({ user: "shopApp", pwd: passwordPrompt(),
  roles: [ { role: "readWrite", db: "shop" } ] })
db.createUser({ user: "analyst", pwd: passwordPrompt(),
  roles: [ { role: "read", db: "shop" } ] })
db.createRole({ role: "orderReader", roles: [], privileges: [
  { resource: { db: "shop", collection: "orders" }, actions: ["find"] } ] })
db.grantRolesToUser("analyst", [ { role: "orderReader", db: "admin" } ])

# mongod.conf
security:
  authorization: enabled
net:
  bindIp: 127.0.0.1,10.0.0.5
  tls:
    mode: requireTLS
    certificateKeyFile: /etc/ssl/mongo.pem

# backup and restore
mongodump --uri "mongodb://admin@localhost:27017/?authSource=admin" \
  --db shop --gzip --archive=shop-2026-11-07.gz
mongorestore --uri "mongodb://admin@localhost:27017/?authSource=admin" \
  --gzip --archive=shop-2026-11-07.gz --drop
mongoexport --db shop --collection orders --type=csv \
  --fields _id,status,total --out orders.csv

Code Explained

passwordPrompt() keeps the password out of shell history
A custom role grants exactly find on one collection
--archive writes one file; --gzip compresses it
--drop replaces collections on restore instead of merging

SQL Equivalent

  • createUser ↔ CREATE ROLE … LOGIN · roles ↔ GRANT · mongodump ↔ pg_dump
  • Atlas point-in-time restore ↔ PostgreSQL WAL archiving and PITR · See SQL 75, 77

Across Engines

  • Redis ACL users (ACL SETUSER), TLS; back up RDB / AOF files
  • DynamoDB IAM policies per table or item; PITR (35 days) and on-demand backups
  • Cassandra CREATE ROLE, GRANT; nodetool snapshot
  • Neo4j role-based access (fine-grained in Enterprise); neo4j-admin database dump / backup

In Your Code

  • Node new MongoClient(uri, { tls: true, auth: { username, password } })
  • Python MongoClient(uri, tls=True, username=u, password=p)
  • Java MongoCredential.createScramSha256Credential(u, "admin", pw) in MongoClientSettings

⚠ Common Mistakes

  • Running with authorization off on a reachable server
  • Apps connecting as root
  • Never testing a restore

✓ Tips & Best Practices

  • One user per app, least privilege
  • Keep connection strings in secrets, not code
  • Schedule restore drills

Quick Summary

  • Auth on, users per app
  • Roles scoped to databases
  • TLS + bindIp
  • Dump, snapshot or Atlas PITR
