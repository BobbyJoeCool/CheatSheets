Streams, TTL & Transactions

DynamoDB Streams · Lambda triggers · TTL attribute · TransactWriteItems · idempotency tokens

Changes, Expiry, All-or-Nothing

DynamoDB Streams records every item change for 24 hours, and Lambda can process it to update caches, search indexes or aggregates. TTL deletes items after a timestamp attribute (epoch seconds) passes, at no cost, usually within a few days. Transactions (TransactWriteItems, TransactGetItems) group up to 100 actions across items and tables: all succeed or all fail, and a client token makes retries idempotent.

Notes

  • TTL deletions appear in the stream, marked as service deletions
  • Filter Lambda events to pay only for the ones you need
  • Transactions cost twice the capacity of normal writes
  • The idempotency token is honored for 10 minutes

Streams, TTL & TransactWriteItems

# change log, read by Lambda
aws dynamodb update-table --table-name Shop \
  --stream-specification StreamEnabled=true,StreamViewType=NEW_AND_OLD_IMAGES
aws lambda create-event-source-mapping --function-name onShopChange \
  --event-source-arn <stream-arn> --starting-position LATEST \
  --filter-criteria '{"Filters":[{"Pattern":"{\"eventName\":[\"INSERT\"]}"}]}'

# expire items when expiresAt (epoch seconds) passes
aws dynamodb update-time-to-live --table-name Shop \
  --time-to-live-specification Enabled=true,AttributeName=expiresAt

# place an order: reserve stock and create the order together
aws dynamodb transact-write-items --client-request-token order-1002-v1 \
  --transact-items '[
  {"Update": {"TableName": "Shop",
    "Key": {"PK": {"S": "PRODUCT#7"}, "SK": {"S": "META"}},
    "UpdateExpression": "SET stock = stock - :q",
    "ConditionExpression": "stock >= :q",
    "ExpressionAttributeValues": {":q": {"N": "2"}}}},
  {"Put": {"TableName": "Shop",
    "Item": {"PK": {"S": "CUSTOMER#42"}, "SK": {"S": "ORDER#2026-11-07#1002"},
             "status": {"S": "pending"}},
    "ConditionExpression": "attribute_not_exists(SK)"}}
]'

Code Explained

NEW_AND_OLD_IMAGES puts both versions of the item in each stream record
The filter means Lambda only runs for inserts
If stock is short, the whole transaction is canceled and no order is created
Retrying with the same --client-request-token won't apply it twice

SQL Equivalent

  • Streams ↔ logical decoding / CDC · TTL ↔ a scheduled DELETE
  • TransactWriteItems ↔ BEGIN … COMMIT; the token ↔ an idempotency key · See SQL 67, 68

Across Engines

  • MongoDB change streams; TTL indexes; withTransaction()
  • Redis keyspace notifications or streams; EXPIRE; MULTI / EXEC
  • Cassandra CDC; USING TTL; lightweight transactions per partition
  • Neo4j CDC; no built-in TTL; ACID transactions

In Your Code

  • Node await doc.send(new TransactWriteCommand({ TransactItems: [...], ClientRequestToken: "order-1002-v1" }))

⚠ Common Mistakes

  • Expecting TTL deletes at the exact second; filter expired items in reads
  • Non-idempotent Lambda handlers (records can repeat)
  • Using transactions for things one conditional update can do

✓ Tips & Best Practices

  • Filter expired items with expiresAt > :now until TTL catches up
  • Use ConditionCheck to assert on items you don't change
  • Read cancellation reasons to tell which condition failed

Quick Summary

  • Streams + Lambda — react to changes
  • TTL — free, delayed deletes
  • Transactions — 100 actions, all-or-nothing
  • Client token — safe retries
