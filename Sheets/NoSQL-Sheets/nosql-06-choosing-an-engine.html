Sheet 06

Choosing an Engine

MongoDB · Redis · DynamoDB · Cassandra · Neo4j · Elasticsearch · managed vs self-hosted · comparison table

Data Shape First, Then Operations

Pick the engine whose data model fits your top access patterns, then weigh the practical side: managed or self-hosted, cloud lock-in, the licence, the cost model and what your team already knows. Managed services remove most of the hard parts of running a distributed database, so start there unless you have a reason not to. Run them all locally with Docker while you learn.

Notes

  • Licences differ: MongoDB SSPL, Redis 8 AGPLv3 / RSAL / SSPL, Valkey BSD, Cassandra Apache 2.0, Neo4j Community GPLv3
  • DynamoDB exists only on AWS
  • Check the licence before offering a database as a service

Every Engine Locally

# compose.yaml: the engines in this set, for local development
services:
  mongo:
    image: mongo:8
    ports: ["27017:27017"]
  redis:
    image: redis:8
    ports: ["6379:6379"]
  dynamodb:
    image: amazon/dynamodb-local
    ports: ["8000:8000"]
  cassandra:
    image: cassandra:5.0
    ports: ["9042:9042"]
    environment:
      MAX_HEAP_SIZE: 1G
      HEAP_NEWSIZE: 256M
  neo4j:
    image: neo4j:latest
    ports: ["7474:7474", "7687:7687"]
    environment:
      NEO4J_AUTH: neo4j/shop-pass-123

# docker compose up -d

Code Explained

DynamoDB Local accepts any credentials; point tools at --endpoint-url http://localhost:8000
Cassandra takes about a minute to start; the heap settings keep it small on a laptop
Neo4j Browser runs at port 7474; drivers connect over Bolt on 7687
Neo4j requires a password of at least 8 characters

SQL Equivalent

  • PostgreSQL stays the safe default for relational data; add a NoSQL engine for a specific job, not instead of thinking
  • Many teams run one SQL database plus Redis and nothing else · See SQL 1

Across Engines

  • MongoDB Atlas on AWS, GCP or Azure; or self-host Community / Enterprise
  • Redis Redis Cloud, ElastiCache, MemoryDB, or self-host; Valkey for a BSD licence
  • DynamoDB AWS only; DynamoDB Local for development
  • Cassandra self-host, DataStax Astra, or Amazon Keyspaces (CQL-compatible)
  • Neo4j Aura (managed) or self-host Community / Enterprise

In Your Code

  • Node new MongoClient(uri) · createClient() · new cassandra.Client({...}) · neo4j.driver(uri)
  • Python MongoClient(uri) · redis.Redis() · boto3.resource("dynamodb") · GraphDatabase.driver(uri)
  • Java MongoClients.create(uri) · new JedisPooled() · CqlSession.builder().build() · GraphDatabase.driver(uri)

⚠ Common Mistakes

  • Choosing by popularity instead of access patterns
  • Self-hosting a distributed database with no one to run it
  • Being surprised by lock-in after building on DynamoDB

✓ Tips & Best Practices

  • Prototype your top three patterns in the candidates
  • Use the compose file to try engines side by side
  • Prefer managed services in production

Quick Summary

  • Fit the data model first
  • Then: managed, licence, cost
  • Start managed
  • Try locally with Docker
