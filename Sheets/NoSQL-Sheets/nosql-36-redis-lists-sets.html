Lists & Sets

LPUSH / RPUSH · LRANGE · BLPOP · SADD · SMEMBERS · SINTER · queues

Ordered Lists, Unique Sets

A list is an ordered sequence that allows duplicates: push and pop at either end in constant time, so it works as a queue, a stack or a "recent items" list capped with LTRIM. Blocking pops (BLPOP) let workers wait for jobs. A set holds unique, unordered strings: membership tests are instant and SINTER, SUNION and SDIFF combine sets, which suits tags, "who viewed this" and shared interests.

Notes

  • LMOVE moves an item atomically, the basis of a reliable queue
  • Indexing into the middle of a long list is slow (O(n))
  • Sets can't hold duplicates; adding one is ignored
  • For real job queues, streams (sheet 38) add acknowledgements

Lists and Sets

# lists: ordered, duplicates allowed
> RPUSH queue:emails "order:1001" "order:1002"
> LPUSH recent:customer:42 "product:7"
> LTRIM recent:customer:42 0 9                # keep the newest 10
> LRANGE recent:customer:42 0 -1
> LPOP queue:emails
"order:1001"
> BLPOP queue:emails 5                        # wait up to 5 s
> LMOVE queue:emails queue:processing LEFT RIGHT
> LLEN queue:emails

# sets: unique, unordered
> SADD product:7:tags sql reference books
(integer) 3
> SISMEMBER product:7:tags sql
(integer) 1
> SMEMBERS product:7:tags
> SADD customer:42:viewed 7 3 21
> SADD customer:43:viewed 7 22
> SINTER customer:42:viewed customer:43:viewed
1) "7"
> SDIFF customer:42:viewed customer:43:viewed
> SCARD product:7:tags
> SRANDMEMBER product:7:tags 2

Code Explained

LPUSH + LTRIM keeps a fixed-length "recently viewed" list
BLPOP returns as soon as an item arrives, or nil after the timeout
LMOVE to a processing list means a crashed worker's job isn't lost
SINTER finds products both customers viewed

SQL Equivalent

  • A list ↔ a table with a position column · a set ↔ a table with a UNIQUE constraint
  • SINTER / SUNION / SDIFF ↔ INTERSECT / UNION / EXCEPT · See SQL 43

Across Engines

  • MongoDB arrays with $push / $addToSet; $setIntersection in pipelines
  • DynamoDB L lists and SS / NS sets; ADD to a set
  • Cassandra list<> and set<> collection columns
  • Neo4j list properties; shared neighbors through MATCH patterns

⚠ Common Mistakes

  • Using LRANGE 0 -1 on huge lists
  • Using SMEMBERS on sets with millions of members
  • Building a job queue on RPOP without a processing list

✓ Tips & Best Practices

  • Cap lists with LTRIM right after each push
  • Use SSCAN for big sets
  • Store the result of a costly SINTER with SINTERSTORE and a TTL
