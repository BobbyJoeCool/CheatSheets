Query Operators

$eq · $gt / $lt · $in · $and / $or · $exists · $type · $regex

Conditions Beyond Equality

Query operators start with $. Comparison operators ($gt, $lte, $in, $ne) test a field's value; logical operators ($or, $and, $nor, $not) combine conditions; element operators ($exists, $type) test whether and how a field is stored. $regex matches patterns and $expr lets you compare two fields with aggregation expressions.

Notes

  • { f: null } matches null and missing fields
  • Anchored, case-sensitive regexes (/^Ada/) can use an index
  • $ne and $nin also match documents without the field
  • $expr usually can't use indexes well

Comparison, Logical, Element & Regex

db.products.find({ price: { $gte: 10, $lte: 50 } })
db.products.find({ category: { $in: ["Books", "Electronics"] } })
db.products.find({ category: { $nin: ["Clearance"] } })
db.products.find({ stock: { $ne: 0 } })        // also matches missing stock

db.orders.find({ $or: [ { status: "pending" }, { total: { $gt: 100 } } ] })
db.orders.find({ $and: [                      // needed to combine two $or
  { $or: [ { status: "pending" }, { status: "paid" } ] },
  { $or: [ { total: { $gt: 100 } }, { rush: true } ] } ] })
db.products.find({ price: { $not: { $gt: 50 } } })

db.customers.find({ email: { $exists: false } })
db.products.find({ price: { $type: "decimal" } })

db.customers.find({ name: { $regex: "^ada", $options: "i" } })
db.customers.find({ name: /^Ada/ })                  // literal form

// compare two fields of the same document
db.products.find({ $expr: { $lt: ["$stock", "$reorderLevel"] } })

Code Explained

Two operators on one field ($gte, $lte) form a range
$and is implicit unless you need the same key twice, such as two $or clauses
$not also matches documents where the field is missing
In $expr, "$stock" means "the value of the stock field"

SQL Equivalent

  • $in ↔ IN · $exists: false ↔ IS NULL (roughly) · $regex ↔ ~ or LIKE
  • $expr ↔ WHERE stock < reorder_level · See SQL 18, 19

Across Engines

  • Redis no operators on values; ranges come from sorted sets (ZRANGE … BYSCORE)
  • DynamoDB key conditions allow =, <, BETWEEN, begins_with on the sort key; filters allow more but run after the read
  • Cassandra ranges on clustering columns only; IN on the partition key
  • Neo4j WHERE p.price >= 10 AND p.category IN ['Books']; =~ for regex

In Your Code

  • Node find({ price: { $gte: 10, $lte: 50 } })
  • Python find({"price": {"$gte": 10, "$lte": 50}})
  • Java find(and(gte("price", 10), lte("price", 50)))

Comparison

OperatorMatches
$eq / $neEqual / not equal
$gt / $gteGreater / or equal
$lt / $lteLess / or equal
$in / $ninIn / not in a list

Logical & Element

OperatorMatches
$and / $orAll / any condition
$norNone of the conditions
$notNegates one operator
$existsField present or absent
$typeField has a BSON type
$regexPattern match
$exprAggregation expression

⚠ Common Mistakes

  • Expecting $ne: 0 to skip documents without the field
  • Unanchored or case-insensitive regexes on big collections
  • Writing { price: { $gt: 10 }, price: { $lt: 50 } }: the second key overwrites the first

✓ Tips & Best Practices

  • Put both bounds in one operator document
  • Use $in instead of long $or chains on one field
  • Store a lowercase copy of a field for fast case-insensitive matches

Quick Summary

  • $gt $lt $in — compare
  • $or $and $not — combine
  • $exists $type — element
  • $expr — compare fields
