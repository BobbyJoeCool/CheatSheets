JSON, Search & Vectors

JSON.SET · JSON.GET · FT.CREATE · FT.SEARCH · vector fields · hybrid search

Documents and Queries in Redis

Redis Open Source 8 includes JSON (store and update nested documents by JSONPath) and the Query Engine (formerly RediSearch). FT.CREATE indexes hashes or JSON documents by key prefix with TEXT, TAG, NUMERIC, GEO and VECTOR fields; FT.SEARCH filters, ranks and sorts, and FT.AGGREGATE groups and computes. The index updates automatically as matching keys change.

Notes

  • Commands below are wrapped for space; type each on one line
  • TAG fields match exact values: @category:{Books}
  • Vectors are passed as raw float32 bytes in PARAMS
  • Indexes live in memory alongside the data

JSON, FT.CREATE & FT.SEARCH

> JSON.SET product:7 $ '{"name":"SQL Pocket Guide","category":"Books",
    "price":19.99,"tags":["sql"]}'
> JSON.GET product:7 $.price
"[19.99]"
> JSON.NUMINCRBY product:7 $.price -2
> JSON.ARRAPPEND product:7 $.tags '"reference"'

# index every key starting with product:
> FT.CREATE idx:products ON JSON PREFIX 1 product: SCHEMA
    $.name AS name TEXT
    $.category AS category TAG
    $.price AS price NUMERIC SORTABLE
    $.embedding AS embedding VECTOR HNSW 6 TYPE FLOAT32 DIM 384 DISTANCE_METRIC COSINE

# full-text + tag + range, sorted
> FT.SEARCH idx:products "@name:(pocket guide) @category:{Books} @price:[10 30]"
    RETURN 2 name price SORTBY price ASC LIMIT 0 10

# group and count
> FT.AGGREGATE idx:products "*" GROUPBY 1 @category REDUCE COUNT 0 AS n

# vector nearest neighbors with a filter
> FT.SEARCH idx:products "(@category:{Books})=>[KNN 5 @embedding $v AS score]"
    PARAMS 2 v "<384 float32 bytes>" SORTBY score DIALECT 2

Code Explained

JSONPath $.price returns an array because paths can match several values
The index covers keys created before and after FT.CREATE
@price:[10 30] is an inclusive numeric range
The part before => filters; KNN then ranks the survivors by vector distance

SQL Equivalent

  • JSON ↔ a jsonb column with -> / ->> · FT.SEARCH ↔ tsvector @@ tsquery
  • Vector KNN ↔ pgvector ORDER BY embedding <=> $1 LIMIT 5 · See SQL 78, 80

⚠ Common Mistakes

  • Indexing text that should be TAG (ids, categories)
  • Forgetting SORTABLE on fields you sort by
  • Index prefixes that don't match your key names

✓ Tips & Best Practices

  • Use TAG for exact values and TEXT for words
  • Return only needed fields with RETURN
  • Check an index with FT.INFO idx:products
