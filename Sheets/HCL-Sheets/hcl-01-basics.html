A Config Language Built for Tools

HCL (HashiCorp Configuration Language) is a toolkit for config files that people write by hand. A file is a body of attributes (name = value) and blocks (type "label" { … }). HCL 2 adds real expressions: math, conditionals, for loops and templates. The app that reads the file decides which blocks, variables and functions exist.

Notes

  • Files are UTF-8; extension .hcl or a tool's own (.pkr.hcl, .nomad.hcl, .tf)
  • A newline ends an attribute; inside ( ), [ ] and { } newlines are allowed
  • Three comment styles: # and // to the end of the line, /* … */ for spans
  • Every native file has a JSON twin, .hcl.json (sheet 10)
  • HCL 1 (before 2019) had no expressions; apps like Terraform added them inside "${…}" strings (HIL)

app.hcl

# Service settings
service_name = "inventory"
tags         = ["api", "v2"]
enabled      = true

// blocks have a type and optional labels
server "web" {
  port    = 8080
  timeout = "30s"
}

/* expressions are first-class in HCL 2 */
max_conns = var.replicas * 100
log_level = var.debug ? "debug" : "info"

Code Explained

service_name = "inventory" — an attribute: a name, =, an expression
server "web" { … } — a block of type server with one label, "web"
var.replicas works only because the app puts var in scope; HCL defines no variables itself
#, // and /* */ are all comments; # is the usual style

Same Data In…

  • JSON {"service_name": "inventory", "server": {"web": {"port": 8080, "timeout": "30s"}}}
  • YAML service_name: inventory / server: {web: {port: 8080, timeout: 30s}}
  • TOML service_name = "inventory" / [server.web] / port = 8080

Gotcha

  • Attributes don't see each other: max_conns = replicas * 100 fails unless the app exposes replicas as a variable
  • A long expression can't continue on the next line by itself; wrap it in ( ) first

⚠ Common Mistakes

  • Expecting one attribute to read another without a variable from the app
  • Splitting a long expression across lines without parentheses
  • Mixing // and # comment styles in one file

✓ Tips & Best Practices

  • Use # for comments; it is the common style in HashiCorp docs
  • Check which HCL version your tool parses: Vault and Consul config still use HCL 1
  • Run the tool's fmt command (packer fmt, nomad fmt) to settle layout

Quick Summary

  • name = expr — attribute
  • type "label" { } — block
  • # // /* */ — comments
  • the app — defines variables, functions and block types
