Heredocs & Multi-line Text

<<EOT · <<-EOT · indent stripping · templates inside · embedded JSON / scripts · trailing newline

Multi-line Strings

A heredoc writes a multi-line string: <<EOT on the attribute line, the text, then EOT alone on its own line. <<-EOT (with a dash) strips the leading whitespace every line shares, so the text can be indented with the code. Heredocs are templates too, so ${ } and %{ } work inside.

Notes

  • The marker is any identifier: EOT, EOF, JSON, SCRIPT
  • The text's final newline is kept unless a ~ strip marker removes it
  • With <<-, the closing marker may be indented
  • Backslashes are literal in heredocs; \n stays two characters
  • Escape interpolation with $${ when embedding shell scripts

Heredoc Forms

user_data = <<EOT
#!/bin/bash
echo "Hello from ${var.name}"
EOT

policy = <<-JSON
  {
    "Version": "2012-10-17",
    "Statement": []
  }
  JSON

script = <<-SH
  for f in *.log; do
    echo "$${f}"          # shell variable, escaped
  done
  SH

motd = <<-EOT
  %{ for u in var.users ~}
  Welcome, ${u}
  %{ endfor ~}
  EOT

Code Explained

<<EOT keeps every space; the text starts at column 1
<<-JSON strips the two-space indent shared by every line
$${f} passes ${f} through to the shell untouched
~} on the directives keeps the loop from adding blank lines

Same Data In…

  • YAML user_data: | block literal holding the same lines
  • JSON {"user_data": "#!/bin/bash\necho \"Hello from web\"\n"}

Gotcha

  • <<- counts leading whitespace by character; mixing tabs and spaces strips less than you expect
  • A shell ${var} in a heredoc is read as HCL interpolation; escape it as $${var}

⚠ Common Mistakes

  • Putting text on the same line as <<EOT; content starts on the next line
  • Building JSON by hand in a heredoc and breaking it with a quote inside a variable
  • Forgetting the trailing newline when the app compares the value exactly

✓ Tips & Best Practices

  • Prefer the app's jsonencode() / yamlencode() over hand-written JSON heredocs
  • Use a descriptive marker (JSON, SCRIPT) so readers know what is inside
  • Use <<- so heredocs follow the code's indentation

Quick Summary

  • <<EOT … EOT — multi-line string
  • <<-EOT — strip the shared indent
  • ${ } / %{ } — templates work inside
  • $${ — escape for shell scripts
