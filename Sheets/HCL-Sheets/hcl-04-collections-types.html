Collections & Types

tuple [ ] · object { } · = or : · (expr) keys · list · set · map · object · list(string)

Brackets Build Values, the App Picks Types

Square brackets build a tuple ([1, "a"]) and braces build an object ({ name = "web" }). HCL's type system (cty) adds list, set and map types. When an app expects list(string) or map(number), it converts the tuple or object you wrote into that type, or reports an error.

Notes

  • Object items may use = or : and may be separated by commas or newlines
  • A bare word as a key is a literal string: { name = 1 } has the key "name"
  • Wrap a key in parentheses to compute it: { (var.k) = 1 }
  • Trailing commas are allowed in tuples and objects
  • Lists and tuples are ordered; sets are unordered with no duplicates

Tuples, Objects & Type Constraints

ports    = [80, 443]                      # tuple → list(number)
mixed    = [1, "two", true]               # tuple of three types
tags     = { team = "web", tier = "1" }   # object → map(string)
json_ish = { "name": "web", "port": 80 }  # ':' also works
computed = { (var.env) = "active" }       # key from a variable

server = {
  name   = "web"
  ports  = [80, 443]
  labels = { app = "nginx" }
}

# a typed variable (type syntax is an HCL extension)
variable "zones" {
  type    = list(string)
  default = ["a", "b", 3]                 # 3 → "3"
}

Code Explained

[80, 443] is a tuple; the app converts it to list(number) if that is what it wants
Parentheses force a key to be evaluated; a bare env would be the literal key "env"
type = list(string) is a type constraint, so the default's 3 becomes "3"
variable blocks come from Terraform and Packer; they read type constraints with HCL's optional typeexpr extension

Same Data In…

  • JSON {"ports": [80, 443], "tags": {"team": "web", "tier": "1"}}
  • YAML ports: [80, 443] / tags: {team: web, tier: "1"}
  • TOML ports = [80, 443] / tags = { team = "web", tier = "1" }

Gotcha

  • A mixed tuple becomes a list only if every element converts to one type: [1, "a", true] → list(string) works, [1, {}] doesn't
  • Sets have no order or index: zones[0] fails on a set(string)

⚠ Common Mistakes

  • Expecting { env = 1 } to use a variable named env; bare keys are literal, so write (env)
  • Indexing a set with [0]
  • Forgetting that { } becomes a map or an object depending on what the app expects

✓ Tips & Best Practices

  • Use map(string) for open-ended tags and object({…}) when the keys are fixed
  • Keep tuples single-typed so they convert cleanly to lists
  • Use = in objects; keep : for data pasted from JSON

Quick Summary

  • [ ] — tuple, converts to list or set
  • { } — object, converts to map
  • (expr) = — computed key
  • list(string) — type constraint
