Sheet 10

HCL JSON Syntax

.hcl.json · blocks as nested objects · labels as keys · strings as templates · arrays for repeated blocks · "//"

The Same Config, Machine-Friendly

Every HCL file has an equivalent in HCL JSON syntax, meant for config that programs generate. Attributes become properties, blocks become nested objects keyed by type and then label, and repeated blocks become arrays. Where the app evaluates them, string values are parsed as templates, so expressions go inside "${…}".

Notes

  • File names end in .json: app.hcl.json, main.tf.json, build.pkr.json
  • The app's schema tells the parser which properties are blocks
  • Numbers, true, false and null map to their JSON forms
  • A lone "${var.x}" keeps its type, just like in native syntax
  • HCL ignores "//" properties in body objects, so they act as comments

Native Syntax

server "web" {
  port  = 8080
  hosts = ["a", "b"]
  url   = "https://${var.host}"
}

listener "tcp" { port = 80 }
listener "tcp" { port = 443 }

Same File in JSON Syntax

{
  "//": "generated by deploy.py",
  "server": {
    "web": {
      "port": 8080,
      "hosts": ["a", "b"],
      "url": "https://${var.host}"
    }
  },
  "listener": {
    "tcp": [
      { "port": 80 },
      { "port": 443 }
    ]
  }
}

Code Explained

"server": {"web": {…}} — block type, then label, then body
The two listener "tcp" blocks become an array under the label
"https://${var.host}" is evaluated as a template unless the app reads that field literally
"//" is skipped in body objects; inside an object value it's an ordinary key

Same Data In…

  • YAML server: {web: {port: 8080, hosts: [a, b]}} / listener: {tcp: [{port: 80}, {port: 443}]}
  • TOML [server.web] / port = 8080 / [[listener.tcp]] / port = 80

Gotcha

  • A JSON property's meaning depends on the schema: the same { … } is a block in one place and an object value in another
  • In an evaluated string, a literal ${ still needs escaping as $${, just like native syntax

⚠ Common Mistakes

  • Writing "x": var.y without quotes; JSON syntax needs the template string "${var.y}"
  • Hand-editing generated .hcl.json files instead of fixing the generator
  • Defining the same block in a native file and a JSON file that the app loads together

✓ Tips & Best Practices

  • Generate .hcl.json with a real JSON library, never with string concatenation
  • Keep generated files beside native ones only if the app loads both (Terraform does)
  • Run hcl2json on a native file to see a block's JSON shape; edge cases can differ (sheet 14)

Quick Summary

  • .hcl.json — JSON twin of native syntax
  • type → label → body — block nesting
  • arrays — repeated blocks
  • "${…}" — expressions inside strings
