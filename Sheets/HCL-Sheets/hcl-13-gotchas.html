Gotchas & Common Errors

tags = { } vs tags { } · duplicate attributes · single quotes · newlines · + on strings · a-b · HCL 1 habits

Where HCL Trips People Up

Most HCL surprises come from three places: the app's schema (attribute or block, how many labels), types (string conversion, unifying conditional branches, null) and layout (newlines ending expressions, dashes inside names). The rest are HCL 1 habits carried into HCL 2 files.

Notes

  • The parser returns diagnostics with file, line and column, and can report several
  • "Unsupported argument" and "Unsupported block type" come from the app's schema, not HCL
  • Type errors appear when the app converts a value, sometimes far from where it was written
  • null is still a value; the app decides whether it means unset
  • HCL 1 files often parse in HCL 2 but behave differently

Five Broken Lines and Their Fixes

# 1. block vs attribute (the app's schema decides)
tags { team = "web" }        # ERROR if tags is an attribute
tags = { team = "web" }      # correct here

# 2. single quotes
name = 'web'                 # ERROR: use "web"

# 3. a newline ends the attribute
size = var.big
  ? "large" : "small"        # ERROR: wrap it in ( )

# 4. joining strings
id = "web" + "-1"            # ERROR: "web" isn't a number
id = "${var.prefix}-1"       # correct

# 5. subtraction needs spaces
free = local.total-local.used    # reads a name "total-local"
free = local.total - local.used  # correct

Code Explained

1: apps reject a block where the schema has an attribute, and the reverse
3: outside brackets a newline ends the expression; wrap multi-line conditionals in ( )
4: + only adds numbers; use a template to join text
5: a dash right after a name becomes part of the name

Same Data In…

  • JSON "tags": {"team": "web"} — in HCL JSON both forms look the same, so only the schema decides
  • YAML name: 'web' is fine in YAML; HCL needs double quotes

Gotcha

  • Terraform lets some nested blocks also be set as attributes (ingress = [ … ]); other apps don't
  • Packer, Nomad and Terraform ship different function lists; a call that validates in one can fail in another

HCL 1 Habits in HCL 2

HCL 1HCL 2
"${var.x}"var.x
enabled = "true"enabled = true

foo = { } or foo { }the schema allows one form

⚠ Common Mistakes

  • Copying blocks between tools and assuming the schema matches
  • Keeping HCL 1 "${…}" wrappers around every value
  • Writing null to empty a list; use [] when the app needs an empty list

✓ Tips & Best Practices

  • Read the app's schema docs to know whether a name is an argument or a block
  • Run the tool's validate command (packer validate, nomad job validate) before applying
  • Keep conditionals on one line or wrap them in parentheses

Quick Summary

  • the schema — decides attribute vs block
  • " only — no single quotes
  • ( ) — needed for multi-line expressions
  • spaces around - — or it is part of a name
