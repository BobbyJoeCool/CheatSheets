Attributes & Blocks

name = expression · block type · labels · nested bodies · one-line blocks · repeated blocks

The Two Building Blocks

A body holds attributes and blocks. An attribute assigns one expression to a name, and each name can appear only once per body. A block has a type, zero or more labels and its own body in { }, so blocks nest. The app's schema decides which names and block types are allowed and how many labels each block takes.

Notes

  • Labels can be quoted strings or bare identifiers: server "web" or server web
  • Blocks can repeat: two listener blocks make a list of listeners
  • A one-line block holds at most one attribute: retry { max = 3 }
  • Attribute order doesn't matter; the order of repeated blocks usually does
  • An attribute can hold an object (labels = { … }); that is not a block

Nomad-Style Nesting

job "web" {                    # type "job", one label
  datacenters = ["dc1"]

  group "frontend" {           # nested block
    count = 2

    task "nginx" {             # deeper still
      driver = "docker"
      config {                 # block with no labels
        image = "nginx:1.27"
      }
    }
  }
}

listener "tcp" { address = "0.0.0.0:8200" }   # one-line
listener "unix" { address = "/run/vault.sock" }

labels = { team = "web", tier = "frontend" }  # attribute

Code Explained

job "web" — block type job with the label "web"; Nomad expects exactly one label here
config { … } — a block with no labels
Two listener blocks repeat the type; the app reads them as a list
labels = { … } uses =, so it is an attribute holding an object, not a block

Same Data In…

  • JSON {"job": {"web": {"datacenters": ["dc1"], "group": {"frontend": {"count": 2}}}}}
  • YAML job: / web: / datacenters: [dc1] / group: {frontend: {count: 2}}

Gotcha

  • labels = { … } and labels { … } aren't interchangeable; the app's schema says which one it expects
  • The same attribute twice in one body is an error, even with the same value

⚠ Common Mistakes

  • Writing config = { … } where the app expects a config { } block, or the other way round
  • Giving a block the wrong number of labels; the app's schema fixes the count
  • Putting two attributes in a one-line block

✓ Tips & Best Practices

  • Quote labels; bare labels work, but quoted ones are the common style
  • Keep repeated blocks in the order the app should apply them
  • Put attributes before nested blocks inside a body

Quick Summary

  • attribute — name = expr, once per body
  • block — type "label" { body }, repeatable
  • labels — quoted or bare, count set by the app
  • one-line block — at most one attribute
