References, Indexing & Function Calls

variables from the app · .attr · [key] · legacy .0 · fn(args) · ... expansion · try / can · dynamic

The App Supplies Names and Functions

HCL defines how references and calls are written, not what exists. The app puts variables in scope (Terraform's var.region, Packer's local.ts) and supplies a function table. HCL also ships optional extensions that many apps turn on: try and can, dynamic blocks, type expressions and user-defined functions.

Notes

  • Variables are immutable; names in a for expression shadow outer ones
  • .name reads an attribute; [key] indexes by number or string
  • list.0 is a legacy index form, the same as list[0]
  • fn(xs...) expands a list into separate arguments
  • Function names and variable names live in separate namespaces

References, Calls & dynamic

# references (names come from the app)
region  = var.region
first   = var.zones[0]            # same as var.zones.0
tag     = var.tags["team"]
port    = var.server.ports[1]

# calls (functions come from the app)
biggest = max(var.sizes...)       # max(3, 9, 4) → 9
shout   = upper(var.name)
port2   = try(var.server.port, 8080)
has_tls = can(var.server.tls.cert)

# dynamic blocks (dynblock ext; no meta-args like lifecycle)
dynamic "listener" {
  for_each = var.ports
  content {
    port = listener.value
  }
}

Code Explained

var.tags["team"] and var.tags.team read the same map key
max(var.sizes...) spreads the list into three separate arguments
try(a, b) returns the first argument that evaluates without an error; can() returns true or false
dynamic "listener" makes one listener block per item; listener.value is the current item

Same Data In…

  • JSON {"first": "a", "biggest": 9, "port2": 8080, "has_tls": false}
  • YAML biggest: 9 / port2: 8080 / has_tls: false

Gotcha

  • A function that works in Terraform may not exist in another HCL app; check that app's function list
  • try() catches evaluation errors like a missing attribute; the app can reject invalid references first

⚠ Common Mistakes

  • Assuming Terraform's function list is part of HCL
  • Wrapping a large expression in try() and hiding real errors
  • Forgetting ... and passing the whole list as one argument

✓ Tips & Best Practices

  • Look up the app's own function reference; Terraform, Packer and Nomad each publish one
  • Use try(x, default) around the one lookup that may fail, nothing more
  • Set iterator = l in a dynamic block when the block label is long

Quick Summary

  • var.x, obj.a, xs[0] — references
  • fn(args) / fn(xs...) — calls
  • the app — supplies variables and functions
  • extensions — try/can, dynamic, types
