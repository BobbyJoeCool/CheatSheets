Parametrize

@pytest.mark.parametrize · multiple arguments · ids= · pytest.param(..., marks=) · stacking decorators · indirect=

One Test, Many Cases

@pytest.mark.parametrize runs a test once for each set of arguments, and each run is reported as its own test with its own ID. It replaces copy-pasted tests and for loops that stop at the first failure. Stack decorators to test every combination, and wrap a case in pytest.param to give it an ID or a mark.

Notes

  • Argument names go in one comma-separated string
  • IDs appear in brackets: test_total[empty]
  • Select one case with -k empty or its node ID
  • indirect=True sends values to a fixture instead of the test

Under the Hood

  • parametrize expands one test function into several items during collection
  • IDs are built from the values (numbers, strings) or argN, unless ids= names them
  • strict_parametrization_ids (in strict) rejects duplicate IDs

Cases in a Table

import pytest

@pytest.mark.parametrize(
    "prices, discount, expected",
    [
        ([], 0, 0),
        ([10, 10], 0.25, 15.0),
        ([9.99], 0, 9.99),
        pytest.param([1], 0.999, 0.0, id="rounds-to-zero"),
        pytest.param([1], 1.5, None, marks=pytest.mark.xfail(raises=ValueError)),
    ],
    ids=["empty", "quarter-off", "one-item", None, None],
)
def test_total(prices, discount, expected):
    assert total(prices, discount) == expected

@pytest.mark.parametrize("currency", ["USD", "EUR"])
@pytest.mark.parametrize("country", ["US", "DE", "JP"])
def test_tax(country, currency):     # 6 combinations
    assert tax_rate(country, currency) >= 0

Code Explained

Each tuple is one case; its values map to the names in order
pytest.param(..., id=) names one case; None in ids keeps the generated ID
Stacked decorators multiply: 3 countries × 2 currencies = 6 tests
indirect=True passes "sqlite" to the db fixture as request.param

unittest Equivalent

  • parametrize → a loop with with self.subTest(case=c): inside one test
  • each case reported separately → subTest reports failures per case but counts one test
  • stacked decorators → nested loops of subTest

Prefer / Avoid

  • a for loop of asserts → parametrize
  • unreadable IDs like test_x[case3] → ids= or pytest.param(id=)
  • copy-pasted tests differing by one value → one parametrized test

⚠ Common Mistakes

  • Passing argument names as a list of one string with commas missing: "prices discount"
  • Building huge cartesian products with stacked decorators that take minutes
  • Mutable defaults in case data (a shared list) that one case modifies

✓ Tips & Best Practices

  • Put the expected value in each case so the table reads as a spec
  • Give cases IDs that describe the situation, not the values
  • Quote node IDs with brackets in the shell: "…::test_total[empty]"

Quick Summary

  • parametrize("a, b", [...]) — one test per case
  • ids= / pytest.param(id=) — readable names
  • stacked — every combination
  • indirect=True — send values to a fixture
