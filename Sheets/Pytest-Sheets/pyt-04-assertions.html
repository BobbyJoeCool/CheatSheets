Sheet 04

Assertions & Failure Output

assert · assertion messages · introspected diffs · -vv · pytest.approx · comparing dicts / lists

Plain assert, Detailed Failures

pytest rewrites assert statements in test modules so a failure prints every sub-expression's value: both sides of ==, the differing dict keys, the first differing list index. Add a message after a comma for context. Floating-point results should use pytest.approx, which compares within a tolerance instead of exactly.

Notes

  • -vv prints full diffs instead of truncated ones
  • Compare whole structures (== {...}) to get a key-by-key diff
  • approx works on numbers, lists, dicts and NumPy arrays
  • Helper modules need pytest.register_assert_rewrite to get the same output

Under the Hood

  • Assertion rewriting happens at import time: pytest's import hook rewrites the AST of test modules and conftest.py
  • Plain helper modules imported by tests are not rewritten, so their asserts show only AssertionError
  • Call pytest.register_assert_rewrite("tests.helpers") in conftest.py before importing them

Asserts and Their Failure Output

def test_user_dict():
    assert get_user(1) == {"id": 1, "name": "Ann", "admin": False}
# E  AssertionError: assert {...} == {...}
# E    Differing items:
# E    {'admin': True} != {'admin': False}

def test_list():
    assert sorted(tags()) == ["a", "b", "c"]
# E    At index 1 diff: 'z' != 'b'

def test_with_message():
    items = cart.items()
    assert len(items) == 2, f"cart had {items!r}"

def test_float():
    assert 0.1 + 0.2 == pytest.approx(0.3)
    assert total() == pytest.approx(19.99, abs=0.01)
    assert [0.1 + 0.2, 0.3] == pytest.approx([0.3, 0.3])

def test_membership_and_identity():
    assert "error" not in log_text
    assert result is None

Code Explained

Comparing whole dicts shows only the differing keys, which is clearer than asserting each key
The message after the comma prints under the failure; use it for context the values don't show
approx defaults to a relative tolerance of 1e-6; set abs= or rel= explicitly for money and sensors
is None checks identity, which is right for None, True and False

unittest Equivalent

  • assert a == b → self.assertEqual(a, b)
  • assert x in y → self.assertIn(x, y)
  • pytest.approx → self.assertAlmostEqual(a, b, places=7)
  • assert x is None → self.assertIsNone(x)

Prefer / Avoid

  • assert a == b == c chains that hide which one failed → separate asserts
  • assert 0.1 + 0.2 == 0.3 → == pytest.approx(0.3)
  • assert len(x) > 0 → assert x when emptiness is the point

⚠ Common Mistakes

  • Wrapping a comparison in parentheses with a message: assert (a == b, "msg") is always true (a tuple)
  • Comparing floats with == and getting random failures
  • Asserting inside a helper module and getting a bare AssertionError with no values

✓ Tips & Best Practices

  • Assert on whole objects or dicts to get one readable diff
  • Use -vv when a diff is truncated with ...Full output truncated
  • Use assert result == expected with expected named in the test, so the failure reads well

Quick Summary

  • assert — rewritten for rich output
  • message — assert cond, "context"
  • pytest.approx — floats within tolerance
  • -vv — full diffs
