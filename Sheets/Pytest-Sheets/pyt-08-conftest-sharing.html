Sheet 08

conftest.py & Sharing Fixtures

conftest.py hierarchy · overriding fixtures · factory fixtures · params= fixtures · request.param · fixture name=

Fixtures Every Test in a Folder Can Use

Fixtures in a conftest.py file are available to every test in that folder and below, with no import. A deeper conftest.py can override a fixture by defining one with the same name. A factory fixture returns a function so a test can build several objects with different arguments. A parametrized fixture (params=) runs every test that uses it once per value.

Notes

  • Never import from conftest.py; pytest loads it for you
  • Root tests/conftest.py holds project-wide fixtures
  • Hooks (sheet 17) also live in conftest.py
  • Factories avoid writing one fixture per variation

Under the Hood

  • pytest loads conftest.py files from the rootdir down to each test's folder before collecting it
  • When names clash, the fixture closest to the test wins
  • Each conftest.py is registered as a plugin, which is why it can hold hooks

tests/conftest.py

import pytest
from shop.models import User

@pytest.fixture
def make_user(db):
    """Factory: build users with any fields."""
    created = []
    def _make(name="ann", admin=False, **extra):
        user = User.create(db, name=name, admin=admin, **extra)
        created.append(user)
        return user
    yield _make
    for user in created:            # clean up everything it made
        user.delete()

@pytest.fixture(params=["sqlite", "postgres"], ids=["lite", "pg"])
def db(request):
    conn = connect(request.param)   # runs every test twice
    yield conn
    conn.close()

# tests/admin/conftest.py — override for this folder only
@pytest.fixture
def make_user(make_user):           # wraps the parent fixture
    return lambda **kw: make_user(admin=True, **kw)

def test_two_users(make_user):
    a, b = make_user("ann"), make_user("bo")
    assert a.id != b.id

Code Explained

The factory tracks what it created so teardown can remove it
params= makes each test using db run as test_x[lite] and test_x[pg]
An override can request the fixture it overrides to extend it
Tests in tests/admin/ get the admin-by-default factory

unittest Equivalent

  • conftest.py → a shared BaseTestCase class every test inherits
  • factory fixture → helper methods like self.make_user()
  • params= fixture → no direct equivalent; loop with subTest or subclass per variant

Prefer / Avoid

  • from conftest import x → request x as a fixture
  • one fixture per variant (admin_user, guest_user…) → a factory fixture
  • huge root conftest.py → split per folder near the tests that use them

⚠ Common Mistakes

  • Importing fixtures from conftest.py, which registers them twice and can break overrides
  • Parametrizing a fixture that many tests use and doubling the suite's run time without noticing
  • A factory that never cleans up, leaving rows behind for the next test

✓ Tips & Best Practices

  • Use pytest --fixtures-per-test path::test to see which fixtures a test gets and from where
  • Read marks with request.node.get_closest_marker to configure a fixture per test
  • Keep fixtures next to the tests that use them; move them up only when shared

Quick Summary

  • conftest.py — fixtures for a folder tree
  • closest definition wins
  • factory fixture — return a function
  • params= + request.param — run per value
