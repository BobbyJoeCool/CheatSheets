Sheet 18

Coverage with pytest-cov

--cov=pkg · --cov-report=term-missing / html · --cov-branch · --cov-fail-under · [tool.coverage] · excluding lines

Which Lines the Tests Actually Ran

pytest-cov runs coverage.py during the test run and reports which lines (and branches) your tests executed. --cov=package picks what to measure; --cov-report picks the output; --cov-fail-under fails the run below a threshold. Coverage shows untested code; it doesn't prove tested code is correct.

Notes

  • pip install pytest-cov
  • Branch coverage catches if statements whose else path never ran
  • Settings go in [tool.coverage.*] in pyproject.toml
  • Works with xdist (-n) and combines results automatically

Measuring Coverage

pytest --cov=orders                           # terminal summary
pytest --cov=orders --cov-report=term-missing # + missing line numbers
pytest --cov=orders --cov-report=html         # htmlcov/index.html
pytest --cov=orders --cov-report=xml          # coverage.xml for CI tools
pytest --cov=orders --cov-branch --cov-fail-under=90

# Name                 Stmts   Miss Branch BrPart  Cover   Missing
# src/orders/cart.py      42      3     14      2    91%   55-57, 61->64
# TOTAL                  310     18     96      9    93%

# pyproject.toml
[tool.coverage.run]
branch = true
source = ["orders"]
omit = ["*/migrations/*"]

[tool.coverage.report]
fail_under = 90
show_missing = true
exclude_also = ["if TYPE_CHECKING:", "raise NotImplementedError"]

Code Explained

Missing lists line numbers never run; 61->64 is a branch never taken
--cov-branch adds the Branch and BrPart columns
exclude_also adds patterns to skip without replacing the defaults
Put --cov in CI scripts rather than addopts, since it slows local runs and the debugger

unittest Equivalent

  • pytest-cov → coverage run -m unittest then coverage report -m
  • --cov-fail-under → coverage report --fail-under=90
  • same coverage.py settings in both cases

Prefer / Avoid

  • chasing 100% with tests that assert nothing → meaningful tests on the risky code
  • line coverage only → --cov-branch
  • # pragma: no cover sprinkled everywhere → exclude_also patterns in config

⚠ Common Mistakes

  • Measuring the tests themselves and inflating the number; set source to your package
  • Treating a high percentage as proof of good tests
  • Leaving --cov in addopts and wondering why breakpoints are slow

✓ Tips & Best Practices

  • Open the HTML report and read the red lines in risky modules first
  • Use a modest fail_under and raise it over time
  • Combine with mutation testing (Testing set) to check the tests catch bugs

Quick Summary

  • --cov=pkg — measure
  • term-missing / html — see gaps
  • --cov-branch — branch coverage
  • --cov-fail-under — enforce a floor
