Plain Functions, Plain assert

pytest is the most widely used Python test runner. A test is a function whose name starts with test_, in a file named test_*.py, that uses the ordinary assert statement. pytest finds the tests, runs them, and when an assert fails it shows the values on both sides. No classes or special assert methods are needed, though pytest also runs existing unittest tests unchanged.

Notes

  • Install into the project's environment: pip install pytest or uv add --dev pytest
  • Run from the project root: pytest
  • Each . is a pass, F a failure, E an error in setup, s a skip
  • Exit code 0 = all passed; anything else fails CI

A First Test File

# src/shop/cart.py
def total(prices, discount=0.0):
    if not 0 <= discount < 1:
        raise ValueError("discount must be 0..1")
    return round(sum(prices) * (1 - discount), 2)

# tests/test_cart.py
from shop.cart import total

def test_total_adds_prices():
    assert total([2.50, 1.25]) == 3.75

def test_total_applies_discount():
    assert total([10, 10], discount=0.25) == 15.0

def test_empty_cart_is_zero():
    assert total([]) == 0

# $ pytest
# tests/test_cart.py ...                     [100%]
# ============ 3 passed in 0.02s ============

Code Explained

Test files start with test_ (or end in _test.py); test functions start with test_
Each test checks one behavior and reads like a sentence
pytest imports the test module, so the code under test must be importable (sheet 03)
The progress line shows one character per test, then a summary

unittest Equivalent

  • def test_x(): + assert → a unittest.TestCase subclass with def test_x(self): and self.assertEqual
  • pytest → python -m unittest discover
  • pytest runs unittest classes as they are, so you can migrate gradually

Prefer / Avoid

  • if result != 3.75: raise AssertionError → assert result == 3.75
  • one test that checks five things → five small tests with clear names
  • print to check results by eye → an assert that fails on its own

⚠ Common Mistakes

  • Naming a file cart_test_utils.py or a function check_total; pytest won't collect them
  • Installing pytest globally and running it against the wrong Python environment
  • Putting several unrelated checks in one test, so the first failure hides the rest

✓ Tips & Best Practices

  • Run python -m pytest if pytest picks up the wrong interpreter; it also adds the current folder to sys.path
  • Keep tests in a tests/ folder that mirrors the package layout
  • Name tests after the behavior: test_empty_cart_is_zero

Quick Summary

  • test_*.py + def test_* — collected automatically
  • assert — plain Python, rich failure output
  • pytest — run from the project root
  • exit code — 0 means everything passed
