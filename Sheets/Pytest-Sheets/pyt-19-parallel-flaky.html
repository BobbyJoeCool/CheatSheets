Sheet 19

Parallel & Flaky Tests

pytest-xdist -n auto · --dist loadscope · pytest-rerunfailures · pytest-randomly · --count · order dependence

Faster Runs, Honest Results

pytest-xdist runs tests in several worker processes: -n auto uses one per CPU core. Parallel runs expose tests that share state or depend on order, which is good. pytest-randomly shuffles order every run to find those dependencies, pytest-rerunfailures retries flaky tests while you fix them, and pytest-repeat runs a test many times to reproduce a flake.

Notes

  • Each xdist worker is a separate process with its own session fixtures
  • -p no:randomly turns shuffling off for one run
  • Reruns hide flakiness; treat them as a temporary measure
  • Tests that write to the same file or port will collide under -n

Under the Hood

  • xdist starts N workers; the controller hands out tests and collects reports
  • session-scoped fixtures run once per worker, not once overall
  • --dist loadscope keeps a module or class on one worker so module fixtures aren't rebuilt

Parallel, Shuffled, Retried

pip install pytest-xdist pytest-randomly pytest-rerunfailures pytest-repeat

pytest -n auto                       # one worker per core
pytest -n 4 --dist loadscope         # group by module / class
pytest -n auto --dist worksteal      # idle workers steal tests
pytest -p no:randomly                # fixed order for this run
pytest --randomly-seed=1234           # reproduce an order
pytest --reruns 2 --reruns-delay 1   # retry failures twice
pytest --count 50 -x tests/test_cache.py::test_expiry   # hunt a flake

# per test
@pytest.mark.flaky(reruns=3)
def test_external_service(): ...

# unique resources per worker
@pytest.fixture(scope="session")
def db_name(worker_id):              # "gw0", "gw1"… or "master"
    return f"test_{worker_id}"

Code Explained

worker_id (from xdist) lets each worker use its own database or port
pytest-randomly prints the seed at the top; reuse it with --randomly-seed to repeat an order
--count (pytest-repeat) runs one test many times; with -x it stops on the first failure
Reruns are reported as R so they're visible, not hidden

unittest Equivalent

  • xdist → no built-in parallel runner in unittest
  • random order → unittest runs alphabetically; no shuffle option
  • reruns → no equivalent

Prefer / Avoid

  • shared files in /tmp → tmp_path per test
  • global reruns in addopts → @pytest.mark.flaky on known tests with an issue link
  • tests depending on order → each test builds its own state

Flake Causes

CauseFix
Shared global stateReset in fixtures
Test orderFind with pytest-randomly
Time / timezoneFreeze or inject the clock
NetworkMock the boundary
Fixed ports / filesworker_id or tmp_path
Async timingAwait events, don't sleep

⚠ Common Mistakes

  • Assuming a session fixture runs once under xdist and creating one database per worker by accident
  • Adding --reruns globally and never fixing the flaky tests
  • Debugging under -n auto; run the single test without xdist first

✓ Tips & Best Practices

  • Use -n auto in CI and plain runs locally while debugging
  • Keep pytest-randomly installed; order bugs show up early instead of in CI
  • Use --count with -x to reproduce an intermittent failure

Quick Summary

  • -n auto — parallel workers
  • --dist loadscope — keep module fixtures together
  • pytest-randomly — shuffle to find order bugs
  • --reruns / flaky — temporary retries
