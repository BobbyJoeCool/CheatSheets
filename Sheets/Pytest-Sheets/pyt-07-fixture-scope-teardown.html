Sheet 07

Fixture Scope & Teardown

function / class / module / package / session · yield teardown · request.addfinalizer · scope mismatch

How Long a Fixture Lives

Scope decides how often a fixture is built: once per test (function, the default), per class, module, package, or once for the whole run (session). Expensive resources like a database server or a browser use wider scopes. Put cleanup after a yield: code before it is setup, the yielded value goes to the test, and code after it runs as teardown even if the test failed.

Notes

  • Teardown runs in reverse order of setup
  • A fixture may only request fixtures of the same or wider scope
  • Shared mutable objects in wide scopes leak state between tests
  • --setup-show prints every SETUP / TEARDOWN as it happens

Under the Hood

  • pytest caches each fixture value per scope key (test, class, module…) and reuses it until that scope ends
  • Teardown is LIFO: the last fixture set up is the first torn down
  • A function-scoped fixture requested by a session fixture raises ScopeMismatch

yield Teardown and Scopes

import pytest, sqlite3

@pytest.fixture(scope="session")
def db_path(tmp_path_factory):
    path = tmp_path_factory.mktemp("db") / "test.sqlite"
    create_schema(path)
    return path

@pytest.fixture
def db(db_path):
    conn = sqlite3.connect(db_path)
    conn.execute("BEGIN")
    yield conn                      # ← test runs here
    conn.rollback()                 # teardown, runs even on failure
    conn.close()

@pytest.fixture(scope="module")
def api_server():
    server = start_server(port=0)
    yield server
    server.stop()

def test_insert(db):
    db.execute("INSERT INTO orders VALUES (1, 'ann')")
    assert db.execute("SELECT count(*) FROM orders").fetchone()[0] == 1

# $ pytest --setup-show tests/test_db.py

Code Explained

The schema is built once per run; each test gets a fresh connection inside a transaction
Rolling back after each test keeps tests independent while sharing the expensive setup
tmp_path_factory is the session-scoped version of tmp_path
--setup-show makes scope bugs visible

unittest Equivalent

  • function scope → setUp / tearDown
  • class scope → setUpClass / tearDownClass (classmethods)
  • module scope → setUpModule / tearDownModule
  • yield teardown → self.addCleanup(fn)

Prefer / Avoid

  • cleanup in a try/finally inside each test → yield fixture
  • session-scoped mutable list shared by tests → function scope or a fresh copy
  • request.addfinalizer for simple cases → yield

⚠ Common Mistakes

  • Requesting a function-scoped fixture (like monkeypatch) from a module-scoped one
  • Putting teardown before yield, or returning instead of yielding
  • Session-scoped database without per-test rollback, so test order changes results

✓ Tips & Best Practices

  • Combine a wide-scope resource with a narrow-scope reset (transaction, truncate)
  • Use scope="session" for anything that takes seconds to start
  • Run --setup-show when you suspect a fixture isn't being rebuilt

Quick Summary

  • scope= — function, class, module, package, session
  • yield — setup above, teardown below
  • teardown runs LIFO, even on failure
  • request only same-or-wider scopes
