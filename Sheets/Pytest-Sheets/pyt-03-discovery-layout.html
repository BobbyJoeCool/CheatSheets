test_*.py / *_test.py · Test* classes · test_* functions · src layout · tests/ folder · --import-mode · __init__.py

How pytest Finds and Imports Tests

pytest collects tests by walking the folders you give it (or testpaths), importing files that match test_*.py or *_test.py, then gathering functions named test* and methods named test* in classes named Test* (with no __init__). The common modern layout puts code in src/package/ and tests in tests/, installed with pip install -e ., and uses --import-mode=importlib so test files don't need __init__.py.

Notes

  • pytest --co -q lists what would run without running it
  • Test classes group tests; they must not define __init__
  • Collection errors (E before any test runs) are usually import errors
  • Change patterns with python_files, python_classes, python_functions

Under the Hood

  • Collection walks testpaths → directories → modules → classes → functions, building items
  • With the default prepend mode, each test file's folder goes on sys.path, so two test_utils.py files in different folders clash
  • importlib mode imports by path without touching sys.path and avoids the clash

src Layout

orders/
├── pyproject.toml          # [tool.pytest] testpaths = ["tests"]
├── src/
│   └── orders/
│       ├── __init__.py
│       ├── cart.py
│       └── payments.py

    ├── conftest.py         # shared fixtures (sheet 08)

    └── payments/
        └── test_refunds.py

$ pip install -e .          # makes "import orders" work
$ pytest --co -q            # list collected tests
tests/test_cart.py::test_total_adds_prices
tests/test_cart.py::TestDiscount::test_quarter_off
tests/payments/test_refunds.py::test_full_refund

Code Explained

The src layout stops tests from accidentally importing the local folder instead of the installed package
The node ID file::Class::test is what you pass to run a single test (sheet 15)
Nested test folders don't need __init__.py with --import-mode=importlib
conftest.py files are picked up automatically wherever they sit

unittest Equivalent

  • test_*.py discovery → unittest discover -p "test*.py"
  • test functions → must be methods on a TestCase subclass
  • --co → no equivalent; unittest has no collect-only mode

Prefer / Avoid

  • sys.path.insert(0, "..") at the top of test files → src layout + pip install -e .
  • duplicate test_utils.py with prepend mode → --import-mode=importlib
  • a TestThing class with __init__ → plain functions or a fixture

Import Modes

ModeBehavior
prepend (default)Adds the test file's rootdir to the front of sys.path
appendAdds it to the end
importlibImports by path, no sys.path changes; recommended for new projects

⚠ Common Mistakes

  • Defining __init__ on a test class; pytest skips the whole class with a warning
  • Running tests against the source folder instead of the installed package and missing packaging bugs
  • Ignoring collection errors and only reading the "passed" count

✓ Tips & Best Practices

  • Run pytest --co -q after moving files to confirm everything is still collected
  • Use pythonpath = ["src"] in config if you can't install the package in editable mode
  • Mirror the package's folders under tests/ so tests are easy to find

Quick Summary

  • test_*.py / Test* / test_* — collected
  • src layout + pip install -e .
  • --import-mode=importlib — no __init__.py needed
  • --co — list without running
