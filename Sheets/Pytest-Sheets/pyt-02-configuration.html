Sheet 02

Configuration

[tool.pytest] in pyproject.toml · pytest.toml · legacy pytest.ini / ini_options · testpaths · addopts · strict · minversion

One Config Block, Read on Every Run

pytest reads its settings from the first config file it finds. pytest 9 reads native TOML: a [tool.pytest] table in pyproject.toml, or a pytest.toml / .pytest.toml file. Older projects use [tool.pytest.ini_options] or pytest.ini, which still work. Put options you always want (testpaths, addopts, markers) here instead of typing them each run.

Notes

  • The directory holding the config file becomes the rootdir
  • pytest --help lists every config key under "[pytest] ini-options"
  • addopts flags are added before the ones you type
  • strict = true turns on all the strict checks at once (9.0)

Under the Hood

  • pytest walks up from the given paths looking for pytest.toml, .pytest.toml, pytest.ini, pyproject.toml (with a pytest table), tox.ini, setup.cfg
  • The first match wins; files are not merged
  • pytest -c path/to/file forces a config file; the header line configfile: shows which one was used

pyproject.toml (pytest 9 native TOML)

[tool.pytest]
minversion = "9.0"
testpaths = ["tests"]
addopts = ["-ra", "--strict-markers", "--import-mode=importlib"]
strict = true
markers = [
  "slow: takes more than a second",
  "integration: needs the database",
]
filterwarnings = ["error", "ignore::DeprecationWarning:somelib.*"]
log_cli_level = "INFO"

# ── pytest 8 and older ────────────────────────
[tool.pytest.ini_options]
testpaths = ["tests"]
addopts = "-ra --strict-markers"

Code Explained

In native TOML, list options are real arrays; ini_options takes strings like an INI file
testpaths sets where to look when you run plain pytest
filterwarnings = ["error"] turns warnings into failures, with exceptions listed after it
minversion fails fast if someone runs an older pytest

unittest Equivalent

  • config file → none built in; you pass options to python -m unittest each time
  • testpaths → python -m unittest discover -s tests
  • filterwarnings → python -W error -m unittest

Prefer / Avoid

  • typing -ra --strict-markers every run → put them in addopts
  • setup.cfg / tox.ini sections → [tool.pytest] in pyproject.toml
  • unregistered markers → register them under markers and use --strict-markers

⚠ Common Mistakes

  • Writing [tool.pytest] with pytest 8, which silently ignores it
  • Having both pytest.ini and pyproject.toml settings and editing the one that isn't used
  • Putting environment-specific flags (like -x) in addopts, so CI stops at the first failure

✓ Tips & Best Practices

  • Check the configfile: line at the top of the output to see which file was read
  • Use strict = true on new projects so typos in markers and config keys fail
  • Keep addopts to flags everyone wants; personal ones go on the command line or in PYTEST_ADDOPTS

Quick Summary

  • [tool.pytest] — native TOML (9.0+)
  • ini_options — older pytest
  • testpaths / addopts — defaults for every run
  • first config file found wins
