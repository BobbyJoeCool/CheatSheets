Sheet 23

pytest in CI

--junitxml · GitHub Actions matrix · tox / nox · caching .pytest_cache · exit codes · --strict-markers in CI

Run the Suite on Every Push

In CI, pytest's exit code decides pass or fail, and --junitxml writes a report most CI systems display. A matrix runs the suite on several Python versions; tox or nox run the same environments locally. Turn on strict options and warnings-as-errors in CI so problems fail early.

Notes

  • Exit code 5 (no tests collected) fails CI; catch it if a job may have nothing to run
  • -p no:cacheprovider avoids writing .pytest_cache in read-only CI
  • CI=true is set by most CI systems; pytest shortens some output when it sees it
  • The GitHub set covers Actions syntax

.github/workflows/test.yml

name: tests
on: [push, pull_request]
jobs:
  pytest:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        python: ["3.12", "3.13", "3.14"]
    steps:
      - uses: actions/checkout@v6
      - uses: actions/setup-python@v6
        with:
          python-version: ${{ matrix.python }}
      - run: python -m pip install -e . --group dev
      - run: >
          pytest -n auto -ra
          --cov=orders --cov-report=xml
          --junitxml=reports/junit.xml
          -W error --strict-markers
      - uses: actions/upload-artifact@v7
        if: always()
        with:
          name: reports-${{ matrix.python }}
          path: reports/

Code Explained

The matrix runs the same steps once per Python version
if: always() uploads reports even when tests fail
-W error turns warnings into failures only in CI
pip install --group dev (pip 25.1+) installs the [dependency-groups] dev packages

unittest Equivalent

  • --junitxml → no built-in XML output; use unittest-xml-reporting or run unittest tests under pytest
  • matrix and tox setup → identical for both runners

Prefer / Avoid

  • different flags locally and in CI → share them in addopts and add only CI-specific ones in the workflow
  • installing with pip install -r and no lock → uv sync or a lock file
  • one Python version → a matrix of supported versions

⚠ Common Mistakes

  • Ignoring exit code 5 when a path filter leaves nothing to run
  • Uploading reports only on success, so failures have no report
  • Testing only the newest Python while supporting older ones

✓ Tips & Best Practices

  • Use the same command locally and in CI (a nox session or a script)
  • Fail on warnings in CI to catch deprecations before upgrades break you
  • Shard huge suites with pytest-split or xdist across jobs

Quick Summary

  • exit code — CI pass / fail
  • --junitxml — reports
  • matrix / tox / nox — many Pythons
  • -W error + strict — fail early
