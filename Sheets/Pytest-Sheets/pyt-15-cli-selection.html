Sheet 15

Selecting & Rerunning Tests

node IDs file::Class::test · -k expressions · -m · --lf / --ff · -x / --maxfail · --sw · --co

Run Exactly the Tests You Need

Running the whole suite for every change is slow. Select tests by path or node ID, by name (-k), or by mark (-m). After a failure, rerun only what failed with --lf (last failed), put failures first with --ff, stop at the first failure with -x, or step through failures one at a time with --sw (stepwise).

Notes

  • Results of the last run live in .pytest_cache/ (gitignore it)
  • -k matches substrings of test, class and file names
  • Combine selectors: pytest tests/api -k refund -m "not slow"
  • --co with any selector shows what would run

Selection Recipes

pytest tests/test_cart.py                    # one file
pytest tests/test_cart.py::test_total        # one test
pytest tests/test_cart.py::TestDiscount      # one class
pytest "tests/test_cart.py::test_total[empty]"   # one case
pytest tests/api/                            # one folder
pytest -k "refund and not partial"           # by name expression
pytest -m "not slow"                         # by mark
pytest --lf                                  # only last failures
pytest --ff                                  # failures first, then the rest
pytest -x                                    # stop at first failure
pytest --maxfail=3                           # stop after 3
pytest --sw                                  # stepwise: resume from last failure
pytest --co -q -k refund                     # list matches without running
pytest --deselect tests/test_api.py::test_flaky

Code Explained

Node IDs are printed in failure output; copy one to rerun that test
--lf with nothing failed last time runs everything (or nothing with --lfnf=none)
--sw runs until a failure, then next time starts from that test
--deselect removes specific node IDs from a run

unittest Equivalent

  • pytest file::test → python -m unittest tests.test_cart.TestCart.test_total
  • -k → python -m unittest -k pattern
  • -x → python -m unittest -f (failfast)
  • --lf / --ff → no equivalent

Prefer / Avoid

  • commenting out tests to run one → a node ID or -k
  • rerunning the full suite after one failure → --lf
  • scrolling for the failing test name → copy the node ID from the short summary

⚠ Common Mistakes

  • Committing .pytest_cache/ to Git
  • Forgetting quotes around node IDs with brackets, so the shell expands them
  • Leaving -x in addopts, so CI reports only the first failure

✓ Tips & Best Practices

  • Use --lf -x while fixing failures one by one
  • Use --sw to walk through a broken suite after a big refactor
  • Add .pytest_cache/ to .gitignore

Quick Summary

  • node ID — file::Class::test[case]
  • -k / -m — by name / by mark
  • --lf / --ff — rerun failures
  • -x / --sw — stop or step
