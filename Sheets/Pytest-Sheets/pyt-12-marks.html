Sheet 12

Marks: skip, xfail & Custom

skip · skipif · xfail(strict=True) · pytest.importorskip · custom markers · markers = registration · -m

Labels That Change How Tests Run

A mark is a decorator that attaches metadata to a test. Built-in marks skip a test always or on a condition, or mark it xfail (expected to fail) so a known bug doesn't break CI. Custom marks like slow or integration let you select or exclude groups with -m. Register every custom mark in config so typos are caught.

Notes

  • -ra in addopts lists the reasons for skips and xfails at the end
  • xfail(strict=True) fails if the test unexpectedly passes
  • Marks on a class or with pytestmark = … apply to every test inside
  • Call pytest.skip("reason") inside a test to skip at run time

Skipping, xfail and Selecting

import sys, pytest

@pytest.mark.skip(reason="payment sandbox is down")
def test_charge(): ...

@pytest.mark.skipif(sys.platform == "win32", reason="POSIX paths only")
def test_symlinks(tmp_path): ...

@pytest.mark.xfail(reason="bug #142: rounding", strict=True, raises=AssertionError)
def test_rounding():
    assert total([0.1, 0.2]) == 0.3

np = pytest.importorskip("numpy")      # skip the module if missing

@pytest.mark.slow
@pytest.mark.integration
def test_full_checkout(db): ...

pytestmark = pytest.mark.integration    # every test in this module

# pyproject.toml
# [tool.pytest]
# markers = ["slow: >1s", "integration: needs the database"]
# $ pytest -m "not slow"
# $ pytest -m "integration and not slow"

Code Explained

skipif takes any boolean expression evaluated at collection
strict=True makes a fixed bug show up as a failure, reminding you to remove the mark
importorskip returns the module when it's installed
-m takes a boolean expression of mark names

unittest Equivalent

  • @pytest.mark.skip → @unittest.skip("reason")
  • skipif → @unittest.skipIf(cond, "reason")
  • xfail → @unittest.expectedFailure
  • custom marks + -m → no equivalent; split test files or use name patterns

Prefer / Avoid

  • commenting out a broken test → xfail(strict=True) with the issue number
  • unregistered marks → register under markers and use strict
  • skip with no reason → always give a reason

Built-in Marks

⚠ Common Mistakes

  • Leaving xfail without strict, so a fixed bug quietly turns into an XPASS nobody notices
  • Typos like @pytest.mark.integation silently creating a new mark when not using strict
  • Skipping on a condition evaluated at import time that depends on test setup

✓ Tips & Best Practices

  • Always add a reason and an issue link to skip and xfail
  • Run fast tests locally with -m "not slow" and everything in CI
  • Use -ra to review skips regularly; skipped tests rot

Quick Summary

  • skip / skipif — don't run
  • xfail(strict=True) — known failure
  • custom marks + -m — select groups
  • register marks — catch typos
