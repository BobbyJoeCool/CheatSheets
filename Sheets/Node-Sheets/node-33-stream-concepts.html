Stream Concepts

Readable · Writable · Duplex · Transform · backpressure · highWaterMark · objectMode

Processing Data in Pieces

A stream moves data in chunks instead of all at once, so memory stays flat no matter how big the input is. There are four kinds: Readable (a source), Writable (a destination), Duplex (both, like a socket), and Transform (a Duplex that changes data, like gzip). Backpressure slows a fast producer down when the consumer can't keep up.

Notes

  • Files, HTTP requests/responses, sockets, and stdin/stdout are all streams
  • Chunks are Buffers by default, strings with an encoding
  • objectMode: true streams carry any JS values

Readable → Transform → Writable

import { createReadStream, createWriteStream } from 'node:fs';
import { createGzip } from 'node:zlib';
import { pipeline } from 'node:stream/promises';

await pipeline(                          // backpressure handled for you
  createReadStream('access.log'),        // Readable: produces chunks
  createGzip(),                          // Transform: compresses
  createWriteStream('access.log.gz'),    // Writable: consumes chunks
);

// What pipeline does for you (simplified):
const src = createReadStream('a.log');
const dst = createWriteStream('b.log');
src.on('data', (chunk) => {
  if (!dst.write(chunk)) src.pause();    // destination buffer is full
});
dst.on('drain', () => src.resume());     // destination caught up
src.on('end', () => dst.end());

src.readableHighWaterMark;               // 65536 (64 KB chunks)

Code Explained

pipeline — connects streams and forwards errors
write() false — buffer passed the high-water mark
pause / resume — the backpressure mechanism
'drain' — safe to write again
highWaterMark — buffer size before backpressure kicks in

Common Mistakes

  • Listening to 'data' and writing without checking write(); memory grows on slow destinations
  • Using .pipe() chains; an error in the middle leaves other streams open
  • Forgetting an 'error' handler on a bare stream; one bad file crashes the process

Tips

  • Default to pipeline from node:stream/promises
  • Consume Readables with for await instead of 'data' events
  • Raise highWaterMark for fast disks or big sequential reads

Summary

  • Readable / Writable — source / destination
  • Transform — modify data in flight
  • backpressure — producer waits for consumer
  • pipeline — the safe way to connect streams
