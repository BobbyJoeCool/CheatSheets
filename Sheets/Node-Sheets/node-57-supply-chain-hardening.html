Supply Chain & Hardening

npm audit · lockfiles · --ignore-scripts · provenance · minimal dependencies · security release lines

Your Dependencies Are Your Code

A typical Node app runs hundreds of packages written by strangers, and any of them can run code at install time (install scripts) or run time. Supply-chain attacks (typosquatted names, hijacked maintainer accounts, malicious updates) target exactly that. Defend with a committed lockfile, few dependencies, audits, and an install process that doesn't run arbitrary scripts.

Notes

  • npm ci installs exactly what the lockfile says
  • postinstall scripts run with your user's permissions
  • Patch releases can contain anything; ranges pull them in

Audit & Harden

npm audit                          # known vulnerabilities
npm audit --omit=dev               # only what ships to production
npm audit signatures               # verify registry signatures
npm ci --ignore-scripts            # install without install scripts
npm ls --all | wc -l               # how many packages you really ship
npm explain minimist               # why a package is in the tree
npm view some-pkg maintainers time.modified   # vet before adding
npm publish --provenance           # prove your package came from CI
npm outdated                       # stale versions

Code Explained

--omit=dev — dev tool advisories rarely matter in production
signatures — detects tampered packages
--ignore-scripts — then allow-list packages that need them
ls --all — the real dependency count is often 10× direct deps
--provenance — links the package to its source commit

Common Mistakes

  • Running npm install some-package from a blog post without checking the exact name
  • Auto-merging every dependency update; a compromised release ships straight to production
  • Ignoring npm audit entirely because it's noisy; filter it instead

Tips

  • Before adding a dependency, ask whether 20 lines of your own code would do
  • Group upgrades weekly with Renovate and review the changelogs
  • Subscribe to Node's security release announcements

Summary

  • lockfile + npm ci — reproducible installs
  • npm audit — known vulnerabilities
  • --ignore-scripts — no install-time code
  • fewer deps — smaller attack surface
