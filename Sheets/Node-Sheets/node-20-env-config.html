Environment Variables & Config

--env-file · process.loadEnvFile() · util.parseEnv() · NODE_ENV · NODE_OPTIONS · dotenv

Configuration from the Environment

Apps read secrets and settings from environment variables so the same code runs in dev, CI, and production. Node can load a .env file itself with --env-file (or process.loadEnvFile() at runtime), so the dotenv package is optional now. Read config once at startup, convert types, validate, and fail fast with a clear message if something is missing.

Notes

  • Variables already set in the shell win over .env values
  • Never commit .env; commit a .env.example with dummy values
  • Node itself ignores NODE_ENV; frameworks and libraries read it

Loading & Validating Config

// node --env-file=.env --env-file-if-exists=.env.local server.js
import { parseEnv } from 'node:util';

process.env.PORT;                  // '8080' (always a string)
const port = Number(process.env.PORT ?? 3000);
const debug = process.env.DEBUG === 'true';

process.loadEnvFile();             // load ./.env from code instead of a flag
process.loadEnvFile('.env.test');  // or a specific file
parseEnv('A=1\nB="two words"');    // { A: '1', B: 'two words' }

const required = ['DATABASE_URL', 'SESSION_SECRET'];
const missing = required.filter((k) => !process.env[k]);
if (missing.length) throw new Error(`Missing env: ${missing.join(', ')}`);

export const config = Object.freeze({
  port, debug, dbUrl: process.env.DATABASE_URL,
});

Code Explained

--env-file — repeatable; later files override earlier ones
-if-exists — optional file, no error when missing
Number() / === 'true' — explicit type conversion
parseEnv — parse .env text without touching process.env
Object.freeze — config can't be changed at runtime

Common Mistakes

  • Reading process.env.X deep inside code; missing config only shows up when that path runs
  • Expecting .env to override a variable already set in the shell; it won't
  • Logging the whole process.env; secrets end up in log storage

Tips

  • Validate with a schema library (Zod, Valibot) for typed config
  • Set NODE_ENV=production in production; many libraries skip dev checks
  • Keep one config.js module that every other file imports

Summary

  • --env-file — load .env without dotenv
  • process.env — string values only
  • validate early — fail at startup, not mid-request
  • NODE_OPTIONS — default flags via env
