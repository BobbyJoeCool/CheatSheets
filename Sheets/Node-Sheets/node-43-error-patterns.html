Error Patterns in Node

err.code · system errors · error.cause · AggregateError · operational vs programmer errors · custom error classes

Errors the Node Way

Node errors carry more than a message. System errors from fs, net, and dns have a code like ENOENT plus syscall and path; Node's own errors use ERR_* codes. Give your own errors a name and code, and when you rethrow, wrap the original as cause so the root problem survives. Separate operational errors (expected; handle them) from programmer errors (bugs; crash and fix).

Notes

  • Branch on err.code, never on err.message
  • cause shows up in stack traces and logs
  • AggregateError holds several errors in .errors

Custom Errors & Wrapping

import { readFile } from 'node:fs/promises';

class NotFoundError extends Error {
  constructor(resource, id, options) {
    super(`${resource} ${id} not found`, options);   // options.cause
    this.name = 'NotFoundError';
    this.code = 'E_NOT_FOUND';
    this.status = 404;
  }
}

try {
  await readFile('config.json', 'utf8');
} catch (err) {
  if (err.code !== 'ENOENT') {                       // ENOENT: use defaults
    throw new Error('Could not load config', { cause: err });
  }
}

new NotFoundError('User', 7).message;   // 'User 7 not found'
throw new AggregateError([e1, e2], '2 jobs failed');   // e.errors → [e1, e2]

Code Explained

super(msg, options) — passes cause through
name — shown at the top of the stack trace
code — stable identifier for callers to check
{ cause: err } — wrap without losing the original

Common Mistakes

  • Throwing strings (throw 'failed'); no stack trace and no code
  • Wrapping without cause; the real reason disappears from logs
  • Catching everything and continuing; programmer errors leave the process in an unknown state

Tips

  • Keep a small set of error classes (NotFound, Validation, Conflict) and map them to HTTP statuses in one place
  • Log errors as objects, not err.message, so stack and cause are kept
  • Use err.code constants from the docs in tests

Summary

  • err.code — what to branch on
  • class X extends Error — custom errors
  • { cause } — wrap and keep context
  • operational vs programmer — handle vs crash
