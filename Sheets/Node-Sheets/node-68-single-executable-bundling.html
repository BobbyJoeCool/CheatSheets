Shipping Without Node Installed

A Single Executable Application (SEA) packs your app and the Node runtime into one binary that runs on machines with no Node installed, which is handy for CLIs and internal tools. Bundle your code into one file first (esbuild, Rollup), generate a SEA blob, and inject it into a copy of the node binary. Bundling alone also helps servers start faster and ship fewer files.

Notes

  • One binary per OS and CPU; build on each target
  • macOS binaries must be re-signed after injection
  • The SEA build steps have been changing; check the docs for your version

Bundle, Then Build a SEA

# 1. bundle to one CommonJS file
npx esbuild src/cli.js --bundle --platform=node \
  --format=cjs --outfile=dist/cli.cjs

# 2. describe the executable
echo '{ "main": "dist/cli.cjs", "output": "sea.blob" }' > sea-config.json
node --experimental-sea-config sea-config.json

# 3. copy node and inject the blob
cp "$(command -v node)" notes
npx postject notes NODE_SEA_BLOB sea.blob \
  --sentinel-fuse NODE_SEA_FUSE_fce680ab2cc467b6e072b8b5df1996b2

./notes --help                       # runs without Node installed

Code Explained

--bundle — inlines every dependency into one file
--platform=node — keeps node: modules as imports
sea-config.json — what goes into the blob
postject — writes the blob into the binary
Sentinel fuse — the marker Node checks at startup

Common Mistakes

  • Bundling native addons; .node files can't be inlined, ship them as assets
  • Building on macOS and shipping to Linux; binaries aren't cross-platform
  • Using __dirname paths to read files; inside a SEA they don't exist, use sea.getAsset()

Tips

  • Sign macOS and Windows binaries so users don't get security warnings
  • Turn on the compile cache (module.enableCompileCache()) for faster cold starts
  • Use node --run in scripts instead of npm run for quicker startup

Summary

  • bundle — one file, faster start
  • SEA — app + Node in one binary
  • assets — embed extra files
  • compile cache — cache compiled code
