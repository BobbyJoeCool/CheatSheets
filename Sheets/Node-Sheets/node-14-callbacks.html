Callbacks & Error-First Style

The Original Async Style

Before promises, every async Node API took a callback as its last argument and called it with (err, result): the error-first convention. If err is non-null, the operation failed and result is meaningless. Most core modules now have promise versions, but you still meet callbacks in older packages, event handlers, and some core APIs. util.promisify converts them.

Notes

  • Callbacks don't return values; results only flow into the callback
  • try/catch around a callback API doesn't catch its async errors
  • A callback must be called exactly once

Error-First Callbacks & Conversion

import fs from 'node:fs';
import { promisify, callbackify } from 'node:util';

fs.readFile('config.json', 'utf8', (err, text) => {
  if (err) return console.error(err.code);   // 'ENOENT' — return early!
  console.log(JSON.parse(text).port);        // 3000
});

function getUser(id, cb) {                     // writing your own
  if (!id) return cb(new Error('id required'));
  setImmediate(() => cb(null, { id, name: 'Ada' }));  // always async
}

const getUserAsync = promisify(getUser);       // callback → promise
const user = await getUserAsync(7);            // { id: 7, name: 'Ada' }

const legacyApi = callbackify(async (id) => ({ id }));  // promise → callback
legacyApi(7, (err, u) => console.log(u));      // { id: 7 }

Code Explained

return console.error — stops the success path running too
cb(null, value) — null means no error
setImmediate — never call a callback synchronously some of the time
promisify — expects (…args, cb) with (err, value)
callbackify — for APIs that still require callbacks

Callback Rules

RuleWhy
err firstpromisify depends on it
call onceTwice causes double replies
always asyncAvoids "Zalgo" ordering bugs
return after errStops fall-through
Error objectsKeep stack traces

Common Mistakes

  • Forgetting return after handling err; the success code runs with undefined
  • Throwing inside a callback; nothing up the stack can catch it, so the process crashes
  • Promisifying a method loses this; use promisify(obj.fn).bind(obj)

Tips

  • Check for a /promises module before reaching for promisify
  • Flatten nested callbacks ("callback hell") by converting to async/await
  • Pass Error objects, never strings, as the first argument

Summary

  • (err, result) — error-first convention
  • return cb(err) — handle and exit
  • promisify — callback API → promise
  • callbackify — promise → callback API
