Managing Dependencies

npm ships with Node. It installs packages into node_modules, records the version ranges you asked for in package.json, and records the exact resolved versions in package-lock.json. Commit the lockfile: it's what makes every install on every machine produce the same tree. npx runs a package's command without installing it globally.

Notes

  • Short forms: i install · rm uninstall · -D dev · -E exact
  • Never commit node_modules; add it to .gitignore
  • Project settings live in .npmrc

Everyday Commands

npm init -y                  # create package.json with defaults
npm install                  # install everything in package.json
npm install fastify          # add a runtime dependency
npm install -D vitest        # add a dev dependency
npm install zod@3.24.1 -E    # exact version, no ^ range
npm uninstall lodash         # remove a dependency
npm ci                       # clean install from the lockfile (CI, Docker)
npm ci --omit=dev            # production install
npm outdated                 # what has newer versions
npm update                   # upgrade within the allowed ranges
npm audit                    # known vulnerabilities
npm ls fastify               # where a package sits in the tree
npm run build                # run a script (npm run lists them all)
npx prettier --write .       # run a package's binary
npm view fastify version     # latest published version

Code Explained

install — may update the lockfile
ci — deletes node_modules, never changes the lockfile, fails if it's out of sync
update — won't cross a major version on ^
npx — uses the local copy if installed, else downloads
ls — explains why a package is present

Common Mistakes

  • Running npm install in CI; it can change the lockfile, so use npm ci
  • Deleting package-lock.json to fix errors; it silently upgrades everything
  • Running npm audit fix --force blindly; it can jump major versions

Tips

  • Check a package before adding it: npm view <pkg> and its repo activity
  • Use npm pkg get version in scripts instead of parsing JSON
  • Pass args to a script after --: npm test -- --watch

Summary

  • npm install — add packages, update lockfile
  • npm ci — exact, reproducible install
  • ^ / ~ — major / minor ranges
  • npx — run a package's command
