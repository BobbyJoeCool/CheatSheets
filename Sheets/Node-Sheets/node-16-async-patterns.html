Controlling Async Work

Real programs need more than await: run independent work in parallel, cap how many tasks run at once, process data that arrives over time with async iteration, and cancel work that's no longer needed. Node standardizes cancellation on AbortController: most async core APIs and fetch accept a signal option.

Notes

  • Aborting rejects with an AbortError (err.name)
  • A signal can only be aborted once
  • Starting a promise starts the work; await only waits for it

Patterns

const a = await getA(); const b = await getB();    // sequential: ~2s
const [a2, b2] = await Promise.all([getA(), getB()]); // parallel: ~1s

// Limit concurrency: at most 5 downloads at a time
async function mapLimit(items, limit, fn) {
  const out = [], queue = items.entries();
  const worker = async () => {
    for (const [i, x] of queue) out[i] = await fn(x);
  };
  await Promise.all(Array.from({ length: limit }, worker));
  return out;
}
await mapLimit(urls, 5, url => fetch(url).then(r => r.json()));

// Cancellation: user timeout OR manual abort
const ac = new AbortController();
const signal = AbortSignal.any([ac.signal, AbortSignal.timeout(3000)]);
const res = await fetch(url, { signal });       // rejects if either fires

for await (const line of rl) { … }              // consume data as it arrives
const { promise, resolve } = Promise.withResolvers();   // resolve from outside

Code Explained

Promise.all — both start immediately
items.entries() — shared iterator; each worker pulls the next item
out[i] — keeps results in input order
AbortSignal.any — aborts when any input aborts
for await — works on streams, readline, events.on()
withResolvers — wrap event-style APIs

Choosing a Pattern

SituationUse
B needs A's resultSequential await

Hundreds of tasksConcurrency limit (p-limit)

First response winsPromise.any + abort rest

Accepting a Signal in Your Code

APIUse
signal.abortedCheck before each step

addEventListener('abort')Clean up resources

Common Mistakes

  • Promise.all over 10,000 URLs; you open 10,000 sockets at once
  • arr.forEach(async x => …); nothing waits for those promises
  • Racing a timeout with Promise.race leaves the losing request running

Tips

  • Accept { signal } in your own async functions and pass it down
  • Use p-limit or p-map rather than hand-rolling pools in apps
  • Abort leftover requests after Promise.any resolves

Summary

  • Promise.all — run in parallel
  • limit — cap concurrent work
  • for await — iterate async sources
  • AbortController — cancel work
