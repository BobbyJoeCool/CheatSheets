NODE_ENV=production · PM2 · systemd unit · health checks · graceful shutdown · reverse proxy

Keeping a Server Running

In production, something must start Node on boot, restart it when it crashes, pass configuration, collect logs, and stop it gracefully. On a Linux VM that's usually systemd (or PM2), with a reverse proxy like nginx or Caddy in front for TLS and static files. Containers and platforms (Sheet 67) do the same jobs for you.

Notes

  • Run as a dedicated, unprivileged user
  • Logs from stdout go to journalctl -u notes
  • Bind to 127.0.0.1 when a proxy sits in front

systemd Service Unit

# /etc/systemd/system/notes.service
[Unit]
Description=Notes API
After=network.target

[Service]
User=notes
WorkingDirectory=/srv/notes
EnvironmentFile=/srv/notes/.env
Environment=NODE_ENV=production
ExecStart=/usr/bin/node --enable-source-maps server.js
Restart=on-failure
RestartSec=2
TimeoutStopSec=15
LimitNOFILE=65535

[Install]
WantedBy=multi-user.target

Code Explained

EnvironmentFile — secrets outside the repo
Absolute path to node — systemd has no nvm PATH
Restart=on-failure — restarts crashes, not clean stops
TimeoutStopSec — SIGTERM, then SIGKILL after 15 s
LimitNOFILE — room for many sockets

Common Mistakes

  • ExecStart=node server.js with nvm-installed Node; systemd can't find it
  • Running as root "to bind port 80"; use a proxy or setcap instead
  • No restart policy; one crash means downtime until someone notices

Tips

  • Keep /healthz cheap; put dependency checks in /readyz
  • Use Environment=NODE_OPTIONS=--max-old-space-size=… for heap limits
  • Reload with zero downtime by running two instances behind the proxy

Summary

  • systemd / PM2 — supervise the process
  • Restart=on-failure — auto-recover
  • reverse proxy — TLS and static files
  • health endpoints — for monitors and LBs
