Three Ways to Call fs

Every node:fs operation comes in three flavors: promise (fs/promises), callback, and synchronous (*Sync). They do the same work; they differ in how you get the result and whether the event loop waits. Use promises by default. Sync calls are fine in CLIs, build scripts, and startup code, but never inside a server's request path.

Notes

  • All three throw or reject with the same err.code values
  • FileHandle (from open()) is the promise API's file descriptor
  • Sync calls block the whole process, including other requests

Same Read, Three Styles

import fs from 'node:fs';
import fsp from 'node:fs/promises';

const a = await fsp.readFile('a.txt', 'utf8');      // 1. promise (default)

fs.readFile('a.txt', 'utf8', (err, b) => {          // 2. callback
  if (err) return console.error(err);
});

const c = fs.readFileSync('a.txt', 'utf8');         // 3. sync (blocks)

await using fh = await fsp.open('log.txt', 'a');    // auto-closes at scope end
await fh.appendFile('line\n');
(await fh.stat()).size;                             // 5

try { await fsp.readFile('missing.txt'); }
catch (err) {
  err.code;      // 'ENOENT'
  err.syscall;   // 'open'
  err.path;      // 'missing.txt'
}

Code Explained

fs/promises — every function returns a promise
callback — error-first (err, data)
*Sync — returns directly, throws on error
await using — calls fh.close() even if code throws
err.code — branch on this, not the message

Common Mistakes

  • readFileSync in a request handler; every other request waits for the disk
  • Opening files with open() and never closing them; you'll hit EMFILE
  • Checking err.message text; messages change, codes don't

Tips

  • Import named functions: import { readFile } from 'node:fs/promises'
  • Use await using (Node 24+) for FileHandles instead of try/finally
  • Retry EMFILE / EBUSY with backoff, or use graceful-fs

Summary

  • fs/promises — default choice
  • *Sync — scripts and startup only
  • FileHandle — open once, many ops
  • err.code — identify the failure
