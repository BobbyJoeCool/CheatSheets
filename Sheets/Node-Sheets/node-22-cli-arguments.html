Parsing Arguments

util.parseArgs() is Node's built-in argument parser. You describe the options your command accepts; it returns the parsed values and any positionals, and by default throws on unknown flags. Combined with a "bin" entry in package.json and a shebang line, it's enough to ship a real command-line tool without dependencies.

Notes

  • Option types are only 'string' and 'boolean'; convert numbers yourself
  • strict: true (default) rejects unknown options
  • -- ends option parsing; the rest are positionals

A Small CLI

#!/usr/bin/env node
// usage: notes add "Buy milk" --tag home -v
import { parseArgs } from 'node:util';

const { values, positionals } = parseArgs({
  allowPositionals: true,
  options: {
    tag:     { type: 'string', short: 't', multiple: true },
    verbose: { type: 'boolean', short: 'v', default: false },
    limit:   { type: 'string', default: '10' },
    help:    { type: 'boolean', short: 'h' },
  },
});
// values      → { tag: ['home'], verbose: true, limit: '10' }
// positionals → ['add', 'Buy milk']

const [command, ...rest] = positionals;
if (values.help || !command) { printHelp(); process.exit(0); }
const limit = Number(values.limit);

Code Explained

short — one-letter alias: -t home
multiple — collects repeats into an array
default — used when the flag is absent
allowPositionals — needed for subcommands and file args
Missing booleans are undefined unless defaulted

Common Mistakes

  • Forgetting the shebang; the OS tries to run the file as a shell script
  • Declaring type: 'number'; it doesn't exist and parseArgs throws
  • Testing a CLI by publishing it; use npm link locally first

Tips

  • Write help text by hand; parseArgs doesn't generate it
  • Exit with code 2 for bad usage, 1 for runtime failures
  • Reach for commander or yargs only when you need nested subcommands

Summary

  • parseArgs — built-in flag parser
  • values / positionals — the result
  • #!/usr/bin/env node — makes a file executable
  • "bin" — installs your command on PATH
