Memory & Garbage Collection

heap vs RSS · --max-old-space-size · heap snapshots · common leaks · WeakRef / FinalizationRegistry · v8.getHeapStatistics()

Where Memory Goes

V8 stores JavaScript objects in a garbage-collected heap with a size limit; the process also uses memory outside it (Buffers, native code). Memory that keeps growing under steady load is a leak: something still references objects you no longer need. Heap snapshots show what's holding them. WeakMap and WeakRef let you reference objects without keeping them alive.

Notes

  • rss = everything the OS gave the process
  • Exceeding the heap limit kills the process ("heap out of memory")
  • GC pauses stop JavaScript briefly

Measuring & Avoiding Leaks

import v8 from 'node:v8';

process.memoryUsage();
// { rss: 81M, heapTotal: 22M, heapUsed: 15M, external: 2M, arrayBuffers: 1M }
v8.getHeapStatistics().heap_size_limit / 1024 ** 2;   // max heap in MB
v8.writeHeapSnapshot();            // 'Heap.20261002….heapsnapshot'

const cache = new Map();           // ✖ grows forever without eviction
const meta = new WeakMap();        // ✔ entry freed with its key object
meta.set(req, { start: Date.now() });

const ref = new WeakRef(bigObject);       // doesn't keep it alive
ref.deref()?.render();                    // undefined once collected
const reg = new FinalizationRegistry((id) => releaseNative(id));
reg.register(handle, handle.id);          // callback after GC (no guarantee)

Code Explained

heapUsed — live JS objects; watch this trend
external — Buffers and native allocations
writeHeapSnapshot — open in DevTools → Memory
WeakMap — keys must be objects
FinalizationRegistry — cleanup hint, never for critical logic

Memory Flags

Common Mistakes

  • Setting --max-old-space-size above the container's memory limit; the OS kills it first
  • Comparing one heap snapshot; take two or three over time and diff them
  • Using a Map as a cache without a size limit

Tips

  • Set the heap limit to ~75% of the container's memory
  • Use lru-cache for bounded in-memory caches
  • Compare snapshots with the "Comparison" view to find what grew

Summary

  • memoryUsage() — current footprint
  • heap snapshot — who holds what
  • WeakMap / WeakRef — non-owning references
  • --max-old-space-size — heap limit in MB
