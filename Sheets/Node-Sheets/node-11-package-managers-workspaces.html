Alternatives & Monorepos

pnpm and Yarn are drop-in replacements for npm. pnpm stores each package version once on disk and links it into projects, so installs are fast and node_modules is strict (you can only import what you declared). Workspaces let one repo hold several packages that depend on each other; the package manager links them together instead of downloading them.

Notes

  • Pick one manager per repo; each writes its own lockfile
  • Pin it with "packageManager": "pnpm@10.x.x"
  • Corepack is not bundled from Node 25 on; install it with npm i -g corepack
  • Internal packages use the workspace:* protocol (pnpm, Yarn)

Workspace Setup

// package.json at the repo root (npm, Yarn)
{ "private": true, "workspaces": ["packages/*", "apps/*"] }

// apps/web/package.json — depends on a sibling package
{ "dependencies": { "@acme/ui": "workspace:*" } }
# pnpm-workspace.yaml (pnpm uses this instead of "workspaces")
packages:
  - "packages/*"
  - "apps/*"
npm install -w apps/web zod         # add a dep to one workspace
npm run build --workspaces          # run in every workspace
pnpm --filter web dev               # run "dev" in one package
pnpm -r build                       # run in all packages, in dependency order

Code Explained

private: true — required at the root
workspace:* — link the local copy; replaced with a real version on publish
-w — target one workspace (npm)
--filter — target by package name (pnpm)
-r — recursive across all packages

Common Mistakes

  • Committing two lockfiles; tools disagree about which versions are installed
  • Importing an undeclared package under pnpm; it worked in npm only because of hoisting
  • Forgetting to build a workspace package before the app that imports it

Tips

  • Use pnpm for monorepos; strictness catches missing dependencies early
  • Add a task runner (Turborepo, Nx) once builds get slow
  • Prefer workspaces over npm link; links break across Node versions

Summary

  • pnpm / yarn — npm alternatives
  • workspaces — many packages, one repo
  • workspace:* — link a sibling package
  • packageManager — pins the tool
