Parsing URLs & Bodies

req.url is just a string like /search?q=node. Parse it with the WHATWG URL class, which needs a base, and read query values from url.searchParams. The request body arrives as a stream; node:stream/consumers collects it into text, JSON, or a Buffer. Always cap the body size before reading it.

Notes

  • searchParams values are strings, already decoded
  • Query keys can repeat: use getAll
  • Check Content-Type before parsing JSON

Query Strings & JSON Bodies

import { createServer } from 'node:http';
import { json } from 'node:stream/consumers';

createServer(async (req, res) => {
  const url = new URL(req.url, `http://${req.headers.host}`);
  url.pathname;                       // '/search'
  url.searchParams.get('q');          // 'node streams'
  url.searchParams.getAll('tag');     // ['a', 'b']
  Number(url.searchParams.get('page') ?? 1);   // 2

  if (req.method === 'POST') {
    if (Number(req.headers['content-length']) > 1_000_000) {
      res.writeHead(413); return res.end('Too large');
    }
    try {
      const body = await json(req);   // read + parse the whole body
      res.writeHead(201, { 'Content-Type': 'application/json' });
      return res.end(JSON.stringify({ received: body }));
    } catch { res.writeHead(400); return res.end('Bad JSON'); }
  }
  res.end();
}).listen(3000);

Code Explained

Base URL — required because req.url is relative
get — first value or null
413 — Payload Too Large
json(req) — throws on invalid JSON, hence try
content-length can be absent (chunked); a stream limit is safer

Common Mistakes

  • Splitting req.url on ? and & by hand; misses decoding and repeated keys
  • Reading the full body without a size cap; one client can exhaust memory
  • Trusting Host to build absolute URLs; it's client-controlled

Tips

  • Use URL.canParse(str) to validate URLs without try/catch
  • Build query strings with new URLSearchParams(obj).toString()
  • Validate parsed bodies with a schema before using them

Summary

  • new URL(req.url, base) — parse a request URL
  • searchParams — query values
  • stream/consumers — read the body
  • size limit — always cap uploads
