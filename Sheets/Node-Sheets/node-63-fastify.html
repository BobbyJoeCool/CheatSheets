A Faster, Schema-Driven Framework

Fastify is a modern alternative to Express focused on speed and structure. Handlers can simply return a value, routes can declare a JSON Schema that validates input and speeds up output serialization, and everything is organized as plugins with encapsulated scope. It ships with pino logging built in.

Notes

  • Schema validation errors return 400 automatically
  • Response schemas drop properties not listed (no accidental leaks)
  • Use fastify-type-provider-zod / TypeBox for typed schemas

Routes, Schemas & Plugins

import Fastify from 'fastify';                    // npm i fastify

const app = Fastify({ logger: true });

app.get('/notes/:id', async (req, reply) => {
  const note = await db.find(req.params.id);
  if (!note) return reply.code(404).send({ error: 'Not found' });
  return note;                                    // sent as JSON
});

app.post('/notes', {
  schema: {
    body: {
      type: 'object', required: ['title'],
      properties: { title: { type: 'string', minLength: 1 } },
    },
  },
}, async (req, reply) => reply.code(201).send(await db.create(req.body)));

app.register(import('./routes/users.js'), { prefix: '/users' });
app.addHook('onRequest', async (req) => { /* auth check */ });

await app.listen({ port: 3000, host: '0.0.0.0' });

Code Explained

logger: true — request logs with IDs, via pino
return note — no res.json needed
schema.body — rejected requests never reach the handler
register — plugins get their own encapsulated scope
host: '0.0.0.0' — default is localhost only

Common Mistakes

  • Calling reply.send() and also returning a value; Fastify warns about a double reply
  • Expecting a decorator or hook from one plugin to be visible in a sibling; wrap with fastify-plugin to share
  • Listening without host in Docker; the container isn't reachable

Tips

  • Add response schemas to every public route
  • Use app.inject() to test routes without opening a port
  • Generate OpenAPI docs from schemas with @fastify/swagger

Summary

  • return value — the response body
  • schema — validation + fast JSON output
  • register — plugins and encapsulation
  • hooks — request lifecycle
