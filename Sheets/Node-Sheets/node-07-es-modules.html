ES Modules

ES modules (ESM) are the JavaScript standard module system, shared with browsers. Imports are static: Node reads every import before running any code, links the files, then executes them. That enables top-level await and live bindings. Node treats a file as ESM if it ends in .mjs, or is .js inside a package whose package.json has "type": "module".

Notes

  • Relative imports need the full extension: './math.js'
  • ESM always runs in strict mode
  • A .js file with no "type" is parsed as ESM if it uses import / export syntax
  • Imports are hoisted: they run before the file body

Import & Export Forms

// math.js  (package.json has "type": "module")
export const PI = 3.14159;                          // named export
export function area(r) { return PI * r * r; }
export default class Circle {}                      // default export

// app.js
import Circle, { area, PI as pi } from './math.js'; // default, named, alias
import * as math from './math.js';                  // namespace: math.area(2)
import { readFile } from 'node:fs/promises';
import config from './config.json' with { type: 'json' };  // JSON

const text = await readFile('notes.txt', 'utf8');   // top-level await
const { default: chalk } = await import('chalk');   // dynamic import
export { area as circleArea } from './math.js';     // re-export under a new name
export * from './shapes.js';                        // re-export everything named

Code Explained

export default — one per module, import with any name
as — renames on import or export
* as — all named exports as one object
with { type: 'json' } — required for JSON imports
import() — returns a promise, works in CJS too
export * — does not include the default export

Common Mistakes

  • Leaving off .js in a relative import gives ERR_MODULE_NOT_FOUND
  • Mixing require into an ES module; it's not defined there (see Sheet 08)
  • Expecting export * to forward the default; re-export it by name

Tips

  • Set "type" explicitly; syntax detection costs a parse and prints a warning
  • Prefer named exports; they autocomplete and rename safely
  • Use import() to load optional or heavy modules only when needed

Summary

  • export — named or default
  • import — static, hoisted, needs extensions
  • import() — dynamic, returns a promise
  • "type": "module" — makes .js files ESM
