Middleware & Routers

Middleware is a function (req, res, next) that runs before your routes: it can read or change the request, end the response, or call next() to pass control on. Order matters: middleware runs in the order you register it. Routers group related routes and middleware and mount them at a prefix. An error handler has four parameters and goes last.

Notes

  • Not calling next() (or responding) hangs the request
  • next(err) skips to the error handler
  • app.use(path, …) matches that prefix

Logger, Router, 404 & Error Handler

import express from 'express';
const app = express();

app.use((req, res, next) => {                     // request logger
  const t0 = performance.now();
  res.on('finish', () => console.log(req.method, req.originalUrl,
    res.statusCode, `${Math.round(performance.now() - t0)}ms`));
  next();
});
app.use(express.static('public'));                // files from ./public
app.use('/api', express.json());

const notes = express.Router();
notes.get('/', listNotes);
notes.post('/', requireAuth, createNote);         // per-route middleware
app.use('/api/notes', notes);                     // mount at a prefix

app.use((req, res) => res.status(404).json({ error: 'Not found' }));
app.use((err, req, res, next) => {                // error handler: 4 args
  req.log?.error(err);
  res.status(err.status ?? 500).json({ error: 'Something went wrong' });
});

Code Explained

'finish' — fires after the response is sent
static — serves files and stops if one matches
requireAuth — middleware for just one route
originalUrl — full URL even inside a mounted router
Four params — Express identifies error handlers by arity

Common Mistakes

  • Registering the error handler before the routes; it never sees their errors
  • Leaking err.message or stack to clients in production
  • Parsing JSON globally when only /api needs it

Tips

  • Write requireAuth once and attach it per Router
  • Send a generic message to clients, log the full error
  • Use express.Router({ mergeParams: true }) for nested params

Summary

  • (req, res, next) — middleware signature
  • next(err) — jump to error handling
  • Router — group and mount routes
  • (err, req, res, next) — error handler, last
