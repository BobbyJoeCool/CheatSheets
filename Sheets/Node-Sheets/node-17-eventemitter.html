Events in Node

EventEmitter is Node's publish/subscribe building block. Objects emit named events and listeners subscribe with on(). Servers, streams, sockets, child processes, and process itself are all emitters. Listeners run synchronously, in the order they were added, at the moment emit() is called.

Notes

  • An 'error' event with no listener throws and usually crashes
  • More than 10 listeners on one event prints a leak warning
  • emit() returns true if anyone was listening

Emitting & Listening

import { EventEmitter, once, on } from 'node:events';

class Order extends EventEmitter {
  pay(amount) {
    if (amount <= 0) return this.emit('error', new Error('bad amount'));
    this.emit('paid', { amount, at: Date.now() });
  }
}

const order = new Order();
const log = (e) => console.log('paid', e.amount);
order.on('paid', log);                     // every time
order.once('paid', () => console.log('first payment only'));
order.on('error', (err) => console.error(err.message));   // always add one
order.pay(25);                             // paid 25 / first payment only
order.off('paid', log);                    // remove (same function reference)

const [evt] = await once(order, 'paid');   // promise for the next event
for await (const [e] of on(order, 'paid')) { … }   // async stream of events

Code Explained

extends EventEmitter — give your class events
emit(name, …args) — args go to every listener
once — auto-removed after one call
'error' listener — prevents a crash
off — needs the exact function you added
events.once — also rejects if 'error' fires first

Common Mistakes

  • Adding listeners per request and never removing them; memory leak plus the 10-listener warning
  • off() with an inline arrow function; it's a new function, so nothing is removed
  • Async listeners that throw become unhandled rejections unless captureRejections is on

Tips

  • Emit data objects, not long positional argument lists
  • Don't silence the leak warning; find the listener you forgot to remove
  • Use events.once(server, 'listening') in tests and startup code

Summary

  • on / emit — subscribe and publish
  • once — fire one time
  • 'error' — always listen for it
  • events.once/on — promise-based events
