CJS ↔ ESM Interop

require(esm) · createRequire() · default export interop · dual packages · module.register · file extensions in imports

Mixing the Two Systems

Most projects end up with both formats: ESM app code that uses CJS packages, or CJS code that needs an ESM-only package. ESM can always import CJS. CJS can require() an ES module directly as long as that module (and everything it imports) has no top-level await. For anything else, use await import(). Inside ESM, createRequire() gives you a working require.

Notes

  • require(esm) works without a flag since Node 22.12 / 20.19
  • Named imports from CJS depend on static analysis of the CJS file
  • The CJS module.exports object is always the ESM default import

Crossing the Boundary

// ── ESM importing CommonJS ──────────────────────────
import legacy from './legacy.cjs';           // default = module.exports
import { helper } from './legacy.cjs';       // named, if Node can detect it
import pkg from 'old-cjs-package';
const { helper: h } = pkg;                   // fallback when named import fails

// ── CommonJS requiring ESM ──────────────────────────
const { area } = require('./math.mjs');      // namespace object
const Circle = require('./math.mjs').default;   // default export
require('./uses-await.mjs');                 // ✖ ERR_REQUIRE_ASYNC_MODULE
async function load() {
  const { default: chalk } = await import('chalk');  // always works
}

// ── require() inside an ES module ───────────────────
import { createRequire } from 'node:module';
const require = createRequire(import.meta.url);
const data = require('./data.json');         // sync JSON load

Code Explained

import legacy — gets the whole module.exports
{ helper } — works for plain exports.x = patterns
.default — where an ESM default export lands
ERR_REQUIRE_ASYNC_MODULE — top-level await can't be loaded synchronously
createRequire — needs a file URL or path as its base

Dual Package (exports)

"exports": {
  ".": {
    "import": "./dist/index.mjs",
    "require": "./dist/index.cjs"
  }
}

Common Mistakes

  • Shipping a dual package with module-level state; ESM and CJS copies don't share it (the dual package hazard)
  • Assuming every CJS named export is importable; computed exports can't be detected
  • Adding top-level await to a library breaks all of its CJS users

Tips

  • On Node 22.12+, you can usually drop the CJS build and ship ESM only
  • Keep library entry points free of top-level await so require() works
  • Check a package's format: look at its "type" and "exports"

Summary

  • ESM → CJS — import works; default is module.exports
  • CJS → ESM — require() if no top-level await
  • import() — works from either side
  • createRequire — require inside ESM
