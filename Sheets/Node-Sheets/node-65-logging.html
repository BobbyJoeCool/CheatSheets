Structured Logs with pino

Production logs should be structured (one JSON object per line) so log tools can search and aggregate them. pino is the standard Node logger: very fast, JSON by default, with levels, child loggers that add fields to every line, and redaction of secrets. In development, pipe its output through pino-pretty for readable lines.

Notes

  • Fields first, message second: log.info({ id }, 'msg')
  • Pass errors as { err } to get the stack serialized
  • Fastify uses pino; Express uses pino-http

Logger Setup & Usage

import pino from 'pino';                          // npm i pino

const log = pino({
  level: process.env.LOG_LEVEL ?? 'info',
  redact: ['req.headers.authorization', '*.password'],
});

log.info('server started');
// {"level":30,"time":1759400000000,"pid":812,"msg":"server started"}
log.info({ userId: 7, ms: 42 }, 'login ok');
log.error({ err }, 'payment failed');             // includes err.stack
log.debug('hidden unless LOG_LEVEL=debug');

const reqLog = log.child({ requestId: 'a1b2' });  // adds requestId to each line
reqLog.warn({ sql }, 'slow query');

// dev only:  node app.js | npx pino-pretty

Code Explained

level — lines below it are skipped cheaply
redact — paths replaced with [Redacted]
{ err } — the err key triggers the error serializer
child — per-request or per-module context
pino-pretty — human-readable, never in production

Common Mistakes

  • log.info('user', user) (console style); the second argument is ignored as a format arg
  • Logging whole request objects; you leak cookies and auth headers
  • String-building messages ('took ' + ms); keep values as fields so they're searchable

Tips

  • Log to stdout and let Docker / systemd / the cloud collect it
  • Use AsyncLocalStorage to attach requestId automatically (Sheet 59)
  • Lower to debug per module with child loggers when investigating

Summary

  • pino — fast JSON logger
  • log.info({ fields }, msg) — call shape
  • child() — contextual fields
  • redact — keep secrets out
