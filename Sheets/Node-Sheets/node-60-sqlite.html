node:sqlite

DatabaseSync · prepare() · run() · get() · all() · named parameters · transactions · :memory:

A Database Built In

node:sqlite embeds SQLite in Node: a full SQL database in a single file, with no server and no package to install. The API is synchronous, which suits CLIs, tests, scripts, desktop apps, and small services (SQLite queries usually take microseconds). Use prepared statements with parameters for every query that includes data.

Notes

  • Only importable with the node: prefix
  • Check the docs for its current stability level
  • ':memory:' creates a throwaway in-memory database

Create, Insert, Query, Transact

import { DatabaseSync } from 'node:sqlite';

const db = new DatabaseSync('notes.db');        // or ':memory:'
db.exec(`
  CREATE TABLE IF NOT EXISTS notes (
    id INTEGER PRIMARY KEY, title TEXT NOT NULL, done INTEGER DEFAULT 0
  ) STRICT;
`);

const insert = db.prepare('INSERT INTO notes (title) VALUES (?)');
insert.run('Buy milk');          // { changes: 1, lastInsertRowid: 1 }

const byId = db.prepare('SELECT * FROM notes WHERE id = :id');
byId.get({ id: 1 });             // { id: 1, title: 'Buy milk', done: 0 }
db.prepare('SELECT * FROM notes WHERE done = ?').all(0);   // all rows

db.exec('BEGIN');
try { for (const t of titles) insert.run(t); db.exec('COMMIT'); }
catch (err) { db.exec('ROLLBACK'); throw err; }
db.close();

Code Explained

exec — runs SQL with no parameters or results
STRICT — SQLite enforces column types
? / :id — positional and named parameters
get — first row or undefined; all — array
Transactions — batch inserts are far faster inside one

Common Mistakes

  • Building SQL with template strings and user input; that's SQL injection, so use parameters
  • Inserting thousands of rows without a transaction; each insert syncs to disk
  • Calling it from a busy server's request path for slow queries; it blocks the loop

Tips

  • Run PRAGMA journal_mode = WAL; for better read/write concurrency
  • Reuse prepared statements instead of preparing in loops
  • Use :memory: databases for fast, isolated tests

Summary

  • DatabaseSync — open a SQLite file
  • prepare + run/get/all — parameterized queries
  • BEGIN / COMMIT — transactions
  • synchronous — fast, but blocks
