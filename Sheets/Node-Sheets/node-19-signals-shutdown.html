Shutting Down Cleanly

Servers get stopped by signals: SIGTERM from Docker, Kubernetes, and systemd, SIGINT from Ctrl+C. By default Node exits immediately, dropping in-flight requests and unflushed data. A graceful shutdown handler stops accepting new work, lets current work finish, closes resources, and then exits, with a hard deadline in case something hangs.

Notes

  • SIGKILL and SIGSTOP can't be caught
  • Docker sends SIGKILL 10 s after SIGTERM by default
  • Windows doesn't send SIGTERM; SIGINT works
  • The 'exit' handler can only run synchronous code

Graceful Shutdown Handler

import { createServer } from 'node:http';
const server = createServer(handler).listen(3000);

let stopping = false;
async function shutdown(signal) {
  if (stopping) return;                 // ignore a second Ctrl+C
  stopping = true;
  console.log(`${signal}: draining`);
  setTimeout(() => process.exit(1), 10_000).unref();   // hard deadline
  server.close();                       // stop accepting; finish in-flight
  server.closeIdleConnections();        // drop idle keep-alive sockets
  await db.end();                       // close pools, flush logs
  process.exitCode = 0;                 // exit once the loop is empty
}
process.on('SIGTERM', shutdown);        // docker stop, k8s, systemd
process.on('SIGINT', shutdown);         // Ctrl+C

process.on('exit', (code) => console.log('exit', code));  // sync only

Code Explained

stopping flag — handlers can fire more than once
unref() — the deadline itself won't keep the process alive
server.close() — waits for open requests to finish
closeIdleConnections — otherwise keep-alive sockets delay close
No process.exit(0) — exit happens naturally when work is done

Common Mistakes

  • Running node as PID 1 in Docker without an init; signals may never reach your handler (use --init or tini)
  • npm start as the container command; npm may not forward SIGTERM to Node
  • Async work in process.on('exit'); it never runs

Tips

  • Keep the deadline shorter than your orchestrator's kill timeout
  • Fail health checks once shutdown starts so load balancers stop sending traffic
  • Run CMD ["node", "server.js"] directly in Dockerfiles (Sheet 67)

Summary

  • SIGTERM / SIGINT — the signals to handle
  • server.close() — stop accepting, drain
  • deadline — force exit if draining hangs
  • 'exit' — final sync hook
