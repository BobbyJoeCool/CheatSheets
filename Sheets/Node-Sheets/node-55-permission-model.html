Sheet 55

Permission Model

--permission · --allow-fs-read · --allow-fs-write · --allow-child-process · --allow-net · process.permission.has()

Restricting What a Process Can Do

Normally Node code can read any file, spawn any program, and open any connection the OS user can. The permission model turns that around: with --permission, file access, child processes, workers, native addons, and WASI are denied until you grant them with --allow-* flags. A blocked call throws ERR_ACCESS_DENIED. It limits damage from bugs and compromised dependencies; it isn't a sandbox for code you know is malicious.

Notes

  • Paths can be files, folders (trailing /), or *
  • --allow-net (network restriction) is only in newer releases
  • Permissions apply to the whole process, including dependencies

Granting Permissions

node --permission app.js                     # everything below is denied
node --permission --allow-fs-read=./data/ --allow-fs-read=./config.json app.js
node --permission --allow-fs-read=* --allow-fs-write=/tmp/app/ app.js
node --permission --allow-child-process app.js
node --permission --allow-worker app.js
node --permission --allow-addons --allow-wasi app.js
node --permission --allow-net app.js         # newer releases only

Code Explained

No --allow-* — the app can't read its own data files
Repeat a flag to allow several paths
Trailing / — grants the whole folder
* — all paths for that operation
The entry file itself is always readable

Flags

FlagGrants

What Code Sees

process.permission
  .has('fs.write');   // false
await writeFile('x', 'a');
// throws:
// ERR_ACCESS_DENIED

Common Mistakes

  • Granting --allow-fs-read=* "to make it work"; you lose most of the benefit
  • Assuming it blocks network access on releases without --allow-net
  • Treating it as a sandbox for untrusted plugins; use a separate process or container

Tips

  • Start with nothing, run your tests, and add flags for each ERR_ACCESS_DENIED
  • Put the flags in the start script so production and CI match
  • Combine with a non-root user and read-only container filesystem

Summary

  • --permission — deny by default
  • --allow-fs-read / write — grant paths
  • ERR_ACCESS_DENIED — what blocked calls throw
  • process.permission.has — check at runtime
