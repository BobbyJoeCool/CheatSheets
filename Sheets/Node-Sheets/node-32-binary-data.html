Reading Binary Formats

Binary file formats and network protocols store numbers as fixed-size fields: 8, 16, 32, or 64 bits, signed or unsigned, in big-endian or little-endian byte order. Buffer's read* / write* methods handle each case. The standard TypedArray, DataView, TextEncoder, and Blob APIs do the same jobs in code that must also run in browsers.

Notes

  • Network protocols are usually big-endian (BE)
  • x86 and ARM CPUs and most file formats are little-endian (LE)
  • 64-bit integers read as BigInt

Fixed-Width Fields

const buf = Buffer.alloc(8);
buf.writeUInt16BE(0x0102, 0);          // bytes 0–1 → 01 02
buf.writeInt32LE(-1, 2);               // bytes 2–5 → ff ff ff ff
buf.readUInt16BE(0);                   // 258
buf.readUInt16LE(0);                   // 513
buf.readUInt32LE(2);                   // 4294967295
buf.readInt32LE(2);                    // -1
buf.readBigUInt64BE(0);                // 64-bit value as BigInt

const u8 = new Uint8Array(buf.buffer, buf.byteOffset, buf.length);
const dv = new DataView(u8.buffer, u8.byteOffset, u8.byteLength);
dv.getUint16(0);                       // 258 (DataView defaults to BE)
dv.getUint16(0, true);                 // 513 (true = little-endian)

new TextEncoder().encode('hi');        // Uint8Array(2) [104, 105]
new TextDecoder().decode(new Uint8Array([104, 105]));   // 'hi'
const blob = new Blob(['hello'], { type: 'text/plain' });
await blob.text();                     // 'hello'

Code Explained

0x0102 — written as bytes 01 02 in BE order
LE read of 01 02 — becomes 0x0201 = 513
Signed vs unsigned — same bytes, different numbers
buf.byteOffset — small Buffers share a larger pool
DataView — standard API, choose endianness per call

Common Mistakes

  • Using buf.buffer directly; small Buffers live inside a shared 8 KB pool, so add byteOffset
  • Writing a value outside the range; Node throws ERR_OUT_OF_RANGE
  • Reading 64-bit IDs into a Number; values above 2⁵³ lose precision

Tips

  • Write down the format's endianness at the top of your parser
  • Use buf.readUIntBE(offset, 3) for odd sizes like 24-bit fields
  • Prefer DataView in libraries meant for both Node and browsers

Summary

  • readUInt16BE — typed read at an offset
  • BE / LE — byte order matters
  • DataView — portable binary access
  • TextEncoder / Blob — web-standard bytes
