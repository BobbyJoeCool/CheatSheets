Cluster & Scaling

cluster.fork() · isPrimary · load balancing · sticky sessions · PM2 cluster mode · when to use workers instead

Using Every Core

A Node process runs your JavaScript on one core. The node:cluster module forks one process per core, all listening on the same port; the primary process hands incoming connections to workers in turn. Today the same result usually comes from a process manager (PM2) or from running several containers behind a load balancer.

Notes

  • Workers are separate processes; they share no memory
  • In-memory sessions or caches differ per worker
  • Default scheduling is round-robin (except on Windows)

Cluster with Auto-Restart

import cluster from 'node:cluster';
import { availableParallelism } from 'node:os';
import { createServer } from 'node:http';

if (cluster.isPrimary) {
  const n = availableParallelism();
  for (let i = 0; i < n; i++) cluster.fork();     // one per core
  cluster.on('exit', (worker, code) => {
    console.log(`worker ${worker.process.pid} exited (${code})`);
    if (code !== 0) cluster.fork();               // replace crashed workers
  });
} else {
  createServer((req, res) => res.end(`pid ${process.pid}\n`))
    .listen(3000);                                // all share port 3000
}

Code Explained

isPrimary — the same file runs in every process
fork() — starts a worker running this file
'exit' — restart only on failure, not on shutdown
listen(3000) — the primary owns the socket

Common Mistakes

  • Storing sessions or rate-limit counters in memory; each worker sees a different subset of users
  • Running cluster inside Kubernetes pods that already scale horizontally; it fights CPU limits
  • Restarting workers in a tight loop when they crash at startup

Tips

  • Put shared state in Redis or a database
  • Prefer one process per container and scale containers
  • Back off restarts if workers die within seconds of starting

Summary

  • cluster.fork() — process per core
  • shared port — primary balances connections
  • PM2 — cluster plus ops tools
  • external state — required for scaling
