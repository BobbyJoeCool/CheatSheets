Databases from Node

Talking to Databases

Node apps reach SQL databases through a driver (pg for PostgreSQL, mysql2 for MySQL), usually behind a connection pool that reuses a fixed number of connections. Always use parameterized queries. ORMs and query builders (Prisma, Drizzle, Kysely) add types and migrations on top of the same drivers.

Notes

  • Create one pool per process and reuse it
  • A transaction must run on a single client
  • $1, $2 (pg) and ? (mysql2) are parameter placeholders

Pooling, Parameters & Transactions

import pg from 'pg';                              // npm i pg
const pool = new pg.Pool({ connectionString: process.env.DATABASE_URL });

const { rows } = await pool.query(
  'SELECT id, title FROM notes WHERE owner_id = $1 AND done = $2',
  [userId, false],
);

const client = await pool.connect();              // one client per transaction
try {
  await client.query('BEGIN');
  await client.query('UPDATE acct SET bal = bal - $1 WHERE id = $2', [50, a]);
  await client.query('UPDATE acct SET bal = bal + $1 WHERE id = $2', [50, b]);
  await client.query('COMMIT');
} catch (err) {
  await client.query('ROLLBACK');
  throw err;
} finally {
  client.release();                               // back to the pool
}

Code Explained

Pool — opens connections lazily up to max (default 10)
$1, $2 — values sent separately; injection-safe
pool.connect() — check out one client
ROLLBACK — undo both updates on any error
release() — in finally, or the pool runs dry

Common Mistakes

  • Building WHERE id = ${id} from user input; that's SQL injection, so use parameters
  • Running BEGIN via pool.query; each call may use a different connection
  • Forgetting release(); the app freezes once all clients are checked out

Tips

  • Size max so instances × max stays under the DB's connection limit
  • Close the pool on shutdown: await pool.end() (Sheet 19)
  • Use PgBouncer or a serverless driver for many short-lived instances

Summary

  • Pool — reuse connections
  • $1 / ? — always parameterize
  • connect + BEGIN/COMMIT — transactions
  • ORMs — types and migrations on top
