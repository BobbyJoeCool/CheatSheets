Crypto

randomUUID() · randomBytes() · createHash() · createHmac() · scrypt() · timingSafeEqual() · crypto.subtle

Hashing, Tokens & Encryption

node:crypto covers secure random values, hashes, HMAC signatures, password hashing, and encryption. The global crypto also exposes the browser-standard Web Crypto API (crypto.subtle), which is the better choice for code that must run in other runtimes. Never use Math.random() for anything security-related.

Notes

  • Hashes are one-way; encryption is reversible with the key
  • Fast hashes (SHA-256) are wrong for passwords; use scrypt or argon2
  • AES-GCM needs a unique IV for every message

Common Crypto Tasks

import { randomUUID, randomBytes, randomInt, createHash, createHmac,
  scrypt, timingSafeEqual } from 'node:crypto';
import { promisify } from 'node:util';

randomUUID();                                  // 'c0a8f2e4-…' (v4)
randomBytes(32).toString('base64url');         // session / API token
randomInt(1, 7);                               // 1–6, unbiased
createHash('sha256').update('hello').digest('hex');   // '2cf24dba5f…'
createHmac('sha256', secret).update(body).digest('hex');   // signature

const salt = randomBytes(16);
const hash = await promisify(scrypt)(password, salt, 64);  // store salt+hash
timingSafeEqual(hash, storedHash);             // constant-time compare

const key = await crypto.subtle.generateKey(
  { name: 'AES-GCM', length: 256 }, true, ['encrypt', 'decrypt']);
const iv = crypto.getRandomValues(new Uint8Array(12));
const sealed = await crypto.subtle.encrypt({ name: 'AES-GCM', iv }, key, data);

Code Explained

base64url — URL-safe token text
randomInt — avoids the bias of % n
HMAC — verifies webhooks were sent by someone with the secret
scrypt — deliberately slow; salt defeats precomputed tables
timingSafeEqual — === leaks timing information

Common Mistakes

  • Comparing signatures with ===; use timingSafeEqual on equal-length Buffers
  • Storing a password hash without its salt; you can't verify it later
  • Hardcoding encryption keys in source; load them from a secret manager

Tips

  • Use crypto.hash('sha256', data) for quick one-shot hashes
  • Store password hashes as salt:hash in hex or base64
  • Prefer a maintained library (jose) for JWTs instead of hand-rolling

Summary

  • randomUUID / randomBytes — secure randomness
  • createHash / createHmac — digests and signatures
  • scrypt — password hashing
  • crypto.subtle — Web Crypto encryption
