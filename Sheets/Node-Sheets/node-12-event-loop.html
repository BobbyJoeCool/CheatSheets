The Event Loop

phases · timers / poll / check / close · microtask queue · process.nextTick() · blocking the loop

How Node Schedules Work

The event loop is what lets one thread juggle many tasks. Node runs your synchronous code to the end, then loops through phases, each with its own queue of callbacks: expired timers, finished I/O, setImmediate, and close events. Between every callback it drains two higher-priority queues: process.nextTick first, then microtasks (promise reactions). The loop exits when nothing is left to wait for.

Notes

  • Only one callback runs at a time; there are no data races in JS code
  • A callback that takes 200 ms delays everything else by 200 ms
  • Timer delays are minimums, never guarantees

Execution Order

// order.cjs — run with: node order.cjs
const fs = require('node:fs');

console.log('1 sync');
setTimeout(() => console.log('timeout'), 0);
setImmediate(() => console.log('immediate'));
Promise.resolve().then(() => console.log('4 promise'));
process.nextTick(() => console.log('3 nextTick'));
console.log('2 sync');
// prints 1, 2, 3, 4, then timeout + immediate in either order

fs.readFile(__filename, () => {           // inside an I/O callback…
  setTimeout(() => console.log('B timeout'), 0);
  setImmediate(() => console.log('A immediate'));   // …immediate always runs first
});

const end = Date.now() + 500;
while (Date.now() < end) {}              // blocks: every timer above waits 500 ms

Code Explained

sync — all top-level code runs before any callback
nextTick — runs as soon as the current operation ends
then — microtask, right after the nextTick queue
timeout vs immediate — order from the main module depends on process timing
After I/O, the check phase comes before timers
while — busy loop starves the event loop

Common Mistakes

  • Expecting setTimeout(fn, 0) to run before a promise; microtasks always win
  • Recursive process.nextTick starves I/O completely; use setImmediate
  • In ES modules, the promise can log before nextTick; top-level ESM code is itself a microtask

Tips

  • Break long loops into chunks with await setImmediate() from timers/promises
  • Measure loop lag with monitorEventLoopDelay() (Sheet 53)
  • Prefer queueMicrotask over nextTick in new code

Summary

  • sync code — always finishes first
  • nextTick → microtasks — after each callback
  • timers → poll → check — phase order
  • blocking — delays every pending callback
