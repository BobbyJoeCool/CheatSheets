Diagnostics & Tracing

util.inspect() · util.debuglog() · NODE_DEBUG · --trace-warnings · diagnostics_channel · process.report

Seeing Inside a Running Process

Beyond a debugger, Node has built-in tools for diagnosing problems in place. util.inspect prints any value in full; util.debuglog adds debug logging that's off unless NODE_DEBUG enables it; process warnings report deprecations and leaks; diagnostics_channel lets tracing tools observe libraries; and diagnostic reports capture a JSON snapshot of the process.

Notes

  • NODE_DEBUG=http,net also enables core module logs
  • Warnings print to stderr once per process
  • APM agents (OpenTelemetry, Datadog) subscribe to diagnostics channels

Inspect, Debug Logs & Channels

import util from 'node:util';
import dc from 'node:diagnostics_channel';

util.inspect(deep, { depth: null, colors: true, breakLength: 100 });
const debug = util.debuglog('payments');   // NODE_DEBUG=payments to enable
debug('charged %d cents', 1250);           // PAYMENTS 4821: charged 1250 cents

process.on('warning', (w) => log.warn({ name: w.name, msg: w.message }));
process.emitWarning('Option "x" is old', 'DeprecationWarning', 'DEP_APP_001');

const ch = dc.channel('app:db.query');
ch.subscribe(({ sql, ms }) => metrics.observe('db_ms', ms));
if (ch.hasSubscribers) ch.publish({ sql, ms: 12 });   // near-zero cost if not

process.report.writeReport();              // report.20261002.123456.json

Code Explained

depth: null — print every nesting level
debuglog — section name is uppercased in the output
'warning' event — route warnings into your logger
hasSubscribers — skip building data no one reads
writeReport — stack, heap stats, handles, env

Diagnostic Flags

FlagShows
--trace-warningsStack for each warning
--trace-deprecationStack for deprecations
--throw-deprecationMake them errors
--stack-trace-limit=50Longer stacks
--report-on-fatalerrorReport on crash
--report-on-signalReport on SIGUSR2

Common Mistakes

  • Logging objects with console.log and seeing [Object]; use util.inspect(x, { depth: null })
  • Silencing all warnings with --no-warnings; you'll miss deprecation notices before upgrades
  • Publishing expensive payloads without checking hasSubscribers

Tips

  • Run CI with --throw-deprecation to catch deprecated APIs early
  • Use NODE_DEBUG=module to see why an import resolves where it does
  • Attach a diagnostic report to bug reports

Summary

  • util.inspect — full object output
  • debuglog — opt-in debug logs
  • diagnostics_channel — hooks for tracers
  • process.report — JSON process snapshot
