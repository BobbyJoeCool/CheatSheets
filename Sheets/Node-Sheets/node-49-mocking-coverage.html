mock.fn() · mock.method() · mock.timers · t.assert.snapshot() · --experimental-test-coverage · reporters

Fakes, Snapshots & Coverage

node:test includes mocking: spy on functions, replace object methods, and control timers so time-based code runs instantly. Mocks created through t.mock are restored when the test ends. Snapshots save a value to a file and compare future runs against it, and coverage reports which lines your tests executed.

Notes

  • mock.fn() records every call's args, result, and this
  • Timer mocks also cover Date when enabled
  • Module mocking needs --experimental-test-module-mocks

Mocks, Timers & Snapshots

import { test, mock } from 'node:test';
import assert from 'node:assert/strict';

test('calls the API once', async (t) => {
  const f = t.mock.method(globalThis, 'fetch',
    async () => Response.json({ id: 1 }));        // fake response
  await loadUser(1);
  assert.equal(f.mock.callCount(), 1);
  assert.match(f.mock.calls[0].arguments[0], /\/users\/1$/);
});                                               // fetch restored here

test('debounce waits 300 ms', (t) => {
  t.mock.timers.enable({ apis: ['setTimeout'] });
  const fn = mock.fn();
  debounce(fn, 300)();
  t.mock.timers.tick(299); assert.equal(fn.mock.callCount(), 0);
  t.mock.timers.tick(1);   assert.equal(fn.mock.callCount(), 1);
});

test('renders card', (t) => {
  t.assert.snapshot(renderCard({ title: 'Hi' }));  // compares to stored
});

Code Explained

t.mock.method — replaces a method for this test only
mock.calls[i].arguments — what each call received
timers.tick(ms) — advances fake time instantly
mock.fn() — a spy with no behavior
snapshot — first run writes the file, later runs compare

Mock API

CallUse
mock.fn(impl?)Spy / stub function
mock.method(obj, name)Replace a method
mock.getter / setterFake properties
mock.timers.enable()Fake time
mock.module(spec)Fake a module
mockImplementationOnceNext call only

Coverage & Snapshots

FlagDoes
--experimental-test-coverageCoverage report
--test-coverage-includeLimit to globs
--test-coverage-lines=80Fail under 80%
--test-update-snapshotsRewrite snapshots
--test-reporter=lcovFor coverage tools

Common Mistakes

  • Using top-level mock.method instead of t.mock; it isn't restored between tests
  • Snapshotting values with timestamps or random IDs; every run fails
  • Treating 100% coverage as "tested"; covered lines can still lack assertions

Tips

  • Inject dependencies (pass fetch in) so you need fewer mocks
  • Review snapshot diffs before running --test-update-snapshots
  • Set a coverage threshold in CI to stop it slipping

Summary

  • t.mock.method — scoped stubs
  • mock.timers — instant time travel
  • t.assert.snapshot — store-and-compare
  • --experimental-test-coverage — line coverage
