What Node.js Is

Node.js is a JavaScript runtime that runs outside the browser. It pairs Google's V8 engine (which executes JavaScript) with libuv (which handles files, sockets, timers, and threads). Your code runs on a single main thread; slow I/O is handed off and its callback runs later, so one process can serve thousands of connections without waiting. Created by Ryan Dahl in 2009, now maintained under the OpenJS Foundation.

Notes

  • File types: .js · .mjs (ESM) · .cjs (CommonJS) · .ts
  • Node 26 enters LTS in October 2026
  • From Node 27: one major release a year, every release becomes LTS
  • CPU-heavy work blocks the loop; move it to worker_threads

Hello, World & Non-Blocking I/O

// app.mjs — run with: node app.mjs
import { readFile } from 'node:fs/promises';
import { createServer } from 'node:http';

console.log('Hello, World!');              // Hello, World!

console.log('start');                      // printed 1st
readFile('notes.txt', 'utf8')              // handed off to libuv
  .then(text => console.log(text.length)); // printed 3rd, when the read finishes
console.log('end');                        // printed 2nd, nothing waited

createServer((req, res) => res.end('Hi\n'))
  .listen(3000, () => console.log('http://localhost:3000'));

Code Explained

node: prefix — marks a built-in core module
readFile — returns at once; result arrives as a promise
'end' before length — the loop never blocked on disk
createServer — one callback handles every request
listen() — keeps the process alive until closed

Common Mistakes

  • Assuming "single-threaded" means slow: only your JS is single-threaded; I/O runs in parallel
  • Running a long loop in a request handler; every other request waits until it ends
  • Using an odd-numbered or EOL version in production; they stop getting security fixes

Tips

  • Run production on an Active LTS line; test on Current in CI
  • Always import core modules as node:fs, not fs
  • Raise the pool with UV_THREADPOOL_SIZE for heavy fs or crypto work

Summary

  • V8 — runs your JavaScript
  • libuv — event loop and async I/O
  • non-blocking — start I/O, continue, handle result later
  • LTS — the version line to deploy
