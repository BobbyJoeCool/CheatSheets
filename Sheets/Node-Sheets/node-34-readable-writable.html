Readable & Writable Streams

'data' / 'end' events · async iteration · Readable.from() · write() return value · 'drain' · end()

Producing & Consuming Streams

You'll rarely subclass streams. Most of the time you consume Readables with for await, and create them from iterables or async generators with Readable.from(). For a custom destination, pass a write function to new Writable(). Readable.fromWeb and toWeb convert to and from the Web Streams that fetch uses.

Notes

  • Async iteration handles pause/resume for you
  • Call callback() in write, or the stream stalls
  • end(chunk) writes a final chunk and closes

Creating Readables & Writables

import { Readable, Writable } from 'node:stream';

const r = Readable.from(['a', 'b', 'c']);        // from any iterable
for await (const chunk of r) console.log(chunk); // a, b, c

async function* lines() {
  for (let i = 1; i <= 3; i++) yield `row ${i}\n`;
}
Readable.from(lines()).pipe(process.stdout);     // row 1, row 2, row 3

const upper = new Writable({
  write(chunk, encoding, callback) {
    process.stdout.write(chunk.toString().toUpperCase());
    callback();                                  // ready for the next chunk
  },
});
upper.write('hello ');
upper.end('world\n');                            // HELLO WORLD
upper.on('finish', () => console.log('done'));

const res = await fetch('https://example.com/data.csv');
const nodeStream = Readable.fromWeb(res.body);   // Web → Node stream

Code Explained

Readable.from — objectMode by default for non-Buffers
async function* — the easiest custom source
callback(err) — pass an error to fail the stream
'finish' — all writes processed
fromWeb — use Node stream APIs on a fetch body

Common Mistakes

  • Never calling callback in a custom write; the stream stops after one chunk
  • Mixing for await with 'data' listeners on the same stream
  • Breaking out of for await and expecting the source to stay open; it's destroyed

Tips

  • Generate large CSV or JSON exports with an async generator + Readable.from
  • Use stream/consumers (text, json) to read a whole stream
  • Add concurrency to map() to process chunks in parallel

Summary

  • for await — consume a Readable
  • Readable.from — make one from data
  • new Writable({ write }) — custom destination
  • fromWeb / toWeb — bridge to fetch streams
