Giving and Handling Reviews

Reviews happen on Files changed. Comment on a line or a range, propose exact code with a suggestion block, and collect comments into one review submitted as Comment, Approve or Request changes. Authors can commit suggestions directly (one at a time or batched) and resolve conversations once addressed.

Review Facts

  • Pending comments stay private until you submit the review
  • Tick Viewed per file; it resets if the file changes
  • Authors can't approve their own PRs

Who Can Do This

  • Role: Read (comment) · Write (approval counts toward rules)
  • Plan: Free
  • Repos: public and private

Review Efficiently

  1. Open Files changed; hide whitespace, pick unified/split
  2. Click + on a line (drag for a range) → Start a review
  3. Use Add a suggestion to propose replacement code
  4. Tick Viewed as you finish each file
  5. Review changes → Comment / Approve / Request changes
  6. Author: Commit suggestion or Add to batch, then resolve

⚠ Common Mistakes

  • Dozens of single comments instead of one review: dozens of notifications
  • Approving with "looks good" after reading the description only
  • Resolving reviewer threads without replying or changing anything

✓ Tips & Best Practices

  • Prefix comments: nit:, question:, blocking: so intent is clear
  • Batch suggestions so the author makes one commit
  • Check out bigger PRs locally or in a codespace to run them
