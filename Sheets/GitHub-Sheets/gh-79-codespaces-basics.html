A Dev Environment in the Cloud

A codespace is a cloud VM with your repo checked out, your dev container applied and VS Code attached, in the browser or desktop VS Code (or JetBrains). Start one from any branch or PR in seconds. You pay by core-hours of compute and GB of storage; personal accounts get a monthly free quota. Codespaces stop when idle and are deleted after a retention period.

Codespace Facts

  • Default idle timeout 30 min; retention 30 days after stopping
  • Forwarded ports are private by default
  • Uncommitted changes survive stop/start, not deletion

Who Can Do This

  • Role: Read on the repo (create for yourself)
  • Plan: Free quota for personal accounts; orgs pay
  • Repos: public and private

Spin One Up

  1. Repo → Code → Codespaces → Create codespace on main
  2. Or … → New with options: branch, region, machine type
  3. Wait for the dev container build (or a prebuild)
  4. Run your app; open the forwarded port from the Ports panel
  5. Commit + push as usual; Stop when done
  6. Manage all of them at github.com/codespaces

⚠ Common Mistakes

  • Leaving codespaces running: core-hours burn while idle until timeout
  • Making a port public to share a demo, then forgetting it
  • Keeping work only in a stopped codespace: it's deleted after retention

✓ Tips & Best Practices

  • Set a spending limit and a short idle timeout
  • Add a dotfiles repo to bring your shell setup everywhere
  • Use prebuilds for repos with slow container builds
