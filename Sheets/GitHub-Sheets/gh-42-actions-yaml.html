Actions: YAML for Workflows

maps & lists · | and > block scalars · quoting · anchors & aliases (& / *) · actionlint

Just Enough YAML

Workflow files are YAML: indentation (spaces only, usually 2) shows nesting, key: value makes a map, and - item makes a list. Most workflow bugs are YAML bugs: a wrong indent, an unquoted value that YAML turns into a boolean or number, or a multi-line run: written with the wrong block style. GitHub supports anchors and aliases (&name / *name) to reuse a block.

YAML Traps

  • Tabs are illegal; use spaces
  • on is fine as a key in workflows, but yes/no/on/off as values may become booleans in other tools; quote them
  • Values starting with *, &, !, {, [, @ or containing : must be quoted
  • Anchors work within one file only; merge keys (<<:) are not supported

Lists, Blocks and Anchors

on:
  push:
    branches: [main, "release/**"]   # flow list
    paths:                            # block list
      - "src/**"
      - "!src/docs/**"
jobs:
  test:
    runs-on: ubuntu-latest
    env: &common-env                  # anchor this map
      NODE_ENV: test
    steps:
      - run: |                        # literal: keeps newlines
          npm ci
          npm test
      - run: >                        # folded: newlines → spaces
          echo one
          two three                   # runs: echo one two three
  build:
    runs-on: ubuntu-latest
    env: *common-env                  # reuse the anchored map
    steps:
      - run: echo "$NODE_ENV"         # test

Code Explained

[a, b] and - a lines — two ways to write the same list
| — literal block; each line is a separate shell line
> — folded block; joins lines with spaces (rarely what you want for run:)
&common-env — names a node; *common-env pastes it
"release/**" — quoted because * would start an alias

In the Logs

  • Invalid workflow file: .github/workflows/ci.yml#L12 — YAML or schema error; the run fails instantly with no jobs
  • You have an error in your yaml syntax on line 12 — usually indentation; check the line above too

Scalars and Quoting

WriteYAML reads it as
version: 3.10number 3.1 ✖ — quote it: "3.10"
flag: yesboolean true in YAML 1.1 tools
path: *.jserror: alias — write "*.js"
msg: "tab\there"double quotes: backslash escapes work

Block Scalar Modifiers

IndicatorEffect
|keep newlines, one trailing newline
|-keep newlines, strip the final newline
>fold lines into one, single trailing newline
>-fold and strip final newline

⚠ Common Mistakes

  • Mixing 2- and 4-space indents within one list: the item lands under the wrong key
  • Using > for multi-command run: blocks: commands get glued onto one line
  • Trying <<: *anchor to merge and override keys: GitHub rejects merge keys

✓ Tips & Best Practices

  • Run actionlint locally or in CI: it catches YAML, expression and shellcheck errors before you push
  • Use the VS Code GitHub Actions extension for schema-aware autocomplete and validation
  • Prefer | for every multi-line run:; it reads exactly like a shell script

Quick Summary

  • key: value / - item — maps and lists
  • | — literal multi-line block (use for run:)
  • "quote" — versions, globs, special characters
  • &a / *a — anchor and reuse within one file
