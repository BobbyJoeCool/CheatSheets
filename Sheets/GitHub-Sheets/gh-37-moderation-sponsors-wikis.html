Moderation, Sponsors & Wikis

interaction limits · block user · hide / minimize comments · report content · .github/FUNDING.yml · Sponsors · repo wikis

Healthy Communities

Maintainers have tools to keep spaces civil: interaction limits temporarily restrict who can comment, hide or minimize comments, lock conversations, block users (personal or org-wide) and report abuse to GitHub. A FUNDING.yml adds a Sponsor button, and wikis give a repo a simple editable docs site.

Facts

  • Interaction limits last 24 h, 3 days, 1 week, 1 or 6 months
  • Org blocks apply to every org repo
  • A wiki is its own Git repo: REPO.wiki.git

Who Can Do This

  • Role: Triage (hide, lock) · Admin (limits, wiki) · Org owner (org block)
  • Plan: Free (private-repo wikis: Pro/Team+)
  • Repos: public and private

A Sponsor Button

# .github/FUNDING.yml
github: [octocat, hubot]          # GitHub Sponsors (up to 4)
patreon: octocat
open_collective: octo-project
ko_fi: octocat
buy_me_a_coffee: octocat
custom: ["https://paypal.me/octocat", "https://octo.dev/donate"]

Code Explained

github: — Sponsors profiles (users or orgs)
platform keys — one username each
custom: — up to 4 extra URLs
Settings → Sponsorships must be ticked to show the button

⚠ Common Mistakes

  • Arguing in a heated thread: lock it and point to the code of conduct
  • Adding FUNDING.yml without enabling Sponsorships in Settings
  • Critical docs in a wiki that nobody reviews

✓ Tips & Best Practices

  • Set interaction limits during a viral moment or spam wave
  • Saved replies with your code of conduct link speed up moderation
  • Disable the wiki if you use docs/ so there's one source of truth
