Planning With Projects

Projects are spreadsheet-like planning boards that pull in issues and pull requests from any repos owned by the same user or org, plus draft issues that live only in the project. Each project has custom fields and multiple views (table, board, roadmap). Changes sync both ways: closing an issue updates the project, and editing a field in the project updates the item.

Project Facts

  • Org projects can span many repos; link them to repos for the Projects tab
  • Draft issues convert to real issues when ready
  • Projects can be public or private, independent of repos

Who Can Do This

  • Role: Org member with project access (Write/Admin on project)
  • Plan: Free
  • Repos: public and private

Start a Project

  1. Org or profile → Projects → New project; pick a template (Board, Table, Roadmap)
  2. Paste issue URLs or type # to search and add items
  3. Add a Status single-select (Todo, In progress, Done)
  4. Create views: Board grouped by Status, Table for triage
  5. Link it to repos: project ⋯ → Settings → Manage access / link repo
  6. Turn on built-in workflows (Sheet 34)

⚠ Common Mistakes

  • One giant project for everything: views get slow and noisy; split by team or product
  • Tracking status in labels *and* a Status field
  • Making a project public without checking it: draft issues and custom field values become visible to everyone

✓ Tips & Best Practices

  • Use Ctrl/⌘ Space in a cell to open its options; arrow keys move around the table
  • Start from your org's project templates for consistent fields
  • Add a Sub-issues progress field to see epic completion
