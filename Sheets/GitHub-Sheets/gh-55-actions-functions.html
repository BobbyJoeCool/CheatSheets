Actions: Functions & Status Checks

contains · startsWith · format · join · toJSON · fromJSON · hashFiles · always()

Built-In Functions

Expressions have a small standard library: string tests (contains, startsWith, endsWith), formatting (format, join), JSON conversion (toJSON, fromJSON), hashFiles for cache keys, and status-check functions that decide whether a step or job runs after earlier failures. An if: with no status function gets an implicit success() && in front.

Status Logic

  • Default if: = success() && <your condition>
  • always() runs even if the run was cancelled
  • Prefer !cancelled() for cleanup that should respect cancel
  • failure() in a step: any earlier step failed

Functions in Context

steps:
  - if: contains(github.event.head_commit.message, '[docs]')
    run: echo "docs change"
  - if: startsWith(github.ref, 'refs/tags/v')
    run: echo "release build"
  - run: echo "${{ format('{0}-{1}', runner.os, github.run_number) }}"
    # → Linux-87
  - run: echo "${{ join(fromJSON('["a","b"]'), ', ') }}"   # a, b
  - uses: actions/cache@v5
    with:
      path: ~/.npm
      key: npm-${{ hashFiles('**/package-lock.json') }}
  - if: failure()
    run: echo "something above failed"
  - if: ${{ !cancelled() }}
    run: ./cleanup.sh

Code Explained

contains(str, sub) — also contains(array, item)
format('{0}', x) — {{ for a literal brace
fromJSON — string → object/number/boolean
hashFiles(glob) — SHA-256 of matching files, '' if none
failure() / !cancelled() — run after failures

In the Logs

  • Step shows ⊘ skipped after a failure — expected; add failure() or always() to if:
  • The template is not valid... hashFiles('...') failed — glob outside GITHUB_WORKSPACE

Status Functions

FunctionTrue when
success()all previous steps/jobs succeeded
failure()any previous step/job failed
cancelled()the run was cancelled
always()always, even on cancel
!cancelled()not cancelled (failures OK)

⚠ Common Mistakes

  • Using always() for long cleanup: it ignores cancel, so cancelled runs keep going
  • fromJSON(inputs.count) > 5 without fromJSON: comparing a string to a number
  • hashFiles on a path that doesn't exist yet: returns '', so every run shares one cache key

✓ Tips & Best Practices

  • Turn strings into booleans/numbers with fromJSON('true') / fromJSON('42')
  • Use steps.<id>.outcome == 'failure' with continue-on-error to react to one specific step
  • format with {{ }} escapes: format('{{0}}') prints {0}

Quick Summary

  • string tests — contains, startsWith, endsWith
  • format / join / toJSON / fromJSON — convert
  • hashFiles — cache keys
  • failure() / !cancelled() — after-failure logic
