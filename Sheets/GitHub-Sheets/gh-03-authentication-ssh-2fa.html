Sheet 03

Authentication: SSH, Passkeys & 2FA

2FA (TOTP / passkeys / security keys) · recovery codes · SSH keys · signing keys · HTTPS + tokens · sudo mode

Proving It's You

Signing in to the website uses your password plus two-factor authentication (2FA): an authenticator app, a passkey, a security key, or GitHub Mobile. Git operations use a separate credential: an SSH key or, over HTTPS, a token stored by a credential manager. Passwords never work for Git over HTTPS. Signing keys (SSH or GPG) add a Verified badge to commits.

Auth Facts

  • 2FA is required for accounts that contribute code on github.com
  • Save recovery codes; support can't bypass 2FA for you
  • One SSH key can be both an auth key and a signing key

Who Can Do This

  • Role: account owner
  • Plan: Free
  • Repos: account-wide

Secure Your Account

  1. Settings → Password and authentication → Enable 2FA; scan with an authenticator app
  2. Download the recovery codes and store them in a password manager
  3. Add a passkey for passwordless sign-in
  4. ssh-keygen -t ed25519 -C "you@example.com", then paste the .pub in SSH and GPG keys → New SSH key
  5. Test: ssh -T git@github.com
  6. Add the same key again as type Signing Key and set git config gpg.format ssh

⚠ Common Mistakes

  • Losing your phone with no recovery codes or backup method: you can be locked out for good
  • Typing your GitHub password at a Git HTTPS prompt: it's rejected; use a token or GCM
  • Uploading the private key (id_ed25519) instead of the .pub file

✓ Tips & Best Practices

  • Register at least two 2FA methods (passkey + app)
  • Turn on vigilant mode so unsigned commits show Unverified
  • Review Sessions and SSH keys once a quarter; remove old laptops

Quick Summary

  • 2FA / passkeys — web sign-in
  • SSH key or token — Git operations
  • signing key — Verified commits
  • recovery codes — your only way back in
