re-run with debug · ::group:: · ::error:: · step summary · actionlint · act · status badges

Finding Out What Went Wrong

Start at the first red step: the log above the failure usually explains it. For more detail, re-run with debug logging (or set the ACTIONS_STEP_DEBUG and ACTIONS_RUNNER_DEBUG secrets/variables to true). Inside scripts, workflow commands (::error::, ::group::) create annotations and collapsible sections, and the step summary gives a readable report.

Where to Look

  • Annotations on the run summary point to file and line
  • Set up job shows image version, token permissions, action versions
  • Post steps run cleanup (cache save, checkout cleanup)
  • Download all logs: run page → ⋯ → Download log archive

Workflow Commands

steps:
  - run: |
      echo "::group::Install"
      npm ci
      echo "::endgroup::"
      echo "::notice title=Build::Version 2.3.1"
      echo "::warning file=app.js,line=12::Deprecated API"
      echo "::error file=src/a.ts,line=4,col=7::Type mismatch"
      echo "::debug::visible only with debug logging"
  - name: Dump contexts when things go wrong
    if: failure()
    env:
      GITHUB_CTX: ${{ toJSON(github) }}
      STEPS_CTX: ${{ toJSON(steps) }}
    run: echo "$GITHUB_CTX"; echo "$STEPS_CTX"
  - run: |
      echo "## Test results" >> "$GITHUB_STEP_SUMMARY"
      echo "| Passed | Failed |" >> "$GITHUB_STEP_SUMMARY"
      echo "|---|---|" >> "$GITHUB_STEP_SUMMARY"
      echo "| 120 | 2 |" >> "$GITHUB_STEP_SUMMARY"

Code Explained

::group:: / ::endgroup:: — collapsible log section
::notice/warning/error — annotations, optional file/line
::debug:: — shown only with debug logging on
toJSON(steps) — see each step's outcome and outputs
$GITHUB_STEP_SUMMARY — Markdown report

⚠ Common Mistakes

  • Re-running the whole workflow when only one job flaked: use Re-run failed jobs
  • Echoing ${{ toJSON(github) }} directly in run:: quotes in payloads break the script; go through env:
  • Leaving debug secrets on permanently: logs get huge and slow

✓ Tips & Best Practices

  • ::stop-commands::<token> pauses command parsing when printing untrusted output
  • Run actionlint in a pre-commit hook or a tiny CI job
  • Add ?branch=main to a badge URL to pin it to one branch
