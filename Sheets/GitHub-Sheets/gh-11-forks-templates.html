Copying Repos the Right Way

A fork is your own copy of someone else's repo that stays connected to it: you push to your fork and open pull requests back to the upstream. Sync fork pulls upstream changes in. A template repository is different: Use this template creates a brand-new repo with the same files but fresh history and no link back. Use forks to contribute; templates to start new projects.

Fork Rules

  • Fork PRs run Actions with a read-only token and no secrets
  • Private forks of private repos are deleted if access is removed
  • Orgs can block forking of private repos

Who Can Do This

  • Role: Read (to fork) · Admin (to make a template)
  • Plan: Free
  • Repos: public and private

Contribute via a Fork

  1. Upstream repo → Fork → Create fork
  2. Clone your fork; add upstream: git remote add upstream <url>
  3. Branch, commit, push to your fork
  4. Contribute → Open pull request against upstream main
  5. Tick Allow edits by maintainers
  6. Before new work: Sync fork → Update branch

Automate It

Sync a fork from a script (REST)
curl -X POST -H "Authorization: Bearer $TOKEN" \
  https://api.github.com/repos/ME/FORK/merge-upstream -d '{"branch":"main"}'

⚠ Common Mistakes

  • Committing on your fork's main: your PR and fork drift; always branch
  • Forking to start a new product: use a template or a fresh repo
  • Expecting a fork's issues tab to collect bug reports: it's off by default

✓ Tips & Best Practices

  • Fork only the default branch unless you need others (checkbox on fork page)
  • Template repos can include .github/ workflows and issue templates
  • Delete stale forks from your profile; they clutter your portfolio

Quick Summary

  • fork — linked copy for PRs upstream
  • Sync fork — catch up with upstream
  • template — new repo, fresh history
  • fork PRs — no secrets in Actions
