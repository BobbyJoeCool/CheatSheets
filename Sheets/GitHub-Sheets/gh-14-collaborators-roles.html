Collaborators & Repo Roles

invite collaborator · Read / Triage / Write / Maintain / Admin · outside collaborators · custom roles · access audit

Who Can Do What in a Repo

Personal repos have one owner plus collaborators with write access. Organization repos use five roles that build on each other: Read, Triage, Write, Maintain and Admin. Access can come from org base permissions, a team, or a direct grant; the highest one wins. Outside collaborators get repo access without joining the org.

Role Facts

  • Triage manages issues/PRs without code write access
  • Maintain manages the repo without destructive settings
  • Custom repository roles: Enterprise

Who Can Do This

  • Role: Admin (repo) · Org owner
  • Plan: Free (custom roles: Enterprise)
  • Repos: public and private

Give Someone Access

  1. Settings → Collaborators and teams → Add people
  2. Search by username or email; pick a role
  3. They accept the invite (expires after 7 days)
  4. Prefer Add teams over individuals in orgs
  5. Review access regularly; remove people who left

Automate It

Grant a role (REST)
curl -X PUT -H "Authorization: Bearer $TOKEN" \
  https://api.github.com/repos/ORG/REPO/collaborators/USER \
  -d '{"permission":"triage"}'

⚠ Common Mistakes

  • Giving Admin to get someone unblocked: they can now change protections and delete the repo
  • Granting access person by person in an org: offboarding misses repos
  • Forgetting outside collaborators when auditing org members

✓ Tips & Best Practices

  • Triage is perfect for community helpers who label and close issues
  • Set org base permission to Read or None; grant more by team
  • Org → People → Export gives an access list for audits

Quick Summary

  • Read → Triage → Write → Maintain → Admin
  • highest grant wins
  • teams beat individual grants
  • outside collaborators — repo-only access
