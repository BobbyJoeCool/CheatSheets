Keeping Projects Up to Date Automatically

Built-in workflows handle routine updates: set Status when items are added, move items to Done when issues close or PRs merge, auto-add new issues that match a filter, and auto-archive old items. For anything more, use Actions with actions/add-to-project or the GraphQL API; both need a PAT or GitHub App token, since GITHUB_TOKEN can't reach projects.

Workflow Facts

  • Auto-add works per repo, with a filter like is:issue label:bug
  • Number of auto-add workflows is limited by plan
  • Auto-archive keeps old Done items out of views

Who Can Do This

  • Role: Admin on the project
  • Plan: Free (more auto-add workflows on Team/Enterprise)
  • Repos: public and private

Turn On the Basics

  1. Project ⋯ → Workflows
  2. Item added to project → Status: Todo
  3. Item closed and Pull request merged → Status: Done
  4. Auto-add to project: repo + filter is:issue,pr is:open
  5. Auto-archive items: is:closed updated:<@today-14d

Automate It

Add items from a workflow
on: { issues: { types: [opened] } }
# step:
- uses: actions/add-to-project@v1
  with:
    project-url: https://github.com/orgs/O/projects/7
    github-token: ${{ secrets.PROJECT_TOKEN }}
    labeled: bug

⚠ Common Mistakes

  • Using secrets.GITHUB_TOKEN with add-to-project: permission error
  • Two automations fighting over Status (built-in + Actions)
  • Auto-add with no filter: every issue from every repo floods in

✓ Tips & Best Practices

  • Use a GitHub App token (Sheet 17) instead of a personal PAT
  • Field and option IDs come from GraphQL; look them up once and store as vars
  • Keep the built-ins for simple status moves; Actions for custom logic

Quick Summary

  • built-in workflows — status moves
  • auto-add / auto-archive — intake and cleanup
  • actions/add-to-project — from Actions
  • PAT/App token — required for projects
