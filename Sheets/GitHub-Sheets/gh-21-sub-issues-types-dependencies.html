Sub-issues, Issue Types & Dependencies

sub-issues · parent issue · progress · issue types (Bug / Feature / Task) · blocked by / blocking · org-level types

Structure Inside Issues

Sub-issues break a large issue into child issues, with a progress bar on the parent; children can have their own children. Issue types (Bug, Feature, Task, or custom ones) are defined once per organization and set on any issue in its repos. Dependencies mark an issue as blocked by or blocking others, and blocked issues show an icon in lists and projects.

Limits

  • Up to 100 sub-issues per parent, nested up to 8 levels
  • Sub-issues can live in other repos of the same owner
  • Issue types are org-level (up to 25)

Who Can Do This

  • Role: Triage (set type, add sub-issues) · Org owner (define types)
  • Plan: Free
  • Repos: public and private (types need an org)

Break Down an Epic

  1. Open the parent issue → Create sub-issue (or Add existing)
  2. Set each child's assignee and type
  3. Drag sub-issues to reorder priority
  4. Sidebar → Relationships → Mark as blocked by
  5. Org Settings → Issue types: add, rename, color
  6. Filter lists: type:Bug, has:sub-issues, is:blocked

Automate It

Add a sub-issue (REST; uses the child's id, not number)
curl -X POST -H "Authorization: Bearer $TOKEN" \
  https://api.github.com/repos/O/R/issues/10/sub_issues \
  -d '{"sub_issue_id": 2271928459}'

⚠ Common Mistakes

  • Using labels bug/feature *and* issue types: pick one
  • Huge parent issues with 60 children: split into intermediate parents
  • Using the issue number with the sub-issues API: it needs the numeric id

✓ Tips & Best Practices

  • Show sub-issue progress as a field in Projects tables
  • Convert task-list items to sub-issues once they need an owner
  • Keep the type list short: Bug, Feature, Task covers most teams

Quick Summary

  • sub-issues — parent/child + progress
  • issue types — org-wide classification
  • blocked by / blocking — dependencies
  • type: is:blocked — search them
