Tracking Work With Issues

An issue tracks a bug, task or idea with a title, a Markdown body, comments and metadata: assignees, labels, type, milestone, projects and linked PRs. Close issues as completed, not planned or duplicate. Issues can be pinned (up to 3), locked to stop comments, or transferred to another repo with the same owner.

Issue Facts

  • Issue and PR numbers share one counter per repo
  • Up to 10 assignees per issue
  • Anyone with Read can open issues if Issues are enabled

Who Can Do This

  • Role: Read (open, comment) · Triage (assign, label, close)
  • Plan: Free
  • Repos: public and private

Write a Useful Issue

  1. Issues → New issue (pick a template if offered)
  2. Title: what's wrong, where ("Checkout fails for EUR prices")
  3. Body: steps to reproduce, expected vs actual, versions, screenshots
  4. Set type, labels, assignee, milestone
  5. Link the fixing PR with Fixes #N (Sheet 22)
  6. Close with a reason: Completed / Not planned / Duplicate

⚠ Common Mistakes

  • Vague titles like "bug": nobody can triage from the list
  • Closing without a reason or comment: reporters don't know what happened
  • Discussing big design questions in an issue: use Discussions

✓ Tips & Best Practices

  • Paste a code permalink in an issue to embed the snippet
  • Use saved replies for common answers (Settings → Saved replies)
  • Assign yourself before starting so work isn't duplicated
