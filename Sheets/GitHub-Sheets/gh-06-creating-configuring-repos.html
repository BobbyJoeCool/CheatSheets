Starting a Repository

New repository asks for an owner (you or an org), a name, visibility and optional starter files (README, .gitignore template, license). After that, Settings → General controls the repo's features (Issues, Projects, Wiki, Discussions), merge options (Sheet 27) and danger-zone actions. The About box on the Code tab sets the description, website and topics shown in search.

Visibility

  • Public — anyone can see; Private — only people you add
  • Internal — every member of your enterprise (Enterprise only)
  • Changing private → public exposes full history; scan for secrets first

Who Can Do This

  • Role: account owner, or org member allowed to create repos
  • Plan: Free (internal needs Enterprise)
  • Repos: public and private

Create and Configure

  1. + → New repository; choose owner, name, visibility
  2. Add a README, .gitignore template and license (or push an existing repo)
  3. Code tab → About ⚙: description, website, topics
  4. Settings → General → Features: turn off unused tabs (Wiki, Projects)
  5. Pull Requests: pick allowed merge methods, auto-delete head branches
  6. Rules → Rulesets: protect main (Sheet 09)

Automate It

Change settings from a script (REST)
curl -X PATCH -H "Authorization: Bearer $TOKEN" \
  https://api.github.com/repos/OWNER/REPO \
  -d '{"has_wiki":false,"delete_branch_on_merge":true}'

⚠ Common Mistakes

  • Initializing with a README when you plan to push an existing repo: unrelated histories on first push
  • Flipping a repo public without checking history for keys and .env files
  • Leaving every tab on: empty Wiki and Projects tabs look abandoned

✓ Tips & Best Practices

  • Use a template repo (Sheet 11) for repeatable project setups
  • Set delete_branch_on_merge on every repo; stale branches pile up fast
  • Terraform's github provider manages repo settings as code for whole orgs

Quick Summary

  • About — description + topics
  • Settings → General — features + merge options
  • Danger Zone — visibility, transfer, delete
