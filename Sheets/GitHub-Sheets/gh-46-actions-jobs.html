Actions: Jobs & Dependencies

jobs.<id> · needs · if: · outputs · continue-on-error · job graph

Ordering and Linking Jobs

Every key under jobs: is an independent job with its own runner. Jobs run in parallel unless needs: creates a dependency, which turns the workflow into a graph (shown visually on the run page). A job that needs a failed job is skipped unless its if: includes a status function like always(). Jobs share data only through outputs and artifacts.

Job Facts

  • Job ids: letters, digits, -, _; start with a letter or _
  • Default timeout-minutes is 360 (6 hours)
  • needs.<job>.result is success, failure, cancelled or skipped
  • continue-on-error: true lets the run succeed even if this job fails

Build → Test → Deploy

jobs:
  build:
    runs-on: ubuntu-latest
    outputs:
      version: ${{ steps.ver.outputs.version }}
    steps: [{ id: ver, run: echo version=1.4.0 >> $GITHUB_OUTPUT }]
  test:
    needs: build
    runs-on: ubuntu-latest
    continue-on-error: true            # flaky suite: don't block
    steps: [{ run: "echo test ${{ needs.build.outputs.version }}" }]
  deploy:
    needs: [build, test]               # waits for both
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    steps: [{ run: "echo v${{ needs.build.outputs.version }}" }]
  notify:
    needs: deploy
    if: always()                       # run even if deploy failed
    runs-on: ubuntu-latest
    steps: [{ run: "echo deploy was ${{ needs.deploy.result }}" }]

Code Explained

outputs: — map step outputs up to the job level
needs: build — waits; also exposes needs.build.outputs
if: at job level — skip the whole job; no ${{ }} needed
always() — run regardless of upstream result

In the Logs

  • Skipped job shows a grey ⊘ and This job was skipped — an upstream needs failed or if: was false
  • Empty needs.x.outputs.y — step id: missing, or the key never reached $GITHUB_OUTPUT

⚠ Common Mistakes

  • Using if: success() on a job after continue-on-error: the upstream counts as success, so it runs
  • Reading steps.x.outputs from another job: only needs.<job>.outputs crosses job boundaries
  • Forgetting always() on cleanup: it's skipped the moment anything upstream fails

✓ Tips & Best Practices

  • Make one all-checks job that needs every job and mark only it as a required check
  • Outputs are strings and capped at 1 MB per job; pass files with artifacts instead
  • Give jobs a name: so the checks list reads well in PRs

Quick Summary

  • jobs.<id> — parallel by default
  • needs: — order and data dependencies
  • outputs: + needs.x.outputs — pass values
  • if: always() — run after failures
