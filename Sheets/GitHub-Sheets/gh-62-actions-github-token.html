Sheet 62

Actions: GITHUB_TOKEN & Permissions

secrets.GITHUB_TOKEN · permissions: · contents: read · id-token: write · least privilege

The Automatic Token

Every job gets a fresh GITHUB_TOKEN: an installation token scoped to the current repo that expires when the job ends (or after 24 hours). Actions like checkout use it by default. The permissions: key sets exactly which scopes it gets; any scope you don't list becomes none. New repos and orgs default to read-only.

Permission Rules

  • permissions: at workflow level applies to all jobs; job level overrides
  • Listing any scope sets every unlisted scope to none
  • Fork PRs get read-only tokens no matter what you request
  • permissions: {} — no access at all

Least Privilege per Job

permissions:
  contents: read                     # baseline for every job
jobs:
  label-pr:
    runs-on: ubuntu-latest
    permissions:
      pull-requests: write
    steps:
      - run: gh pr edit "$PR" --add-label ci-passed
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          PR: ${{ github.event.pull_request.number }}
          GH_REPO: ${{ github.repository }}
  release:
    runs-on: ubuntu-latest
    permissions:
      contents: write                # create tags/releases
      id-token: write                # OIDC (Sheet 63)
    steps:
      - run: gh release create "v1.0.0" --generate-notes

Code Explained

workflow permissions: — baseline for all jobs
job permissions: — replaces the baseline for that job
GH_TOKEN — env var the gh CLI reads
id-token: write — allow requesting an OIDC token

In the Logs

  • Resource not accessible by integration (HTTP 403) — the token is missing a scope; add it under permissions:
  • refusing to allow a GitHub App to create or update workflow — pushing .github/workflows/ changes needs a PAT/App with workflows scope

⚠ Common Mistakes

  • Setting permissions: write-all to make an error go away: every step can now push and delete
  • Adding one scope at job level and losing contents: read: checkout fails on private repos
  • Expecting pushes made with GITHUB_TOKEN to trigger other workflows (Sheet 45)

✓ Tips & Best Practices

  • Set the org/repo default to read (Settings → Actions → Workflow permissions)
  • Declare permissions: in every workflow so reviewers see the blast radius
  • Use a GitHub App token (actions/create-github-app-token) for cross-repo access, not a PAT

Quick Summary

  • GITHUB_TOKEN — per-job, repo-scoped, auto-expires
  • permissions: — declare scopes; rest = none
  • contents: read — the safe baseline
  • 403 not accessible by integration — missing scope
