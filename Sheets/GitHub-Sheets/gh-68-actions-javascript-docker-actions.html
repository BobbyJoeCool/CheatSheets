Actions: JavaScript & Docker Actions

runs.using: node24 · @actions/core · @actions/github · ncc · Dockerfile · Marketplace

Writing Real Actions

A JavaScript action runs Node directly on the runner (runs.using: node24), starts fast and works on every OS. Use the @actions/core toolkit for inputs, outputs and logging, and @actions/github for an authenticated API client. A Docker action runs your image (Linux only) and suits other languages. Publish either by tagging releases in a public repo.

Packaging

  • Commit the bundled dist/index.js (ncc / esbuild / rollup)
  • node20 actions are deprecated in favor of node24
  • Docker actions rebuild each run unless you use image: docker://…
  • Marketplace needs name, description, branding and a public repo

Minimal JavaScript Action

// action.yml
// name: Greet  ·  inputs: { who: { required: true } }
// outputs: { time: { description: Greeting time } }
// runs: { using: node24, main: dist/index.js }

// src/index.js  →  bundle with: npx @vercel/ncc build src/index.js
import * as core from "@actions/core";
import * as github from "@actions/github";

try {
  const who = core.getInput("who", { required: true });
  core.info(`Hello ${who} from ${github.context.repo.repo}`);
  core.setOutput("time", new Date().toISOString());

  const octokit = github.getOctokit(core.getInput("token"));
  await octokit.rest.issues.createComment({
    ...github.context.repo,
    issue_number: github.context.issue.number,
    body: `Hi ${who}!`,
  });
} catch (err) {
  core.setFailed(err.message);          // marks the step failed
}

Code Explained

runs.using: node24 + main: — entry point
core.getInput / setOutput — read inputs, write outputs
github.context — repo, event payload, issue number
getOctokit(token) — REST/GraphQL client
core.setFailed — non-zero exit with an error annotation

Security Check

  • Risk: a public action is trusted with every user's token; a compromised maintainer account or a moved tag ships malware to all of them.
  • Fix: enable 2FA, protect release tags with rulesets, publish immutable releases, and keep dependencies few.

⚠ Common Mistakes

  • Committing src/ without the bundled dist/: Cannot find module '@actions/core'
  • Forgetting to move the v1 major tag after a v1.2.0 release
  • Docker actions on Windows/macOS runners: not supported

✓ Tips & Best Practices

  • Start from the actions/javascript-action or actions/typescript-action template repos
  • Test with a workflow in the action's own repo that does uses: ./
  • Release: tag v1.2.0, then git tag -f v1 && git push -f origin v1

Quick Summary

  • node24 — JS action, any OS
  • @actions/core / @actions/github — toolkit
  • dist/ bundle — commit it
  • Docker — Linux only, any language
