Publishing Packages on GitHub

GitHub Packages hosts packages next to your code: the Container registry (ghcr.io) for Docker/OCI images, plus registries for npm, Maven/Gradle, NuGet and RubyGems. Packages belong to a user or org and can be linked to a repo. From Actions, publish with GITHUB_TOKEN and packages: write; outside Actions, use a classic PAT with write:packages.

Package Facts

  • Public packages are free; private ones use storage + transfer quota
  • npm packages must be scoped to the owner: @octo-org/pkg
  • Fine-grained PATs don't cover most registries yet

Who Can Do This

  • Role: Write (publish via repo) · package Admin (settings)
  • Plan: Free (quota for private packages)
  • Repos: public and private

Container and npm Publishing

# Container image → ghcr.io
echo "$CR_PAT" | docker login ghcr.io -u USERNAME --password-stdin
docker build -t ghcr.io/octo-org/api:1.4.0 \
  --label org.opencontainers.image.source=https://github.com/octo-org/api .
docker push ghcr.io/octo-org/api:1.4.0

# npm → npm.pkg.github.com
# .npmrc
#   @octo-org:registry=https://npm.pkg.github.com
#   //npm.pkg.github.com/:_authToken=${NODE_AUTH_TOKEN}
# package.json
#   "name": "@octo-org/utils",
#   "publishConfig": { "registry": "https://npm.pkg.github.com" }
npm publish

Code Explained

docker login ghcr.io — PAT or GITHUB_TOKEN as password
image.source label — links the image to the repo
@scope:registry — send this scope to GitHub
publishConfig — publish target for npm publish

⚠ Common Mistakes

  • Uppercase letters in image names: registries require lowercase
  • Pushing an image without the source label: it isn't linked and won't inherit repo access
  • Using a personal PAT in CI when GITHUB_TOKEN would work

✓ Tips & Best Practices

  • In Actions: docker/login-action with ${{ github.actor }} + GITHUB_TOKEN (Sheet 65)
  • Tag images with the git SHA as well as the version
  • Public packages can be pulled anonymously; no login needed

Quick Summary
