Consistent Pull Requests

A file named pull_request_template.md (in .github/, root or docs/) pre-fills every new PR description. For several templates, put them in .github/PULL_REQUEST_TEMPLATE/ and pick one with ?template=name.md in the compare URL. Combine templates with conventions such as Conventional Commits titles to make history and release notes readable.

Template Facts

  • Only the default branch's template is used
  • Task-list checkboxes become a progress count
  • Org .github repo templates act as defaults

Who Can Do This

  • Role: Write (add template)
  • Plan: Free
  • Repos: public and private

Conventional Commit Types

TypeUse
feat:new feature (minor bump)
fix:bug fix (patch bump)
docs: / test:docs / tests only
refactor: / chore:no behavior change / tooling
feat!: or BREAKING CHANGE:major bump

⚠ Common Mistakes

  • Template in a feature branch: not used until merged to default
  • Twenty-item checklists: people tick everything without reading
  • Enforcing title formats without telling contributors (add it to CONTRIBUTING)

✓ Tips & Best Practices

  • Squash merges + Conventional PR titles = clean changelog for free
  • Link CONTRIBUTING.md at the top of the template
  • Add a ## Risk line for anything that touches data or auth

Quick Summary

  • pull_request_template.md — default PR body
  • PULL_REQUEST_TEMPLATE/ + ?template= — choices
  • Conventional Commits — readable titles
  • short checklists — actually used
