No Long-Lived Keys, No Injection

OpenID Connect (OIDC) lets a job ask GitHub for a short-lived signed token and trade it with AWS, Azure or GCP for temporary credentials, so no cloud keys live in secrets. The cloud trusts tokens whose subject claim matches your repo, branch or environment. Pair OIDC with the hardening basics: no expressions in scripts, pinned actions, and minimal permissions.

OIDC Setup

  • Cloud side: add GitHub's OIDC provider (token.actions.githubusercontent.com) and a role
  • Trust policy: match sub, e.g. repo:ORG/REPO:environment:production
  • Workflow: permissions: id-token: write
  • Tokens last minutes; nothing to rotate

AWS via OIDC + Safe Script Input

permissions:
  id-token: write
  contents: read
jobs:
  deploy:
    runs-on: ubuntu-latest
    environment: production
    steps:
      - uses: actions/checkout@v6
      - uses: aws-actions/configure-aws-credentials@v5
        with:
          role-to-assume: arn:aws:iam::123456789012:role/gh-deploy
          aws-region: us-east-2
      - run: aws s3 sync ./site s3://my-bucket --delete

      # ✖ injection: title is pasted into the script
      # - run: echo "${{ github.event.issue.title }}"
      # ✔ safe: value arrives as data
      - env:
          TITLE: ${{ github.event.issue.title }}
        run: echo "$TITLE"

Code Explained

id-token: write — required to mint the OIDC token
role-to-assume — AWS role whose trust policy allows this repo
environment: — becomes part of the sub claim
env: + "$TITLE" — the injection-proof pattern

In the Logs

  • Could not assume role with OIDC: Not authorized to perform sts:AssumeRoleWithWebIdentity — the trust policy's sub/aud doesn't match this run
  • Credentials could not be loaded — missing id-token: write

⚠ Common Mistakes

  • Trust policy sub = repo:ORG/*: every repo and branch in the org can assume the role
  • Leaving old access keys in secrets after moving to OIDC
  • Thinking env: protects against injection when you then eval "$TITLE"

✓ Tips & Best Practices

  • Scope trust to environment:production so only approved deploy jobs get prod access
  • Run zizmor to audit workflows for injection, excessive permissions and unpinned actions
  • Turn on Settings → Actions → Require actions to be pinned to a full-length commit SHA where available

Quick Summary

  • OIDC — short-lived cloud creds, no stored keys
  • id-token: write — required permission
  • env: not ${{ }} in run: — stop injection
  • pin · review · lint — hardening basics
