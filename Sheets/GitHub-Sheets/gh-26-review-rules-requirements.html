Review Rules & Requirements

required approvals · dismiss stale reviews · code owner review · last-push approval · re-request review · auto-assignment (round robin / load balance)

Making Reviews Required

A ruleset's Require a pull request rule turns reviews into a gate: set the number of approvals, dismiss approvals when new commits arrive, require code owner review, require approval of the most recent push by someone other than the pusher, and require all conversations resolved. Team code review settings can auto-assign reviewers from a team.

Rule Facts

  • Only reviewers with Write access count toward approvals
  • Last-push approval stops self-approved last-minute changes
  • Auto-assignment picks round-robin or load-balanced members

Who Can Do This

  • Role: Admin (rules) · team maintainer (auto-assignment)
  • Plan: Free for public; Team+ for private
  • Repos: public and private (plan-dependent)

Require One Real Review

  1. Ruleset → Require a pull request before merging
  2. Required approvals: 1 (or 2 for critical repos)
  3. Tick Dismiss stale approvals when new commits are pushed
  4. Tick Require review from Code Owners
  5. Tick Require approval of the most recent reviewable push
  6. Team → Settings → Code review → Enable auto assignment

Automate It

Request reviewers (REST)
curl -X POST -H "Authorization: Bearer $TOKEN" \
  https://api.github.com/repos/O/R/pulls/42/requested_reviewers \
  -d '{"team_reviewers":["backend"]}'

⚠ Common Mistakes

  • Required approvals on a solo repo: you can't approve your own PR and get stuck
  • Not dismissing stale approvals: big changes merge on an old OK
  • Code owner review on, but CODEOWNERS has errors: requirement silently can't be met

✓ Tips & Best Practices

  • Solo maintainer? Require PRs + checks but 0 approvals
  • Request a team, not a person; auto-assignment spreads the load
  • The merge box lists every unmet requirement; read it before asking for help

Quick Summary

  • require PR — approvals as a gate
  • dismiss stale + last-push — keep approvals honest
  • code owners — area experts must approve
  • auto-assignment — fair reviewer rotation
