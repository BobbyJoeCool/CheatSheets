Actions: Your First Workflow

on: push · runs-on: ubuntu-latest · actions/checkout · run: · Actions tab · run logs

From Zero to a Green Check

Create .github/workflows/ci.yml, commit it, and push. GitHub reads every file in that folder on each event, finds the ones whose on: matches, and queues their jobs. The result shows up as a check on the commit and pull request: a yellow dot while running, a green ✓ or red ✗ when done. Click it, or open the Actions tab, to see the logs.

Before You Push

  • The workflow must exist on the branch that is pushed (for push) or the PR's head (for pull_request)
  • Without actions/checkout, the runner has an empty working directory
  • Pause a workflow: Actions tab → workflow → ⋯ → Disable workflow

A Complete Starter (Python)

# .github/workflows/ci.yml
name: CI
on:
  push:
    branches: [main]
  pull_request:

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - name: Check out code
        uses: actions/checkout@v6
      - name: Set up Python
        uses: actions/setup-python@v6
        with:
          python-version: "3.13"
      - name: Install dependencies
        run: pip install -r requirements.txt
      - name: Run tests
        run: pytest -q

Code Explained

branches: [main] — run on pushes to main only
pull_request: — empty = every PR targeting any branch
name: on a step — readable label in the log
"3.13" — quoted so YAML doesn't read it as the number 3.13 (3.10 would become 3.1)
Non-zero exit code from any step fails the job and stops later steps

In the Logs

  • Success: Job succeeded, then a green ✓ on the commit and PR
  • Process completed with exit code 1. — your command failed; scroll up to the first red line
  • Run never appears → file in wrong folder, YAML error, or on: filter didn't match

⚠ Common Mistakes

  • Forgetting actions/checkout: the next step fails with "file not found" because the workspace is empty
  • Unquoted versions like python-version: 3.10: YAML reads 3.1
  • Testing a new workflow on a feature branch with branches: [main]: it never fires there

✓ Tips & Best Practices

  • Add workflow_dispatch: to on: so you can start the run by hand while testing (Sheet 44)
  • Check the version major tags on each action's README; pin and update via Dependabot (Sheet 63)
  • Use npm ci / pip install -r not npm install, so CI matches the lockfile exactly

Quick Summary

  • .github/workflows/ci.yml — commit it and push
  • actions/checkout — always the first step
  • setup-* actions — install the language toolchain
  • exit code ≠ 0 — fails the step and job
