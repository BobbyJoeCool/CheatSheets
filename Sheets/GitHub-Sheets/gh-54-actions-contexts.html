Actions: Contexts

github · env · vars · secrets · steps · runner · needs · matrix · inputs

What Expressions Can Read

A context is an object of run information that expressions can read: github (event, repo, ref, actor), env, vars, secrets, job, steps, runner, strategy, matrix, needs and inputs. Each is available only in certain places: you can't read steps in runs-on, or secrets in an if: at job level. Dump one with toJSON() to see its shape.

Availability Gotchas

  • runs-on, concurrency, job if: can't see env or steps
  • secrets can't be used directly in if:; copy to env first
  • github.event holds the raw webhook payload for the trigger
  • vars — non-secret config variables (Sheet 61)

Reading Contexts

jobs:
  info:
    runs-on: ubuntu-latest
    steps:
      - id: who
        run: echo "name=$GITHUB_ACTOR" >> "$GITHUB_OUTPUT"
      - run: |
          echo "repo:   ${{ github.repository }}"     # owner/repo
          echo "ref:    ${{ github.ref_name }}"       # main / 42/merge
          echo "sha:    ${{ github.sha }}"
          echo "actor:  ${{ steps.who.outputs.name }}"
          echo "os:     ${{ runner.os }}"
          echo "region: ${{ vars.AWS_REGION }}"
      - name: Dump the event payload
        env:
          EVENT: ${{ toJSON(github.event) }}
        run: echo "$EVENT" | jq '.head_commit.message'

Code Explained

github.repository — owner/repo
github.ref_name — short branch/tag name
steps.<id>.outputs — values earlier steps wrote
vars.NAME — config variable from settings
toJSON(...) via env: — safe way to inspect payloads

Security Check

  • Risk: fields like github.event.issue.title, .body, github.head_ref and commit messages are attacker-controlled.
  • Fix: never place them directly in run:; pass through env: and quote the variable.

⚠ Common Mistakes

  • if: secrets.TOKEN != '' at job level: not allowed; set env: HAS_TOKEN: ${{ secrets.TOKEN != '' }} in a step
  • Using github.head_ref on push events: it's only set for PR events
  • Expecting github.sha on pull_request to be the head commit: it's the merge commit

✓ Tips & Best Practices

  • PR head commit: github.event.pull_request.head.sha
  • Docs table Context availability lists exactly where each context works
  • Prefer default env vars ($GITHUB_SHA) inside scripts; contexts in YAML keys

Quick Summary

  • steps / needs — data from steps / jobs
  • vars / secrets — settings values
