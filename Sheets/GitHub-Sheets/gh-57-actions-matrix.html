Actions: Matrix Strategy

strategy.matrix · include / exclude · fail-fast · max-parallel · fromJSON

One Job, Many Combinations

strategy.matrix expands one job definition into a job per combination of the listed values. A 3 × 2 matrix of Node versions and operating systems produces six parallel jobs, each reading its values from the matrix context. include adds or extends combinations, exclude removes them, and the matrix can even come from JSON produced by an earlier job.

Limits & Defaults

  • Max 256 jobs per matrix per workflow run
  • fail-fast: true (default) cancels the rest when one fails
  • max-parallel caps how many run at once
  • Each combination shows as its own check: test (22, ubuntu-latest)

Static and Dynamic Matrices

jobs:
  test:
    runs-on: ${{ matrix.os }}
    strategy:
      fail-fast: false
      max-parallel: 4
      matrix:
        os: [ubuntu-latest, windows-latest]
        node: [20, 22, 24]
        exclude:
          - { os: windows-latest, node: 20 }
        include:
          - { os: ubuntu-latest, node: 24, coverage: true }
    steps:
      - uses: actions/setup-node@v6
        with: { node-version: "${{ matrix.node }}" }
      - run: npm test ${{ matrix.coverage && '-- --coverage' || '' }}

  dynamic:
    needs: plan                     # plan outputs '["api","web"]'
    strategy:
      matrix:
        app: ${{ fromJSON(needs.plan.outputs.apps) }}

Code Explained

runs-on: ${{ matrix.os }} — matrix picks the runner
exclude — drop one combination (5 jobs remain)
include with matching keys — adds coverage to that job
fromJSON(...) — matrix from an earlier job's output

In the Logs

  • Sibling jobs show cancelled after one fails — fail-fast is on; set fail-fast: false
  • Matrix vector 'app' does not contain any values — the dynamic list was empty

⚠ Common Mistakes

  • Unquoted versions in the matrix ([3.10, 3.11]): 3.10 becomes 3.1
  • Required checks naming a matrix job that no longer exists after a version bump
  • Using continue-on-error on the job when you meant fail-fast: false

✓ Tips & Best Practices

  • Add name: test (${{ matrix.os }}) for readable check names
  • Use continue-on-error: ${{ matrix.experimental }} to allow failures on nightly versions only
  • Combine matrix + summary job (needs: test) to have one stable required check
