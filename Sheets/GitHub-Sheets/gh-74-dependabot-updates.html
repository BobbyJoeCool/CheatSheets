Dependabot Version & Security Updates

.github/dependabot.yml · package-ecosystem · schedule · groups · ignore · cooldown · security updates · @dependabot rebase

Automatic Dependency PRs

Dependabot security updates open PRs that bump a vulnerable dependency to the patched version. Version updates keep everything current on a schedule you define in .github/dependabot.yml. Groups combine related bumps into one PR, ignore skips versions, and cooldown waits a few days after a release before proposing it, which avoids grabbing compromised packages on day one.

Facts

  • Security updates are toggled in Settings; version updates need the file
  • One updates entry per ecosystem + directory
  • Dependabot PRs run Actions with read-only token and Dependabot secrets

Who Can Do This

  • Role: Write (merge PRs) · Admin (enable)
  • Plan: Free
  • Repos: public and private

A Practical dependabot.yml

# .github/dependabot.yml
version: 2
updates:
  - package-ecosystem: npm
    directory: "/"
    schedule: { interval: weekly, day: monday }
    cooldown: { default-days: 5 }
    groups:
      minor-and-patch: { update-types: [minor, patch] }
    ignore:
      - dependency-name: "react*"
        update-types: [version-update:semver-major]
    labels: [dependencies]
  - package-ecosystem: github-actions
    directory: "/"
    schedule: { interval: weekly }

Code Explained

package-ecosystem — npm, pip, maven, gradle, docker, github-actions…
cooldown — wait N days after a release
groups — one PR for many bumps
ignore — skip majors for chosen deps
github-actions — keeps action pins current

⚠ Common Mistakes

  • No github-actions entry: action pins go stale
  • Daily schedules with no groups: a wall of PRs every morning
  • Auto-merging majors: keep auto-merge to patch/minor with green CI

✓ Tips & Best Practices

  • Auto-merge patch updates with dependabot/fetch-metadata + auto-merge
  • Use cooldown on fast-moving ecosystems like npm
  • Store registry credentials as Dependabot secrets, not Actions secrets

Quick Summary
