Sheet 65

Actions: Deploy & Release Recipes

deploy-pages · docker/build-push-action · GHCR · release on tag · attestations

Three Workflows Worth Copying

Most deploys follow a pattern: build, package, publish. GitHub Pages deploys a folder uploaded as a Pages artifact. Container images are built with Docker Buildx and pushed to the GitHub Container Registry (ghcr.io) using GITHUB_TOKEN. Releases are created when a v* tag is pushed, with notes generated from merged PRs.

Setup Notes

  • Pages: Settings → Pages → Source: GitHub Actions
  • GHCR needs packages: write; the image links to the repo
  • Releases need contents: write
  • gh is preinstalled on hosted runners

Pages, Container, Release

# 1) GitHub Pages — permissions: pages: write, id-token: write
  - uses: actions/upload-pages-artifact@v4
    with: { path: ./dist }
  - id: deployment
    uses: actions/deploy-pages@v4    # environment: github-pages

# 2) Container to GHCR — permissions: packages: write
  - uses: docker/login-action@v3
    with:
      registry: ghcr.io
      username: ${{ github.actor }}
      password: ${{ secrets.GITHUB_TOKEN }}
  - uses: docker/build-push-action@v6
    with:
      push: true
      tags: ghcr.io/${{ github.repository }}:${{ github.ref_name }}

# 3) Release on tag — on: push: tags: ["v*"]
  - run: gh release create "$GITHUB_REF_NAME" --generate-notes
    env: { GH_TOKEN: "${{ github.token }}" }

Code Explained

upload-pages-artifact + deploy-pages — the Pages pair
github.actor + GITHUB_TOKEN — GHCR login, no PAT
build-push-action — Buildx build + push
--generate-notes — notes from PR titles since last tag
github.token — same as secrets.GITHUB_TOKEN

Security Check

  • Risk: a release job triggered by any tag push lets anyone with write access publish from unreviewed commits.
  • Fix: protect v* tags with a ruleset, gate the job with an environment:, and add build provenance with actions/attest-build-provenance.

Image Tag Patterns

TagWhen
:sha-abc1234every build (traceable)
:mainlatest from the default branch
:1.4.2 / :1.4 / :1semver from a v1.4.2 tag
:latestnewest release only
:pr-42preview builds (don't push from forks)

⚠ Common Mistakes

  • Pages deploy without id-token: write and pages: write: the deploy step fails
  • Uppercase letters in GHCR image names: registry names must be lowercase
  • Building releases on push to main and also on tags: two releases race

✓ Tips & Best Practices

  • docker/metadata-action generates the tag set above from git refs
  • Use cache-from: type=gha / cache-to: type=gha,mode=max to cache Docker layers
  • npm publish --provenance and PyPI trusted publishing use OIDC: no tokens

Quick Summary

  • Pages — upload artifact, then deploy-pages
  • GHCR — login with GITHUB_TOKEN, build-push
  • Releases — gh release create on v* tags
  • gate deploys with environments
