Automatic Reviewers by Path

A CODEOWNERS file maps file patterns to the people or teams responsible for them. When a pull request changes matching files, those owners are automatically requested for review. With a ruleset's Require review from Code Owners, the PR can't merge until an owner approves. GitHub reads the file from the PR's base branch.

Rules

  • Locations: .github/, root, or docs/ (first found wins)
  • Last matching pattern wins, not the most specific
  • Owners must have Write access to the repo

Who Can Do This

  • Role: Write (edit file) · Admin (require owner review)
  • Plan: Free for public; Team+ to enforce on private
  • Repos: public and private

A CODEOWNERS File

# .github/CODEOWNERS
# Default owners for everything
*                       @octo-org/maintainers

# Directory (and everything under it)
/docs/                  @octo-org/docs-team
/src/payments/          @alice @octo-org/payments

# File types anywhere
*.tf                    @octo-org/platform
package*.json           @octo-org/maintainers

# Specific file
/.github/workflows/     @octo-org/platform

# Remove owners for a path (no owner listed)
/src/generated/

Code Explained

* first — the fallback for every file
/docs/ — leading / anchors to the repo root
later lines override earlier ones for matching files
pattern with no owner — clears ownership there
workflows owned by platform — reviews CI changes

Pattern Syntax

PatternMatches
*.jsany .js file, any depth
/build/root build folder only
docs/*files directly in any docs/
**/logslogs folder at any depth
apps/*/README.mdone level of wildcard

Valid Owners

OwnerExample
User@alice
Team (visible, write access)@octo-org/payments
Email of a useralice@example.com
Not allowed! negation, [ ] ranges, \# escapes

⚠ Common Mistakes

  • Putting the broad * rule at the bottom: it overrides every specific line above
  • Listing a team without write access: GitHub shows an error and ignores it
  • Editing CODEOWNERS in a PR and expecting it to apply to that PR: base branch version is used

✓ Tips & Best Practices

  • Open the file on GitHub: syntax errors are highlighted inline
  • Own .github/workflows/ and CODEOWNERS itself with a trusted team
  • Keep it short; one team per area beats long lists of people

Quick Summary

  • CODEOWNERS — path → reviewers
  • last match wins
  • owner review rule — enforce approval
  • base branch — where the file is read
