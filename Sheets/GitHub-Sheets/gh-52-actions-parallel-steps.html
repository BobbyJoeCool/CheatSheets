Actions: Parallel & Background Steps

background: true · wait · wait-all · cancel · parallel:

Concurrency Inside One Job

Since mid-2026, steps don't have to be strictly sequential. background: true starts a step and moves on immediately; wait blocks until named background steps finish, wait-all until all of them do, and cancel stops one. parallel: is shorthand for a group of background steps plus an automatic wait. Everything shares one runner: same files, CPU and memory.

Rules

  • Up to 10 background steps at once per job; extras queue
  • A background step's outputs and env changes appear only after a wait that includes it
  • If a background step fails, the wait for it fails
  • wait, wait-all and cancel steps have no run/uses

Build in Parallel, Test Against a Server

steps:
  - uses: actions/checkout@v6
  - run: npm ci
  - parallel:                     # all three at once, then wait
      - run: npm run build:web
      - run: npm run build:api
      - run: npm run lint
  - id: server
    run: npm start                # never exits on its own
    background: true
  - run: npx wait-on http://localhost:3000
  - run: npm run test:e2e
  - cancel: server                # stop the server cleanly

  # Explicit form:
  - { id: a, run: ./job-a.sh, background: true }
  - { id: b, run: ./job-b.sh, background: true }
  - wait: [a, b]                  # or: - wait-all:

Code Explained

parallel: — list of steps; next step waits for all
background: true — start and continue immediately
wait-on — started ≠ ready; poll before testing
cancel: server — terminate a long-running step
wait: [a, b] — join specific steps by id

⚠ Common Mistakes

  • Reading a background step's output before wait: it's empty
  • Starting a server in the background with no readiness check: tests hit a closed port
  • Parallel steps writing the same files or ports: they race on the shared runner

✓ Tips & Best Practices

  • Give background steps a name:: each gets its own log section
  • Use cancel: for servers; a never-ending background step keeps wait-all pending until timeout
  • Linters and validators may lag new syntax; update actionlint and your editor extension

Quick Summary

  • parallel: — run a group, then continue
  • background: true — fire and forget (for now)
  • wait / wait-all — join; surfaces outputs
  • cancel — stop long-running steps
