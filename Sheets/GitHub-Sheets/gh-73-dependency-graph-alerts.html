Knowing What You Depend On

The dependency graph reads manifests and lockfiles (and data submitted by Actions) to list every dependency, direct and transitive. When the GitHub Advisory Database has an advisory for one of them, Dependabot alerts you with severity, affected versions, the fix version and the exploit-likelihood score (EPSS). Auto-triage rules dismiss or snooze noise in bulk.

Graph Facts

  • Export an SBOM (SPDX) from Insights → Dependency graph
  • Alerts list the vulnerable call paths for some ecosystems
  • Dismiss with a reason so the history makes sense

Who Can Do This

  • Role: Write (view alerts) · Admin (settings, rules)
  • Plan: Free
  • Repos: public and private

Triage Dependabot Alerts

  1. Security → Dependabot; sort by severity or EPSS
  2. Open an alert: affected range, patched version, advisory
  3. Merge the security-update PR, or upgrade by hand
  4. Not reachable? Dismiss → reason (not used, tolerable risk…)
  5. Add an auto-triage rule, e.g. dismiss low-severity dev-only alerts

Automate It

Block risky dependency changes in PRs
on: pull_request
# step:
- uses: actions/dependency-review-action@v4
  with:
    fail-on-severity: high
    deny-licenses: GPL-3.0, AGPL-3.0

⚠ Common Mistakes

  • Repos without lockfiles: transitive dependencies are invisible
  • Dismissing alerts without a reason: next audit starts over
  • Treating all alerts equally: fix high severity + high EPSS first

✓ Tips & Best Practices

  • Use the dependency submission API for Gradle/Maven builds to capture resolved deps
  • Pair alerts with security updates (Sheet 74) for automatic fix PRs
  • Export the SBOM for compliance requests
