Actions: Env Vars, Outputs & File Commands

env: · GITHUB_* vars · $GITHUB_ENV · $GITHUB_OUTPUT · $GITHUB_PATH · $GITHUB_STEP_SUMMARY

Passing Values Between Steps

env: sets environment variables at workflow, job or step level (the narrowest wins). To hand a value to later steps, a step appends NAME=value lines to special files: $GITHUB_ENV (env var for the rest of the job), $GITHUB_OUTPUT (a step output, read as steps.<id>.outputs.NAME), $GITHUB_PATH (prepend to PATH) and $GITHUB_STEP_SUMMARY (Markdown on the run page).

Rules

  • Values written to these files apply from the next step on
  • env context = YAML values; $VAR in shell = the real environment
  • Multiline values need a delimiter (NAME<<EOF)
  • ::set-output / ::set-env are deprecated or disabled; use the files

Writing to the File Commands

env:
  APP: shop                              # workflow level
jobs:
  build:
    runs-on: ubuntu-latest
    env: { STAGE: test }                 # job level
    steps:
      - id: ver
        run: |
          echo "BUILD_DATE=$(date +%F)" >> "$GITHUB_ENV"
          echo "version=2.3.1" >> "$GITHUB_OUTPUT"
          echo "$HOME/.local/bin" >> "$GITHUB_PATH"
          {
            echo "NOTES<<EOF"
            git log -3 --oneline
            echo "EOF"
          } >> "$GITHUB_ENV"
      - run: |
          echo "$APP $BUILD_DATE v${{ steps.ver.outputs.version }}"
          echo "### Built v2.3.1 :rocket:" >> "$GITHUB_STEP_SUMMARY"

Code Explained

>> "$GITHUB_ENV" — env var for all later steps
>> "$GITHUB_OUTPUT" — needs a step id: to read
$GITHUB_PATH — new tools found by later steps
NAME<<EOF … EOF — multiline value
$GITHUB_STEP_SUMMARY — Markdown on the summary page

Security Check

  • Risk: writing untrusted text (a PR title, a branch name) to $GITHUB_ENV can inject extra lines like LD_PRELOAD=... or NODE_OPTIONS=... that hijack later steps.
  • Fix: validate or strip newlines first, and use a random delimiter (EOF_$RANDOM) for multiline values.

File Commands

FileLine format
$GITHUB_ENVNAME=value
$GITHUB_OUTPUTname=value
$GITHUB_PATH/abs/dir (one per line)
$GITHUB_STEP_SUMMARYMarkdown
$GITHUB_STATEname=value for an action's post: step

⚠ Common Mistakes

  • Reading a $GITHUB_ENV value in the same step: it's only set from the next one
  • Forgetting the step id:, so steps.x.outputs is empty
  • PowerShell writes UTF-16 by default: use "X=1" | Out-File -Append -Encoding utf8 $env:GITHUB_ENV

✓ Tips & Best Practices

  • Quote the file path: >> "$GITHUB_OUTPUT"
  • Prefer outputs over env for values other steps or jobs depend on: they're explicit
  • Step summaries accept tables and Mermaid; great for test or coverage reports

Quick Summary

  • env: — workflow / job / step variables
  • $GITHUB_ENV — set env for later steps
  • $GITHUB_OUTPUT — step outputs by id
  • $GITHUB_PATH / $GITHUB_STEP_SUMMARY — PATH, report
