Assigning Issues to Copilot

The Copilot coding agent works on GitHub by itself: assign an issue to Copilot (or ask from chat or the Agents panel) and it spins up an Actions-powered environment, explores the repo, writes code, runs tests and opens a draft pull request. You review it like any PR and leave comments mentioning @copilot to request changes. Its environment is customized with copilot-setup-steps.yml.

Agent Facts

  • Runs on Actions minutes plus premium requests
  • Pushes only to its own copilot/ branches
  • A firewall limits internet access; allowlist hosts if needed

Who Can Do This

  • Role: Write (assign) · Admin (enable, configure)
  • Plan: Pro / Pro+ / Business / Enterprise
  • Repos: public and private

Prepare the Agent's Environment

# .github/workflows/copilot-setup-steps.yml
name: Copilot Setup Steps
on: workflow_dispatch          # lets you test it by hand
jobs:
  copilot-setup-steps:         # job name must match exactly
    runs-on: ubuntu-latest
    permissions: { contents: read }
    steps:
      - uses: actions/checkout@v6
      - uses: actions/setup-node@v6
        with: { node-version: 22, cache: npm }
      - run: npm ci
      - run: npx prisma generate

Code Explained

file + job name — required exactly as shown
install deps up front so the agent can build and test
workflow_dispatch — run it yourself to debug
runs before the agent starts each task

⚠ Common Mistakes

  • Vague issues ("improve performance"): write acceptance criteria and where to look
  • Merging agent PRs without running them: review like a junior dev's PR
  • No setup steps for repos with native deps: the agent can't build or test

✓ Tips & Best Practices

  • Best fits: well-scoped bugs, tests, docs, small features
  • Put build/test commands in copilot-instructions.md (Sheet 83)
  • Batch review comments, then mention @copilot once
