Dev Containers

.devcontainer/devcontainer.json · image / Dockerfile · features · postCreateCommand · customizations.vscode · secrets · prebuilds

Defining the Environment

A dev container describes the environment as code in .devcontainer/devcontainer.json: a base image or Dockerfile, features (installable tools like Node, Python, Docker-in-Docker), ports to forward, lifecycle commands and editor settings. Codespaces, VS Code's Dev Containers extension and other tools all read the same file, so everyone gets the same setup.

Facts

  • No file? Codespaces uses a large default universal image
  • Multiple configs: .devcontainer/<name>/devcontainer.json
  • Rebuild after edits: Codespaces: Rebuild Container

Who Can Do This

  • Role: Write (commit config)
  • Plan: Free
  • Repos: public and private

A Node + Postgres Dev Container

// .devcontainer/devcontainer.json
{
  "name": "shop",
  "image": "mcr.microsoft.com/devcontainers/javascript-node:22",
  "features": {
    "ghcr.io/devcontainers/features/github-cli:1": {},
    "ghcr.io/devcontainers/features/docker-in-docker:2": {}
  },
  "forwardPorts": [3000],
  "postCreateCommand": "npm ci",
  "customizations": {
    "vscode": {
      "extensions": ["dbaeumer.vscode-eslint", "esbenp.prettier-vscode"]
    }
  },
  "secrets": { "STRIPE_KEY": { "description": "Test-mode key" } },
  "hostRequirements": { "cpus": 4 }
}

Code Explained

image — base; or build.dockerfile for your own
features — add tools by ID + version
postCreateCommand — runs once after creation
customizations.vscode.extensions — preinstalled
secrets — prompts users for Codespaces secrets

Lifecycle Commands

KeyRuns
onCreateCommandfirst, during creation (prebuild-friendly)
updateContentCommandafter content updates
postCreateCommandafter creation, user context
postStartCommandevery start
postAttachCommandevery editor attach

Need Several Containers?

KeyUse
dockerComposeFilepoint to docker-compose.yml
servicewhich service VS Code attaches to
runServicesservices to start
workspaceFolderpath inside the container

⚠ Common Mistakes

  • Heavy installs in postStartCommand: every start is slow
  • Hard-coding secrets in devcontainer.json: use Codespaces secrets
  • Pinning latest images: environments drift between teammates

✓ Tips & Best Practices

  • Move slow setup into onCreateCommand so prebuilds cache it
  • Browse features at containers.dev/features
  • The same file works locally with Docker + VS Code Dev Containers

Quick Summary

  • devcontainer.json — environment as code
  • image + features — tools
  • lifecycle commands — setup steps
  • same file — Codespaces and local
