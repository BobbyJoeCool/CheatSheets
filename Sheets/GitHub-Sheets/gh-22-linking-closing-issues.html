Linking & Closing Issues

Fixes #12 / Closes / Resolves · cross-repo owner/repo#12 · Development sidebar · autolink references · default-branch rule

Connecting Issues, PRs and Commits

Writing #42 anywhere links to issue or PR 42 and adds a cross-reference on it. A closing keyword in a PR description (or a commit message) such as Fixes #42 links the issue and closes it automatically when the PR merges into the default branch. The Development sidebar shows and edits these links. Autolink references turn external IDs like JIRA-123 into links.

Closing Rules

  • Only PRs targeting the default branch close issues
  • One keyword per issue: Fixes #1, fixes #2
  • Keywords in PR comments don't close; description or commits do

Who Can Do This

  • Role: Write (merge to close) · Admin (autolinks)
  • Plan: Free (autolinks on private: Pro/Team)
  • Repos: public and private

Link and Close

  1. In the PR body: Fixes #42 (or Closes owner/repo#42)
  2. Check the Development sidebar shows the issue
  3. Or link manually: sidebar → Development → ⚙
  4. Merge to the default branch; the issue closes as completed
  5. Set up Settings → Autolink references for JIRA-<num>

⚠ Common Mistakes

  • Using Fixes #42 in a PR to develop: nothing closes until it reaches the default branch
  • Writing Fixes #1, #2: only #1 closes; repeat the keyword
  • Using "Fixed in #42" in a comment and expecting a close

✓ Tips & Best Practices

  • Issue → Create a branch links branch and issue from the start
  • Use Refs #42 when you want the link without closing
  • Autolinks with <num> placeholder work in commit messages too

Quick Summary
