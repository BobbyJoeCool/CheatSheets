Merge Methods & Auto-Merge

merge commit · squash · rebase · allowed methods setting · auto-merge · auto-delete head branches · commit message defaults

How Changes Land

GitHub offers three merge buttons: Create a merge commit keeps every commit plus a merge commit, Squash and merge turns the PR into one commit, and Rebase and merge replays commits onto the base without a merge commit. Admins choose which are allowed. Auto-merge merges a PR the moment all requirements pass.

Merge Facts

  • Squash commit message defaults can be set to PR title + description
  • Auto-merge must be enabled in Settings and needs branch rules to wait on
  • Auto-delete head branches cleans up after merging

Who Can Do This

  • Role: Write (merge, enable auto-merge) · Admin (settings)
  • Plan: Free
  • Repos: public and private

Set Merge Options

  1. Settings → General → Pull Requests
  2. Allow only Squash merging (or what your team prefers)
  3. Default message: Pull request title and description
  4. Tick Allow auto-merge and Automatically delete head branches
  5. On a PR: Enable auto-merge → pick method → confirm

Automate It

Enable auto-merge (GraphQL)
mutation { enablePullRequestAutoMerge(input: {
  pullRequestId: "PR_kwDOAB12", mergeMethod: SQUASH }) {
  pullRequest { autoMergeRequest { enabledAt } } } }

⚠ Common Mistakes

  • Squash-merging a long-lived branch, then merging it again later: conflicts everywhere
  • Relying on auto-merge without required checks: it merges immediately
  • Rebase-merging and expecting the PR's commit SHAs on main: they change

✓ Tips & Best Practices

  • With squash, the PR title becomes the commit subject; make titles good
  • Pair auto-merge with Dependabot for patch updates that pass CI
  • A merge queue (Sheet 28) is the next step for busy branches

Quick Summary
