Sheet 67

Actions: Composite Actions

action.yml · runs.using: composite · inputs / outputs · shell: · $GITHUB_ACTION_PATH

Bundle Steps Into One

A composite action packages several steps into a single uses:. It lives in a folder with an action.yml that declares inputs, outputs and runs.using: composite. Use it to remove copy-pasted setup (checkout + toolchain + cache + install) across workflows. It runs inside the caller's job, on the caller's runner.

Rules

  • Every run: step must set shell:
  • Inputs are read with inputs.name (all strings)
  • Can call other actions with uses:, including composites
  • No if: at the action level; steps can have if:

action.yml for Project Setup

# .github/actions/setup/action.yml
name: Project setup
description: Node + cache + install
inputs:
  node-version: { description: Node version, default: "22" }
outputs:
  cache-hit:
    value: ${{ steps.node.outputs.cache-hit }}
runs:
  using: composite
  steps:
    - id: node
      uses: actions/setup-node@v6
      with: { node-version: "${{ inputs.node-version }}", cache: npm }
    - run: npm ci
      shell: bash
    - run: $GITHUB_ACTION_PATH/scripts/verify.sh
      shell: bash

# In a workflow (after actions/checkout):
#   - uses: ./.github/actions/setup
#     with: { node-version: "24" }

Code Explained

inputs.<name>.default — used when the caller omits it
outputs.<name>.value — map from an inner step
shell: bash — required on each run:
$GITHUB_ACTION_PATH — folder of this action's files

In the Logs

  • Required property is missing: shell — a composite run: step has no shell:
  • The whole action appears as one step in the log; expand it to see inner steps

⚠ Common Mistakes

  • Using a local composite before actions/checkout: the folder doesn't exist yet
  • Reading secrets inside: composites can't access secrets; pass them as inputs
  • Comparing boolean-looking inputs to true: inputs are strings, use == 'true'

✓ Tips & Best Practices

  • Start with composites for shared setup; reach for reusable workflows when you need jobs
  • Put helper scripts beside action.yml and call them via $GITHUB_ACTION_PATH
  • Version shared composites with tags (v1) like any other action

Quick Summary

  • runs.using: composite — steps as one action
  • shell: — mandatory on run: steps
  • inputs/outputs — strings; map with value:
  • local or repo — ./path or org/repo/path@v1
