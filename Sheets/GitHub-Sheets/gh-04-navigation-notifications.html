Moving Fast and Staying Informed

GitHub is very keyboard-friendly: the command palette (Ctrl+K / ⌘K) jumps to any repo, file or command, t opens the file finder, and . opens the current repo in the browser editor. Notifications arrive when you're mentioned, assigned, review-requested or watching a repo; the inbox at github.com/notifications filters them by reason.

Notification Facts

  • Participating = you were involved; Watching = everything in the repo
  • Watch → Custom picks events: issues, PRs, releases, discussions
  • Email routing per org: Settings → Notifications → Custom routing

Who Can Do This

  • Role: anyone signed in
  • Plan: Free
  • Repos: public and private

Tame Your Inbox

  1. Repo → Watch → Participating and @mentions for busy repos
  2. Use Custom → Releases for libraries you depend on
  3. In the inbox, filter reason:review-requested or reason:mention
  4. Done (e) clears; Save (s) keeps for later
  5. Unsubscribe from a thread you don't care about anymore
  6. Settings → Notifications: pick web vs email per type

⚠ Common Mistakes

  • Watching All Activity on big repos: the inbox becomes useless
  • Sharing branch URLs for code lines: they drift; press y for a permalink
  • Ignoring team mentions: you get them for every team you're on

✓ Tips & Best Practices

  • Save custom inbox filters (e.g. reason:review-requested is:unread)
  • Use the GitHub Mobile app to triage notifications in spare minutes
  • Ctrl/⌘ K then > switches to command mode (e.g. change theme)
