Sheet 66

Actions: Reusable Workflows

on: workflow_call · inputs / secrets / outputs · secrets: inherit · 10 levels / 50 calls

Whole Workflows as Building Blocks

A reusable workflow is a normal workflow file with on: workflow_call. Another workflow calls it as a job with uses: pointing at the file and a ref. It can declare typed inputs, secrets and outputs, and its jobs run on their own runners. Nesting goes up to 10 levels, with up to 50 workflow calls per run.

Rules

  • Called as a whole job: jobs.<id>.uses:, no runs-on or steps
  • Caller's env doesn't pass in; use inputs
  • Same-repo: ./.github/workflows/x.yml
  • Private callees need Settings → Actions → Access

Caller and Callee

# .github/workflows/deploy-reusable.yml  (callee)
on:
  workflow_call:
    inputs:
      environment: { type: string, required: true }
    secrets:
      DEPLOY_TOKEN: { required: true }
    outputs:
      url: { value: "${{ jobs.deploy.outputs.url }}" }
jobs:
  deploy:
    runs-on: ubuntu-latest
    environment: ${{ inputs.environment }}
    outputs: { url: "${{ steps.d.outputs.url }}" }
    steps:
      - id: d
        run: echo "url=https://$ENV.example.com" >> "$GITHUB_OUTPUT"
        env: { ENV: "${{ inputs.environment }}" }

# .github/workflows/ci.yml  (caller)
jobs:
  prod:
    uses: my-org/platform/.github/workflows/deploy-reusable.yml@v2
    with: { environment: production }
    secrets: inherit                 # or pass each secret by name

Code Explained

workflow_call.inputs — typed: string, number, boolean
secrets: — declared, then passed or inherited
outputs.value — maps from a callee job's outputs
uses: org/repo/.github/workflows/x.yml@ref — call it
job.workflow_ref — callee can tell which file it is

Security Check

  • Risk: secrets: inherit hands every caller secret to the called workflow, including ones it doesn't need.
  • Fix: pass secrets explicitly by name for workflows outside your control, and pin cross-repo calls to a tag or SHA.

In the Logs

  • error parsing called workflow ... workflow was not found — wrong path or ref, or the repo isn't shared
  • Invalid secret, DEPLOY_TOKEN is not defined in the referenced workflow — declare it under workflow_call.secrets

Reusable Workflow vs Composite Action

FeatureReusable wf · Composite
Unitjobs · steps
Own runnersyes · no (runs in caller job)
Secretsdeclared/inherit · via inputs
environment: / matrixyes · no

⚠ Common Mistakes

  • Adding runs-on or steps to a uses: job: only with, secrets, needs, if, strategy and a few others are allowed
  • Expecting the callee to inherit the caller's env:
  • Calling @main across repos: any push changes your pipeline

✓ Tips & Best Practices

  • Keep org-standard pipelines in one repo and version them with tags
  • Callers can use a strategy.matrix to call one workflow per environment
  • The callee's permissions can only reduce, never exceed, the caller's

Quick Summary

  • on: workflow_call — make it reusable
  • jobs.x.uses: path@ref — call it
  • inputs · secrets · outputs — the interface
  • 10 levels · 50 calls — nesting limits
