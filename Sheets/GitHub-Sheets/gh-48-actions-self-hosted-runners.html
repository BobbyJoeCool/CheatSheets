Actions: Self-Hosted Runners

config.sh · labels · runs-on: [self-hosted] · runner groups · --ephemeral · ARC

Your Own Machines

A self-hosted runner is the open-source runner app installed on a machine you control: a server, a VM, a Mac mini, or a pod in Kubernetes. It polls GitHub over HTTPS (outbound only), picks up jobs whose runs-on labels it has, and runs them. Use it for special hardware (GPUs), private network access, or big caches. Minutes on your own runners aren't charged against your included minutes.

Runner Facts

  • Default labels: self-hosted, OS (linux, windows, macOS), arch (x64, ARM64)
  • Jobs need all listed labels to match
  • Not wiped between jobs unless you make it ephemeral
  • Runners not seen for 14 days are removed automatically

Register and Target a Runner

# On the machine (token: Settings → Actions → Runners → New)
mkdir actions-runner && cd actions-runner
curl -o runner.tar.gz -L <download-url-from-settings>
tar xzf runner.tar.gz
./config.sh --url https://github.com/OWNER/REPO \
            --token <REG_TOKEN> \
            --labels gpu,cuda12 \
            --ephemeral              # one job, then deregister
sudo ./svc.sh install && sudo ./svc.sh start   # run as a service

# In the workflow:
#   runs-on: [self-hosted, linux, gpu]
#   runs-on: { group: build-farm, labels: [linux] }

Code Explained

config.sh --url — repo, org or enterprise URL decides the scope
--labels — custom labels added to the defaults
--ephemeral — clean runner per job; pair with autoscaling
svc.sh — install as a systemd/launchd service
group: — runner groups limit which repos can use them

Security Check

  • Risk: on a public repo, any fork PR can run code on your runner and persist malware between jobs.
  • Fix: only use self-hosted runners for private repos (or require approval for fork PRs), run them --ephemeral, and isolate them from production networks.

In the Logs

  • Waiting for a runner to pick up this job... — no online runner has every label; check Settings → Runners for Idle status
  • Runner listener exited with error code on the host — expired token or network block to github.com

⚠ Common Mistakes

  • Labels that don't match exactly: jobs queue forever instead of failing
  • Long-lived runners leaking state (files, Docker images, credentials) into the next job
  • Running as root or with prod credentials on the box: one bad workflow owns everything

✓ Tips & Best Practices

  • Use Actions Runner Controller (ARC) to autoscale ephemeral runners on Kubernetes
  • Create registration tokens via the API for automation; they expire after 1 hour
  • Restrict org runners to selected repos with runner groups

Quick Summary

  • ./config.sh — register with URL + token
  • runs-on: [self-hosted, label] — target it
  • --ephemeral — one job per runner
  • never on public repos without isolation
