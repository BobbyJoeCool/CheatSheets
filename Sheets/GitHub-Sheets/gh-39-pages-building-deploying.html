Building & Deploying Pages

Jekyll default · .nojekyll · _config.yml · static site generators via Actions · upload-pages-artifact / deploy-pages · 404.html · limits

Getting Your Site Built

With a branch source, GitHub builds the folder with Jekyll automatically (add .nojekyll to serve files as-is). With the GitHub Actions source, your own workflow builds the site with any generator (Vite, Astro, Hugo, Docusaurus, MkDocs), uploads it as a Pages artifact and deploys it. Actions is the recommended path for anything beyond plain Jekyll.

Build Facts

  • Settings → Pages → Source: GitHub Actions to use a workflow
  • 404.html at the site root becomes the not-found page
  • Project sites live under /REPO/: set your generator's base path

Who Can Do This

  • Role: Write (push, run workflows) · Admin (choose source)
  • Plan: Free for public
  • Repos: public (private with paid plans)

Deploy a Vite Site With Actions

# .github/workflows/pages.yml
on: { push: { branches: [main] }, workflow_dispatch: }
permissions: { contents: read, pages: write, id-token: write }
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6
      - uses: actions/setup-node@v6
        with: { node-version: 22, cache: npm }
      - run: npm ci && npm run build -- --base=/my-repo/
      - uses: actions/upload-pages-artifact@v4
        with: { path: dist }
  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment: { name: github-pages, url: "${{ steps.d.outputs.page_url }}" }
    steps:
      - id: d
        uses: actions/deploy-pages@v4

Code Explained

pages: write + id-token: write — required to deploy
--base=/my-repo/ — project sites live in a subfolder
upload-pages-artifact — packages dist for Pages
environment: github-pages — shows the URL on the run

Generators and Output Folders

ToolBuild → folder
Vitenpm run build → dist
Astronpm run build → dist
Hugohugo → public
MkDocsmkdocs build → site

Troubleshooting

SymptomFix

⚠ Common Mistakes

  • Forgetting the base path on project sites: blank page with 404s for assets
  • Committing build output to main for a branch source when Actions would do it cleanly
  • Two workflows deploying to Pages at once

✓ Tips & Best Practices

  • Add workflow_dispatch so you can redeploy without a commit
  • Use actions/configure-pages to get the right base URL automatically
  • Keep the Actions-side details in Sheet 65

Quick Summary

  • branch source — Jekyll by default
  • Actions source — any generator
  • upload-pages-artifact → deploy-pages
  • base path — /REPO/ for project sites
