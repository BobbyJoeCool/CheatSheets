Sheet 09

CRUD: Delete & Batch Operations

delete · deleteMany · onDelete: Cascade · P2003 · soft delete · $transaction

Removing Data

delete() removes one record by unique where, returns it, and throws P2025 if it's missing. deleteMany() removes every match in one SQL statement and returns { count }. Related rows follow the relation's onDelete action: Cascade removes them, Restrict blocks the delete with P2003, SetNull detaches them.

Notes

  • deleteMany() with no where empties the table
  • Cascades run in the DB, not in Prisma
  • Deleted record is returned — log it first
  • Soft delete = update a deletedAt field

Delete Examples

await prisma.post.delete({ where: { id: 7 } });      // deleted Post, or P2025

await prisma.post.deleteMany({
  where: { published: false, createdAt: { lt: new Date("2025-01-01") } },
});                                                  // { count: 12 }

await prisma.user.delete({ where: { id: 1 } });      // Profile cascades

// Restrict FK → P2003: remove children first, atomically
await prisma.$transaction([
  prisma.post.deleteMany({ where: { authorId: 2 } }),
  prisma.user.delete({ where: { id: 2 } }),
]);

// soft delete instead of removing
await prisma.user.update({ where: { id: 3 }, data: { deletedAt: new Date() } });
await prisma.user.findMany({ where: { deletedAt: null } });   // active only

await prisma.auditLog.deleteMany();                  // ⚠ every row

Code Explained

delete — one row by unique key
deleteMany + filters — one SQL DELETE
onDelete: Cascade — DB removes children
$transaction([...]) — both or neither
deletedAt — keep row, hide it
deletedAt: null — filter active rows
no where — truncates the data

⚠ Common Mistakes

  • deleteMany() with an empty where — wipes the table
  • Deleting a parent under Restrict — fails with P2003
  • Loop of delete() for bulk removal — use deleteMany
  • Soft-deleting but forgetting deletedAt: null filters

✓ Tips & Best Practices

  • Guard bulk deletes: refuse an empty where in services
  • Return the deleted record to support an "undo" toast
  • Index deletedAt when most queries filter on it
  • Centralize soft-delete filters with $extends (Sheet 21)

Quick Summary

  • delete — one by unique key, P2025
  • deleteMany — bulk, { count }
  • onDelete — Cascade · Restrict · SetNull
  • soft delete — deletedAt timestamp
