Sheet 08

CRUD: Update & Upsert

update · updateMany · updateManyAndReturn · increment · upsert · nested update

Modifying Records

update() changes one record by unique where and throws P2025 if none matches. updateMany() changes every match and returns { count }. Atomic operations (increment, multiply…) run in SQL, so concurrent writes never lose updates. upsert() updates if the key exists, else creates.

Notes

  • Omitted fields stay unchanged
  • undefined = skip · null = clear
  • @updatedAt refreshes automatically
  • Upsert uses native ON CONFLICT when possible

Update Examples

await prisma.user.update({
  where: { id: 1 },
  data: { name: "Ada Lovelace", age: null },  // age cleared
});
await prisma.post.update({
  where: { id: 7 },
  data: {
    views: { increment: 1 },                  // views = views + 1
    tags:  { push: "featured" },              // Postgres list append
  },
});
await prisma.post.updateMany({
  where: { authorId: 1, published: false },
  data: { published: true },
});                                           // { count: 3 }
await prisma.user.upsert({
  where:  { email: "ada@example.com" },
  update: { lastLogin: new Date() },
  create: { email: "ada@example.com", lastLogin: new Date() },
});

Generated SQL

UPDATE "Post" SET "views" = "views" + $1
WHERE "id" = $2 RETURNING "id", "views", …;
-- upsert (native)
INSERT INTO "User" ("email", "name") VALUES ($1, $2)
ON CONFLICT ("email") DO UPDATE SET "name" = $3
RETURNING "id", …;

Code Explained

where — unique field required
null — set column to NULL
increment — atomic counter
multiply/divide/set — atomic too
push — append to String[]
updateMany — bulk, { count }
upsert — where + update + create

Prefer / Avoid

  • views: post.views + 1 → views: { increment: 1 }
  • update in a loop → updateMany
  • find, then create or update → upsert

Database Differences

  • Native ON CONFLICT upsert only for one unique where field; otherwise read-then-write
  • push: scalar lists, PostgreSQL / CockroachDB only
  • updateManyAndReturn: PostgreSQL, CockroachDB, SQLite

Prisma Versions

  • 4.6 native database upserts
  • 6.2 updateManyAndReturn

Atomic Operations

⚠ Common Mistakes

  • views: post.views + 1 — races; use increment
  • update with a non-unique where — use updateMany
  • Assuming updateMany throws on no match — check count
  • Upsert where on a non-unique field — not allowed

✓ Tips & Best Practices

  • Catch P2025 from update → HTTP 404
  • Optimistic lock: where: { id, version } + increment
  • Nested: profile: { update: { bio } }
  • Keep upsert create and update consistent

Quick Summary

  • update — one by unique key
  • updateMany — bulk, { count }
  • increment — race-free counter
  • upsert — create or update
