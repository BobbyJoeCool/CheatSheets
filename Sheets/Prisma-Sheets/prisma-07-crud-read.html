Sheet 07

CRUD: Read Operations

findUnique · findFirst · findMany · select · include · omit · orderBy · skip/take

Querying Records

findUnique fetches one record by an @id/@unique field. findFirst returns the first match of any filter. findMany returns an array — empty, never null. All accept select, include, or omit, and the result type is inferred from what you ask for.

Notes

  • …OrThrow variants throw P2025
  • select + include can't be siblings
  • No orderBy = unspecified order
  • findUnique calls are auto-batched

Read Examples

await prisma.user.findUnique({ where: { email: "ada@example.com" } }); // User | null
await prisma.user.findUniqueOrThrow({ where: { id: 1 } });            // or P2025

await prisma.post.findFirst({
  where: { published: true },
  orderBy: { createdAt: "desc" },                 // newest published
});

await prisma.post.findMany({
  where: { authorId: 1, title: { contains: "orm", mode: "insensitive" } },
  select: { id: true, title: true, author: { select: { name: true } } },
  orderBy: [{ createdAt: "desc" }, { id: "desc" }],
  skip: 20,
  take: 10,                                       // page 3
});

await prisma.user.findMany({ omit: { password: true } });
await prisma.user.findMany({ include: { posts: true } });
await prisma.post.findMany({ distinct: ["authorId"] });
await prisma.post.count({ where: { published: true } });   // 42

Code Explained

findUnique — by unique key
orderBy — makes findFirst deterministic
mode: 'insensitive' — Postgres/Mongo
nested select — shaped payload
id tie-breaker — stable pages
skip/take — offset paging
omit — drop secrets
distinct — unique by field

⚠ Common Mistakes

  • findUnique on a non-unique field — use findFirst
  • if (!rows) on findMany — [] is truthy; check .length
  • Huge skip values — DB still scans; use a cursor
  • select and include at the same level — error

✓ Tips & Best Practices

  • Prefer select in APIs — small payloads, no leaks
  • Add id as a final orderBy when paginating
  • Map P2025 from …OrThrow to HTTP 404
  • count() beats findMany().length

Quick Summary

  • findUnique — one by unique key
  • findFirst — first match
  • findMany — list, never null
  • select · include · omit — shape
