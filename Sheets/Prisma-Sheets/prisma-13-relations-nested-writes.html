Relations: Nested Writes

create · connect · connectOrCreate · disconnect · set · update · upsert · delete

Writing Through Relations

Nested writes change related records inside a parent create or update. Prisma wraps the whole operation in a transaction, so the parent and all nested changes succeed or fail together. connect links an existing record by unique key; create makes a new one; connectOrCreate does whichever applies.

Notes

  • connect throws P2025 if the target is missing
  • disconnect sets the FK to NULL (optional FK)
  • set replaces all links (to-many)
  • createMany nested: 1-n only, no deeper nesting

Nested Write Examples

await prisma.post.create({
  data: {
    title: "Hello",
    author: { connect: { email: "ada@example.com" } },        // existing user
    category: { connectOrCreate: {
      where: { slug: "orm" }, create: { slug: "orm", name: "ORM" } } },
  },
});
await prisma.user.update({
  where: { id: 1 },
  data: {
    profile: { upsert: { create: { bio: "Hi" }, update: { bio: "Hi" } } },
    posts: {
      update: { where: { id: 7 }, data: { published: true } },
      updateMany: { where: { published: false }, data: { views: 0 } },
      deleteMany: { createdAt: { lt: new Date("2024-01-01") } },
      disconnect: [{ id: 9 }],                                 // authorId → NULL
    },
  },
});

Code Explained

connect — link by unique key
connectOrCreate — link or create
upsert — 1-1 create-or-update
update — change one child
updateMany/deleteMany — bulk on children
disconnect — unlink, keep row

⚠ Common Mistakes

  • Mixing authorId and author: {…} in one data
  • disconnect on a required FK — fails
  • Concurrent connectOrCreate — can race to P2002
  • set when you meant connect — drops links

✓ Tips & Best Practices

  • Prefer nested writes to manual transactions
  • connect by natural key (email, slug)
  • Retry connectOrCreate on P2002
  • include the result to confirm changes

Quick Summary

  • create / connect — new or existing child
  • connectOrCreate — whichever applies
  • disconnect / set — unlink / replace
  • update / upsert / delete — modify children
  • nested writes — always transactional
