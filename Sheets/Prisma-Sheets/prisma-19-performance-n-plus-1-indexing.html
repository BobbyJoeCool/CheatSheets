Performance: N+1 & Indexing

N+1 · include · in · fluent API batching · relationLoadStrategy · @@index

The N+1 Problem

N+1 happens when you run 1 query for a list and then 1 more per item to load related data — 101 queries for 100 users. Fix it by loading relations in the same call (include/select), by batching IDs with in, or by relying on Prisma's dataloader, which batches findUnique calls made in the same tick.

Notes

  • Spot N+1 with log: ['query']
  • findUnique in the same tick → 1 query
  • join strategy: preview relationJoins
  • Indexes fix slow queries, not query count

N+1 and Fixes

// ✖ N+1: 1 + N queries
const users = await prisma.user.findMany();
for (const u of users) {
  u.posts = await prisma.post.findMany({ where: { authorId: u.id } });
}

// ✔ include: relations loaded with the list
await prisma.user.findMany({ include: { posts: true } });

// ✔ manual batch: 2 queries total
const ids = users.map((u) => u.id);
const posts = await prisma.post.findMany({ where: { authorId: { in: ids } } });

// ✔ dataloader: same-tick findUnique calls are batched (GraphQL resolvers)
await Promise.all(ids.map((id) => prisma.user.findUnique({ where: { id } }).posts()));

// ✔ single SQL query with LATERAL JOINs (Postgres/MySQL)
await prisma.user.findMany({ relationLoadStrategy: "join", include: { posts: true } });

Code Explained

loop query — one round-trip per user
include — Prisma loads posts in bulk
in: ids — one query for all children
fluent .posts() — batched by dataloader
relationLoadStrategy: 'join' — 1 query
default query strategy — 1 query/level

⚠ Common Mistakes

  • await inside for…of over query results — classic N+1
  • include everything "just in case" — slow, heavy
  • Adding indexes without checking the query plan
  • Fixing N+1 with caching instead of batching

✓ Tips & Best Practices

  • Log query counts per request in development
  • Use EXPLAIN ANALYZE via $queryRaw on slow queries
  • Benchmark join vs query strategy on your data
  • Index FK columns used by include and filters

Quick Summary

  • N+1 — 1 list query + N child queries
  • include/select — load relations together
  • in: ids — manual batch
  • @@index — faster filters and sorts
