Unit vs Integration Tests

Unit tests replace the Prisma client with a deep mock (vitest-mock-extended or jest-mock-extended) so business logic runs without a database. Integration tests use a real, separate test database, apply migrations before the run, and clean tables between tests to stay isolated.

Notes

  • Never point tests at your dev DB
  • Mocks can't catch SQL or constraint bugs
  • Run test files serially against one DB
  • Or one DB/schema per worker

Mocked Unit Test (Vitest)

// src/lib/__mocks__/prisma.ts — used automatically by vi.mock()
import { beforeEach } from "vitest";
import { mockDeep, mockReset } from "vitest-mock-extended";
import type { PrismaClient } from "../../../generated/prisma/client";
export const prisma = mockDeep<PrismaClient>();
beforeEach(() => mockReset(prisma));

// src/user.service.test.ts
import { vi, it, expect } from "vitest";
import { prisma } from "./lib/__mocks__/prisma";       // typed mock
import { createUser } from "./user.service";
vi.mock("./lib/prisma");                               // swap the singleton
it("creates a user", async () => {
  prisma.user.create.mockResolvedValue({ id: 1, email: "a@b.c", name: null });
  await expect(createUser("a@b.c")).resolves.toMatchObject({ id: 1 });
  expect(prisma.user.create).toHaveBeenCalledWith({ data: { email: "a@b.c" } });
});

Code Explained

mockDeep — every delegate/method mocked
__mocks__/ — auto-used by vi.mock
import the mock file — typed mock API
mockReset — clean state per test
mockResolvedValue — fake DB result
toHaveBeenCalledWith — assert the query

Integration Setup

// .env.test → DATABASE_URL=".../app_test"
// globalSetup.ts
import { execSync } from "node:child_process";
export default () =>
  execSync("npx prisma migrate reset --force", { stdio: "inherit" });

// per test: children before parents
afterEach(async () => {
  await prisma.$transaction([
    prisma.post.deleteMany(),
    prisma.user.deleteMany(),
  ]);
});

// factory
const makeUser = (o: Partial<Prisma.UserCreateInput> = {}) =>
  prisma.user.create({ data: { email: `u${Date.now()}@t.io`, ...o } });

⚠ Common Mistakes

  • Mock tests only — constraint and SQL bugs reach prod
  • Deleting parents before children — FK error P2003
  • Parallel test files sharing one DB — flaky results
  • migrate reset without --force in CI — prompts and hangs

✓ Tips & Best Practices

  • Load .env.test with dotenv before Prisma is imported
  • Use factories with unique emails to avoid P2002
  • Keep the mock module path identical to the real import
  • Run integration tests in CI against a disposable DB

Quick Summary

  • mockDeep<PrismaClient>() — unit tests
  • test DB + migrate reset --force — integration
  • deleteMany / TRUNCATE — isolation
  • factories — quick valid records
