Self-Referential & Complex Relations

self-relation · manager/reports · parentId tree · followers m-n · WITH RECURSIVE

Models That Point to Themselves

A self-relation links a model to itself: an employee's manager, a category's parent, or users following users. Because both ends are the same model, each pair of fields needs a shared relation name. Prisma loads a fixed number of levels with nested include; for unknown depth, use a recursive CTE with $queryRaw.

Notes

  • Self 1-n: FK + named @relation pair
  • Self m-n: two list fields, one name
  • SQL Server: self-relations need NoAction
  • Guard against cycles in app logic

Schema

model Employee {
  id        Int        @id @default(autoincrement())
  managerId Int?
  manager   Employee?  @relation("Reports", fields: [managerId], references: [id])
  reports   Employee[] @relation("Reports")
}
model Category {
  id       Int        @id @default(autoincrement())
  parentId Int?
  parent   Category?  @relation("Tree", fields: [parentId], references: [id], onDelete: Cascade)
  children Category[] @relation("Tree")
  @@index([parentId])
}
model User {
  id        Int    @id @default(autoincrement())
  followers User[] @relation("Follows")
  following User[] @relation("Follows")
}

Code Explained

"Reports" — names the field pair
managerId Int? — the root has no manager
reports Employee[] — virtual list
onDelete: Cascade — deletes the subtree
@@index([parentId]) — fast child lookups
followers/following — self m-n

Queries

await prisma.employee.findUnique({
  where: { id: 1 },
  include: { manager: true, reports: { include: { reports: true } } },
});                                       // 2 levels down
await prisma.user.update({                // follow
  where: { id: 1 },
  data: { following: { connect: { id: 2 } } },
});
// unknown depth: recursive CTE
await prisma.$queryRaw`
  WITH RECURSIVE tree AS (
    SELECT id, "parentId", 0 AS depth FROM "Category" WHERE id = ${rootId}
    UNION ALL
    SELECT c.id, c."parentId", t.depth + 1
    FROM "Category" c JOIN tree t ON c."parentId" = t.id
  ) SELECT * FROM tree`;

⚠ Common Mistakes

  • Unnamed self-relations — ambiguity error in the schema
  • Cascade on deep trees — deletes whole subtrees
  • Unbounded recursion on cyclic data — add a depth limit
  • Deep nested include — exponential payload growth

✓ Tips & Best Practices

  • Index parentId / managerId for child lookups
  • Use materialized paths for read-heavy category trees
  • Use an explicit Follow model to store createdAt
  • Prevent cycles before setting a new parent

Quick Summary

  • @relation("Name") — pair self-relation fields
  • parent? / children[] — tree
  • followers / following — self m-n
  • WITH RECURSIVE — unlimited depth
