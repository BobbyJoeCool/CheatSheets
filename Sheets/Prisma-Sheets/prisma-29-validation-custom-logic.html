Validating Before You Write

Prisma's types check shape at compile time, not content at runtime: an empty string or a negative price still reaches the database. Validate untrusted input with a schema library such as Zod at the API boundary, enforce business rules in services, and keep database constraints (@unique, FKs, CHECK) as the final safety net.

Notes

  • Validate at the edge: request → DTO → query
  • Pre-save hooks: query extension
  • CHECK constraints via a SQL migration
  • zod-prisma-types can generate schemas

Zod + Extension Hook

import { z } from "zod";

export const ProductInput = z.object({
  name: z.string().trim().min(2).max(120),
  sku: z.string().regex(/^[A-Z0-9-]{4,20}$/),
  price: z.number().positive().multipleOf(0.01),
  stock: z.number().int().min(0).default(0),
});
export type ProductInput = z.infer<typeof ProductInput>;

export async function createProduct(body: unknown) {
  const r = ProductInput.safeParse(body);
  if (!r.success) throw new BadRequestError(z.prettifyError(r.error));
  if (await prisma.product.count({ where: { sku: r.data.sku } }))
    throw new ConflictError("SKU exists");          // business rule
  return prisma.product.create({ data: r.data });
}

export const db = prisma.$extends({ query: { product: {
  async update({ args, query }) {                   // pre-save hook
    args.data = ProductInput.partial().parse(args.data);
    return query(args);
  },
} } });

Code Explained

z.object — runtime schema
.trim().min() — normalize + check
z.infer — TS type from schema
safeParse — no throw; inspect result
prettifyError — readable message (Zod 4)
business rule — service-level check
query extension — hook on every update

CHECK Constraint (migration.sql)

ALTER TABLE "Product"

⚠ Common Mistakes

  • Trusting TS types for request bodies — runtime data is unknown
  • Count-then-create uniqueness checks — race; still catch P2002
  • Validating only in the UI — APIs get called directly
  • Hooking update but not updateMany/upsert

✓ Tips & Best Practices

  • Return field-level errors from error.issues to the client
  • Reuse one Zod schema for create; .partial() for update
  • Normalize input (trim, lowercase emails) in the schema
  • Encode critical invariants as DB constraints too

Quick Summary

  • zod — runtime validation at the edge
  • z.infer — single source for types
  • $extends query — pre-save hooks
  • DB constraints — final safety net
