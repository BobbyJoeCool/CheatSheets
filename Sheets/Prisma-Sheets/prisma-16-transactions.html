Sheet 16

Transactions

$transaction([...]) · interactive tx · isolationLevel · timeout · maxWait · P2034

All-or-Nothing Work

A transaction makes several queries atomic: if any one fails, all are rolled back. Prisma offers the array API — a list of queries run sequentially in one transaction — and the interactive API, a callback that receives a transaction client tx so later queries can depend on earlier results. Throwing inside the callback rolls everything back.

Notes

  • Nested writes are already transactional
  • Promise.all is not a transaction
  • Inside the callback use tx, never prisma
  • Defaults: maxWait 2s · timeout 5s

Array & Interactive Transactions

// array API — independent queries, one transaction
const [post, count] = await prisma.$transaction([
  prisma.post.create({ data: { title: "Hi", authorId: 1 } }),
  prisma.post.count({ where: { authorId: 1 } }),
]);

// interactive API — money transfer
async function transfer(from: number, to: number, amount: number) {
  return prisma.$transaction(async (tx) => {
    const sender = await tx.account.update({
      where: { id: from },
      data: { balance: { decrement: amount } },
    });
    if (sender.balance.lt(0)) throw new Error("Insufficient funds"); // rollback
    return tx.account.update({
      where: { id: to },
      data: { balance: { increment: amount } },
    });
  }, { isolationLevel: "Serializable", maxWait: 5000, timeout: 10000 });
}

Code Explained

array — results returned in order
tx — client bound to the transaction
decrement first — row is locked
.lt(0) — Decimal comparison
throw — rolls back both updates
isolationLevel — e.g. Serializable
maxWait — wait for a connection
timeout — max time the tx may run

⚠ Common Mistakes

  • Using prisma. inside the callback — runs outside the transaction
  • Calling HTTP APIs inside an interactive tx — holds locks and connections
  • Exceeding the 5s default timeout — tx is rolled back with an error
  • Thinking Promise.all([...]) is atomic — it isn't

✓ Tips & Best Practices

  • Keep transactions short: prepare data before, side effects after
  • Retry on P2034 (write conflict/deadlock) with backoff
  • Use atomic increment/decrement to avoid read-then-write races
  • Set defaults via transactionOptions on the client

Quick Summary

  • $transaction([...]) — atomic batch
  • $transaction(async tx => …) — interactive
  • throw — rollback
  • isolationLevel · maxWait · timeout — options
