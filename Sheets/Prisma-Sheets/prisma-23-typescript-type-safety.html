Generated Types

prisma generate emits a type for every model (User), every input (Prisma.UserCreateInput), and helpers to derive result types from a query shape. Query results are inferred automatically; when you need to name a type — for a function parameter or API response — derive it from the same select/include object so it never drifts.

Notes

  • User = scalars only, no relations
  • satisfies keeps literal types for reuse
  • Prisma.validator still works (older style)
  • …GetPayload<T> — not "PayloadOf"

Deriving Types From Queries

import type { User, Prisma } from "../generated/prisma/client";

// reusable query shape + its exact result type
const userWithPosts = {
  include: { posts: { select: { id: true, title: true } } },
} satisfies Prisma.UserDefaultArgs;

type UserWithPosts = Prisma.UserGetPayload<typeof userWithPosts>;
// User & { posts: { id: number; title: string }[] }

export function findAuthor(id: number): Promise<UserWithPosts | null> {
  return prisma.user.findUnique({ where: { id }, ...userWithPosts });
}

// typed inputs for service functions
function search(where: Prisma.PostWhereInput, orderBy?: Prisma.PostOrderByWithRelationInput) {
  return prisma.post.findMany({ where, orderBy });
}

// result type of any delegate call
type Users = Prisma.Result<typeof prisma.user, { select: { email: true } }, "findMany">;

⚠ Common Mistakes

  • Typing results as User when you include relations
  • Hand-writing interfaces that drift from the schema
  • Annotating a shape (: Prisma.UserSelect) — widens to booleans
  • Using any for where — loses filter checking

✓ Tips & Best Practices

  • Co-locate shape + GetPayload type in one module
  • Use satisfies, not type annotations, on shapes
  • Use Unchecked*Input when you have raw FK IDs
  • Run tsc --noEmit in CI after prisma generate

Quick Summary

  • generated types — models, inputs, enums
  • satisfies Prisma.*Args — reusable shape
  • *GetPayload<typeof shape> — result type
  • *WhereInput / *CreateInput — inputs
