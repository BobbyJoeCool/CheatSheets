Raw SQL Queries

$queryRaw · $executeRaw · Prisma.sql · Prisma.join · $queryRawUnsafe · TypedSQL

Escape Hatch to SQL

Use raw SQL when Prisma's API can't express a query: CTEs, window functions, date_trunc buckets, full-text search, or vendor features. $queryRaw returns rows; $executeRaw returns the affected-row count. Written as tagged templates, every ${value} becomes a bound parameter, so input is never spliced into SQL. TypedSQL adds generated types for .sql files.

Notes

  • Results are not validated — type is a cast
  • Use DB column names, not @mapped names
  • bigint → BigInt, numeric → Decimal
  • TypedSQL: preview feature typedSql

Raw Query Examples

import { Prisma } from "../generated/prisma/client";

const email = "ada@example.com";
const users = await prisma.$queryRaw<{ id: number; email: string }[]>`
  SELECT id, email FROM users WHERE email = ${email}`;   // $1 param

const n = await prisma.$executeRaw`
  UPDATE posts SET views = 0 WHERE created_at < ${cutoff}`;  // 37

const ids = [1, 2, 3];
await prisma.$queryRaw`SELECT * FROM users WHERE id IN (${Prisma.join(ids)})`;

const byStatus = status ? Prisma.sql`AND status = ${status}` : Prisma.empty;
await prisma.$queryRaw`SELECT * FROM orders WHERE total > ${min} ${byStatus}`;

const daily = await prisma.$queryRaw`
  SELECT date_trunc('day', created_at) AS day, count(*)::int AS n
  FROM orders GROUP BY 1 ORDER BY 1`;

await prisma.$queryRawUnsafe("SELECT * FROM users WHERE id = $1", id); // positional

Code Explained

$queryRaw<T> — rows cast to T
${email} — parameter, not concatenation
$executeRaw — affected row count
Prisma.join — safe IN (...) list
Prisma.sql / Prisma.empty — compose
::int — avoid BigInt from count(*)
…Unsafe — string SQL; params only

TypedSQL

-- prisma/sql/topAuthors.sql
-- @param {Int} $1:minPosts
SELECT u.id, u.email, count(p.id)::int AS posts
FROM users u JOIN posts p ON p.author_id = u.id
GROUP BY u.id HAVING count(p.id) >= $1;

Safe vs Unsafe

APIInjection-safe?
$queryRaw`…${v}`✔ parameterized
Prisma.sql`…${v}`✔ parameterized
Prisma.join(arr)✔ parameterized
$queryRawUnsafe(sql, v)✔ only with $1 params
$queryRawUnsafe(`…${v}`)✖ string concat
Prisma.raw(str)✖ inserted verbatim

⚠ Common Mistakes

  • $queryRawUnsafe with template-string interpolation — SQL injection
  • Quoting params yourself: '${v}' — breaks binding
  • Interpolating table/column names — params can't be identifiers
  • Using model field names instead of mapped column names

✓ Tips & Best Practices

  • Prefer TypedSQL for complex, frequently used queries
  • Cast count(*) to ::int to get number
  • Allow-list identifiers before using Prisma.raw
  • Use EXPLAIN ANALYZE the same way for tuning

Quick Summary

  • $queryRaw — SELECT → rows
  • $executeRaw — writes → count
  • tagged template — automatic parameters
  • Prisma.join / Prisma.sql — safe composition
  • TypedSQL — .sql files with types
