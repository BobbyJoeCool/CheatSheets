Sheet 17

Migrations

migrate dev · db push · migrate deploy · migrate status · migrate resolve · migrate reset

Versioned Schema Changes

Prisma Migrate compares schema.prisma with the database and writes SQL migration files to prisma/migrations/. Commit them: they are the history every environment replays. Use migrate dev while developing, migrate deploy in CI/production, and db push only for quick prototypes that need no history.

v7 Changes

  • migrate dev no longer runs generate
  • No auto-seed — run prisma db seed
  • --skip-generate / --skip-seed removed
  • URL comes from prisma.config.ts

Workflow

# development
npx prisma migrate dev --name add_user_role    # create + apply + record
npx prisma generate                            # refresh client types
npx prisma migrate dev --create-only --name x  # write SQL, edit, then apply
npx prisma db push                             # prototype: sync, no files
npx prisma db seed                             # run migrations.seed

# CI / production
npx prisma migrate status                      # pending? drift?
npx prisma migrate deploy                      # apply pending only

# fixing history
npx prisma migrate resolve --applied 20261003120000_add_user_role
npx prisma migrate resolve --rolled-back 20261003120000_add_user_role
npx prisma migrate reset                       # ⚠ dev only: drop + reapply

Code Explained

--name — folder suffix for the migration
--create-only — review/edit SQL first
db push — no migration file or history
migrate status — compare files vs DB
migrate deploy — never prompts or resets
resolve — mark a failed migration
reset — deletes all data

⚠ Common Mistakes

  • Running migrate dev against production — it can reset
  • Editing an applied migration.sql — checksum mismatch
  • Using db push on a shared DB — no history to replay
  • Expecting migrate dev to regenerate the client in v7

✓ Tips & Best Practices

  • Run migrate deploy in CI before the new app starts
  • Use --create-only to add data backfills to the SQL
  • Commit migration_lock.toml with the migrations
  • Gate deploys on migrate status showing no drift

Quick Summary

  • migrate dev — create + apply (dev)
  • migrate deploy — apply pending (prod)
  • db push — sync without history
  • migrate resolve / reset — repair / wipe
