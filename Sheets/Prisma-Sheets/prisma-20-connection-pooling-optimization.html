Connection Pooling & Optimization

PrismaPg · max · connectionTimeoutMillis · idleTimeoutMillis · PgBouncer · $on('query')

Managing Connections

In Prisma 7 the driver adapter owns the pool. Pool size and timeouts are adapter options (max, connectionTimeoutMillis, idleTimeoutMillis for pg); the old connection_limit URL parameters no longer apply. Every app instance has its own pool, so total connections = instances × max, which must stay below the database's max_connections.

Notes

  • pg default max is 10 (v6: CPUs × 2 + 1)
  • Serverless: small max + external pooler
  • CLI uses the URL in prisma.config.ts
  • App uses the adapter's connectionString

Pool Configuration & Monitoring

import { PrismaPg } from "@prisma/adapter-pg";

const adapter = new PrismaPg({
  connectionString: process.env.DATABASE_URL,   // pooled URL (PgBouncer)
  max: 10,                                      // pool size per instance
  connectionTimeoutMillis: 5_000,               // fail fast when pool is full
  idleTimeoutMillis: 30_000,                    // close idle connections
});

export const prisma = new PrismaClient({
  adapter,
  log: [{ emit: "event", level: "query" }, "warn", "error"],
});

prisma.$on("query", (e) => {
  if (e.duration > 200) console.warn(`slow ${e.duration}ms: ${e.query}`);
});

// prisma.config.ts → datasource: { url: env("DIRECT_URL") }  // migrations

Code Explained

max — connections per process
connectionTimeoutMillis — default 0 = wait forever
idleTimeoutMillis — default 10s
emit: 'event' — enables $on('query')
e.duration — ms per query
DIRECT_URL — migrations bypass the pooler

⚠ Common Mistakes

  • Copying v6 ?connection_limit= into v7 URLs — ignored
  • Large max × many replicas — "too many connections"
  • Running migrations through a transaction-mode pooler
  • Leaving connectionTimeoutMillis at 0 — requests hang

✓ Tips & Best Practices

  • Set a finite connectionTimeoutMillis to surface pool exhaustion
  • Use a pooled URL in the app and a direct URL for the CLI
  • Log slow queries with $on('query') and duration
  • Call $disconnect() on shutdown to drain the pool

Quick Summary

  • adapter options — pool size & timeouts
  • instances × max < max_connections
  • pooler for serverless, direct URL for CLI
  • $on('query') — slow-query logging
