Sheet 11

Cloud NAT & Connectivity

Cloud NAT · Cloud Router · Private Service Connect · VPC Network Peering · Cloud VPN · Cloud Interconnect · Network Connectivity Center

Outbound, Private Services and Hybrid

Cloud NAT (configured on a Cloud Router) gives private VMs and GKE nodes outbound internet access. Private Service Connect (PSC) exposes Google APIs or producer services on private IPs in your VPC. Private services access peers your VPC with Google-managed services such as Cloud SQL. Cloud VPN, Interconnect and Network Connectivity Center link on-premises and other networks.

Key Points

  • Cloud NAT is a managed, software-defined service (no VM to manage)
  • Peering is not transitive
  • NCC provides hub-and-spoke for VPCs and hybrid links
  • Serverless VPC access / Direct VPC egress connect Cloud Run to a VPC

NAT, PSC for Google APIs, Private Services Access

gcloud compute routers create rtr-usc1 --network=vpc-shop --region=us-central1
gcloud compute routers nats create nat-usc1 --router=rtr-usc1 \
    --region=us-central1 --auto-allocate-nat-external-ips \
    --nat-all-subnet-ip-ranges --enable-logging

# Private Service Connect endpoint for all Google APIs
gcloud compute addresses create psc-apis --global \
    --purpose=PRIVATE_SERVICE_CONNECT --addresses=10.255.255.254 \
    --network=vpc-shop
gcloud compute forwarding-rules create pscapis --global --network=vpc-shop \
    --address=psc-apis --target-google-apis-bundle=all-apis

# Private services access (Cloud SQL, Memorystore…)
gcloud compute addresses create google-managed --global \
    --purpose=VPC_PEERING --prefix-length=16 --network=vpc-shop
gcloud services vpc-peerings connect \
    --service=servicenetworking.googleapis.com \
    --ranges=google-managed --network=vpc-shop

gcloud compute networks peerings create shop-to-data --network=vpc-shop \
    --peer-network=vpc-data --peer-project=data-prod-1111

Code Explained

Cloud NAT needs a Cloud Router in the same region
The PSC endpoint gives Google APIs a private address in your VPC
Private services access reserves a range for Google-managed services
Peering needs a matching peering from the other side

AWS / Azure Equivalent

  • AWS NAT gateway, VPC endpoints / PrivateLink, peering, Transit Gateway (aws-11)
  • Azure NAT Gateway, Private Endpoints, peering, Virtual WAN (az-11)

Cost Check

  • Cloud NAT: per gateway-hour + per GB processed
  • PSC endpoints: hourly + data processed
  • Interconnect beats VPN on egress price at high volume

Do & Don't

  • Do Use HA VPN (two tunnels) rather than Classic VPN
  • Do Size NAT ports for busy egress (dynamic port allocation)
  • Don’t Give every VM an external IP to reach the internet
  • Don’t Forget DNS for PSC endpoints

Local Testing

  • Connectivity Tests simulate paths
  • NAT logs show port exhaustion and drops
  • Practice in a sandbox VPC with tiny VMs

Production Checklist

  • Cloud NAT per region with logging
  • Private access to Google APIs and managed services
  • Hybrid links redundant (HA VPN / dual Interconnect)
