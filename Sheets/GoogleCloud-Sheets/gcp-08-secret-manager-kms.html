Sheet 08

Secret Manager & Cloud KMS

secrets & versions · gcloud secrets create / versions access · rotation · key rings & keys · CMEK · envelope encryption

Secrets and Encryption Keys

Secret Manager stores secrets as immutable, numbered versions; apps read latest or a pinned version with IAM (roles/secretmanager.secretAccessor). Cloud Run and GKE can mount secrets directly. Cloud KMS manages keys in key rings per location; services use them as customer-managed encryption keys (CMEK). Data is encrypted at rest by default with Google-managed keys.

Key Points

  • Rotation: add a new version, update consumers, disable the old one
  • Rotation schedules publish Pub/Sub notifications to trigger your rotator
  • Replication policy: automatic or user-managed locations
  • Cloud HSM and Cloud EKM add hardware and external key options

Security Check

  • Grant secretAccessor per secret, not project-wide
  • Use CMEK where compliance requires key control and audit
  • Enable Data Access audit logs for Secret Manager in sensitive projects

Limits & Quotas

  • Secret payload up to 64 KiB
  • Access requests are quota-limited per project per minute: cache secrets
  • Cloud KMS cryptographic requests have per-project, per-location quotas

Secrets and Keys

gcloud secrets create db-password --replication-policy=automatic
printf '%s' "$DB_PASS" | gcloud secrets versions add db-password --data-file=-
gcloud secrets versions access latest --secret=db-password
gcloud secrets add-iam-policy-binding db-password \
    --member="serviceAccount:api@shop-prod-4821.iam.gserviceaccount.com" \
    --role="roles/secretmanager.secretAccessor"
gcloud secrets versions disable 1 --secret=db-password

# Cloud Run reads it as an env var at startup
gcloud run services update api --region=us-central1 \
    --set-secrets=DB_PASSWORD=db-password:latest

gcloud kms keyrings create main --location=us-central1
gcloud kms keys create app --keyring=main --location=us-central1 \
    --purpose=encryption --rotation-period=90d \
    --next-rotation-time=2026-12-01T00:00:00Z
gcloud kms encrypt --key=app --keyring=main --location=us-central1 \
    --plaintext-file=token.txt --ciphertext-file=token.enc

Code Explained

printf avoids a trailing newline in the secret
The binding grants one service account access to one secret
--set-secrets injects the secret into the Cloud Run container
The key rotates every 90 days automatically

AWS / Azure Equivalent

  • AWS Secrets Manager, Parameter Store, KMS (aws-08)
  • Azure Key Vault secrets and keys (az-08)

Cost Check

  • Secret Manager: per active secret version per month + per 10,000 accesses
  • KMS: per key version per month + operations; HSM keys cost more
  • Disable / destroy old secret versions to stop paying for them

Secret Manager vs KMS

NeedUse
Passwords, API keys, certsSecret Manager
Encrypt your dataCloud KMS (envelope)
Control keys for Google servicesCMEK with Cloud KMS
Hardware-backed keysCloud HSM
Keys outside GoogleCloud EKM

Do & Don't

  • Do Pin versions in production when rollout control matters
  • Do Cache secrets in the app for minutes, not per request
  • Don’t Put secrets in environment variables baked into images
  • Don’t Destroy KMS key versions still protecting data

Local Testing

  • Use a dev project's Secret Manager with impersonated ADC
  • Abstract secret reads behind an interface for unit tests
  • gitleaks / secret scanning before pushing

Production Checklist

  • Per-secret IAM; access audit logs on
  • Rotation process automated and tested
  • CMEK where required, with key rotation
