Config Connector & Choosing IaC

Config Connector (Kubernetes resources for Google Cloud) · Config Controller · exporting existing resources · Pulumi pointer · choosing an IaC tool · decision table

Kubernetes-Style Infrastructure

Config Connector is a Kubernetes add-on that manages Google Cloud resources as Kubernetes objects (StorageBucket, SQLInstance, IAMPolicyMember…), reconciling continuously. Config Controller hosts it as a managed service with Config Sync and Policy Controller. gcloud resource-config bulk-export exports existing resources to Terraform or KRM. Choose the tool your team can review and operate.

Key Points

  • Config Connector runs on GKE (add-on) or Config Controller
  • Resources reconcile: manual changes are reverted
  • Pulumi offers general-purpose languages with the Google Cloud provider
  • Terraform has the widest ecosystem and examples

Config Connector Resources

apiVersion: storage.cnrm.cloud.google.com/v1beta1
kind: StorageBucket
metadata:
  name: acme-uploads-prod
  namespace: shop
  annotations:
    cnrm.cloud.google.com/project-id: shop-prod-4821
spec:
  location: US-CENTRAL1
  uniformBucketLevelAccess: true
  publicAccessPrevention: enforced
  versioning: { enabled: true }
  lifecycleRule:
    - action: { type: Delete }
      condition: { age: 365 }
---
apiVersion: iam.cnrm.cloud.google.com/v1beta1
kind: IAMPolicyMember
metadata: { name: api-uploads, namespace: shop }
spec:
  member: serviceAccount:api@shop-prod-4821.iam.gserviceaccount.com
  role: roles/storage.objectUser
  resourceRef:
    kind: StorageBucket
    name: acme-uploads-prod

Apply and Export

kubectl apply -f bucket.yaml
kubectl -n shop get storagebuckets
kubectl -n shop describe storagebucket acme-uploads-prod

gcloud resource-config bulk-export --project=shop-prod-4821 \
    --resource-format=terraform --path=./exported

Code Explained

The project annotation picks where the bucket is created
Config Connector keeps the bucket matching this spec
IAMPolicyMember adds one binding (non-authoritative)
Bulk export turns existing resources into Terraform files

AWS / Azure Equivalent

  • AWS CDK, AWS Controllers for Kubernetes (aws-35)
  • Azure azd, Azure Service Operator (az-35)

Cost Check

  • Config Connector is free; you pay for the GKE cluster
  • Config Controller bills per instance-hour
  • Pick one tool per resource to avoid fighting reconcilers

Choose an IaC Tool

SituationUse

Legacy Deployment ManagerMigrate to Terraform / Infra Manager

Trade-offs

ToolModel
TerraformPlan / apply on demand
Infra ManagerManaged plan / apply
Config ConnectorContinuous reconcile
PulumiPrograms + state service

Do & Don't

  • Do Pick one primary tool and stick to it
  • Do Export existing resources instead of rewriting by hand
  • Don’t Manage the same resource with two tools
  • Don’t Expect Config Connector to stay quiet about manual console edits (it reverts them)

Local Testing

  • kind + Config Connector for experiments (with a dev project)
  • kubectl apply --dry-run=server validates against CRDs
  • Terraform plans locally with impersonated ADC

Production Checklist

  • One tool of record per resource
  • GitOps or CI applies only
  • Drift detected and reconciled automatically
