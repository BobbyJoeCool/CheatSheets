Pub/Sub

topics & subscriptions · pull vs push · ack deadlines · dead-letter topics · ordering keys · exactly-once delivery · BigQuery / Cloud Storage subscriptions

Global Messaging

Pub/Sub decouples producers and consumers. Publishers send messages to a topic; each subscription gets a copy and delivers by pull or push (HTTPS). Messages must be acked before the ack deadline, or they are redelivered. Dead-letter topics catch poison messages, ordering keys keep per-key order, and BigQuery / Cloud Storage subscriptions write directly to storage.

Key Points

  • At-least-once delivery by default; exactly-once is available for pull
  • Retention: unacked messages up to 7 days (topic retention up to 31)
  • Seek replays messages to a timestamp or snapshot
  • Filters deliver only matching messages to a subscription

Topics and Subscriptions

gcloud pubsub topics create orders
gcloud pubsub topics create orders-dlq
gcloud pubsub subscriptions create orders-worker --topic=orders \
    --ack-deadline=60 --dead-letter-topic=orders-dlq \
    --max-delivery-attempts=5 --enable-message-ordering \
    --min-retry-delay=10s --max-retry-delay=600s
gcloud pubsub subscriptions create orders-push --topic=orders \
    --push-endpoint=https://audit-abc123-uc.a.run.app/ \
    --push-auth-service-account=push@shop-prod-4821.iam.gserviceaccount.com
gcloud pubsub topics publish orders --message='{"id":"o-1001"}' \
    --ordering-key=customer-42 --attribute=type=created

Publish and Pull (Python)

import json
from google.cloud import pubsub_v1

pub = pubsub_v1.PublisherClient(
    publisher_options=pubsub_v1.types.PublisherOptions(
        enable_message_ordering=True))
topic = pub.topic_path("shop-prod-4821", "orders")
pub.publish(topic, json.dumps({"id": "o-1001"}).encode(),
            ordering_key="customer-42", type="created").result()

sub = pubsub_v1.SubscriberClient()
path = sub.subscription_path("shop-prod-4821", "orders-worker")

def handle(msg):
    process(json.loads(msg.data))
    msg.ack()           # nack() or no ack → redelivery

future = sub.subscribe(path, callback=handle)
future.result()         # blocks; streaming pull

Code Explained

After 5 failed deliveries the message goes to the dead-letter topic
Push subscriptions call Cloud Run with an authenticated ID token
Ordering keys keep one customer's messages in order
Streaming pull receives messages as they arrive

Cost Check

  • Throughput billed per TiB published and delivered (first 10 GiB / month free)
  • Retained acked messages and snapshots bill for storage
  • BigQuery subscriptions avoid paying for a separate writer service

Limits & Quotas

  • Message size up to 10 MB
  • Ack deadline 10 s to 600 s (extend with modifyAckDeadline)
  • Publish / subscribe throughput quotas per project and region

Do & Don't

  • Do Make subscribers idempotent
  • Do Add a dead-letter topic to every subscription
  • Don’t Ack before processing finishes
  • Don’t Use one subscription for two different consumers (each needs its own)

Local Testing

  • gcloud beta emulators pubsub start + PUBSUB_EMULATOR_HOST
  • Client libraries switch to the emulator automatically
  • Seek a dev subscription to replay test messages

Production Checklist

  • DLQ with alerting on its backlog
  • Oldest-unacked-message age alerts
  • Push endpoints authenticated with OIDC
