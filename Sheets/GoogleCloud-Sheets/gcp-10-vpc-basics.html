Networking in Google Cloud

A Google Cloud VPC network is global: one network spans all regions, and subnets are regional. Use custom mode to choose subnet ranges (auto mode creates a subnet per region). Routes and firewall rules apply network-wide. Private Google Access lets VMs without external IPs reach Google APIs, and Shared VPC lets many projects use one centrally managed network.

Key Points

  • Google reserves 4 addresses in each subnet
  • Secondary ranges hold GKE Pod and Service IPs
  • Subnets can be expanded later (but not shrunk)
  • The default network is auto mode: avoid it for production

Security Check

  • Delete or never use the default network in production projects
  • Turn on Private Google Access for private subnets
  • Enable VPC Flow Logs on important subnets

Limits & Quotas

  • VPC networks per project are quota-limited (default 15)
  • Subnet, route and peering counts have per-network limits
  • Check quotas: gcloud compute project-info describe

Custom VPC and Subnets

gcloud compute networks create vpc-shop --subnet-mode=custom \
    --bgp-routing-mode=global
gcloud compute networks subnets create app-usc1 --network=vpc-shop \
    --region=us-central1 --range=10.10.0.0/20 \
    --enable-private-ip-google-access --enable-flow-logs
gcloud compute networks subnets create gke-usc1 --network=vpc-shop \
    --region=us-central1 --range=10.10.16.0/20 \
    --secondary-range=pods=10.20.0.0/14,services=10.24.0.0/20 \
    --enable-private-ip-google-access
gcloud compute networks subnets create app-euw1 --network=vpc-shop \
    --region=europe-west1 --range=10.11.0.0/20

gcloud compute networks subnets expand-ip-range app-usc1 \
    --region=us-central1 --prefix-length=19
gcloud compute routes list --filter="network:vpc-shop"

# Shared VPC: host project shares the network with service projects
gcloud compute shared-vpc enable net-host-1234
gcloud compute shared-vpc associated-projects add shop-prod-4821 \
    --host-project=net-host-1234

Code Explained

One network holds subnets in two regions
Secondary ranges reserve IPs for GKE pods and services
Subnets can grow in place
Shared VPC centralizes networking for many projects

AWS / Azure Equivalent

  • AWS Regional VPC, per-AZ subnets (aws-10)
  • Azure Regional VNet, zone-spanning subnets (az-10)
  • Only Google Cloud makes the network itself global

Cost Check

  • VPCs and subnets are free
  • Egress between regions and to the internet bills per GB
  • Flow logs bill as log ingestion: sample if large

Do & Don't

  • Do Plan non-overlapping ranges across regions and environments
  • Do Use Shared VPC for organizations with many projects
  • Don’t Run production in the default network
  • Don’t Make subnets too small for GKE secondary ranges

Local Testing

  • Connectivity Tests explain reachability between endpoints
  • Plan ranges with ipcalc first
  • Docker networks give a quick local model of isolation

Production Checklist

  • Custom-mode VPC in IaC with documented ranges
  • Private Google Access and flow logs enabled
  • Default network deleted (org policy skipDefaultNetworkCreation)
