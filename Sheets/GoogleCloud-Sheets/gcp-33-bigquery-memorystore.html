Analytics and Caching

BigQuery is a serverless data warehouse: load or stream data into tables in datasets and query with GoogleSQL. Partition tables by date and cluster by common filters to scan less. Pay on-demand per TiB scanned or buy editions capacity (slots). Memorystore provides managed in-memory caches: Memorystore for Valkey, Redis Cluster and Redis, plus Memcached.

Key Points

  • Use --dry_run to see bytes scanned before running a query
  • External tables / BigLake query files in Cloud Storage
  • Streaming via the Storage Write API
  • Memorystore uses private IP (PSC for Valkey / Redis Cluster)

BigQuery

bq mk --dataset --location=US shop-prod-4821:sales
bq mk --table --time_partitioning_field=order_date \
    --clustering_fields=customer_id sales.orders schema.json
bq load --source_format=NEWLINE_DELIMITED_JSON sales.orders \
    gs://acme-exports/orders/*.json

bq query --use_legacy_sql=false --dry_run \
  'SELECT customer_id, SUM(total) AS spend
   FROM sales.orders
   WHERE order_date >= "2026-11-01"
   GROUP BY customer_id ORDER BY spend DESC LIMIT 10'

import json, redis
r = redis.Redis(host="10.10.0.30", port=6379)

def get_product(pid):
    if (hit := r.get(f"product:{pid}")):
        return json.loads(hit)
    product = load_from_db(pid)
    r.setex(f"product:{pid}", 300, json.dumps(product))
    return product

Code Explained

Partitioning by date prunes old data from scans
--dry_run reports bytes processed without charging
Valkey speaks the Redis protocol, so redis clients work
Cache entries expire after 5 minutes

Cost Check

  • BigQuery on-demand: per TiB scanned (first 1 TiB per month free) + storage
  • Editions: slot-hours with autoscaling; commitments discount
  • Memorystore: per GB / node-hour, billed while running

Do & Don't

  • Do Dry-run new queries and set maximum bytes billed
  • Do Put TTLs on every cache entry
  • Don’t SELECT * on large tables
  • Don’t Use Memorystore as the only copy of important data

Local Testing

  • BigQuery has no local emulator: use a dev dataset with small samples
  • Valkey / Redis in Docker for cache code
  • Unit test SQL with bq query --dry_run in CI

Production Checklist

  • Partitioned, clustered tables with expiration where suitable
  • Byte limits and quotas per user
  • Cache sized and monitored for evictions
