Scripting Google Cloud

The gcloud CLI manages nearly every Google Cloud service: gcloud <group> <command>. Configurations hold named sets of account, project and region. gcloud auth login signs in the CLI; gcloud auth application-default login creates credentials for your code (client libraries). --format and --filter shape output, and gcloud storage is the modern replacement for gsutil.

Key Points

  • Components: gcloud components install kubectl beta
  • Release tracks: GA, beta, alpha commands
  • bq is the BigQuery CLI; gcloud storage covers Cloud Storage
  • --impersonate-service-account runs commands as a service account

Security Check

  • Run automation as service accounts via impersonation or WIF, not key files
  • Revoke old credentials: gcloud auth revoke
  • Keep ~/.config/gcloud private; it holds tokens

Everyday gcloud

gcloud init                                     # first-time setup
gcloud auth login                               # CLI credentials
gcloud auth application-default login           # credentials for code (ADC)

gcloud config configurations create shop-dev
gcloud config set project shop-dev-1234
gcloud config set compute/region us-central1
gcloud config configurations activate shop-prod
gcloud config list

gcloud compute instances list \
    --filter="status=RUNNING AND labels.env=prod" \
    --format="table(name,zone.basename(),machineType.basename())"
gcloud run services list --format="value(metadata.name)"

gcloud storage ls gs://acme-media-prod/2026/
gcloud storage buckets list \
    --impersonate-service-account=ops@shop-prod-4821.iam.gserviceaccount.com

gcloud components update
gcloud help run deploy                          # full docs

Code Explained

Two logins: one for the CLI, one for client libraries
Configurations switch account / project / region together
--filter selects rows; --format picks and transforms columns
Impersonation borrows a service account's permissions temporarily

AWS / Azure Equivalent

  • AWS AWS CLI profiles, --query (aws-03)
  • Azure Azure CLI, az account set, --query (az-03)
  • gcloud uses --filter / --format instead of JMESPath

Do & Don't

  • Do Use configurations per project / environment
  • Do Pass --project explicitly in scripts
  • Don’t Download service account keys for your laptop
  • Don’t Parse table output in scripts (use value(...) or JSON)

Local Testing

  • Cloud Shell needs no install
  • Docker image gcr.io/google.com/cloudsdktool/google-cloud-cli
  • gcloud beta emulators starts Pub/Sub, Firestore, Bigtable, Spanner emulators

Production Checklist

  • Automation uses WIF or attached service accounts
  • Scripts pin project and region, fail on errors
  • Cloud Audit Logs capture all CLI actions
