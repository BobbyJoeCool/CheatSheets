Google's Cloud

Google Cloud runs in 40+ regions, each with three or more zones, connected by Google's private global network. Resources are zonal (VMs, disks), regional (subnets, Cloud Run services, regional buckets) or global (VPC networks, global load balancers, IAM). Everything lives in a project, grouped under folders and an organization.

Key Points

  • Region / zone names: us-central1, us-central1-a, europe-west1-b
  • A project has a chosen, permanent project ID and a numeric project number
  • APIs are disabled by default per project: enable what you use
  • Premium network tier rides Google's backbone; Standard uses the public internet

Explore Projects, Regions, Zones

gcloud projects list --format="table(projectId,projectNumber,name)"
gcloud config set project shop-prod-4821

gcloud compute regions list --format="value(name)"
gcloud compute zones list --filter="region:us-central1" --format="value(name)"
gcloud services list --enabled          # APIs turned on in this project
gcloud services enable run.googleapis.com compute.googleapis.com

# Full resource names identify everything
# //compute.googleapis.com/projects/shop-prod-4821/zones/us-central1-a/
#   instances/web-1
gcloud asset search-all-resources --scope=projects/shop-prod-4821 \
    --query="labels.env=prod" --format="value(name)"

AWS / Azure Equivalent

  • AWS Regions, AZs, accounts, ARNs (aws-01)
  • Azure Regions, zones, subscriptions, resource groups (az-01)
  • Google Cloud VPCs are global; AWS and Azure networks are regional

Cost Check

  • Free trial credit for 90 days plus Always Free usage (e2-micro, Cloud Run, storage quotas)
  • Standard network tier costs less for egress but is slower
  • Inter-zone and inter-region traffic bills per GB

Do & Don't

  • Do Use one project per app per environment
  • Do Label resources (team, env, app)
  • Don’t Put unrelated apps in one project
  • Don’t Pick a project ID you will regret (it is permanent)

Local Testing

  • Cloud Shell has gcloud, kubectl, Terraform and an editor
  • The free trial plus a budget alert is a safe sandbox
  • Many services have local emulators (Pub/Sub, Firestore, Bigtable, Spanner)

Production Checklist

  • Folders for prod / non-prod with policies attached
  • Organization policies set before teams build
  • Labels enforced for cost attribution
