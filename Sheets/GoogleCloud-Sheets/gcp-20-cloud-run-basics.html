Cloud Run Basics

services & revisions · gcloud run deploy · concurrency · min / max instances · ingress & authentication · traffic splitting

Serverless Containers

Cloud Run runs any container that listens on $PORT. Each deploy creates an immutable revision; traffic can be split between revisions for canaries. Instances scale from zero (or a min instances floor) up to max instances, each handling up to concurrency requests at once. Ingress and IAM authentication decide who can call it.

Key Points

  • Default concurrency is 80 requests per instance
  • Request-based billing charges CPU only during requests; instance-based keeps CPU always allocated
  • Revisions can be tagged for test URLs
  • Direct VPC egress connects to private VPC resources

Security Check

  • Use --no-allow-unauthenticated unless the service is public
  • Set ingress to internal-and-cloud-load-balancing behind an ALB
  • Run as a dedicated service account, not the default compute SA

Limits & Quotas

  • Request timeout up to 60 minutes (default 5)
  • Max concurrency 1,000 per instance
  • Memory up to 32 GiB, CPU up to 8 vCPU per instance; max instances limited by regional quota

Deploy, Configure, Split Traffic

REPO=us-central1-docker.pkg.dev/shop-prod-4821/apps
gcloud run deploy api --image=$REPO/api:1.4.2 --region=us-central1 \
    --service-account=api@shop-prod-4821.iam.gserviceaccount.com \
    --no-allow-unauthenticated --ingress=internal-and-cloud-load-balancing \
    --cpu=1 --memory=512Mi --concurrency=80 --timeout=60s \
    --min-instances=1 --max-instances=50 \
    --set-env-vars=APP_ENV=prod --set-secrets=DB_PASSWORD=db-password:latest \
    --network=vpc-shop --subnet=app-usc1 --vpc-egress=private-ranges-only

# Canary: deploy without traffic, test the tag URL, then shift
gcloud run deploy api --image=$REPO/api:1.5.0 --region=us-central1 \
    --no-traffic --tag=canary
gcloud run services update-traffic api --region=us-central1 \
    --to-tags=canary=10
gcloud run services update-traffic api --region=us-central1 --to-latest

gcloud run services add-iam-policy-binding api --region=us-central1 \
    --member="serviceAccount:web@shop-prod-4821.iam.gserviceaccount.com" \
    --role="roles/run.invoker"
gcloud run revisions list --service=api --region=us-central1

Code Explained

Only the load balancer and internal traffic reach the service
Min 1 instance avoids cold starts for the first request
--no-traffic --tag creates a test URL for the new revision
run.invoker lets the web service call the API

AWS / Azure Equivalent

  • AWS Lambda / App Runner / ECS Fargate (aws-20)
  • Azure Azure Container Apps (az-20)

Cost Check

  • Per vCPU-second, GiB-second and per million requests, with a monthly free tier
  • Min instances bill while idle (at a lower idle rate)
  • Higher concurrency means fewer instances and lower cost

Do & Don't

  • Do Keep containers stateless and fast to start
  • Do Use tags + traffic splitting for canaries
  • Don’t Do background work after returning a response with request-based billing
  • Don’t Make internal APIs public

Local Testing

  • docker run -p 8080:8080 -e PORT=8080 api
  • gcloud run services proxy api tunnels to a private service with your identity
  • Cloud Code runs a local Cloud Run emulator

Production Checklist

  • Dedicated SA, private ingress, IAM auth
  • Min instances for latency-sensitive services
  • Revisions deployed by CI with canary + rollback
