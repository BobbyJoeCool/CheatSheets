Google-Managed Terraform

Infrastructure Manager (Infra Manager) runs Terraform on Google Cloud: you point a deployment at Terraform config (local, Cloud Storage or a Git repo) and a service account, and it runs plan / apply with Cloud Build, stores state, and keeps revisions. Previews show changes first. It replaces Deployment Manager, which reached end of support on March 31, 2026.

Key Points

  • State is managed for you (no backend block needed)
  • Pin the Terraform version with --tf-version-constraint
  • Logs from each run land in Cloud Build / Cloud Storage
  • Supported Terraform versions are limited: check the docs before upgrading

Deploy, Preview, Inspect

gcloud services enable config.googleapis.com
DEP=projects/shop-prod-4821/locations/us-central1/deployments/shop-prod
SA_EMAIL=infra@shop-prod-4821.iam.gserviceaccount.com
SA=projects/shop-prod-4821/serviceAccounts/$SA_EMAIL

gcloud infra-manager previews create \
    projects/shop-prod-4821/locations/us-central1/previews/shop-pr-42 \
    --service-account=$SA --local-source=./infra \
    --input-values=project=shop-prod-4821,image=api:1.5.0
gcloud infra-manager previews export \
    projects/shop-prod-4821/locations/us-central1/previews/shop-pr-42

gcloud infra-manager deployments apply $DEP \
    --service-account=$SA \
    --git-source-repo=https://github.com/acme/shop-infra \
    --git-source-directory=envs/prod --git-source-ref=main \
    --input-values=project=shop-prod-4821,image=api:1.5.0

gcloud infra-manager deployments describe $DEP
gcloud infra-manager revisions list --deployment=$DEP
gcloud infra-manager resources list --revision=$DEP/revisions/r-3
gcloud infra-manager deployments delete $DEP

Code Explained

The Config API powers Infrastructure Manager
The preview produces a plan you can review
The deployment pulls Terraform from a Git path and ref
Each apply creates a revision with its resources

AWS / Azure Equivalent

  • AWS CloudFormation stacks, change sets (aws-34)
  • Azure Deployment stacks, what-if (az-34)

Cost Check

  • Infra Manager bills for the Cloud Build minutes and storage it uses
  • No separate fee for state storage beyond that
  • Previews are cheap insurance before large changes

Do & Don't

  • Do Give each deployment its own least-privilege service account
  • Do Preview before every apply in production
  • Don’t Keep running new work on Deployment Manager
  • Don’t Upgrade Terraform syntax past the versions Infra Manager supports

Local Testing

  • terraform plan locally against the same config
  • tflint and Checkov on the module
  • Previews from pull requests in CI

Production Checklist

  • Deployments sourced from Git refs
  • Previews reviewed before applies
  • Revisions retained for audit and rollback
