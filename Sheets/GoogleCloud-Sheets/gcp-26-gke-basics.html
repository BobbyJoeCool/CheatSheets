Managed Kubernetes

Google Kubernetes Engine (GKE) runs Kubernetes with a Google-managed control plane. Autopilot manages nodes too and bills per Pod request; Standard lets you manage node pools. Use regional clusters for HA, private nodes with limited control plane access, Workload Identity Federation for GKE for Pod permissions, and a release channel for automatic upgrades.

Key Points

  • Autopilot enforces security best practices and Pod resource requests
  • DNS-based control plane endpoint can replace IP allowlists
  • Gateway API replaces many Ingress use cases
  • Use kubectl with gke-gcloud-auth-plugin

Security Check

  • Private nodes and a restricted control plane endpoint
  • Workload Identity Federation for GKE, never node SA keys
  • Enable Binary Authorization and GKE security posture dashboard

Limits & Quotas

  • Standard clusters default to a 15,000-node limit; Autopilot has its own Pod limits
  • Pods per node default 110 (Standard), set by Pod CIDR size
  • Cluster management fee per cluster-hour (free tier credit covers one)

Create, Connect, Grant Permissions to Pods

gcloud container clusters create-auto shop --region=us-central1 \
    --network=vpc-shop --subnetwork=gke-usc1 \
    --cluster-secondary-range-name=pods \
    --services-secondary-range-name=services \
    --enable-private-nodes --release-channel=regular
gcloud container clusters get-credentials shop --region=us-central1
kubectl get nodes

# Pod identity: grant a role directly to a Kubernetes service account
kubectl create namespace api
kubectl create serviceaccount api -n api
POOL=projects/123456789012/locations/global/workloadIdentityPools
WIP=$POOL/shop-prod-4821.svc.id.goog
PRINCIPAL=principal://iam.googleapis.com/$WIP/subject/ns/api/sa/api
gcloud projects add-iam-policy-binding shop-prod-4821 \
    --role=roles/secretmanager.secretAccessor --member="$PRINCIPAL"

kubectl -n api create deployment api \
    --image=us-central1-docker.pkg.dev/shop-prod-4821/apps/api:1.4.2
kubectl -n api set serviceaccount deployment/api api
kubectl -n api set resources deployment/api --requests=cpu=250m,memory=512Mi

Code Explained

The Autopilot cluster uses the subnet's secondary ranges
Private nodes have no external IPs
The principal:// member grants a role to one Kubernetes SA
Autopilot bills on the Pod resource requests

AWS / Azure Equivalent

  • AWS EKS + Pod Identity (aws-26)
  • Azure AKS + workload identity (az-26)

Cost Check

  • Autopilot: per vCPU, memory and storage requested by Pods
  • Standard: per node VM; spread Spot node pools for batch
  • One zonal or Autopilot cluster's management fee is covered by a monthly free tier credit

Do & Don't

  • Do Start with Autopilot
  • Do Set resource requests on every container
  • Don’t Expose the control plane to 0.0.0.0/0
  • Don’t Give Pods the node service account's permissions

Local Testing

  • kind or minikube for manifests
  • Skaffold / Cloud Code for dev loops against GKE
  • kubectl --dry-run=server validates against the cluster

Production Checklist

  • Regional, private, release channel set
  • Workload Identity Federation per workload
  • Binary Authorization and Pod Security enforced
