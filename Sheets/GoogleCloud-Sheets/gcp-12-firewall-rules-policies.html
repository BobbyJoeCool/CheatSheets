Sheet 12

Firewall Rules & Policies

VPC firewall rules · priorities & implied rules · targets by network tag or service account · hierarchical & network firewall policies · Firewall Rules Logging

Filtering Traffic

Google Cloud firewalls are stateful and distributed: rules apply at each VM, defined at the network. VPC firewall rules have a priority (0–65535, lower wins), direction, action and targets (all instances, network tags or service accounts). Implied rules deny all ingress and allow all egress. Hierarchical firewall policies (org / folder) and network firewall policies manage rules centrally.

Key Points

  • Target by service account for stronger identity than tags
  • Health check ranges: 35.191.0.0/16 and 130.211.0.0/22
  • IAP TCP forwarding range: 35.235.240.0/20
  • Cloud NGFW adds L7 inspection, FQDN and geo rules

Security Check

  • Never allow 22 / 3389 from 0.0.0.0/0; allow only the IAP range
  • Use service-account targets instead of free-form tags
  • Enable firewall logging on deny rules

Limits & Quotas

  • Firewall rules per project: default quota 100 (adjustable)
  • Network tags: up to 64 per instance
  • Priority range 0–65535 (implied rules at 65535)

Rules for a Web Tier

SA_WEB=web@shop-prod-4821.iam.gserviceaccount.com
gcloud compute firewall-rules create allow-lb-health --network=vpc-shop \
    --direction=INGRESS --action=allow --rules=tcp:8080 \
    --source-ranges=35.191.0.0/16,130.211.0.0/22 \
    --target-service-accounts=$SA_WEB --priority=1000
gcloud compute firewall-rules create allow-iap-ssh --network=vpc-shop \
    --direction=INGRESS --action=allow --rules=tcp:22 \
    --source-ranges=35.235.240.0/20 --target-service-accounts=$SA_WEB
gcloud compute firewall-rules create deny-egress-inet --network=vpc-shop \
    --direction=EGRESS --action=deny --rules=all \
    --destination-ranges=0.0.0.0/0 --target-tags=db --priority=2000 \
    --enable-logging

# Network firewall policy managed centrally
gcloud compute network-firewall-policies create shop-fw --global
gcloud compute network-firewall-policies rules create 1000 \
    --firewall-policy=shop-fw --global-firewall-policy \
    --direction=INGRESS --action=allow --layer4-configs=tcp:443 \
    --src-ip-ranges=0.0.0.0/0
gcloud compute network-firewall-policies associations create \
    --firewall-policy=shop-fw --network=vpc-shop --global-firewall-policy

Code Explained

Load balancer health checks come from Google's fixed ranges
SSH is allowed only from IAP, never the internet
The egress deny keeps database VMs from calling out
Network firewall policies group rules and attach to networks

Do & Don't

  • Do Allow health check and IAP ranges explicitly
  • Do Keep org-wide denies in hierarchical policies
  • Don’t Open admin ports to 0.0.0.0/0
  • Don’t Rely on tags anyone with instance admin can change

Local Testing

  • Connectivity Tests show which rule allowed or blocked traffic
  • Firewall Insights flags shadowed and unused rules
  • Test from a VM with nc -zv after each change

Production Checklist

  • No public admin ports; IAP only
  • Central policies for org-wide rules
  • Firewall logging and Firewall Insights reviewed
