Cloud DNS

public & private zones · record sets · DNSSEC · routing policies (weighted, geolocation, failover) · gcloud dns record-sets · domain registration through a third-party registrar

Managed DNS

Cloud DNS hosts public zones on Google's anycast name servers and private zones visible only to chosen VPC networks. Routing policies answer by weight, geolocation or failover with health checks on internal load balancers. DNSSEC can be turned on per public zone. Register domains with any registrar and delegate to the zone's name servers.

Key Points

  • Zone DNS names end with a dot: acme-shop.com.
  • Forwarding zones and server policies support hybrid DNS
  • Peering zones resolve names from another VPC
  • Response policies override answers inside a VPC

Zones and Records

gcloud dns managed-zones create shop --dns-name=acme-shop.com. \
    --description="public zone" --dnssec-state=on
gcloud dns managed-zones describe shop --format="value(nameServers)"

gcloud dns record-sets create www.acme-shop.com. --zone=shop \
    --type=A --ttl=300 --rrdatas=34.120.10.20
gcloud dns record-sets create acme-shop.com. --zone=shop --type=TXT \
    --ttl=3600 --rrdatas='"v=spf1 include:_spf.google.com -all"'
gcloud dns record-sets create api.acme-shop.com. --zone=shop --type=A \
    --ttl=60 --routing-policy-type=WRR \
    --routing-policy-data="0.9=34.120.10.21;0.1=34.120.10.22"

# Private zone for internal names
gcloud dns managed-zones create internal --dns-name=shop.internal. \
    --description="private" --visibility=private --networks=vpc-shop
gcloud dns record-sets create db.shop.internal. --zone=internal \
    --type=A --ttl=300 --rrdatas=10.10.0.5
gcloud dns record-sets list --zone=shop

Code Explained

Copy the name servers to your registrar to delegate
DNSSEC on means you must also add the DS record at the registrar
The weighted policy sends 90% / 10% of answers
Private zones resolve only inside vpc-shop

Do & Don't

  • Do Manage zones and records in Terraform
  • Do Add CAA records for your certificate authority
  • Don’t Forget the DS record when enabling DNSSEC
  • Don’t Use long TTLs on records you may change in an incident

Local Testing

  • dig @ns-cloud-a1.googledomains.com www.acme-shop.com tests before delegation
  • dig +dnssec checks signatures
  • CoreDNS in Docker for local name experiments

Production Checklist

  • Records in IaC; DNSSEC with DS at registrar
  • Private zones for internal service names
  • Short TTLs on failover records
