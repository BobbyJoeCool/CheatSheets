Deploying to Google Cloud

google-github-actions/auth (WIF) · Cloud Build & cloudbuild.yaml · Cloud Deploy pipelines · Cloud Run canary via traffic splitting · Binary Authorization · labels strategy

CI/CD Into Google Cloud

From GitHub Actions, authenticate with google-github-actions/auth using Workload Identity Federation (sheet 07), then build and deploy. Cloud Build runs build steps defined in cloudbuild.yaml with triggers from GitHub or other repos. Cloud Deploy promotes releases through targets (dev → staging → prod) with approvals and canary strategies for Cloud Run and GKE.

Key Points

  • id-token: write permission is required for WIF in GitHub Actions
  • Build once, promote the same image digest through environments
  • Cloud Deploy supports canary percentages and verification jobs
  • Labels like app, env, team tie deployments to costs

.github/workflows/deploy.yml

on: { push: { branches: [main] } }
permissions: { contents: read, id-token: write }
jobs:
  deploy:
    runs-on: ubuntu-latest
    environment: production
    env:
      IMG: us-central1-docker.pkg.dev/shop-prod-4821/apps/api:${{ github.sha }}
    steps:
      - uses: actions/checkout@v4
      - uses: google-github-actions/auth@v3
        with:
          workload_identity_provider: ${{ vars.WIF_PROVIDER }}
          service_account: deploy@shop-prod-4821.iam.gserviceaccount.com
      - uses: google-github-actions/setup-gcloud@v2
      - run: gcloud auth configure-docker us-central1-docker.pkg.dev --quiet
      - run: docker build -t "$IMG" . && docker push "$IMG"
      - run: >
          gcloud run deploy api --image="$IMG" --region=us-central1
          --no-traffic --tag=canary

cloudbuild.yaml

steps:
  - name: gcr.io/cloud-builders/docker
    args: [build, -t, "$_IMG:$SHORT_SHA", .]
  - name: gcr.io/cloud-builders/docker
    args: [push, "$_IMG:$SHORT_SHA"]
  - name: gcr.io/google.com/cloudsdktool/cloud-sdk
    entrypoint: gcloud
    args: [deploy, releases, create, "rel-$SHORT_SHA",
           --delivery-pipeline=shop, --region=us-central1,
           "--images=api=$_IMG:$SHORT_SHA"]
substitutions:
  _IMG: us-central1-docker.pkg.dev/$PROJECT_ID/apps/api

Code Explained

The job gets a GitHub OIDC token and exchanges it via WIF
The new revision deploys with no traffic under a canary tag
Cloud Build builds, pushes and creates a Cloud Deploy release
Cloud Deploy then promotes the release through its targets

AWS / Azure Equivalent

  • AWS GitHub OIDC role, CodePipeline / CodeDeploy (aws-39)
  • Azure azure/login with OIDC, Azure Pipelines (az-39)

Cost Check

  • Cloud Build: free build minutes each month, then per build-minute by machine type
  • Cloud Deploy: per active delivery pipeline (first one free)
  • GitHub-hosted runners bill on GitHub, not Google Cloud

Security Check

  • WIF provider condition pinned to the repository and branch / environment
  • Deploy service account with only run / artifact roles
  • Binary Authorization to block unsigned or unscanned images

Do & Don't

  • Do Build once and deploy by digest everywhere
  • Do Gate production with GitHub environments or Cloud Deploy approvals
  • Don’t Store service account JSON keys as GitHub secrets
  • Don’t Rebuild images separately for each environment

Local Testing

  • act runs GitHub workflows locally (no real OIDC)
  • cloud-build-local is retired: test steps with Docker directly
  • Skaffold renders and tests Cloud Deploy manifests

Production Checklist

  • Keyless CI with WIF and narrow conditions
  • Canary + automatic rollback on alerts
  • Deploy history auditable (Cloud Deploy / audit logs)
