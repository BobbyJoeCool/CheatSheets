API Gateway & Apigee

API Gateway (OpenAPI configs) · API keys & JWT auth · Apigee for full API management · Cloud Endpoints · ESPv2 · choosing

Publishing APIs

API Gateway fronts Cloud Run, Functions and App Engine with an OpenAPI 2.0 config: auth (API keys, Google ID tokens, JWT from any issuer), quotas and routing, fully managed. Apigee is the enterprise API management platform: developer portals, monetization, analytics, advanced policies and hybrid deployment. Cloud Endpoints (ESPv2 proxy) suits APIs on GKE or VMs.

Key Points

  • API Gateway calls backends using a service account and ID tokens
  • API keys identify projects; they are not strong authentication
  • Apigee X runs in Google Cloud; Apigee hybrid runs runtimes in your clusters
  • Global ALB + Cloud Armor in front of Cloud Run is often enough for simple APIs

openapi.yaml

swagger: "2.0"
info: { title: shop-api, version: "1.0" }
x-google-backend:
  address: https://api-abc123-uc.a.run.app
securityDefinitions:
  auth0:
    type: oauth2
    flow: implicit
    authorizationUrl: ""
    x-google-issuer: https://acme.auth0.com/
    x-google-jwks_uri: https://acme.auth0.com/.well-known/jwks.json
    x-google-audiences: shop-api
paths:
  /orders:
    get:
      operationId: listOrders
      security: [{ auth0: [] }]
      responses: { "200": { description: OK } }

Create Gateway

gcloud api-gateway apis create shop-api
gcloud api-gateway api-configs create v1 --api=shop-api \
    --openapi-spec=openapi.yaml \
    --backend-auth-service-account=gw@shop-prod-4821.iam.gserviceaccount.com
gcloud api-gateway gateways create shop-gw --api=shop-api \
    --api-config=v1 --location=us-central1
gcloud api-gateway gateways describe shop-gw --location=us-central1 \
    --format="value(defaultHostname)"

Code Explained

x-google-backend routes every path to the Cloud Run service
The security definition validates JWTs from the issuer
Configs are immutable: create v2 and update the gateway
The gateway SA needs run.invoker on the backend

AWS / Azure Equivalent

  • AWS API Gateway HTTP / REST APIs (aws-22)

Cost Check

  • API Gateway: per million calls after a free tier
  • Apigee: subscription or pay-as-you-go environments (much higher)
  • An ALB in front of Cloud Run may cost less for simple routing

Security Check

  • Require JWT / ID tokens, not API keys alone, for user data
  • Keep backends private (--no-allow-unauthenticated) so only the gateway can call them
  • Restrict API keys by API and by referrer / IP

Do & Don't

  • Do Version configs and roll gateways forward
  • Do Keep the OpenAPI spec in the repo with the code
  • Don’t Treat API keys as authentication for sensitive data
  • Don’t Choose Apigee for one small internal API

Local Testing

  • Validate the spec with swagger-cli validate openapi.yaml
  • Test JWT validation with tokens from a dev tenant
  • Run the backend locally and test paths with curl

Production Checklist

  • JWT or ID-token auth on every route
  • Private backends; gateway SA as the only invoker
  • Quotas configured; logs and metrics monitored
