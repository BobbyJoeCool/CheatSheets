Policies, Conditions and Guardrails

An allow policy on a resource is a list of bindings: role + members + optional condition (CEL expressions on time, resource name, tags). Deny policies block specific permissions regardless of allows. Organization Policy constraints restrict configurations (no external IPs, allowed regions, no service account keys) across folders and projects.

Key Points

  • Conditions make temporary or scoped access (e.g. expires at a date)
  • Deny policies attach at organization, folder or project
  • Use etags with set-iam-policy to avoid overwriting concurrent changes
  • Managed constraints and custom constraints exist for org policy

Condition, Deny Policy, Org Policy

gcloud projects add-iam-policy-binding shop-prod-4821 \
    --member="user:contractor@acme.com" --role="roles/viewer" \
    --condition-from-file=until-year-end.yaml

ATTACH=cloudresourcemanager.googleapis.com/projects/shop-prod-4821
gcloud iam policies create deny-delete-db --kind=denypolicies \
    --attachment-point=$ATTACH \
    --policy-file=deny.json

gcloud org-policies set-policy no-external-ip.yaml
gcloud org-policies describe compute.vmExternalIpAccess --project=shop-prod-4821

gcloud policy-intelligence troubleshoot-policy iam \
    //cloudresourcemanager.googleapis.com/projects/shop-prod-4821 \
    --principal-email=ada@acme.com --permission=run.services.update

until-year-end.yaml / no-external-ip.yaml

# until-year-end.yaml (IAM condition):
expression: request.time < timestamp("2026-12-31T00:00:00Z")
title: until-year-end
---
name: projects/shop-prod-4821/policies/compute.vmExternalIpAccess
spec:
  rules:
    - denyAll: true
# deny.json (deny policy):
# {"rules":[{"denyRule":{"deniedPrincipals":["principalSet://goog/public:all"],
#   "deniedPermissions":["sqladmin.googleapis.com/instances.delete"]}}]}

Code Explained

The condition expires access automatically at year end
The deny policy blocks instance deletes for everyone (add exceptions as needed)
The org policy forbids external IPs on VMs in the project
Troubleshooter explains why a permission is allowed or denied

Cost Check

  • IAM, deny policies and org policies are free
  • Org policies like allowed locations prevent costly mistakes
  • Policy Intelligence tools are free for most uses

Limits & Quotas

  • 1,500 principals per allow policy (use groups)
  • 300 custom roles per project and per organization
  • Conditions per binding are limited; keep expressions simple

Do & Don't

  • Do Use conditions for temporary and scoped access
  • Do Set core org policies at the organization
  • Don’t Use set-iam-policy without the current etag
  • Don’t Rely on reviews alone instead of deny policies for critical actions

Local Testing

  • Policy Simulator previews allow-policy changes against recent access
  • Test org policies in a sandbox folder
  • Terraform plans show IAM binding diffs

Production Checklist

  • Key org policies enforced org-wide
  • Deny policies for destructive admin actions
  • IAM recommender and Policy Analyzer reviews scheduled
