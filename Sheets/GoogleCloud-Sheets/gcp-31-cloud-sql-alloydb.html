Cloud SQL & AlloyDB

MySQL, PostgreSQL & SQL Server · Enterprise vs Enterprise Plus editions · high availability & read replicas · point-in-time recovery · Cloud SQL Auth Proxy & connectors · IAM database auth · AlloyDB

Managed Relational Databases

Cloud SQL runs managed MySQL, PostgreSQL and SQL Server with backups, patching, regional HA (standby in another zone) and read replicas. Enterprise Plus adds faster failover and data cache. Connect with private IP and the Cloud SQL Auth Proxy or language connectors (IAM-authorized, TLS). AlloyDB is a PostgreSQL-compatible engine for higher performance and analytics.

Key Points

  • IAM database authentication lets service accounts log in without passwords
  • PITR uses transaction logs (binary logs / WAL)
  • Maintenance windows and deny periods control patching
  • Cross-region replicas support DR and promotion

Security Check

  • Private IP only; no authorized networks of 0.0.0.0/0
  • Use IAM database auth or Secret Manager passwords, never hard-coded
  • Require SSL / connectors (--ssl-mode=ENCRYPTED_ONLY)

Limits & Quotas

  • Storage up to 64 TB per instance
  • Max connections depend on the tier and engine flags
  • Custom machine shapes need the Enterprise edition

Create, Connect, Recover

gcloud sql instances create shop-pg --database-version=POSTGRES_16 \
    --edition=ENTERPRISE --tier=db-custom-2-8192 --region=us-central1 \
    --availability-type=REGIONAL --storage-auto-increase \
    --network=projects/shop-prod-4821/global/networks/vpc-shop \
    --no-assign-ip --enable-point-in-time-recovery \
    --backup-start-time=03:00 --ssl-mode=ENCRYPTED_ONLY \
    --database-flags=cloudsql.iam_authentication=on
gcloud sql databases create shop --instance=shop-pg
gcloud sql users create api@shop-prod-4821.iam --instance=shop-pg \
    --type=CLOUD_IAM_SERVICE_ACCOUNT
gcloud sql instances create shop-pg-r1 --master-instance-name=shop-pg \
    --region=us-east1

./cloud-sql-proxy --auto-iam-authn --private-ip \
    shop-prod-4821:us-central1:shop-pg &
psql "host=127.0.0.1 user=api@shop-prod-4821.iam dbname=shop"

gcloud sql instances clone shop-pg shop-pg-restore \
    --point-in-time=2026-11-12T09:30:00Z

Code Explained

Regional availability keeps a standby in a second zone
The IAM user logs in with its service account token
The proxy handles TLS and IAM auth on localhost
Cloning to a point in time restores into a new instance

AWS / Azure Equivalent

  • AWS RDS, Aurora, RDS Proxy (aws-31)
  • Azure Azure SQL Database, PostgreSQL Flexible Server (az-31)

Cost Check

  • Billed per vCPU, memory, storage and backups; HA roughly doubles compute
  • CUDs discount steady Cloud SQL usage
  • Read replicas and cross-region replicas each bill as instances

Do & Don't

  • Do Turn on PITR and test restores
  • Do Use connectors so credentials never cross the wire
  • Don’t Open public IP with broad authorized networks
  • Don’t Size max connections without a pooler for serverless clients

Local Testing

  • PostgreSQL / MySQL in Docker for development
  • Auth Proxy to reach a dev instance from your laptop
  • Run migrations in CI against a container first

Production Checklist

  • Private IP, regional HA, PITR
  • IAM DB auth; deletion protection on
  • Maintenance window set; replica for DR
