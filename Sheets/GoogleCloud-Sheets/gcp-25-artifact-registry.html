Artifact Registry

Docker, npm, Maven, Python, Go… repositories · standard, remote & virtual repos · gcloud auth configure-docker · vulnerability scanning · cleanup policies · Container Registry is shut down

Storing Images and Packages

Artifact Registry stores container images and language packages in regional or multi-regional repositories. Remote repositories cache upstreams (Docker Hub, npm, PyPI, Maven Central), and virtual repositories combine several behind one URL. Artifact Analysis scans images for vulnerabilities, and cleanup policies delete old versions. Container Registry (gcr.io) has been replaced by Artifact Registry.

Key Points

  • Image paths: LOCATION-docker.pkg.dev/PROJECT/REPO/IMAGE:TAG
  • gcr.io domains can be served by Artifact Registry repositories
  • Use digests (@sha256:…) for immutable deploys
  • Immutable tags can be enforced per repository

Repos, Push, Scan, Clean Up

gcloud artifacts repositories create apps --repository-format=docker \
    --location=us-central1 --immutable-tags \
    --description="Shop container images"
gcloud auth configure-docker us-central1-docker.pkg.dev

IMG=us-central1-docker.pkg.dev/shop-prod-4821/apps/api
docker build -t $IMG:1.4.2 .
docker push $IMG:1.4.2
gcloud builds submit --tag=$IMG:1.4.3 .        # or build in the cloud

gcloud artifacts docker images list $IMG
gcloud artifacts docker images describe $IMG:1.4.2 \
    --show-package-vulnerability

gcloud artifacts repositories set-cleanup-policies apps \
    --location=us-central1 --policy=cleanup.json --no-dry-run

gcloud artifacts repositories create pypi-proxy --location=us-central1 \
    --repository-format=python --mode=remote-repository \
    --remote-python-repo=PYPI
gcloud artifacts repositories add-iam-policy-binding apps \
    --location=us-central1 --role=roles/artifactregistry.reader \
    --member="serviceAccount:api@shop-prod-4821.iam.gserviceaccount.com"

Code Explained

Immutable tags stop a release tag from being overwritten
configure-docker adds a credential helper for the registry host
Scanning results show per-package vulnerabilities
The remote repo caches PyPI packages for builds

AWS / Azure Equivalent

  • AWS ECR + pull-through cache (aws-25)
  • Azure Azure Container Registry (az-25)

Cost Check

  • Storage per GB per month (first 0.5 GB free)
  • Egress across regions and to the internet bills per GB
  • Cleanup policies keep old images from piling up

Security Check

  • Grant artifactregistry.reader to runtimes and writer only to CI
  • Turn on vulnerability scanning and gate deploys with Binary Authorization
  • Enable immutable tags for release repositories

Limits & Quotas

  • Request quotas per project per region (read / write per minute)
  • Docker layer size limits apply (very large layers fail)
  • Cleanup policies run asynchronously (not instant)

Do & Don't

  • Do Deploy by digest, not mutable tags
  • Do Put a remote repo in front of Docker Hub to avoid rate limits
  • Don’t Keep using gcr.io paths without migrating
  • Don’t Grant writer to runtime service accounts

Local Testing

  • docker build + docker run locally before pushing
  • Trivy / Grype scan images locally
  • Point pip / npm at the remote repo to test caching

Production Checklist

  • Immutable tags + scanning on release repos
  • Cleanup policies tested in dry-run
  • Binary Authorization requiring scanned, attested images
