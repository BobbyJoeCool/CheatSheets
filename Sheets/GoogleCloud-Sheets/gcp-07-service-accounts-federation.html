Service Accounts & Workload Identity Federation

service accounts · attaching to resources · --impersonate-service-account · Workload Identity Federation for GitHub Actions · Workload Identity Federation for GKE · disabling key creation

Identities for Workloads

A service account is the identity a workload runs as. Attach it to Cloud Run, Functions, VMs or GKE workloads and the platform supplies short-lived tokens. People and pipelines impersonate service accounts (roles/iam.serviceAccountTokenCreator) instead of downloading keys. Workload Identity Federation (WIF) lets external identities (GitHub Actions, AWS, Azure, OIDC / SAML) get Google credentials without keys.

Key Points

  • Default compute service accounts often have Editor: replace with dedicated ones
  • Deploying a service with an SA requires iam.serviceAccounts.actAs on it
  • WIF uses a pool + provider + attribute mapping + condition
  • GKE workloads federate through the cluster's workload pool

Service Account and GitHub Federation

gcloud iam service-accounts create deploy --display-name="GitHub deploy"
SA=deploy@shop-prod-4821.iam.gserviceaccount.com
gcloud projects add-iam-policy-binding shop-prod-4821 \
    --member="serviceAccount:$SA" --role="roles/run.admin"

gcloud iam workload-identity-pools create github --location=global
MAP="google.subject=assertion.sub,attribute.repository=assertion.repository"
COND="assertion.repository=='acme/shop' && assertion.ref=='refs/heads/main'"
gcloud iam workload-identity-pools providers create-oidc gh \
    --location=global --workload-identity-pool=github \
    --issuer-uri=https://token.actions.githubusercontent.com \
    --attribute-mapping="$MAP" --attribute-condition="$COND"

POOL=projects/123456789012/locations/global/workloadIdentityPools/github
REPO=attribute.repository/acme/shop
gcloud iam service-accounts add-iam-policy-binding $SA \
    --role="roles/iam.workloadIdentityUser" \
    --member="principalSet://iam.googleapis.com/$POOL/$REPO"

# People impersonate instead of using keys
gcloud iam service-accounts add-iam-policy-binding $SA \
    --member="group:platform@acme.com" \
    --role="roles/iam.serviceAccountTokenCreator"
gcloud run services list --impersonate-service-account=$SA

Code Explained

The deploy SA gets only the roles CI needs
The provider maps GitHub token claims to attributes
The condition rejects tokens from other repos or branches
workloadIdentityUser lets matching GitHub jobs act as the SA

AWS / Azure Equivalent

  • AWS IAM roles + OIDC providers (aws-07)
  • Azure Managed identities + federated credentials (az-07)

Cost Check

  • Service accounts, impersonation and WIF are free
  • No key rotation work or leaked-key incidents
  • Each WIF token exchange is a free STS call

Security Check

  • Pin the WIF attribute condition to your repository (and ref / environment)
  • Disable service account key creation by org policy
  • Do not use default compute service accounts for workloads

Roles on Service Accounts

RoleLets Principal
iam.serviceAccountUserAttach SA to resources (actAs)

Do & Don't

  • Do One service account per workload with least privilege
  • Do Federate CI and other clouds with WIF
  • Don’t Download JSON keys for CI
  • Don’t Run apps as the default compute service account

Local Testing

  • Impersonated ADC tests the workload's real permissions
  • gcloud iam service-accounts get-iam-policy reviews who can act as an SA
  • Policy Troubleshooter for permission questions

Production Checklist

  • Zero service account keys (org policy enforced)
  • WIF conditions pinned to repo + ref / environment
  • Service account usage monitored (Activity Analysis / recommender)
