Cloud Run Functions & Jobs

Cloud Run functions (formerly Cloud Functions) · HTTP & event triggers · Functions Framework · Cloud Run jobs · tasks & parallelism · scheduling jobs

Functions and Run-to-Completion Work

Cloud Run functions deploy source code (Node.js, Python, Go, Java, .NET, Ruby, PHP) as a Cloud Run service built with the Functions Framework, triggered by HTTP or Eventarc events. Cloud Run jobs run containers to completion: a job execution starts many tasks in parallel, each with an index, retries and a timeout. Cloud Scheduler can run jobs on a cron.

Key Points

  • gcloud functions deploy --gen2 and gcloud run deploy --function both create Cloud Run functions
  • Tasks read CLOUD_RUN_TASK_INDEX and CLOUD_RUN_TASK_COUNT
  • Event functions receive CloudEvents
  • Jobs can run up to 168 hours per task (7 days)

Function Code (Python)

import functions_framework

@functions_framework.http
def hello(request):
    name = request.args.get("name", "world")
    return {"hello": name}

@functions_framework.cloud_event
def on_upload(event):
    data = event.data
    print(f"New object gs://{data['bucket']}/{data['name']}")

Deploy Function, Job, Schedule

gcloud run deploy hello --source=. --function=hello \
    --base-image=python312 --region=us-central1 --no-allow-unauthenticated

gcloud functions deploy on-upload --gen2 --runtime=python312 \
    --region=us-central1 --source=. --entry-point=on_upload \
    --trigger-bucket=acme-uploads-prod \
    --service-account=fn@shop-prod-4821.iam.gserviceaccount.com

REPO=us-central1-docker.pkg.dev/shop-prod-4821/apps
gcloud run jobs create resize --image=$REPO/resize:1.0 \
    --region=us-central1 --tasks=50 --parallelism=10 \
    --max-retries=3 --task-timeout=15m
gcloud run jobs execute resize --region=us-central1 --wait

RUN=https://run.googleapis.com/v2
gcloud scheduler jobs create http resize-nightly --location=us-central1 \
    --schedule="0 2 * * *" --http-method=POST \
    --uri="$RUN/projects/shop-prod-4821/locations/us-central1/jobs/resize:run" \
    --oauth-service-account-email=sched@shop-prod-4821.iam.gserviceaccount.com

Code Explained

One decorator per trigger type
--trigger-bucket wires an Eventarc trigger for new objects
The job runs 50 tasks, 10 at a time, retrying failures
Cloud Scheduler calls the Run Admin API to start the job nightly

AWS / Azure Equivalent

  • AWS Lambda functions, ECS tasks / Batch (aws-21)
  • Azure Azure Functions, Container Apps jobs (az-21)

Cost Check

  • Functions bill as Cloud Run (CPU, memory, requests)
  • Jobs bill only while tasks run
  • Scheduler: a few free jobs per billing account, then per job per month

Limits & Quotas

  • Up to 10,000 tasks per job execution
  • Task timeout default 10 min, max 168 hours
  • Event-driven functions inherit Eventarc delivery and retry limits

Do & Don't

  • Do Make event handlers idempotent (events can repeat)
  • Do Split big batches by task index
  • Don’t Use a function for long-running batch work (use jobs)
  • Don’t Process an upload event by writing back to the same bucket path (loop)

Local Testing

  • functions-framework --target=hello runs locally on port 8080
  • Send test CloudEvents with curl to the local server
  • Run job containers locally with CLOUD_RUN_TASK_INDEX=0

Production Checklist

  • Dedicated SA per function / job
  • Dead-letter topics on event triggers
  • Alerts on job failures and function errors
