Cloud Load Balancing

Application vs Network Load Balancers · external vs internal · global vs regional · backend services & NEGs · health checks · serverless NEGs for Cloud Run

Choosing a Load Balancer

Cloud Load Balancing is a family: Application Load Balancers (HTTP/S, L7) and Network Load Balancers (TCP/UDP, L4, proxy or passthrough), each external or internal, global or regional. They share building blocks: a forwarding rule (IP + port), a target proxy, a URL map, backend services with health checks, and backends such as MIGs or NEGs (including serverless NEGs for Cloud Run).

Key Points

  • Global external ALB gives one anycast IP worldwide
  • Health check traffic comes from 35.191.0.0/16 and 130.211.0.0/22
  • Serverless NEGs front Cloud Run, Functions and App Engine
  • Cloud Armor and Cloud CDN attach to backend services

Global External ALB for a MIG and Cloud Run

gcloud compute health-checks create http hc-web --port=8080 \
    --request-path=/healthz
gcloud compute backend-services create web-be --global \
    --protocol=HTTP --port-name=http --health-checks=hc-web \
    --load-balancing-scheme=EXTERNAL_MANAGED
gcloud compute backend-services add-backend web-be --global \
    --instance-group=web-mig --instance-group-region=us-central1

gcloud compute network-endpoint-groups create api-neg \
    --region=us-central1 --network-endpoint-type=serverless \
    --cloud-run-service=api
gcloud compute backend-services create api-be --global \
    --load-balancing-scheme=EXTERNAL_MANAGED
gcloud compute backend-services add-backend api-be --global \
    --network-endpoint-group=api-neg --network-endpoint-group-region=us-central1

gcloud compute url-maps create shop-map --default-service=web-be
gcloud compute url-maps add-path-matcher shop-map --path-matcher-name=api \
    --default-service=web-be --path-rules="/api/*=api-be" \
    --new-hosts=shop.acme.com
gcloud compute target-https-proxies create shop-proxy --url-map=shop-map \
    --certificate-map=shop-map
gcloud compute forwarding-rules create shop-https --global \
    --load-balancing-scheme=EXTERNAL_MANAGED \
    --target-https-proxy=shop-proxy --ports=443

Code Explained

The health check probes /healthz on port 8080
The MIG backend serves the website
The serverless NEG routes /api/* to Cloud Run
The forwarding rule exposes the global IP on 443

AWS / Azure Equivalent

  • AWS ALB, NLB, target groups (aws-17)
  • Azure Application Gateway, Load Balancer, Front Door (az-17)

Cost Check

  • Forwarding rules bill hourly (first 5 rules priced together)
  • Data processed by the LB bills per GB
  • Global ALB + CDN can cut egress cost for cacheable content

Do & Don't

  • Do Use EXTERNAL_MANAGED (the modern ALB scheme)
  • Do Point health checks at a cheap /healthz endpoint
  • Don’t Forget firewall rules for health check ranges
  • Don’t Expose Cloud Run publicly when it should only take LB traffic (set ingress)

Local Testing

  • Test URL maps with gcloud compute url-maps validate
  • Check backend health: gcloud compute backend-services get-health
  • Run the app behind a local reverse proxy (Caddy / nginx) to test paths

Production Checklist

  • HTTPS only with a modern SSL policy
  • Cloud Armor attached to public backends
  • Health checks, logging and alerting on 5xx
