Cloud Storage Security & Features

uniform bucket-level access · public access prevention · signed URLs · versioning & soft delete · lifecycle rules · retention policies & Bucket Lock

Protecting and Managing Objects

Uniform bucket-level access makes IAM the only access control. Public access prevention blocks allUsers grants. Signed URLs give time-limited access without IAM. Object versioning and soft delete (7 days by default) recover deletes and overwrites; lifecycle rules change classes or delete objects. Retention policies with Bucket Lock give WORM compliance.

Key Points

  • Signed URLs (V4) are valid for up to 7 days
  • Signing with an attached service account uses the IAM signBlob API (no key file)
  • Static websites: serve through a load balancer backend bucket (sheet 14)
  • CMEK and VPC Service Controls protect sensitive buckets

Lifecycle, Versioning, Retention

gcloud storage buckets update gs://acme-media-prod --versioning \
    --soft-delete-duration=14d
gcloud storage buckets update gs://acme-media-prod \
    --lifecycle-file=lifecycle.json
gcloud storage buckets update gs://acme-audit --retention-period=2557d
gcloud storage buckets update gs://acme-audit --lock-retention-period

gcloud storage ls --soft-deleted gs://acme-media-prod/2026/
gcloud storage restore gs://acme-media-prod/2026/report.pdf#1767225600000000

gcloud storage sign-url gs://acme-media-prod/2026/report.pdf --duration=15m \
    --impersonate-service-account=signer@shop-prod-4821.iam.gserviceaccount.com

lifecycle.json

{"rule": [
  {"action": {"type": "SetStorageClass", "storageClass": "NEARLINE"},
   "condition": {"age": 30, "matchesPrefix": ["logs/"]}},
  {"action": {"type": "Delete"},
   "condition": {"age": 365, "matchesPrefix": ["logs/"]}},
  {"action": {"type": "Delete"},
   "condition": {"isLive": false, "daysSinceNoncurrentTime": 30}}
]}

Signed URL in Python

import datetime
from google.cloud import storage
blob = storage.Client().bucket("acme-media-prod").blob("2026/report.pdf")
url = blob.generate_signed_url(version="v4", method="GET",
    expiration=datetime.timedelta(minutes=15))

Code Explained

Soft delete keeps deleted objects restorable for 14 days
Logs move to Nearline after 30 days, delete after a year
Locking a retention policy is permanent
The signed URL works for 15 minutes for anyone holding it

AWS / Azure Equivalent

  • AWS Block Public Access, presigned URLs, Object Lock (aws-29)
  • Azure SAS tokens, soft delete, immutability (az-29)

Cost Check

  • Versioning and soft delete keep billing for old / deleted data
  • Lifecycle actions are free (class-change operations bill)
  • Early deletion of colder classes still bills the minimum duration

Security Check

  • Enforce public access prevention org-wide (storage.publicAccessPrevention)
  • Keep soft delete on for buckets holding irreplaceable data
  • Prefer short signed URL expiry (minutes, not days)

Do & Don't

  • Do Generate signed URLs server-side with short expiry
  • Do Pair versioning with a noncurrent-version lifecycle rule
  • Don’t Grant allUsers to serve a website (use a load balancer)
  • Don’t Lock a retention policy before you are sure of the period

Local Testing

  • Test lifecycle rules on a scratch bucket with small ages
  • Sign URLs locally with impersonated ADC
  • fake-gcs-server for upload / download flows

Production Checklist

  • Public access prevention enforced by org policy
  • Soft delete + versioning on critical data
  • Retention / Bucket Lock for compliance data
