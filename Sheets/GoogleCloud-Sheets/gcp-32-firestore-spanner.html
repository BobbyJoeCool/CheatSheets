Firestore, Spanner & Bigtable

Firestore documents & collections · queries & composite indexes · security rules · Spanner (global SQL) · Bigtable (wide-column) · choosing a NoSQL store

Non-Relational and Global Databases

Firestore is a serverless document database: documents in collections, real-time listeners, offline mobile sync and security rules for client access. Spanner is a horizontally scaling, strongly consistent relational database with SQL, available regionally or globally. Bigtable is a wide-column store for huge, low-latency key-range workloads like time series.

Key Points

  • Firestore queries need indexes; composite indexes are defined in firestore.indexes.json
  • Firestore with MongoDB compatibility accepts MongoDB drivers
  • Spanner capacity is set in processing units (100 PU minimum)
  • Bigtable row-key design decides performance

Firestore (Python)

from google.cloud import firestore
db = firestore.Client(database="(default)")
db.collection("orders").document("o-1001").set(
    {"customer": "c-42", "status": "open", "total": 59.9,
     "created": firestore.SERVER_TIMESTAMP})

q = (db.collection("orders")
       .where(filter=firestore.FieldFilter("customer", "==", "c-42"))
       .where(filter=firestore.FieldFilter("status", "==", "open"))
       .order_by("created", direction=firestore.Query.DESCENDING)
       .limit(20))
for doc in q.stream():
    print(doc.id, doc.to_dict())

@firestore.transactional
def close(tx, ref):
    tx.update(ref, {"status": "closed"})
close(db.transaction(), db.collection("orders").document("o-1001"))

Create Databases

gcloud firestore databases create --location=nam5 \
    --delete-protection --enable-pitr
gcloud spanner instances create shop-span --config=regional-us-central1 \
    --processing-units=100 --description="shop"
gcloud spanner databases create shop --instance=shop-span \
    --ddl="CREATE TABLE Orders (Id STRING(36), Total NUMERIC) PRIMARY KEY (Id)"
gcloud bigtable instances create metrics --display-name=metrics \
    --cluster-config=id=metrics-c1,zone=us-central1-b,nodes=1

Code Explained

SERVER_TIMESTAMP is set by the server at write time
Two equality filters plus order_by need a composite index
The transaction retries automatically on contention
Spanner starts at 100 processing units (a tenth of a node)

Cost Check

  • Firestore: per document read / write / delete + storage (free daily quota)
  • Spanner: per processing-unit hour + storage (no scale to zero)
  • Bigtable: per node-hour + storage

Security Check

  • Never ship Firestore rules that allow read, write: if true
  • Server code uses IAM (service accounts); clients use security rules + Firebase Auth
  • Turn on point-in-time recovery and delete protection

Limits & Quotas

  • Firestore document up to 1 MiB
  • About 1 sustained write per second per Firestore document
  • Spanner storage scales with compute: about 1 TB per 100 processing units

Do & Don't

  • Do Design Firestore documents around your queries
  • Do Spread Spanner primary keys (avoid monotonically increasing keys)
  • Don’t Write one Firestore document from many clients per second (counter hot spot)
  • Don’t Choose Spanner for a small app that fits Cloud SQL

Local Testing

  • gcloud emulators firestore start + FIRESTORE_EMULATOR_HOST
  • Spanner and Bigtable emulators via gcloud emulators
  • Firebase emulator suite tests security rules

Production Checklist

  • PITR and delete protection on
  • Security rules tested in CI
  • Indexes and schema managed as code
