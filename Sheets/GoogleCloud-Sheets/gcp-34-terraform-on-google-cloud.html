Terraform on Google Cloud

google & google-beta providers · google_project_service · Cloud Storage state backend · WIF authentication · terraform plan / apply · Cloud Foundation Toolkit modules

The Common IaC Choice

Terraform is the most widely used IaC tool for Google Cloud. The google provider covers GA features and google-beta adds preview ones. Store state in a Cloud Storage backend (with built-in locking and versioning), authenticate with ADC or Workload Identity Federation, and reuse Cloud Foundation Toolkit / Terraform Google modules. Enable APIs with google_project_service.

Key Points

  • Provider defaults (project, region) reduce repetition
  • terraform import / import blocks adopt existing resources
  • google_*_iam_member adds bindings; _iam_policy replaces the whole policy
  • Infrastructure Manager runs Terraform for you (sheet 35)

main.tf

terraform {
  required_providers {
    google = { source = "hashicorp/google", version = "~> 7.0" }
  }
  backend "gcs" { bucket = "acme-tfstate", prefix = "shop/prod" }
}
provider "google" {
  project = var.project
  region  = "us-central1"
}

resource "google_project_service" "run" {
  service = "run.googleapis.com"
}

resource "google_service_account" "api" {
  account_id = "api"
}

resource "google_cloud_run_v2_service" "api" {
  name       = "api"
  location   = "us-central1"
  ingress    = "INGRESS_TRAFFIC_INTERNAL_LOAD_BALANCER"
  depends_on = [google_project_service.run]
  template {
    service_account = google_service_account.api.email
    containers { image = var.image }
  }
}

Workflow

terraform init && terraform fmt -check && terraform validate
terraform plan -out=tfplan -var="project=shop-prod-4821"
terraform apply tfplan

Code Explained

The GCS backend stores state with locking
The API is enabled before the Cloud Run service is created
The service runs as its own service account
plan -out saves the exact plan that apply runs

AWS / Azure Equivalent

  • AWS CloudFormation, Terraform AWS provider (aws-34, aws-36)
  • Azure Bicep, Terraform azurerm (az-34, az-36)

Cost Check

  • Terraform CLI is free; HCP Terraform has paid tiers
  • State bucket costs are tiny
  • Infracost estimates plan cost in pull requests

Security Check

  • Turn on versioning for the state bucket and restrict access (state holds secrets)
  • Prefer _iam_member over authoritative _iam_policy resources
  • Run applies from CI with WIF, not personal credentials

Limits & Quotas

  • API quotas still apply during large applies (use -parallelism)
  • Org policy and project quotas can fail applies mid-way
  • One state per environment keeps plans small and fast

IAM Resource Types

SuffixBehavior
_iam_memberAdds one member (safe)
_iam_bindingOwns all members of one role
_iam_policyOwns the entire policy (dangerous)

Do & Don't

  • Do Pin provider major versions
  • Do Separate state per environment and per layer
  • Don’t Mix _iam_policy with other IAM resources on the same resource
  • Don’t Edit Terraform-managed resources in the console

Local Testing

  • terraform plan with impersonated ADC
  • tflint + Checkov in pre-commit
  • terraform test for module tests

Production Checklist

  • CI applies with WIF and approval gates
  • Versioned, locked-down state bucket
  • Drift checked by scheduled plans
