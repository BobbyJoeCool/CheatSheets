Cloud CDN & Certificates

Cloud CDN on an external Application Load Balancer · backend buckets · cache modes & invalidation · Certificate Manager · Google-managed certificates · Media CDN pointer

Edge Caching and TLS

Cloud CDN caches responses at Google's edge for external Application Load Balancers, from backend buckets (Cloud Storage) or backend services (VMs, GKE, Cloud Run via serverless NEGs). Cache modes decide what is cached. Certificate Manager issues and renews Google-managed certificates (DNS authorization works before cut-over) and maps them to load balancers.

Key Points

  • CACHE_ALL_STATIC caches common static types automatically
  • Signed URLs / cookies protect private cached content
  • Invalidations are rate-limited: prefer versioned file names
  • Media CDN targets large video and download workloads

Security Check

  • Keep the bucket private; serve through the load balancer
  • Use an SSL policy with TLS 1.2+ (MODERN or RESTRICTED profile)
  • Attach Cloud Armor to the backend

Static Site Behind a Global ALB With CDN

gcloud compute backend-buckets create site-be --gcs-bucket-name=acme-site \
    --enable-cdn --cache-mode=CACHE_ALL_STATIC --default-ttl=3600
gcloud compute url-maps create site-map --default-backend-bucket=site-be

gcloud certificate-manager dns-authorizations create shop-auth \
    --domain=shop.acme.com
gcloud certificate-manager certificates create shop-cert \
    --domains=shop.acme.com --dns-authorizations=shop-auth
gcloud certificate-manager maps create shop-map
gcloud certificate-manager maps entries create shop-entry --map=shop-map \
    --certificates=shop-cert --hostname=shop.acme.com

gcloud compute ssl-policies create modern-tls --profile=MODERN \
    --min-tls-version=1.2
gcloud compute target-https-proxies create site-proxy --url-map=site-map \
    --certificate-map=shop-map --ssl-policy=modern-tls
gcloud compute addresses create site-ip --global
gcloud compute forwarding-rules create site-https --global \
    --target-https-proxy=site-proxy --address=site-ip --ports=443

gcloud compute url-maps invalidate-cdn-cache site-map --path="/index.html"

Code Explained

The backend bucket serves the Cloud Storage site with CDN on
DNS authorization lets the certificate issue before DNS points at the LB
The certificate map attaches certificates by hostname
The forwarding rule exposes one global anycast IP on 443

AWS / Azure Equivalent

Cost Check

  • Cache egress and cache fill per GB, plus lookups
  • Forwarding rules bill hourly
  • Google-managed certificates through Certificate Manager have a small per-certificate fee beyond a free tier

Do & Don't

  • Do Version asset file names; invalidate only entry points
  • Do Use Certificate Manager with DNS authorization for zero-downtime cut-overs
  • Don’t Make the site bucket public
  • Don’t Use FORCE_CACHE_ALL on pages with user data

Local Testing

  • Preview the site locally with npx serve
  • curl -I shows age and cache headers after deploy
  • Test URL maps with gcloud compute url-maps validate

Production Checklist

  • Private bucket behind the ALB
  • Cloud Armor and modern SSL policy attached
  • HTTP → HTTPS redirect URL map
