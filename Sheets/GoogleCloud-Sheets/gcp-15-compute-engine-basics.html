Virtual Machines

Compute Engine runs VMs in a zone from a public or custom image. Pick a machine type from a family (general purpose E2 / N4 / C4, compute-optimized, memory-optimized, Arm-based C4A / T2A), attach Persistent or Hyperdisk volumes, a service account and network tags. Metadata carries startup scripts and config; OS Login ties SSH access to IAM.

Key Points

  • Custom machine types choose exact vCPU and memory on many families
  • Startup scripts run as root on every boot
  • Spot VMs are cheap but can be preempted any time
  • Shielded VM (Secure Boot, vTPM, integrity monitoring) is on by default for supported images

Security Check

  • No external IP: use IAP for SSH and Cloud NAT for egress
  • Attach a dedicated service account (not the default compute SA)
  • Enable OS Login and block project-wide SSH keys

Limits & Quotas

  • vCPU quotas per region and per family (often small on new projects)
  • External IP address quota per region
  • GPU quotas start at 0: request ahead

Create and Connect

gcloud compute instances create web-1 --zone=us-central1-a \
    --machine-type=e2-standard-2 \
    --image-family=debian-12 --image-project=debian-cloud \
    --boot-disk-size=20GB --boot-disk-type=pd-balanced \
    --subnet=app-usc1 --no-address \
    --service-account=web@shop-prod-4821.iam.gserviceaccount.com \
    --scopes=cloud-platform --tags=web --labels=env=prod,app=shop \
    --metadata=enable-oslogin=TRUE,block-project-ssh-keys=TRUE \
    --metadata-from-file=startup-script=startup.sh \
    --shielded-secure-boot

gcloud compute ssh web-1 --zone=us-central1-a --tunnel-through-iap
gcloud compute instances list --filter="labels.app=shop" \
    --format="table(name,zone.basename(),status,networkInterfaces[0].networkIP)"
gcloud compute instances stop web-1 --zone=us-central1-a
gcloud compute instances set-machine-type web-1 --zone=us-central1-a \
    --machine-type=e2-standard-4
gcloud compute instances start web-1 --zone=us-central1-a

startup.sh

#!/bin/bash
apt-get update && apt-get install -y nginx
systemctl enable --now nginx

Code Explained

--no-address keeps the VM private
cloud-platform scope + IAM roles is the modern pattern
OS Login grants SSH via IAM roles (roles/compute.osLogin)
Machine type changes need a stopped VM

AWS / Azure Equivalent

  • AWS EC2 instances, AMIs, user data (aws-15)
  • Azure Azure VMs, images, cloud-init (az-15)

Cost Check

  • Billed per second (1-minute minimum) for vCPU and memory
  • Stopped VMs still pay for disks and reserved IPs
  • Sustained use discounts apply automatically to N1 / N2 and some other families

Do & Don't

  • Do Use instance templates and MIGs for anything that should scale
  • Do Prefer image families for current OS images
  • Don’t Give VMs external IPs by default
  • Don’t Use the default compute service account with Editor

Local Testing

  • Test startup scripts in a local VM or container first
  • gcloud compute instances get-serial-port-output debugs boot
  • Packer builds custom images reproducibly

Production Checklist

  • Private VMs, IAP SSH, OS Login
  • Dedicated SA with least privilege
  • Built from a template in IaC, not by hand
