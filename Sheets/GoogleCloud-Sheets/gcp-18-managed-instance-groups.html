Managed Instance Groups

instance templates · regional MIGs · autoscaling policies · autohealing · rolling updates & canaries · stateful MIGs

Self-Healing, Scaling VMs

A managed instance group (MIG) runs identical VMs from an instance template. Regional MIGs spread across zones. The autoscaler adds and removes VMs on CPU, load balancer utilization, Cloud Monitoring metrics or schedules. Autohealing recreates VMs that fail a health check, and the updater rolls out new templates with surge, max-unavailable and canary versions.

Key Points

  • Instance templates are immutable: create a new one to change
  • Initial delay prevents autohealing during boot
  • Predictive autoscaling forecasts daily load patterns
  • Stateful MIGs keep disks and IPs for stateful apps

Template, Regional MIG, Autoscaling, Rollout

gcloud compute instance-templates create web-v2 --region=us-central1 \
    --machine-type=e2-standard-2 --subnet=app-usc1 --no-address \
    --image-family=debian-12 --image-project=debian-cloud \
    --service-account=web@shop-prod-4821.iam.gserviceaccount.com \
    --scopes=cloud-platform --metadata-from-file=startup-script=startup.sh

gcloud compute instance-groups managed create web-mig --region=us-central1 \
    --template=web-v1 --size=3 --health-check=hc-web --initial-delay=120
gcloud compute instance-groups managed set-named-ports web-mig \
    --region=us-central1 --named-ports=http:8080
gcloud compute instance-groups managed set-autoscaling web-mig \
    --region=us-central1 --min-num-replicas=3 --max-num-replicas=12 \
    --target-cpu-utilization=0.6 --cool-down-period=90

# Canary 10% on v2, then roll everyone
gcloud compute instance-groups managed rolling-action start-update web-mig \
    --region=us-central1 --version=template=web-v1 \
    --canary-version=template=web-v2,target=10% --max-surge=3
gcloud compute instance-groups managed rolling-action start-update web-mig \
    --region=us-central1 --version=template=web-v2 \
    --max-surge=3 --max-unavailable=0
gcloud compute instance-groups managed list-instances web-mig \
    --region=us-central1

Code Explained

The template is the blueprint for every VM
Autohealing waits 120 s before judging new VMs
The autoscaler keeps CPU near 60% between 3 and 12 VMs
The canary puts 10% on v2 before the full rollout

AWS / Azure Equivalent

  • AWS Launch templates + Auto Scaling groups (aws-18)
  • Azure Virtual Machine Scale Sets (az-18)

Cost Check

  • MIGs and the autoscaler are free; you pay for VMs
  • Mix Spot VMs in a separate MIG for cheap burst capacity
  • Scale-in settings stop flapping that wastes boot time

Limits & Quotas

  • Up to 2,000 instances per regional MIG (1,000 zonal)
  • Autoscaler needs a cool-down / initialization period
  • Regional vCPU quotas still cap scale-out

Do & Don't

  • Do Use regional MIGs for production
  • Do Bake apps into images for fast scale-out
  • Don’t Patch VMs in place inside a MIG
  • Don’t Set the autohealing initial delay shorter than boot time

Local Testing

  • Test the startup script on a single VM first
  • Watch updates: gcloud compute instance-groups managed describe
  • Load test with k6 / hey to see autoscaling react

Production Checklist

  • Regional MIG with health check + autohealing
  • Canary rollouts for new templates
  • Autoscaler bounds set within quota
