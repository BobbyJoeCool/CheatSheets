Sheet 19

Choosing Compute

Cloud Run vs GKE vs Compute Engine · Cloud Run functions · App Engine (legacy choice) · Batch · GKE Autopilot vs Standard · decision table

Which Compute Service

Default to Cloud Run for containers and HTTP or event-driven apps: it scales to zero and needs no cluster. Use Cloud Run functions for small event handlers, GKE (Autopilot first) when you need Kubernetes, Compute Engine for full OS control or licensed software, and Batch for job queues on VMs. App Engine still runs but new apps usually choose Cloud Run.

Key Points

  • Cloud Run functions are Cloud Functions now built on Cloud Run
  • GKE Autopilot bills per Pod resource requests
  • Cloud Run supports GPUs for inference
  • Batch schedules jobs on Compute Engine VMs (incl. Spot)

Same App, Three Ways

# Cloud Run: container → URL
gcloud run deploy api --source=. --region=us-central1 \
    --service-account=api@shop-prod-4821.iam.gserviceaccount.com

# GKE Autopilot: cluster + Kubernetes manifests
gcloud container clusters create-auto shop --region=us-central1
kubectl create deployment api \
    --image=us-central1-docker.pkg.dev/shop-prod-4821/apps/api:1.4.2
kubectl expose deployment api --port=80 --target-port=8080

# Compute Engine: VM running the container directly
gcloud compute instances create api-vm --zone=us-central1-a \
    --machine-type=e2-small --image-family=cos-stable \
    --image-project=cos-cloud --no-address \
    --metadata-from-file=user-data=cloud-init.yaml

# Batch: run 100 tasks on Spot VMs
gcloud batch jobs submit resize-images --location=us-central1 \
    --config=batch-job.json

Code Explained

--source builds the container with Cloud Build
Autopilot manages nodes; you manage workloads
Container-Optimized OS runs the container from cloud-init
Batch handles queuing, retries and VM lifecycle

AWS / Azure Equivalent

  • AWS Lambda, Fargate, EKS, EC2, Batch (aws-19)
  • Azure Functions, Container Apps, AKS, VMs (az-19)

Cost Check

  • Cloud Run: per vCPU-second, GiB-second and requests; scales to zero
  • GKE: cluster management fee (free tier covers one zonal / Autopilot cluster) + nodes or Pods
  • VMs bill while running, idle or not

Do & Don't

  • Do Start with Cloud Run; move only when you hit a real limit
  • Do Containerize so you can switch platforms later
  • Don’t Run a GKE cluster for one small app
  • Don’t Run idle VMs for spiky workloads

Local Testing

  • Same container runs locally with docker run
  • Cloud Code (VS Code / JetBrains) deploys to Cloud Run and GKE
  • kind / minikube for local Kubernetes

Production Checklist

  • Choice documented with reasons (ADR)
  • Container images built once, promoted across environments
  • Cost reviewed monthly per platform
