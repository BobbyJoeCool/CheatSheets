EAS Build

eas.json · build profiles · development / preview / production · eas build --platform · local builds · environment variables

Cloud Builds for Both Stores

EAS Build compiles your app on Expo's cloud machines (macOS for iOS, Linux for Android), manages signing credentials, and produces installable builds or store binaries. It works for Expo and bare React Native apps. Build profiles in eas.json define variants: a dev client for daily work, an internal preview, and production for the stores.

Output Types

  • iOS simulator .app, device .ipa (ad hoc / store)
  • Android .apk (sideload) or .aab (Play Store)
  • Internal distribution — install links / QR codes
  • --local builds on your own machine

eas.json + Commands

{
  "cli": { "version": ">= 16.0.0", "appVersionSource": "remote" },
  "build": {
    "development": {
      "developmentClient": true, "distribution": "internal",
      "env": { "APP_VARIANT": "development" },
      "ios": { "simulator": true }
    },
    "preview": {
      "distribution": "internal",
      "android": { "buildType": "apk" },
      "env": { "APP_VARIANT": "preview" }
    },
    "production": { "autoIncrement": true, "environment": "production" }
  },
  "submit": { "production": {} }
}

iOS

  • Simulator build: "ios": { "simulator": true }
  • Device builds need a provisioning profile — EAS manages it
  • Register ad hoc devices with eas device:create

Android

  • "android": { "buildType": "apk" } for sideloading
  • EAS creates and stores the keystore on the first build
  • eas build:run -p android installs the latest build

CLI

npm i -g eas-cli && eas login
eas build:configure                     # creates eas.json

eas build --profile development --platform ios
eas build -p android --profile preview
eas build -p all --profile production   # both stores
eas build -p ios --local                # on your Mac

eas env:create --name API_URL --value https://api.example.com \
  --environment production
eas build:list                          # history & artifacts
eas credentials                         # view/manage signing

Profile Keys

KeyEffect
developmentClientInclude expo-dev-client
distributioninternal or store
environmentWhich EAS env vars to use
autoIncrementBump build number each build
channelEAS Update channel for OTA
extendsInherit another profile

Environment Variables

KindNotes
EXPO_PUBLIC_*Inlined into JS bundle (not secret)
EAS env secretBuild-time only, hidden in logs
env in profilePlain values per profile
.env filesLocal dev; EAS ignores unless uploaded

⚠ Common Mistakes

  • Putting API keys in EXPO_PUBLIC_ variables thinking they're secret; they're in the bundle
  • Building production with distribution: internal; the stores reject ad hoc builds
  • Forgetting a native rebuild after adding a native library; OTA updates can't add native code

✓ Tips & Best Practices

  • Use APP_VARIANT plus app.config.ts so dev and prod apps install side by side
  • Run eas build --local to debug failing cloud builds faster
  • Cache-friendly: pin Node and package manager versions in eas.json
