Apps in Spatial Computing

React Native visionOS is Callstack's fork that builds native visionOS apps: translucent glass windows, multiple windows, and immersive spaces you define in SwiftUI and open from JS. It lags core (latest 0.79.x in Oct 2026). Without it, your iPad app can still run on Vision Pro in compatibility mode, but it looks like a flat iPad window.

Setup

  • npx @callstack/react-native-visionos@latest init MyApp
  • Entry point is App.swift (SwiftUI), not AppDelegate
  • CLI: run-visionos, build-visionos, log-visionos
  • UIApplicationSupportsMultipleScenes = true for spaces

SwiftUI Entry + Immersive Space

// visionos/MyApp/App.swift
@main
struct MyApp: App {
  @UIApplicationDelegateAdaptor var delegate: AppDelegate
  @State private var style: ImmersionStyle = .mixed

  var body: some Scene {
    RCTMainWindow(moduleName: "MyApp")         // your RN UI
    ImmersiveSpace(id: "Solar") {
      SolarSystemView()                         // RealityKit content
    }
    .immersionStyle(selection: $style, in: .mixed, .progressive, .full)
  }
}

iOS

  • Most iPad apps run unmodified on visionOS
  • RN visionOS forks iOS — UIKit code mostly ports
  • visionos_hoverEffect adds gaze hover effects

Android

  • Android XR runs Android apps in floating panels
  • Meta Quest (Horizon OS) runs Android apps too
  • Spatial features need native Jetpack XR code

Opening It From React Native

import { XR } from '@callstack/react-native-visionos'

async function enterSpace() {
  if (!XR.supportsMultipleScenes) return
  try {
    await XR.requestSession('Solar', { planet: 'earth' })
  } catch (e) {
    Alert.alert('Could not open space', String(e))
  }
}
const exitSpace = () => XR.endSession()

// Hover effect (eye / pointer highlight)
<Pressable style={{ cursor: 'pointer' }} onPress={enterSpace}>
  <Text>Enter</Text>
</Pressable>

⚠ Common Mistakes

  • Forgetting UIApplicationSupportsMultipleScenes; requestSession throws
  • Mismatched IDs between ImmersiveSpace(id:) and requestSession('…')
  • Expecting RN components to render in 3D; immersive content is SwiftUI/RealityKit

✓ Tips & Best Practices

  • Ship the iPad build first; move to the fork only if you need spaces or the glass look
  • Use cursor: 'pointer' on interactive elements so gaze highlighting works
  • Keep 3D scenes in Swift and drive them with data passed from requestSession
