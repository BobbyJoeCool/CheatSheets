Sheet 08

Context, Reducers & Custom Hooks

createContext · useContext · providers · useReducer · custom hooks · rules of hooks

React Refresher: Sharing Logic

Context passes a value deep into the tree without prop drilling; theme, auth user, and locale are typical. useReducer handles state with several related transitions. Custom hooks are functions starting with use that bundle hooks into a reusable piece. Together they cover most app state before you reach for a library.

When to Use What

  • Prop passing — 1–2 levels deep
  • Context — app-wide, rarely changing values
  • useReducer — many actions on one state object
  • Library (Zustand, Redux) — frequent global updates

Auth Context + Reducer + Hook

type State = { user: User | null; loading: boolean }
type Action = { type: 'login'; user: User } | { type: 'logout' }

function reducer(state: State, action: Action): State {
  switch (action.type) {
    case 'login':  return { user: action.user, loading: false }
    case 'logout': return { user: null, loading: false }
  }
}

type Ctx = { state: State; dispatch: Dispatch<Action> }
const AuthContext = createContext<Ctx | null>(null)

export function AuthProvider({ children }: { children: React.ReactNode }) {
  const [state, dispatch] =
    useReducer(reducer, { user: null, loading: true })
  return <AuthContext value={{ state, dispatch }}>{children}</AuthContext>
}

export function useAuth() {
  const ctx = useContext(AuthContext)
  if (!ctx) throw new Error('useAuth must be inside AuthProvider')
  return ctx
}

Notes

Discriminated union — exhaustive, typed actions
<AuthContext value> — React 19 renders context directly as provider
null default — lets the hook detect a missing provider
useAuth — custom hook hides the context plumbing
Wrap the root layout in <AuthProvider>

iOS

  • iOS can terminate a backgrounded app silently — context is lost
  • Keep tokens in the Keychain (SecureStore), not only context
  • Test cold start: swipe the app away in the switcher

Android

  • Low-RAM devices kill background processes often
  • Test with Developer options → Don't keep activities
  • Rehydrate providers from storage before rendering screens

⚠ Common Mistakes

  • Putting rapidly changing values (scroll position, timers) in context; every consumer re-renders
  • Calling a custom hook conditionally; hooks inside it still follow the rules of hooks
  • Forgetting the provider, so consumers silently get the default value

✓ Tips & Best Practices

  • Throw a clear error in the custom hook when the provider is missing
  • Keep reducers pure; do async work in event handlers, then dispatch
  • Name hooks useX so lint rules check them

Quick Summary

  • createContext / use — share values
  • useReducer — action-based state
  • Custom hook — reusable useX logic
  • Split contexts — fewer re-renders
