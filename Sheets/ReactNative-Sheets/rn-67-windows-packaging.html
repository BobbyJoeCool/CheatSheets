Packaging & Distributing on Windows

MSIX · Release builds · certificates · Microsoft Store · sideloading · deploy

Shipping a Windows App

Windows apps built with RNW are packaged as MSIX, the modern Windows installer format with clean install/uninstall and automatic updates. You produce a Release build with the JS bundle embedded, sign the package with a certificate, and then publish to the Microsoft Store (which re-signs it) or distribute it directly (sideloading, App Installer, or enterprise tools like Intune).

Signing Rules

  • Store submissions: Microsoft signs for you
  • Direct distribution: sign with a trusted code-signing cert
  • Self-signed certs need manual trust on each PC
  • Publisher in the manifest must match the certificate subject

Release Builds and Packaging

# Release build with bundled JS
npx react-native run-windows --release --arch x64
npx react-native run-windows --release --no-launch --no-deploy

# Visual Studio → right-click MyApp.Package → Publish →
#   Create App Packages → Microsoft Store or Sideloading
# Output: AppPackages\MyApp_1.0.0.0_x64.msixbundle

# Sign for sideloading (Windows SDK signtool)
signtool sign /fd SHA256 /a /f MyCert.pfx /p <password> MyApp.msix

# Install locally
Add-AppxPackage .\MyApp_1.0.0.0_x64.msix

# Package.appxmanifest essentials:
#   <Identity Name="Acme.MyApp" Publisher="CN=Acme" Version="1.0.0.0" />
#   <Capabilities> <Capability Name="internetClient" /> </Capabilities>

Notes

--release — embeds bundle, disables dev tools
--no-launch --no-deploy — build only (CI)
.msixbundle — multiple architectures in one file
signtool — part of the Windows SDK
Add-AppxPackage — PowerShell install

iOS

  • Microsoft Store ↔ App Store: the store signs for you
  • MSIX ↔ .ipa
  • Package identity ↔ bundle ID

Android

  • Sideloading MSIX ↔ sideloading APK
  • Store listing ↔ Play listing
  • Version must increase on each submission

⚠ Common Mistakes

  • Shipping a Debug build that expects Metro; it shows a red screen on users' PCs
  • Mismatched Publisher and certificate subject; package installation fails
  • Forgetting capabilities (e.g. webcam); APIs fail with access denied

✓ Tips & Best Practices

  • Use the Store for consumer apps to get signing and updates for free
  • Bump the four-part version on every package so updates install
  • Automate packaging in CI with msbuild and the .Package project
