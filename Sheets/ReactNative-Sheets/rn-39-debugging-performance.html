Debugging & Performance

React Native DevTools · console & breakpoints · Performance panel · Hermes profiling · LogBox · re-render tips

Finding Bugs and Jank

React Native DevTools (press j in Metro) is the official debugger: Console, Sources with breakpoints, Memory, Network, the Performance panel, and React's Components and Profiler tabs. LogBox shows warnings and errors in the app. For native crashes use Xcode and Android Studio (Logcat). Performance work focuses on dropped frames, slow startup, and extra re-renders.

Recent Changes

  • Remote JS debugging (Chrome) is gone; use RN DevTools
  • InteractionManager removed in 0.87 → requestIdleCallback
  • DevTools emulates light/dark mode (0.86)
  • Network panel uses CDP; old interceptors deprecated

Debugging Toolkit

console.log('user', user)          // DevTools Console
console.warn('slow path')          // yellow LogBox
console.error('bad state')         // red LogBox
debugger                           // breakpoint when DevTools open

LogBox.ignoreLogs(['Require cycle:'])   // silence a known warning
LogBox.ignoreAllLogs()                  // demos only

// Measure work
performance.mark('load-start')
await loadData()
performance.measure('load', 'load-start')

// Defer non-urgent work (replaces InteractionManager)
requestIdleCallback(() => prefetchImages())

// Find re-renders: React DevTools Profiler → "Highlight updates"
// Hermes CPU profile: DevTools → Performance → Record

// Release-like JS speed on Android without a full release build
// npx react-native run-android --mode debugOptimized

Notes

debugger — pauses when DevTools is attached
LogBox.ignoreLogs — match by substring or regex
performance.mark/measure — Web Performance API
requestIdleCallback — run when JS is idle
debugOptimized — faster JS, still debuggable

iOS

  • Xcode Instruments: Time Profiler, Allocations
  • Native logs: Console.app or xcrun simctl spawn booted log stream
  • Release test: npx expo run:ios --configuration Release

Android

  • Logs: adb logcat *:S ReactNative:V ReactNativeJS:V
  • Android Studio Profiler or Perfetto for traces
  • Release test: npx expo run:android --variant release

Common Fixes

SymptomFix
Laggy listsFlashList, memoized rows, fixed heights
Janky animationsNative driver / Reanimated
Slow startupLazy-load screens, fewer startup requires
Big bundleRemove heavy deps, check with Expo Atlas
Frequent re-rendersReact Compiler, store selectors
Large imagesResize, use expo-image

⚠ Common Mistakes

  • Judging performance in a debug build; dev mode is much slower, so profile release or debugOptimized
  • Leaving console.log in hot paths in production; strip with a Babel plugin
  • Calling LogBox.ignoreAllLogs() permanently and hiding real problems

✓ Tips & Best Practices

  • Use Expo Atlas (EXPO_ATLAS=true npx expo start) to see what's in your bundle
  • Add Sentry or Crashlytics before your first release
  • Check the React Profiler "why did this render" info before reaching for memo
