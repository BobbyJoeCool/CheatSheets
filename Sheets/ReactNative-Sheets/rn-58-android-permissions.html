The Android Permission Model

Every permission must be declared in AndroidManifest.xml. Normal permissions (internet, vibrate) are granted at install. Dangerous ones (camera, location, contacts, notifications on Android 13+) also need a runtime request. Users can deny, deny permanently ("Don't ask again"), or grant once. PermissionsAndroid is the built-in API; Expo modules wrap the same flow.

Version Changes

  • Android 13 (API 33): POST_NOTIFICATIONS runtime permission
  • Android 13: granular READ_MEDIA_IMAGES / VIDEO
  • Android 14: partial photo access (READ_MEDIA_VISUAL_USER_SELECTED)
  • Background location must be requested separately

Manifest + Runtime Request

// AndroidManifest.xml (or app.json "android.permissions")
// <uses-permission android:name="android.permission.CAMERA" />
// <uses-permission android:name="android.permission.POST_NOTIFICATIONS" />

import { PermissionsAndroid, Platform, Linking } from 'react-native'

async function requestCamera(): Promise<boolean> {
  if (Platform.OS !== 'android') return true
  const result = await PermissionsAndroid.request(
    PermissionsAndroid.PERMISSIONS.CAMERA,
    { title: 'Camera access', message: 'Scan receipts to add expenses.',
      buttonPositive: 'OK', buttonNegative: 'Not now' })
  if (result === PermissionsAndroid.RESULTS.GRANTED) return true
  if (result === PermissionsAndroid.RESULTS.NEVER_ASK_AGAIN) {
    Linking.openSettings()
  }
  return false
}

const already = await PermissionsAndroid.check(
  PermissionsAndroid.PERMISSIONS.ACCESS_FINE_LOCATION)

const results = await PermissionsAndroid.requestMultiple([
  PermissionsAndroid.PERMISSIONS.ACCESS_FINE_LOCATION,
  PermissionsAndroid.PERMISSIONS.ACCESS_COARSE_LOCATION,
])

Notes

Rationale object — shown if the user denied once before
NEVER_ASK_AGAIN — only Settings can change it now
check — current status, no dialog
requestMultiple — returns a map of results
Expo: android.permissions and blockedPermissions in app.json

iOS

  • No manifest list — Info.plist usage strings instead
  • One prompt; after that, only Settings
  • No rationale API — explain before asking

Android

  • PermissionsAndroid.request(perm, rationale)
  • 'never_ask_again' → Linking.openSettings()
  • One-time grants for location, camera and mic (11+)

⚠ Common Mistakes

  • Requesting a permission that isn't in the manifest; the request returns denied instantly
  • Asking for background location in the same request as foreground; Android 11+ requires separate steps
  • Leaving unused permissions merged in from libraries; Play flags them, so remove with tools:node="remove"

✓ Tips & Best Practices

  • Use Expo's blockedPermissions to strip permissions added by dependencies
  • Prefer the Photo Picker (no permission) over READ_MEDIA_* for picking images
  • Check aapt dump permissions app.apk to see the final merged list

Quick Summary

  • Manifest — declare every permission
  • PermissionsAndroid.request — runtime prompt
  • never_ask_again — send to Settings
  • POST_NOTIFICATIONS — Android 13+
