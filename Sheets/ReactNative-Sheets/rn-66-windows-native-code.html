Windows Native Modules & APIs

C++ / C# modules · WinRT APIs · WinAppSDK · Fabric on Windows · platform checks · Windows-only components

Calling Windows APIs

On Windows, Turbo Native Modules are written in C++/WinRT (or C#) using attribute macros, and share the same TypeScript spec + Codegen flow as iOS and Android. codegen-windows generates a spec struct; referencing it as ModuleSpec makes the compiler check your implementation against the spec. From native code you can call any WinRT or Windows App SDK API.

Workflow

C++ Turbo Module

// windows/testlib/testlib.h
#include "codegen/NativeTestlibSpec.g.h"
#include "NativeModules.h"

namespace winrt::testlib {
REACT_MODULE(Testlib)
struct Testlib {
  using ModuleSpec = testlibCodegen::TestlibSpec;   // compile-time check

  REACT_INIT(Initialize)
  void Initialize(React::ReactContext const &reactContext) noexcept {
    m_context = reactContext;
  }

  REACT_SYNC_METHOD(multiply)
  double multiply(double a, double b) noexcept { return a * b; }

  REACT_METHOD(getDeviceName)
  void getDeviceName(React::ReactPromise<std::string> promise) noexcept {
    promise.Resolve(winrt::to_string(
      winrt::Windows::Security::ExchangeActiveSyncProvisioning::
        EasClientDeviceInformation().FriendlyName()));
  }
 private:
  React::ReactContext m_context;
};
}
// ReactPackageProvider.cpp:  AddAttributedModules(packageBuilder, true);

Notes

REACT_MODULE — exposes the struct as a module
ModuleSpec — fails to compile if it drifts from the TS spec
REACT_INIT — runs once when created
REACT_SYNC_METHOD / REACT_METHOD — sync / async
ReactPromise<T> — resolve or reject async calls

iOS

  • One TS spec generates iOS, Android and Windows bindings
  • Pure C++ Turbo Modules can be shared with iOS
  • iOS adds C++ through Objective-C++

Android

  • Pure C++ modules need CMake + JNI registration on Android
  • Or implement the same spec in Kotlin
  • Share C++ logic, keep platform UI separate

⚠ Common Mistakes

  • Removing the ModuleSpec line to "fix" compile errors; the JS and native APIs silently drift
  • Forgetting to add new source files to the .vcxproj; they're not compiled
  • Calling UI APIs from a background thread; dispatch to the UI thread

✓ Tips & Best Practices

  • Start from the native module sample library and copy its structure
  • Keep the TS spec shared across iOS, Android, and Windows for one JS API
  • Use C++/WinRT projections to call Windows APIs without COM boilerplate

Quick Summary

  • TS spec + codegen-windows — same contract
  • REACT_MODULE / REACT_METHOD — C++ macros
  • ModuleSpec — compile-time checking
  • WinRT — full Windows API access
