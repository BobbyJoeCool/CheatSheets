Testing Components in Node

Unit and component tests run in Jest on Node, with no simulator. React Native Testing Library (RNTL) renders components to a test tree and queries them the way users perceive them: by text, role, and label. Native modules don't exist in Node, so you mock them; the jest-expo preset mocks the Expo SDK for you.

Setup

  • Expo: npx expo install jest-expo jest @testing-library/react-native
  • "jest": { "preset": "jest-expo" } in package.json
  • Bare: preset: 'react-native' (ships with the template)
  • RNTL 13+ includes the Jest matchers

A Component Test

import { render, screen, userEvent }
  from '@testing-library/react-native'
import { LoginForm } from './LoginForm'

jest.mock('expo-secure-store', () => ({ setItemAsync: jest.fn() }))

test('shows an error for a bad password', async () => {
  const onLogin = jest.fn().mockRejectedValue(new Error('Invalid'))
  const user = userEvent.setup()
  render(<LoginForm onLogin={onLogin} />)

  await user.type(screen.getByLabelText('Email'), 'a@b.com')
  await user.type(screen.getByLabelText('Password'), 'nope')
  await user.press(screen.getByRole('button', { name: 'Sign in' }))

  expect(onLogin).toHaveBeenCalledWith('a@b.com', 'nope')
  expect(await screen.findByText('Invalid')).toBeOnTheScreen()
  expect(screen.queryByText('Welcome')).not.toBeOnTheScreen()
})

Notes

userEvent — realistic press/type sequences (async)
getByLabelText — uses accessibilityLabel
getByRole('button', { name }) — role + accessible name
findBy* — waits for async UI
queryBy* — returns null; use for "not present"

iOS

  • jest-expo/ios preset: Platform.OS is 'ios'
  • It resolves .ios.tsx files
  • Tests run in Node — no Simulator needed

Android

  • jest-expo/android preset: Platform.OS is 'android'
  • jest-expo/universal runs iOS, Android and web together
  • Mock native modules jest-expo doesn't cover

Useful Matchers

⚠ Common Mistakes

  • Querying by testID first; it doesn't test what users see, so prefer role and text
  • Not awaiting userEvent calls; assertions run before state updates
  • Mocking React Native itself wholesale; mock only the native module you need

✓ Tips & Best Practices

  • Wrap renders in a helper that provides your theme, query client, and navigation
  • Use jest.useFakeTimers() for debounces and animations
  • Test hooks with renderHook from RNTL
