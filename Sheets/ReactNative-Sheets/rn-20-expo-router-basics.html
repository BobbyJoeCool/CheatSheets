Expo Router Basics

app/ file routes · index · [id] dynamic routes · <Link> · router.push() · useLocalSearchParams · +not-found

Files Become Screens

Expo Router maps files in app/ to routes, like Next.js does on the web. Every screen gets a URL, so deep links and web support come for free. Navigate declaratively with <Link> or imperatively with router. Dynamic segments use brackets: app/user/[id].tsx matches /user/42. It's built on native navigators (native stack, tabs) under the hood.

File Naming

  • index.tsx → the folder's / route
  • [id].tsx → one dynamic segment
  • [...rest].tsx → catch-all
  • +not-found.tsx → unmatched URLs; _layout.tsx → wrapper

Routes and Navigation

// app/index.tsx  →  "/"
import { Link, router } from 'expo-router'

export default function Home() {
  return (
    <View>
      <Link href="/settings">Settings</Link>
      <Link href={{ pathname: '/user/[id]', params: { id: '42' } }}>
        View profile
      </Link>
      <Link href="/about" asChild>
        <Pressable><Text>About</Text></Pressable>
      </Link>
      <Button title="Go" onPress={() => router.push('/user/7?tab=posts')} />
    </View>
  )
}

// app/user/[id].tsx  →  "/user/42"
import { useLocalSearchParams, Stack } from 'expo-router'
export default function User() {
  const { id, tab } = useLocalSearchParams<{ id: string; tab?: string }>()
  return <>
    <Stack.Screen options={{ title: `User ${id}` }} />
    <Text>Tab: {tab ?? 'overview'}</Text>
  </>
}

Notes

href object — typed params with pathname
asChild — pass navigation to a custom pressable
Query strings arrive as params too (tab)
<Stack.Screen options> inside a screen — set its header
Typed routes — enable experiments.typedRoutes

iOS

  • The Stack uses native navigation — swipe-back works by default
  • headerLargeTitle for collapsing large titles
  • router.back() matches the swipe gesture

Android

  • System back calls router.back() automatically
  • Default push animation follows the Android version
  • Back on the first screen exits the app

⚠ Common Mistakes

  • Forgetting the default export; a route file without one is ignored with a warning
  • Using useGlobalSearchParams everywhere; it re-renders screens in the background on every change
  • Treating params as numbers; they're always strings, so convert them

✓ Tips & Best Practices

  • Turn on typed routes to catch broken hrefs at compile time
  • Keep non-route files (components, utils) outside app/
  • Use router.replace after login so Back doesn't return to the login screen
