iOS Extensions, Widgets & Live Activities

app extensions · WidgetKit · Live Activities · App Groups · App Clips · expo-widgets

Beyond the Main App

Widgets, Live Activities, share extensions, and App Clips are separate targets written in Swift/SwiftUI that ship inside your app. They can't run React Native directly, so they share data with the app through an App Group container. Expo's expo-widgets (iOS widgets stable since SDK 56) and the @bacons/apple-targets plugin generate these targets from config so CNG doesn't wipe them.

How Data Flows

  • App writes to shared UserDefaults(suiteName:) / files
  • Widget reads on its timeline and renders SwiftUI
  • WidgetCenter.shared.reloadAllTimelines() refreshes
  • Live Activities update locally or via ActivityKit push

Widget + Shared Data

// targets/widget/Widget.swift (SwiftUI, WidgetKit)
struct Entry: TimelineEntry { let date: Date; let steps: Int }

struct Provider: TimelineProvider {
  func placeholder(in: Context) -> Entry { Entry(date: .now, steps: 0) }
  func getSnapshot(in: Context, completion: @escaping (Entry) -> Void) {
    completion(load()) }
  func getTimeline(in: Context,
      completion: @escaping (Timeline<Entry>) -> Void) {
    completion(Timeline(entries: [load()], policy: .after(.now + 900))) }
  func load() -> Entry {
    let d = UserDefaults(suiteName: "group.com.acme.myapp")
    return Entry(date: .now, steps: d?.integer(forKey: "steps") ?? 0)
  }
}

@main struct StepsWidget: Widget {
  var body: some WidgetConfiguration {
    StaticConfiguration(kind: "Steps", provider: Provider()) { e in
      Text("\(e.steps) steps").font(.title)
    }.supportedFamilies([.systemSmall, .accessoryCircular])
  }
}

From React Native

Write shared data to the App Group from JS with expo-widgets or a small native module
Then call WidgetCenter.shared.reloadAllTimelines() natively
@bacons/apple-targets — targets live in targets/*/ with expo-target.config.js
Set appleTeamId in the plugin options
Both app and widget list group.com.acme.myapp in entitlements

iOS

  • Extensions are separate targets — add via a config plugin
  • Share data through an App Group (group.com.example)
  • Widgets have tight memory limits

Android

  • Home-screen widgets use AppWidgetProvider / Glance
  • react-native-android-widget renders widgets from JS
  • updatePeriodMillis minimum is 30 minutes

⚠ Common Mistakes

  • Adding a target in Xcode inside a CNG project; prebuild deletes it, so generate it from config
  • Mismatched App Group IDs between app and extension; the widget reads nothing
  • Expecting a widget to refresh every second; WidgetKit budgets updates

✓ Tips & Best Practices

  • Keep widget data small and pre-formatted so the extension stays lightweight
  • Use Live Activities for deliveries, timers, and scores instead of frequent pushes
  • Try expo-widgets first; drop to @bacons/apple-targets for other extension types

Quick Summary
