iOS Permissions & Entitlements

NS*UsageDescription keys · permission prompts · entitlements · capabilities · Background Modes · App Transport Security

Asking iOS for Access

iOS requires a usage description string in Info.plist for every protected resource; if it's missing, the app crashes the moment you touch the API, and App Review rejects vague text. Entitlements turn on capabilities like push, App Groups, Sign in with Apple, and HealthKit; they must also be enabled on your App ID. You get one system prompt per permission; after a denial, only Settings can change it.

Rules

  • Usage text must explain *why*, specifically
  • Ask in context, right before you need it
  • ATTrackingManager prompt required before tracking (ATT)
  • Background work needs a declared Background Mode

Expo Config (generates Info.plist + entitlements)

{ "expo": { "ios": {
  "infoPlist": {
    "NSCameraUsageDescription": "Scan receipts to add expenses.",
    "NSPhotoLibraryUsageDescription": "Attach photos to your notes.",
    "NSLocationWhenInUseUsageDescription": "Show stores near you.",
    "NSMicrophoneUsageDescription": "Record voice memos.",
    "NSFaceIDUsageDescription": "Unlock your vault with Face ID.",
    "UIBackgroundModes": ["remote-notification", "audio"],
    "ITSAppUsesNonExemptEncryption": false
  },
  "entitlements": {
    "com.apple.security.application-groups": ["group.com.acme.myapp"]
  },
  "usesAppleSignIn": true,
  "associatedDomains": ["applinks:example.com"]
} } }

Notes

infoPlist — merged into ios/MyApp/Info.plist
Many Expo modules add these via plugin options instead
UIBackgroundModes — audio, location, fetch, push
ITSAppUsesNonExemptEncryption — skips export compliance prompt
entitlements — must match capabilities on the App ID

iOS

  • A missing usage string crashes on request
  • Photos can be 'limited' — handle partial access
  • Ask "When In Use" before upgrading to "Always"

Android

  • Declare in the manifest, request at runtime
  • No usage strings — explain in your own UI first
  • The system photo picker needs no permission (13+)

⚠ Common Mistakes

  • Missing a usage string; the app crashes on first use and reviewers see it immediately
  • Writing "This app needs camera access"; Apple rejects strings that don't say why
  • Requesting "Always" location up front; ask When In Use first, upgrade later

✓ Tips & Best Practices

  • Use xcrun simctl privacy booted reset all com.acme.myapp to see prompts again
  • Pre-explain with your own screen, then call the system prompt
  • Keep entitlements in config so EAS syncs capabilities to your App ID

Quick Summary
