End-to-End Testing

Maestro flows · Detox · testID · EAS Workflows · device farms · flaky test tips

Testing the Real App

End-to-end tests drive a built app on a simulator or device. Maestro uses simple YAML flows and works with any app (it reads the accessibility tree). Detox is a JavaScript gray-box framework that syncs with React Native's internals to reduce flakiness. Both find elements by testID, text, or accessibility label.

Choosing

  • Maestro — fastest to start, YAML, Maestro Cloud
  • Detox — JS tests, deep RN sync, more setup
  • Appium — cross-tech, WebDriver ecosystem
  • EAS Workflows can run Maestro on every build

Maestro Flow

# .maestro/login.yaml
appId: com.acme.myapp
---
- launchApp:
    clearState: true
- tapOn: "Email"
- inputText: "test@example.com"
- tapOn:
    id: "password-input"          # testID
- inputText: "hunter2"
- tapOn: "Sign in"
- assertVisible: "Welcome back"
- scrollUntilVisible:
    element: "Settings"
- takeScreenshot: home

iOS

  • Tests run against a Simulator build
  • testID becomes the accessibility identifier
  • Pre-grant permissions in the test config

Android

  • testID becomes the view's tag / resource-id
  • Detox needs the androidTest APK as well
  • Disable emulator animations for stable runs

Detox Test

// e2e/login.test.ts
describe('Login', () => {
  beforeAll(async () => { await device.launchApp({ newInstance: true }) })

  it('signs in', async () => {
    await element(by.id('email-input')).typeText('test@example.com')
    await element(by.id('password-input')).typeText('hunter2')
    await element(by.text('Sign in')).tap()
    await expect(element(by.text('Welcome back'))).toBeVisible()
  })
})

// Run:
// maestro test .maestro/
// detox build -c ios.sim.release && detox test -c ios.sim.release

⚠ Common Mistakes

  • Testing against a debug build with Metro; timing differs from release and adds flakiness
  • Using visible copy as the only selector; text changes break tests, add testIDs
  • Sharing state between tests; reset with clearState / newInstance

✓ Tips & Best Practices

  • Start with 3–5 critical flows (sign in, purchase, onboarding) before broad coverage
  • Run E2E on PRs with EAS Workflows or a device farm
  • Use maestro studio to inspect the element tree interactively

Quick Summary

  • Maestro — YAML flows, quick start
  • Detox — JS gray-box testing
  • testID — stable selectors
  • Release builds — realistic runs
