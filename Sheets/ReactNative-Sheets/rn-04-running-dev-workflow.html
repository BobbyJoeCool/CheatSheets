Sheet 04

Running & Dev Workflow

Metro bundler · Fast Refresh · Expo Go · development builds · dev menu · npx expo start · run:ios / run:android

The Inner Loop

Metro bundles your JS and serves it to the app over the network. Fast Refresh swaps edited components in place and keeps state. You run code in Expo Go (a prebuilt sandbox app), in a development build (your own app with expo-dev-client), or in a bare debug build from Xcode/Gradle. Native code changes need a rebuild; JS changes don't.

Which Runner?

  • Expo Go — fastest start, only Expo SDK modules
  • Dev build — any native library, your own icon & config
  • Release build — no dev menu, optimized bundle
  • A new SDK's Expo Go can lag the stores; get it via CLI or eas go

Commands

npx expo start                 # Metro + QR code
npx expo start --clear         # reset Metro cache
npx expo start --tunnel        # device on another network

npx expo run:ios               # prebuild + build + install
npx expo run:ios --device      # pick a connected iPhone
npx expo run:android --variant release

npx expo install expo-dev-client   # turn into a dev build

# Bare CLI
npx react-native start --reset-cache
npx react-native run-ios --simulator "iPhone 17"
npx react-native run-android --mode debugOptimized

Notes

--clear — fixes stale bundles after config changes
--tunnel — uses ngrok; slower but works across networks
run:ios — compiles native code; needed after native changes
expo-dev-client — adds the dev launcher to your own build
debugOptimized — Android build type with faster JS

iOS

  • npx expo run:ios builds and opens the Simulator
  • Dev menu: Cmd+D in the Simulator, shake on a device
  • The Simulator reaches Metro on localhost directly

Android

  • npx expo run:android installs on the emulator or USB device
  • Dev menu: Cmd+M / Ctrl+M in the emulator, shake on a device
  • USB devices reach Metro via adb reverse tcp:8081 tcp:8081

⚠ Common Mistakes

  • Expecting Fast Refresh to pick up native or app.json changes; those need a rebuild
  • Phone and computer on different Wi-Fi networks, so the bundle never loads; use --tunnel or USB
  • Leaving a stale Metro running on port 8081 from another project

✓ Tips & Best Practices

  • Add // @refresh reset to a file to force a remount on every edit
  • Create one dev build per native change, then iterate on JS for days
  • Use adb reverse tcp:8081 tcp:8081 for an Android device over USB

Quick Summary

  • Metro — JS bundler & dev server
  • Fast Refresh — keeps state across edits
  • Expo Go vs dev build — SDK-only vs any native
  • r / j / m — reload, DevTools, menu
