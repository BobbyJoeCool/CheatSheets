iOS Code Signing & Provisioning

Apple Developer account · bundle identifier · certificates · provisioning profiles · automatic signing · EAS credentials

Proving Who Built the App

Every iOS build that runs on a device is code signed. Signing ties together your team, a certificate (your identity), an App ID (bundle identifier + capabilities), and a provisioning profile (which devices or store the build is allowed for). Xcode's automatic signing or EAS credentials can create and manage all of these for you.

Accounts

  • Free Apple ID — run on your own devices, 7-day profiles
  • Developer Program ($99/yr) — TestFlight, App Store, push
  • Organization accounts need a D-U-N-S number
  • Team ID — 10 characters, used in AASA files and entitlements

Managing Credentials

# EAS manages certs + profiles for you
eas credentials                        # interactive manager
eas build -p ios --profile production  # creates or reuses credentials
eas device:create                      # register a test device (ad hoc)

# See what's installed locally
security find-identity -v -p codesigning
ls ~/Library/Developer/Xcode/UserData/Provisioning\ Profiles

# Inspect a profile
security cms -D -i embedded.mobileprovision

# fastlane match (team sharing alternative)
fastlane match appstore
fastlane match development

Notes

eas credentials — view, download, or revoke
device:create — adds UDIDs for internal builds
find-identity — certificates in your keychain
cms -D — decode a profile to check devices/entitlements
match — store certs in a private git repo

iOS

  • Certificate + provisioning profile + bundle ID must match
  • Manage them with eas credentials
  • Distribution certificates are limited per account

Android

  • One upload keystore — no profiles or device lists
  • Play App Signing holds the real signing key
  • Lost upload key → request a reset in Play Console

⚠ Common Mistakes

  • Changing the bundle identifier after setup; profiles, push keys, and App Store records all point to the old one
  • Enabling a capability in code but not on the App ID; signing fails with entitlement mismatches
  • Letting several machines create distribution certs; you hit the cert limit and revoke each other's

✓ Tips & Best Practices

  • Let one system own credentials (EAS or fastlane match), never both
  • Pick reverse-DNS bundle IDs you'll keep forever: com.company.app
  • Use separate bundle IDs for dev/preview builds so they install side by side

Quick Summary

  • Certificate — who signed it
  • App ID — bundle ID + capabilities
  • Profile — where it can run
  • EAS / match — manage it for you
