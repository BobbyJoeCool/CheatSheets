Getting Into the App Store

Release builds are uploaded to App Store Connect, processed, and then available in TestFlight for testing. When ready, you attach a build to a version, fill in metadata, screenshots, privacy details, and age rating, then submit for App Review. Approved versions can release immediately, on a date, or as a phased release over seven days.

Required Before Submitting

  • Privacy manifest (PrivacyInfo.xcprivacy) with required-reason APIs
  • App Privacy "nutrition label" in App Store Connect
  • Built with the current required Xcode/SDK (Xcode 26+)
  • Account deletion in-app if users can create accounts

Upload Paths

# EAS (build + upload)
eas build -p ios --profile production --auto-submit

# Xcode: Product → Archive → Distribute App → App Store Connect

# Command line
xcodebuild -workspace ios/MyApp.xcworkspace -scheme MyApp \
  -configuration Release -archivePath build/MyApp.xcarchive archive
xcodebuild -exportArchive -archivePath build/MyApp.xcarchive \
  -exportOptionsPlist ExportOptions.plist -exportPath build/
xcrun altool --upload-app -f build/MyApp.ipa -t ios \
  --apiKey $KEY_ID --apiIssuer $ISSUER_ID

# Expo privacy manifest (app.json)
# "ios": { "privacyManifests": { "NSPrivacyAccessedAPITypes": [
#   { "NSPrivacyAccessedAPIType":
#       "NSPrivacyAccessedAPICategoryUserDefaults",
#     "NSPrivacyAccessedAPITypeReasons": ["CA92.1"] } ] } }

Notes

--auto-submit — straight to TestFlight after build
Archive — Release build packaged for distribution
ExportOptions.plist — method app-store-connect
altool / Transporter — upload an .ipa
privacyManifests — Expo merges into the manifest

iOS

  • Review usually takes 24–48 h
  • External TestFlight testers need beta review
  • Third-party login requires a privacy-focused login option

Android

  • Play review: hours to days
  • The internal testing track skips review
  • Data safety form ↔ App Privacy label

⚠ Common Mistakes

  • Shipping without a privacy manifest entry for UserDefaults (AsyncStorage uses it); uploads get flagged
  • Giving reviewers no demo account; login-gated apps get rejected for incompleteness
  • Releasing to 100% at once; phased release limits damage from a bad build

✓ Tips & Best Practices

  • Put demo credentials and special instructions in App Review Information
  • Upload early to TestFlight; processing and beta review take time
  • Use eas metadata to keep store listing text in version control

Quick Summary

  • App Store Connect — uploads & listings
  • TestFlight — internal / external betas
  • Privacy manifest + labels — required
  • Phased release — gradual rollout
