Local Databases & Offline

expo-sqlite · op-sqlite · Drizzle · WatermelonDB · sync strategies · migrations

Structured Data on the Device

For relational data, search, or offline-first apps, use SQLite. expo-sqlite offers async and sync APIs, prepared statements, and a React hook for live queries. op-sqlite is a fast JSI alternative. Layer Drizzle ORM on top for typed queries and migrations, or use WatermelonDB / Legend State / PowerSync when you need sync with a backend.

Offline-First Basics

  • Read from the local DB; sync in the background
  • Queue writes while offline, replay when online
  • Track updated_at / version columns for conflicts
  • Run migrations on launch before rendering data

expo-sqlite + Drizzle

import { SQLiteProvider, useSQLiteContext } from 'expo-sqlite'

<SQLiteProvider databaseName="app.db" onInit={migrate}>
  <App />
</SQLiteProvider>

async function migrate(db: SQLiteDatabase) {
  await db.execAsync(`
    PRAGMA journal_mode = WAL;
    CREATE TABLE IF NOT EXISTS todos (
      id INTEGER PRIMARY KEY NOT NULL,
      title TEXT NOT NULL, done INTEGER DEFAULT 0);`)
}

function Todos() {
  const db = useSQLiteContext()
  const add = (t: string) =>
    db.runAsync('INSERT INTO todos (title) VALUES (?)', t)
  const load = () =>
    db.getAllAsync<Todo>('SELECT * FROM todos WHERE done = ?', 0)
}

// Drizzle on top
import { drizzle } from 'drizzle-orm/expo-sqlite'
const orm = drizzle(db)
const open = await orm.select().from(todos).where(eq(todos.done, false))

Notes

SQLiteProvider — opens the DB once for the tree
onInit — run schema setup / migrations
WAL — faster concurrent reads and writes
? placeholders — never build SQL with string concat
Drizzle — typed schema, useLiveQuery, migrations

iOS

  • The DB file lives in the app sandbox
  • Find it: xcrun simctl get_app_container booted <id> data
  • Included in iCloud backups unless excluded

Android

  • The DB lives under the app's private files/ dir
  • Pull it: adb exec-out run-as <pkg> cat <path>
  • Auto Backup may restore an older DB — migrations must cope

⚠ Common Mistakes

  • Building queries with template strings from user input; SQL injection works on-device too
  • Running schema changes without a version check; reinstalls work but updates crash
  • Doing large reads on the JS thread in a loop instead of one query with WHERE / LIMIT

✓ Tips & Best Practices

  • Store a PRAGMA user_version and migrate step by step
  • Use transactions for batch inserts; they're dramatically faster
  • Inspect the DB with the Expo DevTools plugin or by pulling the file from the simulator

Quick Summary

  • SQLite — structured local data
  • runAsync / getAllAsync — write / read
  • Drizzle — typed ORM layer
  • Sync libraries — offline-first apps
