Build Types, Flavors & SDK Levels

minSdk / targetSdk / compileSdk · buildTypes · productFlavors · R8 / ProGuard · Kotlin & AGP versions · ABI splits

Shaping the Android Build

Three SDK numbers matter: minSdk (oldest Android you support), targetSdk (the behavior level you've tested; Google Play requires a recent one), and compileSdk (APIs you compile against). Build types (debug, release) control signing and minification; product flavors create variants like free and pro. R8 shrinks and obfuscates release builds.

Current Numbers

  • RN 0.87 template: min 24, target 36, compile 37
  • Play: new apps & updates must target API 36 (since Aug 31, 2026)
  • Libraries need compileSdk ≥ 34 (minCompileSdk, 0.87)
  • Expo SDK 58 enables R8 by default in release

app/build.gradle Excerpts

android {
  namespace "com.acme.myapp"
  defaultConfig {
    applicationId "com.acme.myapp"
    minSdkVersion rootProject.ext.minSdkVersion        // 24
    targetSdkVersion rootProject.ext.targetSdkVersion  // 36
    versionCode 42
    versionName "1.4.0"
  }
  buildTypes {
    debug { applicationIdSuffix ".debug" }
    release {
      signingConfig signingConfigs.release
      minifyEnabled true                     // R8
      shrinkResources true
      proguardFiles getDefaultProguardFile("proguard-android-optimize.txt"),
        "proguard-rules.pro"
    }
  }
  flavorDimensions "tier"
  productFlavors {
    free { dimension "tier"; applicationIdSuffix ".free" }
    pro  { dimension "tier" }
  }
}
// Expo: expo-build-properties → android.enableMinifyInReleaseBuilds

Notes

namespace — Kotlin/R class package (AGP 8+)
applicationIdSuffix — install debug next to release
minifyEnabled — runs R8 shrinking
proguard-rules.pro — keep rules for reflection-based libs
Flavors × build types — freeRelease, proDebug…

iOS

  • minSdk ↔ deployment target
  • R8 shrinking ↔ Xcode dead-code stripping
  • AAB per-device splits ↔ App Thinning

Android

  • Keep rules in proguard-rules.pro for reflection libraries
  • AAB lets Play deliver per-ABI APKs
  • Test minified release builds before uploading

⚠ Common Mistakes

  • Turning on R8 without testing a release build; reflection-based libraries crash until you add keep rules
  • Bumping targetSdk without reading behavior changes (edge-to-edge, predictive back, large-screen rules)
  • Hardcoding SDK numbers in each module instead of rootProject.ext

✓ Tips & Best Practices

  • Use ./gradlew :app:assembleRelease locally before every store upload
  • Keep mapping.txt from R8 builds and upload it for readable crash stack traces
  • Native libs must support 16 KB memory pages for Play; RN 0.77+ does, check third-party .so files
