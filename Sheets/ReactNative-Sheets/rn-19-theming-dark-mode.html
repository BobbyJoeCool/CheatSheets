Theming & Dark Mode

useColorScheme · Appearance · PlatformColor · theme context · NativeWind · Unistyles

Light, Dark, and Brand Themes

useColorScheme() returns 'light' or 'dark' from the OS and re-renders when it changes. Build a theme object per scheme and share it through context (or your navigation theme). PlatformColor and DynamicColorIOS use native semantic colors that adapt automatically. Libraries like NativeWind (Tailwind classes) and Unistyles add theme-aware styling with less boilerplate.

Setup Requirements

  • Expo: "userInterfaceStyle": "automatic" in app.json
  • useColorScheme() no longer returns 'unspecified' (0.87)
  • Appearance.setColorScheme('auto') resets to the OS setting
  • Navigation libraries have their own theme prop

Theme Hook

const palette = {
  light: { bg: '#fff', text: '#111827', card: '#f3f4f6', tint: '#5c6bc0' },
  dark:  { bg: '#0f1117', text: '#e8eaf6', card: '#1e2130', tint: '#7e57c2' },
}

export function useTheme() {
  const scheme = useColorScheme() ?? 'light'
  return palette[scheme]
}

function Card({ children }: { children: React.ReactNode }) {
  const t = useTheme()
  return <View style={{ backgroundColor: t.card }}>{children}</View>
}

// Force a scheme (e.g. user setting)
Appearance.setColorScheme('dark')   // 'light' | 'dark' | 'auto'

// Native semantic colors
const label = Platform.select({
  ios: PlatformColor('label'),
  android: PlatformColor('?android:attr/textColorPrimary'),
})

Notes

?? 'light' — fallback for null on some platforms
Keep the palette typed so every key exists in both themes
setColorScheme — overrides for this app only
PlatformColor — native named colors, auto light/dark
Pass the scheme to React Navigation's ThemeProvider

iOS

  • PlatformColor('systemBackground') follows Dark Mode
  • DynamicColorIOS({ light, dark }) for custom pairs
  • UIUserInterfaceStyle in Info.plist sets the default

Android

  • PlatformColor('?attr/colorPrimary') reads theme attributes
  • The app theme must be DayNight for dark mode
  • Material You colors: @android:color/system_accent1_500 (API 31+)

⚠ Common Mistakes

  • Hardcoding '#fff' across components, which makes dark mode a rewrite later
  • Forgetting userInterfaceStyle: automatic, so useColorScheme always returns light
  • Theming screens but not the status bar and navigation headers

✓ Tips & Best Practices

  • Store the user's choice (light / dark / system) and call Appearance.setColorScheme
  • Check contrast in both themes; dark grays on black often fail WCAG
  • Use expo-system-ui to set the root background so no white flash appears

Quick Summary

  • useColorScheme — OS scheme, reactive
  • Theme object — one per scheme
  • PlatformColor — native semantic colors
  • NativeWind / Unistyles — themed styling
