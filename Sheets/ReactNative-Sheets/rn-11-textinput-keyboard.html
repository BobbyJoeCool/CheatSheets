TextInput & Keyboard

<TextInput> · value / onChangeText · keyboardType · secureTextEntry · KeyboardAvoidingView · Keyboard.dismiss() · returnKeyType

Getting Text from Users

TextInput is the native text field. Control it with value + onChangeText, which gives you the string directly. Choose the right keyboard with keyboardType, textContentType (iOS) and autoComplete (Android) for autofill. Then deal with the keyboard covering your form: KeyboardAvoidingView, ScrollView settings, or the react-native-keyboard-controller library.

Behaviors

  • onChangeText(text) — string; onChange — native event
  • multiline changes Enter from submit to newline
  • Focus order: ref.focus() from onSubmitEditing
  • Android pads with windowSoftInputMode=adjustResize

A Login Form

const passRef = useRef<TextInputInstance>(null)

<KeyboardAvoidingView style={{ flex: 1 }}
  behavior={Platform.OS === 'ios' ? 'padding' : undefined}>
  <ScrollView keyboardShouldPersistTaps="handled">
    <TextInput
      value={email} onChangeText={setEmail}
      placeholder="Email" keyboardType="email-address"
      autoCapitalize="none" autoComplete="email"
      textContentType="emailAddress"
      returnKeyType="next"
      onSubmitEditing={() => passRef.current?.focus()}
    />
    <TextInput
      ref={passRef} value={password} onChangeText={setPassword}
      placeholder="Password" secureTextEntry
      textContentType="password" returnKeyType="go"
      onSubmitEditing={login}
    />
  </ScrollView>
</KeyboardAvoidingView>

Notes

behavior="padding" — the usual iOS choice
keyboardShouldPersistTaps="handled" — taps reach buttons
autoCapitalize="none" — essential for emails
textContentType / autoComplete — password managers
returnKeyType + onSubmitEditing — field-to-field flow

iOS

  • KeyboardAvoidingView behavior="padding"
  • textContentType enables autofill ('oneTimeCode', 'password')
  • clearButtonMode adds the native clear (×) button

Android

  • The window resizes for the keyboard; often behavior="height" or none
  • autoComplete drives autofill ('sms-otp', 'password')
  • underlineColorAndroid="transparent" removes the underline

⚠ Common Mistakes

  • Using onChange and reading e.target.value; RN gives e.nativeEvent.text, or just use onChangeText
  • Forgetting keyboardShouldPersistTaps, so the first tap on Submit only closes the keyboard
  • Leaving autoCorrect on for usernames and codes

✓ Tips & Best Practices

  • Use react-native-keyboard-controller for consistent avoidance across iOS and Android
  • Wrap a screen in Pressable onPress={Keyboard.dismiss} to close on outside taps
  • Set textContentType="oneTimeCode" for SMS code autofill on iOS

Quick Summary

  • value + onChangeText — controlled input
  • keyboardType — right keyboard
  • KeyboardAvoidingView — keep fields visible
  • returnKeyType — next / go / done
