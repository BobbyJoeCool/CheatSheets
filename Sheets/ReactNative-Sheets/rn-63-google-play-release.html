Google Play Release

.aab bundle · Play Console · internal / closed / open testing tracks · target SDK requirements · Data safety form · staged rollout

Shipping on Google Play

Play takes an Android App Bundle (.aab) and generates optimized APKs per device. You upload to a track: internal testing (fast, up to 100 testers), closed testing, open testing, then production. Before your first release you complete the store listing, content rating, Data safety form, target audience, and, for new personal developer accounts, a closed test with at least 12 testers for 14 days.

Requirements (2026)

  • Target API 36 for new apps and updates (since Aug 31, 2026)
  • AAB required for new apps
  • 16 KB page size support for native libraries
  • Privacy policy URL; account deletion if accounts exist

Build and Upload

# Bare: build a signed AAB
cd android && ./gradlew bundleRelease
# → android/app/build/outputs/bundle/release/app-release.aab

# Test the AAB locally with bundletool
bundletool build-apks --bundle=app-release.aab --output=app.apks \
  --ks=my-upload-key.keystore --ks-key-alias=my-key-alias
bundletool install-apks --apks=app.apks

# EAS: build + submit to the internal track
eas build -p android --profile production
eas submit -p android --latest
# eas.json → "submit": { "production": { "android": {
#   "track": "internal", "releaseStatus": "draft",
#   "serviceAccountKeyPath": "./play-service-account.json" } } }

# Promote internal → production in Play Console,
# start a staged rollout (e.g. 10%) and watch Android vitals

Notes

bundleRelease — signed with your upload key
bundletool — reproduce what Play will install
track — internal · alpha · beta · production
releaseStatus: draft — review before rollout
Service account — needs Play Console API access

iOS

  • TestFlight ↔ internal / closed testing tracks
  • App Privacy label ↔ Data safety form
  • Phased release ↔ staged rollout

Android

  • New personal accounts: 12 testers for 14 days before production
  • Staged rollouts by percentage
  • The pre-launch report tests on real devices

⚠ Common Mistakes

  • Uploading an APK for a new app; Play requires AAB
  • Filling Data safety without checking what third-party SDKs collect; mismatches lead to removal
  • Rolling out 100% immediately; halt is only possible during a staged rollout

✓ Tips & Best Practices

  • Ship every build to the internal track first; it's the fastest way to test on real devices
  • Watch Android vitals (crash and ANR rates); bad numbers reduce store visibility
  • Keep release notes per language in eas metadata or fastlane supply

Quick Summary

  • .aab — required upload format
  • Tracks — internal → production
  • Data safety + target API — policy gates
  • Staged rollout — limit risk
