Sheet 52

iPadOS

supportsTablet · Platform.isPad · multitasking & Split View · orientation · pointer & hardware keyboard · adaptive layouts

Same App, Bigger Canvas

iPad runs your iOS build. If you don't opt in, it shows an iPhone-sized app scaled up. Opt in with ios.supportsTablet (Expo) or by targeting iPad in Xcode, then design adaptive layouts: the window can be full screen, Split View, Slide Over, or a freely resized Stage Manager window. Users also expect pointer hover, keyboard shortcuts, and all orientations.

Key Behaviors

  • Window size ≠ screen size; use useWindowDimensions
  • All four orientations expected on iPad
  • Pointer hover via onHoverIn / onHoverOut
  • Mac (Apple silicon) can run iPad apps too

Adaptive iPad Layout

// app.json
// "ios": { "supportsTablet": true },
// "orientation": "default"          // allow rotation

function Inbox() {
  const { width } = useWindowDimensions()
  const split = Platform.isPad && width >= 700
  return split ? (
    <View style={{ flex: 1, flexDirection: 'row' }}>
      <View style={{ width: 320, borderRightWidth: 1 }}>
        <MessageList onSelect={setSelected} />
      </View>
      <View style={{ flex: 1 }}>
        <MessageDetail id={selected} />
      </View>
    </View>
  ) : (
    <MessageList onSelect={id => router.push(`/message/${id}`)} />
  )
}

<Pressable onHoverIn={() => setHover(true)}
  onHoverOut={() => setHover(false)}
  style={{ backgroundColor: hover ? '#2e3348' : 'transparent' }} />

Notes

supportsTablet — run natively instead of scaled
split — base on window width, not isPad alone
Two-pane — list + detail when wide
Phone-width windows fall back to stack navigation
onHoverIn — pointer and Apple Pencil hover

iOS

  • ios.supportsTablet: true in Expo config
  • Stage Manager resizes windows freely
  • Hardware keyboard shortcuts need native UIKeyCommand

Android

  • Tablets and foldables resize windows at runtime
  • Targeting API 36 ignores orientation locks on large screens
  • Use window size classes for breakpoints

⚠ Common Mistakes

  • Branching on Platform.isPad alone; a ⅓ Split View window is phone-sized
  • Locking iPad to portrait; reviewers and users expect rotation
  • Fixed-width layouts that leave huge empty margins in landscape

✓ Tips & Best Practices

  • Test Split View and Stage Manager sizes, not just full screen
  • Reuse the same breakpoints for foldables and Android tablets
  • Add a max content width (e.g. 700) for reading screens on big windows

Quick Summary

  • Window width — drives layout
