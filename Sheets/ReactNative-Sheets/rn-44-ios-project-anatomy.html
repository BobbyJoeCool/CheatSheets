iOS Project Anatomy

ios/ folder · AppDelegate.swift · Info.plist · Podfile · pod install · .xcworkspace · SwiftPM (experimental)

What's Inside ios/

The ios/ folder is a normal Xcode project that embeds React Native. Native dependencies come from CocoaPods: pod install reads the Podfile, autolinks native modules from node_modules, and creates a .xcworkspace, which is what you open in Xcode. Since 0.77 the entry point is Swift (AppDelegate.swift) using RCTReactNativeFactory. Core RN supports iOS 15.1+; Expo SDK 56+ requires 16.4+.

Key Facts

  • Open .xcworkspace, never .xcodeproj
  • Prebuilt RN core .xcframeworks download during pod install (0.84+)
  • SwiftPM is experimental in 0.87; CocoaPods stays default
  • Expo SDK 58 adds SceneDelegate.swift (UIKit scene lifecycle)

AppDelegate.swift (0.87 template)

import UIKit
import React
import React_RCTAppDelegate
import ReactAppDependencyProvider

@main
class AppDelegate: UIResponder, UIApplicationDelegate {
  var window: UIWindow?
  var reactNativeFactory: RCTReactNativeFactory?

  func application(_ application: UIApplication,
      didFinishLaunchingWithOptions launchOptions:
        [UIApplication.LaunchOptionsKey: Any]? = nil) -> Bool {
    let delegate = ReactNativeDelegate()
    let factory = RCTReactNativeFactory(delegate: delegate)
    delegate.dependencyProvider = RCTAppDependencyProvider()
    reactNativeFactory = factory
    window = UIWindow(frame: UIScreen.main.bounds)
    factory.startReactNative(withModuleName: "MyApp",
      in: window, launchOptions: launchOptions)
    return true
  }
}
// ReactNativeDelegate.bundleURL(): Metro in DEBUG, main.jsbundle in release

Notes

@main — Swift app entry point
RCTReactNativeFactory — boots the RN runtime
withModuleName — must match AppRegistry name
bundleURL — Metro URL vs bundled JS
Expo projects generate an equivalent ExpoAppDelegate

iOS

  • Signing & Capabilities writes the .entitlements file

  • Bundle ID lives in the target's General tab

Android

⚠ Common Mistakes

  • Opening MyApp.xcodeproj; pods aren't linked and the build fails with missing modules
  • Running a system pod instead of bundle exec pod; CocoaPods version mismatches cause odd errors
  • Forgetting pod install after adding a native library; autolinking happens there

✓ Tips & Best Practices

  • Commit Podfile.lock so every machine gets the same native versions
  • When builds break mysteriously, delete ios/Pods, ios/build, and DerivedData, then reinstall
  • In Expo, change iOS settings in app.json ios or a config plugin, not in Xcode

Quick Summary

  • AppDelegate.swift — native entry
  • Podfile + pod install — native deps
  • .xcworkspace — what you open
  • iOS 15.1+ core, 16.4+ Expo SDK 56+
