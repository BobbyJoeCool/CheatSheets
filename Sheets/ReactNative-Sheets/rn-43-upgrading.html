Upgrading React Native & Expo

release cadence · Upgrade Helper · npx expo install --fix · expo-doctor · breaking-change checklist

Staying Current

React Native ships a minor version about every two months and supports the latest three. Expo releases SDKs about three times a year, each pinned to one RN version. Expo apps upgrade by bumping the SDK and running expo install --fix; with CNG, native folders are regenerated. Bare apps use the Upgrade Helper to diff template changes into their native projects.

Current Line-Up (Oct 2026)

  • RN 0.87 stable, 0.86 active, 0.85 end of cycle
  • Expo SDK 57 → RN 0.86; SDK 58 beta → RN 0.88
  • Node 22.13+ required
  • Skipping versions works but read every changelog in between

Upgrade Commands

# Expo
npx expo install expo@^57.0.0      # bump the SDK
npx expo install --fix             # align all expo-* + RN versions
npx expo-doctor                    # check for problems
npx expo prebuild                  # regenerate native folders (CNG)

# Bare React Native
# 1. Open the Upgrade Helper and apply the template diff by hand:
#    react-native-community.github.io/upgrade-helper/?from=0.85.0&to=0.87.0
npm install react-native@0.87 @react-native/babel-preset@0.87
cd ios && bundle exec pod install --repo-update
cd android && ./gradlew clean

# After upgrading
npx tsc --noEmit
npm test

Notes

expo install — picks versions compatible with your SDK
--fix — corrects mismatched dependency versions
expo-doctor — config, duplicate deps, version checks
Upgrade Helper — shows every template file change
pod install --repo-update — refresh CocoaPods specs

iOS

  • After upgrading: cd ios && pod install --repo-update
  • Clear DerivedData on stale build errors
  • Check the minimum iOS deployment target

Android

  • Gradle wrapper and AGP bumps come from the template diff
  • cd android && ./gradlew clean after upgrading
  • Check minSdk, compileSdk and Kotlin versions

⚠ Common Mistakes

  • Upgrading React Native with plain npm install react-native@latest in an Expo app; versions drift from the SDK
  • Ignoring expo-doctor warnings about duplicate native modules
  • Upgrading right before a release instead of on a quiet branch with time to test

✓ Tips & Best Practices

  • Upgrade on a branch and keep it small: SDK bump first, then library bumps
  • Clear Xcode DerivedData and ./gradlew clean when native builds fail after upgrades
  • Subscribe to the RN and Expo changelogs so upgrades are never a surprise

Quick Summary

  • RN — new minor every ~2 months
  • expo install --fix — align versions
  • Upgrade Helper — bare template diff
  • Read changelogs — breaking changes
