Sheet 18

Dimensions, Safe Areas & Responsive Layout

useWindowDimensions · PixelRatio · react-native-safe-area-context · SafeAreaView · useSafeAreaInsets · orientation

Fitting Every Screen

Phones have notches, Dynamic Islands, home indicators, and (on Android 15+) apps draw edge-to-edge under the system bars. Use react-native-safe-area-context to pad content away from those areas. Use useWindowDimensions (which updates on rotation and resizing) to adapt layouts. Breakpoints are plain JavaScript conditions on the width.

Key Facts

  • Core SafeAreaView is iOS-only and deprecated in favor of the library
  • useWindowDimensions re-renders on change; Dimensions.get doesn't
  • Insets differ by device and orientation
  • iPads and foldables resize windows at runtime

Safe Areas and Breakpoints

// Root: once, near the top of the app
<SafeAreaProvider><App /></SafeAreaProvider>

function Screen() {
  const insets = useSafeAreaInsets()
  const { width, height, fontScale } = useWindowDimensions()
  const isTablet = width >= 768
  const columns = width >= 1024 ? 3 : isTablet ? 2 : 1
  const landscape = width > height

  return (
    <View style={{ flex: 1, paddingTop: insets.top,
                   paddingBottom: insets.bottom }}>
      <FlatList key={columns} numColumns={columns} data={items}
        renderItem={renderCard} />
    </View>
  )
}

// Or the component form, choosing edges
<SafeAreaView edges={['top', 'left', 'right']} style={{ flex: 1 }} />

Notes

SafeAreaProvider — required once; Expo Router adds it
insets.top — status bar / notch height
fontScale — the user's text size setting
key={columns} — FlatList must remount when numColumns changes
edges — pad only the sides you need

iOS

  • Insets cover the notch / Dynamic Island and home indicator
  • screen and window match on iPhone
  • iPad Split View and Stage Manager change the window size

Android

  • Edge-to-edge: content draws under the system bars
  • Pad with useSafeAreaInsets(), not hardcoded heights
  • Display cutouts (punch-hole cameras) appear in insets

⚠ Common Mistakes

  • Reading Dimensions.get('window') once at module scope; it never updates on rotation or split view
  • Wrapping every screen in SafeAreaView and also adding header padding; content gets double insets
  • Assuming the window equals the screen on iPad or Android multi-window

✓ Tips & Best Practices

  • Let headers and tab bars handle their own insets; pad only custom edges
  • Test with the largest accessibility text size; use fontScale to adjust layouts
  • Expect Android apps to draw under the system bars (edge-to-edge is the default on Android 15+); never hardcode bar heights

Quick Summary

  • useSafeAreaInsets — notch & bar padding
  • useWindowDimensions — reactive size
  • Breakpoints — JS conditions on width
  • onLayout — measure a view
