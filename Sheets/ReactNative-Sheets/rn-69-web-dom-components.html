Web-Specific Patterns & DOM Components

'use dom' DOM components · responsive breakpoints · hover & cursor · SEO / metadata · Expo Router web hosting

When Native Meets the Web

DOM components ('use dom', Expo SDK 52+) let you drop real web code (HTML, CSS, web-only libraries like charts or rich-text editors) into a native app; on native it renders inside a WebView, on web it renders directly. Combine that with responsive breakpoints, hover states, and per-route metadata to make one codebase feel right in both places.

DOM Component Rules

  • First line of the file: 'use dom'
  • Props must be serializable; functions become async bridges
  • Uses @expo/dom-webview by default (SDK 56)
  • Heavier than native views; use for islands, not whole screens

A DOM Component

// components/RichEditor.tsx
'use dom'
import { useState } from 'react'
import 'quill/dist/quill.snow.css'

export default function RichEditor({ initial, onSave }:
  { initial: string; onSave: (html: string) => Promise<void>;
    dom?: import('expo/dom').DOMProps }) {
  const [html, setHtml] = useState(initial)
  return (
    <div style={{ padding: 12 }}>
      <div contentEditable
        onInput={e => setHtml(e.currentTarget.innerHTML)}
        dangerouslySetInnerHTML={{ __html: initial }} />
      <button onClick={() => onSave(html)}>Save</button>
    </div>
  )
}

// Used from a native screen
<RichEditor initial={note.html}
  onSave={async html => { await api.save(note.id, html) }}
  dom={{ scrollEnabled: false, matchContents: true }} />

Notes

'use dom' — whole file runs in web context
CSS imports — allowed inside DOM components
onSave — native function called from the web side
dom prop — WebView options
On web it's just a normal React component

iOS

  • DOM components render in WKWebView
  • Debug with Safari's Develop menu
  • Enable inspection with webviewDebuggingEnabled

Android

  • Renders in Android System WebView (Chromium)
  • Debug with chrome://inspect
  • Old devices may have old WebViews — avoid new CSS

⚠ Common Mistakes

  • Building entire screens as DOM components; scrolling and gestures feel non-native
  • Passing non-serializable props (class instances, refs) into a DOM component
  • Forgetting the file-level 'use dom' directive, so the component tries to render HTML natively and crashes

✓ Tips & Best Practices

  • Use DOM components to adopt a web library today, then replace with native later if needed
  • Share design tokens between web CSS and RN styles
  • Deploy web builds with EAS Hosting alongside your native releases

Quick Summary

  • 'use dom' — web code in native apps
  • Serializable props — async function bridges
  • Hover / Link / Head — web polish
  • Islands, not screens
