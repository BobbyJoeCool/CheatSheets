eas submit · version vs buildNumber / versionCode · autoIncrement · appVersionSource · release channels

Shipping Builds to the Stores

eas submit uploads a finished build to App Store Connect (TestFlight) or Google Play. Each store tracks two numbers: a user-facing version (1.4.0) and an internal build number that must increase with every upload. With appVersionSource: "remote", EAS stores and auto-increments build numbers for you.

Version Numbers

  • iOS: CFBundleShortVersionString + CFBundleVersion
  • Android: versionName + versionCode (integer)
  • Expo config: version, ios.buildNumber, android.versionCode
  • Runtime check: expo-application nativeApplicationVersion

Submit Commands

# Build and submit in one go
eas build -p ios --profile production --auto-submit

# Submit an existing build
eas submit -p ios --latest
eas submit -p android --id <build-id>
eas submit -p android --path ./app-release.aab

# Version management (appVersionSource: remote)
eas build:version:get -p android
eas build:version:set -p ios          # set starting value
eas build:version:sync                # write back to local config

# eas.json submit profile
# "submit": { "production": {
#   "ios": { "ascAppId": "1234567890" },
#   "android": { "track": "internal", "releaseStatus": "draft" } } }

Notes

--auto-submit — submit as soon as the build finishes
--latest — most recent build for that platform
build:version:* — manage remote build numbers
ascAppId — App Store Connect app ID
track — internal · alpha · beta · production

iOS

  • Use an App Store Connect API key
  • Uploads go through TestFlight processing first
  • buildNumber must rise for each upload of a version

Android

  • The first upload must be done by hand in Play Console
  • Needs a Google service account JSON key
  • versionCode must always increase

⚠ Common Mistakes

  • Re-uploading with the same build number; both stores reject duplicates
  • Expecting the first Android submit to work from CLI; Play needs one manual upload to create the app
  • Mixing local and remote version sources so numbers go backwards

✓ Tips & Best Practices

  • Let EAS own build numbers (autoIncrement + remote) and only edit version by hand
  • Use Play's internal track and TestFlight for every release candidate
  • Show version (build) in your settings screen for bug reports

Quick Summary

  • version — user-facing
  • build number — always increments
  • appVersionSource: remote — EAS tracks it
