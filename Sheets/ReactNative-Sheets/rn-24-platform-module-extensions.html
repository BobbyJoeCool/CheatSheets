Platform Module & File Extensions

Platform.OS · Platform.select() · Platform.Version · .ios.tsx / .android.tsx / .native.tsx / .web.tsx · Platform.isPad / isTV

Writing Platform-Specific Code

Most code is shared, but sometimes iOS and Android need different values, components, or whole files. Use Platform.OS and Platform.select for small differences inline. For bigger ones, create platform files: Metro picks Button.ios.tsx on iOS and Button.android.tsx on Android when you import ./Button. Out-of-tree platforms add their own extensions like .windows.tsx and .macos.tsx.

Resolution Order

  • .ios.tsx / .android.tsx / .web.tsx first
  • then .native.tsx (iOS + Android + other native)
  • then plain .tsx
  • Import without the extension: import Button from './Button'

Inline and File-Based

import { Platform, StyleSheet } from 'react-native'

// Platform.OS: 'ios' | 'android' | 'web' | 'windows' | 'macos'
const isIOS = Platform.OS === 'ios'

const styles = StyleSheet.create({
  card: {
    ...Platform.select({
      ios:     { shadowColor: '#000', shadowOpacity: 0.2, shadowRadius: 6 },
      android: { elevation: 4 },
      default: { boxShadow: '0 2px 6px rgba(0,0,0,.2)' },
    }),
  },
})

if (Platform.OS === 'android' && Platform.Version >= 33) {
  // Android 13+: request POST_NOTIFICATIONS
}
if (Platform.OS === 'ios' && parseInt(Platform.Version, 10) >= 17) {}

// Files
// DatePicker.ios.tsx      ← iOS
// DatePicker.android.tsx  ← Android
// DatePicker.tsx          ← everything else (web)
import DatePicker from './DatePicker'

Notes

Platform.select — ios, android, native, web, default keys
Platform.Version — number on Android (API level), string on iOS
Android API 33 = Android 13
File extensions — Metro chooses at bundle time
Types: give platform files the same exported signature

iOS

  • Platform.isPad, Platform.isTV
  • Platform.Version is a string ('18.2')
  • Platform.constants.interfaceIdiom — 'phone', 'pad'…

Android

  • Platform.Version is the API level (35)
  • Platform.constants.Brand, Model, Release
  • .android.tsx wins over .native.tsx

⚠ Common Mistakes

  • Comparing Platform.Version as a number on iOS; it's a string like '18.2'
  • Platform files with different exports; TypeScript only sees the plain file, so others break at runtime
  • Sprinkling Platform.OS checks everywhere instead of isolating them in one component

✓ Tips & Best Practices

  • Keep a shared Button.types.ts that each platform file implements
  • Prefer capability checks (await Notifications.getPermissionsAsync()) over version checks
  • Use .native.tsx + .web.tsx when only web differs

Quick Summary

  • Platform.OS — which platform
  • Platform.select — per-platform values
  • .ios / .android files — split components
  • Platform.Version — API level / OS string
