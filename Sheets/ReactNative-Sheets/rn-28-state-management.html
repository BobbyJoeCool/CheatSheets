State Management Libraries

Zustand · Redux Toolkit · Jotai · Legend State · persisting state · when context is enough

Client State Beyond useState

Keep server state in TanStack Query and UI state local. For client state shared across many screens (cart, settings, drafts), use a small store. Zustand is the common choice: a hook-based store with selectors and no provider. Redux Toolkit suits large teams that want strict patterns and DevTools. Jotai uses atoms; Legend State focuses on speed and sync.

Picking One

  • Few shared values, rare changes → Context
  • App-wide client state → Zustand
  • Big team, strict conventions → Redux Toolkit
  • Fine-grained reactive/offline sync → Legend State

Zustand Store with Persistence

import { create } from 'zustand'
import { persist, createJSONStorage } from 'zustand/middleware'
import AsyncStorage from '@react-native-async-storage/async-storage'

type CartState = {
  items: CartItem[]
  add: (item: CartItem) => void
  remove: (id: string) => void
  clear: () => void
}

export const useCart = create<CartState>()(
  persist(
    (set) => ({
      items: [],
      add: (item) => set((s) => ({ items: [...s.items, item] })),
      remove: (id) =>
        set((s) => ({ items: s.items.filter(i => i.id !== id) })),
      clear: () => set({ items: [] }),
    }),
    { name: 'cart', storage: createJSONStorage(() => AsyncStorage) },
  ),
)

// Select only what you need → fewer re-renders
const count = useCart((s) => s.items.length)
const add = useCart((s) => s.add)
useCart.getState().clear()        // outside React

Notes

create<T>()(…) — curried form for TS + middleware
set(fn) — immutable updates
persist — saves to storage, rehydrates on launch
Selectors — component re-renders only when slice changes
getState() — read/act from non-React code

iOS

  • iOS kills background apps without warning
  • Persist on AppState change to 'background'
  • Rehydrate before the first screen renders

Android

  • Process death is common on low-RAM devices
  • Test with Don't keep activities
  • AsyncStorage defaults to a 6 MB limit on Android

⚠ Common Mistakes

  • Copying server data into a global store and syncing it by hand; let the query cache own it
  • Selecting the whole store (useCart()) so every change re-renders the component
  • Persisting auth tokens with AsyncStorage; it isn't encrypted

✓ Tips & Best Practices

  • Use useShallow from zustand/react/shallow when selecting several fields
  • Persist with MMKV for synchronous, faster hydration
  • Version persisted stores (version, migrate) so app updates don't break saved state

Quick Summary

  • Server state — query library
  • Zustand — simple global store
  • Selectors — limit re-renders
  • persist — survive restarts
