App Config & Config Plugins

app.json · app.config.ts · Continuous Native Generation · npx expo prebuild · config plugins · expo-build-properties

Native Config Without Native Folders

Expo's Continuous Native Generation (CNG) treats ios/ and android/ as build output. Your app config (app.json or app.config.ts) and config plugins describe everything native: names, icons, permissions, entitlements, Gradle and Podfile settings. npx expo prebuild generates the folders from that config; since SDK 57 it clears and regenerates them by default.

Why CNG

  • Upgrades become config changes, not merges into Xcode projects
  • Libraries ship plugins that edit native files for you
  • Native folders can stay out of git
  • Bare apps can still use plugins via prebuild once

Dynamic Config + Plugins

// app.config.ts
import type { ExpoConfig } from 'expo/config'

const IS_DEV = process.env.APP_VARIANT === 'development'

export default ({ config }: { config: ExpoConfig }): ExpoConfig => ({
  ...config,
  name: IS_DEV ? 'MyApp (Dev)' : 'MyApp',
  slug: 'myapp',
  ios: { bundleIdentifier: IS_DEV ? 'com.acme.app.dev' : 'com.acme.app' },
  android: { package: IS_DEV ? 'com.acme.app.dev' : 'com.acme.app' },
  plugins: [
    'expo-router',
    ['expo-camera', { cameraPermission: 'Scan receipts with your camera' }],
    ['expo-build-properties', {
      android: { minSdkVersion: 24, enableMinifyInReleaseBuilds: true },
      ios: { deploymentTarget: '16.4' },
    }],
    './plugins/withCustomManifest',
  ],
})

Notes

app.config.ts — JS logic, env vars, variants
Different bundle IDs — dev and prod side by side
Plugin tuple — [name, options]
expo-build-properties — SDK levels, minify, deployment target
Local plugin — your own withX function

iOS

  • ios.infoPlist merges keys into Info.plist
  • ios.entitlements adds capabilities
  • ios.bundleIdentifier is permanent once on the App Store

Android

  • android.permissions adds manifest entries; blockedPermissions removes
  • android.package is permanent once on Google Play
  • Plugins use withAndroidManifest, withAppBuildGradle

Prebuild Commands

⚠ Common Mistakes

  • Editing ios/ by hand in a CNG project; the next prebuild (which now cleans) throws it away
  • Changing a plugin option and only restarting Metro; native config needs a rebuild
  • Putting secrets in app.config.ts extra; it ships inside the app bundle

✓ Tips & Best Practices

  • Use APP_VARIANT with EAS build profiles for dev / preview / prod apps on one device
  • Search for a library's config plugin before writing native code yourself
  • Run npx expo prebuild --clean locally to inspect what EAS will build

Quick Summary

  • CNG — native folders are generated
  • app.config.ts — dynamic config
  • Config plugins — edit native files safely
