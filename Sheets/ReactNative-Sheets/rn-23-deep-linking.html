Opening Your App From a URL

A custom scheme (myapp://post/42) opens your app from other apps and notifications. Universal links (iOS) and App Links (Android) use your real https:// domain, open the app if installed, and fall back to the website if not. Expo Router and React Navigation route incoming URLs to screens automatically once linking is configured.

Requirements

  • Scheme set in app config (rebuild needed)
  • iOS: associatedDomains + apple-app-site-association file
  • Android: intentFilters with autoVerify + assetlinks.json
  • Both JSON files served over HTTPS at /.well-known/

Config and Handling

// app.json (Expo)
{ "expo": {
    "scheme": "myapp",
    "ios": { "associatedDomains": ["applinks:example.com"] },
    "android": { "intentFilters": [{
      "action": "VIEW", "autoVerify": true,
      "data": [{ "scheme": "https", "host": "example.com",
                 "pathPrefix": "/post" }],
      "category": ["BROWSABLE", "DEFAULT"] }] } } }

// Expo Router: /post/[id].tsx handles both
//   myapp://post/42  and  https://example.com/post/42

// Manual handling (any app)
import * as Linking from 'expo-linking'
const url = Linking.createURL('post/42')   // myapp://post/42 (dev: exp://…)
const initial = await Linking.getInitialURL()
const sub = Linking.addEventListener('url', ({ url }) => {
  const { path, queryParams } = Linking.parse(url)
})
await Linking.openURL('https://example.com')
await Linking.openSettings()               // this app's OS settings

Notes

scheme — custom URL prefix for your app
applinks: — iOS domain association
autoVerify — Android verifies assetlinks.json
createURL — correct scheme in dev and prod
getInitialURL — URL that cold-started the app

iOS

  • Universal Links: applinks:example.com in associated domains
  • Serve the AASA file without redirects
  • Test: xcrun simctl openurl booted myapp://path

Android

  • App Links: autoVerify + SHA-256 of the Play signing key
  • Test: adb shell am start -a android.intent.action.VIEW -d "myapp://path"
  • Check: adb shell pm get-app-links com.example.app

⚠ Common Mistakes

  • Using the debug keystore's SHA-256 in assetlinks.json for a Play build; Play App Signing uses a different key
  • Changing scheme and expecting it to work without a native rebuild
  • Serving the AASA file behind a redirect; iOS refuses it

✓ Tips & Best Practices

  • Add both the Play signing and upload key fingerprints to assetlinks.json
  • Handle unknown paths with +not-found instead of crashing
  • Use Expo Router's +native-intent.tsx to rewrite third-party URLs before routing
