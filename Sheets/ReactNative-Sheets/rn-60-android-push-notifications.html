Push on Android

Android pushes go through Firebase Cloud Messaging (FCM). Add your app to a Firebase project, download google-services.json, and give your server (or EAS) an FCM v1 service account key. On Android 13+ you must request POST_NOTIFICATIONS. Every notification belongs to a channel (Android 8+) that controls sound and importance, and that users can mute individually.

Requirements

  • google-services.json in config (android.googleServicesFile)
  • FCM v1 service account JSON uploaded to EAS for Expo Push
  • Channel created before the first notification
  • Device must have Google Play services (not some Chinese OEMs)

Channel, Permission, Token

import * as Notifications from 'expo-notifications'

async function setupAndroidPush() {
  await Notifications.setNotificationChannelAsync('orders', {
    name: 'Order updates',
    importance: Notifications.AndroidImportance.HIGH,
    sound: 'default',
    vibrationPattern: [0, 250, 250, 250],
    lightColor: '#7e57c2',
  })
  const { status } = await Notifications.requestPermissionsAsync() // 13+
  if (status !== 'granted') return null
  const { data: fcmToken } = await Notifications.getDevicePushTokenAsync()
  return fcmToken
}

// app.json
// "android": { "googleServicesFile": "./google-services.json" },
// "plugins": [["expo-notifications", {
//    "icon": "./assets/notification-icon.png", "color": "#7e57c2",
//    "defaultChannel": "orders" }]]

// Server → FCM v1 (HTTP)
// POST https://fcm.googleapis.com/v1/projects/<id>/messages:send
// { "message": { "token": "<fcmToken>",
//   "notification": { "title": "Shipped", "body": "Order #42" },
//   "android": { "notification": { "channel_id": "orders" } },

Notes

setNotificationChannelAsync — idempotent; call on startup
importance: HIGH — heads-up banner
Device token — raw FCM token for your server
Notification icon — white silhouette PNG
channel_id — must match an existing channel

iOS

  • APNs key instead of FCM — no channels
  • A permission prompt is always required
  • Silent pushes are throttled by iOS

Android

  • Heads-up banners need a high-importance channel
  • Data-only messages need a background handler
  • Small icon: white on transparent

⚠ Common Mistakes

  • Not creating a channel; on Android 8+ the notification is silently dropped
  • Using a full-color icon; Android renders it as a white blob, use a transparent silhouette
  • Changing a channel's importance in code after creation; Android ignores it, create a new channel ID

✓ Tips & Best Practices

  • Create channels per category (orders, chat, marketing) so users mute only what they want
  • Use data messages + local notifications when you need custom display logic
  • Test background and killed states; delivery differs from foreground

Quick Summary
