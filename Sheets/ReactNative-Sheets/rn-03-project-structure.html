Sheet 03

Project Structure

app/ · ios/ · android/ · app.json · package.json · metro.config · babel.config · index.js entry

What's in a New App

An Expo app keeps your code in app/ (Expo Router screens) plus shared folders you create. The ios/ and android/ folders are generated by npx expo prebuild and usually git-ignored. A bare CLI app commits those folders and starts from index.js, which registers the root component with AppRegistry.

Conventions

  • app/ — routes (Expo Router); src/ optional
  • components/, hooks/, constants/ — shared code
  • assets/ — images, fonts, splash, icons
  • Native folders are build outputs in Expo, source in bare

Expo Router Layout

MyApp/
├── app/                    # every file is a route
│   ├── _layout.tsx         # root layout (Stack)
│   ├── index.tsx           # "/"
│   └── (tabs)/             # group: tab navigator
├── components/
├── assets/images/
├── app.json                # Expo config (name, icons, plugins)
├── package.json            # "main": "expo-router/entry"
├── tsconfig.json
├── metro.config.js         # optional bundler config
├── ios/  android/          # generated by `expo prebuild`
└── .gitignore

Notes

_layout.tsx — wraps sibling routes
(tabs) — parentheses group routes without adding to the URL
"main" — expo-router/entry boots the router
app.json — single source for native config
Add ios/ and android/ to .gitignore when using CNG

iOS

  • ios/ holds the Xcode project, Podfile and Info.plist
  • Commit Podfile.lock in bare apps; never commit Pods/
  • App icons live in Images.xcassets

Android

  • android/ is a Gradle project; the app module is android/app
  • AndroidManifest.xml declares permissions and activities
  • build/ and .gradle/ are generated — keep out of git

⚠ Common Mistakes

  • Hand-editing ios/ or android/ in an Expo CNG project; the next prebuild --clean wipes it, so use config plugins
  • Renaming index.js or App.tsx without updating main / registerComponent
  • Committing ios/Pods or android/build; they're huge and machine-specific

✓ Tips & Best Practices

  • Use path aliases (@/components) via tsconfig paths; Expo supports them without Babel config
  • Keep platform files next to each other: Button.ios.tsx, Button.android.tsx
  • Treat app.json as the place to change names, icons, and permissions

Quick Summary

  • app/ — routes in Expo Router
  • index.js — bare entry point
  • ios/ · android/ — native projects
  • app.json — native config source
