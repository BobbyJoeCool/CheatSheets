Sheet 05

TypeScript in React Native

tsconfig · @react-native/typescript-config · strict API (0.87) · ViewInstance / TextInputInstance refs · *Props types · deep-import removal

Typed by Default

New Expo and CLI projects are TypeScript out of the box. Metro strips types through Babel, so type errors never block the bundle; run tsc to check. Since 0.87 the react-native package ships a strict API: types are generated from source and only what's exported from the package root is public. Deep imports like react-native/Libraries/... are gone.

Strict API Changes

  • Prop types are *Props; old *Properties aliases removed
  • Ref types: ViewInstance, TextInputInstance, HostInstance
  • NativeMethods types removed → use HostInstance
  • Temporary opt-out works through 0.88 only

Config and Typed Components

// tsconfig.json (bare)
{ "extends": "@react-native/typescript-config",
  "compilerOptions": { "strict": true,
    "paths": { "@/*": ["./src/*"] } } }
// Expo: { "extends": "expo/tsconfig.base" }

import { useRef } from 'react'
import { Pressable, Text, TextInput,
  type PressableProps, type TextInputInstance } from 'react-native'

type Props = PressableProps & { label: string }
export function Btn({ label, ...rest }: Props) {
  return <Pressable {...rest}><Text>{label}</Text></Pressable>
}

const inputRef = useRef<TextInputInstance>(null)
inputRef.current?.focus()

Notes

@react-native/typescript-config — base config for bare apps
expo/tsconfig.base — Expo's base
type imports — erased at build time
PressableProps & {...} — extend built-in props
TextInputInstance — 0.87 ref type for TextInput

iOS

  • Platform.OS === 'ios' narrows to iOS-only fields (isPad)
  • Platform.Version is a string, e.g. '18.2'
  • TS needs a base Button.tsx / .d.ts beside Button.ios.tsx

Android

  • Android-only props are typed too (android_ripple, elevation)
  • Platform.Version is the API level number, e.g. 35
  • Keep .ios.tsx and .android.tsx exports identical

⚠ Common Mistakes

  • Assuming a passing Metro build means types are fine; Babel drops types, so run npx tsc --noEmit in CI
  • Importing from react-native/Libraries/...; 0.87 blocks deep imports, use root exports
  • Typing style as ViewStyle instead of StyleProp<ViewStyle>, which rejects arrays

✓ Tips & Best Practices

  • Add "typecheck": "tsc --noEmit" to scripts and run it before commits
  • Use satisfies for style maps or route params to keep literal types
  • Prefer ComponentProps<typeof Foo> to reuse a third-party component's props

Quick Summary

  • tsc --noEmit — type check separately
  • Strict API — root exports only (0.87)
  • *Props / *Instance — prop & ref types
  • StyleProp<T> — style prop type
