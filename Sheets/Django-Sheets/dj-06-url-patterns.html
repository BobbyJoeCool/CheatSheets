URL Patterns

urlpatterns · path() · re_path() · ROOT_URLCONF · trailing slash · APPEND_SLASH

How URLs Reach Views

Django reads ROOT_URLCONF (usually config.urls) and walks its urlpatterns list top to bottom, stopping at the first pattern that matches the request path. path() uses simple angle-bracket captures; re_path() takes a regular expression. The leading slash and the domain are never part of the match: /blog/2026/ is matched as blog/2026/.

Notes

  • Patterns don't include the leading / or the query string
  • First match wins, so put specific routes above catch-alls
  • APPEND_SLASH = True (default) redirects /about → /about/ when only the slashed version exists
  • No match → Http404 (debug page lists the patterns tried)
  • Captured values arrive as keyword arguments to the view

config/urls.py

from django.contrib import admin
from django.urls import path, re_path
from blog import views

urlpatterns = [
    path("", views.home),                          # /
    path("about/", views.about),                   # /about/
    path("posts/<int:pk>/", views.post_detail),    # /posts/7/ -> pk=7
    path("posts/<slug:slug>/", views.post_by_slug),
    re_path(r"^archive/(?P<year>[0-9]{4})/$", views.archive),
    path("admin/", admin.site.urls),
]

# blog/views.py
def post_detail(request, pk):                      # pk is an int
    ...
def archive(request, year):                        # year is a str
    ...

Code Explained

path(route, view) → the route string is matched against the path
<int:pk> converts the segment and passes pk=7
re_path named groups (?P<year>...) become kwargs, always as str
/posts/7/ hits <int:pk> first; /posts/hello/ falls to <slug>
admin.site.urls is itself a list of patterns

⚠ Common Mistakes

  • Starting a route with / ("/about/"); it never matches because the slash is stripped
  • A catch-all like <slug:slug>/ above about/, which swallows the specific route
  • Expecting re_path captures to be int; they are always strings

✓ Tips & Best Practices

  • Prefer path() and converters; reach for re_path() only for real regex needs
  • Always end routes with / and keep APPEND_SLASH on for consistent URLs
  • Pass kwargs={"template": ...} to reuse one view on several URLs

Quick Summary

  • urlpatterns: ordered list, first match wins
  • path("x/<int:pk>/", view): typed capture
  • re_path(r"^...$", view): regex capture
  • APPEND_SLASH: adds the missing slash
