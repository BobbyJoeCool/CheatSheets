Sheet 49

Permissions & Groups

has_perm() · Group · Meta.permissions · @login_required · @permission_required · {{ perms }}

Who Can Do What

Every model gets four permissions automatically: add, change, delete and view. Permissions are named "app_label.codename" and can be given to users directly or through groups (roles). Check them in code with user.has_perm(), in views with decorators or mixins, and in templates with {{ perms }}. Superusers pass every check.

Notes

  • Add custom permissions in the model's Meta.permissions
  • Permissions are cached on the user object per request
  • Model-level only by default; object-level needs django-guardian or rules
  • Inactive users have no permissions
  • Create groups in a data migration so every environment matches

Defining and Checking

class Report(models.Model):
    class Meta:
        permissions = [("publish_report", "Can publish reports")]

from django.contrib.auth.models import Group, Permission
editors, _ = Group.objects.get_or_create(name="Editors")
perm = Permission.objects.get(codename="publish_report")
editors.permissions.add(perm)
user.groups.add(editors)

user.has_perm("reports.publish_report")          # True
user.has_perms(["reports.view_report", "reports.change_report"])
user.get_all_permissions()                       # {'reports.publish_report', ...}
user.groups.filter(name="Editors").exists()      # role check

@permission_required("reports.publish_report", raise_exception=True)
def publish(request, pk): ...

Templates

{% if perms.reports.publish_report %}<button>Publish</button>{% endif %}
{% if perms.reports %}<a href="...">Reports</a>{% endif %}  {# any perm in app #}

Code Explained

(codename, name) tuples in Meta.permissions
Group members inherit all the group's permissions
has_perms requires every listed permission
raise_exception=True returns 403 instead of redirecting
perms.app is true if the user has any permission in that app

⚠ Common Mistakes

  • Checking user.is_staff for feature access; use specific permissions
  • Wrong label format: has_perm("publish_report") must be "reports.publish_report"
  • Adding a permission then reading has_perm on the same user object; the cache is stale, re-fetch

✓ Tips & Best Practices

  • Model roles as groups (Editors, Support) and assign users to groups
  • Create groups and their permissions in a data migration
  • Filter querysets by owner for simple per-object access

Quick Summary

  • app_label.codename: permission name
  • Group: role = bundle of permissions
  • user.has_perm(): check in code
  • {{ perms.app.codename }}: check in templates
