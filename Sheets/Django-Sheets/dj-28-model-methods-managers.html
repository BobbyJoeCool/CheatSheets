Putting Logic on Models

Keep row-level logic on the model as methods and properties, and table-level logic (reusable filters) on a custom QuerySet exposed through a manager. QuerySet.as_manager() gives you chainable methods like Post.objects.published().recent(). get_absolute_url() and clean() are hooks Django itself calls.

Notes

  • get_absolute_url() is used by redirect(obj), the admin "View on site" and generic views
  • clean() runs in full_clean() and ModelForm validation, not on save()
  • The first manager defined becomes _default_manager
  • A manager that filters rows hides them from the admin too
  • Methods on a QuerySet chain; methods on a Manager don't

Methods, Properties, QuerySets

from django.core.exceptions import ValidationError
from django.urls import reverse
from django.utils import timezone
class PostQuerySet(models.QuerySet):
    def published(self):
        return self.filter(status="P", pub_date__lte=timezone.now())

class Post(models.Model):
    title = models.CharField(max_length=200)
    slug = models.SlugField(unique=True)
    status = models.CharField(max_length=1, default="D")
    pub_date = models.DateTimeField(null=True, blank=True)
    objects = PostQuerySet.as_manager()

    def get_absolute_url(self):
        return reverse("blog:detail", kwargs={"slug": self.slug})
    @property
    def is_live(self):
        return self.status == "P" and self.pub_date <= timezone.now()
    def clean(self):
        if self.status == "P" and not self.pub_date:
            raise ValidationError({"pub_date": "Required to publish."})

Post.objects.published().filter(author=user).order_by("-pub_date")

Code Explained

QuerySet methods return QuerySets, so they chain
as_manager() copies QuerySet methods onto objects
@property reads like a field in templates: {{ post.is_live }}
A dict in ValidationError attaches errors to specific fields
get_absolute_url keeps URL logic in one place

⚠ Common Mistakes

  • Putting filters in views repeatedly instead of a QuerySet method
  • Replacing objects with a filtering manager; the admin and related lookups then miss rows
  • Expecting save() to call clean(); call full_clean() yourself if needed

✓ Tips & Best Practices

  • Name QuerySet methods for business meaning: .published(), .overdue()
  • Use cached_property for expensive per-instance values
  • Keep the unfiltered manager first, add filtered ones after it
