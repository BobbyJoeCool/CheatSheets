Models Map to Tables

A model is a Python class that subclasses models.Model. Each model maps to one database table and each field attribute to one column. Django adds an auto-incrementing id primary key unless you define one, and a default manager called objects for queries. Instances are rows: create them, change attributes, then call save().

Notes

  • Table name is <app_label>_<modelname>, e.g. blog_post
  • 6.0+: the default primary key type is BigAutoField
  • __str__ controls how objects appear in the admin and shell
  • save() does INSERT for new rows and UPDATE for existing ones
  • Run makemigrations + migrate after any model change (Sheet 30)

Defining and Using a Model

# blog/models.py
from django.db import models

class Post(models.Model):
    title = models.CharField(max_length=200)
    body = models.TextField(blank=True)
    published = models.BooleanField(default=False)
    created = models.DateTimeField(auto_now_add=True)

    def __str__(self):
        return self.title

# python manage.py shell
p = Post(title="Hello")            # not in the DB yet
p.save()                           # INSERT; p.id -> 1
p.title = "Hello, Django"
p.save(update_fields=["title"])    # UPDATE only that column
Post.objects.create(title="Two")   # build + save in one step
p.pk                               # 1 (alias for the primary key)
p.refresh_from_db()                # reload from the database
p.delete()                         # (1, {'blog.Post': 1})
Post.objects.count()               # 1

Code Explained

Field classes define the column type and validation
auto_now_add=True sets the time once, on creation
update_fields writes only the listed columns (faster, safer)
objects.create() returns the saved instance
delete() returns the count of deleted rows per model

⚠ Common Mistakes

  • Changing a model and forgetting makemigrations: no such column errors
  • Expecting save() to run full_clean(); validation only runs in forms or manually
  • Overriding save() without calling super().save(*args, **kwargs)

✓ Tips & Best Practices

  • Always define __str__; it makes the admin and debugging far easier
  • Use update_fields in background jobs to avoid overwriting concurrent edits
  • Explore models live with python manage.py shell (models are auto-imported)

Quick Summary

  • class M(models.Model): one table
  • Field attribute = column
  • save() / delete(): write rows
  • M.objects: the query manager
