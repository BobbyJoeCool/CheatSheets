Bulk Ops, Raw SQL & Transactions

bulk_create() · bulk_update() · update_or_create() · raw() · connection.cursor() · transaction.atomic()

Writing Efficiently and Safely

Bulk methods write many rows in a few queries instead of one per object. When the ORM can't express a query, raw() maps SQL results back to models and connection.cursor() runs any SQL. transaction.atomic() groups writes so they all succeed or all roll back; use it for anything that must stay consistent, like moving money between accounts.

Notes

  • bulk_create skips save() and signals
  • update_conflicts=True turns bulk_create into an upsert
  • By default each query autocommits; atomic opens a transaction
  • Nested atomic blocks create savepoints
  • on_commit() runs code only after a successful commit

@transaction.atomic
def transfer(src, dst, amount):
    src = Account.objects.select_for_update().get(pk=src.pk)  # row lock
    src.balance -= amount; src.save()
    dst.balance += amount; dst.save()
    transaction.on_commit(lambda: send_receipt.enqueue(src.pk))

with transaction.atomic():               # block form
    order.save(); order.items.create(sku="A1")

Code Explained

ignore_conflicts=True skips duplicates silently
update_or_create 5.0+: create_defaults only used on insert
Always pass parameters as a list (%s), never f-strings
select_for_update() locks rows until the transaction ends
An exception inside atomic rolls back everything in it

⚠ Common Mistakes

  • Building SQL with f-strings: SQL injection; pass params instead
  • Catching exceptions inside atomic and continuing; the transaction is broken
  • Sending emails inside a transaction that later rolls back; use on_commit

✓ Tips & Best Practices

  • Use batch_size for very large bulk writes to keep queries reasonable
  • Enable ATOMIC_REQUESTS for simple apps that want one transaction per request
  • Wrap data imports in one atomic() so a bad row leaves nothing half-done

Quick Summary

  • bulk_create / bulk_update: many rows, few queries
  • update_or_create: upsert one row
  • raw() / cursor(): SQL with params
  • transaction.atomic(): all or nothing
