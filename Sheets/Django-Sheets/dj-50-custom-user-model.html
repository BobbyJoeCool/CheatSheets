Custom User Model

AbstractUser · AbstractBaseUser · AUTH_USER_MODEL · get_user_model() · BaseUserManager · USERNAME_FIELD

Start with a Custom User

Django's docs recommend creating a custom user model at the start of every project, even if it's identical to the default, because switching later means rewriting migrations. Subclass AbstractUser to keep everything and add fields, or AbstractBaseUser + PermissionsMixin to design the model from scratch (for example, email login with no username). Point AUTH_USER_MODEL at it before the first migrate.

Notes

  • Set AUTH_USER_MODEL = "accounts.User" before the first migration
  • Refer to it as settings.AUTH_USER_MODEL in ForeignKeys
  • Use get_user_model() everywhere else
  • Register it in admin with UserAdmin (or a subclass)
  • Profile data unrelated to auth can live in a separate Profile model

Email Login User

# accounts/models.py
from django.contrib.auth.models import AbstractUser, BaseUserManager

class UserManager(BaseUserManager):
    def create_user(self, email, password=None, **extra):
        user = self.model(email=self.normalize_email(email), **extra)
        user.set_password(password)
        user.save(using=self._db)
        return user
    def create_superuser(self, email, password, **extra):
        extra.update(is_staff=True, is_superuser=True)
        return self.create_user(email, password, **extra)

class User(AbstractUser):
    username = None                          # drop the username field
    email = models.EmailField(unique=True)

    USERNAME_FIELD = "email"                 # log in with email
    REQUIRED_FIELDS = []                     # asked by createsuperuser
    objects = UserManager()

# settings.py
AUTH_USER_MODEL = "accounts.User"

# accounts/admin.py
from django.contrib.auth.admin import UserAdmin
admin.site.register(User, UserAdmin)

Code Explained

Setting username = None removes the inherited field
USERNAME_FIELD names the unique login field
REQUIRED_FIELDS excludes USERNAME_FIELD and password
A custom manager is needed once username is gone
UserAdmin may need ordering/fieldsets tweaks without username

⚠ Common Mistakes

  • Switching AUTH_USER_MODEL mid-project; existing migrations and FKs break
  • from django.contrib.auth.models import User in your code; it ignores the custom model
  • Forgetting to update UserCreationForm/UserChangeForm for the new model

✓ Tips & Best Practices

  • Even if unsure, create class User(AbstractUser): pass on day one
  • Keep auth fields on User; put app-specific data on a Profile
  • Make email lookups case-insensitive with a UniqueConstraint(Lower("email"))

Quick Summary
