The Inner Meta Class

An inner class Meta holds model-level settings that aren't fields: default ordering, human-readable names, the table name, indexes and constraints. Constraints are enforced by the database and checked by full_clean(), so they catch bad data from any source. Changes to Meta usually need a migration.

Notes

  • ordering applies to every query unless overridden with order_by()
  • UniqueConstraint replaces the older unique_together
  • CheckConstraint(condition=Q(...)) enforces rules in SQL (5.1+ uses condition)
  • Conditional unique constraints use condition=
  • Read metadata at runtime through Model._meta

Meta in Practice

from django.db import models
from django.db.models import Q, F
from django.db.models.functions import Lower

class Booking(models.Model):
    room = models.ForeignKey("Room", on_delete=models.CASCADE)
    guest_email = models.EmailField()
    start = models.DateField()
    end = models.DateField()
    cancelled = models.BooleanField(default=False)

    class Meta:
        ordering = ["-start", "room"]
        verbose_name_plural = "bookings"
        indexes = [
            models.Index(fields=["room", "start"]),
            models.Index(Lower("guest_email"), name="booking_email_lower"),
        ]
        constraints = [
            models.CheckConstraint(condition=Q(end__gt=F("start")),
                                   name="booking_end_after_start"),
            models.UniqueConstraint(fields=["room", "start"],
                condition=Q(cancelled=False), name="one_active_booking"),
        ]

Code Explained

"-start" sorts descending; ties broken by room
Indexes on expressions need an explicit name
CheckConstraint → CHECK (end > start) in the database
Conditional unique: only one non-cancelled booking per room/day
Violations raise IntegrityError on save, ValidationError in forms

⚠ Common Mistakes

  • Heavy ordering on huge tables; every query sorts even when you don't need it
  • Duplicate constraint names across models; names must be unique per database
  • Using unique_together in new code; prefer UniqueConstraint

✓ Tips & Best Practices

  • Use %(app_label)s_%(class)s in names on abstract base classes
  • Add indexes for columns you filter or sort by often; check with .explain()
  • Set managed = False for tables owned by another system

Quick Summary

  • class Meta: model-level settings
  • ordering: default sort
  • indexes: speed up lookups
  • constraints: DB-enforced rules
