Querying with QuerySets

A QuerySet is a lazy, chainable description of a database query. Methods like filter() and order_by() return new QuerySets without touching the database; SQL only runs when you evaluate it by iterating, slicing with a step, calling len(), list() or bool(), or printing it. Evaluated results are cached on that QuerySet object.

Notes

  • get() returns one object or raises DoesNotExist / MultipleObjectsReturned
  • first() / last() return None instead of raising
  • Slicing [:10] becomes LIMIT 10; negative indexes aren't supported
  • Chain freely: each call adds to the same SQL
  • Async variants exist: aget(), acreate(), async for

Core QuerySet Calls

Post.objects.all()                            # every row (lazy)
Post.objects.filter(published=True)           # WHERE published
Post.objects.exclude(status="D")              # WHERE NOT status = 'D'
Post.objects.filter(published=True).order_by("-created", "title")
Post.objects.get(pk=1)                        # one object or exception
Post.objects.filter(title="Hi").first()       # object or None
Post.objects.order_by("-created")[:5]         # LIMIT 5
Post.objects.all()[10:20]                     # OFFSET 10 LIMIT 10
Post.objects.create(title="New")              # INSERT, returns obj
Post.objects.get_or_create(slug="hi", defaults={"title": "Hi"})  # (obj, created)
Post.objects.filter(status="D").update(status="P")   # bulk UPDATE -> count
Post.objects.filter(old=True).delete()        # bulk DELETE -> (n, {...})
Post.objects.count()                          # SELECT COUNT(*)
Post.objects.filter(pk=1).exists()            # cheap existence test
Post.objects.values("id", "title")            # dicts
Post.objects.values_list("title", flat=True)  # ['Hi', 'New']
print(Post.objects.filter(pk=1).query)        # the SQL

Code Explained

Nothing above hits the DB until evaluated (except create/get/update/delete/count/exists)
"-created" sorts descending
get_or_create returns a tuple (object, created_bool)
update() and delete() skip save() / delete() methods and signals on update
.query shows SQL without running it

⚠ Common Mistakes

  • if qs: followed by len(qs) on big tables; use exists() / count() when you don't need rows
  • Calling get() with a filter that may match several rows: MultipleObjectsReturned
  • Expecting update() to call save() or auto_now; it writes SQL directly

✓ Tips & Best Practices

  • Reuse an evaluated QuerySet variable to benefit from its cache
  • Use values_list("id", flat=True) when you only need ids
  • Print qs.query or use connection.queries to see the SQL

Quick Summary

  • QuerySets are lazy and chainable
  • filter() / exclude() / order_by()
  • get() raises; first() returns None
  • update() / delete(): bulk writes
