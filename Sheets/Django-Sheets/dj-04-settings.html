The Settings Module

All configuration lives in one Python module, config/settings.py. Django finds it through the DJANGO_SETTINGS_MODULE environment variable, which manage.py, wsgi.py and asgi.py set for you. Settings are plain UPPERCASE module variables; read them anywhere with from django.conf import settings.

Notes

  • DEBUG = True shows detailed error pages; never in production
  • SECRET_KEY signs sessions, cookies and tokens; keep it out of git
  • ALLOWED_HOSTS must list your domains when DEBUG = False
  • BASE_DIR is the project root as a pathlib.Path
  • 6.0: DEFAULT_AUTO_FIELD now defaults to BigAutoField

Typical settings.py

import os
from pathlib import Path

BASE_DIR = Path(__file__).resolve().parent.parent
SECRET_KEY = os.environ["DJANGO_SECRET_KEY"]        # from env
DEBUG = os.environ.get("DJANGO_DEBUG", "0") == "1"
ALLOWED_HOSTS = ["example.com", "www.example.com"]

DATABASES = {
    "default": {
        "ENGINE": "django.db.backends.postgresql",
        "NAME": "mysite", "USER": "mysite",
        "PASSWORD": os.environ["DB_PASSWORD"],
        "HOST": "localhost", "PORT": "5432",
    }
}
LANGUAGE_CODE = "en-us"
TIME_ZONE = "America/Chicago"
USE_TZ = True                                       # store UTC

# anywhere else
from django.conf import settings
settings.DEBUG                                      # False

Code Explained

Path(__file__).resolve().parent.parent → folder holding manage.py
os.environ[...] raises KeyError if the variable is missing (fail fast)
DATABASES["default"] is the connection used unless you pick another
USE_TZ = True stores aware datetimes in UTC; TIME_ZONE is for display
Import django.conf.settings, never config.settings directly

⚠ Common Mistakes

  • Committing SECRET_KEY or DB passwords; anyone with the repo can forge sessions
  • DEBUG = False with an empty ALLOWED_HOSTS: every request returns 400
  • Importing config.settings directly, which skips overrides from --settings

✓ Tips & Best Practices

  • Load secrets from environment variables or a .env file via python-dotenv
  • Use manage.py diffsettings to see only what you changed from defaults
  • Keep USE_TZ = True; convert to local time only when displaying

Quick Summary

  • DJANGO_SETTINGS_MODULE: which settings file
  • DEBUG: dev error pages, off in prod
  • DATABASES: connection config
  • from django.conf import settings: read values
