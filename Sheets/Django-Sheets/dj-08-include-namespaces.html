Sheet 08

include() & Namespaces

include() · app_name · namespace · "app:name" · per-app urls.py · handler404

Splitting the URLconf

include() hands the rest of a path to another URLconf, so each app keeps its own urls.py. Setting app_name in that file creates an application namespace, and names are then reversed as "blog:detail", which stops two apps' detail routes from clashing. Custom error views are set with handler404 and friends in the root URLconf.

Notes

  • The prefix matched so far is stripped before the included patterns run
  • include() also accepts a list of path() objects
  • namespace= on include() creates an instance namespace
  • Error handlers only work in the root URLconf with DEBUG = False
  • request.resolver_match shows which pattern matched

Root and App URLconfs

# config/urls.py
from django.urls import include, path

urlpatterns = [
    path("blog/", include("blog.urls")),            # /blog/...
    path("api/v1/", include(("api.urls", "api"), namespace="v1")),
    path("shop/", include([
        path("", shop_home, name="shop-home"),
        path("cart/", cart, name="cart"),
    ])),
]
handler404 = "config.views.not_found"
handler500 = "config.views.server_error"

# blog/urls.py
from django.urls import path
from . import views

app_name = "blog"                                    # namespace
urlpatterns = [
    path("", views.post_list, name="list"),          # /blog/
    path("<int:pk>/", views.post_detail, name="detail"),
]

reverse("blog:detail", args=[3])                     # '/blog/3/'

Template

<a href="{% url 'blog:detail' post.pk %}">Read more</a>

Code Explained

include("blog.urls") takes a dotted module path
A (module, app_name) tuple sets the namespace without editing the app
app_name = "blog" makes names reversible as blog:...
handler404 takes a dotted path to a view(request, exception)
handler500 views take only request

⚠ Common Mistakes

  • Forgetting the trailing slash in path("blog", include(...)), so /blog/1/ never matches
  • Reversing "detail" when the app has app_name; you must use "blog:detail"
  • Testing a custom 404 with DEBUG = True; Django shows its debug page instead

✓ Tips & Best Practices

  • Give every app its own urls.py with app_name
  • Just add templates/404.html; you rarely need a custom handler404
  • Keep 500.html static: it renders with no context and no DB access

Quick Summary

  • include("app.urls"): delegate a prefix
  • app_name: namespace for app:name
  • namespace=: instance namespace
  • handler404: custom error view
