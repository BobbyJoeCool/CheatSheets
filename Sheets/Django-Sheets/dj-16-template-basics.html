The Template System

The Django Template Language (DTL) turns a text file plus a context dict into HTML. The TEMPLATES setting picks the engine and where to look: DIRS lists project-level folders and APP_DIRS = True also searches each installed app's templates/ folder. Views usually call render(), which loads, renders and wraps the result in an HttpResponse.

Notes

  • Templates hold presentation only; no arbitrary Python runs in them
  • Lookup order: DIRS first, then each app in INSTALLED_APPS order
  • Namespace app templates: blog/templates/blog/list.html
  • Missing variables render as an empty string (not an error)
  • Jinja2 is a built-in alternative backend

Configuration and Rendering

# settings.py
TEMPLATES = [{
    "BACKEND": "django.template.backends.django.DjangoTemplates",
    "DIRS": [BASE_DIR / "templates"],          # project-wide templates
    "APP_DIRS": True,                          # + <app>/templates/
    "OPTIONS": {"context_processors": [
        "django.template.context_processors.request",
        "django.contrib.auth.context_processors.auth",
        "django.contrib.messages.context_processors.messages",
    ]},
}]

# views.py
from django.shortcuts import render
from django.template.loader import render_to_string

def home(request):
    ctx = {"title": "Welcome", "items": Item.objects.all()[:5]}
    return render(request, "home.html", ctx)

html = render_to_string("emails/welcome.txt", {"user": u})  # str only

templates/home.html

<h1>{{ title }}</h1>
{% for item in items %}<p>{{ item.name }}</p>{% endfor %}

Code Explained

DIRS takes a list of paths; checked before app folders
Context processors add variables (request, user, messages) to every render()
render() → HttpResponse; render_to_string() → str
{{ }} outputs a value; {% %} runs a tag
Context values can be any Python object

⚠ Common Mistakes

  • Putting blog/templates/list.html without the inner blog/; another app's list.html may win
  • Forgetting APP_DIRS: True, so app templates raise TemplateDoesNotExist
  • Doing heavy queries inside templates via method calls; do them in the view

✓ Tips & Best Practices

  • Keep a project-level templates/ for base.html, 404.html and overrides
  • Read the "Template-loader postmortem" on the debug page to see every path tried
  • Add string_if_invalid in dev OPTIONS to spot missing variables

Quick Summary

  • TEMPLATES: engine + search paths
  • render(request, name, ctx): HTML response
  • {{ }} / {% %}: output / logic
  • Context processors: global variables
