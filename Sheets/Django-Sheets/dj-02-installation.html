Installing Django

Always install Django into a virtual environment so each project has its own Python packages and Django version. Use the standard-library venv module with pip, or the faster uv tool. Record dependencies in requirements.txt (pip) or pyproject.toml + uv.lock (uv) so the project can be rebuilt anywhere.

Notes

  • Django 6.x needs Python 3.12+; check with python3 --version
  • Activate the venv before every pip or manage.py command
  • Pin versions: Django>=6.1,<6.2 avoids surprise upgrades
  • Add .venv/ to .gitignore; commit the requirements file instead
  • Database drivers are separate: psycopg[binary] for PostgreSQL, mysqlclient for MySQL

venv + pip

python3 -m venv .venv                 # create the environment
source .venv/bin/activate             # macOS/Linux
.venv\Scripts\activate                # Windows
python -m pip install --upgrade pip
pip install "Django>=6.1,<6.2"        # install Django
python -m django --version            # 6.1.1
pip freeze > requirements.txt         # save exact versions
pip install -r requirements.txt       # rebuild elsewhere
deactivate                            # leave the venv

uv (fast alternative)

uv init mysite && cd mysite           # pyproject.toml + .venv
uv add django "psycopg[binary]"       # install + lock
uv run django-admin startproject config .
uv run python manage.py runserver     # no activate needed
uv sync                               # rebuild from uv.lock

Code Explained

python3 -m venv .venv creates an isolated interpreter in .venv/
source .venv/bin/activate puts that interpreter first on PATH
Quote version specifiers so the shell doesn't treat < as a redirect
pip freeze lists every installed package with exact versions
uv run runs a command inside the project venv without activating it

⚠ Common Mistakes

  • Installing Django globally with sudo pip, so projects fight over versions
  • Running manage.py without activating the venv: ModuleNotFoundError: django
  • Committing .venv/ to git; it is machine-specific and huge

✓ Tips & Best Practices

  • Name the venv .venv so editors (VS Code, PyCharm) find it automatically
  • Split requirements/base.txt, dev.txt and prod.txt for larger projects
  • Use uv in CI: installs are many times faster than pip

Quick Summary

  • python3 -m venv .venv: create
  • pip install django: install
  • pip freeze > requirements.txt: record
  • uv add django: uv equivalent
