Languages and Time Zones

i18n marks strings for translation in Python (gettext) and templates ({% translate %}); makemessages extracts them into .po files, translators fill them in, and compilemessages builds .mo files Django reads. LocaleMiddleware picks the language per request. For time, keep USE_TZ = True: datetimes are stored in UTC and converted to the active time zone for display.

Notes

  • Use gettext_lazy for strings defined at import time (models, forms)
  • makemessages needs GNU gettext installed
  • Use timezone.now(), never datetime.now(), when USE_TZ = True
  • timezone.activate(tz) sets the display zone per request
  • i18n_patterns() adds /en/, /fr/ URL prefixes

Python and Settings

from django.utils.translation import gettext as _, gettext_lazy, ngettext
from django.utils import timezone
import zoneinfo

class Post(models.Model):
    title = models.CharField(gettext_lazy("title"), max_length=200)

msg = _("Welcome back!")
items = ngettext("%(n)d item", "%(n)d items", n) % {"n": n}

LANGUAGE_CODE = "en"
LANGUAGES = [("en", "English"), ("es", "Español")]
LOCALE_PATHS = [BASE_DIR / "locale"]     # makemessages -l es / compilemessages
MIDDLEWARE += ["django.middleware.locale.LocaleMiddleware"]  # after Session
USE_TZ, TIME_ZONE = True, "UTC"

timezone.now()                                # aware UTC datetime
timezone.localtime(post.created)              # in the active zone
timezone.activate(zoneinfo.ZoneInfo("America/Chicago"))

Template and Commands

{% load i18n tz %}
<h1>{% translate "Latest posts" %}</h1>
{% blocktranslate count n=posts|length %}{{ n }} post{% plural %}
  {{ n }} posts{% endblocktranslate %}
{% timezone "Europe/Paris" %}{{ post.created }}{% endtimezone %}

Code Explained

_ is the usual alias for gettext
ngettext picks singular or plural
LocaleMiddleware goes after SessionMiddleware, before CommonMiddleware
Templates convert to the active zone automatically
{% blocktranslate count %} handles plurals in templates

⚠ Common Mistakes

  • gettext (not lazy) in model fields or forms, so labels freeze in the startup language
  • datetime.now() with USE_TZ = True: naive datetime warnings and wrong times
  • Forgetting compilemessages; edited .po files have no effect

✓ Tips & Best Practices

  • Store each user's time zone and activate it in middleware
  • Use Rosetta or Weblate to let translators edit .po files
  • Wrap strings for translation from day one, even with one language

Quick Summary

  • gettext_lazy: model/form labels
  • {% translate %}: template strings
  • makemessages → .po → compilemessages
  • timezone.now(): aware UTC
