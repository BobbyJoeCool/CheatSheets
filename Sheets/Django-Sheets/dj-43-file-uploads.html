File & Image Uploads

request.FILES · enctype · FileField · ImageField · upload_to · MEDIA_ROOT · MEDIA_URL

Accepting User Files

Uploaded files arrive in request.FILES, but only when the form uses method="post" and enctype="multipart/form-data". A model FileField or ImageField stores the path in the database and saves the file through the storage backend under MEDIA_ROOT. MEDIA_URL is the public URL prefix; in development you add a URL pattern to serve those files.

Notes

  • Pass request.FILES as the second argument to the form
  • ImageField checks the file really is an image (needs Pillow)
  • upload_to can be a string with date codes or a function
  • Deleting a model row does not delete its file
  • Use django-storages to store files on S3 or similar

Settings, Model, View

# settings.py
MEDIA_URL = "media/"
MEDIA_ROOT = BASE_DIR / "media"

# models.py
def avatar_path(instance, filename):
    return f"avatars/user_{instance.user_id}/{filename}"

class Profile(models.Model):
    user = models.OneToOneField(User, on_delete=models.CASCADE)
    avatar = models.ImageField(upload_to=avatar_path, blank=True)
    resume = models.FileField(upload_to="resumes/%Y/%m/", blank=True,
        validators=[FileExtensionValidator(["pdf"])])

# views.py
form = ProfileForm(request.POST, request.FILES, instance=profile)

profile.avatar.url        # '/media/avatars/user_7/me.png'
profile.resume.delete(save=True)   # remove file and clear field

# urls.py (development only)
from django.conf import settings
from django.conf.urls.static import static
urlpatterns += static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)

Code Explained

upload_to function gets the instance and original filename
Duplicate names get a random suffix automatically
.url is for templates; .path only works on local storage
FileExtensionValidator checks the extension (not the contents)
static() helper only works when DEBUG = True

⚠ Common Mistakes

  • Missing enctype="multipart/form-data": request.FILES is empty and the form says "required"
  • Trusting content_type or the extension; validate contents for anything risky
  • Serving user uploads from the same domain without care; HTML/SVG files can run scripts

✓ Tips & Best Practices

  • Store uploads on object storage (S3, GCS) via django-storages in production
  • Put uploads under per-user folders with an upload_to function
  • Clean up orphaned files with a post_delete signal or a periodic task

Quick Summary

  • enctype="multipart/form-data": required
  • Form(request.POST, request.FILES)
  • FileField / ImageField(upload_to=)
  • MEDIA_ROOT / MEDIA_URL: storage + URL
