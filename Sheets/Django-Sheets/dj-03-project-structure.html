Projects and Apps

A project is the whole site: settings, root URLconf and WSGI/ASGI entry points. An app is a self-contained Python package that does one job (blog, accounts, payments) and can be reused across projects. A project contains many apps, and an app only becomes active once it is listed in INSTALLED_APPS.

Notes

  • django-admin startproject config . puts manage.py in the current folder
  • Naming the project package config keeps it clearly separate from apps
  • startapp creates the package but does not register it
  • Each app has an AppConfig in apps.py; ready() runs at startup
  • Templates and static files can live inside apps: blog/templates/blog/

Create and Register

django-admin startproject config .    # project package + manage.py
python manage.py startapp blog        # new app package

Resulting Layout

mysite/
├── manage.py               # command-line entry point
├── config/                 # the project package
│   ├── settings.py         # all configuration
│   ├── urls.py             # root URLconf
│   ├── asgi.py / wsgi.py   # server entry points
└── blog/                   # an app
    ├── apps.py             # AppConfig
    ├── models.py  views.py  admin.py  tests.py
    ├── migrations/         # schema history
    └── urls.py             # add yourself

# config/settings.py
INSTALLED_APPS = [
    "django.contrib.admin", "django.contrib.auth",  # ...4 more
    "blog",                         # or "blog.apps.BlogConfig"
]

Code Explained

The trailing . stops Django nesting mysite/mysite/
apps.py holds BlogConfig(AppConfig) with name = "blog"
Listing "blog" finds the default AppConfig automatically
Apps are found by dotted Python path, so blog must be importable
Django creates urls.py for the project but not for apps

⚠ Common Mistakes

  • Forgetting to add the app to INSTALLED_APPS, so models and templates are ignored
  • Giving an app the same name as a Python module (email, test), which shadows imports
  • One giant app for everything; split by domain so pieces stay reusable

✓ Tips & Best Practices

  • Use startproject config . for a flat, readable layout
  • Namespace app templates: blog/templates/blog/post_list.html
  • Move to an apps/ folder only when you have many apps

Quick Summary

  • startproject: the site + settings
  • startapp: one feature package
  • INSTALLED_APPS: activates apps
  • AppConfig.ready(): startup hook
