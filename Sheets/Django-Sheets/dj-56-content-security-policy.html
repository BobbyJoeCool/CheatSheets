Content Security Policy

ContentSecurityPolicyMiddleware · SECURE_CSP · SECURE_CSP_REPORT_ONLY · CSP constants · nonces · csp() context processor

CSP Built In (Django 6.0)

A Content Security Policy header tells the browser which sources of scripts, styles, images and frames are allowed, so injected scripts can't run even if escaping fails. Django 6.0 adds native support: enable ContentSecurityPolicyMiddleware, describe the policy as a dict in SECURE_CSP, and use CSP.NONCE with {{ csp_nonce }} to allow specific inline scripts.

Notes

  • SECURE_CSP sends an enforced Content-Security-Policy header
  • SECURE_CSP_REPORT_ONLY only reports violations (use it first)
  • Constants live in django.utils.csp.CSP
  • Per-view overrides replace the policy; {} disables it
  • Django doesn't collect reports; point report-uri at your endpoint

settings.py

from django.utils.csp import CSP

MIDDLEWARE += ["django.middleware.csp.ContentSecurityPolicyMiddleware"]
TEMPLATES[0]["OPTIONS"]["context_processors"] += [
    "django.template.context_processors.csp"]       # adds csp_nonce
SECURE_CSP = {
    "default-src": [CSP.SELF],
    "script-src": [CSP.SELF, CSP.NONCE],
    "style-src": [CSP.SELF, "https://fonts.googleapis.com"],
    "img-src": [CSP.SELF, "data:", "https:"],
    "frame-ancestors": [CSP.NONE],
}
SECURE_CSP_REPORT_ONLY = {"default-src": [CSP.SELF], "report-uri": "/csp/"}

Template

<script nonce="{{ csp_nonce }}">initPage();</script>

Per-View

from django.views.decorators.csp import csp_override
@csp_override({"default-src": [CSP.SELF], "img-src": [CSP.SELF, "data:"]})
def gallery(request): ...
@csp_override({})                                    # no CSP header
def legacy_widget(request): ...

Code Explained

CSP.NONCE becomes 'nonce-<random>' per request
Only scripts with the matching nonce attribute run
Header: script-src 'self' 'nonce-…'
frame-ancestors 'none' is the modern clickjacking guard
Report-only and enforced headers can be sent together

⚠ Common Mistakes

  • Enforcing a strict policy on day one; the admin or third-party scripts break
  • Adding CSP.UNSAFE_INLINE to script-src, which removes most XSS protection
  • Caching full pages that contain {{ csp_nonce }}; reused nonces weaken the policy

✓ Tips & Best Practices

  • Start with SECURE_CSP_REPORT_ONLY and watch the browser console
  • Move inline scripts to static files so few nonces are needed
  • 6.1 adds a {% csp_nonce_attr %} tag and nonces in built-in templates

Quick Summary

  • ContentSecurityPolicyMiddleware: sends headers
  • SECURE_CSP = {directive: [sources]}
  • CSP.NONCE + {{ csp_nonce }}: inline scripts
  • @csp_override: per-view policy
