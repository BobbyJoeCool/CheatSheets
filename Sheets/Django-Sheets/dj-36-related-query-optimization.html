Related Objects & Query Optimization

select_related() · prefetch_related() · Prefetch() · only() · defer() · N+1 problem · exists()

Avoiding the N+1 Problem

Accessing a related object in a loop runs one extra query per row: the N+1 problem. select_related() follows ForeignKey and one-to-one links with a SQL JOIN in the same query. prefetch_related() fetches many-to-many and reverse relations in one extra query and joins them in Python. only() and defer() limit which columns load. 6.1 adds fetch modes that can fix N+1 automatically.

Notes

  • select_related: FK / 1:1 forward (JOIN)
  • prefetch_related: M2M and reverse FK (separate query)
  • Prefetch() customizes the prefetched QuerySet
  • Calling .filter() on a prefetched relation ignores the prefetch
  • 6.1: fetch_mode(models.FETCH_PEERS) batch-loads on first access

Before and After

# N+1: 1 query for posts + 1 per post for author
for post in Post.objects.all():
    print(post.author.name)

# 1 query with a JOIN
for post in Post.objects.select_related("author", "author__profile"):
    print(post.author.name)

# 2 queries total: posts, then all their tags
posts = Post.objects.prefetch_related("tags")
for p in posts:
    print([t.name for t in p.tags.all()])

from django.db.models import Prefetch
Author.objects.prefetch_related(Prefetch("post_set",
    queryset=Post.objects.filter(status="P").order_by("-created"),
    to_attr="live_posts"))                # author.live_posts is a list

Post.objects.only("id", "title")          # load just these columns
Post.objects.defer("body")                # load all but body

from django.db import models               # Django 6.1
Book.objects.fetch_mode(models.FETCH_PEERS)   # auto batch-load
Book.objects.fetch_mode(models.FETCH_RAISE)   # error on lazy load

Code Explained

author__profile chains joins through two FKs
Prefetch results are cached on each object
to_attr stores filtered results as a plain list
Accessing a deferred field later triggers another query
FETCH_RAISE is useful in tests to catch N+1

⚠ Common Mistakes

  • select_related("tags") on an M2M: FieldError; use prefetch_related
  • p.tags.filter(...) inside the loop, which ignores the prefetch and queries again
  • Using only() then touching other fields in templates, causing hidden extra queries

✓ Tips & Best Practices

  • Add select_related in list views' get_queryset() by default
  • Guard key views with assertNumQueries in tests
  • Use exists() / count() instead of loading rows just to check

Quick Summary

  • select_related(): JOIN for FK/1:1
  • prefetch_related(): extra query for M2M/reverse
  • only() / defer(): fewer columns
  • fetch_mode() (6.1): auto N+1 handling
