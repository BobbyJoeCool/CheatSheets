Extending the Template Language

When built-ins aren't enough, write your own. Create a templatetags/ package in an app, make a module with a template.Library() named register, and decorate functions as filters, simple tags or inclusion tags. Templates load the module by its file name with {% load %}. Context processors are the other extension point: functions that add variables to every template.

Notes

  • templatetags/ needs an __init__.py; restart runserver after creating it
  • Filters take one value and at most one argument
  • simple_tag takes any arguments and returns a string
  • inclusion_tag renders a small template with its own context
  • Mark returned HTML with format_html() so it's escaped correctly

blog/templatetags/blog_extras.py

from django import template
from django.utils.html import format_html

register = template.Library()

@register.filter
def initials(value):                          # {{ name|initials }}
    return "".join(w[0].upper() for w in value.split())

@register.simple_tag(takes_context=True)
def active(context, url_name):                # {% active 'home' %}
    match = context["request"].resolver_match
    return "active" if match and match.url_name == url_name else ""

@register.simple_tag
def badge(text, color="blue"):                # {% badge "New" color="red" %}
    return format_html('<span class="{}">{}</span>', color, text)

@register.inclusion_tag("blog/_recent.html")
def recent_posts(count=5):                    # {% recent_posts 3 %}
    return {"posts": Post.objects.order_by("-created")[:count]}

Usage

{% load blog_extras %}
{{ "Ada Lovelace"|initials }}  {% badge "New" %}  {% recent_posts 3 %}

Code Explained

The module name (blog_extras) is what {% load %} uses
takes_context=True passes the template context first
format_html escapes the arguments but keeps the markup
Inclusion tags return a context dict for their own template
Context processor: def site(request): return {"SITE_NAME": ...}

⚠ Common Mistakes

  • Returning raw f-string HTML from a tag; it's escaped, or worse, unsafe with mark_safe
  • Naming the tag module the same as an app (blog.py), which confuses imports
  • Running queries in a filter used inside a loop, creating N+1 queries

✓ Tips & Best Practices

  • Add "builtins": ["blog.templatetags.blog_extras"] to OPTIONS to skip {% load %}
  • Keep context processors cheap; they run on every render()
  • Test tags with Template("{% load x %}...").render(Context({...}))
