Validation Order

Validation runs in layers when you call is_valid(). First each field converts and checks its own value, plus any validators. Then each clean_<fieldname>() method runs for single-field rules and must return the cleaned value. Finally clean() runs for rules that involve several fields. Raise ValidationError to reject input, or call add_error() to attach a message to a specific field.

Notes

  • clean_<field> only runs if that field passed its own checks
  • In clean(), fields that failed earlier are missing from cleaned_data
  • Errors raised in clean() become non-field errors
  • Give errors a code so tests and templates can check them
  • Reusable validators are plain functions that raise ValidationError

Field and Form Validation

from django import forms
from django.core.exceptions import ValidationError

def no_profanity(value):                                  # reusable validator
    if "darn" in value.lower():
        raise ValidationError("Please keep it clean.", code="profanity")

class EventForm(forms.Form):
    title = forms.CharField(validators=[no_profanity])
    start = forms.DateField()
    end = forms.DateField()

    def clean_title(self):                                # one field
        title = self.cleaned_data["title"].strip()
        if Event.objects.filter(title__iexact=title).exists():
            raise ValidationError("That title is taken.", code="duplicate")
        return title                                      # must return!

    def clean(self):                                      # several fields
        cleaned = super().clean()
        start, end = cleaned.get("start"), cleaned.get("end")
        if start and end and end < start:
            self.add_error("end", "End must be after start.")
        return cleaned

Code Explained

Validators run during field cleaning, before clean_<field>
Use .get() in clean(): earlier failures remove keys
add_error("end", ...) attaches to the end field
add_error(None, ...) adds a non-field error
Returning a modified value (strip()) changes cleaned_data

⚠ Common Mistakes

  • Forgetting return in clean_<field>(), which sets the value to None
  • self.cleaned_data["start"] in clean() when start failed: KeyError
  • Raising in clean() for a single-field problem; the error shows at the top, not by the field

✓ Tips & Best Practices

  • Put rules that also apply outside forms on the model's clean() instead
  • Pass params to ValidationError for translatable messages: "%(value)s is taken"
  • Test validation by asserting on form.errors and form.has_error("f", code=...)

Quick Summary

  • validators=[...]: reusable checks
  • clean_<field>(): one field, return value
  • clean(): cross-field rules
  • add_error(field, msg): targeted errors
