Converters & Named URLs

<int:pk> · <slug:> · custom converters · name= · reverse() · {% url %} · reverse_lazy()

Converters and Reversing

A path converter validates and converts a captured segment, so <int:pk> only matches digits and hands the view an int. Giving a pattern a name= lets you build its URL from code with reverse() or from templates with {% url %}, so changing a route never breaks links. Use reverse_lazy() where URLs are needed at import time.

Notes

  • Converters: str (default), int, slug, uuid, path
  • str matches any non-empty text without /; path includes /
  • Custom converters need regex, to_python() and to_url()
  • reverse() raises NoReverseMatch if the name or args are wrong
  • redirect("post-detail", pk=7) reverses for you

Naming and Reversing

# urls.py
from django.urls import path, register_converter
from . import views, converters

register_converter(converters.YearConverter, "yyyy")
urlpatterns = [
    path("posts/<int:pk>/", views.detail, name="post-detail"),
    path("archive/<yyyy:year>/", views.archive, name="archive"),
]

# converters.py
class YearConverter:
    regex = r"[0-9]{4}"
    def to_python(self, value): return int(value)
    def to_url(self, value): return f"{value:04d}"

from django.urls import reverse, reverse_lazy
reverse("post-detail", args=[7])          # '/posts/7/'
reverse("post-detail", kwargs={"pk": 7})  # '/posts/7/'
success_url = reverse_lazy("post-list")   # safe at class level

In Templates

<a href="{% url 'post-detail' post.pk %}">{{ post.title }}</a>
{% url 'archive' year=2026 as archive_url %}

Code Explained

register_converter adds <yyyy:...> to the pattern syntax
to_python feeds the view; to_url is used when reversing
Pass args or kwargs to reverse, never both
reverse_lazy delays lookup until the string is used
{% url ... as var %} stores the URL instead of printing it

⚠ Common Mistakes

  • Hard-coding /posts/7/ in templates; one route change breaks every link
  • Calling reverse() in a class attribute; URLconf isn't loaded yet, use reverse_lazy()
  • Using <str:path> for file paths; it stops at /, use the path converter

✓ Tips & Best Practices

  • Name every route; use app:name with namespaces (Sheet 08)
  • Use <uuid:...> for public IDs so URLs don't reveal row counts
  • Add get_absolute_url() on models and call it from templates

Quick Summary

  • <int:pk>: validate + convert
  • name="...": reversible route
  • reverse() / {% url %}: build URLs
  • reverse_lazy(): import-time safe
