Q & F Expressions

Q() · | & ~ · F() · F() arithmetic · update(F()) · Value() · Case / When

Complex Conditions and Column References

Q objects wrap lookups so they can be combined with | (OR), & (AND) and ~ (NOT). F expressions refer to another column's value inside the database, so you can compare two fields or update a counter without reading it into Python first, which also avoids race conditions. Case/When builds SQL CASE expressions.

Notes

  • Q objects must come before keyword arguments in filter()
  • F("views") + 1 runs as SQL: views = views + 1
  • After an F() update, call refresh_from_db() to see the new value
  • Value() wraps a literal for use in expressions
  • Expressions also work in order_by() and annotate()

Q, F, Case/When

from django.db.models import Q, F, Value, Case, When, CharField
from django.db.models.functions import Concat

# OR / NOT
Post.objects.filter(Q(status="P") | Q(author=request.user))
Post.objects.filter(~Q(status="D"), views__gt=10)   # Q first
q = Q()
if term:  q &= Q(title__icontains=term)              # build dynamically
if tag:   q &= Q(tags__name=tag)
Post.objects.filter(q)

# compare two columns
Product.objects.filter(stock__lt=F("reorder_level"))
Event.objects.filter(end__gt=F("start") + timedelta(hours=1))

# atomic update, no race condition
Post.objects.filter(pk=pk).update(views=F("views") + 1)
post.views = F("views") + 1; post.save(update_fields=["views"])

# CASE WHEN
Order.objects.annotate(size=Case(
    When(total__gte=500, then=Value("large")),
    When(total__gte=100, then=Value("medium")),
    default=Value("small"), output_field=CharField()))
User.objects.annotate(full=Concat("first_name", Value(" "), "last_name"))
Post.objects.order_by(F("pub_date").desc(nulls_last=True))

Code Explained

Q() &= ... lets you add conditions only when inputs exist
F("start") + timedelta does date math in SQL
update(views=F(...) + 1) is safe under concurrent requests
Case/When evaluates conditions top to bottom
nulls_last=True controls where NULLs sort

⚠ Common Mistakes

  • Putting a keyword arg before a Q in filter(): SyntaxError
  • post.views += 1; post.save() under load; two requests lose an increment, use F()
  • Reading post.views right after an F() save; it's an expression until refreshed

✓ Tips & Best Practices

  • Build search filters with q = Q() and &= / |=
  • Use Coalesce("nickname", "username") for fallbacks in SQL
  • Mix F() with ExpressionWrapper when the output type differs

Quick Summary

  • Q(...) | Q(...): OR conditions
  • ~Q(...): NOT
  • F("field"): column reference in SQL
  • Case(When(...)): conditional values
