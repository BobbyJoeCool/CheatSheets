Static Files

STATIC_URL · STATICFILES_DIRS · STATIC_ROOT · {% load static %} · {% static %} · collectstatic

CSS, JavaScript and Images

Static files are the assets you ship with the code: CSS, JavaScript, fonts and images. In development django.contrib.staticfiles serves them from each app's static/ folder and from STATICFILES_DIRS. For production, collectstatic copies everything into STATIC_ROOT, where a web server, CDN or WhiteNoise serves it. User uploads are media, not static (Sheet 43).

Notes

  • Namespace app assets: blog/static/blog/style.css
  • {% static %} builds the URL, so changing STATIC_URL never breaks links
  • runserver serves static files only when DEBUG = True
  • ManifestStaticFilesStorage adds content hashes for cache-busting
  • STORAGES["staticfiles"] picks the storage backend

Settings

STATIC_URL = "static/"                          # URL prefix
STATICFILES_DIRS = [BASE_DIR / "static"]        # project-level assets
STATIC_ROOT = BASE_DIR / "staticfiles"          # collectstatic target
STORAGES = {
    "default": {"BACKEND": "django.core.files.storage.FileSystemStorage"},
    "staticfiles": {"BACKEND":
        "django.contrib.staticfiles.storage.ManifestStaticFilesStorage"},
}

Template

{% load static %}
<link rel="stylesheet" href="{% static 'css/site.css' %}">
<img src="{% static 'blog/logo.png' %}" alt="Logo">
<script src="{% static 'js/app.js' %}" defer></script>

Commands

python manage.py findstatic css/site.css      # which file wins?
python manage.py collectstatic --noinput      # copy to STATIC_ROOT

Code Explained

{% load static %} is needed once per template file
{% static 'css/site.css' %} → /static/css/site.a1b2c3.css with the manifest
STATIC_ROOT must differ from every STATICFILES_DIRS entry
findstatic shows search order when two files share a name
Run collectstatic on every deploy

⚠ Common Mistakes

  • Hard-coding /static/css/site.css; it breaks with a CDN or hashed filenames
  • Pointing STATIC_ROOT at a STATICFILES_DIRS folder: ImproperlyConfigured
  • Static files 404 after DEBUG = False; you need WhiteNoise or a web server

✓ Tips & Best Practices

  • Add WhiteNoise early; it makes static serving work the same everywhere
  • Use hashed filenames + long cache headers for fast repeat loads
  • Keep build tools (Vite, Tailwind) outputting into a STATICFILES_DIRS folder

Quick Summary

  • {% static 'path' %}: asset URL
  • STATICFILES_DIRS: source folders
  • collectstatic → STATIC_ROOT
  • Manifest storage: cache-busting
