Many-to-Many & One-to-One

ManyToManyField · through= · add() / remove() / set() · OneToOneField · reverse accessor

M2M and 1:1 Links

A ManyToManyField links many rows to many rows (posts ↔ tags) through a hidden join table. You manage links with add(), remove(), set() and clear() rather than assigning. Use through= to supply your own join model when the link needs extra data, such as a join date. A OneToOneField is a unique ForeignKey, ideal for extending a model like User with a profile.

Notes

  • Declare the M2M on either model; the other side gets a reverse accessor
  • Both objects must be saved before calling add()
  • set() replaces the whole set; add() keeps existing links
  • With a through model, pass through_defaults= to add()
  • One-to-one reverse access raises DoesNotExist if missing

M2M and One-to-One

class Tag(models.Model):
    name = models.CharField(max_length=30, unique=True)

class Post(models.Model):
    title = models.CharField(max_length=200)
    tags = models.ManyToManyField(Tag, related_name="posts", blank=True)

post.tags.add(django, python)          # link (no duplicates)
post.tags.remove(python)               # unlink
post.tags.set([django, web])           # replace all links
post.tags.clear()                      # remove every link
django.posts.all()                     # reverse side
Post.objects.filter(tags__name="django")

class Membership(models.Model):        # custom join table
    person = models.ForeignKey("Person", on_delete=models.CASCADE)
    group = models.ForeignKey("Group", on_delete=models.CASCADE)
    joined = models.DateField()
class Group(models.Model):
    members = models.ManyToManyField("Person", through="Membership")
group.members.add(ann, through_defaults={"joined": date.today()})

class Profile(models.Model):
    user = models.OneToOneField(settings.AUTH_USER_MODEL,
                                on_delete=models.CASCADE)
user.profile.bio                       # reverse 1:1 (no _set)

Code Explained

add() / remove() write to the join table immediately
tags__name filters across the M2M (may duplicate rows; use .distinct())
through= model holds the two FKs plus extra columns
through_defaults fills the extra columns on add()
One-to-one reverse uses the lowercase model name: user.profile

⚠ Common Mistakes

  • post.tags = [t1, t2]: direct assignment is not allowed, use set()
  • Calling add() on an unsaved object: ValueError (needs a primary key)
  • Forgetting .distinct() when filtering across M2M, so rows appear twice

✓ Tips & Best Practices

  • Start with through= if the link might ever need extra data; migrating later is painful
  • Create profiles in a post_save signal or lazily with get_or_create
  • Use prefetch_related("tags") when listing objects with their tags

Quick Summary

  • ManyToManyField: join table
  • add / remove / set / clear: manage links
  • through=: extra link data
  • OneToOneField: unique FK
