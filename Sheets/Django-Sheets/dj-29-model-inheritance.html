Model Inheritance

abstract = True · multi-table inheritance · proxy = True · TimeStampedModel pattern · parent_link

Three Kinds of Inheritance

Django supports three styles. Abstract base classes share fields and methods but create no table of their own. Multi-table inheritance gives each class its own table, joined by an automatic one-to-one link. Proxy models reuse the parent's table exactly and only change Python behavior: ordering, managers or methods.

Notes

  • Abstract bases are the most common and the cheapest
  • Multi-table queries need a JOIN on every access
  • Proxy models can't add fields
  • Child Meta inherits from an abstract parent's Meta unless overridden
  • parent_link=True names the auto one-to-one explicitly

All Three Styles

# 1. Abstract base: fields copied into each child table
class TimeStampedModel(models.Model):
    created = models.DateTimeField(auto_now_add=True)
    updated = models.DateTimeField(auto_now=True)
    class Meta:
        abstract = True
        ordering = ["-created"]

class Article(TimeStampedModel):          # table: has created, updated
    title = models.CharField(max_length=200)

# 2. Multi-table: two tables, joined 1:1
class Place(models.Model):
    name = models.CharField(max_length=50)
class Restaurant(Place):                  # adds place_ptr_id
    serves_pizza = models.BooleanField(default=False)

r = Restaurant.objects.create(name="Luigi's", serves_pizza=True)
Place.objects.get(name="Luigi's").restaurant   # downcast via 1:1

# 3. Proxy: same table, different behavior
class PublishedArticle(Article):
    class Meta:
        proxy = True
        ordering = ["title"]
    objects = PublishedQuerySet.as_manager()

Code Explained

abstract = True: no migration creates a table for the base
Children of an abstract base inherit its Meta.ordering
Multi-table child gets place_ptr as its primary key
place.restaurant raises DoesNotExist if it isn't one
Proxy can register separately in the admin with its own options

⚠ Common Mistakes

  • Multi-table inheritance for shared fields only; every query pays for a JOIN
  • A fixed related_name on an FK in an abstract base, which clashes across children
  • Adding a field to a proxy model: FieldError

✓ Tips & Best Practices

  • Make a TimeStampedModel abstract base for nearly every project
  • Prefer composition (OneToOneField) over multi-table inheritance
  • Use proxies to give one table two admin views (e.g. staff vs customers)

Quick Summary

  • abstract = True: shared fields, no table
  • Multi-table: subclass with its own table
  • proxy = True: same table, new behavior
  • %(class)s: unique related names
