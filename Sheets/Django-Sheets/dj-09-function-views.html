Function-Based Views

Views as Functions

A function-based view (FBV) is a plain function that takes an HttpRequest plus any URL captures and returns an HttpResponse. The django.shortcuts helpers cover the common cases: render() fills a template, redirect() sends the browser elsewhere, and get_object_or_404() fetches a row or raises a 404. Decorators restrict methods or require login.

Notes

  • Branch on request.method to handle GET and POST in one view
  • After a successful POST, always redirect (Post/Redirect/Get)
  • render() returns an HttpResponse with status 200 by default
  • Raising Http404 anywhere in a view returns the 404 page
  • FBVs are explicit and easy to read; CBVs reduce repetition (Sheet 12)

List, Detail and Create

from django.shortcuts import render, redirect, get_object_or_404
from django.views.decorators.http import require_http_methods, require_GET
from .models import Post
from .forms import PostForm

@require_GET
def post_list(request):
    posts = Post.objects.filter(published=True)
    return render(request, "blog/post_list.html", {"posts": posts})

def post_detail(request, pk):
    post = get_object_or_404(Post, pk=pk, published=True)
    return render(request, "blog/post_detail.html", {"post": post})

@require_http_methods(["GET", "POST"])
def post_create(request):
    form = PostForm(request.POST or None)
    if request.method == "POST" and form.is_valid():
        post = form.save()
        return redirect(post)                  # uses get_absolute_url()
    return render(request, "blog/post_form.html", {"form": form})

Code Explained

render(request, template, context) → HttpResponse with HTML
get_object_or_404(Model, **lookup) → object or Http404
PostForm(request.POST or None) is unbound on GET, bound on POST
redirect(obj) calls obj.get_absolute_url()
Wrong method → HttpResponseNotAllowed (405)

⚠ Common Mistakes

  • Returning render() after a successful POST; refreshing resubmits the form
  • Post.objects.get(pk=pk) without handling DoesNotExist, which gives a 500
  • Forgetting return before render(); the view returns None and errors

✓ Tips & Best Practices

  • Filter in get_object_or_404 too: pk=pk, author=request.user blocks other users
  • Use require_POST on views that change data (delete, like, publish)
  • Keep views thin; move business logic into model methods or services

Quick Summary

  • render(): template → HTML
  • redirect(): after POST
  • get_object_or_404(): fetch or 404
