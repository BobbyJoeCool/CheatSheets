What Django Is

Django is a full-stack Python web framework, first released in 2005 at the Lawrence Journal-World newspaper and now run by the Django Software Foundation. It ships with an ORM, templates, forms, an admin site, auth, sessions and security protection out of the box (batteries included). It follows the MTV pattern: Models hold data, Templates render HTML and Views connect the two. This set targets Django 6.0 / 6.1 on Python 3.12+.

Notes

  • DRY: define a thing once (a model field drives the DB column, form field and admin widget)
  • Loose coupling: URLs, views, templates and models are separate layers
  • Used by Instagram, Mozilla, Pinterest, Disqus and the Washington Post
  • Feature releases about every 8 months; every third one (x.2) is an LTS with 3 years of support
  • Files are plain Python: .py for code, .html for templates

Hello, World in One View

# myapp/views.py
from django.http import HttpResponse

def hello(request):                       # every view takes a request
    return HttpResponse("Hello, World")   # ...and returns a response

# mysite/urls.py
from django.urls import path
from myapp.views import hello

urlpatterns = [
    path("", hello),                      # GET /  ->  Hello, World
]

Run It

python manage.py runserver        # http://127.0.0.1:8000/

Code Explained

A view is a function (or class) that gets an HttpRequest
It must return an HttpResponse (or raise an exception)
urlpatterns maps URL paths to views
runserver is the dev server: auto-reloads on save, not for production
Real views usually call render() with a template instead of raw strings

Request / Response Cycle

StepWhat Happens
1. RequestBrowser hits a URL; WSGI/ASGI server passes it in
2. MiddlewareRequest passes down the MIDDLEWARE list
3. URLconfurlpatterns picks the view
4. ViewQueries models, builds context
5. TemplateRenders HTML from the context
6. ResponseBack up through middleware to the client

⚠ Common Mistakes

  • Using runserver in production: it is single-process and has no security hardening
  • Calling the template layer the "view"; in Django the view is the Python function
  • Pinning to a non-LTS release for a long-lived project, then falling out of support

✓ Tips & Best Practices

  • Pick the latest LTS (5.2) for stability, or the latest release (6.1) for new features
  • Read the official tutorial (polls app) once; most docs assume you know it
  • Run python -m django --version to check which Django a venv has

Quick Summary

  • MTV: Model, Template, View
  • view(request): returns an HttpResponse
  • urlpatterns: URL → view map
  • LTS: every x.2 release, 3 years of fixes
