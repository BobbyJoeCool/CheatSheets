Messages Framework

messages.success() · info / warning / error · get_messages · {% for message in messages %} · MESSAGE_TAGS

One-Time Flash Messages

The messages framework shows one-time notices like "Profile saved" on the next page the user sees. Add a message in a view before redirecting; it's stored (in the session or a cookie) and removed once displayed. Templates get a messages variable from the context processor. Each message has a level and tags you can map to CSS classes.

Notes

  • Enabled by default: app, middleware and context processor
  • Messages are consumed when iterated in a template
  • Default storage tries cookies, then falls back to the session
  • SuccessMessageMixin adds messages to generic edit views
  • fail_silently=True avoids errors when the framework is off

Adding Messages

from django.contrib import messages
from django.contrib.messages.views import SuccessMessageMixin

def profile_save(request):
    ...
    messages.success(request, "Profile updated.")
    messages.warning(request, "Your email is not verified.")
    messages.add_message(request, messages.INFO, "Tip: add a photo.",
                         extra_tags="dismissible")
    return redirect("profile")

class PostCreate(SuccessMessageMixin, CreateView):
    model = Post
    fields = ["title", "body"]
    success_message = "\"%(title)s\" was created."

Iterating messages marks them as shown

⚠ Common Mistakes

  • Adding a message and rendering (not redirecting); it shows now and on the next page
  • Not displaying messages in the base template, so they pile up and appear later
  • DEBUG messages never showing; MESSAGE_LEVEL defaults to INFO

✓ Tips & Best Practices

  • Render messages once in base.html so every page shows them
  • Map ERROR to danger when using Bootstrap
  • For htmx, return messages in a response header or an out-of-band swap

Quick Summary

  • messages.success(request, msg): queue one
  • {% for message in messages %}: show them
  • message.tags: CSS class
  • SuccessMessageMixin: for CBVs
