Sessions & Cookies

request.session · SESSION_ENGINE · set_cookie() · COOKIES · signed cookies · flush()

Remembering Users Between Requests

Sessions store per-visitor data on the server and send the browser only a session id cookie. Use request.session like a dict; values must be JSON-serializable. The storage backend (SESSION_ENGINE) can be the database, cache or signed cookies. For small, non-secret values you can set cookies directly on the response, optionally signed to detect tampering.

Notes

  • Sessions are saved only when modified; nested changes need modified = True
  • Default engine stores sessions in the django_session table
  • Run clearsessions regularly to delete expired rows
  • login() rotates the session key; logout() flushes it
  • Signed cookies can be read by the user; don't store secrets in them

Sessions and Cookies

def add_to_cart(request, pk):
    cart = request.session.get("cart", {})       # dict-like
    cart[str(pk)] = cart.get(str(pk), 0) + 1
    request.session["cart"] = cart               # reassign: marks modified
    request.session.set_expiry(60 * 60 * 24 * 7) # one week
    return redirect("cart")

request.session["cart"]["5"] = 2                 # nested change...
request.session.modified = True                  # ...needs this
del request.session["cart"]                      # remove a key
request.session.flush()                          # delete all + new key
request.session.session_key                      # 'k3j2...'

def set_theme(request):
    resp = redirect("home")
    resp.set_cookie("theme", "dark", max_age=31536000,
                    secure=True, httponly=True, samesite="Lax")
    resp.set_signed_cookie("ref", "news", salt="ref")
    return resp
request.COOKIES.get("theme")                     # 'dark'
request.get_signed_cookie("ref", default=None, salt="ref")
resp.delete_cookie("theme")

Code Explained

JSON keys are strings, so use str(pk) as dict keys
Reassigning the key automatically marks the session modified
set_expiry(0) ends the session when the browser closes
httponly=True hides the cookie from JavaScript
Signed cookie reads return default if tampered

⚠ Common Mistakes

  • Storing model instances or Decimal in the session; they aren't JSON-serializable
  • Mutating a nested dict without modified = True, so changes are lost
  • Letting django_session grow forever; schedule clearsessions

✓ Tips & Best Practices

  • Use cached_db for speed with durability
  • Set SESSION_COOKIE_SECURE = True in production
  • Store ids in the session and look objects up per request

Quick Summary

  • request.session[k] = v: per-visitor data
  • SESSION_ENGINE: storage backend
  • set_cookie() / COOKIES: raw cookies
  • set_signed_cookie(): tamper-evident
