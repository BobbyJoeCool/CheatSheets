Security Settings & Deployment Checklist

check --deploy · SECURE_SSL_REDIRECT · SECURE_HSTS_SECONDS · SESSION_COOKIE_SECURE · CSRF_TRUSTED_ORIGINS · secrets in env

Hardening for Production

Development defaults favor convenience, so production needs a short list of settings turned on. python manage.py check --deploy inspects your settings and warns about each missing one. The core items: DEBUG = False, secrets from the environment, HTTPS everywhere with HSTS, secure cookies and correct ALLOWED_HOSTS.

Notes

  • Behind a proxy, set SECURE_PROXY_SSL_HEADER so Django knows the request was HTTPS
  • Start HSTS with a small value (3600), then raise to a year
  • SECURE_HSTS_PRELOAD is hard to undo; be sure first
  • Rotate SECRET_KEY with SECRET_KEY_FALLBACKS
  • Keep Django on a supported release for security patches

Production Settings

import os

DEBUG = False
SECRET_KEY = os.environ["DJANGO_SECRET_KEY"]
SECRET_KEY_FALLBACKS = [os.environ.get("DJANGO_OLD_SECRET_KEY", "")]
ALLOWED_HOSTS = ["example.com", "www.example.com"]
CSRF_TRUSTED_ORIGINS = ["https://example.com", "https://www.example.com"]

SECURE_SSL_REDIRECT = True                   # http -> https
SECURE_PROXY_SSL_HEADER = ("HTTP_X_FORWARDED_PROTO", "https")
SECURE_HSTS_SECONDS = 31536000               # one year
SECURE_HSTS_INCLUDE_SUBDOMAINS = True
SECURE_HSTS_PRELOAD = True
SESSION_COOKIE_SECURE = True                 # cookies only over HTTPS
CSRF_COOKIE_SECURE = True
SECURE_REFERRER_POLICY = "same-origin"
SECURE_CONTENT_TYPE_NOSNIFF = True           # default True

Check It

DJANGO_SETTINGS_MODULE=config.settings.prod python manage.py check --deploy
pip-audit                                     # known-vulnerable packages

Code Explained

SECRET_KEY_FALLBACKS keeps old sessions valid during rotation
SECURE_SSL_REDIRECT handles redirects in SecurityMiddleware
The proxy header must only be trusted if your proxy sets it
HSTS tells browsers to use HTTPS for the whole period
check --deploy reports security.W0xx warnings

⚠ Common Mistakes

  • Leaving DEBUG = True: error pages leak settings, SQL and source code
  • SECURE_SSL_REDIRECT behind a proxy without SECURE_PROXY_SSL_HEADER: infinite redirects
  • ALLOWED_HOSTS = ["*"] in production, which enables host-header attacks

✓ Tips & Best Practices

  • Run check --deploy in CI against production settings
  • Keep a separate prod.py settings file with only safe defaults
  • Subscribe to the Django security announcements mailing list

Quick Summary
