Choosing Field Types

Each field class sets the database column type, the default form widget and basic validation. Pick the narrowest type that fits the data: CharField needs max_length, DecimalField needs max_digits and decimal_places, and file fields store a path while the file itself lives in storage. Relationship fields are covered on Sheets 25–26.

Notes

  • Use DecimalField for money; FloatField has rounding errors
  • DateTimeField stores aware UTC datetimes when USE_TZ = True
  • JSONField works on all supported databases
  • ImageField needs the Pillow package
  • GeneratedField (5.0+) is computed by the database

A Model Using Many Types

import uuid
from django.db import models
from django.db.models.functions import Lower

class Product(models.Model):
    id = models.UUIDField(primary_key=True, default=uuid.uuid4)
    name = models.CharField(max_length=120)
    slug = models.SlugField(unique=True)
    description = models.TextField(blank=True)
    price = models.DecimalField(max_digits=8, decimal_places=2)
    stock = models.PositiveIntegerField(default=0)
    rating = models.FloatField(null=True)
    active = models.BooleanField(default=True)
    released = models.DateField(null=True, blank=True)
    updated = models.DateTimeField(auto_now=True)
    website = models.URLField(blank=True)
    contact = models.EmailField()
    specs = models.JSONField(default=dict)
    manual = models.FileField(upload_to="manuals/", blank=True)
    photo = models.ImageField(upload_to="products/%Y/", blank=True)
    name_lower = models.GeneratedField(expression=Lower("name"),
        output_field=models.CharField(max_length=120), db_persist=True)

Code Explained

max_digits=8, decimal_places=2 holds up to 999999.99
auto_now=True updates the timestamp on every save()
default=dict (a callable) gives each row its own empty dict
upload_to can include date format codes like %Y
GeneratedField is read-only; the DB keeps it in sync

⚠ Common Mistakes

  • default={} or default=[]: one shared mutable object; pass dict or list
  • FloatField for prices; 0.1 + 0.2 gives 0.30000000000000004
  • CharField without max_length: system check error fields.E120

✓ Tips & Best Practices

  • Use PositiveIntegerField for counts so negatives are rejected
  • Prefer TextField over large CharField on PostgreSQL; there's no speed difference
  • Use UUIDField as a public ID and keep the integer pk internal

Quick Summary

  • CharField(max_length=): short text
  • DecimalField: money
  • DateTimeField(auto_now_add=): timestamps
  • JSONField(default=dict): structured data
