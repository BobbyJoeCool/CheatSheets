Sheet 55

CSRF, XSS & Clickjacking

{% csrf_token %} · CsrfViewMiddleware · @csrf_exempt · autoescape · mark_safe · X_FRAME_OPTIONS

Built-in Protections

Django blocks three classic web attacks by default. CSRF protection rejects POST/PUT/DELETE requests that lack a secret token, so other sites can't submit forms as your users. XSS protection auto-escapes template output so user text can't inject scripts. Clickjacking protection sends X-Frame-Options: DENY so your pages can't be framed. The ORM's parameterized queries also prevent SQL injection.

Notes

  • Every POST form needs {% csrf_token %}
  • JavaScript requests send the token in the X-CSRFToken header
  • Cross-origin HTTPS POSTs need the site in CSRF_TRUSTED_ORIGINS
  • mark_safe / |safe turn escaping off; never use them on user input
  • format_html() escapes arguments while building HTML safely

CSRF in Forms and fetch()

<form method="post">{% csrf_token %} ... </form>

<script>
  const token = document.querySelector("[name=csrfmiddlewaretoken]").value;
  fetch("/api/like/", {method: "POST", headers: {"X-CSRFToken": token}});
</script>
<div hx-headers='{"X-CSRFToken": "{{ csrf_token }}"}'> ... </div>  {# htmx #}

{{ comment.text }}                {# <script> becomes &lt;script&gt; #}

Python Side

from django.utils.html import format_html, escape
from django.views.decorators.csrf import csrf_exempt
from django.views.decorators.clickjacking import xframe_options_sameorigin

format_html("<b>{}</b>", user_input)          # input escaped
escape("<i>hi</i>")                           # '&lt;i&gt;hi&lt;/i&gt;'

@csrf_exempt                                  # e.g. signed webhook only
def stripe_webhook(request): ...

@xframe_options_sameorigin                    # allow framing by own site
def embed(request): ...

X_FRAME_OPTIONS = "DENY"                      # settings (default)
CSRF_TRUSTED_ORIGINS = ["https://app.example.com"]

Code Explained

The token is tied to a cookie and checked by CsrfViewMiddleware
{{ csrf_token }} gives the raw value for headers
Auto-escaping converts < > & ' " to entities
Only exempt views that verify requests another way (signatures)
Trusted origins must include the scheme

⚠ Common Mistakes

  • Adding @csrf_exempt to fix a 403 instead of sending the token
  • mark_safe(f"<b>{name}</b>"): user input becomes live HTML; use format_html
  • Putting {{ data }} inside <script>; escaping rules differ there, use json_script

✓ Tips & Best Practices

  • Read the CSRF failure page in DEBUG; it explains the exact cause
  • Add Content Security Policy (Sheet 56) as a second XSS layer
  • Run manage.py check --deploy before every launch

Quick Summary

  • Auto-escape: XSS defense
