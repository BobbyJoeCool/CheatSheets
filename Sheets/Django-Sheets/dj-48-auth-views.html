Built-in Auth Views

LoginView · LogoutView · PasswordChangeView · PasswordResetView · django.contrib.auth.urls · LOGIN_REDIRECT_URL

Login, Logout and Password Flows

Django ships class-based views for the whole account flow: login, logout, password change and the four-step password reset by email. Include django.contrib.auth.urls to get them all at once; you only supply the templates in templates/registration/. Settings control where users go after login and logout.

Notes

  • Templates live in registration/ (e.g. registration/login.html)
  • LogoutView only accepts POST (5.0+)
  • Password reset emails use the EMAIL_BACKEND setting
  • LoginView validates next against allowed hosts
  • Sign-up isn't built in; write a view with UserCreationForm

URLs and Settings

# config/urls.py
urlpatterns = [
    path("accounts/", include("django.contrib.auth.urls")),
    path("accounts/signup/", SignUpView.as_view(), name="signup"),
]
# settings.py
LOGIN_URL = "login"                 # where @login_required sends users
LOGIN_REDIRECT_URL = "dashboard"    # after login (no ?next=)
LOGOUT_REDIRECT_URL = "home"

# accounts/views.py
from django.contrib.auth.forms import UserCreationForm
class SignUpView(CreateView):
    form_class = UserCreationForm
    template_name = "registration/signup.html"
    success_url = reverse_lazy("login")

registration/login.html

<form method="post">{% csrf_token %}
  {{ form }}
  <input type="hidden" name="next" value="{{ next }}">
  <button>Log in</button>  <a href="{% url 'password_reset' %}">Forgot?</a>
</form>
<form method="post" action="{% url 'logout' %}">
  {% csrf_token %}<button>Log out</button>
</form>

Code Explained

One include adds 8 named URLs (table below)
LOGIN_URL accepts a URL name or path
UserCreationForm handles password confirmation and validators
The hidden next input sends users back where they started
Logout is a POST form, not a link

⚠ Common Mistakes

  • A logout <a href> link; GET to LogoutView returns 405 in 5.0+
  • Missing registration/login.html: TemplateDoesNotExist
  • Testing password reset with no email backend; use the console backend in dev

✓ Tips & Best Practices

  • Set EMAIL_BACKEND = "django.core.mail.backends.console.EmailBackend" in dev
  • Subclass UserCreationForm to add fields like email
  • Use django-allauth if you need social login or email verification
