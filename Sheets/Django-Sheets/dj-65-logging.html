Logging & Debugging

LOGGING dict · loggers / handlers / formatters · django.request logger · DEBUG pages · pdb

Seeing What Your App Does

Django uses Python's standard logging module, configured through the LOGGING setting as a dictConfig dict. Loggers produce records, handlers send them somewhere (console, file, email) and formatters shape each line. Django logs request errors to django.request. For interactive debugging, use breakpoint(), the debug error page and the Django Debug Toolbar.

Notes

  • Keep disable_existing_loggers: False so Django's loggers still work
  • 5xx errors log to django.request at ERROR level
  • django.db.backends at DEBUG logs every SQL query (needs DEBUG = True)
  • Get a logger per module: logging.getLogger(__name__)
  • In containers, log to stdout and let the platform collect it

LOGGING and Usage

LOGGING = {
    "version": 1,
    "disable_existing_loggers": False,
    "formatters": {"plain": {
        "format": "{asctime} {levelname} {name}: {message}", "style": "{"}},
    "handlers": {
        "console": {"class": "logging.StreamHandler", "formatter": "plain"},
        "mail_admins": {"class": "django.utils.log.AdminEmailHandler",
                        "level": "ERROR"},
    },
    "root": {"handlers": ["console"], "level": "INFO"},
    "loggers": {
        "django.request": {"handlers": ["mail_admins"], "level": "ERROR"},
        "django.db.backends": {"level": "WARNING"},   # DEBUG to see SQL
        "shop": {"level": "DEBUG"},
    },
}

import logging
log = logging.getLogger(__name__)                     # e.g. "shop.views"
log.info("Order %s paid", order.pk)                   # lazy formatting
try: charge(order)
except PaymentError:
    log.exception("Charge failed for %s", order.pk)   # adds traceback
breakpoint()                                          # pdb in runserver

Code Explained

"style": "{" lets formats use {name} placeholders
AdminEmailHandler emails tracebacks to ADMINS
Logger names are dotted: shop covers shop.views
Pass args separately so formatting only happens if logged
log.exception must be called inside except

⚠ Common Mistakes

  • disable_existing_loggers: True, which silences Django's own loggers
  • f-strings in log calls: log.info(f"...") formats even when the level is off
  • Leaving SQL debug logging on in production, flooding logs

✓ Tips & Best Practices

  • Use JSON logs (python-json-logger) for log aggregators
  • Attach a request id in middleware and include it in every line
  • Install django-debug-toolbar in development only

Quick Summary

  • LOGGING: dictConfig setting
  • getLogger(__name__): per-module logger
  • django.request: server errors
  • log.exception(): traceback included
