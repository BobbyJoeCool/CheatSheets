ListView and DetailView

ListView shows a list of objects and DetailView shows one object fetched by pk or slug from the URL. Set model (or queryset) and Django picks a default template name and context variable. Override get_queryset() to filter per request and get_context_data() to add extra variables.

Notes

  • Default template: <app>/<model>_list.html and <app>/<model>_detail.html
  • Context: object_list / post_list, and object / post
  • DetailView raises 404 if no object matches
  • paginate_by adds page_obj, paginator and is_paginated
  • slug_field and slug_url_kwarg customize slug lookups

Display Views

from django.views.generic import ListView, DetailView
from .models import Post

class PostListView(ListView):
    model = Post
    paginate_by = 20
    ordering = ["-created"]
    context_object_name = "posts"              # instead of post_list
    def get_queryset(self):
        qs = super().get_queryset().filter(published=True)
        if q := self.request.GET.get("q"):
            qs = qs.filter(title__icontains=q)
        return qs

class PostDetailView(DetailView):
    model = Post                               # finds pk or slug in URL
    template_name = "blog/post.html"
    def get_queryset(self):                    # restrict what can be seen
        return Post.objects.filter(published=True)
    def get_context_data(self, **kwargs):
        ctx = super().get_context_data(**kwargs)
        ctx["related"] = self.object.related_posts()[:3]
        return ctx

Code Explained

super().get_queryset() applies model and ordering
self.request.GET gives filters; self.kwargs gives URL captures
Detail lookups go through get_queryset(), so filtering there limits access
self.object is set before get_context_data runs
Override get_object() for lookups that aren't pk/slug

⚠ Common Mistakes

  • Filtering in get_context_data instead of get_queryset; pagination then counts the wrong rows
  • Template named post.html when the view expects blog/post_detail.html
  • Forgetting ordering with paginate_by: UnorderedObjectListWarning and unstable pages

✓ Tips & Best Practices

  • Set context_object_name so templates read naturally (posts, post)
  • Add select_related() in get_queryset() to avoid N+1 queries
  • Scope detail views to the user: Post.objects.filter(author=self.request.user)

Quick Summary

  • ListView: many objects (+ pagination)
  • DetailView: one object by pk/slug
  • get_queryset(): filter per request
  • get_context_data(): extra context
