The Tasks Framework (Django 6.0)

Django 6.0 adds django.tasks, a standard API for defining work to run outside the request: decorate a function with @task and call .enqueue(). Django defines tasks and queues them through a configured backend, but does not ship a worker. The built-in backends are for development and testing; production needs a third-party backend and worker, such as the django-tasks package's database backend.

Notes

  • Arguments must be JSON-serializable (pass ids, not model objects)
  • Built-in: ImmediateBackend (runs now) and DummyBackend (stores, never runs)
  • priority ranges from -100 to 100
  • run_after defers a task (backend must support it)
  • Celery and RQ remain options for heavy workloads

Define, Configure, Enqueue

# settings.py
TASKS = {
    "default": {"BACKEND": "django.tasks.backends.immediate.ImmediateBackend"},
}

# orders/tasks.py
from django.core.mail import send_mail
from django.tasks import task

@task(priority=10, queue_name="emails")
def send_receipt(order_id):
    order = Order.objects.get(pk=order_id)
    send_mail(subject=f"Receipt #{order.pk}", message="Thanks!",
              from_email=None, recipient_list=[order.email])
    return order.pk

# in a view
from django.db import transaction
transaction.on_commit(lambda: send_receipt.enqueue(order.pk))

result = send_receipt.enqueue(order.pk)       # TaskResult
result.id                                    # backend-specific id
result.status                                # TaskResultStatus.READY
result.refresh(); result.return_value        # after it finishes
send_receipt.using(priority=50, run_after=timedelta(minutes=5)).enqueue(7)

Code Explained

@task turns the function into a Task object
enqueue() returns a TaskResult right away
on_commit avoids queueing work for a rolled-back order
return_value raises ValueError until the task succeeds
using() returns a copy with new options

⚠ Common Mistakes

  • Passing a model instance to enqueue(); arguments must survive a JSON round-trip
  • Using ImmediateBackend in production; work still runs inside the request
  • Expecting Django to start workers; you must run the backend's worker process

✓ Tips & Best Practices

  • Install django-tasks for a database backend and db_worker command
  • Use takes_context=True to read context.attempt for retry logic
  • Use DummyBackend in tests and assert on its results list

Quick Summary

  • @task: define background work
  • .enqueue(*args) → TaskResult
  • TASKS: backend config
  • No built-in worker: add one
