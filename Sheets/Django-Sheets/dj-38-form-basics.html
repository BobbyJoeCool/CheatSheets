Handling User Input

A forms.Form class declares fields once and gives you HTML rendering, validation and cleaned Python values. A form is unbound when created empty (for display) and bound when given request.POST. Call is_valid() to run validation; valid data is then in form.cleaned_data, already converted to the right types. Invalid forms re-render with their errors.

Notes

  • cleaned_data only exists after is_valid() returns
  • Errors are in form.errors (a dict of field → messages)
  • Always redirect after a successful POST (PRG pattern)
  • Pass request.FILES as the second argument for uploads
  • Forms work without models; use ModelForm for model data (Sheet 41)

forms.py + View

from django import forms

class ContactForm(forms.Form):
    name = forms.CharField(max_length=100)
    email = forms.EmailField()
    message = forms.CharField(widget=forms.Textarea)
    subscribe = forms.BooleanField(required=False)

def contact(request):
    if request.method == "POST":
        form = ContactForm(request.POST)            # bound
        if form.is_valid():
            data = form.cleaned_data                # {'name': 'Ann', ...}
            send_message(data["email"], data["message"])
            return redirect("contact-thanks")       # PRG
    else:
        form = ContactForm(initial={"subscribe": True})   # unbound
    return render(request, "contact.html", {"form": form})

contact.html

<form method="post" novalidate>
  {% csrf_token %}

</form>

Code Explained

required=False makes a field optional (default is required)
initial= sets display values on an unbound form
Invalid POST falls through to render() with errors attached
{{ form }} renders with the default div template (5.0+)
novalidate turns off browser checks so you can test server validation

⚠ Common Mistakes

  • Reading form.cleaned_data before calling is_valid(): AttributeError
  • Using request.POST["email"] directly, skipping validation and type conversion
  • Creating a new unbound form after a failed POST, which throws the errors away

✓ Tips & Best Practices

  • Use ContactForm(request.POST or None) to collapse the GET/POST branches
  • Render fields individually with {{ form.name.as_field_group }} for custom layouts
  • Use django-crispy-forms or a custom FORM_RENDERER for styled forms

Quick Summary

  • forms.Form: declare fields
  • Bound = has data; unbound = empty
  • is_valid() → cleaned_data
  • {{ form }}: render + errors
