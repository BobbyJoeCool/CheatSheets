Users & Authentication

User model · authenticate() · login() · logout() · request.user · is_authenticated · set_password()

The Auth System

django.contrib.auth provides a User model, password hashing, sessions-based login and permissions. authenticate() checks credentials against the configured backends and returns a user or None. login() stores the user's id in the session, after which AuthenticationMiddleware puts that user on request.user for every request. logout() clears the session.

Notes

  • Passwords are stored hashed (PBKDF2 by default, Argon2 optional)
  • request.user is an AnonymousUser when not logged in
  • login() rotates the session key to stop session fixation
  • Use User.objects.create_user() so the password is hashed
  • Get the active user model with get_user_model() (Sheet 50)

Log In and Out by Hand

from django.contrib.auth import authenticate, login, logout, get_user_model
from django.contrib.auth.decorators import login_required

User = get_user_model()
u = User.objects.create_user("ann", "ann@example.com", "s3cret!pass")
u.check_password("s3cret!pass")          # True
u.set_password("new-pass-123"); u.save() # hashes it

def login_view(request):
    if request.method == "POST":
        user = authenticate(request, username=request.POST["username"],
                            password=request.POST["password"])
        if user is not None:
            login(request, user)         # session cookie set
            return redirect(request.GET.get("next", "home"))
    return render(request, "login.html")

@login_required
def dashboard(request):
    return render(request, "dash.html", {"name": request.user.get_full_name()})

Code Explained

create_user hashes the password; create() would store plain text
authenticate returns None for bad credentials or inactive users
Redirecting to raw next is unsafe; built-in LoginView validates it
logout must be POST when using the built-in LogoutView
In templates, the auth context processor adds user and perms

⚠ Common Mistakes

  • User.objects.create(password="x") stores an unhashed password that never matches
  • Changing a password without update_session_auth_hash, logging the user out
  • Redirecting to next without url_has_allowed_host_and_scheme: open redirect

✓ Tips & Best Practices

  • Use the built-in auth views (Sheet 48) instead of hand-written login views
  • Switch to Argon2 by listing it first in PASSWORD_HASHERS
  • Set AUTH_PASSWORD_VALIDATORS to enforce password strength

Quick Summary

  • authenticate() → user or None
  • login() / logout(): session
  • request.user: current user
  • create_user() / set_password(): hashing
