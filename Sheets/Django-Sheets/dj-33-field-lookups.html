Field Lookups

__exact · __icontains · __in · __gt / __lte · __range · __isnull · __year · spanning relations

Double-Underscore Lookups

Filter keyword arguments use field__lookup=value. With no lookup, exact is assumed. Lookups cover text matching, comparisons, membership, ranges, NULL checks and date parts. The same double underscore also follows relationships: author__username joins to the author table, and you can chain as deep as you need.

Notes

  • Multiple kwargs in one filter() are combined with AND
  • i prefix = case-insensitive (iexact, icontains)
  • Date parts chain with comparisons: created__year__gte=2025
  • Following a reverse relation may return duplicates; add .distinct()
  • Use Q objects for OR logic (Sheet 34)

Lookup Examples

Post.objects.filter(title="Django")                  # exact
Post.objects.filter(title__iexact="django")          # ILIKE 'django'
Post.objects.filter(title__icontains="orm")          # ILIKE '%orm%'
Post.objects.filter(slug__startswith="how-to")
Post.objects.filter(views__gt=100, views__lte=1000)
Post.objects.filter(id__in=[1, 4, 9])
Post.objects.filter(created__range=(start, end))     # BETWEEN
Post.objects.filter(pub_date__isnull=True)
Post.objects.filter(created__year=2026, created__month=10)
Post.objects.filter(created__date=date.today())
Post.objects.filter(created__week_day=2)             # Monday
Post.objects.filter(title__regex=r"^\d+ tips")

# spanning relationships
Post.objects.filter(author__username="ann")          # FK join
Post.objects.filter(author__profile__country="US")   # two joins
Author.objects.filter(post__title__icontains="orm").distinct()  # reverse
Post.objects.filter(tags__name__in=["web", "api"]).distinct()   # M2M
Post.objects.filter(specs__color="red")              # JSONField key

Code Explained

views__gt=100 → WHERE views > 100
__in accepts a list or another QuerySet (subquery)
__range is inclusive on both ends
Reverse FK lookups use the related_query_name (default: model name)
JSONField keys chain like relations: specs__color

⚠ Common Mistakes

  • Using contains when you meant case-insensitive search; use icontains
  • filter(tags__name="a", tags__name="b"): duplicate kwargs; chain two filter() calls
  • Forgetting .distinct() after reverse or M2M lookups, so the same row repeats

✓ Tips & Best Practices

  • Use __date on datetimes rather than building start/end ranges by hand
  • Index columns you filter by startswith or exact often
  • For real full-text search use django.contrib.postgres.search
