Sheet 19

Inheritance, Includes & Partials

{% extends %} · {% block %} · {{ block.super }} · {% include %} · {% partialdef %} · {% partial %}

Reusing Template Code

Inheritance lets a child template {% extends %} a base layout and override its named {% block %}s. {% include %} drops another template in place with the current context. Partials (new in 6.0) define named fragments inside one file with {% partialdef %} and render them with {% partial %} or from a view as "file.html#name", which pairs well with htmx.

Notes

  • {% extends %} must be the first tag in the child
  • Blocks not overridden keep the parent's content
  • {{ block.super }} adds to the parent block instead of replacing it
  • {% include "x.html" with a=1 only %} limits the context
  • Partials: {% partialdef name inline %} also renders it in place

base.html

<!doctype html>
<html><head><title>{% block title %}My Site{% endblock %}</title></head>
<body>
  {% include "partials/nav.html" %}
  <main>{% block content %}{% endblock content %}</main>
</body></html>

blog/post_list.html

{% extends "base.html" %}
{% block title %}Posts · {{ block.super }}{% endblock %}
{% block content %}
  {% partialdef post-row %}
    <li id="post-{{ post.pk }}">{{ post.title }}</li>
  {% endpartialdef %}
  <ul>{% for post in posts %}{% partial post-row %}{% endfor %}</ul>
  {% include "blog/sidebar.html" with tags=tags only %}
{% endblock content %}

Render a Partial from a View

render(request, "blog/post_list.html#post-row", {"post": post})

Code Explained

Child output = parent layout with child blocks swapped in
{{ block.super }} → Posts · My Site
Naming the end tag (endblock content) helps readability
#post-row renders just that fragment: ideal for htmx swaps
only passes just the listed variables to the include

⚠ Common Mistakes

  • Any output or tag before {% extends %}; it's ignored or errors
  • Defining the same block name twice in one template: TemplateSyntaxError
  • Content outside any {% block %} in a child; it never renders

✓ Tips & Best Practices

  • Keep one base.html with blocks for title, content, extra_css, extra_js
  • Use partials instead of many tiny include files for htmx endpoints
  • Use {% include ... only %} to make includes predictable

Quick Summary

  • {% extends %} + {% block %}: layouts
  • {{ block.super }}: extend, not replace
  • {% include %}: insert a template
  • {% partialdef %} / #name: fragments (6.0)
