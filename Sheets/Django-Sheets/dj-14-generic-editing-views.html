Generic Views — Editing

CreateView · UpdateView · DeleteView · FormView · success_url · form_valid()

Create, Update, Delete

The editing views handle the full form cycle: show an empty or bound form on GET, validate on POST, save and redirect on success, or re-render with errors. CreateView and UpdateView build a ModelForm from model + fields, DeleteView asks for confirmation then deletes, and FormView works with any plain Form.

Notes

  • Default template: <app>/<model>_form.html for create and update
  • DeleteView uses <model>_confirm_delete.html and deletes on POST
  • Success redirect: success_url, else the object's get_absolute_url()
  • Override form_valid() to set fields the user shouldn't edit
  • Context has form, and object on update/delete

Editing Views

from django.contrib.auth.mixins import LoginRequiredMixin
from django.urls import reverse_lazy
from django.views.generic.edit import CreateView, UpdateView, DeleteView, FormView
class PostCreateView(LoginRequiredMixin, CreateView):
    model = Post
    fields = ["title", "body", "tags"]
    def form_valid(self, form):
        form.instance.author = self.request.user   # set hidden field
        return super().form_valid(form)            # saves + redirects

class PostUpdateView(LoginRequiredMixin, UpdateView):
    model = Post
    fields = ["title", "body"]
    def get_queryset(self):                        # owner-only edits
        return Post.objects.filter(author=self.request.user)

class PostDeleteView(LoginRequiredMixin, DeleteView):
    model = Post
    success_url = reverse_lazy("blog:list")

class ContactView(FormView):
    form_class, template_name = ContactForm, "contact.html"
    success_url = reverse_lazy("thanks")

Code Explained

fields (or form_class) is required on Create/UpdateView
form.instance is the unsaved model object
super().form_valid() saves and returns the redirect
Owner-only edits: filter get_queryset() by request.user
reverse_lazy because URLs aren't loaded at class creation

⚠ Common Mistakes

  • Using fields = "__all__", which exposes fields like author or is_staff to users
  • Calling form.save() in form_valid and then super(), saving twice
  • No get_queryset() filter on Update/DeleteView, so any user can edit any row

✓ Tips & Best Practices

  • Put LoginRequiredMixin first in the base class list
  • Add SuccessMessageMixin + success_message for flash confirmations
  • Override get_form_kwargs() to pass request.user into a custom form
