Online Transactions on the Mainframe

CICS runs online transactions: a user presses Enter on a 3270 screen, CICS starts a COBOL program, and the program sends a screen back. Programs are pseudo-conversational: they end after each screen and pass state in a COMMAREA, so no memory is held while the user types.

Key Points

  • EXEC CICS commands replace file I/O and DISPLAY/ACCEPT
  • BMS maps define screens; their copybooks give field layouts
  • EIBCALEN = 0 means first time in (no COMMAREA yet)
  • RESP captures the result instead of abending

Pseudo-Conversational Skeleton

       WORKING-STORAGE SECTION.
           COPY ACCTMAP.                      *> BMS map layout
       01  WS-RESP              PIC S9(8) COMP.
       01  WS-COMM.
           05 WS-STEP           PIC X.
       LINKAGE SECTION.
       01  DFHCOMMAREA          PIC X(1).
       PROCEDURE DIVISION.
           IF EIBCALEN = 0                    *> first time
              MOVE LOW-VALUES TO ACCTMAPO
              EXEC CICS SEND MAP("ACCTMAP") MAPSET("ACCTSET")
                   ERASE
              END-EXEC
           ELSE
              EXEC CICS RECEIVE MAP("ACCTMAP") MAPSET("ACCTSET")
                   RESP(WS-RESP)
              END-EXEC
              EVALUATE EIBAID
                 WHEN DFHPF3   EXEC CICS RETURN END-EXEC
                 WHEN DFHENTER PERFORM 2000-LOOKUP-ACCOUNT
              END-EVALUATE
           END-IF
           EXEC CICS RETURN TRANSID("ACCT")
                COMMAREA(WS-COMM) LENGTH(1)
           END-EXEC.

Code Explained

First entry sends an empty screen
On the next Enter, CICS restarts the program with the COMMAREA
EIBAID tells which key the user pressed (PF3 = exit)
RETURN TRANSID ends the task but keeps the conversation going

Modern Equivalent

  • Python A web request handler: stateless, with state in a session or form field
  • Java A servlet or Spring controller with session state
  • JavaScript An Express route handler with state in cookies or the client

Prefer / Avoid

  • conversational programs that wait for input → pseudo-conversational RETURN TRANSID
  • unchecked commands → RESP + EVALUATE instead of HANDLE CONDITION

⚠ Common Mistakes

  • Using DISPLAY, ACCEPT or COBOL file I/O inside CICS programs
  • Not checking EIBCALEN, so first-time logic runs every time
  • Holding a terminal conversation open while the user types

✓ Tips & Best Practices

  • Check RESP after every command and EVALUATE the result
  • Keep the COMMAREA small; use channels/containers for large state
  • Test maps with the CICS-supplied CEDF debugging transaction
