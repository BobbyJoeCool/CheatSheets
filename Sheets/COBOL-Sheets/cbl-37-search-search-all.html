SEARCH & SEARCH ALL

serial SEARCH · AT END · WHEN · SEARCH ALL binary search · ASCENDING KEY / DESCENDING KEY · table must be sorted

Looking Up Table Entries

SEARCH scans a table one entry at a time from the current index until a WHEN condition is true. SEARCH ALL does a binary search on a table declared with ASCENDING or DESCENDING KEY, which is much faster for large tables but requires the data to be in key order.

Key Points

  • Set the index to 1 before a serial SEARCH
  • SEARCH ALL sets its own starting point
  • SEARCH ALL allows only = tests joined by AND
  • AT END runs when nothing matches

Under the Hood

  • SEARCH ALL halves the range each step: about 10 compares for 1,000 entries
  • Unsorted data does not fail loudly: SEARCH ALL just misses entries
  • Unused trailing entries should hold HIGH-VALUES so the order holds

Serial and Binary Search

       01  STATE-TABLE.
           05 STATE-ENT OCCURS 50 TIMES
                 ASCENDING KEY IS ST-CODE
                 INDEXED BY SX.
              10 ST-CODE      PIC XX.
              10 ST-NAME      PIC X(14).
              10 ST-TAX       PIC V9999.

      *>   Serial: start where you want, any condition
           SET SX TO 1
           SEARCH STATE-ENT
              AT END DISPLAY "NOT FOUND"
              WHEN ST-NAME(SX) = "IOWA"
                 DISPLAY "CODE " ST-CODE(SX)       *> IA
           END-SEARCH

      *>   Binary: table must be in ST-CODE order
           SEARCH ALL STATE-ENT
              AT END MOVE 0 TO WS-TAX
              WHEN ST-CODE(SX) = WS-STATE
                 MOVE ST-TAX(SX) TO WS-TAX
           END-SEARCH

Code Explained

Serial SEARCH can test any field with any condition
SEARCH ALL tests only the declared key with =
After a match, SX points at the found entry
AT END handles a missing code

Modern Equivalent

  • Python next((s for s in states if s.name == "IOWA"), None); bisect for sorted
  • Java list.stream().filter(...).findFirst(); Collections.binarySearch
  • JavaScript states.find(s => s.name === "IOWA"); a Map for fast lookups

Prefer / Avoid

  • serial SEARCH on large tables → SEARCH ALL on a sorted table
  • unsorted load into a keyed table → sort first or check order on load

SEARCH vs SEARCH ALL

⚠ Common Mistakes

  • Forgetting SET SX TO 1, so SEARCH starts mid-table
  • SEARCH ALL on unsorted data: it returns "not found" for entries that exist
  • Using > or OR inside SEARCH ALL (not allowed)

✓ Tips & Best Practices

  • Fill unused entries with HIGH-VALUES before a SEARCH ALL
  • Load reference tables from sorted files at startup
  • Use a serial SEARCH when you need the first match by a non-key field

Quick Summary

  • SEARCH — serial, any test
  • SEARCH ALL — binary, key =
  • ASCENDING KEY — needed for ALL
  • AT END — not found
