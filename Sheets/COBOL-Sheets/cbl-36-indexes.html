Indexes

INDEXED BY · SET idx TO / UP BY · index vs subscript · USAGE INDEX · displacement under the hood

Faster Table Access

An index declared with INDEXED BY is tied to one table and holds a byte offset instead of an occurrence number, so table access needs no multiplication. Indexes are required by SEARCH, and you change them only with SET, SEARCH or PERFORM VARYING.

Key Points

  • You still write TBL(IX), as with subscripts
  • Index names are not declared elsewhere: INDEXED BY defines them
  • USAGE INDEX fields store index values for later
  • Mixing: TBL(IX + 1) is allowed (relative indexing)

Under the Hood

  • Index value = (occurrence − 1) × entry length: occurrence 3 of 20-byte entries is 40
  • Subscripts need a multiply on every access; indexes do not
  • Each index is tied to its own table: using it on another table gives wrong offsets

Indexes vs Subscripts

       01  RATE-TABLE.
           05 RATE-ENTRY OCCURS 20 TIMES INDEXED BY RX.
              10 RATE-CODE    PIC XX.
              10 RATE-PCT     PIC V999.
       01  WS-SAVE-IX         USAGE INDEX.
       01  WS-COUNT           PIC 99 VALUE 0.

           SET RX TO 1
           MOVE "A1" TO RATE-CODE(RX)
           SET RX UP BY 1                    *> occurrence 2
           MOVE .045 TO RATE-PCT(RX)
           SET WS-SAVE-IX TO RX              *> remember position
           PERFORM VARYING RX FROM 1 BY 1 UNTIL RX > 20
              IF RATE-CODE(RX) NOT = SPACES
                 ADD 1 TO WS-COUNT
              END-IF
           END-PERFORM
           SET RX TO WS-SAVE-IX              *> back to entry 2
           DISPLAY RATE-CODE(RX + 1)         *> relative index

Code Explained

SET RX TO 1 points at the first occurrence
SET … UP BY moves the index by whole entries
USAGE INDEX saves and restores an index position
PERFORM VARYING works with indexes too

Modern Equivalent

  • Python A position variable; Python lists index directly by number
  • Java int i positions; JIT handles the offset math
  • JavaScript let i positions; typed arrays for fixed layouts

Prefer / Avoid

  • subscripts in SEARCH loops → INDEXED BY (required by SEARCH)
  • MOVE to an index → SET

⚠ Common Mistakes

  • MOVE 1 TO RX (indexes need SET)
  • Displaying an index directly to debug (shows an offset or is not allowed)
  • Using one table's index on another table with a different entry size

✓ Tips & Best Practices

  • Use indexes for tables you search
  • To show the position, SET a numeric field to the index first
  • Give each table its own index name

Quick Summary

  • INDEXED BY — define index
  • SET ix TO / UP BY — change it
  • USAGE INDEX — save positions
  • required by SEARCH
