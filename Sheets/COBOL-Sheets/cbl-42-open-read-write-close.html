OPEN, READ, WRITE & CLOSE

OPEN INPUT / OUTPUT / EXTEND / I-O · READ … AT END · WRITE … FROM · READ … INTO · REWRITE · priming-read loop

The Sequential File Cycle

Every file is opened in a mode, processed record by record, and closed. The standard batch loop uses a priming read: read the first record before the loop, process it inside the loop, and read the next record at the bottom, stopping when AT END sets the end-of-file flag.

Key Points

  • OUTPUT creates or empties the file; EXTEND appends
  • I-O allows READ then REWRITE of the same record
  • READ uses the file name; WRITE uses the record name
  • Always CLOSE files, even on error paths

Copy and Filter a File

       PROCEDURE DIVISION.
       0000-MAIN.
           OPEN INPUT  CUST-IN
                OUTPUT CUST-OUT
           PERFORM 8000-READ-CUST
           PERFORM UNTIL END-OF-CUST
              IF CL-STATE = "IA"
                 WRITE CUST-OUT-REC FROM CUST-LAYOUT
                 ADD 1 TO WS-WRITTEN
              END-IF
              PERFORM 8000-READ-CUST
           END-PERFORM
           CLOSE CUST-IN CUST-OUT
           DISPLAY "WROTE " WS-WRITTEN
           GOBACK.

       8000-READ-CUST.
           READ CUST-IN INTO CUST-LAYOUT
              AT END     SET END-OF-CUST TO TRUE
              NOT AT END ADD 1 TO WS-READ
           END-READ.

      *>   Update in place:
      *>   OPEN I-O CUST-FILE / READ CUST-FILE
      *>   change fields / REWRITE CUST-REC

Code Explained

The priming read means an empty file skips the loop cleanly
READ … INTO copies each record into a working layout
WRITE … FROM copies a layout into the output record and writes it
REWRITE replaces the record just read (I-O mode)

Modern Equivalent

  • Python for line in open(path): (the loop reads for you)
  • Java try (var r = Files.newBufferedReader(p)) { while ((line = r.readLine()) != null) … }
  • JavaScript for await (const line of rl) with readline.createInterface

Prefer / Avoid

  • READ at the top of the loop → priming read + read at the bottom
  • MOVE then WRITE → WRITE … FROM

⚠ Common Mistakes

  • WRITE CUST-OUT (file name) instead of the record name
  • Processing the record in the AT END branch, using stale data
  • OPEN OUTPUT on a file you meant to append to (data is lost)

✓ Tips & Best Practices

  • Count records read and written and DISPLAY them at the end
  • Check FILE STATUS after OPEN before reading
  • Put each READ in its own paragraph so it is written once

Quick Summary

  • OPEN — mode per file
  • READ … AT END — next record
  • WRITE … FROM — output
  • priming read — standard loop
