Sheet 45

Random & Dynamic Access

READ … KEY IS · INVALID KEY · START … KEY >= · READ NEXT · WRITE / REWRITE / DELETE · browse pattern

Reading and Updating by Key

With RANDOM or DYNAMIC access, move a key value into the key field and READ to get that record. START positions at the first record matching a key condition, and READ NEXT then browses forward. INVALID KEY runs when the key is missing or duplicated.

Key Points

  • Set the key field, then READ: the key is not a READ argument
  • INVALID KEY or FILE STATUS 23 means not found
  • WRITE adds; status 22 means the key already exists
  • REWRITE and DELETE need the file open I-O

Lookup, Update and Browse

           OPEN I-O ACCT-MAST

      *>   Random read and update
           MOVE 1000004217 TO AM-ACCT-NO
           READ ACCT-MAST
              INVALID KEY     DISPLAY "NO SUCH ACCOUNT"
              NOT INVALID KEY
                 ADD WS-DEPOSIT TO AM-BALANCE
                 REWRITE ACCT-REC
           END-READ

      *>   Add a new record
           WRITE ACCT-REC FROM WS-NEW-ACCT
              INVALID KEY DISPLAY "DUPLICATE " AM-ACCT-NO
           END-WRITE

      *>   Browse all accounts for one SSN (alternate key)
           MOVE WS-SSN TO AM-SSN
           START ACCT-MAST KEY IS = AM-SSN
              INVALID KEY SET END-OF-BROWSE TO TRUE
           END-START
           PERFORM UNTIL END-OF-BROWSE
              READ ACCT-MAST NEXT RECORD
                 AT END SET END-OF-BROWSE TO TRUE
              END-READ
              IF NOT END-OF-BROWSE AND AM-SSN NOT = WS-SSN
                 SET END-OF-BROWSE TO TRUE
              END-IF
           END-PERFORM

Code Explained

The key value in AM-ACCT-NO picks the record
REWRITE replaces the record just read; the key must not change
START KEY IS = AM-SSN switches the browse to the alternate key
The browse stops when the SSN changes

Modern Equivalent

  • Python row = db.execute("SELECT … WHERE acct=?", (n,)).fetchone()
  • Java ps.setLong(1, n); ResultSet rs = ps.executeQuery();
  • JavaScript await db.get("SELECT … WHERE acct = ?", n)

Prefer / Avoid

  • READ then check a field for "not found" → INVALID KEY / status 23
  • changing the primary key with REWRITE → DELETE + WRITE

⚠ Common Mistakes

  • Changing the key field before REWRITE (status 21 or wrong record)
  • READ NEXT without a successful START or READ first
  • Browsing an alternate key without checking when the value changes

✓ Tips & Best Practices

  • Use a generic START (>=) with a partial key to browse a range
  • Read for update immediately before REWRITE to keep data current
  • Log the key on every INVALID KEY branch

Quick Summary

  • key field + READ — lookup
  • INVALID KEY — not found / dup
  • START + READ NEXT — browse
  • REWRITE / DELETE — I-O mode
