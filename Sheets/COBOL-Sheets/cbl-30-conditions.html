Writing Tests

COBOL conditions compare values (relational), check what kind of data a field holds (class), test the sign of a number (sign), or use level-88 condition names. They combine with AND, OR and NOT, and COBOL allows abbreviated forms that leave out a repeated subject.

Key Points

  • Relational words and symbols are interchangeable: GREATER THAN = >
  • Precedence: NOT, then AND, then OR
  • Alphanumeric comparisons pad the shorter side with spaces
  • Use parentheses whenever AND and OR are mixed

Kinds of Conditions

           IF WS-AGE >= 18                       *> relational
           IF WS-AGE IS GREATER THAN OR EQUAL TO 18
           IF WS-NAME NOT = SPACES
           IF IN-QTY IS NUMERIC                  *> class
           IF WS-CODE IS ALPHABETIC              *> letters + space
           IF WS-CODE IS ALPHABETIC-UPPER
           IF WS-BALANCE IS NEGATIVE             *> sign
           IF WS-BALANCE IS ZERO
           IF END-OF-FILE                        *> condition name
           IF (WS-AGE > 64 OR DISABLED)
              AND NOT WS-STATE = "IA"            *> combined

      *>   Abbreviated: subject and operator carried forward
           IF WS-STATE = "IA" OR "MN" OR "WI"
           IF WS-AGE > 18 AND < 65
      *>   means WS-AGE > 18 AND WS-AGE < 65

Code Explained

Class tests check content, not the PIC: use them on input
ALPHABETIC accepts letters and spaces
Sign tests work on any numeric field
Abbreviated conditions repeat the last subject (and operator)

Modern Equivalent

  • Python state in ("IA", "MN", "WI"); 18 < age < 65; s.isdigit()
  • Java Set.of("IA","MN","WI").contains(state); age > 18 && age < 65
  • JavaScript ["IA","MN","WI"].includes(state); age > 18 && age < 65

Prefer / Avoid

  • long OR chains on literals → an 88 with a VALUE list
  • NOT A = B OR C (confusing) → parentheses or an 88

⚠ Common Mistakes

  • IF A NOT = 1 OR 2, which is always true
  • Testing IS NUMERIC on a COMP field (meaningless for binary)
  • Forgetting that "ABC" = "ABC " is true (space padding)

✓ Tips & Best Practices

  • Rewrite negative OR conditions as positive AND conditions
  • Use 88-levels for code lists to keep conditions short
  • Add parentheses even when precedence would work

Quick Summary

  • relational — =, >, NOT <
  • class — NUMERIC, ALPHABETIC
  • sign — POSITIVE, ZERO
  • abbreviated — = "A" OR "B"
