Sheet 08

Comments & Documentation

* in column 7 · *> inline comments · / page eject · program header blocks · change logs · AUTHOR (obsolete)

Documenting Long-Lived Code

COBOL programs often outlive their authors by decades, so comments carry history. A * in column 7 makes the whole line a comment; COBOL 2002 added *> for comments anywhere on a line. Most shops require a header block with purpose, inputs, outputs and a change log.

Key Points

  • / in column 7 is a comment that also starts a new listing page
  • *> works in free format and modern fixed format
  • AUTHOR, DATE-WRITTEN and REMARKS are obsolete paragraphs
  • Comment the why: business rules and ticket numbers

Header Block & Comment Styles

       IDENTIFICATION DIVISION.
       PROGRAM-ID. INTCALC.
      *================================================*
      * PROGRAM : INTCALC                              *
      * PURPOSE : Monthly interest on savings accounts *
      * INPUT   : ACCTIN  (account master, 200 bytes)  *
      * OUTPUT  : ACCTOUT (updated master), RPTOUT     *
      *------------------------------------------------*
      * DATE       WHO  CHANGE                         *
      * 2019-03-04 RJB  Initial version                *
      * 2026-11-12 RJB  CHG0042 tiered rates           *
      *================================================*
       PROCEDURE DIVISION.
      /
      * New listing page starts here
           COMPUTE WS-INT ROUNDED = WS-BAL * WS-RATE
      *    Rate is annual / 12; see policy FIN-17
           ADD WS-INT TO WS-BAL           *> inline (2002+)
           STOP RUN.

Code Explained

The header block is just * comment lines in column 7
Change-log lines tie code changes to tickets (CHG0042)
/ forces a page break in the compiler listing
*> needs a compiler that supports 2002 syntax

Modern Equivalent

  • Python # comment and """docstring""" at module top
  • Java // comment, /* */, /** Javadoc */ above classes
  • JavaScript // comment, /* */, /** JSDoc */ above functions

Prefer / Avoid

  • commented-out dead code → delete it; version control remembers
  • change log in comments only → also commit messages in Git

Comment Syntax

FormWhere
* in col 7Whole line
/ in col 7Whole line + page eject
*>Rest of line (2002+)
D in col 7Debug-only code

Header Fields

FieldContent
PROGRAMName = load module
PURPOSEBusiness function
INPUT / OUTPUTDD names + layouts
CALLSSubprograms used
CHANGE LOGDate, who, ticket

⚠ Common Mistakes

  • Putting * in column 1 instead of 7, which makes it code
  • Inline *> on a compiler that only supports COBOL-85
  • Comments that restate the code instead of the business rule

✓ Tips & Best Practices

  • List every DD name the program uses in the header
  • Put copybook and layout names next to file definitions
  • Remove obsolete AUTHOR paragraphs only if the shop agrees

Quick Summary

  • * col 7 — line comment
  • *> — inline comment
  • / — comment + page eject
  • header block — purpose, I/O, changes
