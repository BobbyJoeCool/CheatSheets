Sheet 47

The SORT Verb

SD sort file · SORT … ON ASCENDING KEY · USING / GIVING · INPUT PROCEDURE / OUTPUT PROCEDURE · RELEASE / RETURN · SORT-RETURN

Sorting Files Inside a Program

SORT orders records by one or more keys using the system sort (DFSORT on z/OS). The simple form sorts one file USING into another GIVING. Input and output procedures let you filter or change records on the way in (RELEASE) and process them on the way out (RETURN).

Key Points

  • The sort work file is declared with SD, not FD
  • USING/GIVING files must not be open
  • Keys are fields in the SD record
  • SORT-RETURN is 0 on success

Under the Hood

  • COBOL SORT calls DFSORT on z/OS; sort work space comes from SORTWKnn DDs or dynamic allocation
  • GnuCOBOL implements SORT itself with temporary files
  • Filtering in the input procedure means fewer records to sort

USING/GIVING and Procedures

       FILE-CONTROL.
           SELECT SORT-WORK ASSIGN TO SORTWK1.
       DATA DIVISION.
       FILE SECTION.
       SD  SORT-WORK.
       01  SW-REC.
           05 SW-STATE         PIC XX.
           05 SW-CITY          PIC X(20).
           05 SW-SALES         PIC S9(7)V99 COMP-3.
           05 FILLER           PIC X(53).

       PROCEDURE DIVISION.
           SORT SORT-WORK
                ON ASCENDING  KEY SW-STATE SW-CITY
                ON DESCENDING KEY SW-SALES
                USING  SALES-IN
                GIVING SALES-SORTED
           IF SORT-RETURN NOT = 0
              DISPLAY "SORT FAILED " SORT-RETURN
              MOVE 16 TO RETURN-CODE
           END-IF

           SORT SORT-WORK ON ASCENDING KEY SW-STATE
                INPUT PROCEDURE  2000-SELECT-IA-MN
                GIVING SALES-SORTED.
       2000-SELECT-IA-MN.
           PERFORM UNTIL END-OF-SALES
              READ SALES-IN INTO SW-REC
                 AT END SET END-OF-SALES TO TRUE
                 NOT AT END
                    IF SW-STATE = "IA" OR "MN"
                       RELEASE SW-REC
                    END-IF
              END-READ
           END-PERFORM.

Code Explained

Sort by state and city ascending, then sales descending
USING/GIVING opens and closes the files for you
The input procedure opens SALES-IN itself (not shown) and RELEASEs only IA and MN
An output procedure would RETURN sorted records one at a time

Modern Equivalent

  • Python sorted(rows, key=lambda r: (r.state, r.city, -r.sales))
  • Java list.sort(comparing(R::state).thenComparing(R::city).thenComparing(R::sales, reverseOrder()))
  • JavaScript rows.sort((a, b) => a.state.localeCompare(b.state) || b.sales - a.sales)

Prefer / Avoid

  • sorting in a COBOL table by hand → SORT verb or a DFSORT step
  • SORT with no SORT-RETURN check → test it and set RETURN-CODE

SORT Pieces

PieceRole
SDSort work file
ON ASCENDING / DESCENDING KEYSort order
USING fileInput as-is
INPUT PROCEDUREFilter + RELEASE
GIVING fileOutput as-is
OUTPUT PROCEDURERETURN + process
WITH DUPLICATES IN ORDERStable for equal keys

⚠ Common Mistakes

  • Opening the USING or GIVING file yourself (they must be closed)
  • WRITE instead of RELEASE in an input procedure
  • No check of SORT-RETURN, so a failed sort looks successful

✓ Tips & Best Practices

  • Filter early in the input procedure to sort less data
  • Add WITH DUPLICATES IN ORDER when equal keys must keep input order
  • For plain sorts with no logic, a DFSORT JCL step is simpler

Quick Summary

  • SD — sort file
  • SORT … KEY — order
  • USING / GIVING — whole files
  • RELEASE / RETURN — procedures
