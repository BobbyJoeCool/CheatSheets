Building Records from Levels

COBOL data is a hierarchy: an 01 record contains numbered sub-levels, and a smaller-numbered item contains every larger-numbered item below it. Items with a PIC are elementary; items without one are groups, which are just the concatenated bytes of their children.

Key Points

  • Levels 01–49 build hierarchies; any increasing numbers work
  • Common style: 01, 05, 10, 15 so you can insert levels later
  • FILLER reserves unnamed bytes (spacing, unused fields)
  • 77 is a standalone elementary item (old style)

A Customer Record

       WORKING-STORAGE SECTION.
       01  CUSTOMER-REC.
           05 CUST-ID          PIC 9(6).
           05 CUST-NAME.
              10 FIRST-NAME    PIC X(15).
              10 LAST-NAME     PIC X(20).
           05 CUST-ADDR.
              10 STREET        PIC X(30).
              10 CITY          PIC X(20).
              10 STATE         PIC XX.
              10 ZIP           PIC 9(5).
           05 FILLER           PIC X(2).
           05 BALANCE          PIC S9(7)V99.
       77  WS-COUNT            PIC 9(4) VALUE 0.

           MOVE "ADA"      TO FIRST-NAME
           MOVE SPACES     TO CUST-ADDR      *> clears 4 fields
           DISPLAY LENGTH OF CUSTOMER-REC    *> 109

Code Explained

CUST-NAME is a group: 35 bytes made of two fields
Moving SPACES to a group fills all its bytes, numeric fields too
LENGTH OF gives the record length in bytes
FILLER keeps the layout aligned with the file format

Modern Equivalent

  • Python @dataclass with nested dataclasses, or a dict of dicts
  • Java Class with nested record fields (record Address(...))
  • JavaScript Nested object literal { name: { first, last }, addr: {...} }

Prefer / Avoid

  • 77 items → 01 items (same effect, groups later)
  • levels 01, 02, 03 → 01, 05, 10 (room to insert)

Group vs Elementary

ItemRule
GroupNo PIC; alphanumeric; its children's bytes
ElementaryHas PIC; has a type
MOVE to groupByte copy, no conversion
MOVE to elementaryConverted by type

⚠ Common Mistakes

  • Giving a group item a PIC clause (compile error)
  • Moving SPACES to a group with numeric children, then doing math on them (S0C7)
  • Changing a record layout without matching the file's record length

✓ Tips & Best Practices

  • Indent each level 3 spaces so the tree is visible
  • Put shared layouts in copybooks so every program agrees
  • Check record lengths with LENGTH OF while testing

Quick Summary

  • 01 — record
  • 05–49 — children
  • no PIC — group (bytes)
  • FILLER — unnamed bytes
