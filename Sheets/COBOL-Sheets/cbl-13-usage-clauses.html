USAGE Clauses

DISPLAY (zoned) · COMP / BINARY · COMP-3 / PACKED-DECIMAL · COMP-1 / COMP-2 · COMP-5 · INDEX / POINTER

How a Number Is Stored

USAGE decides the bytes behind a picture. DISPLAY stores one character per digit, COMP-3 packs two digits per byte (the standard for money on mainframes), and COMP stores binary integers. The picture still limits the digits; USAGE only changes storage and speed.

Key Points

  • Default USAGE is DISPLAY
  • COMP-3 is fast for decimal math on IBM Z hardware
  • COMP is best for subscripts and counters
  • Floats (COMP-1/2) are approximate: never use for money

Under the Hood

  • PIC S9(5)V99 COMP-3 = 4 bytes: X'0012345C' (C = +, D = -)
  • COMP PIC S9(4) = halfword (2 bytes), S9(9) = fullword (4 bytes)
  • With TRUNC(STD), COMP is truncated to its PIC digits; COMP-5 never is

Same Value, Different USAGE

       01  WS-ZONED   PIC S9(5)V99.               *> 7 bytes
       01  WS-PACKED  PIC S9(5)V99 COMP-3.        *> 4 bytes
       01  WS-BIN     PIC S9(4)    COMP.          *> 2 bytes
       01  WS-NATIVE  PIC S9(4)    COMP-5.        *> 2 bytes
       01  WS-FLOAT   COMP-2.                     *> 8 bytes
       01  WS-IDX     USAGE INDEX.
       01  WS-PTR     USAGE POINTER.

           MOVE -123.45 TO WS-ZONED     *> F0F0F1F2F3F4D5
           MOVE -123.45 TO WS-PACKED    *> 0012345D
           MOVE 1234    TO WS-BIN       *> 04D2
           MOVE 32000   TO WS-NATIVE    *> fits: 2-byte max 32767
           COMPUTE WS-FLOAT = 1 / 3     *> 0.333333...
           MOVE WS-PACKED TO WS-ZONED   *> converted correctly

Code Explained

Zoned: each digit is a byte, the sign is in the last byte's high nibble
Packed: two digits per byte, sign nibble last
Moving between USAGEs converts values; group moves copy raw bytes
COMP-5 holds the full binary range regardless of PIC digits

Modern Equivalent

  • Python int (arbitrary size), float, Decimal; struct.pack for raw bytes
  • Java int, long, double, BigDecimal; ByteBuffer for raw bytes
  • JavaScript Number (double), BigInt; DataView for binary layouts

Prefer / Avoid

  • DISPLAY for heavy arithmetic → COMP-3 (or COMP for counters)
  • even digit counts in COMP-3 → odd (S9(7)) to use every nibble

⚠ Common Mistakes

  • Reading packed data with the wrong PIC length, which shifts every field
  • Displaying a COMP-3 field via a group or X redefine (shows garbage)
  • Using COMP-2 for currency and getting rounding errors

✓ Tips & Best Practices

  • Use odd digit counts for COMP-3 fields
  • Check the copybook for USAGE when mapping a file layout
  • Prefer COMP-5 for values passed to C or Java

Quick Summary

  • DISPLAY — readable digits
  • COMP-3 — packed decimal
  • COMP / COMP-5 — binary
  • COMP-1/2 — floats, not for money
