Coding Format

columns 1–6 sequence · column 7 indicator · Area A (8–11) · Area B (12–72) · >>SOURCE FORMAT FREE · continuation lines

Fixed Columns from the Punch-Card Era

Classic COBOL is fixed format: every 80-column line is divided into areas. Division, section, paragraph and 01/77 level names start in Area A; statements and other levels go in Area B. Free format (2002+) drops the columns, but most production code is still fixed.

Key Points

  • Columns 73–80 are ignored (old card sequence numbers)
  • Column 7: * comment, - continuation, D debug line, / page eject
  • COBOL is case-insensitive; shops usually write uppercase
  • Words are separated by spaces; hyphens join words: WS-TOTAL

Under the Hood

  • Enterprise COBOL stores source as 80-byte FB records (LRECL=80)
  • The compiler ignores columns 73–80, so text there silently disappears
  • GnuCOBOL defaults to fixed; -free or >>SOURCE FORMAT FREE switches

Column Layout

      *A---B---+----2----+----3----+----4----+----5----+
       IDENTIFICATION DIVISION.
       PROGRAM-ID. COLS.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-MSG    PIC X(60) VALUE "THIS LITERAL IS LONG
      -        "ER THAN ONE LINE".
       PROCEDURE DIVISION.
       MAIN-PARA.
           DISPLAY WS-MSG
      D    DISPLAY "ONLY WITH DEBUGGING MODE"
           STOP RUN.

      *> Free format (2002+): no columns
      *> >>SOURCE FORMAT FREE
      *> display "anywhere on the line"

Code Explained

Ruler: * is column 7, A marks column 8 (Area A), B marks column 12 (Area B)
Continuation: the open literal runs to column 72, trailing spaces included; the next line has - in column 7 and reopens the quote
D lines compile only with WITH DEBUGGING MODE
MAIN-PARA. sits in Area A, statements in Area B (col 12+)

Modern Equivalent

  • Python Indentation is syntax; no column limits (PEP 8 suggests 79)
  • Java Free format; braces and semicolons, any column
  • JavaScript Free format; whitespace ignored, Prettier sets 80 columns

Prefer / Avoid

  • continuing long literals → shorter literals joined with STRING
  • mixed case → follow the shop standard (usually uppercase)

⚠ Common Mistakes

  • Code running past column 72 is silently cut off, causing odd errors
  • Paragraph names starting in Area B (column 12) are treated as statements
  • Using tabs, which editors and compilers count differently

✓ Tips & Best Practices

  • Turn on editor rulers at 7, 8, 12 and 72
  • Use *> inline comments only if your compiler supports 2002 syntax
  • Avoid literal continuation; split text into two literals

Quick Summary

  • 8–11 — Area A for names
  • 12–72 — Area B for code
  • * in col 7 — comment
  • >>SOURCE FORMAT FREE — free format
