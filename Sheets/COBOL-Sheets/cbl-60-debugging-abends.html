Sheet 60

Debugging & Abends

S0C7 data exception · S0C4 protection exception · S0CB divide by zero · S806 module not found · CEEDUMP · -ftrace / -debug · z/OS Debugger

When a Program Abends

An abend (abnormal end) stops a program with a code. Most COBOL abends come from bad data or bad addressing: S0C7 means arithmetic on invalid numeric data, S0C4 means touching storage the program does not own. The Language Environment CEEDUMP shows the failing statement and field values.

Key Points

  • System abends start with S, user abends with U
  • CEEDUMP shows the offset; the LIST listing maps it to a line
  • Most S0C7s come from spaces in numeric fields
  • GnuCOBOL reports the source line directly

Under the Hood

  • S0C7 = the hardware decimal instruction (AP, ZAP, CP…) saw a non-packed byte
  • S0C4 often means a LINKAGE item was used without being passed
  • Find the line: CEEDUMP offset → LIST/OFFSET listing → statement

Causes and Checks

      *>   S0C7: spaces in a numeric field
       01  WS-AMT        PIC S9(5)V99 COMP-3.
           MOVE SPACES TO WS-REC          *> WS-AMT now X'4040…'
           ADD 1 TO WS-AMT                *> S0C7

      *>   Fix: validate or initialize first
           IF WS-AMT IS NUMERIC
              ADD 1 TO WS-AMT
           ELSE
              DISPLAY "BAD AMT AT REC " WS-REC-COUNT
           END-IF

      *>   S0CB: divide by zero
           DIVIDE WS-TOTAL BY WS-COUNT GIVING WS-AVG
              ON SIZE ERROR MOVE 0 TO WS-AVG
           END-DIVIDE

      *>   Debug output on GnuCOBOL
      *>   cobc -x -debug -ftrace prog.cbl
      *>   COB_SET_TRACE=Y ./prog     (paragraph trace)
      *>   prog.cbl:57: libcob: error: subscript of 'TBL' out of bounds

Code Explained

Moving SPACES to a group puts X'40' (EBCDIC space) in the packed field
IS NUMERIC catches bad data before the arithmetic
ON SIZE ERROR prevents the divide-by-zero abend
GnuCOBOL -debug gives file and line in the error

Modern Equivalent

  • Python decimal.InvalidOperation / ValueError with a traceback
  • Java NumberFormatException / NullPointerException with a stack trace
  • JavaScript NaN silently, or a TypeError with a stack trace

Prefer / Avoid

  • DISPLAY debugging everywhere → CEEDUMP + listing, or z/OS Debugger
  • retrying abended jobs blindly → find the bad record first

⚠ Common Mistakes

  • Reading the abend code only and not the CEEDUMP traceback
  • Fixing the abend by skipping the record instead of fixing the bad data source
  • Initializing records with MOVE SPACES when they contain packed fields

✓ Tips & Best Practices

  • Keep the compile listing for every production module version
  • Log the record number and key before risky arithmetic
  • Use INITIALIZE instead of MOVE SPACES on mixed records

Quick Summary

  • S0C7 — bad numeric data
  • S0C4 — bad address
  • S806 — module not found
  • CEEDUMP + listing — find the line
