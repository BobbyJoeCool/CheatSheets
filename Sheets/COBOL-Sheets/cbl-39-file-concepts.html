How COBOL Sees Files

COBOL processes files one record at a time: a fixed layout of fields described in the program. The program names a logical file; at run time a DD name (z/OS) or environment variable (GnuCOBOL) connects it to a real dataset. Organization decides how records can be reached.

Key Points

  • Sequential: read in order, append at the end
  • Indexed (VSAM KSDS): read by key or in key order
  • Relative (RRDS): read by record number
  • Record formats: fixed (F/FB) or variable (V/VB)

The File Path Through a Program

       ENVIRONMENT DIVISION.
       INPUT-OUTPUT SECTION.
       FILE-CONTROL.
           SELECT CUST-FILE ASSIGN TO CUSTIN     *> DD name
               ORGANIZATION IS SEQUENTIAL
               FILE STATUS IS WS-CUST-STATUS.
       DATA DIVISION.
       FILE SECTION.
       FD  CUST-FILE
           RECORDING MODE IS F.
       01  CUST-REC             PIC X(100).
       WORKING-STORAGE SECTION.
       01  WS-CUST-STATUS       PIC XX.
       COPY CUSTREC.                             *> 100-byte layout
       PROCEDURE DIVISION.
           OPEN INPUT CUST-FILE
           READ CUST-FILE INTO CUSTOMER-LAYOUT
           CLOSE CUST-FILE

      *>   z/OS JCL:   //CUSTIN DD DSN=PROD.CUSTOMER,DISP=SHR
      *>   GnuCOBOL:   export DD_CUSTIN=customer.dat

Code Explained

SELECT names the file; ASSIGN TO CUSTIN names its DD
FD describes the record buffer
READ … INTO copies the record into a detailed layout
Without the DD in JCL, OPEN fails with status 35

Modern Equivalent

  • Python open("customer.dat"); path comes from config or sys.argv
  • Java Files.newBufferedReader(Path.of(...))
  • JavaScript fs.createReadStream(path) or fs.readFileSync(path)

Prefer / Avoid

  • hard-coded file paths → DD names (the JCL picks the dataset)
  • one FD per layout → one FD + READ … INTO copybook layouts

⚠ Common Mistakes

  • Assuming files are text lines: mainframe records have no newline characters
  • FD record length not matching the dataset LRECL (status 39)
  • Forgetting the DD statement in the JCL (status 35)

✓ Tips & Best Practices

  • Keep record layouts in copybooks shared by every program
  • Always declare FILE STATUS for every file
  • Use LINE SEQUENTIAL for text files when testing on GnuCOBOL
