Sheet 25

ADD & SUBTRACT

ADD … TO · GIVING · SUBTRACT … FROM · CORRESPONDING · ROUNDED · ON SIZE ERROR

English-Style Arithmetic

ADD and SUBTRACT change fields in place (TO, FROM) or store the result elsewhere (GIVING). ROUNDED rounds instead of truncating, and ON SIZE ERROR catches results too big for the receiver instead of silently losing digits.

Key Points

  • ADD A TO B changes B; ADD A B GIVING C leaves A and B alone
  • Several receivers can be listed
  • Without ROUNDED, extra decimals are truncated
  • With SIZE ERROR, the receiver is left unchanged on overflow

ADD and SUBTRACT Forms

       01  WS-A        PIC 9(3)V99  VALUE 10.25.
       01  WS-B        PIC 9(3)V99  VALUE 5.50.
       01  WS-TOTAL    PIC 9(5)V99  VALUE 0.
       01  WS-SMALL    PIC 9(3)     VALUE 990.
       01  WS-WHOLE    PIC 9(3)     VALUE 0.

           ADD WS-A TO WS-TOTAL               *> 10.25
           ADD WS-A WS-B TO WS-TOTAL          *> 26.00
           ADD WS-A WS-B GIVING WS-TOTAL      *> 15.75
           ADD WS-A TO WS-WHOLE ROUNDED       *> 10 (10.25 rounds down)
           SUBTRACT WS-B FROM WS-TOTAL        *> 10.25
           SUBTRACT WS-B FROM WS-A GIVING WS-TOTAL  *> 4.75
           ADD 20 TO WS-SMALL
              ON SIZE ERROR
                 DISPLAY "OVERFLOW: STILL " WS-SMALL   *> 990
              NOT ON SIZE ERROR
                 DISPLAY "OK"
           END-ADD
           ADD CORRESPONDING MONTH-TOTALS TO YEAR-TOTALS

Code Explained

TO adds into the existing value; GIVING replaces it
ROUNDED uses half-up rounding by default
1010 does not fit PIC 9(3), so the size error branch runs
ADD CORRESPONDING adds fields with matching names

Modern Equivalent

  • Python total += a; total = a + b; Decimal.quantize to round
  • Java total = total.add(a); setScale(2, RoundingMode.HALF_UP)
  • JavaScript total += a; for money use integer cents to avoid float drift

Prefer / Avoid

  • no SIZE ERROR on totals → ON SIZE ERROR with a logged message
  • chains of ADD/SUBTRACT → one COMPUTE when it reads better

Forms

StatementResult in
ADD a TO bb = b + a
ADD a b TO cc = c + a + b
ADD a b GIVING cc = a + b
SUBTRACT a FROM bb = b - a
SUBTRACT a FROM b GIVING cc = b - a
ADD CORR g1 TO g2Matching fields

⚠ Common Mistakes

  • Using ADD A TO B when you meant GIVING, which overwrites B's original value
  • Truncated cents because ROUNDED was left off
  • Silent overflow on totals with no SIZE ERROR check

✓ Tips & Best Practices

  • Use scope terminators (END-ADD) whenever you use SIZE ERROR
  • Accumulate totals in fields larger than any single amount
  • Keep signed (S) receivers for subtraction

Quick Summary

  • ADD … TO — in place
  • GIVING — new receiver
  • ROUNDED — half-up
  • ON SIZE ERROR — catch overflow
