PERFORM

PERFORM paragraph · PERFORM section · PERFORM … THRU · PERFORM … TIMES · top-down design · EXIT paragraphs

Calling Paragraphs

PERFORM runs a paragraph (or section) and comes back to the next statement, like calling a function with no parameters. Programs are built top-down: a main paragraph performs initialization, processing and termination paragraphs, which perform smaller ones.

Key Points

  • Paragraphs share all WORKING-STORAGE (no parameters, no locals)
  • THRU runs a range of paragraphs in source order
  • Falling into the next paragraph happens without PERFORM
  • Recursion is not allowed unless the program is RECURSIVE

Top-Down Structure

       PROCEDURE DIVISION.
       0000-MAIN.
           PERFORM 1000-INIT
           PERFORM 2000-PROCESS UNTIL END-OF-FILE
           PERFORM 9000-TERM
           STOP RUN.

       1000-INIT.
           OPEN INPUT IN-FILE OUTPUT OUT-FILE
           PERFORM 8000-READ.

       2000-PROCESS.
           PERFORM 2100-VALIDATE
           IF VALID-REC
              PERFORM 2200-WRITE
           END-IF
           PERFORM 8000-READ.

       8000-READ.
           READ IN-FILE AT END SET END-OF-FILE TO TRUE
           END-READ.

       9000-TERM.
           PERFORM 3 TIMES
              DISPLAY "*** END ***"
           END-PERFORM
           CLOSE IN-FILE OUT-FILE.

Code Explained

0000-MAIN reads like an outline of the whole program
The priming read in 1000-INIT comes before the loop
Each process pass ends by reading the next record
STOP RUN keeps control from falling into 1000-INIT

Modern Equivalent

  • Python Functions init(), process(), term() called from main()
  • Java Private methods called from main, sharing fields
  • JavaScript Functions called from main() sharing module-level state

Prefer / Avoid

  • PERFORM A THRU A-EXIT with GO TOs → plain PERFORM of small paragraphs
  • falling through paragraphs → STOP RUN/GOBACK at the end of main

Paragraph Numbering

RangeTypical Use

⚠ Common Mistakes

  • Missing STOP RUN in main, so execution falls into the next paragraph
  • Performing a paragraph that itself performs back into its caller
  • Using THRU and later inserting a paragraph inside the range

✓ Tips & Best Practices

  • Keep paragraphs short: one job each
  • Number paragraphs in the order they appear
  • Use the read-at-end pattern: priming read, then read last in the loop

Quick Summary

  • PERFORM para — call and return
  • THRU — range of paragraphs
  • n TIMES — repeat
  • top-down — main calls the rest
