Relative Files

ORGANIZATION RELATIVE · RELATIVE KEY · VSAM RRDS · slot numbers · random access by number · when to use them

Records by Slot Number

A relative file is a row of numbered slots, and you read or write a record by its slot number held in the RELATIVE KEY field. It is the COBOL equivalent of an array on disk, mapped to a VSAM RRDS. It suits data keyed by a small dense number, like day of year or store number.

Key Points

  • Slot numbers start at 1
  • The RELATIVE KEY field is in WORKING-STORAGE, not the record
  • Empty slots return INVALID KEY / status 23 on READ
  • Sequential READ skips empty slots

Store Totals by Store Number

       FILE-CONTROL.
           SELECT STORE-FILE ASSIGN TO STORES
               ORGANIZATION IS RELATIVE
               ACCESS MODE  IS RANDOM
               RELATIVE KEY IS WS-STORE-NO
               FILE STATUS  IS WS-STORE-FS.

       FILE SECTION.
       FD  STORE-FILE.
       01  STORE-REC.
           05 SR-NAME          PIC X(20).
           05 SR-SALES         PIC S9(9)V99 COMP-3.

       WORKING-STORAGE SECTION.
       01  WS-STORE-NO         PIC 9(4).

           OPEN I-O STORE-FILE
           MOVE 117 TO WS-STORE-NO
           READ STORE-FILE
              INVALID KEY
                 MOVE "NEW STORE" TO SR-NAME
                 MOVE ZERO TO SR-SALES
                 ADD WS-AMT TO SR-SALES
                 WRITE STORE-REC
              NOT INVALID KEY
                 ADD WS-AMT TO SR-SALES
                 REWRITE STORE-REC
           END-READ

Code Explained

Store 117 lives in slot 117
An empty slot gives INVALID KEY, so the code creates it
WRITE puts the record in the slot named by WS-STORE-NO
The RRDS is defined with IDCAMS NUMBERED

Modern Equivalent

  • Python A list indexed by number, or a fixed-size binary file with seek(n * size)
  • Java RandomAccessFile.seek((n - 1) * size)
  • JavaScript fs.read(fd, buf, 0, size, (n - 1) * size)

Prefer / Avoid

  • relative files for sparse keys (SSNs) → an indexed file
  • record-number math in the program → RELATIVE KEY

⚠ Common Mistakes

  • Putting the RELATIVE KEY inside the record (it must be outside)
  • Slot 0 (numbers start at 1)
  • Using relative files for large, sparse number ranges

✓ Tips & Best Practices

  • Pre-load empty slots if programs expect every slot to exist
  • Use DYNAMIC access plus START to browse from a slot
  • Prefer KSDS for anything that may grow unpredictably
