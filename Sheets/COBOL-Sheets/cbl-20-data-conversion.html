Turning Text into Numbers Safely

COBOL converts between numeric USAGEs automatically on MOVE and in arithmetic. Text is different: a PIC X field holding "12.50" is not a number. Use FUNCTION NUMVAL (or NUMVAL-C for currency) to parse it, and test IS NUMERIC before trusting any input.

Key Points

  • DISPLAY ↔ COMP-3 ↔ COMP conversions are automatic
  • NUMVAL accepts spaces, a sign and a decimal point
  • NUMVAL-C also accepts currency signs and commas
  • Moving an edited field to a numeric field de-edits it

Under the Hood

  • IS NUMERIC on a zoned field checks every byte is X'F0'–X'F9' (sign allowed last)
  • Packed fields are NUMERIC only if every nibble is a digit and the sign is C, D or F
  • Bad packed data is the classic S0C7 cause

Parsing and Converting

       01  IN-AMOUNT     PIC X(12)       VALUE "  -1,234.50".
       01  IN-QTY        PIC X(5)        VALUE "00042".
       01  WS-AMT        PIC S9(7)V99    COMP-3.
       01  WS-QTY        PIC 9(5).
       01  WS-EDITED     PIC ZZ,ZZ9.99-.
       01  WS-BACK       PIC S9(5)V99.

           COMPUTE WS-AMT = FUNCTION NUMVAL-C(IN-AMOUNT)
      *>   WS-AMT = -1234.50
           IF IN-QTY IS NUMERIC
              MOVE IN-QTY TO WS-QTY           *> 42
           ELSE
              DISPLAY "BAD QTY: " IN-QTY
           END-IF
           IF FUNCTION TEST-NUMVAL(IN-AMOUNT) = 0
              DISPLAY "VALID NUMBER TEXT"
           END-IF
           MOVE WS-AMT TO WS-EDITED           *>  1,234.50-
           MOVE WS-EDITED TO WS-BACK          *> -1234.50 (de-edit)

Code Explained

NUMVAL-C strips commas and handles the leading minus
IS NUMERIC guards the plain MOVE from text into a number
TEST-NUMVAL returns 0 when the text is a valid number
De-editing reverses an edited picture back to a value

Modern Equivalent

  • Python Decimal(s.replace(",", "")) inside try/except InvalidOperation
  • Java new BigDecimal(s.replace(",", "").trim()) with NumberFormatException
  • JavaScript Number(s.replace(/,/g, "")) then Number.isNaN() check

Prefer / Avoid

  • moving input straight to numeric → IS NUMERIC or TEST-NUMVAL first
  • manual digit-by-digit parsing → FUNCTION NUMVAL

⚠ Common Mistakes

  • Moving "12.50" from a PIC X field to PIC 9V99 (the period is not a digit)
  • Skipping validation on file input, then abending with S0C7 at 2 a.m.
  • Using NUMVAL on text with commas (use NUMVAL-C)

✓ Tips & Best Practices

  • Validate every external numeric field before arithmetic
  • Write rejects to an error file instead of abending
  • Use TEST-NUMVAL to report the position of the bad character

Quick Summary
