FD & Record Definitions

FD · RECORD CONTAINS · RECORDING MODE F / V · BLOCK CONTAINS 0 · 01 record layouts · copybook layouts

Describing the Record Buffer

The FD (file description) in the FILE SECTION describes a file's records. The 01 levels under it are the I/O buffer: READ fills it and WRITE sends it. Several 01s under one FD redefine the same buffer, which is how files with multiple record types are described.

Key Points

  • BLOCK CONTAINS 0 lets z/OS pick the best block size
  • RECORDING MODE V for variable-length records
  • Multiple 01s under an FD share storage (implicit REDEFINES)
  • Buffer contents are undefined after end-of-file or CLOSE

Under the Hood

  • RECFM=FB, LRECL=100 in JCL must match a 100-byte 01 record
  • Variable records carry a 4-byte RDW the program never sees
  • The FD buffer lives in system I/O areas: copy data out with READ … INTO

FD for Fixed and Variable Files

       FILE SECTION.
       FD  CUST-FILE
           RECORDING MODE IS F
           BLOCK CONTAINS 0 RECORDS
           RECORD CONTAINS 100 CHARACTERS.
       01  CUST-REC             PIC X(100).

       FD  TRAN-FILE
           RECORDING MODE IS V
           RECORD IS VARYING IN SIZE FROM 20 TO 200
              DEPENDING ON WS-TRAN-LEN.
       01  TRAN-HEADER.
           05 TH-TYPE           PIC X.
           05 TH-BATCH          PIC 9(6).
           05 FILLER            PIC X(13).
       01  TRAN-DETAIL.
           05 TD-TYPE           PIC X.
           05 TD-ACCT           PIC 9(10).
           05 TD-AMT            PIC S9(7)V99 COMP-3.
           05 TD-MEMO           PIC X(184).

       WORKING-STORAGE SECTION.
       01  WS-TRAN-LEN          PIC 9(4) COMP.

Code Explained

The JCL dataset for CUST-FILE should be RECFM=FB, LRECL=100
TRAN-HEADER and TRAN-DETAIL overlay the same buffer
On READ, WS-TRAN-LEN gets the actual record length
Check the type byte before using either layout

Modern Equivalent

  • Python struct.Struct("6s30s…").unpack(record) for fixed layouts
  • Java ByteBuffer.wrap(record) and get by offset
  • JavaScript Buffer slices: rec.subarray(0, 6).toString()

Prefer / Avoid

  • detailed layouts inside the FD → PIC X(n) FD + READ … INTO a copybook
  • hard-coded BLOCK CONTAINS 27920 → BLOCK CONTAINS 0

⚠ Common Mistakes

  • 01 record length different from the dataset LRECL (status 39 on OPEN)
  • Reading fields from the FD buffer after end-of-file
  • Counting the 4-byte RDW in the COBOL record length

✓ Tips & Best Practices

  • Let the system choose block sizes with BLOCK CONTAINS 0
  • Use READ … INTO so data survives the next READ
  • Keep a type byte first in every multi-layout record

Quick Summary

  • FD — file description
  • 01s — buffer layouts (shared)
  • BLOCK CONTAINS 0 — system blocks
  • V files — DEPENDING ON length
