Sheet 09

DATA DIVISION Sections

FILE SECTION · WORKING-STORAGE SECTION · LOCAL-STORAGE SECTION · LINKAGE SECTION · section order · storage lifetime

Where Every Variable Lives

All data is declared in the DATA DIVISION, in fixed sections. FILE SECTION describes record buffers, WORKING-STORAGE holds variables that keep their values between calls, LOCAL-STORAGE is fresh on every call, and LINKAGE describes data passed in by a caller.

Key Points

  • Order: FILE, WORKING-STORAGE, LOCAL-STORAGE, LINKAGE
  • WORKING-STORAGE is initialized once, when the program loads
  • LOCAL-STORAGE is re-initialized on each CALL
  • LINKAGE items have no storage of their own

All Four Sections

       DATA DIVISION.
       FILE SECTION.
       FD  CUST-FILE.
       01  CUST-REC.
           05 CUST-ID        PIC 9(6).
           05 CUST-NAME      PIC X(30).
       WORKING-STORAGE SECTION.
       01  WS-CALL-COUNT     PIC 9(5) VALUE 0.
       01  WS-EOF            PIC X    VALUE "N".
           88 END-OF-FILE             VALUE "Y".
       LOCAL-STORAGE SECTION.
       01  LS-TEMP           PIC 9(5) VALUE 0.
       LINKAGE SECTION.
       01  LK-PARM.
           05 LK-LEN         PIC S9(4) COMP.
           05 LK-DATA        PIC X(100).
       PROCEDURE DIVISION USING LK-PARM.
           ADD 1 TO WS-CALL-COUNT   *> grows each call
           ADD 1 TO LS-TEMP         *> always 1
           GOBACK.

Code Explained

CUST-REC is the buffer that each READ fills
WS-CALL-COUNT keeps counting across calls
LS-TEMP resets to 0 on each call
LK-PARM maps the caller's storage (or the JCL PARM=)

Modern Equivalent

  • Python Module globals vs function locals vs function parameters
  • Java Static fields vs local variables vs method parameters
  • JavaScript Module-scope let vs function locals vs function arguments

Prefer / Avoid

  • counters in LOCAL-STORAGE → WORKING-STORAGE when they must persist
  • recursive programs with WORKING-STORAGE → LOCAL-STORAGE + RECURSIVE

⚠ Common Mistakes

  • Reading a FILE SECTION record after end-of-file (contents are undefined)
  • Expecting LOCAL-STORAGE values to survive between calls
  • Writing to a LINKAGE item that the caller did not pass

✓ Tips & Best Practices

  • Use WS-, LS- and LK- prefixes to show each item's section
  • Copy file records into WORKING-STORAGE with READ … INTO
  • Keep LINKAGE layouts in a copybook shared with callers

Quick Summary

  • FILE SECTION — record buffers
  • WORKING-STORAGE — persistent
  • LOCAL-STORAGE — per call
  • LINKAGE — passed-in data
