Sheet 44

Indexed Files (VSAM KSDS)

ORGANIZATION INDEXED · RECORD KEY · ALTERNATE RECORD KEY … WITH DUPLICATES · ACCESS DYNAMIC · VSAM KSDS · defining with IDCAMS

Files You Can Read by Key

An indexed file keeps records in key order and lets you read any record directly by its key. On z/OS this is a VSAM KSDS (key-sequenced data set). You can also define alternate keys, like an index on a second column, which may allow duplicates.

Key Points

  • The primary key must be unique
  • The key field must be inside the record, at the position VSAM expects
  • Alternate keys need an alternate index (AIX) and PATH in VSAM
  • The cluster is created with IDCAMS before the program runs

Under the Hood

  • KSDS = data component + index component, defined together as a cluster
  • The KEYS(len offset) in IDCAMS must match the RECORD KEY in the FD
  • Inserts split control intervals (CI splits); FREESPACE leaves room for them

Indexed File Definition

       FILE-CONTROL.
           SELECT ACCT-MAST ASSIGN TO ACCTMAST
               ORGANIZATION IS INDEXED
               ACCESS MODE  IS DYNAMIC
               RECORD KEY   IS AM-ACCT-NO
               ALTERNATE RECORD KEY IS AM-SSN
                  WITH DUPLICATES
               FILE STATUS  IS WS-ACCT-FS.

       FILE SECTION.
       FD  ACCT-MAST.
       01  ACCT-REC.
           05 AM-ACCT-NO        PIC 9(10).
           05 AM-SSN            PIC 9(9).
           05 AM-NAME           PIC X(30).
           05 AM-BALANCE        PIC S9(9)V99 COMP-3.
           05 FILLER            PIC X(45).

      *>   IDCAMS (see the JCL set):
      *>   DEFINE CLUSTER (NAME(PROD.ACCT.MAST) INDEXED -
      *>          KEYS(10 0) RECORDSIZE(100 100))

Code Explained

KEYS(10 0): a 10-byte key at offset 0 = AM-ACCT-NO
DYNAMIC access allows random reads and browsing
WITH DUPLICATES lets several accounts share an SSN
The record is 100 bytes, matching RECORDSIZE(100 100)

Modern Equivalent

  • Python sqlite3 table with a PRIMARY KEY, or a dict keyed by account
  • Java A database table via JDBC, or a TreeMap<Long, Account>
  • JavaScript A database table, or a Map keyed by account number

Prefer / Avoid

  • sequential master files + sort/merge → KSDS for random lookups
  • key fields mid-record by accident → put the primary key first

⚠ Common Mistakes

  • FD key position or length not matching the IDCAMS KEYS (status 39)
  • Opening a KSDS that was never loaded in INPUT mode (empty cluster issues)
  • Forgetting the PATH DD for alternate keys

✓ Tips & Best Practices

  • Put the primary key first in the record
  • Use DYNAMIC access when one program both looks up and browses
  • Keep the IDCAMS DEFINE in source control with the program

Quick Summary

  • INDEXED — VSAM KSDS
  • RECORD KEY — unique key
  • ALTERNATE RECORD KEY — second index
  • DYNAMIC — random + browse
