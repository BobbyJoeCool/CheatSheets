FILE STATUS Codes

00 success · 10 end of file · 22 duplicate key · 23 record not found · 35 file not found · 39 attribute mismatch · check after every I/O

Checking Every I/O Result

After each OPEN, READ, WRITE, REWRITE, DELETE, START or CLOSE, COBOL puts a two-character result code in the file's FILE STATUS field. The first digit is the class: 0 success, 1 end of file, 2 key errors, 3 permanent errors, 4 logic errors, 9 implementer-specific.

Key Points

  • Declare PIC XX and add 88-levels for the codes you handle
  • With a FILE STATUS field, many errors return instead of abending
  • Check it after every statement, not just OPEN
  • VSAM adds extra feedback in an optional second field

Under the Hood

  • Status 35 on z/OS: the DD statement is missing or the dataset is not found
  • Status 39: LRECL, RECFM or key length in the JCL/catalog does not match the FD
  • Status 9x on VSAM: see the VSAM return/feedback codes (extended status)

Status Checks with 88s

       01  WS-ACCT-FS           PIC XX.
           88 FS-OK                     VALUE "00" "02".
           88 FS-EOF                    VALUE "10".
           88 FS-DUP-KEY                VALUE "22".
           88 FS-NOT-FOUND              VALUE "23".

           OPEN I-O ACCT-MAST
           IF NOT FS-OK
              DISPLAY "OPEN ACCTMAST FAILED, STATUS " WS-ACCT-FS
              MOVE 16 TO RETURN-CODE
              GOBACK
           END-IF

           MOVE WS-ACCT-NO TO AM-ACCT-NO
           READ ACCT-MAST
           EVALUATE TRUE
              WHEN FS-OK         PERFORM 2100-UPDATE
              WHEN FS-NOT-FOUND  PERFORM 2200-ADD-NEW
              WHEN OTHER         PERFORM 9900-IO-ERROR
           END-EVALUATE

Code Explained

02 means OK with a duplicate alternate key, so it counts as success
A failed OPEN ends the program with RC 16
EVALUATE handles the expected codes; anything else is an error
9900-IO-ERROR should log the file, operation, key and status

Modern Equivalent

  • Python try: open(...) except FileNotFoundError:; KeyError for missing keys
  • Java try { … } catch (NoSuchFileException e); Optional for lookups
  • JavaScript try { … } catch (err) { if (err.code === "ENOENT") … }

Prefer / Avoid

  • checking status only after OPEN → after every I/O statement
  • raw "23" literals → 88-level names

⚠ Common Mistakes

  • No FILE STATUS clause, so errors abend with less information
  • Treating status 02 as a failure
  • Continuing after a 3x or 4x status as if nothing happened

✓ Tips & Best Practices

  • Write one common I/O error paragraph that logs and sets RC 16
  • Include the key value in error messages for keyed files
  • Learn 00, 10, 22, 23, 35, 39 by heart: they cover most problems

Quick Summary

  • 00 — OK
  • 10 — end of file
  • 22 / 23 — duplicate / not found
  • 35 / 39 — missing / mismatched file
