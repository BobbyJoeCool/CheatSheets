JSON, XML & Interop

JSON GENERATE / JSON PARSE · XML GENERATE / XML PARSE · NAME OF / SUPPRESS · calling Java / C · OO COBOL note

COBOL Meets Modern Formats

Enterprise COBOL 6 can turn a group item straight into JSON or XML and parse documents back into a group, which is how mainframe programs feed REST APIs. COBOL can also call C functions and Java methods; Object-Oriented COBOL exists but is rarely used in shops.

Key Points

  • JSON GENERATE uses data names as keys (hyphens kept)
  • NAME OF renames keys; SUPPRESS drops fields
  • JSON PARSE matches keys to field names
  • GnuCOBOL support for JSON/XML statements is limited: check your version

JSON Round Trip

       01  CUSTOMER.
           05 CUST-ID        PIC 9(6)    VALUE 104217.
           05 CUST-NAME      PIC X(20)   VALUE "ADA LOVELACE".
           05 CUST-BAL       PIC S9(5)V99 VALUE 1250.50.
           05 CUST-INTERNAL  PIC X(10).
       01  JSON-DOC          PIC X(500).
       01  JSON-LEN          PIC 9(4) COMP.

           JSON GENERATE JSON-DOC FROM CUSTOMER
                COUNT IN JSON-LEN
                NAME OF CUST-ID IS "id", CUST-NAME IS "name",
                        CUST-BAL IS "balance"
                SUPPRESS CUST-INTERNAL
                ON EXCEPTION DISPLAY "JSON ERROR " JSON-CODE
           END-JSON
      *>   {"customer":{"id":104217,"name":"ADA LOVELACE",
      *>    "balance":1250.50}}

           JSON PARSE JSON-DOC(1:JSON-LEN) INTO CUSTOMER
                NAME OF CUST-ID IS "id", CUST-NAME IS "name",
                        CUST-BAL IS "balance"
           END-JSON

      *>   Calling C:  CALL "strlen" USING BY REFERENCE WS-CSTR
      *>               RETURNING WS-LEN

Code Explained

The group name becomes the outer object key
Trailing spaces in CUST-NAME are trimmed in the output
COUNT IN gives the generated length
JSON-CODE holds the error code when generation fails

Modern Equivalent

  • Python json.dumps(asdict(cust)) / json.loads(doc)
  • Java Jackson: mapper.writeValueAsString(cust) / readValue
  • JavaScript JSON.stringify(cust) / JSON.parse(doc)

Prefer / Avoid

  • hand-built JSON with STRING → JSON GENERATE
  • parsing JSON with UNSTRING → JSON PARSE

⚠ Common Mistakes

  • Receiving field too small for the generated document (exception)
  • Expecting keys like customerName without NAME OF (you get CUST-NAME)
  • Assuming GnuCOBOL handles JSON statements like Enterprise COBOL

✓ Tips & Best Practices

  • Add NAME OF clauses so APIs get camelCase keys
  • Size the output field generously and check COUNT IN
  • Use z/OS Connect to expose COBOL programs as REST APIs

Quick Summary

  • JSON GENERATE — group → JSON
  • JSON PARSE — JSON → group
  • NAME OF / SUPPRESS — shape output
  • CALL — C interop
