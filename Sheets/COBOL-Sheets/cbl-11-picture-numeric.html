Sheet 11

PICTURE — Numeric

PIC 9 · S sign · V implied decimal · P scaling · PIC S9(7)V99 · repetition 9(5)

Declaring Exact-Decimal Numbers

A numeric PICTURE says how many digits a field holds and where the decimal point is. 9 is a digit, S keeps a sign, and V marks an implied decimal point that takes no storage. The result is a fixed-point decimal, ideal for money.

Key Points

  • 9(5) is shorthand for 99999
  • Without S, a field is unsigned and drops negative signs
  • Max 18 digits by default; 31 with ARITH(EXTEND)
  • P scales without storing digits (rare)

Under the Hood

  • PIC S9(5)V99 in DISPLAY usage = 7 bytes, sign in the last byte's zone
  • The V is never stored: 123.45 is the digits 12345
  • The same picture in COMP-3 takes only 4 bytes

Numeric Pictures

       01  WS-COUNT      PIC 9(4)       VALUE 42.
      *>   stored: 0042                  range 0 to 9999
       01  WS-PRICE      PIC 9(5)V99    VALUE 123.45.
      *>   stored: 0012345               range 0 to 99999.99
       01  WS-BALANCE    PIC S9(7)V99   VALUE -500.
      *>   stored: 000050000 + sign      range +/-9999999.99
       01  WS-RATE       PIC V999       VALUE .075.
      *>   stored: 075                   range 0 to .999
       01  WS-MILLIONS   PIC 9(3)PPP    VALUE 12000.
      *>   stored: 012 (scaled by 1000)

           MOVE 12345.678 TO WS-PRICE    *> 12345.67 (truncated)
           MOVE 1234567   TO WS-PRICE    *> 34567.00 (high digits lost)
           MOVE -10       TO WS-COUNT    *> 10 (sign dropped)
           COMPUTE WS-BALANCE = WS-BALANCE * 1.05

Code Explained

Extra decimal digits are truncated unless you use ROUNDED
Too many integer digits are cut from the left, silently
Unsigned fields store the absolute value
Decimal math is exact: no floating-point drift

Modern Equivalent

  • Python Decimal("123.45"); quantize(Decimal("0.01")) to fix places
  • Java new BigDecimal("123.45").setScale(2, RoundingMode.DOWN)
  • JavaScript No decimal type: store cents as integers or use decimal.js

Prefer / Avoid

  • money in COMP-1/COMP-2 floats → S9(n)V99 fixed decimal
  • unsigned balances → always S for anything that can go negative

⚠ Common Mistakes

  • Leaving off S, so refunds become positive amounts
  • Field too small: high-order digits vanish with no error unless ON SIZE ERROR
  • Expecting V to print a decimal point (use an edited picture)

✓ Tips & Best Practices

  • Size fields for the largest real value plus headroom
  • Use ON SIZE ERROR on arithmetic into tight fields
  • Match pictures to the copybook exactly when reading files

Quick Summary

  • 9 — digit
  • S — signed
  • V — implied decimal
  • truncation — left and right, silent
