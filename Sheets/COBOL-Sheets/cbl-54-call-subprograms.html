CALL & Subprograms

CALL 'PROG' USING · BY REFERENCE / BY CONTENT / BY VALUE · static vs dynamic calls · CANCEL · ON EXCEPTION · DYNAM option

Calling Other Programs

CALL runs another compiled program and passes data with USING. BY REFERENCE (the default) shares the caller's storage, BY CONTENT passes a copy, and BY VALUE passes the value itself (for C-style APIs). Calls are static (linked in) or dynamic (loaded at run time).

Key Points

  • A literal name with NODYNAM is a static call
  • A data name (CALL WS-PGM) is always dynamic
  • The subprogram stays in memory, keeping WORKING-STORAGE, until CANCEL
  • ON EXCEPTION runs if the program cannot be found

Under the Hood

  • Static calls link the subprogram into the caller's load module (binder resolves it)
  • Dynamic calls load the module from STEPLIB/JOBLIB at the first CALL
  • Missing module on a dynamic call without ON EXCEPTION = S806 abend

Caller and Subprogram

      *> Caller
       01  WS-PGM            PIC X(8) VALUE "CALCTAX".
       01  WS-TAX-PARMS.
           05 TP-AMOUNT      PIC S9(7)V99 COMP-3.
           05 TP-STATE       PIC XX.
           05 TP-TAX         PIC S9(7)V99 COMP-3.
           05 TP-RC          PIC 99.

           MOVE 1250.00 TO TP-AMOUNT
           MOVE "IA"    TO TP-STATE
           CALL WS-PGM USING BY REFERENCE WS-TAX-PARMS
              ON EXCEPTION
                 DISPLAY "CALCTAX NOT FOUND"
           END-CALL
           IF TP-RC NOT = 0 DISPLAY "TAX ERROR " TP-RC END-IF
           CALL "LOGIT" USING BY CONTENT "TAX DONE"
           CANCEL WS-PGM                    *> fresh state next call

      *> Subprogram CALCTAX
       LINKAGE SECTION.
           COPY TAXPARMS.                   *> same layout
       PROCEDURE DIVISION USING TAX-PARMS.
           COMPUTE TP-TAX ROUNDED = TP-AMOUNT * .06
           MOVE 0 TO TP-RC
           GOBACK.

Code Explained

Calling through WS-PGM makes the call dynamic
BY REFERENCE: CALCTAX writes TP-TAX straight into the caller's field
BY CONTENT: LOGIT gets a copy and cannot change the caller's data
Caller and callee share the TAXPARMS copybook so layouts match

Modern Equivalent

  • Python tax = calc_tax(amount, state); mutable objects act like BY REFERENCE
  • Java calcTax(params); objects are passed by reference to the value
  • JavaScript calcTax(params); objects shared, primitives copied

Prefer / Avoid

  • many loose parameters → one parameter group in a copybook
  • STOP RUN in subprograms → GOBACK

⚠ Common Mistakes

  • Caller and callee layouts out of sync, shifting every field
  • Passing fewer parameters than the callee's USING expects (storage overlay)
  • Expecting a subprogram's WORKING-STORAGE to reset each call without CANCEL

✓ Tips & Best Practices

  • Put every parameter in one group defined in a shared copybook
  • Add a return-code field to every parameter area
  • Use dynamic calls when the subprogram changes often

Quick Summary
