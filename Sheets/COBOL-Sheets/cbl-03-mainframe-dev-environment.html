Where Production COBOL Lives

On z/OS, source code is stored as members of partitioned datasets (PDS), not files in folders. You edit with ISPF or VS Code with Zowe Explorer, compile and run by submitting JCL jobs, and read the output in SDSF or the Zowe job view.

Key Points

  • Typical libraries: USER.COBOL (source), USER.COPYLIB, USER.LOADLIB
  • Dataset names are uppercase, dot-separated qualifiers
  • Compile, link and run are each steps in a JCL job
  • IBM Z Xplore gives free z/OS access for learning

Compile & Run a Member (JCL)

//HELLOJOB JOB (ACCT),'COMPILE HELLO',CLASS=A,
//         MSGCLASS=X,NOTIFY=&SYSUID
//* Compile, link and run USER.COBOL(HELLO)
//CLG      EXEC IGYWCLG
//COBOL.SYSIN  DD DSN=USER.COBOL(HELLO),DISP=SHR
//COBOL.SYSLIB DD DSN=USER.COPYLIB,DISP=SHR
//GO.SYSOUT    DD SYSOUT=*

Code Explained

IGYWCLG is IBM's compile-link-go procedure
COBOL.SYSIN overrides the compile step's source input
SYSLIB is where COPY members are found
DISPLAY output lands in GO.SYSOUT in the job log

Modern Equivalent

  • Python Python script run by python job.py; no compile step
  • Java Maven build (mvn package) then java -jar app.jar
  • JavaScript npm run build && node dist/app.js in a CI pipeline

Prefer / Avoid

  • editing in ISPF only → Zowe Explorer + Git for version control
  • copying JCL from coworkers blindly → read each DD (see the JCL set)

⚠ Common Mistakes

  • Lowercase dataset names in JCL (they must be uppercase)
  • Forgetting SYSLIB, so every COPY fails to compile
  • Looking for output on the terminal instead of the job's SYSOUT

✓ Tips & Best Practices

  • Sign up for IBM Z Xplore to practice real z/OS for free
  • Keep a working JCL member per program for quick recompiles
  • Use Zowe Explorer to edit members in VS Code

Quick Summary

  • PDS(member) — where source lives
  • IGYWCLG — compile, link, go
  • SYSOUT — DISPLAY output
  • Zowe — VS Code access to z/OS
