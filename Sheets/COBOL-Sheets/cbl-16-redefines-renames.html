Sheet 16

REDEFINES & RENAMES

REDEFINES · overlaying storage · alternate record layouts · numeric / text views · 66 RENAMES · data exceptions

Two Names for the Same Bytes

REDEFINES lays a second description over the same storage, so one area can be read as different layouts. It is how COBOL handles files with several record types and how it splits a date into parts. 66 RENAMES gives a new name to a range of adjacent fields.

Key Points

  • The redefining item must follow the original at the same level
  • No new storage: both names share the bytes
  • Only the first description may have a VALUE (except 88s)
  • The redefining item must not be longer than the original (at 01 it can be)

Under the Hood

  • A packed field viewed through PIC X shows raw nibbles, not digits
  • Arithmetic on a numeric view holding spaces raises S0C7
  • REDEFINES generates no code: it only changes how offsets are named

Record Types and Date Parts

       01  TRAN-REC.
           05 TRAN-TYPE        PIC X.
              88 HEADER-REC              VALUE "H".
              88 DETAIL-REC              VALUE "D".
           05 TRAN-DATA        PIC X(79).
           05 HDR-DATA REDEFINES TRAN-DATA.
              10 HDR-BATCH     PIC 9(6).
              10 HDR-DATE      PIC 9(8).
              10 FILLER        PIC X(65).
           05 DTL-DATA REDEFINES TRAN-DATA.
              10 DTL-ACCT      PIC 9(10).
              10 DTL-AMT       PIC S9(7)V99.
              10 FILLER        PIC X(60).
       01  WS-DATE             PIC 9(8).
       01  WS-DATE-X REDEFINES WS-DATE.
           05 WS-YYYY          PIC 9(4).
           05 WS-MM            PIC 99.
           05 WS-DD            PIC 99.

           IF DETAIL-REC
              ADD DTL-AMT TO WS-TOTAL
           END-IF
           MOVE 20261112 TO WS-DATE
           DISPLAY WS-MM "/" WS-DD "/" WS-YYYY  *> 11/12/2026

Code Explained

TRAN-TYPE decides which view of TRAN-DATA is valid
Each record type keeps the same total length (79 bytes)
WS-DATE-X splits the date with no MOVEs
Always check the type field before using a view

Modern Equivalent

  • Python Tagged union: match rec.type: then a dataclass per type
  • Java Sealed interface with records per type; ByteBuffer views
  • JavaScript Discriminated union: switch (rec.type); DataView over a buffer

Prefer / Avoid

  • reading a view without checking the type → test the 88 first
  • REDEFINES for unrelated scratch fields → separate fields

66 RENAMES

FormMeaning
66 A RENAMES XAlias of X

PlacementAfter the 01 record
UseRare in new code

⚠ Common Mistakes

  • Using the detail view on a header record, which feeds text into arithmetic (S0C7)
  • Changing one layout's length so the views no longer line up
  • Putting VALUE on the redefining item

✓ Tips & Best Practices

  • Pair every REDEFINES view with an 88 on the type code
  • Keep all views the same length, padding with FILLER
  • Prefer REDEFINES over reference modification for fixed sub-fields

Quick Summary

  • REDEFINES — second layout, same bytes
  • type code + 88 — choose the view
  • 66 RENAMES — alias a field range
  • wrong view — S0C7 risk
