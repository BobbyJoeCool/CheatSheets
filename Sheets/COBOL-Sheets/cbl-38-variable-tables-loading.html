Variable-Length Tables & Loading

OCCURS … DEPENDING ON · ODO object rules · loading a table from a file · hard-coded tables via REDEFINES · table SORT

Tables Whose Size Changes

OCCURS 1 TO n TIMES DEPENDING ON count (ODO) declares a table whose logical size is held in a counter field. Storage is still reserved for the maximum. Reference tables are usually loaded from a file at startup, or hard-coded with a VALUE block redefined as a table.

Key Points

  • The ODO object (counter) must be set before using the table
  • Group length and SEARCH use the current count
  • Hard-coded tables: FILLER VALUEs, then REDEFINES … OCCURS
  • Table SORT is COBOL 2014; check your compiler

ODO, File Load and Constant Table

       01  WS-PROD-COUNT       PIC 9(4) COMP VALUE 0.
       01  PROD-TABLE.
           05 PROD-ENT OCCURS 1 TO 500 TIMES
                 DEPENDING ON WS-PROD-COUNT
                 ASCENDING KEY IS PT-CODE INDEXED BY PX.
              10 PT-CODE        PIC X(6).
              10 PT-PRICE       PIC 9(5)V99.
       01  DAY-NAMES-DATA.
           05 FILLER PIC X(9) VALUE "MONDAY".
           05 FILLER PIC X(9) VALUE "TUESDAY".
           05 FILLER PIC X(9) VALUE "WEDNESDAY".
       01  DAY-NAMES REDEFINES DAY-NAMES-DATA.
           05 DAY-NAME PIC X(9) OCCURS 3 TIMES.

       1000-LOAD-PRODUCTS.
           PERFORM UNTIL END-OF-PROD OR WS-PROD-COUNT = 500
              READ PROD-FILE
                 AT END SET END-OF-PROD TO TRUE
                 NOT AT END
                    ADD 1 TO WS-PROD-COUNT
                    MOVE PF-CODE  TO PT-CODE(WS-PROD-COUNT)
                    MOVE PF-PRICE TO PT-PRICE(WS-PROD-COUNT)
              END-READ
           END-PERFORM.

Code Explained

The counter grows as each record is loaded
The load stops at 500 so the table cannot overflow
SEARCH ALL on PROD-ENT searches only the loaded entries
DAY-NAME(2) is "TUESDAY" from the constant block

Modern Equivalent

  • Python products = [] then products.append(...); len(products)
  • Java List<Product> products = new ArrayList<>(); size()
  • JavaScript const products = []; products.push(...); length

Prefer / Avoid

  • loading without a limit check → stop at the OCCURS maximum and report
  • big hard-coded tables → a reference file loaded at startup

ODO Rules

RuleDetail
SyntaxOCCURS min TO max DEPENDING ON n
StorageAlways the maximum
CounterSet before use; 0 ≤ n ≤ max
PlacementLast item in the record (usually)
MovesGroup length uses current n

⚠ Common Mistakes

  • Using ODO entries before setting the counter
  • No limit check during the load, writing past the table end
  • Reading a file into a keyed table that is not in key order, then using SEARCH ALL

✓ Tips & Best Practices

  • Log how many entries were loaded at startup
  • Abend clearly (RC 16) if the reference file is bigger than the table
  • Keep the max OCCURS in one copybook constant

Quick Summary

  • ODO — logical size in a counter
  • load loop — stop at max
  • VALUE + REDEFINES — constant table
  • SEARCH ALL — searches current count
