Nested Programs & User-Defined Functions

nested programs · END PROGRAM · COMMON · GLOBAL / EXTERNAL data · FUNCTION-ID · REPOSITORY paragraph

Programs Inside Programs

A source file can hold nested programs, each closed with END PROGRAM. Only the parent can call them unless they are COMMON. GLOBAL data is visible to nested programs, and EXTERNAL data is shared by any program that declares it. COBOL 2002 also added user-defined functions with FUNCTION-ID.

Key Points

  • Nested programs keep helper logic private to one source file
  • GLOBAL items can be read and changed by nested programs
  • EXTERNAL items are shared across separately compiled programs
  • User-defined functions need a REPOSITORY entry in the caller

Nested Program and a Function

       IDENTIFICATION DIVISION.
       PROGRAM-ID. MAINPGM.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-TOTAL     PIC 9(7)V99 GLOBAL VALUE 0.
       PROCEDURE DIVISION.
           CALL "ADD-ITEM" USING BY CONTENT 19.99
           DISPLAY WS-TOTAL                     *> 19.99
           GOBACK.

         IDENTIFICATION DIVISION.
         PROGRAM-ID. ADD-ITEM.
         DATA DIVISION.
         LINKAGE SECTION.
         01  LK-AMT     PIC 9(5)V99.
         PROCEDURE DIVISION USING LK-AMT.
             ADD LK-AMT TO WS-TOTAL             *> GLOBAL item
             GOBACK.
         END PROGRAM ADD-ITEM.
       END PROGRAM MAINPGM.

      *> User-defined function (2002; check compiler support)
       IDENTIFICATION DIVISION.
       FUNCTION-ID. DOUBLE-IT.
       DATA DIVISION.
       LINKAGE SECTION.
       01  LK-IN        PIC 9(5).
       01  LK-OUT       PIC 9(6).
       PROCEDURE DIVISION USING LK-IN RETURNING LK-OUT.
           COMPUTE LK-OUT = LK-IN * 2
           GOBACK.
       END FUNCTION DOUBLE-IT.

Code Explained

ADD-ITEM sits inside MAINPGM and closes with END PROGRAM
WS-TOTAL is GLOBAL, so ADD-ITEM can update it directly
A caller declares REPOSITORY. FUNCTION DOUBLE-IT. then uses FUNCTION DOUBLE-IT(5)
Indentation of nested programs is style only

Modern Equivalent

  • Python Nested functions (closures) and module globals
  • Java Private static methods or nested classes; static fields
  • JavaScript Inner functions and module-scope variables

Prefer / Avoid

  • GLOBAL for everything → pass parameters; keep GLOBAL rare
  • EXTERNAL shared data → explicit parameters (easier to trace)

Visibility

ItemSeen By

COMMON programSiblings too

⚠ Common Mistakes

  • Missing END PROGRAM, so the compiler treats the rest as part of one program
  • Calling a nested program from outside its parent (not found)
  • Overusing GLOBAL until nobody knows who changes what

✓ Tips & Best Practices

  • Use nested programs for helpers that no other program needs
  • Check Enterprise COBOL and GnuCOBOL support before using FUNCTION-ID
  • Prefer separately compiled subprograms for shared logic

Quick Summary

  • nested program — private helper
  • END PROGRAM — required close
  • GLOBAL / EXTERNAL — shared data
  • FUNCTION-ID — your own functions
