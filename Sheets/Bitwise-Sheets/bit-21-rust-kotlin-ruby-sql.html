Sheet 21

Bitwise in Rust, Kotlin, Ruby & SQL

Rust !x · Kotlin inv / ushr · Ruby x[i] · SQL XOR # vs ^

Same Ideas, Different Spellings

Rust writes NOT as ! and panics on shift overflow in debug builds. Kotlin has no bitwise symbols: the operators are infix functions (and, or, xor, inv(), shl, shr, ushr). Ruby integers are unbounded like Python's and can read bit i with x[i]. SQL dialects agree on & and |, but not on XOR.

Notes

  • Rust: wrapping_*, checked_*, overflowing_* make overflow explicit
  • Kotlin infix binds looser than +/- but tighter than ==
  • PostgreSQL XOR is #; MySQL and SQL Server use ^

Rust

let x: u32 = 0b1011_0010;           // 178
format!("{x:08b} {x:#x}");          // "10110010 0xb2"
u32::from_str_radix("ff", 16);      // Ok(255)
!x;                                 // NOT: 4294967117
x.count_ones();                     // 4
x.trailing_zeros();                 // 1
x.rotate_left(4);                   // 2848
x.swap_bytes();                     // 0xB2000000
x.to_be_bytes();                    // [0, 0, 0, 178]
1u32.wrapping_shl(33);              // 2 (count masked)
1u32.checked_shl(33);               // None
-16i32 >> 2;                        // -4
(-16i32 as u32) >> 2;               // 1073741820

Kotlin

val x = 0b1011_0010               // 178
x.toString(2)                     // "10110010"
"ff".toInt(16)                    // 255
x and 0x0F                        // 2
x or 1                            // 179
x xor 0xFF                        // 77
x.inv()                           // -179
-16 shr 2                         // -4
-16 ushr 2                        // 1073741820
1L shl 40                         // 1099511627776
x.countOneBits()                  // 4
x.takeLowestOneBit()              // 2
0xFFu.toUByte()                   // 255 (unsigned types)

Ruby

x = 0b1011_0010                   # 178
x.to_s(2)                         # "10110010"
"ff".to_i(16)                     # 255
[x[1], x[0]]                      # [1, 0]  read bit i
x.bit_length                      # 8
x.to_s(2).count("1")              # 4  (popcount)
x.anybits?(0b11)                  # true   (2.5+)
x.allbits?(0b11)                  # false
~5                                # -6
[0x12345678].pack("N")            # "\x124Vx" big-endian

SQL

-- PostgreSQL
SELECT 12 & 10, 12 | 10, 12 # 10, ~12;  -- 8, 14, 6, -13
SELECT 1 << 4, bit_count(B'1011');      -- 16, 3 (PG 14+)
SELECT 178::bit(8);                     -- 10110010
-- MySQL / MariaDB
SELECT 12 ^ 10, BIT_COUNT(178);         -- 6, 4
SELECT BIN(178);                        -- '10110010'
-- SQL Server
SELECT 12 ^ 10, 13 & ~1;                -- 6, 12
-- Flags column: rows with bit 2 set
SELECT * FROM files WHERE (perms & 4) <> 0;

⚠ Common Mistakes

  • Rust: x << 32 on u32 panics in debug. Use checked_shl / wrapping_shl
  • Kotlin: 1 shl n - 1 is 1 shl (n - 1)
  • PostgreSQL ^ is power: 2 ^ 3 = 8; MySQL 2 ^ 3 = 1

✓ Tips & Best Practices

  • Rust: u32::from_be_bytes for parsing; bitflags crate for flag sets
  • Kotlin: UInt / ULong for unsigned math (0xFFu)
  • SQL: wrap flag tests in a view with named boolean columns

Quick Summary

  • Rust !x, count_ones, wrapping_shl
  • Kotlin and or xor inv shl ushr
  • Ruby x[i], to_s(2), unbounded ints
  • SQL & |; XOR # (PG) / ^ (MySQL)
