Which Byte Comes First?

Endianness is the order of a number's bytes in memory or in a file. Little-endian stores the least significant byte first (x86, ARM in practice). Big-endian stores the most significant byte first and is the network byte order of most protocols. Building a value from bytes with shifts works the same on every CPU, so it's the portable way to parse binary data.

Notes

  • 0x12345678 little: 78 56 34 12; big: 12 34 56 78
  • Only matters when bytes cross a boundary: files, sockets, raw memory

Bytes ↔ Integers (pseudocode)

// Big-endian u32 from bytes b[0..3]
v ← (b[0] << 24) | (b[1] << 16) | (b[2] << 8) | b[3]
// Little-endian u32 from the same bytes
v ← b[0] | (b[1] << 8) | (b[2] << 16) | (b[3] << 24)

// Write v as big-endian bytes
for i ← 0 to 3
    out[i] ← (v >> (24 - 8 * i)) & 0xFF

byteN ← (v >> (8 * n)) & 0xFF          // n = 0 is the lowest byte

function bswap32(v)                    // reverse byte order
    return ((v & 0xFF) << 24) | ((v & 0xFF00) << 8)
         | ((v >> 8) & 0xFF00) | ((v >> 24) & 0xFF)

Code Explained

Shifts act on values, not memory, so this code works on any CPU
Java/C# byte is signed: use b[i] & 0xFF before shifting
b[0] << 24 can hit the sign bit in Java/JS; use long or >>> 0
Built-ins: htonl/ntohl, ByteBuffer, DataView, struct, binary.BigEndian

⚠ Common Mistakes

  • Casting a raw buffer to a struct and assuming file order = CPU order
  • Skipping & 0xFF on signed bytes (Java, C#, C char)
  • Swapping twice: once by hand, once by ntohl

✓ Tips & Best Practices

  • Python: int.from_bytes(b, "big"), struct.unpack(">I", b)
  • JS: new DataView(buf).getUint32(0) is big-endian by default
  • Java: ByteBuffer.wrap(b) then .order(LITTLE_ENDIAN)

Quick Summary

  • little-endian — low byte first
  • big-endian — high byte first (network)
  • (v >> 8n) & 0xFF — byte n
  • shifts — portable parsing
