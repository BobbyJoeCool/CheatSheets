General Utilities

<stdlib.h> is the grab bag of the standard library: memory allocation, string-to-number conversion, random numbers, sorting and searching, program termination, environment access and integer helpers like abs and div. Its rand is fine for games and tests but not for security or serious simulations.

Notes

  • RAND_MAX is at least 32767
  • abs(INT_MIN) is UB (no positive equivalent)
  • getenv result must not be modified or freed
  • system runs a shell command; avoid with user input

stdlib.h in Action

#include <stdlib.h>
#include <time.h>

printf("%d %ld\n", abs(-5), labs(-7L));     // 5 7
div_t d = div(17, 5);                       // d.quot 3, d.rem 2

srand((unsigned)time(NULL));                // seed once
int die = rand() % 6 + 1;                   // 1..6 (slightly biased)
double u = rand() / (RAND_MAX + 1.0);       // [0, 1)

const char *home = getenv("HOME");          // NULL if unset
if (home) printf("%s\n", home);

int rc = system("ls -l");                   // shell exit status
char *end;
double x = strtod("2.5kg", &end);           // 2.5, end → "kg"
qsort(arr, n, sizeof arr[0], cmp_int);      // Sheet 62
exit(EXIT_SUCCESS);

Code Explained

div — quotient and remainder together
srand(time(NULL)) — different sequence each run
rand() % 6 — small bias; fine for games
getenv — read environment variables
system — returns implementation-defined status

⚠ Common Mistakes

  • Calling srand inside a loop; every call resets the sequence
  • Using rand() for passwords, tokens or keys
  • Modifying the string returned by getenv

✓ Tips & Best Practices

  • Seed once at startup; use a fixed seed in tests for reproducibility
  • Use arc4random_uniform(n) where available for unbiased ranges
  • Prefer posix_spawn/fork+exec over system for running programs
