inline & Attributes

inline suggests that calls be expanded in place and changes linkage rules; in practice, define small helpers as static inline in headers. Attributes give the compiler extra information. C23 standardized the [[...]] syntax: [[nodiscard]], [[maybe_unused]], [[deprecated]], [[fallthrough]], [[noreturn]]. Older code uses GCC/Clang's __attribute__((...)).

Notes

  • Compilers inline small functions at -O2 anyway
  • Plain inline (no static) needs one extern definition
  • _Noreturn (C11) → [[noreturn]] (C23)
  • Unknown [[vendor::x]] attributes are ignored

Using Attributes

/* util.h */
static inline int clamp(int v, int lo, int hi) {
    return v < lo ? lo : v > hi ? hi : v;
}

[[nodiscard]] int open_db(const char *path);
[[deprecated("use open_db")]] int db_open(const char *path);
[[noreturn]] void die(const char *msg);

void handler([[maybe_unused]] int sig) { }

// GCC/Clang spelling (works before C23)
__attribute__((format(printf, 1, 2)))
void log_info(const char *fmt, ...);
__attribute__((cold, noinline)) void report_error(void);
[[gnu::always_inline]] static inline int sq(int x) { return x * x; }

open_db("x");     // warning: ignoring return value

Code Explained

static inline in a header — each file gets its own copy, no link clash
[[nodiscard]] — warn if the result is ignored
[[deprecated("msg")]] — warn on use
format(printf, 1, 2) — check format string (arg 1) vs args from 2
[[gnu::...]] — vendor attribute in C23 syntax

⚠ Common Mistakes

  • Defining a plain inline function in a header without an extern inline definition somewhere: undefined reference at -O0
  • Expecting inline to force inlining; it's a hint
  • Marking a function [[noreturn]] that can return: UB

✓ Tips & Best Practices

  • Use static inline for small header helpers; it's the least surprising form
  • Add [[nodiscard]] to functions that return error codes or allocated memory
  • Wrap attributes in macros if you must support both C23 and older compilers
