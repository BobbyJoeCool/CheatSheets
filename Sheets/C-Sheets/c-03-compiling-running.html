Sheet 03

Compiling & Running

gcc main.c -o app · ./app · preprocess → compile → assemble → link · -E / -S / -c · .o object files · -I / -L / -l

From Source to Executable

Building a C program runs four stages: the preprocessor expands #include and macros, the compiler turns C into assembly, the assembler produces an object file (.o), and the linker combines object files and libraries into an executable. One cc command normally runs all four; flags let you stop after any stage, which is useful for debugging macros or inspecting generated code.

Notes

  • Each .c file compiles independently into its own .o
  • Link errors (undefined reference) come from the linker, not the compiler
  • Without -o, the output is named a.out
  • Order matters on the command line: libraries go after the files that use them

Build Commands

cc main.c -o app            # all stages → ./app
./app                       # run it (needs ./ on Unix)
./app; echo $?              # print exit status

cc -E main.c > main.i       # stop after preprocessing
cc -S main.c                # stop after compiling → main.s
cc -c main.c                # stop after assembling → main.o

# Multi-file build: compile separately, then link
cc -c main.c util.c         # main.o util.o
cc main.o util.o -o app     # link

# Headers, library paths, libraries
cc main.c -Iinclude -Llib -lmylib -lm -o app

Code Explained

-o app — name the output file
-E — preprocessed source only (see what macros became)
-S — assembly listing; add -O2 to see optimized code
-c — object file, no linking
-I / -L / -l — header dir / library dir / link libNAME

Build Stages

StageInput → OutputFlag

Compile.i → .s (assembly)-S
Assemble.s → .o (object)-c
Link.o + libs → executable(default)

⚠ Common Mistakes

  • Putting -lm before the source file with GNU ld: cc -lm main.c can fail; write cc main.c -lm
  • Compiling only main.c when the program also needs util.c, then getting undefined reference
  • Running app instead of ./app; the current directory isn't on PATH

✓ Tips & Best Practices

  • Use cc -E file.c | less to debug a confusing macro
  • Use -save-temps to keep the .i, .s and .o files from one build
  • Let make or CMake track multi-file builds (Sheets 81–82)

Quick Summary

  • cc x.c -o x — compile and link
  • -E / -S / -c — stop after a stage
  • .o — object file per .c
  • -lNAME — link a library, after the sources
