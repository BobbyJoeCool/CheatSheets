if / else if / else

if runs a statement when its condition is nonzero. Chains of else if test conditions in order and stop at the first true one; a final else catches everything else. Without braces only one statement belongs to each branch, and an else always attaches to the nearest unmatched if (the dangling-else rule), so always using braces avoids a whole class of bugs.

Notes

  • Condition can be any scalar: int, float, pointer
  • if (ptr) ⇔ if (ptr != NULL)
  • A stray ; after if (...) ends the statement
  • No elif keyword; write else if

Branching

int score = 82;
char grade;
if (score >= 90) {
    grade = 'A';
} else if (score >= 80) {
    grade = 'B';                 // this one runs
} else if (score >= 70) {
    grade = 'C';
} else {
    grade = 'F';
}

if (ptr) process(ptr);           // non-NULL

if ((n = read_count()) < 0)      // assign + test (extra parens)
    return -1;

if (x > 0);                      // BUG: empty statement
    puts("always prints");

Code Explained

else if — tested only when earlier conditions fail
Braces — make each branch a block
if (ptr) — idiomatic null check
((n = f()) < 0) — the extra parens show the assignment is intended
if (x > 0); — the ; is the whole body

⚠ Common Mistakes

  • Adding a second statement to a brace-less if: only the first is conditional (Apple's goto fail bug)
  • Testing a range with if (0 < x < 10); write if (x > 0 && x < 10)
  • Checking the same variable with if / if instead of if / else if, so multiple branches run

✓ Tips & Best Practices

  • Always use braces, even for one line; -Wmisleading-indentation catches some cases
  • Return early on errors to keep the main path un-indented
  • Order else if tests from most to least specific

Quick Summary

  • if / else if / else — first true branch wins
  • Nonzero is true
  • else binds to nearest if
  • Always use braces
