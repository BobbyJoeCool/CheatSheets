Growable Arrays

C has no built-in resizable array, so the standard pattern is a struct holding a data pointer, length and capacity. Appending checks whether there's room and, if not, reallocs to a larger capacity (usually double). Doubling keeps the average cost of each append constant. The struct owns the buffer, so it needs init and free functions.

Notes

  • Grow geometrically (×2 or ×1.5), never +1
  • Indexes stay valid after growth; pointers don't
  • Start capacity at 0 or a small number
  • Popular single-header versions exist (stb_ds)

A Minimal int Vector

typedef struct { int *data; size_t len, cap; } IntVec;

int vec_push(IntVec *v, int x) {
    if (v->len == v->cap) {
        size_t cap = v->cap ? v->cap * 2 : 8;
        int *p = realloc(v->data, cap * sizeof *p);
        if (!p) return -1;
        v->data = p;  v->cap = cap;
    }
    v->data[v->len++] = x;
    return 0;
}
int  vec_pop(IntVec *v) { return v->data[--v->len]; }  // check len first
void vec_free(IntVec *v) { free(v->data); *v = (IntVec){0}; }

IntVec v = {0};
for (int i = 0; i < 100; i++) vec_push(&v, i);
printf("%zu %zu\n", v.len, v.cap);       // 100 128
vec_free(&v);

Code Explained

{data, len, cap} — the whole state
v->cap ? v->cap * 2 : 8 — first allocation, then double
realloc(NULL, ...) — works for the first growth
*v = (IntVec){0} — reset after freeing
IntVec v = {0}; — valid empty vector

⚠ Common Mistakes

  • Growing by one element each push: O(n²) copying
  • Holding int *p = &v.data[3] across a push; realloc may move the buffer
  • Popping from an empty vector: --len underflows to SIZE_MAX

✓ Tips & Best Practices

  • Make the element type a macro parameter to generate vectors for many types (Sheet 95)
  • Add vec_reserve(v, n) to pre-size when the count is known
  • Check cap * 2 * sizeof for overflow in library-grade code

Quick Summary

  • struct { T *data; size_t len, cap; }
  • Double capacity on growth
  • realloc via a temp pointer
  • Pointers into it go stale on growth
