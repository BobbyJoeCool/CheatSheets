Defining & Calling Functions

prototype vs definition · void return · f(void) vs f() (C23 change) · prototypes in headers · return · implicit declaration error

Functions

A function has a return type, a name, a parameter list and a body. Before you call it, the compiler must see a declaration (prototype) so it can check arguments. Prototypes usually live in a header, and the definition in a .c file. void means "returns nothing", and (void) in a parameter list means "takes nothing".

Notes

  • C has no overloading or default arguments
  • C23: int f() now means int f(void)
  • Pre-C23 int f() = unspecified arguments
  • Calling an undeclared function is an error in C99+

Prototype, Definition, Call

/* geometry.h */
double area(double w, double h);     // prototype
void   print_area(double a);
int    read_count(void);             // takes no arguments

/* geometry.c */
#include "geometry.h"

double area(double w, double h) {    // definition
    return w * h;
}

void print_area(double a) {
    printf("area: %.2f\n", a);       // no return value
}

/* main.c */
double a = area(3.0, 4.5);           // 13.5
print_area(a);                       // area: 13.50
area(2, 3);                          // ints converted to double

Code Explained

Prototype — lets the compiler check calls
(void) — explicitly no parameters
return w * h; — value converted to the return type
area(2, 3) — arguments converted like assignment

⚠ Common Mistakes

  • Missing return in a non-void function: compiles with a warning, returns garbage
  • Writing int f() and assuming it means "no args" in pre-C23 code; the compiler won't check calls
  • Defining a non-static function in a header: duplicate symbols at link time

✓ Tips & Best Practices

  • Make file-local helpers static
  • Keep functions short; one job each
  • Enable -Wmissing-prototypes to catch public functions without a header declaration

Quick Summary

  • Prototype in .h, definition in .c
  • (void) — no parameters
  • void return — no value
  • static — file-private function
