Comments in C

C has two comment forms: block comments /* ... */, which can span lines, and line comments //, added in C99. Comments are replaced by a single space before preprocessing, so they can appear almost anywhere. Block comments don't nest, so the reliable way to disable a chunk of code that already contains comments is #if 0 ... #endif.

Notes

  • // is C99+; strict -std=c89 rejects it
  • Comments inside string literals are just text: "/* no */"
  • A \ at the end of a // line continues the comment onto the next line
  • Doxygen reads /** */ and /// comments to generate docs

Comment Styles

/*
 * vec.c — small dynamic array
 * Author: Ana Ruiz   License: MIT
 */

#include <stdlib.h>   // line comment: runs to end of line

/**
 * Append a value, growing the buffer if needed.
 *
 * @param v      vector to modify (not NULL)
 * @param value  value to append
 * @return 0 on success, -1 if allocation failed
 */
int vec_push(struct vec *v, int value);

int x = 10; /* inline block comment */

#if 0
    old_code();   /* comments inside are fine here */
#endif

Code Explained

File header block — purpose, author, license
/** ... */ — Doxygen doc comment; @param, @return tags
/* */ mid-line — works because it becomes a space
#if 0 — the preprocessor drops everything until #endif

⚠ Common Mistakes

  • Nesting block comments: /* a /* b */ c */ ends at the first */, leaving c */ as code
  • Commenting out code with /* */ when it already contains a block comment; use #if 0
  • Comments that repeat the code (i++; // add 1 to i) instead of explaining why

✓ Tips & Best Practices

  • Document every function in its header: what it does, ownership of pointers, error returns
  • Say who frees returned memory: "caller must free() the result"
  • Prefer #if 0 to deleting code only briefly; version control keeps the history

Quick Summary

  • /* */ — block comment, doesn't nest
  • // — line comment (C99)
  • /** @param */ — Doxygen docs
  • #if 0 — disable a code block
