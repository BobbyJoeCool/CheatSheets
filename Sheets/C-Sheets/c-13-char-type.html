The char Type

char is a 1-byte integer type that usually holds a character code. A character literal like 'A' is just a number (65 in ASCII) and in C its type is actually int. Whether plain char is signed or unsigned is implementation-defined: signed on x86, unsigned on ARM Linux. Use unsigned char when you mean raw bytes.

Notes

  • char, signed char, unsigned char are 3 distinct types
  • sizeof('A') is sizeof(int) in C (1 in C++)
  • '0' is 48, not 0; '7' - '0' is 7
  • EOF is an int (-1), not a char

Characters as Numbers

char c = 'A';
printf("%c %d\n", c, c);       // A 65
printf("%c\n", c + 1);         // B
printf("%c\n", 'a' - 32);      // A

char digit = '7';
int  value = digit - '0';      // 7

char tab = '\t', nl = '\n', nul = '\0';
char hexA = '\x41';            // 'A'
char quote = '\'';             // single quote

unsigned char byte = 0xFF;     // 255
signed char   sc   = -1;       // always signed
printf("%zu\n", sizeof('A'));  // 4 (it's an int)

Code Explained

%c prints the character; %d prints its code
digit - '0' — convert a digit character to its value
'\x41' — hex escape; '\101' octal does the same
unsigned char — 0..255, safe for byte buffers

⚠ Common Mistakes

  • Storing getchar()'s result in a char: you can't tell EOF from byte 0xFF. Use int c
  • Assuming char is signed: char c = 200; if (c > 127) behaves differently on ARM
  • Confusing 'a' (char) with "a" (2-byte string {'a', '\0'})

✓ Tips & Best Practices

  • Use unsigned char (or uint8_t) for binary data
  • Use <ctype.h> (toupper, isdigit) instead of ASCII arithmetic (Sheet 21)
  • GCC/Clang: -fsigned-char / -funsigned-char show how code depends on it

Quick Summary

  • char — 1-byte integer for characters
  • 'A' is an int (65) in C
  • c - '0' — digit char → value
  • unsigned char — raw bytes
