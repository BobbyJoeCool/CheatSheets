Unit Testing in C

C has no built-in test framework, but testing is still straightforward. The smallest option is a file of asserts run as a program. Frameworks add test discovery, readable failure messages and fixtures: Unity (tiny, embedded-friendly), Criterion (auto-registers tests), and CMocka (adds mocking). Register test executables with CTest or a make test target.

Notes

  • A test program returns non-zero on failure
  • Run tests under ASan/UBSan
  • Test static functions by #include-ing the .c in the test file
  • ctest --output-on-failure shows failing output

Minimal Harness & Unity

/* test_vec.c — no framework */
#include <assert.h>
#include "vec.h"
int main(void) {
    IntVec v = {0};
    assert(vec_push(&v, 1) == 0);
    assert(v.len == 1 && v.data[0] == 1);
    vec_free(&v);
    puts("ok");
    return 0;
}

/* test_math.c — Unity */
#include "unity.h"
void setUp(void) {}  void tearDown(void) {}
void test_add(void) { TEST_ASSERT_EQUAL_INT(5, add(2, 3)); }
void test_div(void) { TEST_ASSERT_DOUBLE_WITHIN(1e-9, 2.5, divide(5, 2)); }
int main(void) {
    UNITY_BEGIN();
    RUN_TEST(test_add);  RUN_TEST(test_div);
    return UNITY_END();
}

Code Explained

assert — aborts on the first failure
setUp / tearDown — run around each test
TEST_ASSERT_EQUAL_INT(expected, actual)
..._WITHIN(tol, ...) — float comparison
UNITY_END() — returns failure count

⚠ Common Mistakes

  • Testing with assert in a build that defines NDEBUG: nothing is checked
  • Tests that depend on run order or leftover global state
  • Comparing floats with exact equality in tests

✓ Tips & Best Practices

  • Keep each test small and named after the behavior: test_push_grows_capacity
  • Test error paths too: allocation failure, bad input, empty collections
  • Add a regression test for every bug you fix

Quick Summary

  • Test = program that exits non-zero on failure
  • Unity / Criterion / CMocka
  • Register with CTest or make test
  • Run tests under sanitizers
