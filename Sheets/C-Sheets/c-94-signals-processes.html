Signals & Processes

A signal is an asynchronous notification sent to a process: SIGINT on Ctrl-C, SIGTERM to request shutdown, SIGSEGV on a bad memory access. Standard C offers signal and raise; POSIX adds the more reliable sigaction. Handlers may only do very little: set a volatile sig_atomic_t flag and return. POSIX also creates processes with fork, exec* and waitpid.

Notes

  • Only async-signal-safe functions in handlers
  • printf and malloc are not signal-safe
  • SIGKILL / SIGSTOP can't be caught
  • fork duplicates the process; exec replaces it

Graceful Shutdown & Child Process

#include <signal.h>
#include <unistd.h>
#include <sys/wait.h>

static volatile sig_atomic_t stop = 0;
static void on_sigint(int sig) { (void)sig; stop = 1; }   // just set a flag

struct sigaction sa = {0};
sa.sa_handler = on_sigint;
sigaction(SIGINT, &sa, NULL);           // POSIX; signal() is simpler
while (!stop) do_work();
puts("shutting down");                  // safe here, not in handler

pid_t pid = fork();
if (pid == 0) {                         // child
    execlp("ls", "ls", "-l", (char *)NULL);
    _exit(127);                         // only reached if exec failed
}
int status;
waitpid(pid, &status, 0);               // parent waits
if (WIFEXITED(status)) printf("exit %d\n", WEXITSTATUS(status));

Code Explained

volatile sig_atomic_t — the only portable handler-shared type
sigaction — well-defined semantics across systems
Main loop checks the flag and cleans up normally
fork returns 0 in the child, child's pid in the parent
WEXITSTATUS — child's exit code

⚠ Common Mistakes

  • Calling printf, malloc or exit inside a signal handler; use a flag (or _exit/write)
  • Not reaping children with waitpid; they linger as zombies
  • Ignoring SIGPIPE in network code, so a closed socket kills the program

✓ Tips & Best Practices

  • Use posix_spawn for simple "run this program" cases
  • signal(SIGPIPE, SIG_IGN) and handle EPIPE instead
  • For complex signal handling, use signalfd (Linux) or a self-pipe

Quick Summary

  • Handlers: set a sig_atomic_t flag only
  • sigaction over signal
  • fork + exec + waitpid
  • SIGKILL can't be caught
