Precedence & Order

Precedence decides how an expression is grouped (a + b * c is a + (b * c)). Evaluation order is a separate question, and C mostly leaves it unspecified: in f() + g() either call may run first. Modifying the same variable twice without a sequence point between, as in i = i++, is undefined behavior. When in doubt, add parentheses and split statements.

Sequence points / ordering

  • Full expression end (;)
  • &&, ||, ?: and comma operator
  • After evaluating all function arguments, before the call
  • Function args: order unspecified

Grouping vs Order

int r = 2 + 3 * 4;          // 14
int s = (2 + 3) * 4;        // 20
int m = 1 << 2 + 1;         // 8: + binds tighter than <<

int *p = arr;
*p++;                       // *(p++): moves p, reads old element
(*p)++;                     // increments the element

int i = 1;
i = i++;                    // UB
a[i] = i++;                 // UB
printf("%d %d\n", i, i++);  // UB

int x = f() + g();          // f or g may run first
int t1 = f(); int t2 = g(); // fixed order when it matters
int y = t1 + t2;

Code Explained

* before + — standard math precedence
1 << 2 + 1 — shifts are below arithmetic
*p++ — postfix ++ binds tighter than unary *
i = i++ — two unsequenced writes to i
Separate statements to force an order

⚠ Common Mistakes

  • if (x & 1 == 0) means x & (1 == 0); write (x & 1) == 0
  • *p++ = 0 vs (*p)++: one moves the pointer, the other changes the value
  • Relying on argument order: f(i++, i++) is UB

✓ Tips & Best Practices

  • Parenthesize any mix of bitwise, shift and comparison operators
  • Use -Wsequence-point (in -Wall) and -Wparentheses
  • If a line needs a precedence table to read, split it

Quick Summary

  • Precedence groups; it doesn't order evaluation
  • Unary binds tighter than binary; , loosest
  • Two unsequenced writes = UB
  • When unsure, parenthesize
