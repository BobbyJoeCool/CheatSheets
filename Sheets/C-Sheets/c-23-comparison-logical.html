Comparison & Logical Operators

Comparing & Combining

Relational operators (< > <= >=) and equality operators (== !=) produce an int: 1 for true, 0 for false. The logical operators &&, || and ! treat any nonzero operand as true and short-circuit: the right side runs only if the left side doesn't already decide the result. That guarantee makes guards like p && p->next safe.

Notes

  • && and || are sequence points
  • && binds tighter than ||
  • Chained a < b < c is not a range check
  • Pointers compare with == or to NULL

Comparisons & Short-Circuit

int x = 5, y = 10;
printf("%d %d\n", x < y, x == y);   // 1 0
printf("%d\n", !x);                 // 0
printf("%d\n", x && 0);             // 0
printf("%d\n", 0 || y);             // 1

if (p != NULL && p->count > 0)      // safe: right side skipped if p is NULL
    use(p);

if (1 < x < 3) puts("??");          // always true! (1<x) is 0 or 1, < 3
if (1 < x && x < 3) puts("in range");

if (x = 0) { }                      // assignment, always false (bug)
if (x == 0) { }                     // comparison

int found = count > 0 || load();    // load() runs only if count <= 0

Code Explained

x < y — evaluates to int 1 or 0
p != NULL && ... — && stops at the first false operand
1 < x < 3 — parsed as (1 < x) < 3
x = 0 — assigns; -Wall warns "suggest parentheses"
|| — stops at the first true operand

⚠ Common Mistakes

  • if (x = 5) assigns and is always true. Compile with -Wall; some people write 5 == x
  • Using & instead of &&: if (n & valid()) doesn't short-circuit and does bit math
  • Comparing floats or strings with == (Sheets 12, 19)

✓ Tips & Best Practices

  • Put cheap or guarding tests first in && chains
  • Wrap an intentional assignment in extra parens: if ((n = read()) > 0)
  • Compare pointers to NULL explicitly when it helps readability

Quick Summary

  • == != < > <= >= → int 0/1
  • && || ! — logical, short-circuit
  • a < b < c is not a range test
  • = assigns, == compares
