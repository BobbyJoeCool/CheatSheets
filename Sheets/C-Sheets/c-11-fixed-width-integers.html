Exact-Size Integers

<stdint.h> (C99) defines integer types with known widths, so code means the same thing on every platform. int32_t is exactly 32 bits; int_least32_t is the smallest type with at least 32; int_fast32_t is the fastest with at least 32. It also defines intptr_t for holding pointers as integers. <inttypes.h> adds the printf/scanf macros for these types.

Notes

  • Exact types are optional, but exist on all mainstream platforms
  • size_t (unsigned) — sizes and indexes; from <stddef.h>
  • ptrdiff_t (signed) — difference of two pointers
  • Literal macros: INT64_C(1), UINT32_C(5)

Using <stdint.h>

#include <stdint.h>
#include <inttypes.h>   // PRId64 etc. (includes stdint.h)

uint8_t  byte  = 255;           // 0..255
int16_t  temp  = -40;
uint32_t crc   = 0xDEADBEEF;
int64_t  nanos = INT64_C(1700000000000000000);

size_t   n     = sizeof(int64_t);   // 8
intptr_t addr  = (intptr_t)&temp;   // pointer as integer

byte++;                             // wraps to 0
printf("%" PRIu8 " %" PRId64 "\n", byte, nanos);
printf("%zu\n", n);                 // 8
printf("%" PRIu32 "\n", UINT32_MAX);  // 4294967295

Code Explained

uint8_t — exactly 8 bits, unsigned; good for bytes
INT64_C(x) — makes a literal of the right type
intptr_t — integer wide enough to round-trip a pointer
PRIu8 / PRId64 — format strings for these types

⚠ Common Mistakes

  • Printing int64_t with %ld: wrong on Windows and macOS. Use PRId64
  • Looping for (size_t i = n - 1; i >= 0; i--): size_t is never negative, so it never stops
  • Doing math on uint8_t and expecting 8-bit results; operands are promoted to int first

✓ Tips & Best Practices

  • Use size_t for anything holding sizeof or an array index
  • Use exact-width types for binary file formats and network protocols
  • Count down safely with for (size_t i = n; i-- > 0; )

Quick Summary

  • int32_t / uint64_t — exact widths
  • size_t — unsigned size/index type
  • intptr_t — integer that holds a pointer
  • PRId64 — matching printf macro
