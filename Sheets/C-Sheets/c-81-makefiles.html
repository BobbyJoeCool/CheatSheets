Makefiles

make rebuilds only what changed. A Makefile lists rules: a target, the prerequisites it depends on, and a recipe of shell commands (indented with a tab). If any prerequisite is newer than the target, the recipe runs. Variables like CC and CFLAGS, automatic variables like $@, and pattern rules keep Makefiles short.

Notes

  • Recipes must start with a tab character
  • First target is the default (make alone)
  • make -j8 builds in parallel
  • -MMD -MP auto-tracks header dependencies

A Practical Makefile

CC      := cc
CFLAGS  := -std=c17 -Wall -Wextra -g -MMD -MP
LDFLAGS :=
LDLIBS  := -lm

SRCS := $(wildcard src/*.c)
OBJS := $(SRCS:src/%.c=build/%.o)

app: $(OBJS)
	$(CC) $(LDFLAGS) $^ $(LDLIBS) -o $@

build/%.o: src/%.c | build
	$(CC) $(CFLAGS) -c $< -o $@

build:
	mkdir -p build

.PHONY: clean
clean:
	rm -rf build app

-include $(OBJS:.o=.d)

Code Explained

:= — assign once (simply expanded)
$(SRCS:src/%.c=build/%.o) — map sources to objects
$@ target, $< first prereq, $^ all prereqs
| build — order-only: dir must exist
-include *.d — header deps from -MMD

⚠ Common Mistakes

  • Spaces instead of a tab before a recipe: missing separator
  • Not listing headers as dependencies, so changing a .h doesn't rebuild; use -MMD -MP
  • Forgetting .PHONY for clean; a file named clean stops it from running

✓ Tips & Best Practices

  • Put objects in a separate build/ directory
  • Put LDLIBS after the objects in the link line
  • For multi-platform projects, consider CMake (Sheet 82)
