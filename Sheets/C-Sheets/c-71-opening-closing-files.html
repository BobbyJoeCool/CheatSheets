Opening & Closing Files

FILE * · fopen modes "r" "w" "a" "r+" · "b" · "wx" (C11) · fclose · stdin / stdout / stderr · freopen

FILE Streams

Standard C I/O works through FILE * streams. fopen(path, mode) opens a file and returns a stream, or NULL with errno set. Three streams are always open: stdin, stdout and stderr. Every stream you open must be closed with fclose, which also flushes buffered output; ignoring its return value can hide write failures.

Notes

  • "b" matters only on Windows (no \r\n translation)
  • "x" (C11) fails if the file exists
  • Max open files is limited (FOPEN_MAX, ulimit)
  • freopen redirects an existing stream

Open, Use, Close

FILE *f = fopen("notes.txt", "r");
if (!f) {
    perror("notes.txt");               // notes.txt: No such file or directory
    return -1;
}
/* ... read ... */
fclose(f);

FILE *out = fopen("out.txt", "w");     // create or truncate
FILE *log = fopen("app.log", "a");     // append, create if missing
FILE *db  = fopen("data.bin", "r+b");  // read/write, must exist
FILE *nw  = fopen("new.txt", "wx");    // (C11) fail if it exists

if (fclose(out) == EOF) perror("close out.txt");   // write error!

freopen("errors.log", "a", stderr);    // redirect stderr
fprintf(stdout, "to the terminal\n");

Code Explained

fopen returns NULL on failure; errno says why
"w" — truncates an existing file to zero length
"a" — writes always go to the end
"r+b" — update an existing binary file
fclose result — last chance to see a failed write

⚠ Common Mistakes

  • Opening with "w" when you meant to append: the file is erased immediately
  • Not checking fopen for NULL before reading
  • Leaking file handles on early returns; use the goto cleanup pattern (Sheet 35)

✓ Tips & Best Practices

  • Include the path in error messages: perror(path)
  • Use "wx" to avoid clobbering existing files
  • Write to a temp file and rename it over the original for safe saves

Quick Summary

  • fopen(path, mode) → FILE * or NULL
  • "r" "w" "a" + +, b, x
  • fclose — flush and close; check it
  • stdin stdout stderr — always open
