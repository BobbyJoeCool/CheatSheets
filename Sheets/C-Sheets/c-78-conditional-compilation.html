Conditional Compilation

Preprocessor conditionals include or drop code before compilation, based on macros. They handle platform differences, debug-only code, feature detection and optional dependencies. #ifdef tests whether a macro is defined; #if evaluates an integer expression and can use defined(). C23 adds #elifdef, #elifndef, #warning and __has_include.

Notes

  • Undefined names in #if evaluate to 0
  • Define macros at build time: -DDEBUG
  • #error stops compilation with a message
  • List predefined macros: cc -dM -E - < /dev/null

Platform & Feature Checks

#ifdef DEBUG
#  define DBG(...) fprintf(stderr, __VA_ARGS__)
#else
#  define DBG(...) ((void)0)
#endif

#if defined(_WIN32)
#  include <windows.h>
#elif defined(__APPLE__)
#  include <TargetConditionals.h>
#elif defined(__linux__)
#  include <unistd.h>
#else
#  error "unsupported platform"
#endif
#if __STDC_VERSION__ < 201112L
#  error "C11 or newer required"
#endif

#if __has_include(<threads.h>)          // (C23; earlier as extension)
#  include <threads.h>
#endif

Code Explained

#ifdef DEBUG — only when built with -DDEBUG
((void)0) — no-op that still needs a ;
#if defined(...) / #elif — platform branches
#error — fail early with a clear message
__has_include — test whether a header exists

⚠ Common Mistakes

  • Typos in macro names: #ifdef DEBGU is silently false. Use #if with -Wundef
  • Checking __GNUC__ to mean GCC; Clang defines it too. Check __clang__ first
  • Large #ifdef blocks that are never compiled in CI and rot

✓ Tips & Best Practices

  • Keep platform-specific code in separate files behind a common header
  • Prefer #if FEATURE with -DFEATURE=0/1 over #ifdef so typos warn
  • Use CMake/configure checks to define feature macros instead of guessing
