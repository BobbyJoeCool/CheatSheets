C Strings

C has no string type. A string is an array of char ending in a null terminator '\0', and most code passes it around as a char * pointing at the first character. Every library function finds the end by scanning for '\0', so a missing terminator or a buffer one byte too small breaks everything. String literals live in read-only memory.

Notes

  • "hi" occupies 3 bytes: h, i, \0
  • strlen counts chars before \0; O(n)
  • Arrays can't be assigned: use strcpy/snprintf
  • Adjacent literals join: "ab" "cd" → "abcd"

Arrays vs Pointers

#include <string.h>

char a[] = "hello";       // array copy: 6 bytes, writable
char *p  = "hello";       // pointer to read-only literal
const char *q = "hello";  // better: say it's read-only

a[0] = 'H';               // OK → "Hello"
// p[0] = 'H';            // UB: writing to a literal

printf("%zu %zu\n", strlen(a), sizeof a);   // 5 6
printf("%zu\n", sizeof p);                  // 8 (pointer size)

char buf[16] = "hi";      // rest filled with '\0'
char name[4] = {'B', 'o', 'b', '\0'};

const char *days[] = {"Mon", "Tue", "Wed"};  // array of strings
printf("%s %c\n", days[1], days[1][0]);    // Tue T

Code Explained

char a[] — array sized by the initializer, contents copied
char *p = "..." — points at a literal; modifying it is UB
strlen vs sizeof — length vs storage (incl. \0)
const char *days[] — array of pointers to literals

⚠ Common Mistakes

  • char buf[5] = "hello"; compiles in C but leaves no room for \0; later calls read past the end
  • Comparing strings with ==: it compares addresses. Use strcmp(a, b) == 0
  • Writing through char *p = "text"; declare it const char * so the compiler stops you

✓ Tips & Best Practices

  • Size buffers as "max characters + 1"
  • Cache strlen(s) outside loops: for (size_t i = 0, n = strlen(s); i < n; i++)
  • Compile with -Wwrite-strings (GCC) to make literals const char[]

Quick Summary

  • String = char array + '\0'
  • strlen — chars before \0
  • sizeof — bytes of the array
  • Literals are read-only: const char *
