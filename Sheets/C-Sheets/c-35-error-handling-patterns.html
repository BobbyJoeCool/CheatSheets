Error Handling Patterns

goto cleanup · reverse-order cleanup · out-parameters for results · status enum returns · setjmp / longjmp · [[nodiscard]] (C23)

Structuring Error Handling

Without exceptions or destructors, C code handles errors with patterns. The most common is single-exit cleanup: on failure, goto a label that releases resources in reverse order of acquisition. Return a status code and pass results through out-parameters. setjmp/longjmp can unwind several call levels at once, but skip all cleanup in between.

Notes

  • The Linux kernel uses goto cleanup widely
  • free(NULL) is a no-op, which simplifies cleanup
  • longjmp doesn't free memory or close files
  • [[nodiscard]] (C23) warns if a status is ignored

goto Cleanup

typedef enum { OK = 0, ERR_IO, ERR_NOMEM } status;

[[nodiscard]] status load(const char *path, char **out) {
    status rc = ERR_IO;
    char *buf = NULL;
    FILE *f = fopen(path, "rb");
    if (!f) goto done;

    buf = malloc(4096);
    if (!buf) { rc = ERR_NOMEM; goto close_file; }
    if (fread(buf, 1, 4096, f) == 0) goto free_buf;

    *out = buf;                 // success: hand ownership out
    buf = NULL;
    rc = OK;
free_buf:   free(buf);
close_file: fclose(f);
done:       return rc;
}

Code Explained

status enum — one return type for all errors
Labels in reverse order — undo only what succeeded
*out = buf; buf = NULL; — transfer ownership, skip free
[[nodiscard]] — caller must use the result

⚠ Common Mistakes

  • Freeing on some error paths but not others; one cleanup block avoids leaks
  • Using longjmp across functions that hold malloced memory or open files; they leak
  • Returning -1 from one function and 0-for-error from another in the same API

✓ Tips & Best Practices

  • Initialize every resource to NULL at the top so cleanup can run unconditionally
  • Document which out-parameters are set on failure (ideally: none)
  • Provide const char *status_str(status s) for readable messages

Quick Summary

  • goto cleanup — single exit, reverse-order release
  • Status return + out-params
  • setjmp/longjmp — unwind, no cleanup
  • Be consistent across your API
