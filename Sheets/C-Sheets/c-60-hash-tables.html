Hash Tables

A hash table maps keys to values with average O(1) lookup. A hash function turns the key into an index into an array of buckets. Collisions are handled by chaining (each bucket holds a linked list) or open addressing (probe for the next free slot). When the load factor (entries / buckets) gets too high, the table grows and rehashes every entry.

Notes

  • C has no standard hash table
  • POSIX hsearch exists but is limited (one global table)
  • Keep load ≤ ~0.75 (chaining) or ≤ ~0.5–0.7 (open addressing)
  • Decide who owns key strings

Chained Hash Map (string → int)

typedef struct E { char *key; int val; struct E *next; } Entry;
typedef struct { Entry **buckets; size_t nbuckets, count; } Map;

static uint64_t fnv1a(const char *s) {          // FNV-1a hash
    uint64_t h = 14695981039346656037u;
    while (*s) { h ^= (unsigned char)*s++; h *= 1099511628211u; }
    return h;
}
int *map_get(Map *m, const char *key) {
    Entry *e = m->buckets[fnv1a(key) % m->nbuckets];
    for (; e; e = e->next)
        if (strcmp(e->key, key) == 0) return &e->val;
    return NULL;
}
int map_put(Map *m, const char *key, int val) {  // key is new
    Entry *e = malloc(sizeof *e);
    if (!e || !(e->key = strdup(key))) { free(e); return -1; }
    size_t i = fnv1a(key) % m->nbuckets;
    e->val = val; e->next = m->buckets[i]; m->buckets[i] = e;
    m->count++;                 // grow when count > 0.75 * nbuckets
    return 0;
}

Code Explained

fnv1a — simple, decent-quality string hash
% nbuckets — map hash to a bucket
Chain walk with strcmp — handle collisions
strdup(key) — the map owns its own key copy
Update existing keys via map_get; it returns int *

⚠ Common Mistakes

  • Storing the caller's key pointer instead of a copy; the key changes or is freed later
  • Never resizing: chains grow long and lookups become O(n)
  • Using % with a poor hash and a power-of-two table size; low bits collide

✓ Tips & Best Practices

  • Use an existing library for production (khash, uthash, stb_ds)
  • Use SipHash or a random seed when keys come from untrusted input
  • Keep bucket count a power of two and mix the hash, or use a prime with %

Quick Summary

  • hash(key) → bucket index
  • Chaining or open addressing
  • Resize when load factor is high
  • Own (copy) your keys
