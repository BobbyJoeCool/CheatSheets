break, continue & goto

break · continue · goto label · breaking out of nested loops · return early · when goto is acceptable

Jump Statements

break exits the innermost loop or switch; continue skips to the next iteration of the innermost loop. C has no labeled break, so leaving nested loops needs a flag, a function return, or goto. goto jumps to a label in the same function; it's discouraged in general but widely accepted for breaking out of deep nesting and for cleanup (Sheet 35).

Notes

  • break in a switch inside a loop leaves only the switch
  • continue in for still runs the step
  • Labels are function-scoped
  • Can't goto into a VLA's scope

break, continue, goto

for (int i = 0; i < 10; i++) {
    if (i % 2) continue;      // skip odd numbers
    if (i > 6) break;         // stop entirely
    printf("%d ", i);         // 0 2 4 6
}

// Leaving nested loops with goto
for (int r = 0; r < rows; r++)
    for (int c = 0; c < cols; c++)
        if (grid[r][c] == target)
            goto found;
puts("not found");
return -1;
found:
    printf("found\n");

// Or move the search into a function and return early
bool contains(int g[][COLS], int rows, int t) { /* ... return true; */ }

Code Explained

continue — jumps to i++, then the condition
break — ends the for loop
goto found — exits both loops at once
found: — label; must precede a statement
A function with return is often the cleanest exit

⚠ Common Mistakes

  • Expecting break inside a switch to exit the surrounding loop; it only leaves the switch
  • continue in a while loop that skips the increment, causing an infinite loop
  • Jumping backwards with goto to make loops; use a real loop

✓ Tips & Best Practices

  • Extract nested searches into functions so return replaces goto
  • Use a bool done flag when goto would hurt readability
  • Keep goto forward-only and local to cleanup

Quick Summary

  • break — leave loop / switch
  • continue — next iteration
  • No labeled break: goto, flag or return
  • goto — forward jumps for cleanup
