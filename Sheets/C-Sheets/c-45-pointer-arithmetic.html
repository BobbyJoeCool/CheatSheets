Pointer Arithmetic

Adding an integer to a pointer moves it by that many elements, not bytes: p + 1 on an int * advances sizeof(int) bytes. Subtracting two pointers into the same array gives the number of elements between them as a ptrdiff_t. Arithmetic is only defined within one array (plus the position one past its end); going beyond that is UB even if you never dereference.

Notes

  • p[i] is defined as *(p + i)
  • So i[p] also works (don't use it)
  • void * arithmetic is a GNU extension
  • Use char * for byte-level math

Walking an Array

int a[5] = {10, 20, 30, 40, 50};
int *p = a;                  // &a[0]

printf("%d\n", *(p + 2));    // 30
printf("%d\n", p[2]);        // 30 (same thing)
p++;                         // now &a[1]
printf("%d\n", *p);          // 20

int *end = a + 5;            // one past the end: OK to form
for (int *q = a; q < end; q++)
    printf("%d ", *q);       // 10 20 30 40 50

ptrdiff_t n = end - a;       // 5
int *mid = a + n / 2;        // &a[2]

char *bytes = (char *)a;
bytes += sizeof(int);        // moves 4 bytes → a[1]
// a + 6;                    // UB: beyond one-past-end

Code Explained

p + 2 — two ints forward (8 bytes)
p++ — move to the next element
a + 5 — valid to compute and compare; never dereference
end - a — element count as ptrdiff_t
(char *) — byte steps

⚠ Common Mistakes

  • Adding byte offsets to an int *: p + 4 moves 16 bytes, not 4
  • Comparing pointers from different arrays with <: unspecified/UB
  • Decrementing below the start (p = a - 1) as a loop sentinel: UB

✓ Tips & Best Practices

  • Prefer index notation a[i] for clarity; compilers generate the same code
  • Use begin/end pointer pairs for half-open ranges
  • Print ptrdiff_t with %td

Quick Summary

  • p + n — moves n elements
  • p[i] == *(p + i)
  • p - q — distance (ptrdiff_t)
  • Stay within array + one past end
