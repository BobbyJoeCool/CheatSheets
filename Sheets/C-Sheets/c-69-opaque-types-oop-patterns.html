Opaque Types & OOP Patterns

struct Foo; opaque pointer · create / destroy functions · encapsulation via .c files · vtable of function pointers · "inheritance" via first member · container_of

Objects in C

C has no classes, but the same ideas work with conventions. An opaque type declares struct Foo; in the header and defines it only in the .c file, so users can hold Foo * but can't touch its fields: real encapsulation. Create/destroy functions stand in for constructors and destructors. A struct of function pointers (a vtable) gives polymorphism, and embedding a base struct as the first member gives simple inheritance.

Notes

  • Pointer to struct = pointer to its first member
  • container_of recovers the outer struct from a member
  • Name functions type_verb: stack_push
  • GObject and the Linux kernel use these patterns

Opaque Type + vtable

/* shape.h */
typedef struct Shape Shape;                 // forward declaration
typedef struct {
    double (*area)(const Shape *);
    void   (*destroy)(Shape *);
} ShapeOps;
struct Shape { const ShapeOps *ops; };      // "base class"
/* circle.c */
typedef struct { Shape base; double r; } Circle;   // hidden in .c
static double circle_area(const Shape *s) {
    const Circle *c = (const Circle *)s;    // downcast
    return 3.14159 * c->r * c->r;
}
static void circle_destroy(Shape *s) { free(s); }
static const ShapeOps CIRCLE_OPS = { circle_area, circle_destroy };

Shape *circle_new(double r) {
    Circle *c = malloc(sizeof *c);
    if (c) *c = (Circle){ .base.ops = &CIRCLE_OPS, .r = r };
    return (Shape *)c;
}

Code Explained

Circle — defined only in circle.c; users hold Shape *
ShapeOps — table of "virtual" functions
Shape base first — Circle * ↔ Shape * cast is valid
static functions — private to circle.c
circle_new — the constructor

⚠ Common Mistakes

  • Putting the base struct anywhere but first and then casting Derived * ↔ Base *
  • Exposing the struct definition in the header "for convenience"; users start depending on fields
  • Forgetting to call the destroy function, or calling free directly on an object with owned resources

✓ Tips & Best Practices

  • Accept NULL in destroy functions, like free does
  • Make ops tables static const so there's one shared copy
  • Keep the public header minimal: typedef + function prototypes

Quick Summary

  • Opaque struct T; — encapsulation
  • t_new / t_free — lifecycle
  • Ops table — polymorphism
  • Base-first struct — inheritance
