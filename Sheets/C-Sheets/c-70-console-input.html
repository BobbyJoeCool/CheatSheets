Reading from stdin

scanf parses formatted input directly but is easy to misuse: it leaves the newline in the buffer, stops at whitespace for %s, and overflows buffers without a width. The robust pattern is to read a whole line with fgets, then parse it with sscanf or strtol. Always check the return value: scanf returns the number of fields it filled, or EOF.

Notes

  • scanf needs addresses: &n (not for arrays)
  • %s reads one word; always give a width
  • fgets keeps the \n if it fits
  • gets was removed in C11; never use it

scanf vs fgets + sscanf

int age;
printf("Age: ");
if (scanf("%d", &age) != 1) {           // returns fields matched
    fprintf(stderr, "not a number\n");
    return 1;
}

char name[32];
scanf("%31s", name);                    // width = size - 1, no &

char line[128];
int qty; double price;
if (fgets(line, sizeof line, stdin)) {
    line[strcspn(line, "\n")] = '\0';   // strip newline
    if (sscanf(line, "%d %lf", &qty, &price) == 2)
        printf("%d x %.2f\n", qty, price);
}

int c;
while ((c = getchar()) != '\n' && c != EOF) { }   // discard rest of line

Code Explained

!= 1 — check how many fields were read
%31s — limit prevents overflow of name[32]
fgets(buf, size, stdin) — reads one line safely
%lf — double in scanf (but %f in printf)
getchar loop — clear leftover input after a bad scanf

⚠ Common Mistakes

  • scanf("%d", age) without &: writes to a garbage address
  • Mixing scanf("%d") and fgets: the leftover \n makes fgets return an empty line
  • Looping on scanf without checking its result; bad input causes an infinite loop

✓ Tips & Best Practices

  • Read lines with fgets and parse them; it's easier to recover from bad input
  • Put a space before %c (" %c") to skip leftover whitespace
  • Use getline (POSIX) for lines of unknown length (Sheet 72)

Quick Summary

  • scanf — check the return value
  • %Ns — always set a width
  • fgets + sscanf — robust input
  • %lf for double in scanf
