Linked Lists

A linked list stores each element in a separately allocated node that points to the next node. Inserting or removing at a known position is O(1) with no shifting, but finding an element is O(n) and nodes are scattered in memory. A doubly linked list adds a prev pointer. Using a pointer-to-pointer (node **) removes special cases for the head.

Notes

  • Last node's next is NULL
  • Empty list = NULL head pointer
  • Pass &head to functions that change the head
  • Arrays are usually faster in practice (cache)

Singly Linked List

typedef struct Node { int value; struct Node *next; } Node;

int push_front(Node **head, int v) {      // O(1)
    Node *n = malloc(sizeof *n);
    if (!n) return -1;
    *n = (Node){ .value = v, .next = *head };
    *head = n;
    return 0;
}

void remove_value(Node **pp, int v) {     // no head special case
    while (*pp && (*pp)->value != v) pp = &(*pp)->next;
    if (*pp) { Node *dead = *pp; *pp = dead->next; free(dead); }
}

void list_free(Node *n) {
    while (n) { Node *next = n->next; free(n); n = next; }
}

Node *head = NULL;
push_front(&head, 3); push_front(&head, 2);   // 2 -> 3
for (Node *n = head; n; n = n->next) printf("%d ", n->value);

Code Explained

struct Node *next — self-referential type needs the tag
Node **head — lets the function change the caller's head
pp = &(*pp)->next — walk the links, not the nodes
*pp = dead->next — unlink, whether head or middle
Save next before free(n)

⚠ Common Mistakes

  • Freeing a node and then reading n->next: use-after-free
  • Passing head instead of &head to push_front; the caller's list never changes
  • Forgetting to free every node when done

✓ Tips & Best Practices

  • Keep a tail pointer for O(1) appends
  • Use the Node ** technique to delete without tracking prev
  • Consider a dynamic array first; lists win only with frequent middle inserts

Quick Summary

  • Node = value + next pointer
  • NULL head = empty list
  • Node ** — edit links uniformly
  • Free nodes one by one, saving next
