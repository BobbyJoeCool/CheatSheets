Scope & Linkage

Scope is where a name is visible: inside a block { } (block scope) or from its declaration to the end of the file (file scope). Linkage is whether the same name in different files refers to the same thing. File-scope names have external linkage by default; static makes them internal (private to the file). extern declares a name defined elsewhere.

Notes

  • Inner names shadow outer ones
  • Block-scope names have no linkage
  • One definition per external name per program
  • Function parameters have block scope

Scope & Linkage Across Files

/* counter.c */
static int count = 0;          // internal: only this file
int total = 0;                 // external: visible to others

static void bump(void) { count++; }   // private helper
void record(int n) { bump(); total += n; }

/* counter.h */
extern int total;              // declaration, not definition
void record(int n);

/* main.c */
#include "counter.h"
int x = 1;                     // file scope
void f(void) {
    int x = 2;                 // shadows file-scope x
    { int x = 3; printf("%d\n", x); }   // 3
    printf("%d\n", x);         // 2
}

Code Explained

static int count — invisible outside counter.c
int total — the one definition
extern int total; in the header — declares it for other files
Inner int x — hides the outer one inside its block

⚠ Common Mistakes

  • Defining int total = 0; in a header: every .c that includes it defines it again (link error since GCC 10's -fno-common)
  • Accidentally shadowing a parameter or global; enable -Wshadow
  • Making every helper external, so names collide across files

✓ Tips & Best Practices

  • Default to static for file-level functions and variables
  • Declare globals extern in one header, define them in one .c
  • Prefer passing data as parameters over sharing globals

Quick Summary

  • Block scope — inside { }
  • File scope — whole file after declaration
  • static — internal linkage
  • extern — declared here, defined elsewhere
