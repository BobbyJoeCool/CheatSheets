Return Codes & errno

return-code conventions (0 / -1 / NULL) · <errno.h> · errno · EINVAL / ENOMEM / ENOENT · perror · strerror · check every call

Errors Without Exceptions

C has no exceptions. Functions report failure through their return value: -1, NULL, EOF or a non-zero status, depending on the API. Many library and POSIX calls also set the global errno to a code describing *why* they failed. errno is only meaningful right after a call reports failure, and successful calls may leave it unchanged.

Notes

  • errno is thread-local in modern libcs
  • 0 is never a valid error code
  • perror(msg) prints msg: <reason>
  • Error codes are macros in <errno.h>

Checking Calls

#include <errno.h>
#include <string.h>

FILE *f = fopen("data.txt", "r");
if (f == NULL) {
    perror("data.txt");                 // data.txt: No such file or directory
    return -1;
}

errno = 0;
long v = strtol(text, &end, 10);
if (errno == ERANGE) { /* out of range */ }

char *buf = malloc(n);
if (!buf) {
    fprintf(stderr, "alloc %zu: %s\n", n, strerror(errno));
    exit(EXIT_FAILURE);
}
int saved = errno;                      // save before other calls

Code Explained

fopen returns NULL and sets errno on failure
perror — prefix + text for the current errno
errno = 0 first when 0/valid results can't signal errors
strerror(errno) — message string for formatting
Save errno before calling anything else (even printf)

Return Conventions

API returnsMeans failure
pointerNULL (fopen, malloc)
int (POSIX)-1 (open, read)
int (stdio)EOF (fclose, fputs)
countless than requested (fread)
statusnon-zero (pthread_* return the code)

⚠ Common Mistakes

  • Checking errno without a failed return: a success can leave an old value there
  • Calling printf before reading errno; it may overwrite it
  • Ignoring return values of fclose, fwrite and snprintf; data loss goes unnoticed

✓ Tips & Best Practices

  • Mark your own functions [[nodiscard]] (C23) so callers can't ignore errors
  • Return 0 for success and a negative or enum code for errors, consistently
  • Wrap repeated checks: void *xmalloc(size_t n) that exits on failure

Quick Summary

  • Check every return value
  • errno — why it failed
  • perror / strerror — readable messages
  • Save errno immediately
