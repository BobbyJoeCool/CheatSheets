Declaring Variables

A declaration tells the compiler a name and its type; a definition also reserves storage. Local variables that aren't initialized hold an indeterminate value, and reading one is undefined behavior. Globals and static variables start at zero. C99 lets you declare variables anywhere in a block, not just at the top.

Naming Rules

  • Letters, digits, _; can't start with a digit
  • _Upper and __x names are reserved
  • Case-sensitive: count ≠ Count
  • Common style: snake_case for variables

Declarations & Initialization

int count;              // local: indeterminate!
int total = 0;          // initialized
double rate = 0.075, tax = 0.0;
char grade = 'A';

int *a, b;              // a is int*, b is plain int
int *c, *d;             // both pointers

extern int shared;      // declaration only (defined elsewhere)
int shared = 5;         // definition

static int calls;       // zero-initialized (static storage)
auto n = 10;            // (C23) n is int
const int MAX = 100;    // read-only after init

Code Explained

int count; — inside a function, reading it before assignment is UB
int *a, b; — the * binds to a only
extern — says the variable exists in another file
auto (C23) — type inferred from initializer; before C23 auto meant automatic storage

⚠ Common Mistakes

  • int total; total += x; reads garbage. Initialize: int total = 0;
  • int* a, b; makes only a a pointer; spacing doesn't change that
  • Defining a global (int x = 1;) in a header: every file that includes it defines x again

✓ Tips & Best Practices

  • Declare variables where first used, initialized, in the smallest scope
  • One declarator per line avoids the int *a, b trap
  • Turn on -Wuninitialized (in -Wall) and run with -O1 or higher so it can see more

Quick Summary

  • int x = 0; — declare + initialize
  • Locals start indeterminate; globals start at 0
  • extern — declare, define elsewhere
  • auto (C23) — inferred type
