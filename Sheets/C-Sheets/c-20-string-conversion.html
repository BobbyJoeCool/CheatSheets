Converting Text and Numbers

To parse numbers from text, use the strto* family: they report where parsing stopped through an end pointer and signal overflow through errno. The older atoi and atof can't report errors at all: atoi("abc") and atoi("0") both return 0. To go the other way, format with snprintf.

Notes

  • Set errno = 0 before calling strtol
  • base 0 auto-detects 0x and leading 0
  • strtol skips leading whitespace
  • sscanf returns how many fields matched

Robust Parsing

#include <stdlib.h>
#include <errno.h>

bool parse_int(const char *s, int *out) {
    char *end;
    errno = 0;
    long v = strtol(s, &end, 10);
    if (end == s || *end != '\0') return false;   // no digits / junk
    if (errno == ERANGE || v < INT_MIN || v > INT_MAX) return false;
    *out = (int)v;
    return true;
}

strtol("0x1F", NULL, 16);      // 31
strtol("0x1F", NULL, 0);       // 31 (auto base)
strtod("3.5e2", NULL);         // 350.0
char buf[32]; snprintf(buf, sizeof buf, "%d", 42);  // "42"

Code Explained

end == s — no digits were read
*end != '\0' — trailing characters after the number
errno == ERANGE — value didn't fit in long
range check — long may be wider than int
snprintf — number → string

⚠ Common Mistakes

  • Using atoi on user input: no error detection, and overflow is UB
  • Forgetting errno = 0 first; an old ERANGE from earlier code looks like a new error
  • sscanf(s, "%d", &n) without checking it returned 1

✓ Tips & Best Practices

  • Wrap strtol in a helper like parse_int and use it everywhere
  • Use strtoul with care: "-1" parses to ULONG_MAX; reject a leading - yourself
  • For a whole line, read with fgets, then parse with strtol or sscanf

Quick Summary

  • strtol(s, &end, base) — parse with error info
  • Check end and errno
  • Avoid atoi / atof for input
  • snprintf — number to text
