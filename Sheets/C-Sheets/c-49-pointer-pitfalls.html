Pointer Bugs

Pointer bugs compile cleanly and often seem to work, then crash or corrupt data later. The main families are pointers to memory that's gone (dangling, use-after-free), pointers that were never valid (wild, NULL), accessing outside an object (out-of-bounds), freeing incorrectly (double free, freeing non-heap memory), and reading memory through the wrong type (strict aliasing).

Detect with

  • -fsanitize=address — most of these at runtime
  • -Wall -Wextra — some at compile time
  • Valgrind (Linux) — no rebuild needed
  • clang --analyze / gcc -fanalyzer

Spot the Bug

int *p = malloc(4 * sizeof *p);
free(p);
p[0] = 1;                  // use-after-free
free(p);                   // double free

int *q;                    // wild: uninitialized
*q = 3;

int a[4];
a[4] = 0;                  // out of bounds (valid: 0..3)

char *s = get_name();      // may return NULL
printf("%zu\n", strlen(s)); // NULL deref if it did

int *dangle(void) { int x = 1; return &x; }   // dangling

float f = 1.0f;
int bits = *(int *)&f;     // strict aliasing violation
int ok;  memcpy(&ok, &f, sizeof ok);           // correct way

Code Explained

After free, set p = NULL to make reuse crash predictably
a[4] — one past the end; writes over a neighbor
Check returns that may be NULL
return &x — x dies at return
memcpy — the legal way to reinterpret bytes

⚠ Common Mistakes

  • "It works on my machine": UB can pass tests and fail in production or after a compiler upgrade
  • Freeing memory you didn't malloc (stack arrays, string literals, p + 1)
  • Type punning through pointer casts instead of memcpy or a union

✓ Tips & Best Practices

  • Run every test suite under ASan + UBSan at least in CI
  • Decide and document who owns each pointer
  • Keep pointer lifetimes short and scopes small

Quick Summary

  • Dangling / use-after-free — memory gone
  • Wild / NULL — never valid
  • Out-of-bounds — past the object
  • ASan catches most at runtime
