The Conditional Operator

cond ? a : b evaluates cond and then only one of a or b, producing a value. It's the expression form of if/else, handy for initializing variables, choosing arguments and writing macros. Both branches are converted to a common type, so mixing int and double gives a double. Nested ternaries quickly get hard to read.

Notes

  • Only the chosen branch is evaluated
  • Right-associative: a ? b : c ? d : e
  • Lower precedence than most operators
  • Not an lvalue in C (it is in C++)

Choosing Values

int a = 7, b = 3;
int max = (a > b) ? a : b;               // 7
const char *word = (n == 1) ? "item" : "items";
printf("%d %s\n", n, word);

printf("%s\n", ok ? "pass" : "fail");
int abs_x = x < 0 ? -x : x;

// Common type: int and double → double
double v = flag ? 1 : 2.5;               // 1.0 or 2.5

// Nested: readable only when laid out like a table
const char *size = n < 10   ? "small"
                 : n < 100  ? "medium"
                 :            "large";

#define MIN(x, y) ((x) < (y) ? (x) : (y))

Code Explained

(a > b) ? a : b — parentheses around the condition aid reading
Inline in calls — no temporary needed
flag ? 1 : 2.5 — both arms become double
Aligned nesting — reads like an else if chain
MIN macro — evaluates the winner twice (Sheet 77)

⚠ Common Mistakes

  • x = cond ? a : b + 1; adds 1 only to b; parenthesize: (cond ? a : b) + 1
  • Putting side effects in both arms and expecting both to run
  • Mixing signed and unsigned arms: c ? -1 : 1u gives UINT_MAX, not -1

✓ Tips & Best Practices

  • Great for const variables that need a computed value
  • Use for plural words and "yes/no" in output
  • Stop at one level of nesting unless formatted as a table

Quick Summary

  • cond ? a : b — pick a value
  • Only one arm is evaluated
  • Arms convert to a common type
  • Keep it short and shallow
