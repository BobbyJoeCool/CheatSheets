Reading Text

Read text a line at a time with fgets (fixed buffer) or POSIX getline (grows its buffer), or a character at a time with fgetc. Loop on the result of the read call, not on feof: feof only becomes true after a read has already failed, so a while (!feof(f)) loop processes the last line twice or handles garbage. After the loop, ferror tells you whether it ended due to an error.

Notes

  • fgets reads at most n-1 chars and adds \0
  • A line longer than the buffer arrives in pieces
  • getline allocates; free the buffer once at the end
  • fgetc returns int so EOF is distinct

Line & Character Loops

char line[256];
int n = 0;
while (fgets(line, sizeof line, f)) {        // NULL at EOF/error
    line[strcspn(line, "\n")] = '\0';
    printf("%3d: %s\n", ++n, line);
}
if (ferror(f)) perror("read");

char *buf = NULL;  size_t cap = 0;  ssize_t len;  // POSIX getline
while ((len = getline(&buf, &cap, f)) != -1)
    printf("%zd chars\n", len);
free(buf);

int c;  long lines = 0;
while ((c = fgetc(f)) != EOF)                // char by char
    if (c == '\n') lines++;

int id; char name[32];                       // structured: fscanf
while (fscanf(f, "%d %31s", &id, name) == 2) { }

Code Explained

while (fgets(...)) — stops on EOF or error
strcspn trick — drop the trailing newline
getline(&buf, &cap, f) — reallocates buf as needed
int c — must be int to hold EOF
== 2 — stop when a record doesn't parse

⚠ Common Mistakes

  • while (!feof(f)) { fgets(...); ... } handles the last line twice
  • Storing fgetc's result in char: 0xFF bytes look like EOF (or EOF is never seen)
  • Assuming fgets always returns a full line; check for \n to detect truncation

✓ Tips & Best Practices

  • Use getline on POSIX systems for unknown line lengths
  • Track line numbers for error messages: file:line: message
  • Read files in binary mode on Windows if you need exact bytes

Quick Summary

  • Loop on fgets / getline / fgetc results
  • Never while (!feof(f))
  • ferror after the loop
  • int c for fgetc
