Function Pointers

A function pointer stores the address of a function so you can call it indirectly. They power callbacks (qsort's comparator), plug-in style dispatch tables and simple polymorphism. The declaration syntax is awkward, int (*fp)(int), so a typedef usually makes them readable. A function name used as a value converts to a pointer automatically.

Notes

  • fp(x) and (*fp)(x) are equivalent
  • &f and f give the same pointer
  • Signatures must match exactly
  • Can't convert to void * portably

Callbacks & Dispatch

int add(int a, int b) { return a + b; }
int mul(int a, int b) { return a * b; }

int (*op)(int, int) = add;           // pointer to function
printf("%d\n", op(2, 3));            // 5
op = mul;
printf("%d\n", op(2, 3));            // 6

typedef int (*binop)(int, int);      // readable alias
int apply(binop f, int a, int b) { return f(a, b); }
apply(add, 4, 5);                    // 9

binop table[] = { add, mul };        // dispatch table
table[1](3, 4);                      // 12

int cmp_int(const void *a, const void *b) {
    int x = *(const int *)a, y = *(const int *)b;
    return (x > y) - (x < y);
}
qsort(arr, n, sizeof arr[0], cmp_int);

Code Explained

int (*op)(int, int) — parens around *op are required
typedef ... binop — name the pointer type once
apply(add, ...) — pass a function as an argument
table[1](3, 4) — call through an array
(x > y) - (x < y) — overflow-safe comparator

⚠ Common Mistakes

  • int *fp(int) declares a function, not a pointer; you need int (*fp)(int)
  • Comparator return x - y; overflows for large values
  • Calling a function through a pointer of a different type: UB

✓ Tips & Best Practices

  • Always typedef function pointer types used more than once
  • Pass a void *ctx alongside callbacks so they can reach user data
  • Check the pointer for NULL before calling an optional callback

Quick Summary

  • T (*fp)(args) — function pointer
  • typedef it
  • Callbacks, dispatch tables, qsort
  • Signatures must match
