Atomics

<stdatomic.h> (C11) provides atomic types and operations that are safe to use from multiple threads without a lock: _Atomic int counter; makes counter++ an indivisible read-modify-write. Every atomic operation takes a memory order; the default, memory_order_seq_cst, is the easiest to reason about. A data race on a non-atomic variable is undefined behavior.

Notes

  • Plain ++ on _Atomic is atomic (seq_cst)
  • atomic_int etc. are typedefs for _Atomic int
  • atomic_flag is the only guaranteed lock-free type
  • volatile is not atomic

Atomic Counters & Flags

#include <stdatomic.h>

atomic_int hits = 0;                     // _Atomic int
atomic_bool ready = false;

void on_request(void) {
    atomic_fetch_add(&hits, 1);          // same as hits++ here
}

atomic_fetch_add_explicit(&hits, 1, memory_order_relaxed);  // just counting
int seen = atomic_load(&hits);

int expected = 0;                        // compare-and-swap
if (atomic_compare_exchange_strong(&hits, &expected, 100))
    puts("was 0, now 100");              // else expected = current value

atomic_flag lock = ATOMIC_FLAG_INIT;     // tiny spinlock
while (atomic_flag_test_and_set(&lock)) { /* spin */ }
/* critical section */
atomic_flag_clear(&lock);

atomic_store_explicit(&ready, true, memory_order_release);   // publish

Code Explained

atomic_fetch_add — atomic +=, returns old value
memory_order_relaxed — atomicity only, no ordering
compare_exchange — set only if current == expected
atomic_flag_test_and_set — basic spinlock
release store / acquire load — publish data safely

⚠ Common Mistakes

  • Using volatile int for thread communication: no atomicity, no ordering
  • Mixing atomic and non-atomic access to the same variable
  • Choosing relaxed to publish data another thread will read; use release/acquire

✓ Tips & Best Practices

  • Default to seq_cst; optimize memory orders only with measurements
  • Prefer a mutex for anything more complex than a counter or flag
  • Check atomic_is_lock_free(&x) for large atomic types

Quick Summary

  • _Atomic T / atomic_int
  • atomic_fetch_add, CAS
  • seq_cst default; relaxed for counters
  • Data races on plain vars = UB
