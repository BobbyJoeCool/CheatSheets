Arithmetic Operators

C has the usual + - * / % plus increment and decrement. With integers, / truncates toward zero and % takes the sign of the left operand. Signed overflow is undefined behavior, so the compiler may assume it never happens; unsigned arithmetic wraps around. C23's <stdckdint.h> adds ckd_add, ckd_sub and ckd_mul, which report overflow safely.

Notes

  • (a / b) * b + a % b == a always holds
  • Dividing by zero is UB for integers
  • % works only on integers; use fmod for floats
  • INT_MIN / -1 overflows (UB)

Integer Arithmetic

printf("%d\n", 7 / 2);      // 3
printf("%d\n", -7 / 2);     // -3 (toward zero)
printf("%d\n", 7 % 3);      // 1
printf("%d\n", -7 % 3);     // -1 (sign of left)
printf("%f\n", 7 / 2.0);    // 3.500000

int i = 5;
int a = i++;                // a = 5, i = 6
int b = ++i;                // b = 7, i = 7

unsigned u = 0;
u--;                        // UINT_MAX (wraps, defined)
int big = INT_MAX;
// big + 1                  // UB!

#include <stdckdint.h>      // (C23)
int sum;
if (ckd_add(&sum, big, 1)) puts("overflow");  // overflow

Code Explained

7 / 2 — integer division drops the fraction
-7 % 3 — -1, not 2
i++ / ++i — value before / after increment
u-- from 0 — unsigned wrap is well-defined
ckd_add(&r, a, b) — returns true if the result overflowed

⚠ Common Mistakes

  • Checking overflow after it happens: if (a + b < a) is UB for int. Check first or use ckd_add / __builtin_add_overflow
  • Using % to test oddness with negatives: -3 % 2 == -1, so x % 2 == 1 misses it; use x % 2 != 0
  • average = (a + b) / 2 can overflow; use a + (b - a) / 2

✓ Tips & Best Practices

  • Pre-C23, GCC/Clang offer __builtin_add_overflow(a, b, &r)
  • Build tests with -fsanitize=undefined to catch signed overflow at runtime
  • Use -fwrapv only if you truly need wrapping signed math; it hides bugs

Quick Summary

  • / truncates toward zero
  • % takes the left operand's sign
  • Signed overflow = UB; unsigned wraps
  • ckd_add (C23) — checked arithmetic
