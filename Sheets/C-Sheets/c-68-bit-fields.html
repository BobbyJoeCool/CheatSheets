Bit-Fields

A bit-field member declares an exact number of bits: unsigned mode : 3;. The compiler packs adjacent bit-fields into storage units, saving memory and making flag sets readable. The catch is portability: bit order, packing across units and padding are all implementation-defined, so bit-fields don't reliably match hardware registers or file formats across compilers.

Notes

  • Allowed types: unsigned int, signed int, _Bool (+ others as extensions)
  • Can't take the address of a bit-field
  • Plain int bit-fields may be signed or unsigned
  • : 0 forces the next field to a new unit

Declaring Bit-Fields

struct flags {
    unsigned is_open   : 1;
    unsigned is_dirty  : 1;
    unsigned mode      : 3;     // 0..7
    unsigned           : 0;     // start a new storage unit
    unsigned priority  : 4;     // 0..15
};

struct flags f = {.is_open = 1, .mode = 5};
f.priority = 12;
f.mode = 9;                      // truncated to 9 & 7 == 1
printf("%zu\n", sizeof f);      // 8 (typical)
// unsigned *p = &f.mode;        // error: no address

// Portable alternative: masks on a fixed-width integer
enum { OPEN = 1u << 0, DIRTY = 1u << 1, MODE_SHIFT = 2, MODE_MASK = 7u << 2 };
uint32_t reg = OPEN | (5u << MODE_SHIFT);
unsigned mode = (reg & MODE_MASK) >> MODE_SHIFT;   // 5

⚠ Common Mistakes

  • Mapping bit-fields onto hardware registers or network headers and expecting the same layout on every compiler
  • Using signed 1-bit fields: int b : 1 can only hold 0 and -1
  • Updating bit-fields from multiple threads; neighbors share a memory unit

✓ Tips & Best Practices

  • Use bit-fields for in-memory flag sets; masks for external formats
  • Always use unsigned (or bool) for bit-field types
  • Check sizes with static_assert if memory layout matters

Quick Summary

  • unsigned x : n — n-bit member
  • Packing & order are implementation-defined
  • No address-of
  • Masks for portable layouts
