Recursion

A recursive function calls itself on a smaller problem until it reaches a base case that returns directly. Each call gets its own stack frame with its own locals, so deep recursion can overflow the stack (often 8 MB on Linux/macOS main threads, 1 MB on Windows). C compilers may turn tail calls into loops at -O2, but the standard doesn't guarantee it.

Notes

  • Every recursive function needs a base case
  • Each call costs a stack frame
  • Tail-call elimination isn't guaranteed
  • Trees and divide-and-conquer suit recursion

Classic Examples

unsigned long long factorial(unsigned n) {
    if (n <= 1) return 1;           // base case
    return n * factorial(n - 1);    // recursive case
}
factorial(5);                       // 120

long fib(int n) {                   // exponential time: O(2^n)
    return n < 2 ? n : fib(n - 1) + fib(n - 2);
}

long fib_iter(int n) {              // same result, O(n), no stack growth
    long a = 0, b = 1;
    while (n-- > 0) { long t = a + b; a = b; b = t; }
    return a;
}

int sum_tail(const int *a, size_t n, int acc) {   // tail recursive
    return n == 0 ? acc : sum_tail(a + 1, n - 1, acc + a[0]);
}

Code Explained

if (n <= 1) return 1; — stops the recursion
n * factorial(n - 1) — work done after the call returns
fib — recomputes subproblems; fine only for small n
fib_iter — loop version
sum_tail — last action is the call; may be optimized to a loop

⚠ Common Mistakes

  • Missing or unreachable base case: infinite recursion → stack overflow (segfault)
  • Recursing on user-controlled depth (e.g. deeply nested JSON) without a limit
  • Naive fib(50) takes billions of calls; memoize or iterate

✓ Tips & Best Practices

  • Convert deep recursion to a loop with an explicit stack (array)
  • Memoize overlapping subproblems with a lookup table
  • Check stack size with ulimit -s; raise it for threads via pthread_attr_setstacksize

Quick Summary

  • Base case + smaller recursive case
  • Each call uses stack space
  • Tail calls may be optimized, not guaranteed
  • Deep or linear → prefer loops
