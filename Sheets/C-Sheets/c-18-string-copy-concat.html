Copying & Concatenating

strcpy / strncpy · strcat / strncat · buffer overflows · snprintf as safe copy · strdup / strndup (C23) · strlcpy (BSD)

Copying & Joining

Copying and concatenating strings means moving bytes into a buffer you sized. The classic functions strcpy and strcat don't know the destination size and will overflow it. The bounded versions have traps too: strncpy may leave the result unterminated. For most code, snprintf is the safest single tool: it always terminates and tells you whether the output was truncated.

Notes

  • snprintf returns the length it wanted to write
  • strdup / strndup allocate; caller must free
  • strdup is standard in C23 (POSIX before)
  • strlcpy / strlcat — BSD, macOS, glibc 2.38+

Safe Copy & Concatenate

#include <string.h>
#include <stdlib.h>
char dst[16];

strcpy(dst, "short");                  // fine if it fits
snprintf(dst, sizeof dst, "%s", src);  // always terminated

int n = snprintf(dst, sizeof dst, "%s-%d", name, id);
if (n < 0 || (size_t)n >= sizeof dst) { /* truncated */ }

size_t len = strlen(dst);              // append safely
snprintf(dst + len, sizeof dst - len, "%s", ".txt");

strncpy(dst, src, sizeof dst - 1);     // may not terminate,
dst[sizeof dst - 1] = '\0';            // so do it yourself

char *copy = strdup(src);              // malloc'd copy
free(copy);

Code Explained

snprintf(dst, size, ...) — writes at most size-1 chars + \0
n >= sizeof dst — output was truncated
dst + len — append by printing at the current end
strncpy — pads with zeros, no \0 if src is too long
strdup — returns heap memory you must free

Concatenate Functions

FunctionNotes
strcat(d, s)no bound; overflow risk
strncat(d, s, n)n = max chars from s, not buffer size
strlcat(d, s, n)n = full buffer size
snprintf(d + len, ...)portable bounded append

⚠ Common Mistakes

  • strncat(dst, src, sizeof dst): the limit is characters to append, not buffer size, so it can still overflow
  • Assuming strncpy terminates: it doesn't when the source fills the buffer
  • Overlapping source and destination with strcpy/memcpy; that's UB. Use memmove

✓ Tips & Best Practices

  • Prefer snprintf for building strings and check its return value
  • Track lengths yourself (len variable) to avoid repeated strlen scans
  • Turn on -D_FORTIFY_SOURCE=2 -O2 to add runtime overflow checks to these calls

Quick Summary

  • snprintf — bounded, always terminated
  • strcpy / strcat — only when size is proven
  • strncpy — may not terminate
  • strdup — heap copy; free it
