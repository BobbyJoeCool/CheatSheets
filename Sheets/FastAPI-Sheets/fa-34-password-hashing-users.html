Password Hashing & Users

pwdlib (Argon2) · hash / verify · never store plain text · get_current_active_user · user models

Description

Never store passwords: store a slow, salted hash and compare on login. FastAPI's docs now recommend pwdlib with Argon2, the current best-practice algorithm. Keep three user shapes: UserCreate (has password), the DB User (has hashed_password), and UserOut (has neither).

Notes

  • pip install "pwdlib[argon2]"
  • Each hash includes its own salt and settings
  • verify takes constant time; don't compare strings yourself
  • passlib is unmaintained; prefer pwdlib

Register & Authenticate

from pwdlib import PasswordHash

hasher = PasswordHash.recommended()        # Argon2id

def hash_password(raw: str) -> str:
    return hasher.hash(raw)                # "$argon2id$v=19$m=65536,..."

def authenticate(db, email: str, password: str) -> User | None:
    user = db.scalar(select(User).where(User.email == email))
    if user is None:
        hasher.hash(password)              # same work, no timing leak
        return None
    if not hasher.verify(password, user.hashed_password):
        return None
    return user

@app.post("/users", status_code=201)
def register(data: UserCreate, db: DbSession) -> UserOut:
    if db.scalar(select(User).where(User.email == data.email)):
        raise HTTPException(409, "Email already registered")
    user = User(email=data.email,
                hashed_password=hash_password(data.password))
    db.add(user); db.commit(); db.refresh(user)
    return user

Code Explained

PasswordHash.recommended() — Argon2id with safe defaults
hasher.hash() — salt + hash in one string
hasher.verify() — check a login attempt
dummy hash on unknown email — equal timing
409 — duplicate email

Other Framework

  • Flask — werkzeug.security.generate_password_hash() / check_password_hash()
  • Django — user.set_password() / check_password() (PBKDF2 or Argon2)

Prefer / Avoid

  • Avoid MD5/SHA-256 for passwords · Prefer Argon2 or bcrypt
  • Avoid returning the DB User · Prefer UserOut

⚠ Common Mistakes

  • Logging request bodies that include passwords
  • Different error messages for "no user" vs "wrong password"
  • Enforcing maximum lengths too small; allow long passphrases

✓ Tips & Best Practices

  • Use hasher.verify_and_update() to upgrade old hashes on login
  • Add is_active and check it in get_current_user
  • Require min_length=12 on UserCreate.password

Quick Summary

  • pwdlib + Argon2 — current best practice
  • hash() / verify() — never compare yourself
  • three user models — create, DB, out
  • same timing — unknown user vs wrong password
