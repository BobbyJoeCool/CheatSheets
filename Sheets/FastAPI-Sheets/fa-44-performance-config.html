Sheet 44

Performance & Production Config

ORJSONResponse · response caching · connection pooling · root_path · docs off in prod · logging

Description

FastAPI is fast out of the box; most real gains come from fewer and cheaper I/O calls. Reuse connection pools and HTTP clients, cache hot responses, pick a faster JSON encoder, and paginate. Production config also means correct proxy settings (root_path, forwarded headers), structured logging, and no debug-only features.

Notes

  • Measure first: py-spy, OpenTelemetry, or simple timing middleware
  • Pydantic v2 serialization is already Rust-fast
  • orjson helps with large JSON responses
  • Uvicorn --proxy-headers trusts X-Forwarded-*

Production Settings

import logging
from fastapi import FastAPI
from fastapi.responses import ORJSONResponse

logging.basicConfig(level=logging.INFO,
    format="%(asctime)s %(levelname)s %(name)s %(message)s")
log = logging.getLogger("todo")

app = FastAPI(
    default_response_class=ORJSONResponse,    # faster JSON
    root_path="/api",                         # behind proxy at /api
    docs_url=None if settings.prod else "/docs",
    redoc_url=None,
)

@app.get("/todos/stats")
async def stats(response: Response, cache: Redis):
    if hit := await cache.get("stats"):
        return ORJSONResponse(content=json.loads(hit))
    data = await compute_stats()
    await cache.set("stats", json.dumps(data), ex=60)
    response.headers["Cache-Control"] = "public, max-age=60"
    return data

Code Explained

default_response_class=ORJSONResponse — app-wide fast JSON
root_path — correct URLs and docs behind a path prefix
docs disabled in prod via settings
Redis cache — 60 s for an expensive query
Cache-Control — let CDNs and browsers cache

Other Framework

  • Flask — flask-caching; ProxyFix for proxy headers
  • Django — cache framework + @cache_page

Prefer / Avoid

  • Avoid N+1 queries · Prefer eager loading / joins
  • Avoid print() debugging in prod · Prefer logging with levels

⚠ Common Mistakes

  • Optimizing JSON speed while making 50 DB queries per request
  • Missing --forwarded-allow-ips, so client IPs all show as the proxy
  • Caching per-user data under a shared key

✓ Tips & Best Practices

  • Add OpenTelemetry instrumentation for traces across services
  • Set pool_size + max_overflow per worker, not per server
  • Load-test with realistic data sizes

Quick Summary

  • measure, then optimize I/O first
  • ORJSONResponse — faster JSON
  • root_path + proxy headers — behind a proxy
  • logging + no docs/reload — prod config
