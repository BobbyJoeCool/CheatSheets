Sheet 16

model_config & Settings

ConfigDict · extra=forbid · populate_by_name · pydantic-settings · BaseSettings · .env · lru_cache

Description

model_config = ConfigDict(...) changes how a model behaves: reject unknown keys, use camelCase aliases, freeze instances. pydantic-settings applies the same idea to configuration: a BaseSettings class reads environment variables and .env files, validates them, and fails fast at startup if something is missing.

Notes

  • pip install pydantic-settings (separate package)
  • Env var names are case-insensitive by default
  • Real env vars override .env file values
  • Never commit .env; commit .env.example

Config + Settings

from functools import lru_cache
from typing import Annotated
from fastapi import Depends
from pydantic import BaseModel, ConfigDict
from pydantic.alias_generators import to_camel
from pydantic_settings import BaseSettings, SettingsConfigDict

class ApiModel(BaseModel):
    model_config = ConfigDict(alias_generator=to_camel,
                              populate_by_name=True, extra="forbid")
    due_date: str                    # JSON key "dueDate"

class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=".env", env_prefix="APP_")
    database_url: str                # APP_DATABASE_URL (required)
    debug: bool = False
    secret_key: str

@lru_cache
def get_settings() -> Settings:
    return Settings()

SettingsDep = Annotated[Settings, Depends(get_settings)]

Code Explained

alias_generator=to_camel — snake in Python, camel in JSON
populate_by_name — accept either name on input
extra="forbid" — unknown keys → 422
env_prefix="APP_" — read APP_DEBUG, etc.
@lru_cache — build settings once, reuse

Other Framework

  • Flask — app.config.from_prefixed_env() (sheet 52)
  • Django — settings.py + os.environ or django-environ

Prefer / Avoid

  • Avoid os.getenv() scattered in code · Prefer one Settings class
  • Avoid a global settings = Settings() in tests · Prefer get_settings + override

⚠ Common Mistakes

  • Calling Settings() in many places: rereads env each time
  • Committing .env with real secrets
  • extra="forbid" on settings, then crashing on unrelated env vars from .env

✓ Tips & Best Practices

  • Override get_settings in tests with app.dependency_overrides
  • Use SecretStr for keys so they don't print
  • Validate settings at startup in the lifespan (sheet 26)

Quick Summary

  • ConfigDict — model behavior switches
  • aliases — camelCase JSON, snake_case Python
  • BaseSettings — typed env config
  • @lru_cache — one settings instance
