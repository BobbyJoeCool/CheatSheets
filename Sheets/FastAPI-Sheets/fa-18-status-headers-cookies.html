Sheet 18

Status Codes, Headers & Cookies

status.HTTP_201_CREATED · Response parameter · response.headers · set_cookie() · responses=

Description

To change the status code, headers or cookies while still returning a model, declare a parameter of type Response. FastAPI injects a temporary response; anything you set on it is merged into the final one. Use status_code= on the decorator for the normal case and responses= to document other codes.

Notes

  • from fastapi import status has named constants
  • Setting response.status_code overrides the decorator for that call
  • set_cookie and delete_cookie take standard cookie options
  • responses= only documents; it doesn't change behavior

Tweak the Response

from fastapi import Response, status

@app.put("/todos/{todo_id}", status_code=200,
         responses={201: {"description": "Created"},
                    404: {"description": "Not found"}})
def upsert(todo_id: int, todo: TodoIn, response: Response) -> TodoOut:
    if not exists(todo_id):
        response.status_code = status.HTTP_201_CREATED
    response.headers["X-Todo-Version"] = "3"
    return save(todo_id, todo)

@app.post("/login")
def login(form: LoginForm, response: Response):
    token = make_session(form)
    response.set_cookie("session", token, httponly=True,
                        secure=True, samesite="lax",
                        max_age=60 * 60 * 24 * 7)
    return {"ok": True}

@app.post("/logout")
def logout(response: Response):
    response.delete_cookie("session")

Code Explained

response: Response — injected, merged into the result
response.status_code — per-call override
response.headers[...] — add custom headers
set_cookie(httponly, secure, samesite) — safe session cookie
responses={...} — extra codes in /docs

Other Framework

  • Flask — return (body, 201, {"X-H": "v"}) or make_response()
  • Django — resp = JsonResponse(...); resp.status_code = 201

Prefer / Avoid

  • Avoid building a JSONResponse just to add a header · Prefer the Response param
  • Avoid cookies without httponly/secure · Prefer safe defaults

⚠ Common Mistakes

  • Returning a new Response and also setting the injected one: injected changes are lost
  • samesite="none" without secure=True: browsers reject it
  • Using 200 for creates: clients expect 201 + the new resource

✓ Tips & Best Practices

  • Add a Location header on 201 responses
  • Document every non-200 code clients must handle
  • Prefer status constants over bare numbers in reviews

Quick Summary

  • status_code= — default success code
  • response: Response — set code, headers, cookies
  • set_cookie() — httponly + secure + samesite
  • responses= — document other codes
