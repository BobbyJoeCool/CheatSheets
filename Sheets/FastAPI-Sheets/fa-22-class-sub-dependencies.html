Sheet 22

Class & Sub-Dependencies

classes as dependencies · __call__ · dependency chains · use_cache=False · parameterized

Description

A class works as a dependency because calling it creates an instance: its __init__ parameters become request parameters. Dependencies can depend on other dependencies, forming chains such as session → current user → admin check. An instance with __call__ lets you parameterize a dependency, like RoleChecker("admin").

Notes

  • Depends() with no arg reuses the annotated type
  • Sub-dependency results are cached per request too
  • use_cache=False forces a fresh call
  • Chains keep each dependency small and testable

Chain + Parameterized Check

from dataclasses import dataclass
from typing import Annotated
from fastapi import Depends, HTTPException

@dataclass
class Pager:                                  # class dependency
    skip: int = 0
    limit: int = 20

def get_current_user(token: Annotated[str, Depends(oauth2)]) -> User:
    return decode_user(token)                  # sheet 33

CurrentUser = Annotated[User, Depends(get_current_user)]

class RoleChecker:
    def __init__(self, role: str):
        self.role = role
    def __call__(self, user: CurrentUser) -> User:
        if self.role not in user.roles:
            raise HTTPException(403, "Forbidden")
        return user

@app.get("/admin/users")
def admin_users(pager: Annotated[Pager, Depends()],
                admin: Annotated[User, Depends(RoleChecker("admin"))]):
    ...

Code Explained

Pager dataclass — fields become query params
Depends() empty — uses the annotated class
RoleChecker("admin") — configured instance
__call__(user: CurrentUser) — sub-dependency chain
403 raised before the route body runs

Other Framework

  • Flask — decorators like @roles_required("admin") (Flask-Security)
  • Django — PermissionRequiredMixin, @permission_required

Prefer / Avoid

  • Avoid copying role checks inside route bodies · Prefer a dependency
  • Avoid one giant get_everything dependency · Prefer small chained ones

Resolution Order

StepWhat happens
1sub-dependencies resolved first
2results cached by callable

4route called with all results

⚠ Common Mistakes

  • Mutable class-level defaults on dependency classes shared across requests
  • Expecting use_cache to cache across requests: it is per request only
  • Raising 401 for a logged-in user who lacks a role: use 403

✓ Tips & Best Practices

  • Name aliases after what they give: CurrentUser, AdminUser, DbSession
  • Use dataclasses for parameter-group dependencies
  • Put role checks on routers with dependencies=[...] (sheet 24)
