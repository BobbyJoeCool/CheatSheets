Pydantic BaseModel

class Item(BaseModel) · type coercion · defaults · model_dump() · model_validate() · model_dump_json()

Description

A Pydantic model is a class that declares fields with type hints. Creating one validates and coerces the input ("3" becomes 3 for an int field) or raises ValidationError. FastAPI uses models for request bodies, responses and settings. Pydantic v2 is the current major version, with a Rust core and model_* method names.

Notes

  • Fields without defaults are required
  • Strict mode turns off coercion: ConfigDict(strict=True)
  • Models are mutable unless frozen=True
  • v1 names (.dict(), .parse_obj()) are deprecated

Under the Hood

  • pydantic-core (Rust) builds a validator from your class at import time
  • Validation runs in Rust, then fills the Python object
  • model_fields holds the schema; FastAPI turns it into JSON Schema

Create, Validate, Dump

from datetime import datetime
from pydantic import BaseModel, ValidationError

class Todo(BaseModel):
    id: int
    title: str
    done: bool = False
    created: datetime | None = None

t = Todo(id="7", title="Buy milk")  # "7" → 7
t.model_dump()     # {'id': 7, 'title': 'Buy milk', ...}
t.model_dump(exclude_none=True)    # drops created
t.model_dump_json()                # '{"id":7,...}'

Todo.model_validate({"id": 1, "title": "x"})
Todo.model_validate_json('{"id":1,"title":"x"}')
t2 = t.model_copy(update={"done": True})

try:
    Todo(id="abc")
except ValidationError as e:
    e.error_count()          # 2: bad id, missing title

Code Explained

Class fields + hints — the schema
Constructor validates and coerces
model_dump() — to dict; model_dump_json() — to JSON string
model_validate() — from dict or object
model_copy(update=) — changed copy

Other Framework

  • Flask — no built-in models; pair with Pydantic or Marshmallow
  • Django — forms.Form or DRF Serializer fill this role

Prefer / Avoid

  • Avoid v1 .dict() / .json() · Prefer model_dump() / model_dump_json()
  • Avoid raw dicts passed between layers · Prefer models with real types

⚠ Common Mistakes

  • Using v1 tutorials: orm_mode, .dict() and @validator changed in v2
  • Assuming assignment re-validates: it does not unless validate_assignment=True
  • Mutable defaults like tags: list = [] are fine in Pydantic, but not in dataclasses

✓ Tips & Best Practices

  • Use model_dump(mode="json") to get JSON-safe types (dates as strings)
  • Turn on strict=True for money or ID fields
  • Inspect Model.model_json_schema() to see what the docs will show

Quick Summary

  • BaseModel — typed, validated data class
  • constructor — validate + coerce
  • model_dump() / model_validate() — in and out
  • Pydantic v2 — model_* method names
