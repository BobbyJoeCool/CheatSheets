Sheet 36

async def vs def

event loop · threadpool for def · blocking in async def · await I/O · run_in_threadpool · httpx.AsyncClient

Description

FastAPI runs async def routes on the event loop and plain def routes in a threadpool. Both are fast when used right. The one real mistake is calling blocking code (requests, time.sleep, sync DB drivers) inside async def: that freezes every other request on that worker.

Notes

  • Rule: async def only if everything inside is awaitable
  • Not sure? Use def; it's safe
  • Same rules apply to dependencies
  • CPU-heavy work belongs in a process pool or task queue

Under the Hood

  • The threadpool comes from AnyIO, default 40 threads
  • def routes are run with run_in_threadpool
  • One blocking call in async def stalls the whole event loop

Right and Wrong

import time, asyncio, httpx, requests
from fastapi.concurrency import run_in_threadpool

@app.get("/bad")
async def bad():
    time.sleep(2)                          # blocks the event loop!
    return requests.get(URL).json()        # also blocking

@app.get("/good-sync")
def good_sync():
    time.sleep(2)                          # fine: runs in a thread
    return requests.get(URL).json()

@app.get("/good-async")
async def good_async(request: Request):
    await asyncio.sleep(2)                 # yields to other requests
    client: httpx.AsyncClient = request.state.client
    r1, r2 = await asyncio.gather(client.get(URL_A), client.get(URL_B))
    return {"a": r1.json(), "b": r2.json()}

@app.get("/mixed")
async def mixed():
    data = await run_in_threadpool(legacy_sync_call, 42)
    return data

Code Explained

/bad — time.sleep and requests freeze the worker
/good-sync — plain def runs in the threadpool
asyncio.gather — run two calls at once
run_in_threadpool — call sync code from async

Other Framework

  • Flask — WSGI: one request per thread; async def views run in a loop per request
  • Django — async views + sync_to_async() for sync code

Prefer / Avoid

  • Avoid requests in async def · Prefer httpx.AsyncClient
  • Avoid async def by default · Prefer it only when you await something

⚠ Common Mistakes

  • Declaring everything async def out of habit while using sync libraries
  • Running CPU-heavy model inference in async def: blocks all requests
  • Creating a new httpx.AsyncClient per request

✓ Tips & Best Practices

  • Load-test with hey or locust before deciding async helps
  • Use asyncio.timeout() around slow calls
  • Raise the threadpool size only after measuring

Quick Summary

  • async def — event loop; never block
  • def — threadpool; safe default
  • gather — parallel awaits
  • run_in_threadpool — sync from async
