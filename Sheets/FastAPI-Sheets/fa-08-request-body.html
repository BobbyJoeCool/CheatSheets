Sheet 08

Request Body

Pydantic model param · JSON body · body + path + query · Body(embed=True) · multiple bodies

Description

Declare a parameter typed as a Pydantic model and FastAPI reads the JSON request body, validates it, and hands you a model instance. Path, query and body parameters can be mixed freely: FastAPI decides where each comes from by its name and type. Several model params become keys in one JSON object.

Notes

  • Model type → body; path name → path; simple type → query
  • Wrong JSON or missing fields → 422 with field locations
  • GET with a body is allowed but poorly supported by clients
  • Body() marks a simple value as part of the body

Under the Hood

  • Body bytes are read once and parsed with Pydantic's Rust JSON parser
  • Starlette's Request caches the body for later reads
  • Validation errors are collected, not raised one by one

Model in, Model out

from typing import Annotated
from pydantic import BaseModel
from fastapi import FastAPI, Body

class TodoIn(BaseModel):
    title: str
    notes: str | None = None
    priority: int = 3

app = FastAPI()

@app.post("/lists/{list_id}/todos")
def add_todo(list_id: int, todo: TodoIn, notify: bool = False):
    return {"list": list_id, **todo.model_dump(), "notify": notify}

@app.put("/todos/{todo_id}")
def update(todo_id: int, todo: TodoIn, user: User,
           importance: Annotated[int, Body()]): ...
# body: {"todo": {...}, "user": {...}, "importance": 5}

@app.post("/todos/embedded")
def embedded(todo: Annotated[TodoIn, Body(embed=True)]): ...
# body: {"todo": {"title": "Buy milk"}}

Code Explained

todo: TodoIn — parsed from JSON body
list_id from the path, notify from the query string
todo.model_dump() — model → dict
Two models → each keyed by its param name
Body(embed=True) — wrap a single model under its name

Other Framework

  • Flask — data = request.get_json(), validate yourself
  • Django — json.loads(request.body) or DRF serializers

Prefer / Avoid

  • Avoid request: Request + await request.json() · Prefer a typed model param
  • Avoid dict as the body type · Prefer a model so it is validated and documented

⚠ Common Mistakes

  • Sending form data to a JSON model endpoint: 422; forms need Form() (sheet 10)
  • Adding a second model and breaking clients that sent the flat shape
  • Reading await request.json() after FastAPI already parsed it, then mutating the wrong copy

✓ Tips & Best Practices

  • Use separate In and Out models (sheet 15)
  • Send Content-Type: application/json from clients
  • Use list[Model] for bulk create endpoints

Quick Summary

  • model param — JSON body
  • mix path, query and body in one signature
  • two models — keyed JSON object
  • Body(embed=True) — force the wrapper key
