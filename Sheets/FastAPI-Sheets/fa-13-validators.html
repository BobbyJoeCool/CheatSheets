Sheet 13

Custom Validators

@field_validator · @model_validator · mode=before/after · AfterValidator · @computed_field

Description

When Field() rules aren't enough, write validators. A @field_validator checks or transforms one field; a @model_validator sees the whole model, which is how you compare two fields. Raise ValueError with a clear message and FastAPI turns it into a 422 entry. @computed_field adds read-only values to the output.

Notes

  • Validators are @classmethods in v2
  • mode="before" sees raw input; "after" sees typed values
  • Return the (possibly changed) value from a field validator
  • Return self from an after model validator

Field, Model & Computed

from datetime import date
from typing import Annotated
from pydantic import (BaseModel, AfterValidator, computed_field,
                      field_validator, model_validator)

def no_spaces(v: str) -> str:
    if " " in v: raise ValueError("no spaces allowed")
    return v

class Trip(BaseModel):
    code: Annotated[str, AfterValidator(no_spaces)]
    city: str
    start: date; end: date

    @field_validator("city")
    @classmethod
    def tidy_city(cls, v: str) -> str:
        return v.strip().title()      # " ames" → "Ames"

    @model_validator(mode="after")
    def check_dates(self):
        if self.end < self.start: raise ValueError("end < start")
        return self

    @computed_field
    @property
    def nights(self) -> int:
        return (self.end - self.start).days

Code Explained

AfterValidator(fn) — reusable validator inside Annotated
@field_validator("city") — runs for that field
@model_validator(mode="after") — cross-field checks
ValueError → 422 item with your message
@computed_field — included in model_dump() and docs

Other Framework

  • Flask — WTForms validate_<field>() methods (sheet 50)
  • Django — clean_<field>() and clean() on forms

Prefer / Avoid

  • Avoid v1 @validator / @root_validator · Prefer @field_validator / @model_validator
  • Avoid raising HTTPException in validators · Prefer ValueError

⚠ Common Mistakes

  • Forgetting return v: the field becomes None
  • Missing @classmethod under @field_validator
  • Doing DB lookups in validators: slow, and validators can't use dependencies

✓ Tips & Best Practices

  • Check uniqueness (email taken) in the route or a dependency, not the model
  • Use mode="before" to accept "a,b,c" and split into a list
  • Keep messages user-facing; they go straight to API clients

Quick Summary

  • @field_validator — one field
  • @model_validator — whole model, cross-field
  • AfterValidator — reusable via Annotated
  • @computed_field — derived output value
