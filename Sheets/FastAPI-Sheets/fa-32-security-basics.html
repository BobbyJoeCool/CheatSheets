Security Basics & OAuth2 Password Flow

fastapi.security · OAuth2PasswordBearer(tokenUrl=) · OAuth2PasswordRequestForm · /token · Authorize

Description

fastapi.security provides dependency classes that read credentials and document them in OpenAPI. OAuth2PasswordBearer reads Authorization: Bearer <token> and returns the token string. OAuth2PasswordRequestForm parses the username/password form a login endpoint receives. Together they light up the Authorize button in /docs.

Notes

  • These classes only extract credentials; you verify them
  • Missing header → automatic 401 with WWW-Authenticate
  • tokenUrl is relative and used by /docs to log in
  • The login form is form-encoded, not JSON

Login + Protected Route

from typing import Annotated
from fastapi import Depends, HTTPException, status
from fastapi.security import (OAuth2PasswordBearer,
                              OAuth2PasswordRequestForm)

oauth2 = OAuth2PasswordBearer(tokenUrl="auth/token")

@app.post("/auth/token")
def login(form: Annotated[OAuth2PasswordRequestForm, Depends()]):
    user = authenticate(form.username, form.password)
    if not user:
        raise HTTPException(status.HTTP_401_UNAUTHORIZED,
                            "Incorrect username or password",
                            headers={"WWW-Authenticate": "Bearer"})
    return {"access_token": create_token(user.id),
            "token_type": "bearer"}

def get_current_user(token: Annotated[str, Depends(oauth2)]) -> User:
    return user_from_token(token)          # sheet 33

@app.get("/me")
def me(user: Annotated[User, Depends(get_current_user)]) -> UserOut:
    return user

Code Explained

OAuth2PasswordBearer(tokenUrl=) — reads the Bearer token
OAuth2PasswordRequestForm — username, password, scope
Response must include access_token and token_type
get_current_user — turns a token into a user
/me — any route can require a user

Other Framework

  • Flask — Flask-Login sessions (sheet 55) or Flask-JWT-Extended
  • Django — built-in auth + sessions; DRF token/JWT classes

Prefer / Avoid

  • Avoid reading the header manually · Prefer OAuth2PasswordBearer
  • Avoid saying which part was wrong · Prefer "Incorrect username or password"

⚠ Common Mistakes

  • Expecting JSON on /token: the OAuth2 spec uses form fields
  • Forgetting python-multipart, so the form can't be parsed
  • Returning 403 for a missing token; it should be 401

✓ Tips & Best Practices

  • Use a real identity provider (Auth0, Cognito, Keycloak) for big apps
  • Rate-limit the login endpoint
  • Use the Authorize button in /docs to test protected routes

Quick Summary

  • OAuth2PasswordBearer — extract Bearer token
  • OAuth2PasswordRequestForm — login form
  • /token returns access_token + token_type
  • get_current_user — token → user dependency
