Sheet 50

Forms & Flask-WTF

FlaskForm · StringField · validators · validate_on_submit() · CSRF token · flash() · get_flashed_messages()

Description

Flask-WTF integrates WTForms with Flask: define a form class with fields and validators, render it in a template, and call validate_on_submit() in the view. It adds CSRF protection automatically. Use flash() to queue one-time messages shown on the next page.

Notes

  • pip install flask-wtf (needs SECRET_KEY)
  • validate_on_submit() = POST and all validators pass
  • form.hidden_tag() renders the CSRF token
  • Email validation needs email-validator

Form + View

from flask import flash, redirect, render_template, url_for
from flask_wtf import FlaskForm
from wtforms import StringField, IntegerField, SubmitField
from wtforms.validators import (DataRequired, Length,
                                NumberRange, ValidationError)

class TodoForm(FlaskForm):
    title = StringField("Title",
                        validators=[DataRequired(), Length(max=100)])
    priority = IntegerField("Priority", default=3,
                            validators=[NumberRange(1, 5)])
    submit = SubmitField("Add")

    def validate_title(self, field):         # custom rule
        if repo.exists(field.data):
            raise ValidationError("Already on the list")

@app.route("/todos/new", methods=["GET", "POST"])
def new_todo():
    form = TodoForm()
    if form.validate_on_submit():
        repo.add(form.title.data, form.priority.data)
        flash("Todo added", "success")
        return redirect(url_for("todo_list"))
    return render_template("new.html", form=form)

Code Explained

FlaskForm — WTForms + CSRF
validators=[...] — rules per field
validate_<field>() — custom check
validate_on_submit() — POST + valid
flash() + redirect — message on the next page

Other Framework

  • FastAPI — Form() params + Pydantic validation (sheet 10)
  • Django — forms.Form / ModelForm with {% csrf_token %}

Prefer / Avoid

  • Avoid rendering the page directly after a successful POST · Prefer redirect
  • Avoid disabling CSRF globally · Prefer @csrf.exempt on specific API views

⚠ Common Mistakes

  • Missing SECRET_KEY: CSRF fails with a cryptic error
  • Forgetting {{ form.hidden_tag() }} in the template: every POST fails validation
  • Reading request.form instead of form.field.data and skipping validation

✓ Tips & Best Practices

  • Render errors with {% for e in form.title.errors %}
  • Show flashes in base.html with get_flashed_messages()
  • Use CSRFProtect(app) to protect non-WTForms POSTs too
