Sheet 26

Lifespan Events

@asynccontextmanager · lifespan= · startup/shutdown · app.state · on_event (deprecated)

Description

The lifespan function runs once when the app starts and once when it stops. Code before yield is startup (open DB pools, load ML models, create HTTP clients); code after is shutdown (close them). Store shared objects on app.state or yield a dict that becomes request.state.

Notes

  • Replaces @app.on_event("startup") / ("shutdown")
  • Runs per worker process, not once per server
  • Startup failure stops the server from starting
  • TestClient runs lifespan only inside with TestClient(app)

Under the Hood

  • ASGI servers send lifespan.startup / lifespan.shutdown messages
  • Starlette runs your context manager on those messages
  • A yielded dict becomes the initial request.state for every request

Shared Resources

from contextlib import asynccontextmanager
import httpx
from fastapi import FastAPI, Request

@asynccontextmanager
async def lifespan(app: FastAPI):
    # startup
    engine = create_async_engine(settings.database_url)
    client = httpx.AsyncClient(timeout=10)
    model = load_model("sentiment.bin")
    yield {"client": client, "model": model}
    # shutdown
    await client.aclose()
    await engine.dispose()

app = FastAPI(lifespan=lifespan)

@app.get("/score")
async def score(text: str, request: Request):
    model = request.state.model
    return {"score": model.predict(text)}

Code Explained

@asynccontextmanager — turns the generator into a lifespan
before yield — startup work
yield {...} — state shared with requests
after yield — shutdown cleanup

Other Framework

  • Flask — create resources in create_app(); no shutdown hook
  • Django — AppConfig.ready() for startup code

Prefer / Avoid

  • Avoid @app.on_event · Prefer lifespan=
  • Avoid creating httpx.AsyncClient() per request · Prefer one in lifespan

⚠ Common Mistakes

  • Using a plain TestClient(app) without with: startup never runs
  • Heavy startup in every worker multiplies memory use
  • Mixing lifespan= with on_event handlers: the event handlers are ignored

✓ Tips & Best Practices

  • Wrap state access in a dependency so tests can override it
  • Fail fast: check DB connectivity during startup
  • Log startup and shutdown so deploys are easy to debug

Quick Summary

  • lifespan — startup before yield, shutdown after
  • yield {...} — becomes request.state
  • per worker — runs in each process
  • replaces on_event
