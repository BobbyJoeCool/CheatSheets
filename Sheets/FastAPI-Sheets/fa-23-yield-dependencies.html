Dependencies with yield

yield setup/teardown · DB session per request · try / finally · exceptions after yield · cleanup order

Description

A dependency that yields gives the route a value, then resumes after the response is ready to run cleanup. That's the standard way to open a DB session per request and always close it. Exceptions raised in the route are re-raised at the yield, so you can roll back with try/except and clean up in finally.

Notes

  • Code before yield = setup; after = teardown
  • Only one yield per dependency
  • Cleanup runs in reverse order of setup
  • Re-raise caught exceptions after yield, or they are swallowed

Under the Hood

  • FastAPI wraps yield dependencies in an AsyncExitStack per request
  • Exit code runs as the stack unwinds
  • Teardown now runs before the response is sent, so cleanup can still affect it

Session per Request

from typing import Annotated
from fastapi import Depends
from sqlalchemy.orm import Session

def get_db():
    db = SessionLocal()
    try:
        yield db                      # route runs here
        db.commit()
    except Exception:
        db.rollback()
        raise                         # keep the error
    finally:
        db.close()

DbSession = Annotated[Session, Depends(get_db)]

@app.post("/todos", status_code=201)
def create(todo: TodoIn, db: DbSession) -> TodoOut:
    row = Todo(**todo.model_dump())
    db.add(row)
    db.flush()                        # get row.id
    return row

Code Explained

yield db — hands the session to the route
after yield — commit if the route succeeded
except + raise — roll back, keep the error
finally — always close

Other Framework

  • Flask — teardown_appcontext closes the session (sheet 53)
  • Django — connections managed per request by the framework

Prefer / Avoid

  • Avoid opening sessions inside each route · Prefer one yield dependency
  • Avoid except: pass after yield · Prefer re-raising

⚠ Common Mistakes

  • Swallowing the exception after yield: client gets 200 and data isn't saved
  • Using yield deps for app-wide resources: they run every request
  • Committing in both the route and the dependency without knowing it

✓ Tips & Best Practices

  • Pick one place to commit (route or dependency) and stick to it
  • Use with / async with inside the dependency for automatic close
  • Use lifespan for engines and pools; yield deps for sessions

Quick Summary

  • yield — setup, give value, teardown
  • try/except/finally — rollback and close
  • re-raise — never hide route errors
  • session per request — the classic use
