Sheet 55

Sessions & Flask-Login

session[...] · signed cookies · LoginManager · UserMixin · @login_required · login_user / logout_user · current_user

Description

Flask's session stores small data in a signed cookie: users can read it but can't change it without the SECRET_KEY. Flask-Login builds user logins on top: it remembers the user ID in the session, loads the user each request into current_user, and protects views with @login_required.

Notes

  • Session cookie is signed, not encrypted: no secrets inside
  • Flask-Login doesn't hash passwords or render forms
  • user_loader turns the stored ID back into a user
  • remember=True sets a long-lived remember cookie

Login Flow

from flask_login import (LoginManager, UserMixin, current_user,
                         login_required, login_user)
from werkzeug.security import check_password_hash as check_pw

login_manager = LoginManager()
login_manager.login_view = "auth.login"     # redirect target
class User(UserMixin, db.Model): ...         # is_authenticated, get_id

@login_manager.user_loader
def load_user(user_id: str):
    return db.session.get(User, int(user_id))

@bp.post("/login")
def login():
    f = request.form
    user = db.session.scalar(db.select(User).filter_by(email=f["email"]))
    if user and check_pw(user.password_hash, f["password"]):
        login_user(user, remember=True)
        return redirect(url_for("todos.index"))
    flash("Invalid credentials")
    return redirect(url_for("auth.login"))

@bp.get("/dashboard")
@login_required
def dashboard():
    session["visits"] = session.get("visits", 0) + 1
    return f"Hi {current_user.email} (#{session['visits']})"

Code Explained

login_view — where anonymous users get sent
UserMixin — default user properties
user_loader — ID from session → user
login_user() / logout_user() — start/end
session[...] — small signed per-user data

Other Framework

  • FastAPI — OAuth2 + JWT dependencies (sheets 32–33)
  • Django — built-in login(), @login_required, request.user

Prefer / Avoid

  • Avoid redirecting to next blindly · Prefer checking it is a local URL
  • Avoid storing user objects in session · Prefer the user ID only

⚠ Common Mistakes

  • Open redirect via ?next=https://evil.com
  • Rotating SECRET_KEY and wondering why everyone is logged out
  • Putting large data in session: browsers cap cookies near 4 KB

✓ Tips & Best Practices

  • Hash with generate_password_hash() (scrypt by default)
  • Use Flask-Session for server-side sessions (Redis) if you need more space
  • Add @login_required at blueprint level with before_request

Quick Summary

  • session — signed cookie storage
  • LoginManager + user_loader — load users
  • @login_required — protect views
  • current_user — the logged-in user
