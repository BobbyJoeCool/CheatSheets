Sheet 48

Request & Response

request.args · request.form · request.get_json() · request.files · jsonify · make_response · (body, status, headers)

Description

Flask's request object holds everything the client sent: query string, form data, JSON, files, headers and cookies. A view can return a string, a dict or list (JSON), a Response, or a tuple of body, status and headers. Use make_response() when you need to set cookies or tweak headers before returning.

Notes

  • request is a context-local; import it, don't pass it
  • args / form are MultiDicts: .get(), .getlist()
  • get_json() returns None or 415 for non-JSON
  • jsonify is optional now; dicts become JSON

Reading & Responding

from flask import request, jsonify, make_response

@app.post("/todos")
def create_todo():
    data = request.get_json(silent=True) or {}
    title = data.get("title", "").strip()
    if not title:
        return {"error": "title is required"}, 400
    todo = repo.add(title)
    return todo, 201, {"Location": f"/todos/{todo['id']}"}

@app.get("/search")
def search():
    q = request.args.get("q", "")
    page = request.args.get("page", 1, type=int)
    tags = request.args.getlist("tag")       # ?tag=a&tag=b
    agent = request.headers.get("User-Agent")
    return jsonify(results=find(q, page, tags))

@app.post("/prefs")
def prefs():
    resp = make_response({"ok": True})
    resp.set_cookie("theme", request.form["theme"], httponly=True)
    return resp

Code Explained

get_json(silent=True) — None instead of an error
return (body, status, headers) tuple
args.get(..., type=int) — convert, default on failure
getlist("tag") — repeated params
make_response() — then set cookies/headers

Other Framework

  • FastAPI — typed params + Pydantic replace manual parsing (sheets 07–08)
  • Django — request.GET, request.POST, json.loads(request.body)

Prefer / Avoid

  • Avoid request.form["x"] when it may be missing (400) · Prefer .get()
  • Avoid hand-validating big payloads · Prefer Pydantic or Marshmallow

⚠ Common Mistakes

  • request.form["x"] on a missing key returns a 400 page, confusing API clients
  • Calling get_json() without Content-Type: application/json
  • Reading request.data for form posts: it's empty after parsing

✓ Tips & Best Practices

  • Validate JSON with Pydantic: Todo.model_validate(request.get_json())
  • Set MAX_CONTENT_LENGTH to cap upload size
  • Use request.get_json(force=True) only for clients you control

Quick Summary

  • request.args / form / get_json() — inputs
  • dict return — JSON
  • tuple — body, status, headers
  • make_response() — cookies and headers
