Sheet 19

HTTPException & Exception Handlers

raise HTTPException(404) · detail= · headers= · @app.exception_handler · custom exceptions

Description

Raise HTTPException to stop a request and send an error response: FastAPI returns {"detail": ...} with your status code. For domain errors, define your own exception classes and register an exception handler that turns them into responses. That keeps business code free of HTTP details.

Notes

  • raise, don't return, an HTTPException
  • detail can be any JSON-able value (str, dict, list)
  • Uncaught exceptions → 500 and a server log entry
  • Use fastapi.HTTPException (allows headers=)

Errors Two Ways

from fastapi import HTTPException, Request, status
from fastapi.responses import JSONResponse

@app.get("/todos/{todo_id}")
def get_todo(todo_id: int) -> TodoOut:
    todo = repo.get(todo_id)
    if todo is None:
        raise HTTPException(status.HTTP_404_NOT_FOUND,
                            detail=f"Todo {todo_id} not found")
    return todo

class QuotaExceeded(Exception):          # domain error
    def __init__(self, limit: int):
        self.limit = limit

@app.exception_handler(QuotaExceeded)
async def quota_handler(request: Request, exc: QuotaExceeded):
    return JSONResponse(status_code=429,
        content={"detail": f"Limit of {exc.limit} reached"},
        headers={"Retry-After": "3600"})

# anywhere in services: raise QuotaExceeded(limit=100)

Code Explained

raise HTTPException(404, detail=) — immediate error response
Response body: {"detail": "Todo 7 not found"}
QuotaExceeded — plain Python exception, no HTTP coupling
@app.exception_handler(Cls) — maps it to a response
Handlers get the Request and the exception

Other Framework

  • Flask — abort(404) and @app.errorhandler(404) (sheet 53)
  • Django — raise Http404 or get_object_or_404()

Prefer / Avoid

  • Avoid return {"error": ...} with 200 · Prefer raising with the right status
  • Avoid HTTPException deep in services · Prefer domain exceptions + handlers

⚠ Common Mistakes

  • return HTTPException(...): returns 200 with a weird body
  • Catching Exception in every route and hiding real bugs
  • Leaking stack traces or SQL in detail

✓ Tips & Best Practices

  • Register a handler for starlette.exceptions.HTTPException to restyle all errors
  • Use headers={"WWW-Authenticate": "Bearer"} on 401s
  • Keep error bodies one consistent shape (sheet 20)

Quick Summary

  • raise HTTPException(code, detail) — error response
  • domain exception + handler — clean separation
  • @app.exception_handler — custom mapping
  • uncaught — 500, logged
