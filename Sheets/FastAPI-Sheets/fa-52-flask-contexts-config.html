Sheet 52

Contexts, g & Configuration

app context · request context · current_app · g · config.from_object / from_prefixed_env · SECRET_KEY · .flaskenv

Description

Flask makes request, session, current_app and g act like globals by pushing contexts: an app context (which app is active) and a request context (which request). g is scratch space for one request, like the current user or a DB connection. Configuration lives in app.config, loaded from objects, files or environment variables.

Notes

  • Contexts are pushed automatically during requests and CLI commands
  • Outside them, use with app.app_context():
  • g is reset for every request
  • FLASK_ env vars load via from_prefixed_env()

Under the Hood

  • Contexts are stored in Python contextvars, safe across threads and async
  • request, g, current_app are LocalProxy objects that look up the active context
  • Teardown functions run when the app context is popped

Contexts & Config

from flask import Flask, current_app, g, request

class Default:
    SECRET_KEY = "dev"                     # override in prod!
    ITEMS_PER_PAGE = 20

app = Flask(__name__)
app.config.from_object(Default)
app.config.from_prefixed_env()        # FLASK_SECRET_KEY → SECRET_KEY

@app.before_request
def load_user():
    g.user = users.from_session()          # per-request scratch space

@app.get("/todos")
def todos():
    per_page = current_app.config["ITEMS_PER_PAGE"]
    return repo.for_user(g.user, per_page)

with app.app_context():                    # scripts / shell
    db.create_all()

Code Explained

from_object(Default) — load UPPERCASE attributes
from_prefixed_env() — read FLASK_* env vars
g.user — data for this request only
current_app — the active app (use in blueprints)
app.app_context() — run code outside requests

Other Framework

  • FastAPI — dependencies replace g; settings via pydantic-settings (sheet 16)
  • Django — request.user from middleware; django.conf.settings

Prefer / Avoid

  • Avoid importing app in blueprints for config · Prefer current_app.config
  • Avoid storing request data in module globals · Prefer g

⚠ Common Mistakes

  • "Working outside of application context" in scripts: wrap in app.app_context()
  • Shipping SECRET_KEY = "dev" to production
  • Lowercase config keys: only UPPERCASE names are loaded

✓ Tips & Best Practices

  • Use .flaskenv for FLASK_APP/FLASK_DEBUG and .env for secrets
  • Generate keys with python -c "import secrets; print(secrets.token_hex())"
  • Use flask shell; it pushes an app context for you

Quick Summary

  • app + request contexts — make globals safe
  • g — per-request storage
  • current_app — active app in blueprints
  • app.config — objects, files, env vars
