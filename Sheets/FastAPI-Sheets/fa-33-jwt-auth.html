JWT Authentication

PyJWT · jwt.encode / decode · exp claim · get_current_user · 401 + WWW-Authenticate · refresh tokens

Description

A JWT is a signed token carrying claims like the user ID (sub) and expiry (exp). The server signs it at login and verifies the signature on each request, so no session lookup is needed. Use PyJWT to encode and decode, keep access tokens short-lived, and use refresh tokens to get new ones.

Notes

  • pip install pyjwt
  • JWT payloads are signed, not encrypted: no secrets inside
  • decode checks exp automatically
  • HS256 = shared secret; RS256 = public/private key pair

Create & Verify Tokens

from datetime import datetime, timedelta, timezone
import jwt
from jwt.exceptions import InvalidTokenError

SECRET = settings.secret_key            # 32+ random bytes
ALGO = "HS256"

def create_token(user_id: int, minutes: int = 15) -> str:
    now = datetime.now(timezone.utc)
    claims = {"sub": str(user_id), "iat": now,
              "exp": now + timedelta(minutes=minutes)}
    return jwt.encode(claims, SECRET, algorithm=ALGO)

def get_current_user(token: Annotated[str, Depends(oauth2)],
                     db: DbSession) -> User:
    unauthorized = HTTPException(401, "Could not validate credentials",
                                 headers={"WWW-Authenticate": "Bearer"})
    try:
        payload = jwt.decode(token, SECRET, algorithms=[ALGO])
    except InvalidTokenError:            # bad signature, expired...
        raise unauthorized
    user = db.get(User, int(payload["sub"]))
    if user is None or not user.is_active:
        raise unauthorized
    return user

Code Explained

sub — subject (user ID), must be a string
exp — expiry; PyJWT rejects expired tokens
algorithms=[ALGO] — always pin allowed algorithms
InvalidTokenError — base for all token errors
Same 401 for every failure

Prefer / Avoid

  • Avoid long-lived access tokens · Prefer ~15 min + refresh tokens
  • Avoid algorithms omitted or "none" · Prefer an explicit list

⚠ Common Mistakes

  • Putting emails or roles you rely on for security in an unverifiable place
  • Hard-coding the secret in source control
  • Integer sub: spec says string; PyJWT may reject it

✓ Tips & Best Practices

  • Generate secrets with openssl rand -hex 32
  • Add aud and iss checks if several services share keys
  • Use RS256 when other services must verify but not issue tokens

Quick Summary

  • JWT — signed claims, not encrypted
  • jwt.encode/decode — PyJWT
  • exp — short-lived access tokens
  • one 401 for all auth failures
