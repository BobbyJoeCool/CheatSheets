REST APIs & Async in Flask

JSON APIs · MethodView · flask-smorest / APIFlask · async def views · flask-cors · async limits on WSGI

Description

Flask builds JSON APIs well: return dicts, use MethodView for one class per resource, and add APIFlask or flask-smorest if you want validation and OpenAPI docs like FastAPI. Flask also accepts async def views, but on WSGI each async request still occupies a worker, so it helps only for concurrent calls inside one request.

Notes

  • pip install "flask[async]" enables async views
  • Each async view runs its own event loop in a thread
  • Use Quart if you want a fully async Flask-like framework
  • flask-cors adds CORS headers

Code Explained

MethodView — methods map to HTTP verbs
as_view("todo") — endpoint name
return "", 204 — empty success
CORS(app, origins=) — allow a frontend origin
async view — two calls at once, inside one request

Other Framework

  • FastAPI — validation, docs and real async built in
  • Django — DRF APIView / ViewSet + routers

Prefer / Avoid

  • Avoid hand-rolled validation for big APIs · Prefer APIFlask, flask-smorest or Pydantic
  • Avoid async views expecting more throughput · Prefer an ASGI framework for that

⚠ Common Mistakes

  • Expecting async views to handle more requests per worker on WSGI
  • CORS(app) with defaults in production: allows every origin
  • Forgetting flask[async] and getting a RuntimeError

✓ Tips & Best Practices

  • Use jsonify only for lists in very old Flask; modern Flask accepts lists
  • Version API blueprints: url_prefix="/api/v1"
  • Consider FastAPI for new API-only services

Quick Summary

  • MethodView — class per resource
  • APIFlask / smorest — validation + OpenAPI
  • async def views — concurrency within a request
  • flask-cors — cross-origin access
