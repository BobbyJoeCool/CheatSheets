Sheet 31

Alembic Migrations & CRUD Patterns

alembic init · revision --autogenerate · upgrade head · downgrade -1 · CRUD helpers · exclude_unset

Description

Alembic tracks schema changes as versioned migration scripts, so every environment's database can be brought to the same state. Point env.py at your models' metadata and --autogenerate drafts migrations from model changes. Keep data access in small CRUD functions so routes stay thin.

Notes

  • Always read autogenerated migrations before running them
  • Autogenerate misses some changes (renames, some constraints)
  • Run alembic upgrade head in deploys, not create_all()
  • Commit the alembic/versions/ folder

Alembic Workflow

alembic init alembic                     # creates alembic/ + alembic.ini
# alembic/env.py:  target_metadata = Base.metadata
alembic revision --autogenerate -m "add todos.due"
alembic upgrade head                     # apply all
alembic downgrade -1                     # undo one
alembic current                          # where am I?

crud.py — Thin Data Layer

def get_todo(db: Session, todo_id: int) -> Todo | None:
    return db.get(Todo, todo_id)

def update_todo(db: Session, todo: Todo, data: TodoUpdate) -> Todo:
    for key, value in data.model_dump(exclude_unset=True).items():
        setattr(todo, key, value)          # only fields sent
    db.add(todo)
    db.commit()
    db.refresh(todo)
    return todo

Code Explained

alembic init — scaffolding + config
target_metadata — lets autogenerate compare models
--autogenerate -m — draft a migration
exclude_unset=True — PATCH only changes sent fields
refresh() — reload DB defaults

Other Framework

  • Flask — Flask-Migrate wraps Alembic: flask db migrate (sheet 54)
  • Django — makemigrations / migrate built in

Prefer / Avoid

  • Avoid editing a migration after it ran elsewhere · Prefer a new migration
  • Avoid SQL in route bodies · Prefer crud.py or repository functions

⚠ Common Mistakes

  • Not setting target_metadata: autogenerate produces empty migrations
  • Adding a NOT NULL column without a default to a table with rows
  • Two branches creating migrations from the same head: merge with alembic merge

✓ Tips & Best Practices

  • Use alembic init -t async alembic for async engines
  • Read the DB URL from settings inside env.py
  • Test downgrade once so rollbacks are possible

Quick Summary

  • revision --autogenerate — draft migration
  • upgrade head — apply all
  • CRUD functions — thin routes
  • exclude_unset — true PATCH
