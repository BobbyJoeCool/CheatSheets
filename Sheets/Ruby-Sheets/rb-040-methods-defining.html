Defining and Calling Methods

Methods are defined with def and return the value of the last expression; return is only needed to leave early. Parentheses are optional at both the definition and the call site. Naming conventions add meaning: ? for predicates, ! for dangerous variants, and name= for setters.

Method Notes

  • Every method returns something (nil if the body is empty)
  • def x = expr defines an endless one-line method (3.0+)
  • Top-level def methods become private methods of Object

def, Return Values, Naming

def greet(name)
  "Hello, #{name}"          # implicit return
end
greet "Ada"                 # "Hello, Ada" (parens optional)

def sign(n)
  return :zero if n.zero?   # early return
  n.positive? ? :pos : :neg
end

def square(x) = x * x       # endless method
def adult?(age) = age >= 18 # predicate
def min_max(a) = [a.min, a.max]
lo, hi = min_max([3, 9, 1]) # multiple return via array

class Account
  def balance=(v)           # setter: acct.balance = 10
    raise ArgumentError if v.negative?
    @balance = v
  end
  def reset! = @balance = 0 # bang: dangerous / mutating
end

Code Explained

implicit return — the last line's value comes back
return :zero if — early exit, then the normal path
def square(x) = x * x — endless definition
min_max — "multiple returns" are just an array
balance= — called as acct.balance = 10

The Ruby Way

  • return x on the last line → just x
  • def is_adult(age) → def adult?(age)
  • def get_name / set_name → name / name=

In Rails

  • Rails · boolean columns get ? methods for free: user.admin?
  • AS · delegate :email, to: :user defines a forwarding method

⚠ Common Mistakes

  • Putting a space before the parenthesis: greet ("a", "b") parses the parens as one argument expression and fails
  • Expecting a setter's return value; obj.x = 5 always returns 5, whatever the method returns
  • Writing return a, b and forgetting it returns an array [a, b]

✓ Tips & Best Practices

  • Keep methods short; Ruby's style guide suggests under ~10 lines
  • Use parentheses when there are arguments, except for DSL-style calls like puts and raise
  • ? methods should return true / false, not truthy values, so callers can store them safely

Quick Summary

  • def — define; last expression returns
  • def x = expr — endless method
  • ? / ! / = — naming conventions
  • arrays — multiple return values
