Modules as Namespaces

Modules also group constants: classes, other modules and values nested inside a module are referenced with :: (Billing::Invoice). Namespaces avoid name clashes between libraries. module_function and extend self turn a module into a bag of utility functions you call directly on the module.

Namespace Notes

  • module A; class B; end; end defines A::B
  • ::Name forces top-level lookup
  • Constant lookup checks lexical scope first, then ancestors

Namespaces and Utility Modules

module Billing
  TAX_RATE = 0.08
  class Invoice
    def total(amt) = amt * (1 + TAX_RATE)  # sees TAX_RATE
  end
  module Formatter
    module_function                 # callable as Formatter.money
    def money(n) = format("$%.2f", n)
  end
end

Billing::Invoice.new.total(100)     # 108.0
Billing::Formatter.money(5)         # "$5.00"

module Slug
  extend self                       # all methods on the module
  def call(s) = s.downcase.gsub(/\W+/, "-")
end
Slug.call("Hello World")            # "hello-world"

class Billing::Report               # compact style
  def rate = TAX_RATE               # NameError: no lexical Billing
end

Code Explained

Billing::Invoice — nested class in a namespace
TAX_RATE — found lexically from inside module Billing
module_function — methods callable as Formatter.money
extend self — similar, keeps methods public on the module
compact class Billing::Report — no lexical access to Billing constants

The Ruby Way

  • class Billing::Report → nested module Billing; class Report when you need its constants
  • Global helper methods → a utility module with module_function
  • Prefixing class names (BillingInvoice) → namespace them (Billing::Invoice)

In Rails

  • Rails · Zeitwerk maps paths to constants: app/models/admin/user.rb → Admin::User
  • Rails · file and constant names must match or autoloading raises NameError

⚠ Common Mistakes

  • Using compact class A::B and getting NameError for constants defined in A
  • Naming a class like a stdlib one (File, Logger) at top level; namespace it instead
  • Reopening a module by accident when two files use the same namespace and method names

✓ Tips & Best Practices

  • One top-level namespace per gem or app (MyGem::), matching the gem name
  • Module.nesting inside a body shows the lexical scope Ruby searches
  • Use module_function for stateless helpers that need no instance

Quick Summary

  • A::B — namespaced constant
  • nested module … class — lexical constant access
  • module_function / extend self — utility modules
  • ::Name — top-level lookup
