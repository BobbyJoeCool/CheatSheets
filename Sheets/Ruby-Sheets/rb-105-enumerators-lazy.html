Enumerators and Lazy Evaluation

An Enumerator is an object that produces values on demand. Calling an iterator without a block returns one, and external iteration (next, peek, rewind) lets you pull values one at a time. Enumerator.new builds custom sequences, Enumerator.produce generates from a seed, and lazy chains transformations that only run as far as needed.

Notes

  • next raises StopIteration at the end (loop rescues it)
  • Lazy chains need a terminal: first(n), to_a, force, each
  • .eager turns a lazy enumerator back into a normal one
  • Infinite sequences are fine with lazy or first(n)

Enumerators and Lazy

e = [10, 20, 30].each           # no block → Enumerator
e.next                          # 10
e.peek                          # 20 (doesn't advance)
e.next                          # 20
e.rewind; e.next                # 10

fib = Enumerator.new do |y|
  a, b = 0, 1
  loop { y << a; a, b = b, a + b }
end
fib.take(8)                     # [0, 1, 1, 2, 3, 5, 8, 13]

Enumerator.produce(1) { it * 2 }.take(5)   # [1, 2, 4, 8, 16]
Enumerator.produce([0, 1]) { |a, b| [b, a + b] }.take(4)

(1..Float::INFINITY).lazy
  .map { it * it }
  .select(&:even?)
  .first(3)                     # [4, 16, 36]
File.foreach("big.log").lazy.grep(/ERROR/).first(10)

Code Explained

each without a block — returns an Enumerator
next / peek / rewind — external iteration
Enumerator.new { |y| y << v } — custom generator
Enumerator.produce(seed) { } — next value from the previous
lazy … first(3) — computes only what's needed

The Ruby Way

  • Building a huge array to take a few → lazy … first(n)
  • Fibers for generators → Enumerator.new
  • while loops with manual state → Enumerator.produce

⚠ Common Mistakes

  • Calling to_a on an infinite enumerator; it never returns
  • Using lazy for small arrays; the overhead makes it slower than eager methods
  • Sharing one external enumerator between threads; next isn't thread-safe

✓ Tips & Best Practices

  • Return enum_for(__method__) when no block is given so your methods chain (sheet 106)
  • Enumerator::Lazy#filter_map and #compact work lazily too
  • lazy + File.foreach processes huge files with constant memory

Quick Summary
