Sorting and Searching

sort uses <=> on the elements; sort_by sorts by a computed key and is usually faster and clearer. min, max, minmax and their _by forms find extremes without sorting. On a sorted array, bsearch finds elements in O(log n). Ruby's sort is not guaranteed stable.

Notes

  • sort / sort_by return new arrays; ! versions sort in place
  • Descending: sort_by { -it } for numbers or sort.reverse
  • Multi-key: return an array from the block
  • max(2) returns the two largest

Sorting and Searching

nums = [5, 3, 9, 1]
nums.sort                          # [1, 3, 5, 9]
nums.sort.reverse                  # [9, 5, 3, 1]
nums.sort { |a, b| b <=> a }       # [9, 5, 3, 1]
nums.max                           # 9
nums.min(2)                        # [1, 3]
nums.minmax                        # [1, 9]

words = %w[pear Fig apple cherry]
words.sort_by(&:length)            # ["Fig", "pear", "apple", "cherry"]
words.sort_by(&:downcase)          # ["apple", "cherry", "Fig", "pear"]
words.max_by(&:length)             # "cherry"

people = [["Bo", 30], ["Al", 30], ["Cy", 25]]
people.sort_by { |name, age| [-age, name] }
# => [["Al", 30], ["Bo", 30], ["Cy", 25]]

sorted = [1, 3, 5, 7, 9]
sorted.bsearch { it >= 6 }         # 7
sorted.bsearch_index { it >= 6 }   # 3
words.each_with_index.sort_by { |w, i| [w.size, i] }  # stable

Code Explained

sort { |a, b| b <=> a } — custom comparator
sort_by(&:length) — sort by a key
[-age, name] — multi-key: age descending, then name
bsearch { it >= 6 } — first element meeting the condition
with index key — forces a stable order

The Ruby Way

  • sort { |a, b| a.size <=> b.size } → sort_by(&:size)
  • sort.first / sort.last → min / max
  • sort_by { }.reverse for numbers → sort_by { -it }

In Rails

  • Rails · User.order(:name) sorts in SQL; users.sort_by(&:name) loads everything into Ruby
  • Rails · maximum(:age) / minimum(:age) run as SQL aggregates

⚠ Common Mistakes

  • Sorting mixed types; <=> returns nil and sort raises ArgumentError
  • Calling bsearch on an unsorted array; it returns wrong answers without raising
  • Assuming equal elements keep their order; add the index as a tie-breaker when it matters

✓ Tips & Best Practices

  • sort_by computes each key once, so it beats sort with an expensive block
  • Use max_by(n) instead of sorting the whole array when you only need the top few
  • Comparable#clamp and between? handle range checks without sorting

Quick Summary

  • sort / sort_by — order elements
  • min / max / minmax — extremes
  • [a, b] keys — multi-key sort
  • bsearch — fast search in sorted arrays
