Singleton Classes

Every object has a hidden singleton class (eigenclass) that holds methods for that object only. def obj.method, define_singleton_method and obj.extend(Module) all add methods there. Class methods are singleton methods of the class object, which is why class << self works for defining them.

Notes

  • Method lookup checks the singleton class first, then the class
  • obj.singleton_class returns it; singleton_methods lists its methods
  • extend mixes a module into the singleton class

Per-Object Methods

dog = Object.new
def dog.speak = "woof"             # singleton method
dog.speak                          # "woof"
Object.new.respond_to?(:speak)     # false (only this object)

cat = Object.new
cat.define_singleton_method(:speak) { "meow" }
cat.singleton_methods              # [:speak]

module Loud
  def shout = "#{speak.upcase}!"
end
dog.extend(Loud)                   # module on dog's singleton class
dog.shout                          # "WOOF!"
dog.singleton_class.ancestors.first(2)  # [#<Class:#<Object…>>, Loud]

class Report
  class << self                    # Report's singleton class
    def build = new
  end
end
Report.singleton_methods           # [:build]
5.singleton_class                  # TypeError: can't define singleton

Code Explained

def dog.speak — method only on dog
define_singleton_method — same, with a block (closure)
extend(Loud) — add a module's methods to one object
class << self — opens the class's singleton class
5.singleton_class — immediates don't have one

The Ruby Way

  • Subclassing just to change one object → extend or a singleton method
  • def self.a; def self.b scattered → class << self block
  • Patching a shared object (like a constant) → wrap it instead

⚠ Common Mistakes

  • Expecting dup to keep singleton methods; only clone copies them
  • Adding singleton methods to objects that get serialized; Marshal can't dump them
  • Forgetting that class methods aren't inherited by instances; they live on the class's singleton class

✓ Tips & Best Practices

  • extend self in a module puts its methods on the module's own singleton class
  • Tests can stub one object with define_singleton_method without mocking libraries
  • singleton_class? tells you whether a class object is a singleton class

Quick Summary

  • singleton class — per-object methods
  • def obj.m / define_singleton_method — add one
  • extend — add a module to one object
  • class methods — singleton methods of the class
