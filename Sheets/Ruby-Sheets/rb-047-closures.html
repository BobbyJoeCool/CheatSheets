Closures

Blocks, procs and lambdas are closures: they capture the variables (not just the values) from where they were created and keep them alive. Changing a captured variable later is visible inside the closure, and the closure can change it too. This is how counters, memoizers and callbacks keep private state without classes.

Closure Facts

  • Captures bindings, not copies
  • Each call of a factory method creates new captured variables
  • def doesn't close over outer locals; define_method does

Capturing State

def make_counter
  count = 0
  increment = -> { count += 1 }
  current   = -> { count }
  [increment, current]
end
inc, cur = make_counter
inc.(); inc.()
cur.()                        # 2

x = 1
show = -> { x }
x = 99
show.()                       # 99 (sees the variable, not a copy)

def multiplier(n) = ->(v) { v * n }
triple = multiplier(3)
[1, 2].map(&triple)           # [3, 6]

class Greeter
  name = "Ada"
  define_method(:hello) { "Hi #{name}" }  # closes over name
end
Greeter.new.hello             # "Hi Ada"

Code Explained

count — lives on after make_counter returns
x = 99 — closures see later changes
multiplier(3) — returns a configured function
define_method { } — a method body that's a closure

The Ruby Way

  • Global counters → a closure or a small object
  • Building similar methods by copy-paste → define_method in a loop
  • Long-lived closures over big objects → capture only what's needed

⚠ Common Mistakes

  • Creating lambdas in a loop that capture one shared variable; with each each iteration gets its own, but a while loop variable is shared
  • Holding a closure that captures a huge object and wondering why memory isn't freed
  • Expecting a closure to snapshot a value; it reads the variable's current value

✓ Tips & Best Practices

  • Prefer a class once a closure needs more than two or three pieces of state
  • each creates a fresh block variable per iteration, which avoids the classic loop-closure bug
  • define_method closures can't be seen by def, which makes them handy for metaprogramming (sheet 109)

Quick Summary

  • closure — captures variables
  • factory method — fresh state per call
  • define_method — closure as a method
  • def — not a closure
