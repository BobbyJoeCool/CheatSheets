Open Classes and Refinements

Ruby classes are open: you can reopen any class, including core ones like String, and add or replace methods. This monkey patching is powerful but changes behavior globally. Refinements scope changes: refine defines the patch in a module, and it only applies in files (or modules) that call using.

Notes

  • Reopening a class adds to it; it doesn't replace it
  • Monkey patches affect every gem in the process
  • Refinements are lexically scoped (file / module after using)
  • Refinements don't apply to send or method lookups in other scopes

Monkey Patching vs Refinements

class String                    # reopen a core class (global!)
  def shout = upcase + "!"
end
"hi".shout                      # "HI!"

module Shouting
  refine String do
    def whisper = downcase + "…"
  end
end

"HI".respond_to?(:whisper)      # false (not active yet)
using Shouting                  # active for the rest of this file
"HI".whisper                    # "hi…"

class Integer                   # safer: add, don't override
  def minutes = self * 60
end
5.minutes                       # 300

String.instance_method(:shout).source_location  # [file, line]

Code Explained

class String … end — reopens it; existing methods stay
refine String do — define a scoped patch
using Shouting — activate it from here to end of file
respond_to? — false before using
source_location — find who defined a patched method

The Ruby Way

  • Patching core classes in a library → refinements or helper modules
  • Overriding existing core methods → add new, clearly named methods
  • class Foo reopening by accident → check for name clashes first

In Rails

  • AS · ActiveSupport core extensions (blank?, 5.minutes, squish) are monkey patches on core classes
  • AS · each extension can be required on its own, e.g. core_ext/string/filters

⚠ Common Mistakes

  • Overriding a core method (like String#to_s) and breaking unrelated gems
  • Expecting a refinement to be active in another file because you called using once
  • Two libraries patching the same method name; the last one loaded wins silently

✓ Tips & Best Practices

  • Prefix patch methods with your project name when you must monkey patch
  • Keep patches in one place (lib/core_ext/) so they're easy to find
  • Prefer refinements in gems; leave global patches to applications

Quick Summary

  • open classes — reopen anything
  • monkey patch — global change
  • refine + using — scoped change
  • add, don't override
