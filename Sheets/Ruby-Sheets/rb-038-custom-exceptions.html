Exception Hierarchy and Custom Errors

All exceptions inherit from Exception, but application errors should inherit from StandardError, because that's what a bare rescue catches. Define custom errors as small subclasses, ideally under one base class per library or app so callers can rescue all of them at once.

Hierarchy Notes

  • Exception also covers Interrupt, SystemExit, NoMemoryError
  • Custom errors: class MyError < StandardError; end
  • A class can carry extra data via attr_reader
  • rescue clauses match subclasses: rescue MyLib::Error gets them all

Custom Exceptions

module Shop
  class Error < StandardError; end          # library base
  class OutOfStock < Error; end
  class PaymentFailed < Error
    attr_reader :code
    def initialize(msg = "payment failed", code: nil)
      super(msg)
      @code = code
    end
  end
end

begin
  raise Shop::PaymentFailed.new(code: 402)
rescue Shop::OutOfStock
  puts "restock"
rescue Shop::Error => e                     # catches PaymentFailed
  puts "#{e.message} (#{e.code})"           # payment failed (402)
end

Code Explained

Error < StandardError — one base for the whole library
OutOfStock < Error — specific, but still rescuable as Shop::Error
super(msg) — keeps message working
rescue order — specific classes first, base class last

The Ruby Way

  • class MyError < Exception → < StandardError
  • Many unrelated top-level error classes → nest them under MyLib::Error
  • Encoding details in the message string → expose them with attr_reader

In Rails

  • Rails · app errors often live in app/errors/ and inherit from a shared base
  • Rails · rescue_from Shop::Error, with: :render_error maps them to HTTP responses

⚠ Common Mistakes

  • Inheriting from Exception; a plain rescue then misses your error entirely
  • Forgetting super(msg) in initialize; message falls back to the class name
  • Rescuing the base class before specific subclasses; specific handlers never run

✓ Tips & Best Practices

  • Give each gem or app one Error base class; it's the first thing callers look for
  • A default message in initialize keeps raise OutOfStock short at call sites
  • Name errors for what went wrong (OutOfStock), not where (InventoryServiceError)

Quick Summary

  • < StandardError — custom error base
  • MyLib::Error — one base per library
  • attr_reader — extra error data
  • specific first — rescue order matters
