Equality and Hash Keys

Ruby has three equality methods: == for value equality, eql? for stricter equality used by Hash and Set, and equal? for identity. To use your own objects as hash keys or in uniq, override eql? and hash together so equal objects produce equal hash codes.

Rules

  • Objects that are eql? must return the same hash
  • Default ==, eql? and equal? all compare identity
  • 1 == 1.0 but !1.eql?(1.0), so they're different hash keys
  • Never override equal?

Value Equality for Your Classes

class Point
  attr_reader :x, :y
  def initialize(x, y) = (@x, @y = x, y)

  def ==(other) = other.is_a?(Point) && [x, y] == [other.x, other.y]
  alias eql? ==
  def hash = [self.class, x, y].hash
end

a = Point.new(1, 2)
b = Point.new(1, 2)
a == b                     # true
a.equal?(b)                # false (different objects)
{ a => "home" }[b]         # "home" (eql? + hash)
[a, b].uniq.size           # 1
Set[a, b].size             # 1

class Bare; end
Bare.new == Bare.new       # false (identity by default)
{ 1 => :int }[1.0]         # nil (1.eql?(1.0) is false)

Code Explained

== — compares fields
alias eql? == — reuse it for hash lookups
hash — combine the same fields into one code
{ a => … }[b] — works because b.eql?(a) and hashes match
default behavior — identity unless you override

The Ruby Way

  • Overriding only == → also define eql? and hash
  • Hand-written value classes → Data.define gives all three
  • hash built with string concatenation → [fields].hash

In Rails

  • Rails · ActiveRecord == compares class and id, so two loads of one row are equal
  • Rails · new (unsaved) records are only equal to themselves

⚠ Common Mistakes

  • Defining == but not hash; objects compare equal but hash lookups and uniq miss them
  • Including mutable fields in hash and then changing them while the object is a hash key
  • Comparing with equal? when you mean value equality

✓ Tips & Best Practices

  • Data.define and Struct already implement value equality and hashing
  • Include self.class in hash so different types with the same fields don't collide
  • After mutating keys, call hash.rehash to rebuild the index

Quick Summary

  • == — value equality
  • eql? + hash — hash-key equality
  • equal? — identity
  • override all three together (except equal?)
