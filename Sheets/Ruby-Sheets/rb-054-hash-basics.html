Hash Basics

A Hash maps keys to values and keeps insertion order. Keys can be any object, but symbols (name: "Ada") are the norm for fixed fields and strings for external data. Missing keys return the hash's default (usually nil); fetch raises instead, and Hash.new with a block computes defaults on demand.

Hash Facts

  • { name: "Ada" } is shorthand for { :name => "Ada" }
  • { x:, y: } uses local variables x and y as values (3.1+)
  • Hash.new(0) is great for counting
  • Hash.new([]) shares one array across all keys (a trap)

Creating and Reading Hashes

user = { name: "Ada", age: 36 }      # symbol keys
headers = { "Content-Type" => "json" }  # string keys
user[:name]                  # "Ada"
user[:email]                 # nil
user.fetch(:email, "n/a")    # "n/a"
user.fetch(:email)           # KeyError: key not found: :email
user[:email] = "a@b.c"       # add or update

x, y = 1, 2
point = { x:, y: }           # {x: 1, y: 2}

counts = Hash.new(0)
%w[a b a].each { |w| counts[w] += 1 }
counts                       # {"a" => 2, "b" => 1}

groups = Hash.new { |h, k| h[k] = [] }   # fresh array per key
groups[:odd] << 1
groups                       # {odd: [1]}
user.size                    # 3
user.key?(:age)              # true

Code Explained

name: — symbol key; "k" => — any other key type
fetch — raises or uses a default for missing keys
{ x:, y: } — value omission shorthand
Hash.new(0) — default value for counters
Hash.new { |h, k| h[k] = [] } — default block stores per key

The Ruby Way

  • { :name => "Ada" } → { name: "Ada" }
  • h[k] = [] unless h[k]; h[k] << v → Hash.new { |h, k| h[k] = [] }
  • h[:required_key] → h.fetch(:required_key)

In Rails

  • Rails · params is ActionController::Parameters; call permit before mass assignment
  • AS · h.with_indifferent_access[:name] and ["name"] both work

⚠ Common Mistakes

  • Hash.new([]) then h[:a] << 1; every key shares that one array and the hash stays empty
  • Mixing "name" and :name keys and getting nil lookups
  • Using string keys from JSON with symbol lookups; parse with symbolize_names: true

✓ Tips & Best Practices

  • Prefer fetch for required keys; the KeyError names the missing key
  • Hashes preserve insertion order, so they work as ordered maps
  • Freeze config hashes (CONFIG = {...}.freeze) to prevent accidental changes

Quick Summary

  • { key: value } — symbol-key hash
  • h[k] / fetch — soft / strict lookup
  • Hash.new(0) — counter default
  • Hash.new { } — computed default
