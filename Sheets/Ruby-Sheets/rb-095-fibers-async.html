Fibers and the Fiber Scheduler

A Fiber is a lightweight, manually scheduled coroutine: resume runs it until it calls Fiber.yield, which hands a value back. Since Ruby 3.0 a Fiber Scheduler can make blocking I/O non-blocking, so thousands of fibers can wait on sockets concurrently. The async gem provides a production scheduler.

Fiber Notes

  • Fibers never run in parallel; they switch only at yield points or I/O
  • Fiber.new(blocking: false) fibers use the scheduler
  • async gives you tasks, timeouts and HTTP clients

Fibers and async

gen = Fiber.new do
  Fiber.yield 1
  Fiber.yield 2
  3                              # final value
end
gen.resume                       # 1
gen.resume                       # 2
gen.resume                       # 3

echo = Fiber.new { |x| loop { x = Fiber.yield(x * 2) } }
echo.resume(5)                   # 10
echo.resume(7)                   # 14

require "async"
require "async/http/internet"
Async do |task|
  internet = Async::HTTP::Internet.new
  pages = %w[https://a.com https://b.com].map do |url|
    task.async { internet.get(url).read.size }   # concurrent
  end
  p pages.map(&:wait)            # [1256, 3471]
ensure
  internet&.close
end

Code Explained

Fiber.yield 1 — pause and return 1 to resume
resume(7) — the value becomes Fiber.yield's return
alive? — false after the block finishes
Async do |task| — starts a scheduler event loop
task.async { } — child task; wait gets its result

The Ruby Way

  • Manual fiber juggling for generators → Enumerator.new (sheet 105)
  • Threads for thousands of mostly idle connections → async fibers
  • Callback-style I/O → plain blocking calls inside Async

⚠ Common Mistakes

  • Calling resume on a finished fiber; it raises FiberError: dead fiber called
  • Expecting fibers to run CPU work in parallel; they're cooperative and single-threaded
  • Mixing blocking C extensions inside Async; calls the scheduler can't hook will block every task

✓ Tips & Best Practices

  • Async::Barrier waits for a group of tasks; Async::Semaphore limits concurrency
  • Falcon is a fiber-based web server built on async
  • Most programs never touch Fiber directly; use Enumerator or async

Quick Summary

  • Fiber.new / resume / Fiber.yield — coroutines
  • Fiber Scheduler — non-blocking I/O
  • async — production scheduler
  • cooperative — no parallel CPU
