Logical Operators

&&, || and ! work on truthiness and short-circuit: the right side runs only if needed. They return one of the operands, not necessarily true / false, which is why x || default works. The word forms and, or, not have much lower precedence and are meant for control flow, not expressions.

Logic Rules

  • a && b returns a if a is falsy, otherwise b
  • a || b returns a if a is truthy, otherwise b
  • && binds tighter than ||
  • and / or bind looser than =, which causes bugs

&& || ! and Precedence

true && "yes"            # "yes"
nil && "yes"             # nil
nil || "default"         # "default"
"set" || "default"       # "set"
!nil                     # true
!"text"                  # false

name = params[:name] || "Guest"
user && user.admin?      # safe even if user is nil
@config ||= load_config  # assign once
count &&= count + 1      # only if count is truthy

x = true and false       # x is true!  (= runs first)
x = (true and false)     # x is false
x = true && false        # x is false

file = File.open(path) or raise "can't open"
save or return           # control-flow style
not true                 # false

Code Explained

|| default — returns the first truthy value
&& guard — stops at nil before calling admin?
||= / &&= — conditional assignment
x = true and false — = binds tighter than and
or raise — idiomatic "do this or bail out"

The Ruby Way

  • if a == true && b == true → if a && b
  • x = y and z in assignments → x = y && z
  • if !(x.nil?) → if x or unless x.nil?

⚠ Common Mistakes

  • Using and / or in assignments and conditions; precedence below = gives surprising results
  • Relying on || for defaults when false is a valid value; false || true is true
  • Expecting && to return true; it returns the last evaluated operand

✓ Tips & Best Practices

  • Reserve and / or for control flow like do_it or raise; RuboCop flags other uses
  • Use x.nil? ? default : x (or fetch) when false must be preserved
  • Short-circuiting means expensive checks belong on the right side

Quick Summary

  • && / \|\| — short-circuit, return an operand
  • ! — negate truthiness
  • \|\|= / &&= — conditional assignment
  • and / or — low precedence, control flow only
