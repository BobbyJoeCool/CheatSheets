Blocks and yield

A block is a chunk of code passed to a method, written with { } (one line) or do ... end (multi-line). The method runs it with yield, passing values that arrive as block parameters, and gets the block's last value back. block_given? checks whether a block was supplied. it (3.4+) and _1 name the parameter implicitly.

Block Facts

  • Every method can take one block; it isn't in the param list
  • yield with no block raises LocalJumpError
  • { } binds tighter than do ... end
  • it refers to the single block parameter (Ruby 3.4+)

Writing and Calling Blocks

[1, 2, 3].each { |n| print n }    # 123

def twice
  yield 1
  yield 2
end
twice { |x| print x }             # 12

def transform(value)
  return value unless block_given?
  yield(value)                    # block's result returned
end
transform(5)                      # 5
transform(5) { |v| v * 3 }        # 15


[1, 2, 3].map { it * 2 }          # [2, 4, 6] (3.4+)
[1, 2, 3].map { _1 * 2 }          # [2, 4, 6] (2.7+)

Code Explained

{ } / do ... end — same thing; style differs by length
yield 1 — call the block with an argument
block_given? — make the block optional
it / _1 — implicit parameter names

The Ruby Way

  • { } blocks spanning many lines → do ... end
  • map { |x| x * 2 } → map { it * 2 } (3.4+), or keep |x| when clearer
  • Methods returning arrays only to iterate → yield each item

⚠ Common Mistakes

  • puts [1, 2].map do |x| x end; do...end binds to puts, so map gets no block. Use { }
  • Calling yield in a method that's sometimes called without a block; guard with block_given?
  • Mixing it with explicit params, or using it in nested blocks where it's ambiguous

✓ Tips & Best Practices

  • Return to_enum(__method__) when no block is given so your iterator chains with map etc. (sheet 106)
  • Prefer yield over &block + call; it's faster and reads better
  • Use it for short single-parameter blocks; name the parameter when the block grows
