to_s vs to_str · to_a vs to_ary · to_h · to_proc · inspect · implicit vs explicit conversion

Conversion Protocols

Ruby distinguishes explicit conversions (to_s, to_a, to_h, to_i), which any object may offer, from implicit ones (to_str, to_ary, to_hash, to_int), which mean "I really am a string/array". Core methods call the implicit forms automatically, so defining them makes your object usable wherever the real type is expected.

Protocol Rules

  • Define to_s freely; define to_str only for string-like objects
  • to_ary enables destructuring: a, b = obj
  • to_proc enables &obj as a block
  • inspect is for developers; to_s for users

Explicit vs Implicit

class Path
  def initialize(p) = @p = p
  def to_s   = @p                 # explicit: interpolation, puts
  def to_str = @p                 # implicit: acts like a String
end
"dir/" + Path.new("a.rb")         # "dir/a.rb" (uses to_str)
File.basename(Path.new("x/y.rb")) # "y.rb"

class Pair
  def initialize(a, b) = (@a, @b = a, b)
  def to_ary = [@a, @b]           # implicit array
end
x, y = Pair.new(1, 2)             # x=1, y=2

class Doubler
  def to_proc = ->(n) { n * 2 }
end
[1, 2].map(&Doubler.new)          # [2, 4]

"n=" + 5                          # TypeError (Integer has no to_str)
"n=#{5}"                          # "n=5" (interpolation uses to_s)

Code Explained

to_s — "here's a string version of me"
to_str — "treat me as a String"; + calls it
to_ary — multiple assignment and flatten call it
to_proc — &obj turns the object into a block
"n=" + 5 — integers aren't string-like, so no implicit conversion

The Ruby Way

  • Calling .to_s before every string + → interpolate
  • Defining to_str just to print nicely → to_s (and inspect)
  • Lambda wrappers for & → give the class a to_proc

In Rails

  • Rails · as_json / to_json control how models serialize
  • Rails · to_param (URL) and to_partial_path (render) are Rails protocols

⚠ Common Mistakes

  • Defining to_str on non-string objects; Ruby then silently treats them as strings in + and file APIs
  • Returning a non-String from to_s; puts and interpolation then misbehave
  • Overriding to_s but not inspect, so p obj still shows #<Path:0x…>

✓ Tips & Best Practices

  • Rule of thumb: implicit conversions only if your class is a drop-in replacement for the core type
  • Kernel#String() / Array() are the safest way to normalize unknown input
  • Implement to_h on value objects; it plugs into JSON and pattern matching neatly

Quick Summary

  • to_s / to_a / to_h — explicit
  • to_str / to_ary / to_hash — implicit
  • to_proc — use as a block
  • String() / Array() — normalize input
