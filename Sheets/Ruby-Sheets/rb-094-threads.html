Threads and Mutex

Thread.new runs a block concurrently; join waits for it and value returns its result. CRuby has a Global VM Lock (GVL), so threads don't run Ruby code in parallel, but they do overlap I/O (network, files, sleep), which makes them useful for concurrent requests. Shared mutable state needs a Mutex, and Thread::Queue passes work between threads safely.

Thread Notes

  • Exceptions in a thread surface on join / value
  • Ruby's GVL means CPU-bound work needs Ractors or processes
  • Thread::Queue#pop blocks until an item is available

Threads, Mutex, Queue

urls = %w[https://a.com https://b.com https://c.com]
threads = urls.map do |url|
  Thread.new(url) { |u| Net::HTTP.get(URI(u)).size }   # I/O overlaps
end
threads.map(&:value)            # [1256, 3471, 902]

count = 0
lock = Mutex.new
10.times.map {
  Thread.new { 1000.times { lock.synchronize { count += 1 } } }
}.each(&:join)
count                           # 10000 (always)

queue = Thread::Queue.new
workers = 3.times.map do
  Thread.new do
    while (job = queue.pop)     # nil after close
      puts "done #{job}"
    end
  end
end
5.times { queue << it }
queue.close
workers.each(&:join)

Code Explained

Thread.new(url) { |u| } — pass values in as arguments
value — joins and returns the block's result
lock.synchronize { } — one thread at a time in the block
Thread::Queue — thread-safe work queue
queue.close — pop returns nil, ending the workers

The Ruby Way

  • count += 1 from many threads → Mutex#synchronize
  • Polling shared arrays → Thread::Queue
  • Unbounded Thread.new per item → a fixed worker pool

⚠ Common Mistakes

  • Expecting threads to speed up CPU-heavy work in CRuby; the GVL serializes Ruby code
  • Updating shared counters or arrays without a lock; += isn't atomic
  • Forgetting to join; the main program exits and kills unfinished threads

✓ Tips & Best Practices

  • concurrent-ruby provides thread pools, futures and atomic counters
  • Keep the critical section inside synchronize as small as possible
  • Use SizedQueue so fast producers can't exhaust memory

Quick Summary

  • Thread.new / join / value — run and wait
  • GVL — concurrency for I/O, not CPU
  • Mutex#synchronize — protect shared state
  • Thread::Queue — pass work safely
