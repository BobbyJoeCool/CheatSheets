Struct and Data

Struct.new builds a small class with accessors, equality, to_h and pattern matching in one line, and its fields are mutable. Data.define (3.2+) builds immutable value objects: no setters, keyword or positional construction, and with to copy with changes. Both accept a block to add methods.

Notes

  • Struct fields have setters; Data fields don't
  • Data requires every field (unless you add defaults in initialize)
  • Both define == by value, not identity
  • Both support deconstruct / deconstruct_keys

Struct and Data

Point = Struct.new(:x, :y) do
  def dist = Math.hypot(x, y)
end
p = Point.new(3, 4)
p.x                          # 3
p.x = 6                      # mutable
p.dist                       # 7.211102550927978
p.to_a                       # [6, 4]
Point.new(1, 2) == Point.new(1, 2)   # true
Point.new(x: 1, y: 2)        # keyword init works (3.2+)

Money = Data.define(:amount, :currency) do
  def to_s = format("%.2f %s", amount, currency)
end
m = Money.new(amount: 5, currency: "USD")
m.to_s                       # "5.00 USD"
m.amount = 6                 # NoMethodError (immutable)
m.with(amount: 9)            # #<data Money amount=9, currency="USD">
m.to_h                       # {amount: 5, currency: "USD"}
m => { amount: }; amount     # 5 (pattern matching)

Code Explained

Struct.new(:x, :y) do … end — class with accessors + methods
p.x = 6 — Struct fields are writable
Data.define — read-only value object
with(amount: 9) — copy with one field changed
pattern matching — both work in case/in

The Ruby Way

  • Tiny classes with only attr_accessor + initialize → Struct
  • Value objects with hand-written == → Data.define
  • Passing loose hashes around → named Data objects

In Rails

  • Rails · include ActiveModel::Model gives validations and form helpers to plain classes
  • Rails · ActiveModel::Attributes adds typed attribute :age, :integer

⚠ Common Mistakes

  • Subclassing with class Point < Struct.new(:x, :y); it creates an extra anonymous class. Assign to a constant with a block instead
  • Expecting Data to accept missing fields; every field is required
  • Using a mutable Struct as a hash key and then changing a field

✓ Tips & Best Practices

  • Prefer Data for anything that shouldn't change after creation (money, coordinates, results)
  • Add defaults to Data with def initialize(amount:, currency: "USD") = super
  • Struct's keyword_init: true is no longer needed; both styles work since 3.2

Quick Summary

  • Struct.new — quick mutable record
  • Data.define — immutable value object
  • with — copy with changes
  • to_h / pattern matching — built in
