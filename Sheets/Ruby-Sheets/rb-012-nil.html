nil and Safe Navigation

nil is the single instance of NilClass and means "no value". Calling a method on nil that it doesn't define raises NoMethodError, the most common Ruby error. The safe navigation operator &. returns nil instead of raising, and || / ||= supply defaults.

nil Facts

  • Many lookups return nil on a miss: hash[:x], arr[99], str[/re/]
  • nil.to_s is "", nil.to_a is [], nil.to_i is 0
  • &. skips the call and any arguments; it doesn't evaluate them
  • x ||= v assigns only when x is nil or false

Handling nil

user = nil
user.name                    # NoMethodError
user&.name                   # nil
user&.profile&.city          # nil (chain stops at first nil)
user.nil?                    # true

name = user&.name || "guest" # "guest"
@cache ||= {}                # set once, reuse after

h = { a: 1 }
h[:b]                        # nil  (silent miss)
h.fetch(:b)                  # KeyError: key not found: :b
h.fetch(:b, 0)               # 0
h.fetch(:b) { |k| "no #{k}" }  # "no b"

Array(nil)                   # []
Array([1, 2])                # [1, 2]  (no double wrap)
Array("x")                   # ["x"]
[1, nil, 2, nil].compact     # [1, 2]

Code Explained

&. — call only if the receiver isn't nil
|| "guest" — default when the left side is nil / false
||= — memoize; common for lazy instance variables
fetch — raise or default instead of a silent nil
Array(x) — normalize "nil, one, or many" into an array

The Ruby Way

  • if user && user.profile && user.profile.city → user&.profile&.city
  • @x = @x || compute → @x ||= compute
  • hash[:key] when the key must exist → hash.fetch(:key)

In Rails

  • AS · presence returns the value or nil when blank: params[:q].presence || "all"
  • AS · user.try(:name) is like &. but also skips methods it doesn't respond to
  • AS · blank? treats nil and "" alike

⚠ Common Mistakes

  • Using ||= for booleans: @enabled ||= true overwrites a stored false. Use @enabled = true if @enabled.nil?
  • Chaining &. everywhere and hiding real bugs; a required value that is nil should raise early
  • Forgetting &. doesn't help with []: nil&.[](0) works, but nil[0] still raises

✓ Tips & Best Practices

  • Prefer fetch for config and required keys; the error message names the missing key
  • Use Array(x) at method boundaries so callers can pass one item or many
  • Ruby 3.4+ error messages show the receiver: undefined method 'name' for nil, which points to the nil source

Quick Summary

  • nil — the only NilClass object
  • &. — safe navigation
  • ||= — default/memoize
  • fetch — loud lookup
