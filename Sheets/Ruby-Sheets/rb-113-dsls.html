Building DSLs

A DSL (domain-specific language) is Ruby code shaped to read like configuration. The usual ingredients are blocks, instance_eval (so bare method calls hit a builder object), method calls without parentheses, and keyword arguments. Rake tasks, RSpec, Gemfiles and Rails routes are all Ruby DSLs.

DSL Ingredients

  • A builder object that collects settings
  • instance_eval(&block) or yield the builder (|config|)
  • Methods named like keywords: title "x", route "/a"
  • Class.new / Module.new for anonymous classes

A Small Config DSL

class Server
  Route = Data.define(:verb, :path, :to)
  attr_reader :routes

  def self.build(&block) = new.tap { it.instance_eval(&block) }

  def initialize = @routes = []
  def port(n = nil) = n ? @port = n : @port
  def get(path, to:)  = @routes << Route.new(:get, path, to)
end

app = Server.build do
  port 8080
  get  "/users", to: "users#index"
end
app.port                               # 8080
app.routes.first.to                    # "users#index"

Config = Struct.new(:env, :debug)
def configure = (@config ||= Config.new).tap { yield it }
configure { |c| c.env = :prod; c.debug = false }   # yield style

Code Explained

instance_eval(&block) — bare calls (port, get) go to the builder
def port(n = nil) — one method as setter and getter
get "/users", to: — keywords read like configuration
tap { yield it } — the explicit-receiver style (c.env =)

The Ruby Way

  • Long hashes of options → a block DSL with named methods
  • instance_eval where outer methods are needed → yield the builder instead
  • DSLs for one-off scripts → plain method calls

In Rails

  • Rails · routes.rb, has_many :posts, validates :email, presence: true are DSLs on class bodies
  • Rails · Rails.application.configure do … end uses instance_eval

⚠ Common Mistakes

  • Using instance_eval and then calling your own helper methods inside the block; self changed, so they aren't found
  • Building a DSL where plain method calls would do; it adds indirection for no gain
  • Letting DSL methods silently ignore typos; raise on unknown settings

✓ Tips & Best Practices

  • Support both styles: block.arity == 1 ? yield(self) : instance_eval(&block)
  • Freeze the built object after the block runs so configuration can't drift
  • Name DSL methods after the domain (route, task), not after implementation details
