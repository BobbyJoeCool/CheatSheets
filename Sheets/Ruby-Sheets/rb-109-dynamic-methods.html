Dynamic Dispatch and define_method

send / public_send call methods by name, and define_method creates methods at runtime with a block body that is a closure. Combined with instance_variable_get / set and const_get / set, they let you generate repetitive methods from data instead of writing them by hand.

Notes

  • define_method(name) { |args| … } — block becomes the body
  • Called inside a class body, self is the class
  • remove_method deletes from this class; undef_method blocks lookup entirely
  • Prefer public_send with user-derived names

Generating Methods

class Settings
  FIELDS = %i[theme lang timezone]

  FIELDS.each do |field|
    define_method(field) { @data[field] }               # getter
    define_method("#{field}=") { |v| @data[field] = v } # setter
    define_method("#{field}?") { !@data[field].nil? }   # predicate
  end

  def initialize = @data = {}
end

s = Settings.new
s.theme = "dark"
s.theme                         # "dark"
s.lang?                         # false
s.public_send(:theme)           # "dark"
Settings.instance_methods(false).size   # 9

s.instance_variable_set(:@data, { theme: "light" })
s.theme                         # "light"

Code Explained

FIELDS.each { define_method … } — three methods per field
"#{field}=" — method names can be strings
block body — closes over field
public_send(:theme) — call by name, respecting visibility
const_set / const_get — define and read constants by name

The Ruby Way

  • Copy-pasted getters and setters → loop over a field list with define_method
  • eval("def #{name} …") → define_method(name) { }
  • send(params[:action]) → public_send with an allow-list

In Rails

  • Rails · ActiveRecord defines attribute methods (name, name=, name?, name_changed?) from the table schema
  • Rails · enum :status, %i[draft live] generates draft?, live! and scopes the same way

⚠ Common Mistakes

  • Generating methods nobody can find; add a comment listing the generated names
  • Using send with user input; it can reach private methods like system or exit
  • Defining methods inside instance methods with define_method; that changes the class for every instance

✓ Tips & Best Practices

  • define_method returns the method name, so private define_method(:x) { } works
  • respond_to_missing? + method_missing is the alternative when names aren't known up front (sheet 110)
  • Generate methods once at class load, not per object

Quick Summary

  • define_method — methods from data
  • public_send — call by name safely
  • instance_variable_get/set — dynamic state
  • const_get/set — dynamic constants
