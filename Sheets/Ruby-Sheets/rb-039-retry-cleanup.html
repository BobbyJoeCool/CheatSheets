retry and Cleanup Patterns

retry inside a rescue jumps back to the start of the begin block, which is handy for flaky network calls when combined with an attempt counter. For cleanup, prefer block-based APIs (File.open { }, Mutex#synchronize { }) that release resources automatically; ensure and at_exit cover the rest.

Notes

  • retry without a limit can loop forever
  • Back off between attempts (sleep 2 ** attempts)
  • at_exit blocks run in reverse order of registration

Retry and Cleanup

attempts = 0
begin
  attempts += 1
  response = fetch_data          # may raise Net::OpenTimeout
rescue Net::OpenTimeout, Errno::ECONNRESET
  if attempts < 3
    sleep(2 ** attempts)         # 2s, 4s
    retry                        # back to `begin`
  end
  raise                          # give up after 3 tries
end

def with_tempfile
  file = File.open("tmp.dat", "w")
  yield file
ensure
  file&.close
  File.delete("tmp.dat") if File.exist?("tmp.dat")
end

Timeout.timeout(5) { slow_call }  # require "timeout"
at_exit { puts "bye" }

Code Explained

retry — restarts the begin block; counter lives outside it
sleep(2 ** attempts) — exponential backoff
raise after the limit — re-raise the last error
yield + ensure — build your own cleanup helper

The Ruby Way

  • f = File.open(...); ...; f.close → File.open(...) { |f| ... }
  • Copy-pasted retry loops → one with_retries(times: 3) { } helper
  • Timeout.timeout around IO → the library's own timeout options

In Rails

  • Rails · ActiveJob has retry_on Net::OpenTimeout, wait: :polynomially_longer, attempts: 5
  • Rails · discard_on ActiveJob::DeserializationError drops jobs that can't succeed

Cleanup Tools

⚠ Common Mistakes

  • Retrying on every StandardError; bugs like NoMethodError will be retried pointlessly
  • Initializing the counter inside begin; it resets on every retry, so the loop never ends
  • Relying on Timeout.timeout for code that holds locks; it can interrupt at unsafe points

✓ Tips & Best Practices

  • Use Net::HTTP options (open_timeout, read_timeout) instead of wrapping in Timeout
  • Write cleanup helpers with yield inside begin/ensure, like the stdlib does
  • Add jitter (sleep(2 ** n + rand)) when many clients retry at once

Quick Summary

  • retry — re-run the begin block
  • attempt counter — limit retries
  • block APIs — automatic cleanup
  • ensure / at_exit — always-run code
