Inheritance and super

A class inherits from one parent with <, gaining its methods and overriding any it redefines. super calls the parent's version of the current method: bare super passes the same arguments, super() passes none, and super(a, b) passes exactly those. Method lookup walks the ancestors chain.

Inheritance Facts

  • Single inheritance only; share behavior across classes with modules
  • Default parent is Object, whose parent is BasicObject
  • super also forwards the block automatically
  • ancestors shows the full lookup order (including modules)

Overriding and super

class Animal
  attr_reader :name
  def initialize(name) = @name = name
  def speak = "..."
  def to_s = "#{self.class.name.downcase} #{name}"
end

class Dog < Animal
  def initialize(name, breed)
    super(name)               # parent's initialize(name)
    @breed = breed
  end

  def speak = "Woof"          # override
  def to_s = super + " (#{@breed})"   # bare super: same args
end

d = Dog.new("Rex", "lab")
d.speak                       # "Woof"
d.to_s                        # "dog Rex (lab)"
Dog.superclass                # Animal
Dog.ancestors.take(3)         # [Dog, Animal, Object]

Code Explained

Dog < Animal — single inheritance
super(name) — pass only what the parent expects
super (bare) — forwards the current arguments
ancestors — method lookup order

The Ruby Way

  • Copy-pasting methods between classes → a parent class or a module
  • Deep inheritance trees → composition or modules
  • super() vs super confusion → be explicit with arguments in initialize

In Rails

  • Rails · models inherit from ApplicationRecord, controllers from ApplicationController
  • Rails · single-table inheritance: a type column makes class Admin < User share one table

⚠ Common Mistakes

  • Calling bare super in an initialize with different parameters; the parent gets the wrong number of args
  • Forgetting super in initialize, so the parent's instance variables are never set
  • Using inheritance for code reuse between unrelated classes; prefer a mixin (sheet 066)

✓ Tips & Best Practices

  • Prefer shallow hierarchies (1–2 levels); combine with modules for shared behavior
  • method(:speak).super_method shows the next implementation up the chain
  • Call super at the start of initialize so parent state exists before you use it

Quick Summary

  • class B < A — inherit
  • override — redefine a method
  • super / super() / super(x) — call parent
  • ancestors — lookup order
