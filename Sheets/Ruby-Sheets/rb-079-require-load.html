require · require_relative · load · $LOAD_PATH · autoload · Zeitwerk naming conventions

require and load

require loads a library or file once by searching $LOAD_PATH (and installed gems). require_relative loads a file relative to the current file, which is what you want inside your own project. load re-runs a file every time it's called. autoload defers loading a constant until first use.

Notes

  • require returns true the first time, false after
  • The .rb extension is optional
  • $LOADED_FEATURES lists everything already required
  • Gems are added to the load path by RubyGems / Bundler

Loading Code

require "json"                     # stdlib / gem
require "json"                     # => false (already loaded)
require_relative "lib/parser"      # ./lib/parser.rb from this file
require_relative "../config"       # relative paths work

load "settings.rb"                 # runs the file again every time
load "./tasks.rb", true            # wrap in an anonymous module

$LOAD_PATH.unshift File.expand_path("lib", __dir__)
require "my_app"                   # now finds lib/my_app.rb

module MyApp
  autoload :Report, "my_app/report"   # loaded on first MyApp::Report
end

$LOADED_FEATURES.grep(/json/).first   # path of loaded json.rb
defined?(JSON)                     # "constant"

Code Explained

require — search load path, load once
require_relative — path relative to this file
load — execute again each call (scripts, reloading)
$LOAD_PATH.unshift — add your lib directory
autoload — load a file when the constant is first used

The Ruby Way

  • require "./lib/parser" → require_relative "lib/parser"
  • require File.expand_path("../x", __FILE__) → require_relative "x"
  • Requiring every file by hand in a big app → Zeitwerk autoloading

In Rails

  • Rails · Zeitwerk autoloads app/ constants; don't require your own app files
  • Rails · code in lib/ needs config.autoload_lib or explicit requires

⚠ Common Mistakes

  • Using require "lib/x" and depending on the current directory; it breaks when run from elsewhere
  • Using load in libraries; constants get redefined and warnings appear
  • Circular requires (a requires b requires a); one file sees half-defined constants

✓ Tips & Best Practices

  • Inside a gem, require your own files with the gem's namespace: require "my_gem/version"
  • Zeitwerk works outside Rails too (gem "zeitwerk") for any app with conventional file names
  • ruby -rjson -e '…' requires a library from the command line

Quick Summary

  • require — load once via load path
  • require_relative — load from this file's directory
  • load — run again
  • autoload / Zeitwerk — lazy loading
