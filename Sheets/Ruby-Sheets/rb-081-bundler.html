Bundler

Gemfile · bundle install · Gemfile.lock · bundle exec · groups · ~> constraints · bundle update

Bundler

Bundler manages a project's gems: you list dependencies in a Gemfile, bundle install resolves compatible versions and records them in Gemfile.lock, and bundle exec runs commands with exactly those versions. Commit both files so every machine and CI run uses the same gems.

Bundler Notes

  • Bundler ships with Ruby (bundle -v)
  • Gemfile.lock pins exact versions; commit it for apps
  • Groups (:development, :test) keep tools out of production
  • bundle add edits the Gemfile and installs in one step

Gemfile

source "https://rubygems.org"
ruby "~> 4.0"                     # required Ruby version

gem "sinatra", "~> 4.1"           # >= 4.1, < 5.0
gem "pg", ">= 1.5"
gem "csv"                         # bundled gem: list it explicitly
gem "my_lib", path: "../my_lib"   # local path
gem "toolkit", github: "acme/toolkit", branch: "main"

group :development, :test do
  gem "rspec", "~> 3.13"
  gem "debug"

end

Commands

bundle install          # resolve + write Gemfile.lock
bundle add faraday      # add to Gemfile + install
bundle exec rspec       # run with locked versions
bundle update sinatra   # upgrade one gem

Code Explained

~> 4.1 — pessimistic constraint: allow 4.x updates
path: / github: — gems from local dirs or git
group :test — only installed / loaded where needed
bundle exec — guarantees lock-file versions

The Ruby Way

  • gem install per project → Gemfile + bundle install
  • bundle update (everything) → bundle update gem_name
  • Typing bundle exec constantly → binstubs (bin/rspec)

In Rails

  • Rails · bin/rails and other binstubs already run under Bundler
  • Rails · Bundler.require(*Rails.groups) auto-requires gems for the current environment

⚠ Common Mistakes

  • Running rspec instead of bundle exec rspec and getting a different gem version
  • Not committing Gemfile.lock for an application; teammates resolve different versions
  • Running bundle update with no arguments and upgrading every dependency at once

✓ Tips & Best Practices

  • bundle config set --local path vendor/bundle keeps gems inside the project
  • bundle binstubs rspec-core creates bin/rspec so you can skip bundle exec
  • Gems (libraries) usually don't commit Gemfile.lock; apps always do

Quick Summary

  • Gemfile — declare dependencies
  • Gemfile.lock — exact versions (commit it)
  • bundle exec — run with locked gems
  • ~> — pessimistic constraint
