Classes and Objects

A class is a blueprint defined with class Name ... end; new allocates an object and calls initialize. State lives in instance variables (@name), which are private to the object and spring into existence when first assigned. Inside methods, self is the current object.

Class Facts

  • Class names are constants: CamelCase
  • @ivars are nil until assigned (no error on read)
  • Every class inherits from Object unless told otherwise
  • Override to_s for puts and inspect for p

A Complete Small Class

class BankAccount
  def initialize(owner, balance = 0)
    @owner = owner
    @balance = balance
  end

  def deposit(amount)
    @balance += amount
    self                    # return self to allow chaining
  end

  def to_s = "#{@owner}: $#{@balance}"
  def inspect = "#<BankAccount #{@owner}>"
end

acct = BankAccount.new("Ada", 100)
acct.deposit(50).deposit(25)
puts acct                     # Ada: $175
p acct                        # #<BankAccount Ada>
acct.instance_variables       # [:@owner, :@balance]

Code Explained

initialize — runs on BankAccount.new(...)
@balance — per-object state, hidden from outside
self — returning it enables method chaining
to_s / inspect — control puts and p output
instance_variables — introspect an object's state

The Ruby Way

  • def get_balance; return @balance; end → attr_reader :balance (sheet 062)
  • Classes with only data → Struct or Data (sheet 059)
  • Printing #<BankAccount:0x000…> → define to_s / inspect

In Rails

  • Rails · models are plain classes: class User < ApplicationRecord
  • Rails · don't define initialize on models; use callbacks or after_initialize

⚠ Common Mistakes

  • Typo in an instance variable name (@balnce); it's silently nil instead of an error
  • Calling BankAccount.initialize; you always call new, which calls initialize
  • Forgetting that p obj uses inspect, so overriding only to_s doesn't change p output

✓ Tips & Best Practices

  • Keep initialize simple: assign arguments, validate, nothing more
  • Return self from mutating methods when chaining reads naturally
  • Use Data.define when objects shouldn't change after creation

Quick Summary

  • class … end — define a class
  • new → initialize — construct
  • @ivar — per-object state
  • to_s / inspect — printable forms
