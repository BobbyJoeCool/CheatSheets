Raising Exceptions

raise creates and throws an exception. With just a string it raises RuntimeError; with a class and message it raises that class. Inside a rescue, a bare raise re-raises the current exception, and raising a new one automatically records the original as its cause.

raise Notes

  • raise "msg" → RuntimeError
  • cause is set automatically when you raise inside rescue

Raising and Re-raising

def withdraw(amount)
  raise ArgumentError, "must be positive" unless amount.positive?
  raise "insufficient funds" if amount > @balance  # RuntimeError
  @balance -= amount
end

def load_config(path)
  JSON.parse(File.read(path))
rescue Errno::ENOENT
  raise ConfigError, "no config at #{path}"   # wraps original
end

begin
  load_config("x.json")
rescue ConfigError => e
  e.cause.class               # Errno::ENOENT
end

begin
  risky
rescue => e
  log(e)
  raise                       # re-raise the same exception
end

Code Explained

raise ArgumentError, "..." — class plus message
raise "..." — defaults to RuntimeError
raising in rescue — the original becomes e.cause
bare raise — re-raises the exception being handled

The Ruby Way

  • raise "invalid" for bad input → raise ArgumentError, "invalid"
  • raise e after logging → bare raise (keeps the original backtrace)
  • Returning error strings → raise a specific exception class

⚠ Common Mistakes

  • Raising bare strings for programmer errors; callers can't rescue RuntimeError precisely
  • rescue => e; raise e.message; you lose the class and the backtrace
  • Raising inside ensure; it replaces whatever exception was already in flight

✓ Tips & Best Practices

  • Use built-in classes when they fit: ArgumentError, TypeError, KeyError, NotImplementedError
  • Validate arguments at the top of the method with guard-clause raises
  • Error messages should include the bad value: "expected positive, got #{amount}"

Quick Summary

  • raise Cls, "msg" — raise a specific error
  • raise "msg" — RuntimeError
  • bare raise — re-raise
  • e.cause — wrapped original
