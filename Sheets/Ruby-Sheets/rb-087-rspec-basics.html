RSpec Basics

RSpec is the most widely used Ruby testing framework, built around a readable DSL: describe groups examples, context describes a situation, it defines an example, and expect(actual).to matcher states the expectation. let defines lazy helpers and before runs setup.

RSpec Notes

  • Files end in _spec.rb under spec/
  • Run with bundle exec rspec, or rspec spec/x_spec.rb:12 for one example
  • let is lazy and memoized per example; let! runs eagerly
  • subject names the object under test

A Spec File

require "cart"

RSpec.describe Cart do
  subject(:cart) { described_class.new }
  let(:pen) { { price: 2.5, qty: 2 } }

  it "starts empty" do
    expect(cart.items).to be_empty
  end

  context "with items" do
    before { cart.add(**pen) }

    it "totals the prices" do
      expect(cart.total).to eq(5.0)
    end
  end
end

Code Explained

RSpec.describe Cart — example group for the class
subject(:cart) — named object under test
let(:pen) — lazy, memoized helper
context + before — shared setup for a situation
expect(x).to eq(y) — the expectation

The Ruby Way

  • Instance variables in before → let
  • it "works" → describe the behavior: it "totals the prices"
  • Repeated setup in each it → before in a context

In Rails

  • Rails · rspec-rails adds model, request and system specs (type: :request)
  • Rails · FactoryBot builds records: let(:user) { create(:user) }

⚠ Common Mistakes

  • Overusing let!; eager setup slows every example even when it isn't needed
  • Sharing state between examples through instance variables set outside hooks
  • Putting several unrelated expectations in one it; the first failure hides the rest

✓ Tips & Best Practices

  • Name contexts "when …" / "with …" so output reads like documentation
  • --only-failures (with example_status_persistence_file_path) shortens the fix-test loop
  • described_class keeps specs working when the class is renamed

Quick Summary

  • expect(x).to matcher — expectations
  • let / subject / before — setup
  • rspec file:line — run one example
