Creating a Gem

bundle gem name scaffolds a gem with the conventional layout: code in lib/, a .gemspec describing metadata and dependencies, a version.rb constant, and test setup. gem build packages it into a .gem file, and gem push publishes it to rubygems.org.

Conventions

  • Gem name my_gem → lib/my_gem.rb → module MyGem
  • Dashes mean namespaces: my-gem → lib/my/gem.rb
  • Put runtime deps in the gemspec, dev tools in the Gemfile
  • Executables go in exe/ and are listed in spec.executables

Scaffold, Build, Publish

bundle gem slugify --test=rspec --mit
# slugify/
#   lib/slugify.rb          main file
#   lib/slugify/version.rb  VERSION constant
#   slugify.gemspec         metadata
#   spec/                   tests
cd slugify
bundle exec rake spec       # run tests
gem build slugify.gemspec   # → slugify-0.1.0.gem
gem push slugify-0.1.0.gem  # publish (needs an account)
bundle exec rake release    # tag + build + push in one step

slugify.gemspec (excerpt)

Gem::Specification.new do |spec|
  spec.name    = "slugify"
  spec.version = Slugify::VERSION
  spec.required_ruby_version = ">= 3.2"
  spec.files   = Dir["lib/**/*.rb", "README.md"]
  spec.add_dependency "unicode_normalize", "~> 1.0"
end

Code Explained

bundle gem — generates the standard layout
version.rb — single source for the version number
gem build — packages into a .gem file
rake release — tags git, builds and pushes
add_dependency — runtime dependencies users get

The Ruby Way

  • Hard-coding the version in several files → MyGem::VERSION
  • Dev tools in add_dependency → put them in the Gemfile
  • Dir["**/*"] in spec.files → list only shipped files

⚠ Common Mistakes

  • Forgetting to bump VERSION; rubygems.org rejects re-pushing an existing version
  • Leaving spec.files using git ls-files with untracked files missing from the package
  • Defining top-level constants or monkey patches in a gem; everything should live under its module

✓ Tips & Best Practices

  • Enable MFA on your rubygems.org account before pushing
  • Use trusted publishing from GitHub Actions instead of storing API keys
  • Run gem build then gem install ./x.gem locally to test the packaged version

Quick Summary

  • bundle gem — scaffold
  • .gemspec — metadata + deps
  • gem build / gem push — package / publish
  • lib/name.rb + module Name — layout
