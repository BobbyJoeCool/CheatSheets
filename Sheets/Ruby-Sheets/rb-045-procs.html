Procs and &block

A Proc is a block turned into an object you can store, pass around and call later. &block in a parameter list converts the caller's block into a Proc; &obj at a call site converts a Proc (or anything with to_proc) back into a block. Procs are lenient about arguments: extra args are dropped and missing ones become nil.

Proc Facts

  • Create with proc { }, Proc.new { }, or capture with &block
  • Call with .call, .(), [], or yield
  • &:name uses Symbol#to_proc
  • return inside a proc returns from the enclosing method

Creating and Calling Procs

square = proc { |x| x * x }
square.call(4)               # 16
square.(4)                   # 16
square.call(4, 99)           # 16  (extra arg ignored)
proc { |a, b| [a, b] }.call(1)  # [1, nil]

def run(&block)              # block → Proc
  block.call(10)
end
run { |n| n + 1 }            # 11

shout = proc { |s| s.upcase }
%w[a b].map(&shout)          # ["A", "B"]  (Proc → block)
%w[a b].map(&:upcase)        # ["A", "B"]  (Symbol#to_proc)

callbacks = []
callbacks << proc { puts "saved" }
callbacks.each(&:call)       # saved

add = proc { |a, b| a + b }
add.curry[1][2]              # 3

Code Explained

.call / .() / [] — three ways to call
lenient arity — extras dropped, missing are nil
&block param — the caller's block, as a Proc
map(&shout) — turn a Proc back into a block
callbacks.each(&:call) — store blocks and run them later

The Ruby Way

  • map { |x| x.upcase } → map(&:upcase)
  • Storing a block via Proc.new with no block → capture with &block
  • Procs for argument-checked callbacks → lambdas (sheet 046)

⚠ Common Mistakes

  • Using return in a proc stored for later; once its method has returned, it raises LocalJumpError
  • Relying on lenient arity and hiding bugs where callers pass the wrong number of values
  • Writing map(&:method(arg)); &:sym only works for methods without arguments

✓ Tips & Best Practices

  • Use &block when you need to store or forward a block; use yield when you only call it
  • Procs respond to ===, so they work as when conditions
  • Method#to_proc lets you pass named methods: items.each(&method(:puts))

Quick Summary

  • proc { } — block as an object
  • &block — block → Proc
  • &obj — Proc → block
  • lenient arity — extras ignored
