Checking Types and Identity

Ruby is duck typed: you usually ask whether an object can do something (respond_to?) rather than what class it is. When you do need the class, is_a? checks the whole ancestry, instance_of? checks the exact class, and === powers case/when. Ruby has three different equality methods with different jobs.

Equality Methods

  • == — same value (overridden by most classes)
  • eql? — same value and type; used by Hash keys
  • equal? — same object (identity); never override it
  • object_id — unique integer per live object

Type Checks

5.class                     # Integer
5.is_a?(Integer)            # true
5.is_a?(Numeric)            # true  (ancestor)
5.instance_of?(Numeric)     # false (exact class only)
Integer === 5               # true  (used by case/when)
Integer.ancestors.take(4)   # [Integer, Numeric, Comparable, Object]

"hi".respond_to?(:upcase)   # true
nil.respond_to?(:each)      # false

1 == 1.0                    # true
1.eql?(1.0)                 # false (Integer vs Float)
a = "x"; b = "x"
a == b                      # true
a.equal?(b)                 # false (two objects)
a.equal?(a)                 # true

case 5
when String  then "text"
when Integer then "number"  # => "number"
end

Code Explained

is_a? / kind_of? — same method; includes superclasses and modules
instance_of? — exact class, ignores inheritance
Integer === 5 — class === means "is an instance of"
respond_to? — duck-typing check
eql? — stricter ==; why 1 and 1.0 are different hash keys

The Ruby Way

  • if x.class == String → if x.is_a?(String) (or better, respond_to?)
  • if x.is_a?(A) ... elsif x.is_a?(B) → case x when A ... when B
  • Checking types before every call → call it and let NoMethodError surface

⚠ Common Mistakes

  • Writing case x when "Integer"; when needs the class constant, not a string
  • Using equal? to compare values; it only checks identity, so equal strings return false
  • Reversing ===: 5 === Integer is false; the pattern goes on the left

✓ Tips & Best Practices

  • Prefer respond_to?(:each) over is_a?(Array) so hashes, sets and custom collections also work
  • Pass several classes to when: when Integer, Float
  • obj.class.ancestors shows exactly what is_a? will accept

Quick Summary

  • is_a? — class or ancestor
  • instance_of? — exact class
  • respond_to? — duck typing
  • == / eql? / equal? — value / value+type / identity
