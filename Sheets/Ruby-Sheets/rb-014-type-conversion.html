Type Conversion

to_s · to_i · to_f · Integer() / Float() strict · to_a · to_sym · implicit to_str / to_ary

Converting Between Types

Ruby has two families of conversion. Explicit methods like to_s, to_i, to_f, to_a always try and return something, even if it's 0 or "". Strict Kernel functions like Integer(), Float(), String(), Array() raise on bad input, which is what you want for validation.

Conversion Rules

  • "12abc".to_i is 12; "abc".to_i is 0
  • Integer("12abc") raises ArgumentError
  • Ruby never converts implicitly in +: "a" + 1 raises TypeError
  • to_str / to_ary are implicit protocols used by core methods

to_* vs Kernel()

"42".to_i                    # 42
"42.7".to_i                  # 42
"3.5kg".to_f                 # 3.5
"abc".to_i                   # 0
Integer("42")                # 42
Integer("4x")                # ArgumentError
Integer("4x", exception: false)  # nil
Float("1e3")                 # 1000.0

42.to_s                      # "42"
3.0.to_s                     # "3.0"
3.7.to_i                     # 3 (truncates)
3.7.round                    # 4
:id.to_s                     # "id"
"id".to_sym                  # :id
[[:a, 1], [:b, 2]].to_h      # {a: 1, b: 2}
{ a: 1 }.to_a                # [[:a, 1]]
(1..3).to_a                  # [1, 2, 3]
"Total: " + 5                # TypeError
"Total: #{5}"                # "Total: 5"

Code Explained

to_i — reads leading digits, ignores the rest, never raises
Integer() — whole string must be a valid integer
exception: false — return nil instead of raising
3.7.to_i — truncates toward zero; use round to round
"a" + 5 — no implicit coercion; interpolate instead

The Ruby Way

  • "Total: " + n.to_s → "Total: #{n}"
  • Integer(s) rescue nil → Integer(s, exception: false)
  • value.to_s.to_i chains → convert once at the input boundary

In Rails

  • Rails · ActiveRecord casts on assignment: user.age = "42" stores 42
  • AS · { q: "ruby", page: 2 }.to_query → "page=2&q=ruby"
  • Rails · to_param is what models return in URLs (the id by default)

⚠ Common Mistakes

  • Validating input with to_i; junk becomes 0 and passes as a real number
  • Expecting "5" + 5 to coerce like JavaScript; Ruby raises TypeError
  • Using to_i to round prices; 19.99.to_i is 19

✓ Tips & Best Practices

  • Convert at the edge (user input, files, env vars) and work with real types inside
  • Float(x, exception: false) makes a quick "is this numeric?" check
  • Integer("0b101"), Integer("0o17") and Integer("0x1F") read base prefixes

Quick Summary

  • to_i / to_f / to_s — lenient conversion
  • Integer() / Float() — strict conversion
  • exception: false — nil on failure
  • no implicit coercion — interpolate
