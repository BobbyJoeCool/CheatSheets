eval Family and Hooks

instance_eval runs a block with self set to an object, class_eval (alias module_eval) runs it inside a class so def adds instance methods, and instance_exec does the same while passing arguments. Hook methods like inherited, included, extended and method_added let classes and modules react when they're used.

Notes

  • Prefer blocks over string eval; strings can't be checked and are an injection risk
  • class_eval with a block can reopen classes held in variables
  • included(base) is the standard way to add class methods from a module

eval Variants and Hooks

class Box; def initialize = @secret = 42; end
Box.new.instance_eval { @secret }        # 42 (self is the box)
Box.class_eval { def size = 3 }          # adds an instance method
Box.new.instance_exec(10) { |n| @secret + n }  # 52

module Trackable
  def self.included(base) = base.extend(ClassMethods)  # hook
  module ClassMethods
    def tracked? = true
  end
end
class Order; include Trackable; end
Order.tracked?                           # true

class Plugin
  def self.registry = @registry ||= []   # class-level ivar
  def self.inherited(sub) = (super; registry << sub)   # hook
end
class CsvPlugin < Plugin; end
Plugin.registry                          # [CsvPlugin]

Code Explained

instance_eval — self is the receiver, ivars readable
class_eval { def … } — define methods on a class
instance_exec(10) — like instance_eval with arguments
self.included(base) — runs when the module is included
self.inherited(sub) — runs for each new subclass

The Ruby Way

  • eval("def #{n}; end") → define_method(n) { }
  • instance_eval to read private state in app code → add a public method
  • Manual plugin lists → inherited hook (or subclasses)

In Rails

  • AS · ActiveSupport::Concern wraps included with included do … end and class_methods do … end
  • Rails · ApplicationRecord uses inherited to set up each model class

⚠ Common Mistakes

  • Forgetting super in inherited; other libraries' hooks on the parent stop running
  • Using string eval with interpolated input; it can execute arbitrary code
  • Expecting instance_eval { def x } to add an instance method; it defines a singleton method

✓ Tips & Best Practices

  • instance_eval with a block is the core of most Ruby DSLs (sheet 113)
  • Use Module#prepended / included to register behavior without monkey patching
  • __method__ and caller_locations help hooks report where they were triggered

Quick Summary

  • instance_eval / instance_exec — run as the object
  • class_eval — run inside the class
  • included / inherited — react to use
  • avoid string eval
