Loop Controls

Inside loops and blocks, next skips to the next iteration, break exits the loop (optionally with a value that becomes the loop's result), and redo repeats the current pass. throw / catch exit several levels of nesting at once. In a block, return returns from the enclosing method, not just the block.

Control Notes

  • break value makes the iterator return value
  • next value sets the block's result for that element (useful in map)
  • Ruby has no labeled break; use throw / catch or a method return

break, next, throw/catch, return

[1, 2, 3, 4].each do |n|
  next if n.even?            # skip evens
  print n                    # 13
end

found = [5, 8, 12].each { |n| break n if n > 6 }   # 8
[1, 2, 3].map { |n| next 0 if n == 2; n * 10 }    # [10, 0, 30]

result = catch(:done) do
  (1..3).each do |i|
    (1..3).each { |j| throw :done, [i, j] if i * j == 6 }
  end
  nil
end
result                       # [2, 3]

def first_negative(nums)
  nums.each { |n| return n if n.negative? }  # leaves the method
  nil
end

Code Explained

next if — skip the rest of this iteration
break n — stop and make each return n
next 0 — the block's value for this element
throw :done, value — unwinds to the matching catch
return in a block — exits first_negative itself

The Ruby Way

  • break loops to search → find { |n| n > 6 }
  • Flag variables to escape nested loops → catch / throw or extract a method
  • next unless cond around the whole body → select or filter_map

⚠ Common Mistakes

  • Using return inside a block passed to a method defined elsewhere; you exit your own method, which surprises readers
  • Using break inside a proc that outlives its method; it raises LocalJumpError
  • Writing break in map and expecting a partial array; break returns nil (or its value) instead

✓ Tips & Best Practices

  • Most explicit loops with break are really find, any?, take_while or detect
  • next value in map is cleaner than wrapping the block body in if/else
  • throw / catch is for rare deep exits; usually extracting a method and using return reads better

Quick Summary

  • next — skip
  • break v — exit with a value
  • throw / catch — multi-level exit
  • return in block — leaves the method
