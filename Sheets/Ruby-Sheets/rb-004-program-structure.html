Program Structure & Style

no main() · newline-terminated statements · end keyword · { } vs do...end · 2-space indent · ? and ! naming · RuboCop

How a Ruby File Is Laid Out

Ruby has no main() and no required boilerplate: statements run top to bottom. Lines end statements (no semicolons needed), blocks close with end, and indentation is two spaces by convention but not enforced. Method names may end in ? (returns a boolean) or ! (dangerous or mutating variant).

Style Conventions

  • snake_case methods/variables, CamelCase classes, SCREAMING_CASE constants
  • { } for one-line blocks, do...end for multi-line
  • RuboCop (or Standard) enforces the community style guide

Typical File Structure

# frozen_string_literal: true
require "json"                  # libraries first

MAX_RETRIES = 3                 # constants

class Greeter                   # class / module definitions
  def initialize(name)
    @name = name
  end

  def greet!  = puts("Hi, #{@name}")   # endless method
  def valid?  = !@name.empty?
end

g = Greeter.new("Ada")          # script body runs top-down
g.greet! if g.valid?            # Hi, Ada
[1, 2].each { |n| puts n }      # one-line block: { }
[1, 2].each do |n|              # multi-line block: do...end
  puts n * 10
end

Code Explained

# frozen_string_literal: true — magic comment; must be the first line(s)
require — load libraries before using them
class ... end — every block construct closes with end
greet! / valid? — naming signals intent, not enforced by Ruby
def x = expr — endless method for one-liners (3.0+)

The Ruby Way

  • print("hi"); → puts "hi" (no semicolons, parens optional)
  • def isValid() → def valid?
  • Multi-line { } blocks → do ... end

⚠ Common Mistakes

  • Putting the magic comment after require; it only works at the top of the file
  • Writing { } with a do ... end meaning: puts [1].map do ... end binds the block to puts
  • Assuming ! always means "mutates"; it means "the more dangerous version" (e.g. save! raises)

✓ Tips & Best Practices

  • Run rubocop -a to auto-fix most style issues
  • Start every file with # frozen_string_literal: true; it catches accidental string mutation
  • Use ? methods that return true/false, never other values like nil or strings

Quick Summary

  • no main() — code runs top to bottom
  • end — closes class, def, if, do
  • ? / ! — predicate / dangerous variant
  • 2 spaces — conventional indentation
