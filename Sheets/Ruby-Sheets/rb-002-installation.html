Getting Ruby Installed

macOS and most Linux distros ship an old system Ruby that you should not use for projects. Install Ruby with a version manager so each project can pin its own version in a .ruby-version file and gems install without sudo.

Before You Start

  • Never sudo gem install; that writes into the system Ruby
  • Version managers compile Ruby, so install build deps first (libyaml, openssl)
  • On Windows, use RubyInstaller with the MSYS2 devkit
  • mise and asdf manage Ruby, Node, Python, etc. with one tool

Install with rbenv or mise

# macOS — Homebrew + rbenv
brew install rbenv ruby-build
rbenv init                  # adds shims to your shell
rbenv install 4.0.0
rbenv global 4.0.0          # default everywhere
rbenv local 3.4.7           # writes .ruby-version here

# mise (any OS)
mise use --global ruby@4.0
mise use ruby@3.4           # project-level (mise.toml)

# verify
ruby -v                     # ruby 4.0.0 (2025-12-25 ...)
which ruby                  # ~/.rbenv/shims/ruby
gem -v                      # RubyGems version

Code Explained

rbenv init — puts shims ahead of system Ruby on PATH
rbenv install — downloads and compiles a version
global / local — default version vs per-folder pin
mise use — same idea; writes mise.toml or .tool-versions
which ruby — confirm a shim, not /usr/bin/ruby

The Ruby Way

  • sudo gem install x → install Ruby with a version manager, then gem install x
  • Hard-coding versions in docs → commit .ruby-version
  • Mixing rvm and rbenv → pick one manager per machine

⚠ Common Mistakes

  • Running gem install with sudo on macOS; it fails on modern macOS and pollutes system Ruby
  • Forgetting to restart the shell after rbenv init, so ruby -v still shows the system version
  • Missing openssl / libyaml headers, so the compile fails or require "psych" breaks later

✓ Tips & Best Practices

  • Run rbenv rehash (or reopen the terminal) after installing gems that add executables
  • Put ruby "~> 4.0" in the Gemfile so Bundler warns when the wrong Ruby is active
  • Use rbenv install -l / mise ls-remote ruby to see installable versions

Quick Summary

  • version manager — never use system Ruby
  • .ruby-version — per-project pin
  • ruby -v / which ruby — verify the active install
  • no sudo — gems install into your user Ruby
