Polymorphism and Duck Typing

Ruby polymorphism is mostly duck typing: if an object responds to the method you call, it works, regardless of its class. Different classes implement the same method name (to_s, each, call), and callers just send the message. "Abstract" methods are a convention: define them to raise NotImplementedError.

Notes

  • No interfaces keyword; the contract is the method names
  • respond_to? checks capability when you must branch
  • Overriding in subclasses is classic polymorphism

Duck Typing in Practice

class Pdf;  def render = "PDF bytes"; end
class Html; def render = "<html>";    end
[Pdf.new, Html.new].map(&:render)   # no shared base class

def save(io, data) = io.write(data) # File, StringIO, $stdout…
save($stdout, "hi\n")

class Shape
  def area = raise(NotImplementedError, "#{self.class}#area")
end
class Square < Shape
  def initialize(s) = @s = s
  def area = @s**2
end
Square.new(3).area            # 9
Shape.new.area                # NotImplementedError

def describe(x) = x.respond_to?(:each) ? "collection" : "single"
describe([1])                 # "collection"
describe(5)                   # "single"

Code Explained

map(&:render) — no shared base class needed
io.write — any object with write is a valid io
NotImplementedError — marks an "abstract" method
respond_to?(:each) — branch on capability, not class
overriding area — subclass polymorphism

The Ruby Way

  • if obj.is_a?(File) … elsif obj.is_a?(StringIO) → just call obj.write
  • Abstract base classes with no shared code → document the duck type
  • case obj.class dispatch → define the method on each class

In Rails

  • Rails · any object with to_param can go in a URL helper
  • Rails · render @item works for any object that responds to to_partial_path

⚠ Common Mistakes

  • Type-checking everywhere with is_a?; it blocks valid duck-typed objects like StringIO
  • Raising NotImplementedError from methods meant to be overridden but forgetting subclasses must define them; add a test per subclass
  • Defining respond_to? without respond_to_missing? when using method_missing (sheet 110)

✓ Tips & Best Practices

  • Accept the narrowest interface: "anything with each" beats "an Array"
  • StringIO is the go-to fake for any code that writes to files or streams
  • Name the duck type in docs: @param io [#write]

Quick Summary

  • duck typing — call the method, don't check the class
  • respond_to? — check capability
  • NotImplementedError — abstract by convention
  • override — subclass polymorphism
