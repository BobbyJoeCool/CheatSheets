Modifiers, Ternary, Guard Clauses

Short conditions can go after a statement as modifiers: do_it if ready. The ternary cond ? a : b picks one of two values. Guard clauses return early at the top of a method so the main logic isn't nested. Ruby 4.0 also lets a line start with && or \|\| to continue the previous condition.

Notes

  • Modifiers work with if, unless, while, until, rescue
  • A modifier if returns nil when the condition is false
  • Nested ternaries are legal but hard to read
  • Leading && / \|\| line continuation is new in 4.0

Modifiers and Guards

puts "ready" if ready
save unless dirty?
retries += 1 while retries < 3

label = count == 1 ? "item" : "items"
"#{count} #{count == 1 ? 'item' : 'items'}"

def ship(order)
  return :empty   if order.items.empty?   # guard clauses
  return :blocked unless order.paid?
  raise ArgumentError, "no address" if order.address.nil?

  order.ship!                              # main path, unnested
  :shipped
end

valid = user.active?
  && user.verified?           # Ruby 4.0: leading &&
  || user.admin?

value = Integer(input) rescue 0   # rescue modifier (use sparingly)

Code Explained

puts "ready" if ready — statement first, condition after
count == 1 ? "item" : "items" — ternary returns one value
return ... if ... — guard clauses handle edge cases first
leading && — continue a condition on the next line (4.0+)
rescue 0 — inline fallback; it rescues every StandardError

The Ruby Way

  • if ready then puts "ready" end → puts "ready" if ready
  • Nested if around a method body → guard clauses at the top
  • a ? (b ? 1 : 2) : 3 → a case or if/elsif

⚠ Common Mistakes

  • Writing long statements before a modifier; readers miss the condition at the end of the line
  • Using rescue modifiers to hide real errors; it swallows every StandardError, including typos
  • Running Ruby 4.0-style leading && lines on 3.x; it's a syntax error there. Use trailing && for older versions

✓ Tips & Best Practices

  • One guard clause per edge case reads like a checklist of preconditions
  • Keep ternaries on one line with simple operands; otherwise use if
  • Prefer Integer(input, exception: false) \|\| 0 over rescue 0

Quick Summary

  • x if c — modifier condition
  • c ? a : b — ternary
  • return x if c — guard clause
  • leading && / \|\| — 4.0 line continuation
