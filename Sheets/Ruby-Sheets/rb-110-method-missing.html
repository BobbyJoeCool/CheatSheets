method_missing and Delegation

When a method isn't found, Ruby calls method_missing(name, *args, &block), which you can override to handle "ghost methods" dynamically. Always pair it with respond_to_missing? and call super for names you don't handle. For plain forwarding, Forwardable and SimpleDelegator are simpler and faster.

Notes

  • super in method_missing raises the normal NoMethodError
  • Without respond_to_missing?, respond_to? and method lie
  • Ghost methods are slower than real ones

Ghost Methods and Delegation

class Config
  def initialize(data) = @data = data
  def method_missing(name, *args)
    return @data[name] if @data.key?(name) && args.empty?
    super                                 # NoMethodError for others
  end
  def respond_to_missing?(name, priv = false) = @data.key?(name) || super
end
c = Config.new(port: 8080)
c.port                                    # 8080
c.respond_to?(:port)                      # true
c.host                                    # NoMethodError

require "forwardable"
class Stack
  extend Forwardable
  def_delegators :@items, :size, :last, :push, :pop
  def initialize = @items = []
end

require "delegate"
class Loud < SimpleDelegator
  def to_s = __getobj__.to_s.upcase       # override one, forward the rest
end

Code Explained

method_missing(name, *args) — catch unknown calls
super — fall back to NoMethodError
respond_to_missing? — keep respond_to? honest
def_delegators :@items, … — forward named methods
SimpleDelegator — wrap an object and forward everything

The Ruby Way

  • method_missing for a fixed list of names → define_method (sheet 109)
  • Hand-written forwarding methods → Forwardable
  • Decorators that copy every method → SimpleDelegator

In Rails

  • AS · delegate :name, :email, to: :user, prefix: true → user_name, user_email
  • Rails · old dynamic finders like find_by_email used method_missing; today use find_by(email:)

⚠ Common Mistakes

  • Forgetting super in method_missing; typos then silently return nil
  • Skipping respond_to_missing?; respond_to?, method(:x) and duck-typing checks break
  • Using method_missing in hot paths; every call goes through a failed lookup first

✓ Tips & Best Practices

  • Define the real method on first use (define_singleton_method) to speed up repeated ghost calls
  • SimpleDelegator is ideal for presenters and decorators around models
  • Keep the handled-name check identical in both hooks; extract it into one private method

Quick Summary

  • method_missing — handle unknown methods
  • respond_to_missing? + super — always pair them
  • Forwardable — forward named methods
  • SimpleDelegator — wrap an object
