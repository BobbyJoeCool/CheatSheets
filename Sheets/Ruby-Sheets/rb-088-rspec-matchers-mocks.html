RSpec Matchers and Mocks

Matchers describe expectations: equality (eq), truthiness (be_truthy), collections (include, contain_exactly), errors (raise_error) and changes (change { }). Test doubles stand in for collaborators: double creates a fake object, allow(...).to receive stubs a method, and expect(...).to receive verifies a call happened.

Notes

  • to / not_to flip any matcher
  • Predicate matchers: be_empty calls empty?
  • instance_double(Class) verifies stubbed methods really exist
  • Spies: have_received checks calls after the fact

Matchers and Doubles

expect(total).to eq(5.0)
expect(user).to be_admin                  # calls admin?
expect(list).to include(3)
expect(list).to contain_exactly(3, 1, 2)  # any order
expect(name).to match(/^A/)
expect(price).to be_within(0.01).of(9.99)
expect { cart.add(qty: -1) }.to raise_error(ArgumentError, /qty/)
expect { cart.add(qty: 1) }.to change { cart.count }.by(1)

mailer = instance_double(Mailer)
allow(mailer).to receive(:deliver).and_return(true)
Signup.new(mailer).call("a@b.c")
expect(mailer).to have_received(:deliver).with("a@b.c")

api = double("api", fetch: { id: 1 })     # quick fake
expect(api).to receive(:fetch).once
api.fetch
allow(Time).to receive(:now).and_return(Time.at(0))

Code Explained

be_admin — predicate matcher for admin?
contain_exactly — same elements, any order
raise_error / change { }.by — block expectations
instance_double — fake that only allows real methods
have_received — verify after the call (spy)

The Ruby Way

  • expect(x == y).to be true → expect(x).to eq(y)
  • double for real classes → instance_double (catches typos)
  • Stubbing the object under test → stub its collaborators

⚠ Common Mistakes

  • Using be when you mean eq; be checks identity, so expect("a").to be("a") fails
  • Stubbing methods that don't exist on the real class with plain double; tests pass while code is broken
  • Setting expect(...).to receive after the call; use have_received (spy style) instead

✓ Tips & Best Practices

  • Compose matchers: include(a_hash_including(id: 1))
  • aggregate_failures reports every failed expectation in one example
  • Freeze time with travel_to (Rails) or stub Time.now only at the edges

Quick Summary

  • eq / include / match — value matchers
  • raise_error / change — block matchers
  • instance_double — verified doubles
  • allow / expect … to receive — stub / verify
