Marshal and Serialization

Marshal converts almost any Ruby object to a binary string and back, preserving classes and object graphs. It's fast and convenient for caches, but the format is Ruby-only and Marshal.load on untrusted data is a security risk because it can instantiate arbitrary classes. For data that leaves your process, prefer JSON, YAML or MessagePack.

Notes

  • Procs, IO objects and singleton methods can't be marshaled
  • Format can change between major Ruby versions
  • marshal_dump / marshal_load customize what's saved
  • Struct / Data convert cleanly with to_h

Marshal and Alternatives

data = { user: "Ada", tags: [:admin], at: Time.now }
bytes = Marshal.dump(data)              # binary String
copy  = Marshal.load(bytes)             # same structure, new objects
copy[:tags]                             # [:admin] (symbols survive)


class Session
  def initialize(id, conn) = (@id, @conn = id, conn)
  def marshal_dump = [@id]              # skip the connection
  def marshal_load((id)) = @id = id
end
Marshal.load(Marshal.dump(Session.new(1, $stdout)))

Point = Data.define(:x, :y)
json = Point.new(1, 2).to_h.to_json     # '{"x":1,"y":2}'
Point.new(**JSON.parse(json, symbolize_names: true))  # round trip

require "msgpack"
MessagePack.unpack({ a: 1 }.to_msgpack) # {"a" => 1}

Code Explained

Marshal.dump / load — full Ruby object round-trip
symbols and Time survive, unlike JSON
marshal_dump / marshal_load — save only some state
to_h + JSON — portable round-trip for value objects

The Ruby Way

  • Marshal.load(params[:data]) → JSON with explicit fields
  • Marshal as a deep copy for objects with IO → initialize_copy
  • Custom string formats → JSON or MessagePack

In Rails

  • Rails · serialize :prefs, coder: JSON stores a column as JSON
  • Rails · ActiveJob serializes arguments; pass ids or simple values, not whole objects

⚠ Common Mistakes

  • Calling Marshal.load on cookies, uploads or network data; it can lead to remote code execution
  • Caching marshaled objects across Ruby upgrades and failing to load them later
  • Marshaling objects that hold procs or IO; it raises TypeError: no _dump_data is defined

✓ Tips & Best Practices

  • Version your cache keys so a format change just misses the cache
  • For APIs and storage, define to_h and rebuild with new(**hash)
  • Marshal.load(bytes, freeze: true) returns deeply frozen objects

Quick Summary

  • Marshal.dump / load — Ruby object serialization
  • never load untrusted Marshal data
  • marshal_dump / marshal_load — customize
  • JSON / MessagePack — portable formats
