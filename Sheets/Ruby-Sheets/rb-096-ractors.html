Ractors

Ractors (Ruby 3.0+) run Ruby code in true parallel, each with its own GVL. They share almost nothing: objects pass between Ractors by copying or moving, and only shareable (deeply frozen) objects can be read from several Ractors. Ruby 4.0 replaces Ractor.yield / take with Ractor::Port for communication.

Ractor Notes

  • Still marked experimental; Ruby warns on first use
  • Many gems aren't Ractor-safe (global state, C extensions)
  • Ractor.make_shareable deep-freezes an object
  • Ruby 4.0: Ractor#join / #value and Ractor::Port replace take / yield

Ractor Basics (Ruby 4.0)

def fib(n) = n < 2 ? n : fib(n - 1) + fib(n - 2)

rs = 4.times.map { |i| Ractor.new(30 + i) { |n| fib(n) } }
rs.map(&:value)                 # computed in parallel

port = Ractor::Port.new
worker = Ractor.new(port) do |out|
  while (msg = Ractor.receive) != :stop
    out << msg.upcase           # send results back
  end
end
worker << "a"                   # Ractor#send
worker << "b"
port.receive                    # "A"
port.receive                    # "B"
worker << :stop
worker.join

CONFIG = Ractor.make_shareable({ level: 3 })
Ractor.new { CONFIG[:level] }.value   # 3 (shareable constant)

Code Explained

Ractor.new(arg) { |n| } — pass arguments in (copied)
value — wait for the Ractor's final result
Ractor::Port — a channel others can send to
Ractor.receive / << — the Ractor's own inbox
make_shareable — deep-freeze so any Ractor can read it

The Ruby Way

  • Threads for CPU-bound math → Ractors (or processes)
  • Mutable globals read inside Ractors → shareable constants
  • Ractor.yield / take (3.x) → Ractor::Port (4.0)

Sharing Rules

⚠ Common Mistakes

  • Accessing non-shareable constants or globals inside a Ractor; it raises Ractor::IsolationError
  • Using 3.x Ractor.yield / take code on 4.0; switch to ports and value
  • Assuming every gem works inside Ractors; check before relying on them in production

✓ Tips & Best Practices

  • Start with pure functions on plain data; that's where Ractors work best today
  • Pass move: true to send to transfer large objects without copying
  • Benchmark against processes (fork, parallel gem); they're often simpler for CPU work

Quick Summary

  • Ractor.new — parallel execution
  • Ractor::Port — 4.0 message channels
  • value / join — get results
  • shareable objects — deeply frozen data
