Modules as Mixins

A module groups methods that can be mixed into classes. include adds the module's methods as instance methods, extend adds them as methods on a single object (often the class, giving class methods), and prepend inserts the module before the class so it can wrap existing methods with super.

Mixin Facts

  • A class can include any number of modules
  • Included modules appear in ancestors after the class
  • Prepended modules appear before the class
  • Comparable and Enumerable are core mixins

include, extend, prepend

module Greet
  def greet = "Hi, I'm #{name}"
end
module Loud
  def greet = super.upcase + "!"   # wraps the original
end
module Registry
  def all = @all ||= []
end

class Person
  include Greet                    # instance methods
  prepend Loud                     # runs before Person#greet
  extend Registry                  # class methods
  attr_reader :name
  def initialize(name) = (@name = name; self.class.all << self)
end

Person.new("Ada").greet            # "HI, I'M ADA!"
Person.all.size                    # 1
Person.ancestors.take(3)           # [Loud, Person, Greet]

Code Explained

include Greet — greet becomes an instance method
prepend Loud — Loud#greet runs first and calls super
extend Registry — Person.all becomes a class method
ancestors — prepend before, include after the class

The Ruby Way

  • Copying the same methods into several classes → a module + include
  • alias_method chains to wrap methods → prepend with super
  • A class only used to hold helper methods → a module

In Rails

  • AS · ActiveSupport::Concern adds included do … end and class_methods do … end
  • Rails · concerns live in app/models/concerns and are included like any module

⚠ Common Mistakes

  • Using include and expecting class methods; use extend (or a self.included hook)
  • Two modules defining the same method; the last one included wins, silently
  • Mixing in modules that depend on methods the class doesn't define; document the contract (e.g. "requires each")

✓ Tips & Best Practices

  • Implement <=> and include Comparable; implement each and include Enumerable
  • The self.included(base) hook lets a module run setup or base.extend(ClassMethods)
  • Keep modules focused on one behavior; name them as adjectives (Comparable, Printable)

Quick Summary

  • include — instance methods
  • extend — class/object methods
  • prepend — wrap with super
  • Comparable / Enumerable — core mixins
