Variable Scope

Ruby has scope gates: def, class and module each start a fresh local scope, so a method cannot see local variables from outside it. Blocks are different: they see and can change the locals around them, which is what makes closures work. Instance variables belong to self, constants are looked up lexically, and globals are visible everywhere.

Scope Rules

  • def can't read outer locals (use args or @ivars)
  • Blocks read and write surrounding locals
  • Block params and |x; y| block-locals shadow outer names
  • define_method with a block crosses the def gate

Scope Gates and Blocks

x = 10
def show_x
  x                       # NameError: undefined local variable
end

def show_ivar = @name     # instance variables live on self
@name = "top"
show_ivar                 # "top" (same self at top level)

total = 0
[1, 2, 3].each { |n| total += n }
total                     # 6 — block changed outer local

y = 1
[5].each { |y| y += 1 }   # block param shadows outer y
y                         # 1
z = 1
[5].each { |n; z| z = n } # z is block-local
z                         # 1

LIMIT = 3
def under_limit?(n) = n < LIMIT   # constants pass scope gates

Code Explained

def show_x — new scope; outer x isn't visible
@name — belongs to self, not to a scope
total += n — blocks share outer locals
|n; z| — declare a block-local variable
LIMIT — constants are visible inside methods

The Ruby Way

  • $counter to share state between methods → an instance variable or object
  • Reading outer locals in def → pass them as arguments
  • Reusing outer names as block params → choose distinct names

⚠ Common Mistakes

  • Expecting a top-level local to be visible in a method; Ruby isn't JavaScript or Python here
  • Accidentally overwriting an outer local inside a block because names collide
  • Treating @ivar at top level as global state; it belongs to the main object and gets confusing fast

✓ Tips & Best Practices

  • Pass data into methods explicitly; it keeps them testable and reusable
  • Use define_method or Class.new when you deliberately need a closure over locals (sheet 047)
  • binding.local_variables shows what's in scope while debugging

Quick Summary

  • def / class / module — scope gates
  • blocks — see outer locals
  • @ivar — tied to self
  • |x; y| — block-local variable
