Databases

Ruby talks to databases through driver gems: sqlite3 for SQLite, pg for PostgreSQL, mysql2 for MySQL. Always use placeholders (? or $1) for values to avoid SQL injection. Sequel is a lightweight toolkit with a query DSL, and ActiveRecord (Rails' ORM) also works standalone.

Notes

  • gem "sqlite3" / gem "pg" in your Gemfile
  • results_as_hash = true returns rows as hashes
  • Wrap related writes in a transaction
  • Close connections (or use a connection pool)

sqlite3 and Sequel

require "sqlite3"
db = SQLite3::Database.new("app.db")
db.results_as_hash = true
db.execute <<~SQL
  CREATE TABLE IF NOT EXISTS users
    (id INTEGER PRIMARY KEY, name TEXT, age INT)
SQL
db.execute("INSERT INTO users (name, age) VALUES (?, ?)", ["Ada", 36])
db.execute("SELECT * FROM users WHERE age > ?", [30]).each do |row|
  puts row["name"]                       # Ada
end
db.transaction do
  db.execute("UPDATE users SET age = age + 1 WHERE name = ?", ["Ada"])
end

require "sequel"
DB = Sequel.sqlite("app.db")
DB[:users].where { age > 30 }.order(:name).select_map(:name)  # ["Ada"]
DB[:users].insert(name: "Lin", age: 41)
DB[:users].where(name: "Lin").update(age: 42)

Code Explained

SQLite3::Database.new — open (or create) a database file
results_as_hash — rows as {"name" => …}
execute(sql, [values]) — placeholders keep values safe
transaction do — all-or-nothing writes
Sequel DB[:users].where { } — composable query DSL

The Ruby Way

  • "... WHERE name = '#{name}'" → placeholders: "name = ?", [name]
  • Hand-written SQL strings for every query → Sequel datasets
  • Opening a connection per query → one connection or a pool

In Rails

  • Rails · User.where("age > ?", 30) and User.find_by(name:) (see a Rails set for the full ORM)
  • Rails · migrations (bin/rails g migration) manage schema instead of CREATE TABLE

⚠ Common Mistakes

  • Interpolating user input into SQL; that's SQL injection. Always use placeholders
  • Forgetting results_as_hash and indexing rows by position after the schema changes
  • Running many inserts without a transaction; each commits separately and is slow

✓ Tips & Best Practices

  • db.execute_batch(sql) runs a multi-statement script
  • Sequel's DB.loggers << Logger.new($stdout) prints every query
  • Use SQLite's :memory: database for fast tests

Quick Summary

  • driver gems — sqlite3, pg, mysql2
  • placeholders — never interpolate values
  • transaction — atomic writes
  • Sequel / ActiveRecord — higher-level access
