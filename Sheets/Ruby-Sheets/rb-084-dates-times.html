Standard Library: Dates and Times

Time (core) represents a moment with date, time and UTC offset. Date (require "date") represents calendar days without a time. Arithmetic on Time uses seconds, on Date uses days; strftime formats both, and Time.parse / Date.parse / iso8601 read strings.

Notes

  • Time.now uses the system time zone; Time.now.utc for UTC
  • Subtracting two Times gives seconds as a Float
  • Date.today + 1 is tomorrow
  • require "time" adds Time.parse and Time#iso8601

Time and Date

now = Time.now                    # 2026-10-17 14:05:09 -0500
now.year / now.month / now.day    # 2026 / 10 / 17
now + 3600                        # one hour later
(Time.now - now).round(2)         # elapsed seconds
now.strftime("%Y-%m-%d %H:%M")    # "2026-10-17 14:05"
now.strftime("%b %-d, %Y")        # "Oct 17, 2026"
Time.at(0).utc                    # 1970-01-01 00:00:00 UTC
now.to_i                          # Unix timestamp

require "time"
Time.parse("2026-10-17 09:30")    # local time
Time.iso8601("2026-10-17T09:30:00Z")
now.utc.iso8601                   # "2026-10-17T19:05:09Z"

require "date"
d = Date.new(2026, 12, 25)
(d - Date.today).to_i             # days until Christmas
d.saturday?                       # false (it's a Friday)
d >> 1                            # 2027-01-25 (add a month)
Date.parse("Oct 17 2026").yday    # 290

Code Explained

now + 3600 — Time math is in seconds
strftime — format with %Y, %m, %d, %H, %M
Time.at(0) — from a Unix timestamp
iso8601 — standard machine-readable format
Date - Date — a Rational number of days

The Ruby Way

  • Time.now.to_s for logs or APIs → Time.now.utc.iso8601
  • t + 86400 * 30 for "a month" → Date#>> (calendar aware)
  • Parsing with Date.parse for user input → Date.strptime(s, "%m/%d/%Y")

In Rails

  • AS · Time.zone.now / Time.current respect the app's configured zone
  • AS · 2.days.ago, 1.week.from_now, beginning_of_day, end_of_month
  • AS · Date.current instead of Date.today in Rails apps

⚠ Common Mistakes

  • Storing local times without offsets and getting DST bugs; store UTC and convert for display
  • Adding 86400 seconds for "tomorrow" across a DST change; use Date + 1
  • Using Date.parse on ambiguous strings like "01/02/03"; use strptime with a format

✓ Tips & Best Practices

  • Measure durations with the monotonic clock (Process::CLOCK_MONOTONIC), not Time.now
  • Time#round / floor(2) trim fractional seconds
  • DateTime is deprecated in practice; use Time for moments and Date for days

Quick Summary

  • Time.now / Time.at — moments
  • Date.new / Date.today — calendar days
  • strftime — format
  • iso8601 / strptime — parse
