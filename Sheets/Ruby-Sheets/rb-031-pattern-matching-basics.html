Pattern Matching Basics

case/in matches the shape of data and binds variables in one step. Array patterns check length and elements, hash patterns check keys, and plain values or classes are compared with ===. Unlike case/when, a case/in with no matching branch and no else raises NoMatchingPatternError.

Basics

  • Hash patterns match symbol keys and ignore extra keys
  • Array patterns must match the whole length (use *rest for more)
  • Bare names bind values: in [x, y]
  • => (rightward assignment) destructures or raises

case / in

def describe(data)
  case data
  in []                   then "empty"
  in [Integer => a, Integer => b] then "pair #{a + b}"
  in [first, *rest]       then "#{first} +#{rest.size}"
  in { type: "user", name: String => name } then "user #{name}"
  in { status: 200 | 201 } then "ok"
  in nil                  then "nil"
  end
end
describe([1, 2])                 # "pair 3"
describe(["a", 2, 3])            # "a +2"
describe({ type: "user", name: "Ada", id: 1 })  # "user Ada"
describe("?")                    # NoMatchingPatternError

config = { db: { host: "localhost", port: 5432 } }
config => { db: { host:, port: } }   # binds host, port
port                                 # 5432

Code Explained

Integer => a — check with ===, then bind to a
[first, *rest] — any length ≥ 1
{ type: "user" } — key must exist and match; extra keys OK
host: — shorthand binds the value to a local named host

The Ruby Way

  • if h[:type] == "user" && h[:name].is_a?(String) → in { type: "user", name: String }
  • a = arr[0]; b = arr[1] checks → case arr in [a, b]
  • h.dig(:db, :host) plus nil checks → h => { db: { host: } }

⚠ Common Mistakes

  • Expecting string-keyed hashes to match { name: }; hash patterns only match symbol keys. Use JSON.parse(s, symbolize_names: true)
  • Forgetting else and getting NoMatchingPatternError in production
  • Writing in x as a catch-all early; a bare name matches everything, so later branches never run

✓ Tips & Best Practices

  • Use case/in for JSON-like data, API responses, and tuples; keep case/when for simple values
  • **nil in a hash pattern requires no other keys: in { id:, **nil }
  • in [Integer, Integer] => pair binds the whole match as well as checking it

Quick Summary

  • case x in pattern — match shape + bind
  • [a, *rest] — array pattern
  • { key: } — hash pattern + binding
  • => — destructure or raise
