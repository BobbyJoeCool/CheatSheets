Sheet 13

Dynamic & Repeated Tests

@TestFactory · DynamicTest.dynamicTest · DynamicContainer · @RepeatedTest · RepetitionInfo · failureThreshold

Tests Built at Run Time, Tests Run Many Times

A @TestFactory method returns a stream or collection of DynamicTest objects, so tests can be generated from data found at run time (files in a folder, rows from a service). DynamicContainer groups them into a tree. @RepeatedTest runs the same test N times, which helps find flaky behavior.

Notes

  • Dynamic tests don't get @BeforeEach / @AfterEach per dynamic test, only per factory
  • Each dynamic test has a display name and an Executable
  • failureThreshold stops repeating after N failures
  • RepetitionInfo gives the current repetition number

Factories and Repetition

import static org.junit.jupiter.api.DynamicTest.dynamicTest;
import static org.junit.jupiter.api.DynamicContainer.dynamicContainer;

@TestFactory
Stream<DynamicTest> everyFixtureFileParses() throws IOException {
    return Files.list(Path.of("src/test/resources/orders"))
        .map(path -> dynamicTest(path.getFileName().toString(),
                                 () -> assertNotNull(OrderParser.parse(path))));
}

@TestFactory
Stream<DynamicContainer> perCountry() {
    return Stream.of("US", "DE").map(c -> dynamicContainer(c, Stream.of(
        dynamicTest("has a rate", () -> assertTrue(Tax.rate(c) > 0)),
        dynamicTest("formats money", () -> assertNotNull(Money.format(1, c))))));
}

@RepeatedTest(value = 50, failureThreshold = 1,
              name = "{displayName} {currentRepetition}/{totalRepetitions}")
void idsAreUnique(RepetitionInfo info) {
    assertNotEquals(IdGen.next(), IdGen.next());
}

Code Explained

File names become test names in the report
Containers show as folders in the IDE test tree
failureThreshold = 1 stops after the first failure, saving time on a flake hunt
The repetition placeholders build readable names

JUnit 4 / TestNG Equivalent

  • JUnit 4 No dynamic tests; use the Parameterized runner with computed parameters; no @RepeatedTest (loop or rule)
  • TestNG @Factory creates test class instances; invocationCount = 50 repeats

Prefer / Avoid

  • a loop of asserts over files → @TestFactory with one dynamic test per file
  • fixed cases known at compile time → @ParameterizedTest
  • rerunning a flaky test by hand → @RepeatedTest with failureThreshold

⚠ Common Mistakes

  • Expecting @BeforeEach to run before every dynamic test
  • Dynamic tests whose names collide, making reports confusing
  • Repeating slow tests 1000 times in the normal suite

✓ Tips & Best Practices

  • Use dynamic tests for data discovered at run time; parameterized tests for fixed data
  • Tag repeated flake hunts so they don't run in CI
  • Give dynamic tests names that identify the input

Quick Summary

  • @TestFactory — tests at run time
  • dynamicContainer — grouped
  • @RepeatedTest — run N times
  • failureThreshold — stop early
