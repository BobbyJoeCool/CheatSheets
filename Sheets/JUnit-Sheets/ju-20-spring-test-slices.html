Sheet 20

Spring Test Slices

@WebMvcTest · MockMvc / MockMvcTester · @DataJpaTest · @JsonTest · @RestClientTest · @WebFluxTest

Start Only the Layer You're Testing

A test slice starts a small part of the context: @WebMvcTest loads controllers and MVC config with MockMvc / MockMvcTester, @DataJpaTest loads JPA repositories with a test database, @JsonTest loads JSON mapping, @RestClientTest loads HTTP clients with a mock server. Slices start much faster than @SpringBootTest and keep tests focused.

Notes

  • Beans outside the slice must be mocked with @MockitoBean
  • @DataJpaTest runs each test in a rolled-back transaction
  • MockMvcTester (Spring 6.2+) gives AssertJ-style checks
  • Boot 4 moved slice annotations into per-technology modules; check imports

A Controller Slice and a JPA Slice

@WebMvcTest(OrderController.class)
class OrderControllerTest {
    @Autowired MockMvcTester mvc;
    @MockitoBean OrderService service;

    @Test
    void returnsOrder() {
        given(service.get(1L)).willReturn(new OrderDto(1L, "PAID"));
        assertThat(mvc.get().uri("/orders/1"))
            .hasStatusOk()
            .bodyJson().extractingPath("$.status").isEqualTo("PAID");
    }

    @Test
    void validatesInput() {
        assertThat(mvc.post().uri("/orders")
                      .contentType(MediaType.APPLICATION_JSON).content("{}"))
            .hasStatus(HttpStatus.BAD_REQUEST);
    }
}

@DataJpaTest
class OrderRepositoryTest {
    @Autowired OrderRepository repo;
    @Autowired TestEntityManager em;

    @Test
    void findsPaidOrders() {
        em.persist(new Order(OrderStatus.PAID));
        em.persist(new Order(OrderStatus.NEW));
        assertThat(repo.findByStatus(OrderStatus.PAID)).hasSize(1);
    }
}

Code Explained

@WebMvcTest(OrderController.class) loads just that controller plus MVC infrastructure
The service is mocked because services aren't part of the web slice
bodyJson().extractingPath(...) reads a JSON path from the response
TestEntityManager sets up data; each test rolls back

JUnit 4 / TestNG Equivalent

  • JUnit 4 Same slices with @RunWith(SpringRunner.class)
  • TestNG Same slices with AbstractTestNGSpringContextTests

Prefer / Avoid

  • @SpringBootTest + MockMvc for controller tests → @WebMvcTest
  • in-memory H2 for @DataJpaTest when prod is Postgres → Testcontainers (sheet 21)
  • classic MockMvc.perform(...).andExpect(...) → MockMvcTester with AssertJ

⚠ Common Mistakes

  • Expecting services to be injected in @WebMvcTest without mocking them
  • @DataJpaTest against H2 hiding Postgres-specific SQL bugs
  • Pulling the whole app into a slice with @Import of large configs

✓ Tips & Best Practices

  • Write most web tests as @WebMvcTest and a few as full @SpringBootTest
  • Use @AutoConfigureTestDatabase(replace = NONE) with Testcontainers in @DataJpaTest
  • Keep controllers thin so slice tests stay simple

Quick Summary

  • slice — one layer of the context
  • @WebMvcTest + MockMvcTester
  • @DataJpaTest — repositories, rolled back
  • mock everything outside the slice
