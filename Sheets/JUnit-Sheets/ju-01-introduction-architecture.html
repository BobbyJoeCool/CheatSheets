A Platform, an API and Engines

JUnit is the standard test framework for Java. Since JUnit 5 it is split in three: the Platform launches tests and talks to IDEs and build tools, Jupiter is the API you write tests with (@Test, Assertions), and Vintage runs old JUnit 4 tests. Other engines (Spock, Cucumber, Kotest) plug into the same Platform. JUnit 6 keeps the Jupiter API, raises the baseline to Java 17 and gives every module one version number.

Notes

  • Imports: org.junit.jupiter.api.*
  • Test classes and methods can be package-private
  • JUnit 6 deprecates the Vintage engine; migrate JUnit 4 tests (sheet 22)
  • Most JUnit 5 tests run unchanged on JUnit 6

First Test Class

// src/main/java/shop/Cart.java
public class Cart {
    private final Map<String, Integer> items = new HashMap<>();
    public void add(String sku, int qty) {
        if (qty <= 0) throw new IllegalArgumentException("qty must be > 0");
        items.merge(sku, qty, Integer::sum);
    }
    public int count(String sku) { return items.getOrDefault(sku, 0); }
}

// src/test/java/shop/CartTest.java
import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.*;

class CartTest {
    @Test
    void addsNewItem() {
        Cart cart = new Cart();
        cart.add("A1", 2);
        assertEquals(2, cart.count("A1"));
    }

    @Test
    void rejectsZeroQuantity() {
        assertThrows(IllegalArgumentException.class, () -> new Cart().add("A1", 0));
    }
}

Code Explained

Tests live in src/test/java in the same package as the class they test
@Test marks a test method; it returns void and takes no arguments (unless resolved, sheet 14)
assertEquals(expected, actual) puts the expected value first
A new instance of CartTest is created for each test method

JUnit 4 / TestNG Equivalent

  • JUnit 4 org.junit.Test on public methods in a public class; org.junit.Assert.*
  • TestNG org.testng.annotations.Test; Assert.assertEquals(actual, expected) (actual first!)

Prefer / Avoid

  • public class / public void tests → package-private (less noise)
  • System.out.println checks → assertions
  • one test per class method → one test per behavior

⚠ Common Mistakes

  • Mixing org.junit.Test (JUnit 4) and org.junit.jupiter.api.Test imports; the wrong one runs on the wrong engine or not at all
  • Swapping expected and actual in assertEquals, which makes failure messages misleading
  • Sharing state in instance fields expecting it to survive between tests

✓ Tips & Best Practices

  • Let the IDE generate the test class (⇧⌘T / Ctrl+Shift+T in IntelliJ)
  • Name methods after behavior: rejectsZeroQuantity
  • Check imports first when a test "doesn't run"

Quick Summary

  • Jupiter — @Test, Assertions
  • Vintage — JUnit 4 (deprecated in 6)
  • JUnit 6 — Java 17+, one version
