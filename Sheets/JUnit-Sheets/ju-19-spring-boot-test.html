Spring Boot Test Basics

@SpringBootTest · webEnvironment · @MockitoBean · @TestConfiguration · @ActiveProfiles · context caching

Test With the Whole Application Context

@SpringBootTest starts your Spring Boot application context for a test class, so beans are real and wired together. With webEnvironment = RANDOM_PORT it starts a real server too. @MockitoBean swaps one bean for a mock, @TestConfiguration adds test-only beans, and @ActiveProfiles picks configuration. Contexts are cached between classes with identical setup, so keep setups consistent. The Spring set covers the app side.

Notes

  • @MockBean was deprecated in Boot 3.4 and removed in Boot 4; use @MockitoBean
  • Each distinct context configuration costs a full start-up
  • Use slices (sheet 20) when you only need one layer
  • Test properties: @SpringBootTest(properties = "feature.x=true")

Full-Context Tests

@SpringBootTest
@ActiveProfiles("test")
class CheckoutFlowTest {
    @Autowired CheckoutService checkout;
    @MockitoBean PaymentGateway gateway;          // replaces the real bean

    @Test
    void chargesAndStoresOrder() {
        given(gateway.charge(any())).willReturn(new Receipt("r1"));
        Order o = checkout.pay(sampleCart());
        assertThat(o.status()).isEqualTo(OrderStatus.PAID);
    }
}

@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)
class HealthEndpointTest {
    @Autowired WebTestClient client;              // or TestRestTemplate

    @Test
    void healthIsUp() {
        client.get().uri("/actuator/health").exchange()
              .expectStatus().isOk()
              .expectBody().jsonPath("$.status").isEqualTo("UP");
    }
}

@TestConfiguration
class FixedClockConfig {
    @Bean Clock clock() { return Clock.fixed(Instant.parse("2026-11-04T00:00:00Z"), ZoneOffset.UTC); }
}

Code Explained

@MockitoBean mocks are reset after each test
RANDOM_PORT starts a real embedded server on a free port
@TestConfiguration beans are added only when imported or found as nested classes
Every class with the same annotations reuses one cached context

JUnit 4 / TestNG Equivalent

  • JUnit 4 @RunWith(SpringRunner.class) + @SpringBootTest; @MockBean
  • TestNG AbstractTestNGSpringContextTests base class + @SpringBootTest

Prefer / Avoid

  • @MockBean → @MockitoBean
  • @SpringBootTest for a controller test → @WebMvcTest slice
  • @DirtiesContext everywhere → reset state explicitly, keep the cache

Common Annotations

AnnotationEffect
@MockitoBeanReplace bean with a mock
@MockitoSpyBeanWrap a real bean
@TestConfigurationExtra test beans
@ActiveProfiles("test")Profile
@DynamicPropertySourceProperties computed at run time
@DirtiesContextDrop cached context (slow)

⚠ Common Mistakes

  • Slightly different @MockitoBean sets per class, each forcing a new context
  • Using @SpringBootTest for every test and making the suite take minutes
  • Tests that change shared beans and break later classes using the cached context

✓ Tips & Best Practices

  • Keep a few standard test base annotations so contexts are reused
  • Use slices or plain unit tests for most cases
  • Watch the log for "Started … in N seconds" to count context starts

Quick Summary

  • @SpringBootTest — whole context
  • @MockitoBean — replace a bean
  • RANDOM_PORT — real server
  • context caching — keep setups identical
