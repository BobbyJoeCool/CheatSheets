Sheet 02

Setup with Maven & Gradle

junit-bom · junit-jupiter · Surefire · useJUnitPlatform() · junit-platform-launcher · test source folders

Add JUnit to the Build

Import the junit-bom so every JUnit module has the same version, then depend on junit-jupiter (API, params and engine in one) in test scope. Maven's Surefire plugin (3.x) finds the JUnit Platform automatically; Gradle needs useJUnitPlatform() and the junit-platform-launcher on the test runtime classpath. The Maven and Gradle sets cover the build tools.

Notes

  • Spring Boot's starter already brings JUnit; don't add versions by hand
  • Add assertj-core and mockito-junit-jupiter the same way
  • Failsafe runs *IT.java integration tests in Maven's verify phase
  • Test sources: src/test/java, resources: src/test/resources

In Spring Boot

  • spring-boot-starter-test includes JUnit Jupiter, AssertJ, Mockito, Hamcrest and JSONassert
  • Boot's dependency management picks the JUnit version; override with the junit-jupiter.version property only if needed

pom.xml and build.gradle.kts

<!-- pom.xml -->
<dependencyManagement>
  <dependencies>
    <dependency>
      <groupId>org.junit</groupId>
      <artifactId>junit-bom</artifactId>
      <version>6.1.1</version>
      <type>pom</type><scope>import</scope>
    </dependency>
  </dependencies>
</dependencyManagement>
<dependencies>
  <dependency>
    <groupId>org.junit.jupiter</groupId>
    <artifactId>junit-jupiter</artifactId>
    <scope>test</scope>
  </dependency>
</dependencies>
<!-- Surefire 3.x detects the JUnit Platform -->

// build.gradle.kts
dependencies {
    testImplementation(platform("org.junit:junit-bom:6.1.1"))
    testImplementation("org.junit.jupiter:junit-jupiter")
    testRuntimeOnly("org.junit.platform:junit-platform-launcher")
}
tasks.test { useJUnitPlatform() }

Code Explained

The BOM sets one version; individual JUnit dependencies then omit <version>
junit-jupiter is an aggregate of the API, -params and -engine artifacts
Gradle runs nothing until useJUnitPlatform() is set
Gradle versions 9+ want the launcher declared explicitly

JUnit 4 / TestNG Equivalent

  • JUnit 4 junit:junit:4.13.2 dependency; Surefire uses its JUnit 4 provider
  • TestNG org.testng:testng dependency; Gradle useTestNG()

Prefer / Avoid

  • hard-coded versions on each JUnit artifact → the BOM
  • old Surefire 2.x → Surefire 3.x
  • separate -api + -engine dependencies → junit-jupiter

⚠ Common Mistakes

  • Forgetting useJUnitPlatform() in Gradle; the build passes with zero tests run
  • Mixing BOM and explicit versions so modules drift apart
  • Adding JUnit versions manually in a Spring Boot project and fighting Boot's managed versions

✓ Tips & Best Practices

  • Check the test count in build output after setup; zero means misconfiguration
  • Use Failsafe (Maven) or a separate Gradle source set for slow integration tests
  • Let Spring Boot manage test library versions

Quick Summary

  • junit-bom — one version
  • junit-jupiter — everything you need
  • Surefire 3 — auto-detects
  • useJUnitPlatform() — required in Gradle
