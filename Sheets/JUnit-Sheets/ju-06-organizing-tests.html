Sheet 06

Nested, Tagged & Ordered Tests

@Nested · @Tag · @Disabled · @TestMethodOrder · @Order · @Suite · tag filtering in Maven / Gradle

Group, Label and Select

@Nested inner classes group tests by situation ("when empty", "after adding an item"), each with its own setup that builds on the outer class. @Tag labels tests so builds can include or exclude them (fast, integration). @Disabled skips with a reason. @TestMethodOrder fixes an order when you truly need one, and @Suite groups classes into a named run.

Notes

  • @Nested classes must be non-static inner classes
  • Outer @BeforeEach runs before inner @BeforeEach
  • Tag expressions: fast & !slow, integration | e2e
  • @Suite needs junit-platform-suite

In Spring Boot

  • @Nested test classes reuse the outer class's @SpringBootTest configuration and context
  • @ActiveProfiles on an inner class can switch profiles for that group

Nested and Tagged

@DisplayName("Cart")
class CartTest {
    Cart cart;

    @BeforeEach void newCart() { cart = new Cart(); }

    @Nested
    class WhenEmpty {
        @Test void totalIsZero() { assertEquals(0, cart.total()); }
    }

    @Nested
    class AfterAddingAnItem {
        @BeforeEach void addOne() { cart.add("A1", 1, 5.00); }

        @Test void countIsOne() { assertEquals(1, cart.size()); }
        @Test @Tag("slow") void syncsToServer() { /* … */ }
    }

    @Test
    @Disabled("flaky until #142 is fixed")
    void legacyPricing() { }
}

@Suite
@SelectPackages("shop.checkout")
@IncludeTags("integration")
class CheckoutIntegrationSuite { }

// Maven:  mvn test -Dgroups="fast & !slow"
// Gradle: tasks.test { useJUnitPlatform { includeTags("fast"); excludeTags("slow") } }

Code Explained

Each @Nested class reads like a scenario in the report
AfterAddingAnItem gets newCart() then addOne() before each test
@Disabled always takes a reason
A @Suite class selects tests by package, class or tag

JUnit 4 / TestNG Equivalent

  • JUnit 4 No @Nested (use Enclosed runner); @Category for tags; @Ignore; @FixMethodOrder; @RunWith(Suite.class)
  • TestNG @Test(groups = "fast"), enabled = false, priority / dependsOnMethods, testng.xml suites

Prefer / Avoid

  • long test classes with name prefixes → @Nested groups
  • commented-out tests → @Disabled("reason + issue")
  • tests that depend on order → independent tests (use @Order only for genuine sequences)

Annotations

AnnotationEffect
@NestedInner class group
@Tag("x")Label for filtering
@Disabled("why")Skip
@TestMethodOrder(…)Method order
@Order(n)Position with OrderAnnotation
@Suite + @Select…Named group of tests

Tag Expressions

ExpressionSelects
fastTagged fast
!slowNot slow
fast & !slowBoth conditions
integration | e2eEither
(a | b) & !cGrouped

⚠ Common Mistakes

  • Making @Nested classes static; they won't be discovered
  • Using @Order to make tests depend on each other
  • @Disabled tests piling up with no issue link

✓ Tips & Best Practices

  • Use constants for tag names to avoid typos
  • Run fast tests locally and everything in CI
  • Review @Disabled tests regularly

Quick Summary

  • @Nested — scenario groups
  • @Tag + build filters — select
  • @Disabled("why") — skip
  • @Suite — named group
