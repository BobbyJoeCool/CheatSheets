Mockito Basics

MockitoExtension · @Mock · @InjectMocks · when(…).thenReturn · verify · any() / eq() · times() / never()

Fake Collaborators, Check Interactions

Mockito creates mocks: objects that implement a class or interface, return defaults (null, 0, empty) until stubbed, and record every call. With MockitoExtension, @Mock fields are created for each test and @InjectMocks builds the class under test with them. Stub with when(...).thenReturn(...) and check calls with verify.

Notes

  • Add mockito-junit-jupiter (Spring Boot includes it)
  • Mockito 5 uses the inline mock maker: final classes and methods can be mocked
  • Strict stubs: unused stubbing fails the test (UnnecessaryStubbingException)
  • If you use one matcher, every argument needs a matcher

In Spring Boot

  • @MockitoBean replaces a bean in the Spring context with a Mockito mock; @Mock only creates a plain mock
  • Use plain @Mock + @InjectMocks for unit tests; it's much faster than starting Spring

A Service Test With Mocks

import static org.mockito.Mockito.*;
import static org.mockito.ArgumentMatchers.*;

@ExtendWith(MockitoExtension.class)
class OrderServiceTest {
    @Mock OrderRepository repo;
    @Mock Mailer mailer;
    @InjectMocks OrderService service;      // new OrderService(repo, mailer)

    @Test
    void placesOrderAndSendsMail() {
        when(repo.save(any(Order.class))).thenAnswer(inv -> inv.getArgument(0));

        Order o = service.place(new Cart("ann@example.com"));

        assertEquals(OrderStatus.NEW, o.status());
        verify(repo).save(o);
        verify(mailer).send(eq("ann@example.com"), contains("Order"));
        verifyNoMoreInteractions(mailer);
    }

    @Test
    void unknownOrder() {
        when(repo.findById(99L)).thenReturn(Optional.empty());
        assertThrows(OrderNotFoundException.class, () -> service.get(99L));
        verify(mailer, never()).send(any(), any());
    }
}

Code Explained

@InjectMocks uses constructor injection when it can
thenAnswer returns the saved order itself, like a real repository would
verify(repo).save(o) checks the call happened once with that argument
never() asserts no email was sent

JUnit 4 / TestNG Equivalent

  • JUnit 4 @RunWith(MockitoJUnitRunner.class) or MockitoJUnit.rule()
  • TestNG MockitoAnnotations.openMocks(this) in @BeforeMethod, or MockitoTestNGListener

Prefer / Avoid

  • Mockito.mock() in every test → @Mock fields + extension
  • mocking value objects and DTOs → real instances
  • verifying every call → verify only the interactions that matter

Stubbing

CallEffect
when(m.x()).thenReturn(v)Return v
…thenReturn(a, b)a, then b
…thenThrow(new E())Throw
…thenAnswer(inv -> …)Compute
doReturn(v).when(m).x()Stub spies / void-safe

Verifying

CallChecks
verify(m).x()Called once
verify(m, times(2)).x()Twice
verify(m, never()).x()Never
verify(m, atLeastOnce()).x()≥ 1
verifyNoMoreInteractions(m)Nothing else
any() / eq(v) / argThat(p)Argument matchers

⚠ Common Mistakes

  • Mixing raw values and matchers: verify(m).send("a", any()) throws; use eq("a")
  • Stubbing things the test never uses (strict stubs fail it)
  • Mocking the class under test

✓ Tips & Best Practices

  • Mock at boundaries (repositories, HTTP clients, clocks), not your domain objects
  • Prefer asserting on results; verify only important side effects
  • Add Mockito as a Java agent in the build to avoid JDK 21+ dynamic-agent warnings

Quick Summary

  • @Mock + @InjectMocks + MockitoExtension
  • when(…).thenReturn(…) — stub
  • verify(m, times(n)) — check calls
  • matchers — all or none
