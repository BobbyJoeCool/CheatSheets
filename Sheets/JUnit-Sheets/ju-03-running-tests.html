Sheet 03

Running Tests

IDE gutter · mvn test -Dtest= · gradle test --tests · Failsafe for integration tests · ConsoleLauncher · junit-platform.properties

From the IDE, the Build or the Console

Run one test from the IDE gutter, a class or package from the build tool, or the whole suite in CI. Maven filters with -Dtest=Class#method, Gradle with --tests. The ConsoleLauncher runs tests without a build tool. junit-platform.properties in src/test/resources holds settings such as parallel execution and default display names.

Notes

  • IntelliJ: ⌃⇧R / Ctrl+Shift+F10 runs the test at the cursor
  • Patterns allow *: -Dtest="Cart*Test"
  • Gradle caches test results; --rerun forces a run
  • Tag filters (@Tag) are sheet 06

Command Line

# Maven
mvn test                                   # all unit tests
mvn test -Dtest=CartTest                   # one class
mvn test -Dtest=CartTest#addsNewItem       # one method
mvn test -Dtest="Cart*Test,Order*Test"     # patterns
mvn verify                                 # + Failsafe *IT.java tests
mvn test -Dgroups=fast -DexcludedGroups=slow

# Gradle
./gradlew test
./gradlew test --tests "shop.CartTest"
./gradlew test --tests "shop.CartTest.addsNewItem"
./gradlew test --tests "*Cart*" --rerun
./gradlew test --continuous                # rerun on change

# ConsoleLauncher (no build tool)
java -jar junit-platform-console-standalone.jar execute \
  --class-path target/test-classes:target/classes --scan-classpath

Code Explained

#method selects one method in Maven; Gradle uses a dot
mvn verify runs integration tests after packaging
-Dgroups / -DexcludedGroups filter by @Tag
--continuous keeps Gradle watching for changes

JUnit 4 / TestNG Equivalent

  • JUnit 4 Same Maven / Gradle commands; JUnit 4 classes picked by Surefire's JUnit 4 provider
  • TestNG testng.xml suite files; -Dsurefire.suiteXmlFiles=testng.xml

Prefer / Avoid

  • running the whole suite for one change → IDE gutter or -Dtest
  • integration tests mixed with unit tests → Failsafe *IT or a Gradle source set
  • flags repeated on every run → junit-platform.properties

⚠ Common Mistakes

  • Quoting patterns wrong in the shell so * expands to file names
  • Expecting mvn test to run *IT classes (Failsafe runs those in verify)
  • Thinking tests ran when Gradle reported "UP-TO-DATE"

✓ Tips & Best Practices

  • Use the IDE for the edit-test loop and the build tool for the full run
  • Open build/reports/tests/test/index.html for a readable Gradle report
  • Use --rerun (Gradle 7.6+) instead of cleanTest

Quick Summary

  • IDE gutter — one test
  • -Dtest=Class#method — Maven
  • --tests "pkg.Class.method" — Gradle
  • junit-platform.properties — shared settings
