Sheet 15

Built-in Parameters & Extensions

@TempDir (cleanup modes) · TestInfo · TestReporter · @DefaultLocale · @DefaultTimeZone · system property extension (6.1)

Things JUnit Gives You for Free

JUnit resolves some parameters on its own: a fresh temporary directory with @TempDir, TestInfo with the current test's name and tags, and TestReporter to publish key-value data. JUnit 6.1 also adds built-in extensions for default locale and time zone and for setting and restoring system properties, which used to need JUnit Pioneer.

Notes

  • @TempDir works on fields and parameters, Path or File
  • Cleanup modes: ALWAYS (default), ON_SUCCESS, NEVER
  • Locale and time-zone extensions restore the original afterwards
  • Check the 6.1 user guide for the exact system-property annotations

In Spring Boot

  • Spring @DynamicPropertySource can point properties at a @TempDir path for file-based beans
  • Boot's @SpringBootTest(properties = …) sets properties per test class without touching system properties

Built-ins

@Test
void writesReport(@TempDir Path dir) throws IOException {
    Path out = dir.resolve("report.csv");
    Reports.export(out);
    assertThat(Files.readAllLines(out)).first().isEqualTo("sku,qty");
}

@TempDir(cleanup = CleanupMode.ON_SUCCESS)    // keep files when a test fails
Path workDir;

@Test
@Tag("fast")
void info(TestInfo info, TestReporter reporter) {
    assertTrue(info.getTags().contains("fast"));
    reporter.publishEntry("user", "ann");      // appears in reports
}

@Test
@DefaultLocale("de-DE")                         // JUnit 6.1
@DefaultTimeZone("Europe/Berlin")
void formatsGermanDates() {
    assertEquals("04.11.2026", Dates.format(LocalDate.of(2026, 11, 4)));
}

Code Explained

Each test gets its own @TempDir, deleted afterwards (unless the cleanup mode keeps it)
ON_SUCCESS leaves the files behind for debugging failed tests
TestInfo exposes display name, tags, class and method
Locale and time zone are restored after the test, so other tests aren't affected

JUnit 4 / TestNG Equivalent

  • JUnit 4 TemporaryFolder rule, TestName rule; no locale helpers
  • TestNG No built-in temp dir; ITestContext / ITestResult for info; set locale manually

Prefer / Avoid

  • Files.createTempDirectory + manual cleanup → @TempDir
  • Locale.setDefault without restoring → @DefaultLocale
  • System.setProperty in tests → the 6.1 system-property extension or Spring test properties

⚠ Common Mistakes

  • Writing test files to the project folder or /tmp with fixed names
  • Changing the default locale or time zone without restoring it
  • Relying on the machine's locale for date or number formatting in assertions

✓ Tips & Best Practices

  • Use ON_SUCCESS cleanup while debugging file-producing code
  • Pin locale and time zone in formatting tests
  • Publish IDs and URLs with TestReporter to make CI failures easier to trace

Quick Summary

  • @TempDir — temp folder
  • TestInfo / TestReporter — context and report data
  • @DefaultLocale / @DefaultTimeZone (6.1)
  • built-ins restore state afterwards
