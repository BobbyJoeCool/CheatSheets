Sheet 22

Migrating from JUnit 4 & 5

@Before → @BeforeEach · @Rule → extensions · expected= → assertThrows · @RunWith → @ExtendWith · Vintage engine · 5 → 6 changes

Moving to Jupiter and JUnit 6

JUnit 4 tests can run unchanged on the Vintage engine while you migrate, but Vintage is deprecated in JUnit 6, so plan to move them. Most changes are mechanical: new packages, renamed annotations, message-last assertions, and runners and rules replaced by extensions. OpenRewrite recipes automate much of it. Going from JUnit 5 to 6 is small for most suites: Java 17, unified versions, and removed deprecated APIs.

Notes

  • Run old and new tests side by side with Vintage during the move
  • OpenRewrite: org.openrewrite.java.testing.junit5.JUnit4to5Migration
  • IntelliJ has a "Migrate to JUnit 5" inspection
  • Hamcrest still works; many teams switch to AssertJ at the same time

JUnit 4 → Jupiter

// JUnit 4                                 // JUnit Jupiter (5 / 6)
import org.junit.*;                         import org.junit.jupiter.api.*;

public class CartTest {                     class CartTest {
  @Rule public TemporaryFolder tmp          @TempDir Path tmp;
      = new TemporaryFolder();
  @BeforeClass public static void a()       @BeforeAll static void a()
  @Before public void setUp()               @BeforeEach void setUp()
  @After public void tearDown()             @AfterEach void tearDown()
  @Ignore("why")                            @Disabled("why")
  @Category(Slow.class)                     @Tag("slow")

  @Test(expected = IAE.class)               @Test void rejects() {
  public void rejects() {                     assertThrows(IAE.class, () -> cart.add("A1", 0));
    cart.add("A1", 0);                      }
  }

  @Test(timeout = 1000)                     @Test @Timeout(1)
  assertEquals("msg", 2, n);                assertEquals(2, n, "msg");
}                                           }

@RunWith(MockitoJUnitRunner.class)    →     @ExtendWith(MockitoExtension.class)
@RunWith(SpringRunner.class)          →     (implied by @SpringBootTest)

Code Explained

Annotations live in org.junit.jupiter.api; assertions in Assertions
The assertion message moves from the first argument to the last
Rules become extensions or built-ins (@TempDir, @Timeout)
Classes and methods no longer need public

JUnit 4 / TestNG Equivalent

  • JUnit 4 This sheet is the JUnit 4 map
  • TestNG TestNG → Jupiter: @BeforeMethod → @BeforeEach, dataProvider → @MethodSource, groups → @Tag, expectedExceptions → assertThrows

Prefer / Avoid

  • hand-editing hundreds of files → OpenRewrite / IDE migration
  • keeping Vintage forever → migrate and drop it before it's removed
  • migrating and refactoring tests at once → migrate first, then improve

⚠ Common Mistakes

  • Mixing JUnit 4 and Jupiter imports in one class
  • Leaving the message as the first argument after migration (it becomes the "expected" value)
  • Forgetting the Vintage engine during migration, so JUnit 4 tests silently stop running

✓ Tips & Best Practices

  • Upgrade to the last 5.x release and clear deprecation warnings before moving to 6
  • Track test counts before and after migration
  • Remove junit:junit once nothing imports it

Quick Summary

  • @Before → @BeforeEach, @Ignore → @Disabled
  • rules / runners → extensions
  • message moves last
  • JUnit 6 — Java 17, Vintage deprecated
