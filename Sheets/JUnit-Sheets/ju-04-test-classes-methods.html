Test Classes & Methods

@Test · package-private visibility · naming conventions · @DisplayName · @DisplayNameGeneration · test class layout

Readable Tests and Readable Reports

A test class is a plain class with @Test methods; neither needs to be public. Name methods after behavior, and use @DisplayName for a sentence in reports, or @DisplayNameGeneration to turn snake_case_names into words automatically. Arrange-Act-Assert inside each method keeps the steps easy to see.

Notes

  • Test methods must not be private or static, and return void
  • Display names show in IDE and build reports, not in code
  • Emoji and spaces are allowed in @DisplayName
  • @IndicativeSentencesGeneration builds sentences from class + method

Names and Layout

import org.junit.jupiter.api.*;
import static org.junit.jupiter.api.Assertions.*;

@DisplayName("Cart")
@DisplayNameGeneration(DisplayNameGenerator.ReplaceUnderscores.class)
class CartTest {

    @Test
    void total_is_zero_when_empty() {             // → "total is zero when empty"
        assertEquals(0, new Cart().total());
    }

    @Test
    @DisplayName("applies a 25% discount")
    void discount() {
        // arrange
        Cart cart = new Cart();
        cart.add("A1", 2, 10.00);
        // act
        double total = cart.total(0.25);
        // assert
        assertEquals(15.00, total, 0.001);
    }
}

Code Explained

ReplaceUnderscores turns method names into readable report lines
@DisplayName on the class prefixes every test in the report
Comments for arrange / act / assert are optional; blank lines often suffice
The third argument to assertEquals for doubles is the tolerance

JUnit 4 / TestNG Equivalent

  • JUnit 4 No display names; method names only; classes and methods must be public
  • TestNG @Test(description = "…") and testName in reports

Prefer / Avoid

  • test1, test2 → names that describe behavior
  • public everywhere → package-private
  • long setup inside each test → @BeforeEach or a factory method

⚠ Common Mistakes

  • Making test methods private or static; they're silently skipped
  • Testing several behaviors in one method named testCart
  • Display names that contradict what the test checks after a refactor

✓ Tips & Best Practices

  • Set a default generator in junit-platform.properties for the whole project
  • Keep one Act per test
  • Group related tests with @Nested (sheet 06) instead of long names
