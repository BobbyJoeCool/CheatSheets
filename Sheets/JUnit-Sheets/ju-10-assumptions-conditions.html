Sheet 10

Assumptions & Conditional Tests

assumeTrue · assumingThat · @EnabledOnOs · @EnabledForJreRange · @EnabledIfEnvironmentVariable · @EnabledIf · @DisabledIf

Run Only Where It Makes Sense

An assumption aborts a test (reported as skipped, not failed) when a precondition isn't met, such as a missing environment variable. Conditional annotations decide before the test starts: only on Linux, only on Java 21+, only when CI=true, or when a custom method returns true. Both keep the suite green on machines that can't run every test.

Notes

  • A failed assumption marks the test aborted / skipped
  • assumingThat runs part of a test only when the condition holds
  • Every @Enabled… has a @Disabled… twin
  • disabledReason shows why in reports

Assumptions and Conditions

import static org.junit.jupiter.api.Assumptions.*;
import org.junit.jupiter.api.condition.*;

@Test
void onlyOnCi() {
    assumeTrue("true".equals(System.getenv("CI")), "CI only");
    // …
}

@Test
void partly() {
    assumingThat(System.getenv("STRIPE_KEY") != null,
        () -> assertTrue(payments.liveCheck()));
    assertTrue(payments.offlineCheck());       // always runs
}

@Test @EnabledOnOs(OS.LINUX)
void usesProcFs() { }

@Test @EnabledForJreRange(min = JRE.JAVA_21)
void usesVirtualThreads() { }

@Test @EnabledIfEnvironmentVariable(named = "DB_URL", matches = "jdbc:postgresql:.*")
void againstPostgres() { }

@Test @DisabledIfSystemProperty(named = "skipSlow", matches = "true",
                                disabledReason = "slow")
void slowReport() { }

@Test @EnabledIf("dockerAvailable")
void withDocker() { }
static boolean dockerAvailable() { return DockerClientFactory.instance().isDockerAvailable(); }

Code Explained

assumeTrue aborts the rest of the test when false
assumingThat guards only the lambda; the rest of the test still runs
matches takes a regex
@EnabledIf names a static method (or Class#method) returning boolean

JUnit 4 / TestNG Equivalent

  • JUnit 4 Assume.assumeTrue(...); no conditional annotations (use rules)
  • TestNG throw new SkipException("…"); enabled = false; group-based filtering

Prefer / Avoid

  • if (!condition) return; (reports a pass) → assumeTrue (reports skipped)
  • OS checks inside tests → @EnabledOnOs
  • commented-out platform tests → conditional annotations

Assumptions

MethodEffect
assumeTrue(cond[, msg])Abort if false
assumeFalse(cond)Abort if true
assumingThat(cond, exec)Run exec only if true
abort(msg)Abort unconditionally (5.9+)

⚠ Common Mistakes

  • Returning early from a test instead of assuming, which reports a false pass
  • Conditions that skip tests in CI by accident (wrong env var name)
  • Hiding broken tests behind assumptions

✓ Tips & Best Practices

  • Check skipped counts in CI reports; a sudden jump means a condition broke
  • Use @EnabledIf with Testcontainers' Docker check
  • Always give disabledReason

Quick Summary

  • assumeTrue — skip at run time
  • assumingThat — guard part of a test
  • @EnabledOnOs / @EnabledForJreRange — before start
  • @EnabledIf — custom condition
