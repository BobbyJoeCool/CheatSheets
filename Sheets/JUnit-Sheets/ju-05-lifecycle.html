Sheet 05

Lifecycle

@BeforeEach / @AfterEach · @BeforeAll / @AfterAll · static requirement · @TestInstance(PER_CLASS) · execution order

Setup and Teardown Around Tests

JUnit creates a new instance of the test class for every test method, then calls @BeforeEach, the test, and @AfterEach. @BeforeAll and @AfterAll run once per class and must be static, unless the class uses @TestInstance(Lifecycle.PER_CLASS), which keeps one instance for all tests.

Notes

  • @AfterEach runs even if the test failed
  • Superclass @BeforeEach runs before the subclass's
  • Parameters like TestInfo can be injected into lifecycle methods
  • Avoid relying on test order; there is none by default

In Spring Boot

  • @SpringBootTest contexts are cached and reused across test classes with the same configuration
  • @DirtiesContext throws the cached context away, which slows the suite
  • @BeforeAll is a good place for Testcontainers, not for Spring beans (not injected yet in static methods)

Lifecycle Methods

import org.junit.jupiter.api.*;

class OrderRepositoryTest {
    static Database db;
    OrderRepository repo;

    @BeforeAll
    static void startDb() {           // once, before all tests (static)
        db = Database.startInMemory();
    }

    @BeforeEach
    void setUp() {                    // before every test
        repo = new OrderRepository(db);
        db.beginTransaction();
    }

    @Test
    void savesOrder() {
        repo.save(new Order(1, 10.0));
        assertEquals(1, repo.count());
    }

    @AfterEach
    void rollback() { db.rollback(); }     // after every test, pass or fail

    @AfterAll
    static void stopDb() { db.stop(); }
}

@TestInstance(TestInstance.Lifecycle.PER_CLASS)
class SharedInstanceTest {
    @BeforeAll void init() { }        // no static needed
}

Code Explained

Order per test: constructor → @BeforeEach → test → @AfterEach
Rolling back in @AfterEach keeps tests independent while sharing one database
PER_CLASS is handy in Kotlin, where static methods are awkward
Instance fields reset each test because each test gets a new instance

JUnit 4 / TestNG Equivalent

  • JUnit 4 @Before / @After / @BeforeClass / @AfterClass (static)
  • TestNG @BeforeMethod / @AfterMethod / @BeforeClass / @AfterClass (not static), plus @BeforeSuite

Prefer / Avoid

  • static mutable fields shared by tests → per-test setup
  • heavy @BeforeEach work → @BeforeAll + reset per test
  • cleanup inside each test → @AfterEach

Execution Order

StepRuns
1. @BeforeAllOnce per class
2. constructorPer test (PER_METHOD)
3. @BeforeEachSuperclass first, then subclass
4. @TestThe test
5. @AfterEachSubclass first, then superclass
6. @AfterAllOnce per class

Annotations

AnnotationStatic?
@BeforeAll / @AfterAllYes (unless PER_CLASS)
@BeforeEach / @AfterEachNo
@TestInstance(PER_CLASS)One instance per class
@TestInstance(PER_METHOD)Default: new instance per test

⚠ Common Mistakes

  • Non-static @BeforeAll without PER_CLASS (JUnit reports an error)
  • Expecting instance fields set in one test to be there in the next
  • Using PER_CLASS and leaking state between tests through fields

✓ Tips & Best Practices

  • Prefer the default per-method lifecycle for isolation
  • Use PER_CLASS in Kotlin or when @BeforeAll needs instance state
  • Keep teardown in @AfterEach so it runs on failure

Quick Summary

  • @BeforeEach / @AfterEach — every test
  • @BeforeAll / @AfterAll — once, static
  • new instance per test (default)
  • PER_CLASS — one instance
