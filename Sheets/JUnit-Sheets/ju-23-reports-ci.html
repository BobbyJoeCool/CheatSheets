Sheet 23

Reports, Coverage & CI

Surefire XML reports · Open Test Reporting · JaCoCo · coverage thresholds · GitHub Actions · test result publishing

Results Your CI Can Read

Maven Surefire and Gradle write JUnit XML reports that every CI system understands. JUnit's Open Test Reporting format adds richer events. JaCoCo measures code coverage and can fail the build below a threshold. In CI, run the build's test task, publish the reports, and keep the artifacts when tests fail.

Notes

  • Surefire XML: target/surefire-reports/TEST-*.xml
  • Gradle XML: build/test-results/test/; HTML: build/reports/tests/test/
  • Enable Open Test Reporting: junit.platform.reporting.open.xml.enabled=true
  • The Maven, Gradle and GitHub sets cover each tool

JaCoCo and a Workflow

// build.gradle.kts
plugins { java; jacoco }
tasks.test {
    useJUnitPlatform()
    finalizedBy(tasks.jacocoTestReport)
}
tasks.jacocoTestReport { reports { xml.required = true; html.required = true } }
tasks.jacocoTestCoverageVerification {
    violationRules { rule { limit { minimum = "0.80".toBigDecimal() } } }
}
tasks.check { dependsOn(tasks.jacocoTestCoverageVerification) }

# .github/workflows/test.yml
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6
      - uses: actions/setup-java@v5
        with: { distribution: temurin, java-version: 21, cache: gradle }
      - run: ./gradlew check
      - uses: actions/upload-artifact@v7
        if: always()
        with: { name: test-reports, path: build/reports/ }

Code Explained

finalizedBy builds the coverage report after every test run
jacocoTestCoverageVerification fails check below 80% line coverage
cache: gradle speeds up dependency downloads in CI
Reports upload even when tests fail (if: always())

JUnit 4 / TestNG Equivalent

  • JUnit 4 Same Surefire / Gradle XML reports and JaCoCo setup
  • TestNG TestNG writes its own testng-results.xml plus JUnit-style XML

Prefer / Avoid

  • reading raw logs for failures → publish JUnit XML to the CI test tab
  • coverage only on a laptop → JaCoCo in check
  • artifacts only on success → if: always()

⚠ Common Mistakes

  • Publishing only Surefire results when integration tests run in Failsafe
  • Setting a coverage rule so high that teams write empty tests to pass it
  • Forgetting useJUnitPlatform() in CI-only Gradle builds

✓ Tips & Best Practices

  • Fail the build on test failures and coverage regressions in the same check task
  • Upload HTML reports as artifacts for quick debugging
  • Use a test-report action to show failures in the PR

Quick Summary

  • JUnit XML — Surefire / Gradle
  • Open Test Reporting — richer events
  • JaCoCo — coverage + thresholds
  • CI — publish reports on failure too
