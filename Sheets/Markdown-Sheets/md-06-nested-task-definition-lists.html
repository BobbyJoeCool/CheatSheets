Nesting, Tasks & Definitions

To nest anything inside a list item (a sub-list, a second paragraph, a code block), indent it to the item's content column: the first character after the marker and its space. That's 2 spaces under - and 3 under 1. . Task lists (GFM) add [ ] or [x] after the marker. Definition lists pair a term with : definitions and only work in Pandoc, PHP Markdown Extra and MkDocs.

Rules

  • 4 spaces is safe under both - and 1. , and is required by Python-Markdown / MkDocs
  • Indenting past the content column by 4+ spaces makes an indented code block
  • Lazy continuation: an unindented line still continues the item's paragraph
  • GitHub task boxes are clickable in issues and PRs and edit the source

⚠ Common Mistakes

  • Indenting a child by 1 space — not nested, it becomes a sibling item
  • Code fence at column 0 inside an item — ends the list early
  • 2-space nesting in MkDocs — Python-Markdown needs 4, so lists flatten
  • [] without a space — not a task box

✓ Tips & Best Practices

  • Set your editor to insert spaces (not tabs) for list indents
  • Use task lists in PR descriptions and READMEs for checklists
  • On GitHub, write definition lists in HTML <dl>
  • Preview deeply nested lists — renderers disagree most here

Quick Summary

  • content column — indent children to it
  • - child — 2 spaces under -
  • 1. child — 3 spaces under 1.
  • - [ ] / - [x] — task list (GFM)
  • : def — definition (Pandoc, Extra, MkDocs)
