When Pipe Tables Aren't Enough

Pipe tables can't merge cells, hold block content (lists, code blocks, paragraphs) or set column widths. The portable answer is an HTML <table>, which GitHub and most renderers accept, with colspan and rowspan for merged cells. Pandoc adds grid tables drawn with +, - and | that allow block content, and MultiMarkdown supports column spans.

Good to Know

  • GitHub keeps colspan, rowspan and align but strips style
  • Markdown inside an HTML cell needs a blank line before and after it
  • Grid table borders must line up exactly, character for character
  • Pandoc caption: a Table: … or : … line next to the table

HTML & Grid Tables

<table>
  <tr><th rowspan="2">Plan</th><th colspan="2">Limits</th></tr>
  <tr><th>Users</th><th>Storage</th></tr>
  <tr><td>Free</td><td>1</td><td>5 GB</td></tr>
  <tr><td>Pro</td><td colspan="2">

**Unlimited** — see [pricing](pricing.md)

  </td></tr>
</table>

| Plan  | Features          |
+=======+===================+
| Free  | - 1 user          |

+-------+-------------------+

⚠ Common Mistakes

  • No blank lines around Markdown in <td> — **text** prints literally
  • Relying on style="…" widths on GitHub — they're stripped
  • Off-by-one border in a grid table — the whole table falls back to text
  • Indenting HTML table rows 4+ spaces after a blank line — becomes a code block

✓ Tips & Best Practices

  • Try a pipe table first; reach for HTML only when you need it
  • Keep HTML tables compact: one <tr> per line
  • For huge tables, link to a CSV instead of inlining it
  • Use a formatter to draw grid tables; never align by hand
