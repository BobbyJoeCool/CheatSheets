Inline Code & Code Blocks

Inline code wraps text in backticks; everything inside is literal, so escapes and Markdown don't apply. To include a backtick, use a longer backtick run as the delimiter. Fenced code blocks start and end with 3+ backticks or tildes; the word after the opening fence (the info string) names the language. An older form, the indented code block, is any text indented 4 spaces.

Rules

  • The closing fence must use the same character and be at least as long as the opening one
  • An unclosed fence runs to the end of the document
  • One leading + trailing space inside `` `x` `` is stripped
  • An indented code block cannot interrupt a paragraph

⚠ Common Mistakes

  • An unclosed fence — the rest of the document becomes code
  • Typing ''' (quotes) instead of ``` (backticks)
  • Indenting a paragraph 4 spaces for looks — it turns into a code block
  • Trying \` inside inline code — use a longer delimiter instead

✓ Tips & Best Practices

  • Always add a language after the fence for highlighting
  • Show fences in docs with ~~~ or 4 backticks around them
  • Use <kbd>, not backticks, for key presses
  • Keep code lines short (~80 chars) so they don't scroll
