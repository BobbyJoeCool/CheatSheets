Images

An image is a link with a leading !: ![alt text](path "title"). The alt text is read by screen readers and shown if the file fails to load. Reference syntax works too: ![alt][label]. CommonMark and GFM have no sizing syntax, so use an HTML <img> tag to set width or alignment. Wrapping an image in a link makes it clickable.

Good to Know

  • Any format the browser shows works: PNG, JPG, GIF, SVG, WebP
  • Relative paths resolve from the Markdown file's folder
  • Drag an image into a GitHub issue or PR to upload it
  • Use alt="" only for purely decorative images

Image Syntax

![Project logo](images/logo.png)                    <!-- relative -->
![Logo](images/logo.png "Shown on hover")           <!-- title -->
![Build pipeline][pipeline]                         <!-- reference -->

[pipeline]: assets/pipeline.svg

[![CI](https://img.shields.io/badge/CI-passing-green)](https://ci.example.com)

<img src="images/logo.png" alt="Logo" width="200">  <!-- sized -->
<p align="center"><img src="shot.png" alt="App" width="60%"></p>

![Photo](photo.jpg){width=50%}                      <!-- Pandoc -->
![[diagram.png|300]]                                <!-- Obsidian -->

<picture>                                           <!-- dark mode -->
  <source media="(prefers-color-scheme: dark)" srcset="logo-dark.png">
  <img alt="Logo" src="logo-light.png">
</picture>

⚠ Common Mistakes

  • Empty or filename alt text (![](a.png), ![IMG_2041]) — useless to screen readers
  • Local absolute paths like C:\Users\… — break for everyone else
  • Spaces in file names — wrap in <…> or rename with hyphens
  • Using {width=…} on GitHub — prints literally; use <img>

✓ Tips & Best Practices

  • Keep images in an images/ or assets/ folder next to the docs
  • Use SVG for diagrams and compress PNG/JPG screenshots
  • Describe the point of the image, not its appearance
  • Set only width so the image keeps its aspect ratio
