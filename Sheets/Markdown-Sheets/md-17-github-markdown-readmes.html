Markdown on GitHub

GitHub renders .md files, issues, pull requests, discussions and wikis with GFM plus extras: @mentions, issue and PR references, commit links, emoji shortcodes, alerts, footnotes, math and Mermaid. A README.md in the repo root, .github/ or docs/ is shown on the repo's front page, so it's the first thing visitors read.

Good to Know

  • References and mentions link only in comments, issues, PRs and rendered files — not inside code
  • Fixes #12 in a PR description closes the issue when the PR merges
  • GitHub adds an auto-generated outline (TOC) menu to rendered files
  • Relative links resolve against the branch being viewed

⚠ Common Mistakes

  • Linking repo files with absolute …/blob/main/… URLs — break on forks and other branches
  • A wall-of-text README — readers bail before finding install steps
  • Badges that don't link anywhere — wrap them in a link to the source
  • Expecting #12 to link inside a code span or block

✓ Tips & Best Practices

  • Lead with: what, why, install, quick example — in that order
  • Use <details> for long optional sections
  • Link with permalinks (press y on a file) so line refs don't drift
  • Use Closes / Fixes / Resolves #N to auto-close issues
