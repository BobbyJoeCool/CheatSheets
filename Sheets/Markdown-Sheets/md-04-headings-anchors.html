Headings & Anchors

ATX headings start with 1–6 # characters followed by a space; the count sets the level (<h1>–<h6>). Setext headings underline text with = (level 1) or - (level 2). Most renderers also give every heading an id (a slug of its text), so you can link to it with [text](#slug).

Rules

  • A space after # is required: #Title is a paragraph
  • Closing #s are optional and ignored: ## Title ##
  • Use one # H1 per document and don't skip levels

Heading Syntax

# Heading 1                      <!-- <h1 id="heading-1"> -->
## Heading 2
### Heading 3 ###                <!-- closing #s ignored -->
#### Heading 4                   <!-- … down to ###### (h6) -->
#Not a heading                   <!-- no space → paragraph -->

⚠ Common Mistakes

  • #Heading without a space — renders as a paragraph in CommonMark
  • Skipping levels (h1 → h3) — breaks the outline and screen-reader navigation
  • --- right under a paragraph line makes it an h2; add a blank line for a rule
  • Linking #Getting Started — anchors are lowercase and hyphenated

✓ Tips & Best Practices

  • Prefer ATX: works for all six levels and is easy to grep
  • Generate a TOC from headings (pandoc --toc, VS Code "Markdown All in One")
  • Keep headings short and stable — renaming one breaks every link to it
  • Check the real anchor by hovering the heading's link icon on GitHub

Quick Summary

  • # … ###### — heading levels 1–6
  • === / --- — setext h1 / h2
  • #slug — auto id: lowercase, hyphens
  • {#id} — custom id (Pandoc, Extra, MkDocs)
  • [text](#id) — link to a heading
