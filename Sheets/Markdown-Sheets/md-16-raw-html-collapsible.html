HTML Inside Markdown

Markdown passes raw HTML through. Inline tags (<kbd>, <sub>, <br>) work anywhere in text. An HTML block starts when a line begins with a block tag such as <div> or <details>, and it ends at the next blank line. Markdown is not parsed inside the block until a blank line separates it. <details> + <summary> make collapsible sections. Hosted renderers like GitHub sanitize HTML and remove scripts and styles.

Rules

  • Blank line after <summary> = Markdown works inside
  • Indenting an HTML block 4+ spaces turns it into a code block
  • <details open> starts expanded

⚠ Common Mistakes

  • No blank line after </summary> — the content shows as raw **text**
  • Indenting HTML for neatness after a blank line — becomes a code block
  • Expecting <style> or style= to work on GitHub
  • Forgetting </details> — the rest of the page collapses into it

✓ Tips & Best Practices

  • Use <details> to hide long logs, FAQs and optional steps
  • Prefer Markdown syntax first; HTML only where Markdown has no answer
  • Keep HTML blocks flush left with blank lines around them
  • Test in the target renderer; sanitizers differ by platform
