Links

An inline link puts the URL right after the text: [text](url "title"). A reference link uses a label, [text][label], and defines the URL once elsewhere with [label]: url; definitions never render. Autolinks wrap a URL in angle brackets, and GFM also links bare https:// and www. URLs. Relative paths link to other files in the same repo or site.

Rules

  • No space between ] and ( — [a] (b) is not a link
  • Reference labels are case-insensitive; define them anywhere in the file
  • Titles can use "…", '…' or (…)
  • URLs with spaces: wrap in <…> or encode as %20

Link Syntax

[Markdown Guide](https://www.markdownguide.org)
[Guide](https://example.com "Hover title")      <!-- title -->
[Install notes](docs/install.md)                <!-- relative file -->
[Usage](docs/install.md#usage)                  <!-- file + heading -->
[Jump to FAQ](#faq)                             <!-- same page -->
[Spec](<docs/my spec.md>)                       <!-- spaces in path -->
[Email us](mailto:team@example.com)

Read the [spec][cm] and the [GFM spec][].       <!-- full / collapsed -->
More in [cm].                                   <!-- shortcut -->

[cm]: https://spec.commonmark.org "CommonMark"
[GFM spec]: https://github.github.com/gfm/

<https://example.com>                           <!-- autolink -->
Visit www.example.com today.                    <!-- GFM bare URL -->

Code Explained

[text](url) — inline link; "title" = tooltip
docs/file.md — path relative to this file
#faq — heading anchor (see Sheet 04)
[text][label] + [label]: url — reference link
[label][] / [label] — collapsed / shortcut forms
<url> — autolink; bare URLs need GFM

⚠ Common Mistakes

  • [text] (url) — a space breaks the link; both parts print literally
  • Using an undefined label — [text][x] renders as plain brackets
  • Absolute github.com/…/blob/main/ links to repo files — break on forks and branches
  • "Click here" link text — tells readers and screen readers nothing

✓ Tips & Best Practices

  • Write link text that makes sense alone: [install guide](…)
  • Use relative links for files in the same repo
  • Collect reference definitions at the end of the section or file
  • Reference links keep long URLs out of paragraphs and diffs

Quick Summary

  • [t](url) — inline link
  • [t][id] + [id]: url — reference link
  • <url> — autolink
  • (#id) — heading anchor
  • (../a.md) — relative file link
