Conditional CSS

@media applies rules only when a condition about the device or viewport is true. Conditions combine a media type (screen, print) with media features (width, orientation, hover…). The modern range syntax reads like math: (width >= 48rem), (30rem <= width < 60rem). Mobile-first CSS writes the small-screen layout as the default and adds min-width/>= queries to enhance it as space grows.

Notes

  • and requires all conditions; a comma means OR; not negates a whole query
  • em/rem in media queries are relative to the browser default, not your html font size
  • Media queries respond to the viewport; container queries (sheet 60) respond to a component's space
  • Requires <meta name="viewport" content="width=device-width, initial-scale=1"> on mobile

♿ Accessibility

  • Content must reflow at 320 CSS px without horizontal scrolling (WCAG 1.4.10)
  • Query in em/rem so layouts respond when users enlarge text

Browser Support

  • @media, min-width/max-width, orientation: universal
  • Range syntax (width >= 48rem): Baseline 2023

Code Explained

Base styles need no query; queries only add
>= queries layer up from small to large
Range syntax avoids the .99 overlap hack
A comma lets either condition match
Height queries catch short landscape phones

Mobile-First Queries

/* base: small screens */
.layout { display: grid; gap: 1rem; }
.nav    { display: none; }

/* tablet and up */
@media (width >= 48rem) {
  .layout { grid-template-columns: 14rem 1fr; }
  .nav    { display: block; }
}

/* desktop */
@media (width >= 75rem) {
  .layout { grid-template-columns: 16rem 1fr 18rem; }
}

/* a range */
@media (48rem <= width < 75rem) {
  .promo { display: none; }
}

/* older syntax, same as above */
@media (min-width: 48rem) and (max-width: 74.99rem) { }

/* OR with a comma */
@media (orientation: landscape), (width >= 60rem) { }

/* type + feature */
@media screen and (max-height: 30rem) {
  .hero { min-height: auto; }
}

⚠ Common Mistakes

  • Desktop-first max-width queries that pile up overrides
  • Forgetting the viewport meta tag; phones render at ~980px and zoom out
  • Choosing breakpoints by device instead of where the content breaks

✓ Tips & Best Practices

  • Set breakpoints where your layout breaks, not at device sizes
  • Store breakpoints as comments or custom media (preprocessor) to keep them consistent
  • Reach for container queries for components
