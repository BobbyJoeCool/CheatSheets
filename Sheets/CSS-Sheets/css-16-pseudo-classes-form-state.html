Sheet 16

Pseudo-Classes: Form & State

:checked · :disabled · :required · :valid · :user-invalid · :placeholder-shown · :open · :popover-open

Styling Control States

Form controls expose their state through pseudo-classes: :checked for ticked boxes and selected radios, :disabled/:enabled, :required/:optional, and validity via :valid and :invalid. Because :invalid matches on page load (an empty required field is invalid), prefer :user-invalid, which waits until the user has interacted. Newer state pseudo-classes cover open <details>, dialogs and popovers.

Notes

  • :indeterminate matches a checkbox set to the mixed state via JS
  • :placeholder-shown is true while the field is empty and showing its placeholder
  • :default matches the default button and initially-checked options
  • :read-only matches non-editable inputs and ordinary text elements

♿ Accessibility

  • Don't signal errors by color alone; add an icon or message next to the field
  • Disabled controls are skipped by Tab; consider aria-disabled with styling when users need to discover them

Browser Support

  • :checked, :disabled, :valid, :required: universal
  • :user-invalid/:user-valid: Baseline 2023; :popover-open: Baseline 2024
  • :open (details, dialog, select): newer; check support

Code Explained

:checked + label: style the label next to a ticked input
:user-invalid stays quiet until the user edits or submits
:placeholder-shown: drives floating-label effects
form:has(:user-invalid): parent styling from a child's state
details[open] works everywhere; :open is the newer equivalent

Form States

input:checked + label        { font-weight: 600; }
:disabled         { opacity: .5; cursor: not-allowed; }
input:required    { border-left: 3px solid #5b4bc4; }

/* only after the user has touched the field */
input:user-invalid           { border-color: #c62828; }
input:user-invalid + .error  { display: block; }
input:user-valid             { border-color: #2e7d32; }

/* floating label */
.field input:placeholder-shown + label {
  translate: 0 1.5rem;
}

/* mixed-state checkbox */
input:indeterminate          { accent-color: gray; }

/* parent reacts to state with :has() */
form:has(:user-invalid) .submit { opacity: .6; }

/* open/closed components */
details[open] > summary      { color: #5b4bc4; }
details:open > summary       { }   /* newer */
[popover]:popover-open       { animation: pop .2s; }
dialog[open]::backdrop       { background: #0008; }

Input State

SelectorMatches
:checkedTicked checkbox, chosen radio or option
:indeterminateMixed checkbox or unset radio group
:disabled / :enabledDisabled or usable controls
:read-only / :read-writeEditable or not
:required / :optionalHas or lacks required
:placeholder-shownShowing its placeholder
:defaultDefault button or preselected choice

Validity & Open

SelectorMatches
:valid / :invalidPasses or fails constraints (immediately)
:user-valid / :user-invalidSame, after interaction
:in-range / :out-of-rangemin/max check
:autofillField filled by the browser
:openOpen details, dialog or select
:popover-openShowing popover
:modalDialog opened with showModal()

⚠ Common Mistakes

  • Styling :invalid red: every empty required field is red before the user types
  • Hiding the native checkbox with display: none: it leaves the tab order and the accessibility tree
  • Forgetting [open] attribute selectors still work where :open doesn't

✓ Tips & Best Practices

  • Use :user-invalid for error styling
  • Style custom checkboxes with appearance: none on the real input
  • Combine with :has() to style fieldsets, forms or labels from control state

Quick Summary

  • :checked · :disabled · :required
  • :user-invalid for errors
  • :placeholder-shown = empty field
  • :popover-open · :modal · [open]
