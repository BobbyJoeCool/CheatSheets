Sheet 05

The Cascade

origins · user-agent · author · !important · cascade order · source order · inline styles

How Conflicts Resolve

When several declarations set the same property on the same element, the cascade picks one. It compares, in order: origin and importance, context (shadow DOM), inline style, cascade layer, specificity, and finally order of appearance. The first step that finds a difference decides; later steps never get a say. That's why a low-specificity rule in a later layer beats a high-specificity one in an earlier layer.

Notes

  • Origins: user-agent (browser defaults), user (preferences), author (your CSS)
  • !important flips origin priority: important user styles beat important author styles
  • Inline style="" beats every selector of the same origin and importance
  • Animations override normal declarations; transitions override everything else

♿ Accessibility

  • Important user styles beat yours by design; never fight them with !important
  • Browser zoom and forced-colors mode act at the user-agent level, so test with them on

Browser Support

  • The cascade algorithm: universal
  • Cascade layers step: Baseline 2022

Code Explained

.note beats p on specificity, the third tie-breaker step
Two .note rules tie on specificity, so source order decides
!important moves a declaration to a higher-priority stage
@layer base, theme;: later layers win over earlier ones
Unlayered styles beat all layered styles (for normal declarations)

Who Wins?

/* Same element: <p class="note" id="tip"> */

p        { color: black; }    /* (0,0,1) */
.note    { color: blue; }     /* (0,1,0) wins */

/* Equal specificity: last one wins */
.note    { color: green; }    /* now green */

/* !important jumps the queue */
p        { color: red !important; }  /* red */

/* Layers decide before specificity */
@layer base, theme;
@layer theme { p { color: purple; } }
@layer base  { #tip { color: gold; } }
/* unlayered .note above beats both layers */

/* Inline style beats any normal selector */
/* <p style="color: teal"> → teal
   unless another rule says !important */

Cascade Order

StepHigher priority wins
1 Origin & importanceTransitions > important UA > important user > important author > animations > author > user > UA
2 ContextShadow DOM: outer context wins normal, inner wins important
3 Element-attachedInline style beats selectors
4 LayersLater layer > earlier; unlayered > layered (reversed for !important)
5 Specificity(id, class, type) compared left to right
6 OrderLast declared wins

⚠ Common Mistakes

  • Raising specificity to beat a rule that actually wins on layer or origin
  • Assuming the later file always wins: specificity is checked before order
  • Sprinkling !important to win fights; it starts a new, harder fight

✓ Tips & Best Practices

  • In DevTools, the Styles pane lists winning declarations first and strikes through losers
  • Use layers to set priority by intent instead of by specificity
  • Keep specificity low and even so source order stays predictable

Quick Summary

  • Origin/importance → inline → layer → specificity → order
  • First difference decides
  • !important reverses origin and layer order
  • Last declared wins only on a full tie
