Preference & Feature Queries

prefers-color-scheme · prefers-reduced-motion · prefers-contrast · forced-colors · hover · pointer · @supports

Respecting Users and Browsers

User preference media features let CSS follow settings people chose in their OS: dark mode (prefers-color-scheme), less motion (prefers-reduced-motion), more contrast (prefers-contrast), and forced high-contrast palettes (forced-colors). Input features (hover, pointer) tell you whether the main input can hover and how precise it is. @supports tests whether the browser understands a property, value or selector, so new CSS can be layered on safely.

Notes

  • any-hover / any-pointer check any input, not just the primary one
  • In forced-colors: active, the browser replaces your colors with a system palette
  • @supports not (…) and and/or combinations are allowed
  • @supports selector(:has(a)) tests selector support

♿ Accessibility

  • Reduce or remove non-essential motion under prefers-reduced-motion: reduce (WCAG 2.3.3)
  • In forced-colors mode, backgrounds and box-shadows vanish; keep borders or outlines on controls

Browser Support

  • prefers-color-scheme, prefers-reduced-motion, hover, pointer, @supports: universal
  • prefers-contrast: Baseline 2022; forced-colors: check support (forced-colors mode is mainly a Windows feature)
  • prefers-reduced-transparency: not in all engines yet

Code Explained

Dark tokens swap only the variables, not every rule
Opt-in motion: transitions only when the user hasn't asked for less
prefers-contrast: more strengthens borders and muted text
CanvasText is the system text color in forced-colors mode
@supports not provides the fallback for older browsers

Preferences and Support

/* dark mode tokens */
@media (prefers-color-scheme: dark) {
  :root { --surface: #16141d; --text: #ece9f6; }
}

/* motion only when allowed */
@media (prefers-reduced-motion: no-preference) {
  .card { transition: translate .3s ease; }
  html  { scroll-behavior: smooth; }
}

/* more contrast requested */
@media (prefers-contrast: more) {
  :root { --muted: #333; }
  .btn  { border: 2px solid; }
}

/* Windows high contrast etc. */
@media (forced-colors: active) {
  .icon { forced-color-adjust: auto; }
  .card { border: 1px solid CanvasText; }
}

/* touch vs mouse */
@media (pointer: coarse) { .btn { min-height: 44px; } }
@media (hover: hover) { .row:hover { background: #eee; } }

/* feature queries */
@supports (display: grid) and (gap: 1rem) { }
@supports not (aspect-ratio: 1) {
  .square { height: 0; padding-top: 100%; }
}
@supports selector(:has(a)) { .card:has(img) { } }

⚠ Common Mistakes

  • Writing animations first and only disabling them in reduce; opt in with no-preference instead
  • Using @media (max-width) to detect touch devices instead of pointer: coarse
  • Relying on box-shadow focus rings that disappear in forced-colors mode

✓ Tips & Best Practices

  • Test preferences in DevTools Rendering → Emulate CSS media features
  • Put dark mode in tokens and switch them with one media query
  • Wrap new features in @supports rather than browser sniffing

Quick Summary
