Anatomy of a Rule

A stylesheet is a list of rules. A style rule is a selector followed by a declaration block in braces; each declaration is property: value;. At-rules start with @ and either hold other rules (@media, @layer) or end with a semicolon (@import). When the browser can't parse a declaration it drops only that declaration and keeps going, which is what makes fallbacks work.

Notes

  • Property names and keywords are case-insensitive; class names, IDs and URLs are not
  • The last semicolon in a block is optional, but always write it
  • A shorthand (margin) sets every longhand it covers, resetting the ones you omit
  • An invalid selector in a selector list drops the whole rule (except inside :is()/:where())

♿ Accessibility

  • Keep shorthand resets in mind: font: 1rem serif resets line-height to normal, which can cramp text
  • Readable, consistently formatted CSS makes accessibility fixes easier to find

Browser Support

  • Core syntax: universal
  • Native nesting inside rules: Baseline 2023
  • Newer at-rules (@scope, @starting-style): check per feature

Code Explained

h1, h2: a selector list; both get the declarations
Second background overrides the first only where it parses
margin: 1rem 2rem: top/bottom then left/right
Statement at-rules end with ;, block at-rules wrap rules
Comments can go anywhere whitespace is allowed

Rules, Declarations, At-Rules

/* style rule */
h1, h2 {                      /* selector list */
  color: #222;                /* declaration */
  margin-block: 0 0.5em;
}

/* fallback: unknown value is dropped */
.box {
  background: #5b4bc4;        /* everyone */
  background: oklch(50% 0.2 280); /* newer */
}

/* shorthand vs longhands */
.a { margin: 1rem 2rem; }
.b {
  margin-top: 1rem;
  margin-right: 2rem;
  margin-bottom: 1rem;
  margin-left: 2rem;
}                             /* same result */

/* at-rules */
@import url("base.css");      /* statement */
@media (prefers-color-scheme: dark) {
  body { background: #111; }  /* block */
}

⚠ Common Mistakes

  • Missing semicolon: the next declaration becomes part of the previous value and both fail
  • Using a shorthand after longhands: it silently resets them
  • One bad selector in a list (a, ::-moz-x) kills the whole rule in other browsers

✓ Tips & Best Practices

  • Put the fallback first, the modern value second
  • Use longhands when you only mean to change one side or part
  • Validate with DevTools: dropped declarations show struck through with a warning icon

Quick Summary

  • selector { prop: value; }: style rule
  • @rule …; or @rule { … }: at-rule
  • Invalid declaration → skipped, rest still applies
  • Shorthand resets omitted longhands
