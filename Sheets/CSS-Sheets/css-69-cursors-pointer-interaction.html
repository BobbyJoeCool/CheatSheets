Sheet 69

Cursors & Pointer Interaction

cursor · pointer-events · user-select · touch-action · caret-color · resize · appearance

How Elements Respond to Input

A handful of properties shape interaction rather than looks. cursor shows what a click will do. pointer-events: none lets clicks pass through an element to what's beneath. user-select controls whether text can be selected, touch-action tells the browser which touch gestures to handle itself (pan, zoom) so your JS gets the rest, resize adds a drag handle, and appearance: none strips native control styling so you can restyle it.

Notes

  • cursor: pointer is a convention for links and buttons only
  • pointer-events: none doesn't stop keyboard focus or activation
  • resize only works when overflow is not visible
  • touch-action: manipulation removes double-tap-to-zoom delay on buttons

♿ Accessibility

  • Never use pointer-events: none as a way to disable controls; use disabled or inert so keyboards are blocked too
  • user-select: none on content frustrates people who copy text to translate or read aloud

Browser Support

  • cursor, pointer-events, resize, caret-color, touch-action, appearance: universal
  • user-select: Safari still needs -webkit-user-select

Code Explained

not-allowed signals a disabled control
Custom cursor: image, hotspot x y, then a keyword fallback
Children can re-enable pointer-events
user-select: all selects the whole snippet in one click
touch-action: pan-y lets the page scroll while JS handles horizontal swipes

Interaction Properties

a, button, [role="button"], label[for] { cursor: pointer; }
[disabled], [aria-disabled="true"] { cursor: not-allowed; }
.draggable        { cursor: grab; }
.draggable:active { cursor: grabbing; }
.help             { cursor: help; }

/* custom cursor with fallback */
.paint { cursor: url("brush.svg") 4 28, crosshair; }

/* overlay that doesn't block clicks */
.gradient-overlay { pointer-events: none; }
.gradient-overlay a { pointer-events: auto; }

/* no text selection on UI chrome */
.toolbar {
  -webkit-user-select: none;
  user-select: none;
}
.code-snippet { user-select: all; } /* select on click */

/* gestures */
.map      { touch-action: none; }       /* JS handles all */
.carousel { touch-action: pan-y; }      /* page scrolls */
button    { touch-action: manipulation; }

textarea { resize: vertical; }
input    { caret-color: #5b4bc4; }
select   { appearance: none; }          /* restyle */

⚠ Common Mistakes

  • Disabling with pointer-events: none while the control is still keyboard-operable
  • user-select: none on articles and documentation
  • Removing appearance from checkboxes without adding visible checked and focus states

✓ Tips & Best Practices

  • Pair custom cursors with a keyword fallback
  • Use touch-action instead of preventDefault() in touch handlers
  • Limit resize to vertical for textareas in layouts

Quick Summary

  • cursor signals the action
  • pointer-events: none = click-through
  • user-select / touch-action
  • appearance: none to restyle
