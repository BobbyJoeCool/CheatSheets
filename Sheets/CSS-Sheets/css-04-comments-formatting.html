Comments & Formatting

Writing Readable CSS

CSS has one comment syntax, /* … */, which can span lines but cannot nest. There is no // line comment: it silently breaks the next declaration or rule. Beyond comments, readability comes from consistent formatting (one declaration per line, a stable property order) and from tools like Prettier and Stylelint that enforce it. Comments and whitespace are stripped by minifiers, so explain freely.

Notes

  • Nested /* /* */ */ ends at the first */, leaving stray text
  • Comments are allowed between tokens, not inside them: col/* */or is invalid
  • Use comments for why (a browser bug, a design decision), not what
  • Section banners help in long files; split very long files instead

♿ Accessibility

  • Note accessibility decisions in comments (e.g. why an outline was replaced) so nobody removes them later

Browser Support

  • /* */ comments: universal
  • // comments: valid in Sass/Less source, invalid in plain CSS

Comments and Formatting

/* ==========================================
   Components: Card
   ========================================== */

.card {
  /* Positioning */
  position: relative;
  z-index: 1;

  /* Box */
  display: grid;
  gap: 1rem;
  padding: 1.5rem;

  /* Visual */
  background: white;
  border-radius: 0.5rem;
}

// .old { color: red; }   ← NOT a comment:
//                          eats the next rule

/* TODO: remove after Safari 17 drops off */
.card { -webkit-backdrop-filter: blur(4px); }

/* minified: .card{position:relative;z-index:1} */

⚠ Common Mistakes

  • Commenting out with //: breaks the next rule, not just the line
  • Nesting comments to disable a block that already has comments
  • Leaving dead commented-out code instead of deleting it (git keeps history)

✓ Tips & Best Practices

  • Format on save with Prettier; lint on commit with Stylelint
  • Pick one property order and let a linter enforce it
  • Keep comments that explain hacks next to the hack

Quick Summary

  • /* … */: the only CSS comment
  • No //, no nesting
  • Consistent order + formatter = readable diffs
  • Minify for production
