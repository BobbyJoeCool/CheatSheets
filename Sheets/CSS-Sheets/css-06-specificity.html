Specificity

(a, b, c) weights · id · class · type · :is()/:not()/:has() weight · :where() zero · specificity wars

Selector Weight

Specificity scores a selector as three numbers (A, B, C): A counts IDs, B counts classes, attributes and pseudo-classes, C counts type selectors and pseudo-elements. Compare A first, then B, then C; the first column that differs decides. No number of classes beats one ID, because the columns never carry over. :where() always adds zero, which makes it the tool for writing easy-to-override defaults.

Notes

  • * and combinators (>, +, ~, space) add nothing
  • :is(), :not() and :has() take the weight of their most specific argument
  • :nth-child(2 of .x) counts as one pseudo-class plus its argument
  • Inline styles and !important aren't specificity; they're earlier cascade steps

♿ Accessibility

  • High-specificity component styles make it hard to add focus or contrast fixes later; keep weights low

Browser Support

  • Specificity rules: universal
  • :is()/:where(): Baseline 2021; :has(): Baseline 2023

Code Explained

Columns are compared left to right: (1,0,0) beats (0,99,0)
Pseudo-elements count as types; pseudo-classes count as classes
:is(#a, .b) scores as #a even when .b is what matched
:where() lets any later class override a default
Repeating a class (.card.card) raises B without adding an ID

Scoring Selectors

*                       /* (0,0,0) */
li                      /* (0,0,1) */
ul li                   /* (0,0,2) */
li::marker              /* (0,0,2) */
.item                   /* (0,1,0) */
[type="email"]          /* (0,1,0) */
a:hover                 /* (0,1,1) */
nav .link.active        /* (0,2,1) */
#main                   /* (1,0,0) */
#main .card h2          /* (1,1,1) */

/* functional pseudo-classes */
:is(#a, .b) p           /* (1,0,1)  most specific arg */
:where(#a, .b) p        /* (0,0,1)  always zero */
:not(.hidden)           /* (0,1,0) */
article:has(> img)      /* (0,0,2) */

/* easy-to-override defaults */
:where(.btn) { padding: .5em 1em; }
.btn-large   { padding: 1em 2em; } /* wins */

/* bumping without IDs */
.card.card { }          /* (0,2,0) */

⚠ Common Mistakes

  • Styling with IDs: one ID outweighs any number of classes and forces more IDs to override
  • Expecting 11 classes to beat an ID: columns don't overflow
  • Forgetting :is() takes its heaviest argument, raising a whole rule's weight

✓ Tips & Best Practices

  • Style with classes; keep IDs for fragment links and JS hooks
  • Wrap library and reset selectors in :where() so they're trivial to override
  • Hover a selector in DevTools to see its specificity
