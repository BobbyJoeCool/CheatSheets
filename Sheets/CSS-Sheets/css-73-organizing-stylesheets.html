Sheet 73

Organizing Stylesheets

file structure · base/layout/components/utilities · @layer order · @import vs bundling · DRY tokens

Structure That Scales

Large stylesheets stay manageable when they're split by job and ordered from generic to specific: tokens and resets, base element styles, layout primitives, components, then utilities. Cascade layers encode that order so specificity stops mattering between groups. Methodologies like ITCSS formalize the idea (see the CSS Systems set); plain CSS with layers, custom properties and nesting gets you most of the way.

Notes

  • One component per file makes ownership and deletion easy
  • Tokens (custom properties) remove repeated magic numbers
  • A bundler (Vite, Lightning CSS) combines partials; avoid runtime @import chains
  • Utilities go last so they can override components

♿ Accessibility

  • Keep focus styles, reduced-motion and forced-colors rules in base layers so every component inherits them

Browser Support

  • @layer: Baseline 2022; native nesting: Baseline 2023

Code Explained

The @layer statement fixes the priority order once
Each import goes into its layer, so file order matters less
Tokens hold every reusable value
Layout primitives (stack, grid) stay separate from components
Utilities win because their layer is last

A Layered Project

/* main.css */
@layer reset, tokens, base, layout, components, utilities;

@import url("reset.css")            layer(reset);
@import url("tokens.css")           layer(tokens);
@import url("base.css")             layer(base);
@import url("layout/stack.css")     layer(layout);
@import url("layout/grid.css")      layer(layout);
@import url("components/card.css")  layer(components);
@import url("components/btn.css")   layer(components);
@import url("utilities.css")        layer(utilities);

/* tokens.css */
:root {
  --space-1: .25rem;  --space-2: .5rem;  --space-3: 1rem;
  --radius: 8px;
  --brand: oklch(58% .18 285);
}

/* layout/stack.css */
.stack > * + * { margin-block-start: var(--space, 1rem); }

/* components/card.css */
.card {
  padding: var(--space-3);
  border-radius: var(--radius);
  & .card__title { margin: 0; }
}

/* utilities.css */
.visually-hidden { /* see sheet 75 */ }
.mt-0 { margin-block-start: 0; }

Typical Folders

FolderContains
tokens/Colors, spacing, type scale
base/Reset, element defaults, typography
layout/Stack, cluster, grid, sidebar
components/One file per component
utilities/Single-purpose helpers
pages/Rare page-specific overrides

Generic → Specific

⚠ Common Mistakes

  • One huge styles.css where nobody knows what's safe to delete
  • Page-specific overrides scattered through component files
  • Shipping many @imports unbundled to production

✓ Tips & Best Practices

  • Declare layer order in one place
  • Delete a component's CSS file when the component goes
  • See CSS Systems (ITCSS, BEM, Sass) for team-scale methods

Quick Summary

  • Generic → specific
  • @layer encodes the order
  • Tokens for repeated values
  • Bundle partials for production
