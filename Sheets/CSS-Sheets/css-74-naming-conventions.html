Naming Conventions

BEM · block__element--modifier · utility classes · state classes (.is-) · js- hooks · data-attribute state

Names That Explain Themselves

Class names are the API between HTML and CSS. BEM (Block, Element, Modifier) makes relationships explicit: .card is a block, .card__title an element inside it, .card--featured a variation. Utility classes do one thing each (.flex, .mt-2). State is best expressed with .is-* classes or, better, ARIA and data-* attributes that also carry meaning. Keep js-* hooks separate from styling so refactors don't break scripts.

Notes

  • BEM keeps every selector a single class, so specificity stays flat
  • Name by purpose (.btn--danger), not appearance (.btn--red)
  • Never nest BEM elements in names: .card__body__title → .card__title
  • Utility-first frameworks are covered in the CSS Systems set

♿ Accessibility

  • Style from ARIA state ([aria-expanded="true"]) so the visual state can't disagree with what screen readers announce

Browser Support

  • Naming is a convention; nothing here depends on browser support

Code Explained

.card__title: element of the card block
.card--featured: a variant of the same block
.is-open describes temporary state
ARIA and data-* state doubles as accessible meaning
js- classes are for scripts only, so styling changes can't break JS

BEM, State, Hooks

/* block */
.card { border: 1px solid #ddd; }

/* elements */
.card__media { aspect-ratio: 16 / 9; }
.card__title { font-size: 1.25rem; }
.card__body  { padding: 1rem; }

/* modifiers */
.card--featured { border-color: gold; }
.card--compact .card__body { padding: .5rem; }

/* state classes */
.accordion.is-open   { }
.btn.is-loading      { cursor: progress; }

/* prefer attribute state */
.accordion[data-state="open"] { }
.menu-btn[aria-expanded="true"] .icon { rotate: 180deg; }
.tab[aria-selected="true"] { border-bottom: 2px solid; }

/* utilities */
.flex   { display: flex; }
.gap-2  { gap: .5rem; }
.sr-only { /* visually hidden */ }

/* JS hook: never styled */
/* <button class="btn js-open-cart"> */

⚠ Common Mistakes

  • Naming by looks (.blue-box) and renaming everything after a redesign
  • Deeply chained BEM like .a__b__c__d
  • Styling js-* classes, then breaking styles when JS changes

✓ Tips & Best Practices

  • Pick one convention and write it down
  • Use ARIA attributes for state when they apply
  • Keep class names lowercase with hyphens

Quick Summary

  • .block__element--modifier
  • Purpose over appearance
  • .is-* or ARIA for state
  • js-* hooks unstyled
