Color Functions & Schemes

color-mix() · relative color (from) · light-dark() · color-scheme · accent-color · system colors

Deriving Colors

color-mix(in oklch, A 30%, B) blends two colors in a chosen space. Relative color syntax builds a new color from an existing one: oklch(from var(--brand) calc(l - 0.1) c h) darkens a token without a second hard-coded value. color-scheme tells the browser which themes a page supports, so form controls and scrollbars match, and light-dark(A, B) picks a value based on the active scheme.

Notes

  • Mix percentages default to 50/50 and normalize if they don't add to 100%
  • In relative syntax, channel names (l, c, h, r, g, b, alpha) are numbers you can use in calc()
  • light-dark() only works when color-scheme includes both light and dark
  • accent-color tints checkboxes, radios, range and progress

♿ Accessibility

  • color-scheme: light dark makes native controls readable in dark mode
  • Use system colors (Canvas, CanvasText, LinkText) inside forced-colors styles

Browser Support

  • color-mix(): Baseline 2023; color-scheme, accent-color: Baseline 2022
  • Relative color syntax, light-dark(): Baseline 2024

Code Explained

color-scheme: light dark enables light-dark() and dark native UI
color-mix(…, black 15%): a 15% darker shade
Mixing with transparent makes a translucent tint
from var(--brand) exposes l c h as numbers for calc()
accent-color restyles checkboxes and radios in one line

Mixing and Theming

:root {
  color-scheme: light dark;            /* both themes */
  --brand: oklch(58% 0.18 285);

  --surface: light-dark(#ffffff, #16141d);
  --text:    light-dark(#1d1b26, #ece9f6);
}

body { background: var(--surface); color: var(--text); }

/* mix: tints and shades */
.btn         { background: var(--brand); }
.btn:hover {
  background: color-mix(in oklch, var(--brand), black 15%);
}
.btn-soft {
  background: color-mix(in oklch, var(--brand) 15%,
                        transparent);
}

/* relative color syntax */
.btn:active {
  background: oklch(from var(--brand) calc(l - .12) c h);
}
.muted       { color: rgb(from var(--text) r g b / 60%); }
.complement {
  color: oklch(from var(--brand) l c calc(h + 180));
}

/* native controls */
form { accent-color: var(--brand); }

/* user forced a palette (Windows contrast) */
@media (forced-colors: active) {
  .btn { border: 1px solid ButtonText; }
}

⚠ Common Mistakes

  • Using light-dark() without setting color-scheme: always returns the light value
  • Mixing in srgb and getting muddy midpoints; mix in oklch or oklab
  • Hard-coding hover shades that drift from the token when the brand changes

✓ Tips & Best Practices

  • Derive hover, active and soft variants from one token
  • Set color-scheme on :root in every project
  • Test with Windows contrast themes via DevTools' forced-colors emulation
