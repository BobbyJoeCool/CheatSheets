Combinators

descendant · > child · + next-sibling · ~ subsequent-sibling · combinators in nesting

Relationships Between Elements

Combinators join selectors by the relationship between elements in the tree. A space matches any descendant, > only direct children, + the element right after a sibling, and ~ any later sibling. Selectors are read right to left: the rightmost part is the element being styled, and everything to its left is a condition on its ancestors or earlier siblings.

Notes

  • Sibling combinators only look forward; use :has() to style an earlier sibling
  • * with a combinator (.grid > *) targets every child
  • Long descendant chains are fragile when markup changes
  • In nesting, a leading combinator (> li) is relative to the parent

♿ Accessibility

  • The "lobotomized owl" * + * spacing keeps rhythm without margins that collapse into focus outlines
  • Don't rely on DOM order hacks (~) to show content that screen readers reach in a different order

Browser Support

  • All four combinators: universal
  • Column combinator ||: not supported anywhere

Code Explained

article p: paragraphs anywhere inside an article
.menu > li: not nested lis in submenus
h2 + p: only the first paragraph after each h2
.flow > * + *: every child except the first gets top margin
li + li: borders between items, none on the first

Four Combinators

/* descendant: any depth */
article p          { max-width: 65ch; }

/* child: direct children only */
.menu > li         { display: inline-block; }

/* next sibling: immediately after */
h2 + p             { margin-top: 0; font-size: 1.1em; }
label + input      { margin-left: .5rem; }

/* subsequent sibling: any later sibling */
h2 ~ p             { color: #444; }

/* checkbox hack: state → later sibling */
#nav-toggle:checked ~ .nav { display: block; }

/* flow spacing ("owl") */
.flow > * + *      { margin-top: 1em; }

/* every child */
.grid > *          { min-width: 0; }

/* in nesting */
.list {
  > li     { padding: .25rem; }   /* .list > li */
  li + li  { border-top: 1px solid #ddd; }
}

⚠ Common Mistakes

  • Expecting + or ~ to match an earlier sibling: they only look forward
  • Using div > div > div > p: breaks as soon as markup changes
  • Forgetting siblings must share the same parent

✓ Tips & Best Practices

  • Prefer > over a space when you only mean direct children
  • Use li + li instead of :not(:first-child) for in-between styles
  • Reach backward with :has(): h2:has(+ p)

Quick Summary

  • space = descendant
  • > = child
  • + = next sibling
  • ~ = any later sibling
