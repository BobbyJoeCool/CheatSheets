Sheet 51

Logging & Monitoring

pino-http · morgan formats · request ids · log levels · /health & /ready routes · OpenTelemetry

Description

Production logs should be structured JSON, one line per event, with a request id tying lines together. pino-http logs every request with method, URL, status and duration, and gives each request a child logger at req.log. Add health routes so load balancers and orchestrators know when to send traffic, and OpenTelemetry for traces and metrics across services.

Notes

  • /health (liveness): process is up; /ready (readiness): dependencies reachable
  • Log levels: trace debug info warn error fatal
  • Redact secrets (authorization, cookies, passwords)
  • Pretty-print only in development (pino-pretty)

pino-http + Health Checks

import pino from "pino";
import { pinoHttp } from "pino-http";
import { randomUUID } from "node:crypto";

export const logger = pino({
  level: config.LOG_LEVEL,
  redact: ["req.headers.authorization", "req.headers.cookie", "*.password"],
  transport: config.isProd ? undefined : { target: "pino-pretty" },
});

app.use(pinoHttp({
  logger,
  genReqId: (req, res) => {
    const id = req.get("x-request-id") ?? randomUUID();
    res.set("X-Request-Id", id);
    return id;
  },
  customLogLevel: (req, res, err) => (err || res.statusCode >= 500 ? "error"
    : res.statusCode >= 400 ? "warn" : "info"),
  autoLogging: { ignore: (req) => req.url === "/health" },
}));

app.get("/todos", async (req, res) => {
  req.log.info({ userId: req.user.id }, "listing todos");   // has req id
  res.json(await repo.list());
});

app.get("/health", (req, res) => res.json({ status: "ok" }));
app.get("/ready", async (req, res) => {
  try { await db.query("SELECT 1"); res.json({ db: "ok" }); }
  catch { res.status(503).json({ db: "down" }); }
});

Code Explained

redact — paths replaced with [Redacted]
genReqId — reuse an incoming id or make one
customLogLevel — 5xx as error, 4xx as warn
/ready returns 503 so the balancer stops routing

Prefer / Avoid

  • console.log in production → pino JSON logs
  • Logging whole request bodies → log ids and fields you need; redact
  • One /health that checks everything → cheap liveness + separate readiness

⚠ Common Mistakes

  • Logging auth headers or passwords: credentials leak into log storage
  • Readiness that never fails: traffic keeps flowing to a server with a dead DB connection
  • Using pino-pretty in production: slow and breaks log parsers

✓ Tips & Best Practices

  • Start OpenTelemetry with node --import @opentelemetry/auto-instrumentations-node/register
  • Include req.id in error responses (sheet 25)
  • Alert on error rate and p95 latency, not on single errors

Quick Summary

  • pino-http — JSON request logs
  • req.log — per-request logger
  • /health & /ready — probes
  • redact secrets
