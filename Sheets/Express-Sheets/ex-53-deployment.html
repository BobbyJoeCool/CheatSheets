Deployment

trust proxy behind Nginx · graceful shutdown server.close() · SIGTERM · Dockerfile · PM2 · HTTPS termination · serverless

Description

In production an Express app usually runs behind a reverse proxy or load balancer that terminates HTTPS, so set trust proxy correctly. It runs under a supervisor (Docker, Kubernetes, systemd, PM2) that restarts it and sends SIGTERM on deploys: handle that by closing the server, finishing in-flight requests and closing database pools before exiting. Containers are the most common packaging.

Notes

  • Listen on 0.0.0.0 inside containers (Express's default host is all interfaces)
  • Health checks: /health liveness, /ready readiness (51)
  • Run as a non-root user
  • Serverless: serverless-http for Lambda; Vercel can run an Express app

Graceful Shutdown

const server = app.listen(config.PORT);

function shutdown(signal) {
  logger.info({ signal }, "shutting down");
  server.close(async () => {     // stop accepting; wait for in-flight
    await db.end();
    await redis.quit();
    process.exit(0);
  });
  server.closeIdleConnections();             // drop idle keep-alives
  setTimeout(() => process.exit(1), 10_000).unref();   // hard stop
}
process.on("SIGTERM", shutdown);
process.on("SIGINT", shutdown);

Dockerfile

FROM node:22-slim
ENV NODE_ENV=production
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev
COPY src ./src
USER node
EXPOSE 3000
CMD ["node", "src/server.js"]

Code Explained

server.close(cb) — waits for open requests to finish
Timeout + unref() — never hang forever
CMD ["node", …] — node gets SIGTERM directly (not via npm)
npm ci --omit=dev — production deps only

Prefer / Avoid

  • CMD npm start → CMD ["node", "src/server.js"] (signals reach Node)
  • Express serving HTTPS certs itself → terminate TLS at the proxy / load balancer
  • Killing the process on deploy → handle SIGTERM and drain

⚠ Common Mistakes

  • CMD npm start in Docker: npm doesn't forward SIGTERM, so connections are cut on deploy
  • No shutdown timeout: one stuck request blocks the deploy
  • Forgetting trust proxy behind the load balancer: secure cookies never set and IPs are wrong

✓ Tips & Best Practices

  • Docker set covers multi-stage builds and .dockerignore
  • Run migrations as a separate release step, not on boot
  • Pin the Node major in the image tag (node:22-slim)
