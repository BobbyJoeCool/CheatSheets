Sheet 38

Password Hashing & Login

bcrypt / argon2 hash & verify · signup / login routes · timing-safe compare · never return hashes · requireAuth

Description

Store password hashes, never passwords. bcrypt and Argon2 are deliberately slow and salted, so a stolen database can't be reversed quickly. On signup, hash and save; on login, look up the user and verify the password against the hash, returning the same error whether the email or the password was wrong. A requireAuth middleware then protects routes.

Notes

  • bcrypt cost 12 is a reasonable default (~250 ms)
  • Argon2id is the current OWASP recommendation
  • bcrypt only uses the first 72 bytes of a password
  • Rate limit login routes (sheet 42)

Signup, Login, Guard

import argon2 from "argon2";            // or: import bcrypt from "bcrypt"

app.post("/signup", validate({ body: Signup }), async (req, res) => {
  const { email, password } = req.valid.body;
  const hash = await argon2.hash(password);   // bcrypt.hash(pw, 12)
  const user = await users.create({ email, passwordHash: hash });
  res.status(201).json({ id: user.id, email: user.email });   // no hash!
});

app.post("/login", loginLimiter, validate({ body: Login }),
  async (req, res, next) => {
  const { email, password } = req.valid.body;
  const user = await users.findByEmail(email);
  const ok = user && (await argon2.verify(user.passwordHash, password));
  //               bcrypt.compare(password, user.passwordHash)
  if (!ok) return res.status(401).json({ error: "Invalid email or password" });
  req.session.regenerate((err) => {
    if (err) return next(err);
    req.session.userId = user.id;
    res.json({ id: user.id });
  });
});

export const requireAuth = async (req, res, next) => {
  if (!req.session.userId) return res.sendStatus(401);
  req.user = await users.find(req.session.userId);
  if (!req.user) return res.sendStatus(401);
  next();
};

Code Explained

argon2.hash — salt is generated and stored in the hash string
Same 401 message for unknown email and wrong password
Never include passwordHash in responses
requireAuth — loads the user and sets req.user

Prefer / Avoid

  • crypto.createHash("sha256") for passwords → argon2 / bcrypt
  • "No user with that email" errors → one generic "invalid email or password"
  • res.json(user) from the DB → pick safe fields explicitly

⚠ Common Mistakes

  • Comparing hashes with === on custom schemes: leaks timing; use crypto.timingSafeEqual
  • Revealing whether an email exists on login or reset: helps attackers enumerate accounts
  • Hashing in a sync call (bcrypt.hashSync): blocks the event loop for every request

✓ Tips & Best Practices

  • Rehash on login when you raise the cost factor (argon2.needsRehash)
  • Store passwordHash in a column you never SELECT by default
  • Consider passkeys / OAuth so you store no passwords at all (40)

Quick Summary

  • hash — argon2 / bcrypt, never plain
  • verify — compare against hash
  • one generic login error
  • requireAuth — sets req.user
