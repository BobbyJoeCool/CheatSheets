Sheet 04

Project Layout & Scripts

app.js vs server.js · routes/ · controllers/ · middleware/ · public/ · npm scripts · --env-file

Description

Express does not impose a layout, so pick one and keep it. The common pattern splits **app.js (builds and exports the app: middleware, routes, error handler) from server.js** (reads config and calls listen). Routes live in one router file per resource, handlers in controllers, and shared logic in services. Tests import app.js without opening a port.

Notes

  • src/ keeps source separate from config files at the root
  • One router per resource: routes/todos.js → mounted at /api/todos
  • Middleware you write goes in middleware/; error handler is the last app.use
  • Static assets in public/, templates in views/

Folder Layout

todo-api/
├─ src/
│  ├─ app.js            # build + export app
│  ├─ server.js         # listen() only
│  ├─ config.js         # env vars, validated
│  ├─ routes/todos.js   # express.Router()
│  ├─ controllers/todos.js
│  ├─ services/todos.js
│  └─ middleware/errors.js
├─ public/              # static files
├─ test/todos.test.js
├─ .env                 # gitignored
└─ package.json

app.js + server.js

// src/app.js
import express from "express";
import todos from "./routes/todos.js";
import { errorHandler } from "./middleware/errors.js";

export const app = express();
app.use(express.json());
app.use("/api/todos", todos);
app.use(errorHandler);              // always last

// src/server.js
import { app } from "./app.js";
app.listen(process.env.PORT ?? 3000);

Code Explained

export const app — tests do request(app) with no port (sheet 48)
Relative imports need the .js extension in ES modules
Mount order is the run order: parsers, routes, then errors
server.js stays tiny so nothing important hides there

Prefer / Avoid

  • One 800-line index.js → app.js + routers + controllers
  • app.listen inside app.js → listen in server.js, export the app
  • Folders by type for big apps → feature folders (todos/, users/) once it grows (47)

⚠ Common Mistakes

  • Leaving the .js off relative imports: ESM throws ERR_MODULE_NOT_FOUND
  • Mounting the error handler before the routes: it never sees their errors
  • Putting database calls in route files: they become impossible to test or reuse

✓ Tips & Best Practices

  • Use import.meta.dirname (Node 20.11+) for paths like public/
  • Add a "imports": { "#src/*": "./src/*" } alias to avoid ../../
  • Copy a layout you like once, then reuse it for every project

Quick Summary

  • app.js — build + export
  • server.js — listen
  • routes / controllers / services — separation
  • error handler — mounted last
