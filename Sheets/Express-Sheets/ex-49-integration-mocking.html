Sheet 49

Integration Tests & Mocking

test database · seeding & cleanup · mocking services · testing middleware alone · auth in tests · supertest.agent()

Description

Route tests with fakes are fast; integration tests run against a real database to catch query and migration bugs. Use a separate test database, reset it between tests (truncate or wrap each test in a rolled-back transaction), and seed only what each test needs. For external services (email, payments) inject fakes. **request.agent(app)** keeps cookies between requests for session-based login flows.

Notes

  • Point tests at DATABASE_URL for a throwaway DB (Docker / Testcontainers)
  • Run migrations once before the suite, not per test
  • Test middleware alone by mounting it on a tiny app
  • Use mock.fn() (node:test) or vi.fn() (Vitest) for spies

Real DB, Fake Mailer, Logged-In Agent

import { test, before, beforeEach, after, mock } from "node:test";
import assert from "node:assert/strict";
import request from "supertest";
import pg from "pg";

const db = new pg.Pool({ connectionString: process.env.TEST_DATABASE_URL });
const mailer = { send: mock.fn(async () => {}) };
const app = createApp({ db, mailer });

before(() => migrate(db));
beforeEach(async () => {
  await db.query("TRUNCATE users, todos RESTART IDENTITY CASCADE");
  mailer.send.mock.resetCalls();
});
after(() => db.end());

test("signup sends a welcome email", async () => {
  await request(app).post("/signup")
    .send({ email: "a@b.co", password: "pw-123456" }).expect(201);
  assert.equal(mailer.send.mock.callCount(), 1);
  assert.equal(mailer.send.mock.calls[0].arguments[0].to, "a@b.co");
});

test("session login flow", async () => {
  await seedUser(db, { email: "a@b.co", password: "pw-123456" });
  const agent = request.agent(app);                // keeps cookies
  await agent.post("/login")
    .send({ email: "a@b.co", password: "pw-123456" }).expect(200);
  await agent.get("/me").expect(200);              // cookie sent
});

test("requireRole alone", async () => {
  const mini = express()
    .use((req, res, next) => { req.user = { role: "user" }; next(); })
    .get("/", requireRole("admin"), (req, res) => res.send("ok"));
  await request(mini).get("/").expect(403);
});

Code Explained

TRUNCATE … RESTART IDENTITY — clean tables, ids from 1
mock.fn() — records calls; no emails sent
request.agent — cookie jar across requests
Mini app — test one middleware in isolation

Prefer / Avoid

  • Tests against the dev database → a dedicated test database
  • Mocking pg / Prisma internals → a real test DB or a repo fake
  • Order-dependent tests → reset state in beforeEach

⚠ Common Mistakes

  • Running test files in parallel against one database: tests wipe each other's data
  • Forgetting db.end(): the runner never exits
  • Asserting on generated ids without resetting sequences: tests break on rerun

✓ Tips & Best Practices

  • Use node --test --test-concurrency=1 for shared-DB suites
  • Seed with small factory functions (seedUser, seedTodo)
  • Keep a few end-to-end browser tests too (Playwright set)
