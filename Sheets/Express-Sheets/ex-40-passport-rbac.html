Passport & Role-Based Access

passport.use(new LocalStrategy()) · passport.authenticate() · serializeUser · OAuth strategies · requireRole · req.user

Description

Passport is authentication middleware with 500+ strategies: username/password (passport-local), OAuth providers (Google, GitHub), JWT and more. Each strategy verifies credentials and hands back a user; with sessions, serializeUser stores the user id and deserializeUser loads it into req.user on later requests. Authorization (who may do what) is your job: a small requireRole middleware covers most apps.

Notes

  • Mount order: express-session → passport.initialize() → passport.session()
  • req.isAuthenticated(), req.login(user, cb), req.logout(cb)
  • Passport 0.6+ regenerates the session on login automatically
  • req.logout needs a callback since 0.6

Local + GitHub Login, Roles

import passport from "passport";
import { Strategy as LocalStrategy } from "passport-local";
import { Strategy as GitHubStrategy } from "passport-github2";

passport.use(new LocalStrategy({ usernameField: "email" },
  async (email, password, done) => {
    const user = await users.findByEmail(email);
    const ok = user && (await argon2.verify(user.passwordHash, password));
    done(null, ok ? user : false);
  }));
passport.use(new GitHubStrategy({ clientID, clientSecret, callbackURL },
  async (at, rt, profile, done) => done(null, await users.fromGitHub(profile))));

passport.serializeUser((user, done) => done(null, user.id));
passport.deserializeUser((id, done) => users.find(id).then((u) => done(null, u)));

app.use(session({ /* sheet 37 */ }), passport.initialize(), passport.session());

app.post("/login", passport.authenticate("local",
  { successRedirect: "/", failureRedirect: "/login" }));
app.get("/auth/github", passport.authenticate("github"));
app.get("/auth/github/cb",
  passport.authenticate("github", { failureRedirect: "/login" }),
  (req, res) => res.redirect("/"));

const requireRole = (...roles) => (req, res, next) =>
  !req.isAuthenticated() ? res.sendStatus(401)
  : roles.includes(req.user.role) ? next() : res.sendStatus(403);
app.delete("/users/:id", requireRole("admin"), deleteUser);

Code Explained

done(null, false) — credentials wrong; done(err) — real error
serializeUser — what goes in the session (just the id)
authenticate("github") — redirects to GitHub, then the callback
requireRole — 401 if anonymous, 403 if wrong role

Prefer / Avoid

  • Role checks inside every handler → requireRole("admin") in the route
  • Serializing the whole user → serialize the id; deserialize per request
  • Rolling your own OAuth dance → a Passport strategy (or Auth.js / Better Auth)

⚠ Common Mistakes

  • Mounting passport.session() before express-session: req.session is undefined
  • Calling req.logout() without a callback on Passport 0.6+: throws
  • Checking roles on the client only: anyone can call the API directly

✓ Tips & Best Practices

  • Use passport.authenticate("jwt", { session: false }) for APIs
  • Put permissions in a table (can(user, "delete", todo)) once roles get complex
  • Consider hosted auth (Auth0, Clerk) or Better Auth for MFA and passkeys

Quick Summary

  • authenticate() — run a strategy
  • serializeUser / deserializeUser — session ↔ user
