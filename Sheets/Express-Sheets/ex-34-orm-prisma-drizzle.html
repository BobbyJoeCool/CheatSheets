Sheet 34

ORMs: Prisma & Drizzle

PrismaClient singleton · findMany · create · P2002 → 409 · Drizzle db.select().from() · migrations

Description

An ORM maps tables to typed objects so you write prisma.todo.findMany() instead of SQL strings. Prisma uses its own schema file and generates a client; Drizzle defines tables in TypeScript and keeps a SQL-like query API. Either way: create one client for the app, translate known database errors to HTTP codes, and run migrations as a deploy step, not at request time.

Notes

  • Prisma unique-constraint error: code P2002; record not found: P2025
  • Drizzle returns plain objects; .returning() for inserted rows (Postgres)
  • Migrations: prisma migrate dev / drizzle-kit generate + migrate
  • Prisma set covers schema, relations and the client in depth

The Same Routes, Two ORMs

// ── Prisma ──
import { prisma } from "./db.js";             // one shared client

app.get("/todos", async (req, res) => {
  res.json(await prisma.todo.findMany({
    where: { userId: req.user.id, done: false },
    orderBy: { createdAt: "desc" }, take: 20,
  }));
});
app.post("/users", async (req, res) => {
  try {
    res.status(201).json(await prisma.user.create({ data: req.valid.body }));
  } catch (err) {
    if (err.code === "P2002") throw new HttpError(409, "Email already used");
    throw err;
  }
});

// ── Drizzle ──
import { drizzle } from "drizzle-orm/node-postgres";
import { eq, and, desc } from "drizzle-orm";
import { todos } from "./schema.js";
const db = drizzle(process.env.DATABASE_URL);

app.get("/v2/todos", async (req, res) => {
  res.json(await db.select().from(todos)
    .where(and(eq(todos.userId, req.user.id), eq(todos.done, false)))
    .orderBy(desc(todos.createdAt)).limit(20));
});
app.post("/v2/todos", async (req, res) => {
  const [row] = await db.insert(todos)
    .values({ ...req.valid.body, userId: req.user.id }).returning();
  res.status(201).json(row);
});

Code Explained

Shared client — one connection pool for the app
take / .limit() — always bound list queries
P2002 — translate to 409 instead of a 500
Drizzle eq, and, desc — typed SQL operators

Prefer / Avoid

  • new PrismaClient() inside handlers → one exported client
  • Running migrations on app start in production → a separate deploy step
  • Selecting whole rows with passwords → select / pick only needed columns

⚠ Common Mistakes

  • Creating a client per request: exhausts database connections fast
  • Returning ORM objects with password hashes straight to res.json
  • Leaving N+1 queries in list endpoints: use include / joins

✓ Tips & Best Practices

  • Map ORM errors in one place: the error handler (sheet 25)
  • Use $transaction([...]) / db.transaction(async (tx) => …) for multi-step writes
  • Log slow queries in development (log: ["query"] in Prisma)

Quick Summary

  • one client — shared
  • findMany / select().from() — reads
  • map P2002 → 409
  • migrations — deploy step
