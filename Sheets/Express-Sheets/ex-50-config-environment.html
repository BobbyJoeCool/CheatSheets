Sheet 50

Configuration & Environments

NODE_ENV=production · process.env · --env-file · validating config with zod · app.get("env") · secrets

Description

Configuration comes from environment variables so the same build runs in dev, staging and production. Read and validate them once at startup into a typed config object, and crash immediately if something required is missing. Set NODE_ENV=production in production: Express then caches views, hides stack traces from its default error handler, and many libraries switch to faster code paths.

Notes

  • app.get("env") mirrors NODE_ENV (default "development")
  • Node 20.6+ loads .env with --env-file; 22.9+ has --env-file-if-exists
  • Never commit .env; commit .env.example with dummy values
  • Platforms (Render, Fly, ECS) inject env vars; no .env in production

Validated Config Module

// src/config.js
import { z } from "zod";

const Env = z.object({
  NODE_ENV: z.enum(["development", "test", "production"])
    .default("development"),
  PORT: z.coerce.number().int().default(3000),
  DATABASE_URL: z.string().url(),
  SESSION_SECRET: z.string().min(32),
  CORS_ORIGINS: z.string().default("")
    .transform((s) => s.split(",").filter(Boolean)),
  LOG_LEVEL: z.enum(["debug", "info", "warn", "error"]).default("info"),
});

const parsed = Env.safeParse(process.env);
if (!parsed.success) {
  const bad = parsed.error.issues.map((i) => i.path.join("."));
  console.error("Invalid environment:", bad.join(", "));
  process.exit(1);                            // fail fast at boot
}
const isProd = parsed.data.NODE_ENV === "production";
export const config = Object.freeze({ ...parsed.data, isProd });

// elsewhere
import { config } from "./config.js";
app.use(cors({ origin: config.CORS_ORIGINS, credentials: true }));
app.listen(config.PORT);

Code Explained

z.coerce.number() — env vars are always strings
process.exit(1) — fail at boot, not at the first request
Object.freeze — config can't be changed at runtime
Only config.js reads process.env

Prefer / Avoid

  • process.env.X scattered through the code → one validated config module
  • Defaults for secrets (|| "dev-secret") → required in production; fail if missing
  • Branching on NODE_ENV everywhere → explicit settings (config.LOG_LEVEL)

⚠ Common Mistakes

  • Running production without NODE_ENV=production: slower views and stack traces in error pages
  • Validating config lazily: the app boots fine and fails on the first real request
  • Logging process.env at startup: secrets end up in log storage

✓ Tips & Best Practices

  • Print a redacted config summary at boot (keys, not values)
  • Keep feature flags in config, not in if (isProd) checks
  • Use the platform's secret store (AWS Secrets Manager, Doppler) for rotation

Quick Summary

  • env vars — config source
  • validate once — fail fast
  • NODE_ENV=production — always in prod
  • .env — local only
