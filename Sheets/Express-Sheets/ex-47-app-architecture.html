Sheet 47

Application Architecture

routes → controllers → services → data layer · dependency injection by hand · createApp() factory · config module · feature folders

Description

As an app grows, split it into layers: routes map URLs, controllers translate HTTP to function calls, services hold business rules, and a data layer talks to the database. A createApp(deps) factory that receives its dependencies (DB, cache, mailer) makes testing easy: pass fakes in tests, real clients in server.js. Group files by feature once there are more than a handful of resources.

Notes

  • Services never touch req / res: they take plain values and throw errors
  • Controllers stay thin: validate, call one service method, respond
  • Config is read and validated once, in one module
  • No framework needed for DI; function arguments are enough

Wiring with Plain Functions

// todos.service.js: business rules, no HTTP
export const todoService = ({ repo, clock }) => ({
  async complete(id, userId) {
    const todo = await repo.find(id);
    if (todo?.userId !== userId) throw new HttpError(404, "Todo not found");
    return repo.update(id, { done: true, doneAt: clock.now() });
  },
});

// todos.routes.js: HTTP in, HTTP out
export const todoRoutes = (svc) => Router()
  .post("/:id/complete", async (req, res) =>
    res.json(await svc.complete(req.params.id, req.user.id)));

// app.js
export function createApp({ db, clock = { now: () => new Date() } }) {
  const todos = todoService({ repo: todoRepo(db), clock });
  return express().use(express.json())
    .use("/api/todos", todoRoutes(todos)).use(errorHandler);
}

// server.js
createApp({ db: new pg.Pool(config.db) }).listen(config.port);

Code Explained

Service takes repo and clock — fake both in tests
Route file only maps HTTP to the service
createApp — no globals; build as many apps as tests need
server.js is the only place real clients are created

Prefer / Avoid

  • Services that read req.body → services take plain arguments
  • Importing the DB client everywhere → inject it through createApp
  • A heavy DI framework for a small app → factory functions; NestJS if you want the full thing

⚠ Common Mistakes

  • Throwing HTTP-shaped errors from the repo: the data layer shouldn't know about status codes
  • Module-level DB clients: tests can't swap them without mocking imports
  • Splitting a 5-route app into 20 files: structure should follow size

✓ Tips & Best Practices

  • Write services first and test them without Express at all
  • Keep one index.js per feature that exports its router factory
  • Look at NestJS when you want enforced modules and DI (sheet 55)
