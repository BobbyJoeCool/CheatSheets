Custom Errors & 404 Handling

class HttpError extends Error · err.status · http-errors · catch-all 404 · JSON error envelope · unhandledRejection

Description

A small error class with a status and a machine-readable code makes errors predictable: throw it from anywhere, and one error handler turns it into a JSON response. Unmatched routes are not errors in Express; add a 404 middleware (no path) after all routes. For crashes outside requests, log and exit from process.on("unhandledRejection") and "uncaughtException".

Notes

  • http-errors gives you createError(404, "msg") with the right name and status
  • err.expose (http-errors) is true for 4xx: safe to show the message
  • Keep an error code ("TODO_NOT_FOUND") separate from the human message
  • Let a process manager restart the app after a fatal error

Error Class, 404, Envelope

// errors.js
export class HttpError extends Error {
  constructor(status, message, code = `HTTP_${status}`) {
    super(message);
    this.name = "HttpError";
    this.status = status;
    this.code = code;
  }
}

// in a route
if (!todo) throw new HttpError(404, "Todo not found", "NOT_FOUND");

// after all routes: 404, then the error envelope
app.use((req, res, next) => next(new HttpError(404, `No route ${req.path}`)));
app.use((err, req, res, next) => {
  const status = err.status ?? 500;
  res.status(status).json({ error: {
    code: err.code ?? "INTERNAL",
    message: status < 500 ? err.message : "Something went wrong",
    requestId: req.id,
  } });
});

process.on("unhandledRejection", (err) => {
  console.error(err);
  process.exit(1);
});

Code Explained

this.status — read by your handler and Express's default handler
404 middleware has no path and sits after every route
One envelope shape: { error: { code, message, details, requestId } }
Exit on unhandled rejections; the supervisor restarts cleanly

Prefer / Avoid

  • res.status(404).send("nope") scattered around → throw notFound("Todo")
  • throw "not found" (a string) → throw Error subclasses (stack traces)
  • Catch-all app.get("*") for 404 → final app.use((req, res, next) => …)

⚠ Common Mistakes

  • Throwing strings or plain objects: no stack trace, and err.status checks break
  • Leaking database messages in 500 responses: exposes table names and queries
  • Keeping the process alive after uncaughtException: state may be corrupt

✓ Tips & Best Practices

  • Add Error.captureStackTrace(this, HttpError) to trim the constructor frame
  • Follow RFC 9457 (application/problem+json) if clients expect it
  • Return the same envelope for 404 routes and 404 records

Quick Summary

  • HttpError(status, msg) — throwable errors
  • 404 middleware — after all routes
  • one error envelope — { error: {…} }
  • fatal errors — log and exit
