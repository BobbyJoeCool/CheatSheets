Server-Sent Events & Streaming

text/event-stream · res.write() · res.flushHeaders() · req.on("close") · stream.pipeline(src, res) · large files

Description

res is a writable stream, so you can send a response in pieces. Server-Sent Events use that for one-way live updates: set Content-Type: text/event-stream, keep the connection open, and write data: lines; the browser's EventSource reconnects automatically. For big files or generated exports, pipe a readable stream into res with stream.pipeline so memory stays flat and errors clean up both ends.

Notes

  • Each SSE message ends with a blank line (\n\n)
  • event:, id:, retry: fields are optional
  • Compression middleware buffers output: skip it for SSE or flush
  • Proxies may need X-Accel-Buffering: no (Nginx)

SSE Feed & Streamed Export

import { pipeline } from "node:stream/promises";
import { createReadStream } from "node:fs";

const clients = new Set();

app.get("/events", (req, res) => {
  res.set({ "Content-Type": "text/event-stream", "Cache-Control": "no-cache",
            Connection: "keep-alive", "X-Accel-Buffering": "no" });
  res.flushHeaders();                         // send headers now
  res.write("retry: 5000\n\n");               // client reconnect delay
  clients.add(res);
  const ping = setInterval(() => res.write(": ping\n\n"), 25_000);
  req.on("close", () => { clearInterval(ping); clients.delete(res); });
});

export const broadcast = (event, data) => {
  const msg = `event: ${event}\ndata: ${JSON.stringify(data)}\n\n`;
  for (const res of clients) res.write(msg);
};

app.get("/exports/todos.csv", async (req, res) => {
  res.attachment("todos.csv");
  await pipeline(db.todos.streamCsv(), res);  // rejects → error middleware
});

app.get("/videos/:name", async (req, res) => {
  res.type("mp4");
  await pipeline(createReadStream(`/media/${safe(req.params.name)}`), res);
});
// browser: new EventSource("/events").addEventListener("todo", (e) => …)

Code Explained

flushHeaders — the browser sees the stream open immediately
Comment lines (: ping) keep idle proxies from closing it
req.on("close") — remove clients that left
pipeline — backpressure + destroys both streams on error

Prefer / Avoid

  • Building a 500 MB CSV in memory → stream rows with pipeline
  • src.pipe(res) without error handling → await pipeline(src, res)
  • WebSockets for server→client only → SSE (plain HTTP, auto-reconnect)

SSE Message Fields

FieldPurpose
data:payload (repeat for lines)
event:named event type
id:resume with Last-Event-ID
retry:reconnect ms
: commentkeep-alive

Streaming Calls

CallDoes
res.write(chunk)send a piece
res.flushHeaders()send headers now
res.end()finish
pipeline(src, res)pipe + errors
res.on("drain")ready for more (backpressure)

⚠ Common Mistakes

  • Leaving compression() on the SSE route: events arrive in bursts or never
  • Not removing closed clients: writes to dead sockets and memory leaks
  • Using pipe() and ignoring errors: file handles leak when the client disconnects

✓ Tips & Best Practices

  • Send an id: with each event so clients can resume after a drop
  • Stream LLM output the same way: write tokens as they arrive
  • Use res.sendFile for plain files: it already streams with ranges (16)

Quick Summary

  • SSE — text/event-stream + data: lines
  • flushHeaders — open the stream
  • req.on("close") — cleanup
  • pipeline(src, res) — stream big responses
