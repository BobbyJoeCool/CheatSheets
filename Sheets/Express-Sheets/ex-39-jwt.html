Sheet 39

JWT Authentication

jsonwebtoken sign() / verify() · Authorization: Bearer · expiresIn · refresh tokens · httpOnly cookie · 401 vs 403

Description

A JSON Web Token is a signed string holding claims (user id, role, expiry). The server signs it at login and verifies the signature on each request, so no session store is needed. That also means a JWT can't be revoked before it expires, so keep access tokens short (5–15 min) and issue a longer-lived refresh token that you can revoke.

Notes

  • JWTs are signed, not encrypted: never put secrets in the payload
  • Send as Authorization: Bearer <token> or in an httpOnly cookie
  • Always pin algorithms in verify
  • jwt.verify throws TokenExpiredError or JsonWebTokenError

Issue, Verify, Refresh

import jwt from "jsonwebtoken";
const { JWT_SECRET } = process.env;

const issue = (user) =>
  jwt.sign({ sub: String(user.id), role: user.role }, JWT_SECRET,
    { expiresIn: "15m", algorithm: "HS256" });

app.post("/auth/login", async (req, res) => {
  const user = await auth.check(req.valid.body);           // 401 inside
  const refresh = await refreshTokens.create(user.id);  // revocable
  res.cookie("refresh", refresh, { httpOnly: true, secure: true,
    sameSite: "strict", path: "/auth/refresh", maxAge: 30 * 24 * 3600e3 });
  res.json({ accessToken: issue(user) });
});

export const requireJwt = (req, res, next) => {
  const [scheme, token] = (req.get("authorization") ?? "").split(" ");
  if (scheme !== "Bearer" || !token) return res.sendStatus(401);
  try {
    req.user = jwt.verify(token, JWT_SECRET, { algorithms: ["HS256"] });
    next();
  } catch (err) {
    const expired = err.name === "TokenExpiredError";
    res.status(401).json({ error: expired ? "token expired" : "invalid token" });
  }
};

app.post("/auth/refresh", async (req, res) => {
  const user = await refreshTokens.consume(req.cookies.refresh);  // rotate
  if (!user) return res.sendStatus(401);
  res.json({ accessToken: issue(user) });
});

app.get("/api/me", requireJwt, (req, res) => res.json({ id: req.user.sub }));

Code Explained

sub — standard subject claim (user id, as a string)
Refresh cookie scoped to /auth/refresh only
algorithms: ["HS256"] — blocks algorithm-swap attacks
consume — one-time refresh tokens; reuse means theft

Prefer / Avoid

  • Access tokens that last days → 15 min access + revocable refresh
  • JWT in localStorage → memory or httpOnly cookie
  • jwt.decode() to authenticate → jwt.verify() with algorithms

⚠ Common Mistakes

  • Using jwt.decode instead of verify: anyone can forge a token
  • Weak or committed JWT_SECRET: tokens can be brute-forced or forged
  • Putting emails or permissions that change into long-lived tokens: stale until expiry

✓ Tips & Best Practices

  • Use RS256 / ES256 (key pairs) when other services verify your tokens
  • Use the jose library for JWKS and modern algorithms
  • Plain sessions are simpler for a single web app (sheet 37)
