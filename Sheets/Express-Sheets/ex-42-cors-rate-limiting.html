Sheet 42

CORS & Rate Limiting

cors({ origin, credentials }) · origin allowlist · preflight OPTIONS · express-rate-limit windowMs / limit · trust proxy

Description

Browsers block JavaScript from reading responses from another origin unless the server sends CORS headers. The cors package adds them and answers preflight OPTIONS requests. Rate limiting caps how many requests a client can make in a window and replies 429. Both depend on correct client identity: CORS on the Origin header, rate limits on req.ip (set trust proxy).

Notes

  • CORS only affects browsers; curl and servers ignore it
  • credentials: true needs an exact origin, never *
  • Preflight happens for non-simple requests (JSON bodies, custom headers)
  • Use a Redis store for limits across several instances

Allowlisted CORS + Tiered Limits

import cors from "cors";
import { rateLimit } from "express-rate-limit";
import { RedisStore } from "rate-limit-redis";

const allowed = new Set(["https://app.example.com", "http://localhost:5173"]);
app.use(cors({
  // no Origin header = same-origin request or a non-browser tool
  origin: (origin, cb) => cb(null, !origin || allowed.has(origin)),
  credentials: true,                    // allow cookies
  methods: ["GET", "POST", "PATCH", "DELETE"],
  allowedHeaders: ["Content-Type", "Authorization"],
  maxAge: 600,                          // cache preflight 10 min
}));

app.set("trust proxy", 1);              // real client IP for limits

const api = rateLimit({
  windowMs: 60_000, limit: 120,
  standardHeaders: "draft-8", legacyHeaders: false,
  store: new RedisStore({ sendCommand: (...a) => redis.sendCommand(a) }),
});
const login = rateLimit({
  windowMs: 15 * 60_000, limit: 5, skipSuccessfulRequests: true,
  message: { error: "Too many login attempts, try again later" },
});

app.use("/api", api);
app.post("/auth/login", login, loginHandler);

Code Explained

origin function — return true to reflect the request's origin
maxAge — fewer preflight round-trips
skipSuccessfulRequests — only failed logins count
RedisStore — shared counters across instances

Prefer / Avoid

  • origin: "*" with credentials: true → an explicit allowlist
  • One global limit for everything → tight limits on login/signup, looser on reads
  • app.options("*", cors()) → global app.use(cors()) (handles preflight)

⚠ Common Mistakes

  • Thinking CORS protects your API: it stops browsers reading responses, not attackers sending requests
  • Rate limiting without trust proxy behind a proxy: the proxy IP gets blocked for everyone
  • In-memory limit store on several instances: each counts separately

✓ Tips & Best Practices

  • Expose custom headers (X-Total-Count) with exposedHeaders or JS can't read them
  • Return Retry-After on 429 (standard headers do this)
  • Rate limit by user id (keyGenerator) on authenticated routes

Quick Summary

  • cors({ origin }) — allowlist origins
  • preflight — handled by cors()
  • rateLimit — 429 after limit
  • trust proxy — real IPs
