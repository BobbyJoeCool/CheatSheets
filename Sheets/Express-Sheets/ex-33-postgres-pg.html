Sheet 33

PostgreSQL with pg

new Pool() · pool.query(text, values) · $1 parameters · RETURNING · transactions · pool lifecycle

Description

The pg package is the standard PostgreSQL driver for Node. Create **one Pool at startup and share it: it keeps connections open and hands one to each query. Always pass values as parameters** ($1, $2) so the driver escapes them. For multi-statement transactions, check out a client with pool.connect(), and always release() it.

Notes

  • pool.query() borrows and returns a connection for one query
  • Results: rows (array of objects) and rowCount
  • Postgres error codes: 23505 unique violation, 23503 foreign key
  • Close the pool on shutdown: await pool.end()

Queries & a Transaction

import pg from "pg";
export const pool = new pg.Pool({
  connectionString: process.env.DATABASE_URL, max: 10 });

app.get("/todos/:id", async (req, res) => {
  const { rows } = await pool.query(
    "SELECT id, title, done FROM todos WHERE id = $1", [req.params.id]);
  if (!rows[0]) throw new HttpError(404, "Todo not found");
  res.json(rows[0]);
});

app.post("/todos", async (req, res) => {
  const { rows } = await pool.query(
    "INSERT INTO todos (title, user_id) VALUES ($1, $2) RETURNING *",
    [req.valid.body.title, req.user.id]);
  res.status(201).json(rows[0]);
});

app.post("/transfer", async (req, res) => {
  const client = await pool.connect();
  try {
    await client.query("BEGIN");
    const sql = "UPDATE accounts SET balance = balance + $1 WHERE id = $2";
    await client.query(sql, [-amt, from]);
    await client.query(sql, [amt, to]);
    await client.query("COMMIT");
    res.sendStatus(204);
  } catch (err) {
    await client.query("ROLLBACK");
    throw err;
  } finally {
    client.release();                           // always
  }
});

Code Explained

$1, $2 — placeholders; values never touch the SQL text
RETURNING * — get the inserted row back in one trip
pool.connect() — same connection for BEGIN…COMMIT
finally { client.release() } — or the pool runs dry

Prefer / Avoid

  • WHERE id = ${id} string SQL → $1 parameters
  • new Pool() per request → one pool for the whole app
  • Transactions with pool.query → pool.connect() client

⚠ Common Mistakes

  • Forgetting client.release() on an error path: the pool runs out and requests hang
  • Concatenating user input into SQL: injection
  • Running BEGIN with pool.query: each query may use a different connection

✓ Tips & Best Practices

  • Add pool.on("error", log) so idle-connection errors don't crash the app
  • Use a query builder or ORM for dynamic filters (sheet 34)
  • SQL set covers queries, joins and indexes in depth

Quick Summary

  • one Pool — shared
  • $1 params — always
  • RETURNING — get rows back
  • transactions — connect, BEGIN, release
