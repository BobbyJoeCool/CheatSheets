Rendering Views & Locals

res.render("page", data) · res.locals · app.locals · partials & layouts · escaping · view cache

Description

res.render(view, locals) renders a template and sends it as HTML. The data a template sees is merged from three places: **app.locals (whole app: site name, helpers), res.locals** (this request: current user, flash messages, set by middleware) and the object passed to render (this view). Later sources win on name clashes.

Notes

  • res.render(view, locals, cb) — with a callback, you send the HTML yourself
  • Render errors go to error middleware (or the callback)
  • Express 5 makes res.render behave asynchronously for every engine
  • res.locals is the standard place for per-request view data

Locals from Three Places

app.locals.siteName = "Todo App";                  // every view
app.locals.formatDate = (d) => d.toLocaleDateString("en-US");

app.use((req, res, next) => {                      // every request
  res.locals.user = req.user ?? null;
  res.locals.currentPath = req.path;
  res.locals.flash = req.session?.flash;
  if (req.session) delete req.session.flash;
  next();
});

app.get("/todos", async (req, res) => {
  const todos = await repo.list(req.user.id);
  res.render("todos/index", { title: "My Todos", todos }); // this view
});

// render to string, then post-process
app.get("/report", (req, res, next) => {
  res.render("report", { rows }, (err, html) => {
    if (err) return next(err);
    res.set("Cache-Control", "no-store").send(html);
  });
});

app.set("view cache", true);   // default in production

Code Explained

formatDate — helper functions can live in app.locals
res.locals.user — available in layouts and partials
"todos/index" — subfolders map to views/todos/index.ejs
Callback form — no automatic send; you control headers

Prefer / Avoid

  • Passing user to every res.render call → set res.locals.user once in middleware
  • Big business logic in templates → prepare data in the handler
  • view cache off in production → leave the production default on

⚠ Common Mistakes

  • Putting secrets in app.locals: every template (and its errors) can print them
  • Setting res.locals after res.render runs: the template has already been rendered
  • Forgetting return next(err) in the render callback: errors are swallowed

✓ Tips & Best Practices

  • Keep a res.locals middleware for user, flash, CSRF token and current path
  • Name views by resource: todos/index, todos/show, todos/form
  • Test rendered HTML with Supertest + .expect(/My Todos/)

Quick Summary

  • res.render(view, data) — render + send
  • app.locals — app-wide
  • res.locals — per request
  • callback — render to string
