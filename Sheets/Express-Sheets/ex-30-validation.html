Sheet 30

Request Validation

zod safeParse · validation middleware factory · express-validator body() · validationResult · 400 vs 422

Description

Never trust req.body, req.query or req.params. A schema library describes the shape you expect, checks the input, and gives you typed, cleaned data or a list of problems. Zod is the common choice for JS/TS; express-validator chains checks per field. Wrap either in a middleware factory so routes declare their schema in one line.

Notes

  • Validate at the edge, before any business logic or DB call
  • Use z.coerce.number() for query/params (they're strings)
  • Return all problems at once, with field paths
  • Strip unknown fields so clients can't set role: "admin"

Zod Validation Middleware

import { z } from "zod";

const TodoBody = z.object({
  title: z.string().trim().min(1).max(200),
  due: z.coerce.date().optional(),
  priority: z.enum(["low", "normal", "high"]).default("normal"),
});                                         // unknown keys stripped
const ListQuery = z.object({
  page: z.coerce.number().int().min(1).default(1),
  done: z.enum(["true", "false"]).transform((v) => v === "true").optional(),
});

const validate = (schemas) => (req, res, next) => {
  req.valid = {};
  for (const [part, schema] of Object.entries(schemas)) {
    const result = schema.safeParse(req[part]);
    if (!result.success) {
      const details = result.error.issues.map((i) => ({
        path: [part, ...i.path].join("."), message: i.message }));
      return res.status(400).json({ error: { code: "VALIDATION", details } });
    }
    req.valid[part] = result.data;
  }
  next();
};

app.post("/todos", validate({ body: TodoBody }), (req, res) =>
  res.status(201).json(repo.create(req.valid.body)));
app.get("/todos", validate({ query: ListQuery }), (req, res) =>
  res.json(repo.list(req.valid.query)));

Code Explained

safeParse — returns { success, data, error }; never throws
req.valid — cleaned data; req.query is read-only in Express 5
coerce — turns "2" into 2 for query strings
issues[].path — e.g. body.title

Prefer / Avoid

  • if (!req.body.title) checks by hand → a schema per route
  • Overwriting req.query with parsed data → store on req.valid
  • z.object(...).passthrough() for bodies → default strip (or .strict())

⚠ Common Mistakes

  • Validating req.body but using req.body afterwards: defaults and trimming are lost
  • Using z.number() for query params: "5" is a string and always fails
  • Returning only the first error: users fix forms one field at a time

✓ Tips & Best Practices

  • Share zod schemas with the front end for matching client checks
  • Infer TS types with z.infer<typeof TodoBody> (sheet 46)
  • Pick 400 or 422 for validation and use it everywhere

Quick Summary

  • schema — describe expected input
  • safeParse — check without throwing
  • validate({ body, query }) — middleware
  • req.valid — cleaned data
