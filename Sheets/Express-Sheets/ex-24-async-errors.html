Sheet 24

Async Errors in Express 5

rejected promises → error middleware · async handlers · throw · callback APIs need next(err) · express-async-errors

Description

In Express 5, a route handler or middleware that returns a rejected promise has its rejection passed to next(err) for you. So async handlers can simply await and throw. This removes the try/catch and asyncHandler wrappers Express 4 needed. Errors thrown inside callbacks (timers, event emitters, old callback APIs) are still outside the promise and must be forwarded with next(err) yourself.

Notes

  • Rejecting with no value or a falsy value → Express creates an Error
  • Works for app.param callbacks and router middleware too
  • Unhandled rejections outside requests still need process.on("unhandledRejection")
  • express-async-errors / express-async-handler are no longer needed

Before & After

// Express 5: just await and throw
app.get("/todos/:id", async (req, res) => {
  const todo = await db.todos.find(Number(req.params.id));  // may reject
  if (!todo) throw new HttpError(404, "Todo not found");
  res.json(todo);
});

// returning a promise works too
app.get("/users", (req, res) => db.users.all().then((u) => res.json(u)));

// still manual: errors inside callbacks
app.get("/legacy", (req, res, next) => {
  fs.readFile("data.json", "utf8", (err, text) => {
    if (err) return next(err);               // forward yourself
    res.type("json").send(text);
  });
});

// still manual: work after the response
app.post("/jobs", async (req, res) => {
  res.status(202).json({ queued: true });
  sendEmail(req.body).catch((err) => req.log.error(err));  // not next()
});

// Express 4 style you can delete:
// app.get("/x", asyncHandler(async (req, res) => { … }));

Code Explained

throw in an async handler → rejected promise → error middleware
Callback errors happen later, outside the promise: call next(err)
Background work after responding must catch its own errors
Use fs/promises to avoid the callback case entirely

Prefer / Avoid

  • try { … } catch (e) { next(e) } in every handler → plain async + throw
  • express-async-errors patch → remove it on Express 5
  • Callback-style fs.readFile → await fs.readFile from node:fs/promises

Express 4 → 5

  • 4.x rejected promises hung the request or crashed → 5.x passed to next(err) automatically
  • 4.x needed asyncHandler wrappers → 5.x not needed

⚠ Common Mistakes

  • Keeping asyncHandler wrappers and *also* try/catch: double handling hides the real error
  • Throwing inside a setTimeout or stream.on("data") callback: process crashes
  • Calling next(err) after already sending: the error handler can't respond

✓ Tips & Best Practices

  • Prefer promise APIs (node:fs/promises, stream/promises) so throws stay catchable
  • Use try/catch only when you can do something useful with the error
  • Add process.on("unhandledRejection", …) to log and exit (sheet 25)

Quick Summary

  • async handlers — throw freely
  • rejections → error middleware
  • callbacks — next(err) yourself
  • drop express-async-errors
