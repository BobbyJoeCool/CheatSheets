Sheet 05

Route Methods

app.get · post · put · patch · delete · app.all() · route order · first match wins

Description

A route is an HTTP method, a path and one or more handlers. Express checks routes and middleware in the order they were added and runs the first match; a handler either sends a response or calls next() to pass control on. If nothing sends a response, Express's built-in 404 handler replies Cannot GET /path.

Notes

  • Methods mirror HTTP verbs: get post put patch delete head options
  • app.get also answers HEAD requests automatically
  • app.all(path, fn) — every method; good for per-path middleware
  • Handler signature: (req, res, next); next is optional if you always respond

CRUD on One Resource

const todos = new Map();
let nextId = 1;

app.get("/todos", (req, res) => {          // list
  res.json([...todos.values()]);
});

app.get("/todos/stats", (req, res) => {    // fixed path FIRST
  res.json({ count: todos.size });
});

app.get("/todos/:id", (req, res) => {      // then the param path
  const todo = todos.get(Number(req.params.id));
  if (!todo) return res.sendStatus(404);
  res.json(todo);
});

app.post("/todos", (req, res) => {
  const todo = { id: nextId++, ...req.body };
  todos.set(todo.id, todo);
  res.status(201).json(todo);
});

app.delete("/todos/:id", (req, res) => {
  todos.delete(Number(req.params.id));
  res.sendStatus(204);                     // no body
});

Code Explained

/todos/stats before /todos/:id, or "stats" becomes the id
return res.sendStatus(404) — return stops the handler there
res.status(201).json() — status setters chain
req.body needs express.json() mounted (sheet 13)

Prefer / Avoid

  • Verbs in paths like /getTodos → GET /todos
  • app.del() → app.delete()
  • One handler checking req.method → one route per method

Express 4 → 5

  • 4.x app.del() alias → 5.x removed; use app.delete()

Route API

CallMatches

app.post(p, fn)POST on p
app.all(p, fn)any method on p
app.METHOD(p, a, b)runs a then b
app.route(p)chain methods (10)
router.get(p, fn)same on a Router (09)

⚠ Common Mistakes

  • Ordering /users/:id above /users/me: me hits the param route
  • Forgetting return before an early res.send: code keeps running and sends twice
  • Sending a body with 204: Node drops it, and clients that expect one get nothing

✓ Tips & Best Practices

  • Group a resource's routes on a Router (sheet 09)
  • Use res.sendStatus(code) for empty responses
  • Log unmatched routes with a final 404 middleware (sheet 25)

Quick Summary

  • app.METHOD(path, fn) — one route
  • registration order — first match wins
  • next() — pass to the next match
  • app.all — every method
