Sheet 37

Sessions with express-session

session({ secret, resave, saveUninitialized }) · req.session · cookie options · connect-redis · regenerate · destroy

Description

express-session gives each browser a signed session-id cookie and keeps the data on the server in a store. Anything you put on req.session is saved after the response. The default MemoryStore leaks memory and loses sessions on restart, so production apps use Redis or a database store. Regenerate the session on login to stop session fixation.

Notes

  • resave: false, saveUninitialized: false — the recommended settings
  • Cookie is named connect.sid unless you set name
  • Set app.set("trust proxy", 1) when cookie.secure is on behind a proxy
  • Mount after express.static so assets don't touch the store

Redis-Backed Sessions

import session from "express-session";
import { RedisStore } from "connect-redis";

app.set("trust proxy", 1);
app.use(session({
  store: new RedisStore({ client: redis, prefix: "sess:" }),
  name: "sid",
  secret: process.env.SESSION_SECRET,     // or [new, old] to rotate
  resave: false,                          // don't save unchanged sessions
  saveUninitialized: false,               // no cookie until something is stored
  cookie: { httpOnly: true, secure: true, sameSite: "lax",
            maxAge: 7 * 24 * 3600e3 },
}));

app.post("/login", async (req, res, next) => {
  const user = await auth.verify(req.valid.body);
  req.session.regenerate((err) => {       // new id: stops fixation
    if (err) return next(err);
    req.session.userId = user.id;
    res.redirect(303, "/dashboard");
  });
});

app.post("/logout", (req, res, next) => {
  req.session.destroy((err) =>
    err ? next(err) : res.clearCookie("sid").redirect("/"));
});

Code Explained

RedisStore — sessions survive restarts and scale across instances
regenerate — new session id after login
req.session.userId = … — saved automatically after the response
destroy + clearCookie("sid") — full logout

Prefer / Avoid

  • Default MemoryStore in production → Redis / database store
  • Keeping the same session id across login → req.session.regenerate()
  • Storing the whole user object → store userId; load the user per request

req.session Methods

MethodDoes
regenerate(cb)new id, empty data

⚠ Common Mistakes

  • cookie.secure: true without trust proxy behind HTTPS termination: cookie never sets
  • Using MemoryStore with several instances: users bounce between logged in and out
  • Not regenerating on login: an attacker-planted session id becomes authenticated

✓ Tips & Best Practices

  • Use req.session.save(cb) before redirecting if you modified the session and see races
  • Expire idle sessions with rolling: true + a short maxAge
  • Sessions + sameSite: "lax" + CSRF tokens for form apps (sheet 43)

Quick Summary

  • session({...}) — server-side sessions
  • store — Redis in production
  • regenerate on login
  • destroy on logout
