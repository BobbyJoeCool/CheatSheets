Sheet 29

REST API Design

resource routes · CRUD ↔ HTTP methods · 201 + Location · 204 · idempotency · consistent JSON

Description

A REST API models resources as nouns in URLs and uses HTTP methods as the verbs. GET reads, POST creates, PUT replaces, PATCH changes some fields, DELETE removes. Good APIs return accurate status codes, a Location header for created resources, and the same JSON shape everywhere. Express gives you the routing; these conventions are up to you.

Notes

  • Plural nouns: /todos, /todos/7, /users/3/todos
  • Idempotent: GET, PUT, DELETE can be retried safely; POST can't
  • Return the created or updated resource so clients don't need a second call
  • HTTP set covers methods, status codes and headers in depth

A Complete Resource

const r = express.Router();

r.get("/", async (req, res) => res.json(await repo.list()));

r.get("/:id", async (req, res) => {
  res.json(await repo.findOrThrow(req.params.id));       // 404 via HttpError
});

r.post("/", async (req, res) => {
  const todo = await repo.create(req.body);
  res.status(201).location(`${req.baseUrl}/${todo.id}`).json(todo);
});

r.put("/:id", async (req, res) => {                      // full replace
  res.json(await repo.replace(req.params.id, req.body));
});

r.patch("/:id", async (req, res) => {                    // partial
  res.json(await repo.update(req.params.id, req.body));
});

r.delete("/:id", async (req, res) => {
  await repo.remove(req.params.id);
  res.sendStatus(204);
});

app.use("/api/todos", r);

Code Explained

201 + Location — where the new resource lives
PUT sends the whole object; missing fields are cleared
PATCH sends only what changes
204 — success, no body

Prefer / Avoid

  • POST /todos/7/delete → DELETE /todos/7
  • 200 { success: false } → a 4xx status with an error body
  • Different JSON shapes per endpoint → one envelope for lists, items and errors

⚠ Common Mistakes

  • Treating PUT as partial update: clients that send one field wipe the rest
  • Returning 200 for created resources: clients can't tell create from update
  • Nesting URLs three levels deep (/users/1/projects/2/todos/3): use filters instead

✓ Tips & Best Practices

  • Add an Idempotency-Key header for retry-safe POSTs (payments)
  • Document the API with OpenAPI (sheet 32)
  • Version from day one: mount under /api/v1

Quick Summary

  • nouns in URLs, verbs as methods
  • 201 + Location — creates
  • 204 — deletes
  • one JSON shape — everywhere
