Sheet 18

Middleware Basics

(req, res, next) · next() · ending vs passing on · app.use() order · res.locals · req augmentation

Description

Middleware is any function with the signature (req, res, next). Express keeps one ordered list of middleware and routes; each request walks that list until something sends a response. A middleware can change req/res, end the request by sending, or pass control with next(). If it does neither, the request hangs.

Notes

  • app.use(fn) runs fn for every method and every path
  • app.use("/api", fn) runs for paths starting with /api
  • res.locals — per-request data for later middleware and views
  • Async middleware may await; a rejected promise goes to error middleware

A Logging + Context Middleware

import { randomUUID } from "node:crypto";

// 1. runs first: add an id and a start time
app.use((req, res, next) => {
  req.id = req.get("X-Request-Id") ?? randomUUID();
  res.set("X-Request-Id", req.id);
  req.startedAt = performance.now();
  next();                                    // pass on
});

// 2. log when the response is done
app.use((req, res, next) => {
  res.on("finish", () => {
    const ms = (performance.now() - req.startedAt).toFixed(1);
    console.log(`${req.method} ${req.originalUrl} ${res.statusCode} ${ms}ms`);
  });
  next();
});

// 3. short-circuit: maintenance mode
app.use((req, res, next) => {
  if (process.env.MAINTENANCE) return res.status(503).send("Back soon");
  next();
});

app.get("/", (req, res) => res.send(`request ${req.id}`));

Code Explained

Order matters: #1 must run before anything reads req.id
res.on("finish") — fires after the last byte is handed off
return res.status(503)… — ends the chain; next not called
Adding props to req is the normal way to pass data on

Prefer / Avoid

  • Forgetting next() in a branch → every path either responds or calls next()
  • Global variables for request data → req.x or res.locals.x
  • Heavy work in global middleware → mount it only where needed (19)

⚠ Common Mistakes

  • Calling next() and then res.send(): two parties try to respond
  • Mounting a parser after the routes that need it: req.body is undefined there
  • Throwing inside a setTimeout callback: Express can't catch it; the process crashes

✓ Tips & Best Practices

  • Name middleware functions so stack traces and logs are readable
  • Use res.on("finish") for metrics instead of wrapping res.send
  • Keep the order list above as a comment at the top of app.js

Quick Summary

  • (req, res, next) — middleware shape
  • next() — continue
  • send — end the chain
  • order of app.use = run order
