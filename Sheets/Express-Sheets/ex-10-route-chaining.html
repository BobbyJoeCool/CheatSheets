app.route & Multiple Handlers

app.route("/books").get().post() · handler arrays · next("route") · next("router") · route middleware

Description

A route can take several handlers, run left to right, each calling next() to continue: the usual way to attach auth or validation to one route. app.route(path) returns a chainable object so all methods for one path sit together. Two special values skip ahead: next("route") jumps to the next matching route, and next("router") leaves the current router entirely.

Notes

  • Handlers can be passed individually, as arrays, or mixed
  • next("route") works only inside app.METHOD / router.METHOD handlers
  • next(err) with any other value skips to error middleware
  • router.route() works the same on routers

Chains & Skips

const validateTodo = (req, res, next) => {
  if (!req.body.title) return res.status(400).json({ error: "title required" });
  next();
};
const guards = [requireAuth, requireRole("editor")];

app.route("/todos/:id")
  .get(getTodo)
  .put(guards, validateTodo, replaceTodo)   // arrays + fns
  .delete(guards, deleteTodo);

// next("route"): skip to the next matching route
app.get("/users/:id",
  (req, res, next) => (req.params.id === "me" ? next("route") : next()),
  (req, res) => res.json(findUser(req.params.id)));
app.get("/users/:id", (req, res) => res.json(req.user));  // "me"

// next("router"): bail out of a whole router
const admin = express.Router();
admin.use((req, res, next) => (req.user?.isAdmin ? next() : next("router")));
admin.get("/stats", stats);
app.use("/admin", admin);
app.use("/admin", (req, res) => res.sendStatus(403));

Code Explained

app.route(path) — one path, many methods, no repetition
guards array — reused across methods
next("route") — remaining handlers of this route are skipped
next("router") — continues after the app.use that mounted admin

Prefer / Avoid

  • Copy-pasting auth checks into handlers → a middleware in the handler list
  • Two app.get("/x/:id") blocks far apart → app.route() keeps them together
  • Nested ifs for special ids → next("route") to a dedicated route

⚠ Common Mistakes

  • Calling next() after sending a response: the next handler tries to send again
  • Using next("route") in app.use middleware: it is ignored there
  • Passing next("Route") (wrong case): it's treated as an error value

✓ Tips & Best Practices

  • Keep handler lists short: auth, validate, handle
  • Export guard arrays (const adminOnly = [auth, role("admin")]) for reuse
  • Prefer explicit routes over clever next("route") chains when you can

Quick Summary

  • multiple handlers — run in order
  • app.route(p) — chain methods
  • next("route") — skip to next route
  • next("router") — leave router
