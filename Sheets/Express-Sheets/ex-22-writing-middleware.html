Sheet 22

Writing Configurable Middleware

factory (opts) => (req, res, next) · async middleware · res.on("finish") · request-id · timing · packaging

Description

Reusable middleware is usually a factory: a function that takes options and returns the (req, res, next) function. That lets one implementation serve many routes with different settings, the same way express.json({ limit }) works. Express 5 handles async middleware: if the returned promise rejects, the error goes to your error handler.

Notes

  • Validate options once in the factory, not on every request
  • Use res.on("finish") / "close" to run code after the response
  • Don't monkey-patch res.send; listen to events or wrap in a handler instead
  • Export the factory as the default export of its own module

Three Reusable Middleware

// 1. role guard factory
export const requireRole = (...roles) => (req, res, next) => {
  if (!req.user) return res.sendStatus(401);
  if (!roles.includes(req.user.role)) return res.sendStatus(403);
  next();
};

// 2. response-time header with options
export function responseTime({ header = "X-Response-Time", digits = 1 } = {}) {
  return (req, res, next) => {
    const start = process.hrtime.bigint();
    res.on("finish", () => {
      const ms = Number(process.hrtime.bigint() - start) / 1e6;
      console.log(`${header}: ${ms.toFixed(digits)}ms`);
    });
    next();
  };
}

// 3. async loader: rejected promise → error middleware
export const loadUser = (repo) => async (req, res, next) => {
  req.user = req.session?.userId ? await repo.find(req.session.userId) : null;
  next();
};

app.use(responseTime({ digits: 2 }), loadUser(usersRepo));
app.delete("/todos/:id", requireRole("admin", "owner"), deleteTodo);

Code Explained

requireRole("admin") — returns a fresh middleware per call
Default params = {} — calling with no options still works
hrtime.bigint() — nanosecond clock, immune to clock changes
Headers can't be set in finish; log there or set them earlier

Prefer / Avoid

  • Copy-pasted middleware with tiny differences → one factory with options
  • Wrapping res.send to read the body → res.on("finish") + res.statusCode
  • .then().catch(next) boilerplate in Express 5 → plain async middleware

⚠ Common Mistakes

  • Calling the factory per request (app.use((req,res,next) => cors()(req,res,next))): rebuilds state every time
  • Trying res.set() inside finish: headers are already sent
  • Forgetting to call next() in the success path of async middleware: the request hangs

✓ Tips & Best Practices

  • Test middleware alone with fake req/res objects or a tiny app + Supertest (49)
  • Accept dependencies (repos, clients) as factory args for easy mocking
  • Look at on-finished and on-headers packages for edge cases

Quick Summary
