Sheet 44

WebSockets with Socket.IO

http.createServer(app) · new Server(server) · io.on("connection") · socket.emit / on · rooms · ws alternative

Description

HTTP is request/response; WebSockets keep a two-way connection open so the server can push messages. Express doesn't handle WebSockets itself, so you create the HTTP server explicitly and attach Socket.IO (or the lighter ws package) to it. Socket.IO adds reconnection, rooms, acknowledgements and fallbacks, at the cost of needing its own client library.

Notes

  • Share the same http.Server between Express and Socket.IO
  • io.engine.use(sessionMiddleware) reuses express-session (Socket.IO 4.6+)
  • Several instances need the Redis adapter to broadcast across servers
  • Load balancers need sticky sessions for Socket.IO's polling fallback

Chat Rooms

import { createServer } from "node:http";
import { Server } from "socket.io";

const server = createServer(app);                 // instead of app.listen
const io = new Server(server, {
  cors: { origin: "https://app.example.com", credentials: true } });

io.engine.use(sessionMiddleware);                 // req.session in sockets
io.use((socket, next) => {                        // auth for every connection
  const userId = socket.request.session?.userId;
  if (!userId) return next(new Error("unauthorized"));
  socket.data.userId = userId;
  next();
});

io.on("connection", (socket) => {
  socket.on("join", (room) => socket.join(room));
  socket.on("message", ({ room, text }, ack) => {
    io.to(room).emit("message", { from: socket.data.userId, text });
    ack?.({ ok: true });                          // acknowledgement
  });
  socket.on("disconnect", (reason) => console.log("left", reason));
});

app.post("/rooms/:id/announce", (req, res) => {   // push from a REST route
  io.to(req.params.id).emit("announcement", req.body);
  res.sendStatus(202);
});

server.listen(3000);

Code Explained

createServer(app) — one server for HTTP and WebSocket traffic
io.use — runs once per connection; reject with next(err)
io.to(room).emit — everyone in the room; socket.to(room) — everyone but sender
REST routes can push through io

Prefer / Avoid

  • Polling an endpoint every second → push with Socket.IO or SSE (45)
  • Trusting socket.handshake.query.userId → authenticate with the session or a token
  • Socket.IO for one-way updates → Server-Sent Events

⚠ Common Mistakes

  • Calling app.listen() and also server.listen(): two servers, sockets attached to the wrong one
  • Skipping auth in io.use: anyone can connect and join any room
  • Running several instances without the Redis adapter: messages reach only one server's clients

✓ Tips & Best Practices

  • Validate socket payloads like request bodies (zod)
  • Use @socket.io/redis-adapter when you scale out
  • Use ws when clients are plain browsers or devices speaking raw WebSocket

Quick Summary

  • new Server(server) — attach Socket.IO
  • rooms — join / to(room)
  • io.use — authenticate
