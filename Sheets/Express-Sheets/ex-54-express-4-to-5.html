Migrating from Express 4 to 5

path syntax changes · removed app.del / req.param() / res.sendfile · res.json(obj, status) · req.body / req.query defaults · v5-migration-recipe codemod

Description

Express 5 is a small major release: most apps upgrade in an afternoon. The big items are the path-to-regexp 8 route syntax, removed deprecated methods and argument orders, Node 18+, and behavior changes around req.body, req.query and rejected promises. Upgrade Node first, run the official codemod, then grep for the patterns in the tables below and run your tests.

Notes

  • npm install express@5 (and @types/express@5 for TS)
  • Express 4 is in maintenance; plan the move
  • Most middleware works unchanged; check routers that use * paths
  • Promise rejections now reach your error handler: remove wrappers

Upgrade Steps & Common Rewrites

# 1. upgrade and rewrite
npm install express@5
npx codemod@latest @expressjs/v5-migration-recipe   # all codemods

// 2. rewrite what the codemod misses
app.get("*", h)                → app.get("/{*all}", h)
app.get("/files/*", h)         → app.get("/files/*path", h)  // array
app.get("/user/:id?", h)       → app.get("/user{/:id}", h)
app.get("/:id(\\d+)", h)        → app.get("/:id", h) + validate
app.del("/x", h)               → app.delete("/x", h)
req.param("id")                → req.params.id / req.body.id / req.query.id
res.json(obj, 201)             → res.status(201).json(obj)
res.send(404)                  → res.sendStatus(404)
res.redirect("/x", 301)        → res.redirect(301, "/x")
res.redirect("back")           → res.redirect(req.get("Referrer") || "/")
res.sendfile(p)                → res.sendFile(p)
req.acceptsLanguage("en")      → req.acceptsLanguages("en")
asyncHandler(async (req,res)…) → async (req, res) => …

Code Explained

Codemod first, then grep for "*", :id?, res.json( with two args
Wildcards return arrays: req.params.path.join("/")
Optional params use braces
Run the full test suite: behavior changes don't show as errors

Prefer / Avoid

  • Staying on Express 4 for new work → upgrade; 5 is the supported line
  • Hand-editing every route → run the v5-migration-recipe codemod first
  • Keeping express-async-errors → remove it after upgrading

Express 4 → 5

  • 4.x req.body {} without parser → 5.x undefined
  • 4.x req.query writable, extended parser → 5.x read-only, simple parser

⚠ Common Mistakes

  • Leaving app.get("*") catch-alls: the app throws at startup on Express 5
  • Treating req.params.splat as a string after the upgrade: .split is not a function
  • Mutating req.query in middleware: silently ignored or throws

✓ Tips & Best Practices

  • Upgrade on a branch and run integration tests (49) before merging
  • Read the official migration guide on expressjs.com for the full list
  • Update @types/express together with Express
