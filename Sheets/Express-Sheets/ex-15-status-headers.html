Sheet 15

Status Codes & Headers

res.status() · invalid codes throw · res.set() · res.get() · res.type() · res.vary() · res.location()

Description

res.status(code) sets the status and returns res for chaining; in Express 5 it throws if the code isn't an integer from 100 to 999. res.set() sets headers (one or an object of many), res.get() reads one back, and res.append() adds to an existing header. res.type() sets Content-Type from a short name or extension. Headers must be set before the body is sent.

Notes

  • Default status is 200
  • res.set("Content-Type", "text/plain") adds charset=utf-8 automatically
  • res.location(url) sets Location (used with 201 and redirects)
  • res.links({ next: url }) builds a Link header for pagination

Status & Header Helpers

res.status(201).json(todo);                 // Created
res.status(404).json({ error: "not found" });

res.set("Cache-Control", "no-store");       // one header
res.set({                                   // several
  "X-Request-Id": req.id,
  "Cache-Control": "public, max-age=60",
});
res.append("Set-Cookie", "a=1; Path=/");    // keep existing values
res.get("Cache-Control");                   // "public, max-age=60"

res.type("json");          // application/json; charset=utf-8
res.type("png");           // image/png
res.vary("Accept-Language");                // add to Vary
res.location(`/todos/${todo.id}`);          // Location header
res.links({ next: "/todos?page=3", prev: "/todos?page=1" });

res.status(999);           // ok (in range)
res.status("200");         // throws in Express 5 (string)
res.status(1000);          // throws: out of range

Code Explained

res.set(obj) — sets each key; res.header is an alias
res.append — adds instead of replacing (cookies, Link)
res.type — extension or MIME type
Invalid res.status() values now fail loudly

Prefer / Avoid

  • Magic numbers sprinkled everywhere → a small HTTP constants object or http-status-codes
  • res.setHeader after res.json → set headers first; check res.headersSent
  • res.set("Set-Cookie", …) twice → res.cookie() (17) or res.append

Express 4 → 5

  • 4.x res.status("200") / res.status(0) accepted → 5.x throws unless integer 100–999
  • 4.x res.vary() with no field silently ignored → 5.x throws without a field

⚠ Common Mistakes

  • Setting headers after res.json(): ERR_HTTP_HEADERS_SENT
  • Returning 200 with { error } in the body: clients and monitoring think it worked
  • Passing req.query.code straight to res.status: a string throws in Express 5

✓ Tips & Best Practices

  • Use 201 + Location for creates and 204 for deletes
  • Keep a status table in the HTTP set (HTTP sheets) for the rest
  • Set security headers in one place with helmet() (sheet 41)

Quick Summary

  • res.status(code) — chainable status
  • res.set / append — headers
  • res.type — Content-Type
  • headers before body
