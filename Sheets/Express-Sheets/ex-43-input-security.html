Sheet 43

Input Security & CSRF

SQL / NoSQL injection · prototype pollution · XSS escaping · CSRF tokens (csrf-csrf) · sameSite · npm audit

Description

Most web vulnerabilities come from trusting input. Injection happens when input becomes code (SQL strings, Mongo operators, shell commands). XSS happens when input is rendered as HTML unescaped. CSRF happens when a browser sends your cookie on a request another site triggered. The fixes are parameters, escaping, validation, sameSite cookies and CSRF tokens for cookie-authenticated forms.

Notes

  • Parameterized queries stop SQL injection (sheet 33)
  • Validate types: { "$gt": "" } where a string was expected is an attack
  • Never merge user objects into config (Object.assign(cfg, req.body))
  • csurf is deprecated; use csrf-csrf or csrf-sync

Defenses in One Place

import { doubleCsrf } from "csrf-csrf";

// 1. type-check before querying (blocks NoSQL operator injection)
app.post("/login", async (req, res) => {
  const { email, password } = req.body;
  if (typeof email !== "string" || typeof password !== "string")
    return res.sendStatus(400);
  const user = await User.findOne({ email });          // safe: plain string
  // …
});

// 2. CSRF tokens for cookie-based forms
const { generateCsrfToken, doubleCsrfProtection } = doubleCsrf({
  getSecret: () => process.env.CSRF_SECRET,
  getSessionIdentifier: (req) => req.session.id,
});
app.use((req, res, next) => {
  res.locals.csrfToken = generateCsrfToken(req, res);
  next();
});
app.use(doubleCsrfProtection);           // checks POST/PUT/PATCH/DELETE
// form: <input type="hidden" name="_csrf" value="<%= csrfToken %>">

// 3. no prototype pollution from merges
const allowedKeys = ["title", "done"];
const patch = Object.fromEntries(
  Object.entries(req.body).filter(([k]) => allowedKeys.includes(k)));

// 4. never build shell commands from input
execFile("convert", [file.path, "out.png"]);   // not exec(`convert ${name}`)

Code Explained

typeof check — rejects { "$ne": null } objects
Double-submit CSRF — token in cookie + form, must match
Allowlist keys — __proto__ / constructor never get through
execFile with an args array — no shell parsing

Prefer / Avoid

  • csurf package → csrf-csrf / csrf-sync
  • Object.assign(obj, req.body) → pick allowed fields (or a zod schema)
  • child_process.exec with input → execFile / spawn with an args array

⚠ Common Mistakes

  • Escaping on input instead of output: data gets double-escaped and still unsafe elsewhere
  • Skipping CSRF because "it's an API" while auth uses cookies: browsers send them anyway
  • Ignoring npm audit warnings for direct dependencies

✓ Tips & Best Practices

  • Run npm audit --omit=dev in CI and update Express patch releases promptly
  • Validate every request with schemas (sheet 30); it closes most of these at once
  • Read the OWASP Top 10 and the Express security best practices page

Quick Summary

  • parameters — stop SQL injection
  • type checks — stop NoSQL injection
  • escape output + CSP — stop XSS
  • sameSite + tokens — stop CSRF
