Sheet 08

Query Strings

req.query · query parser · simple vs extended · qs · arrays ?tag=a&tag=b · read-only getter

Description

Everything after ? in the URL is parsed into **req.query. Express 5 uses the "simple"** parser by default (Node's querystring): flat keys only, repeated keys become arrays. The "extended" parser (qs) adds nested objects like ?filter[status]=done. Values are strings or arrays of strings, never numbers or booleans, so coerce and validate.

Notes

  • Missing key → undefined; empty value ?q= → ""
  • req.query is a getter in Express 5: you can't reassign it
  • Set the parser with app.set("query parser", "extended") or a function
  • Nested qs parsing is a classic source of type confusion and prototype bugs

Reading the Query

// GET /todos?status=done&limit=10&tag=home&tag=urgent
app.get("/todos", (req, res) => {
  const { status = "all", tag = [] } = req.query;
  const limit = Math.min(Math.max(parseInt(req.query.limit, 10) || 20, 1), 100);
  const tags = [].concat(tag);          // string or array → array

  console.log(req.query);
  // { status: "done", limit: "10", tag: ["home", "urgent"] }
  res.json({ status, limit, tags });
});

// opt in to nested objects (qs)
app.set("query parser", "extended");
// /todos?filter[status]=done&sort[by]=date
//   req.query.filter → { status: "done" }

// custom parser function
app.set("query parser", (str) =>
  Object.fromEntries(new URLSearchParams(str)));  // last value wins

Code Explained

Defaults in destructuring cover missing keys
Number(x) || 20 — falls back on NaN and 0; cap with Math.min
[].concat(tag) — normalizes one value vs many
Set the parser before routes that read req.query

Prefer / Avoid

  • Assigning req.query = cleaned → store results on req.validated or res.locals
  • Trusting req.query.limit as a number → coerce, clamp and validate
  • "extended" by default → "simple" unless you need nesting

Express 4 → 5

  • 4.x default "extended" (qs) parser → 5.x default "simple"
  • 4.x req.query writable → 5.x read-only getter

⚠ Common Mistakes

  • Checking if (req.query.done === true): the value is the string "true"
  • Assuming one value: ?tag=a&tag=b makes an array and tag.toLowerCase() throws
  • Passing req.query straight into a Mongo filter: ?role[$ne]=x with extended parsing injects operators

✓ Tips & Best Practices

  • Parse the whole query with zod and keep the typed result (sheet 30)
  • Build links with new URLSearchParams(obj).toString()
  • Use req.originalUrl if you need the raw query string

Quick Summary

  • req.query — parsed ?a=b pairs
  • "simple" — default flat parser
  • "extended" — nested (qs)
  • values are strings — coerce them
