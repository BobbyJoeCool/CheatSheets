Sheet 55

Express vs Fastify, Koa, Hono & NestJS

middleware model · schema validation · performance · TypeScript story · ecosystem size · when to pick each

Description

Express is the default Node web framework because it is simple and has the largest ecosystem, not because it's the fastest or most structured. Fastify adds JSON-Schema validation and much higher throughput, Koa is a minimal async-first successor from the same authors, Hono runs on Web Standard Request/Response across Node, Bun, Deno and edge runtimes, and NestJS adds modules, decorators and DI (on top of Express or Fastify).

Notes

  • All five run on Node; Hono also on Cloudflare Workers, Bun, Deno
  • NestJS uses Express by default; switch to Fastify with an adapter
  • Express middleware can be reused in NestJS directly, in Fastify via @fastify/express
  • Benchmarks favor Fastify and Hono; real apps are usually DB-bound

Prefer / Avoid

  • Picking a framework for benchmark numbers → pick for team, ecosystem and deploy target
  • Rewriting a working Express app for speed → profile first (52); fix hot paths
  • Express on edge runtimes → Hono (Web Standard APIs)

Express 4 → 5

  • 4.x needed wrappers for async errors (unlike Koa/Fastify) → 5.x async errors built in, closing the gap

⚠ Common Mistakes

  • Choosing NestJS for a three-route service: lots of ceremony for little gain
  • Assuming Express middleware drops into Koa or Hono: different signatures
  • Comparing frameworks with hello-world benchmarks: your database dominates real latency

✓ Tips & Best Practices

  • Keep business logic framework-free (sheet 47) so switching is cheap
  • Try Fastify for a new high-traffic service; keep Express where it works
  • FastAPI & Flask set covers the Python equivalents

Quick Summary

  • Express — simplest, biggest ecosystem
  • Fastify — speed + schemas
  • Hono — edge + Web Standards
  • NestJS — structure + DI
