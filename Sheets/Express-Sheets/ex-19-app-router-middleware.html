Sheet 19

App-Level & Router-Level Middleware

app.use(fn) · app.use("/path", fn) · router.use() · per-route middleware · middleware arrays · scoping

Description

Where you mount middleware decides which requests it sees. App-level app.use(fn) sees everything; adding a path limits it to that prefix. Router-level router.use(fn) sees only requests that reach that router. Route-level middleware sits in the handler list of one route. Mount as narrowly as you can so expensive work (auth, parsing, DB lookups) runs only where needed.

Notes

  • Prefix matching is by segment: /api matches /api/x but not /apiary
  • Inside app.use("/api", fn), req.url has the prefix stripped
  • app.use(a, b, c) and app.use([a, b]) mount several at once
  • A sub-app (express()) can be mounted like a router

Three Scopes

// app-level: every request
app.use(helmet());
app.use(express.json());

// app-level with a path: only /admin/*
app.use("/admin", requireAuth, requireRole("admin"));

// router-level: only requests that reach this router
const api = express.Router();
api.use(rateLimit({ windowMs: 60_000, limit: 100 }));
api.use((req, res, next) => {
  res.type("json");                 // all API responses are JSON
  next();
});
api.get("/todos", listTodos);

// route-level: one route
api.post("/todos", requireAuth, validate(todoSchema), createTodo);

app.use("/api", api);

// sub-app with its own settings
const docs = express();
docs.set("view engine", "ejs");
app.use("/docs", docs);

Code Explained

/admin guard — runs before any /admin route
Rate limit only counts API traffic, not static files
validate(schema) — factory returning middleware (22)
Sub-apps keep separate settings; routers don't have settings

Prefer / Avoid

  • requireAuth on every route by hand → router.use(requireAuth) for the group
  • Global JSON parser for a mostly-static site → express.json() on the API router
  • Path checks inside middleware (if (req.path.startsWith…)) → mount at that path

⚠ Common Mistakes

  • Expecting app.use("/api") to match /api-docs: prefixes match whole segments only
  • Putting auth on app globally: login and health routes get blocked too
  • Assuming a sub-app sees parent settings changed after mounting

✓ Tips & Best Practices

  • Mount public routes (health, login, static) before global auth
  • Use arrays of middleware as named policies: const staff = [auth, role("staff")]
  • Use app.all("/admin/{*rest}", guard) when you need method-agnostic exact paths

Quick Summary

  • app.use(fn) — global
  • app.use(path, fn) — prefix
  • router.use(fn) — one router
  • route-level — one route
