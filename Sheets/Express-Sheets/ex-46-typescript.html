Express with TypeScript

@types/express · Request<Params, ResBody, ReqBody, Query> · typed handlers · declaration merging req.user · tsx · type stripping

Description

Express is written in JavaScript; types come from **@types/express**. Request and Response are generics, so a handler can declare the shape of its params, body, query and response. Extra properties you add in middleware (req.user) are declared once with declaration merging. Run TypeScript directly in development with tsx or Node's built-in type stripping, and compile with tsc for production.

Notes

  • Install: npm i -D typescript @types/express @types/node tsx
  • @types/express 5.x matches Express 5
  • Node 22.18+ runs .ts files directly (erasable syntax only)
  • Generics: Request<Params, ResBody, ReqBody, ReqQuery>

Typed Handlers

import express from "express";
import type { Request, Response, NextFunction } from "express";
import { z } from "zod";

const TodoBody = z.object({
  title: z.string().min(1), done: z.boolean().default(false) });
type TodoIn = z.infer<typeof TodoBody>;
interface Todo extends TodoIn { id: number }

const app = express();
app.use(express.json());

type Err = { error: string };
app.get("/todos/:id",
  (req: Request<{ id: string }>, res: Response<Todo | Err>) => {
    const todo = repo.find(Number(req.params.id));
    if (!todo) return res.status(404).json({ error: "not found" });
    res.json(todo);
  });

app.post("/todos", (req: Request<{}, Todo, TodoIn>, res: Response<Todo>) => {
  res.status(201).json(repo.create(TodoBody.parse(req.body)));
});

const requireAuth = (req: Request, res: Response, next: NextFunction) =>
  req.user ? next() : res.sendStatus(401);     // req.user from merging

types/express.d.ts

import type { User } from "../src/models.js";
declare global {
  namespace Express {
    interface Request { user?: User; id: string }
  }
}
export {};

Code Explained

z.infer — one schema gives both runtime check and type
Response<Todo> — res.json() only accepts that shape
Request<{}, Todo, TodoIn> — {} params, response, body
Declaration merging — every req gains user and id

Prefer / Avoid

  • (req as any).user → declaration merging in a .d.ts
  • ts-node + nodemon → tsx watch or node --watch with type stripping
  • Trusting req.body types → parse with zod; types alone don't validate

⚠ Common Mistakes

  • Annotating req.body as TodoIn and skipping validation: types vanish at runtime
  • Forgetting export {} in the .d.ts: the global augmentation isn't applied
  • Using enums or namespaces with Node type stripping: not erasable; use tsx or tsc

✓ Tips & Best Practices

  • Set "module": "nodenext" and import .js extensions from .ts files
  • Type RequestHandler<…> once and reuse for many handlers
  • JavaScript & TypeScript set covers tsconfig in depth
