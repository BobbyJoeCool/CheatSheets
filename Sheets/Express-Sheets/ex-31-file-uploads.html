File Uploads with Multer

multer · upload.single() · .array() · .fields() · req.file · diskStorage · memoryStorage · limits · fileFilter

Description

Express's parsers don't handle multipart/form-data, the encoding browsers use for file uploads. Multer parses it, puts text fields in req.body and file info in req.file / req.files. Store files on disk, keep them in memory as Buffers (to forward to S3), and always set limits and a fileFilter so users can't fill your disk or upload executables.

Notes

  • Form needs enctype="multipart/form-data"; field name must match single("name")
  • Mount Multer per route, never globally
  • dest only: random filenames without extensions
  • Errors are MulterError with codes like LIMIT_FILE_SIZE

Avatar Upload with Limits

import multer from "multer";
import path from "node:path";
import { randomUUID } from "node:crypto";

const storage = multer.diskStorage({
  destination: "uploads/avatars",
  filename: (req, file, cb) =>
    cb(null, randomUUID() + path.extname(file.originalname)),
});

const upload = multer({
  storage,
  limits: { fileSize: 2 * 1024 * 1024, files: 1 },     // 2 MB
  fileFilter: (req, file, cb) =>
    cb(null, ["image/png", "image/jpeg", "image/webp"].includes(file.mimetype)),
});

app.post("/me/avatar", requireAuth, upload.single("avatar"), (req, res) => {
  if (!req.file) return res.status(400).json({ error: "image required" });
  res.status(201).json({ url: `/avatars/${req.file.filename}` });
});

const memory = multer({ storage: multer.memoryStorage(),
  limits: { fileSize: 5e6 } });
app.post("/docs", memory.array("files", 5), async (req, res) => {
  await Promise.all(req.files.map((f) => s3.put(f.originalname, f.buffer)));
  res.sendStatus(201);
});

app.use((err, req, res, next) => err instanceof multer.MulterError
  ? res.status(413).json({ error: err.code }) : next(err));

Code Explained

diskStorage — control folder and filename
fileFilter → cb(null, false) skips the file (no req.file)
memoryStorage — file.buffer; keep limits small
MulterError — map LIMIT_* codes to 413 / 400

Prefer / Avoid

  • file.originalname as the stored name → a generated name (no path tricks, no clashes)
  • No limits → fileSize and files on every uploader
  • Trusting mimetype alone → check magic bytes (file-type) for risky uses

⚠ Common Mistakes

  • Field name mismatch (single("photo") vs name="avatar"): LIMIT_UNEXPECTED_FILE
  • Using upload.any(): accepts unlimited unexpected files
  • Serving the upload folder with the same origin and no Content-Type checks: uploaded HTML runs as your site

✓ Tips & Best Practices

  • Upload straight to S3 with presigned URLs to skip your server entirely
  • Serve user files from a separate domain or with Content-Disposition: attachment
  • Use Multer 2.x (security fixes over 1.x)

Quick Summary

  • multer — parse multipart
  • single / array / fields — pick files
  • limits + fileFilter — always
  • MulterError — handle codes
