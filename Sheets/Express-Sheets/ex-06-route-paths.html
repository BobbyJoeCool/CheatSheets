Sheet 06

Route Paths & Patterns

string paths · /*splat · {/:id} optional · regex routes · reserved characters · strict routing

Description

Express 5 matches paths with path-to-regexp 8, which is stricter than the Express 4 version. Wildcards must be named (/*splat), optional parts go in braces (/users{/:id}), and regex characters like ?, +, (, ) are no longer allowed inside path strings. For real regex matching, pass a RegExp object instead of a string.

Notes

  • Paths are case-insensitive and ignore a trailing slash by default
  • /*splat needs at least one segment; /{*splat} also matches the bare /
  • req.params.splat is an array of segments: ["a", "b"]
  • Reserved in strings: ( ) [ ] ? + ! — escape with \\ to match literally
  • Param names must be JS identifiers, or quoted: /:"user-id"

Path Syntax (Express 5)

app.get("/about", h);                  // exact: /about, /About, /about/
app.get("/files/*path", h);            // /files/a/b.txt
//   req.params.path → ["a", "b.txt"]
app.get("/{*all}", h);                 // everything, including "/"

app.get("/users{/:id}", h);            // /users and /users/42
app.get("/docs{.:ext}", h);            // /docs and /docs.pdf
app.get("/:from-:to", h);              // /NYC-LAX → {from, to}

app.get(/^\/v(\d+)\/status$/, h);     // RegExp object
//   /v2/status → req.params[0] === "2"
app.get(["/home", "/index"], h);       // array of paths

app.set("case sensitive routing", true);  // /About ≠ /about
app.set("strict routing", true);          // /about/ ≠ /about

Code Explained

*path — named wildcard; the name becomes the param key
{ … } — optional group; replaces the old ? suffix
RegExp routes — capture groups land in req.params[0], [1]…
Settings apply to routes registered after they're set

Prefer / Avoid

  • app.get("*", …) catch-all → app.get("/{*all}", …) or a final app.use
  • /:id? optional param → {/:id}
  • Regex inside strings /:id(\\d+) → validate in the handler, or a RegExp route

Express 4 → 5

  • 4.x * unnamed wildcard → 5.x must be named: *splat
  • 4.x :id? optional, :id+ repeat → 5.x {/:id} braces; *name for repeats
  • 4.x (\\d+) regex in path strings → 5.x not supported; use a RegExp object

⚠ Common Mistakes

  • Upgrading to Express 5 with app.get("*"): it throws Missing parameter name at startup
  • Treating req.params.splat as a string: it's an array; join("/") it
  • Expecting /:id(\\d+) to restrict to digits: Express 5 rejects the pattern

✓ Tips & Best Practices

  • Run the Express 5 codemod to rewrite old patterns (sheet 54)
  • Validate ids in the handler or with app.param() instead of regex paths
  • Use a final app.use() (no path) for 404s rather than a * route

Quick Summary

  • :name — one segment
  • *name — many segments (array)
  • { … } — optional part
  • RegExp — full regex routes
