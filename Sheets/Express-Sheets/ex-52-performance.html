Sheet 52

Performance

compression · caching headers · avoid sync calls · cluster / PM2 cluster mode · view cache · autocannon

Description

Express itself is rarely the bottleneck; slow apps usually block the event loop with sync work, make too many database round-trips, or send uncompressed, uncached responses. Measure first with a load tester, fix the hot paths, and only then scale out across CPU cores with the cluster module or PM2, or across machines behind a load balancer.

Notes

  • One Node process uses one CPU core for JavaScript
  • Sync APIs (fs.readFileSync, bcrypt.hashSync, big JSON.parse) block every request
  • NODE_ENV=production alone gives a noticeable speedup
  • Compress at the proxy/CDN if one exists; skip compression() then

Common Wins

import compression from "compression";

app.use(compression({ threshold: 1024 }));          // gzip ≥ 1 KB

// cache what can be cached
app.use("/static", express.static(dist, { maxAge: "1y", immutable: true }));
app.get("/api/countries", (req, res) => {
  res.set("Cache-Control", "public, max-age=86400").json(countries);
});

// don't block the loop
app.get("/report", async (req, res) => {
  const data = await fs.promises.readFile(file, "utf8");   // not readFileSync
  res.json(await runInWorker("./report-worker.js", data)); // CPU off-thread
});

// batch DB work instead of N+1
const sql = "SELECT * FROM todos WHERE user_id = ANY($1)";
const { rows } = await db.query(sql, [ids]);

Code Explained

threshold — tiny responses aren't worth compressing
Immutable assets — one download per version
Worker threads — CPU work off the event loop
ANY($1) — one query for many ids

Prefer / Avoid

  • Optimizing before measuring → load test with autocannon, profile with --cpu-prof
  • *Sync calls in request handlers → async APIs or worker threads
  • node:cluster boilerplate → PM2 cluster mode or one process per container

⚠ Common Mistakes

  • Compressing in both Express and Nginx: wasted CPU
  • Clustering an app that keeps sessions in memory: users lose state between workers
  • Load testing in development mode: numbers don't match production

✓ Tips & Best Practices

  • Watch event-loop delay as a metric; spikes mean blocking code
  • Cache expensive results in Redis (sheet 36)
  • Consider Fastify for raw throughput-heavy services (55)

Quick Summary

  • measure first — autocannon
  • no sync calls in handlers
  • compress + cache headers
  • scale — PM2 / replicas
