Auto-Configuration & Conditionals

@AutoConfiguration · @ConditionalOnClass · @ConditionalOnMissingBean · @ConditionalOnProperty · --debug report · exclude=

How Boot Configures Itself

Auto-configuration classes add beans when conditions hold: a class is on the classpath, a property is set, or no bean of that type exists yet. Because most use @ConditionalOnMissingBean, defining your own bean makes Boot's back off. Run with --debug to see a report of which configurations matched and why.

Notes

  • Auto-configs are listed in META-INF/spring/…AutoConfiguration.imports
  • They run after your own configuration
  • Exclude one with @SpringBootApplication(exclude = …)
  • Boot 4 splits them into per-technology modules

Writing Your Own

@AutoConfiguration
@ConditionalOnClass(Stripe.class)                     // library present
@ConditionalOnProperty(prefix = "payments", name = "enabled",
                       havingValue = "true", matchIfMissing = true)
@EnableConfigurationProperties(PaymentProperties.class)
public class PaymentAutoConfiguration {

    @Bean
    @ConditionalOnMissingBean                         // user's bean wins
    PaymentGateway paymentGateway(PaymentProperties props) {
        return new StripeGateway(props.apiKey());
    }
}

Register It

# src/main/resources/META-INF/spring/
#   org.springframework.boot.autoconfigure.AutoConfiguration.imports
com.example.payments.PaymentAutoConfiguration

See What Applied

java -jar app.jar --debug       # CONDITIONS EVALUATION REPORT

Code Explained

@AutoConfiguration = @Configuration(proxyBeanMethods=false) + ordering
matchIfMissing = true: enabled unless set to false
Users override the gateway just by declaring their own bean
The report lists Positive and Negative matches with reasons

⚠ Common Mistakes

  • Annotating an auto-config class @Component so it's scanned, which breaks ordering
  • Putting @ConditionalOnMissingBean on a user config class; order isn't guaranteed
  • Excluding DataSourceAutoConfiguration to "fix" a missing URL instead of setting it

✓ Tips & Best Practices

  • Read the --debug report before overriding anything
  • Ship custom auto-config in its own module plus a *-spring-boot-starter
  • Test conditions with ApplicationContextRunner

Quick Summary

  • Auto-config: conditional @Beans
  • @ConditionalOnMissingBean: yours wins
  • --debug: conditions report
  • exclude: turn one off
