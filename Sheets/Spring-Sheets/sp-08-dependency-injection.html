Injecting Dependencies

With dependency injection a bean receives its collaborators instead of creating them. Constructor injection is preferred: fields are final, required and visible, and tests can call new. With a single constructor Spring uses it automatically, so @Autowired is optional.

Notes

  • Matching is by type, then by name if several match
  • Missing bean → NoSuchBeanDefinitionException at startup
  • List<T> / Map<String,T> inject every bean of a type
  • Circular dependencies fail at startup by default

Constructor Injection (Preferred)

@Service
class CheckoutService {
    private final PaymentGateway payments;        // required
    private final List<DiscountRule> rules;       // all rule beans
    private final ObjectProvider<AuditLog> audit; // optional

    CheckoutService(PaymentGateway payments, List<DiscountRule> rules,
                    ObjectProvider<AuditLog> audit) {
        this.payments = payments;
        this.rules = rules;
        this.audit = audit;
    }

    void checkout(Cart cart) {
        rules.forEach(r -> r.apply(cart));
        payments.charge(cart.total());
        audit.ifAvailable(a -> a.record(cart));  // only if bean exists
    }
}

Field & Setter Injection (Avoid)

@Autowired private PaymentGateway payments;        // field
@Autowired void setAudit(AuditLog a) { audit = a; } // setter

Code Explained

final fields are set once, so the object is always complete
List<DiscountRule> follows @Order on the beans
ObjectProvider defers lookup and tolerates a missing bean
Unit test: new CheckoutService(fake, List.of(), provider)

⚠ Common Mistakes

  • Private field injection: the class can't be unit-tested without Spring
  • Hiding a circular dependency with @Lazy instead of splitting the logic
  • Adding a 2nd constructor without @Autowired on one; Spring can't choose

✓ Tips & Best Practices

  • Over ~5 constructor parameters? The class is doing too much
  • Inject interfaces so tests can pass fakes
  • Lombok @RequiredArgsConstructor writes the constructor

Quick Summary

  • Constructor injection: final fields
  • ObjectProvider<T>: optional/lazy
  • List<T>: every bean of a type
  • Field injection: tests only
