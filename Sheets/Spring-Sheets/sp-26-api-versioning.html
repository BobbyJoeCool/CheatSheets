Built-In API Versioning

Spring Framework 7 adds first-class API versioning. Choose where clients send the version (a header, query parameter, path segment or media-type parameter), then add a version attribute to mappings. A baseline like "1.1+" matches that version and every later one, so a method keeps serving new versions until you replace it.

Notes

  • Header-only? Set …apiversion.use.header in properties
  • Other strategies: override configureApiVersioning()
  • Unsupported version → 400
  • Clients send it with .apiVersion() (Sheet 30)

Versioned Mappings

@RestController
@RequestMapping("/api/accounts")
class AccountController {

    @GetMapping(path = "/{id}", version = "1.0")     // exactly 1.0
    AccountV1 getV1(@PathVariable long id) { … }

    @GetMapping(path = "/{id}", version = "1.1+")    // 1.1, 1.2, 2.0 …
    AccountV2 get(@PathVariable long id) { … }
}

@Configuration
class ApiVersionConfig implements WebMvcConfigurer {
    @Override
    public void configureApiVersioning(ApiVersionConfigurer c) {
        c.useRequestHeader("API-Version")         // API-Version: 1.1
         .useQueryParam("v")                      // or ?v=1.1
         .addSupportedVersions("1.0", "1.1", "2.0")
         .setDefaultVersion("1.0");
    }
}

Or with Properties

spring.mvc.apiversion.use.header=API-Version
spring.mvc.apiversion.default=1.0

Code Explained

Both methods share a path; the version picks one
1.1+ is a baseline: it keeps matching newer versions
Several strategies can be combined; the first one found wins
usePathSegment(1) reads /api/{version}/… instead

⚠ Common Mistakes

  • Adding version to mappings without configuring a strategy; startup fails
  • Copying a whole controller per version instead of using baselines
  • Path versioning without a {version} URI variable in the path

✓ Tips & Best Practices

  • Prefer header or media-type versioning; URLs stay stable
  • setDeprecationHandler() sends Deprecation / Sunset headers
  • Keep version DTOs (AccountV1) next to the controller

Quick Summary

  • version = "1.1": exact match
  • "1.1+": this and later
  • configureApiVersioning(): strategy
  • apiVersion(): client side
