Transactions

@Transactional on a public bean method runs it in a database transaction: it commits when the method returns and rolls back on a RuntimeException. It works through an AOP proxy, so it only applies to calls from another bean. Put it on service methods that change data; use readOnly = true for queries.

Notes

  • Checked exceptions don't roll back by default
  • Default propagation REQUIRED joins an existing transaction
  • Inside a transaction, loaded entities are auto-saved on commit
  • Spring's @Transactional has more options than Jakarta's

Declarative and Programmatic

@Service
@Transactional(readOnly = true)                 // default for the class
class TransferService {

    @Transactional                              // read-write, overrides
    public void transfer(long from, long to, BigDecimal amount) {
        Account a = accounts.findById(from).orElseThrow();
        Account b = accounts.findById(to).orElseThrow();
        a.withdraw(amount);                     // dirty checking:
        b.deposit(amount);                      // no save() needed
    }                                           // commit here

    @Transactional(rollbackFor = IOException.class, timeout = 10)
    public void importFile(Path p) throws IOException { … }

    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public void audit(String msg) { … }         // own tx, commits alone

    public Balance balance(long id) { … }       // read-only from class
}

// programmatic
transactionTemplate.executeWithoutResult(status -> {
    repo.save(order);
    if (!stock.reserve(order)) status.setRollbackOnly();
});

Code Explained

A RuntimeException from withdraw rolls back both changes
rollbackFor adds checked exceptions to the rollback rule
REQUIRES_NEW suspends the outer transaction
TransactionTemplate gives fine-grained control in code

⚠ Common Mistakes

  • Catching the exception inside the method; the transaction commits
  • @Transactional on controllers; keep transactions in the service layer
  • Calling a remote API inside a transaction, holding a DB connection

✓ Tips & Best Practices

  • Class-level readOnly = true, method-level @Transactional for writes
  • Set the …transaction logger to DEBUG to see tx boundaries
  • Use @TransactionalEventListener for work after commit (Sheet 60)

Quick Summary

  • @Transactional: commit / rollback
  • Runtime exceptions roll back
  • readOnly = true: queries
  • Proxy-based: no self-calls
