Bean Lifecycle & Callbacks

@PostConstruct · @PreDestroy · InitializingBean · DisposableBean · BeanPostProcessor · SmartLifecycle

Lifecycle of a Bean

After Spring creates a bean and injects its dependencies, it runs initialization callbacks; at shutdown it runs destruction callbacks. The usual choice is @PostConstruct and @PreDestroy (from jakarta.annotation). BeanPostProcessor hooks run around every bean's init and are how Spring adds proxies, while SmartLifecycle starts and stops background work in phases.

Notes

  • Constructor runs before setter/field injection; use @PostConstruct for setup that needs them
  • Destroy callbacks run on ctx.close() or normal JVM shutdown
  • Prototype beans get init callbacks but no destroy callbacks
  • Graceful shutdown (default) lets in-flight requests finish first

Init & Destroy Callbacks

@Component
class FeedPoller implements SmartLifecycle {
    private final FeedClient client;
    private volatile boolean running;

    FeedPoller(FeedClient client) { this.client = client; } // 1. inject

    @PostConstruct void init() { client.connect(); }    // 2. after inject
    @PreDestroy void close()   { client.disconnect(); } // last

    @Override public void start() { running = true; }   // all beans ready
    @Override public void stop()  { running = false; }  // before @PreDestroy
    @Override public boolean isRunning() { return running; }
}

@Component
class TimingPostProcessor implements BeanPostProcessor {
    @Override
    public Object postProcessAfterInitialization(Object bean, String name) {
        return bean;           // could wrap it in a proxy here
    }
}

Code Explained

SmartLifecycle.start() runs after all singletons are ready
stop() runs before destroy callbacks, in reverse phase order
@PostConstruct method: no args, return void, any visibility
BeanPostProcessor sees every bean the context creates

⚠ Common Mistakes

  • Using an @Autowired field inside the constructor; it's still null there
  • Implementing InitializingBean in app code; it couples you to Spring
  • Long-running work in @PostConstruct; it blocks startup

✓ Tips & Best Practices

  • Prefer constructor injection, then the constructor can do the setup
  • Use SmartLifecycle (or ApplicationReadyEvent) for background threads
  • Set spring.lifecycle.timeout-per-shutdown-phase for slow shutdowns

Quick Summary

  • @PostConstruct: after injection
  • @PreDestroy: before shutdown
  • BeanPostProcessor: wrap any bean
  • SmartLifecycle: start/stop work
