Application Structure

@SpringBootApplication · main() · SpringApplication.run() · package layout · component scan root · resources/

How a Boot App Is Laid Out

One class carries @SpringBootApplication and its main() calls SpringApplication.run(). The annotation combines @SpringBootConfiguration, @EnableAutoConfiguration and @ComponentScan. Scanning starts at the main class's package and goes down, so the main class lives in the root package.

Notes

  • Code in src/main/java, config in src/main/resources
  • A class outside the root package is not scanned
  • Package by feature (order/, customer/), not by layer
  • Tests mirror the same packages under src/test/java

Main Class & Customization

package com.example.shop;                  // root package

@SpringBootApplication
public class ShopApplication {
    public static void main(String[] args) {
        var app = new SpringApplication(ShopApplication.class);
        app.setBannerMode(Banner.Mode.OFF);  // optional tweaks
        app.setAdditionalProfiles("local");
        app.run(args);
    }
}

Package-by-Feature Layout

com/example/shop/
├── ShopApplication.java       # @SpringBootApplication
├── order/     OrderController  OrderService  Order
├── customer/  CustomerController  CustomerService
└── config/    SecurityConfig  WebConfig

Code Explained

One line usually suffices: SpringApplication.run(Shop.class, args)
setAdditionalProfiles() adds to spring.profiles.active
order/, customer/, config/ are sub-packages → scanned
run() returns a ConfigurableApplicationContext

⚠ Common Mistakes

  • Main class in a sub-package (shop.app); sibling packages aren't scanned
  • Main class in the default package; Boot scans every jar on the classpath
  • Adding @ComponentScan with other packages, which replaces the default

✓ Tips & Best Practices

  • Keep main() to one line; put setup in @Configuration so tests get it
  • Prefer scanBasePackageClasses over strings so refactors don't break it
  • Make feature-internal classes package-private

Quick Summary

  • @SpringBootApplication: config + scan
  • Main class: root package
  • resources/: config, static, templates
  • CommandLineRunner: startup code
