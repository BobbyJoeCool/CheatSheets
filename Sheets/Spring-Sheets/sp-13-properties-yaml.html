Sheet 13

application.properties & YAML

application.yml · property syntax · relaxed binding · placeholders ${} · spring.config.import · .env-style overrides

Where Configuration Lives

Boot reads settings from application.properties or application.yml in src/main/resources, then layers environment variables, command-line arguments and other sources on top. Keys use relaxed binding, so server.port, SERVER_PORT and server-port all reach the same property. Values can reference others with ${...} placeholders.

Notes

  • Use one format per app; if both exist, .properties wins
  • YAML: indentation matters, two spaces, no tabs
  • --- splits one YAML file into several documents
  • spring.config.import pulls in more files, .env files or config servers

application.yml

spring:
  application:
    name: shop
  datasource:
    url: jdbc:postgresql://localhost:5432/shop
    username: ${DB_USER:shop}            # env var with default
    password: ${DB_PASSWORD}
  config:
    import: optional:file:.env[.properties]

server:
  port: 8080
  servlet:
    context-path: /api

app:
  base-url: https://shop.example.com
  checkout-url: ${app.base-url}/checkout  # reuse another key

Same in .properties

server.port=8080
spring.datasource.username=${DB_USER:shop}

Code Explained

${DB_USER:shop} uses env var DB_USER, or shop if missing
optional: means no error when the file doesn't exist
file:.env[.properties] reads a .env file as properties
app.* is your own namespace; bind it with Sheet 15

⚠ Common Mistakes

  • Committing real passwords to application.yml; use env vars or a vault
  • Tabs in YAML; Boot fails with a parse error
  • Unquoted YAML values like on / no / 08, parsed as booleans or octal

✓ Tips & Best Practices

  • Run with --debug or check /actuator/env to see where a value came from
  • Put local-only overrides in a git-ignored application-local.yml
  • Add spring-boot-configuration-processor for IDE autocompletion of your keys

Quick Summary

  • application.yml: main config file
  • ${KEY:default}: placeholder
  • Env vars / CLI override files
  • Relaxed binding: SERVER_PORT
