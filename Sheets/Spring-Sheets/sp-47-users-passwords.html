Users & Password Encoding

UserDetailsService · UserDetails · InMemoryUserDetailsManager · PasswordEncoder · BCryptPasswordEncoder · DelegatingPasswordEncoder

Where Users Come From

For username/password login, Spring Security asks a UserDetailsService to load a user by name, then checks the password with a PasswordEncoder. Use InMemoryUserDetailsManager for demos, JdbcUserDetailsManager for the standard schema, or implement the interface over your own user table. Passwords are always stored hashed, never in plain text.

Notes

  • Default encoder is delegating: hashes start with {bcrypt}
  • {id} prefix lets old and new algorithms coexist
  • User.withUsername(…) builds UserDetails objects
  • Expose one UserDetailsService bean; Boot wires the rest

Users from Your Database

@Bean
PasswordEncoder passwordEncoder() {
    return PasswordEncoderFactories.createDelegatingPasswordEncoder();
}

@Service
class AppUserDetailsService implements UserDetailsService {
    private final AppUserRepository users;
    AppUserDetailsService(AppUserRepository users) { this.users = users; }

    @Override
    public UserDetails loadUserByUsername(String email) {
        AppUser u = users.findByEmail(email)
            .orElseThrow(() -> new UsernameNotFoundException(email));
        return User.withUsername(u.email())
            .password(u.passwordHash())            // "{bcrypt}$2a$10$..."
            .roles(u.role().name())                // -> ROLE_USER
            .disabled(!u.active())
            .build();
    }
}

Code Explained

UsernameNotFoundException makes login fail with a generic error
.roles("USER") adds authority ROLE_USER
encode() produces a new salted hash each call
Use matches(raw, hash) to check a password yourself

⚠ Common Mistakes

  • Storing passwords with {noop} or a plain MessageDigest hash
  • Comparing hashes with equals; use encoder.matches()
  • Telling users whether the username or the password was wrong

✓ Tips & Best Practices

  • Keep the delegating encoder so you can upgrade algorithms later
  • Use a UserDetailsPasswordService to re-hash on login
  • Return your own UserDetails type to carry extra fields like an id

Quick Summary

  • UserDetailsService: load by name
  • PasswordEncoder: hash + match
  • {bcrypt}: delegating default
  • User.withUsername(): build users
