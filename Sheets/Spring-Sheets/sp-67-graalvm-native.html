GraalVM Native Images

native-maven-plugin · nativeCompile · AOT processing · RuntimeHints · reflection config · startup / memory tradeoffs

Native Executables

GraalVM Native Image compiles the app ahead of time into a standalone executable that starts in milliseconds and uses far less memory, at the cost of long builds and a closed world: everything reachable must be known at build time. Spring's AOT processing generates the bean setup in advance; you add runtime hints for reflection, resources or proxies Spring can't detect.

Notes

  • Boot 4 needs GraalVM 25 or later
  • Profiles and @Conditional beans are fixed at build time
  • Run tests natively with -PnativeTest / nativeTest
  • Buildpacks can build a native image without local GraalVM

Build Commands

./mvnw -Pnative native:compile          # target/shop (executable)
./gradlew nativeCompile                 # build/native/nativeCompile/shop
./mvnw -Pnative spring-boot:build-image # native container image
./target/shop                           # starts in ~50 ms

Runtime Hints

@Configuration
@ImportRuntimeHints(ShopHints.class)
@RegisterReflectionForBinding(LegacyDto.class)   // JSON via reflection
class NativeConfig { }

class ShopHints implements RuntimeHintsRegistrar {
    @Override
    public void registerHints(RuntimeHints hints, ClassLoader cl) {
        hints.resources().registerPattern("templates/*.txt");
        hints.reflection().registerType(PluginImpl.class,
            MemberCategory.INVOKE_PUBLIC_CONSTRUCTORS);
        hints.proxies().registerJdkProxy(Auditor.class);
    }
}

Gradle Plugin

plugins { id("org.graalvm.buildtools.native") }   // version: use Initializr's

Code Explained

Maven's native profile comes from spring-boot-starter-parent
@RegisterReflectionForBinding covers Jackson-bound types
Resource patterns include files read with getResource()
Missing hints fail at runtime, so test the native binary

⚠ Common Mistakes

  • Testing only on the JVM; reflection gaps show up only in the native binary
  • Choosing beans with runtime profiles; native fixes them at build time
  • Expecting native to be faster at peak load; the JIT often wins there

✓ Tips & Best Practices

  • Run the GraalVM tracing agent to discover needed hints
  • Build native images in CI; they take minutes and lots of RAM
  • Try Java 25's AOT cache first if you only need faster startup

Quick Summary

  • native:compile / nativeCompile
  • AOT: beans prepared at build time
  • RuntimeHintsRegistrar: extra hints
  • Fast start, closed world
