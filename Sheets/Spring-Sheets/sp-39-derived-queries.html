Queries from Method Names

Spring Data parses repository method names into queries. A name is a subject (find…By, count…By, exists…By, delete…By) followed by predicates on entity properties joined with And / Or, plus optional OrderBy and limits such as Top10. Invalid names fail at startup, so typos are caught early.

Notes

  • Property paths traverse relations: findByCustomerEmail
  • Return List, Optional, Stream, Page or Slice
  • IgnoreCase applies to one property; AllIgnoreCase to all
  • Long names are a hint to switch to @Query

Derived Query Methods

interface OrderRepository extends JpaRepository<Order, Long> {

    List<Order> findByStatus(Status status);

    List<Order> findByStatusAndTotalGreaterThan(Status s, BigDecimal min);

    List<Order> findByCustomerEmailIgnoreCase(String email);   // join

    List<Order> findByCreatedAtBetween(Instant from, Instant to);

    List<Order> findByNoteContaining(String text);             // %text%

    List<Order> findByStatusInOrderByCreatedAtDesc(Collection<Status> s);

    Optional<Order> findFirstByCustomerIdOrderByCreatedAtDesc(long id);

    List<Order> findTop5ByOrderByTotalDesc();

    boolean existsByCustomerIdAndStatus(long customerId, Status status);

    long countByStatus(Status status);

    @Transactional
    long deleteByStatusAndCreatedAtBefore(Status s, Instant cutoff);
}

Code Explained

CustomerEmail walks order.customer.email with a join
Containing wraps the value in %…% for LIKE
First / Top5 add a LIMIT
Derived delete loads each entity, then deletes (fires callbacks)

⚠ Common Mistakes

  • Misspelled property in the name; startup fails with No property … found
  • findByName(null) expecting IS NULL; use findByNameIsNull()
  • Derived deleteBy on many rows; it loads each one first

✓ Tips & Best Practices

  • Switch to @Query once a name passes ~4 conditions
  • Return Optional<T> for single results that may be missing
  • Use @Modifying @Query for bulk deletes

Quick Summary

  • findBy…And…: AND conditions
  • OrderBy…Desc: sorting
  • Top / First: limits
  • countBy / existsBy: aggregates
