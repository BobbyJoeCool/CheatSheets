Bean Scopes

singleton · prototype · request · session · @Scope · scoped proxies · @Lazy

How Long a Bean Lives

A bean's scope decides how many instances exist. The default, singleton, means one instance per container, shared by everyone, so it must be stateless or thread-safe. Prototype creates a new instance every time it's requested. Web apps add request, session and application scopes, tied to the HTTP lifecycle.

Notes

  • Singletons are created at startup; prototypes on demand
  • Spring does not call destroy methods on prototypes
  • A prototype injected into a singleton is created once
  • Use a scoped proxy or ObjectProvider to get fresh instances

Declaring Scopes

@Component                                     // singleton (default)
class PriceCalculator { }

@Component
@Scope(ConfigurableBeanFactory.SCOPE_PROTOTYPE) // new each lookup
class ReportBuilder { }

@Component
@RequestScope                                   // one per HTTP request
class RequestContext { String traceId; }

@Service
class ReportService {
    private final ObjectProvider<ReportBuilder> builders;
    private final RequestContext ctx;             // proxy → current request

    ReportService(ObjectProvider<ReportBuilder> builders, RequestContext ctx) {
        this.builders = builders;
        this.ctx = ctx;
    }
    Report build() { return builders.getObject().with(ctx.traceId).build(); }
}

Code Explained

builders.getObject() returns a new ReportBuilder each call
@RequestScope creates a proxy, so a singleton can hold it
The proxy forwards to the bean of the current request
Using request scope outside a request throws IllegalStateException

⚠ Common Mistakes

  • Keeping per-user data in a field of a singleton; all users share it
  • Expecting a prototype field in a singleton to change on each call
  • Using @SessionScope beans in stateless JWT APIs where no session exists

✓ Tips & Best Practices

  • Default to stateless singletons; pass state as method arguments
  • Use ObjectProvider<T> to get a fresh prototype on demand
  • @Lazy on an injection point delays creation of expensive beans

Quick Summary

  • singleton: one shared instance
  • prototype: new per lookup
  • @RequestScope: per request, proxied
  • ObjectProvider: fresh instances
