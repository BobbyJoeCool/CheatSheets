Caching Method Results

The cache abstraction stores method results by their arguments: @Cacheable returns a cached value when present, @CachePut always runs and updates the cache, @CacheEvict removes entries. Enable it with @EnableCaching. Boot picks a provider from the classpath: a simple map by default, or Caffeine, Redis and others.

Notes

  • Add spring-boot-starter-cache plus a provider
  • The key defaults to the method arguments
  • Cached values for Redis must be serializable
  • Proxy-based: self-calls skip the cache

Cache Annotations

@Configuration @EnableCaching class CacheConfig { }

@Service
class ProductService {

    @Cacheable("products")                           // key = id
    public Product find(long id) { return repo.findById(id).orElseThrow(); }

    @Cacheable(value = "search", key = "#q.toLowerCase()",
               unless = "#result.isEmpty()")
    public List<Product> search(String q) { … }

    @CachePut(value = "products", key = "#p.id")     // refresh entry
    public Product update(Product p) { return repo.save(p); }

    @CacheEvict(value = "products", key = "#id")
    public void delete(long id) { repo.deleteById(id); }
}

Provider Config

spring.cache:
  cache-names: products, search
  caffeine.spec: maximumSize=1000,expireAfterWrite=10m
  # type: redis   +   spring.cache.redis.time-to-live: 10m

Code Explained

Second find(7) call returns the cached product, no query
unless skips caching empty results
@CachePut keeps the cache in sync after updates
@CacheEvict(allEntries = true) clears a whole cache

⚠ Common Mistakes

  • Caching mutable entities, then changing them; the cache holds the same object
  • No expiry or size limit; the cache grows until memory runs out
  • Expecting @Cacheable to work on a call from the same class

✓ Tips & Best Practices

  • Use sync = true to stop a cache stampede on cold keys
  • Watch cache.gets hit/miss metrics in Actuator
  • Set spring.cache.type=none in tests that need fresh data
