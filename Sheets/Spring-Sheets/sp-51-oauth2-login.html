OAuth2 Login & Client

oauth2Login() · spring.security.oauth2.client.registration · OidcUser · @AuthenticationPrincipal · OAuth2AuthorizedClientManager

Logging In with OAuth2 / OIDC

oauth2Login() lets users sign in through an external provider (Google, GitHub, Okta, Keycloak) using OpenID Connect. Register the provider under spring.security.oauth2.client.registration, and Spring handles the redirect, code exchange and user info. As an OAuth2 client, your app can also call other APIs with the user's access token.

Notes

  • Add spring-boot-starter-security-oauth2-client
  • Google, GitHub, Facebook and Okta have built-in provider defaults
  • Callback path: /login/oauth2/code/{id}
  • OIDC users arrive as OidcUser; plain OAuth2 as OAuth2User

Configuration

spring.security.oauth2.client:
  registration:
    google:
      client-id: ${GOOGLE_CLIENT_ID}
      client-secret: ${GOOGLE_CLIENT_SECRET}
      scope: openid, profile, email
    keycloak:
      client-id: shop-web
      client-secret: ${KC_SECRET}
      scope: openid
  provider:
    keycloak:
      issuer-uri: https://auth.example.com/realms/shop

Security + Controller

http.authorizeHttpRequests(a -> a.anyRequest().authenticated())
    .oauth2Login(Customizer.withDefaults())
    .logout(l -> l.logoutSuccessUrl("/"));

@GetMapping("/profile")
String profile(@AuthenticationPrincipal OidcUser user, Model model) {
    model.addAttribute("name", user.getFullName());
    return "profile";
}

Code Explained

Google needs only id, secret and scopes
Custom providers need an issuer-uri for discovery
Visiting a protected page redirects to the provider
OidcUser exposes the ID token's claims

⚠ Common Mistakes

  • Committing client-secret to the repo; use env vars
  • Redirect URI in the provider console not matching the app's
  • Using the ID token to call APIs; use the access token

✓ Tips & Best Practices

  • Map provider claims to local users in a custom OidcUserService
  • Use OAuth2ClientHttpRequestInterceptor with RestClient for downstream calls
  • For SPAs, consider a backend-for-frontend with this setup

Quick Summary

  • oauth2Login(): social / OIDC login
  • registration.<id>: client settings
  • OidcUser: the signed-in user
  • Access token: for API calls
