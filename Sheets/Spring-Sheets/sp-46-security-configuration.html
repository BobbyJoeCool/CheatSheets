Configuring HttpSecurity

@EnableWebSecurity · http.authorizeHttpRequests() · requestMatchers() · permitAll() · authenticated() · hasRole() · lambda DSL

Declaring the Rules

Customize security with a SecurityFilterChain bean built from HttpSecurity. Configure each feature with a lambda: authorizeHttpRequests lists URL rules in order (first match wins), then pick login mechanisms such as httpBasic, formLogin or oauth2ResourceServer. Defining this bean replaces Boot's default chain.

Notes

  • Rules are checked top to bottom; put specific ones first
  • End with anyRequest() so nothing slips through
  • Several chains: use securityMatcher + @Order
  • .and() chaining was removed in Security 7; use lambdas

A Typical Configuration

@Configuration
@EnableWebSecurity
class SecurityConfig {

    @Bean
    SecurityFilterChain api(HttpSecurity http) throws Exception {
        http
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/", "/css/**", "/actuator/health").permitAll()
                .requestMatchers(HttpMethod.GET, "/api/products/**").permitAll()
                .requestMatchers("/api/admin/**").hasRole("ADMIN")
                .requestMatchers("/api/**").hasAnyRole("USER", "ADMIN")
                .anyRequest().authenticated())
            .httpBasic(Customizer.withDefaults())
            .formLogin(form -> form.loginPage("/login").permitAll())
            .csrf(csrf -> csrf.ignoringRequestMatchers("/api/**"))
            .cors(Customizer.withDefaults());
        return http.build();
    }
}

Code Explained

permitAll() lets anonymous users through
hasRole("ADMIN") checks for authority ROLE_ADMIN
Customizer.withDefaults() enables a feature with defaults
CSRF is skipped for the stateless /api/** endpoints

⚠ Common Mistakes

  • anyRequest() before specific rules; later matchers never run
  • hasRole("ROLE_ADMIN"); the prefix is added for you
  • Disabling CSRF for a browser app that uses session cookies

✓ Tips & Best Practices

  • Permit CSS/JS/images with PathRequest.toStaticResources()
  • Prefer method security for business rules (Sheet 48)
  • Write a @WebMvcTest per rule with @WithMockUser (Sheet 55)

Quick Summary
