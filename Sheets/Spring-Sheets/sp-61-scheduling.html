Running Tasks on a Schedule

Add @EnableScheduling and annotate methods with @Scheduled to run them periodically: at a fixed rate, with a fixed delay between runs, or on a cron expression. Methods take no arguments and return void. By default all scheduled tasks share one thread, so a slow task delays the others unless you raise the pool size or use virtual threads.

Notes

  • Spring cron has 6 fields: second first
  • zone sets the cron time zone (default: server's)
  • Values can come from properties: cron = "${jobs.cleanup}"
  • Multiple instances each run the job; use ShedLock to run once

Scheduled Jobs

@Configuration
@EnableScheduling
class SchedulingConfig { }

@Component
class Jobs {

    @Scheduled(fixedRate = 30, timeUnit = TimeUnit.SECONDS)
    void pollFeed() { … }                    // every 30 s, start to start

    @Scheduled(fixedDelay = 5000, initialDelay = 10000)
    void drainQueue() { … }                  // 5 s after previous ends

    @Scheduled(cron = "0 0 2 * * *", zone = "America/Chicago")
    void nightlyCleanup() { … }              // 02:00 every day

    @Scheduled(cron = "0 */15 9-17 * * MON-FRI")
    void businessHours() { … }               // every 15 min, 9–5 weekdays

    @Scheduled(cron = "${jobs.report.cron:0 0 6 * * MON}")
    void weeklyReport() { … }                // from config
}

Thread Pool

spring.task.scheduling.pool.size=4
spring.task.scheduling.thread-name-prefix=sched-

Code Explained

fixedRate measures from the start of each run
fixedDelay waits after the previous run finishes
initialDelay postpones the first run
Cron "-" disables a job (handy via properties)

⚠ Common Mistakes

  • Unix 5-field cron (0 2 * * *); Spring expects 6 fields
  • Long jobs on the single default thread, blocking every other job
  • Every replica running the same job at once in a cluster

✓ Tips & Best Practices

  • Use ShedLock or a database lock for cluster-wide single runs
  • With virtual threads enabled, each run gets its own virtual thread
  • Keep job methods thin; call a service you can test directly

Quick Summary

  • @EnableScheduling + @Scheduled
  • fixedRate vs fixedDelay
  • 6-field cron + zone
  • pool.size: parallel jobs
