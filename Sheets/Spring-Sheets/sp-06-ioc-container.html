The IoC Container

ApplicationContext · BeanFactory · bean definitions · getBean() · container startup · CommandLineRunner

The Container

The IoC container creates your objects (beans), injects their dependencies and manages their lifecycle. In Boot it is an ApplicationContext, which adds events, messages and environment access to the basic BeanFactory. At startup it registers bean definitions, then creates every singleton in dependency order.

Notes

  • Bean definition = recipe; bean = the instance
  • Singletons are created at startup, so wiring errors fail fast
  • Default name: class name, first letter lower-case
  • Prefer injection over getBean() (Sheet 08)

Looking Into the Context

public static void main(String[] args) {
    var ctx = SpringApplication.run(App.class, args);

    var svc  = ctx.getBean(OrderService.class);          // by type
    var same = ctx.getBean("orderService", OrderService.class);
    System.out.println(svc == same);                     // true

    ctx.getBeanDefinitionCount();        // e.g. 142
    ctx.getBeansOfType(Clock.class);     // Map<String, Clock>
    ctx.containsBean("dataSource");      // true
}

@Bean
CommandLineRunner seed(OrderRepository repo) {  // runs after startup
    return args -> repo.save(new Order("first"));
}

Code Explained

run() returns the started ConfigurableApplicationContext
getBean(Type) throws if zero or several beans match
svc == same → singleton scope (Sheet 11)
getBeansOfType() returns name → bean, empty if none
The runner's repo parameter is injected like a constructor arg

⚠ Common Mistakes

  • Calling getBean() all over (service locator); it hides dependencies
  • Creating a second context with new AnnotationConfigApplicationContext()
  • Heavy work in constructors; it slows startup and every test

✓ Tips & Best Practices

  • List every bean with Actuator's /actuator/beans (Sheet 57)
  • spring.main.lazy-initialization=true speeds dev startup
  • Use ApplicationReadyEvent for work that needs the server up

Quick Summary

  • ApplicationContext: the container
  • Bean: object it manages
  • getBean(): lookup, rarely needed
  • CommandLineRunner: after startup
