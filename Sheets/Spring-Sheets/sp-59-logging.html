Logging

Boot logs through SLF4J with Logback by default and prints colored console output. Set levels per package with logging.level.*, write to a file with logging.file.name, and switch to structured JSON logs with one property. For full control, add logback-spring.xml, which supports <springProfile> blocks.

Notes

  • Default level is INFO
  • Use parameterized messages: log.info("id={}", id)
  • MDC values (traceId, your own keys) appear in every line

Logging in Code

@Service
class OrderService {
    private static final Logger log = LoggerFactory.getLogger(OrderService.class);

    void place(Order o) {
        log.debug("Placing order {}", o.id());          // lazy formatting
        MDC.put("orderId", String.valueOf(o.id()));
        try {
            gateway.charge(o);
            log.info("Order {} placed, total={}", o.id(), o.total());
        } catch (PaymentException e) {
            log.error("Payment failed for {}", o.id(), e);   // stack trace
        } finally {
            MDC.remove("orderId");
        }
    }
}

application.yml

logging:
  level:
    root: INFO
    com.example: DEBUG
    org.hibernate.SQL: DEBUG
  file.name: logs/shop.log
  structured.format.console: ecs      # JSON: ecs, logstash or gelf

Code Explained

{} placeholders skip string building when the level is off
The exception as last argument prints its stack trace
MDC adds orderId to every log line in this thread
structured.format.console writes one JSON object per line

⚠ Common Mistakes

  • String concatenation in log calls; it runs even when DEBUG is off
  • log.error(e.getMessage()); the stack trace is lost
  • Logging passwords, tokens or full request bodies

✓ Tips & Best Practices

  • Change levels live via /actuator/loggers while debugging
  • Use structured logs in production; plain text in dev
  • Use logging.group.web style groups for related packages

Quick Summary
