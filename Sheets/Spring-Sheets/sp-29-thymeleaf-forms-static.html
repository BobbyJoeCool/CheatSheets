Thymeleaf Forms & Static Resources

th:object · th:field · @ModelAttribute · validation errors · redirect: · RedirectAttributes · static/

HTML Forms the Spring Way

A form binds to a form-backing object: th:object names it and th:field connects each input to a property. On submit, Spring binds the fields into a @ModelAttribute parameter, @Valid checks it, and BindingResult holds the errors. On success, redirect (Post/Redirect/Get) and pass a flash message with RedirectAttributes.

Notes

  • BindingResult must come right after the validated parameter
  • th:field sets id, name and value for you
  • Thymeleaf adds the CSRF token to th:action forms automatically
  • Static files in static/ are served from /

GET Form, POST Handler

@GetMapping("/new")
String form(Model model) {
    model.addAttribute("product", new ProductForm());
    return "products/form";
}

@PostMapping
String save(@Valid @ModelAttribute("product") ProductForm form,
            BindingResult result, RedirectAttributes flash) {
    if (result.hasErrors()) return "products/form";   // re-show with errors
    service.create(form);
    flash.addFlashAttribute("msg", "Product saved");
    return "redirect:/products";                      // PRG
}

templates/products/form.html

<form th:action="@{/products}" th:object="${product}" method="post">
  <input th:field="*{name}" />
  <p th:if="${#fields.hasErrors('name')}" th:errors="*{name}">err</p>
  <input th:field="*{price}" type="number" step="0.01" />
  <button>Save</button>
</form>
<p th:text="${msg}" th:if="${msg}"></p>          <!-- on list page -->
<link th:href="@{/css/app.css}" rel="stylesheet"> <!-- static/css/app.css -->

Code Explained

The GET puts an empty object in the model for th:object
*{name} is shorthand for ${product.name}
th:errors prints that field's validation messages
Flash attributes survive exactly one redirect

⚠ Common Mistakes

  • Returning the view after a successful POST; refresh resubmits the form
  • Putting BindingResult after another parameter; Spring throws instead
  • Forgetting to add the form object on GET; th:object fails

✓ Tips & Best Practices

  • Use a separate form class, not the entity, for user input
  • Use @ModelAttribute methods for dropdown data every view needs
  • Turn on the resource chain's content strategy for cache-busting asset URLs

Quick Summary

  • th:object + th:field: bind form
  • @Valid + BindingResult: errors
  • redirect: + flash: PRG
  • static/: served at /
