Browser Sessions and CSRF

Browser apps usually use form login with an HTTP session: after login the JSESSIONID cookie identifies the user. Because the browser sends cookies automatically, these apps need CSRF protection (on by default): every state-changing request must carry a token. Stateless token APIs instead set the session policy to STATELESS and can disable CSRF.

Notes

  • Thymeleaf forms include the CSRF token automatically
  • SPAs read the token from an XSRF-TOKEN cookie
  • rememberMe() keeps users logged in across browser restarts
  • Login changes the session id (session fixation protection)

Session-Based Web App

@Bean
SecurityFilterChain web(HttpSecurity http) throws Exception {
    http
        .authorizeHttpRequests(a -> a
            .requestMatchers("/login", "/css/**").permitAll()
            .anyRequest().authenticated())
        .formLogin(f -> f
            .loginPage("/login")
            .defaultSuccessUrl("/dashboard"))
        .logout(l -> l.logoutSuccessUrl("/login?logout"))
        .rememberMe(r -> r.tokenValiditySeconds(14 * 24 * 3600))
        .sessionManagement(s -> s.maximumSessions(1))
        .csrf(c -> c.spa());                     // cookie-based token for SPAs
    return http.build();
}

Stateless API

http.sessionManagement(s -> s.sessionCreationPolicy(STATELESS))
    .csrf(c -> c.disable());     // safe only without cookie auth

Code Explained

Custom /login page must post username and password
logout is a POST by default (needs the CSRF token)
maximumSessions(1) limits each user to one login
csrf.spa() (Security 6.4+) sets up cookie + header for JS apps

⚠ Common Mistakes

  • Disabling CSRF in a cookie-session app to make a form work
  • Making logout a GET link; Spring expects POST with a token
  • Storing large objects in the session; it hurts memory and clustering

✓ Tips & Best Practices

  • Use Spring Session (Redis/JDBC) to share sessions across instances
  • Set same-site=strict cookies where possible
  • Use a token API (Sheet 50) for mobile clients instead of sessions

Quick Summary

  • formLogin(): session login
  • CSRF: on by default, keep it for cookies
  • STATELESS: token APIs
  • rememberMe(): long-lived login
