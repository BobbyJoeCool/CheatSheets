Controllers & Request Mappings

@RestController · @RequestMapping · @GetMapping · @PostMapping · @PutMapping · @DeleteMapping · produces / consumes

Mapping Requests to Methods

A @RestController handles HTTP requests; each method's return value is written to the response body as JSON by default. @RequestMapping on the class sets a common path prefix, and @GetMapping, @PostMapping, @PutMapping, @PatchMapping and @DeleteMapping map individual methods by HTTP method and path.

Notes

  • Return an object → Jackson writes JSON with status 200
  • Paths support {vars}, *, ** and regex {id:\d+}
  • Trailing-slash matching is off: /orders/ ≠ /orders
  • produces / consumes restrict media types

A CRUD Controller

@RestController
@RequestMapping("/api/orders")
class OrderController {
    private final OrderService service;
    OrderController(OrderService service) { this.service = service; }

    @GetMapping                                   // GET /api/orders
    List<Order> list() { return service.findAll(); }

    @GetMapping("/{id}")                          // GET /api/orders/42
    Order get(@PathVariable long id) { return service.find(id); }

    @PostMapping                                  // POST /api/orders
    @ResponseStatus(HttpStatus.CREATED)           // 201
    Order create(@RequestBody NewOrder body) { return service.create(body); }

    @PutMapping("/{id}")
    Order replace(@PathVariable long id, @RequestBody NewOrder body) { … }

    @DeleteMapping("/{id}")
    @ResponseStatus(HttpStatus.NO_CONTENT)        // 204
    void delete(@PathVariable long id) { service.delete(id); }
}

Code Explained

Class-level @RequestMapping prefixes every method path
@RequestBody reads JSON into NewOrder (Sheet 21)
@ResponseStatus changes the success status code
void + 204 sends an empty body

⚠ Common Mistakes

  • Using @Controller for a JSON API; Spring looks for a view template
  • Two methods with the same path + method → ambiguous mapping at startup
  • Returning JPA entities directly; lazy fields and cycles break JSON

✓ Tips & Best Practices

  • Return records as DTOs, not entities
  • List all mappings at /actuator/mappings
  • Use ResponseEntity when the status depends on the outcome (Sheet 22)

Quick Summary

  • @RestController: JSON responses
  • @RequestMapping: class prefix
  • @GetMapping …: per method
  • @ResponseStatus: success code
