Testcontainers

@Testcontainers · @Container · @ServiceConnection · PostgreSQLContainer · TestApplication · spring-boot-testcontainers

Real Services in Tests

Testcontainers starts real databases and brokers in Docker for your tests. With @ServiceConnection on a container field, Boot reads its host, port and credentials and configures the matching connection automatically: no @DynamicPropertySource needed. The same containers can power local development through a test main class.

Notes

  • Needs Docker (or a compatible runtime) on the machine
  • Boot 4 uses Testcontainers 2: new packages, e.g. org.testcontainers.postgresql
  • Artifacts: spring-boot-testcontainers + testcontainers-postgresql
  • static containers are shared by all tests in the class

Container per Test Class

@SpringBootTest
@Testcontainers
class OrderRepositoryIT {

    @Container
    @ServiceConnection                          // sets spring.datasource.*
    static PostgreSQLContainer postgres = new PostgreSQLContainer("postgres:17");

    @Autowired OrderRepository repo;      // tests hit real Postgres
}

Shared Config + Dev Mode

@TestConfiguration(proxyBeanMethods = false)
class Containers {
    @Bean @ServiceConnection PostgreSQLContainer pg() {
        return new PostgreSQLContainer("postgres:17");
    }
}
class TestShopApplication {               // dev mode, in src/test
    public static void main(String[] args) {
        SpringApplication.from(ShopApplication::main)
            .with(Containers.class).run(args);
    }
}

Code Explained

@Testcontainers starts and stops @Container fields
Testcontainers 2's PostgreSQLContainer has no generic parameter
Containers as beans are shared across tests via the context cache
SpringApplication.from(…).with(…) runs the app plus containers

⚠ Common Mistakes

  • Non-static @Container fields; a new container starts for every test
  • Using latest image tags; tests change when the image does
  • Keeping H2-only tests for queries that use Postgres features

✓ Tips & Best Practices

  • Match the production database version in the image tag
  • Run Testcontainers ITs in CI with Docker available
  • Use the test main class instead of a hand-made Docker Compose for dev
