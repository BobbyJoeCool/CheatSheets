Profiles

@Profile · spring.profiles.active · application-{profile}.yml · profile groups · default profile · env var SPRING_PROFILES_ACTIVE

Environment-Specific Config

A profile is a named set of configuration and beans, such as dev, test or prod. Activate profiles with spring.profiles.active; Boot then loads application-{profile}.yml on top of the base file and registers beans marked @Profile for that profile. With none active, the default profile applies.

Notes

  • Later active profiles override earlier ones
  • Profile files always beat the base application.yml
  • spring.profiles.group activates several profiles under one name
  • spring.profiles.active can't be set inside a profile-specific file

Profile-Specific Beans

interface PaymentGateway { void charge(Money m); }

@Component @Profile("prod")
class StripeGateway implements PaymentGateway { /* real calls */ }

@Component @Profile("!prod")              // everything except prod
class FakeGateway implements PaymentGateway { /* logs only */ }

@Configuration @Profile({"dev", "test"})  // dev OR test
class DevDataConfig {
    @Bean CommandLineRunner seed(ProductRepository r) {
        return args -> r.save(new Product("Sample"));
    }
}

Files & Activation

# application.yml
spring.profiles.group.prod: [prod-db, prod-mail]
---
spring.config.activate.on-profile: dev   # this document = dev only
logging.level.com.example: DEBUG

Activate

java -jar app.jar --spring.profiles.active=prod
SPRING_PROFILES_ACTIVE=dev,local ./mvnw spring-boot:run

Code Explained

!prod matches whenever prod is not active
@Profile on a config class affects all its @Beans
prod group turns on prod-db and prod-mail too
on-profile scopes one YAML document to a profile

@Profile Expressions

ExpressionActive When
"prod"prod is active
"!prod"prod not active
{"a", "b"}a OR b
"a & b"a AND b
"a | (b & !c)"Combined

⚠ Common Mistakes

  • Setting spring.profiles.active inside application-dev.yml; it's rejected
  • Building one jar per environment instead of activating profiles at runtime
  • Too many profiles for small differences; use env vars for single values

✓ Tips & Best Practices

  • Use @ActiveProfiles("test") in tests (Sheet 52)
  • Keep prod settings in env vars or a secret store, not in the jar
  • Log active profiles at startup; Boot prints them in the first lines

Quick Summary

  • @Profile("x"): bean only in x
  • application-x.yml: config for x
  • spring.profiles.active: switch on
  • Groups: several profiles at once
