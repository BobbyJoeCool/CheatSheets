SecurityFilterChain · DelegatingFilterProxy · filter order · default login page · SecurityContextHolder · Authentication

How Spring Security Works

Adding spring-boot-starter-security secures every endpoint immediately: a login form, HTTP Basic, a generated password in the log, CSRF protection and secure headers. Under the hood a servlet filter (DelegatingFilterProxy) hands each request to a SecurityFilterChain: an ordered list of filters that authenticate the caller and then authorize the request.

Notes

  • Default user: user, password printed at startup
  • The result of authentication is an Authentication object
  • It's stored in the SecurityContextHolder (thread-local)
  • Boot 4 ships Spring Security 7 (lambda DSL only)

Reading the Current User

@RestController
class MeController {

    @GetMapping("/me")
    Map<String, Object> me(@AuthenticationPrincipal UserDetails user) {
        return Map.of("name", user.getUsername(),
                      "roles", user.getAuthorities());
    }

    @GetMapping("/whoami")
    String whoami(Authentication auth) {          // injected directly
        return auth.getName();
    }
}

// anywhere in the same thread (e.g. a service)
var auth = SecurityContextHolder.getContext().getAuthentication();

Code Explained

@AuthenticationPrincipal injects the logged-in principal
An Authentication parameter works in any controller method
Roles are authorities with a ROLE_ prefix
Fixed dev credentials replace the generated password

⚠ Common Mistakes

  • Shipping with the generated password or spring.security.user.*
  • Reading SecurityContextHolder in another thread; it's thread-local
  • Assuming security is off for some URLs; it locks down everything

✓ Tips & Best Practices

  • Log org.springframework.security at DEBUG to see each filter decision
  • Use @AuthenticationPrincipal with your own user type
  • Read the filter list Boot logs at startup with DEBUG
