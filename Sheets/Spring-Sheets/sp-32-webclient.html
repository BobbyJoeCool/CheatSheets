The Reactive Client

WebClient is the non-blocking HTTP client from Spring WebFlux. Calls return Mono<T> (zero or one value) or Flux<T> (a stream) instead of the value itself, so many requests can run concurrently on few threads. In a regular Spring MVC app, RestClient is simpler; reach for WebClient when you're on WebFlux or need streaming.

Notes

  • Needs spring-boot-starter-webflux (MVC apps stay on Tomcat)
  • Inject Boot's WebClient.Builder, like RestClient.Builder
  • Nothing happens until something subscribes (or you block())
  • Never block() inside a WebFlux request thread

Mono, Flux and Timeouts

@Component
class WeatherClient {
    private final WebClient http;
    WeatherClient(WebClient.Builder b) {
        this.http = b.baseUrl("https://api.weather.example").build();
    }

    Mono<Forecast> forecast(String city) {
        return http.get().uri("/forecast?city={c}", city)
            .retrieve()
            .bodyToMono(Forecast.class)
            .timeout(Duration.ofSeconds(3))                   // per call
            .onErrorResume(WebClientResponseException.NotFound.class,
                           e -> Mono.empty());
    }

    Flux<Alert> alerts() {                                    // stream
        return http.get().uri("/alerts").retrieve().bodyToFlux(Alert.class);
    }
}

Mono.zip(client.forecast("Oslo"), client.forecast("Rome"))
    .map(t -> List.of(t.getT1(), t.getT2()))
    .block(Duration.ofSeconds(5));                            // MVC only

Code Explained

bodyToMono / bodyToFlux decode JSON lazily
timeout() fails the Mono if no result in time
onErrorResume turns a 404 into an empty result
Mono.zip runs both calls at once and waits for both

⚠ Common Mistakes

  • Adding WebFlux just for WebClient when RestClient would do
  • Calling block() in a reactive pipeline; it can deadlock the event loop
  • Building a Mono and never subscribing; the request is never sent

✓ Tips & Best Practices

  • With virtual threads, blocking RestClient code scales well too
  • Use Mono.zip / Flux.merge for fan-out calls
  • Set connector timeouts via spring.http.clients.* properties

Quick Summary

  • WebClient: non-blocking client
  • bodyToMono / bodyToFlux
  • Lazy: runs on subscribe / block()
  • Prefer RestClient in MVC apps
