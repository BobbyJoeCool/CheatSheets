Entity Relationships

@ManyToOne · @OneToMany · mappedBy · @ManyToMany · @JoinColumn · cascade · orphanRemoval · FetchType.LAZY

Associations Between Entities

Relationships map foreign keys to object references. @ManyToOne is the owning side with the FK column; @OneToMany(mappedBy = …) is its inverse; @ManyToMany uses a join table. The side without mappedBy owns the relationship, and only changes to the owning side are written to the database.

Notes

  • Make @ManyToOne LAZY; its default is EAGER
  • @OneToMany and @ManyToMany are LAZY by default
  • Keep both sides in sync with helper methods
  • Use Set for @ManyToMany to avoid duplicate-delete issues

Order ↔ OrderLine

@Entity
class Order {
    @Id @GeneratedValue private Long id;

    @ManyToOne(fetch = FetchType.LAZY, optional = false)
    @JoinColumn(name = "customer_id")             // FK column
    private Customer customer;

    @OneToMany(mappedBy = "order", cascade = CascadeType.ALL,
               orphanRemoval = true)
    private List<OrderLine> lines = new ArrayList<>();

    @ManyToMany
    @JoinTable(name = "order_tag",
        joinColumns = @JoinColumn(name = "order_id"),
        inverseJoinColumns = @JoinColumn(name = "tag_id"))
    private Set<Tag> tags = new HashSet<>();

    void addLine(OrderLine l)    { lines.add(l); l.setOrder(this); }
    void removeLine(OrderLine l) { lines.remove(l); l.setOrder(null); }
}

@Entity
class OrderLine {
    @Id @GeneratedValue private Long id;
    @ManyToOne(fetch = FetchType.LAZY) private Order order;   // owning side
}

Code Explained

mappedBy = "order" names the field on OrderLine that owns it
CascadeType.ALL: saving an Order saves its lines
orphanRemoval: removing a line from the list deletes the row
addLine sets both sides, so memory and DB agree

⚠ Common Mistakes

  • Setting only order.getLines().add(line); the FK isn't written
  • CascadeType.REMOVE on @ManyToMany, deleting shared rows
  • Leaving @ManyToOne EAGER; every load pulls the parent too

✓ Tips & Best Practices

  • Prefer unidirectional @ManyToOne unless you need the collection
  • Model a join table with extra columns as its own entity
  • Initialize collections at declaration to avoid null

Quick Summary

  • @ManyToOne: owning side + FK
  • mappedBy: inverse side
  • cascade + orphanRemoval: children
  • FetchType.LAZY: default choice
