Application Events

Beans can communicate through events without depending on each other: one publishes with ApplicationEventPublisher, others react with @EventListener methods. Listeners run synchronously in the same thread by default. @TransactionalEventListener waits until the surrounding transaction commits, which is the right place for emails and messages.

Notes

  • Any object can be an event; records work well
  • Add @Async to a listener to run it on another thread
  • Boot publishes lifecycle events such as ApplicationReadyEvent
  • Spring Modulith builds on events for modular apps

Publish and Listen

public record OrderPlaced(long orderId, String email) { }

@Service
class OrderService {
    private final ApplicationEventPublisher events;
    OrderService(ApplicationEventPublisher events) { this.events = events; }

    @Transactional
    public void place(Order o) {
        repo.save(o);
        events.publishEvent(new OrderPlaced(o.id(), o.email()));
    }
}

@Component
class OrderListeners {
    @EventListener
    void updateStats(OrderPlaced e) { … }                  // same tx, sync

    @TransactionalEventListener                          // after commit
    void sendEmail(OrderPlaced e) { mail.confirm(e.email()); }
}

Code Explained

publishEvent calls each synchronous listener before returning
A rollback means sendEmail never runs
@EventListener(condition = "#e.orderId > 1000") filters events
Listener exceptions in sync listeners propagate to the publisher

⚠ Common Mistakes

  • Sending emails in a plain @EventListener, then the transaction rolls back
  • Writing to the DB in an AFTER_COMMIT listener without a new transaction
  • Events for everything; direct calls are clearer inside one module

✓ Tips & Best Practices

  • Use REQUIRES_NEW for DB writes in after-commit listeners
  • Combine @Async + @TransactionalEventListener for slow side effects
  • Test with @RecordApplicationEvents + ApplicationEvents

Quick Summary

  • publishEvent(obj): fire
  • @EventListener: react (sync)
  • @TransactionalEventListener: after commit
  • @Async: off the caller's thread
