Creating and Evolving the Schema

For anything beyond a demo, manage the schema with a migration tool. Flyway runs versioned SQL files from db/migration in order and records each one in flyway_schema_history, so every environment ends up identical. Liquibase does the same with XML/YAML/SQL changelogs. For quick prototypes, schema.sql / data.sql or Hibernate's ddl-auto can create tables.

Notes

  • Boot 4: add spring-boot-starter-flyway (or -liquibase)
  • Migrations run at startup, before JPA starts
  • Never edit an applied migration; add a new one
  • ddl-auto=validate checks entities against the real schema

Flyway Migration Files

-- src/main/resources/db/migration/V1__create_customer.sql
CREATE TABLE customer (
    id         BIGSERIAL PRIMARY KEY,
    name       VARCHAR(80)  NOT NULL,
    email      VARCHAR(120) NOT NULL UNIQUE,
    created_at TIMESTAMP    NOT NULL DEFAULT now()
);

-- V2__add_customer_phone.sql
ALTER TABLE customer ADD COLUMN phone VARCHAR(20);

-- R__customer_view.sql   (repeatable: re-runs when it changes)
CREATE OR REPLACE VIEW active_customer AS SELECT * FROM customer;

application.yml

spring:
  flyway:
    locations: classpath:db/migration
    baseline-on-migrate: true      # adopt an existing database
  jpa.hibernate.ddl-auto: validate   # never let Hibernate change prod

Code Explained

V1__ / V2__: version, two underscores, description
Flyway runs pending versions in order, once each
R__ files re-run whenever their checksum changes
validate fails startup if an entity doesn't match a table

ddl-auto Values

ValueDoes
noneNothing (prod default)
validateCheck, don't change
updateAdd missing columns
createDrop + create
create-drop…and drop on exit

⚠ Common Mistakes

  • Editing V1__…sql after it ran; checksum mismatch fails every startup
  • ddl-auto=update in production; it never drops or renames safely
  • Mixing Flyway with schema.sql; both try to create the same tables

✓ Tips & Best Practices

  • Test migrations against the real database with Testcontainers
  • Name files by intent: V7__add_order_status_index.sql
  • Keep data fixes in migrations too, so every environment gets them

Quick Summary

  • V#__desc.sql: versioned migration
  • starter-flyway: runs at startup
  • ddl-auto=validate: check only
  • schema.sql / data.sql: prototypes
