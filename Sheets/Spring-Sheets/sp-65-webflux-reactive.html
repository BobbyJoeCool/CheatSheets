Reactive Web with WebFlux

Spring WebFlux is the non-blocking alternative to Spring MVC, running on Netty by default. Handlers return Mono<T> (0–1 item) or Flux<T> (0–N items) from Project Reactor, and nothing runs until the framework subscribes. Use it for streaming and very high concurrency with reactive drivers; with virtual threads, Spring MVC now covers most other cases.

Notes

  • Add spring-boot-starter-webflux (not together with webmvc as server)
  • Every layer must be non-blocking: R2DBC, reactive Mongo/Redis
  • Same annotations as MVC: @RestController, @GetMapping
  • Or use functional RouterFunction endpoints

Annotated and Functional Endpoints

@RestController
@RequestMapping("/api/products")
class ProductController {
    private final ProductRepository repo;          // ReactiveCrudRepository

    @GetMapping("/{id}")
    Mono<Product> get(@PathVariable String id) {
        return repo.findById(id)
            .switchIfEmpty(Mono.error(new ProductNotFound(id)));
    }

    @GetMapping(produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    Flux<Product> stream() {                         // server-sent events
        return repo.findAll().delayElements(Duration.ofMillis(100));
    }

    @PostMapping
    Mono<Product> create(@RequestBody Mono<Product> body) {
        return body.map(Product::normalize).flatMap(repo::save);
    }
}

Code Explained

switchIfEmpty turns an empty Mono into an error (404)
TEXT_EVENT_STREAM streams items as they arrive
flatMap chains another async call (the save)
RouterFunction beans are the annotation-free alternative

⚠ Common Mistakes

  • Calling JDBC/JPA or block() inside a WebFlux handler; it stalls the event loop
  • Building a Mono and never returning or subscribing to it
  • Choosing WebFlux for a CRUD app that virtual threads would serve fine

✓ Tips & Best Practices

  • Use publishOn(Schedulers.boundedElastic()) for unavoidable blocking calls
  • Test with WebTestClient and Reactor's StepVerifier
  • Turn on BlockHound in tests to catch blocking calls

Quick Summary

  • Mono (0–1) · Flux (0–N)
  • Same annotations, reactive types
  • Non-blocking end to end
  • Lazy: runs on subscribe
