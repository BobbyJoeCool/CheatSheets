@ConfigurationProperties

@ConfigurationProperties · prefix · records · @Validated · @EnableConfigurationProperties · metadata

Type-Safe Configuration

@ConfigurationProperties binds a whole prefix of keys onto a class or record, converting types and nesting objects, lists and maps. Add @Validated with Bean Validation annotations to fail startup on bad values. It's the recommended way to read your own settings; @Value is for one-offs.

Notes

  • Records bind through the constructor and are immutable
  • Register with @ConfigurationPropertiesScan or @EnableConfigurationProperties
  • Binding is relaxed: max-size, maxSize and MAX_SIZE all work
  • spring-boot-configuration-processor adds IDE autocomplete

Binding a Prefix to a Record

@ConfigurationProperties("app.storage")
@Validated
public record StorageProperties(
        @NotBlank String bucket,
        @DefaultValue("10MB") DataSize maxUpload,
        @DefaultValue("30s") Duration timeout,
        List<String> allowedTypes,
        Map<String, String> tags,
        Retry retry) {

    public record Retry(@DefaultValue("3") int attempts) { }
}

@SpringBootApplication
@ConfigurationPropertiesScan          // finds @ConfigurationProperties
class App { }

application.yml

app.storage:
  bucket: media
  max-upload: 25MB
  allowed-types: [jpg, png]
  retry.attempts: 5

Code Explained

@DefaultValue sets a default for a constructor-bound field
@NotBlank fails startup if app.storage.bucket is missing
Nested record Retry maps to app.storage.retry.*
Inject StorageProperties into any bean's constructor

⚠ Common Mistakes

  • Forgetting to register the class; startup says no bean of that type
  • Using a mutable JavaBean without setters; fields stay null
  • Validation annotations without @Validated; they're ignored

✓ Tips & Best Practices

  • Prefer records: immutable, no setters, constructor binding
  • Prefix with your app name (app., shop.) to avoid clashes
  • Add the configuration processor so typos show up in the IDE

Quick Summary
