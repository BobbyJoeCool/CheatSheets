@SpringBootTest · webEnvironment · RANDOM_PORT · @TestConfiguration · @DynamicPropertySource · context caching

Full Integration Tests

@SpringBootTest starts the whole application context for a JUnit test, just like main() would, so you can inject real beans. By default it uses a mock servlet environment; with webEnvironment = RANDOM_PORT it starts a real server. Spring caches contexts between test classes with the same configuration, so keep that configuration consistent.

Notes

  • Needs spring-boot-starter-test (JUnit, AssertJ, Mockito)
  • Boot 4: MockMvc and test clients need @AutoConfigure… annotations
  • @ActiveProfiles picks profiles for the test
  • @DynamicPropertySource sets properties from code

Integration Test

@SpringBootTest(webEnvironment = WebEnvironment.RANDOM_PORT)
@AutoConfigureRestTestClient
@ActiveProfiles("test")
class OrderFlowTests {

    @Autowired RestTestClient client;          // bound to the running server
    @Autowired OrderRepository orders;

    @Test
    void placesAnOrder() {
        client.post().uri("/api/orders")
            .body(new NewOrder("book", 2))
            .exchange()
            .expectStatus().isCreated();

        assertThat(orders.count()).isEqualTo(1);
    }

    @TestConfiguration                          // extra beans for this test
    static class Clocks {
        @Bean Clock clock() { return Clock.fixed(Instant.EPOCH, ZoneOffset.UTC); }
    }
}

Code Explained

RANDOM_PORT avoids clashes when tests run in parallel
Test classes can use field injection with @Autowired
@TestConfiguration adds beans without replacing the app config
Different properties or mocks = a new (slower) context

⚠ Common Mistakes

  • @SpringBootTest for everything; slices are much faster (Sheet 53)
  • @DirtiesContext everywhere; it throws away the cached context
  • @Transactional on RANDOM_PORT tests; the server runs another thread

✓ Tips & Best Practices

  • Share one base test class so contexts are cached and reused
  • Use Testcontainers for the database (Sheet 56)
  • Inject Clock so time-based logic is testable

Quick Summary

  • @SpringBootTest: whole app
  • RANDOM_PORT: real server
  • @TestConfiguration: extra beans
  • Context cache: keep config stable
