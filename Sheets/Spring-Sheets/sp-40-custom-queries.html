@Query & Projections

@Query JPQL · nativeQuery · named params · @Modifying · interface projections · DTO / record projections

Writing Your Own Queries

@Query puts JPQL (or native SQL with nativeQuery = true) on a repository method. Bind values with named parameters (:email). Add @Modifying for UPDATE / DELETE. Return projections to fetch only the columns you need: an interface with getters, or a record (DTO) built by the query.

Notes

  • JPQL uses entity and field names, not tables and columns
  • Queries are validated at startup (JPQL only)
  • @Modifying bypasses the persistence context; set clearAutomatically
  • Record projections are matched by constructor parameter names

JPQL, Native and Projections

interface OrderRepository extends JpaRepository<Order, Long> {

    @Query("""
        select o from Order o
        where o.customer.email = :email and o.total > :min""")
    List<Order> bigOrders(String email, BigDecimal min);

    @Query(value = "select * from orders where created_at > :since",
           nativeQuery = true)
    List<Order> since(Instant since);

    @Modifying(clearAutomatically = true)
    @Transactional
    @Query("update Order o set o.status = :to where o.status = :from")
    int moveAll(Status from, Status to);                 // rows updated

    // interface projection
    interface OrderSummary { Long getId(); BigDecimal getTotal(); }
    List<OrderSummary> findByStatus(Status s);

    // record (DTO) projection
    record CustomerTotal(String email, BigDecimal total) { }
    @Query("select new com.example.CustomerTotal(c.email, sum(o.total)) " +
           "from Order o join o.customer c group by c.email")
    List<CustomerTotal> totals();
}

Code Explained

Named params bind by parameter name (-parameters flag)
@Modifying methods return affected-row count
Interface projection: only id, total are selected
new …CustomerTotal(…): JPQL constructor expression

⚠ Common Mistakes

  • Table/column names in JPQL; it expects entity/field names
  • @Modifying without a transaction → TransactionRequiredException
  • Native queries tied to one database, then switching to H2 for tests

✓ Tips & Best Practices

  • Use text blocks ("""…""") for long queries
  • Return projections for list screens; load entities only to change them
  • Name the parameters exactly like the :placeholders

Quick Summary

  • @Query("jpql"): custom query
  • nativeQuery = true: raw SQL
  • @Modifying: update / delete
  • Projections: fetch less
