Auditing and Dynamic Queries

Auditing records who created or changed an entity and when: annotate fields with @CreatedDate, @CreatedBy and friends, then turn it on with @EnableJpaAuditing. Specifications build WHERE clauses at runtime from optional filters, ideal for search screens.

Notes

  • AuditorAware supplies the current user (e.g. from Spring Security)
  • A @MappedSuperclass base entity shares audit fields
  • Repository must extend JpaSpecificationExecutor<T>
  • Query by Example: repo.findAll(Example.of(probe))

Auditing

@MappedSuperclass
@EntityListeners(AuditingEntityListener.class)
abstract class Audited {
    @CreatedDate        Instant createdAt;
    @LastModifiedDate   Instant updatedAt;
    @CreatedBy          String createdBy;
}

@Configuration @EnableJpaAuditing
class AuditConfig {
    @Bean AuditorAware<String> auditor() {      // current user
        return () -> Optional.of(currentUser.name());
    }
}

Specifications

static Specification<Product> nameLike(String q) {
    return (root, query, cb) -> q == null ? null
        : cb.like(cb.lower(root.get("name")), "%" + q.toLowerCase() + "%");
}
static Specification<Product> maxPrice(BigDecimal max) {
    return (root, query, cb) -> max == null ? null : cb.le(root.get("price"), max);
}

repo.findAll(nameLike(q).and(maxPrice(max)), pageable);

Code Explained

Auditing fields are set on insert and update automatically
AuditorAware returns the username, or empty for system jobs
A spec returning null is ignored, so filters are optional
and() / or() combine specs; paging still works

⚠ Common Mistakes

  • Forgetting the AuditingEntityListener; audit fields stay null
  • Using field-name strings that drift from the entity; use the JPA metamodel
  • Specs that join collections without query.distinct(true)

✓ Tips & Best Practices

  • Generate the metamodel (Product_.price) for type-safe specs
  • Use Querydsl if you prefer a fluent, typed query API
  • Inject Clock via a DateTimeProvider to test audit times

Quick Summary

  • @EnableJpaAuditing: turn on
  • @CreatedDate / @CreatedBy
  • Specification: dynamic WHERE
  • JpaSpecificationExecutor: run them
