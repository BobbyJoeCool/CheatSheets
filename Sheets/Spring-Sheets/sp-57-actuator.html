Production Endpoints

Actuator adds operational endpoints under /actuator: health, info, metrics, environment, loggers, beans and more. Only health is exposed over HTTP by default; expose others explicitly and secure them. Health combines indicators for the database, disk, Redis and so on, and Kubernetes liveness/readiness probes come built in.

Notes

  • Add spring-boot-starter-actuator
  • Run Actuator on a separate port with management.server.port
  • Health details are hidden unless show-details allows them
  • /actuator/loggers changes log levels at runtime (POST)

application.yml

management:
  endpoints.web.exposure.include: health, info, metrics, prometheus, loggers
  endpoint.health:
    show-details: when-authorized
    probes.enabled: true          # /actuator/health/liveness, /readiness
  info.env.enabled: true
info.app:
  name: shop
  version: '@project.version@'    # Maven resource filtering

Custom Health Indicator

@Component
class PaymentGatewayHealth implements HealthIndicator {
    private final PaymentClient client;
    PaymentGatewayHealth(PaymentClient client) { this.client = client; }

    @Override
    public Health health() {
        return client.ping()
            ? Health.up().withDetail("latencyMs", client.lastLatency()).build()
            : Health.down().withDetail("reason", "no response").build();
    }
}

Code Explained

Exposed endpoints appear at /actuator/{id}
when-authorized shows details to users with a role
Bean PaymentGatewayHealth shows up as paymentGateway
Any DOWN indicator makes overall health DOWN (503)

⚠ Common Mistakes

  • exposure.include=* on a public port; env and heapdump leak secrets
  • Probes that check external services; one outage restarts every pod
  • Forgetting to secure Actuator when Spring Security is present

✓ Tips & Best Practices

  • Put Actuator on an internal management.server.port
  • Group indicators: management.endpoint.health.group.*
  • Add a @ReadOperation custom endpoint with @Endpoint(id = "…")

Quick Summary
