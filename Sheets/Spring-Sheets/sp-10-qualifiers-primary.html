Sheet 10

Resolving Ambiguity

@Qualifier · @Primary · @Fallback · bean name matching · NoUniqueBeanDefinitionException · custom qualifiers

When Several Beans Match

Injection is by type. When two beans share a type, Spring needs a tie-breaker or startup fails with NoUniqueBeanDefinitionException. Mark the default with @Primary, pick one explicitly with @Qualifier, demote a bean with @Fallback (6.2+), or let the parameter name match the bean name.

Notes

  • Resolution order: @Qualifier → @Primary → non-@Fallback → name
  • @Qualifier on the bean and on the injection point must match
  • Parameter-name matching needs the -parameters compiler flag (Boot sets it)
  • List<T> injection sidesteps the problem by taking all of them

Three Ways to Choose

interface Notifier { void send(String msg); }

@Component @Primary                         // default choice
class EmailNotifier implements Notifier { /* ... */ }

@Component @Qualifier("sms")                // tagged
class SmsNotifier implements Notifier { /* ... */ }

@Component @Fallback                        // used only if nothing else
class LogNotifier implements Notifier { /* ... */ }

@Service
class AlertService {
    AlertService(Notifier main,                       // EmailNotifier
                 @Qualifier("sms") Notifier urgent,   // SmsNotifier
                 Notifier logNotifier) {              // by name
    }
}

Custom Qualifier Annotation

@Qualifier @Retention(RUNTIME) @Target({TYPE, PARAMETER, METHOD})
@interface Urgent { }        // then: @Urgent Notifier n

Code Explained

main gets the @Primary bean
@Qualifier("sms") matches the bean tagged sms (or named sms)
logNotifier matches the bean name of LogNotifier
A custom qualifier is type-safe; no typo-prone strings

Tie-Breakers

AnnotationEffect
@PrimaryDefault when ambiguous
@Qualifier("x")Select by tag/name
@FallbackLowest priority (6.2)
@Priority(n)Lower n wins
@Order(n)Order in List<T> only

⚠ Common Mistakes

  • Two @Primary beans of one type; you're back to ambiguity
  • Using @Order to pick a single bean; it only sorts collections
  • Relying on parameter names, then renaming a bean in a refactor

✓ Tips & Best Practices

  • Prefer one @Primary + @Qualifier for the exceptions
  • Use custom qualifier annotations in larger codebases
  • Use @Fallback for library defaults that apps may override

Quick Summary

  • @Primary: default bean
  • @Qualifier: pick explicitly
  • @Fallback: only if nothing else
  • Param name = bean name: last resort
