Where Names Live

Python looks up names with the LEGB rule: Local, Enclosing function, Global (module), then Built-in. Reading an outer name needs no declaration. But assigning to a name anywhere in a function makes it local for the whole function, unless you declare it global or nonlocal.

Notes

  • if, for, while, with do not create scopes
  • Functions, classes, and comprehensions do
  • Loop variables remain after the loop ends
  • global targets module level; nonlocal the enclosing function
  • Shadowing a built-in (list = ...) hides it module-wide

LEGB in Action

x = "global"
def outer():
    x = "enclosing"
    def inner():
        x = "local"
        print(x)               # local
    inner()
    print(x)                   # enclosing
outer(); print(x)              # global

count = 0
def bump():
    global count               # rebind the module-level name
    count += 1
bump(); print(count)           # 1

def broken():
    print(count)               # UnboundLocalError
    count = 5                  # this makes count local everywhere

Code Explained

each function has its own x
lookup stops at the first scope that has the name
global count — assignment changes the module variable
broken() — the later assignment makes count local, so the read fails

⚠ Common Mistakes

  • UnboundLocalError — reading a name you assign later in the function
  • Overusing global — hidden coupling; pass and return values
  • Naming variables list, sum, input — shadows built-ins
  • Expecting for or if blocks to hide variables

✓ Tips & Best Practices

  • Pass data in as arguments and return results
  • Module-level constants are fine; mutable globals are not
  • Use nonlocal for small closures, a class for bigger state
  • Lint with ruff to catch shadowed built-ins

Quick Summary

  • LEGB — lookup order
  • assign inside → local
  • global — rebind module name
  • blocks — no new scope
