Creating Packages

__init__.py · package layout · pyproject.toml · src layout · namespace packages

Organizing and Shipping Code

A package is a folder of modules, usually marked with an __init__.py file that runs when the package is imported. Modern projects describe themselves in pyproject.toml (name, version, dependencies, entry points) and keep code under src/ to avoid accidental imports from the working folder. Build a wheel to share it, or install it in editable mode while developing.

Notes

  • __init__.py can be empty, or re-export the public API
  • Folders without __init__.py become namespace packages
  • __main__.py makes python -m mypkg work
  • Editable installs pick up code changes immediately

__init__.py and pyproject.toml

# src/mypkg/__init__.py
"""mypkg: tools for tidy data."""
from .core import load, save        # re-export the public API
__all__ = ["load", "save"]
__version__ = "0.1.0"
# pyproject.toml
[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"
[project]
name = "mypkg"
version = "0.1.0"
requires-python = ">=3.10"
dependencies = ["requests>=2.31"]
[project.scripts]
mypkg = "mypkg.cli:main"            # command-line entry point

Code Explained

re-export — users write from mypkg import load
[build-system] — which tool builds the package
[project] — metadata and dependencies
[project.scripts] — installs a mypkg command

⚠ Common Mistakes

  • Flat layout with tests importing local folders instead of the installed package
  • Heavy work in __init__.py — slows every import
  • Forgetting to bump version before publishing — upload rejected
  • Listing dev tools (pytest, ruff) as runtime dependencies

✓ Tips & Best Practices

  • Use the src/ layout for anything you'll distribute
  • Put dev tools under [project.optional-dependencies] or dependency groups
  • Keep the public API small and re-exported from __init__.py
  • Test publishing on TestPyPI first

Quick Summary

  • package — folder + __init__.py
  • pyproject.toml — project config
  • src/ layout — safer imports
  • pip install -e . — develop in place
