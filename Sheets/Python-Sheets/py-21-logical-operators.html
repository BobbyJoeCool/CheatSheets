Logical Operators

and · or · not · short-circuit · return values

Combining Conditions

and, or, and not combine conditions. and and or short-circuit: they stop as soon as the result is known and return the last operand evaluated, which may not be a bool. not always returns True or False. Precedence runs not → and → or.

Notes

  • Words, not symbols: no && or ||
  • & and | are bitwise, with different precedence
  • Right-hand side is skipped when the left decides
  • Works on truthiness (Sheet 10), not just bools
  • De Morgan: not (a and b) == not a or not b

Logic & Short-Circuiting

True and False, True or False  # (False, True)
not True, not 0                # (False, True)
0 and 1 / 0                    # 0  (right side never runs)
1 or 1 / 0                     # 1
"" or "default"                # 'default'
"Ana" and "Bo"                 # 'Bo'  (last evaluated)
None or [] or 0                # 0  (all falsy → last one)
True or False and False        # True  (and binds first)
(True or False) and False      # False
x = 7
not (x > 5 or x < 0)           # False
user = {"name": "Ana"}
user and user.get("name")      # 'Ana'  (guard)

Code Explained

0 and ... — and stops at the first falsy value
1 or ... — or stops at the first truthy value
"" or "default" — classic fallback pattern
user and user.get(...) — skips the call when user is empty

⚠ Common Mistakes

  • if x == "a" or "b": — always true; use x in ("a", "b")
  • Using & / | instead of and / or — bitwise, binds tighter
  • count or 10 replaces a valid 0 with 10
  • Mixing and/or without parentheses — easy to misread

✓ Tips & Best Practices

  • Guard against None: if obj and obj.items:
  • Use any() / all() for conditions over a collection
  • Put the cheap or most-likely-false check first in and
  • Parenthesize mixed and/or even when not required

Quick Summary

  • and — both truthy; returns an operand
  • or — either truthy; returns an operand
  • not — always a bool
  • short-circuit — skips the right side
