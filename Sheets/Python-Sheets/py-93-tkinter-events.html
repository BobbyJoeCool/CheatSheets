Events & Callbacks

command= · bind() · event object · <Button-1> · <Key> · StringVar

Responding to the User

GUIs are event-driven: your code runs when the user does something. command= attaches a no-argument callback to buttons and similar widgets. bind() attaches a handler to any event, such as a key press or mouse click, and passes an event object with details. Control variables like StringVar keep widgets in sync and can notify you when they change.

Notes

  • command= callbacks take no arguments
  • bind() handlers receive one event argument
  • Bind on root for window-wide shortcuts
  • Callbacks must return quickly to keep the UI responsive
  • trace_add("write", f) watches a variable

command, bind, Variables

import tkinter as tk
root = tk.Tk()
name = tk.StringVar(value="Ana")
tk.Entry(root, textvariable=name).pack()
tk.Label(root, textvariable=name).pack()   # mirrors the entry live
def on_click():                            # command=: no arguments
    print("Hello", name.get())
tk.Button(root, text="Greet", command=on_click).pack()
def on_key(event):                         # bind(): gets an event
    print(event.keysym, repr(event.char))  # e.g. a 'a'
root.bind("<Key>", on_key)
canvas = tk.Canvas(root, width=200, height=100, bg="white")
canvas.pack()
canvas.bind("<Button-1>", lambda e: print(e.x, e.y))  # click position
root.bind("<Control-s>", lambda e: print("save"))
root.bind("<Return>", lambda e: on_click())
name.trace_add("write", lambda *args: print("now:", name.get()))
root.mainloop()

Code Explained

textvariable= — widget reads and writes the variable
command=on_click — pass the function, don't call it
event.keysym — key name like Return or a
lambda e: ... — adapt a no-arg function for bind()
trace_add — runs whenever the value changes

⚠ Common Mistakes

  • command=save() — runs once at startup, then never
  • bind() handler without an event parameter — TypeError
  • Lambdas created in a loop all use the last value — bind with i=i
  • Long tasks in a callback — the window freezes

✓ Tips & Best Practices

  • Use root.bind_all() for shortcuts that work in every widget
  • Return "break" from a handler to stop default behavior
  • Use functools.partial to pass arguments to command=
  • Use after() or threads for slow work

Quick Summary

  • command= — button callbacks
  • bind("<Event>", f) — any event
  • event object — details of what happened
  • StringVar & co. — linked values
