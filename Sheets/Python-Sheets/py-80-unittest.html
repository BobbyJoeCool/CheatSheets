unittest Testing Framework

TestCase · setUp · tearDown · assertEqual · assertRaises · discover

Built-in Test Framework

unittest ships with Python and organizes tests as methods on classes that subclass unittest.TestCase. Each method whose name starts with test is one test. setUp() runs before every test and tearDown() after it. Assertion methods report clear failure messages, and python -m unittest discover finds and runs every test file.

Notes

  • Test files are named test_*.py for discovery
  • Each test gets a fresh setUp() state
  • Tests run in alphabetical order; don't depend on it
  • unittest.mock replaces dependencies with fakes
  • pytest can run unittest-style tests unchanged

A TestCase

import unittest
from shop import Cart                  # code under test
class TestCart(unittest.TestCase):
    def setUp(self):                   # before each test
        self.cart = Cart()
    def test_starts_empty(self):
        self.assertEqual(len(self.cart), 0)
    def test_add_item(self):
        self.cart.add("pen", 1.50)
        self.assertAlmostEqual(self.cart.total(), 1.50)
        self.assertIn("pen", self.cart)
    def test_negative_price(self):
        with self.assertRaises(ValueError):
            self.cart.add("pen", -1)
    @unittest.skip("not ready")
    def test_discounts(self): ...
if __name__ == "__main__":
    unittest.main()                    # python test_cart.py

Code Explained

TestCase — base class for a group of tests
setUp — build fresh fixtures for every test
assertAlmostEqual — safe float comparison
assertRaises as a context manager — expects an error
@unittest.skip — temporarily disable a test

⚠ Common Mistakes

  • Naming a method check_add — not collected; must start with test
  • Tests relying on each other's state or order
  • assertTrue(a == b) — failure message hides both values; use assertEqual
  • Comparing floats with assertEqual

✓ Tips & Best Practices

  • Use self.subTest(i=i) to loop over cases without stopping at the first failure
  • Patch dependencies with unittest.mock.patch("module.name")
  • Keep each test focused on one behavior
  • Run single tests by dotted name while debugging

Quick Summary

  • TestCase — test container
  • test_* methods — tests
  • setUp / tearDown — fixtures
  • assert* — checks with messages
