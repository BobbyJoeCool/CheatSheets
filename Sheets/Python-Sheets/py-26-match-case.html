match/case Pattern Matching

match · case · _ wildcard · | or-patterns · if guards · capture · class patterns

Structural Pattern Matching

match (3.10+) compares a subject against case patterns from top to bottom and runs the first one that matches. Patterns can be literals, alternatives joined with |, names that capture values, sequences, mappings, and class patterns, and any case can add an if guard. case _: is the catch-all. Unlike a C switch, there's no fall-through and no break.

Notes

  • Requires Python 3.10 or newer
  • If nothing matches, nothing happens — no error
  • A bare name always matches and binds; it doesn't compare
  • Compare against constants with dotted names: Color.RED

Literal, Guard, Sequence, Mapping

def http_status(code):
    match code:
        case 200 | 201: return "OK"          # or-pattern
        case 404: return "Not found"
        case n if 500 <= n < 600:            # capture + guard
            return f"Server error {n}"
        case _: return "Other"               # wildcard
http_status(503)                             # 'Server error 503'
def handle(cmd):
    match cmd.split():
        case ["go", direction]: return f"move {direction}"
        case ["drop", *items]: return f"drop {len(items)}"
        case []: return "empty"
handle("go north"), handle("drop a b")       # ('move north', 'drop 2')
event = {"type": "click", "pos": (3, 4)}
match event:
    case {"type": "click", "pos": (x, y)}:   # mapping pattern
        print(x, y)                          # 3 4

Code Explained

200 | 201 — matches either value
case n if ... — bind to n, then test the guard
["go", direction] — exactly two items, first is "go"
mapping pattern — checks listed keys; extra keys are ignored

⚠ Common Mistakes

  • case MAX: to compare a constant — it captures every value; use Config.MAX
  • Leaving out case _: — unmatched values pass silently
  • Expecting C-style fall-through — only one case ever runs
  • Using match for a plain value → value lookup — a dict is simpler

✓ Tips & Best Practices

  • Order cases from most specific to most general
  • Use match for command parsing and JSON-shaped data
  • Pair it with Enum members for readable constant cases
  • Raise in case _: when unknown input is a bug

Quick Summary

  • match x: — test x against cases
  • | / guards — alternatives and conditions
  • sequence / mapping / class — destructure
  • case _: — default; first match wins
