Multiple Inheritance & MRO

multiple inheritance · MRO · __mro__ · super() · diamond problem · mixins

Several Parents

A class can inherit from several bases: class D(B, C):. Python decides lookup order with the Method Resolution Order (MRO), computed by C3 linearization: a class comes before its parents, and parents keep their listed left-to-right order. super() calls the next class in the MRO, not necessarily the parent, which lets cooperative methods run every class exactly once.

Notes

  • Inspect order with Class.__mro__ or Class.mro()
  • Each class appears once, object last
  • An impossible order raises TypeError at class creation
  • Mixins add one small ability to many classes
  • Prefer composition when the hierarchy gets tangled

Diamond and Mixin

class A:
    def hello(self): return "A"
class B(A):
    def hello(self): return "B>" + super().hello()
class C(A):
    def hello(self): return "C>" + super().hello()
class D(B, C):
    def hello(self): return "D>" + super().hello()
D().hello()                            # 'D>B>C>A'
[k.__name__ for k in D.__mro__]        # ['D', 'B', 'C', 'A', 'object']

class JsonMixin:                       # adds one ability
    def to_json(self):
        import json
        return json.dumps(vars(self))
class User(JsonMixin):
    def __init__(self, name): self.name = name
User("Ana").to_json()                  # '{"name": "Ana"}'

Code Explained

diamond — B and C share parent A
B's super() goes to C, not A — that's the MRO
A runs once, even with two paths to it
JsonMixin — reusable behavior, no state of its own

⚠ Common Mistakes

  • Assuming super() means "my parent" — it means "next in MRO"
  • Calling A.__init__(self) directly in a diamond — A runs twice
  • Base order that contradicts another class's order — TypeError
  • Mixins with their own required state — fragile combinations

✓ Tips & Best Practices

  • Print Cls.__mro__ whenever lookup surprises you
  • Keep multiple inheritance to mixins plus one real base
  • Use **kwargs passthrough in cooperative __init__ methods
  • Prefer composition for anything more complex

Quick Summary
