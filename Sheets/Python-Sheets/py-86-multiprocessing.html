Multiprocessing

Process · Pool · Queue · ProcessPoolExecutor · __main__ guard

True Parallelism with Processes

multiprocessing runs code in separate processes, each with its own interpreter and memory, so CPU-heavy work can use every core despite the GIL. Data moves between processes by pickling, which adds overhead. Use Pool or concurrent.futures.ProcessPoolExecutor for parallel maps, and always put startup code under if __name__ == "__main__":.

Notes

  • Each process has separate globals; nothing is shared by default
  • Functions and arguments must be picklable (top-level defs)
  • Windows and macOS use the "spawn" start method
  • A Process discards its target's return value
  • Best for large CPU-bound tasks, not tiny ones

Process, Pool, Queue, Executor

from multiprocessing import Process, Pool, Queue, cpu_count
from concurrent.futures import ProcessPoolExecutor
def square(n):
    return n * n                       # runs in a worker process
def worker(q):
    q.put("hello from child")
if __name__ == "__main__":             # required with spawn
    p = Process(target=square, args=(5,))
    p.start(); p.join()                # return value is discarded
    with Pool(processes=cpu_count()) as pool:
        pool.map(square, range(5))     # [0, 1, 4, 9, 16]
    q = Queue()
    Process(target=worker, args=(q,)).start()
    q.get()                            # 'hello from child'
    with ProcessPoolExecutor() as ex:
        list(ex.map(square, [10, 20])) # [100, 400]
        ex.submit(square, 7).result()  # 49

Code Explained

__main__ guard — child processes re-import the module
Pool.map() — splits work across cores
Queue — pass results back from a Process
ProcessPoolExecutor — same API as the thread version
submit().result() — one task, then wait for its value

⚠ Common Mistakes

  • No __main__ guard — RuntimeError or endless child processes
  • Passing a lambda or nested function — PicklingError
  • Parallelizing tiny tasks — overhead outweighs the gain
  • Expecting a child to change the parent's globals

✓ Tips & Best Practices

  • Start with ProcessPoolExecutor().map()
  • Set chunksize for long input lists
  • Return results instead of sharing state
  • Measure first; sometimes NumPy vectorization beats processes
