pytest Testing Framework

assert · fixtures · parametrize · pytest.raises · markers

The Popular Test Runner

pytest is a third-party test framework (pip install pytest) that uses plain functions and plain assert statements; it rewrites asserts to show detailed failure output. Fixtures supply setup by naming them as test parameters. @pytest.mark.parametrize runs one test over many inputs, and pytest.raises checks for exceptions.

Notes

  • Collects test_*.py files and test_* functions
  • Shared fixtures live in conftest.py
  • Fixtures can yield to run teardown afterward
  • Built-in fixtures: tmp_path, capsys, monkeypatch
  • Configure in pyproject.toml under [tool.pytest.ini_options]

Fixtures, Raises, Parametrize

# test_cart.py   →  run with: pytest -v
import pytest
from shop import Cart
@pytest.fixture
def cart():                            # fresh object per test
    return Cart()
def test_add_item(cart):               # fixture injected by name
    cart.add("pen", 1.50)
    assert cart.total() == pytest.approx(1.50)
    assert "pen" in cart
def test_negative_price(cart):
    with pytest.raises(ValueError, match="price"):
        cart.add("pen", -1)
@pytest.mark.parametrize("qty, expected", [(1, 1.5), (3, 4.5), (0, 0)])
def test_quantities(cart, qty, expected):
    cart.add("pen", 1.50, qty=qty)
    assert cart.total() == pytest.approx(expected)

Code Explained

@pytest.fixture — reusable setup
cart parameter — pytest passes the fixture's return value
pytest.approx — tolerant float comparison
match= — regex checked against the error message
parametrize — three tests from one function

⚠ Common Mistakes

  • File or function names without the test_ prefix — silently skipped
  • Module-scoped fixtures that tests mutate — state leaks between tests
  • Comparing floats with == — use pytest.approx
  • pytest.raises without match= — passes on the wrong error message

✓ Tips & Best Practices

  • Put shared fixtures in conftest.py
  • Use tmp_path instead of writing to real folders
  • Add pytest-cov and run pytest --cov=mypkg
  • Register custom markers to avoid warnings

Quick Summary

  • plain assert — detailed failures
  • fixtures — setup by parameter name
  • parametrize — many cases, one test
  • pytest.raises — expect errors
