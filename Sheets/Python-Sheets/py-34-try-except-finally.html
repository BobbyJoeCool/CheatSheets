try/except/finally Blocks

try · except · else · finally · except as e · exception hierarchy

Handling Exceptions

try runs code that might fail. except catches matching exceptions, else runs only when nothing was raised, and finally always runs, even after return or an unhandled error, which makes it the place for cleanup. Python favors EAFP (easier to ask forgiveness than permission): try the operation and handle failure instead of pre-checking everything.

Notes

  • except clauses are checked top to bottom
  • A parent class catches all its subclasses
  • e from except ... as e is deleted after the block
  • Unhandled exceptions print a traceback and exit
  • For files and locks, with replaces most finally use

try / except / else / finally

text = "abc"
try:
    value = int(text)
except ValueError as e:
    print(f"bad data: {e}")    # bad data: invalid literal for int() ...
    value = 0
except TypeError:
    value = 0                  # text was None
else:
    print("parsed OK")         # only if no exception
finally:
    print("done")              # always runs

try:
    1 / 0
except (ZeroDivisionError, OverflowError) as e:
    print(type(e).__name__)    # ZeroDivisionError

Code Explained

except E as e — binds the exception object
multiple except — first match handles it
else — success path kept out of the try
finally — cleanup that must happen
tuple — one handler for several types

Clauses

ClauseRuns When
try:Always (first)
except E:E or a subclass raised
except (A, B):Either raised
except E as e:Same, with the object
else:No exception
finally:Always (last)

⚠ Common Mistakes

  • Bare except: — also catches Ctrl+C and sys.exit()
  • except Exception: pass — hides real bugs silently
  • Wrapping a whole function in try — you can't tell what failed
  • return inside finally — swallows the active exception

✓ Tips & Best Practices

  • Catch the most specific exception that you can handle
  • Keep the try block to the line(s) that can fail
  • Log with logger.exception("msg") to keep the traceback
  • Use with for files and locks instead of manual finally

Quick Summary

  • try / except — catch errors
  • else — success-only code
  • finally — guaranteed cleanup
  • specific exceptions — catch narrowly
