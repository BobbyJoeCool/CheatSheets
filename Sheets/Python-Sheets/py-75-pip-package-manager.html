pip & Package Management

pip install · pip uninstall · pip list · pip freeze · requirements.txt · pyproject.toml

Installing Third-Party Packages

pip installs packages from the Python Package Index (PyPI). Run it as python -m pip so it installs into the interpreter you actually use. Create a virtual environment per project so each project has its own isolated packages and versions. Record dependencies in requirements.txt for apps or pyproject.toml for packages.

Notes

  • venv ships with Python; no install needed
  • Activate the venv before installing
  • pip freeze lists exact installed versions
  • Never use sudo pip install
  • uv is a much faster pip/venv-compatible tool

pip & venv Commands

python -m venv .venv                       # create a virtual env
source .venv/bin/activate                  # macOS / Linux
.venv\Scripts\activate                     # Windows
python -m pip install requests             # latest version
python -m pip install "requests>=2.31,<3"  # version range
python -m pip install -U requests          # upgrade
python -m pip uninstall requests
python -m pip list                         # installed packages
python -m pip list --outdated              # upgrades available
python -m pip show requests                # version, location, deps
python -m pip freeze > requirements.txt    # pin exact versions
python -m pip install -r requirements.txt  # reproduce env
python -m pip install -e .                 # editable project install
deactivate                                 # leave the venv

Code Explained

python -m pip — ties pip to this interpreter
-U — upgrade to the newest allowed version
freeze — exact pins for reproducible installs
-r — install everything listed in a file
-e . — install your own project in editable mode

⚠ Common Mistakes

  • pip pointing at a different Python — use python -m pip
  • Installing without activating the venv — packages land globally
  • sudo pip install — can break the system Python
  • Committing .venv/ to git — add it to .gitignore

✓ Tips & Best Practices

  • One virtual environment per project
  • Pin versions for apps; use ranges for libraries
  • Run python -m pip check to find broken dependencies
  • Use pipx install ruff for tools you run everywhere

Quick Summary

  • python -m venv .venv — isolate
  • pip install / uninstall — manage
  • pip freeze — pin versions
  • -r requirements.txt — reproduce
