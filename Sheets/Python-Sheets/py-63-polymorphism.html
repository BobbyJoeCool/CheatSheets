Polymorphism & Duck Typing

overriding · duck typing · protocols · isinstance() · EAFP

Same Interface, Different Behavior

Polymorphism means code can call the same method on different types and get type-appropriate behavior. Python does this through method overriding and, more broadly, duck typing: if an object has the method you need, it works, regardless of its class. typing.Protocol lets type checkers verify that structural contract without inheritance.

Notes

  • "If it walks like a duck and quacks like a duck…"
  • Python checks for methods at call time, not class membership
  • EAFP: try it and catch the error
  • LBYL: check first with hasattr / isinstance
  • Operator overloading is polymorphism too (Sheet 66)

Overriding, Duck Typing, Protocol

class Circle:
    def __init__(self, r): self.r = r
    def area(self): return 3.14159 * self.r ** 2
class Square:
    def __init__(self, s): self.s = s
    def area(self): return self.s ** 2
shapes = [Circle(1), Square(2)]
[round(s.area(), 2) for s in shapes]   # [3.14, 4]
class FakeFile:                        # not a file, but has write()
    def write(self, text): print("LOG:", text)
def save(out, text): out.write(text)
save(FakeFile(), "hi")                 # LOG: hi
from typing import Protocol
class HasArea(Protocol):
    def area(self) -> float: ...
def total_area(items: list[HasArea]) -> float:
    return sum(i.area() for i in items)
total_area(shapes)                     # 7.14159

Code Explained

same call s.area() — each class answers its own way
FakeFile — accepted because it has write()
Protocol — describes the needed methods
no inheritance needed — Circle never mentions HasArea

⚠ Common Mistakes

  • Checking type(x) == list — rejects tuples and other sequences
  • Long isinstance chains — use overriding or singledispatch
  • Catching AttributeError around a big block — hides real bugs
  • Overrides with incompatible signatures — callers break

✓ Tips & Best Practices

  • Accept the most general type you can: any iterable, not just lists
  • Use Protocol to document duck-typed parameters
  • Use functools.singledispatch for type-based functions
  • Keep EAFP try blocks to a single operation

Quick Summary

  • polymorphism — one call, many behaviors
  • duck typing — methods matter, not class
  • EAFP — try, then handle
  • Protocol — structural type hints
