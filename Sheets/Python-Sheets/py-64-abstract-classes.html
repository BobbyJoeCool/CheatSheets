Defining Required Methods

An abstract base class (ABC) defines methods that subclasses must implement. Subclass abc.ABC and mark methods with @abstractmethod; Python then refuses to instantiate the base or any subclass that leaves one unimplemented. ABCs can also provide concrete shared methods. For interfaces checked by structure rather than inheritance, use typing.Protocol.

Notes

  • The check happens at instantiation, not at class definition
  • Abstract methods can still have a body for super() calls
  • Combine @property with @abstractmethod for required attributes
  • collections.abc has ready-made ABCs
  • @runtime_checkable enables isinstance with Protocols

ABC and Protocol

from abc import ABC, abstractmethod
class Shape(ABC):
    @abstractmethod
    def area(self) -> float: ...
    def describe(self):                # concrete, inherited
        return f"{type(self).__name__}: {self.area():.1f}"
class Rect(Shape):
    def __init__(self, w, h): self.w, self.h = w, h
    def area(self): return self.w * self.h
Shape()                                # TypeError: can't instantiate
Rect(2, 3).describe()                  # 'Rect: 6.0'
class Bad(Shape): pass
Bad()                                  # TypeError: abstract method 'area'
from typing import Protocol, runtime_checkable
@runtime_checkable
class Closeable(Protocol):
    def close(self) -> None: ...
isinstance(open(__file__), Closeable)  # True (structural match)

Code Explained

Shape(ABC) — marks the class as abstract
@abstractmethod — subclasses must override
describe() — shared code that relies on area()
Protocol — matches any class with close()

⚠ Common Mistakes

  • Forgetting to inherit from ABC — @abstractmethod is ignored
  • Misspelling the override name — the class stays abstract
  • Using ABCs for one-implementation code — needless ceremony
  • Expecting Protocol to enforce anything at runtime without @runtime_checkable

✓ Tips & Best Practices

  • Inherit from collections.abc.Mapping etc. to get mixin methods free
  • Use Protocol when you can't change the implementing classes
  • Raise NotImplementedError only for optional hooks
  • Keep interfaces small — two or three methods
