Context Managers

with · __enter__ · __exit__ · contextlib.contextmanager · suppress

Setup and Guaranteed Cleanup

A context manager runs setup code when a with block starts and cleanup code when it ends, even if the block raises an exception. Files, locks, database transactions, and temporary changes all use this pattern. Write one as a class with __enter__ / __exit__, or as a generator decorated with @contextlib.contextmanager.

Notes

  • __enter__'s return value is bound to the as name
  • __exit__ receives the exception info, or three Nones
  • Returning True from __exit__ suppresses the exception
  • Several managers: with a() as x, b() as y:

Class-Based and Generator-Based

import os, time
from contextlib import contextmanager
class Timer:
    def __enter__(self):
        self.start = time.perf_counter()
        return self                    # bound to `as t`
    def __exit__(self, exc_type, exc, tb):
        self.elapsed = time.perf_counter() - self.start
        return False                   # don't suppress errors
with Timer() as t:
    sum(range(10**6))
t.elapsed                              # 0.012 (seconds)
@contextmanager
def cd(path):
    old = os.getcwd(); os.chdir(path)  # setup
    try: yield                         # the with-body runs here
    finally: os.chdir(old)             # cleanup

Code Explained

__enter__ — setup; returns the as value
__exit__ — cleanup; runs on success or error
@contextmanager — code before yield is setup, after is cleanup
try/finally around yield — cleanup survives errors

⚠ Common Mistakes

  • Opening files without with — they stay open if an error occurs
  • No try/finally around yield — cleanup skipped on exceptions
  • Returning True from __exit__ by accident — errors vanish
  • Using a file after its with block — it's closed

✓ Tips & Best Practices

  • Use with for anything that must be released
  • Prefer @contextmanager for short setup/cleanup pairs
  • Use ExitStack when the number of resources varies

Quick Summary
