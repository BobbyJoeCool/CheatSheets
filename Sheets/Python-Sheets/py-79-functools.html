functools Module

partial() · reduce() · lru_cache() · cache · wraps() · singledispatch()

Function Tools

functools contains higher-order tools for working with functions. partial() pre-fills arguments, reduce() folds a sequence into one value, cache and lru_cache memoize results, wraps preserves metadata in decorators, singledispatch picks an implementation by argument type, and cached_property computes an attribute once.

Notes

  • Cached functions need hashable arguments
  • cache is lru_cache(maxsize=None) (3.9+)
  • Caching methods keeps self alive; be careful
  • total_ordering is covered on Sheet 65
  • wraps is covered on Sheet 44

functools in Action

from functools import partial, reduce, cache, lru_cache, singledispatch
int_from_bin = partial(int, base=2)
int_from_bin("1010")                   # 10
reduce(lambda a, b: a * b, [1, 2, 3, 4], 1)   # 24
@cache                                 # unbounded memo
def fib(n): return n if n < 2 else fib(n - 1) + fib(n - 2)
fib(80)                                # 23416728348467685, instantly
@lru_cache(maxsize=128)                # keeps 128 recent results
def lookup(key): ...
lookup.cache_info()                    # CacheInfo(hits=..., misses=...)
lookup.cache_clear()                   # empty the cache
@singledispatch
def show(x): return f"obj {x}"
@show.register
def _(x: int): return f"int {x}"
show(5), show("a")                     # ('int 5', 'obj a')

Code Explained

⚠ Common Mistakes

  • Caching a function that takes a list — TypeError: unhashable
  • Caching functions with side effects or time-dependent results
  • @lru_cache on methods — instances never get garbage-collected
  • reduce() on an empty sequence without initial — TypeError

✓ Tips & Best Practices

  • Use @cache for pure recursive functions
  • Use partial for callbacks that need fixed arguments
  • Prefer sum, max, math.prod over reduce
  • Use cached_property for expensive per-instance values
