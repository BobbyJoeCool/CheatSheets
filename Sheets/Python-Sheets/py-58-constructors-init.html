Initializing Instances

When you call a class, Python creates the object with __new__ and then runs __init__ to initialize it. __init__ receives the new object as self plus the call's arguments, sets attributes, and must return None. Python has no constructor overloading; use default arguments or @classmethod alternative constructors instead. @dataclass writes __init__ for you.

Notes

  • __init__ initializes; __new__ creates (rarely overridden)
  • Validate arguments in __init__ and raise early
  • Subclasses must call super().__init__(...)
  • Name alternative constructors from_x()
  • __post_init__ runs after a dataclass's __init__

__init__, Alternative Constructor, dataclass

class Account:
    def __init__(self, owner, balance=0.0):
        if balance < 0:
            raise ValueError("balance must be >= 0")
        self.owner = owner
        self.balance = balance
        self.history = []              # fresh list per instance
    @classmethod
    def from_csv(cls, line):           # alternative constructor
        owner, bal = line.split(",")
        return cls(owner, float(bal))
b = Account.from_csv("Bo,25.5")        # owner='Bo', balance=25.5
from dataclasses import dataclass, field
@dataclass
class Item:
    name: str
    price: float = 0.0
    tags: list = field(default_factory=list)
Item("pen", 1.5)                       # Item(name='pen', price=1.5, tags=[])

⚠ Common Mistakes

  • Returning a value from __init__ — TypeError
  • Mutable default parameter history=[] — shared across instances
  • Forgetting super().__init__() in a subclass — parent attributes missing
  • Misspelling __init__ (e.g. _init_) — never called, no error

✓ Tips & Best Practices

  • Use @dataclass for classes that mostly hold data
  • Add from_dict, from_json, from_csv classmethods
  • Keep __init__ cheap; no network or file I/O
  • Validate dataclass fields in __post_init__
