Operators & Containers

Dunder methods also let your objects use operators (+, *, abs()) and behave like containers (len(), indexing, in, iteration) or functions (obj()). When a + b fails on a, Python tries the reflected method b.__radd__(a). In-place methods like __iadd__ power +=; without one, Python falls back to __add__.

Notes

  • Return a new object from arithmetic methods
  • Return NotImplemented for unsupported operand types
  • __getitem__ alone makes objects iterable and sliceable
  • __call__ makes obj() work

A Vector and a Container

class Vec:
    def __init__(self, x, y): self.x, self.y = x, y
    def __repr__(self): return f"Vec({self.x}, {self.y})"
    def __add__(self, o): return Vec(self.x + o.x, self.y + o.y)
    def __mul__(self, k): return Vec(self.x * k, self.y * k)
    def __rmul__(self, k): return self * k      # handles 3 * v
    def __abs__(self): return (self.x**2 + self.y**2) ** 0.5
v = Vec(3, 4)
v + Vec(1, 1), v * 2, 2 * v   # (Vec(4, 5), Vec(6, 8), Vec(6, 8))
abs(v)                        # 5.0
class Playlist:
    def __init__(self, songs): self.songs = list(songs)
    def __len__(self): return len(self.songs)
    def __getitem__(self, i): return self.songs[i]
    def __contains__(self, s): return s in self.songs
p = Playlist(["A", "B", "C"])
len(p), p[1], p[-2:], "B" in p  # (3, 'B', ['B', 'C'], True)

Code Explained

__add__ — v + w
__rmul__ — 2 * v after int gives up
__getitem__ — indexing, slicing, and iteration
p[-2:] — slices arrive as a slice object

⚠ Common Mistakes

  • Mutating self in __add__ — a + b shouldn't change a
  • Forgetting __rmul__ — 2 * v raises TypeError
  • __len__ returning a non-int or negative — TypeError / ValueError
  • Raising TypeError instead of returning NotImplemented

✓ Tips & Best Practices

  • Implement __iter__ with yield for clean iteration
  • Subclass collections.abc.Sequence to get index, count, reversed free
  • Keep operators intuitive; don't overload + for unrelated actions
  • Use __call__ for configurable function objects
