Dunder Methods — Basics

__str__ · __repr__ · __eq__ · __lt__ · __hash__ · @total_ordering

Representation & Comparison

Dunder (double-underscore) methods let your classes plug into Python's built-in behavior. __repr__ and __str__ control how objects display, __eq__ and __lt__ define comparisons, and __hash__ lets objects go in sets and act as dict keys. @functools.total_ordering derives the remaining comparisons from __eq__ plus one ordering method.

Notes

  • print() uses __str__, falling back to __repr__
  • Defining __eq__ sets __hash__ to None unless you define it
  • Equal objects must have equal hashes
  • Return NotImplemented for types you don't handle
  • @dataclass(order=True) generates comparisons

A Comparable, Hashable Class

from functools import total_ordering
@total_ordering
class Version:
    def __init__(self, major, minor):
        self.major, self.minor = major, minor
    def _key(self): return (self.major, self.minor)
    def __repr__(self): return f"Version({self.major}, {self.minor})"
    def __str__(self): return f"v{self.major}.{self.minor}"
    def __eq__(self, other):
        if not isinstance(other, Version): return NotImplemented
        return self._key() == other._key()
    def __lt__(self, other): return self._key() < other._key()
    def __hash__(self): return hash(self._key())
v = Version(1, 2)
str(v), repr(v)                     # ('v1.2', 'Version(1, 2)')
v == Version(1, 2), v < Version(2, 0)   # (True, True)
v >= Version(1, 0)                  # True  (via total_ordering)
len({v, Version(1, 2)})             # 1  (equal + same hash)

Code Explained

__repr__ — unambiguous, for developers
__str__ — friendly, for users
NotImplemented — lets Python try the other operand
_key() — one tuple drives eq, lt, and hash

⚠ Common Mistakes

  • Defining __eq__ only — instances become unhashable
  • Hashing mutable fields — objects get lost inside sets
  • Returning False for foreign types — blocks the reflected comparison
  • __repr__ returning non-str — TypeError

✓ Tips & Best Practices

  • Make __repr__ look like the constructor call
  • Compare via a tuple key to keep methods consistent
  • Use @dataclass(frozen=True, order=True) for value objects
  • Define __str__ only if users need a friendlier form

Quick Summary

  • __repr__ / __str__ — display
  • __eq__ / __lt__ — comparisons
  • __hash__ — sets and dict keys
  • @total_ordering — fill the rest
