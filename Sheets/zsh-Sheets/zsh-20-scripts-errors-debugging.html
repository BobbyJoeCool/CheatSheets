Robust Scripts

A zsh script is a text file starting with #!/usr/bin/env zsh and marked executable. For safer scripts, turn on strict options so errors stop execution, clean up with trap or an always block (zsh's try/finally), and parse flags with the zparseopts builtin. When something goes wrong, XTRACE prints every command before it runs.

Notes

  • ERR_EXIT = set -e, NO_UNSET = set -u
  • ERR_RETURN returns from the function instead of exiting
  • Check syntax without running: zsh -n script.zsh
  • ${0:A:h} is the script's own directory

Script Skeleton

#!/usr/bin/env zsh
setopt NO_UNSET PIPE_FAIL               # strict mode

zparseopts -D -E -F -- h=help v=verbose o:=out || exit 1
(( $#help )) && { print "usage: ${0:t} [-v] [-o FILE] ARGS"; exit 0 }
outfile=${out[-1]:-out.txt}             # value after -o, or default

tmp=$(mktemp)
trap 'rm -f $tmp' EXIT                  # cleanup on any exit
TRAPINT() { print -u2 "interrupted"; return 130 }

main() {
  setopt LOCAL_OPTIONS ERR_RETURN       # stop at the first failure
  build_report > $tmp
  mv $tmp $outfile
}
{ main "$@" } always { print -u2 "done (status $?)" }

Code Explained

zparseopts -D — removes parsed flags from $@; -E allows unknown args; -F fails on bad flags
o:=out — -o takes a value; $out becomes (-o FILE)
trap … EXIT — runs when the script exits, for any reason
ERR_RETURN — makes main return at its first failing command
{ } always { } — like finally: runs after errors and returns, but not after exit

⚠ Common Mistakes

  • Relying on ERR_EXIT inside if, && or ||: failures there are ignored by design
  • Counting on always with ERR_EXIT or exit: the shell exits first. Use a trap … EXIT for cleanup that must run
  • Reading $out as the value: zparseopts stores (-o FILE). Use $out[-1]

✓ Tips & Best Practices

  • Use print -u2 for messages so stdout stays clean for data
  • Find a script's folder with ${0:A:h} to load files next to it
  • Exit with clear codes: exit 2 for usage errors, exit 1 for failures
