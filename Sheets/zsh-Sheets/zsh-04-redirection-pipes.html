Redirection & Pipes

> >> < · 2>&1 / &> · >| with noclobber · MULTIOS > a > b · <<EOF here-doc · <<< here-string · |&

Redirection

Every command has three standard streams: stdin (0), stdout (1) and stderr (2). Redirections point them at files, and pipes connect one command's stdout to the next command's stdin. Zsh adds MULTIOS: redirect one stream to several files at once (an implicit tee), or read several files in a row (an implicit cat). Redirections are processed left to right, so their order matters.

Notes

  • MULTIOS is on by default
  • NO_CLOBBER protects files from >; >| forces it
  • $pipestatus holds the exit code of every command in the last pipeline
  • < file with no command shows the file with $READNULLCMD (default more)

Redirection in Practice

ls > files.txt                # stdout to file (truncates)
ls >> files.txt               # append
sort < names.txt              # stdin from file
cmd 2> err.log                # stderr only
cmd > out.log 2>&1            # stdout + stderr (order matters)
cmd &> all.log                # same thing, shorter
cmd |& grep warn              # pipe stdout + stderr
setopt NO_CLOBBER
echo hi > old.txt             # zsh: file exists: old.txt
echo hi >| old.txt            # force overwrite
date > a.txt > b.txt          # MULTIOS: writes both files
cat < a.txt < b.txt           # MULTIOS: reads a then b
false | true; echo $pipestatus  # 1 0
cat <<EOF                     # here-doc: $vars expand
Home: $HOME
EOF
wc -w <<< "one two three"     # 3   (here-string)

Code Explained

2>&1 — "send 2 where 1 points *now*"; 2>&1 > file leaves stderr on the terminal
|& — shorthand for 2>&1 |
> a > b — MULTIOS copies output to both files, like tee
<<EOF — lines up to EOF become stdin; quote it (<<'EOF') to stop expansion
<<< — a single string as stdin, with a trailing newline

⚠ Common Mistakes

  • Writing cmd 2>&1 > file: stderr was copied before stdout moved, so errors still hit the screen
  • Running sort f > f: the shell truncates f before sort reads it. Write to a temp file
  • Using <<-EOF with spaces: only leading tabs are stripped
  • Checking $? after a pipe and missing an early failure: use $pipestatus or PIPE_FAIL

✓ Tips & Best Practices

  • Use &> for "everything to a file"; it reads better than > f 2>&1
  • Turn on NO_CLOBBER interactively to protect files from accidental >
  • Use MULTIOS (> log > /dev/tty) instead of tee for quick double output
  • Quote the here-doc delimiter ('EOF') when writing scripts or code that contain $

Quick Summary

  • > >> < — out, append, in
  • 2>&1 / &> — merge stderr
  • |& — pipe both streams
  • <<EOF / <<< — here-doc / here-string
  • $pipestatus — all pipeline exit codes
