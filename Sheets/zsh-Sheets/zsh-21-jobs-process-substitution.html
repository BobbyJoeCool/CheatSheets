Jobs & Substitution

Ending a command with & runs it as a background job. jobs, fg, bg and Ctrl-Z move jobs between the foreground, background and stopped states. Command substitution $(cmd) captures output as text, while process substitution turns a command's output into something that looks like a file: <(cmd) (a pipe path), >(cmd) (a pipe you write into) and zsh's =(cmd) (a real temp file).

Notes

  • Refer to jobs as %1, %+ (current), %- (previous), %vim (by name)
  • Zsh warns about running jobs on exit; exit again to confirm
  • =(cmd) works with programs that need to seek, like editors
  • $(<file) reads a file without running cat

Jobs & Substitution

sleep 60 &                    # [1] 4182
jobs -l                       # [1]  + 4182 running    sleep 60
fg %1                         # bring job 1 to the foreground
# press Ctrl-Z to stop it, then:
bg                            # continue it in the background
kill %1                       # stop job 1
server.sh &!                  # start already disowned (no job entry)
disown %2                     # stop tracking an existing job
wait                          # wait for all background jobs

today=$(date +%F)             # capture output as text
diff <(sort a.txt) <(sort b.txt)    # compare sorted output
vim =(curl -s example.com)    # open output as a temp file
tar cf >(gzip > site.tgz) site/     # write through a command
coproc bc -l                  # two-way pipe to bc
print -p "2^10"; read -p ans; echo $ans   # 1024

Code Explained

&! (or &|) — background and disown at once; survives closing the terminal
<(cmd) — gives a path like /proc/self/fd/11 to read from
=(cmd) — writes output to a temp file and passes its name; deleted afterwards
coproc — print -p writes to it and read -p reads from it

⚠ Common Mistakes

  • Closing the terminal with jobs running: they get killed. Use &! or disown
  • Using <(cmd) with a program that seeks or reopens the file: it fails. Use =(cmd)
  • Expecting $(cmd) to keep trailing newlines: they're stripped
  • Using backticks in new code: they're hard to nest. Use $( )

✓ Tips & Best Practices

  • Diff two command outputs with diff <(cmd1) <(cmd2)
  • Run tasks in parallel with &, then wait for all of them
  • Use %name to refer to jobs by command: fg %vim
  • Use kill -STOP %1 / kill -CONT %1 to pause and resume a background job

Quick Summary

  • & / fg / bg — job control
  • &! — start detached
  • $(cmd) — capture output
  • <(cmd) / =(cmd) — output as a file
  • wait — wait for jobs
