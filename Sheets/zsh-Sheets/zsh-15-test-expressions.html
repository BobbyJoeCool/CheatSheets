Test Expressions

[[ ]] vs [ ] · -f -d -e · -z / -n · == pattern match · =~ with $match / $MATCH · -nt / -ot · && / ||

Testing Conditions

[[ ... ]] is zsh's conditional expression. It checks files, compares strings, and matches patterns or regular expressions, then sets an exit status: 0 means true. Because [[ is a shell keyword, variables inside it are not split or globbed, so quoting is rarely needed. The right side of == is a pattern unless you quote it. For numbers, (( )) is usually clearer (Sheet 17).

Notes

  • [ ] / test is the old POSIX command: quote every variable and use =
  • In zsh, =~ treats a quoted right side as a regex too (unlike bash)
  • $MATCH = whole regex match, $match[n] = capture groups
  • setopt RE_MATCH_PCRE switches =~ to Perl-style regex

Common Tests

[[ -f notes.txt ]] && echo "is a file"
[[ -d ~/src ]] || mkdir ~/src
[[ -z $name ]] && echo "empty"          # zero length
[[ -n $name ]] && echo "has a value"
[[ $answer == y* ]] && echo yes         # pattern: y, yes, yep …
[[ $ver == <1-9>.* ]]                   # zsh numeric glob in a test

s="2024-ok"
if [[ $s =~ '^([0-9]+)-(.*)$' ]]; then
  echo $MATCH $match[1] $match[2]       # 2024-ok 2024 ok
fi

[[ a.txt -nt b.txt ]] && echo "a is newer"
[[ $n -gt 5 && $n -lt 10 ]]             # numeric compare
(( n > 5 && n < 10 ))                   # same, arithmetic form

Code Explained

&& / || — run the next command only on success / failure
== — glob pattern match; = works the same inside [[ ]]
=~ — extended regex; groups land in $match
-nt — newer than (modification time); -ot older than

⚠ Common Mistakes

  • Comparing numbers with < in [[ ]]: 10 < 9 is true as strings. Use -lt or (( ))
  • Quoting a pattern you meant to match: [[ $f == "*.txt" ]] only matches a literal *.txt
  • Leaving out the spaces: [[$x == y]] is a syntax error
  • Using [ $x = y ] with an empty $x: the test breaks. Use [[ ]]

✓ Tips & Best Practices

  • Prefer [[ ]] in zsh scripts; use [ ] only for strict POSIX sh
  • Use (( )) for numbers: (( count > 0 )) reads like math
  • Store complex regexes in a variable: re='^v([0-9]+)'; [[ $t =~ $re ]]
  • Test commands directly: if grep -q x file instead of [[ $(grep …) ]]

Quick Summary

  • [[ -f f ]] — file checks
  • [[ -z s ]] / -n — empty / not empty
  • [[ s == pat ]] — pattern match
  • [[ s =~ re ]] — regex, $match
  • (( a > b )) — numeric compare
