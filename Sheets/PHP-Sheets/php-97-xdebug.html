Sheet 97

Debugging with Xdebug

xdebug.mode · step debugging · breakpoints · IDE setup · profiling · trace mode

Real Debugging

Xdebug is a PHP extension for step debugging, profiling, tracing and code coverage. With xdebug.mode=debug it connects to your IDE (PhpStorm, VS Code) so you can set breakpoints, step through code and inspect variables — far faster than scattering var_dump(). Turn modes on only when needed: Xdebug slows PHP down significantly. PCOV is a lighter alternative for coverage only.

Notes

  • Xdebug 3 uses xdebug.mode (debug, develop, coverage, profile, trace)
  • Default client port is 9003
  • start_with_request=trigger debugs only when asked (cookie/env)
  • In Docker, set client_host=host.docker.internal
  • Never enable Xdebug in production

Configuration and Triggers

; php.ini / conf.d/xdebug.ini
zend_extension=xdebug
xdebug.mode=debug,develop
xdebug.start_with_request=trigger
xdebug.client_host=127.0.0.1
xdebug.client_port=9003
xdebug.output_dir=/tmp/xdebug

; Profiling instead (writes cachegrind files)
; xdebug.mode=profile

; ── Triggering a session ─────────────────────
; Browser: install "Xdebug helper" → sets XDEBUG_TRIGGER cookie
; URL:     https://app.test/?XDEBUG_TRIGGER=1
; CLI:     XDEBUG_TRIGGER=1 php artisan migrate
; CLI:     php -dxdebug.mode=debug -dxdebug.start_with_request=yes t.php

; Check it's loaded
; php -v            → "with Xdebug v3.x"
; php -r 'xdebug_info();'

Code Explained

zend_extension loads Xdebug
develop mode improves var_dump and error output
trigger avoids slowing every request
Profile output opens in KCachegrind / QCacheGrind
xdebug_info() shows the active configuration

⚠ Common Mistakes

  • Leaving xdebug.mode=debug + start_with_request=yes on always
  • Using port 9000 from Xdebug 2 docs
  • Missing path mappings for Docker or VMs

✓ Tips & Best Practices

  • Use trigger mode and a browser extension
  • Use conditional breakpoints in loops
  • Use PCOV in CI when you only need coverage

Quick Summary

  • xdebug.mode picks features
  • Port 9003
  • Trigger-based sessions
  • Never in production
