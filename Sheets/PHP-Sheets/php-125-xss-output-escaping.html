XSS & Output Escaping

htmlspecialchars() · ENT_QUOTES · context-aware escaping · urlencode() · JSON_HEX_TAG · Content-Security-Policy

Cross-Site Scripting

XSS happens when user-controlled text is output as HTML or JavaScript, letting an attacker run scripts in other users' browsers. The fix is escaping on output, for the right context: htmlspecialchars() for HTML text and attributes, rawurlencode() for URL parts, json_encode() with hex flags for data inside <script>. A Content-Security-Policy header is a strong second layer.

Notes

  • Escape at output time, not when saving input
  • Default flags (8.1+): ENT_QUOTES | ENT_SUBSTITUTE | ENT_HTML401
  • Always quote HTML attributes
  • javascript: URLs slip past HTML escaping — validate schemes
  • Template engines with auto-escaping prevent most XSS

Escape for Each Context

<?php
$name = $_GET['name'] ?? '';        // e.g. <script>alert(1)</script>
$e = fn(string $s) => htmlspecialchars($s,
    ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8');
?>
<!-- HTML text -->
<p>Hello, <?= $e($name) ?></p>

<!-- Quoted attribute -->
<input value="<?= $e($name) ?>">

<!-- URL parameter -->
<a href="/search?q=<?= rawurlencode($name) ?>">Search</a>

<!-- User-supplied link: allow-list the scheme -->
<?php $url = $_GET['site'] ?? '';
      $safe = preg_match('#^https?://#i', $url) ? $url : '#'; ?>
<a href="<?= $e($safe) ?>">Website</a>

<!-- Data for JavaScript -->
<script>
  const user = <?= json_encode(['name' => $name],
      JSON_HEX_TAG | JSON_HEX_AMP | JSON_HEX_APOS | JSON_HEX_QUOT) ?>;
</script>
<?php
header("Content-Security-Policy: default-src 'self'; script-src 'self'");

Code Explained

ENT_QUOTES escapes both quote types
Same escaper works for text and quoted attributes
URL parts need URL encoding
Block javascript: by allowing only http(s)
JSON hex flags make data safe inside <script>

⚠ Common Mistakes

  • Escaping on input and then outputting raw elsewhere
  • Unquoted attributes: <input value=<?= $v ?>>
  • Using strip_tags() as an XSS filter

✓ Tips & Best Practices

  • Escape every dynamic value in templates
  • Add a strict CSP
  • Use HTML Purifier if users may submit rich HTML

Quick Summary

  • Escape on output
  • Match the context
  • htmlspecialchars + ENT_QUOTES
  • CSP as backup
