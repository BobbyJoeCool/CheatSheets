Sheet 108

Memory, Weak References & Lazy Objects

refcounting · gc_collect_cycles() · WeakReference · WeakMap · lazy ghosts · lazy proxies (8.4)

How PHP Manages Memory

PHP frees values automatically using reference counting: when the last variable pointing to a value goes away, it's freed immediately. Objects that reference each other in a cycle are cleaned up by the cycle collector. WeakReference and WeakMap hold objects without keeping them alive — ideal for caches. PHP 8.4's lazy objects create placeholders that initialise only when first used.

Notes

  • Memory resets after each web request (share-nothing)
  • Long-running workers must avoid growing arrays and static caches
  • unset() drops a reference, not necessarily the value
  • memory_limit caps per-request memory
  • Lazy objects are mostly for frameworks (ORMs, DI containers)

Weak Maps and Lazy Objects

<?php
$before = memory_get_usage();
$big = range(1, 1_000_000);
echo memory_get_usage() - $before;     // ~ 16 MB
unset($big);                           // freed immediately

$a = new stdClass(); $b = new stdClass();
$a->other = $b; $b->other = $a;        // cycle
unset($a, $b);
gc_collect_cycles();                   // cycle collector

$cache = new WeakMap();
$user = new User(7);
$cache[$user] = expensiveReport($user);
unset($user);                          // entry vanishes too
count($cache);                         // 0

$ref = WeakReference::create($obj);
$ref->get();                           // object or null

// PHP 8.4: lazy ghost — constructor runs on first access
$rc = new ReflectionClass(Report::class);
$report = $rc->newLazyGhost(function (Report $r) {
    $r->__construct(loadRows());       // expensive work deferred
});
echo $report->title;                   // initialises now

Code Explained

Measure with memory_get_usage() before and after
Refcount 0 → freed at once
Cycles need the collector
WeakMap entries disappear with their key object
Lazy ghost runs its initializer on first property access

⚠ Common Mistakes

  • Unbounded static caches in queue workers
  • Assuming unset() frees memory held elsewhere
  • Loading full result sets instead of streaming

✓ Tips & Best Practices

  • Use generators for big datasets
  • Use WeakMap for per-object caches
  • Restart long-running workers periodically

Quick Summary

  • Refcounting + cycle collector
  • Weak references don't keep objects alive
  • Lazy objects (8.4)
  • Watch memory in long-running processes
