PDO — Transactions & Errors

beginTransaction() · commit() · rollBack() · inTransaction() · PDOException · errorInfo

All or Nothing

A transaction groups several statements so they all succeed or none do. Call beginTransaction(), run your queries, then commit(); if anything throws, rollBack() undoes the changes. With ERRMODE_EXCEPTION, failures raise PDOException, whose errorInfo holds the SQLSTATE and driver codes — useful for handling duplicates or deadlocks specifically. Transactions also speed up bulk inserts.

Notes

  • MySQL DDL statements (CREATE, ALTER) commit implicitly
  • Only transactional engines (InnoDB) can roll back
  • Nested beginTransaction() throws — use savepoints
  • Keep transactions short to avoid lock contention
  • Retry on deadlock (SQLSTATE 40001)

Transfer Money Safely

<?php
function transfer(PDO $pdo, int $from, int $to, int $cents): void
{
    $pdo->beginTransaction();
    try {
        $debit = $pdo->prepare(
            'UPDATE accounts SET balance = balance - ?
             WHERE id = ? AND balance >= ?');
        $debit->execute([$cents, $from, $cents]);
        if ($debit->rowCount() !== 1) {
            throw new DomainException('Insufficient funds');
        }
        $pdo->prepare('UPDATE accounts
             SET balance = balance + ? WHERE id = ?')
            ->execute([$cents, $to]);
        $pdo->commit();
    } catch (Throwable $e) {
        if ($pdo->inTransaction()) $pdo->rollBack();
        throw $e;
    }
}

try {
    $pdo->prepare('INSERT INTO users (email) VALUES (?)')
        ->execute([$email]);
} catch (PDOException $e) {
    if ($e->errorInfo[1] === 1062) {          // MySQL duplicate key
        echo 'Email already registered';
    } else {
        throw $e;
    }
}

Code Explained

Start the transaction before the first write
Conditional UPDATE guards the balance atomically
rowCount() confirms the debit happened
Any exception → roll back, then rethrow
errorInfo[1] is the driver error code

⚠ Common Mistakes

  • Forgetting rollBack() on failure — connection stays in a transaction
  • Long transactions that wait on HTTP calls
  • Assuming MyISAM tables roll back

✓ Tips & Best Practices

  • Wrap multi-step writes in a helper like transactional(fn)
  • Use conditional updates to avoid race conditions
  • Handle unique-key violations instead of pre-checking

Quick Summary

  • begin → commit / rollBack
  • Exceptions trigger rollback
  • errorInfo codes
  • Short transactions
