Building an API Endpoint

A router maps an HTTP method and path to a handler. In plain PHP you read REQUEST_METHOD and the path from REQUEST_URI, match it against patterns, decode a JSON body from php://input, and send a JSON response with the right status code. Real projects use a router library or framework built on PSR-7 (HTTP message objects) and PSR-15 (middleware and request handlers).

Notes

  • Return 405 with an Allow header for wrong methods
  • Return 404 JSON for unknown routes
  • Validate JSON input like form input
  • Middleware handles auth, CORS, logging
  • Libraries: FastRoute, Slim, Laravel, Symfony

A Minimal Router

<?php
$method = $_SERVER['REQUEST_METHOD'];
$path   = parse_url($_SERVER['REQUEST_URI'], PHP_URL_PATH);
$path   = rtrim($path, '/') ?: '/';

$routes = [
    ['GET',  '#^/api/users$#',           fn() => listUsers()],
    ['GET',  '#^/api/users/(\d+)$#',     fn($id) => showUser((int) $id)],
    ['POST', '#^/api/users$#',           fn() => createUser(readJson())],
];

function readJson(): array {
    try {
        return json_decode(file_get_contents('php://input'), true,
            flags: JSON_THROW_ON_ERROR) ?? [];
    } catch (JsonException) {
        sendJson(['error' => 'Invalid JSON'], 400);
    }
}

function sendJson(mixed $body, int $status = 200): never {
    http_response_code($status);
    header('Content-Type: application/json');
    echo json_encode($body);
    exit;
}

foreach ($routes as [$verb, $pattern, $handler]) {
    if (preg_match($pattern, $path, $m) && $verb === $method) {
        sendJson($handler(...array_slice($m, 1)));
    }
}
sendJson(['error' => 'Not found'], 404);

Code Explained

Normalise the path (no trailing slash)
Each route: method, regex, handler
Capture groups become handler arguments
Bad JSON → 400 response
Unmatched → 404 JSON

⚠ Common Mistakes

  • Returning 200 with an error message in the body
  • Matching routes without anchors (^…$)
  • No validation on JSON input

✓ Tips & Best Practices

  • Use a router library (FastRoute) or framework
  • Keep handlers thin; put logic in services
  • Document the API (OpenAPI)

Quick Summary

  • Method + path → handler
  • JSON in via php://input
  • JSON out + status code
