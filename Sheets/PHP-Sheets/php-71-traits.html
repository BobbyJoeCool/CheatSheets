Traits

trait · use · insteadof · as alias · abstract & static in traits · trait constants (8.2)

Reusing Code Without Inheritance

A trait is a bundle of methods and properties copied into a class with use TraitName;. Traits solve the single-inheritance limit for code reuse: any number of unrelated classes can share them. When two traits define the same method, resolve the conflict with insteadof, and rename or change visibility with as. Traits can declare abstract methods to require something from the using class.

Notes

  • Class methods override trait methods; trait methods override inherited ones
  • Traits can't be instantiated or used as types
  • Traits can have static members and (8.2+) constants
  • self inside a trait refers to the using class
  • Prefer composition when the shared code needs its own state or dependencies

Using and Combining Traits

<?php
trait HasTimestamps
{
    public ?DateTimeImmutable $createdAt = null;

    public function touch(): void
    {
        $this->createdAt = new DateTimeImmutable();
    }
}

trait SoftDeletes
{
    public bool $deleted = false;
    public function delete(): void { $this->deleted = true; }
    abstract public function id(): int;      // requirement
}

trait Loggable   { public function log($m) { echo $m; } }
trait Debuggable { public function log($m) { var_dump($m); } }

class Post
{
    use HasTimestamps, SoftDeletes;
    use Loggable, Debuggable {
        Loggable::log insteadof Debuggable;  // pick one
        Debuggable::log as protected dump;   // keep other, renamed
    }

    public function id(): int { return 1; }
}

$p = new Post();
$p->touch();
$p->log('saved');

⚠ Common Mistakes

  • Using traits as a dumping ground for unrelated helpers
  • Hidden dependencies — trait assumes properties the class may not have
  • Trying to type-hint a trait

✓ Tips & Best Practices

  • Declare requirements with abstract methods
  • Pair a trait with an interface: interface for type, trait for default code
  • Keep traits small and focused
