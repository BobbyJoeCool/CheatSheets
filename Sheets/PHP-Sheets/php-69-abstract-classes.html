Abstract Classes

abstract class · abstract method · partial implementation · template method · abstract vs interface

Incomplete Base Classes

An abstract class can't be instantiated; it exists to be extended. It may contain normal methods and properties plus abstract methods — signatures without bodies that every concrete child must implement. This makes abstract classes ideal for the template method pattern: the base class defines the algorithm and children fill in specific steps.

Notes

  • Any class with an abstract method must be declared abstract
  • Children must implement abstract methods with compatible signatures
  • Abstract classes can have constructors and state
  • A class can extend only one abstract class
  • Abstract methods can be protected

Template Method Pattern

<?php
abstract class Report
{
    public function __construct(protected array $rows) {}

    // Template method: fixed algorithm
    public function render(): string
    {
        return $this->header() . $this->body() . $this->footer();
    }

    abstract protected function header(): string;
    abstract protected function body(): string;

    protected function footer(): string      // default step
    {
        return "Rows: " . count($this->rows) . "\n";
    }
}

final class CsvReport extends Report
{
    protected function header(): string { return "id,name\n"; }

    protected function body(): string
    {
        return implode('', array_map(
            fn($r) => "{$r['id']},{$r['name']}\n", $this->rows));
    }
}

echo (new CsvReport([['id' => 1, 'name' => 'Ana']]))->render();
// new Report([]);   // Error: Cannot instantiate abstract class

Code Explained

render() defines the order of steps
Abstract steps have no body
footer() is a default that children may override
Concrete child implements every abstract method
Instantiating the abstract base is an Error

⚠ Common Mistakes

  • Making a class abstract with no abstract members and no reason
  • Putting too much logic in the base class
  • Using abstract classes where an interface is enough

✓ Tips & Best Practices

  • Pair an interface with an optional abstract base
  • Keep template methods final if steps must not change
  • Name bases clearly: AbstractReport or Report

Quick Summary

  • Can't instantiate
  • Abstract methods = required steps
  • Can hold code and state
  • Template method pattern
