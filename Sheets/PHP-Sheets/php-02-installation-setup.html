Getting PHP

Install PHP from your OS package manager, a bundle such as XAMPP or Laragon, or run it in Docker. The CLI binary (php) is all you need to run scripts and the built-in server. Behaviour is controlled by php.ini; each SAPI (CLI, FPM, Apache) can load a different ini file. Features such as pdo_mysql, mbstring and intl come from extensions that must be installed and enabled.

Notes

  • php -v shows version; php -m lists loaded extensions
  • php --ini shows which ini files were loaded
  • Extra ini snippets live in a conf.d/ folder
  • Ship php.ini-development locally, php.ini-production on servers
  • Restart FPM / Apache after editing ini files

Install & Inspect

# macOS (Homebrew)
brew install php

# Debian / Ubuntu
sudo apt install php-cli php-mbstring php-xml php-pdo

# Windows: winget install PHP.PHP.8.4  (or XAMPP)

php -v                  # version + Zend Engine
php -m                  # loaded extensions
php --ini               # loaded php.ini path(s)
php -i | grep memory    # one ini setting (CLI)
php -r 'echo ini_get("memory_limit");'

# Docker: run a script with no local install
docker run --rm -v "$PWD":/app -w /app \
  php:8.4-cli php script.php

Code Explained

Package names vary by distro (php8.4-cli on some)
-m — confirm an extension such as pdo_mysql is enabled
--ini — the first thing to check when a setting won't apply
-r — run inline code without <?php tags
php:8.4-cli — official image; use -fpm / -apache for servers

⚠ Common Mistakes

  • Editing the wrong php.ini — CLI and FPM often use different files
  • Forgetting to restart FPM after an ini change
  • Leaving display_errors=On in production

✓ Tips & Best Practices

  • Run php --ini before editing any configuration
  • Put custom settings in a small conf.d/99-local.ini file
  • Use the same major.minor version locally and in production

Quick Summary

  • php -v / -m / --ini to inspect
  • php.ini controls behaviour per SAPI
  • Extensions add features
  • Docker gives exact versions
