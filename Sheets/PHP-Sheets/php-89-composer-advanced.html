Composer — Scripts & Publishing

scripts · autoload-dev · Packagist · repositories · platform requirements · composer audit · bump

Beyond Installing

Composer is also a task runner and publishing tool. Scripts in composer.json define shortcuts such as composer test. Repositories add sources beyond Packagist — a private VCS repo or a local path for developing packages side by side. composer audit checks installed packages against security advisories, and config.platform pins the PHP version used for dependency resolution.

Notes

  • Scripts can call other scripts with @name
  • composer run-script --list shows available scripts
  • Publish a library by tagging a release and submitting the repo to Packagist
  • Libraries commit composer.json but usually not the lock file
  • composer bump raises constraints to installed versions

composer.json with Scripts and Repositories

{
    "name": "acme/shop",
    "type": "project",
    "require": {
        "php": "^8.3",
        "acme/payments": "^2.0"
    },
    "repositories": [
        { "type": "vcs",  "url": "git@github.com:acme/payments.git" },
        { "type": "path", "url": "../packages/*" }
    ],
    "scripts": {
        "test": "pest --parallel",
        "lint": "php-cs-fixer fix --dry-run",
        "stan": "phpstan analyse",
        "check": ["@lint", "@stan", "@test"]
    },
    "config": {
        "platform": { "php": "8.3.0" },
        "sort-packages": true
    },
    "minimum-stability": "stable"
}

Code Explained

vcs repository — private Git package
path repository — symlinks local packages
Scripts become composer test, composer check
@name chains scripts
platform.php resolves deps for production's PHP version

⚠ Common Mistakes

  • Leaving minimum-stability: dev without prefer-stable
  • Ignoring composer audit warnings
  • Resolving dependencies with a newer local PHP than production

✓ Tips & Best Practices

  • Add composer audit to CI
  • Set config.platform.php to production's version
  • Use path repos for monorepo packages
