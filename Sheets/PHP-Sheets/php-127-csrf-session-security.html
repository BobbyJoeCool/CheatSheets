CSRF & Session Security

CSRF tokens · random_bytes() · hash_equals() · SameSite · session fixation · session.cookie_secure

Requests the User Didn't Mean to Send

Cross-Site Request Forgery tricks a logged-in user's browser into submitting a request to your site from another site — the browser attaches the session cookie automatically. Defend every state-changing request with a CSRF token: a random secret stored in the session, embedded in forms, and compared with hash_equals() on submit. SameSite cookies add a strong second layer. Protect the session itself against fixation and hijacking.

Notes

  • Only POST/PUT/PATCH/DELETE should change state
  • One token per session is fine; per-form tokens are stricter
  • Send the token in a header for AJAX (X-CSRF-Token)
  • Regenerate the session ID at login and privilege changes
  • Frameworks include CSRF middleware — use it

Token Generation and Checking

<?php
session_start();

function csrfToken(): string
{
    return $_SESSION['csrf'] ??= bin2hex(random_bytes(32));
}

function checkCsrf(): void
{
    $sent = $_POST['_token'] ?? $_SERVER['HTTP_X_CSRF_TOKEN'] ?? '';
    $ok = is_string($sent)
        && hash_equals($_SESSION['csrf'] ?? '', $sent);
    if (!$ok) {
        http_response_code(403);
        exit('Invalid CSRF token');
    }
}

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    checkCsrf();
    // … perform the change …
}
?>
<form method="post" action="/account/delete">
  <input type="hidden" name="_token"
         value="<?= htmlspecialchars(csrfToken()) ?>">
  <button>Delete account</button>
</form>
<meta name="csrf-token" content="<?= htmlspecialchars(csrfToken()) ?>">

Code Explained

??= creates the token once per session
random_bytes(32) = unpredictable secret
Accept the token from a form field or header
hash_equals compares in constant time
Meta tag lets JavaScript send the header

⚠ Common Mistakes

  • Comparing tokens with == / === — use hash_equals()
  • Changing data on GET requests
  • Generating tokens with uniqid() or rand()

✓ Tips & Best Practices

  • Use your framework's CSRF protection
  • Set SameSite=Lax on the session cookie
  • Regenerate the session ID on login and logout
