Fibers & Async PHP

Fiber · start() · suspend() · resume() · event loops · Revolt · ReactPHP · AMPHP

Cooperative Concurrency (8.1)

A Fiber is a block of code with its own call stack that can pause (Fiber::suspend()) and resume later, exchanging values each way. Fibers don't run in parallel — they let an event loop switch tasks while one waits on I/O. Application code rarely uses fibers directly; libraries such as Revolt (the shared loop), AMPHP and ReactPHP build async HTTP clients, servers and database drivers on top of them without async/await keywords.

Notes

  • Fibers are single-threaded; CPU-bound work still blocks
  • Suspending is invisible to callers — no function colouring
  • Blocking functions (sleep, PDO) block the whole loop
  • Use async-aware libraries for sockets, HTTP, DB
  • For real parallelism: processes, queues, or ext-parallel

Fiber Basics and an Async Library

<?php
$fiber = new Fiber(function (string $start): string {
    echo "got $start\n";
    $x = Fiber::suspend('paused-1');     // pause, send value out
    echo "resumed with $x\n";
    $y = Fiber::suspend('paused-2');
    return "done $y";
});

$out = $fiber->start('go');              // got go
echo $out, "\n";                         // paused-1
$out = $fiber->resume('A');              // resumed with A
echo $out, "\n";                         // paused-2
$fiber->resume('B');
echo $fiber->getReturn();                // done B

// AMPHP: concurrent HTTP requests
use Amp\Future;
use Amp\Http\Client\HttpClientBuilder;
use function Amp\async;

$client = HttpClientBuilder::buildDefault();
$fetch = fn(string $url) => $client
    ->request(new Amp\Http\Client\Request($url))
    ->getBody()->buffer();
$futures = array_map(fn($u) => async($fetch, $u), $urls);
$bodies = Future\await($futures);       // all run concurrently

Code Explained

start() runs until the first suspend()
suspend() returns the value passed to resume()
Values flow out through suspend() and back via resume()
getReturn() reads the final value
AMPHP's async() + await() hide the fiber plumbing

⚠ Common Mistakes

  • Expecting fibers to speed up CPU-bound code
  • Calling blocking functions inside an async loop
  • Building your own scheduler instead of using Revolt

✓ Tips & Best Practices

  • Use AMPHP or ReactPHP rather than raw fibers
  • Offload heavy work to queues
  • Use curl_multi or async clients for many HTTP calls

Quick Summary

  • Fibers pause and resume
  • Single-threaded, cooperative
  • Libraries provide the loop
  • Not for CPU-bound work
