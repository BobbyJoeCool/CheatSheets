Sheet 107

Performance, OPcache & JIT

OPcache · opcache.validate_timestamps · preloading · JIT · realpath cache · memory_get_usage() · profiling

Making PHP Fast

OPcache stores compiled bytecode in shared memory so scripts aren't re-parsed on every request — it's the single biggest win and should always be on in production. Turn off timestamp checks there and clear the cache on deploy. Preloading loads framework classes into memory at server start. The JIT compiles hot code to machine code; it helps CPU-heavy work far more than typical I/O-bound web apps. Measure with a profiler before optimising.

Notes

  • OPcache is bundled; enable it with opcache.enable=1
  • opcache_reset() or an FPM reload clears it after deploys
  • JIT is off by default; enable with opcache.jit + buffer size
  • Composer's optimised autoloader also matters (Sheet 87)
  • Most web latency is database and network, not PHP

Production php.ini Settings

; OPcache
opcache.enable=1
opcache.enable_cli=0
opcache.memory_consumption=256
opcache.interned_strings_buffer=16
opcache.max_accelerated_files=20000
opcache.validate_timestamps=0     ; reload FPM on deploy
opcache.preload=/app/config/preload.php
opcache.preload_user=www-data

; JIT (helps CPU-bound code)
opcache.jit=tracing
opcache.jit_buffer_size=64M

; Filesystem caching
realpath_cache_size=4096K
realpath_cache_ttl=600

; Check at runtime:
;   php -r 'var_dump(opcache_get_status()["opcache_enabled"]);'
;   memory_get_peak_usage(true), hrtime(true) for timing
;   Profilers: Xdebug profile, Blackfire, Tideways, SPX

Code Explained

Enough memory and file slots for the whole codebase
validate_timestamps=0 skips file checks — reload on deploy
Preload script opcache_compile_file()s hot classes
tracing JIT mode suits most workloads
Bigger realpath cache cuts filesystem lookups

⚠ Common Mistakes

  • Running production without OPcache
  • validate_timestamps=0 but no cache reset on deploy — old code runs
  • Micro-optimising PHP while queries dominate

✓ Tips & Best Practices

  • Profile first, then optimise the hot path
  • Keep PHP up to date — each release is faster
  • Cache at the right layer (HTTP, app, DB)

Quick Summary

  • OPcache always on
  • Reset on deploy
  • Preload + JIT for extra speed
  • Measure before optimising
