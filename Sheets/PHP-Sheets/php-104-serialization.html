Serialization

serialize() · unserialize() · allowed_classes · object injection risk · var_export() · igbinary

Turning Values into Strings

serialize() converts almost any PHP value — including objects — into a string, and unserialize() rebuilds it. It's used for caches and sessions. The danger: unserialize() on untrusted input can instantiate arbitrary classes and trigger their magic methods (PHP object injection). For data that crosses trust boundaries, use JSON. If you must unserialize, restrict classes with allowed_classes.

Notes

  • Closures and most resources can't be serialized
  • Objects control their format with __serialize() (Sheet 74)
  • Serialized data is PHP-specific and version-sensitive
  • igbinary is a faster, smaller binary serializer extension
  • Sign data (HMAC) if it must round-trip through a client

serialize, unserialize & Safer Options

<?php
$data = ['id' => 7, 'tags' => ['a', 'b'], 'ok' => true];
$s = serialize($data);
// a:3:{s:2:"id";i:7;s:4:"tags";a:2:{i:0;s:1:"a";i:1;s:1:"b";}s:2:"ok";b:1;}
$back = unserialize($s);                     // same array

// Untrusted input: never allow objects
$value = unserialize($cookie, ['allowed_classes' => false]);

// Or allow-list specific classes
$cart = unserialize($cached, ['allowed_classes' => [Cart::class]]);

// Prefer JSON across trust boundaries
$json = json_encode($data, JSON_THROW_ON_ERROR);
$data = json_decode($json, true, flags: JSON_THROW_ON_ERROR);

// Integrity check when data leaves the server
$payload = base64_encode($s);
$sig = hash_hmac('sha256', $payload, $secretKey);
if (!hash_equals($sig, $_COOKIE['sig'] ?? '')) {
    throw new RuntimeException('Tampered');
}

var_export($data);       // PHP source code form

Code Explained

The format records type and length of each value
allowed_classes => false turns objects into __PHP_Incomplete_Class
An allow-list limits which classes can be created
JSON can't create objects — safe by design
HMAC + hash_equals detects tampering

⚠ Common Mistakes

  • unserialize($_COOKIE[...]) — object injection vulnerability
  • Serializing objects whose class may later be renamed
  • Using serialize() for data shared with JavaScript

✓ Tips & Best Practices

  • Use JSON by default
  • Pass allowed_classes every time
  • Sign anything that round-trips through users

Quick Summary

  • serialize / unserialize
  • Never unserialize untrusted data
  • allowed_classes
  • Prefer JSON
