Sheet 06

Dumping & Inspecting Values

print_r() · var_dump() · var_export() · debug_print_backtrace() · error_log() · json_encode()

Seeing Inside Variables

echo can't show arrays or objects. For debugging, print_r() prints a readable structure, var_dump() adds types and lengths, and var_export() prints valid PHP code you can paste back. Pass true as the second argument to print_r() or var_export() to get a string instead of output. For production, write to the log with error_log() rather than the page.

Notes

  • var_dump() is the only one that shows bool and null clearly
  • Wrap dumps in <pre> in a browser to keep indentation
  • With Xdebug, var_dump() output is formatted and limited
  • json_encode($x, JSON_PRETTY_PRINT) is handy for APIs
  • Symfony's dump() / Laravel's dd() are library helpers

Comparing the Dumpers

<?php
$user = ['id' => 7, 'admin' => false, 'tags' => null];

print_r($user);
// Array ( [id] => 7 [admin] => [tags] => )

var_dump($user);
// array(3) { ["id"]=> int(7)
//   ["admin"]=> bool(false) ["tags"]=> NULL }

var_export($user);
// array ( 'id' => 7, 'admin' => false,
//   'tags' => NULL, )

$s = print_r($user, true);       // as a string
error_log('user: ' . $s);        // to the error log

echo '<pre>'; var_dump($user); echo '</pre>';

Code Explained

print_r hides false and null — both print as empty
var_dump shows the type of every element
var_export output is executable PHP
true second arg returns the text
error_log() writes to the server log, not the page

⚠ Common Mistakes

  • Reading print_r output as "empty" when the value was false
  • Leaving var_dump() calls in committed code
  • Dumping secrets (passwords, tokens) into logs

✓ Tips & Best Practices

  • Use var_dump() when types matter
  • Use Xdebug step debugging instead of scattering dumps
  • Search for var_dump( before every commit

Quick Summary

  • var_dump — types
  • var_export — PHP code
