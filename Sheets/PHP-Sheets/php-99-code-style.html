Code Style & Refactoring Tools

PER Coding Style · PSR-12 · PHP-CS-Fixer · PHP_CodeSniffer · Rector · php -l

Consistent, Modern Code

PER Coding Style (the successor to PSR-12) defines the community formatting standard: 4-space indents, braces on their own line for classes and methods, one class per file. PHP-CS-Fixer and PHP_CodeSniffer (phpcs / phpcbf) check and fix style automatically. Rector goes further and rewrites code — upgrading syntax to newer PHP versions or applying refactorings across a project.

Notes

  • Run fixers in a pre-commit hook or CI
  • --dry-run --diff previews changes
  • Laravel Pint is a PHP-CS-Fixer preset
  • Rector sets: UP_TO_PHP_84, dead code, code quality
  • php -l checks syntax only

Configs and Commands

<?php
// .php-cs-fixer.dist.php
$finder = PhpCsFixer\Finder::create()
    ->in([__DIR__ . '/src', __DIR__ . '/tests']);

return (new PhpCsFixer\Config())
    ->setRiskyAllowed(true)
    ->setRules([
        '@PER-CS' => true,
        '@PHP84Migration' => true,
        'declare_strict_types' => true,
        'ordered_imports' => true,
        'no_unused_imports' => true,
    ])
    ->setFinder($finder);

// rector.php
use Rector\Config\RectorConfig;
return RectorConfig::configure()
    ->withPaths([__DIR__ . '/src'])
    ->withPhpSets(php84: true)
    ->withPreparedSets(deadCode: true, codeQuality: true);

// vendor/bin/php-cs-fixer fix --dry-run --diff
// vendor/bin/phpcs --standard=PSR12 src
// vendor/bin/rector process --dry-run

Code Explained

Finder selects which folders to fix
@PER-CS rule set = community standard
Risky rules (like strict types) need opting in
Rector upgrades syntax to the target PHP version
Always preview with dry-run first

⚠ Common Mistakes

  • Mixing style fixes with logic changes in one commit
  • Running Rector without tests to catch regressions
  • Arguing style in code review instead of automating it

✓ Tips & Best Practices

  • Automate formatting in CI
  • Run Rector with a clean git tree
  • Commit tool configs to the repo

Quick Summary
