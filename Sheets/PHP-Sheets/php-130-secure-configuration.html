Sheet 130

Secure Configuration & File Safety

display_errors=Off · expose_php · open_basedir · disable_functions · allow_url_include · LFI/RFI · upload directories

Hardening the Environment

Many PHP breaches come from configuration, not code. In production, hide errors from visitors, stop advertising the PHP version, block remote file inclusion and keep secrets out of the web root. File inclusion bugs (LFI/RFI) let attackers run or read files when paths come from user input — never build include paths from requests. Keep PHP and dependencies patched and run composer audit.

Notes

  • Only public/ should be web-accessible
  • Uploaded files must never be executable as PHP
  • open_basedir limits which paths PHP can open
  • disable_functions can block shell functions you don't use
  • Use HTTPS everywhere with HSTS

Production php.ini Hardening

; Errors: log, don't display
display_errors = Off
display_startup_errors = Off
log_errors = On
error_log = /var/log/php/error.log
error_reporting = E_ALL

; Don't advertise
expose_php = Off

; Remote code / file access
allow_url_include = Off
allow_url_fopen = Off          ; if you use an HTTP client instead

; Limit the blast radius
open_basedir = /var/www/app:/tmp
disable_functions = exec,passthru,shell_exec,system,proc_open,popen

; Sessions
session.use_strict_mode = 1
session.cookie_secure = 1
session.cookie_httponly = 1
session.cookie_samesite = Lax

; Uploads
file_uploads = On
upload_max_filesize = 10M
post_max_size = 12M

Code Explained

Visitors see a generic page; details go to the log
expose_php=Off removes the X-Powered-By version header
No remote include, ever
open_basedir jails file access to app paths
Disable shell functions if the app doesn't need them

⚠ Common Mistakes

  • display_errors=On in production
  • Project root as document root — .env downloadable
  • Including files chosen by request parameters

✓ Tips & Best Practices

  • Start from php.ini-production
  • Serve uploads through a controller, from outside the web root
  • Patch PHP and run composer audit regularly

Quick Summary

  • Log errors, don't display
  • No remote include
  • public/ is the only web root
  • Patch and audit
