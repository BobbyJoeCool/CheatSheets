SQL Injection

prepared statements · never interpolate · identifier allow-lists · LIKE wildcards · IN() lists · least privilege

Keeping Input Out of Your SQL

SQL injection happens when user input is pasted into a query string, letting an attacker change the query — reading other users' data, bypassing logins or deleting tables. The fix is simple and absolute: pass every value through prepared-statement placeholders. Placeholders can't hold identifiers, so column names, sort directions and table names must come from an allow-list in your code.

Notes

  • Escaping functions are not a substitute for placeholders
  • Second-order injection: data from your DB is still untrusted
  • ORMs and builders are safe until you use their raw-SQL methods
  • Give the app's DB user only the privileges it needs
  • Log and alert on SQL syntax errors — they can signal probing

Vulnerable vs Safe

<?php
// ❌ Vulnerable: input becomes SQL
$id = $_GET['id'];                       // "1 OR 1=1"
$pdo->query("SELECT * FROM users WHERE id = $id");

// ✅ Safe: value travels separately
$stmt = $pdo->prepare('SELECT * FROM users WHERE id = ?');
$stmt->execute([$_GET['id']]);

// ✅ Identifiers: allow-list, never bind or interpolate input
$columns = ['name' => 'name', 'date' => 'created_at'];
$col = $columns[$_GET['sort'] ?? ''] ?? 'name';
$dir = strtoupper($_GET['dir'] ?? '') === 'DESC' ? 'DESC' : 'ASC';
$stmt = $pdo->prepare("SELECT * FROM posts ORDER BY $col $dir LIMIT ?");
$stmt->bindValue(1, 20, PDO::PARAM_INT);
$stmt->execute();

// ✅ LIKE: bind the pattern, escape wildcards in the term
$term = str_replace(['!', '%', '_'], ['!!', '!%', '!_'], $_GET['q'] ?? '');
$stmt = $pdo->prepare("SELECT * FROM posts WHERE title LIKE ? ESCAPE '!'");
$stmt->execute(["%$term%"]);

// ✅ IN list: one placeholder per value
$ids = array_map('intval', (array) ($_GET['ids'] ?? []));
$in  = implode(',', array_fill(0, max(1, count($ids)), '?'));
$stmt = $pdo->prepare("SELECT * FROM tags WHERE id IN ($in)");
$stmt->execute($ids ?: [0]);

Code Explained

Interpolated input can rewrite the WHERE clause
Placeholders keep data and code separate
Map user choices to known column names
Escape % and _ so users can't widen LIKE searches
Generate placeholders for variable-length lists

⚠ Common Mistakes

  • "Sanitising" input instead of using placeholders
  • Binding the sort column as a value — it sorts by a constant
  • Trusting values because they came from your own database

✓ Tips & Best Practices

  • Grep for query(" and ->query($ in reviews
  • Use static analysis rules that flag string-built SQL
  • Run the app with a restricted DB account

Quick Summary

  • Placeholders for every value
  • Allow-list identifiers
  • Escape LIKE wildcards
  • Least privilege as backup
