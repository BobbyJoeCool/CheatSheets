Program Structure & PHP Tags

<?php · <?= · omitting ?> · semicolons · declare(strict_types=1) · mixing HTML

Anatomy of a PHP File

The parser only runs code between PHP tags. Everything outside <?php ... ?> is sent to the output unchanged, which is how PHP mixes with HTML. Statements end with a semicolon; blocks use braces. Files that contain only PHP should omit the closing tag (?>) so stray whitespace can't leak into the response. declare(strict_types=1); must be the very first statement to take effect.

Notes

  • <?= is short for <?php echo and is always enabled
  • Short open tag <? depends on ini — don't use it
  • The last statement before ?> doesn't need a semicolon
  • Whitespace and newlines are not significant (unlike Python)
  • Case-insensitive: keywords, function and class names; case-sensitive: variables

A Typical Script File

<?php
declare(strict_types=1);          // must be first

namespace App;                    // optional

use App\Models\User;             // imports

require __DIR__ . '/vendor/autoload.php';

function greet(string $name): string
{
    return "Hello, {$name}!";
}

echo greet('Ana'), PHP_EOL;
// no closing ?> in pure-PHP files

Code Explained

declare(strict_types=1) — scalar types are not coerced in calls made from this file
namespace must come before any other code except declare
use imports a class name into this file
__DIR__ — folder of the current file; keeps paths stable
Omitting ?> avoids "headers already sent" bugs

Tag Forms

Template Mixing

CodeOutput

<?php if ($ok): ?>Start a block
<p>Yes</p>Sent only if $ok
<?php endif; ?>End the block

Case Rules

ItemCase-Sensitive?
$variablesYes
constantsYes
functionsNo (STRLEN() works)
classes / methodsNo
keywordsNo (IF, ECHO)

⚠ Common Mistakes

  • Whitespace before <?php or after ?> — breaks header() and sessions
  • Putting declare(strict_types=1) after other code — fatal error
  • Relative require 'x.php' paths — they resolve from the working directory

✓ Tips & Best Practices

  • One class per file, no closing tag
  • Start every file with declare(strict_types=1);
  • Use <?= and alternative syntax in templates

Quick Summary

  • Code lives between <?php and ?>
  • Outside tags = raw output
  • Omit ?> in PHP-only files
  • strict_types goes first
