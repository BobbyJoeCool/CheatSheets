Static Analysis — PHPStan & Psalm

PHPStan levels · phpstan.neon · baseline · Psalm · @template generics · @phpstan-ignore

Finding Bugs Without Running Code

Static analysers read your code and report type errors, impossible conditions, undefined methods and dead code before anything runs. PHPStan uses levels 0–10 (higher = stricter); Psalm offers similar checks plus taint analysis for security. Both understand PHPDoc types such as generics (@template, array<int, User>), letting you describe what PHP's native type system can't. Start low, fix, raise the level.

Notes

  • Install: composer require --dev phpstan/phpstan
  • A baseline records existing errors so you can adopt it gradually
  • Framework extensions add knowledge of magic (Laravel: Larastan)
  • @phpstan-ignore with an identifier silences one error
  • Run it in CI on every pull request

Config, Generics & Running

# phpstan.neon
parameters:
    level: 8
    paths:
        - src
        - tests
    excludePaths:
        - src/Legacy/*
includes:
    - phpstan-baseline.neon

<?php
/**
 * @template T
 */
final class Collection
{
    /** @param list<T> $items */
    public function __construct(private array $items) {}

    /** @return T|null */
    public function first(): mixed { return $this->items[0] ?? null; }
}

/** @var Collection<User> $users */
$users = new Collection([new User()]);
$users->first()?->email;      // PHPStan knows this is ?User

# vendor/bin/phpstan analyse
# vendor/bin/phpstan analyse --generate-baseline
# vendor/bin/psalm --init && vendor/bin/psalm

Code Explained

Level 8+ checks nullability strictly
Baseline file holds known errors
@template T declares a type parameter
Analyser infers first() returns ?User
Generate a baseline, then pay it down

⚠ Common Mistakes

  • Starting at max level on a legacy codebase
  • Silencing errors without an identifier or comment
  • Docblock types that lie about runtime behaviour

✓ Tips & Best Practices

  • Run in CI and fail on new errors
  • Raise the level step by step
  • Add framework extensions for magic APIs
