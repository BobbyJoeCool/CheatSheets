Comments and Doc Blocks

PHP has single-line comments (// and #) and block comments (/* ... */). A block that starts with /** is a DocBlock: editors, static analysers and documentation tools read its @tags. Since PHP 8, #[ starts an attribute, not a comment, so prefer // for single lines. Native type declarations replace many DocBlock tags; keep tags for detail the type system can't express.

Notes

  • Block comments do not nest
  • A single-line comment ends at ?> as well as at a newline
  • PHPStan and Psalm read generic types such as array<int, User>
  • DocBlocks go directly above the element they describe
  • Don't duplicate a type that's already in the signature

Comment Styles & DocBlocks

<?php
// Single-line comment
# Also single-line (avoid: looks like #[attributes])

/*
 * Block comment spanning lines
 */

/**
 * Find active users by role.
 *
 * @param list<string> $roles  role names to match
 * @return array<int, User>    keyed by user id
 * @throws InvalidArgumentException if $roles is empty
 */
function findUsers(array $roles, int $limit = 50): array
{
    /** @var User[] $rows */
    $rows = [];
    return $rows;
}

Code Explained

list<string> — more precise than the native array type
@return array<int, User> — key and value types
@throws — documents exceptions callers should handle
$limit has a native type, so no @param is needed
Inline @var tells tools the type of a local variable

⚠ Common Mistakes

  • Using # comments at line start next to attributes — confusing to read
  • DocBlock types that contradict the native types
  • Commenting what the code does instead of why

✓ Tips & Best Practices

  • Let native types carry the basics; DocBlocks add precision
  • Run PHPStan so DocBlock types are checked
  • Delete commented-out code — version control remembers it

Quick Summary

  • // and /* */ for notes
  • /** */ DocBlocks for tools
  • @param @return @throws @var
  • #[...] is an attribute
