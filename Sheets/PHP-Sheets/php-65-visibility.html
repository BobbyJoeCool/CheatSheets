Visibility & Access Control

public · protected · private · private(set) asymmetric visibility (8.4) · getters & setters · encapsulation

Who Can Touch What

Visibility controls access to properties, methods and constants. public members are accessible anywhere, protected ones from the class and its subclasses, private ones only from the declaring class. PHP 8.4 adds asymmetric visibility: public private(set) lets everyone read a property but only the class write it — no getter boilerplate needed.

Notes

  • Visibility is per class, not per object: an instance can access another instance's private members
  • Private members aren't inherited for access, but still exist
  • Methods without a keyword are public; properties need one (or var)
  • protected(set) allows subclasses to write
  • Asymmetric visibility requires a typed property

Visibility in Practice

<?php
class BankAccount
{
    public private(set) float $balance = 0.0;   // 8.4
    protected string $currency = 'EUR';
    private array $log = [];

    public function deposit(float $amt): void
    {
        if ($amt <= 0) throw new DomainException('Must be > 0');
        $this->balance += $amt;
        $this->record("deposit $amt");
    }

    private function record(string $msg): void
    {
        $this->log[] = $msg;
    }

    public function sameCurrency(BankAccount $o): bool
    {
        return $this->currency === $o->currency; // allowed
    }
}

$acct = new BankAccount();
$acct->deposit(50);
echo $acct->balance;        // 50 (public read)
// $acct->balance = 1e6;    // Error: private(set)
// $acct->record('x');      // Error: private method

Code Explained

public private(set) — read anywhere, write inside only
protected — visible to subclasses
private — this class only
Methods enforce rules before changing state
Same-class instances can read each other's protected/private data

⚠ Common Mistakes

  • Making everything public by default
  • Writing trivial getters/setters in 8.4+ when private(set) would do
  • Expecting private methods to be overridable by children

✓ Tips & Best Practices

  • Start with private; widen only when needed
  • Expose behaviour (methods), not raw data
  • Use asymmetric visibility for read-only public state

Quick Summary

  • public / protected / private
  • Class-level, not object-level
  • private(set) (8.4)
  • Default to private
