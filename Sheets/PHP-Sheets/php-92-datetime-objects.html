Sheet 92

DateTime Objects

DateTimeImmutable · DateTime · DateInterval · DatePeriod · DateTimeZone · diff() · modify()

Object-Oriented Dates

DateTimeImmutable represents a moment with a timezone; every change returns a new object, so values can't be altered by accident. (DateTime is the mutable version — avoid it in new code.) Parse with the constructor or createFromFormat(), shift with modify() or add(), compare with < > ==, and measure gaps with diff(), which returns a DateInterval. DatePeriod iterates over ranges.

Notes

  • DateTimeInterface covers both classes for type hints
  • setTimezone() converts the same instant to another zone
  • PHP 8.3 throws specific exceptions like DateMalformedStringException
  • createFromFormat('!Y-m-d', …) resets unspecified fields to zero
  • Libraries: Carbon, Chronos build on these classes

Creating, Changing, Comparing

<?php
$tz  = new DateTimeZone('Europe/Berlin');
$now = new DateTimeImmutable('now', $tz);
$due = new DateTimeImmutable('2026-12-24 18:00', $tz);

$d = DateTimeImmutable::createFromFormat('d/m/Y', '25/12/2026');
echo $d->format('Y-m-d');                    // 2026-12-25

$next = $now->modify('+1 month');            // $now unchanged
$later = $now->add(new DateInterval('P1DT2H'));   // +1 day 2 hours
$utc = $now->setTimezone(new DateTimeZone('UTC'));

var_dump($due > $now);                       // compare directly
$gap = $now->diff($due);
echo $gap->days, ' days, ', $gap->h, ' hours';
echo $gap->format('%a days %R');             // total days, sign

$period = new DatePeriod(
    new DateTimeImmutable('2026-10-01'),
    new DateInterval('P1W'),
    new DateTimeImmutable('2026-11-01'),
);
foreach ($period as $week) echo $week->format('M j'), ' ';
// Oct 1 Oct 8 Oct 15 Oct 22 Oct 29

Code Explained

Always pass a timezone (or set a default)
createFromFormat() parses a known pattern
Immutable methods return new objects
DateInterval spec: P = period, T = time part
DatePeriod yields each step in the range

⚠ Common Mistakes

  • Using mutable DateTime and changing a shared value
  • Comparing format() strings instead of objects
  • Forgetting timezones when parsing user input

✓ Tips & Best Practices

  • Use DateTimeImmutable everywhere
  • Inject a clock (PSR-20) to test time-dependent code
  • Store UTC, convert at the edges

Quick Summary

  • DateTimeImmutable + timezone
  • modify / add return new objects
  • diff() → DateInterval
  • DatePeriod for ranges
