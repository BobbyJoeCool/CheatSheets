Your Own Exception Types

Create a custom exception by extending Exception or, better, the closest SPL class. A custom type lets callers catch your failures specifically and can carry extra data such as an order ID or HTTP status. Give a package a common base class or marker interface so users can catch everything from it in one place. Pass the original exception as $previous to keep the full chain.

Notes

  • Constructor signature: ($message = '', $code = 0, ?Throwable $previous = null)
  • Named constructors (static fromId()) keep messages consistent
  • Mark leaf exception classes final unless you expect subclasses
  • Don't put secrets in messages; they end up in logs
  • Keep exception classes in an Exception/ namespace

A Small Exception Hierarchy

<?php
namespace Shop\Exception;

interface ShopException extends \Throwable {}   // marker

class OrderNotFound extends \RuntimeException
    implements ShopException
{
    public function __construct(
        public readonly int $orderId,
        ?\Throwable $previous = null,
    ) {
        parent::__construct("Order #$orderId not found",
            404, $previous);
    }

    public static function forId(int $id): self
    {
        return new self($id);
    }
}

try {
    throw OrderNotFound::forId(42);
} catch (OrderNotFound $e) {
    echo $e->getMessage(), ' ', $e->getCode();  // ... 404
    echo $e->orderId;                           // 42
} catch (ShopException $e) {
    // any other error from this package
}

Code Explained

Marker interface groups all package exceptions
Extend the closest SPL type, not bare Exception
Promoted readonly property carries context
parent::__construct() sets message, code, previous
Catch the specific type or the package interface

⚠ Common Mistakes

  • Overriding getMessage() — it's final; pass the message to the parent
  • Losing the original error by not passing $previous
  • A custom class for every possible problem

✓ Tips & Best Practices

  • Create exceptions for failures callers will handle differently
  • Name them after the problem, not the module
  • Expose context via typed properties

Quick Summary

  • Extend an SPL exception
  • Marker interface per package
  • Readonly context properties
  • Always chain $previous
