The Request Lifecycle

share-nothing model · SAPI · php-fpm · nginx · Apache · front controller · FrankenPHP

From URL to Response

A browser request reaches a web server (nginx, Apache, Caddy), which passes PHP requests to PHP-FPM over FastCGI. A worker runs your script from the top, builds the response (headers + body) and then throws all state away — the share-nothing model. Modern apps route every request through one front controller (public/index.php) that bootstraps the app and dispatches to the right handler. Worker-mode runtimes (FrankenPHP, RoadRunner, Swoole) keep the app booted between requests.

Notes

  • Each request gets fresh globals, superglobals and memory
  • Persistent data lives in sessions, databases or caches
  • FPM pool size limits concurrent requests
  • In worker mode, reset state between requests yourself
  • fastcgi_finish_request() sends the response, then keeps working

Front Controller + nginx

# nginx: send everything that isn't a file to index.php
server {
    root /var/www/app/public;
    index index.php;

    location / {
        try_files $uri /index.php$is_args$args;
    }

    location ~ \.php$ {
        fastcgi_pass unix:/run/php/php8.4-fpm.sock;
        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
    }
}

<?php // public/index.php — the front controller
require __DIR__ . '/../vendor/autoload.php';

$app = App\Kernel::boot(getenv('APP_ENV') ?: 'prod');
$response = $app->handle(App\Http\Request::fromGlobals());
$response->send();                    // headers, then body

fastcgi_finish_request();             // FPM: client done
$app->terminate();                    // slow cleanup after

Code Explained

Document root is public/, never the project root
try_files routes unknown paths to index.php
fastcgi_pass hands PHP files to FPM
One entry point bootstraps and dispatches
Post-response work runs after the client has its answer

⚠ Common Mistakes

  • Pointing the web root at the project folder — exposes .env and vendor/
  • Expecting variables to persist between requests
  • Leaking state across requests in worker mode

✓ Tips & Best Practices

  • Use a single front controller
  • Tune pm.max_children to available memory
  • Offload slow work to queues

Quick Summary

  • Server → FPM → script → response
  • Share-nothing per request
  • Front controller pattern
  • Worker modes keep the app booted
