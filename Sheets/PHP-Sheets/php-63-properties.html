Sheet 63

Properties & Readonly

typed properties · defaults · readonly (8.1) · readonly classes (8.2) · dynamic properties deprecated · #[AllowDynamicProperties]

Object State

Properties should be typed. A typed property without a default starts uninitialized and throws if read before it's assigned. readonly properties (8.1) can be set once, from inside the class scope, and never changed — perfect for value objects. A readonly class (8.2) makes every property readonly. Creating undeclared dynamic properties is deprecated since 8.2.

Notes

  • Readonly properties must be typed and have no default
  • A readonly property holding an object can still mutate that object
  • 8.3 allows re-initialising readonly props inside __clone()
  • stdClass still allows dynamic properties
  • #[AllowDynamicProperties] opts a legacy class back in

Typed and Readonly Properties

<?php
class User
{
    public int $id;                    // uninitialized
    public string $name = 'guest';     // default
    public ?string $email = null;      // nullable
    public array $roles = [];
    public readonly DateTimeImmutable $created;

    public function __construct()
    {
        $this->created = new DateTimeImmutable();   // set once
    }
}

$u = new User();
// echo $u->id;      // Error: must not be accessed before init
$u->id = 7;
// $u->created = new DateTimeImmutable();  // Error: readonly
// $u->nickname = 'A';  // Deprecated: dynamic property

readonly class Money
{
    public function __construct(
        public int $amount,
        public string $currency,
    ) {}
}
$m = new Money(500, 'EUR');
// $m->amount = 1;   // Error: Cannot modify readonly property

Code Explained

No default → uninitialized until assigned
?string ... = null → explicitly nullable
Readonly set once in the constructor
Undeclared property assignment is deprecated
readonly class + promoted properties = compact value object

⚠ Common Mistakes

  • Reading a typed property before assigning it
  • Relying on dynamic properties (deprecated 8.2)
  • Thinking readonly makes nested objects immutable

✓ Tips & Best Practices

  • Type every property
  • Use readonly for identity and value objects
  • Use DateTimeImmutable inside readonly objects

Quick Summary

  • Typed properties
  • Uninitialized ≠ null
