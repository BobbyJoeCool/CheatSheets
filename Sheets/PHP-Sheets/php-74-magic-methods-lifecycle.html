Sheet 74

Magic Methods — Cloning & Serialization

__clone · __serialize · __unserialize · __sleep · __wakeup · __debugInfo · __set_state

Lifecycle Hooks

These magic methods run at specific points in an object's life. __clone() runs on the copy after clone, letting you deep-copy nested objects. __serialize() / __unserialize() (7.4) control how serialize() stores the object and how it's rebuilt — they replace the older __sleep() / __wakeup(). __debugInfo() customises var_dump() output and __set_state() supports var_export().

Notes

  • __clone runs with $this = the new copy
  • If both exist, __serialize wins over __sleep
  • __unserialize runs instead of the constructor
  • Never unserialize() untrusted input (Sheet 104)
  • Hide secrets from dumps with __debugInfo() or #[\SensitiveParameter]

__clone, __serialize & __debugInfo

<?php
class Order
{
    public function __construct(
        public array $items,
        public DateTime $placed,
        private string $apiKey,
    ) {}

    public function __clone(): void
    { $this->placed = clone $this->placed; }      // deep copy

    public function __serialize(): array
    { return ['items' => $this->items, 'at' => $this->placed]; }

    public function __unserialize(array $d): void
    {
        [$this->items, $this->placed] = [$d['items'], $d['at']];
        $this->apiKey = '';                       // never stored
    }

    public function __debugInfo(): array
    { return ['items' => $this->items, 'apiKey' => '***']; }
}

$a = new Order(['mug'], new DateTime(), 'secret');
$b = clone $a;                        // $b->placed is its own
$copy = unserialize(serialize($a));   // via __(un)serialize
var_dump($a);                         // uses __debugInfo

Code Explained

clone is shallow; __clone copies nested objects
__serialize returns a plain array to store
Secrets are left out of the serialised form
__unserialize rebuilds state (constructor not called)
__debugInfo masks sensitive fields in dumps

⚠ Common Mistakes

  • Shallow clones sharing mutable DateTime or collections
  • Implementing the deprecated Serializable interface
  • Leaking passwords via var_dump in logs

✓ Tips & Best Practices

  • Use immutable objects to avoid clone surprises
  • Prefer JSON over serialize() for storage
  • Mask secrets in __debugInfo()

Quick Summary

  • __clone for deep copies
  • __serialize / __unserialize
  • __debugInfo for dumps
  • Avoid Serializable
