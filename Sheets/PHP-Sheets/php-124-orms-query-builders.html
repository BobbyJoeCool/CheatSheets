ORMs & Query Builders

Doctrine ORM · Doctrine DBAL · Eloquent · entities · migrations · N+1 queries

Higher-Level Database Access

A query builder (Doctrine DBAL, Laravel's query builder) composes SQL with method calls and binds values for you. An ORM maps rows to objects. Eloquent (Laravel) uses Active Record — each model saves itself. Doctrine ORM (Symfony) uses Data Mapper — plain entities plus an EntityManager that tracks changes. Both include migrations for versioning the schema. Watch out for the N+1 query problem and use eager loading.

Notes

  • ORMs still use prepared statements under the hood
  • Raw SQL is fine for reports and complex queries
  • Migrations belong in version control
  • Log queries in development to spot N+1
  • Eager loading: Eloquent with(), Doctrine fetch joins

Eloquent, Doctrine, and the N+1 Fix

<?php
// Eloquent (Active Record)
class Post extends Illuminate\Database\Eloquent\Model
{
    protected $fillable = ['title', 'body'];
    public function author()
    { return $this->belongsTo(User::class); }
}
$post = Post::create(['title' => 'Hi', 'body' => '…']);
$recent = Post::where('published', true)->latest()->take(10)->get();

foreach (Post::all() as $p) echo $p->author->name;    // N+1!
foreach (Post::with('author')->get() as $p) {         // 2 queries
    echo $p->author->name;
}

// Doctrine ORM (Data Mapper, attributes)
use Doctrine\ORM\Mapping as ORM;

#[ORM\Entity]
class Product
{
    #[ORM\Id, ORM\GeneratedValue, ORM\Column]
    public ?int $id = null;
    #[ORM\Column(length: 120)]
    public string $name;
}
$product = new Product();
$product->name = 'Mug';
$em->persist($product);
$em->flush();                                 // INSERT here
$found = $em->getRepository(Product::class)
    ->findOneBy(['name' => 'Mug']);

Code Explained

Eloquent models map to tables by convention
Query methods chain and bind values
Lazy relation in a loop = one query per row
with() eager-loads in a single extra query
Doctrine tracks entities and writes on flush()

⚠ Common Mistakes

  • Accessing relations inside loops without eager loading
  • Mass assignment without $fillable guards
  • Loading whole tables into objects for a count

✓ Tips & Best Practices

  • Enable query logging during development
  • Use DTO/array hydration for read-heavy reports
  • Keep migrations small and reversible

Quick Summary

  • Builders compose SQL
  • Eloquent = Active Record
  • Doctrine = Data Mapper
  • Eager-load to avoid N+1
