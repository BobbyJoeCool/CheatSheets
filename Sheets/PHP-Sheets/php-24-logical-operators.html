Logical Operators

&& · || · ! · and · or · xor · precedence pitfall · short-circuit

Combining Conditions

&&, || and ! combine boolean conditions and always return bool. Both && and || short-circuit: the right side runs only if needed. PHP also has word forms and, or and xor, but and/or have lower precedence than =, which causes real bugs: $ok = true and false; sets $ok to true. Use the symbol forms in expressions.

Notes

  • xor is true when exactly one side is true (no symbol form)
  • ! binds tightly: !$a == $b means (!$a) == $b
  • Operands are converted to bool using truthiness rules
  • $x || throw new E() works because throw is an expression (8.0)
  • or die() idiom is old style — prefer exceptions

Short-Circuit & Precedence

<?php
$age = 20; $member = false;

if ($age >= 18 && !$member) { echo "adult guest\n"; }
if ($age < 13 || $age > 65) { echo "discount\n"; }

// Short-circuit: right side skipped
$user = null;
if ($user !== null && $user->isAdmin()) { /* safe */ }

// Precedence trap
$a = true and false;   // ($a = true) and false
var_dump($a);          // bool(true)
$b = (true and false); // bool(false)
$c = true && false;    // bool(false)

var_dump(true xor true);   // false
var_dump(true xor false);  // true

$config = load() ?: throw new RuntimeException('none');

Code Explained

&& stops at the first falsy operand
Null check before the method call prevents an error
and loses to =, so the assignment happens first
Parentheses or && give the expected result
throw in an expression aborts when the left side is falsy

⚠ Common Mistakes

  • $ok = check() and other(); — $ok ignores other()
  • !$a == $b when you meant !($a == $b)
  • Putting expensive calls first in || chains

✓ Tips & Best Practices

  • Use && / || everywhere; avoid and / or
  • Order conditions cheapest and most likely first
  • Add parentheses whenever you mix && and ||

Quick Summary

  • && || !
  • Short-circuit evaluation
  • and/or bind below =
  • xor = exactly one
