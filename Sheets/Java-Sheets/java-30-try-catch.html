Handling Exceptions

An exception is an object thrown when something goes wrong at runtime. Code that might fail goes in a try block, and a catch block handles a specific exception type. If no catch matches, the exception travels up the call stack and, if never caught, ends the program with a stack trace.

Notes

  • Catch blocks are checked in order; first match wins
  • Catch specific types before general ones
  • Java 7+: catch several types with |
  • All exceptions extend Throwable

Syntax

try {
    int n = Integer.parseInt(input);     // may throw
    int r = 100 / n;                     // may throw
    System.out.println(r);
} catch (NumberFormatException e) {
    System.out.println("Not a number: " + e.getMessage());
} catch (ArithmeticException e) {
    System.out.println("Can't divide by zero");
} catch (Exception e) {                  // catch-all, last
    e.printStackTrace();
}

try {
    Files.readString(path);
} catch (IOException | SecurityException e) {   // multi-catch
    log.error("Read failed", e);
}

Notes

Execution jumps to the first matching catch
Lines after the failing line in try never run
getMessage() — short description
printStackTrace() — full call stack to stderr

⚠ Common Mistakes

  • Empty catch blocks that silently swallow errors
  • Catching Exception first, which makes later catches unreachable (compile error)
  • Using exceptions for normal flow, like ending a loop

✓ Tips & Best Practices

  • Catch only what you can handle; let the rest propagate
  • Always log or rethrow with the original exception as the cause
  • Validate input (hasNextInt) instead of relying on catches

Quick Summary

  • try — risky code
  • catch (Type e) — handle one type
  • A | B — multi-catch
  • Specific before general
