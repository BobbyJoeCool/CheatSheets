Virtual Threads (Java 21)

virtual threads · Thread.ofVirtual · newVirtualThreadPerTaskExecutor · carrier thread · pinning · blocking I/O · structured concurrency

Millions of Cheap Threads

Virtual threads (final in Java 21) are lightweight threads managed by the JVM rather than the OS. When one blocks on I/O, the JVM parks it and frees the underlying carrier thread for other work. This lets plain, blocking, one-thread-per-request code scale to hundreds of thousands of concurrent tasks without async callbacks.

Notes

  • Best for I/O-bound work: HTTP calls, database queries, files
  • No benefit for CPU-bound work; use a fixed platform pool there
  • Don't pool virtual threads; create one per task
  • Java 24+ removes most synchronized pinning

Using Virtual Threads

Thread vt = Thread.ofVirtual().name("vt-1").start(() -> handle(request));
vt.join();

Thread.startVirtualThread(() -> System.out.println("hello"));

try (ExecutorService exec = Executors.newVirtualThreadPerTaskExecutor()) {
    List<Future<String>> pages = urls.stream()
        .map(u -> exec.submit(() -> fetch(u)))   // 10,000 tasks is fine
        .toList();
    for (Future<String> p : pages) process(p.get());
}                                                 // waits for all

Thread.currentThread().isVirtual();              // true inside a virtual thread

Semaphore dbLimit = new Semaphore(20);           // limit scarce resources
Callable<Row> job = () -> {
    dbLimit.acquire();
    try { return queryDb(); } finally { dbLimit.release(); }
};

Notes

Each task gets its own virtual thread
Blocking fetch doesn't tie up an OS thread
Use a Semaphore to cap access to limited resources like DB connections
Thread-locals work but get costly with millions of threads

⚠ Common Mistakes

  • Putting virtual threads in a fixed-size pool, which removes the benefit
  • Expecting CPU-heavy code to run faster
  • Unbounded fan-out hammering a database — limit with a Semaphore

✓ Tips & Best Practices

  • Switch servers (Tomcat, Jetty, Spring Boot 3.2+) to virtual threads with a config flag
  • Keep code blocking and simple; skip reactive complexity for I/O workloads
  • Watch for pinning with -Djdk.tracePinnedThreads (older JDKs) or JFR

Quick Summary

  • Lightweight JVM threads
  • One per task, never pooled
  • Ideal for blocking I/O
  • newVirtualThreadPerTaskExecutor()
