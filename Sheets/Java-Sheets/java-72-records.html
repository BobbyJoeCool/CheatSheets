Records (Java 16+)

record · components · accessor · compact constructor · immutability · equals · hashCode · toString

Concise Immutable Data Classes

A record declares a class whose purpose is to carry data. From one line, record Point(int x, int y), Java generates private final fields, a constructor, accessors x() and y(), and value-based equals, hashCode, and toString. Records are immutable and implicitly final.

Notes

  • Records can't extend classes, but can implement interfaces
  • No extra instance fields allowed beyond the components
  • Static fields and methods are allowed
  • Shallowly immutable: a List component can still be mutated

Record Features

public record Point(int x, int y) { }

Point p = new Point(3, 4);
p.x();                              // 3   (accessor, no "get")
p.toString();                       // "Point[x=3, y=4]"
p.equals(new Point(3, 4));          // true (value equality)

public record Range(int lo, int hi) {
    public Range {                              // compact constructor
        if (lo > hi) throw new IllegalArgumentException(lo + " > " + hi);
    }
    public int length() { return hi - lo; }     // extra method
    public static Range of(int n) { return new Range(0, n); }
}

public record Team(String name, List<String> members) {
    public Team { members = List.copyOf(members); }   // defensive copy
}

if (obj instanceof Point(int x, int y)) {    // record pattern (Java 21)
    System.out.println(x + y);
}

Notes

Compact constructors validate or normalize without repeating assignments
List.copyOf makes the component truly immutable
Records are ideal map keys and DTOs

⚠ Common Mistakes

  • Calling p.getX() — record accessors have no get prefix
  • Assuming list components are immutable without copying them
  • Trying to add instance fields or extend another class

✓ Tips & Best Practices

  • Use records for DTOs, API responses, and multiple return values
  • Validate in a compact constructor
  • Declare local records inside methods for temporary groupings
