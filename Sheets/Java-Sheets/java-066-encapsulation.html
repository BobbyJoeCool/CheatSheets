Encapsulation

Hiding Internal State

Encapsulation keeps an object's data private and exposes only the operations that make sense. Outside code can't put the object into an invalid state because every change goes through methods that enforce the rules (invariants). Java's four access levels control who can see each class, field, and method.

Notes

  • Default (no modifier) is package-private
  • Top-level classes can only be public or package-private
  • private is per-class, not per-object: instances of the same class can read each other's private fields
  • Expose the narrowest access that works

Protecting an Invariant

public class BankAccount {
    private double balance;                       // hidden
    private final List<String> history = new ArrayList<>();

    public void deposit(double amt) {
        if (amt <= 0) throw new IllegalArgumentException("amount > 0");
        balance += amt;
        history.add("+" + amt);
    }
    public void withdraw(double amt) {
        if (amt > balance) throw new IllegalStateException("insufficient");
        balance -= amt;
        history.add("-" + amt);
    }
    public double getBalance() { return balance; }
    public List<String> getHistory() {
        return List.copyOf(history);              // no outside edits
    }
}

acct.balance = -500;            // ✖ compile error: private
acct.getHistory().clear();      // ✖ UnsupportedOperationException

Notes

Rule: balance never goes negative
Only deposit/withdraw change state
Returning a copy stops callers from editing internal lists

Java Versions

  • 1.0 — public · protected · package-private · private
  • 9 — modules add a layer above public (exports)
  • 17 — sealed controls who can extend

Idiomatic Java

  • protected "in case a subclass needs it" → private until one does
  • public just so tests can reach it → package-private, tests in the same package
  • setBalance(double) → intention methods: deposit, withdraw

⚠ Common Mistakes

  • Public fields that anyone can set to invalid values
  • Returning internal mutable collections or arrays directly
  • Adding a getter and setter for every field by reflex, which exposes everything anyway

✓ Tips & Best Practices

  • Start every field as private final; relax only when needed
  • Return List.copyOf or Collections.unmodifiableList
  • Validate in constructors and mutators

Quick Summary

  • private fields, public methods
  • Four access levels
  • Methods enforce invariants
  • Return copies, not internals
