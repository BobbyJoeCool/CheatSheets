JDBC CRUD Operations

INSERT · SELECT · UPDATE · DELETE · executeUpdate · generated keys · transactions · commit · rollback · batch

Create, Read, Update, Delete

CRUD maps directly to SQL INSERT, SELECT, UPDATE, and DELETE. In JDBC, writes use executeUpdate, which returns the number of affected rows. Group related writes in a transaction by turning off auto-commit, then commit() on success or rollback() on failure. Batching sends many statements in one round trip.

Notes

  • Auto-commit is on by default: each statement commits immediately
  • Request generated IDs with RETURN_GENERATED_KEYS

CRUD + Transaction

String ins = "INSERT INTO product(name, price) VALUES (?, ?)";
try (var ps = conn.prepareStatement(ins, Statement.RETURN_GENERATED_KEYS)) {
    ps.setString(1, "Lamp");
    ps.setBigDecimal(2, new BigDecimal("29.99"));
    ps.executeUpdate();                               // 1 row
    try (ResultSet keys = ps.getGeneratedKeys()) {
        long id = keys.next() ? keys.getLong(1) : -1;
    }
}

String upd = "UPDATE product SET price = ? WHERE id = ?";
try (var ps = conn.prepareStatement(upd)) {
    ps.setBigDecimal(1, new BigDecimal("24.99"));
    ps.setLong(2, 7);
    int rows = ps.executeUpdate();                    // 0 → not found
}

conn.setAutoCommit(false);                            // transaction
String sub = "UPDATE acct SET bal = bal - ? WHERE id = ?";
String add = "UPDATE acct SET bal = bal + ? WHERE id = ?";
try (var debit = conn.prepareStatement(sub);
     var credit = conn.prepareStatement(add)) {
    debit.setInt(1, 100);  debit.setLong(2, 1);  debit.executeUpdate();
    credit.setInt(1, 100); credit.setLong(2, 2); credit.executeUpdate();
    conn.commit();                                    // both or neither
} catch (SQLException e) { conn.rollback(); throw e; }
finally { conn.setAutoCommit(true); }

Notes

Generated keys come back as a small ResultSet
commit makes both updates permanent together
rollback undoes everything since the last commit

⚠ Common Mistakes

  • Forgetting commit() with auto-commit off — changes vanish when the connection closes
  • Not rolling back after a failed statement in a transaction
  • Inserting thousands of rows one round trip at a time instead of batching

✓ Tips & Best Practices

  • Wrap transactions in a helper that commits or rolls back automatically
  • Batch large inserts: ps.addBatch() in a loop, then executeBatch()
  • Use UPDATE … RETURNING (PostgreSQL) to get updated values in one call

Quick Summary

  • executeUpdate — writes, returns row count
  • executeQuery — reads
  • setAutoCommit(false) + commit/rollback
  • Batch for bulk writes
