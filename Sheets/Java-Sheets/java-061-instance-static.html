Sheet 061

Instance vs Static Members

static field · instance field · static block · static nested · class variable · shared state · memory

One per Object vs One per Class

Instance fields exist once per object, so each object has its own copy. Static fields exist once per class and are shared by every instance. Static initializer blocks run once when the class is first loaded, which is useful for setting up complex static data.

Notes

  • Access static members through the class name: Counter.total
  • Static fields are initialized before any instance is created
  • static final primitives and strings are compile-time constants
  • Mutable static state is shared across threads

Under the JVM

  • <clinit> runs once, under a lock, the first time the class is used — that's why the holder idiom is thread-safe
  • Static fields live with the class's Class object on the heap; class metadata sits in Metaspace
  • Static data is collected only when its class loader is unloaded

Counting Instances

public class Ticket {
    private static int issued = 0;              // shared by all tickets
    private static final Map<String, Double> PRICES;

    static {                                    // runs once at class load
        PRICES = Map.of("adult", 12.0, "child", 6.0);
    }

    private final int number;                   // per object
    private final String type;

    public Ticket(String type) {
        this.type = type;
        this.number = ++issued;                 // update shared counter
    }
    public double price() { return PRICES.get(type); }
    public static int issuedCount() { return issued; }
}

Ticket a = new Ticket("adult");   // number 1
Ticket b = new Ticket("child");   // number 2
Ticket.issuedCount();             // 2
b.price();                        // 6.0

Notes

issued is one counter for the whole class
number differs per ticket
static {} handles setup too complex for one line
Instance methods can read static fields; not vice versa

Java Versions

  • 1.0 — static fields and static {} blocks
  • 5 — AtomicInteger / AtomicLong
  • 16 — static members allowed in inner classes

Idiomatic Java

  • Double-checked locking for a lazy singleton → a holder class: static class H { static final X I = new X(); }
  • static {} block that only fills an immutable map → Map.of(...) inline

⚠ Common Mistakes

  • Making a field static by accident — every object then shares one value
  • Incrementing a static counter from multiple threads without synchronization
  • Accessing static members through instances: a.issuedCount() compiles but misleads

✓ Tips & Best Practices

  • Use static final for constants, rarely mutable statics
  • Use AtomicInteger for shared counters in concurrent code
  • Prefer dependency injection over static singletons for testability

Quick Summary

  • Instance — per object
  • Static — per class, shared
  • static { } — one-time setup
  • Access statics via class name
