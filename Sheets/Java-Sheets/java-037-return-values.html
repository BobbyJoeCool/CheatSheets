Return Values

return · void · early return · returning objects · returning multiple values · record · Optional

Getting Results Back

return ends a method and, for non-void methods, sends a value back to the caller. The returned value must match (or be assignable to) the declared return type. A Java method returns one value, but that value can be an array, collection, record, or Optional when you need more than a single number.

Notes

  • void methods may use a bare return; to exit early
  • Code directly after return is unreachable (compile error)
  • Every path in a non-void method must return or throw
  • Prefer empty collections over null

Under the JVM

  • Values come back on the operand stack: ireturn, dreturn, areturn
  • Returning a primitive never allocates; returning an object usually does
  • Escape analysis can scalar-replace a short-lived returned record, skipping the allocation

Return Patterns

static boolean isEven(int n) { return n % 2 == 0; }   // expression

static String grade(int s) {                    // early returns
    if (s >= 90) return "A";
    if (s >= 80) return "B";
    return "C";
}

record MinMax(int min, int max) { }             // multiple values
static MinMax range(int[] a) {
    return new MinMax(Arrays.stream(a).min().orElseThrow(),
                      Arrays.stream(a).max().orElseThrow());
}
MinMax r = range(new int[]{4, 1, 9});
r.min(); r.max();                               // 1, 9

static Optional<User> find(String id) {         // maybe-absent
    return Optional.ofNullable(db.get(id));
}
static List<String> tags() { return List.of(); } // never null

Notes

Returning a boolean expression beats if … return true; else return false;
A record names each returned value
Optional makes "not found" explicit

Java Versions

  • 1.0 — return and void
  • 8 — Optional for maybe-missing results
  • 10 — Optional.orElseThrow() · 16 — records for multiple values

Idiomatic Java

  • opt.get() → opt.orElseThrow() (same behavior, honest name)
  • int[] out parameter to send back a second value → return a record
  • return null; for an empty collection → return List.of();

⚠ Common Mistakes

  • if (x > 0) return true; else return false; — just return x > 0;
  • Returning null for "no results" and causing NPEs downstream
  • Returning an internal mutable list that callers can modify; return List.copyOf or an unmodifiable view

✓ Tips & Best Practices

  • Use guard-clause early returns to reduce nesting
  • Prefer records over arrays like int[]{min, max} for multiple values
  • Don't return Optional from getters of fields or for collections

Quick Summary

  • return value; — send result
  • return; — exit a void method
  • Many values → record
  • Absent value → Optional
