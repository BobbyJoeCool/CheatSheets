Annotations & Reflection

@interface · @Retention · @Target · @Override · Class<?> · getDeclaredFields · getMethods · invoke

Metadata and Runtime Inspection

Annotations attach metadata to code (@Override, @Deprecated, @Test). You can define your own with @interface. Reflection lets a program inspect classes, fields, methods, and annotations at runtime through Class<?> objects. Frameworks like JUnit, Spring, and Jackson combine the two: read annotations via reflection and act on them.

Notes

  • @Retention(RUNTIME) is required to read an annotation via reflection
  • @Target limits where an annotation may appear
  • Reflection is slower and bypasses compile-time checks

Custom Annotation + Reflection

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
@interface Required { String message() default "is required"; }

class SignupForm {
    @Required String email;
    @Required(message = "needs a value") String password;
    String nickname;
}

static List<String> validate(Object obj) throws IllegalAccessException {
    List<String> errors = new ArrayList<>();
    for (Field f : obj.getClass().getDeclaredFields()) {
        Required r = f.getAnnotation(Required.class);
        if (r == null) continue;
        f.setAccessible(true);
        if (f.get(obj) == null) errors.add(f.getName() + " " + r.message());
    }
    return errors;
}
validate(new SignupForm());   // [email is required, password needs a value]

Method m = String.class.getMethod("toUpperCase");
m.invoke("hi");                                  // "HI"

Notes

default supplies an element value when omitted
getDeclaredFields includes private fields
invoke calls a method found at runtime

⚠ Common Mistakes

  • Forgetting @Retention(RUNTIME) — getAnnotation returns null
  • Using reflection for ordinary logic that an interface would express safely
  • Ignoring checked reflection exceptions instead of handling or wrapping them

✓ Tips & Best Practices

  • Use annotations for declarative config read by tools or frameworks
  • Cache Field/Method lookups; reflection lookups are costly
  • Prefer MethodHandle or records' accessors for faster dynamic access
