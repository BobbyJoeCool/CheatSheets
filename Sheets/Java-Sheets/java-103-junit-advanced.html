JUnit 5 — Advanced

@ParameterizedTest · @ValueSource · @CsvSource · @MethodSource · @Nested · @Tag · assumptions · @TempDir

Data-Driven and Organized Tests

JUnit 5 can run one test method with many inputs using parameterized tests, group related tests with @Nested classes, tag tests for selective runs, skip tests conditionally with assumptions, and inject helpers like temporary directories. Parameterized tests need the junit-jupiter-params artifact (included in junit-jupiter).

Notes

  • Each parameter set shows as a separate test in reports
  • @CsvSource converts strings to parameter types automatically
  • @MethodSource references a static method returning a stream

Advanced Features

@ParameterizedTest @ValueSource(strings = {"racecar", "level"})
void palindromes(String w) { assertTrue(Strings.isPalindrome(w)); }

@ParameterizedTest(name = "{0} + {1} = {2}")
@CsvSource({"1, 2, 3", "10, -5, 5", "0, 0, 0"})
void add(int a, int b, int expected) {
    assertEquals(expected, calc.add(a, b));
}

@ParameterizedTest
@MethodSource("orders")
void totals(Order o, double exp) { assertEquals(exp, o.total(), 0.01); }
static Stream<Arguments> orders() {
    return Stream.of(Arguments.of(new Order(2, 5.0), 10.0),
                     Arguments.of(new Order(0, 9.0), 0.0));
}

@Nested class WhenEmpty { @Test void sizeIsZero() { /* … */ } }

@Test @Tag("slow")
void bigImport(@TempDir Path dir) {
    assumeTrue(System.getenv("CI") != null);   // skip unless on CI
    Files.writeString(dir.resolve("in.csv"), "a,b");
}

⚠ Common Mistakes

  • Non-static @MethodSource methods (only allowed with @TestInstance(PER_CLASS))
  • Commas inside @CsvSource values without quoting them: "'a, b', 2"
  • Using assumptions to hide genuinely failing tests

✓ Tips & Best Practices

  • Replace copy-pasted tests with one parameterized test
  • Use @Nested to mirror "given/when" scenarios
  • Tag slow or integration tests and run them separately
