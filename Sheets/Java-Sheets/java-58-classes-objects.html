Blueprints and Instances

A class is a blueprint that defines fields (state) and methods (behavior). An object is one instance of that class, created with new. Variables of a class type hold a reference to an object, not the object itself, so two variables can point to the same object, and a variable can be null.

Notes

  • Every class implicitly extends Object
  • Objects live on the heap; the GC frees unreachable ones
  • Override toString() for readable printing
  • Use a record (Sheet 72) for simple data carriers

A Complete Small Class

public class Dog {
    private String name;                 // fields (state)
    private int age;

    public Dog(String name, int age) {   // constructor
        this.name = name;
        this.age = age;
    }

    public void bark() {                 // method (behavior)
        System.out.println(name + " says woof");
    }
    public int getAge() { return age; }

    @Override
    public String toString() { return "Dog[" + name + ", " + age + "]"; }
}

Dog rex = new Dog("Rex", 3);   // create an object
rex.bark();                     // Rex says woof
Dog alias = rex;                // same object, two references
System.out.println(alias);      // Dog[Rex, 3]
Dog none = null;
none.bark();                    // ✖ NullPointerException

Notes

new allocates the object and runs the constructor
rex.bark() — dot operator calls a method
alias and rex point to one Dog
println(obj) calls obj.toString()

⚠ Common Mistakes

  • Calling methods on a null reference → NullPointerException
  • Making fields public instead of using methods to control access
  • Forgetting @Override on toString, so a typo like tostring() silently doesn't override

✓ Tips & Best Practices

  • One public class per file; name the file after it
  • Keep classes focused on one responsibility
  • Override toString for every class you'll debug or log
