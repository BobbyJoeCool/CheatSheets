Lambda Expressions

-> · functional interface · Predicate · Function · Consumer · Supplier · BiFunction · @FunctionalInterface

Functions as Values

A lambda is a short anonymous function written as (params) -> body. It implements a functional interface, which is any interface with exactly one abstract method. Lambdas let you pass behavior to methods like sort, forEach, removeIf, and stream operations without writing a full class.

Notes

  • Parameter types are usually inferred
  • One parameter: parentheses optional x -> x * 2
  • Multi-statement bodies need { } and an explicit return
  • Captured locals must be effectively final

Lambda Syntax

Runnable hello = () -> System.out.println("hi");
Function<Integer, Integer> square = x -> x * x;
BiFunction<Integer, Integer, Integer> add = (a, b) -> a + b;
Predicate<String> empty = s -> s.isEmpty();
Consumer<String> shout = s -> System.out.println(s.toUpperCase());
Supplier<List<String>> maker = () -> new ArrayList<>();

square.apply(5);              // 25
add.apply(2, 3);              // 5
empty.test("");               // true
shout.accept("hey");          // HEY

Comparator<String> byLen = (a, b) -> {
    int d = Integer.compare(a.length(), b.length());
    return d != 0 ? d : a.compareTo(b);
};
names.sort(byLen);
names.removeIf(s -> s.startsWith("x"));

Notes

Each functional interface has its own method name: apply, test, accept, get
Predicates combine with and, or, negate
@FunctionalInterface makes the compiler enforce one abstract method

Core Functional Interfaces (java.util.function)

⚠ Common Mistakes

  • Modifying a captured local: count++ inside a lambda won't compile
  • Writing long, multi-line lambdas — extract a method and use a method reference
  • Using Function<Integer,Integer> in hot loops; IntUnaryOperator avoids boxing

✓ Tips & Best Practices

  • Prefer method references when they read better (Sheet 41)
  • Use primitive specializations: IntPredicate, ToIntFunction
  • Name reusable lambdas as variables to document intent
