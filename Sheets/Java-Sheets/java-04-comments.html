Comments & Javadoc

// · /* */ · /** */ · @param · @return · @throws · javadoc tool

Three Kinds of Comments

Java has single-line comments (//), block comments (/* */), and Javadoc comments (/** */). The compiler ignores all three. Javadoc comments placed directly above a class, field, or method are read by the javadoc tool to generate HTML API docs and by IDEs to show hover documentation.

Notes

  • Block comments cannot be nested: /* /* */ */ breaks
  • Javadoc's first sentence becomes the summary line
  • Javadoc accepts HTML tags (<p>, <code>) and {@code ...}

Comment Styles

// Single-line comment
int count = 0;   // trailing comment

/*
 * Block comment spanning
 * several lines.
 */

/**
 * Returns the area of a circle.
 *
 * @param radius the radius in centimeters; must be ≥ 0
 * @return the area in square centimeters
 * @throws IllegalArgumentException if radius is negative
 * @see Math#PI
 */
public static double area(double radius) {
    if (radius < 0) throw new IllegalArgumentException("radius");
    return Math.PI * radius * radius;
}

⚠ Common Mistakes

  • Commenting what the code does instead of why — the code already says what
  • Leaving commented-out code in commits; version control keeps history
  • Writing /* ... */ inside an existing block comment to disable code — it ends the outer comment early

✓ Tips & Best Practices

  • Write Javadoc for every public API; skip it for obvious private helpers
  • Start the summary with a verb: "Returns…", "Creates…"
  • Use {@code null} instead of plain text so it renders as code

Quick Summary

  • // — rest of the line
  • /* */ — block, not nestable
  • /** */ — Javadoc for docs and IDE hovers
  • @param @return @throws — core tags
