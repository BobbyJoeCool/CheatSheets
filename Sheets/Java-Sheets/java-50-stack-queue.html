LIFO and FIFO

A stack is last-in, first-out (LIFO): push adds to the top and pop takes from the top. A queue is first-in, first-out (FIFO): offer adds to the back and poll takes from the front. Java's legacy Stack class still works, but Deque (Sheet 51) is the recommended implementation for both.

Notes

  • Stack extends Vector, so it's synchronized and slower
  • Queue is an interface; use ArrayDeque or LinkedList
  • PriorityQueue polls the smallest element first
  • offer/poll/peek don't throw on full or empty

Stack & Queue Usage

Deque<Integer> stack = new ArrayDeque<>();   // preferred stack
stack.push(1); stack.push(2); stack.push(3);
stack.peek();              // 3
stack.pop();               // 3
stack.pop();               // 2

Queue<String> q = new ArrayDeque<>();        // FIFO
q.offer("a"); q.offer("b"); q.offer("c");
q.peek();                  // "a"
q.poll();                  // "a"
q.size();                  // 2

PriorityQueue<Integer> pq = new PriorityQueue<>(List.of(5, 1, 4));
pq.poll();                 // 1 (smallest)
PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Comparator.reverseOrder());

Stack<Character> legacy = new Stack<>();      // works, but legacy
legacy.push('x');
legacy.pop();              // 'x'

Notes

Use Deque methods push/pop for stacks
PriorityQueue iteration order is not sorted; only poll order is
reverseOrder() turns it into a max-heap

⚠ Common Mistakes

  • Using Stack in new code; it's synchronized and inherits index methods that break LIFO
  • Printing a PriorityQueue and expecting sorted output
  • Calling pop() on an empty ArrayDeque → NoSuchElementException; check isEmpty() or use poll

✓ Tips & Best Practices

  • Declare stacks and queues as Deque<T> / Queue<T>
  • Use a stack for undo, bracket matching, and DFS
  • Use a queue for BFS, task processing, and buffering
