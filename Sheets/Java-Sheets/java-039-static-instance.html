Static vs Instance Methods

static · instance · this · utility class · factory method · static context · state

Class-Level vs Object-Level

An instance method runs on a specific object and can read and change that object's fields through this. A static method belongs to the class itself: it runs without an object and cannot touch instance fields directly. Use static for stateless utilities and factories; use instance methods for behavior that depends on an object's state.

Notes

  • Static methods have no this
  • Instance methods can call static ones, not the other way around without an object
  • Static methods can't be overridden, only hidden
  • Math.max, Integer.parseInt, List.of are static

Under the JVM

  • invokestatic has no receiver, so there's no null check or virtual lookup
  • Static calls are always bound at link time and easy for the JIT to inline
  • Static fields live with the class and are GC roots while it's loaded

Side by Side

public class Temperature {
    private final double celsius;

    private Temperature(double c) { this.celsius = c; }

    // static factory: no object yet
    public static Temperature ofFahrenheit(double f) {
        return new Temperature((f - 32) * 5 / 9);
    }

    // static utility: no state needed
    public static double cToF(double c) { return c * 9 / 5 + 32; }

    // instance: uses this object's field
    public boolean isFreezing() { return celsius <= 0; }

    public double inFahrenheit() { return cToF(celsius); }  // calls static
}

Temperature t = Temperature.ofFahrenheit(212);   // static call
t.isFreezing();                                  // false (instance)
Temperature.cToF(100);                           // 212.0

Notes

ofFahrenheit — named constructor alternative
cToF — pure function: same input, same output
isFreezing — needs celsius, so it's instance

Java Versions

  • 1.0 — static methods and fields
  • 5 — import static

Idiomatic Java

  • static getInstance() singleton → an enum singleton
  • Static method that reads the database or clock → instance method with injected dependencies
  • LocalDate.now() inside logic → pass a Clock so tests can fix the time

⚠ Common Mistakes

  • Making everything static to avoid creating objects — you lose polymorphism and testability
  • Calling a static method through an instance: t.cToF(5) compiles but misleads readers
  • Storing per-user data in static fields, which then leak across users and threads

✓ Tips & Best Practices

  • If a method doesn't use this, consider making it static
  • Prefer static factories with clear names over many constructors
  • Give utility classes a private constructor

Quick Summary

  • static — belongs to class
  • Instance — belongs to object
  • No this in static methods
  • Static for pure helpers & factories
