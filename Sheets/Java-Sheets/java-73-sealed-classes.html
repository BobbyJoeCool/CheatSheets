Sealed Classes (Java 17+)

sealed · permits · non-sealed · final · exhaustive switch · algebraic data types · pattern matching

Restricting Who Can Extend

A sealed class or interface lists exactly which types may extend or implement it with permits. Each permitted subtype must be final, sealed, or non-sealed. Because the compiler knows every subtype, a pattern switch over a sealed type can be exhaustive without a default.

Notes

  • Permitted subclasses must be in the same module (or package if unnamed module)
  • permits can be omitted if subclasses are in the same file
  • Records are implicitly final, so they pair well with sealed interfaces
  • non-sealed reopens a branch for anyone to extend

Sealed Hierarchy

public sealed interface Shape permits Circle, Square, Rect { }

public record Circle(double r) implements Shape { }
public record Square(double side) implements Shape { }
public record Rect(double w, double h) implements Shape { }

static double area(Shape s) {
    return switch (s) {                 // exhaustive: no default
        case Circle c -> Math.PI * c.r() * c.r();
        case Square q -> q.side() * q.side();
        case Rect(double w, double h) -> w * h;
    };
}

public sealed abstract class Payment permits Card, Cash, Crypto { }
public final class Card extends Payment { }
public final class Cash extends Payment { }
public non-sealed class Crypto extends Payment { }   // open again
public class Bitcoin extends Crypto { }              // allowed

// class Check extends Payment { }   ✖ not in permits list

Notes

Add a new Shape and every switch without default fails to compile, showing you what to update
Rect(double w, double h) deconstructs the record
non-sealed trades exhaustiveness for extensibility

⚠ Common Mistakes

  • Adding default to a switch over a sealed type, which hides missing cases
  • Forgetting a modifier on a permitted subclass — compile error
  • Putting permitted subclasses in another package of an unnamed module

✓ Tips & Best Practices

  • Model "one of these" data with sealed interface + records
  • Let the compiler's exhaustiveness check drive updates
  • Pair with record patterns for concise deconstruction

Quick Summary

  • sealed … permits A, B

  • Exhaustive pattern switch
