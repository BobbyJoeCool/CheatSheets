Unit Testing With JUnit

JUnit is Java's standard unit-testing framework. JUnit 5 ("Jupiter") marks test methods with @Test, checks results with static assertion methods, and sets up shared state with lifecycle annotations. Build tools find tests in src/test/java and run them with mvn test or ./gradlew test. JUnit 6 (2025) keeps the same Jupiter API.

Notes

  • Imports come from org.junit.jupiter.api
  • Test classes and methods can be package-private
  • A failed assertion stops that test only

A Test Class

import org.junit.jupiter.api.*;
import static org.junit.jupiter.api.Assertions.*;

class CalculatorTest {
    private Calculator calc;

    @BeforeEach
    void setUp() { calc = new Calculator(); }      // runs before every test

    @Test
    @DisplayName("adds two positive numbers")
    void add() {
        assertEquals(5, calc.add(2, 3));           // expected, actual
    }

    @Test
    void divideByZeroThrows() {
        var ex = assertThrows(ArithmeticException.class,
                              () -> calc.divide(1, 0));
        assertEquals("/ by zero", ex.getMessage());
    }

    @Test void doubles() { assertEquals(0.3, 0.1 + 0.2, 1e-9); }   // delta
}

Notes

assertEquals(expected, actual) — order matters for messages
assertThrows returns the exception for further checks
assertAll(...) reports every failure, not just the first
Doubles need a tolerance (delta)

Assertions

MethodPasses when
assertEquals(e, a)e equals a
assertNotNull(x)x != null
assertTrue / assertFalseCondition holds
assertThrows(T.class, code)code throws T
assertIterableEquals(e, a)Same elements, same order

Lifecycle Annotations

AnnotationRuns
@BeforeAllOnce before all tests (static)
@BeforeEachBefore each test
@AfterEachAfter each test
@AfterAllOnce after all tests (static)

⚠ Common Mistakes

  • Swapping expected and actual, which makes failure messages misleading
  • Comparing doubles with assertEquals(a, b) without a delta
  • Tests that depend on each other's order or shared static state

✓ Tips & Best Practices

  • One behavior per test; name tests after the behavior
  • Arrange–Act–Assert structure keeps tests readable
  • Use AssertJ for fluent assertions if your team prefers it

Quick Summary
