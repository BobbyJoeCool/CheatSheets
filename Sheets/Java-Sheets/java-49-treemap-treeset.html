TreeMap & TreeSet

TreeMap · TreeSet · sorted order · firstKey · floorKey · ceiling · headMap · tailSet · descending

Sorted Collections

TreeMap and TreeSet keep elements sorted at all times using a red-black tree, so operations are O(log n). Keys are ordered by their natural order (Comparable) or a Comparator you supply. They also implement NavigableMap/NavigableSet, adding range queries and nearest-match lookups.

Notes

  • No null keys (they can't be compared)
  • Keys must be Comparable or you must pass a Comparator
  • Views like headMap are live: changes flow both ways
  • Slower than hash versions; use only when order matters

Navigable Operations

TreeMap<Integer, String> grades = new TreeMap<>(Map.of(
    90, "A", 80, "B", 70, "C", 60, "D"));
grades.firstKey();              // 60
grades.lastKey();               // 90
grades.floorKey(85);            // 80   (≤ 85)
grades.ceilingKey(85);          // 90   (≥ 85)
grades.floorEntry(77).getValue();   // "C"  → grade lookup
grades.headMap(80);             // {60=D, 70=C}       (< 80)
grades.tailMap(80, true);       // {80=B, 90=A}       (≥ 80)
grades.descendingMap();         // {90=A, 80=B, 70=C, 60=D}

TreeSet<String> words = new TreeSet<>(List.of("pear", "apple", "fig"));
words;                          // [apple, fig, pear]
words.first();                  // "apple"
words.higher("fig");            // "pear"
words.pollFirst();              // removes "apple"

⚠ Common Mistakes

  • A comparator that ignores fields — the TreeSet silently drops "equal" items
  • Inserting null → NullPointerException
  • Using TreeMap where HashMap would do, paying O(log n) for nothing

✓ Tips & Best Practices

  • Use floorEntry/ceilingEntry for thresholds and time-based lookups
  • Chain thenComparing so the comparator never ties unintentionally
  • new TreeMap<>(hashMap) gives a sorted snapshot

Quick Summary

  • Always sorted, O(log n)
  • floor ceiling higher lower
  • headMap tailMap — ranges
  • Needs Comparable or Comparator
