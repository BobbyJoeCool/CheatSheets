Scriptable Builds

Gradle is a build tool configured with code instead of XML: either the Kotlin DSL (build.gradle.kts, the default for new projects) or the Groovy DSL (build.gradle). It uses the same Maven Central dependencies, supports incremental builds and caching, and is the standard for Android projects.

Notes

  • Always run through the wrapper: ./gradlew (Windows: gradlew.bat)
  • implementation hides a dependency from consumers; api exposes it
  • settings.gradle(.kts) names the project and lists subprojects
  • Output goes to build/

build.gradle.kts (Kotlin DSL)

plugins { application }

java { toolchain { languageVersion = JavaLanguageVersion.of(21) } }
repositories { mavenCentral() }

dependencies {
    implementation("com.google.code.gson:gson:2.11.0")
    testImplementation("org.junit.jupiter:junit-jupiter:5.11.0")
    testRuntimeOnly("org.junit.platform:junit-platform-launcher")
}

application { mainClass = "com.acme.billing.Main" }

tasks.test { useJUnitPlatform() }

Notes

toolchain downloads/selects the right JDK
./gradlew build — compile, test, assemble
./gradlew run — run mainClass (application plugin)
./gradlew test / clean / dependencies
useJUnitPlatform() is required for JUnit 5

Same in Groovy DSL

plugins { id 'application' }
java { toolchain { languageVersion = JavaLanguageVersion.of(21) } }
repositories { mavenCentral() }
dependencies {
    implementation 'com.google.code.gson:gson:2.11.0'
    testImplementation 'org.junit.jupiter:junit-jupiter:5.11.0'
}
application { mainClass = 'com.acme.billing.Main' }
test { useJUnitPlatform() }

⚠ Common Mistakes

  • Using compile (removed in Gradle 7) instead of implementation
  • Running a system-installed gradle instead of ./gradlew, causing version mismatches
  • Forgetting useJUnitPlatform() so no tests run

✓ Tips & Best Practices

  • Prefer Kotlin DSL for IDE autocompletion
  • Use a version catalog (libs.versions.toml) for shared versions
  • ./gradlew build --scan explains slow or failing builds
