Comparison Operators

== · != · < · > · <= · >= · equals() · compareTo · reference vs value

Comparing Values

Relational operators return a boolean. For primitives, == compares values. For objects, == compares references: it is true only when both variables point to the same object. To compare object contents, use .equals(); to order objects, use compareTo or a Comparator.

Notes

  • < > <= >= only work on numeric primitives and char
  • String must be compared with .equals()
  • Objects.equals(a, b) is null-safe
  • Double.NaN is not equal to anything, including itself

Reference vs Value

String a = "hi";
String b = "hi";
String c = new String("hi");
a == b;                   // true   (same pooled literal)
a == c;                   // false  (different object)
a.equals(c);              // true   ✔ compare contents
"HI".equalsIgnoreCase(a); // true

Objects.equals(null, null);  // true  (no NPE)
"apple".compareTo("banana"); // negative (a < b)
"b".compareTo("a");          // positive
Integer.compare(10, 3);      // positive

'a' < 'b';                // true   (compares char codes)
0.1 + 0.2 == 0.3;         // false
Math.abs((0.1 + 0.2) - 0.3) < 1e-9;  // true ✔

Notes

String literals are interned, which is why a == b can mislead you
compareTo returns negative / 0 / positive
Compare floating point with a tolerance (epsilon)

⚠ Common Mistakes

  • if (name == "admin") — works by accident with literals, fails with input; use .equals
  • input.equals("yes") throws NPE if input is null; write "yes".equals(input)
  • Chaining 1 < x < 10 doesn't compile; write 1 < x && x < 10

✓ Tips & Best Practices

  • Put the literal first in equals to avoid NPEs
  • Override equals and hashCode together in your own classes
  • Use Comparator.comparing(...) for custom ordering (Sheet 101)

Quick Summary

  • == — value for primitives, identity for objects
  • .equals() — object contents
  • compareTo — ordering (−, 0, +)
  • Floats — compare with tolerance
