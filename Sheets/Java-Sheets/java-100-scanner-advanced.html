Beyond Keyboard Input

Scanner can read from files, strings, and streams, not just System.in. You can change how it splits input with useDelimiter, read typed values with a specific Locale, test the next token against a pattern, and stream all tokens with tokens(). Basics are on Sheet 17.

Notes

  • Default delimiter is whitespace (\p{javaWhitespace}+)
  • nextDouble respects the Scanner's locale: 3,5 vs 3.5
  • Scanner(File) throws FileNotFoundException
  • Scanners on files should be closed (try-with-resources)

Advanced Scanner Usage

try (Scanner sc = new Scanner(Path.of("scores.txt"))) {      // file
    while (sc.hasNextLine()) {
        String[] parts = sc.nextLine().split(":");
    }
}

Scanner csv = new Scanner("Ada,36,98.5").useDelimiter(",");   // string source
String name = csv.next();        // "Ada"
int age = csv.nextInt();         // 36
double score = csv.nextDouble(); // 98.5

Scanner de = new Scanner("3,5").useLocale(Locale.GERMANY);
de.nextDouble();                 // 3.5

Scanner s = new Scanner("id=42 name=Ada");
s.findInLine("id=(\\d+)");
s.match().group(1);              // "42"

new Scanner("x 1 y 2").tokens().toList();   // [x, 1, y, 2]
new Scanner("a1 b2").hasNext("[a-z]\\d");   // true

Scanner in = new Scanner(System.in);
int n = Integer.parseInt(in.nextLine().trim());   // avoids newline bug

Notes

Scanner(Path) reads a file (UTF-8 by default in Java 18+)
useDelimiter takes a regex
findInLine + match() extracts groups
Reading every line then parsing avoids nextInt/nextLine mixups

⚠ Common Mistakes

  • Forgetting the locale: nextDouble() fails on "3.5" with a German default locale
  • Not closing file Scanners
  • Using Scanner for big files where BufferedReader would be far faster

✓ Tips & Best Practices

  • Set Locale.ROOT for machine-generated numeric data
  • Use tokens() with streams for quick parsing
  • Prefer Files.lines + split for large structured files
