Querying With JPA

An EntityManager performs CRUD on entities inside a transaction: persist inserts, find loads by ID, changing a managed entity updates it, and remove deletes. For queries, JPQL is SQL-like but uses entity and field names, and the Criteria API (CriteriaBuilder) builds type-checked queries in code.

Notes

  • Managed entities are saved automatically at commit ("dirty checking")
  • merge copies a detached object's state into a managed one
  • JPQL uses class names: FROM Customer, not FROM customer
  • JOIN FETCH solves most N+1 query problems

CRUD, JPQL, Criteria

EntityManager em = emf.createEntityManager();
em.getTransaction().begin();

Customer c = new Customer("Ada", "ada@x.com");
em.persist(c);                                     // INSERT on commit
Customer found = em.find(Customer.class, c.getId());
found.setName("Ada L.");                           // UPDATE (dirty checking)
em.remove(em.find(Customer.class, 99L));           // DELETE

List<Customer> big = em.createQuery(
        "SELECT DISTINCT c FROM Customer c JOIN FETCH c.orders o " +
        "WHERE o.total > :min",
        Customer.class)
    .setParameter("min", new BigDecimal("100"))
    .getResultList();

CriteriaBuilder cb = em.getCriteriaBuilder();
CriteriaQuery<Customer> q = cb.createQuery(Customer.class);
Root<Customer> root = q.from(Customer.class);
q.select(root).where(cb.like(root.get("email"), "%@x.com"));
List<Customer> matches = em.createQuery(q).getResultList();

em.getTransaction().commit(); em.close();

Notes

:min is a named parameter (safe like ?)
JOIN FETCH loads orders in the same query
Criteria queries are verbose but composable at runtime

⚠ Common Mistakes

  • N+1 queries: looping over customers and touching getOrders() for each
  • remove on a detached entity fails; find it first
  • Concatenating values into JPQL instead of using parameters

✓ Tips & Best Practices

  • Use JOIN FETCH or entity graphs for associations you'll read
  • Use DTO projections (SELECT new com.x.Dto(...)) for read-only lists
  • Spring Data derived queries (findByEmail) remove most boilerplate
