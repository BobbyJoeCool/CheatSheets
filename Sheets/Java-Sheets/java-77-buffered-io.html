Efficient Line-Based Files

BufferedReader and BufferedWriter add an in-memory buffer around another reader or writer, so the program makes far fewer slow disk calls. BufferedReader.readLine() reads whole lines, and BufferedWriter.newLine() writes the platform line separator. PrintWriter adds println and printf on top.

Notes

  • Default buffer size is 8 KB
  • readLine() strips the line terminator and returns null at EOF
  • flush() pushes buffered data out; close() flushes automatically
  • Files.newBufferedReader(path) defaults to UTF-8

Read & Write Lines

Path in = Path.of("input.txt"), out = Path.of("output.txt");

try (BufferedReader br = Files.newBufferedReader(in);
     BufferedWriter bw = Files.newBufferedWriter(out)) {
    String line;
    int n = 0;
    while ((line = br.readLine()) != null) {
        bw.write(++n + ": " + line);
        bw.newLine();
    }
}                                                  // both closed + flushed

try (var br = new BufferedReader(new FileReader("data.csv"))) {
    long count = br.lines()                        // Stream<String>
                   .filter(l -> !l.isBlank())
                   .count();
}

try (PrintWriter pw = new PrintWriter(Files.newBufferedWriter(out))) {
    pw.println("Report");
    pw.printf("%-10s %5d%n", "items", 42);
}

Notes

Opening two resources in one try header closes both
br.lines() turns the file into a lazy stream
PrintWriter swallows IOExceptions; call checkError() to detect them

⚠ Common Mistakes

  • Forgetting newLine() and writing everything on one line
  • Not closing or flushing the writer — the last buffer is lost
  • Reading a huge file into a List when a streaming while loop would use constant memory

✓ Tips & Best Practices

  • Prefer Files.newBufferedReader/Writer — UTF-8 by default
  • Use br.lines() with try-with-resources so the file closes
  • Use PrintWriter when you want printf

Quick Summary

  • Buffer = fewer disk calls
  • readLine() until null
  • newLine() — line break
  • PrintWriter — println/printf
