Converting Between Types

Widening conversions (small → large, like int → long) happen automatically because no data is lost. Narrowing conversions (large → small, like double → int) require an explicit cast and may truncate or wrap. Converting between strings and numbers uses methods such as Integer.parseInt and String.valueOf, not casts.

Notes

  • Casting double → int truncates toward zero; it does not round
  • Arithmetic promotes byte, short, char to int
  • parseInt throws NumberFormatException on bad input
  • You cannot cast between boolean and any number

Conversion Examples

int i = 100;
long l = i;                    // widening: 100
double d = i;                  // widening: 100.0

double price = 9.99;
int whole = (int) price;       // 9     (truncated)
int neg = (int) -9.99;         // -9
long r = Math.round(price);    // 10    (rounds)
byte b = (byte) 200;           // -56   (wraps)
char c = (char) 66;            // 'B'
int code = 'B';                // 66

int n = Integer.parseInt("42");          // 42
double x = Double.parseDouble("3.5");    // 3.5
String s1 = String.valueOf(42);          // "42"
String s2 = Integer.toString(255, 16);   // "ff"
int fromHex = Integer.parseInt("ff", 16); // 255

Notes on the Example

(type) — cast operator; you accept possible data loss
Math.round(double) returns long
(byte) 200 keeps the low 8 bits → −56
Radix argument converts to/from other bases

⚠ Common Mistakes

  • byte b = 10; b = b + 1; fails: b + 1 is int. Use b += 1 or a cast
  • (int) "42" — strings can't be cast to numbers; use parseInt
  • Expecting (int) 2.9 to give 3 — it gives 2

✓ Tips & Best Practices

  • Use Math.round, Math.floor, or Math.ceil when you mean rounding
  • Wrap parseInt in try/catch NumberFormatException for user input
  • int → long → float can lose precision on huge values; check if it matters

Quick Summary

  • Widening — automatic, safe
  • (type) — explicit narrowing cast
  • parseXxx — String → number
  • String.valueOf — anything → String
