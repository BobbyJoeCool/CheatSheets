Scanner · System.in · nextLine · nextInt · nextDouble · hasNextInt · close

Reading Keyboard Input

java.util.Scanner reads text from System.in (or a file or string) and breaks it into tokens separated by whitespace. Methods like nextInt() parse the next token; nextLine() reads the rest of the current line. Mixing the two is the most common beginner bug: nextInt() leaves the newline behind.

Notes

  • import java.util.Scanner; is required
  • Create one Scanner for System.in and reuse it
  • nextInt() throws InputMismatchException on non-numbers
  • Closing a Scanner on System.in closes System.in too

Reading Input

import java.util.Scanner;

Scanner in = new Scanner(System.in);

System.out.print("Name: ");
String name = in.nextLine();          // whole line: "Ada Lovelace"

System.out.print("Age: ");
int age = in.nextInt();               // 36
in.nextLine();                        // ✔ consume leftover newline

System.out.print("City: ");
String city = in.nextLine();          // works now

System.out.print("Enter a number: ");
while (!in.hasNextInt()) {            // validate before reading
    System.out.print("Not a number, try again: ");
    in.next();                        // discard bad token
}
int n = in.nextInt();

Notes

nextLine() — reads up to and removes the line break
nextInt() — reads a token, leaves \n in the buffer
hasNextInt() — peeks without consuming
in.next() — read one word (token)

⚠ Common Mistakes

  • nextInt() then nextLine() returns "" — call an extra nextLine() first
  • Creating a new Scanner(System.in) inside a loop; keep one instance
  • Closing the Scanner early, then trying to read again — System.in is gone

✓ Tips & Best Practices

  • Read everything with nextLine() and parse with Integer.parseInt for predictable behavior
  • Use hasNextXxx() to validate instead of catching exceptions
  • For large input, BufferedReader is much faster (Sheet 18)
