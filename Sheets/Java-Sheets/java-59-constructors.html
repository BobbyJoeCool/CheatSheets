Constructors

constructor · default constructor · parameterized · this() · super() · overloading · initialization order

Initializing Objects

A constructor runs when you create an object with new. It has the same name as the class and no return type. If you write no constructor, Java supplies a no-argument default constructor; as soon as you write any constructor, that default disappears. Constructors can be overloaded and can call each other with this(...).

Notes

  • this(...) or super(...) must be the first statement
  • If omitted, super() is inserted automatically
  • private constructors prevent outside instantiation

Constructor Forms

public class Account {
    private final String id;
    private double balance;
    private final String currency;

    public Account(String id, double balance, String currency) {  // full
        if (balance < 0) throw new IllegalArgumentException("negative");
        this.id = id;
        this.balance = balance;
        this.currency = currency;
    }
    public Account(String id, double balance) {   // chain with defaults
        this(id, balance, "USD");
    }
    public Account(String id) {
        this(id, 0);
    }
}

new Account("A1");                  // balance 0, USD
new Account("A2", 50);              // USD
new Account("A3", 10, "EUR");

class Savings extends Account {
    Savings(String id) { super(id, 100); }   // call parent constructor
}

Notes

Put validation in the most complete constructor
Shorter constructors delegate with this(...)
final fields must be assigned exactly once in every constructor
super(...) picks which parent constructor runs

Initialization Order

StepWhat runs
1Static fields & static blocks (once per class)
2Parent constructor (super)
3Instance field initializers & instance blocks
4Constructor body

⚠ Common Mistakes

  • Adding a return type (public void Dog()) — that's a method, not a constructor
  • Adding a parameterized constructor and breaking code that relied on the default one
  • Calling overridable methods from a constructor; subclasses may see half-built state

✓ Tips & Best Practices

  • Validate arguments in constructors so objects are always valid
  • Use static factories or a builder when there are many optional params
  • Chain constructors with this(...) to avoid duplicate code

Quick Summary

  • Same name as class, no return type
  • this(...) — call another constructor
  • super(...) — call parent's
  • Default constructor vanishes once you declare one
