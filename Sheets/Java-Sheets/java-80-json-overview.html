Working With JSON

JSON (JavaScript Object Notation) is the standard text format for web APIs and config files. The JDK has no built-in JSON parser, so Java programs use a library. The two most common are Gson (simple, Google) and Jackson (fast, feature-rich, used by Spring). Both map JSON to Java objects and back. Each has its own sheet.

Notes

  • Full Gson coverage: Sheet 108
  • Full Jackson coverage: Sheet 109
  • JSON keys are always double-quoted strings
  • Records map cleanly to JSON objects in both libraries

Same Task, Both Libraries

record User(String name, int age, List<String> roles) { }
String json = """
    {"name": "Ada", "age": 36, "roles": ["admin", "dev"]}
    """;

// Gson (Sheet 108)
Gson gson = new Gson();
User u1 = gson.fromJson(json, User.class);
String out1 = gson.toJson(u1);

// Jackson (Sheet 109)
ObjectMapper mapper = new ObjectMapper();
User u2 = mapper.readValue(json, User.class);
String out2 = mapper.writeValueAsString(u2);   // {"name":"Ada","age":36,…}

Notes

Serialize = object → JSON; deserialize = JSON → object
Gson supports records from 2.10
Jackson supports records from 2.12
Add the library via Maven/Gradle (Sheets 86–87)

⚠ Common Mistakes

  • Parsing JSON with string methods or regex — use a library
  • Mixing Gson and Jackson annotations on the same class and expecting both to apply
  • Treating numbers as double when IDs exceed 2⁵³ — use long or String

✓ Tips & Best Practices

  • Pick one library per project; Jackson if you use Spring
  • Model JSON with records for concise, immutable DTOs
  • Validate API JSON shapes with tests
