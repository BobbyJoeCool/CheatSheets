Assignment Operators

= · += · -= · *= · /= · %= · compound assignment · implicit cast

Assigning and Updating

= stores the right-hand value in the variable on the left, and the whole expression evaluates to that value. Compound assignment operators combine an operation with assignment: x += 5 means x = (type of x)(x + 5). That hidden cast lets compound operators compile where the long form would not.

Notes

  • Assignment is right-associative: a = b = 0 sets both
  • += on a String concatenates
  • Compound operators include an implicit narrowing cast
  • = is assignment; == is comparison

Compound Assignment Details

int a, b, c;
a = b = c = 0;            // chained: all 0

short s = 10;
// s = s + 1;             // ✖ int → short needs a cast
s += 1;                   // ✔ 11 (implicit (short) cast)

byte by = 127;
by += 1;                  // -128 (silent overflow)

int total = 7;
total /= 2;               // 3  (integer division)
double avg = 7;
avg /= 2;                 // 3.5

String msg = "Hi";
msg += ", Ada";           // "Hi, Ada"

int n;
if ((n = readValue()) > 0) { }   // assign inside expression

Notes

The implicit cast can hide overflow — by += 1 wraps
/= follows the variable's type, not the right side
Assigning inside a condition works but hurts readability

⚠ Common Mistakes

  • if (x = 5) — in Java this fails to compile for int, but if (flag = true) compiles and is always true
  • Using += on String inside a big loop creates many objects — use StringBuilder
  • Expecting i += 0.5 on an int to add half — it truncates back to int

✓ Tips & Best Practices

  • Use compound operators for counters and totals: sum += price
  • Avoid chained assignment for objects; all variables share one reference
  • Write if (flag) instead of comparing booleans to avoid =/== typos

Quick Summary

  • = — assign, returns the value
  • op= — update in place
  • Compound ops cast implicitly
  • String += — concatenates
