Collections Utility Class

Collections.sort · reverse · shuffle · max · min · frequency · unmodifiableList · synchronizedList · nCopies

Static Helpers for Collections

java.util.Collections (with an s) is a utility class of static methods that operate on or return collections: sorting, searching, shuffling, counting, building read-only or thread-safe wrappers, and creating empty or singleton collections. Don't confuse it with the Collection interface.

Notes

  • Most methods modify the list in place
  • unmodifiableX returns a read-only view, not a copy
  • List.copyOf (Java 10) gives a true immutable copy
  • synchronizedX wrappers lock every call

Common Operations

List<Integer> nums = new ArrayList<>(List.of(4, 1, 3, 1, 5));

Collections.sort(nums);                    // [1, 1, 3, 4, 5]
Collections.reverse(nums);                 // [5, 4, 3, 1, 1]
Collections.shuffle(nums);                 // random order
Collections.swap(nums, 0, 1);
Collections.max(nums);                     // 5
Collections.min(nums, Comparator.reverseOrder());   // 5
Collections.frequency(nums, 1);            // 2
Collections.rotate(nums, 2);               // shift right by 2
Collections.fill(nums, 0);                 // all zeros

List<String> blanks = Collections.nCopies(3, "-");    // [-, -, -]
List<String> empty = Collections.emptyList();
Set<String> one = Collections.singleton("only");

List<String> view = Collections.unmodifiableList(names);
view.add("x");                             // ✖ UnsupportedOperationException
names.add("x");                            // view now shows "x" too!

List<String> safe = Collections.synchronizedList(new ArrayList<>());
Collections.addAll(safe, "a", "b", "c");

Notes

max/min accept an optional comparator
rotate moves elements by a distance, wrapping around
Unmodifiable views reflect changes in the backing list

⚠ Common Mistakes

  • Assuming unmodifiableList is immutable — the original can still change it
  • Iterating a synchronizedList without holding its lock → ConcurrentModificationException
  • Collections.copy(dest, src) requires dest to already be at least as long as src

✓ Tips & Best Practices

  • Prefer List.of / List.copyOf for immutable data
  • Prefer ConcurrentHashMap / CopyOnWriteArrayList over synchronized wrappers
  • Return Collections.emptyList() or List.of() instead of null
