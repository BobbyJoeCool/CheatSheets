ActionListener · addActionListener · MouseListener · MouseAdapter · KeyListener · DocumentListener · SwingWorker · lambdas

Responding to User Actions

Swing components fire events (clicks, key presses, text changes) and call the listeners you register. Most listeners are interfaces with one method, so lambdas work well; multi-method listeners have adapter classes you can subclass. Listeners run on the EDT, so slow work must move to a SwingWorker.

Notes

  • ActionEvent fires for buttons, menu items, and Enter in text fields
  • Use DocumentListener to react to every text change
  • Adapters (MouseAdapter, KeyAdapter) let you override only what you need
  • Key bindings are more reliable than KeyListener

Listeners in Action

JButton save = new JButton("Save");
save.addActionListener(e -> saveFile());              // lambda listener

JLabel area = new JLabel("Click me");
area.addMouseListener(new MouseAdapter() {            // override only one
    public void mouseClicked(MouseEvent e) { area.setText("Clicked"); }
});

JTextField search = new JTextField(20);
search.getDocument().addDocumentListener(new DocumentListener() {
    public void insertUpdate(DocumentEvent e)  { filter(search.getText()); }
    public void removeUpdate(DocumentEvent e)  { filter(search.getText()); }
    public void changedUpdate(DocumentEvent e) { }
});

JButton load = new JButton("Load");
load.addActionListener(e -> new SwingWorker<String, Void>() {
    protected String doInBackground() { return slowDownload(); } // worker
    protected void done() {                                      // EDT
        try { area.setText(get()); }
        catch (Exception ex) { area.setText("Failed"); }
    }
}.execute());

Notes

MouseAdapter avoids writing five empty methods
DocumentListener catches typing, pasting, and deleting
doInBackground runs off the EDT; done returns to it
get() retrieves the background result

⚠ Common Mistakes

  • Calling slowDownload() directly in actionPerformed, freezing the UI
  • Updating labels from the doInBackground thread instead of done/process
  • Adding the same listener repeatedly (e.g., inside a refresh method), so it fires several times

✓ Tips & Best Practices

  • Use Action objects to share behavior between buttons and menus
  • Debounce search fields with a javax.swing.Timer
  • Keep listeners thin; call well-named methods

Quick Summary

  • Register listeners on components
  • Lambdas for single-method listeners
  • Adapters for multi-method ones
  • SwingWorker for slow work
