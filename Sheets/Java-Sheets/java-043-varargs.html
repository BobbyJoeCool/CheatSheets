Varargs

... · variable arguments · array parameter · last parameter · overload resolution · String.format · @SafeVarargs

Variable-Length Arguments

Varargs (Type... name) lets a method accept zero or more arguments of a type. Inside the method, the parameter is an ordinary array. Callers can pass separate values, nothing at all, or an existing array. String.format, List.of, and Arrays.asList all use varargs.

Notes

  • Only one varargs parameter, and it must be last
  • Varargs are chosen last in overload resolution
  • Passing null alone is ambiguous with an array
  • Generic varargs trigger "heap pollution" warnings

Under the JVM

  • Every call allocates an array: sum(1, 2, 3) is sum(new int[]{1, 2, 3})
  • Even sum() allocates an empty array
  • Generic varargs create an Object[], which is where heap-pollution warnings come from

Varargs in Use

static int sum(int... nums) {          // nums is int[]
    int total = 0;
    for (int n : nums) total += n;
    return total;
}
sum();                    // 0
sum(5);                   // 5
sum(1, 2, 3);             // 6
sum(new int[]{4, 5});     // 9  (array passes directly)

static String label(String prefix, Object... parts) {   // must be last
    return prefix + ": " + Arrays.toString(parts);
}
label("vals", 1, "two", 3.0);   // "vals: [1, two, 3.0]"

static int max(int first, int... rest) {   // require at least one
    int m = first;
    for (int r : rest) m = Math.max(m, r);
    return m;
}
max(7);                   // 7
// max();                 ✖ compile error: needs one argument

@SafeVarargs
static <T> List<T> listOf(T... items) { return List.of(items); }

Notes

sum() passes an empty array, never null
first, int... rest enforces a minimum count
@SafeVarargs asserts generic varargs are handled safely

Java Versions

  • 5 — varargs
  • 7 — @SafeVarargs
  • 9 — @SafeVarargs on private methods · fixed-arity List.of overloads

Idiomatic Java

  • Arrays.asList(1, 2, 3) → List.of(1, 2, 3)
  • log.info(String.format("...", x)) → log.info("... {}", x)
  • Generic T... you know is safe → @SafeVarargs on a static or final method

⚠ Common Mistakes

  • Overloading f(int...) and f(Integer...), which causes ambiguous calls
  • Calling f(null) — passes a null array, not an array containing null
  • Using varargs in performance-critical code; every call allocates an array

✓ Tips & Best Practices

  • Use first, rest... to require at least one argument
  • Provide fixed-arity overloads for common counts if performance matters (as List.of does)
  • Prefer List<T> parameters when callers already have collections

Quick Summary

  • Type... name — 0 or more args
  • Arrives as an array
  • Must be the last parameter
  • Lowest overload priority
