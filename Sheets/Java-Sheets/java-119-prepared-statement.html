PreparedStatement

PreparedStatement · ? placeholders · setString · setInt · SQL injection · batching · setNull · IN clause

Safe, Parameterized SQL

A PreparedStatement is SQL with ? placeholders whose values are sent separately from the query text. The database never interprets those values as SQL, which prevents SQL injection. Statements are also precompiled, so re-executing with new values is faster. Use one for every query that includes variable data.

Notes

  • Parameter indexes start at 1
  • Placeholders replace values only, not table or column names
  • setNull(i, Types.X) for SQL NULL

Injection vs Parameters

String user = request.getParameter("user");          // e.g. "x' OR '1'='1"

// ✖ Vulnerable: input becomes part of the SQL
String bad = "SELECT * FROM users WHERE name = '" + user + "'";

// ✔ Safe: input is only ever a value
String sql = "SELECT id, email FROM users WHERE name = ? AND active = ?";
try (PreparedStatement ps = conn.prepareStatement(sql)) {
    ps.setString(1, user);
    ps.setBoolean(2, true);
    try (ResultSet rs = ps.executeQuery()) {
        while (rs.next()) System.out.println(rs.getString("email"));
    }
}

try (var ps = conn.prepareStatement("INSERT INTO log(msg, at) VALUES (?,?)")) {
    for (String m : messages) {
        ps.setString(1, m);
        ps.setTimestamp(2, Timestamp.from(Instant.now()));
        ps.addBatch();                               // queue
    }
    int[] counts = ps.executeBatch();                // one round trip
}

Notes

The malicious string is treated as a plain name
Each ? is filled by position
addBatch + executeBatch inserts many rows efficiently

IN Clause With N Values

List<Long> ids = List.of(3L, 7L, 9L);
String qs = String.join(",",
    Collections.nCopies(ids.size(), "?"));
var ps = conn.prepareStatement(
    "SELECT * FROM product WHERE id IN (" + qs + ")");
for (int i = 0; i < ids.size(); i++)
    ps.setLong(i + 1, ids.get(i));

⚠ Common Mistakes

  • Concatenating user input into SQL, even "just for a quick test"
  • Trying to bind a table or column name with ? — validate against an allow-list instead
  • Using setInt(i, value) with a null Integer → NPE; use setObject or setNull

✓ Tips & Best Practices

  • Use setObject for java.time types (JDBC 4.2+)
  • Build IN (?, ?, ?) dynamically, never by concatenating values
  • Libraries like JDBI or jOOQ reduce boilerplate while staying safe

Quick Summary

  • ? placeholders + setX(i, v)
  • Stops SQL injection
  • Values only, not identifiers
  • addBatch / executeBatch
