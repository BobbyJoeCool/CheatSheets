Talking to Relational Databases

JDBC (Java Database Connectivity) is the standard API in java.sql for running SQL against relational databases. A vendor driver (PostgreSQL, MySQL, SQLite, H2…) on the classpath implements it. You open a Connection with a JDBC URL, create statements, execute SQL, and read rows from a ResultSet.

Notes

  • Drivers register automatically (JDBC 4+); no Class.forName needed
  • Connections, statements, and result sets must be closed
  • ResultSet column indexes start at 1
  • Use PreparedStatement for any user input (Sheet 119)

Connect, Query, Read

String url = "jdbc:postgresql://localhost:5432/shop";

try (Connection conn = DriverManager.getConnection(url, "app", "secret");
     Statement st = conn.createStatement();
     ResultSet rs = st.executeQuery("SELECT id, name, price FROM product")) {

    while (rs.next()) {                       // move to next row
        long id = rs.getLong("id");
        String name = rs.getString("name");
        BigDecimal price = rs.getBigDecimal(3);   // by index (1-based)
    }
} catch (SQLException e) {
    System.err.println(e.getSQLState() + ": " + e.getMessage());
}

Notes

Resources close in reverse order: rs, st, conn
rs.next() returns false after the last row
Read by column name or 1-based index
getSQLState gives a portable error code

⚠ Common Mistakes

  • Building SQL with string concatenation of user input → SQL injection
  • Forgetting to close connections → pool exhaustion or "too many connections"
  • Calling rs.getString(0) — indexes start at 1

✓ Tips & Best Practices

  • Use a connection pool in real apps (Sheet 120)
  • Keep credentials in environment variables, not code
  • Use H2 or Testcontainers for database tests
