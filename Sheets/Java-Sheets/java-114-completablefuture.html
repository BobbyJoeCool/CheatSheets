CompletableFuture

supplyAsync · thenApply · thenCompose · thenCombine · allOf · exceptionally · handle · join · async pipelines

Composable Async Pipelines

CompletableFuture<T> represents a result that will be available later and lets you chain what happens next without blocking: transform it, run another async step, combine several, or recover from errors. Tasks run on the common ForkJoinPool unless you pass your own executor.

Notes

  • thenApply — sync transform; thenCompose — async next step
  • join() throws unchecked CompletionException; get() throws checked
  • Pass an executor for blocking I/O work
  • Non-Async callbacks run on whichever thread completed the stage

Building a Pipeline

ExecutorService io = Executors.newFixedThreadPool(8);

var userF = CompletableFuture.supplyAsync(() -> loadUser(id), io);
var ordersF = CompletableFuture.supplyAsync(() -> loadOrders(id), io);

CompletableFuture<String> summary = userF
    .thenCombine(ordersF, (u, os) -> u.name() + ": " + os.size() + " orders")
    .thenApply(String::toUpperCase)
    .exceptionally(ex -> "unavailable (" + ex.getMessage() + ")");

summary.thenAccept(System.out::println);         // non-blocking callback
String s = summary.join();                       // block only at the edge

CompletableFuture<Profile> p = userF.thenCompose(u -> fetchProfileAsync(u));

List<CompletableFuture<Price>> quotes = shops.stream()
    .map(sh -> CompletableFuture.supplyAsync(() -> sh.quote(item), io))
    .toList();
CompletableFuture.allOf(quotes.toArray(CompletableFuture[]::new)).join();
Price best = quotes.stream().map(CompletableFuture::join)
                   .min(Comparator.comparing(Price::amount)).orElseThrow();

Notes

thenCombine merges two independent futures
exceptionally provides a fallback value
thenCompose flattens a future-returning function
allOf waits for many; then join each result

Chaining Methods

MethodInput → Output
thenApply(fn)T → U
thenAccept(fn)T → void
thenCompose(fn)T → CompletableFuture<U>
thenCombine(other, fn)(T, U) → V
exceptionally(fn)Throwable → T
handle(fn)(T, Throwable) → U

Starting & Combining

MethodPurpose
supplyAsync(supplier, ex)Async with result
runAsync(runnable)Async, no result
allOf(fs…)All complete
anyOf(fs…)First completes
orTimeout(n, unit)Fail after timeout

⚠ Common Mistakes

  • Calling join() right after supplyAsync, which makes it synchronous
  • Running blocking I/O on the common pool, starving other tasks
  • Using thenApply with a function that returns a future, producing CF<CF<T>>

✓ Tips & Best Practices

  • Block (join) only at the outermost layer
  • Add orTimeout to remote calls
  • With virtual threads (Sheet 116), plain blocking code is often simpler
