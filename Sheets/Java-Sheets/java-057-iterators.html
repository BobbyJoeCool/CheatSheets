Iterators & Iterables

Iterator · hasNext · next · remove · ListIterator · Iterable · forEachRemaining · fail-fast

Walking a Collection

An Iterator steps through a collection one element at a time with hasNext() and next(), and can safely remove the last element returned. Any class that implements Iterable (one method: iterator()) works with the enhanced for loop. Collection iterators are fail-fast: changing the collection behind their back throws ConcurrentModificationException.

Notes

  • next() past the end throws NoSuchElementException
  • remove() may be called once per next()
  • ListIterator moves both ways and supports set and add
  • Implement Iterable<T> to make your own types for-each friendly

Under the JVM

  • Fail-fast is best-effort: modCount is checked in next(), not locked
  • CopyOnWriteArrayList and concurrent maps iterate a snapshot and never throw CME
  • The iterator object is often removed by escape analysis in hot loops

Using & Implementing

Iterator<String> it = names.iterator();
while (it.hasNext()) {
    String n = it.next();
    if (n.isBlank()) it.remove();          // safe removal
}

ListIterator<String> li = names.listIterator();
while (li.hasNext()) {
    li.set(li.next().toUpperCase());       // replace in place
}

class Range implements Iterable<Integer> {   // custom iterable
    private final int start, end;
    Range(int s, int e) { start = s; end = e; }
    public Iterator<Integer> iterator() {
        return new Iterator<>() {
            int cur = start;
            public boolean hasNext() { return cur < end; }
            public Integer next() {
                if (!hasNext()) throw new NoSuchElementException();
                return cur++;
            }
        };
    }
}
for (int i : new Range(1, 4)) System.out.print(i);   // 123

Notes

it.remove() is the only safe removal during iteration
set replaces the element last returned by next
An anonymous class implements the iterator inline
Range now works in any for-each loop

Java Versions

  • 1.0 — Enumeration · 1.2 — Iterator
  • 5 — Iterable powers for-each
  • 8 — forEachRemaining · removeIf · Spliterator · 9 — Enumeration.asIterator()

Idiomatic Java

  • Looping a legacy Enumeration → e.asIterator() or Collections.list(e)
  • Hand-written Iterator class over an internal list → return list.iterator() (or an unmodifiable view's)

⚠ Common Mistakes

  • Calling next() twice per loop pass and skipping elements
  • Calling list.remove(x) instead of it.remove() during iteration
  • Calling remove() twice without an intervening next() → IllegalStateException

✓ Tips & Best Practices

  • Prefer removeIf for simple conditional removal
  • Implement Iterable instead of exposing internal lists
  • Use Spliterator / streams if you need parallel traversal

Quick Summary

  • hasNext() / next() — step through
  • it.remove() — safe delete
  • ListIterator — two-way + set
  • Iterable — enables for-each
