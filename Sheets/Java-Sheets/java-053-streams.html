Streams

stream() · pipeline · intermediate · terminal · lazy evaluation · IntStream · Stream.of · toList

Declarative Data Pipelines

A stream is a sequence of elements processed through a pipeline: a source (a collection, array, or generator), zero or more intermediate operations (filter, map, sorted) that build a recipe, and one terminal operation (toList, count, forEach) that runs it. Streams are lazy and single-use, and they never modify the source.

Notes

  • Nothing executes until a terminal operation is called
  • A stream can be consumed only once
  • IntStream/LongStream/DoubleStream avoid boxing
  • .toList() (Java 16+) returns an unmodifiable list

Under the JVM

  • Nothing runs until the terminal operation
  • Stages are fused: each element flows through the whole pipeline with no intermediate lists
  • sorted() is a barrier that buffers every element before passing any on

Building Pipelines

List<String> names = List.of("Ada", "alan", "Grace", "Al");

List<String> result = names.stream()        // source
    .filter(n -> n.length() > 2)            // intermediate
    .map(String::toUpperCase)               // intermediate
    .sorted()                               // intermediate
    .toList();                              // terminal → [ADA, ALAN, GRACE]

long count = names.stream().filter(n -> n.startsWith("A")).count();  // 2
Stream.of(3, 1, 2).sorted().toList();       // [1, 2, 3]
Arrays.stream(new int[]{4, 5, 6}).sum();    // 15
IntStream.rangeClosed(1, 5).map(i -> i * i).toArray();   // [1,4,9,16,25]
Stream.iterate(1, x -> x * 2).limit(5).toList();         // [1,2,4,8,16]

Stream<String> s = names.stream();
s.count();
s.count();                                  // ✖ IllegalStateException

names.stream().peek(System.out::println)    // lazy: prints nothing…
     .map(String::length);                  // …no terminal op

Notes

Read top to bottom: what, then how, then collect
rangeClosed includes the upper bound; range excludes it
iterate + limit builds finite sequences
peek is for debugging only

Java Versions

  • 8 — streams
  • 9 — takeWhile · dropWhile · Stream.ofNullable
  • 16 — Stream.toList() · 24 — gather(...) for custom stages

Idiomatic Java

  • .collect(Collectors.toList()) → .toList() (unmodifiable result)
  • stream().filter(p).count() > 0 → anyMatch(p)
  • list.stream().forEach(...) → list.forEach(...)

⚠ Common Mistakes

  • Reusing a stream after a terminal operation
  • Forgetting a terminal operation and wondering why nothing happens
  • Using forEach to add to an external list; use collect/toList instead

✓ Tips & Best Practices

  • Use mapToInt(...).sum() instead of reduce for numeric totals
  • Keep lambdas short; extract complex logic to methods
  • Use a plain loop when it's clearer, especially with early exits or checked exceptions

Quick Summary

  • Source → intermediate → terminal
  • Lazy, single-use
  • Never modifies source
  • toList() — collect results
