Enums

enum · constants · values() · valueOf · ordinal · fields · constructor · EnumMap · EnumSet · switch

Fixed Sets of Constants

An enum defines a type with a fixed set of named instances, like days of the week or order states. Enums are full classes: they can have fields, constructors, methods, and can implement interfaces. They're type-safe, work in switch, and compare safely with ==.

Notes

  • Enum constructors are always private
  • Each constant is a singleton
  • valueOf("X") throws IllegalArgumentException if no match
  • Prefer EnumMap/EnumSet for enum-keyed data

Under the JVM

  • An enum is a final class extending java.lang.Enum; each constant is one static instance built in <clinit>
  • values() returns a fresh array clone every call — cache it in hot code
  • EnumSet is a bit vector in a long; EnumMap is an array indexed by ordinal()

Enum Features

public enum Planet {
    MERCURY(3.303e23, 2.4397e6),
    EARTH(5.976e24, 6.37814e6);           // constants call the constructor

    private final double mass, radius;
    Planet(double m, double r) { mass = m; radius = r; }
    public double gravity() { return 6.67e-11 * mass / (radius * radius); }
}
Planet.EARTH.gravity();          // ≈ 9.8

enum Status { NEW, PAID, SHIPPED }
Status s = Status.valueOf("PAID");   // PAID
s.name();                             // "PAID"
s.ordinal();                          // 1
Status.values();                      // [NEW, PAID, SHIPPED]
s == Status.PAID;                     // true

String label = switch (s) {           // exhaustive, no default needed
    case NEW -> "Awaiting payment";
    case PAID -> "Preparing";
    case SHIPPED -> "On the way";
};
EnumSet<Status> open = EnumSet.of(Status.NEW, Status.PAID);
EnumMap<Status, Integer> counts = new EnumMap<>(Status.class);

Notes

Constants must come first, ending with ; if more members follow
ordinal() is the declaration position — don't persist it
Switch on enums needs no default when every constant is covered

Java Versions

  • 5 — enums, EnumMap, EnumSet
  • 17 — enums in exhaustive switches with sealed types
  • 21 — qualified enum constants in case labels

Idiomatic Java

  • HashMap<Day, X> → new EnumMap<>(Day.class)
  • switch (this) inside the enum → a field or a constant-specific method body
  • valueOf(input) wrapped in try / catch → a static Optional<Planet> parse(String) helper

⚠ Common Mistakes

  • Storing ordinal() in a database; adding a constant later shifts every value
  • Using int or String constants instead of an enum, losing type safety
  • Calling valueOf on user input without handling the exception

✓ Tips & Best Practices

  • Store name() (or a dedicated code field) when persisting
  • Put behavior in the enum instead of switching on it everywhere
  • Use enums for singletons: enum Config { INSTANCE; }
