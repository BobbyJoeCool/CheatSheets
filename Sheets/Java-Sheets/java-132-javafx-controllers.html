The Logic Behind FXML

An FXML controller is a plain class whose @FXML-annotated fields receive the nodes marked with fx:id, and whose @FXML methods handle events wired with #method. After injection, the loader calls initialize(), the place to set up bindings and listeners. Controllers keep event logic out of the layout file.

Notes

  • Fields and methods may be private when annotated @FXML
  • The controller needs a public no-arg constructor (unless you set a factory)
  • initialize() runs after all fx:id fields are injected

LoginController.java

public class LoginController {
    @FXML private TextField userField;
    @FXML private PasswordField passField;
    @FXML private Label errorLabel;   private AuthService auth;

    @FXML
    private void initialize() {                       // after injection
        errorLabel.setVisible(false);
        userField.textProperty()
                 .addListener((o, a, b) -> errorLabel.setVisible(false));
    }

    @FXML
    private void handleLogin(ActionEvent e) {         // onAction="#handleLogin"
        if (auth.login(userField.getText(), passField.getText())) {
            ((Stage) userField.getScene().getWindow()).close();
        } else {
            errorLabel.setText("Invalid login"); errorLabel.setVisible(true);
        }
    }

    public void setAuthService(AuthService a) { auth = a; }   // pass data
}

var loader = new FXMLLoader(getClass().getResource("login.fxml"));
Parent root = loader.load();
loader.<LoginController>getController().setAuthService(authService);

Notes

Field names must match fx:id values exactly
Pass dependencies after load() with a setter, or use a controller factory

⚠ Common Mistakes

  • Using controller fields in the constructor — they're still null; use initialize()
  • Mismatched names between fx:id and the field
  • Putting business logic in controllers instead of services or models

✓ Tips & Best Practices

  • Keep controllers thin: UI wiring only
  • Use a shared view-model with properties for multi-screen state

Quick Summary

  • @FXML fields ← fx:id
  • @FXML methods ← #handler
  • initialize() — post-injection setup
  • Pass data via setters or factories
