ExecutorService

Executors · newFixedThreadPool · submit · Future · invokeAll · shutdown · awaitTermination · Callable · ScheduledExecutorService

Thread Pools

An ExecutorService manages a pool of threads and a queue of tasks, so you submit work instead of creating threads yourself. submit returns a Future for retrieving the result later. Pools must be shut down when you're done. Since Java 19 ExecutorService is AutoCloseable, so try-with-resources waits and shuts it down for you.

Notes

  • Callable<T> returns a value and may throw; Runnable doesn't
  • future.get() blocks until the result is ready
  • Exceptions inside tasks surface as ExecutionException from get()
  • Size CPU-bound pools near Runtime.getRuntime().availableProcessors()

Submitting Tasks

try (ExecutorService pool = Executors.newFixedThreadPool(4)) {
    Future<Integer> f = pool.submit(() -> expensiveCalc());   // Callable
    pool.submit(() -> System.out.println("fire and forget")); // Runnable

    int result = f.get();                         // blocks
    Integer maybe = f.get(2, TimeUnit.SECONDS);   // TimeoutException if slow

    List<Callable<String>> jobs = List.of(() -> fetch("a"), () -> fetch("b"));
    for (Future<String> r : pool.invokeAll(jobs)) // run all, wait for all
        System.out.println(r.get());
    String fastest = pool.invokeAny(jobs);        // first successful result
}                                                 // close(): shutdown + wait

ScheduledExecutorService sched = Executors.newScheduledThreadPool(1);
sched.scheduleAtFixedRate(() -> ping(), 0, 30, TimeUnit.SECONDS);
// later:
sched.shutdown();
if (!sched.awaitTermination(5, TimeUnit.SECONDS)) sched.shutdownNow();

Notes

try-with-resources (Java 19+) calls close() = shutdown + await
invokeAll returns futures in the same order as tasks
shutdownNow interrupts running tasks
Scheduled pools run periodic jobs

⚠ Common Mistakes

  • Never calling shutdown() — the JVM may not exit
  • Ignoring the Future of a task that throws, so the exception vanishes
  • Using newCachedThreadPool for unbounded bursts of blocking work → thousands of threads

✓ Tips & Best Practices

  • Use try-with-resources with executors on Java 19+
  • Prefer CompletableFuture (Sheet 114) for chaining async steps
  • Name threads with a custom ThreadFactory for clearer logs

Quick Summary

  • Pool + task queue
  • submit → Future
  • invokeAll / invokeAny
  • Always shut down
