Build and Dependency Management

Maven builds Java projects from a declarative pom.xml file. You list dependencies by coordinates (groupId:artifactId:version) and Maven downloads them from Maven Central. Builds follow a fixed lifecycle (compile → test → package → install), and plugins do the work at each phase.

Notes

  • Convention: src/main/java, src/test/java, target/ output
  • Local repository cache: ~/.m2/repository
  • Use the Maven Wrapper (./mvnw) to pin the Maven version
  • Search packages at central.sonatype.com

pom.xml

<project xmlns="http://maven.apache.org/POM/4.0.0">
  <modelVersion>4.0.0</modelVersion>
  <groupId>com.acme</groupId>
  <artifactId>billing</artifactId>
  <version>1.0.0</version>
  <properties>
    <maven.compiler.release>21</maven.compiler.release>
  </properties>
  <dependencies>
    <dependency>
      <groupId>com.google.code.gson</groupId>
      <artifactId>gson</artifactId>
      <version>2.11.0</version>
    </dependency>
    <dependency>
      <groupId>org.junit.jupiter</groupId>
      <artifactId>junit-jupiter</artifactId>
      <version>5.11.0</version>
      <scope>test</scope>
    </dependency>
  </dependencies>
</project>

Notes

groupId — organization; artifactId — project name
maven.compiler.release — target Java version
test scope keeps JUnit out of the final JAR
-SNAPSHOT versions mean "in development"

mvn Commands

CommandDoes
mvn compileCompile main code
mvn testCompile + run tests
mvn packageBuild JAR in target/
mvn installPut JAR in ~/.m2
mvn dependency:treeShow all dependencies

Dependency Scopes

ScopeAvailable at
compile (default)Compile + runtime
testTests only
providedCompile; supplied at runtime
runtimeRuntime only (e.g., JDBC driver)

⚠ Common Mistakes

  • Forgetting <scope>test</scope> and shipping test libraries
  • Two versions of one library via transitive dependencies; check dependency:tree
  • Running mvn package and expecting a runnable fat JAR — that needs the Shade or Assembly plugin

✓ Tips & Best Practices

  • Put versions in <properties> and reuse them
  • Use a BOM (<dependencyManagement>) for aligned versions
  • mvn -q -DskipTests package for quick local builds

Quick Summary

  • pom.xml — project definition
  • groupId:artifactId:version
  • compile → test → package → install
  • Scopes control the classpath
