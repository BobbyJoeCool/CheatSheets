Lombok

@Getter · @Setter · @Data · @Value · @Builder · @NoArgsConstructor · @AllArgsConstructor · @Slf4j · annotation processing

Generated Boilerplate

Lombok is an annotation processor that generates boilerplate at compile time: getters, setters, constructors, equals/hashCode, toString, builders, and loggers. Your source stays short while the compiled class contains the full methods. IDEs need the Lombok plugin (built into IntelliJ) to see generated members.

Notes

  • Add as compileOnly + annotationProcessor (Gradle) or provided (Maven)
  • Generated code doesn't appear in your source files
  • Records (Sheet 72) cover many @Value use cases natively

Before → After

@Data                                 // getters, setters, equals,
public class Customer {               // hashCode, toString, required-args ctor
    private Long id;
    private String name;
    private String email;
}

@Value                                // immutable: private final fields,
@Builder                              // getters, all-args ctor, no setters
public class Address {
    String street;
    String city;
    @Builder.Default String country = "US";
}

Address a = Address.builder().street("1 Main").city("Austin").build();
a.getCity();                          // "Austin"

@Slf4j @RequiredArgsConstructor       // logger + ctor for final fields
public class OrderService { private final OrderRepository repo; }

Notes

@Data = @Getter @Setter @ToString @EqualsAndHashCode @RequiredArgsConstructor
@Value makes the class final and its fields private final
@RequiredArgsConstructor enables constructor injection
@Builder.Default keeps a field's default in builders

⚠ Common Mistakes

  • @Data on JPA entities — generated equals/hashCode/toString can trigger lazy loading and loops
  • Forgetting annotation-processor configuration, so builds fail with "cannot find symbol"
  • @EqualsAndHashCode on a subclass without callSuper = true

✓ Tips & Best Practices

  • Prefer records for simple immutable data
  • On entities, use @Getter @Setter and write equals by ID yourself
  • Use @Builder for classes with many optional fields

Quick Summary

  • Compile-time code generation
  • @Data — mutable bean
  • @Value — immutable class
  • @Builder @Slf4j
