Sheet 031

Throws & Checked Exceptions

throw · throws · checked · unchecked · RuntimeException · IOException · rethrow · cause chaining

Throwing and Declaring

throw raises an exception object; throws in a method signature declares which checked exceptions the method may pass to its caller. Checked exceptions (subclasses of Exception but not RuntimeException) must be caught or declared, which the compiler enforces. Unchecked exceptions (RuntimeException and its subclasses) need neither.

Notes

  • Checked = recoverable conditions outside your control (files, network)
  • Unchecked = programming errors (null, bad index, bad argument)
  • Lambdas can't throw checked exceptions through standard functional interfaces
  • Wrap a low-level exception with a cause to keep the stack trace

Under the JVM

  • Checked exceptions are a compiler rule only; the JVM never checks throws
  • Code from other JVM languages (Kotlin, Groovy) can throw checked exceptions with no throws clause
  • Lambdas for Function / Supplier can't throw checked exceptions because those interfaces don't declare any

throw, throws, Rethrow

public void setAge(int age) {
    if (age < 0)
        throw new IllegalArgumentException("age must be ≥ 0: " + age);
    this.age = age;
}

public String load(Path p) throws IOException {   // declare
    return Files.readString(p);                     // checked
}

public Config readConfig(Path p) {
    try {
        return parse(load(p));
    } catch (IOException e) {
        throw new UncheckedIOException("Can't read " + p, e);  // wrap
    }
}

Notes

throw new … — create and raise in one step
throws IOException — caller must handle it
Passing e as the cause preserves the original trace
UncheckedIOException wraps IOException for lambdas

Java Versions

  • 1.0 — checked vs unchecked, throw, throws
  • 1.4 — exception chaining: new X(msg, cause) · getCause()
  • 8 — UncheckedIOException

Idiomatic Java

  • throw new RuntimeException(ioe) → throw new UncheckedIOException(ioe)
  • throws IOException, FileNotFoundException → just IOException (the subclass is redundant)
  • IllegalArgumentException for an object in the wrong state → IllegalStateException

⚠ Common Mistakes

  • throws Exception on every method — callers can no longer tell what really fails
  • Wrapping without a cause: new RuntimeException(e.getMessage()) loses the stack trace
  • Catching checked exceptions just to print them and continue in a broken state

✓ Tips & Best Practices

  • Use Objects.requireNonNull(x, "x") to validate arguments
  • Prefer standard exceptions before writing custom ones
  • Include the bad value in the message

Quick Summary

  • throw — raise an exception
  • throws — declare checked exceptions
  • Checked: catch or declare
  • Wrap with a cause
