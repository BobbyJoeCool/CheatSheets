Finally & Try-with-Resources

finally · try-with-resources · AutoCloseable · close() · suppressed exceptions · resource cleanup

Guaranteed Cleanup

A finally block runs after try/catch no matter what: normal completion, exception, or return. Java 7 added try-with-resources, which declares resources in the try header and closes them automatically in reverse order. Any class implementing AutoCloseable works. It replaces almost every manual finally { close(); }.

Notes

  • finally is skipped only by System.exit() or a JVM crash
  • Resources close in reverse declaration order
  • Close-time exceptions are attached as suppressed

finally vs try-with-resources

// Old style
BufferedReader br = null;
try {
    br = new BufferedReader(new FileReader("data.txt"));
    return br.readLine();
} catch (IOException e) {
    return null;
} finally {
    if (br != null) try { br.close(); } catch (IOException ignored) { }
}

// Modern: try-with-resources
try (var br = new BufferedReader(new FileReader("data.txt"));
     var out = new PrintWriter("copy.txt")) {
    out.println(br.readLine());
}   // out closes, then br — automatically

// Your own resource
class Timer implements AutoCloseable {
    long start = System.nanoTime();
    public void close() {
        System.out.println((System.nanoTime() - start) + " ns");
    }
}
try (var t = new Timer()) { work(); }   // prints elapsed time

Notes

Resources are separated by ; in the header
No catch is required with try-with-resources
close() runs even when work() throws
Get hidden close errors with e.getSuppressed()

Execution Order

ScenarioOrder
No exceptiontry → finally
Caught exceptiontry → catch → finally
Uncaught exceptiontry → finally → propagate
return in trytry (value saved) → finally → return

⚠ Common Mistakes

  • Returning from finally — it overrides the try result and swallows exceptions
  • Forgetting to close a Files.lines() stream; wrap it in try-with-resources
  • Using try-with-resources on System.in Scanners closes standard input permanently

✓ Tips & Best Practices

  • Use try-with-resources for anything with a close() method
  • Keep finally for non-resource cleanup like unlocking (lock.unlock())
  • Implement AutoCloseable on your own classes that hold resources

Quick Summary

  • finally — always runs
  • try (res) — auto-close
  • Reverse close order
  • AutoCloseable — opt in
