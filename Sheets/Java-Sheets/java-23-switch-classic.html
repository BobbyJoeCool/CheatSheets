Switch — Classic

switch · case · break · default · fall-through · String switch · enum switch

The Classic Switch Statement

A switch statement compares one value against a list of case labels and jumps to the match. Without a break, execution falls through into the next case, which is occasionally useful and frequently a bug. default handles every unmatched value. This colon-style form works in every Java version.

Notes

  • Supported types: int, char, byte, short, wrappers, String, enum
  • Not allowed: long, float, double, boolean (before Java 21 patterns)
  • Case labels must be compile-time constants
  • switch on a null String throws NPE

Classic Syntax

int day = 3;
String name;
switch (day) {
    case 1:
        name = "Mon";
        break;
    case 2:
        name = "Tue";
        break;
    case 3:
        name = "Wed";      // ← match
        break;             // exits the switch
    default:
        name = "Other";
}

switch (month) {           // intentional fall-through grouping
    case 12: case 1: case 2:
        season = "Winter"; break;
    case 6: case 7: case 8:
        season = "Summer"; break;
    default:
        season = "Spring/Fall";
}

Notes

break — leave the switch
Stacked labels share one body
default can appear anywhere but belongs last
Enum cases use bare names: case RED:

Fall-Through Example

Codex = 1 prints
case 1: print("A");A
case 2: print("B");B (fell through)
case 3: print("C"); break;C
default: print("D");not reached

⚠ Common Mistakes

  • Missing break causes the next case's code to run too
  • Using switch on a possibly null String — check for null first
  • Duplicate case values don't compile; neither do variables as labels

✓ Tips & Best Practices

  • Comment intentional fall-through: // fall through
  • Prefer arrow syntax (Sheet 24) in Java 14+ to make fall-through impossible
  • Always include default, even if it just throws

Quick Summary

  • switch (x) { case v: … break; }
  • No break → fall-through
  • default — no match
  • Constants only as labels
