Polymorphism

polymorphism · upcasting · downcasting · instanceof · dynamic dispatch · ClassCastException · pattern matching

One Interface, Many Forms

Polymorphism means code written against a parent type or interface works with any subtype. A List<Shape> can hold circles and squares, and calling area() runs each object's own version. Upcasting (child → parent) is automatic; downcasting (parent → child) needs a check with instanceof or risks ClassCastException.

Notes

  • Variable type controls which methods you can call
  • Object type controls which implementation runs
  • Java 16+ pattern matching: if (s instanceof Circle c)
  • Prefer polymorphic methods over chains of instanceof

Polymorphism at Work

interface Shape { double area(); }
record Circle(double r) implements Shape {
    public double area() { return Math.PI * r * r; }
}
record Square(double side) implements Shape {
    public double area() { return side * side; }
}

List<Shape> shapes = List.of(new Circle(1), new Square(2));
double total = 0;
for (Shape s : shapes) total += s.area();    // each runs its own area()

Shape s = new Circle(2);        // upcast (automatic)
// s.r();                       ✖ Shape has no r()
if (s instanceof Circle c) {    // safe downcast + bind
    System.out.println(c.r());  // 2.0
}
Square sq = (Square) s;         // ✖ ClassCastException at runtime

String info = switch (s) {      // Java 21 pattern switch
    case Circle c -> "circle r=" + c.r();
    case Square q -> "square " + q.side();
    default -> "unknown";
};

Notes

The loop never checks types; dispatch picks the method
instanceof Circle c tests and casts in one step
An explicit cast compiles but fails if the type is wrong

⚠ Common Mistakes

  • Downcasting without checking → ClassCastException
  • Long if (x instanceof A) … else if (x instanceof B) chains instead of an overridden method
  • Calling subclass-only methods through a parent-typed variable — compile error

✓ Tips & Best Practices

  • Program to interfaces: List<Shape>, not ArrayList<Circle>
  • Use sealed types + pattern switch for exhaustive type handling
  • Put type-specific behavior in the types themselves

Quick Summary

  • Parent type, child behavior
  • Upcast: automatic
  • Downcast: instanceof first
  • Dispatch by runtime type
