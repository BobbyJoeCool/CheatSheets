Threads

Thread · Runnable · start · run · join · sleep · interrupt · daemon · thread states · race condition

Running Code Concurrently

A thread is an independent path of execution inside a program. You create one by passing a Runnable (or lambda) to Thread and calling start(), which runs the task alongside the calling thread. join() waits for a thread to finish. Threads share memory, which makes them powerful and also the source of race conditions.

Notes

  • Call start(), not run(); run() executes on the current thread
  • A thread can be started only once
  • The JVM exits when only daemon threads remain
  • Prefer executors (Sheet 113) over creating threads by hand

Creating & Coordinating Threads

Runnable task = () ->
    System.out.println(Thread.currentThread().getName() + " running");
Thread t1 = new Thread(task, "worker-1");
Thread t2 = Thread.ofPlatform().name("worker-2").start(task);   // Java 21
t1.start();
t1.join();                          // wait for t1
t2.join();

Thread sleeper = new Thread(() -> {
    try {
        Thread.sleep(5_000);
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();     // restore flag
        System.out.println("woken early");
    }
});
sleeper.start();
sleeper.interrupt();                // politely ask it to stop

int[] count = {0};                  // ✖ race condition demo
Runnable inc = () -> { for (int i = 0; i < 10_000; i++) count[0]++; };
// two threads running inc → total is usually < 20_000

Notes

Output order between threads is unpredictable
interrupt() sets a flag; blocking calls throw InterruptedException
count[0]++ is read-modify-write: not atomic
Fixes: synchronized, AtomicInteger (Sheet 115)

⚠ Common Mistakes

  • Calling run() instead of start() — nothing runs in parallel
  • Swallowing InterruptedException without restoring the interrupt flag
  • Sharing mutable data between threads without synchronization

✓ Tips & Best Practices

  • Use ExecutorService or virtual threads instead of raw Thread
  • Give threads meaningful names for debugging
  • Prefer immutable data shared between threads

Quick Summary

  • new Thread(runnable).start()
  • join() — wait
  • interrupt() — cooperative stop
  • Shared state needs synchronization
