Synchronization & Locks

synchronized · volatile · ReentrantLock · ReadWriteLock · AtomicInteger · ConcurrentHashMap · deadlock · happens-before

Safe Access to Shared State

When threads share mutable data, you must coordinate access. synchronized lets only one thread at a time run a block guarded by the same lock, and guarantees visibility of changes. ReentrantLock adds timeouts and fairness. Atomic classes and concurrent collections often avoid explicit locking entirely.

Notes

  • volatile guarantees visibility, not atomicity
  • Always unlock a Lock in finally
  • Deadlock: two threads each waiting for the other's lock
  • Prefer higher-level tools over wait/notify

Four Ways to Protect a Counter

class SyncCounter {                                  // 1. synchronized
    private int n;
    public synchronized void inc() { n++; }
    public synchronized int get() { return n; }
}

class LockCounter {                                  // 2. explicit lock
    private final ReentrantLock lock = new ReentrantLock();
    private int n;
    public void inc() {
        lock.lock();
        try { n++; } finally { lock.unlock(); }
    }
}

AtomicInteger hits = new AtomicInteger();            // 3. atomic
hits.incrementAndGet();
hits.updateAndGet(x -> Math.min(x + 5, 100));

ConcurrentHashMap<String, Integer> counts = new ConcurrentHashMap<>();   // 4.
counts.merge("page", 1, Integer::sum);               // atomic per key

private volatile boolean running = true;             // visibility flag
public void stop() { running = false; }

Notes

synchronized methods lock on this
lock/unlock must be balanced with try/finally
merge on ConcurrentHashMap is atomic
volatile is right for a simple stop flag

⚠ Common Mistakes

  • Assuming volatile int x; x++ is thread-safe — it isn't
  • Synchronizing reads but not writes (or vice versa)
  • Synchronizing on a mutable or public object like a String literal

✓ Tips & Best Practices

  • Prefer immutability and confinement over locks
  • Use java.util.concurrent collections instead of Collections.synchronizedX
  • Virtual threads (Java 21–23) pinned on synchronized; use ReentrantLock there or Java 24+

Quick Summary

  • synchronized — mutual exclusion
  • ReentrantLock — flexible lock
  • Atomic* — lock-free counters
  • volatile — visibility only
