Comparable & Comparator

Comparable · compareTo · Comparator · compare · comparing · thenComparing · reversed · nullsFirst · natural order

Defining Order

Comparable gives a class a single natural order by implementing compareTo inside the class. Comparator defines an order *outside* the class, so one type can be sorted many ways. Both return a negative number, zero, or a positive number for less than, equal, or greater than.

Notes

  • compareTo should be consistent with equals
  • Comparator.comparing builds comparators from key extractors
  • Avoid subtraction (a - b); it overflows — use Integer.compare
  • TreeSet/TreeMap treat compare-equal items as duplicates

Both Approaches

public record Employee(String name, String dept, int age, Double rating)
        implements Comparable<Employee> {
    @Override
    public int compareTo(Employee o) {            // natural order: by name
        return name.compareTo(o.name);
    }
}

Collections.sort(staff);                          // uses compareTo

Comparator<Employee> byAge = Comparator.comparingInt(Employee::age);
staff.sort(byAge);                                // youngest first
staff.sort(byAge.reversed());                     // oldest first

staff.sort(Comparator.comparing(Employee::dept)
        .thenComparing(Employee::age, Comparator.reverseOrder())
        .thenComparing(Employee::name));

staff.sort(Comparator.comparing(Employee::rating,
        Comparator.nullsLast(Comparator.naturalOrder())));   // null-safe

Optional<Employee> oldest = staff.stream().max(byAge);

Notes

comparingInt avoids boxing
thenComparing breaks ties in order
nullsLast puts null keys at the end instead of throwing
Comparators also work with max, min, sorted, TreeMap

⚠ Common Mistakes

  • return a.age - b.age; overflows for large values; use Integer.compare
  • Comparators that never tie-break, so TreeSet drops "equal" elements
  • Calling .reversed() in the middle of a chain and reversing everything before it

✓ Tips & Best Practices

  • Implement Comparable only when there's one obvious order
  • Build comparators declaratively with comparing + thenComparing
  • Store common comparators as static final constants

Quick Summary

  • Comparable — natural order, in class
  • Comparator — external, many orders
  • −, 0, + return values
  • comparing().thenComparing()
