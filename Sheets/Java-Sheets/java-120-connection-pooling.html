Connection Pooling (HikariCP)

HikariCP · DataSource · HikariConfig · maximumPoolSize · connectionTimeout · leak detection · pool sizing

Reusing Database Connections

Opening a database connection is slow (network handshake, authentication). A connection pool keeps a set of open connections and lends them out; calling close() returns the connection to the pool instead of closing it. HikariCP is the fastest, most common pool and the default in Spring Boot.

Notes

  • Artifact: com.zaxxer:HikariCP
  • Code depends on javax.sql.DataSource, not on Hikari directly
  • Create one pool per database for the whole application
  • Close the pool on application shutdown

Configuring HikariCP

HikariConfig cfg = new HikariConfig();
cfg.setJdbcUrl("jdbc:postgresql://localhost:5432/shop");
cfg.setUsername(System.getenv("DB_USER"));
cfg.setPassword(System.getenv("DB_PASS"));
cfg.setMaximumPoolSize(10);
cfg.setMinimumIdle(2);
cfg.setConnectionTimeout(5_000);          // ms to wait for a free connection
cfg.setLeakDetectionThreshold(30_000);    // warn if held > 30 s
cfg.setPoolName("shop-pool");

HikariDataSource ds = new HikariDataSource(cfg);   // app-wide singleton

try (Connection conn = ds.getConnection();          // borrow
     var ps = conn.prepareStatement("SELECT count(*) FROM product");
     var rs = ps.executeQuery()) {
    rs.next();
    System.out.println(rs.getLong(1));
}                                                    // close() = return to pool

Runtime.getRuntime().addShutdownHook(new Thread(ds::close));

Notes

getConnection() blocks until a connection is free or the timeout passes
Leak detection logs a stack trace for unreturned connections
ds.close() shuts down the whole pool

⚠ Common Mistakes

  • Creating a new HikariDataSource per request
  • Forgetting to close borrowed connections — the pool runs dry and requests time out
  • Setting the pool huge "for performance"; databases slow down with too many connections

✓ Tips & Best Practices

  • Load settings from a properties file or environment
  • Enable leak detection in development
  • Expose pool metrics (Micrometer) to see waits and usage

Quick Summary

  • Pool = reuse open connections
  • HikariCP — fast default
  • ds.getConnection() / close() returns it
  • One pool per database
