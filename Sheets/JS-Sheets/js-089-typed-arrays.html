Sheet 089

Typed Arrays & Binary Data

ArrayBuffer · Uint8Array · DataView · TextEncoder · TextDecoder · endianness

Overview

An ArrayBuffer is a fixed-size block of raw bytes. You read and write it through views: typed arrays like Uint8Array or Float32Array treat it as a list of fixed-width numbers, and DataView reads mixed types at any offset with explicit endianness. TextEncoder/TextDecoder convert between strings and UTF-8 bytes.

Notes

  • Typed arrays have a fixed length and a single element type
  • Values outside range wrap (Uint8Array) or clamp (Uint8ClampedArray)
  • Several views can share one buffer
  • Node's Buffer is a Uint8Array subclass

Bytes, views, encoding

const buf = new ArrayBuffer(8);            // 8 zeroed bytes
const bytes = new Uint8Array(buf);
bytes[0] = 255;  bytes[1] = 256;           // 255, 0 (wraps)
new Uint8ClampedArray([300, -5]);          // [255, 0]

const floats = new Float32Array([1.5, 2.5]);
floats.byteLength;                         // 8
floats.map(x => x * 2);                    // Float32Array [3, 5]

const view = new DataView(buf);
view.setUint16(0, 0x1234);                 // big-endian by default
view.getUint8(0).toString(16);             // "12"
view.getUint16(0, true).toString(16);      // "3412" (little-endian)

const enc = new TextEncoder().encode("héllo");  // Uint8Array(6)
new TextDecoder().decode(enc);             // "héllo"

const hex = [...enc].map(b => b.toString(16).padStart(2, "0")).join("");
// "68c3a96c6c6f"
const resp = await fetch("/img.png");
const data = new Uint8Array(await resp.arrayBuffer());

Code Explained

Typed arrays — array-like but fixed type and length
DataView — mixed types and endianness control
TextEncoder — always UTF-8
Hex string from bytes with padStart(2, "0")

TypeScript

  • Typed arrays are generic over their buffer type since TS 5.7 (Uint8Array<ArrayBuffer>)
  • That can cause new errors when passing SharedArrayBuffer-backed arrays; adjust types if so

⚠ Common Mistakes

  • Expecting typed arrays to grow with push; they don't have it
  • Ignoring endianness when parsing binary file formats
  • Using String.fromCharCode on UTF-8 bytes; use TextDecoder

✓ Tips & Best Practices

  • Use subarray for zero-copy slices (it shares the buffer)
  • Use Uint8Array.prototype.toHex() / fromBase64() where supported (ES2026)
  • Transfer buffers to workers instead of copying (sheet 090)

Quick Summary

  • ArrayBuffer — raw bytes
  • typed arrays — fixed-type views
  • DataView — mixed types, endianness
  • TextEncoder/Decoder — string ↔ UTF-8
