Program Structure

scripts vs modules · statements · semicolons & ASI · blocks · "use strict" · top-level await

Overview

A JavaScript program is a sequence of statements executed top to bottom. Files are either classic scripts (shared global scope) or modules (own scope, strict mode on, can use import/export and top-level await). Semicolons are optional thanks to automatic semicolon insertion (ASI), but a few edge cases make it worth understanding.

Notes

  • There's no main() entry point; the file runs from the top
  • Modules are always in strict mode; scripts need "use strict"
  • Blocks { } create scope for let/const
  • Indentation is cosmetic; braces define structure

Anatomy of a module

import { readFile } from "node:fs/promises";  // imports first

const PATH = "./data.txt";                   // module-scoped constant

function countLines(text) {                  // declaration (hoisted)
  return text.split("\n").length;
}

const text = await readFile(PATH, "utf8");   // top-level await (modules only)
console.log(countLines(text));               // 42

export { countLines };                       // public API

// ASI trap: a line starting with ( or [ joins the previous line
const a = 1
;[1, 2].forEach(n => console.log(n))         // leading ; protects it

Code Explained

import — hoisted and resolved before any code runs
Top-level await — only allowed in modules
export — makes names available to other modules
Leading ; — guards lines that start with (, [, or a template literal

TypeScript

  • Same structure; a file with any import/export is a module, otherwise its declarations become global across files
  • Use export {} to force a file to be a module

⚠ Common Mistakes

  • Putting the return value on the line after return; ASI inserts a semicolon and returns undefined
  • Relying on globals between <script> tags, then breaking when switching to modules
  • Mixing semicolon styles; pick one and enforce it with Prettier

✓ Tips & Best Practices

  • Default to modules everywhere; scripts are legacy
  • If you skip semicolons, let a formatter add the defensive leading ; for you
  • Keep imports at the top and exports at the bottom for readability
