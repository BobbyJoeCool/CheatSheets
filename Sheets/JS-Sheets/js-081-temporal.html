Sheet 081

Temporal

PlainDate · ZonedDateTime · Instant · Duration · add / subtract · until / since

Overview

Temporal is the modern replacement for Date. It provides immutable types for each kind of time value: PlainDate for calendar dates, PlainTime for wall-clock times, ZonedDateTime for a moment in a specific time zone, Instant for an exact point on the timeline, and Duration for lengths of time. Months are 1-based and arithmetic is DST-safe.

Notes

  • Every operation returns a new object; nothing mutates
  • Check current browser/Node support; use the @js-temporal/polyfill otherwise
  • Temporal.Now gives the current time in any form
  • Convert from a legacy Date with date.toTemporalInstant()

Temporal types

const today = Temporal.Now.plainDateISO();          // 2026-10-02
const due = Temporal.PlainDate.from("2026-12-25");
today.until(due).days;                              // 84
due.add({ months: 1 }).toString();                  // "2027-01-25"
due.dayOfWeek;                                      // 5 (Friday, 1 = Mon)

const t = Temporal.PlainTime.from("09:30");
t.add({ minutes: 45 }).toString();                  // "10:15:00"

const meeting = Temporal.ZonedDateTime.from(
  "2026-03-08T01:30[America/Chicago]");
meeting.add({ hours: 1 }).toString();               // DST-aware
meeting.withTimeZone("Asia/Tokyo").toLocaleString();

const d = Temporal.Duration.from({ hours: 1, minutes: 90 });
d.round({ largestUnit: "hour" }).toString();        // "PT2H30M"

Temporal.PlainDate.compare(today, due);             // -1
today.equals(Temporal.PlainDate.from("2026-10-02")); // true

Code Explained

Plain… — no time zone attached
until / since — durations between values
ZonedDateTime — handles DST transitions
compare — use for sorting

TypeScript

  • Types are available with lib esnext or from the polyfill package
  • Each Temporal class is its own type, so mixing PlainDate and Instant is a compile error

⚠ Common Mistakes

  • Using PlainDateTime for events that happen at a real moment; use ZonedDateTime
  • Comparing with <; use Temporal.X.compare or equals
  • Shipping Temporal code without checking support or loading a polyfill

✓ Tips & Best Practices

  • Pick the most specific type: dates-only data should be PlainDate
  • Store Instant or ZonedDateTime.toString(); both round-trip losslessly
  • Format with toLocaleString or Intl.DateTimeFormat, which accept Temporal values

Quick Summary

  • PlainDate — calendar date
  • ZonedDateTime — real moment + zone
  • Duration — lengths
  • immutable — every op returns new
