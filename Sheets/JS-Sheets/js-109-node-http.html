HTTP Server (node:http)

createServer · req / res · routing · JSON responses · status codes · listen

Overview

Node's built-in node:http module creates web servers with no dependencies. createServer takes a handler that receives a request (IncomingMessage) and a response (ServerResponse). You route on req.method and the URL, read bodies from the request stream, and set status and headers before ending the response. Frameworks like Express and Fastify build on this.

Notes

  • The request body arrives as a stream; collect it before parsing
  • Call res.end() exactly once per request
  • req.url is only path and query; combine with a base to parse
  • Node 22+ can also run Web-standard handlers via frameworks like Hono

A tiny JSON API

import { createServer } from "node:http";

const todos = [{ id: 1, title: "Learn Node" }];

const server = createServer(async (req, res) => {
  const url = new URL(req.url, `http://${req.headers.host}`);
  const send = (status, data) => {
    res.writeHead(status, { "Content-Type": "application/json" });
    res.end(JSON.stringify(data));
  };

  if (req.method === "GET" && url.pathname === "/todos") {
    return send(200, todos);
  }
  if (req.method === "POST" && url.pathname === "/todos") {
    let body = "";
    for await (const chunk of req) body += chunk;
    const todo = { id: todos.length + 1, ...JSON.parse(body) };
    todos.push(todo);
    return send(201, todo);
  }
  send(404, { error: "Not found" });
});

server.listen(3000, () => console.log("http://localhost:3000"));

Code Explained

new URL(req.url, base) — easy path and query parsing
writeHead — status plus headers in one call
for await over req — read the body
Return after sending so only one response goes out

⚠ Common Mistakes

  • Forgetting res.end(), leaving requests hanging until timeout
  • Calling JSON.parse on bodies without try/catch
  • Sending a response twice ("headers already sent" error)

✓ Tips & Best Practices

  • Use a framework (Express, Fastify, Hono) for anything beyond a few routes
  • Limit body size to protect against huge uploads
  • Use node --watch server.js during development
