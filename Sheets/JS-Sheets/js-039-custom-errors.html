Sheet 039

Custom Errors

class extends Error · name · instanceof · extra fields · cause chains

Overview

Create custom errors by extending Error. Set this.name so logs and stack traces show your type, and add fields that callers need, like an HTTP status or a field name. Callers then branch with instanceof. Create one base class per library or app so all your errors can be caught together.

Notes

  • Always call super(message, options) first in the constructor
  • Setting name via a class field is the cleanest pattern
  • instanceof works across a class hierarchy
  • Error objects serialize poorly with JSON.stringify; add a toJSON if needed

A small error hierarchy

class AppError extends Error {
  name = "AppError";             // inherited constructor keeps cause
}
class NotFoundError extends AppError {
  name = "NotFoundError";
  status = 404;
}
class ValidationError extends AppError {
  name = "ValidationError";
  status = 400;
  constructor(field, message, options) {
    super(`${field}: ${message}`, options);
    this.field = field;
  }
}

const e = new ValidationError("email", "is required");
e instanceof AppError;           // true
e.field;                         // "email"
`${e}`;                          // "ValidationError: email: is required"

Code Explained

name field — shows in stack traces and toString()
Base AppError — catch every app error with one instanceof
Extra fields like status and field carry structured info
Pass options to super to keep cause support

TypeScript

  • Declare extra fields with types: readonly status = 404;
  • When targeting ES5, add Object.setPrototypeOf(this, new.target.prototype) or instanceof breaks

⚠ Common Mistakes

  • Forgetting to set name, so every error logs as "Error"
  • Accessing this before calling super()
  • Creating a custom class for every possible failure; keep the hierarchy small

✓ Tips & Best Practices

  • Add a stable code string; messages change, codes shouldn't
  • Map custom errors to HTTP responses in one central handler
  • Export your error classes so callers can use instanceof

Quick Summary
