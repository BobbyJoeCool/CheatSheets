Sheet 116

Object Types

optional ? · readonly · index signatures · excess property checks · Record

Overview

Object types describe properties and their types. Mark properties optional with ? and read-only with readonly. Index signatures describe dictionaries with unknown keys, and Record<K, V> is the shorthand. Fresh object literals get excess property checks, which catch typos in property names.

Notes

  • readonly is compile-time only
  • Optional ?: allows the property to be missing
  • Index signatures make every key's value potentially undefined with noUncheckedIndexedAccess
  • Excess property checks apply only to object literals assigned directly

Object type features

interface Product {
  readonly id: number;
  name: string;
  price: number;
  description?: string;                 // optional
  tags: readonly string[];
}

const p: Product = { id: 1, name: "Pen", price: 2, tags: [] };
// p.id = 2;                            // error: read-only
p.description?.toUpperCase();          // may be undefined

type Scores = { [player: string]: number };   // index signature
type Inventory = Record<string, number>;      // same idea
const stock: Inventory = { pens: 40, pads: 12 };
stock.erasers;                          // number | undefined (strict index)

type Flags = Record<"darkMode" | "beta", boolean>;  // fixed keys
const f: Flags = { darkMode: true, beta: false };

// const q: Product = { id: 2, name: "Pad", price: 4, tags: [], colour: "red" };
// error: Object literal may only specify known properties
const extra = { id: 2, name: "Pad", price: 4, tags: [], colour: "red" };
const q: Product = extra;               // OK: not a fresh literal

Code Explained

readonly — no reassignment after creation
?: — property may be absent
Record<string, V> — open dictionary
Record<"a" | "b", V> — required fixed keys
Excess checks catch typos in literals

⚠ Common Mistakes

  • Assuming readonly protects data at runtime; use Object.freeze for that
  • Using index signatures when the keys are known; list them explicitly
  • Confusing optional (a?: T) with nullable (a: T | null)

✓ Tips & Best Practices

  • Make properties readonly by default in data objects
  • Enable exactOptionalPropertyTypes to forbid assigning undefined to optional props
  • Use Map when keys are dynamic and frequently changing

Quick Summary

  • ? — optional
  • readonly — no reassign
  • index signature / Record — dictionaries
  • excess checks — catch typos
