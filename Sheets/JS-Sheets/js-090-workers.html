Workers & Parallelism

Web Workers · postMessage · worker_threads · transferables · SharedArrayBuffer · Atomics

Overview

JavaScript runs your code on one thread, so heavy CPU work blocks everything else. Web Workers (browser) and worker_threads (Node) run scripts on separate threads. They don't share variables; they communicate by message passing with postMessage. Large buffers can be transferred instead of copied, and SharedArrayBuffer with Atomics allows true shared memory.

Notes

  • Workers have no DOM access
  • Messages are copied with the structured clone algorithm
  • Transferring a buffer makes it unusable in the sender
  • SharedArrayBuffer in browsers needs cross-origin isolation headers

Offloading work to a worker

// main.js (browser)
const worker = new Worker(new URL("./prime.worker.js", import.meta.url),
                          { type: "module" });
worker.postMessage({ limit: 5_000_000 });
worker.onmessage = e => console.log("primes:", e.data.count);
worker.onerror = e => console.error(e.message);

// prime.worker.js
self.onmessage = ({ data }) => {
  let count = 0;
  for (let n = 2; n < data.limit; n++) if (isPrime(n)) count++;
  self.postMessage({ count });
};

// Node
import { Worker, isMainThread, parentPort, workerData } from "node:worker_threads";
if (isMainThread) {
  new Worker(new URL(import.meta.url), { workerData: 42 })
    .on("message", m => console.log(m));       // 84
} else {
  parentPort.postMessage(workerData * 2);
}

worker.postMessage(bigBuffer, [bigBuffer]);    // transfer, no copy

Code Explained

new URL(…, import.meta.url) — lets bundlers find the worker file
postMessage / onmessage — the whole communication channel
Node: same file can act as main or worker
Transfer list — moves ownership of buffers

TypeScript

  • Messages are untyped; wrap them in a typed helper or use a library like Comlink
  • Add "lib": ["WebWorker"] for worker files so self is typed correctly

⚠ Common Mistakes

  • Using workers for I/O-bound work that async already handles
  • Sending huge objects repeatedly; copying costs more than the work saved
  • Forgetting to terminate() workers you no longer need

✓ Tips & Best Practices

  • Use a worker pool (e.g., piscina in Node) for many small jobs
  • Measure first: worker startup has overhead
  • Use Comlink to call worker functions like normal async functions

Quick Summary

  • workers — real parallel threads
  • postMessage — communicate
  • transfer — move buffers, no copy
  • no DOM — compute only
