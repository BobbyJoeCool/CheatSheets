Testing with Vitest

describe · it · expect · toBe / toEqual · vi.fn · vi.mock · watch mode

Overview

Vitest is a fast test runner with a Jest-compatible API that works out of the box with ES modules and TypeScript. Group tests with describe, write them with it (or test), and assert with expect. vi.fn() creates mock functions and vi.mock() replaces whole modules.

Notes

  • Test files match *.test.js / *.spec.ts by default
  • npx vitest runs in watch mode; vitest run runs once
  • toBe uses Object.is; toEqual compares deeply
  • Async tests just await inside an async test function

A passing test file

// price.test.js
import { describe, it, expect, vi, beforeEach } from "vitest";
import { withTax, fetchRate } from "./price.js";

describe("withTax", () => {
  it("adds 7% by default", () => {
    expect(withTax(100)).toBe(107);
  });
  it("rejects negatives", () => {
    expect(() => withTax(-1)).toThrow(RangeError);
  });
  it("loads the rate", async () => {
    await expect(fetchRate("IA")).resolves.toBeCloseTo(0.07);
  });
});

it("calls the logger", () => {
  const log = vi.fn();
  withTax(10, { log });
  expect(log).toHaveBeenCalledWith("tax applied");
});

Code Explained

describe — groups related tests
toThrow(Type) — pass a function, not a call
resolves / rejects — assert on Promises
vi.fn() — records calls for assertions

TypeScript

  • Runs .ts test files with no extra setup
  • expectTypeOf(fn).returns.toBeNumber() tests types themselves

⚠ Common Mistakes

  • expect(fn()).toThrow() calls fn too early; wrap it: expect(() => fn())
  • Using toBe on objects or arrays; use toEqual
  • Forgetting to await async expectations, so failures go unnoticed

✓ Tips & Best Practices

  • Name tests as behavior: it("rejects negative amounts")
  • Use vi.useFakeTimers() to test timeouts instantly
  • Jest users: the API is nearly identical, mostly swap jest. for vi.

Quick Summary
