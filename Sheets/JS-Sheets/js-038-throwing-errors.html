Throwing Errors

throw · new Error() · cause · rethrow · AggregateError · throwing non-Errors

Overview

throw stops the current function and unwinds the call stack until a catch handles it. Throw Error instances (or subclasses) so you get a stack trace. Use the cause option to wrap a low-level error in a higher-level one without losing the original.

Notes

  • throw is a statement; it can't be used as an expression (yet)
  • Throwing a string loses the stack trace
  • AggregateError bundles several errors in .errors
  • Uncaught errors crash Node processes and log in browsers

Throwing, rethrowing, wrapping

function withdraw(balance, amount) {
  if (typeof amount !== "number") {
    throw new TypeError("amount must be a number");
  }
  if (amount > balance) {
    throw new RangeError(`Insufficient funds: ${balance}`);
  }
  return balance - amount;
}

async function loadUser(id) {
  try {
    return await db.get(id);
  } catch (err) {
    throw new Error(`Failed to load user ${id}`, { cause: err });
  }
}

try { await loadUser(7); }
catch (e) { console.log(e.message, e.cause.message); }

throw new AggregateError([e1, e2], "2 checks failed");
const fail = msg => { throw new Error(msg); };  // throw in an expression

Code Explained

Pick the most specific built-in type that fits
{ cause: err } — keeps the original error attached
e.cause — read the underlying error
Wrap throw in an arrow to use it where an expression is needed

TypeScript

  • Function signatures don't declare what they throw; there are no checked exceptions
  • A function that always throws can return never

⚠ Common Mistakes

  • Throwing strings or plain objects, which have no stack trace
  • Catching, logging, and rethrowing at every level, producing duplicate logs
  • Using exceptions for normal control flow like "not found"

✓ Tips & Best Practices

  • Include the offending value in the message: Invalid port: ${port}
  • Wrap third-party errors at module boundaries using cause
  • Validate inputs at the top of public functions and throw early

Quick Summary

  • throw new Error(msg) — always Error objects
  • TypeError / RangeError — specific types
  • { cause } — wrap without losing info
  • AggregateError — several failures
