ES Modules

import · export · default vs named · as · import * as · re-export · import() · import.meta

Overview

ES modules are the standard module system. Each file has its own scope and shares values with export and import. Imports are static and hoisted, which lets tools tree-shake unused code. Use import() to load a module dynamically at runtime, which returns a Promise.

Notes

  • Imports are live, read-only bindings, not copies
  • A module runs once, no matter how many files import it
  • Browsers and Node need full paths with extensions: ./util.js
  • import.meta holds module info like url

Exports and imports

// math.js
export const PI = 3.14159;
export function area(r) { return PI * r * r; }
export default class Circle { /* … */ }

// app.js
import Circle, { PI, area } from "./math.js";    // default + named
import { area as circleArea } from "./math.js";   // rename
import * as math from "./math.js";               // namespace
math.area(2);                                    // 12.56636

export { area } from "./math.js";                // re-export
export * from "./shapes.js";                     // re-export all
export { default as Circle } from "./math.js";

const { default: Chart } = await import("./chart.js");  // dynamic
if (needsAdmin) await import("./admin.js");      // conditional load

import data from "./data.json" with { type: "json" };  // JSON module
import.meta.url;                                 // "file:///…/app.js"

Code Explained

Named exports — imported by exact name in { }
Default export — one per module, any name on import
import * as ns — all exports as an object
import() — lazy loading, code splitting

TypeScript

  • import type { User } from "./types.js" imports only types; it's erased from output
  • Enable verbatimModuleSyntax so type-only imports must say so explicitly

⚠ Common Mistakes

  • Leaving off .js in Node or browser imports
  • Mixing up default and named imports: import { Circle } when it's a default export
  • Creating circular imports that read values before they're initialized

✓ Tips & Best Practices

  • Prefer named exports; they rename consistently and autocomplete better
  • Use index.js barrel files sparingly; they can defeat tree-shaking
  • Lazy-load heavy features with import()

Quick Summary

  • export / import — share values
  • default vs named — one vs many
  • import() — dynamic, returns Promise
  • static imports — tree-shakable
