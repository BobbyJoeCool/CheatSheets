Sheet 023

Comparison Operators

== vs === · != !== · < > <= >= · Object.is · string comparison · NaN

Overview

Use strict equality === and !==: they compare value and type with no conversion. Loose equality == converts types first and has rules few people remember. Relational operators (<, >) compare strings character by character by code unit, and objects are equal only if they're the same reference.

Notes

  • NaN isn't equal to anything, including itself
  • Object.is is like === but treats NaN as equal and +0/-0 as different
  • Arrays and objects compare by reference, never by contents
  • "10" < "9" is true (string comparison)

Comparisons with results

5 === 5;             // true
5 === "5";           // false
5 == "5";            // true   (coerces)
0 == "";             // true
null == undefined;   // true
null == 0;           // false
NaN === NaN;         // false
Object.is(NaN, NaN); // true
Object.is(0, -0);    // false

[1] === [1];         // false  (different references)
const a = [1]; a === a;  // true

"apple" < "banana";  // true
"Z" < "a";           // true   (uppercase sorts first)
"10" < "9";          // true   (string compare)
10 < 9;              // false
"10" < 9;            // false  (string converted to number)

Code Explained

=== — no type conversion, the safe default
== — converts operands; null == undefined is the one useful case
Two strings compare lexically; a string vs number compares numerically
Compare arrays by contents with a loop or JSON.stringify for simple data

TypeScript

  • Comparing types with no overlap (x === "a" when x: number) is a compile error
  • Comparisons narrow: after if (x === null) return, x is non-null

⚠ Common Mistakes

  • Using == and getting coerced matches like "" == 0
  • Comparing objects or arrays with === and expecting content equality
  • Sorting or comparing numeric strings without converting them

✓ Tips & Best Practices

  • Turn on ESLint's eqeqeq rule (allowing == null if you like)
  • Use Number.isNaN instead of comparing to NaN
  • Use a.localeCompare(b) for natural, locale-aware string ordering

Quick Summary

  • === — strict, use by default
  • == — coerces, avoid
  • objects — compared by reference
  • Object.is — handles NaN and -0
