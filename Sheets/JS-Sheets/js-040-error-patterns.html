Global Handlers & Error Patterns

window.onerror · unhandledrejection · process.on('uncaughtException') · error-first callbacks · result objects

Overview

Some errors escape every try/catch. Global handlers are the last line of defense: log the error, report it, and (in Node) exit cleanly. Beyond exceptions, JavaScript code uses other error patterns: Node's legacy error-first callbacks and result objects that return errors as values instead of throwing.

Notes

  • Unhandled promise rejections crash Node by default
  • After uncaughtException, the process is in an unknown state; exit
  • Browsers fire error and unhandledrejection on window
  • Global handlers are for logging, not recovery

Global handlers and patterns

// Browser
window.addEventListener("error", e => report(e.error));
window.addEventListener("unhandledrejection", e => {
  report(e.reason);
  e.preventDefault();               // suppress console noise
});

// Node
process.on("uncaughtException", err => {
  log(err); process.exit(1);        // state is unsafe, exit
});
process.on("unhandledRejection", reason => { throw reason; });

// Error-first callback (legacy Node style)
fs.readFile("a.txt", "utf8", (err, data) => {
  if (err) return console.error(err);
  console.log(data);
});

// Result object: errors as values
function parse(s) {
  try { return { ok: true, value: JSON.parse(s) }; }
  catch (error) { return { ok: false, error }; }
}
const r = parse(input);
if (!r.ok) showError(r.error);

Code Explained

unhandledrejection — a promise rejected with no .catch
uncaughtException — log, then exit
Error-first callbacks — check err before using data
Result objects — callers must check ok; nothing is thrown

TypeScript

  • Result types shine with discriminated unions: { ok: true; value: T } | { ok: false; error: E }
  • TS then forces callers to check ok before touching value

⚠ Common Mistakes

  • Continuing to run after uncaughtException
  • Using global handlers instead of handling errors where they happen
  • Mixing callbacks and promises; use fs/promises or util.promisify

✓ Tips & Best Practices

  • Send global errors to a reporting service (Sentry, etc.)
  • Use result objects for expected failures like form validation
  • Convert callback APIs with util.promisify(fn)

Quick Summary

  • unhandledrejection — unhandled promises
  • uncaughtException — log and exit
  • error-first callbacks — legacy
  • result objects — errors as values
