Sheet 113

Basic Types

string · number · boolean · arrays · tuples · any · unknown · never

Overview

Basic annotations use a colon: let x: number. The primitive types are lowercase: string, number, boolean, bigint, symbol, null, undefined. Arrays are T[], and tuples fix both length and position types. Special types: any turns checking off, unknown is a safe "could be anything", void means no return value, and never means "can't happen".

Notes

  • Prefer unknown over any for values you haven't checked
  • any spreads silently through everything it touches
  • object means any non-primitive
  • Lowercase types only; String/Number are wrapper objects

Basic types

let title: string = "Report";
let count: number = 3;
let done: boolean = false;
let big: bigint = 10n;

let tags: string[] = ["a", "b"];
let ids: Array<number> = [1, 2];
let point: [number, number] = [3, 4];             // tuple
let entry: [name: string, age?: number] = ["Ana"]; // labeled, optional
const fixed: readonly string[] = ["x"];

let anything: any = 4;
anything.foo.bar();               // no error (and a runtime crash)
let input: unknown = JSON.parse(text);
// input.name;                    // error: 'input' is of type 'unknown'
if (typeof input === "object" && input !== null && "name" in input) {
  input.name;                     // OK after narrowing
}

function log(msg: string): void { console.log(msg); }
function fail(msg: string): never { throw new Error(msg); }

Code Explained

T[] and Array<T> — identical
Tuples — exact length and per-position types
any — disables checking; avoid
unknown — must narrow before use
never — function never returns normally

⚠ Common Mistakes

  • Using any to silence errors instead of fixing types
  • Writing String or Object (wrapper types) instead of string or object
  • Annotating everything; let inference handle obvious locals

✓ Tips & Best Practices

  • Type function parameters and exports; let TS infer locals
  • Use unknown for parsed JSON and caught errors
  • Enable typescript-eslint's no-explicit-any as a warning
