Sheet 034

for...of & for...in

for...of · for...in · entries() · Object.entries() · iterables vs enumerable keys

Overview

for...of loops over the values of any iterable: arrays, strings, Maps, Sets, NodeLists, generators. for...in loops over the enumerable string keys of an object, including inherited ones. Use for...of for arrays and Object.entries() + for...of for objects.

Notes

  • for...in on arrays gives string indexes and can include extra properties
  • Plain objects aren't iterable; for...of on one throws
  • break, continue, and return work in both (unlike forEach)
  • for await...of iterates async iterables (sheet 094)

for...of vs for...in

const colors = ["red", "green"];
for (const c of colors) console.log(c);          // red, green
for (const [i, c] of colors.entries()) {}         // 0 red, 1 green
for (const ch of "hi") console.log(ch);          // h, i

const prices = { apple: 1.2, pear: 0.8 };
for (const key in prices) {
  console.log(key, prices[key]);                  // apple 1.2, pear 0.8
}
for (const [fruit, price] of Object.entries(prices)) {
  console.log(`${fruit}: $${price}`);
}

const m = new Map([["a", 1], ["b", 2]]);
for (const [k, v] of m) console.log(k, v);       // a 1, b 2
for (const v of new Set([1, 1, 2])) {}            // 1, 2

for (const i in colors) typeof i;                 // "string"!
// for (const x of prices) {}                     // TypeError: not iterable

Code Explained

entries() — index and value together
Object.entries — [key, value] pairs of an object
Map iteration yields [key, value] pairs in insertion order
for...in keys are always strings

TypeScript

  • In for...in, the key is typed string, not keyof T, so indexing needs a cast or Object.entries
  • for...of infers the element type from the iterable

⚠ Common Mistakes

  • Using for...in on arrays; you get string indexes and possibly extra keys
  • Using for...of on a plain object; it throws "not iterable"
  • Declaring the loop variable with let when you never reassign it; use const

✓ Tips & Best Practices

  • Default to for (const x of arr)
  • Destructure in the loop head: for (const { id, name } of users)
  • Use Object.entries instead of for...in to avoid inherited keys

Quick Summary

  • for...of — values of iterables
  • for...in — object keys (strings)
  • entries() — index + value
  • Object.entries — loop over objects
