Sheet 065

Constructors

constructor · field initializers · init order · super() before this · returning objects

Overview

The constructor runs when you call new. Its job is to set up the instance from its arguments. Field initializers run before the constructor body. In a subclass you must call super(...) before touching this. JavaScript allows only one constructor per class, so "overloads" use defaults, options objects, or static factory methods.

Notes

  • A class without a constructor gets a default one
  • Subclass default constructor passes all args to super
  • Returning an object from a constructor replaces the instance (rarely useful)
  • new.target tells you which class was actually instantiated

Constructors, order, factories

class Point {
  x = 0; y = 0;                        // 1. fields initialize
  constructor(x, y) {                  // 2. then constructor body
    this.x = x ?? this.x;
    this.y = y ?? this.y;
  }
  static fromArray([x, y]) { return new Point(x, y); }   // factory
  static origin() { return new Point(); }
}
new Point(3, 4);                       // Point { x: 3, y: 4 }
Point.fromArray([1, 2]);               // Point { x: 1, y: 2 }

class Point3D extends Point {
  z;
  constructor(x, y, z = 0) {
    super(x, y);                       // must come before this
    this.z = z;
  }
}

class Shape {
  constructor() {
    if (new.target === Shape) throw new TypeError("abstract");
  }
}

Code Explained

Fields first, then constructor body
Static factories — named alternatives to overloaded constructors
super(...) — runs the parent constructor
new.target — fake abstract classes in plain JS

TypeScript

  • Parameter properties declare and assign in one step: constructor(private x: number) {}
  • Real overloads are possible with multiple signatures above one implementation

⚠ Common Mistakes

  • Using this before super() in a subclass: ReferenceError
  • Doing async work in a constructor; constructors can't be async
  • Defining two constructors; only the last one survives (actually a SyntaxError)

✓ Tips & Best Practices

  • Use static async create() when setup needs await
  • Prefer field initializers for defaults; the constructor stays short
  • Name factories by intent: fromJSON, parse, empty

Quick Summary

  • constructor — runs on new
  • fields before body
  • super() first in subclasses
  • static factories — named constructors
