Sheet 007

Variables & Declarations

let · const · var · hoisting · TDZ · naming conventions · const ≠ immutable

Overview

Declare variables with const by default and let when the value must be reassigned. Avoid var: it is function-scoped and hoisted with an undefined value, which causes subtle bugs. let and const are block-scoped and sit in a temporal dead zone (TDZ) until their declaration runs, so using them early throws.

Notes

  • const prevents reassignment, not mutation of the object it holds
  • Names: letters, digits, _, $; can't start with a digit
  • Convention: camelCase for variables, UPPER_SNAKE for true constants
  • Undeclared assignment creates a global in sloppy mode; throws in strict mode

let, const, var

const name = "Ana";          // can't reassign
let count = 0;               // can reassign
count += 1;                  // 1

const user = { age: 30 };
user.age = 31;               // OK: mutating, not reassigning
// user = {};                // TypeError: Assignment to constant

console.log(x);              // undefined (var is hoisted)
var x = 5;

// console.log(y);           // ReferenceError: TDZ
let y = 5;

if (true) { var v = 1; let b = 2; }
console.log(v);              // 1  (var leaks out of the block)
// console.log(b);           // ReferenceError
let a = 1, z = 2;            // multiple declarations

Code Explained

const — binding is fixed; contents can change
var hoisting — declaration moves up, value doesn't
TDZ — let/const exist but can't be touched before their line
var ignores block scope; let respects it

TypeScript

  • Annotate with let count: number = 0, but inference usually handles it
  • const infers a literal type ("Ana"); let widens to string

⚠ Common Mistakes

  • Assuming const makes objects immutable; use Object.freeze for that
  • Using var in loops with callbacks, so every callback sees the final value
  • Reusing one let for unrelated values; declare a new const instead

✓ Tips & Best Practices

  • Start with const; change to let only when the linter or a reassignment requires it
  • Enable ESLint's prefer-const and no-var
  • Declare variables as close to first use as possible

Quick Summary

  • const — default choice
  • let — when reassigning
  • var — legacy, avoid
  • TDZ — no access before declaration
