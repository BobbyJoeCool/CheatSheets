Logical Operators

&& · || · ! · short-circuit · returns an operand · || defaults

Overview

&&, ||, and ! combine conditions, but && and || don't return booleans. They return one of their operands: || returns the first truthy value (or the last), && returns the first falsy value (or the last). They also short-circuit, so the right side runs only when needed.

Notes

  • ! always returns a boolean
  • Precedence: ! › && › ||
  • Mixing ?? with &&/|| requires parentheses
  • Short-circuiting makes a && a.b a safe guard (though ?. is cleaner)

Operand values and short-circuiting

true && "yes";        // "yes"
0 && "yes";           // 0      (first falsy)
"a" && "b" && "c";    // "c"    (all truthy → last)

"" || "default";      // "default"
"hi" || "default";    // "hi"   (first truthy)
null || 0 || "";      // ""     (none truthy → last)

!true;                // false
!!"text";             // true

isLoggedIn && showDashboard();   // calls only if logged in
const port = env.PORT || 3000;   // fallback (but 0 → 3000)
const ok = (a > 0 && b > 0) || override;

// a ?? b || c;                  // SyntaxError
(a ?? b) || c;                   // OK with parentheses

Code Explained

&& — stops at the first falsy operand
|| — stops at the first truthy operand
cond && fn() — run a function conditionally
Use ?? instead of || when 0 or "" are valid values

TypeScript

  • && and || narrow types: inside if (user && user.name), both are known to exist
  • The result type is a union, e.g. 0 | "yes"

⚠ Common Mistakes

  • Expecting a || b to return true/false; it returns one of the values
  • Using || for defaults when 0, false, or "" are legitimate
  • Writing long && chains as statements; an if is often clearer

✓ Tips & Best Practices

  • Use !!x or Boolean(x) when you need an actual boolean
  • Put the cheapest or most likely-to-fail check first in && chains
  • Use parentheses when mixing && and || even if precedence is right

Quick Summary

  • && — first falsy or last value
  • || — first truthy or last value
  • ! — always boolean
  • short-circuit — right side may not run
