Inference, Widening & satisfies

inference · widening · literal types · as const · satisfies · contextual typing

Overview

TypeScript infers most types from values, so you rarely annotate locals. const keeps literal types ("GET"), while let widens to the general type (string). as const freezes an expression into its narrowest readonly form. satisfies checks a value against a type without widening it, so you keep precise inferred types.

Notes

  • Return types are inferred from return statements
  • Callback parameters get types from context (contextual typing)
  • Empty arrays infer as any[] or never[]; annotate them
  • Hover in your editor to see inferred types

Inference, as const, satisfies

let a = 5;                    // number
const b = 5;                  // 5 (literal)
let method = "GET";           // string (widened)
const m2 = "GET";             // "GET"
const arr = [1, "x"];         // (string | number)[]

[1, 2].map(n => n * 2);       // n inferred as number from context

const routes = ["home", "about"] as const;
// readonly ["home", "about"]
type Route = (typeof routes)[number];        // "home" | "about"

const config = { mode: "dark", size: 12 } as const;
// { readonly mode: "dark"; readonly size: 12 }

type Colors = Record<string, string | [number, number, number]>;
const palette = {
  red: [255, 0, 0],
  blue: "#00f",
} satisfies Colors;
palette.red[0];               // OK: still known as a tuple
palette.blue.toUpperCase();   // OK: still known as string
// with ": Colors" both would be string | tuple

Code Explained

const — literal type; let — widened type
as const — readonly, literal everything
(typeof x)[number] — union of array element types
satisfies — validates shape, keeps precise types
Annotation (: Colors) — widens to the declared type

When to Annotate

⚠ Common Mistakes

  • Annotating with a broad type and losing useful literal information
  • Using as to "fix" a type error; that's an assertion, not a check
  • const list = [] then pushing values; annotate const list: string[] = []

✓ Tips & Best Practices

  • Use as const for lookup tables and option lists
  • Use satisfies for config objects
  • Derive types from values (typeof) so they never drift

Quick Summary
