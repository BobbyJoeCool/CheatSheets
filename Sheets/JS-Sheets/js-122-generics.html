Generics

<T> · constraints extends · defaults · generic functions · generic classes · type-argument inference

Overview

Generics let a function, class, or type work with many types while keeping them connected. A type parameter like <T> is a placeholder filled in at each use, usually by inference from the arguments. Constraints (T extends …) limit what T can be so you can safely use its members, and defaults fill in T when it isn't specified.

Notes

  • Name parameters meaningfully when there are several: <TKey, TValue>
  • If T appears only once in a signature, you probably don't need a generic
  • Explicit type arguments: fn<string>(x)
  • In .tsx, write <T,> for generic arrows

Generic functions, constraints, classes

function first<T>(items: T[]): T | undefined { return items[0]; }
first([1, 2]);              // number | undefined (T inferred)
first(["a"]);               // string | undefined

function longest<T extends { length: number }>(a: T, b: T): T {
  return a.length >= b.length ? a : b;            // .length is safe
}
longest("hi", "hello");     // "hello"
longest([1], [1, 2]);       // number[]
// longest(1, 2);           // error: number has no length

function pluck<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}
pluck({ id: 7, name: "Ana" }, "name");            // string

class Box<T = string> {                           // default type
  constructor(public value: T) {}
  map<U>(fn: (v: T) => U): Box<U> { return new Box(fn(this.value)); }
}
new Box(3).map(n => n.toFixed(1)).value;          // string
type ApiResponse<T> = { data: T; error?: string };

Code Explained

<T> — placeholder, inferred from arguments
extends { length: number } — constraint
K extends keyof T — key must belong to T
T[K] — the property's type
<T = string> — default type argument

⚠ Common Mistakes

  • Adding generics that never relate two things (<T>(x: T): void is just unknown)
  • Over-constraining with extends any or extends object when no constraint is needed
  • Returning T from a function that actually builds a new object of a different shape

✓ Tips & Best Practices

  • Let inference work; supply type arguments only when it can't
  • Use const type parameters (<const T>) to infer literal types
  • Start concrete, then generalize once you see repetition

Quick Summary

  • <T> — type placeholder
  • extends — constraint
  • keyof + T[K] — typed property access
  • defaults — <T = X>
