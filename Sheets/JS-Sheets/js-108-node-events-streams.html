EventEmitter & Streams

EventEmitter · on / once / emit · Readable · Writable · pipeline · backpressure

Overview

Much of Node is built on EventEmitter: objects emit named events and listeners react with on. Streams are emitters that move data in chunks, letting you process files and network data larger than memory. Connect them with pipeline, which handles errors and backpressure (slowing a fast producer for a slow consumer).

Notes

  • Four stream types: Readable, Writable, Duplex, Transform
  • An error event with no listener crashes the process
  • Readable streams are async iterable: for await (const chunk of r)
  • Use stream/promises for the Promise-based pipeline

Emitters and stream pipelines

import { EventEmitter, once } from "node:events";
import { pipeline } from "node:stream/promises";
import { createReadStream, createWriteStream } from "node:fs";
import { createGzip } from "node:zlib";
import { Transform } from "node:stream";

class Job extends EventEmitter {
  run() { this.emit("progress", 50); this.emit("done", { ok: true }); }
}
const job = new Job();
job.on("progress", pct => console.log(`${pct}%`));
job.once("done", result => console.log(result));
job.on("error", err => console.error(err));     // always handle
job.run();
const [result] = await once(job, "done");       // await an event

const upper = new Transform({
  transform(chunk, enc, cb) { cb(null, chunk.toString().toUpperCase()); },
});
await pipeline(
  createReadStream("in.txt"), upper, createGzip(),
  createWriteStream("out.txt.gz"),
);                                              // errors reject here

Code Explained

emit(name, ...args) — call every listener
once — listen one time; events.once returns a Promise
Transform — modify chunks as they pass
pipeline — wires streams, handles errors and backpressure

TypeScript

  • Type events with a generic map (Node 20.11+ @types/node): class Job extends EventEmitter<{ done: [Result] }>
  • Streams are typed in @types/node; chunks are Buffer unless an encoding is set

⚠ Common Mistakes

  • Not listening for error events, so one failure crashes everything
  • Using .pipe() chains, which don't forward errors; use pipeline
  • Adding listeners in a loop and triggering MaxListenersExceeded warnings

✓ Tips & Best Practices

  • Use for await over readable streams for simple line or chunk processing
  • Prefer pipeline from node:stream/promises in async code
  • Remove listeners (or use once) for short-lived subscriptions
