Variable Scope

global · function · block · lexical · shadowing · var leaking

Overview

Scope decides where a variable is visible. JavaScript uses lexical scope: what a function can see depends on where it's *written*, not where it's called. let/const are block-scoped, var is function-scoped, and inner scopes can shadow outer names.

Notes

  • Lookups go inner → outer until found, else ReferenceError
  • Modules have their own top-level scope
  • globalThis is the global object everywhere (window in browsers)
  • Function parameters live in the function's scope

Scope levels and shadowing

const app = "global";               // module/global scope

function outer() {
  const x = "outer";                // function scope
  if (true) {
    const x = "block";              // shadows outer x
    let y = 1;                      // block scope
    console.log(x);                 // "block"
  }
  console.log(x);                   // "outer"
  // console.log(y);                // ReferenceError
  function inner() {
    return `${app} > ${x}`;         // reads outer scopes
  }
  return inner();
}
outer();                            // "global > outer"

function leak() { if (true) { var v = 1; } return v; }
leak();                             // 1  (var ignores blocks)

Code Explained

Inner scopes see outer variables, never the reverse
Shadowing — inner x hides outer x inside the block
let y disappears when its block ends
var belongs to the whole function

TypeScript

  • Scope rules are identical; TS adds no runtime behavior
  • Enable ESLint's no-shadow (typescript-eslint version) to flag accidental shadowing

⚠ Common Mistakes

  • Shadowing a variable by accident and updating the wrong one
  • Relying on globals between files instead of imports
  • Using var and expecting block scoping

✓ Tips & Best Practices

  • Keep variables in the smallest scope that works
  • Avoid reusing outer names for inner variables
  • Wrap scripts in modules rather than IIFEs to avoid globals

Quick Summary

  • lexical scope — set by where code is written
  • let/const — block scoped
  • var — function scoped
  • shadowing — inner name hides outer
