Sheet 093

Promises

new Promise · resolve / reject · then · catch · finally · chaining · Promise.resolve

Overview

A Promise represents a value that will exist later. It starts pending and settles exactly once, either fulfilled with a value or rejected with a reason. Attach handlers with .then, .catch, and .finally. Each returns a new Promise, so calls chain, and returning a Promise inside .then waits for it.

Notes

  • A settled Promise never changes state
  • Handlers always run asynchronously (as microtasks)
  • An error thrown in .then becomes a rejection down the chain
  • Unhandled rejections are reported and crash Node

Creating and chaining

function delay(ms, value) {
  return new Promise((resolve, reject) => {
    if (ms < 0) reject(new RangeError("negative delay"));
    setTimeout(() => resolve(value), ms);
  });
}

delay(500, 42)
  .then(v => v * 2)                       // 84
  .then(v => delay(100, v + 1))           // waits, then 85
  .then(v => console.log(v))              // 85
  .catch(err => console.error(err))       // any error above
  .finally(() => console.log("done"));    // always

fetch("/api/user")
  .then(res => {
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return res.json();
  })
  .then(user => console.log(user.name));

Promise.resolve(5);                       // already fulfilled
Promise.reject(new Error("no"));          // already rejected

Code Explained

Executor (resolve, reject) — runs immediately
Return a value from .then — next handler gets it
Return a Promise — chain waits for it
One .catch at the end handles every step

TypeScript

  • Type as Promise<T>: new Promise<number>(resolve => …)
  • Rejection reasons are untyped (any); narrow in .catch

Promise States

StateMeaning
pendingnot settled yet
fulfilledresolved with a value
rejectedfailed with a reason
settledfulfilled or rejected

Instance Methods

MethodRuns when
.then(onOk, onErr)fulfilled (or rejected)
.catch(fn)rejected
.finally(fn)either; value passes through

⚠ Common Mistakes

  • Forgetting to return inside .then, so the next step gets undefined
  • Nesting .then inside .then ("promise pyramid") instead of chaining
  • Creating a Promise around something that already returns one (the constructor anti-pattern)

✓ Tips & Best Practices

  • Prefer async/await (sheet 094) for readability; know promises to understand it
  • Always end chains with .catch or return them to a caller who will
  • Use util.promisify to convert callback APIs

Quick Summary

  • then / catch / finally — handlers
  • chaining — return values flow on
