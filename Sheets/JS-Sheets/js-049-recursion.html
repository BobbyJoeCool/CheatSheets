Sheet 049

Recursion

base case · factorial · fibonacci · tree traversal · stack size · no TCO

Overview

A recursive function calls itself on a smaller piece of the problem until it reaches a base case that returns without recursing. Recursion fits naturally shaped problems: trees, nested data, and divide-and-conquer algorithms. JavaScript engines (except Safari) don't do tail-call optimization, so very deep recursion overflows the stack.

Notes

  • Every recursive function needs a base case
  • Each call adds a stack frame; depth limits are around 10,000
  • Overflow throws RangeError: Maximum call stack size exceeded
  • Memoize recursive functions that repeat work (like naive fibonacci)

Classic recursion

function factorial(n) {
  if (n <= 1) return 1;              // base case
  return n * factorial(n - 1);       // recursive case
}
factorial(5);                        // 120

const fib = (n, memo = {}) =>
  n < 2 ? n : (memo[n] ??= fib(n - 1, memo) + fib(n - 2, memo));
fib(50);                             // 12586269025

function sumTree(node) {             // nested data
  if (!node) return 0;
  return node.value + (node.children ?? []).reduce((t, c) => t + sumTree(c), 0);
}

const flatten = arr =>
  arr.reduce((out, x) => out.concat(Array.isArray(x) ? flatten(x) : x), []);
flatten([1, [2, [3, [4]]]]);         // [1, 2, 3, 4]

// factorial(1e5);                   // RangeError: call stack exceeded

Code Explained

Base case stops the recursion
Memo object — each fib(n) computed once
Tree walks recurse into each child
Use loops or explicit stacks for very deep inputs

TypeScript

  • Recursive functions often need an explicit return type, or TS reports the type as implicitly any
  • Recursive *types* work too: type Tree = { value: number; children?: Tree[] }

⚠ Common Mistakes

  • Missing or unreachable base case, causing infinite recursion
  • Naive fib(n-1) + fib(n-2) without memoization: exponential time
  • Recursing over user-sized data (deep JSON, long lists) and overflowing the stack

✓ Tips & Best Practices

  • Write and test the base case first
  • Convert to an explicit stack (while (stack.length)) for unbounded depth
  • Use arr.flat(Infinity) instead of writing your own flatten

Quick Summary

  • base case — stops recursion
  • recursive case — smaller input
  • memoize — avoid repeated work
  • no TCO — watch depth
