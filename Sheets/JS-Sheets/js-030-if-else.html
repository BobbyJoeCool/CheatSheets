if / else if / else

if · else if · else · truthiness in conditions · guard clauses · block scope

Overview

if runs a block when its condition is truthy; else if chains further checks; else catches everything left. Conditions don't need to be booleans, which is convenient and occasionally dangerous. Guard clauses (early returns) keep the main logic un-nested.

Notes

  • Braces are optional for single statements, but always use them
  • let/const inside a block are scoped to that block
  • There's no elif; it's else if
  • Only the first matching branch runs

Branching and guard clauses

const score = 82;

if (score >= 90) {
  grade = "A";
} else if (score >= 80) {
  grade = "B";               // this branch runs
} else {
  grade = "C";
}

// Guard clauses: handle bad cases first, then the main path
function ship(order) {
  if (!order) return "no order";
  if (order.items.length === 0) return "empty";
  if (!order.paid) return "awaiting payment";
  return `shipping ${order.items.length} items`;
}

if (user) { /* truthy: object exists */ }
if (count === 0) { /* explicit beats truthy for numbers */ }

Code Explained

Conditions are checked top to bottom; first truthy wins
Guard clauses — return early so the happy path isn't nested
Truthy checks are fine for objects; be explicit for numbers and strings
Each branch has its own block scope

TypeScript

  • Each branch narrows types: after if (typeof x === "string"), x is a string inside
  • After a guard if (!user) return, TS knows user is defined below

Condition Patterns

PatternMeaning
if (x)x is truthy
if (x != null)x is not null/undefined
if (arr.length)array not empty
if (str.trim())string has content
if (Object.keys(o).length)object has keys
if (a && b)both truthy

⚠ Common Mistakes

  • Writing if (x = 5); it assigns and is always true
  • Using if (count) when 0 is a valid count
  • Nesting four levels of if; invert the conditions and return early

✓ Tips & Best Practices

  • Extract long conditions into a named boolean: const canShip = paid && inStock;
  • Use a lookup object instead of long else if chains that map values
  • Keep the most common case first for readability

Quick Summary

  • if / else if / else — branch on truthiness
  • guard clauses — early return
  • block scope — per branch
  • explicit checks for 0 and ""
