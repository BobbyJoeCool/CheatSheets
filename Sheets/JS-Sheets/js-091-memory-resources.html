Sheet 091

Memory & Resource Management

garbage collection · common leaks · WeakRef · FinalizationRegistry · using · Symbol.dispose

Overview

JavaScript frees memory automatically with garbage collection: once nothing can reach an object, it can be reclaimed. Leaks happen when references linger unexpectedly. For external resources (files, locks, connections), explicit resource management with using and Symbol.dispose guarantees cleanup when a block exits.

Notes

  • GC timing is unpredictable; never rely on it for cleanup
  • WeakRef lets you hold an object without keeping it alive
  • FinalizationRegistry callbacks may run late or never
  • await using handles async cleanup with Symbol.asyncDispose

Leaks, weak refs, using

// Common leak: listener holds a big object forever
const big = new Array(1e6).fill("x");
window.addEventListener("resize", () => big.length);   // never removed

const ac = new AbortController();                      // fix: removable
window.addEventListener("resize", onResize, { signal: ac.signal });
ac.abort();                                            // removes it

const cache = new WeakMap();                           // auto-cleans
cache.set(node, computeLayout(node));

const ref = new WeakRef(expensiveObject);
ref.deref()?.render();             // undefined once collected

class DbConnection {
  [Symbol.asyncDispose]() { return this.close(); }
}
async function report() {
  await using db = await connect();  // closed when the function exits,
  return db.query("SELECT …");       // even if query throws
}

Code Explained

AbortController signal — remove many listeners at once
WeakMap — cache that doesn't block GC
deref() — may return undefined
using — dispose at block end, like try/finally

TypeScript

  • using and await using are supported since TS 5.2; add esnext.disposable to lib if needed
  • Implement the Disposable / AsyncDisposable interfaces

⚠ Common Mistakes

  • Relying on FinalizationRegistry for essential cleanup
  • Unbounded Map caches that grow forever
  • Using using in runtimes without support; check before shipping

✓ Tips & Best Practices

  • Compare two heap snapshots to find what's growing
  • Give caches a max size or TTL (or use an LRU library)
  • Use using for anything with a close(), release(), or unlock()

Quick Summary

  • GC — frees unreachable objects
  • leaks — lingering references
  • WeakMap / WeakRef — weak holds
  • using — guaranteed cleanup
