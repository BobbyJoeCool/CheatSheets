Decorators

class / method / field decorators · context object · accessor · metadata · experimentalDecorators (legacy)

Overview

Decorators are functions that wrap or annotate classes and their members using @name syntax. TypeScript 5.0+ implements the standard (TC39 stage 3) decorators: each receives the original value and a context object, and can return a replacement. Older code and some frameworks (Angular, NestJS) still use the legacy experimentalDecorators version, which works differently.

Notes

  • Standard decorators need no tsconfig flag
  • The two versions aren't compatible; check what your framework uses
  • Parameter decorators exist only in the legacy version
  • The accessor keyword creates an auto getter/setter that decorators can wrap

Standard decorators

function logged<T extends (...a: any[]) => any>(
  target: T, ctx: ClassMethodDecoratorContext) {
  return function (this: unknown, ...args: Parameters<T>): ReturnType<T> {
    console.log(`→ ${String(ctx.name)}(${args.join(", ")})`);
    return target.apply(this, args);
  };
}

function clamp(min: number, max: number) {          // decorator factory
  return (t: ClassAccessorDecoratorTarget<unknown, number>,
          _ctx: ClassAccessorDecoratorContext) => ({
    set(this: unknown, v: number) {
      t.set.call(this, Math.min(max, Math.max(min, v)));
    },
  });
}

class Calculator {
  @clamp(0, 100) accessor percent = 50;
  @logged add(a: number, b: number) { return a + b; }
}
new Calculator().add(2, 3);       // logs "→ add(2, 3)", returns 5

Code Explained

Method decorator — returns a replacement function

Factory — a function that returns a decorator
accessor — decoratable auto-property
ctx.name — the decorated member's name

⚠ Common Mistakes

  • Mixing standard decorator code with a framework that needs experimentalDecorators
  • Assuming decorators work on plain functions; they're for classes only
  • Putting heavy logic in decorators, making behavior hard to trace

✓ Tips & Best Practices

  • Use decorators for cross-cutting concerns: logging, binding, validation, timing
  • Keep decorators small and well named
  • Check runtime support: TS downlevels them, but native JS support is still arriving
