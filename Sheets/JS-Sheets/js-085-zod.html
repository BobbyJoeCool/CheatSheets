Sheet 085

Runtime Validation with Zod

z.object · z.string · parse · safeParse · refine · error formatting

Overview

Data from outside your program (APIs, forms, files, localStorage) can be anything. Zod lets you declare a schema once and validate data against it at runtime. parse returns clean data or throws; safeParse returns a result object you can branch on. Schemas can also transform and coerce values.

Notes

  • Zod 4 is current; the core API is the same as Zod 3
  • Unknown keys are stripped by default
  • z.coerce.number() converts strings like form inputs
  • Error messages can be customized per check

Schemas and validation

import { z } from "zod";

const User = z.object({
  id: z.number().int().positive(),
  email: z.email(),
  name: z.string().min(1).max(50),
  role: z.enum(["admin", "user"]).default("user"),
  tags: z.array(z.string()).optional(),
});

const user = User.parse(await res.json());    // throws ZodError if bad

const result = User.safeParse(input);
if (!result.success) {
  console.log(z.flattenError(result.error).fieldErrors);
  // { email: ["Invalid email address"] }
} else {
  result.data.role;                           // "user" (default applied)
}

const Form = z.object({ age: z.coerce.number().min(18) });
Form.parse({ age: "21" });                    // { age: 21 }
const Password = z.string().refine(s => /\d/.test(s),
  { message: "needs a digit" });

Code Explained

z.object({...}) — describes the expected shape
parse — returns typed data or throws
safeParse — { success, data } or { success, error }
refine — custom checks

TypeScript

  • type User = z.infer<typeof User> derives the static type from the schema, so you write it once
  • After safeParse succeeds, result.data is fully typed

Schema Types

SchemaValidates
z.string()strings
z.number().int()integers
z.boolean()booleans
z.enum([...])one of values
z.array(s)arrays of s
z.union([a, b])either
z.literal("x")exact value

Modifiers

ModifierEffect
.optional()may be undefined
.nullable()may be null
.default(v)fill when missing
.transform(fn)change output
.strict()reject extra keys

⚠ Common Mistakes

  • Trusting res.json() without validating
  • Using parse in request handlers without catching the ZodError
  • Writing a TypeScript type and a schema separately so they drift apart

✓ Tips & Best Practices

  • Validate once at the boundary, then trust the typed data inside
  • Share schemas between client and server
  • Use z.coerce for query strings and form fields

Quick Summary

  • schema — runtime shape
  • parse — validate or throw
  • safeParse — validate, no throw
  • z.infer — type from schema
