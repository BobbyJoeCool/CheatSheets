Sheet 092

The Event Loop & Timers

call stack · task queue · microtasks · setTimeout · setInterval · queueMicrotask · ordering

Overview

JavaScript runs one thing at a time on a call stack. Async work (timers, network, I/O) is handled outside, and its callbacks wait in queues. The event loop runs all synchronous code first, then drains the microtask queue (Promise callbacks, queueMicrotask), then takes one task (timer, event) and repeats.

Notes

  • Microtasks always run before the next task
  • setTimeout(fn, 0) means "after current work and microtasks", not now
  • Timer delays are minimums, never guarantees
  • Long synchronous code freezes the page: no clicks, no rendering

Execution order puzzle

console.log("1 sync");

setTimeout(() => console.log("5 timeout (task)"), 0);

Promise.resolve().then(() => console.log("3 promise (microtask)"));

queueMicrotask(() => console.log("4 microtask"));

console.log("2 sync");

// Output: 1 sync, 2 sync, 3 promise, 4 microtask, 5 timeout

const id = setTimeout(save, 1000);       // run once after ~1s
clearTimeout(id);                        // cancel
const tick = setInterval(update, 500);   // repeat every ~500ms
clearInterval(tick);
await new Promise(r => setTimeout(r, 300));   // sleep 300ms
await scheduler.yield?.();               // let the browser breathe

Code Explained

Sync code always finishes first
Then every queued microtask, in order
Then one macrotask (timer), then microtasks again
Promise + setTimeout — the standard sleep

TypeScript

  • Timer IDs differ: number in browsers, NodeJS.Timeout in Node; use ReturnType<typeof setTimeout>
  • Otherwise identical in TypeScript

⚠ Common Mistakes

  • Expecting setTimeout(fn, 0) to run before Promise callbacks
  • Using setInterval with async work that can take longer than the interval, so calls pile up
  • Running heavy loops on the main thread and freezing the UI

✓ Tips & Best Practices

  • Use chained setTimeout instead of setInterval for async polling
  • Break long tasks into chunks (or use a worker)
  • Visualize the loop with Jake Archibald's "In the Loop" talk or loupe

Quick Summary
