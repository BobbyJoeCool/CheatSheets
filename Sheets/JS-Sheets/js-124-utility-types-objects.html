Utility Types — Objects

Partial · Required · Readonly · Pick · Omit · Record

Overview

Utility types are built-in generics that transform object types. They save you from writing near-duplicate interfaces. Partial makes everything optional (great for updates), Required does the opposite, Readonly locks properties, Pick and Omit select or drop keys, and Record builds an object type from keys and a value type.

Notes

  • All utility types are shallow
  • Omit doesn't check that the keys exist on the type
  • Combine them: Partial<Omit<User, "id">>
  • They're implemented with mapped types (sheet 127)

Object utility types

interface User {
  id: number;
  name: string;
  email: string;
  avatar?: string;
}

type UserUpdate = Partial<User>;          // every field optional
function update(id: number, patch: Partial<Omit<User, "id">>) {}
update(1, { name: "Bo" });                // OK

type FullUser = Required<User>;  type Frozen = Readonly<User>;

type UserPreview = Pick<User, "id" | "name">;
// { id: number; name: string }

type NewUser = Omit<User, "id">;          // for create forms
// { name: string; email: string; avatar?: string }

type Role = "admin" | "editor";
const perms: Record<Role, string[]> = {
  admin: ["*"],
  editor: ["posts:write"],
};                                        // both keys required

Code Explained

Partial — patches and option objects
Omit<T, "id"> — create-forms without server fields
Pick — lightweight views
Record<Role, …> — compile error if a role is missing
Nest them for precise shapes

⚠ Common Mistakes

  • Typo in an Omit key silently does nothing (use a stricter custom helper if needed)
  • Expecting Readonly or Partial to apply to nested objects
  • Using Partial<T> everywhere and losing the guarantee that fields exist

✓ Tips & Best Practices

  • Derive request/response shapes from one model type instead of rewriting them
  • Name composed utility types (type NewUser = …) for readability
  • Use type-fest for deep variants like PartialDeep

Quick Summary

  • Partial / Required — optionality
  • Readonly — immutability
  • Pick / Omit — select keys
  • Record — keys → values
