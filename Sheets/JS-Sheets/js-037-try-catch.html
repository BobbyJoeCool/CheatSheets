Sheet 037

try / catch / finally

try · catch · finally · optional catch binding · built-in Error types · finally return

Overview

try runs code that might throw; catch receives the thrown value; finally always runs afterward, whether or not an error happened, even if try returns. Errors are objects with name, message, and stack. Catch only what you can handle, and let the rest propagate.

Notes

  • The catch binding is optional: catch { … }
  • try/catch only catches synchronous errors and awaited rejections
  • A return in finally overrides earlier returns and swallows errors
  • Any value can be thrown, but always throw Error objects

try / catch / finally

function parseConfig(text) {
  try {
    return JSON.parse(text).port;
  } catch (err) {
    if (err instanceof SyntaxError) {
      console.error("Bad JSON:", err.message);
      return 3000;                     // recover
    }
    throw err;                         // not ours: rethrow
  } finally {
    console.log("parse attempted");    // always runs
  }
}

try { null.prop; }
catch (e) {
  e.name;      // "TypeError"
  e.message;   // "Cannot read properties of null…"
}

try { risky(); } catch { /* ignore on purpose */ }

Code Explained

Check the error type before handling it
Rethrow errors you don't recognize
finally — cleanup that must always happen
catch { } without a variable when you don't need the error

TypeScript

  • With strict (useUnknownInCatchVariables), err is unknown; narrow with instanceof Error before using .message
  • There are no typed catch clauses; you can't write catch (e: SyntaxError)

⚠ Common Mistakes

  • Empty catch blocks that hide real bugs
  • Wrapping async calls in try/catch without await; the rejection escapes
  • Returning from finally, which silently discards thrown errors

✓ Tips & Best Practices

  • Catch at the level that can do something useful (retry, fallback, user message)
  • Log err itself, not just err.message, to keep the stack
  • Check types with instanceof, not by comparing message strings

Quick Summary

  • try — risky code
  • catch (e) — handle or rethrow
  • finally — always runs
  • instanceof — choose what to handle
