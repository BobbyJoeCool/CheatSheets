Sheet 121

Classes in TypeScript

public / private / protected · readonly · parameter properties · abstract · implements · override

Overview

TypeScript adds compile-time features to classes: access modifiers (public, private, protected), readonly fields, parameter properties that declare and assign in one step, abstract classes and methods, implements for interfaces, and override to mark replaced methods. Remember that TS private is not enforced at runtime; JS #private is.

Notes

  • Members are public by default
  • protected — visible in subclasses, hidden outside
  • implements checks the shape; it adds nothing to the class
  • Parameter properties aren't erasable syntax

Class features in TS

interface Shape { area(): number; name: string }

abstract class Base implements Shape {
  abstract readonly name: string;          // subclasses must define
  protected createdAt = new Date();
  abstract area(): number;
  describe(): string { return `${this.name}: ${this.area().toFixed(1)}`; }
}

class Circle extends Base {
  readonly name = "circle";
  constructor(private readonly r: number) { // parameter property
    super();
  }
  override area(): number { return Math.PI * this.r ** 2; }
}

const c = new Circle(2);
c.describe();              // "circle: 12.6"
// c.r;                    // error: private
// new Base();             // error: abstract class

class Account { #pin = "";  private note = ""; }  // runtime vs TS-only

Code Explained

abstract — can't instantiate; forces implementations
implements Shape — compile error if members are missing
private readonly r in constructor — declares and assigns
override — errors if the parent has no such method
#pin vs private — runtime vs compile-time privacy

⚠ Common Mistakes

  • Relying on TS private for security; it's visible in the JS output
  • Using parameter properties in projects that run TS via type stripping
  • Forgetting override after renaming a parent method, leaving a dead method

✓ Tips & Best Practices

  • Prefer #private when privacy must hold at runtime
  • Turn on noImplicitOverride
  • Favor interfaces + composition over deep abstract hierarchies

Quick Summary

  • public / protected / private — access
  • abstract — must implement
  • implements — shape check
  • override — explicit replacement
