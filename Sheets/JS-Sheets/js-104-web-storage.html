Sheet 104

Storage & Cookies

localStorage · sessionStorage · JSON storage · storage event · document.cookie · IndexedDB

Overview

Web Storage gives each origin a simple string key–value store. localStorage persists across sessions; sessionStorage lasts for one tab. Both are synchronous and limited to about 5 MB, so store JSON and keep it small. Cookies are sent to the server with every request. IndexedDB handles large or structured data.

Notes

  • Values are always strings; store objects with JSON.stringify
  • Storage can be unavailable or throw (private mode, quota exceeded)
  • The storage event fires in other tabs when a value changes
  • Never store secrets or auth tokens in localStorage (XSS can read it)

Storage APIs

localStorage.setItem("theme", "dark");
localStorage.getItem("theme");             // "dark"
localStorage.getItem("missing");           // null
localStorage.removeItem("theme");

const prefs = { fontSize: 14, lang: "en" };
localStorage.setItem("prefs", JSON.stringify(prefs));

function load(key, fallback) {
  try { return JSON.parse(localStorage.getItem(key)) ?? fallback; }
  catch { return fallback; }
}
load("prefs", {}).fontSize;                // 14

sessionStorage.setItem("step", "2");       // this tab only

window.addEventListener("storage", e => {  // sync across tabs
  if (e.key === "theme") applyTheme(e.newValue);
});

document.cookie = "seen=1; max-age=86400; path=/; SameSite=Lax";
document.cookie;                           // "seen=1; other=x"
await cookieStore?.get("seen");            // async Cookie Store API

Code Explained

getItem returns null for missing keys
Safe load helper — handles missing and corrupt data
storage event — keeps multiple tabs in sync
document.cookie — assignment adds one cookie, read returns all

TypeScript

  • getItem returns string | null; JSON.parse returns any, so validate or type the result
  • Wrap storage in a typed helper: load<T>(key: string, fallback: T): T

⚠ Common Mistakes

  • Storing objects directly, which saves "[object Object]"
  • Putting JWTs or passwords in localStorage
  • Calling storage in Node or SSR code where localStorage doesn't exist

✓ Tips & Best Practices

  • Version your stored data (prefs:v2) so format changes don't break old users
  • Use the idb-keyval library for an easy IndexedDB key–value API
  • Use HttpOnly cookies (set by the server) for sessions

Quick Summary

  • localStorage — persistent strings
  • sessionStorage — per tab
  • JSON — store objects
  • IndexedDB — big/structured data
