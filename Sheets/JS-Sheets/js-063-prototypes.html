Sheet 063

Prototypes

prototype chain · __proto__ · Object.create · getPrototypeOf · constructor functions · new

Overview

Every object has a hidden link to another object, its prototype. When a property isn't found on the object itself, JavaScript looks up the prototype chain until it finds it or reaches null. Classes are built on this mechanism: methods live once on the prototype and are shared by every instance.

Notes

  • Object.getPrototypeOf(o) reads the link; avoid __proto__
  • Object.create(proto) makes an object with a chosen prototype
  • Object.create(null) makes an object with no prototype at all
  • Functions have a .prototype property used by new

The prototype chain

const animal = { eats: true, walk() { return `${this.name} walks`; } };
const dog = Object.create(animal);   // dog → animal → Object.prototype
dog.name = "Rex";
dog.walk();                          // "Rex walks" (found on animal)
dog.eats;                            // true (inherited)
Object.hasOwn(dog, "eats");          // false
Object.getPrototypeOf(dog) === animal;  // true

function Person(name) { this.name = name; }   // constructor function
Person.prototype.hi = function () { return `Hi, ${this.name}`; };
const p = new Person("Ana");
p.hi();                              // "Hi, Ana"
p.hi === new Person("Bo").hi;        // true (shared)

class Cat { meow() {} }
typeof Cat;                          // "function"
Object.getPrototypeOf(new Cat()) === Cat.prototype;  // true

const dict = Object.create(null);    // no inherited keys
"toString" in dict;                  // false

Code Explained

Lookup walks the chain until a match or null
Writing a property always creates it on the object itself
new F() links the new object to F.prototype
Classes are syntax on top of constructor functions

TypeScript

  • Prefer classes; TS can't easily type methods added to Function.prototype by hand
  • Augmenting built-in prototypes needs declaration merging (sheet 128)

⚠ Common Mistakes

  • Adding methods to built-in prototypes like Array.prototype; it breaks other code and future standards
  • Using __proto__ in new code; it's legacy
  • Putting arrays or objects on a prototype, so every instance shares one mutable value

✓ Tips & Best Practices

  • Use class syntax for new code; know prototypes to debug it
  • Use Object.create(null) or Map for dictionaries with arbitrary keys
  • Inspect chains in DevTools by expanding [[Prototype]]
