Sheet 080

Date

new Date() · Date.now() · getters / setters · 0-based months · toISOString · Intl.DateTimeFormat

Overview

Date stores a single moment as milliseconds since 1970-01-01 UTC. Getters and setters read and change parts in local time (or UTC with getUTC…). It's mutable, months are 0-based, and parsing non-ISO strings is unreliable. For display, use Intl.DateTimeFormat; for serious date math, prefer Temporal (sheet 081).

Notes

  • new Date() is now; Date.now() is now in ms
  • Months: 0 = January, 11 = December; days of week: 0 = Sunday
  • ISO strings without a time zone are parsed as UTC (date-only) or local (date-time)
  • Setters overflow: setting day 32 rolls into the next month

Creating, reading, formatting

const now = new Date();
Date.now();                             // 1790935200000 (ms)
new Date("2026-03-15T09:30:00Z");       // ISO, UTC
new Date(2026, 2, 15);                  // Mar 15 2026, local (month 2!)

const d = new Date(2026, 0, 31);
d.getFullYear();  d.getMonth();         // 2026, 0
d.getDate();      d.getDay();           // 31, 6 (Saturday)
d.setDate(d.getDate() + 1);             // Feb 1 (rolls over)
d.toISOString();                        // "2026-02-01T…Z"

const days = (b - a) / 86_400_000;      // difference in days

new Intl.DateTimeFormat("en-US", { dateStyle: "medium" }).format(d);
// "Feb 1, 2026"
d.toLocaleDateString("de-DE");          // "1.2.2026"
d.toLocaleTimeString("en-US", { timeStyle: "short" });  // "12:00 AM"
new Intl.RelativeTimeFormat("en", { numeric: "auto" })
  .format(-1, "day");                   // "yesterday"

⚠ Common Mistakes

  • Forgetting months are 0-based when constructing dates
  • Parsing strings like "03/04/2026"; the result depends on the engine
  • Mutating a shared Date with setters and changing it everywhere

✓ Tips & Best Practices

  • Store and transmit dates as ISO strings or epoch ms
  • Copy before changing: const next = new Date(d)
  • Use Intl.DateTimeFormat with timeZone to show other zones
