Polymorphism, Duck Typing & Mixins

duck typing · overriding · mixin functions · Object.assign mixins · composition over inheritance

Overview

Polymorphism means different objects respond to the same method call in their own way. JavaScript uses duck typing: if an object has the method you need, you can use it, regardless of its class. Mixins copy reusable behavior into classes, and composition (objects holding other objects) is often simpler than inheritance.

Notes

  • Check capabilities, not classes: typeof x.render === "function"
  • Mixin functions take a base class and return an extended class
  • Order of mixins matters when methods collide
  • Composition: "has a" instead of "is a"

Duck typing, mixins, composition

class Circle { constructor(r) { this.r = r; }
               area() { return Math.PI * this.r ** 2; } }
class Square { constructor(s) { this.s = s; }
               area() { return this.s ** 2; } }
const total = shapes => shapes.reduce((t, s) => t + s.area(), 0);
total([new Circle(1), new Square(2), { area: () => 10 }]); // ≈17.14

const Serializable = Base => class extends Base {
  toJSON() { return { type: this.constructor.name, ...this }; }
};
const Timestamped = Base => class extends Base {
  createdAt = new Date();
};
class User { constructor(n) { this.name = n; } }
class Model extends Serializable(Timestamped(User)) {}
JSON.stringify(new Model("Ana"));  // {"type":"Model","name":"Ana",…}

class Car {                        // composition
  constructor() { this.engine = new Engine(); }
  start() { return this.engine.start(); }   // delegate
}

TypeScript

  • Structural typing is duck typing at compile time: any object matching an interface's shape is accepted
  • Mixins need a constructor type: type Ctor = new (...a: any[]) => {}

⚠ Common Mistakes

  • Checking instanceof when any object with the right method should be accepted
  • Mixins that overwrite each other's methods silently
  • Inheriting just to reuse one method; compose or extract a function instead

✓ Tips & Best Practices

  • Favor composition over inheritance for flexible designs
  • Document the "protocol" (methods expected) for duck-typed APIs
  • Keep mixins small and focused on one capability

Quick Summary

  • polymorphism — same call, different behavior
  • duck typing — check for the method
  • mixins — class → class functions
  • composition — has-a over is-a
