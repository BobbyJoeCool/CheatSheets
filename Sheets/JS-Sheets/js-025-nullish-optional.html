Nullish Coalescing & Optional Chaining

?? · ?. · ?.[] · ?.() · ?? vs ||

Overview

Nullish coalescing ?? returns its right side only when the left is null or undefined, unlike ||, which also replaces 0, "", and false. Optional chaining ?. stops evaluation and returns undefined when the value before it is nullish, instead of throwing a TypeError.

Notes

  • ?. works for properties a?.b, brackets a?.[k], and calls a.f?.()
  • Short-circuit covers the whole chain: a?.b.c is safe if a is nullish
  • You can't assign through ?.: a?.b = 1 is a SyntaxError
  • ?? can't mix with &&/|| without parentheses

?? and ?. in action

0 ?? 10;               // 0      (0 is not nullish)
0 || 10;               // 10
"" ?? "n/a";           // ""
null ?? "n/a";         // "n/a"
undefined ?? false;    // false

const user = { profile: null, tags: ["a"] };
user.profile?.name;           // undefined (no TypeError)
user.settings?.theme;         // undefined
user.tags?.[0];               // "a"
user.greet?.();               // undefined (method missing)
user.profile?.name ?? "Guest"; // "Guest"

const limit = opts.limit ?? 25;      // keeps 0 if passed
const len = list?.length ?? 0;

Code Explained

?? — default only for missing values
?.[] — optional bracket access
?.() — call only if the function exists
Combine: a?.b ?? fallback is the common pattern

TypeScript

  • The non-null assertion x! tells TS a value isn't null without a runtime check; prefer ?. or a real check
  • TS knows the result of a?.b includes undefined

⚠ Common Mistakes

  • Sprinkling ?. everywhere, which hides bugs where a value should always exist
  • Using || for numeric settings so a deliberate 0 gets overridden
  • Writing a?.b = 1; optional chaining can't be assigned to

✓ Tips & Best Practices

  • Use ?. only where nullish is a valid, expected state
  • Use ??= to set a default in place: opts.retries ??= 3
  • Read a ?? b as "a, unless it's missing"

Quick Summary

  • ?? — default for null/undefined only
  • ?. — safe property access
  • ?.() — safe call
  • a?.b ?? d — access with fallback
