Sheet 111

TypeScript: Introduction & Compiler

tsc · type checking vs type erasure · .ts / .tsx / .d.ts · tsc --noEmit · type stripping · erasableSyntaxOnly

Overview

TypeScript adds a static type system to JavaScript. You write .ts files with type annotations; the compiler tsc checks them and emits plain JavaScript with the types erased. Types never exist at runtime, so they can't validate data from outside. Many runtimes now strip types and run .ts directly, but stripping doesn't check anything; only tsc does.

Notes

  • Every valid JS program is valid TS (possibly with type errors)
  • Types cost nothing at runtime; they're gone after compilation
  • Type stripping only works for "erasable" syntax (no enums, namespaces, parameter properties)
  • A native Go-based compiler (TypeScript 7) is in progress; check its status

From .ts to .js

// greet.ts
interface User { name: string; age?: number }

function greet(user: User): string {
  return `Hi ${user.name}`;
}
greet({ name: "Ana" });          // OK
// greet({ nam: "Ana" });        // error: 'nam' does not exist in type 'User'

// $ npx tsc greet.ts            → greet.js (types erased):
function greet(user) {
  return `Hi ${user.name}`;
}

// $ npx tsc --noEmit            // type-check only, no output
// $ node greet.ts               // Node strips types and runs (no checking)
// $ npx tsx greet.ts            // run in dev with esbuild
// $ deno run greet.ts  /  bun greet.ts

⚠ Common Mistakes

  • Assuming types validate API responses at runtime; they don't
  • Running with tsx or Vite only and never running tsc, so type errors ship
  • Using enums or namespaces with Node type stripping, which can't erase them

✓ Tips & Best Practices

  • Add tsc --noEmit to CI and a pre-commit hook
  • Turn on erasableSyntaxOnly if you run TS through type stripping
  • Start new projects with strict: true from day one

Quick Summary

  • TS = JS + static types
  • tsc — check and emit
  • types erased — nothing at runtime
  • stripping — runs, doesn't check
