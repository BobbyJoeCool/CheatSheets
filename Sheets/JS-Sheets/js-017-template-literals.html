Sheet 017

Template Literals

${} · multiline · nesting · tagged templates · String.raw

Overview

Template literals use backticks and support ${expression} interpolation, real line breaks, and tagged templates, where a function receives the string parts and values separately. Any expression works inside ${}: math, function calls, ternaries, even other template literals.

Notes

  • Values inside ${} are converted with String()
  • Whitespace and newlines inside backticks are kept exactly
  • String.raw keeps backslashes as written
  • Tags power libraries like styled-components and lit-html

Interpolation and tags

const name = "Ana", items = 3, price = 4.5;

`Hi ${name}!`;                          // "Hi Ana!"
`Total: $${(items * price).toFixed(2)}`; // "Total: $13.50"
`${items > 1 ? "items" : "item"}`;      // "items"
`Upper: ${name.toUpperCase()}`;         // "Upper: ANA"

const html = `
<ul>
  ${["a", "b"].map(x => `<li>${x}</li>`).join("")}
</ul>`;                                  // nested templates

String.raw`C:\new\table`;              // "C:\new\table" (raw)

function tag(strings, ...values) {
  return strings.raw.join("|") + " :: " + values.join(",");
}
tag`a${1}b${2}c`;                        // "a|b|c :: 1,2"

Code Explained

$${…} — a literal $ followed by an interpolation
map(...).join("") — common pattern for lists in HTML
Tag receives strings (length = values + 1) and the values
strings.raw — the uninterpreted text

TypeScript

  • Template literal types use the same syntax at type level: type Id = `user-${number}`
  • Tag functions can be typed: (s: TemplateStringsArray, ...v: unknown[])

Template vs Concatenation

ConcatenationTemplate
"Hi " + name`Hi ${name}`
a + " + " + b`${a} + ${b}`
"l1\n" + "l2"`l1↵l2` (real newline)
"$" + n.toFixed(2)`$${n.toFixed(2)}`

⚠ Common Mistakes

  • Using quotes instead of backticks, so ${x} prints literally
  • Injecting user input into HTML with templates; that's an XSS hole (use textContent or escape)
  • Accidental indentation inside multi-line templates

✓ Tips & Best Practices

  • Use JSON.stringify(obj) inside ${} to print objects
  • Keep complex logic out of ${}; compute it in a variable first
  • Use String.raw for Windows paths and regex sources

Quick Summary

  • `${x}` — interpolation
  • multi-line — newlines kept
  • tagged templates — custom processing
  • String.raw — no escape handling
