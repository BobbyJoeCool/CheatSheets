Closures

closure · counter factory · module pattern · loop closure bug · private state

Overview

A closure is a function plus the variables it captured from the scope where it was created. The function keeps access to those variables even after the outer function has returned. Closures power private state, factories, callbacks, memoization, and the module pattern.

Notes

  • Closures capture variables, not snapshots of their values
  • Each call of the outer function creates a fresh set of captured variables
  • Captured variables stay in memory as long as the closure is reachable
  • Every function in JavaScript is technically a closure

Closures in practice

function makeCounter(start = 0) {
  let count = start;                 // private state
  return {
    inc: () => ++count,
    get: () => count,
  };
}
const a = makeCounter(), b = makeCounter(10);
a.inc(); a.inc();                    // 2
b.inc();                             // 11  (independent)

const multiplier = n => x => x * n;  // factory
const double = multiplier(2);
double(7);                           // 14

function memo(fn) {
  const cache = new Map();
  return arg => cache.has(arg) ? cache.get(arg)
                               : (cache.set(arg, fn(arg)), cache.get(arg));
}

for (var i = 0; i < 3; i++) setTimeout(() => console.log(i)); // 3 3 3

Code Explained

count is unreachable except through inc/get
Each makeCounter() call gets its own count
Factories return configured functions
var loop — all callbacks share one i; use let

TypeScript

  • Captured variables keep their inferred types; a closure's return type is inferred too
  • Type factories with generics to keep them reusable (sheet 122)

⚠ Common Mistakes

  • Expecting a closure to capture the value at creation time; it sees later changes
  • Holding large objects in long-lived closures (e.g., event listeners), causing leaks
  • Creating closures inside hot loops when one shared function would do

✓ Tips & Best Practices

  • Use closures for privacy in plain functions; use #private fields in classes
  • Remove event listeners that capture big data when you're done
  • Name returned functions to get clearer stack traces

Quick Summary

  • private state — hidden variables
