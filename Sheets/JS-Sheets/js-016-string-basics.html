Sheet 016

String Basics

'' · "" · \\ · length · immutability · escapes · concatenation · surrogate pairs

Overview

Strings are immutable sequences of UTF-16 code units. You can write them with single quotes, double quotes, or backticks (template literals, sheet 017). Every "modifying" method returns a new string. length counts UTF-16 units, so some emoji and rare characters count as 2.

Notes

  • Single and double quotes behave identically
  • Strings are compared by value: "a" === "a"
  • Index access s[0] is read-only; assignments are silently ignored (or throw in strict mode)
  • String.length is a property, not a method

Literals, escapes, length

const a = 'single';
const b = "double";
const c = `template ${a}`;          // "template single"

"It's".length;                     // 4
'Say "hi"';                        // quotes inside quotes
"Line 1\nLine 2";                  // newline escape
"Tab\there";                       // tab
"\u00e9";                          // "é"
"\u{1F600}";                       // "😀"

"😀".length;                       // 2  (surrogate pair)
[..."😀"].length;                  // 1  (code points)

let s = "cat";
s[0] = "b";                        // ignored; strings are immutable
s = "b" + s.slice(1);              // "bat"
"a" + "b" + 1 + 2;                 // "ab12"

Code Explained

\u{…} — code point escape for any Unicode character
[...str] — spread iterates code points, not UTF-16 units
Build a new string to "change" one
+ goes left to right: once a string appears, everything concatenates

TypeScript

  • Type string; literal types like "GET" | "POST" restrict to exact values
  • Assigning to s[0] is a compile error (index signature is readonly)

⚠ Common Mistakes

  • Using length to count user-visible characters; use [...s].length or Intl.Segmenter
  • Trying to change one character in place
  • Concatenating in a loop to build huge strings; collect parts in an array and join

✓ Tips & Best Practices

  • Pick one quote style and let Prettier enforce it
  • Use template literals whenever you embed values
  • Use localeCompare for human sorting, not <

Quick Summary
