Sheet 078

npm & package.json

npm install · -D · scripts · semver ^ ~ · package-lock.json · npx · exports field

Overview

npm installs packages into node_modules and records them in package.json. Dependencies ship with your app; devDependencies are for building and testing. The lockfile (package-lock.json) pins exact versions so every install is identical. Scripts in package.json are run with npm run.

Notes

  • Commit package-lock.json; never commit node_modules
  • Use npm ci in CI: clean install exactly from the lockfile
  • ^1.2.3 allows minor/patch updates; ~1.2.3 allows patch only
  • npx runs a package's binary without installing it globally

Everyday npm

$ npm install express          # add dependency
$ npm i -D vitest eslint       # add devDependencies
$ npm uninstall lodash         # remove
$ npm ci                       # exact install from lockfile
$ npm outdated                 # what's behind
$ npm update                   # update within semver ranges
$ npm ls express               # where a package comes from
$ npm audit                    # known vulnerabilities
$ npm run build                # run a script
$ npx create-vite@latest app   # run without installing

// package.json
{
  "name": "my-app", "version": "1.0.0", "type": "module",
  "scripts": { "dev": "vite", "test": "vitest", "build": "vite build" },
  "dependencies":    { "express": "^5.1.0" },
  "devDependencies": { "vitest": "^3.2.0" },
  "engines": { "node": ">=22" }
}

Code Explained

-D — saves to devDependencies
npm ci — fast, reproducible, deletes node_modules first
scripts — npm test and npm start work without run
engines — documents the required Node version

TypeScript

  • Packages ship types via a "types" field, or you install them from @types/*: npm i -D @types/node
  • Add "typecheck": "tsc --noEmit" to scripts

⚠ Common Mistakes

  • Installing build tools as regular dependencies, bloating production installs
  • Deleting the lockfile to "fix" problems, which pulls in untested versions
  • Running npm install in CI instead of npm ci

✓ Tips & Best Practices

  • Use npm pkg set scripts.lint="eslint ." to edit package.json safely
  • Review npm audit results; not every advisory affects you
  • Pin the package manager with the packageManager field and Corepack

Quick Summary

  • npm i / -D — add deps
  • npm ci — reproducible install
  • lockfile — exact versions
  • npm run — scripts
