Keyboard Focus and Navigation

Only one widget at a time has keyboard focus, and key events go to it. Users move focus with Tab and Shift+Tab in creation (stacking) order, skipping widgets whose takefocus is false. Set focus in code with focus_set(), and check it with focus_get(). <FocusIn> and <FocusOut> fire as focus moves, which suits field validation and highlighting. Accelerators shown in menus are just labels; you must also bind the keys yourself.

Notes

  • focus_set() only takes effect when the window is active
  • focus_force() steals focus from other apps; avoid it
  • Labels and Frames don't take focus by default
  • Tab order follows stacking order; lift()/lower() change it
  • Use tk_focusNext() to find the next widget in order

Form Focus Handling

import tkinter as tk
from tkinter import ttk

root = tk.Tk()
fields = []
for r, name in enumerate(("Name", "Email", "Phone")):
    ttk.Label(root, text=name).grid(row=r, column=0, sticky="w", padx=4)
    e = ttk.Entry(root, width=28)
    e.grid(row=r, column=1, pady=2, padx=4)
    fields.append(e)

ttk.Button(root, text="?", takefocus=False).grid(row=0, column=2)  # no Tab

def next_field(event):
    event.widget.tk_focusNext().focus_set()
    return "break"                             # don't insert newline
def mark(event, on):
    event.widget.configure(style="Focus.TEntry" if on else "TEntry")

ttk.Style().configure("Focus.TEntry", fieldbackground="#fffbd6")
for e in fields:
    e.bind("<Return>", next_field)             # Enter acts like Tab
    e.bind("<FocusIn>", lambda ev: mark(ev, True))
    e.bind("<FocusOut>", lambda ev: mark(ev, False))

fields[0].focus_set()                          # start in Name
root.bind("<Control-l>", lambda e: print(root.focus_get()))
root.mainloop()

Code Explained

Entries are created in order, so Tab follows rows
takefocus=False removes the help button from the Tab cycle
tk_focusNext() gives the next widget; "break" stops default
<FocusIn>/<FocusOut> swap a highlighted style
focus_get() returns the focused widget object

⚠ Common Mistakes

  • Expecting accelerator= in menus to bind keys
  • Calling focus_set() before the window is mapped
  • Creating widgets out of visual order, scrambling Tab order

✓ Tips & Best Practices

  • Set initial focus to the first field users need
  • Reorder a Tab stop with w.lift(other) instead of re-creating it
  • Keep keyboard-only use working for every form

Quick Summary

  • One focused widget receives keys
  • Tab order = creation order
  • takefocus controls tab stops
  • Bind accelerator keys yourself
