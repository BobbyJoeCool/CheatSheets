after() & Timers

after() · after_cancel() · after_idle() · update_idletasks() · update() pitfalls · repeating timers

Scheduling Work on the Event Loop

after(ms, func, *args) asks Tk to call func once, at least ms milliseconds later, from the event loop. It returns an id you can pass to after_cancel(). Repeating timers are made by having the function reschedule itself. after_idle(func) runs once the loop has no pending events. update_idletasks() processes pending redraws and geometry work immediately, which is safe; update() processes all events, including clicks, and can re-enter your code unexpectedly.

Notes

  • Timing is a minimum, not exact; long callbacks delay timers
  • after(0, f) runs f as soon as the loop is free
  • Cancel pending timers before destroying widgets they touch
  • after without a function sleeps but blocks; avoid it
  • Each after callback must finish quickly

Clock, Countdown and Debounce

import tkinter as tk, time

root = tk.Tk()
clock = tk.Label(root, font=("Consolas", 24)); clock.pack(padx=20)
def tick():
    clock.config(text=time.strftime("%H:%M:%S"))
    root.after(1000 - int(time.time() * 1000) % 1000, tick)  # align to second
tick()

count = tk.IntVar(value=10)
tk.Label(root, textvariable=count).pack()
def countdown():
    if count.get() > 0:
        count.set(count.get() - 1)
        root.countdown_id = root.after(1000, countdown)
countdown()
tk.Button(root, text="Stop",
          command=lambda: root.after_cancel(root.countdown_id)).pack()

search = tk.Entry(root); search.pack(pady=6)
pending = None
def on_key(event):                     # debounce: run 300 ms after typing stops
    global pending
    if pending: root.after_cancel(pending)
    pending = root.after(300, lambda: print("search", search.get()))
search.bind("<KeyRelease>", on_key)
root.after_idle(lambda: print("UI ready"))

Code Explained

The clock reschedules itself, aligned to whole seconds
The countdown stores its id so Stop can cancel it
Debounce cancels the previous timer on every keystroke
Only the last pending search runs after typing pauses
after_idle runs once startup events are processed

⚠ Common Mistakes

  • time.sleep() in callbacks, freezing the window
  • Calling update() inside callbacks and re-entering handlers
  • Leaving timers running after their widget is destroyed

✓ Tips & Best Practices

  • Split long loops into chunks scheduled with after(0, …)
  • Debounce expensive work triggered by typing or resizing
  • Keep timer ids on self for clean cancellation

Quick Summary

  • after(ms, f) schedules; returns an id
  • Self-rescheduling = repeating timer
  • after_cancel stops it
  • Prefer update_idletasks over update
