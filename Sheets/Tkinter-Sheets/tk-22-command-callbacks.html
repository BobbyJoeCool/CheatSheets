Wiring Buttons to Functions

command= expects a callable that takes no arguments. To pass data, wrap the call in a lambda or functools.partial. The classic trap is late binding in loops: a lambda looks up loop variables when it runs, not when it's created, so every button ends up using the last value. Fix it by binding the current value as a default argument (lambda n=n: …) or with partial. Bound methods (self.save) are the cleanest choice in class-based apps.

Notes

  • command=f() calls f once immediately; drop the parentheses
  • partial freezes arguments at creation time
  • Callbacks run on the main thread and block the UI while running
  • A callback's return value is ignored for command=
  • Exceptions print to stderr; the app keeps running

Passing Arguments Safely

import tkinter as tk
from functools import partial

root = tk.Tk()
display = tk.StringVar(value="")
tk.Entry(root, textvariable=display, justify="right",
         font=("Consolas", 14)).grid(row=0, column=0, columnspan=3)

def press(key):
    display.set(display.get() + key)

# WRONG: all buttons would type "9" (late binding)
# for i, k in enumerate("123456789"):
#     tk.Button(root, text=k, command=lambda: press(k))

for i, k in enumerate("123456789"):            # default-arg capture
    tk.Button(root, text=k, width=4,
              command=lambda k=k: press(k)).grid(row=1 + i // 3,
                                                 column=i % 3)

tk.Button(root, text="0", width=4,
          command=partial(press, "0")).grid(row=4, column=1)
tk.Button(root, text="C", width=4,
          command=lambda: display.set("")).grid(row=4, column=0)
tk.Button(root, text="=", width=4,
          command=lambda: display.set(str(eval(display.get() or "0")))
          ).grid(row=4, column=2)
root.mainloop()

Code Explained

press(key) needs an argument, so it can't go in command bare
The commented loop shows the late-binding bug
k=k copies the current value into the lambda
partial(press, "0") is the import-based alternative
Demo only: never eval untrusted input in real apps

⚠ Common Mistakes

  • command=save() runs at startup, not on click
  • Loop lambdas capturing the loop variable by reference
  • Doing slow work in a callback and freezing the window

✓ Tips & Best Practices

  • Prefer methods for callbacks with real logic
  • Use partial when the intent is clearer than a lambda
  • Move long tasks to threads or after() (Sheets 50–51)

Quick Summary

  • command= takes a zero-argument callable
  • Use lambda or partial to pass data
  • Capture loop values with defaults
  • Keep callbacks short
