Toplevel Windows & Lifecycle

Toplevel · transient() · protocol("WM_DELETE_WINDOW") · destroy() · quit() · winfo_exists()

Extra Windows with Toplevel

A tk.Toplevel is an additional window that belongs to the same application and the same event loop as the root. It accepts the same wm methods as the root. transient(parent) marks it as a child window (no taskbar entry, stays above its parent). protocol("WM_DELETE_WINDOW", handler) intercepts the close button, so you can confirm or clean up first. Destroying the root destroys every Toplevel; destroying a Toplevel only removes that window.

Notes

  • Never create a second Tk(); use Toplevel
  • destroy() removes a window and all its child widgets
  • quit() stops mainloop() but leaves windows alive
  • winfo_exists() checks whether a window is still open
  • A Toplevel can be reused by hiding it with withdraw()

Opening and Closing a Toplevel

import tkinter as tk
from tkinter import ttk, messagebox

class App(tk.Tk):
    def __init__(self):
        super().__init__()
        self.settings = None
        ttk.Button(self, text="Settings…",
                   command=self.open_settings).pack(padx=20, pady=20)
        self.protocol("WM_DELETE_WINDOW", self.on_close)

    def open_settings(self):
        if self.settings and self.settings.winfo_exists():
            self.settings.lift()          # already open: bring to front
            return
        self.settings = win = tk.Toplevel(self)
        win.title("Settings")
        win.transient(self)               # child of the main window
        ttk.Label(win, text="Options go here").pack(padx=30, pady=20)
        ttk.Button(win, text="Close", command=win.destroy).pack(pady=8)

    def on_close(self):
        if messagebox.askokcancel("Quit", "Exit the app?", parent=self):
            self.destroy()

App().mainloop()

Code Explained

winfo_exists() prevents opening duplicate windows
lift() raises an existing window instead
transient(self) ties the window to the main one
win.destroy closes only the Toplevel
protocol replaces the default close behavior

⚠ Common Mistakes

  • Opening a new Toplevel on every click without checking
  • Using quit() to close; windows remain on screen
  • Forgetting self.destroy() inside a custom close handler

✓ Tips & Best Practices

  • Store the Toplevel on self so you can reuse or check it
  • Pass parent= to dialogs so they center on the right window
  • Use transient() for tool and settings windows

Quick Summary

  • Toplevel = extra window, same app
  • transient() for child windows
  • protocol("WM_DELETE_WINDOW", fn) intercepts close
  • destroy() removes, quit() just stops the loop
