Structuring Larger Apps

As apps grow, split them into pages (Frame subclasses), a controller (usually the tk.Tk subclass) that owns shared state and navigation, and a model layer with no Tk imports. A common navigation trick stacks all pages in the same grid cell and brings one forward with tkraise(). Pages talk to the controller, not to each other, and the model can be unit-tested without opening a window. This mirrors MVC without needing a framework.

Notes

  • Pass the controller into each page's constructor
  • Keep file, network and math code in the model
  • Use virtual events (<<Saved>>) to notify pages
  • Build pages lazily if they're expensive
  • One module per page keeps diffs small

Controller + Pages + tkraise()

import tkinter as tk
from tkinter import ttk

class Model:                                  # no Tk imports needed
    user = None
    def login(self, name): self.user = name.strip() or None; return self.user
class LoginPage(ttk.Frame):
    def __init__(self, parent, app):
        super().__init__(parent, padding=20); name = tk.StringVar()
        ttk.Entry(self, textvariable=name).pack(pady=6)
        ttk.Button(self, text="Log in", command=lambda: app.login(name.get())).pack()
class HomePage(ttk.Frame):
    def __init__(self, parent, app):
        super().__init__(parent, padding=20)
        self.msg = ttk.Label(self); self.msg.pack(pady=6)
        ttk.Button(self, text="Log out", command=lambda: app.show("LoginPage")).pack()
    def on_show(self, app): self.msg.config(text=f"Welcome, {app.model.user}")

class App(tk.Tk):
    def __init__(self):
        super().__init__(); self.model = Model()
        self.pages = {P.__name__: P(self, self) for P in (LoginPage, HomePage)}
        for p in self.pages.values(): p.grid(row=0, column=0, sticky="nsew")
        self.show("LoginPage")
    def show(self, name):
        page = self.pages[name]
        if hasattr(page, "on_show"): page.on_show(self)
        page.tkraise()
    def login(self, name):
        if self.model.login(name): self.show("HomePage")

Code Explained

Model holds state and rules, testable without a GUI
Pages receive the controller (app) to request actions
All pages share one grid cell; tkraise() picks the visible one
on_show hooks refresh a page when it appears
Navigation lives only in the controller

⚠ Common Mistakes

  • Pages reaching into each other's widgets
  • Database or HTTP calls inside button callbacks
  • Building every page with global variables

✓ Tips & Best Practices

  • Unit-test the model with pytest; no window needed
  • Give pages an on_show hook for refreshes
  • Prefer composition: small Frame components in pages
