Stacking Widgets with pack()

pack() places widgets one after another against a side of the remaining space in their parent: top (default), bottom, left or right. Each packed widget claims a full-width (or full-height) parcel. fill stretches the widget within its parcel, and expand=True lets the parcel grab leftover space when the window grows. Packing order matters: widgets packed first get space first and are the last to shrink, so pack toolbars and status bars before the main content.

Notes

  • fill = grow inside the parcel; expand = grow the parcel
  • padx/pady add space outside; ipadx/ipady inside
  • pack_forget() hides a widget and discards its pack options
  • before=/after= insert relative to an already packed widget
  • Best for simple rows, columns and edge-docked bars

Toolbar, Status Bar, Content

import tkinter as tk
from tkinter import ttk

root = tk.Tk()
root.geometry("420x260")

toolbar = ttk.Frame(root, padding=4)
toolbar.pack(side="top", fill="x")
for name in ("New", "Open", "Save"):
    ttk.Button(toolbar, text=name).pack(side="left", padx=2)
ttk.Button(toolbar, text="Help").pack(side="right")

status = ttk.Label(root, text="Ready", relief="sunken", anchor="w")
status.pack(side="bottom", fill="x")        # packed before content

sidebar = tk.Listbox(root, width=14)
sidebar.pack(side="left", fill="y")

editor = tk.Text(root)
editor.pack(side="left", fill="both", expand=True, padx=(4, 0))

status.pack_forget()                         # hide status bar
status.pack(side="bottom", fill="x", before=sidebar)  # show again
root.mainloop()

Code Explained

Toolbar docks to the top and stretches horizontally
Buttons pack left-to-right; Help sits at the far right
Status bar is packed before content so it never gets squeezed
Only the editor has expand=True, so it absorbs extra space
before=sidebar restores the bar's original packing slot

⚠ Common Mistakes

  • Using expand=True without fill, then wondering why it doesn't stretch
  • Packing the status bar last, so it gets cut off when shrinking
  • Mixing pack and grid for children of the same parent

✓ Tips & Best Practices

  • Pack edge bars first, the flexible area last
  • Use a Frame per row when you need several horizontal groups
  • Tuple padding padx=(4, 0) pads one side only

Quick Summary

  • Widgets stack against a side
  • fill stretches, expand claims space
  • Order of packing decides priority
  • Great for bars and simple stacks
