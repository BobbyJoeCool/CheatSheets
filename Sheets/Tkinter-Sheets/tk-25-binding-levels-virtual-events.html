Bind Tags and Custom Events

Each widget has a list of bindtags that decides which bindings run for an event, in order: the widget itself, its class ("Entry"), its toplevel window, then "all". bind() targets the widget, bind_class() a whole class, and bind_all() the "all" tag. A handler that returns "break" stops the remaining tags, which is how you override default behavior. Virtual events like <<Save>> are named events you define with event_add() or fire with event_generate().

Notes

  • Class bindings implement default widget behavior
  • Changing bind_class affects every widget of that class
  • Built-in virtual events: <<Copy>>, <<Paste>>, <<Modified>>
  • event_generate runs handlers immediately by default
  • when="tail" queues a generated event instead

Override, Broadcast, Signal

import tkinter as tk

root = tk.Tk()
entry = tk.Entry(root); entry.pack(padx=10, pady=10)
print(entry.bindtags())   # ('.!entry', 'Entry', '.', 'all')

def digits_only(e):
    if e.char and not e.char.isdigit() and e.keysym != "BackSpace":
        return "break"           # skip the class binding: no insert

entry.bind("<Key>", digits_only)

# Same shortcut for every widget in the app
root.bind_all("<Control-q>", lambda e: root.destroy())

# Virtual event mapped to two physical key combos
root.event_add("<<Save>>", "<Control-s>", "<F2>")
root.bind("<<Save>>", lambda e: print("saving…"))

# A custom signal any code can fire
root.bind("<<DataLoaded>>", lambda e: print("refresh UI"))
root.after(500, lambda: root.event_generate("<<DataLoaded>>"))

# Reorder tags: run toplevel bindings before the widget's own
tags = entry.bindtags()
entry.bindtags((tags[2], tags[0], tags[1], tags[3]))
root.mainloop()

Code Explained

Tag order: widget, class, toplevel, all
Returning "break" prevents the Entry class from inserting
bind_all catches Ctrl+Q anywhere in the app
event_add maps several key combos to <<Save>>
event_generate fires a custom event on demand

⚠ Common Mistakes

  • Returning "break" from a command= callback (no effect)
  • Using bind_class and changing every Entry by accident
  • Firing event_generate from a worker thread

✓ Tips & Best Practices

  • Use "break" for input filters and custom keys
  • Name app events <<Noun>> and fire them on state changes
  • Prefer bind_all for global shortcuts only

Quick Summary

  • Bindtags: widget → class → toplevel → all
  • "break" stops further handlers
  • bind_class / bind_all widen scope
  • Virtual events: <<Name>>
