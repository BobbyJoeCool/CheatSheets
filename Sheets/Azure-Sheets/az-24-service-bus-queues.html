Service Bus & Storage Queues

Reliable Messaging

Azure Service Bus is the enterprise message broker: queues for one consumer group, topics with subscriptions (each with filters) for fan-out. Receivers use peek-lock: a message is locked, processed, then completed, or returned on failure. Sessions give ordered processing per key, and failed messages move to a dead-letter queue. Storage Queues are a simpler, cheaper option.

Key Points

  • Peek-lock + complete gives at-least-once processing
  • Max delivery count (default 10) before dead-lettering
  • Duplicate detection drops repeats by message ID within a window
  • Event Hubs is for high-volume streams, not commands

Limits & Quotas

  • Message size: 256 KB (Standard), up to 100 MB (Premium)
  • Lock duration up to 5 minutes (renew for longer work)
  • Queue / topic size up to 5 GB on Standard; Premium scales with messaging units

Namespace, Queue, Topic

az servicebus namespace create -g rg-msg -n sb-shop -l eastus2 --sku Standard
az servicebus queue create -g rg-msg --namespace-name sb-shop -n orders \
    --max-delivery-count 10 --lock-duration PT1M \
    --enable-dead-lettering-on-message-expiration true
az servicebus topic create -g rg-msg --namespace-name sb-shop -n events
az servicebus topic subscription create -g rg-msg --namespace-name sb-shop \
    --topic-name events -n eu-only
az servicebus topic subscription rule create -g rg-msg \
    --namespace-name sb-shop \
    --topic-name events --subscription-name eu-only -n region \
    --filter-sql-expression "region = 'eu'"

Send and Receive (Python, managed identity)

from azure.identity import DefaultAzureCredential
from azure.servicebus import ServiceBusClient, ServiceBusMessage
sb = ServiceBusClient("sb-shop.servicebus.windows.net",
                      DefaultAzureCredential())
with sb.get_queue_sender("orders") as s:
    s.send_messages(ServiceBusMessage('{"id": 42}', message_id="42"))
with sb.get_queue_receiver("orders", max_wait_time=5) as r:
    for m in r:
        try:
            process(str(m)); r.complete_message(m)
        except Exception:
            r.abandon_message(m)            # retry until max delivery count

Code Explained

A subscription rule filters topic messages with SQL-like expressions
Setting message_id enables duplicate detection when turned on
complete_message removes it; abandon_message makes it visible again
Roles: Azure Service Bus Data Sender / Data Receiver

AWS / GCP Equivalent

  • AWS SQS (queues), SNS (topics), Amazon MQ (aws-24)

Cost Check

  • Basic / Standard: per operation; Standard adds a base monthly charge
  • Premium: per messaging unit per hour, predictable performance
  • Storage Queues cost a fraction of Service Bus for simple needs

Do & Don't

  • Do Make consumers idempotent and set message IDs
  • Do Alert on dead-letter queue depth
  • Don’t Hold a lock longer than its duration without renewing
  • Don’t Put large payloads in messages (store in Blob, send a link)

Local Testing

  • The Service Bus emulator runs in Docker with a config file of queues and topics
  • Azurite emulates Storage Queues
  • Service Bus Explorer (portal) peeks and resubmits messages

Production Checklist

  • Managed identity with Data Sender / Receiver roles
  • Dead-letter monitoring and replay process
  • Premium tier or zone redundancy for critical workloads
