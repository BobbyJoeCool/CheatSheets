Azure Container Registry

az acr create · az acr login · tag & push · ACR Tasks (az acr build) · retention & purge · geo-replication · pull with managed identity

Private Container Images

Azure Container Registry (ACR) stores container images and OCI artifacts (Helm charts, signatures). az acr login connects Docker, and ACR Tasks build images in Azure (az acr build) without a local Docker daemon. Pull with a managed identity holding AcrPull; Premium adds geo-replication, private endpoints and higher throughput.

Key Points

  • Login server: <name>.azurecr.io
  • Tags are mutable; deploy by digest or use immutable tags (tag locking)
  • Purge old images on a schedule with acr purge
  • Defender for Containers scans images for vulnerabilities

Security Check

  • Disable the admin user; use Entra ID and AcrPull / AcrPush roles
  • Private endpoint + public access disabled (Premium)
  • Scan images and block deploys with critical vulnerabilities

Limits & Quotas

  • Included storage: 10 GiB (Basic), 100 GiB (Standard), 500 GiB (Premium)
  • Geo-replication and private endpoints need Premium
  • Read / write throughput and webhooks scale with tier

Create, Build, Push, Pull

az acr create -g rg-app -n shopacr --sku Standard --admin-enabled false
az acr login -n shopacr

docker build -t shopacr.azurecr.io/api:1.4.0 .
docker push shopacr.azurecr.io/api:1.4.0

# Build in Azure from the current folder (no local Docker needed)
az acr build -r shopacr -t api:{{.Run.ID}} -t api:latest .

az acr repository list -n shopacr -o table
az acr repository show-tags -n shopacr --repository api --orderby time_desc

# Lock a release tag against overwrite
az acr repository update -n shopacr --image api:1.4.0 --write-enabled false

# Purge untagged and old images every day
az acr task create -r shopacr -n purge --schedule "0 3 * * *" \
    --cmd "acr purge --filter 'api:.*' --ago 30d --untagged" --context /dev/null

# Let a Container App / AKS pull with managed identity
az role assignment create --assignee-object-id $MI \
    --assignee-principal-type ServicePrincipal --role AcrPull \
    --scope $(az acr show -n shopacr --query id -o tsv)

Code Explained

az acr login fetches a token and configures Docker
{{.Run.ID}} gives each ACR Tasks build a unique tag
Disabling writes makes a tag effectively immutable
The purge task deletes untagged and month-old images daily

AWS / GCP Equivalent

  • AWS ECR, lifecycle policies, image scanning (aws-25)
  • GCP Artifact Registry, cleanup policies (gcp-25)

Cost Check

  • Fixed daily price per tier plus extra storage per GB
  • ACR Tasks bill per build-second
  • Purging old images keeps storage within the included amount

Do & Don't

  • Do Tag with version or commit SHA; deploy by digest
  • Do Schedule purge tasks
  • Don’t Enable the admin user for convenience
  • Don’t Deploy latest to production

Local Testing

  • Run a local registry: docker run -d -p 5000:5000 registry:2
  • Build with BuildKit locally; push to ACR only from CI
  • Trivy scans images locally before push

Production Checklist

  • Admin user disabled; AcrPull via managed identity
  • Vulnerability scanning with deploy gates
  • Premium with private endpoint and geo-replication where needed
