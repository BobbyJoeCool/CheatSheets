Sheet 35

Azure Developer CLI (azd)

azd init · templates · azure.yaml · azd up / provision / deploy · environments · azd pipeline config

From Code to Running App in One Command

The Azure Developer CLI (azd) ties application code to infrastructure (Bicep or Terraform in infra/) through an azure.yaml file. azd up provisions resources and deploys services; azd deploy ships code only. Environments hold per-stage settings, and azd pipeline config sets up GitHub Actions or Azure Pipelines with federated credentials.

Key Points

  • Start from a template: azd init -t <template> or the Awesome azd gallery
  • Service hosts: containerapp, appservice, function, staticwebapp, aks
  • Environment values live in .azure/<env>/.env
  • azd down --purge deletes everything including soft-deleted vaults

Everyday azd

azd auth login
azd init -t todo-python-mongo-aca        # or: azd init (detect existing code)
azd env new shop-dev
azd env set AZURE_LOCATION eastus2
azd up                                   # provision + deploy
azd deploy api                           # redeploy one service
azd monitor --overview                   # open Application Insights
azd env new shop-prod && azd up          # second environment
azd pipeline config --provider github    # CI/CD with OIDC
azd down --purge                         # remove everything

azure.yaml

name: shop
metadata: { template: shop@1.0.0 }
services:
  api:
    project: ./src/api
    language: python
    host: containerapp
  web:
    project: ./src/web
    language: js
    host: staticwebapp
    dist: dist
infra: { provider: bicep, path: infra }

Code Explained

A template brings app code, infra and the azure.yaml together
Each environment gets its own resource group and settings
azd deploy api updates only that service
pipeline config creates the identity, federated credential and workflow

AWS / GCP Equivalent

  • AWS AWS Copilot CLI / SAM / Amplify (aws-35, aws-36)
  • GCP Cloud Run --source deploys, Cloud Code (gcp-20)

Cost Check

  • azd is free; you pay for what the template provisions
  • Check the template's SKUs before azd up: samples may include premium tiers
  • azd down --purge avoids paying for forgotten resources

Do & Don't

  • Do Use separate azd environments per stage
  • Do Review infra/ before the first azd up
  • Don’t Commit .azure/ folders with environment secrets
  • Don’t Use azd in production without pinning template versions

Local Testing

  • azd runs locally against your subscription; app services can run locally with Docker / func start
  • Dev containers in many templates set up the toolchain
  • azd provision --preview shows planned changes

Production Checklist

  • Production environment deployed only by the generated pipeline
  • Template infra reviewed and SKUs right-sized
  • Environment settings stored in Key Vault / pipeline variables
