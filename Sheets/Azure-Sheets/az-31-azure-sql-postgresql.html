Azure SQL & PostgreSQL

Azure SQL Database vs Managed Instance · serverless & Hyperscale · Azure Database for PostgreSQL / MySQL Flexible Server · high availability · point-in-time restore · Entra authentication

Managed Relational Databases

Azure SQL Database is managed SQL Server with serverless (auto-pause, per-second billing) and Hyperscale (very large, fast scaling) options; SQL Managed Instance offers near-full SQL Server compatibility. Azure Database for PostgreSQL / MySQL Flexible Server runs the open-source engines with zone-redundant high availability, read replicas and point-in-time restore.

Key Points

  • Use Entra authentication and managed identities instead of SQL passwords
  • Zone-redundant HA keeps a standby in another zone
  • PITR restores to a new server or database
  • Private endpoints / VNet integration keep databases off the internet

Azure SQL (serverless) and PostgreSQL Flexible Server

az sql server create -g rg-data -n sql-shop -l eastus2 \
    --enable-ad-only-auth --external-admin-principal-type Group \
    --external-admin-name sg-dba --external-admin-sid <group-object-id>
az sql db create -g rg-data -s sql-shop -n shopdb \
    --edition GeneralPurpose --compute-model Serverless --family Gen5 \
    --capacity 2 --auto-pause-delay 60 --backup-storage-redundancy Zone

az postgres flexible-server create -g rg-data -n pg-shop -l eastus2 \
    --tier GeneralPurpose --sku-name Standard_D2ds_v5 --version 17 \
    --storage-size 128 --high-availability ZoneRedundant \
    --public-access None --microsoft-entra-auth Enabled --password-auth Disabled
az postgres flexible-server replica create -g rg-data \
    --replica-name pg-shop-read --source-server pg-shop

az postgres flexible-server restore -g rg-data -n pg-shop-restored \
    --source-server pg-shop --restore-time "2026-11-12T08:00:00Z"

Connect With an Entra Token (Python)

import psycopg
from azure.identity import DefaultAzureCredential
tok = DefaultAzureCredential().get_token(
    "https://ossrdbms-aad.database.windows.net/.default").token
conn = psycopg.connect(host="pg-shop.postgres.database.azure.com",
                       dbname="shop", user="app-identity", password=tok,
                       sslmode="require")

Code Explained

Entra-only auth means no SQL logins with passwords
Serverless pauses after 60 idle minutes and bills storage only
Zone-redundant HA and a read replica for scale-out reads
The Entra access token is used as the PostgreSQL password

Cost Check

  • Serverless SQL bills per vCore-second while active; good for intermittent use
  • Zone-redundant HA roughly doubles compute cost
  • Reserved capacity discounts steady databases

Security Check

  • Enable Entra-only authentication where possible
  • Disable public network access; use private endpoints
  • Microsoft Defender for SQL / open-source databases for threat detection

Limits & Quotas

  • Point-in-time restore window: 1–35 days
  • Azure SQL General Purpose up to 4 TB; Hyperscale up to 128 TB
  • Flexible Server max connections depend on SKU

Do & Don't

  • Do Connect apps with managed identity tokens
  • Do Test PITR restores regularly
  • Don’t Expose databases with "Allow Azure services" and public access
  • Don’t Pick Burstable tiers for production with HA needs

Local Testing

  • Run SQL Server or PostgreSQL in Docker with the same version
  • Azure SQL Edge / SQL Server containers for local T-SQL work
  • Testcontainers for integration tests

Production Checklist

  • Entra auth, private endpoints, public access off
  • Zone-redundant HA and backups with suitable retention
  • Query Performance Insight / Query Store and alerts on DTU / CPU
