Secrets, Keys and Certificates

Azure Key Vault stores secrets (passwords, connection strings), cryptographic keys and TLS certificates. Access is controlled by Azure RBAC (the default for new vaults) or legacy access policies. Soft delete keeps deleted items recoverable, and purge protection stops anyone from permanently deleting them early. App Service and Functions can read secrets through Key Vault references without code.

Key Points

  • Vault names are global: https://kv-shop-prod.vault.azure.net
  • Secrets are versioned; reference a version or always the latest
  • Standard tier uses software keys; Premium adds HSM-backed keys
  • Managed HSM is a dedicated, single-tenant HSM pool

Vault, Secret, Reference

az keyvault create -n kv-shop-prod -g rg-shop -l eastus2 \
    --enable-rbac-authorization true --enable-purge-protection true \
    --public-network-access Disabled
KV=$(az keyvault show -n kv-shop-prod --query id -o tsv)

ME=$(az ad signed-in-user show --query id -o tsv)
az role assignment create --assignee $ME \
    --role "Key Vault Secrets Officer" --scope $KV
az keyvault secret set --vault-name kv-shop-prod -n db-password \
    --value '<from-a-file-or-pipeline>'
az keyvault secret show --vault-name kv-shop-prod -n db-password \
    --query id -o tsv                       # versioned URI

# App setting that resolves the secret at runtime
az webapp config appsettings set -g rg-shop -n app-shop-api --settings \
  "DB_PASS=@Microsoft.KeyVault(VaultName=kv-shop-prod;SecretName=db-password)"

az keyvault secret recover --vault-name kv-shop-prod -n db-password

Read in Python

from azure.identity import DefaultAzureCredential
from azure.keyvault.secrets import SecretClient
c = SecretClient("https://kv-shop-prod.vault.azure.net",
                 DefaultAzureCredential())
print(c.get_secret("db-password").value)

Code Explained

RBAC authorization and purge protection are set at creation
Secrets Officer can write; the app only needs Secrets User
The Key Vault reference syntax pulls the latest secret version
recover undoes a soft delete

AWS / GCP Equivalent

  • AWS Secrets Manager, KMS (aws-08)
  • GCP Secret Manager, Cloud KMS (gcp-08)
  • Key Vault combines secrets, keys and certificates in one service

Cost Check

  • Billed per 10,000 operations; HSM keys and Managed HSM cost more
  • Certificate renewals through partner CAs carry their own fees
  • Caching secrets in the app cuts both cost and throttling

Security Check

  • Turn on purge protection for production vaults
  • Disable public network access; use a private endpoint
  • Use RBAC roles (Key Vault Secrets User) instead of access policies

Limits & Quotas

  • Secret value up to 25 KB
  • Throttled per vault per region (thousands of GETs per 10 s); cache secrets
  • Soft delete retention 7–90 days (default 90)

Do & Don't

  • Do One vault per app per environment
  • Do Read secrets with managed identity and cache them briefly
  • Don’t Put secret values in Bicep parameters files or pipeline logs
  • Don’t Use access policies on new vaults

Local Testing

  • Use a dev vault in a sandbox subscription; there is no official local emulator
  • Tests can swap in an in-memory secret provider behind an interface
  • az keyvault secret list checks names without revealing values

Production Checklist

  • Purge protection and soft delete on
  • Private endpoint with public access disabled
  • Diagnostic logs to Log Analytics; alerts on access failures
