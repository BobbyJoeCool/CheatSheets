Azure's Identity Directory

Microsoft Entra ID (formerly Azure Active Directory) holds users, groups and application identities for a tenant. An app registration defines an application once; a service principal (shown as an enterprise application) is its instance in a tenant and is what you grant roles to. Conditional Access decides when sign-ins need MFA, a compliant device or are blocked.

Key Points

  • Entra ID controls sign-in; Azure RBAC (sheet 06) controls what you can do in Azure
  • Group-based access scales better than per-user grants
  • Managed identities are service principals Azure manages for you
  • Conditional Access needs Entra ID P1 or higher

Users, Groups and App Identities

# Users and groups
az ad user create --display-name "Ada Lovelace" \
    --user-principal-name ada@contoso.onmicrosoft.com \
    --password '<temp>' --force-change-password-next-sign-in true
az ad group create --display-name sg-shop-devs --mail-nickname sg-shop-devs
az ad group member add --group sg-shop-devs \
    --member-id $(az ad user show --id ada@contoso.onmicrosoft.com \
                  --query id -o tsv)

# App registration + service principal
APP=$(az ad app create --display-name shop-api --query appId -o tsv)
az ad sp create --id $APP
az ad sp list --display-name shop-api --query "[].{app:appId, id:id}" -o table

# Who am I and what tenant
az ad signed-in-user show --query userPrincipalName
az account show --query tenantId -o tsv

Code Explained

Users get a temporary password and must change it at first sign-in
Groups are the unit you grant roles to
An app registration plus sp create gives an identity you can grant roles
Object IDs (not names) are what role assignments use

AWS / GCP Equivalent

  • AWS IAM Identity Center / IAM users and roles (aws-05)
  • GCP Cloud Identity / Google Workspace accounts, groups (gcp-05)
  • Entra ID also handles SSO for Microsoft 365 and SaaS apps

Cost Check

  • Entra ID Free comes with every subscription
  • Conditional Access and PIM need P1 / P2 licenses
  • Guest (B2B) users are free up to generous monthly active user limits

Do & Don't

  • Do Require MFA for every user (security defaults or Conditional Access)
  • Do Keep two break-glass Global Administrator accounts excluded and monitored
  • Don’t Use Global Administrator for daily work
  • Don’t Create client secrets for apps that can use managed identity

Local Testing

  • Use a free developer tenant (Microsoft 365 Developer Program, if eligible) for experiments
  • az ad commands work in Cloud Shell with your user
  • jwt.ms decodes Entra ID tokens to inspect claims

Production Checklist

  • MFA enforced and legacy authentication blocked
  • Privileged Identity Management for admin roles
  • Sign-in and audit logs exported to Log Analytics
