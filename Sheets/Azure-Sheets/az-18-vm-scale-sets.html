Sheet 18

Virtual Machine Scale Sets

Flexible vs Uniform orchestration · instance count min / max · autoscale rules · scheduled profiles · upgrade policies · automatic instance repairs

Groups of Identical VMs

A Virtual Machine Scale Set (VMSS) manages a group of VMs from one model and spreads them across zones. Flexible orchestration (the default for new sets) uses regular VMs and allows mixing sizes and Spot; Uniform is the older identical-instance mode. Autoscale rules add or remove instances on metrics or schedules, and automatic repairs replace unhealthy instances.

Key Points

  • Upgrade policy decides how model changes roll out: Manual, Automatic or Rolling
  • Use a health extension or load balancer probe for repairs and rolling upgrades
  • Scheduled profiles scale up before business hours
  • Instance protection prevents specific instances from scale-in

Limits & Quotas

  • Up to 1,000 instances per scale set
  • Autoscale settings: up to 20 profiles each
  • Regional vCPU quotas cap scale-out (sheet 15)

Scale Set With Autoscale

az vmss create -g rg-app -n vmss-web --orchestration-mode Flexible \
    --image Ubuntu2404 --vm-sku Standard_D2ps_v6 --instance-count 2 \
    --zones 1 2 3 --platform-fault-domain-count 1 \
    --vnet-name vnet-shop-prod --subnet snet-app \
    --lb lb-api --backend-pool-name be \
    --custom-data cloud-init.yaml --generate-ssh-keys \
    --upgrade-policy-mode Rolling

az monitor autoscale create -g rg-app -n as-web \
    --resource vmss-web \
    --resource-type Microsoft.Compute/virtualMachineScaleSets \
    --min-count 2 --max-count 10 --count 2
az monitor autoscale rule create -g rg-app --autoscale-name as-web \
    --condition "Percentage CPU > 70 avg 5m" --scale out 2
az monitor autoscale rule create -g rg-app --autoscale-name as-web \
    --condition "Percentage CPU < 30 avg 10m" --scale in 1

az vmss update -g rg-app -n vmss-web --enable-automatic-repairs true \
    --automatic-repairs-grace-period 30
az vmss list-instances -g rg-app -n vmss-web -o table

Code Explained

Flexible mode spreads instances across the three zones
Rolling upgrades replace instances in batches using health signals
Scale out fast (2 at a time), scale in slowly
Automatic repairs wait 30 minutes after boot before judging health

AWS / GCP Equivalent

  • AWS Launch templates + Auto Scaling groups (aws-18)
  • GCP Instance templates + managed instance groups (gcp-18)

Cost Check

  • Scale sets are free; you pay for the VMs
  • Mix Spot and regular instances in Flexible mode for cheap burst capacity
  • Scheduled scale-in at night saves on predictable workloads

Upgrade Policies

PolicyBehavior
ManualYou upgrade instances
AutomaticAll at once (risky)
RollingBatches with health checks

Do & Don't

  • Do Use Rolling upgrades with a health probe
  • Do Keep instances stateless and replaceable
  • Don’t Scale on CPU alone when queue depth or latency is the real signal
  • Don’t Set min-count to 1 for production

Local Testing

  • Load-test with k6 or Azure Load Testing in a sandbox to tune rules
  • Test cloud-init locally (sheet 15) before baking into the model
  • az monitor autoscale show reviews rules before go-live

Production Checklist

  • Min 2+ instances across zones
  • Automatic repairs and rolling upgrades enabled
  • Autoscale notifications sent to the team
