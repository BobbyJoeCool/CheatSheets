Running Web Apps in Production

App Service hosts web apps, APIs and Functions on a plan (a set of VMs you pay for). Deployment slots run staging copies you can swap into production with warm-up and instant rollback. Scale up to a bigger tier or out to more instances, manually or with autoscale. Durable Functions adds stateful orchestrations to Functions.

Key Points

  • Many apps can share one plan; they share its CPU and memory
  • Slot settings marked "deployment slot setting" stay with the slot on swap
  • Always On keeps the app loaded (not available on Free / Shared)
  • Health check path removes unhealthy instances

Limits & Quotas

  • Deployment slots: 5 on Standard, 20 on Premium
  • Instances: up to 10 (Standard), 30 (Premium v3)
  • Free / Shared tiers have CPU minutes per day and no slots

Plans, Slots, Swaps

az appservice plan create -g rg-app -n asp-shop --sku P1v3 --is-linux \
    --number-of-workers 2 --zone-redundant
az webapp create -g rg-app -n app-shop-api -p asp-shop \
    --runtime "PYTHON:3.12"
az webapp config set -g rg-app -n app-shop-api --always-on true \
    --health-check-path /health

az webapp deployment slot create -g rg-app -n app-shop-api --slot staging
az webapp deploy -g rg-app -n app-shop-api --slot staging --src-path app.zip
az webapp deployment slot swap -g rg-app -n app-shop-api \
    --slot staging --target-slot production      # swap back to roll back

az appservice plan update -g rg-app -n asp-shop --sku P2v3   # scale up
az webapp log tail -g rg-app -n app-shop-api

Durable Functions Orchestrator (Python)

import azure.durable_functions as df
app = df.DFApp()
@app.orchestration_trigger(context_name="ctx")
def order_flow(ctx: df.DurableOrchestrationContext):
    paid = yield ctx.call_activity("charge", ctx.get_input())
    yield ctx.call_activity("ship", paid)

Code Explained

Zone-redundant plans need at least 2–3 instances
Deploy to staging, test, then swap; swapping back is the rollback
Scale up changes the tier for every app on the plan
The orchestrator replays from history, so it must be deterministic

AWS / GCP Equivalent

  • AWS Elastic Beanstalk / App Runner, Lambda aliases, Step Functions (aws-21)

Cost Check

  • You pay for plan instances whether apps are busy or idle
  • Slots run on the same plan: no extra charge, but they use capacity
  • Premium v3 / v4 often costs less per core than Standard

Do & Don't

  • Do Swap through a staging slot with warm-up
  • Do Mark per-environment settings as slot settings
  • Don’t Deploy directly to production slot
  • Don’t Pack CPU-heavy and latency-sensitive apps on one plan

Local Testing

  • func start runs Durable Functions locally with Azurite
  • Run the web app locally in Docker with the same image
  • az webapp log tail streams logs during tests

Production Checklist

  • Zone-redundant Premium plan with at least 3 instances
  • Health check path and autoscale rules
  • Slot swap deployments with automated smoke tests
