Generative AI on Azure

Microsoft Foundry (formerly Azure AI Foundry) is Azure's platform for models, agents and evaluations. You create a Foundry resource and projects, deploy models (OpenAI GPT models plus others from the catalog) with a deployment name and quota, then call them through the OpenAI-compatible v1 API (Responses or chat completions) using Entra ID. Content filters run by default; Foundry Agent Service builds tool-using agents.

Key Points

  • Deployment types: Global Standard, Data Zone, Standard (regional), Provisioned
  • Your code calls the deployment name, not the raw model name
  • Use the OpenAI SDK with an Azure base URL and Entra token provider
  • RAG: retrieve from Azure AI Search, then pass results to the model

Create a Resource and Deployment

az cognitiveservices account create -g rg-ai -n ai-shop -l eastus2 \
    --kind AIServices --sku S0 --custom-domain ai-shop \
    --disable-local-auth true
az cognitiveservices account deployment create -g rg-ai -n ai-shop \
    --deployment-name chat --model-name gpt-5-mini \
    --model-version <version> --model-format OpenAI \
    --sku-name GlobalStandard --sku-capacity 50
AI=$(az cognitiveservices account show -g rg-ai -n ai-shop --query id -o tsv)
az role assignment create --assignee-object-id $MI \
    --assignee-principal-type ServicePrincipal \
    --role "Cognitive Services OpenAI User" --scope $AI

Call It (Python, Entra ID)

from openai import OpenAI
from azure.identity import DefaultAzureCredential, get_bearer_token_provider
token = get_bearer_token_provider(
    DefaultAzureCredential(), "https://cognitiveservices.azure.com/.default")
client = OpenAI(base_url="https://ai-shop.openai.azure.com/openai/v1/",
                api_key=token)
resp = client.responses.create(
    model="chat",                                  # deployment name
    input="Summarize our return policy in 3 bullets.")
print(resp.output_text)

Code Explained

--disable-local-auth removes API keys from the resource
sku-capacity 50 sets thousands of tokens per minute for the deployment
The token provider refreshes Entra tokens for the OpenAI client
model is the deployment name you chose

Cost Check

  • Pay per input / output token on Standard deployments
  • Provisioned throughput: reserved capacity, hourly or monthly
  • Smaller models (mini / nano) cost a fraction for simple tasks

Security Check

  • Disable key-based auth; grant Cognitive Services OpenAI User to app identities
  • Private endpoints for the Foundry resource
  • Keep content filters on and log prompts responsibly

Limits & Quotas

  • Quota is tokens per minute (TPM) per model per region per subscription
  • Requests per minute follow from TPM; exceeding returns 429 with retry-after
  • Request quota increases in the Foundry portal

Do & Don't

  • Do Use Entra ID auth and managed identity
  • Do Handle 429s with retry-after and backoff
  • Don’t Ship API keys in client apps
  • Don’t Send sensitive data without checking data residency options

Local Testing

  • Call a dev deployment from a notebook with az login credentials
  • Prompt and evaluation work in the Foundry portal playground
  • Mock the OpenAI client in unit tests; test prompts with evals

Production Checklist

  • Key auth disabled, private endpoint, content filters on
  • Quota monitored with alerts on 429 rates
  • Evaluations run on prompt or model changes
