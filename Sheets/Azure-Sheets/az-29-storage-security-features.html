Sheet 29

Storage Security & Features

Entra ID data roles · SAS tokens (user delegation SAS) · disable shared key & anonymous access · versioning & soft delete · lifecycle management · static website hosting

Protecting and Managing Blob Data

Grant access with Entra ID data roles; when a client needs a temporary link, issue a user delegation SAS signed with Entra credentials rather than account keys. Versioning, soft delete and immutability protect against overwrites, deletes and ransomware. Lifecycle management moves or deletes blobs by age, and static website hosting serves a $web container.

Key Points

  • Account-key SAS tokens cannot be revoked without rotating the key
  • User delegation SAS lasts up to 7 days and can be revoked by revoking delegation keys
  • Point-in-time restore for block blobs builds on versioning and change feed
  • Immutability policies make blobs write-once (WORM)

Security Check

  • Prefer user delegation SAS with short expiry and minimal permissions
  • Turn on versioning and soft delete for blobs and containers
  • Alert on any change that re-enables public or shared-key access

SAS, Protection, Lifecycle, Static Site

az storage blob generate-sas --account-name stshopdata -c uploads \
    -n 2026/11/photo.jpg --permissions r --expiry 2026-11-13T00:00Z \
    --as-user --auth-mode login --full-uri -o tsv

az storage account blob-service-properties update -n stshopdata -g rg-data \
    --enable-versioning true --enable-delete-retention true \
    --delete-retention-days 14 --enable-container-delete-retention true \
    --container-delete-retention-days 14

az storage account management-policy create -n stshopdata -g rg-data \
    --policy @lifecycle.json

az storage blob service-properties update --account-name stshopdata \
    --static-website --index-document index.html --404-document 404.html \
    --auth-mode login
az storage account show -n stshopdata --query primaryEndpoints.web -o tsv

lifecycle.json

{ "rules": [{ "name": "age-out", "enabled": true, "type": "Lifecycle",
  "definition": {
    "filters": { "blobTypes": ["blockBlob"], "prefixMatch": ["logs/"] },
    "actions": { "baseBlob": {
      "tierToCool":    { "daysAfterModificationGreaterThan": 30 },
      "tierToArchive": { "daysAfterModificationGreaterThan": 180 },
      "delete":        { "daysAfterModificationGreaterThan": 730 } } } } }] }

Code Explained

--as-user signs the SAS with a user delegation key from Entra ID
Soft delete keeps deleted blobs and containers for 14 days
The lifecycle rule cools logs at 30 days, archives at 180, deletes at 2 years
Static website content goes in the $web container

AWS / GCP Equivalent

  • AWS S3 bucket policies, presigned URLs, versioning, lifecycle (aws-29)
  • GCP IAM, signed URLs, versioning, soft delete, lifecycle (gcp-29)

Cost Check

  • Versions and soft-deleted blobs bill as normal storage: pair with lifecycle cleanup
  • Lifecycle actions are free; tier changes bill transaction fees
  • Static website hosting is cheap; add Front Door for HTTPS on custom domains

Do & Don't

  • Do Issue SAS links valid for minutes or hours, read-only
  • Do Pair versioning with lifecycle rules that delete old versions
  • Don’t Embed long-lived account-key SAS tokens in apps
  • Don’t Serve a public site straight from a public container

Local Testing

  • Azurite supports SAS generation and soft delete for testing
  • Validate lifecycle JSON with az storage account management-policy show in a sandbox
  • Test static sites locally with npx serve

Production Checklist

  • Versioning, soft delete and lifecycle cleanup configured
  • Only user delegation SAS allowed (policy / key access disabled)
  • Front Door with HTTPS in front of static websites
