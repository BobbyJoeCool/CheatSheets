Event-Driven Code

Azure Functions runs code in response to triggers (HTTP, timer, queue, blob, Event Grid, Cosmos DB…) and connects to services with input / output bindings instead of SDK boilerplate. The Flex Consumption plan is the recommended serverless option: scale to zero, fast scale-out, VNet integration and per-instance memory sizes. The Python v2 and Node.js v4 models declare functions in code with decorators.

Key Points

  • A function app is the unit of deploy and scale; it holds many functions
  • Each app needs a storage account for its runtime state
  • App settings become environment variables
  • Use identity-based connections (__accountName, __fullyQualifiedNamespace) instead of keys

function_app.py (Python v2 model)

import azure.functions as func, logging, json
app = func.FunctionApp()

@app.route(route="orders", methods=["POST"], auth_level=func.AuthLevel.FUNCTION)
@app.queue_output(arg_name="msg", queue_name="orders",
                  connection="QueueConn")
def create_order(req: func.HttpRequest,
                 msg: func.Out[str]) -> func.HttpResponse:
    order = req.get_json()
    msg.set(json.dumps(order))              # output binding: enqueue
    return func.HttpResponse(status_code=202)

@app.timer_trigger(schedule="0 */15 * * * *", arg_name="t")
def cleanup(t: func.TimerRequest):
    logging.info("cleanup ran")

Build, Run, Publish

func init shop-func --python && cd shop-func
func start                                  # local runtime on :7071
az functionapp create -g rg-app -n func-shop --storage-account stshopfunc \
    --flexconsumption-location eastus2 --runtime python --runtime-version 3.12
func azure functionapp publish func-shop
az functionapp config appsettings set -g rg-app -n func-shop \
    --settings QueueConn__queueServiceUri=https://stshop.queue.core.windows.net

Code Explained

The HTTP function writes the order to a queue via an output binding
Timer schedules use six-field NCRONTAB (with seconds)
func start runs the same runtime locally
The __queueServiceUri suffix makes the binding use managed identity

AWS / GCP Equivalent

  • AWS Lambda handler, triggers, function URLs (aws-20)
  • GCP Cloud Run functions, Eventarc triggers (gcp-21)
  • Bindings have no direct AWS / GCP equivalent

Cost Check

  • Flex Consumption: per GB-second and executions, with a monthly free grant
  • Always-ready instances remove cold starts but bill continuously
  • The storage account and Application Insights add small costs

Security Check

  • Use Entra ID authentication (Easy Auth) or APIM in front, not just function keys
  • Identity-based connections for storage, Service Bus, Event Hubs
  • Restrict inbound with private endpoints or access restrictions

Limits & Quotas

  • Flex Consumption: 30-minute default timeout, can be raised; Consumption: 10-minute max
  • HTTP requests: about 230 seconds before the front end times out
  • Flex instance memory 512 MB, 2 GB or 4 GB; up to 1,000 instances

Do & Don't

  • Do Keep functions small and idempotent
  • Do Use output bindings to cut SDK code
  • Don’t Do heavy work inside an HTTP function past the 230-second limit
  • Don’t Store connection strings with keys in app settings

Local Testing

  • func start with Azurite for storage triggers
  • local.settings.json holds local app settings (never commit secrets)
  • VS Code Azure Functions extension debugs locally

Production Checklist

  • Identity-based connections and Key Vault references
  • Application Insights with alerts on failures
  • Auth in front (Easy Auth / APIM); function keys not the only control
