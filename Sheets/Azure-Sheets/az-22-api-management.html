API Management

A Gateway in Front of Your APIs

Azure API Management (APIM) publishes back-end APIs through a gateway with a developer portal. APIs contain operations; products bundle APIs for consumers with subscription keys. Policies (XML) transform requests and responses, validate JWTs, enforce rate limits and quotas, cache, and route to back ends, at global, product, API or operation scope.

Key Points

  • Import from OpenAPI, Functions, App Service or Logic Apps
  • Policy pipeline: inbound → backend → outbound → on-error
  • Named values hold settings and Key Vault secret references
  • v2 tiers deploy in minutes; classic tiers can take much longer

Create and Import

az apim create -g rg-api -n apim-shop -l eastus2 --sku-name BasicV2 \
    --publisher-email api@contoso.com --publisher-name Contoso
az apim api import -g rg-api --service-name apim-shop --api-id shop \
    --path shop --specification-format OpenApi \
    --specification-url https://app-shop-api.azurewebsites.net/openapi.json
az apim product create -g rg-api --service-name apim-shop \
    --product-id partners --product-name Partners \
    --subscription-required true --state published

Inbound Policy (XML)

<policies>
  <inbound>
    <base />
    <validate-jwt header-name="Authorization" failed-validation-httpcode="401">
      <!-- named value: Entra ID v2.0 .well-known/openid-configuration URL -->
      <openid-config url="{{entra-openid-config-url}}" />
      <audiences><audience>api://shop-api</audience></audiences>
    </validate-jwt>
    <rate-limit-by-key calls="100" renewal-period="60"
        counter-key="@(context.Request.IpAddress)" />
    <set-backend-service base-url="https://app-shop-api.azurewebsites.net" />
  </inbound>
  <backend><base /></backend>
  <outbound><base /></outbound>
  <on-error><base /></on-error>
</policies>

Code Explained

BasicV2 is a quick-to-provision production tier
The OpenAPI import creates operations automatically
validate-jwt rejects requests without a valid Entra ID token
The rate limit counts calls per caller IP (key on subscription or user instead if needed)

AWS / GCP Equivalent

  • AWS API Gateway (HTTP / REST APIs), usage plans (aws-22)
  • GCP API Gateway, Apigee (gcp-22)
  • APIM policies are closest to Apigee policies

Cost Check

  • Consumption: per-call pricing, no fixed fee
  • v2 tiers: fixed monthly per unit plus overage
  • Developer tier is cheap but has no SLA: never production

Security Check

  • Validate Entra ID tokens with validate-jwt; keys alone identify, they do not authenticate
  • Lock back ends to APIM only (private networking or managed identity)
  • Never return back-end error details to clients

Common Policies

PolicyDoes
validate-jwtCheck tokens
rate-limit-by-keyThrottle
quota-by-keyVolume caps
set-header / rewrite-uriTransform
cache-lookup / storeResponse cache
authentication-managed-identityCall back end as APIM

Do & Don't

  • Do Keep policies in source control (APIOps)
  • Do Use products to separate internal and partner access
  • Don’t Treat a subscription key as authentication
  • Don’t Put business logic in policy expressions

Local Testing

  • Test policies against a Developer-tier instance in a sandbox
  • The self-hosted gateway container can run locally against an APIM instance
  • Validate OpenAPI specs locally with Spectral before import

Production Checklist

  • JWT validation on every API
  • Back ends reachable only from APIM
  • Diagnostics to Application Insights; alerts on 4xx / 5xx spikes
