Guardrails and Threat Detection

Azure Policy evaluates resources against rules and can deny, audit or fix them, with initiatives grouping many policies. Microsoft Defender for Cloud scores your security posture and adds threat protection plans per service. The Activity Log records every management action, resource locks prevent accidental deletes, and Microsoft Sentinel is the SIEM for correlating it all.

Key Points

  • Policy effects: Deny, Audit, Modify, DeployIfNotExists, Append
  • Assign policies at management groups for broad coverage
  • Activity Log keeps 90 days; export it for longer retention
  • Defender CSPM foundational checks are free; plans per resource type are paid

Policy, Locks, Defender

# Require an "owner" tag on resource groups (built-in policy)
DEF=$(az policy definition list \
  --query "[?displayName=='Require a tag on resource groups'].name" -o tsv)
az policy assignment create -n require-owner-tag --policy $DEF \
    --scope /subscriptions/<sub-id> --params '{"tagName":{"value":"owner"}}'
az policy state summarize --subscription <sub-id>

# Prevent deletes on production
az lock create -n no-delete -g rg-shop-prod --lock-type CanNotDelete

# Defender plans and posture
az security pricing create -n VirtualMachines --tier Standard
az security pricing list -o table
az security secure-scores list -o table

# Export Activity Log to Log Analytics
az monitor diagnostic-settings subscription create -n activity-to-law \
    --location eastus2 --workspace <law-id> \
    --logs '[{"category":"Administrative","enabled":true}]'

Code Explained

Built-in policies are found by display name and assigned with parameters
policy state summarize counts compliant and non-compliant resources
A CanNotDelete lock blocks deletes even for Owners until removed
Diagnostic settings send Activity Log to a workspace for longer retention

Cost Check

  • Azure Policy is free for Azure resources
  • Defender plans bill per resource per hour (servers, storage, SQL…)
  • Sentinel bills on ingested GB: filter what you send

Policy Effects

EffectDoes
DenyBlock the request
AuditReport only
ModifyAdd / fix tags or properties
DeployIfNotExistsDeploy a missing setting
DisabledTurn off

Do & Don't

  • Do Start policies in Audit, then switch to Deny
  • Do Lock production resource groups against deletion
  • Don’t Assign hundreds of policies to one subscription by hand
  • Don’t Ignore Defender recommendations because the score looks fine

Local Testing

  • Test policy rules against sample JSON with the Azure Policy VS Code extension
  • PSRule for Azure and Checkov check Bicep / Terraform before deploy
  • Use a sandbox subscription to verify a Deny policy blocks what you expect

Production Checklist

  • Baseline initiative (e.g. Microsoft cloud security benchmark) assigned
  • Activity Log exported and retained per compliance
  • Defender plans on for production workloads
