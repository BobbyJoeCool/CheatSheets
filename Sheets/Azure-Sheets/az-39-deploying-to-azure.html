CI/CD Into Azure

Pipelines sign in with OIDC: GitHub Actions uses azure/login with a user-assigned identity or app registration that has a federated credential; Azure Pipelines uses a workload identity federation service connection. Deploy with slot swaps (App Service), revision traffic shifts (Container Apps) or IaC deployments, behind environment approvals.

Key Points

  • No client secrets or publish profiles in CI
  • Give the deploy identity only the roles it needs on target resource groups
  • Build once, deploy the same artifact to each environment
  • Tag resources with repo and commit for traceability

GitHub Actions: Build, Push, Deploy to Container Apps

on: { push: { branches: [main] } }
permissions: { id-token: write, contents: read }
jobs:
  deploy:
    runs-on: ubuntu-latest
    environment: production
    steps:
      - uses: actions/checkout@v4
      - uses: azure/login@v2
        with:
          client-id: ${{ vars.AZURE_CLIENT_ID }}
          tenant-id: ${{ vars.AZURE_TENANT_ID }}
          subscription-id: ${{ vars.AZURE_SUBSCRIPTION_ID }}
      - run: az acr build -r shopacr -t api:${{ github.sha }} .
      - run: |
          az containerapp update -g rg-app -n api \
            --image shopacr.azurecr.io/api:${{ github.sha }} \
            --tags commit=${{ github.sha }}

Azure Pipelines Step

- task: AzureCLI@2
  inputs:
    azureSubscription: sc-shop-prod      # workload identity federation
    scriptType: bash
    scriptLocation: inlineScript
    inlineScript: az deployment group create -g rg-shop-prod -f infra/main.bicep

Code Explained

id-token: write is required for OIDC
The client ID belongs to the identity with the federated credential
az acr build builds in Azure, so the runner needs no Docker login
The service connection uses federation instead of a secret

AWS / GCP Equivalent

  • AWS configure-aws-credentials OIDC, CodeDeploy (aws-39)
  • GCP google-github-actions/auth, Cloud Deploy (gcp-39)

Cost Check

  • GitHub-hosted minutes and Azure Pipelines parallel jobs have free tiers
  • ACR Tasks builds bill per second
  • Staging slots and revisions reuse existing capacity

Security Check

  • Federated subjects bound to protected environments (environment:production)
  • Deploy identity scoped to specific resource groups, not the subscription
  • Disable basic auth publishing credentials on App Service

Do & Don't

  • Do Gate production with environment approvals
  • Do Promote one immutable image by digest or SHA tag
  • Don’t Use publish profiles or client secrets
  • Don’t Give the pipeline Owner on the subscription

Local Testing

  • act runs workflows locally (OIDC steps need GitHub)
  • actionlint validates workflow syntax
  • Run the same az commands from a laptop against a dev environment first

Production Checklist

  • OIDC-only pipeline identity with least privilege
  • Approvals and change records for production
  • Rollback documented (slot swap back / revision traffic shift)
