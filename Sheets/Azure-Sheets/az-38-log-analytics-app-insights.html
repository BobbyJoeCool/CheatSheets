Logs, Traces and KQL

A Log Analytics workspace stores logs in tables queried with KQL (Kusto Query Language). Application Insights (workspace-based) collects app requests, dependencies, exceptions and traces; instrument with the Azure Monitor OpenTelemetry distro. Table plans (Analytics, Basic, Auxiliary) and retention settings control cost.

Key Points

  • App Insights tables: AppRequests, AppDependencies, AppExceptions, AppTraces
  • Operation IDs join a request with its dependencies across services
  • Interactive retention up to 2 years; long-term retention up to 12 years
  • One workspace per environment or region is a common pattern

from azure.monitor.opentelemetry import configure_azure_monitor
from opentelemetry import trace

tracer = trace.get_tracer(__name__)

KQL Queries

AppRequests
| where TimeGenerated > ago(1h)
| summarize count(), p95 = percentile(DurationMs, 95) by Name, ResultCode
| order by p95 desc

AppExceptions
| where TimeGenerated > ago(24h)
| summarize n = count() by ProblemId
| top 10 by n

Create and Query

az monitor log-analytics workspace create -g rg-ops -n law-shop-prod \
    --retention-time 90
az monitor app-insights component create -g rg-ops -a ai-shop-prod \
    -l eastus2 --workspace law-shop-prod
az monitor log-analytics query -w <workspace-guid> \
    --analytics-query "AppRequests | take 5" -o table

Code Explained

One call wires traces, metrics and logs to Application Insights
Custom spans and attributes become searchable
summarize with percentile gives p95 latency per operation
The App Insights component points at a workspace

Cost Check

  • Analytics logs bill per GB ingested; Basic and Auxiliary plans are cheaper but limited
  • Commitment tiers discount high daily volumes
  • Sampling in App Insights cuts telemetry volume and cost

Limits & Quotas

  • Query results up to 500,000 rows or 64 MB
  • Query timeout 10 minutes
  • Daily cap optional; ingestion stops when reached

Do & Don't

  • Do Use workspace-based App Insights with the OpenTelemetry distro
  • Do Set retention per table to match need
  • Don’t Log at debug level in production without sampling
  • Don’t Create a workspace per resource

Local Testing

  • The OpenTelemetry console exporter prints spans during development
  • Run queries in the portal's Logs blade or Azure Data Explorer web UI against the workspace
  • Use the Kusto VS Code extension for KQL authoring

Production Checklist

  • Sampling and daily cap tuned
  • Alerts on failures and p95 latency from log queries
  • Retention and table plans set for cost and compliance
