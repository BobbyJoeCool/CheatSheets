Sheet 14

Front Door & Certificates

Azure Front Door Standard / Premium · origins & routes · rules engine · caching & purge · managed certificates · WAF policies

Global Entry Point

Azure Front Door is Microsoft's global layer-7 entry point: CDN caching, TLS termination with managed certificates, routing to origins in any region, health probes and failover, and a WAF. A profile holds endpoints; routes map domains and paths to origin groups. Premium adds Private Link origins and managed WAF rule sets with bot protection.

Key Points

  • Front Door (classic) retires on March 31, 2027: use Standard or Premium
  • Origins can be App Service, Container Apps, Storage, load balancers or any public host
  • Rules engine rewrites headers, redirects and changes cache behavior
  • Purge clears cached paths after a deploy

Security Check

  • Lock origins to Front Door only (Private Link or the X-Azure-FDID header + service tag)
  • Enable WAF in Prevention mode after tuning
  • Redirect HTTP to HTTPS on every route

Profile, Origin, Route, WAF

az afd profile create -g rg-web --profile-name afd-shop \
    --sku Premium_AzureFrontDoor
az afd endpoint create -g rg-web --profile-name afd-shop --endpoint-name shop

az afd origin-group create -g rg-web --profile-name afd-shop \
    --origin-group-name og-app --probe-path /health \
    --probe-protocol Https --probe-request-type GET \
    --probe-interval-in-seconds 30 --sample-size 4 \
    --successful-samples-required 3 \
    --additional-latency-in-milliseconds 50
az afd origin create -g rg-web --profile-name afd-shop \
    --origin-group-name og-app --origin-name eus2 \
    --host-name app-shop-eus2.azurewebsites.net \
    --origin-host-header app-shop-eus2.azurewebsites.net \
    --priority 1 --weight 1000 --enabled-state Enabled

az afd route create -g rg-web --profile-name afd-shop --endpoint-name shop \
    --route-name default --origin-group og-app \
    --supported-protocols Https Http --https-redirect Enabled \
    --forwarding-protocol HttpsOnly --link-to-default-domain Enabled

az afd endpoint purge -g rg-web --profile-name afd-shop \
    --endpoint-name shop --content-paths "/index.html"

Code Explained

Premium is needed for Private Link origins and managed WAF rules
The origin group health probe decides which origins get traffic
Origin host header must match what the back end expects
Routes tie the endpoint to the origin group and enforce HTTPS

AWS / GCP Equivalent

  • AWS CloudFront + ACM + AWS WAF; Global Accelerator (aws-14)
  • GCP Global external Application LB + Cloud CDN + Cloud Armor (gcp-14)
  • Front Door combines CDN, global L7 load balancing and WAF

Cost Check

  • Base fee per profile per month plus requests and data transfer
  • Premium costs much more than Standard: use it when you need Private Link or managed rules
  • Caching static content cuts origin compute and egress

Do & Don't

  • Do Cache static assets with long TTLs and versioned names
  • Do Use custom domains with managed certificates
  • Don’t Leave origins reachable directly from the internet
  • Don’t Purge /* on every release

Local Testing

  • Test origins locally first; Front Door has no emulator
  • curl -I https://shop.azurefd.net/app.js shows cache headers (x-cache)
  • Use a Standard profile in a sandbox to try routing rules cheaply

Production Checklist

  • Origins locked to Front Door (Private Link or FDID header check)
  • WAF policy in Prevention mode with logging
  • Two origins in different regions with health probes
