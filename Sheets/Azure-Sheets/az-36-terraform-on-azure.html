Terraform With Azure

The azurerm provider covers most Azure services with typed resources; azapi calls any ARM API version directly, useful for brand-new features. State lives in a storage account container with blob leases for locking. In CI, authenticate with OIDC (federated credentials) instead of client secrets.

Key Points

  • azurerm 4.x requires subscription_id in the provider block
  • Use use_azuread_auth = true for the state backend
  • Import existing resources with import blocks
  • Azure Verified Modules also exist for Terraform

Provider, Backend, Resources

terraform {
  required_providers {
    azurerm = { source = "hashicorp/azurerm", version = "~> 4.0" }
    azapi   = { source = "Azure/azapi", version = "~> 2.0" }
  }
  backend "azurerm" {
    resource_group_name  = "rg-tfstate"
    storage_account_name = "sttfstateshop"
    container_name       = "tfstate"
    key                  = "shop/prod.tfstate"
    use_azuread_auth     = true
    use_oidc             = true
  }
}

provider "azurerm" {
  features {}
  subscription_id = var.subscription_id
  use_oidc        = true
}

resource "azurerm_resource_group" "shop" {
  name     = "rg-shop-prod"
  location = "eastus2"
  tags     = { owner = "team-a", env = "prod" }
}

resource "azurerm_container_app_environment" "cae" {
  name                = "cae-shop-prod"
  resource_group_name = azurerm_resource_group.shop.name
  location            = azurerm_resource_group.shop.location
}

Code Explained

Version constraints keep provider upgrades deliberate
The backend stores state in a blob and locks with leases
use_oidc reads the GitHub OIDC token in CI
Resources reference each other to build dependencies

AWS / GCP Equivalent

  • AWS Terraform AWS provider, S3 state (aws-36)

Cost Check

  • Terraform CLI is free; HCP Terraform has free and paid tiers
  • State storage costs pennies
  • terraform plan in PRs catches costly changes (pair with Infracost)

Do & Don't

  • Do Lock provider versions and upgrade on purpose
  • Do One state file per environment and component
  • Don’t Store state locally or in git
  • Don’t Mix manual portal changes with Terraform-managed resources

Local Testing

  • terraform validate / fmt / tflint --enable-plugin=azurerm run offline
  • terraform plan against a sandbox subscription
  • Checkov / Trivy scan for misconfigurations

Production Checklist

  • Apply only from CI with OIDC and approvals
  • State account with versioning, soft delete and private access
  • Drift detection on a schedule
