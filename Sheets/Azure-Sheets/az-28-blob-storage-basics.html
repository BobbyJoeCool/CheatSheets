Blob Storage Basics

Object Storage on Azure

Blob Storage keeps objects (blobs) in containers inside a storage account, the unit that sets the name, region, redundancy and network rules. Access tiers trade storage price for read price: Hot, Cool, Cold and Archive. Redundancy ranges from three copies in one datacenter (LRS) to zone (ZRS) and cross-region (GRS / GZRS) replication.

Key Points

  • Endpoint: https://<account>.blob.core.windows.net/<container>/<blob>
  • Use --auth-mode login so the CLI uses Entra ID, not account keys
  • AzCopy is the fast tool for bulk copy and sync
  • Archive blobs must be rehydrated (hours) before reading

Security Check

  • Create accounts with anonymous access and shared keys disabled
  • Require TLS 1.2+ and HTTPS only
  • Use private endpoints or network rules for production accounts

Limits & Quotas

  • Default max capacity 5 PiB per account
  • 250 storage accounts per region per subscription (can be raised)
  • Single block blob up to about 190.7 TiB

Account, Container, Copy

az storage account create -g rg-data -n stshopdata -l eastus2 \
    --sku Standard_ZRS --kind StorageV2 --min-tls-version TLS1_2 \
    --allow-blob-public-access false --allow-shared-key-access false
az role assignment create --assignee $ME \
    --role "Storage Blob Data Contributor" \
    --scope $(az storage account show -n stshopdata --query id -o tsv)

az storage container create --account-name stshopdata -n uploads \
    --auth-mode login
az storage blob upload --account-name stshopdata -c uploads \
    -f photo.jpg -n 2026/11/photo.jpg --auth-mode login
az storage blob upload-batch --account-name stshopdata -d uploads \
    -s ./images --pattern "*.jpg" --auth-mode login
az storage blob list --account-name stshopdata -c uploads \
    --prefix 2026/ --auth-mode login -o table
az storage blob set-tier --account-name stshopdata -c uploads \
    -n 2026/11/photo.jpg --tier Cool --auth-mode login

azcopy login
azcopy sync ./site "https://stshopdata.blob.core.windows.net/site" \
    --delete-destination=true

Code Explained

ZRS keeps copies in three zones of the region
With shared keys off, you need a data role (Blob Data Contributor)
upload-batch uploads a folder by pattern
AzCopy sync mirrors a folder and can delete extra blobs

AWS / GCP Equivalent

  • AWS S3 buckets and storage classes (aws-28)

Cost Check

  • Billed for capacity per tier, operations, retrieval (cool / cold / archive) and egress
  • Early deletion fees: Cool 30, Cold 90, Archive 180 days
  • GRS roughly doubles storage price versus LRS

Do & Don't

  • Do One account per app / environment with clear names
  • Do Use lifecycle rules to move old data to colder tiers (sheet 29)
  • Don’t Hand out account keys or connection strings
  • Don’t Read archive data frequently (rehydration fees and delays)

Local Testing

  • Azurite emulates Blob, Queue and Table storage: docker run -p 10000:10000 mcr.microsoft.com/azure-storage/azurite
  • Azure Storage Explorer browses Azurite and real accounts
  • Connection string UseDevelopmentStorage=true targets Azurite

Production Checklist

  • Anonymous access and shared keys disabled
  • ZRS or GZRS for production data
  • Private endpoint, soft delete and versioning enabled
