Sheet 37

Azure Monitor Metrics & Alerts

platform metrics · diagnostic settings · alert rules · action groups · Workbooks & dashboards · az monitor metrics list

Watching Resources

Azure Monitor collects platform metrics for every resource automatically (CPU, requests, latency). Diagnostic settings send resource logs and metrics to Log Analytics, storage or Event Hubs. Alert rules fire on metric thresholds, log queries or activity log events, and notify action groups (email, SMS, webhooks, Functions, ITSM). Workbooks build interactive reports.

Key Points

  • Platform metrics are kept 93 days
  • Dynamic thresholds learn normal patterns
  • Alert processing rules suppress alerts during maintenance
  • Azure Monitor Baseline Alerts (AMBA) give recommended alert sets

Metrics, Action Groups, Alerts

VM=$(az vm show -g rg-app -n vm-web-1 --query id -o tsv)
az monitor metrics list --resource $VM --metric "Percentage CPU" \
    --interval PT5M --aggregation Average -o table

az monitor action-group create -g rg-ops -n ag-oncall --short-name oncall \
    --action email oncall ops@contoso.com \
    --action webhook teams https://contoso.webhook.office.com/...

az monitor metrics alert create -g rg-ops -n cpu-high --scopes $VM \
    --condition "avg Percentage CPU > 80" --window-size 5m \
    --evaluation-frequency 1m --severity 2 --action ag-oncall

# Send a resource's logs to Log Analytics
az monitor diagnostic-settings create -n to-law --resource $KV \
    --workspace $LAW --logs '[{"categoryGroup":"allLogs","enabled":true}]' \
    --metrics '[{"category":"AllMetrics","enabled":true}]'

az monitor activity-log alert create -g rg-ops -n rg-deleted \
    --condition category=Administrative and \
      operationName=Microsoft.Resources/subscriptions/resourceGroups/delete \
    --action-group ag-oncall

Code Explained

metrics list pulls data points for a time grain
One action group can notify many channels
The alert evaluates every minute over a 5-minute window
Activity log alerts fire on management events such as deletes

Cost Check

  • Platform metrics are free; metric alert rules bill per time series monitored
  • Log ingestion via diagnostic settings bills per GB
  • Send only needed log categories; use Basic / Auxiliary tables for verbose logs

Do & Don't

  • Do Alert on user-impacting symptoms with runbook links
  • Do Use alert processing rules for maintenance windows
  • Don’t Alert on every metric at Sev 0
  • Don’t Send all log categories from every resource without a plan

Local Testing

  • Query metrics with the CLI against a dev subscription
  • Test webhooks with a request bin before wiring production channels
  • Workbooks can be authored in a sandbox and exported as JSON

Production Checklist

  • Baseline alerts (AMBA) deployed for core services
  • Action groups with on-call rotation integration
  • Service health and resource health alerts enabled
