Managed Kubernetes on Azure

Azure Kubernetes Service (AKS) runs the Kubernetes control plane for you; you choose node pools, networking and add-ons. AKS Automatic goes further, managing nodes, scaling, upgrades and security defaults. Workload identity lets pods use Entra ID identities through federated credentials. Attaching ACR lets nodes pull images without secrets.

Key Points

  • System node pool runs cluster add-ons; user pools run apps
  • Azure CNI Overlay is the common default network mode
  • Upgrades: control plane first, then node pools (auto-upgrade channels available)
  • See the Kubernetes set for kubectl and manifests

Cluster, Pools, Identity

az aks create -g rg-aks -n aks-shop -l eastus2 --tier standard \
    --node-count 3 --zones 1 2 3 --node-vm-size Standard_D4ps_v6 \
    --network-plugin azure --network-plugin-mode overlay \
    --enable-oidc-issuer --enable-workload-identity \
    --attach-acr shopacr --generate-ssh-keys
# Or let Azure manage nodes and defaults
az aks create -g rg-aks -n aks-auto --sku automatic -l eastus2

az aks get-credentials -g rg-aks -n aks-shop
kubectl get nodes -o wide

az aks nodepool add -g rg-aks --cluster-name aks-shop -n spot \
    --priority Spot --eviction-policy Delete --spot-max-price -1 \
    --enable-cluster-autoscaler --min-count 0 --max-count 10

# Workload identity: federate a Kubernetes service account
ISSUER=$(az aks show -g rg-aks -n aks-shop \
    --query oidcIssuerProfile.issuerUrl -o tsv)
az identity federated-credential create -g rg-aks --identity-name id-api \
    -n api-sa --issuer $ISSUER \
    --subject system:serviceaccount:shop:api \
    --audiences api://AzureADTokenExchange

az aks get-upgrades -g rg-aks -n aks-shop -o table
az aks upgrade -g rg-aks -n aks-shop --kubernetes-version <version>

Code Explained

Standard tier adds the uptime SLA and larger scale limits
--attach-acr grants the kubelet identity AcrPull
A Spot pool scales from zero for cheap batch work
Pods using service account shop/api get the identity's Entra tokens

AWS / GCP Equivalent

  • AWS EKS, eksctl, Pod Identity, EKS Auto Mode (aws-27)
  • GCP GKE Standard / Autopilot, Workload Identity Federation (gcp-26, gcp-27)

Cost Check

  • Free tier: no cluster fee, no SLA; Standard tier: hourly fee per cluster
  • You pay for node VMs, disks and load balancers
  • Spot pools and the cluster autoscaler cut node cost

Limits & Quotas

  • Up to 5,000 nodes per cluster (Standard tier)
  • Up to 100 node pools per cluster
  • Up to 250 pods per node (set at pool creation)

Do & Don't

  • Do Use workload identity for pods; never mount cloud secrets as env vars by hand
  • Do Spread node pools across zones
  • Don’t Run apps on the system node pool
  • Don’t Fall far behind on Kubernetes versions (support windows are short)

Local Testing

  • kind / k3d / minikube test the same manifests locally
  • Bridge to Kubernetes / mirrord connect local code to a cluster
  • az aks command invoke runs kubectl against private clusters

Production Checklist

  • Standard tier, three zones, autoscaler bounds set
  • Auto-upgrade channel and maintenance windows configured
  • Workload identity, Key Vault CSI and Azure Policy enabled
