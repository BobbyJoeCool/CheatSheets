Sheet 07

Managed Identities & Federation

system- vs user-assigned identities · granting roles to an identity · federated credentials (GitHub Actions OIDC) · workload identity for AKS · no secrets in code

Identities Azure Manages for You

A managed identity is a service principal Azure creates and rotates automatically. System-assigned identities live and die with one resource; user-assigned identities are standalone and can be shared and pre-authorized. Federated credentials let outside workloads (GitHub Actions, Kubernetes pods, other clouds) exchange their own OIDC tokens for Azure tokens: no secrets anywhere.

Key Points

  • Enable on App Service, Functions, Container Apps, VMs, AKS and more
  • Grant roles to the identity's principal ID
  • User-assigned identities avoid role-assignment delays on new resources
  • Federated credential subjects pin exactly which repo / branch / environment may log in

Security Check

  • Scope federated subjects tightly (repo:org/app:environment:production)
  • Avoid wildcard-like broad subjects and shared identities across apps
  • Remove client secrets from app registrations once federation works

Create, Attach, Federate

# User-assigned identity attached to a web app
az identity create -g rg-shop -n id-shop-api
MI=$(az identity show -g rg-shop -n id-shop-api --query principalId -o tsv)
az webapp identity assign -g rg-shop -n app-shop-api \
    --identities $(az identity show -g rg-shop -n id-shop-api --query id -o tsv)
az role assignment create --assignee-object-id $MI \
    --assignee-principal-type ServicePrincipal \
    --role "Key Vault Secrets User" --scope $KV

# System-assigned on a VM
az vm identity assign -g rg-shop -n vm-worker

# Trust GitHub Actions for production deploys (no secret)
az identity federated-credential create -g rg-shop \
    --identity-name id-shop-deploy --name gh-prod \
    --issuer https://token.actions.githubusercontent.com \
    --subject repo:contoso/shop:environment:production \
    --audiences api://AzureADTokenExchange

Code Explained

The identity gets roles like any principal
--assignee-principal-type ServicePrincipal avoids lookup delays for new identities
The federated subject must match the GitHub token claim exactly
GitHub then uses azure/login with the identity's client ID (sheet 39)

AWS / GCP Equivalent

  • AWS IAM roles, instance profiles, OIDC providers (aws-07)
  • GCP Service accounts, Workload Identity Federation (gcp-07)

Cost Check

  • Managed identities and federated credentials are free
  • They remove the cost of secret rotation work and incidents
  • Up to 20 federated credentials per identity / app

Do & Don't

  • Do Use user-assigned identities in IaC so roles exist before the app starts
  • Do One identity per app or workload
  • Don’t Store a service principal secret in GitHub secrets
  • Don’t Reuse the deploy identity as the runtime identity

Local Testing

  • Locally, DefaultAzureCredential falls back to your az login
  • Grant your own user the same data role for local testing
  • The managed identity endpoint only exists inside Azure; do not try to mock it

Production Checklist

  • All apps use managed identities; zero client secrets
  • Federated credentials limited to protected environments
  • Identity role assignments reviewed quarterly
