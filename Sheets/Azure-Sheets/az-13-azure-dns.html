Sheet 13

Azure DNS & Traffic Manager

public & private zones · record sets · alias records · Traffic Manager routing methods · App Service domains

Names and Global Routing

Azure DNS hosts public zones on Microsoft's anycast name servers and private zones that resolve only inside linked VNets. Alias records point a name at an Azure resource (public IP, Front Door, Traffic Manager) and follow it if its IP changes. Traffic Manager is DNS-based global routing: priority failover, weighted, performance or geographic.

Key Points

  • Delegate a domain by setting the registrar's NS records to the zone's name servers
  • Alias records can sit at the zone apex where CNAMEs cannot
  • Private zones handle privatelink.* names for private endpoints
  • Traffic Manager works at DNS level; clients cache by TTL

Zones, Records, Traffic Manager

az network dns zone create -g rg-dns -n contoso-shop.com
az network dns zone show -g rg-dns -n contoso-shop.com --query nameServers

az network dns record-set a add-record -g rg-dns -z contoso-shop.com \
    -n api -a 20.42.10.5 --ttl 300
az network dns record-set cname set-record -g rg-dns -z contoso-shop.com \
    -n www -c shop.azurefd.net
az network dns record-set txt add-record -g rg-dns -z contoso-shop.com \
    -n @ -v "v=spf1 include:spf.protection.outlook.com -all"
# Alias A record at the apex pointing to a public IP resource
az network dns record-set a create -g rg-dns -z contoso-shop.com -n @ \
    --target-resource $(az network public-ip show -g rg-net -n pip-agw \
                        --query id -o tsv)

# Traffic Manager: primary region, failover to secondary
az network traffic-manager profile create -g rg-dns -n tm-shop \
    --routing-method Priority --unique-dns-name tm-contoso-shop \
    --monitor-path /health --protocol HTTPS --port 443
az network traffic-manager endpoint create -g rg-dns --profile-name tm-shop \
    -n eus2 --type azureEndpoints --priority 1 --target-resource-id <app-id>

Code Explained

Copy the zone's name servers to your registrar to delegate
TTL 300 keeps changes quick to propagate
The alias record follows the public IP resource, not a fixed address
Traffic Manager health-checks /health and fails over by priority

AWS / GCP Equivalent

  • AWS Route 53 hosted zones, alias, routing policies (aws-13)
  • GCP Cloud DNS zones and routing policies (gcp-13)
  • Traffic Manager ≈ Route 53 routing policies; Front Door adds L7

Cost Check

  • DNS zones bill monthly per zone plus per million queries
  • Traffic Manager bills per million queries and per health-checked endpoint
  • Alias queries to Azure resources are free

Do & Don't

  • Do Keep zones in IaC with records reviewed like code
  • Do Add CAA records for your certificate authority
  • Don’t Point a CNAME at the zone apex (use an alias record)
  • Don’t Set long TTLs on records you may fail over

Local Testing

  • dig NS contoso-shop.com confirms delegation
  • dig @<azure-ns> api.contoso-shop.com tests a record before delegation
  • CoreDNS or dnsmasq in Docker for local name experiments

Production Checklist

  • Zone records managed in IaC
  • Health-checked failover for critical names
  • DNSSEC signing considered for public zones
