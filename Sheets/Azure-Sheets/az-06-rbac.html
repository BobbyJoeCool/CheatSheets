Azure RBAC

role definitions · role assignments · scope (management group → subscription → resource group → resource) · Owner / Contributor / Reader · custom roles · az role assignment create

Who Can Do What in Azure

Azure role-based access control grants permissions by assigning a role to a principal at a scope. A role definition lists allowed actions (management plane) and data actions (reading blobs, secrets, messages). Assignments inherit downward: a role at a subscription applies to every resource group and resource inside it.

Key Points

  • Owner = full control including access; Contributor = full control minus access; Reader = view
  • Data access needs data roles (e.g. Storage Blob Data Contributor), not Contributor
  • Role changes can take a few minutes to apply
  • Prefer built-in roles; there are hundreds

Limits & Quotas

  • 4,000 role assignments per subscription
  • 5,000 custom roles per tenant
  • Assignments at management groups: 500 per group

Assign, List, Customize

# Grant a group Contributor on one resource group
az role assignment create --assignee-object-id <group-object-id> \
    --assignee-principal-type Group --role Contributor \
    --scope /subscriptions/<sub-id>/resourceGroups/rg-shop-dev

# Give an app identity read access to blobs in one storage account
az role assignment create --assignee <mi-principal-id> \
    --role "Storage Blob Data Reader" --scope $STG

# What can this principal do, everywhere?
az role assignment list --assignee <object-id> --all -o table
az role definition list --name "Key Vault Secrets User" \
    --query "[].permissions[].dataActions"

Custom Role (JSON)

{ "Name": "VM Operator",
  "Actions": ["Microsoft.Compute/virtualMachines/start/action",
              "Microsoft.Compute/virtualMachines/restart/action",
              "Microsoft.Compute/virtualMachines/read"],
  "AssignableScopes": ["/subscriptions/<sub-id>"] }

Code Explained

Scope is a resource ID; narrower scope means less access
--assignee-principal-type avoids a directory lookup and race conditions
--all lists assignments at every scope
Create the custom role with az role definition create --role-definition @vm-operator.json

AWS / GCP Equivalent

  • AWS IAM policies attached to roles / users (aws-06)
  • GCP IAM roles bound in allow policies (gcp-05, gcp-06)
  • AWS policies are documents you attach; Azure assigns a role at a scope

Cost Check

  • RBAC is free
  • Over-broad roles cost money indirectly: anyone with Contributor can create premium resources
  • Use Azure Policy to cap allowed SKUs if needed

Do & Don't

  • Do Assign roles to groups and managed identities
  • Do Use PIM for time-limited Owner access
  • Don’t Grant Owner at subscription scope to developers
  • Don’t Use Contributor where a data role is what the app needs

Local Testing

  • Test in a sandbox resource group with your own Reader-only test user
  • az role assignment list --assignee audits effective grants
  • Azure Portal "Check access" shows effective permissions

Production Checklist

  • No standing Owner assignments except break-glass
  • Assignments managed in IaC and reviewed
  • Alerts on role assignment changes (Activity Log)
