Picking the Right Azure Host

Azure offers a host for every level of control. App Service runs web apps and APIs from code or containers with slots and autoscale. Functions runs event-driven code. Container Apps runs containers serverlessly with scale-to-zero, revisions and Dapr. AKS gives full Kubernetes. VMs give the OS. Static Web Apps hosts front ends with optional APIs.

Key Points

  • App Service plans are always-on capacity you pay for even when idle
  • Container Apps and Functions (Flex / Consumption) scale to zero
  • Container Instances run a single container quickly (no orchestration)
  • Azure Batch handles large parallel jobs

Same App, Four Hosts

# App Service: code or container on a plan
az webapp up -n app-shop-api --runtime "PYTHON:3.12" --sku P0v3 -l eastus2

# Container Apps: serverless containers
az containerapp up -n shop-api -g rg-app -l eastus2 \
    --image shopacr.azurecr.io/api:1.4.0 --ingress external --target-port 8080

# Functions: event-driven code
az functionapp create -g rg-app -n func-shop --storage-account stshopfunc \
    --flexconsumption-location eastus2 --runtime python --runtime-version 3.12

# Static Web Apps: front end + optional API
az staticwebapp create -n swa-shop -g rg-app -l eastus2 \
    --source https://github.com/contoso/shop-web --branch main \
    --app-location "/" --output-location "dist" --login-with-github

Code Explained

az webapp up creates the plan and app and deploys the current folder
az containerapp up creates an environment if needed
Flex Consumption is the recommended serverless Functions plan
Static Web Apps wires a GitHub Actions workflow for you

AWS / GCP Equivalent

  • AWS EC2 vs Lambda vs ECS / Fargate vs EKS vs App Runner (aws-19)
  • GCP Compute Engine vs Cloud Run vs GKE vs App Engine (gcp-19)

Cost Check

  • App Service: fixed hourly per plan instance, many apps can share a plan
  • Container Apps / Functions Flex: per vCPU-second and memory, free monthly grants
  • AKS: nodes plus an optional Standard tier fee per cluster

Do & Don't

  • Do Start with Container Apps or App Service for HTTP workloads
  • Do Containerize so you can move between hosts
  • Don’t Pick AKS for one small app
  • Don’t Run one App Service plan per tiny app (share plans)

Local Testing

  • Functions Core Tools, Docker and kind cover local runs for each host
  • Azure Developer CLI (azd up) deploys templates to compare hosts quickly (sheet 35)
  • Static Web Apps CLI: swa start emulates routing and auth locally

Production Checklist

  • Host choice documented with expected cost
  • Autoscale bounds and health checks on the chosen host
  • Same container image promoted through environments
