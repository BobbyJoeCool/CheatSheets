NAT, Private Endpoints & Connectivity

NAT Gateway · service endpoints vs Private Endpoints (Private Link) · Private DNS zones · VNet peering · VPN Gateway · ExpressRoute · Virtual WAN

Getting In, Out and Across

NAT Gateway gives a subnet a fixed outbound public IP. A Private Endpoint places a PaaS service (storage, SQL, Key Vault) on a private IP in your VNet, with a Private DNS zone so its normal name resolves privately. Peering links VNets; VPN Gateway and ExpressRoute link on-premises; Virtual WAN manages hub-and-spoke at scale.

Key Points

  • Private endpoints beat service endpoints: traffic stays on a private IP
  • Each PaaS type has a private DNS zone, e.g. privatelink.blob.core.windows.net
  • Peering is not transitive: spoke A cannot reach spoke B through the hub without routing
  • ExpressRoute is a private circuit through a connectivity provider

NAT and a Private Endpoint for Blob Storage

az network public-ip create -g rg-net -n pip-nat --sku Standard
az network nat gateway create -g rg-net -n ng-shop --public-ip-addresses pip-nat
az network vnet subnet update -g rg-net --vnet-name vnet-shop-prod \
    -n snet-app --nat-gateway ng-shop

az network private-endpoint create -g rg-net -n pe-shopdata-blob \
    --vnet-name vnet-shop-prod --subnet snet-data \
    --private-connection-resource-id $STG --group-id blob \
    --connection-name shopdata-blob

az network private-dns zone create -g rg-net \
    -n privatelink.blob.core.windows.net
az network private-dns link vnet create -g rg-net -n link-shop \
    --zone-name privatelink.blob.core.windows.net \
    --virtual-network vnet-shop-prod --registration-enabled false
az network private-endpoint dns-zone-group create -g rg-net \
    --endpoint-name pe-shopdata-blob -n default \
    --private-dns-zone privatelink.blob.core.windows.net --zone-name blob

# Peer two VNets (run in both directions)
az network vnet peering create -g rg-net -n hub-to-spoke \
    --vnet-name vnet-hub --remote-vnet vnet-shop-prod --allow-vnet-access

Code Explained

The NAT gateway gives every VM in snet-app the same outbound IP
--group-id blob picks the storage sub-resource to expose
The DNS zone group keeps the private A record in sync
Peering needs a link from each side

Cost Check

  • NAT Gateway: hourly + per GB processed
  • Private endpoints: hourly + per GB in and out
  • Peering bills per GB in each direction; global peering costs more

Do & Don't

  • Do Centralize private DNS zones in a hub subscription
  • Do Disable public network access once private endpoints work
  • Don’t Forget DNS: a private endpoint without the zone still resolves publicly
  • Don’t Assume peering chains route automatically

Local Testing

  • nslookup shopdata.blob.core.windows.net from a VM shows whether DNS returns the private IP
  • Network Watcher connection troubleshoot tests paths
  • Practice hub-and-spoke in a sandbox with tiny VMs

Production Checklist

  • PaaS services reachable only through private endpoints
  • Private DNS zones linked to every VNet that needs them
  • Fixed outbound IPs (NAT Gateway) shared with partners who allow-list
