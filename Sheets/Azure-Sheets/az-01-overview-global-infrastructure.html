Microsoft's Cloud

Azure runs in 60+ regions; most large regions have three availability zones, and many are matched with a paired region for platform updates and recovery. Every request goes through Azure Resource Manager (ARM), which places each resource in a resource group inside a subscription, inside a Microsoft Entra tenant. Management groups sit above subscriptions to apply policy at scale.

Key Points

  • Region names: eastus2, westeurope, centralus
  • Zones are numbered 1, 2, 3; numbering is mapped per subscription
  • A resource group is a lifecycle boundary: delete it and everything inside goes
  • Every resource has a full resource ID used by RBAC, CLI and IaC

Explore the Hierarchy

az login
az account tenant list -o table              # tenants you can reach
az account management-group list -o table    # needs permission at root
az account list -o table                     # subscriptions
az account list-locations \
    --query "[].{name:name, geo:metadata.geographyGroup}" \
    -o table

az group create -n rg-shop-dev -l eastus2 --tags owner=team-a env=dev
az resource list -g rg-shop-dev -o table

# Every resource has an ID like this
# /subscriptions/<sub-id>/resourceGroups/rg-shop-dev/providers/
#   Microsoft.Storage/storageAccounts/shopdevdata
az resource show --ids <resource-id> --query location

Code Explained

az login opens a browser; --use-device-code works over SSH
Locations list shows the geography each region belongs to
Resource groups hold resources that share a lifecycle
Resource IDs name provider, type and resource in one path

AWS / GCP Equivalent

  • AWS Regions, AZs, Organizations / accounts (aws-01)
  • GCP Regions, zones, organization / folders / projects (gcp-01)
  • Azure adds the resource group layer: no direct AWS or GCP twin

Cost Check

  • Free account: credit for the first 30 days plus 12 months of select free services
  • Region choice changes price; compare in the pricing calculator
  • Zone-redundant SKUs often cost more than single-zone ones

Do & Don't

  • Do Name resource groups by app, env and region (rg-shop-prod-eus2)
  • Do Tag every resource group with owner and cost center
  • Don’t Mix unrelated apps in one resource group
  • Don’t Assume a region has every service: check product availability by region

Local Testing

  • Azure Cloud Shell has az, Bicep, Terraform and kubectl preinstalled
  • A free account sandbox with a budget alert is safe for practice
  • Microsoft Learn sandboxes give temporary subscriptions for exercises

Production Checklist

  • Management groups for prod / non-prod with policies attached
  • Zone-redundant SKUs for production services
  • Resource naming and tagging standards enforced by Azure Policy
