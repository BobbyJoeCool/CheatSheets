Authenticating Code

Azure SDKs authenticate with token credentials from the azure-identity library. DefaultAzureCredential tries a chain: environment variables, workload identity, managed identity, then developer tools such as the Azure CLI. The same code uses your az login on a laptop and the app's managed identity in Azure, with no secrets in code.

Key Points

  • Python: pip install azure-identity azure-storage-blob
  • JavaScript: npm i @azure/identity @azure/storage-blob
  • Assign data roles (e.g. Storage Blob Data Reader) to the identity
  • In production, a specific credential (ManagedIdentityCredential) avoids slow fallbacks

Security Check

  • Prefer managed identity; client secrets expire and leak
  • Disable shared keys on storage once identity access works
  • Grant data-plane roles, not Owner, to app identities

Python and JavaScript

from azure.identity import DefaultAzureCredential, ManagedIdentityCredential
from azure.storage.blob import BlobServiceClient

cred = DefaultAzureCredential()            # laptop: az login; Azure: MI
svc = BlobServiceClient("https://shopdata.blob.core.windows.net", cred)
for c in svc.list_containers():
    print(c.name)

prod_cred = ManagedIdentityCredential(client_id="<user-assigned-mi-id>")

JavaScript

import { DefaultAzureCredential } from "@azure/identity";
import { BlobServiceClient } from "@azure/storage-blob";
const svc = new BlobServiceClient(
  "https://shopdata.blob.core.windows.net", new DefaultAzureCredential());
for await (const c of svc.listContainers()) console.log(c.name);

Code Explained

No key or connection string appears in the code
client_id selects a user-assigned identity when several exist
The JS SDK uses the same credential pattern
Environment variables are the first link in the chain

  • Token requests to Entra ID are free
  • Key Vault calls for secrets are billed per 10,000 operations

Do & Don't

  • Do Use DefaultAzureCredential in dev and a specific credential in prod
  • Do Reuse one client per service across requests
  • Don’t Put connection strings with account keys in config files
  • Don’t Give the app identity Contributor when it only reads blobs

Local Testing

  • az login makes DefaultAzureCredential work locally
  • Azurite accepts the well-known dev account key or connection string UseDevelopmentStorage=true
  • Set AZURE_LOG_LEVEL / SDK logging to debug auth fallbacks

Production Checklist

  • Managed identity with least-privilege data roles
  • Shared key access disabled where supported
  • No client secrets; if unavoidable, stored in Key Vault and rotated
