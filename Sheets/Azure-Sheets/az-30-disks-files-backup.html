Block, File and Backup Storage

Managed disks are block devices attached to VMs, sized and tiered independently. Azure Files provides fully managed SMB and NFS file shares that many VMs, containers or on-premises machines can mount. Azure Backup protects VMs, disks, file shares, SQL and blobs with policies stored in Recovery Services or Backup vaults.

Key Points

  • Premium SSD v2 lets you set IOPS and throughput separately from size
  • Azure Files SMB works from Windows, macOS and Linux; NFS needs Premium
  • Azure File Sync caches shares on Windows servers
  • Backup vaults support soft delete and immutability

File Share and VM Backup

# Azure Files: share and mount (Linux, SMB)
az storage share-rm create -g rg-data --storage-account stshopfiles \
    -n shared --quota 100 --enabled-protocols SMB
sudo mount -t cifs //stshopfiles.file.core.windows.net/shared /mnt/shared \
    -o vers=3.1.1,credentials=/etc/smbcredentials/stshopfiles.cred,serverino

# Disk snapshot and restore to a new disk
az snapshot create -g rg-app -n snap-data --source disk-data --incremental true
az disk create -g rg-app -n disk-data-restored --source snap-data

# Azure Backup for a VM
az backup vault create -g rg-backup -n rsv-shop -l eastus2
az backup protection enable-for-vm -g rg-backup --vault-name rsv-shop \
    --vm $(az vm show -g rg-app -n vm-web-1 --query id -o tsv) \
    --policy-name DefaultPolicy
az backup job list -g rg-backup --vault-name rsv-shop -o table

Code Explained

share-rm creates the share through Resource Manager
SMB 3.1.1 with encryption is required over the internet
A disk can be created straight from a snapshot
DefaultPolicy backs up daily and keeps 30 days

Cost Check

  • Disks bill by provisioned size (and IOPS / throughput for v2), not usage
  • Azure Files: by provisioned or used capacity depending on billing model
  • Backup: per protected instance plus vault storage

Do & Don't

  • Do Use Premium SSD v2 to tune IOPS without oversizing disks
  • Do Enable soft delete and immutability on backup vaults
  • Don’t Treat snapshots as your only backup
  • Don’t Mount SMB shares with account keys stored in plain files on many servers

Local Testing

  • Practice SMB mounts against a local Samba container
  • Restore drills: restore a VM backup to a new resource group
  • fio benchmarks disk IOPS on a test VM

Production Checklist

  • Backup policies on every production VM and file share
  • Restore tested on a schedule
  • Vault soft delete, immutability and cross-region restore where required
