Private Networking on Azure

A virtual network (VNet) is a regional private address space split into subnets that span the region's zones. Azure adds system routes automatically; route tables (user-defined routes) override them, for example to send traffic through a firewall. Some PaaS services need a delegated subnet. New VNets now have private subnets by default: VMs need an explicit outbound path.

Key Points

  • Default outbound access for new VNets retired on March 31, 2026
  • Outbound options: NAT Gateway, load balancer outbound rules, public IP, firewall
  • Azure reserves 5 addresses in every subnet
  • Some services need dedicated subnets (Application Gateway, Bastion, Firewall)

Security Check

  • Do not attach public IPs to VMs; use Bastion and a load balancer
  • Put an NSG on every subnet (sheet 12)
  • Use private endpoints for PaaS services in the VNet (sheet 11)

Limits & Quotas

  • 1,000 VNets per subscription per region
  • 3,000 subnets per VNet
  • 500 peerings per VNet

VNet, Subnets, Routes

az network vnet create -g rg-net -n vnet-shop-prod -l eastus2 \
    --address-prefixes 10.20.0.0/16 \
    --subnet-name snet-app --subnet-prefixes 10.20.1.0/24
az network vnet subnet create -g rg-net --vnet-name vnet-shop-prod \
    -n snet-data --address-prefixes 10.20.2.0/24
az network vnet subnet create -g rg-net --vnet-name vnet-shop-prod \
    -n snet-aca --address-prefixes 10.20.16.0/23 \
    --delegations Microsoft.App/environments

# Send all outbound traffic through a firewall appliance
az network route-table create -g rg-net -n rt-to-fw
az network route-table route create -g rg-net --route-table-name rt-to-fw \
    -n default --address-prefix 0.0.0.0/0 \
    --next-hop-type VirtualAppliance --next-hop-ip-address 10.20.255.4
az network vnet subnet update -g rg-net --vnet-name vnet-shop-prod \
    -n snet-app --route-table rt-to-fw

az network vnet subnet list -g rg-net --vnet-name vnet-shop-prod -o table

Code Explained

The VNet and its first subnet are created together
Container Apps environments need a delegated subnet
A 0.0.0.0/0 route to a virtual appliance forces traffic through the firewall
Route tables attach per subnet

AWS / GCP Equivalent

  • AWS VPC, subnets per AZ, route tables (aws-10)
  • GCP Global VPC, regional subnets, routes (gcp-10)
  • Azure subnets span zones like Google Cloud's, unlike AWS's one-AZ subnets

Cost Check

  • VNets and subnets are free; peering, gateways and NAT are billed
  • Data between zones in a region is billed per GB
  • Unused public IPs bill hourly

Do & Don't

  • Do Plan non-overlapping /16s per environment and region
  • Do Give each tier its own subnet with its own NSG
  • Don’t Rely on implicit outbound internet access for VMs
  • Don’t Make subnets so small that scaling or new services do not fit

Local Testing

  • Practice address plans with ipcalc before creating anything
  • Network Watcher "IP flow verify" and "Next hop" explain routing in Azure
  • Docker networks give a local feel for subnet isolation

Production Checklist

  • Address plan documented and non-overlapping with on-premises
  • Explicit outbound path (NAT Gateway or firewall) for every subnet
  • VNet flow logs enabled
