Azure Container Apps

environments · revisions & traffic splitting · ingress · scale rules (KEDA) · Dapr · jobs · az containerapp up

Serverless Containers

Azure Container Apps runs containers without managing Kubernetes. Apps live in an environment (a shared network and logging boundary). Each deploy creates a revision; in multiple-revision mode you can split traffic for canary releases. Scale rules (powered by KEDA) scale on HTTP concurrency, queues, events or CPU, including to zero. Jobs run scheduled or event-driven tasks.

Key Points

  • Ingress can be external or internal to the environment
  • Built-in Dapr adds service invocation, pub/sub and state APIs
  • Secrets can reference Key Vault via managed identity
  • Workload profiles add dedicated hardware options to the consumption model

Security Check

  • Use internal ingress for back-end services
  • Pull images and read secrets with managed identity (no registry passwords)
  • Deploy into your own VNet for private networking

Limits & Quotas

  • Up to 1,000 replicas per revision
  • Consumption replicas: up to 4 vCPU / 8 GiB each
  • Environment core quotas per region; request increases for large fleets

Environment, App, Revisions, Job

az containerapp env create -g rg-app -n cae-shop -l eastus2 \
    --infrastructure-subnet-resource-id $SUBNET_ACA

az containerapp create -g rg-app -n api --environment cae-shop \
    --image shopacr.azurecr.io/api:1.4.0 \
    --registry-server shopacr.azurecr.io --registry-identity $MI_ID \
    --user-assigned $MI_ID --ingress external --target-port 8080 \
    --min-replicas 0 --max-replicas 20 \
    --scale-rule-name http --scale-rule-type http \
    --scale-rule-http-concurrency 50 \
    --secrets "db-pass=keyvaultref:$SECRET_URI,identityref:$MI_ID" \
    --env-vars DB_PASSWORD=secretref:db-pass

# Canary: two revisions, 90/10 split
az containerapp revision set-mode -g rg-app -n api --mode multiple
az containerapp update -g rg-app -n api --image shopacr.azurecr.io/api:1.5.0
az containerapp ingress traffic set -g rg-app -n api \
    --revision-weight api--v14=90 latest=10

# Scheduled job
az containerapp job create -g rg-app -n nightly --environment cae-shop \
    --trigger-type Schedule --cron-expression "0 2 * * *" \
    --image shopacr.azurecr.io/batch:1.0 --replica-timeout 1800

Code Explained

The environment joins your VNet through a delegated subnet
Managed identity pulls the image and resolves the Key Vault secret
HTTP concurrency of 50 adds a replica per 50 concurrent requests
Traffic weights shift users between revisions gradually

AWS / GCP Equivalent

  • AWS ECS on Fargate, App Runner (aws-26)
  • GCP Cloud Run services and jobs (gcp-20, gcp-21)
  • Container Apps ≈ Cloud Run with built-in Dapr and KEDA

Cost Check

  • Consumption: per vCPU-second and GiB-second with a monthly free grant
  • Scale to zero means no compute charge when idle
  • Dedicated workload profiles bill per node like VMs

Do & Don't

  • Do Use multiple-revision mode for canaries and instant rollback
  • Do Keep min replicas at 1 for latency-sensitive APIs
  • Don’t Store registry passwords as secrets when managed identity works
  • Don’t Expose internal services with external ingress

Local Testing

  • Run the same image with docker run -p 8080:8080
  • Dapr CLI: dapr run emulates sidecar APIs locally
  • Docker Compose for multi-container local stacks

Production Checklist

  • Managed identity for registry and secrets
  • VNet-integrated environment with internal ingress for back ends
  • Health probes, min replicas and alerts set
