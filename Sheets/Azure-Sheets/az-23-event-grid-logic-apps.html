Reacting to Events and Orchestrating Steps

Event Grid routes discrete events from Azure services (system topics) or your apps (custom topics) to handlers such as Functions, queues, webhooks or Event Hubs, with filtering and retries. Logic Apps builds workflows with a designer and hundreds of connectors (Office 365, Salesforce, SQL, SAP), good for integration without much code.

Key Points

  • Event Grid uses push delivery with retry and dead-lettering to storage
  • Filters on event type, subject prefix / suffix and advanced fields
  • CloudEvents 1.0 is supported alongside the Event Grid schema
  • Logic Apps Standard runs single-tenant; Consumption is pay per action

React to Blob Uploads

FUNC_ID=$(az functionapp show -g rg-app -n func-shop --query id -o tsv)
az eventgrid system-topic create -g rg-app -n st-uploads-events \
    --location eastus2 --topic-type Microsoft.Storage.StorageAccounts \
    --source $STG
az eventgrid system-topic event-subscription create -g rg-app \
    --system-topic-name st-uploads-events -n on-upload \
    --endpoint-type azurefunction \
    --endpoint "$FUNC_ID/functions/onUpload" \
    --included-event-types Microsoft.Storage.BlobCreated \
    --subject-begins-with /blobServices/default/containers/uploads/ \
    --max-delivery-attempts 10 --event-ttl 1440 \
    --deadletter-endpoint $STG/blobServices/default/containers/deadletter

# Custom topic for your own events
az eventgrid topic create -g rg-app -n egt-orders \
    --input-schema cloudeventschemav1_0

Event Grid Trigger (Python)

@app.event_grid_trigger(arg_name="event")
def onUpload(event: func.EventGridEvent):
    url = event.get_json()["url"]           # the new blob
    logging.info("new upload %s", url)

Code Explained

A system topic represents events from one Azure resource
Filters limit events to new blobs in the uploads container
Undeliverable events go to a dead-letter container
The Functions trigger receives one event per invocation

AWS / GCP Equivalent

  • AWS EventBridge rules, Step Functions (aws-23)
  • GCP Eventarc, Workflows, Cloud Scheduler (gcp-23)
  • Logic Apps connectors have no close AWS / GCP twin

Cost Check

  • Event Grid: per million operations, first 100,000 free per month
  • Logic Apps Consumption: per action and connector call
  • Logic Apps Standard: hosting plan like App Service

Do & Don't

  • Do Filter at the subscription so handlers get only what they need
  • Do Configure dead-lettering and alert on it
  • Don’t Use Event Grid for ordered or transactional messaging
  • Don’t Build complex app logic in a Logic App designer

Local Testing

  • Functions Core Tools can receive Event Grid events via a local tunnel (e.g. VS Code dev tunnels / ngrok)
  • Post sample events to the local function with curl and the Event Grid schema
  • Logic Apps Standard runs locally in VS Code

Production Checklist

  • Dead-letter destinations and retry settings set
  • Handlers idempotent (events can repeat)
  • Metrics on delivery failures alerting
