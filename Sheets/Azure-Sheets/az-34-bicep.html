Bicep

Azure's Native IaC Language

Bicep is a concise language that compiles to ARM JSON templates. A file declares parameters, resources (with API versions), and outputs; modules reuse other Bicep files. Deploy with az deployment group create at resource group scope (or subscription, management group, tenant), preview with what-if, and use deployment stacks to manage and protect the resources a template owns.

Key Points

  • Resource references create dependencies automatically
  • @secure() hides parameter values from logs and history
  • Azure Verified Modules provide maintained, reusable modules
  • The Bicep VS Code extension gives IntelliSense from Azure APIs

main.bicep

@allowed(['dev', 'prod'])
param env string = 'dev'
param location string = resourceGroup().location

var name = 'stshop${env}${uniqueString(resourceGroup().id)}'

resource stg 'Microsoft.Storage/storageAccounts@2024-01-01' = {
  name: take(name, 24)
  location: location
  sku: { name: env == 'prod' ? 'Standard_ZRS' : 'Standard_LRS' }
  kind: 'StorageV2'
  properties: {
    allowBlobPublicAccess: false
    allowSharedKeyAccess: false
    minimumTlsVersion: 'TLS1_2'
  }
}

module kv 'br/public:avm/res/key-vault/vault:0.11.0' = {
  name: 'kv'
  params: { name: 'kv-shop-${env}', enablePurgeProtection: true }
}

output storageId string = stg.id

Deploy

az bicep build -f main.bicep                       # compile / lint
az deployment group what-if -g rg-shop-dev -f main.bicep -p env=dev
az deployment group create -g rg-shop-dev -f main.bicep -p env=dev
az stack group create -n shop -g rg-shop-prod -f main.bicep -p env=prod \
    --action-on-unmanage deleteResources --deny-settings-mode denyDelete

Code Explained

uniqueString builds a stable, unique storage name
The ternary picks ZRS for prod
The module pulls an Azure Verified Module from the public registry
Stacks delete removed resources and deny manual deletes

Cost Check

  • Bicep and ARM deployments are free
  • what-if catches accidental SKU upgrades before they bill
  • Stacks can clean up resources removed from the template, avoiding orphans

Security Check

  • Mark secrets @secure() and never output them
  • Read secrets from Key Vault with getSecret() in module parameters
  • Deny settings on deployment stacks block out-of-band deletes

Limits & Quotas

  • 800 resources per deployment (including copies)
  • 256 parameters, 256 variables, 64 outputs per template
  • Compiled template up to 4 MB

Do & Don't

  • Do Run what-if in pull requests
  • Do Use Azure Verified Modules for common resources
  • Don’t Hard-code secrets in parameter files
  • Don’t Deploy with --mode Complete without understanding it deletes unlisted resources

Local Testing

  • az bicep build and the linter run offline
  • PSRule for Azure checks templates against best practices
  • Bicep VS Code extension visualizes resource graphs

Production Checklist

  • Deployments from CI with OIDC (sheet 39)
  • what-if output reviewed before apply
  • Deployment stacks with deny settings for production resource groups
