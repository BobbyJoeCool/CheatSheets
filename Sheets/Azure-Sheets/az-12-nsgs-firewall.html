Sheet 12

NSGs & Azure Firewall

network security groups · rule priorities · service tags · application security groups · Azure Firewall · VNet flow logs

Filtering Traffic

A network security group (NSG) holds stateful allow / deny rules, attached to a subnet or a NIC. Rules run in priority order (100 first, 4096 last) and can use service tags (Internet, AzureLoadBalancer, Storage.EastUS2) and application security groups instead of IPs. Azure Firewall is a managed central firewall for hub networks with FQDN filtering and threat intelligence.

Key Points

  • Default rules (priority 65000+) allow VNet-to-VNet and load balancer probes, deny other inbound
  • NSG on subnet and NIC: both must allow the traffic
  • ASGs group VMs by role, e.g. asg-web, asg-db
  • VNet flow logs replace NSG flow logs

Security Check

  • Never allow 22 / 3389 from Internet; use Azure Bastion
  • Review rules with "Any" source or destination
  • Deny outbound to the internet from data subnets

Limits & Quotas

  • 1,000 rules per NSG
  • 5,000 NSGs per subscription
  • Priorities 100–4096 for custom rules

NSG With Service Tags and ASGs

az network nsg create -g rg-net -n nsg-app
az network asg create -g rg-net -n asg-web
az network asg create -g rg-net -n asg-db

az network nsg rule create -g rg-net --nsg-name nsg-app -n allow-https \
    --priority 100 --direction Inbound --access Allow --protocol Tcp \
    --source-address-prefixes Internet --destination-port-ranges 443 \
    --destination-asgs asg-web
az network nsg rule create -g rg-net --nsg-name nsg-app -n web-to-db \
    --priority 110 --direction Inbound --access Allow --protocol Tcp \
    --source-asgs asg-web --destination-asgs asg-db \
    --destination-port-ranges 5432
az network nsg rule create -g rg-net --nsg-name nsg-app -n deny-inet-out \
    --priority 4000 --direction Outbound --access Deny \
    --destination-address-prefixes Internet --destination-port-ranges '*'

az network vnet subnet update -g rg-net --vnet-name vnet-shop-prod \
    -n snet-app --network-security-group nsg-app
az network nsg rule list -g rg-net --nsg-name nsg-app --include-default -o table

Code Explained

The Internet service tag stands for all public addresses
ASGs let rules say "web may reach db" without IPs
A low-priority outbound deny blocks internet egress
NSGs attach to subnets (preferred) or individual NICs

AWS / GCP Equivalent

  • AWS Security groups (stateful), NACLs (stateless) (aws-12)
  • GCP VPC firewall rules and firewall policies (gcp-12)
  • NSGs can sit on subnets, which AWS security groups cannot

Cost Check

  • NSGs and ASGs are free
  • Azure Firewall bills hourly plus per GB processed: one per hub, not per spoke
  • Flow logs bill for storage and optional traffic analytics

Do & Don't

  • Do Leave gaps between priorities (100, 110, 120) for later rules
  • Do Use service tags for Azure services instead of IP ranges
  • Don’t Open broad port ranges to Internet
  • Don’t Stack NIC and subnet NSGs without documenting why

Local Testing

  • Network Watcher "IP flow verify" says which rule allows or blocks a packet
  • "Effective security rules" on a NIC shows the merged rule set
  • Test from a VM with nc -zv / curl after each change

Production Checklist

  • NSG on every subnet; no SSH / RDP from Internet
  • Central egress through Azure Firewall where required
  • VNet flow logs with traffic analytics enabled
