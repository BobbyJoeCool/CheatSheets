Sheet 03

Sharing, Comments & Version History

Viewer / Commenter / Editor · link sharing · expiring access · action items · version history · named versions · Approvals

One File, Many People

Share a file with people or a link and choose Viewer, Commenter or Editor. Comments can assign action items (+name), which email the person and show up in their task list. Version history keeps every change: name important versions, compare, and restore. Approvals (Workspace) collect sign-off on a final version.

Notes

  • Share: the Share button (top right) in any editor or . in Drive
  • Link sharing: Restricted, your organization, or Anyone with the link
  • Expiring access (Workspace): set an end date per person
  • Comment: ⌘⌥M / Ctrl+Alt+M; type +email to assign it
  • Version history: ⌘⌥⇧H / Ctrl+Alt+Shift+H

Share and Track Changes

  1. Click Share, add people, pick Viewer / Commenter / Editor
  2. Under General access, keep Restricted unless a link must work for others
  3. Settings (gear): stop editors changing permissions; stop viewers downloading
  4. Reviewers comment or use Suggesting mode (Docs, sheet 09)
  5. Before big edits: File › Version history › Name current version
  6. To roll back: open Version history, pick a version, Restore this version

⚠ Common Mistakes

  • Sharing with "Anyone with the link" for internal documents
  • Making copies to "freeze" a version instead of naming a version
  • Leaving editors able to reshare sensitive files; change it in Share settings

✓ Tips & Best Practices

  • Send /copy links for templates so people never edit your master
  • Assign comments with +name instead of emailing about them
  • Use Version history's Show changes to see who edited what

Quick Summary

  • Viewer / Commenter / Editor — roles
  • +name — assign a comment
  • Name current version — save milestones
  • /copy — force a copy
