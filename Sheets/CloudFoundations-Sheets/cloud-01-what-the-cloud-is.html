Renting Computing Instead of Owning It

A cloud provider runs data centers full of servers, storage and networks and rents them out through an API. You ask for a virtual machine, a database or a storage bucket and get it in minutes, pay only while you use it, and hand back what you no longer need. AWS, Microsoft Azure and Google Cloud are the three largest providers; most of their ideas match, only the names differ.

Key Points

  • Everything is an API call: the web console, CLI, SDKs and IaC tools all call the same APIs
  • The more the provider manages, the less you control (and the less you maintain)
  • Elasticity: scale up for a spike, back down afterwards
  • This set teaches each idea once; the provider sets show the details

The Same Request on Three Clouds

# Who am I, and which account / subscription / project am I in?
aws sts get-caller-identity
az account show --output table
gcloud config list

# Create a storage bucket (object storage, sheet 17)
aws s3 mb s3://demo-bucket-7f3a --region us-east-1
az storage account create -n demostore7f3a -g rg-demo -l eastus2
az storage container create -n demo --account-name demostore7f3a
gcloud storage buckets create gs://demo-bucket-7f3a --location=us-central1

# Delete it when done (you pay while it exists)
aws s3 rb s3://demo-bucket-7f3a
az storage account delete -n demostore7f3a -g rg-demo --yes
gcloud storage buckets delete gs://demo-bucket-7f3a

Code Explained

Each provider has one main CLI: aws, az and gcloud
Bucket names must be globally unique, hence the random suffix
Azure puts containers inside a storage account, so it needs two commands
Deleting what you made is part of the workflow: idle resources still bill

Rule of Thumb

  • Use managed services (PaaS) unless you have a reason to run the server yourself
  • Pick one provider to learn deeply; the concepts transfer
  • Script every change: a click you cannot repeat is a click you will repeat wrong

Do & Don't

  • Do Tag every resource with an owner and purpose from day one
  • Do Set a budget alert before you create anything
  • Don’t Lift and shift everything onto VMs and call it cloud-native
  • Don’t Leave test resources running overnight "just in case"

Local Testing

  • Practice in a free-tier account with a budget alert set to a few dollars
  • Use the browser shells (CloudShell, Azure Cloud Shell, Cloud Shell): CLIs are preinstalled and authenticated
  • Emulators for single services appear on later sheets (LocalStack, Azurite, Google emulators)

Production Checklist

  • Separate accounts / subscriptions / projects for dev, test and prod
  • Billing alerts and an owner tag on every resource
  • Everything created by IaC, not by hand (sheet 20)
