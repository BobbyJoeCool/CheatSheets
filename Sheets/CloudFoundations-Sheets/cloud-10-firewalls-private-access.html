Firewalls & Private Access

security groups · NSGs · VPC firewall rules · stateful vs stateless · private endpoints / PrivateLink / Private Service Connect · bastions & identity-aware access

Controlling Traffic In and Out

Each cloud filters traffic with stateful rules: security groups on AWS, network security groups (NSGs) on Azure, VPC firewall rules / policies on Google Cloud. To reach managed services without the public internet, use private endpoints (PrivateLink, Azure Private Endpoint, Private Service Connect). For admin access, use identity-aware tunnels instead of open SSH ports.

Key Points

  • Stateful: replies to allowed traffic are allowed automatically
  • Reference groups / tags / service accounts instead of IP addresses
  • Private endpoints give a service a private IP inside your network
  • Session Manager, Azure Bastion and IAP replace public SSH / RDP

Allow HTTPS In, Nothing Else

# AWS security group: 443 from anywhere
aws ec2 create-security-group --group-name web-sg \
    --description "web" --vpc-id vpc-0abc
aws ec2 authorize-security-group-ingress --group-id sg-0123 \
    --protocol tcp --port 443 --cidr 0.0.0.0/0

# Azure NSG rule on the web subnet
az network nsg create -g rg-net -n nsg-web
az network nsg rule create -g rg-net --nsg-name nsg-web \
    -n allow-https --priority 100 --direction Inbound \
    --access Allow --protocol Tcp --destination-port-ranges 443

# Google Cloud firewall rule targeting tagged VMs
gcloud compute firewall-rules create allow-https --network=vpc-app \
    --direction=INGRESS --allow=tcp:443 \
    --source-ranges=0.0.0.0/0 --target-tags=web

# Admin access without opening port 22
aws ssm start-session --target i-0abc123
az network bastion ssh -n bas-app -g rg-net --target-resource-id <vm-id> \
    --auth-type AAD
gcloud compute ssh web-1 --zone=us-central1-a --tunnel-through-iap

Code Explained

All three deny inbound by default, so you add only what you need
Azure rules run in priority order (lower number first)
Google Cloud rules apply to VMs by network tag or service account
The last three lines open admin sessions through identity, not open ports

Across the Clouds

  • AWS security groups, NACLs, PrivateLink (aws-11, aws-12)
  • Azure NSGs, Azure Firewall, Private Endpoints (az-11, az-12)
  • Google Cloud firewall rules & policies, Private Service Connect, IAP (gcp-11, gcp-12)

Rule of Thumb

  • Only load balancers face the internet; everything else is private
  • Use private endpoints for databases, storage and secret stores in production
  • Never open 22 / 3389 to 0.0.0.0/0

Do & Don't

  • Do Reference security groups / ASGs / tags rather than IP lists
  • Do Log denied traffic while you tune rules
  • Don’t Allow all outbound and inbound "for now"
  • Don’t Expose a database on a public IP, even with a password

Local Testing

  • Test rules in a sandbox with nc -zv host 443 or curl -v from inside and outside
  • Reachability Analyzer (AWS), Network Watcher (Azure) and Connectivity Tests (Google Cloud) explain blocked paths
  • Docker Compose networks mimic tiered isolation locally

Production Checklist

  • No public IPs on app servers or databases
  • Private endpoints plus private DNS for PaaS services
  • Flow logs and firewall logs sent to the central log store
