Designing for Failure

Hardware, zones and even regions fail; well-built systems expect it. Each provider publishes a framework of best practices organized into pillars such as reliability, security, cost, operations, performance and sustainability. Reliability starts with two numbers: RTO (how long you can be down) and RPO (how much data you can lose). They decide between multi-zone, warm standby and multi-region active-active.

Key Points

  • Multi-zone covers most failures at modest cost
  • Multi-region is for strict RTO / RPO or regulations
  • Backups are only as good as your last tested restore
  • Health checks, retries with backoff and timeouts prevent cascades

Retries, Timeouts and a Circuit Breaker Idea

import random, time, requests

def call_with_retry(url, attempts=4, timeout=2.0):
    for n in range(attempts):
        try:
            r = requests.get(url, timeout=timeout)   # always set a timeout
            if r.status_code < 500:
                return r
        except requests.RequestException:
            pass
        sleep = min(8, 0.2 * 2 ** n) * random.uniform(0.5, 1.5)
        time.sleep(sleep)               # exponential backoff + jitter
    raise RuntimeError(f"{url} unavailable after {attempts} tries")

Framework Reviews

aws wellarchitected create-workload --workload-name shop \
    --environment PRODUCTION --lenses wellarchitected --review-owner me \
    --aws-regions us-east-1 --description "shop"
az advisor recommendation list --category HighAvailability -o table
gcloud recommender recommendations list --project=app-prod \
    --location=global --recommender=google.iam.policy.Recommender

Code Explained

Timeouts stop one slow dependency from tying up every worker
Exponential backoff with jitter avoids retry storms
Only retry server errors and network failures, not 4xx
Each provider has a review tool or advisor that checks your setup

Rule of Thumb

  • Agree RTO / RPO with the business before choosing an architecture
  • Multi-zone first; multi-region only with a proven need
  • Run a restore drill every quarter

Do & Don't

  • Do Set timeouts on every network call
  • Do Practice failover with game days
  • Don’t Retry instantly in a tight loop
  • Don’t Claim multi-region resilience you have never tested

Local Testing

  • Toxiproxy or tc netem inject latency and failures locally
  • Chaos tools: AWS Fault Injection Service, Azure Chaos Studio, Chaos Mesh / Litmus on Kubernetes
  • Restore last night's backup into a scratch environment

Production Checklist

  • RTO / RPO written down and tested
  • Every dependency call has timeout, retry and backoff
  • Runbooks for zone and region failure
