Serving Content Close to Users

A content delivery network caches responses at hundreds of edge locations so users get static files (and cacheable API responses) from nearby. You configure origins (a bucket, load balancer or app), cache rules and TTLs, and optionally a WAF. The classic pattern is a static site in object storage behind the CDN with a managed certificate.

Key Points

  • Cache keys decide what counts as the same object (path, query, headers)
  • Use versioned file names (app.3f9a.js) instead of frequent invalidations
  • Keep the origin private: only the CDN can read it
  • Edge services also absorb DDoS traffic

Static Site Behind a CDN

# AWS: upload, then invalidate after a deploy
aws s3 sync ./dist s3://site-bucket --delete
aws cloudfront create-invalidation --distribution-id E1ABC \
    --paths "/index.html"

# Azure: Front Door profile + endpoint, then purge after deploy
az afd profile create -g rg-web --profile-name afd-site \
    --sku Standard_AzureFrontDoor
az afd endpoint create -g rg-web --profile-name afd-site \
    --endpoint-name site
az afd endpoint purge -g rg-web --profile-name afd-site \
    --endpoint-name site --content-paths "/index.html"

# Google Cloud: backend bucket with CDN, invalidate a path
gcloud compute backend-buckets create site-be \
    --gcs-bucket-name=site-bucket --enable-cdn
gcloud compute url-maps invalidate-cdn-cache site-map \
    --path="/index.html"

Code Explained

sync --delete mirrors the build folder into the bucket
Invalidate only the entry HTML when asset names are versioned
Azure Front Door is the CDN and global L7 balancer in one
Google Cloud CDN attaches to a load balancer backend bucket or service

Across the Clouds

  • AWS CloudFront, ACM, Origin Access Control (aws-14)
  • Azure Front Door Standard / Premium (az-14)
  • Google Cloud Cloud CDN, Certificate Manager (gcp-14)

Rule of Thumb

  • Long TTLs on hashed assets, short TTL on index.html
  • Lock the origin so it only accepts CDN traffic
  • Put a WAF on the edge for public apps

Do & Don't

  • Do Fingerprint asset file names in the build
  • Do Set Cache-Control on upload, not only in CDN rules
  • Don’t Invalidate /* on every deploy (slow and sometimes billed)
  • Don’t Leave the storage bucket publicly readable behind the CDN

Local Testing

  • npx serve or python -m http.server previews the static site
  • Check headers with curl -I https://site/app.js
  • Use the HTTP set's caching sheet for header details

Production Checklist

  • Managed certificate and HTTPS redirect at the edge
  • Origin locked to the CDN only
  • Cache hit ratio monitored; WAF rules in prevention mode
