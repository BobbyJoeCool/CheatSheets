Object, Block & File Storage

buckets & objects · block volumes · shared file systems · storage classes & tiers · lifecycle rules · durability vs availability

Three Kinds of Storage

Object storage (S3, Azure Blob Storage, Cloud Storage) keeps files as objects in buckets, reached over HTTPS, with near-unlimited size and very high durability. Block storage (EBS, managed disks, Persistent Disk / Hyperdisk) is a virtual disk attached to one VM. File storage (EFS, Azure Files, Filestore) is a shared network file system many machines mount at once.

Key Points

  • Object storage is the default for uploads, backups, logs, static sites and data lakes
  • Durability: designed for 99.999999999% (11 nines) on object storage
  • Colder tiers cost less to store and more to read
  • Lifecycle rules move or delete objects by age automatically

Copy, List, Tier

# Upload and list
aws s3 cp report.pdf s3://acme-docs/2026/report.pdf
az storage blob upload --account-name acmedocs -c docs \
    -f report.pdf -n 2026/report.pdf --auth-mode login
gcloud storage cp report.pdf gs://acme-docs/2026/report.pdf

aws s3 ls s3://acme-docs/2026/
az storage blob list --account-name acmedocs -c docs \
    --prefix 2026/ --auth-mode login -o table
gcloud storage ls gs://acme-docs/2026/

# Store infrequently-read data in a colder class
aws s3 cp backup.tar s3://acme-backup/ --storage-class STANDARD_IA
az storage blob upload --account-name acmebackup -c b \
    -f backup.tar --tier Cool --auth-mode login
gcloud storage cp backup.tar gs://acme-backup/ --storage-class=NEARLINE

A Lifecycle Rule (Google Cloud JSON)

{ "rule": [
  { "action": { "type": "SetStorageClass", "storageClass": "COLDLINE" },
    "condition": { "age": 90 } },
  { "action": { "type": "Delete" }, "condition": { "age": 365 } } ] }

Code Explained

"Folders" are just key prefixes like 2026/
--auth-mode login uses your Entra ID login instead of account keys
Each provider names its colder classes differently (table)
The lifecycle JSON moves objects to Coldline at 90 days and deletes them at a year

Across the Clouds

  • AWS S3, EBS, EFS (aws-28, aws-29, aws-30)
  • Azure Blob Storage, managed disks, Azure Files (az-28, az-29, az-30)
  • Google Cloud Cloud Storage, Persistent Disk / Hyperdisk, Filestore (gcp-28, gcp-29, gcp-30)

Rule of Thumb

  • Object storage unless an app needs a disk or a shared POSIX mount
  • Turn on versioning or soft delete for anything you cannot recreate
  • Add a lifecycle rule the day you create a log or backup bucket

Do & Don't

  • Do Use one bucket per purpose and environment
  • Do Block public access at the account / organization level
  • Don’t Use object storage as a database with constant small rewrites
  • Don’t Put archive-class data where it is read often (retrieval fees add up)

Local Testing

  • LocalStack emulates S3; Azurite emulates Blob, Queue and Table storage
  • The fake-gcs-server container emulates Cloud Storage APIs
  • MinIO gives an S3-compatible server for local testing

Production Checklist

  • Public access blocked; access through identities or signed URLs
  • Versioning / soft delete and lifecycle rules configured
  • Replication or backups for data you cannot lose
