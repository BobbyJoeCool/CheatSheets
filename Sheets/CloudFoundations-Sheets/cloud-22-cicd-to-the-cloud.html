CI/CD to the Cloud

GitHub Actions OIDC to AWS, Azure & Google Cloud · build → push → deploy · blue/green & canary · environments & approvals · pointer to GitHub set

Shipping From a Pipeline

A deployment pipeline builds and tests the code, pushes an artifact (usually a container image), then deploys it with infrastructure as code or a deploy command. Pipelines should log in to the cloud with OIDC federation, not stored keys. Gradual rollouts (blue/green, canary) let you shift traffic slowly and roll back fast.

Key Points

  • GitHub Actions, GitLab CI, Azure Pipelines, Cloud Build and CodePipeline all work
  • Protected environments add approvals before production
  • Deploy immutable artifacts: the image tested is the image shipped
  • Roll back by moving traffic, not by rebuilding

GitHub Actions: Build and Deploy to Cloud Run

on: { push: { branches: [main] } }
permissions: { contents: read, id-token: write }
jobs:
  deploy:
    runs-on: ubuntu-latest
    environment: production          # approval gate
    steps:
      - uses: actions/checkout@v4
      - uses: google-github-actions/auth@v2
        with:
          workload_identity_provider: ${{ vars.WIF_PROVIDER }}
          service_account: ${{ vars.DEPLOY_SA }}
      - uses: google-github-actions/setup-gcloud@v2
      - run: |
          IMG=us-central1-docker.pkg.dev/app-prod/web/api:${{ github.sha }}
          gcloud auth configure-docker us-central1-docker.pkg.dev -q
          docker build -t $IMG . && docker push $IMG
          gcloud run deploy api --image $IMG --region us-central1

Swap the Login Step for Other Clouds

- uses: aws-actions/configure-aws-credentials@v4
  with: { role-to-assume: ${{ vars.AWS_ROLE }}, aws-region: us-east-1 }
- uses: azure/login@v2
  with: { client-id: ${{ vars.AZ_CLIENT }}, tenant-id: ${{ vars.AZ_TENANT }},
          subscription-id: ${{ vars.AZ_SUB }} }

Code Explained

id-token: write lets the job request an OIDC token
The environment gate can require a reviewer before deploy
Tagging the image with the commit SHA makes every deploy traceable
Only the login step changes per cloud

Across the Clouds

  • AWS GitHub OIDC + CodeDeploy / CodePipeline (aws-39)
  • Azure GitHub OIDC + Azure Pipelines, slot swaps (az-39)
  • Google Cloud GitHub OIDC + Cloud Build / Cloud Deploy (gcp-39)

Rule of Thumb

  • OIDC everywhere; delete any cloud keys stored in CI secrets
  • Same artifact through dev, staging and prod
  • Automate rollback triggers on error-rate alerts

Rollout Strategies

StrategyHowNative Support
RollingReplace instances in batchesASG / VMSS / MIG, Kubernetes
Blue/greenTwo environments, switch trafficCodeDeploy, App Service slots, Cloud Deploy
CanarySend a small % firstLambda aliases, Container Apps revisions, Cloud Run traffic
Feature flagsShip dark, enable laterAppConfig, App Configuration, Firebase Remote Config

Do & Don't

  • Do Pin third-party actions to a version or commit SHA
  • Do Scope the cloud role to deploy-only permissions
  • Don’t Give the pipeline Owner / Administrator access
  • Don’t Rebuild images per environment

Local Testing

  • act runs GitHub workflows locally (cloud login steps need the real runner)
  • actionlint catches workflow syntax errors
  • Build and run the image locally exactly as the pipeline does

Production Checklist

  • OIDC trust restricted to the repo, branch and environment
  • Approval gate and change record for production
  • Automated rollback or one-command traffic shift
