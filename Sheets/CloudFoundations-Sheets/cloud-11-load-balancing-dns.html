Sheet 11

Load Balancing & DNS

L4 vs L7 · health checks · global vs regional load balancers · managed DNS zones · routing policies · TLS certificates

Getting Users to Healthy Servers

A load balancer spreads requests across healthy back ends and gives users one address. Layer 4 balancers forward TCP/UDP; layer 7 balancers understand HTTP and route by host or path, terminate TLS and add a WAF. Managed DNS maps names to those addresses and can route by latency, weight or health.

Key Points

  • Health checks remove failed instances automatically
  • Google Cloud's external Application Load Balancer is global: one anycast IP worldwide
  • AWS and Azure L7 balancers are regional; global front doors are separate services
  • Managed certificates renew automatically

An HTTP Load Balancer, Sketched

# AWS Application Load Balancer + target group
aws elbv2 create-load-balancer --name web-alb \
    --subnets subnet-a subnet-b --security-groups sg-0123
aws elbv2 create-target-group --name web-tg --protocol HTTP \
    --port 8080 --vpc-id vpc-0abc --health-check-path /health

# Azure Application Gateway (L7) in its own subnet
az network application-gateway create -g rg-net -n agw-web \
    --sku Standard_v2 --capacity 2 --vnet-name vnet-app \
    --subnet snet-agw --public-ip-address pip-agw --priority 100

# Google Cloud: health check + backend service (global ALB)
gcloud compute health-checks create http web-hc --port=8080 \
    --request-path=/health
gcloud compute backend-services create web-be --global \
    --protocol=HTTP --health-checks=web-hc

# DNS record pointing a name at the balancer
aws route53 change-resource-record-sets --hosted-zone-id Z123 \
    --change-batch file://alias-record.json
az network dns record-set a add-record -g rg-dns -z example.com \
    -n www -a 20.42.0.10
gcloud dns record-sets create www.example.com. --zone=example \
    --type=A --ttl=300 --rrdatas=34.120.0.10

Code Explained

Every balancer needs a health check path that returns 200 when healthy
Azure Application Gateway needs a dedicated subnet
Google Cloud builds an ALB from parts: health check, backend service, URL map, proxy, forwarding rule
AWS alias records point at AWS resources without a fixed IP

Across the Clouds

  • AWS ALB / NLB, Route 53 (aws-13, aws-17)
  • Azure Load Balancer, Application Gateway, Azure DNS, Traffic Manager (az-13, az-17)
  • Google Cloud Cloud Load Balancing, Cloud DNS (gcp-13, gcp-17)

Rule of Thumb

  • Use L7 for web apps and APIs, L4 for raw TCP / UDP and extreme throughput
  • Keep DNS TTLs low (60–300 s) on records you may fail over
  • Terminate TLS at the balancer with managed certificates

Do & Don't

  • Do Make health checks test real dependencies lightly (not just "process alive")
  • Do Redirect HTTP to HTTPS at the balancer
  • Don’t Point DNS straight at single VM IPs in production
  • Don’t Set a 24-hour TTL on a record you might need to change quickly

Local Testing

  • Run nginx, HAProxy or Traefik in Docker Compose to practice routing and health checks
  • dig +short www.example.com and curl -v --resolve test DNS and TLS
  • kind / minikube Ingress controllers mimic L7 routing

Production Checklist

  • Balancer across at least two zones with health checks tuned
  • Managed TLS certificates with monitored expiry
  • WAF on public HTTP endpoints
