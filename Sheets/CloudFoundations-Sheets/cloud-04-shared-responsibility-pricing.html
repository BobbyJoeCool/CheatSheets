Sheet 04

Shared Responsibility & Pricing Models

shared responsibility model · on-demand · reserved / committed use · spot / preemptible · free tiers · egress charges

Who Secures What, and How You Pay

Under the shared responsibility model the provider secures the hardware, facilities and the services it runs; you secure your data, identities, configuration and code. The more managed the service, the more the provider takes on. Pricing follows a few patterns on every cloud: on-demand, discounted commitments, cheap interruptible spot capacity, and egress fees for data leaving the cloud.

Key Points

  • Misconfiguration (public buckets, open ports, leaked keys) is your responsibility
  • Commitments trade flexibility for 30–70% off
  • Spot capacity can be reclaimed with short notice (30 s to 2 min)
  • Data in is free; data out to the internet is billed per GB

Pricing Lookups and Budgets

# AWS: a monthly budget that emails at 80% of $50
aws budgets create-budget --account-id 111122223333 \
    --budget file://budget.json \
    --notifications-with-subscribers file://notify.json

# Azure: budget on the current subscription
az consumption budget create --budget-name monthly-50 \
    --amount 50 --category cost --time-grain Monthly \
    --start-date 2026-12-01 --end-date 2027-12-01

# Google Cloud: budget with thresholds on a billing account
gcloud billing budgets create --billing-account=0X0X0X-0X0X0X-0X0X0X \
    --display-name="monthly-50" --budget-amount=50USD \
    --threshold-rule=percent=0.5 --threshold-rule=percent=0.9

# Spot / preemptible capacity
aws ec2 run-instances --instance-market-options MarketType=spot ...
az vm create ... --priority Spot --eviction-policy Deallocate
gcloud compute instances create ... --provisioning-model=SPOT

Code Explained

Budgets alert; they do not stop spending by themselves
AWS budget details live in JSON files passed with file://
Spot flags differ but mean the same thing: cheap, can be taken back
The ... stands for the usual instance options on each provider

Across the Clouds

  • AWS Free Tier, Savings Plans, Spot (aws-02, aws-16)
  • Azure free account, Reservations, savings plans, Spot VMs (az-02, az-16)
  • Google Cloud Free Tier, committed and sustained use discounts, Spot VMs (gcp-02, gcp-16)

Rule of Thumb

  • Run steady workloads on commitments, spiky ones on demand, batch on spot
  • Price the network: egress and NAT often surprise more than compute
  • Read the free-tier limits: they are per month and per service

Do & Don't

  • Do Set budgets with alerts at 50%, 80% and 100%
  • Do Use spot for CI runners, batch jobs and stateless workers
  • Don’t Buy a 3-year commitment for a workload you have run for a month
  • Don’t Assume "serverless" means free when idle (some plans bill minimums)

Local Testing

  • Price designs with the AWS Pricing Calculator, Azure Pricing Calculator and Google Cloud Pricing Calculator
  • Test spot interruptions with AWS Fault Injection Service, az vm simulate-eviction, or by stopping a Google Cloud Spot VM
  • Infracost estimates Terraform cost changes in pull requests

Production Checklist

  • Budget alerts routed to a team channel, not one inbox
  • Cost allocation tags / labels enforced by policy
  • A monthly review of the top 10 cost lines
