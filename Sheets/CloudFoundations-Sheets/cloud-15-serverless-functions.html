Sheet 15

Serverless Functions

event-driven functions · triggers · cold starts · concurrency · timeouts & limits · Lambda / Azure Functions / Cloud Run functions

Code That Runs When Something Happens

A serverless function is a handler the platform runs in response to an event: an HTTP request, a new file in a bucket, a queue message or a timer. You pay per invocation and execution time, and it scales to zero when idle. The trade-offs are cold starts on the first request after idle time, execution time limits, and less control over the runtime.

Key Points

  • AWS Lambda, Azure Functions and Cloud Run functions (formerly Cloud Functions)
  • Triggers are wired by the platform; your code just receives the event
  • Keep handlers small; reuse clients across invocations
  • Long work goes to queues, workflows or containers

An HTTP Function on Each Cloud

# AWS Lambda (Python)
def handler(event, context):
    name = (event.get("queryStringParameters") or {}).get("name", "world")
    return {"statusCode": 200, "body": f"hello {name}"}

# Azure Functions (Python v2 programming model)
import azure.functions as func
app = func.FunctionApp()
@app.route(route="hello", auth_level=func.AuthLevel.ANONYMOUS)
def hello(req: func.HttpRequest) -> func.HttpResponse:
    return func.HttpResponse(f"hello {req.params.get('name', 'world')}")

# Cloud Run functions (Functions Framework)
import functions_framework
@functions_framework.http
def hello(request):
    return f"hello {request.args.get('name', 'world')}"

Deploy

aws lambda create-function --function-name hello --runtime python3.13 \
    --handler app.handler --zip-file fileb://app.zip --role <role-arn>
func azure functionapp publish func-hello
gcloud functions deploy hello --gen2 --runtime=python313 \
    --trigger-http --entry-point=hello --region=us-central1

Code Explained

Each platform wraps the request in its own event / request object
Azure declares routes with decorators in function_app.py
The Functions Framework makes the Google function a normal Flask-style handler
Deploy commands package and upload the code

Across the Clouds

  • AWS Lambda (aws-20, aws-21)
  • Azure Azure Functions (az-20, az-21)
  • Google Cloud Cloud Run functions (gcp-21)

Rule of Thumb

  • Use functions for glue, webhooks, scheduled jobs and event processing
  • Move to containers when a function needs more than a few minutes or custom runtimes
  • Make handlers idempotent: events can arrive twice

Do & Don't

  • Do Create SDK clients outside the handler so warm calls reuse them
  • Do Send failures to a dead-letter queue
  • Don’t Chain functions synchronously into a call stack
  • Don’t Hold database connections without a pool or proxy

Local Testing

  • AWS SAM: sam local invoke / sam local start-api
  • Azure Functions Core Tools: func start
  • Functions Framework: functions-framework --target=hello

Production Checklist

  • Timeouts and memory tuned from real measurements
  • Dead-letter queues and alerts on errors and throttles
  • Concurrency limits set to protect downstream databases
