Running Containers Without Running Servers

Package the app as a container image, push it to a registry, and pick how much of the platform you want to manage. Serverless containers (AWS Fargate with ECS or App Runner, Azure Container Apps, Google Cloud Run) run an image with autoscaling and no cluster to maintain. Managed Kubernetes (EKS, AKS, GKE) gives you the full Kubernetes API with the control plane run for you.

Key Points

  • Registries: ECR, Azure Container Registry, Artifact Registry
  • Cloud Run and Container Apps can scale to zero; idle cost is near nothing
  • Cluster fees: EKS and GKE bill per cluster-hour (a GKE credit covers one cluster); AKS Free tier has none
  • See the Docker and Kubernetes sets for the tools themselves

Build, Push, Run

# Push to each registry
aws ecr get-login-password | docker login --username AWS \
    --password-stdin 111122223333.dkr.ecr.us-east-1.amazonaws.com
az acr login --name shopacr
gcloud auth configure-docker us-central1-docker.pkg.dev
docker push us-central1-docker.pkg.dev/app-prod/web/api:1.4.0

# Serverless containers
az containerapp up -n api -g rg-app \
    --image shopacr.azurecr.io/api:1.4.0 --ingress external \
    --target-port 8080
gcloud run deploy api --region=us-central1 \
    --image=us-central1-docker.pkg.dev/app-prod/web/api:1.4.0

# Managed Kubernetes: create a cluster, get kubectl credentials
eksctl create cluster --name shop --region us-east-1
az aks create -g rg-app -n aks-shop --generate-ssh-keys
gcloud container clusters create-auto shop --region=us-central1
aws eks update-kubeconfig --name shop
az aks get-credentials -g rg-app -n aks-shop
gcloud container clusters get-credentials shop --region=us-central1

Code Explained

Each registry has its own login helper for Docker
Cloud Run and Container Apps deploy straight from an image
Autopilot (GKE) and AKS Automatic manage nodes for you
After get-credentials, plain kubectl works the same on all three

Across the Clouds

  • AWS ECR, ECS / Fargate, EKS (aws-25, aws-26, aws-27)
  • Azure ACR, Container Apps, AKS (az-25, az-26, az-27)
  • Google Cloud Artifact Registry, Cloud Run, GKE (gcp-25, gcp-20, gcp-26)

Rule of Thumb

  • Start with serverless containers; move to Kubernetes when you need its ecosystem
  • Pin images by tag and digest; never deploy latest
  • One cluster can host many apps; one Cloud Run service hosts one

Do & Don't

  • Do Scan images in the registry and fail builds on critical findings
  • Do Run containers as non-root with read-only file systems where possible
  • Don’t Store secrets in the image
  • Don’t Build a Kubernetes platform for a single small service

Local Testing

  • Docker Desktop, Podman or Rancher Desktop run the same image
  • kind / k3d / minikube give a local Kubernetes cluster
  • Cloud Run: gcloud beta code dev or plain docker run -p 8080:8080

Production Checklist

  • Images signed or from a trusted registry only
  • Resource requests / limits and health probes defined
  • Autoscaling bounds set (min for latency, max for cost)
