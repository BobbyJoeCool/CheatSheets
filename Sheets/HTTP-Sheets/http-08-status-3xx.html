Sheet 08

3xx Redirects & Not Modified

301 vs 308 · 302 vs 307 · 303 See Other · Post/Redirect/Get · Location · 304 Not Modified · loops

Go Somewhere Else, or Use Your Copy

A 3xx response tells the client to look elsewhere, with the new URL in Location. Two questions pick the code: is the move permanent (clients and search engines update links), and must the client keep the method and body? 307 and 308 keep them; 301 and 302 let browsers turn POST into GET; 303 always means "now GET this". 304 Not Modified is different: it answers a conditional request and says the cached copy is still good.

Notes

  • Browsers follow redirects automatically; curl only with -L
  • Browsers cache 301/308 hard, sometimes for months
  • Location may be relative (/orders/9001)
  • 304 has no body; the client reuses what it cached (sheet 12)

Post/Redirect/Get and a 304

POST /orders HTTP/1.1
Content-Type: application/x-www-form-urlencoded

sku=A-100&qty=2

HTTP/1.1 303 See Other
Location: /orders/9001

GET /orders/9001 HTTP/1.1

GET /api/v1/users HTTP/1.1

HTTP/1.1 308 Permanent Redirect
Location: /api/v2/users

GET /logo.png HTTP/1.1
If-None-Match: "a1b2c3"

HTTP/1.1 304 Not Modified
ETag: "a1b2c3"
Cache-Control: max-age=3600

Code Explained

PRG: answer a form POST with 303 so refresh doesn't resubmit
The browser then GETs the Location URL
308 moves an endpoint for good and keeps the method
304: the ETag still matches, so no body is re-sent

In Your Stack

  • Express — res.redirect(303, '/orders/9001') (default is 302)
  • Django — redirect('order-detail', pk=9001) (302); permanent=True for 301
  • Spring — MVC: return "redirect:/orders/9001"; API: ResponseEntity.status(303).location(uri).build()
  • Rails — redirect_to order_path(o), status: :see_other (default 302)
  • ASP.NET — Results.Redirect(url) (302); permanent: true, preserveMethod: true for 308
  • Go — http.Redirect(w, r, "/orders/9001", http.StatusSeeOther)

Debug It

  • curl -sIL url lists every hop and its status
  • ERR_TOO_MANY_REDIRECTS behind a proxy: app thinks it's on http; trust X-Forwarded-Proto
  • A stale 301 sticks in the browser cache: test with DevTools "Disable cache" or a private window

⚠ Common Mistakes

  • Using 301/302 to move a POST endpoint: browsers switch it to GET and the body is lost
  • Redirecting API clients to an HTML login page instead of returning 401
  • Shipping a 301 by mistake: users' browsers keep obeying it after you fix the server

✓ Tips & Best Practices

  • Start with 307 while testing a move; switch to 308 once you're sure
  • Always use PRG (303) after HTML form posts
  • Keep redirect chains to one hop; each hop is a full round trip

Quick Summary

  • 301 / 308 — permanent (308 keeps method)
  • 302 / 307 — temporary (307 keeps method)
  • 303 — "now GET this" after POST
  • 304 — not modified; use the cache
