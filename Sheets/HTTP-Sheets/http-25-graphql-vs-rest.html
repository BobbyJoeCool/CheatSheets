GraphQL Basics & GraphQL vs REST

single endpoint · POST /graphql · query · mutation · subscription · over- / under-fetching · introspection

Ask for Exactly the Fields You Need

GraphQL puts one typed schema behind a single endpoint. Clients send a query that names exactly the fields they want, across related objects, and get back JSON in the same shape: no over-fetching (fields you don't need) and no under-fetching (five calls to build one screen). Writes are mutations; live updates are subscriptions. The cost moves to the server: caching, authorization and query cost need more care than in REST.

Notes

  • Usually POST /graphql with a JSON body; GET works for queries
  • Responses are 200 even when part of the query failed; check errors (sheet 28)
  • Introspection lets tools read the schema (GraphiQL, codegen)
  • Same HTTP auth as REST: Authorization: Bearer ...

Security Check

  • Restrict introspection and field suggestions in production for private APIs
  • Only accept application/json POSTs for mutations, never GET (CSRF)
  • First-party apps: allow-list persisted queries so random queries can't run

A Query Over HTTP

POST /graphql HTTP/1.1
Content-Type: application/json
Authorization: Bearer eyJhbGciOi...

{
  "operationName": "OrderCard",
  "query": "query OrderCard($id: ID!) { order(id: $id) { status total customer { name } } }",
  "variables": { "id": "9001" }
}

HTTP/1.1 200 OK
Content-Type: application/graphql-response+json

{
  "data": {
    "order": { "status": "PENDING", "total": 4998, "customer": { "name": "Ada" } }
  }
}

Code Explained

One request fetches the order and its customer together
Only status, total and the customer's name come back
variables keep values out of the query string
graphql-response+json is the GraphQL-over-HTTP media type

In Your Stack

  • Express — Apollo Server (Express integration) or GraphQL Yoga
  • Django — Strawberry GraphQLView.as_view(schema=schema); Graphene-Django
  • Spring — Spring for GraphQL: spring-boot-starter-graphql, serves /graphql
  • Rails — graphql-ruby: rails g graphql:install → GraphqlController#execute
  • ASP.NET — Hot Chocolate: AddGraphQLServer().AddQueryType<Query>() + app.MapGraphQL()
  • Go — gqlgen generates resolvers from the schema; serve with handler.New(...)

GraphQL vs REST

RESTGraphQL
EndpointsMany URLsOne (/graphql)
Response shapeServer decidesClient decides
Related dataSeveral calls or ?include=One query
HTTP cachingBuilt in (GET + ETag)Needs persisted queries / client cache
ErrorsStatus codeserrors array, mostly 200
Versioning/v2Add fields, deprecate old ones
TypingOptional (OpenAPI)Required (schema)

⚠ Common Mistakes

  • Treating GraphQL as a database query language and exposing every table
  • Assuming 200 OK means success; partial errors live in the body
  • Skipping pagination on list fields, so one query returns 100,000 rows

✓ Tips & Best Practices

  • Always name operations (query OrderCard); logs and tracing become readable
  • Generate typed clients from the schema (GraphQL Code Generator, Apollo iOS / Kotlin)
  • Use GraphiQL or Apollo Sandbox to explore the schema

Quick Summary

  • query — read · mutation — write · subscription — live
  • One endpoint, client picks the fields
  • 200 + data / errors in the body
  • Strong schema, but caching and cost need work
