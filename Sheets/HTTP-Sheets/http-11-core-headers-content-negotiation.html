Sheet 11

Core Headers & Content Negotiation

Host · Content-Type · Content-Length · Accept · Accept-Encoding · Content-Encoding · multipart · 406 / 415

Metadata That Shapes Every Exchange

Headers describe the message: Content-Type says what the body is, Accept says what the client wants back. Matching them is content negotiation: the client lists media types, languages and encodings it can handle, and the server picks one and says so. When nothing fits, the server answers 406 Not Acceptable; when it can't read what was sent, 415 Unsupported Media Type.

Notes

  • q= weights rank choices: Accept: application/json, text/html;q=0.8
  • Set Vary to the request headers that changed the response (sheet 12)
  • Custom headers no longer need an X- prefix (RFC 6648)
  • Most JSON APIs ignore Accept and always return JSON; that's fine if documented

Security Check

  • Send X-Content-Type-Options: nosniff so browsers trust your Content-Type
  • Reject request bodies whose Content-Type you don't expect; cap body size
  • Never serve user uploads as text/html; use Content-Disposition: attachment

Negotiating Format and Encoding

GET /reports/q3 HTTP/1.1
Accept: application/json, text/csv;q=0.5
Accept-Encoding: gzip, br
Accept-Language: en-US, en;q=0.8

HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8
Content-Encoding: br
Content-Language: en-US
Vary: Accept, Accept-Encoding

POST /avatars HTTP/1.1
Content-Type: multipart/form-data; boundary=XyZ

--XyZ
Content-Disposition: form-data; name="file"; filename="me.png"
Content-Type: image/png

(binary bytes)
--XyZ--

Code Explained

Client prefers JSON, accepts CSV at lower weight
Server compressed with Brotli and says so in Content-Encoding
Vary tells caches which request headers picked this version
Multipart: parts separated by the boundary; each has its own headers

In Your Stack

  • Express — express.json() · express.urlencoded() · multer · compression(); req.accepts('json')
  • Django — request.POST · request.FILES; DRF parser_classes / renderer_classes; GZipMiddleware
  • Spring — @PostMapping(consumes = ..., produces = ...); MultipartFile; server.compression.enabled
  • Rails — respond_to { |f| f.json; f.csv }; params parses JSON and forms; Active Storage uploads
  • ASP.NET — [Consumes] / [Produces]; IFormFile; AddResponseCompression()
  • Go — json.NewDecoder(r.Body) · r.ParseMultipartForm(32 << 20) · http.MaxBytesReader

Debug It

  • Garbled bytes from curl: the body is compressed; add --compressed
  • DevTools shows JSON as plain text: server sent the wrong Content-Type
  • 415 = your request's Content-Type; 406 = your Accept

⚠ Common Mistakes

  • Sending JSON without Content-Type: application/json; many parsers then ignore the body
  • Compressing already-compressed files (PNG, ZIP): CPU cost, no gain
  • Setting Content-Length by hand and getting it wrong; let the framework do it

✓ Tips & Best Practices

  • Always add charset=utf-8 to text types or rely on JSON's UTF-8 default
  • Upload big files straight to object storage with a pre-signed URL
  • Log Content-Type and Content-Length on 400/415 to debug client bugs fast

Quick Summary

  • Content-Type — what I'm sending
  • Accept — what I want back
  • Content-Encoding — how it's compressed
  • 406 / 415 — can't produce / can't read
