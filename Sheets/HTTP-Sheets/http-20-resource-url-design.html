Resource & URL Design

plural nouns · /users/{id} · nesting one level · method × URL · non-CRUD actions · kebab-case · field casing

URLs Clients Can Guess

Good URLs are predictable: plural nouns for collections, an ID for one item, and HTTP methods for the verbs. Nest only to show ownership one level deep (/customers/42/orders), and give every item one canonical URL (/orders/9001). Actions that don't fit CRUD become a sub-resource (POST /orders/9001/cancellation) or a clearly marked custom method. Pick one casing for paths and one for JSON fields, and never mix.

Notes

  • Paths: lowercase, kebab-case (/order-items)
  • JSON fields: camelCase or snake_case, the same everywhere
  • IDs in URLs are often strings; don't promise they're numbers
  • No file extensions (.json); use Accept

A Consistent URL Map

GET    /customers                  list (paged)
POST   /customers                  create → 201 + Location
GET    /customers/42               read one
PATCH  /customers/42               change some fields
DELETE /customers/42               remove
GET    /customers/42/orders        orders owned by one customer
GET    /orders?customer_id=42      same data, as a filter
GET    /orders/9001                each order has ONE canonical URL
POST   /orders/9001/cancellation   action as a sub-resource
POST   /orders/9001:cancel         action as a custom method (Google AIP)
PUT    /users/42/avatar            singleton sub-resource
GET    /me                         shortcut for the current user
GET    /order-items?order_id=9001  kebab-case paths

{"orderId": 9001, "createdAt": "2026-11-02T15:00:00Z", "isGift": false}

Code Explained

Collection + item URLs cover most endpoints
Nesting shows ownership; a filter is the flat alternative
cancellation is a noun you can create; pick one action style
Timestamps: ISO 8601 in UTC with Z

In Your Stack

  • Express — router.get('/customers/:id/orders', ...); Router({ mergeParams: true }) for nested routers
  • Django — path('customers/<int:pk>/orders/', ...); drf-nested-routers for nested viewsets
  • Spring — @GetMapping("/customers/{id}/orders"); Jackson naming strategy for field casing
  • Rails — resources :customers do resources :orders, shallow: true end; member { post :cancel }
  • ASP.NET — group.MapGet("/{id}/orders", ...); System.Text.Json uses camelCase by default
  • Go — "GET /customers/{id}/orders"; struct tags set casing: json:"createdAt"

⚠ Common Mistakes

  • Deep nesting that forces clients to know every parent ID
  • Two URLs for the same item (/orders/9001 and /customers/42/orders/9001) with different behavior
  • Exposing auto-increment IDs where guessing them leaks data; use UUIDs or check access

✓ Tips & Best Practices

  • Write the URL map first and review it before any code
  • Prefer filters (?customer_id=) over nesting when items have many parents
  • Reserve /me for the authenticated user's own resources

Quick Summary

  • /things + /things/{id} — the core pattern
  • Methods are the verbs; URLs are nouns
  • Nest one level for ownership, else filter
  • One casing for paths, one for fields
