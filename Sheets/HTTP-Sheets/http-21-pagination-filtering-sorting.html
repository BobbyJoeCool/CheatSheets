Pagination, Filtering & Sorting

limit / offset · cursor pagination · Link header · total counts · filters · ?sort=-created_at · sparse fields

Big Collections in Small Pages

Never return an unbounded list. Offset paging (page, limit) is simple and lets users jump to page 7, but gets slow on big tables and skips or repeats rows when data changes. Cursor (keyset) paging returns an opaque token pointing after the last item; it's fast and stable, at the cost of random access. Filters and sort go in the query string with documented names, and the response says how to get the next page.

Notes

  • Default limit (e.g. 25) and a hard maximum (e.g. 100)
  • sort=-created_at,name: minus means descending
  • Totals cost a COUNT(*); make them optional on large data
  • Link: <...>; rel="next" (RFC 8288) works for any media type

Security Check

  • Cap limit; ?limit=1000000 is a denial of service
  • Allow-list filter and sort fields; never paste them into SQL
  • Make cursors opaque and signed if they encode anything sensitive

Cursor and Offset Responses

GET /orders?status=shipped&created_after=2026-10-01&sort=-created_at&limit=25 HTTP/1.1

HTTP/1.1 200 OK
Content-Type: application/json
Link: </orders?status=shipped&limit=25&cursor=eyJpZCI6OTAwMX0>; rel="next"

{
  "data": [{"id": 9025, "status": "shipped"}, ...],
  "next_cursor": "eyJpZCI6OTAwMX0",
  "has_more": true
}

GET /orders?page=3&per_page=25 HTTP/1.1

HTTP/1.1 200 OK

{"data": [...], "page": 3, "per_page": 25, "total": 1042}

GET /orders/9001?fields=id,status,total HTTP/1.1

Code Explained

Filters and sort ride along in the next link automatically
The cursor is Base64 of {"id":9001}: the last row seen
Server query: WHERE id < 9001 ORDER BY id DESC LIMIT 26
Fetch one extra row to know has_more without counting

In Your Stack

  • Express — No built-in; validate req.query with zod; Prisma take + cursor + skip: 1
  • Django — DRF CursorPagination / LimitOffsetPagination; django-filter; OrderingFilter
  • Spring — Pageable: ?page=2&size=25&sort=createdAt,desc → Page<T> or Slice<T>
  • Rails — pagy or kaminari; where(...).order(created_at: :desc).limit(25)
  • ASP.NET — [AsParameters] query object; EF Core .Where(o => o.Id < cursor).Take(25)
  • Go — strconv.Atoi(q.Get("limit")); WHERE id < $1 ORDER BY id DESC LIMIT $2

⚠ Common Mistakes

  • Sorting a cursor page by a non-unique column; add the ID as a tie-breaker
  • Letting clients pass raw column names straight into ORDER BY
  • Changing default sort order between releases; clients depend on it

✓ Tips & Best Practices

  • Index the columns you filter and sort on, in the same order
  • Return the same envelope (data, next_cursor) on every list endpoint
  • For exports, cursor paging or an async job (sheet 23), not page 400 of 400

Quick Summary

  • limit + cursor — fast, stable paging
  • page + per_page — simple, jumpable
  • ?field=value filters · ?sort=-field
  • Always cap limit
