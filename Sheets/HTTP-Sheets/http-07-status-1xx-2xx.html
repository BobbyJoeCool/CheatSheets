Sheet 07

1xx Informational & 2xx Success

100 Continue · 101 Switching Protocols · 103 Early Hints · 200 · 201 · 202 · 204 · 206

It Worked, and How

2xx codes tell the client the request succeeded, and the exact code says what kind of success: 200 returned data, 201 created something (with Location), 202 accepted work that will finish later, 204 succeeded with nothing to send back, and 206 returned only the byte range asked for. 1xx codes are interim: the final response follows on the same request. Picking the precise code lets clients react without parsing the body.

Notes

  • Every 2xx is success; clients should treat unknown 2xx like 200
  • 204 must not have a body; 200 with {} is not the same
  • 103 Early Hints lets the browser preload CSS/JS while the server works
  • 101 is how a request upgrades to WebSockets (HTTP/1.1)

Code Explained

Range asks for the first 1 MiB; 206 + Content-Range delivers it
Accept-Ranges: bytes tells clients they can resume or seek
202 means "queued"; Location is where to poll (sheet 23)
101 switches the connection to another protocol

In Your Stack

  • Express — res.sendStatus(204) · res.status(202).location(url).end()
  • Django — HttpResponse(status=204) · DRF Response(status=status.HTTP_202_ACCEPTED)
  • Spring — ResponseEntity.noContent().build() · ResponseEntity.accepted().location(uri).build()
  • Rails — head :no_content · head :accepted, location: job_url(job)
  • ASP.NET — Results.NoContent() · Results.Accepted(url)
  • Go — w.WriteHeader(http.StatusNoContent) · http.StatusAccepted; http.ServeContent handles Range

⚠ Common Mistakes

  • Returning 200 with {"error": ...} in the body: clients and monitoring think it worked
  • Sending a body with 204; some clients hang or drop it
  • Using 201 without a Location header

✓ Tips & Best Practices

  • Return the created object with 201 so the client has server-set fields (ID, timestamps)
  • Serve large files through your framework's range-aware helper instead of streaming by hand
  • Document every success code an endpoint can return, not just 200

Quick Summary

  • 200 — OK with data
  • 201 — created + Location
  • 202 — accepted, finishes later
  • 204 — success, empty body
