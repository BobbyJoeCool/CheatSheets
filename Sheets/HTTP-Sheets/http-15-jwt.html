Sheet 15

JSON Web Tokens (JWT)

header.payload.signature · Base64URL · iss · sub · aud · exp · HS256 vs RS256 · verify, don't decode

Signed Claims You Can Check Locally

A JWT is three Base64URL parts joined by dots: a header (algorithm, key ID), a payload of claims (who, for which API, until when) and a signature. Any API holding the right key can verify the token without calling the issuer, which is why JWTs suit distributed systems. The payload is signed, not encrypted: anyone can read it. The trade-off is revocation: a valid JWT works until it expires.

Notes

  • HS256 = shared secret: issuer and every API hold the same key
  • RS256 / ES256 = private key signs, public key (from a JWKS URL) verifies
  • Times are seconds since 1970 (Unix time), in UTC
  • Keep access tokens short-lived (5–15 min) and refresh them

Security Check

  • Pin the allowed algorithms; reject alg: none and HS/RS confusion
  • Always check exp, iss and aud, not just the signature
  • No secrets or personal data in claims; prefer an HttpOnly cookie to localStorage in browsers

Peek at a Token (Not Verification)

TOKEN=eyJhbGciOiJSUzI1NiIsImtpZCI6ImsxIn0.eyJpc3Mi...SflKxw
echo "$TOKEN" | cut -d. -f2 | tr '_-' '/+' | base64 -d 2>/dev/null | jq .

Header and Payload

{ "alg": "RS256", "typ": "JWT", "kid": "k1" }

{
  "iss": "https://auth.example.com",
  "sub": "user_42",
  "aud": "https://api.example.com",
  "iat": 1793631600,
  "exp": 1793632500,
  "scope": "orders:read orders:write"
}

Code Explained

Base64URL uses - and _, hence the tr before decoding
kid picks which public key in the issuer's JWKS verifies it
exp − iat = 900 s: a 15-minute token
Verify = check signature, then iss, aud, exp, nbf

In Your Stack

  • Express — jose: await jwtVerify(token, JWKS, { issuer, audience })
  • Django — djangorestframework-simplejwt; or jwt.decode(t, key, algorithms=["RS256"], audience=aud)
  • Spring — Resource server starter; spring.security.oauth2.resourceserver.jwt.issuer-uri
  • Rails — jwt gem: JWT.decode(t, key, true, algorithm: "RS256", aud: aud, verify_aud: true)
  • ASP.NET — AddJwtBearer(o => { o.Authority = issuer; o.Audience = aud; })
  • Go — golang-jwt/jwt/v5: jwt.Parse(t, keyFn, jwt.WithValidMethods([]string{"RS256"}))

Debug It

  • 401 with "invalid audience" or "issuer": compare aud / iss with your config exactly
  • Fails only on some servers: clock skew; allow 30–60 s leeway
  • "kid not found": the issuer rotated keys; refresh the cached JWKS

Registered Claims

ClaimMeaning
issIssuer (who signed it)
subSubject (user or client ID)
audAudience (which API)
expExpires at
nbfNot valid before
iatIssued at
jtiUnique token ID (deny-lists)

Algorithms

algTypeUse
HS256HMAC + shared secretOne service issues and verifies
RS256RSA key pairMost identity providers
ES256ECDSA key pairSmaller tokens
EdDSAEd25519Modern, fast
noneUnsignedAlways reject

⚠ Common Mistakes

  • Decoding the payload and trusting it without verifying the signature
  • Long-lived JWTs (days) with no way to revoke them
  • Using JWTs as server sessions just because they're popular; a session cookie is often simpler

✓ Tips & Best Practices

  • Use a maintained library; never hand-roll signature checks
  • Need revocation? Short exp + refresh tokens, or a jti deny-list
  • Decode tokens locally when debugging; don't paste production tokens into websites

Quick Summary

  • header.payload.signature — Base64URL, signed
  • iss · sub · aud · exp — check all four
  • RS256 — sign private, verify public (JWKS)
  • Readable by anyone; valid until exp
