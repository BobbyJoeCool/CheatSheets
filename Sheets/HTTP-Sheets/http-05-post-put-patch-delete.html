Sheet 05

Writing: POST, PUT, PATCH & DELETE

POST create · PUT replace · PATCH partial · JSON Merge Patch · JSON Patch · DELETE · 201 + Location

Methods That Change Things

POST asks the server to process the body, most often to create a resource whose URL the server picks. PUT replaces the resource at a URL the client knows with the full body. PATCH applies a partial change, described by a patch format: JSON Merge Patch (send the fields that change, null removes) or JSON Patch (a list of operations). DELETE removes the resource.

Notes

  • PUT with missing fields means "clear them"; that's why PATCH exists
  • PUT can also create when the client chooses the ID: PUT /users/ada
  • Merge Patch can't set a value to null or edit arrays item by item; JSON Patch can
  • DELETE usually returns 204, or 200 with the deleted item

Security Check

  • Mass assignment: never bind the whole body to the model; allow-list fields so clients can't set role or is_admin
  • Check ownership on every write: PATCH /orders/9001 must belong to the caller (BOLA, OWASP API #1)

Create, Replace, Patch, Delete

POST /users HTTP/1.1
Content-Type: application/json

{"name":"Ada","email":"ada@example.com"}

HTTP/1.1 201 Created
Location: /users/42

PUT /users/42 HTTP/1.1
Content-Type: application/json

{"name":"Ada L.","email":"ada@example.com","role":"editor"}

PATCH /users/42 HTTP/1.1
Content-Type: application/merge-patch+json

{"name":"Ada Lovelace","role":null}

PATCH /users/42 HTTP/1.1
Content-Type: application/json-patch+json

[{"op":"replace","path":"/name","value":"Ada"},
 {"op":"remove","path":"/role"}]

DELETE /users/42 HTTP/1.1

HTTP/1.1 204 No Content

Code Explained

POST: server picks ID 42 and returns it in Location
PUT: the whole user, every field, at a known URL
Merge Patch (RFC 7396): changed fields only; null deletes role
JSON Patch (RFC 6902): ordered ops, applied all-or-nothing
Host lines left out to save space

In Your Stack

  • Express — app.post/put/patch/delete(); res.status(201).location(url).json(user)
  • Django — DRF ModelViewSet → create · update · partial_update · destroy
  • Spring — @PostMapping · @PutMapping · @PatchMapping · @DeleteMapping; ResponseEntity.created(uri)
  • Rails — resources :users → create · update (PUT and PATCH) · destroy; params.require(:user).permit(:name)
  • ASP.NET — MapPost · MapPut · MapPatch · MapDelete; Results.Created($"/users/{id}", user)
  • Go — "POST /users", "PATCH /users/{id}" patterns; w.WriteHeader(http.StatusCreated)

Debug It

  • 415 Unsupported Media Type: the Content-Type doesn't match what the endpoint parses
  • Handler sees an empty body: no JSON body parser registered (express.json()) or wrong Content-Type
  • 405 Method Not Allowed + Allow header: the route exists, just not for this method

⚠ Common Mistakes

  • Using PUT for partial updates: fields the client left out get wiped
  • Returning 200 with an empty body after create instead of 201 + Location
  • Treating DELETE of an already-deleted item as a 500; return 404 or 204

✓ Tips & Best Practices

  • Accept application/merge-patch+json for PATCH; it's the simplest format for clients
  • Return the updated resource from PUT/PATCH so clients don't need a follow-up GET
  • Soft-delete (deleted_at) when you need undo or audit history

Quick Summary

  • POST — create / process; 201 + Location
  • PUT — replace whole resource
  • PATCH — partial update via a patch format
  • DELETE — remove; 204
