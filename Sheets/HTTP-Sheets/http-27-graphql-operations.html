Writing Operations Clients Send

An operation is a named query, mutation or subscription with a selection set of fields. Values come in through typed variables ($id: ID!), sent as a separate JSON object, never pasted into the query text. Aliases fetch the same field twice under different names, fragments reuse a selection, and the @include / @skip directives turn fields on and off. Mutations return a payload you select from like any query.

Notes

  • Variable types must match the argument type exactly (ID! ≠ Int)
  • Default values: $withItems: Boolean = false
  • Top-level mutation fields run in order; query fields may run in parallel
  • __typename tells you which type a union / interface returned

Query, Fragment, Mutation

query OrderPage($id: ID!, $withItems: Boolean = false) {
  order(id: $id) {
    ...OrderSummary
    items @include(if: $withItems) { sku quantity }
    customer { name email }
  }
  recent: orders(first: 3, status: SHIPPED) {
    edges { node { ...OrderSummary } }
  }
}

fragment OrderSummary on Order { id status total }

mutation PlaceOrder($input: PlaceOrderInput!) {
  placeOrder(input: $input) {
    order { id status }
    errors { field message }
  }
}

Variables (sent alongside)

{ "id": "9001", "withItems": true }
{ "input": {
    "customerId": "42",
    "items": [{"sku": "A-100", "quantity": 2}]}}

Code Explained

...OrderSummary pastes the fragment's fields in both places
recent: is an alias, so orders can appear next to order
items only comes back when $withItems is true
Mutation payload holds the result and user-facing errors

In Your Stack

  • Express — Tests: server.executeOperation({ query, variables })
  • Django — Tests: schema.execute_sync(query, variable_values={...})
  • Spring — Tests: graphQlTester.document(q).variable("id", "9001").execute()
  • Rails — Tests: MySchema.execute(query, variables: { "id" => "9001" })
  • ASP.NET — Tests: executor.ExecuteAsync(OperationRequestBuilder.New().SetDocument(q)...)
  • Go — Tests: client.New(srv).MustPost(q, &resp, client.Var("id", "9001"))

Debug It

  • Every call is POST /graphql in DevTools: check Payload → operationName to find yours
  • "Cannot query field X on type Y": client and server schemas are out of sync
  • "Variable $id of type Int used where ID! expected": fix the variable's declared type

⚠ Common Mistakes

  • Building query strings with string interpolation instead of variables (injection, no caching)
  • Anonymous operations; you can't tell them apart in logs
  • Selecting every field "just in case", bringing over-fetching back

✓ Tips & Best Practices

  • Co-locate fragments with the UI components that use them
  • Return user-fixable errors in the payload; reserve errors[] for real failures
  • Persist operations at build time and send only their hash

Quick Summary

  • query Name($v: Type!) — named, typed operation
  • alias: · ...Fragment · @include / @skip
  • Variables go in a separate JSON object
