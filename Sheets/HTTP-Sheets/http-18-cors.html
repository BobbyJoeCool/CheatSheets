CORS

same-origin policy · Origin · preflight OPTIONS · Access-Control-Allow-* · credentials + wildcard · Max-Age

Letting Other Origins Read Your API

Browsers block a page's script from reading responses from a different origin (scheme + host + port). CORS is how a server opts in: it answers with Access-Control-Allow-Origin and friends. For anything beyond a "simple" request the browser first sends a preflight OPTIONS asking which method and headers are allowed, and only sends the real request if the answer says yes. CORS is enforced by the browser: curl, servers and mobile apps ignore it.

Notes

  • https://app.example.com and https://api.example.com are different origins
  • Simple = GET / HEAD / POST, standard headers, form or text/plain body; JSON triggers a preflight
  • Browsers cap Access-Control-Max-Age (Chrome: 2 hours)
  • Read non-standard response headers only if listed in Access-Control-Expose-Headers

Security Check

  • Allow-list exact origins; never reflect any Origin back with credentials allowed
  • * is fine for public, cookie-free data and is rejected with credentials anyway
  • CORS doesn't protect the API from non-browsers: still authenticate every request

Preflight, Then the Real Request

OPTIONS /api/orders HTTP/1.1
Origin: https://app.example.com
Access-Control-Request-Method: POST
Access-Control-Request-Headers: content-type, authorization

HTTP/1.1 204 No Content
Access-Control-Allow-Origin: https://app.example.com
Access-Control-Allow-Methods: GET, POST, PATCH, DELETE
Access-Control-Allow-Headers: Content-Type, Authorization
Access-Control-Allow-Credentials: true
Access-Control-Max-Age: 600
Vary: Origin

POST /api/orders HTTP/1.1
Origin: https://app.example.com
Content-Type: application/json

HTTP/1.1 201 Created
Access-Control-Allow-Origin: https://app.example.com
Access-Control-Allow-Credentials: true
Access-Control-Expose-Headers: Location
Location: /api/orders/9001
Vary: Origin

Code Explained

Browser asks: may this origin POST with these headers?
Server says yes and lets the browser cache that for 10 minutes
The real response repeats Allow-Origin or script can't read it
Vary: Origin stops a CDN serving one origin's answer to another

In Your Stack

  • Express — app.use(cors({ origin: ['https://app.example.com'], credentials: true }))
  • Django — django-cors-headers: CORS_ALLOWED_ORIGINS = [...] · CORS_ALLOW_CREDENTIALS = True
  • Spring — CorsConfigurationSource bean + .cors(withDefaults()), or @CrossOrigin(origins = ...)
  • Rails — rack-cors: allow { origins "https://app.example.com"; resource "*", credentials: true }
  • ASP.NET — AddCors(o => o.AddPolicy("app", p => p.WithOrigins(...).AllowCredentials())) + UseCors("app")
  • Go — rs/cors: cors.New(cors.Options{AllowedOrigins: ..., AllowCredentials: true}).Handler(mux)

Debug It

  • "No 'Access-Control-Allow-Origin' header": open the preflight in Network (method OPTIONS) and check its status
  • Preflight gets 401: auth middleware runs before CORS; let OPTIONS through without a token
  • A real 500 shows up as a CORS error if error responses skip the CORS headers

⚠ Common Mistakes

  • Access-Control-Allow-Origin: * with Allow-Credentials: true: browsers reject it
  • Trying to fix CORS in the front-end code; only the server's headers matter
  • Listing several origins in one Allow-Origin header; send the one that matched

✓ Tips & Best Practices

  • Same-origin is easiest: serve the SPA and /api from one host or proxy
  • Let a well-tested CORS middleware answer preflights; don't hand-write them
  • Test with curl -i -X OPTIONS -H 'Origin: ...' -H 'Access-Control-Request-Method: POST' url

Quick Summary

  • origin — scheme + host + port
  • preflight — OPTIONS before non-simple requests
  • Allow-Origin — exact origin, with Vary: Origin
  • Browser-only; not a security boundary for the API
