Sheet 01

How HTTP Works

client / server · request / response · stateless · TCP + TLS · HTTP/1.1 vs 2 vs 3 · HTTPS · HSTS

Requests In, Responses Out

HTTP is a text-based request / response protocol: a client (browser, app, curl, another server) sends a request, and the server sends back exactly one response. It is stateless: each request carries everything the server needs (auth, cookies, IDs), so any server behind a load balancer can answer it. HTTPS is the same protocol inside a TLS tunnel. HTTP/1.1, HTTP/2 and HTTP/3 change how bytes travel, not what methods, status codes and headers mean (RFC 9110).

Notes

  • Default ports: 80 for http://, 443 for https://
  • State lives in cookies, tokens or the database, never in the connection
  • HTTP/2 and HTTP/3 are binary on the wire, but tools show them as HTTP/1.1-style text
  • Browsers only use HTTP/2 and HTTP/3 over TLS

Security Check

  • Plain http:// sends tokens and cookies in clear text: serve every API over HTTPS
  • Add Strict-Transport-Security so browsers never try http:// again
  • Redirect 80 → 443 for pages, but reject API calls on port 80 instead of redirecting them

One Round Trip

GET /api/users/42 HTTP/1.1
Host: api.example.com
Accept: application/json
User-Agent: curl/8.10.1

HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 37
Cache-Control: no-store
Strict-Transport-Security: max-age=31536000; includeSubDomains

{"id":42,"name":"Ada","role":"admin"}

Code Explained

Line 1 is the request line: method · path · version
Host is required in HTTP/1.1; one IP can serve many sites
Response starts with the status line: version · code · reason
A blank line separates headers from the body in both directions
Content-Length is the body size in bytes (37 here)

In Your Stack

  • Express — app.get('/api/users/:id', (req, res) => res.json(user))
  • Django — path('api/users/<int:id>/', views.user), view returns JsonResponse
  • Spring — @GetMapping("/api/users/{id}") on a @RestController
  • Rails — get "/api/users/:id", to: "users#show" in config/routes.rb
  • ASP.NET — app.MapGet("/api/users/{id}", (int id) => ...)
  • Go — mux.HandleFunc("GET /api/users/{id}", h) (Go 1.22+ patterns)

⚠ Common Mistakes

  • Keeping per-user state in server memory: the next request may land on a different server
  • Trusting the client IP from the socket behind a proxy; read X-Forwarded-For only from trusted proxies
  • Assuming HTTP/2 changes your API: methods, codes and headers mean the same thing

✓ Tips & Best Practices

  • See the raw exchange any time with curl -v (sheet 03)
  • Behind a proxy, configure your framework's trusted-proxy setting so https and client IP are right
  • Turn on HTTP/2 at the proxy or CDN; app servers rarely need to change

Quick Summary

  • request — method + path + headers + optional body
  • response — status + headers + optional body
  • stateless — every request stands alone
  • HTTPS — HTTP over TLS; required for anything real
