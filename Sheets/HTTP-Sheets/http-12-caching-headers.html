Sheet 12

Caching Headers

Cache-Control · max-age · no-cache · no-store · private / public · ETag · If-None-Match · Vary

Don't Send What They Already Have

Cache-Control tells browsers and shared caches (CDNs, proxies) whether they may store a response and how long it stays fresh. When it goes stale, the client revalidates with a conditional request: If-None-Match with the ETag it has, or If-Modified-Since with Last-Modified. If nothing changed, the server sends 304 Not Modified with no body. The same validators guard writes: If-Match makes an update fail with 412 if someone else changed it first.

Notes

  • no-cache = store it, but revalidate every time; no-store = don't store at all
  • private = browser only; public / s-maxage = CDNs may cache too
  • A weak ETag (W/"v42") means "same meaning", not byte-identical
  • Age on a response = seconds it has sat in a shared cache

Security Check

  • Personal or authenticated responses: Cache-Control: private, no-store
  • A public response that varies by user leaks one user's data to the next
  • Logout pages and token endpoints must be no-store

Fresh, Revalidated, Never Stored

GET /api/products/7 HTTP/1.1

HTTP/1.1 200 OK
Cache-Control: public, max-age=60
ETag: "v42"
Last-Modified: Mon, 02 Nov 2026 15:00:00 GMT
Vary: Accept-Encoding

GET /api/products/7 HTTP/1.1
If-None-Match: "v42"

HTTP/1.1 304 Not Modified
ETag: "v42"
Cache-Control: public, max-age=60

GET /api/me HTTP/1.1
Authorization: Bearer eyJhbGciOi...

HTTP/1.1 200 OK
Cache-Control: private, no-store

Code Explained

Fresh for 60 s in the browser and in shared caches (public)
After 60 s the client asks "still v42?" and gets an empty 304
/api/me is per-user, so nothing may store it
Hash the content or use a version column to make ETags

In Your Stack

  • Express — ETags on by default (app.set('etag')); res.set('Cache-Control', 'no-store'); express.static(dir, { maxAge: '1y' })
  • Django — @cache_control(max_age=60) · @never_cache · ConditionalGetMiddleware
  • Spring — ResponseEntity.ok().cacheControl(CacheControl.maxAge(Duration.ofSeconds(60))).eTag("v42")
  • Rails — expires_in 1.minute, public: true · fresh_when(@product) · stale?
  • ASP.NET — [ResponseCache(Duration = 60)] for headers; AddOutputCache() for a server cache
  • Go — w.Header().Set("Cache-Control", ...); http.ServeContent answers conditional requests

Debug It

  • DevTools Size column: (memory cache) / (disk cache) = never hit the network
  • CDN hit or miss: look for Age, X-Cache: HIT or CF-Cache-Status
  • Normal reload revalidates; Empty Cache and Hard Reload refetches everything

Validators & Conditional Requests

HeaderRole
ETagVersion tag for the representation
If-None-MatchGET: send body only if changed → 304
If-MatchPUT/PATCH: only if unchanged → else 412
Last-ModifiedTimestamp validator (1 s resolution)
If-Modified-SinceDate-based conditional GET
VaryRequest headers that change the response

⚠ Common Mistakes

  • Thinking no-cache means "don't cache"; that's no-store
  • Long max-age on URLs that change (e.g. /app.js); use hashed file names instead
  • Forgetting Vary: Accept-Encoding or Vary: Origin when the response depends on them

✓ Tips & Best Practices

  • Static assets: hashed names + max-age=31536000, immutable
  • Use If-Match + ETag for optimistic locking on updates
  • Pick one: cache at the CDN with s-maxage, or not at all; partial setups confuse

Quick Summary

  • max-age — how long it's fresh
  • no-store — never cache; no-cache — always revalidate
  • ETag + If-None-Match — 304 when unchanged
  • If-Match — 412 on a lost update
