The Contract, Written in SDL

The Schema Definition Language (SDL) declares every type a client can ask for. Object types have fields; each field has a type and may take arguments. Built-in scalars are ID, String, Int, Float and Boolean; add custom ones like DateTime. Fields are nullable unless marked !. The root types Query, Mutation and Subscription are the entry points; input types describe arguments, and interfaces and unions model "one of several types".

Notes

  • ID is serialized as a string, even when it looks numeric
  • Int is 32-bit; use a custom scalar or String for big numbers
  • "Descriptions" in quotes show up in tools and docs
  • @deprecated(reason: "...") retires a field without a new version

An Orders Schema

"An order placed by a customer"
type Order implements Node {
  id: ID!
  status: OrderStatus!
  total: Int!                     # cents
  placedAt: DateTime!
  customer: Customer!
  items(first: Int = 20): [OrderItem!]!
  note: String                    # nullable
  legacyRef: String @deprecated(reason: "Use id")
}

interface Node { id: ID! }
enum OrderStatus { PENDING PAID SHIPPED CANCELLED }
scalar DateTime
union SearchResult = Order | Customer | Product

input PlaceOrderInput {
  customerId: ID!
  items: [OrderItemInput!]!
}

type Query {
  order(id: ID!): Order
  orders(status: OrderStatus, first: Int = 25, after: String): OrderConnection!
  search(text: String!): [SearchResult!]!
}

type Mutation {
  placeOrder(input: PlaceOrderInput!): PlaceOrderPayload!
}

Code Explained

order(id) returns Order (nullable): null means not found
[OrderItem!]! = a list that's never null, of items never null
input types can only hold scalars, enums and other inputs
orders returns a connection for cursor paging (sheet 28)

In Your Stack

  • Express — Schema-first: typeDefs in SDL + a resolvers map
  • Django — Code-first: @strawberry.type class Order: id: strawberry.ID ... (type hints)
  • Spring — Schema-first: src/main/resources/graphql/*.graphqls + @QueryMapping
  • Rails — Code-first: class Types::OrderType < Types::BaseObject + field :status, ...
  • ASP.NET — Code-first: plain C# classes (Query.GetOrder(id)) become the schema
  • Go — Schema-first: .graphqls files; gqlgen generate makes models and resolver stubs

⚠ Common Mistakes

  • Making everything non-null; one failing field then nulls its whole parent
  • Generic JSON scalars that throw away the type system
  • Separate createX / updateX arguments instead of one input type each

✓ Tips & Best Practices

  • Design the schema from UI needs, not database tables
  • One input and one payload type per mutation; easy to extend later
  • Run a schema diff in CI to catch breaking changes

Quick Summary
