Authentication Basics

authentication vs authorization · Authorization header · Basic · Bearer · API keys · WWW-Authenticate

Who Are You, and What May You Do?

Authentication proves who is calling; authorization decides what they may do. HTTP carries credentials in the Authorization header as <scheme> <credentials>, and a server that wants them answers 401 with WWW-Authenticate naming the scheme. Basic sends a Base64 username:password; Bearer sends a token (opaque or a JWT, sheet 15); API keys identify an application rather than a person; sessions use cookies (sheet 13).

Notes

  • Base64 is encoding, not encryption: Basic is only safe over HTTPS
  • Bearer means "whoever holds this token is the user"; protect it like a password
  • API keys often travel in a custom header such as X-API-Key
  • Check authorization on every request, at the resource, not just at login

Security Check

  • Store API keys hashed; show the full key once; give it a prefix (sk_live_) so leaks are searchable
  • Compare secrets in constant time; never log Authorization headers
  • Scope keys and tokens to the least access needed, and support rotation

Challenge and Credentials

GET /reports HTTP/1.1

HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer realm="api"

GET /reports HTTP/1.1
Authorization: Basic YWRhOnMzY3JldA==

GET /reports HTTP/1.1
Authorization: Bearer eyJhbGciOiJSUzI1NiJ9...

GET /reports HTTP/1.1
X-API-Key: sk_live_51Hx...

HTTP/1.1 200 OK

Code Explained

No credentials → 401 + which scheme to use
YWRhOnMzY3JldA== is just ada:s3cret in Base64
Bearer token: from a login or OAuth flow (sheets 16–17)
API key identifies the calling app; pair it with per-key limits

In Your Stack

  • Express — passport strategies, or middleware reading req.get('Authorization')
  • Django — django.contrib.auth; DRF DEFAULT_AUTHENTICATION_CLASSES + permission_classes
  • Spring — Spring Security SecurityFilterChain; .httpBasic() · .oauth2ResourceServer(o -> o.jwt())
  • Rails — has_secure_password · authenticate_or_request_with_http_token; Rails 8 auth generator
  • ASP.NET — AddAuthentication().AddJwtBearer(); [Authorize] / .RequireAuthorization("policy")
  • Go — Middleware: r.BasicAuth() or parse Authorization; put the user in r.Context()

Debug It

  • curl -v: is the > Authorization: line actually there?
  • Clients drop Authorization when a redirect goes to another host; call the final URL
  • Works locally, 401 behind a proxy: the proxy may strip or rename the header

⚠ Common Mistakes

  • Checking "is logged in" but not "owns this record" (BOLA, the #1 API flaw)
  • Putting API keys in URLs (?api_key=): they land in logs and browser history
  • Shipping a secret API key inside a mobile app or SPA bundle

✓ Tips & Best Practices

  • Centralize authentication in middleware; do authorization near the data
  • Return 401 with WWW-Authenticate, 403 when the identity is known
  • Use an identity provider instead of storing passwords if you can
