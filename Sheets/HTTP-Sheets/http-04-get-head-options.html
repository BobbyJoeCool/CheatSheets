Sheet 04

Reading: GET, HEAD & OPTIONS

GET · query params · no request body · HEAD · OPTIONS · Allow · conditional GET

Methods That Only Read

GET fetches a representation of a resource; everything that shapes the result (filters, paging, sort) goes in the query string, not a body. HEAD is GET without the body, so you can check size, type or freshness cheaply. OPTIONS asks what a resource supports; servers answer with an Allow header, and browsers use it for CORS preflight (sheet 18). All three are safe: they must not change server state.

Notes

  • A GET body has no defined meaning; proxies and caches may drop it
  • HEAD must return the same headers GET would, minus the body
  • OPTIONS * asks about the whole server; rarely used
  • Conditional GET (If-None-Match) can return 304 with no body (sheet 12)

Three Read Requests

GET /products?category=books&sort=-price&page=2 HTTP/1.1
Host: api.example.com
Accept: application/json

HEAD /files/report.pdf HTTP/1.1
Host: api.example.com

HTTP/1.1 200 OK
Content-Type: application/pdf
Content-Length: 482113
Last-Modified: Tue, 27 Oct 2026 14:02:11 GMT

OPTIONS /products/7 HTTP/1.1
Host: api.example.com

HTTP/1.1 204 No Content
Allow: GET, HEAD, PUT, PATCH, DELETE, OPTIONS

Code Explained

Query carries the filter, sort and page; the path stays /products
HEAD returns the PDF's size and date without downloading it
Content-Length on a HEAD response is the size GET would send
OPTIONS answers with Allow; 204 because there's no body

In Your Stack

  • Express — app.get() also answers HEAD automatically; OPTIONS via app.options() or cors()
  • Django — Class-based views answer HEAD with get() and OPTIONS automatically; @require_GET for functions
  • Spring — @GetMapping handles HEAD and OPTIONS (with Allow) out of the box
  • Rails — get routes also match HEAD; OPTIONS needs a route or rack-cors
  • ASP.NET — MapGet(); add HEAD with MapMethods(path, ["HEAD"], ...) if clients need it
  • Go — A "GET /path" pattern also matches HEAD

Debug It

  • curl -I url sends a real HEAD; compare its headers with curl -i
  • A search that "ignores" its filters may be sending them in a GET body: move them to the query
  • 405 on OPTIONS from a browser usually means CORS isn't set up (sheet 18)

⚠ Common Mistakes

  • Changing data in a GET handler (e.g. GET /users/42/delete): crawlers and prefetch will trigger it
  • Sending a JSON body with GET: it works locally, then a proxy or client library drops it
  • Returning a body on HEAD, or different headers than GET

✓ Tips & Best Practices

  • Use HEAD for "does it exist?" and "has it changed?" checks on large files
  • Keep query names consistent across endpoints: page, limit, sort, fields
  • Let the framework answer HEAD/OPTIONS; override only when you must

Quick Summary

  • GET — read; params in the query
  • HEAD — GET without the body
  • OPTIONS — what's allowed; CORS preflight
  • safe — none of them change state
