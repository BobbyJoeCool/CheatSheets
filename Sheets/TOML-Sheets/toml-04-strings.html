String Styles & Escapes

basic "…" · literal '…' · multi-line """ ''' · line-ending \ · \u \U · \e \xHH (1.1)

Four Kinds of String

TOML has four string styles: basic "…" (with escapes), literal '…' (no escapes), and the multi-line versions """…""" and '''…'''. A newline right after the opening delimiter is dropped, and in multi-line basic strings a backslash at the end of a line joins it to the next.

Notes

  • Literal strings suit Windows paths and regex: 'C:\Users\bob'
  • Basic strings can't contain a raw newline; use \n or """
  • Up to two quote characters in a row are fine inside """ and '''
  • TOML 1.1 adds \e (escape, U+001B) and \xHH (U+0000–U+00FF)
  • Tabs may appear raw (newlines too in multi-line forms); other control characters need a basic-string escape

String Forms

name   = "Bob \"BJ\" Breutzmann"
path   = 'C:\Users\bob\config'       # no escapes
regex  = '<\i\c*\s*>'
accent = "caf\u00e9"                 # café
bell   = "\x07 and \e[1m"            # TOML 1.1 only

poem = """
Roses are red
Violets are blue"""                  # first newline dropped

oneline = """\
    The quick brown \
    fox jumps."""                    # "The quick brown fox jumps."

raw = '''
C:\temp\new
'''                                  # backslashes kept

Code Explained

\" and \\ escape a quote and a backslash in basic strings
'…' keeps every character as written; there is no way to escape ' inside it
A line-ending \ removes the newline and the leading whitespace of the next line
\x07 and \e parse only in TOML 1.1; 1.0 parsers reject them

Same Data In…

  • JSON {"path": "C:\\Users\\bob\\config", "poem": "Roses are red\nViolets are blue"}
  • YAML path: 'C:\Users\bob\config' / poem: |- block literal

Gotcha

  • A literal '…' string can't hold '; use a basic string or '''…''' for that value
  • A closing """ on its own line adds a trailing newline to the value

⚠ Common Mistakes

  • Writing Windows paths in "…", where \U starts a Unicode escape and fails
  • Expecting '…' to turn \n into a newline
  • Forgetting the trailing newline added by a closing """ on its own line

✓ Tips & Best Practices

  • Default to literal strings for paths, globs and regex
  • Close """ right after the last word when you don't want a trailing newline
  • Wrap long text with a line-ending \ instead of one very long line

Quick Summary

  • "…" — basic, with escapes
  • '…' — literal, raw
  • """ / ''' — multi-line
  • \e \xHH — TOML 1.1 escapes
