Keys — Bare, Quoted & Dotted

bare keys · "quoted" · 'literal' · dotted keys a.b.c · empty key · duplicate keys

Three Ways to Name a Value

A key is bare (A–Z a–z 0–9 _ -), quoted ("…" or '…'), or dotted (a.b.c), which builds nested tables in one line. A bare key and its quoted spelling are the same key, and each key can be defined only once per table.

Notes

  • Bare keys may be all digits: 1234 = "ok"
  • Quoted keys follow single-line string rules: "site.com" = true
  • Whitespace around dots is ignored: fruit . color equals fruit.color
  • "" = "x" (empty quoted key) is legal but discouraged
  • A bare key can't be empty: = "x" is an error

Key Forms

name = "orders"            # bare
api-key = "abc"            # dashes are fine
1234 = "digits only"       # bare, all digits
"site.com" = true          # quoted: dot is literal
'C:\Users' = "home"        # literal quoted key

# dotted keys build nested tables
server.host = "0.0.0.0"
server.port = 8080
server."tls.cert" = "cert.pem"

3.14159 = "pi"             # { "3": { "14159": "pi" } }

# name = "again"           # ERROR: duplicate key
# "name" = "again"         # ERROR: same key as name

Code Explained

server.host and server.port create one table server with two keys
"tls.cert" is a single key containing a dot, inside server
3.14159 is two dotted bare keys, not a float
Bare name and quoted "name" collide because they are the same key

Same Data In…

  • JSON {"server": {"host": "0.0.0.0", "port": 8080, "tls.cert": "cert.pem"}}
  • YAML server: / host: 0.0.0.0 / tls.cert: cert.pem
  • .env SERVER_HOST=0.0.0.0 (flat; nesting is only a naming convention)

Gotcha

  • Bare keys are ASCII only; café = 1 needs quotes: "café" = 1
  • After server.port = 8080 at the root, a later [server] header redefines the table and fails

⚠ Common Mistakes

  • Writing my key = 1; spaces need quotes: "my key" = 1
  • Writing site.com = true and getting a table site with a key com
  • Defining the same key twice under two spellings

✓ Tips & Best Practices

  • Pick kebab-case or snake_case and stay consistent within a file
  • Use dotted keys for 1–3 nested settings; switch to a [table] header for more
  • Quote keys that hold paths, globs or hostnames: "tests/*"

Quick Summary

  • bare key — letters, digits, _, -
  • "quoted" — string rules
  • a.b.c — nested tables in one line
  • one definition per key
