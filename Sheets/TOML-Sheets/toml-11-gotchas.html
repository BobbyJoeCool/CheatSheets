Gotchas & Common Errors

redefined table · dotted keys vs headers · closed inline tables · [[ ]] vs [ ] · no null · int64 · 1.1 in 1.0 parsers

Most Errors Break the Define-Once Rule

Most TOML errors come from the define-once rule: a table, key or array can be created only once, and an inline table is closed for good. The rest come from types (no null, int64 limits, local date-times) and from TOML 1.1 syntax reaching a 1.0 parser.

Notes

  • Error count, wording and line/column details depend on the parser
  • "Duplicate key" and "cannot redefine table" are the most common messages
  • There is no null, so there is nothing to write for "unset"
  • Integers past int64 load only in some parsers; the rest must error, never wrap
  • A 1.0 parser fails on multi-line inline tables, \e, \xHH and seconds-free times

Five Broken Files

# 1. table defined twice
[server]
port = 8080
[server]                  # ERROR: redefined
host = "x"

# 2. dotted keys, then a header
db.host = "x"
[db]                      # ERROR: db already defined

# 3. extending an inline table
point = { x = 1 }
point.y = 2               # ERROR: inline is closed

# 4. static array, then [[ ]]
plugins = []
[[plugins]]               # ERROR

# 5. no null
timeout = null            # ERROR: not a value

Code Explained

1: merge both blocks under one [server] header
2: use [db] with host = "x", or keep dotted keys only
3: put y inside the braces: { x = 1, y = 2 }
4: pick one form, plugins = [ … ] or repeated [[plugins]]; 5: delete the line

Same Data In…

  • JSON duplicate keys usually parse, with the last one winning; TOML rejects them
  • YAML timeout: null is valid; in TOML you leave timeout out

Gotcha

  • Some writers sort keys or reflow arrays on save; diff the file after a round trip
  • Error wording differs between parsers; search by the line number, not the message

⚠ Common Mistakes

  • Copying a [table] block to the end of a file to "override" values
  • Writing null or none to clear a setting
  • Testing only with a 1.1 parser when users run 1.0 tools

✓ Tips & Best Practices

  • Run taplo lint (TOML 1.0) or tomllib.load (Python 3.15+ for 1.1) in CI on every TOML file
  • Go to the reported line first; the message names the rule, the line shows the clash
  • Store values past int64 (IDs, big counters) as strings

Quick Summary

  • define once — tables, keys, arrays
  • inline tables — closed when written
  • no null — omit the key
  • 1.0 parsers — no 1.1 syntax
