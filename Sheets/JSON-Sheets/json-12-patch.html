Sheet 12

JSON Patch & Merge Patch

RFC 6902 · op · path · add · remove · replace · move · copy · test · RFC 7396 merge patch

Sending Only the Changes

A PATCH request updates part of a resource. JSON has two standard formats for that. JSON Patch (RFC 6902) is an ordered list of operations — add, remove, replace, move, copy, test — each aimed at a JSON Pointer path. JSON Merge Patch (RFC 7396) is a partial document: send the keys to change, null to delete. Merge Patch is simpler to write; JSON Patch can edit arrays element by element and can fail safely with test.

JSON Pointer Paths (RFC 6901)

  • "" — the whole document; "/name" — top-level key
  • "/tags/0" — array index (zero-based); "/tags/-" — one past the end (append)
  • ~1 encodes / and ~0 encodes ~ in a key: key "a/b" → "/a~1b"
  • Pointers are exact — no wildcards or filters (that is JSONPath, Sheet 06)

Original Document

{ "name": "Ada", "role": "viewer", "tags": ["a", "b"],
  "address": { "city": "Paris", "zip": "75001" } }

JSON Patch — application/json-patch+json

[
  { "op": "test",    "path": "/role",   "value": "viewer" },
  { "op": "replace", "path": "/role",   "value": "admin" },
  { "op": "add",     "path": "/tags/-", "value": "c" },
  { "op": "add",     "path": "/tags/0", "value": "z" },
  { "op": "remove",  "path": "/address/zip" },
  { "op": "copy", "from": "/name", "path": "/nickname" },
  { "op": "move", "from": "/address/city", "path": "/city" }
]
// → { "name": "Ada", "role": "admin",
//     "tags": ["z","a","b","c"], "address": {},
//     "nickname": "Ada", "city": "Paris" }

Merge Patch — application/merge-patch+json

{ "role": "admin", "address": { "zip": null },
  "tags": ["c"] }
// → { "name": "Ada", "role": "admin", "tags": ["c"],
//     "address": { "city": "Paris" } }

Notes

test — aborts the whole patch if the value differs; use it for optimistic concurrency
add on an array index inserts and shifts later items; on an object key it creates or overwrites
replace — like remove + add, but the target must already exist
move / copy — take a from pointer instead of a value
Operations run in order; if any fails, none are applied
Merge Patch: objects merge recursively, null deletes, arrays are replaced whole
Merge Patch cannot set a value to null — null always means “delete”

Applying Patches in JavaScript

import { applyPatch, compare } from "fast-json-patch";
applyPatch(doc, ops).newDocument;  // apply
compare(before, after);            // diff → ops

Common Mistakes

  • Sending a Merge Patch to change one array element — the whole array is replaced with what you sent
  • Forgetting that ops run in order — after add /tags/0, every later index into tags has shifted by one
  • Using null in a Merge Patch to mean “set to null” — the key is deleted instead; use JSON Patch
  • Building pointers by string concatenation without escaping / and ~ in keys

Tips

  • Start a JSON Patch with a test op on a version field to avoid overwriting someone else’s change
  • Return 415 Unsupported Media Type when the Content-Type is not the patch format you accept
  • Generate patches with compare(before, after) rather than writing ops by hand
  • kubectl patch --type=merge and --type=json use these exact formats

Summary

  • JSON Pointer — /a/b/0 paths; - appends; ~1 = /
  • JSON Patch — ordered ops; atomic; arrays by index
  • test — guard op; whole patch fails on mismatch
  • Merge Patch — partial doc; null deletes; arrays replaced
