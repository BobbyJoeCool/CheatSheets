Sheet 09

JSON Schema in Practice

$schema drafts · if / then / else · dependentRequired · unevaluatedProperties · Ajv · jsonschema

Beyond the Core Keywords

Sheet 04 covers type, properties and required. Real payloads also need conditional rules (“if it’s a card payment, a card number is required”), dependencies between fields, and a way to reject unknown keys that still works when schemas are combined with allOf. This sheet covers those keywords, the differences between drafts that break schemas copied from old tutorials, and how to run validation in JavaScript (Ajv) and Python (jsonschema).

Which Draft?

  • $schema decides the rules; validators default to different drafts if it is missing
  • draft-07 — still the most common in tutorials and older tools
  • 2019-09 — added $defs, dependentRequired, unevaluatedProperties
  • 2020-12 — current; prefixItems replaced the array form of items
  • OpenAPI 3.1 uses 2020-12; OpenAPI 3.0 uses a modified draft-04/05 subset

Notes

"if" — a subschema; when the data matches it, "then" applies, otherwise "else"
"required": ["method"] inside if — without it, a payload with no method matches if and gets the card rule
"dependentRequired" — if billing is present, zip must be too
"unevaluatedProperties": false — rejects keys no subschema (including allOf / if branches) looked at
Ajv2020 — the default ajv import only understands draft-07; 2020-12 schemas need the ajv/dist/2020 build

Conditional Payment Schema (2020-12)

{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "object",
  "properties": {
    "method":  { "enum": ["card", "bank"] },
    "card":    { "type": "string", "pattern": "^[0-9]{16}$" },
    "iban":    { "type": "string" },
    "billing": { "type": "string" },
    "zip":     { "type": "string" }
  },
  "required": ["method"],
  "if":   { "properties": { "method": { "const": "card" } },
            "required": ["method"] },
  "then": { "required": ["card"] },
  "else": { "required": ["iban"] },
  "dependentRequired": { "billing": ["zip"] },
  "unevaluatedProperties": false
}

Validating It

// JavaScript — Ajv (npm i ajv ajv-formats)
import Ajv2020 from "ajv/dist/2020";       // 2020-12 build
import addFormats from "ajv-formats";
const ajv = new Ajv2020({ allErrors: true });
addFormats(ajv);                          // "format": "email" etc.
const validate = ajv.compile(schema);     // compile once, reuse
validate({ method: "card" });             // false
validate.errors[0].message;  // "must have required property 'card'"


# Python — jsonschema (pip install jsonschema)
from jsonschema import Draft202012Validator
v = Draft202012Validator(schema)
for err in v.iter_errors({"method": "bank", "billing": "x"}):
    print(err.message)   # 'iban' is a required property
                         # 'zip' is a dependency of 'billing'

Conditional & Dependency Keywords

KeywordMeaning
if / then / elseapply then when data matches if, else else
dependentRequiredkey A present → keys B, C required
dependentSchemaskey A present → whole subschema applies
constvalue must equal this exactly
unevaluatedPropertiesrule for keys no subschema evaluated
contains / minContainsarray must hold N items matching a schema

Common Mistakes

  • additionalProperties: false inside an allOf branch rejects keys defined in the *other* branch — use unevaluatedProperties: false at the top level instead
  • Loading a 2020-12 schema with the default Ajv import — it fails with “no schema with key or ref”; import ajv/dist/2020
  • Writing if without required — a missing field matches every properties check, so the then branch fires unexpectedly
  • Calling ajv.compile() on every request — compiling is slow; compile once at startup and reuse the function

Tips

  • Always set $schema so every tool reads the schema with the same draft rules
  • Use allErrors: true for form feedback; leave it off for fast API rejection
  • Validate in CI with ajv validate --spec=draft2020 -s schema.json -d "data/*.json" or check-jsonschema --schemafile
  • Validators: Ajv (JS), jsonschema (Python), networknt (Java), santhosh-tekuri/jsonschema (Go), JsonSchema.Net (.NET)

Summary

  • if / then / else — conditional rules on the same object
  • dependentRequired — one key requires others
  • unevaluatedProperties — strict objects that survive allOf
  • $schema — pin the draft; 2020-12 is current
  • Ajv2020 / Draft202012Validator — compile once, collect errors
