Type Aliases & Type Checking

typealias · type(of:) · is · Any · AnyObject · Self

Naming and Inspecting Types

typealias gives an existing type a second name, which is useful for long closure or generic types. At runtime, type(of:) returns a value's dynamic type and is tests it. Any holds a value of any type, AnyObject holds any class instance, and Self refers to the current type inside a type or protocol.

Notes

  • A typealias creates no new type: both names are interchangeable
  • Any loses type safety; avoid it in APIs
  • T.self is the metatype value for a type
  • Self (capital S) = current type; self = current instance

Aliases & Runtime Types

typealias UserID = String
typealias Completion = (Result<Data, Error>) -> Void
typealias Grid<T> = [[T]]           // generic alias

let id: UserID = "u_42"             // just a String

let values: [Any] = [1, "two", 3.0]
for v in values {
    print(type(of: v))              // Int, String, Double
    if v is String { print("string!") }
}

let t: Int.Type = Int.self          // metatype
t.init("5")                         // Optional(5)

struct Box {
    static func make() -> Self { Self() }   // Self = Box
}

⚠ Common Mistakes

  • Expecting a typealias to block mixing UserID and String: use a wrapper struct for real safety
  • Using Any arrays and casting everywhere: model the data with an enum or protocol
  • Confusing Self (type) with self (instance)

✓ Tips & Best Practices

  • Wrap IDs in a struct (struct UserID: Hashable { let raw: String }) for compile-time safety
  • Use typealiases to name long closure types used in many places
  • Use Never as a return type for functions that always fatalError
