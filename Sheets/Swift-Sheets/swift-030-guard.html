Early Exit with guard

guard checks a condition and, if it fails, must leave the current scope with return, throw, break, continue or a Never call. Values unwrapped by guard let stay available for the rest of the scope. This keeps the main path at the left margin instead of nested inside if blocks.

Notes

  • The else block is required and must exit
  • Unwrapped names live after the guard, unlike if let
  • Works in functions, loops (continue/break) and closures
  • guard let self else { return } is common in closures

guard in Practice

func register(name: String?, age: String?) throws -> User {
    guard let name, !name.isEmpty else {
        throw FormError.missingName
    }
    guard let ageText = age, let years = Int(ageText) else {
        throw FormError.badAge
    }
    guard years >= 13 else { throw FormError.tooYoung }

    return User(name: name, age: years)   // name, years usable here
}

for line in lines {
    guard !line.hasPrefix("#") else { continue }   // skip comments
    process(line)
}

loader.fetch { [weak self] data in
    guard let self else { return }
    self.show(data)
}

guard cond else { exit } — continue only if true

throw / return / continue — required exits
guard let self — safe self in closures

The Swifty Way

  • ✗ if let a { if let b { if let c { … } } }
    ✓ three guard let lines, then the logic — flat beats nested

Coming From…

  • Kotlin val x = y ?: return ≈ guard let x = y else { return }
  • TypeScript if (!x) return; early-return pattern
  • Python if x is None: return at top

⚠ Common Mistakes

  • An else block that doesn't exit: compile error
  • Using guard for normal branching where both paths continue
  • Forgetting that guard let names can't be redeclared later in the same scope

✓ Tips & Best Practices

  • Validate all inputs with guards at the top, then write the real work
  • Pair guard with throw to report why the input was bad
  • guard case .loaded(let data) = state else { return } works with patterns

Quick Summary

  • guard … else { exit } — early exit
  • Unwrapped values stay in scope
  • Keeps the happy path unindented
