Swift Beyond Apple

Swift Off Apple Platforms

The same compiler and standard library run on Linux and Windows, so Swift is used for servers, CLIs and cross-platform libraries. Foundation is available everywhere through swift-foundation and swift-corelibs-foundation, but Apple-only frameworks (SwiftUI, UIKit, Combine) are not. Newer targets include Embedded Swift for microcontrollers and WebAssembly.

Notes

  • Official Linux toolchains for Ubuntu, Debian, Fedora, Amazon Linux and others
  • Windows has been officially supported since Swift 5.3
  • Server frameworks: Vapor and Hummingbird, both on SwiftNIO
  • Docker images: swift:latest, swift:6.0-noble

Linux / Server Basics

# Docker: build and test a package on Linux
docker run --rm -v "$PWD":/app -w /app swift:latest swift test

# Guard Apple-only code with #if
#if canImport(UIKit)
import UIKit
#elseif os(Linux)
import Glibc
#endif

// Minimal Vapor route (Package dep: vapor/vapor)
import Vapor
let app = try await Application.make(.detect())
app.get("hello") { _ in "Hello from Linux" }
try await app.execute()

⚠ Common Mistakes

  • Importing SwiftUI or Combine in a package meant for Linux: the build fails there
  • Assuming every Foundation API exists on Linux; test there in CI
  • Using os(iOS) checks when you mean module availability (canImport)

✓ Tips & Best Practices

  • Run swift test in a swift:latest container in CI to catch Linux-only failures
  • Keep business logic in a platform-neutral package; keep UI in the app target
  • Swift Package Index (swiftpackageindex.com) shows which platforms each package supports

Quick Summary

  • Linux / Windows — full compiler + stdlib + Foundation
  • Vapor / Hummingbird — server-side Swift
  • #if canImport — write portable code
