Async Streams & Bridges

An AsyncSequence delivers values over time; you loop over it with for await. AsyncStream builds one from callbacks or events. To wrap a single callback-based API in an async function, use a continuation: withCheckedThrowingContinuation suspends until you call resume exactly once.

Notes

  • for try await for throwing sequences
  • A continuation must be resumed exactly once (checked at runtime)
  • AsyncStream.makeStream() returns stream + continuation (5.9)
  • Many Apple APIs expose AsyncSequences: url.lines, NotificationCenter.notifications

Streams & Continuations

// Wrap a completion-handler API
func currentLocation() async throws -> CLLocation {
    try await withCheckedThrowingContinuation { cont in
        legacyLocator.request { location, error in
            if let location { cont.resume(returning: location) }
            else { cont.resume(throwing: error ?? LocError.unknown) }
        }
    }
}

// A stream of values over time
func ticks(every s: Double) -> AsyncStream<Date> {
    AsyncStream { continuation in
        let timer = Timer.scheduledTimer(withTimeInterval: s, repeats: true) { _ in
            continuation.yield(.now)
        }
        continuation.onTermination = { _ in timer.invalidate() }
    }
}
for await t in ticks(every: 1).prefix(3) { print(t) }    // 3 ticks

let (stream, cont) = AsyncStream.makeStream(of: Int.self)
cont.yield(1); cont.finish()
for await n in stream { print(n) }                       // 1

⚠ Common Mistakes

  • Resuming a continuation twice, or never: runtime warning or crash, or a hung task
  • Forgetting onTermination cleanup: timers and observers leak
  • Iterating one AsyncStream from two places: values are split, not copied

✓ Tips & Best Practices

  • Use AsyncAlgorithms (Apple package) for debounce, merge, combineLatest
  • Use withCheckedContinuation in debug; only switch to unsafe after profiling
  • Set a bufferingPolicy on high-volume streams
