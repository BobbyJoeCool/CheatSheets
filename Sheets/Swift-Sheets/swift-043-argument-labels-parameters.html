Argument Labels & Parameters

argument labels · _ · default values · inout · & · parameter names

Labels and Parameters

Each parameter has an argument label (used at the call site) and a parameter name (used in the body). By default they're the same; write two names to make them differ, or _ to drop the label. Parameters are constants; mark one inout to let the function change the caller's variable, passed with &.

Notes

  • Labels make calls read like sentences: move(from: a, to: b)
  • Default values let callers skip arguments
  • Parameters with defaults usually go last
  • inout can't take a let or a literal

Labels, Defaults, inout

func move(from start: Int, to end: Int) -> Int { end - start }
move(from: 2, to: 9)                        // 7

func square(_ x: Int) -> Int { x * x }      // no label
square(5)                                   // 25

func greet(_ name: String, greeting: String = "Hello",
           punctuation: Character = "!") -> String {
    "\(greeting), \(name)\(punctuation)"
}
greet("Ada")                                // "Hello, Ada!"
greet("Ada", greeting: "Hi")                // "Hi, Ada!"

func doubleInPlace(_ n: inout Int) { n *= 2 }
var score = 21
doubleInPlace(&score)                       // score == 42

// x = 5    // error: parameters are let constants

Code Explained

from start: — label from, name start
_ x: — no label at the call site
= "Hello" — default argument
inout + & — modify the caller's var

The Swifty Way

  • ✗ func add(a: Int, b: Int)
    ✓ func add(_ a: Int, to b: Int) — read the call aloud: add(3, to: 5)

Coming From…

  • Kotlin Named args optional there; labels required here
  • TypeScript Options object {from, to} ≈ labels
  • Python Keyword args ≈ labels, but order is fixed here

Declaration → Call

DeclarationCall
f(x: Int)f(x: 1)
f(_ x: Int)f(1)
f(at x: Int)f(at: 1)
f(x: Int = 0)f() or f(x: 1)
f(_ x: inout Int)f(&n)

⚠ Common Mistakes

  • Passing labeled arguments in a different order: order is fixed
  • Forgetting & when calling an inout function
  • Using inout to return values instead of returning a tuple

✓ Tips & Best Practices

  • Follow the API Design Guidelines at swift.org for label naming
  • Omit the first label when it would repeat the function name: remove(item)
  • Prefer returning a new value over inout unless mutating in place matters

Quick Summary

  • label name: Type — two names
  • _ — unlabeled argument
  • inout / & — mutate caller's var
