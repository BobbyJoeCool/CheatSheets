Recursion

A recursive function calls itself on a smaller input until it reaches a base case. Swift handles recursion fine for moderate depths, but it doesn't guarantee tail-call optimization, so very deep recursion can overflow the stack. Indirect enums let you define recursive data types such as trees and expressions.

Notes

  • Always write the base case first
  • Main thread stack: 8 MB on macOS, 1 MB on iOS; others 512 KB
  • Memoize repeated subproblems with a dictionary
  • indirect lets an enum case contain its own type

Recursive Functions & Data

func factorial(_ n: Int) -> Int {
    n <= 1 ? 1 : n * factorial(n - 1)        // base case: n <= 1
}
factorial(5)                                 // 120

var memo: [Int: Int] = [:]
func fib(_ n: Int) -> Int {
    if n < 2 { return n }
    if let cached = memo[n] { return cached }
    let r = fib(n - 1) + fib(n - 2)
    memo[n] = r
    return r
}
fib(50)                                      // 12586269025

indirect enum Expr {
    case num(Int)
    case add(Expr, Expr)
    case mul(Expr, Expr)
}
func eval(_ e: Expr) -> Int {
    switch e {
    case .num(let n): n
    case .add(let a, let b): eval(a) + eval(b)
    case .mul(let a, let b): eval(a) * eval(b)
    }
}
eval(.add(.num(2), .mul(.num(3), .num(4))))  // 14

Code Explained

base case — stops the recursion
memo — cache results to avoid exponential work
indirect enum — recursive data type
switch + recursion — walk the structure

The Swifty Way

  • ✗ naive fib(n-1) + fib(n-2)
    ✓ memoize, or iterate with two vars — naive fib is O(2ⁿ)

Coming From…

  • Kotlin tailrec exists there; no Swift equivalent
  • Python Recursion limit ~1000; Swift limit is stack size
  • TypeScript Same: no reliable tail calls

Recursion vs Iteration

ApproachTrade-off
RecursionClear for trees, risks deep stacks
IterationConstant stack, more bookkeeping
MemoizedFast, uses memory
Explicit stackRecursion without call stack

⚠ Common Mistakes

  • Missing or unreachable base case: stack overflow (EXC_BAD_ACCESS)
  • Recursing over a 100k-element list: use a loop
  • Forgetting indirect: "recursive enum is not marked indirect"

✓ Tips & Best Practices

  • Convert deep recursion to a loop with an explicit [Node] stack
  • Use a nested helper function to hide accumulator parameters
  • indirect can mark just one case instead of the whole enum

Quick Summary

  • base case + smaller subproblem
  • memoize repeated work
  • indirect enum — recursive types
