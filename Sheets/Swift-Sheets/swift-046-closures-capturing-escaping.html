Closures — Capturing & Escaping

capture lists · [weak self] · @escaping · @autoclosure · non-escaping default

Capturing & Escaping

Closures capture the variables they use, keeping them alive. Capturing self strongly in a closure that self also holds creates a retain cycle, so use a capture list like [weak self]. A closure parameter that's stored or called later must be marked @escaping; non-escaping is the default and is cheaper.

Notes

  • Captured vars are shared by reference, not copied
  • Capture lists copy values at creation: [count]
  • @escaping closures must use self. explicitly (for classes)
  • @autoclosure wraps an argument expression in a closure

Capture Lists & @escaping

func makeCounter() -> () -> Int {
    var count = 0
    return { count += 1; return count }     // captures count
}
let next = makeCounter()
next(); next()                              // 1, 2

var x = 1
let byValue = { [x] in print(x) }           // copies 1 now
x = 99
byValue()                                   // 1

final class Loader {
    var onDone: (() -> Void)?
    func start(completion: @escaping () -> Void) {
        onDone = completion                 // stored → escaping
    }
    func setup() {
        start { [weak self] in
            guard let self else { return }
            self.finish()                   // no retain cycle
        }
    }
    func finish() {}
}

Capture Options

ListEffect
[weak self]Optional self, no retain
[unowned self]No retain, crash if freed
[x]Copy x at creation
[weak d = delegate]Rename + weak

Code Explained

capture — closure keeps count alive
[x] — capture list copies the current value
@escaping — closure outlives the call
[weak self] — break the self ↔ closure cycle
guard let self — strong self for the body

The Swifty Way

  • ✗ [unowned self] by default
    ✓ [weak self] + guard let self — unowned crashes if self is gone

Coming From…

  • Kotlin No cycles under GC; Swift's ARC needs [weak self]
  • TypeScript Closures capture by reference too; no leaks under GC
  • Java Lambdas need effectively-final vars; Swift allows mutation

In SwiftUI

  • SwiftUI views are structs: [weak self] isn't needed inside body
  • Do use [weak self] in long-lived Tasks in @Observable models
  • See SwiftUI 16 · @Observable Models

⚠ Common Mistakes

  • Storing a closure that strongly captures self in self: memory leak
  • Forgetting @escaping when storing a parameter: compile error
  • Expecting a captured var to be frozen: it's shared unless in a capture list

✓ Tips & Best Practices

  • Use Xcode's Memory Graph Debugger to find closure retain cycles
  • Non-escaping closures (e.g. map) never need [weak self]
  • Task { } captures self strongly; cancel long tasks in deinit or use weak

Quick Summary

  • closures capture by reference
  • [weak self] — avoid cycles
  • @escaping — closure stored or run later
