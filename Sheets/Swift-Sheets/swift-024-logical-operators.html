Logical Operators

&& · || · ! · short-circuit · precedence · grouping with ()

Boolean Logic

The logical operators && (and), || (or) and ! (not) work only on Bool. && and || short-circuit: the right side is skipped if the left side already decides the result. In if, guard and while, a comma also means "and", and it lets you mix in let unwrapping.

Notes

  • && binds tighter than ||
  • Use parentheses whenever you mix && and ||
  • Comma-separated conditions are evaluated left to right
  • ! must touch its operand: !isReady, not ! isReady

Logical Operators

let isAdmin = false, isOwner = true, isLocked = false

isAdmin || isOwner                  // true
isOwner && !isLocked                // true
!(isAdmin || isOwner)               // false

// short-circuit: second call never runs
func expensive() -> Bool { print("ran"); return true }
false && expensive()                // false, prints nothing
true  || expensive()                // true, prints nothing

// mixing needs parentheses for clarity
if (isAdmin || isOwner) && !isLocked { print("can edit") }

// commas in conditions = && plus unwrapping
let input: String? = "42"
if let s = input, let n = Int(s), n > 0 {
    print(n)                        // 42
}

Code Explained

|| — true if either side is true
&& — true if both sides are true
! — negation
short-circuit — right side may never run
if a, b, c — all must hold; can include let

The Swifty Way

  • ✗ if a == true && b == false
    ✓ if a && !b
  • ✗ nested if for each condition
    ✓ if let x, let y, x > y { }

⚠ Common Mistakes

  • Relying on &&-over-|| precedence without parentheses: hard to read and easy to break
  • Putting a side effect on the right of &&/|| and expecting it to always run
  • Writing ! x with a space: parsed differently or a compile error

✓ Tips & Best Practices

  • Name complex conditions: let canEdit = (isAdmin || isOwner) && !isLocked
  • Put cheap checks first so short-circuiting skips costly ones
  • Use allSatisfy / contains(where:) for collection-wide logic
