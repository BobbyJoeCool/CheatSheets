Sheet 067

Access Control

open · public · package · internal · fileprivate · private · private(set)

Access Levels

Access control limits which code can see a declaration. From most to least open: open, public, package, internal (the default), fileprivate and private. The boundary that matters most is the module: internal code is visible across your whole app target but not to other modules.

Notes

  • internal is the default; you rarely need to write it
  • private is visible in the enclosing declaration and its extensions in the same file
  • open allows subclassing/overriding from other modules; public does not
  • A type's members can't be more visible than the type

Access Modifiers

// In a framework module "Payments"
public struct Price {
    public let cents: Int
    public init(cents: Int) { self.cents = cents }   // must be public
    var display: String { "$\(cents / 100)" }        // internal
}

open class PaymentView {                  // subclassable elsewhere
    open func render() {}                 // overridable elsewhere
    public func reset() {}                // callable, not overridable
}

package func sharedHelper() {}            // visible in same package

final class Cart {
    private(set) var items: [String] = [] // read outside, write inside
    private var token = ""                // this type + same-file extensions
    fileprivate func audit() {}           // whole file
}
extension Cart {
    func add(_ s: String) { items.append(s); token = s }  // ok: same file
}

Levels (open → closed)

LevelVisible to
openAll modules, subclassable
publicAll modules
packageModules in the same package
internalSame module (default)
fileprivateSame file
privateEnclosing scope + same-file extensions

Code Explained

public — usable from other modules
open — plus subclass/override
package — same Swift package only
private(set) — public read, private write
private — type + same-file extensions

The Swifty Way

  • ✗ everything public in an app target
    ✓ default internal; private for details — access control matters at module borders

Coming From…

  • Java package ≈ package-private; private ≈ private
  • Kotlin internal means module there too
  • TypeScript export ≈ public; #private ≈ private

Swift Versions

  • 5.9 — package access level
  • 4.0 — private includes same-file extensions

⚠ Common Mistakes

  • Forgetting a public init on a public struct: other modules can't create it
  • Using open when public is enough: you promise subclass support forever
  • Making properties public var when callers should only read: use public private(set)

✓ Tips & Best Practices

  • Split apps into local packages so internal actually hides things
  • Default to private; widen only when the compiler asks
  • @testable import lets tests reach internal symbols

Quick Summary

  • open › public › package › internal › fileprivate › private
  • internal — default
  • private(set) — read-only outside
