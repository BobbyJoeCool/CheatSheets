Sendable & Strict Concurrency

Sendable · @Sendable · Swift 6 language mode · data-race errors · sending · @unchecked Sendable

Data-Race Safety

Sendable marks types that are safe to share between concurrent tasks. Value types with Sendable members, actors and immutable final classes qualify. In the Swift 6 language mode, the compiler checks every crossing between isolation domains and turns potential data races into compile errors.

Notes

  • Structs/enums are implicitly Sendable when all members are (non-public)
  • Closures crossing tasks must be @Sendable
  • sending parameters transfer ownership to another domain
  • @unchecked Sendable = you promise thread safety manually

Sendable in Practice

struct Point: Sendable { var x, y: Double }         // value type: easy

final class Config: Sendable {                     // immutable class
    let apiURL: URL
    init(apiURL: URL) { self.apiURL = apiURL }
}

final class Counter: @unchecked Sendable {         // manual safety
    private let lock = NSLock()
    private var value = 0
    func increment() { lock.withLock { value += 1 } }
}

class Cache { var items: [String] = [] }           // not Sendable
let cache = Cache()
Task { cache.items.append("x") }                   // Swift 6: error
// "sending 'cache' risks causing data races"

func process(_ job: sending Job) async { … }       // ownership moves

// Package.swift
// swiftLanguageModes: [.v6]
// Xcode: Build Settings › Swift Language Version = 6

Code Explained

Sendable struct — copied safely
final class with only lets — Sendable
@unchecked Sendable — you guarantee it
non-Sendable capture — compile error in Swift 6
sending — transfer ownership

The Swifty Way

  • ✗ @unchecked Sendable to silence errors
    ✓ make it a struct, an actor, or immutable — unchecked hides real races

Coming From…

  • Rust Send / Sync ≈ Sendable checks
  • Kotlin No compile-time race checks
  • Java No equivalent; races found at runtime

Swift Versions

  • 5.5 — Sendable introduced
  • 6.0 — Swift 6 mode: full data-race checking, sending
  • 6.2 — nonisolated(nonsending), @concurrent, approachable defaults

⚠ Common Mistakes

  • Turning on Swift 6 mode for a big app in one step: migrate module by module
  • Spreading @unchecked Sendable and nonisolated(unsafe) everywhere
  • Capturing a non-Sendable class in Task { }

✓ Tips & Best Practices

  • Enable -strict-concurrency=complete warnings first, then switch modes
  • Prefer value types for data passed between tasks
  • Use Mutex from the Synchronization module for small shared state

Quick Summary

  • Sendable — safe to share
  • Swift 6 mode — races are errors
  • @unchecked — last resort
