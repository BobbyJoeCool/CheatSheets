Classes

class · reference semantics · deinit · identity === · final

Reference Types with class

A class is a reference type: variables hold references, so two variables can point at the same object and see each other's changes. Classes support inheritance, identity comparison with ===, and a deinit that runs when the last reference goes away (ARC). Classes get no memberwise init: all stored properties need defaults or an init.

Notes

  • Mark classes final unless you design for subclassing
  • let obj = MyClass() still allows changing its var properties
  • No mutating keyword: methods can always change properties
  • Classes are needed for Objective-C interop and shared mutable state

Defining a Class

final class BankAccount {
    let owner: String
    private(set) var balance: Double

    init(owner: String, balance: Double = 0) {
        self.owner = owner
        self.balance = balance
    }
    deinit { print("closing \(owner)'s account") }

    func deposit(_ amount: Double) { balance += amount }
}

let a = BankAccount(owner: "Ada")
let b = a                                   // same object
b.deposit(100)
a.balance                                   // 100.0 (shared)
a === b                                     // true

var c: BankAccount? = BankAccount(owner: "Temp")
c = nil                                     // closing Temp's account

Code Explained

final class — no subclasses, faster dispatch
init — required to set every stored property
deinit — runs when the last reference is released
b = a — copies the reference, not the object
=== — same instance

The Swifty Way

  • ✗ class with no final
    ✓ final class until a subclass is needed — clearer intent, static dispatch

⚠ Common Mistakes

  • Expecting let to make a class instance immutable
  • Creating retain cycles between objects (parent ↔ child): use weak
  • Sharing a class instance across threads without isolation (Swift 6 flags this)

✓ Tips & Best Practices

  • Use @Observable final class for SwiftUI view models
  • Use actor instead of class for shared mutable state across tasks
  • Add a deinit print while debugging leaks
