Async Functions

An async function can suspend while waiting (for the network, disk, or another task) without blocking a thread. You call it with await, which marks each possible suspension point. async let starts child work in parallel, and Task { } starts async work from synchronous code such as a button action.

Notes

  • await can only appear in an async context
  • Order: try await (try first)
  • A suspended function may resume on a different thread
  • Properties can be async getters: var data: Data { get async throws }

async / await

func fetchUser(id: Int) async throws -> User {
    let url = URL(string: "https://api.example.com/users/\(id)")!
    let (data, _) = try await URLSession.shared.data(from: url)
    return try JSONDecoder().decode(User.self, from: data)
}

func loadProfile() async throws -> Profile {
    async let user = fetchUser(id: 1)            // starts now
    async let posts = fetchPosts(userID: 1)      // runs in parallel
    return try await Profile(user: user, posts: posts)   // wait for both
}

// From synchronous code (e.g. a button action)
func refreshTapped() {
    Task {
        do { let p = try await loadProfile(); show(p) }
        catch { showError(error) }
    }
}

@main struct Tool {
    static func main() async throws { print(try await loadProfile()) }
}

In SwiftUI

  • .task { await model.load() } runs when a view appears and cancels on disappear
  • Button actions start work with Task { await … }
  • See SwiftUI 37 · .task, onAppear & onChange

⚠ Common Mistakes

  • Awaiting calls one by one when they could run in parallel with async let
  • Calling blocking APIs (sleep, semaphore.wait) in async code
  • Creating Task { } in loops without keeping or cancelling them

✓ Tips & Best Practices

  • Wrap old callback APIs with continuations (Sheet 103)
  • Use Task.sleep(for: .seconds(1)) for delays
  • Mark UI-touching functions @MainActor (Sheet 101)

Quick Summary

  • async / await — suspend, don't block
