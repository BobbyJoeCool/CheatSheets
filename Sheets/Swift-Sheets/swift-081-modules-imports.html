Modules and import

A module is a unit of code distribution: an app target, a framework, or a Swift package target. Everything inside a module shares one namespace, so files don't import each other. You import other modules to use their public API. Foundation and Swift's standard library are the two you'll see most.

Notes

  • The stdlib (Swift module) is imported automatically
  • Two modules can define the same name; qualify with Module.Name
  • @testable import exposes internal symbols to tests
  • import struct Module.Type imports a single declaration

import Forms

import Foundation                 // dates, URLs, files, JSON
import SwiftUI                    // UI (Apple platforms)
import OSLog                      // Logger
import struct Foundation.UUID     // just one type
@testable import MyApp            // tests can see internal

import Collections                // a package product

#if canImport(UIKit)
import UIKit
#endif

// Name clash: qualify with the module
let a = Swift.Result<Int, Error>.success(1)
let b = MyApp.Result.ok           // your own type named Result

// Same module = no import needed
// File A.swift: struct Helper {}
// File B.swift: let h = Helper()

Code Explained

import Foundation — the core library
import struct M.T — import one symbol
@testable import — tests see internals
#if canImport — optional imports
Swift.Result — module-qualified name

The Swifty Way

  • ✗ import UIKit in every model file
    ✓ import only what the file uses — keeps models portable and builds faster

Coming From…

  • Java import pkg.Class ≈ import struct Module.Type
  • Python import x ≈ import X; no per-file imports inside a module
  • TypeScript No per-file imports needed inside a module

⚠ Common Mistakes

  • Expecting import between files in the same target: not needed
  • Naming your type the same as a common module type (Result, Task)
  • Importing SwiftUI in a package that should build on Linux

✓ Tips & Best Practices

  • Split large apps into local Swift packages (one module per feature)
  • Use @_exported import sparingly: it re-exports a module
  • Watch build times: fewer imports per file helps incremental builds

Quick Summary

  • module = target / package product
  • import other modules only
  • @testable import for tests
