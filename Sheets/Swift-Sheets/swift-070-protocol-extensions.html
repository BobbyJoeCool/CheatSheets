Protocol Extensions

Extensions on a protocol add default implementations that every conforming type gets for free. This is the heart of protocol-oriented programming: share behavior through protocols and extensions instead of base classes. A where clause limits an extension to conforming types that meet extra constraints.

Notes

  • Conforming types can still provide their own version
  • Methods only in the extension (not the protocol) are statically dispatched
  • extension Collection where Element: Numeric targets a subset
  • This is how the stdlib gives every Collection map, filter …

Defaults & Constraints

protocol Greeter {
    var name: String { get }
    func greet() -> String                     // requirement
}
extension Greeter {
    func greet() -> String { "Hello, \(name)" }  // default
    func shout() -> String { greet().uppercased() }  // extra helper
}

struct English: Greeter { let name: String }
struct Pirate: Greeter {
    let name: String
    func greet() -> String { "Ahoy, \(name)" }   // custom
}
English(name: "Ada").greet()                   // "Hello, Ada"
Pirate(name: "Jack").shout()                   // "AHOY, JACK"

extension Collection where Element: Numeric {
    var total: Element { reduce(0, +) }
}
[1, 2, 3].total                                // 6
[1.5, 2.5].total                               // 4.0

Code Explained

custom override — conforming type wins
extra helper — available to all conformers
where Element: Numeric — constrained extension

The Swifty Way

  • ✗ class BaseGreeter with overridable methods
    ✓ protocol Greeter + extension defaults

Coming From…

  • Java Default methods in interfaces ≈ protocol extensions
  • Kotlin Interface default methods + extension functions
  • TypeScript No equivalent; mixins come closest

⚠ Common Mistakes

  • Adding a method only in the extension, overriding it in a type, then calling through any P: the default runs
  • Huge protocol extensions that hide where behavior comes from
  • Constraining with where Self: SomeClass when a separate protocol is clearer

✓ Tips & Best Practices

  • List a method in the protocol body if conformers should be able to customize it
  • Use constrained extensions to add APIs only where they make sense
  • Combine with some P generics for zero-cost abstractions

Quick Summary

  • extension on protocol = defaults
  • where — constrained extensions
  • protocol-oriented over class-based
