ARC Basics

ARC · strong references · reference counting · deinit · value types and ARC

Automatic Reference Counting

Swift manages class instance memory with ARC: each strong reference adds to a count, and when the count drops to zero the instance is freed immediately and its deinit runs. There is no garbage collector and no pauses. Value types (structs, enums) aren't reference counted themselves, though class references stored inside them are.

Notes

  • Deallocation is deterministic: right when the last strong ref goes
  • deinit is the place for cleanup (observers, files)
  • Copy-on-write collections use ARC on their hidden buffers
  • The optimizer removes many retain/release pairs

Watching ARC Work

final class Session {
    let name: String
    init(name: String) { self.name = name; print("open \(name)") }
    deinit { print("close \(name)") }
}

var a: Session? = Session(name: "A")     // open A   (count 1)
var b = a                                // count 2
a = nil                                  // count 1
b = nil                                  // close A  (count 0)

do {
    let temp = Session(name: "T")        // open T
    print(temp.name)
}                                        // close T (scope ended)

func make() -> Session { Session(name: "R") }
let kept = make()                        // returned: stays alive

isKnownUniquelyReferenced(&storage)      // copy-on-write check

Code Explained

strong reference — keeps the object alive
= nil — releases a reference
deinit — runs at count 0
end of scope — locals released
isKnownUniquelyReferenced — used for COW

The Swifty Way

  • ✗ calling a close() you might forget
    ✓ clean up in deinit (or defer)

Coming From…

  • Java GC frees later; ARC frees immediately
  • Kotlin JVM GC; Kotlin/Native uses a GC too
  • Python Ref counting + cycle collector; Swift has no cycle collector

Reference Kinds

KindKeeps alive?
strong (default)Yes
weakNo, becomes nil
unownedNo, must outlive use
unowned(unsafe)No, no checks

⚠ Common Mistakes

  • Expecting a cycle collector: cycles leak forever
  • Doing heavy work or async calls in deinit
  • Relying on deinit timing for objects captured by escaping closures

✓ Tips & Best Practices

  • Add a deinit print to confirm screens and models are freed
  • Use Instruments › Allocations to watch object counts
  • Prefer value types to avoid ARC traffic in hot paths

Quick Summary

  • ARC — reference counting, no GC
  • freed at count 0; deinit runs
  • structs aren't counted
