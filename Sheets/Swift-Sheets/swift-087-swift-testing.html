Swift Testing

Swift Testing is the modern test framework that ships with Xcode 16 and the Swift 6 toolchain. Tests are plain functions marked @Test; checks use the #expect and #require macros, which print the actual values on failure. Suites are just types, and parameterized tests run one function over many inputs.

Notes

  • Runs alongside XCTest in the same target
  • Tests run in parallel by default
  • #require stops the test on failure; #expect continues
  • Tests can be async and throws

Tests with @Test

import Testing
@testable import MyApp

@Test func addition() {
    #expect(2 + 2 == 4)
}

@Suite("Cart")
struct CartTests {
    var cart = Cart()                          // fresh per test

    @Test("Adding an item increases count")
    mutating func add() throws {
        cart.add("apple")
        #expect(cart.count == 1)
        let first = try #require(cart.items.first)   // stop if nil
        #expect(first == "apple")
    }

    @Test(arguments: ["", " ", "\n"])
    func rejectsBlank(name: String) {
        #expect(throws: CartError.blankName) { try Cart().add(named: name) }
    }

}

Code Explained

@Test — mark a test function
#expect(cond) — check, show values on failure
#require — unwrap or stop the test
arguments: — parameterized test
@Suite — group tests in a type

The Swifty Way

  • ✗ XCTAssertEqual(a, b) in new tests
    ✓ #expect(a == b) — one macro, better failure messages

Coming From…

  • Kotlin JUnit 5 @ParameterizedTest ≈ arguments:

  • Python pytest functions + parametrize ≈ @Test

Swift Versions

  • 6.0 toolchain / Xcode 16 — Swift Testing ships built in

⚠ Common Mistakes

  • Sharing mutable static state between parallel tests
  • Using #expect(x != nil) then force-unwrapping: use try #require(x)
  • Forgetting @testable import for internal symbols

✓ Tips & Best Practices

  • Run from the CLI with swift test --filter CartTests
  • Use confirmation { } to test callbacks or events
  • Use withKnownIssue { } for expected failures
