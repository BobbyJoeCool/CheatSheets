Type Conversion & Casting

Int(_:) · Double(_:) · failable String init · as · as? · as!

Converting Between Types

Swift never converts numeric types implicitly: Int + Double is a compile error. You convert with an initializer (Double(x)), and conversions that can fail, such as parsing a string, return an optional. For class hierarchies and protocols, as? casts safely, as! forces, and as upcasts or bridges.

Notes

  • Numeric initializers truncate or trap on out-of-range values
  • Int(exactly:) returns nil instead of losing data
  • String(x) and "\(x)" both stringify
  • as? returns an optional; as! traps on failure

Conversions

let i = 7, d = 2.5
Double(i) * d                       // 17.5
Int(d)                              // 2 (truncates)
Int(d.rounded())                    // 3 (round first)
Int(exactly: 2.5)                   // nil
Int8(300)                           // CRASH: out of range
Int8(clamping: 300)                 // 127
UInt8(truncatingIfNeeded: 300)      // 44

Int("123")                          // Optional(123)
Int("12a")                          // nil
Int("ff", radix: 16)                // Optional(255)
Double("3.14")                      // Optional(3.14)
String(42)                          // "42"
String(255, radix: 2)               // "11111111"

let anyValue: Any = "hi"
anyValue as? String                 // Optional("hi")
anyValue as? Int                    // nil

Code Explained

Double(i) — explicit numeric conversion
Int(exactly:) — nil if not representable
clamping: / truncatingIfNeeded: — non-trapping
Int(_:radix:) / String(_:radix:) — base conversion
as? — conditional cast

The Swifty Way

  • ✗ let n = Int(text)!
    ✓ guard let n = Int(text) else { … } — user input fails sometimes

Coming From…

  • Java No implicit widening; always explicit
  • TypeScript Number(s) ≈ Double(s) but returns nil, not NaN
  • Python int(s) raises; Int(s) returns nil

⚠ Common Mistakes

  • Adding Int and Double directly: convert one side first
  • Int8(300) and similar: out-of-range numeric init traps; use clamping:
  • Int(" 42") with whitespace returns nil: trim first

✓ Tips & Best Practices

  • Use Int(text.trimmingCharacters(in: .whitespaces)) for user input
  • Prefer as? with if let over is followed by as!
  • Int(exactly:) is the safe way to accept only whole-number Doubles

Quick Summary

  • Type(value) — explicit conversion
  • Int("…") — failable parsing
  • as? / as! / is — runtime casts
