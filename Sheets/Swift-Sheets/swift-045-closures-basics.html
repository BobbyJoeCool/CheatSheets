Closures — Basics

{ (x) in } · trailing closures · $0 shorthand · implicit return · multiple trailing closures

Closure Syntax

A closure is an unnamed function written inline: { (params) -> Return in body }. Swift lets you shrink it step by step: infer types, drop return for one expression, use $0 shorthand, and move it outside the parentheses as a trailing closure. Trailing closures are why Swift APIs (and SwiftUI) read like blocks.

Notes

  • If the closure is the only argument, drop the () too
  • Multiple trailing closures: the first is unlabeled, the rest labeled
  • $0, $1 … refer to parameters by position
  • Use named parameters when the closure is longer than a line

From Full to Short

let names = ["Chris", "Alex", "Ewa"]

names.sorted(by: { (a: String, b: String) -> Bool in
    return a < b
})
names.sorted(by: { a, b in a < b })         // inferred types
names.sorted { $0 < $1 }                    // trailing + shorthand
names.sorted(by: <)                         // operator as function

let shout = { (s: String) -> String in s.uppercased() + "!" }
shout("hi")                                 // "HI!"

names.map { $0.count }                      // [5, 4, 3]

UIView.animate(withDuration: 0.3) {         // multiple trailing
    view.alpha = 0
} completion: { _ in
    view.removeFromSuperview()
}

Shortening Steps

StepForm
Full{ (x: Int) -> Int in return x * 2 }
Infer types{ x in return x * 2 }
Implicit return{ x in x * 2 }
Shorthand{ $0 * 2 }

Code Explained

{ (a, b) -> Bool in … } — full syntax
in — separates the signature from the body
$0 $1 — positional shorthand
trailing closure — after ) or instead of ()
completion: — label for later trailing closures

The Swifty Way

  • ✗ items.map({ (item: Item) -> String in return item.name })
    ✓ items.map(\.name) — key paths work as functions

Coming From…

  • Kotlin Trailing lambdas list.map { it * 2 } ≈ { $0 * 2 }
  • TypeScript (a, b) => a < b ≈ { a, b in a < b }
  • Python lambda x: x * 2 ≈ { $0 * 2 }

Swift Versions

  • 5.3 — multiple trailing closures

In SwiftUI

  • Button("Save") { save() } — action is a trailing closure
  • VStack { … } — content is a trailing @ViewBuilder closure
  • See SwiftUI 20 · Buttons

⚠ Common Mistakes

  • Using $0/$1 in multi-line closures: hard to follow; name them
  • Trailing closure in an if condition: wrap the call in parentheses
  • Mixing $0 with named parameters in one closure: not allowed

✓ Tips & Best Practices

  • Read in as "where the body begins"
  • Annotate the closure's type when inference produces confusing errors
  • Prefer key paths (\.name) for simple property access

Quick Summary

  • { params in body } — closure
  • $0 — shorthand parameter
  • trailing closures — cleaner calls
