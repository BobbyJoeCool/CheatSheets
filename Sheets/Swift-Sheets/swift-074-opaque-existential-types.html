Opaque & Existential Types

some · any · primary associated types · type erasure · some View

some vs any

some P is an opaque type: one specific concrete type that conforms to P, chosen by the implementation and known to the compiler (fast, full type info). any P is an existential: a box that can hold *any* conforming type, which can change at runtime (flexible, small runtime cost). Use some by default and any when you truly need mixed types.

Notes

  • some P as a parameter = shorthand for a generic <T: P>
  • A function returning some P must return one concrete type on every path
  • any P allows heterogeneous arrays: [any Shape]
  • Primary associated types: some Collection<Int>

Opaque & Existential

protocol Shape { func area() -> Double }
struct Circle: Shape { var r = 1.0; func area() -> Double { .pi * r * r } }
struct Square: Shape { var s = 2.0; func area() -> Double { s * s } }

func makeShape() -> some Shape { Circle() }   // one hidden concrete type
// func bad(_ b: Bool) -> some Shape { b ? Circle() : Square() }  // error

var shapes: [any Shape] = [Circle(), Square()]   // mixed: needs any
shapes.append(Circle(r: 3))

func printArea(_ s: some Shape) { print(s.area()) }   // generic shorthand
func total(_ list: [any Shape]) -> Double { list.map { $0.area() }.reduce(0, +) }

func evens(_ xs: some Collection<Int>) -> [Int] { xs.filter { $0 % 2 == 0 } }
evens(1...10)                                  // [2, 4, 6, 8, 10]

var current: any Shape = Circle()
current = Square()                             // can change type

The Swifty Way

  • ✗ func f(_ s: any Shape) for a single value
    ✓ func f(_ s: some Shape) — static dispatch, no boxing

Swift Versions

In SwiftUI

  • var body: some View — one concrete (huge) type the compiler knows
  • See SwiftUI 55 · Performance & Debugging

⚠ Common Mistakes

  • Returning different concrete types from a some P function
  • Using any P everywhere "to be safe": slower and loses type info
  • Forgetting any before a protocol type in Swift 6 mode: warning/error

✓ Tips & Best Practices

  • Default to some; reach for any only for mixed collections
  • You can often open an any P by passing it to a some P parameter
  • Use @ViewBuilder to return different views from one function

Quick Summary

  • some P — one hidden concrete type
  • any P — box for any conformer
  • prefer some
