FileManager & Paths

URL · FileManager · URL.documentsDirectory · appending(path:) · fileExists · createDirectory

Locating Files

Foundation represents file locations as URLs, and FileManager performs file-system operations: checking existence, creating folders, listing, moving and deleting. On Apple platforms, apps are sandboxed, so you write into well-known folders such as Documents, Caches and tmp, found through static URL properties.

Notes

  • Prefer URL over path strings everywhere
  • URL.documentsDirectory etc. need iOS 16 / macOS 13
  • Documents is backed up; Caches can be purged by the system
  • appending(path:) adds a component; path() returns the string

Paths & FileManager

import Foundation
let fm = FileManager.default

let docs = URL.documentsDirectory
let file = docs.appending(path: "notes/today.txt")
file.lastPathComponent                       // "today.txt"
file.pathExtension                           // "txt"
file.deletingLastPathComponent()             // …/Documents/notes/

let folder = docs.appending(path: "notes")
try fm.createDirectory(at: folder, withIntermediateDirectories: true)
fm.fileExists(atPath: file.path())           // false

let items = try fm.contentsOfDirectory(at: docs,
                includingPropertiesForKeys: [.fileSizeKey])
for url in items where url.pathExtension == "txt" { print(url.lastPathComponent) }

try fm.moveItem(at: file, to: docs.appending(path: "old.txt"))
try fm.removeItem(at: folder)
let size = try file.resourceValues(forKeys: [.fileSizeKey]).fileSize

Code Explained

URL.documentsDirectory — sandbox folder
appending(path:) — build a path
createDirectory(…withIntermediateDirectories:)
contentsOfDirectory(at:…) — list a folder
moveItem / removeItem — throwing operations

The Swifty Way

  • ✗ NSHomeDirectory() + "/Documents/x.txt"
    ✓ URL.documentsDirectory.appending(path: "x.txt")

Coming From…

  • Python pathlib.Path ≈ URL; os ≈ FileManager
  • Kotlin File(context.filesDir, …) ≈ documentsDirectory
  • TypeScript Node path + fs ≈ URL + FileManager

App Folders

URLUse
documentsDirectoryUser data (backed up)
applicationSupportDirectoryApp data, hidden
cachesDirectoryRe-creatable data
temporaryDirectoryShort-lived files
Bundle.main.url(…)Read-only bundled files

⚠ Common Mistakes

  • Hard-coding absolute paths: the sandbox path changes between installs
  • Using url.absoluteString as a file path: it includes file://
  • Storing big re-downloadable files in Documents: bloats backups

✓ Tips & Best Practices

  • Use url.path(percentEncoded: false) for display
  • Check fileExists only for UI; just try the operation and catch errors
  • Create app-support folders at launch with intermediate directories

Quick Summary
