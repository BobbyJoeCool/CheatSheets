Protocols

A protocol lists the methods and properties a type must provide. Structs, enums, classes and actors can all conform, and one type can adopt many protocols. Protocols are the main tool for abstraction in Swift: code can depend on "anything that can fetch()" instead of a concrete class.

Notes

  • Property requirements say { get } or { get set }
  • Mutating requirements need mutating for structs to conform
  • Conformance can be added in an extension
  • Use some P / any P when a protocol is a parameter type (Sheet 074)

Defining & Adopting

protocol Shape {
    var name: String { get }
    func area() -> Double
}

struct Circle: Shape {
    let r: Double
    var name: String { "circle" }
    func area() -> Double { .pi * r * r }
}

struct Square: Shape {
    let side: Double
    let name = "square"                         // stored also satisfies { get }
    func area() -> Double { side * side }
}

let shapes: [any Shape] = [Circle(r: 1), Square(side: 2)]
for s in shapes { print(s.name, s.area()) }     // circle 3.14…, square 4.0

func largest(_ list: [any Shape]) -> (any Shape)? {
    list.max { $0.area() < $1.area() }
}

protocol Resettable { mutating func reset() }

Requirement Forms

var x: T { get }let, var or computed

func f()Method

init()required init (classes)
static func make()Static or class method

Code Explained

protocol — list of requirements
{ get } — readable property (stored or computed)
: Shape — conformance
[any Shape] — mixed conforming types
mutating func — lets structs conform

The Swifty Way

  • ✗ a base class just to share an interface
    ✓ a protocol — works for structs and enums too

Coming From…

  • Java interface ≈ protocol
  • Kotlin interface ≈ protocol
  • TypeScript interface, but conformance is declared, not structural

In SwiftUI

  • struct MyView: View — conform by providing var body: some View
  • Identifiable lets List and ForEach track rows
  • See SwiftUI 03 · Views & body

⚠ Common Mistakes

  • Declaring a { get set } requirement and conforming with a let
  • Forgetting mutating in the protocol, then structs can't change state
  • Using a protocol as a type without any (warning in Swift 6 mode)

✓ Tips & Best Practices

  • Name capability protocols with -able/-ing (Sendable) and roles with nouns (Collection)
  • Keep protocols small; compose with P & Q
  • Use protocols to inject fakes in tests
