Sheet 073

Generics

<T> · constraints · where clauses · generic types · associatedtype

Generic Code

Generics let one function or type work with any type that meets stated requirements. Type parameters go in angle brackets (<T>), and constraints (T: Comparable) or where clauses restrict them. Protocols declare their own placeholder types with associatedtype. The compiler specializes generic code, so it stays fast.

Notes

  • Array, Dictionary, Optional and Result are all generic
  • Constraints: <T: Hashable> or where T: Hashable
  • associatedtype = a generic placeholder inside a protocol
  • Type inference usually fills in T at the call site

Generic Functions & Types

func largest<T: Comparable>(_ items: [T]) -> T? {
    items.max()
}
largest([3, 9, 2])                          // Optional(9)
largest(["b", "a"])                         // Optional("b")

struct Stack<Element> {
    private var items: [Element] = []
    mutating func push(_ x: Element) { items.append(x) }
    mutating func pop() -> Element? { items.popLast() }
}
var s = Stack<Int>(); s.push(1); s.pop()    // Optional(1)

func countMatches<C: Collection>(_ c: C, _ x: C.Element) -> Int
    where C.Element: Equatable {
    c.filter { $0 == x }.count
}
countMatches("banana", "a")                 // 3

protocol Container {
    associatedtype Item
    mutating func push(_ x: Item)
}
extension Stack: Container {}               // Item inferred as Element

Constraint Syntax

SyntaxMeaning
<T>Any type
<T: P>Conforms to P
<T: P & Q>Conforms to both
where T == IntExact type
where C.Element: PAssociated type constraint

Code Explained

<T: Comparable> — constrained type parameter
Stack<Element> — generic type
where C.Element: Equatable — extra constraints
C.Element — associated type of Collection
associatedtype Item — protocol placeholder

The Swifty Way

  • ✗ func f(_ x: Any) -> Any
    ✓ func f<T>(_ x: T) -> T — keeps the type information

Coming From…

  • Java No type erasure: Swift specializes generics
  • Kotlin <T : Comparable<T>> ≈ <T: Comparable>
  • TypeScript <T extends X> ≈ <T: X>

⚠ Common Mistakes

  • Using generics where a concrete type or some P would be simpler
  • Forgetting a constraint and getting "binary operator cannot be applied"
  • Over-constraining with long where clauses nobody can read

✓ Tips & Best Practices

  • Start concrete, generalize when you have a second use
  • some Collection<Int> often replaces a full generic signature
  • Name type parameters meaningfully (Element, Key) unless it's a one-liner

Quick Summary

  • <T> — type parameter
  • T: P / where — constraints
  • associatedtype — protocol generics
