Comments & Documentation

// · /* */ nesting · /// · - Parameters: · // MARK: · DocC

Comments in Swift

Swift has // line comments and /* */ block comments, and block comments nest, so you can comment out code that already has comments in it. Doc comments use /// (or /** */) with Markdown; Xcode shows them in Quick Help, and DocC builds them into a documentation site.

Notes

  • Doc comments go directly above the declaration
  • Option-click a symbol in Xcode to see its doc comment
  • // MARK: - adds a divider in Xcode's jump bar
  • #warning("…") and #error("…") show up as build diagnostics

Comment Syntax

// Single-line comment
/* Block comment
   /* nested comments are fine */ */

/// Returns the area of a rectangle.
///
/// - Parameters:
///   - width: Width in points.
///   - height: Height in points.
/// - Returns: `width * height`.
/// - Throws: `GeometryError.negative` if a side is < 0.
func area(width: Double, height: Double) throws -> Double {
    width * height
}

// MARK: - Networking
// TODO: retry on timeout
// FIXME: handle 401
#warning("Remove before release")

Code Explained

/// — doc comment, Markdown supported
- Parameters: / - Returns: / - Throws: — Quick Help sections
// MARK: - — named section with a divider line
TODO: / FIXME: — listed in the jump bar
#warning — compiler warning you can't miss

The Swifty Way

  • ✗ // This function adds two numbers
    ✓ /// Adds a and b, wrapping on overflow. — doc comments show in autocomplete; say what isn't obvious

Coming From…

  • Kotlin KDoc /** */ ≈ /// with - Parameters
  • Java Javadoc @param ≈ - Parameter name:
  • Python docstrings ≈ /// above the func

⚠ Common Mistakes

  • Using // above a public API: only /// appears in Quick Help
  • Commenting what the code already says instead of why it does it
  • Leaving a #warning in a target that builds with warnings-as-errors

✓ Tips & Best Practices

  • Type /// above a function in Xcode to generate a doc template (or press ⌥⌘/)
  • Use // MARK: - Protocol Name above each protocol conformance extension
  • Write - Complexity: O(n) for performance-sensitive APIs

Quick Summary

  • // and /* */ — comments (block comments nest)
  • /// — doc comments shown in Quick Help and DocC
  • // MARK: — organize the jump bar
