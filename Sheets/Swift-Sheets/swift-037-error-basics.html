Error Handling Basics

Error · throw · throws · do / catch · try · try? · try!

How Swift Errors Work

Swift errors are values of any type that conforms to the Error protocol. A function marked throws can throw one; every call to it must be marked with try, and the error is handled in a do/catch block or passed further up by another throws function. Unlike exceptions in many languages, errors are cheap and always visible at the call site.

Notes

  • try is required on every throwing call: no hidden control flow
  • try? turns the result into an optional (nil on error)
  • try! crashes on error: only when failure is truly impossible
  • Inside catch with no pattern, the error is named error

throw · try · do/catch

enum LoginError: Error { case emptyPassword, locked(minutes: Int) }

func login(_ user: String, _ pass: String) throws -> String {
    guard !pass.isEmpty else { throw LoginError.emptyPassword }
    if user == "bob" { throw LoginError.locked(minutes: 5) }
    return "token-123"
}

do {
    let token = try login("ada", "secret")
    print(token)                                    // token-123
} catch LoginError.locked(let mins) {
    print("Locked for \(mins) min")
} catch {
    print("Failed: \(error)")                       // any other error
}

let t = try? login("ada", "")                       // nil
let sure = try! login("ada", "x")                   // crash if it throws

Code Explained

: Error — any type can be an error

The Swifty Way

  • ✗ try! on network or file calls
    ✓ do/catch or try? with a fallback — those fail in real life

⚠ Common Mistakes

  • Using try? everywhere: you lose the reason for the failure
  • Catching too broadly and printing: handle or rethrow instead
  • Forgetting that a catch list must be exhaustive unless the enclosing function also throws

✓ Tips & Best Practices

  • Model each error case with an enum and associated values
  • Let errors propagate to a layer that can show a message
  • In LLDB, Swift Error Breakpoint stops where an error is thrown

Quick Summary

  • throws + throw — raise an error
  • try + do/catch — handle it
  • try? / try! — optional / crash
