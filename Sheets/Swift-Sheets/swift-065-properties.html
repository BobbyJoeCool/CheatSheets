Properties

stored · computed · lazy · willSet / didSet · static · get / set

Stored & Computed Properties

Stored properties hold values; computed properties calculate one each time with a getter (and optional setter). Property observers willSet and didSet run code around changes to stored properties. lazy var delays creating a value until it's first used, and static properties belong to the type itself.

Notes

  • Computed properties must be var
  • A get-only computed property can drop the get { } wrapper
  • didSet gives you oldValue; willSet gives newValue
  • Observers don't fire during init

Property Kinds

struct Temperature {
    var celsius: Double {                     // stored + observer
        didSet { print("changed from \(oldValue)") }
    }
    var fahrenheit: Double {                  // computed get/set
        get { celsius * 9 / 5 + 32 }
        set { celsius = (newValue - 32) * 5 / 9 }
    }
    var isFreezing: Bool { celsius <= 0 }     // get-only shorthand

    static let boiling = 100.0                // type property
}

var t = Temperature(celsius: 20)
t.fahrenheit                                  // 68.0
t.fahrenheit = 212                            // changed from 20.0
t.celsius                                     // 100.0
Temperature.boiling                           // 100.0

final class Report {
    lazy var formatter = DateFormatter()      // created on first use
    private(set) var pages = 0                // read-only outside
}

Property Kinds

Code Explained

didSet / oldValue — react after a change
get / set / newValue — computed property
get-only — no get { } needed
static let — one value for the type
lazy var — built on first access

The Swifty Way

  • ✗ func getFullName() -> String
    ✓ var fullName: String { … } — no-argument, cheap, no side effects → property

Coming From…

  • Kotlin val x get() = … ≈ computed property
  • TypeScript get x() / set x(v) accessors
  • Python @property ≈ computed property

In SwiftUI

  • @State, @Binding, @Environment are property wrappers on stored properties
  • var body: some View is a computed property
  • See SwiftUI 14 · @State

⚠ Common Mistakes

  • Doing slow work in a computed property: callers assume it's cheap
  • Expecting didSet to run when setting the value in init
  • Using lazy on a let: not allowed

✓ Tips & Best Practices

  • Use private(set) to allow reading but not writing from outside
  • Use didSet to validate or clamp: didSet { x = min(x, 100) }
  • lazy isn't thread-safe; avoid it in shared classes
