Sequence & Collection Protocols

Sequence · IteratorProtocol · Collection · lazy · indices · makeIterator

The Collection Protocols

Every collection type builds on a small protocol stack. A Sequence can be iterated once with an iterator; a Collection adds indices and multi-pass access; BidirectionalCollection and RandomAccessCollection add backward and O(1) indexing. Conform your own types to inherit map, filter, contains and the rest for free.

Notes

  • Sequence needs only makeIterator()
  • An IteratorProtocol needs only next() -> Element?
  • lazy delays work until elements are needed
  • Generic code should ask for the weakest protocol it needs

Conforming to Sequence

struct Countdown: Sequence {
    let start: Int
    func makeIterator() -> some IteratorProtocol<Int> {
        var current = start
        return AnyIterator {
            guard current > 0 else { return nil }
            defer { current -= 1 }
            return current
        }
    }
}
for n in Countdown(start: 3) { print(n) }  // 3 2 1
Countdown(start: 5).map { $0 * 10 }        // [50, 40, 30, 20, 10]
Countdown(start: 5).contains(2)            // true

let firstBig = (1...1_000_000).lazy
    .map { $0 * $0 }
    .first { $0 > 500 }                    // 529, only 23 squares computed

func total(_ xs: some Sequence<Int>) -> Int { xs.reduce(0, +) }
total([1, 2]); total(1...3); total(Set([4]))

Code Explained

makeIterator() — the one Sequence requirement
AnyIterator { } — iterator from a closure
free methods — map, contains, etc.
.lazy — compute on demand
some Sequence<Int> — accept any sequence

The Swifty Way

  • ✗ func f(_ a: [Int]) that only iterates
    ✓ func f(_ a: some Sequence<Int>) — accepts ranges, sets, slices

Coming From…

  • Kotlin Sequence ≈ lazy Swift sequence; Iterable ≈ Sequence
  • Python __iter__ / __next__ ≈ makeIterator / next
  • TypeScript [Symbol.iterator] ≈ Sequence

Protocol Stack

ProtocolAdds
Sequencefor-in, map, filter
Collectionindices, count, subscript
BidirectionalCollectionlast, reversed()
RandomAccessCollectionO(1) index math
MutableCollectionAssign through subscript

⚠ Common Mistakes

  • Iterating a single-pass Sequence twice: the second pass may be empty
  • Using .lazy and then calling count: it runs the whole chain
  • Conforming to Collection with an O(n) subscript: breaks performance promises

✓ Tips & Best Practices

  • sequence(first:next:) builds a sequence from a seed
  • stride and zip are lazy sequences too
  • Use AnySequence only when you must erase types

Quick Summary

  • Sequence → Collection → RandomAccess
  • makeIterator / next — custom sequences
  • .lazy — deferred work
