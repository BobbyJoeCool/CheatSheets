Key Paths

A key path like \User.name is a reference to a property itself, not its value. Read or write through it with value[keyPath: kp]. Key paths can be passed around, stored and composed, and they work anywhere a function from root to value is expected, so users.map(\.name) is valid.

Notes

  • \.name uses inference when the root type is known
  • KeyPath is read-only; WritableKeyPath allows writes (vars)
  • ReferenceWritableKeyPath writes through class references
  • Key paths are Hashable: usable as dictionary keys

Using Key Paths

struct User { var name: String; var age: Int; var address: Address }
struct Address { var city: String }
var u = User(name: "Ada", age: 36, address: Address(city: "London"))

let kp = \User.name                        // WritableKeyPath<User, String>
u[keyPath: kp]                             // "Ada"
u[keyPath: \.address.city] = "Paris"       // nested, writable

let users = [u, User(name: "Bo", age: 20, address: .init(city: "Rome"))]
users.map(\.name)                          // ["Ada", "Bo"]
users.filter(\.address.city.isEmpty)       // [] (Bool key path)
users.sorted(using: KeyPathComparator(\.age))   // Bo, Ada
users.max { $0.age < $1.age }?.name        // "Ada"

func sortBy<T, V: Comparable>(_ xs: [T], _ kp: KeyPath<T, V>) -> [T] {
    xs.sorted { $0[keyPath: kp] < $1[keyPath: kp] }
}
sortBy(users, \.name)

let city = (\User.address).appending(path: \.city)   // composed

Code Explained

\User.name — key path literal
[keyPath:] — read / write through it
map(\.name) — key path as a function
KeyPathComparator — sort descriptors
KeyPath<T, V> — generic over properties

The Swifty Way

  • ✗ users.map { $0.name }
    ✓ users.map(\.name)

Coming From…

  • Kotlin User::name property references ≈ key paths
  • TypeScript keyof T + obj[key] (weaker typing)
  • Python operator.attrgetter('name') ≈ \.name

In SwiftUI

  • ForEach(items, id: \.id) takes a key path
  • $model.name bindings use key paths under the hood
  • See SwiftUI 17 · @Bindable & Sharing Models

Key Path Types

TypeCan
KeyPath<R, V>Read
WritableKeyPath<R, V>Read / write (value types)
ReferenceWritableKeyPathWrite through a class ref
PartialKeyPath<R>Value type erased
AnyKeyPathFully erased

⚠ Common Mistakes

  • Trying to write through a KeyPath to a let property
  • Expecting \.count to infer without context: specify \String.count
  • Using key paths to private properties from outside the type

✓ Tips & Best Practices

  • Bool key paths work as predicates: filter(\.isDone)
  • Store sort options as [KeyPathComparator<T>] for UI tables
  • Use key paths in generic helpers instead of closures for simple access

Quick Summary

  • \Type.prop — property reference
  • x[keyPath:] — read/write
  • map(\.prop) — key path as function
