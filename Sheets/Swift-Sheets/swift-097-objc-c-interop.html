Objective-C & C Interop

@objc · NSObject · bridging header · C functions · UnsafePointer · C++ interop

Calling Other Languages

Swift interoperates directly with Objective-C (most Apple frameworks), C (system libraries), and, since 5.9, C++. Mark Swift members @objc to expose them to Objective-C, use a bridging header to see Objective-C in an app target, and call C functions directly through module maps. Raw memory uses Unsafe…Pointer types.

Notes

  • Swift classes need NSObject or @objc to be seen by Obj-C
  • Selectors: #selector(method) needs an @objc method
  • Unsafe APIs skip safety checks: keep them small and local
  • C++ interop: Build setting "C++ and Objective-C Interoperability"

Interop Basics

import UIKit

final class Handler: NSObject {
    @objc func tapped(_ sender: UIButton) { print("tap") }
}
button.addTarget(handler, action: #selector(Handler.tapped(_:)),
                 for: .touchUpInside)

// MyApp-Bridging-Header.h   →  #import "LegacyParser.h"
let parser = LegacyParser()              // Obj-C class, used directly

import Darwin                           // C standard library
let len = strlen("hello")               // 5
var buf = [UInt8](repeating: 0, count: 8)
buf.withUnsafeMutableBufferPointer { p in
    p[0] = 0xFF                         // raw buffer access
}

var n: Int32 = 0
withUnsafeMutablePointer(to: &n) { $0.pointee = 7 }   // n == 7

// C++ (5.9+): -cxx-interoperability-mode=default
// import CxxStdlib; let s = std.string("hi")

Code Explained

NSObject + @objc — visible to Obj-C
#selector — reference an @objc method
bridging header — Obj-C into an app target
C functions — called like Swift functions
withUnsafe…Pointer — scoped raw memory

The Swifty Way

  • ✗ returning UnsafeMutablePointer from a function
    ✓ keep pointers inside withUnsafe… closures — pointers must not escape

Coming From…

  • Kotlin JNI / Kotlin/Native cinterop ≈ C interop
  • Java JNI ≈ C interop (much more ceremony)
  • Python ctypes ≈ C interop

⚠ Common Mistakes

  • Forgetting @objc on a selector target method: compile error
  • Letting an UnsafePointer escape its withUnsafe… closure
  • Assuming Obj-C APIs never return nil: check implicitly unwrapped results

✓ Tips & Best Practices

  • Add nullability annotations to Obj-C headers for clean Swift types
  • Wrap C APIs in a small Swift type that handles errors and memory
  • Prefer Span / buffer pointers over raw pointers when available

Quick Summary

  • @objc — Swift → Obj-C
