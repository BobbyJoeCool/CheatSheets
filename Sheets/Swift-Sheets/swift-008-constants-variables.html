Sheet 008

Constants & Variables

let · var · type annotation · type inference · naming rules · shadowing

let vs var

let declares a constant that is set once; var declares a variable that can change. Swift infers the type from the initial value, or you can write it with a type annotation. Every value must be initialized before it is read: the compiler checks this for you.

Notes

  • Default to let; the compiler warns when a var is never mutated
  • A let can be declared first and assigned once later
  • Names are camelCase; types are UpperCamelCase
  • Unicode names are legal but rarely a good idea

Declaring Values

let maxUsers = 100                  // constant, Int
var score = 0                       // variable, Int
score += 10                         // 10

let pi: Double = 3.14159            // explicit type
var name: String                    // declared, not set
name = "Ada"                        // set before first use

let label: String                   // deferred constant
if score > 5 { label = "high" } else { label = "low" }

var x = 1, y = 2, z = 3             // several on one line
let (w, h) = (1920, 1080)           // tuple destructuring
let `class` = "ok"                  // backticks: keyword name

let total = 5                       // shadowing in inner scope
do { let total = "five"; print(total) }   // five

let on a Struct vs Class

DeclarationCan mutate properties?
let s = MyStruct()No (whole value is constant)
var s = MyStruct()Yes
let c = MyClass()Yes (only the reference is constant)

Code Explained

let — assign once; var — reassignable
: Double — type annotation
let label: String — assigned once on every path
let (w, h) — destructure a tuple
` class ` — backticks allow a keyword as a name

The Swifty Way

  • ✗ var for values that never change
    ✓ let everywhere, var only when needed — the compiler warns about unmutated vars

Coming From…

  • Kotlin val / var ≈ let / var
  • TypeScript const / let ≈ let / var
  • Java final int x ≈ let x: Int

⚠ Common Mistakes

  • Expecting let on a class instance to freeze it: only the reference is constant
  • Reading a declared-but-unassigned var: compile error "used before being initialized"
  • Shadowing an outer name by accident inside an if or loop

✓ Tips & Best Practices

  • Let the compiler infer obvious types; annotate when it helps a reader
  • Use deferred let with if/switch instead of a var set in branches
  • Turn on "Treat Warnings as Errors" to keep var→let warnings from piling up

Quick Summary

  • let — constant, preferred
  • var — variable
  • name: Type = value — annotation + initial value
