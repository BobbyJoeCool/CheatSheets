Typed Errors

Since Swift 6, a function can declare exactly which error type it throws: throws(ParseError). Callers then get a concrete error type in catch, without casting. Result<Success, Failure> stores a success or an error as a value, which is handy for callbacks and caching. rethrows marks a function that throws only if its closure argument does.

Notes

  • Plain throws is the same as throws(any Error)
  • Use typed throws for closed, internal error sets
  • Result.get() converts back into a throwing call
  • throws(Never) means the function never throws

Typed Throws & Result

enum ParseError: Error { case empty, notNumber(String) }

func parse(_ s: String) throws(ParseError) -> Int {
    guard !s.isEmpty else { throw .empty }      // type inferred
    guard let n = Int(s) else { throw .notNumber(s) }
    return n
}

do {
    let n = try parse("x")
} catch {                                       // error: ParseError
    switch error {
    case .empty: print("empty")
    case .notNumber(let s): print("bad: \(s)")  // bad: x
    }
}

let r: Result<Int, ParseError> = Result { try parse("42") }
switch r {
case .success(let n): print(n)                  // 42
case .failure(let e): print(e)
}
let value = try r.get()                         // 42
r.map { $0 * 2 }                                // .success(84)

Code Explained

throws(ParseError) — only this error type
throw .empty — case inferred from the declared type
catch — error is ParseError, not any Error
Result { try … } — capture a throwing call
get() / map / mapError — use a Result

The Swifty Way

  • ✗ completion: (Data?, Error?) -> Void
    ✓ async throws -> Data (or Result<Data, Error>)

Coming From…

⚠ Common Mistakes

  • Using typed throws on public library APIs: adding an error case later breaks clients
  • Building new APIs on completion-handler Result when async throws fits
  • Forgetting rethrows on a helper that takes a throwing closure

✓ Tips & Best Practices

  • Prefer untyped throws at module boundaries, typed throws(E) inside
  • Generic code can use throws(E) to pass an error type through
  • Result is great for storing outcomes (caches, test doubles)

Quick Summary

  • throws(E) — typed throws (6.0)
  • Result<T, E> — error as a value
  • rethrows — throws only if the closure does
