Program Structure

main.swift · @main · top-level code · import · semicolons · statements

How a Program Is Laid Out

A Swift file is a list of declarations and statements. In a script or a file named main.swift, top-level statements run in order: that file is the entry point. Everywhere else (apps and libraries), execution starts at the type marked @main. Statements end at the line break, and blocks always use braces.

Notes

  • Only main.swift (or a script) may contain top-level executable code
  • @main marks the entry type in apps and CLIs with multiple files
  • Semicolons are optional; only needed for two statements on one line
  • No header files: every file in a module sees every other file

Entry Points

// ── main.swift (top-level code runs in order) ──
import Foundation                   // bring in a module

let args = CommandLine.arguments
print("Got \(args.count - 1) args")

// ── Tool.swift (multi-file CLI using @main) ──
@main
struct Tool {
    static func main() async throws {   // may be async/throws
        print("Started at \(Date.now)")
    }
}

// ── SwiftUI app (also @main) ──
@main
struct MyApp: App {
    var body: some Scene { WindowGroup { Text("Hi") } }
}

File Rules

RuleDetail
ModuleAll files in a target share one namespace
OrderDeclarations can appear in any order
main.swiftTop-level code allowed only here
@mainExactly one per executable target

Code Explained

import — load a module (Foundation, SwiftUI, a package)
main.swift — the one file allowed to run top-level code
@main — type whose static func main() starts the program
async throws — entry point can await and throw

The Swifty Way

  • ✗ main.swift + @main in the same target
    ✓ pick one entry point per target — having both is a compile error

Coming From…

  • Kotlin fun main() ≈ @main struct with static main
  • Java public static void main ≈ static func main()
  • Python main.swift ≈ a module run as __main__

⚠ Common Mistakes

  • Putting statements at top level in a non-main file: "expressions are not allowed at the top level"
  • Naming a file main.swift in an app that also has @main
  • Leaving out braces for one-line if bodies: Swift always requires them

✓ Tips & Best Practices

  • Use @main with static func main() async throws for CLIs that need concurrency
  • Group related types in one file, but let each major type have its own
  • Add the ArgumentParser package for real CLI flags (@main struct Cmd: ParsableCommand)

Quick Summary

  • main.swift — top-level code entry
  • @main — entry type for apps and multi-file CLIs
  • import — use another module
