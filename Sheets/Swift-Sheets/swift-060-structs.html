Structs

struct · stored properties · memberwise init · mutating · value semantics

Value Types with struct

A struct bundles stored properties and methods into a value type: every assignment or pass makes an independent copy. Swift writes a memberwise initializer for you. Methods that change properties must be marked mutating, and they can only be called on a var. Most Swift types, including String, Array and Int, are structs.

Notes

  • Structs can't inherit, but they can adopt protocols
  • The memberwise init uses defaults for properties that have them
  • Writing your own init in the struct body removes the memberwise one
  • Copies are cheap: large stdlib types use copy-on-write

Defining a Struct

struct Counter {
    var name: String
    var count = 0                           // default value

    mutating func increment(by n: Int = 1) { count += n }
    func describe() -> String { "\(name): \(count)" }
}

var a = Counter(name: "clicks")             // memberwise init
a.increment()
a.increment(by: 4)
a.describe()                                // "clicks: 5"

var b = a                                   // copy
b.increment()
a.count                                     // 5 (unchanged)
b.count                                     // 6

let c = Counter(name: "fixed", count: 9)
// c.increment()                            // error: c is a let

extension Counter {                         // keeps memberwise init
    init(_ name: String) { self.init(name: name) }
}

The Swifty Way

  • ✗ class for plain data models
    ✓ struct — value semantics avoid shared-state bugs

Coming From…

  • Kotlin data class ≈ struct, but Kotlin's is a reference
  • TypeScript Objects are shared refs; structs copy
  • Java record ≈ immutable struct

In SwiftUI

  • Every SwiftUI View is a struct: cheap to create, recreated on each update
  • Model data as structs passed into views
  • See SwiftUI 03 · Views & body

⚠ Common Mistakes

  • Calling a mutating method on a let instance
  • Adding an init in the struct body and losing the memberwise init
  • Expecting a change through one variable to show up in a copy

✓ Tips & Best Practices

  • Start every type as a struct; switch to class only when you need identity
  • Conform to Equatable, Hashable, Codable with one line each
  • Use private(set) var to expose read-only state

Quick Summary

  • struct — value type, copied
  • memberwise init for free
  • mutating — changes self
