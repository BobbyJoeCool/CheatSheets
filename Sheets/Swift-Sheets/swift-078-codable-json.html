Codable · JSONEncoder · JSONDecoder · CodingKeys · keyDecodingStrategy · dateDecodingStrategy

JSON with Codable

Conform a type to Codable (= Encodable & Decodable) and JSONEncoder / JSONDecoder convert it to and from JSON automatically. Property names map to JSON keys; when they differ, declare a CodingKeys enum or use a key strategy such as .convertFromSnakeCase. Optionals become missing or null keys.

Notes

  • All stored properties must be Codable (String, Int, arrays, nested Codables…)
  • Extra JSON keys are ignored by default
  • Missing non-optional keys throw keyNotFound
  • Dates need a dateDecodingStrategy

Encode & Decode

import Foundation
struct Post: Codable {
    let id: Int
    let title: String
    let createdAt: Date
    var tags: [String]?
    enum CodingKeys: String, CodingKey {
        case id, title, tags
        case createdAt = "created"                // JSON key differs
    }
}

let json = #"{"id":1,"title":"Hi","created":"2026-10-26T12:00:00Z"}"#
let dec = JSONDecoder()
dec.dateDecodingStrategy = .iso8601
let post = try dec.decode(Post.self, from: Data(json.utf8))
post.tags                                         // nil

let enc = JSONEncoder()
enc.outputFormatting = [.prettyPrinted, .sortedKeys]
enc.dateEncodingStrategy = .iso8601
let out = String(decoding: try enc.encode(post), as: UTF8.self)
let posts = try dec.decode([Post].self, from: arrayData)   // arrays too

Code Explained

Codable — encode + decode
CodingKeys — rename keys
decode(Post.self, from:) — JSON → struct
.iso8601 — date strategy
.prettyPrinted, .sortedKeys — readable output

⚠ Common Mistakes

  • Non-optional property for a key the server sometimes omits: whole decode fails
  • Forgetting the date strategy: default expects seconds since 2001
  • Mixing CodingKeys and .convertFromSnakeCase incorrectly (keys are converted first)

✓ Tips & Best Practices

  • Print DecodingError in full while debugging; it names the failing key path
  • Make fields optional only when the API can omit them
  • Use .convertFromSnakeCase instead of CodingKeys for simple snake_case APIs
