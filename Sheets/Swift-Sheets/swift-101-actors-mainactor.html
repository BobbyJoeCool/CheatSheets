Actors & @MainActor

actor · isolation · nonisolated · reentrancy · @MainActor · global actors

Actors

An actor is a reference type that protects its mutable state: only one task at a time can run code inside it, so data races are impossible. Code outside must await to call into the actor. @MainActor is a global actor for the main thread; mark UI types and functions with it so they always run there.

Notes

  • Actor methods are synchronous inside, await from outside
  • nonisolated members skip isolation (only for immutable data)
  • Actors are re-entrant: state can change across an await
  • MainActor.run { } hops to the main actor briefly

Actors & @MainActor

actor BankAccount {
    private(set) var balance = 0
    let id = UUID()

    func deposit(_ amount: Int) { balance += amount }   // isolated

    func withdraw(_ amount: Int) throws {
        guard balance >= amount else { throw BankError.insufficient }
        balance -= amount
    }
    nonisolated var label: String { "Account \(id)" }   // no await needed
}

let acct = BankAccount()
await acct.deposit(100)                  // await from outside
try await acct.withdraw(30)
print(await acct.balance)                // 70
print(acct.label)                        // nonisolated

@MainActor
@Observable final class FeedModel {      // all members on main
    var posts: [Post] = []
    func load() async {
        posts = (try? await api.fetchPosts()) ?? []   // back on main
    }
}

Code Explained

actor — isolated mutable state
await acct.deposit — cross-actor call
nonisolated — opt out for immutable data
@MainActor — run on the main thread
after await, back on the model's actor

The Swifty Way

  • ✗ DispatchQueue.main.async { self.posts = … }
    ✓ @MainActor on the type — the compiler enforces it

Coming From…

  • Kotlin Mutex / single-thread dispatcher ≈ actor
  • Java synchronized class ≈ actor, without await
  • TypeScript Single-threaded JS ≈ everything on MainActor

Swift Versions

  • 5.5 — actors and @MainActor
  • 6.2 — opt-in default MainActor isolation for app targets

In SwiftUI

  • View is @MainActor; mark view models @MainActor too
  • Heavy work belongs in another actor or a @concurrent function
  • See SwiftUI 16 · @Observable Models

⚠ Common Mistakes

  • Assuming state is unchanged after an await inside an actor (re-entrancy)
  • Calling DispatchQueue.main.sync from the main actor: deadlock
  • Making everything an actor: adds awaits; use structs for data

✓ Tips & Best Practices

  • Re-check conditions after each await inside actor methods
  • Keep actor methods small and synchronous where possible
  • Use Mutex (Synchronization) for tiny, non-async critical sections

Quick Summary

  • actor — one task inside at a time
  • await to call from outside
  • @MainActor — UI code
