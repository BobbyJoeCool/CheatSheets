Sheet 106

Ownership & Noncopyable Types

~Copyable · borrowing · consuming · consume · discard self

Ownership Control

Swift 5.9 added tools for performance-critical code. A noncopyable type (~Copyable) can't be copied, only moved, so it models unique resources like file handles. Parameter modifiers borrowing and consuming state whether a function reads a value or takes it over, and consume ends a variable's lifetime explicitly.

Notes

  • Most code never needs these; they're for libraries and hot paths
  • Noncopyable structs can have a deinit
  • consuming methods can discard self to skip deinit
  • Swift 6 supports noncopyable types in generics (T: ~Copyable)

Noncopyable & Ownership

struct FileDescriptor: ~Copyable {
    let fd: Int32
    init(path: String) { fd = open(path, O_RDONLY) }
    borrowing func read() -> [UInt8] { /* uses fd */ [] }
    consuming func close() {
        Darwin.close(fd)
        discard self                          // skip deinit
    }
    deinit { Darwin.close(fd) }               // auto-close if not closed
}

let file = FileDescriptor(path: "/etc/hosts")
let bytes = file.read()                       // borrow
// let copy = file                            // error: can't copy
file.close()                                  // consumed
// file.read()                                // error: used after consume

func log(_ msg: borrowing String) { print(msg) }   // read only
func store(_ s: consuming [Int]) { cache = s }    // takes ownership

var big = [Int](repeating: 0, count: 1_000_000)
store(consume big)                            // move, no copy
// big is no longer usable here

Code Explained

~Copyable — move-only type
borrowing — read without taking ownership
consuming — take ownership
discard self — end without deinit
consume x — explicit move

The Swifty Way

  • ✗ a class + manual close() for a unique handle
    ✓ a ~Copyable struct with deinit — the compiler enforces single ownership

Coming From…

  • Rust Move semantics, borrowing ≈ the same ideas
  • C++ std::move ≈ consume; unique_ptr ≈ ~Copyable
  • Kotlin No equivalent

Swift Versions

  • 5.9 — ~Copyable, borrowing, consuming, consume
  • 6.0 — noncopyable generics

Modifiers

KeywordMeaning

⚠ Common Mistakes

  • Using these everywhere "for speed": measure first
  • Trying to put a ~Copyable value in an Array on older toolchains
  • Using a variable after consume: compile error

✓ Tips & Best Practices

  • Profile with Instruments before reaching for ownership modifiers
  • Model unique resources (locks, handles) as ~Copyable structs
  • Read SE-0390 and SE-0377 for the full rules

Quick Summary

  • ~Copyable — move-only types
  • borrowing / consuming parameters
  • consume — explicit move
