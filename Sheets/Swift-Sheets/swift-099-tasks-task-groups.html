Tasks & Task Groups

Task · withTaskGroup · withThrowingTaskGroup · Task.sleep · priority · detached

Structured Concurrency

A TaskGroup runs a dynamic number of child tasks in parallel and collects their results as they finish. Child tasks are structured: the group waits for all of them, cancels the rest if one throws, and can't outlive its scope. Unstructured Task { } and Task.detached { } create independent tasks you manage yourself.

Notes

  • Results arrive in completion order, not submission order
  • Throwing group: first error cancels the remaining children
  • Task inherits priority and actor context; detached doesn't
  • Keep a Task handle to await its value or cancel() it

Task Groups & Tasks

func downloadAll(_ urls: [URL]) async throws -> [URL: Data] {
    try await withThrowingTaskGroup(of: (URL, Data).self) { group in
        for url in urls {
            group.addTask {
                let (data, _) = try await URLSession.shared.data(from: url)
                return (url, data)
            }
        }
        var results: [URL: Data] = [:]
        for try await (url, data) in group { results[url] = data }
        return results
    }
}

let handle = Task(priority: .userInitiated) { try await downloadAll(urls) }
let files = try await handle.value                // wait for result
handle.cancel()                                   // or cancel it

Task.detached(priority: .background) { await cleanUpCache() }
try await Task.sleep(for: .milliseconds(250))
await Task.yield()                                // let others run

Code Explained

withThrowingTaskGroup(of:) — parallel children
group.addTask { } — add a child
for try await … in group — collect results
Task(priority:) / .value — unstructured task
Task.detached — no inherited context

The Swifty Way

  • ✗ Task.detached by default
    ✓ Task { } or a task group — detached loses actor and priority context

Coming From…

  • Kotlin coroutineScope { launch {} } ≈ TaskGroup
  • TypeScript Promise.all(urls.map(f)) ≈ group (no cancel)
  • Python asyncio.TaskGroup ≈ withThrowingTaskGroup

⚠ Common Mistakes

  • Mutating a shared array from inside addTask: data race; return values instead
  • Expecting results in input order
  • Launching thousands of children at once: limit concurrency for network calls

✓ Tips & Best Practices

  • Limit parallelism by adding the next task as each one finishes
  • Return (index, value) pairs when you need the original order
  • Use withDiscardingTaskGroup for servers handling many connections

Quick Summary

  • TaskGroup — dynamic parallel children
  • structured: waits, cancels on error
  • Task { } — unstructured, keep the handle
