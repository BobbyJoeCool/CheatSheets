Sheet 006

Print & Debug Output

print · separator: · terminator: · debugPrint · dump · CustomStringConvertible

Printing Output

print writes values to standard output, separated by spaces and ending with a newline by default. debugPrint shows the debug form (strings get quotes), and dump prints a whole object tree. A type controls how it prints by conforming to CustomStringConvertible.

Notes

  • print takes any number of values (Any...)
  • separator: and terminator: change the joiners
  • print(_:to:) writes into any TextOutputStream, including a String
  • In apps, prefer Logger (OSLog) over print for real logging

print · debugPrint · dump

print("Hello")                          // Hello
print(1, 2, 3)                          // 1 2 3
print(1, 2, 3, separator: ", ")         // 1, 2, 3
print("no newline", terminator: "")     // no newline
print([1, 2], ["a": 1])                 // [1, 2] ["a": 1]

debugPrint("hi", 1.5)                   // "hi" 1.5
let name: String? = "Ada"
print(name as Any)                      // Optional("Ada")

struct Point: CustomStringConvertible {
    var x = 0, y = 0
    var description: String { "(\(x), \(y))" }
}
print(Point(x: 3, y: 4))                // (3, 4)
dump(Point())                           // ▿ (0, 0) - x: 0 - y: 0

var log = ""
print("saved", to: &log)                // log == "saved\n"

Code Explained

separator: — between values (default " ")
terminator: — after the last value (default "\n")
debugPrint — quotes strings, shows debug form
description — what print shows for your type
dump — recursive tree of all properties

The Swifty Way

  • ✗ print("\(a) \(b)")
    ✓ print(a, b)
  • ✗ print(optional!)
    ✓ print(optional ?? "none") — no crash just to print

Coming From…

  • Kotlin println(x) ≈ print(x)
  • TypeScript console.log(a, b) ≈ print(a, b)
  • Python print(a, sep=", ", end="") ≈ separator:/terminator:

⚠ Common Mistakes

  • Printing an optional directly: you get Optional("x") and a compiler warning; unwrap or use ??
  • Leaving print calls in shipping app code: they cost time and leak data to the device console
  • Using print for errors in CLIs: write to stderr so pipes stay clean

✓ Tips & Best Practices

  • Send errors to stderr with FileHandle.standardError.write(_:)
  • In LLDB, po value uses debugDescription
  • Conform types to CustomStringConvertible to make logs readable

Quick Summary

  • print(a, b, separator:, terminator:) — stdout
  • debugPrint / dump — debugging forms
  • CustomStringConvertible — custom text for your types
