Sheet 068

Inheritance

subclassing · override · super · final · class vs static methods

Subclassing

A class can inherit from one superclass, gaining its properties and methods. Override behavior with override, call the parent's version with super, and stop further overriding with final. Swift checks overrides at compile time, so a typo in a method name can't silently create a new method.

Notes

  • Only classes inherit; structs and enums use protocols
  • override is required, not optional
  • static members can't be overridden; class members can
  • Prefer composition and protocols over deep hierarchies

Inheritance

class Animal {
    let name: String
    init(name: String) { self.name = name }

    func speak() -> String { "..." }
    class var kingdom: String { "Animalia" }    // overridable type prop
    final func id() -> String { "#\(name)" }    // can't override
}

class Dog: Animal {
    override func speak() -> String { "Woof" }
}

final class Puppy: Dog {
    override func speak() -> String { super.speak() + "!" }
}

let pets: [Animal] = [Dog(name: "Rex"), Puppy(name: "Bit")]
for p in pets { print(p.name, p.speak()) }      // Rex Woof, Bit Woof!

if let d = pets[0] as? Dog { print("dog:", d.name) }
pets[1] is Dog                                  // true

Keywords

KeywordMeaning
overrideReplace parent member
superParent implementation
finalNo overriding / subclassing
class func / varOverridable type member
static func / varNon-overridable type member

Code Explained

class Dog: Animal — single inheritance
override — replace a method
super.speak() — call the parent version
final — block further overrides
as? / is — downcast and check

The Swifty Way

  • ✗ a 4-level class hierarchy
    ✓ a protocol + small structs, or composition

Coming From…

  • Java extends ≈ :; @Override is required here
  • Kotlin Classes are final by default there; open here unless final
  • Python Single inheritance only; no MRO

⚠ Common Mistakes

  • Forgetting override: compile error (good!)
  • Overriding without calling super where the parent does required work (viewDidLoad)
  • Downcasting with as! when the type isn't guaranteed

✓ Tips & Best Practices

  • Mark classes final unless they're designed to be subclassed
  • Use protocol default implementations to share behavior across structs
  • Call super first in setup methods and last in teardown

Quick Summary

  • class B: A — inherit
  • override + super
  • final — stop inheritance
