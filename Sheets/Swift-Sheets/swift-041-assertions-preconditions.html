Assertions & Preconditions

assert · precondition · fatalError · assertionFailure · debug vs release

Checking Assumptions

These functions stop the program when something that "can't happen" does. assert checks only in debug builds; precondition also checks in release builds; fatalError always stops. Use them for programmer mistakes, not for recoverable failures like bad user input (throw an error for those).

Notes

  • -O builds skip assert entirely
  • -Ounchecked builds skip precondition too
  • fatalError returns Never, so it satisfies any return type
  • Array out-of-bounds and force-unwrap nil are built-in preconditions

assert · precondition · fatalError

func setVolume(_ v: Int) {
    assert((0...100).contains(v), "volume out of range: \(v)")
    // debug: stops here   release: keeps going
}

func withdraw(_ amount: Int, from balance: Int) -> Int {
    precondition(amount > 0, "amount must be positive")
    return balance - amount            // checked in release too
}

func cell(for row: Int) -> Cell {
    guard let cell = table.dequeue(row) else {
        fatalError("Cell not registered for row \(row)")
    }
    return cell
}

required init?(coder: NSCoder) {
    fatalError("init(coder:) not supported")
}

Code Explained

assert(cond, msg) — debug-only check
precondition(cond, msg) — debug + release
fatalError(msg) — always stops, returns Never
assertionFailure / preconditionFailure — no condition

The Swifty Way

  • ✗ precondition(!email.isEmpty) on user input
    ✓ throw ValidationError.emptyEmail — users make mistakes; code shouldn't crash

Coming From…

  • Java assert ≈ assert (off by default there)
  • Kotlin require ≈ precondition; check ≈ assert
  • Python assert ≈ assert; -O disables both

⚠ Common Mistakes

  • Putting side effects inside assert(...): they vanish in release builds
  • Using fatalError for network or parsing failures
  • Leaving fatalError("TODO") in shipped code paths

✓ Tips & Best Practices

  • Write messages that include the bad value
  • Use precondition at public API boundaries in libraries
  • Search for fatalError( before every release

Quick Summary

  • assert — debug only
  • precondition — always (except -Ounchecked)
  • fatalError — always, returns Never
