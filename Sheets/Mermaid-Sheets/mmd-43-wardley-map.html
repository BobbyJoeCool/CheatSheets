Value Chain vs Evolution

A wardley-beta map places components by visibility to the user (vertical, 0–1) and evolution from genesis to commodity (horizontal, 0–1). Coordinates use the OnlineWardleyMaps order [visibility, evolution] — y first. Anchors are users or needs at the top; -> links show dependencies; evolve draws where a component is heading; decorators like (build) and (buy) mark sourcing choices.

Notes

  • [0.9, 0.2] = high visibility, early evolution
  • Names may contain spaces and hyphens without quotes
  • (inertia) marks resistance to change
  • size [1100, 600] sets the canvas
  • Added in v11.14

⚠ Common Mistakes

  • Writing coordinates as [x, y]. Wardley uses [visibility, evolution] — vertical first.
  • Putting infrastructure near the top. Low visibility (bottom) means further from the user.
  • Using evolve with a value lower than the current evolution; components move toward commodity.

✓ Tips & Best Practices

  • Start from the anchor (user need) and add only components the user's need depends on.
  • Use (build) only where you differentiate; most commodity parts should be (buy) or (market).
  • Draw the map twice — today and in 18 months — to drive strategy talks.

Quick Summary

  • wardley-beta — declaration
  • [visibility, evolution] — coordinates, y first
  • anchor / component — needs and parts
  • -> · evolve · decorators — dependencies, movement, sourcing
