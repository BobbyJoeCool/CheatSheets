Actors and Goals

A usecase-beta diagram shows actors (people or systems) and the use cases they take part in, usually inside a system boundary. Actors must be declared with actor; use cases are written with parentheses for the classic ellipse or brackets for a rectangle. UML relationships have explicit operators: ..> : include, ..> : extend and --|> for generalization. It is one of the v12 types that defaults to redux-color, neo and ELK.

Notes

  • Undeclared endpoints become use cases — actors need actor
  • Login("Sign in") = id Login, label Sign in
  • Boundaries are one level deep and hold only declarations
  • Actor types: @{ type: hollow }, awesome, or icon
  • ; is not a separator; one statement per line

Online Shop

usecase-beta
  direction LR
  actor Shopper
  actor Bank@{ type: hollow }
  systemBoundary shop["Web shop"]
    Browse("Browse items")
    Checkout("Check out")
    Pay("Pay by card")
    Coupon("Apply coupon")
  end
  Shopper --> Browse
  Shopper --> Checkout
  Checkout ..> : include Pay
  Coupon ..> : extend Checkout
  Pay --> Bank

⚠ Common Mistakes

  • Expecting User --> Login to create an actor. Endpoints without a declaration become use cases; add actor User.
  • Writing include as a label: A -- "include" --> B is an ordinary association. Use A ..> : include B.
  • Putting relationships inside systemBoundary. Boundaries only hold actor and use case declarations.

✓ Tips & Best Practices

  • Name use cases as verb phrases from the actor's view: Check out, Track order.
  • Put external systems (bank, email) outside the boundary as hollow actors.
  • Use include for steps that always happen, extend for optional ones.

Quick Summary

  • usecase-beta — declaration
  • actor — required for actors
  • ( ) / [ ] — ellipse / rectangle use cases
  • systemBoundary … end — the system
  • ..> : include · ..> : extend · --|> — UML relations
