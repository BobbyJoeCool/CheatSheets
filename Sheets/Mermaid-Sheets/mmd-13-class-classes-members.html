Classes and Members

A classDiagram describes types in object-oriented code. Define a class with class Name { … } and list members inside, one per line: attributes as +type name and methods with parentheses +name(args) returnType. A leading symbol sets visibility; a trailing $ marks static and * abstract. Generics use tildes (List~int~), and annotations like <<interface>> describe the kind of class.

Rules

  • Members can also be added one per line: Account : +deposit(amt)
  • Anything with () is a method; everything else is an attribute
  • Nested generics work: List~List~int~~
  • Group classes with namespace Name { … }
  • v12 default theme: redux-color, look neo

Shapes

classDiagram

⚠ Common Mistakes

  • Putting the type after the name for attributes (name String). Mermaid draws exactly what you write; pick one style and keep it.
  • Using <T> for generics. Angle brackets clash with the syntax; write ~T~.
  • Adding a space before $ or * (area() $). The marker must touch the closing parenthesis or name.

✓ Tips & Best Practices

  • Show only the public API on overview diagrams; private fields make boxes long and change often.
  • Use <<interface>> plus a realization arrow ..|> to show what implements what (sheet 14).
  • Write enums as <<enumeration>> with one value per line.

Quick Summary

  • class Name { … } — class with members
  • + - # ~ — public, private, protected, package
  • ()$ / ()* — static / abstract
  • ~T~ — generics
  • <<interface>> — annotations
