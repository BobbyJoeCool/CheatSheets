Sheet 19

Git Graph — Commits & Branches

gitGraph · commit id: / tag: · type: · branch · checkout / switch · order:

Drawing Git History

A gitGraph replays Git commands to draw history. It starts on main; commit adds a commit to the current branch, branch name creates a branch and switches to it, and checkout name (or switch name) moves back to an existing branch. Commits can get a custom id, a tag, and a type that changes the dot (normal, reverse, highlight). Commands run top to bottom, exactly as you would type them.

Rules

  • The first branch is main (rename with mainBranchName)
  • branch both creates and checks out the new branch
  • checkout and switch are interchangeable
  • Without id:, commits get random ids
  • Quote ids and tags: id: "fix-1"

Feature Branch

gitGraph
  commit id: "init"
  commit id: "readme" tag: "v1.0"
  branch feature
  commit id: "add-login"
  commit id: "tests" type: HIGHLIGHT
  checkout main
  commit id: "hotfix" type: REVERSE
  merge feature tag: "v1.1"
  commit

Rendered Output

Commits

Syntax Effect
commit New commit on current branch
commit id: "abc" Custom id (shown as label)
commit tag: "v1.0" Tag label
commit type: NORMAL Filled dot (default)
commit type: REVERSE Crossed dot (revert)
commit type: HIGHLIGHT Square, highlighted
commit id: "x" tag: "t" Attributes combine

Branches

Syntax Effect
branch develop Create + switch to develop
branch hotfix order: 3 Fix display position
checkout main Switch to existing branch
switch main Same as checkout
branch "feat/x" Quote names with /

Orientation

Declaration Direction
gitGraph Left → right (default)
gitGraph LR: Left → right
gitGraph TB: Top → bottom
gitGraph BT: Bottom → top (v11)

⚠ Common Mistakes

  • Running checkout on a branch that hasn't been created. Mermaid stops with an error; create it with branch first.
  • Writing branch x and then checkout x again — branch already switched. The extra checkout is harmless but hides intent.
  • Forgetting the colon in orientation: gitGraph TB instead of gitGraph TB:.

✓ Tips & Best Practices

  • Give meaningful commits an id: — merges and cherry-picks (sheet 20) need ids to refer to.
  • Use type: HIGHLIGHT to point at the commit a discussion is about.
  • Use order: to keep long-lived branches (main, develop) next to each other.

Quick Summary

  • gitGraph — starts on main
  • commit id: tag: type: — commits
  • branch — create and switch
  • checkout / switch — move between branches
  • LR: TB: BT: — orientation
