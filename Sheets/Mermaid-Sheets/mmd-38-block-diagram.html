Blocks You Place Yourself

A block diagram lets you control placement instead of a layout engine. Set the number of columns; blocks then fill the grid left to right, top to bottom, in the order written. A block can span several columns (id:2), space leaves an empty cell, and block:id … end nests a group with its own columns. Shapes reuse flowchart brackets, and links (-->) are drawn on top of the grid.

Notes

  • Several blocks can share a line: a b c
  • Without columns, blocks sit in one row
  • Arrow blocks: id<["text"]>(right) — left up down x y
  • block-beta still works as an alias

Three-Tier App

block
  columns 3
  web["Web"] space:1 cdn[("CDN")]
  arrow<[" "]>(down) space:2
  block:back:3
    api["API"] worker["Worker"] db[("DB")]
  end
  web --> cdn
  api --> db
  classDef tier fill:#e3f2fd,stroke:#1e88e5
  class api,worker tier

Links & Style

Syntax Meaning

⚠ Common Mistakes

  • Expecting blocks to move to make links neat. Placement is fixed by the grid; links just draw over it.
  • Spanning more columns than exist (a:4 with columns 3). The block overflows onto the next row.
  • Forgetting end after a nested block: group; the rest of the diagram ends up inside it.

✓ Tips & Best Practices

  • Sketch the grid on paper first; count cells, then write rows as lines of source.
  • Use space cells to line up blocks across rows instead of padding labels.
  • Use block diagrams for layered stacks (UI / API / DB) where position carries meaning.

Quick Summary

  • block + columns n — grid
  • id:n / space — span and gaps
  • block:id … end — nested groups
  • a --> b — links over the grid
