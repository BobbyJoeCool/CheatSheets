Pick the Diagram by the Question

Start from the question the reader needs answered, not from the diagram you know best. Flowcharts show steps and decisions, sequence diagrams show who talks to whom and in what order, ER and class diagrams show structure, state diagrams show lifecycles, and the chart types turn numbers into pictures. The tables below match common goals to the diagram that fits, with the declaration keyword and the sheet that covers it.

Rules of Thumb

  • Steps over time with decisions → flowchart
  • Messages between systems → sequence diagram
  • Tables and keys → ER diagram; code types → class diagram
  • Something that changes status → state diagram
  • Dates and durations → Gantt; dated events → timeline
  • When two fit, choose the one with fewer lines of source

⚠ Common Mistakes

  • Forcing everything into a flowchart. Message order between services reads far better as a sequence diagram.
  • Using a pie chart for more than about six slices or for values that don't add up to a whole; use xychart bars instead.
  • Drawing a database schema as a class diagram. erDiagram has keys and crow's-foot cardinality built in.

✓ Tips & Best Practices

  • Sketch the question first ("what happens when…", "what is connected to…") — the verb usually names the diagram type.
  • Split one huge diagram into several small ones of the right type rather than one of the wrong type.
  • Check platform support before choosing a beta type for docs that render on GitHub or GitLab.

Quick Summary

  • flowchart / sequenceDiagram — process / interactions
  • erDiagram / classDiagram — data / code structure
  • stateDiagram-v2 — lifecycles
  • gantt / timeline — schedules / history
  • pie · xychart · sankey — numbers
