Diagram Anatomy & Common Syntax

declaration line · -beta · %% comments · --- front matter · accTitle / accDescr · #quot; · markdown strings

The Shape of Every Diagram

Every Mermaid diagram has the same skeleton: optional front matter between --- lines (title and config), a declaration line naming the diagram type, then statements, usually one per line. %% starts a comment. accTitle and accDescr add accessible text for screen readers. Labels that contain symbols go in double quotes, and characters that would break the syntax can be written as entity codes.

Rules

  • Front matter must start on line 1 — nothing before the first ---
  • The declaration is the first line after front matter (comments aside)
  • Keywords are case-sensitive: sequenceDiagram, gitGraph, erDiagram
  • %% comments go on their own line
  • %%{init: … }%% directives are deprecated since v10.5 — use front matter config:

Front Matter, Accessibility, Comments & Labels

---
title: Checkout
config:
  look: handDrawn
---
flowchart LR
  accTitle: Checkout flow
  accDescr: Cart to payment to confirmation
  %% comments are ignored by the parser
  cart["Cart (2 items)"] --> pay["`**Pay** now`"]
  pay --> done["Order #35;1042 #9829;"]

Rendered Output

Skeleton Pieces

Syntax Purpose
--- Opens and closes the YAML front matter
title: Text Title drawn above the diagram
config: Per-diagram settings: theme, look, layout, …
flowchart LR Declaration: diagram type (+ options)
%% text Comment, ignored when rendering
accTitle: Text Accessible title (<title> in the SVG)
accDescr: Text Accessible description, one line
accDescr { … } Accessible description over several lines

Labels & Escaping

Syntax Result
id[Text] Plain label
id["A (b) & c"] Quotes allow ( ) [ ] { } & in a label
#quot; Double quote inside a quoted label
#35; # written as its decimal code
#9829; Any character by code: ♥
"`**b** _i_`" Markdown string: bold, italic, auto-wrap
Line 1<br>Line 2 Line break inside a label

Gotchas

Pitfall Fix
end Lowercase end as a node text breaks flowcharts: write End or quote it
A---oB A node name starting with o / x after a link becomes a circle / cross edge: add a space
indentation Mindmap, treemap, ishikawa and tree view use it as structure
; Optional statement separator; one statement per line is clearer
tabs vs spaces Mix them and indentation-based diagrams nest wrongly

⚠ Common Mistakes

  • Putting a comment or blank text above the opening ---. Front matter is only recognized when --- is the very first line.
  • Pasting from a word processor: curly quotes “ ” are not string delimiters, so labels with symbols fail to parse.
  • Writing %%{init: …}%% in new diagrams. It still works for now, but it is deprecated; front matter config: is the supported form.
  • Typing # directly in some labels. Use #35; or quote the whole label.

✓ Tips & Best Practices

  • Always add accTitle and accDescr to diagrams in public docs; they become the SVG's <title> and <desc>.
  • Quote any label with punctuation by default. It costs two characters and avoids most parse errors.
  • Use markdown strings (backticks inside quotes) for long labels: they wrap automatically.

Quick Summary

  • --- — front matter: title and config for one diagram
  • declaration — first statement names the diagram type
  • %% — comment line
  • accTitle / accDescr — accessible title and description
  • "…" / #code; — quote labels, escape characters by code
