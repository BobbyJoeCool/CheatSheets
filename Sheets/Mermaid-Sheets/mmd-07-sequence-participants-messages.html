Sheet 07

Sequence — Participants & Messages

sequenceDiagram · participant / actor · as alias · ->> · -->> · create / destroy · autonumber

Who Talks to Whom

A sequenceDiagram shows participants across the top and messages between them in time order, top to bottom. Participants appear when first used, or in the order you declare them with participant / actor. Each message line is From->>To: text; the arrow sets solid vs dotted and the arrowhead. Since v11 a participant can take a type such as database or queue to change its symbol.

Notes

  • Declare participants first to control their left-to-right order
  • as gives a short id a longer display name
  • Only the receiver of a message can be created mid-diagram
  • Hex colors don't work in box — # starts a comment; use names or rgb()
  • v12 default theme: redux-color, look neo

Login

sequenceDiagram
  autonumber
  actor U as User
  participant W as Web App
  participant DB@{ "type": "database" }
  U->>W: Log in
  W->>DB: Find user
  DB-->>W: User row
  create participant M as Mailer
  W-)M: Send welcome email
  W-->>U: Dashboard

⚠ Common Mistakes

  • Using -> when you meant a call. -> and --> draw no arrowhead; use ->> for requests and -->> for replies.
  • Writing box #eef Frontend. The # starts a comment, so the box loses its color and label.
  • Trying to create the sender of a message. Only the recipient can be created; the sender must already exist.

✓ Tips & Best Practices

  • Use actor for people and participant (with a type) for systems so the roles read at a glance.
  • Stick to one convention: solid ->> for requests, dotted -->> for responses, -) for fire-and-forget.
  • Add autonumber when the diagram will be discussed in review; people can say "step 4".

Quick Summary

  • participant / actor — declare and order lifelines
  • A@{ "type": … } — database, queue, boundary symbols
  • ->> / -->> — request / reply
  • create / destroy — lifelines that start or end mid-way
  • autonumber — number the messages
