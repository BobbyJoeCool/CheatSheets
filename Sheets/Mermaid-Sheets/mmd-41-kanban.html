Kanban

kanban · column[Title] · task[Text] · @{ assigned, ticket, priority } · ticketBaseUrl

A Board of Work Items

A kanban diagram draws a board: columns for workflow stages and tasks (cards) inside them. Columns sit at the first indent level as id[Title]; tasks are indented under their column as id[Description]. Add metadata with @{ … } — assigned, ticket and priority — and set ticketBaseUrl in config to turn ticket numbers into links.

Notes

  • Indentation decides which column a task belongs to
  • Ids must be unique across the board
  • priority: 'Very High' 'High' 'Low' 'Very Low'
  • #TICKET# in ticketBaseUrl is replaced by the ticket id

Sprint Board

---
config:
  kanban:
    ticketBaseUrl: "https://jira.example.com/browse/#TICKET#"
---
kanban
  todo[To do]
    t1[Write release notes]@{ assigned: "ana" }
    t2[Fix login bug]@{ ticket: WEB-42, priority: "High" }
  doing[In progress]
    t3[Dark mode]@{ assigned: "raj", priority: "Low" }
  done[Done]
    t4[Upgrade Mermaid to 12]

Rendered Output

Syntax

Syntax Meaning
kanban Declaration
todo[To do] Column (first indent)
t1[Task text] Task in that column
[Task text] Task without an id
t1[…]@{ … } Task metadata

Metadata

Key Value
assigned: "ana" Person responsible
ticket: WEB-42 Ticket id (link)
priority: "Very High" Highest
priority: "High" High
priority: "Low" Low
priority: "Very Low" Lowest

kanban: Config

Key Effect
ticketBaseUrl Link pattern with #TICKET#
sectionWidth Column width
padding Space around cards

⚠ Common Mistakes

  • Indenting a task at the same level as columns. It becomes a new column.
  • Inventing priority values ('Medium', 'P1'). Only the four listed values are recognized.
  • Reusing an id in two columns. Ids must be unique, or cards collide.

✓ Tips & Best Practices

  • Use a kanban diagram for snapshots in docs or status reports, not as a live tracker.
  • Set ticketBaseUrl once so every ticket: becomes a clickable link.
  • Keep card text short; put details in the ticket.
