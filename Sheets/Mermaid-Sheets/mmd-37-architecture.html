Cloud Services and Connections

An architecture-beta diagram shows services (nodes with icons), groups that contain them, and edges between them. Every element has an id, an icon in parentheses and a label in brackets: service db(database)[Orders DB] in api. Edges name the side each end attaches to — T, B, L, R — which is how you steer the layout. Five icons are built in; register an Iconify pack for thousands more.

Notes

  • Built-in icons: cloud database disk internet server
  • Other icons: pack:name after registerIconPacks()
  • in groupId puts a service or group inside a group
  • junction splits one edge four ways
  • align row / align column line up siblings (v11.16)

⚠ Common Mistakes

  • Referencing an id before it's declared. Groups and services must be declared before edges use them.
  • Leaving out the sides (api --> db). Architecture edges need :T|B|L|R on both ends.
  • Using a pack:icon name without registering the pack. The service shows a fallback icon.

✓ Tips & Best Practices

  • Point edges the way you read: left-to-right for request flow, top-to-bottom for data stores.
  • Register Iconify packs (logos, mdi) in mermaid.registerIconPacks() to get vendor icons like AWS or Azure.
  • If two siblings overlap, add align row or align column instead of fiddling with spacing.
