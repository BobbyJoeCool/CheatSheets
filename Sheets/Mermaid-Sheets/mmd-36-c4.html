Software Architecture in Levels

Mermaid's C4 diagrams follow Simon Brown's C4 model and use the C4-PlantUML syntax: function-style statements such as Person(alias, "Label", "Description"). Pick the level with the declaration — C4Context, C4Container, C4Component, C4Dynamic or C4Deployment — then add elements, nest them in boundaries { }, and connect them with Rel(from, to, "label"). Layout follows statement order, not an automatic algorithm.

Notes

  • Still marked experimental in the docs
  • _Ext versions draw external (grey) elements
  • Optional params by name: $techn="…", $link="…"
  • Text wraps by default since v11.17.1
  • Reorder statements to move shapes

Shop — Container Level

C4Container
  title Web shop containers
  Person(user, "Shopper", "Buys products")
  System_Boundary(shop, "Web Shop") {
    Container(web, "Web App", "React", "Storefront")
    Container(api, "API", "Node.js")
    ContainerDb(db, "Database", "PostgreSQL")
  }
  System_Ext(pay, "Payment Provider")
  Rel(user, web, "Uses", "HTTPS")
  Rel(web, api, "Calls", "JSON")
  Rel(api, db, "Reads/writes")
  Rel(api, pay, "Charges card")

⚠ Common Mistakes

  • Expecting automatic layout. C4 places shapes in statement order; reorder lines or use UpdateLayoutConfig to fix crowding.
  • Mixing levels in one diagram (people, containers and classes). Draw one diagram per level.
  • Using unsupported C4-PlantUML features such as tags, sprites or Lay_* statements — they aren't implemented.

✓ Tips & Best Practices

  • Start with C4Context for non-technical readers, then zoom into C4Container for engineers.
  • Always put the technology in Rel and Container ("HTTPS", "PostgreSQL"); it's what reviewers ask about.
  • For freer layouts consider architecture-beta (sheet 37) or a flowchart.

Quick Summary

  • C4Context … C4Deployment — pick the level
  • Person · System · Container · Component — elements
  • *_Boundary(…) { } — grouping
  • Rel(a, b, "label") — relationships
