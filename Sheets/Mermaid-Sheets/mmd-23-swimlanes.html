A Flowchart Split by Owner

A swimlane-beta diagram is a flowchart whose top-level subgraphs become lanes, one per person, team or system. Nodes and edges use the flowchart syntax from sheets 05–06, so the new part is only where you declare each node: inside the lane that owns the step. Links that cross a lane boundary are handoffs, the places where work changes hands. Swimlanes use their own swimlane layout and the v12 redux-color / neo defaults.

Notes

  • Default direction is TB; LR makes horizontal lanes
  • Lane id + label: subgraph ops [Operations]
  • Declare a node inside the lane that owns it
  • Supports accTitle / accDescr
  • New in v12 — needs the -beta suffix

⚠ Common Mistakes

  • Using flowchart with subgraphs and expecting lanes. Only swimlane-beta lays top-level subgraphs out as aligned lanes.
  • Declaring a node only in an edge line. It then lands outside every lane; declare it inside its lane first.
  • Nesting lanes inside lanes. Only top-level subgraphs become lanes.

✓ Tips & Best Practices

  • Write the lanes first with their nodes, then all the edges at the bottom — the source mirrors the picture.
  • Use LR for long processes so lanes run across the page.
  • Label every edge that crosses lanes with what is handed over (ticket, invoice).

Quick Summary

  • swimlane-beta — flowchart with lanes
  • subgraph … end — one lane per owner
  • flowchart shapes and edges — same as sheets 05–06
  • cross-lane edges — handoffs worth labeling
