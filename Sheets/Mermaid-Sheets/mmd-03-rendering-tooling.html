Getting a Diagram on Screen

On a web page, Mermaid finds elements with class="mermaid", reads their text and replaces it with an SVG. Load it as an ES module from a CDN or npm, call mermaid.initialize() once with site-wide options, and let startOnLoad render the page, or call mermaid.run() / mermaid.render() yourself for content that arrives later. Outside the browser, the mmdc command line tool renders .mmd files to SVG, PNG or PDF.

Notes

  • Pin a version in CDN URLs (mermaid@12.2.0) so diagrams don't change under you
  • mermaid.init() is deprecated since v10 — use mermaid.run()
  • Render after fonts load, or labels may be measured with the wrong font
  • securityLevel: 'strict' (default) blocks click scripts and HTML in labels
  • The tiny build omits mindmap, architecture, KaTeX and ELK

Mermaid on a Web Page

<pre class="mermaid">
flowchart LR
  A[Request] --> B[Response]
</pre>

<script type="module">
  import mermaid from
    "https://cdn.jsdelivr.net/npm/mermaid@12.2.0/dist/mermaid.esm.min.mjs";
  mermaid.initialize({ startOnLoad: true, theme: "neutral" });

  // later, for content added after load:
  await mermaid.run({ querySelector: ".late-diagram" });
  const { svg } = await mermaid.render("d1", "pie\n \"A\" : 1");
</script>

Code Explained

class="mermaid" — the element's text is the diagram source
import mermaid — ESM build from jsDelivr, version pinned
initialize() — site-wide config, call once
startOnLoad — render every .mermaid element on page load
run() — render elements matched by querySelector / nodes
render(id, text) — returns { svg, bindFunctions } for you to insert

JavaScript API

Call Does
initialize(config) Set site-wide config (theme, look, securityLevel, …)
run(options) Render matching elements; suppressErrors: true keeps going
render(id, text) Render one definition → { svg, bindFunctions }
parse(text, opts) Validate only → { diagramType }, or throws
registerIconPacks([…]) Add Iconify packs for icon / architecture
registerExternalDiagrams Add plugin diagrams such as ZenUML

mmdc (mermaid-cli)

Command Result
npm i -g @mermaid-js/mermaid-cli Install the mmdc command
mmdc -i in.mmd -o out.svg Render to SVG (format from extension)
mmdc … -o out.png -s 2 PNG at 2× scale
mmdc … -o out.pdf PDF output
-t dark -b transparent Theme and background color
-c config.json Mermaid config file
mmdc -i doc.md -o out.md Render every fence; links SVGs into Markdown

⚠ Common Mistakes

  • Calling initialize() with startOnLoad: true and also calling run() on the same elements. They render twice, or the second pass sees SVG instead of source.
  • HTML-escaping the source wrong: inside <pre class="mermaid"> write --> as is, but < and & must be &lt; and &amp;.
  • Rendering into a hidden tab or collapsed <details>: elements with zero width produce squashed or empty diagrams. Render when visible.

✓ Tips & Best Practices

  • Use mermaid.parse(text, { suppressErrors: true }) to validate user input before rendering.
  • In CI, run mmdc on every .mmd file so a syntax error fails the build.
  • Give each render() call a unique id; reusing one id overwrites the previous temporary element.

Quick Summary

  • class="mermaid" + startOnLoad — simplest page setup
  • initialize() — global config, once per page
  • run() / render() — render on demand
  • mmdc -i … -o … — render files to SVG / PNG / PDF
