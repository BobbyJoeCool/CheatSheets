ZenUML

zenuml · @Actor / @Database · A.method() · A->B: msg · if / while / try · return · plugin

Sequence Diagrams Written as Code

zenuml is an alternative sequence-diagram syntax that reads like code. A sync call is A.method(args), and braces { } nest the calls it makes. Async messages use A->B: text, new A() creates a participant, and return (or x = A.call()) draws the reply. Control flow uses familiar keywords: if/else, while, opt, par, try/catch/finally. ZenUML is an external plugin: the page must register @mermaid-js/mermaid-zenuml.

Notes

  • Not in core Mermaid — registerExternalDiagrams([zenuml])
  • // comments above a message are rendered (markdown OK)
  • Annotators set the symbol: @Actor, @Database, …
  • A as Alice gives an alias
  • GitHub and most platforms don't render it

⚠ Common Mistakes

  • Using ZenUML where only core Mermaid runs (GitHub, mermaid.live without the plugin). It fails with "unknown diagram type".
  • Mixing Mermaid sequence syntax (->>, activate) into ZenUML. The two syntaxes are separate.
  • Forgetting braces after a call that makes further calls — nested calls then appear as top-level messages.

✓ Tips & Best Practices

  • Choose ZenUML when the diagram mirrors real code; choose sequenceDiagram (sheet 07) for portability.
  • Name calls after real methods (OrderService.place) so the diagram stays in sync with the code.
  • Use // comments for the "why"; they render above the message.

Quick Summary

  • zenuml — plugin diagram type
  • A.method() { } — sync call with nesting
  • A->B: text — async
  • return / x = … — replies
  • if · while · try — control flow
