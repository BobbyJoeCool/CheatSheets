Sequence — Activations, Notes & Control Blocks

activate / +- · Note over · loop · alt / else · opt · par / and · critical · break · rect

Showing Logic in Time

Activations draw a thin bar on a lifeline while a participant is busy: use activate / deactivate, or the shortcut + / - on a message arrow. Notes sit beside or across lifelines. Control blocks wrap messages in a labeled frame: loop for repetition, alt/else for branches, opt for optional steps, par/and for parallel work, critical and break for error paths. Every block closes with end.

Notes

  • + activates the receiver, - deactivates the sender
  • Activations can stack on the same lifeline
  • Blocks nest: an alt inside a loop is fine
  • rect takes a color: rect rgb(240,240,255) … end
  • Each block needs its own end

Payment with Retry

sequenceDiagram
  participant C as Client
  participant P as Payments
  C->>+P: Charge $40
  loop up to 3 times
    P->>P: Call bank
  end
  alt approved
    P-->>C: Receipt
  else declined
    P-->>C: Error 402
  end
  Note over C,P: Card data never logged
  P-->>-C: Done

Activations & Notes

Syntax Effect
activate B Start a bar on B
deactivate B End B's bar
A->>+B: msg Send and activate B
B-->>-A: msg Reply and deactivate B
Note right of A: … Note to the right
Note left of A: … Note to the left
Note over A: … Note on one lifeline
Note over A,B: … Note across two lifelines

Control Blocks

Block Use
loop label Repeat
alt label First branch of if / else
else label Next branch (inside alt)
opt label Optional step, no else
par label Parallel actions
and label Next parallel branch
critical label Must happen atomically
option label Alternative inside critical
break label Stop the flow (exception)
rect rgb(…) Highlight background
end Close any block

⚠ Common Mistakes

  • Deactivating a participant that isn't active. Mermaid throws an error; every - or deactivate needs a matching activation.
  • Forgetting end after alt or loop. The parser reports an error at the end of the diagram, not where the block opened.
  • Putting else inside opt. opt has no branches; use alt … else … end instead.

✓ Tips & Best Practices

  • Use the + / - shortcuts; they keep activation next to the message that causes it.
  • Label blocks with the condition (alt card declined), not just the outcome.
  • Use Note over A,B for protocol rules that apply to a whole exchange.

Quick Summary

  • activate / + - — busy bars on lifelines
  • Note over A,B — notes beside or across lifelines
  • loop · alt/else · opt — repeat, branch, optional
  • par/and · critical · break — parallel and error paths
  • end — closes every block
