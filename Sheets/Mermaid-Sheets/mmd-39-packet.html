Packet

packet · 0-15: "field" · +16 bit counts · bitsPerRow · bitOrder · title

Bits in a Header

A packet diagram shows the layout of a network packet, file header or hardware register as rows of bit fields. Each line gives a bit range and a quoted label: 0-15: "Source Port", or a single bit 106: "URG". Since v11.7 you can write a bit count instead (+16: "Length"), which starts where the previous field ended. Rows are 32 bits wide by default.

Notes

  • Ranges are inclusive: 0-15 is 16 bits
  • +n counts from the end of the previous field
  • Ranges and +n lines can be mixed
  • Fields must not overlap or leave gaps
  • bitOrder: descending mirrors rows for registers (v12)

UDP Header

---
config:
  packet:
    bitsPerRow: 16
    showBits: true
---
packet
  title UDP datagram
  +16: "Source Port"
  +16: "Destination Port"
  32-47: "Length"
  48-63: "Checksum"
  64-95: "Data (variable)"

⚠ Common Mistakes

  • Counting ranges as exclusive. 0-16 is 17 bits; a 16-bit field is 0-15.
  • Leaving a gap or overlap between fields. Mermaid reports an error; every bit must belong to exactly one field.
  • Writing ranges high-to-low (7-0) for registers. Always declare low-to-high and use bitOrder: descending to flip the drawing.

✓ Tips & Best Practices

  • Prefer +n bit counts: inserting a field later doesn't force you to renumber everything after it.
  • Set bitsPerRow: 16 or 8 for small registers so fields aren't tiny.
  • Label variable-length tails clearly (Data (variable)).

Quick Summary

  • packet — declaration
  • start-end: "label" — bit range
  • +n: "label" — bit count from the last field
  • bitsPerRow / bitOrder — row width and direction
