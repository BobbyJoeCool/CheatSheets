Sheet 05

IAM Users, Groups & Roles

users vs roles · groups · aws iam create-role · least privilege · access keys · aws sts get-caller-identity

Identities in AWS

IAM controls who can call AWS APIs in an account. Users have long-term credentials and are now mainly for edge cases; people should use IAM Identity Center. Roles have no long-term credentials: a trusted principal (a person, a service such as Lambda, another account, or an OIDC identity) assumes the role and gets temporary keys. Groups attach policies to many users.

Key Points

  • Every role has a trust policy (who can assume) and permission policies (what it can do)
  • Service roles let AWS services act for you (Lambda execution role)
  • Service-linked roles are created and managed by a service
  • IAM is global within an account

Create a Role for Lambda

cat > trust.json <<'JSON'
{ "Version": "2012-10-17",
  "Statement": [{ "Effect": "Allow",
    "Principal": { "Service": "lambda.amazonaws.com" },
    "Action": "sts:AssumeRole" }] }
JSON
aws iam create-role --role-name resize-fn-role \
    --assume-role-policy-document file://trust.json
aws iam attach-role-policy --role-name resize-fn-role \
    --policy-arn \
    arn:aws:iam::aws:policy/service-role/AWSLambdaBasicExecutionRole

aws iam list-roles --query "Roles[?starts_with(RoleName,'resize')].Arn"
aws iam list-attached-role-policies --role-name resize-fn-role

# Who am I right now?
aws sts get-caller-identity
# Find old access keys
aws iam generate-credential-report && aws iam get-credential-report \
    --query Content --output text | base64 -d | cut -d, -f1,9,10

Code Explained

The trust policy lets the Lambda service assume the role
The managed policy grants CloudWatch Logs access
JMESPath filters roles by name prefix
The credential report lists users and key ages

Cost Check

  • IAM is free
  • Leaked access keys are the most expensive mistake: crypto-mining bills
  • Unused roles cost nothing but widen the attack surface

Do & Don't

  • Do Use roles for every workload and Identity Center for people
  • Do Remove unused users, keys and roles
  • Don’t Share IAM user credentials among a team
  • Don’t Attach AdministratorAccess to application roles

Local Testing

  • IAM Policy Simulator tests what a role can do
  • IAM Access Analyzer validates policies and finds unused access
  • LocalStack accepts IAM calls (enforcement optional)

Production Checklist

  • No IAM users for humans; MFA on any that remain
  • Credential report reviewed; keys rotated or removed
  • Access Analyzer unused-access findings acted on
