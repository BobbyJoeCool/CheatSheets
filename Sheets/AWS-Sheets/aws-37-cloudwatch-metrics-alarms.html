CloudWatch Metrics & Alarms

namespaces & dimensions · put-metric-data · alarms & SNS actions · dashboards · composite alarms · anomaly detection

Watching AWS Resources

CloudWatch collects metrics from AWS services in namespaces (AWS/EC2, AWS/Lambda) with dimensions (InstanceId, FunctionName). Publish your own with put-metric-data or embedded metric format (EMF) logs. Alarms watch a metric or expression and notify SNS, scale ASGs or run actions. Composite alarms combine alarms; anomaly detection learns normal bands.

Key Points

  • Basic monitoring: 5-minute EC2 metrics; detailed: 1-minute
  • Metric math builds error rates from counts
  • Alarms have OK / ALARM / INSUFFICIENT_DATA states
  • Application Signals adds SLOs and service maps

Custom Metric, Alarm, Dashboard

aws cloudwatch put-metric-data --namespace Shop \
    --metric-name OrdersPlaced --dimensions Env=prod --value 1 --unit Count

aws sns create-topic --name oncall
aws cloudwatch put-metric-alarm --alarm-name api-5xx \
    --namespace AWS/ApplicationELB --metric-name HTTPCode_Target_5XX_Count \
    --dimensions Name=LoadBalancer,Value=app/shop-alb/abc123 \
    --statistic Sum --period 60 --evaluation-periods 5 --datapoints-to-alarm 3 \
    --threshold 10 --comparison-operator GreaterThanThreshold \
    --treat-missing-data notBreaching --alarm-actions $ONCALL_TOPIC

aws cloudwatch put-metric-alarm --alarm-name lambda-errors \
    --namespace AWS/Lambda --metric-name Errors \
    --dimensions Name=FunctionName,Value=orders --statistic Sum \
    --period 300 --evaluation-periods 1 --threshold 1 \
    --comparison-operator GreaterThanOrEqualToThreshold \
    --alarm-actions $ONCALL_TOPIC

aws cloudwatch get-metric-statistics --namespace AWS/Lambda \
    --metric-name Duration --dimensions Name=FunctionName,Value=orders \
    --start-time 2026-11-12T00:00:00Z --end-time 2026-11-12T12:00:00Z \
    --period 3600 --statistics Average Maximum
aws cloudwatch put-dashboard --dashboard-name shop \
    --dashboard-body file://dash.json

Code Explained

Custom metrics live in your own namespace
3 of 5 one-minute periods over 10 errors trigger the alarm
Missing data is treated as OK for sparse metrics
Dashboards are JSON documents you can keep in IaC

Azure / GCP Equivalent

  • Azure Azure Monitor metrics, alert rules, action groups (az-37)
  • GCP Cloud Monitoring, alerting policies (gcp-37)

Cost Check

  • Basic AWS service metrics are free; custom metrics bill per metric per month
  • Alarms bill per alarm metric; high-resolution costs more
  • High-cardinality dimensions multiply custom metric costs

Do & Don't

  • Do Alarm on user-facing symptoms (errors, latency, queue age)
  • Do Keep alarms and dashboards in IaC
  • Don’t Create custom metrics with user IDs as dimensions
  • Don’t Page on single noisy data points

Local Testing

  • Emit EMF logs locally and inspect the JSON
  • LocalStack emulates CloudWatch APIs for tests
  • Test alarm thresholds against historical data with get-metric-statistics

Production Checklist

  • Alarms with runbooks routed to on-call
  • Composite alarms to cut noise
  • Dashboards per service with golden signals
