Managed Kubernetes on AWS

Amazon EKS runs the Kubernetes control plane across AZs. Workers come from managed node groups, Fargate profiles, Karpenter, or EKS Auto Mode, which manages compute, networking and storage components for you. EKS Pod Identity gives pods IAM roles. Add-ons (VPC CNI, CoreDNS, kube-proxy, EBS CSI) are versioned and managed.

Key Points

  • Access entries map IAM principals to Kubernetes permissions
  • The VPC CNI gives pods real VPC IP addresses
  • Upgrade the control plane, then add-ons and nodes
  • See the Kubernetes set for kubectl and manifests

Limits & Quotas

  • 100 clusters per Region by default
  • 30 managed node groups per cluster; 450 nodes per group
  • 10 Fargate profiles per cluster

Cluster, Access, Pod Identity

eksctl create cluster --name shop --region us-east-1 --version 1.34 \
    --enable-auto-mode
# or managed node groups:
# eksctl create cluster --name shop --nodegroup-name ng1 \
#   --node-type m7g.large --nodes 3 --nodes-min 3 --nodes-max 10

aws eks update-kubeconfig --name shop --region us-east-1
kubectl get nodes

aws eks create-access-entry --cluster-name shop \
    --principal-arn arn:aws:iam::111122223333:role/platform-admins
aws eks associate-access-policy --cluster-name shop \
    --principal-arn arn:aws:iam::111122223333:role/platform-admins \
    --policy-arn $EKS_ADMIN_POLICY_ARN \
    --access-scope type=cluster

aws eks create-pod-identity-association --cluster-name shop \
    --namespace shop --service-account api \
    --role-arn arn:aws:iam::111122223333:role/shop-api-pod
aws eks list-addons --cluster-name shop
aws eks update-cluster-version --name shop --kubernetes-version <next>

Code Explained

Auto Mode provisions and scales nodes automatically
update-kubeconfig writes a context that authenticates with IAM
Access entries replace editing the aws-auth ConfigMap
Pods using service account shop/api get the role's credentials

Azure / GCP Equivalent

  • Azure AKS, AKS Automatic, workload identity (az-27)
  • GCP GKE Autopilot / Standard, Workload Identity Federation (gcp-26, gcp-27)

Cost Check

  • Cluster fee per hour (higher in extended support)
  • Auto Mode adds a per-instance management fee on top of EC2
  • Spot nodes and Karpenter consolidation cut node cost

Do & Don't

  • Do Use Pod Identity (or IRSA) for every workload needing AWS access
  • Do Stay within standard support versions
  • Don’t Run apps with the node role's permissions
  • Don’t Hand-edit aws-auth when access entries exist

Local Testing

  • kind / k3d / minikube run the same manifests
  • eksctl dry-run prints the CloudFormation it will create
  • Telepresence / mirrord bridge local code to a cluster

Production Checklist

  • Control plane logging and Container Insights
  • Upgrades planned before end of standard support
  • Pod Identity, network policies, and private endpoint access
