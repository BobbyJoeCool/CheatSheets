Infrastructure in a Programming Language

The AWS Cloud Development Kit (CDK) defines infrastructure in TypeScript, Python, Java, C# or Go, then synthesizes CloudFormation templates. Constructs come in levels: L1 (raw CloudFormation), L2 (sensible defaults and helper methods like grantRead) and L3 patterns (whole architectures). An app contains stacks; cdk deploy ships them.

Key Points

  • cdk bootstrap creates the staging bucket and roles once per account / Region
  • L2 grant* methods write least-privilege IAM for you
  • cdk-nag checks constructs against best-practice rules
  • Construct Hub lists community libraries

lib/shop-stack.ts

import * as cdk from "aws-cdk-lib";
import { Construct } from "constructs";
import * as s3 from "aws-cdk-lib/aws-s3";
import * as lambda from "aws-cdk-lib/aws-lambda";
import * as sqs from "aws-cdk-lib/aws-sqs";
import { SqsEventSource } from "aws-cdk-lib/aws-lambda-event-sources";

export class ShopStack extends cdk.Stack {
  constructor(scope: Construct, id: string, props?: cdk.StackProps) {
    super(scope, id, props);
    const bucket = new s3.Bucket(this, "Uploads", {
      versioned: true, enforceSSL: true,
      blockPublicAccess: s3.BlockPublicAccess.BLOCK_ALL,
      removalPolicy: cdk.RemovalPolicy.RETAIN,
    });
    const queue = new sqs.Queue(this, "Orders", {
      visibilityTimeout: cdk.Duration.seconds(60) });
    const fn = new lambda.Function(this, "Worker", {
      runtime: lambda.Runtime.NODEJS_22_X,
      architecture: lambda.Architecture.ARM_64,
      handler: "index.handler", code: lambda.Code.fromAsset("lambda"),
      environment: { BUCKET: bucket.bucketName } });
    bucket.grantReadWrite(fn);                 // least-privilege IAM
    fn.addEventSource(new SqsEventSource(queue, { batchSize: 10 }));
  }
}

CLI

npx cdk init app --language typescript
npx cdk bootstrap aws://111122223333/us-east-1
npx cdk synth && npx cdk diff && npx cdk deploy --require-approval broadening

Code Explained

L2 constructs set secure defaults like enforceSSL
grantReadWrite adds exactly the S3 permissions the function needs
addEventSource wires the SQS trigger and its IAM
diff shows template and IAM changes before deploy

Cost Check

  • CDK is free; it deploys through CloudFormation
  • Bootstrap creates a small S3 bucket and ECR repo for assets
  • cdk diff reveals costly replacements (e.g. renaming a database)

Do & Don't

  • Do Use L2 constructs and grant* methods
  • Do Run cdk-nag in CI
  • Don’t Rename construct IDs of stateful resources (causes replacement)
  • Don’t Put environment-specific logic everywhere instead of stack props

Local Testing

  • cdk synth runs fully offline
  • Jest / pytest assertions test synthesized templates
  • LocalStack cdklocal deploys to the local emulator

Production Checklist

  • Pipelines (CDK Pipelines or GitHub Actions) deploy, not laptops
  • RemovalPolicy.RETAIN on data resources
  • cdk-nag and diff review in pull requests
