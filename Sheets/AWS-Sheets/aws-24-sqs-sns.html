Sheet 24

SQS & SNS

standard vs FIFO queues · visibility timeout · dead-letter queues · SNS topics & subscriptions · fan-out pattern · Lambda triggers

Queues and Topics

SQS queues hold messages until a consumer processes and deletes them. Standard queues give nearly unlimited throughput with at-least-once, best-effort ordering; FIFO queues give ordering per message group and deduplication. The visibility timeout hides a message while it is processed. SNS topics push each message to many subscribers (SQS, Lambda, HTTP, email): the fan-out pattern.

Key Points

  • Long polling (WaitTimeSeconds up to 20) cuts empty receives
  • A redrive policy moves repeatedly failing messages to a DLQ
  • SNS subscription filter policies route by message attributes
  • Set visibility timeout to at least 6× the Lambda timeout for Lambda consumers

Limits & Quotas

  • SQS message up to 1 MiB (raised from 256 KB in 2025)
  • Retention 1 minute–14 days (default 4 days)
  • Visibility timeout up to 12 hours

Queue, DLQ, Topic Fan-Out

DLQ=$(aws sqs create-queue --queue-name orders-dlq \
  --query QueueUrl --output text)
DLQ_ARN=$(aws sqs get-queue-attributes --queue-url $DLQ \
  --attribute-names QueueArn --query Attributes.QueueArn --output text)
Q=$(aws sqs create-queue --queue-name orders \
  --attributes file://orders-attrs.json --query QueueUrl --output text)
# orders-attrs.json:
# {"VisibilityTimeout": "60", "ReceiveMessageWaitTimeSeconds": "20",
#  "RedrivePolicy": "{\"deadLetterTargetArn\": \"<dlq-arn>\",
#                     \"maxReceiveCount\": \"5\"}"}

aws sqs send-message --queue-url $Q --message-body '{"id": 42}'
aws sqs receive-message --queue-url $Q --max-number-of-messages 10
aws sqs delete-message --queue-url $Q --receipt-handle <handle>

T=$(aws sns create-topic --name order-events --query TopicArn --output text)
aws sns subscribe --topic-arn $T --protocol sqs --notification-endpoint $Q_ARN \
    --attributes file://sub-attrs.json   # filter policy: region = eu
aws sns publish --topic-arn $T --message '{"id": 42}' \
    --message-attributes '{"region":{"DataType":"String","StringValue":"eu"}}'
aws sqs start-message-move-task --source-arn $DLQ_ARN   # redrive back

Code Explained

After 5 failed receives a message moves to the DLQ
Delete with the receipt handle after successful processing
The SQS subscription only gets EU messages (filter policy)
start-message-move-task redrives DLQ messages to the source queue

Cost Check

  • Per million requests; first million each month free (SQS and SNS)
  • Long polling and batching (up to 10 messages) cut request counts
  • SNS to HTTP / SMS / email has delivery charges

Standard vs FIFO

ThroughputNearly unlimitedHigh with high-throughput mode
OrderingBest effortPer message group
DeliveryAt least onceExactly-once processing (dedup)

Do & Don't

  • Do Make consumers idempotent and delete only after success
  • Do Alarm on DLQ depth and oldest message age
  • Don’t Set visibility timeout shorter than processing time
  • Don’t Send large blobs in messages (store in S3, send a pointer)

Local Testing

  • LocalStack emulates SQS and SNS
  • ElasticMQ is a lightweight SQS-compatible server
  • moto mocks SQS / SNS in Python tests

Production Checklist

  • DLQs with alarms and a redrive process
  • Encryption (SSE-SQS / KMS) on queues and topics
  • Queue policies restricting senders
