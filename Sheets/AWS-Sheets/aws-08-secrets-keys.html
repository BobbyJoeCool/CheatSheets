Sheet 08

Secrets, Parameters & KMS

Secrets Manager · rotation · SSM Parameter Store SecureString · KMS keys · envelope encryption · aws kms encrypt

Protecting Secrets and Keys

Secrets Manager stores secrets with versioning and built-in rotation (RDS passwords, API keys via Lambda). SSM Parameter Store holds configuration and SecureString parameters, cheaper for simple needs. KMS manages encryption keys used by almost every AWS service; it never exposes the key material and uses envelope encryption for large data.

Key Points

  • Secrets Manager integrates with RDS, ECS, Lambda and EKS
  • Parameter Store standard tier is free; advanced tier adds size and policies
  • KMS key types: AWS owned, AWS managed (aws/s3), customer managed
  • Key policies control who can use and manage each KMS key

Security Check

  • Encrypt secrets with a customer managed KMS key where you need audit and control
  • Restrict secretsmanager:GetSecretValue to the workload role only
  • Enable automatic rotation for database credentials

Limits & Quotas

  • Secret value up to 64 KB
  • Parameter Store: 4 KB standard / 8 KB advanced per parameter
  • KMS request rates are throttled per Region (cache data keys)

Secrets, Parameters, KMS

aws secretsmanager create-secret --name prod/shop/db \
    --kms-key-id alias/shop --secret-string file://db.json
aws secretsmanager get-secret-value --secret-id prod/shop/db \
    --query SecretString --output text
aws secretsmanager rotate-secret --secret-id prod/shop/db \
    --rotation-rules AutomaticallyAfterDays=30

aws ssm put-parameter --name /shop/prod/feature-x --type String --value on
aws ssm put-parameter --name /shop/prod/api-key --type SecureString \
    --value file://key.txt --key-id alias/shop
aws ssm get-parameters-by-path --path /shop/prod --with-decryption

aws kms create-key --description "shop data key" --key-usage ENCRYPT_DECRYPT
aws kms create-alias --alias-name alias/shop --target-key-id <key-id>
aws kms generate-data-key --key-id alias/shop --key-spec AES_256
aws kms enable-key-rotation --key-id <key-id>

Code Explained

The secret is encrypted with the alias/shop customer managed key
Rotation uses a Lambda function (AWS provides templates for RDS)
Parameter paths group config by app and environment
generate-data-key returns a plaintext + encrypted data key for envelope encryption

Azure / GCP Equivalent

  • Azure Key Vault secrets, keys and references (az-08)
  • GCP Secret Manager and Cloud KMS (gcp-08)

Cost Check

  • Secrets Manager: per secret per month + per 10,000 API calls
  • KMS: per customer managed key per month + requests; AWS managed keys have no monthly fee
  • Cache secrets and data keys (AWS caching libraries) to cut calls

Do & Don't

  • Do Fetch secrets at startup with the workload role and cache them
  • Do Use customer managed keys for sensitive data
  • Don’t Store secrets in Lambda env vars or task definitions in plain text
  • Don’t Schedule KMS key deletion without checking what uses it

Local Testing

  • LocalStack emulates Secrets Manager, SSM and KMS
  • moto mocks them in Python tests
  • Use a gitignored .env locally; never real production secrets

Production Checklist

  • Rotation enabled for database credentials
  • KMS key rotation and deletion protection (waiting period) in place
  • CloudTrail alerts on GetSecretValue from unexpected roles
