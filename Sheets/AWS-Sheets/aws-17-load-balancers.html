Spreading Traffic Across Targets

Application Load Balancers (ALB) work at layer 7: HTTP / HTTPS routing by host, path, headers or query, with TLS termination, authentication and WAF. Network Load Balancers (NLB) work at layer 4 with static IPs, very high throughput and TLS passthrough. Both send traffic to target groups (instances, IPs, Lambda) checked by health checks.

Key Points

  • Listeners accept connections on a port; rules route to target groups
  • ALB can authenticate users with Cognito or any OIDC provider
  • Deregistration delay drains connections before removing targets
  • Gateway Load Balancer inserts third-party appliances

ALB With HTTPS and Path Routing

ALB=$(aws elbv2 create-load-balancer --name shop-alb --type application \
  --subnets $PUB_A $PUB_B --security-groups $ALB_SG \
  --query "LoadBalancers[0].LoadBalancerArn" --output text)
TG=$(aws elbv2 create-target-group --name shop-api --protocol HTTP \
  --port 8080 --vpc-id $VPC --target-type ip \
  --health-check-path /health --health-check-interval-seconds 15 \
  --query "TargetGroups[0].TargetGroupArn" --output text)

aws elbv2 create-listener --load-balancer-arn $ALB --protocol HTTPS \
    --port 443 --certificates CertificateArn=$CERT \
    --ssl-policy ELBSecurityPolicy-TLS13-1-2-2021-06 \
    --default-actions Type=forward,TargetGroupArn=$TG
aws elbv2 create-listener --load-balancer-arn $ALB --protocol HTTP --port 80 \
    --default-actions file://redirect-https.json        # 301 → HTTPS

aws elbv2 create-rule --listener-arn $HTTPS_LISTENER --priority 10 \
    --conditions Field=path-pattern,Values='/admin/*' \
    --actions Type=forward,TargetGroupArn=$ADMIN_TG
aws elbv2 describe-target-health --target-group-arn $TG

Code Explained

target-type ip suits Fargate and containers
The HTTPS listener uses an ACM certificate and a TLS 1.3 policy
Port 80 redirects to HTTPS
A path rule sends /admin/* to a separate target group

Cost Check

  • Hourly fee plus LCUs (ALB) / NLCUs (NLB) for traffic
  • One ALB can serve many apps via host / path rules
  • Cross-zone traffic for NLB can add data charges

Do & Don't

  • Do Redirect HTTP to HTTPS and use modern TLS policies
  • Do Spread across at least two AZs
  • Don’t Point health checks at a page that hits the database heavily
  • Don’t Create one ALB per microservice when rules can share one

Local Testing

  • Traefik or nginx in Docker Compose mimics host / path routing
  • LocalStack supports ELBv2 APIs for IaC tests
  • curl -H "Host: …" tests host rules before DNS

Production Checklist

  • HTTPS only, WAF attached, access logs to S3
  • Deletion protection on
  • Alarms on 5xx and unhealthy host count
