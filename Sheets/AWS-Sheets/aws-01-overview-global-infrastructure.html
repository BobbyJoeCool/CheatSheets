Amazon Web Services

AWS runs in 30+ Regions, each with three or more isolated Availability Zones (AZs) and hundreds of edge locations for CloudFront and Route 53. Most services are regional (EC2, S3 buckets, Lambda); a few are global (IAM, Route 53, CloudFront). Every resource is named by an ARN, and the account is the main security and billing boundary.

Key Points

  • Region codes: us-east-1, us-west-2, eu-west-1
  • AZ names (us-east-1a) map to different buildings per account; AZ IDs (use1-az1) are fixed
  • Some Regions are opt-in and must be enabled first
  • Shared responsibility: AWS secures the cloud, you secure what you put in it

Explore Regions, AZs and ARNs

aws sts get-caller-identity                   # account and principal
aws ec2 describe-regions --query "Regions[].RegionName" --output text
aws ec2 describe-availability-zones --region us-east-1 \
    --query "AvailabilityZones[].[ZoneName,ZoneId]" --output table
aws account list-regions --region-opt-status-contains ENABLED_BY_DEFAULT

# ARN format: arn:partition:service:region:account-id:resource
# arn:aws:s3:::acme-logs                      (S3: no region / account)
# arn:aws:lambda:us-east-1:111122223333:function:resize
# arn:aws:iam::111122223333:role/app-role     (IAM: global, no region)

aws resourcegroupstaggingapi get-resources \
    --tag-filters Key=env,Values=prod \
    --query "ResourceTagMappingList[].ResourceARN"

Code Explained

get-caller-identity shows who and where you are
Zone IDs let you line up AZs across accounts
ARNs leave out region or account when a service is global
The tagging API lists resources across many services by tag

Azure / GCP Equivalent

  • Azure regions, zones, region pairs, resource groups (az-01)
  • GCP regions, zones, global VPCs, projects (gcp-01)
  • AWS uses the account where Azure uses subscription + resource group

Cost Check

  • Free Tier: credits for new accounts plus always-free allowances (Lambda requests, DynamoDB storage)
  • Prices vary by Region; us-east-1 is often cheapest
  • Inter-AZ and inter-Region data transfer is billed per GB

Do & Don't

  • Do Pick a home Region and keep resources there unless there is a reason
  • Do Tag everything (owner, env, app)
  • Don’t Use the root user for anything but account-level tasks
  • Don’t Forget global services when cleaning up a Region

Local Testing

  • CloudShell has the CLI preinstalled and authenticated
  • LocalStack emulates many AWS APIs locally for development
  • A new account with a budget alert is a safe sandbox

Production Checklist

  • Multi-AZ by default for production services
  • Separate accounts per environment (Organizations)
  • Tag policy and cost allocation tags enabled
