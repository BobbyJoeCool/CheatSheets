Private Networking on AWS

A VPC is a regional private network with one or more IPv4 CIDR blocks (and optional IPv6). Each subnet lives in one AZ. A subnet is public when its route table sends 0.0.0.0/0 to an Internet Gateway; private subnets reach the internet through a NAT gateway (sheet 11) or not at all. Every Region has a default VPC for quick tests; build your own for real work.

Key Points

  • AWS reserves 5 addresses in each subnet
  • Use at least two AZs (three for production)
  • Public IPv4 addresses are billed hourly; consider IPv6 or private designs
  • VPC Flow Logs capture accepted / rejected traffic

Security Check

  • Keep databases and app servers in private subnets
  • Disable auto-assign public IP on private subnets
  • Enable VPC Flow Logs

Limits & Quotas

  • 5 VPCs per Region by default (adjustable)
  • 200 subnets per VPC
  • 5 IPv4 CIDR blocks per VPC by default (up to 50)

VPC, Subnets, Internet Route

VPC=$(aws ec2 create-vpc --cidr-block 10.30.0.0/16 \
  --tag-specifications 'ResourceType=vpc,Tags=[{Key=Name,Value=shop-prod}]' \
  --query Vpc.VpcId --output text)
PUB_A=$(aws ec2 create-subnet --vpc-id $VPC --cidr-block 10.30.0.0/24 \
  --availability-zone us-east-1a --query Subnet.SubnetId --output text)
APP_A=$(aws ec2 create-subnet --vpc-id $VPC --cidr-block 10.30.10.0/24 \
  --availability-zone us-east-1a --query Subnet.SubnetId --output text)

IGW=$(aws ec2 create-internet-gateway \
  --query InternetGateway.InternetGatewayId \
  --output text)
aws ec2 attach-internet-gateway --vpc-id $VPC --internet-gateway-id $IGW
RT=$(aws ec2 create-route-table --vpc-id $VPC --query RouteTable.RouteTableId \
  --output text)
aws ec2 create-route --route-table-id $RT --destination-cidr-block 0.0.0.0/0 \
    --gateway-id $IGW
aws ec2 associate-route-table --route-table-id $RT --subnet-id $PUB_A

aws ec2 create-flow-logs --resource-type VPC --resource-ids $VPC \
    --traffic-type ALL --log-destination-type cloud-watch-logs \
    --log-group-name /vpc/shop-prod --deliver-logs-permission-arn <role-arn>

Code Explained

Each subnet is pinned to one AZ
Only the public subnet's route table points at the Internet Gateway
Private subnets keep the main route table (local only) until NAT is added
Flow logs go to CloudWatch Logs through an IAM role

Azure / GCP Equivalent

  • Azure VNet with zone-spanning subnets (az-10)
  • GCP global VPC with regional subnets (gcp-10)
  • AWS subnets are per-AZ; Azure and GCP subnets span zones

Cost Check

  • VPCs, subnets and route tables are free
  • Public IPv4 addresses bill hourly, even on running instances
  • Cross-AZ traffic bills per GB in each direction

Do & Don't

  • Do Plan CIDRs that never overlap with other VPCs or on-premises
  • Do Build VPCs with IaC (VPC module / CDK construct)
  • Don’t Run production in the default VPC
  • Don’t Make every subnet public "to keep it simple"

Local Testing

  • Reachability Analyzer explains why traffic can or cannot flow
  • Docker networks mimic tiers locally
  • LocalStack supports EC2 / VPC API calls for IaC tests

Production Checklist

  • Three AZs, public / private / data tiers
  • Flow logs enabled and retained
  • No public IPs on private tiers
