Caches and Purpose-Built Databases

ElastiCache runs Valkey (recommended, lower cost), Redis OSS or Memcached, as node-based clusters or Serverless. DocumentDB is MongoDB-compatible, OpenSearch Service handles search and log analytics (including vector search), Neptune is a graph database, Timestream stores time series, and MemoryDB is a durable Valkey / Redis-compatible primary database.

Key Points

  • Cache-aside: read cache, fall back to the database, then populate
  • ElastiCache Serverless scales automatically with no node sizing
  • OpenSearch Serverless removes cluster management
  • Keep caches in private subnets with TLS and auth

Valkey Serverless Cache

aws elasticache create-serverless-cache --serverless-cache-name shop-cache \
    --engine valkey --subnet-ids $DATA_A $DATA_B \
    --security-group-ids $CACHE_SG
aws elasticache describe-serverless-caches \
    --query "ServerlessCaches[].Endpoint" --output table

aws opensearchserverless create-collection --name shop-search --type SEARCH

Cache-Aside in Python

import json, redis
r = redis.Redis(host="shop-cache-abc.serverless.use1.cache.amazonaws.com",
                port=6379, ssl=True)

def get_product(pid):
    if (hit := r.get(f"product:{pid}")):
        return json.loads(hit)
    row = db_fetch_product(pid)                 # slow path
    r.set(f"product:{pid}", json.dumps(row), ex=300)
    return row

Code Explained

Serverless caches need only subnets and security groups
Valkey is wire-compatible with Redis clients
An OpenSearch Serverless collection still needs encryption / network / access policies
Entries expire after 300 seconds

  • Valkey pricing is lower than Redis OSS on ElastiCache
  • Serverless caches bill per GB stored + processing units
  • OpenSearch bills instances / OCUs plus storage

Do & Don't

  • Do Set TTLs on every cache key
  • Do Choose Valkey for new caches
  • Don’t Treat a cache as the source of truth
  • Don’t Pick a niche database before checking if PostgreSQL fits

Local Testing

  • Run Valkey / Redis in Docker: docker run -p 6379:6379 valkey/valkey
  • OpenSearch and MongoDB containers for local search / document tests
  • Mock the cache layer in unit tests

Production Checklist

  • Encryption in transit + at rest, auth enabled
  • Multi-AZ / replicas for caches that matter
  • Hit-rate, memory and eviction alarms
