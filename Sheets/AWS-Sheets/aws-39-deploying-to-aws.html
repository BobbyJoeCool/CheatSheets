Deploying to AWS

GitHub Actions + configure-aws-credentials (OIDC) · CodeBuild / CodePipeline · blue/green & canary · CodeDeploy · tagging strategy

CI/CD Into AWS

Pipelines should assume an IAM role through OIDC: GitHub Actions uses aws-actions/configure-aws-credentials with a role whose trust policy pins the repo and environment. Build images and push to ECR, then deploy with CloudFormation / CDK / SAM / Terraform or service commands. CodeDeploy runs blue/green and canary rollouts for ECS, Lambda and EC2.

Key Points

  • No access keys in CI secrets
  • Separate deploy roles per environment and account
  • CodePipeline / CodeBuild are AWS-native alternatives to GitHub Actions
  • Tag resources with repo, commit and owner

GitHub Actions: Build, Push, Deploy to ECS

on: { push: { branches: [main] } }
permissions: { id-token: write, contents: read }
jobs:
  deploy:
    runs-on: ubuntu-latest
    environment: production
    steps:
      - uses: actions/checkout@v4
      - uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::111122223333:role/gh-deploy-prod
          aws-region: us-east-1
      - uses: aws-actions/amazon-ecr-login@v2
        id: ecr
      - run: |
          IMG=${{ steps.ecr.outputs.registry }}/shop-api:${{ github.sha }}
          docker build -t $IMG . && docker push $IMG
          echo "IMG=$IMG" >> $GITHUB_ENV
      - run: |
          aws ecs describe-task-definition --task-definition shop-api \
            --query taskDefinition > td.json
      - uses: aws-actions/amazon-ecs-render-task-definition@v1
        id: td
        with:
          task-definition: td.json
          container-name: api
          image: ${{ env.IMG }}
      - uses: aws-actions/amazon-ecs-deploy-task-definition@v2
        with: { task-definition: "${{ steps.td.outputs.task-definition }}",
                service: api, cluster: shop, wait-for-service-stability: true }

Code Explained

id-token: write lets the job request the OIDC token
The role is assumed with no stored secret
The image tag is the commit SHA for traceability
Render + deploy updates the ECS service and waits for stability

Azure / GCP Equivalent

  • Azure azure/login OIDC, Azure Pipelines, slot swaps (az-39)
  • GCP google-github-actions/auth WIF, Cloud Build, Cloud Deploy (gcp-39)

Cost Check

  • GitHub-hosted runner minutes / CodeBuild per build-minute
  • CodeDeploy is free for ECS / Lambda / EC2 (on-premises costs extra)
  • Blue/green briefly runs double capacity

Security Check

  • Trust policy sub pinned to repo:org/app:environment:production
  • Deploy role scoped to the services and resources it changes
  • Pin third-party actions to a commit SHA

Do & Don't

  • Do Require environment approvals for production
  • Do Wait for service stability and fail the job on rollback
  • Don’t Store AWS keys in GitHub secrets
  • Don’t Use the same role for every environment

Local Testing

  • act runs workflows locally (OIDC needs real GitHub)
  • actionlint validates workflow files
  • Run the same CLI steps from a laptop against dev first

Production Checklist

  • OIDC role per environment with least privilege
  • Approval gates and deployment alarms with auto-rollback
  • Every deploy traceable to a commit (tags, image SHA)
