EBS, EFS & AWS Backup

EBS volume types (gp3, io2) · snapshots · EFS shared file systems · S3 vs EBS vs EFS · AWS Backup plans

Block, File and Backup

EBS volumes are block storage attached to one instance in one AZ (multi-attach for some io2 cases). EFS is an elastic NFS file system many instances, containers and Lambdas can mount across AZs. FSx offers Windows, Lustre, NetApp ONTAP and OpenZFS file systems. AWS Backup centralizes backup plans across EBS, EFS, RDS, DynamoDB, S3 and more.

Key Points

  • EBS snapshots are incremental and can be copied across Regions
  • EFS storage classes (Standard, IA, Archive) with lifecycle management
  • EFS access points enforce a path and POSIX user per app
  • Backup vault lock makes backups immutable

EFS Mount and Backup Plan

FS=$(aws efs create-file-system --encrypted --throughput-mode elastic \
  --tags Key=Name,Value=shared --query FileSystemId --output text)
aws efs create-mount-target --file-system-id $FS --subnet-id $APP_A \
    --security-groups $EFS_SG
aws efs put-lifecycle-configuration --file-system-id $FS \
    --lifecycle-policies TransitionToIA=AFTER_30_DAYS
sudo mount -t efs -o tls $FS:/ /mnt/shared        # amazon-efs-utils

aws backup create-backup-vault --backup-vault-name prod-vault
aws backup create-backup-plan --backup-plan '{"BackupPlanName":"daily",
  "Rules":[{"RuleName":"daily","TargetBackupVaultName":"prod-vault",
    "ScheduleExpression":"cron(0 5 * * ? *)",
    "Lifecycle":{"DeleteAfterDays":35}}]}'
aws backup create-backup-selection --backup-plan-id <plan-id> \
    --backup-selection '{"SelectionName":"tagged","IamRoleArn":"<role-arn>",
      "ListOfTags":[{"ConditionType":"STRINGEQUALS",
        "ConditionKey":"backup","ConditionValue":"daily"}]}'

Code Explained

Elastic throughput scales with demand automatically
One mount target per AZ lets instances mount locally
The EFS mount helper encrypts traffic in transit with tls
Backup selects resources by tag, so new resources join automatically

Azure / GCP Equivalent

  • Azure managed disks, Azure Files, Azure Backup (az-30)
  • GCP Persistent Disk / Hyperdisk, Filestore, Backup and DR (gcp-30)

Cost Check

  • EBS bills provisioned GB (and IOPS / throughput above gp3 baseline)
  • EFS bills stored GB by class plus elastic throughput
  • Backup bills per GB stored in vaults

Do & Don't

  • Do Back up by tag with AWS Backup
  • Do Use EFS access points per application
  • Don’t Use EFS for database data files
  • Don’t Keep snapshots forever without lifecycle

Local Testing

  • Practice NFS mounts with a local NFS server container
  • Restore drills from AWS Backup into a scratch account
  • fio benchmarks EBS settings on a test instance

Production Checklist

  • Backup plans with vault lock for critical data
  • Cross-Region / cross-account backup copies
  • Restores tested regularly
