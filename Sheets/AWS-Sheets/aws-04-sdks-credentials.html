Sheet 04

SDKs & Credentials

credential provider chain · ~/.aws/config & credentials · AWS_PROFILE env vars · boto3 Session / client · JS SDK v3 clients · roles over access keys

Authenticating Code

AWS SDKs look for credentials in a provider chain: environment variables, the shared config / SSO profile, web identity tokens (EKS, CI), the container credentials endpoint (ECS), then the EC2 instance metadata service. The same code uses your SSO profile on a laptop and the attached IAM role in AWS. Create clients once and reuse them.

Key Points

  • Python: pip install boto3; JavaScript: @aws-sdk/client-s3 (modular v3)
  • Region comes from AWS_REGION, the profile or the client argument
  • Retries with backoff are built in; tune with retries config
  • Never hard-code keys in code or images

Security Check

  • Use IAM roles for compute; no access keys on servers or in containers
  • Require IMDSv2 so SSRF bugs cannot steal instance credentials
  • Rotate or remove any remaining access keys (alert on keys older than 90 days)

Python (boto3)

import boto3
s3 = boto3.client("s3")                     # default chain + Region
for b in s3.list_buckets()["Buckets"]:
    print(b["Name"])

dev = boto3.Session(profile_name="shop-dev", region_name="us-east-1")
ddb = dev.resource("dynamodb").Table("orders")
ddb.put_item(Item={"pk": "o#42", "total": 59})

sts = boto3.client("sts")                   # assume another role
creds = sts.assume_role(RoleArn="arn:aws:iam::222233334444:role/reader",
                        RoleSessionName="report")["Credentials"]

JavaScript SDK v3

import { S3Client, ListObjectsV2Command } from "@aws-sdk/client-s3";
const s3 = new S3Client({ region: "us-east-1" });   // default chain
const out = await s3.send(new ListObjectsV2Command({ Bucket: "acme-logs" }));
console.log(out.Contents?.map(o => o.Key));

Code Explained

boto3.client finds credentials and Region automatically
A Session pins a profile for multi-account scripts
assume_role returns temporary keys for another account
JS v3 imports one client per service and sends command objects

Azure / GCP Equivalent

  • Azure DefaultAzureCredential, managed identity (az-04)
  • GCP Application Default Credentials, service accounts (gcp-04)

Cost Check

  • SDKs are free; you pay for the API calls they make
  • STS calls are free
  • Reusing clients and connections cuts latency and request overhead

Do & Don't

  • Do Create SDK clients once per process
  • Do Let roles provide credentials everywhere in AWS
  • Don’t Put access keys in environment variables on servers
  • Don’t Disable SSL verification to "fix" endpoint errors

Local Testing

  • SSO profiles feed the same default chain on your laptop
  • LocalStack: set endpoint_url="http://localhost:4566" in the client
  • moto mocks AWS APIs inside Python unit tests

Production Checklist

  • Zero long-lived access keys for workloads
  • IMDSv2 required on all instances
  • Least-privilege roles per workload
