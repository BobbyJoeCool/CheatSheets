CloudFront & ACM

distributions · origins & behaviors · Origin Access Control · cache policies & TTLs · invalidations · ACM certificates (us-east-1)

CDN and Certificates

CloudFront caches content at hundreds of edge locations in front of origins (S3, ALB, API Gateway, any HTTP server). Behaviors map path patterns to origins and cache / origin-request policies. Origin Access Control (OAC) lets only CloudFront read a private S3 bucket. ACM issues free, auto-renewing TLS certificates; CloudFront certificates must be in us-east-1.

Key Points

  • Managed cache policies (CachingOptimized, CachingDisabled) cover common cases
  • CloudFront Functions run lightweight JS at the edge; Lambda@Edge for heavier logic
  • Invalidations are free for the first 1,000 paths per month
  • Price classes limit edge locations to cut cost

Security Check

  • Keep the S3 origin private with OAC and Block Public Access
  • Redirect HTTP to HTTPS and use a modern TLS security policy
  • Attach AWS WAF to public distributions

Certificate, Distribution, Invalidation

aws acm request-certificate --region us-east-1 \
    --domain-name shop.acme-shop.com --validation-method DNS
aws acm describe-certificate --region us-east-1 --certificate-arn <arn> \
    --query "Certificate.DomainValidationOptions[].ResourceRecord"

aws cloudfront create-origin-access-control \
    --origin-access-control-config file://oac.json   # sigv4, always, s3
aws cloudfront create-distribution --distribution-config file://dist.json

aws s3 sync ./dist s3://acme-site --delete \
    --cache-control "public,max-age=31536000,immutable" --exclude index.html
aws s3 cp ./dist/index.html s3://acme-site/ --cache-control "no-cache"
aws cloudfront create-invalidation --distribution-id E1ABCDEF \
    --paths /index.html

Code Explained

The DNS validation record proves you own the domain; ACM renews automatically
OAC signs CloudFront's requests to S3
Hashed assets get a one-year cache; index.html revalidates
Only index.html needs invalidating after a deploy

Do & Don't

  • Do Use versioned asset names and long TTLs
  • Do Request ACM certificates in us-east-1 for CloudFront
  • Don’t Leave the S3 bucket public behind CloudFront
  • Don’t Invalidate /* on every deploy

Local Testing

  • npx serve dist previews the site
  • curl -I shows x-cache: Hit from cloudfront once deployed
  • Test CloudFront Functions in the console test tool

Production Checklist

  • OAC + Block Public Access on the origin bucket
  • WAF attached; HTTPS-only with TLSv1.2_2021 or newer
  • Standard logs or real-time logs enabled
