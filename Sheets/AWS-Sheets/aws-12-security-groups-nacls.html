Sheet 12

Security Groups & NACLs

stateful security groups · SG-to-SG references · stateless NACLs · inbound / outbound rules · ephemeral ports · VPC Flow Logs

Filtering Traffic

Security groups are stateful firewalls attached to ENIs (instances, load balancers, RDS, Lambda in a VPC). They only allow; replies are automatic. Rules can reference other security groups, so "the app tier may reach the database" needs no IPs. Network ACLs are stateless allow / deny lists on subnets, evaluated in rule-number order, and must allow return traffic on ephemeral ports.

Key Points

  • New security groups deny all inbound and allow all outbound
  • SG references follow instances as they scale
  • NACLs are a coarse second layer; most designs leave the default allow-all NACL
  • Flow Logs show ACCEPT / REJECT decisions

Security Check

  • Never allow 22 / 3389 from 0.0.0.0/0; use Session Manager
  • Restrict outbound on data-tier security groups
  • Alert on security group changes that open ports to the world

Limits & Quotas

  • 60 inbound and 60 outbound rules per security group (adjustable)
  • 5 security groups per network interface (up to 16)
  • 20 rules per NACL direction by default

Tiered Security Groups

ALB_SG=$(aws ec2 create-security-group --vpc-id $VPC --group-name alb \
  --description "public ALB" --query GroupId --output text)
APP_SG=$(aws ec2 create-security-group --vpc-id $VPC --group-name app \
  --description "app tier" --query GroupId --output text)
DB_SG=$(aws ec2 create-security-group --vpc-id $VPC --group-name db \
  --description "database" --query GroupId --output text)

aws ec2 authorize-security-group-ingress --group-id $ALB_SG \
    --protocol tcp --port 443 --cidr 0.0.0.0/0
aws ec2 authorize-security-group-ingress --group-id $APP_SG \
    --protocol tcp --port 8080 --source-group $ALB_SG
aws ec2 authorize-security-group-ingress --group-id $DB_SG \
    --protocol tcp --port 5432 --source-group $APP_SG
aws ec2 revoke-security-group-egress --group-id $DB_SG \
    --ip-permissions '[{"IpProtocol":"-1","IpRanges":[{"CidrIp":"0.0.0.0/0"}]}]'

aws ec2 describe-security-group-rules \
    --filters Name=group-id,Values=$APP_SG --output table

Code Explained

Only the ALB is open to the internet
The app tier accepts traffic only from the ALB's group
The database accepts only the app tier on 5432
Removing default egress stops the database from calling out

Cost Check

  • Flow Logs bill for log ingestion / storage
  • AWS Network Firewall (central inspection) bills hourly + per GB

Do & Don't

  • Do Reference security groups instead of IP ranges inside the VPC
  • Do Name and describe every group clearly
  • Don’t Open 0.0.0.0/0 on anything but public load balancers
  • Don’t Add deny rules to NACLs without allowing ephemeral return ports

Local Testing

  • Reachability Analyzer shows which rule blocks a path
  • Flow Logs + Logs Insights find rejected connections
  • nc -zv host port from inside the VPC tests rules

Production Checklist

  • No admin ports open to the internet
  • Data-tier egress restricted
  • Config rule / Security Hub control for open security groups
