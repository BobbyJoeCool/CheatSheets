RDS & Aurora

engines · Multi-AZ · read replicas · snapshots & PITR · parameter groups · RDS Proxy · Aurora Serverless v2

Managed Relational Databases

Amazon RDS runs PostgreSQL, MySQL, MariaDB, SQL Server, Oracle and Db2 with automated backups, patching and Multi-AZ failover. Aurora is AWS's cloud-native PostgreSQL / MySQL with storage replicated across three AZs, fast replicas and Serverless v2 autoscaling. RDS Proxy pools connections for Lambda and spiky apps.

Key Points

  • Multi-AZ DB clusters (two readable standbys) are an option for MySQL / PostgreSQL
  • Point-in-time restore creates a new instance
  • Parameter groups hold engine settings
  • IAM database authentication avoids passwords for apps

Security Check

  • No public accessibility; private subnets only
  • Store master password in Secrets Manager (--manage-master-user-password)
  • Encryption at rest with KMS; enforce TLS (rds.force_ssl)

Limits & Quotas

  • Backup retention 1–35 days for PITR
  • Storage up to 64 TiB (most RDS engines); Aurora up to 128 TiB
  • 40 DB instances per Region by default

RDS PostgreSQL and Aurora Serverless v2

aws rds create-db-subnet-group --db-subnet-group-name shop-db \
    --db-subnet-group-description shop --subnet-ids $DATA_A $DATA_B $DATA_C
aws rds create-db-instance --db-instance-identifier shop-pg \
    --engine postgres --engine-version 17 --db-instance-class db.m7g.large \
    --allocated-storage 100 --storage-type gp3 --multi-az \
    --master-username app --manage-master-user-password \
    --db-subnet-group-name shop-db --vpc-security-group-ids $DB_SG \
    --no-publicly-accessible --storage-encrypted --backup-retention-period 14 \
    --enable-iam-database-authentication --deletion-protection

aws rds create-db-cluster --db-cluster-identifier shop-aurora \
    --engine aurora-postgresql --serverless-v2-scaling-configuration \
    MinCapacity=0.5,MaxCapacity=16 --master-username app \
    --manage-master-user-password --db-subnet-group-name shop-db
aws rds create-db-instance --db-instance-identifier shop-aurora-1 \
    --db-cluster-identifier shop-aurora --engine aurora-postgresql \
    --db-instance-class db.serverless

aws rds restore-db-instance-to-point-in-time \
    --source-db-instance-identifier shop-pg \
    --target-db-instance-identifier shop-pg-restore \
    --restore-time 2026-11-12T08:00:00Z

Code Explained

Subnet groups place the database in private data subnets
Multi-AZ keeps a synchronous standby in another AZ
Aurora Serverless v2 scales between 0.5 and 16 ACUs
PITR restores into a new instance you can inspect

Azure / GCP Equivalent

  • Azure Azure SQL, PostgreSQL Flexible Server (az-31)
  • GCP Cloud SQL, AlloyDB (gcp-31)

Cost Check

  • Instance hours + storage + I/O (Aurora Standard) or Aurora I/O-Optimized
  • Multi-AZ roughly doubles instance cost
  • Reserved Instances discount steady databases; Graviton classes cost less

Do & Don't

  • Do Turn on deletion protection and Multi-AZ for production
  • Do Use RDS Proxy with Lambda
  • Don’t Expose databases publicly
  • Don’t Change parameter groups in production without a test

Local Testing

  • Run the same engine version in Docker
  • Testcontainers for integration tests
  • Restore a snapshot to a scratch instance for realistic testing

Production Checklist

  • Multi-AZ, encryption, deletion protection
  • Performance Insights / Database Insights and alarms
  • Restore tested; backup retention per compliance
