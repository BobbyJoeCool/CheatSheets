IAM Policies

Writing Permissions

An IAM policy is a JSON document of statements with Effect (Allow / Deny), Action (s3:GetObject), Resource (ARNs) and optional Condition (IP, tags, MFA, time). Identity policies attach to users, groups and roles; resource policies attach to buckets, queues, keys and more. Requests are denied by default, allowed by any Allow, and blocked by any explicit Deny.

Key Points

  • AWS managed policies are broad; customer managed policies fit your needs
  • Permission boundaries cap what a role can ever be granted
  • SCPs (Organizations) cap entire accounts
  • Use tags in conditions for attribute-based access control (ABAC)

Limits & Quotas

  • Managed policy up to 6,144 characters
  • 10 managed policies per role by default (can raise)
  • Role trust policy up to 2,048 characters by default

A Least-Privilege Policy

{ "Version": "2012-10-17",
  "Statement": [
    { "Sid": "ReadUploads",
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:PutObject"],
      "Resource": "arn:aws:s3:::acme-uploads/user/${aws:PrincipalTag/uid}/*" },
    { "Sid": "TeamTables",
      "Effect": "Allow",
      "Action": ["dynamodb:GetItem", "dynamodb:Query", "dynamodb:PutItem"],
      "Resource": "arn:aws:dynamodb:us-east-1:111122223333:table/*",
      "Condition": { "StringEquals":
        { "aws:ResourceTag/team": "${aws:PrincipalTag/team}" } } },
    { "Sid": "DenyNonTLS",
      "Effect": "Deny", "Action": "s3:*", "Resource": "*",
      "Condition": { "Bool": { "aws:SecureTransport": "false" } } } ] }

Create, Attach, Test

aws iam create-policy --policy-name app-data --policy-document file://p.json
aws iam attach-role-policy --role-name app --policy-arn <policy-arn>
aws iam simulate-principal-policy --policy-source-arn <role-arn> \
    --action-names s3:GetObject --resource-arns arn:aws:s3:::acme-uploads/x
aws accessanalyzer validate-policy --policy-type IDENTITY_POLICY \
    --policy-document file://p.json

Code Explained

Policy variables scope S3 paths to the caller's tag
The tag condition lets teams touch only their own tables (ABAC)
The explicit Deny blocks non-TLS requests even if allowed elsewhere
Simulate and validate before attaching to production roles

Azure / GCP Equivalent

  • Azure Azure RBAC role definitions and assignments (az-06)
  • GCP IAM allow / deny policies and conditions (gcp-06)
  • AWS evaluates policy documents; Azure and GCP evaluate role bindings

Cost Check

  • Policies are free
  • Overly broad * grants let mistakes create expensive resources
  • SCPs can deny expensive services or Regions organization-wide

Do & Don't

  • Do Start from AWS managed policies, then narrow with Access Analyzer policy generation
  • Do Use conditions (tags, VPC endpoints, TLS)
  • Don’t Use "Action": "*" with "Resource": "*" for apps
  • Don’t Write inline policies you cannot reuse or audit

Local Testing

  • aws accessanalyzer validate-policy lints offline-authored policies
  • Policy Simulator tests before deploy
  • cfn-lint / Checkov catch broad IAM in templates

Production Checklist

  • Least-privilege customer managed policies
  • Permission boundaries for roles developers create
  • Access Analyzer external and unused access findings reviewed
