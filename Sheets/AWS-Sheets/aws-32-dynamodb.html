DynamoDB

partition & sort keys · PutItem / GetItem / Query / Scan · GSIs & LSIs · on-demand vs provisioned · TTL · Streams

Serverless Key-Value and Document Database

DynamoDB stores items in tables keyed by a partition key (and optional sort key). Access is by key: GetItem, Query within a partition, or Scan (expensive). Global secondary indexes add alternate access patterns. Capacity is on-demand (pay per request) or provisioned with autoscaling. TTL expires items; Streams feed changes to Lambda.

Key Points

  • Design tables around access patterns first (single-table design is common)
  • Strongly consistent reads cost 2× eventually consistent ones
  • Global tables replicate across Regions (multi-active)
  • PartiQL offers SQL-like syntax

Security Check

  • Least-privilege IAM with dynamodb:LeadingKeys conditions for per-user data
  • Point-in-time recovery and deletion protection on
  • VPC gateway endpoint for private access

Limits & Quotas

  • Item size up to 400 KB
  • Per-partition throughput about 3,000 RCU / 1,000 WCU
  • 20 global secondary indexes per table by default

Table, Items, Queries

aws dynamodb create-table --table-name orders \
    --attribute-definitions AttributeName=pk,AttributeType=S \
      AttributeName=sk,AttributeType=S AttributeName=status,AttributeType=S \
    --key-schema AttributeName=pk,KeyType=HASH AttributeName=sk,KeyType=RANGE \
    --global-secondary-indexes file://gsi-by-status.json \
    --billing-mode PAY_PER_REQUEST --deletion-protection-enabled
aws dynamodb update-time-to-live --table-name orders \
    --time-to-live-specification Enabled=true,AttributeName=expires
aws dynamodb update-continuous-backups --table-name orders \
    --point-in-time-recovery-specification PointInTimeRecoveryEnabled=true

Python (boto3 resource)

import boto3
from boto3.dynamodb.conditions import Key
t = boto3.resource("dynamodb").Table("orders")
t.put_item(Item={"pk": "CUST#7", "sk": "ORDER#2026-11-12#42",
                 "status": "PAID", "total": 59})
t.get_item(Key={"pk": "CUST#7", "sk": "ORDER#2026-11-12#42"})
recent = t.query(KeyConditionExpression=Key("pk").eq("CUST#7")
                 & Key("sk").begins_with("ORDER#2026-11"))["Items"]
paid = t.query(IndexName="by-status",
               KeyConditionExpression=Key("status").eq("PAID"))["Items"]

Code Explained

Composite keys group a customer's orders in one partition
The GSI supports "orders by status"
TTL deletes items after the expires epoch time
query with begins_with reads one customer's month efficiently

Azure / GCP Equivalent

  • Azure Cosmos DB: partition keys, RUs, consistency levels (az-32)
  • GCP Firestore, Bigtable, Spanner (gcp-32)

Cost Check

  • On-demand: per million read / write request units; provisioned: per RCU / WCU-hour
  • Storage per GB-month; GSIs store and bill their own copies
  • Scans read (and bill) every item they touch

Operations

OperationUse
GetItemOne item by full key
QueryItems in one partition, sort-key range
ScanWhole table (avoid on hot paths)
BatchGet / BatchWriteUp to 100 / 25 items
TransactWriteItemsAll-or-nothing writes
UpdateItemConditional updates, counters

Capacity Modes

ModeBest For
On-demandUnknown / spiky traffic
Provisioned + autoscalingSteady, predictable traffic
Reserved capacityLarge steady provisioned use

Do & Don't

  • Do Model access patterns before creating tables
  • Do Use condition expressions for safe concurrent updates
  • Don’t Scan in request paths
  • Don’t Use low-cardinality partition keys (hot partitions)

Local Testing

  • DynamoDB Local runs in Docker (amazon/dynamodb-local)
  • NoSQL Workbench models tables and generates code
  • moto mocks DynamoDB in tests

Production Checklist

  • PITR, deletion protection, encryption with a customer managed key if required
  • Alarms on throttled requests and errors
  • Global tables if multi-Region active is needed
