Sheet 19

Choosing Compute

EC2 vs Lambda vs ECS / Fargate vs EKS · App Runner · Elastic Beanstalk · Lightsail · decision table

Picking the Right AWS Host

AWS has a host at every level of control. Lambda runs functions on events. ECS on Fargate runs containers without servers; App Runner deploys a container or repo as a web service with almost no configuration. EKS gives Kubernetes. EC2 gives full control. Elastic Beanstalk and Lightsail are simpler packaged options.

Key Points

  • Fargate removes node management for ECS and EKS
  • Lambda scales to zero; ECS / EKS services usually do not
  • App Runner suits small HTTP services with low ops needs
  • AWS Batch runs batch jobs on EC2 or Fargate

One Container, Several Hosts

IMG=111122223333.dkr.ecr.us-east-1.amazonaws.com/shop-api:1.4.0

# App Runner: container to HTTPS URL (config in a JSON file)
aws apprunner create-service --service-name shop-api \
    --source-configuration file://apprunner.json
# apprunner.json: {"ImageRepository": {"ImageIdentifier": "<IMG>",
#   "ImageRepositoryType": "ECR", "ImageConfiguration": {"Port": "8080"}},
#   "AuthenticationConfiguration": {"AccessRoleArn": "<ecr-access-role>"}}

# ECS on Fargate (sheet 26)
aws ecs create-service --cluster shop --service-name api \
    --task-definition shop-api:7 --desired-count 2 --launch-type FARGATE \
    --network-configuration "awsvpcConfiguration={subnets=[$APP_A],\
securityGroups=[$APP_SG]}"

# Lambda from a container image (sheet 21)
aws lambda create-function --function-name shop-api --package-type Image \
    --code ImageUri=$IMG --role $LAMBDA_ROLE

Code Explained

App Runner needs a role that can pull from ECR
ECS services keep a desired number of Fargate tasks running
Lambda can run container images up to 10 GB
The same image can target several services

Cost Check

  • Lambda: per request + GB-second, free tier each month
  • Fargate: per vCPU-hour and GB-hour while tasks run
  • EC2 / EKS nodes bill while running; EKS adds a cluster-hour fee

Do & Don't

  • Do Default to Lambda or Fargate for new services
  • Do Containerize to keep options open
  • Don’t Choose EKS for a single small service
  • Don’t Run long CPU-heavy jobs on Lambda

Local Testing

  • SAM CLI for Lambda, Docker Compose for containers, kind for Kubernetes
  • AWS Copilot CLI scaffolds ECS services
  • Compare costs in the Pricing Calculator

Production Checklist

  • Host choice documented with expected cost and limits
  • Autoscaling and health checks on the chosen service
  • Same image promoted across environments
