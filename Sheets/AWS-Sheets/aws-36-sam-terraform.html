Serverless Templates and Terraform

The AWS Serverless Application Model (SAM) extends CloudFormation with short resource types (AWS::Serverless::Function, Api, SimpleTable) and a CLI that builds, runs locally and deploys. Terraform with the AWS provider is the common multi-cloud choice; state goes in S3 with native locking (lock files).

Key Points

  • sam deploy --guided saves settings in samconfig.toml
  • sam sync --watch pushes code changes in seconds during development
  • Terraform S3 backend supports use_lockfile = true (DynamoDB locking is legacy)
  • Use OIDC roles for Terraform in CI

template.yaml (SAM)

Transform: AWS::Serverless-2016-10-31
Globals:
  Function: { Runtime: python3.13, Architectures: [arm64], Timeout: 10 }
Resources:
  OrdersFn:
    Type: AWS::Serverless::Function
    Properties:
      Handler: app.handler
      CodeUri: src/
      Policies: [{ DynamoDBCrudPolicy: { TableName: !Ref Orders } }]
      Events:
        Api: { Type: HttpApi, Properties: { Path: /orders, Method: post } }
  Orders:
    Type: AWS::Serverless::SimpleTable

Terraform

terraform {
  required_providers { aws = { source = "hashicorp/aws", version = "~> 6.0" } }
  backend "s3" {
    bucket       = "acme-tfstate"
    key          = "shop/prod.tfstate"
    region       = "us-east-1"
    use_lockfile = true
  }
}
provider "aws" {
  region = "us-east-1"
  default_tags { tags = { owner = "team-a", env = "prod" } }
}
resource "aws_sqs_queue" "orders" { visibility_timeout_seconds = 60 }

CLIs

sam build && sam local invoke OrdersFn -e event.json && sam deploy --guided
terraform init && terraform plan -out tf.plan && terraform apply tf.plan

Code Explained

The SAM transform expands short types into full CloudFormation
Policy templates like DynamoDBCrudPolicy scope IAM to one table
default_tags tags every AWS resource Terraform creates
The S3 backend locks state with a lock file

Choosing IaC on AWS

ToolBest When
CloudFormationAWS-only, declarative YAML
SAMServerless apps with local testing
CDKTeams who prefer code, rich constructs
Terraform / OpenTofuMulti-cloud, existing Terraform skills
PulumiCode with multi-cloud state

Do & Don't

  • Do Keep one state file per environment / component
  • Do Use SAM policy templates instead of broad managed policies
  • Don’t Store Terraform state locally or in git
  • Don’t Mix console edits with IaC-managed resources

Local Testing

  • sam local start-api / invoke run functions in Docker
  • terraform validate and tflint run offline
  • LocalStack works with both SAM (samlocal) and Terraform (tflocal)

Production Checklist

  • CI deploys with OIDC roles and approvals
  • State bucket versioned, encrypted, private
  • Drift detection (terraform plan on a schedule)
