CloudFormation

AWS's Native IaC

CloudFormation creates and updates stacks of resources from YAML or JSON templates. Templates declare Parameters, Resources and Outputs, with intrinsic functions like !Ref, !Sub and !GetAtt. Change sets preview updates, drift detection finds manual changes, and StackSets deploy across accounts and Regions. Failed updates roll back automatically.

Key Points

  • aws cloudformation deploy creates or updates a stack via a change set
  • DeletionPolicy: Retain / Snapshot protects data on delete
  • Stack policies and termination protection guard critical stacks
  • cfn-lint and cfn-guard validate templates

template.yaml

AWSTemplateFormatVersion: "2010-09-09"
Parameters:
  Env: { Type: String, AllowedValues: [dev, prod], Default: dev }
Conditions:
  IsProd: !Equals [!Ref Env, prod]
Resources:
  Uploads:
    Type: AWS::S3::Bucket
    DeletionPolicy: Retain
    Properties:
      BucketName: !Sub "acme-uploads-${Env}-${AWS::AccountId}"
      VersioningConfiguration:
        Status: !If [IsProd, Enabled, Suspended]
      PublicAccessBlockConfiguration:
        { BlockPublicAcls: true, BlockPublicPolicy: true,
          IgnorePublicAcls: true, RestrictPublicBuckets: true }
Outputs:
  BucketArn: { Value: !GetAtt Uploads.Arn }
  BucketName: { Value: !Ref Uploads, Export: { Name: !Sub "${Env}-uploads" } }

Deploy, Preview, Drift

aws cloudformation validate-template --template-body file://template.yaml
aws cloudformation deploy --stack-name shop-prod --template-file template.yaml \
    --parameter-overrides Env=prod --no-execute-changeset
aws cloudformation deploy --stack-name shop-prod --template-file template.yaml \
    --parameter-overrides Env=prod
aws cloudformation detect-stack-drift --stack-name shop-prod

Code Explained

!Sub builds names from parameters and pseudo parameters
The condition enables versioning only in prod
Retain keeps the bucket if the stack is deleted
--no-execute-changeset previews before applying

Cost Check

  • CloudFormation is free for AWS resource types
  • Third-party / private resource types bill per handler operation
  • Change sets catch expensive resource replacements before they happen

Security Check

  • Never put secrets in parameters defaults or outputs; use dynamic references ({{resolve:secretsmanager:…}})
  • Termination protection and stack policies on production stacks
  • Deploy roles (--role-arn) instead of broad user permissions

Limits & Quotas

  • 500 resources per stack
  • 200 parameters and 200 outputs per template
  • Template body up to 51,200 bytes inline; 1 MB from S3

Do & Don't

  • Do Preview with change sets before production updates
  • Do Use DeletionPolicy on data resources
  • Don’t Edit stack resources by hand in the console
  • Don’t Hard-code account IDs and Regions (use pseudo parameters)

Local Testing

  • cfn-lint and cfn-guard run offline
  • LocalStack deploys many CloudFormation resources locally
  • Rain CLI formats and deploys templates with nicer output

Production Checklist

  • Deploy from CI with a dedicated deploy role and OIDC
  • Termination protection + drift detection schedule
  • Templates linted and policy-checked in pull requests
