Sheet 07

Roles & Temporary Credentials

trust policies · aws sts assume-role · instance profiles · cross-account roles · OIDC federation (GitHub Actions) · session duration

Short-Lived Access

AWS STS issues temporary credentials when a principal assumes a role. EC2 gets them through an instance profile, ECS through a task role, Lambda through its execution role. Cross-account roles let one account act in another, and OIDC federation lets GitHub Actions, EKS pods or other identity providers assume roles with no stored secret.

Key Points

  • Sessions last 15 minutes to 12 hours (role setting, default 1 hour)
  • Trust policy conditions narrow who can assume (repo, branch, external ID)
  • Use an external ID for third parties assuming your roles
  • Role chaining limits sessions to 1 hour

Assume a Role and Trust GitHub

aws sts assume-role --role-arn arn:aws:iam::222233334444:role/audit \
    --role-session-name me --duration-seconds 3600

# One-time: register GitHub's OIDC provider in the account
aws iam create-open-id-connect-provider \
    --url https://token.actions.githubusercontent.com \
    --client-id-list sts.amazonaws.com

Trust Policy for a GitHub Deploy Role

{ "Version": "2012-10-17",
  "Statement": [{ "Effect": "Allow",
    "Principal": { "Federated":
      "arn:aws:iam::1111:oidc-provider/token.actions.githubusercontent.com" },
    "Action": "sts:AssumeRoleWithWebIdentity",
    "Condition": {
      "StringEquals": {
        "token.actions.githubusercontent.com:aud": "sts.amazonaws.com",
        "token.actions.githubusercontent.com:sub":
          "repo:acme/shop:environment:production" } } }] }

Profile That Assumes a Role

# ~/.aws/config
# [profile prod-admin]
# source_profile = sso-base
# role_arn = arn:aws:iam::222233334444:role/admin

Code Explained

assume-role returns an access key, secret and session token
The OIDC provider is registered once per account
The sub condition allows only the production environment of one repo
Profiles can chain from an SSO profile into a target role

Azure / GCP Equivalent

  • Azure managed identities + federated credentials (az-07)
  • GCP service accounts + Workload Identity Federation (gcp-07)

Cost Check

  • STS and OIDC providers are free
  • Removing static keys removes rotation work and leak risk
  • No extra charge for instance profiles or task roles

Security Check

  • Pin OIDC trust to repo:org/app:environment:production, never repo:org/*
  • Require sts:ExternalId for vendor cross-account roles
  • Review trust policies for "Principal": "*"

Do & Don't

  • Do Federate CI with OIDC and delete CI access keys
  • Do Keep session durations as short as practical
  • Don’t Trust an entire GitHub org in a production role
  • Don’t Pass temporary credentials around in logs

Local Testing

  • aws configure export-credentials --profile p --format env prints temporary creds for tools that need env vars
  • LocalStack accepts STS calls for local tests
  • act can test workflows (OIDC needs the real runner)

Production Checklist

  • OIDC trust conditions pinned to repo + environment
  • CloudTrail alerts on AssumeRole from unexpected principals
  • Cross-account roles reviewed and use external IDs for vendors
