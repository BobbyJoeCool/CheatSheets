NAT, Endpoints & Connectivity

NAT gateway · gateway vs interface VPC endpoints (PrivateLink) · VPC peering · Transit Gateway · Site-to-Site VPN

Getting Out, Reaching AWS Privately, Connecting Networks

A NAT gateway in a public subnet gives private subnets outbound internet access. VPC endpoints reach AWS services without the internet: gateway endpoints for S3 and DynamoDB (free, via route tables) and interface endpoints (PrivateLink ENIs) for most other services. Peering links two VPCs; Transit Gateway is a hub for many VPCs and VPNs.

Key Points

  • One NAT gateway per AZ avoids cross-AZ dependency and charges
  • Gateway endpoints cut NAT data charges for S3 / DynamoDB traffic
  • Interface endpoints need private DNS enabled to keep normal service names
  • Peering is not transitive; Transit Gateway routes between many

NAT, Endpoints, Peering

EIP=$(aws ec2 allocate-address --query AllocationId --output text)
NAT=$(aws ec2 create-nat-gateway --subnet-id $PUB_A --allocation-id $EIP \
  --query NatGateway.NatGatewayId --output text)
aws ec2 create-route --route-table-id $APP_RT \
    --destination-cidr-block 0.0.0.0/0 --nat-gateway-id $NAT

# Free gateway endpoint for S3
aws ec2 create-vpc-endpoint --vpc-id $VPC --vpc-endpoint-type Gateway \
    --service-name com.amazonaws.us-east-1.s3 --route-table-ids $APP_RT

# Interface endpoint (PrivateLink) for Secrets Manager
aws ec2 create-vpc-endpoint --vpc-id $VPC --vpc-endpoint-type Interface \
    --service-name com.amazonaws.us-east-1.secretsmanager \
    --subnet-ids $APP_A $APP_B --security-group-ids $SG_ENDPOINTS \
    --private-dns-enabled

# Peer two VPCs
aws ec2 create-vpc-peering-connection --vpc-id $VPC --peer-vpc-id $VPC2
aws ec2 accept-vpc-peering-connection --vpc-peering-connection-id pcx-0abc

Code Explained

The NAT gateway needs an Elastic IP and lives in a public subnet
Private route table sends internet traffic to the NAT gateway
The S3 gateway endpoint is a route-table entry, no ENIs
Interface endpoints create ENIs in your subnets with private DNS

Cost Check

  • NAT gateway: hourly + per GB processed, even when idle
  • Interface endpoints: hourly per AZ + per GB; gateway endpoints are free
  • Transit Gateway: per attachment-hour + per GB

Do & Don't

  • Do Add S3 and DynamoDB gateway endpoints to every VPC
  • Do Put a NAT gateway in each AZ for production
  • Don’t Leave NAT gateways in idle dev VPCs (they bill hourly)
  • Don’t Forget security groups on interface endpoints

Local Testing

  • Reachability Analyzer and Network Access Analyzer test paths
  • Price NAT vs endpoints in the Pricing Calculator
  • IaC plans show endpoint and route changes before apply

Production Checklist

  • NAT per AZ; gateway endpoints for S3 / DynamoDB
  • Interface endpoints for sensitive service APIs
  • Routing documented; non-overlapping CIDRs
