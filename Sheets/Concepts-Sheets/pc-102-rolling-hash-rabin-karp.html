Compare Substrings by Hash

A polynomial hash turns a string into a number: h = c₀·Bᵐ⁻¹ + c₁·Bᵐ⁻² + … + cₘ₋₁ (mod M). Sliding the window one step removes the leading character's term and appends a new one in O(1), so all windows of length m hash in O(n). Equal strings always have equal hashes; unequal ones rarely do, so verify on a match or use two moduli.

Choosing B and M

  • B: a prime larger than the alphabet (e.g. 131, 911382323)
  • M: a large prime (10⁹ + 7) or 2⁶¹ − 1
  • Double hashing: two (B, M) pairs, compare both
  • Collision chance with one 10⁹ modulus ≈ 1 in 10⁹ per pair

Rabin-Karp Search

function rabinKarp(t, p)
    m ← length(p)
    if m > n return []
    pw ← power(B, m - 1, M)                 // weight of the leading char
    (hp, ht) ← (0, 0)
    for i ← 0 to m - 1
        hp ← (hp * B + code(p[i])) mod M
        ht ← (ht * B + code(t[i])) mod M
    out ← []
    for i ← 0 to n - m
        if hp = ht and t[i..i+m-1] = p      // verify: hashes can collide
            out.append(i)
        if i + m < n                         // slide right by one
            ht ← (ht - code(t[i]) * pw mod M + M) mod M
            ht ← (ht * B + code(t[i + m])) mod M
    return out

Code Explained

pw — Bᵐ⁻¹, the leading character's weight
build both hashes for the first window
remove left char, shift by B, add right char
+ M keeps the value non-negative
expected O(n + m)

Prefix Hashes: Any Substring in O(1)

(h[0], pw[0]) ← (0, 1)
for i ← 0 to n - 1
    h[i + 1] ← (h[i] * B + code(s[i])) mod M
    pw[i + 1] ← pw[i] * B mod M

function hashOf(l, r)          // s[l..r]
    x ← h[r + 1] - h[l] * pw[r - l + 1]
    return ((x mod M) + M) mod M

Longest Duplicate Substring

function longestDup(s)        // binary search on L
    (lo, hi, best) ← (1, n - 1, "")
    while lo ≤ hi
        L ← (lo + hi) div 2
        start ← findDup(L)    // −1 if none:
        if start ≠ -1         // set of hashOf(i, i+L−1)
            best ← s[start .. start + L - 1]
            lo ← L + 1
        else
            hi ← L - 1
    return best

⚠ Common Mistakes

  • Skipping verification with a small modulus: collisions give false matches
  • Forgetting + M after subtraction: negative hashes never match
  • Overflow in ht * B with 64-bit M: use 2⁶¹ − 1 tricks or 128-bit products

✓ Tips & Best Practices

  • Binary search + hashing: any "longest repeated / common substring" question
  • Practice: Find the Index of First Occurrence, Repeated DNA Sequences, Longest Duplicate Substring
  • For exact guarantees use KMP / Z (Sheet 101) or a suffix array

Quick Summary

  • polynomial hash — string → number
  • rolling update — O(1) per slide
  • prefix hashes — any substring in O(1)
  • verify or double-hash — collisions
