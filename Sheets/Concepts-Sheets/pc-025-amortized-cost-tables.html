Average Cost over Many Operations

Amortized analysis spreads the cost of a rare expensive step over many cheap ones. A dynamic array occasionally copies everything when it grows, but because it doubles, n appends cost under 3n total: O(1) amortized each. The tables below are the cost reference used throughout the rest of the set.

Amortized vs Average

  • Amortized: guaranteed over any sequence of operations
  • Average case: expected over random inputs (hashing)
  • Growing by a constant (+10) instead of ×2 → O(n) per append
  • Hash maps resize too: O(1) amortized insert

Dynamic Array Append

function append(x)
    if size = capacity
        capacity ← capacity * 2         // rare: O(n) copy
        newData ← new Array(capacity)
        for i ← 0 to size - 1
            newData[i] ← data[i]
        data ← newData
    data[size] ← x                      // usual: O(1)
    size ← size + 1

// n appends copy 1 + 2 + 4 + … + n < 2n items
// total O(n)  →  O(1) amortized per append

⚠ Common Mistakes

  • Calling one append O(1) worst case: a resize step is O(n)
  • Assuming hash maps are always O(1): bad hashes or attacks degrade to O(n)
  • Saying quicksort uses O(1) space: recursion needs O(log n) on average

✓ Tips & Best Practices

  • Pre-size arrays/maps when n is known to avoid resizes
  • Quote "O(1) amortized" for appends and hash inserts
  • Keep this table handy when picking a structure (Sheet 003)

Quick Summary

  • amortized — averaged over a sequence
  • ×2 growth — O(1) amortized append
  • hash map — O(1) avg, O(n) worst
  • heap — O(1) peek, O(log n) push/pop
