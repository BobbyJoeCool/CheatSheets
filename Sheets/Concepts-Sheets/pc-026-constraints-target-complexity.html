Constraints → Target Complexity

n ≤ 10 · n ≤ 20 · n ≤ 500 · n ≤ 10⁴ · n ≤ 10⁶ · n ≥ 10⁹ · ~10⁸ ops/sec · TLE fixes

Let the Limits Pick the Algorithm

Problem constraints tell you how fast your solution must be. A judge allows roughly 10⁸ simple operations per second in C++ or Java (about 10⁷ in Python), with typical limits of 1–2 seconds. Plug n into candidate complexities, and anything far over ~10⁸ won't pass.

How to Use

  • Find the largest n in the constraints
  • Look up the allowed complexity below
  • That narrows the pattern before you design
  • Small n (≤ 20) is a hint that exponential is fine

Back-of-Envelope Check

// budget: 10⁸ ops (Java), 10⁷ (Py)
n ← 10⁵
n * n          // 10¹⁰: too slow
n * log2(n)    // 1.7 × 10⁶: fine
n ← 20
2^n * n        // 2 × 10⁷: fine
n ← 5000
n * n          // 2.5 × 10⁷: fine
n * n * n      // 10¹¹: too slow

⚠ Common Mistakes

  • Ignoring the constraints and coding O(n²) for n = 10⁵
  • Over-engineering O(n log n) when n ≤ 100 and O(n³) is simpler
  • Forgetting the second dimension: grid 10³ × 10³ is already 10⁶ cells

✓ Tips & Best Practices

  • Ask for constraints in interviews if they aren't stated
  • Count operations of the inner loop body, not lines of code
  • Python's constant factor is ~10× higher; leave extra headroom

Quick Summary

  • 10⁸ ops/sec — rough judge budget
  • n ≤ 20 — exponential is OK
  • n ≤ 10⁵ — need O(n log n)
  • n ≥ 10⁹ — log n or math
