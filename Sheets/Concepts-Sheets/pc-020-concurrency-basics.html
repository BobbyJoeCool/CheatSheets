Concurrency Basics

threads vs processes · race condition · mutex / lock · semaphore · deadlock · async / await · producer-consumer

Doing Several Things at Once

Concurrency is structuring a program as tasks that overlap in time; parallelism is actually running them at the same instant on multiple cores. When tasks share mutable data, unsynchronized access causes race conditions. Locks make a section exclusive, but taking locks in inconsistent order causes deadlock.

Vocabulary

  • Process: own memory; thread: shares process memory
  • Critical section: code touching shared state
  • Mutex: one holder at a time; semaphore: up to N
  • async/await: overlap waiting (I/O) on one thread

Races, Locks, Async

counter ← 0
lock ← new Mutex()

function worker()
    repeat 1000 times
        lock.acquire()
        counter ← counter + 1          // read-modify-write: not atomic
        lock.release()

t1 ← startThread(worker)
t2 ← startThread(worker)
join(t1)
join(t2)                               // 2000 with the lock; often less without

// Deadlock: T1 takes A then B, T2 takes B then A → both wait forever
// Fix: every thread acquires locks in the same global order

async function loadPage()
    userTask ← fetch("/user")          // both requests start now
    postsTask ← fetch("/posts")
    return (await userTask, await postsTask)

Code Explained

race — two threads interleave read → add → write
mutex — only one thread in the critical section
join — wait for a thread to finish
lock ordering — the standard deadlock fix
await — pause this task, not the whole thread

⚠ Common Mistakes

  • Assuming counter ← counter + 1 is one step: it's read, add, write
  • Holding a lock while doing slow I/O: other threads stall
  • Python threads for CPU-bound work: the GIL blocks real parallelism (use processes)

✓ Tips & Best Practices

  • Share as little mutable state as possible; pass messages instead
  • Use async for many slow network calls, threads/processes for CPU work
  • Release locks in finally (or with / using) so errors can't leak them

Quick Summary

  • race condition — unsynchronized shared writes
  • mutex / semaphore — 1 / N at a time
  • deadlock — circular wait; fix with lock order
  • async / await — overlap waiting
