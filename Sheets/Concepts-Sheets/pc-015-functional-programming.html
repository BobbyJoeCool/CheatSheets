Functional Programming

pure functions · immutability · first-class functions · higher-order functions · map / filter / reduce · composition · currying

Functions as Values

Functional programming treats functions as first-class values: store them in variables, pass them in, return them. Code is built from pure functions that don't mutate data, so results depend only on inputs. Higher-order functions like map, filter, and reduce replace most hand-written loops.

Core Terms

  • Pure: no side effects, same output for same input
  • Immutable: data is copied, never changed in place
  • Higher-order: takes or returns a function
  • Currying: f(a, b) becomes f(a)(b)

The Toolkit

square ← lambda x: x * x                   // function stored in a variable
nums ← [1, 2, 3, 4, 5]
map(nums, square)                          // [1, 4, 9, 16, 25]
filter(nums, lambda x: x mod 2 = 0)        // [2, 4]
reduce(nums, lambda acc, x: acc + x, 0)    // 15

function compose(f, g)                     // returns a new function
    return lambda x: f(g(x))
inc ← lambda x: x + 1
compose(square, inc)(3)                    // square(inc(3)) = 16

function add(a)                            // curried
    return lambda b: a + b
add5 ← add(5)
add5(10)                                   // 15

sortBy(people, lambda p: p.age)            // pass behavior as an argument
raised ← map(salaries, lambda s: s * 1.1)  // new list; salaries unchanged

Code Explained

lambda x: … — anonymous function
map — transform every item
filter — keep items that pass a test
reduce — fold items into one value (needs a start value)
compose — chain functions right to left
add(5) — partial application via currying

⚠ Common Mistakes

  • reduce without a start value on an empty list: error or undefined
  • Side effects inside map (printing, pushing to an outer list): use a loop instead
  • Chaining many passes over huge data: each step allocates a new list

✓ Tips & Best Practices

  • Prefer comprehensions in Python: [x * x for x in nums if x % 2 == 0]
  • Name lambdas that grow past one line; readability beats cleverness
  • Immutability makes concurrent code safer: nothing to lock

Quick Summary

  • map / filter / reduce — transform, select, fold
  • lambda — inline function value
  • compose(f, g) — f after g
  • pure — no side effects, easy to test
