Sheet 038

Binary Tree Recursion Patterns

max depth · invert · same tree / subtree · balanced check · diameter · path sum · return-a-tuple recursion

Think in Subtrees

Nearly every binary-tree problem is a recursive function that trusts its calls on left and right. Decide which way information flows: top-down passes values down as parameters (remaining sum, bounds); bottom-up returns values from children (height, balanced flag). When the answer can pass through any node, combine bottom-up returns with a running best.

Template Questions

  • What does the function return for null?
  • What do I need from each child?
  • What do I combine at the current node?
  • Does the answer bend through a node? Track best

Classic One-Liners

function maxDepth(node)
    if node = null return 0
    return 1 + max(maxDepth(node.left), maxDepth(node.right))

function invert(node)
    if node = null return null
    (l, r) ← (invert(node.left), invert(node.right))
    (node.left, node.right) ← (r, l)
    return node

function isSame(a, b)
    if a = null or b = null return a = b
    return a.val = b.val
        and isSame(a.left, b.left)
        and isSame(a.right, b.right)

Top-Down: Pass State Down

function hasPathSum(node, target)
    if node = null return false
    rest ← target - node.val
    if node.left = null and node.right = null
        return rest = 0              // leaf check
    return hasPathSum(node.left, rest)
        or hasPathSum(node.right, rest)

function isSubtree(root, sub)
    if root = null return false
    return isSame(root, sub)
        or isSubtree(root.left, sub)
        or isSubtree(root.right, sub)

Bottom-Up + Running Best

function diameter(root)            // longest path (edges)
    best ← 0
    function depth(node)
        if node = null return 0
        l ← depth(node.left)
        r ← depth(node.right)
        best ← max(best, l + r)    // bends here
        return 1 + max(l, r)       // longest arm upward
    depth(root)
    return best

Return a Tuple

function isBalanced(root)
    function check(node)           // → (balanced, height)
        if node = null return (true, 0)
        (lb, lh) ← check(node.left)
        (rb, rh) ← check(node.right)
        ok ← lb and rb and abs(lh - rh) ≤ 1
        return (ok, 1 + max(lh, rh))
    (ok, h) ← check(root)
    return ok

// one pass: O(n) instead of O(n²)

⚠ Common Mistakes

  • Calling height() inside isBalanced at every node: O(n²) instead of O(n)
  • Treating a node with one child as a leaf in path-sum problems
  • Returning the diameter instead of the arm length from the helper

✓ Tips & Best Practices

  • Practice: Max Depth, Invert, Same Tree, Subtree, Path Sum, Diameter, Balanced
  • Use a closure variable or a one-element array for best
  • Write the null case first, then the leaf case if needed

Quick Summary

  • top-down — parameters carry state
  • bottom-up — return values carry state
  • best — answers that bend through a node
  • tuple return — several facts in one pass
