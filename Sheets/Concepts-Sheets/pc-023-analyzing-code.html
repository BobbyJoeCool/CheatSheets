Analyzing Loops & Code

sequential = add · nested = multiply · halving loop = log n · O(n + m) vs O(n·m) · hidden costs (slice, concat, contains)

Reading Complexity from Code

To find Big O, look at how many times the innermost work runs. Blocks that run one after another add; loops inside loops multiply. Then watch for hidden costs: library calls such as insert, slicing, and string + can be O(n) each and quietly turn a loop into O(n²).

Rules

  • Sequential → add, keep the biggest term
  • Nested → multiply the iteration counts
  • Loop variable × or ÷ by a constant → log n
  • Different inputs keep different letters

Patterns

for i ← 0 to n - 1                // O(n)
    work()
for j ← 0 to n - 1                // + O(n)  → sequential: O(n)
    work()

for i ← 0 to n - 1                // nested → O(n · n) = O(n²)
    for j ← i + 1 to n - 1        // triangle n(n-1)/2 is still O(n²)
        work()
i ← n
while i > 1                       // halving → O(log n)
    i ← i div 2
for i ← 1 to n                    // inner loop doubles → O(n log n)
    j ← 1
    while j < n
        j ← j * 2

s ← ""
for each ch in text               // hidden cost: + copies s each time
    s ← s + ch                    // → O(n²); use a string builder

Code Explained

sequential blocks — add
nested loops — multiply
i div 2 / j * 2 — logarithmic loops
two inputs A, B — O(|A| · |B|), not n²
immutable string + — O(length) per append

⚠ Common Mistakes

  • Calling a two-pointer or sliding-window loop O(n²) because it has a nested while
  • Ignoring the cost of contains on a list inside a loop: O(n²) total
  • Using n for both dimensions of a grid: it's O(rows × cols)

✓ Tips & Best Practices

  • Count how many times each pointer moves in total, not per outer step
  • Swap list lookups for a set when checking membership in a loop
  • Build strings with a list + join or a builder

Quick Summary

  • Sequential — add
  • Nested — multiply
  • ×2 / ÷2 — log n
  • Library calls have costs too
