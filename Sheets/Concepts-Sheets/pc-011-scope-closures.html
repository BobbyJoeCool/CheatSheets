Scope & Closures

local vs global · block vs function scope · lexical scope · shadowing · closures · captured variables · loop-closure pitfall

Where Names Are Visible

Scope decides where a variable can be read. Most languages use lexical scope: a function sees the variables of the code it was written inside. A closure is a function plus the variables it captured from that enclosing scope; they stay alive as long as the function does.

Scope Levels

  • Global: visible everywhere in the file/program
  • Function: visible inside one function call
  • Block: visible inside { } / an indented block (not in Python)
  • Enclosing: outer function's locals, seen by inner functions

Scope, Shadowing, Closures

total ← 0                         // global
function addToTotal(x)
    total ← total + x             // Python needs `global total`

x ← 1
function shadow()
    x ← 2                         // new local x shadows the global
    return x                      // 2; global x is still 1

function makeCounter()
    count ← 0                     // captured by the closure below
    function next()
        count ← count + 1         // Python needs `nonlocal count`
        return count
    return next

c ← makeCounter()
c()                               // 1
c()                               // 2  (count survives between calls)
d ← makeCounter()
d()                               // 1  (each closure has its own count)

Code Explained

global — readable everywhere; writing often needs a keyword
shadowing — inner name hides the outer one
closure — next keeps count alive after makeCounter returns
each call to makeCounter creates a fresh count
closures power callbacks, memoization, and private state

⚠ Common Mistakes

  • Assuming a Python if block creates a new scope: it doesn't
  • Closures in a loop capturing the variable, not its value at that time
  • Accidentally shadowing a built-in (list, max, sum) with a local name

✓ Tips & Best Practices

  • Keep variables in the smallest scope that works
  • Pass values as parameters instead of reading globals; functions get easier to test
  • Use closures for small private state (counters, memo caches)

Quick Summary

  • lexical scope — decided by where code is written
  • shadowing — inner name hides outer
  • closure — function + captured variables
  • nonlocal / global — Python's write-outer keywords
