Handling What Goes Wrong

Errors are inevitable: bad input, missing files, broken invariants. Exceptions jump out of normal flow to the nearest matching handler; error values (Go, Rust) make the caller check explicitly. Either way, fail fast: detect bad state as early as possible and report it clearly.

Principles

  • Validate at the boundary (user input, files, network)
  • Catch only errors you can actually handle
  • finally runs whether or not an error occurred
  • assert checks your assumptions, not user input

Throwing, Catching, Returning Errors

function parseAge(text)
    if text is empty
        throw ValueError("age is required")   // fail fast
    n ← toInt(text)
    if n < 0 or n > 150
        throw ValueError("age out of range")
    return n

try
    age ← parseAge(input)
catch ValueError as e
    print("bad input: " + e.message)        // handle and recover
finally
    closeFile()                             // always runs

(value, err) ← parseAgeResult(input)        // error as a value
if err ≠ null
    return err                              // caller must check

idx ← indexOf(arr, target)                  // sentinel: -1 = not found
assert lo ≤ hi                              // internal invariant

Code Explained

throw — stop and signal an error
catch — handle a specific error type
finally — cleanup that always runs
(value, err) — Go / Rust Result style
sentinel — special return like -1 or null
assert — crash loudly if a bug breaks an invariant

⚠ Common Mistakes

  • Catching every exception and ignoring it: hides bugs and corrupts state
  • Using exceptions for normal control flow (e.g. ending a loop): slow and unclear
  • Returning -1 when -1 is a valid answer: sentinel collides with real data

✓ Tips & Best Practices

  • Throw specific error types with messages that say what and why
  • Release resources with finally or using / with / defer
  • In interviews, state input assumptions instead of over-validating

Quick Summary

  • throw / catch / finally — exception flow
  • (value, err) — errors as values
  • -1 / null — sentinel results
  • assert — guard internal invariants
