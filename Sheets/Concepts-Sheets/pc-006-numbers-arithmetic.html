Numbers & Arithmetic

integer division · mod with negatives · overflow · 32/64-bit limits · floating-point error · epsilon compare · rounding

Computer Arithmetic Is Not School Math

Integers have fixed sizes and can overflow; floats are binary approximations, so 0.1 + 0.2 isn't exactly 0.3. Integer division and mod round differently across languages when negatives are involved. Knowing these rules prevents a whole class of wrong answers.

Rules of Thumb

  • Sums of many 32-bit values may need 64-bit
  • Never compare floats with =; use a tolerance
  • Use integer math when exact answers are required
  • Fix negative mod with ((a mod m) + m) mod m

Arithmetic Behavior

7 div 2                  // 3
-7 div 2                 // -4 (Python: floor)  ·  -3 (Java/C/JS: truncate)
7 mod 3                  // 1
-7 mod 3                 // 2 (Python)  ·  -1 (Java/C/JS)
((a mod m) + m) mod m    // always in 0..m-1

(a + b - 1) div b        // ceil(a / b) for positive ints
0.1 + 0.2                // 0.30000000000000004
abs(a - b) < 1e-9        // float "equality" with tolerance

2147483647 + 1           // -2147483648 (32-bit overflow wraps)
mid ← lo + (hi - lo) div 2   // avoids overflow of lo + hi

floor(-2.5)              // -3
ceil(-2.5)               // -2
truncate(-2.5)           // -2   (toward zero)
round(2.5)               // 2 (Python, banker's)  ·  3 (JS Math.round)

Code Explained

div — rounding direction matters for negatives
mod — sign of result follows the divisor (Python) or dividend (Java/C/JS)
(a + b - 1) div b — integer ceiling without floats
1e-9 — epsilon; scale it to the size of your values
lo + (hi - lo) div 2 — safe midpoint

⚠ Common Mistakes

  • Translating Python's // and % into Java/C for negatives: results differ
  • Using floats for money: rounding errors accumulate; use integer cents
  • Checking overflow after it happens: the wrapped value already lies

✓ Tips & Best Practices

  • When a problem says "return modulo 10⁹+7", the true answer overflows; reduce at every step
  • JavaScript numbers are all float64: integers above 2⁵³ lose precision (use BigInt)
  • Python ints never overflow, but your translated Java solution will

Quick Summary

  • div / mod — check negative behavior
  • 0.1 + 0.2 — floats are approximate
  • int32 — about 2.1 billion
  • lo + (hi - lo) div 2 — overflow-safe midpoint
