Names, Values, and Types

A variable is a name bound to a value. Every value has a type that decides what operations make sense (+ on numbers adds, on strings joins). Languages differ in when types are checked (static: at compile time; dynamic: at run time) and how strictly (strong: no silent conversions; weak: converts for you).

Key Ideas

  • Primitive: a single value (int, float, bool, char)
  • Composite: built from other values (array, map, object)
  • Constant: a name that can't be rebound
  • null means "no value"; using it like a value crashes

Declaring and Converting

count ← 0                        // integer
ratio ← 0.75                     // floating point
done ← false                     // boolean
initial ← 'A'                    // character
name ← "Ada"                     // string
const MAX_SIZE ← 100             // constant: can't be reassigned
items ← [1, 2, 3]                // array / list
point ← (3, 4)                   // tuple: fixed-size group
user ← { "name": "Ada", "age": 36 }   // map / record
nothing ← null                   // absence of a value

toInt("42")                      // 42
toFloat(7)                       // 7.0
toString(3.5)                    // "3.5"
truncate(4.9)                    // 4
toInt("4.9")                     // error in most languages
"5" + 3                          // "53" (JS)  ·  error (Python)

Code Explained

const — binding is fixed; the object it points to may still change
(3, 4) — tuple: ordered, usually immutable
{ … } — map: key → value pairs
toInt / toFloat — explicit conversion (cast)
"5" + 3 — implicit conversion: depends on the language

⚠ Common Mistakes

  • Assuming "5" + 3 means the same everywhere: it's "53" in JS and an error in Python
  • Comparing values of different types ("1" = 1): false or surprising
  • Using a null variable before assigning it: null-reference crash

✓ Tips & Best Practices

  • Convert input text to numbers once, at the edge of your program
  • Use constants for magic numbers (MAX_SIZE) so intent is clear
  • In static languages, let types document the code; in dynamic ones, add type hints

Quick Summary

  • variable — name bound to a value
  • static / dynamic — when types are checked
  • strong / weak — how freely types convert
  • toInt(x) — explicit conversion beats implicit
