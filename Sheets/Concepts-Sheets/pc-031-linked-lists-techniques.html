Linked Lists — Techniques

reverse in place · fast / slow pointers · Floyd cycle detection · find middle · merge two sorted · remove nth from end

Pointer Patterns That Solve Most List Problems

Almost every linked-list problem combines a few moves: reverse links in place, run fast and slow pointers (to find the middle, detect a cycle, or keep a fixed gap), and merge with a dummy tail. All run in O(n) time and O(1) extra space.

Recognize It When

  • "in place", "O(1) extra space" on a list
  • "middle", "cycle", "nth from end"
  • "reverse" all or part of a list
  • "merge", "reorder", "palindrome list"

Reverse · Middle

function reverse(head)               // O(n), O(1)
    prev ← null
    curr ← head
    while curr ≠ null
        nxt ← curr.next              // save
        curr.next ← prev             // flip
        prev ← curr
        curr ← nxt
    return prev                      // new head

function middle(head)                // fast: 2 steps
    slow ← head
    fast ← head
    while fast ≠ null and fast.next ≠ null
        slow ← slow.next
        fast ← fast.next.next
    return slow                      // 2nd middle if even

Cycle · Nth From End

function hasCycle(head)              // Floyd
    (slow, fast) ← (head, head)
    while fast ≠ null and fast.next ≠ null
        slow ← slow.next
        fast ← fast.next.next
        if slow = fast return true   // they meet
    return false

function removeNthFromEnd(head, n)   // gap of n
    dummy ← new Node(0, head)
    (fast, slow) ← (dummy, dummy)
    for i ← 1 to n + 1
        fast ← fast.next
    while fast ≠ null
        (fast, slow) ← (fast.next, slow.next)
    slow.next ← slow.next.next       // skip target
    return dummy.next

Merge Two Sorted Lists

function mergeTwo(a, b)
    dummy ← new Node(0)
    tail ← dummy
    while a ≠ null and b ≠ null
        if a.val ≤ b.val
            (tail.next, a) ← (a, a.next)
        else
            (tail.next, b) ← (b, b.next)
        tail ← tail.next
    tail.next ← if a ≠ null then a else b
    return dummy.next

⚠ Common Mistakes

  • Overwriting curr.next before saving it: the rest of the list is lost
  • Loop condition fast.next ≠ null alone: crashes when fast is null
  • Using slow = fast to start Floyd's loop: they're equal before moving

✓ Tips & Best Practices

  • Cycle start: after they meet, move one pointer to head; step both by 1 until they meet again
  • Palindrome list: find middle, reverse second half, compare
  • Use a dummy head for any merge or removal

Quick Summary

  • reverse — prev / curr / next
  • slow + fast — middle, cycles
  • gap of n — nth from end
  • dummy tail — merging
