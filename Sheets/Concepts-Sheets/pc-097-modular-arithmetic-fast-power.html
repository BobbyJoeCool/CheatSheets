Modular Arithmetic & Fast Exponentiation

mod 10⁹+7 · (a·b) mod m · negative mod fix · binary exponentiation · modular inverse (Fermat) · overflow-safe multiply

Arithmetic That Wraps Around

When answers are astronomically large, problems ask for them modulo 10⁹ + 7. Addition, subtraction, and multiplication can be reduced at every step, so numbers never overflow. Division can't: multiply by the modular inverse instead. Binary exponentiation computes aⁿ mod m in O(log n) by squaring.

Why 10⁹ + 7?

  • It's prime, so inverses exist (Fermat)
  • It fits in a signed 32-bit int
  • Product of two values < 10⁹ + 7 fits in 64 bits
  • 998244353 is the other common prime

Rules, Fast Power, Inverse

MOD ← 10^9 + 7
(a + b) mod m = ((a mod m) + (b mod m)) mod m
(a * b) mod m = ((a mod m) * (b mod m)) mod m
(a - b) mod m = ((a - b) mod m + m) mod m        // keep it non-negative

function power(base, exp, m)                    // O(log exp)
    result ← 1
    base ← base mod m
    while exp > 0
        if exp & 1 = 1                          // this bit is set
            result ← result * base mod m
        base ← base * base mod m                // square for the next bit
        exp ← exp >> 1
    return result

function inverse(a, m)                          // m prime, a mod m ≠ 0
    return power(a, m - 2, m)                   // Fermat's little theorem
// a / b  (mod m)  =  a * inverse(b, m) mod m

Code Explained

reduce after every + and *
negative results: add m before the final mod
exp & 1 — current binary digit of the exponent
squaring base steps through a¹, a², a⁴, a⁸ …
inverse needs a prime modulus (else extended Euclid)

⚠ Common Mistakes

  • Reducing only at the end: intermediate products already overflowed
  • Dividing directly under a modulus: (a / b) mod m ≠ (a mod m) / (b mod m)
  • Negative mod in Java/C/JS after subtraction

✓ Tips & Best Practices

  • Multiplying two 64-bit residues mod a 64-bit prime needs 128-bit math or mulmod
  • Fibonacci(10¹⁸) mod p: 2×2 matrix fast power
  • Keep MOD as a constant to avoid typos like 10^9 + 9

Quick Summary

  • reduce every step — no overflow
  • ((x mod m) + m) mod m — non-negative
  • fast power — O(log n) by squaring
  • power(a, m − 2) — inverse for prime m
