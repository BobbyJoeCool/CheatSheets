Edge Cases & Dry Runs

empty input · single element · duplicates · negatives & zero · overflow · off-by-one checks · trace table

Break It Before They Do

Correct code for the normal case still fails on edge cases: inputs at the boundaries of what the problem allows. A dry run (tracing code by hand with a small input, writing each variable in a table) catches off-by-one errors and wrong loop conditions before the computer does.

When to Check

  • After planning: list edge cases next to your examples
  • After coding: trace one normal and one edge case
  • Off-by-one bugs live at loop bounds and slice ends
  • Overflow lives in sums, products, and midpoints

Dry Run: Trace Table

// Sum of positive numbers
function sumPositive(arr)
    total ← 0
    for i ← 0 to length(arr) - 1
        if arr[i] > 0
            total ← total + arr[i]
    return total

// Trace with arr = [3, -1, 4]
//  i | arr[i] | arr[i] > 0 | total
//  - |   -    |     -      |   0
//  0 |   3    |    true    |   3
//  1 |  -1    |    false   |   3
//  2 |   4    |    true    |   7
// return 7  ✓

// Edge: arr = [] → "0 to -1" is empty, returns 0 ✓

⚠ Common Mistakes

  • Testing only the example from the prompt: it was chosen to be easy
  • Returning a default like 0 for empty input without checking the spec: it may want -1 or an error
  • Forgetting null children in trees: most crashes are node.left.val on a leaf

✓ Tips & Best Practices

  • Keep a personal list of edge cases you missed; it becomes your checklist
  • Trace with the smallest input that exercises every branch
  • Guard clauses (if arr is empty return …) at the top keep the main logic clean

Quick Summary

  • Edge cases — boundaries of the allowed input
  • Trace table — one row per iteration
  • Off-by-one — check loop starts, ends, and < vs ≤
  • Overflow — sums, products, midpoints
