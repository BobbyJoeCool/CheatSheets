Space Complexity & Recursive Analysis

auxiliary vs total space · recursion depth · recursion tree · branches^depth · Master Theorem · memoization effect

Memory and Recursive Cost

Space complexity counts extra memory as n grows. Auxiliary space is what your algorithm adds; total space also counts the input. Recursion uses hidden space: one stack frame per active call, so depth = space. For time, draw the recursion tree: work ≈ (number of calls) × (work per call).

Quick Rules

  • Recursion space = maximum depth × frame size
  • Recursion time ≈ branches^depth without memoization
  • Memoization: time ≈ (distinct states) × (work per state)
  • Output arrays usually don't count as auxiliary space

Analyzing Recursion

function sumTo(n)                 // 1 call per level, depth n
    if n = 0 return 0             // time O(n), stack space O(n)
    return n + sumTo(n - 1)

function fib(n)                   // 2 branches, depth n
    if n ≤ 1 return n             // time O(2ⁿ), space O(n)
    return fib(n - 1) + fib(n - 2)

memo ← new Map()
function fibMemo(n)               // n distinct states, O(1) each
    if n ≤ 1 return n             // time O(n), space O(n)
    if memo.has(n) return memo[n]
    memo[n] ← fibMemo(n - 1) + fibMemo(n - 2)
    return memo[n]

⚠ Common Mistakes

  • Calling recursive DFS O(1) space: the call stack is O(depth), up to O(n)
  • Using the Master Theorem on T(n − 1) recurrences: it only applies to T(n/b)
  • Forgetting memo table space: memoized DP still uses O(states) memory

✓ Tips & Best Practices

  • Draw the first three levels of the recursion tree; the pattern usually shows
  • Balanced tree recursion is O(log n) space; skewed is O(n)
  • Convert to an iterative loop to cut stack space to O(1) when possible

Quick Summary

  • space — depth of recursion counts
  • branches^depth — naive recursion time
  • states × work — memoized time
  • 2T(n/2)+O(n) — O(n log n)
