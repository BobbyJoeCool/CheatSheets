Pattern Matching on Text

A regular expression is a compact pattern that describes a set of strings, used to validate, search, extract, and replace text. Engines in most languages share the same core syntax shown here. This is a one-page primer; the RegEx set covers flags, lookaround, Unicode, performance, and per-language APIs.

Good to Know

  • Escape special characters with \: \. matches a dot
  • Quantifiers are greedy by default; add ? for lazy
  • LeetCode "Regular Expression Matching" is DP (Sheet 083)
  • Use raw strings (r"…") in Python to keep backslashes

Common Operations

match("^\d{3}-\d{4}$", "555-1234")          // true: whole string
search("[A-Z]\w+", "say Hello there")        // "Hello"
findAll("\d+", "a1b22c333")                  // ["1", "22", "333"]
replace("\s+", " ", "a   b    c")            // "a b c"
groups("(\w+)@(\w+)\.com", "ada@site.com")   // ["ada", "site"]
match("colou?r", "color")                    // true: u is optional
match("^(cat|dog)s?$", "dogs")               // true: alternation
search("<.+>", "<a><b>")                     // "<a><b>"  greedy
search("<.+?>", "<a><b>")                    // "<a>"     lazy
search("\bcat\b", "concat cat")             // matches the word "cat" only

Code Explained

match — pattern must fit the whole string (with ^…$)
search — first match anywhere
findAll — every non-overlapping match
groups — text captured by ( )
+? — lazy: as few characters as possible

⚠ Common Mistakes

  • Forgetting anchors: \d+ "validates" "abc123" because it finds a match inside
  • Unescaped . in domains: site.com also matches siteXcom
  • Greedy .* swallowing too much; use .*? or a negated class [^>]*

✓ Tips & Best Practices

  • Test patterns interactively (regex101.com) with the right flavor selected
  • Prefer simple string methods (split, startsWith) when they're enough

Quick Summary

  • \d \w \s — digit, word, space
  • * + ? {m,n} — quantifiers
  • ( ) — capture groups
  • ^ $ — anchor the whole string
