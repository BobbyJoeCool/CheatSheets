SOLID & Design Patterns

SRP · OCP · LSP · ISP · DIP · factory · strategy · observer

Principles and Reusable Shapes

SOLID is five guidelines for object-oriented code that stays easy to change. Design patterns are named, reusable solutions to common design problems. Both aim at the same thing: depend on abstractions, keep each piece small, and add features by adding code instead of editing working code.

When They Matter

  • System-design and OOP-design interview rounds
  • Code that many people extend over years
  • Overkill for a 30-line script or a LeetCode answer
  • Patterns are vocabulary: say "use a strategy"

Strategy, Factory, Observer

interface Discount                       // Strategy: swappable behavior
    function apply(price)
class NoDiscount implements Discount
    function apply(price)
        return price
class Sale implements Discount
    function apply(price)
        return price * 0.8
function checkout(cart, discount)        // depends on the interface (DIP)
    return discount.apply(sum(cart))

function makeDiscount(code)              // Factory: one place picks the class
    if code = "SALE" return new Sale()
    return new NoDiscount()

class Store                              // Observer: notify subscribers
    listeners ← []
    function subscribe(fn)
        listeners.append(fn)
    function publish(event)
        for each fn in listeners
            fn(event)

Code Explained

strategy — new discount = new class, no edits (OCP)
checkout never names a concrete class
factory — hides construction decisions
observer — publisher doesn't know its subscribers

⚠ Common Mistakes

  • Applying patterns before there's a need: extra layers with no payoff
  • Singletons as hidden globals: hard to test and to reason about
  • A Square subclass of Rectangle that breaks setWidth: violates Liskov

✓ Tips & Best Practices

  • Refactor toward a pattern when the second or third variant appears
  • Inject dependencies through constructors so tests can swap them
  • In design interviews, name the pattern and the principle it serves

Quick Summary

  • SOLID — five design guidelines
  • strategy — pluggable behavior
  • factory — centralized creation
  • observer — event subscribers
