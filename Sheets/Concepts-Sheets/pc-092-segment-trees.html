Range Queries with Updates

A segment tree stores an answer (sum, min, max, gcd…) for each segment of the array: the root covers everything, and each node splits its range in half. Any range query or point update touches O(log n) nodes. Lazy propagation postpones range updates by storing them at covering nodes until a query needs to go deeper.

Recognize It When

  • Range sum / min / max with values that change
  • Range updates ("add v to l..r") plus range queries
  • Prefix sums fail because updates are frequent
  • Counting by value ranges (with coordinate compression)

Build and Query (Range Sum)

// node 1 = root; children 2i and 2i+1
// t has 4n slots
function build(a, node, l, r)
    if l = r
        t[node] ← a[l]
        return
    m ← (l + r) div 2
    build(a, 2 * node, l, m)
    build(a, 2 * node + 1, m + 1, r)
    t[node] ← t[2 * node] + t[2 * node + 1]

function query(node, l, r, ql, qr)
    if qr < l or r < ql return 0      // no overlap
    if ql ≤ l and r ≤ qr return t[node]   // inside
    m ← (l + r) div 2
    return query(2 * node, l, m, ql, qr)
         + query(2 * node + 1, m + 1, r, ql, qr)

Shape for a = [2, 1, 5, 3]

           [0..3] 11
          /         \
     [0..1] 3     [2..3] 8
      /    \       /    \
   [0] 2  [1] 1 [2] 5  [3] 3

query(1..2) visits:
 [0..1] → partial → [1] = 1
 [2..3] → partial → [2] = 5
 total 6

Point Update

function update(node, l, r, i, val)
    if l = r
        t[node] ← val             // a[i] ← val
        return
    m ← (l + r) div 2
    if i ≤ m
        update(2 * node, l, m, i, val)
    else
        update(2 * node + 1, m + 1, r, i, val)
    t[node] ← t[2 * node] + t[2 * node + 1]

Lazy Propagation (Range Add)

// fully covered node: add v·(r − l + 1)
// to t[node], add v to lazy[node], stop
function push(node, l, r)          // before
    if lazy[node] ≠ 0               // going down
        m ← (l + r) div 2
        apply(2 * node, l, m, lazy[node])
        apply(2 * node + 1, m + 1, r, lazy[node])
        lazy[node] ← 0
function apply(node, l, r, v)
    t[node] ← t[node] + v * (r - l + 1)
    lazy[node] ← lazy[node] + v

⚠ Common Mistakes

  • Allocating 2n slots for the recursive version: it needs up to 4n
  • Returning the wrong identity on no overlap: 0 for sum, ∞ for min, −∞ for max
  • Forgetting push before recursing in lazy trees: children miss pending adds

✓ Tips & Best Practices

  • Sum-only with point updates? A Fenwick tree (Sheet 093) is shorter
  • Iterative bottom-up segment trees use 2n slots and no recursion
  • Practice: Range Sum Query – Mutable, Count of Smaller Numbers After Self, My Calendar III

Quick Summary

  • node covers [l..r]; children split it
  • query / update — O(log n)
  • identity value — no-overlap result
  • lazy — deferred range updates
