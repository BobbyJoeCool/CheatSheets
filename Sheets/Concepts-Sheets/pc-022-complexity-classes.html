Common Complexity Classes

O(1) · O(log n) · O(n) · O(n log n) · O(n²) · O(2ⁿ) · O(n!) · growth chart

The Complexity Ladder

A handful of growth rates cover almost every algorithm. Each step up the ladder is dramatically slower for large inputs: at n = 1,000, O(n log n) is about 10,000 steps while O(n²) is a million and O(2ⁿ) is beyond astronomical. Learn to recognize each class from the shape of the code.

Shapes to Recognize

  • Halving the problem each step → log n
  • One pass over the data → n
  • Sort, or divide-and-conquer with linear merge → n log n
  • Every subset / every ordering → 2ⁿ / n!

Typical Code per Class

x ← arr[i]                        // O(1)        index, hash lookup
binarySearch(sorted, t)           // O(log n)    halves the range
for each x in arr                 // O(n)        single pass
sort(arr)                         // O(n log n)  comparison sort
for i …  for j …                  // O(n²)       all pairs
for i …  for j …  for k …         // O(n³)       all triples
subsets(items)                    // O(2ⁿ)       include / exclude each
permutations(items)               // O(n!)       every ordering

⚠ Common Mistakes

  • Treating O(log n) and O(n) as "both fast": at 10⁹ that's 30 steps vs a billion
  • Calling 2ⁿ "polynomial": exponential grows faster than any n^k
  • Forgetting the log base doesn't matter: log₂ and log₁₀ differ by a constant

✓ Tips & Best Practices

  • Rough feel: log₂(10⁶) ≈ 20, log₂(10⁹) ≈ 30
