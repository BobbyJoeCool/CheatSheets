Binary Search Beyond Sorted Arrays

Binary search works whenever you can look at the middle and rule out half. That includes rotated arrays (one half is always sorted), peaks (walk uphill), and most powerfully search on the answer: if a yes/no test ok(x) flips from false to true exactly once as x grows, binary search over x finds the smallest x that works.

Recognize It When

  • "Minimum capacity / speed / days so that …"
  • "Maximize the minimum" or "minimize the maximum"
  • Answer range is huge (up to 10⁹) but checking one value is O(n)
  • Sorted-but-rotated input, or "find any peak"

Search in Rotated Sorted Array

function searchRotated(arr, t)
    (lo, hi) ← (0, length(arr) - 1)
    while lo ≤ hi
        mid ← lo + (hi - lo) div 2
        if arr[mid] = t return mid
        if arr[lo] ≤ arr[mid]         // left half sorted
            if arr[lo] ≤ t and t < arr[mid]
                hi ← mid - 1
            else
                lo ← mid + 1
        else                          // right half sorted
            if arr[mid] < t and t ≤ arr[hi]
                lo ← mid + 1
            else
                hi ← mid - 1
    return -1

Find Peak Element

function findPeak(arr)
    (lo, hi) ← (0, length(arr) - 1)
    while lo < hi
        mid ← lo + (hi - lo) div 2
        if arr[mid] < arr[mid + 1]
            lo ← mid + 1          // uphill right
        else
            hi ← mid              // mid may be peak
    return lo

// min of rotated array: same shape,
// compare arr[mid] > arr[hi] → lo ← mid + 1

Search on the Answer (Koko Eating Bananas)

function minEatingSpeed(piles, h)
    function canFinish(k)                // monotonic in k
        hours ← 0
        for each p in piles
            hours ← hours + (p + k - 1) div k
        return hours ≤ h
    (lo, hi) ← (1, max(piles))
    while lo < hi                        // first k that works
        mid ← lo + (hi - lo) div 2
        if canFinish(mid)
            hi ← mid
        else
            lo ← mid + 1
    return lo

⚠ Common Mistakes

  • Wrong answer range: Koko's low end is 1, not 0 (division by zero)
  • Testing t < arr[mid] without the arr[lo] ≤ t side in rotated search
  • Real-valued loops with while lo < hi: floats may never meet; use a fixed count

✓ Tips & Best Practices

  • Write ok(x) first and confirm it's monotonic before coding the search
  • "Minimize" → first true; "maximize" → last true (flip the test)
  • Duplicates in rotated arrays: shrink lo and hi by one when ends equal

Quick Summary

  • rotated — one half is always sorted
  • peak — move toward the bigger neighbor
  • search on answer — binary search over x
  • monotonic ok(x) — the requirement
