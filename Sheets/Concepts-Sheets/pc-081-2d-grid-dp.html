DP on a Grid of Cells

When you move through a grid only right and down (or along rows), each cell's answer depends on the cell above and the cell to the left, so a row-by-row fill works. Counting paths adds the two; cheapest paths take the min. Some problems are easier backward (from the goal), and padding the table with an extra row/column removes edge checks.

Recognize It When

  • Moves restricted to right/down, or row to row
  • "Number of unique paths", "minimum path sum"
  • "Largest square / rectangle of 1s"
  • "Minimum health / fuel needed" → fill from the end

Unique Paths with Obstacles

function uniquePaths(grid)        // 1 = blocked
    dp ← R × C grid of 0
    for r ← 0 to R - 1
        for c ← 0 to C - 1
            if grid[r][c] = 1
                dp[r][c] ← 0
            else if r = 0 and c = 0
                dp[r][c] ← 1
            else
                up ← if r > 0 then dp[r-1][c] else 0
                left ← if c > 0 then dp[r][c-1] else 0
                dp[r][c] ← up + left
    return dp[R-1][C-1]
// min path sum: grid[r][c] + min(up, left)

Maximal Square

function maximalSquare(m)
    dp ← (R+1) × (C+1) grid of 0  // padded
    best ← 0
    for r ← 1 to R
        for c ← 1 to C
            if m[r-1][c-1] = '1'
                dp[r][c] ← 1 + min(dp[r-1][c],
                                   dp[r][c-1],
                                   dp[r-1][c-1])
                best ← max(best, dp[r][c])
    return best * best
// dp[r][c] = side of the biggest square
// whose bottom-right corner is (r, c)

Triangle (Bottom-Up, 1 Row)

function minimumTotal(tri)
    dp ← copy(tri[last row])
    for i ← rows - 2 down to 0
        for j ← 0 to i
            dp[j] ← tri[i][j] + min(dp[j], dp[j + 1])
    return dp[0]

Dungeon Game (Fill from the Goal)

function minHP(d)                 // need ≥ 1 HP always
    need ← (R+1) × (C+1) grid of ∞
    need[R][C-1] ← 1
    need[R-1][C] ← 1
    for r ← R - 1 down to 0
        for c ← C - 1 down to 0
            next ← min(need[r+1][c], need[r][c+1])
            need[r][c] ← max(1, next - d[r][c])
    return need[0][0]

⚠ Common Mistakes

  • Initializing the whole first row to 1 when an obstacle sits in it: cells past it are 0
  • Filling Dungeon Game forward: the answer depends on the future, so go backward
  • Returning the max side instead of the area in Maximal Square

✓ Tips & Best Practices

  • Practice: Unique Paths I/II, Minimum Path Sum, Triangle, Maximal Square, Dungeon Game
  • Unique Paths has a closed form: C(R + C − 2, R − 1)
  • Reduce to one row: dp[c] ← dp[c] + dp[c − 1]

Quick Summary

  • dp[r][c] from up and left
  • add — count · min — cost
  • pad the table — no bounds checks
  • backward fill — requirements depend on the future
