Sheet 002

Pseudocode Conventions

← vs = · indentation blocks · div / mod · for … to · for each · collection operations · null · ∞

The House Style

Every code block in this set uses one small, consistent pseudocode. It reads like plain English but is precise enough to translate line by line into a real language. Indentation marks blocks, ← assigns, and = compares, so there is never confusion between the two.

Why Pseudocode

  • Shows the idea, not language syntax
  • Arrays are 0-indexed
  • for … to … ranges are inclusive

A Complete Example

// Find target in a sorted array. Returns index or -1.
function binarySearch(arr, target)
    lo ← 0
    hi ← length(arr) - 1
    while lo ≤ hi
        mid ← lo + (hi - lo) div 2
        if arr[mid] = target
            return mid
        else if arr[mid] < target
            lo ← mid + 1
        else
            hi ← mid - 1
    return -1

for i ← 0 to n - 1               // i = 0, 1, …, n-1
for i ← n - 1 down to 0          // counts backward
for each x in items              // values, not indexes
(a, b) ← (b, a)                  // swap via tuple

Code Explained

function name(params) — defines a function; body is indented
← — assignment; = is always a comparison
div — integer division (7 div 2 is 3)
length(arr) — number of elements
while / if / else — no colons or end
(a, b) — tuple: return or unpack several values

⚠ Common Mistakes

  • Reading = as assignment: here it only compares
  • Treating 0 to n as exclusive: it includes n, so write n - 1
  • Translating div as JavaScript /: use Math.floor(a / b)

✓ Tips & Best Practices

  • Map heap to your language's priority queue (heapq, PriorityQueue)
  • Write lo + (hi - lo) div 2 everywhere; it never overflows
  • Keep indentation strict in interview pseudocode

Quick Summary

  • ← — assign · = — compare
  • div / mod — integer quotient / remainder
  • for i ← a to b — inclusive range
  • (a, b) — return or unpack multiple values
