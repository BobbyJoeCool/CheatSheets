Data Structure Design Problems

Composing Structures to Hit a Target Cost

Design problems ask for a class whose operations each meet a time bound. The approach is always the same: list the operations, note what each needs (lookup by key → map, random index → array, order → list or tree, recency → queue), and combine structures so every operation is fast. Keep them in sync on every change.

Building Blocks

  • Map + array → O(1) insert, delete, random pick
  • Map of sorted lists + binary search → time-travel lookups
  • Stack of iterators → flatten nested lists

Insert / Delete / GetRandom O(1)

class RandomizedSet
    vals ← []                  // for random index
    pos ← new Map()            // value → index
    function insert(x)
        if pos.has(x) return false
        pos[x] ← length(vals)
        vals.append(x)
        return true
    function remove(x)
        if not pos.has(x) return false
        i ← pos[x]
        last ← vals[length(vals) - 1]
        (vals[i], pos[last]) ← (last, i)   // fill hole
        vals.pop()
        pos.delete(x)
        return true
    function getRandom()
        return vals[randomInt(0, length(vals) - 1)]

Time-Based Key-Value Store

class TimeMap
    store ← map key → list of (t, value)
    function set(key, value, t)  // t increasing
        store[key].append((t, value))
    function get(key, t)
        list ← store[key]
        i ← upperBound(list, t) - 1
        if i < 0 return ""       // nothing ≤ t
        return list[i].value
class HitCounter                 // last 300 s
    q ← new Queue()
    function hit(t)
        q.enqueue(t)
    function getHits(t)
        while not q.isEmpty() and q.front() ≤ t - 300
            q.dequeue()
        return length(q)

Flatten Nested List Iterator

class NestedIterator
    stack ← [iterator(nestedList)]
    function hasNext()
        while not stack.isEmpty()
            it ← stack.peek()
            if not it.hasNext()
                stack.pop()                   // level done
            else if it.peekNext() is an integer
                return true
            else                              // go deeper
                stack.push(iterator(it.next().getList()))
        return false
    function next()
        return stack.peek().next()

⚠ Common Mistakes

  • RandomizedSet: deleting from the middle (O(n)) instead of swapping in the last item
  • Updating one structure but not the other: the map points at stale indexes
  • Nested iterator: doing all the flattening in the constructor when lazy is expected

✓ Tips & Best Practices

  • Write each operation's target Big O next to its signature
  • Remove the last element after updating its index in the map
  • Heavy traffic: keep per-second buckets, not every hit

Quick Summary

  • map + array — O(1) random access
  • sorted list + binary search — by timestamp
  • stack of iterators — nested data
  • queue — sliding time window
