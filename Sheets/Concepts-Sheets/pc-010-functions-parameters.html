Sheet 010

Functions & Parameters

define / call · return values · pass by value vs reference · default params · pure vs side effects · call stack frames

Reusable Blocks of Logic

A function names a piece of logic, takes parameters, and returns a value. Each call gets its own stack frame holding its parameters and locals, which is why recursion works. Whether a function can change the caller's data depends on how arguments are passed.

Vocabulary

  • Parameter: the name in the definition
  • Argument: the value passed in a call
  • Pure: same input → same output, no side effects
  • Side effect: changes something outside the function

Defining and Calling

function area(width, height ← 1)     // height has a default
    return width * height
area(3, 4)                           // 12
area(5)                              // 5

function minMax(arr)                 // return several values
    return (min(arr), max(arr))
(lo, hi) ← minMax([4, 1, 9])         // lo = 1, hi = 9

function addOne(n)                   // n is a copy of the value
    n ← n + 1
x ← 5
addOne(x)                            // x is still 5

function addItem(list)               // list refers to caller's object
    list.append(99)
a ← [1]
addItem(a)                           // a is now [1, 99]

Code Explained

height ← 1 — default used when argument is omitted
return (a, b) — tuple return, unpacked by caller
numbers — copied, so the caller can't see changes
objects — the reference is copied; mutations are shared
reassigning a parameter never changes the caller's variable

Argument Passing

Pure vs Impure

FunctionPure?
square(x)yes
sort(list) in placeno: mutates input
now() / random()no: output varies
print(x)no: I/O side effect

⚠ Common Mistakes

  • Using a mutable default (list ← []) in Python: the same list is shared across calls
  • Expecting n ← n + 1 inside a function to change the caller's number
  • Forgetting return: the caller gets null / None / undefined

✓ Tips & Best Practices

  • Keep functions small: one job, a name that says what it returns
  • Prefer returning new values over mutating arguments unless performance needs it
  • In interviews, write helper functions for each step; it reads like the plan

Quick Summary

  • function f(a, b ← 1) — params with default
  • return (x, y) — multiple results
  • by sharing — mutations visible, rebinding not
  • pure — easier to test and reason about
