Programming Paradigms

imperative · procedural · object-oriented · functional · declarative · event-driven · multi-paradigm languages

Styles of Programming

A paradigm is a way of organizing code. Imperative code says *how*: step-by-step statements that change state. Declarative code says *what*: describe the result and let the language work out the steps. Most modern languages are multi-paradigm, so you pick the style that fits each problem.

Quick Facts

  • Procedural = imperative code organized into functions
  • OOP bundles data and the functions that act on it
  • Functional avoids mutation; functions are values
  • SQL, HTML, and regex are declarative

One Task, Several Paradigms

// Task: sum the squares of the even numbers in nums

// Imperative / procedural: HOW, step by step
total ← 0
for each n in nums
    if n mod 2 = 0
        total ← total + n * n

// Functional: compose transformations, no mutation
total ← sum(map(filter(nums, isEven), square))

// Declarative (SQL): describe the result
SELECT SUM(n * n) FROM nums WHERE n % 2 = 0

// Object-oriented: data + behavior in one object
total ← numberList.sumOfEvenSquares()

// Event-driven: code runs when something happens
button.onClick(lambda: show(total))

Code Explained

imperative — explicit loop and a changing total
functional — filter → map → sum pipeline
declarative — no loop at all; engine decides
OOP — the object owns the logic
event-driven — a callback waits for an event

⚠ Common Mistakes

  • Forcing every problem into classes: a 10-line script doesn't need a hierarchy
  • Mixing mutation into a map callback: hard to read and breaks parallel use
  • Thinking declarative means slower: SQL engines often beat hand-written loops

✓ Tips & Best Practices

  • Use imperative loops when you need early exit or index tricks
  • Use functional pipelines for clear transform-filter-aggregate steps
  • Interview solutions are usually imperative; know the functional form too

Quick Summary

  • imperative — how, with changing state
  • declarative — what, not how
  • OOP — data + behavior together
  • functional — pure functions and pipelines
