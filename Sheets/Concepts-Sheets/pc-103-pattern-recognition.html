From Problem Wording to Technique

Scan the problem for signals: the shape of the input, the words in the question, and the size limits. Each row maps a signal to the pattern that usually solves it and the sheet that covers it. Read the constraints first; when two patterns fit, they usually break the tie (Sheet 026).

⚠ Common Mistakes

  • Matching on one keyword and ignoring the constraints
  • Using BFS distances on weighted edges, or DP where greedy suffices
  • Coding before confirming the chosen pattern fits a small example

✓ Tips & Best Practices

  • Underline input shape and question words, then try that pattern's template (104)
  • Keep a log of problems you misclassified; it sharpens recognition fast
  • Combine patterns: sort + two pointers, prefix sums + hash map
