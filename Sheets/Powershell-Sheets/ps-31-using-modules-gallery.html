Sheet 31

Using Modules & the PowerShell Gallery

Import-Module · Get-Module -ListAvailable · $env:PSModulePath · Install-PSResource · Install-Module · #Requires -Modules

Overview

A module is a package of commands. Modules in any folder on $env:PSModulePath autoload the first time you use one of their commands, so explicit Import-Module is rarely needed. Get new modules from the PowerShell Gallery with Install-PSResource (PSResourceGet, built into 7.4+) or the older Install-Module.

Notes

  • Install for yourself with -Scope CurrentUser: no admin needed
  • Install-PSResource defaults to CurrentUser scope
  • PSGallery is untrusted by default, so you get a prompt
  • 5.1 and 7 have separate user module folders

Finding, Installing, Loading

Get-Module                               # loaded in this session
Get-Module -ListAvailable Az*            # installed on disk
$env:PSModulePath -split [IO.Path]::PathSeparator

Find-PSResource -Name ImportExcel        # search the Gallery
Install-PSResource -Name ImportExcel     # CurrentUser by default
Install-PSResource Pester -Version '[5.0,6.0)'   # version range
Update-PSResource ImportExcel
Get-InstalledPSResource
Set-PSResourceRepository -Name PSGallery -Trusted   # no prompt

Install-Module Az -Scope CurrentUser     # PowerShellGet v2 style
Import-Module ActiveDirectory            # explicit import
Import-Module .\MyTools -Force           # reload after edits
Get-Command -Module ImportExcel

#Requires -Modules @{ ModuleName = 'Az.Accounts'; ModuleVersion = '2.0' }

Code Explained

Get-Module -ListAvailable — everything installed, loaded or not
PSModulePath — folders searched for modules, in order
Install-PSResource — PSResourceGet; faster successor to PowerShellGet
'[5.0,6.0)' — NuGet version range: ≥ 5.0 and < 6.0
-Force — reimport so code changes take effect
#Requires -Modules — fail early if a module or version is missing

⚠ Common Mistakes

  • Running Install-Module without -Scope CurrentUser in 5.1. It needs admin for AllUsers and fails otherwise
  • Editing a module and re-running Import-Module without -Force. The old version stays loaded
  • Installing a module in 5.1 and expecting pwsh to see it. The user module folders differ

✓ Tips & Best Practices

  • Pin versions in scripts with #Requires -Modules so upgrades don’t break you
  • Use Save-PSResource to vet a module’s code before installing it
  • Use Get-Command -Module X to see what a new module gives you

Quick Summary

  • $env:PSModulePath — where modules autoload from
  • Install-PSResource / Install-Module — get from PSGallery
  • Get-Module -ListAvailable — what’s installed
  • #Requires -Modules — declare dependencies
