Sheet 05

Comments & Comment-Based Help

# · <# #> · .SYNOPSIS · .PARAMETER · .EXAMPLE · #region

Overview

Use # for single-line comments and <# … #> for blocks. A block comment placed at the top of a function or script with special help keywords becomes real help: Get-Help shows it exactly like a built-in cmdlet's help, and VS Code shows it on hover.

Notes

  • Help block goes just inside the function body or just above function
  • Keywords start with a dot and are case-insensitive
  • .PARAMETER names must match the actual parameters
  • #region/#endregion create foldable sections in VS Code

Comment-Based Help

function Get-DiskFree {
    <#
    .SYNOPSIS
        Shows free space per drive.
    .DESCRIPTION
        Returns one object per fixed drive with size and free GB.
    .PARAMETER MinFreeGB
        Only show drives with less free space than this.
    .EXAMPLE
        Get-DiskFree -MinFreeGB 20
    #>
    param([int]$MinFreeGB = [int]::MaxValue)
    Get-CimInstance Win32_LogicalDisk -Filter 'DriveType=3' |
        Where-Object { $_.FreeSpace / 1GB -lt $MinFreeGB }
}
Get-Help Get-DiskFree -Examples

Code Explained

<# … #> — block comment; can span many lines
.SYNOPSIS — one-line summary shown in Get-Help lists
.PARAMETER name — one block per parameter
.EXAMPLE — code line, then a description line
# TODO — ordinary comment; VS Code can highlight TODOs
Get-Help -Examples — works on your function right away

Help Keywords

KeywordPurpose

.DESCRIPTIONfull explanation
.PARAMETER xdescribe parameter x
.EXAMPLEusage + explanation
.NOTESextra info
.LINKrelated URL or command

⚠ Common Mistakes

  • Leaving two or more blank lines between a help block and function. Help placed above a function is ignored unless it sits right above the keyword
  • Misspelling a .PARAMETER name. The entry silently doesn’t show; names must match exactly
  • Using # comments for help. Only <# #> blocks with dot-keywords are parsed as help

✓ Tips & Best Practices

  • Put help inside the function, right after {, so it travels with the code when moved
  • Write at least .SYNOPSIS and one .EXAMPLE; it’s the part people actually read
  • Use #region to group a long script into sections you can fold

Quick Summary

  • # — single-line comment
  • <# #> — block comment
  • .SYNOPSIS / .EXAMPLE — comment-based help keywords
  • #region — foldable section
