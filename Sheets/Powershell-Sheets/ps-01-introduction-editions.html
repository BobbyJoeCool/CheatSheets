Introduction & Editions

pwsh · $PSVersionTable · winget / brew · Set-ExecutionPolicy · .ps1 · #Requires

Overview

PowerShell is a cross-platform shell and scripting language built on .NET. Its big idea is that commands pass objects down the pipeline, not text, so you filter and sort by property instead of parsing columns. There are two editions: Windows PowerShell 5.1 (powershell.exe, .NET Framework, Windows only, maintenance mode) and PowerShell 7 (pwsh, modern .NET, Windows/macOS/Linux). Both can be installed side by side.

Notes

  • Script files use .ps1; modules .psm1; manifests .psd1
  • Commands are case-insensitive: get-process = Get-Process
  • This set targets PowerShell 7.4+; 5.1 gaps are flagged as 5.1:
  • VS Code + the PowerShell extension is the standard editor (ISE is 5.1-only)

Install, Check, Run

# Install PowerShell 7
winget install --id Microsoft.PowerShell     # Windows
brew install powershell/tap/powershell       # macOS
pwsh                                         # start a session

$PSVersionTable.PSVersion     # 7.4.6 (Major.Minor.Patch)
$PSVersionTable.PSEdition     # Core   (5.1 shows Desktop)

# hello.ps1
#Requires -Version 7.0
param([string]$Name = 'World')
"Hello, $Name!"                # implicit output → Hello, World!

.\hello.ps1 -Name Bob          # Hello, Bob!  (.\ is required)
pwsh -File ./hello.ps1         # run from another shell

Code Explained

winget / brew — official package installs; Linux uses apt/dnf repos or Snap
$PSVersionTable — hashtable of version, edition, OS details
#Requires — script refuses to run if the version/module/admin check fails
param() — script-level parameters, same syntax as functions
.\hello.ps1 — the current folder is not on the path, so prefix .\ or ./

⚠ Common Mistakes

  • Typing script.ps1 without .\ fails with “not recognized”. PowerShell never runs scripts from the current folder implicitly, as a safety feature
  • Assuming 5.1 and 7 share modules. 7 loads most 5.1 modules, but some Windows-only ones need -UseWindowsPowerShell
  • Using Set-ExecutionPolicy Unrestricted machine-wide to fix one script. Use -Scope CurrentUser RemoteSigned or Unblock-File

✓ Tips & Best Practices

  • Check $PSVersionTable first when an example doesn’t work. Most “broken” snippets are 7-only features run in 5.1
  • Set RemoteSigned per user: Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
  • Add #Requires -Version 7.0 to scripts that use 7-only syntax so they fail with a clear message

Quick Summary

  • pwsh — PowerShell 7, cross-platform; powershell is 5.1
  • $PSVersionTable — version and edition info
  • .\script.ps1 — run a script; needs a path prefix
  • Set-ExecutionPolicy — controls whether scripts may run (Windows)
