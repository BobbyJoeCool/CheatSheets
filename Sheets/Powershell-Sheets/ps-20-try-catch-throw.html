try / catch / finally & throw

try / catch / finally · catch [Type] · $_.Exception.Message · throw · rethrow · trap

Overview

try runs code, catch handles terminating errors, and finally always runs (cleanup). Catch specific exception types first, then a general catch. Inside catch, $_ is the ErrorRecord. Use throw to raise your own terminating error, or a bare throw to rethrow.

Notes

  • Only terminating errors reach catch: add -ErrorAction Stop
  • First matching catch wins; put specific types first
  • finally runs even after return, break or Ctrl+C
  • Find a type to catch with $_.Exception.GetType().FullName

Structured Error Handling

try {
    $data = Get-Content .\config.json -ErrorAction Stop | ConvertFrom-Json
    $stream = [IO.File]::OpenRead($data.LogPath)
}
catch [System.Management.Automation.ItemNotFoundException] {
    Write-Warning "No config file: $($_.Exception.Message)"
}
catch [System.ArgumentException], [System.FormatException] { 'Bad config' }
catch {
    Write-Error "Unexpected: $($_.Exception.GetType().FullName)"
    throw                       # rethrow the same error
}
finally {
    if ($stream) { $stream.Dispose() }   # always runs
}

if (-not $Path) { throw 'Path is required' }
throw [System.IO.FileNotFoundException]::new('Missing', $Path)

Code Explained

-ErrorAction Stop — needed so the cmdlet error is catchable
catch [Type] — matches that type or any subclass
[A], [B] — one block can catch several types
$_.Exception — the .NET exception: .Message, .InnerException
throw — bare in catch = rethrow, preserving details
finally — close files, connections, restore settings

⚠ Common Mistakes

  • Catching but not rethrowing in a library function. The caller thinks it worked; log and throw
  • Using throw $_ instead of throw. It works but resets details in some cases; a bare throw keeps the original
  • Putting cleanup after the try block instead of in finally. It’s skipped when an error escapes

✓ Tips & Best Practices

  • Log $_.ScriptStackTrace in catch blocks to see where it failed
  • Run the failing line once, then check $Error[0].Exception.GetType() to learn which type to catch
  • Keep try blocks small so you know which line failed

Quick Summary

  • try / catch / finally — handle terminating errors, always clean up
  • catch [Type] — specific first, general last
  • $_.Exception.Message — the error text
  • throw — raise, or rethrow when bare
