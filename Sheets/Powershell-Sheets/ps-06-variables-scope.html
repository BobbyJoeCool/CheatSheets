Sheet 06

Variables & Scope

$var · ${odd name} · New-Variable · $global: / $script: · $env: · Remove-Variable

Overview

Variables start with $, need no declaration, and can hold any object. Names are case-insensitive. PowerShell uses dynamic scope: a child scope (function, script block, script) can read its parent's variables, but assigning creates a new local copy unless you name a scope with a modifier like $script:.

Notes

  • $Name and $name are the same variable
  • Unset variables are $null (error only under Set-StrictMode)
  • Environment variables live on the env: drive
  • Variables persist for the session; scripts get their own scope

Variables in Action

$count = 5                     # create / assign
$a, $b = 1, 2                  # multiple assignment
$a, $b = $b, $a                # swap → a=2, b=1
${my var} = 'ok'               # braces allow spaces/symbols

New-Variable -Name Pi2 -Value 6.283 -Option ReadOnly
Set-Variable  -Name Max -Value 10 -Option Constant

$env:APP_MODE = 'dev'          # set for this process
$env:PATH -split [IO.Path]::PathSeparator   # one path per line

$total = 0
function Add-One { $total = $total + 1 }       # local copy
function Add-Two { $script:total += 2 }        # script scope
Add-One; Add-Two; $total                       # 2

Get-Variable c*; Test-Path variable:count      # True
Remove-Variable count

Code Explained

$a, $b = 1, 2 — spreads values across variables; extras go to the last
${my var} — needed for names with spaces, dashes, or :
ReadOnly — change with -Force; Constant can never change
$env: — process-level; persists only while the session lives
$script:total — assigns in the script scope instead of the function
variable: — the variable drive, usable with Test-Path

⚠ Common Mistakes

  • Expecting a function to change an outer variable by assignment. It creates a local copy; return the value or use $script:
  • Naming a variable $input, $args or $PSItem. These are automatic variables and get overwritten
  • Setting $env:PATH and expecting it to persist. It lasts only for the process; use [Environment]::SetEnvironmentVariable with 'User'

✓ Tips & Best Practices

  • Return values from functions instead of reaching into $global:
  • Turn on Set-StrictMode -Version Latest in scripts to catch typos in variable names
  • Use $PSDefaultParameterValues for session-wide parameter defaults

Quick Summary

  • $x = value — create or reassign; no declaration
  • $script: / $global: — write to an outer scope
  • $env:NAME — read or set environment variables
  • New-Variable -Option — ReadOnly or Constant
