Advanced Functions & Parameter Validation

[CmdletBinding()] · [Parameter(Mandatory)] · ParameterSetName · [ValidateSet()] · [ValidateScript()] · -Verbose

Overview

Adding [CmdletBinding()] turns a function into an advanced function that behaves like a compiled cmdlet: it gets common parameters (-Verbose, -ErrorAction…), and its parameters can be mandatory, positional, grouped into sets, and validated before your code runs. Validation attributes replace most hand-written input checks.

Notes

  • Any [Parameter()] attribute also makes it advanced
  • Mandatory prompts if the caller omits it
  • Validation failures throw before the body runs
  • $PSCmdlet.ParameterSetName tells you which set was used

An Advanced Function

function New-AppUser {
    [CmdletBinding(DefaultParameterSetName = 'ByName')]
    param(
        [Parameter(Mandatory, Position = 0, ParameterSetName = 'ByName')]
        [ValidateNotNullOrEmpty()]
        [string]$UserName,

        [Parameter(Mandatory, ParameterSetName = 'ById')]
        [ValidatePattern('^\d{6}$')] [string]$EmployeeId,

        [ValidateSet('Dev', 'Test', 'Prod')] [string]$Environment = 'Dev',

        [ValidateScript({ Test-Path $_ -PathType Container })]
        [string]$HomeDir = $HOME
    )
    Write-Verbose "Set: $($PSCmdlet.ParameterSetName), env: $Environment"
}

Code Explained

DefaultParameterSetName — set used when the input is ambiguous
Mandatory — required; same as Mandatory = $true
Position = 0 — allows New-AppUser bob without -UserName
ParameterSetName — UserName and EmployeeId can’t be used together
[ValidateSet()] — also gives tab completion of the values
Write-Verbose — shown only when called with -Verbose

⚠ Common Mistakes

  • Testing if ($Days) to see if a parameter was passed. Defaults and 0 fool it; check $PSBoundParameters keys
  • Giving a Mandatory parameter a default value. The default is ignored; the user is prompted anyway
  • Writing manual if (-not ($x -in …)) { throw } checks that a [ValidateSet()] does better

✓ Tips & Best Practices

  • Add [Alias('CN')] to support familiar alternate parameter names
  • Use [ValidateScript({ … })] with a throw 'message' inside to give a clear error
  • Use [ArgumentCompleter()] for dynamic tab completion (e.g. server names)

Quick Summary

  • [CmdletBinding()] — cmdlet-like function + common params
  • [Parameter(Mandatory, Position=0)] — required, positional
  • ParameterSetName — mutually exclusive groups
  • [Validate*()] — check input before the body runs
