Sheet 37

Debugging & Testing

Set-StrictMode · Set-PSBreakpoint · Wait-Debugger · Invoke-ScriptAnalyzer · Pester Describe / It · Should / Mock

Overview

Catch bugs at three levels. Set-StrictMode turns silent mistakes (undefined variables, missing properties) into errors. The debugger (VS Code F5, or breakpoints in the console) lets you step through code. PSScriptAnalyzer lints for bad practices, and Pester runs automated tests.

Notes

  • Install: Install-PSResource Pester, PSScriptAnalyzer
  • Windows ships Pester 3.x; current syntax is Pester 5
  • Test files are named *.Tests.ps1
  • In VS Code: F9 breakpoint, F5 run, F10/F11 step

Strict Mode, Breakpoints, Pester

Set-StrictMode -Version Latest           # undefined vars → error
Set-PSBreakpoint -Script .\deploy.ps1 -Line 42
Set-PSBreakpoint -Variable total -Mode Write   # break when it changes
Invoke-ScriptAnalyzer -Path . -Recurse -Severity Warning, Error

# Get-Greeting.Tests.ps1  (Pester 5)
BeforeAll { . $PSScriptRoot/Get-Greeting.ps1 }
Describe 'Get-Greeting' {
    It 'greets by name' { Get-Greeting -Name Ada | Should -Be 'Hello, Ada!' }
    It 'rejects empty names' { { Get-Greeting -Name '' } | Should -Throw }
    It 'logs the call' {
        Mock Write-Log {}
        Get-Greeting -Name Bob
        Should -Invoke Write-Log -Times 1 -Exactly
    }
}
Invoke-Pester -Output Detailed

Code Explained

-Version Latest — strictest checks; scoped to the script
-Mode Write — breaks whenever the variable is assigned
BeforeAll — loads the code under test before the tests run
Should -Be — assertion; failure message shows expected vs actual
{ … } | Should -Throw — wrap code in a script block to test errors
Mock / Should -Invoke — replace a command and verify it was called

⚠ Common Mistakes

  • Putting code outside BeforeAll/It in Pester 5. It runs during discovery, not during the test run
  • Leaving Set-StrictMode off and then chasing a typo like $Totl. Strict mode would flag it immediately
  • Testing output text instead of objects. Assert on properties so formatting changes don’t break tests

✓ Tips & Best Practices

  • Add Invoke-ScriptAnalyzer and Invoke-Pester -CI to your build pipeline
  • Use Wait-Debugger in code that runs in a job or remote session to attach there
  • Use $PSDebugContext or Set-PSDebug -Trace 1 for quick line tracing

Quick Summary

  • Set-StrictMode -Version Latest — catch silent mistakes
  • Set-PSBreakpoint / VS Code F9 — pause and inspect
  • Invoke-ScriptAnalyzer — lint scripts
  • Describe / It / Should / Mock — Pester tests
