Sheet 23

Pipeline Input & ShouldProcess

ValueFromPipeline · ByPropertyName · begin / process / end · clean · SupportsShouldProcess · -WhatIf / -Confirm

Overview

To accept pipeline input, mark a parameter ValueFromPipeline (whole objects) or ValueFromPipelineByPropertyName (match a property by name), then put per-item work in a process block. Functions that change things should support -WhatIf and -Confirm by declaring SupportsShouldProcess and checking $PSCmdlet.ShouldProcess().

Notes

  • Without a process block, the body runs once, in end
  • begin runs once before input, end once after
  • clean (7.3+) always runs, even on Ctrl+C or errors
  • ByPropertyName also matches parameter [Alias()] names

Pipeline-Aware, Safe Function

function Remove-OldLog {
    [CmdletBinding(SupportsShouldProcess, ConfirmImpact = 'Medium')]
    param([Parameter(Mandatory, ValueFromPipeline)] [IO.FileInfo[]]$File,
          [int]$Days = 30)
    begin   { $cutoff = (Get-Date).AddDays(-$Days); $n = 0 }
    process {
        foreach ($f in $File) {
            if ($f.LastWriteTime -lt $cutoff -and
                $PSCmdlet.ShouldProcess($f.FullName, 'Delete')) {
                Remove-Item $f.FullName; $n++
            }
        }
    }
    end { Write-Verbose "Removed $n file(s)" }
}
Get-ChildItem C:\Logs -File | Remove-OldLog -Days 7 -WhatIf

Code Explained

SupportsShouldProcess — adds -WhatIf and -Confirm parameters
ConfirmImpact — prompts automatically when ≥ $ConfirmPreference (High)
ValueFromPipeline — each piped FileInfo binds to $File
foreach ($f in $File) — also handles -File $a, $b passed directly
ShouldProcess(target, action) — returns False under -WhatIf and prints “What if: …”

⚠ Common Mistakes

  • Putting the work outside process. Only the last piped item is handled, because the body runs once in end
  • Calling Remove-Item before checking ShouldProcess. -WhatIf then deletes for real
  • Typing a pipeline parameter as [string] when callers pass arrays directly; use [string[]] plus foreach

✓ Tips & Best Practices

  • Test new destructive functions with -WhatIf first, every time
  • Use ByPropertyName so output from Get-ADUser, Import-Csv etc. binds by column name
  • Use [OutputType([pscustomobject])] so tooling knows what you return

Quick Summary

  • ValueFromPipeline / …ByPropertyName — accept input
  • begin / process / end — setup, per item, wrap up
  • SupportsShouldProcess — add -WhatIf / -Confirm
  • $PSCmdlet.ShouldProcess() — guard every change
