Sheet 03

Profiles & PSReadLine

$PROFILE · prompt · Set-PSReadLineOption · Set-PSReadLineKeyHandler · Get-History · Oh My Posh

Overview

A profile is a script that runs every time PowerShell starts, where you put aliases, functions, modules and your prompt. PSReadLine is the module that powers the interactive line editor: syntax colors, history search, predictive IntelliSense and key bindings. Both are per-user and per-host, and both make the shell feel like your own.

Notes

  • $PROFILE points to CurrentUserCurrentHost; it may not exist yet
  • 5.1 and 7 use different profile folders
  • Start with pwsh -NoProfile to rule out profile problems
  • Keep profiles fast; slow imports delay every new tab

Profile Setup

$PROFILE                        # path to your profile script
Test-Path $PROFILE              # False on a fresh install
New-Item $PROFILE -ItemType File -Force
code $PROFILE                   # edit in VS Code
. $PROFILE                      # reload without restarting

# --- inside the profile ---
Set-Alias ll Get-ChildItem
function prompt { "PS $(Split-Path -Leaf $PWD)> " }

Set-PSReadLineOption -PredictionSource HistoryAndPlugin
Set-PSReadLineOption -PredictionViewStyle ListView
Set-PSReadLineOption -EditMode Windows      # or Emacs / Vi
Set-PSReadLineKeyHandler -Key Tab -Function MenuComplete
Set-PSReadLineKeyHandler -Key UpArrow -Function HistorySearchBackward

oh-my-posh init pwsh | Invoke-Expression    # themed prompt

Code Explained

$PROFILE — path string with extra properties for all four profiles
New-Item -Force — creates the file and any missing folders
. $PROFILE — dot-sources it so changes apply to this session
function prompt — whatever it returns becomes your prompt
PredictionSource — ghost-text suggestions from history (and plugins)
MenuComplete — Tab shows a selectable menu, like zsh

The Four Profiles

⚠ Common Mistakes

  • Editing the 5.1 profile and wondering why pwsh ignores it. Each edition has its own $PROFILE path
  • Putting heavy Import-Module calls in the profile. Modules autoload on first use, so most imports are unnecessary
  • Assuming Clear-History removes saved history. PSReadLine keeps its own file at HistorySavePath

✓ Tips & Best Practices

  • Use $PROFILE.CurrentUserAllHosts for settings you want in both the terminal and VS Code
  • Measure startup with pwsh -NoProfile -Command "Measure-Command { . $PROFILE }"
  • Run Get-PSReadLineKeyHandler to list every binding and its key

Quick Summary

  • $PROFILE — startup script path; create it with New-Item -Force
  • function prompt — define a custom prompt
  • Set-PSReadLineOption — predictions, edit mode, colors
  • Ctrl+R / Get-History — find and rerun past commands
