Hashtables & Dictionaries

@{} · [ordered]@{} · .ContainsKey() · .GetEnumerator() · Dictionary[string,int] · HashSet[T]

Overview

A hashtable stores key/value pairs with fast lookup by key. Keys are case-insensitive strings by default and order isn't kept; use [ordered]@{} when order matters. Hashtables are everywhere in PowerShell: splatting, calculated properties, [PSCustomObject] literals, config data and lookup tables.

Notes

  • Access with dot or index: $h.Name or $h['Name']
  • Missing keys return $null, no error
  • You can’t add keys while looping over .Keys
  • For typed keys/values use Dictionary[K,V]

Working with Hashtables

$ages = @{ Ada = 36; Linus = 54 }
$ages.Ada                         # 36
$ages['Linus']                    # 54
$ages.Grace = 85                  # add or update
$ages.Add('Alan', 41)             # error if key exists
$ages.ContainsKey('Ada')          # True
$ages.Remove('Alan')

foreach ($kv in $ages.GetEnumerator()) { "$($kv.Key) is $($kv.Value)" }
$ages.GetEnumerator() | Sort-Object Value -Descending

$cfg = [ordered]@{ Name = 'web'; Port = 443; Tls = $true }
$cfg.Keys                         # Name Port Tls (in order)

$counts = [System.Collections.Generic.Dictionary[string,int]]::new()
$counts['err'] = 1
$counts.ContainsKey('ERR')         # False (case-sensitive)
$seen = [System.Collections.Generic.HashSet[string]]::new()
$seen.Add('a'); $seen.Add('a')    # True; False (duplicate)

Code Explained

$ages.Grace = 85 — assignment adds a new key or replaces a value
.Add(k, v) — strict add; throws on duplicates
.GetEnumerator() — needed to pipe or sort key/value pairs
[ordered] — keeps insertion order (OrderedDictionary)
Dictionary[string,int] — typed; keys are case-sensitive by default
HashSet[string] — unique values; Add returns False on duplicates

⚠ Common Mistakes

  • Piping a hashtable and expecting one item per key. It goes through as one object; use .GetEnumerator()
  • Modifying $h inside foreach ($k in $h.Keys). The collection changed error; loop over @($h.Keys) instead
  • Expecting @{} to keep key order in output. Use [ordered]@{}

✓ Tips & Best Practices

  • Use a hashtable lookup instead of a long switch for code-to-name mapping
  • Use Group-Object Id -AsHashTable -AsString to index records by key
  • Use $h.Keys | Sort-Object for stable, readable output

Quick Summary

  • @{ k = v } — create; $h.k / $h['k'] — read
  • [ordered]@{} — keep insertion order
  • .ContainsKey() / .Remove() / .GetEnumerator()
  • Dictionary[K,V] / HashSet[T] — typed .NET collections
