Sheet 32

Writing Modules

.psm1 · Export-ModuleMember · New-ModuleManifest · FunctionsToExport · Public / Private · Publish-PSResource

Overview

A script module is a .psm1 file in a folder with the same name, optionally with a .psd1 manifest describing version, author, dependencies and exports. Keep one function per file in Public and Private folders and dot-source them from the .psm1. Place the folder on $env:PSModulePath and it autoloads.

Notes

  • Folder name = module name = file base name
  • Without exports, every function in the .psm1 is public
  • List exports explicitly; * slows autoloading
  • Bump ModuleVersion on every release

Module Layout & Manifest

# MyTools\                       ← folder on $env:PSModulePath
#   MyTools.psd1  MyTools.psm1
#   Public\Get-Thing.ps1   Private\Format-Thing.ps1

# --- MyTools.psm1 ---
$public  = @(Get-ChildItem $PSScriptRoot\Public\*.ps1)
$private = @(Get-ChildItem $PSScriptRoot\Private\*.ps1)
foreach ($file in $public + $private) { . $file.FullName }
Export-ModuleMember -Function $public.BaseName

# --- create the manifest ---
$m = @{
    Path = '.\MyTools\MyTools.psd1'; RootModule = 'MyTools.psm1'
    ModuleVersion = '1.0.0'; Author = 'Bob'
    FunctionsToExport = 'Get-Thing'; PowerShellVersion = '7.2'
}
New-ModuleManifest @m
Test-ModuleManifest .\MyTools\MyTools.psd1
Publish-PSResource -Path .\MyTools -ApiKey $env:PSGALLERY_KEY

Code Explained

folder layout — Public = exported, Private = helpers
. $file.FullName — dot-source each function into module scope
$public.BaseName — file names double as function names
RootModule — the .psm1 the manifest loads
FunctionsToExport — what users see; also drives autoload
Test-ModuleManifest — validates the .psd1 before publishing

⚠ Common Mistakes

  • Folder and .psm1 names don’t match. Import-Module by name then can’t find the module
  • Leaving FunctionsToExport = '*'. Works, but autoload must load the module to find commands
  • Exporting in the .psm1 but not the .psd1. The manifest’s list wins, so the function stays hidden

✓ Tips & Best Practices

  • Use Import-Module .\MyTools -Force -Verbose while developing to see what loads
  • Keep tests next to code: Tests\Get-Thing.Tests.ps1
  • Store the Gallery API key in a secret vault, never in the script

Quick Summary

  • .psm1 in a same-named folder — a module
  • .psd1 via New-ModuleManifest — metadata + exports
  • Public/Private + dot-sourcing — tidy layout
  • Publish-PSResource — release to a gallery
