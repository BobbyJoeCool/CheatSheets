Sheet 35

Jobs & Parallelism

Start-Job · Receive-Job · Start-ThreadJob · ForEach-Object -Parallel · -ThrottleLimit · $using:

Overview

PowerShell can run work in the background or in parallel. Start-Job runs code in a separate process (heavy, but isolated); Start-ThreadJob uses a thread in the same process (fast). ForEach-Object -Parallel (7.0+) is the easiest way to process a list concurrently. None of them see your variables unless you pass them with $using: or -ArgumentList.

Notes

  • Default -ThrottleLimit for -Parallel is 5
  • Job output is serialized: objects become property bags
  • -Parallel blocks run in separate runspaces
  • Parallel is only faster for slow I/O or CPU-heavy work

Background and Parallel Work

$job = Start-Job { param($p) Get-ChildItem $p -Recurse } -Arg C:\Logs
Get-Job                                  # State: Running / Completed
Wait-Job $job | Out-Null
$files = Receive-Job $job                # get output (once)
Remove-Job $job

$tj = Start-ThreadJob { Invoke-RestMethod https://api.github.com }
Receive-Job $tj -Wait -AutoRemoveJob

$servers = 'web01', 'web02', 'db01', 'db02'
$timeout = 2
$servers | ForEach-Object -Parallel {
    [PSCustomObject]@{ Server = $_
        Up = Test-Connection $_ -Count 1 -Quiet -TimeoutSeconds $using:timeout
    }
} -ThrottleLimit 10

$bg = Get-Process &                      # background operator (7+)

Code Explained

-ArgumentList — values passed to the block’s param()
Receive-Job — returns output once; -Keep to read again
-Wait -AutoRemoveJob — wait, collect and clean up in one call
$using:timeout — copies a caller variable into each parallel runspace
-ThrottleLimit 10 — maximum blocks running at once
& — end a pipeline with & to run it as a job

⚠ Common Mistakes

  • Referencing an outer variable in a job without $using:. It’s $null inside the job’s runspace
  • Modifying a shared collection from -Parallel blocks. Not thread-safe; output objects and collect them instead
  • Forgetting Receive-Job or Remove-Job. Output sits in memory and finished jobs pile up

✓ Tips & Best Practices

  • Prefer Start-ThreadJob over Start-Job unless you need process isolation
  • Tune -ThrottleLimit to the bottleneck: higher for network waits, ≈ cores for CPU
  • Use -AsJob on ForEach-Object -Parallel to keep the console free

Quick Summary

  • Start-Job / Receive-Job — background process
  • Start-ThreadJob — lightweight background thread
  • ForEach-Object -Parallel — concurrent pipeline (7+)
  • $using: — pass outer variables in
