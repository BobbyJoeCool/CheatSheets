Sheet 19

Errors & ErrorAction

non-terminating · -ErrorAction Stop · $ErrorActionPreference · $Error[0] · -ErrorVariable · Get-Error

Overview

PowerShell has two kinds of errors. A non-terminating error (most cmdlet errors) is reported and the command keeps going with the next item. A terminating error stops the statement and can be caught with try/catch. -ErrorAction Stop turns a non-terminating error into a terminating one.

Notes

  • $Error holds recent errors, newest first: $Error[0]
  • -ErrorAction is a common parameter on every cmdlet
  • Ignore hides the error and skips $Error; SilentlyContinue still logs it
  • Native exe failures set $LASTEXITCODE, not errors

Error Behavior

Get-Item a.txt, nope.txt, b.txt   # error for nope.txt; a, b still return

Get-Item nope.txt -ErrorAction SilentlyContinue   # quiet, still in $Error
Get-Item nope.txt -ErrorAction Ignore             # quiet, not recorded
Get-Item nope.txt -ErrorAction Stop               # terminating → catchable

Get-ChildItem C:\Windows -Recurse -ErrorAction SilentlyContinue `
    -ErrorVariable errs
$errs.Count                          # how many were skipped

$Error[0]                            # last error
$Error[0].InvocationInfo.ScriptLineNumber
Get-Error                            # detailed view (7+)

Write-Error 'Config missing' -Category ObjectNotFound
$ErrorActionPreference = 'Stop'      # whole script: all errors terminate

Code Explained

a.txt, nope.txt, b.txt — non-terminating: one bad item doesn’t stop the rest
SilentlyContinue — hide the message but keep a record
-ErrorVariable errs — collect this command’s errors; +errs appends
InvocationInfo — where the error happened: line, command
Get-Error — expands the full error record and inner exceptions
Write-Error — emit a non-terminating error from your code

⚠ Common Mistakes

  • Wrapping a cmdlet in try/catch without -ErrorAction Stop. Non-terminating errors skip the catch entirely
  • Using SilentlyContinue everywhere to hide noise. Real failures disappear; collect them with -ErrorVariable instead
  • Assuming git or robocopy failures throw. Check $LASTEXITCODE after native commands

✓ Tips & Best Practices

  • Set $ErrorActionPreference = 'Stop' at the top of automation scripts so nothing fails silently
  • Use $Error[0] | Format-List * -Force in 5.1 where Get-Error doesn’t exist
  • Use -ErrorVariable on long recursive scans to report skipped items at the end

Quick Summary

  • Non-terminating — reported, command continues
  • -ErrorAction Stop — make it terminating / catchable
  • $Error[0] / Get-Error — inspect the last error
  • -ErrorVariable — capture errors for one command
