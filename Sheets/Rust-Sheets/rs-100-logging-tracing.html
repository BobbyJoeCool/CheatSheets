Logging with log & tracing

log facade · env_logger · tracing · #[instrument] · spans & events · tracing-subscriber · RUST_LOG

Structured Diagnostics

The log crate is a facade: libraries call info! / warn!, and the application picks a backend such as env_logger. tracing adds spans (timed scopes with fields) and structured key-value events, which matters for async code where many tasks interleave. Both are filtered with the RUST_LOG environment variable.

Key Points

  • Libraries depend only on log or tracing, never a backend
  • Levels: error, warn, info, debug, trace
  • RUST_LOG=info,my_crate=debug filters per module
  • tracing can also capture log records via tracing-log

log and tracing

// ---- log + env_logger ----
use log::{debug, error, info, warn};

fn init_simple() {
    env_logger::init();                     // reads RUST_LOG
    info!("starting v{}", env!("CARGO_PKG_VERSION"));
    warn!("disk at {}%", 91);
    debug!("only with RUST_LOG=debug");
    error!(target: "db", "connection lost");
}

// ---- tracing ----
use tracing::{info_span, instrument, Level};
use tracing_subscriber::EnvFilter;

#[instrument(skip(password), fields(user = %name))]
async fn login(name: &str, password: &str) -> bool {
    tracing::info!("checking credentials");  // inside the login span
    tracing::debug!(attempt = 1, "verifying");
    !password.is_empty()
}

#[tokio::main]
async fn main() {
    tracing_subscriber::fmt()
        .with_env_filter(EnvFilter::from_default_env())   // RUST_LOG
        .with_target(false)
        .init();

    let span = info_span!("request", id = 42, path = "/login");
    {
        let _enter = span.enter();      // sync code only: never across .await
        tracing::info!(status = 200, ms = 12.5, "handled"); // structured fields
    }
    let ok = login("ada", "secret").await;  // async: #[instrument] instead
    tracing::event!(Level::WARN, ok, "login finished");
}

Code Explained

env_logger::init() sets the log backend once
#[instrument] wraps a function in a span with its arguments
skip(password) keeps secrets out of logs
Fields like status = 200 are recorded as structured data

Coming From…

  • Java SLF4J facade + Logback (same split as log + env_logger)
  • Python logging module; structlog for structured events
  • Go log/slog structured logging; OpenTelemetry for spans

The Rust Way

  • println! for diagnostics → tracing::info! / log::info!
  • formatting values into the message → structured fields

⚠ Common Mistakes

  • Initializing a logger in a library
  • Logging secrets (use skip / redact)
  • Forgetting to initialize any backend, so nothing prints

✓ Tips & Best Practices

  • Use tracing for async services, log for small tools
  • Use % for Display and ? for Debug in fields: user = %name
  • Output JSON in production with .json() on the fmt subscriber
