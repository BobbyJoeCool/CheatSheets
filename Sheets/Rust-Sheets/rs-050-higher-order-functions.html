Higher-Order Functions

closures as arguments · returning impl Fn · Box<dyn Fn> · fn(i32) -> i32 pointers · composing functions · callbacks

Functions That Take or Return Functions

Pass closures with generic parameters (impl Fn) for zero-cost static dispatch. Return a single closure type with impl Fn. When you need to store different closures together or choose one at runtime, box them as Box<dyn Fn>, paying for a heap allocation and an indirect call.

Key Points

  • impl Fn in return position = one concrete hidden type
  • Two different closures need Box<dyn Fn> to share a type
  • Returned closures usually need move
  • Iterators are the most common higher-order API

Passing, Returning, Storing

fn make_adder(n: i32) -> impl Fn(i32) -> i32 {
    move |x| x + n                          // captures n by value
}
let add5 = make_adder(5);
println!("{}", add5(10));                   // 15

fn compose<A, B, C>(f: impl Fn(A) -> B, g: impl Fn(B) -> C) -> impl Fn(A) -> C {
    move |x| g(f(x))
}
let inc_then_double = compose(|x: i32| x + 1, |x| x * 2);
println!("{}", inc_then_double(4));         // 10

fn op(name: &str) -> Box<dyn Fn(f64, f64) -> f64> {
    match name {
        "add" => Box::new(|a, b| a + b),
        "pow" => Box::new(f64::powf),
        _ => Box::new(|_, _| f64::NAN),
    }
}
println!("{}", op("pow")(2.0, 10.0));       // 1024

struct Button {
    label: String,
    on_click: Vec<Box<dyn Fn(&str)>>,       // list of callbacks
}
impl Button {
    fn click(&self) { for cb in &self.on_click { cb(&self.label); } }
}
let b = Button {
    label: "OK".into(),
    on_click: vec![Box::new(|l| println!("clicked {l}")),
                   Box::new(|l| println!("log: {l}"))],
};
b.click();

let pipeline: [fn(i32) -> i32; 3] = [|x| x + 1, |x| x * 10, |x| x - 3];
println!("{}", pipeline.iter().fold(1, |v, f| f(v)));   // 17

Code Explained

make_adder returns a closure that remembers n
compose combines two functions into one
op returns different closures, so it boxes them
A Vec<Box<dyn Fn>> stores callbacks of different types

Coming From…

  • JavaScript functions are first-class values; no boxing decisions
  • Python decorators and functools.partial
  • C++ std::function ≈ Box<dyn Fn>; templates ≈ impl Fn

The Rust Way

  • Box<dyn Fn> parameters → impl Fn (no allocation)
  • returning Box<dyn Fn> for a single closure → impl Fn

Choosing a Form

FormDispatchUse
impl Fn (param)StaticMost callbacks
impl Fn (return)StaticOne closure type
Box<dyn Fn>DynamicMixed closures, storage
&dyn FnDynamicBorrowed, no alloc
fn(T) -> UPointerNo captures

⚠ Common Mistakes

  • Returning a closure without move (borrows a local: E0373)
  • Trying to return two different closures as impl Fn
  • Boxing closures when generics would do

✓ Tips & Best Practices

  • Add + Send + 'static to boxed callbacks used across threads
  • Prefer iterator adapters over hand-written HOFs
  • Use &dyn Fn to avoid generics bloat without allocating

Quick Summary

  • impl Fn — static, zero-cost
  • Box<dyn Fn> — mixed / stored
  • move for returned closures
  • compose small functions
