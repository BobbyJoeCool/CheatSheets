async / await & Futures

async fn · .await · Future trait · futures are lazy · async blocks · executors · async closures · async fn in traits

Asynchronous Rust

An async fn returns a Future, a value representing work that has not run yet. Futures are lazy: nothing happens until something .awaits them or an executor polls them. Rust has no built-in runtime; crates like Tokio provide the executor. Async suits many concurrent I/O tasks; threads suit CPU work.

Key Points

  • .await only works inside async code
  • Async closures async || {} are stable since Rust 1.85
  • async fn in traits is stable since 1.75
  • Blocking calls inside async code stall the executor

Under the Hood

  • The compiler turns each async fn into a state machine enum: one variant per .await point
  • Locals that live across .await are stored in that enum (its size can grow large)
  • Future::poll returns Ready(v) or Pending; a Waker tells the executor when to poll again
  • Futures may be self-referential, so polling requires Pin<&mut Self>

async Basics

use std::time::Duration;

async fn fetch_user(id: u32) -> String {
    tokio::time::sleep(Duration::from_millis(50)).await;   // yields, no block
    format!("user{id}")
}

#[tokio::main]
async fn main() {
    let fut = fetch_user(1);                // nothing runs yet (lazy)
    println!("created");
    let name = fut.await;                   // runs now
    println!("{name}");                     // user1

    let (a, b) = tokio::join!(fetch_user(2), fetch_user(3));   // concurrent
    println!("{a} {b}");                    // ~50ms total, not 100ms

    let block = async { fetch_user(4).await.len() };   // async block
    println!("{}", block.await);            // 5

    let greet = async |n: &str| format!("hi {n}");   // async closure (1.85)
    println!("{}", greet("Ada").await);
}

trait Store {
    async fn get(&self, key: &str) -> Option<String>;   // async fn in traits
}

Code Explained

Calling fetch_user(1) only builds a future
.await drives the future to completion
join! runs futures concurrently on one task
Async blocks and closures create futures inline

Coming From…

  • JavaScript async/await with Promises, but Promises start eagerly
  • Python asyncio coroutines are lazy like Rust futures
  • C# async Task<T>; Go uses goroutines instead of async

The Rust Way

  • std::thread::sleep in async code → tokio::time::sleep(...).await
  • awaiting independent futures one by one → join! / try_join!

⚠ Common Mistakes

  • Calling an async fn and forgetting .await (warning: unused future)
  • Blocking I/O or heavy CPU loops inside async tasks
  • Holding a std MutexGuard across .await (future not Send)

✓ Tips & Best Practices

  • Use spawn_blocking for blocking work (sheet 097)
  • Keep large locals out of futures that live across awaits
  • Pick one runtime (usually Tokio) per application

Quick Summary

  • async fn returns a Future
  • futures are lazy
  • .await drives them
  • runtime (Tokio) executes
