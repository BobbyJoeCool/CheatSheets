thiserror & anyhow

#[derive(Error)] · #[error("…")] · #[from] · anyhow::Result · .context() / with_context · bail! / ensure! · library vs application rule

The Two Error Crates

thiserror derives Display, Error and From for your error enums, ideal for libraries whose callers need to match on errors. anyhow gives applications one easy error type, anyhow::Error, that wraps anything and adds context messages. The common rule: thiserror in libraries, anyhow in binaries.

Key Points

  • cargo add thiserror anyhow
  • #[from] generates the From impl and sets source
  • .context("…") wraps an error with a message
  • {:#} prints the full chain on one line; {:?} adds a backtrace

thiserror and anyhow

// ---- library: thiserror ----
use thiserror::Error;

#[derive(Debug, Error)]
pub enum StoreError {
    #[error("item {0} not found")]
    NotFound(u64),
    #[error("database error")]
    Db(#[from] std::io::Error),
    #[error("invalid name {name:?}: {reason}")]
    Invalid { name: String, reason: &'static str },
}
pub fn get(id: u64) -> Result<String, StoreError> {
    if id == 0 { return Err(StoreError::NotFound(id)); }
    let data = std::fs::read_to_string("store.db")?;   // #[from] converts
    Ok(data)
}

// ---- application: anyhow ----
use anyhow::{bail, ensure, Context, Result};

fn load_config(path: &str) -> Result<u16> {
    let text = std::fs::read_to_string(path)
        .with_context(|| format!("reading {path}"))?;
    let port: u16 = text.trim().parse().context("port is not a number")?;
    ensure!(port >= 1024, "port {port} is privileged");
    if port == 9999 { bail!("port 9999 is reserved"); }
    Ok(port)
}

fn main() -> Result<()> {
    let port = load_config("port.txt")?;
    let item = get(7).context("loading item 7")?;
    println!("{port} {item}");
    Ok(())
}

Code Explained

#[error("…")] writes the Display impl; {0} and {name} use fields
#[from] adds From<io::Error> and source()
with_context builds the message only on failure
bail! returns an error; ensure! is a checked assert

Coming From…

  • Java exception wrapping: throw new X("msg", cause) ≈ .context()
  • Go fmt.Errorf("reading %s: %w", path, err)
  • Python raise ConfigError("msg") from e

The Rust Way

  • Box<dyn Error> in apps → anyhow::Result
  • anyhow::Error in a public library API → thiserror enum

⚠ Common Mistakes

  • Returning anyhow::Error from a library
  • Context messages that restate the cause instead of the action
  • Using context(format!(…)) (allocates even on success)

✓ Tips & Best Practices

  • Describe what you were doing: "reading config.toml"
  • Print errors with {:#} for one-line chains in logs
  • Use #[error(transparent)] to wrap another crate's error
