Deref & Drop

Deref / DerefMut · deref coercion · Drop · RAII · drop(x) early · drop order

Smart Pointer Traits

Deref lets a type act like a reference: *x and method calls pass through to the target, and deref coercion turns &String into &str or &Box<T> into &T automatically. Drop runs cleanup code when a value goes out of scope, the basis of RAII: files close, locks release and memory frees without manual calls.

Key Points

  • You cannot call x.drop() directly; use drop(x)
  • Fields drop after the struct's own drop, in declaration order
  • Locals drop in reverse order of declaration
  • Implement Deref only for smart-pointer-like types

Deref and Drop

use std::ops::{Deref, DerefMut};

struct Wrapper(Vec<i32>);
impl Deref for Wrapper {
    type Target = Vec<i32>;
    fn deref(&self) -> &Vec<i32> { &self.0 }
}
impl DerefMut for Wrapper {
    fn deref_mut(&mut self) -> &mut Vec<i32> { &mut self.0 }
}
let mut w = Wrapper(vec![3, 1, 2]);
w.push(4);                                  // Vec method via DerefMut
w.sort();                                   // slice method via two derefs
println!("{} {:?}", w.len(), *w);           // 4 [1, 2, 3, 4]

fn takes_str(s: &str) -> usize { s.len() }
let boxed: Box<String> = Box::new("hello".into());
println!("{}", takes_str(&boxed));          // &Box<String> → &String → &str

struct Guard(&'static str);
impl Drop for Guard {
    fn drop(&mut self) { println!("drop {}", self.0); }
}
{
    let _a = Guard("a");
    let _b = Guard("b");
    println!("in scope");
}                                           // drop b, then drop a

let early = Guard("early");
drop(early);                                // drop early (now)
println!("after early");

let _ = Guard("temp");                      // `_` drops immediately: drop temp
let _keep = Guard("kept");                  // lives to end of scope

Code Explained

Deref exposes Vec methods on Wrapper
Coercion follows &Box<String> down to &str
Locals drop in reverse order: b, then a
let _ = drops at once; _keep lives to scope end

Coming From…

  • C++ destructors and RAII (same idea); operator* / operator->
  • Java try-with-resources / AutoCloseable
  • Python with context managers; __del__ is unreliable

The Rust Way

  • explicit close() methods callers can forget → impl Drop
  • impl Deref to fake inheritance → composition + explicit methods

⚠ Common Mistakes

  • let _ = lock.lock() dropping the guard instantly
  • Calling x.drop() (E0040: explicit destructor call)
  • Panicking inside drop (can abort the process)

✓ Tips & Best Practices

  • Name guards _guard so they live to scope end
  • Use drop(x) to release locks and files early
  • Keep Drop impls small and infallible
