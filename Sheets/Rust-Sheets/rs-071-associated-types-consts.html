Types and Constants Inside Traits

An associated type is a placeholder type each implementor fixes once, like Iterator::Item. Use it when a type has exactly one natural choice; use a generic trait (From<T>) when one type can implement it many times. Traits can also declare associated constants, and fully qualified syntax resolves name clashes.

Key Points

  • Refer to it as Self::Item inside the trait
  • Bound it from outside: I: Iterator<Item = u8>
  • Associated consts: const ID: u32;
  • Default type params: trait Add<Rhs = Self>

Associated Items

trait Container {
    type Item;                              // associated type
    const CAPACITY: usize;                  // associated const
    fn get(&self, i: usize) -> Option<&Self::Item>;
    fn first(&self) -> Option<&Self::Item> { self.get(0) }
}

struct Names(Vec<String>);
impl Container for Names {
    type Item = String;
    const CAPACITY: usize = 100;
    fn get(&self, i: usize) -> Option<&String> { self.0.get(i) }
}

let n = Names(vec!["Ada".into()]);
println!("{:?} {}", n.first(), Names::CAPACITY);   // Some("Ada") 100

fn print_first<C: Container>(c: &C) where C::Item: std::fmt::Debug {
    println!("{:?}", c.first());
}

fn sum_bytes<I: Iterator<Item = u8>>(it: I) -> u32 { it.map(u32::from).sum() }
println!("{}", sum_bytes("AB".bytes()));    // 131

// Generic trait: one type implements it many times
struct Celsius(f64);
impl From<f64> for Celsius { fn from(v: f64) -> Self { Celsius(v) } }
impl From<i32> for Celsius { fn from(v: i32) -> Self { Celsius(v as f64) } }

trait Pilot { fn fly(&self) -> &str; }
trait Wizard { fn fly(&self) -> &str; }
struct Human;
impl Pilot for Human { fn fly(&self) -> &str { "captain speaking" } }
impl Wizard for Human { fn fly(&self) -> &str { "up!" } }
let h = Human;
println!("{}", Pilot::fly(&h));             // captain speaking
println!("{}", <Human as Wizard>::fly(&h)); // up!

Code Explained

Each implementor picks Item once
Names::CAPACITY reads an associated const
Iterator<Item = u8> bounds the associated type
<Human as Wizard>::fly picks between same-named methods

Coming From…

  • C++ member typedefs: std::vector<T>::value_type
  • Swift associatedtype in protocols (very similar)
  • Java no equivalent; extra generic parameters instead

The Rust Way

  • trait Container<T> with one impl per type → associated type Item
  • magic numbers per type → associated consts

⚠ Common Mistakes

  • Using a generic parameter where an associated type fits (forces annotations)
  • Ambiguous method calls when two traits share a name (E0034)
  • Forgetting to set the associated type in the impl

✓ Tips & Best Practices

  • Ask "can a type implement this more than once?" to choose
  • Use where C::Item: Bound for associated type bounds
  • Use associated consts for per-type configuration
