Sheet 015

Type Conversion

as casts (truncation, sign) · From / Into · TryFrom / TryInto · parse::<T>() · to_string() · lossless vs lossy

Explicit Conversions Only

Rust never converts types implicitly. as does primitive casts and can truncate or change sign silently. The From/Into traits do lossless conversions, TryFrom/TryInto do checked ones that return Result, parse turns strings into values, and to_string goes the other way.

Key Points

  • Implementing From<A> for B also gives Into<B> for A
  • as on floats to ints saturates and maps NaN to 0
  • parse needs the target type (annotation or turbofish)
  • Prefer From/TryFrom over as for integers

Conversions

use std::convert::TryFrom;

let big: i64 = 300;
let a = big as u8;                    // 44 (truncated!)
let b = -1i32 as u32;                 // 4294967295
let c = 3.99_f64 as i32;              // 3
let d = 1e20_f64 as i32;              // 2147483647 (saturates)
let e = 65u8 as char;                 // 'A'

let wide: i64 = i64::from(42i32);     // lossless
let w2: f64 = 7u32.into();            // lossless via Into
let small = u8::try_from(big);        // Err(TryFromIntError(()))
let ok: Result<u8, _> = 200i64.try_into();   // Ok(200)

let n: i32 = "42".parse().unwrap();
let m = "3.5".parse::<f64>()?;        // turbofish
let bad = "x".parse::<i32>();         // Err(ParseIntError)

let s = 42.to_string();               // "42"
let s2 = String::from("hi");          // &str → String
let owned: String = "hi".into();

struct Celsius(f64);
struct Fahrenheit(f64);
impl From<Celsius> for Fahrenheit {
    fn from(c: Celsius) -> Self { Fahrenheit(c.0 * 9.0 / 5.0 + 32.0) }
}
let f: Fahrenheit = Celsius(100.0).into();   // 212.0

Code Explained

as keeps the low bits: 300 becomes 44
try_from reports out-of-range values as errors
parse returns a Result; ? passes errors up
Implementing From gives you .into() for free

Coming From…

  • C++ implicit narrowing compiles; static_cast is explicit
  • Java widening is implicit; (byte) 300 truncates like as
  • Python int("42"), str(42); ints never truncate

The Rust Way

  • x as u8 on values that may not fit → u8::try_from(x)?
  • custom to_fahrenheit() methods → impl From<…>

⚠ Common Mistakes

  • Silent truncation with as on lengths and IDs
  • "42".parse() with no target type (cannot infer)
  • Implementing Into instead of From

✓ Tips & Best Practices

  • Enable clippy's cast_possible_truncation lint (pedantic)
  • Implement From for your error types to use ? (sheet 044)
  • Use TryFrom for validated domain types
