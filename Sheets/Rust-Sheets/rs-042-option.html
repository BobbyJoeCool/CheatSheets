A Value That May Be Absent

Rust has no null. A value that might be missing has type Option<T>: either Some(value) or None. The compiler forces you to handle None before using the value. Combinator methods like map, and_then and unwrap_or transform options without nested match blocks.

Key Points

  • Option is an enum in the prelude: Some / None need no import
  • ? on Option returns None early
  • ok_or converts to Result with an error
  • as_ref() / as_deref() borrow the inner value

Under the Hood

  • Option<&T>, Option<Box<T>>, Option<NonZeroU32> use the null/zero niche: same size as T
  • Option<u32> needs a tag byte plus padding: 8 bytes
  • Combinators inline to the same code as a hand-written match
  • ? desugars to a match that returns None

Working with Option

fn find_user(id: u32) -> Option<&'static str> {
    match id { 1 => Some("Ada"), 2 => Some("Bob"), _ => None }
}

let name = find_user(1);
match name {
    Some(n) => println!("found {n}"),
    None => println!("no user"),
}

println!("{}", find_user(9).unwrap_or("guest"));        // guest
println!("{}", find_user(9).unwrap_or_else(|| "anon")); // lazy default
let count: u32 = None.unwrap_or_default();              // 0

let len = find_user(1).map(|n| n.len());                // Some(3)
let initial = find_user(2).and_then(|n| n.chars().next());   // Some('B')
let long = find_user(1).filter(|n| n.len() > 5);        // None
println!("{}", find_user(1).is_some_and(|n| n.starts_with('A')));   // true

let res: Result<&str, String> = find_user(7).ok_or("not found".to_string());

fn first_char_upper(id: u32) -> Option<char> {
    let n = find_user(id)?;                 // None → return None
    Some(n.chars().next()?.to_ascii_uppercase())
}

let mut slot: Option<String> = Some("job".into());
let job = slot.take();                      // slot = None, job = Some("job")
let title: Option<String> = Some("Dr".into());
let t: Option<&str> = title.as_deref();     // Option<String> → Option<&str>
let filled: &mut String = slot.get_or_insert_with(|| "new".into());   // "new"

Code Explained

match forces both cases to be handled
unwrap_or_else only runs the closure when needed
and_then chains steps that also return Option
take() moves the value out and leaves None

Coming From…

  • Java Optional<T> with map, orElse, orElseGet
  • Kotlin / Swift nullable types T? with ?. and ?:
  • Python None with no compile-time checks; Optional[T] hints only

The Rust Way

  • if x.is_some() { x.unwrap() } → if let Some(v) = x
  • .map(…).unwrap_or(…) → .map_or(default, f)

⚠ Common Mistakes

  • unwrap() everywhere
  • unwrap_or(expensive()) evaluating eagerly (use _else)
  • Matching &Option<String> and moving the String out

✓ Tips & Best Practices

  • Return Option from lookups, Result from failures
  • Use as_deref() for Option<String> → Option<&str>
  • Use let … else to unwrap at the top of functions
