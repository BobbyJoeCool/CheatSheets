Unsafe Rust

unsafe blocks & fns · the five unsafe superpowers · *const T / *mut T · unsafe impl · unsafe extern (2024) · // SAFETY: comments

Opting Out of Some Checks

unsafe unlocks five extra abilities that the compiler cannot verify, and makes you responsible for upholding Rust's rules. It does not turn off the borrow checker. The goal is to build small, well-reviewed unsafe cores wrapped in safe APIs, as Vec, String and Mutex do internally.

Key Points

  • Undefined behavior anywhere can break code everywhere
  • Every unsafe block deserves a // SAFETY: comment
  • Edition 2024: unsafe extern blocks, unsafe_op_in_unsafe_fn warns
  • Test unsafe code with Miri

unsafe in Practice

let mut x = 10;
let r = &x as *const i32;                   // creating raw pointers is safe
println!("{}", unsafe { *r });              // 10 (SAFETY: x is alive)
let p = &raw mut x;                         // raw borrow syntax (1.82)
unsafe {
    // SAFETY: p points to x, which is alive and not otherwise borrowed.
    *p += 1;
    println!("{}", *p);                     // 11
}

/// # Safety
/// `idx` must be less than `v.len()`.
unsafe fn get_fast(v: &[u32], idx: usize) -> u32 {
    // SAFETY: the caller guarantees idx is in bounds.
    unsafe { *v.get_unchecked(idx) }
}
let v = [1, 2, 3];
let n = unsafe { get_fast(&v, 2) };         // 3

fn split_halves(s: &mut [i32]) -> (&mut [i32], &mut [i32]) {   // safe wrapper
    let mid = s.len() / 2;
    let ptr = s.as_mut_ptr();
    // SAFETY: the two ranges don't overlap and both lie within `s`.
    unsafe {
        (std::slice::from_raw_parts_mut(ptr, mid),
         std::slice::from_raw_parts_mut(ptr.add(mid), s.len() - mid))
    }
}

static mut COUNTER: u32 = 0;
unsafe { COUNTER += 1; }    // SAFETY: single-threaded, no other access

unsafe extern "C" {                          // 2024 edition syntax
    safe fn abs(x: i32) -> i32;              // declared safe to call
    fn strlen(s: *const std::ffi::c_char) -> usize;
}
println!("{}", abs(-5));                     // 5, no unsafe block needed

Code Explained

Raw pointers can be created safely; dereferencing needs unsafe
unsafe fn documents its contract in a # Safety section
split_halves wraps unsafe code in a safe, sound API
safe fn inside unsafe extern marks foreign functions safe to call

Coming From…

  • C / C++ all code is effectively unsafe; UB is everywhere possible
  • Go unsafe package; C# unsafe blocks with pointers
  • Java sun.misc.Unsafe / FFM API; Python ctypes

The Rust Way

  • unsafe to get around the borrow checker → restructure, or use a safe std API
  • unsafe spread across a codebase → one small module with a safe API

⚠ Common Mistakes

  • Thinking unsafe disables the borrow checker (it does not)
  • Missing // SAFETY: justifications
  • static mut in multi-threaded code (use atomics or Mutex)

✓ Tips & Best Practices

  • Run cargo +nightly miri test on unsafe code
  • Enable #![deny(unsafe_op_in_unsafe_fn)]
  • Search crates.io first: someone may have a safe abstraction
