Copy vs Clone

Copy types (ints, bool, char, &T) · Clone / .clone() · #[derive(Copy, Clone)] · cost of cloning · to_owned() · when cloning is fine

Implicit Copies and Explicit Clones

Copy types are duplicated bit-for-bit on assignment; the original stays usable. Clone is an explicit, possibly expensive deep copy you ask for with .clone(). A type can be Copy only if all its fields are Copy and it has no Drop, so String and Vec are Clone but never Copy.

Key Points

  • Copy requires Clone (#[derive(Clone, Copy)])
  • clone() on Rc/Arc only bumps a counter
  • to_owned() turns a borrow into an owned value (&str → String)
  • Cloning small data in non-hot code is fine

Copy and Clone

#[derive(Debug, Clone, Copy, PartialEq)]
struct Point { x: i32, y: i32 }             // all fields Copy → can be Copy

let p1 = Point { x: 1, y: 2 };
let p2 = p1;                                // copied
println!("{p1:?} {p2:?}");                  // both usable

#[derive(Debug, Clone)]
struct User { name: String, tags: Vec<String> }   // String → not Copy

let u1 = User { name: "Ada".into(), tags: vec!["admin".into()] };
let u2 = u1.clone();                        // deep copy: new heap buffers
let u3 = u1;                                // move
// println!("{:?}", u1);                    // E0382
println!("{:?} {:?}", u2, u3);

let s: &str = "hi";
let owned: String = s.to_owned();           // &str → String
let slice: &[i32] = &[1, 2];
let v: Vec<i32> = slice.to_vec();           // &[T] → Vec<T>

use std::rc::Rc;
let shared = Rc::new(vec![0u8; 1_000_000]);
let alias = Rc::clone(&shared);             // cheap: count 1 → 2

let mut names = vec![String::from("b"), String::from("a")];
let mut sorted = names.clone();             // fine: keep the original
sorted.sort();
names.push("c".into());

Code Explained

Point is Copy because both fields are
u1.clone() allocates new String and Vec buffers
to_owned / to_vec create owned copies of borrowed data
Rc::clone shares instead of copying the data

Coming From…

  • C++ copy constructors run implicitly; Rust makes deep copies explicit
  • Python copy.deepcopy(); assignment only copies the reference
  • Java clone() exists but is rarely used; records are copied by reference

The Rust Way

  • x.clone() on a Copy type → just x (clippy: clone_on_copy)
  • rc.clone() → Rc::clone(&rc) to show it is cheap

⚠ Common Mistakes

  • Deriving Copy on a type with a String field (compile error)
  • Cloning large Vecs inside loops
  • Making big structs Copy (silent large memcpys)

✓ Tips & Best Practices

  • Derive Copy for small value types (points, IDs, colors)
  • Clone freely at startup and in tests; avoid in hot loops
  • Use Rc/Arc when many owners need the same large data

Quick Summary

  • Copy — implicit, bitwise
  • Clone — explicit .clone()
  • no Copy with heap or Drop
  • to_owned() — borrow → owned
