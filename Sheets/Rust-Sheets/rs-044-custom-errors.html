Designing Your Own Errors

Libraries usually define an error enum with one variant per failure kind, so callers can match on it. Implement Display for a human message, std::error::Error for interoperability, and From<OtherError> so ? converts underlying errors automatically. source() exposes the wrapped cause.

Key Points

  • Variants can carry data: NotFound(String)
  • Error requires Debug + Display
  • From impls make ? work across error types
  • #[non_exhaustive] lets you add variants later

An Error Enum

use std::{error::Error, fmt, fs, io, num::ParseIntError};

#[derive(Debug)]
#[non_exhaustive]
pub enum ConfigError {
    Io(io::Error),
    BadPort(ParseIntError),
}

impl fmt::Display for ConfigError {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        match self {
            Self::Io(e) => write!(f, "could not read config: {e}"),
            Self::BadPort(e) => write!(f, "invalid port: {e}"),
        }
    }
}
impl Error for ConfigError {
    fn source(&self) -> Option<&(dyn Error + 'static)> {
        match self { Self::Io(e) => Some(e), Self::BadPort(e) => Some(e) }
    }
}
impl From<io::Error> for ConfigError {
    fn from(e: io::Error) -> Self { Self::Io(e) }
}
impl From<ParseIntError> for ConfigError {
    fn from(e: ParseIntError) -> Self { Self::BadPort(e) }
}

fn load_port(path: &str) -> Result<u16, ConfigError> {
    let text = fs::read_to_string(path)?;   // io::Error → ConfigError
    Ok(text.trim().parse()?)                // ParseIntError → ConfigError
}

match load_port("port.txt") {
    Err(ConfigError::BadPort(e)) => eprintln!("fix the port: {e}"),
    Err(e) => eprintln!("{e}"),
    Ok(p) => println!("port {p}"),
}

⚠ Common Mistakes

  • Display messages that repeat the source message (shown twice in chains)
  • One giant error enum for the whole crate
  • Forgetting From, then writing map_err everywhere

✓ Tips & Best Practices

  • Keep messages lowercase without trailing periods (std style)
  • Group errors by module or operation
  • Expose the source instead of formatting it into the message
