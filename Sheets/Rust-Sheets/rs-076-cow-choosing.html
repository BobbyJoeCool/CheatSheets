Cow & Choosing a Pointer

Cow<'a, str> · to_mut() / into_owned() · Box vs Rc vs Arc · Rc<RefCell> vs Arc<Mutex> · Pin preview

Clone on Write and Pointer Choice

Cow<'a, T> ("clone on write") holds either a borrowed &T or an owned value, so a function can return the input unchanged without allocating and only allocate when it must modify. The rest of this sheet is a decision guide for Box, Rc, Arc and their interior-mutability pairings.

Key Points

  • Cow::Borrowed(&x) / Cow::Owned(v)
  • to_mut() clones only if currently borrowed
  • Pin<P> guarantees a value will not move (needed by async futures)
  • Start with plain ownership; reach for pointers when needed

Cow and Pointer Choices

use std::borrow::Cow;

fn normalize(input: &str) -> Cow<'_, str> {
    if input.contains(' ') {
        Cow::Owned(input.replace(' ', "_"))  // allocate only if needed
    } else {
        Cow::Borrowed(input)                 // zero-copy path
    }
}
let a = normalize("no_spaces");
let b = normalize("has spaces");
println!("{a} {b}");                         // no_spaces has_spaces
println!("{}", matches!(a, Cow::Borrowed(_)));   // true

let mut c: Cow<[i32]> = Cow::Borrowed(&[1, 2, 3]);
c.to_mut().push(4);                          // clones into a Vec here
let owned: Vec<i32> = c.into_owned();

let lossy = String::from_utf8_lossy(b"ok");  // std returns Cow<str>

use std::rc::Rc;
use std::cell::RefCell;
use std::sync::{Arc, Mutex};

let single_owner = Box::new(5);                       // one owner
let shared_read = Rc::new(vec![1, 2]);                // many owners, 1 thread
let shared_mut = Rc::new(RefCell::new(0));            // + mutation
*shared_mut.borrow_mut() += 1;
let thread_read = Arc::new(String::from("cfg"));      // many threads
let thread_mut = Arc::new(Mutex::new(0));             // + mutation
*thread_mut.lock().unwrap() += 1;

use std::pin::Pin;
let pinned: Pin<Box<i32>> = Box::pin(10);   // won't move again

Code Explained

normalize borrows when no change is needed
to_mut() turns a borrowed Cow into an owned one
std APIs like from_utf8_lossy return Cow
Each pointer adds one capability: sharing, threads, mutation

Coming From…

  • C++ no std Cow; copy-on-write strings were removed in C++11
  • Swift arrays/strings are copy-on-write automatically
  • Python / Java immutable strings; sharing is via the GC

The Rust Way

  • returning String from a function that usually doesn't change input → Cow<str>
  • Arc<Mutex<T>> in single-threaded code → Rc<RefCell<T>> or plain &mut

Choosing a Pointer

NeedUse
One owner, heapBox<T>
Many owners, one threadRc<T>
… and mutationRc<RefCell<T>>
Many owners, threadsArc<T>
… and mutationArc<Mutex<T>> / Arc<RwLock<T>>

⚠ Common Mistakes

  • Reaching for Rc<RefCell> before trying plain ownership
  • Using Arc and Mutex where threads never share data
  • Returning Cow from APIs that always allocate anyway

✓ Tips & Best Practices

  • Accept impl Into<Cow<'a, str>> for flexible constructors
  • Use indices into a Vec instead of pointer graphs
  • Learn Pin when writing futures or self-referential types

Quick Summary

  • Cow — borrowed or owned
  • to_mut() clones lazily
  • Box · Rc · Arc ladder
  • RefCell (1 thread) · Mutex (threads)
