The Iterator Trait

An iterator is any type with a next() method returning Option<Item>. Collections offer three: iter() yields &T, iter_mut() yields &mut T, and into_iter() yields owned T. Adapters are lazy: nothing runs until a consumer such as for, collect or sum pulls items.

Key Points

  • Implement only next(); 70+ methods come free
  • for x in coll calls IntoIterator::into_iter
  • An unconsumed adapter chain does nothing (compiler warns)
  • Iterators can be infinite: (0..), repeat, successors

Under the Hood

  • Adapter chains compile to a single loop: no intermediate collections
  • map, filter are structs wrapping the previous iterator
  • LLVM often vectorizes slice iterator loops
  • Iterating a slice skips per-element bounds checks that indexing needs

Using and Writing Iterators

let v = vec![1, 2, 3];
let mut it = v.iter();
println!("{:?}", it.next());                // Some(1)
println!("{:?}", it.next());                // Some(2)
println!("{:?}", it.next());                // Some(3)
println!("{:?}", it.next());                // None

let lazy = v.iter().map(|x| { println!("map {x}"); x * 2 });  // nothing yet
let doubled: Vec<i32> = lazy.collect();     // now it runs

let mut owned = vec![String::from("a")];
for s in owned.iter_mut() { s.push('!'); }  // &mut String
for s in owned.into_iter() { println!("{s}"); }   // String, owned moved

struct Countdown(u32);
impl Iterator for Countdown {
    type Item = u32;
    fn next(&mut self) -> Option<u32> {
        if self.0 == 0 { return None; }
        self.0 -= 1;
        Some(self.0 + 1)
    }
}
let c: Vec<u32> = Countdown(3).collect();   // [3, 2, 1]
println!("{}", Countdown(4).sum::<u32>());  // 10 (free method)

let mut n = 0;
let evens = std::iter::from_fn(|| { n += 2; (n <= 6).then_some(n) });
println!("{:?}", evens.collect::<Vec<_>>());   // [2, 4, 6]
let pow2: Vec<u32> = std::iter::successors(Some(1u32), |x| x.checked_mul(2))
    .take(5).collect();                     // [1, 2, 4, 8, 16]
let first_big = (1..).map(|x| x * x).find(|&x| x > 50);   // Some(64)

Code Explained

Each next() call returns the following item or None
The map closure runs only when collect pulls items
Implementing next gives sum, collect and the rest
(1..) is infinite; find stops it

Coming From…

  • Java Stream (lazy) and Iterator (hasNext/next)
  • Python __next__ / generators; StopIteration instead of None
  • C++ iterator pairs / C++20 ranges with lazy views

The Rust Way

  • building temporary Vecs between steps → one adapter chain
  • index loops over collections → iterators

⚠ Common Mistakes

  • Building an adapter chain and never consuming it
  • Calling into_iter() and then using the collection
  • Expecting side effects in map to run in a lazy chain

✓ Tips & Best Practices

  • Implement Iterator for your own sequences
  • Return impl Iterator<Item = T> from functions (sheet 106)
  • Use by_ref() to consume part of an iterator and keep the rest

Quick Summary

  • next() → Option<Item>
  • iter / iter_mut / into_iter
  • adapters are lazy
  • implement next, get the rest
