Databases with sqlx

PgPool · query! / query_as! compile-time checks · sqlx migrate · rusqlite · Diesel / SeaORM

SQL from Rust

sqlx is an async, pure-Rust SQL toolkit for PostgreSQL, MySQL and SQLite. Its query! macros check SQL against a real database at compile time, catching typos and type mismatches before running. Connection pools are cheap to clone. Alternatives: rusqlite (sync SQLite), Diesel (typed query builder) and SeaORM (async ORM).

Key Points

  • cargo add sqlx -F runtime-tokio,postgres,macros
  • Compile-time checks need DATABASE_URL or cargo sqlx prepare
  • Always bind parameters ($1, ?); never format SQL strings
  • Migrations live in migrations/ and run with sqlx migrate run

sqlx with PostgreSQL

use sqlx::postgres::PgPoolOptions;
use sqlx::FromRow;

#[derive(Debug, FromRow)]
struct User { id: i64, name: String, email: Option<String> }

#[tokio::main]
async fn main() -> Result<(), sqlx::Error> {
    let url = std::env::var("DATABASE_URL").expect("DATABASE_URL is set");
    let pool = PgPoolOptions::new().max_connections(5).connect(&url).await?;

    sqlx::migrate!("./migrations").run(&pool).await?;   // embedded migrations

    let id: i64 = sqlx::query_scalar(
        "INSERT INTO users (name, email) VALUES ($1, $2) RETURNING id")
        .bind("Ada").bind("ada@example.com")
        .fetch_one(&pool).await?;

    let user = sqlx::query_as!(User,        // checked at compile time
        "SELECT id, name, email FROM users WHERE id = $1", id)
        .fetch_one(&pool).await?;
    println!("{user:?}");

    let all: Vec<User> = sqlx::query_as("SELECT id, name, email FROM users")
        .fetch_all(&pool).await?;           // runtime-checked variant

    let mut tx = pool.begin().await?;       // transaction
    sqlx::query!("UPDATE users SET name = $1 WHERE id = $2", "Ada L.", id)
        .execute(&mut *tx).await?;
    tx.commit().await?;                     // dropped without commit → rollback
    println!("{} users", all.len());
    Ok(())
}
// $ sqlx migrate add create_users && sqlx migrate run     (sqlx-cli)

Code Explained

A pool manages and reuses connections
query_as! verifies columns and types against the database
.bind() passes parameters safely
A transaction rolls back automatically if not committed

Coming From…

  • Python SQLAlchemy / asyncpg; psycopg for Postgres
  • Java JDBC / jOOQ (typed SQL) / JPA-Hibernate (ORM)
  • Go database/sql + sqlc (compile-time generated, similar goal)

The Rust Way

  • format!("… WHERE id = {id}") → bind parameters
  • a new connection per request → a shared pool

⚠ Common Mistakes

  • String-formatting SQL (injection risk)
  • CI builds failing because no database is reachable (use cargo sqlx prepare)
  • Forgetting tx.commit() and silently rolling back

✓ Tips & Best Practices

  • Commit the .sqlx/ offline data for reproducible builds
  • Use Option<T> for nullable columns
  • Keep SQL in the code where reviewers can read it

Quick Summary

  • sqlx — async SQL
  • query! checked at compile time
  • pools + transactions
  • bind, never format
