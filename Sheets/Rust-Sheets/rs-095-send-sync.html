Send & Sync

Send · Sync · why Rc isn't Send · auto traits · opting out · compile-time data-race freedom

Thread-Safety Marker Traits

Send means a value can be moved to another thread; Sync means &T can be shared between threads (T is Sync if &T is Send). The compiler implements both automatically for types made of Send/Sync parts. thread::spawn requires Send + 'static, which is how Rust rejects data races at compile time.

Key Points

  • Most types are Send + Sync: ints, String, Vec, Arc<Mutex<T>>
  • Rc<T>: neither (non-atomic count)
  • Cell / RefCell: Send but not Sync
  • Raw pointers are neither; unsafe impl opts back in

Send and Sync in Practice

use std::rc::Rc;
use std::sync::{Arc, Mutex};
use std::cell::RefCell;
use std::thread;

fn assert_send<T: Send>() {}
fn assert_sync<T: Sync>() {}

assert_send::<String>();
assert_sync::<Vec<u8>>();
assert_send::<Arc<Mutex<i32>>>();
assert_sync::<Arc<Mutex<i32>>>();
assert_send::<RefCell<i32>>();              // can move to another thread…
// assert_sync::<RefCell<i32>>();           // …but not be shared: error
// assert_send::<Rc<i32>>();                // E0277: Rc cannot be sent

let rc = Rc::new(5);
// thread::spawn(move || println!("{rc}"));
// error[E0277]: `Rc<i32>` cannot be sent between threads safely
let arc = Arc::new(5);                      // fix: atomic counting
thread::spawn(move || println!("{arc}")).join().unwrap();

fn run_in_background<F>(f: F) -> thread::JoinHandle<()>
where
    F: FnOnce() + Send + 'static,           // what spawn requires
{
    thread::spawn(f)
}
run_in_background(|| println!("ok"));

struct Handle(*mut u8);                     // raw pointer: not Send
unsafe impl Send for Handle {}              // SAFETY: we promise exclusive use

use std::marker::PhantomData;
struct NotSend { _p: PhantomData<*const ()> }   // opt out on stable

Code Explained

The assert_* helpers check traits at compile time
RefCell is Send but not Sync
Replacing Rc with Arc makes the value Send
unsafe impl Send is a promise the compiler cannot check

Coming From…

  • C++ / Java thread safety is documentation and discipline
  • Go the race detector finds races at runtime, in tests
  • Swift Sendable (a direct analog, checked at compile time)

The Rust Way

  • wrapping everything in Arc<Mutex> "to be safe" → only what threads share
  • unsafe impl Send to silence an error → fix the type (Arc, Mutex)

⚠ Common Mistakes

  • Trying to send Rc or RefCell-shared data to threads
  • Forgetting + Send on boxed trait objects used in threads
  • Unsound unsafe impl Sync on types with interior mutability

✓ Tips & Best Practices

  • Read E0277 notes: they show which field is not Send
  • Add + Send + Sync to Box<dyn Error> in threaded apps
  • Async runtimes need futures to be Send for multi-threaded executors

Quick Summary

  • Send — move across threads
  • Sync — share &T across threads
  • auto-implemented
  • data races fail to compile
