const fn, Recursion & Attributes

const fn · recursion & stack depth · no guaranteed tail calls · #[inline] · #[must_use] · diverging -> !

Compile-Time and Special Functions

A const fn can run at compile time to initialize constants, and also at runtime like any function. Recursion works, but Rust does not guarantee tail-call optimization, so deep recursion can overflow the stack; iterate instead. Attributes like #[inline] and #[must_use] give hints and warnings.

Key Points

  • const fn bodies are limited (no heap, no traits calls in most cases)
  • Main thread stack is usually 8 MB; spawned threads default to 2 MB
  • #[must_use] warns when a result is ignored
  • #[inline] matters mostly across crates

const fn, Recursion, Attributes

const fn kib(n: usize) -> usize { n * 1024 }
const BUF: usize = kib(64);                 // computed at compile time

const fn fib_const(n: u32) -> u64 {
    let (mut a, mut b, mut i) = (0, 1, 0);
    while i < n { let t = a + b; a = b; b = t; i += 1; }
    a
}
const FIB_50: u64 = fib_const(50);          // 12586269025

fn factorial(n: u64) -> u64 {
    if n <= 1 { 1 } else { n * factorial(n - 1) }   // recursion
}

fn sum_to(n: u64) -> u64 { (1..=n).sum() }  // iteration: no stack risk
// fn deep(n: u64) -> u64 { if n == 0 { 0 } else { 1 + deep(n - 1) } }
// deep(10_000_000)                        // stack overflow

fn depth(tree: &Node) -> usize {
    1 + tree.children.iter().map(depth).max().unwrap_or(0)
}
struct Node { children: Vec<Node> }

#[must_use = "the new string is returned; the input is unchanged"]
fn shout(s: &str) -> String { s.to_uppercase() }
// shout("hi");                            // warning: unused return value
#[inline]
fn square(x: i32) -> i32 { x * x }
#[cold]
fn report(msg: &str) -> ! {                 // rarely called, never returns
    eprintln!("fatal: {msg}");
    std::process::exit(1)
}

println!("{} {}", BUF, FIB_50);             // 65536 12586269025
println!("{}", factorial(20));              // 2432902008176640000

Code Explained

kib(64) runs during compilation
const fn can use loops but not heap allocation
Recursion suits trees; use loops for long linear work
-> ! tells the compiler report never returns

Coming From…

  • C++ constexpr / consteval functions
  • Python recursion limit of 1000 by default
  • Go / Java no compile-time function execution in the language

The Rust Way

  • deep linear recursion → a loop or an explicit stack
  • #[inline(always)] everywhere → measure first

Attributes

AttributeEffect
#[inline]Allow cross-crate inlining
#[inline(always)] / (never)Strong hint
#[cold]Unlikely path
#[must_use]Warn if ignored
#[track_caller]Panic points to caller
#[deprecated]Warn on use
#[doc(hidden)]Hide from docs

⚠ Common Mistakes

  • Assuming tail recursion will be optimized
  • Calling non-const functions inside const fn
  • Ignoring #[must_use] warnings on Results

✓ Tips & Best Practices

  • Use stacker or a bigger thread stack for deep trees if needed
  • Put #[must_use] on builders and pure functions
  • Use #[track_caller] on helpers that panic

Quick Summary

  • const fn — compile-time capable
  • no guaranteed TCO
  • #[must_use] / #[inline]
  • -> ! diverges
