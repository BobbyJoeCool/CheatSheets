Sorting & Searching

sort / sort_unstable · sort_by / sort_by_key · cmp::Reverse · binary_search · position / find / any / all · max_by_key / min_by

Ordering and Finding Data

sort is a stable sort and sort_unstable is usually faster and uses no extra memory. sort_by_key sorts by a computed key and sort_by takes a comparison function. binary_search works on sorted slices and returns Ok(index) or Err(insert_position). Iterators provide find, position, any, all and max_by_key.

Key Points

  • Sorting needs Ord; floats need sort_by(f64::total_cmp)
  • sort_by_cached_key computes each key once
  • Reverse(key) sorts descending
  • is_sorted() checks order (Rust 1.82)

Sorting and Searching

use std::cmp::Reverse;

let mut v = vec![5, 2, 9, 1, 7];
v.sort();                                   // [1, 2, 5, 7, 9]
v.sort_unstable_by(|a, b| b.cmp(a));        // [9, 7, 5, 2, 1]
v.sort_by_key(|&x| Reverse(x));             // descending again

let mut words = vec!["banana", "Apple", "fig", "cherry"];
words.sort_by_key(|w| w.len());     // ["fig", "Apple", "banana", "cherry"]
words.sort_by_key(|w| w.to_lowercase());   // allocates on every compare
words.sort_by_cached_key(|w| w.to_lowercase());   // allocates once per item

#[derive(Debug)]
struct P { name: &'static str, age: u32 }
let mut people = vec![P { name: "Bo", age: 30 }, P { name: "Al", age: 30 },
                      P { name: "Cy", age: 25 }];
people.sort_by(|a, b| b.age.cmp(&a.age).then_with(|| a.name.cmp(b.name)));
                                            // Al 30, Bo 30, Cy 25

let mut f = vec![2.5, -1.0, 9.75];
f.sort_by(f64::total_cmp);                  // [-1.0, 2.5, 9.75]

let sorted = [1, 3, 5, 7, 9];
println!("{:?}", sorted.binary_search(&7)); // Ok(3)
println!("{:?}", sorted.binary_search(&4)); // Err(2) → insert at 2
println!("{}", sorted.partition_point(|&x| x < 6));   // 3

println!("{:?}", v.iter().position(|&x| x == 5));     // Some(2)
println!("{:?}", v.iter().find(|&&x| x < 3));         // Some(2)
println!("{}", v.iter().any(|&x| x > 8));             // true
println!("{}", v.iter().all(|&x| x > 0));             // true
let oldest = people.iter().max_by_key(|p| p.age).unwrap();   // last max: Bo
let youngest = people.iter().min_by_key(|p| p.age).unwrap(); // Cy
println!("{} {}", oldest.name, sorted.is_sorted());   // Bo true

Code Explained

sort_unstable_by(|a, b| b.cmp(a)) sorts descending
sort_by_cached_key avoids recomputing expensive keys
then_with adds a tie-breaker
binary_search returns where a missing item would go

Coming From…

  • Python sorted(xs, key=…, reverse=True); bisect for binary search
  • Java list.sort(Comparator.comparing(P::age).reversed())
  • C++ std::sort (unstable) / std::stable_sort; lower_bound

The Rust Way

  • sort_by(|a, b| a.partial_cmp(b).unwrap()) → sort_by(f64::total_cmp)
  • sort_by_key with an allocating key → sort_by_cached_key

⚠ Common Mistakes

  • binary_search on unsorted data (meaningless result)
  • Sorting floats with sort() (E0277: f64 is not Ord)
  • Expecting max_by_key to return the first max (it returns the last)

✓ Tips & Best Practices

  • Use sort_unstable for primitives
  • Use Reverse inside key tuples: (Reverse(score), name)
  • Use select_nth_unstable for medians and top-k

Quick Summary

  • sort stable · sort_unstable fast
  • sort_by_key / Reverse
  • binary_search → Ok/Err
  • find / position / any
