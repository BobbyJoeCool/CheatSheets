if / else as Expressions

if / else if / else · condition must be bool · let x = if … · arms must match types · no ternary

Conditions That Produce Values

if needs a real bool and no parentheses. Because if is an expression, it replaces the ternary operator: let x = if a { 1 } else { 2 };. When used for a value, every branch must produce the same type and an else is required.

Key Points

  • Braces are always required; parentheses are not used
  • No truthiness: if n {} fails for integers
  • An if without else has type ()
  • Long else if chains often read better as match

if Expressions

let temp = 72;

if temp > 85 {
    println!("hot");
} else if temp > 60 {
    println!("nice");                       // nice
} else {
    println!("cold");
}

let label = if temp >= 70 { "warm" } else { "cool" };   // no ternary
let fee = if temp > 100 { 25 } else { 0 };

// let bad = if temp > 70 { "warm" } else { 5 };   // error: incompatible types
// if temp { }                      // error: expected bool, found integer

let items: Vec<i32> = Vec::new();
if !items.is_empty() {
    println!("{} items", items.len());
}

let grade = {
    let score = 88;
    if score >= 90 { 'A' }
    else if score >= 80 { 'B' }
    else { 'C' }
};
println!("{label} {fee} {grade}");          // warm 0 B

let name: Option<&str> = Some("Ada");
if let Some(n) = name { println!("hi {n}"); }   // see sheet 033

Code Explained

if arms are blocks; the last expression is the value
label gets the value of whichever branch runs
Mismatched branch types are a compile error
Integers are not truthy; compare explicitly

Coming From…

  • C++ / Java cond ? a : b ternary
  • Python a if cond else b
  • Go no ternary at all; Rust's if expression covers it

The Rust Way

  • let x; if c { x = 1 } else { x = 2 } → let x = if c { 1 } else { 2 };
  • deep else if on one value → match

⚠ Common Mistakes

  • Adding ; after the branch values (branches become ())
  • Missing else when the if is used as a value
  • Writing if (x > 5) (works, but rustc warns about unnecessary parens)

✓ Tips & Best Practices

  • Use if expressions to keep variables immutable
  • Use bool::then / then_some for Option: cond.then_some(x)
  • Switch to match once there are three or more cases on one value

Quick Summary

  • condition is bool
  • if is an expression
  • branches same type
  • no ternary needed
