Publishing & Documentation

cargo publish · crates.io & docs.rs · cargo doc · #![warn(missing_docs)] · package metadata · cargo semver-checks · yanking

Sharing a Crate

Publishing uploads a crate to crates.io, and docs.rs builds its documentation automatically. A published version is permanent; it can be yanked to stop new projects depending on it, but never deleted. Follow semver: breaking changes need a new major version (or minor for 0.x).

Key Points

  • Log in once with cargo login <token>
  • Required metadata: description, license (or license-file)
  • cargo package --list shows what will be uploaded
  • Use exclude / include to trim the package

Metadata and Publishing

[package]
name = "tiny-geo"
version = "0.2.0"
edition = "2024"
description = "Small geometry helpers for 2-D shapes"
license = "MIT OR Apache-2.0"
repository = "https://github.com/ada/tiny-geo"
documentation = "https://docs.rs/tiny-geo"
readme = "README.md"
keywords = ["geometry", "math", "2d"]          # up to 5
categories = ["mathematics"]
rust-version = "1.85"
exclude = ["/benches/data", "*.png"]

[package.metadata.docs.rs]
all-features = true                            # document every feature

# Terminal:
# cargo doc --open --no-deps        preview docs
# cargo test --doc                  run doc examples
# cargo package --list              files that will ship
# cargo publish --dry-run           build the package without uploading
# cargo publish                     upload (permanent)
# cargo yank --version 0.2.0        block new users of a bad release
# cargo yank --version 0.2.0 --undo
# cargo semver-checks               detect accidental breaking changes

# src/lib.rs
# #![warn(missing_docs)]
# #![doc = include_str!("../README.md")]   // README as crate docs
# //! Small geometry helpers.
# #[doc(hidden)] pub mod internal;
# #[deprecated(since = "0.2.0", note = "use `area` instead")]

Code Explained

description and license are required by crates.io
docs.rs reads [package.metadata.docs.rs]
--dry-run checks that the package builds
Yanking hides a version from new lock files only

Coming From…

  • JavaScript npm publish / npm deprecate (npm allows unpublish briefly)
  • Python build + twine upload to PyPI; Read the Docs for docs
  • Java Maven Central with signed artifacts; Javadoc jars

The Rust Way

  • breaking changes in a patch release → bump major (or minor for 0.x)
  • separate hand-written docs → doc comments + README as crate docs

Semver for Crates

ChangeBump (1.x)Bump (0.x)
Bug fixPatchPatch
New public itemMinorPatch
Remove/rename public itemMajorMinor
New required trait methodMajorMinor
Raise MSRVMinor (common practice)Minor

⚠ Common Mistakes

  • Publishing secrets or large test data (check package --list)
  • Expecting to delete a published version
  • Breaking changes without a version bump

✓ Tips & Best Practices

  • Dual-license MIT OR Apache-2.0 like the Rust ecosystem
  • Run cargo semver-checks in CI before releases
  • Use release-plz or cargo-release to automate

Quick Summary

  • cargo publish — permanent
  • docs.rs builds docs
  • yank, never delete
  • semver discipline
