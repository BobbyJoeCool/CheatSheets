Sheet 089

Unit Tests

#[cfg(test)] mod tests · #[test] · assert_eq! / assert_ne! · #[should_panic] · tests returning Result · cargo test name · -- --nocapture

Built-In Testing

Unit tests live next to the code in a #[cfg(test)] mod tests module, compiled only for cargo test. Each #[test] function passes if it returns without panicking. Because the module is a child, tests can call private functions. Tests run in parallel threads by default.

Key Points

  • use super::*; imports the code under test
  • Output is captured unless a test fails (or --nocapture)
  • cargo test parse runs tests whose names contain "parse"
  • #[ignore] skips slow tests unless --ignored

Unit Tests

pub fn add(a: i32, b: i32) -> i32 { a + b }
fn parse_pair(s: &str) -> Result<(i32, i32), String> {     // private
    let (a, b) = s.split_once(',').ok_or("missing comma")?;
    let a = a.trim().parse().map_err(|_| "bad a")?;
    Ok((a, b.trim().parse().map_err(|_| "bad b")?))
}
pub fn divide(a: i32, b: i32) -> i32 {
    if b == 0 { panic!("divide by zero"); }
    a / b
}
#[cfg(test)]
mod tests {
    use super::*;
    #[test]
    fn adds_numbers() {
        assert_eq!(add(2, 3), 5);
        assert_ne!(add(2, 2), 5, "math is broken");
    }
    #[test]
    fn parses_private_fn() {                // private items are visible
        assert_eq!(parse_pair("1, 2"), Ok((1, 2)));
        assert!(parse_pair("1 2").is_err());
    }
    #[test]
    #[should_panic(expected = "divide by zero")]
    fn panics_on_zero() { divide(1, 0); }
    #[test]
    fn returns_result() -> Result<(), String> {
        let (a, b) = parse_pair("4,5")?;    // ? instead of unwrap
        assert_eq!(a + b, 9);
        Ok(())
    }
}

Code Explained

#[cfg(test)] keeps tests out of normal builds
assert_eq! prints both values when they differ
should_panic(expected = …) checks the panic message
Tests returning Result can use ?

Coming From…

  • Python pytest discovers test_* functions; asserts are plain assert
  • Java JUnit 5 @Test, assertEquals, assertThrows
  • Go func TestX(t *testing.T) in _test.go files

The Rust Way

  • assert!(a == b) → assert_eq!(a, b) (better failure output)
  • .unwrap() chains in tests → return Result and use ?

⚠ Common Mistakes

  • Tests sharing files or globals while running in parallel
  • Forgetting use super::*;
  • should_panic without expected (any panic passes)

✓ Tips & Best Practices

  • Name tests as behaviors: rejects_empty_name
  • Use pretty_assertions for readable diffs
  • Use cargo-nextest for faster, isolated runs (sheet 091)
