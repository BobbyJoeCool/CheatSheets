HashMap — Basics

HashMap::new() · insert / get / remove · contains_key · random iteration order · HashMap::from([…]) · key / value ownership

Key-Value Storage

HashMap<K, V> maps keys to values with average O(1) lookups. Keys must implement Eq + Hash. insert takes ownership of the key and value and returns the old value, get returns Option<&V>, and iteration order is unspecified and varies between runs.

Key Points

  • Import with use std::collections::HashMap;
  • Default hasher is SipHash 1-3: resistant to HashDoS, not the fastest
  • get accepts a borrowed key: map.get("k") for String keys
  • Indexing map["k"] panics if missing

Under the Hood

  • std uses a SwissTable layout (hashbrown): control bytes + slots in one allocation
  • Each map gets a random seed (RandomState), so iteration order differs per run
  • HashMap::new() does not allocate until the first insert
  • Swap the hasher for speed with ahash / FxHashMap when DoS is not a concern

HashMap

use std::collections::HashMap;

let mut ages: HashMap<String, u32> = HashMap::new();
ages.insert("Ada".to_string(), 36);
ages.insert("Bob".to_string(), 25);
let old = ages.insert("Bob".to_string(), 26);   // Some(25): replaced

println!("{:?}", ages.get("Ada"));          // Some(36)
println!("{:?}", ages.get("Zed"));          // None
println!("{}", ages["Ada"]);                // 36 (panics if missing)
println!("{}", ages.contains_key("Bob"));   // true
println!("{}", ages.len());                 // 2

if let Some(age) = ages.get_mut("Ada") { *age += 1; }
let removed = ages.remove("Bob");           // Some(26)

let caps = HashMap::from([("fr", "Paris"), ("jp", "Tokyo")]);
let squares: HashMap<u32, u32> = (1..=4).map(|n| (n, n * n)).collect();

for (country, city) in &caps {              // order is not defined
    println!("{country}: {city}");
}
let mut keys: Vec<_> = squares.keys().copied().collect();
keys.sort();                                // sort for stable output
println!("{keys:?}");                       // [1, 2, 3, 4]
let total: u32 = squares.values().sum();    // 30

let key = String::from("Cy");
ages.insert(key, 50);                       // key moved into the map
// println!("{key}");                       // E0382
let n = ages.get("Cy").copied().unwrap_or(0);   // Option<&u32> → u32
ages.retain(|_, v| *v > 40);

Code Explained

insert returns the previous value if the key existed
get("Ada") works with String keys thanks to Borrow
collect() builds a map from (key, value) pairs
Sort keys when you need deterministic output

Coming From…

  • Python dict (keeps insertion order; Rust's HashMap does not)
  • Java HashMap<K,V>; get returns null instead of Option
  • Go map[K]V; v, ok := m[k] ≈ get

The Rust Way

  • if map.contains_key(k) { map[k] } → if let Some(v) = map.get(k)
  • need sorted or stable order → BTreeMap (sheet 056) or indexmap

⚠ Common Mistakes

  • Relying on iteration order (it changes between runs)
  • Using map[k] for keys that may be missing
  • Floats as keys (f64 is not Eq/Hash)

✓ Tips & Best Practices

  • Use the entry API for insert-or-update (sheet 056)
  • Use &str lookups on String keys
  • Use indexmap when insertion order matters

Quick Summary

  • HashMap<K, V>, O(1) average
  • insert / get / remove
  • get → Option<&V>
  • no defined order
