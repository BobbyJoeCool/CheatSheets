Pattern Matching

match compares a value against patterns from top to bottom and runs the first arm that matches. The compiler checks that it is exhaustive: every possible value must be covered, so adding an enum variant shows you every match to update. match is an expression, and all arms must return the same type.

Key Points

  • _ matches anything and binds nothing
  • a | b matches either; 1..=5 matches a range
  • Arms are pattern => expression,
  • A name in a pattern binds the value

match

let n = 7;
let kind = match n {
    0 => "zero",
    1 | 2 | 3 => "small",
    4..=9 => "medium",
    _ => "large",
};
println!("{kind}");                         // medium

let c = 'q';
match c {
    'a' | 'e' | 'i' | 'o' | 'u' => println!("vowel"),
    'a'..='z' => println!("consonant"),     // consonant
    _ => println!("other"),
}

let maybe: Option<i32> = Some(42);
match maybe {
    Some(0) => println!("zero"),
    Some(x) => println!("got {x}"),         // got 42
    None => println!("nothing"),
}

let r: Result<u8, String> = "300".parse::<u8>().map_err(|e| e.to_string());
let value = match r {
    Ok(v) => v,
    Err(e) => { eprintln!("bad: {e}"); 0 }  // bad: number too large…
};

let pair = (0, -3);
match pair {
    (0, y) => println!("on y axis at {y}"),
    (x, 0) => println!("on x axis at {x}"),
    _ => println!("elsewhere"),
}

Code Explained

Arms are tried in order; _ catches the rest
Char ranges and alternatives combine
Some(x) binds the inner value to x
A block arm can run statements then return a value

Coming From…

  • C++ / Java switch; Java 21 pattern switch is the closest match
  • Python match (3.10) with similar patterns, but not exhaustive
  • Go switch with no exhaustiveness check

The Rust Way

  • _ => on your own enums → list variants so new ones cause errors
  • chains of if x == … → match

⚠ Common Mistakes

  • Putting _ first so later arms never run (warning: unreachable)
  • Non-exhaustive match on integers without _
  • Arms that return different types

✓ Tips & Best Practices

  • Let exhaustiveness errors guide refactors
  • Use matches!(x, Pat) for a bool test
  • Keep arms short; call functions for big branches

Quick Summary

  • first matching arm wins
  • exhaustive by design
  • _ · | · ..=
  • match is an expression
