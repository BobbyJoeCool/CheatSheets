Sheet 009

Variables, Mutability & Shadowing

let · let mut · shadowing with let · block scope · unused _x · destructuring let (a, b) · must initialize before use

Immutable by Default

Variables declared with let are immutable: assign once and they cannot change. Add mut to allow changes. Declaring a new variable with the same name shadows the old one, which lets you transform a value (even to a different type) without inventing new names.

Key Points

  • Types are inferred but fixed: a mut i32 stays i32
  • Shadowing creates a new variable; the old one is hidden
  • Variables must be initialized before use (checked at compile time)
  • Names are snake_case

let, mut and Shadowing

let x = 5;
// x = 6;                     // error: cannot assign twice to immutable

let mut count = 0;
count += 1;                   // OK: mut

let input = "42";
let input: i32 = input.parse().unwrap();   // shadowing, new type
let input = input * 2;        // 84

let (a, b) = (1, "one");      // destructuring
let [first, .., last] = [10, 20, 30, 40];  // first = 10, last = 40

let y;                        // declare now
if count > 0 { y = "positive"; } else { y = "zero"; }
println!("{y}");              // assigned exactly once on every path

{
    let x = "inner";          // shadows only inside this block
    println!("{x}");          // inner
}
println!("{x}");              // 5

let _unused = 99;             // no warning

Code Explained

Reassigning an immutable variable is a compile error
Shadowing lets input go from &str to i32
Arrays and tuples destructure in let
y is assigned once on every path, so it needs no mut

Coming From…

  • C++ variables are mutable unless const; Rust is the reverse
  • Java final ≈ Rust let; shadowing in the same scope is not allowed
  • Python / JavaScript reassignment is free; const in JS ≈ Rust let

The Rust Way

  • mut by habit → immutable let, add mut only when needed
  • input_str, input_num names → shadow input

Declarations

FormMeaning
let x = 5;Immutable, inferred
let mut x = 5;Mutable
let x: u8 = 5;Explicit type
let x;Declare, assign later
let (a, b) = t;Destructure
let _x = v;Unused OK
let _ = v;Ignore (drops at once)

⚠ Common Mistakes

  • Adding mut everywhere and losing the safety benefit
  • Confusing shadowing with mutation
  • let _ = guard; drops the value immediately (use _guard)

✓ Tips & Best Practices

  • Let the compiler tell you when mut is needed
  • Use shadowing for parse-and-convert steps
  • Keep variables in the smallest scope

Quick Summary

  • let — immutable
  • let mut — mutable
  • shadowing — new variable
  • initialize before use
