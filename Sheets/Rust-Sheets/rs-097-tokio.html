Tokio

#[tokio::main] · tokio::spawn · join! / select! · tokio::time::sleep · tokio::sync::Mutex / mpsc · spawn_blocking

The Most Common Async Runtime

Tokio provides the executor, timers, async I/O, channels and sync primitives. #[tokio::main] starts a multi-threaded runtime. tokio::spawn runs a future as an independent task (like a lightweight thread). join! waits for several futures, select! takes the first to finish, and spawn_blocking moves blocking work off the async threads.

Key Points

  • cargo add tokio -F full (or pick features)
  • Spawned tasks need Send + 'static futures
  • JoinHandle::await returns Result<T, JoinError>
  • Use tokio::sync::Mutex only when holding the lock across .await

Tokio Tasks, Timers, Channels

use std::time::Duration;
use tokio::sync::mpsc;
use tokio::time::{sleep, timeout};

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let h = tokio::spawn(async { 7 });      // independent task
    println!("{}", h.await?);               // 7

    let (a, b) = tokio::join!(work("a", 30), work("b", 10)); // both at once
    println!("{a} {b}");
    tokio::select! {                        // first one wins, other is dropped
        v = work("fast", 5) => println!("got {v}"),
        _ = sleep(Duration::from_secs(1)) => println!("timed out"),
    }
    let (tx, mut rx) = mpsc::channel::<String>(16);   // bounded async channel
    for id in 0..3 {
        let tx = tx.clone();
        tokio::spawn(async move { tx.send(format!("job {id}")).await.ok(); });
    }
    drop(tx);
    while let Some(msg) = rx.recv().await { println!("{msg}"); }

    let hash = tokio::task::spawn_blocking(|| expensive_cpu_hash()).await?;
    println!("{hash}");
    Ok(())
}

async fn work(name: &str, ms: u64) -> String {
    sleep(Duration::from_millis(ms)).await;
    name.to_uppercase()
}
fn expensive_cpu_hash() -> u64 { (0..1_000_000u64).fold(0, |h, x| h ^ x) }

Code Explained

tokio::spawn returns a handle you can .await
join! runs both futures and waits for both
select! cancels the losing branch by dropping it
spawn_blocking keeps CPU work off the async worker threads

Coming From…

  • JavaScript Promise.all ≈ join!, Promise.race ≈ select!
  • Python asyncio.gather, asyncio.wait_for, asyncio.Queue
  • Go goroutines + channels + select (built into the language)

The Rust Way

  • std::sync::mpsc in async code → tokio::sync::mpsc
  • CPU-heavy loops in tasks → spawn_blocking or rayon

⚠ Common Mistakes

  • Calling blocking std functions inside tasks
  • Ignoring JoinHandle results and missing panics
  • Assuming select! lets the losing future finish (it is dropped)

✓ Tips & Best Practices

  • Use JoinSet to manage a dynamic group of tasks
  • Use CancellationToken (tokio-util) for graceful shutdown
  • Enable only the Tokio features you use
