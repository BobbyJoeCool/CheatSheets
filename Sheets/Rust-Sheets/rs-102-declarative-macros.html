Declarative Macros

macro_rules! · $x:expr / $t:ty / $i:ident · repetition $(…),* · hygiene · #[macro_export] · when to use a macro

Macros by Example

macro_rules! defines a macro by pattern matching on Rust syntax: each rule matches input tokens and expands to code. Fragment specifiers like $x:expr capture pieces, and $( … ),* handles repetition. Macros can take variable numbers of arguments and generate items, which functions cannot. Prefer functions when they suffice.

Key Points

  • Invoke with !: my_vec![1, 2], m!(…), m!{…}
  • Rules are tried top to bottom
  • Macros must be defined before use in a file (textual order)
  • #[macro_export] makes a macro available at the crate root

Under the Hood

  • Expansion happens after parsing, before type checking
  • Hygiene: local variables created inside a macro do not clash with the caller's names
  • Expanded code is then type-checked like hand-written code
  • cargo expand shows the exact expansion

macro_rules!

macro_rules! square {
    ($x:expr) => { $x * $x };
}
println!("{}", square!(2 + 3));             // 25: $x is one expression

macro_rules! my_vec {
    () => { Vec::new() };
    ($($item:expr),+ $(,)?) => {{       // one or more, optional trailing comma
        let mut v = Vec::new();
        $( v.push($item); )+
        v
    }};
}
let v: Vec<i32> = my_vec![1, 2, 3,];        // [1, 2, 3]

#[macro_export]
macro_rules! hashmap {
    ($($k:expr => $v:expr),* $(,)?) => {
        std::collections::HashMap::from([$(($k, $v)),*])
    };
}
let m = hashmap! { "a" => 1, "b" => 2 };

macro_rules! getter {                       // generate methods
    ($name:ident : $t:ty) => {
        pub fn $name(&self) -> &$t { &self.$name }
    };
}
struct User { name: String, age: u32 }
impl User { getter!(name: String); getter!(age: u32); }

Code Explained

square!(2 + 3) treats 2 + 3 as one expression, so the result is 25
$( … ),+ repeats for each comma-separated item
ident and ty fragments let macros generate methods
#[macro_export] makes hashmap! usable from other crates

Coming From…

  • C / C++ #define text substitution: no hygiene, no syntax awareness
  • Python no macros; decorators and metaclasses cover some uses
  • Java no macros; annotation processors / Lombok generate code

The Rust Way

  • a macro that could be a generic function → the function
  • C-style #define constants → const items

Repetition

SyntaxMeans
$( … ),*Zero or more, comma-separated
$( … ),+One or more
$( … )?Optional
$(,)?Optional trailing comma
$( … );*Semicolon-separated

⚠ Common Mistakes

  • Expecting C-like text substitution (macros work on tokens)
  • Using a macro before its definition in the file
  • Unreadable recursive macros where a function would do

✓ Tips & Best Practices

  • Add a $(,)? rule for trailing commas
  • Use cargo expand to debug expansions
  • Use $crate::path inside exported macros

Quick Summary

  • macro_rules! pattern → code
  • $x:expr, $i:ident, $t:ty
  • $( … ),* repetition
  • hygienic, token-based
