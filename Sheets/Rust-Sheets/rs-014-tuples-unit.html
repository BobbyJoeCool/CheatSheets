Tuples & the Unit Type

(i32, &str) · .0 / .1 · destructuring · unit () · returning multiple values · never type !

Grouping Values Without a Struct

A tuple groups a fixed number of values of possibly different types, accessed by position (.0, .1) or destructured with let. The empty tuple () is the unit type: the value of expressions that return nothing. The never type ! marks expressions that never finish, like panic! or loop {}.

Key Points

  • Tuples up to 12 elements implement Debug, PartialEq, etc.
  • A one-element tuple needs a comma: (5,)
  • Functions with no return type return ()
  • ! coerces to any type

Under the Hood

  • () is a zero-sized type: it takes no memory
  • Tuple fields may be reordered in memory for alignment (no guaranteed layout)
  • Vec<()> stores only a length; no allocation for elements

Tuples, Unit and Never

let point = (3, -4);
let record: (&str, u32, bool) = ("Ada", 36, true);

println!("{}", point.0);           // 3
println!("{:?}", record);          // ("Ada", 36, true)

let (name, age, _) = record;       // destructure, ignore the bool
println!("{name} is {age}");

fn min_max(v: &[i32]) -> (i32, i32) {
    (*v.iter().min().unwrap(), *v.iter().max().unwrap())
}
let (lo, hi) = min_max(&[4, 9, 1]);    // (1, 9)

let single = (5,);                 // one-element tuple
let not_tuple = (5);               // just 5 in parentheses

fn log(msg: &str) { println!("{msg}"); }   // returns ()
let unit: () = log("hi");

fn fail(msg: &str) -> ! { panic!("{msg}") }
let n: i32 = if lo > 0 { lo } else { fail("bad") };   // ! fits as i32

let mut pairs = vec![(2, 'b'), (1, 'a')];
pairs.sort();                      // sorts by .0, then .1

Code Explained

Tuples are accessed by index fields .0, .1
Returning a tuple is the easy way to return two values
() is what functions without -> return
fail returns !, so it fits where an i32 is expected

Coming From…

  • C++ std::tuple / std::pair with structured bindings
  • Python tuples and unpacking work the same way
  • Java no tuples; use records or Map.Entry

The Rust Way

  • tuples with 4+ fields passed around → a named struct
  • (T,) confusion → remember the trailing comma

⚠ Common Mistakes

  • (5) expecting a tuple
  • Long tuples that hide meaning (t.3?)
  • Comparing tuples of different lengths (type error)

✓ Tips & Best Practices

  • Use tuples for short-lived pairs; structs for anything named
  • Destructure in for (i, x) in … loops
  • Use () as the "nothing" type in generics like Result<(), E>

Quick Summary

  • (a, b) — tuple
  • .0 / destructure
  • () — unit
  • ! — never returns
