Sheet 010

Constants & Statics

const · static · static mut (unsafe) · SCREAMING_CASE · compile-time evaluation · LazyLock / OnceLock

Global Values

const defines a compile-time value that is copied into every place it is used. static defines a single value with a fixed memory address for the whole program. Mutable statics require unsafe; for global state computed at runtime, use LazyLock or OnceLock from the standard library.

Key Points

  • Both need explicit types
  • const can be used in array lengths and generics
  • static values must be Sync (safe to share across threads)
  • LazyLock (Rust 1.80) computes on first access

const, static, LazyLock

use std::sync::{LazyLock, Mutex, OnceLock};
use std::collections::HashMap;

const MAX_USERS: u32 = 1_000;
const BUFFER: usize = 4 * 1024;
static APP_NAME: &str = "cheatsheets";

const fn square(x: u32) -> u32 { x * x }
const AREA: u32 = square(12);          // computed at compile time

static CODES: LazyLock<HashMap<&str, u16>> = LazyLock::new(|| {
    HashMap::from([("ok", 200), ("not_found", 404)])
});

static COUNTER: Mutex<u64> = Mutex::new(0);   // safe mutable global

static CONFIG: OnceLock<String> = OnceLock::new();

fn main() {
    let buf = [0u8; BUFFER];              // const as array length
    println!("{} {}", MAX_USERS, AREA);   // 1000 144
    println!("{}", CODES["not_found"]);   // 404
    *COUNTER.lock().unwrap() += 1;
    CONFIG.set("prod".into()).unwrap();   // set once
    println!("{}", CONFIG.get().unwrap());
}

Code Explained

const fn can run at compile time
LazyLock builds the HashMap on first use, once
A Mutex makes a static safely mutable
OnceLock is set once at runtime, then read many times

Coming From…

  • C++ constexpr ≈ const; globals ≈ static
  • Java static final fields; lazy holder idiom
  • Python module-level constants (by convention only)

The Rust Way

  • static mut → Mutex, atomics, or OnceLock
  • lazy_static! / once_cell crates → std LazyLock / OnceLock

⚠ Common Mistakes

  • Using static mut and needing unsafe everywhere
  • Expecting const to have one address (each use is a copy)
  • Heavy runtime work in a constant (not allowed: use LazyLock)

✓ Tips & Best Practices

  • Prefer const for plain values
  • Use LazyLock for regexes and lookup tables
  • Keep global mutable state rare; pass values instead

Quick Summary

  • const — inlined value
  • static — one address
  • const fn — compile-time code
  • LazyLock / OnceLock — runtime init
