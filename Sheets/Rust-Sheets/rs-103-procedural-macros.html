Procedural Macros

derive macros · attribute macros · function-like macros · proc-macro crate · syn / quote · reading cargo expand output

Macros as Compiler Plugins

Procedural macros are Rust functions that run at compile time, take a TokenStream and return a new one. Derive macros (#[derive(Serialize)]) add impls, attribute macros (#[tokio::main]) transform an item, and function-like macros (sql!(…)) look like calls. They live in a separate crate with proc-macro = true and almost always use syn and quote.

Key Points

  • A proc-macro crate can only export macros
  • syn parses tokens into a syntax tree
  • quote! builds tokens with #var interpolation
  • Errors: syn::Error::new_spanned(...).to_compile_error()

A Derive Macro

// hello_derive/Cargo.toml: [lib] proc-macro = true · deps: syn, quote

// hello_derive/src/lib.rs
use proc_macro::TokenStream;
use quote::quote;
use syn::{parse_macro_input, DeriveInput};
#[proc_macro_derive(Hello)]
pub fn derive_hello(input: TokenStream) -> TokenStream {
    let ast = parse_macro_input!(input as DeriveInput);
    let name = &ast.ident;                   // the type's name
    let expanded = quote! {
        impl #name {
            pub fn hello() -> String {
                format!("Hello from {}!", stringify!(#name))
            }
        }
    };
    expanded.into()
}

#[proc_macro_attribute]
pub fn log_call(_attr: TokenStream, item: TokenStream) -> TokenStream {
    let f = parse_macro_input!(item as syn::ItemFn);
    let sig = &f.sig;
    let body = &f.block;
    let fname = sig.ident.to_string();
    quote! { #sig { println!("calling {}", #fname); #body } }.into()
}

// app/src/main.rs
// use hello_derive::{Hello, log_call};
// #[derive(Hello)]
// struct Pancakes;
// #[log_call]
// fn work() { println!("working"); }
// fn main() { println!("{}", Pancakes::hello()); work(); }
// → Hello from Pancakes!  calling work  working

Code Explained

parse_macro_input! turns tokens into a DeriveInput
#name inside quote! inserts the type name
The attribute macro wraps the function body with a log line
Users import macros like any other item

Coming From…

  • Java annotation processors (generate new files, cannot modify)
  • Python decorators run at runtime, not compile time
  • C# source generators; Kotlin KSP

The Rust Way

  • complex macro_rules! parsing → a proc macro with syn
  • a proc macro for something a trait + generics can do → the trait

⚠ Common Mistakes

  • Trying to export normal functions from a proc-macro crate
  • Panicking instead of emitting compile_error! with a span
  • Heavy syn features slowing every build

✓ Tips & Best Practices

  • Read real expansions with cargo expand before writing your own
  • Use spans so errors point at user code
  • Keep proc macros thin; put logic in a normal library
