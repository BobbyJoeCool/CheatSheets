Sheet 017

String vs &str

String (owned, heap) · &str (borrowed slice) · literals are &'static str · &String → &str deref · as_str() · take &str params

Two String Types

String is an owned, growable, heap-allocated UTF-8 buffer. &str is a borrowed view (a string slice) into UTF-8 data owned by someone else: a String, a literal baked into the binary, or part of a file buffer. Functions that only read text should take &str; return or store String when you need ownership.

Key Points

  • String literals have type &'static str
  • &String coerces to &str automatically (deref coercion)
  • Convert &str → String with to_string(), String::from, into()
  • Both are always valid UTF-8

Under the Hood

  • String = Vec<u8>: pointer, capacity, length (24 bytes on the stack)
  • &str is a fat pointer: data pointer + length (16 bytes)
  • Literals live in the read-only data section; no allocation
  • A slice like &s[0..3] points into the same heap buffer

Owned and Borrowed Text

let literal: &'static str = "hello";       // in the binary
let mut owned: String = String::from("hello");
owned.push_str(", world");                  // String can grow

let view: &str = &owned;                    // &String → &str
let part: &str = &owned[0..5];              // "hello" (a slice)
let again: String = part.to_string();       // copy into a new String

fn shout(s: &str) -> String {               // read-only param: &str
    s.to_uppercase()
}
println!("{}", shout(literal));             // HELLO
println!("{}", shout(&owned));              // HELLO, WORLD
println!("{}", shout(owned.as_str()));      // explicit

struct User { name: String }                // store owned data
let u = User { name: "Ada".into() };

fn first_word(s: &str) -> &str {            // return a borrow of the input
    s.split(' ').next().unwrap_or("")
}
println!("{}", first_word("big red dog")); // big

Code Explained

A literal is a &'static str pointing into the binary
&owned gives a &str view without copying
shout accepts literals and Strings because it takes &str
Structs usually own their text as String

Coming From…

  • C++ std::string vs std::string_view (same split, but views can dangle)
  • Go one immutable string type; []byte for building
  • Java / Python one immutable string type; builders for mutation

The Rust Way

  • fn f(s: &String) → fn f(s: &str) (accepts more)
  • fn f(s: String) that only reads → &str (no clone needed)

⚠ Common Mistakes

  • Taking &String parameters (clippy: ptr_arg)
  • Returning &str to a local String (E0515: returns a reference to local data)
  • Cloning Strings just to call a function

✓ Tips & Best Practices

  • Default to &str params and String fields
  • Use impl Into<String> for constructors that store a name
  • Use Cow<str> when you only sometimes allocate (sheet 076)

Quick Summary
