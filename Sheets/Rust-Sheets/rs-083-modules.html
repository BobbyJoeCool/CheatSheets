Sheet 083

Modules

mod · inline vs file modules (foo.rs, foo/mod.rs) · use · crate:: / super:: / self:: · pub use re-exports · glob imports

Organizing Code

A crate is a tree of modules rooted at main.rs or lib.rs. mod foo; tells the compiler to load foo.rs (or foo/mod.rs), and mod foo { … } declares one inline. use brings paths into scope. Paths start from crate:: (root), super:: (parent) or self:: (current module).

Key Points

  • Files are not modules until declared with mod
  • Prefer foo.rs + foo/ folder over foo/mod.rs (2018+)
  • pub use re-exports items at a nicer path
  • Glob use x::* is fine for preludes and tests

Module Tree

// src/
// ├── main.rs
// ├── config.rs            mod config;
// └── net/
//     ├── mod.rs  (or net.rs beside the folder)
//     └── http.rs          pub mod http;   (inside net)

// main.rs
mod config;                                 // loads src/config.rs
mod net;                            // loads src/net.rs or src/net/mod.rs

mod util {                                  // inline module
    pub fn clamp01(x: f64) -> f64 { x.clamp(0.0, 1.0) }
    pub mod text {
        pub fn shout(s: &str) -> String { s.to_uppercase() }
        pub fn helper() -> f64 { super::clamp01(2.0) }   // parent module
    }
}

use util::text::shout;                      // bring into scope
use std::collections::{HashMap, HashSet};   // grouped import
use std::io::{self, Write};                 // self = std::io
use std::fmt::Result as FmtResult;          // rename

fn main() {
    println!("{}", shout("hi"));
    println!("{}", crate::util::clamp01(-1.0));   // absolute path
    println!("{}", util::text::helper());
    let _cfg = config::load();
}

// net.rs
// pub mod http;
// pub use http::Client;                    // re-export: net::Client

// lib.rs prelude pattern
// pub mod prelude { pub use crate::{Client, Config, Error}; }
// user code: use mycrate::prelude::*;

Code Explained

mod config; pulls in config.rs as a child module
super::clamp01 calls the parent module's function
Grouped and renamed imports reduce clutter
pub use exposes net::Client without the http level

Coming From…

  • Python files are modules automatically; Rust needs mod
  • Java packages follow folders; one public class per file
  • Go one package per folder; capitalized names are exported

The Rust Way

  • deep use a::b::c::d::E paths in user code → pub use re-exports
  • use super::super::x chains → use crate::path::x

⚠ Common Mistakes

  • Creating a file but never declaring mod for it
  • Declaring the same file with mod in two places
  • Mixing foo.rs and foo/mod.rs for one module (E0761)

✓ Tips & Best Practices

  • One module per concept; keep files under a few hundred lines
  • Use pub use to design a flat public API
  • Let rust-analyzer add use lines

Quick Summary

  • mod x; loads x.rs
  • use brings names in
  • crate:: / super:: / self::
  • pub use — re-export
