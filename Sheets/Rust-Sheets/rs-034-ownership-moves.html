Sheet 034

Ownership & Moves

three ownership rules · move on assignment · move into functions · drop at scope end · E0382 use after move · stack vs heap

Every Value Has One Owner

Ownership is how Rust manages memory without a garbage collector. Each value has one owner; when the owner goes out of scope, the value is dropped. Assigning a heap-owning value like String or Vec to another variable, or passing it to a function, moves it: the old name can no longer be used. This prevents double frees at compile time.

Key Points

  • Rule 1: each value has an owner
  • Rule 2: only one owner at a time
  • Rule 3: owner out of scope → value dropped
  • Copy types (ints, bool, char) are copied instead of moved

Under the Hood

  • A move is a shallow memcpy of the stack part (ptr, len, cap)
  • The source is marked uninitialized at compile time; no runtime flag in most cases
  • Drop runs at the closing brace, in reverse declaration order
  • When drops depend on runtime paths, the compiler adds a hidden drop flag

Moves and Drops

let s1 = String::from("hello");             // s1 owns the heap buffer
let s2 = s1;                                // MOVE: s2 owns it now
// println!("{s1}");                // E0382: borrow of moved value: `s1`
println!("{s2}");

let n1 = 5;
let n2 = n1;                                // i32 is Copy: both usable
println!("{n1} {n2}");

fn take(s: String) { println!("took {s}"); }   // s dropped at end
fn give() -> String { String::from("new") }    // ownership moves out

let a = String::from("data");
take(a);                                    // a moved into take
// take(a);                                 // E0382: use of moved value
let b = give();                             // b owns the returned String

fn take_and_return(s: String) -> String { s }
let c = take_and_return(b);                 // round-trip ownership

{
    let temp = vec![1, 2, 3];               // allocated
    println!("{}", temp.len());
}                                           // temp dropped here, memory freed

let v = vec![String::from("x"), String::from("y")];
let first = v[0].clone();                   // can't move out of a Vec index
for s in v { println!("{s}"); }             // v moved into the loop

Code Explained

let s2 = s1 transfers ownership; s1 becomes unusable
Integers implement Copy, so assignment copies them
Passing a to take moves it into the function
Leaving a block drops everything it owns

Coming From…

  • C++ like std::move, but the source cannot be used afterwards (no moved-from state)
  • Java / Python / Go assignment copies a reference; a GC frees memory later
  • C manual free; Rust inserts the free at scope end

The Rust Way

  • .clone() to silence E0382 → pass &s if the callee only reads
  • returning a value just to give it back → borrow instead (sheet 036)

⚠ Common Mistakes

  • Using a variable after passing it to a function by value
  • Cloning everything instead of borrowing
  • Trying to move a field out of a borrowed struct

✓ Tips & Best Practices

  • Read E0382 notes: they show where the move happened
  • Take &T when a function only needs to read
  • Use std::mem::take to move out and leave a default

Quick Summary

  • one owner per value
  • assignment moves heap types
  • scope end → drop
  • Copy types are copied
