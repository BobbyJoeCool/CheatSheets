Shared State: Arc, Mutex & Atomics

Arc<T> · Mutex<T> / lock() · RwLock · poisoning · AtomicUsize & Ordering · avoiding deadlocks

Sharing Data Between Threads

Arc<T> is a thread-safe reference-counted pointer that lets threads share ownership. Pair it with Mutex<T> to mutate: lock() returns a guard that unlocks when dropped, and the data is only reachable through the guard. RwLock allows many readers or one writer, and atomics handle simple counters without locks.

Key Points

  • lock() returns Result: Err means a thread panicked while holding it (poisoned)
  • Keep critical sections short; never hold a lock across .await
  • Lock in a consistent order to avoid deadlocks
  • parking_lot offers faster, non-poisoning locks

Under the Hood

  • Arc clone/drop use atomic increments; Rc uses plain ones
  • std Mutex on Linux is a futex: uncontended lock/unlock costs a few atomic ops
  • The guard's Drop calls unlock, so early returns and ? cannot leak a lock
  • Atomic Ordering::Relaxed is enough for counters; use Acquire/Release to publish data

Arc + Mutex + Atomics

use std::sync::{Arc, Mutex, RwLock};
use std::sync::atomic::{AtomicUsize, Ordering};
use std::thread;

let counter = Arc::new(Mutex::new(0));
let mut handles = vec![];
for _ in 0..8 {
    let c = Arc::clone(&counter);
    handles.push(thread::spawn(move || {
        for _ in 0..1000 { *c.lock().unwrap() += 1; }   // unlock at each ;
    }));
}
for h in handles { h.join().unwrap(); }
println!("{}", *counter.lock().unwrap());   // 8000

let hits = Arc::new(AtomicUsize::new(0));   // lock-free counter
thread::scope(|s| {
    for _ in 0..4 {
        s.spawn(|| { hits.fetch_add(1, Ordering::Relaxed); });
    }
});
println!("{}", hits.load(Ordering::Relaxed));   // 4

let config = RwLock::new(String::from("v1"));
println!("{}", *config.read().unwrap());    // many readers at once
config.write().unwrap().push_str("-patched");   // one writer

let poisoned = Arc::new(Mutex::new(0));
let p2 = Arc::clone(&poisoned);
let _ = thread::spawn(move || { let _g = p2.lock().unwrap(); panic!() }).join();
println!("{}", poisoned.is_poisoned());     // true
let value = poisoned.lock().unwrap_or_else(|e| e.into_inner());   // recover

Code Explained

Each thread gets its own Arc clone of the same Mutex
The guard unlocks at the end of each statement
Atomics count without a lock
A panic while locked poisons the Mutex; into_inner recovers the data

Coming From…

  • C++ std::shared_ptr + std::mutex (data not tied to the lock)
  • Java synchronized / ReentrantLock; AtomicInteger
  • Go sync.Mutex beside the data (by convention only)

The Rust Way

  • Mutex<i32> counters → AtomicI32 / AtomicUsize
  • locking inside a hot loop → accumulate locally, lock once

⚠ Common Mistakes

  • Holding a guard while calling code that locks the same Mutex (deadlock)
  • Holding a std Mutex guard across .await
  • Rc<RefCell<T>> across threads (E0277: not Send)

✓ Tips & Best Practices

  • Wrap shared state in a struct with methods that lock internally
  • Prefer message passing when ownership can move
  • Use parking_lot::Mutex or dashmap for heavy contention

Quick Summary
