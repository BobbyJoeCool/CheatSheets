Enums with Data

variants with data · struct-like variants · impl on enums · Option & Result are enums · C-like enums & discriminants · match on enums

Sum Types

A Rust enum is a type that is one of several variants, and each variant can carry its own data. This models states and messages precisely: a value cannot be in an impossible combination. match must handle every variant, so adding one shows you every place to update. Option and Result are ordinary enums.

Key Points

  • Variants can be unit, tuple-like or struct-like
  • Enums can have methods and implement traits
  • C-like enums can have explicit discriminants and as casts
  • Use enums for state machines and protocol messages

Under the Hood

  • Layout: a tag (discriminant) + space for the largest variant
  • Niche optimization: Option<&T>, Option<Box<T>> reuse the null value as the tag
  • Size check: size_of::<Option<bool>>() is 1
  • A match on an enum typically compiles to a jump table on the tag

Enums

#[derive(Debug)]
enum Shape {
    Circle(f64),                            // tuple-like
    Rect { w: f64, h: f64 },                // struct-like
    Point,                                  // unit
}
impl Shape {
    fn area(&self) -> f64 {
        match self {
            Shape::Circle(r) => std::f64::consts::PI * r * r,
            Shape::Rect { w, h } => w * h,
            Shape::Point => 0.0,
        }
    }
}
let shapes = vec![Shape::Circle(1.0), Shape::Rect { w: 2.0, h: 3.0 },
                  Shape::Point];
let total: f64 = shapes.iter().map(Shape::area).sum();   // 9.14…

enum Msg { Quit, Move { x: i32, y: i32 }, Write(String) }
fn handle(m: Msg) {
    match m {
        Msg::Quit => println!("bye"),
        Msg::Move { x, y } => println!("to {x},{y}"),
        Msg::Write(text) => println!("{text}"),
    }
}
handle(Msg::Move { x: 1, y: 2 });

#[derive(Debug, Clone, Copy, PartialEq)]
enum Level { Low = 1, Mid = 5, High = 10 }  // C-like, explicit values
println!("{}", Level::Mid as i32);          // 5

use std::mem::size_of;
println!("{}", size_of::<Option<Box<i32>>>());   // 8: niche, no extra tag
println!("{}", size_of::<Option<u64>>());        // 16: tag + padding

Code Explained

Each variant holds different data
match self handles every variant in area
Explicit discriminants allow as i32 casts
Option<Box<T>> uses the null niche, so no tag byte is needed

Coming From…

  • C++ std::variant + std::visit (much clunkier)
  • Java sealed interfaces + records + pattern switch (Java 21)
  • Go / Python no sum types; use interfaces, classes or tags

The Rust Way

  • a struct with kind: String and optional fields → an enum with data
  • bool flags that conflict → enum variants

⚠ Common Mistakes

  • A _ => arm on your own enum hiding new variants
  • Large variant making every value big (box the big one)
  • Casting a data-carrying enum with as (only C-like enums)

✓ Tips & Best Practices

  • Box large variant payloads: Big(Box<Data>)
  • Use #[non_exhaustive] on public enums that may grow
  • Use strum to iterate variants or parse names
