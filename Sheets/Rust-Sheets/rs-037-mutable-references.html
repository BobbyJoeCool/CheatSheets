Sheet 037

Mutable References

&mut T · one mutable OR many shared · E0499 / E0502 · non-lexical lifetimes (NLL) · reborrowing · mem::swap / take / replace

Exclusive Access

A &mut T lets you change a value you do not own. While it exists, it is the only way to reach that value: no other &mut (E0499) and no & (E0502). This rule prevents data races and iterator invalidation at compile time. Borrows end at their last use (non-lexical lifetimes), not at the closing brace.

Key Points

  • The variable itself must be let mut to take &mut
  • &mut is not Copy; it is moved or reborrowed
  • Passing &mut *r or just r to a function reborrows
  • mem::take moves a value out, leaving Default

&mut and the Rules

fn add_suffix(s: &mut String) { s.push_str("!"); }

let mut msg = String::from("hi");
add_suffix(&mut msg);
println!("{msg}");                          // hi!

let r1 = &mut msg;
// let r2 = &mut msg;                       // E0499: second mutable borrow
r1.push('?');

let mut v = vec![1, 2, 3];
let first = &v[0];
// v.push(4);                               // E0502: v borrowed as immutable
println!("{first}");                        // last use of `first`
v.push(4);                                  // OK now (NLL)

for x in v.iter_mut() { *x *= 10; }         // [10, 20, 30, 40]

fn bump(n: &mut i32) { *n += 1; }
let mut count = 0;
let r = &mut count;
bump(r);                                    // implicit reborrow
bump(r);                                    // r still usable
println!("{count}");                        // 2

use std::mem;
let mut a = String::from("a");
let mut b = String::from("b");
mem::swap(&mut a, &mut b);                  // a = "b", b = "a"
let old = mem::take(&mut a);                // a = "", old = "b"
let prev = mem::replace(&mut b, "z".into()); // b = "z", prev = "a"

let (left, right) = v.split_at_mut(2);      // two &mut to disjoint parts
left[0] += right[0];

Code Explained

&mut msg lets add_suffix modify the caller's String
A second &mut while r1 is live is rejected
After first's last use, v can be mutated again
split_at_mut gives two non-overlapping mutable slices

Coming From…

  • C++ any number of non-const references may alias
  • Go / Java shared mutable objects; data races are possible
  • Python everything is mutable through any reference

The Rust Way

  • let tmp = x.clone(); x = y; y = tmp; → mem::swap(&mut x, &mut y)
  • Option field move-out errors → field.take()

⚠ Common Mistakes

  • Holding a reference into a Vec while pushing to it
  • Forgetting let mut on the owner
  • Calling self.a() (&mut self) while holding &self.b across it

✓ Tips & Best Practices

  • Shorten borrows: copy out the value you need, then mutate
  • Borrow disjoint struct fields separately: &mut s.a, &mut s.b
  • Use split_at_mut / chunks_mut for parallel slice edits

Quick Summary

  • &mut T — exclusive
  • E0499 / E0502
