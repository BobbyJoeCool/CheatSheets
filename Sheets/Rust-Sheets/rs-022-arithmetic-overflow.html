Arithmetic & Overflow

+ - * / % · integer division truncates · rem_euclid · pow · checked_add / wrapping_add / saturating_add / overflowing_add · no ++

Arithmetic Operators

Arithmetic needs both operands to be the same type: i32 + i64 does not compile. Integer division truncates toward zero and % keeps the sign of the left operand. Overflow panics in debug builds, so code that might overflow should use the explicit checked, wrapping or saturating methods.

Key Points

  • There is no ++ or --: use += 1
  • Division by zero panics for integers; floats give inf/NaN
  • pow(u32) for integers, powi / powf for floats
  • rem_euclid always returns a non-negative result

Operators and Overflow

let a = 17;
let b = 5;
println!("{} {} {}", a + b, a - b, a * b);   // 22 12 85
println!("{} {}", a / b, a % b);             // 3 2
println!("{} {}", -17 / 5, -17 % 5);         // -3 -2
println!("{}", (-17i32).rem_euclid(5));      // 3
println!("{}", (-17i32).div_euclid(5));      // -4
println!("{}", 17.0 / 5.0);                  // 3.4
println!("{}", 2i32.pow(10));                // 1024
println!("{}", 10_i64.pow(12));              // 1000000000000

let x: i32 = 10;
let y: i64 = 20;
// let z = x + y;                            // error: mismatched types
let z = i64::from(x) + y;                    // 30

let mut n = 0;
n += 1;                                      // no n++

let big = u8::MAX;
println!("{:?}", big.checked_add(1));        // None
println!("{}", big.wrapping_add(1));         // 0
println!("{}", big.saturating_add(1));       // 255
println!("{:?}", big.overflowing_add(1));    // (0, true)
println!("{:?}", 10u32.checked_sub(20));     // None
println!("{:?}", 7i32.checked_div(0));       // None (no panic)
println!("{}", 7u32.abs_diff(10));           // 3
println!("{}", (-5i32).abs());               // 5

Code Explained

/ and % truncate toward zero
rem_euclid / div_euclid floor-style math for negatives
Mixed types need an explicit conversion
checked_div returns None instead of panicking on zero

Coming From…

  • C++ mixed types promote silently; signed overflow is UB
  • Java silent wraparound; Math.addExact throws on overflow
  • Python -17 // 5 is -4 (floors); ints never overflow

The Rust Way

  • i += 1 where i may hit MAX → i = i.checked_add(1)?
  • (a % n + n) % n → a.rem_euclid(n)

⚠ Common Mistakes

  • Assuming release builds catch overflow
  • u32 subtraction going below zero (panic or wrap)
  • Python-style floor division expectations for negatives

✓ Tips & Best Practices

  • Use abs_diff for unsigned distances
  • Use i64 for intermediate sums of i32
  • Enable overflow-checks in release where correctness matters
