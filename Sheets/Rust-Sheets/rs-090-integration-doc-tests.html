Integration & Doc Tests

tests/ directory · tests/common/mod.rs · doc tests in /// · no_run / ignore / should_panic · #[ignore] · cargo test --doc

Testing the Public API

Integration tests in the tests/ folder are separate crates that use your library exactly as a user would: only pub items are reachable. Doc tests are the code blocks in /// comments; they compile and run with cargo test, keeping examples correct. Binary-only crates need a lib.rs to be integration-tested.

Key Points

  • Each file in tests/ is its own test crate
  • Shared helpers go in tests/common/mod.rs (not tests/common.rs)
  • Doc test lines starting with # are hidden but run
  • Code block attributes: no_run, ignore, should_panic, compile_fail

Integration and Doc Tests

// src/lib.rs
/// Returns the slug form of a title.
///
/// ```
/// use blogtool::slugify;
/// assert_eq!(slugify("Hello World"), "hello-world");
/// ```
///
/// Hidden setup lines:
/// ```
/// # use blogtool::slugify;
/// let s = slugify("A  B");
/// assert_eq!(s, "a-b");
/// ```
/// ```should_panic
/// blogtool::slugify("");   // panics on empty input
/// ```
/// ```no_run
/// blogtool::publish_to("https://example.com");   // compiled, not run
/// ```
pub fn slugify(s: &str) -> String {
    assert!(!s.is_empty(), "empty title");
    s.split_whitespace().map(str::to_lowercase).collect::<Vec<_>>().join("-")
}
pub fn publish_to(_url: &str) {}

Code Explained

Doc examples run as tests, so docs stay accurate
# lines run but do not appear in rendered docs
should_panic and no_run change how a block is tested
Integration tests import the crate by name, like users

Coming From…

  • Python doctest + a tests/ folder for pytest
  • Java separate src/test tree; no runnable Javadoc examples
  • Go Example functions in _test.go run and appear in docs

The Rust Way

  • examples in README that drift → doc tests (include_str! the README)
  • testing internals from tests/ → unit tests in the module

⚠ Common Mistakes

  • Putting helpers in tests/common.rs (treated as a test crate)
  • Integration-testing a binary crate with no lib target
  • Doc examples that use unwrap on fallible network calls without no_run

✓ Tips & Best Practices

  • Keep main.rs thin and test the library
  • Use ? in doc tests by ending with # Ok::<(), Box<dyn std::error::Error>>(())
  • Run cargo test --doc in CI
