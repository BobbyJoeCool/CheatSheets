Cargo Basics

cargo new / cargo init · cargo build / --release · cargo run · cargo check · target/ · Cargo.toml & Cargo.lock · cargo add

Rust's Build Tool and Package Manager

Cargo creates projects, downloads dependencies from crates.io, builds, runs, tests and documents your code. Cargo.toml describes the package and its dependencies; Cargo.lock records exact versions. cargo check type-checks without producing a binary, which is much faster while editing.

Key Points

  • cargo new app = binary; cargo new --lib mylib = library
  • Debug builds go to target/debug, release to target/release
  • Commit Cargo.lock for applications
  • Pass program arguments after --

Everyday Cargo

cargo new hello            # binary crate with src/main.rs
cargo new --lib geometry   # library crate with src/lib.rs
cd hello

cargo check                # fast type check, no binary
cargo build                # debug build → target/debug/hello
cargo build --release      # optimized → target/release/hello
cargo run -- --name Ada    # build + run, args after --
cargo test                 # run tests
cargo add serde --features derive
cargo add tokio@1 -F full
cargo doc --open           # build and open docs
cargo clean                # delete target/

# Cargo.toml
# [package]
# name = "hello"
# version = "0.1.0"
# edition = "2024"
#
# [dependencies]
# serde = { version = "1", features = ["derive"] }

Code Explained

cargo check is the fastest feedback loop
--release turns on optimizations (much faster binaries)
cargo add edits Cargo.toml for you
edition = "2024" picks the language edition

Coming From…

  • Python uv / pip + pyproject.toml
  • Java Maven / Gradle with pom.xml or build.gradle.kts
  • JavaScript npm with package.json + package-lock.json

The Rust Way

  • benchmarking debug builds → always measure --release
  • waiting on cargo build while editing → cargo check (or rust-analyzer)

⚠ Common Mistakes

  • Timing debug builds and concluding Rust is slow
  • Forgetting -- before program arguments
  • Deleting Cargo.lock in an application repo

✓ Tips & Best Practices

  • Use cargo watch -x check (cargo-watch crate) for live checking
  • Add [profile.release] lto = true for smaller, faster binaries
  • Use cargo tree to inspect dependencies
