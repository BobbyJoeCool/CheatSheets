Fn, FnMut & FnOnce

The Three Closure Traits

Every closure implements one or more of three traits. FnOnce can be called once (it may consume captures), FnMut can be called many times and may mutate captures, and Fn can be called many times through a shared reference. Functions that accept closures state which trait they need; ask for the weakest one you can.

Key Points

  • Every Fn is also FnMut, and every FnMut is FnOnce
  • Accept FnOnce if you call it once (most flexible for callers)
  • fn(i32) -> i32 is a function pointer type
  • Plain functions implement all three traits

Accepting Closures

fn apply<F: Fn(i32) -> i32>(f: F, x: i32) -> i32 { f(x) }

fn repeat<F>(n: usize, mut f: F)
where
    F: FnMut(usize),
{
    for i in 0..n { f(i); }
}

fn run_once<F: FnOnce() -> String>(f: F) -> String { f() }

println!("{}", apply(|x| x * 2, 21));        // 42

let mut log = Vec::new();
repeat(3, |i| log.push(i));                  // FnMut: mutates log
println!("{log:?}");                         // [0, 1, 2]

let name = String::from("Ada");
let msg = run_once(move || name + "!");      // FnOnce: consumes name
println!("{msg}");                           // Ada!

fn double(x: i32) -> i32 { x * 2 }
println!("{}", apply(double, 5));            // functions work too: 10

let ops: Vec<fn(i32) -> i32> = vec![double, |x| x + 1];   // no captures
println!("{}", ops.iter().fold(3, |acc, f| f(acc)));      // 7

let consume = move || drop(log);             // FnOnce only
consume();
// consume();                          // E0382: closure moved by first call

fn make_counter() -> impl FnMut() -> u32 {
    let mut c = 0;
    move || { c += 1; c }
}
let mut next = make_counter();
println!("{} {}", next(), next());           // 1 2

Code Explained

apply needs Fn: it only reads its captures
repeat needs FnMut because the closure pushes to log
run_once accepts closures that consume what they capture
Closures without captures coerce to fn pointers

Coming From…

  • C++ std::function<int(int)> or a template parameter
  • Java Function<T,R>, Consumer<T>, Supplier<T>
  • Python any callable; no compile-time distinction

The Rust Way

  • F: Fn() for a callback called once → F: FnOnce()
  • long inline bounds → where clause

⚠ Common Mistakes

  • Requiring Fn when callers need to mutate state
  • Forgetting mut f: F to call an FnMut
  • Expecting a capturing closure to coerce to fn

✓ Tips & Best Practices

  • Accept impl FnOnce for one-shot callbacks
  • Use where clauses for readability
  • Use fn pointers for tables of plain functions

Quick Summary

  • FnOnce ⊇ FnMut ⊇ Fn
  • captures decide the trait
  • ask for the weakest
  • fn — pointer, no captures
