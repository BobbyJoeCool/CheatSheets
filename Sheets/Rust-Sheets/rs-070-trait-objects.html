Trait Objects & dyn

dyn Trait · Box<dyn Trait> / &dyn Trait · dynamic dispatch & vtables · dyn compatibility · Vec<Box<dyn Shape>> · generics vs trait objects

Runtime Polymorphism

A trait object dyn Trait lets one variable hold any type implementing the trait, chosen at runtime. It must sit behind a pointer: &dyn Trait, Box<dyn Trait> or Arc<dyn Trait>. Method calls go through a vtable. Only dyn-compatible traits (formerly "object safe") can be used this way.

Key Points

  • Use for heterogeneous collections and plugin-style APIs
  • Not dyn-compatible: generic methods, -> Self, Self: Sized requirements
  • Add + Send + Sync for thread-safe objects
  • Downcasting needs std::any::Any

Under the Hood

  • &dyn Trait is a fat pointer: data pointer + vtable pointer (16 bytes)
  • The vtable holds drop, size, align and one entry per method
  • Calls are indirect and usually not inlined
  • One vtable per (type, trait) pair, stored in read-only data

dyn Trait

trait Shape {
    fn area(&self) -> f64;
    fn name(&self) -> &str { "shape" }
}
struct Circle(f64);
struct Square(f64);
impl Shape for Circle {
    fn area(&self) -> f64 { std::f64::consts::PI * self.0 * self.0 }
    fn name(&self) -> &str { "circle" }
}
impl Shape for Square { fn area(&self) -> f64 { self.0 * self.0 } }

let shapes: Vec<Box<dyn Shape>> =
    vec![Box::new(Circle(1.0)), Box::new(Square(2.0))];
for s in &shapes {
    println!("{} {:.2}", s.name(), s.area());   // circle 3.14 / shape 4.00
}
let total: f64 = shapes.iter().map(|s| s.area()).sum();

fn print_area(s: &dyn Shape) { println!("{:.1}", s.area()); }   // borrowed
print_area(&Square(3.0));                   // 9.0

fn make(kind: &str) -> Box<dyn Shape> {     // type chosen at runtime
    if kind == "c" { Box::new(Circle(2.0)) } else { Box::new(Square(2.0)) }
}

use std::sync::Arc;
let shared: Arc<dyn Shape + Send + Sync> = Arc::new(Circle(0.5));

trait Cloner { fn dup(&self) -> Self; }     // returns Self → not dyn compatible
// let x: Box<dyn Cloner>;                  // E0038

use std::any::Any;
let items: Vec<Box<dyn Any>> = vec![Box::new(5i32), Box::new("hi")];
for i in &items {
    if let Some(n) = i.downcast_ref::<i32>() { println!("int {n}"); }
}
println!("{}", std::mem::size_of::<&dyn Shape>());   // 16

Code Explained

Vec<Box<dyn Shape>> holds different shape types together
&dyn Shape borrows a trait object without allocating
make decides the concrete type at runtime
Methods returning Self make a trait not dyn-compatible (E0038)

Coming From…

  • C++ virtual functions and std::unique_ptr<Base>
  • Java interface references (every call is virtual)
  • Go interface values (also data + itab pointers)

The Rust Way

  • Box<dyn Trait> param used with one type → impl Trait
  • an enum is closed and known → enum instead of dyn (faster, matchable)

⚠ Common Mistakes

  • Vec<dyn Shape> without a pointer (E0277: size not known)
  • Trying to clone a Box<dyn Trait> (use dyn-clone)
  • Defaulting to dyn when generics or enums would be faster

✓ Tips & Best Practices

  • Add where Self: Sized to exclude a method from the vtable
  • Use enums when you control every variant
  • Use Box<dyn Error + Send + Sync> for thread-safe errors

Quick Summary
