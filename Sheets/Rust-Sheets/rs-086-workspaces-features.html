Sheet 086

Workspaces, Features & Profiles

[workspace] · members · shared lock & target/ · [features] · optional deps · --features / --all-features · [profile.release]

Multi-Crate Projects and Build Options

A workspace groups several crates that share one Cargo.lock and target/ folder, so they build together and agree on dependency versions. Features are named, additive compile-time switches (#[cfg(feature = "…")]). Profiles tune optimization, debug info, LTO and panic strategy.

Key Points

  • Run commands for one member with -p name
  • [workspace.dependencies] shares versions across members
  • Features must be additive: enabling one must not break another
  • opt-level, lto, codegen-units, strip live in profiles

Workspace, Features, Profiles

# Cargo.toml (workspace root)
[workspace]
members = ["app", "core", "cli"]
resolver = "3"                       # default for edition 2024

[workspace.package]
edition = "2024"
version = "0.5.0"

[workspace.dependencies]
serde = { version = "1", features = ["derive"] }

[profile.release]
opt-level = 3
lto = "fat"                          # whole-program optimization
codegen-units = 1                    # slower build, faster binary
strip = true                         # smaller binary
panic = "abort"

# core/Cargo.toml
[package]
name = "core"
edition.workspace = true
version.workspace = true

[dependencies]
serde = { workspace = true }
chrono = { version = "0.4", optional = true }   # becomes a feature

[features]
default = ["json"]
json = []
time = ["dep:chrono"]                # enable chrono only with "time"
full = ["json", "time"]

# In code:  #[cfg(feature = "time")] pub mod timestamps;

Code Explained

members lists crates in the workspace
workspace = true inherits shared versions and settings
dep:chrono ties an optional dependency to a feature
Release profile settings trade build time for speed and size

Coming From…

  • JavaScript npm/pnpm workspaces with a shared lock file
  • Java Gradle multi-project builds / Maven modules
  • Go go.work workspaces; build tags ≈ features

The Rust Way

  • copying versions into each member → [workspace.dependencies]
  • features that remove functionality → additive features only

Profile Keys

KeyEffect
opt-level 0–3, "s", "z"Speed / size
debug = true/falseDebug info
lto = "thin"/"fat"Link-time opt
codegen-units = 1Better opt, slower build
strip = trueRemove symbols
panic = "abort"No unwinding
incrementalFaster rebuilds

Commands

CommandDoes
cargo build -p xOne member
cargo test --workspaceAll members
--features a,bEnable features
--all-featuresEverything
--no-default-featuresDisable defaults
cargo build --profile pCustom profile

⚠ Common Mistakes

  • Non-additive features that conflict when both are enabled
  • Profiles in member Cargo.toml files (only the root counts)
  • Testing only default features in CI

✓ Tips & Best Practices

  • Use cargo hack --feature-powerset to test feature combos
  • Add a [profile.profiling] that inherits release with debug info
  • Keep binaries thin; put logic in a library member

Quick Summary

  • workspace — shared lock + target
  • [workspace.dependencies]
  • features — additive switches
  • profiles — opt, lto, strip
