Common Standard Traits

Debug / Display · Clone / Copy · PartialEq / Eq / Hash · PartialOrd / Ord · Default · From / Into · AsRef / Borrow

Traits Every Type Should Consider

A handful of std traits make your types work with the rest of Rust: printing (Debug, Display), copying (Clone, Copy), comparing and hashing (PartialEq, Eq, Hash, Ord), defaults (Default) and conversions (From, AsRef). Implementing them unlocks {}, ==, sorting, HashMap keys and .into().

Key Points

  • Display is never derived; write it by hand
  • Hash must agree with Eq: equal values hash equally
  • Implement From; Into comes free
  • AsRef<str> accepts String, &str and more

Implementing Std Traits

use std::fmt;
use std::collections::HashMap;

#[derive(Debug, Clone, PartialEq, Eq, Hash, PartialOrd, Ord, Default)]
struct Email(String);
impl fmt::Display for Email {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(f, "<{}>", self.0)
    }
}
impl From<&str> for Email {
    fn from(s: &str) -> Self { Email(s.to_lowercase()) }
}
impl AsRef<str> for Email {
    fn as_ref(&self) -> &str { &self.0 }
}

let e: Email = "Ada@X.io".into();           // From → Into
println!("{e}");                            // <ada@x.io>
println!("{e:?}");                          // Email("ada@x.io")

let mut logins: HashMap<Email, u32> = HashMap::new();   // needs Eq + Hash
*logins.entry(e.clone()).or_default() += 1;

let mut list = vec![Email::from("b@x"), Email::from("a@x")];
list.sort();                                // needs Ord
println!("{}", list[0]);                    // <a@x>

fn domain<S: AsRef<str>>(s: S) -> String {
    s.as_ref().split('@').nth(1).unwrap_or("").to_string()
}
println!("{} {}", domain(&e), domain("x@y.com"));   // x.io y.com

Code Explained

Display controls {}; Debug (derived) controls {:?}
From<&str> makes "…".into() work
Eq + Hash make Email a HashMap key; Ord enables sort
domain accepts both &Email and &str through AsRef<str>

Coming From…

  • Java toString, equals/hashCode, Comparable
  • Python __str__/__repr__, __eq__/__hash__, __lt__
  • C++ operator<<, operator==, std::hash specialization

The Rust Way

  • a to_string() method → impl Display (gives to_string free)
  • implementing Into → implement From instead

⚠ Common Mistakes

  • Manual Hash that disagrees with PartialEq
  • Implementing Display with a trailing newline
  • Implementing Into directly (blocks the blanket impl benefit)

✓ Tips & Best Practices

  • Derive Debug on every type
  • Implement Display for user-facing types and errors
  • Use Borrow for map keys that should look up by &str

Quick Summary

  • Debug derive · Display by hand
  • Eq + Hash → map keys
  • Ord → sort
  • From → .into()
