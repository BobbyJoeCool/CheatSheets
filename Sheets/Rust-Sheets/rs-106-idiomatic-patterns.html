Idiomatic Patterns

newtype · builder · typestate · RAII guards · impl From conversions · iterator-returning APIs

Patterns Rust Code Uses Everywhere

Rust's type system makes some patterns especially effective: newtypes prevent mixing values, builders replace default arguments, typestate encodes valid state transitions in types, RAII guards pair setup with automatic cleanup, From impls make conversions and ? smooth, and returning impl Iterator keeps APIs lazy.

Key Points

  • Newtypes are free at runtime (same layout)
  • Builders often consume and return self
  • Typestate turns runtime state errors into compile errors
  • Guards implement Drop

Six Patterns

// Newtype
#[derive(Debug, Clone, Copy, PartialEq)]
struct UserId(u64);                         // not mixable with OrderId(u64)
// Builder
#[derive(Debug, Default)]
struct Request { url: String, timeout: u64, retries: u8 }
struct RequestBuilder(Request);
impl RequestBuilder {
    fn new(url: &str) -> Self {
        Self(Request { url: url.into(), timeout: 30, ..Default::default() })
    }
    fn timeout(mut self, s: u64) -> Self { self.0.timeout = s; self }
    fn build(self) -> Request { self.0 }
}
let req = RequestBuilder::new("https://x.io").timeout(5).build();
// Typestate
struct Draft; struct Published;
struct Post<S> { body: String, _s: std::marker::PhantomData<S> }
impl Post<Draft> {
    fn publish(self) -> Post<Published> {
        Post { body: self.body, _s: Default::default() }
    }
}
impl Post<Published> { fn url(&self) -> String { format!("/p/{}", self.body) } }
// RAII guard
struct Timer(&'static str, std::time::Instant);
impl Drop for Timer {
    fn drop(&mut self) { println!("{} took {:?}", self.0, self.1.elapsed()); }
}
{ let _t = Timer("load", std::time::Instant::now()); /* work */ }
// From conversions power `?`
impl From<u64> for UserId { fn from(v: u64) -> Self { UserId(v) } }
let id: UserId = 7.into();
// Iterator-returning API
struct Library { books: Vec<(String, u16)> }
impl Library {
    fn published_after(&self, y: u16) -> impl Iterator<Item = &str> + '_ {
        self.books.iter().filter(move |b| b.1 > y).map(|b| b.0.as_str())
    }
}

Code Explained

UserId and OrderId are both u64 inside but cannot be mixed
The builder chains settings and fills the rest with defaults
Only Post<Published> has a url method
Returning impl Iterator lets callers chain without allocating

Coming From…

  • Java builders and value objects are common; typestate is rare
  • Python keyword arguments replace builders; NewType is only a hint
  • C++ strong typedefs, RAII and builders all apply

The Rust Way

  • raw u64 IDs everywhere → newtypes
  • returning Vec<T> just to iterate → impl Iterator<Item = T>

⚠ Common Mistakes

  • Builders that allow build() with required fields missing (use typestate or Result)
  • Newtypes without the traits users need (derive them)
  • Overusing typestate for simple runtime states

✓ Tips & Best Practices

  • Derive or forward traits on newtypes with derive_more
  • Use bon / typed-builder to generate builders
  • Name guards _guard so they live to the end of scope
