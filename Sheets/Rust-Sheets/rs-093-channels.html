Sheet 093

Channels

mpsc::channel · Sender / Receiver · send / recv / try_recv · cloning senders · sync_channel · iterating a receiver

Message Passing

Channels move values between threads: "do not communicate by sharing memory; share memory by communicating." mpsc::channel() returns a Sender and a Receiver (multiple producers, single consumer). Sending moves the value to the receiving thread. When all senders are dropped, the receiver's loop ends.

Key Points

  • channel() is unbounded; sync_channel(n) blocks when full
  • recv() blocks; try_recv() and recv_timeout() do not
  • send fails only if the receiver is gone
  • crossbeam-channel and flume add multi-consumer and select!

mpsc Channels

use std::sync::mpsc;
use std::thread;
use std::time::Duration;

let (tx, rx) = mpsc::channel();
thread::spawn(move || {
    for i in 1..=3 {
        tx.send(format!("msg {i}")).unwrap();   // ownership moves
        thread::sleep(Duration::from_millis(5));
    }
});                                         // tx dropped here
for msg in rx {                             // ends when all senders drop
    println!("{msg}");
}

let (tx, rx) = mpsc::channel::<(usize, u64)>();
for id in 0..3 {
    let tx = tx.clone();                    // one sender per producer
    thread::spawn(move || {
        let sum = (1..=1000u64).map(|n| n * id as u64).sum();
        tx.send((id, sum)).unwrap();
    });
}
drop(tx);                                   // drop the original
let mut results: Vec<_> = rx.iter().collect();
results.sort();
println!("{results:?}");            // [(0, 0), (1, 500500), (2, 1001000)]

let (tx, rx) = mpsc::sync_channel(2);       // bounded: backpressure
thread::spawn(move || for i in 0..5 { tx.send(i).unwrap(); });
thread::sleep(Duration::from_millis(10));
println!("{:?}", rx.try_recv());            // Ok(0)
println!("{:?}", rx.recv_timeout(Duration::from_secs(1)));   // Ok(1)

let (tx, rx) = mpsc::channel::<i32>();
drop(tx);
println!("{:?}", rx.recv());                // Err(RecvError): no senders

Code Explained

Each send moves a String into the channel
for msg in rx stops once the sender is dropped
Clone the Sender for each producer, then drop the original
sync_channel(2) makes senders wait when 2 items are queued

Coming From…

  • Go ch := make(chan T, n), ch <- v, range ch (the model Rust copies)
  • Java BlockingQueue (LinkedBlockingQueue, ArrayBlockingQueue)
  • Python queue.Queue between threads

The Rust Way

  • Arc<Mutex<Vec<T>>> as a work queue → a channel
  • busy-looping on try_recv → recv() or recv_timeout

⚠ Common Mistakes

  • Keeping the original tx alive so the receive loop never ends
  • Unbounded channels growing without limit under load
  • Using std mpsc when multiple consumers are needed

✓ Tips & Best Practices

  • Drop the original sender after cloning for workers
  • Use bounded channels for backpressure
  • Use tokio::sync::mpsc inside async code

Quick Summary

  • mpsc::channel() — tx / rx
