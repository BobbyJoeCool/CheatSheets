panic! & Unrecoverable Errors

panic! · unwrap() / expect() · unreachable! / todo! / unimplemented! · assert! / assert_eq! / debug_assert! · RUST_BACKTRACE=1 · panic = "abort"

Bugs, Not Expected Failures

A panic stops the current thread, unwinding the stack and running destructors. Use it for bugs and broken invariants, not for errors a caller could handle (those return Result). unwrap() and expect() panic on None/Err; expect("why") documents the assumption.

Key Points

  • A panic in main's thread ends the program with exit code 101
  • Other threads' panics show up as Err from join()
  • RUST_BACKTRACE=1 prints a stack trace
  • panic = "abort" in Cargo.toml skips unwinding (smaller binary)

Panicking Macros

fn divide(a: i32, b: i32) -> i32 {
    if b == 0 { panic!("division by zero: {a}/{b}"); }
    a / b
}

let v = vec![1, 2, 3];
// let x = v[10];              // panic: index out of bounds: the len is 3…

let port: u16 = "8080".parse().expect("PORT must be a number");
let first = v.first().unwrap();             // fine when you just checked

fn grade(n: u8) -> char {
    match n {
        90..=100 => 'A',
        0..=89 => 'B',
        _ => unreachable!("score {n} out of range"),
    }
}
fn later() -> u32 { todo!("implement caching") }   // compiles, panics if called

assert!(v.len() == 3, "expected 3 items, got {}", v.len());
assert_eq!(divide(10, 2), 5);
assert_ne!(port, 0);
debug_assert!(v.windows(2).all(|w| w[0] <= w[1]));   // debug builds only

let r = std::panic::catch_unwind(|| divide(1, 0));
println!("{}", r.is_err());                 // true (rarely needed)

// Terminal:
// $ RUST_BACKTRACE=1 cargo run
// thread 'main' panicked at src/main.rs:2:17:
// division by zero: 1/0

// Cargo.toml
// [profile.release]
// panic = "abort"

Code Explained

panic! takes a format string like println!
expect adds a message explaining why the value should exist
unreachable! marks branches that indicate a bug
debug_assert! is removed in release builds

Coming From…

  • Go panic / recover, also for bugs only
  • Java unchecked exceptions (IllegalStateException)
  • Python assert and uncaught exceptions

The Rust Way

  • unwrap() on user input → return Result and use ?
  • unwrap() on an invariant → expect("reason it holds")

⚠ Common Mistakes

  • Using panics for validation errors
  • Bare unwrap() hiding why a value must exist
  • Relying on catch_unwind for control flow

✓ Tips & Best Practices

  • Write expect messages as the expected state: "config loaded"
  • Ban unwrap in libraries with clippy::unwrap_used
  • Use todo!() to sketch code that still compiles

Quick Summary

  • panic = bug
  • expect > unwrap
  • unreachable! / todo!
