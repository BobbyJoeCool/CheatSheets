Generics

generic functions fn largest<T> · generic structs & enums · impl<T> · monomorphization · const generics [T; N] · PhantomData

Code That Works for Many Types

Generics let one definition work for many types: fn largest<T: PartialOrd>(v: &[T]) -> &T. Structs and enums can be generic too (Vec<T>, Option<T>). The compiler generates a specialized copy for each concrete type used, so generics have zero runtime cost. Const generics parameterize over values like array lengths.

Key Points

  • Type parameters are CamelCase single letters by convention
  • Bounds (T: Trait) say what the code may do with T
  • impl<T> Point<T> vs impl Point<f64> (specific type only)
  • PhantomData<T> marks an unused type parameter

Under the Hood

  • Monomorphization: largest::<i32> and largest::<f64> become separate machine-code functions
  • Calls are static and inlinable, as fast as hand-written code
  • Cost: longer compile times and larger binaries
  • Const generics are also monomorphized per N

Generic Functions and Types

fn largest<T: PartialOrd>(items: &[T]) -> &T {
    let mut max = &items[0];
    for it in items { if it > max { max = it; } }
    max
}
println!("{}", largest(&[3, 9, 2]));        // 9
println!("{}", largest(&["b", "z", "a"]));  // z

#[derive(Debug)]
struct Point<T> { x: T, y: T }

impl<T: std::ops::Add<Output = T> + Copy> Point<T> {
    fn sum(&self) -> T { self.x + self.y }
}
impl Point<f64> {                           // only for f64
    fn dist(&self) -> f64 { (self.x * self.x + self.y * self.y).sqrt() }
}
let pi = Point { x: 1, y: 2 };
let pf = Point { x: 3.0, y: 4.0 };
println!("{} {}", pi.sum(), pf.dist());     // 3 5

struct Pair<A, B> { a: A, b: B }
let p = Pair { a: "id", b: 7u8 };

fn sum_all<const N: usize>(arr: [i32; N]) -> i32 { arr.iter().sum() }
println!("{}", sum_all([1, 2, 3]));         // 6 (N = 3)

struct Matrix<const R: usize, const C: usize>([[f32; C]; R]);
let m: Matrix<2, 3> = Matrix([[0.0; 3]; 2]);

use std::marker::PhantomData;
struct Meters;
struct Length<Unit> { value: f64, _unit: PhantomData<Unit> }
let len: Length<Meters> = Length { value: 5.0, _unit: PhantomData };

Code Explained

T: PartialOrd allows > on items
impl Point<f64> adds a method only for f64 points
Const generic N is inferred from the array length
PhantomData<Unit> tags a type without storing data

Coming From…

  • C++ templates (also monomorphized), checked at instantiation
  • Java generics with type erasure: one runtime copy, boxed values
  • Go generics (1.18+) with type sets; partly dictionary-based

The Rust Way

  • copy-pasted functions for i32/f64 → one generic function
  • Box<dyn Trait> where one type is used per call site → generics

⚠ Common Mistakes

  • Using an operation without the bound (E0369 binary operation cannot be applied)
  • Over-generic APIs that are hard to read
  • Expecting runtime type info about T

✓ Tips & Best Practices

  • Start concrete, generalize when a second type appears
  • Put long bounds in where clauses (sheet 069)
  • Use const generics for fixed-size buffers and matrices

Quick Summary

  • <T> on fns, structs, enums
  • bounds limit what T can do
  • monomorphized: zero cost
  • const generics <const N: usize>
