Operator Overloading

std::ops::Add / Sub / Mul · Neg / Not · AddAssign · Index / IndexMut · type Output · derived comparisons

Operators Are Traits

Every operator maps to a trait in std::ops. Implement Add and a + b works for your type; Output names the result type. Comparison operators come from PartialEq/PartialOrd, usually derived. You cannot create new operators or overload &&, || or =.

Key Points

  • Add<Rhs = Self> can take a different right-hand type
  • Implement for references too to avoid moving operands
  • Index must return a reference
  • Keep the meaning unsurprising (+ should add)

Implementing Operators

use std::ops::{Add, AddAssign, Index, Mul, Neg};

#[derive(Debug, Clone, Copy, PartialEq)]
struct V2 { x: f64, y: f64 }

impl Add for V2 {
    type Output = V2;
    fn add(self, o: V2) -> V2 { V2 { x: self.x + o.x, y: self.y + o.y } }
}
impl Mul<f64> for V2 {                      // V2 * f64
    type Output = V2;
    fn mul(self, k: f64) -> V2 { V2 { x: self.x * k, y: self.y * k } }
}
impl Neg for V2 {
    type Output = V2;
    fn neg(self) -> V2 { V2 { x: -self.x, y: -self.y } }
}
impl AddAssign for V2 {
    fn add_assign(&mut self, o: V2) { self.x += o.x; self.y += o.y; }
}

struct Poly(Vec<i32>);
impl Index<usize> for Poly {
    type Output = i32;
    fn index(&self, i: usize) -> &i32 { &self.0[i] }
}

let a = V2 { x: 1.0, y: 2.0 };
let mut b = a + a * 3.0;                    // V2 { x: 4.0, y: 8.0 }
b += -a;                                    // V2 { x: 3.0, y: 6.0 }
println!("{:?} {}", b, a == a);
println!("{}", Poly(vec![5, 7])[1]);        // 7

Code Explained

type Output sets the result type of +
Mul<f64> lets a vector be multiplied by a scalar
Deriving Copy means operands are not moved
Index returns &i32; p[1] dereferences it

Coming From…

  • C++ operator+ member or free functions
  • Python __add__, __mul__, __getitem__
  • Java no operator overloading

The Rust Way

  • a.add(b) methods for math types → impl Add
  • overloading + for non-additive meaning → a named method

⚠ Common Mistakes

  • Implementing only for owned values, so a + b moves non-Copy operands
  • Forgetting type Output
  • Returning a value from Index (must be a reference)

✓ Tips & Best Practices

  • Derive Copy for small math types
  • Also implement impl Add<&V2> for &V2 for heavy types
  • Use the derive_more crate to cut boilerplate
