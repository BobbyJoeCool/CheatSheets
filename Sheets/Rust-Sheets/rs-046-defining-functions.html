Defining Functions

fn name(x: i32) -> i32 · implicit return · early return · unit return · snake_case · functions are items (order doesn't matter)

Functions

Functions are declared with fn, and every parameter and return type must be written out. The last expression without a semicolon is the return value; use return only for early exits. A function with no -> returns (). Functions can be declared in any order and even nested inside other functions.

Key Points

  • Names are snake_case; types are CamelCase
  • Parameter types are never inferred
  • -> ! means the function never returns
  • Nested fns cannot capture local variables (use closures)

Functions

fn main() {
    greet("Ada");                       // defined below: order doesn't matter
    println!("{}", add(2, 3));              // 5
    println!("{}", classify(-4));           // negative
    println!("{:?}", divide(7, 0));         // None
    println!("{}", hypot(3.0, 4.0));        // 5

    fn helper(x: i32) -> i32 { x * 10 }     // nested function
    println!("{}", helper(4));              // 40
}

fn greet(name: &str) {                      // returns ()
    println!("Hello, {name}!");
}

fn add(a: i32, b: i32) -> i32 {
    a + b                                   // implicit return
}

fn classify(n: i32) -> &'static str {
    if n < 0 {
        return "negative";                  // early return
    }
    if n == 0 { "zero" } else { "positive" }
}

fn divide(a: i32, b: i32) -> Option<i32> {
    if b == 0 { return None; }
    Some(a / b)
}

fn hypot(x: f64, y: f64) -> f64 { (x * x + y * y).sqrt() }

fn min_max(v: &[i32]) -> (i32, i32) {       // return several values as a tuple
    (*v.iter().min().unwrap(), *v.iter().max().unwrap())
}

Code Explained

main calls functions declared later in the file
The last expression a + b is returned
return exits early from inside an if
Return a tuple or struct for several values

Coming From…

  • Go func add(a, b int) int with explicit return
  • Python def add(a, b): with optional type hints
  • Java methods live in classes; Rust functions can be free-standing

The Rust Way

  • return x; as the last line → just x
  • many related free functions → methods in an impl block

⚠ Common Mistakes

  • A trailing ; on the return expression ("expected i32, found ()")
  • Omitting parameter types
  • Very long functions instead of small helpers

✓ Tips & Best Practices

  • Keep functions short and named for what they return
  • Return Option/Result instead of sentinel values
  • Use #[must_use] on functions whose result matters

Quick Summary

  • fn name(p: T) -> R
  • last expression returns
  • return for early exit
  • any declaration order
