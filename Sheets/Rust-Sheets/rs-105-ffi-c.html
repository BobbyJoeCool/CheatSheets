FFI & Calling C

extern "C" · #[unsafe(no_mangle)] (2024) · CString / CStr · bindgen / cbindgen · build.rs · cc crate

Talking to C

Rust calls C functions declared in extern "C" blocks and exposes Rust functions to C with extern "C" fn plus #[unsafe(no_mangle)]. Strings cross the boundary as CString (owned, NUL-terminated) and CStr (borrowed). bindgen generates Rust declarations from C headers, cbindgen generates C headers from Rust, and build.rs with the cc crate compiles C sources.

Key Points

  • Use #[repr(C)] for structs shared with C
  • Types: c_int, c_char, c_void in std::ffi
  • #[link(name = "z")] or build.rs links native libraries
  • Never let a Rust panic unwind into C (use catch_unwind or extern "C-unwind")

FFI Both Ways

use std::ffi::{c_char, c_int, CStr, CString};

// ---- calling C from Rust ----
#[link(name = "m")]
unsafe extern "C" {
    fn cos(x: f64) -> f64;
    fn strlen(s: *const c_char) -> usize;
}

let c = unsafe { cos(0.0) };                // 1.0
let s = CString::new("hello").unwrap();     // adds the NUL byte
let n = unsafe { strlen(s.as_ptr()) };      // 5

// ---- exposing Rust to C ----
#[repr(C)]
pub struct Point { pub x: f64, pub y: f64 }

#[unsafe(no_mangle)]                         // 2024 edition spelling
pub extern "C" fn point_len(p: Point) -> f64 { (p.x * p.x + p.y * p.y).sqrt() }

#[unsafe(no_mangle)]
pub extern "C" fn greet(name: *const c_char) -> c_int {
    if name.is_null() { return -1; }
    // SAFETY: caller passes a valid NUL-terminated string.
    let name = unsafe { CStr::from_ptr(name) }.to_string_lossy();
    println!("hello, {name}");
    0
}

// Cargo.toml for a C-callable library: [lib] crate-type = ["cdylib"]

// build.rs: fn main() { cc::Build::new().file("src/fast.c").compile("fast"); }

// Generate bindings:
// $ bindgen wrapper.h -o src/bindings.rs        (C → Rust)
// $ cbindgen --lang c -o include/mylib.h         (Rust → C)

Code Explained

Calls into C are unsafe because Rust cannot check them
CString::new adds the NUL terminator C expects
#[repr(C)] gives Point C-compatible layout
cdylib / staticlib build a library C programs can link

Coming From…

  • C++ extern "C" linkage works the same way
  • Python ctypes / cffi; PyO3 for Rust extensions
  • Java JNI / Panama FFM API; Go cgo

The Rust Way

  • passing &str to C → CString::new(s)?.as_ptr()
  • hand-written C declarations for big headers → bindgen

⚠ Common Mistakes

  • Dropping a CString while C still holds its pointer
  • Struct layout mismatch without #[repr(C)]
  • Panics unwinding across extern "C" (aborts in recent Rust)

✓ Tips & Best Practices

  • Wrap raw FFI in a -sys crate plus a safe wrapper crate
  • Use CStr::to_str() when you need validated UTF-8
  • Use PyO3 / napi-rs instead of raw FFI for Python / Node
