Benchmarks & Debugging

criterion · cargo bench · dbg! · lldb / gdb · cargo expand · Miri · cargo-nextest

Measuring and Investigating

Use criterion for statistically sound benchmarks with cargo bench. Debug with dbg! for quick looks or rust-lldb / rust-gdb (or an IDE) for breakpoints. cargo expand shows macro output, Miri detects undefined behavior in unsafe code, and cargo-nextest runs tests faster with per-test isolation.

Key Points

  • Benchmark only --release builds (cargo bench does this)
  • Use black_box so the optimizer does not delete benchmarked work
  • Miri runs on nightly: cargo +nightly miri test
  • Profilers: cargo flamegraph, samply, perf

criterion and Tools

// Cargo.toml
// [dev-dependencies]
// criterion = "0.5"
// [[bench]]
// name = "fib"
// harness = false

// benches/fib.rs
use criterion::{criterion_group, criterion_main, Criterion};
use std::hint::black_box;

fn fib(n: u64) -> u64 { if n < 2 { n } else { fib(n - 1) + fib(n - 2) } }
fn fib_iter(n: u64) -> u64 {
    let (mut a, mut b) = (0, 1);
    for _ in 0..n { (a, b) = (b, a + b); }
    a
}

fn bench(c: &mut Criterion) {
    c.bench_function("fib 20 recursive", |b| b.iter(|| fib(black_box(20))));
    c.bench_function("fib 20 iter", |b| b.iter(|| fib_iter(black_box(20))));
}
criterion_group!(benches, bench);
criterion_main!(benches);

// $ cargo bench
// fib 20 recursive   time: [15.2 µs 15.3 µs 15.4 µs]
// fib 20 iter        time: [6.1 ns 6.2 ns 6.2 ns]

// Tools
// $ cargo install cargo-expand && cargo expand module::path
// $ cargo +nightly miri test       UB detector for unsafe code
// $ cargo install cargo-nextest && cargo nextest run
// $ cargo install flamegraph && cargo flamegraph --bin app

Code Explained

harness = false lets criterion provide main
black_box prevents the compiler from precomputing fib(20)
criterion reports a confidence interval for each benchmark
Command-line debuggers wrap lldb/gdb with Rust pretty-printers

Coming From…

  • Go built-in go test -bench and pprof

The Rust Way

  • timing with Instant in a loop → criterion (or divan)
  • println! debugging spread everywhere → dbg! or a debugger

⚠ Common Mistakes

  • Benchmarking debug builds
  • Benchmarks the optimizer folds away (no black_box)
  • Debugging release builds without debug info

✓ Tips & Best Practices

  • Add debug = true to a profiling profile for symbols
  • Compare against a baseline with criterion's saved runs
  • Run Miri on any crate with unsafe code
