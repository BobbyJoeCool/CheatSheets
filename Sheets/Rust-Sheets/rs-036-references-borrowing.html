References & Borrowing

&T shared borrow · * deref · auto-deref on method calls · the borrowing rules · references must stay valid · passing & to functions

Using Values Without Taking Them

A reference &T borrows a value without taking ownership, so the owner can keep using it afterwards. The borrow checker enforces two rules: you can have **many &T or one &mut T** at a time, and a reference can never outlive the value it points to. References are never null.

Key Points

  • &x creates a reference; *r reads through it
  • Method calls and . field access auto-deref
  • Comparison operators work through references
  • Function signatures show borrows clearly: fn len(s: &String)

Under the Hood

  • &T is a plain pointer at runtime (8 bytes); the rules cost nothing at runtime
  • &[T], &str and &dyn Trait are fat pointers (16 bytes)
  • References to Copy data may be optimized into passing the value
  • Option<&T> is the same size as &T (null is the None niche)

Shared References

fn length(s: &String) -> usize { s.len() }  // borrows, doesn't own

let name = String::from("Ferris");
let n = length(&name);                      // lend it
println!("{name} has {n} letters");         // name still usable

let x = 5;
let r = &x;
println!("{}", *r + 1);                     // 6, explicit deref
println!("{}", r + 1);                      // 6, arithmetic auto-derefs
println!("{}", r == &5);                    // true

let words = vec![String::from("a"), String::from("bb")];
let first: &String = &words[0];             // borrow an element
println!("{}", first.len());                // auto-deref for methods

let r1 = &words;
let r2 = &words;                            // many shared borrows OK
println!("{} {}", r1.len(), r2.len());

fn longest_len(items: &[String]) -> usize {
    items.iter().map(|s| s.len()).max().unwrap_or(0)
}
println!("{}", longest_len(&words));        // 2

// let dangling: &String;
// { let tmp = String::from("x"); dangling = &tmp; }
//                                          // E0597: does not live long enough
// println!("{dangling}");

let rr: &&i32 = &&7;
println!("{}", **rr);                       // 7

Code Explained

length(&name) lends name and gets it back automatically
*r follows the reference to the value
Many & borrows can coexist
A reference to tmp cannot escape tmp's block (E0597)

Coming From…

  • C++ references and pointers can dangle; Rust proves they cannot
  • Go pointers keep values alive via the GC
  • Java / Python every object variable is already a shared reference

The Rust Way

  • fn f(v: Vec<T>) that only reads → fn f(v: &[T])
  • explicit (*r).len() → r.len() (auto-deref)

Borrowing Rules

RuleMeaning
Many &TAny number of readers
One &mut TExactly one writer
Not both at onceNo reading during a write
Must not dangleRef ≤ lifetime of value
Never nullUse Option<&T>

⚠ Common Mistakes

  • Returning a reference to a local variable (E0515/E0106)
  • Storing references in structs without lifetimes (sheet 040)
  • Cloning instead of borrowing to make errors go away

✓ Tips & Best Practices

  • Borrow by default; move only when the callee must own
  • Prefer &str and &[T] parameters
  • Let NLL shorten borrows: use the value, then move on

Quick Summary

  • &T — shared borrow
  • many & or one &mut
  • refs never dangle or null
  • * deref, auto-deref on .
