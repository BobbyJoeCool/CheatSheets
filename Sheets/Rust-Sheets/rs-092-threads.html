OS Threads

thread::spawn runs a closure on a new OS thread and returns a JoinHandle; join() waits and returns the closure's result, or Err if it panicked. Spawned closures must own their data (move) because the thread may outlive the caller. Scoped threads (thread::scope) can borrow local data safely because they are joined before the scope ends.

Key Points

  • When main returns, remaining threads are killed
  • A panicking thread does not crash others; join reports it
  • thread::Builder sets name and stack size
  • Use rayon for data parallelism over collections

Spawning Threads

use std::thread;
use std::time::Duration;

let handle = thread::spawn(|| {
    for i in 1..=3 {
        println!("worker {i}");
        thread::sleep(Duration::from_millis(10));
    }
    42                                      // thread's return value
});
println!("main continues");
let result = handle.join().unwrap();        // wait: 42

let data = vec![1, 2, 3];
let h = thread::spawn(move || data.iter().sum::<i32>());   // data moved in
println!("{}", h.join().unwrap());          // 6

let handles: Vec<_> = (0..4)
    .map(|id| thread::spawn(move || id * id))
    .collect();
let squares: Vec<i32> =
    handles.into_iter().map(|h| h.join().unwrap()).collect();
println!("{squares:?}");                    // [0, 1, 4, 9]

let mut counts = [0u32; 2];
let words = ["a", "bb", "a", "ccc"];
thread::scope(|s| {                         // borrow locals safely
    let (left, right) = counts.split_at_mut(1);
    s.spawn(|| left[0] = words.iter().filter(|w| w.len() == 1).count() as u32);
    s.spawn(|| right[0] = words.len() as u32);
});                                         // both joined here
println!("{counts:?}");                     // [2, 4]

let r = thread::spawn(|| panic!("boom")).join();
println!("{}", r.is_err());                 // true
println!("{}", thread::available_parallelism()?.get());   // e.g. 8

Code Explained

join() returns the closure's value
move gives the thread ownership of data
Scoped threads borrow words and parts of counts
A panic in a thread shows up as Err from join

Coming From…

  • C++ std::thread / std::jthread; capture rules are unchecked
  • Java Thread / virtual threads; shared objects need manual locking
  • Go goroutines are lighter (M:N); Rust threads are 1:1 OS threads

The Rust Way

  • Arc just to share read-only locals with short threads → thread::scope
  • manual chunking for parallel loops → rayon par_iter()

⚠ Common Mistakes

  • Borrowing locals in thread::spawn (E0373: may outlive borrowed value)
  • Forgetting to join and losing work when main exits
  • Spawning one thread per tiny task (use a pool or rayon)

✓ Tips & Best Practices

  • Prefer thread::scope when threads finish inside a function
  • Use rayon for CPU-bound loops
  • Name threads to make debugging and panics clearer
