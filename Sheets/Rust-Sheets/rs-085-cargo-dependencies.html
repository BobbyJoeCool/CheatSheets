Cargo Dependencies

[dependencies] · semver "1.0" / "=1.2.3" · cargo add / remove / update · Cargo.lock · [dev-dependencies] · git & path deps

Using Crates

Dependencies are listed in Cargo.toml and downloaded from crates.io. A version like "1.4" is a caret requirement: any compatible 1.x release ≥ 1.4. Cargo.lock pins the exact versions chosen. [dev-dependencies] are only for tests, examples and benchmarks; [build-dependencies] are for build.rs.

Key Points

  • "1.4" = ^1.4 = ≥1.4.0, <2.0.0
  • For 0.x, "0.4" means ≥0.4.0, <0.5.0
  • cargo update refreshes the lock file within requirements
  • Features enable optional parts of a crate

Cargo.toml Dependencies

[package]
name = "webtool"
version = "0.3.1"
edition = "2024"
rust-version = "1.85"           # minimum supported Rust

[dependencies]
serde = { version = "1", features = ["derive"] }
tokio = { version = "1.40", features = ["rt-multi-thread", "macros"] }
reqwest = { version = "0.12", default-features = false,
            features = ["json", "rustls-tls"] }
regex = "1.10"                  # ^1.10
uuid = "=1.8.0"                 # exactly this version
log = ">=0.4.20, <0.5"          # explicit range
anyhow = "1"

# local and git sources
shared = { path = "../shared" }
fancy = { git = "https://github.com/org/fancy", tag = "v2.1.0" }

# renamed dependency
http1 = { package = "http", version = "0.2" }

[dev-dependencies]
pretty_assertions = "1"
tempfile = "3"

[build-dependencies]
cc = "1"

[target.'cfg(windows)'.dependencies]
winapi = { version = "0.3", features = ["winuser"] }

# Terminal:
# cargo add serde -F derive      cargo remove regex
# cargo update                   cargo update -p tokio
# cargo tree -d                  # duplicate versions
# cargo outdated                 # (cargo-outdated plugin)

Code Explained

Caret requirements accept compatible updates
default-features = false trims a crate to what you enable
path and git deps work for local or unreleased code
Target-specific tables add deps per platform

Coming From…

  • JavaScript package.json ^1.4.0 and package-lock.json (same model)
  • Python pyproject.toml >=1.4,<2 + uv.lock / poetry.lock
  • Java Maven/Gradle coordinates with exact versions by default

The Rust Way

  • "*" versions → a real requirement like "1"
  • pinning with = everywhere → caret + committed Cargo.lock

Version Syntax

RequirementAllows
"1.4"≥1.4.0 <2.0.0
"0.4"≥0.4.0 <0.5.0
"~1.4"≥1.4.0 <1.5.0
"=1.4.2"Exactly 1.4.2
">=1.2, <1.5"Range
"*"Anything (avoid)

Sections

TableUsed For

⚠ Common Mistakes

  • Not committing Cargo.lock for binaries
  • Turning on full features and bloating compile times
  • Two versions of the same crate (check cargo tree -d)

✓ Tips & Best Practices

  • Check crates on crates.io, docs.rs and lib.rs before adding
  • Use cargo audit / cargo deny for security and licenses
  • Set rust-version so users get a clear MSRV error

Quick Summary

  • [dependencies] from crates.io
  • "1.4" = compatible updates
  • Cargo.lock pins versions
  • dev / build / target deps
