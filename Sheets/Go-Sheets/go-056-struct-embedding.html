Embedding

Go has no inheritance. Instead, a struct can embed another type by listing it without a field name. The embedded type's fields and methods are promoted, so they can be used as if declared on the outer struct. This is composition: the outer type *has* the inner one, and the inner methods still receive the inner value as their receiver.

Notes

  • The embedded field's name is its type name: e.Logger
  • Outer fields/methods shadow promoted ones with the same name
  • Promoted methods count toward interface satisfaction
  • Embedding an interface in a struct delegates to whatever value is set

Composition by Embedding

type Logger struct{ prefix string }
func (l *Logger) Log(msg string) { fmt.Println(l.prefix + msg) }

type Service struct {
    *Logger                     // embedded pointer
    name string
}

s := Service{Logger: &Logger{"[svc] "}, name: "api"}
s.Log("started")                // promoted: [svc] started
s.Logger.Log("explicit")        // still reachable by type name

type ReadWriter struct{ io.Reader; io.Writer } // interfaces

type Admin struct {
    User                        // promotes User fields + methods
    Level int
}
a := Admin{User: User{Name: "Ann"}, Level: 9}
fmt.Println(a.Name)             // Ann (promoted field)
func (a Admin) Greet() string { return "Hi " + a.User.Greet() } // shadows

Code Explained

*Logger — embedded pointer; set it or calls panic
s.Log — promoted from *Logger
s.Logger — the embedded field, named by its type
embedding io.Reader + io.Writer — satisfies io.ReadWriter
Admin.Greet — outer method shadows User.Greet

Coming From…

  • Java — no extends; embedding is composition
  • Python — no MRO; outer field simply shadows inner
  • Java — no polymorphism via embedding; use interfaces

⚠ Common Mistakes

  • Passing an Admin where a User is expected; it doesn't compile, pass a.User
  • Expecting the inner method to call the outer's "override"; there's no virtual dispatch
  • Leaving an embedded pointer or interface nil and calling a promoted method: nil dereference

✓ Tips & Best Practices

  • Embed to reuse behavior; use an interface when callers need substitutability
  • Embed sync.Mutex only in unexported types (it exposes Lock/Unlock publicly)
  • Wrap an interface by embedding it and overriding one method (decorator pattern)

Quick Summary

  • embedding — field with no name
  • promotion — inner fields/methods usable on outer
  • shadowing — outer wins
  • composition, not inheritance
