Modules & go.mod

A module is a versioned collection of packages defined by a go.mod file at its root. go.mod records the module path, the minimum Go version, an optional preferred toolchain, and dependency requirements. Go uses minimal version selection: builds use the lowest versions that satisfy every requirement, so they're reproducible.

Notes

  • Module path is usually the repo URL: github.com/me/app
  • Major versions ≥ 2 put /v2 in the module path
  • // indirect marks deps needed only by other deps
  • go.sum holds checksums; commit both files

A go.mod File

// $ go mod init github.com/me/shop

module github.com/me/shop

go 1.27                               // minimum language version
toolchain go1.27.1                    // preferred toolchain

require (
    github.com/go-chi/chi/v5 v5.2.1
    github.com/jackc/pgx/v5 v5.7.4
    golang.org/x/sync v0.14.0 // indirect
)

replace github.com/me/lib => ../lib   // local development
exclude github.com/bad/pkg v1.2.3     // never use this version
retract v1.0.1                        // "don't use our v1.0.1"

tool golang.org/x/tools/cmd/stringer  // 1.24: go tool stringer

Code Explained

module — the import-path prefix for your packages
go 1.27 — enables 1.27 language features (and requires it)
require — minimum versions of dependencies
replace — point a module at a local path or fork
tool — track dev tools; run with go tool <name> (1.24)

Coming From…

  • Node — go.mod ≈ package.json; go.sum ≈ lockfile
  • Python — ≈ pyproject.toml with pinned minimums
  • Java — ≈ pom.xml dependencies, far simpler

⚠ Common Mistakes

  • Committing replace ../local lines; they break everyone else's builds
  • Tagging v2.0.0 without changing the module path to /v2
  • Editing go.mod by hand and not running go mod tidy afterwards

✓ Tips & Best Practices

  • Use go.work instead of replace for multi-module local development
  • Pin dev tools with the tool directive instead of a tools.go file
  • Set the go line to the oldest version you actually support

Quick Summary

  • go mod init path — create a module
  • go / toolchain — version requirements
  • require / replace — dependencies
  • /v2 — major version in path
