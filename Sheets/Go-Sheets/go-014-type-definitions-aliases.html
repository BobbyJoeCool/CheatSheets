Defined Types & Aliases

type Name Underlying creates a new, distinct type that shares the underlying representation but not its methods. You can attach methods to it, and the compiler stops you mixing it with other types. type A = B creates an alias: another name for the same type, mainly for refactoring.

Key Rules

  • Methods can only be declared on defined types in your own package
  • Defined types convert to/from their underlying type with T(v)
  • Untyped constants assign directly: var d Celsius = 100
  • Generic aliases type Set[T comparable] = map[T]bool work since Go 1.24

Defined Type vs Alias

type Celsius float64             // defined type
type Fahrenheit float64

func (c Celsius) ToF() Fahrenheit {
    return Fahrenheit(c*9/5 + 32)
}

var t Celsius = 100              // untyped constant: OK
fmt.Println(t.ToF())             // 212
var f Fahrenheit = 50
// t = f                         // error: mismatched types
t = Celsius((f - 32) * 5 / 9)    // explicit conversion

type MyInt = int                 // alias: identical to int
var b int = MyInt(5)             // OK: same type

type UserID int64                // domain type
func Load(id UserID) {}  // Load(OrderID(7)) fails

d := 90 * time.Second            // time.Duration is int64

Code Explained

type Celsius float64 — new type; gets its own method set
Assigning Fahrenheit to Celsius needs a conversion
type MyInt = int — alias; no new methods possible
UserID / OrderID — same layout, can't be swapped by accident
time.Duration — a defined int64 with methods like .Seconds()

Coming From…

  • Java — no extends; type T U copies layout, not methods
  • TS — type A = B alias ≈ TS type alias
  • C — typedef ≈ alias; defined types are stricter

⚠ Common Mistakes

  • Expecting a defined type to inherit methods: type MyTime time.Time has none of time.Time's methods
  • Adding methods to a type from another package (func (s string) X()); define your own type
  • Using aliases everywhere for "readability"; they add no type safety

✓ Tips & Best Practices

  • Embed the original type in a struct if you need its methods plus your own
  • Use defined types for IDs, units and states to catch mixups at compile time
  • Reserve aliases for moving a type between packages without breaking callers

Quick Summary

  • type T U — new type, can have methods
  • type T = U — alias, same type
  • conversion — T(v) between same underlying types
  • domain types — compile-time safety for IDs/units
