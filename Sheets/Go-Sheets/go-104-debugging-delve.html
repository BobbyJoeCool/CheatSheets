Debugging with Delve

Delve (dlv) is Go's debugger: it understands goroutines, interfaces and Go's runtime, which gdb doesn't. You can debug a package, a test, a running process or a core dump, from the terminal or through VS Code / GoLand, which use Delve underneath. For quick checks, print debugging with %+v and slog is still common.

Notes

  • Install: go install github.com/go-delve/delve/cmd/dlv@latest
  • Optimizations make variables <optimized out>; build with -gcflags=all="-N -l"
  • dlv test debugs tests; pass test flags after --
  • Remote/headless: dlv debug --headless --listen=:2345

A Delve Session

dlv debug ./cmd/app -- -port 8080   # build + start, args after --
dlv test ./store -- -test.run TestSave
dlv attach $(pgrep app)             # running process

(dlv) break main.go:42              # or: b store.(*DB).Save
(dlv) condition 1 id == 7           # conditional breakpoint
(dlv) continue                      # c: run to breakpoint
(dlv) next                          # n: step over
(dlv) step                          # s: step into
(dlv) stepout                       # finish current function
(dlv) print user                    # p: inspect value
(dlv) locals                        # all local variables
(dlv) goroutines                    # list goroutines
(dlv) goroutine 18 bt               # stack of one goroutine
(dlv) set count = 0                 # change a variable
(dlv) restart                       # r: start over

go build -gcflags=all="-N -l" -o app-dbg ./cmd/app

Code Explained

dlv debug — compile with debug info and launch
b pkg.(*T).Method — break on a method
condition — stop only when an expression is true
goroutines / goroutine N bt — inspect concurrency
-N -l — disable optimizations and inlining

Coming From…

  • Python — ≈ pdb
  • C — ≈ gdb, but goroutine-aware
  • Java — ≈ IDE debugger via jdwp

⚠ Common Mistakes

  • Debugging an optimized build and seeing skipped lines / missing variables
  • Forgetting -- before program args, so Delve tries to parse them
  • Leaving debug fmt.Println calls in committed code; use slog.Debug

✓ Tips & Best Practices

  • In VS Code, use launch.json with "mode": "debug" or "test"
  • Use trace (dlv trace pkg Func) to log calls without stopping
  • Send SIGQUIT to a hung program to print every goroutine's stack

Quick Summary

  • dlv debug / test / attach — start
  • break, continue, next, step — control
  • print, locals, goroutines — inspect
  • -gcflags=all="-N -l" — debuggable builds
