Handlers & Middleware

Everything in net/http revolves around one interface, http.Handler with ServeHTTP(w, r). http.HandlerFunc adapts a plain function into a Handler. Middleware is a function that takes a Handler and returns a new one wrapping it, adding logging, auth, recovery or CORS around every request.

Notes

  • Middleware order matters: the outermost runs first
  • Pass request-scoped data via r.WithContext(ctx)
  • net/http already recovers panics per request, but logs noisily
  • Wrap ResponseWriter to capture the status code for logging

Writing Middleware

func logging(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        start := time.Now()
        next.ServeHTTP(w, r)                   // call the next handler
        slog.Info("req", "path", r.URL.Path, "took", time.Since(start))
    })
}

type userKey struct{}
func auth(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        user, err := verify(r.Header.Get("Authorization"))
        if err != nil { http.Error(w, "unauthorized", 401); return }
        ctx := context.WithValue(r.Context(), userKey{}, user)
        next.ServeHTTP(w, r.WithContext(ctx))  // pass data on
    })
}

mux.Handle("GET /admin/", auth(adminHandler))  // per-route
mux.Handle("/static/", http.StripPrefix("/static/", http.FileServer(http.Dir("public"))))
http.ListenAndServe(":8080", logging(recoverer(mux))) // global chain

Code Explained

func(http.Handler) http.Handler — middleware shape
next.ServeHTTP — continue the chain (or don't, to block)
r.WithContext(ctx) — attach values for later handlers
StripPrefix + FileServer — static files
logging(recoverer(mux)) — logging runs outermost

⚠ Common Mistakes

  • Writing to w after calling next and expecting to change the status (already sent)
  • Using string keys for context values; collide across packages. Use an unexported key type
  • Applying auth middleware to the whole mux and accidentally protecting health checks

✓ Tips & Best Practices

  • Build a tiny chain(h, m1, m2, …) helper to make order explicit
  • Wrap ResponseWriter in a struct that records WriteHeader for status logging
  • Use http.NewResponseController(w) (1.20) for flush/deadline control
