Profiling & Tracing

pprof shows where a program spends CPU and memory; the execution tracer shows what goroutines, the scheduler and GC were doing over time. Profiles come from tests (-cpuprofile), from code (runtime/pprof), or from a live server via net/http/pprof. Go 1.25 added a flight recorder that keeps the last few seconds of trace in memory, and PGO feeds a profile back into the compiler.

Notes

  • Profile before optimizing; intuition about hot spots is often wrong
  • Expose /debug/pprof only on an internal port
  • default.pgo in the main package enables PGO automatically (2-14% gains)
  • Go 1.27 adds the goroutineleak profile

Collecting Profiles

import _ "net/http/pprof"           // registers /debug/pprof/*
go http.ListenAndServe("localhost:6060", nil)

f, _ := os.Create("cpu.out")        // programmatic CPU profile
pprof.StartCPUProfile(f)
defer pprof.StopCPUProfile()

fr := trace.NewFlightRecorder(trace.FlightRecorderConfig{
    MinAge: 5 * time.Second,        // keep last ~5s (1.25)
})
fr.Start()
if slowRequest { fr.WriteTo(traceFile) } // snapshot on anomaly

// $ go test -bench=. -cpuprofile cpu.out -memprofile mem.out
// $ go tool pprof -http=:8080 cpu.out          # web UI + flame graph
// $ go tool pprof http://localhost:6060/debug/pprof/heap
// $ curl -o trace.out localhost:6060/debug/pprof/trace?seconds=5
// $ go tool trace trace.out
// $ cp cpu.out ./cmd/app/default.pgo && go build ./cmd/app  # PGO

Code Explained

_ "net/http/pprof" — adds handlers to the default mux

FlightRecorder — rolling in-memory trace buffer
pprof -http — interactive graphs and flame graph
default.pgo — profile-guided optimization

⚠ Common Mistakes

  • Exposing /debug/pprof on a public port; it leaks internals and can be abused
  • Profiling a debug build or a tiny input that doesn't reflect production
  • Reading flat vs cum wrong: cum includes time in callees

✓ Tips & Best Practices

  • Start with the flame graph view; it makes wide (expensive) stacks obvious
  • Enable runtime.SetMutexProfileFraction / SetBlockProfileRate only when investigating
  • Commit a representative default.pgo and refresh it periodically

Quick Summary

  • pprof — CPU, heap, goroutine profiles
  • net/http/pprof — live server profiling
  • go tool trace + flight recorder — timelines
  • PGO — default.pgo speeds up builds
