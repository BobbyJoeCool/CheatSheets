embed & io/fs

The //go:embed directive compiles files into the binary at build time, so templates, static web assets and SQL migrations ship inside a single executable. Embedded directories become an embed.FS, which implements the io/fs.FS interface. Code written against fs.FS works equally with embedded files, real directories (os.DirFS) and test fakes (fstest.MapFS).

Rules

  • The directive goes directly above a package-level var
  • Patterns are relative to the source file's directory; no ..
  • Files starting with . or _ are skipped unless you use all:
  • Requires import "embed" (blank import for string/[]byte vars)

Embedding Files

//go:embed version.txt
var version string               // file contents as string

//go:embed logo.png
var logo []byte

//go:embed templates/*.html static
var assets embed.FS              // directory tree

//go:embed all:public
var public embed.FS              // include dot/underscore files

page, _ := assets.ReadFile("templates/index.html")
tmpl := template.Must(template.ParseFS(assets, "templates/*.html"))

sub, _ := fs.Sub(assets, "static")              // strip prefix
http.Handle("/static/", http.StripPrefix("/static/",
    http.FileServerFS(sub)))                    // 1.22

var testFS = fstest.MapFS{"a.txt": {Data: []byte("hi")}}

Code Explained

string / []byte — single file only
embed.FS — one or more files and directories
all: — keep hidden and _ files
fs.Sub — re-root an FS at a subdirectory
fstest.MapFS — in-memory FS for tests

⚠ Common Mistakes

  • Putting //go:embed above a local variable; it only works at package level
  • Writing // go:embed with a space; it becomes a plain comment
  • Using OS-style \ separators with embed.FS; paths are always /

✓ Tips & Best Practices

  • Embed migrations and templates to deploy a single binary
  • Accept fs.FS in functions so tests can use fstest.MapFS
  • Use go list -f '{{.EmbedFiles}}' to see what got embedded

Quick Summary
