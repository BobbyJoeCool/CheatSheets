Package Initialization

Before main runs, Go initializes every imported package once, dependencies first. Within a package, package-level variables are initialized in dependency order (not file order), then every init() function runs in the order the files are presented to the compiler. A blank import import _ "pkg" runs a package's init purely for its side effects.

Notes

  • A file can have multiple init() functions
  • init takes no args, returns nothing, and can't be called
  • Imported packages finish initializing before the importer
  • Initialization runs in a single goroutine

Init Order

package app

import (                        // side-effect imports
    _ "image/png"               // registers PNG decoder
    _ "github.com/lib/pq"       // registers "postgres" driver
)

var a = b + 1          // initialized second (needs b)
var b = f()            // initialized first
func f() int { return 41 }

func init() {          // runs after all package vars
    fmt.Println("init 1:", a)   // init 1: 42
}
func init() {          // multiple inits are allowed
    registry["json"] = jsonCodec{}
}
var loadCfg = sync.OnceValue(readConfig) // lazy alternative

Code Explained

a depends on b, so b initializes first
init() — after every package-level var is set
two init funcs — run in source order
_ "image/png" — import only for its init registration
sync.OnceValue — defer expensive setup until first use

Coming From…

  • Java — init() ≈ static initializer blocks
  • Python — ≈ module-level code run on import
  • JS — side-effect imports ≈ import 'polyfill'

⚠ Common Mistakes

  • Doing network or file I/O in init; failures can't be returned and tests become slow
  • Relying on init order across files; it depends on file naming
  • Mutable global registries filled in init that tests can't reset

✓ Tips & Best Practices

  • Prefer explicit New… constructors called from main over init side effects
  • Use sync.OnceValue / OnceFunc for lazy, error-aware setup
  • Keep init for cheap registrations and constant tables

Quick Summary

  • deps → package vars → init() → main
  • vars — dependency order
  • init() — automatic, multiple allowed
  • import _ — side effects only
