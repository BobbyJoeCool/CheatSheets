Assignment & Precedence

= assigns to existing variables and := declares new ones. Compound operators like += and &^= combine an operation with assignment. In a tuple assignment, all right-hand values are evaluated before any assignment happens, which makes swaps a one-liner. Go has only five precedence levels for binary operators.

Notes

  • Assignment is a statement, not an expression: no if x = f()
  • := reuses existing names in the same scope if at least one is new
  • Unary operators (!, -, ^, *, &, <-) bind tightest
  • Operators of equal precedence group left to right

Assignment Forms

x := 10          // declare + assign
x = 20           // assign
x += 5           // 25
x -= 3           // 22
x *= 2           // 44
x /= 4           // 11
x %= 4           // 3
x <<= 2          // 12
x &^= 4          // 8

a, b := 1, 2
a, b = b, a      // swap → 2 1
i, s := 0, []int{10, 20}
i, s[i] = 1, 9   // index evaluated first: s[0] = 9

v, err := strconv.Atoi("7")   // declare both
w, err := strconv.Atoi("8")   // OK: w is new, err reused

fmt.Println(1 + 2*3)          // 7
fmt.Println(1<<2 + 1)         // 5: << binds tighter than +

Code Explained

x op= y — same as x = x op y (x evaluated once)
a, b = b, a — swap without a temp variable
i, s[i] = … — operands on the left are evaluated first
w, err := — legal because w is new
1<<2 + 1 — << is level 5, + is level 4

Coming From…

  • Python — a, b = b, a works the same
  • C — x = y = 0 chaining isn't allowed
  • JS — assignment isn't an expression: no if (x = f())

⚠ Common Mistakes

  • Assuming C precedence: Go's << binds tighter than +, so a + b<<1 is a + (b<<1)
  • if x := f(); x = 5 { typos; Go rejects assignment in conditions
  • := inside a block meant to update an outer variable creates a shadow

✓ Tips & Best Practices

  • Add parentheses when mixing shifts and arithmetic; clarity beats memorizing levels
  • gofmt hints precedence through spacing: 1<<2 + 1
  • Use tuple assignment for swaps and Fibonacci-style updates: a, b = b, a+b
