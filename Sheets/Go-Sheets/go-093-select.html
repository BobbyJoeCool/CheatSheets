select

select waits on several channel operations at once and runs whichever case is ready first; if several are ready, it picks one at random. A default case makes it non-blocking. Combined with time.After or ctx.Done(), select implements timeouts and cancellation.

Notes

  • select {} with no cases blocks forever
  • A nil channel case is never ready: use it to disable a case
  • break inside select exits the select, not the loop (label it)
  • time.After in a hot loop allocates a timer per iteration; reuse a Timer

select Patterns

select {                               // first ready wins
case msg := <-msgs: fmt.Println("got", msg)
case <-time.After(2 * time.Second):    // timeout
    return errors.New("timed out")
case <-ctx.Done():                     // cancellation
    return ctx.Err()
}

select { case jobs <- j: default: log.Println("full, dropped") } // try-send

for a != nil || b != nil {             // merge two channels
    select {
    case v, ok := <-a:
        if !ok { a = nil; continue }   // disable closed channel
        out <- v
    case v, ok := <-b:
        if !ok { b = nil; continue }
        out <- v
    }
}

Code Explained

multiple ready cases — chosen at random (fairness)
time.After — channel that fires once after d
ctx.Done() — closed when the context is canceled
default — runs immediately if nothing is ready
a = nil — stop selecting on a closed channel

⚠ Common Mistakes

  • Busy loop for { select { … default: } } burning 100% CPU
  • Expecting case order to set priority; selection among ready cases is random
  • Forgetting a ctx.Done() case, so the goroutine can't be stopped

✓ Tips & Best Practices

  • Always include ctx.Done() in long-running for/select loops
  • Prefer context.WithTimeout over time.After when calling APIs that take a context
  • For priority, check the urgent channel in a separate non-blocking select first

Quick Summary
