Goroutines

go f() · go func() { … }() · cheap (KB-sized stacks) · main returning kills all goroutines · GOMAXPROCS (container-aware, 1.25) · runtime.NumGoroutine · "share memory by communicating" · unrecovered panic crashes the process

Goroutines

A goroutine is a function running concurrently with others, started with the go keyword. Goroutines are cheap (they start with a few KB of stack that grows as needed) and the runtime multiplexes them onto OS threads, so programs routinely run thousands. When main returns, the program exits, even if goroutines are still running.

Notes

  • go f(x) evaluates x now, runs f later
  • No handle or return value: communicate via channels or shared state + sync
  • GOMAXPROCS = OS threads running Go code; container-aware since 1.25
  • An unrecovered panic in any goroutine crashes the whole program

Starting & Waiting

func worker(id int, wg *sync.WaitGroup) {
    defer wg.Done()
    time.Sleep(100 * time.Millisecond)
    fmt.Println("worker", id, "done")
}
var wg sync.WaitGroup
for i := range 3 {
    wg.Add(1)
    go worker(i, &wg)               // pass pointer, never copy wg
}
wg.Wait()                           // block until all Done

var wg2 sync.WaitGroup
for _, url := range urls {
    wg2.Go(func() { fetch(url) })   // Go 1.25: Add + go + Done
}
wg2.Wait()
go func(msg string) { fmt.Println(msg) }("hello") // anonymous
fmt.Println(runtime.NumGoroutine(), runtime.GOMAXPROCS(0))

Code Explained

go worker(…) — returns immediately; worker runs concurrently
wg.Add(1) before go, defer wg.Done() inside
wg.Wait() — waits for the counter to reach zero
wg.Go(f) — 1.25 shortcut, no Add/Done bookkeeping
GOMAXPROCS(0) — query without changing

Coming From…

  • Java — goroutine ≈ virtual thread
  • Python — real parallelism; no GIL
  • JS — no event loop; blocking calls are fine

⚠ Common Mistakes

  • wg.Add(1) inside the goroutine; Wait may run before it and return early
  • Exiting main without waiting, so goroutines are killed mid-work
  • Starting goroutines with no way to stop them (leaks, sheet 098)

✓ Tips & Best Practices

  • Prefer wg.Go(f) (1.25) or errgroup over manual Add/Done
  • Every goroutine should have a clear owner and exit condition
  • Recover panics at the top of long-lived worker goroutines

Quick Summary

  • go f() — start a goroutine
  • sync.WaitGroup / wg.Go — wait for completion
  • cheap & many — M:N scheduling
  • main returns → program exits
