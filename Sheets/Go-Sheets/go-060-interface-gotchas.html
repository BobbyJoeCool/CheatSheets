Interface Gotchas

Most interface surprises come from two facts: an interface value is a (type, value) pair, and a type's method set depends on whether you hold a T or a *T. An interface holding a nil pointer is not nil, and a value T doesn't satisfy an interface whose methods have pointer receivers.

Remember

  • iface == nil only when both type and value are nil
  • T has only value-receiver methods; *T has both
  • Comparing interfaces with uncomparable dynamic types panics
  • Interfaces belong to the consumer, not the implementer

The Classic Traps

type MyErr struct{}
func (*MyErr) Error() string { return "boom" }

func run() error {
    var e *MyErr = nil
    return e                    // returns non-nil error!
}
fmt.Println(run() == nil)       // false
func runFixed() error { return nil } // return literal nil

type Speaker interface{ Speak() }
type Dog struct{}
func (d *Dog) Speak() {}        // pointer receiver
// var s Speaker = Dog{}        // error: Speak has pointer receiver
var s Speaker = &Dog{}          // OK

var a, b any = []int{1}, []int{1}
// a == b                       // panic: comparing uncomparable
k := map[any]int{}
// k[[]int{1}] = 1              // panic: hash of unhashable type

func Save(w io.Writer) {}       // accept the small interface

Code Explained

return e — interface gets type *MyErr, value nil
run() == nil — false because the type part is set
Dog{} lacks Speak (pointer method) in its method set
&Dog{} — *Dog has the method
uncomparable dynamic types panic at runtime, not compile time

Coming From…

  • Java — no null check on interfaces; typed nil isn't nil
  • C# — interface holding nil ≠ null reference
  • Python — no equivalent trap; learn this one

⚠ Common Mistakes

  • Returning a typed nil pointer through an error result
  • Putting values (not pointers) in an []Speaker when methods use pointer receivers
  • Defining an interface next to its only implementation "for mocking" in the producer package

✓ Tips & Best Practices

  • Return nil explicitly on success paths, never a nil-valued variable of concrete type
  • Use reflect.ValueOf(x).IsNil() only as a last resort; fix the source instead
  • nilness and nilerr linters catch many of these traps

Quick Summary

  • interface nil — needs nil type and value
  • typed nil pointer — non-nil interface
  • pointer methods — only *T satisfies
  • uncomparable dynamic types — == panics
