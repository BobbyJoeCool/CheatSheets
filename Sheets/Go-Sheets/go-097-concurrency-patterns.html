Concurrency Patterns

Most concurrent Go code is built from a few patterns: a worker pool reading jobs from a channel, fan-out/fan-in to parallelize and merge, pipelines of stages connected by channels, and bounded concurrency with a semaphore or errgroup.SetLimit. Each pattern needs a clear shutdown path via channel close or context cancel.

Principles

  • The goroutine that creates a channel usually closes it
  • Bound concurrency; unbounded goroutines exhaust memory/sockets
  • Propagate ctx so every stage can stop
  • golang.org/x/sync/errgroup = WaitGroup + errors + cancel

Worker Pool & errgroup

func pool(ctx context.Context, jobs []Job, n int) []Result {
    in, out := make(chan Job), make(chan Result)
    var wg sync.WaitGroup
    for range n {                             // fan-out
        wg.Go(func() { for j := range in { out <- process(j) } })
    }
    go func() {                               // feed jobs
        defer close(in)
        for _, j := range jobs {
            select { case in <- j: case <-ctx.Done(): return }
        }
    }()
    go func() { wg.Wait(); close(out) }()     // close when all done
    var res []Result
    for r := range out { res = append(res, r) } // fan-in
    return res
}

g, ctx := errgroup.WithContext(ctx)
g.SetLimit(8)                                 // at most 8 at once
for _, u := range urls { g.Go(func() error { return fetch(ctx, u) }) }
err := g.Wait()

Code Explained

N workers range over one input channel
producer closes in; workers then exit
wg.Wait(); close(out) — signals fan-in to stop
errgroup.SetLimit — bounded parallelism + first error
buffered chan — counting semaphore

⚠ Common Mistakes

  • Closing the output channel from a worker while others still send
  • Unbounded go per item on a million-item list
  • Fan-in reader that stops early, leaving workers blocked on send forever

✓ Tips & Best Practices

  • Reach for errgroup first; hand-roll pools only when you need streaming results
  • Use x/time/rate.Limiter for requests-per-second limits
  • Keep results ordered by sending {index, value} and placing into a slice

Quick Summary

  • worker pool — N goroutines, one job chan
  • fan-out / fan-in — parallelize & merge
  • errgroup.SetLimit — bounded + errors
  • clean shutdown — close / cancel
