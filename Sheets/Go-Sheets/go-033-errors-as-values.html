Errors as Values

error interface Error() string · if err != nil { return err } · errors.New · fmt.Errorf · return (T, error) · error last · zero value alongside error · never discard with _

Errors Are Values

Go has no exceptions for ordinary failures. A function that can fail returns an error as its last result, and the caller checks it immediately with if err != nil. error is a one-method interface, so any type with Error() string is an error. A nil error means success.

Conventions

  • Error strings are lowercase, no trailing punctuation
  • On error, other results are usually zero values; don't use them
  • Return errors up the stack, adding context as you go
  • Handle each error once: log it or return it, not both

Returning & Checking

type error interface { Error() string } // built in

func divide(a, b float64) (float64, error) {
    if b == 0 {
        return 0, errors.New("division by zero")
    }
    return a / b, nil
}

q, err := divide(10, 0)
if err != nil {
    fmt.Println("error:", err)    // error: division by zero
    return
}
fmt.Println(q)

func loadUser(id int) (*User, error) {
    row, err := db.Query(id)
    if err != nil {
        return nil, fmt.Errorf("load user %d: %w", id, err)
    }
    return parseUser(row)         // forward both results
}

Code Explained

error — built-in interface with one method
(T, error) — error is always the last result
errors.New — a fixed message
fmt.Errorf("…: %w", err) — add context, keep the cause
return parseUser(row) — forward both results

Coming From…

  • Python / Java — no try/catch; errors are return values
  • JS — no rejected promises; check err after every call
  • Rust — like Result<T, E>, without the ? operator

⚠ Common Mistakes

  • result, _ := f() dropping errors; failures turn into silent wrong data
  • Capitalized or punctuated messages: "Failed." reads badly when wrapped (load: Failed.)
  • Logging an error and also returning it, so it's reported several times

✓ Tips & Best Practices

  • Use the errcheck linter (in golangci-lint) to find ignored errors
  • Wrap with the operation, not "error": fmt.Errorf("open config: %w", err)
  • At the top (main/handler), log once with full context

Quick Summary

  • error — interface with Error() string
  • (T, error) — error last
  • if err != nil — check immediately
  • nil — success
