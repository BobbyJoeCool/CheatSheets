Slices — Internals & Gotchas

How Slices Work

A slice value is a small header: a pointer to a backing array, a length and a capacity. Slicing creates a new header over the same array, so writes through one slice are visible through the other. append writes in place while capacity remains, and only allocates a new array when it runs out, after which the slices no longer share.

Notes

  • Header = {ptr, len, cap} (24 bytes on 64-bit)
  • Growth roughly doubles small slices, ~1.25× for large ones
  • s[a:b:c] — full slice expression sets cap to c - a
  • copy(dst, src) copies min(len(dst), len(src)) elements

Sharing & Growth

base := []int{1, 2, 3, 4, 5}
a := base[1:3]                // [2 3], cap 4
a[0] = 99                     // base is now [1 99 3 4 5]

a = append(a, 100)            // fits in cap: overwrites base[3]!
fmt.Println(base)             // [1 99 3 100 5]

b := base[1:3:3]              // full slice expr: cap 2
b = append(b, 7)              // exceeds cap → new array
b[0] = -1                     // base unaffected

dst := make([]int, 2)
n := copy(dst, base)          // 2, dst = [1 99]
c := slices.Clone(base)       // independent copy

big := loadMB()               // 1 MB
head := big[:10]              // keeps the whole MB alive
head = slices.Clone(big[:10]) // keeps only 10 elements

func addOne(s []int) { s = append(s, 1) } // caller won't see it

Code Explained

a := base[1:3] — same backing array
append within cap — overwrites base[3]
[1:3:3] — limit cap so append must copy
slices.Clone — break the sharing
addOne — append changes the local header only

Coming From…

  • Python — s[1:3] copies in Python; in Go it shares memory
  • JS — .slice() copies; Go needs slices.Clone
  • Rust — slice ≈ &mut [T] view

⚠ Common Mistakes

  • Appending to a sub-slice and corrupting the parent's later elements
  • Expecting func f(s []int) { s = append(s, x) } to grow the caller's slice; return it instead
  • Holding a tiny sub-slice of a huge buffer; the whole buffer can't be GC'd

✓ Tips & Best Practices

  • Return the slice from functions that append: s = add(s, x)
  • Use s[a:b:b] when handing out sub-slices that others may append to
  • Reuse buffers with buf = buf[:0] in hot loops

Quick Summary

  • header — ptr, len, cap
  • sub-slices — share memory
  • append past cap — new array
  • slices.Clone / copy — independent data
