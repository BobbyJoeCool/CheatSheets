Structs

A struct groups named fields into one type and is Go's main way to model data. Struct literals should use field names so adding fields later doesn't break code; omitted fields get zero values. Structs are values (copied on assign) and comparable if all fields are. Tags attach metadata used by encoders like json.

Notes

  • Exported fields start with a capital; only they are seen by json, etc.
  • &T{…} creates a pointer directly
  • Anonymous structs are handy for one-off data and tests
  • Go 1.27: literal keys can be field selectors of embedded fields

Defining & Using Structs

type Address struct{ City, Zip string }

type User struct {
    ID      int       `json:"id"`
    Name    string    `json:"name"`
    Email   string    `json:"email,omitempty"`
    Address           // embedded (sheet 056)
    tags    []string  // unexported
}

u := User{ID: 1, Name: "Ann"}       // named fields; rest zero
p := &User{Name: "Bo"}              // pointer
p.Name = "Bob"                      // auto-deref
u2 := u                             // copy
u2.Name = "Cy"                      // u unchanged

pt := struct{ X, Y int }{1, 2}      // anonymous struct
fmt.Printf("%+v\n", pt)             // {X:1 Y:2}

tests := []struct{ in, want string }{ {"a", "A"}, {"b", "B"} }

Code Explained

`json:"id"` — struct tag read via reflection
Address — embedded field; its fields are promoted
User{ID: 1, Name: "Ann"} — keyed literal
u2 := u — independent copy (slices inside still shared)
[]struct{…} — table-driven test data

Coming From…

  • Java — no classes; struct + methods, no constructors
  • Python — ≈ @dataclass; fields are fixed
  • C — struct tags add metadata (JSON names)

Literal Forms

⚠ Common Mistakes

  • Positional literals for structs from other packages; they break when fields are added (vet warns)
  • Lowercase fields that should be serialized; json silently ignores them
  • Typos in tags (json:name): no compile error. go vet checks tag syntax

✓ Tips & Best Practices

  • Use %+v to print structs with field names while debugging
  • Order fields large → small to reduce padding in hot structs (fieldalignment linter)
  • Use anonymous structs for table-driven tests and one-off JSON shapes

Quick Summary

  • type T struct{…} — named fields
  • T{Field: v} — keyed literal
  • tags — metadata for encoders
  • values — copied; comparable if fields are
