Variables & Declarations

var x int · var x = 1 · x := 1 · multiple a, b := 1, 2 · var ( … ) blocks · zero values · _ blank identifier · package vs local vars

Declaring Variables

Go has two declaration forms. var name T = value works everywhere and lets you omit either the type or the value. The short form name := value infers the type and only works inside functions. Every variable is initialized: if you don't give a value it gets its type's zero value, so there is no such thing as an uninitialized variable.

Rules

  • := is function-scope only; package level needs var
  • := declares; = assigns to an existing variable
  • Unused local variables are compile errors (package vars are fine)
  • Names are camelCase; exported names start with a capital

All Declaration Forms

var count int              // 0 (zero value)
var name = "Gopher"        // type inferred: string
var ratio float64 = 1.5    // explicit type + value

var (                      // grouped block
    host = "localhost"
    port = 8080
    debug bool             // false
)

func main() {
    n := 42                // short declaration, int
    a, b := 1, "two"       // multiple, mixed types
    x, y := 10, 20
    x, y = y, x            // swap: 20 10
    _, err := os.Open("f") // _ discards a value
    n, z := 7, 3           // ok: z is new, n is reassigned
    fmt.Println(n, a, b, z, err != nil)
}

Code Explained

var x T — zero value; var x = v — type inferred
var ( … ) — groups related declarations
:= — needs at least one new name on the left
_ — blank identifier; value is discarded
x, y = y, x — right side evaluated first, so swaps work

Coming From…

  • JS — := ≈ let x =; var is not hoisted or function-scoped
  • Python — must declare before use; types fixed after
  • Java — type comes after the name: var n int

⚠ Common Mistakes

  • Using := at package level: syntax error: non-declaration statement outside function body
  • x := 1 inside an if block shadows an outer x instead of assigning it
  • a, b := f() when both already exist: "no new variables on left side of :="

✓ Tips & Best Practices

  • Prefer := inside functions; use var x T when the zero value is the point
  • Keep variable scope small: declare right before first use
  • Use go vet -vettool shadow analyzer or golangci-lint govet shadow to catch shadowing

Quick Summary

  • var x T / var x = v — long form, anywhere
  • x := v — short form, functions only
  • zero values — every variable starts initialized
  • _ — discard unwanted values
