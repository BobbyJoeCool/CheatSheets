Constraints

A constraint is an interface that can also list type sets: int | float64 allows exactly those types, and ~int allows any type whose underlying type is int. cmp.Ordered covers every type that supports <.

Notes

  • Constraint interfaces with type sets can't be used as normal variable types
  • ~ matters: without it, type Celsius float64 wouldn't match float64
  • Inline constraints are allowed: [T ~int | ~int64]

Defining Constraints

type Number interface {
    ~int | ~int32 | ~int64 | ~float32 | ~float64
}

func Sum[T Number](xs []T) T {
    var total T
    for _, x := range xs { total += x }  // + allowed for all
    return total
}

type Celsius float64
Sum([]Celsius{20.5, 21})                 // 41.5 thanks to ~

func Largest[T cmp.Ordered](xs ...T) T { // ints, floats, strings
    m := xs[0]
    for _, x := range xs[1:] { m = max(m, x) }
    return m
}


func Keys[M ~map[K]V, K comparable, V any](m M) []K {
    return slices.Collect(maps.Keys(m))
}

Code Explained

Number — union of underlying types
total += x — every member supports +
~ — accepts defined types like Celsius
cmp.Ordered — < <= > >= available
M ~map[K]V — accept named map types too

Coming From…

  • Java — cmp.Ordered ≈ <T extends Comparable>
  • Rust — constraints ≈ trait bounds
  • C++ — ≈ concepts; ~int ≈ underlying type match

⚠ Common Mistakes

  • Forgetting ~, so named types (time.Duration) are rejected
  • Using a type-set constraint as a variable type: var n Number doesn't compile
  • Expecting T Number to allow mixing int and float64 in one call; T is one type per call

✓ Tips & Best Practices

  • Use the S ~[]E pattern so functions accept named slice types and return them unchanged
  • Import cmp.Ordered rather than redefining your own ordered constraint
  • Keep constraints minimal: ask only for the operations you use

Quick Summary

  • constraint — interface + optional type set
  • A | B — union; ~T — underlying type
  • cmp.Ordered — comparison operators
