What Is Go?

Go is a compiled, statically typed language created at Google in 2007 and released as open source in 2009. It was designed to keep large codebases simple: a small spec, fast builds, one formatting style, and built-in concurrency with goroutines and channels. Go produces a single static binary, which is why it dominates cloud tooling (Docker, Kubernetes, Terraform) and network services.

Key Facts

  • Designers: Robert Griesemer, Rob Pike and Ken Thompson
  • Go 1 compatibility promise (2012): code written for Go 1.x keeps compiling on later 1.x releases
  • New release every 6 months (Feb / Aug); this set targets Go 1.27 (Aug 2026)
  • Source files end in .go; docs at go.dev, packages at pkg.go.dev

Hello, World

// hello.go
package main            // executables live in package main

import "fmt"            // stdlib formatting package

func main() {           // entry point: no args, no result
    fmt.Println("Hello, World!")   // Hello, World!
}

// $ go run hello.go       → compile + run in one step
// $ go build -o hello .  → static binary ./hello
// $ ./hello               → Hello, World!

Code Explained

package main — marks a program (not a library) package
import "fmt" — imports are paths; unused imports are compile errors
func main() — runs when the binary starts; returning ends the program
go run — builds to a temp dir and runs; go build keeps the binary
Formatting is not a choice: run gofmt (tabs, brace on same line)

Coming From…

  • Python — compiled to one binary; no interpreter
  • Java — no JVM or classes; fast startup
  • C — garbage collected, memory-safe, built-in concurrency

⚠ Common Mistakes

  • Calling it "Golang" in code or imports; the language is Go (golang is only the domain/search term)
  • Expecting classes, exceptions, or inheritance; Go uses structs, interfaces, and error values instead
  • Fighting gofmt; brace placement is enforced by the grammar (automatic semicolons)

✓ Tips & Best Practices

  • Try snippets in the Go Playground (go.dev/play) without installing anything
  • Work through A Tour of Go (go.dev/tour) and Effective Go first
  • Read the release notes at go.dev/doc/go1.N when upgrading

Quick Summary

  • package main + func main() — every program's entry point
  • go run / go build — run now vs produce a binary
  • Go 1 promise — old code keeps compiling
  • Strengths — simplicity, fast builds, concurrency, static binaries
