Floating-Point & Complex

float64 is the default floating-point type (IEEE-754 double precision); float32 is for memory-sensitive data like graphics. Floats can't represent most decimals exactly, so never compare floats with == after arithmetic. Dividing a float by zero gives +Inf or NaN rather than panicking. Go also has built-in complex64 / complex128 numbers.

Float Facts

  • Untyped float literals default to float64: x := 1.5
  • NaN != NaN is true; test with math.IsNaN(x)
  • Float → int conversion truncates toward zero
  • Use integers (cents) or math/big for money

Floats in Practice

x := 0.1 + 0.2
fmt.Println(x == 0.3)            // false
fmt.Println(x)                   // 0.30000000000000004
eq := math.Abs(x-0.3) < 1e-9     // true: use epsilon

fmt.Println(math.Round(2.5))     // 3  (half away from zero)
fmt.Println(math.Floor(-2.5))    // -3
fmt.Println(math.Trunc(-2.7))    // -2
fmt.Println(math.Ceil(2.1))      // 3
fmt.Printf("%.2f\n", 3.14159)    // 3.14

zero := 0.0
fmt.Println(1/zero, -1/zero)     // +Inf -Inf
nan := math.NaN()
fmt.Println(nan == nan, math.IsNaN(nan)) // false true
fmt.Println(math.MaxFloat64)     // 1.7976931348623157e+308

c := complex(3, 4)               // (3+4i)
fmt.Println(real(c), imag(c), cmplx.Abs(c)) // 3 4 5

Code Explained

0.1 + 0.2 — binary floats can't store 0.1 exactly
math.Abs(a-b) < eps — the correct equality test
math.Round — rounds half away from zero; RoundToEven also exists
1/zero — +Inf; only integer division by zero panics
complex(re, im) — built-in complex type; math/cmplx for functions

Coming From…

  • JS / Python — same IEEE floats: 0.1 + 0.2 != 0.3
  • Java — no BigDecimal in stdlib; use big.Float / ints
  • C — math.NaN() instead of NAN macro

⚠ Common Mistakes

  • if total == 0.3 after arithmetic; it's almost never exactly equal
  • Storing money as float64; rounding errors accumulate. Use int64 cents
  • int(2.9) expecting 3; conversion truncates to 2, use int(math.Round(x))

✓ Tips & Best Practices

  • Format output with %.2f or strconv.FormatFloat(x, 'f', 2, 64) instead of rounding the value
  • Use big.Rat when you need exact rational arithmetic
  • Prefer float64 unless you have millions of values and measured memory pressure

Quick Summary

  • float64 — default float type
  • == on floats — use an epsilon instead
  • math.Round/Floor/Ceil/Trunc — rounding
  • +Inf, NaN — results of float division by zero
