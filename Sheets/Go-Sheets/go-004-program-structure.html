Program Structure

Anatomy of a Go Program

Every Go file starts with a package clause, then imports, then top-level declarations in any order. An executable needs package main with a func main(). Visibility is decided by the first letter: Capitalized names are exported from the package, lowercase ones are private to it. There are no header files and no forward declarations.

Rules the Compiler Enforces

  • Unused imports and unused local variables are compile errors
  • Semicolons are inserted automatically at line ends, so { must stay on the same line
  • All files in one directory share one package name
  • os.Exit(n) sets the exit code; returning from main exits with 0

A Complete Program

package main                    // 1. package clause

import (                        // 2. grouped imports
    "fmt"
    "os"
    "strings"
)

const greeting = "hello"        // 3. package-level decls

func shout(s string) string {   // lowercase = unexported
    return strings.ToUpper(s) + "!"
}

func main() {                   // 4. entry point
    if len(os.Args) < 2 {
        fmt.Fprintln(os.Stderr, "usage: greet NAME")
        os.Exit(2)              // skips deferred calls
    }
    fmt.Println(shout(greeting), os.Args[1])  // HELLO! Bob
}

Code Explained

import ( … ) — factored import block; gofmt sorts it
const / var at top level — visible to the whole package
shout — unexported; Shout would be callable from other packages
os.Args[1] — command-line args; os.Args[0] is the program name
os.Exit — immediate exit; use return from main when possible

Coming From…

  • Java — no class wrapper; main is a plain function
  • Python — braces, not indentation; unused imports fail the build
  • C — no headers or forward declarations

⚠ Common Mistakes

  • Putting { on the next line; the auto-inserted ; makes it a syntax error
  • Leaving debug imports or variables; delete them or use _ = x temporarily
  • Calling os.Exit in a function that has defers; the deferred cleanup never runs

✓ Tips & Best Practices

  • Let your editor run goimports on save: it formats and adds/removes imports
  • Keep main thin: parse flags, then call run() error and exit based on its result
  • Group related declarations with const ( … ) and var ( … ) blocks

Quick Summary

  • package main + func main() — executable program
  • Capitalized — exported; lowercase — package-private
  • Unused imports/vars — compile errors
  • os.Exit(code) — non-zero exit status
