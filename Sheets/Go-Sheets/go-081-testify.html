testify

github.com/stretchr/testify is the most widely used Go testing helper library. assert functions report a failure and keep going; require functions report and stop the test immediately. It also provides test suites with setup/teardown and a mock package for hand-written mocks.

Notes

  • Argument order is (t, expected, actual)
  • Use require for preconditions (no point continuing on nil)
  • Every assertion accepts an optional message + args at the end
  • assert.New(t) saves passing t repeatedly

Assertions, Suites & Mocks

func TestParse(t *testing.T) {
    cfg, err := Parse("port=80")
    require.NoError(t, err)                  // stop if err
    require.NotNil(t, cfg)
    assert.Equal(t, 80, cfg.Port)
    assert.ElementsMatch(t, []int{1, 2}, []int{2, 1}) // any order
    _, err = Parse("port=x")
    assert.ErrorIs(t, err, ErrBadPort)
    assert.Contains(t, err.Error(), "port")
}

type MockStore struct{ mock.Mock }
func (m *MockStore) Get(id int) (string, error) {
    args := m.Called(id)
    return args.String(0), args.Error(1)
}
st := new(MockStore)
st.On("Get", 7).Return("ann", nil).Once()
st.AssertExpectations(t)

Code Explained

require.NoError — fail now; later lines would panic
assert.Equal(t, want, got) — prints a diff on failure
ElementsMatch — compare ignoring order
ErrorIs — wraps errors.Is
mock.Mock + On(…).Return(…) — scripted behavior

⚠ Common Mistakes

  • Swapping expected and actual; failure messages become misleading
  • Using assert.NoError then dereferencing the result; use require
  • Calling require from a goroutine other than the test's; FailNow must run on the test goroutine

✓ Tips & Best Practices

  • Prefer table-driven tests + assert; reach for suite only for heavy shared setup
  • Generate mocks with mockery instead of writing them by hand
  • Plain if got != want { t.Errorf(…) } is fine; testify is optional

Quick Summary

  • assert — record failure, continue
  • require — stop the test
  • (t, expected, actual) — argument order
  • mock / suite — mocks & fixtures
