Closures

A closure is a function literal that captures variables from its surrounding scope by reference: it sees and can modify their current values, and they live as long as the closure does. Closures power generators, middleware, deferred cleanups and callbacks. Since Go 1.22, loop variables are per-iteration, so capturing them in a loop is safe.

Notes

  • Captured variables are shared, not copied
  • Each call to the outer function creates new captured state
  • Closures that escape move captured vars to the heap
  • sync.OnceValue(f) wraps a closure to run it once (1.21)

Capturing State

func counter() func() int {
    n := 0                      // captured
    return func() int { n++; return n }
}
c1, c2 := counter(), counter()
c1(); c1()                      // 1, 2
fmt.Println(c1(), c2())         // 3 1: separate state

x := 1
show := func() { fmt.Println(x) }
x = 2
show()                          // 2: sees the latest value

var funcs []func()
for i := range 3 {
    funcs = append(funcs, func() { fmt.Print(i) })
}
for _, f := range funcs { f() } // 012 (Go 1.22+)

config := sync.OnceValue(func() Config { return load() })
cfg := config()                 // load() runs only once

Code Explained

n — lives on after counter returns
c1, c2 — each has its own n
show() — reads x at call time, not creation
loop capture — each iteration's i is distinct (1.22)
sync.OnceValue — lazy, thread-safe initialization

Coming From…

  • JS — closures capture variables, like JS
  • Python — no nonlocal needed to modify captured vars
  • Java — captured vars needn't be effectively final

⚠ Common Mistakes

  • Expecting a closure to snapshot a variable; it reads whatever the variable holds when called
  • Goroutines capturing a shared variable they all write: a data race. Pass values as args or lock
  • Keeping a closure around that captured a huge slice, preventing it from being freed

✓ Tips & Best Practices

  • Remove old i := i loop copies once your module targets Go 1.22+ (go fix can help)
  • Use closures for small adapters; switch to a struct with methods when state grows
  • Pass values as parameters (go func(v int){…}(v)) when intent should be explicit

Quick Summary

  • closure — func literal + captured vars
  • capture is by reference
  • per-iteration loop vars — Go 1.22
  • sync.OnceValue — run-once closure
