Sheet 038

Defining & Calling Functions

func name(a, b int) int · shared-type params · pass by value · multiple returns (int, error) · named results · naked return · no overloading / no default args

Functions

Functions are declared with func, parameters list the name before the type, and the result type comes last. Go functions can return multiple values, which is how (result, error) works. Arguments are always passed by value (copied); pass a pointer when the callee must modify the caller's data.

Rules

  • Consecutive params of one type share it: func f(a, b int)
  • No overloading and no default or named arguments
  • Named results are zero-initialized and documented in signatures
  • A function with results must end in return (or panic)

Declaring & Calling

func add(a, b int) int { return a + b }

func divmod(a, b int) (int, int) {     // multiple results
    return a / b, a % b
}

func split(sum int) (x, y int) {       // named results
    x = sum * 4 / 9
    y = sum - x
    return                             // naked return: x, y
}

func rename(u *User, name string) { u.Name = name } // mutate

sum := add(2, 3)                       // 5
q, r := divmod(17, 5)                  // 3 2
_, r = divmod(9, 4)                    // ignore quotient
x, y := split(17)                      // 7 10
rename(&user, "Ann")
fmt.Println(add(divmod(7, 2)))         // 4: results feed args

Code Explained

(a, b int) int — shared param type, single result
(int, int) — two unnamed results
(x, y int) — named results act as local variables
naked return — returns the named results
add(divmod(7, 2)) — multi-result call passed straight through

Coming From…

  • Python — no default/keyword args; use options structs
  • Java — no overloading; different names instead
  • Python / JS — multiple returns, not tuples/arrays

⚠ Common Mistakes

  • Naked returns in long functions; readers can't see what's returned
  • Passing a large struct by value then mutating it, expecting the caller to see changes
  • Returning many unnamed results of the same type: (int, int, int) is easy to misorder

✓ Tips & Best Practices

  • Name results when they document meaning: (width, height int)
  • Return a struct once you have more than three results
  • Accept an options struct instead of long parameter lists

Quick Summary

  • func name(p T) R — declaration
  • multiple results — (T, error)
  • named results + naked return
  • pass by value — use pointers to mutate
