Comments & Doc Comments

// line · / / block · doc comment on declarations · package comment & doc.go · [pkg.Name] doc links · Deprecated: · //go: directives · // Output: in examples

Comments & Documentation

Go has // line comments and /* */ block comments. A comment placed directly above a top-level declaration (no blank line) is its doc comment: go doc, gopls hovers and pkg.go.dev all render it. Doc comments start with the name being documented and are full sentences. Special //go: lines (no space after //) are directives to the toolchain, not comments.

Doc Comment Syntax

  • Start with the identifier: // Parse reads …
  • [strings.Cut] and [Config] become links in rendered docs
  • Indented lines render as code; # Heading lines become headings
  • // Deprecated: use X instead. paragraph marks an API deprecated

Comments in a Package

// Package shapes computes areas of simple geometric shapes.
//
// See [math.Pi] for the constant used by [Circle].
package shapes

// Circle is a circle with radius R.
type Circle struct{ R float64 }

// Area returns the area of c.
func (c Circle) Area() float64 {
    return math.Pi * c.R * c.R /* πr² */
}

// Deprecated: use [Circle.Area] instead.
func OldArea(c Circle) float64 { return c.Area() }

//go:generate stringer -type=Color  ← no space after //
//go:embed version.txt
var version string

Code Explained

// Package shapes … — package comment, usually in doc.go
[math.Pi] — doc link to another package's symbol
Deprecated: — tools (gopls, staticcheck) warn on use
//go:generate — run by go generate; //go:embed read by the compiler
Block comments are rare; mostly for disabling code or license headers

Coming From…

  • Java — no /** @param */; plain sentences starting with the name
  • Python — doc comments go above, not inside like docstrings
  • C# — no XML doc tags; [Name] makes links

⚠ Common Mistakes

  • A blank line between the comment and the declaration; it's no longer the doc comment
  • Writing // go:generate with a space; it becomes an ordinary comment and silently does nothing
  • Doc comments that restate the signature (// GetName gets the name) instead of explaining behavior

✓ Tips & Best Practices

  • Put long package docs in a dedicated doc.go file
  • Use Example test functions with // Output: for docs that are checked by go test
  • Run go doc -all . to preview how your package documentation reads

Quick Summary

  • // — everyday comments; /* */ — rare
  • Comment right above a decl — its doc comment
  • [Name] links, Deprecated: notices
  • //go: — compiler/tool directives
