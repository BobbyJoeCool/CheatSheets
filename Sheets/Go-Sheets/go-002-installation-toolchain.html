Installing Go

Go ships as a single toolchain: the compiler, linker, formatter, test runner and module tool are all behind the go command. Install it from go.dev/dl or a package manager, then check go version. Since Go 1.21 the go command can also download a newer toolchain on demand when a module's go.mod asks for one, controlled by GOTOOLCHAIN.

Environment Variables

  • GOROOT — where the toolchain is installed (rarely set by hand)
  • GOPATH — module cache + installed binaries; defaults to ~/go
  • GOBIN — where go install puts binaries (default $GOPATH/bin); add it to PATH
  • GOTOOLCHAIN — auto (default), local, or a version like go1.27.0

Install & Verify

# macOS
brew install go           # or the .pkg from go.dev/dl
# Linux (tarball)
sudo tar -C /usr/local -xzf go1.27.0.linux-amd64.tar.gz
export PATH=$PATH:/usr/local/go/bin:$HOME/go/bin
# Windows
winget install GoLang.Go

go version                # go1.27.0 darwin/arm64
go env GOPATH GOROOT      # /Users/me/go  /opt/…
go env -w GOBIN=$HOME/bin # persist a setting
go env -u GOBIN           # unset it again

# editor support (VS Code Go extension installs this)
go install golang.org/x/tools/gopls@latest

Code Explained

brew install go — simplest on macOS; upgrades with brew upgrade go
$HOME/go/bin — must be on PATH to run tools you go install
go env — prints every setting; -w writes to the user config file
gopls — the official language server (completion, rename, diagnostics)
No virtualenvs needed: dependencies are per-module via go.mod

Coming From…

  • Python — no venv; deps are per-module in go.mod
  • Node — no node_modules; modules cache in GOMODCACHE
  • Java — one toolchain binary, no JDK/Maven split

Toolchain Selection

SettingEffect
go 1.27go.mod minimum version for the module
toolchain go1.27.1go.mod preferred toolchain
GOTOOLCHAIN=autodownload newer toolchain if go.mod needs it
GOTOOLCHAIN=localnever download; fail if too old
GOTOOLCHAIN=go1.26.3force a specific version

⚠ Common Mistakes

  • Forgetting to add $(go env GOPATH)/bin to PATH, so installed tools "aren't found"
  • Setting GOPATH to the project folder (old pre-modules habit); with modules, code can live anywhere
  • Installing two Go versions (brew + tarball) and running the wrong one; check which go

✓ Tips & Best Practices

  • Pin a team's toolchain with a toolchain line in go.mod instead of README instructions
  • Use go env -json in scripts to read settings reliably
  • Install extra versions side by side: go install golang.org/dl/go1.26.3@latest

Quick Summary

  • go version — confirm the install
  • go env [-w] — read or persist settings
  • GOPATH/bin — where go install binaries land
  • GOTOOLCHAIN — automatic toolchain switching
