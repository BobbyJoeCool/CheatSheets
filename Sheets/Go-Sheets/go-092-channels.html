Channels

A channel is a typed pipe between goroutines: ch <- v sends and v := <-ch receives. An unbuffered channel synchronizes sender and receiver (each waits for the other); a buffered channel lets senders run ahead until it's full. The sender closes a channel to signal "no more values", which ends for range ch loops.

Rules

  • Send on a closed channel → panic; close twice → panic
  • Receive from a closed channel → zero value, ok == false
  • Send/receive on a nil channel blocks forever
  • Only the sender should close; receivers never close

Channel Basics

ch := make(chan int)              // unbuffered
go func() {
    for i := range 3 { ch <- i }  // blocks until received
    close(ch)                     // signal: done sending
}()
for v := range ch {               // ends when closed + drained
    fmt.Print(v, " ")             // 0 1 2
}

buf := make(chan string, 2)       // buffered, cap 2
buf <- "a"; buf <- "b"            // no receiver needed yet
fmt.Println(len(buf), cap(buf))   // 2 2
fmt.Println(<-buf)                // a (FIFO)

v, ok := <-ch                     // 0 false: closed

func producer(out chan<- int) { out <- 42 }   // send-only
func consumer(in <-chan int)  { fmt.Println(<-in) } // receive-only

done := make(chan struct{})       // signal-only channel
go func() { work(); close(done) }()
<-done                            // wait for the signal

Code Explained

unbuffered — each send waits for a matching receive
close(ch) + range — clean end of stream
buffered — sends block only when full
chan<- / <-chan — direction enforced by the compiler
chan struct{} + close — broadcast a one-time signal

⚠ Common Mistakes

  • Closing from the receiver side, or from multiple senders: "send on closed channel" panics
  • Unbuffered send with no receiver in main: "all goroutines are asleep - deadlock!"
  • Using buffer size to "fix" a deadlock; it usually just hides a design bug

✓ Tips & Best Practices

  • Use a buffered channel of size 1 so a goroutine can deliver its result and exit even if nobody reads
  • Declare directional types in function params to document ownership
  • With multiple senders, close via a sync.WaitGroup in a separate goroutine

Quick Summary

  • ch <- v / <-ch — send / receive
  • close + range — end a stream
  • chan<- / <-chan — directions
