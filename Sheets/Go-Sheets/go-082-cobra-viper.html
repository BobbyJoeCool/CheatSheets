Cobra & Viper

Cobra (spf13/cobra) builds CLIs with nested subcommands, POSIX-style flags, help text and shell completion; it powers kubectl, gh and hugo. Viper (spf13/viper) loads configuration from files, environment variables and flags with a single lookup API. They're often used together.

Notes

  • Each command is a *cobra.Command; AddCommand nests them
  • PersistentFlags are inherited by subcommands
  • Use RunE to return errors instead of calling os.Exit
  • cobra-cli init / add scaffold a project

A Cobra CLI with Viper

var rootCmd = &cobra.Command{Use: "shop", Short: "Shop CLI"}

var serveCmd = &cobra.Command{
    Use:   "serve",
    Short: "Start the HTTP server",
    RunE: func(cmd *cobra.Command, args []string) error {
        port := viper.GetInt("port")
        return runServer(port)
    },
}

func init() {
    rootCmd.PersistentFlags().String("config", "", "config file")
    serveCmd.Flags().IntP("port", "p", 8080, "listen port")
    viper.BindPFlag("port", serveCmd.Flags().Lookup("port"))
    viper.SetEnvPrefix("SHOP"); viper.AutomaticEnv() // SHOP_PORT
    rootCmd.AddCommand(serveCmd)
}

func main() {
    if err := rootCmd.Execute(); err != nil { os.Exit(1) }
}

Code Explained

Use / Short — usage line and help summary
RunE — command body that returns an error
IntP("port", "p", …) — --port and -p
BindPFlag + AutomaticEnv — flag, env or config file
Execute() — parses args and dispatches

⚠ Common Mistakes

  • Using Run and calling os.Exit inside; tests can't capture errors
  • Reading flag variables in init() before Execute has parsed them
  • Expecting AutomaticEnv to map server.port to SERVER_PORT without SetEnvKeyReplacer

✓ Tips & Best Practices

  • Set SilenceUsage: true on root so runtime errors don't print the usage text
  • Use cmd.OutOrStdout() so command output can be captured in tests
  • For simple tools, the stdlib flag package is enough

Quick Summary

  • cobra.Command — commands + subcommands
  • RunE — return errors
