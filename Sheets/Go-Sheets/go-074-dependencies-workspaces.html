Managing Dependencies

go get adds, upgrades or removes a dependency in go.mod; go mod tidy then syncs requirements with what the code actually imports. Modules are downloaded through a proxy (proxy.golang.org) and verified against the checksum database. Workspaces (go.work) let you develop several modules together.

Notes

  • go get pkg@none removes a dependency
  • GOPRIVATE=github.com/myorg/* skips proxy + checksum DB
  • go mod vendor copies deps into vendor/ for offline builds
  • Don't commit go.work in library repos (usually)

Dependency Commands

go get github.com/go-chi/chi/v5         # add latest
go get github.com/go-chi/chi/v5@v5.1.0  # specific version
go get -u ./...                         # upgrade all (minor/patch)
go get -u=patch ./...                   # patch upgrades only
go get example.com/old@none             # remove
go mod tidy                             # add missing, drop unused

go list -m all                          # full module graph
go list -m -u all                       # show available updates
go mod why -m golang.org/x/text         # why is this needed?
go mod graph | grep chi                 # who requires what

go env -w GOPRIVATE='github.com/myorg/*'
go mod vendor                           # create vendor/
govulncheck ./...                       # known vulnerabilities

go work init ./api ./lib                # workspace (go.work)
go work use ./tools                     # add another module

Code Explained

@version — tag, branch, commit or latest
-u — upgrade deps of the named packages
go mod tidy — the go-to cleanup after changes
go mod why — trace an unexpected dependency
go work — local multi-module development

Coming From…

  • npm — go get ≈ npm install pkg
  • npm — go mod tidy ≈ prune + install
  • pip — govulncheck ≈ pip-audit

⚠ Common Mistakes

  • Running go get -u ./... in CI and getting different builds each day
  • Not setting GOPRIVATE for company repos: "410 Gone" / checksum errors
  • Forgetting go mod tidy, so CI fails on a dirty go.mod

✓ Tips & Best Practices

  • In CI, run go mod tidy -diff (1.23) to fail on untidy modules
  • Run govulncheck in CI; it reports only vulnerabilities your code actually calls
  • Use Dependabot/Renovate to propose upgrades as reviewable PRs

Quick Summary

  • go get pkg@ver — add / change
  • go mod tidy — sync with imports
  • GOPRIVATE — private modules
  • go work — multi-module dev
