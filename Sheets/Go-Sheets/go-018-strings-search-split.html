Searching & Splitting

The strings package holds the functions other languages put on a string object. They take the string as the first argument and are all case-sensitive unless the name says otherwise. Go 1.24 added iterator versions like SplitSeq and Lines that avoid building a slice.

Notes

  • Index functions return -1 when not found
  • Cut is the idiomatic "split once" (Go 1.18)
  • strings.CutLast splits at the last separator (Go 1.27)
  • Fields splits on any run of whitespace, dropping empties

Search & Split

s := "go is fun, go is fast"
strings.Contains(s, "fun")         // true
strings.ContainsAny(s, "xyz")      // false
strings.Index(s, "is")             // 3
strings.LastIndex(s, "go")         // 11
strings.HasPrefix(s, "go")         // true
strings.Count(s, "go")             // 2
strings.EqualFold("Go", "GO")      // true

k, v, ok := strings.Cut("k=v", "=")       // "k" "v" true
d, f, _ := strings.CutLast("a/b/c.go", "/") // a/b c.go
rest, ok := strings.CutPrefix("v1.2", "v") // "1.2" true

strings.Split("a,b,,c", ",")       // ["a" "b" "" "c"]
strings.SplitN("a,b,c", ",", 2)    // ["a" "b,c"]
strings.Fields("  a  b\tc ")       // ["a" "b" "c"]
for part := range strings.SplitSeq("x,y,z", ",") {
    fmt.Print(part)                // xyz (no slice built)
}

Code Explained

Index / LastIndex — byte offset or -1
Cut — before, after, found: replaces Index + slicing
CutLast — new in 1.27; great for paths and extensions
Split keeps empty fields; Fields drops them
SplitSeq / Lines — iterators (1.24) for range

Coming From…

  • Python — s.find → strings.Index; in → Contains
  • JS — s.split → strings.Split; methods are package funcs
  • Python — partition ≈ strings.Cut

⚠ Common Mistakes

  • strings.Split("", ",") returns [""] (one empty string), not an empty slice
  • Using Index + manual slicing for key/value parsing; Cut is shorter and safer
  • Calling strings.Contains(strings.ToLower(a), …) in hot loops; consider EqualFold or precomputing

✓ Tips & Best Practices

  • Use strings.Fields for user input where spacing is inconsistent
  • Prefer SplitSeq / FieldsSeq in loops over large text (no allocation of the full slice)
  • For repeated searches over the same text, use regexp or strings.Index with offsets
