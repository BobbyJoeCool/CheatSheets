Iterators (range-over-func)

Since Go 1.23, for range accepts iterator functions. An iter.Seq[V] is a func(yield func(V) bool): it calls yield for each value and must stop when yield returns false (the loop hit break). iter.Seq2[K, V] yields pairs. The slices and maps packages produce and consume these iterators.

Notes

  • Iterators are lazy: values are produced on demand
  • Ignoring a false from yield causes a runtime panic
  • iter.Pull converts a push iterator into next()/stop()
  • Name iterator methods All, Keys, Values, Backward

Writing & Using Iterators

func Countdown(n int) iter.Seq[int] {
    return func(yield func(int) bool) {
        for i := n; i > 0; i-- {
            if !yield(i) { return }   // stop on break
        }
    }
}
for v := range Countdown(5) {
    if v < 3 { break }
    fmt.Print(v, " ")                 // 5 4 3
}

func (s *Set[T]) All() iter.Seq[T] {  // method iterator
    return func(yield func(T) bool) {
        for k := range s.m { if !yield(k) { return } }
    }
}

for i, v := range slices.All([]string{"a", "b"}) { _, _ = i, v }
evens := slices.Collect(Filter(slices.Values(nums), isEven))
next, stop := iter.Pull(Countdown(3))
defer stop()
v, ok := next()                       // 3 true

⚠ Common Mistakes

  • Not checking yield's result: panic: range function continued iteration after exit
  • Returning a []T built eagerly when callers only need the first few items
  • Forgetting defer stop() with iter.Pull, leaking its goroutine-like state

✓ Tips & Best Practices

  • Write small adapters (Filter, Map) once and compose them
  • Expose All() methods on your collections instead of exporting internals
  • Use slices.Collect / maps.Collect at the end of an iterator pipeline
