Generic Methods & More

Methods on generic types use the type's parameters: func (s *Stack[T]) Push(v T). Since Go 1.27, methods can also declare their own type parameters, like math/rand/v2's (*Rand).N[Int]. Generic methods still can't appear in interfaces or satisfy interface methods. Go 1.24 added generic type aliases, and 1.27 extended inference to function assignment.

Version Notes

  • 1.18 — type params on funcs and types
  • 1.24 — generic aliases: type Set[T comparable] = map[T]struct{}
  • 1.27 — generic methods; inference generalized to func conversions
  • Interface methods still can't have type params

Advanced Generics

type List[T any] struct{ items []T }
func (l *List[T]) Add(v T) { l.items = append(l.items, v) }

// Go 1.27: method with its own type parameter
func (l *List[T]) MapTo[U any](f func(T) U) *List[U] {
    out := &List[U]{}
    for _, v := range l.items { out.Add(f(v)) }
    return out
}
nums := &List[int]{items: []int{1, 2}}
strs := nums.MapTo(strconv.Itoa)       // *List[string]

r := rand.New(rand.NewPCG(1, 2))
d := r.N(10 * time.Second)             // generic method (1.27)

type Set[T comparable] = map[T]struct{} // generic alias (1.24)

var idx func([]string, string) int = slices.Index // inferred
f := (func([]int, int) int)(slices.Index) // conversion (1.27)

type Node[T any] interface {           // self-referential
    Children() []T
}
func Walk[T Node[T]](n T) { for _, c := range n.Children() { Walk(c) } }

Code Explained

(*List[T]).Add — method using the type's T
MapTo[U any] — method-level type parameter (1.27)
r.N(…) — rand.N as a generic method on *Rand
type Set[T] = … — alias with type params (1.24)
T Node[T] — constraint referring to T itself

⚠ Common Mistakes

  • Adding a generic method to an interface; it's still not allowed in 1.27
  • Using generic methods on a module whose go.mod says go 1.26 or earlier
  • Deep generic abstractions that hurt readability more than they remove duplication

✓ Tips & Best Practices

  • Prefer top-level generic functions when a method doesn't need the receiver's state
  • Use generic aliases to rename types across packages without breaking callers
  • Run go fix to apply modernizers after upgrading Go versions

Quick Summary

  • func (x *T[P]) M() — method on generic type
  • func (x *T) M[U any]() — generic method (1.27)
  • type A[T] = … — generic alias (1.24)
  • no type params in interface methods
