Wrapping & Inspecting

fmt.Errorf with the %w verb wraps an error: the message gains context while the original stays reachable. errors.Is walks the chain looking for a specific value (sentinel), and errors.As looks for a specific type. Go 1.26 added the generic errors.AsType[T], which returns the match directly.

Notes

  • %v formats the cause but does not wrap it
  • Multiple %w verbs in one Errorf wrap several errors (1.20)
  • errors.Join combines errors; Is/As search all of them
  • Never compare wrapped errors with ==; use errors.Is

Is, As & AsType

_, err := os.Open("missing.txt")
err = fmt.Errorf("load config: %w", err)
fmt.Println(err) // load config: open missing.txt: no such…

errors.Is(err, fs.ErrNotExist)           // true
err == fs.ErrNotExist                    // false (wrapped)

var pe *fs.PathError
if errors.As(err, &pe) {                 // find by type
    fmt.Println(pe.Path)                 // missing.txt
}
if pe, ok := errors.AsType[*fs.PathError](err); ok { // 1.26
    fmt.Println(pe.Op)                   // open
}

inner := errors.Unwrap(err)              // one level down

e := errors.Join(errA, errB)             // both kept
errors.Is(e, errB)                       // true
w := fmt.Errorf("both: %w, %w", errA, errB) // multi-wrap

Code Explained

%w — wrap; the chain is searchable
errors.Is(err, target) — any error in the chain == target?
errors.As(err, &ptr) — first error assignable to ptr's type
errors.AsType[T] — generic form, no pre-declared var (1.26)
errors.Join — tree of errors; message joins with newlines

Coming From…

  • Java — %w wrapping ≈ exception cause
  • Python — raise X from err ≈ fmt.Errorf("…: %w", err)
  • Python — except ValueError ≈ errors.As / AsType

%w vs %v

VerbEffect
%wwraps: Is/As can see cause
%vtext only: cause hidden
%w twicewraps both (1.20+)
vetflags %w of *E pointer (1.27)

⚠ Common Mistakes

  • Wrapping with %v and then expecting errors.Is to find the cause
  • errors.As(err, pe) without &: As needs a pointer to the target variable
  • Wrapping internal errors into public APIs, making them part of your contract

✓ Tips & Best Practices

  • Prefer errors.AsType on Go 1.26+; it reads better than declare-then-As
  • Use %v deliberately at API boundaries to hide implementation details
  • In tests, assert with errors.Is rather than comparing message strings

Quick Summary

  • %w — wrap with context
  • errors.Is — match by value
  • errors.As / AsType — match by type
  • errors.Join — combine errors
