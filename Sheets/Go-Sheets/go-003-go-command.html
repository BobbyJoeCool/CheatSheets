Sheet 003

The go Command

go run · go build -o · go install pkg@version · go fmt · go vet · go doc (incl. pkg@version, -ex) · go clean -cache · go help

One Command for Everything

The go command builds, runs, tests, formats, documents and manages dependencies. Most subcommands take package patterns: . is the current package and ./... is it plus every package below it. Builds are cached, so repeated go build and go test runs are fast.

Package Patterns

  • . — package in the current directory
  • ./... — current package and all sub-packages
  • example.com/app/cmd/... — every package under that import path
  • pkg@version — a specific module version (go install, go run, go doc)

Daily Commands

go run .                    # build + run this package
go run ./cmd/srv -port 8080 # args after pkg → program
go build                    # binary named after dir
go build -o bin/app ./cmd/app  # choose output path
go install ./cmd/app        # build + copy to $GOBIN
go install golang.org/x/tools/cmd/stringer@latest

go fmt ./...                # gofmt every package
go vet ./...                # static checks
go test ./...               # run all tests

go doc strings.Cut          # docs for one symbol
go doc -all net/http | less # whole package
go doc rsc.io/quote@v1.5.2  # pkg@version (1.27)
go doc -ex sort.Slice       # with examples (1.27)

go clean -cache -testcache  # clear caches
go help build               # help on a subcommand

Code Explained

go run . — runs a whole package, not just one file
-o — output file or directory for go build
go install pkg@version — install a tool without touching go.mod
go vet — also runs automatically (a subset) during go test
go doc — offline docs straight from source comments

Coming From…

  • npm / pip — go does build, test, format, deps in one tool
  • Maven/Gradle — no build file; packages are directories
  • cargo — go run ≈ cargo run, go vet ≈ cargo clippy (lite)

⚠ Common Mistakes

  • go run main.go in a multi-file package fails with "undefined"; run the package with go run .
  • Putting flags after the package for go build (go build . -o x); build flags go before the package
  • Using go get to install tools; since 1.17 that's go install tool@version

✓ Tips & Best Practices

  • Add -v to see which packages build; -x prints every command run
  • go list -f '{{.Dir}}' ./... scripts over packages with templates
  • Use go build -race / go test -race while developing concurrent code

Quick Summary

  • go run . / go build — run vs compile
  • ./... — this package and everything below
  • go fmt + go vet — format and lint before committing
  • go doc — documentation at the terminal
