Interfaces

An interface is a set of method signatures. A type satisfies an interface implicitly, simply by having those methods; there's no implements keyword. That keeps packages decoupled: you can define a small interface where you use it, and existing types fit automatically. An interface value holds a (type, value) pair.

Design Rules

  • Keep interfaces small; one-method interfaces end in -er
  • "Accept interfaces, return structs"
  • Define interfaces in the consumer package
  • Interfaces can embed other interfaces

Implicit Satisfaction

type Shape interface {
    Area() float64
    Perimeter() float64
}

type Rect struct{ W, H float64 }
func (r Rect) Area() float64      { return r.W * r.H }
func (r Rect) Perimeter() float64 { return 2 * (r.W + r.H) }

type Circle struct{ R float64 }
func (c Circle) Area() float64      { return math.Pi * c.R * c.R }
func (c Circle) Perimeter() float64 { return 2 * math.Pi * c.R }

func total(shapes ...Shape) (sum float64) {
    for _, s := range shapes { sum += s.Area() }
    return
}
total(Rect{2, 3}, Circle{1})          // 9.14…

var _ Shape = Rect{}                  // compile-time check
var _ io.Writer = (*bytes.Buffer)(nil)

type ReadCloser interface { io.Reader; io.Closer } // embedding

Code Explained

Shape — any type with both methods qualifies
Rect, Circle — no declaration of intent needed
total(...Shape) — polymorphism via interfaces
var _ Shape = Rect{} — fails to compile if methods drift
io.Reader; io.Closer — compose interfaces

Coming From…

  • Python — duck typing, but checked at compile time
  • TS — like structural typing for interfaces

⚠ Common Mistakes

  • Declaring big interfaces up front "just in case" (interface pollution)
  • Returning an interface from constructors, hiding useful concrete methods
  • Assigning a nil pointer to an interface and then checking iface == nil (sheet 060)

✓ Tips & Best Practices

  • Add var _ I = (*T)(nil) next to types that must satisfy I
  • Write the interface after you have two implementations or a test double
  • Accept io.Reader instead of *os.File to make functions testable

Quick Summary

  • interface — set of methods
  • implicit satisfaction — no implements
  • small, consumer-defined interfaces
