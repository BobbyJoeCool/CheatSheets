Production HTTP Servers

For production, configure an http.Server struct instead of calling http.ListenAndServe: set timeouts so slow clients can't exhaust resources, and implement graceful shutdown so in-flight requests finish when the process gets SIGTERM. Go serves HTTP/2 automatically over TLS, and Go 1.25's http.CrossOriginProtection blocks CSRF-style cross-origin requests.

Notes

  • ListenAndServe returns http.ErrServerClosed after Shutdown; that's normal
  • Shutdown stops accepting, then waits for active requests
  • Set ReadHeaderTimeout at minimum (Slowloris protection)
  • Behind a load balancer, add /healthz and /readyz endpoints

Graceful Server

srv := &http.Server{
    Addr:              ":8080",
    Handler:           http.NewCrossOriginProtection().Handler(mux),
    ReadHeaderTimeout: 5 * time.Second,
    ReadTimeout:       15 * time.Second,
    WriteTimeout:      30 * time.Second,
    IdleTimeout:       120 * time.Second,
}
ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
defer stop()

go func() {
    err := srv.ListenAndServe()            // or ListenAndServeTLS
    if !errors.Is(err, http.ErrServerClosed) { log.Fatal(err) }
}()
<-ctx.Done()                               // wait for signal
sctx, cancel := context.WithTimeout(context.Background(), 20*time.Second)
defer cancel()
if err := srv.Shutdown(sctx); err != nil { log.Print(err) } // drain

Code Explained

timeouts — bound every phase of a connection
CrossOriginProtection — rejects unsafe cross-origin requests (1.25)
signal.NotifyContext — ctx canceled on Ctrl-C / SIGTERM
ErrServerClosed — expected after Shutdown
Shutdown(ctx) — drain in-flight requests, with a deadline

⚠ Common Mistakes

  • No timeouts: slow or malicious clients hold connections open indefinitely
  • Calling os.Exit on SIGTERM, killing in-flight requests mid-write
  • Treating http.ErrServerClosed as a fatal error during shutdown

✓ Tips & Best Practices

  • Set the shutdown timeout below your orchestrator's grace period (e.g. 20s < 30s)
  • Use http.TimeoutHandler for per-route limits shorter than WriteTimeout
  • Flip readiness to failing first, then call Shutdown, so load balancers drain traffic

Quick Summary

  • http.Server{…Timeout} — always set timeouts
  • signal.NotifyContext + Shutdown — graceful stop
  • ErrServerClosed — normal on shutdown
  • CrossOriginProtection (1.25), TLS, health checks
