defer

defer schedules a function call to run when the surrounding function returns, whether normally or by panic. Deferred calls run in LIFO order. The call's arguments are evaluated immediately at the defer statement, but the call itself runs later. It's Go's tool for cleanup: closing files, unlocking mutexes, ending spans.

Notes

  • Defers run at function exit, not block or loop-iteration exit
  • Deferred closures can read and modify named results
  • os.Exit skips deferred calls; panic runs them
  • Defer cost is near zero since Go 1.14 (open-coded defers)

defer Patterns

func readConfig(path string) (cfg Config, err error) {
    f, err := os.Open(path)
    if err != nil { return cfg, err }
    defer f.Close()                 // runs on every return

    defer func() {                  // sees named result
        if err != nil { err = fmt.Errorf("cfg: %w", err) }
    }()
    return parse(f)
}

for i := range 3 { defer fmt.Print(i) } // prints 210 (LIFO)

x := 1
defer fmt.Println("x =", x)  // x = 1 (args evaluated now)
x = 2

for _, name := range files {        // defer in a loop: wrap
    func() { f := open(name); defer f.Close(); use(f) }()
}

Code Explained

defer f.Close() — after the error check, never before
defer mu.Unlock() — unlock even on early return/panic
defer func() { … }() — closure sees the final err
defer fmt.Println("x =", x) — captures x = 1 immediately
Wrap loop bodies in a func so each defer runs per iteration

Coming From…

  • Python — defer ≈ with / finally for cleanup
  • Java — ≈ try-with-resources, but any call works
  • C# — ≈ using / finally

⚠ Common Mistakes

  • defer f.Close() before checking err; f is nil and Close panics
  • Deferring inside a long loop; files stay open until the function ends
  • Ignoring the Close error on files you wrote; write errors may surface there

✓ Tips & Best Practices

  • Pair acquire + defer release on adjacent lines so they're reviewed together
  • For writes, capture the close error: defer func() { err = errors.Join(err, f.Close()) }()
  • Use a deferred closure to add context to every returned error

Quick Summary

  • defer call() — runs at function return
  • LIFO — last deferred runs first
  • args — evaluated immediately
  • closures — can modify named results
