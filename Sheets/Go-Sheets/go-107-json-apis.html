Building JSON APIs

A JSON API handler decodes the request body into a struct, validates it, does the work, and encodes a response with the right status code and Content-Type. Limit body size with http.MaxBytesReader, reject unknown fields to catch client typos, and return errors in a consistent JSON shape.

Notes

  • Order: Header().Set → WriteHeader → body
  • 201 Created for POST, 204 No Content for DELETE
  • Map domain errors to statuses in one place
  • r.Body is closed by the server; no need to close it

Decode, Validate, Respond

type createReq struct {
    Name  string `json:"name"`
    Price int    `json:"price"`
}
func writeJSON(w http.ResponseWriter, status int, v any) {
    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(status)
    json.NewEncoder(w).Encode(v)
}
func createItem(w http.ResponseWriter, r *http.Request) {
    r.Body = http.MaxBytesReader(w, r.Body, 1<<20)  // 1 MB max
    dec := json.NewDecoder(r.Body)
    dec.DisallowUnknownFields()
    var req createReq
    if err := dec.Decode(&req); err != nil {
        writeJSON(w, 400, errBody(err)); return
    }
    if req.Name == "" { writeJSON(w, 422, errMsg("name required")); return }
    item, err := store.Create(r.Context(), req.Name, req.Price)
    if errors.Is(err, ErrDuplicate) { writeJSON(w, 409, errBody(err)); return }
    writeJSON(w, http.StatusCreated, item)
}

Code Explained

writeJSON — one helper for headers, status, body
MaxBytesReader — 413-style failure for huge bodies
DisallowUnknownFields — reject {"nmae": …} typos
422 for validation, 409 for conflicts
r.Context() — cancel DB work if the client leaves

⚠ Common Mistakes

  • Calling WriteHeader before setting Content-Type; the header is lost
  • Returning raw internal errors (SQL text) to clients; log them, send a generic message
  • Decoding without a size limit, letting clients exhaust memory

✓ Tips & Best Practices

  • Define type apiError struct{ Error string json:"error" } for one error shape
  • Validate with a library like go-playground/validator once rules grow
  • Version your API in the path (/v1/…) from the start

Quick Summary

  • decode — MaxBytesReader + DisallowUnknownFields
  • validate — 400 / 422
  • respond — header → status → body
  • consistent JSON error shape
