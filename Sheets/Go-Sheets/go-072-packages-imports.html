Packages & Imports

A package is a directory of .go files sharing one package name, and it's the unit of compilation and visibility. You import packages by import path (module path + directory), but refer to them by package name. Import cycles are forbidden, which keeps dependency graphs clean.

Conventions

  • Package names: short, lowercase, no underscores (strconv, httputil)
  • Avoid util, common, helpers; name by purpose
  • internal/ restricts importers to the parent tree
  • cmd/<name>/main.go for each binary in a repo

Import Forms

import (
    "fmt"                                // stdlib
    "net/http"                           // name is "http"

    "github.com/google/uuid"             // third-party module
    "example.com/shop/internal/store"    // own module, internal

    mrand "math/rand/v2"                 // alias (avoid clash)
    _ "github.com/lib/pq"                // side effects only
    . "example.com/shop/testutil"        // dot import (avoid)
)

func main() {
    id := uuid.New()                     // pkg name, not path
    n := mrand.IntN(10)
    http.ListenAndServe(":8080", store.Handler())
}

// shop/
//   go.mod              module example.com/shop
//   cmd/api/main.go     package main
//   internal/store/     package store (shop-only)
//   pkg/client/         package client (importable)

Code Explained

stdlib first, then third-party, then local (goimports groups)
net/http — import path; http — package name
mrand — alias when two packages share a name
_ — run init only; . — names without prefix
internal/store — importable only within shop/…

Coming From…

  • Python — directory = package; no __init__.py
  • Java — import paths, but no one-class-per-file rule
  • JS — no default exports; capitalized names export

Import Kinds

FormUse
"pkg/path"normal
alias "pkg/path"rename / resolve clash
_ "pkg/path"side effects (drivers)

Layout Dirs

DirHolds
cmd/<app>package main per binary
internal/private packages
pkg/ (optional)public libraries
testdata/fixtures, ignored by build
vendor/vendored deps

⚠ Common Mistakes

  • Import cycles (a imports b imports a): move shared types to a third package
  • Stuttering names: user.UserService → user.Service
  • One giant utils package that everything imports

✓ Tips & Best Practices

  • Run goimports to add, remove and group imports automatically
  • Start flat (one package); split when a clear boundary appears
  • Put shared-but-private code in internal/ to keep your public API small

Quick Summary

  • package — one directory, one name
  • import path vs package name
  • alias, _, . import forms
  • internal/ & cmd/ — layout conventions
