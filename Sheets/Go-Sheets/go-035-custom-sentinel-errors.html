Sentinels & Custom Types

A sentinel error is a package-level variable such as io.EOF that callers compare against with errors.Is. A custom error type is a struct implementing Error() that carries extra fields (status codes, paths) for callers to read with errors.As. Add an Unwrap method if your type wraps another error.

Guidelines

  • Name sentinels ErrXxx; name types XxxError
  • Return custom types as *T (pointer receiver) consistently
  • An Is(target error) bool method customizes matching
  • Exported sentinels and types become part of your API

Defining Errors

var ErrNotFound = errors.New("not found")   // sentinel

type ValidationError struct {              // custom type
    Field string
    Err   error
}
func (e *ValidationError) Error() string {
    return e.Field + ": " + e.Err.Error()
}
func (e *ValidationError) Unwrap() error { return e.Err }

func find(id int) (*Item, error) {
    if id < 0 {
        return nil, &ValidationError{"id", ErrNotFound}
    }
    return nil, ErrNotFound
}

_, err := find(-1)
errors.Is(err, ErrNotFound)             // true (via Unwrap)
if ve, ok := errors.AsType[*ValidationError](err); ok {
    fmt.Println(ve.Field)                  // id
}

Code Explained

var ErrNotFound — compare with errors.Is
*ValidationError — carries structured data
Unwrap() — makes the inner error visible to Is/As
&ValidationError{…} — return the pointer, matching the receiver
AsType[*ValidationError] — extract the fields

Coming From…

  • Java — custom error types replace exception subclasses
  • Python — sentinel ErrX ≈ a module-level exception value
  • Rust — custom error structs, matched with errors.As

⚠ Common Mistakes

  • Returning a nil *MyErr as error: the interface holds a type, so err != nil is true
  • Defining Error() on the value receiver but returning &T{} (or vice versa) inconsistently
  • Matching errors by err.Error() == "not found"; messages change, use errors.Is

✓ Tips & Best Practices

  • Keep sentinels for conditions callers act on (ErrNotFound), not every failure
  • Expose behavior via small interfaces (interface{ Timeout() bool }) instead of types
  • Always end functions with return nil on success, never a typed nil variable

Quick Summary

  • var ErrX = errors.New(…) — sentinel
  • type XError struct + Error() — custom type
  • Unwrap() — expose the cause
  • typed nil — never return a nil *T as error
