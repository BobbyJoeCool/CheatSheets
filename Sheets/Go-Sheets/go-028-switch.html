switch

A switch evaluates cases top to bottom and runs the first match, then stops: there is no implicit fallthrough and no break needed. Cases can list several values, and a tagless switch (no expression) is a clean replacement for long if-else chains. Use the explicit fallthrough keyword to continue into the next case.

Notes

  • Case values needn't be constants: any expression works
  • default can appear anywhere; it runs if nothing matches
  • break exits the switch (not an enclosing loop)
  • Type switches switch v := x.(type) are on sheet 059

switch Forms

switch day {
case "Sat", "Sun":                  // multiple values
    fmt.Println("weekend")
case "Fri":
    fmt.Println("almost")
    fallthrough                     // run next body too
case "Mon", "Tue", "Wed", "Thu":
    fmt.Println("workday")
default:
    fmt.Println("unknown")
}

switch {                            // tagless: like if-else
case score >= 90:
    grade = "A"
case score >= 80:
    grade = "B"
default:
    grade = "C"
}

switch os := runtime.GOOS; os {     // init statement
case "darwin", "linux":
    fmt.Println("unix-like:", os)
}

Code Explained

case "Sat", "Sun" — matches either value
fallthrough — unconditionally enters the next case body
switch { — each case is a boolean expression
switch x := …; x { — init statement, scoped to switch
Cases are checked in order; first match wins

Coming From…

  • C / Java / JS — no fallthrough and no break needed
  • Python — like match, but cases can be any expression
  • Rust — switch {} ≈ match with guards

⚠ Common Mistakes

  • Adding break to every case out of habit; harmless but noisy
  • Using break inside a switch in a for loop expecting to exit the loop; use a label
  • Expecting fallthrough to re-check the next case condition; it doesn't

✓ Tips & Best Practices

  • Prefer a tagless switch over 3+ else if branches
  • List enum cases explicitly; the exhaustive linter flags missing ones
  • Put the most common case first for readability (no performance difference)

Quick Summary

  • switch x { case a, b: } — value switch
  • no fallthrough — first match only
  • fallthrough — explicit continue
  • switch { — clean if-else chains
