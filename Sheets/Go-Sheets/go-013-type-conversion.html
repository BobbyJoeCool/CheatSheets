Type Conversion

T(v) explicit only · int ↔ float truncation · narrowing overflow · string(rune) vs strconv.Itoa pitfall · []byte(s) / string(b) copy · []rune(s) · slice → array [4]int(s)

Explicit Conversions Only

Go never converts between types implicitly. The conversion syntax is T(v), and it works between numeric types, between strings and byte/rune slices, and between types with the same underlying type. Numeric conversions can lose data silently (truncation, wraparound). For string ↔ number conversion you need the strconv package (sheet 021), not T(v).

Conversion Notes

  • Untyped constants convert automatically when they fit: var f float64 = 1
  • []byte(s) and string(b) copy the data
  • string(65) gives "A", not "65" (go vet warns)
  • Interface → concrete type uses an assertion x.(T), not a conversion (sheet 059)

Conversion Examples

i := 42
f := float64(i)          // 42.0
n := int(3.99)           // 3: truncates toward zero
neg := int(-3.99)        // -3
// uint8(300)           // compile error: constant overflow
v := 300
b := uint8(v)            // 44: wraps at runtime (300 - 256)

s := strconv.Itoa(65)    // "65"
r := string(rune(65))    // "A"
bs := []byte("héllo")    // [104 195 169 108 108 111]
rs := []rune("héllo")    // [104 233 108 108 111]
back := string(bs)       // "héllo"

arr := [3]int(sl[:3])    // slice → array (1.20)
type Celsius float64
c := Celsius(f)          // same underlying type: OK

Code Explained

float64(i) — explicit widening
int(3.99) — truncation, not rounding
uint8(v) — keeps the low 8 bits at runtime
string(rune(65)) — code point → character
[3]int(slice) — converts a slice to an array copy (Go 1.20)

Coming From…

  • JS — no implicit coercion: "1" + 1 won't compile
  • Python — int("5") is strconv.Atoi, not int()
  • Java — no auto-widening between int and int64

⚠ Common Mistakes

  • string(n) to print a number; it produces the Unicode character for n
  • Converting a large int64 to int32 without a range check; it wraps silently
  • Expecting int(x) to round; add math.Round first

✓ Tips & Best Practices

  • Check ranges before narrowing: if v < 0 || v > math.MaxUint8 { … }
  • Use strconv for any string ↔ number work; it reports errors
  • Define named types (type UserID int64) so mixups need an explicit conversion

Quick Summary

  • T(v) — the only conversion syntax
  • float → int — truncates
  • narrowing — wraps silently
  • strconv — string ↔ number
