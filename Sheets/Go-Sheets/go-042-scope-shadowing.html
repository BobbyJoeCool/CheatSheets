Scope & Shadowing

Go is lexically scoped by blocks: each { }, plus the implicit blocks of if, for and switch statements, starts a new scope. Declaring a name that already exists in an outer scope shadows it. The usual source of bugs is := creating a new err or variable inside a block when you meant to assign the outer one.

Scope Levels

  • Universe — builtins: int, len, nil, true, error…
  • Package — top-level names, visible in every file of the package
  • File — imports are file-scoped
  • Function / block — params, locals, init statements

Shadowing Bugs

var cfg *Config                      // package level

func setup() error {
    cfg, err := load()               // BUG: new local cfg
    _ = cfg                          // package cfg still nil
    return err
}

func setupFixed() error {
    var err error
    cfg, err = load()                // assigns package cfg
    return err
}

x := 1
if x := 2; x > 1 {                   // shadows outer x
    fmt.Println(x)                   // 2
}
fmt.Println(x)                       // 1

len := 3                             // shadows builtin len!
// n := len("abc")                   // error: len is int

Code Explained

cfg, err := load() — declares a new cfg in the function
var err error + = — reuse the package-level cfg
if x := 2 — x lives only inside the if
len := 3 — legal, but breaks len() in that scope
Shadowing isn't an error; the compiler allows it

Coming From…

  • Python — block scope; variables in if don't leak out
  • JS — like let/const, no hoisting
  • Java — shadowing is allowed (and a common bug)

⚠ Common Mistakes

  • err shadowed inside if/for, so the outer err checked later is always nil
  • Naming a variable new, len, copy, string or error
  • Package-level mutable variables used as hidden globals across files

✓ Tips & Best Practices

  • Declare var err error up front when assigning to existing variables
  • Keep scopes tiny with if x := …; cond init statements
  • Enable the shadow and predeclared linters in CI

Quick Summary

  • block scope — every {} and if/for/switch
  • := in a block — may shadow
  • imports — file scope
  • builtins — can be (but shouldn't be) shadowed
