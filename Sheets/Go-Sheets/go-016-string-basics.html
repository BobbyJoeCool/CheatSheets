Strings Are Byte Slices

A Go string is an immutable sequence of bytes, conventionally UTF-8. len(s) counts bytes, s[i] returns a byte, and slicing s[a:b] shares memory with the original. Strings can't be modified in place; every change builds a new string.

Literal Forms

  • "interpreted" — escapes like \n, \t, \u00e9 work
  • `raw` — backquotes, no escapes, can span lines
  • Raw strings are ideal for regex, SQL, JSON and Windows paths
  • Zero value is ""; strings are never nil

String Basics

s := "Hello, 世界"
fmt.Println(len(s))          // 13 (bytes, not characters)
fmt.Println(s[0])            // 72 (byte 'H')
fmt.Println(s[:5])           // Hello
fmt.Println(s[7:])           // 世界
// s[0] = 'h'                // error: immutable

t := s + "!"                 // concatenation → new string
t += "?"
fmt.Println(t)               // Hello, 世界!?

fmt.Println("abc" < "abd")   // true (byte-wise compare)

Code Explained

len(s) — 13 because 世 and 界 are 3 bytes each
s[0] — a byte (uint8), print with %c for the char
s[7:] — byte offsets; slicing mid-character gives garbage
+ / += — allocate a new string each time
<, == — lexicographic byte comparison

Coming From…

  • Python — len() counts bytes, not characters
  • Java / JS — strings are UTF-8 bytes, not UTF-16
  • C — length is stored; no \0 terminator

⚠ Common Mistakes

  • Using len(s) as a character count; non-ASCII text has more bytes than characters
  • Indexing s[i] and printing it with %v; you get a number. Use %c or string(s[i]) for ASCII
  • Building a large string with += in a loop; it's O(n²). Use strings.Builder

✓ Tips & Best Practices

  • Use raw strings for regex patterns so you don't double every backslash
  • Check emptiness with s == "" or len(s) == 0 (both idiomatic)
  • A small substring keeps a huge parent string alive; strings.Clone it if you store it

Quick Summary

  • string — immutable UTF-8 bytes
  • len(s) / s[i] — byte count / byte
  • "…" vs `…` — escapes vs raw
  • + — concatenation creates new strings
