Sheet 12

XSLT — Variables, Keys & Grouping

xsl:variable · xsl:param · xsl:key · key() · mode · xsl:for-each-group · Muenchian grouping

The Next Step After Templates

Once basic templates work, most real transforms need four more tools. Variables hold computed values (they never change after being set). Parameters let callers pass values in from the command line. Keys build an index for fast lookups by value — like a join. Grouping turns flat records into nested summaries. XSLT 2.0/3.0 has xsl:for-each-group; XSLT 1.0 (browsers, xsltproc, lxml, .NET) needs the Muenchian key trick to do the same.

Input Used Below

  • <orders> with <order id customer total/> children
  • acme has orders 1 and 3 (40 + 25); globex has order 2 (15)
  • Goal: one <customer> per name with order count and sum
  • Output: <customer name="acme" count="2" sum="65"/>, then globex (1, 15)

Notes

xsl:param — a variable with a default that callers can override
{…} in a literal attribute — attribute value template; the XPath inside is evaluated
group-by — one group per distinct value; current-group() and current-grouping-key() inside
xsl:key + key() — index orders by customer; key('by-cust', 'acme') returns both acme orders
generate-id() — unique ID per node; equal only when it is the same node, so it picks each group’s first member

XSLT 3.0 — xsl:for-each-group

<xsl:stylesheet version="3.0" xmlns:xsl="http://www.w3.org/1999/XSL/Transform">
  <xsl:param name="minTotal" select="0"/>          <!-- set from command line -->

  <xsl:template match="/orders">
    <report>
      <xsl:for-each-group select="order[@total &gt;= $minTotal]" group-by="@customer">
        <xsl:sort select="current-grouping-key()"/>
        <customer name="{current-grouping-key()}"
                  count="{count(current-group())}"
                  sum="{sum(current-group()/@total)}"/>
      </xsl:for-each-group>
    </report>
  </xsl:template>
</xsl:stylesheet>

XSLT 1.0 — Muenchian Grouping with xsl:key

<xsl:key name="by-cust" match="order" use="@customer"/>

<xsl:template match="/orders">
  <report>
    <!-- keep only the FIRST order for each customer -->
    <xsl:for-each select="order[generate-id() = generate-id(key('by-cust', @customer)[1])]">
      <xsl:sort select="@customer"/>
      <xsl:variable name="group" select="key('by-cust', @customer)"/>
      <customer name="{@customer}" count="{count($group)}" sum="{sum($group/@total)}"/>
    </xsl:for-each>
  </report>
</xsl:template>

Common Mistakes

  • Trying to update a variable inside a loop — variables are immutable; compute with XPath (sum(), count()) or recursion
  • Writing select="USD" — that selects child elements named USD; a string needs select="'USD'"
  • Using for-each-group in a 1.0 processor — it errors or is ignored; check system-property('xsl:version')
  • Declaring xsl:key inside a template — keys must be top-level children of xsl:stylesheet

Tips

  • Use keys for any repeated lookup (“find the product for this order line”) — much faster than //product[@id = $x]
  • Prefer apply-templates with modes over big xsl:choose blocks — each case becomes its own template
  • Install Saxon HE (free) when you need 2.0/3.0 features; keep 1.0 only where the processor is fixed
  • Pass params from the shell: xsltproc --stringparam minTotal 20 report.xsl orders.xml or Saxon … -xsl:report.xsl minTotal=20

Summary

  • xsl:variable / xsl:param — immutable values; params overridable
  • xsl:key + key() — indexed lookups
  • mode — multiple template sets for the same nodes
  • xsl:for-each-group — grouping in 2.0+
  • Muenchian grouping — generate-id() + key() in 1.0
