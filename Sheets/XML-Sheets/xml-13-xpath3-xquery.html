XPath 2.0 / 3.1 & XQuery Basics

sequences · if / then / else · for · let · ! · || · => · maps & arrays · FLWOR

Beyond XPath 1.0

XPath 1.0 (Sheet 07) works on node-sets, strings, numbers and booleans. XPath 2.0 replaced node-sets with sequences and added typed values (dates, durations), if, for and regular expressions. 3.0 added let, the ! map operator and || string concatenation; 3.1 added maps, arrays and JSON. XQuery is the query language built on the same expression syntax, with FLWOR expressions (for, let, where, order by, return) that work like SQL over XML. These need a 2.0+ engine such as Saxon or BaseX — browsers, lxml and xmllint stop at 1.0.

Sample Data

  • <books> with <book year="…"> children holding title, author, price
  • “Dune” · Herbert · 1965 · 9.99
  • “The Dispossessed” · Le Guin · 1974 · 12.50
  • “Neuromancer” · Gibson · 1984 · 8.75

Notes

Sequence — an ordered list of items (nodes or values); (1, 2, 3); no nesting
for … return — maps over a sequence; $b/price * 2 runs once per book
if (…) then … else … — else is required
matches / replace / tokenize — regex functions; $1 back-references in replace
xs:date + duration — real date arithmetic; strings must be cast first
! — simple map: evaluate the right side once per item on the left
|| — string concatenation; numbers are converted automatically
=> — arrow: passes the left value as the first argument
?key — lookup in a map or array; arrays index from 1
FLWOR group by — re-binds $b to the whole group inside return (XQuery 3.0)

XPath 2.0 – 3.1 Expressions

(: ── 2.0 ── :)
string-join(//author, ", ")                (: "Herbert, Le Guin, Gibson" :)
//book[@year < 1970]/title/string()        (: "Dune" :)
for $b in //book return $b/price * 2       (: 19.98, 25, 17.5 :)
if (count(//book) > 2) then "many" else "few"     (: "many" :)
avg(//book/price)                           (: 10.413… :)
matches("978-0441013593", "^\d{3}-\d{10}$")  (: true :)
replace("2026-10-23", "(\d+)-(\d+)-(\d+)", "$3/$2/$1")   (: "23/10/2026" :)
xs:date("2026-10-23") + xs:dayTimeDuration("P30D")   (: 2026-11-22 :)

(: ── 3.0 ── :)
//book ! upper-case(title)                  (: "DUNE", "THE DISPOSSESSED", ... :)
"Dune" || " (" || 1965 || ")"               (: "Dune (1965)" :)
let $n := count(//book) return $n * 10      (: 30 :)

(: ── 3.1 ── :)
//book => count()                          (: 3  — same as count(//book) :)
map { "a": 1, "b": 2 }?b                    (: 2 :)
[10, 20, 30]?2                              (: 20  (arrays are 1-based) :)
parse-json('{"tags": ["x", "y"]}')?tags?1   (: "x" :)

XQuery — FLWOR

for $b in doc("books.xml")//book
let $y := xs:integer($b/@year)
where $y >= 1970
order by $b/price descending
return <item year="{$y}">{ $b/title/text() }</item>
(: <item year="1974">The Dispossessed</item>
   <item year="1984">Neuromancer</item> :)

for $b in //book
group by $decade := $b/@year idiv 10 * 10
return <decade start="{$decade}" books="{count($b)}"/>

Common Mistakes

  • Running 2.0+ expressions in lxml, xmllint or a browser — they report “invalid expression”; use Saxon or elementpath
  • Comparing a string attribute to a date without casting — use xs:date(@due) < current-date()
  • Using = to test one value against a sequence and expecting “all” — = is true if any item matches; use every $x in … satisfies
  • Indexing arrays from 0 — XPath arrays and sequences start at 1

Tips

  • Try expressions interactively in the BaseX GUI or java -cp saxon-he.jar net.sf.saxon.Query -qs:"…"
  • Use parse-json() / json-doc() (3.1) to query JSON with the same language as your XML
  • Prefer ! over for … return for simple one-line mappings
  • Declare types on variables in XQuery (let $y as xs:integer := …) to catch bad data early

Summary

  • sequences — 2.0+ data model; replace node-sets
  • for / let / if — expressions inside XPath
  • ! / || / => — 3.x operators: map, concat, arrow
  • map {} / [] / ? — 3.1 maps, arrays, lookup
  • FLWOR — XQuery’s for-let-where-order-return
