Sheet 06

XML Schema (XSD)

schema structure · simple types · complex types · restrictions · xs:sequence · xs:attribute

What is XSD?

XML Schema Definition (XSD) is the W3C standard for describing the structure and data types of an XML document. Unlike DTDs, XSD schemas are themselves valid XML documents, support over 40 built-in data types (string, integer, date, boolean, etc.), and are fully namespace-aware. A schema is linked to an XML document via the xsi:schemaLocation attribute. XSD uses the namespace prefix xs: or xsd: bound to http://www.w3.org/2001/XMLSchema.

XSD vs DTD Advantages

  • 40+ built-in data types: xs:integer, xs:date, xs:boolean, etc.
  • Full namespace support
  • XSD is itself XML — parse and generate with standard XML tools
  • Supports default and fixed values, min/maxOccurs
  • Extensible: derive new types from existing ones
  • Supports xs:any for open-content models
  • Can import/include other schemas

XSD Syntax

<?xml version="1.0" encoding="UTF-8"?>
<xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">

  <!-- ── Simple element ─────────────────────────────────── -->
  <xs:element name="title"  type="xs:string"/>
  <xs:element name="price"  type="xs:decimal"/>
  <xs:element name="inStock" type="xs:boolean"/>

  <!-- ── Complex type with sequence of children ──────────── -->
  <xs:complexType name="BookType">
    <xs:sequence>
      <xs:element name="title"  type="xs:string"/>
      <xs:element name="author" type="xs:string" maxOccurs="unbounded"/>
      <xs:element name="price"  type="xs:decimal"/>
      <xs:element name="note"   type="xs:string" minOccurs="0"/>
    </xs:sequence>
    <xs:attribute name="id"   type="xs:ID"     use="required"/>
    <xs:attribute name="lang" type="xs:string" default="en"/>
  </xs:complexType>

  <!-- ── Restriction: constrain a string ─────────────────── -->
  <xs:simpleType name="CurrencyCode">
    <xs:restriction base="xs:string">
      <xs:enumeration value="USD"/>
      <xs:enumeration value="EUR"/>
      <xs:enumeration value="GBP"/>
    </xs:restriction>
  </xs:simpleType>

  <!-- ── Root element using our complex type ──────────────── -->
  <xs:element name="catalog">
    <xs:complexType>
      <xs:sequence>
        <xs:element name="book" type="BookType" maxOccurs="unbounded"/>
      </xs:sequence>
    </xs:complexType>
  </xs:element>

</xs:schema>

Notes

xs:sequence — children must appear in the declared order; use xs:all for any order, xs:choice for one-of
minOccurs="0" — makes element optional (default is 1); maxOccurs="unbounded" allows unlimited repetitions
xs:complexType — element that contains children or attributes; xs:simpleType — element with text only
xs:restriction — derives a new type by constraining an existing one; facets include xs:minLength, xs:pattern, xs:enumeration
use="required" — attribute must be present; use="optional" (default) or use="prohibited"
type="xs:ID" — value must be unique in the document, just like DTD's ID type

Common Mistakes

  • Confusing xs:sequence (ordered) with xs:all (any order) — sequence is far more common and enforces child element ordering
  • Forgetting minOccurs="0" to make an element optional — default is required (minOccurs=1)
  • Linking the schema with the wrong namespace URI in xsi:schemaLocation — the namespace must exactly match the schema's targetNamespace

Tips

  • Name complex types with a Type suffix (BookType) to distinguish type definitions from element declarations
  • Use xs:pattern with a regex to validate formats like postal codes, phone numbers, or version strings
  • Validate with xmllint --schema schema.xsd doc.xml on the command line, or use an IDE plugin for immediate feedback

Summary

  • xs:element + xs:complexType — define structured elements with children
  • xs:sequence / xs:choice / xs:all — control child ordering
  • minOccurs / maxOccurs — control repetition (default 1 each)
  • xs:restriction — constrain a base type with facets like xs:pattern, xs:enumeration
