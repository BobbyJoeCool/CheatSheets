Sheet 11

XML Security

XXE · billion laughs · external entities · disallow-doctype-decl · defusedxml · XPath injection

The DTD Is the Attack Surface

XML parsers support DTD features that most applications never use: external entities that pull in files or URLs, and entity expansion that can grow a few bytes into gigabytes. Attackers abuse them through any endpoint that parses XML they control — SOAP APIs, SAML logins, file uploads (.docx, .svg), RSS imports. XXE (XML External Entity) reads server files or makes the server call internal URLs; billion laughs exhausts memory. The fix is the same everywhere: turn off DTD processing unless you truly need it.

Defense Checklist

  • Disallow <!DOCTYPE> entirely — the simplest and safest setting
  • If DTDs are needed: disable external entities, external DTD loading and XInclude
  • Keep entity-expansion limits on (Java secure processing, libxml2 defaults, Expat ≥ 2.4.1)
  • Never build XPath or XQuery strings from user input — pass variables
  • Treat uploaded Office files and SVGs as XML input — they are parsed too

Notes

SYSTEM "file:///…" — external entity; &xxe; is replaced by the file’s contents in the parsed result
SYSTEM "http://…" instead of a file → SSRF: the server fetches internal URLs such as cloud metadata
defusedxml — drop-in wrappers for the stdlib parsers that forbid entity declarations and external access
resolve_entities=False — lxml keeps &xxe; unexpanded; no_network=True blocks URL fetches
disallow-doctype-decl — Xerces/JDK parsers reject any document with a DOCTYPE (OWASP’s recommended setting)
FEATURE_SECURE_PROCESSING — turns on the JDK’s entity-expansion and size limits

Attack Payloads

<!-- XXE: read a local file into the document -->
<?xml version="1.0"?>
<!DOCTYPE user [ <!ENTITY xxe SYSTEM "file:///etc/passwd"> ]>
<user><name>&xxe;</name></user>

<!-- Billion laughs: 10 levels × 10 refs = 10^9 "lol"s ≈ 3 GB -->
<!DOCTYPE lolz [
  <!ENTITY lol  "lol">
  <!ENTITY lol1 "&lol;&lol;&lol;&lol;&lol;&lol;&lol;&lol;&lol;&lol;">
  <!ENTITY lol2 "&lol1;&lol1;&lol1;&lol1;&lol1;&lol1;&lol1;&lol1;&lol1;&lol1;">
  <!-- … lol3 … lol8 the same way … -->
  <!ENTITY lol9 "&lol8;&lol8;&lol8;&lol8;&lol8;&lol8;&lol8;&lol8;&lol8;&lol8;">
]>
<lolz>&lol9;</lolz>

Safe Parsing — Python

import defusedxml.ElementTree as ET        # pip install defusedxml
tree = ET.parse("upload.xml")              # raises EntitiesForbidden on <!ENTITY>

from lxml import etree
parser = etree.XMLParser(resolve_entities=False, no_network=True, load_dtd=False)
tree = etree.parse("upload.xml", parser)

Safe Parsing — Java

DocumentBuilderFactory f = DocumentBuilderFactory.newInstance();
f.setFeature("http://apache.org/xml/features/disallow-doctype-decl", true);
f.setFeature(XMLConstants.FEATURE_SECURE_PROCESSING, true);
f.setXIncludeAware(false);
f.setExpandEntityReferences(false);
Document doc = f.newDocumentBuilder().parse(input);

Common Mistakes

  • Assuming JSON-only APIs are safe — many frameworks still accept Content-Type: application/xml on the same endpoint
  • Parsing SAML responses, .docx or .svg uploads with default parser settings — they are XML documents too
  • Passing LIBXML_NOENT (PHP) or --noent (xmllint) “to expand entities” — that is exactly what enables XXE
  • Building XPath with string concatenation: "//user[name='" + name + "']" — use bound variables

Tips

  • Search the codebase for every parser factory (DocumentBuilderFactory, XMLInputFactory, etree.XMLParser) and harden each one
  • Test endpoints with the XXE payload above pointing at a harmless file you control
  • OWASP’s XXE Prevention Cheat Sheet lists the exact flags for each Java, .NET and C/C++ parser
  • If you only need data, consider JSON for new APIs — it has no entity system to attack

Summary

  • XXE — external entities read files / call URLs
  • billion laughs — nested entities exhaust memory
  • disallow-doctype-decl / DtdProcessing.Prohibit — reject DTDs
  • defusedxml — safe drop-in for Python
  • XPath variables — never concatenate user input
