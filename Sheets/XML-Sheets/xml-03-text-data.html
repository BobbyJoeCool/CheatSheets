Text Content & Escaping

Text inside XML elements is called character data (CDATA). Five characters have special meaning to the XML parser and must be escaped when they appear in text content or attribute values: <, >, &, ', and ". For longer blocks of text containing many special characters — such as embedded code or HTML — wrap the block in a CDATA section (<![CDATA[ … ]]>), which tells the parser to treat the entire block as raw text. Character references let you insert any Unicode code point directly using either decimal (&#65;) or hex (&#x41;) notation.

Predefined Entities

  • &lt; → < (less-than)
  • &gt; → > (greater-than)
  • &amp; → & (ampersand)
  • &apos; → ' (apostrophe)
  • &quot; → " (double quote)
  • &#65; → A (decimal char ref)
  • &#x41; → A (hex char ref)

Escaping & CDATA Examples

<!-- ── Escaped special characters ──────────────────────────── -->
<formula>a &lt; b &amp;&amp; b &gt; c</formula>
<!-- renders as:  a < b && b > c -->

<title lang=&apos;en&apos;>O&apos;Brien</title>

<!-- ── CDATA section — no escaping needed inside ───────────── -->
<script>
  <![CDATA[
    if (a < b && c > d) {
      console.log("raw HTML & JS here");
    }
  ]]>
</script>

<!-- ── Character references ────────────────────────────────── -->
<symbol>&#169;</symbol>      <!-- © -->
<symbol>&#x00A9;</symbol>   <!-- © (hex) -->
<symbol>&#8364;</symbol>    <!-- € -->

<!-- ── Whitespace in text content ──────────────────────────── -->
<desc xml:space="preserve">  indented   text  </desc>

Notes

<![CDATA[]]> — the sequence ]]> cannot appear inside a CDATA block; split into two sections if needed
&lt; is mandatory in text; &gt; is only strictly required after ]] but escaping it everywhere is best practice
&apos; and &quot; — only strictly required inside attribute values using the matching quote character
Decimal char refs (&#169;) and hex refs (&#xA9;) are equivalent; hex is more common for Unicode
xml:space="preserve" — instructs processors to preserve all whitespace in this element; default behavior is application-defined
Encoding declared in the prolog must match the actual file bytes — UTF-8 is safe for all Unicode

Whitespace Handling

ContextBehavior
Text contentPreserved exactly as written by default
Between elementsTechnically preserved; often ignored by apps
xml:space="preserve"Signals processor to keep all whitespace
xml:space="default"Application may normalize whitespace
Attribute valuesLeading/trailing spaces stripped by parser
CDATA sectionsAll whitespace preserved verbatim

Common Encodings

Common Mistakes

  • Using bare & in text — e.g. AT&T must be AT&amp;T or parser throws
  • Embedding ]]> inside a CDATA block — split the section at that point
  • Declaring encoding="UTF-8" but saving the file as UTF-16 — the mismatch causes parse failures

Tips

  • Use CDATA sections for any content containing HTML, code snippets, or SQL — it eliminates the need to escape every special character
  • Prefer UTF-8 for all new XML documents — it is universally supported and the XML default
  • Add xml:space="preserve" to elements where indentation or line breaks carry meaning

Summary

  • 5 predefined entities: &lt; &gt; &amp; &apos; &quot;
  • <![CDATA[…]]> — raw text block; no escaping needed inside
  • Char refs: &#169; (decimal) or &#xA9; (hex) for any Unicode point
  • UTF-8 is the default and recommended encoding for all XML
