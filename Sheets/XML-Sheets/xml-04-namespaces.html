Sheet 04

Namespaces

xmlns · prefixes · default namespace · scope · XHTML · SOAP · SVG

What are XML Namespaces?

Namespaces prevent element name collisions when combining XML vocabularies from different sources — for example, merging an HTML <table> with a furniture <table>. A namespace is a URI that uniquely identifies a vocabulary. It is declared with the xmlns attribute: xmlns="URI" for a default namespace (applies to all unprefixed elements in scope) or xmlns:prefix="URI" for a prefixed namespace. The URI is just an identifier — it does not need to resolve to a real web page.

Namespace Rules

  • A namespace URI is an identifier, not a URL — it need not be accessible
  • Namespace declarations are inherited by all descendant elements
  • A prefix can be overridden on a child element
  • Default namespace does not apply to attributes — attributes without a prefix have no namespace
  • The prefix xml is predefined and always maps to http://www.w3.org/XML/1998/namespace
  • The prefix xmlns itself is reserved and cannot be used as a regular prefix

Namespace Syntax

<!-- ── Default namespace ──────────────────────────────────── -->
<html xmlns="http://www.w3.org/1999/xhtml">
  <head><title>Page</title></head>
</html>
<!-- all unprefixed elements belong to XHTML namespace -->

<!-- ── Prefixed namespaces ────────────────────────────────── -->
<root
  xmlns:h="http://www.w3.org/1999/xhtml"
  xmlns:f="http://example.com/furniture">

  <h:table>             <!-- HTML table -->
    <h:tr><h:td>Cell</h:td></h:tr>
  </h:table>

  <f:table>             <!-- furniture table -->
    <f:width>80cm</f:width>
    <f:length>120cm</f:length>
  </f:table>

</root>

<!-- ── SOAP envelope (real-world example) ─────────────────── -->
<soap:Envelope
  xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/"
  xmlns:xsd="http://www.w3.org/2001/XMLSchema">
  <soap:Body>
    <GetPrice xmlns="http://example.com/prices">
      <Item>Widget</Item>
    </GetPrice>
  </soap:Body>
</soap:Envelope>

Notes

xmlns="URI" — default namespace; all unprefixed child elements inherit this namespace automatically
xmlns:h="URI" — binds prefix h to the URI; elements must be written as <h:element>
Prefixes are arbitrary shorthand — h, html, and xhtml all work if bound to the same URI
Two elements with the same local name but different namespace URIs are completely different elements
xmlns:soap="..." in the SOAP example — declaring on the root is idiomatic; avoids repeating on every element
To un-declare a default namespace on a child: xmlns=""

Common Mistakes

  • Assuming the default namespace applies to attributes — it doesn't; attributes without a prefix have no namespace
  • Using the same prefix for different URIs in the same document — prefix-URI bindings must be consistent within a scope
  • Treating the namespace URI as a URL that must resolve — it's just a unique string identifier

Tips

  • Declare all namespaces on the root element — it keeps them visible in one place and avoids repeated declarations
  • Use well-known prefixes (xs, xsi, soap) to match community convention and aid readability
  • When writing XPath against namespaced XML, you must register prefix-URI bindings in your XPath engine too

Summary

  • xmlns="URI" — default namespace for all unprefixed elements in scope
  • xmlns:prefix="URI" — binds a prefix; elements use prefix:name
  • Namespace URIs are identifiers only — they don't need to resolve
  • Default namespace does not apply to attributes
