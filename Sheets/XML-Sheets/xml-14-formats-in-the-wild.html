Sheet 14

XML Formats in the Wild

plist · .docx / .xlsx (OOXML) · sitemap.xml · Atom · .csproj · JUnit XML · GPX / KML

You Already Use These

Beyond the formats on Sheet 10 (RSS, SOAP, SVG, Maven, Android), a lot of everyday files are XML under the hood: macOS and iOS property lists, Office documents (OOXML — a ZIP of XML parts), sitemaps for search engines, Atom feeds, .NET project files, JUnit XML test reports that every CI system reads, and GPX/KML for maps and GPS. Each is a small vocabulary with a fixed root element and (usually) a namespace — once you know that, XPath, XSLT and xmllint work on all of them.

Shared Patterns

  • Find the root element and its xmlns first — XPath queries must use that namespace
  • Many “binary” formats are ZIPs of XML: .docx, .xlsx, .pptx, .epub, .odt
  • Pretty-print to explore: xmllint --format file.xml | less

Notes

plist — values are typed by element: <string>, <integer>, <real>, <true/>, <array>, <dict>, <date>
Most plists on disk are binary; plutil converts both ways; Python has plistlib
sitemap — up to 50,000 URLs / 50 MB per file; list several files in a <sitemapindex>
Atom vs RSS — Atom has a namespace, required id / updated / author, and RFC 3339 dates
JUnit XML — tests, failures, errors, skipped on <testsuite>; GitHub, GitLab and Jenkins all read it
local-name() — match elements regardless of namespace when you don’t want to bind a prefix

Five Small Vocabularies

<!-- Info.plist (Apple) — <key> followed by its value -->
<plist version="1.0"><dict>
  <key>CFBundleName</key>               <string>MyApp</string>
  <key>CFBundleShortVersionString</key> <string>2.1.0</string>
  <key>UIRequiresFullScreen</key>       <true/>
</dict></plist>

<!-- sitemap.xml -->
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url><loc>https://example.com/docs</loc><lastmod>2026-10-01</lastmod></url>
</urlset>

<!-- Atom feed (id, title, updated, author are required) -->
<feed xmlns="http://www.w3.org/2005/Atom">
  <id>urn:uuid:60a76c80-d399-11d9-b93c-0003939e0af6</id>
  <title>Release Notes</title>  <updated>2026-10-23T09:00:00Z</updated>
  <author><name>Dev Team</name></author>
  <entry><id>tag:example.com,2026:v2.1</id><title>v2.1</title>
    <updated>2026-10-23T09:00:00Z</updated>
    <link rel="alternate" href="https://example.com/v2.1"/></entry>
</feed>

<!-- JUnit XML test report -->
<testsuite name="api" tests="2" failures="1" time="0.42">
  <testcase classname="users" name="creates user" time="0.10"/>
  <testcase classname="users" name="rejects bad email" time="0.32">
    <failure message="expected 422, got 200"/>
  </testcase>
</testsuite>

Peeking Inside

plutil -convert xml1 -o - Info.plist           # binary plist → XML (macOS)
plutil -p Info.plist                           # readable dump
unzip -l report.docx                           # list the XML parts
unzip -p report.docx word/document.xml | xmllint --format -
xmllint --xpath "count(//*[local-name()='url'])" sitemap.xml

Common Mistakes

  • Editing a binary plist in a text editor — convert it with plutil -convert xml1 first (and back if required)
  • Searching .docx text with grep — Word splits words across several w:r runs; join w:t text first
  • Writing KML coordinates as lat,lon — KML uses longitude first: -93.6,42.0,0
  • Reading .xlsx cell values directly — t="s" cells hold an index into sharedStrings.xml, not the text

Tips

  • Use libraries for Office files (python-docx, openpyxl, Open XML SDK) — the raw XML is easy to break
  • Point your CI’s test-report step at JUnit XML from any language — pytest --junitxml, Jest jest-junit
  • Validate sitemaps against the official XSD before submitting them to search engines
  • Use plistlib.load() in Python — it reads XML and binary plists the same way

Summary

  • plist — <key> + typed value pairs; often binary on disk
  • OOXML — ZIP of XML parts; text lives in w:t
  • sitemap / Atom — namespaced web vocabularies
  • .csproj / JUnit XML — build and CI files
  • GPX / KML — geo data; KML is lon,lat
