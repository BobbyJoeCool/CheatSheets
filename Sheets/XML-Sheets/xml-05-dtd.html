Sheet 05

DTD — Document Type Definition

!ELEMENT · !ATTLIST · !ENTITY · content models · internal · external

What is a DTD?

A Document Type Definition (DTD) defines the legal structure of an XML document: which elements are allowed, in what order, how many times, and what attributes they carry. A DTD can be internal (embedded in the document's <!DOCTYPE> declaration) or external (a separate .dtd file referenced by URI). DTDs use their own non-XML syntax with declarations starting with <!. While DTDs were the original XML validation mechanism, XML Schema (XSD) has largely replaced them in modern workflows because XSD supports data types and namespaces.

DTD Limitations

  • No data type support — all values are treated as text strings
  • No namespace awareness
  • Cannot constrain element content to a specific number pattern (e.g. exactly 3)
  • Non-XML syntax — harder to process with standard XML tools
  • External DTDs must be fetched at validation time (network cost)
  • XSD or Relax NG preferred for new projects

DTD Syntax

<!-- ── Internal DTD ────────────────────────────────────────── -->
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE catalog [
  <!ELEMENT catalog  (book+)>
  <!ELEMENT book     (title, author, price, note?)>
  <!ELEMENT title    (#PCDATA)>
  <!ELEMENT author   (#PCDATA)>
  <!ELEMENT price    (#PCDATA)>
  <!ELEMENT note     (#PCDATA)>

  <!ATTLIST book
    id        ID       #REQUIRED
    lang      CDATA    "en"
    available (yes|no) "yes"
  >

  <!ENTITY pub "Publisher Name Inc.">
]>

<catalog>
  <book id="bk101" lang="en">
    <title>XML Guide</title>
    <author>&pub;</author>
    <price>44.95</price>
  </book>
</catalog>

<!-- ── External DTD ─────────────────────────────────────────  -->
<!DOCTYPE catalog SYSTEM "catalog.dtd">
<!DOCTYPE html PUBLIC
  "-//W3C//DTD XHTML 1.0 Strict//EN"
  "http://www.w3.org/TR/xhtml1/DTD/xhtml1-strict.dtd">

Notes

(book+) — content model; + means one or more; see occurrence table below
#PCDATA — Parsed Character Data; element contains text (may include entity references)
!ATTLIST — declares attributes for an element; can list multiple attributes in one declaration
ID — attribute type meaning the value must be unique across the document
#REQUIRED — attribute must be present; #IMPLIED = optional; #FIXED "val" = fixed value
!ENTITY pub "..." — defines a reusable text entity; referenced as &pub; anywhere in the document
SYSTEM vs PUBLIC — SYSTEM is a private URI; PUBLIC identifies a well-known DTD with a fallback URI

Common Mistakes

  • Declaring elements out of order in a sequence model — (a, b, c) enforces that exact order in the document
  • Using ID type but not ensuring uniqueness — parsers will error on duplicate ID values
  • Expecting DTD to validate data types like numbers or dates — it can't; use XSD for that

Tips

  • Use !ENTITY to define repeated strings (company names, copyright text) — a single change updates the whole document
  • Prefer external DTDs for shared schemas; internal DTDs are fine for quick one-off validation
  • For new projects requiring validation, use XSD instead — it supports namespaces and data types that DTDs cannot express

Summary

  • !ELEMENT — defines an element and its content model
  • !ATTLIST — declares attributes, their types, and defaults
  • !ENTITY — defines reusable text; referenced as &name;
  • Occurrence: ? 0–1 · * 0–n · + 1–n · (none) exactly 1
