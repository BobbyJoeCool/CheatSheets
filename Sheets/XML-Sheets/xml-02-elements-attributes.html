Elements and Attributes

An element is the primary building block of XML, consisting of a start tag, content, and an end tag: <price>44.95</price>. Elements can contain text, other elements, or both (mixed content). An attribute provides additional metadata directly on the start tag in name="value" form. The key design question is always: should this be an element or an attribute? Use elements for data that might expand, repeat, or need child structure; use attributes for concise, single-value metadata like IDs and types.

Element Naming Rules

  • Names must start with a letter or underscore (_)
  • Can contain letters, digits, hyphens, underscores, periods
  • Cannot start with a digit or hyphen
  • Cannot start with xml (any case) — reserved
  • No spaces in names
  • Case-sensitive: <Book> ≠ <book>
  • Convention: use camelCase or kebab-case consistently

Element & Attribute Syntax

<!-- Basic element: start tag · content · end tag -->
<title>XML Developer's Guide</title>

<!-- Empty element — two equivalent forms -->
<br />
<br></br>

<!-- Element with attributes -->
<book id="bk101" lang="en" available="true">
  <title>XML Developer's Guide</title>
  <price currency="USD">44.95</price>
</book>

<!-- Mixed content (text + child elements) -->
<description>
  A <em>comprehensive</em> guide to XML.
</description>

<!-- Multiple same-name children (repetition is fine) -->
<catalog>
  <tag>fiction</tag>
  <tag>reference</tag>
  <tag>xml</tag>
</catalog>

Notes

<br /> — self-closing syntax; the space before / is optional but improves compatibility with older parsers
id="bk101" — attribute order on a tag is not significant; parsers may reorder them
Attribute values must always be quoted — single or double quotes are both valid, but pick one style and be consistent
An element cannot have two attributes with the same name
Mixed content (text and child elements together) is valid but makes XPath and schema validation more complex — avoid it when possible
Repeated child elements like <tag> are idiomatic XML for lists

Element vs. Attribute — When to Use

Use ElementUse Attribute
Content that can repeatSingle, non-repeating value
Data with child structureSimple scalar (ID, code, flag)
Human-readable contentMachine-readable metadata
Data you query with XPathClassifiers and identifiers
Values that may grow/changeValues fixed by schema/type

Content Models

ModelDescription
Element contentContains only child elements, no direct text
Text contentContains only text (character data)
Mixed contentContains both text and child elements
EmptyNo content; self-closing or open+close
AnyAny combination (used in flexible schemas)

Common Mistakes

  • Duplicate attribute names on the same element — id="a" id="b" is invalid; only one per name allowed
  • Starting element names with a digit: <1item> is invalid; use <item1>
  • Unquoted attribute values: id=42 fails — must be id="42"

Tips

  • Always add an id or key attribute on repeating elements — makes XPath selection and merging far easier later
  • Avoid mixed content models unless you're authoring document-style XML (like DocBook or DITA)
  • Stick to one attribute quoting style across the whole document — double quotes are the convention

Summary

  • Elements hold data; attributes hold metadata on elements
  • Empty elements can self-close: <tag />
  • Attribute values must always be quoted; no duplicate names on one element
  • Use elements for repeatable/expandable data, attributes for scalar identifiers
