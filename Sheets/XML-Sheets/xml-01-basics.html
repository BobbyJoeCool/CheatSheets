What is XML?

XML (eXtensible Markup Language) is a text-based format for storing and transporting structured data. Unlike HTML, XML has no predefined tags — you define your own tag names to describe your data. Every XML document must be well-formed: it must have exactly one root element, all tags must be properly nested and closed, and attribute values must be quoted. XML is case-sensitive: <Book> and <book> are different elements.

Key Facts

  • Defined by the W3C in 1998; current spec is XML 1.0 (5th ed.)
  • File extensions: .xml, .xsl, .xsd, .svg, .rss
  • Default encoding is UTF-8; declare others in the prolog
  • Whitespace outside elements is preserved by default
  • Comments use <!-- text --> syntax; cannot nest
  • Processing instructions use <?target data?>
  • Common parsers: browser DOM, Python xml.etree, Java JAXP

Anatomy of an XML Document

<?xml version="1.0" encoding="UTF-8"?>
<!-- XML prolog ↑ — always line 1 if present -->

<!-- Optional DOCTYPE declaration -->
<!DOCTYPE catalog SYSTEM "catalog.dtd">

<catalog>                          <!-- root element (exactly one) -->

  <book id="bk101" lang="en">     <!-- element with attributes -->
    <title>XML Developer's Guide</title>
    <author>Gambardella, Matthew</author>
    <price currency="USD">44.95</price>
  </book>

  <book id="bk102" lang="en">
    <title>Midnight Rain</title>
    <author>Ralls, Kim</author>
    <price currency="USD">5.95</price>
    <note />                       <!-- empty element (self-closing) -->
  </book>

</catalog>

Notes

<?xml?> — prolog; optional but strongly recommended; must be first line with no whitespace before it
version="1.0" — only version in wide use; XML 1.1 exists but is rarely needed
encoding="UTF-8" — omitting this defaults to UTF-8; declare explicitly for clarity
<catalog> — every document must have exactly one root element wrapping all content
Attributes must always be quoted — single or double quotes both valid
<note /> — self-closing form for empty elements; equivalent to <note></note>
Tags are case-sensitive: opening and closing tags must match exactly

Well-Formedness Rules

RuleExample — Wrong → Right
One root element<a/><b/> → wrap in <root>
Tags must close<p>text → <p>text</p>
Proper nesting<a><b></a></b> → <a><b/></a>
Quoted attributesid=42 → id="42"
Case-sensitive tags<Book>…</book> → match case
Escape special chars< in text → &lt;
Unique attr namesid="a" id="b" → only one id

Common Mistakes

  • Whitespace or a BOM before the <?xml?> prolog — parsers will reject the document
  • Using bare < or & in text content — must escape as &lt; / &amp;
  • Mismatched tag case: <Title>…</title> is not valid XML

Tips

  • Always declare encoding="UTF-8" in the prolog, even though it's the default — it prevents encoding surprises when files are moved between systems
  • Validate with an online XML linter or your editor before parsing programmatically
  • Use attributes for metadata (IDs, types) and child elements for content that may grow

Summary

  • <?xml version="1.0" encoding="UTF-8"?> — prolog goes on line 1
  • One root element wraps all content — no siblings at the top level
  • Well-formed = closed tags, proper nesting, quoted attributes, escaped specials
  • XML is case-sensitive; opening and closing tags must match exactly
