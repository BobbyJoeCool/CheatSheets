XML in the Real World

XML underpins many formats you encounter daily without necessarily thinking of them as "XML." SVG graphics, RSS/Atom feeds, SOAP web service messages, Office Open XML (.docx, .xlsx internals), Maven pom.xml, Android layouts and manifests, and Spring configuration files are all XML vocabularies. Understanding the shared XML foundation means you can read, edit, validate, and transform any of them with the same tools and mental model.

Common XML Tooling

  • xmllint — validate, format, and XPath-query from the command line
  • xsltproc — apply XSLT stylesheets from the command line
  • VS Code + XML extension (Red Hat) — schema-aware editing and validation
  • Oxygen XML Editor — full IDE for XML, XSD, XSLT, and XPath
  • Python lxml — fast C-backed DOM, full XPath 1.0, XSLT 1.0
  • Java JAXB — bind XML to Java objects with annotations
  • Online: xmlvalidation.com, freeformatter.com/xml-formatter

Real-World XML Snippets

<!-- ── RSS 2.0 feed ──────────────────────────────────────── -->
<rss version="2.0">
  <channel>
    <title>My Blog</title>
    <link>https://example.com</link>
    <description>Latest posts</description>
    <item>
      <title>Post Title</title>
      <link>https://example.com/post-1</link>
      <pubDate>Mon, 01 Jan 2025 00:00:00 GMT</pubDate>
      <guid>https://example.com/post-1</guid>
    </item>
  </channel>
</rss>

<!-- ── SOAP 1.1 request envelope ──────────────────────────── -->
<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
  <soap:Header/>
  <soap:Body>
    <GetStockPrice xmlns="http://example.com/stock">
      <StockName>AAPL</StockName>
    </GetStockPrice>
  </soap:Body>
</soap:Envelope>

<!-- ── Maven pom.xml (partial) ────────────────────────────── -->
<project xmlns="http://maven.apache.org/POM/4.0.0">
  <modelVersion>4.0.0</modelVersion>
  <groupId>com.example</groupId>
  <artifactId>my-app</artifactId>
  <version>1.0.0</version>
  <dependencies>
    <dependency>
      <groupId>org.springframework</groupId>
      <artifactId>spring-core</artifactId>
      <version>6.1.0</version>
    </dependency>
  </dependencies>
</project>

Notes

RSS 2.0 is plain XML with no namespace — each <item> is one post/episode; <guid> should be a permanent unique URL
SOAP wraps every request in <soap:Envelope> + <soap:Body>; the actual operation is a child of Body in its own namespace
SOAP responses follow the same envelope structure; faults go in <soap:Fault> inside Body
Maven POM must declare xmlns="http://maven.apache.org/POM/4.0.0"; Maven validates against its embedded XSD
SVG is XML: you can open any .svg file in a text editor, apply XPath, or transform it with XSLT
Android AndroidManifest.xml and layout files use the android: namespace — attributes like android:id reference the SDK's namespace URI

xmllint Command Reference

CommandPurpose
xmllint file.xmlCheck well-formedness
xmllint --format file.xmlPretty-print / indent
xmllint --schema s.xsd f.xmlValidate against XSD
xmllint --dtdvalid d.dtd f.xmlValidate against DTD
xmllint --xpath "//book" f.xmlRun XPath expression
xsltproc t.xsl input.xmlApply XSLT stylesheet
xmllint --noout --valid f.xmlSilent validation (exit code only)

Common Mistakes

  • Editing pom.xml or Android XML files without namespace awareness — removing or changing xmlns declarations breaks tool processing
  • Treating RSS/Atom feeds as plain text — they're full XML; parse with an XML parser to handle entities and encoding correctly
  • Converting XML to JSON naively — attributes, mixed content, and repeated element names all need special mapping decisions before writing conversion code

Tips

  • Run xmllint --format file.xml to canonicalize indentation before committing XML files to version control — cleaner diffs
  • Use xmllint --noout --schema schema.xsd doc.xml in CI pipelines to validate config XML on every build
  • When converting XML → JSON, document your mapping rules for attributes (prefix with @?) and repeated elements (always array?) before writing any code

Summary

  • SVG, RSS, SOAP, pom.xml, Android layouts — all standard XML vocabularies
  • XML favors documents + namespaces + schema; JSON favors lightweight data APIs
  • xmllint validates, formats, and XPath-queries from the command line
  • Know the XML → JSON mapping conventions before writing conversion logic
