One-Time Setup

The recommended way to run something once before tests (seed a DB, log in) is a setup project: a normal project whose tests do the setup, listed in other projects' dependencies. Setup tests show in reports, get traces, and can use fixtures. The older globalSetup file still works for plain scripts. Test locks (1.63) serialize tests that share an external resource.

Notes

  • Dependencies run first; if they fail, dependents are skipped
  • teardown names a project that runs after all dependents finish
  • --no-deps skips dependencies when iterating locally
  • globalSetup gets no fixtures, traces or report entry

playwright.config.ts

export default defineConfig({
  projects: [
    { name: 'setup db', testMatch: /global\.setup\.ts/, teardown: 'cleanup db'},
    { name: 'cleanup db', testMatch: /global\.teardown\.ts/ },
    {
      name: 'chromium',
      use: { ...devices['Desktop Chrome'] },
      dependencies: ['setup db'],
    },
  ],
});

// tests/global.setup.ts
import { test as setup } from '@playwright/test';
setup('seed database', async ({ request }) => {
  await request.post('/api/test/reset');
});

// test locks: never run these two at the same time (1.63)
test('edits shared config', { lock: 'settings' }, async ({ page }) => {});
test.describe.configure({ lock: 'settings' });             // whole file (1.64)

Code Explained

setup project — matched by testMatch
dependencies — run before this project
teardown — run after dependents finish
{ lock } — serialize tests sharing a resource

⚠ Common Mistakes

  • Using beforeAll for once-per-run work; it runs once per worker
  • Forgetting to add the setup file to testMatch; the default pattern doesn't match *.setup.ts
  • Teardown that depends on state from setup variables; projects run in separate processes

✓ Tips & Best Practices

  • Put auth login in a setup project and save storageState (next sheet)
  • Use --no-deps locally once setup data exists
  • Use locks instead of workers: 1 when only a few tests conflict

Quick Summary

  • setup project + dependencies — run first
  • teardown — run last
  • globalSetup — legacy script hook
  • { lock: 'name' } — mutual exclusion
