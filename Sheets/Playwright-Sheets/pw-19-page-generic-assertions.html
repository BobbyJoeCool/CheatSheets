Page-Level and Plain Value Assertions

Page assertions (toHaveURL, toHaveTitle, toHaveScreenshot) retry like locator assertions. Generic matchers (toBe, toEqual, toMatchObject, toContain, …) work on plain values, check once and are synchronous — use them for data you already have, such as API responses or computed values. API responses also get toBeOK().

Notes

  • Generic matchers follow Jest semantics
  • expect.configure({ timeout, soft }) creates a preconfigured expect
  • Global expect timeout: expect: { timeout: 10_000 } in config
  • Custom failure message: expect(value, 'message')

Examples

await expect(page).toHaveURL('/dashboard');           // relative to baseURL
await expect(page).toHaveURL(/\/orders\/\d+$/);
await expect(page).toHaveURL((u) => u.searchParams.get('tab') === 'billing');
await expect(page).toHaveTitle(/Checkout/);

const res = await page.request.get('/api/user');
await expect(res).toBeOK();                                // 2xx
const user = await res.json();
expect(user).toEqual({ id: 7, name: 'Ada', roles: ['admin'] });   // deep equal
expect(user).toMatchObject({ name: 'Ada' });              // subset
expect(user.roles).toContain('admin');
expect(user.id).toBeGreaterThan(0);
expect(user).toHaveProperty('name', 'Ada');
expect(user.createdAt).toEqual(expect.any(String));

const slowExpect = expect.configure({ timeout: 15_000 });
await slowExpect(page.getByText('Report ready')).toBeVisible();
expect(user.name, 'user should be renamed after PATCH').toBe('Ada L.');

Code Explained

toHaveURL — string, RegExp or predicate
toBeOK() — APIResponse status 200–299
toEqual — deep equality
toMatchObject — partial match
expect.any() — asymmetric matcher
expect.configure() — reusable timeout/soft

⚠ Common Mistakes

  • expect(page.url()).toBe('/x') right after a click; it doesn't wait, use await expect(page).toHaveURL('/x')
  • Using toBe on objects; reference equality fails, use toEqual
  • Awaiting generic matchers or not awaiting page matchers; only the retrying ones are async

✓ Tips & Best Practices

  • Rule: locator or page → await expect(...); plain value → expect(...)
  • Use toMatchObject on API responses so new fields don't break tests
  • Name important assertions with the message argument for clearer reports

Quick Summary

  • toHaveURL / toHaveTitle — retrying page checks
  • toEqual / toMatchObject — data checks
  • toBeOK() — API status
  • expect.configure() — custom timeout/soft defaults
