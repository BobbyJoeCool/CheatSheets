The playwright CLI

Everything runs through npx playwright <command>. test runs the suite and accepts file filters, line numbers and many flags; show-report opens the HTML report; codegen records interactions into code; show-trace and the newer trace subcommands inspect recorded traces. The CLI also bundles the MCP server (playwright mcp) and the agent CLI (playwright cli).

Notes

  • Positional args to test are regex filters on file paths
  • file.spec.ts:42 runs only the test at line 42
  • Flags override matching config values for that run
  • npx playwright --help / <command> --help lists everything

Everyday Commands

npx playwright test                         # whole suite, all projects
npx playwright test tests/login.spec.ts     # one file
npx playwright test login cart              # files matching "login" or "cart"
npx playwright test login.spec.ts:18        # test at line 18
npx playwright test --project=chromium      # one project
npx playwright test --headed --workers=1    # watch it, serially
npx playwright test --ui                    # interactive UI mode
npx playwright test --debug                 # Inspector, step through
npx playwright test -g "add to cart"        # filter by title
npx playwright show-report                  # open HTML report
npx playwright codegen https://example.com  # record a test
npx playwright show-trace trace.zip         # open a trace

Code Explained

test [filters] — runs matching files
:line — pins to one test or describe
--project — repeatable; matches project name
--ui / --debug — interactive modes
show-report — serves playwright-report/

--last-failedRe-run only failures

--timeout=msPer-test timeout

⚠ Common Mistakes

  • Passing a test title as a positional argument; positionals filter file paths, use -g for titles
  • Using --headed with many workers and wondering why the machine crawls
  • Forgetting -- when running through npm: npm test -- --headed

✓ Tips & Best Practices

  • --last-failed after a red run is the fastest feedback loop
  • --list confirms which tests a filter selects before running them
  • Add common invocations as npm scripts so the team uses the same flags

Quick Summary

  • test — run, filter by path, line, project, title
  • show-report — view results
  • codegen — record new tests
  • show-trace — post-mortem debugging
