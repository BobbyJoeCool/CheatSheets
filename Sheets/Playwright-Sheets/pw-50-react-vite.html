Testing React SPAs

A Vite-based React app is a static bundle talking to APIs, which makes it ideal for Playwright: build once, serve with vite preview, and mock the API with page.route() for fast, deterministic UI tests. Client-side routing means URL changes aren't page loads, so assert with toHaveURL and visible content. React Testing Library habits (roles, labels) translate directly to Playwright locators.

Notes

  • npm create vite@latest app -- --template react-ts
  • Dev: 5173 · vite preview: 4173
  • StrictMode double-invokes effects in dev only: duplicate requests
  • VITE_* env vars are inlined at build time

Config + Test

// playwright.config.ts
export default defineConfig({
  use: { baseURL: 'http://localhost:4173' },
  webServer: {
    command: 'npm run build && npm run preview -- --port 4173 --strictPort',
    url: 'http://localhost:4173',
    reuseExistingServer: !process.env.CI,
  },
});

// tests/products.spec.ts
test('lists products from the API', async ({ page }) => {
  await page.route('**/api/products', (r) =>
    r.fulfill({ json: [{ id: 1, name: 'Mug', price: 9 }] }));
  await page.goto('/products');                         // React Router route
  await expect(page.getByRole('heading', { name: 'Products' })).toBeVisible();
  await page.getByRole('link', { name: 'Mug' }).click();
  await expect(page).toHaveURL('/products/1');          // client-side navigation
  await expect(page.getByText('$9.00')).toBeVisible();
});

Code Explained

build && preview — test the production bundle
--strictPort — fail instead of picking another port
page.route — deterministic API data
toHaveURL — SPA route change

⚠ Common Mistakes

  • Testing against vite dev in CI; first-load module compilation slows tests
  • Expecting page.goto to wait for React data fetching; assert the content instead
  • Using page.waitForLoadState('networkidle') as a "React finished" signal

✓ Tips & Best Practices

  • Combine Playwright e2e with component tests (sheets 53–54) for UI states
  • Mock only the backend boundary; keep routing and state real
  • Use React Developer Tools in headed/debug mode to inspect state

Quick Summary

  • build && preview — production-like server
  • page.route() — mock the API
  • toHaveURL — client routing
  • roles first, data-testid for the rest
