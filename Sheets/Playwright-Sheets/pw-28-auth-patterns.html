Sheet 28

Multi-Role & Advanced Auth

multiple roles · per-worker accounts · API login · sessionStorage · passkeys (context.credentials) · httpCredentials

Beyond One User

Real apps need several roles, accounts that don't collide in parallel, and auth schemes beyond cookies. Save one state file per role and pick it per file or per context. For tests that mutate shared account data, use a worker-scoped fixture that logs in a distinct account per worker. Passkeys use the virtual WebAuthn authenticator context.credentials (1.61).

Notes

  • HTTP Basic auth: use: { httpCredentials: { username, password } }
  • sessionStorage: read with page.evaluate, restore via addInitScript
  • Or use page.sessionStorage / page.localStorage APIs (1.61)
  • Client certificates: use: { clientCertificates: [...] }

Patterns

// 1. two roles in one test
test('admin approves user request', async ({ browser }) => {
  const admin = await browser.newContext({ storageState: '.auth/admin.json' });
  const user = await browser.newContext({ storageState: '.auth/user.json' });
  /* … drive both pages, then close both contexts … */
});

// 2. one account per parallel worker
export const test = base.extend<{}, { workerStorageState: string }>({
  storageState: ({ workerStorageState }, use) => use(workerStorageState),
  workerStorageState: [async ({ browser }, use, { workerIndex }) => {
    const file = `playwright/.auth/worker-${workerIndex}.json`;
    const ctx = await browser.newContext({ storageState: undefined });
    const res = await ctx.request.post('/api/login',
      { data: { user: `qa${workerIndex}`, pass: process.env.E2E_PASS } });
    await ctx.storageState({ path: file }); await ctx.close();
    await use(file);
  }, { scope: 'worker' }],
});

Code Explained

per-role state files — switch identity per context
override storageState fixture — inject worker file
ctx.request — API login shares cookies with ctx
workerIndex — unique account per worker

⚠ Common Mistakes

  • Many parallel tests changing the same user's settings; use per-worker accounts
  • Logging in through the UI inside the worker fixture; API login is faster and less flaky
  • Assuming storageState captures sessionStorage; it doesn't

✓ Tips & Best Practices

  • Keep role files named by role (admin.json, viewer.json)
  • Use ctx.request so API login cookies land in the browser context
  • Seed test accounts in the setup project before workers start
