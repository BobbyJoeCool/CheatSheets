Auth with storageState

auth.setup.ts · storageState() · playwright/.auth · setStorageState() · reuse across projects

Log In Once, Reuse Everywhere

Logging in through the UI in every test is slow. Instead, a setup project signs in once and saves cookies and local storage with context.storageState({ path }). Test projects load that file through use.storageState, so every test starts already authenticated. Since 1.59, context.setStorageState() can swap state into an existing context.

Notes

  • State file = cookies + localStorage (+ IndexedDB if asked)
  • sessionStorage is not saved; see next sheet
  • Add playwright/.auth to .gitignore
  • Expired sessions: delete the file or re-run setup

tests/auth.setup.ts

import { test as setup, expect } from '@playwright/test';
const authFile = 'playwright/.auth/user.json';

setup('authenticate', async ({ page }) => {
  await page.goto('/login');
  await page.getByLabel('Email').fill(process.env.E2E_USER!);
  await page.getByLabel('Password').fill(process.env.E2E_PASS!);
  await page.getByRole('button', { name: 'Sign in' }).click();
  await expect(page.getByRole('button', { name: 'Account' })).toBeVisible();
  await page.context().storageState({ path: authFile, indexedDB: true });
});

Code Explained

wait for a logged-in signal before saving
storageState({ path }) — write the file
indexedDB: true — for Firebase-style auth
credentials from env, never hard-coded

playwright.config.ts

projects: [
  { name: 'setup', testMatch: /.*\.setup\.ts/ },
  {
    name: 'chromium',
    use: {
      ...devices['Desktop Chrome'],
      storageState: 'playwright/.auth/user.json',
    },
    dependencies: ['setup'],
  },
],
// opt a file out: test.use({ storageState: { cookies: [], origins: [] } });

Code Explained

storageState in use — every test starts logged in
dependencies — setup runs first
empty state — test logged-out flows

⚠ Common Mistakes

  • Saving state before the login redirect finishes; the file has no session cookie
  • Committing .auth/*.json; it's a live session token
  • Sharing one account across parallel tests that mutate server state; they collide

✓ Tips & Best Practices

  • Log in via API (request.post('/api/login')) in setup for speed
  • Use test.use({ storageState: … }) per file for different roles
  • Regenerate state in CI on every run; it's fast and avoids expiry

Quick Summary

  • setup project — log in once
  • storageState({ path }) — save session
  • use.storageState — load for tests
  • empty state — logged-out tests
