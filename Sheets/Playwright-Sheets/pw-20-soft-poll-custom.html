Soft, Polling & Custom Assertions

expect.soft · expect.poll · expect.soft.poll · toPass() · expect.extend · custom message

Beyond Basic Assertions

Soft assertions record a failure but let the test continue, so one run reports several problems. expect.poll() turns any async function into a retrying assertion, and expect(fn).toPass() retries a whole block until it stops throwing. expect.extend() adds custom matchers that show up in reports like built-ins.

Notes

  • Test still fails at the end if any soft assertion failed
  • expect.soft.poll() combines both (1.61)
  • toPass default timeout is 0 (unbounded until test timeout); set one
  • Check test.info().errors.length to stop early after soft failures

Examples

await expect.soft(page.getByTestId('status')).toHaveText('Success');
await expect.soft(page.getByTestId('eta')).toHaveText('2 days');
expect(test.info().errors).toHaveLength(0);              // optional: stop here

await expect.poll(async () => {
  const res = await page.request.get('/api/jobs/42');
  return (await res.json()).state;
}, { message: 'job should finish', timeout: 30_000, intervals: [1_000, 2_000] })
  .toBe('done');

await expect(async () => {
  const res = await page.request.get('/api/health');
  expect(res.status()).toBe(200);
}).toPass({ timeout: 20_000, intervals: [1_000] });

// custom matcher
expect.extend({
  async toHaveAmount(locator: Locator, expected: number) {
    const text = await locator.textContent();
    const pass = Number(text?.replace(/[^\d.]/g, '')) === expected;
    return { pass, message: () => `expected amount ${expected}, got ${text}` };
  },
});

Code Explained

expect.soft — keep going after failure
expect.poll(fn) — retry a value-producing function
intervals — polling back-off in ms
toPass() — retry a block of assertions
expect.extend — add toHaveAmount matcher

⚠ Common Mistakes

  • Using toPass() without a timeout; a never-passing block runs until the test timeout
  • Wrapping page.click() inside toPass to "make it pass"; fix the locator or wait instead
  • Thinking soft failures make a test pass; they still fail it at the end

✓ Tips & Best Practices

  • Use soft assertions for page-content audits with many independent checks
  • Prefer expect.poll over waitForTimeout loops for eventual consistency
  • Export custom matchers from your fixtures file with mergeExpects()

Quick Summary

  • expect.soft() — non-fatal checks
  • expect.poll() — retry any async value
  • toPass() — retry assertion blocks
  • expect.extend() — custom matchers
