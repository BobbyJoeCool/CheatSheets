Containers and Other CI Systems

The official image mcr.microsoft.com/playwright:v1.64.0-noble contains browsers and all OS dependencies, so CI jobs and local runs render identically (important for screenshots). Match the image tag to your @playwright/test version. Any CI that can run a container or Node works: GitLab, Jenkins, Azure Pipelines, CircleCI and others follow the same install → test → publish-report pattern.

Notes

  • Use --ipc=host (Chromium shared memory) and --init
  • Image runs as root; for untrusted sites use a non-root user + seccomp
  • Image has browsers but not your @playwright/test; still npm ci
  • Remote: run-server in Docker, connect with PW_TEST_CONNECT_WS_ENDPOINT

Docker

docker run -it --rm --ipc=host --init -v "$PWD":/work -w /work \
  mcr.microsoft.com/playwright:v1.64.0-noble \
  /bin/bash -c "npm ci && npx playwright test"

# browsers in Docker, tests on host (e.g. macOS screenshots that match Linux CI)
docker run -p 3000:3000 --rm --init -it \
  mcr.microsoft.com/playwright:v1.64.0-noble \
  /bin/sh -c "npx -y playwright@1.64.0 run-server --port 3000 --host 0.0.0.0"
PW_TEST_CONNECT_WS_ENDPOINT=ws://127.0.0.1:3000/ npx playwright test

Code Explained

--ipc=host — avoids Chromium OOM crashes
-v $PWD — mount the project
run-server — remote browser server
PW_TEST_CONNECT_WS_ENDPOINT — use it from the host

GitLab CI and Jenkins

# .gitlab-ci.yml
e2e:
  image: mcr.microsoft.com/playwright:v1.64.0-noble
  script: [npm ci, npx playwright test]
  artifacts: { when: always, paths: [playwright-report/], expire_in: 1 week }

# Jenkinsfile (declarative)
# pipeline {
#   agent { docker { image 'mcr.microsoft.com/playwright:v1.64.0-noble' } }
#   stages { stage('e2e') { steps { sh 'npm ci'; sh 'npx playwright test' } } }
# }

CI Notes

when: always — keep reports on failure
Azure Pipelines: NodeTool → npx playwright install --with-deps → test → PublishTestResults (JUnit)

⚠ Common Mistakes

  • Image tag v1.63 with @playwright/test 1.64; browser builds don't match and tests fail to launch
  • Omitting --ipc=host; Chromium crashes under memory pressure
  • Generating screenshot baselines on macOS, comparing in Linux containers

✓ Tips & Best Practices

  • Pin the image digest or exact tag in CI
  • Use the same image locally to update visual baselines
  • Publish JUnit to your CI's test tab and the HTML report as an artifact

Quick Summary

  • mcr.microsoft.com/playwright — official image
  • --ipc=host --init — recommended flags
  • run-server — browsers in Docker, tests anywhere
  • same pattern on any CI
