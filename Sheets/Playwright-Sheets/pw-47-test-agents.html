AI Test Agents

Since 1.56, Playwright ships three agent definitions for AI coding tools: the planner explores your app and writes a Markdown test plan, the generator turns plans into Playwright tests while verifying locators live, and the healer runs failing tests, inspects the UI and patches or skips them. npx playwright init-agents installs the definitions for your agent loop.

Notes

  • Supported loops include VS Code (Copilot), Claude Code, Codex, OpenCode
  • Re-run init-agents after upgrading Playwright
  • Needs a seed test that sets up the app and provides page
  • VS Code agent mode needs v1.105+

Setup and Flow

npx playwright init-agents --loop=vscode      # GitHub Copilot in VS Code
npx playwright init-agents --loop=claude      # Claude Code

# project after init
# .github/ (or agent folder)  agent definitions
# specs/                      Markdown test plans (planner output)
# tests/seed.spec.ts          seed test: env setup + ready page
# tests/*.spec.ts             generated tests

# 1. "Plan tests for the guest checkout"  → planner → specs/guest-checkout.md
# 2. "Generate tests from specs/guest-checkout.md" → generator → tests/
# 3. "Fix failing tests"                  → healer → passing or test.fixme

Code Explained

--loop — target agent tool
specs/ — reviewable plans in Markdown
seed test — shared starting point
healer — repairs or marks broken features

tests/seed.spec.ts

import { test, expect } from './fixtures';
test('seed', async ({ page }) => {
  await page.goto('/');                 // agents start from this state
  await expect(page.getByRole('banner')).toBeVisible();
});

Seed Test

Uses your fixtures (auth, data)
Keep it minimal and green

⚠ Common Mistakes

  • Accepting generated tests without review; agents can assert the wrong behaviour
  • Skipping the seed test; the planner explores a logged-out or empty app
  • Letting the healer "fix" a real product bug by weakening an assertion

✓ Tips & Best Practices

  • Review plans in specs/ before generating; it's cheaper to fix a plan than tests
  • Give the planner a PRD or user story for better coverage
  • Run generated tests in CI like any other test; agents are authoring tools

Quick Summary

  • init-agents --loop=… — install definitions
  • planner — Markdown test plans
  • generator — tests from plans
  • healer — repair failing tests
