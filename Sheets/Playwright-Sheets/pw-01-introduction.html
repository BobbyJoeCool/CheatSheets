What Is Playwright?

Playwright is Microsoft's open-source framework for end-to-end testing and browser automation. One API drives Chromium, Firefox and WebKit in headed or headless mode on Windows, macOS and Linux. It ships two layers: the playwright library for scripting browsers, and @playwright/test, a full test runner with fixtures, parallelism, retries, reporters and tracing. Every action auto-waits for the element to be ready, which removes most manual sleeps.

Key Facts

  • Current release: 1.64 (Chromium 156, Firefox 157, WebKit 27.2)
  • Official bindings: TypeScript/JavaScript, Python, Java, .NET
  • Browsers are patched builds downloaded by npx playwright install
  • Talks to browsers over CDP / custom protocols, not WebDriver
  • Test files: *.spec.ts or *.test.ts under testDir

Hello, Playwright

// tests/example.spec.ts
import { test, expect } from '@playwright/test';

test('homepage has a title', async ({ page }) => {   // page fixture = fresh tab
  await page.goto('https://playwright.dev/');          // waits for "load"
  await expect(page).toHaveTitle(/Playwright/);        // retries until true

  await page.getByRole('link', { name: 'Get started' }).click();
  await expect(page.getByRole('heading', { name: 'Installation' }))
    .toBeVisible();                                    // web-first assertion
});
// npx playwright test  → runs in every configured browser, headless

Code Explained

test — declares a test; receives fixtures
{ page } — isolated page in a new browser context
page.goto() — navigates and waits for load
getByRole() — user-facing locator (preferred)
expect(...).toBeVisible() — auto-retrying assertion

⚠ Common Mistakes

  • Installing playwright and hand-rolling a runner when @playwright/test already gives fixtures, retries and reports
  • Adding waitForTimeout() sleeps; actions and expect already wait
  • Assuming WebKit = real Safari; it is the engine, not the branded browser

✓ Tips & Best Practices

  • Start with npm init playwright@latest; it scaffolds config, example tests and CI
  • Prefer getByRole locators; they match how users and assistive tech see the page
  • One context per test gives full isolation at almost no cost

Quick Summary

  • @playwright/test — runner + assertions + fixtures
  • browser → context → page — isolation layers
  • auto-wait — actions wait for actionable elements
  • 3 engines — Chromium, Firefox, WebKit
