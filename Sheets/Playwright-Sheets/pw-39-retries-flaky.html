Retries & Flaky Tests

retries · retryStrategy · testInfo.retry · --fail-on-flaky-tests · --repeat-each · --shuffle

Handling Flakiness

With retries > 0, a failed test is re-run in a fresh worker. A test that fails first and then passes is reported as flaky: green, but flagged. retryStrategy (1.62) chooses whether retries run immediately or isolated at the end, and failOnFlakyTests turns flaky results into a failing exit code. --repeat-each and --shuffle (1.64) help reproduce order- and timing-dependent bugs.

Notes

  • Retries restart the worker; beforeAll runs again
  • Serial groups retry from the start of the group
  • testInfo.retry is 0 on the first attempt
  • Traces with 'on-first-retry' capture the failing rerun

Configuration

export default defineConfig({
  retries: process.env.CI ? 2 : 0,
  retryStrategy: 'isolated',          // retries run last, one by one (1.62)
  failOnFlakyTests: !!process.env.CI, // flaky = exit code 1
  use: { trace: 'on-first-retry', video: 'retain-on-failure-and-retries' },
});

test('dashboard loads', async ({ page }, testInfo) => {
  if (testInfo.retry) await page.context().clearCookies();   // extra cleanup on retry
  await page.goto('/dashboard');
});

test.describe.configure({ retries: 3 });          // per-file override

// reproduce flakiness locally
// npx playwright test cart.spec.ts --repeat-each=20 --workers=4
// npx playwright test --shuffle                 (random order, 1.64)
// npx playwright test --shuffle=1234            (replay an order)

Code Explained

retries — attempts after the first
retryStrategy: 'isolated' — less interference
failOnFlakyTests — don't let flakes pass CI
testInfo.retry — branch on retry attempt
--repeat-each — stress one test
--shuffle[=seed] — find order dependencies

⚠ Common Mistakes

  • Treating retries as a fix; flaky tests still hide real race conditions
  • Using retries without traces; you can't see what went wrong in the failed attempt
  • Raising timeouts everywhere instead of finding the one slow wait

✓ Tips & Best Practices

  • Track flaky tests from the HTML/JSON report and fix the top offenders weekly
  • Use --repeat-each=20 locally before declaring a test fixed
  • Set video: 'retain-on-failure-and-retries' (1.61) to see both attempts

Quick Summary

  • retries — re-run failures
  • flaky — passed after retry
  • failOnFlakyTests — strict CI
  • --repeat-each / --shuffle — reproduce flakes
