Waiting on Network Traffic

waitForResponse() · waitForRequest() · on('request') · response.json() · apiResponse.timing() · routeWebSocket()

Observing Requests

Sometimes a test needs to wait for or inspect a specific call: confirm the form actually POSTed, grab an ID from a response, or log failures. Start waitForResponse() before the triggering action. Event listeners (page.on('request' | 'response' | 'requestfailed')) observe everything, and routeWebSocket() mocks or inspects WebSocket traffic.

Notes

  • Match by URL glob, RegExp or predicate on the Response
  • response.ok() is true for 200–299
  • HAR and trace recordings include WebSockets (1.61)
  • page.requests() / consoleMessages() read buffered history

Examples

const saved = page.waitForResponse((r) =>
  r.url().endsWith('/api/orders') && r.request().method() === 'POST');
await page.getByRole('button', { name: 'Place order' }).click();
const res = await saved;
expect(res.status()).toBe(201);
const { id } = await res.json();

const reqPromise = page.waitForRequest('**/api/search?q=*');
await page.getByRole('searchbox').fill('mug');
expect((await reqPromise).url()).toContain('q=mug');

page.on('requestfailed', (r) => console.log('FAILED', r.url()));
page.on('response', (r) => r.status() >= 500 && console.log('5xx', r.url()));

await page.routeWebSocket('wss://example.com/live', (ws) => {
  ws.onMessage((msg) => msg === 'ping' && ws.send('pong'));   // fake server
});

Code Explained

waitForResponse(predicate) — promise before click
res.json() — parsed body
waitForRequest(glob) — inspect outgoing call
on('requestfailed') — log network errors
routeWebSocket — mock a WS server

⚠ Common Mistakes

  • await page.waitForResponse(...) before clicking; it blocks forever
  • Matching only the URL when GET and POST share it; check request().method() too
  • Asserting on a response that the UI hasn't rendered yet; also assert the UI

✓ Tips & Best Practices

  • Use response waits to grab server-generated IDs for later steps
  • Add an auto fixture that fails tests on unexpected 5xx responses
  • Prefer UI assertions; network waits are for data you can't see

Quick Summary

  • waitForResponse() — wait + inspect
  • waitForRequest() — verify outgoing calls
  • page.on('…') — observe all traffic
  • routeWebSocket() — mock WebSockets
