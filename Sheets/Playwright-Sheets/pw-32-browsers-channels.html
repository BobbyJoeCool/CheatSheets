Choosing Browsers

Cross-browser runs are configured as projects, one per browser or device. By default Playwright uses its own Chromium build; set channel to run branded Google Chrome or Microsoft Edge that you install with npx playwright install chrome. Headless Chromium runs the lighter chromium-headless-shell unless you choose channel: 'chromium' for the full new headless mode.

Notes

  • npx playwright test --project=firefox runs one project
  • launchOptions.args passes Chromium flags
  • slowMo slows every action (debugging)
  • connectOverCDP() attaches to an existing Chrome (Chromium only)

playwright.config.ts

import { defineConfig, devices } from '@playwright/test';
export default defineConfig({
  projects: [
    { name: 'chromium', use: { ...devices['Desktop Chrome'] } },
    { name: 'firefox',  use: { ...devices['Desktop Firefox'] } },
    { name: 'webkit',   use: { ...devices['Desktop Safari'] } },
    { name: 'chrome',   use: { ...devices['Desktop Chrome'], channel: 'chrome' } },
    { name: 'edge',     use: { ...devices['Desktop Edge'], channel: 'msedge' } },
    {
      name: 'chromium-debug',
      use: {
        headless: false,
        launchOptions: { slowMo: 250, args: ['--disable-gpu'] },
      },
    },
  ],
});
// attach to a running Chrome started with --remote-debugging-port=9222
// const browser = await chromium.connectOverCDP('http://localhost:9222');

Code Explained

devices[...] — UA, viewport, scale for a browser
channel — branded browser instead of bundled
headless: false — show the window
slowMo — ms pause after each action
connectOverCDP — drive an existing browser

⚠ Common Mistakes

  • Testing only Chromium, then shipping Safari bugs; add a WebKit project
  • Using channel: 'chrome' in CI without npx playwright install chrome
  • Overriding devices fields in the wrong order; spread ...devices[x] first, then overrides

✓ Tips & Best Practices

  • Run all browsers on CI and only Chromium locally for speed
  • Use branded chrome / msedge when testing codecs, DRM or enterprise policies
  • Add a headed slowMo project for demos and debugging

Quick Summary
