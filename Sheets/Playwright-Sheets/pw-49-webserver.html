webServer & baseURL

webServer.command · url · reuseExistingServer · timeout · multiple servers · env · gracefulShutdown

Starting Your App for Tests

The webServer config starts your app (or API, or mock server) before tests and stops it afterwards. Playwright waits until url responds (2xx–4xx) or port accepts connections. Combined with use.baseURL, tests call page.goto('/path') and work against any framework: React, Next.js, Vue, Angular or SvelteKit just differ in the start command and port.

Notes

  • reuseExistingServer: !process.env.CI reuses your local dev server
  • Array form starts several servers (frontend + API)
  • Default startup timeout: 60 s
  • Without gracefulShutdown the process group is SIGKILLed

playwright.config.ts

export default defineConfig({
  use: { baseURL: 'http://localhost:3000' },
  webServer: [
    {
      name: 'api',                                   // log prefix
      command: 'npm run start --workspace=api',
      url: 'http://localhost:4000/health',
      env: { DATABASE_URL: 'postgres://localhost/e2e' },
      reuseExistingServer: !process.env.CI,
    },
    {
      name: 'web',
      command: process.env.CI ? 'npm run build && npm run start' : 'npm run dev',
      url: 'http://localhost:3000',
      timeout: 120_000,                              // slow builds
      gracefulShutdown: { signal: 'SIGTERM', timeout: 5_000 },
      reuseExistingServer: !process.env.CI,
    },
  ],
});

Code Explained

array — several servers, started in order
url — readiness check endpoint
env — server environment variables
CI vs local command — prod build on CI
gracefulShutdown — clean stop

⚠ Common Mistakes

  • Testing against npm run dev in CI; dev servers compile on demand and make tests slow and flaky
  • url pointing at a page that needs auth and returns 401 forever; use a health endpoint
  • Hard-coding ports that differ between dev and preview

✓ Tips & Best Practices

  • Run the production build in CI (build && start/preview)
  • Use a dedicated .env.test for the server via env
  • Use wait: { stdout: /listening on (?<PORT>\d+)/ } for random ports

Quick Summary

  • webServer — boot the app
  • url — readiness probe
  • reuseExistingServer — reuse local server
  • baseURL — relative goto()
