Narrowing Locators

Locators are lazy and chainable: calling a getBy method on a locator searches inside it. filter() keeps matches that contain (or don't contain) text or another locator. and()/or() combine locators, within() (1.64) restricts one locator to another container, and visible() keeps only visible matches. Raw CSS and XPath via page.locator() remain available as a last resort.

Notes

  • Strictness: actions throw if a locator matches more than one element
  • nth()/first()/last() silence strictness but are brittle
  • XPath does not pierce shadow DOM; CSS and getBy* do
  • has locators are relative to the outer element

Examples

const rows = page.getByRole('row');
rows.filter({ hasText: 'Alice' })  // row containing "Alice"
rows.filter({ hasNotText: 'Archived' })
rows.filter({ has: page.getByRole('button', { name: 'Edit' }) })  // contains a button
rows.filter({ hasNot: page.getByText('Paid') })
rows.filter({ hasText: 'Alice' }).getByRole('button', { name: 'Delete' }).click();

page.getByRole('button').and(page.getByTitle('Subscribe'))  // both match
page.getByRole('button', { name: 'New' }).or(page.getByText('Confirm'))  // either
page.getByRole('button', { name: 'Save' }).within(page.getByTestId('settings-dialog'))
page.locator('button').visible().click();  // visible only
rows.first(); rows.last(); rows.nth(2);  // index (0-based)

page.locator('css=.card >> text=Pro')  // legacy chained selector
page.locator('#cart .item:has-text("Mug")')  // CSS + Playwright pseudo-class
page.locator('xpath=//table//tr[2]/td[1]')  // XPath (no shadow DOM)

Code Explained

filter() — narrows by text or inner locator
.getBy…() on a locator — searches inside it
and() / or() — intersect / union
within() — scope to a container (1.64)
nth() — positional, use sparingly
locator() — raw CSS/XPath escape hatch

⚠ Common Mistakes

  • rows.nth(3) to find "Alice's row"; order changes break it, filter by content instead
  • Passing a page-level locator to has that can't be found inside the outer element
  • Copying long auto-generated CSS paths (div > div:nth-child(4) > span) from DevTools

✓ Tips & Best Practices

  • Build locators top-down: container → filter → target role
  • Store reusable container locators in page objects
  • Use or() for "either the dialog or the banner appears" races

Quick Summary

  • filter({ hasText, has }) — narrow by content
  • and / or — combine locators
  • within() — restrict to a container
  • locator('css') — last-resort raw selector
