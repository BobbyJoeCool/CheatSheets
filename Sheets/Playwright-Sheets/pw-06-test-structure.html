Sheet 06

Test Structure

test() · test.describe() · beforeEach · afterEach · beforeAll · afterAll · { page }

Anatomy of a Test File

A test file imports test and expect from @playwright/test. Each test(title, async ({ fixtures }) => {}) gets fresh fixtures, so every test has its own browser context and page. Group tests with test.describe() and share setup with hooks. Tests in a file run in order inside one worker; files run in parallel across workers.

Rules of Thumb

  • Every test is fully isolated: new context, new cookies, new storage
  • beforeAll/afterAll run once per worker, not once per run
  • Hooks can use fixtures: beforeEach(async ({ page }) => …)
  • Titles must be unique within a file (used in reports and -g)

Full Example

import { test, expect } from '@playwright/test';

test.describe('todo list', () => {
  test.beforeEach(async ({ page }) => {
    await page.goto('/todos');                 // runs before each test
  });

  test('adds an item', async ({ page }) => {
    await page.getByPlaceholder('What needs doing?').fill('Buy milk');
    await page.keyboard.press('Enter');
    await expect(page.getByTestId('todo-item')).toHaveText(['Buy milk']);
  });

  test('starts empty', async ({ page }) => {
    await expect(page.getByTestId('todo-item')).toHaveCount(0);
  });

});

Code Explained

test.describe() — named group; nests freely
beforeEach — shared navigation per test
{ page } — destructure only the fixtures you need
testInfo — 2nd argument to tests and hooks

Hooks

HookRuns
test.beforeAllOnce per worker before tests in scope
test.beforeEachBefore every test in scope
test.afterEachAfter every test, pass or fail
test.afterAllOnce per worker after tests in scope

Declaration Forms

FormMeaning
test(title, fn)Basic test
test(title, details, fn)With { tag, annotation }
test.describe(title, fn)Named group
test.describe(fn)Anonymous group (shared hooks)
test.describe.serialOrdered; stop after first failure

⚠ Common Mistakes

  • Sharing a page between tests via a module variable; each test must use its own fixture
  • Using beforeAll to log in for every test, then wondering why parallel workers each log in again
  • Forgetting await on actions; the test ends before the action runs and fails mysteriously

✓ Tips & Best Practices

  • Keep tests independent so they can run in any order and in parallel
  • Put navigation in beforeEach, not in every test body
  • Prefer fixtures over beforeAll for shared expensive resources

Quick Summary

  • test() — one isolated scenario
  • test.describe() — grouping + shared hooks
  • beforeEach/afterEach — per-test setup/teardown
  • beforeAll/afterAll — per-worker setup/teardown
