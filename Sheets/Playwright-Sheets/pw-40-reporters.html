Reporters

Reporting Results

Reporters turn test events into output. Terminal reporters (list, line, dot) show progress; file reporters (html, json, junit, blob) feed CI and dashboards. You can use several at once. The HTML report includes traces, screenshots, videos and attachments, and is opened with npx playwright show-report. Custom reporters implement the Reporter interface.

Notes

  • Default: list locally, dot on CI
  • --add-reporter (1.63) adds to config reporters instead of replacing
  • HTML open: 'always' | 'never' | 'on-failure'
  • PLAYWRIGHT_JUNIT_OUTPUT_FILE / PLAYWRIGHT_JSON_OUTPUT_FILE set paths

Configuration

export default defineConfig({
  reporter: [
    ['list'],
    ['html', { open: 'never', outputFolder: 'playwright-report' }],
    ['junit', { outputFile: 'results/junit.xml' }],
    ['./reporters/slack-reporter.ts', { channel: '#qa' }],
  ],
});

// reporters/slack-reporter.ts
import type { Reporter, TestCase, TestResult, FullResult }
  from '@playwright/test/reporter';
export default class SlackReporter implements Reporter {
  failed = 0;
  onTestEnd(test: TestCase, r: TestResult) { if (r.status === 'failed') this.failed++; }
  async onEnd(r: FullResult) { console.log(`Run ${r.status}: ${this.failed} failed`); }
}
// npx playwright test --reporter=dot --add-reporter=junit

Code Explained

array form — several reporters at once
options per reporter — paths, open behaviour
path string — your own reporter module
onTestEnd / onEnd — reporter hooks

Reporter Hooks

HookCalled
onBegin(config, suite)Run starts
onTestBegin(test)Test starts
onStepBegin/EndEach step
onTestEnd(test, result)Test finishes
onError(error)Global error
onEnd(result)Run finishes

⚠ Common Mistakes

  • Using --reporter=junit and losing the HTML report from config; use --add-reporter
  • Leaving HTML open at default on CI; it tries to serve the report and blocks
  • Writing JUnit to a path your CI doesn't collect

✓ Tips & Best Practices

  • On CI use blob + github, merge to html in a final job
  • Upload playwright-report/ as an artifact; it's self-contained
  • Use omitTags/title options to keep reports readable

Quick Summary

  • list / dot / line — terminal
  • html — rich interactive report
  • junit / json / blob — CI integration
  • Reporter interface — custom output
