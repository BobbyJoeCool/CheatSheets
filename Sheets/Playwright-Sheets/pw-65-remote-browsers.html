launchServer() · connect() · wsEndpoint · Azure Playwright Workspaces · @azure/playwright · BrowserStack/LambdaTest

Running Browsers Elsewhere

Tests can drive browsers on another machine: a Playwright browser server (launchServer() / run-server) exposes a WebSocket endpoint that connect() or use.connectOptions attaches to. Cloud services build on this. Azure Playwright Workspaces (Azure App Testing, formerly Microsoft Playwright Testing) runs dozens of cloud browsers in parallel while your tests still run in your CI.

Notes

  • Client and server Playwright versions must match (major.minor)
  • exposeNetwork: '<loopback>' lets cloud browsers reach your localhost app
  • connectOverCDP is for existing Chrome, not Playwright servers
  • Vendors (BrowserStack, LambdaTest, Sauce) offer SDKs or WS endpoints

Self-Hosted Server + Azure

// server.ts — on the remote machine
import { chromium } from 'playwright';
const server = await chromium.launchServer({ port: 4444, host: '0.0.0.0' });
console.log(server.wsEndpoint());                  // ws://host:4444/<guid>

// playwright.config.ts — connect every test
use: {
  connectOptions: { wsEndpoint: process.env.PW_WS!, exposeNetwork: '<loopback>' },
},

// Azure Playwright Workspaces: npm init @azure/playwright@latest
// playwright.service.config.ts
import { defineConfig } from '@playwright/test';
import { createAzurePlaywrightConfig, ServiceOS } from '@azure/playwright';
import { DefaultAzureCredential } from '@azure/identity';
import config from './playwright.config';
export default defineConfig(config, createAzurePlaywrightConfig(config, {
  os: ServiceOS.LINUX,
  exposeNetwork: '<loopback>',
  credential: new DefaultAzureCredential(),
}));
// PLAYWRIGHT_SERVICE_URL=wss://… \
//   npx playwright test -c playwright.service.config.ts --workers=20

Code Explained

launchServer() — expose a browser over WS
connectOptions — runner connects instead of launching
exposeNetwork — tunnel to local app
createAzurePlaywrightConfig — cloud browsers
--workers=20 — parallelism beyond your CPU

⚠ Common Mistakes

  • Mismatched client/server versions; the protocol handshake fails
  • Forgetting exposeNetwork; cloud browsers can't reach localhost:3000
  • Committing service tokens; use CI secrets or Entra ID credentials

✓ Tips & Best Practices

  • Start with local workers; move to cloud browsers when CI time hurts
  • Keep traces on in cloud runs; they're downloaded to your report
  • Use run-server in Docker to fix cross-OS screenshot diffs
