Playwright as a Library

The playwright package exposes the browser API without the test runner: no fixtures, no retries, no reports. Use it for scripts, scraping, PDF generation, screenshots in back-end services, or to embed Playwright in another framework. You manage the lifecycle yourself; since 1.59 many objects are async disposables, so await using closes them automatically.

Notes

  • npm i playwright (downloads browsers) or playwright-core (doesn't)
  • expect web-first assertions come from @playwright/test
  • launchPersistentContext() keeps a real profile on disk
  • PDF generation: Chromium only (page.pdf())

Script

import { chromium, devices } from 'playwright';

await using browser = await chromium.launch({ headless: true });      // auto-close
await using context = await browser.newContext({ ...devices['Desktop Chrome'] });
const page = await context.newPage();

await page.goto('https://news.ycombinator.com');
const titles = await page.locator('.titleline > a').allTextContents();
console.log(titles.slice(0, 5));

await page.pdf({ path: 'front-page.pdf', format: 'A4' });            // Chromium only
await page.screenshot({ path: 'front-page.png', fullPage: true });

// persistent profile (extensions, logged-in sessions)
const ctx = await chromium.launchPersistentContext('./profile', { headless: false });
await ctx.close();

Code Explained

chromium.launch() — start a browser
await using — dispose at scope end (1.59)
allTextContents() — scrape a list
page.pdf() — print to PDF
launchPersistentContext — real user-data dir

⚠ Common Mistakes

  • Forgetting browser.close() without await using; Node never exits
  • Rebuilding a test runner on top of the library; use @playwright/test
  • Scraping sites against their terms or robots rules; check before automating

✓ Tips & Best Practices

  • Use playwright-core in Docker images that already ship browsers
  • Reuse one browser and create a context per job in services
  • Add context.tracing for debugging scripts too
