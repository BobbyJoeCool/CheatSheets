Running in GitHub Actions

npm init playwright can generate .github/workflows/playwright.yml. The essentials: install dependencies, install browsers with OS deps, run tests, and always upload the report so failures can be inspected. For large suites, a matrix of shards writes blob reports that a final job merges into one HTML report.

Notes

  • if: ${{ !cancelled() }} uploads reports even when tests fail
  • Set CI=true (Actions does) so config picks CI settings
  • The github reporter adds failure annotations to PRs
  • Alternatively run jobs in the Playwright container image

.github/workflows/playwright.yml (sharded)

name: Playwright Tests
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    timeout-minutes: 60
    strategy: { fail-fast: false, matrix: { shard: [1/4, 2/4, 3/4, 4/4] } }
    steps:
      - uses: actions/checkout@v5
      - uses: actions/setup-node@v5
        with: { node-version: lts/*, cache: npm }
      - run: npm ci
      - run: npx playwright install --with-deps
      - run: npx playwright test --shard=${{ matrix.shard }}
      - uses: actions/upload-artifact@v4
        if: ${{ !cancelled() }}
        with: { name: "blob-${{ strategy.job-index }}", path: blob-report }
  merge:
    if: ${{ !cancelled() }}
    needs: [test]
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - uses: actions/setup-node@v5
      - run: npm ci
      - uses: actions/download-artifact@v4
        with: { path: all-blob-reports, pattern: blob-*, merge-multiple: true }
      - run: npx playwright merge-reports --reporter html ./all-blob-reports
      - uses: actions/upload-artifact@v4
        with: { name: html-report, path: playwright-report, retention-days: 14 }

Code Explained

matrix shard — 4 parallel machines
fail-fast: false — let all shards finish
--with-deps — Linux packages for browsers
blob artifact per shard
merge job — one combined HTML report
!cancelled() — run even after failures

⚠ Common Mistakes

  • Uploading playwright-report only on success; you lose the report when you need it most
  • Sharding without reporter: 'blob' on CI; there's nothing to merge
  • Caching ~/.cache/ms-playwright with a key that ignores the Playwright version

✓ Tips & Best Practices

  • Use reporter: process.env.CI ? 'blob' : 'html' in config
  • Run a quick --only-changed=origin/main job on PRs, full suite on main
  • Download html-report and run npx playwright show-report locally

Quick Summary

  • install --with-deps — CI browsers
  • matrix --shard — parallel machines
  • blob → merge-reports — one report
  • upload artifacts with !cancelled()
