Sheet 09

Parameterized Tests

for…of test loops · data files · project-level options · test.use() · describe.configure({ mode })

Data-Driven Tests

Playwright has no special parameterize API: you generate tests with plain loops at declaration time. Each generated test needs a unique title. For values that should vary per run (locale, user role, environment), declare a fixture option and set it per project or with test.use(), so the same test runs under several configurations.

Notes

  • Loops must run at module load, not inside a test
  • Data can come from JSON/CSV read synchronously at the top of the file
  • test.use() applies to a file or describe block
  • Parallel mode lets generated tests in one file run concurrently

Loop + Data File

import { test, expect } from '@playwright/test';
import users from './data/users.json';            // [{ name, role, canDelete }]

test.describe.configure({ mode: 'parallel' });

for (const { name, role, canDelete } of users) {
  test(`${role} sees correct actions (${name})`, async ({ page }) => {
    await page.goto(`/login-as/${name}`);
    const del = page.getByRole('button', { name: 'Delete' });
    if (canDelete) await expect(del).toBeVisible();
    else await expect(del).toBeHidden();
  });
}

test.describe('German UI', () => {
  test.use({ locale: 'de-DE', timezoneId: 'Europe/Berlin' });
  test('greeting', async ({ page }) => { /* runs with de-DE */ });
});

Code Explained

for…of — one test per row
Template literal title — keeps titles unique
mode: 'parallel' — rows run concurrently
test.use() — override options for a block

Project-Level Parameter

// fixtures.ts
export const test = base.extend<{ tier: 'free' | 'pro' }>({
  tier: ['free', { option: true }],
});
// playwright.config.ts
projects: [
  { name: 'free', use: { tier: 'free' } },
  { name: 'pro',  use: { tier: 'pro' } },
],

Code Explained

{ option: true } — settable from config
Each project runs the whole suite with its value
Tests read it like any fixture: ({ tier })

⚠ Common Mistakes

  • Building tests inside beforeAll or an async function; tests must be declared synchronously
  • Duplicate titles from loops; Playwright errors on duplicates
  • Reading data with await fetch() at the top of the file; declaration must be synchronous

✓ Tips & Best Practices

  • Put the parameter in the title so failures are self-explanatory
  • Use options + projects for cross-cutting variants (roles, tiers, locales)
  • Use test.describe per data row when each row has several tests

Quick Summary

  • for…of — generate tests from data
  • test.use() — override options per block
  • { option: true } — project-configurable fixture
  • mode: 'parallel' — run rows concurrently
