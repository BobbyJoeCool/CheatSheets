Sheet 18

Web-First Locator Assertions

toBeVisible · toHaveText · toContainText · toHaveValue · toBeEnabled · toHaveCount · toHaveAttribute · toHaveCSS

Auto-Retrying Assertions

Web-first assertions take a locator and retry until the condition holds or the expect timeout (5 s default) runs out. They are async, so they must be awaited. This makes them the right tool for UI state: never read a value with textContent() and compare it with a plain expect, which checks once and races the page.

Notes

  • Negate with .not: expect(l).not.toBeVisible()
  • Per-call timeout: toBeVisible({ timeout: 10_000 })
  • toHaveText = full match; toContainText = substring
  • Arrays check lists in order: toHaveText(['a', 'b'])

Examples

const toast = page.getByRole('status');
await expect(toast).toBeVisible();
await expect(toast).toHaveText('Saved');               // exact (normalized)
await expect(toast).toContainText('Sav');
await expect(page.getByRole('listitem')).toHaveCount(3);
await expect(page.getByRole('listitem')).toHaveText(['One', 'Two', 'Three']);
await expect(page.getByLabel('Email')).toHaveValue('ada@example.com');
await expect(page.getByRole('button', { name: 'Pay' })).toBeEnabled();
await expect(page.getByRole('link')).toHaveAttribute('href', '/docs');
await expect(page.getByTestId('card')).toHaveClass(/selected/);
await expect(page.getByTestId('banner')).toHaveCSS('color', 'rgb(255, 0, 0)');
await expect(page.getByTestId('ok')).toHaveCSS('content', '"✓"',
  { pseudo: 'before' });
await expect(page.getByRole('dialog')).not.toBeVisible();   // or toBeHidden()
await expect(page.getByRole('button')).toHaveAccessibleName('Close');

Code Explained

await expect(locator) — retries until pass/timeout
text matchers — string, RegExp or array
toHaveAttribute — name + optional value
pseudo — check ::before/::after (1.60)
.not — waits for the opposite state

⚠ Common Mistakes

  • expect(await l.textContent()).toBe('Saved'); reads once and races, use await expect(l).toHaveText('Saved')
  • Forgetting await before expect(locator); the assertion never runs
  • toHaveText('Sav') expecting a substring; it's a full match, use toContainText

✓ Tips & Best Practices

  • Assert the outcome users see (toast, URL, heading), not internal state
  • Raise the timeout on the one slow assertion, not globally
  • Use array forms to check list order in one assertion

Quick Summary

  • await expect(locator).toX() — auto-retrying
  • toHaveText / toContainText — full / partial text
  • toHaveCount — list size
  • .not — negate with retry
