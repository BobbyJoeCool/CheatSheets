Annotations & Tags

test.skip · test.fixme · test.fail · test.slow · test.only · { tag: '@smoke' } · --grep / -G

Annotations and Tags

Annotations change how a test is treated: skipped, expected to fail, given more time, or focused. They can be static (test.skip('title', …)) or conditional inside the test (test.skip(browserName === 'webkit', 'reason')). Tags are labels such as @smoke that you filter on with --grep. Both appear in the HTML report.

Notes

  • Tags must start with @
  • Tags can also be written in the title: 'login @smoke'
  • test.only + forbidOnly: !!process.env.CI blocks accidental commits
  • test.slow() triples the timeout

Examples

test('checkout', { tag: ['@smoke', '@payments'] }, async ({ page }) => {});

test.describe('admin', { tag: '@admin' }, () => {
  test('bulk delete', async ({ page }) => { /* inherits @admin */ });
});

test('mobile menu', async ({ page, isMobile }) => {
  test.skip(!isMobile, 'Only relevant on mobile viewports');
  test.slow();                                     // 3× timeout
});

test.fixme('known broken export', async ({ page }) => { /* not run */ });
test.fail('bug #412 still open', async ({ page }) => { /* must fail */ });

test('issue link', {
  annotation: { type: 'issue', description: 'https://github.com/org/app/issues/9' },
}, async ({ page }) => { /* shown in report */ });

Code Explained

{ tag } — string or array; inherited by nested tests
test.skip(cond, why) — runtime skip
test.fixme — skip and mark as needing work
test.fail — passes only if it fails
annotation — custom { type, description }

Annotations

CallEffect
test.skip()Not run; reported as skipped
test.fixme()Not run; marked "fixme"
test.fail()Inverts pass/fail
test.slow()Timeout × 3
test.only()Run only focused tests

Filtering by Tag

CommandSelects
--grep @smokeTests tagged @smoke
-g "@smoke|@fast"Either tag (regex)
--grep-invert @slowEverything except @slow
-G @slowShort form of --grep-invert
--grep "(?=.*@a)(?=.*@b)"Both tags

⚠ Common Mistakes

  • Committing test.only; CI runs one test and goes green
  • Using test.fail() for flaky tests; it hides real regressions when the bug is fixed
  • Writing tags without @; Playwright rejects them

✓ Tips & Best Practices

  • Set forbidOnly: !!process.env.CI in config
  • Always give skip/fixme a reason string so the report explains itself
  • Use project-level grep to make a "smoke" project that runs only @smoke

Quick Summary

  • skip / fixme — don't run
  • fail — expect failure
  • slow — 3× timeout
  • { tag: '@x' } + --grep — label and filter
