Test Framework Integrations

Microsoft.Playwright.NUnit, .MSTest and .Xunit provide base classes (PageTest, ContextTest, BrowserTest) that create isolated browser contexts per test and expose Page, Context and Expect(). Override ContextOptions() for context settings, and configure browser, headless mode and timeouts in a .runsettings file or with environment variables.

Notes

  • NUnit: [Parallelizable(ParallelScope.Self)] for parallel fixtures
  • xUnit: Microsoft.Playwright.Xunit (v3: .Xunit.v3)
  • BROWSER=webkit dotnet test switches engine

NUnit Test + .runsettings

using System.Text.RegularExpressions;
using Microsoft.Playwright;
using Microsoft.Playwright.NUnit;

[Parallelizable(ParallelScope.Self)]
public class CheckoutTests : PageTest
{
    public override BrowserNewContextOptions ContextOptions() => new()
    {
        BaseURL = "http://localhost:3000",
    };

    [Test]
    public async Task AddsItemToCart()
    {
        await Page.GotoAsync("/products");
        await Page.GetByRole(AriaRole.Button, new() { Name = "Add to cart" })
                  .First.ClickAsync();
        await Expect(Page.GetByTestId("cart-count")).ToHaveTextAsync("1");
    }
}
// dotnet test --settings test.runsettings   (BrowserName, Headless, ExpectTimeout)

Code Explained

PageTest — fresh context + Page per test
ContextOptions() — BaseURL, locale, color scheme
Page / Expect — inherited members
.First — property in .NET
.runsettings — browser, headless, timeouts

⚠ Common Mistakes

  • Creating Playwright manually inside a PageTest; the base class already manages it
  • Forgetting [Parallelizable]; NUnit runs fixtures sequentially by default
  • Hard-coding absolute URLs instead of BaseURL in ContextOptions()

✓ Tips & Best Practices

  • Keep separate .runsettings files for local (headed) and CI
  • Use Context.Tracing.StartAsync in [SetUp] for traces on failure
  • Generate tests with codegen --target csharp-nunit or csharp-mstest
