Writing Stories and Component Tests

A story is a tiny wrapper that sets up one scenario with fixed props, mock data, context providers or recorded callbacks. Each named export is one story; its ID is the file path under src/ without .story plus the export name, e.g. components/Button/Primary. Tests call mount(id) and use normal locators and assertions on the returned root Locator.

Notes

  • Unique suffixes work as IDs: Button/Primary
  • mount<typeof Story>(…) type-checks props against the story
  • component.update(props) re-renders without remounting
  • Unknown story or render error → mount() throws

src/components/Button.story.tsx

import { Button } from './Button';
import { ThemeProvider } from '../theme';

export const Primary = () => <Button title="Submit" />;
export const Disabled = () => <Button title="Submit" disabled />;
export const Dark = () => (
  <ThemeProvider mode="dark"><Button title="Submit" /></ThemeProvider>
);

// record callbacks on window so tests can read them
const w = window as any;
export const Clickable = () => (
  <Button title="Go" onClick={() => { w.clicks = (w.clicks ?? 0) + 1; }} />
);

Story Patterns

one export = one scenario
providers wrap the component
callbacks stored on window for assertions

tests/components/button.spec.ts

import { test, expect } from '@playwright/test';

test('renders primary button', async ({ mount }) => {
  const component = await mount('components/Button/Primary');
  await expect(component.getByRole('button')).toHaveText('Submit');
});

test('click fires onClick', async ({ mount, page }) => {
  const component = await mount('Button/Clickable');            // suffix id
  await component.getByRole('button').click();
  expect(await page.evaluate(() => (window as any).clicks)).toBe(1);
});

Test Patterns

mount(id) — Locator for the root
suffix IDs — shorter when unique
page.evaluate — read recorded callbacks
toHaveScreenshot works per component

⚠ Common Mistakes

  • Passing JSX to mount() like the old experimental API; pass a story ID
  • Putting test logic in stories; stories set up state, tests act and assert
  • Two stories with the same suffix and using the short ID; the lookup is ambiguous

✓ Tips & Best Practices

  • Co-locate *.story.tsx with the component it covers
  • Add visual checks: await expect(component).toHaveScreenshot()
  • Reuse stories in Storybook-like tools for documentation

Quick Summary

  • *.story.tsx — named export per scenario
  • story ID — path under src + export
  • mount(id) — root Locator
  • update(props) — re-render in place
