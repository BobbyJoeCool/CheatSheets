Auto-Waiting & Timeouts

actionability checks · test timeout · expect timeout · actionTimeout · navigationTimeout · signal (AbortSignal) · timeout: 0

How Waiting Works

Playwright waits in three places: actions wait for actionability, web-first assertions retry until they pass, and navigation waits for a load state. Each wait is bounded by a timeout. Since 1.62 you can also cancel actions and assertions with an AbortSignal, and timeout: 0 disables the default for that call. Hard sleeps (waitForTimeout) are almost never needed.

Default Timeouts

  • Test: 30 s (includes hooks and fixtures)
  • Expect: 5 s per assertion
  • Action / navigation: no limit (bounded by test timeout)
  • Global run: unlimited (globalTimeout)

Configuring Timeouts

// playwright.config.ts
export default defineConfig({
  timeout: 60_000,                       // per test
  globalTimeout: 30 * 60_000,            // whole run (CI safety net)
  expect: { timeout: 10_000 },           // per assertion
  use: { actionTimeout: 15_000, navigationTimeout: 30_000 },
});

// per test / per call
test('big export', async ({ page }) => {
  test.setTimeout(120_000);              // or test.slow() → 3×
  await page.getByRole('button', { name: 'Export' }).click({ timeout: 5_000 });
  await expect(page.getByText('Ready')).toBeVisible({ timeout: 60_000 });

  const ctrl = new AbortController();
  setTimeout(() => ctrl.abort(), 2_000);
  await page.getByText('Maybe').click({ signal: ctrl.signal, timeout: 0 });  // 1.62
});

Code Explained

timeout — whole test incl. hooks
expect.timeout — each assertion
actionTimeout — each click/fill
setTimeout() / slow() — per-test override
signal — cancel externally (1.62)

⚠ Common Mistakes

  • Raising the global timeout to hide one slow page; fix or test.slow() that test
  • waitForTimeout(3000) sleeps; they slow every run and still flake
  • Setting actionTimeout higher than the test timeout; the test times out first

✓ Tips & Best Practices

  • Set globalTimeout in CI so a hung run fails instead of burning minutes
  • Read "Timeout 5000ms exceeded" errors: they say which assertion and what was received
  • Prefer assertions over waitFor(); they explain failures better

Quick Summary

  • auto-wait — actions + assertions wait
  • timeout / expect.timeout — test vs assertion
  • test.slow() — 3× for one test
  • signal — cancel any action (1.62)
