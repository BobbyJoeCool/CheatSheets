Page Object Model

class with Locator fields · constructor(page) · action methods · fixtures for POMs · component objects

Page Objects

A page object wraps one page (or component) behind a small class: locators are fields created in the constructor, and user actions are methods. Tests then read like specs, and a markup change is fixed in one place. In Playwright, locators are lazy, so defining them up front costs nothing; expose page objects to tests through fixtures.

Guidelines

  • Keep assertions in tests, not in page objects (mostly)
  • Methods model user intent: addItem(), not clickPlus()
  • Return other page objects on navigation for fluent flows
  • Component objects (header, modal) can be shared by pages

LoginPage + Fixture

// pages/LoginPage.ts
import { type Page, type Locator, expect } from '@playwright/test';
export class LoginPage {
  readonly email: Locator;
  readonly password: Locator;
  readonly submit: Locator;
  constructor(readonly page: Page) {
    this.email = page.getByLabel('Email');
    this.password = page.getByLabel('Password');
    this.submit = page.getByRole('button', { name: 'Sign in' });
  }
  async goto() { await this.page.goto('/login'); }
  async login(email: string, pw: string) {
    await this.email.fill(email);
    await this.password.fill(pw);
    await this.submit.click();
  }
}
// fixtures.ts
export const test = base.extend<{ loginPage: LoginPage }>({
  loginPage: async ({ page }, use) => { await use(new LoginPage(page)); },
});

Code Explained

readonly locator fields — defined once, resolved lazily
constructor(page) — receives the test's page
login() — intent-level action
fixture — tests get loginPage ready-made

Test Using It

test('valid login', async ({ loginPage, page }) => {
  await loginPage.goto();
  await loginPage.login('ada@example.com', 's3cret');
  await expect(page.getByRole('heading', { name: 'Dashboard' })).toBeVisible();
});

Why Fixtures?

No new LoginPage(page) in every test
Fixtures can pre-navigate or seed data

⚠ Common Mistakes

  • Storing element handles ($()) instead of locators; handles go stale after re-render
  • Giant "god" page objects for the whole app; split by page and component
  • Hiding every assertion inside page objects; failures lose context

✓ Tips & Best Practices

  • Wrap page-object methods in test.step() for readable reports
  • Use getByRole-based locators in page objects; they survive redesigns
  • Generate first drafts with codegen, then refactor into page objects

Quick Summary

  • class XPage — locators + actions
