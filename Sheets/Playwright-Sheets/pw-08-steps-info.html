Steps and TestInfo

test.step() groups actions into named steps that show up in the HTML report, trace viewer and UI mode, turning a long test into a readable story. Steps can return values and nest. testInfo (or test.info()) exposes the running test's metadata and lets you attach files, add annotations and get per-test output paths.

Notes

  • box: true reports failures at the step call site, not inside it
  • subtitle and params (1.63) add detail in reports/trace
  • timeout option fails a step that hangs
  • test.abort(message?) fails the test immediately (fixtures, hooks, route handlers)

Steps, Attachments, Abort

test('purchase', async ({ page }) => {
  const orderId = await test.step('place order', async () => {
    await page.getByRole('button', { name: 'Buy' }).click();
    return page.getByTestId('order-id').textContent();   // step returns a value
  });

  await test.step('verify email', async () => {
    /* … */
  }, { box: true, timeout: 10_000, subtitle: `order ${orderId}` });

  const info = test.info();
  await info.attach('order', { body: JSON.stringify({ orderId }),
                               contentType: 'application/json' });
  await page.screenshot({ path: info.outputPath('s.png') });
  await info.attach('screen', { path: info.outputPath('s.png') });
  info.annotations.push({ type: 'order', description: String(orderId) });
});

// in a route handler or fixture:
// if (!process.env.API_KEY) test.abort('API_KEY not set');

Code Explained

test.step(title, fn, opts) — named, nestable
return — value flows out of the step
attach(name, { body | path }) — shows in report
outputPath() — unique per-test file path
annotations.push() — runtime annotation

Step Options

OptionEffect
boxErrors point at the step call
timeoutFail if the step runs longer

test.step.skipDeclare a skipped step

⚠ Common Mistakes

  • Calling test.info() at module level; it throws outside a running test
  • Attaching huge files on every run; attach only on failure or when useful
  • Writing artifacts to fixed paths; parallel tests overwrite each other, use outputPath()

✓ Tips & Best Practices

  • Wrap page-object methods in test.step so reports read like specs
  • Use box: true on helper steps so errors point at the caller
  • Check testInfo.retry > 0 to add extra diagnostics only on retries

Quick Summary

  • test.step() — readable, reportable steps
  • testInfo.attach() — files in the report
  • outputPath() — collision-free artifact paths
  • test.abort() — fail fast from fixtures/handlers
