Accessibility & ARIA Snapshots

Automated Accessibility Checks

Two complementary tools: axe-core (via @axe-core/playwright) scans the page for WCAG rule violations such as missing labels and low contrast, and ARIA snapshots assert the accessibility tree's structure as YAML. Axe finds rule breaks; ARIA snapshots catch regressions in what screen readers announce.

Notes

  • npm i -D @axe-core/playwright
  • Automated tools catch roughly a third of issues; still test manually
  • page.ariaSnapshot() and toMatchAriaSnapshot on page (1.60)
  • Snapshot text supports RegExp: - heading /Order #\d+/

Examples

import AxeBuilder from '@axe-core/playwright';

test('checkout has no WCAG A/AA violations', async ({ page }) => {
  await page.goto('/checkout');
  const results = await new AxeBuilder({ page })
    .withTags(['wcag2a', 'wcag2aa', 'wcag21aa'])
    .exclude('#third-party-chat')
    .analyze();
  expect(results.violations).toEqual([]);
});

test('nav structure', async ({ page }) => {
  await page.goto('/');
  await expect(page.getByRole('navigation')).toMatchAriaSnapshot(`
    - navigation:
      - link "Home"
      - link "Pricing"
      - link /Docs/:
        - /url: /docs
  `);
});

Code Explained

AxeBuilder({ page }) — scan current page
withTags — limit to WCAG levels
exclude — skip regions you don't own
violations — array of failed rules
toMatchAriaSnapshot — YAML template of roles + names

ARIA Snapshot Syntax

LineMatches
- heading "Title" [level=1]Role, name, attribute
- link /Docs/RegExp name
- checkbox [checked]State
- /url: /docsLink target property

AxeBuilder Methods

MethodPurpose
include(sel) / exclude(sel)Scope
withTags([...])Rule tags
withRules([...])Only these rules
disableRules([...])Skip rules
analyze()Run, return results

⚠ Common Mistakes

  • Expecting violations to be [] on a legacy app; baseline known issues with disableRules first
  • Scanning before the page renders; wait for a key element first
  • Over-specifying ARIA snapshots; include only the structure that matters

✓ Tips & Best Practices

  • Wrap AxeBuilder in a fixture with your team's tags and exclusions
  • Attach results JSON with testInfo.attach for triage
  • Generate ARIA templates with codegen's "Assert snapshot" or --update-snapshots

Quick Summary

  • AxeBuilder.analyze() — WCAG rule scan
  • withTags — choose standards
  • toMatchAriaSnapshot — tree regression check
  • ariaSnapshot() — dump the tree
