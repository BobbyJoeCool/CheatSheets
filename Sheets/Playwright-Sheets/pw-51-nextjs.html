Testing Next.js

Next.js renders on the server, so page.route() only intercepts browser requests; server-side fetch in Server Components and Server Actions never reaches it. Test the real production server (next build && next start), seed data through APIs or the database, and use the request fixture for Route Handlers. Next's experimental test mode can mock server-side fetches when you need it.

Notes

  • npx create-next-app@latest --example with-playwright
  • Server Actions are tested through the UI form that calls them
  • proxy.ts (formerly middleware) runs on every request; test redirects with toHaveURL
  • NEXT_PUBLIC_* vars are baked in at build time

Config + Tests

// playwright.config.ts
webServer: {
  command: 'npm run build && npm run start',
  url: 'http://localhost:3000',
  reuseExistingServer: !process.env.CI,
},

test('server action creates a post', async ({ page }) => {
  await page.goto('/posts/new');
  await page.getByLabel('Title').fill('Hello');
  await page.getByRole('button', { name: 'Publish' }).click();   // form action
  await expect(page).toHaveURL(/\/posts\/\d+/);                 // redirect()
  await expect(page.getByRole('heading', { name: 'Hello' })).toBeVisible();
});
test('route handler returns JSON', async ({ request }) => {
  const res = await request.get('/api/health');                 // app/api/health/route.ts
  await expect(res).toBeOK();
});
test('proxy redirects anonymous users', async ({ page }) => {
  await page.goto('/dashboard');
  await expect(page).toHaveURL('/login?from=%2Fdashboard');
});

Code Explained

production server — realistic caching and rendering
form + toHaveURL — covers the Server Action end-to-end
request — Route Handlers directly
proxy.ts — auth redirects

⚠ Common Mistakes

  • Mocking /api/* with page.route() and expecting Server Components to see the mock
  • Running tests against next dev in CI; on-demand compilation causes timeouts
  • Forgetting to rebuild after changing NEXT_PUBLIC_* values

✓ Tips & Best Practices

  • Use a separate test database and reset it in a setup project
  • Assert visible results of Server Actions, not network calls
  • Use the with-playwright example as a starting template
