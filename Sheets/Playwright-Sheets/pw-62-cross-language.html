One API, Four Languages

All bindings wrap the same engine and share concepts, defaults and behaviour. Only naming and option syntax change: camelCase with object literals (TS), snake_case with keyword args (Python), camelCase with option builders (Java) and PascalCaseAsync with new() { } initialisers (C#). Use this table to translate examples from the docs.

Notes

  • Only TS has the full @playwright/test runner features (projects, UI mode, sharding)
  • Python/Java/.NET use pytest, JUnit/TestNG, NUnit/MSTest/xUnit
  • Trace viewer, codegen and Inspector work for all
  • Versions are released in lockstep

⚠ Common Mistakes

  • Copying TS option objects into Java/C#; each language has its own options syntax
  • Expecting projects, webServer or UI mode in Python/Java/.NET; they're TS-runner features
  • Calling first() as a method in Python/C#; it's a property there

✓ Tips & Best Practices

  • Switch the docs language selector on playwright.dev to see every example in your language
  • Use codegen with the right --target to learn idioms quickly
  • Keep locator strategies identical across language suites

Quick Summary

  • TS — camelCase + objects
  • Python — snake_case + kwargs
  • Java — builders + assertThat
  • C# — Async + new() { }
