Post-Mortem Debugging with Traces

A trace is a zip file holding every action, DOM snapshots before and after, screenshots, network (including WebSockets since 1.61), console logs and source. Record traces in CI and open them with npx playwright show-trace, from the HTML report, or by dropping the file onto trace.playwright.dev (runs locally in your browser). Since 1.59, npx playwright trace offers CLI subcommands for agents and scripts.

Notes

  • 'on-first-retry' is the recommended CI setting
  • Traces add overhead; avoid 'on' for the full suite
  • snapshots: { dom, aria, screen } controls captured detail (1.63)
  • Library mode: context.tracing.start() / stop({ path })

Recording and Opening

// playwright.config.ts
use: { trace: 'on-first-retry' },              // or 'retain-on-failure'

// CLI override for one run
// npx playwright test --trace on

// library / manual
await context.tracing.start({ screenshots: true, snapshots: true, sources: true });
await page.goto('/');
await context.tracing.stop({ path: 'trace.zip' });

// opening
// npx playwright show-trace test-results/cart-chromium-retry1/trace.zip
// npx playwright show-report   → click the trace icon
// npx playwright trace open trace.zip       (1.59 CLI subcommands)
// npx playwright trace actions              → list actions
// npx playwright trace snapshot <action-id> → dump a DOM snapshot

Code Explained

trace option — when to record
--trace on — force for one run
tracing.start/stop — manual control
show-trace — open viewer
trace … subcommands — scriptable access

trace Modes

ModeRecords
offNothing
onEvery test (slow)
on-first-retryOnly the first retry
on-all-retriesEvery retry
retain-on-failureAll, keep failures only
retain-on-first-failureKeep first failure only

⚠ Common Mistakes

  • trace: 'on' in CI for thousands of tests; huge artifacts and slower runs
  • Uploading traces with real user data to public places; traces contain everything the page saw
  • Looking only at the final screenshot; the "before" snapshot of the failing action usually shows the cause

✓ Tips & Best Practices

  • Upload test-results/ as a CI artifact so traces survive the job
  • Use the Log tab to see what auto-wait was waiting for
  • Share traces via trace.playwright.dev; nothing is uploaded to a server

Quick Summary

  • trace: 'on-first-retry' — CI default
  • show-trace / HTML report — open traces
  • trace.playwright.dev — browser-only viewer
  • npx playwright trace — CLI access
