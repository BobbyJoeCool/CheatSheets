Project Structure

playwright.config.ts · tests/ · tests-examples/ · test-results/ · playwright-report/ · .gitignore

Project Layout

A Playwright project is driven by playwright.config.ts at the root. Test files live under testDir (default ./tests) and are matched by testMatch (**/*.@(spec|test).?(c|m)[jt]s?(x)). Each run writes artifacts (traces, screenshots, videos) to test-results/ and the HTML report to playwright-report/; both are disposable and belong in .gitignore.

Notes

  • testDir is resolved relative to the config file
  • Helpers, fixtures and page objects can live anywhere; only matched files run as tests
  • outputDir (default test-results) is wiped at the start of each run
  • playwright/.auth/ is the conventional home for saved login state

Typical Layout

my-app/
├── playwright.config.ts      # runner configuration
├── package.json              # "test:e2e": "playwright test"
├── tests/
│   ├── auth.setup.ts         # setup project (login once)
│   ├── home.spec.ts          # test file
│   ├── checkout/cart.spec.ts # nested folders are fine
│   ├── fixtures.ts           # custom test.extend()
│   └── pages/LoginPage.ts    # page objects (not matched)
├── playwright/.auth/user.json   # saved storageState (gitignored)
├── test-results/             # per-test artifacts (gitignored)
├── playwright-report/        # HTML report (gitignored)
└── blob-report/              # shard reports for merging (gitignored)

Code Explained

*.spec.ts — matched by default testMatch
*.setup.ts — matched only when a project's testMatch says so
pages/ — plain modules imported by tests
.auth/ — contains session cookies; never commit

⚠ Common Mistakes

  • Putting page objects in files ending .spec.ts; they get collected and run as empty tests
  • Committing playwright/.auth/*.json; it holds live session cookies
  • Writing files into test-results/ and expecting them later; the folder is cleared per run

✓ Tips & Best Practices

  • Use testInfo.outputPath() for per-test scratch files
  • Keep e2e tests in their own folder so unit-test runners (Vitest/Jest) ignore them
  • Add testIgnore for folders the runner should skip

Quick Summary

  • playwright.config.ts — single source of configuration
  • testDir + testMatch — which files are tests
  • test-results/ — artifacts, cleared per run
  • playwright-report/ — HTML report
