Writing Your Own Fixtures

test.extend() returns a new test with extra fixtures. Each fixture is an async function that does setup, hands a value to the test with await use(value), then runs teardown after use returns. Fixtures can depend on other fixtures, be worker-scoped for expensive resources, run automatically, or act as configurable options.

Notes

  • Export the extended test/expect from one fixtures.ts
  • Code after use() is teardown and runs even on failure
  • Worker fixtures can only depend on worker fixtures
  • Override built-ins too: page: async ({ page }, use) => …

fixtures.ts

import { test as base, expect } from '@playwright/test';
import { TodoPage } from './pages/TodoPage';

type TestFx = { todoPage: TodoPage };
type WorkerFx = { dbUrl: string };

export const test = base.extend<TestFx, WorkerFx>({
  todoPage: async ({ page }, use) => {
    const todo = new TodoPage(page);
    await todo.goto();
    await use(todo);                                   // test runs here
    await todo.removeAll();                            // teardown
  },
  dbUrl: [async ({}, use, workerInfo) => {
    await use(`postgres://localhost/test_${workerInfo.workerIndex}`);
  }, { scope: 'worker' }],
});
export { expect };

Code Explained

base.extend<T, W>() — test + worker fixture types
await use(value) — hand value to the test
after use — teardown
[fn, { scope: 'worker' }] — once per worker
workerIndex — unique per worker (data isolation)

⚠ Common Mistakes

  • Forgetting await use(...); the test never receives the value and hangs
  • Putting teardown before use; it runs before the test
  • Worker fixture depending on page; worker scope can't use test-scoped fixtures

✓ Tips & Best Practices

  • Use auto: true fixtures for global hooks like console-error collection
  • Make test data unique with testInfo.workerIndex or IDs to stay parallel-safe
  • Prefer fixtures over beforeEach for anything with teardown

Quick Summary

  • test.extend() — add fixtures
  • use(value) — setup → test → teardown
  • scope: 'worker' — share expensive resources
  • mergeTests() — combine fixture modules
