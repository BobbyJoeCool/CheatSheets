Clicking and Typing

Actions live on locators. Before each action Playwright runs actionability checks (attached, visible, stable, enabled, receives events) and waits until they pass. fill() sets an input's value in one go and fires input; use pressSequentially() only when the page reacts to individual keystrokes (autocomplete, masks).

Notes

  • fill('') or clear() empties a field
  • force: true skips actionability checks (hides real bugs)
  • trial: true runs the checks without acting
  • click()'s noWaitAfter is deprecated

Examples

const btn = page.getByRole('button', { name: 'Save' });
await btn.click();                                   // left click
await btn.dblclick();
await btn.click({ button: 'right' });                // context menu
await btn.click({ modifiers: ['Shift'] });           // Alt, Control, Meta…
await btn.click({ position: { x: 5, y: 5 } });       // offset from top-left
await btn.click({ clickCount: 3 });                  // triple-click
await btn.click({ trial: true });                    // checks only
await btn.click({ force: true });                    // skip checks

const email = page.getByLabel('Email');
await email.fill('ada@example.com');                 // replace value
await email.clear();
await page.getByLabel('Search').pressSequentially('play', { delay: 80 });
await email.press('Enter');
await page.getByLabel('Bio').fill('line 1\nline 2'); // textarea

Code Explained

click(opts) — button, modifiers, position, clickCount
fill() — fastest, fires one input event
pressSequentially() — per-key events, optional delay
press() — single key or chord
force — last resort for covered elements

Actionability Checks

CheckMeaning
AttachedElement is in the DOM
VisibleNon-empty box, not visibility:hidden
StableNot animating (2 frames)
EnabledNot disabled
Receives EventsNot covered by another element
EditableNot readonly (fill/clear)

⚠ Common Mistakes

  • type() in new code; it's deprecated, use fill() or pressSequentially()
  • force: true to "fix" a click intercepted by an overlay; close the overlay instead
  • Checking a value right after pressSequentially without expect; debounced UIs update later

✓ Tips & Best Practices

  • Read "element intercepts pointer events" errors: they name the covering element
  • ControlOrMeta writes cross-platform shortcuts (Cmd on macOS)
  • Use fill() by default; it's faster and less flaky

Quick Summary

  • click() — waits, then clicks
  • fill() — set value instantly
  • pressSequentially() — real keystrokes
  • force / trial — skip / dry-run checks
