Sheet 29

Routing, Mocking & HAR

page.route() · route.fulfill() · route.continue() · route.abort() · route.fetch() · routeFromHAR() · tracing.startHar()

Intercepting Network Traffic

page.route() (or context.route()) intercepts requests matching a glob, RegExp or predicate. The handler can fulfill with a fake response, continue with modified headers, abort, or fetch the real response and patch it. For whole flows, record traffic to a HAR file once and replay it with routeFromHAR() so tests run without the backend.

Notes

  • Register routes before the navigation that triggers them
  • Last registered matching route wins; route.fallback() passes on
  • Service workers can bypass routing; set serviceWorkers: 'block'
  • page.unroute() / unrouteAll() remove handlers

Examples

// mock a JSON API
await page.route('**/api/products', (route) =>
  route.fulfill({ status: 200, json: [{ id: 1, name: 'Mug', price: 9 }] }));

// patch a real response
await page.route('**/api/user', async (route) => {
  const response = await route.fetch();
  const json = await response.json();
  await route.fulfill({ response, json: { ...json, plan: 'pro' } });
});

// block images, force an error
await page.route(/\.(png|jpe?g|webp)$/, (route) => route.abort());
await page.route('**/api/checkout', (route) => route.fulfill({ status: 500 }));

// HAR: record with update: true, then replay
await page.routeFromHAR('hars/shop.har', { url: '**/api/**', update: false });

Code Explained

fulfill({ json }) — fake response body
route.fetch() — get real response to patch
abort() — simulate network failure
routeFromHAR — replay recorded traffic

Route Methods

MethodEffect
fulfill(opts)Respond without network (status, json, body, path)
continue(opts)Send request, optionally changing url, headers, postData
fetch()Perform it, return the response
abort(code?)Fail the request
fallback()Defer to next handler

HAR Options

Option / APIPurpose
update: trueRecord/refresh the HAR file
urlOnly serve matching URLs
notFound: 'fallback'Unmatched → real network
tracing.startHar()Record HAR via tracing (1.60)

⚠ Common Mistakes

  • Adding the route after goto; the request already went out
  • Glob '/api/products' without **/; it must match the full URL
  • Forgetting to re-record HARs after API changes; replays drift from reality

✓ Tips & Best Practices

  • Mock only third-party or flaky dependencies; keep your own API real in e2e
  • Use route.fetch() + patch to test edge cases with real data shapes
  • Use context.route() so popups and new pages are mocked too

Quick Summary

  • route(url, handler) — intercept
  • fulfill / continue / abort — respond, pass, fail
  • route.fetch() — patch real responses
  • routeFromHAR() — replay recorded traffic
