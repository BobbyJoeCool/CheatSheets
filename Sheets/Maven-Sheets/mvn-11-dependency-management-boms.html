Sheet 11

Dependency Management & BOMs

<dependencyManagement> · version alignment · scope import · type pom · junit-bom · spring-boot-dependencies · versions:display-dependency-updates

Pin Versions in One Place

<dependencyManagement> declares versions (and optionally scopes and exclusions) without adding the dependency. Any <dependency> for that artifact, direct or transitive, then uses the managed version, so you can leave <version> out. A BOM (bill of materials) is a POM full of managed versions. Import it with scope import to align a whole family of libraries (JUnit, Jackson, Spring) at once.

Notes

  • Managed versions also apply to transitive dependencies
  • Import BOMs inside dependencyManagement only
  • A version written on a <dependency> beats the managed one

Under the Hood

  • BOM imports are merged when the model is built; the first import wins a tie
  • Your own dependencyManagement entries beat any imported BOM
  • Imports aren't inherited as imports; their managed entries are

Importing BOMs

<dependencyManagement>
  <dependencies>
    <dependency>                         <!-- pin one artifact -->
      <groupId>com.fasterxml.jackson.core</groupId>
      <artifactId>jackson-databind</artifactId>
      <version>2.19.2</version>
    </dependency>
    <dependency>                         <!-- import a BOM -->
      <groupId>org.junit</groupId>
      <artifactId>junit-bom</artifactId>
      <version>5.13.4</version>
      <type>pom</type>
      <scope>import</scope>
    </dependency>
  </dependencies>
</dependencyManagement>

<dependencies>
  <dependency>                           <!-- no versions needed -->
    <groupId>org.junit.jupiter</groupId>
    <artifactId>junit-jupiter</artifactId>
    <scope>test</scope>
  </dependency>
</dependencies>

Code Explained

jackson-databind — every path that pulls it now gets 2.19.2
<type>pom + <scope>import — both required for a BOM
junit-jupiter — version filled in from junit-bom
Order matters: put the BOM you trust most first

Gradle Equivalent

  • dependencyManagement → constraints { }
  • BOM import → implementation(platform("org.junit:junit-bom:5.13.4"))
  • Version properties → version catalog [versions]
  • See Gradle 11 · Gradle 12

Idiomatic Maven

  • <version> on every child dependency → manage it once in the parent
  • separate versions per Jackson module → import jackson-bom
  • hand-checking for updates → versions:display-dependency-updates

⚠ Common Mistakes

  • Putting a BOM under <dependencies> instead of dependencyManagement — it does nothing useful
  • Forgetting <type>pom</type> — Maven looks for a JAR and fails
  • Two BOMs managing the same artifact — the first import wins, which may not be the one you meant

✓ Tips & Best Practices

  • Override one version from an imported BOM by declaring it in your own dependencyManagement
  • Publish your own BOM (packaging pom) for multi-module libraries
  • Spring Boot without the parent: import spring-boot-dependencies as a BOM

Quick Summary

  • dependencyManagement — versions without adding deps
  • scope import — pull in a BOM
  • Managed versions — apply to transitives too
  • BOM — aligns a library family
