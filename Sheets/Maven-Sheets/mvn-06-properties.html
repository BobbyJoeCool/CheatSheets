Sheet 06

Properties & Interpolation

<properties> · ${project.version} · ${env.NAME} · maven.compiler.release · project.build.sourceEncoding · -Dname=value · ${revision}

Reusable Values with ${…}

Define values once in <properties> and reference them anywhere with ${name}. Maven also exposes built-in values: ${project.*} for POM fields, ${env.*} for environment variables, ${settings.*} for settings.xml, and Java system properties like ${user.home}. Many plugins read user properties directly (maven.compiler.release, skipTests), so setting a property is often all the configuration needed.

Notes

  • -Dname=value on the command line overrides the POM
  • Properties are inherited from parent POMs
  • Use properties for versions shared by several dependencies

Defining and Using Properties

<properties>
  <!-- read by plugins -->
  <maven.compiler.release>21</maven.compiler.release>
  <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>

  <!-- your own -->
  <jackson.version>2.19.2</jackson.version>
  <app.env>dev</app.env>
</properties>

<dependency>
  <groupId>com.fasterxml.jackson.core</groupId>
  <artifactId>jackson-databind</artifactId>
  <version>${jackson.version}</version>
</dependency>

<build>
  <finalName>${project.artifactId}-${app.env}</finalName>
</build>

<!-- mvn package -Dapp.env=prod → invoice-service-prod.jar -->
<!-- mvn help:evaluate -Dexpression=jackson.version -q -DforceStdout -->

Code Explained

maven.compiler.release — the compiler plugin reads it, no plugin block needed
sourceEncoding — stops "platform encoding" warnings
${jackson.version} — one place to upgrade all Jackson modules
-Dapp.env=prod — overrides the POM value for this run

Gradle Equivalent

  • <properties> → gradle.properties or extra["x"]
  • ${jackson.version} → version catalog version.ref
  • -Dname=value → -Pname=value + providers.gradleProperty
  • See Gradle 08

Idiomatic Maven

  • ${pom.version} → ${project.version}
  • source + target properties → maven.compiler.release
  • a version repeated in 5 dependencies → a BOM or one property (sheet 11)

⚠ Common Mistakes

  • Expecting ${name} to work in src/main/resources — only with resource filtering (sheet 15)
  • Using properties in groupId / artifactId — Maven warns; only ${revision}-style versions are supported
  • Relying on ${env.X} that CI doesn't set — the literal ${env.X} leaks into output

✓ Tips & Best Practices

  • Name your own properties with a dot prefix (app.) to avoid clashing with plugin properties
  • See every resolved property: mvn help:effective-pom -Dverbose
  • Prefer maven.compiler.release over plugin config in simple projects

Quick Summary

  • <properties> — define once
  • ${name} — reference anywhere in the POM
  • -Dname=value — override per run
  • ${project.*} / ${env.*} — built-ins
