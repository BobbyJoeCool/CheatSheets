Builds That Run Anywhere

In CI, run Maven in batch mode through the wrapper, cache ~/.m2/repository between runs, and use verify as the main command. When a build fails, add -e for stack traces or -X for full debug output. Most "works on my machine" failures come from a stale local repository, a different JDK, or a different Maven version.

Notes

  • The cache key should include every pom.xml
  • For faster local builds, try mvnd (Maven Daemon)
  • The build cache extension skips modules whose inputs haven't changed

GitHub Actions Workflow

name: build
on: [push, pull_request]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - uses: actions/setup-java@v5
        with:
          distribution: temurin
          java-version: 21
          cache: maven              # caches ~/.m2/repository
      - run: ./mvnw -B -ntp verify
      - uses: actions/upload-artifact@v4
        if: failure()
        with:
          name: test-reports
          path: '**/target/surefire-reports/'

# local troubleshooting
./mvnw -e verify                     # stack traces
./mvnw -X verify > build.log         # full debug log
./mvnw -U verify                     # re-check remote repos
./mvnw dependency:purge-local-repository   # re-download deps

Code Explained

cache: maven — keyed on the hash of every pom.xml
-B -ntp — no colors or prompts, no download progress lines
Upload Surefire reports on failure so you can read them
purge-local-repository — fixes corrupt or partial downloads

Gradle Equivalent

  • cache: maven → gradle/actions/setup-gradle
  • -X → --debug; -e → --stacktrace
  • -U → --refresh-dependencies
  • See Gradle 25

Idiomatic Maven

  • mvn clean install in CI → ./mvnw -B -ntp verify
  • deleting all of ~/.m2 → purge-local-repository or -U
  • re-running failed CI to "see if it passes" → read surefire-reports first

⚠ Common Mistakes

  • Caching ~/.m2 including your own SNAPSHOTs — stale artifacts leak between branches
  • CI using a different JDK than developers — pin java-version and use requireJavaVersion
  • Ignoring "[WARNING]" lines about missing plugin versions — builds change when Maven upgrades

✓ Tips & Best Practices

  • Reproduce CI locally with a clean repo: -Dmaven.repo.local=/tmp/m2
  • Turn on -Dstyle.color=always if your CI shows ANSI colors
  • Add -fae in CI to see every failing module, not just the first

Quick Summary

  • ./mvnw -B -ntp verify — the CI command
  • cache: maven — reuse downloads
  • -e / -X — more error detail
  • -U / purge — fix a stale local repo
