Sheet 04

Running Maven from the CLI

phases vs plugin:goal · mvn clean install · -D properties · -P profiles · -o offline · -q / -X · -B batch mode · -T threads

Phases and Goals

You can give mvn two kinds of arguments. A phase (package) runs that phase and every phase before it. A goal (dependency:tree) runs one plugin goal on its own. You can mix them, and they run left to right. Options start with -: -D sets a property, -P picks a profile, -pl picks modules.

Notes

  • mvn clean verify — the safest full build
  • Goals use prefix:goal or full groupId:artifactId:version:goal
  • Put default options in .mvn/maven.config

Under the Hood

  • A phase runs every earlier phase; plugin:goal runs only that goal
  • -T builds independent reactor modules in parallel, not steps inside one module
  • .mvn/maven.config and .mvn/jvm.config are read at startup

Everyday Commands

mvn compile                    # validate → compile
mvn test                       # … → test
mvn package                    # … → jar in target/
mvn verify                     # … → integration tests, checks
mvn install                    # … → copy to ~/.m2
mvn clean verify               # wipe target/ first

mvn dependency:tree            # one goal, no lifecycle
mvn clean package dependency:tree    # mix, left to right

mvn verify -DskipTests         # -D sets a property
mvn verify -Pprod              # activate a profile
mvn -o verify                  # offline (cache only)
mvn -U verify                  # re-check SNAPSHOTs / missing
mvn -q verify                  # quiet: errors only
mvn -X verify                  # debug logging
mvn -B -ntp verify             # CI: batch, no download noise
mvn -T 1C verify               # 1 thread per CPU core
mvn -f other/pom.xml verify    # use another POM

Code Explained

mvn test — also runs compile, process-resources…
dependency:tree — prefix dependency → maven-dependency-plugin
-U — forces update checks for SNAPSHOTs and failed lookups
-ntp — --no-transfer-progress

Gradle Equivalent

  • mvn package → ./gradlew assemble; verify → build
  • -DskipTests → -x test
  • -Pprofile → no equivalent; use -Pname=value properties
  • See Gradle 04 · Gradle 26

Idiomatic Maven

  • mvn clean install by habit → mvn verify unless another build needs the JAR
  • long flag lists in every command → .mvn/maven.config
  • -Dmaven.test.skip=true to save time → -DskipTests (tests still compile)

⚠ Common Mistakes

  • Thinking mvn install is needed to run tests — mvn test or verify is enough
  • Running mvn jar:jar and expecting a compile first — a lone goal skips the lifecycle
  • Using -o on a fresh machine — offline mode fails on anything not already cached

✓ Tips & Best Practices

  • Shell autocompletion: the maven plugin for oh-my-zsh, or bash-completion scripts
  • Find a goal's parameters: mvn help:describe -Dplugin=surefire -Ddetail
  • Add -Dstyle.color=always when CI strips colors you want

Quick Summary

  • phase — runs itself and all earlier phases
  • plugin:goal — runs one goal only
  • -D / -P / -pl — properties, profiles, modules
  • -B -ntp — clean CI output
