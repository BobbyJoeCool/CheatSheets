Sheet 18

Code Quality & Enforcer

maven-enforcer-plugin · requireMavenVersion · requireJavaVersion · JaCoCo coverage · Spotless / Checkstyle · versions-maven-plugin

Guardrails in the Build

Quality plugins turn team rules into build failures. The enforcer plugin checks the environment and the dependency graph: Maven and Java versions, pinned plugins, banned or conflicting dependencies. JaCoCo measures test coverage and can enforce a minimum. Formatters and linters like Spotless and Checkstyle keep style consistent. Bind the checks to verify so CI runs them.

Notes

  • Put these in the parent POM so every module gets them
  • Spotless: spotless:apply fixes, spotless:check fails
  • JaCoCo report: target/site/jacoco/index.html

Enforcer + JaCoCo

<plugin>
  <artifactId>maven-enforcer-plugin</artifactId>
  <version>3.5.0</version>
  <executions><execution>
    <id>enforce</id>
    <goals><goal>enforce</goal></goals>
    <configuration><rules>
      <requireMavenVersion><version>[3.9,)</version></requireMavenVersion>
      <requireJavaVersion><version>[21,)</version></requireJavaVersion>
      <requirePluginVersions/>
      <dependencyConvergence/>
      <bannedDependencies><excludes>
        <exclude>commons-logging:commons-logging</exclude>
      </excludes></bannedDependencies>
    </rules></configuration>
  </execution></executions>
</plugin>
<plugin>
  <groupId>org.jacoco</groupId>
  <artifactId>jacoco-maven-plugin</artifactId>
  <version>0.8.13</version>
  <executions>
    <execution><id>agent</id><goals><goal>prepare-agent</goal></goals></execution>
    <execution><id>report</id><phase>verify</phase><goals><goal>report</goal></goals></execution>
  </executions>
</plugin>

Code Explained

enforce — binds to validate by default, so it fails fast
[3.9,) — version range: 3.9 or newer
dependencyConvergence — fails when two paths bring different versions
prepare-agent — sets argLine so tests run with coverage

Gradle Equivalent

  • Enforcer → no built-in; use failOnVersionConflict() and plugins
  • JaCoCo → the jacoco plugin + jacocoTestReport
  • Spotless / Checkstyle → same tools as Gradle plugins
  • See Gradle 06

Idiomatic Maven

  • "use Java 21" in the README → requireJavaVersion
  • style debates in code review → spotless:check in CI
  • coverage numbers no one reads → a JaCoCo check rule with a floor

Useful Enforcer Rules

RuleFails when
requireMavenVersionMaven too old
requireJavaVersionJDK too old
requirePluginVersionsA plugin has no version
dependencyConvergenceConflicting transitive versions
requireUpperBoundDepsA lower version beat a higher one
bannedDependenciesA listed artifact appears

⚠ Common Mistakes

  • Adding dependencyConvergence to a big legacy project at once — hundreds of failures; start with requireUpperBoundDeps
  • Overriding Surefire's argLine without @{argLine} — JaCoCo shows 0% coverage
  • Running Spotless apply in CI — it changes files instead of failing

✓ Tips & Best Practices

  • Run mvn enforcer:enforce alone to test rules quickly
  • Use spotless:apply in a pre-commit hook and spotless:check in CI
  • Start the JaCoCo floor at your current coverage, then raise it

Quick Summary

  • Enforcer — environment and dependency rules
  • JaCoCo — coverage report and floor
  • Spotless / Checkstyle — formatting and style
  • Bind checks to verify
