Packaging & Running JARs

maven-jar-plugin · manifest Main-Class · exec:java · maven-shade-plugin (uber JAR) · maven-assembly-plugin · war packaging · source / javadoc JARs

From Classes to a Runnable JAR

mvn package creates a plain JAR with your classes only, so dependencies are not inside it. To run it with java -jar, set a Main-Class in the manifest and either ship the dependencies alongside it or build an uber JAR with the shade plugin. For quick runs during development, exec:java runs a main class with the full classpath.

Notes

  • Spring Boot apps use spring-boot-maven-plugin (repackage)
  • war packaging runs war:war instead of jar:jar
  • Libraries publish -sources and -javadoc JARs too

Main-Class + Shaded Uber JAR

<plugin>
  <artifactId>maven-shade-plugin</artifactId>
  <version>3.6.0</version>
  <executions>
    <execution>
      <phase>package</phase>
      <goals><goal>shade</goal></goals>
      <configuration>
        <transformers>
          <transformer implementation=
            "org.apache.maven.plugins.shade.resource.ManifestResourceTransformer">
            <mainClass>com.acme.App</mainClass>
          </transformer>
          <transformer implementation=
            "org.apache.maven.plugins.shade.resource.ServicesResourceTransformer"/>
        </transformers>
      </configuration>
    </execution>
  </executions>
</plugin>

<!-- mvn package && java -jar target/invoice-service-2.4.0.jar -->
<!-- dev run: mvn compile exec:java -Dexec.mainClass=com.acme.App -->

Code Explained

shade — unpacks every dependency into one JAR at package
ManifestResourceTransformer — writes Main-Class
ServicesResourceTransformer — merges META-INF/services files
exec:java — runs in Maven's JVM with the project classpath

Gradle Equivalent

  • Main-Class → application { mainClass = "…" }
  • Shade plugin → Shadow plugin (shadowJar)
  • exec:java → ./gradlew run
  • See Gradle 15

Idiomatic Maven

  • shading a library you publish → shade only applications
  • assembly jar-with-dependencies → shade (handles service files)
  • java -cp with a hand-built path → shade or dependency:copy-dependencies

⚠ Common Mistakes

  • java -jar on the plain JAR — "no main manifest attribute" or NoClassDefFoundError
  • Shading without ServicesResourceTransformer — JDBC drivers or SLF4J providers vanish
  • Signed dependency JARs inside a shaded JAR — SecurityException; filter out *.SF, *.RSA

✓ Tips & Best Practices

  • Use <relocations> to rename clashing packages in a shaded JAR
  • Set <createDependencyReducedPom>false if the reduced POM confuses tools
  • For containers, a thin JAR plus a dependency layer builds faster than an uber JAR

Quick Summary

  • jar:jar — classes only
  • shade — runnable uber JAR
  • exec:java — run during development
  • Source / javadoc JARs — for published libraries
