Sheet 07

Parent POMs & Inheritance

<parent> · relativePath · Super POM · what gets inherited · help:effective-pom · spring-boot-starter-parent

Sharing Configuration Down

A POM can name a parent and inherit its properties, dependency management, plugin configuration and repositories. Every POM ultimately inherits from the built-in Super POM, which supplies the standard layout and Central. A parent must have packaging pom. Use a company parent for shared rules, or a framework parent like spring-boot-starter-parent.

Notes

  • relativePath defaults to ../pom.xml
  • Use <relativePath/> for a parent from a repository
  • Only one parent; share more through BOM imports (sheet 11)

Under the Hood

  • Effective POM = Super POM + parent chain + active profiles, merged, then ${} interpolated
  • Plugins merge by groupId:artifactId; config elements merge, they aren't appended
  • combine.children="append" / combine.self="override" change the merge

A Child POM

<parent>
  <groupId>com.acme</groupId>
  <artifactId>acme-parent</artifactId>
  <version>7</version>
  <relativePath/>        <!-- look it up in repositories -->
</parent>

<artifactId>invoice-service</artifactId>
<!-- groupId and version inherited from the parent -->

<build>
  <plugins>
    <plugin>
      <groupId>org.apache.maven.plugins</groupId>
      <artifactId>maven-compiler-plugin</artifactId>
      <configuration>
        <compilerArgs combine.children="append">
          <arg>-parameters</arg>    <!-- added to the parent's args -->
        </compilerArgs>
      </configuration>
    </plugin>
  </plugins>
</build>

<!-- mvn help:effective-pom -Doutput=effective.xml -->

Code Explained

<relativePath/> — skip the ../pom.xml lookup
No <version> on the plugin — it comes from the parent's pluginManagement
combine.children="append" — keeps the parent's list items too
help:effective-pom — the merged result Maven actually runs

Gradle Equivalent

  • Parent POM → a convention plugin in build-logic
  • Super POM defaults → the java plugin's conventions
  • Several parents → apply several convention plugins
  • See Gradle 18

Idiomatic Maven

  • dependencies in a parent POM → dependencyManagement in the parent
  • copy-pasted plugin blocks → one pluginManagement in a parent
  • a parent only for versions → a BOM import

⚠ Common Mistakes

  • Putting <dependencies> in a parent — every child gets them, wanted or not
  • Forgetting <relativePath/> — Maven warns that ../pom.xml isn't the parent
  • Changing parent config and not seeing it — the child has a local copy of the old parent; run install on the parent

✓ Tips & Best Practices

  • Debug any "where did this come from" question with help:effective-pom -Dverbose
  • Version company parents with plain integers (7, 8) and release them often
  • Use <inherited>false</inherited> for plugin config only the parent itself needs

Quick Summary

  • <parent> — inherit config
  • relativePath — where to find it locally
  • Super POM — the root of every POM
  • help:effective-pom — the merged result
