Compiler & Resources

maven-compiler-plugin · <release> · compilerArgs -Xlint · annotationProcessorPaths · resource filtering · toolchains.xml

Compiling Java, Copying Resources

The compiler plugin runs javac on src/main/java and src/test/java. Set the target Java version with <release>, which also checks you only use APIs from that version. Annotation processors such as Lombok and MapStruct go on annotationProcessorPaths. The resources plugin copies src/main/resources into target/classes and can replace ${…} placeholders when filtering is on.

Notes

  • Since JDK 23, javac doesn't run processors found on the classpath by default
  • <release> needs JDK 9+; it replaces source + target
  • Toolchains compile with a different JDK than the one running Maven

Under the Hood

  • The compiler plugin runs javac in-process through javax.tools (no fork by default)
  • Change detection is coarse; a stale target/ can hide errors, so clean when in doubt
  • Filtering replaces ${} during process-resources, before compiling

Compiler and Resources Setup

<build>
  <resources>
    <resource>
      <directory>src/main/resources</directory>
      <filtering>true</filtering>         <!-- ${project.version} → 2.4.0 -->
    </resource>
  </resources>
  <plugins>
    <plugin>
      <artifactId>maven-compiler-plugin</artifactId>
      <version>3.14.0</version>
      <configuration>
        <release>21</release>
        <compilerArgs>
          <arg>-Xlint:all</arg>
          <arg>-parameters</arg>
        </compilerArgs>
        <annotationProcessorPaths>
          <path>
            <groupId>org.projectlombok</groupId>
            <artifactId>lombok</artifactId>
            <version>1.18.38</version>
          </path>
        </annotationProcessorPaths>
      </configuration>
    </plugin>
  </plugins>
</build>

Code Explained

<filtering>true — app.version=${project.version} gets the real value
<release>21 — same as the maven.compiler.release property
-parameters — keeps parameter names (Spring, Jackson use them)
annotationProcessorPaths — runs Lombok without leaking it to runtime

Gradle Equivalent

  • <release> → options.release = 21 or a toolchain
  • annotationProcessorPaths → annotationProcessor(…)
  • Filtering → tasks.processResources { expand(…) }
  • See Gradle 13 · Gradle 14

Idiomatic Maven

  • <source>21</source><target>21</target> → <release>21</release>
  • filtering the whole resources folder → a separate filtered folder
  • Lombok only as a provided dependency → also on annotationProcessorPaths

⚠ Common Mistakes

  • Filtering fonts or images — the bytes get corrupted
  • Lombok "cannot find symbol" errors on JDK 23+ — add it to annotationProcessorPaths
  • Spring Boot apps filtering application.properties — Boot's own ${} placeholders get replaced too; Boot's parent uses @x@

✓ Tips & Best Practices

  • Put -Xlint:all and failOnWarning in the parent to keep code clean
  • Use @project.version@ in Boot projects to avoid placeholder clashes
  • Run mvn clean compile after switching branches with big refactors

Quick Summary

  • <release> — target Java version
  • annotationProcessorPaths — Lombok, MapStruct
  • <filtering> — replace ${} in resources
  • toolchains — compile with another JDK
