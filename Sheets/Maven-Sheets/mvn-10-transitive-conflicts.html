Sheet 10

Transitive Dependencies & Conflicts

nearest-wins mediation · <exclusions> · dependency:tree · -Dverbose · dependency:analyze · enforcer dependencyConvergence

Dependencies of Dependencies

When you depend on a library, you also get its dependencies, and theirs. When two paths bring different versions of the same artifact, Maven picks one by dependency mediation: the version nearest to your project in the tree wins, and the first one declared wins a tie. It does not pick the highest version, so an old version can silently win. dependency:tree shows what happened.

Notes

  • Declaring a dependency directly always wins (depth 1)
  • dependencyManagement overrides mediation (sheet 11)
  • -Dverbose shows the versions that lost

Under the Hood

  • Mediation: nearest, then first declared, never highest
  • optional, test and provided dependencies don't propagate
  • A transitive dependency's scope comes from its parent's: test → everything below is test

Reading the Tree, Excluding

$ mvn dependency:tree -Dverbose -Dincludes=com.fasterxml.jackson.core
[INFO] com.acme:invoice-service:jar:2.4.0-SNAPSHOT
[INFO] +- com.acme:pdf-lib:jar:1.3.0:compile
[INFO] |  \- com.fasterxml.jackson.core:jackson-databind:jar:2.12.7:compile
[INFO] \- com.acme:http-lib:jar:4.0.0:compile
[INFO]    \- (com.fasterxml.jackson.core:jackson-databind:jar:2.19.2:compile
             - omitted for conflict with 2.12.7)

<!-- fix 1: drop the old one -->
<dependency>
  <groupId>com.acme</groupId>
  <artifactId>pdf-lib</artifactId>
  <version>1.3.0</version>
  <exclusions>
    <exclusion>
      <groupId>com.fasterxml.jackson.core</groupId>
      <artifactId>jackson-databind</artifactId>
    </exclusion>
  </exclusions>
</dependency>
<!-- fix 2 (better): pin it in dependencyManagement -->

Code Explained

-Dincludes= — filter the tree to one group or artifact
omitted for conflict — 2.19.2 lost; 2.12.7 was declared first at the same depth
<exclusion> — removes that artifact from this path only
* works as a wildcard for groupId / artifactId

Gradle Equivalent

  • Nearest wins → Gradle picks the highest version by default
  • <exclusions> → exclude(group = "…", module = "…")
  • dependency:tree → ./gradlew dependencies / dependencyInsight
  • See Gradle 12

Idiomatic Maven

  • excluding from every dependency that pulls it → one entry in dependencyManagement
  • ignoring conflicts until runtime → enforcer dependencyConvergence
  • using a class you get transitively → declare it directly

⚠ Common Mistakes

  • Assuming the newest version wins — Maven's nearest-wins can pick an old one and cause NoSuchMethodError
  • Excluding a library that the dependency really needs — runtime ClassNotFoundException
  • Fixing conflicts by reordering dependencies — fragile; pin the version instead

✓ Tips & Best Practices

  • Add the enforcer's dependencyConvergence or requireUpperBoundDeps rule to catch conflicts early (sheet 18)
  • IntelliJ's Maven dependency diagram shows conflicts in red
  • When NoSuchMethodError appears, run dependency:tree -Dverbose -Dincludes=… first

Quick Summary

  • Transitive — you get your dependencies' dependencies
  • Mediation — nearest, then first declared
  • <exclusions> — drop one path
  • dependency:tree -Dverbose — see conflicts
