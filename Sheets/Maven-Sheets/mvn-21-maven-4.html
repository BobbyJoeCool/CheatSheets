Sheet 21

What's Changing in Maven 4

Java 17 to run · modelVersion 4.1.0 · build POM vs consumer POM · <subprojects> · inferred parent version · mvnup check / apply

Maven 4 at a Glance

Maven 4 is a major release that keeps Maven 3 POMs building while cleaning up long-standing pain points. It splits the build POM (what you write) from the consumer POM (what gets published), so build-only details stop leaking to users. A new POM model, 4.1.0, allows shorter POMs. As of October 2026 it is at release candidate 4.0.0-rc-7, with GA expected soon.

Notes

  • Running Maven 4 needs Java 17+; it can still compile older targets
  • Existing 4.0.0 POMs keep working; most builds just run
  • mvnup check lists problems; mvnup apply fixes them

A Maven 4.1.0 POM

<project xmlns="http://maven.apache.org/POM/4.1.0">
  <modelVersion>4.1.0</modelVersion>

  <parent>
    <!-- groupId / version inferred from ../pom.xml -->
    <artifactId>billing</artifactId>
  </parent>
  <artifactId>app</artifactId>

  <dependencies>
    <dependency>
      <groupId>com.acme</groupId>
      <artifactId>core</artifactId>   <!-- sibling: version inferred -->
    </dependency>
  </dependencies>
</project>

<!-- root: <subprojects><subproject>app</subproject></subprojects> -->

mvnup check                # report upgrade issues
mvnup apply                # rewrite POMs where safe
mvn -r verify              # resume after a failed build

Code Explained

4.1.0 — opt in to the new model; publishing stays compatible
Parent and sibling versions can be left out inside one build
<subprojects> — new name for <modules>
-r / --resume — continues where the last build failed

Gradle Equivalent

  • Consumer POM → Gradle Module Metadata + generated POM
  • Inferred versions → project(":core") never needed versions
  • No direct mvnup counterpart
  • See Gradle 23

Idiomatic Maven

  • flatten-maven-plugin for ${revision} → Maven 4 handles CI-friendly versions itself
  • repeating parent groupId / version → inferred in a 4.1.0 POM
  • upgrading POMs by hand → mvnup apply, then review the diff

⚠ Common Mistakes

  • Switching the POM to 4.1.0 while teammates still run Maven 3 — Maven 3 can't read it
  • Assuming every plugin works — very old plugins that use removed Maven 2 APIs fail
  • Upgrading CI and laptops separately — pin the version with the wrapper instead

✓ Tips & Best Practices

  • Trial Maven 4 on a branch: mvn wrapper:wrapper -Dmaven=4.0.0-rc-7
  • Run with -e and report plugin failures to the plugin's project
  • Read "What's new in Maven 4" on maven.apache.org before upgrading

Quick Summary

  • Java 17+ — required to run Maven 4
  • Consumer POM — clean published POMs
  • 4.1.0 — shorter POMs, inferred versions
  • mvnup — upgrade helper
