Deploying & Releasing

mvn deploy · <distributionManagement> · snapshot vs release repositories · Central Portal publishing · GPG signing · versions:set · maven-release-plugin

Publishing Artifacts

mvn deploy uploads the built artifacts to the repository named in <distributionManagement>: SNAPSHOT versions go to the snapshot repository and releases to the release repository. Publishing open source to Maven Central goes through the Central Portal (OSSRH was shut down in 2025) and requires sources, javadoc, GPG signatures and complete POM metadata.

Notes

  • Credentials come from settings.xml <server> by id
  • Central needs name, description, url, licenses, developers, scm
  • A release version can never be overwritten on Central

Under the Hood

  • deploy uploads the artifact, POM, checksums and maven-metadata.xml
  • SNAPSHOTs get unique timestamped versions on the remote: 2.4.0-20261026.141503-7
  • install only copies to ~/.m2; nothing leaves your machine

Company Repo + Central Portal

<distributionManagement>                  <!-- company Nexus -->
  <repository>
    <id>corp-releases</id>
    <url>https://nexus.acme.com/repository/maven-releases/</url>
  </repository>
  <snapshotRepository>
    <id>corp-snapshots</id>
    <url>https://nexus.acme.com/repository/maven-snapshots/</url>
  </snapshotRepository>
</distributionManagement>

<plugin>                                  <!-- Maven Central -->
  <groupId>org.sonatype.central</groupId>
  <artifactId>central-publishing-maven-plugin</artifactId>
  <version>0.8.0</version>
  <extensions>true</extensions>
  <configuration>
    <publishingServerId>central</publishingServerId>
    <autoPublish>false</autoPublish>
  </configuration>
</plugin>

mvn versions:set -DnewVersion=2.4.0 -DgenerateBackupPoms=false
mvn -Prelease deploy           # sources, javadoc, gpg in the profile
mvn versions:set -DnewVersion=2.5.0-SNAPSHOT

Code Explained

<id> — must match a <server> in settings.xml
<extensions>true — the plugin replaces the default deploy step
autoPublish=false — review the upload in the Portal before releasing
versions:set — updates the version in every module

Gradle Equivalent

  • distributionManagement → publishing { repositories { } }
  • mvn deploy → ./gradlew publish
  • GPG plugin → the signing plugin
  • See Gradle 23

Idiomatic Maven

  • deploying from a laptop → deploy from CI on a tag
  • manual version edits in each POM → versions:set or ${revision}
  • signing every dev build → GPG + javadoc only in a release profile

⚠ Common Mistakes

  • Deploying a SNAPSHOT to a release-only repository — 400 Bad Request
  • Still pointing at oss.sonatype.org (OSSRH) — it's retired; use the Central Portal plugin
  • Missing GPG passphrase in CI — set MAVEN_GPG_PASSPHRASE as a secret

✓ Tips & Best Practices

  • Test a release locally with mvn -Prelease install before deploying
  • Use -DaltDeploymentRepository=id::url to deploy elsewhere once
  • Many teams skip release:prepare and let CI set the version from the Git tag

Quick Summary

  • mvn deploy — upload to a remote repo
  • distributionManagement — where to upload
  • Central Portal — the way into Maven Central
  • versions:set — change the version
