What Maven Is

Apache Maven builds Java projects from a declarative pom.xml (Project Object Model). Instead of scripting steps, you describe what the project is: its coordinates, dependencies and packaging. Maven follows convention over configuration: a standard folder layout and a fixed lifecycle of phases, where each phase runs plugin goals. Dependencies download from Maven Central into a local cache at ~/.m2/repository.

Notes

  • Current: Maven 3.9.x / 3.10.x (runs on Java 8+)
  • Maven 4 is at release candidate and needs Java 17+ (sheet 21)
  • Everything is a plugin: compiler, surefire, jar, install…
  • Central hosts most open-source JVM libraries

Under the Hood

  • mvn starts a JVM → classworlds launcher → Maven core → resolver → plugin mojos
  • Core plugins download on first use, which is why the very first build is slow
  • Each run reads the POM, builds the effective POM, then plans which goals to run

A Minimal pom.xml

<project xmlns="http://maven.apache.org/POM/4.0.0">
  <modelVersion>4.0.0</modelVersion>

  <groupId>com.example</groupId>      <!-- who -->
  <artifactId>hello</artifactId>      <!-- what -->
  <version>1.0.0-SNAPSHOT</version>   <!-- which -->

  <properties>
    <maven.compiler.release>21</maven.compiler.release>
  </properties>

  <dependencies>
    <dependency>
      <groupId>org.junit.jupiter</groupId>
      <artifactId>junit-jupiter</artifactId>
      <version>5.13.4</version>
      <scope>test</scope>
    </dependency>
  </dependencies>
</project>

<!-- mvn package → target/hello-1.0.0-SNAPSHOT.jar -->

Code Explained

groupId:artifactId:version — the project's unique coordinates
maven.compiler.release — target Java version for javac
<scope>test</scope> — only on the test classpath
No <build> section needed: the defaults compile, test and jar

Gradle Equivalent

  • pom.xml → build.gradle.kts + settings.gradle.kts
  • Fixed phases → a task graph you can extend
  • ~/.m2/repository → ~/.gradle/caches
  • See Gradle 01

Idiomatic Maven

  • copying JARs into lib/ → declare them as <dependency>
  • custom folder layout → the standard src/main/java layout
  • Ant-style scripted steps → plugins bound to phases

⚠ Common Mistakes

  • Treating the POM like a script — logic belongs in plugins, not in long property hacks
  • Fighting the standard layout — every plugin assumes it, so overrides multiply
  • Running the system mvn with a different version than teammates — use the wrapper (sheet 02)

✓ Tips & Best Practices

  • Run mvn help:effective-pom to see what Maven will actually use
  • Start from an archetype or Spring Initializr rather than a blank file
  • Pin plugin versions in a parent POM so builds are repeatable

Quick Summary

  • pom.xml — declarative project model
  • phase — a lifecycle step; goals do the work
  • ~/.m2 — local artifact cache
  • mvn package — compile, test, jar
