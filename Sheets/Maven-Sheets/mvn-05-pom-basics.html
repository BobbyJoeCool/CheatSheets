POM Basics & Coordinates

modelVersion · groupId · artifactId · version · packaging · SNAPSHOT vs release · name / description

Coordinates Identify an Artifact

Every artifact in the Maven world is identified by its coordinates: groupId (organization, reverse domain), artifactId (project name) and version. packaging decides what gets built and which plugins run (jar by default). A version ending in -SNAPSHOT means "in development" and can change. A version without it is a release and must never change once published.

Notes

  • Written as groupId:artifactId:version (GAV)
  • File name in a repo: artifactId-version.jar
  • modelVersion is always 4.0.0 in Maven 3
  • name, url, licenses are needed to publish to Central

The Top of a POM

<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0
           https://maven.apache.org/xsd/maven-4.0.0.xsd">
  <modelVersion>4.0.0</modelVersion>

  <groupId>com.acme.billing</groupId>
  <artifactId>invoice-service</artifactId>
  <version>2.4.0-SNAPSHOT</version>
  <packaging>jar</packaging>          <!-- default -->

  <name>Invoice Service</name>
  <description>Creates and sends invoices</description>
  <url>https://github.com/acme/invoice-service</url>

  <!-- dependencies, build, profiles … -->
</project>
<!-- → com/acme/billing/invoice-service/2.4.0-SNAPSHOT/
       invoice-service-2.4.0-SNAPSHOT.jar -->

Code Explained

xsi:schemaLocation — gives the IDE completion and validation
groupId dots become folders in the repository
-SNAPSHOT — rebuilt and re-downloaded as it changes
packaging — jar, war, pom, maven-plugin…

Gradle Equivalent

  • groupId → group = "com.acme.billing"
  • artifactId → rootProject.name / project name
  • version → version = "2.4.0-SNAPSHOT"
  • See Gradle 03 · Gradle 09

Idiomatic Maven

  • groupId = billing → reverse domain: com.acme.billing
  • re-publishing 1.2.0 with a fix → release 1.2.1
  • 1.0, 1.0-final, v1 → semantic MAJOR.MINOR.PATCH

Packaging Types

packagingProduces
jarLibrary or app JAR (default)
warWeb archive for a servlet container
pomParent / aggregator, no code
maven-pluginA Maven plugin
earEnterprise archive

Version Order

VersionNotes
1.0-alpha-1Qualifiers sort before the release
1.0-beta-2
1.0-RC1Release candidate
1.0-SNAPSHOTBefore 1.0, mutable
1.0Release, immutable
1.0.1Patch

⚠ Common Mistakes

  • Depending on another team's -SNAPSHOT in a release — the build changes under you
  • Mismatched artifactId and folder name in multi-module builds — confusing errors
  • Using uppercase or spaces in artifactId — keep it lowercase-hyphenated

✓ Tips & Best Practices

  • Check what a POM resolves to: mvn help:evaluate -Dexpression=project.version -q -DforceStdout
  • Keep -SNAPSHOT on main; strip it only when releasing
  • Add the schema header so your IDE flags typos in element names

Quick Summary

  • groupId:artifactId:version — unique coordinates
  • packaging — what gets built
  • -SNAPSHOT — mutable dev version
  • Release — immutable once published
