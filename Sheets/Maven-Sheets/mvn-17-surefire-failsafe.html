Sheet 17

Testing with Surefire & Failsafe

maven-surefire-plugin · JUnit 5 · -Dtest=Class#method · -DskipTests vs -Dmaven.test.skip · failsafe *IT classes · integration-test / verify · test reports

Unit Tests and Integration Tests

Surefire runs unit tests in the test phase and fails the build right away on a failure. Failsafe runs integration tests (classes named *IT) in integration-test but only fails the build in verify, so post-integration-test cleanup (stopping a server or container) still runs. Both detect JUnit 5 automatically when junit-jupiter is on the test classpath.

Notes

  • Surefire is bound by default; Failsafe must be added
  • Reports: target/surefire-reports, target/failsafe-reports
  • JUnit and Mockito APIs: Java sheets 102–104

Under the Hood

  • Surefire forks a separate test JVM (forkCount=1, reuseForks=true)
  • <argLine> sets that JVM's flags; JaCoCo injects its agent through @{argLine}
  • Failsafe records results in integration-test and fails in verify

Failsafe Setup and Test Commands

<plugin>
  <artifactId>maven-surefire-plugin</artifactId>
  <version>3.5.3</version>
  <configuration>
    <argLine>@{argLine} -Xmx1g</argLine>   <!-- keeps JaCoCo's agent -->
  </configuration>
</plugin>
<plugin>
  <artifactId>maven-failsafe-plugin</artifactId>
  <version>3.5.3</version>
  <executions>
    <execution>
      <goals>
        <goal>integration-test</goal>
        <goal>verify</goal>
      </goals>
    </execution>
  </executions>
</plugin>

mvn test                              # unit tests only
mvn verify                            # unit + integration tests
mvn test -Dtest=InvoiceServiceTest    # one class
mvn test -Dtest='InvoiceServiceTest#creates*'   # methods by pattern
mvn verify -Dit.test=PaymentIT        # one integration test
mvn verify -DskipITs                  # skip Failsafe only

Code Explained

@{argLine} — late replacement, so JaCoCo's agent isn't overwritten
Both Failsafe goals are needed: one runs tests, one fails the build
-Dtest — Surefire filter; -Dit.test — Failsafe filter
Quote patterns with # or * in the shell

Gradle Equivalent

  • mvn test → ./gradlew test; -Dtest=X → --tests X
  • Failsafe → a jvm-test-suite named integrationTest
  • -DskipTests → -x test
  • See Gradle 16

Idiomatic Maven

  • -Dmaven.test.skip=true by default → -DskipTests (tests still compile)
  • slow container tests named *Test → name them *IT for Failsafe
  • <argLine>-Xmx1g</argLine> with JaCoCo → @{argLine} -Xmx1g

Default Name Patterns

PluginRuns classes named
Surefire**/Test*, **/*Test, **/*Tests, **/*TestCase
Failsafe**/IT*, **/*IT, **/*ITCase

Skipping & Filtering

PropertyEffect
-DskipTestsCompile tests, run none
-Dmaven.test.skip=trueDon't compile or run tests
-DskipITsSkip Failsafe only
-Dsurefire.failIfNoSpecifiedTests=falseOK if -Dtest matches nothing in a module
-Dgroups=fastJUnit 5 @Tag filter
-Dsurefire.rerunFailingTestsCount=2Retry flaky tests

⚠ Common Mistakes

  • Only declaring Failsafe's integration-test goal — failures never break the build
  • -Dtest=X in a multi-module build fails in modules without X — add -Dsurefire.failIfNoSpecifiedTests=false
  • Test classes named *Spec or Check* — the default patterns skip them silently; add <includes>

✓ Tips & Best Practices

  • Speed up: <forkCount>1C</forkCount> runs one fork per CPU core
  • Readable reports: mvn surefire-report:report
  • Watch out for "Tests run: 0" in CI; it usually means a naming or engine problem

Quick Summary

  • Surefire — unit tests in test
  • Failsafe — *IT tests, fails in verify
  • -Dtest=Class#method — run a subset
  • -DskipTests — skip running, keep compiling
