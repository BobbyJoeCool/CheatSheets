Sheet 67

Triggers

CREATE TRIGGER · BEFORE / AFTER · FOR EACH ROW · NEW / OLD · INSTEAD OF · audit trigger

Code That Runs on Change

A trigger runs automatically when rows are inserted, updated or deleted. BEFORE triggers can inspect and change the incoming row (NEW) or cancel it; AFTER triggers react once the change is made, which suits audit logs; INSTEAD OF triggers make views writable. FOR EACH ROW fires per changed row, FOR EACH STATEMENT once per statement. In PostgreSQL the logic lives in a trigger function.

Trigger Facts

  • NEW = row after the change; OLD = row before
  • Triggers fire for every writer: apps, scripts, ORMs
  • They run inside the same transaction
  • Hidden side effects surprise people: document them

NoSQL Comparison

  • MongoDB change streams (collection.watch()) react after commits
  • Atlas Triggers run functions on changes
  • No BEFORE triggers: validate in the app or with $jsonSchema

Audit Trigger

CREATE TABLE price_history (
  product_id INT,
  old_price  NUMERIC(10,2),
  new_price  NUMERIC(10,2),
  changed_at TIMESTAMPTZ DEFAULT now(),
  changed_by TEXT DEFAULT current_user
);

-- Trigger function: runs once per changed row
CREATE FUNCTION log_price() RETURNS trigger
LANGUAGE plpgsql AS $$
BEGIN
  INSERT INTO price_history
         (product_id, old_price, new_price)
  VALUES (OLD.product_id, OLD.price, NEW.price);
  RETURN NEW;
END $$;

CREATE TRIGGER products_price_audit
AFTER UPDATE OF price ON products
FOR EACH ROW
WHEN (OLD.price IS DISTINCT FROM NEW.price)
EXECUTE FUNCTION log_price();

UPDATE products SET price = 42 WHERE product_id = 7;
SELECT * FROM price_history;   -- one new row

Code Explained

RETURNS trigger — a special function type for triggers
UPDATE OF price — only when price is in the SET list
WHEN (…) skips updates that didn't change the value
RETURN NEW is required for row triggers (ignored in AFTER)

⚠ Common Mistakes

  • Business logic hidden in triggers nobody knows about
  • Triggers that update the same table and recurse
  • Slow AFTER triggers turning bulk updates into crawls

✓ Tips & Best Practices

  • Use triggers for integrity and auditing, not workflows
  • Name them <table>_<purpose> and list them in docs
  • PG: pg_trigger_depth() guards against recursion

Quick Summary

  • BEFORE / AFTER / INSTEAD OF
  • NEW / OLD row values
  • Fire for every writer
