Upsert & MERGE

ON CONFLICT · DO UPDATE · DO NOTHING · EXCLUDED · ON DUPLICATE KEY UPDATE · MERGE

Insert or Update in One Step

An upsert inserts a row, or updates it if one with the same key already exists, in one atomic statement, so two concurrent requests can't both insert. PostgreSQL and SQLite write INSERT … ON CONFLICT (key) DO UPDATE, with the rejected row available as EXCLUDED; DO NOTHING just skips duplicates. MySQL uses ON DUPLICATE KEY UPDATE. MERGE is the standard, more general form: compare a source with a target and insert, update or delete per row.

Upsert Facts

  • The conflict target needs a unique index or PK
  • EXCLUDED.col = the value you tried to insert
  • Add WHERE to DO UPDATE to update conditionally
  • Select-then-insert in app code races; upsert doesn't

NoSQL Comparison

  • MongoDB: updateOne(filter, { $set: … }, { upsert: true })
  • $setOnInsert sets fields only when inserting
  • Needs a unique index on the filter field to stay safe

Upsert & MERGE

-- Insert, or update if the email exists
INSERT INTO customers (email, name, city)
VALUES ('ada@example.com', 'Ada Lovelace', 'London')
ON CONFLICT (email)
DO UPDATE SET name = EXCLUDED.name,
              city = EXCLUDED.city;

-- Insert only if missing
INSERT INTO customers (email, name)
VALUES ('bo@example.com', 'Bo')
ON CONFLICT (email) DO NOTHING;
-- Add to an existing quantity
INSERT INTO order_items
       (order_id, product_id, quantity, unit_price)
VALUES (101, 7, 1, 39.99)
ON CONFLICT (order_id, product_id) DO UPDATE
SET    quantity = order_items.quantity + EXCLUDED.quantity;
-- MERGE (PostgreSQL 15+, SQL Server)
MERGE INTO products p
USING staging_prices s ON s.product_id = p.product_id
WHEN MATCHED AND s.price IS NULL THEN DELETE
WHEN MATCHED THEN UPDATE SET price = s.price
WHEN NOT MATCHED THEN
  INSERT (name, price) VALUES (s.name, s.price);

Code Explained

ON CONFLICT (email) relies on the UNIQUE email
order_items.quantity = stored value, EXCLUDED = new one
WHEN branches run in order; first match wins
staging_prices — a loaded table of new prices

⚠ Common Mistakes

  • Upserting on a column without a unique index
  • SELECT then INSERT from app code: race conditions
  • SQL Server MERGE without HOLDLOCK under concurrency

✓ Tips & Best Practices

  • Use DO NOTHING + RETURNING to learn which rows were new
  • Prefer ON CONFLICT for single-row upserts in PostgreSQL
  • Use MERGE for syncing a staging table into a target

Quick Summary

  • ON CONFLICT … DO UPDATE / NOTHING
  • ON DUPLICATE KEY UPDATE (MySQL)
  • MERGE — standard sync
