HAVING & Conditional Aggregation

HAVING · WHERE vs HAVING · FILTER (WHERE) · SUM(CASE …) · COUNT(CASE …)

Filtering Groups

HAVING filters groups after aggregation, so it can test aggregates like count(*) >= 3. WHERE filters rows before grouping and can't. Conditional aggregation computes several filtered totals in one pass: the standard FILTER (WHERE …) clause attaches a condition to one aggregate, and SUM(CASE …) does the same on engines without FILTER. It's how you build pivot-style reports.

Filter Facts

  • Use WHERE for anything that doesn't need an aggregate
  • HAVING without GROUP BY treats all rows as one group
  • FILTER reads better than CASE
  • count(CASE … THEN 1 END) — no ELSE

NoSQL Comparison

  • MongoDB: HAVING is a $match stage after $group
  • [{ $group: { _id: '$customerId', n: { $sum: 1 } } }, { $match: { n: { $gte: 3 } } }]
  • Conditional sums: $sum: { $cond: [cond, 1, 0] }

HAVING & FILTER

-- Customers with 3+ orders
SELECT customer_id, count(*) AS n
FROM   orders
GROUP  BY customer_id
HAVING count(*) >= 3;

-- WHERE first, then HAVING
SELECT category, avg(price) AS avg_price
FROM   products
WHERE  stock > 0              -- rows
GROUP  BY category
HAVING avg(price) > 50;       -- groups

-- One pass, several filtered aggregates
SELECT customer_id,
       count(*)                                AS orders,
       count(*) FILTER (WHERE status = 'paid') AS paid,
       sum(total) FILTER (
         WHERE status = 'cancelled')           AS lost
FROM   orders
GROUP  BY customer_id;

-- Portable CASE form
SELECT customer_id,
       sum(CASE WHEN status = 'paid' THEN 1 ELSE 0 END)
         AS paid
FROM   orders
GROUP  BY customer_id;

Code Explained

HAVING count(*) >= 3 drops small groups
stock > 0 belongs in WHERE: it's per row
FILTER counts only the rows matching its condition
CASE returns 1 or 0 per row; sum adds them up

Dialect Notes

EngineSyntax / behavior

MySQLno FILTER → SUM(status = 'paid') (true = 1)

In an ORM

await prisma.order.groupBy({
  by: ['customerId'],
  _count: { _all: true },
  having: { customerId: { _count: { gte: 3 } } },
});

⚠ Common Mistakes

  • Putting row conditions in HAVING: same result, slower
  • Using an aggregate in WHERE (error)
  • SUM(CASE … END) without ELSE 0 and getting NULL

✓ Tips & Best Practices

  • Read it as: filter rows, group, filter groups
  • Build dashboards with one FILTER-based query
  • SQL Server: repeat the expression in HAVING, not the alias

Quick Summary

  • WHERE → rows · HAVING → groups
  • FILTER (WHERE …) per aggregate
  • SUM(CASE …) everywhere
