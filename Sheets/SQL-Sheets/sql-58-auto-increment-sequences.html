Auto-Increment & Sequences

GENERATED AS IDENTITY · SERIAL · AUTO_INCREMENT · IDENTITY(1,1) · CREATE SEQUENCE · nextval · gen_random_uuid

Generating Key Values

An identity column fills itself with the next number from a counter. The standard form is GENERATED ALWAYS AS IDENTITY (no manual values) or BY DEFAULT (manual values allowed). PostgreSQL's older SERIAL is a shortcut for an integer plus a sequence; MySQL uses AUTO_INCREMENT and SQL Server IDENTITY(1,1). A sequence is a standalone counter you call with nextval. UUIDs are the alternative when IDs must be created anywhere.

Sequence Facts

  • Numbers are never reused, so gaps are normal
  • Rolled-back inserts still consume a number
  • After loading explicit IDs, reset the counter
  • Prefer identity over SERIAL in new PostgreSQL code

NoSQL Comparison

  • MongoDB uses ObjectId by default; no auto-increment
  • Sequential numbers: a counter document updated with findOneAndUpdate({ $inc: { seq: 1 } })

Identity & Sequences

CREATE TABLE invoices (
  id        BIGINT GENERATED ALWAYS AS IDENTITY
            PRIMARY KEY,
  number    INT GENERATED BY DEFAULT AS IDENTITY
            (START WITH 1000),
  public_id UUID NOT NULL DEFAULT gen_random_uuid()
);
INSERT INTO invoices DEFAULT VALUES RETURNING *;
INSERT INTO invoices (id) VALUES (5);
-- ERROR: cannot insert a non-DEFAULT value into "id"
INSERT INTO invoices (id) OVERRIDING SYSTEM VALUE
VALUES (5);

-- Older style: integer + sequence + default
CREATE TABLE legacy (id SERIAL PRIMARY KEY);

-- Standalone sequence
CREATE SEQUENCE ticket_seq START 1;
SELECT nextval('ticket_seq');   -- 1
SELECT currval('ticket_seq');   -- 1 (this session)

-- Resync after loading explicit ids
SELECT setval(pg_get_serial_sequence('orders',
                                     'order_id'),
              (SELECT max(order_id) FROM orders));

Code Explained

ALWAYS rejects manual ids; BY DEFAULT accepts them
START WITH 1000 — invoice numbers begin at 1000
currval is per session: other sessions don't affect it
setval moves the counter past existing rows

model Invoice {
  id       BigInt @id @default(autoincrement())

}

⚠ Common Mistakes

  • Assuming IDs have no gaps (invoice audits!)
  • Bulk-loading ids without setval: duplicate key errors later
  • Exposing sequential ids in URLs when they shouldn't be guessable

✓ Tips & Best Practices

  • Need gap-free numbers? Use a counter table with row locking
  • Use BIGINT identities for large tables
  • Expose a UUID publicly, keep the integer internally

Quick Summary

  • GENERATED … AS IDENTITY (standard)
  • SERIAL · AUTO_INCREMENT · IDENTITY(1,1)
  • Sequences: nextval / setval
