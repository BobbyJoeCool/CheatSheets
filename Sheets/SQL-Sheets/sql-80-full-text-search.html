Full-Text Search

to_tsvector · to_tsquery · @@ · ts_rank · MATCH … AGAINST · FTS5

Searching Words, Not Characters

LIKE '%lamp%' matches characters; full-text search matches words. PostgreSQL turns text into a tsvector: normalized word stems ("jumped" → jump) with positions, minus stop words like "the". A tsquery describes what to find (desk & lamp), and @@ tests a match. Store the vector in a generated column, index it with GIN, and sort by ts_rank. MySQL uses FULLTEXT + MATCH … AGAINST, SQLite the FTS5 extension.

Search Facts

  • The language config ('english') controls stemming
  • websearch_to_tsquery accepts Google-style input
  • setweight ranks title hits above body hits
  • Typos need trigram fuzzy matching (pg_trgm)

NoSQL Comparison

  • MongoDB: createIndex({ name: 'text' }) + find({ $text: { $search: 'desk lamp' } })
  • Atlas Search (Lucene): relevance, fuzzy, autocomplete

tsvector & tsquery

SELECT to_tsvector('english',
                   'The quick brown foxes jumped');
-- 'brown':3 'fox':4 'jump':5 'quick':2

SELECT name FROM products
WHERE  to_tsvector('english', name)
       @@ to_tsquery('english', 'desk & lamp');

-- Store a weighted vector and index it
ALTER TABLE products ADD COLUMN search tsvector
  GENERATED ALWAYS AS (
    setweight(to_tsvector('english', name), 'A') ||
    setweight(to_tsvector('english',
              coalesce(category, '')), 'B')
  ) STORED;
CREATE INDEX products_search_gin
  ON products USING gin (search);
-- Ranked search with user-style input
SELECT name, ts_rank(search, q) AS rank
FROM   products,
       websearch_to_tsquery('english',
                            'led lamp -wood') AS q
WHERE  search @@ q
ORDER  BY rank DESC
LIMIT  10;

Code Explained

Stop word "the" is dropped; "foxes" stems to fox
& = AND inside to_tsquery
Name matches (weight A) outrank category matches (B)
-wood excludes; quotes would require a phrase

⚠ Common Mistakes

  • Using LIKE '%word%' on large text columns
  • Mixing language configs between vector and query
  • Computing to_tsvector per row at query time on big tables

✓ Tips & Best Practices

  • Store the vector in a generated column with a GIN index
  • Use websearch_to_tsquery for user input
  • ts_headline highlights matches for display
