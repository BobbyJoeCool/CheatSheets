Offset & Value Functions

LAG · LEAD · FIRST_VALUE · LAST_VALUE · NTH_VALUE · default offset

Looking at Other Rows

lag(x) returns x from the previous row in the window's order and lead(x) from the next one; both take an optional offset and a default for when no such row exists. That makes period-over-period changes a one-liner. first_value, last_value and nth_value return a value from a position in the frame. Watch last_value: the default frame stops at the current row, so you must widen it.

Offset Facts

  • lag(x, n, default) — n rows back
  • No previous row → NULL (or the default)
  • lag / lead ignore the frame; value functions don't
  • Partition so a customer's lag never reads another's row

NoSQL Comparison

  • MongoDB: $shift: { output: '$total', by: -1, default: 0 } = lag
  • $first / $last with a window give first / last value
  • Both run inside $setWindowFields

LAG, LEAD & Value Functions

-- Change from the previous order, per customer
SELECT customer_id, order_date, total,
       lag(total)         OVER w AS prev_total,
       total - lag(total) OVER w AS change,
       lead(order_date)   OVER w AS next_date
FROM   orders
WINDOW w AS (PARTITION BY customer_id
             ORDER BY order_date, order_id);

-- Offset and default
SELECT order_id, total,
       lag(total, 2, 0) OVER (ORDER BY order_id) AS two_back
FROM   orders;

-- First, last and 2nd in each department
SELECT first_name, dept_id, salary,
       first_value(first_name) OVER w AS top_paid,
       last_value(first_name)  OVER w AS lowest_paid,
       nth_value(first_name, 2) OVER w AS runner_up
FROM   employees
WINDOW w AS (PARTITION BY dept_id ORDER BY salary DESC
             ROWS BETWEEN UNBOUNDED PRECEDING
                      AND UNBOUNDED FOLLOWING);

Code Explained

total - lag(total) — growth from the last order
lag(total, 2, 0) — two rows back, 0 when missing
The full-partition frame makes last_value truly last
Without it, last_value ≈ the current row

⚠ Common Mistakes

  • last_value with the default frame
  • No PARTITION BY, so one customer's lag reads another's order
  • Ordering the window differently from the output

✓ Tips & Best Practices

  • Pass a default to lag / lead to avoid NULL math
  • Use lag(…) IS DISTINCT FROM x to spot changes
  • Percent change: (x - lag(x)) / nullif(lag(x), 0)

Quick Summary

  • lag / lead — previous / next row
  • first_value / last_value / nth_value
  • Widen the frame for last_value
