User-Defined Functions

CREATE FUNCTION · RETURNS · RETURNS TABLE · LANGUAGE sql · plpgsql · IMMUTABLE

Your Own Functions

CREATE FUNCTION packages logic you can call inside queries, like a built-in. A scalar function returns one value; a table function (RETURNS TABLE) returns rows and is used in FROM. PostgreSQL functions can be plain LANGUAGE sql (simple, often inlined) or plpgsql with variables, IF and loops. Mark volatility honestly: IMMUTABLE functions can be used in indexes, and the planner optimizes around the label.

Function Facts

  • Functions run inside the caller's transaction
  • They can't COMMIT; procedures can (sheet 66)
  • Overloading: same name, different argument types
  • $$ … $$ quotes the body without escaping

NoSQL Comparison

  • MongoDB has no user-defined query functions in practice
  • Logic lives in the app or in Atlas Functions
  • $function (server-side JS) exists but is discouraged

CREATE FUNCTION

-- Scalar SQL function (PG 14+ RETURN syntax)
CREATE FUNCTION with_tax(amount NUMERIC,
                         rate NUMERIC DEFAULT 0.08)
RETURNS NUMERIC LANGUAGE sql IMMUTABLE
RETURN round(amount * (1 + rate), 2);

SELECT name, with_tax(price) FROM products;
-- Table function
CREATE FUNCTION customer_orders(p_customer INT)
RETURNS TABLE (order_id INT, order_date DATE, total NUMERIC)
LANGUAGE sql STABLE AS $$
  SELECT order_id, order_date, total
  FROM   orders
  WHERE  customer_id = p_customer
$$;
SELECT * FROM customer_orders(7);

CREATE OR REPLACE FUNCTION loyalty_tier(p_id INT)
RETURNS TEXT LANGUAGE plpgsql STABLE AS $$
DECLARE spent NUMERIC;
BEGIN
  SELECT coalesce(sum(total), 0) INTO spent
  FROM   orders WHERE customer_id = p_id;
  RETURN CASE WHEN spent >= 1000 THEN 'gold'
              WHEN spent >= 250  THEN 'silver'
              ELSE 'bronze' END;
END $$;

Code Explained

DEFAULT 0.08 — rate can be left out
IMMUTABLE — same inputs, same result, no table reads
STABLE — reads tables; constant within one statement
SELECT … INTO spent stores a query result in a variable

⚠ Common Mistakes

  • Labeling a function IMMUTABLE when it reads tables
  • Calling a slow function per row in a big SELECT
  • Parameter names that clash with column names in PL/pgSQL

✓ Tips & Best Practices

  • Prefix parameters (p_) and variables (v_)
  • Prefer LANGUAGE sql for simple logic; it can be inlined
  • Version functions with your migrations

Quick Summary

  • CREATE FUNCTION … RETURNS …
  • Scalar or RETURNS TABLE
  • IMMUTABLE · STABLE · VOLATILE
