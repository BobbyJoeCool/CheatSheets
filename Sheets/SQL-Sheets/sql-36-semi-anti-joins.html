Semi & Anti Joins

EXISTS · NOT EXISTS · IN · LEFT JOIN … IS NULL · NOT IN NULL trap

"Has Any" and "Has None"

A semi-join returns rows from one table that have at least one match in another, without duplicating them. Write it with EXISTS or IN. An anti-join returns rows with no match: NOT EXISTS or LEFT JOIN … WHERE right.key IS NULL. Avoid NOT IN with a subquery: if the subquery returns a single NULL, NOT IN is never true and you get no rows at all.

Facts

  • EXISTS stops at the first match
  • SELECT 1 inside EXISTS is convention; the list is ignored
  • Semi-joins never duplicate the outer row
  • NOT EXISTS is NULL-safe; NOT IN isn't

NoSQL Comparison

  • MongoDB: $lookup, then $match: { orders: { $ne: [] } } (has any)
  • { orders: { $size: 0 } } for has none
  • Or keep an orderCount field on the customer

EXISTS, IN & Anti-Joins

-- Semi-join: customers who have ordered
SELECT c.name
FROM   customers c
WHERE  EXISTS (SELECT 1 FROM orders o
               WHERE o.customer_id = c.customer_id);

SELECT name FROM customers
WHERE  customer_id IN (SELECT customer_id FROM orders);

-- Anti-join: customers who never ordered
SELECT c.name
FROM   customers c
WHERE  NOT EXISTS (SELECT 1 FROM orders o
                   WHERE o.customer_id = c.customer_id);

SELECT c.name
FROM   customers c
LEFT   JOIN orders o ON o.customer_id = c.customer_id
WHERE  o.order_id IS NULL;

-- NOT IN trap: employees who manage nobody
SELECT first_name FROM employees
WHERE  emp_id NOT IN (SELECT manager_id FROM employees);
-- manager_id has a NULL (the CEO) → 0 rows!
SELECT first_name FROM employees e
WHERE  NOT EXISTS (SELECT 1 FROM employees r
                   WHERE r.manager_id = e.emp_id);

Code Explained

EXISTS and IN return each customer once, however many orders
o.order_id IS NULL keeps only unmatched left rows
x NOT IN (1, NULL) is UNKNOWN for every x
NOT EXISTS ignores the NULL and works

In an ORM

await prisma.customer.findMany({
  where: { orders: { some: {} } },   // EXISTS
});
await prisma.customer.findMany({
  where: { orders: { none: {} } },   // NOT EXISTS
});

Patterns

NOT IN (subquery)rows with no matchno

Pick One

NeedWrite
has at least oneEXISTS or IN
has noneNOT EXISTS
has none + right-side columnsLEFT JOIN … IS NULL
literal list without NULLsNOT IN (1, 2, 3) is fine

⚠ Common Mistakes

  • NOT IN (SELECT nullable_col …) returning nothing
  • Using JOIN for "has any" and getting duplicates
  • Testing a column that is never NULL in the anti-join IS NULL

✓ Tips & Best Practices

  • Default to EXISTS / NOT EXISTS for subquery tests
  • Index the foreign key the subquery looks up
  • In anti-joins, test the right table's primary key IS NULL

Quick Summary

  • Semi-join — EXISTS / IN
  • Anti-join — NOT EXISTS / LEFT JOIN … IS NULL
  • Avoid NOT IN with subqueries
