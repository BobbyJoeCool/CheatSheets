Correlated Subqueries

correlated subquery · outer reference · EXISTS · per-row evaluation · rewrite as join

Subqueries That Look Outward

A correlated subquery refers to a column of the outer query (p.category below), so logically it runs once per outer row. That's how you compare each row with its own group: products priced above their category's average, or each customer's latest order date. Planners often rewrite these into joins, but not always. When one is slow, rewrite it as a join to a grouped derived table, a window function or a LATERAL join (sheet 37).

Facts

  • You can't run a correlated subquery on its own
  • EXISTS subqueries are almost always correlated
  • Outer aliases must be unique to avoid confusion
  • Slow? Check the plan for a per-row SubPlan (sheet 73)

NoSQL Comparison

  • MongoDB $lookup with let + a pipeline using $expr is correlated
  • Each document's values feed the inner pipeline
  • Same per-document cost: index the inner match field

Correlated Subqueries

-- Products above their own category's average
SELECT p.name, p.category, p.price
FROM   products p
WHERE  p.price > (SELECT avg(x.price)
                  FROM   products x
                  WHERE  x.category = p.category);

-- Rewrite 1: join a grouped derived table
SELECT p.name, p.category, p.price
FROM   products p
JOIN  (SELECT category, avg(price) AS avg_price
       FROM   products GROUP BY category) a
  ON   a.category = p.category
WHERE  p.price > a.avg_price;

-- Rewrite 2: window function, one pass
SELECT name, category, price
FROM  (SELECT *, avg(price) OVER w AS cat_avg
       FROM products WINDOW w AS (PARTITION BY category)) t
WHERE  price > cat_avg;

Code Explained

x.category = p.category — the outer reference
Logically the subquery reruns for every product row
Rewrite 1 computes each average once, then joins
Rewrite 2 attaches the average to every row (sheet 44)

⚠ Common Mistakes

  • Reusing the same alias inside and outside (p and p)
  • A per-row scalar subquery over a big table with no index
  • Assuming every engine flattens it into a join

✓ Tips & Best Practices

  • Index the inner lookup column (orders.customer_id)
  • Compare plans of the subquery and rewritten forms
  • Keep correlated subqueries for clarity on small sets

Quick Summary

  • Inner query references outer row
  • Logically runs per row
  • Rewrite with joins or windows when slow
