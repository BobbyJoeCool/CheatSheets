Databases, Schemas & the Catalog

CREATE DATABASE · CREATE SCHEMA · search_path · USE · information_schema · \d

Where Tables Live

A server holds databases; in PostgreSQL and SQL Server each database holds schemas (namespaces such as public or dbo), and schemas hold tables. Refer to a table as schema.table, or let search_path (PG) or the default schema find it. The catalog is the database describing itself: the standard information_schema views, plus engine-specific ones (pg_catalog, sys), list every table, column and constraint.

Catalog Facts

  • MySQL "schema" and "database" mean the same thing
  • Cross-database queries: SQL Server yes, PG no
  • information_schema is portable but slow
  • Engine catalogs show more detail

NoSQL Comparison

  • MongoDB: server → databases → collections
  • use shop, show collections, db.getCollectionInfos()
  • db.orders.getIndexes() lists indexes

Databases, Schemas & Catalog

CREATE DATABASE shop;            -- server level
\c shop                          -- psql: connect to it

CREATE SCHEMA sales;             -- namespace in a DB
CREATE TABLE sales.invoices (id INT);
SET search_path TO sales, public;
SELECT * FROM invoices;          -- finds sales.invoices

-- Which tables exist?
SELECT table_schema, table_name
FROM   information_schema.tables
WHERE  table_schema = 'public';

-- Columns of one table
SELECT column_name, data_type, is_nullable, column_default
FROM   information_schema.columns
WHERE  table_name = 'orders'
ORDER  BY ordinal_position;

-- Foreign keys pointing at customers (PG catalog)
SELECT conname, conrelid::regclass AS from_table
FROM   pg_constraint
WHERE  confrelid = 'customers'::regclass;

SELECT pg_size_pretty(pg_total_relation_size('orders'));

Code Explained

search_path sets the lookup order for unqualified names
information_schema — standard views in PG, MySQL, SQL Server
::regclass turns a table name into its catalog id
pg_total_relation_size includes indexes and TOAST

⚠ Common Mistakes

  • Creating tables in public by accident (wrong search_path)
  • Hard-coding dbo. or public. everywhere
  • Querying information_schema in a hot path

✓ Tips & Best Practices

  • Group related tables per schema; grant per schema (sheet 75)
  • Use the catalog to generate docs and checks
  • Keep one database per app, not per customer, unless you must

Quick Summary

  • Database › schema › table
  • search_path / USE for defaults
  • information_schema + engine catalogs
