Sorting with ORDER BY

ORDER BY · ASC · DESC · NULLS FIRST/LAST · multiple keys · ordinal position · COLLATE

Putting Rows in Order

Without ORDER BY, row order is whatever the engine finds fastest and can change between runs. ASC (the default) sorts low to high, DESC high to low. With several keys, later keys only break ties in earlier ones. NULLS FIRST / NULLS LAST decide where NULLs land. You can sort by aliases, expressions, a CASE for custom orders, or a column's position number (avoid that one).

Sorting Facts

  • ORDER BY runs after SELECT, so aliases work
  • Each key has its own direction: a DESC, b ASC
  • Text sorts by collation (sheet 08)
  • Add a unique key last for repeatable order

NoSQL Comparison

  • MongoDB: .sort({ category: 1, price: -1 })
  • null and missing fields sort before numbers ascending
  • No positional sorting; name the field

ORDER BY

SELECT name, price FROM products
ORDER  BY price DESC;                 -- high → low

SELECT name, category, price FROM products
ORDER  BY category, price DESC;       -- ties → price

SELECT name, city FROM customers
ORDER  BY city NULLS FIRST;           -- PG default: last

SELECT name, price * stock AS value FROM products
ORDER  BY value DESC;                 -- alias OK

SELECT name, price FROM products
ORDER  BY 2 DESC;                     -- 2nd column

-- Custom order with CASE
SELECT order_id, status FROM orders
ORDER  BY CASE status WHEN 'pending' THEN 1
                      WHEN 'paid'    THEN 2
                      ELSE 3 END,
          order_id;

SELECT name FROM customers
ORDER  BY lower(name), customer_id;   -- expression

Code Explained

category with no direction is ASC
NULLS FIRST overrides PostgreSQL's NULLs-last default
ORDER BY 2 breaks silently when the column list changes
CASE maps each status to a sort rank

Dialect Notes

In an ORM

await prisma.product.findMany({
  orderBy: [
    { category: 'asc' },
    { price: { sort: 'desc', nulls: 'last' } },
  ],
});

⚠ Common Mistakes

  • Expecting insertion order without ORDER BY
  • ORDER BY inside a view or subquery: the outer query can ignore it
  • Sorting numbers stored as text: '10' before '9'

✓ Tips & Best Practices

  • End every paged sort with a unique column (sheet 16)
  • An index in the same order can skip the sort step (sheet 71)
  • Name columns instead of using ordinals

Quick Summary

  • Only ORDER BY guarantees order
  • ASC default · DESC reverse
  • NULLS FIRST / LAST where supported
