CASE Expressions

simple CASE · searched CASE · ELSE · CASE in ORDER BY · CASE in aggregates · IIF

If / Else Inside a Query

CASE is SQL's if/else. It's an expression, so it returns a value and can go anywhere a value can: SELECT, WHERE, ORDER BY, GROUP BY, inside an aggregate, or in UPDATE … SET. A searched CASE tests any condition; a simple CASE compares one value to a list. Branches are checked top to bottom and the first match wins; with no match and no ELSE, the result is NULL.

CASE Facts

  • All branches must return compatible types
  • Missing ELSE → NULL
  • Simple CASE x WHEN NULL never matches
  • IIF(c, a, b) is shorthand (SQL Server, SQLite)

NoSQL Comparison

  • MongoDB: $cond: { if: …, then: …, else: … }
  • $switch: { branches: [{ case, then }], default } for many branches
  • Both work only inside aggregation pipelines

CASE

-- Searched CASE: any conditions
SELECT name, price,
       CASE WHEN price >= 100 THEN 'premium'
            WHEN price >= 20  THEN 'standard'
            ELSE 'budget'
       END AS tier
FROM   products;

-- Simple CASE: compare one value
SELECT order_id,
       CASE status WHEN 'paid'    THEN 'Paid'
                   WHEN 'shipped' THEN 'On its way'
                   ELSE 'Other' END AS label
FROM   orders;

-- Inside aggregates: several counts in one pass
SELECT count(CASE WHEN status = 'paid' THEN 1 END) AS paid,
       sum(CASE WHEN status = 'cancelled'
                THEN total ELSE 0 END)   AS lost
FROM   orders;
-- In ORDER BY and UPDATE
SELECT name FROM products
ORDER  BY CASE WHEN stock = 0 THEN 1 ELSE 0 END, name;
UPDATE products
SET    price = CASE WHEN category = 'Books'
                    THEN price * 0.9 ELSE price END;

Code Explained

Order matters: a 150 price stops at premium
count(CASE … THEN 1 END) counts only matches (no ELSE)
ORDER BY CASE pushes out-of-stock items to the end
ELSE price keeps other rows unchanged

In an ORM

// Prisma has no CASE builder: use raw SQL
const rows = await prisma.$queryRaw`
  SELECT name,
         CASE WHEN price >= 100 THEN 'premium'
              ELSE 'standard' END AS tier
  FROM   products`;

⚠ Common Mistakes

  • No ELSE and an unexpected NULL
  • Mixed branch types: THEN 'none' vs THEN 0
  • Putting a broad WHEN first so later ones never fire

✓ Tips & Best Practices

  • Most specific WHEN first
  • Long code → label mappings belong in a lookup table
  • PG: count(*) FILTER (WHERE …) reads better than CASE

Quick Summary

  • CASE WHEN … THEN … ELSE … END
  • First match wins; no match → ELSE or NULL
  • Works in any clause
