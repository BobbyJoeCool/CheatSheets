The Relational Model

Data lives in tables: each row is one fact, each column one typed attribute. A primary key identifies a row; a foreign key points at another table's key, and links to missing rows are rejected. Every later example uses this shop schema: customers place orders of products; employees belong to departments and report to a manager.

Terms

  • Table = relation · row = tuple · column = attribute
  • Primary key — unique and never NULL
  • Foreign key — must match a parent key
  • Composite key — 2+ columns (order_items)

NoSQL Comparison

  • MongoDB would embed order items inside each order document
  • Customers and products stay separate, referenced by _id
  • No foreign keys: the app keeps references valid

Schema Script (PostgreSQL)

CREATE TABLE departments (
  dept_id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name    VARCHAR(50) NOT NULL UNIQUE,
  budget  NUMERIC(12,2)
);
CREATE TABLE employees (
  emp_id  INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  first_name VARCHAR(50)  NOT NULL,
  last_name  VARCHAR(50)  NOT NULL,
  email      VARCHAR(255) NOT NULL UNIQUE,
  dept_id    INT REFERENCES departments,
  manager_id INT REFERENCES employees,
  hire_date  DATE NOT NULL,
  salary     NUMERIC(10,2)
);
CREATE TABLE customers (
  customer_id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name        VARCHAR(100) NOT NULL,
  email       VARCHAR(255) UNIQUE,
  city        VARCHAR(50),
  country     CHAR(2),
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);

Schema Script (continued)

CREATE TABLE products (
  product_id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name       VARCHAR(100)  NOT NULL,
  category   VARCHAR(50),
  price      NUMERIC(10,2) NOT NULL CHECK (price >= 0),
  stock      INT NOT NULL DEFAULT 0
);
CREATE TABLE orders (
  order_id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  customer_id INT NOT NULL REFERENCES customers,
  order_date  DATE NOT NULL DEFAULT CURRENT_DATE,
  status      VARCHAR(20) NOT NULL DEFAULT 'pending',
  total       NUMERIC(10,2)
);
CREATE TABLE order_items (
  order_id   INT REFERENCES orders ON DELETE CASCADE,
  product_id INT REFERENCES products,
  quantity   INT NOT NULL CHECK (quantity > 0),
  unit_price NUMERIC(10,2) NOT NULL,
  PRIMARY KEY (order_id, product_id)
);

In an ORM (Prisma schema)

model Order {
  id         Int      @id @default(autoincrement()) @map("order_id")
  customerId Int      @map("customer_id")
  customer   Customer @relation(fields: [customerId], references: [id])
  items      OrderItem[]
  @@map("orders")
}

⚠ Common Mistakes

  • Storing a list in one column ('1,4,9')
  • Assuming SQLite enforces foreign keys by default
  • Using a changeable value (email) as the primary key

✓ Tips & Best Practices

  • orders.total is a stored copy of the item sum; sheet 61 covers the trade-off
  • status values: pending, paid, shipped, cancelled
  • ORM boxes use camelCase Prisma fields mapped to these columns
