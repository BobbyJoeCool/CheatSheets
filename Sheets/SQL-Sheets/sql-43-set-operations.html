Set Operations

UNION · UNION ALL · INTERSECT · EXCEPT · MINUS · column & type compatibility · ORDER BY placement

Combining Result Sets

Set operators combine the rows of two queries vertically. UNION ALL stacks them as they are; UNION stacks and removes duplicates; INTERSECT keeps rows present in both; EXCEPT (Oracle: MINUS) keeps rows in the first but not the second. Both queries must return the same number of columns with compatible types, matched by position. Column names come from the first query, and one ORDER BY at the end sorts the whole result.

Set Facts

  • UNION ALL is cheapest: no duplicate check
  • INTERSECT binds tighter than UNION / EXCEPT
  • Set operators treat NULLs as equal
  • Joins combine sideways; set ops combine downward

NoSQL Comparison

  • MongoDB: $unionWith appends another collection (UNION ALL)
  • $setUnion, $setIntersection, $setDifference work on arrays
  • No INTERSECT between collections; use $lookup

Set Operations

-- Everyone we can email
SELECT email, 'customer' AS kind FROM customers
UNION ALL
SELECT email, 'employee'         FROM employees
ORDER  BY email;               -- sorts everything

SELECT city FROM customers WHERE country = 'US'
UNION                          -- no duplicates
SELECT city FROM customers WHERE country = 'CA';

-- Customers who ordered in both September and October
SELECT customer_id FROM orders
WHERE  date_trunc('month', order_date) = '2026-09-01'
INTERSECT
SELECT customer_id FROM orders
WHERE  date_trunc('month', order_date) = '2026-10-01';

-- Products never ordered
SELECT product_id FROM products
EXCEPT
SELECT product_id FROM order_items;

-- Parentheses control grouping
(SELECT 1 UNION SELECT 2) EXCEPT SELECT 2;     -- 1

Code Explained

kind labels which query each row came from
ORDER BY after the last query sorts the combined rows
INTERSECT returns each matching customer once
EXCEPT = rows in the first result missing from the second

⚠ Common Mistakes

  • UNION when UNION ALL was meant: slower, rows vanish
  • Columns in a different order in the second query
  • ORDER BY inside the first query (error or ignored)

✓ Tips & Best Practices

  • Default to UNION ALL; add dedupe only if needed
  • Add a literal kind column to tell sources apart
  • NOT EXISTS is often faster than EXCEPT on big tables

Quick Summary

  • UNION [ALL] · INTERSECT · EXCEPT
  • Same column count, compatible types
  • One ORDER BY at the end
