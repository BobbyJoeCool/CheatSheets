String Functions — Search & Extract

SUBSTRING · LEFT · RIGHT · POSITION · STRPOS · REPLACE · SPLIT_PART · REVERSE

Finding and Cutting Text

position(sub IN s) (or strpos) returns where a substring starts, counting from 1, and 0 when it's absent. substring, left and right cut out pieces by position. split_part splits on a delimiter and returns the nth field, which is the quickest way to pull the domain out of an email. replace swaps every occurrence of one substring for another, and reverse flips the string.

Search Facts

  • Positions start at 1, not 0
  • Not found → 0, not NULL
  • replace is case-sensitive
  • translate swaps or deletes single characters

NoSQL Comparison

  • MongoDB: $indexOfCP, $substrCP, $split, $replaceAll
  • $split returns an array; take a field with $arrayElemAt
  • $regexFind extracts with a regex

Search & Extract

SELECT email,
       left(email, 1)             AS first_char,
       right(email, 4)            AS last_four,
       position('@' IN email)     AS at_pos,
       split_part(email, '@', 1)  AS local_part,
       split_part(email, '@', 2)  AS domain
FROM   customers;

SELECT substring('2026-10-18' FROM 1 FOR 4); -- 2026
SELECT substring('2026-10-18', 6, 2);        -- 10
SELECT strpos('banana', 'an');               -- 2
SELECT position('z' IN 'banana');            -- 0
SELECT replace('2026-10-18', '-', '/');     -- 2026/10/18
SELECT split_part('a,b,c', ',', -1);        -- c (PG 14+)
SELECT reverse('stressed');                 -- desserts
SELECT translate('(555) 123-4567', '() -', '');
-- 5551234567

SELECT name FROM products
WHERE  position('lamp' IN lower(name)) > 0;

Code Explained

split_part(email, '@', 2) — everything after the @
substring(s FROM i FOR n) — standard; (s, i, n) also works
Negative split_part index counts from the end
translate with an empty target deletes those characters

⚠ Common Mistakes

  • Treating a 0 result from position as "found at the start"
  • Parsing structured data (JSON, CSV) with string functions
  • Off-by-one slicing from 0-based habits

✓ Tips & Best Practices

  • Store parts separately if you query them often (email_domain)
  • Use JSON functions for JSON (sheet 78)
  • For complex patterns reach for regex (sheet 19)
