DELETE & TRUNCATE

DELETE · DELETE … USING · TRUNCATE · RESTART IDENTITY · CASCADE · soft delete

Removing Rows

DELETE FROM table WHERE … removes matching rows one by one: triggers fire, foreign keys are checked, and it can be rolled back. TRUNCATE empties a whole table at once, much faster, and can reset identity counters; it has no WHERE. Many apps prefer a soft delete: set a deleted_at timestamp and filter it out, so history and references survive. Removing the table itself is DROP TABLE (sheet 59).

Delete Facts

  • No WHERE = every row
  • FK ON DELETE CASCADE deletes child rows too (sheet 56)
  • Deleted space is reused later, not returned at once
  • TRUNCATE skips row-level triggers

NoSQL Comparison

  • MongoDB: deleteMany(filter); drop() removes the collection
  • Soft delete: { $set: { deletedAt: new Date() } }
  • A TTL index deletes expired documents automatically

DELETE & TRUNCATE

DELETE FROM orders
WHERE  status = 'cancelled'
  AND  order_date < DATE '2026-01-01'
RETURNING order_id;

-- Delete using another table (PostgreSQL)
DELETE FROM order_items i
USING  products p
WHERE  p.product_id = i.product_id
  AND  p.category = 'Discontinued';

-- Portable form
DELETE FROM order_items
WHERE  product_id IN (SELECT product_id FROM products
                      WHERE  category = 'Discontinued');

-- Empty tables fast
TRUNCATE order_items, orders RESTART IDENTITY;
TRUNCATE customers CASCADE;  -- + tables referencing it

-- Soft delete: hide instead of destroy
ALTER TABLE customers ADD COLUMN deleted_at TIMESTAMPTZ;
UPDATE customers SET deleted_at = now()
WHERE  customer_id = 42;
SELECT * FROM customers WHERE deleted_at IS NULL;

Code Explained

RETURNING lists exactly what was removed
USING joins products to choose which items go
RESTART IDENTITY resets the ID counters to 1
Soft-deleted rows stay; queries filter them out

⚠ Common Mistakes

  • DELETE without WHERE (or with the wrong one)
  • Deleting millions of rows in one transaction
  • Soft delete without updating unique constraints

✓ Tips & Best Practices

  • Delete in batches: WHERE id IN (SELECT … LIMIT 10000)
  • Preview with SELECT count(*) and the same WHERE
  • Use TRUNCATE for staging tables between loads

Quick Summary

  • DELETE … WHERE — some rows
  • TRUNCATE — all rows, fast
  • Soft delete — deleted_at
