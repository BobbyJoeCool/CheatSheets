CREATE TABLE

CREATE TABLE · column definitions · DEFAULT · IF NOT EXISTS · CREATE TABLE AS · TEMPORARY

Defining a Table

CREATE TABLE names a table and lists its columns, each with a type and optional rules: NOT NULL, a DEFAULT, keys and checks. IF NOT EXISTS makes scripts safe to re-run. CREATE TABLE … AS SELECT builds and fills a table from a query, but copies no keys, defaults or indexes. Temporary tables live for one session, which is handy for scratch work.

Table Facts

  • Constraints can be per column or listed at the end
  • DEFAULT applies only when the column is omitted
  • AS SELECT copies data, not constraints
  • Generated columns compute from other columns

NoSQL Comparison

  • MongoDB creates a collection on first insert
  • createCollection('reviews', { validator: { $jsonSchema: … } }) adds rules
  • Without a validator, any document shape is accepted

CREATE TABLE

CREATE TABLE IF NOT EXISTS reviews (
  review_id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  product_id  INT NOT NULL REFERENCES products,
  customer_id INT NOT NULL REFERENCES customers,
  rating      SMALLINT NOT NULL
              CHECK (rating BETWEEN 1 AND 5),
  body        TEXT,
  body_len    INT GENERATED ALWAYS AS
              (length(body)) STORED,
  is_public   BOOLEAN NOT NULL DEFAULT true,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- Structure + data from a query
CREATE TABLE big_orders AS
SELECT * FROM orders WHERE total > 1000;

-- Same columns, defaults, indexes; no rows
CREATE TABLE orders_2027 (LIKE orders INCLUDING ALL);

-- Scratch table for this session only
CREATE TEMP TABLE cart (product_id INT, qty INT);

Code Explained

REFERENCES products points at its primary key
GENERATED … STORED — computed on write, read-only
DEFAULT now() fills the time when created_at is omitted
LIKE … INCLUDING ALL copies structure, not data

⚠ Common Mistakes

  • Expecting CREATE TABLE AS to copy keys and indexes
  • IF NOT EXISTS hiding a table with a different definition
  • Forgetting NOT NULL and getting half-empty rows

✓ Tips & Best Practices

  • Make columns NOT NULL unless NULL means something
  • Keep DDL in versioned migration files
  • Name tables plural snake_case (sheet 63)
