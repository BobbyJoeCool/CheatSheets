INSERT

INSERT INTO · VALUES · multi-row insert · INSERT … SELECT · DEFAULT · RETURNING

Adding Rows

INSERT INTO table (columns) VALUES (…) adds rows. Always list the columns: omitted ones get their default (or NULL), and the statement survives new columns being added later. One VALUES list can hold many rows, which is far faster than one statement per row. INSERT … SELECT copies rows produced by a query. RETURNING hands back generated values such as the new ID, so you don't need a second query.

INSERT Facts

  • Values match the column list by position
  • DEFAULT uses the column default explicitly
  • Identity ALWAYS columns can't be given a value
  • A failed row fails the whole statement

NoSQL Comparison

  • MongoDB: insertOne(doc) and insertMany([docs])
  • _id is generated client-side, returned as insertedId
  • No column list: each document carries its own fields

INSERT

INSERT INTO customers (name, email, city, country)
VALUES ('Ada Lovelace', 'ada@example.com', 'London', 'GB');

-- Several rows in one statement
INSERT INTO products (name, category, price, stock)
VALUES ('Desk Lamp', 'Lighting',   39.99,  25),
       ('Bookshelf', 'Furniture', 129.00,   4),
       ('Notebook',  'Stationery',  4.50, 300);

-- Column default, explicitly
INSERT INTO orders (customer_id, status, total)
VALUES (1, DEFAULT, 59.98);           -- 'pending'

-- Get generated values back
INSERT INTO orders (customer_id, total)
VALUES (1, 59.98)
RETURNING order_id, order_date;

-- Copy rows from a query (same columns)
INSERT INTO archived_orders (order_id, customer_id, total)
SELECT order_id, customer_id, total
FROM   orders
WHERE  order_date < DATE '2025-01-01';

Code Explained

customer_id and created_at are filled by defaults
Three rows, one round trip, one transaction
RETURNING returns the identity value and default date
INSERT … SELECT has no VALUES keyword

⚠ Common Mistakes

  • INSERT INTO t VALUES (…) without columns breaks when a column is added
  • Inserting in a loop: thousands of round trips
  • Sending numbers as text and relying on implicit casts

✓ Tips & Best Practices

  • Batch inserts: hundreds to a few thousand rows per statement
  • Use parameters, never string-built values (sheet 76)
  • For files and huge loads, use COPY (sheet 54)

Quick Summary
