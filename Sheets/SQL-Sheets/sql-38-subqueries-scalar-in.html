Subqueries — Scalar & IN

scalar subquery · IN (subquery) · ANY · ALL · subquery in SELECT

Queries Inside Queries

A subquery is a SELECT in parentheses used inside another statement. A scalar subquery returns one row and one column, so it can stand in for a value anywhere; zero rows give NULL and two or more rows are an error. A column subquery returns a list for IN, ANY or ALL. A subquery that doesn't reference the outer query runs once.

Subquery Facts

  • Always wrap subqueries in parentheses
  • = ANY (…) is the same as IN (…)
  • > ALL of an empty set is true for every row
  • Referencing the outer query makes it correlated (sheet 39)

NoSQL Comparison

  • MongoDB has no inline subqueries: run two queries
  • Or compute the comparison value in the pipeline:
  • $setWindowFields / $group, then $match with $expr

Scalar & IN Subqueries

-- Products priced above the average
SELECT name, price
FROM   products
WHERE  price > (SELECT avg(price) FROM products);

-- Scalar subquery as a column
SELECT name, price,
       price - (SELECT avg(price) FROM products) AS vs_avg
FROM   products;

-- IN: orders from Canadian customers
SELECT order_id, total
FROM   orders
WHERE  customer_id IN (SELECT customer_id
                       FROM   customers
                       WHERE  country = 'CA');

-- ALL / ANY
SELECT name FROM products
WHERE  price > ALL (SELECT price FROM products
                    WHERE  category = 'Books');
SELECT name FROM products
WHERE  price = ANY (SELECT unit_price FROM order_items);

SELECT (SELECT order_id FROM orders);
-- ERROR: more than one row returned by a subquery

Code Explained

(SELECT avg(price) …) runs once; its value is reused
IN (SELECT …) builds the list of Canadian customer IDs
> ALL (…) — pricier than every book
A scalar subquery must return at most one row

In an ORM

const { _avg } = await prisma.product.aggregate({
  _avg: { price: true },
});
await prisma.product.findMany({
  where: { price: { gt: _avg.price ?? 0 } },
});

ANY / ALL

ExpressionTrue when
x > ANY (s)x beats at least one value
x > ALL (s)x beats every value
x = ANY (s)same as x IN (s)
x <> ALL (s)same as x NOT IN (s) (NULL trap)
x > ALL (empty)always true

⚠ Common Mistakes

  • A "scalar" subquery that sometimes returns two rows
  • > ALL against an empty set matching everything
  • Repeating the same scalar subquery in five places

✓ Tips & Best Practices

  • Name a repeated subquery once with a CTE (sheet 41)
  • Prefer EXISTS for big correlated lists (sheet 36)
  • Add LIMIT 1 / max() when one row must win

Quick Summary

  • Scalar → one value
  • Column → IN / ANY / ALL
  • Uncorrelated → runs once
