Sheet 07

Numeric Types

INTEGER · BIGINT · SMALLINT · NUMERIC(p,s) · DECIMAL · REAL · DOUBLE PRECISION

Exact vs Approximate

Integers (SMALLINT, INTEGER, BIGINT) hold whole numbers exactly. NUMERIC(p,s) (same as DECIMAL) holds exact decimals: p digits in total, s after the point, so it is the type for money. REAL and DOUBLE PRECISION are binary floating point: fast and compact but approximate, so 0.1 + 0.2 is not quite 0.3. A value that doesn't fit raises an error; nothing wraps around.

Number Facts

  • NUMERIC = DECIMAL in every engine here
  • Casting to fewer decimals rounds
  • int / int drops the fraction (sheet 20)
  • No UNSIGNED in PostgreSQL; use CHECK (x >= 0)

NoSQL Comparison

  • MongoDB numbers are double unless you say otherwise
  • NumberInt / NumberLong for int32 / int64
  • Decimal128 for money; JSON itself has one number type

Numeric Types

CREATE TABLE measurements (
  id        BIGINT GENERATED ALWAYS AS IDENTITY,
  qty       SMALLINT,          -- ±32,767
  stock     INTEGER,           -- ±2.1 billion
  price     NUMERIC(10,2),     -- max 99,999,999.99
  weight_kg DOUBLE PRECISION   -- ~15 digits, approx
);

SELECT 0.1 + 0.2 = 0.3;                  -- true
SELECT 0.1::float8 + 0.2::float8 = 0.3;  -- false
SELECT 12.345::NUMERIC(5,2);             -- 12.35
SELECT 1234.5::NUMERIC(5,2);
-- ERROR: numeric field overflow
SELECT 2147483647::INT + 1;
-- ERROR: integer out of range
SELECT 7 / 2, 7 / 2.0;            -- 3 | 3.5000000000000000
SELECT pg_typeof(7), pg_typeof(7.0);  -- integer | numeric

Code Explained

NUMERIC(10,2) — 10 digits total, 2 after the point
Plain 0.1 is a numeric literal in PostgreSQL, so it's exact
float8 = DOUBLE PRECISION: binary, 15–17 significant digits
7 / 2 is integer division; one decimal operand fixes it

⚠ Common Mistakes

  • Using FLOAT for money and getting 19.989999999 totals
  • INTEGER keys running out at 2.1 billion rows
  • SQL Server AVG(int_col) returns an integer; cast to decimal first

✓ Tips & Best Practices

  • Always give NUMERIC a precision and scale
  • Use BIGINT keys for tables that grow without limit
  • Compare floats with a tolerance: abs(a - b) < 1e-9

Quick Summary

  • Whole numbers — INTEGER / BIGINT
  • Exact decimals — NUMERIC(p,s)
  • Approximate — REAL / DOUBLE PRECISION
  • Overflow — an error, never a wrap
