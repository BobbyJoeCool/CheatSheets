Boolean, Binary, UUID & Enum Types

BOOLEAN · BIT · BYTEA · BLOB · UUID · ENUM · CREATE TYPE

The Other Types

BOOLEAN holds true, false or NULL. Binary types (BYTEA, BLOB) hold raw bytes such as hashes or small files. UUID is a 128-bit identifier you can generate anywhere without coordination: v4 is random, v7 starts with a timestamp so new values sort together. An enum limits a column to a fixed list of labels; in PostgreSQL you create it once with CREATE TYPE and reuse it.

Facts

  • WHERE is_active is enough; no = true needed
  • Enum values sort in declared order
  • PG can add enum values but not drop them
  • uuidv7() is built in from PostgreSQL 18

NoSQL Comparison

  • MongoDB has bool and BinData; ObjectId plays the UUID role
  • ObjectId starts with a timestamp, like UUIDv7
  • Enums are enforced with $jsonSchema enum: [...]

Boolean, Binary, UUID & Enum

CREATE TYPE order_status AS ENUM
  ('pending', 'paid', 'shipped', 'cancelled');

CREATE TABLE payments (
  payment_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  status     order_status NOT NULL DEFAULT 'pending',
  is_refund  BOOLEAN NOT NULL DEFAULT false,
  receipt    BYTEA
);

SELECT * FROM payments WHERE is_refund;
SELECT * FROM payments WHERE NOT is_refund;
SELECT 'yes'::boolean, 'f'::boolean;     -- t | f
SELECT * FROM payments ORDER BY status;  -- enum order
ALTER TYPE order_status ADD VALUE 'refunded'
  AFTER 'shipped';

SELECT gen_random_uuid();   -- v4: random
SELECT uuidv7();            -- PG 18+: time-ordered
SELECT decode('DEADBEEF', 'hex');        -- \xdeadbeef

Code Explained

CREATE TYPE … AS ENUM — reusable type with fixed labels
DEFAULT gen_random_uuid() — the database fills the key
Boolean input accepts true/false, yes/no, t/f, 1/0
decode(…, 'hex') turns a hex string into bytes

In an ORM

enum OrderStatus { pending paid shipped cancelled }
model Payment {
  id       String      @id @default(uuid(7)) @db.Uuid
  status   OrderStatus @default(pending)
  isRefund Boolean     @default(false)
}

⚠ Common Mistakes

  • Random v4 UUID keys scattering inserts across a big index
  • Storing UUIDs as VARCHAR(36): 2× the space, slower joins
  • Needing to remove an enum value later; PG can't drop one

✓ Tips & Best Practices

  • Name booleans as questions: is_active, has_paid
  • Prefer CHECK or a lookup table when values may change
  • Use the native UUID type, or BINARY(16) in MySQL

Quick Summary

  • BOOLEAN — true / false / NULL
  • BYTEA / BLOB — raw bytes
  • UUID — v4 random, v7 time-ordered
  • Enum — fixed label list
