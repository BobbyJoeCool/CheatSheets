Multi-Table Joins

3+ table joins · junction table · join fan-out · duplicate rows · join order

Chaining Joins

Joins chain left to right: each JOIN adds a table to the rows built so far. A junction table (order_items) links two tables in a many-to-many relationship, so going from orders to products takes two joins. The big risk is fan-out: joining a parent to a child repeats the parent once per child row, so summing a parent column after the join counts it many times. The fix is to aggregate the child first, then join.

Multi-Join Facts

  • The planner picks join order; write it for readers
  • Each join should follow a key relationship
  • Two child tables at once multiply each other
  • DISTINCT hides fan-out; it doesn't fix it

NoSQL Comparison

  • Chained $lookup stages work but get slow
  • Typical design embeds order items, copying name and price
  • Copied data is a snapshot: it doesn't follow later changes

Multi-Table Joins

-- Order lines with customer and product names
SELECT o.order_id, c.name AS customer,
       p.name AS product, i.quantity, i.unit_price
FROM   orders o
JOIN   customers   c ON c.customer_id = o.customer_id
JOIN   order_items i ON i.order_id    = o.order_id
JOIN   products    p ON p.product_id  = i.product_id
WHERE  o.order_date >= DATE '2026-10-01';

-- Fan-out: o.total repeats once per order item
SELECT c.name, sum(o.total) AS spent        -- WRONG
FROM   customers c
JOIN   orders o      USING (customer_id)
JOIN   order_items i USING (order_id)
GROUP  BY c.name;

-- Fix: aggregate the child first, then join
SELECT c.name, sum(o.total) AS spent,
       sum(q.items)          AS items
FROM   customers c
JOIN   orders o USING (customer_id)
JOIN   (SELECT order_id, sum(quantity) AS items
        FROM order_items GROUP BY order_id) q
       USING (order_id)
GROUP  BY c.name;

Code Explained

Each JOIN … ON follows one foreign key
An order with 3 items appears 3 times after the item join
sum(o.total) then counts that order 3 times
The derived table returns one row per order (sheet 40)

⚠ Common Mistakes

  • Summing a parent column after joining its children
  • Joining two unrelated child tables in one query
  • Missing one join condition among many

✓ Tips & Best Practices

  • Line up JOIN and ON clauses so missing keys stand out
  • Check row counts after each added join
  • Pre-aggregate in CTEs, then join the summaries (sheet 41)

Quick Summary

  • Joins chain table by table
  • Junction table = two joins
  • Fan-out → aggregate first
