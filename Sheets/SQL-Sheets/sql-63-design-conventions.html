Design Conventions

snake_case · surrogate vs natural key · created_at / updated_at · soft delete · FK naming

House Rules That Pay Off

Consistent conventions make a schema predictable. Use snake_case names, which never need quotes. Give most tables a surrogate key (a meaningless identity or UUID) and enforce the natural key (email, SKU) with a unique constraint, so business values can change without rewriting foreign keys. Add created_at / updated_at timestamps, name foreign keys <table>_id, and decide up front how deletes work (hard or soft).

Convention Facts

  • Pick plural (orders) or singular and stick to it
  • Booleans as questions: is_active, has_paid
  • Store money as NUMERIC, times as TIMESTAMPTZ
  • Avoid reserved words: user, order, group

NoSQL Comparison

  • MongoDB convention: camelCase fields and the surrogate _id
  • Mongoose timestamps: true adds createdAt / updatedAt
  • Soft delete with deletedAt the same way

A Table Following the Conventions

CREATE TABLE support_tickets (
  ticket_id   BIGINT GENERATED ALWAYS AS IDENTITY
              PRIMARY KEY,               -- surrogate
  public_ref  TEXT NOT NULL UNIQUE,      -- natural key
  customer_id INT NOT NULL
              REFERENCES customers,      -- <table>_id
  subject     TEXT NOT NULL,
  is_closed   BOOLEAN NOT NULL DEFAULT false,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  deleted_at  TIMESTAMPTZ                -- soft delete
);
CREATE INDEX support_tickets_customer_id_idx
  ON support_tickets (customer_id);

-- Keep updated_at current
CREATE FUNCTION touch() RETURNS trigger
LANGUAGE plpgsql AS $$
BEGIN NEW.updated_at := now(); RETURN NEW; END $$;
CREATE TRIGGER support_tickets_touch
  BEFORE UPDATE ON support_tickets
  FOR EACH ROW EXECUTE FUNCTION touch();

Code Explained

ticket_id never changes; public_ref is what users see
FK named after the table it points to: customer_id
Index name: <table>_<column>_idx
The trigger stamps updated_at on every update (sheet 67)

In an ORM

model SupportTicket {
  id        BigInt    @id @default(autoincrement())
  createdAt DateTime  @default(now()) @map("created_at")
  updatedAt DateTime  @updatedAt @map("updated_at")
  deletedAt DateTime? @map("deleted_at")
  @@map("support_tickets")
}

⚠ Common Mistakes

  • Mixed styles: CustomerID, order_id, productid
  • Naming a table user or order and quoting forever
  • Email as the primary key, then a customer changes it

✓ Tips & Best Practices

  • Write the conventions down in the repo
  • Let a linter (sqlfluff, squawk) enforce them
  • Prisma @map / @@map bridges camelCase code and snake_case tables

Quick Summary

  • snake_case, <table>_id, <event>_at
  • Surrogate PK + unique natural key
  • created_at / updated_at / deleted_at
