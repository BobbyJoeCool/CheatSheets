Sheet 08

Character Types

CHAR(n) · VARCHAR(n) · TEXT · NVARCHAR · collation · UTF-8

Storing Text

CHAR(n) is fixed width and pads with spaces; VARCHAR(n) stores up to n characters; TEXT has no practical limit. In PostgreSQL all three perform the same, so TEXT (plus a CHECK if you need a limit) is the usual choice. A collation decides how text compares and sorts: case and accent sensitivity, and whether 'B' comes before 'a'. Use UTF-8 so every language and emoji fits.

Text Facts

  • Strings use single quotes: 'O''Brien'
  • Too-long values are an error (PG, MySQL strict mode)
  • CHAR trailing spaces are ignored when comparing
  • MySQL utf8 is 3-byte; use utf8mb4

NoSQL Comparison

  • MongoDB strings are UTF-8 with no length type; only the 16 MB document cap
  • Limit length with $jsonSchema maxLength
  • Collation is set per collection, index or query

Character Types

CREATE TABLE contacts (
  country CHAR(2),         -- always 2: 'US'
  phone   VARCHAR(20),     -- up to 20 characters
  bio     TEXT,            -- no practical limit
  CHECK (length(bio) <= 5000)
);

SELECT 'ab'::CHAR(5) || '|';             -- ab|
SELECT length('ab'::CHAR(5));            -- 2
SELECT length('é'), octet_length('é');   -- 1 | 2
INSERT INTO contacts (country) VALUES ('USA');
-- ERROR: value too long for type character(2)

-- Case-insensitive comparison
SELECT 'abc' = 'ABC';                    -- false
CREATE COLLATION ci (provider = icu,
  locale = 'und-u-ks-level2', deterministic = false);
SELECT 'abc' = 'ABC' COLLATE ci;         -- true
SELECT name FROM customers
ORDER  BY name COLLATE "C";              -- byte order

Code Explained

CHAR(5) pads to 5, but the padding is dropped as text
length counts characters; octet_length counts bytes
ks-level2 — ICU strength that ignores case
COLLATE "C" — plain byte order: fast, case-sensitive

Dialect Notes

EngineSyntax / behavior
PostgreSQLTEXT preferred; VARCHAR with no n = TEXT
MySQLVARCHAR(n) ≤ 65,535 bytes/row; TEXT = 64 KB
SQL ServerVARCHAR(n) counts bytes; NVARCHAR(n) UTF-16; (MAX)
SQLiteall are TEXT affinity; n is not enforced

In an ORM

model Customer {
  country String  @db.Char(2)
  phone   String? @db.VarChar(20)
  bio     String? @db.Text
}

⚠ Common Mistakes

  • Using CHAR(n) for variable data and fighting padding
  • MySQL utf8 columns rejecting emoji; switch to utf8mb4
  • Assuming 'abc' = 'ABC' behaves the same on every engine

✓ Tips & Best Practices

  • PostgreSQL: TEXT + CHECK (length(x) <= n)
  • Choose the collation when creating the database
  • Case-insensitive unique email: index lower(email)

Quick Summary

  • CHAR fixed · VARCHAR limited · TEXT open
  • Collation = compare + sort rules
  • UTF-8 everywhere (utf8mb4 in MySQL)
