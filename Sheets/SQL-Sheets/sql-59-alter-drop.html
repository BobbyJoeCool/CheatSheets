ALTER & DROP

ALTER TABLE · ADD COLUMN · DROP COLUMN · RENAME · ALTER COLUMN TYPE · ADD CONSTRAINT · DROP TABLE

Changing Structure

ALTER TABLE changes an existing table: add, drop or rename columns, change types and defaults, and add or remove constraints. DROP TABLE removes a table with its data and indexes; it fails if other objects depend on it unless you add CASCADE. On busy production tables, the question is not only *what* to change but how long it locks: some changes are instant, others rewrite the whole table.

ALTER Facts

  • PostgreSQL DDL is transactional: it can roll back
  • MySQL and Oracle DDL commit immediately
  • IF EXISTS keeps drop scripts re-runnable
  • Renames break code that uses the old name

NoSQL Comparison

  • MongoDB has no table structure to alter
  • New fields simply appear; backfill with updateMany({}, { $set: { pts: 0 } })
  • $rename renames a field; $unset removes it

ALTER & DROP

ALTER TABLE customers ADD COLUMN phone VARCHAR(20);
ALTER TABLE customers
  ADD COLUMN loyalty_pts INT NOT NULL DEFAULT 0;
ALTER TABLE customers DROP COLUMN phone;
ALTER TABLE customers RENAME COLUMN city TO town;
ALTER TABLE customers RENAME TO clients;

ALTER TABLE products
  ALTER COLUMN name TYPE VARCHAR(200);
ALTER TABLE products
  ALTER COLUMN stock TYPE BIGINT USING stock::bigint;
ALTER TABLE products ALTER COLUMN category SET NOT NULL;
ALTER TABLE products ALTER COLUMN stock SET DEFAULT 0;

ALTER TABLE products
  ADD CONSTRAINT price_pos CHECK (price > 0);
ALTER TABLE products DROP CONSTRAINT price_pos;

DROP TABLE IF EXISTS big_orders;
DROP TABLE customers;
-- ERROR: other objects depend on it (orders FK)
DROP TABLE customers CASCADE;  -- also drops the FK

Code Explained

A constant DEFAULT with ADD COLUMN is instant in PG 11+
USING tells PG how to convert existing values
SET NOT NULL scans the table to check existing rows
CASCADE removes dependent constraints and views

⚠ Common Mistakes

  • Renaming a column the app still reads
  • Type changes on huge tables during business hours
  • DROP … CASCADE removing more than you meant

✓ Tips & Best Practices

  • Expand → migrate → contract: add new, backfill, then drop old
  • Test migrations on a production-size copy
  • Set lock_timeout so DDL gives up instead of blocking

Quick Summary

  • ALTER TABLE add / drop / rename / type
  • DROP TABLE [IF EXISTS] [CASCADE]
  • Mind locks and rewrites
