LATERAL & APPLY

LATERAL · CROSS APPLY · OUTER APPLY · top-N per row · set-returning functions

A Subquery per Row

A normal subquery in FROM can't see the other tables in the same FROM. LATERAL lifts that rule: the subquery runs once per outer row and may reference its columns, like a for each loop. That makes top-N per group easy: the 3 latest orders for each customer. SQL Server calls the same thing CROSS APPLY (inner) and OUTER APPLY (keeps rows with no result).

LATERAL Facts

  • CROSS JOIN LATERAL drops rows with no result
  • LEFT JOIN LATERAL … ON true keeps them
  • Index the inner lookup or each row scans
  • Window functions also do top-N (sheet 49)

NoSQL Comparison

  • MongoDB $lookup with a pipeline runs per document:
  • pipeline: [{ $match: { $expr: … } }, { $sort: { date: -1 } }, { $limit: 3 }]
  • That's the same top-N-per-parent idea

LATERAL & APPLY

-- Latest 3 orders per customer
SELECT c.name, r.order_id, r.order_date
FROM   customers c
CROSS  JOIN LATERAL (
         SELECT o.order_id, o.order_date
         FROM   orders o
         WHERE  o.customer_id = c.customer_id
         ORDER  BY o.order_date DESC
         LIMIT  3) AS r;

-- Keep customers with no orders
SELECT c.name, r.order_id, r.total
FROM   customers c
LEFT   JOIN LATERAL (
         SELECT order_id, total FROM orders o
         WHERE  o.customer_id = c.customer_id
         ORDER  BY order_date DESC
         LIMIT  1) AS r ON true;

-- SQL Server equivalent
SELECT c.name, r.order_id
FROM   customers c
CROSS  APPLY (SELECT TOP (3) order_id FROM orders o
              WHERE  o.customer_id = c.customer_id
              ORDER  BY order_date DESC) AS r;

Code Explained

c.customer_id inside the subquery is the lateral reference
LIMIT 3 applies per customer, not to the whole result
ON true — the subquery already did the matching
CROSS APPLY ≈ CROSS JOIN LATERAL

⚠ Common Mistakes

  • CROSS JOIN LATERAL silently dropping parents with no rows
  • No index on the inner WHERE column: one scan per outer row
  • Using LATERAL where a simple join would do

✓ Tips & Best Practices

  • Index (customer_id, order_date DESC) for top-N lookups
  • Use LIMIT 1 lateral to fetch several columns of the latest row
  • Compare plans with the ROW_NUMBER() version (sheet 49)
