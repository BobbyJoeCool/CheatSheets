Outer Joins

LEFT JOIN · RIGHT JOIN · FULL OUTER JOIN · NULL-extended rows · ON vs WHERE filter

Keeping Unmatched Rows

An outer join keeps rows that have no match and fills the other side's columns with NULL. LEFT JOIN keeps every row from the left table; RIGHT JOIN every row from the right; FULL OUTER JOIN both. The trap is where you filter: a condition on the right table belongs in ON. Put it in WHERE and the NULL rows fail it, which silently turns the outer join back into an inner join.

Outer Join Facts

  • LEFT JOIN = LEFT OUTER JOIN
  • RIGHT JOIN is a LEFT JOIN with tables swapped
  • Count the right side's key, not *, to get zeros
  • WHERE right.id IS NULL → rows with no match (sheet 36)

NoSQL Comparison

  • $lookup already behaves like a left outer join
  • No match → an empty array, not a dropped document
  • $unwind with preserveNullAndEmptyArrays: true keeps them

Outer Joins

-- Every customer, with orders if any
SELECT c.name, o.order_id, o.total
FROM   customers c
LEFT   JOIN orders o ON o.customer_id = c.customer_id;

-- Order count per customer, including zero
SELECT c.name, count(o.order_id) AS orders
FROM   customers c
LEFT   JOIN orders o ON o.customer_id = c.customer_id
GROUP  BY c.customer_id, c.name;

-- Filter the right table in ON
SELECT c.name, o.order_id
FROM   customers c
LEFT   JOIN orders o
  ON   o.customer_id = c.customer_id
 AND   o.status = 'paid';    -- all customers kept
-- WHERE o.status = 'paid'   -- would drop them

-- Every department, even with no staff
SELECT d.name, e.first_name
FROM   employees e
RIGHT  JOIN departments d ON d.dept_id = e.dept_id;

SELECT c.customer_id, o.order_id
FROM   customers c
FULL   OUTER JOIN orders o
  ON   o.customer_id = c.customer_id;

Code Explained

Customers with no orders get NULL order_id and total
count(o.order_id) → 0 for them; count(*) would say 1
o.status in ON limits which orders attach
FULL OUTER also keeps orders with no customer

In an ORM

await prisma.customer.findMany({
  include: {
    orders: { where: { status: 'paid' } },
  },
});  // every customer; orders = [] when none match

ON vs WHERE in a LEFT JOIN

Condition on the right tableEffect
in ONlimits matches; every left row stays
in WHEREremoves NULL rows → acts as INNER
WHERE right.key IS NULLonly left rows with no match
WHERE right.col IS NULL OR …keeps them; usually means ON

⚠ Common Mistakes

  • Filtering the right table in WHERE after a LEFT JOIN
  • count(*) showing 1 order for customers with none
  • Mixing LEFT and RIGHT in one query; rewrite as all LEFT

✓ Tips & Best Practices

  • Default to LEFT JOIN and put the "keep all" table first
  • Wrap nullable outputs in coalesce for display
  • Check row counts before and after adding a join

Quick Summary

  • LEFT / RIGHT / FULL keep unmatched rows
  • Missing side → NULLs
  • Right-table filters go in ON
