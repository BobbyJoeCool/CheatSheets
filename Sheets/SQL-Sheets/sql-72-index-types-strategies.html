Index Types & Strategies

partial index · expression index · leftmost prefix · GIN · GiST · BRIN · hash

Choosing the Right Index

A composite B-tree helps queries that use its leftmost columns: (customer_id, status) serves customer_id alone or both, but not status alone. A partial index covers only rows matching a WHERE, so it stays small. An expression index stores lower(email) so a query on lower(email) can use it. PostgreSQL also offers other index types: GIN for arrays, JSONB and text search, GiST for ranges and geometry, BRIN for huge naturally ordered tables, Hash for equality only.

Strategy Facts

  • Equality columns first, then range / sort columns
  • The query must repeat the partial index's condition
  • The expression in WHERE must match the index exactly
  • PG 18 skip scan can use (a, b) for b alone, sometimes

NoSQL Comparison

  • MongoDB: partialFilterExpression = partial index
  • Also text, wildcard, 2dsphere and TTL indexes
  • Compound indexes follow the same prefix rule

Index Strategies

-- Partial: only the rows you query
CREATE INDEX orders_pending_idx
  ON orders (order_date)
  WHERE status = 'pending';

-- Expression: matches lower(email) lookups
CREATE INDEX customers_email_lower_idx
  ON customers (lower(email));
SELECT * FROM customers
WHERE  lower(email) = 'ada@example.com';

-- Leftmost prefix
CREATE INDEX orders_cust_status_idx
  ON orders (customer_id, status);
-- WHERE customer_id = 1                  ✓
-- WHERE customer_id = 1 AND status = 'x' ✓
-- WHERE status = 'paid'                  ✗ mostly

-- GIN trigram: fast '%lamp%' searches
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE INDEX products_name_trgm
  ON products USING gin (name gin_trgm_ops);

-- BRIN: tiny index for huge, date-ordered tables
CREATE INDEX orders_date_brin
  ON orders USING brin (order_date);

Code Explained

The partial index skips every shipped and paid order
WHERE lower(email) = … matches the indexed expression
A phone book sorted by last name can't find first names
BRIN stores min/max per block range: KBs, not GBs

⚠ Common Mistakes

  • Putting a range column before an equality column
  • Partial index whose condition queries don't repeat
  • GIN indexes on write-heavy tables without measuring

✓ Tips & Best Practices

  • Design indexes from real queries, not from tables
  • One good composite beats three single-column indexes
  • Re-check plans after adding an index (sheet 73)
