Type Conversion & Casting

CAST · :: · CONVERT · TRY_CAST · implicit conversion · type affinity

Changing Types

CAST(x AS type) is the standard way to convert; PostgreSQL also accepts x::type. When types differ the engine may convert implicitly: PostgreSQL is strict and errors on mismatches it can't resolve, while MySQL and SQLite quietly turn '12abc' into 12. SQL Server's TRY_CAST and TRY_CONVERT return NULL instead of failing. For formatted text and dates, use formatting functions (to_char, to_date) rather than plain casts.

Casting Rules

  • Numeric → integer rounds in PG and MySQL, truncates in SQL Server and SQLite
  • Text → number fails on bad input (PG, SQL Server)
  • A cast on a column in WHERE can block an index (sheet 74)
  • PG 16+: pg_input_is_valid(text, type) tests first

Casting

SELECT CAST('42' AS INTEGER) + 1;          -- 43
SELECT '42'::int, '3.14'::numeric(4,2);    -- PG shorthand
SELECT CAST(9.99 AS INTEGER);              -- 10
SELECT CAST('2026-10-18' AS DATE);
SELECT order_id::text || '-A' FROM orders;
SELECT CAST('abc' AS INTEGER);
-- ERROR: invalid input syntax for type integer

-- Check before casting
SELECT pg_input_is_valid('abc', 'integer');  -- false
SELECT CASE WHEN qty ~ '^[0-9]+$'
            THEN qty::int END AS qty
FROM   staging_rows;

-- Format and parse with functions
SELECT to_char(1234.5, 'FM9,999.00');      -- 1,234.50
SELECT to_number('1,234.50', '9G999D99');  -- 1234.50
SELECT to_date('18/10/2026', 'DD/MM/YYYY');
SELECT to_timestamp(1760000000);           -- epoch → tz

Code Explained

:: — PostgreSQL-only shorthand for CAST
CAST(9.99 AS INTEGER) rounds to 10; it doesn't truncate
~ '^[0-9]+$' — regex guard so the cast can't fail (sheet 19)
FM drops padding; G and D are locale separators

⚠ Common Mistakes

  • MySQL CAST(x AS INT); the target must be SIGNED
  • Casting a column in WHERE and losing the index
  • Relying on MySQL turning bad text into 0 instead of failing

✓ Tips & Best Practices

  • Cast the literal, not the column: WHERE d = '2026-10-18'::date
  • Validate staging data before casting the whole table
  • Prefer to_char / FORMAT for display, casts for logic

Quick Summary

  • CAST(x AS t) · x::t · TRY_CAST
  • Implicit rules differ by engine
  • Format with functions, not casts
