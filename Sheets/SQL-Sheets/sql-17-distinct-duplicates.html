DISTINCT & Duplicates

DISTINCT · DISTINCT ON · COUNT(DISTINCT) · finding duplicates · DISTINCT vs GROUP BY

Removing Repeats

SELECT DISTINCT removes duplicate output rows, comparing every selected column (two NULLs count as equal here). COUNT(DISTINCT x) counts unique non-NULL values. PostgreSQL's DISTINCT ON (key) keeps the first row per key according to ORDER BY, a quick way to get "latest order per customer". To find duplicate data, group by the columns that should be unique and keep groups with count(*) > 1.

Duplicate Facts

  • DISTINCT applies to the whole row, not one column
  • Without aggregates, DISTINCT = GROUP BY all columns
  • Deduplicating sorts or hashes the result: not free
  • Prevent duplicates with UNIQUE (sheet 57)

NoSQL Comparison

  • MongoDB: db.customers.distinct('city')
  • Pipeline: { $group: { _id: '$city' } }
  • Unique index: createIndex({ email: 1 }, { unique: true })

DISTINCT & Duplicates

SELECT DISTINCT city FROM customers;
SELECT DISTINCT city, country FROM customers;
SELECT count(DISTINCT city) FROM customers;  -- no NULLs

-- Latest order per customer (PostgreSQL)
SELECT DISTINCT ON (customer_id)
       customer_id, order_id, order_date
FROM   orders
ORDER  BY customer_id, order_date DESC;

-- Find duplicate emails
SELECT lower(email) AS email, count(*) AS n
FROM   customers
GROUP  BY lower(email)
HAVING count(*) > 1;

-- Delete duplicates, keep the lowest id
DELETE FROM customers c
USING  customers d
WHERE  lower(c.email) = lower(d.email)
  AND  c.customer_id > d.customer_id;

Code Explained

DISTINCT city, country — one row per unique pair
DISTINCT ON keeps the first row in ORDER BY order
ORDER BY must start with the DISTINCT ON columns
USING self-join deletes every copy but the oldest

⚠ Common Mistakes

  • Adding DISTINCT to hide duplicates from a bad join (sheet 35)
  • SELECT DISTINCT * on wide rows: slow and rarely meaningful
  • DISTINCT ON without ORDER BY: an arbitrary row wins

✓ Tips & Best Practices

  • Ask why duplicates exist before removing them
  • Clean up duplicates, then add the UNIQUE constraint
  • Normalize before comparing: lower(trim(email))

Quick Summary

  • DISTINCT — unique output rows
  • count(DISTINCT x) — unique values
  • DISTINCT ON — first row per key (PG)
