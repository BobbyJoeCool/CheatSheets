Sheet 49

Window Function Patterns

top-N per group · deduplication · gaps & islands · sessionization · QUALIFY

Classic Problems, Solved

Most window recipes follow one shape: compute a rank, lag or running value in a CTE or subquery, then filter it in the outer query, because window results can't be used in WHERE. Top-N per group keeps row_number() <= n; deduplication keeps rn = 1; gaps and islands finds runs of consecutive values by subtracting a row number; sessionization splits events wherever the gap since the previous one is too long. A few engines add QUALIFY to filter window results directly.

Pattern Facts

  • Window results are filtered one level up
  • Use row_number for exactly N, dense_rank to keep ties
  • Islands: consecutive values share value − row_number
  • QUALIFY isn't in PostgreSQL, MySQL, SQL Server or SQLite

NoSQL Comparison

  • MongoDB 5.2+: $topN / $bottomN give top-N per group inside $group
  • Or $setWindowFields → $rank, then $match

Window Patterns

-- Top 2 products by price in each category
SELECT name, category, price
FROM  (SELECT p.*,
              row_number() OVER (PARTITION BY category
                                 ORDER BY price DESC) AS rn
       FROM   products p) t
WHERE  rn <= 2;

-- Gaps & islands: runs of consecutive order days
WITH d AS (SELECT DISTINCT order_date FROM orders),
     g AS (SELECT order_date,
                  order_date - (row_number()
                    OVER (ORDER BY order_date))::int AS grp
           FROM d)
SELECT min(order_date) AS run_start,
       max(order_date) AS run_end, count(*) AS days
FROM   g
GROUP  BY grp;

-- QUALIFY (DuckDB, Snowflake, BigQuery)
SELECT * FROM products
QUALIFY row_number() OVER (PARTITION BY category
                           ORDER BY price DESC) <= 2;

Code Explained

rn <= 2 in the outer query keeps two per category
Consecutive days minus 1, 2, 3 … give the same grp date
::int because date - bigint isn't defined
QUALIFY does the outer filter in one level

Dialect Notes

EngineSyntax / behavior
PostgreSQLno QUALIFY; filter in a CTE or subquery
MySQLno QUALIFY; delete via JOIN to a ranked table
SQL Serverno QUALIFY; WITH d AS (…) DELETE FROM d WHERE rn > 1
SQLiteno QUALIFY; same subquery pattern

⚠ Common Mistakes

  • Putting row_number() in WHERE
  • Using rank for "exactly 2 per group" and getting 3 on ties
  • Forgetting DISTINCT before gaps & islands on repeated dates

✓ Tips & Best Practices

  • Keep the ranked CTE: it doubles as a debugging view
  • Index (category, price DESC) for top-N queries
  • Check dedupe with SELECT before turning it into DELETE

Quick Summary

  • Compute in a CTE, filter outside
  • Top-N · dedupe · islands · sessions
  • QUALIFY only in a few engines
