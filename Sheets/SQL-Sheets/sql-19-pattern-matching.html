Sheet 19

Pattern Matching

LIKE · % · _ · ESCAPE · ILIKE · SIMILAR TO · ~ · REGEXP

Matching Text Patterns

LIKE matches text against a pattern where % means "any run of characters" and _ means "exactly one character". Use ESCAPE to match a literal % or _. PostgreSQL adds ILIKE (case-insensitive) and full regular expressions with ~; MySQL has REGEXP. A pattern that starts with % can't use a normal B-tree index, so it scans the whole table.

Pattern Facts

  • LIKE must match the whole string
  • Case sensitivity follows the engine and collation
  • 'Desk%' can use an index; '%desk' can't
  • For words in prose, use full-text search (sheet 80)

NoSQL Comparison

  • MongoDB: { name: /lamp/i } or { $regex: '^Desk', $options: 'i' }
  • Only an anchored, case-sensitive ^prefix regex uses an index
  • Atlas Search handles fuzzy and full-text matching

LIKE & Regex

SELECT name FROM products WHERE name LIKE 'Desk%';
SELECT name FROM products WHERE name LIKE '%lamp%';
SELECT name FROM products WHERE name LIKE '_at';
SELECT email FROM customers
WHERE  email NOT LIKE '%@%.%';

-- Case-insensitive (PostgreSQL)
SELECT name FROM products WHERE name ILIKE '%LAMP%';

-- Match a literal %
SELECT name FROM products
WHERE  name LIKE '%50!%%' ESCAPE '!';   -- contains 50%

-- Regular expressions (PostgreSQL)
SELECT email FROM customers
WHERE  email ~* '^[^@\s]+@[^@\s]+\.[a-z]{2,}$';
SELECT name FROM products WHERE name ~ '^[A-Z]{3}-\d+';
SELECT regexp_replace(name, '[^A-Za-z ]', '', 'g')
FROM   customers;                       -- letters only
SELECT substring(email FROM '@(.*)$')   -- domain
FROM   customers;

Code Explained

'_at' — exactly three characters ending in at
ESCAPE '!' makes !% a literal percent sign
~ regex · ~* case-insensitive · !~ doesn't match
'g' flag replaces every match, not just the first

⚠ Common Mistakes

  • Forgetting _ is a wildcard: LIKE 'user_1' matches userX1
  • Leading % on a big table: full scan every time
  • Assuming LIKE is case-insensitive in PostgreSQL

✓ Tips & Best Practices

  • PG: a pg_trgm GIN index speeds up '%x%' searches (sheet 72)
  • Anchor regexes with ^ and $ when validating
  • Clean data once on write instead of regex on every read

Quick Summary

  • % any run · _ one char
  • ILIKE / ~* — case-insensitive (PG)
  • Leading % → no index
