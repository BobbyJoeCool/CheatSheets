Recursive CTEs

WITH RECURSIVE · anchor member · recursive member · UNION ALL · hierarchy · CYCLE

Queries That Repeat

A recursive CTE refers to itself. It has two parts joined by UNION ALL: the anchor runs once and produces the starting rows; the recursive member joins the table to the rows produced in the previous round, and repeats until it adds nothing. That's how SQL walks trees and graphs of unknown depth (org charts, category trees, bill of materials) and generates series.

Recursion Facts

  • Anchor first, then UNION ALL, then the recursive part
  • Recursion stops when a round returns no rows
  • Column types must match in both parts
  • Always include a stop condition or cycle check

NoSQL Comparison

  • MongoDB: $graphLookup walks a tree in one stage
  • { from: 'employees', startWith: '$_id', connectFromField: '_id', connectToField: 'managerId', as: 'reports', maxDepth: 5 }

WITH RECURSIVE

-- Everyone under employee 1, with depth
WITH RECURSIVE chain AS (
  SELECT emp_id, first_name, manager_id, 1 AS depth
  FROM   employees
  WHERE  emp_id = 1                         -- anchor
  UNION ALL
  SELECT e.emp_id, e.first_name, e.manager_id, c.depth+1
  FROM   employees e
  JOIN   chain c ON e.manager_id = c.emp_id -- recursive
)
SELECT * FROM chain ORDER BY depth;
-- Breadcrumb path from the top
WITH RECURSIVE path AS (
  SELECT emp_id, first_name::text AS trail
  FROM   employees WHERE manager_id IS NULL
  UNION ALL
  SELECT e.emp_id, p.trail || ' > ' || e.first_name
  FROM   employees e
  JOIN   path p ON e.manager_id = p.emp_id
)
SELECT * FROM path;

-- 1 to 10 without generate_series
WITH RECURSIVE n(i) AS (
  SELECT 1 UNION ALL SELECT i + 1 FROM n WHERE i < 10)
SELECT i FROM n;

Code Explained

Round 1: the anchor returns employee 1
Each round adds the direct reports of the last round
::text makes both parts the same type for ||
WHERE i < 10 is the stop condition

⚠ Common Mistakes

  • No stop condition on cyclic data: runs until a limit hits
  • Type mismatch between anchor and recursive part
  • SQL Server: writing WITH RECURSIVE (syntax error)

✓ Tips & Best Practices

  • Track depth and a path array for debugging
  • Index the parent column (manager_id)
  • For deep, frequent tree reads consider ltree or closure tables

Quick Summary

  • Anchor + UNION ALL + recursive part
  • Walks trees of any depth
  • Always guard against cycles
