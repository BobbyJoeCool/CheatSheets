Views & Materialized Views

CREATE VIEW · OR REPLACE · WITH CHECK OPTION · updatable view · MATERIALIZED VIEW · REFRESH · CONCURRENTLY · indexed view

Saved Queries

A view is a named query you select from like a table. It stores no data: each use runs the query, so it's always current. Views hide complexity, give apps a stable interface and limit which columns or rows a role can see. A simple single-table view is updatable; WITH CHECK OPTION blocks writes the view couldn't see. A materialized view stores the result: fast to read, but stale until you REFRESH it.

View Facts

  • Views can be granted separately from tables (sheet 75)
  • OR REPLACE can add columns, not drop or retype them
  • Filters on a view are pushed into its query
  • CONCURRENTLY needs a unique index on the MV

NoSQL Comparison

  • MongoDB: db.createView('active', 'customers', [pipeline]) — read-only
  • On-demand materialized views: an aggregation ending in $merge
  • Re-run the $merge pipeline to refresh

Views

CREATE VIEW active_customers AS
SELECT customer_id, name, email, city
FROM   customers
WHERE  deleted_at IS NULL;

SELECT * FROM active_customers WHERE city = 'Oslo';

CREATE OR REPLACE VIEW order_summary AS
SELECT o.order_id, c.name, o.order_date, o.total
FROM   orders o
JOIN   customers c USING (customer_id);

-- Updatable view that rejects out-of-view rows
CREATE VIEW ca_customers AS
SELECT * FROM customers WHERE country = 'CA'
WITH CHECK OPTION;
INSERT INTO ca_customers (name, country)
VALUES ('Zed', 'US');
-- ERROR: new row violates check option

-- Stored result, refreshed on demand
CREATE MATERIALIZED VIEW monthly_revenue AS
SELECT date_trunc('month', order_date) AS month,
       sum(total) AS revenue
FROM   orders GROUP BY month;
CREATE UNIQUE INDEX ON monthly_revenue (month);
REFRESH MATERIALIZED VIEW CONCURRENTLY monthly_revenue;

Code Explained

active_customers hides soft-deleted rows (sheet 52)
WITH CHECK OPTION — inserts must satisfy country = 'CA'
The materialized view is computed once and stored
CONCURRENTLY refreshes without blocking readers

⚠ Common Mistakes

  • Stacking views on views until no one can tune the query
  • Reading a materialized view as if it were live
  • SELECT * in a view: columns are fixed at creation time

✓ Tips & Best Practices

  • Use views as the API for reporting tools
  • Schedule MV refreshes (cron, pg_cron) after loads
  • List columns explicitly in view definitions

Quick Summary

  • View — saved query, no data
  • Materialized — stored, needs refresh
  • WITH CHECK OPTION guards writes
