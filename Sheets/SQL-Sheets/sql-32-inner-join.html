INNER JOIN

INNER JOIN · ON · USING · table aliases · NATURAL JOIN · comma join

Matching Rows Across Tables

A join pairs rows from two tables wherever the ON condition is true. INNER JOIN (plain JOIN) keeps only the pairs that match: an order with no customer, or a customer with no orders, disappears. A row that matches three rows appears three times. USING (col) is shorthand when both tables share a column name. Table aliases (orders o) keep long joins readable.

Join Facts

  • JOIN = INNER JOIN
  • Join on keys: FK = PK is the normal case
  • USING merges the shared column into one
  • NATURAL JOIN matches every same-named column

NoSQL Comparison

  • MongoDB: $lookup: { from: 'customers', localField: 'customer_id', foreignField: '_id', as: 'customer' }
  • $unwind turns the array into one document per match
  • Often the name is simply embedded in the order instead

INNER JOIN

SELECT o.order_id, o.order_date, c.name
FROM   orders o
JOIN   customers c
  ON   c.customer_id = o.customer_id;

SELECT order_id, name
FROM   orders
JOIN   customers USING (customer_id);

-- Extra conditions belong in ON too
SELECT p.name, i.quantity
FROM   order_items i
JOIN   products p
  ON   p.product_id = i.product_id
 AND   p.category   = 'Books';

SELECT e.first_name, d.name AS department
FROM   employees e
INNER  JOIN departments d ON d.dept_id = e.dept_id;

-- Old comma style: same result, easy to break
SELECT o.order_id, c.name
FROM   orders o, customers c
WHERE  c.customer_id = o.customer_id;

Code Explained

c.customer_id = o.customer_id — FK in orders = PK in customers
USING outputs a single customer_id column
Employees with a NULL dept_id drop out of an inner join
Comma joins without a WHERE become cross joins (sheet 34)

⚠ Common Mistakes

  • NATURAL JOIN breaking when both tables gain a created_at
  • Forgetting a join condition and multiplying rows
  • Using INNER when rows without a match should stay (sheet 33)

✓ Tips & Best Practices

  • Use short, meaningful aliases: o, c, oi
  • Always write explicit JOIN … ON
  • Index foreign key columns used in joins (sheet 71)

Quick Summary

  • JOIN … ON — matched pairs only
  • USING (col) — same-named key
  • One row per matching pair
