Named Steps with WITH

A CTE names a subquery at the top of a statement with WITH name AS (…); the main query then uses it like a table. Several CTEs, separated by commas, can each build on the ones before, so a long report reads top to bottom as named steps instead of nesting inward. A CTE lives only for its one statement. PostgreSQL inlines simple CTEs; MATERIALIZED forces it to compute the CTE once and keep the result.

CTE Facts

  • One WITH, many CTEs: WITH a AS (…), b AS (…)
  • Later CTEs can reference earlier ones
  • A CTE can be used several times in the main query
  • PG: INSERT … RETURNING can feed a CTE

NoSQL Comparison

  • A MongoDB pipeline is already a list of steps
  • No named, reusable intermediate results inside one query
  • $facet runs several sub-pipelines on the same input

WITH

WITH paid AS (
  SELECT customer_id, sum(total) AS spent
  FROM   orders
  WHERE  status = 'paid'
  GROUP  BY customer_id
)
SELECT c.name, p.spent
FROM   customers c
JOIN   paid p USING (customer_id)
ORDER  BY p.spent DESC;

-- Chained CTEs: each builds on the last
WITH monthly AS (
  SELECT date_trunc('month', order_date) AS month,
         sum(total) AS revenue
  FROM   orders GROUP BY month
), changes AS (
  SELECT month, revenue,
         revenue - lag(revenue) OVER (ORDER BY month)
           AS change
  FROM   monthly
)
SELECT * FROM changes WHERE change < 0;
-- PostgreSQL 12+: compute once, keep the result
WITH big AS MATERIALIZED (
  SELECT * FROM orders WHERE total > 1000)
SELECT count(*) FROM big;

Code Explained

paid is a named result the main query joins
changes reads from monthly, defined just above
lag(…) — previous month's revenue (sheet 46)
MATERIALIZED stops PG from inlining the CTE

⚠ Common Mistakes

  • SQL Server: missing ; before WITH → syntax error
  • Expecting a CTE to persist for the next statement
  • Assuming every engine computes a CTE only once

✓ Tips & Best Practices

  • One CTE per logical step, named for what it holds
  • Debug by running the main query as SELECT * FROM step
  • Use a temp table when you need an index on the step

Quick Summary

  • WITH name AS (…)
  • Chain steps; read top to bottom
  • Scope: one statement
