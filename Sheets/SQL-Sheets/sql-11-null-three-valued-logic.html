NULL & Three-Valued Logic

NULL · IS NULL · IS NOT NULL · UNKNOWN · IS DISTINCT FROM · NULL in comparisons

Unknown Values

NULL means "unknown" or "not applicable". It is not zero and not an empty string. Any comparison with NULL returns UNKNOWN, and WHERE keeps only rows that are TRUE, so city = NULL never matches anything. Test with IS NULL. Most operators return NULL when an input is NULL. IS DISTINCT FROM compares values but treats two NULLs as equal.

NULL Rules

  • = NULL is always UNKNOWN; use IS NULL
  • 1 + NULL and 'a' || NULL are NULL
  • TRUE OR NULL is TRUE; FALSE AND NULL is FALSE
  • Aggregates skip NULLs (sheet 27)

NoSQL Comparison

  • MongoDB separates a missing field from null
  • { city: null } matches both; { city: { $exists: false } } only missing
  • No three-valued logic: comparisons are just true or false

NULL in Practice

SELECT NULL = NULL;             -- NULL (unknown)
SELECT NULL IS NULL;            -- true
SELECT 1 + NULL, 'a' || NULL;   -- NULL | NULL

-- Customers with no city
SELECT name FROM customers WHERE city IS NULL;
SELECT name FROM customers WHERE city = NULL; -- 0 rows!

-- "Not Oslo" silently skips NULL cities
SELECT count(*) FROM customers WHERE city <> 'Oslo';
SELECT count(*) FROM customers
WHERE  city IS DISTINCT FROM 'Oslo';     -- counts NULLs

-- NULL-safe match between columns
SELECT a.emp_id, b.emp_id
FROM   employees a
JOIN   employees b
  ON   a.manager_id IS NOT DISTINCT FROM b.manager_id
 AND   a.emp_id < b.emp_id;

SELECT TRUE OR NULL, FALSE AND NULL;   -- true | false

Code Explained

city <> 'Oslo' is UNKNOWN for NULL cities, so they drop
IS DISTINCT FROM — NULL vs value is TRUE, NULL vs NULL FALSE
The self-join pairs employees with the same manager, NULL too
OR with a TRUE side is TRUE even if the other is unknown

In an ORM

await prisma.customer.findMany({
  where: { city: null },           // IS NULL
});
await prisma.customer.findMany({
  where: { city: { not: null } },  // IS NOT NULL
});

Where NULLs Bite

SituationWhat happens
COUNT(col)skips NULL rows; COUNT(*) doesn't
ORDER BY colNULLs last in PG, first in MySQL / SQL Server / SQLite
GROUP BY colall NULLs form one group
UNIQUE colmany NULLs allowed (SQL Server: only one)
x NOT IN (…, NULL)never TRUE → no rows (sheet 36)
CHECK (x > 0)passes when x is NULL

⚠ Common Mistakes

  • Writing = NULL or <> NULL
  • Losing NULL rows with <> filters
  • NOT IN against a subquery that can return NULL

✓ Tips & Best Practices

  • Decide per column: NOT NULL unless unknown is real
  • Use COALESCE for display defaults (sheet 26)
  • Reach for IS DISTINCT FROM when comparing nullable columns

Quick Summary

  • NULL = unknown, not empty
  • Comparisons → UNKNOWN; WHERE keeps TRUE only
  • IS NULL · IS DISTINCT FROM
