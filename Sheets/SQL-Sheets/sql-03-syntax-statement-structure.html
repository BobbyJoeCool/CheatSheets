How a Statement Is Built

A statement is a sequence of clauses (SELECT, FROM, WHERE …), each starting with a keyword, ended by a semicolon. Whitespace and line breaks don't matter. Strings use single quotes; double quotes wrap identifiers that need spaces, capitals or reserved words. Clauses are written in one order but evaluated in another: FROM runs first and SELECT near the end, which explains most "why can't I use my alias here?" errors.

Rules of Thumb

  • Keywords in UPPER, names in snake_case — a convention, not a rule
  • 'text' is a string; "text" is a name
  • Double a quote to escape it: 'O''Brien'
  • ; is required between statements in a script

Written vs Evaluated

SELECT   category,                -- 5. compute output columns
         COUNT(*) AS n
FROM     products                 -- 1. pick the source rows
WHERE    price > 10               -- 2. filter rows
GROUP BY category                 -- 3. form groups
HAVING   COUNT(*) >= 3            -- 4. filter groups
ORDER BY n DESC                   -- 6. sort (aliases OK here)
LIMIT    10;                      -- 7. keep the first 10

/* Literals */
SELECT 'O''Brien'        AS surname,  -- escaped quote
       1.5e3             AS big,      -- 1500
       DATE '2026-01-31' AS due,      -- typed literal
       TRUE              AS ok;

-- Identifiers
select * from PRODUCTS;          -- same as products
CREATE TABLE "Order Notes" (    -- quoted: must be
  "Note Text" TEXT);            -- quoted forever

Code Explained

Numbers on the right — the logical evaluation order
n works in ORDER BY because sorting runs after SELECT
n fails in WHERE or HAVING: they run before it exists
"Order Notes" — legal, but every query must quote it

⚠ Common Mistakes

  • Using "double quotes" for strings; PostgreSQL reads them as column names
  • Referencing a SELECT alias in WHERE
  • Creating mixed-case quoted names, then forgetting the quotes

✓ Tips & Best Practices

  • One clause per line, aligned, makes diffs and reviews easier
  • Use snake_case names so you never need quotes
  • Comment the why, not the what: -- exclude test accounts

Quick Summary

  • Clauses — written SELECT … FROM …, run FROM first
  • 'string' vs "identifier"
  • -- and /* */ comments
  • ; ends each statement
