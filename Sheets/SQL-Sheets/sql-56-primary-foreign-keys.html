Sheet 56

Primary & Foreign Keys

PRIMARY KEY · composite key · FOREIGN KEY · REFERENCES · ON DELETE CASCADE · SET NULL

Identity and Relationships

A primary key uniquely identifies each row and is never NULL; a table has one, made of one column or several (composite). A foreign key says "this column's value must exist as a key in that table", so orders can't point at missing customers. ON DELETE decides what happens to child rows when the parent goes: block it, CASCADE the delete, or SET NULL.

Key Facts

  • PK = UNIQUE + NOT NULL, plus an index
  • FK columns allow NULL unless you forbid it
  • Default action: NO ACTION (blocks the delete)
  • Index FK columns yourself in PG and SQL Server

NoSQL Comparison

  • MongoDB _id is the primary key: unique and immutable
  • No foreign keys: references are plain values
  • Orphans are possible; the app (or embedding) prevents them

Keys

CREATE TABLE order_items (
  order_id   INT NOT NULL,
  product_id INT NOT NULL,
  quantity   INT NOT NULL,
  PRIMARY KEY (order_id, product_id),
  FOREIGN KEY (order_id) REFERENCES orders
    ON DELETE CASCADE,       -- items die with order
  FOREIGN KEY (product_id) REFERENCES products
    ON DELETE RESTRICT       -- keep sold products
);

-- Column shorthand
CREATE TABLE employees (
  emp_id     INT PRIMARY KEY,
  dept_id    INT REFERENCES departments
               ON DELETE SET NULL,
  manager_id INT REFERENCES employees (emp_id)
);

-- Named constraint, added later
ALTER TABLE orders
  ADD CONSTRAINT orders_customer_fk
  FOREIGN KEY (customer_id) REFERENCES customers;

INSERT INTO orders (customer_id, total) VALUES (99999, 10);
-- ERROR: … violates foreign key constraint
--        "orders_customer_fk"

Code Explained

(order_id, product_id) — each product once per order
CASCADE deletes an order's items with the order
SET NULL keeps employees when a department is removed
manager_id references the same table (self-reference)

⚠ Common Mistakes

  • No index on FK columns: slow joins and cascades
  • CASCADE on a parent you didn't expect to wipe children
  • SQLite without PRAGMA foreign_keys = ON

✓ Tips & Best Practices

  • Name constraints (orders_customer_fk) for clear errors
  • Use RESTRICT for history you must keep
  • Load parents before children in data imports

Quick Summary

  • PK — unique, not NULL, one per table
  • FK — value must exist in the parent
  • ON DELETE — restrict, cascade, set null
