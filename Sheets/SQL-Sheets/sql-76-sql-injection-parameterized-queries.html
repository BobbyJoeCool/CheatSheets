SQL Injection & Parameterized Queries

parameterized query · $1 · ? · @param · PREPARE · EXECUTE · dynamic SQL · quote_ident

Never Build SQL from Input

SQL injection happens when user input is pasted into SQL text, so the input can change the query itself: ' OR '1'='1 returns every row, and worse inputs drop tables. The fix is parameters: the SQL text contains placeholders ($1, ?, @email) and the values travel separately, so they are always treated as data. Parameters work for values only; table or column names must come from a whitelist or be quoted with quote_ident / format('%I').

Injection Facts

  • Escaping by hand is fragile; parameters aren't
  • Prepared statements also cache the plan
  • Dynamic SQL in functions is just as vulnerable
  • Least privilege limits the damage (sheet 75)

NoSQL Comparison

  • NoSQL injection: a body of { "email": { "$ne": null } } matches everyone
  • Cast inputs to expected types before building filters
  • Reject keys starting with $; avoid $where

Parameters, Not Concatenation

-- ✗ App code that builds SQL from input:
--   "… WHERE email = '" + input + "'"
--   input:  ' OR '1'='1   → every customer
--   input:  '; DROP TABLE orders; --

-- ✓ Placeholders; values are sent separately
SELECT * FROM customers WHERE email = $1;     -- PG
SELECT * FROM customers WHERE email = ?;      -- MySQL
SELECT * FROM customers WHERE email = @email; -- SQL Svr

-- Server-side prepared statement
PREPARE find_customer (text) AS
  SELECT * FROM customers WHERE email = $1;
EXECUTE find_customer('ada@example.com');
DEALLOCATE find_customer;

-- Dynamic SQL inside the database
CREATE FUNCTION count_rows(tbl text) RETURNS bigint
LANGUAGE plpgsql AS $$
DECLARE n bigint;
BEGIN
  EXECUTE format('SELECT count(*) FROM %I', tbl) INTO n;
  RETURN n;
END $$;
-- %I quotes identifiers; pass values with USING

Code Explained

The injected quote closes the string and adds OR true
A placeholder value can't change the query's structure
PREPARE parses once; EXECUTE supplies values
format('%I', tbl) = quote_ident(tbl)

In an ORM

// ✓ tagged template → sent as $1
await prisma.$queryRaw`
  SELECT * FROM customers WHERE email = ${email}`;
// ✗ string building → injectable
await prisma.$queryRawUnsafe(
  `SELECT * FROM customers WHERE email = '${email}'`);

⚠ Common Mistakes

  • Template strings with ${…} passed to raw-unsafe APIs
  • Escaping quotes by hand and missing a case
  • Trusting "internal" input (headers, cookies, CSV files)

✓ Tips & Best Practices

  • Ban $queryRawUnsafe and friends in code review
  • Run the app with a role that can't drop tables
  • Test with ', -- and ; in every input

Quick Summary

  • Values → parameters, always
  • Names → whitelist / quote_ident
  • $1 · ? · @name
