Sheet 75

Users, Roles & Privileges

CREATE ROLE · CREATE USER · GRANT · REVOKE · least privilege · ALTER DEFAULT PRIVILEGES

Who Can Do What

Databases control access with roles. A role that can log in is a user; a role that can't is a group you grant to others. GRANT gives privileges (SELECT, INSERT, UPDATE, DELETE, EXECUTE …) on tables, schemas, sequences or functions; REVOKE takes them back. Follow least privilege: the app's login gets only the data access it needs, migrations run as a separate owner role, and analysts get read-only access.

Privilege Facts

  • Grants on existing tables don't cover future ones
  • ALTER DEFAULT PRIVILEGES handles new tables
  • Table owners and superusers bypass grants
  • Row-level security filters rows per user (PG)

NoSQL Comparison

  • MongoDB RBAC: db.createUser({ user, pwd, roles: [{ role: 'read', db: 'shop' }] })
  • Built-in roles: read, readWrite, dbAdmin
  • Custom roles can grant actions per collection

Roles & Grants

-- Group role: read-only access to the schema
CREATE ROLE readonly NOLOGIN;
GRANT CONNECT ON DATABASE shop TO readonly;
GRANT USAGE  ON SCHEMA public TO readonly;
GRANT SELECT ON ALL TABLES IN SCHEMA public
  TO readonly;
ALTER DEFAULT PRIVILEGES IN SCHEMA public
  GRANT SELECT ON TABLES TO readonly;   -- future

-- A login that inherits it
CREATE ROLE analyst LOGIN PASSWORD 'change-me';
GRANT readonly TO analyst;

-- App login: data only, no DDL
CREATE ROLE app_rw LOGIN PASSWORD 'from-vault';
GRANT SELECT, INSERT, UPDATE, DELETE
  ON ALL TABLES IN SCHEMA public TO app_rw;
GRANT USAGE ON ALL SEQUENCES IN SCHEMA public
  TO app_rw;
REVOKE DELETE ON orders FROM app_rw;

-- Only some columns
GRANT SELECT (customer_id, name, city)
  ON customers TO support;

Code Explained

NOLOGIN — a group role; nobody signs in as it
USAGE ON SCHEMA is needed before any table access
Sequence USAGE lets inserts take identity values
Column grants hide email from the support role

⚠ Common Mistakes

  • The app connecting as a superuser or owner
  • Granting on ALL TABLES but forgetting future tables
  • Shared logins that make audits meaningless

✓ Tips & Best Practices

  • Grant to group roles, then add people to groups
  • Keep passwords in a secret store; rotate them
  • PG RLS: CREATE POLICY … USING (tenant_id = …)

Quick Summary

  • Roles = users + groups
  • GRANT / REVOKE privileges
  • Least privilege per role
