Sheet 22

String Functions — Transform

LENGTH · UPPER · LOWER · TRIM · LPAD · RPAD · REPEAT · INITCAP

Reshaping Text

These functions return a changed copy of a string; the stored value only changes if you UPDATE it. length counts characters, upper / lower / initcap change case, trim strips spaces (or any characters you name) from one or both ends, lpad / rpad pad to a fixed width, and repeat repeats. The most common use is cleaning input: lower(trim(email)) before comparing or storing.

Transform Facts

  • Functions don't modify data unless used in UPDATE
  • lpad cuts strings longer than the width
  • MySQL LENGTH() counts bytes; use CHAR_LENGTH()
  • NULL in → NULL out

NoSQL Comparison

  • MongoDB: $toUpper, $toLower, $trim, $ltrim, $rtrim
  • $strLenCP counts characters, $strLenBytes bytes
  • Used inside $project / $set pipeline stages

Transform Functions

SELECT name,
       length(name)   AS chars,
       upper(name)    AS shout,
       lower(email)   AS email_key,
       initcap(name)  AS proper       -- Ada Lovelace
FROM   customers;

SELECT trim('  hi  '),                 -- 'hi'
       ltrim('  hi'), rtrim('hi  '),
       trim(BOTH '-' FROM '--x--'),    -- 'x'
       trim(LEADING '0' FROM '00420'); -- '420'

SELECT lpad(order_id::text, 6, '0') AS ref  -- 000042
FROM   orders;
SELECT rpad('ab', 5, '.'),             -- 'ab...'
       lpad('abcdef', 3),              -- 'abc' (cut!)
       repeat('=', 10);

-- Clean data in place
UPDATE customers
SET    email = lower(trim(email)),
       name  = initcap(trim(name));

Code Explained

initcap capitalizes each word and lowercases the rest
trim(BOTH | LEADING | TRAILING 'x' FROM s) — standard form
lpad(…, 6, '0') — zero-padded reference numbers
The UPDATE normalizes every row once

In an ORM

// Normalize on write instead of on every read
await prisma.customer.create({
  data: { name, email: email.trim().toLowerCase() },
});

⚠ Common Mistakes

  • Using MySQL LENGTH() to validate character limits
  • lpad silently cutting values longer than the width
  • Calling lower() in every query instead of storing clean data

✓ Tips & Best Practices

  • Normalize once on write: trim, case, collapse spaces
  • Index lower(email) if you must compare case-insensitively
  • initcap mangles names like McDonald; don't force it
