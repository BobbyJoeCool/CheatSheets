CROSS JOIN & Self Joins

CROSS JOIN · Cartesian product · self join · employee/manager · pairs · date spine

Every Combination, and a Table with Itself

CROSS JOIN pairs every row of one table with every row of another (the Cartesian product): 3 sizes × 2 colors = 6 rows. It's useful for building grids and calendars, and dangerous by accident. A self join joins a table to itself under two aliases, which is how you follow employees.manager_id back to employees, or compare rows within one table. A date spine (one row per day) left-joined to your data shows days with zero activity.

Facts

  • Row count of a cross join = m × n
  • A self join needs two different aliases
  • a.id < b.id lists each pair once
  • For the previous row, use LAG (sheet 46)

NoSQL Comparison

  • MongoDB has no cross join
  • Self references use $lookup on the same collection
  • Whole hierarchies: $graphLookup (sheet 42)

CROSS & Self Joins

-- Every size with every color: 3 × 2 = 6 rows
SELECT s.size, c.color
FROM   (VALUES ('S'), ('M'), ('L')) AS s(size)
CROSS  JOIN (VALUES ('red'), ('blue')) AS c(color);

-- Self join: employee and manager
SELECT e.first_name AS employee,
       m.first_name AS manager
FROM   employees e
LEFT   JOIN employees m ON m.emp_id = e.manager_id;

-- Same-category product pairs, each pair once
SELECT a.name, b.name
FROM   products a
JOIN   products b
  ON   a.category   = b.category
 AND   a.product_id < b.product_id;

-- Date spine: every day, even with no orders
SELECT d::date AS day, count(o.order_id) AS orders
FROM   generate_series(DATE '2026-10-01',
                       DATE '2026-10-31',
                       INTERVAL '1 day') AS d
LEFT   JOIN orders o ON o.order_date = d::date
GROUP  BY d
ORDER  BY d;

Code Explained

VALUES … AS s(size) — an inline table with a column name
LEFT JOIN keeps the top boss, whose manager_id is NULL
< instead of <> avoids (A, B) and (B, A) duplicates
generate_series builds the 31 days to join against

⚠ Common Mistakes

  • Accidental cross join from a missing ON: millions of rows
  • Self join with <> returning every pair twice
  • Using INNER for the manager join and losing the CEO

✓ Tips & Best Practices

  • Check count(*) on any join that looks slow
  • Name self-join aliases by role: employee, manager
  • Keep a calendar table for reporting spines

Quick Summary

  • CROSS JOIN — all combinations
  • Self join — two aliases, one table
  • Spine + LEFT JOIN — no gaps
