Window Function Basics

OVER () · PARTITION BY · ORDER BY · WINDOW clause · window vs GROUP BY

Calculations Across Rows

A window function computes a value over a set of rows related to the current row, but unlike GROUP BY it keeps every row. OVER (…) defines the window: PARTITION BY splits rows into groups, ORDER BY orders rows inside each group, and an empty OVER () means the whole result. Any aggregate (sum, avg, count) becomes a window function when you add OVER. They run after WHERE, GROUP BY and HAVING, so you can't filter on them directly.

Window Facts

  • Detail and group values side by side, no join
  • Not allowed in WHERE: wrap in a CTE (sheet 49)
  • ORDER BY inside OVER changes the frame (sheet 48)
  • WINDOW w AS (…) names a window for reuse

NoSQL Comparison

  • MongoDB 5.0+: $setWindowFields
  • { partitionBy: '$category', sortBy: { price: 1 }, output: { catAvg: { $avg: '$price' } } }
  • Same idea: every document keeps its fields

OVER & PARTITION BY

-- Each product next to its category average
SELECT name, category, price,
       avg(price) OVER (PARTITION BY category) AS cat_avg
FROM   products;

-- Share of the grand total, every row kept
SELECT order_id, total,
       sum(total) OVER ()                       AS grand,
       round(100 * total / sum(total) OVER (), 1) AS pct
FROM   orders;

-- Number each customer's orders in date order
SELECT customer_id, order_id, order_date,
       row_number() OVER (PARTITION BY customer_id
                          ORDER BY order_date) AS nth
FROM   orders;

-- Named window, used twice
SELECT first_name, dept_id, salary,
       min(salary) OVER w AS dept_min,
       max(salary) OVER w AS dept_max
FROM   employees
WINDOW w AS (PARTITION BY dept_id);

Code Explained

PARTITION BY category — one average per category, on every row
OVER () — the window is the whole result
row_number() restarts at 1 for each customer
WINDOW w avoids repeating the same OVER (…)

⚠ Common Mistakes

  • Filtering with WHERE rank_col = 1 in the same query
  • Adding ORDER BY to an average window and getting a running average
  • Using GROUP BY + self-join where a window would do

✓ Tips & Best Practices

  • Think of PARTITION BY as GROUP BY that keeps rows
  • Name windows with WINDOW when used more than once
  • Index (partition cols, order cols) for big windows

Quick Summary

  • f() OVER (PARTITION BY … ORDER BY …)
  • Keeps every row
  • Runs after GROUP BY / HAVING
