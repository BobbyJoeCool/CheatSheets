Sheet 57

Constraints

NOT NULL · UNIQUE · CHECK · CONSTRAINT name · DEFERRABLE · EXCLUDE

Rules the Database Enforces

Constraints reject bad data no matter which app or script writes it. NOT NULL requires a value; UNIQUE forbids duplicates (NULLs usually don't count); CHECK requires a condition to be true (or NULL); keys link and identify rows (sheet 56). Name constraints with CONSTRAINT name so errors are readable. PostgreSQL adds DEFERRABLE (check at commit, not per statement) and EXCLUDE (no two rows may overlap, such as double-booked rooms).

Constraint Facts

  • CHECK passes when the expression is NULL
  • UNIQUE creates an index behind the scenes
  • A unique index on an expression handles case-insensitive rules
  • Adding a constraint validates existing rows

NoSQL Comparison

  • MongoDB: unique indexes enforce UNIQUE
  • $jsonSchema validators cover required, minimum, maximum, enum
  • Validation can warn instead of reject (validationAction)

Constraints

CREATE TABLE coupons (
  code      VARCHAR(20)  NOT NULL,
  percent   NUMERIC(5,2) NOT NULL,
  starts_on DATE NOT NULL,
  ends_on   DATE,
  CONSTRAINT coupons_code_uq UNIQUE (code),
  CONSTRAINT coupons_pct_chk
    CHECK (percent > 0 AND percent <= 100),
  CONSTRAINT coupons_dates_chk
    CHECK (ends_on IS NULL OR ends_on > starts_on)
);

-- Treat NULLs as equal (PostgreSQL 15+)
ALTER TABLE customers ADD CONSTRAINT email_uq
  UNIQUE NULLS NOT DISTINCT (email);

-- No overlapping bookings per room
CREATE EXTENSION IF NOT EXISTS btree_gist;
CREATE TABLE bookings (
  room   INT,
  during TSTZRANGE,
  EXCLUDE USING gist (room WITH =, during WITH &&)
);

Code Explained

Named checks show up in error messages by name
ends_on IS NULL OR … allows open-ended coupons
NULLS NOT DISTINCT allows only one NULL email
&& means "ranges overlap"; EXCLUDE forbids it per room

Constraint Types

ConstraintRejects
NOT NULLmissing values
UNIQUE (cols)duplicate values or combinations
CHECK (expr)rows where expr is false
PRIMARY KEYduplicates and NULLs
FOREIGN KEYreferences to missing rows
EXCLUDE (PG)rows that conflict by any operator

⚠ Common Mistakes

  • Checking rules only in app code
  • Expecting CHECK (x > 0) to reject NULL
  • Adding a constraint to a huge table at peak time

✓ Tips & Best Practices

  • Case-insensitive unique: UNIQUE INDEX … (lower(email))
  • Add big constraints as NOT VALID, then VALIDATE (PG)
  • Use DEFERRABLE for circular or swap-style updates

Quick Summary

  • NOT NULL · UNIQUE · CHECK
  • Name them: CONSTRAINT x …
  • DEFERRABLE · EXCLUDE (PG)
