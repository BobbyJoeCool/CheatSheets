Sheet 14

Filtering with WHERE

WHERE · AND · OR · NOT · parentheses · precedence · aliases in WHERE

Keeping Some Rows

WHERE keeps only the rows whose condition is TRUE (not FALSE, not UNKNOWN). Join conditions with AND, OR and NOT. AND binds tighter than OR, exactly like * before +, so mixing them without parentheses is the classic filtering bug. WHERE runs before SELECT, which is why output aliases aren't visible here.

WHERE Facts

  • Rows where the condition is NULL are dropped
  • Precedence: NOT → AND → OR
  • The planner picks evaluation order, not you
  • Test a filter with SELECT before UPDATE / DELETE

NoSQL Comparison

  • MongoDB filter documents have the same shape:
  • { $or: [{ category: 'Books' }, { category: 'Games' }], price: { $lt: 10 } }
  • Top-level fields are ANDed together

WHERE

SELECT name, price FROM products
WHERE  price > 20;

SELECT * FROM orders
WHERE  status = 'paid'
  AND  order_date >= DATE '2026-01-01';

-- AND binds first: not what it looks like
SELECT * FROM products
WHERE  category = 'Books' OR category = 'Games'
  AND  price < 10;   -- Books OR (Games AND < 10)

SELECT * FROM products
WHERE  (category = 'Books' OR category = 'Games')
  AND  price < 10;

SELECT * FROM customers
WHERE  NOT (country = 'US' OR country = 'CA');

-- Output alias isn't visible: repeat the expression
SELECT name, price * 0.9 AS sale FROM products
WHERE  price * 0.9 < 20;

Code Explained

Without parentheses, cheap Books slip through at any price
NOT (a OR b) = NOT a AND NOT b (De Morgan)
sale doesn't exist yet when WHERE runs
Wrap the query in a CTE (sheet 41) to filter on an alias

⚠ Common Mistakes

  • Mixing AND and OR without parentheses
  • Referencing a SELECT alias in WHERE
  • Forgetting WHERE on an UPDATE or DELETE

✓ Tips & Best Practices

  • Always parenthesize OR groups, even when not required
  • Put each condition on its own line, AND at the start
  • Write date ranges half-open: >= start AND < end

Quick Summary

  • WHERE keeps TRUE rows only
  • AND before OR; use parentheses
  • No output aliases in WHERE
