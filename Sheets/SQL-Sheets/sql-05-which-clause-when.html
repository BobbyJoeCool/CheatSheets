Sheet 05

Which Clause When

WHERE vs HAVING · GROUP BY vs ORDER BY vs PARTITION BY · DISTINCT vs GROUP BY · JOIN vs subquery vs CTE · IN vs EXISTS · UNION vs UNION ALL · DELETE vs TRUNCATE vs DROP

Filtering

PickUse it when#
WHEREfilter rows before grouping; no aggregates allowed14
HAVINGfilter groups after GROUP BY, using aggregates29
FILTER (WHERE …)count or sum only some rows inside one aggregate29
CASE in SELECTlabel or transform values, not remove rows21
QUALIFYfilter on a window result (DuckDB, Snowflake); elsewhere wrap in a CTE49

Grouping & Sorting

PickUse it when#
GROUP BYcollapse rows to one per group with aggregates28
PARTITION BYcompute per group but keep every row (window)44
ORDER BYsort the final output; the only way to guarantee order15
DISTINCTdrop duplicate output rows; no aggregates needed17
GROUP BY vs DISTINCTsame rows without aggregates; prefer DISTINCT for intent17
ROLLUP / CUBEadd subtotal and grand-total rows30

Paging

PickUse it when#
LIMIT / OFFSETfirst pages, small offsets (PG, MySQL, SQLite)16
FETCH FIRST n ROWSstandard form; also SQL Server with OFFSET16
TOP (n)SQL Server only16
keyset (WHERE id > last)deep pages and infinite scroll; stays fast16

Combining Tables

PickUse it when#
INNER JOINneed columns from both tables, matches only32
LEFT JOINkeep every left row, even without a match33
scalar subqueryneed one value from another query38
derived tablea one-off step in FROM (…) AS t40
CTE (WITH)name steps, reuse one, or read top to bottom41
recursive CTEwalk a hierarchy or generate a series42
LATERAL / APPLYrun a subquery per row (top-N per customer)37
viewsave a query for many callers64

Existence Tests

PickUse it when#
IN (subquery)match against a list; fine for semi-joins38
EXISTS"has at least one"; stops at the first match36
NOT EXISTS"has none"; NULL-safe anti-join36
NOT INonly when the list cannot contain NULL36
LEFT JOIN … IS NULLanti-join when you also need left columns36

Stacking Results

PickUse it when#
UNION ALLstack two queries' rows, keep duplicates (fast)43
UNIONstack and remove duplicates (sorts or hashes)43
INTERSECTrows present in both queries43
EXCEPTrows in the first query but not the second43

Changing Data

PickUse it when#
INSERT … VALUESadd rows you have in hand50
INSERT … SELECTcopy rows from a query50
UPDATEchange columns in existing rows51
ON CONFLICT / MERGEinsert or update in one statement (upsert)53
COPY / LOAD DATAload thousands of rows from a file54

Removing Data

PickUse it when#
DELETE … WHEREremove some rows; triggers fire; can roll back52
TRUNCATEempty a whole table fast; resets identity with RESTART IDENTITY52
DROP TABLEremove the table itself: data, indexes, grants59
soft deleteUPDATE … SET deleted_at = now(); keep history52
