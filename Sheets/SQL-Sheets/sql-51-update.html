UPDATE

UPDATE · SET · WHERE · UPDATE … FROM · UPDATE JOIN · RETURNING · OUTPUT

Changing Rows

UPDATE table SET col = expr WHERE … changes every row the WHERE matches, and every row in the table if you leave WHERE off. Expressions on the right see the old values, so SET stock = stock - 1 works and two columns can swap. To update from another table, PostgreSQL and SQLite use UPDATE … FROM, MySQL and SQL Server join in the update. RETURNING shows the changed rows.

UPDATE Facts

  • No WHERE = every row
  • All SET expressions read the old row
  • The result reports how many rows changed
  • Run the WHERE as a SELECT first

NoSQL Comparison

  • MongoDB: updateMany({ category: 'Books' }, { $mul: { price: 1.05 } })
  • $set, $inc, $unset change single fields
  • findOneAndUpdate returns the document, like RETURNING

UPDATE

UPDATE products
SET    price = price * 1.05
WHERE  category = 'Books';

UPDATE products
SET    price = 24.99,
       stock = stock + 10
WHERE  product_id = 7
RETURNING product_id, price, stock;

-- Update from another table (PostgreSQL, SQLite)
UPDATE orders o
SET    total = s.amt
FROM  (SELECT order_id, sum(quantity * unit_price) AS amt
       FROM   order_items
       GROUP  BY order_id) s
WHERE  s.order_id = o.order_id;

-- Portable: correlated subquery
UPDATE orders o
SET    total = (SELECT sum(quantity * unit_price)
                FROM   order_items i
                WHERE  i.order_id = o.order_id);

Code Explained

price * 1.05 reads each row's current price
RETURNING lists the rows after the change
FROM joins the pre-aggregated item totals
The subquery form sets NULL for orders with no items

Dialect Notes

In an ORM

await prisma.product.updateMany({
  where: { category: 'Books' },
  data: { price: { multiply: 1.05 } },
});                             // → { count: 12 }
await prisma.product.update({
  where: { id: 7 }, data: { price: 24.99 },
});

⚠ Common Mistakes

  • Forgetting WHERE and updating every row
  • Expecting SET a = b, b = a to fail (it swaps)
  • Correlated update setting NULL where no source row exists

✓ Tips & Best Practices

  • Wrap risky updates in a transaction and check the count
  • Update in batches on huge tables to keep locks short
  • Add AND col IS DISTINCT FROM new to skip no-op writes

Quick Summary

  • UPDATE t SET … WHERE …
  • Right side sees old values
  • FROM / JOIN to use other tables
