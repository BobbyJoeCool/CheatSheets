Bulk Loading & Export

COPY · \copy · LOAD DATA INFILE · BULK INSERT · .import · CSV

Moving Data In and Out in Bulk

For thousands or millions of rows, use the engine's bulk path instead of INSERT: PostgreSQL COPY, MySQL LOAD DATA, SQL Server BULK INSERT / bcp, SQLite's .import. They stream rows with far less overhead. Watch where the file lives: server-side commands read files on the database server, while client-side ones (\copy, LOAD DATA LOCAL) read files on your machine. Most of them also export.

Bulk Facts

  • Server-side file access needs extra privileges
  • \copy is a psql command: one line, no ;
  • Load into a staging table, validate, then insert
  • CSV quirks: header row, quotes, NULL marker

NoSQL Comparison

  • mongoimport --type csv --headerline -d shop -c products products.csv
  • mongoexport writes JSON or CSV
  • insertMany(docs, { ordered: false }) for app-side batches

Load & Export

-- PostgreSQL: file on the server
COPY products (name, category, price, stock)
FROM '/srv/import/products.csv'
WITH (FORMAT csv, HEADER true);

-- psql: file on your machine (one line, no ;)
\copy products FROM 'products.csv' CSV HEADER
\copy (SELECT * FROM orders) TO 'orders.csv' CSV HEADER

-- MySQL
LOAD DATA LOCAL INFILE 'products.csv'
INTO TABLE products
FIELDS TERMINATED BY ',' ENCLOSED BY '"'
IGNORE 1 LINES (name, category, price, stock);

-- SQL Server
BULK INSERT products FROM 'C:\data\products.csv'
WITH (FORMAT = 'CSV', FIRSTROW = 2);

-- SQLite shell
.import --csv --skip 1 products.csv products

Code Explained

HEADER true skips the first line on input
\copy streams through the client connection
IGNORE 1 LINES — MySQL's header skip
--skip 1 — skip the header in the SQLite shell

Dialect Notes

EngineSyntax / behavior

MySQLLOAD DATA [LOCAL]; SELECT … INTO OUTFILE; local_infile=1

SQLite.import --csv; export with .mode csv + .once

In an ORM

// createMany sends multi-row INSERTs
await prisma.product.createMany({
  data: rows,             // parsed from the CSV
  skipDuplicates: true,   // ON CONFLICT DO NOTHING

⚠ Common Mistakes

  • Using server-side COPY with a path on your laptop
  • Loading straight into production tables with bad rows
  • Forgetting ANALYZE after a big load

✓ Tips & Best Practices

  • Keep loads idempotent: truncate staging, reload, merge (sheet 53)
  • Match column order explicitly in the command
  • Use NULL '' / NULL AS options for empty fields
