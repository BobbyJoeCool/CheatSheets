Rounding & Math

round(x, d) rounds to d decimal places (a negative d rounds to tens, hundreds…). ceil goes up, floor goes down, and trunc just cuts digits off, which differs from floor for negative numbers. abs, mod, power and sqrt do what their names say. random() returns a value from 0 up to (not including) 1, handy for sampling and test data.

Math Facts

  • numeric rounds half away from zero: 2.5 → 3
  • float8 rounds half to even: 2.5 → 2
  • floor(-4.1) = -5, trunc(-4.1) = -4
  • PG log(x) is base 10, ln(x) natural

NoSQL Comparison

  • MongoDB pipelines: $round, $ceil, $floor, $trunc, $abs, $mod, $pow
  • $rand gives 0 ≤ x < 1
  • $sample: { size: 3 } picks random documents

Numeric Functions

SELECT round(2.5), round(-2.5), round(3.14159, 2);
-- 3 | -3 | 3.14
SELECT round(1234.5, -2);                  -- 1200
SELECT ceil(4.1), floor(4.9), trunc(4.99); -- 5 | 4 | 4
SELECT ceil(-4.1), floor(-4.1), trunc(-4.9);
-- -4 | -5 | -4
SELECT abs(-7), mod(17, 5), 17 % 5;        -- 7 | 2 | 2
SELECT power(2, 10), sqrt(16), cbrt(27);   -- 1024 | 4 | 3
SELECT sign(-3), ln(10), log(100);         -- -1 | 2.30… | 2

-- Order totals to two places
SELECT order_id, round(sum(unit_price * quantity), 2)
FROM   order_items
GROUP  BY order_id;

SELECT ceil(95 / 20.0);     -- pages for 95 rows → 5

SELECT random();                        -- 0 ≤ x < 1
SELECT floor(random() * 6 + 1)::int;    -- dice 1–6
SELECT * FROM products ORDER BY random() LIMIT 3;

Code Explained

round(x, -2) rounds to the nearest hundred
ceil(95 / 20.0) — the .0 avoids integer division
floor(random() * n + 1) → whole number from 1 to n
ORDER BY random() sorts the whole table: fine for small ones

⚠ Common Mistakes

  • Rounding each line, then summing: totals drift by cents
  • Expecting trunc and floor to agree on negatives
  • SQL Server ORDER BY RAND(): same value for every row

✓ Tips & Best Practices

  • Round once, at the end, on numeric values
  • Sample huge tables with TABLESAMPLE SYSTEM (1) (PG)
  • Use setseed() for repeatable random test data
