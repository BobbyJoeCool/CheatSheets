Window Frames

ROWS · RANGE · GROUPS · UNBOUNDED PRECEDING · CURRENT ROW · N FOLLOWING · EXCLUDE

Which Rows the Function Sees

The frame is the slice of the partition an aggregate or value function looks at for the current row. ROWS counts physical rows; RANGE uses the distance between ORDER BY values, so rows with equal values (peers) move together; GROUPS counts groups of peers. With ORDER BY and no frame, the default is RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW, which includes the current row's peers. Without ORDER BY the frame is the whole partition.

Frame Facts

  • Frames apply to aggregates and value functions only
  • lag, lead and ranking functions ignore frames
  • RANGE n PRECEDING needs one numeric or date sort key
  • EXCLUDE drops the current row, its peers or ties

NoSQL Comparison

  • MongoDB: window: { documents: [-1, 1] } = ROWS 1 PRECEDING AND 1 FOLLOWING
  • window: { range: [-1, 0] } = RANGE
  • Bounds: numbers, 'current', 'unbounded'

Frames Compared

WITH s(d, v) AS (
  VALUES (1, 10), (2, 20), (2, 5), (3, 30))
SELECT d, v,
  sum(v) OVER (ORDER BY d) AS dflt,
  sum(v) OVER (ORDER BY d ROWS
    BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)
                           AS rows_run,
  sum(v) OVER (ORDER BY d ROWS
    BETWEEN 1 PRECEDING AND 1 FOLLOWING)
                           AS nbr,
  sum(v) OVER (ORDER BY d RANGE
    BETWEEN 1 PRECEDING AND CURRENT ROW)
                           AS rng,
  sum(v) OVER (ORDER BY d GROUPS
    BETWEEN 1 PRECEDING AND CURRENT ROW)
                           AS grp,
  sum(v) OVER (ORDER BY d ROWS
    BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    EXCLUDE CURRENT ROW)   AS others
FROM s;

Code Explained

The two d = 2 rows are peers
dflt gives both peers 35; rows_run steps 30 → 35
RANGE 1 PRECEDING at d = 3 covers d 2 to 3
others = everything except the current row

⚠ Common Mistakes

  • Relying on the default frame for last_value (sheet 46)
  • Using RANGE and wondering why ties share a value

✓ Tips & Best Practices

  • Write the frame out in full when it matters
  • ROWS is also faster than RANGE in SQL Server
  • Test frames on a tiny VALUES table like this one

Quick Summary

  • Default with ORDER BY: start → current + peers
