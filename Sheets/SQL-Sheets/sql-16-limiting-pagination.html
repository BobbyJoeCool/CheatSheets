Limiting & Pagination

LIMIT · OFFSET · FETCH FIRST · TOP · WITH TIES · keyset pagination

Returning a Page of Rows

LIMIT n returns the first n rows of the sorted result; OFFSET k skips k rows first. The standard spelling is OFFSET k ROWS FETCH NEXT n ROWS ONLY, and SQL Server also has TOP. OFFSET still reads every skipped row, so deep pages get slow and rows shift when data changes. Keyset pagination instead filters past the last row you saw, so page 1,000 costs the same as page 1.

Paging Facts

  • Always pair a limit with ORDER BY
  • Sort by a unique key, or pages overlap
  • WITH TIES also returns rows tied with the last
  • Fetch n + 1 rows to know if a next page exists

NoSQL Comparison

  • MongoDB: .sort({ _id: 1 }).skip(20).limit(10)
  • skip has the same deep-page cost as OFFSET
  • Keyset: find({ _id: { $gt: lastId } }).limit(10)

Limit & Paginate

SELECT name, price FROM products
ORDER  BY price DESC
LIMIT  10;                              -- top 10

SELECT name, price FROM products
ORDER  BY price DESC, product_id
LIMIT  10 OFFSET 20;                    -- page 3

-- Standard form (PG, SQL Server, Oracle)
SELECT name, price FROM products
ORDER  BY price DESC
OFFSET 20 ROWS FETCH NEXT 10 ROWS ONLY;

SELECT name, price FROM products
ORDER  BY price DESC
FETCH  FIRST 3 ROWS WITH TIES;          -- + ties

-- Keyset: continue after the last row seen
SELECT order_id, order_date FROM orders
WHERE  (order_date, order_id) < ('2026-09-30', 4211)
ORDER  BY order_date DESC, order_id DESC
LIMIT  20;

Code Explained

product_id breaks price ties so pages don't overlap
Page p of size n → OFFSET (p - 1) * n
WITH TIES needs ORDER BY; may return more than 3
Row comparison (a, b) < (x, y) resumes after the last row

In an ORM

await prisma.order.findMany({
  orderBy: [{ orderDate: 'desc' }, { id: 'desc' }],
  take: 20,
  skip: 1,                 // skip the cursor row
  cursor: { id: lastId },  // keyset-style paging
});

⚠ Common Mistakes

  • LIMIT without ORDER BY: a different 10 rows each time
  • Sorting by a non-unique column, so rows repeat across pages
  • Running count(*) over a huge table for every page

✓ Tips & Best Practices

  • Index the sort columns in sort order
  • Use keyset for anything users scroll through
  • Return the cursor (last key) to the client

Quick Summary

  • LIMIT / OFFSET · FETCH FIRST · TOP
  • WITH TIES keeps ties
  • Keyset = WHERE key > last
