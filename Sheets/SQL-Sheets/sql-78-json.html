JSON

json · jsonb · -> · ->> · @> · jsonb_set · JSON_VALUE · JSON_EXTRACT

Documents Inside Rows

JSON columns hold flexible attributes that don't deserve their own columns: product specs, settings, raw API payloads. PostgreSQL's jsonb stores parsed, binary JSON that can be indexed; -> returns a JSON value, ->> returns text, and @> tests containment. Change part of a document with jsonb_set or ||. The SQL standard's JSON_VALUE / JSON_QUERY / JSON_TABLE work in PostgreSQL 17+, MySQL and SQL Server.

JSON Facts

  • jsonb drops duplicate keys and whitespace
  • Keep fields you filter or join on as real columns
  • A GIN index speeds up @> and ?
  • Cast ->> text before comparing numbers

NoSQL Comparison

  • This is MongoDB's home ground: documents are the data
  • find({ 'size.w': { $gt: 20 } }) queries nested fields
  • $set: { 'size.w': 35 } updates one field in place

jsonb

ALTER TABLE products ADD COLUMN attrs JSONB;
UPDATE products
SET    attrs = '{"color": "black",
                 "size": {"w": 30, "h": 45},
                 "tags": ["desk", "led"]}'
WHERE  product_id = 7;

SELECT attrs -> 'size'                 AS size_json,
       attrs ->> 'color'               AS color,
       attrs #>> '{size,w}'            AS width,
       (attrs -> 'size' ->> 'h')::int  AS height,
       JSON_VALUE(attrs, '$.size.w')   AS w_std  -- PG 17
FROM   products
WHERE  product_id = 7;

-- Containment and key tests (GIN-indexable)
SELECT name FROM products
WHERE  attrs @> '{"color": "black"}';
SELECT name FROM products WHERE attrs -> 'tags' ? 'led';

UPDATE products
SET    attrs = jsonb_set(attrs, '{color}', '"white"')
WHERE  product_id = 7;
UPDATE products SET attrs = attrs - 'tags';

Code Explained

-> keeps JSON; ->> gives text
#>> follows a path: {size,w} = size.w
@> — does the document contain this fragment?
jsonb_set replaces one path; - 'key' removes a key

In an ORM

await prisma.product.findMany({
  where: { attrs: { path: ['color'], equals: 'black' } },
});
await prisma.product.update({
  where: { id: 7 },
  data: { attrs: { color: 'white', size: { w: 30 } } },
});   // replaces the whole JSON value

⚠ Common Mistakes

  • Putting core, frequently filtered fields only inside JSON
  • Comparing ->> text to numbers without a cast
  • Using json when you meant jsonb

✓ Tips & Best Practices

  • Promote hot JSON keys to generated columns + indexes
  • Validate shape with CHECK (jsonb_typeof(attrs) = 'object')
  • Index with USING gin (attrs) for @> and ? lookups
