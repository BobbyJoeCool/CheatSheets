Sheet 73

Reading Query Plans

EXPLAIN · EXPLAIN ANALYZE · Seq Scan · Index Scan · Nested Loop · Hash Join · cost

How the Database Runs Your Query

EXPLAIN shows the plan the optimizer chose: a tree of steps such as scans, joins and sorts, each with an estimated cost and row count. EXPLAIN ANALYZE actually runs the query and adds real times and row counts, so you can compare estimates with reality. Read it inside-out: the most indented nodes run first. Large gaps between estimated and actual rows usually mean stale statistics (sheet 74).

Plan Facts

  • ANALYZE executes the query: careful with writes
  • Wrap write statements in BEGIN … ROLLBACK
  • Cost is in arbitrary units; compare, don't read literally
  • A seq scan isn't always bad: small tables, big results

NoSQL Comparison

  • MongoDB: db.orders.find({ … }).explain('executionStats')
  • COLLSCAN = full scan, IXSCAN = index
  • Compare totalDocsExamined with nReturned

EXPLAIN

EXPLAIN
SELECT * FROM orders WHERE customer_id = 42;
-- Index Scan using orders_customer_id_idx on orders
--   (cost=0.29..8.31 rows=5 width=40)
--   Index Cond: (customer_id = 42)

EXPLAIN (ANALYZE, BUFFERS)
SELECT c.name, sum(o.total)
FROM   customers c
JOIN   orders o USING (customer_id)
WHERE  o.order_date >= '2026-10-01'
GROUP  BY c.name;
-- HashAggregate (actual time=4.1..4.3 rows=120)
--   -> Hash Join (rows=900) (actual rows=1150)
--        Hash Cond: (o.customer_id = c.customer_id)
--        -> Seq Scan on orders o
--             Filter: (order_date >= '2026-10-01')
--             Rows Removed by Filter: 48850
--        -> Hash
--             -> Seq Scan on customers c
-- Planning Time: 0.3 ms
-- Execution Time: 4.6 ms        (output trimmed)

Code Explained

cost=0.29..8.31 — startup cost .. total cost
rows=900 estimate vs actual rows=1150: close enough
48,850 rows removed by a filter → an index candidate
Hash Join builds a hash of customers, probes with orders

Numbers to Read

FieldTells you
cost=a..bstartup .. total estimate
rows=estimated rows out
actual time=a..bms to first .. last row
loops=times the node ran (multiply!)
Rows Removed by Filterwasted reads
Buffers: shared hit / readcache hits / disk reads

⚠ Common Mistakes

  • Tuning from EXPLAIN estimates without ANALYZE
  • Running EXPLAIN ANALYZE DELETE … outside a rolled-back transaction
  • Ignoring loops: per-loop time × loops = real time

✓ Tips & Best Practices

  • Paste plans into explain.dalibo.com or explain.depesz.com
  • Fix the node with the biggest actual time first
  • Compare plans before and after each change

Quick Summary

  • EXPLAIN — plan · ANALYZE — real run
  • Read inner nodes first
  • Estimates vs actuals → statistics
