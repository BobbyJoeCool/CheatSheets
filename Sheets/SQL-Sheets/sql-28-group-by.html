Sheet 28

GROUP BY

GROUP BY · multiple columns · grouping expressions · functional dependency · ONLY_FULL_GROUP_BY

One Row per Group

GROUP BY sorts rows into groups, one per distinct value (or combination of values) of the listed columns or expressions, and each aggregate is computed per group. Every column in SELECT must either appear in GROUP BY or sit inside an aggregate. The exception is functional dependency: group by a table's primary key and PostgreSQL and MySQL let you select its other columns too. All NULLs fall into one group.

Grouping Rules

  • Selectable: grouped columns, aggregates, constants
  • Not selectable: other plain columns (with exceptions)
  • Group order isn't output order; add ORDER BY
  • GROUP BY runs after WHERE, before HAVING

NoSQL Comparison

  • MongoDB: { $group: { _id: '$status', n: { $sum: 1 } } }
  • Several keys: _id: { country: '$country', city: '$city' }
  • Group key comes back in _id; rename it with $project

GROUP BY

SELECT status, count(*) AS n, sum(total) AS revenue
FROM   orders
GROUP  BY status
ORDER  BY revenue DESC;

-- Several columns: one group per combination
SELECT country, city, count(*) AS customers
FROM   customers
GROUP  BY country, city;

-- Group by an expression
SELECT date_trunc('month', order_date) AS month,
       count(*)                        AS orders
FROM   orders
GROUP  BY date_trunc('month', order_date);

-- Join, then group (name depends on the PK)
SELECT c.customer_id, c.name, count(o.order_id) AS n
FROM   customers c
LEFT   JOIN orders o ON o.customer_id = c.customer_id
GROUP  BY c.customer_id;

SELECT category, name, count(*)
FROM   products GROUP BY category;
-- ERROR: column "products.name" must appear in GROUP BY

Code Explained

One output row per status, sorted by revenue
country, city → a group per unique pair
count(o.order_id) counts 0 for customers with no orders
name is legal because customer_id is the primary key

⚠ Common Mistakes

  • Selecting a column that isn't grouped or aggregated
  • Turning off ONLY_FULL_GROUP_BY and getting random values
  • Grouping by a display string (to_char) instead of a date

✓ Tips & Best Practices

  • Group by the key, select the details (functional dependency)
  • Aggregate in a CTE, then join for names (sheet 41)
  • Index the grouping columns for big tables

Quick Summary

  • GROUP BY → one row per group
  • SELECT = grouped columns + aggregates
  • NULLs share one group
