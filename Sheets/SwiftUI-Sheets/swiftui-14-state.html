@State

@State · private · source of truth · value types · view identity · state reset

Local View State

@State stores a value owned by a view. SwiftUI keeps the storage outside the struct, so it survives when body is recomputed, and changing it schedules a redraw. Mark it private: it belongs to this view alone. State lives as long as the view's identity; if the view is removed or its identity changes, the state resets.

Notes

  • Use for simple, local values: flags, text input, selection
  • Initialize with a default; don't set it from init parameters
  • .id(x) changes identity and resets state on purpose
  • Holds @Observable class instances too (Sheet 16)
  • Swift set: 095 · Property Wrappers

@State

struct SearchBox: View {
    @State private var query = ""
    @State private var isExpanded = false
    @State private var taps = 0

    var body: some View {
        VStack(alignment: .leading) {
            TextField("Search", text: $query)       // binding to state
            Button(isExpanded ? "Less" : "More") {
                isExpanded.toggle()                  // triggers redraw
                taps += 1
            }
            if isExpanded { Text("Typed: \(query)") }
            Text("Tapped \(taps) times").font(.caption)
        }
        .padding()
    }
}

#Preview { SearchBox() }

Minimum OS

  • @State: iOS 13
  • @State holding an @Observable class: iOS 17

UIKit / React Equivalent

  • UIKit Stored properties + manual label.text = … updates
  • React Native const [query, setQuery] = useState("")

⚠ Common Mistakes

  • Initializing @State from an init parameter: later parent changes are ignored
  • Using @State for data other views own: pass a @Binding or model instead
  • Making @State non-private and setting it from outside

✓ Tips & Best Practices

  • Keep state as close as possible to where it's used
  • Use .id(item.id) to reset a form when switching items
  • Group related state into a small struct

Quick Summary

  • @State — view-owned storage
