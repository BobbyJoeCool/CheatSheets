Previews

#Preview · traits · @Previewable · preview data · canvas modes · device variants

Live Previews

The #Preview macro shows a view in Xcode's canvas, updating as you type. You can declare several previews per file, give them names, and apply traits such as landscape orientation or a fixed size. @Previewable lets a preview use @State directly, so you can preview views that need a binding.

Notes

  • Previews run your real code in a small app process
  • Pin a preview to keep it visible while editing other files
  • Use sample data, never live network calls
  • Canvas modes: Live (interactive) and Selectable
  • Swift set: 096 · Macros

#Preview Variations

#Preview { CounterView() }

#Preview("Dark, large text") {
    CounterView()
        .preferredColorScheme(.dark)
        .dynamicTypeSize(.xxxLarge)
}

#Preview(traits: .landscapeLeft) { Dashboard() }
#Preview(traits: .sizeThatFitsLayout) { ProBadge() }

#Preview("Toggle row") {
    @Previewable @State var isOn = true       // state inside a preview
    SettingRow(title: "Wi-Fi", isOn: $isOn)
}

#Preview("With data") {
    NoteList()
        .modelContainer(for: Note.self, inMemory: true)
}

Code Explained

#Preview("name") — named preview
traits: — orientation, size
@Previewable @State — bindable preview state
inMemory: true — throwaway SwiftData store
modifiers — dark mode, Dynamic Type

Minimum OS

  • #Preview macro: Xcode 15
  • @Previewable: Xcode 16

UIKit / React Equivalent

  • UIKit #Preview { MyViewController() } works for UIKit too
  • React Native Storybook stories ≈ named previews

⚠ Common Mistakes

  • Calling the network or real database in previews: slow and flaky
  • Old PreviewProvider structs in new code: use #Preview
  • A crashing preview with no idea why: check the diagnostics button

✓ Tips & Best Practices

  • Create static let sample / .mock values on models for previews
  • Preview dark mode and large Dynamic Type every time
  • ⌥⌘↩ toggles the canvas; ⌥⌘P refreshes it
