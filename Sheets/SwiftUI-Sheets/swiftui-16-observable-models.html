@Observable Models

@Observable · Observation · @State with a class · @ObservationIgnored · fine-grained updates

Observable Model Classes

For data shared by several views or with logic attached, use a class marked @Observable. SwiftUI tracks which properties each view reads in body and redraws only those views when those properties change. The view that creates the model holds it in @State; other views simply receive it as a normal property.

Notes

  • No @Published needed: every stored property is tracked
  • Only properties read in body cause redraws
  • @ObservationIgnored excludes a property from tracking
  • Mark UI models @MainActor
  • Swift set: 096 · Macros, 061 · Classes

@Observable

import Observation

@MainActor @Observable
final class CartModel {
    var items: [Item] = []
    var couponCode = ""
    @ObservationIgnored var analytics = Analytics()   // not tracked

    var total: Decimal { items.reduce(0) { $0 + $1.price } }
    func add(_ item: Item) { items.append(item) }
}

struct ShopView: View {
    @State private var cart = CartModel()        // owner
    var body: some View {
        VStack {
            CartBadge(cart: cart)                // plain property
            Button("Add") { cart.add(.sample) }
        }
    }
}

struct CartBadge: View {
    let cart: CartModel                          // reads → tracked
    var body: some View { Text("\(cart.items.count) items") }
}

Code Explained

@Observable — macro adds change tracking
@State private var cart — owning view keeps it alive
let cart — other views just read it
computed total — tracked through items
@ObservationIgnored — opt out

Minimum OS

  • @Observable: iOS 17 / macOS 14
  • Before iOS 17: ObservableObject (Sheet 19)

UIKit / React Equivalent

  • UIKit Delegates, KVO, or Combine publishers to push updates
  • React Native Zustand / MobX store; selectors limit re-renders

⚠ Common Mistakes

  • Creating the model as a plain let in the owner: recreated on every parent update
  • Mixing @Published into an @Observable class
  • Mutating the model from a background thread without @MainActor

✓ Tips & Best Practices

  • Keep side effects (networking) in model methods, not views
  • Store large immutable data in let to skip tracking overhead
  • Use withObservationTracking outside SwiftUI if needed

Quick Summary

  • @Observable class — shared model
  • per-property redraws
  • owner uses @State, others let
