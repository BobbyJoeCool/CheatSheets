Apps, Scenes & Windows

A SwiftUI app starts at a type marked @main that conforms to App. Its body returns one or more scenes: WindowGroup for the main window (multiple windows on iPad and Mac), Settings for a Mac preferences window, and others like DocumentGroup and Window. App-wide setup, such as SwiftData containers and environment values, attaches here.

Notes

  • One @main App type per target
  • Xcode's App template creates MyApp.swift + ContentView.swift
  • Scenes can be modified like views (.modelContainer, .environment)
  • Use @State in the App for app-wide models

App Entry Point

import SwiftUI
import SwiftData

@main
struct NotesApp: App {
    @State private var store = NoteStore()      // app-wide model

    var body: some Scene {
        WindowGroup {
            ContentView()
                .environment(store)             // share with all views
        }
        .modelContainer(for: Note.self)         // SwiftData

        #if os(macOS)
        Settings { SettingsView() }             // ⌘, window on Mac
        #endif
    }
}

Code Explained

@main + App — program entry
some Scene — scene builder, like some View
WindowGroup — main window(s)
.environment(store) — inject a model
Settings — macOS preferences scene

Minimum OS

  • App / Scene: iOS 14 / macOS 11
  • Window (single window), openWindow: macOS 13

UIKit / React Equivalent

  • UIKit AppDelegate + SceneDelegate + root view controller
  • React Native App.tsx root component registered with AppRegistry

⚠ Common Mistakes

  • Creating models inside ContentView with @State when the whole app needs them
  • Two @main types in one target: compile error
  • Using Settings on iOS: it's Mac-only

✓ Tips & Best Practices

  • Use @UIApplicationDelegateAdaptor for push notification setup (Sheet 39)
  • Keep App small: create models, inject them, nothing else
  • Add .commands { } to a scene for Mac menu items

Quick Summary

  • @main struct X: App — entry
  • WindowGroup — main scene
  • inject app-wide state at the scene
