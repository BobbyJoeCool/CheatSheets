Making Views Fast

SwiftUI performance comes down to how often body runs and how much each run does. Keep body cheap, keep view identity stable, read only the state each view needs (Observation helps), and use lazy containers for long content. Self._printChanges() explains why a view redrew, and Instruments shows slow bodies and update causes.

Notes

  • Unstable IDs (like UUID() in body) rebuild views every time
  • AnyView hides structure from the diffing engine
  • Pass child views only the data they use
  • Format and sort in the model, not in body

Diagnosing Updates

struct MessageRow: View {
    let message: Message
    var body: some View {
        let _ = Self._printChanges()          // logs why body ran
        HStack { Text(message.sender).bold(); Text(message.preview) }
    }
}

// ✗ new identity every render → state lost, slow
ForEach(items, id: \.self) { … }               // when items aren't unique
List(items) { Row(id: UUID(), item: $0) }      // never generate IDs in body

// ✓ precompute in the model
@Observable final class Inbox {
    var messages: [Message] = [] { didSet { sorted = messages.sorted(by: >) } }
    private(set) var sorted: [Message] = []
}

struct Avatar: View, Equatable {               // skip redraws if equal
    let url: URL
    var body: some View { AsyncImage(url: url) }
}

Minimum OS

  • _printChanges: iOS 15 (debug only)
  • Observation's per-property tracking: iOS 17

UIKit / React Equivalent

  • UIKit Avoiding reloadData; profiling layoutSubviews
  • React Native React.memo, useMemo, FlatList keyExtractor

⚠ Common Mistakes

  • Sorting, filtering or formatting large data inside body
  • Whole-screen models read by every row: rows redraw on any change
  • .id(UUID()) to force refresh: destroys and rebuilds the view

✓ Tips & Best Practices

  • Split big views so changes redraw only small pieces
  • Profile release builds on a real device
  • Use LazyVStack / List for anything over ~50 items

Quick Summary

  • cheap bodies, stable identity
  • read only needed state
  • _printChanges + Instruments
