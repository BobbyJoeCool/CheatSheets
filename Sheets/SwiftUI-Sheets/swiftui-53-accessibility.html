Accessibility

accessibilityLabel · accessibilityHint · accessibilityAddTraits · accessibilityElement(children:) · VoiceOver · Accessibility Inspector

Accessible SwiftUI

Standard controls are accessible by default: VoiceOver reads labels and values, and Dynamic Type scales text. Your job is to fill gaps: labels for icon-only views, traits for custom controls, grouping of related elements, actions for gestures, and hiding decoration. Verify with VoiceOver and Xcode's Accessibility Inspector.

Notes

  • Label = what it is; value = its state; hint = what happens
  • .combine merges children into one element
  • @AccessibilityFocusState moves VoiceOver focus
  • Accessibility Inspector: Xcode › Open Developer Tool

Accessibility Modifiers

HStack {
    Image(systemName: "star.fill").foregroundStyle(.yellow)
    Text("4.8")
    Text("(2,104 reviews)").foregroundStyle(.secondary)
}
.accessibilityElement(children: .combine)        // one element
.accessibilityLabel("Rated 4.8 stars from 2,104 reviews")

Button(action: toggleFavorite) {
    Image(systemName: isFav ? "heart.fill" : "heart")
}
.accessibilityLabel("Favorite")
.accessibilityValue(isFav ? "On" : "Off")
.accessibilityHint("Saves this recipe")

Text("Ingredients").font(.title2)
    .accessibilityAddTraits(.isHeader)            // rotor heading

SwipeCard(item)
    .accessibilityAction(named: "Archive") { archive(item) }

Image("divider").accessibilityHidden(true)       // decorative

CustomSlider(value: $v)
    .accessibilityRepresentation { Slider(value: $v) }

Code Explained

children: .combine — group a row
label / value / hint — describe a control
.isHeader trait — headings for the rotor
accessibilityAction(named:) — gesture alternative
accessibilityRepresentation — act like a standard control

Minimum OS

  • Accessibility modifiers: iOS 14–15
  • accessibilityRepresentation, @AccessibilityFocusState: iOS 15

UIKit / React Equivalent

  • UIKit accessibilityLabel, accessibilityTraits, UIAccessibilityCustomAction
  • React Native accessibilityLabel, accessibilityRole, accessibilityActions

⚠ Common Mistakes

  • Labels that repeat the trait: "Favorite button" (VoiceOver already says "button")
  • Combining elements that contain separate buttons: they become unreachable
  • Custom controls built from shapes with no label or value

✓ Tips & Best Practices

  • Run the Accessibility Inspector's Audit on every screen
  • Use .accessibilitySortPriority to fix reading order
  • Write UI tests against accessibility labels; it doubles as a check

Quick Summary

  • label / value / hint / traits
  • combine, hide, add actions
  • test with VoiceOver + Inspector
