Alerts & Confirmations

.alert shows a short message with buttons; .confirmationDialog shows an action sheet of choices, usually to confirm something destructive. Both are driven by a Bool and can take presenting data so the buttons know which item they act on. Button roles (.destructive, .cancel) place and color buttons correctly.

Notes

  • A Cancel button is added automatically if you don't provide one
  • presenting: passes the item into the actions and message
  • Alerts can contain TextFields
  • LocalizedError makes error alerts easy

Alert & Dialog

@State private var toDelete: Note?
@State private var showConfirm = false
@State private var error: AppError?

List(notes) { note in
    Text(note.title)
        .swipeActions {
            Button("Delete", role: .destructive) {
                toDelete = note; showConfirm = true
            }
        }
}
.confirmationDialog("Delete note?", isPresented: $showConfirm,
                    titleVisibility: .visible, presenting: toDelete) { note in
    Button("Delete \"\(note.title)\"", role: .destructive) { delete(note) }
    Button("Cancel", role: .cancel) { }
}
.alert(isPresented: .constant(error != nil), error: error) { _ in
    Button("OK") { error = nil }
} message: { e in Text(e.recoverySuggestion ?? "") }

Code Explained

.confirmationDialog(presenting:) — item-aware choices
role: .destructive / .cancel — placement + color
titleVisibility: .visible — show the title
.alert(error:) — alert from a LocalizedError
message: — body text

Minimum OS

  • .alert / .confirmationDialog with actions: iOS 15
  • TextField inside alerts: iOS 16

UIKit / React Equivalent

  • UIKit UIAlertController (.alert / .actionSheet)
  • React Native Alert.alert(title, msg, buttons) / ActionSheetIOS

Which One

NeedUse
Inform / error.alert
Confirm destructive action.confirmationDialog
Choose among actions.confirmationDialog
Ask for a short value.alert + TextField

⚠ Common Mistakes

  • Putting long content in an alert: use a sheet
  • Reading a separately stored item in alert buttons: pass it with presenting:
  • Showing alerts for every validation error: inline messages are better

✓ Tips & Best Practices

  • Make your errors LocalizedError to use .alert(isPresented:error:)
  • Name the destructive button after the action: "Delete Note", not "OK"
  • On iPad, dialogs show as popovers from the source view

Quick Summary

  • .alert for messages
  • .confirmationDialog for choices
  • roles + presenting: data
