.task, onAppear & onChange

.task · .task(id:) · onAppear · onDisappear · onChange(of:) · automatic cancellation

View Lifecycle Hooks

.task starts async work when a view appears and cancels it automatically when the view disappears; .task(id:) also restarts when a value changes. onAppear and onDisappear run synchronous code, and onChange(of:) reacts when a value changes. These replace UIKit's viewDidLoad/viewWillAppear style hooks.

Notes

  • .task runs on the main actor by default (in a View)
  • onAppear can fire more than once (tabs, navigation)
  • onChange closure gets old and new values
  • Use initial: true to also run once at appearance
  • Swift set: 098 · async / await, 100 · Task Cancellation

.task, onAppear, onChange

struct ArticleView: View {
    let id: Article.ID
    @State private var article: Article?
    @State private var fontSize = 17.0

    var body: some View {
        ScrollView { if let article { ArticleBody(article) } }
            .task(id: id) {                         // restarts when id changes
                article = try? await api.article(id)
            }
            .onAppear { analytics.log("article_open") }
            .onDisappear { saveReadingPosition() }
            .onChange(of: fontSize) { old, new in
                prefs.save(fontSize: new)
            }
            .onChange(of: article?.isRead, initial: true) {
                updateBadge()
            }
    }
}

Code Explained

.task(id:) — async, cancels/restarts automatically
onAppear / onDisappear — sync hooks
onChange(of:) { old, new in } — react to changes
initial: true — run once at start too

Minimum OS

  • .task, .task(id:): iOS 15
  • Two-value onChange(of:) and initial:: iOS 17

UIKit / React Equivalent

  • UIKit viewDidLoad, viewWillAppear, viewDidDisappear, KVO
  • React Native useEffect(() => {…; return cleanup}, [id])

NeedUse

⚠ Common Mistakes

  • Starting Task { } in onAppear: no automatic cancellation
  • Expecting onAppear to run only once
  • Old one-argument onChange closures: deprecated in iOS 17

✓ Tips & Best Practices

  • Use .task(id:) + Task.sleep to debounce input
  • Keep loading logic in the model; .task { await model.load() }
  • Guard against reloading data you already have

Quick Summary

  • .task — async + auto-cancel
  • onAppear / onDisappear
  • onChange(of:) for reactions
