Building Forms

Form arranges controls into platform-standard settings layouts: grouped rows on iOS, aligned label columns on macOS. Split it into Sections with headers and footers. LabeledContent shows a label with a value or custom control. Disable the submit button until the input is valid.

Notes

  • Controls inside a Form adapt their style automatically
  • Section footers are good for help text and errors
  • .formStyle(.grouped) gives iOS-style grouping on macOS
  • Navigation links inside forms push detail pages

A Sign-Up Form

struct SignUpForm: View {
    @State private var name = ""
    @State private var email = ""
    @State private var plan = Plan.free
    @State private var agreed = false
    private var isValid: Bool {
        !name.isEmpty && email.contains("@") && agreed
    }

    var body: some View {
        Form {
            Section("Account") {
                TextField("Name", text: $name)
                TextField("Email", text: $email)
            }
            Section {
                Picker("Plan", selection: $plan) { /* options */ }
                LabeledContent("Price", value: plan.price,
                               format: .currency(code: "USD"))
            } footer: { Text("Cancel anytime.") }
            Toggle("I agree to the terms", isOn: $agreed)
            Button("Create Account", action: submit).disabled(!isValid)
        }
    }
}

Code Explained

Form — platform settings layout
Section("Title") — grouped rows with header
footer: — help text under a section
LabeledContent — label + value row
.disabled(!isValid) — gate submission

Minimum OS

  • Form, Section: iOS 13
  • LabeledContent, .formStyle: iOS 16

UIKit / React Equivalent

  • UIKit Static UITableView with grouped style and custom cells
  • React Native ScrollView of inputs; react-hook-form for validation

⚠ Common Mistakes

  • Validating only on submit: show problems as the user types
  • Putting long scrolling content in a Form: use List or ScrollView
  • Custom HStack rows that break macOS alignment: use LabeledContent

✓ Tips & Best Practices

  • Keep a computed isValid in the view or model
  • Use .alert to report server errors after submit
  • Use @FocusState to jump to the first invalid field

Quick Summary

  • Form + Section
