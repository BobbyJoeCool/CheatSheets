Hosting SwiftUI in UIKit

Existing UIKit apps adopt SwiftUI screen by screen. UIHostingController wraps a SwiftUI view as a view controller you can push, present or embed as a child. UIHostingConfiguration puts SwiftUI content inside table and collection view cells. Share state through @Observable models that both sides hold.

Notes

  • Push/present a hosting controller like any VC
  • Embedding as a child needs the standard containment calls
  • sizingOptions = .intrinsicContentSize lets Auto Layout size it
  • UIKit can call back into SwiftUI via closures passed into the view

UIHostingController & Cells

final class ProfileViewController: UIViewController {
    let model = ProfileModel()                         // @Observable

    func showEditor() {
        let editor = EditProfileView(profile: model) { [weak self] in
            self?.dismiss(animated: true)              // closure back to UIKit
        }
        present(UIHostingController(rootView: editor), animated: true)
    }

    override func viewDidLoad() {
        super.viewDidLoad()
        let host = UIHostingController(rootView: StatsCard(model: model))
        host.sizingOptions = .intrinsicContentSize
        addChild(host)
        view.addSubview(host.view)
        host.view.frame = view.bounds              // or Auto Layout
        host.view.autoresizingMask = [.flexibleWidth, .flexibleHeight]
        host.didMove(toParent: self)
    }
}

Code Explained

UIHostingController(rootView:) — SwiftUI as a VC
present / push — like any VC
addChild + didMove(toParent:) — embed
sizingOptions — Auto Layout friendly sizing
UIHostingConfiguration — SwiftUI cells

Minimum OS

  • UIHostingController: iOS 13
  • UIHostingConfiguration, sizingOptions: iOS 16

⚠ Common Mistakes

  • Forgetting addChild / didMove(toParent:): lifecycle and safe area bugs
  • Rebuilding the hosting controller to update data: update the model instead
  • Doubling navigation bars by wrapping hosted views in NavigationStack inside a UINavigationController

✓ Tips & Best Practices

  • Pass closures for actions UIKit should handle (dismiss, route)
  • Use @Observable models so both UIKit and SwiftUI see changes
  • Migrate leaf screens first, containers last

Quick Summary

  • UIHostingController wraps views
  • child containment for embedding
  • UIHostingConfiguration for cells
