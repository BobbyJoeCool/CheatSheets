Querying & Changing Data

@Query fetches models into a view and keeps the results live: inserts, edits and deletes show up automatically. Filter with a #Predicate, sort with key paths or SortDescriptors. To change data, use the modelContext from the environment: insert, delete, and edit properties directly; changes autosave.

Notes

  • Predicates are type-checked Swift closures turned into queries
  • Dynamic filters: build the Query in the view's init
  • Autosave happens periodically; call save() for certainty
  • Edit model properties with @Bindable
  • Swift set: 094 · Key Paths

@Query & modelContext

struct TripList: View {
    @Environment(\.modelContext) private var context
    @Query(sort: \Trip.start, order: .reverse) private var trips: [Trip]

    var body: some View {
        List {
            ForEach(trips) { TripRow(trip: $0) }
                .onDelete { for i in $0 { context.delete(trips[i]) } }
        }
        .toolbar {
            Button("Add", systemImage: "plus") {
                context.insert(Trip(name: "New Trip", start: .now))
            }
        }
    }
}

struct SearchResults: View {
    @Query private var trips: [Trip]
    init(text: String) {
        _trips = Query(filter: #Predicate<Trip> {
            text.isEmpty || $0.name.localizedStandardContains(text)
        }, sort: \.name)
    }
    var body: some View { List(trips) { Text($0.name) } }
}

context.insert / context.delete
#Predicate<Trip> { … } — typed filter
_trips = Query(…) — dynamic query in init
edits to model properties — saved automatically

Minimum OS

  • @Query, #Predicate, ModelContext: iOS 17
  • #Expression in queries: iOS 18

UIKit / React Equivalent

  • UIKit NSFetchedResultsController + NSManagedObjectContext
  • React Native WatermelonDB observe() queries / Realm live results

⚠ Common Mistakes

  • Unsupported functions in #Predicate: compile or runtime error; keep predicates simple
  • Fetching in body with context.fetch: use @Query
  • Deleting by offset from a filtered array that isn't the one shown

✓ Tips & Best Practices

  • Use FetchDescriptor with fetchLimit for background work
  • Use @ModelActor for heavy imports off the main actor
  • Debug with -com.apple.CoreData.SQLDebug 1 launch argument
