App Architecture

@Observable view models · MVVM · dependency injection · environment injection · feature modules

Structuring an App

A common SwiftUI architecture: views stay thin and declarative; @Observable models (view models or feature stores) hold state and logic; services (API clients, persistence) sit behind protocols and are injected, often through the environment. This keeps views previewable and models unit-testable without a UI.

Notes

  • One model per screen or feature, not per view
  • Services as protocols allow fakes in previews and tests
  • Inject dependencies at the top, not as singletons
  • Feature modules can be local Swift packages
  • Swift set: 069 · Protocols — Basics, 102 · Sendable & Strict Concurrency

Model + Injected Service

protocol RecipeService: Sendable {
    func recipes() async throws -> [Recipe]
}
struct LiveRecipeService: RecipeService { /* URLSession */ }
struct MockRecipeService: RecipeService {
    func recipes() async throws -> [Recipe] { Recipe.samples }
}

extension EnvironmentValues {
    @Entry var recipeService: any RecipeService = LiveRecipeService()
}

@MainActor @Observable final class RecipeListModel {
    private let service: any RecipeService
    var recipes: [Recipe] = []
    init(service: any RecipeService) { self.service = service }
    func load() async { recipes = (try? await service.recipes()) ?? [] }
}

struct RecipeListView: View {
    @Environment(\.recipeService) private var service
    @State private var model: RecipeListModel?
    var body: some View {
        List(model?.recipes ?? []) { Text($0.name) }
            .task {
                if model == nil { model = RecipeListModel(service: service) }
                await model?.load()
            }
    }
}

#Preview { RecipeListView().environment(\.recipeService, MockRecipeService()) }

Code Explained

service protocol — swap live/mock
@Entry — inject through the environment
@MainActor @Observable model — state + logic
model created from env in .task
preview injects a mock

Minimum OS

  • @Observable: iOS 17; @Entry: Xcode 16
  • Pattern works on iOS 16 with ObservableObject

UIKit / React Equivalent

  • UIKit MVVM / Coordinator with view models
  • React Native Hooks + context providers; Redux Toolkit slices

⚠ Common Mistakes

  • Networking code directly in views
  • Global singletons that previews and tests can't replace
  • A view model for every tiny view

✓ Tips & Best Practices

  • Pass dependencies into model inits so tests can construct them
  • Start with plain @State in views; add a model when logic grows
  • Keep models free of SwiftUI imports where possible

Quick Summary

  • thin views, @Observable models
  • services behind protocols
  • inject via environment / init
