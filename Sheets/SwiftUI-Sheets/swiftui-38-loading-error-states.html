Loading & Error States

Real screens are loading, loaded, empty or failed. Model this with an enum in a @MainActor model and switch over it in the view, so every state has a deliberate UI. ProgressView shows activity, ContentUnavailableView handles empty and error states, and .redacted(reason: .placeholder) shows a skeleton of the real layout.

Notes

  • One enum prevents impossible combinations (loading + error)
  • Keep previous data visible during refresh if possible
  • Treat CancellationError as not-an-error
  • Offer a retry action on failure
  • Swift set: 064 · Enums — Associated Values, 101 · Actors & @MainActor

State Enum Pattern

@MainActor @Observable final class FeedModel {
    enum Phase { case loading, loaded([Post]), empty, failed(Error) }
    var phase = Phase.loading
    func load() async {
        do {
            let posts = try await api.posts()
            phase = posts.isEmpty ? .empty : .loaded(posts)
        } catch is CancellationError {} catch { phase = .failed(error) }
    }
}

struct FeedView: View {
    @State private var model = FeedModel()
    var body: some View {
        Group {
            switch model.phase {
            case .loading:
                PostList(posts: Post.placeholders)
                    .redacted(reason: .placeholder)
            case .loaded(let posts): PostList(posts: posts)
            case .empty:
                ContentUnavailableView("No Posts", systemImage: "tray")
            case .failed:
                ContentUnavailableView {
                    Label("Couldn't Load", systemImage: "wifi.slash")
                } actions: {
                    Button("Retry") { Task { await model.load() } }
                }
            }
        }
        .task { await model.load() }
    }
}

Code Explained

enum Phase — every screen state
catch is CancellationError — ignore cancels
.redacted(reason: .placeholder) — skeleton
ContentUnavailableView actions — retry button
.task — load on appear

Minimum OS

  • ProgressView, .redacted: iOS 14
  • ContentUnavailableView: iOS 17

UIKit / React Equivalent

  • UIKit UIActivityIndicatorView + manual state view swapping
  • React Native isLoading / error state + ActivityIndicator, React Query

⚠ Common Mistakes

  • Separate isLoading, error and items properties that disagree
  • Showing an error alert when the user just navigated away (cancellation)
  • Spinner covering data the user was reading during refresh

✓ Tips & Best Practices

  • Make sample placeholders the same size as real rows
  • Use .refreshable for refresh; keep .loaded data during it
  • Unit-test the model's phase transitions

Quick Summary

  • enum for screen phases
  • redacted skeletons while loading
  • ContentUnavailableView for empty/failed
