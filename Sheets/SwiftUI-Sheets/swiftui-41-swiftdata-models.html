Defining SwiftData Models

SwiftData is Apple's persistence framework built for SwiftUI. Mark a class with the @Model macro and its stored properties become persisted columns; relationships to other models are tracked automatically. Attach a model container to the app or a view with .modelContainer(for:), and SwiftData creates the store and injects a context.

Notes

  • @Model classes are also Observable
  • Every @Model needs an initializer
  • @Attribute(.unique) enforces uniqueness (upsert on insert)
  • Use an in-memory container for previews and tests
  • Swift set: 096 · Macros

@Model & Container

import SwiftData

@Model final class Trip {
    @Attribute(.unique) var name: String
    var start: Date
    var notes = ""
    @Relationship(deleteRule: .cascade, inverse: \Stop.trip)
    var stops: [Stop] = []

    init(name: String, start: Date) { self.name = name; self.start = start }
}

@Model final class Stop {
    var place: String
    var trip: Trip?
    init(place: String) { self.place = place }
}

@main struct TravelApp: App {
    var body: some Scene {
        WindowGroup { TripList() }
            .modelContainer(for: Trip.self)       // Stop found via relation
    }
}

#Preview { TripList().modelContainer(for: Trip.self, inMemory: true) }

Attribute Options

OptionEffect
.uniqueOne row per value

.ephemeralNot persisted
@TransientSkip a property

Code Explained

@Model — persisted, observable class
@Attribute(.unique) — no duplicates
@Relationship(deleteRule: .cascade) — delete children too
.modelContainer(for:) — create store + context
inMemory: true — preview store

Minimum OS

  • SwiftData: iOS 17 / macOS 14
  • #Unique, #Index, history tracking: iOS 18

UIKit / React Equivalent

  • UIKit Core Data NSManagedObject + NSPersistentContainer
  • React Native WatermelonDB / Realm / SQLite models

⚠ Common Mistakes

  • Forgetting the init: @Model classes don't get a memberwise init
  • Using structs: @Model requires a class
  • Changing models without a migration plan once users have data

✓ Tips & Best Practices

  • Use VersionedSchema + SchemaMigrationPlan for later changes
  • Pass ModelConfiguration(cloudKitDatabase: .automatic) for iCloud sync
  • Keep a static var preview: ModelContainer with sample data
