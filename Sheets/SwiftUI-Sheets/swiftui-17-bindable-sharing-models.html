@Bindable & Sharing Models

@Bindable · $model.name · passing models · ownership · let vs @State

Bindings into Models

Controls need bindings, but a model passed as let can't produce them. Declare it @Bindable in the view that edits it, then use $model.property. Ownership stays clear: one view owns the model in @State, editing views mark it @Bindable, and read-only views take it as let.

Notes

  • @Bindable works on any @Observable reference
  • Create a local one in body: @Bindable var m = model
  • Environment models need @Bindable locally to bind
  • No copying: all views share one instance
  • Swift set: 094 · Key Paths

@Bindable

@Observable final class Profile {
    var name = ""
    var bio = ""
    var notifications = true
}

struct EditProfileView: View {
    @Bindable var profile: Profile                 // can make bindings
    var body: some View {
        Form {
            TextField("Name", text: $profile.name)
            TextField("Bio", text: $profile.bio, axis: .vertical)
            Toggle("Notifications", isOn: $profile.notifications)
        }
    }
}

struct SettingsScreen: View {
    @Environment(Profile.self) private var profile
    var body: some View {
        @Bindable var profile = profile            // local bindable
        Toggle("Alerts", isOn: $profile.notifications)
    }
}

#Preview { EditProfileView(profile: Profile()) }

Code Explained

@Bindable var profile — enables $profile.x
$profile.name — binding to a property
@Environment(Profile.self) — injected model
local @Bindable var — bind to an environment model

Minimum OS

  • @Bindable: iOS 17 / macOS 14
  • TextField(axis: .vertical): iOS 16

UIKit / React Equivalent

  • UIKit Target-action / delegates writing back to the model
  • React Native Store actions like setName(text) from inputs

⚠ Common Mistakes

  • Using @State in the editing view: it becomes a second owner
  • Copying model fields into local @State and syncing them by hand
  • Expecting $model.x to compile on a plain let

✓ Tips & Best Practices

  • For cancellable edits, edit a copy (struct draft) and save on Done
  • Pass the narrowest thing: a binding for one field, the model for many
  • Keep validation in the model so every view gets it

Quick Summary

  • @Bindable → $model.prop
  • owner @State, editors @Bindable
  • local @Bindable for env models
