Environment

@Environment · .environment() · @Entry · dismiss · openURL · colorScheme

The Environment

The environment passes values down the whole view tree without threading them through every initializer. SwiftUI provides many built-in values (color scheme, locale, dismiss, openURL), and you can inject your own @Observable models with .environment(model) or define new keys with the @Entry macro.

Notes

  • Read with @Environment(\.key) or @Environment(Type.self)
  • Values set on a view apply to all its descendants
  • Missing environment model = runtime crash; inject it at the root
  • Some values are actions: dismiss(), openURL(url)
  • Swift set: 094 · Key Paths

Reading & Injecting

extension EnvironmentValues {
    @Entry var accentTheme: Theme = .ocean           // custom key
}

struct DetailView: View {
    @Environment(\.dismiss) private var dismiss
    @Environment(\.colorScheme) private var scheme
    @Environment(\.openURL) private var openURL
    @Environment(CartModel.self) private var cart   // injected model
    @Environment(\.accentTheme) private var theme

    var body: some View {
        VStack {
            Text(scheme == .dark ? "Dark" : "Light")
            Text("\(cart.items.count) in cart")
            Button("Help") { openURL(URL(string: "https://ex.com")!) }
            Button("Close") { dismiss() }
        }
        .tint(theme.color)
    }
}

// Injection somewhere above:
RootView().environment(cart).environment(\.accentTheme, .forest)

Built-in Values

Code Explained

@Entry — declare a custom environment value
\.dismiss — close the current presentation
@Environment(CartModel.self) — injected model
.environment(cart) — inject an Observable
.environment(\.key, value) — set a value

Minimum OS

  • @Environment(Type.self) for Observables: iOS 17
  • @Entry macro: Xcode 16

UIKit / React Equivalent

  • UIKit Trait collections, singletons, or passing dependencies by hand
  • React Native React.createContext + useContext

⚠ Common Mistakes

  • Forgetting to inject an environment model: crash with "No Observable object of type…"
  • Using the environment for data only one child needs: pass a property
  • Calling dismiss from the wrong view (it closes that view's presentation)

✓ Tips & Best Practices

  • Inject app-wide models once in the App scene
  • Previews need the same .environment(...) calls
  • Use @Entry instead of writing EnvironmentKey boilerplate

Quick Summary

  • @Environment reads down the tree
  • .environment(model) injects
  • @Entry for custom keys
