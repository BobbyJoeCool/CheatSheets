Generation Data Groups (GDGs)

DEFINE GDG · LIMIT / SCRATCH / NOEMPTY · relative generations (+1) / (0) / (-1) · G0001V00 names · daily-file pattern

Versioned Datasets

A GDG is a group of datasets with one base name, each run adding a new generation. Programs refer to generations by relative number: (0) is the newest, (-1) the one before, (+1) a new one created in this job. The base keeps only the last LIMIT generations, rolling older ones off automatically.

Key Points

  • Real names end in .GnnnnV00 (e.g. .G0042V00)
  • Relative numbers are fixed for the whole job
  • The base is defined once with IDCAMS
  • Giving the base name alone reads all generations, newest first

Define and Use a GDG

//* One-time setup: keep the last 7 generations
//DEFGDG   EXEC PGM=IDCAMS
//SYSPRINT DD SYSOUT=*
//SYSIN    DD *
  DEFINE GDG (NAME(PROD.SALES.DAILY) -
         LIMIT(7) NOEMPTY SCRATCH)
/*
//*
//* Daily job: read yesterday, write today
//DAILY    EXEC PGM=SALESUPD
//PREVDAY  DD DSN=PROD.SALES.DAILY(0),DISP=SHR
//NEWDAY   DD DSN=PROD.SALES.DAILY(+1),
//            DISP=(NEW,CATLG,DELETE),
//            SPACE=(CYL,(5,5),RLSE),RECFM=FB,LRECL=100
//*
//* Later step in the SAME job sees the new one as (+1)
//REPORT   EXEC PGM=SALESRPT
//SALESIN  DD DSN=PROD.SALES.DAILY(+1),DISP=SHR
//*
//* Read every generation at once
//ALLDAYS  DD DSN=PROD.SALES.DAILY,DISP=SHR

Code Explained

LIMIT(7): the eighth generation pushes the oldest out
SCRATCH deletes rolled-off generations; NOEMPTY rolls off one at a time
(0) at job start is yesterday's file; (+1) is today's
Inside the same job the new generation stays (+1)

Modern Equivalent

  • Python Date-stamped files sales_2026-11-12.csv plus a cleanup that keeps 7
  • Java Rolling files (Logback maxHistory=7)
  • JavaScript Rotating logs (rotating-file-stream with maxFiles: 7)

Abend Check

  • Allocation fails on (+1): the GDG base was never defined; run the IDCAMS DEFINE GDG first
  • Rerun creates another (+1) and shifts (0): restart carefully or use absolute names

Relative References

ReferenceMeans
(+1)New generation (this job)
(0)Newest existing
(-1)One before newest
(-n)n before newest
base name onlyAll generations

DEFINE GDG Options

OptionEffect
LIMIT(n)Generations kept (max 255; 999 extended)
SCRATCH / NOSCRATCHDelete / keep rolled-off
EMPTY / NOEMPTYRoll all / one at limit
PURGEAllow delete before expiry

⚠ Common Mistakes

  • Expecting (0) to mean the generation created earlier in the same job (it is still +1)
  • Rerunning a failed job and creating an extra generation
  • Using EMPTY, which uncatalogs all generations when the limit is hit

✓ Tips & Best Practices

  • Use NOEMPTY SCRATCH unless you have a reason not to
  • Note in run books how to rerun safely (delete the bad +1 first)
  • Use GDGs for daily, weekly and monthly files instead of date-named datasets

Quick Summary

  • GDG — versioned dataset
  • (+1) new · (0) newest · (-1) previous
  • LIMIT — generations kept
  • relative numbers — fixed per job
