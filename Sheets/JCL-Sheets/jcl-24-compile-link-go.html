Compile, Link & Go

IGYWCL / IGYWCLG procs · SYSLIB copybooks · SYSLMOD load library · binder (link-edit) · compile listing in SYSPRINT · DB2 precompile & BIND note

Building a COBOL Program

A COBOL build has two steps: the compiler (IGYCRCTL) turns source into an object deck, and the binder (IEWL/IEWBLINK) links it into a load module stored in a load library. IBM procs combine them: IGYWC compiles, IGYWCL compiles and links, IGYWCLG also runs the program.

Key Points

  • Proc step names: COBOL (compile), LKED (link), GO (run)
  • Compile listing and messages go to COBOL.SYSPRINT
  • The load module name is the member name in SYSLMOD
  • Compile RC 4 = warnings; 8+ = errors, so the link is skipped

In COBOL

  • COPY member statements are resolved from COBOL.SYSLIB
  • Static CALLs are resolved by the binder from LKED.SYSLIB
  • DB2 programs also need the SQL coprocessor option and a BIND

Compile and Link with IGYWCL

//USER01C  JOB (ACCT),'COMPILE',CLASS=A,MSGCLASS=X,
//         NOTIFY=&SYSUID
//         JCLLIB ORDER=(IGY.SIGYPROC)
//CL       EXEC IGYWCL,
//         PARM.COBOL='LIST,MAP,XREF,SSRANGE'
//COBOL.SYSIN   DD DSN=USER.COBOL.SRC(PAYCALC),DISP=SHR
//COBOL.SYSLIB  DD DSN=USER.COPYLIB,DISP=SHR
//              DD DSN=PROD.COPYLIB,DISP=SHR
//LKED.SYSLMOD  DD DSN=USER.LOADLIB(PAYCALC),DISP=SHR
//LKED.SYSLIB   DD DSN=CEE.SCEELKED,DISP=SHR
//              DD DSN=USER.LOADLIB,DISP=SHR

Code Explained

JCLLIB points to the library holding the IGY procs (name varies by site)
PARM.COBOL sets compiler options for this compile
Copybooks are searched in USER.COPYLIB, then PROD.COPYLIB
The load module PAYCALC is written to USER.LOADLIB

Modern Equivalent

  • Python No build: python paycalc.py; packaging with pip wheel
  • Java javac compiles, jar packages (Maven/Gradle run both)
  • JavaScript tsc compiles, a bundler (Vite/esbuild) links

Abend Check

  • Compile RC 8/12: read the IGYxxxxx-E/S messages in COBOL.SYSPRINT
  • IEW2456E SYMBOL … UNRESOLVED: a statically called program is not in LKED.SYSLIB

⚠ Common Mistakes

  • No SYSLIB, so every COPY fails with severe errors
  • Writing the load module to production by mistake
  • Ignoring RC 4 warnings that point at real truncation bugs

✓ Tips & Best Practices

  • Keep one compile JCL member per program, or one proc with the name as a symbol
  • Save listings with LIST/OFFSET for abend analysis
  • Use IGYWCLG while learning so compile and run happen in one job

Quick Summary

  • IGYCRCTL — compiler
  • binder — makes load module
  • IGYWCL / IGYWCLG — IBM procs
  • SYSLIB / SYSLMOD — in / out
