Sheet 29

Common Abends

S0C7 · S0C4 · S013 · S806 · S222 / S322 · SB37 / SD37 / SE37 · U-codes (user abends) · CEE messages

Abend Codes You Will See

An abend ends a step abnormally. System abends (Sxxx) come from z/OS or the hardware; user abends (Unnnn) are raised by programs or Language Environment. The code plus the reason code and the CEEDUMP usually point straight at the cause.

Key Points

  • Abended steps have no RC; later steps are bypassed unless COND=EVEN/ONLY or IF ABEND
  • Reason codes add detail: S013-18, S806-04
  • S0Cx abends are program checks (bad data or address)
  • LE turns many program checks into U4038 plus CEE messages

Abend in the Job Log

IEA995I SYMPTOM DUMP OUTPUT
  SYSTEM COMPLETION CODE=0C7  REASON CODE=00000007
   TIME=02.14.31  SEQ=00412  CPU=0000  ASID=0031
   PSW AT TIME OF ERROR  078D1000 8001A6E2
     ACTIVE LOAD MODULE           ADDRESS=0001A000
     NAME=PAYCALC
     OFFSET=000006E2
IEF450I USER01R PAYRUN - ABEND=S0C7 U0000 REASON=00000007

CEE3207S The system detected a data exception (System
         Completion Code=0C7).
         From compile unit PAYCALC at entry point PAYCALC at
         statement 214 at compile unit offset +000006E2

Code Explained

S0C7: a packed/zoned decimal instruction hit invalid data
The OFFSET maps to a statement in the LIST/OFFSET compile listing
The CEE message gives the statement number directly (with TEST/listing info)
Look at the input record being processed at the time

Modern Equivalent

  • Python decimal.InvalidOperation or ValueError with a traceback line number
  • Java NumberFormatException / ArithmeticException with a stack trace
  • JavaScript NaN results or a RangeError / TypeError with a stack trace

Abend Check

  • S0C7 at 2 a.m.: find the bad record (key in SYSOUT), fix or skip it, rerun from the step
  • S806 after a deploy: the new load module was not copied to the library in STEPLIB

⚠ Common Mistakes

  • Rerunning an S0C7 job without fixing the data
  • Raising REGION for an S0C4 (it is a bad address, not memory size)
  • Raising TIME for an S322 caused by an infinite loop

✓ Tips & Best Practices

  • Always keep CEEDUMP and SYSUDUMP DDs in COBOL steps
  • Log record counts and keys so the bad record is easy to find
  • Map offsets with the LIST/OFFSET listing of the exact module version

Quick Summary

  • S0C7 — bad numeric data
  • S0C4 — bad address
  • S806 — module not found
  • S322 / SB37 — time / space
