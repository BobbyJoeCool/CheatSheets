Special DD Names

JOBLIB / STEPLIB · SYSIN · SYSOUT / SYSPRINT · SYSUDUMP / SYSABEND / CEEDUMP · SYSTSIN / SYSTSPRT · SYSLIB

DD Names with Built-in Meanings

Some DD names are reserved or used by convention. STEPLIB and JOBLIB tell z/OS where to find programs. SYSIN carries control statements, SYSPRINT and SYSOUT collect messages, and the dump DDs capture diagnostics when a step abends.

Key Points

  • JOBLIB goes right after the JOB statement; STEPLIB after an EXEC
  • STEPLIB overrides JOBLIB for its step
  • Utilities read SYSIN and write SYSPRINT
  • Most COBOL DISPLAY output lands in SYSOUT

In COBOL

  • COBOL DISPLAY → SYSOUT; ACCEPT → SYSIN
  • Language Environment writes CEEDUMP when a COBOL step abends
  • The compile step reads copybooks from SYSLIB

Special DDs in One Job

//USER01R  JOB (ACCT),'SPECIAL DDS',CLASS=A,MSGCLASS=X
//JOBLIB   DD DSN=USER.LOADLIB,DISP=SHR
//         DD DSN=PROD.LOADLIB,DISP=SHR
//*
//STEP1    EXEC PGM=PAYCALC
//STEPLIB  DD DSN=USER.TEST.LOADLIB,DISP=SHR
//SYSIN    DD *
RUNDATE=20261112
/*
//SYSOUT   DD SYSOUT=*
//CEEDUMP  DD SYSOUT=*
//SYSUDUMP DD SYSOUT=*
//*
//STEP2    EXEC PGM=IKJEFT01
//SYSTSPRT DD SYSOUT=*
//SYSTSIN  DD *
LISTCAT LEVEL(USER)
/*

Code Explained

JOBLIB is searched for every step (two libraries concatenated)
STEP1 looks in USER.TEST.LOADLIB first because of STEPLIB
CEEDUMP and SYSUDUMP catch diagnostics if PAYCALC abends
IKJEFT01 runs TSO commands from SYSTSIN

Modern Equivalent

  • Python PYTHONPATH (≈ STEPLIB), stdin (≈ SYSIN), stdout/stderr (≈ SYSOUT)
  • Java -classpath (≈ STEPLIB), System.in, System.out
  • JavaScript NODE_PATH / node_modules (≈ STEPLIB), process.stdin, process.stdout

Abend Check

  • S806 with STEPLIB coded: the library is fine but the member is in a different one
  • No dump after an abend: add CEEDUMP DD SYSOUT=* (or SYSUDUMP)

⚠ Common Mistakes

  • JOBLIB placed after the first EXEC (it must come first)
  • Missing SYSOUT DD, so DISPLAY output ends up somewhere unexpected
  • Production STEPLIB left in a test job

✓ Tips & Best Practices

  • Concatenate test before production libraries in STEPLIB while testing
  • Always include CEEDUMP for COBOL steps
  • Code SYSPRINT for every utility step: that is where its errors go

Quick Summary

  • STEPLIB / JOBLIB — find programs
  • SYSIN — control input
  • SYSOUT / SYSPRINT — messages
  • CEEDUMP — COBOL abend dump
