Concatenation, Temp Datasets & Backward References

concatenated DDs · &&TEMP datasets · DISP=(NEW,PASS) · DSN=*.STEP1.DDNAME referbacks · VOL=REF · DCB=*.

Chaining Data Through a Job

Several datasets under one DD name are concatenated and read as one file. Temporary datasets (&&name) exist only for the life of the job and pass data between steps. Backward references (*.step.ddname) reuse a dataset or attributes defined earlier, so names are typed once.

Key Points

  • Concatenation: following DDs have no name
  • Temp datasets are deleted when the job ends
  • PASS keeps a dataset available to later steps
  • Referbacks name the step (and proc step) plus DD

In COBOL

  • A COBOL program reading a concatenated DD sees one long file and one end-of-file
  • Pass data from a sort step to a COBOL step through &&SORTED with no cleanup
  • Concatenated datasets should share RECFM and LRECL

Temp Data Between Steps

//STEP1    EXEC PGM=SORT
//SYSOUT   DD SYSOUT=*
//* Three months read as one input
//SORTIN   DD DSN=PROD.SALES.SEP,DISP=SHR
//         DD DSN=PROD.SALES.OCT,DISP=SHR
//         DD DSN=PROD.SALES.NOV,DISP=SHR
//SORTOUT  DD DSN=&&SORTED,DISP=(NEW,PASS),
//            SPACE=(CYL,(10,5)),RECFM=FB,LRECL=100
//SYSIN    DD *
  SORT FIELDS=(1,10,CH,A)
/*
//STEP2    EXEC PGM=SALESRPT
//SALESIN  DD DSN=&&SORTED,DISP=(OLD,DELETE)
//* Same data via a referback
//SALESIN2 DD DSN=*.STEP1.SORTOUT,DISP=(OLD,DELETE)
//RPTOUT   DD SYSOUT=*

Code Explained

SORTIN reads September, October and November as one file
&&SORTED is created in STEP1 and passed
STEP2 reads it and deletes it when done
*.STEP1.SORTOUT refers back to the same dataset

Modern Equivalent

  • Python itertools.chain(open(a), open(b)); tempfile.NamedTemporaryFile
  • Java SequenceInputStream; Files.createTempFile
  • JavaScript Stream piping (stream.pipeline); fs.mkdtemp + cleanup

Abend Check

  • IEF212I … DATA SET NOT FOUND on a referback: misspelled step or DD name
  • Concatenation with different LRECLs: IEC141I 013-xx or truncated records

Temp & Referbacks

FormMeaning
DSN=&&NAMETemp dataset
DISP=(NEW,PASS)Create, pass on
DISP=(OLD,DELETE)Use, then delete
DSN=*.STEP.DDSame dataset as earlier DD
DSN=*.STEP.PSTEP.DDThrough a proc step
DCB=*.STEP.DDCopy DCB attributes
VOL=REF=*.STEP.DDSame volume

⚠ Common Mistakes

  • Naming the concatenated DDs (only the first has a name)
  • Forgetting PASS, so the temp dataset is deleted before the next step
  • Single & instead of && (that is a symbolic parameter)

✓ Tips & Best Practices

  • Use temp datasets for all intermediate files: no cleanup jobs needed
  • Put the largest block size dataset first in a concatenation (older rules)
  • Prefer referbacks over retyping long names

Quick Summary

  • unnamed DDs — concatenation
  • &&TEMP — job-life dataset
  • PASS — keep for later steps
  • *.STEP.DD — referback
