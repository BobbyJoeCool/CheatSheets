Sheet 06

The JOB Statement

job name · accounting & programmer name · CLASS · MSGCLASS · MSGLEVEL=(1,1) · NOTIFY=&SYSUID · REGION / TIME · TYPRUN=SCAN / HOLD

Starting Every Job

The JOB statement is the first line of every job. It gives the job a name, accounting information and a programmer name, then tells JES2 how to run it: which class (queue) to use, where to send messages (MSGCLASS), how much detail to list and who to notify when it ends.

Key Points

  • Positional first: accounting, then programmer name
  • Keyword parameters follow in any order
  • Job names are often your user ID plus a letter
  • Shops publish which CLASS and MSGCLASS values to use

JOB Statement Variations

//USER01A  JOB (D1234),'PAYROLL TEST',
//         CLASS=A,
//         MSGCLASS=X,
//         MSGLEVEL=(1,1),
//         NOTIFY=&SYSUID,
//         REGION=0M,
//         TIME=(5,0)
//*
//* Check syntax only: nothing runs
//USER01S  JOB (D1234),'SCAN',CLASS=A,MSGCLASS=X,
//         TYPRUN=SCAN
//*
//* Hold in the queue until released in SDSF (A)
//USER01H  JOB (D1234),'HELD',CLASS=A,MSGCLASS=X,
//         TYPRUN=HOLD

Code Explained

MSGLEVEL=(1,1): list all JCL, procs and allocation messages
NOTIFY=&SYSUID sends a TSO message to whoever submitted it
REGION=0M asks for the maximum memory the site allows
TIME=(5,0) limits the whole job to 5 CPU minutes

Modern Equivalent

  • Python A job definition: name, queue and timeout, like a CI job or Celery task options
  • Java Job config for a scheduler (Spring Batch job parameters, Quartz)
  • JavaScript A GitHub Actions job: with runs-on and timeout-minutes

Abend Check

  • S322 abend: the TIME limit was exceeded; raise TIME or fix a loop
  • IEFC452I JOB NOT RUN - JCL ERROR with a bad CLASS: use a class your site defines

JOB Parameters

ParameterMeaning
(acct)Accounting info (site format)
'name'Programmer name, max 20
CLASS=Input queue / job class
MSGCLASS=Output class for the job log
MSGLEVEL=(s,m)JCL / message detail
NOTIFY=User to notify
REGION=Memory per step
TIME=CPU time limit
TYPRUN=SCAN, HOLD, COPY
RESTART=Rerun from a step

MSGLEVEL

ValueLists
(0,0)JOB statement only
(1,1)All JCL + all messages
(2,0)Your JCL only
(1,0)All JCL, messages on failure

⚠ Common Mistakes

  • A job name already in use by another running job (it waits)
  • Missing NOTIFY, so you poll SDSF waiting for results
  • Copying a production JOB card with production accounting into test

✓ Tips & Best Practices

  • Keep a personal JOB card member and COPY it into new JCL
  • Use TYPRUN=SCAN before running new or edited jobs
  • Ask which MSGCLASS keeps output held so you can read it

Quick Summary

  • JOB — first statement
  • CLASS — queue
  • MSGCLASS / MSGLEVEL — log
  • TYPRUN=SCAN — syntax check
