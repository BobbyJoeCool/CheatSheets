Reading Job Logs & JCL Errors

JCL ERROR · IEFC / IEF messages · IEF212I dataset not found · IEF453I job failed · IEC open errors · dataset in use (enqueue)

Finding What Went Wrong

A JCL error means z/OS rejected the job before any step ran: a syntax problem, a missing dataset or a bad parameter. The message ID tells you where to look: IEFC messages are syntax errors, IEF messages are allocation and step messages, and IEC messages are open/close errors from the access methods.

Key Points

  • Message IDs end in a severity: I info, W warning, E/A error/action
  • JESJCL shows the line number the message refers to
  • Datasets in use: the job waits with an enqueue message
  • TYPRUN=SCAN catches syntax errors before running

Code Explained

Statement 5 has a misspelled operation (e.g. EXCE for EXEC)
IEF212I: the TRANIN dataset name is wrong or not cataloged
013-18: member PAYCLAC not found (typo for PAYCALC)
IEF861I/IEF099I: another job holds PROD.ACCT.MASTER with DISP=OLD

Modern Equivalent

  • Python A Python traceback: the last line names the error, the file and line
  • Java A Java stack trace: exception type, message, then the call chain
  • JavaScript A Node error: ENOENT: no such file or directory, open '…'

Abend Check

  • Reading only the last message: the first error usually caused the rest
  • Job waits forever on IEF099I: find the job holding the dataset (SDSF ENQ) or use DISP=SHR

⚠ Common Mistakes

  • Fixing a later error message when the first one caused it
  • Ignoring warnings like NOT CATLGD that cause next-day failures
  • Resubmitting unchanged JCL hoping it works this time

✓ Tips & Best Practices

  • Search the IBM docs for the full message ID
  • Use TYPRUN=SCAN after every JCL edit
  • Keep a personal list of the messages you meet most often
