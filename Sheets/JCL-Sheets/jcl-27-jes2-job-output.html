JES2 & Job Output

job lifecycle · job & output classes · SDSF / Zowe job views · JESMSGLG / JESJCL / JESYSMSG · held output · purging jobs

Where Jobs and Output Go

JES2 reads submitted jobs, queues them by class, starts them on an initiator and stores their output on the spool. Each job has three system files: JESMSGLG (job log and step summary), JESJCL (the expanded JCL) and JESYSMSG (allocation messages and condition codes), followed by your SYSOUT DDs.

Key Points

  • Job IDs look like JOB04711
  • Phases: input → conversion → execution → output → purge
  • MSGCLASS decides whether output is held or printed
  • Held output stays until you purge it or it ages off

Reading Output with Zowe and SDSF

# List my jobs
zowe jobs list jobs --owner USER01
# JOB04711  PAYROLL  OUTPUT  CC 0008

# List the job's spool files
zowe jobs list sfbi JOB04711
# 1 JESMSGLG  2 JESJCL  3 JESYSMSG  101 SYSOUT  102 RPTOUT

zowe jobs view sfbi JOB04711 3     # condition codes per step
zowe jobs view sfbi JOB04711 101   # program DISPLAY output

# SDSF equivalents (ISPF)
#   =SD ; ST         status panel
#   ?  next to job   list spool files
#   S  next to file  view it
#   P  next to job   purge

Code Explained

CC 0008 is the highest step return code in the job
JESYSMSG lists each step with its condition code
Your program's DISPLAY output is in its SYSOUT DD file
Purge output you no longer need to free spool space

Modern Equivalent

  • Python CI job logs per step (GitHub Actions run page)
  • Java Spring Batch job repository and logs

Abend Check

  • No output at all: MSGCLASS sends it to a printer or discards it; use a held class
  • $HASP… messages in JESMSGLG: JES2 problems such as spool full or job held

⚠ Common Mistakes

  • Purging output before reading why the job failed
  • Looking only at the last file instead of JESYSMSG's step codes
  • Submitting to a class that is not started, so the job waits forever

✓ Tips & Best Practices

  • Check JESYSMSG first: it shows every step's RC or abend
  • Download output with Zowe to attach it to tickets
  • Ask which classes your site uses for test jobs and held output

Quick Summary
