Scheduling & Modern Workflow

batch windows · schedulers (IBM Workload Scheduler, Control-M) · job dependencies · JCL in Git · zowe zos-jobs submit … --wait-for-output in CI · z/OSMF REST jobs API

From Submitting by Hand to Pipelines

Production jobs are run by a scheduler such as IBM Workload Scheduler or Control-M, which starts jobs at set times or when other jobs finish, and alerts on failures. Development teams now keep JCL in Git and use Zowe CLI or the z/OSMF REST API to submit jobs and check return codes from CI pipelines.

Key Points

  • Schedulers track dependencies: job B runs after job A ends RC ≤ 4
  • The batch window is the overnight period jobs must finish in
  • Restarts are run from the scheduler, usually with RESTART=step
  • CI should fail the build when a job's RC is above 4 or it abends

Submitting from GitHub Actions

# .github/workflows/zos.yml (run step)
npm install -g @zowe/cli
zowe config set profiles.zosmf.properties.host "$ZOS_HOST"

# Upload JCL and source from the repo
zowe files upload dir-to-pds jcl/ "USER.CI.JCL"
zowe files upload dir-to-pds cobol/ "USER.CI.COBOL"

# Compile, then run tests; fail on RC > 4 or abend
for job in COMPILE TESTRUN; do
  out=$(zowe jobs submit ds "USER.CI.JCL($job)" \
        --wait-for-output --rfj)
  rc=$(echo "$out" | jq -r '.data.retcode')
  echo "$job: $rc"
  case "$rc" in "CC 0000"|"CC 0004") ;; *) exit 1 ;; esac
done

# z/OSMF REST: PUT /zosmf/restjobs/jobs  (submit)
#              GET /zosmf/restjobs/jobs/{name}/{id}  (status)

Code Explained

--rfj returns JSON so the script can read the retcode
RC 0 and 4 pass; 8, abends and JCL errors fail the pipeline
Uploading from Git makes the repo the source of truth
The same API calls work from Jenkins or GitLab CI

Modern Equivalent

  • Python Airflow DAGs or cron + a Python driver that checks exit codes
  • Java Spring Batch or Quartz jobs with dependency flows
  • JavaScript GitHub Actions / node-cron with needs: dependencies

Abend Check

  • CI passes but the job abended: you checked "submitted" instead of the final retcode
  • Scheduler shows the job late: an upstream job failed and dependents are waiting

⚠ Common Mistakes

  • Pipelines that do not wait for job completion
  • Hard-coded passwords in workflow files (use repository secrets)
  • Editing production JCL directly instead of through Git and the scheduler

✓ Tips & Best Practices

  • Store host and credentials as CI secrets
  • Name CI datasets per branch or build to avoid collisions
  • Download job output as build artifacts for every run

Quick Summary

  • scheduler — times + dependencies
  • batch window — overnight limit
  • Zowe --wait-for-output — CI submit
