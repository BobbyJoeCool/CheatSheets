Permission Rules

Permission rules say which specific tool calls are allowed, asked about, or denied, regardless of mode. They live in the permissions block of any settings file. Rules are checked in a fixed order: deny first, then ask, then allow; the first match wins. Use deny rules to keep secrets unreadable and destructive commands blocked even in permissive modes.

Rule Format

  • Tool or Tool(specifier)
  • * wildcard in Bash patterns
  • Path rules use gitignore-style globs
  • mcp__server__tool for MCP tools
  • Manage interactively with /permissions

A Practical permissions Block

{
  "permissions": {
    "allow": [
      "Bash(npm run *)",
      "Bash(git status)", "Bash(git diff *)", "Bash(git log *)",
      "WebFetch(domain:docs.python.org)",
      "mcp__github__get_issue"
    ],
    "ask":  ["Bash(git push *)", "Bash(npm publish *)"],
    "deny": [
      "Read(./.env)", "Read(./.env.*)", "Read(./secrets/**)",
      "Read(~/.aws/**)", "Bash(rm -rf *)", "Bash(curl *)"
    ],
    "additionalDirectories": ["../shared-lib"]
  }
}

Code Explained

Bash(npm run *) — any npm script; not npm install
Bash(git diff *) — read-only git without prompts
ask — always confirm pushes and publishes
Read(./.env) — blocks file tools and cat, head, etc.
Bash(curl *) — force web access through WebFetch rules
additionalDirectories — extra folders Claude may access

⚠ Common Mistakes

  • Thinking a specific allow overrides a broad deny; deny is always checked first
  • Relying on Bash(rm *) alone; /bin/rm or sh -c 'rm …' won't match, so combine with sandboxing
  • Writing Read(.env) and expecting it to cover .env files in parent directories
  • Allowing Bash(*) to stop prompts; that allows everything

✓ Tips & Best Practices

  • Commit secret-blocking deny rules in .claude/settings.json for the whole team
  • Use ask for anything irreversible: push, publish, deploy, drop
  • Pair Bash deny rules with the sandbox for real enforcement
  • Review rules with /permissions; it shows which scope each came from

Quick Summary

  • allow · ask · deny — three rule lists in settings
  • deny → ask → allow — evaluation order; first match wins
  • Bash(cmd *) — wildcard command patterns
  • Read(./.env) — keep secrets out of reach
