The Tool Landscape

Agentic coding tools come in three shapes. Terminal agents run in your shell and work on local files. IDE agents live inside the editor and show diffs inline. Cloud agents run in a remote sandbox, often started from an issue or chat, and return a pull request. Most vendors now ship all three surfaces on top of the same agent.

Choosing

  • Terminal agents are the most scriptable (headless mode, CI, hooks)
  • IDE agents are the easiest to review as you go
  • Cloud agents suit well-scoped tasks you hand off and check later
  • Most tools speak MCP and read an instructions file

⚠ Common Mistakes

  • Picking a tool by hype instead of where you already work (terminal vs editor vs GitHub)
  • Assuming every tool reads the same config file; each has its own name and location
  • Running two agents on the same working tree at once; use separate worktrees
  • Comparing tools on one prompt; behavior varies a lot by task type

✓ Tips & Best Practices

  • Learn one agent deeply before adding others
  • Keep shared rules in AGENTS.md and import or symlink it for other tools
  • Use cloud agents for chores (deps, small bugs) and local agents for design work
  • Check each vendor's docs monthly; features and names change fast

Quick Summary

  • terminal — Claude Code, Codex CLI, Gemini CLI, Aider
  • IDE — Copilot agent mode, Cursor, Windsurf, Cline
  • cloud — Claude Code on the web, Codex cloud, Copilot coding agent
  • common ground — MCP + an instructions file
