Codex Config, Approvals & Sandbox

Codex separates what commands can touch (the sandbox_mode) from when it asks you (the approval_policy). Both live in ~/.codex/config.toml alongside the model, reasoning effort, MCP servers, and named profiles. The OS sandbox (Seatbelt on macOS, Landlock/seccomp on Linux, a Windows sandbox) enforces the boundary for every command.

Defaults

  • Trusted repo: workspace-write + on-request
  • Network off in workspace-write unless enabled
  • untrusted approval policy is deprecated
  • Project .codex/config.toml can't set auth/provider

~/.codex/config.toml

model = "<your-default-model>"
model_reasoning_effort = "medium"      # low | medium | high
approval_policy = "on-request"         # on-request | never
sandbox_mode = "workspace-write"       # read-only | workspace-write | danger-full-access

[sandbox_workspace_write]
network_access = false                 # allow outbound network from commands?
writable_roots = ["/tmp/build"]

[profiles.review]                      # codex --profile review
sandbox_mode = "read-only"
model_reasoning_effort = "high"

[mcp_servers.github]
url = "https://api.githubcopilot.com/mcp/"

[mcp_servers.pg]
command = "npx"
args = ["-y", "@modelcontextprotocol/server-postgres"]
env = { DATABASE_URL = "postgres://localhost/dev" }

Code Explained

approval_policy — when Codex asks you
sandbox_mode — OS-enforced boundary
network_access — off by default in workspace-write
writable_roots — extra writable folders
[profiles.x] — named bundles of settings
[mcp_servers.x] — url (remote) or command (stdio)

Sandbox Modes

ModeCommands Can

⚠ Common Mistakes

  • Using danger-full-access on your laptop "to make it work"; fix the specific network or path need instead
  • Turning approvals to never with danger-full-access; nothing stops a bad command
  • Expecting network calls (installs, APIs) to work in workspace-write without network_access = true
  • Putting API keys in a committed .codex/config.toml

✓ Tips & Best Practices

  • Make profiles for review, CI, and exploration
  • Enable network only for the domains/tools you need (network proxy feature)
  • Use -c key=value to test a setting before saving it
  • Keep secrets in env vars referenced by MCP config

Quick Summary

  • sandbox_mode — read-only · workspace-write · danger-full-access
  • approval_policy — on-request · never
  • profiles — switch bundles with --profile
  • mcp_servers — remote url or local command
