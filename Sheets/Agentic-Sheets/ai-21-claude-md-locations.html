CLAUDE.md Locations & Load Order

CLAUDE.md files exist at several levels and are additive: all of them load together, ordered from broadest (org) to most specific (your folder). Files in the working directory and every parent load at launch; files in subdirectories load later, when Claude reads files in those folders. Since v2.1.277, a repo's AGENTS.md loads automatically when no CLAUDE.md is present.

Loading Rules

  • Concatenated, not overridden; conflicts are resolved by judgment
  • Order: filesystem root → down to working directory
  • Subdirectory files load on demand (monorepos)
  • CLAUDE.local.md loads alongside; keep it gitignored

⚠ Common Mistakes

  • Putting personal preferences in the committed ./CLAUDE.md instead of ~/.claude/CLAUDE.md or CLAUDE.local.md
  • Adding a CLAUDE.local.md to an AGENTS.md-only repo and wondering why AGENTS.md stopped loading (it counts as a CLAUDE.md)
  • Duplicating the same rules at user and project level; they all load, so you pay twice
  • Expecting a subdirectory CLAUDE.md to apply before Claude has touched that folder

✓ Tips & Best Practices

  • Org-wide rules → managed; personal habits → user; team rules → project
  • In monorepos, put package-specific commands in each package's CLAUDE.md
  • Use /memory to see and open every loaded instruction file
  • Let a CLAUDE.md @AGENTS.md import keep one shared source for all tools

Quick Summary

  • additive — every level loads together
  • ~/.claude/CLAUDE.md — personal, all projects
  • ./CLAUDE.md — team, committed
  • AGENTS.md — read when no CLAUDE.md exists
