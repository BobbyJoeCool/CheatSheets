Models, Effort & Cost

Each tool lets you pick a model and often a reasoning effort. Bigger models handle hard design work and long tasks better; smaller ones are faster and cheaper for routine edits. Extended thinking gives the model room to reason before answering, at the cost of time and tokens. You pay either through a subscription with usage limits or per token through an API key.

Cost Drivers

  • Input tokens (context) usually dominate agent costs
  • Long sessions re-send history every turn (caching helps)
  • Higher effort = more thinking tokens per step
  • Subagents and parallel agents multiply usage

⚠ Common Mistakes

  • Using the biggest model for every trivial edit; slower and burns limits for no gain
  • Using the smallest model for a gnarly multi-file bug, then fixing its mistakes by hand
  • Leaving API-key agents in CI with no spend limit or --max-turns
  • Ignoring usage until you hit a limit mid-task

✓ Tips & Best Practices

  • Default to the mid tier; switch up for planning or stuck bugs, down for chores
  • Use a strong model to plan, then a faster one to implement the approved plan
  • Check /usage or /cost regularly to learn what tasks cost
  • Set budget alerts and per-key limits in the provider console

Quick Summary

  • model tier — trade capability for speed and cost
  • effort / thinking — more reasoning, more tokens
  • subscription — flat fee, rate-limited
  • API key — pay per token; set limits
