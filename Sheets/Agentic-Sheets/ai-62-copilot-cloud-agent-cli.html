Copilot Cloud Agent & CLI

The Copilot cloud agent works asynchronously on GitHub: assign it an issue (or ask from the agents panel, a PR comment, VS Code, or the CLI) and it spins up a GitHub Actions environment, makes changes on a copilot/ branch, and opens a draft PR for review. The Copilot CLI brings an agent to your terminal with GitHub context, custom agents, MCP, and a /delegate handoff to the cloud agent.

Cloud Agent Facts

  • Available on paid plans; admins enable the policy
  • Runs in GitHub Actions; uses Actions minutes
  • Sessions time out (max 59 min)
  • GitHub + Playwright MCP enabled by default
  • Firewall limits outbound network

Cloud Agent Setup + CLI Usage

# .github/workflows/copilot-setup-steps.yml  (prepare the agent's environment)
#   jobs:
#     copilot-setup-steps:
#       runs-on: ubuntu-latest
#       steps:
#         - uses: actions/checkout@v5
#         - run: npm ci

# Copilot CLI
npm install -g @github/copilot        # or: brew install copilot-cli
copilot                               # interactive; /login on first run
copilot -p "summarize open PRs" --allow-tool 'shell(gh)'   # programmatic
copilot --allow-all-tools -p "fix lint errors"             # trusted dirs only
# In a session:
#   /model   /agent   /mcp   /delegate "add pagination to /users"

Code Explained

copilot-setup-steps — job name the cloud agent looks for
npm ci — deps installed before the agent starts
copilot -p — one-shot programmatic mode
--allow-tool — pre-approve specific tools
--allow-all-tools — no prompts; use with care
/delegate — hand the task to the cloud agent

⚠ Common Mistakes

  • Assigning vague issues; the agent needs clear acceptance criteria like any teammate
  • No setup-steps workflow, so the agent can't install deps or run tests
  • Merging draft PRs without running CI and reading the diff
  • Using --allow-all-tools in directories with secrets or prod credentials

✓ Tips & Best Practices

  • Write issues with steps to reproduce, expected behavior, and files to look at
  • Use custom agents for repeat task types (tests, docs, deps)
  • Iterate by commenting @copilot on the PR rather than starting over
  • Use the CLI's /delegate to push long tasks to the cloud and keep working

Quick Summary

  • cloud agent — issue → copilot/ branch → draft PR
  • copilot-setup-steps.yml — prepare its environment
  • copilot — terminal agent; -p for scripts
  • /delegate — CLI → cloud handoff
