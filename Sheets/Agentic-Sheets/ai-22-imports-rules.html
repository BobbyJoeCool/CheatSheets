Imports & .claude/rules

Keep CLAUDE.md short by splitting it. Imports (@path/to/file) pull another file in at launch. Rules in .claude/rules/ are small Markdown files that load every session, or only when Claude works on matching files if you add a paths: frontmatter. Use rules for language- or folder-specific guidance so it costs context only when relevant.

Import Rules

  • Relative paths resolve from the importing file
  • Absolute and ~/ paths work
  • Imports can nest up to four hops deep
  • External imports need one-time approval
  • Imports inside code spans/blocks are ignored

Imports and a Path-Scoped Rule

<!-- CLAUDE.md -->
# Project
See @README.md for an overview and @docs/architecture.md for design.
Shared rules for every tool: @AGENTS.md
Personal notes across worktrees: @~/.claude/my-project-notes.md

<!-- .claude/rules/api.md : loads only for matching files -->
---
paths:
  - "src/api/**/*.ts"
---
# API Rules
- Validate all input with zod schemas in src/api/schemas/
- Return errors as { error: { code, message } }
- Every new route needs a test in tests/api/

Code Explained

@README.md — file contents expanded into context
@AGENTS.md — one shared file for Claude, Codex, Copilot
@~/... — personal file shared across worktrees
paths: — glob(s) that trigger loading the rule
no paths: — rule loads every session, like CLAUDE.md

Example .claude/rules/ Layout

Filepaths:
testing.md"**/*.test.ts"
api.md"src/api/**"
frontend.md"src/components/**/*.tsx"

security.md(none: always loaded)

⚠ Common Mistakes

  • Importing huge files (full API specs) with @; they load every session. Use a skill instead
  • Forgetting the quotes around glob patterns in paths: YAML
  • Expecting a path-scoped rule to apply before Claude reads a matching file
  • Symlinking rules from outside the repo and not approving external imports

✓ Tips & Best Practices

  • Move each "when editing X, do Y" section of CLAUDE.md into a scoped rule
  • Keep each rule file to one topic and under ~50 lines
  • Use ~/.claude/rules/ for personal habits you want everywhere
  • Check what loaded with /memory or /context

Quick Summary

  • @path — import a file into CLAUDE.md
  • .claude/rules/*.md — modular instruction files
  • paths: — load only for matching files
  • skills — for big reference content
