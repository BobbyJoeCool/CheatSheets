Instruction File Map

Every agentic tool reads a Markdown file of project instructions, but each looks for a different name in a different place. AGENTS.md has become the shared standard that most tools read, while vendor-specific files add features like path scoping. Knowing which file each tool loads (and when) is how you avoid rules that silently don't apply.

Common Patterns

  • Root file = repo-wide rules
  • Nested files = closer folder wins / adds
  • Glob-scoped rules for file types
  • User-level file in your home directory
  • Org-level rules for enterprises

⚠ Common Mistakes

  • Writing rules in .cursorrules or CLAUDE.md and expecting Codex to see them; Codex reads AGENTS.md
  • Keeping three copies of the same rules that drift apart over time
  • Adding a CLAUDE.md to an AGENTS.md repo and unknowingly stopping Claude from reading AGENTS.md
  • Using .md instead of .mdc for Cursor project rules; plain .md files in .cursor/rules are ignored

✓ Tips & Best Practices

  • Make AGENTS.md the single source; point other files at it
  • Ask each tool to "summarize the instructions you loaded" to verify
  • Put tool-specific extras (hooks, scoped rules) only in that tool's files
  • List the instruction files in your README for new contributors
