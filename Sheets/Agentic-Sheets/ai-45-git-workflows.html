Git Workflows with Claude

Claude Code is fluent in git and the GitHub CLI (gh). It can write commit messages from the diff, create branches and PRs, read review comments, resolve merge conflicts, and dig through history to explain why code looks the way it does. Keep yourself as the final reviewer: commit often, review diffs, and never let an agent force-push shared branches.

Setup

  • Install and auth gh for PR work
  • Allow read-only git: Bash(git diff *), Bash(git log *)
  • Keep git push on ask
  • Commit message format in CLAUDE.md

Everyday Git Prompts

> commit these changes with a conventional commit message
> create a branch fix/tax-rounding, commit, push, and open a PR with gh.
  Link issue #311 and list how you tested it.
> read the review comments on PR #87 and address each one
> resolve the merge conflicts in src/cart.ts; keep both features working,
  then run the cart tests
> why does calculateTotal round twice? check git log -p and blame
> what changed between v2.3.0 and v2.4.0 that could affect checkout?
> /security-review                  # review branch diff before the PR

Code Explained

conventional commit — format from your CLAUDE.md rule
gh pr create — PR body with testing notes
review comments — gh fetches them; Claude fixes each
merge conflicts — resolve, then verify with tests
log -p / blame — history archaeology
/security-review — vulnerability scan of the branch

Suggested Git Permissions

RuleList
Bash(git status) · Bash(git diff *) · Bash(git log *)allow
Bash(git add *) · Bash(git commit *)allow or ask
Bash(git push *) · Bash(gh pr create *)ask
Bash(git push --force *) · Bash(git reset --hard *)deny

⚠ Common Mistakes

  • Letting the agent push directly to main; use branches and PRs
  • Approving git push --force or git reset --hard prompts on autopilot
  • Huge single commits mixing refactors and features; ask for small, focused commits
  • Resolving conflicts without running tests afterwards

✓ Tips & Best Practices

  • Ask for commits at each milestone; small commits make review and rollback easy
  • Use claude --from-pr 123 to reopen sessions linked to a PR
  • Use worktrees (-w) for parallel branches
  • Ask Claude to explain unfamiliar history before changing old code

Quick Summary

  • commit / PR — messages and PR bodies from the diff
  • gh — PRs, reviews, issues from the terminal
  • conflicts — resolve, then test
  • guardrails — push on ask; force-push denied
