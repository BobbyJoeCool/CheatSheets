Writing Portable Instructions

Teams often use several agents. Keep one source of truth (usually AGENTS.md) and make every other tool read it, through imports, symlinks, or native support. Put tool-specific extras (Claude hooks, Cursor globs, Copilot applyTo rules) in each tool's own files. That way a rule change happens once and no tool falls out of sync.

Strategy

  • Shared rules → AGENTS.md
  • Claude-only extras → CLAUDE.md importing AGENTS.md
  • Scoped rules → each tool's scoped format
  • Enforcement → hooks / CI, not prose

Wiring One File into Every Tool

# Claude Code: import (keeps room for Claude-specific additions)
cat > CLAUDE.md <<'EOF'
@AGENTS.md
## Claude Code
- Use plan mode for multi-file changes
EOF

# ...or a symlink if you need nothing extra
ln -s AGENTS.md CLAUDE.md

# Gemini CLI: read AGENTS.md too (in .gemini/settings.json)
#   { "context": { "fileName": ["AGENTS.md", "GEMINI.md"] } }

# Copilot + Codex + Cursor: read AGENTS.md natively; nothing to do

# Aider: load it read-only every session (.aider.conf.yml)
#   read: AGENTS.md

Code Explained

@AGENTS.md — Claude expands the file inline
Claude section — extras only Claude needs
ln -s — same file under two names
context.fileName — Gemini CLI file list
read: — Aider's always-loaded files

⚠ Common Mistakes

  • Symlinking on Windows checkouts without core.symlinks; the link becomes a text file
  • Putting Claude-only syntax (@imports) in AGENTS.md; other tools see it as literal text
  • Duplicating rules "just to be safe"; duplicates diverge and conflict
  • Encoding hard requirements as prose instead of linters, tests, or hooks

✓ Tips & Best Practices

  • Prefer an import over a symlink when you need tool-specific additions
  • Verify each tool by asking it to list the rules it loaded
  • Keep the shared file tool-neutral: no tool names, no special syntax
  • Document the setup in a short CONTRIBUTING section

Quick Summary

  • single source — AGENTS.md holds shared rules
  • import / symlink — wire other tools to it
  • tool extras — only in that tool's files
  • enforce — with hooks, CI, linters
