Sandboxing & Isolation

Permission rules match command text; a sandbox is enforced by the operating system. With /sandbox on, every Bash command and its child processes can write only to the project (and approved paths) and reach only allowed network domains through a local proxy. Because the OS holds the line, sandboxed commands can run without prompts. For stronger isolation, run Claude in a devcontainer, Docker, or a VM.

Platform Support

  • macOS: built-in Seatbelt
  • Linux / WSL2: needs bubblewrap + socat
  • Native Windows: not supported (use WSL2)
  • Covers shell commands only; file tools, MCP, hooks run outside

Sandbox Settings

{
  "sandbox": {
    "enabled": true,
    "filesystem": {
      "allowWrite": ["~/.kube", "/tmp/build"],
      "denyRead":  ["~/.ssh", "~/.aws"]
    },
    "network": {
      "allowedDomains": ["github.com", "*.npmjs.org", "pypi.org"]
    },
    "excludedCommands": ["docker *"],
    "allowUnsandboxedCommands": false
  }
}

Code Explained

enabled — turn the sandbox on (or use /sandbox)
allowWrite — extra writable paths beyond the project
denyRead — hide credential folders from commands
allowedDomains — network allowlist; starts empty
excludedCommands — run these outside the sandbox
allowUnsandboxedCommands — false = no unsandboxed retries

Default Boundaries

AreaDefault
WritesWorking dir, temp dir, added dirs
ReadsMost of the machine (restrict with denyRead)
NetworkProxy; allowed domains start empty
PromptsSandboxed commands auto-approved

Isolation Levels

OptionStrength

⚠ Common Mistakes

  • Assuming /sandbox restricts the Read tool or MCP servers; it only wraps shell commands
  • Leaving default reads open, so commands can still read ~/.ssh unless you add denyRead
  • Adding broad excludedCommands that quietly escape the sandbox
  • Running --dangerously-skip-permissions on a host with real credentials instead of in a container

✓ Tips & Best Practices

  • Turn on /sandbox to cut prompts safely on macOS / Linux
  • Add your package registries and Git host to allowedDomains
  • Set allowUnsandboxedCommands: false in managed settings for strict orgs
  • Use a devcontainer when you want fully unattended runs

Quick Summary

  • /sandbox — OS-level limits on shell commands
  • filesystem — allowWrite · denyRead
  • network — allowedDomains via local proxy
  • containers / VMs — strongest isolation
