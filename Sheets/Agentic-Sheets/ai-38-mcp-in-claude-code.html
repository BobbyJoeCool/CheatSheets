MCP in Claude Code

The Model Context Protocol (MCP) connects Claude Code to outside tools and data: issue trackers, databases, browsers, design files, monitoring. Add a server with claude mcp add, choose a scope (just you, the team, or all your projects), and authenticate with /mcp. Tool search is on by default, so idle servers cost little context until a tool is needed.

Transports

  • http: remote server (recommended)
  • stdio: local process launched by Claude Code
  • sse: older remote transport (deprecated)
  • ws: WebSocket via .mcp.json / add-json

Adding and Managing Servers

# Remote (HTTP) server, OAuth via /mcp afterwards
claude mcp add --transport http sentry https://mcp.sentry.dev/mcp
# Header auth
claude mcp add --transport http api https://api.example.com/mcp \
  --header "Authorization: Bearer $API_TOKEN"
# Local stdio server; everything after -- is the server command
claude mcp add --transport stdio pg --env DATABASE_URL=$DB_URL \
  -- npx -y @modelcontextprotocol/server-postgres
# Share with the team (writes .mcp.json)
claude mcp add --scope project --transport http github https://api.githubcopilot.com/mcp/

claude mcp list            # status of every server
claude mcp get sentry      # details
claude mcp remove pg
claude mcp login sentry    # OAuth from the CLI

Code Explained

--transport http — remote server URL
--header — static auth header
--env — env vars for a stdio server
-- — separates Claude flags from the server command
--scope project — committed .mcp.json for the team
mcp login — OAuth without opening /mcp

⚠ Common Mistakes

  • Committing tokens inside .mcp.json; use ${ENV_VAR} expansion instead
  • Forgetting the -- before a stdio server command, so its flags are parsed as Claude flags
  • Connecting a dozen servers you rarely use; each adds processes and some context
  • Trusting a random MCP server; it runs with your permissions and its output can carry prompt injection

✓ Tips & Best Practices

  • Prefer official remote servers from the vendor over unofficial local ones
  • Use project scope + env vars so teammates share config but not secrets
  • Pre-allow read-only MCP tools; keep write tools on ask
  • Raise MAX_MCP_OUTPUT_TOKENS only if a tool's results get truncated
