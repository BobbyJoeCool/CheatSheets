Prompt Patterns & Anti-Patterns

A few patterns show up again and again in teams that use agents well: let the agent interview you before big work, drive work from a written spec, keep one task per session, and ask for options before code when the path is unclear. The anti-patterns are their mirror images: vague asks, kitchen-sink sessions, and accepting output you didn't read.

Pattern Mindset

  • Spend effort up front on the spec, not on fixes later
  • Small, scoped sessions beat one heroic session
  • Ask the agent to question you, not just obey you
  • Read the diff every time

Interview-Then-Spec Prompt

I want to add CSV export to the reports page.
Interview me about requirements one question at a time:
columns, filters, file size limits, auth, edge cases.
When we're done, write a spec to docs/specs/csv-export.md
with goals, non-goals, API changes, UI changes, and a test plan.
Don't write any code.

Code Explained

interview me — surfaces requirements you hadn't thought of
one at a time — keeps answers focused
spec to file — a durable source of truth
non-goals — prevents scope creep
don't write code — keeps this session about design

⚠ Common Mistakes

  • Writing a 2,000-word prompt full of edge cases instead of a short spec file plus tests
  • Asking the agent to "do everything" in one go; tasks get dropped silently
  • Keeping a prompt you use daily in a notes app instead of a reusable skill
  • Treating a confident tone as correctness; agents sound sure even when wrong

✓ Tips & Best Practices

  • Save prompts you repeat as skills or slash commands
  • Use a second session (or subagent) as a fresh-eyed reviewer
  • Ask "what did you not do?" at the end; agents admit skipped steps
  • Keep specs and plans in the repo so teammates and agents share them

Quick Summary

  • interview me — agent asks; you answer; spec gets written
  • spec-driven — durable file guides many sessions
  • one task per session — clean context, better results
  • read the diff — never skip review
