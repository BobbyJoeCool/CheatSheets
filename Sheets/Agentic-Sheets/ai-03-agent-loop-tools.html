How Agents Work

An agent is a loop. The model reads your prompt and its context, then either answers or emits a tool call. The harness runs the tool and feeds the result (the observation) back in. This repeats until the model decides the task is done, hits a limit, or you interrupt. Everything the agent knows comes from its context: instructions, files it read, command output.

Loop Phases

  • Gather context: search, read files, check git status
  • Act: edit files, run commands, call MCP tools
  • Verify: run tests, linters, builds; read errors
  • Repeat or stop: fix failures or report back

One Turn of the Loop (simplified)

messages = [system_prompt, user_prompt]
while True:
    reply = model(messages, tools=TOOLS)      # model may request tools
    if not reply.tool_calls:                 # no tool call → final answer
        break
    for call in reply.tool_calls:
        result = run_tool(call.name, call.input)  # harness executes
        messages.append(tool_result(call.id, result))
    if over_budget(messages):                # turn/token limits
        messages = compact(messages)         # summarize old history
print(reply.text)

Code Explained

tools=TOOLS — JSON schemas describing each tool the model may call
tool_calls — structured requests, e.g. Edit(file, old, new)
run_tool — the harness, not the model, touches your files
tool_result — output goes back into context as an observation
compact — long sessions get summarized to free space

Why a Loop Stops

ReasonWhat To Do
Task completeReview the diff and test
Needs approvalApprove, deny, or redirect
Max turns / budgetRaise the limit or split the task
Stuck repeatingInterrupt and give a hint
You pressed EscAdd guidance, then continue

⚠ Common Mistakes

  • Assuming the agent "remembers" earlier sessions; it only knows what is in context now
  • Thinking the model runs commands itself; the harness does, under your permission rules
  • Ignoring tool output in the transcript; that is where errors and wrong turns show up
  • Letting a stuck loop run; repeated failed edits burn tokens without progress

✓ Tips & Best Practices

  • Read the agent's plan and first few tool calls; steer early if it heads the wrong way
  • Point the agent at the right files up front to cut the gather-context phase
  • Give it a fast verify command (npm test -- file) so loops stay short
  • Use subagents for heavy searching so the main context stays clean

Quick Summary

  • loop — context → action → observation → repeat
  • tool call — model asks; harness executes
  • observation — tool output fed back as context
  • stop — done, limit hit, approval needed, or interrupted
