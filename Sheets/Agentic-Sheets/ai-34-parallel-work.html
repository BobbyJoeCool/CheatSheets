Parallel & Multi-Agent Work

You can run several agents at once, but they need separate workspaces and independent tasks. Git worktrees give each session its own checkout. Background sessions keep running while you do other work. Dynamic workflows let Claude write a script that fans out many subagents and cross-checks results, and cross-session messaging lets one of your sessions pass a finding to another.

Rules for Parallel Work

  • One worktree (or clone) per writing agent
  • Split by independent files or features
  • Merge and test after each branch lands
  • Review each branch like a teammate's PR

Running Agents in Parallel

# Separate worktrees, one session each
claude -w auth-refactor          # .claude/worktrees/auth-refactor
claude -w billing-tests --tmux   # in its own tmux pane

# Background agents
claude --bg "upgrade eslint to v10 and fix lint errors"
claude agents                    # agent view: monitor / dispatch
claude attach 7c5dcf5d           # jump into one
claude logs 7c5dcf5d             # recent output
/background                      # detach the current session

# Inside a session
> use a workflow to audit every API route for missing auth checks,
  with a second agent verifying each finding
/workflows                       # watch, pause, resume workflows
/batch migrate all class components in src/ to hooks

Code Explained

-w name — isolated worktree per session
--bg — start as background agent
claude agents — dashboard of background sessions
attach / logs — check in without stopping it
workflow — Claude scripts many subagents + verification
/batch — decomposes a big change into parallel units

⚠ Common Mistakes

  • Running two writing agents in the same working tree; they overwrite each other's changes
  • Fanning out ten agents for a task one agent could do; cost multiplies, quality doesn't
  • Splitting work into tasks that depend on each other's output
  • Merging every agent branch without running the full test suite after each

✓ Tips & Best Practices

  • Start with two parallel sessions before trying more
  • Give each worktree its own .env / port so dev servers don't collide
  • Use a workflow when you want findings cross-checked before you see them
  • Use /list-agents to see which sessions can message each other

Quick Summary

  • worktrees — one checkout per agent
  • --bg · claude agents — background sessions + dashboard
  • workflows — scripted fan-out with verification
  • independent tasks — the precondition for parallelism
