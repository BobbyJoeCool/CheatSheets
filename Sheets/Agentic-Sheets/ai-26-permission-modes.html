Permission Modes

Permission Modes

A permission mode decides which actions Claude can take without asking you. Manual (default) asks for edits and most commands. acceptEdits auto-approves file edits. plan is read-only analysis. auto lets a second model, a safety classifier, review actions instead of you. dontAsk denies anything not pre-allowed, and bypassPermissions skips checks entirely. Press Shift+Tab to cycle.

Starting Mode

  • v2.1.283+: interactive sessions start in auto by default
  • Override with --permission-mode <mode>
  • Or permissions.defaultMode in user settings
  • Status bar shows the active mode
  • Cycle: auto → default → acceptEdits → plan → …

The Modes

Mode (config value)Runs Without AskingBest For
Manual (default)Reads onlySensitive work; reviewing every action
acceptEditsReads, file edits, common file commands (mkdir, mv, cp)Iterating on code you're watching
planReads; no edits until you approve the planExploring and planning before changes
autoMost actions; a classifier blocks risky onesLong tasks with fewer interruptions
dontAskOnly what allow rules permit; everything else deniedLocked-down scripts and CI
bypassPermissionsEverything (protected paths still guarded)Isolated containers / VMs only

Setting the Mode

claude --permission-mode plan          # start read-only
claude --permission-mode acceptEdits
/plan add rate limiting to /login      # jump into plan mode with a task

# settings.json (user scope)
{ "permissions": { "defaultMode": "acceptEdits" } }

# Only in a throwaway container:
claude --dangerously-skip-permissions  # = bypassPermissions
claude auto-mode defaults              # print the classifier's rules

Code Explained

--permission-mode — starting mode for this session
/plan — enter plan mode from the prompt
defaultMode — persisted starting mode
--dangerously-skip-permissions — no prompts at all
auto-mode defaults — see what auto mode blocks

⚠ Common Mistakes

  • Running bypassPermissions on your main machine; one bad command can delete or leak real data
  • Setting "defaultMode": "auto" in project settings; it's ignored there by design, so set it in user settings
  • Staying in Manual for long tasks and approving everything without reading ("approval fatigue")
  • Assuming plan mode can't run commands; read-only commands can still run while it explores

✓ Tips & Best Practices

  • Use plan mode for anything medium-sized, then switch to acceptEdits to implement
  • Use auto mode for long tasks, but keep deny rules for secrets and destructive commands
  • Reserve bypassPermissions for disposable devcontainers or VMs
  • Run /fewer-permission-prompts to build an allow list from your history

Quick Summary

  • default (Manual) — ask for edits and commands
  • acceptEdits — auto-approve file edits
  • plan — read and plan, no edits
  • auto — classifier reviews actions for you
