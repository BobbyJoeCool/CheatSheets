Reviewing AI-Generated Code

Agents write plausible code fast, which makes review the bottleneck and the main safety net. AI code fails in recognizable ways: invented APIs, quietly weakened tests, extra abstractions nobody asked for, and changes outside the requested scope. Review it like a capable but overconfident new teammate's PR: small diffs, tests first, and a real read of every line that matters.

Review Mindset

  • You own every line you merge
  • Confident tone ≠ correct code
  • Smaller diffs get better reviews
  • Tests are part of the review, not a substitute

Common AI Failure Modes

FailureWhat to Look For
Hallucinated APIsFunctions, flags, or packages that don't exist or are from another version
Weakened testsDeleted asserts, skip, loosened expectations, mocked-away logic
Scope creepUnrequested refactors, renamed files, reformatting noise
Over-engineeringNew layers, factories, configs for a one-line need
Silent error swallowingBroad try/except, empty catch, default fallbacks hiding bugs
Duplicate helpersRe-implementing utilities that already exist
Security slipsString-built SQL, missing auth checks, secrets in code or logs
Stale patternsDeprecated APIs from older training data

Review Workflow Prompts

> /diff                                   # look at everything that changed
> list every file you changed and why, and anything you did NOT do
> did you modify or delete any tests? show those hunks only
> /security-review                        # vulnerability pass on the branch
> use a subagent with fresh context to review this diff for bugs,
  missing edge cases, and unnecessary changes. Report file:line.

Code Explained

/diff — full change set before commit
what you did NOT do — surfaces skipped steps
test changes — catch weakened tests fast
/security-review — focused security scan
fresh-context reviewer — no bias from writing it

⚠ Common Mistakes

  • Approving because the tests pass, without checking whether the tests were changed
  • Skimming large diffs; ask for smaller commits instead of reviewing 1,500 lines at once
  • Trusting imports and API calls without checking they exist in your versions
  • Letting "while I was there" refactors ride along with a bug fix

✓ Tips & Best Practices

  • Ask for the change in reviewable commits (one concern each)
  • Use a second agent or human for review; the author agent is biased toward its own code
  • Grep for new dependencies and check them on the registry
  • Keep a team checklist of AI failure modes in your PR template

Quick Summary

  • read every diff — you own what you merge
  • tests changed? — check first, every time
  • fresh reviewer — second agent or human
  • small PRs — better review, easier rollback
