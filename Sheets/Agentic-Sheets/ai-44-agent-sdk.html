Claude Agent SDK

The Claude Agent SDK gives you Claude Code's agent loop, built-in tools, permissions, sessions, hooks, subagents, and MCP support as a library for Python and TypeScript. Use it to build your own agents and internal tools: a triage bot, a migration runner, a support agent. It loads .claude/ config like the CLI does. Products built on it should use API-key auth.

Install

  • Python: pip install claude-agent-sdk
  • TypeScript: npm i @anthropic-ai/claude-agent-sdk
  • Auth: ANTHROPIC_API_KEY (or Bedrock/Vertex env)
  • Other languages: run claude -p as a subprocess

Python: query() with Options and a Custom Tool

import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions, tool, create_sdk_mcp_server
@tool("get_ticket", "Fetch a ticket by id", {"id": str})
async def get_ticket(args):
    return {"content": [{"type": "text", "text": f"#{args['id']}: login fails"}]}
tickets = create_sdk_mcp_server(name="tickets", tools=[get_ticket])
options = ClaudeAgentOptions(
    cwd="/repo",
    allowed_tools=["Read", "Grep", "Edit", "mcp__tickets__get_ticket"],
    permission_mode="acceptEdits",
    mcp_servers={"tickets": tickets},
    max_turns=15,
)
async def main():
    async for msg in query(prompt="Fix ticket 42", options=options):
        print(msg)
asyncio.run(main())

Code Explained

query() — async iterator of agent messages
@tool — define a custom tool in-process
create_sdk_mcp_server — expose tools as an MCP server
allowed_tools — pre-approved tool list
mcp__tickets__get_ticket — MCP tool naming pattern
max_turns — cap on agent turns

⚠ Common Mistakes

  • Offering claude.ai login inside your own product; use API keys unless Anthropic approved otherwise
  • Giving a production agent bypassPermissions; use explicit allowed tools and permission callbacks
  • Forgetting the SDK loads local .claude/ config, so behavior differs between machines
  • Building on the old Claude Code SDK packages; migrate to claude-agent-sdk

✓ Tips & Best Practices

  • Prototype with claude -p, then move to the SDK when you need control flow
  • Use hooks in the SDK for audit logging and policy checks
  • Keep tools small and well-described; the model picks tools by description
  • Use sessions to resume long tasks instead of re-sending context
