Explore → Plan → Code → Commit

The most reliable workflow for anything beyond a trivial fix has four steps. Explore: have the agent read the relevant code without editing. Plan: ask for a written plan and review it. Code: implement the approved plan and verify as it goes. Commit: write a clear message and open a PR. Skipping the first two is the top cause of large, wrong diffs.

Why Plan First

  • Catches wrong assumptions before any code exists
  • A plan is 30 lines to review; a diff may be 800
  • Gives the agent a checklist it can reread later
  • Plans can be saved to a file and reused across sessions

The Four Steps as Prompts

1. EXPLORE (read-only; Plan Mode in Claude Code: Shift+Tab)
   Read src/billing/ and explain how invoices are generated.
   Don't change anything yet.

2. PLAN
   Plan how to add proration for mid-cycle upgrades.
   List files to change, new functions, edge cases, and tests.
   Save the plan to docs/plans/proration.md.

3. CODE
   Implement the plan step by step. After each step run
   `pytest tests/billing -q` and fix failures before moving on.

4. COMMIT
   Commit with a descriptive message and open a PR with gh,
   linking issue #311 and summarizing the edge cases handled.

Step Notes

explore — read-only mode prevents premature edits
plan — review it like a design doc; push back
save to file — survives /clear and new sessions
verify per step — small failures are easy to fix
commit — agent writes message + PR body with gh

⚠ Common Mistakes

  • Jumping straight to "implement X" on a medium task; you get the agent's first idea, not the best
  • Approving a plan without reading it; problems surface later as a large diff
  • Keeping the plan only in chat; it vanishes when the session is cleared or compacted
  • Letting implementation drift from the plan without updating it

✓ Tips & Best Practices

  • Ask for two or three alternative approaches with trade-offs before choosing
  • Edit the plan file yourself; the agent will follow your changes
  • For big work, ask the agent to interview you about requirements first
  • Start implementation in a fresh session that reads only the plan file

Quick Summary

  • explore — read, don't edit
  • plan — written, reviewed, saved to a file
  • code — implement with verification per step
  • commit — clear message + PR
