Useful MCP Servers

A few servers cover most developer workflows: source control and issues, a browser for testing UIs, error monitoring, databases, design files, and up-to-date library docs. Start with the ones that remove copy-paste from your day. Remote servers from the vendor are usually easiest: no local install, OAuth sign-in, and automatic updates.

Choosing Servers

  • Official vendor server > community server
  • Read-only access first; add write later
  • Check the tool list (/mcp) before trusting it
  • Disconnect what you don't use this week

⚠ Common Mistakes

  • Connecting a production database with a read-write role; use a read-only user or a replica
  • Letting a browser MCP log into real accounts with saved passwords without watching it
  • Installing a lookalike community server instead of the vendor's official one
  • Expecting servers to work in cloud sessions that only exist on your laptop

✓ Tips & Best Practices

  • Playwright MCP + a running dev server lets Claude verify UI changes itself
  • Pair a server with a skill that teaches your conventions for using it
  • Use a docs server to stop answers based on outdated library versions
  • Keep DB credentials in env vars referenced from .mcp.json

Quick Summary

  • GitHub — issues, PRs, Actions
  • Playwright — browser testing and screenshots
  • Sentry / DB — real errors and schema
  • least privilege — read-only first; write on ask
