Security Risks

Agents run commands, read files, and act on content they fetch, so they inherit every risk of a script with your credentials plus a new one: prompt injection, where text in a file, issue, web page, or tool result tries to redirect the agent. Defend in layers: limit what the agent can read and reach, keep humans on irreversible actions, and verify dependencies and generated code.

Defense in Depth

  • Deny rules for secrets
  • Sandbox / containers for commands
  • Ask-before for push, deploy, publish
  • Scoped tokens; no prod creds locally
  • Review + security scans on every PR

⚠ Common Mistakes

  • Opening an untrusted repo in a permissive mode; its files can carry injected instructions
  • Keeping production credentials in your shell where the agent can read them
  • Running npm install on whatever package name the agent suggests
  • Treating prompt instructions ("never read .env") as a security control

✓ Tips & Best Practices

  • Use plan / read-only mode first in unfamiliar repos
  • Turn on secret scanning and push protection in your Git host
  • Pin MCP servers and dependencies; review lockfile diffs
  • Run security review (/security-review, SAST) on every agent PR

Quick Summary

  • prompt injection — untrusted text can steer the agent
  • secrets — deny reads; use scoped tokens
  • packages — verify before install
  • layers — rules + sandbox + review + CI
