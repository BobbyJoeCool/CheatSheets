Give the Agent a Way to Verify

The single biggest lever on agent quality is a feedback signal it can check by itself. With a test to pass, a type checker, a linter, or a screenshot to compare against, the agent can iterate until it is actually right. Without one, it stops when the code *looks* right to it, which is a much lower bar.

Verification Signals

  • Unit / integration tests (best: fast and specific)
  • Type checker: tsc --noEmit, mypy, cargo check
  • Linter / formatter: eslint, ruff, golangci-lint
  • Build or run the app and check output
  • Browser screenshots via Playwright MCP for UI

Test-Driven Loop with an Agent

Step 1: Write failing tests only
  Write tests in tests/test_slugify.py for slugify():
  unicode → ascii, collapse dashes, strip ends, max 60 chars.
  Do NOT write the implementation. Run pytest; confirm they fail.

Step 2: Commit the tests
  Commit the tests with message "test: slugify spec".

Step 3: Implement until green
  Implement slugify() in src/text.py so all tests pass.
  Don't modify the tests. Run `pytest tests/test_slugify.py -q`
  after each change. Stop when green and show me the diff.

Code Explained

failing tests first — locks in the spec before code exists
confirm they fail — proves the tests test something
commit tests — edits to tests show up clearly in the diff
don't modify tests — blocks "make the test pass by changing it"
run after each change — tight loop, fast feedback

⚠ Common Mistakes

  • Letting the agent "fix" a failing test by weakening the assertion or deleting it
  • Only checking that the code compiles; compiles is not the same as correct
  • Running the full 20-minute suite after every tiny edit; give a focused command
  • Trusting "all tests pass" without seeing the output yourself

✓ Tips & Best Practices

  • Put your exact verify commands in CLAUDE.md / AGENTS.md
  • Use a hook to run the linter or tests automatically after edits
  • For UI, connect Playwright MCP so the agent can screenshot and compare
  • Ask for the test output in the final summary, not just a claim of success

Quick Summary

  • feedback signal — tests, types, lint, build, screenshots
  • TDD — failing test → commit → implement until green
  • protect tests — never let the agent edit them to pass
  • done — a written checklist the agent runs
