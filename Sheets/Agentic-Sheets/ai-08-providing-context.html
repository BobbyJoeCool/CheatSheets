Providing Context

Agents can search, but every search costs time and tokens and may find the wrong thing. Hand over what you already know: the exact files, the full error, a screenshot of the broken UI, the docs page for the library version you use. Raw evidence beats your summary of it: paste the actual stack trace, not "it crashes".

Context Sources

  • @path/to/file mentions pull a file in directly
  • Paste or drag images (UI bugs, diagrams, mockups)
  • Pipe output: npm test 2>&1 | claude -p "why?"
  • Give URLs for docs; the agent can fetch them
  • MCP servers pull tickets, logs, designs, DB schemas

Ways to Hand Over Context

# Mention files in the prompt (Claude Code, Copilot, Cursor, Codex)
> Refactor @src/api/client.ts to use @src/lib/retry.ts

# Pipe command output straight in
cat build.log | claude -p "explain the first error and fix it"
git diff main | claude -p "review this for bugs"

# Paste a screenshot: Ctrl+V in the terminal (or drag the file)
> The modal in this screenshot overflows on mobile. Fix it.

# Point at docs for the exact version you use
> Use the v5 API from https://tanstack.com/query/v5/docs

Code Explained

@file — adds the file to context without a search
2>&1 / pipe — stdin becomes part of the prompt
claude -p — one-shot, non-interactive answer
git diff | ... — review exactly the change set
Ctrl+V image — visual bugs are faster to show than describe
docs URL — avoids answers from an older API version

⚠ Common Mistakes

  • Paraphrasing errors; the exact message and line number are what the agent needs
  • Dumping the whole repo or a 10K-line log; noise buries the signal and fills context
  • Assuming the agent knows your library version; it may write code for an older API
  • Describing a visual bug in words when a screenshot would take two seconds

✓ Tips & Best Practices

  • Trim logs before piping: | tail -50 or | grep -A5 ERROR
  • Connect an MCP server for systems you copy from daily (issues, Sentry, DB)
  • Keep a docs/ folder of key decisions the agent can be pointed to
  • Put version pins and key library notes in your instructions file

Quick Summary

  • @mentions — pull exact files into context
  • pipe — send command output as the prompt
  • images — show UI bugs instead of describing
  • evidence — real errors beat summaries
