Writing an Effective CLAUDE.md

Claude follows short, specific, checkable instructions much more reliably than long, vague ones. Every line should earn its place: if removing it wouldn't change Claude's behavior, delete it. Use the repeated-mistake rule: when you correct the same thing twice, add one line. Prune when instructions go stale. Auto memory handles smaller learnings Claude picks up on its own.

Style That Works

  • Imperative bullets: "Use X", "Never Y"
  • Concrete commands and paths, not descriptions
  • Emphasis (IMPORTANT, YOU MUST) for the few critical rules
  • Headings so humans can maintain it
  • Examples for anything ambiguous

⚠ Common Mistakes

  • Writing paragraphs of prose; bullets with one rule each are followed more reliably
  • Emphasizing everything; when every line says IMPORTANT, nothing stands out
  • Contradicting rules across files (user says tabs, project says spaces)
  • Letting auto memory and CLAUDE.md both hold the same rule in different words

✓ Tips & Best Practices

  • Test a new rule: start a fresh session and see if behavior changes
  • Ask Claude: "which rules in CLAUDE.md did you not follow and why?"
  • Review auto memory entries in /memory and promote good ones to CLAUDE.md
  • Keep team rules in CLAUDE.md and personal ones in ~/.claude/CLAUDE.md

Quick Summary

  • specific — checkable rules, real commands
  • repeated-mistake rule — two corrections → one new line
  • prune — delete what no longer changes behavior
  • auto memory — Claude's own notes; review in /memory
