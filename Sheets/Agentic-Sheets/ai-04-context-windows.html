Context Windows & Tokens

The context window is the model's working memory: system prompt, instruction files, your messages, every file it read, and every command output, measured in tokens (roughly ¾ of a word, or about 4 characters of English). When it fills up, the tool compacts (summarizes) old history. Quality drops as context gets long and noisy, a problem often called context rot.

Rules of Thumb

  • 1,000 tokens ≈ 750 words ≈ 40–80 lines of code
  • Big windows (200K–1M tokens) still degrade when cluttered
  • Instruction files load every session, so keep them short
  • Start a fresh session for each unrelated task

⚠ Common Mistakes

  • Running one giant session for a whole day of unrelated tasks; old context misleads new work
  • Letting a test run dump 5,000 lines of logs into context
  • Pasting whole files when only one function matters
  • Stuffing everything into the instructions file; it costs tokens on every single request

✓ Tips & Best Practices

  • /clear between tasks; it is the cheapest quality boost there is
  • Use /compact keep the API decisions to steer what survives summarization
  • Delegate wide searches to a subagent; only its summary returns
  • Watch the context meter and compact before you hit the limit, not after

Quick Summary

  • token — ≈ 4 characters of English text
  • context window — everything the model sees this request
  • compaction — summarizes old history to free space
  • context rot — long, noisy context lowers quality
