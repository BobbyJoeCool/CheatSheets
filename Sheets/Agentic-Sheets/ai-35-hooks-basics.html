Hooks — Basics

Hooks run your own code at points in Claude Code's lifecycle: before a tool runs, after it runs, when a prompt is submitted, when Claude stops, and more. Unlike CLAUDE.md, hooks are deterministic: they always fire. A hook can run a shell command, call an HTTP endpoint or MCP tool, ask a model, or spawn an agent. Its exit code and output can block an action or feed text back to Claude.

Key Facts

  • Configured under "hooks" in any settings file
  • Hooks from all scopes and plugins merge; all fire
  • Command hooks get event JSON on stdin
  • Run with your user permissions; review before adding
  • /hooks shows every hook and where it came from

Hook Structure in settings.json

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/block-dangerous.sh",
            "timeout": 30
          }
        ]
      }
    ]
  }
}

Code Explained

PreToolUse — the event to hook into
matcher — tool name(s): Bash, Edit|Write, regex
type — command · http · mcp_tool · prompt · agent
${CLAUDE_PROJECT_DIR} — project root; use for portable paths
timeout — seconds before the hook is killed

Exit Codes (command hooks)

CodeMeaning
0Success; stdout JSON parsed for decisions
2Block the action; stderr shown to Claude
otherNon-blocking error; action continues

Matcher Syntax

MatcherMatches
"*" or omittedEverything
BashExactly the Bash tool
Edit|WriteEither tool
mcp__github__.*Regex: all GitHub MCP tools
"if": "Bash(rm *)"Extra filter by rule syntax

Hook Input (stdin JSON)

FieldHolds

⚠ Common Mistakes

  • Relying on CLAUDE.md for rules that must always hold; only hooks (or deny rules) enforce
  • Using exit code 1 to block; only exit code 2 blocks the action
  • Hard-coding absolute paths; use ${CLAUDE_PROJECT_DIR} so hooks work for teammates
  • Slow hooks on every tool call; they add latency to each step

✓ Tips & Best Practices

  • Write hooks as small scripts in .claude/hooks/ and commit them
  • Test a hook by piping sample JSON: echo '{...}' | ./hook.sh; echo $?
  • Use jq to pull fields from stdin JSON in shell hooks
  • Use --safe-mode to rule out a misbehaving hook

Quick Summary

  • hooks — deterministic code at lifecycle events
  • matcher — which tools the hook applies to
  • exit 2 — block the action
  • stdin JSON — event details for your script
