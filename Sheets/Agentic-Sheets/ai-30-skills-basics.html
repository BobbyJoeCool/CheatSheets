Skills — Basics

A skill is a folder with a SKILL.md file: instructions, knowledge, or a workflow Claude can use. Claude sees each skill's name and description every session and loads the full content only when the task matches, or when you type /skill-name. Skills replace the old .claude/commands/ files (which still work) and are the main way to package repeatable know-how.

Two Kinds

  • Reference skills: knowledge (API style guide, schema notes)
  • Action skills: workflows you trigger (/deploy, /release)
  • Description quality decides when Claude picks it up
  • Plugin skills are namespaced: /plugin:skill

A Minimal Skill: .claude/skills/fix-issue/SKILL.md

---
name: fix-issue
description: Fix a GitHub issue end to end. Use when the user gives an
  issue number or link and wants it implemented with a test and a PR.
argument-hint: "[issue-number]"
---

Fix GitHub issue #$ARGUMENTS.

1. Run `gh issue view $ARGUMENTS` and read the issue and comments.
2. Find the relevant code; explain the cause in two sentences.
3. Write a failing test that reproduces it, then fix the code.
4. Run `npm test` and `npm run lint`; fix anything that fails.
5. Commit as `fix: <summary> (#$ARGUMENTS)` and open a PR with `gh pr create`.

Code Explained

folder name — becomes the command: /fix-issue
description — Claude matches tasks against this text
argument-hint — autocomplete hint in the / menu
$ARGUMENTS — replaced with what you type after the name
numbered steps — a checklist Claude follows in order

⚠ Common Mistakes

  • Writing a vague description ("helps with code"); Claude won't know when to load it
  • Putting a huge reference doc in CLAUDE.md instead of a skill that loads on demand
  • Making a side-effect skill (deploy, publish) auto-invocable; set disable-model-invocation: true
  • Forgetting /reload-skills after creating a skill mid-session

✓ Tips & Best Practices

  • Turn any prompt you've typed three times into a skill
  • Write descriptions as "Use when …" so matching is clear
  • Keep SKILL.md focused; put long references in supporting files the skill points to
  • Commit team skills in .claude/skills/ so everyone shares them

Quick Summary

  • SKILL.md — frontmatter + instructions in a folder
  • description — drives automatic invocation
  • /skill-name args — manual invocation with $ARGUMENTS
  • on demand — full content loads only when used
