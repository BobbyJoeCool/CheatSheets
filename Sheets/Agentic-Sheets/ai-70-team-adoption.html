Team Adoption & Governance

Rolling agents out to a team works best with shared defaults in the repo, guardrails enforced centrally, and clear expectations about review. Commit project settings, instructions, skills, and MCP config so everyone starts from the same baseline. Use managed settings for policies that individuals must not override, and track usage so costs and value stay visible.

Shared in the Repo

  • AGENTS.md / CLAUDE.md
  • .claude/settings.json (permissions, hooks)
  • .claude/skills/ · .claude/agents/
  • .mcp.json (no secrets)
  • PR template with AI review checklist

⚠ Common Mistakes

  • Every developer inventing their own config; no shared guardrails or conventions
  • Measuring lines of code generated instead of delivery and quality outcomes
  • Mandating tools without training or time to learn them
  • Letting bypassPermissions spread to laptops because it's convenient

✓ Tips & Best Practices

  • Run /team-onboarding to draft an onboarding guide from real usage
  • Host an internal plugin marketplace for approved skills and hooks
  • Use analytics / usage dashboards to spot cost outliers early
  • Collect "agent got this wrong" examples and turn them into rules

Quick Summary

  • repo defaults — instructions, settings, skills committed
  • managed settings — org policy nobody can override
  • policy — tools, data, review, autonomy
  • measure outcomes — cycle time, quality, cost
