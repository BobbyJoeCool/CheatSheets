Subagents — Basics

A subagent is a separate Claude instance with its own context window, system prompt, and tool set. The main agent hands it a task; it reads, searches, or edits as needed and returns only a summary. That keeps your main conversation small and focused. Claude delegates on its own when a task matches a subagent's description, or you can ask for one explicitly.

Why Use Them

  • Context isolation: 50 file reads → 1 summary
  • Parallelism: several investigations at once
  • Specialization: own prompt, tools, model
  • Cheaper models for simple subtasks

Asking for Subagents

> Use a subagent to find every place we parse dates and report
  file:line plus which library each uses. Don't change anything.

> In parallel, use three subagents to investigate why checkout is slow:
  one for DB queries, one for API calls, one for frontend bundle size.
  Summarize findings and rank the likely causes.

> @code-reviewer review the diff on this branch       # @-mention = guaranteed

> /subtask draft migration notes for the v3 API        # forked background subagent
> /agents                                              # create / manage subagents

Code Explained

@name — type @ and pick an agent; always runs it
/subtask — fork: inherits full conversation, runs in background

⚠ Common Mistakes

  • Delegating tightly coupled edits to parallel subagents; they conflict on the same files
  • Expecting a subagent to know your earlier conversation; only a fork inherits it
  • Asking for a subagent and then a full transcript back; you lose the context savings
  • Rewinding and assuming subagent edits were reverted; use git

✓ Tips & Best Practices

  • Say "report only file:line and a one-line note" to keep summaries tight
  • Use subagents for exploration, review, and test-failure triage
  • Use Ctrl+B to background a long subagent and keep working
  • Stop all background subagents with Ctrl+X Ctrl+K
