Headless Mode

Print mode (claude -p) runs one prompt non-interactively and exits, so you can use Claude Code in shell scripts, cron jobs, git hooks, and CI. Pipe input in, get text or JSON out, cap the turns and budget, and pre-approve exactly the tools the job needs. For anything nobody watches, set permissions so no prompt is ever waiting.

Unattended Safety

  • Use --allowedTools for exactly what's needed
  • --permission-prompts none denies anything else
  • Cap with --max-turns and --max-budget-usd
  • --bare skips local config for reproducibility

Scripting with claude -p

claude -p "explain what src/auth.ts does"               # text answer
git diff main | claude -p "review for bugs; be terse"   # piped input
cat error.log | claude -p "root cause?" > diagnosis.md

claude -p "fix the lint errors" \
  --allowedTools "Read" "Edit" "Bash(npm run lint *)" \
  --permission-prompts none --max-turns 10 --max-budget-usd 2

claude -p "list TODOs as JSON" --output-format json | jq -r '.result'
claude -p --json-schema '{"type":"object","properties":{"risk":{"type":"string"}}}' \
  "rate the risk of this migration"                     # validated JSON
claude -p --output-format stream-json --verbose "..."   # event stream
claude -c -p "now add tests for that"                   # continue last session
claude --bare -p "summarize README.md"                  # no CLAUDE.md, hooks, MCP

Code Explained

-p — run once, print, exit
pipe | — stdin is added to the prompt
--allowedTools — pre-approved tools only
--permission-prompts none — deny instead of waiting
--output-format json — result + cost + session_id
--json-schema — structured output, validated
--bare — fast, minimal, reproducible

⚠ Common Mistakes

  • Running headless with broad permissions on a machine with real credentials
  • No --max-turns or budget cap; a confused run can loop and burn money
  • Parsing text output with regex; use --output-format json or --json-schema
  • Expecting interactive-only features like /rewind or permission prompts in -p runs

✓ Tips & Best Practices

  • Start scripted runs with --bare so local config doesn't change results
  • Log the JSON result's session_id so you can -r into a run later
  • Use the Agent SDK when a script grows into an application
  • Give CI its own settings via --settings ./ci-settings.json

Quick Summary

  • claude -p — one-shot non-interactive run
  • --allowedTools — exact tool allowlist
  • --output-format json — machine-readable results
  • --max-turns / --max-budget-usd — hard limits
