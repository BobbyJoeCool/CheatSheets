Codex CLI Basics

The Codex TUI works like other terminal agents: type a task, watch it read files and run commands inside its sandbox, approve anything outside the policy, and review diffs. Slash commands control the session, @ searches files, and Esc interrupts. Start new repos with /init to generate an AGENTS.md.

Habits

  • /init once per repo, then edit AGENTS.md
  • /diff before committing
  • /compact or /new when context gets heavy
  • /review for a second look at changes

Common Flags

codex -m <model>                    # model for this run
codex -s read-only                  # sandbox (see Sheet 55)
codex -a on-request                 # approvals: on-request | never
codex --full-auto                   # workspace-write + on-request
codex -C ../service                 # working directory
codex -c model_reasoning_effort=high   # override a config key
codex --profile ci                  # use [profiles.ci]

Code Explained

-s / --sandbox — what commands can touch
-a / --ask-for-approval — when Codex stops to ask
--full-auto — fewer prompts, still sandboxed
-C / --cd — run against another folder
-c key=value — one-off config override

⚠ Common Mistakes

  • Never running /diff; you miss stray or untracked files the agent created
  • Using /new and expecting it to remember the old thread; that's what /resume is for
  • Reaching for --yolo to avoid prompts instead of tuning sandbox and approvals
  • Ignoring /status, then being surprised by the active model or sandbox

✓ Tips & Best Practices

  • Use @ to point at files instead of describing them
  • Ask for /plan on medium tasks and review it before code
  • Put your favorite flags in a [profiles.x] block
  • Use /review as a quick second opinion before a PR

Quick Summary

  • /diff · /review — inspect changes
  • /compact · /new — manage context
  • -s · -a — sandbox and approval flags
