Choosing a Workflow

Not every task deserves an agent, and not every agent task deserves full autonomy. Size the task first. Small, well-specified changes with good tests can run autonomously or in the cloud. Ambiguous design work needs you in the loop, planning together. Some work (secrets rotation, prod data fixes, security-critical logic) is better done by hand or with tight review.

Quick Test

  • Can you describe "done" in one or two sentences?
  • Is there a test or command that proves it works?
  • Would a wrong change be cheap to undo?
  • Three yeses → good candidate for autonomy

Task Sizing Guide

Task SizeExampleWorkflow
TrivialRename a variable, fix a typo, add a log lineJust ask; auto-accept edits
SmallFix a bug with a failing test, add an endpointPrompt → review diff → commit
MediumNew feature touching 5–15 filesExplore → plan → approve plan → implement → test
LargeMigration, new subsystem, framework upgradeWrite a spec; split into tasks; one session per task
Unclear"Make it faster", "clean this up"Investigate first; ask the agent for options, not changes

Sync vs Async

ModeWhen
Interactive (sync)Design decisions, unfamiliar code, UI work
Headless / scriptedRepeatable chores, CI checks, batch edits
Cloud (async)Independent tickets; parallel work

Use Extra Care

AreaWhy
Auth, crypto, paymentsSubtle bugs are costly
Prod data / migrationsHard to undo
Secrets & credentialsLeak risk
Legacy code with no testsNothing catches regressions

⚠ Common Mistakes

  • Handing a vague, large task to an autonomous agent and hoping for the best
  • Skipping the plan on medium tasks; the agent picks an approach you would have rejected
  • Using an agent on untested legacy code without first adding characterization tests
  • Splitting work into tasks that depend on each other, then running them in parallel

✓ Tips & Best Practices

  • For greenfield work, start with a short spec file the agent can reread
  • For legacy code, ask the agent to explain the module and add tests before changing it
  • One task per session; /clear when you switch topics
  • Keep a running TODO in a file so long work survives session resets

Quick Summary

  • size first — trivial → just ask; large → spec + split
  • verify — no test, no autonomy
  • sync vs async — decisions in the loop; chores in the cloud
  • care zones — auth, prod data, secrets, untested code
