Settings Files & Scopes

Claude Code reads JSON settings from several scopes and merges them. User settings apply to all your projects, project settings are committed and shared with the team, local project settings are yours only (gitignored), and managed settings are enforced by your organization. More specific scopes override broader ones, but managed settings always win.

Precedence (high → low)

  • Managed (org policy)
  • Command-line flags (--settings, etc.)
  • Local project: .claude/settings.local.json
  • Project: .claude/settings.json
  • User: ~/.claude/settings.json

Example .claude/settings.json (committed)

{
  "model": "sonnet",
  "permissions": {
    "defaultMode": "acceptEdits",
    "allow": ["Bash(npm run test *)", "Bash(git diff *)"],
    "deny":  ["Read(./.env)", "Read(./secrets/**)", "Bash(rm -rf *)"]
  },
  "env": { "NODE_ENV": "development" },
  "hooks": {
    "PostToolUse": [{ "matcher": "Edit|Write",
      "hooks": [{ "type": "command",
                 "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/format.sh" }] }]
  },
  "autoUpdatesChannel": "stable"
}

Key Fields

model — default model alias or full ID
permissions — allow / ask / deny + defaultMode
env — environment variables for every session
hooks — lifecycle automation (Sheets 35–37)
autoUpdatesChannel — latest or stable

⚠ Common Mistakes

  • Putting personal preferences in .claude/settings.json; they get committed for the whole team
  • Committing settings.local.json; it's meant to stay out of git
  • Expecting a project allow rule to override an org deny rule; managed settings always win
  • Hand-editing JSON and breaking it; run claude doctor to catch validation errors

✓ Tips & Best Practices

  • Use /config or /permissions for safe interactive edits
  • Use the /update-config skill: describe the change in plain words
  • Keep shared deny rules for secrets in the committed project settings
  • Use --settings ./ci.json to give CI runs their own locked-down config

Quick Summary

  • user — ~/.claude/settings.json, all projects
  • project — .claude/settings.json, shared
  • local — .claude/settings.local.json, personal
  • managed — org policy, always wins
