Copilot Custom Instructions

Copilot reads several kinds of instruction files. Repository-wide rules go in .github/copilot-instructions.md. Path-specific rules go in .github/instructions/*.instructions.md with an applyTo glob. Copilot also reads AGENTS.md, CLAUDE.md, and GEMINI.md files (nearest one wins). Personal and organization instructions add another layer.

Priority

  • Personal instructions (highest)
  • Repository instructions
  • Organization instructions
  • All relevant sets are combined in the prompt

Repo-Wide + Path-Specific Instructions

<!-- .github/copilot-instructions.md -->
This is a Rails 8 app with Hotwire. Postgres 16.
- Run tests with `bin/rails test`; system tests with `bin/rails test:system`
- Use service objects in app/services for business logic
- Never add gems without asking

<!-- .github/instructions/models.instructions.md -->
---
applyTo: "app/models/**/*.rb"
excludeAgent: "code-review"
---
- Validate presence of required attributes
- Add a database index for every foreign key
- Keep callbacks minimal; prefer explicit service calls

Code Explained

copilot-instructions.md — applies to every request in the repo
*.instructions.md — path-specific instruction files
applyTo — glob(s) of files the rules cover
excludeAgent — skip for code-review or cloud-agent

⚠ Common Mistakes

  • Putting instructions in .github/copilot-instructions/ (folder) instead of the single .md file
  • Forgetting applyTo frontmatter on .instructions.md files, so they never match
  • Writing instructions that conflict with AGENTS.md; both get loaded
  • Assuming every surface reads path-specific files; support varies by feature

✓ Tips & Best Practices

  • Generate a first draft: ask Copilot to create copilot-instructions.md from the repo
  • Keep shared rules in AGENTS.md and Copilot-only extras here
  • Use excludeAgent: "code-review" for rules that only make sense when writing code
  • Check the references list in chat responses to confirm the file was used

Quick Summary

  • .github/copilot-instructions.md — repo-wide rules
  • .github/instructions/*.instructions.md — path rules via applyTo
  • AGENTS.md / CLAUDE.md — also read; nearest wins
  • personal > repo > org — priority order
