Your First Session

Open a terminal in your project and run claude. On a new repo, start with /init so Claude scans the code and writes a starter CLAUDE.md. Then ask questions before asking for changes. When Claude wants to edit a file or run a command, it asks for permission (depending on mode); read the request, approve, deny, or redirect. Press Esc any time to stop it.

First Ten Minutes

  • cd my-project && claude
  • /init → review and edit the generated CLAUDE.md
  • Ask "how is this project structured?"
  • Make one small change; read the diff; run tests
  • Commit, then /clear before the next task

A Typical First Session

$ cd ~/code/invoice-api && claude

> /init                                  # writes CLAUDE.md from the codebase
> what are the main modules and how do requests flow?
> where is tax calculated? don't change anything yet
> add a unit test for tax on zero-value invoices, then run it

  ● Edit tests/test_tax.py               # permission prompt appears
    1. Yes  2. Yes, don't ask again  3. No, tell Claude what to do

> !pytest -q tests/test_tax.py           # ! runs a shell command yourself
> /diff                                  # review all changes so far
> commit this with a good message
> /clear                                 # fresh context for the next task

Code Explained

/init — starter CLAUDE.md: commands, layout, conventions
ask first — build understanding before edits
permission prompt — approve once, always, or redirect
! prefix — shell mode; output goes into the session
/diff — review the working-tree changes
/clear — new conversation, empty context

Answering Permission Prompts

ChoiceEffect
YesAllow this one action
Yes, don't ask againAdds an allow rule (per repo for Bash)
No + feedbackDeny and tell Claude what to do instead
TabAdd a comment to your answer
EscInterrupt the whole turn

Input Prefixes

PrefixMeaning
/Command or skill
!Shell mode: run a command yourself
@File path mention with autocomplete
?Shortcut help (on empty input)

⚠ Common Mistakes

  • Skipping /init; without CLAUDE.md the agent rediscovers build commands every session
  • Accepting /init output blindly; it can include wrong or outdated commands, so edit it
  • Clicking "don't ask again" on broad commands you don't fully trust
  • Never using /clear, so every new task inherits the last one's clutter

✓ Tips & Best Practices

  • Ask Claude to explain before it edits; you learn the code and catch misreads
  • Use ! to run a command yourself and let Claude react to the output
  • Check /diff before committing anything
  • Run /powerup for short interactive lessons on features

Quick Summary

  • claude — start in the project root
  • /init — generate CLAUDE.md, then edit it
  • permission prompt — yes · always · no + feedback
  • /diff then /clear — review, commit, reset
