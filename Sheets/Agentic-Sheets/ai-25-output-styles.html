Output Styles

An output style changes how Claude responds for a whole session: its tone, length, and role. Claude Code ships four built-in styles on top of Default, and you can write your own as Markdown files. Styles shape responses; they don't change permissions and aren't enforced. Use CLAUDE.md for project facts and hooks for guarantees.

Switching

  • /output-style concise (case-insensitive)
  • /config → Output style
  • "outputStyle": "Explanatory" in settings (case-sensitive)
  • Takes effect on your next message
  • Saved to .claude/settings.local.json by default

Custom Style: ~/.claude/output-styles/reviewer.md

---
name: Strict Reviewer
description: Terse, risk-first answers with file:line references
keep-coding-instructions: true
---

Lead every answer with the single biggest risk or the direct answer.
Reference code as `path/file.ts:42`.
No preamble, no recap. Use bullets, max 6 per answer.
When unsure, say what you'd need to check instead of guessing.

Code Explained

name — shown in the /config picker
description — picker subtitle
keep-coding-instructions — keep Claude Code's engineering rules
body — instructions sent with every request

⚠ Common Mistakes

  • Leaving out keep-coding-instructions: true on a coding style; Claude loses its built-in engineering guidance
  • Writing "outputStyle": "explanatory" in settings; the value is case-sensitive and silently falls back to Default
  • Expecting a style to restrict actions; permission mode still controls what runs
  • Editing a style file mid-session and expecting it to reload; restart to pick it up

✓ Tips & Best Practices

  • Use Learning style to onboard juniors or learn a new language
  • Use Explanatory when exploring an unfamiliar codebase
  • Use Concise when you know the code and want results fast
  • Build non-coding roles (writer, analyst) as custom styles without coding instructions

Quick Summary
