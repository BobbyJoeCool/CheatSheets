Skills — Advanced

Frontmatter controls who can invoke a skill, which tools it may use, and where it runs. context: fork runs the skill in an isolated subagent so its work doesn't fill your main context. Dynamic context injection (! followed by a command in backticks) runs shell commands before the skill reaches Claude and inlines their output. Supporting files and scripts live next to SKILL.md.

Who Can Invoke

  • Default: both you and Claude
  • disable-model-invocation: true → only you
  • user-invocable: false → only Claude (hidden from /)
  • skillOverrides in settings hides skills you didn't write

Advanced SKILL.md

---
name: pr-review
description: Review the current branch's diff for bugs and risky changes.
disable-model-invocation: true
allowed-tools: Read Grep Bash(git diff *) Bash(git log *)
context: fork
agent: Explore
model: opus
paths: "src/**"
---

## Changes on this branch
!`git diff --stat origin/main...HEAD`

## Checklist
Review against @${CLAUDE_SKILL_DIR}/checklist.md.
Report findings as `file:line — issue — fix`, most severe first.
Run ${CLAUDE_SKILL_DIR}/scripts/find-todos.sh and include new TODOs.

Code Explained

disable-model-invocation — manual /pr-review only
allowed-tools — pre-approved while the skill runs
context: fork — runs in an isolated subagent
agent: Explore — which subagent type to fork into
paths — only offered when matching files are in play
!`cmd` — output inlined before Claude reads it
${CLAUDE_SKILL_DIR} — path to this skill's folder

⚠ Common Mistakes

  • Using allowed-tools too broadly (Bash); it pre-approves every command while the skill runs
  • A ! command that fails; failure aborts the whole skill invocation
  • Expecting forked skill edits to be undone by rewind; background forks aren't checkpointed
  • Field names with underscores or wrong case; misspelled fields are silently ignored

✓ Tips & Best Practices

  • Use context: fork for research-heavy skills to keep the main thread clean
  • Inject live state (git status, failing tests) with ! + a backticked command instead of asking Claude to fetch it
  • Ship helper scripts inside the skill folder; reference them via ${CLAUDE_SKILL_DIR}
  • Try bundled skills first: /verify, /run, /simplify, /batch, /debug

Quick Summary

  • disable-model-invocation — you trigger; Claude can't
  • allowed-tools — pre-approve tools for the skill
  • context: fork — run isolated in a subagent
  • !`cmd` — inject command output at load time
