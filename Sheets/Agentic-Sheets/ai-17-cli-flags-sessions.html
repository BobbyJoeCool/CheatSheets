CLI Flags & Sessions

Flags control how a session starts: which model, which permission mode, which extra folders, whether it's interactive. Every conversation is saved as a session you can continue (-c) or resume by ID or name (-r). Print mode (-p) runs one prompt non-interactively and exits, which is the basis for scripting and CI.

Session Storage

  • Transcripts saved per project under ~/.claude/projects/
  • -c picks the most recent session in this folder
  • -r with no arg opens a picker; bg marks background sessions
  • claude purge deletes a project's local state

Common Invocations

claude                                  # interactive session
claude "explain the auth flow"          # interactive, with first prompt
claude -c                               # continue most recent session here
claude -r auth-refactor                 # resume by name or ID
claude -r abc123 --fork-session         # resume as a new branch
claude -n "billing-fix"                 # name the session

claude --model opus --effort high       # model + effort for this session
claude --permission-mode plan           # start read-only
claude --add-dir ../shared-lib          # grant access to another folder
claude -w feature-auth                  # isolated git worktree
claude --bg "investigate flaky test"    # background agent, returns now

claude -p "summarize this repo"         # print mode: answer and exit
claude -p --output-format json "..."    # machine-readable result

Code Explained

-c / --continue — latest conversation in this directory
-r / --resume — by ID, name, or picker
--fork-session — new ID; original stays intact
--effort — low · medium · high · xhigh · max
-w / --worktree — .claude/worktrees/<name>
--bg — runs as a background agent
-p / --print — non-interactive; see Sheet 42

⚠ Common Mistakes

  • Using -c in the wrong folder; it continues the latest session for the current directory only
  • Resuming a stale session for a new task instead of starting fresh
  • Passing --dangerously-skip-permissions casually on your main machine
  • Forgetting -p flags like --max-turns only apply in print mode

✓ Tips & Best Practices

  • Name long-running work with -n so you can -r it by name
  • Use --safe-mode to check whether a hook, plugin, or CLAUDE.md is causing a problem
  • Use -w to run two sessions on the same repo without collisions
  • Use --fork-session to try an alternative without losing the original

Quick Summary

  • -c · -r — continue latest · resume specific
  • --model · --effort — per-session model choices
  • --permission-mode — start in plan, acceptEdits, auto…
  • -p — one-shot, scriptable mode
