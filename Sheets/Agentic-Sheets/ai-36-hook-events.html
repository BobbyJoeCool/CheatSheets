Hook Events

Each event fires at a specific point and supports different controls. PreToolUse can allow, deny, or rewrite a tool call before it runs. PostToolUse sees the result and can feed back context (like lint errors). UserPromptSubmit can add context or block a prompt. Stop can force Claude to keep going. SessionStart can load context or set environment variables.

Control Fields (JSON stdout)

  • permissionDecision: allow · deny · ask · defer (PreToolUse)
  • decision: "block" + reason
  • hookSpecificOutput.additionalContext
  • updatedInput: rewrite tool args (PreToolUse)
  • continue: false + stopReason

⚠ Common Mistakes

  • Blocking Stop forever when tests fail; add a retry limit or Claude loops endlessly
  • Doing slow work in UserPromptSubmit; it delays every prompt you send
  • Returning JSON with exit code 2 and expecting it to be parsed; exit 2 ignores stdout JSON
  • Using PostToolUse to prevent an action; it's too late, the tool already ran

✓ Tips & Best Practices

  • Prevent with PreToolUse; react with PostToolUse
  • Use additionalContext to hand Claude lint or test output it should fix
  • Use SessionStart to inject the current ticket or branch notes
  • Use Notification hooks to get pinged when Claude is waiting on you

Quick Summary

  • PreToolUse — allow / deny / rewrite before running
  • PostToolUse — react to results; add context
  • Stop — verify before Claude finishes
  • SessionStart — load context at startup
