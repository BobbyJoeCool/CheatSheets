Codex Automation & Cloud

codex exec runs Codex non-interactively for scripts and CI, streaming progress to stderr and the final answer to stdout (or JSON Lines with --json). Codex cloud runs tasks in remote sandboxes you can start from the web, IDE, CLI, or GitHub, run several in parallel, and apply the resulting diff locally. On GitHub, comment @codex review for a PR review.

CI Safety

  • Use workspace-write + --ask-for-approval never
  • Pass the API key as a CI secret
  • Capture output with --output-last-message
  • Avoid --yolo outside disposable runners

Non-Interactive and Cloud Commands

codex exec "update the README install section"          # final message → stdout
codex exec --full-auto "fix failing unit tests"          # sandboxed, no prompts
codex exec --json "list TODOs" > events.jsonl            # JSON Lines event stream
codex exec --output-last-message out.md "summarize the diff"
git diff | codex exec "write a commit message for this"  # stdin as context
codex exec resume --last "now add tests"                 # continue last exec session

codex review                      # review uncommitted changes / branch diff
codex cloud                       # browse / launch cloud tasks from terminal
codex apply <task-id>             # apply a cloud task's diff locally

# GitHub PR comment:
#   @codex review               → Codex posts a code review
#   @codex fix the CI failure   → starts a cloud task

⚠ Common Mistakes

  • Using danger-full-access in CI because a test needed network; enable network access narrowly instead
  • Parsing human-readable output in scripts instead of --json / --output-last-message
  • Applying cloud diffs without reviewing them
  • No timeout on CI jobs that run codex exec

✓ Tips & Best Practices

  • Use profiles (--profile ci) to lock CI settings
  • Run cloud tasks in parallel for independent tickets
  • Use codex review as a pre-PR check in CI
  • Keep AGENTS.md test commands accurate; cloud tasks rely on them
