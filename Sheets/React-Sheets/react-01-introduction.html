What React Is

React is a JavaScript library for building user interfaces out of components: functions that take data (props and state) and return a description of the UI. You describe what the screen should look like for the current data, and React works out how to update the DOM when the data changes. Data flows one way, from parent to child, and changes travel back up through callbacks.

Notes

  • react holds components and hooks; react-dom renders them to the browser DOM
  • React is a library, not a framework: routing, data loading and builds come from other tools
  • Frameworks (Next.js, React Router framework mode) add routing, server rendering and bundling
  • A re-render means calling your component again; React then commits only the DOM changes

♿ Accessibility

  • React outputs ordinary HTML, so accessibility depends on the elements and attributes you render
  • Prefer native elements (button, a, label) over clickable divs; React doesn't add roles for you

Version Notes

  • Current release: React 19.3 (September 2026); no React 20 has been announced
  • React 18 added concurrent rendering; React 19 added Actions, use(), ref as a prop and metadata tags
  • Keep react and react-dom on the same version

Code Explained

Counter is a component: a function whose name starts with a capital letter and returns JSX
label arrives as a prop from the parent; props are read-only
useState gives each Counter its own count; the two counters are independent
Clicking calls setCount, which schedules a re-render with the new value
React compares the new output with the old and updates only the changed text node

UI as a Function of State

import { useState } from 'react';

// A component: data in, UI out
function Counter({ label }) {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      {label}: {count}
    </button>
  );
}

// Composing components into a tree
export default function App() {
  return (
    <main>
      <h1>Scoreboard</h1>
      <Counter label="Home" />
      <Counter label="Away" />
    </main>
  );
}

// Mental model:
//   UI = f(props, state)
//   event -> setState -> re-render -> commit DOM diff

Core Ideas

⚠ Common Mistakes

  • Manipulating the DOM directly (document.querySelector) instead of changing state
  • Treating React as a full framework and expecting built-in routing or data fetching
  • Mixing major versions of react and react-dom

✓ Tips & Best Practices

  • Think in terms of data: what state exists, and what UI follows from it
  • Start new apps with Vite or a framework, not a hand-rolled setup
  • Read react.dev's Thinking in React before building your first app

Quick Summary

  • Components are functions of props and state
  • Data flows down; events flow up
  • React diffs and commits DOM changes for you
  • react + react-dom work together
