Environment Variables

import.meta.env · VITE_ prefix · .env files · modes · no secrets in the client · typing env

Configuration at Build Time

Vite loads variables from .env files and exposes those prefixed with VITE_ on import.meta.env. Values are inlined into the bundle at build time, so anything you expose is public: never put secrets in client env vars. Vite picks files by mode (development for dev, production for build), and built-ins like import.meta.env.MODE, DEV and PROD are always available.

Notes

  • Load order: .env → .env.local → .env.[mode] → .env.[mode].local (later wins)
  • *.local files are for machine-specific values and should be gitignored
  • Changing .env requires restarting the dev server
  • Type custom variables in src/vite-env.d.ts with ImportMetaEnv

♿ Accessibility

  • Gate dev-only tools (mock APIs, debug overlays) behind import.meta.env.DEV so they never ship to users

Version Notes

  • Next.js uses NEXT_PUBLIC_ and React Router framework uses server-side process.env; prefixes differ by tool
  • CRA's REACT_APP_ prefix doesn't work in Vite

Code Explained

Only VITE_-prefixed variables reach client code
.env.production overrides .env during vite build
DB_PASSWORD stays out of the bundle because it lacks the prefix
import.meta.env.DEV starts mock APIs in dev; the branch is removed from production builds
ImportMetaEnv types the variables for autocomplete

.env Files and import.meta.env

# .env  (committed: safe defaults)
VITE_APP_NAME=Acme
VITE_API_URL=http://localhost:3000

# .env.production
VITE_API_URL=https://api.acme.com

# .env.local  (gitignored)
VITE_MAPS_KEY=pk_test_123          # public key, still visible!
DB_PASSWORD=secret                 # not exposed (no VITE_ prefix)

// src/api.ts
const base = import.meta.env.VITE_API_URL;
export const getUsers = () => fetch(`${base}/users`);

if (import.meta.env.DEV) {
  const { worker } = await import('./mocks/browser');
  await worker.start();              // MSW only in dev
}

console.log(import.meta.env.MODE);   // 'development' | 'production'

// src/vite-env.d.ts
/// <reference types="vite/client" />
interface ImportMetaEnv {
  readonly VITE_APP_NAME: string;
  readonly VITE_API_URL: string;
}
interface ImportMeta { readonly env: ImportMetaEnv; }

# custom mode
npx vite build --mode staging      # loads .env.staging

⚠ Common Mistakes

  • Putting secret keys in VITE_ variables
  • Using process.env.X in Vite client code
  • Committing .env.local

✓ Tips & Best Practices

  • Validate env vars at startup with Zod
  • Keep a .env.example with every key and dummy values
  • Proxy API calls through your server when a key must stay secret

Quick Summary

  • VITE_ prefix → import.meta.env
  • Inlined at build: public
  • Mode picks .env.[mode]
  • Type with ImportMetaEnv
