Finding and Fixing Slow Renders

Measure before optimizing. The DevTools Profiler records commits and shows which components rendered, why, and how long each took. The <Profiler> component logs timing from code. For long lists, the usual fix is virtualization: render only the rows in view with TanStack Virtual or react-window, or let the browser skip off-screen work with CSS content-visibility: auto.

Notes

  • Profile production builds; development React is much slower
  • Look for components that render often and take long
  • Virtualization keeps DOM size constant regardless of list length
  • content-visibility: auto with contain-intrinsic-size skips rendering off-screen sections

♿ Accessibility

  • Virtualized lists remove off-screen rows from the DOM; set aria-rowcount/aria-setsize and aria-posinset so screen readers know the full size
  • Browser find-in-page can't see virtualized rows; offer search

Version Notes

  • <Profiler> API is stable and unchanged in React 19
  • React 19.2 adds React tracks to the Chrome Performance panel

Code Explained

onRender warns when a commit takes longer than a frame
useVirtualizer calculates which rows are visible
Only visible rows plus overscan are in the DOM
aria-setsize/aria-posinset report the full list size
content-visibility lets the browser skip off-screen layout and paint

Profiler and Virtualization

import { Profiler, useRef } from 'react';
import { useVirtualizer } from '@tanstack/react-virtual';

function onRender(id, phase, actualDuration, baseDuration) {
  if (actualDuration > 16) {
    console.warn(`${id} ${phase}: ${actualDuration.toFixed(1)}ms`);
  }
}

<Profiler id="Inbox" onRender={onRender}>
  <Inbox />
</Profiler>

function BigList({ rows }) {
  const parentRef = useRef(null);
  const v = useVirtualizer({
    count: rows.length,
    getScrollElement: () => parentRef.current,
    estimateSize: () => 36,
    overscan: 5,
  });

  return (
    <div ref={parentRef} style={{ height: 400, overflow: 'auto' }}>
      <ul role="list"
        style={{ height: v.getTotalSize(), position: 'relative' }}>
        {v.getVirtualItems().map((item) => (
          <li key={item.key}
            aria-setsize={rows.length}
            aria-posinset={item.index + 1}
            style={{ position: 'absolute', top: 0, width: '100%',
              transform: `translateY(${item.start}px)` }}>
            {rows[item.index].name}
          </li>
        ))}
      </ul>
    </div>
  );
}

/* CSS alternative for long pages */
.feed-item { content-visibility: auto;
  contain-intrinsic-size: auto 120px; }

⚠ Common Mistakes

  • Optimizing based on development-mode timings
  • Virtualizing short lists and adding complexity
  • Rendering 10,000 rows and blaming React

✓ Tips & Best Practices

  • Start with the Profiler's Ranked view
  • Virtualize lists over a few hundred rows
  • Combine virtualization with memo on row components

Quick Summary

  • Measure with Profiler first
  • <Profiler onRender> in code
  • Virtualize long lists
  • content-visibility for long pages
