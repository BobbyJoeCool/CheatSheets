Server Components

Components That Stay on the Server

Server Components run only on the server (at request or build time). They can be async, read databases and files directly, and use secrets, and their code never ships to the browser. Client Components, marked with 'use client' at the top of a file, run on both server (for HTML) and client, and can use state, effects and event handlers. Server Components can render Client Components and pass them serializable props.

Notes

  • In RSC frameworks, components are Server Components by default
  • 'use client' marks a boundary: that module and everything it imports become client code
  • Server Components can't use useState, useEffect, context providers or browser APIs
  • Pass Server Components into Client Components as children or other JSX props

♿ Accessibility

  • Server-rendered markup should be complete and semantic; interactivity added on the client should not change roles or structure

Version Notes

  • Server Components are stable in React 19 and require a framework or bundler integration (Next.js App Router, React Router RSC, Parcel, Vite plugin)
  • React 19.3: <Context> can be rendered in Server Components

Server and Client Together

// app/products/page.tsx  (Server Component)
import { db } from '@/lib/db';
import 'server-only';
import AddToCart from './AddToCart';
import Collapsible from './Collapsible';

export default async function ProductsPage() {
  const products = await db.product.findMany();   // direct DB access
  return (
    <ul>
      {products.map((p) => (
        <li key={p.id}>
          {p.name} ${p.price}
          <AddToCart productId={p.id} />     {/* client island */}
          <Collapsible title="Details">
            <ProductDetails id={p.id} />      {/* server, as children */}
          </Collapsible>
        </li>
      ))}
    </ul>
  );
}

// app/products/AddToCart.tsx  (Client Component)
'use client';
import { useState } from 'react';

export default function AddToCart({ productId }: { productId: string }) {
  const [added, setAdded] = useState(false);
  return (
    <button onClick={() => setAdded(true)} aria-pressed={added}>
      {added ? 'Added' : 'Add to cart'}
    </button>
  );
}

⚠ Common Mistakes

  • Adding 'use client' to every file and losing the benefits
  • Importing a Server Component into a Client Component (it becomes client code)
  • Leaking secrets by passing whole DB rows as props

✓ Tips & Best Practices

  • Push 'use client' down to the smallest interactive leaves
  • Pass server-rendered content into client wrappers as children
  • Use server-only and client-only packages to enforce boundaries

Quick Summary

  • Server by default, 'use client' opts in
  • Server: async, DB, no JS shipped
  • Client: state, effects, events
  • Serializable props across the boundary
