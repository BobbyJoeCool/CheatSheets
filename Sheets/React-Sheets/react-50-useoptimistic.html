useOptimistic

optimistic state · update function · automatic rollback · inside actions · pending markers

Show the Result Early

useOptimistic(state, updateFn) shows a temporary value while an async Action is running. You call addOptimistic(input) at the start of the action; React renders the optimistic value immediately, and when the action finishes it switches back to the real state (which by then includes the server result). If the action fails, the optimistic value simply disappears.

Notes

  • updateFn(currentState, optimisticValue) returns the optimistic state
  • Call addOptimistic inside an Action or startTransition
  • The real state must be updated by the action for the item to stay
  • Mark optimistic items (sending: true) so users can see they're pending

♿ Accessibility

  • Mark pending items with text such as Sending…, not only reduced opacity
  • If the action fails, announce the failure; silently removing the item is confusing

Version Notes

  • useOptimistic is new in React 19
  • TanStack Query offers its own optimistic update pattern (sheet 78)

Code Explained

optimistic equals messages except while an action is running
addOptimistic(text) runs the update function and renders right away
When sendAction finishes, React drops optimistic state and shows messages
On failure, the real state was never updated, so the temp message disappears
sending: true lets the UI label the pending item

Optimistic Messages

import { useOptimistic, useState } from 'react';

function Thread() {
  const [messages, setMessages] = useState([
    { id: 1, text: 'Hi!', sending: false },
  ]);

  const [optimistic, addOptimistic] = useOptimistic(
    messages,
    (state, text) => [
      ...state,
      { id: `temp-${state.length}`, text, sending: true },
    ],
  );

  async function sendAction(formData) {
    const text = formData.get('message');
    addOptimistic(text);                 // shows instantly
    try {
      const saved = await api.send(text);
      setMessages((m) => [...m, saved]); // real state
    } catch {
      toast('Message failed to send');   // optimistic item vanishes
    }
  }

  return (
    <>
      <ul>
        {optimistic.map((m) => (
          <li key={m.id}>
            {m.text} {m.sending && <small>(Sending…)</small>}
          </li>
        ))}
      </ul>
      <form action={sendAction}>
        <input name="message" required />
        <button>Send</button>
      </form>
    </>
  );
}

⚠ Common Mistakes

  • Calling addOptimistic outside an action or transition
  • Forgetting to update the real state, so the item vanishes on success
  • Hiding failures instead of telling the user

✓ Tips & Best Practices

  • Generate stable temp IDs and replace them with server IDs
  • Keep optimistic logic pure and quick
  • Use for low-risk actions; confirm destructive ones first

Quick Summary

  • Temporary state during an action
  • addOptimistic(v) at the start
  • Reverts to real state when done
  • Label pending items
