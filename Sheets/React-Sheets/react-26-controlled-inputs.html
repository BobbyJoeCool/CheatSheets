Sheet 26

Controlled Inputs

value + onChange · checked · <select> · multiple select · <textarea> · number inputs as strings

React Owns the Value

A controlled input gets its value from state and reports every change through onChange. React state becomes the single source of truth, so you can validate, format or disable as the user types. Text inputs, textareas and selects use value; checkboxes and radios use checked. Passing value without onChange makes the field read-only.

Notes

  • e.target.value is always a string, even for type="number"
  • <textarea value> replaces the HTML text-content form
  • <select value> replaces selected on options; multiple takes an array
  • Switching between undefined and a defined value triggers a controlled/uncontrolled warning

♿ Accessibility

  • Every input needs a <label>; htmlFor must match the input's id
  • Don't reformat input while the user types in a way that moves the caret

Version Notes

  • Controlled inputs work the same in React 19
  • For simple submit-only forms, React 19 Actions (sheet 28) can replace controlled state

Code Explained

One update handler serves many fields by reading name
[name]: … is a computed key that sets the matching field
Checkboxes read checked; everything else reads value
<select value> marks the matching option as selected
selectedOptions collects all chosen values for a multi-select

Controlled Fields

function Signup() {
  const [form, setForm] = useState({
    name: '', bio: '', plan: 'free', agree: false, tags: [],
  });

  function update(e) {
    const { name, value, type, checked } = e.target;
    setForm((f) => ({
      ...f, [name]: type === 'checkbox' ? checked : value,
    }));
  }

  return (
    <form>
      <label htmlFor="name">Name</label>
      <input id="name" name="name"
        value={form.name} onChange={update} />

      <textarea name="bio" value={form.bio} onChange={update} />

      <select name="plan" value={form.plan} onChange={update}>
        <option value="free">Free</option>
        <option value="pro">Pro</option>
      </select>

      <label>
        <input type="checkbox" name="agree"
          checked={form.agree} onChange={update} />
        I agree
      </label>

      <select multiple value={form.tags} onChange={(e) =>
        setForm({ ...form, tags: [...e.target.selectedOptions]
          .map((o) => o.value) })}>
        <option>react</option><option>css</option>
      </select>
    </form>
  );
}

⚠ Common Mistakes

  • value without onChange (field won't change)
  • Initializing value as undefined then setting a string
  • Storing numbers and losing the user's partially typed 1. input

✓ Tips & Best Practices

  • Use name attributes so one handler covers the form
  • Use defaultValue when you don't need the value until submit
  • Use a form library (sheet 30) for large forms

Quick Summary

  • value/checked + onChange
  • State is the source of truth
  • Inputs give strings
  • File inputs are never controlled
