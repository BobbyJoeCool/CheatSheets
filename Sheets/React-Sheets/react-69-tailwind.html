Utility Classes in JSX

Tailwind CSS styles elements with small utility classes (flex, p-4, text-sm) written directly in className. Tailwind v4 is configured in CSS: install the Vite plugin, add @import "tailwindcss";, and define design tokens with @theme. For variants and conditional classes, combine clsx with tailwind-merge in a cn() helper, and use cva to define component variants.

Notes

  • Tailwind scans your source files for class names; build them as complete strings
  • tailwind-merge resolves conflicts: cn('p-2', 'p-4') → 'p-4'
  • dark:, hover:, focus-visible:, md: are variants
  • See the CSS Systems set for Tailwind's full utility reference

♿ Accessibility

  • Use focus-visible: utilities so every interactive element has a visible focus style
  • sr-only hides text visually but keeps it for screen readers
  • motion-reduce: variants disable animation for users who ask

Version Notes

  • Tailwind v4 (2025) uses CSS-first config (@theme) and the @tailwindcss/vite plugin; tailwind.config.js is optional
  • shadcn/ui and many component kits use the cn() + cva pattern

Code Explained

The Vite plugin replaces PostCSS setup in Tailwind v4
@theme creates bg-brand, text-brand and similar utilities from the token
cn() merges classes and lets callers override with className
cva maps intent and size props to class strings
sr-only adds context for screen readers without changing the visible label

Tailwind v4 + cn() + cva

// vite.config.ts
import tailwindcss from '@tailwindcss/vite';
export default defineConfig({ plugins: [react(), tailwindcss()] });

/* src/index.css */
@import "tailwindcss";
@theme {
  --color-brand: oklch(0.62 0.19 255);
}

// lib/cn.ts
import { clsx } from 'clsx';
import { twMerge } from 'tailwind-merge';
export const cn = (...inputs) => twMerge(clsx(inputs));

// Button.tsx
import { cva } from 'class-variance-authority';

const button = cva(
  'inline-flex items-center rounded-md font-medium ' +
  'focus-visible:outline-2 focus-visible:outline-brand',
  {
    variants: {
      intent: {
        primary: 'bg-brand text-white hover:bg-brand/90',
        ghost: 'bg-transparent hover:bg-gray-100',
      },
      size: { sm: 'h-8 px-3 text-sm', md: 'h-10 px-4' },
    },
    defaultVariants: { intent: 'primary', size: 'md' },
  },
);

export function Button({ intent, size, className, ...props }) {
  return <button className={cn(button({ intent, size }),
    className)} {...props} />;
}

<Button intent="ghost" className="w-full dark:text-white">
  Cancel <span className="sr-only">editing profile</span>
</Button>

⚠ Common Mistakes

  • Building class names dynamically so Tailwind can't detect them
  • Concatenating conflicting classes without tailwind-merge
  • Removing focus outlines (outline-none) without a replacement

✓ Tips & Best Practices

  • Extract components, not @apply rules, when class lists repeat
  • Use the Prettier Tailwind plugin to sort classes
  • Use arbitrary values sparingly: w-[37px]
