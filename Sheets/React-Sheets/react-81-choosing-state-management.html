Choosing State Management

local vs global · server vs client state · URL state · context vs store · decision table

Picking the Right Home

Before adding a library, sort your state by kind. Local UI state (open/closed, input text) belongs in useState. Server state (data from an API) belongs in a data library such as TanStack Query. URL state (filters, pages, selected tab) belongs in the router. Form state belongs in the form or a form library. Only what's left, truly global client state shared by distant components, needs context or a store.

Notes

  • Most global state problems are really server-state caching problems
  • Context is fine for values that change rarely (theme, user, locale)
  • Stores (Zustand, Redux, Jotai) add selectors so components re-render only for what they read
  • You can combine: TanStack Query for data, Zustand for UI preferences

♿ Accessibility

  • Keep user preferences such as reduced motion, font size and high contrast in persisted global state so every screen honors them

Version Notes

  • React 19 Actions and useOptimistic reduce the need for client stores around forms
  • Redux Toolkit 2, Zustand 5 and Jotai 2 are the current majors

Where Each Piece Lives

// Local UI state
const [isOpen, setIsOpen] = useState(false);

// Server state
const { data: orders } = useQuery({
  queryKey: ['orders', page], queryFn: () => getOrders(page),
});

// URL state
const [params, setParams] = useSearchParams();
const page = Number(params.get('page') ?? 1);

// Form state
<form action={submitOrder}>…</form>

// Rarely-changing global: context
<ThemeContext value={theme}>…</ThemeContext>

// Frequently-changing global client state: store
const useCart = create((set) => ({
  items: [],
  add: (item) => set((s) => ({ items: [...s.items, item] })),
}));
const count = useCart((s) => s.items.length);

// Decision order:
//  1. Can it be derived?            -> compute it
//  2. Used by one component?        -> useState
//  3. From the server?              -> TanStack Query / loader
//  4. Should survive refresh/share? -> URL
//  5. Shared, changes rarely?       -> context
//  6. Shared, changes often?        -> store

⚠ Common Mistakes

  • Putting API responses in Redux and hand-writing caching
  • Global stores for state only one component uses
  • Duplicating URL state in a store

✓ Tips & Best Practices

  • Start with built-in tools; add a store when you feel the pain
  • Keep stores small and split by domain
  • Write a short state map for each feature

Quick Summary

  • Classify state first
  • Server state → data library
  • URL state → router
  • Store only for global client state
