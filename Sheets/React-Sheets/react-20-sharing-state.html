Sharing State Between Components

lifting state up · single source of truth · controlled vs uncontrolled components · prop drilling · inverse data flow

Lifting State Up

When two components need the same changing data, move the state to their closest common parent and pass it down as props, along with callbacks to change it. The parent becomes the single source of truth. A component whose important values come from props is controlled by its parent; one that keeps them in local state is uncontrolled. Lifting too high causes prop drilling through layers that don't use the data.

Notes

  • Data flows down as props; changes flow up through callback props
  • Name callbacks after what happened: onChange, onSelect, onToggle
  • Components can support both modes: value + onChange, or defaultValue
  • Fix deep prop drilling with composition first, then context

♿ Accessibility

  • Lifted state keeps related widgets (accordion panels, radio groups) consistent, so only one reports aria-expanded="true" at a time

Version Notes

  • The pattern is unchanged; React 19 adds no new API for sharing local state

Code Explained

openIndex lives in Accordion, the common parent of both panels
Each Panel receives isOpen instead of owning it
onShow sends the request back up; the parent decides
Only one panel can be open because there is one source of truth
The heading-wrapped button follows the WAI-ARIA accordion pattern

Accordion with Lifted State

function Accordion() {
  const [openIndex, setOpenIndex] = useState(0);

  return (
    <>
      <Panel
        title="About"
        isOpen={openIndex === 0}
        onShow={() => setOpenIndex(0)}
      >
        Founded in 2010.
      </Panel>
      <Panel
        title="Contact"
        isOpen={openIndex === 1}
        onShow={() => setOpenIndex(1)}
      >
        hello@example.com
      </Panel>
    </>
  );
}

// Controlled: state lives in the parent
function Panel({ title, isOpen, onShow, children }) {
  return (
    <section>
      <h3>
        <button aria-expanded={isOpen} onClick={onShow}>
          {title}
        </button>
      </h3>
      {isOpen && <div>{children}</div>}
    </section>
  );
}

⚠ Common Mistakes

  • Keeping copies of the same state in sibling components
  • Lifting state to the app root when only two siblings need it
  • Passing the setter itself instead of an intent-named callback

✓ Tips & Best Practices

  • Lift only as high as the closest common parent
  • Pass JSX as children to skip intermediate layers
  • Switch to context when the same prop passes through three or more layers that don't use it

Quick Summary

  • Shared state → common parent
  • Value down, callback up
  • Single source of truth
  • Watch for prop drilling
