Async Logic and RTK Query

createAsyncThunk wraps an async function and dispatches pending, fulfilled and rejected actions that slices handle in extraReducers. For API data, RTK Query is usually better: createApi defines endpoints, generates hooks like useGetPostsQuery, and handles caching, deduplication and refetching. Tags connect queries and mutations so writes invalidate the right reads.

Notes

  • thunkAPI.rejectWithValue(x) sends a custom error payload
  • RTK Query adds its reducer and middleware to the store
  • providesTags labels cached data; invalidatesTags refetches it after mutations
  • Query hooks return data, isLoading, isFetching, error and refetch

♿ Accessibility

  • Use isLoading and isError to render accessible status messages, as with any data hook

Version Notes

  • RTK Query ships inside @reduxjs/toolkit (@reduxjs/toolkit/query/react)
  • RTK 2: extraReducers uses only the builder callback

Code Explained

The thunk dispatches user/fetch/pending, then fulfilled or rejected
rejectWithValue puts the HTTP status in action.payload
extraReducers handles actions defined outside the slice
createApi generates useGetPostsQuery and useAddPostMutation
invalidatesTags: ['Post'] refetches getPosts after adding

createAsyncThunk and createApi

import { createAsyncThunk, createSlice } from '@reduxjs/toolkit';

export const fetchUser = createAsyncThunk('user/fetch',
  async (id: string, { rejectWithValue }) => {
    const res = await fetch(`/api/users/${id}`);
    if (!res.ok) return rejectWithValue(res.status);
    return (await res.json()) as User;
  });

const userSlice = createSlice({
  name: 'user',
  initialState: { data: null as User | null, status: 'idle' },
  reducers: {},
  extraReducers: (builder) => {
    builder
      .addCase(fetchUser.pending, (s) => { s.status = 'loading'; })
      .addCase(fetchUser.fulfilled, (s, a) => {
        s.status = 'idle'; s.data = a.payload; })
      .addCase(fetchUser.rejected, (s) => { s.status = 'failed'; });
  },
});

// RTK Query
import { createApi, fetchBaseQuery } from '@reduxjs/toolkit/query/react';

export const api = createApi({
  reducerPath: 'api',
  baseQuery: fetchBaseQuery({ baseUrl: '/api' }),
  tagTypes: ['Post'],
  endpoints: (build) => ({
    getPosts: build.query<Post[], void>({
      query: () => 'posts', providesTags: ['Post'] }),
    addPost: build.mutation<Post, Partial<Post>>({
      query: (body) => ({ url: 'posts', method: 'POST', body }),
      invalidatesTags: ['Post'] }),
  }),
});
export const { useGetPostsQuery, useAddPostMutation } = api;

// store: reducer: { [api.reducerPath]: api.reducer },
//   middleware: (gDM) => gDM().concat(api.middleware)

function Posts() {
  const { data = [], isLoading } = useGetPostsQuery();
  const [addPost, { isLoading: saving }] = useAddPostMutation();
}

⚠ Common Mistakes

  • Storing API data in slices and rebuilding caching by hand
  • Forgetting to add api.middleware to the store
  • Tags that don't match between providesTags and invalidatesTags

✓ Tips & Best Practices

  • Use RTK Query for server data, slices for client state
  • Use await dispatch(thunk()).unwrap() in handlers to catch errors
  • Generate endpoints from OpenAPI with @rtk-query/codegen-openapi

Quick Summary

  • createAsyncThunk → pending/fulfilled/rejected
  • Handle in extraReducers builder
  • createApi generates hooks
  • Tags invalidate cached queries
