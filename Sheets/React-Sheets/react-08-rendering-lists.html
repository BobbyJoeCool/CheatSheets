Sheet 08

Rendering Lists

map() · key · stable IDs · index as key · filter then map · keyed Fragment

Arrays Become Elements

To render a list, transform an array of data into an array of elements with map(). Each item needs a key: a string or number that is unique among its siblings and stays the same for that item across renders. React uses keys to match items between renders, so a stable key keeps each item's state and DOM attached to the right data when the list is sorted, filtered or edited.

Notes

  • Keys only need to be unique among siblings, not across the whole app
  • Use IDs from your data: database IDs, UUIDs, slugs
  • key is not passed to the component as a prop; pass the ID separately if needed
  • Array index keys are safe only for static lists that never reorder or change length

♿ Accessibility

  • Render lists with <ul>/<ol> and <li> so screen readers announce item counts
  • When filtering, announce the new result count in a live region

Version Notes

  • Unchanged; React 19 still warns when list items lack keys

Code Explained

filter() runs first, then map() turns each todo into an element
key={todo.id} goes on the outermost element returned from map()
id is passed again because components can't read key
<Fragment key> groups <dt> and <dd> without an extra wrapper
The short <> syntax can't take a key

Lists with Keys

const todos = [
  { id: 'a1', text: 'Write docs', done: true },
  { id: 'b2', text: 'Ship release', done: false },
];

function TodoList({ items }) {
  const pending = items.filter((t) => !t.done);

  return (
    <ul>
      {pending.map((todo) => (
        <TodoItem key={todo.id} id={todo.id} todo={todo} />
      ))}
    </ul>
  );
}

function TodoItem({ id, todo }) {
  return <li data-id={id}>{todo.text}</li>;
}

// Several elements per item: keyed Fragment
import { Fragment } from 'react';

function Glossary({ terms }) {
  return (
    <dl>
      {terms.map((t) => (
        <Fragment key={t.id}>
          <dt>{t.word}</dt>
          <dd>{t.meaning}</dd>
        </Fragment>
      ))}
    </dl>
  );
}

Key Choices

SourceVerdict
Database IDbest
crypto.randomUUID() at creationgood (store it)
Slug / unique namegood if stable
Array indexonly for static lists
Math.random() in rendernever: new key every render

⚠ Common Mistakes

  • Generating keys during render with Math.random() or Date.now()
  • Putting key on the inner element instead of the one returned by map()
  • Using index keys for editable or sortable lists

✓ Tips & Best Practices

  • Assign IDs when items are created, not when they are rendered
  • Extract the item into its own component once it has more than a line of JSX
  • Use a keyed Fragment when each item renders siblings

Quick Summary

  • items.map(i => <X key={i.id} />)
  • Keys: unique among siblings, stable
  • Index keys only for static lists
  • Keyed Fragment for multi-element items
