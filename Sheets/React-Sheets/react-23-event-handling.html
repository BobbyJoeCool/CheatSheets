Event Handling

onClick · passing handlers · handleX / onX naming · synthetic events · handler vs call · inline arrows

Responding to the User

Attach event handlers as props named onClick, onChange, onSubmit and so on. Pass a function, not the result of calling one: onClick={handleClick}, or an inline arrow when you need arguments. Handlers receive a synthetic event, a cross-browser wrapper with the same interface as the native event (e.target, e.preventDefault()) plus e.nativeEvent.

Notes

  • Define handlers inside the component so they can read props and state
  • Convention: handleX for the function, onX for the prop that receives it
  • Inline arrows (() => remove(id)) are fine; the React Compiler memoizes them
  • Custom components only get events you wire up: <Button onClick> must forward it

♿ Accessibility

  • Put onClick on a <button> or <a>, not a <div>; native elements give keyboard and screen-reader support for free
  • If you must use a non-native element, add role, tabIndex={0} and key handling

Version Notes

  • React 17+ attaches listeners to the root container instead of document
  • Event pooling was removed in React 17; events can be read asynchronously

Code Explained

Toolbar receives handlers as props and passes them to Button
The inline arrow lets you pass 'photo' as an argument
e.type and e.target work just like native events
handlePlay() with parentheses runs during render, not on click
A <div> can't be focused or activated with Enter/Space

Handlers and Callback Props

function Toolbar({ onPlay, onUpload }) {
  return (
    <div>
      <Button onClick={onPlay}>Play</Button>
      <Button onClick={() => onUpload('photo')}>Upload</Button>
    </div>
  );
}

function Button({ onClick, children }) {
  return <button onClick={onClick}>{children}</button>;
}

function App() {
  const [log, setLog] = useState([]);

  function handlePlay(e) {
    console.log(e.type, e.target.tagName);   // click BUTTON
    setLog((l) => [...l, 'play']);
  }

  return <Toolbar onPlay={handlePlay}
    onUpload={(kind) => setLog((l) => [...l, kind])} />;
}

// ✗ Calls immediately during render
<button onClick={handlePlay()}>Play</button>

// ✗ Clickable div: no keyboard, no role
<div onClick={handlePlay}>Play</div>

⚠ Common Mistakes

  • onClick={doThing()} instead of onClick={doThing}
  • Lowercase onclick (ignored with a warning)
  • Attaching click handlers to non-interactive elements

✓ Tips & Best Practices

  • Name props by meaning (onPlayMovie) rather than DOM event names when they represent app actions
  • Keep handler logic short; call named functions for real work
  • Use <button type="button"> inside forms to avoid accidental submits

Quick Summary

  • onEvent={fn}, not fn()
  • handleX → onX
  • Synthetic events mirror native
  • Buttons, not divs
