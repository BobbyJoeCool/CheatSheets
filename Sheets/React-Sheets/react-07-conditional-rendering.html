Sheet 07

Conditional Rendering

if + early return · ternary · && · the 0 pitfall · return null · element variables

Showing Different UI

React has no special conditional syntax: you use JavaScript. Return early with if, choose between two pieces of JSX with a ternary, or show something only when a condition is true with &&. Return null to render nothing. Watch the left side of &&: if it is the number 0, React renders 0.

Notes

  • cond && <X /> renders <X /> when cond is truthy, otherwise renders cond itself
  • false, null and undefined render nothing; 0 and NaN render as text
  • Element variables (let content = …) keep complex branches readable
  • Returning null still runs the component's hooks

♿ Accessibility

  • Hiding content by not rendering it also removes it from screen readers
  • Announce status changes (loading, errors) with a live region, not just a swapped element

Version Notes

  • Unchanged across React versions

Four Patterns

function Inbox({ user, messages, loading, error }) {
  // 1. Early return
  if (!user) return <SignIn />;
  if (error) return <p role="alert">{error.message}</p>;

  // 2. Element variable
  let body;
  if (loading) body = <Spinner />;
  else body = <MessageList items={messages} />;

  return (
    <section>
      {/* 3. Ternary */}
      <h2>{messages.length ? 'Inbox' : 'No mail'}</h2>

      {/* 4. && with a boolean on the left */}
      {messages.length > 0 && (
        <Badge count={messages.length} />
      )}

      {/* Bug: renders "0" when empty */}
      {/* {messages.length && <Badge />} */}

      {body}
    </section>
  );
}

⚠ Common Mistakes

  • {count && <X />} printing 0
  • Nesting ternaries three deep instead of using early returns
  • Calling hooks after an early return, which breaks the Rules of Hooks

✓ Tips & Best Practices

  • Coerce with !!value or a comparison before &&
  • Put all hooks at the top, then the early returns
  • Use a map object ({ idle: <A/>, done: <B/> }[status]) for status switches

Quick Summary

  • if + early return
  • Ternary for either/or
  • && with a boolean only
  • null = render nothing
