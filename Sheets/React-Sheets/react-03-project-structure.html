Sheet 03

Project Structure & Tooling

index.html · src/main.tsx · App.tsx · vite.config.ts · public/ · eslint-plugin-react-hooks · Prettier

What Vite Generates

A Vite React project is small: an index.html with a <div id="root">, a src/main.tsx entry that mounts the app, and an App.tsx root component. Static files that must keep their exact names go in public/; everything else is imported from src/ so Vite can bundle and fingerprint it. ESLint with eslint-plugin-react-hooks catches hook mistakes; Prettier handles formatting.

Notes

  • index.html sits at the project root and is the real entry point for Vite
  • Files in public/ are served at / as-is; imported assets get hashed file names
  • Group code by feature (features/cart/) once the app outgrows flat folders
  • Path aliases (@/components) need both vite.config.ts and tsconfig.json

♿ Accessibility

  • index.html holds <html lang="en">; change it for non-English apps
  • Enable eslint-plugin-jsx-a11y rules alongside the hooks plugin

Version Notes

  • Recent eslint-plugin-react-hooks releases include the React Compiler lint rules
  • Current Vite templates use flat ESLint config (eslint.config.js)

Code Explained

index.html loads /src/main.tsx with <script type="module">
@vitejs/plugin-react handles JSX, Fast Refresh and the React Compiler hook-in
The @ alias lets you write import x from '@/hooks/x'
public/favicon.svg is copied unchanged; src/assets files are fingerprinted
features/ keeps components, hooks and tests for one feature together

Project Layout

my-app/
├── index.html          # <div id="root"> + script tag
├── package.json
├── vite.config.ts
├── tsconfig.json
├── eslint.config.js
├── public/
│   └── favicon.svg     # served as /favicon.svg
└── src/
    ├── main.tsx        # createRoot(...).render(<App/>)
    ├── App.tsx         # root component
    ├── index.css       # global styles
    ├── assets/         # imported images, fonts
    ├── components/     # shared UI
    ├── features/       # feature folders
    └── hooks/          # custom hooks

// vite.config.ts
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [react()],
  resolve: { alias: { '@': '/src' } },
});

⚠ Common Mistakes

  • Putting imported images in public/ and losing cache-busting hashes
  • Adding an alias in Vite but not in tsconfig.json (or the reverse)
  • Turning off react-hooks/exhaustive-deps instead of fixing the dependency

✓ Tips & Best Practices

  • Keep one component per file, named after the component
  • Co-locate a component's styles and tests next to it
  • Run ESLint and Prettier on save so reviews skip style debates

Quick Summary

  • index.html → main.tsx → App.tsx
  • public/ = copied; src/ = bundled
  • Lint hooks with the official plugin
  • Organize by feature as you grow
