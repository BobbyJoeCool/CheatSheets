TanStack Query: Mutations & Cache

useMutation · invalidateQueries · setQueryData · optimistic updates · onSettled · mutation state

Changing Server Data

useMutation({ mutationFn }) runs create, update and delete requests. Call mutate(variables) (or await mutateAsync) to trigger it, and read isPending, isError and data. After a mutation succeeds, keep the cache correct by invalidating affected queries so they refetch, or by writing the new data directly with setQueryData. For instant feedback, apply an optimistic update and roll back on error.

Notes

  • invalidateQueries({ queryKey: ['todos'] }) matches all keys starting with ['todos']
  • Returning the invalidation promise from onSuccess/onSettled keeps the mutation pending until refetch completes
  • onMutate runs before the request; its return value is the context passed to onError
  • Simplest optimistic UI: render variables while isPending

♿ Accessibility

  • Disable or mark buttons while isPending, and announce success or failure

Version Notes

  • In v5, the value returned by onMutate arrives as the third argument of onError and onSettled
  • useMutationState reads pending mutations from anywhere

Code Explained

invalidateQueries marks every todos query stale and refetches active ones
add.variables shows the pending title as a faded item
cancelQueries stops in-flight fetches from overwriting the optimistic data
onMutate snapshots and updates the cache, returning the snapshot
onError restores it; onSettled refetches to sync with the server

Mutations and Cache Updates

import { useMutation, useQueryClient } from '@tanstack/react-query';

function AddTodo() {
  const queryClient = useQueryClient();
  const add = useMutation({
    mutationFn: (title) => api.post('/todos', { title }),
    onSuccess: () =>
      queryClient.invalidateQueries({ queryKey: ['todos'] }),
  });

  return (
    <form onSubmit={(e) => {
      e.preventDefault();
      add.mutate(new FormData(e.currentTarget).get('title'));
    }}>
      <input name="title" />
      <button disabled={add.isPending}>Add</button>
      {add.isError && <p role="alert">{add.error.message}</p>}
      {add.isPending && <li style={{ opacity: 0.5 }}>{add.variables}</li>}
    </form>
  );
}

// Optimistic update with rollback
const toggle = useMutation({
  mutationFn: (todo) => api.patch(`/todos/${todo.id}`,
    { done: !todo.done }),
  onMutate: async (todo) => {
    await queryClient.cancelQueries({ queryKey: ['todos'] });
    const previous = queryClient.getQueryData(['todos']);
    queryClient.setQueryData(['todos'], (old) => old.map((t) =>
      t.id === todo.id ? { ...t, done: !t.done } : t));
    return { previous };
  },
  onError: (err, todo, context) =>
    queryClient.setQueryData(['todos'], context.previous),
  onSettled: () =>
    queryClient.invalidateQueries({ queryKey: ['todos'] }),
});

⚠ Common Mistakes

  • Mutating cached arrays in place inside setQueryData
  • Forgetting to invalidate, so lists show stale data
  • Optimistic updates without cancelQueries (race with refetch)

✓ Tips & Best Practices

  • Prefer invalidation; use setQueryData when the response contains the new entity
  • Use variables-based optimistic UI for simple cases
  • Centralize mutations in custom hooks (useAddTodo)

Quick Summary

  • useMutation({ mutationFn })
  • Invalidate after success
  • setQueryData for direct writes
  • onMutate + rollback for optimistic UI
