vite build · dist/ · vite preview · static hosts · SPA fallback rewrites · base path

Shipping a Vite App

npm run build produces a static dist/ folder: an index.html plus hashed JS and CSS files. Any static host can serve it. Single-page apps need one server rule: rewrite unknown paths to index.html so client-side routes work on refresh. Hashed assets can be cached forever; index.html should not be cached. If the app lives in a subfolder, set Vite's base option.

Notes

  • npm run preview serves dist/ locally to test the real build
  • Asset file names include content hashes, so new deploys bust caches automatically
  • GitHub Pages serves from /<repo>/: set base: '/<repo>/'
  • SSR or framework apps need a Node, edge or serverless runtime instead of static hosting

♿ Accessibility

  • Test the production build with Lighthouse and axe; minification can't break semantics, but missing assets can break icon labels

Version Notes

  • Vercel, Netlify, Cloudflare Pages and GitHub Pages all host Vite builds
  • React Router framework mode and Next.js have their own adapters and build commands

Code Explained

vite build bundles, minifies and hashes everything into dist/
preview catches problems that only appear in production builds
base prefixes asset URLs when the app isn't at the domain root
Each host's rewrite rule sends deep links like /users/42 to index.html
Long-lived caching is safe for hashed files in /assets/

  build: { sourcemap: true },

# Netlify: public/_redirects

// Vercel: vercel.json
{ "rewrites": [{ "source": "/(.*)", "destination": "/" }] }

# Nginx
location / {
  try_files $uri /index.html;
}
location /assets/ {
  add_header Cache-Control "public, max-age=31536000, immutable";
}

# GitHub Pages (Actions) uploads dist/ as the Pages artifact
# Cloudflare Pages: build command "npm run build", output "dist"

⚠ Common Mistakes

  • 404s on refresh because the host has no SPA rewrite
  • Caching index.html, so users keep loading old asset names
  • Wrong base and blank pages on GitHub Pages

✓ Tips & Best Practices

  • Deploy previews per pull request (Vercel/Netlify/Cloudflare)
  • Upload source maps to your error tracker, not the public site
  • Check bundle size in CI and fail on large regressions

Quick Summary

  • build → static dist/
  • Rewrite routes to index.html
  • Cache hashed assets forever
  • Set base for subfolders
