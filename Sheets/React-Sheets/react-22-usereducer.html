Reducers for Complex Updates

useReducer moves update logic out of event handlers into a single reducer function: (state, action) => newState. Handlers dispatch actions that describe what happened; the reducer decides how state changes. This keeps related transitions in one place, makes them easy to test, and suits state where many fields change together.

Notes

  • Reducers must be pure: no fetches, timers or mutation
  • Actions are plain objects, usually { type: 'added', ...payload }
  • dispatch has a stable identity; pass it down freely
  • A third argument init lazily builds the initial state

♿ Accessibility

  • Centralized transitions make it easier to also update focus or announcement state in one place

Version Notes

  • Unchanged in React 19; pairs with context for app-wide state (sheet 40)
  • Immer's useImmerReducer lets reducers write draft-style updates

Code Explained

Each case returns a new array; nothing is mutated
The default throws so typos in action names fail loudly
The ID is generated in the handler, keeping the reducer pure
Handlers only describe events; the reducer owns the logic
init(arg) runs once to build the starting state

Todo Reducer

import { useReducer } from 'react';

function todosReducer(todos, action) {
  switch (action.type) {
    case 'added':
      return [...todos, { id: action.id, text: action.text,
        done: false }];
    case 'toggled':
      return todos.map((t) =>
        t.id === action.id ? { ...t, done: !t.done } : t);
    case 'deleted':
      return todos.filter((t) => t.id !== action.id);
    default:
      throw new Error(`Unknown action: ${action.type}`);
  }
}

function TodoApp() {
  const [todos, dispatch] = useReducer(todosReducer, []);

  function handleAdd(text) {
    dispatch({ type: 'added', id: crypto.randomUUID(), text });
  }

  return (
    <>
      <AddTodo onAdd={handleAdd} />
      <TodoList
        todos={todos}
        onToggle={(id) => dispatch({ type: 'toggled', id })}
        onDelete={(id) => dispatch({ type: 'deleted', id })}
      />
    </>
  );
}

// Lazy init: useReducer(reducer, arg, init)
const [s, d] = useReducer(reducer, userId, loadInitial);

useState vs useReducer

Independent simple valuesRelated fields

Less codeEasier to test

⚠ Common Mistakes

  • Mutating state inside the reducer
  • Generating IDs or reading Date.now() inside the reducer
  • Naming actions as commands (setX) instead of events (added)

✓ Tips & Best Practices

  • Unit-test reducers as plain functions
  • Use a TypeScript discriminated union for actions
  • Log action in the reducer while debugging

Quick Summary

  • (state, action) => next
  • dispatch({ type, ...payload })
  • Pure reducer, events not commands
  • Use for related, complex state
