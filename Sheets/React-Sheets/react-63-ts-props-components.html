Typing Components

In TypeScript, a component is a function whose props parameter has a type. Declare props with a type alias or interface, mark optional ones with ?, and give defaults in the destructuring pattern. Use React.ReactNode for anything renderable, such as children. To accept every attribute of a native element, extend ComponentProps<'button'> and spread the rest.

Notes

  • Files containing JSX use the .tsx extension
  • React.FC is optional and no longer adds implicit children; many teams skip it
  • PropsWithChildren<P> adds children?: ReactNode to P
  • Return type is inferred; annotate as React.JSX.Element only if you need to

♿ Accessibility

  • Make accessibility props required in the type (e.g. alt: string, label: string) so callers can't omit them
  • Including ComponentProps<'button'> lets callers pass aria-* attributes with full type checking

Version Notes

  • React 19 types (@types/react 19) removed the global JSX namespace; use React.JSX
  • propTypes and defaultProps for functions are ignored in React 19; TypeScript replaces them

Code Explained

Props Types

import type { ComponentProps, ReactNode } from 'react';

type CardProps = {
  title: string;
  subtitle?: string;            // optional
  variant?: 'plain' | 'outlined';
  children: ReactNode;
  footer?: ReactNode;
};

export function Card({
  title, subtitle, variant = 'plain', children, footer,
}: CardProps) {
  return (
    <section className={`card ${variant}`}>
      <h2>{title}</h2>
      {subtitle && <p>{subtitle}</p>}
      {children}
      {footer}
    </section>
  );
}

// Extend native element props
type ButtonProps = ComponentProps<'button'> & {
  tone?: 'primary' | 'danger';
};

export function Button({ tone = 'primary', className, ...rest }:
  ButtonProps) {
  return <button className={`btn ${tone} ${className ?? ''}`}
    {...rest} />;
}

<Button tone="danger" type="submit" aria-describedby="hint">
  Delete
</Button>

// Optional FC style
const Badge: React.FC<{ count: number }> = ({ count }) =>
  <span>{count}</span>;

⚠ Common Mistakes

  • Typing children as JSX.Element and rejecting strings
  • Using the global JSX namespace removed in React 19 types
  • Forgetting to spread ...rest after extending native props

✓ Tips & Best Practices

  • Export props types (export type CardProps) for reuse
  • Prefer unions of literals over loose string
  • Use ComponentProps<typeof X> to wrap third-party components
