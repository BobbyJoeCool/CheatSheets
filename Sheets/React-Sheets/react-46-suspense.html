Suspense

<Suspense> · fallback · nested boundaries · reveal order · Suspense-enabled data · showing stale content

Declarative Loading States

<Suspense fallback={…}> shows a fallback while anything inside it is suspended: waiting for lazy-loaded code, a promise read with use(), or Suspense-enabled data from a framework or library. When everything is ready, React swaps in the content. Nest boundaries to reveal a page in stages, and place them where a loading state makes sense to the user.

Notes

  • Only Suspense-enabled sources trigger it: lazy, use(promise), framework loaders, useSuspenseQuery
  • Fetching in useEffect does not suspend
  • The nearest boundary above the suspending component catches it
  • Updates inside a transition keep showing old content instead of the fallback

♿ Accessibility

  • Give fallbacks accessible text (role="status", Loading results…), not only a spinner
  • Avoid many tiny boundaries that pop in one by one and shift focus targets

Version Notes

  • React 19 shows the fallback immediately and pre-warms siblings in the background
  • React 19.2 batches Suspense reveals during SSR streaming for smoother reveals
  • Suspense for data needs a framework or library; React has no built-in fetch cache for client components

Code Explained

The outer boundary covers the article; the inner one only covers comments
The article can appear while comments are still loading

Boundaries and Nesting

import { Suspense, lazy } from 'react';

const Comments = lazy(() => import('./Comments'));

export default function ArticlePage({ id }) {
  return (
    <Suspense fallback={<PageSkeleton />}>
      <Article id={id} />

      {/* Reveal comments separately */}
      <Suspense fallback={<p role="status">Loading comments…</p>}>
        <Comments articleId={id} />
      </Suspense>
    </Suspense>
  );
}

// Suspending sources:
//   lazy(() => import(...))
//   use(promise)
//   useSuspenseQuery(...)          (TanStack Query)
//   framework loaders / RSC data

// Keep old UI during navigation instead of fallback
function Tabs() {
  const [tab, setTab] = useState('home');
  const [isPending, startTransition] = useTransition();
  return (
    <>
      <button onClick={() => startTransition(() => setTab('posts'))}>
        Posts
      </button>
      <div style={{ opacity: isPending ? 0.6 : 1 }}>
        <Suspense fallback={<Spinner />}>
          <TabPanel tab={tab} />
        </Suspense>
      </div>
    </>
  );
}

⚠ Common Mistakes

  • Expecting effect-based fetching to show the Suspense fallback
  • Creating the promise inside the suspended component (refetches forever)
  • One boundary per item, causing layout jumps

✓ Tips & Best Practices

  • Design fallbacks the same size as the content to avoid shifts
  • Pair Suspense with an error boundary at the same level
  • Use transitions for navigation so users keep context

Quick Summary

  • <Suspense fallback> catches waits
  • Needs Suspense-enabled sources
  • Nest for staged reveal
  • Transitions keep old UI
