Sheet 10

Function Components

capitalized names · function vs arrow · default vs named export · returning JSX · one component per file · no nested definitions

Components Are Functions

A function component is a JavaScript function that returns JSX. Its name must start with a capital letter so JSX treats <Avatar /> as a component and <avatar /> as an HTML tag. Components are defined at the top level of a module and exported for use elsewhere. React calls the function on every render, so it should only compute and return UI.

Notes

  • Function declarations and arrow functions both work; pick one style per codebase
  • A file can export one default and any number of named exports
  • Return null to render nothing; returning undefined is allowed since React 18
  • Components can be as small as one element; split when a piece has its own purpose

♿ Accessibility

  • Give reusable components props for aria-label, id and aria-describedby so callers can label them
  • Forward unknown props (...rest) to the root element so ARIA attributes reach the DOM

Version Notes

  • Function components with hooks are the standard since React 16.8
  • React.FC is optional; most codebases type props directly instead

Code Explained

The default export is imported without braces and can be renamed
Named exports are imported in braces with their exact names
...rest collects props like onClick and spreads them onto <button>
Arrow components need parentheses to return JSX implicitly
A component defined inside another is recreated every render, so its state resets

Defining and Exporting

// Avatar.tsx: default export
export default function Avatar({ src, name }) {
  return <img className="avatar" src={src} alt={name} />;
}

// Buttons.tsx: named exports
export function PrimaryButton({ children, ...rest }) {
  return <button className="btn primary" {...rest}>
    {children}
  </button>;
}

export const GhostButton = ({ children, ...rest }) => (
  <button className="btn ghost" {...rest}>{children}</button>
);

// App.tsx
import Avatar from './Avatar';

⚠ Common Mistakes

  • Lowercase component names (<userCard />) rendering as unknown HTML tags
  • Defining a component inside another component's body
  • Forgetting to return the JSX from a block-bodied arrow function

✓ Tips & Best Practices

  • Default-export page-level components, name-export shared ones
  • Keep components small enough to read without scrolling
  • Accept and spread ...rest on design-system components

Quick Summary

  • Capitalized function returning JSX
  • Define at module top level
  • Default or named exports
  • Split by purpose, not by size
