Testing Setup

Vitest · jsdom · @testing-library/react · jest-dom matchers · setupFiles · test scripts

Vitest + Testing Library

Vitest is a fast, Vite-native test runner with a Jest-compatible API (describe, it, expect, vi). React Testing Library (RTL) renders components into a simulated DOM (jsdom or happy-dom) and queries them the way users find things: by role, label and text. jest-dom adds DOM matchers like toBeInTheDocument() and toBeDisabled(). A setup file wires them together.

Notes

  • Install: vitest, jsdom, @testing-library/react, @testing-library/dom, @testing-library/jest-dom, @testing-library/user-event
  • globals: true enables describe/it/expect without imports and lets RTL auto-cleanup
  • Test files: *.test.tsx next to the component
  • Jest works the same way with jest-environment-jsdom

♿ Accessibility

  • Querying by role and label means a test fails when an element loses its accessible name: your tests double as accessibility checks

Version Notes

  • RTL 16 requires @testing-library/dom as a peer dependency and supports React 19
  • Vitest browser mode can run tests in a real browser via Playwright

Code Explained

test in vite.config.ts reuses the app's Vite plugins and aliases
environment: 'jsdom' provides document and window
The setup file registers jest-dom matchers with Vitest's expect
render mounts the component; screen queries the whole document
getByRole('heading', { name }) finds the <h1> by its accessible name

Config, Setup, First Test

// vite.config.ts
/// <reference types="vitest/config" />
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [react()],
  test: {
    environment: 'jsdom',
    globals: true,
    setupFiles: './src/test/setup.ts',
    css: true,
  },
});

// src/test/setup.ts
import '@testing-library/jest-dom/vitest';

// package.json
// "test": "vitest", "test:run": "vitest run --coverage"

// src/components/Greeting.test.tsx
import { render, screen } from '@testing-library/react';
import Greeting from './Greeting';

describe('Greeting', () => {
  it('greets the user by name', () => {
    render(<Greeting name="Ada" />);
    expect(
      screen.getByRole('heading', { name: /hello, ada/i }),
    ).toBeInTheDocument();
  });

  it('shows a sign-in button when anonymous', () => {
    render(<Greeting />);
    expect(screen.getByRole('button', { name: 'Sign in' }))
      .toBeEnabled();
  });
});

⚠ Common Mistakes

  • Forgetting the setup file, so toBeInTheDocument is undefined
  • Testing implementation details (state values, class names)
  • Snapshot tests of entire pages that nobody reviews

✓ Tips & Best Practices

  • Test behavior users see: text, roles, enabled/disabled
  • Run vitest in watch mode while developing
  • Use Playwright for full end-to-end flows
