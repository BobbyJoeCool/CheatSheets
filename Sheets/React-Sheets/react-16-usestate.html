Sheet 16

useState

[value, setValue] · initial value · lazy initializer · re-render trigger · multiple state variables · per-instance state

Component Memory

useState gives a component a value that survives re-renders. It returns a pair: the current value and a setter. Calling the setter stores the new value and asks React to re-render the component. Each instance of a component gets its own state, so two <Counter />s count independently. Pass a function as the initial value (a lazy initializer) when computing it is expensive.

Notes

  • Name the pair [thing, setThing] by convention
  • The initial value is used only on the first render; later values come from React
  • Regular variables reset on every render and don't trigger updates
  • Use several useState calls for unrelated values

♿ Accessibility

  • When state toggles visibility, mirror it in ARIA: aria-expanded, aria-pressed, aria-checked

Version Notes

  • useState arrived in React 16.8 and is unchanged in React 19
  • The React Compiler doesn't change how state works

Code Explained

useState(0) sets count to 0 on the first render only
setCount(count + 1) stores a new value and schedules a re-render
aria-expanded={open} keeps assistive tech in sync with the toggle
useState(() => …) reads localStorage once instead of every render
Broken changes n, but nothing tells React to render again

useState Basics

import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);
  return (
    <button onClick={() => setCount(count + 1)}>
      Clicked {count} times
    </button>
  );
}

function Disclosure({ title, children }) {
  const [open, setOpen] = useState(false);
  return (
    <div>
      <button aria-expanded={open}
        onClick={() => setOpen(!open)}>
        {title}
      </button>
      {open && <div>{children}</div>}
    </div>
  );
}

// Lazy initializer: runs once
function Editor() {
  const [draft, setDraft] = useState(
    () => localStorage.getItem('draft') ?? ''
  );
  return <textarea value={draft}
    onChange={(e) => setDraft(e.target.value)} />;
}

// ✗ Regular variable: never updates the UI
function Broken() {
  let n = 0;
  return <button onClick={() => n++}>{n}</button>;
}

⚠ Common Mistakes

  • Calling useState inside a condition or loop
  • Writing useState(expensive()) so the work runs every render
  • Storing values in state that can be computed from other state

✓ Tips & Best Practices

  • Keep state minimal; derive everything else during render
  • Use the updater form when the next value depends on the current one
  • Reach for useReducer when several values change together
