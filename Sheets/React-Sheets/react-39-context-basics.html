Context Basics

Passing Data Deeply

Context lets a parent make a value available to every component below it without passing props through each level. Create a context with createContext(default), provide a value by rendering <MyContext value={…}> around a subtree, and read it with useContext(MyContext) (or use(MyContext)). A component reads the value from the nearest provider above it; with none, it gets the default.

Notes

  • Good fits: theme, current user, locale, router, a store or client instance
  • When the provided value changes, every component that reads it re-renders
  • Providers can be nested; inner ones override outer ones for their subtree
  • Export the context object or, better, a custom hook that reads it

♿ Accessibility

  • A locale or reduced-motion preference in context lets every component adapt text and animation consistently

Version Notes

  • React 19: render <ThemeContext value> directly; <ThemeContext.Provider> still works but will be deprecated
  • React 19: use(Context) can read context conditionally
  • React 19.3: <Context> can be rendered directly in Server Components

Code Explained

createContext('light') sets the default used with no provider
<ThemeContext value={theme}> provides the value to everything inside
Page doesn't pass theme; Button reads it directly
Toggling theme re-renders every component that reads the context
An inner provider overrides the value for its subtree

createContext, Provider, useContext

import { createContext, useContext, useState } from 'react';

export const ThemeContext = createContext('light');

export default function App() {
  const [theme, setTheme] = useState('dark');
  return (
    <ThemeContext value={theme}>
      <Page />
      <button onClick={() =>
        setTheme(theme === 'dark' ? 'light' : 'dark')}>
        Toggle theme
      </button>
    </ThemeContext>
  );
}

function Page() {
  return <Panel title="Welcome"><Button>Sign up</Button></Panel>;
}

function Button({ children }) {
  const theme = useContext(ThemeContext);
  return <button className={`btn-${theme}`}>{children}</button>;
}

// Nested override
<ThemeContext value="light">
  <Sidebar />   {/* always light */}
</ThemeContext>

// Legacy provider syntax
<ThemeContext.Provider value={theme}>…</ThemeContext.Provider>

Props vs Context

PropsContext
Explicit data flowImplicit, any depth
Easy to traceHarder to trace
Re-render only receiversRe-render all readers
Use by defaultUse for widely shared values

⚠ Common Mistakes

  • Reading context in the same component that renders its provider (it gets the outer value)
  • Using context for values only one or two levels down
  • Forgetting the provider and silently using the default

✓ Tips & Best Practices

  • Wrap useContext in a custom hook with a helpful error (sheet 40)
  • Default to null and throw when no provider is found
  • Try passing children before reaching for context

Quick Summary

  • createContext → <Ctx value> → useContext
  • Nearest provider wins
  • All readers re-render on change
  • .Provider is legacy in 19
