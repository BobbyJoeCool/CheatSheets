Form Validation

constraint validation · Zod schemas · safeParse · zodResolver · field errors · aria-invalid / aria-describedby

Validate Once, Everywhere

Start with native constraint validation (required, type, pattern, min) for free browser checks. For real rules, define a Zod schema once and use it everywhere: safeParse returns either typed data or a list of field errors. With React Hook Form, zodResolver plugs the schema straight into useForm. Always validate again on the server.

Notes

  • schema.safeParse(data) never throws; check result.success
  • z.infer<typeof schema> gives the TypeScript type for free
  • z.coerce.number() converts form strings to numbers
  • noValidate on <form> turns off browser bubbles when you render your own messages

♿ Accessibility

  • Set aria-invalid="true" on invalid fields and connect the message with aria-describedby
  • Show errors as text, not only red borders
  • Move focus to the first invalid field on submit

Version Notes

  • Zod 4 is current; z.email() and other top-level string formats are new in v4 (z.string().email() still works)
  • @hookform/resolvers/zod supports Zod 4

Code Explained

The schema is the single definition of what valid data looks like
z.coerce.number() turns the '17' string from FormData into 17
z.flattenError(...).fieldErrors maps each field to its messages
zodResolver runs the same schema inside React Hook Form
noValidate hides native bubbles so only your messages show

One Schema, Two Uses

import { z } from 'zod';
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';

const Signup = z.object({
  email: z.email('Enter a valid email'),
  age: z.coerce.number().int().min(13, 'Must be 13+'),
  password: z.string().min(8, 'At least 8 characters'),
});
type SignupData = z.infer<typeof Signup>;

// 1) With a React 19 action
async function signUp(prev, formData) {
  const result = Signup.safeParse(Object.fromEntries(formData));
  if (!result.success) {
    return { errors: z.flattenError(result.error).fieldErrors };
  }
  await api.signUp(result.data);
  return { errors: {} };
}

// 2) With React Hook Form
function SignupForm() {
  const { register, handleSubmit, formState: { errors } } =
    useForm<SignupData>({ resolver: zodResolver(Signup) });
  return (
    <form noValidate onSubmit={handleSubmit(api.signUp)}>
      <input {...register('email')}
        aria-invalid={!!errors.email}
        aria-describedby="email-err" />
      <p id="email-err">{errors.email?.message}</p>
    </form>
  );
}

⚠ Common Mistakes

  • Validating only on the client
  • Using parse (throws) where safeParse fits better
  • Showing all errors before the user has touched a field

✓ Tips & Best Practices

  • Share schemas between client and server code
  • Validate on blur, then on change once a field has an error
  • Keep messages specific: say what to fix

Quick Summary

  • Native constraints first
  • Zod schema = single source
  • safeParse → data or errors
  • zodResolver for RHF
