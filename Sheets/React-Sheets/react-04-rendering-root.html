Sheet 04

Rendering & the Root

createRoot · root.render · <StrictMode> · root.unmount · multiple roots · hydrateRoot · ReactDOM.render (removed)

Mounting the App

A React app starts by creating a root for a DOM node and rendering a component into it. createRoot comes from react-dom/client; root.render(<App />) draws the tree, and calling it again updates it. Wrap the app in <StrictMode> during development: it double-invokes renders and effects to expose impure code. For server-rendered HTML, use hydrateRoot instead so React attaches to existing markup.

Notes

  • Most apps call createRoot once; widgets embedded in other pages may create several roots
  • root.unmount() removes the tree and runs every cleanup
  • StrictMode checks run in development only and have no production cost
  • Root options include onCaughtError, onUncaughtError and identifierPrefix

♿ Accessibility

  • Mount into an element inside <body> so landmarks render in document order
  • Render a <main> landmark inside your root layout

Version Notes

  • ReactDOM.render and ReactDOM.hydrate were removed in React 19
  • createRoot arrived in React 18 and enables concurrent features
  • React 19 added root error callbacks (onCaughtError, onUncaughtError)

Code Explained

createRoot(container) takes over the DOM node; existing children are replaced
The ! tells TypeScript the element exists; check it in libraries
onUncaughtError reports errors no error boundary caught
<StrictMode> wraps the tree so every component gets development checks
hydrateRoot reuses server HTML instead of rebuilding it

main.tsx

import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';
import App from './App';
import './index.css';

const container = document.getElementById('root')!;
const root = createRoot(container, {
  onUncaughtError(error, info) {
    reportError(error, info.componentStack);
  },
});

root.render(
  <StrictMode>
    <App />
  </StrictMode>,
);

// Later: tear everything down
// root.unmount();

// ReactDOM.render(<App />, container);

Root APIs

APIUse
createRoot(el, opts?)Client-rendered app
root.render(node)Render or update the tree
root.unmount()Remove the tree, run cleanups
hydrateRoot(el, node)Attach to server HTML
createPortal(node, el)Render into another DOM node

CheckCatches

⚠ Common Mistakes

  • Calling createRoot twice on the same element
  • Removing StrictMode to silence double effects instead of adding cleanup
  • Using createRoot on server HTML and causing a full re-render flash

✓ Tips & Best Practices

  • Keep main.tsx tiny: providers belong in App or a Providers component
  • Wire root error callbacks to your error reporter early
  • Use portals for modals that must escape overflow: hidden parents

Quick Summary

  • createRoot(el).render(<App />)
  • hydrateRoot for SSR markup
  • StrictMode = dev-only checks
  • ReactDOM.render is gone in 19
