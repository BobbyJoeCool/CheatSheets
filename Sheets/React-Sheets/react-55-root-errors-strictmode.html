Root Error Handling & StrictMode

onCaughtError · onUncaughtError · onRecoverableError · StrictMode checks · console warnings · owner stacks

Errors at the Root and Dev Checks

React 19 lets you handle errors where the root is created. createRoot and hydrateRoot accept onCaughtError (an error boundary caught it), onUncaughtError (nothing caught it, so the tree unmounted) and onRecoverableError (React recovered automatically, e.g. after a hydration mismatch). In development, StrictMode double-runs renders, effects and ref callbacks to expose bugs, and owner stacks show which component rendered the one that failed.

Notes

  • Root callbacks receive (error, errorInfo) with componentStack
  • Uncaught errors unmount the entire root; boundaries prevent that
  • Recoverable errors include hydration mismatches that React fixed by client rendering
  • captureOwnerStack() returns the owner stack in development for custom logging

♿ Accessibility

  • When an uncaught error unmounts the app, render a minimal static message outside React so the page isn't blank

Version Notes

  • Root error callbacks are new in React 19
  • Owner stacks and captureOwnerStack shipped in React 19.1
  • React 19 reports errors once instead of logging and re-throwing

Code Explained

onCaughtError fires after a boundary handled the error
onUncaughtError is your last chance to report and show a static message
onRecoverableError often signals hydration problems worth fixing
StrictMode wraps the app to run development checks
captureOwnerStack is only available in development builds

Root Callbacks and StrictMode

import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';

const root = createRoot(document.getElementById('root'), {
  onCaughtError(error, info) {
    // a boundary rendered a fallback
    reporter.warn(error, { stack: info.componentStack });
  },
  onUncaughtError(error, info) {
    // no boundary: the tree is gone
    reporter.error(error, { stack: info.componentStack });
    document.getElementById('fatal').hidden = false;
  },
  onRecoverableError(error, info) {
    // e.g. hydration mismatch recovered by client render
    reporter.info(error, { cause: error.cause });
  },
});

root.render(
  <StrictMode>
    <App />
  </StrictMode>,
);

// Dev-only owner stack in custom logging
import { captureOwnerStack } from 'react';
if (process.env.NODE_ENV !== 'production') {
  console.log(captureOwnerStack());
}

// StrictMode in dev runs, on mount:
//   render x2, effect setup -> cleanup -> setup,
//   ref callback attach -> detach -> attach

⚠ Common Mistakes

  • Treating StrictMode double calls as a React bug
  • Ignoring recoverable hydration errors
  • Not reporting errors to a service in production

✓ Tips & Best Practices

  • Wire root callbacks to Sentry or a similar service
  • Fix the cause of each StrictMode symptom instead of guarding with flags
  • Keep a static #fatal message in index.html for uncaught errors

Quick Summary

  • onCaughtError / onUncaughtError
  • onRecoverableError for hydration
  • StrictMode double-runs in dev
  • Owner stacks show who rendered what
