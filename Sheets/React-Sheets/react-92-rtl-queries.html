Finding Elements Like a User

Testing Library queries come in three families. getBy* returns the element or throws, for things that should be there. queryBy* returns null instead of throwing, for asserting absence. findBy* returns a promise and waits, for things that appear asynchronously. Prefer queries in priority order: by role (with name), by label, by placeholder, by text, and only last by data-testid.

Notes

  • getAllBy* / queryAllBy* / findAllBy* return arrays
  • { name: /save/i } matches the accessible name with a regex
  • within(element) scopes queries to part of the page
  • screen.debug() prints the current DOM; screen.logTestingPlaygroundURL() suggests queries

♿ Accessibility

  • If getByRole can't find your button, assistive tech probably can't either: fix the markup, not the query

Version Notes

  • Query APIs are stable across RTL 14–16
  • *ByRole supports level for headings and checked, pressed, expanded, selected filters

Code Explained

getByRole with name and level pins down exactly one heading
checked: false filters checkboxes by state
queryByRole returns null, so .not.toBeInTheDocument() passes
findByText waits (default 1000 ms) for the text to appear
within(reviews) searches only inside the Reviews region

Queries in Priority Order

import { render, screen, within } from '@testing-library/react';

test('product card', async () => {
  render(<ProductPage id="42" />);

  // 1. Role + name (best)
  screen.getByRole('heading', { name: 'Blue Mug', level: 1 });
  screen.getByRole('button', { name: /add to cart/i });
  screen.getByRole('checkbox', { name: 'Gift wrap', checked: false });

  // 2. Label
  screen.getByLabelText('Quantity');

  // 3. Placeholder / text / display value
  screen.getByPlaceholderText('Promo code');
  screen.getByText(/free shipping/i);
  screen.getByDisplayValue('1');

  // 4. alt / title
  screen.getByAltText('Blue mug on a table');

  // 5. Test ID (last resort)
  screen.getByTestId('price-chart');

  // Absence
  expect(screen.queryByRole('alert')).not.toBeInTheDocument();

  // Async appearance
  expect(await screen.findByText('In stock')).toBeVisible();

  // Scope to a region
  const reviews = screen.getByRole('region', { name: 'Reviews' });
  expect(within(reviews).getAllByRole('article')).toHaveLength(3);

  screen.debug(reviews);
});

⚠ Common Mistakes

  • Using getBy* to assert something is absent (it throws)
  • Wrapping findBy* in waitFor (it already waits)
  • Reaching for data-testid first

✓ Tips & Best Practices

  • Use Testing Playground to find the best query
  • Match names with case-insensitive regexes to survive copy changes
  • Scope with within instead of adding test IDs

Quick Summary

  • getBy present, queryBy absent, findBy async
  • Role + name first
  • within() to scope
  • Test IDs last
