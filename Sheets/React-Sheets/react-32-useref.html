useRef

ref.current · no re-render · timer IDs · previous values · refs vs state · no reads during render

Values That Don't Re-render

useRef(initial) returns a mutable object, { current: initial }, that lives for the whole life of the component. Changing ref.current does not trigger a re-render, which makes refs right for values the UI doesn't display: timer IDs, the previous value of a prop, a flag that an effect already ran, or a DOM node. If the screen should change when the value changes, use state.

Notes

  • The same ref object is returned on every render
  • Read and write ref.current in handlers and effects, not during render
  • Lazy init: if (ref.current === null) ref.current = create() is the one allowed render-time write
  • Refs are per component instance, unlike module variables

♿ Accessibility

  • Refs are how you move focus programmatically (sheet 33)

Version Notes

  • React 19 requires an argument: useRef() with no initial value is a TypeScript error in @types/react 19
  • Under the React Compiler, reading ref.current during render is flagged

Code Explained

intervalRef keeps the interval ID between renders without displaying it
Writing intervalRef.current in a handler causes no re-render
now and start are state because the output shows them
clearInterval before starting avoids two intervals running
The null check creates the Player once instead of every render

Refs as Instance Variables

import { useRef, useState } from 'react';

function Stopwatch() {
  const [start, setStart] = useState(null);
  const [now, setNow] = useState(null);
  const intervalRef = useRef(null);

  function handleStart() {
    setStart(Date.now());
    setNow(Date.now());
    clearInterval(intervalRef.current);
    intervalRef.current = setInterval(() => {
      setNow(Date.now());
    }, 10);
  }

  function handleStop() {
    clearInterval(intervalRef.current);
  }

  const seconds = start && now ? (now - start) / 1000 : 0;
  return (
    <>
      <output>{seconds.toFixed(2)}s</output>
      <button onClick={handleStart}>Start</button>
      <button onClick={handleStop}>Stop</button>
    </>
  );
}

// Lazy, one-time creation
function Video() {
  const player = useRef(null);
  if (player.current === null) player.current = new Player();
}

⚠ Common Mistakes

  • Displaying ref.current and expecting the UI to update
  • Reading or writing refs during render
  • Using a module-level variable shared by every instance

✓ Tips & Best Practices

  • Think of refs as an escape hatch; most data belongs in state
  • Name refs with a Ref suffix
  • Wrap ref patterns in custom hooks (useInterval, usePrevious)

Quick Summary

  • useRef(init) → { current }
  • Mutating doesn't re-render
  • Use in handlers and effects
  • State if it's shown on screen
