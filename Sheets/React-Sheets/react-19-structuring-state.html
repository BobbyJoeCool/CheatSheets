Structuring State

derived values · redundant state · duplicated state · flattening nested state · grouping related state · impossible states

Choosing the Right Shape

Well-structured state is the smallest set of values from which everything else can be derived. Avoid storing data that can be computed during render, avoid duplicating the same object in two places, and avoid combinations of booleans that allow impossible states. Group values that always change together, and flatten deeply nested data so updates stay simple.

Notes

  • Derived data (counts, filtered lists, full names) is computed in the render body
  • Store a selected item's ID, not a copy of the item
  • A single status string beats isLoading + isError + isSuccess
  • Normalize nested trees into a lookup object keyed by ID

♿ Accessibility

  • A single status makes it easy to render one accurate message for screen readers

Version Notes

  • These principles come from react.dev's Choosing the State Structure guide; unchanged in 19

Code Explained

fullName updates automatically because it's computed each render
status makes sending and sent at once impossible
Storing selectedId means edits to items show up in selected
pos keeps x and y in one update
A flat map lets you update one place without copying the whole tree

Before and After

// ✗ Redundant and contradictory
const [first, setFirst] = useState('');
const [last, setLast] = useState('');
const [fullName, setFullName] = useState('');   // derived
const [isSending, setIsSending] = useState(false);
const [isSent, setIsSent] = useState(false);    // both true?

// ✓ Minimal
const [first, setFirst] = useState('');
const [last, setLast] = useState('');
const fullName = `${first} ${last}`;            // derived
const [status, setStatus] = useState('typing'); // 'sending' | 'sent'

// ✗ Duplicated object
const [items, setItems] = useState(list);
const [selected, setSelected] = useState(list[0]);

// ✓ Store the ID, look it up
const [selectedId, setSelectedId] = useState(list[0].id);
const selected = items.find((i) => i.id === selectedId);

// ✓ Group values that change together
const [pos, setPos] = useState({ x: 0, y: 0 });

// ✓ Flat, normalized tree
const [places, setPlaces] = useState({
  root: { id: 'root', childIds: ['eu', 'as'] },
  eu: { id: 'eu', title: 'Europe', childIds: [] },
});

⚠ Common Mistakes

  • Syncing derived state with an effect
  • Initializing state from a prop and expecting it to follow the prop
  • Tracking isOpen for each item instead of one openId

✓ Tips & Best Practices

  • Ask: can I compute this from what I already have?
  • Name the prop initialX when you really do want a one-time copy
  • Draw the state transitions as a small diagram for complex forms

Quick Summary

  • Minimal state, derive the rest
  • One status, not many booleans
  • IDs, not copies
  • Flat beats nested
