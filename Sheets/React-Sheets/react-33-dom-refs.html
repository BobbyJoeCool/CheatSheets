Sheet 33

Refs to DOM Elements

ref attribute · focus() / scrollIntoView() · ref as a prop · forwardRef (legacy) · ref callback cleanup · useImperativeHandle

Reaching the DOM

Pass a ref object to a JSX element's ref attribute and React sets ref.current to the DOM node after mounting, and back to null on unmount. Use it for focus, scrolling, measuring, and third-party DOM libraries. In React 19, ref is a regular prop for function components, so a child can forward it to its own element without forwardRef. Ref callbacks can now return a cleanup function.

Notes

  • DOM refs are available in effects and handlers, not during the first render
  • Ref callback: ref={(node) => { …; return () => cleanup }}
  • useImperativeHandle(ref, () => ({ focus })) exposes a limited API instead of the node
  • For lists, store nodes in a Map via ref callbacks

♿ Accessibility

  • Move focus to dialogs, error summaries and new content with ref.current.focus()
  • Return focus to the triggering button when a dialog closes
  • Don't steal focus on page load unless the page has a single obvious task

Version Notes

  • React 19: ref as a prop; forwardRef still works but will be deprecated
  • React 19: ref callbacks may return a cleanup function
  • String refs (ref="input") were removed in React 19

Code Explained

TextInput destructures ref like any prop and attaches it to <input>
The parent's inputRef.current becomes the <input> element
The ref callback's returned function runs when the node unmounts
useImperativeHandle hands parents an object with only play and pause

DOM Refs in React 19

import { useRef, useImperativeHandle } from 'react';

// ref is just a prop now
function TextInput({ label, ref, ...props }) {
  return (
    <label>
      {label}
      <input ref={ref} {...props} />
    </label>
  );
}

function SearchPage() {
  const inputRef = useRef(null);
  return (
    <>
      <TextInput label="Search" ref={inputRef} />
      <button onClick={() => inputRef.current.focus()}>
        Focus search
      </button>
    </>
  );
}

// Ref callback with cleanup
function Measured() {
  return (
    <div ref={(node) => {
      const ro = new ResizeObserver(() => console.log(node.offsetWidth));
      ro.observe(node);
      return () => ro.disconnect();
    }} />
  );
}

// Expose only selected methods
function VideoPlayer({ ref, src }) {
  const video = useRef(null);
  useImperativeHandle(ref, () => ({
    play: () => video.current.play(),
    pause: () => video.current.pause(),
  }));
  return <video ref={video} src={src} />;
}

// Legacy: const TextInput = forwardRef((props, ref) => …)

⚠ Common Mistakes

  • Reading ref.current during render (it's null on first render)
  • Changing DOM content that React manages (React will overwrite it)
  • Wrapping new components in forwardRef out of habit

✓ Tips & Best Practices

  • Use refs for reading the DOM, state for changing what's rendered
  • Keep a Map of item refs for scroll-to-item lists
  • Prefer Fragment refs (sheet 09) over wrapper divs
