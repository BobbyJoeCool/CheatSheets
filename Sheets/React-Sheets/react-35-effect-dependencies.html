Sheet 35

Effect Dependencies

exhaustive-deps · object & function deps · removing deps · updater functions · useEffectEvent · never suppress the linter

Deps Are Not a Choice

Every reactive value an effect reads (props, state, and anything computed from them in the component body) must be in its dependency array. You don't pick dependencies; the code does, and the react-hooks/exhaustive-deps lint rule checks them. To remove a dependency, change the code so the effect doesn't need it. useEffectEvent lets an effect read the latest values without re-running when they change.

Notes

  • Objects and functions created during render are new each time, so they re-run the effect every render
  • Move such objects inside the effect, or outside the component if they don't use props
  • Use updater functions (setX(x => …)) so the effect doesn't depend on x
  • Values outside the component, refs and setters are not reactive

♿ Accessibility

  • Over-firing effects can re-announce live regions or steal focus repeatedly; correct deps prevent it

Version Notes

  • useEffectEvent is stable in React 19.2
  • The React Compiler lint rules in eslint-plugin-react-hooks also catch dependency problems

Code Explained

options is a new object each render, so [options] always changes
Building the object inside the effect leaves only roomId as a dependency
setCount(c => c + 1) doesn't read count, so the deps can be []
onConnected always sees the latest theme but isn't a dependency
Effect Events are called only from inside effects

Fixing Dependencies

import { useEffect, useEffectEvent, useState } from 'react';

// ✗ options is new every render -> reconnects every render
function Chat({ roomId }) {
  const options = { serverUrl, roomId };
  useEffect(() => {
    const c = createConnection(options);
    c.connect();
    return () => c.disconnect();
  }, [options]);
}

// ✓ Create it inside the effect; depend on primitives
function Chat2({ roomId }) {
  useEffect(() => {
    const c = createConnection({ serverUrl, roomId });
    c.connect();
    return () => c.disconnect();
  }, [roomId]);
}

// ✓ Updater removes the state dependency
useEffect(() => {
  const id = setInterval(() => setCount((c) => c + 1), 1000);
  return () => clearInterval(id);
}, []);

// ✓ Read latest theme without reconnecting on theme change
function Room({ roomId, theme }) {
  const onConnected = useEffectEvent(() => {
    showToast('Connected!', theme);
  });
  useEffect(() => {
    const c = createConnection({ serverUrl, roomId });
    c.on('connected', () => onConnected());
    c.connect();
    return () => c.disconnect();
  }, [roomId]);   // theme is not a dependency
}

⚠ Common Mistakes

  • Silencing the linter with // eslint-disable-next-line
  • Wrapping everything in useCallback to stabilize deps instead of restructuring
  • Passing Effect Events to other components or hooks

✓ Tips & Best Practices

  • Treat a lint warning as a bug report
  • Prefer primitive deps (roomId) over objects (room)
  • Ask whether the code needs to be in an effect at all (sheet 36)

Quick Summary

  • Every reactive value is a dep
  • Change code, not the array
  • Updaters remove state deps
  • useEffectEvent for non-reactive reads
