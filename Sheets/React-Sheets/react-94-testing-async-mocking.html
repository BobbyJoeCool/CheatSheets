Testing Async Code, Hooks & Mocks

findBy · waitFor · renderHook · vi.mock · MSW · fake timers

Waiting, Hooks and Fakes

For async UI, prefer findBy* queries; use waitFor(() => expect(…)) when you need to wait for an assertion that isn't a query. Test custom hooks with renderHook. Replace modules with vi.mock, spy on functions with vi.fn() and vi.spyOn, and control time with fake timers. For network calls, MSW (Mock Service Worker) intercepts requests at the network level, so components keep using real fetch.

Notes

  • waitFor retries its callback until it stops throwing or times out
  • renderHook returns { result, rerender, unmount }; read result.current
  • Wrap hooks that need context with the wrapper option
  • With fake timers, pass advanceTimers: vi.advanceTimersByTime to userEvent.setup

♿ Accessibility

  • Assert that error states render role="alert" so failures are announced

Version Notes

  • renderHook lives in @testing-library/react; @testing-library/react-hooks is deprecated
  • MSW 2 uses http and HttpResponse (v1's rest and res(ctx…) are gone)

Code Explained

MSW answers /api/user for every test; server.use overrides one test
findByText waits for the fetched name to render
renderHook runs the hook in a test component; act applies the update
vi.mock replaces the analytics module with a spy
Fake timers skip the 300 ms debounce instantly

Async, Hooks, Mocks

import { act, fireEvent, render, renderHook, screen }
  from '@testing-library/react';
import { http, HttpResponse } from 'msw';
import { setupServer } from 'msw/node';

const server = setupServer(
  http.get('/api/user', () => HttpResponse.json({ name: 'Ada' })),
);
beforeAll(() => server.listen());
afterEach(() => server.resetHandlers());
afterAll(() => server.close());

test('loads the user', async () => {
  render(<Profile />);
  expect(await screen.findByText('Ada')).toBeInTheDocument();
});

test('shows an error', async () => {
  server.use(http.get('/api/user', () =>
    new HttpResponse(null, { status: 500 })));
  render(<Profile />);
  expect(await screen.findByRole('alert')).toHaveTextContent(/error/i);
});

test('useCounter', () => {
  const { result } = renderHook(() => useCounter(5));
  act(() => result.current.increment());
  expect(result.current.count).toBe(6);
});

vi.mock('./analytics', () => ({ track: vi.fn() }));

test('debounced search', async () => {
  vi.useFakeTimers();
  const onSearch = vi.fn();
  render(<Search onSearch={onSearch} />);
  fireEvent.change(screen.getByRole('searchbox'),
    { target: { value: 'mug' } });
  act(() => vi.advanceTimersByTime(300));
  expect(onSearch).toHaveBeenCalledWith('mug');
  vi.useRealTimers();
});

Async Helpers

waitFor(fn)wait for an assertion
waitForElementToBeRemoved(el)wait for removal
act(fn)flush manual updates
vi.advanceTimersByTime(ms)move fake time

⚠ Common Mistakes

  • Side effects inside waitFor callbacks (they run many times)
  • Mocking fetch by hand in every test instead of MSW
  • Forgetting to restore real timers

✓ Tips & Best Practices

  • Share MSW handlers between tests, Storybook and local dev
  • Test hooks through components when possible; use renderHook for reusable hooks
  • Set onUnhandledRequest: 'error' in MSW to catch unmocked calls

Quick Summary

  • findBy / waitFor for async
  • renderHook for hooks
  • MSW for the network
  • vi.fn, vi.mock, fake timers
