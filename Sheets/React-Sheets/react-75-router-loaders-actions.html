React Router: Loaders & Actions

loader · useLoaderData · action · <Form> · useFetcher · useNavigation · redirect()

Data Before Render

In data and framework modes, each route can define a loader that runs before the route renders and returns its data, read with useLoaderData(). An action handles form submissions: <Form method="post"> sends FormData to the route's action, and after it runs, React Router revalidates all loaders so the UI shows fresh data. useFetcher submits or loads without navigating, and useNavigation reports pending state.

Notes

  • Loaders receive { params, request }; read query strings from new URL(request.url)
  • Return plain objects; throw data('Not found', { status: 404 }) for HTTP errors
  • redirect('/x') from a loader or action navigates
  • Loaders for parent and child routes run in parallel

♿ Accessibility

  • Show navigation.state === 'submitting' as text on the submit button
  • Return validation errors from actions and render them next to fields with aria-describedby

Version Notes

  • json() and defer() are deprecated since v7; return objects and promises directly
  • <Form> works without JavaScript in framework mode with SSR

Code Explained

The loader throws a 404 that the route's error boundary renders
The action validates, saves, then redirects
Returned { error } shows up in useActionData()
useNavigation() drives the pending button label
fetcher.formData gives an optimistic star before the server responds

loader, action, Form, useFetcher

import { Form, data, redirect, useActionData, useFetcher,
  useLoaderData, useNavigation } from 'react-router';

const route = {
  path: 'projects/:id',
  async loader({ params }) {
    const project = await db.project(params.id);
    if (!project) throw data('Not found', { status: 404 });
    return { project };
  },
  async action({ request, params }) {
    const form = await request.formData();
    const title = String(form.get('title'));
    if (!title) return { error: 'Title is required' };
    await db.update(params.id, { title });
    return redirect(`/projects/${params.id}`);
  },
  Component: Project,
};

function Project() {
  const { project } = useLoaderData();
  const result = useActionData();
  const navigation = useNavigation();
  const saving = navigation.state === 'submitting';
  return (
    <Form method="post">
      <input name="title" defaultValue={project.title} />
      {result?.error && <p role="alert">{result.error}</p>}
      <button disabled={saving}>{saving ? 'Saving…' : 'Save'}</button>
      <StarButton id={project.id} starred={project.starred} />
    </Form>
  );
}

function StarButton({ id, starred }) {
  const fetcher = useFetcher();
  const on = fetcher.formData
    ? fetcher.formData.get('starred') === 'true' : starred;
  return (
    <fetcher.Form method="post" action={`/projects/${id}/star`}>
      <button name="starred" value={String(!on)}>{on ? '★' : '☆'}</button>
    </fetcher.Form>
  );
}

⚠ Common Mistakes

  • Fetching in useEffect inside routes that could use loaders
  • Using <form> instead of <Form> and doing a full page submit
  • Navigating with useFetcher when the URL should change

✓ Tips & Best Practices

  • Use useFetcher for inline actions: likes, toggles, quick edits
  • Validate in actions with Zod and return field errors
  • Let revalidation refresh data instead of updating caches by hand

Quick Summary

  • loader → useLoaderData()
  • <Form> → action → revalidate
  • useFetcher for non-navigating calls
  • useNavigation for pending UI
