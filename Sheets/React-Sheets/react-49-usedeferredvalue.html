Sheet 49

useDeferredValue

deferred value · initialValue · stale indicator · vs debounce / throttle · pairing with memo

A Value That Lags Behind

useDeferredValue(value) returns a version of value that may lag behind during heavy rendering. On an update, React first re-renders with the old deferred value (fast), then renders again in the background with the new one, and discards that work if value changes again. It's ideal for keeping an input responsive while a slow list or chart updates.

Notes

  • Works only if the slow child is wrapped in memo (or compiled by the React Compiler)
  • No fixed delay: it adapts to the device's speed
  • value !== deferred tells you the shown content is stale
  • initialValue (React 19) lets the first render use a cheap placeholder

♿ Accessibility

  • Mark stale results visually (dimmed) and with aria-busy so users don't act on outdated data

Version Notes

  • React 18 introduced useDeferredValue; React 19 added the initialValue argument
  • Deferred renders that suspend show the old content, not the fallback

Code Explained

Typing updates query immediately, so the input never lags
SlowList receives deferredQuery, which updates in the background
memo lets React skip SlowList while the deferred value is unchanged
isStale dims the list until it catches up
initialValue [] renders an empty chart first, then the real data

Responsive Search

import { memo, useDeferredValue, useState } from 'react';

function Search() {
  const [query, setQuery] = useState('');
  const deferredQuery = useDeferredValue(query);
  const isStale = query !== deferredQuery;

  return (
    <>
      <input
        value={query}
        onChange={(e) => setQuery(e.target.value)}
        placeholder="Search 10,000 items"
      />
      <div aria-busy={isStale}
        style={{ opacity: isStale ? 0.5 : 1 }}>
        <SlowList query={deferredQuery} />
      </div>
    </>
  );
}

const SlowList = memo(function SlowList({ query }) {
  const items = filterItems(allItems, query);   // expensive
  return (
    <ul>{items.map((i) => <li key={i.id}>{i.name}</li>)}</ul>
  );
});

// Cheap first render, full one after
function Dashboard({ data }) {
  const deferredData = useDeferredValue(data, []);
  return <Chart data={deferredData} />;
}

⚠ Common Mistakes

  • Forgetting memo on the slow child, so nothing is skipped
  • Using it to throttle network requests (use debounce)
  • Passing a new object each render as the value

✓ Tips & Best Practices

  • Combine with a debounced fetch for search-as-you-type
  • Dim stale content instead of showing a spinner
  • Profile first: if the list is fast, you don't need it

Quick Summary

  • Lagging copy of a value
  • Keeps inputs responsive
  • Needs memo on the slow child
  • initialValue in React 19
