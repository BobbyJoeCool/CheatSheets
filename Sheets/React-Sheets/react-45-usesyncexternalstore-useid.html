Sheet 45

useSyncExternalStore & useId

subscribe · getSnapshot · getServerSnapshot · tearing · useId · label & aria linking

External Stores and Stable IDs

useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot?) reads a value from a source React doesn't own (a browser API, a third-party store) and re-renders when it changes, without tearing during concurrent rendering. useId() generates a unique, stable ID that matches between server and client, ideal for linking labels and ARIA attributes.

Notes

  • subscribe(callback) must return an unsubscribe function
  • getSnapshot must return the same value (by Object.is) if nothing changed
  • Define subscribe outside the component, or React re-subscribes every render
  • Never use useId for list keys; keys should come from your data

♿ Accessibility

  • useId links <label htmlFor>, aria-describedby and aria-labelledby without hard-coded, duplicated IDs
  • Generate one ID and suffix it for related elements: ${id}-hint

Version Notes

  • Both hooks arrived in React 18
  • React 19.1 changed useId format to «r1»; 19.2 changed it to _r_1_ so it's valid in CSS selectors and view-transition-name

Code Explained

subscribe is defined at module level so its identity never changes
The snapshot returns a boolean, so equal values skip re-renders
The server snapshot avoids touching navigator during SSR
useId produces the same ID on server and client
Suffixes create related IDs from one generated base

Subscribe and Link

import { useId, useSyncExternalStore } from 'react';

// Browser API store
function subscribe(callback) {
  window.addEventListener('online', callback);
  window.addEventListener('offline', callback);
  return () => {
    window.removeEventListener('online', callback);
    window.removeEventListener('offline', callback);
  };
}

function useOnline() {
  return useSyncExternalStore(
    subscribe,
    () => navigator.onLine,   // client snapshot
    () => true,               // server snapshot
  );
}

// Third-party store
const count = useSyncExternalStore(
  store.subscribe, () => store.getState().count,
);

// Accessible IDs
function PasswordField() {
  const id = useId();
  return (
    <>
      <label htmlFor={id}>Password</label>
      <input id={id} type="password"
        aria-describedby={`${id}-hint`} />
      <p id={`${id}-hint`}>At least 8 characters</p>
    </>
  );
}

// Several fields from one prefix
const base = useId();
<input id={`${base}-first`} />;
<input id={`${base}-last`} />;

⚠ Common Mistakes

  • Returning a new object from getSnapshot every call (infinite loop)
  • Using useEffect + setState to mirror an external store
  • Using Math.random() IDs that differ between server and client

✓ Tips & Best Practices

  • Prefer a store's own hook (Zustand, Redux) if it exists; they use this API internally
  • Call useId once per component and derive suffixes
  • Set identifierPrefix on roots when several React apps share a page

Quick Summary

  • useSyncExternalStore for outside data
  • Stable subscribe, cached snapshot
  • useId for accessible IDs
  • Not for list keys
