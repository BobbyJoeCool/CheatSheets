Class Components (Legacy)

extends Component · render() · this.state · setState · componentDidMount · componentWillUnmount · hook equivalents

Classes You'll Still Meet

Before hooks, components with state were classes extending React.Component. They define render(), keep state in this.state, update it with this.setState(), and react to mounting and updates with lifecycle methods. New code uses function components, but classes still appear in older codebases and are the only way to write an error boundary without a library.

Notes

  • setState merges the object you pass into existing state (hooks replace instead)
  • this must be bound for handlers; class fields with arrow functions do it for you
  • Classes can't use hooks; wrap them or convert them
  • PureComponent skips re-renders when props and state are shallowly equal

♿ Accessibility

  • Focus management in classes used componentDidUpdate plus refs; the same rules apply with hooks

Version Notes

  • Classes are still supported in React 19 but receive no new features
  • String refs and legacy context (contextTypes) were removed in React 19
  • UNSAFE_componentWillMount and similar remain deprecated

Code Explained

state = {…} is a class field that sets initial state
componentDidMount runs once after the first render is in the DOM
componentWillUnmount cleans up the interval
tick is an arrow class field, so this is bound
The hook version puts setup and cleanup together in one useEffect

A Class Component and Its Hook Version

import { Component, useEffect, useState } from 'react';

class Clock extends Component {
  state = { now: new Date() };

  componentDidMount() {
    this.id = setInterval(this.tick, 1000);
  }

  componentWillUnmount() {
    clearInterval(this.id);
  }

  tick = () => this.setState({ now: new Date() });

  render() {
    return <time>{this.state.now.toLocaleTimeString()}</time>;
  }
}

// Same component with hooks
function ClockFn() {
  const [now, setNow] = useState(new Date());

  useEffect(() => {
    const id = setInterval(() => setNow(new Date()), 1000);
    return () => clearInterval(id);
  }, []);

  return <time>{now.toLocaleTimeString()}</time>;
}

⚠ Common Mistakes

  • Mutating this.state directly instead of calling setState
  • Reading this.state right after setState and expecting the new value
  • Forgetting to bind handlers and getting this as undefined

✓ Tips & Best Practices

  • Convert classes to functions when you touch them for other work
  • Use setState(prev => …) when the next state depends on the previous one
  • Keep a class only for error boundaries, or use react-error-boundary
