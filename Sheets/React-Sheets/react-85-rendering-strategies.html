Rendering Strategies

CSR · SSR · SSG · streaming · hydration · choosing a framework

Where HTML Gets Made

React can render in the browser, on the server per request, or at build time. CSR (client-side rendering) ships an empty HTML shell and builds the UI in JavaScript. SSR renders HTML on each request, then hydrates it so it becomes interactive. SSG renders HTML at build time. Streaming sends HTML in chunks as Suspense boundaries resolve. Server Components run only on the server and send no JavaScript for themselves.

Notes

  • Hydration attaches event handlers to existing server HTML; output must match
  • SSR improves first paint and SEO but needs a server
  • SSG suits content that changes rarely (docs, marketing)
  • Frameworks (Next.js, React Router framework mode) handle these choices for you

♿ Accessibility

  • Server-rendered HTML is readable before JavaScript loads and works with slow devices and assistive tech
  • Avoid hydration mismatches that cause content to flash and confuse screen readers

Version Notes

  • React 18 added streaming SSR with Suspense; React 19 made Server Components and Server Functions stable for frameworks
  • React 19.2 added Partial Pre-rendering APIs (prerender + resume)

Code Explained

CSR renders everything after JavaScript downloads
SSR sends HTML; hydrateRoot makes it interactive
prerender waits for all data and returns static HTML
Suspense boundaries let the server stream slow sections later
A Server Component queries the database and ships only the result

Strategies at a Glance

// CSR: index.html has <div id="root"></div>
createRoot(document.getElementById('root')).render(<App />);

// SSR (per request) + hydration
// server
const html = await renderToReadableStream(<App url={req.url} />);
// client
hydrateRoot(document.getElementById('root'), <App />);

// SSG (build time)
for (const path of ['/', '/about', '/blog/hello']) {
  const { prelude } = await prerender(<App url={path} />);
  await writeFile(`dist${path}/index.html`, prelude);
}

// Streaming: shell first, slow parts later
function Page() {
  return (
    <Layout>
      <Hero />
      <Suspense fallback={<ReviewsSkeleton />}>
        <Reviews />        {/* streams in when ready */}
      </Suspense>
    </Layout>
  );
}

// Server Component (framework): no client JS for this file
export default async function Products() {
  const products = await db.products.findMany();
  return <ProductGrid products={products} />;
}

// Rendering timeline (SSR + streaming):
// request -> shell HTML -> boundary chunks -> JS -> hydrate

⚠ Common Mistakes

  • Building SSR by hand when a framework fits
  • Rendering browser-only values (dates, window) differently on server and client
  • One giant Suspense boundary that delays the whole page

✓ Tips & Best Practices

  • Choose per route: static where possible, dynamic where needed
  • Use streaming to show the shell immediately
  • Measure Core Web Vitals to pick a strategy

Quick Summary

  • CSR, SSR, SSG, streaming
  • Hydration attaches interactivity
  • Server Components send no JS
  • Frameworks make these choices easy
