React Router: Params & Search Params

:param · optional segments · splat * · useParams · useSearchParams · useLocation

Reading the URL

Dynamic segments (:id) capture parts of the path; read them with useParams(). Add ? to make a segment optional (:lang?), and use * as a splat to capture the rest of the URL. The query string is read and written with useSearchParams(), which works like useState but stores values in the URL. useLocation() returns the full location: pathname, search, hash and state.

Notes

  • All params are strings (or undefined); convert numbers yourself
  • params['*'] holds the splat value
  • setSearchParams replaces the whole query; use the function form to update one key
  • Search params are great for filters, sorting and pagination

♿ Accessibility

  • Reflect filter state in the URL so users can bookmark and share accessible views
  • Announce result counts after search params change

Version Notes

  • Unchanged API in v7 and v8
  • Framework mode provides typed params via generated route types (sheet 76)

Code Explained

:userId and :postId become keys on the params object
:lang? matches /docs and /en/docs
The splat captures everything after files/
searchParams.get returns null when missing, so a default follows ??
The updater form keeps other query keys while changing sort

Params and Search Params

import { useLocation, useParams, useSearchParams } from 'react-router';

// Route config
// { path: 'users/:userId/posts/:postId', Component: Post }
// { path: ':lang?/docs', Component: Docs }
// { path: 'files/*', Component: FileBrowser }

function Post() {
  const { userId, postId } = useParams();
  return <h1>Post {postId} by user {userId}</h1>;
}

function FileBrowser() {
  const params = useParams();
  const path = params['*'];       // "a/b/readme.md"
  return <code>{path}</code>;
}

function ProductList() {
  const [searchParams, setSearchParams] = useSearchParams();
  const sort = searchParams.get('sort') ?? 'name';
  const page = Number(searchParams.get('page') ?? 1);

  function setSort(next) {
    setSearchParams((prev) => {
      prev.set('sort', next);
      prev.set('page', '1');
      return prev;
    });
  }

  return (
    <>
      <select value={sort} onChange={(e) => setSort(e.target.value)}>
        <option value="name">Name</option>
        <option value="price">Price</option>
      </select>
      <Products sort={sort} page={page} />
    </>
  );
}

function Debug() {
  const { pathname, search, hash, state } = useLocation();
}

⚠ Common Mistakes

  • Treating params as numbers without converting
  • Calling setSearchParams({ sort }) and wiping other keys
  • Storing filter state in React state so it's lost on refresh

✓ Tips & Best Practices

  • Validate params with Zod in loaders
  • Use replace: true for search updates that shouldn't add history entries
  • Keep URLs human-readable: ?sort=price&page=2

Quick Summary

  • :param → useParams()
  • :opt? optional, * splat
  • useSearchParams() for ?query
  • Everything is a string
