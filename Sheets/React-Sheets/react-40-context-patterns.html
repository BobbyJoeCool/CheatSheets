Context Patterns

reducer + context · provider component · useX() hook with guard · splitting state & dispatch · use(Context)

Patterns That Scale

In real apps, context usually comes wrapped in a provider component and a custom hook. The provider owns the state (often with useReducer), and the hook reads the context and throws a clear error when used outside the provider. Splitting state and dispatch into two contexts lets components that only send actions avoid re-rendering when state changes.

Notes

  • Keep the context object private to the module; export the provider and hook
  • dispatch is stable, so a dispatch-only context never changes
  • Initialize context with null to detect a missing provider
  • use(Ctx) can be called inside if blocks and loops, unlike useContext

♿ Accessibility

  • A notifications provider is a good place to render one shared aria-live region

Version Notes

  • use(Context) is new in React 19
  • The reducer + context pattern is documented on react.dev as Scaling Up with Reducer and Context

Reducer + Context Provider

import { createContext, use, useReducer } from 'react';

const TasksContext = createContext(null);
const DispatchContext = createContext(null);

function tasksReducer(tasks, action) {
  switch (action.type) {
    case 'added': return [...tasks, action.task];
    case 'deleted': return tasks.filter((t) => t.id !== action.id);
    default: throw new Error(action.type);
  }
}

export function TasksProvider({ children }) {
  const [tasks, dispatch] = useReducer(tasksReducer, []);
  return (
    <TasksContext value={tasks}>
      <DispatchContext value={dispatch}>
        {children}
      </DispatchContext>
    </TasksContext>
  );
}

export function useTasks() {
  const ctx = use(TasksContext);
  if (ctx === null) throw new Error('useTasks needs <TasksProvider>');
  return ctx;
}

export function useTasksDispatch() {
  const ctx = use(DispatchContext);
  if (ctx === null) throw new Error('needs <TasksProvider>');
  return ctx;
}

// Anywhere below the provider
function AddTask() {
  const dispatch = useTasksDispatch();   // never re-renders on task changes
  return <button onClick={() => dispatch({ type: 'added',
    task: { id: crypto.randomUUID(), text: 'New' } })}>Add</button>;
}

⚠ Common Mistakes

  • Exporting the raw context so callers skip validation
  • Putting state and dispatch in one object and re-rendering every writer
  • Creating one giant app-wide context for unrelated data

✓ Tips & Best Practices

  • Compose providers in a single Providers component
  • Keep each context focused on one concern
  • Move to an external store (sheet 84) when updates are frequent

Quick Summary

  • Provider component + custom hook
  • Throw outside the provider
  • Split state and dispatch
  • use(Ctx) allowed in conditions
