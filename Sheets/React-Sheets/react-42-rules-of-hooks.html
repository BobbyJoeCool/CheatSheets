Sheet 42

Rules of Hooks

top level only · components & hooks only · call order · use prefix · eslint-plugin-react-hooks · use() exception

Two Rules

Hooks are functions whose names start with use. React tracks them by call order, so two rules apply. Only call hooks at the top level of a component or custom hook: never inside conditions, loops, nested functions or after an early return. Only call hooks from React functions: components and custom hooks, not regular functions or class components. The react-hooks ESLint plugin enforces both.

Notes

  • React stores each hook's state in a list indexed by call position
  • A conditional hook shifts every later hook's position and mixes up state
  • Put the condition inside the hook: useEffect(() => { if (x) … })
  • use() is the exception: it may be called in conditions and loops

♿ Accessibility

  • Hook-order bugs often surface as the wrong aria-expanded or focus state on the wrong item

Version Notes

  • Rules unchanged since 16.8; use() (React 19) is an API, not a hook, and can be conditional
  • eslint-plugin-react-hooks adds compiler-based rules for purity and ref access

Code Explained

The early return means useState runs on some renders but not others
Moving hooks above the branch keeps their order fixed
Hooks can't run in loops or in callbacks that run later
Effects can contain conditions; they just can't be conditional themselves
use(promise) after a branch is allowed

Breaking and Following the Rules

// ✗ Conditional hook
function Profile({ user }) {
  if (!user) return <SignIn />;          // early return...
  const [tab, setTab] = useState('info');// ...then a hook
}

// ✓ Hooks first, then branch
function Profile2({ user }) {
  const [tab, setTab] = useState('info');
  if (!user) return <SignIn />;
  return <Tabs value={tab} onChange={setTab} />;
}

// ✗ Hook in a loop or callback
items.forEach(() => useState(0));
const onClick = () => { useEffect(…); };

// ✓ Condition inside the effect
useEffect(() => {
  if (!enabled) return;
  const id = setInterval(tick, 1000);
  return () => clearInterval(id);
}, [enabled]);

// ✓ use() may be conditional
function Message({ show, messagePromise }) {
  if (!show) return null;
  const msg = use(messagePromise);
  return <p>{msg}</p>;
}

// eslint.config.js
import reactHooks from 'eslint-plugin-react-hooks';
export default [reactHooks.configs.recommended];

⚠ Common Mistakes

  • Early returns before hooks
  • Naming a regular function useSomething without calling hooks
  • Disabling the lint rule to make a conditional hook compile

✓ Tips & Best Practices

  • Order component bodies: hooks → derived values → handlers → early returns → JSX
  • Split a component when hooks differ between branches
  • Run ESLint in CI so violations never merge

Quick Summary

  • Top level only
  • Only in components and hooks
  • Order must never change
  • use() is the exception
