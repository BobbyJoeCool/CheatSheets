Catching Render Errors

An error boundary catches errors thrown while rendering the components below it, shows a fallback, and keeps the rest of the app running. Without one, a render error unmounts the whole root. Boundaries are class components that implement static getDerivedStateFromError (to show the fallback) and usually componentDidCatch (to log). Most apps use the react-error-boundary package instead of writing the class.

Notes

  • Boundaries catch errors in render, lifecycle methods, effects-during-commit and use() rejections
  • They don't catch errors in event handlers, async code outside React, or the boundary itself
  • Rejected form Actions and transitions are also caught
  • Place boundaries around routes and independent widgets

♿ Accessibility

  • Make the fallback a clear message with role="alert" and a button to retry or go back
  • Move focus to the fallback heading so keyboard users know the content changed

Version Notes

  • There is still no hook equivalent in React 19; boundaries remain class-based
  • React 19 logs caught errors once (with component stack) instead of re-throwing them

Code Explained

getDerivedStateFromError stores the error so render shows the fallback
componentDidCatch reports to your logging service
resetErrorBoundary clears the error and re-renders the children
resetKeys resets automatically when userId changes
Handler errors don't reach boundaries, so catch them and set state

Class Boundary and Library

import { Component } from 'react';

class ErrorBoundary extends Component {
  state = { error: null };

  static getDerivedStateFromError(error) {
    return { error };                 // render fallback next
  }

  componentDidCatch(error, info) {
    logError(error, info.componentStack);
  }

  render() {
    if (this.state.error) return this.props.fallback;
    return this.props.children;
  }
}

// react-error-boundary
import { ErrorBoundary as EB } from 'react-error-boundary';

function Fallback({ error, resetErrorBoundary }) {
  return (
    <div role="alert">
      <h2>Something went wrong</h2>
      <pre>{error.message}</pre>
      <button onClick={resetErrorBoundary}>Try again</button>
    </div>
  );
}

<EB FallbackComponent={Fallback}
  onReset={() => queryClient.resetQueries()}
  resetKeys={[userId]}>
  <UserPanel userId={userId} />
</EB>

// Errors in handlers: catch them yourself
async function handleSave() {
  try { await save(); } catch (e) { setError(e); }
}

⚠ Common Mistakes

  • One boundary at the root so any error blanks the whole app
  • Expecting boundaries to catch errors in click handlers
  • Showing raw stack traces to users in production

✓ Tips & Best Practices

  • Wrap each route and each independent widget
  • Pair every Suspense boundary with an error boundary
  • Use showBoundary from useErrorBoundary to surface async errors

Quick Summary

  • Boundaries catch render-phase errors
  • Class-only or react-error-boundary
  • Not event handlers or async code
  • Offer a retry
