CSS Modules

.module.css · styles.x · composes · :global · dynamic class names · TypeScript declarations

Scoped Class Names

A CSS Module is a CSS file named *.module.css. Importing it returns an object that maps each class name to a unique, generated name, so .title in one module never clashes with .title in another. Vite supports CSS Modules with no configuration. Use composes to reuse classes, :global for intentional global selectors, and Sass by naming files *.module.scss.

Notes

  • Class names with dashes need bracket access: styles['card-title']
  • Vite can convert dashes to camelCase with css.modules.localsConvention
  • Global styles (resets, fonts, variables) stay in a normal .css file
  • Missing classes are undefined at runtime; TypeScript can catch them with typed declarations

♿ Accessibility

  • Keep visible focus styles in modules: .button:focus-visible { outline: … }

Version Notes

  • Vite and Next.js support CSS Modules out of the box
  • Works with Server Components because the CSS is static

Code Explained

styles.primary resolves to a hashed class name unique to this file
composes: base adds the base class wherever primary is used
:global(.dark) targets the unscoped dark class on an ancestor
styles[tone] selects the class by a prop value
clsx skips undefined when active is false

Button.module.css + Button.tsx

/* Button.module.css */
.base {
  padding: 0.5rem 1rem;
  border-radius: 6px;
}
.primary {
  composes: base;
  background: var(--brand);
  color: white;
}
.danger {
  composes: base;
  background: crimson;
}
.button:focus-visible { outline: 2px solid var(--focus); }
:global(.dark) .primary { background: var(--brand-dark); }

// Button.tsx
import styles from './Button.module.css';
import clsx from 'clsx';

export function Button({ tone = 'primary', active, ...rest }) {
  return (
    <button
      className={clsx(styles[tone], active && styles.active)}
      {...rest}
    />
  );
}

// Rendered HTML (generated names)
// <button class="_primary_x8a1q _base_x8a1q">

// vite.config.ts
// css: { modules: { localsConvention: 'camelCaseOnly' } }

⚠ Common Mistakes

  • Forgetting .module in the file name, so classes aren't scoped
  • Writing className="title" instead of className={styles.title}
  • Putting resets inside modules and expecting them to be global

✓ Tips & Best Practices

  • One module per component, next to the component file
  • Use typescript-plugin-css-modules for autocomplete
  • Keep design tokens as global custom properties and use them inside modules

Quick Summary

  • *.module.css → scoped classes
