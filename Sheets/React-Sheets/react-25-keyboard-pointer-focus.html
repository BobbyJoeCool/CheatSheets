onKeyDown · e.key · onPointerDown · onFocus / onBlur · onChange per keystroke · onScroll · passive listeners

Keys, Pointers and Focus

Keyboard events (onKeyDown, onKeyUp) report e.key ('Enter', 'Escape', 'ArrowDown') plus modifier flags. Pointer events (onPointerDown, onPointerMove) unify mouse, pen and touch. React's onFocus and onBlur bubble like the DOM's focusin/focusout, so a container can track focus inside it. onChange fires on every keystroke, unlike the DOM's change event.

Notes

  • Use e.key, not the deprecated e.keyCode
  • e.relatedTarget on blur tells you where focus went
  • Wheel and touch listeners attached by React are passive; call preventDefault from a native non-passive listener
  • onScroll doesn't bubble in React

♿ Accessibility

  • Every pointer interaction needs a keyboard equivalent
  • Close popups on Escape and return focus to the trigger
  • Don't trap focus unintentionally with onBlur logic that refocuses

Version Notes

  • React 17 stopped onScroll from bubbling and made onFocus/onBlur use focusin/focusout
  • Pointer events have been supported since React 16.4

Code Explained

e.key compares readable names; check metaKey or ctrlKey for shortcuts
setPointerCapture keeps move events flowing even if the pointer leaves the element
e.buttons === 1 means the primary button is held
onBlur bubbles, so the container hears when any child loses focus
relatedTarget outside the menu means focus left; dismiss it

Keyboard, Pointer, Focus

function SearchBox({ onSearch, onClose }) {
  return (
    <input
      type="search"
      onKeyDown={(e) => {
        if (e.key === 'Enter') onSearch(e.currentTarget.value);
        if (e.key === 'Escape') onClose();
        if (e.key === 'k' && (e.metaKey || e.ctrlKey)) {
          e.preventDefault();
        }
      }}
    />
  );
}

function Draggable() {
  const [pos, setPos] = useState({ x: 0, y: 0 });
  return (
    <div
      className="handle"
      onPointerDown={(e) =>
        e.currentTarget.setPointerCapture(e.pointerId)}
      onPointerMove={(e) => {
        if (e.buttons !== 1) return;
        setPos((p) => ({ x: p.x + e.movementX,
          y: p.y + e.movementY }));
      }}
      style={{ translate: `${pos.x}px ${pos.y}px` }}
    />
  );
}

function Menu({ onDismiss, children }) {
  return (
    <div
      onBlur={(e) => {
        if (!e.currentTarget.contains(e.relatedTarget)) onDismiss();
      }}
    >{children}</div>
  );
}

⚠ Common Mistakes

  • Using keyCode or which
  • Expecting onChange to wait until the input loses focus
  • Calling preventDefault in React's passive onWheel/onTouchMove

✓ Tips & Best Practices

  • Use e.code for game-style controls that depend on key position
  • Prefer onPointer* over separate mouse and touch handlers
  • Debounce expensive work triggered by onChange or onPointerMove

Quick Summary

  • e.key for keys
  • Pointer events = mouse + touch + pen
  • Focus events bubble in React
  • onChange = every keystroke
