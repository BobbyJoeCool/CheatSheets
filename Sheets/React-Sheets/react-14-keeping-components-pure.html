Sheet 14

Keeping Components Pure

pure render · side effects in handlers · local mutation · StrictMode double render · idempotence · props as snapshots

Render Must Be Pure

React expects components to be pure functions of their props, state and context: given the same inputs, return the same JSX, and don't change anything outside the function while rendering. Side effects (network calls, timers, DOM changes, logging to services) belong in event handlers or, as a last resort, effects. StrictMode renders components twice in development to surface impurity.

Notes

  • Mutating variables or objects created during this render is fine (local mutation)
  • Mutating props, state, context or module-level variables is not
  • React may render a component several times before committing, or not commit at all
  • Purity is what lets React pause, resume and skip renders safely

♿ Accessibility

  • Impure renders cause flicker and duplicated content that confuses screen readers

Version Notes

  • StrictMode double rendering exists since React 18; React 19 dims the second log in DevTools
  • The React Compiler assumes purity; impure components can break when memoized

Code Explained

BadGuest shows different numbers in StrictMode because it renders twice
Guest returns the same output for the same number
guests is created inside the render, so pushing to it is safe
analytics.track during render fires on every re-render, not once per visit
Work triggered by the user belongs in the event handler

Pure vs Impure

let guestCount = 0;

// ✗ Impure: changes a module variable during render
function BadGuest() {
  guestCount = guestCount + 1;
  return <h2>Guest #{guestCount}</h2>;
}

// ✓ Pure: output depends only on props
function Guest({ number }) {
  return <h2>Guest #{number}</h2>;
}

// ✓ Local mutation is fine
function GuestList({ count }) {
  const guests = [];
  for (let i = 1; i <= count; i++) {
    guests.push(<Guest key={i} number={i} />);
  }
  return <>{guests}</>;
}

// ✗ Side effect in render
function Tracker({ page }) {
  analytics.track(page);        // runs on every render
  return <p>{page}</p>;
}

// ✓ Side effects go in handlers or effects
function SaveButton({ data }) {
  const save = () => api.save(data);   // on click
  return <button onClick={save}>Save</button>;
}

⚠ Common Mistakes

  • Calling setState during render without a guard (infinite loop)
  • Sorting a prop array in place: items.sort() mutates the parent's data
  • Disabling StrictMode to hide double-render symptoms

✓ Tips & Best Practices

  • Copy before sorting: items.toSorted() or [...items].sort()
  • Read Date.now() and random values in handlers or state initializers
  • Treat StrictMode warnings as bugs

Quick Summary

  • Same inputs → same JSX
  • No outside changes during render
  • Local mutation is OK
  • Effects go in handlers first
