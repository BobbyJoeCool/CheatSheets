How Rendering Works

trigger · render · commit · reconciliation · re-render causes · bailouts

Trigger, Render, Commit

Every screen update goes through three steps. A trigger (initial mount or a state update) asks React to render. In the render phase, React calls your components to compute new JSX and reconciles it with the previous output. In the commit phase, it applies the minimal DOM changes and runs effects. Rendering a component doesn't mean the DOM changed; React only touches what differs.

Notes

  • A state change re-renders that component and, by default, all its children
  • Parents re-rendering is the most common cause of child re-renders
  • Context changes re-render every reader
  • React bails out when a setter receives a value equal (Object.is) to the current one

♿ Accessibility

  • Committing only changed nodes keeps focus and selection stable during updates

Version Notes

  • Concurrent rendering (React 18+) can pause and resume the render phase; commit is always synchronous
  • The React Compiler skips re-rendering children whose props didn't change

What Re-renders

function App() {
  const [count, setCount] = useState(0);
  console.log('App renders');
  return (
    <>
      <button onClick={() => setCount(count + 1)}>{count}</button>
      <Header />            {/* re-renders: parent rendered */}
      <List items={items} />{/* re-renders too */}
    </>
  );
}

// Same type + position -> React updates in place
<input className={dark ? 'dark' : 'light'} />
// Only the className attribute is changed in the DOM

// Different type -> unmount old, mount new
{isEditing ? <input /> : <span />}

// Moving state down limits re-renders
function App2() {
  return (
    <>
      <Counter />           {/* only this re-renders */}
      <Header />
      <List items={items} />
    </>
  );
}

// Passing children keeps them from re-rendering
function ScrollTracker({ children }) {
  const [y, setY] = useState(0);
  // children were created by the parent; not re-rendered
  return <div onScroll={(e) => setY(e.currentTarget.scrollTop)}>
    {children}
  </div>;
}

⚠ Common Mistakes

  • Assuming a re-render means slow DOM updates
  • Optimizing before measuring
  • Lifting state higher than needed and re-rendering large trees

✓ Tips & Best Practices

  • Keep state as close as possible to where it's used
  • Pass expensive subtrees as children
  • Measure with the Profiler before adding memo

Quick Summary

  • Trigger → render → commit
  • Children re-render with parents
  • DOM changes are minimal
  • Move state down, lift content up
