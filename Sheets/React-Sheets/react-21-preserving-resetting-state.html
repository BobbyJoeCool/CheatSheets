Preserving & Resetting State

position in the tree · same type, same position · key to reset · nested definition bug · state across conditionals

State Lives in the Tree

React ties state to a component's position in the render tree, not to the JSX variable or function call. If the same component type renders at the same position, its state is preserved across re-renders, even with different props. Change the type, or move it to a different position, and the state is destroyed. Give a component a different key to force a fresh instance with reset state.

Notes

  • Swapping <Counter /> for <p> at a position destroys the counter's state
  • {cond ? <A /> : <A />} keeps state: same type, same position
  • {cond && <A />}{!cond && <A />} resets: two different positions
  • Defining a component inside another creates a new type every render, resetting its state

♿ Accessibility

  • Resetting with key also resets focus; move focus deliberately after a reset

Version Notes

  • React 19.2's <Activity> can hide a subtree while preserving its state (see sheet 51)

Preserve or Reset

function Scoreboard() {
  const [isPlayerA, setIsPlayerA] = useState(true);

  return (
    <div>
      {/* Same position + type: state is kept */}
      {isPlayerA
        ? <Counter person="Taylor" />
        : <Counter person="Sarah" />}

      {/* Different key: state resets */}
      {isPlayerA
        ? <Counter key="taylor" person="Taylor" />
        : <Counter key="sarah" person="Sarah" />}

      <button onClick={() => setIsPlayerA(!isPlayerA)}>
        Next player
      </button>
    </div>
  );
}

// Reset a form when the selected contact changes
function Messenger({ contact }) {
  return <ChatForm key={contact.id} contact={contact} />;
}

// ✗ Nested definition: new type each render
function Parent() {
  const Input = () => <input />;  // state lost on every render
  return <Input />;
}

Use key To

GoalExample
Reset a form<Form key={userId} />
Restart an animation<Fade key={slide} />
Separate instanceskey="a" / key="b"
Avoid effect-based resetskey instead of useEffect

⚠ Common Mistakes

  • Resetting state with an effect that watches a prop
  • Wrapping a component in a conditional <div> and losing its state
  • Declaring components inside other components

✓ Tips & Best Practices

  • Reach for key whenever new item = fresh state
  • Keep the tree shape stable to keep state
  • Lift state up if it must survive the component being removed

Quick Summary

  • State is tied to tree position
  • Same type + spot = preserved
  • New type or key = reset
  • Never nest component definitions
