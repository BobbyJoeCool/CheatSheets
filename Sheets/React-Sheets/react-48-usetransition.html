useTransition & startTransition

isPending · non-blocking updates · async actions · transitions + Suspense · not for text inputs

Non-Blocking Updates

A transition marks a state update as non-urgent. React renders it in the background, keeps the current UI interactive, and can interrupt it if something more urgent (like typing) happens. useTransition() returns [isPending, startTransition]. In React 19, startTransition accepts async functions, called Actions, and isPending stays true until they finish.

Notes

  • Use transitions for tab switches, navigation, filtering large lists
  • Updates inside a transition don't show Suspense fallbacks for already-visible content
  • Text input updates must be urgent; never put the controlled value update in a transition
  • Standalone startTransition (imported from react) works without isPending

♿ Accessibility

  • Show isPending as visible text or aria-busy so users know something is happening
  • Don't disable the controls that started the transition; users may change their mind

Version Notes

  • React 18 introduced transitions
  • React 19: async functions in startTransition (Actions); state set after await must be wrapped in another startTransition

Code Explained

setTab inside startTransition lets a click on About interrupt rendering Posts
aria-busy and isPending signal the background work
The async function makes isPending true for the whole request
State updates after await need their own startTransition (a current limitation)
name updates stay urgent so typing never lags

useTransition

import { useState, useTransition } from 'react';

function TabContainer() {
  const [tab, setTab] = useState('about');
  const [isPending, startTransition] = useTransition();

  function selectTab(next) {
    startTransition(() => setTab(next));   // interruptible
  }

  return (
    <>
      <TabButton onClick={() => selectTab('about')}>About</TabButton>
      <TabButton onClick={() => selectTab('posts')}>Posts (slow)</TabButton>
      <section aria-busy={isPending}>
        {tab === 'about' ? <About /> : <Posts />}
      </section>
    </>
  );
}

// Async Action (React 19)
function UpdateName() {
  const [name, setName] = useState('');
  const [error, setError] = useState(null);
  const [isPending, startTransition] = useTransition();

  const submit = () => startTransition(async () => {
    const err = await updateName(name);
    startTransition(() => {
      if (err) setError(err);
      else redirect('/profile');
    });
  });

  return (
    <>
      <input value={name} onChange={(e) => setName(e.target.value)} />
      <button onClick={submit} disabled={isPending}>Update</button>
      {error && <p role="alert">{error}</p>}
    </>
  );
}

⚠ Common Mistakes

  • Wrapping a controlled input's setValue in a transition
  • Expecting setTimeout callbacks inside startTransition to be transitions
  • Forgetting the inner startTransition for updates after await

✓ Tips & Best Practices

  • Use transitions before reaching for debouncing
  • Show pending state near the thing that is changing
  • Routers (React Router, Next.js) already wrap navigation in transitions

Quick Summary

  • [isPending, startTransition]
  • Non-urgent, interruptible updates
  • Async functions = Actions (19)
  • Never for input values
