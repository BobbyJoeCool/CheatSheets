Testing Library: User Interactions

userEvent.setup() · click · type · keyboard · fireEvent vs userEvent · act

Simulating Real Input

user-event simulates complete interactions the way a browser would: a click fires pointer, mouse, focus and click events; typing fires key events and updates the value one character at a time. Create a session with userEvent.setup() at the start of each test and await every call. Use fireEvent only for events user-event doesn't cover. RTL wraps interactions in act, so you rarely call it yourself.

Notes

  • user.type(el, 'text') clicks the element, then types
  • {Enter}, {Escape}, {ArrowDown}, {Shift>}A{/Shift} describe special keys
  • user.keyboard('…') types into whatever has focus
  • user.tab() moves focus like the Tab key

♿ Accessibility

  • Test keyboard paths with user.tab() and user.keyboard('{Enter}') so keyboard support can't regress

Version Notes

  • user-event v14: all APIs are async; call userEvent.setup() before rendering
  • React 19 act is imported from react; RTL re-exports it

Code Explained

userEvent.setup() creates a session that tracks pointer and keyboard state
{Enter} submits the form after typing
user.tab() then toHaveFocus() checks keyboard order
selectOptions and upload cover selects and file inputs
hover then findByRole('tooltip') waits for the tooltip to appear

user-event in Practice

import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';

test('adds a todo with the keyboard', async () => {
  const user = userEvent.setup();
  render(<TodoApp />);

  const input = screen.getByRole('textbox', { name: 'New todo' });
  await user.type(input, 'Buy milk{Enter}');

  expect(screen.getByRole('listitem')).toHaveTextContent('Buy milk');
  expect(input).toHaveValue('');
});

test('toggles and deletes', async () => {
  const user = userEvent.setup();
  render(<TodoApp initial={[{ id: '1', text: 'Walk dog' }]} />);

  await user.click(screen.getByRole('checkbox', { name: 'Walk dog' }));
  expect(screen.getByRole('checkbox')).toBeChecked();

  await user.tab();
  expect(screen.getByRole('button', { name: 'Delete' })).toHaveFocus();
  await user.keyboard('{Enter}');
  expect(screen.queryByRole('listitem')).not.toBeInTheDocument();
});

test('select and upload', async () => {
  const user = userEvent.setup();
  render(<ProfileForm />);
  await user.selectOptions(screen.getByLabelText('Plan'), 'pro');
  const file = new File(['img'], 'me.png', { type: 'image/png' });
  await user.upload(screen.getByLabelText('Avatar'), file);
  await user.hover(screen.getByRole('button', { name: 'Help' }));
  expect(await screen.findByRole('tooltip')).toBeVisible();
});

⚠ Common Mistakes

  • Forgetting await on user-event calls
  • Calling userEvent.click without setup() in v14
  • Wrapping every call in act (RTL already does)

✓ Tips & Best Practices

  • Create user before render in each test
  • Assert on visible results, not handler calls
  • Write a setup() helper that renders and returns user plus key elements

Quick Summary

  • const user = userEvent.setup()
  • await user.click/type/keyboard
  • {Enter} for special keys
  • fireEvent only for edge cases
