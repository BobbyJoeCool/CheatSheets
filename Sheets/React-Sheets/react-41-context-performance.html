consumers re-render · memoizing value · splitting contexts · composition before context · when to use a store

When Context Gets Slow

Every component that reads a context re-renders when its value changes, even if it only uses one field. Providing a new object every render (value={{ user, setUser }}) makes all readers re-render whenever the provider re-renders. Memoize the value, split contexts by how often they change, and remember that composition often removes the need for context. For high-frequency global state, use a store with selectors.

Notes

  • React compares the provided value with Object.is
  • memo on a child does not block context updates it reads
  • The React Compiler memoizes { user, setUser } objects for you
  • Context is a transport, not a state manager: it has no selectors

♿ Accessibility

  • Frequent context churn can re-render focus-sensitive widgets and reset their transient state

Version Notes

  • Context selectors are not part of React 19; libraries like use-context-selector or stores fill the gap
  • React Compiler 1.0 (October 2025) auto-memoizes provider values

Code Explained

The object literal is recreated each render, so the value always differs
useMemo keeps the same object until user or login change

Passing <Avatar user> as JSX skips the middle layers entirely
A selector re-renders only when cart.count changes

Stable Values and Split Contexts

// ✗ New object every render -> every reader re-renders
function AuthProvider({ children }) {
  const [user, setUser] = useState(null);
  return (
    <AuthContext value={{ user, setUser }}>{children}</AuthContext>
  );
}

// ✓ Memoize (or let the React Compiler do it)
function AuthProvider2({ children }) {
  const [user, setUser] = useState(null);
  const login = useCallback(async (c) => setUser(await api.login(c)), []);
  const value = useMemo(() => ({ user, login }), [user, login]);
  return <AuthContext value={value}>{children}</AuthContext>;
}

// ✓ Split fast-changing from slow-changing data
<SettingsContext value={settings}>       {/* rarely changes */}
  <CursorContext value={cursor}>         {/* changes on mousemove */}
    <Canvas />
  </CursorContext>
</SettingsContext>

// ✓ Composition instead of context
function Layout({ user }) {
  return <Page header={<Avatar user={user} />} />;
}

// ✓ Store with selectors for high-frequency state
const count = useStore((s) => s.cart.count);  // Zustand

⚠ Common Mistakes

  • Putting rapidly changing values (scroll, input text) in app-wide context
  • Expecting memo to stop context-triggered re-renders
  • Memoizing the value but recreating the functions inside it each render

✓ Tips & Best Practices

  • Profile before optimizing; context is often fast enough
  • Pass IDs through context and let components fetch details
  • Move the provider down to wrap only the part of the tree that needs it

Quick Summary

  • Readers re-render on value change
  • Stable value object
  • Split by update frequency
  • Stores for hot global state
