Accessible Markup in JSX

React renders whatever HTML you write, so accessibility starts with semantic elements: <button> for actions, <a href> for navigation, <label> for inputs, headings in order, and landmarks (<header>, <nav>, <main>). JSX supports every ARIA attribute with its HTML spelling (aria-label, aria-expanded). Use htmlFor and useId to link labels, and lint with eslint-plugin-jsx-a11y.

Notes

  • aria-* and role keep lowercase, hyphenated HTML names
  • Boolean ARIA values can be booleans in JSX: aria-expanded={open}
  • First rule of ARIA: use a native element before adding a role
  • Fragments let components return valid list and table structures

♿ Accessibility

  • Every image needs alt; use alt="" for decorative ones
  • Icon-only buttons need an accessible name (aria-label or visually hidden text)
  • Never remove focus outlines without a visible replacement

Version Notes

  • React 19 adds no ARIA-specific APIs; useId (React 18) is the standard way to link labels
  • WCAG 2.2 is the current W3C recommendation for conformance targets

Code Explained

role="search" marks the form as a search landmark
useId links the label and hint to the input
aria-label names the icon button; the icon is hidden from screen readers
aria-expanded and aria-controls describe the disclosure state
A native <button> is focusable and responds to Enter and Space

Semantic, Labeled, Linted

function SearchForm({ onSearch }) {
  const id = useId();
  return (
    <form role="search" onSubmit={onSearch}>
      <label htmlFor={id}>Search products</label>
      <input id={id} type="search" name="q"
        aria-describedby={`${id}-hint`} />
      <p id={`${id}-hint`}>Try “red shoes”</p>
      <button type="submit">Search</button>
    </form>
  );
}

function IconButton({ label, icon, ...props }) {
  return (
    <button type="button" aria-label={label} {...props}>
      <span aria-hidden="true">{icon}</span>
    </button>
  );
}

function Disclosure({ title, children }) {
  const [open, setOpen] = useState(false);
  const panelId = useId();
  return (
    <>
      <button aria-expanded={open} aria-controls={panelId}
        onClick={() => setOpen(!open)}>{title}</button>
      <div id={panelId} hidden={!open}>{children}</div>
    </>
  );
}

JSX Accessibility Attributes

AttributeUse
htmlForlink label → input
aria-labelname without visible text
aria-labelledbyname from another element
aria-describedbyhints and errors
aria-expanded / aria-pressedtoggle state
aria-hiddenhide decorative content

Element Choice

NeedUse
Action<button>
Navigation<a href> / <Link>
Page regions<header>, <nav>, <main>, <footer>
Lists<ul>/<ol> + <li>
Data<table> with <th scope>

⚠ Common Mistakes

  • Clickable <div>s and <span>s
  • Placeholder text used as the only label
  • aria-label on non-interactive elements where it's ignored

✓ Tips & Best Practices

  • Run axe DevTools or Lighthouse on every page
  • Test with keyboard only: Tab, Shift+Tab, Enter, Space, Escape
  • Use React Aria or Radix for complex widgets

Quick Summary

  • Semantic elements first
  • Label everything (htmlFor, useId)
  • ARIA for state, not structure
  • Lint with jsx-a11y
