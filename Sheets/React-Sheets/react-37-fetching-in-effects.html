Fetching Data in Effects

fetch in useEffect · AbortController · ignore flag · loading/error state · race conditions · when to use a library

Fetching Without a Library

You can fetch inside useEffect, but you must handle loading, errors and race conditions: if the input changes quickly, an older response can arrive after a newer one. Cancel stale requests with an AbortController in the cleanup, or set an ignore flag. For real apps, prefer TanStack Query, SWR or a framework loader, which add caching, deduping and retries.

Notes

  • The effect callback can't be async; define an async function inside and call it
  • AbortController cancels the network request; ignore flags just drop the result
  • fetch only rejects on network errors; check res.ok for HTTP errors
  • Effects don't run on the server, so this pattern can't prefetch during SSR

♿ Accessibility

  • Render loading and error text inside an element with role="status" or aria-live="polite"
  • Use aria-busy="true" on the region being updated

Version Notes

  • React 19's use() with Suspense offers a different approach for cached promises (sheet 47)
  • React docs recommend frameworks or data libraries over effect-based fetching

Code Explained

One status field avoids contradictory loading/error booleans
signal ties the request to the controller
Cleanup aborts the old request when userId changes or the component unmounts
AbortError is expected and ignored
res.ok turns 404s and 500s into errors

useEffect + AbortController

function UserProfile({ userId }) {
  const [state, setState] = useState({
    status: 'loading', user: null, error: null,
  });

  useEffect(() => {
    const controller = new AbortController();
    setState({ status: 'loading', user: null, error: null });

    async function load() {
      try {
        const res = await fetch(`/api/users/${userId}`, {
          signal: controller.signal,
        });
        if (!res.ok) throw new Error(`HTTP ${res.status}`);
        const user = await res.json();
        setState({ status: 'success', user, error: null });
      } catch (err) {
        if (err.name === 'AbortError') return;
        setState({ status: 'error', user: null, error: err });
      }
    }

    load();
    return () => controller.abort();
  }, [userId]);

  if (state.status === 'loading')
    return <p role="status">Loading…</p>;
  if (state.status === 'error')
    return <p role="alert">{state.error.message}</p>;
  return <h2>{state.user.name}</h2>;
}

⚠ Common Mistakes

  • useEffect(async () => …), which returns a promise instead of cleanup
  • Ignoring stale responses and showing the wrong user's data
  • Treating a 404 as success because fetch didn't throw

✓ Tips & Best Practices

  • Extract the pattern into a useFetch hook while learning
  • Switch to TanStack Query (sheet 77) before adding caching by hand
  • Show stale data with a spinner rather than blanking the UI on refetch

Quick Summary
