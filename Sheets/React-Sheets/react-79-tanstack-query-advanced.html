TanStack Query: Advanced

queryOptions · useSuspenseQuery · useInfiniteQuery · dependent queries · prefetchQuery · select · Devtools

Beyond the Basics

queryOptions() bundles a key and fetcher into a reusable, type-safe object you can pass to useQuery, useSuspenseQuery, prefetchQuery and getQueryData. useSuspenseQuery integrates with Suspense: data is always defined and loading is handled by the nearest boundary. useInfiniteQuery handles paginated feeds, dependent queries wait on other data via enabled, and select transforms data per component.

Notes

  • useSuspenseQuery throws errors to error boundaries
  • enabled: !!userId waits until userId exists
  • select re-runs only when data or the selector changes
  • Prefetch on hover or in a router loader to make navigation instant

♿ Accessibility

  • Infinite lists need a real Load more button as well as scroll triggers, and should announce new items

Version Notes

  • queryOptions and useSuspenseQuery are v5 features
  • initialPageParam is required for infinite queries in v5

Code Explained

userQuery(id) is the single definition of how to fetch a user
useSuspenseQuery suspends until data arrives, so no loading branch
enabled keeps the projects query idle until userId exists
getNextPageParam returns undefined to signal the last page
prefetchQuery warms the cache before the user clicks

queryOptions, Suspense, Infinite

import { queryOptions, useInfiniteQuery, useQuery,
  useSuspenseQuery, useQueryClient } from '@tanstack/react-query';

export const userQuery = (id) => queryOptions({
  queryKey: ['user', id],
  queryFn: () => api.get(`/users/${id}`),
  staleTime: 5 * 60_000,
});

function Profile({ id }) {
  const { data: user } = useSuspenseQuery(userQuery(id));
  return <h1>{user.name}</h1>;            // data is defined
}

// Dependent query + select
function Projects({ userId }) {
  const { data: names } = useQuery({
    queryKey: ['projects', userId],
    queryFn: () => api.get(`/projects?owner=${userId}`),
    enabled: !!userId,
    select: (projects) => projects.map((p) => p.name),
  });
}

// Infinite feed
function Feed() {
  const { data, fetchNextPage, hasNextPage, isFetchingNextPage } =
    useInfiniteQuery({
      queryKey: ['feed'],
      queryFn: ({ pageParam }) => api.get(`/feed?cursor=${pageParam}`),
      initialPageParam: 0,
      getNextPageParam: (last) => last.nextCursor ?? undefined,
    });
  const posts = data?.pages.flatMap((p) => p.items) ?? [];
  return <>
    {posts.map((p) => <Post key={p.id} post={p} />)}
    <button onClick={() => fetchNextPage()}
      disabled={!hasNextPage || isFetchingNextPage}>Load more</button>
  </>;
}

// Prefetch on hover
const qc = useQueryClient();
<Link to={`/users/${id}`}
  onMouseEnter={() => qc.prefetchQuery(userQuery(id))} />;

⚠ Common Mistakes

  • Calling useSuspenseQuery without a Suspense boundary above
  • Building infinite lists with page-number state and manual merging
  • Inline select functions that do heavy work on every render

✓ Tips & Best Practices

  • Export queryOptions factories from feature modules
  • Prefetch in route loaders: await qc.ensureQueryData(userQuery(id))
  • Use keepPreviousData for paginated tables
