<Outlet> · layout routes · index routes · pathless routes · useOutletContext · 404 route

Layouts with Outlet

Nested routes share UI. A parent route renders the common layout (header, sidebar) and an <Outlet /> where the matching child route appears. Index routes render at the parent's own URL. Layout routes have no path and only add UI; pathless groupings help share loaders or error boundaries. Each route can define an ErrorBoundary that catches errors from its loader, action or component.

Notes

  • The URL /dashboard/settings renders Dashboard with Settings in its outlet
  • useOutletContext() reads a value passed with <Outlet context={…} />
  • A child's error boundary replaces only that child, keeping the parent layout
  • useRouteError() reads the error inside an error boundary

♿ Accessibility

  • Keep landmark structure in the layout: one <nav>, one <main> that wraps the <Outlet>
  • Error boundary pages should keep the layout's navigation so users can recover

Version Notes

  • Route-level ErrorBoundary and HydrateFallback exist in data and framework modes
  • isRouteErrorResponse(error) detects thrown Responses and data() errors

Code Explained

AppLayout wraps every page; DashboardLayout wraps dashboard pages
index: true renders Overview at /dashboard
AuthLayout adds UI for /login without adding a URL segment
<Outlet context> passes user to whichever child renders
AppError handles 404s and thrown errors for the whole app

Nested Routes

import { Outlet, useOutletContext, useRouteError,
  isRouteErrorResponse } from 'react-router';

const router = createBrowserRouter([
  {
    path: '/',
    Component: AppLayout,
    ErrorBoundary: AppError,
    children: [
      { index: true, Component: Home },
      {
        path: 'dashboard',
        Component: DashboardLayout,
        children: [
          { index: true, Component: Overview },
          { path: 'settings', Component: Settings },
        ],
      },
      { Component: AuthLayout,            // layout route: no path
        children: [{ path: 'login', Component: Login }] },
    ],
  },
]);

function DashboardLayout() {
  const user = useUser();
  return (
    <div className="dashboard">
      <aside><DashboardNav /></aside>
      <main><Outlet context={{ user }} /></main>
    </div>
  );
}

function Settings() {
  const { user } = useOutletContext();
  return <h1>Settings for {user.name}</h1>;
}

function AppError() {
  const error = useRouteError();
  if (isRouteErrorResponse(error))
    return <h1>{error.status} {error.statusText}</h1>;
  return <h1>Something went wrong</h1>;
}

⚠ Common Mistakes

  • Forgetting <Outlet /> so child routes never appear
  • Leading slashes in child paths (/settings makes it absolute)
  • One app-level error boundary only, which hides the layout

✓ Tips & Best Practices

  • Use handle on routes plus useMatches() to build breadcrumbs
  • Use lazy on routes to split code per route
  • Give each major section its own error boundary

Quick Summary

  • Parent layout + <Outlet />
  • index: true for the default child
  • Pathless layout routes
  • ErrorBoundary per route
