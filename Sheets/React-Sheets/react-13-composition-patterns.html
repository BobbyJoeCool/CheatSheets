Composition Patterns

compound components · render props · higher-order components · components as props · Children API · cloneElement (legacy)

Reusable Structure

Beyond children, a few patterns share structure between components. Compound components split one widget into parts that coordinate through context (<Tabs>, <Tabs.List>, <Tabs.Panel>). Render props pass a function that returns JSX. Higher-order components wrap a component to add behavior. Custom hooks have replaced most render props and HOCs, but you will still meet all three in libraries.

Notes

  • Compound components keep their shared state private and expose a readable API
  • A render prop can be children as a function: <Mouse>{pos => …}</Mouse>
  • HOCs are named withX and return a new component
  • Children.map and cloneElement inspect or modify children; both are fragile

♿ Accessibility

  • Compound widgets must wire ARIA between parts (role="tablist", aria-controls, aria-selected)
  • Headless libraries (React Aria, Radix) supply this wiring; prefer them for tabs, menus and listboxes

Version Notes

  • React docs list Children and cloneElement as legacy APIs
  • Custom hooks (16.8+) are the default way to share logic

Code Explained

Tabs owns the state; parts read it through context
<TabsContext value> is the React 19 provider syntax
Attaching parts as Tabs.Tab groups the API under one import
Each Tab sets aria-selected so assistive tech knows the active tab
Callers arrange the parts however they want

Compound Tabs

import { createContext, use, useState } from 'react';

const TabsContext = createContext(null);

export function Tabs({ defaultValue, children }) {
  const [value, setValue] = useState(defaultValue);
  return (
    <TabsContext value={{ value, setValue }}>
      {children}
    </TabsContext>
  );
}

Tabs.Tab = function Tab({ value, children }) {
  const ctx = use(TabsContext);
  const selected = ctx.value === value;
  return (
    <button role="tab" aria-selected={selected}
      onClick={() => ctx.setValue(value)}>
      {children}
    </button>
  );
};

Tabs.Panel = function Panel({ value, children }) {
  const ctx = use(TabsContext);
  return ctx.value === value
    ? <div role="tabpanel">{children}</div> : null;
};

// Usage
<Tabs defaultValue="a">
  <div role="tablist">
    <Tabs.Tab value="a">Profile</Tabs.Tab>
    <Tabs.Tab value="b">Billing</Tabs.Tab>
  </div>
  <Tabs.Panel value="a">…</Tabs.Panel>
</Tabs>

⚠ Common Mistakes

  • Using cloneElement to inject props that break when children are wrapped
  • Stacking several HOCs and losing track of where props come from
  • Building tabs or menus without keyboard support

✓ Tips & Best Practices

  • Reach for a custom hook first, compound components second
  • Throw a clear error when a part is used outside its parent
  • Use a headless library for complex ARIA widgets

Quick Summary

  • Compound = parts sharing context
  • Render prop = function returning JSX
  • HOC = withX(Component)
  • Hooks replace most of these
