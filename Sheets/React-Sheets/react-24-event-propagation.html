Bubbling, Capture and Defaults

Most React events bubble: a click on a button also runs onClick handlers on its ancestors, innermost first. Call e.stopPropagation() to stop it. Add Capture to a prop name (onClickCapture) to run during the capture phase, before children. e.preventDefault() stops the browser's default action (submitting a form, following a link) but doesn't stop bubbling.

Notes

  • onScroll is the main React event that doesn't bubble
  • e.target is where the event started; e.currentTarget is the element whose handler is running
  • React delegates listeners to the root container
  • Native listeners added with addEventListener run separately from React's

♿ Accessibility

  • Stopping propagation can break shortcut handlers and focus traps higher up; stop it only where needed
  • Don't preventDefault on keyboard events that users rely on (Tab, Escape) unless you replace the behavior

Version Notes

  • React 17 moved delegation from document to the root, which made nested React apps and native listeners interoperate

Code Explained

Without stopPropagation, clicking Delete would also call onOpen
preventDefault stops the full-page form submission
e.currentTarget is the <form>, so FormData reads all its fields
onClickCapture sees every click inside before children handle it
Delegating on <ul> and reading e.target handles many items with one listener

Propagation in Practice

function Card({ onOpen, onDelete }) {
  return (
    <article onClick={onOpen} className="card">
      <h3>Report</h3>
      <button
        onClick={(e) => {
          e.stopPropagation();     // don't also open the card
          onDelete();
        }}
      >
        Delete
      </button>
    </article>
  );
}

function SignupForm({ onSignup }) {
  return (
    <form
      onSubmit={(e) => {
        e.preventDefault();        // no page reload
        onSignup(new FormData(e.currentTarget));
      }}
    >
      <input name="email" type="email" required />
      <button>Sign up</button>
    </form>
  );
}

⚠ Common Mistakes

  • Returning false from a handler to prevent defaults
  • Using e.target when you mean the element with the handler
  • Stopping propagation everywhere and breaking analytics or menus

✓ Tips & Best Practices

  • Prefer passing a callback and letting the child decide over relying on bubbling
  • Use capture handlers for logging, not for app logic
  • Add native listeners in effects and remove them in cleanup

Quick Summary

  • Events bubble child → parent
  • stopPropagation stops bubbling
  • preventDefault stops browser action
  • *Capture runs first
