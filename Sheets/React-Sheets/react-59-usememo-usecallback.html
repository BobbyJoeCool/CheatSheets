useMemo & useCallback

caching calculations · stable callbacks · dependency arrays · when it's worth it · measuring first

Caching Values and Functions

useMemo(fn, deps) caches the result of a calculation and recomputes only when a dependency changes. useCallback(fn, deps) caches the function itself. Use them for expensive calculations, for props passed to memo components, and for values used as effect dependencies. They're performance hints, not guarantees: React may discard caches, so code must still be correct without them.

Notes

  • useCallback(fn, deps) equals useMemo(() => fn, deps)
  • Dependencies follow the same rules as effects; the linter checks them
  • Expensive means roughly 1ms or more; measure with console.time
  • The React Compiler inserts equivalent memoization automatically

♿ Accessibility

  • Not an accessibility concern directly; faster renders keep input and focus responsive

Version Notes

  • Unchanged in React 19; with React Compiler 1.0, most new code doesn't need them
  • The compiler's lint rules warn when manual memoization conflicts with its own

useMemo and useCallback

import { useCallback, useMemo, useState } from 'react';

function ProductTable({ products, query, sortBy }) {
  // Expensive: only recompute when inputs change
  const visible = useMemo(() => {
    console.time('filter');
    const result = products
      .filter((p) => p.name.toLowerCase().includes(query))
      .toSorted((a, b) => a[sortBy] - b[sortBy]);
    console.timeEnd('filter');
    return result;
  }, [products, query, sortBy]);

  // Stable function for a memoized child
  const handleAdd = useCallback((id) => {
    cart.add(id);
  }, []);

  // Stable object for an effect dependency
  const options = useMemo(() => ({ query, limit: 50 }), [query]);
  useEffect(() => { track('search', options); }, [options]);

  return <Rows items={visible} onAdd={handleAdd} />;
}

// ✗ Not worth it: cheap calculation
const total = useMemo(() => a + b, [a, b]);

// ✓ Just compute it
const total2 = a + b;

⚠ Common Mistakes

  • Missing dependencies, which cause stale values
  • Memoizing everything and making code harder to read
  • Relying on memoization for correctness (e.g. to avoid infinite effects)

✓ Tips & Best Practices

  • Measure with production builds; dev mode is slower
  • Restructure (move state down) before memoizing
  • Turn on the React Compiler and delete most manual memos

Quick Summary

  • useMemo caches values
  • useCallback caches functions
  • Only for expensive or identity-sensitive cases
  • The Compiler automates both
