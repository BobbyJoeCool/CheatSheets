SWR

useSWR · fetcher · revalidateOnFocus · mutate · useSWRMutation · conditional keys · SWRConfig

Stale-While-Revalidate

SWR, from Vercel, is a small data-fetching hook named after the HTTP caching strategy: return cached (stale) data immediately, then revalidate in the background and update. useSWR(key, fetcher) returns data, error, isLoading and mutate. The key (usually the URL) identifies the cache entry; pass null to skip fetching. useSWRMutation handles remote mutations.

Notes

  • Requests with the same key are deduplicated
  • Revalidates on focus, on reconnect and on mount by default
  • mutate() (bound) revalidates this key; global mutate(key, data) updates any key
  • SWRConfig sets the fetcher and options for a subtree

♿ Accessibility

  • Show isLoading and error states with live-region text
  • Avoid jumping content when revalidated data arrives; keep layout stable

Version Notes

  • SWR 2.x is current; supports React 18 and 19
  • useSWRMutation lives in swr/mutation; useSWRInfinite in swr/infinite

Code Explained

The global fetcher in SWRConfig is used when useSWR gets only a key
The URL key caches each user separately
A null key keeps the team request idle until the user loads
Bound mutate() revalidates just this key
trigger(arg) calls updateUser and updates the cache with its result

useSWR and useSWRMutation

import useSWR, { SWRConfig, useSWRConfig } from 'swr';
import useSWRMutation from 'swr/mutation';

const fetcher = async (url) => {
  const res = await fetch(url);
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return res.json();
};

export function App() {
  return (
    <SWRConfig value={{ fetcher, revalidateOnFocus: true }}>
      <Profile id="42" />
    </SWRConfig>
  );
}

function Profile({ id }) {
  const { data, error, isLoading, mutate } = useSWR(`/api/users/${id}`);
  // Dependent: skip until data.teamId exists
  const { data: team } = useSWR(data ? `/api/teams/${data.teamId}` : null);

  if (isLoading) return <p role="status">Loading…</p>;
  if (error) return <p role="alert">{error.message}</p>;
  return (
    <>
      <h1>{data.name}</h1>
      <button onClick={() => mutate()}>Refresh</button>
    </>
  );
}

async function updateUser(url, { arg }) {
  return fetch(url, { method: 'PATCH', body: JSON.stringify(arg) })
    .then((r) => r.json());
}

function Rename({ id }) {
  const { trigger, isMutating } =
    useSWRMutation(`/api/users/${id}`, updateUser);
  return <button disabled={isMutating}
    onClick={() => trigger({ name: 'Ada' })}>Rename</button>;
}

⚠ Common Mistakes

  • Fetcher that doesn't throw on HTTP errors
  • Building keys from objects that change identity every render
  • Using global mutate with a key that doesn't match exactly

✓ Tips & Best Practices

  • Use URLs as keys; they're unique and readable
  • Set dedupingInterval and refreshInterval per use case
  • Pick one data library per app; don't mix SWR and TanStack Query

Quick Summary

  • useSWR(key, fetcher)
  • Stale first, then revalidate
  • null key = don't fetch
  • useSWRMutation for writes
