Inspecting Components

React DevTools is a browser extension (Chrome, Firefox, Edge) that adds Components and Profiler tabs. Components shows the tree as React sees it: select a component to read and edit its props, state, hooks and context, jump to its source, and see its owner (the component that rendered it). Profiler records renders so you can see what rendered, why, and how long it took.

Notes

  • $r in the console refers to the selected component
  • Hook values are listed in call order; useDebugValue labels custom hooks
  • Enable Highlight updates when components render to spot extra renders
  • Standalone react-devtools (npm) debugs React Native and Safari

♿ Accessibility

  • Use the browser's Accessibility panel alongside React DevTools to check the rendered roles and names

Version Notes

  • DevTools shows a Memo ✨ badge on components optimized by the React Compiler
  • React 19.2 adds Performance-panel tracks (Scheduler and Components) in Chrome DevTools

Code Explained

$r lets you poke at the selected component in the console
The second argument to useDebugValue formats the label lazily
Named functions inside memo show as Row instead of Anonymous
<Profiler onRender> logs timing for one subtree
Record why each component rendered explains each render in the Profiler

Debugging Workflow

// 1. Select a component in the Components tab, then:
$r                     // selected component instance/props
$r.props               // (class components)

// 2. Label custom hooks
function useCart() {
  const cart = useSyncExternalStore(store.subscribe, store.get);
  useDebugValue(cart, (c) => `${c.items.length} items`);
  return cart;
}

// 3. Name components so they show up clearly
const Row = memo(function Row(props) { /* … */ });

// 4. Measure in code
import { Profiler } from 'react';
<Profiler id="Feed" onRender={(id, phase, ms) =>
  console.log(id, phase, ms.toFixed(1))}>
  <Feed />
</Profiler>

// 5. Log why a render happened (dev)
useEffect(() => {
  console.log('render', { props });
});

// Profiler tab settings:
//   ✓ Record why each component rendered
//   ✓ Highlight updates when components render

⚠ Common Mistakes

  • Profiling the development build and trusting absolute timings
  • Anonymous arrow components that show as Anonymous in the tree
  • Leaving console.log render tracing in committed code

✓ Tips & Best Practices

  • Use the profiling build of react-dom for realistic numbers
  • Toggle Suspense and error states from DevTools to test fallbacks
  • Check the Compiler badge to confirm components are optimized
