React Router: Framework Mode

routes.ts · route modules · typegen · SSR & prerender · clientLoader · ErrorBoundary export

Full-Stack React Router

Framework mode turns React Router into a full-stack framework (formerly Remix). The @react-router/dev Vite plugin reads a route config from app/routes.ts; each entry points to a route module that exports a default component plus optional loader, action, clientLoader, meta and ErrorBoundary. Type generation produces Route types per module, so loader data and params are typed. Choose SSR, static prerendering or SPA output in react-router.config.ts.

Notes

  • npx create-react-router@latest scaffolds a framework-mode app
  • loader runs on the server; clientLoader runs in the browser
  • react-router typegen writes ./+types/<route> files (also runs during dev)
  • ssr: false builds a SPA; prerender lists URLs to render at build time

♿ Accessibility

  • Server-rendered HTML is readable before JavaScript loads, which helps slow connections and assistive tech
  • Export meta per route for unique titles

Version Notes

  • Framework mode arrived in v7 (Remix merged into React Router)
  • v8 keeps the same file conventions; Remix v2 is end of life

Code Explained

routes.ts lists routes explicitly; helpers build the config
./+types/product is generated, so params.id and loaderData are typed
The loader runs on the server and can query the database directly
meta sets the page title from loader data
The config enables SSR and prerenders two static pages

routes.ts and a Route Module

// app/routes.ts
import { type RouteConfig, index, layout, route }
  from '@react-router/dev/routes';

export default [
  index('routes/home.tsx'),
  route('products/:id', 'routes/product.tsx'),
  layout('routes/auth-layout.tsx', [
    route('login', 'routes/login.tsx'),
  ]),
] satisfies RouteConfig;

// app/routes/product.tsx
import type { Route } from './+types/product';

export async function loader({ params }: Route.LoaderArgs) {
  const product = await db.product(params.id);   // server only
  if (!product) throw new Response('Not found', { status: 404 });
  return { product };
}

export function meta({ data }: Route.MetaArgs) {
  return [{ title: `${data?.product.name} | Shop` }];
}

export default function Product({ loaderData }: Route.ComponentProps) {
  return <h1>{loaderData.product.name}</h1>;
}

export function ErrorBoundary({ error }: Route.ErrorBoundaryProps) {
  return <p role="alert">Couldn't load this product.</p>;
}

// react-router.config.ts
import type { Config } from '@react-router/dev/config';
export default { ssr: true, prerender: ['/', '/about'] }
  satisfies Config;

⚠ Common Mistakes

  • Importing server-only modules (DB clients) into code that runs in the browser
  • Editing generated +types files
  • Mixing data-mode createBrowserRouter code into a framework app

✓ Tips & Best Practices

  • Name server-only files *.server.ts so they can't be bundled for the client
  • Run react-router typegen in CI before tsc
  • Start with SPA mode and switch on SSR later if you need it

Quick Summary

  • Vite plugin + app/routes.ts
  • Route modules export loader/action/UI
  • Generated Route types
  • SSR, prerender or SPA
