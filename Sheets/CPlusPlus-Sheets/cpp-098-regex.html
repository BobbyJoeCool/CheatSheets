Regular Expressions

std::regex · regex_match · regex_search · regex_replace · std::smatch · sregex_iterator · performance caveats

std::regex

<regex> (C++11) provides regular expressions using ECMAScript syntax by default. std::regex_match tests whether the whole string matches, std::regex_search finds the first match anywhere, std::regex_replace substitutes matches, and std::sregex_iterator walks all matches. Results come back in a std::smatch with capture groups. The standard implementation is known to be slow; see the Regex set for pattern syntax.

Notes

  • Use raw strings R"(\d+)" to avoid double escaping
  • Constructing a std::regex is expensive: build once, reuse
  • std::smatch for std::string, std::cmatch for const char*
  • Flags: std::regex::icase, std::regex::multiline (C++17)

match, search, replace, iterate

#include <regex>

const std::regex date{R"((\d{4})-(\d{2})-(\d{2}))"};   // compile once
std::string s = "Released 2026-10-11, patched 2026-11-02.";

std::regex_match("2026-10-11", date);       // true (whole string)
std::regex_match(s, date);                  // false

std::smatch m;
if (std::regex_search(s, m, date)) {
    m[0];               // "2026-10-11"  whole match
    m[1];               // "2026"        group 1
    m.position(0);      // 9
}
std::regex_replace(s, date, "$3/$2/$1");    // "...11/10/2026, ...02/11/2026."

for (std::sregex_iterator it{s.begin(), s.end(), date}, end; it != end; ++it)
    std::println("{}", it->str());          // each date

std::regex word{R"(\bcolou?r\b)", std::regex::icase};

Code Explained

R"(…)" — raw string; backslashes stay literal
regex_match — must match the entire input
regex_search — first match anywhere; groups in m[1], m[2]…
$1, $2 — group references in the replacement
sregex_iterator — loop over every match
icase — case-insensitive matching

⚠ Common Mistakes

  • Constructing std::regex inside a loop; compilation is costly. Make it static const
  • Using regex_match when you meant "contains"; use regex_search
  • Running std::regex on large inputs in hot paths; it can be orders of magnitude slower than alternatives

✓ Tips & Best Practices

  • For performance, use CTRE (compile-time regex), RE2, or PCRE2
  • For simple checks, starts_with, contains, and find are faster and clearer
  • Use named sub-expressions in comments since std::regex has no named groups

Quick Summary

  • regex_match — whole string
  • regex_search — first match + groups
  • regex_replace — substitution with $n
  • build once — regex construction is expensive
