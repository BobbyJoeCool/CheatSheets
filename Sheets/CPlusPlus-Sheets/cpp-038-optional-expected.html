Sheet 038

std::optional & std::expected

std::optional · std::nullopt · value_or · std::expected · std::unexpected · and_then / transform / or_else

Errors as Values

Not every failure deserves an exception. std::optional<T> (C++17) holds either a T or nothing, good for "not found". std::expected<T, E> (C++23) holds either a value or an error describing what went wrong, like Rust's Result. Both support monadic chaining with and_then, transform, and or_else, so you can build pipelines without nested ifs.

Access

  • if (opt) / opt.has_value() — check first
  • *opt — unchecked; opt.value() — throws if empty
  • opt.value_or(def) — fallback value
  • exp.error() — the error when !exp

optional & expected

#include <optional>
#include <expected>

std::optional<User> findUser(int id) {
    if (auto it = db.find(id); it != db.end()) return it->second;
    return std::nullopt;                      // "no value"
}
auto name = findUser(7).transform(&User::name).value_or("guest");

enum class ParseErr { Empty, NotNumber };
std::expected<int, ParseErr> parsePort(std::string_view s) {
    if (s.empty()) return std::unexpected(ParseErr::Empty);
    int v{};
    auto [p, ec] = std::from_chars(s.data(), s.data() + s.size(), v);
    if (ec != std::errc{}) return std::unexpected(ParseErr::NotNumber);
    return v;
}
auto r = parsePort("8080");
if (r) std::println("port {}", *r);           // port 8080
auto checked = parsePort(arg)
    .and_then([](int p) -> std::expected<int, ParseErr> { return p; })
    .transform([](int p) { return p + 1; });

Code Explained

std::nullopt — the empty state of an optional
.transform(f) — apply f if there's a value, keep empty otherwise
std::unexpected(e) — construct the error alternative
if (r) — true when it holds a value
.and_then(f) — chain functions that themselves return expected

⚠ Common Mistakes

  • Dereferencing *opt without checking; that's UB when empty
  • Using std::optional<T&>; it isn't allowed before C++26. Use a pointer or std::reference_wrapper
  • Returning std::optional<bool> and testing if (opt), which checks presence, not the bool

✓ Tips & Best Practices

  • Return std::expected from parsers and I/O helpers; callers see the error type in the signature
  • Use value_or for defaults instead of if/else
  • Mark functions returning optional/expected [[nodiscard]]

Quick Summary

  • std::optional<T> — value or nothing
  • std::expected<T, E> — value or error (C++23)
  • value_or — fallback
  • and_then / transform — chain without nesting
