Compilation Model & Linking

preprocess → compile → link · translation units · object files · ODR · static .a/.lib vs shared .so/.dll · "undefined reference"

From Source to Executable

Building C++ is a three-stage pipeline. The preprocessor expands #include and macros, producing a translation unit (TU). The compiler turns each TU into an object file independently. The linker combines object files and libraries into one executable, resolving every name used in one TU to its definition in another. Most confusing build errors make sense once you know which stage produced them.

The ODR

  • One Definition Rule: each function/variable has exactly one definition program-wide
  • Declarations (in headers) may repeat; definitions (in .cpp) may not
  • inline functions and templates may be defined in headers: once per TU, all identical
  • Breaking the ODR is often silent UB, not a compile error

Building in Stages

g++ -E main.cpp -o main.ii      # 1. preprocess only
g++ -c main.cpp -o main.o       # 2. compile one TU → object file
g++ -c math.cpp -o math.o
g++ main.o math.o -o app        # 3. link objects → executable

# Static library: archive of .o files, copied into the app
ar rcs libmath.a math.o
g++ main.o -L. -lmath -o app

# Shared library: loaded at run time
g++ -fPIC -shared math.cpp -o libmath.so
g++ main.o -L. -lmath -Wl,-rpath,. -o app

nm -C math.o                    # list symbols in an object file

Code Explained

-E — stop after preprocessing; shows what the compiler really sees
-c — compile without linking; one .o per .cpp
ar rcs — bundle objects into a static .a archive
-fPIC -shared — build position-independent shared library
-Wl,-rpath,. — tell the loader where to find .so at run time
nm -C — dump (demangled) symbols to debug link errors

⚠ Common Mistakes

  • Putting a non-inline function definition in a header included by two .cpp files, which causes "multiple definition"
  • Compiling only main.cpp and getting "undefined reference" because math.cpp was never passed to the build
  • Listing libraries before the objects that use them (-lmath main.o); GNU ld resolves left to right

✓ Tips & Best Practices

  • Read the first error only; later errors are often fallout from it
  • Use extern "C" when linking against C libraries to stop C++ name mangling
  • Let a build system (CMake) track which TUs need recompiling instead of hand-written commands

Quick Summary

  • preprocess → compile → link — the three build stages
  • translation unit — one .cpp after preprocessing
  • ODR — one definition per entity across the program
  • undefined reference — linker error: missing definition
