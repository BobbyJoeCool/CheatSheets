Sheet 015

Constants: const, constexpr, constinit

const · constexpr variables · constinit · top-level vs low-level const · static_assert · magic numbers

Immutability Levels

const means "can't be modified through this name" and can be initialized at run time. constexpr means "computable at compile time" and implies const, so the value can be used for array sizes, template arguments, and static_assert. constinit (C++20) guarantees a static/global is initialized at compile time but leaves it mutable, which avoids the static initialization order problem.

Pointers & const

  • const int* p — pointee is const (low-level)
  • int* const p — pointer itself is const (top-level)
  • Read declarations right to left: "p is a const pointer to int"
  • constexpr variables must have a constant initializer

const, constexpr, constinit

const int limit = readConfig();     // run-time value, then frozen
// limit = 5;                       // ERROR: assignment to const

constexpr int kSize = 16;           // compile-time constant
std::array<int, kSize> buf{};       // OK: needs a constant
static_assert(kSize % 8 == 0, "kSize must be a multiple of 8");

constexpr double kPi = 3.14159265358979;
constexpr int sq(int x) { return x * x; }
constexpr int kArea = sq(kSize);    // 256, computed by compiler

constinit int counter = 0;          // static init guaranteed
void tick() { ++counter; }          // still mutable

int n = 10;
const int* p1 = &n;   // *p1 = 3;  ERROR   p1 = &other; OK
int* const p2 = &n;   // *p2 = 3;  OK      p2 = &other; ERROR
const int* const p3 = &n;           // neither may change

Code Explained

const — read-only after initialization; value may come from run time
constexpr — must be known at compile time; usable in constant expressions
static_assert — compile-time check with a message
constinit — only for static/thread storage; not const
const int* vs int* const — what the const sits next to is what's frozen

⚠ Common Mistakes

  • Using #define for constants; macros ignore scope and types. Use constexpr
  • Expecting const int x = f(); to work as an array bound; only constexpr values do
  • Casting away const with const_cast and writing to an object that was defined const is UB

✓ Tips & Best Practices

  • Make everything const by default; only drop it when the variable truly needs to change
  • In headers, use inline constexpr for namespace-scope constants so every TU shares one definition
  • Use static_assert to lock in assumptions like sizeof(Packet) == 16

Quick Summary

  • const — read-only after init
  • constexpr — compile-time constant
  • constinit — compile-time init, still mutable
  • static_assert — compile-time assertion
