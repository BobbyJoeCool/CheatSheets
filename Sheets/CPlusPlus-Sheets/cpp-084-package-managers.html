Package Managers

vcpkg · vcpkg.json · Conan · find_package · FetchContent · manifest mode

Getting Dependencies

C++ has no single official package manager, but two dominate. vcpkg (Microsoft) builds libraries from source using a vcpkg.json manifest and integrates with CMake through a toolchain file. Conan uses conanfile.txt/conanfile.py, supports binary caching, and generates CMake config. CMake's own FetchContent downloads and builds dependencies as part of your project without any external tool.

Notes

  • All three end with find_package(...) + target_link_libraries(...)
  • vcpkg manifest mode pins dependencies per project
  • Conan 2.x is current; Conan 1 recipes differ
  • Header-only libraries can also be vendored into third_party/

vcpkg Manifest + CMake

{
  "name": "inventory",
  "version": "1.0.0",
  "dependencies": [ "fmt", "spdlog", "nlohmann-json", "gtest" ]
}

Code Explained

vcpkg.json — lives next to the top-level CMakeLists.txt
dependencies — installed automatically at configure time
configure with the toolchain: -DCMAKE_TOOLCHAIN_FILE=…/vcpkg.cmake
then find_package(fmt CONFIG REQUIRED) and link fmt::fmt

FetchContent (no external tool)

include(FetchContent)
FetchContent_Declare(
  json
  URL https://github.com/nlohmann/json/releases/download/v3.11.3/json.tar.xz
)
FetchContent_MakeAvailable(json)
target_link_libraries(app PRIVATE nlohmann_json::nlohmann_json)

Code Explained

FetchContent_Declare — where to get the source (URL or git tag)
FetchContent_MakeAvailable — downloads and adds it to the build
then link the library's exported target as usual

⚠ Common Mistakes

  • Mixing system-installed and vcpkg copies of the same library, which links two versions
  • Forgetting the vcpkg toolchain file, so find_package can't find anything
  • Pinning nothing; builds change when upstream releases a new version

✓ Tips & Best Practices

  • Commit vcpkg.json (plus a builtin-baseline) or conan.lock for reproducible builds
  • Use FetchContent for small, header-only, or test-only dependencies
  • Put the toolchain path in CMakePresets.json so nobody has to remember it

Quick Summary

  • vcpkg — manifest-based, CMake toolchain
  • Conan — profiles, binary packages
  • FetchContent — CMake-native download + build
  • find_package + target_link_libraries — the consumer side
