What's Coming in C++26

C++26 is the next standard. Its headline features are static reflection (inspecting types and generating code at compile time), contracts (pre, post, contract_assert), and std::execution (a senders/receivers framework for async and parallel work). Smaller additions include pack indexing, #embed, std::inplace_vector, saturation arithmetic, and std::hive. Compiler support is still arriving, so check cppreference's support table before relying on any of these.

Status

  • Feature set frozen in 2025; publication expected around late 2026
  • GCC and Clang implement features behind -std=c++26 / c++2c
  • Reflection syntax uses ^^T (reflect) and [: r :] (splice)
  • Treat examples here as illustrative; details may shift in implementations

C++26 Features (illustrative)

// Static reflection: enum → string
template <typename E> requires std::is_enum_v<E>
constexpr std::string_view to_string(E value) {
    template for (constexpr auto e :
                  std::define_static_array(std::meta::enumerators_of(^^E)))
        if (value == [:e:]) return std::meta::identifier_of(e);
    return "<unknown>";
}
// Contracts
int safe_div(int a, int b) pre (b != 0) post (r: r * b <= a);
// Pack indexing
template <typename... Ts> using First = Ts...[0];
// #embed binary data
constexpr unsigned char icon[] = {
    #embed "icon.png"
};
std::inplace_vector<int, 16> small;        // fixed capacity, no heap
auto s = std::add_sat<std::uint8_t>(200, 100);   // 255 (saturating)

Code Explained

^^E — reflect the type into a std::meta::info value
[:e:] — splice a reflection back into code
template for — expansion statement over compile-time ranges
pre / post — checked function contracts
Ts...[0] — index directly into a parameter pack
#embed — include a file's bytes at compile time

⚠ Common Mistakes

  • Writing C++26 code for a project that must build on older compilers; gate it behind feature-test macros
  • Assuming reflection replaces all macros today; tooling and debuggers are still catching up
  • Copying syntax from early proposals; several features changed spelling during standardization

✓ Tips & Best Practices

  • Test features on Compiler Explorer with GCC trunk / Clang trunk before adopting
  • Use feature-test macros like __cpp_contracts and __cpp_impl_reflection (check names on cppreference)
  • Start with library features (inplace_vector, add_sat); they're easy to polyfill

Quick Summary

  • reflection — ^^T and [: :] (C++26)
  • contracts — pre, post, contract_assert
  • std::execution — senders / receivers
  • #embed, pack indexing, inplace_vector — smaller wins
