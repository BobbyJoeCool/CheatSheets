Constructors

default ctor · parameterized ctor · member initializer list · delegating ctors · explicit · = default

Initializing Objects

A constructor is a special member function with the class's name and no return type, called automatically when an object is created. The member initializer list (: a(x), b(y)) initializes members directly, before the constructor body runs. It's required for const members, references, and members without default constructors. A constructor can delegate to another constructor of the same class.

Notes

  • Members initialize in declaration order, not initializer-list order
  • If you declare no constructors, the compiler provides a default one
  • explicit blocks implicit conversions from a single argument
  • = default asks for the compiler-generated version

Constructor Forms

class Temperature {
public:
    Temperature() = default;                          // default ctor
    explicit Temperature(double c) : celsius_(c) {}   // init list
    Temperature(double v, char unit)                  // delegating
        : Temperature(unit == 'F' ? (v - 32) / 1.8 : v) {}
    double celsius() const { return celsius_; }
private:
    double celsius_ = 0.0;
};
Temperature a;                  // 0.0
Temperature b{21.5};            // 21.5
Temperature c{98.6, 'F'};       // 37.0
// Temperature d = 30.0;        // ERROR: constructor is explicit
void show(Temperature t);
// show(25.0);                  // ERROR: no implicit conversion
show(Temperature{25.0});        // OK

Code Explained

= default — compiler-generated default constructor
: celsius_(c) — direct member initialization
: Temperature(...) — delegates to another constructor
explicit — prevents Temperature t = 30.0; and silent conversions
braces — Temperature b{21.5} calls the matching constructor

⚠ Common Mistakes

  • Assigning in the body (name_ = n;) instead of initializing; members are default-constructed first, then assigned
  • Listing initializers in a different order than declaration and relying on that order; -Wreorder warns
  • Single-argument constructors without explicit, allowing surprising implicit conversions

✓ Tips & Best Practices

  • Make single-argument constructors explicit unless conversion is intended
  • Prefer default member initializers for defaults; keep constructors for real parameters
  • Use a static factory (static std::expected<T, E> create(...)) when construction can fail without exceptions

Quick Summary

  • constructor — same name as class, no return type
  • : m(x) — member initializer list
  • explicit — no implicit conversion
  • delegating — T(a) : T(a, default) {}
