Sheet 092

Mutexes & Locks

std::mutex · std::lock_guard · std::unique_lock · std::scoped_lock · std::shared_mutex · deadlock avoidance

Protecting Shared Data

A mutex ensures only one thread at a time runs a critical section. Never call lock()/unlock() by hand; use RAII lock guards so the mutex is released even if an exception is thrown. std::scoped_lock (C++17) locks one or more mutexes and avoids deadlock when locking several. std::shared_mutex allows many readers or one writer.

Notes

  • Keep critical sections short; never call unknown code while locked
  • std::unique_lock — movable, can unlock early, needed for condition variables
  • std::shared_lock — shared (read) ownership
  • Mutexes aren't copyable or movable

Locks in Practice

class Counter {
    mutable std::mutex m_;
    int value_ = 0;
public:
    void increment() { std::scoped_lock lock{m_}; ++value_; }
    int get() const  { std::scoped_lock lock{m_}; return value_; }
};
void transfer(Account& a, Account& b, double amt) {
    std::scoped_lock lock{a.m, b.m};      // both, deadlock-free
    a.balance -= amt; b.balance += amt;
}
std::shared_mutex cacheMutex;
std::string read(const std::string& k) {
    std::shared_lock lock{cacheMutex};    // many readers at once
    return cache.at(k);
}
void write(std::string k, std::string v) {
    std::unique_lock lock{cacheMutex};    // exclusive writer
    cache[std::move(k)] = std::move(v);
}

Code Explained

std::scoped_lock lock{m_} — locks now, unlocks at end of scope
mutable std::mutex — lock inside const member functions
scoped_lock{a.m, b.m} — locks both with deadlock avoidance
shared_lock — concurrent readers
unique_lock on shared_mutex — exclusive writer

⚠ Common Mistakes

  • Writing std::scoped_lock(m_); without a name; that's a temporary unlocked immediately (or declares a variable named m_)
  • Locking two mutexes in different orders in different threads, causing deadlock; use scoped_lock with both
  • Returning a reference to protected data, letting callers access it unlocked

✓ Tips & Best Practices

  • Bundle each mutex with the data it protects inside one class
  • Use std::atomic for single counters or flags instead of a mutex
  • Run tests with -fsanitize=thread to detect data races

Quick Summary

  • std::mutex — mutual exclusion
  • std::scoped_lock — RAII, multi-mutex safe
  • std::shared_mutex — readers/writer
  • short critical sections — lock only what's needed
