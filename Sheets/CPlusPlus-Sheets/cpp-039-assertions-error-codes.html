Sheet 039

Assertions & Error Codes

assert · NDEBUG · static_assert · std::error_code · errno · contracts: pre / post / contract_assert (C++26)

Checks & Codes

Assertions catch programmer errors during development. assert(cond) aborts with a message when the condition is false and disappears when NDEBUG is defined, while static_assert checks at compile time. For OS-level errors, C APIs set errno and C++ wraps them in std::error_code. Contracts in C++26 add pre, post, and contract_assert as language features; verify compiler support before relying on them.

Notes

  • Release builds usually pass -DNDEBUG, removing assert
  • Never put side effects inside assert(...)
  • std::error_code = integer value + category (generic, system)
  • Contracts (C++26) can be checked, observed, or ignored per build

assert, static_assert, error_code

#include <cassert>
#include <system_error>
#include <filesystem>

double average(std::span<const double> v) {
    assert(!v.empty() && "average of empty span");   // debug only
    return std::accumulate(v.begin(), v.end(), 0.0) / v.size();
}

static_assert(sizeof(void*) == 8, "64-bit only");
static_assert(std::is_trivially_copyable_v<Packet>);

std::error_code ec;
auto size = std::filesystem::file_size("missing.txt", ec);
if (ec) std::println("{}: {}", ec.value(), ec.message());
                                     // 2: No such file or directory
if (std::fopen("x", "r") == nullptr)
    std::println("{}", std::strerror(errno));
int safe_div(int a, int b)           // C++26 contracts
    pre (b != 0)
    post (r: r * b <= a);

Code Explained

assert(cond && "msg") — the string makes the failure message readable
static_assert — compile-time; message optional since C++17
overloads taking std::error_code& — report errors instead of throwing
ec.message() — human-readable description
pre / post — C++26 function contracts; r names the return value

⚠ Common Mistakes

  • assert(file.open()) — the call vanishes in release builds. Do the work outside, assert the result
  • Using assert to validate user input; it's for bugs, not expected failures
  • Reading errno after another call that may have overwritten it

✓ Tips & Best Practices

  • Keep assertions on in testing builds and run tests in both debug and release modes
  • Compare portably: ec == std::errc::no_such_file_or_directory
  • Check your compiler's contracts support before adopting pre/post in shared code

Quick Summary

  • assert — debug-only run-time check
  • static_assert — compile-time check
  • std::error_code — non-throwing OS errors
  • pre / post — C++26 contracts
