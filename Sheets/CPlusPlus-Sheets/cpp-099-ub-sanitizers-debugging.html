Undefined Behavior & Tools

Undefined behavior (UB) means the standard places no requirements on what happens: the program may crash, appear to work, or be "optimized" into something surprising. Common UB includes out-of-bounds access, signed overflow, use-after-free, data races, and dereferencing null. Sanitizers instrument your build to catch UB at run time, and debuggers let you inspect a running or crashed program.

Notes

  • UB can appear to work until a compiler upgrade changes optimizations
  • Sanitizers slow programs 2–5×; use them in tests and CI
  • ASan and TSan can't be combined in one build
  • std::stacktrace (C++23) prints a call stack from code

Catching UB

# AddressSanitizer + UndefinedBehaviorSanitizer
g++ -std=c++23 -g -O1 -fsanitize=address,undefined \
    -fno-omit-frame-pointer main.cpp -o app
./app        # reports: heap-use-after-free / signed-integer-overflow ...

# ThreadSanitizer (separate build)
clang++ -std=c++23 -g -fsanitize=thread main.cpp -o app_tsan

# Debug with gdb (or lldb on macOS)
gdb ./app
(gdb) break inventory.cpp:42
(gdb) run --config test.json
(gdb) bt            # backtrace after a crash
(gdb) print items.size()
(gdb) next / step / continue

valgrind --leak-check=full ./app      # leaks & invalid reads (Linux)

Code Explained

-fsanitize=address — out-of-bounds, use-after-free, leaks
undefined — signed overflow, bad shifts, null dereference
-fno-omit-frame-pointer — better stack traces
thread — data races (needs its own build)
bt — show the call stack at the crash
valgrind — no recompilation needed, but slower

⚠ Common Mistakes

  • Concluding code is correct because it "works on my machine"; UB often hides until optimization changes
  • Debugging release builds without -g; you get no line numbers
  • Ignoring sanitizer reports in third-party code paths your program triggers

✓ Tips & Best Practices

  • Add a sanitizer job to CI that runs the whole test suite with ASan + UBSan
  • Use _GLIBCXX_ASSERTIONS or libc++ hardening modes to bounds-check operator[] in debug builds
  • Print std::stacktrace::current() in fatal error handlers (C++23, link -lstdc++exp on GCC)

Quick Summary

  • UB — no guarantees; must be avoided, not tolerated
  • -fsanitize=address,undefined — catch UB at run time
  • -fsanitize=thread — catch data races
  • gdb / lldb — breakpoints, bt, print
