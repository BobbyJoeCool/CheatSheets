Overloading & Default Arguments

function overloading · overload resolution · ambiguous calls · default arguments · name mangling

Same Name, Different Parameters

Overloading lets several functions share a name when their parameter lists differ in number or types. The compiler picks the best match at each call using overload resolution: exact match beats promotion, which beats conversion. If two candidates tie, the call is ambiguous and won't compile. Default arguments supply values for trailing parameters the caller omits.

Rules

  • Return type alone can't distinguish overloads
  • Defaults must be trailing: f(int a, int b = 0) OK, not f(int a = 0, int b)
  • Specify defaults in the declaration (header) only
  • The compiler encodes parameter types in symbol names (name mangling)

Overloads & Defaults

void print(int v)              { std::println("int {}", v); }
void print(double v)           { std::println("double {}", v); }
void print(std::string_view v) { std::println("text {}", v); }

print(42);          // int 42
print(3.14);        // double 3.14
print("hi");        // text hi
print(2.5f);        // double 2.5   (float → double promotion)
// print(42L);      // ERROR: ambiguous (long → int or double?)

void connect(std::string_view host, int port = 443, bool tls = true);
connect("example.com");              // port 443, tls true
connect("example.com", 8080);        // tls true
connect("example.com", 80, false);

void f(int);
void f(int*);
f(0);         // calls f(int)
f(nullptr);   // calls f(int*)

Code Explained

three prints — chosen by argument type
float → double — promotion wins over conversion to int
42L — converting long to int or double ties: ambiguous
default arguments — filled in from the right
nullptr — always picks the pointer overload; 0 picks int

Valid vs Invalid Overloads

PairValid?
f(int) / f(double)✔
f(int) / f(int, int)✔
f(int&) / f(const int&)✔
int f() / double f()✖
f(int) / f(const int)✖ (same)
f(int a = 1) / f()✔ but f() is ambiguous

⚠ Common Mistakes

  • Overloading on bool and std::string: f("text") picks bool because pointer → bool is a standard conversion
  • Repeating default arguments in both the declaration and the definition; it's a redefinition error
  • Changing a default argument in a header without rebuilding callers; defaults are baked in at the call site

✓ Tips & Best Practices

  • Prefer distinct names (parseInt, parseFloat) when overloads would do different things
  • Use = delete to block unwanted conversions: void f(double) = delete;
  • Use std::string_view instead of separate const char* and std::string overloads

Quick Summary

  • overloading — same name, different parameters
  • best match — exact > promotion > conversion
  • default args — trailing parameters only
  • nullptr vs 0 — pointer vs int overload
