Sheet 102

Pointer Arithmetic & Arrays

p + 1 · array decay · std::ptrdiff_t · iterating with pointers · one-past-the-end · out-of-bounds UB

Moving Through Memory

Pointer arithmetic moves a pointer by whole elements, not bytes: p + 1 points to the next T. It's only valid within one array (plus the one-past-the-end position, which you may compute but not dereference). Arrays decay to a pointer to their first element, which is why a[i] is defined as *(a + i). Subtracting two pointers into the same array gives a std::ptrdiff_t element count.

Notes

  • p + n advances n * sizeof(T) bytes
  • Comparing pointers into different arrays with < is unspecified
  • Iterators generalize pointers; raw pointers *are* random-access iterators
  • std::to_address(it) gets a raw pointer from an iterator-like object

Arithmetic & Arrays

int a[5] = {10, 20, 30, 40, 50};
int* p = a;              // decay: &a[0]
*(p + 2);                // 30, same as a[2] and p[2]
p += 3;                  // now points to a[3]
*p;                      // 40
p - a;                   // 3   (std::ptrdiff_t)

int* end = a + 5;        // one past the end: OK to form
for (int* it = a; it != end; ++it) std::print("{} ", *it);   // 10 … 50
// *end;                 // UB: one-past-end can't be dereferenced
// a + 6;                // UB: beyond one-past-end

std::vector<double> v{1.5, 2.5, 3.5};
double* d = v.data();
d[1];                    // 2.5
std::sort(a, a + 5);     // pointers work as iterators

Code Explained

a decays to &a[0] in most expressions
p + 2 — two elements forward, not two bytes
p - a — distance in elements
end = a + 5 — valid sentinel, never dereferenced
v.data() — raw pointer into a vector's contiguous storage

⚠ Common Mistakes

  • Going past one-past-the-end, even without dereferencing; just computing it is UB
  • Doing byte-level arithmetic on a T*; cast to std::byte* / char* first if you mean bytes
  • Assuming sizeof(arr) inside a function parameter is the array size; it's the pointer size

✓ Tips & Best Practices

  • Wrap pointer + length pairs in std::span as early as possible
  • Use std::begin(a) / std::end(a) for C arrays in generic code
  • Compile debug builds with -D_GLIBCXX_ASSERTIONS or ASan to catch out-of-bounds bugs

Quick Summary

  • p + n — n elements forward
  • a[i] — same as *(a + i)
  • one-past-the-end — may form, may not dereference
  • std::span — safer pointer + size
