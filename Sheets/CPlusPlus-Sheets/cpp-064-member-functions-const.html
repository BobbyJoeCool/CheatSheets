Qualifying Member Functions

A const member function promises not to modify the object, so it can be called on const objects and through const&. Inside it, this is a pointer to const. mutable members are exempt, for caches or mutexes that don't affect the object's logical state. Ref-qualifiers (&, &&) overload on whether the object is an lvalue or a temporary, and C++23's explicit object parameter (this auto&& self) collapses const/non-const/ref overloads into one template.

Notes

  • Mark every function that doesn't modify state const
  • const objects can only call const member functions
  • const and non-const overloads are often written as a pair
  • Deducing this removes that duplication (C++23)

const, mutable, &/&&, deducing this

class Document {
public:
    std::size_t wordCount() const {           // callable on const objects
        if (!cache_) cache_ = countWords();   // OK: cache_ is mutable
        return *cache_;
    }
    std::string& title() & { return title_; }           // lvalue object
    std::string  title() && { return std::move(title_); } // temporary
    template <class Self>
    auto& text(this Self&& self) { return self.text_; } // C++23: one for all
private:
    std::size_t countWords() const;
    std::string title_, text_;
    mutable std::optional<std::size_t> cache_;
};
const Document doc = load();
doc.wordCount();                // OK
auto t = load().title();        // && overload: moves the title out

Code Explained

const after the parameter list — this is const Document*
mutable — lazily computed cache can change inside const functions
& / && qualifiers — choose by value category of the object
this Self&& self — deduces const and ref-ness from the call
load().title() — temporary object picks the && version

⚠ Common Mistakes

  • Forgetting const on getters, so const& parameters can't call them
  • Using mutable to dodge const for real state changes; that breaks the promise and thread-safety assumptions
  • Returning a non-const reference from a const function; it won't compile (and shouldn't)

✓ Tips & Best Practices

  • Write the const version first; add non-const only when callers need to modify
  • Pair mutable std::mutex m_; with std::scoped_lock in const accessors for thread-safe reads
  • Use deducing this to replace duplicated const/non-const accessor pairs

Quick Summary

  • f() const — doesn't modify the object
  • mutable — exempt from const (caches, mutexes)
  • f() & / f() && — overload on lvalue vs temporary
  • this auto&& self — explicit object parameter (C++23)
