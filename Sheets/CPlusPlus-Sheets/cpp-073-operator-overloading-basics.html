Operator Overloading — Basics

arithmetic operators · member vs non-member · operator<< / >> · operator== / <=> · operator[] · hidden friends

Custom Operators

Operator overloading lets user-defined types use built-in operator syntax: a + b, std::cout << p, v[i]. An overloaded operator is just a function named operator@. Implement symmetric binary operators (+, ==) as non-members, often hidden friends defined inside the class, so conversions work on both sides. Implement compound assignment (+=) as a member and build + on top of it.

Rules

  • You can't invent new operators or change precedence
  • ::, ., .*, ?:, sizeof can't be overloaded
  • At least one operand must be a user-defined type
  • Defaulted <=> and == (C++20) cover all six comparisons

Vector2 with Operators

struct Vec2 {
    double x{}, y{};
    Vec2& operator+=(const Vec2& o) { x += o.x; y += o.y; return *this; }
    friend Vec2 operator+(Vec2 a, const Vec2& b) { return a += b; }
    friend Vec2 operator*(Vec2 v, double k) { return {v.x * k, v.y * k}; }
    friend Vec2 operator*(double k, Vec2 v) { return v * k; }
    Vec2 operator-() const { return {-x, -y}; }        // unary
    auto operator<=>(const Vec2&) const = default;     // ==, <, …
    double& operator[](std::size_t i) { return i == 0 ? x : y; }
    friend std::ostream& operator<<(std::ostream& os, const Vec2& v) {
        return os << '(' << v.x << ", " << v.y << ')';
    }
};
Vec2 a{1, 2}, b{3, 4};
a + b;              // (4, 6)
2.0 * a;            // (2, 4)
a == Vec2{1, 2};    // true
a[1] = 9;           // a == (1, 9)
std::cout << -a;    // (-1, -9)

Code Explained

operator+= — member; modifies and returns *this
operator+ via += — takes a by value, reuses the logic
hidden friend — found only via argument-dependent lookup; works with conversions on either side
operator<=> = default — memberwise comparisons
operator<< — must be a non-member (left operand is the stream)

⚠ Common Mistakes

  • Overloading operators with surprising meanings (+ that removes items); readers assume normal semantics
  • Making operator+ a member, so 2.0 * v or "a" + str won't compile
  • Returning a reference from operator+; it returns a new value

✓ Tips & Best Practices

  • Implement op= first, then op in terms of it
  • Default <=> and == instead of writing six comparison operators
  • Provide a const overload of operator[] returning const T&

Quick Summary

  • operator@ — overload by naming a function
  • += member, + non-member — canonical pattern
  • hidden friends — symmetric operators inside the class
  • <=> = default — all comparisons
