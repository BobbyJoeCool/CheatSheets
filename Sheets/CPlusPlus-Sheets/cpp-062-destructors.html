Destructors

~Class() · destruction order · virtual destructors · scope exit · = default · never throw from a destructor

Cleaning Up

A destructor ~T() runs automatically when an object's lifetime ends: when it goes out of scope, when delete is called, or when its owner is destroyed. It's where a class releases resources it acquired. Members are destroyed after the destructor body, in reverse declaration order; local objects are destroyed in reverse order of creation. If a class will be deleted through a base pointer, its base needs a virtual destructor.

Rules

  • One destructor per class, no parameters, no return type
  • Implicitly noexcept; never let exceptions escape it
  • Most classes need no destructor at all (rule of zero)
  • Base classes used polymorphically: virtual ~Base() = default;

Destructors in Action

class Logger {
public:
    explicit Logger(std::string name) : name_(std::move(name)) {
        std::println("open {}", name_);
    }
    ~Logger() { std::println("close {}", name_); }   // destructor
private:
    std::string name_;
};
void run() {
    Logger a{"A"};
    {
        Logger b{"B"};
    }                       // "close B" here (end of inner scope)
    Logger c{"C"};
}                           // "close C", then "close A"
struct Shape { virtual ~Shape() = default; };
struct Circle : Shape { ~Circle() override { /* ... */ } };

Code Explained

~Logger() — runs automatically, even during exception unwinding
inner scope — b dies at its closing brace
reverse order — c is destroyed before a
virtual ~Shape() — makes delete shapePtr call ~Circle()
override on a destructor — allowed, documents intent

⚠ Common Mistakes

  • Deleting a derived object through a base pointer without a virtual destructor; that's UB and usually leaks
  • Throwing from a destructor; during unwinding this calls std::terminate
  • Calling the destructor manually (obj.~T()) on a normal object; it runs again at scope end

✓ Tips & Best Practices

  • Wrap each resource (file, socket, lock) in its own class so destructors clean up automatically
  • Use std::unique_ptr with a custom deleter for C handles instead of writing a destructor
  • Write virtual ~Base() = default; in every class meant to be inherited from polymorphically

Quick Summary

  • ~T() — runs automatically at end of lifetime
  • reverse order — locals and members
  • virtual ~Base() — required for polymorphic deletion
  • noexcept — destructors must not throw
