Lambdas — Advanced

generic lambdas (auto) · init capture [x = std::move(y)] · template lambdas []<typename T> · IIFE · recursive lambdas (this auto&)

Beyond the Basics

Lambdas grew steadily after C++11. Generic lambdas take auto parameters and act like templates (C++14). Init captures create new variables in the capture list, including moving objects in (C++14). Template lambdas name their type parameters explicitly (C++20), and deducing this (C++23) gives a lambda access to itself, so it can recurse without std::function.

Notes

  • auto parameters → one template per call type
  • [p = std::move(ptr)] moves a unique_ptr into the lambda
  • IIFE: define and call immediately for complex initialization
  • Lambdas in unevaluated contexts and as default template args since C++20

Advanced Lambdas

auto twice = [](auto x) { return x + x; };      // generic
twice(4); twice(1.5);   // 8, 3.0

auto ptr = std::make_unique<Job>();
auto task = [job = std::move(ptr)] { job->run(); };   // init capture

auto sum = []<typename T>(const std::vector<T>& v) {  // template lambda
    return std::accumulate(v.begin(), v.end(), T{});
};
const auto config = [&] {                       // IIFE
    Config c;
    if (debug) c.level = 3;
    return c;
}();                                            // note the ()
auto fact = [](this auto self, int n) -> long { // deducing this
    return n <= 1 ? 1 : n * self(n - 1);
};
fact(5);           // 120

Code Explained

[](auto x) — generic; works for any type with +
[job = std::move(ptr)] — creates a member job owning the pointer
[]<typename T> — explicit template parameter for the vector element
[&] { … }() — IIFE lets config be const
this auto self — the lambda receives itself, enabling recursion

⚠ Common Mistakes

  • Forgetting the trailing () on an IIFE, so config becomes the lambda instead of its result
  • Copying a lambda that holds a unique_ptr; it's move-only, so std::function can't store it (use std::move_only_function)
  • Using std::function for recursion; it adds heap allocation and indirect calls. Use deducing this

✓ Tips & Best Practices

  • Prefer generic lambdas for small predicates used with multiple types
  • Use IIFE to keep variables const when initialization needs branches or loops
  • Combine lambdas with std::visit via an overloaded helper for variant dispatch

Quick Summary
