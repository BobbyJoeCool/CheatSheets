Sheet 095

Futures & std::async

std::async · std::future · std::promise · std::packaged_task · launch policies · std::shared_future

Getting Results Back

A std::future<T> is a handle to a value that will be produced later, usually by another thread. std::async runs a callable and returns a future for its result; get() waits for the value and rethrows any exception the task threw. std::promise lets you set a future's value manually, and std::packaged_task wraps a callable so its result goes into a future when it runs.

Notes

  • get() can be called once; use shared_future for many readers
  • Pass std::launch::async to guarantee a new thread
  • The future from std::async blocks in its destructor until done
  • Exceptions travel through the future to get()

async, promise, packaged_task

#include <future>

auto f1 = std::async(std::launch::async,
                     [] { return slowSum(1, 1'000'000); });
auto f2 = std::async(std::launch::async, fetchUser, 42);
long total = f1.get();                       // waits, then returns
User u = f2.get();                           // rethrows if fetchUser threw

std::promise<std::string> p;
std::future<std::string> fut = p.get_future();
std::jthread worker{[&p] {
    try { p.set_value(download("https://example.com")); }
    catch (...) { p.set_exception(std::current_exception()); }
}};
std::string body = fut.get();

std::packaged_task<int(int, int)> task{[](int a, int b) { return a + b; }};
auto r = task.get_future();
std::jthread t{std::move(task), 2, 3};
r.get();                                     // 5
if (fut.wait_for(0s) == std::future_status::ready) {}  // poll

Code Explained

std::launch::async — run on a new thread now
get() — blocks for the result, rethrows exceptions
promise::set_value — fulfill the future from any thread
set_exception — deliver an error instead
packaged_task — callable + future, run wherever you like
wait_for(0s) — non-blocking readiness check

Pieces

TypeRole
std::future<T>read result once
std::shared_future<T>read result many times
std::promise<T>write side, set manually
std::packaged_taskwraps a callable
std::asyncrun + return future

Launch Policies

PolicyBehavior
launch::asyncnew thread
launch::deferredruns lazily on get()
async | deferredimplementation chooses (default)

⚠ Common Mistakes

  • Calling get() twice on a std::future; the second call is UB / throws future_error
  • Ignoring the future returned by std::async; its destructor blocks, making the call synchronous
  • Relying on the default launch policy; the task may never run if you never call get()

✓ Tips & Best Practices

  • Always pass std::launch::async when you want real parallelism
  • Use wait_for with a timeout to avoid hanging forever on a stuck task
  • For many small tasks, use a thread pool (or C++26 std::execution) instead of std::async per task

Quick Summary

  • std::async — run a task, get a future
  • future::get() — wait + value or exception
  • std::promise — set a result manually
  • std::packaged_task — callable bound to a future
