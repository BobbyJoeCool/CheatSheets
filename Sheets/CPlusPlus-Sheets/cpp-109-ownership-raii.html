Resource Ownership Rules

RAII (Resource Acquisition Is Initialization) ties every resource to an object's lifetime: acquire in the constructor, release in the destructor. Because destructors run on every exit path, including exceptions, RAII makes leaks structurally impossible. Combined with clear ownership types (smart pointers and containers own; raw pointers, references, span, and string_view observe), it's the core of safe modern C++.

Core Guidelines (R.*)

  • R.1: manage resources automatically using RAII
  • R.3: a raw pointer T* is non-owning
  • R.11: avoid calling new and delete explicitly
  • R.20/21: use unique_ptr or shared_ptr to represent ownership

RAII Wrappers

class File {                                    // RAII wrapper
public:
    explicit File(const char* path) : f_(std::fopen(path, "r")) {
        if (!f_) throw std::runtime_error("open failed");
    }
    ~File() { std::fclose(f_); }
    File(const File&) = delete;                 // non-copyable
    File& operator=(const File&) = delete;
    std::FILE* get() const { return f_; }
private:
    std::FILE* f_;
};
void work(std::mutex& m) {
    std::scoped_lock lock{m};                   // RAII lock
    File cfg{"app.cfg"};                        // RAII file
    parse(cfg.get());                           // may throw
}                                               // file closed, mutex unlocked

Code Explained

constructor acquires and throws if it can't
destructor releases unconditionally
deleted copies — one owner per handle
scoped_lock — the standard library's RAII lock
on any exit (return or throw), both resources are released

⚠ Common Mistakes

  • Manual lock() / unlock() or fopen / fclose pairs; any early return or exception skips the release
  • Treating a raw pointer parameter as owning and deleting it
  • Writing an RAII class but leaving copying enabled, so two objects release the same handle

✓ Tips & Best Practices

  • Follow the rule of zero: compose RAII members so your class needs no destructor
  • Use std::unique_ptr with a custom deleter as a one-line RAII wrapper for C APIs
  • Make ownership visible in signatures: unique_ptr by value means "I take it"

Quick Summary

  • RAII — acquire in ctor, release in dtor
  • owning types — values, smart pointers, containers
  • non-owning — T*, T&, span, string_view
  • rule of zero — let members own resources
