C++20 Modules

export module · import · import std; · module partitions · .cppm / .ixx · build system support

Modules

C++20 modules replace textual #include with compiled interfaces. A module interface unit declares export module name; and marks what it exports; consumers write import name;. Modules are parsed once, don't leak macros, and are isolated from include order. C++23 adds import std; for the whole standard library. Tooling support has matured but still varies, so check your compiler and build system versions.

Support (late 2026)

  • GCC 15+, Clang 18+, MSVC 17.x support named modules
  • CMake 3.28+ builds modules with Ninja / VS generators
  • import std; needs CMake 3.30+ and a recent standard library
  • Macros from a module are not visible to importers

A Simple Module

// math.cppm — module interface unit
module;                          // global module fragment (optional)
#include <cmath>                 // legacy headers go here
export module math;              // declares the module

export namespace math {
    double hypot(double a, double b) { return std::sqrt(a * a + b * b); }
    constexpr double pi = 3.14159265358979;
}
int helper() { return 42; }      // not exported: module-private

// main.cpp
import math;                     // consume the module
import std;                      // C++23: entire standard library
int main() {
    std::println("{}", math::hypot(3, 4));   // 5
}

Code Explained

module; — starts the global module fragment for old #includes
export module math; — names the module
export — only exported names are visible to importers
helper() — module-private (similar to internal linkage)
import std; — replaces dozens of standard #includes

⚠ Common Mistakes

  • Expecting macros (like NDEBUG checks or config macros) defined in a module to reach importers
  • Putting #include after export module; legacy includes belong in the global module fragment
  • Mixing compilers or flags between a module and its consumers; module binaries aren't portable

✓ Tips & Best Practices

  • Start by using import std; in new code if your toolchain supports it; it's a big compile-time win
  • Migrate leaf libraries first and keep header shims for old consumers
  • Use .cppm (Clang/GCC) or .ixx (MSVC) consistently and tell CMake via FILE_SET CXX_MODULES

Quick Summary

  • export module m; — define a module
  • export — choose what's visible
  • import m; — use it; no macro leakage
  • import std; — standard library as a module (C++23)
