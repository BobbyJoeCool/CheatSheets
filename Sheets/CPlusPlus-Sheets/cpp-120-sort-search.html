Sorting & Searching

sort · stable_sort · partial_sort · nth_element · binary_search · lower_bound / upper_bound · custom comparators

Ordering & Binary Search

std::sort sorts random-access ranges in O(n log n), but it isn't stable: equal elements may change order. Use std::stable_sort when that matters. partial_sort and nth_element do less work when you only need the top k or the median. On sorted data, binary search algorithms find elements in O(log n). All accept a custom comparator, and the ranges versions accept projections.

Comparator Rules

  • Must be a strict weak ordering: use <, never <=
  • std::greater<>{} — descending order
  • Binary search requires data sorted by the same comparator
  • std::list has its own .sort() member

Sorting & Searching

std::vector<int> v{5, 2, 9, 1, 7};
std::ranges::sort(v);                                // 1 2 5 7 9
std::ranges::sort(v, std::greater<>{});              // 9 7 5 2 1

struct Emp { std::string name; int dept; double pay; };
std::ranges::sort(staff, {}, &Emp::pay);             // by pay (projection)
std::ranges::stable_sort(staff, {}, &Emp::dept);     // keeps pay order
std::ranges::sort(staff, [](const Emp& a, const Emp& b) {
    return std::tie(a.dept, a.name) < std::tie(b.dept, b.name);  // multi-key
});

std::ranges::partial_sort(v, v.begin() + 3);         // smallest 3 first
std::ranges::nth_element(v, v.begin() + v.size() / 2);   // median in place

std::vector<int> s{1, 3, 5, 7, 9};
std::ranges::binary_search(s, 7);                    // true
auto lo = std::ranges::lower_bound(s, 6);            // first >= 6 → 7
auto hi = std::ranges::upper_bound(s, 7);            // first > 7 → 9
auto [b, e] = std::ranges::equal_range(s, 5);        // range of 5s

Code Explained

std::greater<>{} — reverse order
projection &Emp::pay — sort by a member without a lambda
stable_sort after sorting by pay — groups by dept, keeps pay order
std::tie — lexicographic multi-key comparison
nth_element — O(n) average; element at position n is the one a full sort would put there
lower_bound — insertion point for keeping a vector sorted

⚠ Common Mistakes

  • A comparator using <=; it violates strict weak ordering and can crash std::sort
  • Running binary_search / lower_bound on unsorted data
  • Sorting by two keys with two sort calls instead of one comparator or stable_sort

✓ Tips & Best Practices

  • Insert into a sorted vector with v.insert(std::ranges::upper_bound(v, x), x);
  • Use partial_sort or nth_element for top-k problems instead of a full sort
  • Projections plus std::greater<> sort descending by member: ranges::sort(v, std::greater<>{}, &T::score)

Quick Summary

  • sort / stable_sort — order a range
  • comparators — strict weak ordering (<)
  • partial_sort / nth_element — partial work
  • lower_bound / binary_search — O(log n) on sorted data
