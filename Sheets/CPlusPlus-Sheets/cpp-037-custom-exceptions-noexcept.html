Your Own Exceptions & noexcept

Define custom exceptions by deriving from a standard type, usually std::runtime_error, and add fields that callers need, like an error code or file name. Mark functions that will never throw noexcept: it documents the promise and lets the library choose faster paths (e.g., std::vector moves elements only if the move constructor is noexcept). If a noexcept function does throw, std::terminate is called.

Guarantees

  • Nothrow: never throws (destructors, swaps, moves)
  • Strong: on failure, state is unchanged (commit-or-rollback)
  • Basic: on failure, no leaks and invariants hold
  • Destructors are implicitly noexcept

Custom Exception + noexcept

class HttpError : public std::runtime_error {
public:
    HttpError(int status, const std::string& url)
        : std::runtime_error(std::format("HTTP {} for {}", status, url)),
          status_(status) {}
    int status() const noexcept { return status_; }
private:
    int status_;
};
try { throw HttpError(404, "/api/users"); }
catch (const HttpError& e) {
    std::println("{}", e.what());   // HTTP 404 for /api/users
    if (e.status() == 404) retryLater();
}
struct Buffer {
    Buffer(Buffer&& other) noexcept;           // enables fast vector growth
    void swap(Buffer& o) noexcept;
};
template <class T>
void relocate(T& t) noexcept(std::is_nothrow_move_constructible_v<T>);
static_assert(std::is_nothrow_move_constructible_v<Buffer>);

⚠ Common Mistakes

  • Forgetting noexcept on move constructors, so std::vector copies instead of moving when it grows
  • Marking a function noexcept that calls code that can throw; the program terminates instead of propagating the error
  • Overriding what() and returning a pointer to a local string that dies on return

✓ Tips & Best Practices

  • Let std::runtime_error store the message; don't keep your own std::string just for what()
  • Use = default special members; they deduce noexcept automatically
  • Verify with std::is_nothrow_move_constructible_v for types stored in vectors
