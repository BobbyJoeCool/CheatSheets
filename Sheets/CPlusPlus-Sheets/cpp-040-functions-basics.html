Sheet 040

Defining & Calling Functions

declaration vs definition · prototypes · return · void · trailing return type · auto return · recursion

Functions

A function has a return type, a name, a parameter list, and a body. It must be declared before it's called; a declaration without a body (a prototype) is enough, and the definition can come later or live in another .cpp file. void means no value is returned. The return type can also go after the parameters (trailing return type) or be deduced with auto.

Rules

  • Declarations usually go in headers, definitions in .cpp files
  • Falling off the end of a non-void function is UB (except main)
  • auto f() deduces the return type from return statements
  • Recursion: a function may call itself; each call gets its own locals

Declare, Define, Call

int add(int a, int b);                  // declaration (prototype)

int main() {
    int s = add(2, 3);                  // 5  — call
    greet("Ada");                       // Hello, Ada
}

int add(int a, int b) { return a + b; } // definition

void greet(std::string_view who) {      // no return value
    std::println("Hello, {}", who);
}
auto area(double w, double h) -> double { return w * h; } // trailing
auto half(int x) { return x / 2.0; }    // deduced: double

unsigned long long fact(unsigned n) {   // recursion
    return n <= 1 ? 1 : n * fact(n - 1);
}
fact(10);                               // 3628800

Code Explained

prototype — lets main call add before its definition
void — the function returns nothing; return; may end it early
-> double — trailing return type, useful with templates
auto half(...) — return type deduced as double
fact — base case n <= 1, recursive case n * fact(n - 1)

⚠ Common Mistakes

  • Calling a function before any declaration is visible: "'foo' was not declared in this scope"
  • Forgetting return in a non-void function; enable -Wreturn-type (on with -Wall)
  • Deep recursion without a base case overflows the stack; C++ doesn't guarantee tail-call optimization

✓ Tips & Best Practices

  • Keep functions short and single-purpose; name them with verbs (loadConfig, parseLine)
  • Mark functions whose result must be used with [[nodiscard]]
  • Return multiple values with a struct or std::pair, then unpack with structured bindings

Quick Summary

  • T name(params) — declaration; add {} for a definition
  • prototype — declare before use
  • auto f() -> T — trailing / deduced return type
  • recursion — base case plus self-call
