Virtual Functions & Polymorphism

virtual · override · final · vtable · base pointers & references · dynamic_cast · typeid

Dynamic Dispatch

A virtual function is resolved at run time based on the actual type of the object, not the static type of the pointer or reference used to call it. That's polymorphism: code written against Shape& works for every derived shape. Mark overriding functions override so the compiler checks the signature. Under the hood, each polymorphic object carries a pointer to a vtable of function pointers.

Notes

  • Dispatch works only through references or pointers
  • override — compile error if nothing is overridden
  • final on a function — no further overriding
  • Virtual calls in constructors/destructors use the current class

virtual, override, dynamic_cast

struct Shape {
    virtual ~Shape() = default;
    virtual double area() const = 0;                 // pure virtual
    virtual std::string name() const { return "shape"; }
};
struct Circle : Shape {
    double r; explicit Circle(double r) : r(r) {}
    double area() const override { return 3.14159 * r * r; }
    std::string name() const override { return "circle"; }
};
struct Square : Shape {
    double s; explicit Square(double s) : s(s) {}
    double area() const final { return s * s; }
};
std::vector<std::unique_ptr<Shape>> shapes;
shapes.push_back(std::make_unique<Circle>(1.0));
shapes.push_back(std::make_unique<Square>(2.0));
for (const auto& sh : shapes) std::println("{} {}", sh->name(), sh->area());
if (auto* c = dynamic_cast<Circle*>(shapes[0].get())) c->r *= 2;

Code Explained

virtual — enables run-time dispatch
= 0 — pure virtual; Shape can't be instantiated
override — checked override; typos become errors
final — Square::area can't be overridden further
dynamic_cast<Circle*> — nullptr if it isn't a Circle
prints "circle 3.14159" then "shape 4"

⚠ Common Mistakes

  • Signature mismatch (missing const) creates a new function instead of overriding; override catches it
  • Calling virtual functions from a constructor expecting the derived version
  • Storing polymorphic objects by value in std::vector<Shape>; it slices. Store unique_ptr<Shape>

✓ Tips & Best Practices

  • Always write override; enable -Wsuggest-override / -Winconsistent-missing-override
  • Prefer std::variant + std::visit for closed sets of types with no virtual overhead
  • Avoid dynamic_cast chains; add a virtual function instead

Quick Summary

  • virtual — run-time dispatch
  • override — checked overriding
  • vtable — mechanism behind virtual calls
  • dynamic_cast — safe downcast, null on failure
