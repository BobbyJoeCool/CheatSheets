Sheet 056

std::deque & std::list

std::deque · std::list · std::forward_list · splice · push_front · cache-locality tradeoffs

Other Sequences

std::deque (double-ended queue) supports O(1) insertion at both ends and O(1) random access, storing elements in fixed-size chunks rather than one block. std::list is a doubly linked list: O(1) insert/erase anywhere given an iterator, and iterators stay valid, but no random access and poor cache locality. std::forward_list is singly linked and smaller still.

When to Use

  • deque — queue/sliding window needing push_front
  • list — frequent middle insert/erase with stable iterators
  • list::splice moves nodes between lists in O(1)
  • In practice, vector usually beats list even for middle inserts on small data

deque, list, forward_list

#include <deque>
#include <list>
#include <forward_list>

std::deque<int> dq{2, 3};
dq.push_front(1);                 // 1 2 3
dq.push_back(4);                  // 1 2 3 4
dq.pop_front();                   // 2 3 4
dq[1];                            // 3 (random access)
std::list<std::string> todo{"wash", "cook"};
auto it = std::next(todo.begin());
todo.insert(it, "shop");          // wash shop cook  (it still valid)
todo.remove("wash");              // shop cook
todo.sort();                      // member sort: cook shop
std::list<std::string> later{"nap"};
todo.splice(todo.end(), later);   // cook shop nap; later empty
std::forward_list<int> fl{3, 1, 2};
fl.push_front(0);                 // 0 3 1 2
fl.insert_after(fl.begin(), 9);   // 0 9 3 1 2

Code Explained

push_front / pop_front — O(1) on deque and lists
dq[1] — deque allows indexing; lists don't
list::insert — doesn't invalidate other iterators
list::sort / remove — members, because std::sort needs random access
splice — relinks nodes, no copying
forward_list — insert/erase *after* a position

⚠ Common Mistakes

  • Choosing std::list for "fast insertion" without measuring; pointer chasing often makes it slower than vector
  • Calling std::sort on a list; it needs random-access iterators. Use list.sort()
  • Assuming deque is contiguous and passing &dq[0] to a C API

✓ Tips & Best Practices

  • Use std::deque as the underlying container for queues and sliding windows
  • Use std::list when you need iterators that survive insertions and erasures elsewhere
  • Profile before replacing vector; its cache behavior wins surprisingly often

Quick Summary

  • std::deque — O(1) at both ends, indexable
  • std::list — linked list, stable iterators
  • splice — O(1) node transfer
  • std::forward_list — singly linked, minimal
