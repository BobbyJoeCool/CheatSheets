std::string_view

std::string_view · "abc"sv · remove_prefix / remove_suffix · substr · non-owning · dangling-view pitfalls

Non-Owning String Reference

std::string_view (C++17, <string_view>) is a lightweight pointer + length pair that refers to characters owned by someone else. It can view a std::string, a literal, or part of a buffer without copying, and slicing with substr is O(1). It's the best type for read-only string parameters. Because it doesn't own the data, it must never outlive the string it points into.

Rules

  • Pass by value: it's only 16 bytes
  • Not guaranteed null-terminated, so don't pass .data() to C APIs
  • Converting to std::string needs an explicit std::string{sv}
  • "text"sv creates a string_view literal

Using string_view

#include <string_view>
using namespace std::literals;

void log(std::string_view msg) {          // accepts anything string-ish
    std::println("[log] {}", msg);
}
log("literal");                           // no allocation
log(std::string{"owned"});                // OK during the call

std::string_view path = "/usr/local/bin";
path.substr(5);                           // "local/bin"  O(1)
path.remove_prefix(1);                    // "usr/local/bin"
path.remove_suffix(4);                    // "usr/local"
path.find('/');                           // 3

std::string owned{path};                  // explicit copy
std::string_view bad() {
    std::string tmp = "temporary";
    return tmp;                           // DANGLING: tmp destroyed
}
std::string_view oops = std::string{"x"}; // dangles immediately

Code Explained

std::string_view msg — one signature handles literals, strings, and slices
substr — returns another view, no allocation
remove_prefix / remove_suffix — shrink the view in place
std::string{path} — explicit conversion when you need ownership
returning a view of a local — classic dangling bug

⚠ Common Mistakes

  • Storing a string_view member that points into a temporary std::string; it dangles as soon as the temporary dies
  • Passing sv.data() to printf("%s") or fopen; there may be no terminator
  • Returning std::string_view from a function that builds a local string

✓ Tips & Best Practices

  • Default read-only string parameters to std::string_view
  • Compile with -Wdangling (GCC 14+) / Clang's lifetime warnings to catch view misuse
  • Use std::string_view in constexpr lookup tables; it's a literal type

Quick Summary

  • std::string_view — non-owning (ptr, len) view
  • pass by value — cheap read-only parameter
  • substr / remove_prefix — O(1) slicing
  • lifetime — never outlive the source string
