Constraining Templates

A concept (C++20) is a named, compile-time predicate on template arguments. Constraints say what a template needs, produce short readable errors, and let overload resolution pick the most specific candidate (subsumption). Write constraints with a requires clause, as a type-constraint (template <std::integral T>), or on auto. Requires expressions check that operations compile.

Notes

  • Standard concepts live in <concepts>, <iterator>, <ranges>
  • requires requires (T x) { … } — ad-hoc constraint (rarely needed)
  • More constrained overloads win over less constrained ones
  • Concepts are evaluated, never instantiated: no code generated

Concepts in Action

#include <concepts>

template <typename T>
concept Shape = requires(const T& s) {
    { s.area() } -> std::convertible_to<double>;   // must return ~double
    { s.name() } -> std::same_as<std::string>;
};
template <Shape S> void report(const S& s) {       // type-constraint
    std::println("{}: {}", s.name(), s.area());
}
template <typename T> requires std::integral<T>    // requires clause
T gcd(T a, T b) { return b == 0 ? a : gcd(b, a % b); }
auto half(std::floating_point auto x) { return x / 2; }   // constrained auto
template <std::integral T>        void describe(T) { std::print("int"); }
template <std::signed_integral T> void describe(T) { std::print("signed"); }
describe(5u);   // int
describe(-5);   // signed (more constrained wins)

Code Explained

concept Shape = requires … — define a concept from required expressions
{ expr } -> Concept — expression must compile and satisfy the concept
template <Shape S> — shortest constraint syntax
requires std::integral<T> — clause form, can combine with &&
subsumption — signed_integral refines integral, so it's preferred

⚠ Common Mistakes

  • Writing a requirement without braces: s.area() -> std::convertible_to<double>; (needs { s.area() })
  • Over-constraining with std::same_as<int> when std::integral or std::convertible_to is what you mean
  • Expecting a concept to check semantics (like "sorted"); it only checks that code compiles

✓ Tips & Best Practices

  • Start with standard concepts before writing your own
  • Name concepts after capabilities (Drawable, Serializable) rather than types
  • Use static_assert(Shape<Circle>); to test that your types model a concept

Quick Summary

  • concept C = … — named compile-time predicate
  • template <C T> / requires C<T> / C auto — three spellings
  • requires expression — check that operations compile
  • subsumption — most constrained overload wins
