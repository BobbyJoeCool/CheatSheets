std::shared_ptr & std::weak_ptr

std::make_shared · use_count · control block · std::weak_ptr · lock() · reference cycles · enable_shared_from_this

Shared Ownership

std::shared_ptr<T> allows multiple owners. A control block holds a reference count; the object is deleted when the last shared_ptr to it is destroyed. Copying increments the count atomically, so shared_ptr costs more than unique_ptr. std::weak_ptr observes a shared object without owning it, which breaks reference cycles and lets you check whether the object still exists.

Notes

  • Create with std::make_shared<T>(args...) (one allocation)
  • use_count() — current number of owners (for debugging)
  • weak_ptr::lock() — get a shared_ptr or null if expired
  • The count is thread-safe; the pointed-to object isn't automatically

shared_ptr & weak_ptr

auto cfg = std::make_shared<Config>("prod");   // count 1
auto alias = cfg;                              // count 2
cfg.use_count();                               // 2
alias.reset();                                 // count 1

std::weak_ptr<Config> watcher = cfg;           // doesn't own
if (auto locked = watcher.lock()) {            // shared_ptr or null
    locked->reload();
}
cfg.reset();                                   // count 0 → deleted
watcher.expired();                             // true

struct Node {
    std::shared_ptr<Node> next;
    std::weak_ptr<Node>   prev;                // weak: no cycle
};
struct Session : std::enable_shared_from_this<Session> {
    void start() { schedule(shared_from_this()); }   // keep alive
};

Code Explained

copying a shared_ptr — increments the count
reset() — drops this owner
weak_ptr::lock() — safe temporary access
expired() — true once the object is gone
prev as weak_ptr — avoids a cycle that would never be freed
shared_from_this() — get a shared_ptr to this safely

⚠ Common Mistakes

  • Two shared_ptrs built from the same raw pointer (shared_ptr<T>(raw) twice); each deletes it
  • Reference cycles (A → B → A) with shared_ptr; neither count reaches zero, so both leak
  • Calling shared_from_this() in a constructor or on an object not owned by a shared_ptr

✓ Tips & Best Practices

  • Start with unique_ptr; convert to shared_ptr only when ownership is truly shared (unique_ptr converts implicitly)
  • Pass const T& or T* to functions that don't care about ownership
  • Use weak_ptr for caches, observers, and back-pointers

Quick Summary

  • std::shared_ptr — shared ownership, ref-counted
  • make_shared — one allocation
  • std::weak_ptr — non-owning observer, breaks cycles
  • enable_shared_from_this — safe self-reference
