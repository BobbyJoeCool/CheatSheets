Sheet 018

C-Style Strings

char[] · '\0' terminator · const char* literals · strlen · strcpy / strncpy · strcmp · buffer overflows

Strings Inherited from C

A C-string is an array of char ending in a null terminator '\0'. String literals like "hi" have type const char[3] and decay to const char*. The <cstring> functions walk memory until they hit '\0', and none of them know the buffer's size, so they are a classic source of buffer overflows. You still meet C-strings at API boundaries such as main's argv, C libraries, and c_str().

Key Facts

  • "cat" occupies 4 bytes: c a t \0
  • sizeof(arr) counts the terminator; strlen doesn't
  • Modifying a string literal is UB
  • Convert: std::string s = cstr; and back with s.c_str()

C-String Basics

#include <cstring>

char name[6] = "Alice";              // 5 chars + '\0'
const char* greet = "Hello";         // points to read-only literal

std::strlen(name);                   // 5
sizeof(name);                        // 6
std::strcmp("abc", "abd");           // < 0  (a before b)
std::strcmp(name, "Alice") == 0;     // true: equal

char buf[16];
std::strncpy(buf, greet, sizeof buf - 1);
buf[sizeof buf - 1] = '\0';          // strncpy may not terminate!
std::strncat(buf, "!", sizeof buf - std::strlen(buf) - 1);  // "Hello!"
std::strchr(greet, 'l');             // pointer to first 'l'
std::strstr(greet, "ll");            // pointer to "llo"
std::string s = greet;               // C-string → std::string
const char* back = s.c_str();        // std::string → C-string

Code Explained

char name[6] = "Alice" — the compiler appends '\0'
strcmp returns 0 when equal; == would compare addresses
strncpy — bounded copy, but doesn't terminate if the source is too long
strchr / strstr — search, returning a pointer or nullptr
c_str() — valid until the std::string is modified or destroyed

⚠ Common Mistakes

  • Comparing C-strings with ==; that compares pointers. Use std::strcmp(a, b) == 0 or convert to std::string_view
  • Forgetting space for '\0' when sizing a buffer, so the terminator overruns it
  • Storing s.c_str() and using it after s changes; the pointer dangles

✓ Tips & Best Practices

  • Use std::string or std::string_view for everything except C interop
  • Wrap incoming C-strings immediately: std::string_view sv{argv[1]};
  • Prefer std::snprintf or std::format_to_n when you must fill a fixed char buffer

Quick Summary

  • '\0' — terminator that ends every C-string
  • strlen / strcmp — length and comparison
  • strncpy — bounded, but terminate manually
  • c_str() — get a C-string from std::string
