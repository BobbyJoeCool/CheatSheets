Abstract Classes & Interfaces

pure virtual = 0 · abstract base classes · interface pattern · virtual destructor · NVI idiom

Interfaces in C++

A class with at least one pure virtual function (= 0) is abstract: it can't be instantiated, only derived from. C++ has no interface keyword; an interface is an abstract class with only pure virtual functions and a virtual destructor. The Non-Virtual Interface (NVI) idiom makes the public functions non-virtual and the customization points private virtual, so the base class controls pre- and post-conditions.

Notes

  • Derived classes must override every pure virtual to be concrete
  • A pure virtual function may still have a body (called explicitly)
  • A pure virtual destructor still needs a definition
  • Interfaces should have no data members

Interface + NVI

class Storage {                                   // interface
public:
    virtual ~Storage() = default;
    virtual void put(std::string_view key, std::string value) = 0;
    virtual std::optional<std::string> get(std::string_view key) const = 0;
};
class MemoryStorage final : public Storage {
public:
    void put(std::string_view k, std::string v) override {
        data_[std::string(k)] = std::move(v);
    }
    std::optional<std::string> get(std::string_view k) const override;
private:
    std::unordered_map<std::string, std::string> data_;
};
class Report {                                    // NVI
public:
    std::string render() const { auto s = body(); return header() + s; }
private:
    virtual std::string body() const = 0;         // customization point
    std::string header() const { return "== Report ==\n"; }
};

Code Explained

= 0 — pure virtual; Storage is abstract
virtual ~Storage() — safe deletion through the interface
MemoryStorage — overrides every pure virtual, so it's concrete
NVI render() — public, non-virtual; controls the flow
private body() — derived classes override; callers can't call it

⚠ Common Mistakes

  • Forgetting one pure virtual override, then getting "cannot instantiate abstract class" far from the cause
  • Omitting the virtual destructor on an interface, so delete through it is UB
  • Putting data members in an interface, coupling every implementation to them

✓ Tips & Best Practices

  • Depend on interfaces in function parameters (Storage&) to make code testable with fakes
  • Use NVI when every override needs the same logging, locking, or validation around it
  • Consider a C++20 concept instead when the set of types is known at compile time

Quick Summary

  • virtual f() = 0 — pure virtual
  • abstract class — can't instantiate
  • interface — only pure virtuals + virtual dtor
  • NVI — public non-virtual wrapper, private virtual hooks
