Iterators

begin / end · cbegin · rbegin · iterator categories · std::next / std::prev · std::distance · back_inserter

The Glue of the STL

An iterator is a generalized pointer that walks through a container. Every container provides begin() (first element) and end() (one past the last), forming a half-open range [begin, end). Algorithms work on iterator pairs, so one std::sort works with any container that offers the right iterator category. Inserters like std::back_inserter let algorithms append to containers.

Notes

  • *it reads/writes, ++it advances, it == end stops
  • cbegin() / cend() — const iterators (read-only)
  • rbegin() / rend() — reverse traversal
  • Many operations invalidate iterators; see the container sheets

Using Iterators

std::vector<int> v{10, 20, 30, 40};

for (auto it = v.begin(); it != v.end(); ++it) *it += 1;   // 11 21 31 41
for (auto it = v.cbegin(); it != v.cend(); ++it) {}        // read-only
for (auto it = v.rbegin(); it != v.rend(); ++it) {}   // visits 41 31 21 11

auto it = std::find(v.begin(), v.end(), 31);
std::distance(v.begin(), it);           // 2
auto third = std::next(v.begin(), 2);   // iterator to 31
auto prev  = std::prev(v.end());        // iterator to 41
std::advance(it, -1);                   // now at 21

std::vector<int> out;
std::copy_if(v.begin(), v.end(), std::back_inserter(out),
             [](int x) { return x > 20; });   // out: 21 31 41
std::list<int> l{1, 2, 3};
// l.begin() + 1;                       // ERROR: list isn't random access

Code Explained

half-open range — end() is never dereferenced
cbegin — prevents accidental writes
std::distance — element count between iterators
std::next / std::prev / std::advance — move by n
std::back_inserter — calls push_back for each output
list iterators are bidirectional, so no + n

⚠ Common Mistakes

  • Dereferencing end(); it points past the last element
  • Using an iterator after the container reallocated or erased that element
  • Comparing iterators from two different containers; it's UB

✓ Tips & Best Practices

  • Prefer range-for and range algorithms; reach for raw iterators only when you need positions
  • Use std::ranges::begin(r) in generic code; it handles more range types
  • Write auto it rather than spelling out std::vector<int>::iterator
