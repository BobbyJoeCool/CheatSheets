std::unique_ptr

std::make_unique · exclusive ownership · std::move · reset / release · custom deleters · unique_ptr<T[]>

Exclusive Ownership

std::unique_ptr<T> (<memory>) owns a heap object and deletes it automatically when the pointer is destroyed. Ownership is exclusive: a unique_ptr can be moved but not copied, so there's always exactly one owner. It's the same size as a raw pointer and costs nothing extra, making it the default choice for dynamic allocation. Custom deleters let it manage C resources like FILE*.

Notes

  • Create with std::make_unique<T>(args...)
  • Transfer ownership with std::move
  • get() — raw pointer for non-owning use
  • unique_ptr<T[]> — arrays (prefer std::vector)

unique_ptr in Use

#include <memory>

auto w = std::make_unique<Widget>("main", 3);   // owns a Widget
w->draw();                                      // like a raw pointer
if (w) {}                                       // non-null?

auto w2 = std::move(w);                         // transfer; w is null
// auto w3 = w2;                                // ERROR: no copy

void render(const Widget& wd);                  // non-owning parameter
render(*w2);
void adopt(std::unique_ptr<Widget> owned);      // takes ownership
adopt(std::move(w2));

std::unique_ptr<Shape> s = std::make_unique<Circle>(2.0);   // polymorphic
s.reset();                                      // delete now; s == null
Widget* raw = s.release();                      // give up ownership (rare)

auto file = std::unique_ptr<std::FILE, decltype(&std::fclose)>(
    std::fopen("log.txt", "w"), &std::fclose);  // custom deleter

Code Explained

make_unique — allocates and wraps in one exception-safe step
std::move(w) — ownership moves; w becomes null
pass const Widget& when the callee only uses the object
pass unique_ptr by value to transfer ownership
reset() deletes now; release() hands back a raw owning pointer
custom deleter — fclose runs instead of delete

⚠ Common Mistakes

  • Creating two unique_ptrs from the same raw pointer; both delete it
  • Calling release() and forgetting to delete the returned pointer
  • Passing const unique_ptr<T>& everywhere instead of T&; it couples functions to ownership

✓ Tips & Best Practices

  • Always prefer std::make_unique over unique_ptr<T>(new T)
  • Return std::unique_ptr from factory functions to make ownership transfer explicit
  • Store polymorphic objects in std::vector<std::unique_ptr<Base>>

Quick Summary

  • std::unique_ptr<T> — single owner, auto-delete
  • make_unique — create safely
  • move-only — transfer with std::move
  • custom deleter — manage C handles
