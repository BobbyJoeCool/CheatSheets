Condition Variables & Sync Primitives

std::condition_variable · wait with predicate · notify_one / all · std::latch · std::barrier · std::counting_semaphore

Waiting for Events

A condition variable lets threads sleep until another thread signals that some condition may now be true, which is the basis of producer/consumer queues. Always wait with a predicate to handle spurious wakeups. C++20 added simpler one-purpose primitives: std::latch (count down once), std::barrier (reusable phase sync), and std::counting_semaphore (limit concurrent access).

Notes

  • wait requires a std::unique_lock, not scoped_lock
  • Modify the shared state while holding the mutex, then notify
  • notify_one wakes one waiter, notify_all wakes all
  • std::condition_variable_any works with stop_token (C++20)

Producer / Consumer Queue

#include <condition_variable>
#include <queue>
template <class T> class BlockingQueue {
public:
    void push(T v) {
        { std::scoped_lock lock{m_}; q_.push(std::move(v)); }
        cv_.notify_one();                        // wake one consumer
    }
    T pop() {
        std::unique_lock lock{m_};
        cv_.wait(lock, [&] { return !q_.empty(); });   // predicate wait
        T v = std::move(q_.front()); q_.pop();
        return v;
    }
private:
    std::mutex m_;
    std::condition_variable cv_;
    std::queue<T> q_;
};
std::latch ready{3};           // 3 workers count down
ready.count_down();            // in each worker; main calls ready.wait()

Code Explained

push — modify under the lock, notify after releasing it
cv_.wait(lock, pred) — sleeps until pred() is true
the predicate loop handles spurious wakeups
unique_lock — wait unlocks while sleeping and relocks on wake
std::latch — one-shot countdown (C++20)

⚠ Common Mistakes

  • Calling wait(lock) without a predicate; spurious wakeups and missed notifications cause bugs
  • Changing the condition without holding the mutex, then notifying; the waiter can miss it
  • Using notify_one when several different conditions share one condition variable

✓ Tips & Best Practices

  • Prefer std::latch / std::barrier / semaphores when they fit; they're harder to misuse
  • Use std::counting_semaphore to cap parallel downloads or DB connections
  • Add a "closed" flag to queues so consumers can exit cleanly

Quick Summary

  • condition_variable — sleep until signaled
  • wait(lock, pred) — always use a predicate
  • std::latch / std::barrier — C++20 sync points
  • counting_semaphore — limit concurrent access
