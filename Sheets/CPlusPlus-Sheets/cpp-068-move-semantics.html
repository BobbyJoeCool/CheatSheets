Move Semantics

rvalue references && · std::move · move constructor · move assignment · noexcept moves · rule of five / zero

Moving Instead of Copying

Move semantics (C++11) let an object steal the resources of another object that's about to die, instead of copying them. A move constructor T(T&&) and move assignment T& operator=(T&&) take an rvalue reference. std::move(x) doesn't move anything; it's a cast that says "treat x as an rvalue", allowing a move. The moved-from object must stay valid but has an unspecified value.

Rules

  • Temporaries and std::move(x) bind to T&&
  • Mark moves noexcept so containers use them
  • Rule of five: dtor, copy ctor, copy assign, move ctor, move assign
  • Rule of zero: write none; let members handle it

Move Constructor & Assignment

class Buffer {
public:
    Buffer(Buffer&& o) noexcept                       // move ctor
        : size_(std::exchange(o.size_, 0)),
          data_(std::exchange(o.data_, nullptr)) {}   // steal, leave empty
    Buffer& operator=(Buffer&& o) noexcept {          // move assign
        if (this != &o) {
            delete[] data_;
            size_ = std::exchange(o.size_, 0);
            data_ = std::exchange(o.data_, nullptr);
        }
        return *this;
    }
    // ... ctor, dtor, copy ops as on the previous sheet
};
std::vector<std::string> v;
std::string s = "long text that won't fit in SSO";
v.push_back(std::move(s));   // moves; s is now valid but unspecified
Buffer make() { Buffer b(1024); return b; }   // moved or elided

Code Explained

Buffer&& — binds to temporaries and std::moved objects
std::exchange(o.x, 0) — take the value, reset the source
noexcept — lets std::vector move during reallocation
std::move(s) — enables the move; don't use s's value afterwards
returning a local — automatically moved (or elided)

⚠ Common Mistakes

  • return std::move(local); — this blocks copy elision. Just return local;
  • Using an object after std::move as if it still held its value
  • Declaring a destructor (even empty) and silently losing implicit moves, making everything copy

✓ Tips & Best Practices

  • Write = default for all special members when you need just one non-default one
  • Take "sink" parameters by value and std::move them into members
  • Verify with std::is_nothrow_move_constructible_v in a static_assert

Quick Summary

  • T(T&&) — move constructor
  • std::move — cast to rvalue; enables moving
  • noexcept moves — required for fast container growth
  • rule of five / zero — all or nothing
