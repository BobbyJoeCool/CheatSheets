Inheritance

: public Base · protected / private inheritance · base ctor calls · using Base::Base · final classes · object slicing

Deriving Classes

Inheritance creates a new class from an existing one: the derived class gets the base's members and can add or override behavior. class Dog : public Animal models "is-a". Base subobjects are constructed first and destroyed last. Copying a derived object into a base-typed variable slices off the derived part, which is why polymorphic objects are used through references or pointers.

Notes

  • Base constructor args go in the derived initializer list
  • using Base::Base; inherits the base constructors
  • final on a class forbids further derivation
  • Prefer composition ("has-a") when "is-a" doesn't really hold

Base & Derived

class Animal {
public:
    explicit Animal(std::string name) : name_(std::move(name)) {}
    virtual ~Animal() = default;
    const std::string& name() const { return name_; }
protected:
    int age_ = 0;                       // visible to derived classes
private:
    std::string name_;
};
class Dog final : public Animal {
public:
    Dog(std::string name, std::string breed)
        : Animal(std::move(name)), breed_(std::move(breed)) {}
    std::string describe() const { return name() + " the " + breed_; }
private:
    std::string breed_;
};
Dog rex{"Rex", "collie"};  rex.describe();   // "Rex the collie"
Animal a = rex;                              // SLICED: only Animal part

Code Explained

: public Animal — public inheritance keeps the base's public interface public
: Animal(std::move(name)) — base constructed before breed_
protected age_ — derived classes can use it
final — nobody can inherit from Dog
Animal a = rex; — copies only the base part (slicing)

⚠ Common Mistakes

  • Passing derived objects by value as the base type, which slices them; use const Base& or pointers
  • Forgetting public in class D : B; the default for class is private inheritance
  • Using inheritance just to reuse code; composition is usually simpler and less coupled

✓ Tips & Best Practices

  • Keep hierarchies shallow; two or three levels is plenty
  • Use using Base::Base; to forward constructors when the derived class adds no state
  • Mark leaf classes final; it documents intent and enables devirtualization

Quick Summary

  • class D : public B — "is-a" inheritance
  • base constructed first, destroyed last
  • slicing — copying derived into base loses data
  • final — stop further derivation
