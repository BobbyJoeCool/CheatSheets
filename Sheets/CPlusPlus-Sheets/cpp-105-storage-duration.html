Stack, Heap & Storage Duration

automatic · static · thread_local · dynamic · object lifetime · stack overflow · alignas

Where Objects Live

Every object has a storage duration that decides its lifetime. Automatic objects (locals) live on the stack and die at the end of their scope. Static objects (globals, static locals) live for the whole program. Thread storage (thread_local) gives one copy per thread. Dynamic objects are created on the heap with new (or by containers and smart pointers) and live until they are explicitly destroyed.

Stack vs Heap

  • Stack: fast, automatic, limited size (often 1–8 MB)
  • Heap: large, flexible lifetime, slower to allocate
  • Deep recursion or big local arrays → stack overflow
  • alignas(N) forces stricter alignment

Storage Durations

int g_count = 0;                         // static: whole program
thread_local int t_requests = 0;         // one per thread

void handle() {
    int local = 42;                      // automatic: stack
    static int calls = 0;                // static: initialized once
    ++calls;
    auto buf = std::make_unique<char[]>(1 << 20); // dynamic: 1 MB heap
    std::vector<int> v(1000);            // object on stack, data on heap
}                                        // local, buf, v destroyed here

void bad() { char big[50'000'000]; }     // likely stack overflow

struct alignas(64) CacheLine { int data[16]; };   // 64-byte aligned
static_assert(alignof(CacheLine) == 64);

Code Explained

g_count — exists before main and after it returns
static int calls — keeps its value between calls
make_unique<char[]> — heap buffer owned by a stack object
std::vector — small handle on the stack, elements on the heap
alignas(64) — avoid false sharing between threads

⚠ Common Mistakes

  • Returning a pointer or reference to a local; the stack frame is gone
  • Huge local arrays (double m[1000][1000]) that overflow the stack; use std::vector
  • Relying on initialization order of globals in different files (static init order fiasco)

✓ Tips & Best Practices

  • Default to automatic (stack) objects; let containers handle heap memory
  • Replace mutable globals with function-local statics or explicit dependencies
  • Use constinit to guarantee compile-time initialization of globals

Quick Summary

  • automatic — stack, scope-bound
  • static — whole program
  • thread_local — one per thread
  • dynamic — heap, owned by smart pointers/containers
