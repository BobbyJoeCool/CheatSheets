Sheet 043

Linkage, inline & static

inline · static functions · extern · extern "C" · anonymous namespace · internal vs external linkage

Visibility Across Files

Linkage decides whether a name in one .cpp file refers to the same entity in another. Functions and globals have external linkage by default: visible program-wide, so they must be defined exactly once. static at namespace scope or an anonymous namespace gives internal linkage, private to the translation unit. inline allows identical definitions in many TUs, which is how header-only functions work.

Keywords

  • extern int x; — declaration only; defined elsewhere
  • static void helper() — file-private (old style)
  • namespace { … } — file-private (preferred)
  • inline — "may be defined in several TUs", not a speed hint

Across Translation Units

// config.h
extern int g_verbosity;                 // declared, not defined
inline int clampLevel(int v) {          // OK to define in a header
    return v < 0 ? 0 : (v > 3 ? 3 : v);
}
inline constexpr int kMaxLevel = 3;     // one shared constant

// config.cpp
int g_verbosity = 1;                    // the single definition

namespace {                             // internal linkage
    int parseLevel(std::string_view s) { return s.size(); }
}
static int s_calls = 0;                 // also internal (C style)
// C interop: no name mangling
extern "C" int sqlite3_open(const char*, sqlite3**);
extern "C" {
    void legacy_init();
}

Code Explained

extern — tells the compiler the variable lives in another TU
inline function in a header — every TU gets the same definition; linker merges
inline constexpr — one constant instead of a copy per TU
anonymous namespace — names are invisible to other files
extern "C" — use C linkage to call or expose C functions

⚠ Common Mistakes

  • Defining int counter = 0; in a header included by two files, causing "multiple definition of counter"
  • Thinking inline makes code faster; the optimizer decides inlining on its own
  • Using static inside a header for functions; each TU gets its own copy, bloating the binary and its static locals

✓ Tips & Best Practices

  • Put helpers used by one .cpp in an anonymous namespace
  • Avoid mutable globals entirely; pass state explicitly or wrap it in a class
  • Use inline variables (C++17) for header-only singletons and constants

Quick Summary

  • external linkage — visible across TUs (default)
  • namespace {} / static — file-private
  • inline — allows definitions in headers
  • extern "C" — C linkage, no mangling
