Sheet 106

new & delete

new · delete · new[] / delete[] · placement new · memory leaks · double free · std::nothrow

Manual Allocation

new allocates memory on the heap and constructs an object; delete destroys it and frees the memory. Arrays use new[] / delete[], and mixing the forms is UB. Every new must be matched by exactly one delete on every path, including when exceptions are thrown, which is why modern code almost never writes them directly. Placement new constructs an object in memory you already own.

Failure Modes

  • Leak: forgetting delete
  • Double free: deleting twice
  • Use after free: touching memory after delete
  • new throws std::bad_alloc; new (std::nothrow) returns nullptr

new / delete & Friends

int* n = new int{42};            // allocate + construct
delete n;                        // destroy + free
n = nullptr;                     // avoid dangling reuse

int* arr = new int[5]{1, 2, 3};  // 1 2 3 0 0
delete[] arr;                    // must use delete[]

Widget* w = new Widget{"cfg"};
process(*w);                     // if this throws → leak!
delete w;

int* maybe = new (std::nothrow) int[1'000'000];
if (!maybe) { /* handle failure */ }

alignas(Widget) std::byte storage[sizeof(Widget)];
Widget* pw = new (storage) Widget{"inplace"};   // placement new
pw->~Widget();                   // destroy manually, no delete
auto good = std::make_unique<Widget>("cfg");    // what to write instead

Code Explained

new int{42} — heap allocation with initialization
delete[] — required for new[], runs every element's destructor
exception between new and delete — memory leaks
std::nothrow — returns null instead of throwing
placement new — construct in existing storage; call the destructor yourself

⚠ Common Mistakes

  • delete on memory from new[] (or vice versa); that's UB
  • Mixing malloc/free with new/delete; constructors and destructors don't run
  • Deleting through a base pointer without a virtual destructor

✓ Tips & Best Practices

  • Replace new with std::make_unique / std::make_shared and containers
  • If you must hold a raw owning pointer temporarily, wrap it in a smart pointer immediately
  • Run tests with -fsanitize=address to find leaks and double frees

Quick Summary

  • new / delete — allocate+construct / destroy+free
  • new[] / delete[] — array forms, never mix
  • placement new — construct in existing memory
  • modern code — use smart pointers instead
