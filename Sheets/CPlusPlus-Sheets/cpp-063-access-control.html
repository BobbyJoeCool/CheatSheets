Access Control & friend

public · private · protected · friend functions · friend classes · encapsulation · getters / setters

Encapsulation

Access specifiers control who can use a class member. public members form the interface; private members are visible only inside the class (and its friends); protected members are also visible to derived classes. Access is checked per class, not per object, so one Account can read another Account's private data. friend grants a specific function or class full access.

Notes

  • Access control is compile-time only; no run-time cost
  • friend is not inherited and not transitive
  • Prefer non-member functions that use the public interface over friends
  • Getters/setters only where they add value (validation, invariants)

Access Levels & friend

class Account {
public:
    explicit Account(double opening) : balance_(opening) {}
    double balance() const { return balance_; }        // getter
    void deposit(double amt) {
        if (amt <= 0) throw std::invalid_argument("amount must be > 0");
        balance_ += amt;                               // invariant kept
    }
    bool richerThan(const Account& o) const {
        return balance_ > o.balance_;      // other's private: OK
    }
    friend std::ostream& operator<<(std::ostream& os, const Account& a) {
        return os << "Account(" << a.balance_ << ")";
    }
protected:
    void audit() const {}                              // derived classes only
private:
    double balance_;
};

Code Explained

public — callable by anyone
validation in deposit — the reason to keep balance_ private
o.balance_ — allowed; access is per class
friend operator<< — non-member with private access
protected — visible to subclasses, not to outsiders

⚠ Common Mistakes

  • A getter and setter for every field; that's public data with extra steps. Expose operations instead
  • Returning a non-const reference to private data (std::vector<int>& items()), which lets callers bypass invariants
  • Using friend widely to work around design problems

✓ Tips & Best Practices

  • Make data private by default; start with the smallest public interface that works
  • Define operators like operator<< and operator== as hidden friends inside the class
  • Return const T& or std::span<const T> from accessors to large members

Quick Summary

  • public — interface for everyone
  • private — implementation details
  • protected — open to derived classes
  • friend — selective access grant
