Exception Basics

try · catch · throw · catch by const& · catch (...) · rethrow with throw; · stack unwinding

Exceptions

An exception reports an error that the current code can't handle. throw creates an exception object and starts stack unwinding: the runtime leaves functions one by one, running destructors for every local, until it finds a matching catch. If none matches, std::terminate ends the program. Unwinding plus destructors (RAII) is what makes exceptions safe for resource cleanup.

Notes

  • Throw by value, catch by const&
  • catch clauses are tried in order; put derived types first
  • catch (...) catches anything
  • C++ has no finally; destructors do the cleanup

try / catch / throw

#include <stdexcept>

double divide(double a, double b) {
    if (b == 0) throw std::invalid_argument("divide by zero");
    return a / b;
}
try {
    auto r = divide(10, 0);                  // throws; rest skipped
} catch (const std::invalid_argument& e) {
    std::println("bad input: {}", e.what()); // bad input: divide by zero
} catch (const std::exception& e) {          // any std exception
    std::println("error: {}", e.what());
} catch (...) {                              // anything else
    std::println("unknown error");
    throw;                                   // rethrow the same object
}
void load() {
    std::ifstream f{"data.txt"};             // closed by destructor
    parse(f);                                // even if this throws
}

Code Explained

throw std::invalid_argument(...) — create and throw an exception object
catch (const T& e) — matches T and anything derived from T
e.what() — the message passed to the constructor
throw; — rethrows the current exception, preserving its type
std::ifstream destructor — runs during unwinding (RAII)

⚠ Common Mistakes

  • Catching by value: catch (std::exception e) copies and slices derived exceptions. Catch by const&
  • Ordering catch (const std::exception&) before a more specific handler, so the specific one never runs
  • Using throw e; to rethrow; it copies and may slice. Use plain throw;

✓ Tips & Best Practices

  • Throw types derived from std::exception so callers can catch one base type
  • Catch at the level that can actually do something: retry, report to the user, or abort cleanly
  • Wrap main's body in try { … } catch (const std::exception& e) to log unexpected errors

Quick Summary

  • throw — raise; starts stack unwinding
  • catch (const T&) — handle by reference
  • throw; — rethrow unchanged
  • RAII — destructors replace finally
