Catch2

Catch2 (v3) is a popular test framework with a lighter feel than GoogleTest. Tests are named with free-form strings, one assertion macro (REQUIRE / CHECK) handles every comparison by decomposing the expression to print both sides, and sections give each path through a test its own fresh setup. It also includes generators for data-driven tests and a micro-benchmark facility.

Setup

  • vcpkg: catch2; CMake: find_package(Catch2 3 REQUIRED)
  • Link Catch2::Catch2WithMain for a default main
  • catch_discover_tests(tests) registers with CTest
  • Run with tags: ./tests "[cart]"

TEST_CASE, SECTION, Generators

#include <catch2/catch_test_macros.hpp>
#include <catch2/generators/catch_generators.hpp>

TEST_CASE("vector grows when pushing", "[vector]") {
    std::vector<int> v;
    REQUIRE(v.empty());
    SECTION("push_back adds one element") {
        v.push_back(1);
        CHECK(v.size() == 1);          // prints both sides on failure
    }
    SECTION("reserve doesn't change size") {
        v.reserve(10);                 // v is empty again here
        CHECK(v.size() == 0);
        CHECK(v.capacity() >= 10);
    }
}
TEST_CASE("squares", "[math]") {
    auto x = GENERATE(1, 2, 3);
    REQUIRE(square(x) == x * x);
}

Code Explained

TEST_CASE("name", "[tag]") — any descriptive string
REQUIRE — stops this test on failure; CHECK continues
each SECTION re-runs the code above it from scratch
GENERATE(1, 2, 3) — runs the test once per value
expression decomposition — failure shows 2 == 1 with real values

⚠ Common Mistakes

  • Expecting state changed in one SECTION to be visible in the next; each section starts over
  • Including the old single-header catch.hpp (v2) with v3 libraries
  • Writing REQUIRE(a == b && c == d); complex expressions can't be decomposed. Split into two checks

✓ Tips & Best Practices

  • Use tags to group slow or integration tests and exclude them by default
  • Use Catch::Approx or WithinRel matchers for floating comparisons
  • BENCHMARK("name") { return f(); }; for quick micro-benchmarks

Quick Summary

  • TEST_CASE("…", "[tag]") — define a test
  • REQUIRE / CHECK — stop / continue on failure
  • SECTION — independent paths with shared setup
  • GENERATE — data-driven tests
