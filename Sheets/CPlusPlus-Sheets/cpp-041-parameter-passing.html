Parameter Passing

by value · by reference & · by const& · by pointer · out-parameters · choosing the right form

How Arguments Are Passed

Parameters are copies by default (pass by value). A reference parameter (T&) aliases the caller's object so the function can modify it, and a const reference (const T&) avoids the copy while promising not to modify. Pointers (T*) also give access to the caller's object but can be null, which makes them a fit for optional arguments. The choice says a lot about intent.

Rule of Thumb

  • Cheap types (int, double, string_view, span): by value
  • Read-only large types: const T&
  • Must modify caller's object: T&
  • Optional / nullable: T*; taking ownership: by value + std::move

Passing Styles

void byValue(int x)            { x = 99; }   // caller unaffected
void byRef(int& x)             { x = 99; }   // caller changed
void byConstRef(const std::string& s) { std::println("{}", s.size()); }
void byPtr(int* p)             { if (p) *p = 99; }  // may be null

int n = 1;
byValue(n);      // n == 1
byRef(n);        // n == 99
byPtr(&n);       // n == 99
byPtr(nullptr);  // OK, no-op

// "sink": take by value, then move into place
class Person {
    std::string name_;
public:
    explicit Person(std::string name) : name_(std::move(name)) {}
};
Person p{"Ada"};                      // one construction, one move

Code Explained

by value — the function gets its own copy
int& — the parameter is the caller's variable
const std::string& — no copy, read-only
int* — explicit &n at the call site; check for null
sink parameter + std::move — efficient ownership transfer

Call Site Looks

f(int&&)f(5) / f(std::move(n))

⚠ Common Mistakes

  • Passing std::vector or std::string by value to read it; each call copies everything
  • Trying to pass a literal or temporary to a non-const T& parameter; it won't compile
  • Returning a reference or pointer to a local variable; it dangles as soon as the function returns

✓ Tips & Best Practices

  • Prefer return values over out-parameters; copy elision makes returning objects cheap
  • Use std::span for "any contiguous sequence" parameters (arrays, vectors, std::array)
  • Pass smart pointers only when the function deals with ownership; otherwise pass T& or T*

Quick Summary

  • T — copy; good for cheap types and sinks
  • const T& — read-only, no copy
  • T& — modify the caller's object
  • T* — nullable access
