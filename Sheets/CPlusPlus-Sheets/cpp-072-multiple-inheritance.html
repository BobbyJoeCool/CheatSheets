Multiple & Virtual Inheritance

multiple bases · diamond problem · virtual base classes · name ambiguity · mixins

More Than One Base

C++ allows a class to inherit from multiple base classes. This works well for combining independent interfaces or mixins, but introduces name ambiguity and the diamond problem: if two bases share a common base, the derived class contains two copies of it. Virtual inheritance (: virtual public Base) merges them into one shared subobject, at the cost of extra indirection and special construction rules.

Notes

  • Resolve name clashes with Base1::f() qualification
  • With virtual bases, the most derived class constructs the shared base
  • Inheriting several pure interfaces is common and safe
  • Virtual inheritance is rare outside framework code

Diamond & Virtual Inheritance

struct Device {
    explicit Device(int id) : id(id) {}
    int id;
};
struct Scanner : virtual Device {                // virtual base
    Scanner() : Device(0) {}
    void scan() {}
};
struct Printer : virtual Device {
    Printer() : Device(0) {}
    void print() {}
};
struct Copier : Scanner, Printer {
    explicit Copier(int id) : Device(id) {}      // most derived builds Device
};
Copier c{42};
c.id;                     // 42 — only one Device subobject
c.scan(); c.print();
struct Loggable { void log() const {} };         // mixins
struct Serializable { std::string toJson() const; };
struct Order : Loggable, Serializable {};        // independent features

Code Explained

virtual Device — Scanner and Printer share one Device
Copier(int id) : Device(id) — the most derived class initializes the virtual base
Device(0) calls in Scanner/Printer — ignored when building a Copier
without virtual — c.id would be ambiguous (two copies)
mixins — unrelated small bases add capabilities

⚠ Common Mistakes

  • Accidentally creating a diamond without virtual, then hitting "request for member 'id' is ambiguous"
  • Forgetting that the most derived class must initialize virtual bases; intermediate initializers are skipped
  • Using multiple inheritance of implementation where composition would be clearer

✓ Tips & Best Practices

  • Limit multiple inheritance to interfaces and empty mixins
  • If you need a diamond, make the shared base an interface with no data
  • Consider CRTP mixins (struct Order : Loggable<Order>) for compile-time features

Quick Summary

  • class D : A, B — multiple bases
  • diamond — shared base duplicated
  • virtual inheritance — one shared base subobject
  • mixins — small, independent capability bases
