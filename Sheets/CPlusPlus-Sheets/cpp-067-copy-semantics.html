Copying Objects

Copying is controlled by two special members: the copy constructor T(const T&) creates a new object from an existing one, and the copy assignment operator T& operator=(const T&) overwrites an existing object. The compiler generates memberwise versions, which are correct when every member copies itself properly. Classes owning raw resources need a deep copy, and the rule of three says if you write one of destructor / copy ctor / copy assignment, you probably need all three.

Notes

  • Copy ctor: T b = a; or T b{a}; or pass-by-value
  • Copy assign: b = a; on an existing object
  • = delete makes a type non-copyable
  • Copy elision: returning a local or temporary often skips the copy entirely

Deep Copy (Rule of Three)

class Buffer {
public:
    explicit Buffer(std::size_t n) : size_(n), data_(new int[n]{}) {}
    ~Buffer() { delete[] data_; }
    Buffer(const Buffer& o)                         // copy constructor
        : size_(o.size_), data_(new int[o.size_]) {
        std::copy_n(o.data_, size_, data_);         // deep copy
    }
    Buffer& operator=(const Buffer& o) {            // copy assignment
        if (this != &o) { Buffer tmp(o); swap(tmp); }   // copy-and-swap
        return *this;
    }
    void swap(Buffer& o) noexcept {
        std::swap(size_, o.size_); std::swap(data_, o.data_);
    }
private:
    std::size_t size_;
    int* data_;
};

Code Explained

default copy would copy the pointer — two objects, one array, double delete
copy constructor — allocates its own array and copies elements
if (this != &o) — self-assignment guard
copy-and-swap — strong exception guarantee
better: use std::vector<int> and write none of this (rule of zero)

⚠ Common Mistakes

  • Owning a raw pointer and relying on the default copy; both objects delete the same memory
  • Forgetting the self-assignment case, so a = a; frees data before copying it
  • Writing a destructor but not the copy operations (violating the rule of three)

✓ Tips & Best Practices

  • Prefer the rule of zero: hold resources in std::vector, std::string, smart pointers, and write no special members
  • Make resource handles move-only (= delete copies) when copying makes no sense
  • Pass large objects by const& to avoid accidental copies

Quick Summary

  • T(const T&) — copy constructor
  • operator=(const T&) — copy assignment
  • rule of three — dtor + copy ctor + copy assign together
  • rule of zero — let members manage resources
