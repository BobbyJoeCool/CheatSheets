Template Idioms

CRTP · policy-based design · tag dispatch · type erasure · template template parameters

Generic Design Patterns

A handful of template idioms show up constantly in real code. CRTP (Curiously Recurring Template Pattern) lets a base class call into its derived class at compile time, giving static polymorphism with no vtable. Policy-based design plugs behavior in through template parameters. Tag dispatch picks overloads with empty tag types. Type erasure hides concrete types behind a uniform interface, as std::function and std::any do.

Notes

  • CRTP: class Derived : public Base<Derived>
  • C++23 deducing this replaces many CRTP uses
  • Tag dispatch is mostly superseded by if constexpr and concepts
  • Template template parameters: template <template <class> class C>

CRTP, Policy, Type Erasure

template <class Derived>
struct Printable {                                  // CRTP base
    void print() const { std::println("{}", self().toString()); }
    const Derived& self() const { return static_cast<const Derived&>(*this); }
};
struct Point : Printable<Point> {
    int x, y;
    std::string toString() const { return std::format("({}, {})", x, y); }
};
Point{1, 2}.print();                                // (1, 2)

template <class LockPolicy = std::mutex>            // policy-based
class Registry { LockPolicy lock_; /* ... */ };
Registry<NullMutex> fastSingleThreaded;
template <template <class...> class Container>      // template template param
Container<int> makeInts() { return {1, 2, 3}; }
auto v = makeInts<std::vector>();
std::vector<std::function<void()>> tasks;           // type erasure in std

Code Explained

CRTP — Printable knows the derived type at compile time
static_cast<const Derived&>(*this) — the CRTP downcast
policy parameter — swap locking strategy without virtual calls
template template parameter — pass std::vector itself, not std::vector<int>
std::function — holds any callable behind one type

⚠ Common Mistakes

  • In CRTP, deriving class B : public Base<A> by copy-paste mistake; self() casts to the wrong type (UB)
  • Exposing policy parameters in every public type name, making signatures unreadable; add aliases
  • Writing a custom type-erasure class when std::function, std::any, or std::move_only_function already fits

✓ Tips & Best Practices

  • Make the CRTP base constructor private and friend Derived to prevent wrong-type derivation
  • Provide defaults for policy parameters so most users never see them
  • Study std::function and std::any implementations to learn type erasure (small-buffer optimization included)

Quick Summary

  • CRTP — base templated on derived
  • policies — behavior via template parameters
  • tag dispatch — overload on empty types
  • type erasure — hide types behind one interface
