Coroutines

co_await · co_yield · co_return · promise_type · std::coroutine_handle · std::generator

Suspendable Functions

A coroutine is a function that can suspend and resume later, keeping its local state. Any function using co_await, co_yield, or co_return is a coroutine. C++20 provides the low-level machinery (a promise_type and std::coroutine_handle) but almost no ready-made types; C++23 adds std::generator for lazy sequences. For async I/O, use a library such as cppcoro, Boost.Asio, or std::execution (C++26).

Notes

  • The return type decides behavior via its nested promise_type
  • Coroutine state lives on the heap (often optimized away)
  • std::generator<T> is a range: use it in range-for
  • Coroutines can't be constexpr, consteval, or main

std::generator & co_await

#include <generator>                       // C++23
std::generator<int> fibonacci() {
    int a = 0, b = 1;
    while (true) {
        co_yield a;                         // suspend, hand out a
        a = std::exchange(b, a + b);
    }
}
for (int x : fibonacci() | std::views::take(8))
    std::print("{} ", x);                   // 0 1 1 2 3 5 8 13
// Async style (with a library task type, e.g. asio::awaitable):
asio::awaitable<void> session(tcp::socket s) {
    char buf[1024];
    auto n = co_await s.async_read_some(asio::buffer(buf),
                                        asio::use_awaitable);
    co_await asio::async_write(s, asio::buffer(buf, n),
                               asio::use_awaitable);
}

Code Explained

std::generator<int> — lazy sequence produced with co_yield
co_yield a — suspend and give the caller a value
infinite generator — safe because take(8) stops pulling
co_await — suspend until the awaited operation completes
Asio's awaitable — a library-provided coroutine task type

⚠ Common Mistakes

  • Capturing references in a coroutine that outlive the caller's data; the coroutine resumes after the referent is gone
  • Passing std::string_view or references as coroutine parameters for long-lived coroutines; copy instead
  • Writing your own promise_type for production use instead of using a tested library

✓ Tips & Best Practices

  • Use std::generator for tree walks, file readers, and infinite sequences
  • Take coroutine parameters by value so the frame owns its data
  • Check your standard library for std::generator support (GCC 14+ ships it)

Quick Summary

  • coroutine — any function with co_* keywords
  • co_yield / co_await / co_return — suspend points
  • std::generator<T> — lazy range (C++23)
  • libraries — provide task/awaitable types
