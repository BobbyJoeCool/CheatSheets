Lambdas — Basics

[](){} · capture by value / reference · [=] [&] · [this] · mutable · explicit return type

Anonymous Functions

A lambda is an unnamed function object written inline: [captures](params) { body }. The capture list decides which outside variables the lambda can use and whether it copies them ([x], [=]) or refers to them ([&x], [&]). Lambdas are the standard way to pass custom behavior to algorithms like std::sort or std::ranges::count_if.

Notes

  • Each lambda has its own unique, unnamed type: store with auto
  • Captured copies are const inside the body unless mutable
  • A capture-less lambda converts to a plain function pointer
  • Global and static variables don't need capturing

Lambda Basics

auto add = [](int a, int b) { return a + b; };
add(2, 3);                                   // 5

std::vector<int> v{5, 2, 9, 1};
std::ranges::sort(v, [](int a, int b) { return a > b; }); // 9 5 2 1

int limit = 4;
auto big = std::ranges::count_if(v, [limit](int x) { return x > limit; }); // 2

int total = 0;
std::ranges::for_each(v, [&total](int x) { total += x; }); // total 17

auto counter = [n = 0]() mutable { return ++n; };
counter(); counter();                        // 1, 2

auto toDouble = [](int x) -> double { return x / 2; };  // explicit return
toDouble(5);                                 // 2.0 (int division first)

Code Explained

[] — captures nothing
[limit] — copies limit into the lambda
[&total] — refers to the caller's total
mutable — allows modifying the lambda's own copies
-> double — explicit return type
[this] — access members of the enclosing object

Capture Forms

CaptureMeaning
[]nothing
[x]x by value (copy)
[&x]x by reference
[=]everything used, by value
[&]everything used, by reference
[this]the enclosing object (pointer)

⚠ Common Mistakes

  • Capturing locals by reference in a lambda that outlives them (stored callback, thread); it dangles
  • Expecting [=] to copy *this members; it captures this (deprecated implicitly in C++20). Use [this] or [*this]
  • Forgetting mutable and getting "assignment of read-only variable" on a captured copy

✓ Tips & Best Practices

  • List captures explicitly ([&total]) rather than [&] in longer lambdas
  • Name non-trivial lambdas with auto variables so call sites read clearly
  • For async callbacks, capture by value or capture a shared_ptr to keep data alive

Quick Summary
