std::vector — Basics

construction · push_back · emplace_back · [] vs at() · size() vs capacity() · reserve · iteration

The Default Container

std::vector<T> is a dynamic array: contiguous memory that grows as needed. Appending is amortized O(1) because the vector reserves extra capacity and reallocates (usually doubling) only when it's full. Contiguous storage makes it cache-friendly and compatible with C APIs via data(). When in doubt, use a vector.

Size vs Capacity

  • size() — elements stored
  • capacity() — elements that fit before reallocating
  • reserve(n) — grow capacity, size unchanged
  • Reallocation invalidates all pointers, references, and iterators

Building & Reading a Vector

#include <vector>

std::vector<int> a;                  // empty
std::vector<int> b{1, 2, 3};         // 1 2 3
std::vector<int> c(4, 7);            // 7 7 7 7
std::vector<std::string> names(3);   // 3 empty strings

a.push_back(10);                     // copy/move in
a.emplace_back(20);                  // construct in place
a.reserve(100);                      // capacity >= 100, size 2

b[0];                                // 1 (unchecked)
b.at(5);                             // throws std::out_of_range
b.front(); b.back();                 // 1, 3
b.size(); b.empty();                 // 3, false

for (const auto& x : b) std::print("{} ", x);   // 1 2 3
for (std::size_t i = 0; i < b.size(); ++i) {}
int* raw = b.data();                 // pointer to contiguous storage

Code Explained

c(4, 7) vs b{4, 7} — parentheses: count + value; braces: elements
emplace_back — forwards arguments to the element constructor
reserve — avoids repeated reallocation when the final size is known
at() — checked; [] — unchecked
data() — interop with C functions expecting T*

⚠ Common Mistakes

  • Holding a pointer or reference to an element, then calling push_back; reallocation leaves it dangling
  • Calling v.reserve(10); v[3] = 1; — reserve doesn't create elements, so this is UB. Use resize
  • Using std::vector<bool>; it's a packed specialization whose elements are proxies, not bool&

✓ Tips & Best Practices

  • Call reserve() before a loop of push_back when you know roughly how many elements are coming
  • Prefer emplace_back(args...) for types with multi-argument constructors
  • Use std::vector<char> or std::bitset/std::vector<std::uint8_t> instead of vector<bool> when you need real references

Quick Summary

  • std::vector<T> — contiguous, growable array
  • push_back / emplace_back — append
  • size / capacity / reserve — growth control
  • reallocation — invalidates pointers and iterators
