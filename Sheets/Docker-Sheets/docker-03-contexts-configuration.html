Sheet 03

Contexts & Configuration

docker context create / use · DOCKER_HOST · ssh:// hosts · ~/.docker/config.json · credsStore · /etc/docker/daemon.json

Where the CLI Points

The docker CLI is only a client. A context stores *which daemon* it talks to (local socket, remote host over SSH, Desktop's VM) plus TLS settings, so you can switch targets with one command. Client settings live in ~/.docker/config.json; daemon settings live in /etc/docker/daemon.json on Linux or in Settings › Docker Engine in Docker Desktop.

Precedence

  • --context flag beats everything
  • then DOCKER_HOST / DOCKER_CONTEXT env vars
  • then the current context from docker context use
  • default context = local socket unix:///var/run/docker.sock

Contexts

docker context ls                          # * marks the active context
docker context create prod \
  --docker "host=ssh://deploy@prod.example.com"
docker context use prod                    # all commands now hit prod
docker --context default ps                # one-off override
docker context use default                 # back to local

export DOCKER_HOST=ssh://deploy@prod.example.com   # env-var alternative
DOCKER_CONTEXT=prod docker ps                      # per-command env

docker context inspect prod                # endpoint + TLS details
docker context rm prod

Notes

SSH contexts need key-based login and Docker on the remote host
Desktop creates a desktop-linux context; Engine on Linux uses default
Contexts don't copy files: docker build . sends the local folder to the remote daemon
docker context export/import moves a context between machines

~/.docker/config.json (client)

{
  "credsStore": "osxkeychain",
  "currentContext": "default",
  "auths": { "ghcr.io": {} },
  "psFormat": "table {{.Names}}\t{{.Status}}",
  "detachKeys": "ctrl-x,x"
}

/etc/docker/daemon.json (Linux daemon)

{
  "data-root": "/mnt/docker",
  "log-driver": "json-file",
  "log-opts": { "max-size": "10m", "max-file": "3" },
  "dns": ["1.1.1.1"],
  "registry-mirrors": ["https://mirror.example.com"],
  "features": { "containerd-snapshotter": true }
}

⚠ Common Mistakes

  • Editing daemon.json with a syntax error — the daemon won't start; validate with dockerd --validate
  • Changing daemon.json without sudo systemctl restart docker — settings load only at startup
  • Leaving DOCKER_HOST exported — every later command silently goes to the remote host
  • Storing registry passwords as base64 in auths — set credsStore to use the OS keychain

✓ Tips & Best Practices

  • Name contexts after environments (dev, staging, prod) and check docker context ls before risky commands
  • Use credsStore (osxkeychain, wincred, pass, secretservice) to keep tokens out of plain text
  • Set default log rotation in daemon.json so json-file logs can't fill the disk
  • DOCKER_CONFIG=/path points the CLI at a different config folder

Quick Summary

  • docker context use — switch target daemon
  • DOCKER_HOST — env override, e.g. ssh://…
  • config.json — client prefs + credentials
  • daemon.json — engine settings (restart needed)
