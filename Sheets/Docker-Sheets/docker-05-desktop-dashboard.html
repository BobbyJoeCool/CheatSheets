The Dashboard

The Docker Desktop window is a GUI over the same engine the CLI uses: anything you start with docker run or docker compose up shows up here, and actions taken here are ordinary API calls. It is most useful for browsing logs, poking around inside a container's files, cleaning up space and reading Scout vulnerability reports.

Good to Know

  • Compose projects appear as a group you can start/stop together
  • Search bar finds images on Docker Hub and local objects
  • The built-in Terminal opens a host shell inside Desktop
  • Some views need a Docker account sign-in

⚠ Common Mistakes

  • Thinking the GUI shows a different engine than the CLI — check the CLI's active context
  • Deleting a volume from the Volumes view — the data is gone for good; export it first
  • Editing files through Files and expecting them to persist — they're lost when the container is removed
  • Installing many extensions — each runs containers and uses VM resources

✓ Tips & Best Practices

  • Use Builds to find the slow step in a Dockerfile; it shows per-step timing and cache hits
  • Use Exec › Debug mode to get tools like curl and vim inside slim or distroless containers
  • Group by Compose project to restart a whole stack with one click
  • Treat Gordon's answers as drafts; review generated Dockerfiles before using them

Quick Summary

  • Images — layers, Scout CVEs, SBOM
