Sheet 16

docker build & BuildKit

docker build -t · -f · build context · --build-arg · --target · --no-cache · --progress=plain · DOCKER_BUILDKIT

Building

docker build sends the build context (a folder, Git URL or tarball) to the builder and runs the Dockerfile against it. Since Engine 23 the builder is BuildKit: it runs independent steps in parallel, skips stages you don't need, and supports cache and secret mounts. docker build is an alias for docker buildx build with the default builder.

Build Context

  • . at the end = context folder, not the Dockerfile
  • Only files in the context can be COPY'd
  • .dockerignore shrinks what's sent
  • First line of output shows context size transferred

Build Commands

docker build -t myapp:1.0 .                      # Dockerfile in current folder
docker build -t myapp:1.0 -t myapp:latest .      # several tags at once
docker build -f docker/Dockerfile.prod -t myapp:prod .   # another Dockerfile
docker build --build-arg APP_VERSION=1.0 -t myapp:1.0 .
docker build --target test -t myapp:test .       # stop at a stage
docker build --no-cache -t myapp:1.0 .           # ignore cache
docker build --pull -t myapp:1.0 .               # re-check the base image
docker build --progress=plain . 2>&1 | tee build.log   # full output
docker build --platform linux/amd64 -t myapp:amd64 .
docker build -t myapp https://github.com/acme/app.git#main   # Git context
docker build - < Dockerfile                      # no context at all
docker build --secret id=npm,src=$HOME/.npmrc -t myapp .
docker builder prune                             # clear build cache

Code Explained

-t name:tag — tag the result (repeatable)
-f — Dockerfile path; context is still the last argument
--target — build only up to a named stage
--pull — always fetch the newest base image for that tag
--progress=plain — show every RUN line (great for debugging)
--secret — mount a secret into one RUN step (Sheet 17)

⚠ Common Mistakes

  • docker build -f Dockerfile with no context — the trailing . (or a path) is required
  • Sending a 2 GB context because node_modules or datasets aren't in .dockerignore
  • COPY ../shared /app — paths outside the context are invisible; move the context up a level and use -f
  • Using --no-cache to fix every problem — fix the step order instead; it's much slower

✓ Tips & Best Practices

  • Use --progress=plain when a RUN step fails; the default view hides most output
  • docker build --check . catches common Dockerfile mistakes in seconds
  • Tag with both a version and the commit SHA in CI
  • Use --build-context name=../shared to add a second folder without widening the main context

Quick Summary

  • build -t name:tag . — build + tag
  • -f / --target — which file, which stage
  • --build-arg / --secret — inputs
  • BuildKit — default builder since Engine 23
