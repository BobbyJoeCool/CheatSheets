Sheet 08

Container Lifecycle

docker ps -a · start / stop / restart · kill · pause · rm -f · container prune · --restart policies · container states

States

A container moves through created → running → (paused) → exited, and finally removed. Stopping keeps the container and its writable layer, so you can start it again with the same config; removing deletes it. Restart policies tell the daemon to bring a container back after it exits or after the host reboots.

Stop vs Kill

  • stop sends SIGTERM, waits 10 s, then SIGKILL
  • kill sends SIGKILL right away (or -s another signal)
  • Image STOPSIGNAL changes the first signal
  • stop -t 30 waits 30 s before forcing

Lifecycle Commands

docker ps                         # running only
docker ps -a                      # all, including exited
docker ps -a --filter status=exited --format '{{.Names}}: {{.Status}}'
docker start web                  # start an existing (stopped) container
docker start -ai web              # start and attach (interactive)
docker stop web                   # graceful stop
docker stop -t 30 web             # longer grace period
docker restart web
docker kill web                   # immediate SIGKILL
docker kill -s HUP web            # send SIGHUP (e.g. reload config)
docker pause web                  # freeze all processes (unpause to thaw)
docker rm web                     # remove stopped container
docker rm -f web                  # stop + remove in one step
docker container prune            # remove ALL stopped containers
docker wait web                   # block until it exits, print exit code

Notes

Most commands take a name, a full ID or a unique ID prefix (docker stop 3f2)
Pass several at once: docker stop web db cache
docker rm $(docker ps -aq -f status=exited) — remove exited ones
docker update --restart=no web changes a policy without recreating

⚠ Common Mistakes

  • Expecting docker stop to be instant — apps that ignore SIGTERM wait the full 10 s, then get killed
  • Using always for one-off jobs — they restart forever; use on-failure or no
  • docker container prune on a shared host — deletes everyone's stopped containers
  • Debugging a crash loop by restarting — read docker logs first (Sheet 09)

✓ Tips & Best Practices

  • Use unless-stopped for long-running services on a single host
  • Make your app handle SIGTERM to shut down cleanly within the grace period
  • Filter with -f name=, -f label=, -f status=, -f ancestor=nginx
  • Use docker wait in scripts to get a job's exit code

Quick Summary

  • stop / kill — SIGTERM+grace vs SIGKILL
  • rm -f — force stop + remove
  • --restart unless-stopped — survive reboots
  • ps -a — see exited containers too
