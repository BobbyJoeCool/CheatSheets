Compose Workflows

compose exec vs run --rm · build --pull · watch / develop.watch · -f override files · compose.override.yaml · config · include · --scale

Working with a Stack Day to Day

Beyond up and down, Compose has commands for one-off tasks, live code sync during development, and layering files for different environments. Compose automatically merges compose.override.yaml on top of compose.yaml, which is the usual place for dev-only settings.

exec vs run

  • exec — command in the running service container
  • run --rm — new one-off container from the service config
  • run skips ports unless you add --service-ports
  • run starts dependencies first

Commands

docker compose exec web sh                        # shell in running container
docker compose run --rm web npm test              # one-off container
docker compose run --rm --no-deps web rake db:migrate

docker compose build --pull web                   # rebuild with fresh base
docker compose up -d --force-recreate web
docker compose up -d --scale worker=3             # 3 worker containers
docker compose watch                              # sync + rebuild on change

docker compose -f compose.yaml -f compose.prod.yaml up -d
docker compose config                             # final merged YAML
docker compose ls                                 # all projects on host

Notes

--no-deps — don't start linked services
--force-recreate — new containers even if config is unchanged
--scale fails if the service has container_name or a fixed host port
Later -f files override earlier ones key by key
Lists like ports are merged, not replaced

develop.watch

services:
  web:
    build: .
    develop:
      watch:
        - action: sync
          path: ./src
          target: /app/src
        - action: sync+restart
          path: ./config
          target: /app/config
        - action: rebuild
          path: package.json

include + override

# compose.yaml
include:
  - ./db/compose.yaml      # own project dir
services:
  web:
    build: .

# compose.override.yaml (auto-loaded)
services:
  web:
    volumes: ["./src:/app/src"]
    environment: { DEBUG: "1" }

⚠ Common Mistakes

  • Running tests with exec and finding the dev server's state — use run --rm for a clean container
  • Prod deploy picking up compose.override.yaml — pass -f compose.yaml -f compose.prod.yaml explicitly
  • watch with a bind mount of the same folder — files sync twice; use one or the other
  • Expecting --scale to load-balance published ports — use a proxy (Traefik, nginx) in front

✓ Tips & Best Practices

  • sync for interpreted code, sync+restart for config, rebuild for dependency files
  • Use docker compose config > resolved.yaml to review exactly what will deploy
  • include lets each team own its own Compose file while sharing one stack
  • docker compose ls finds stacks you forgot were running

Quick Summary

  • exec vs run --rm — existing vs fresh container
  • watch — live sync / rebuild
  • -f a -f b / override file — layer configs
  • config — print the final merged model
