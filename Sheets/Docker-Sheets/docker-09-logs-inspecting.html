Sheet 09

Logs & Inspecting

docker logs -f --tail --since · inspect · --format '{{.State.Status}}' · top · stats · port · diff · events

Seeing Inside

Docker captures everything a container's main process writes to stdout and stderr; docker logs reads it back. docker inspect returns the full JSON config and state of any object (container, image, volume, network), and --format pulls out single fields with Go templates. stats, top and events show live resource use, processes and daemon activity.

Notes

  • Apps must log to stdout/stderr, not files, for docker logs to work
  • Logs persist until the container is removed
  • docker logs works with json-file and local drivers (and others via dual logging)

Logs and Inspect

docker logs web                        # everything so far
docker logs -f web                     # follow (like tail -f)
docker logs --tail 50 -f web           # last 50 lines, then follow
docker logs --since 10m web            # last 10 minutes (or 2026-10-16T09:00)
docker logs -t web 2>&1 | grep ERROR   # timestamps; merge stderr to grep

docker inspect web                     # full JSON
docker inspect -f '{{.State.Status}} {{.State.ExitCode}}' web
docker inspect -f '{{.NetworkSettings.Networks.bridge.IPAddress}}' web
docker inspect -f '{{json .Mounts}}' web | jq
docker inspect -f '{{.State.Health.Status}}' web    # healthy / unhealthy
docker inspect -f '{{.Config.Env}}' web             # env vars

Template Tips

{{.Field.Sub}} — walk the JSON keys shown by plain inspect
{{json .X}} — print a sub-object as JSON
{{range .Mounts}}{{.Source}} {{end}} — loop over a list
{{index .Config.Labels "env"}} — keys with dots or dashes
Pipe to jq for anything complicated

Live Views

⚠ Common Mistakes

  • Logging to /var/log/app.log inside the container — docker logs shows nothing; symlink it to /dev/stdout
  • Grepping docker logs without 2>&1 — stderr lines skip the pipe
  • No log rotation — json-file grows forever; set max-size (Sheets 03, 28)
  • Reading the IP from inspect to connect containers — use network names instead (Sheet 20)

✓ Tips & Best Practices

  • docker logs --since 5m -f is the fastest way to watch a misbehaving service
  • docker events --filter event=oom catches memory kills as they happen
  • Save a template: docker ps --format '{{.Names}}\t{{.Image}}' in psFormat
  • docker diff quickly shows what an app wrote to the container filesystem

Quick Summary

  • logs -f --tail N --since T — read output
  • inspect -f '{{…}}' — any config/state field
  • stats / top — resources and processes
  • events / diff / port — activity, file changes, ports
