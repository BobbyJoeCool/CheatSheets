Sheet 06

Docker Desktop — Desktop-Only Features

built-in Kubernetes · host.docker.internal · Model Runner (docker model) · Enhanced Container Isolation · proxy settings · Troubleshoot / reset to factory defaults

Features Engine Doesn't Have

Docker Desktop adds a few things plain Docker Engine on Linux lacks: a one-click local Kubernetes cluster, the special DNS name host.docker.internal for reaching your host, Model Runner for local AI models, admin-level security controls, and a troubleshooting menu that can reset the VM without reinstalling.

Notes

  • On Linux Engine, add --add-host=host.docker.internal:host-gateway to get the same name
  • Enhanced Container Isolation and Settings Management need a Docker Business plan
  • Kubernetes here is for local dev; see the Kubernetes set for kubectl

Using the Extras

# Reach a service running on your laptop (e.g. Postgres on :5432)
docker run --rm postgres:17 psql -h host.docker.internal -U app

# Built-in Kubernetes (after enabling it in Settings › Kubernetes)
kubectl config use-context docker-desktop
kubectl get nodes

# Model Runner: local LLMs with an OpenAI-compatible API
docker model pull ai/smollm2
docker model run ai/smollm2 "Explain Docker volumes in one line"
docker model list                # models stored locally
docker model ps                  # models loaded in memory
docker model rm ai/smollm2

Notes

host.docker.internal resolves to the host from inside any container
gateway.docker.internal reaches the VM's gateway
Desktop Kubernetes can use kubeadm (single node) or kind (multi-node)
Model Runner models are OCI artifacts pulled from Docker Hub or Hugging Face
Compose can declare models with a top-level models: key

⚠ Common Mistakes

  • Using localhost inside a container to reach the host — that's the container itself; use host.docker.internal
  • Hard-coding host.docker.internal in prod config — it exists only on Desktop (or with host-gateway)
  • Clicking Clean / Purge data without backups — every volume is deleted
  • Leaving Kubernetes enabled when unused — it uses CPU and memory all the time

✓ Tips & Best Practices

  • Try Restart first, then Reset Kubernetes, before Reset to factory defaults
  • Use extra_hosts: ["host.docker.internal:host-gateway"] in Compose so it works on Linux too
  • Run docker model status to check Model Runner before calling its API
  • Corporate proxies: set them in Resources › Proxies so both pulls and containers use them

Quick Summary

  • host.docker.internal — reach the host
  • docker-desktop — local Kubernetes context
  • docker model — run local AI models
  • Troubleshoot — restart, reset, diagnose
