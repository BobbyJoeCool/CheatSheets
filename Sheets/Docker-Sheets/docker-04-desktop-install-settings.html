Sheet 04

Docker Desktop — Install & Settings

macOS / Windows / Linux installs · WSL 2 backend · CPU / memory / disk limits · file sharing (VirtioFS) · Rosetta on Apple silicon · docker desktop start / stop / status · license terms

What Docker Desktop Adds

Docker Desktop runs the Linux engine inside a managed VM and adds the CLI, Compose, Buildx, a dashboard, Kubernetes and extensions in one installer. Containers can only use the CPU, memory and disk you give that VM, so the Resources settings matter. On Windows the VM is a WSL 2 distro; on macOS it uses Apple's Virtualization framework.

Install

  • macOS — .dmg from docker.com or brew install --cask docker
  • Windows — installer; enable WSL 2 first (wsl --install)
  • Linux — .deb/.rpm package; runs its own VM, separate from Engine
  • Free for personal, education and small business; paid for larger orgs

docker desktop CLI

docker desktop status            # running / stopped
docker desktop start             # start the VM + engine (no GUI needed)
docker desktop stop              # stop everything
docker desktop restart
docker desktop update --check-only
docker desktop logs              # Desktop's own log entries
docker desktop diagnose          # gather + upload diagnostics
docker desktop enable model-runner      # turn a feature on/off
docker desktop engine use windows       # Windows only: switch engine

Notes

Handy for scripts and CI agents: start Desktop headless, wait for status
engine ls/use switch between Linux and Windows containers (Windows hosts only)
docker desktop kubernetes manages the built-in cluster (Sheet 06)
Settings changes in the GUI may restart the VM and stop running containers

⚠ Common Mistakes

  • Mounting a host folder that isn't shared — add it under Resources › File sharing (macOS/Linux)
  • Running a bind-mounted Node/PHP project from the Windows filesystem — very slow; move it into the WSL distro
  • Giving the VM 2 GB and wondering why builds get OOMKilled — raise memory under Resources
  • Installing Desktop for Linux next to Engine and confusing contexts — check docker context ls

✓ Tips & Best Practices

  • Turn on Rosetta for x86/amd64 emulation on Apple silicon for faster amd64 containers
  • Use docker desktop start in login scripts instead of opening the GUI
  • Enable the containerd image store to build and load multi-platform images locally
  • Set a sane disk limit; Desktop's VM disk does not shrink on its own

Quick Summary

  • Docker Desktop — VM + engine + GUI + tools
  • WSL 2 — the Windows backend
  • Resources — CPU/memory/disk for all containers
  • docker desktop start|stop|status — CLI control
