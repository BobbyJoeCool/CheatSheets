Sheet 18

Buildx & Multi-Platform Builds

docker buildx create / use · --platform linux/amd64,linux/arm64 · --push · --cache-to / --cache-from · imagetools inspect · buildx bake

One Tag, Many CPUs

Laptops are often arm64 (Apple silicon) while servers are often amd64. A multi-platform image is one tag pointing at an index with a variant per architecture; each host pulls the one it needs. Buildx builds them using QEMU emulation, native nodes, or cross-compiling in the Dockerfile.

Where Multi-Platform Works

  • Docker Desktop and Engine 29+ with the containerd image store
  • Or a docker-container builder (buildx create)
  • Emulation needs QEMU (binfmt); Desktop includes it
  • Emulated builds are slow; cross-compile when you can

Buildx Commands

docker buildx ls                                 # builders + platforms
docker buildx create --name multi --driver docker-container --use
docker run --privileged --rm tonistiigi/binfmt --install all   # QEMU (Linux)

docker buildx build --platform linux/amd64,linux/arm64 \
  -t ghcr.io/acme/api:1.4 --push .

docker buildx build --platform linux/amd64 --load -t api:amd64 .

docker buildx build \
  --cache-from type=registry,ref=ghcr.io/acme/api:cache \
  --cache-to   type=registry,ref=ghcr.io/acme/api:cache,mode=max \
  -t ghcr.io/acme/api:1.4 --push .

docker buildx imagetools inspect ghcr.io/acme/api:1.4   # list platforms
docker buildx bake                     # build targets from docker-bake.hcl

Notes

--push sends all platforms + the index in one go
--load puts the image in the local store (multi-platform needs the containerd store)
mode=max caches every stage, not just the final one
In GitHub Actions use --cache-to type=gha
TARGETPLATFORM, TARGETARCH, BUILDPLATFORM are automatic build args

Cross-Compile Instead of Emulating

FROM --platform=$BUILDPLATFORM golang:1.25 AS build
ARG TARGETOS TARGETARCH
RUN GOOS=$TARGETOS GOARCH=$TARGETARCH \
    go build -o /out/app .
FROM alpine:3.22
COPY --from=build /out/app /app

docker-bake.hcl

group "default" { targets = ["api", "web"] }
target "api" {
  context   = "./api"
  platforms = ["linux/amd64", "linux/arm64"]
  tags      = ["ghcr.io/acme/api:1.4"]
}
target "web" { context = "./web" }

⚠ Common Mistakes

  • Running an arm64 image on amd64 servers — exec format error; build for linux/amd64 too
  • --platform a,b --load on the classic image store — error; enable containerd or use --push
  • Emulating a 20-minute compile under QEMU — can be 5–10× slower; cross-compile with $BUILDPLATFORM
  • Forgetting docker buildx use after create — builds still go to the old builder

✓ Tips & Best Practices

  • Check what a tag supports with buildx imagetools inspect before deploying
  • Use a registry or GHA cache in CI so builds don't start cold
  • Bake files keep long build commands in version control
  • docker buildx bake --print shows the resolved targets without building

Quick Summary

  • --platform a,b — multi-arch build
  • --push / --load — where the result goes
  • --cache-to/--cache-from — shared cache
  • $BUILDPLATFORM + $TARGETARCH — cross-compile
