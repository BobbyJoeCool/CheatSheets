Sheet 11

Resource Limits & Runtime Options

--memory · --cpus · --pids-limit · --user · --read-only · --tmpfs · --init · OOMKilled / 137

Limits and Hardening

By default a container can use all of the host's CPU and memory. Limits use Linux cgroups: hit the memory limit and the kernel kills the process (OOMKilled, exit 137); hit the CPU limit and it's only slowed down. Runtime flags such as --user and --read-only also shrink what a compromised app could do.

Units

  • Memory: b, k, m, g — e.g. 512m, 2g
  • --cpus 1.5 = one and a half cores' worth of time
  • On Desktop, limits sit inside the VM's own limits
  • Change limits live: docker update --memory 1g web

Setting Limits

docker run -d --name api \
  --memory 512m --memory-swap 512m \
  --cpus 1.5 --pids-limit 200 \
  --user 1000:1000 \
  --read-only --tmpfs /tmp:size=64m \
  --init --ulimit nofile=65536:65536 \
  myapi:1.4

docker stats --no-stream api             # check usage vs limit
docker inspect -f '{{.State.OOMKilled}}' api   # true → raise --memory
docker update --cpus 2 --memory 1g --memory-swap 1g api

Code Explained

--memory-swap = memory + swap; equal to --memory means no swap
--pids-limit caps processes (stops fork bombs)
--cpus throttles; it never kills the container
--read-only plus --tmpfs keeps only /tmp writable (in RAM)
--init reaps zombie processes and forwards signals to your app
--ulimit raises per-process limits like open files

⚠ Common Mistakes

  • Setting --memory below what the app (or JVM heap) needs — instant exit 137; check OOMKilled
  • Expecting --cpus 0.5 to fail when exceeded — it only throttles, so things just get slow
  • --read-only without --tmpfs for /tmp or /run — apps that write temp files crash
  • Running Chrome/Playwright with the default 64 MB /dev/shm — random crashes; raise --shm-size

✓ Tips & Best Practices

  • Set both --memory and --cpus on shared hosts so one container can't starve the rest
  • Java 10+, Node 20+ and Go read cgroup limits; size heaps relative to --memory
  • Use --init (or init: true in Compose) for apps that spawn child processes
  • Prefer --user with a fixed UID that owns the files your app writes

Quick Summary

  • --memory — hard cap; exceed = OOMKilled
  • --cpus — throttle, never kill
  • --read-only + --tmpfs — locked-down filesystem
  • docker update — change limits live
