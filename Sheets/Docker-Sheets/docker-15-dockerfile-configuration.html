Dockerfile Configuration Instructions

ENV vs ARG · USER · LABEL · HEALTHCHECK · VOLUME · SHELL · STOPSIGNAL · # syntax=

Configuring the Image

These instructions don't add files; they set metadata and defaults baked into the image: environment variables, the user to run as, a health probe, labels and signals. ARG values exist only during the build, while ENV values stay in the image and are visible to every container started from it.

ENV vs ARG

  • ARG — build-time only; set with --build-arg
  • ENV — build time and run time; override with -e
  • ARG before FROM is only usable in FROM lines
  • Neither is safe for secrets — both show in history/inspect

Config Instructions in Use

# syntax=docker/dockerfile:1
ARG PY_VERSION=3.13
FROM python:${PY_VERSION}-slim
# ARGs declared before FROM must be re-declared after it
ARG APP_VERSION=dev
ENV PYTHONUNBUFFERED=1 \
    APP_ENV=production
LABEL org.opencontainers.image.version=$APP_VERSION \
      org.opencontainers.image.source="https://github.com/acme/api"
RUN useradd --create-home --uid 10001 app
WORKDIR /home/app
COPY --chown=app:app . .
USER app
VOLUME /home/app/data
STOPSIGNAL SIGINT
HEALTHCHECK --interval=30s --timeout=3s --start-period=10s --retries=3 \
  CMD ["python", "healthcheck.py"]
CMD ["gunicorn", "-b", "0.0.0.0:8000", "app:app"]

Notes

# syntax= must be the first line; picks the Dockerfile frontend version
ARG defaults can be overridden: --build-arg APP_VERSION=1.4
HEALTHCHECK sets status shown in docker ps (healthy/unhealthy)
The check needs a tool in the image; here a script that exits 1 on failure
USER affects every later RUN, CMD and ENTRYPOINT

⚠ Common Mistakes

  • ENV API_KEY=… or ARG TOKEN for secrets — readable by anyone with the image; use build secrets (Sheet 17)
  • Declaring ARG before FROM and using it later — it's out of scope; repeat ARG NAME after FROM
  • HEALTHCHECK CMD curl … on an image without curl — always unhealthy
  • VOLUME in a base image — later RUN changes to that path are thrown away

✓ Tips & Best Practices

  • Use OCI label keys (org.opencontainers.image.*) so registries display them
  • Give the app user a fixed UID (e.g. 10001) so file permissions are predictable
  • Add --start-period so slow-starting apps aren't marked unhealthy too early
  • Keep # syntax=docker/dockerfile:1 to get new features like RUN --mount

Quick Summary

  • ARG — build only · ENV — build + run
  • USER — drop root
  • HEALTHCHECK — container health status
  • LABEL / STOPSIGNAL / SHELL — metadata and behavior
