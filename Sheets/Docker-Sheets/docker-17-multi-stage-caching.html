Sheet 17

Multi-Stage Builds & Layer Caching

FROM … AS · COPY --from= · layer order · RUN --mount=type=cache · --mount=type=secret · slim / alpine / distroless

Small Images, Fast Rebuilds

A multi-stage build uses several FROM lines: early stages hold compilers and dev tools, and the final stage copies in only the finished output, so the shipped image stays small. Layer caching reuses a step when its instruction and inputs haven't changed; once one step misses, every step after it rebuilds.

Cache Rules

  • COPY/ADD miss when file contents change
  • RUN misses only when its command text changes
  • Order steps from least- to most-often changed
  • Changing the base image invalidates everything

Multi-Stage Go Build with Cache + Secret

# syntax=docker/dockerfile:1
FROM golang:1.25 AS build
WORKDIR /src
COPY go.mod go.sum ./
RUN --mount=type=cache,target=/go/pkg/mod go mod download
COPY . .
RUN --mount=type=cache,target=/root/.cache/go-build \
    CGO_ENABLED=0 go build -o /out/api ./cmd/api

FROM build AS test
RUN go test ./...

FROM gcr.io/distroless/static-debian12 AS final
COPY --from=build /out/api /api
USER nonroot
ENTRYPOINT ["/api"]

Code Explained

AS build — names a stage so others can refer to it
--mount=type=cache — keeps the module/compiler cache between builds, not in the image
FROM build AS test — stage built only with --target test
Final stage is distroless: no shell, no package manager, ~2 MB base
COPY --from=build — pull files from an earlier stage (or any image)

Secrets and Other Mounts

RUN --mount=type=secret,id=npm,target=/root/.npmrc npm ci
#   docker build --secret id=npm,src=$HOME/.npmrc .
RUN --mount=type=ssh git clone git@github.com:acme/priv.git
#   docker build --ssh default .
RUN --mount=type=bind,source=req.txt,target=/tmp/req.txt \
    pip install -r /tmp/req.txt
COPY --from=nginx:1.27 /etc/nginx/nginx.conf /etc/nginx/

⚠ Common Mistakes

  • COPY . . before installing dependencies — any code change re-runs the whole install
  • RUN apt-get update in one step and apt-get install in another — stale cached index; combine them
  • Passing tokens with ARG — stored in image history; use --mount=type=secret
  • Shipping the build stage by forgetting a final FROM — image includes the whole toolchain

✓ Tips & Best Practices

  • Put --target stages (test, lint) after build so CI can run them on demand
  • Use apt-get install --no-install-recommends and clean lists in the same RUN
  • Name every stage; COPY --from=0 breaks when stages move
  • Check results with docker image ls and docker image history

Quick Summary

  • FROM … AS name — define a stage
  • COPY --from=name — take only the output
  • --mount=type=cache — fast dependency installs
  • --mount=type=secret — secrets that never land in layers
