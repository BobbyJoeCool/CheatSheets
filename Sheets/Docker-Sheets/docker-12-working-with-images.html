Images, Tags and Digests

An image reference looks like registry/namespace/name:tag@digest. A tag (1.27, latest) is a movable label the publisher can point at a new build; a digest (sha256:…) is the content hash and never changes. Images are stacks of read-only layers, and layers shared between images are stored only once on disk.

Reading a Reference

  • nginx = docker.io/library/nginx:latest
  • bitnami/redis:7.4 — Docker Hub user/org bitnami
  • ghcr.io/acme/api:2.1 — another registry
  • nginx@sha256:ab12… — exact, immutable content

Pull, List, Remove

docker pull nginx:1.27                       # one tag
docker pull --platform linux/arm64 nginx:1.27
docker pull nginx@sha256:<digest>            # exact content

docker image ls                              # same as docker images
docker image ls --digests                    # show sha256 digests
docker image ls -f dangling=true             # untagged <none> layers

docker image history nginx:1.27              # layers + the step that made each

docker rmi nginx:1.27                        # remove tag (+ layers if unused)
docker image prune                           # dangling only
docker image prune -a                        # every image no container uses

Notes

rmi fails while a container (even stopped) uses the image; add -f or remove it first
Dangling = <none>:<none>, left over when a tag moves to a new build
history --no-trunc shows full RUN commands
Size shown is the uncompressed size on disk

Moving Images Without a Registry

⚠ Common Mistakes

  • Relying on latest — it can change any time; two hosts may run different code
  • docker image prune -a on a build server — wipes base images, so the next build re-downloads everything
  • Using export/import to back up an image — it flattens layers and drops CMD, ENV and other config
  • Thinking docker rmi frees space while containers still use the layers — remove containers first

✓ Tips & Best Practices

  • Pin by digest in production: FROM python:3.13-slim@sha256:…
  • Use docker image ls --digests to grab the digest of what you just tested
  • docker save/load is the way to ship images to air-gapped machines
  • Check docker image history to find which step made an image huge

Quick Summary

  • pull name:tag — download
  • tag vs @sha256: — movable vs fixed
  • rmi / image prune -a — clean up
  • save / load — images as tar files
