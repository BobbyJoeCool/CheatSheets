Exec, Copy & Debugging

docker exec -it sh · exec -u root · attach vs exec · docker cp · docker debug · commit · exit codes 125 / 126 / 127

Getting Into a Container

docker exec starts a new process inside a running container — usually a shell for poking around. docker attach instead connects your terminal to the main process (PID 1), so Ctrl-C there can stop the container. docker cp copies files in or out, even from stopped containers, and docker debug gives you a full toolbox shell in slim images that have no shell at all.

exec vs attach

  • exec — new process; exiting it leaves the container running
  • attach — main process's stdin/stdout; detach with Ctrl-P Ctrl-Q
  • exec only works on running containers
  • Use docker logs -f rather than attach to watch output

Exec, Copy, Debug

docker exec -it web sh                  # shell (bash may not exist)
docker exec -it web bash
docker exec -it -u root web sh          # as root, even if image uses USER
docker exec web cat /etc/os-release     # one command, no TTY
docker exec -e DEBUG=1 -w /app web ./check.sh
docker exec -it db psql -U postgres     # open a DB client inside

docker cp web:/etc/nginx/nginx.conf .   # container → host
docker cp ./site/. web:/usr/share/nginx/html/   # host → container
docker cp web:/var/log - | tar -t       # stream a tar archive

docker debug web                        # toolbox shell (Desktop)
docker debug myimage:1.0                # debug an image without running it
docker commit web web-snapshot:debug    # save container state as an image

Notes

Distroless/scratch images have no sh, so exec fails; use docker debug
docker debug changes to a running container are real; for images they're discarded
docker cp paths: trailing /. copies a folder's contents
docker commit is for debugging snapshots, not for building images

⚠ Common Mistakes

  • docker exec -it app bash on Alpine — bash isn't installed; use sh
  • Fixing a bug inside a running container with exec — lost on the next deploy; change the Dockerfile
  • Pressing Ctrl-C while attached — stops the main process and often the container
  • docker cp ./dir web:/app vs ./dir/. — the first nests dir inside /app

✓ Tips & Best Practices

  • Check docker inspect -f '{{.State.ExitCode}}' before digging through logs
  • Use docker exec web env to confirm env vars actually reached the app
  • Crash on start? Override the command: docker run -it --entrypoint sh myimage
  • Exit 139 on Apple silicon often means an amd64-only image; add --platform

Quick Summary

  • exec -it … sh — shell in a running container
  • cp src dest — files in/out (name:/path)
  • debug — toolbox for slim images
  • 125/126/127/137 — docker, not-exec, not-found, killed
