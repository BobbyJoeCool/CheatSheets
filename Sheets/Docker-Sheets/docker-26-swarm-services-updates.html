Swarm Services & Rolling Updates

docker service create / ls / ps · service scale · replicated vs global · --update-parallelism · --update-delay · service rollback · --constraint

Services and Tasks

A service is the desired state: image, replica count, ports, limits. Swarm turns it into tasks, each running one container on some node, and replaces tasks that fail. Changing a service (new image, env, limits) triggers a rolling update that replaces tasks a few at a time and can roll back automatically on failure.

Service Modes

  • replicated — run N copies anywhere (default)
  • global — exactly one per node (agents, log shippers)
  • Service name = DNS name on its overlay networks
  • service create flags mirror docker run flags

Create, Scale, Update

docker service create --name web --replicas 3 -p 8080:80 \
  --limit-memory 256M --constraint node.role==worker nginx:1.27
docker service ls                         # replicas: 3/3
docker service ps web                     # tasks + which node they're on
docker service logs -f web                # logs from all tasks
docker service scale web=6
docker service update \
  --image nginx:1.28 \
  --update-parallelism 2 --update-delay 10s \
  --update-order start-first \
  --update-failure-action rollback web
docker service rollback web               # back to previous spec

docker service create --mode global --name agent \
  --mount type=bind,src=/var/log,dst=/host/log,ro datadog/agent
docker service rm web

Code Explained

--constraint — only schedule where the expression is true
--update-parallelism 2 — replace 2 tasks at a time
--update-delay 10s — pause between batches
start-first — start new task before stopping old (no gap)
--update-failure-action rollback — undo automatically on failure
--mode global — one task per node

⚠ Common Mistakes

  • Updating with --image nginx:latest when the tag hasn't changed — Swarm sees no change; use versioned tags
  • No HEALTHCHECK — Swarm considers a task healthy as soon as it starts, so bad releases roll out fully
  • Constraints no node satisfies — tasks sit in Pending; check docker service ps --no-trunc web
  • Expecting docker ps on a manager to show all containers — it shows only that node; use service ps

✓ Tips & Best Practices

  • Always set --update-failure-action rollback plus a healthcheck for safe deploys
  • start-first gives zero-downtime updates if you have spare capacity
  • docker service ps web --filter desired-state=running hides old, shut-down tasks
  • Prefer stacks (Sheet 27) over long service create commands

Quick Summary

  • service create/scale/rm — manage services
  • service ps / logs — tasks across nodes
  • service update --image — rolling update
  • service rollback — previous version
