Stacks, Secrets & Overlay Networks

docker stack deploy -c · stack ls / ps / rm · deploy: keys · secret create · config create · overlay networks · routing mesh

Stacks

A stack deploys a whole Compose file to a swarm: each service becomes a swarm service, networks become overlay networks spanning all nodes, and secrets and configs are stored encrypted in the Raft log. The same compose.yaml format works (Sheets 21–23), but the deploy: section now matters and some build-time keys are ignored.

Compose vs Stack

  • build: is ignored — push images to a registry first
  • depends_on, container_name are ignored
  • .env is not read; export variables in your shell
  • Re-run stack deploy to apply changes

stack.yaml

services:
  web:
    image: ghcr.io/acme/web:1.4.2
    ports: ["80:8080"]
    networks: [front]
    secrets: [db_password]
    deploy:
      replicas: 3
      placement:
        constraints: [node.role == worker]
      update_config: { parallelism: 1, delay: 10s, order: start-first,
                       failure_action: rollback }
      restart_policy: { condition: on-failure, max_attempts: 3 }
      resources: { limits: { cpus: "0.5", memory: 256M } }
networks:
  front: { driver: overlay }
secrets:
  db_password: { external: true }

⚠ Common Mistakes

  • Deploying a file with build: only — no image on other nodes; build, push, then reference the tag
  • Expecting .env substitution — docker stack deploy doesn't read it; export vars or pre-render with docker compose config
  • Using a named local volume for a database with 3 replicas — each node gets its own empty volume
  • Trying to docker secret rm a secret in use — remove it from services first

✓ Tips & Best Practices

  • Version secrets and configs in their names (_v2) to rotate without downtime
  • Pin a stateful service to one node with a label constraint, or use a shared storage driver
  • Add --opt encrypted for overlay networks carrying sensitive traffic
  • Re-run stack deploy to apply changes; Swarm updates only what changed

Quick Summary

  • stack deploy -c file name — deploy/update
  • deploy: — replicas, placement, updates
  • secret create — encrypted, mounted as files
  • overlay + routing mesh — multi-node networking
