Docker Compose

Compose describes a multi-container app in one YAML file: each service becomes one or more containers, and Compose creates a shared network so services reach each other by service name. docker compose up builds, creates and starts everything; down tears it all down. The project name (default: the folder name) prefixes every container, network and volume.

Versions

  • Compose v2 is a CLI plugin: docker compose (space)
  • Legacy v1 docker-compose (hyphen) is end-of-life
  • The top-level version: key is obsolete and ignored
  • Default file names: compose.yaml, then docker-compose.yml

compose.yaml

services:
  web:
    build: .                     # build from ./Dockerfile
    ports: ["8080:3000"]
    environment:
      DATABASE_URL: postgres://app:secret@db:5432/app
    depends_on: [db]
  db:
    image: postgres:17           # use a ready-made image
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: secret
    volumes:
      - pgdata:/var/lib/postgresql/data
volumes:
  pgdata:

Everyday Commands

docker compose up -d          # create + start all
docker compose up -d --build  # rebuild first
docker compose ps             # this project's containers
docker compose logs -f web    # follow one service
docker compose stop           # stop, keep containers
docker compose start
docker compose restart web
docker compose down           # remove containers + network
docker compose down -v        # …and named volumes
docker compose pull           # newer images
docker init                   # generate starter files

⚠ Common Mistakes

  • Using localhost in DATABASE_URL — use the service name (db) from inside the network
  • docker compose down -v in a real environment — deletes the database volume
  • Editing code and running up -d — images aren't rebuilt unless you add --build (or use watch)
  • Two copies of the same folder name on one host — same project name, so they collide; set -p

✓ Tips & Best Practices

  • Quote port mappings ("8080:3000") so YAML doesn't misread values like 22:22
  • Run docker compose config to see the final merged file with variables filled in
  • docker compose up -d web starts one service plus whatever it depends on
  • docker init writes a Dockerfile, compose.yaml and .dockerignore for common languages

Quick Summary

  • compose.yaml — services, volumes, networks
  • up -d / down — start / remove the stack
  • logs -f / ps — watch the stack
  • service name = DNS name
