Volumes & Bind Mounts

volume create / ls / rm · -v vs --mount · named vs anonymous · bind mounts · :ro · tmpfs · volume backup pattern

Keeping Data

A container's writable layer disappears with docker rm, so anything worth keeping goes in a mount. Volumes are storage managed by Docker (under /var/lib/docker/volumes) and are the right choice for databases and app data. Bind mounts map a host path into the container, ideal for live-editing source code. tmpfs mounts live in memory only.

Which One?

  • Named volume — databases, uploads, anything persistent
  • Bind mount — dev source code, config files from the host
  • tmpfs — secrets or scratch files that must never hit disk
  • Anonymous volume — from VOLUME / -v /path; easy to lose

Mounting

docker volume create pgdata
docker run -d --name db -v pgdata:/var/lib/postgresql/data postgres:17
docker run -d --name db \
  --mount type=volume,src=pgdata,dst=/var/lib/postgresql/data postgres:17

docker run --rm -v "$PWD":/app -w /app node:22 npm test      # bind mount
docker run --rm -v "$PWD/nginx.conf":/etc/nginx/nginx.conf:ro nginx
docker run --rm --mount type=bind,src="$PWD",dst=/app,readonly alpine ls /app
docker run --rm --tmpfs /scratch:size=100m alpine df -h /scratch

docker volume ls                       # all volumes
docker volume inspect pgdata           # Mountpoint, driver, labels
docker volume rm pgdata
docker volume prune -a                 # remove ALL unused volumes
docker rm -v web                       # + its anonymous volumes

-v vs --mount

-v src:dst[:opts] — short; if src has no /, it's a volume name
--mount type=…,src=…,dst=… — explicit; preferred in scripts
-v creates a missing host path as a folder; --mount errors instead
:ro / readonly — mount read-only
An empty volume is pre-filled from the image's files at that path; a bind mount hides them

Backup and Restore a Volume

docker run --rm -v pgdata:/data -v "$PWD":/backup alpine \
  tar czf /backup/pgdata.tgz -C /data .
docker run --rm -v pgdata:/data -v "$PWD":/backup alpine \
  tar xzf /backup/pgdata.tgz -C /data

Mount Options

⚠ Common Mistakes

  • docker volume prune -a thinking it's safe — it deletes every volume no container uses right now
  • Bind-mounting over the app folder and losing node_modules from the image — add a volume for that subfolder
  • Mixing up -v data:/x (volume) and -v ./data:/x (bind) — a leading ./ or / makes it a host path
  • Permission denied on bind mounts — the container UID doesn't own the host files; match UIDs or use --user

✓ Tips & Best Practices

  • Name volumes explicitly; anonymous ones get random IDs and are easy to delete by accident
  • Back up volumes with a throwaway container + tar, as shown above
  • Use :ro for config files so a compromised app can't rewrite them
  • On macOS/Windows Desktop, named volumes are much faster than bind mounts for heavy I/O

Quick Summary

  • -v name:/path — named volume
  • -v $PWD:/path — bind mount
  • --tmpfs /path — RAM only
  • volume ls/inspect/rm/prune — manage
