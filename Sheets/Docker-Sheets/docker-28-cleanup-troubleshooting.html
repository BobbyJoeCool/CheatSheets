Keeping Docker Healthy

Docker never deletes images, stopped containers, volumes or build cache on its own, so disks fill up over time. docker system df shows where the space went and the prune commands reclaim it. Most other problems come down to a handful of error messages, listed below with their usual fixes.

What prune Removes

  • container prune — stopped containers
  • image prune — dangling images (-a: all unused)
  • volume prune — unused anonymous volumes (-a: named too)
  • builder prune — build cache

Reclaiming Space

docker system df                      # images, containers, volumes, cache
docker system df -v                   # per-object detail
docker system prune                   # stopped containers, dangling images,
                                      # unused networks, dangling build cache
docker system prune -a                # + all images not used by a container
docker system prune -a --volumes      # + unused volumes (data loss!)
docker image prune -a --filter "until=168h"   # unused and older than 7 days
docker builder prune --filter until=72h       # cache older than 3 days

# Where the space lives
sudo du -sh /var/lib/docker/*         # Linux Engine

Notes

-f skips the confirmation prompt (careful in scripts)
--filter until= and label= work on most prune commands
Desktop: the VM disk doesn't shrink automatically; prune, then check Settings
Rotate logs: --log-driver local or --log-opt max-size=10m

Common Errors

MessageCause → fix
port is already allocatedSomething uses the host port → change -p or stop it (lsof -i :8080)
permission denied …docker.sockUser not in docker group → usermod -aG docker $USER, re-login
Cannot connect to the Docker daemonDaemon/Desktop not running or wrong context/DOCKER_HOST
no space left on deviceDisk full → system df, prune, raise Desktop disk limit
exec format errorWrong CPU architecture → --platform or multi-arch build
pull access denied / not foundTypo, private repo or not logged in → docker login
toomanyrequestsDocker Hub rate limit → log in or use a mirror
OCI runtime create failedBad entrypoint/mount path → read the full message

⚠ Common Mistakes

  • docker system prune -a --volumes on a server — deletes database volumes not attached to a running container
  • Fixing socket errors with sudo chmod 666 /var/run/docker.sock — gives every user root access
  • Leaving json-file unrotated — a chatty container can fill the disk
  • Restarting Docker to clear an error without reading it — the message usually names the exact cause

✓ Tips & Best Practices

  • Schedule docker image prune -a --filter until=168h -f on CI runners
  • Set default log rotation in daemon.json for every container (Sheet 03)
  • docker events + docker logs + docker inspect answer most "why did it stop?" questions
  • journalctl -u docker shows daemon errors on Linux; docker desktop logs on Desktop

Quick Summary

  • system df — see usage
  • system prune [-a] [--volumes] — reclaim
  • builder prune — clear build cache
  • --log-opt max-size — rotate logs
