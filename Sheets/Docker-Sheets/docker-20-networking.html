Networking

-p host:container · network create · bridge / host / none · user-defined bridge DNS · --network · network connect · overlay / macvlan

How Containers Talk

Each container gets its own network stack. On the default bridge network, containers can reach each other only by IP. Create your own user-defined bridge and containers on it find each other by name through Docker's built-in DNS. To reach a container from outside the host, publish a port with -p.

Notes

  • -p 8080:80 = host port 8080 → container port 80
  • Containers on the same network use the container port, not the published one
  • Published ports bypass ufw-style firewalls on Linux; bind to 127.0.0.1 to keep them private

Networks in Practice

docker network create appnet                    # user-defined bridge
docker run -d --name db  --network appnet -e POSTGRES_PASSWORD=dev postgres:17
docker run -d --name api --network appnet -p 8080:3000 \
  -e DATABASE_URL=postgres://postgres:dev@db:5432/postgres myapi
docker exec api ping -c1 db                     # name resolves via DNS

docker network connect frontend api             # attach a 2nd network
docker network disconnect frontend api
docker run -d --network-alias search --network appnet elasticsearch:8.15

docker network ls
docker network inspect appnet -f '{{range .Containers}}{{.Name}} {{end}}'
docker network rm appnet
docker network prune                            # unused networks

Code Explained

db resolves to the db container's IP for anything on appnet
API listens on 3000 inside; reachable at localhost:8080 from the host
A container can join several networks (e.g. frontend + backend)
--network-alias adds an extra DNS name; several containers can share one

⚠ Common Mistakes

  • Using localhost to reach another container — that's the container itself; use the other container's name
  • Relying on the default bridge network for names — DNS only works on user-defined networks
  • Connecting to db:5433 because you published -p 5433:5432 — inside the network it's still 5432
  • Publishing database ports on 0.0.0.0 on a public server — bind to 127.0.0.1 or don't publish

✓ Tips & Best Practices

  • Create one network per app (Compose does this for you)
  • Use docker run --rm --network appnet nicolaka/netshoot for dig, curl, tcpdump
  • --network container:api shares another container's network stack (sidecars, debugging)
  • host networking works fully on Linux; on Desktop it is limited

Quick Summary

  • -p host:container — publish a port
  • network create — user-defined bridge with DNS
  • --network name — join at start
  • network connect — join later
