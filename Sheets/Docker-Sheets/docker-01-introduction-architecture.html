What Docker Is

Docker packages an app with everything it needs (runtime, libraries, config) into an image, then runs that image as an isolated container. Containers share the host's Linux kernel, so they start in milliseconds and use far less memory than virtual machines. The same image runs the same way on a laptop, a CI runner and a production server.

Key Terms

  • Image — read-only template built from layers (the class)
  • Container — a running (or stopped) instance of an image (the object)
  • Registry — server that stores images, e.g. Docker Hub, ghcr.io
  • Dockerfile — recipe that builds an image, one layer per step

Hello, Docker

docker run hello-world              # pull a test image, run it, print a message
docker run --rm -it alpine sh       # throwaway shell in a 5 MB Alpine container
docker run -d -p 8080:80 nginx      # web server at http://localhost:8080

docker ps                           # running containers
docker ps -a                        # include stopped ones
docker images                       # images stored locally
docker stop <container>             # SIGTERM, then SIGKILL after 10 s
docker rm <container>               # delete a stopped container

docker version                      # client + server (engine) versions
docker info                         # storage driver, cgroups, # of containers

What Happens on docker run

docker CLI sends a REST call to the daemon over /var/run/docker.sock
dockerd looks for the image locally, pulls it from the registry if missing
dockerd hands the container to containerd, which manages its lifecycle
runc creates namespaces + cgroups and starts the process
A thin writable layer is added on top of the read-only image layers

⚠ Common Mistakes

  • Treating containers like VMs — run one main process per container, not SSH + cron + app
  • Expecting data to survive docker rm — the writable layer is deleted; use volumes (Sheet 19)
  • Running a Windows or macOS app in a Linux image — containers share the host kernel type
  • Confusing image and container — docker rmi removes images, docker rm removes containers

✓ Tips & Best Practices

  • Add --rm to one-off docker run commands so stopped containers don't pile up
  • Use small official images (alpine, -slim) to keep pulls fast
  • Run docker info first when something is off — it shows the storage driver, context and errors
  • Docker Desktop runs Linux containers inside a small VM on macOS and Windows

Quick Summary

  • image — read-only, layered template
  • container — image + writable layer + process
  • dockerd → containerd → runc — the run path
  • registry — where images are pushed and pulled
