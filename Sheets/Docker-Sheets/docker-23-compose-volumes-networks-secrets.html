Sheet 23

Compose Volumes, Networks & Secrets

top-level volumes / networks · external: true · secrets · configs · .env interpolation · ${VAR:-default} · profiles

Shared Resources

Top-level volumes:, networks:, secrets: and configs: declare resources once; services then reference them by name. Compose creates them with the project prefix unless marked external: true. Variables like ${TAG} are filled in from your shell or a .env file next to compose.yaml before anything runs, and profiles let optional services stay off by default.

Notes

  • Secrets mount as files at /run/secrets/<name>
  • .env feeds interpolation; env_file feeds containers
  • Services with no profiles always start

compose.yaml

services:
  api:
    image: acme/api:${TAG:-latest}
    networks: [backend, frontend]
    volumes: [uploads:/app/uploads, ./config:/app/config:ro]
    secrets: [db_password]
    environment:
      DB_PASSWORD_FILE: /run/secrets/db_password
  db:
    image: postgres:17
    networks: [backend]
    volumes: [pgdata:/var/lib/postgresql/data]
  adminer: { image: adminer, profiles: [debug], ports: ["8081:8080"] }
volumes:
  pgdata:
  uploads: { external: true }       # Compose won't create/delete
networks:
  backend: { internal: true }       # no outside access
  frontend:
secrets:
  db_password: { file: ./secrets/db_password.txt }

.env (interpolation)

TAG=1.4.2
COMPOSE_PROJECT_NAME=shop
COMPOSE_PROFILES=debug

Notes

profiles: [debug] — start with --profile debug
*_FILE env vars: many official images read secrets this way

Interpolation Syntax

SyntaxResult
${VAR}Value, or empty + warning
${VAR:-default}Default if unset or empty
${VAR:?error msg}Fail if unset or empty
$$Literal $

Profiles & Externals

CommandDoes
docker compose --profile debug upInclude debug services
COMPOSE_PROFILES=a,bSame via env / .env
docker compose up adminerNaming a service enables it
docker volume create uploadsCreate an external volume

⚠ Common Mistakes

  • Expecting .env values inside containers — they're only for ${…} substitution unless you also use env_file
  • Committing secrets/*.txt or .env to git — add them to .gitignore
  • docker compose down -v with external volumes — those survive, but project volumes are deleted
  • Writing $PATH-style shell vars in command: — Compose substitutes them; escape as $$PATH

✓ Tips & Best Practices

  • Use ${VAR:?set VAR first} for values that must be provided
  • Put debug tools (adminer, mailhog) behind a profile
  • Mark backend networks internal: true so databases have no internet access
  • docker compose config shows the file after interpolation — great for debugging

Quick Summary

  • volumes / networks — declared once, shared
  • secrets — files at /run/secrets/…
  • ${VAR:-default} — fill from shell or .env
  • profiles — optional services
