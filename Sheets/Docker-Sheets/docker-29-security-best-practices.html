Security & Best Practices

non-root USER · --cap-drop ALL · --security-opt no-new-privileges · secrets not ENV · pin by digest · docker scout cves · SBOM · minimal base images

Defense in Depth

Containers share the host kernel, so a container running as root with extra privileges is only a short step from root on the host. Good practice layers several controls: small trusted base images, non-root users, dropped capabilities, read-only filesystems, secrets kept out of images, and regular vulnerability scans.

Never Do

  • --privileged for normal apps (full host device access)
  • Mount /var/run/docker.sock into untrusted containers
  • Bake passwords into ENV, ARG or COPY'd files
  • Run unpinned latest images in production

A Locked-Down Run

docker run -d --name api \
  --user 10001:10001 \
  --read-only --tmpfs /tmp \
  --cap-drop ALL --cap-add NET_BIND_SERVICE \
  --security-opt no-new-privileges \
  --memory 512m --cpus 1 --pids-limit 100 \
  -p 127.0.0.1:8080:8080 \
  ghcr.io/acme/api:1.4.2@sha256:<digest>

docker scout quickview ghcr.io/acme/api:1.4.2     # summary of CVEs
docker scout cves --only-severity critical,high ghcr.io/acme/api:1.4.2
docker scout recommendations ghcr.io/acme/api:1.4.2   # better base images
docker buildx build --sbom=true --provenance=mode=max \
  -t ghcr.io/acme/api:1.4.2 --push .

Code Explained

--user — non-root UID (also set USER in the Dockerfile)
--cap-drop ALL then add back only what's needed
no-new-privileges — blocks setuid binaries from gaining root
@sha256: — run exactly the image you scanned
--sbom / --provenance — attach a package list and build record to the image

⚠ Common Mistakes

  • Adding --privileged to "fix" a permission error — find the one capability or device actually needed
  • Scanning once and never again — new CVEs appear daily; scan on every build and on a schedule
  • Deleting a secret in a later layer (RUN rm .env) — it still exists in the earlier layer
  • Trusting any image on Docker Hub — prefer Docker Official Images and Verified Publishers

✓ Tips & Best Practices

  • Add --exit-code to docker scout cves in CI to fail builds with critical CVEs
  • Rebuild images weekly with --pull even when your code hasn't changed
  • Use read-only bind mounts (:ro) for config files
  • Run Docker Bench for Security or similar checks against hosts

Quick Summary

  • USER / --user — never root
  • --cap-drop ALL + no-new-privileges
  • @sha256: — pin what you scanned
  • docker scout cves — find and fix vulnerabilities
