Service Keys

Almost every docker run flag has a matching key under a service. The most useful extra is depends_on with conditions: combined with a healthcheck, Compose waits until a dependency is actually ready (not just started) before starting the services that need it.

A Fully Configured Service

services:
  api:
    build: ./api
    image: acme/api:dev
    ports: ["127.0.0.1:8080:3000"]
    env_file: [.env, .env.local]
    environment:
      NODE_ENV: development
      LOG_LEVEL: ${LOG_LEVEL:-info}
    command: ["npm", "run", "dev"]
    restart: unless-stopped
    init: true
    depends_on:
      db: { condition: service_healthy }
      migrate: { condition: service_completed_successfully }
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:3000/health"]
      interval: 10s
      retries: 5
      start_period: 15s
    deploy:
      resources: { limits: { cpus: "1.5", memory: 512M } }
  db:
    image: postgres:17
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s

Code Explained

127.0.0.1: — publish on localhost only
${LOG_LEVEL:-info} — from shell/.env, default info
service_healthy — wait for db's healthcheck to pass
service_completed_successfully — wait for a one-shot job (migrations) to exit 0
service_started — the default: just started
CMD runs exec form; CMD-SHELL runs through sh -c
init: true — same as --init
limits — same as --cpus / --memory; environment beats env_file

⚠ Common Mistakes

  • Plain depends_on: [db] — only waits for the container to start, not for Postgres to accept connections
  • healthcheck using curl in an image without it — service never becomes healthy
  • Setting container_name — prevents scaling and clashes across projects
  • Unquoted cpus: 1.5 or "8080:80" mistakes — quote numbers-with-colons and decimals

✓ Tips & Best Practices

  • Pair every depends_on you care about with a healthcheck on the dependency
  • Run migrations as a one-shot service and gate the app on service_completed_successfully
  • Use restart: unless-stopped for anything that should come back after a reboot
  • Short env syntax - LOG_LEVEL passes the value straight from your shell

Quick Summary

  • ports / environment / env_file — basics
  • depends_on.condition — real startup order
  • healthcheck — readiness probe
  • deploy.resources.limits — CPU/memory caps
