Java Plugin & Source Sets

java / java-library plugins · sourceSets · main / test · resources · compileJava · JavaCompile options · -Xlint

Building Java Code

The java plugin adds the compile → process resources → test → jar pipeline and the source set model. A source set is a group of source files with its own classpath and tasks: main and test exist by default, and you can add more. Use java-library instead of java for anything other projects depend on; it adds the api configuration.

Notes

  • Each source set gets tasks like compile<Name>Java and configurations like <name>Implementation
  • Prefer a toolchain (sheet 14) over sourceCompatibility
  • For extra test types, prefer jvm-test-suite (sheet 16)

Configuring Java Compilation

plugins { `java-library` }

java { withSourcesJar(); withJavadocJar() }   // extra JARs to publish
sourceSets {
    main { java.srcDir("src/generated/java") }   // extra source dir
    create("tools") {                            // a new source set
        compileClasspath += sourceSets.main.get().output
        runtimeClasspath += sourceSets.main.get().output
    }
}
tasks.withType<JavaCompile>().configureEach {
    options.encoding = "UTF-8"
    options.compilerArgs.addAll(listOf("-Xlint:all", "-Werror", "-parameters"))
}

Code Explained

withSourcesJar() — publish a -sources.jar with the library
java.srcDir(...) — add a folder, keep the default one
create("tools") — adds src/tools/java and its tasks
+= main.output — let the new set see main's classes
-Xlint:all -Werror — every warning fails the build
-parameters — keep parameter names (Spring, Jackson)

In Groovy DSL

`java-library` → id 'java-library'
create("tools") { } → tools { }; drop .get(): sourceSets.main.output
listOf("-Xlint:all", …) → ['-Xlint:all', …]

Java vs Kotlin Projects

Kotlin — kotlin.srcDir(…); default src/main/kotlin, tools gets src/tools/kotlin
Kotlin — compilerOptions { allWarningsAsErrors = true; javaParameters = true }
Kotlin — javadoc ignores Kotlin code; use Dokka for the docs JAR

⚠ Common Mistakes

  • Replacing a source dir with setSrcDirs when you meant to add one — the default src/main/java disappears
  • Setting sourceCompatibility but compiling with a newer JDK — you can still call APIs that don't exist on the target
  • Using java for a shared library — consumers then see every implementation dependency as missing at compile time

✓ Tips & Best Practices

  • Use options.release (or a toolchain) to truly target an older Java
  • Generated sources: register the generator task and pass it to srcDir(task)
  • Keep custom source sets rare; most needs fit main, test or a test suite

Quick Summary

  • java-library — Java plugin + api
  • sourceSets — groups of sources with own tasks
  • withSourcesJar() — publish sources
