Toolchains

A toolchain tells Gradle which JDK to compile, test and run with, independent of the JDK that runs Gradle itself. Gradle finds a matching JDK on the machine or, with the foojay resolver plugin, downloads one. This keeps builds reproducible: every developer and CI agent compiles with Java 21 even if their default java is 17 or 25.

Notes

  • Gradle 9 needs JVM 17+ to run; toolchains can target Java 8
  • Toolchain JDKs are cached in ~/.gradle/jdks
  • Gradle 9.8 supports Java 27 for toolchains and the daemon
  • The daemon JVM can also be pinned (see commands)

Pinning a JDK

// settings.gradle.kts — lets Gradle download missing JDKs
plugins {
    id("org.gradle.toolchains.foojay-resolver-convention") version "1.0.0"
}
// build.gradle.kts
java {
    toolchain {
        languageVersion = JavaLanguageVersion.of(21)
        vendor = JvmVendorSpec.ADOPTIUM          // optional
    }
}
tasks.register<JavaExec>("runOnJava25") {        // one task on another JDK
    javaLauncher = javaToolchains.launcherFor {
        languageVersion = JavaLanguageVersion.of(25)
    }
    mainClass = "com.example.App"
    classpath = sourceSets.main.get().runtimeClasspath
}

Code Explained

foojay-resolver-convention — auto-downloads JDKs from foojay.io
languageVersion — the Java version all JVM tasks use
vendor — limit to one distribution (Adoptium, Azul…)
javaToolchains.launcherFor — a JVM for one specific task
compilerFor / javadocToolFor — the same for other tools

In Groovy DSL

settings.gradle: id '…foojay-resolver-convention' version '1.0.0'
register<JavaExec>("x") → register('x', JavaExec)
sourceSets.main.get().runtimeClasspath → sourceSets.main.runtimeClasspath

Java vs Kotlin Projects

Java — java { toolchain { languageVersion = … } }
Kotlin — kotlin { jvmToolchain(21) } sets it for Kotlin and Java tasks
Kotlin — jvmTarget follows the toolchain unless you set it

Commands

CommandDoes
./gradlew javaToolchainsList JDKs Gradle detected
./gradlew updateDaemonJvm --jvm-version=21Pin the JVM that runs Gradle

gradle.properties Switches

PropertyEffect
org.gradle.java.installations.auto-download=falseNever download JDKs
org.gradle.java.installations.auto-detect=falseIgnore JDKs found on the system
org.gradle.java.installations.paths=/opt/jdk-21Extra JDK locations

⚠ Common Mistakes

  • Setting sourceCompatibility = 21 and also a toolchain — redundant; the toolchain already sets the release
  • Forgetting the foojay plugin on fresh CI agents — the build fails with "no matching toolchain"
  • Using updateDaemonJvm but not committing gradle/gradle-daemon-jvm.properties

✓ Tips & Best Practices

  • Pin the toolchain in a convention plugin so all subprojects match
  • Test on several JDKs by registering extra Test tasks with javaLauncher
  • In CI, cache ~/.gradle/jdks alongside the dependency cache

Quick Summary

  • java { toolchain { } } — choose the build JDK
  • foojay resolver — auto-download JDKs
  • launcherFor { } — per-task JVM
  • updateDaemonJvm — pin Gradle's own JVM
