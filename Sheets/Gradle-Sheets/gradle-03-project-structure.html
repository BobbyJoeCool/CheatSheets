Sheet 03

Project Structure & gradle init

gradle init · settings.gradle.kts · build.gradle.kts · gradle.properties · libs.versions.toml · src/main · src/test · build/

Anatomy of a Build

A Gradle build has one settings file at the root that names the build and lists its subprojects, plus one build script per project. Shared flags go in gradle.properties and dependency versions in the version catalog gradle/libs.versions.toml. gradle init scaffolds all of this, including the wrapper, using the Maven-style src/main / src/test layout.

Notes

  • gradle init in a folder with a pom.xml offers to convert the Maven build
  • Generated apps put code in an app/ subproject, not the root
  • .gradle/ and every build/ folder are generated: add them to .gitignore
  • buildSrc/ or build-logic/ holds shared build logic (sheet 18)

Typical Layout

my-app/
├── settings.gradle.kts       # build name + included subprojects
├── gradle.properties         # Gradle flags (jvmargs, caching…)
├── gradlew  gradlew.bat      # wrapper scripts (commit)
├── gradle/
│   ├── wrapper/              # wrapper jar + properties (commit)
│   └── libs.versions.toml    # version catalog
├── app/
│   ├── build.gradle.kts      # this subproject's build script
│   └── src/
│       ├── main/java/        # production code
│       ├── main/resources/   # config files, templates
│       ├── test/java/        # tests
│       └── test/resources/
├── .gradle/                  # local caches (ignore)
└── app/build/                # outputs: classes, jars, reports

Key Files

settings.gradle.kts — rootProject.name = "my-app" and include("app")
build.gradle.kts — plugins, dependencies and task config for one project
gradle.properties — org.gradle.caching=true and other switches
libs.versions.toml — one place for every dependency version
build/libs/ — where ./gradlew jar puts the JAR

⚠ Common Mistakes

  • Running gradle init where a build already exists — it stops (or offers to convert a pom.xml); start in an empty folder
  • Committing build/ or .gradle/ — huge diffs and stale outputs on other machines
  • Forgetting to include() a new subproject in settings — Gradle silently ignores its folder

✓ Tips & Best Practices

  • Script it: gradle init --type java-application --dsl kotlin --use-defaults
  • Keep rootProject.name explicit; otherwise it is the folder name, which varies on CI
  • Use ./gradlew projects to print the project tree Gradle sees

Quick Summary

  • settings.gradle.kts — which projects are in the build
  • build.gradle.kts — how one project is built
  • gradle/libs.versions.toml — dependency versions
  • gradle init — scaffold a new build
