Repositories

mavenCentral() · google() · maven { url } · mavenLocal() · credentials · dependencyResolutionManagement · content filtering

Where Dependencies Come From

A repository is a server or folder Gradle downloads modules from, checked in the order you declare them. Declare repositories once in settings.gradle.kts under dependencyResolutionManagement so every project uses the same list. Use content filtering so each group is looked up only where it lives: faster builds and less risk of dependency-confusion attacks.

Notes

  • jcenter() was removed in Gradle 9; use mavenCentral()
  • Downloads are cached in ~/.gradle/caches/modules-2
  • Plugin repositories are separate: pluginManagement { repositories { } }
  • --offline uses only the cache; --refresh-dependencies re-checks remotes

Central Repository Setup

// settings.gradle.kts
dependencyResolutionManagement {
    repositoriesMode.set(RepositoriesMode.FAIL_ON_PROJECT_REPOS)
    repositories {
        mavenCentral()
        google()                                 // Android / AndroidX
        maven("https://repo.example.com/releases") {
            name = "company"           // → companyUsername / companyPassword
            credentials(PasswordCredentials::class)
            content { includeGroupByRegex("com\\.example.*") }
        }
        mavenLocal { content { includeGroup("com.example.dev") } }
    }
}

Code Explained

dependencyResolutionManagement — repositories for every project
FAIL_ON_PROJECT_REPOS — error if a project declares its own
maven(url) — any Maven-layout repository (Nexus, Artifactory)
credentials(PasswordCredentials::class) — read from <name>Username / <name>Password properties
content { } — only look up matching groups here

In Groovy DSL

settings.gradle — same blocks
maven("url") { … } → maven { url = '…'; name = 'company' }
credentials(PasswordCredentials::class) → credentials(PasswordCredentials)

Java vs Kotlin Projects

Repositories are the same for Java and Kotlin projects
Kotlin — stdlib and kotlinx libraries resolve from mavenCentral()
Android / Kotlin Multiplatform builds also need google()

repositoriesMode

⚠ Common Mistakes

  • Putting mavenLocal() first — stale local builds shadow real releases and builds differ per machine
  • Committing repository passwords in build files — use ~/.gradle/gradle.properties or env vars
  • Declaring repos in every subproject — they drift apart; centralize them in settings

✓ Tips & Best Practices

  • Pass secrets in CI as ORG_GRADLE_PROJECT_companyPassword
  • Use exclusiveContent { } to force a group to come from one repo only
  • Order repos by how often they hit: Central first, private last

Quick Summary

  • dependencyResolutionManagement — one repo list for all
  • mavenCentral() — the standard source
  • maven(url) { credentials(…) } — private repos
  • content { includeGroup } — scope lookups
