Convention Plugins (build-logic)

buildSrc · build-logic included build · kotlin-dsl plugin · precompiled script plugins · java-conventions.gradle.kts · sharing config

Sharing Build Logic

A convention plugin is a build script turned into a plugin: shared setup (toolchain, test config, linting) lives in one file, and each project opts in with plugins { id("java-conventions") }. Put them in a build-logic included build (or the older buildSrc). The file name of a precompiled script plugin becomes its id.

Notes

  • kotlin-dsl plugin compiles src/main/kotlin/*.gradle.kts into plugins
  • Changing buildSrc invalidates the whole build; build-logic less so
  • libs accessors are not generated inside precompiled plugins
  • Read the catalog there with the<VersionCatalogsExtension>()

A build-logic Setup

// settings.gradle.kts (root)
pluginManagement { includeBuild("build-logic") }

// build-logic/build.gradle.kts
plugins { `kotlin-dsl` }
repositories { gradlePluginPortal() }

// build-logic/src/main/kotlin/java-conventions.gradle.kts
plugins { `java-library` }
val libs = the<VersionCatalogsExtension>().named("libs")
java { toolchain { languageVersion = JavaLanguageVersion.of(21) } }
dependencies {
    testImplementation(libs.findLibrary("junit-jupiter").get())
}
tasks.withType<Test>().configureEach { useJUnitPlatform() }

// core/build.gradle.kts
plugins { id("java-conventions") }

Code Explained

includeBuild("build-logic") — plugins from this build are usable
kotlin-dsl — turns .gradle.kts files into plugins
java-conventions.gradle.kts — id is java-conventions
the<VersionCatalogsExtension>() — untyped catalog lookup
plugins { id(…) } — a project opts in, no version needed

In Groovy DSL

`kotlin-dsl` → id 'groovy-gradle-plugin'
Script: src/main/groovy/java-conventions.gradle
Catalog: versionCatalogs.named('libs').findLibrary('junit-jupiter').get()

Java vs Kotlin Projects

kotlin-dsl is for the build logic — the projects can be Java or Kotlin
Kotlin conventions — add org.jetbrains.kotlin:kotlin-gradle-plugin to build-logic dependencies
…then plugins { kotlin("jvm") } with no version in the script

⚠ Common Mistakes

  • Using libs.junit.jupiter inside a precompiled plugin — the accessor doesn't exist there; use findLibrary
  • Giving the plugin a version in plugins { } — local convention plugins are versionless
  • Forgetting repositories { } in build-logic — external plugins it applies can't be resolved

✓ Tips & Best Practices

  • Make one plugin per role: java-conventions, library-conventions, app-conventions
  • Share the root catalog with build-logic from its own settings file (sheet 11)
  • Layer plugins: library-conventions applies java-conventions

Quick Summary

  • build-logic — an included build for plugins
  • kotlin-dsl — precompiled script plugins
  • File name — becomes the plugin id
  • plugins { id("x-conventions") } — opt in
