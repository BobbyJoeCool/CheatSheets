Properties & Providers

Property<T> · Provider · .set() / .get() · providers.gradleProperty · -Pname=value · extra · environment variables · lazy wiring

Lazy Configuration

Modern Gradle APIs use lazy properties: a Provider<T> is a value that is computed later, and a Property<T> is a provider you can set(). Wiring providers together (map, flatMap, orElse) lets Gradle read values only at execution time and track which task produced them. Read build settings with providers.gradleProperty(…) and providers.environmentVariable(…) instead of System.getenv.

Where Values Come From

  • -Pname=value on the command line (highest priority)
  • ~/.gradle/gradle.properties (user-wide, keep secrets here)
  • gradle.properties in the project root
  • ORG_GRADLE_PROJECT_name environment variable
  • -Dname=value — JVM system property, not a project property

Reading and Wiring Values

// gradle.properties →  appEnv=dev
val appEnv = providers.gradleProperty("appEnv").orElse("dev")
val apiKey = providers.environmentVariable("API_KEY")
val gitSha = providers.exec { commandLine("git", "rev-parse", "HEAD") }
    .standardOutput.asText.map { it.take(7) }

tasks.register("showEnv") {
    val env = appEnv; val sha = gitSha   // capture providers, not project
    doLast { println("env=${env.get()} sha=${sha.get()}") }
}
tasks.named<Jar>("jar") {
    archiveBaseName.set("my-app")        // Property<String>.set()
    archiveVersion = appEnv.map { "1.0-$it" }  // lazy assignment
}
// ./gradlew showEnv -PappEnv=prod  →  env=prod sha=3f2a9c1

Code Explained

providers.gradleProperty — reads -P / gradle.properties lazily
.orElse("dev") — fallback when the property is missing
providers.exec — runs a command; replaces the removed project.exec
.map { } — transform without reading the value yet
.get() — read the value; only inside task actions

In Groovy DSL

val x = providers… → def x = providers…
named<Jar>("jar") → named('jar', Jar)
"${env.get()}" and archiveVersion = … work the same

Java vs Kotlin Projects

⚠ Common Mistakes

  • Calling .get() at configuration time — forces the value early, may run a command on every build and defeats lazy wiring
  • Putting secrets in the project's gradle.properties — it gets committed; use ~/.gradle/gradle.properties or env vars
  • Confusing -D with -P — -D sets a JVM system property, which gradleProperty() will not see

✓ Tips & Best Practices

  • Prefix with systemProp. in gradle.properties to set a system property
  • In CI, pass secrets as ORG_GRADLE_PROJECT_name env vars
  • Expose settings as Property fields on an extension for typed, lazy config

Quick Summary

  • Provider<T> — read-only lazy value
  • Property<T> — settable lazy value
  • providers.gradleProperty("x") — read -Px
  • .map { } — transform without resolving
