Sheet 02

Installing Gradle & the Wrapper

gradlew / gradlew.bat · gradle-wrapper.properties · gradle wrapper --gradle-version · distributionUrl · SDKMAN / Homebrew · Java 17+

The Wrapper

The Gradle Wrapper (gradlew, gradlew.bat and the gradle/wrapper/ folder) pins the exact Gradle version a project uses and downloads it on first run. Everyone, including CI, builds with the same version without installing Gradle. You only need a local Gradle install to create a wrapper for a brand-new project; after that, always run ./gradlew.

Requirements

  • A JDK 17+ on PATH or in JAVA_HOME to run Gradle 9
  • Commit all four wrapper files to version control
  • Distributions are cached in ~/.gradle/wrapper/dists
  • -bin = runtime only; -all adds sources and docs for IDE help

Install & Manage the Wrapper

java -version                       # must report 17 or newer
# Install Gradle once (only needed to create new wrappers)
sdk install gradle 9.8.0            # SDKMAN (macOS / Linux)
brew install gradle                 # Homebrew
gradle --version                    # Gradle 9.8.0, JVM …
# Create or upgrade the wrapper in a project
gradle wrapper --gradle-version 9.8.0
./gradlew wrapper --gradle-version latest
./gradlew wrapper --distribution-type all
# Build through the wrapper from now on
./gradlew build                     # macOS / Linux
gradlew.bat build                   # Windows (cmd / PowerShell)
chmod +x gradlew                    # fix "permission denied"

Code Explained

sdk / brew / choco — package managers for a local install
gradle wrapper — writes gradlew, gradlew.bat and gradle/wrapper/*
--gradle-version latest — resolves the newest stable release
--distribution-type all — downloads the larger -all ZIP
Run wrapper twice when upgrading: the second run updates the scripts with the new version

⚠ Common Mistakes

  • Not committing gradle-wrapper.jar (a *.jar ignore rule hides it) — fresh clones can't build
  • Editing distributionUrl by hand — re-run ./gradlew wrapper so the scripts update too
  • Running on Java 11 — Gradle 9 refuses to start; point JAVA_HOME at a 17+ JDK

✓ Tips & Best Practices

  • Use --gradle-distribution-sha256-sum when upgrading so the checksum is written for you
  • Add gradle-wrapper.jar validation to CI with gradle/actions/wrapper-validation

Quick Summary

  • ./gradlew — always build through the wrapper
  • gradle wrapper --gradle-version X — pin or upgrade the version
  • gradle-wrapper.properties — source of truth for the version
  • JDK 17+ — needed to run Gradle 9
