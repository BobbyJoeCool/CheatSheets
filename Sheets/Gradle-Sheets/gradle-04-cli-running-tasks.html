Running Tasks

You run a build by naming one or more tasks; Gradle adds their dependencies and runs each task once, in graph order. Task names can be abbreviated by camelCase (cTJ for compileTestJava) and qualified with a project path (:app:test). Run without a path, a task runs in the current project and every subproject that has it.

Task Outcomes

  • UP-TO-DATE — inputs and outputs unchanged, skipped
  • FROM-CACHE — outputs restored from the build cache
  • NO-SOURCE — no input files, nothing to do
  • SKIPPED — excluded with -x or onlyIf false
  • No label — the task actually executed

Everyday Commands

./gradlew build                 # compile, test, jar — the works
./gradlew tasks                 # tasks in named groups
./gradlew tasks --all           # every task, including ungrouped
./gradlew help --task test      # details and options for one task
./gradlew build -x test         # exclude a task
./gradlew test --continue       # keep going after a failure
./gradlew build --dry-run       # list what would run (-m)
./gradlew :app:run              # task in one subproject
./gradlew test --tests '*UserTest'   # task option
./gradlew test --rerun         # force just this task to run
./gradlew build --rerun-tasks   # ignore up-to-date for all tasks

Notes

Task names are case-sensitive; abbreviations must be unambiguous
Options after a task name (--tests) belong to that task
-x test also skips tasks only test needed
:app:run is an absolute path; app:run is relative to the current dir
--rerun (one task) is much cheaper than --rerun-tasks (everything)

⚠ Common Mistakes

  • Expecting ./gradlew test to run only the root project — it runs test in every subproject; use :test for root only
  • Using clean build out of habit — clean throws away incremental work and makes every build a full rebuild
  • Using the removed -b build.gradle.kts option — Gradle 9 dropped -b/-c; use -p <dir>

✓ Tips & Best Practices

  • ./gradlew help --task <name> lists a task's type, path and options
  • Combine --dry-run with a task list to check ordering before a slow build
  • Use --continue in CI to collect every failing test module in one run

Quick Summary

  • ./gradlew <task> — run a task plus its dependencies
  • -x <task> — exclude a task
  • :project:task — target one project
  • tasks --all — discover what exists
