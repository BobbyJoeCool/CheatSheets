Sheet 05

Kotlin DSL vs Groovy DSL

.gradle.kts vs .gradle · type-safe accessors · quotes & parentheses · = assignment · tasks.named<T> · migrating to Kotlin

Two DSLs, One API

Both DSLs drive the same Gradle API, so every concept on these sheets applies to both. The Kotlin DSL (.gradle.kts) is statically typed: the IDE completes and checks it, and mistakes fail at script compile time. The Groovy DSL (.gradle) is dynamic and terser but errors show up only when the line runs. Kotlin is the default for new builds; you can mix both file types in one build.

Notes

  • Kotlin DSL scripts compile once, then are cached
  • Gradle 9 embeds Kotlin 2.2 and Groovy 4
  • Groovy space-assignment (version '1.0') is deprecated; use =
  • Type-safe accessors (libs, java { }) exist only for plugins in plugins { }

build.gradle.kts (Kotlin)

plugins {
    id("application")
    id("com.gradleup.shadow") version "9.0.0"
}
group = "com.example"
version = "1.0.0"
repositories { mavenCentral() }
dependencies {
    implementation("com.google.guava:guava:33.4.0-jre")
    testImplementation(libs.junit.jupiter)
    testRuntimeOnly(libs.junit.launcher)
}
application { mainClass = "com.example.App" }
tasks.named<Test>("test") {
    useJUnitPlatform()
    maxHeapSize = "1g"
}

build.gradle (Groovy)

plugins {
    id 'application'
    id 'com.gradleup.shadow' version '9.0.0'
}
group = 'com.example'
version = '1.0.0'
repositories { mavenCentral() }
dependencies {
    implementation 'com.google.guava:guava:33.4.0-jre'
    testImplementation libs.junit.jupiter
    testRuntimeOnly libs.junit.launcher
}
application { mainClass = 'com.example.App' }
tasks.named('test', Test) {
    useJUnitPlatform()
    maxHeapSize = '1g'
}

Migrating Groovy → Kotlin

StepDo
1Rename settings.gradle, then each build file, to .kts
2Change ' to "; add () to method calls
3Replace ext with extra or the catalog
4Move apply plugin: into plugins { }

⚠ Common Mistakes

  • Single quotes in .kts (id('java')) — that is a Kotlin Char literal, so the script fails to compile
  • Using tasks.test { }-style accessors for a plugin applied with apply(plugin = …) — accessors only exist for plugins { }
  • Using "test"() { } task syntax from old Kotlin DSL samples — removed in Gradle 9; use tasks.named("test")

✓ Tips & Best Practices

  • Convert one file at a time; Groovy and Kotlin scripts can live side by side
  • After editing a .kts file, sync the IDE so new accessors appear
  • Run ./gradlew help after a migration to catch compile errors fast

Quick Summary

  • .gradle.kts — typed, IDE-checked, default
  • .gradle — dynamic Groovy, terser
  • "…" + () — the two main Kotlin syntax rules
  • tasks.named<T>() — typed task access in Kotlin
