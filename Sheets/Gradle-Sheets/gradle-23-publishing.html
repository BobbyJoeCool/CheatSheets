Publishing to a Repository

The maven-publish plugin turns a component (your JAR plus its dependency metadata) into a publication and uploads it to Maven repositories. Gradle also publishes Gradle Module Metadata (.module) next to the POM, which preserves features like api vs implementation and platforms. Add signing for Maven Central, which also requires sources and Javadoc JARs.

Notes

  • Maven Central uploads now go through the Central Portal (OSSRH closed in 2025)
  • Community plugins (e.g. com.vanniktech.maven.publish, JReleaser) handle Central
  • Coordinates: group, project name (or artifactId), version

maven-publish + signing

plugins { `java-library`; `maven-publish`; signing }
java { withSourcesJar(); withJavadocJar() }

publishing {
    publications {
        create<MavenPublication>("maven") {
            from(components["java"])
            artifactId = "json-lib"
            pom { name = "JSON Lib"; url = "https://example.com" }
        }
    }
    repositories {
        maven("https://repo.example.com/releases") {
            name = "company"
            credentials(PasswordCredentials::class)
        }
    }
}
signing { sign(publishing.publications["maven"]) }

Code Explained

from(components["java"]) — the JAR plus dependency metadata
artifactId — defaults to the project name
pom { } — name, license, SCM, developers (required by Central)
name = "company" — gives the task name and credential keys
sign(...) — adds .asc signatures for every file

In Groovy DSL

create<MavenPublication>("maven") → maven(MavenPublication) { }
components["java"] → components.java
sign(publishing.publications["maven"]) → sign publishing.publications.maven

Java vs Kotlin Projects

Same components["java"] for Java and Kotlin/JVM libraries
Kotlin — javadoc ignores Kotlin code; use Dokka for the -javadoc.jar
Kotlin — withSourcesJar() includes the .kt sources

⚠ Common Mistakes

  • Publishing with enforcedPlatform or dynamic versions — consumers inherit forced or unpredictable versions
  • Forgetting withSourcesJar() / withJavadocJar() — Maven Central rejects the upload
  • Testing with publishToMavenLocal and leaving mavenLocal() in consumers — use a composite build instead

✓ Tips & Best Practices

  • Set group and version once in gradle.properties
  • In CI, pass keys as ORG_GRADLE_PROJECT_signingKey and use in-memory keys
  • Inspect output in build/publications/maven/ before uploading

Quick Summary

  • maven-publish — publish to Maven repos
  • create<MavenPublication> — define what to publish
  • publishToMavenLocal — local install
  • signing { sign(…) } — required for Central
