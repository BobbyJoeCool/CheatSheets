Running Tests

The test task runs the tests in src/test and writes HTML reports to build/reports/tests/test/. Call useJUnitPlatform() for JUnit 5/6, TestNG via its engine, Spock or Kotest. For extra kinds of tests, such as integration tests, the JVM Test Suite plugin creates a source set, configurations and a Test task in one block.

Gradle 9 Changes

  • Declare junit-platform-launcher as testRuntimeOnly yourself
  • test fails if it finds no tests (failOnNoDiscoveredTests)
  • Custom Test tasks no longer inherit the test classpath
  • Tests are cached: unchanged code → UP-TO-DATE

Test Configuration

import org.gradle.api.tasks.testing.logging.TestExceptionFormat.FULL

dependencies {
    testImplementation(platform("org.junit:junit-bom:5.13.4"))
    testImplementation("org.junit.jupiter:junit-jupiter")
    testRuntimeOnly("org.junit.platform:junit-platform-launcher")
}
tasks.test {
    useJUnitPlatform { excludeTags("slow") }
    maxParallelForks = 4
    testLogging { events("failed", "skipped"); exceptionFormat = FULL }
}
testing.suites {                                // jvm-test-suite plugin
    register<JvmTestSuite>("integrationTest") {
        useJUnitJupiter()
        dependencies { implementation(project()) }
    }
}

Code Explained

junit-bom — one version for all JUnit modules
excludeTags("slow") — skip @Tag("slow") tests
maxParallelForks — run test classes in parallel JVMs
exceptionFormat = FULL — full stack traces in the console
register<JvmTestSuite> — adds src/integrationTest + task
implementation(project()) — the suite sees main's code

In Groovy DSL

exceptionFormat = FULL → exceptionFormat = 'full', no import
tasks.test { } → tasks.named('test') { }; excludeTags 'slow'
register<JvmTestSuite>("x") → x(JvmTestSuite) { }

Java vs Kotlin Projects

Same test task and JUnit Platform for Java and Kotlin
Kotlin — testImplementation(kotlin("test")) picks kotlin-test-junit5
Kotlin — backtick test names: fun `adds two numbers`()

⚠ Common Mistakes

  • Calling useJUnitPlatform() but adding JUnit 4 tests only — no engine finds them; add junit-vintage-engine
  • Registering a plain Test task for integration tests — in Gradle 9 it has no classpath; use a test suite
  • Using --rerun-tasks to re-run tests — it reruns everything; test --rerun is enough

✓ Tips & Best Practices

  • Open build/reports/tests/test/index.html for full results and output
  • Make check depend on integrationTest so build runs the suite too
  • Use --scan to see slowest tests and flaky retries

Quick Summary

  • useJUnitPlatform() — run JUnit Platform engines
  • --tests — filter by class or method
  • testing.suites — extra test types
  • testLogging — console output
