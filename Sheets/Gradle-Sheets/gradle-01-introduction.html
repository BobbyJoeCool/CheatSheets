What Gradle Is

Gradle is a build automation tool for Java, Kotlin, Groovy, Scala, Android and C++. A build is a set of projects, each with tasks (compile, test, jar). Gradle wires tasks into a directed acyclic graph and runs only what changed, using up-to-date checks, a build cache and a long-lived daemon. Build scripts are real code written in the Kotlin DSL (build.gradle.kts) or the Groovy DSL (build.gradle).

Good to Know

  • Created in 2008; maintained by Gradle Inc. Current line: 9.x (9.8, Sept 2026)
  • Default build tool for Android; an option in Spring Initializr and IntelliJ
  • Gradle 9 runs on JVM 17+; toolchains can still compile for Java 8
  • gradle init generates Kotlin DSL by default

The Smallest Useful Build

// build.gradle.kts
plugins { java }              // adds compileJava, test, jar, build…

tasks.register("hello") {     // a custom task, created lazily
    group = "demo"
    description = "Prints a greeting"
    doLast { println("Hello from Gradle!") }   // execution phase
}

// $ ./gradlew hello
// > Task :hello
// Hello from Gradle!
// BUILD SUCCESSFUL in 1s

Code Explained

plugins { java } — applies the core Java plugin and its task set
tasks.register — declares a task; it is only configured if it will run
group / description — shown by ./gradlew tasks
doLast { } — the action; code outside it runs at configuration time
./gradlew — the wrapper script; downloads the pinned Gradle version

In Groovy DSL

build.gradle — same script, Groovy file name
plugins { java } → plugins { id 'java' }
println("…") → println '…' — '…' is literal, "…" interpolates

Java vs Kotlin Projects

Java — plugins { java }: compileJava, sources in src/main/java
Kotlin — kotlin("jvm") version "2.2.20": compileKotlin, src/main/kotlin; applies java too
Task code (register, doLast) is identical in both

Build Lifecycle

PhaseWhat happens
InitializationReads settings.gradle.kts, decides which projects are in the build
ConfigurationRuns each build.gradle.kts, creates and configures the needed tasks
ExecutionRuns the requested tasks and their dependencies in graph order

Core Terms

TermMeaning

taskOne unit of work: compile, copy, test

⚠ Common Mistakes

  • Putting work outside doLast { } — it then runs on every build during configuration, even when the task is not requested
  • Running a globally installed gradle instead of ./gradlew — you get a different Gradle version than the project expects
  • Thinking Gradle needs Java 17 for your code — only the daemon does; set a toolchain to target older Java

✓ Tips & Best Practices

  • Run ./gradlew tasks in any unfamiliar project to see what it can do
  • Add --scan to a build for a shareable web report of what ran and why
  • Prefer the Kotlin DSL for new builds: compile-time checks and IDE completion

Quick Summary

  • project + task — the two building blocks of every build
  • init → configure → execute — the three build phases
  • ./gradlew <task> — run a task through the wrapper
  • doLast { } — where task work belongs
