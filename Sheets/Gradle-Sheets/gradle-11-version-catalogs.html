Version Catalogs

gradle/libs.versions.toml · [versions] · [libraries] · [bundles] · [plugins] · libs.x.y accessors · version.ref

One File for Versions

A version catalog is a TOML file, gradle/libs.versions.toml, that names every dependency and plugin with its version. Gradle reads it automatically and generates a type-safe libs accessor, so build scripts say libs.guava instead of repeating coordinates. A catalog only declares names; it does not add anything to a project until you use an entry.

Naming Rules

  • -, _ and . in keys become dots: junit-jupiter → libs.junit.jupiter
  • Plugins are under libs.plugins.*, bundles under libs.bundles.*
  • Versions: libs.versions.kotlin.get() gives the string

gradle/libs.versions.toml

[versions]
kotlin = "2.2.20"
junit = "5.13.4"
springBoot = "4.1.0"

[libraries]
guava = "com.google.guava:guava:33.4.0-jre"
junit-bom = { module = "org.junit:junit-bom", version.ref = "junit" }
junit-jupiter = { module = "org.junit.jupiter:junit-jupiter" }
junit-launcher = { module = "org.junit.platform:junit-platform-launcher" }
assertj = { module = "org.assertj:assertj-core", version = "3.27.3" }

[bundles]
testing = ["junit-jupiter", "assertj"]

[plugins]
kotlin-jvm = { id = "org.jetbrains.kotlin.jvm", version.ref = "kotlin" }
spring-boot = { id = "org.springframework.boot", version.ref = "springBoot" }

Using It in build.gradle.kts

implementation(libs.guava) — a library entry
platform(libs.junit.bom) — a BOM entry
libs.bundles.testing — several at once
alias(libs.plugins.kotlin.jvm) — in the plugins { } block
version.ref — share one [versions] value across entries
No version — expected to come from a platform/BOM

Library Entry Forms

TOMLMeaning
"g:a:1.0"Shorthand coordinates

⚠ Common Mistakes

  • Using libs.bundles or libs libraries inside plugins { } — removed in Gradle 9; only libs.plugins.* works there
  • Naming a key junit.jupiter and a key junit — a key cannot be both a leaf and a group
  • Expecting a catalog entry to be a dependency — nothing is added until you reference it

✓ Tips & Best Practices

  • Keep shared versions in [versions] and use version.ref everywhere else
  • Sort entries alphabetically; diff reviews get much easier
  • Pair the catalog with a BOM for big families (Spring, Jackson, JUnit)

Quick Summary

  • libs.versions.toml — all versions in one file
  • libs.x — type-safe accessor for [libraries]
  • alias(libs.plugins.x) — plugins from the catalog
  • version.ref — reuse a named version
