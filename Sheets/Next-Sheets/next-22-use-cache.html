Cache Components & 'use cache'

cacheComponents · 'use cache' · cache keys · 'use cache: remote' · 'use cache: private'

Explicit, Opt-In Caching

With cacheComponents: true, nothing is cached unless you say so. Add the 'use cache' directive to an async function, component, or a whole file to cache its return value. The cache key is built automatically from the build ID, the function's identity, and its serialized arguments (including captured closure variables).

Constraints

  • Cached functions must be async
  • Arguments and return values must be serializable
  • No cookies() / headers() / searchParams inside
  • Entries don't survive a new deploy (key includes build ID)

Three Levels of Caching

// next.config.ts → { cacheComponents: true }
import { cacheLife, cacheTag } from 'next/cache'

export async function getProduct(id: string) {     // function level
  'use cache'
  cacheLife('hours'); cacheTag(`product-${id}`)
  return db.product.findUnique({ where: { id } })
}

export async function Footer() {                   // component level
  'use cache'
  cacheLife('max')
  const links = await cms.getFooterLinks()
  return <footer>{/* … */}</footer>
}

// 'use cache' as first line of a file → every export is cached

Notes

id is part of the cache key: one entry per product
cacheLife — how long the entry lives (sheet 23)
cacheTag — label for on-demand invalidation
Read cookies outside, pass values in as arguments
children / JSX props pass through without affecting the key

⚠ Common Mistakes

  • Calling cookies() inside a cached function; it throws next-request-in-use-cache
  • Passing a promise of request data into a cached component; the build hangs then times out after 50 s
  • Relying on default in-memory 'use cache' for runtime hits on serverless; instances don't share memory

✓ Tips & Best Practices

  • Always call cacheLife() in each cached scope so its lifetime is obvious
  • Cache on low-cardinality keys (category, language), then filter in memory
  • All three directives are enabled by cacheComponents (stable since 16.0)

Quick Summary

  • cacheComponents: true — opt into the model
  • 'use cache' — cache a function, component, or file
  • Key — build ID + function ID + arguments
  • remote / private — shared store / browser only
