Platforms & Deployment Adapters

Vercel · Netlify · Cloudflare via OpenNext · adapterPath · Bun · edge vs Node.js runtime

Choosing Where to Deploy

Next.js runs fully on any Node.js server or container. Platforms that run it differently use the Deployment Adapter API (adapterPath) to transform the build output. Verified adapters (currently Vercel and Bun) run the full Next.js test suite; Netlify and Cloudflare offer their own integrations while building verified adapters.

Runtime Notes

  • Node.js is the default runtime everywhere
  • runtime = 'edge' segment config is deprecated
  • proxy.ts always runs on Node.js
  • preferredRegion is deprecated

Adapter Config and Platform Setup

// next.config.ts — custom adapter (platforms usually set this for you)
const nextConfig: NextConfig = {
  adapterPath: require.resolve('./my-adapter.js'),
}
// or zero-config on a platform:  NEXT_ADAPTER_PATH=/path/to/adapter

// Cloudflare Workers via OpenNext
$ npm i -D @opennextjs/cloudflare wrangler
$ npx opennextjs-cloudflare build && npx opennextjs-cloudflare deploy

// Vercel
$ npx vercel            # or connect the Git repo

// Netlify: built-in Next.js runtime, connect the repo
// Bun:     bun --bun next build && bun --bun next start

Notes

Adapters hook build output: routes, prerenders, functions
Reference implementation: nextjs/adapter-vercel
OpenNext also targets AWS (SST)
Check each platform's support matrix for 16.x features

⚠ Common Mistakes

  • Choosing runtime = 'edge' for new routes; it's deprecated, and Node.js gets the full API surface
  • Assuming every host supports Cache Components and PPR the same way; check the adapter's notes
  • Hard-coding a platform's paths into app code; keep platform specifics in config

✓ Tips & Best Practices

  • Pick a verified adapter or plain next start when you need every feature
  • Test your production build locally before switching platforms
  • Read 'Deploying to Platforms' in the docs for the feature-by-feature matrix
