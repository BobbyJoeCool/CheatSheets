Sheet 53

Static Export

output: 'export' · out/ · unsupported features · trailingSlash · images.unoptimized · CDN hosting

HTML Files, No Server

With output: 'export', next build writes plain HTML, CSS, and JS to out/. Host it on any static server or CDN (S3, GitHub Pages, Nginx). Server Components still run at build time, and Client Components work normally in the browser, but anything that needs a server at request time is unavailable.

What Still Works

  • Server Components (rendered at build)
  • Client-side fetching and navigation
  • Route Handlers with GET (emitted as static files)
  • next/image with a custom loader or unoptimized

Configure and Build

// next.config.ts
const nextConfig: NextConfig = {
  output: 'export',
  trailingSlash: true,          // /about → /about/index.html
  images: { unoptimized: true },// no optimizer server
  // basePath: '/my-repo',      // GitHub Pages project site
}

// app/blog/[slug]/page.tsx — every param must be known at build
export async function generateStaticParams() {
  return (await getPosts()).map((p) => ({ slug: p.slug }))
}

$ next build                    # writes ./out
$ npx serve out                 # preview locally

Notes

Dynamic routes need generateStaticParams
trailingSlash helps hosts that serve folder/index.html
unoptimized — or point loaderFile at an image CDN
next start doesn't serve an export; use a static server

⚠ Common Mistakes

  • Adding cookies() or a Server Action to an exported app; the build fails
  • Forgetting basePath on GitHub Pages project sites; every asset path 404s
  • Expecting new blog posts to appear without rebuilding; the export is frozen at build time

✓ Tips & Best Practices

  • Start static and remove output: 'export' later if you need server features
  • Use client-side fetching (SWR) for data that changes between builds
  • Trigger a rebuild from your CMS webhook to publish new content

Quick Summary

  • output: 'export' — static out/ folder
  • generateStaticParams — required for dynamic routes
  • images.unoptimized — or a custom loader
  • No request-time features
