Route Handlers

route.ts · GET · POST · PUT · DELETE · NextRequest · NextResponse · Response.json()

HTTP Endpoints in app/

A route.ts file exports functions named after HTTP methods. Each receives a Web Request (or NextRequest) and returns a Response. Route Handlers replace Pages Router API routes and are the right tool for webhooks, public APIs, file downloads, and endpoints that non-React clients call.

Rules

  • Supported: GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS
  • Unsupported methods return 405 automatically
  • Can't live in the same folder as page.tsx
  • GET handlers are dynamic by default

CRUD Endpoint

// app/api/posts/[id]/route.ts
import { NextRequest, NextResponse } from 'next/server'
type Ctx = RouteContext<'/api/posts/[id]'>

export async function GET(_req: NextRequest, ctx: Ctx) {
  const { id } = await ctx.params                      // Promise in 16
  const post = await db.post.findUnique({ where: { id } })
  if (!post) return NextResponse.json({ error: 'Not found' }, { status: 404 })
  return Response.json(post)                           // 200
}

export async function PUT(req: NextRequest, ctx: Ctx) {
  const { id } = await ctx.params
  const body = await req.json()
  const post = await db.post.update({ where: { id }, data: body })
  return Response.json(post)
}

export async function DELETE(_req: Request, ctx: Ctx) {
  await db.post.delete({ where: { id: (await ctx.params).id } })
  return new Response(null, { status: 204 })
}

Notes

RouteContext<'/api/posts/[id]'> — typed params helper
Response.json() — standard Web API; works everywhere
NextResponse.json() — same plus cookie helpers
204 responses must have a null body
Validate body before writing (Zod)

⚠ Common Mistakes

  • Calling your own Route Handler from a Server Component; call the data function directly
  • Expecting GET responses to be cached by default; they're dynamic unless you opt in
  • Using a Route Handler for your own form submissions where a Server Action is simpler

✓ Tips & Best Practices

  • Use RouteContext for typed params instead of hand-written types
  • Return consistent error shapes ({ error }) with correct status codes
  • Put handlers under app/api/ by convention so they're easy to exclude in proxy.ts matchers

Quick Summary
