Client-Side Fetching

SWR · TanStack Query · route handlers as endpoints · useEffect pitfalls · polling

When the Browser Should Fetch

Most data should be fetched on the server. Fetch on the client when data depends on user interaction after load (search-as-you-type, infinite scroll), needs polling or real-time updates, or is per-user and not worth server rendering. Use a data library such as SWR or TanStack Query for caching, deduping, and revalidation.

Good Client Cases

  • Live data: notifications, stock prices
  • Infinite scroll and pagination UI
  • Optimistic updates with local cache
  • Data needed only after a user action

SWR Seeded From the Server

// app/inbox/page.tsx (server) — initial data, no spinner
const initial = await getMessages()
return <Inbox fallback={initial} />

// app/inbox/inbox.tsx
'use client'
import useSWR from 'swr'
const fetcher = (url: string) => fetch(url).then((r) => r.json())

export function Inbox({ fallback }: { fallback: Message[] }) {
  const { data, error, isLoading, mutate } = useSWR(
    '/api/messages', fetcher,
    { fallbackData: fallback, refreshInterval: 10_000 })   // poll 10 s
  if (error) return <p>Failed to load</p>
  return <MessageList items={data} onRead={() => mutate()} />
}

Notes

fallbackData — first render uses server data
/api/messages — a Route Handler (app/api/messages/route.ts)
refreshInterval — background polling
mutate() — revalidate after a change
Same key in two components = one request

⚠ Common Mistakes

  • Fetching first-render data in useEffect; users see a spinner the server could have avoided
  • Calling a Route Handler with a relative URL from a Server Component; there is no browser origin on the server
  • Putting QueryClientProvider in a Server Component; it must live in a client provider

✓ Tips & Best Practices

  • Seed client caches with server data (fallbackData or HydrationBoundary) to skip loading states
  • Prefer Server Actions over custom POST endpoints for mutations from your own UI
  • Create the TanStack QueryClient with useState(() => new QueryClient()) so it's stable

Quick Summary

  • Server first — client only for interactive data
  • useSWR / useQuery — cache, dedupe, revalidate
  • Route Handlers — JSON endpoints for the client
  • Seed client caches from server data
