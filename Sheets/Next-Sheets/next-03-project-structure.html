Sheet 03

Project Structure & Special Files

app/ · public/ · src/ · page · layout · loading · error · route.ts

How Files Become Routes

Inside app/, folders define URL segments and special files define the UI for that segment. Only a page or route file makes a segment publicly reachable, so you can safely colocate components, tests, and styles next to the route that uses them.

Top-Level Files

  • public/ — static assets at / (e.g. /logo.svg)
  • next.config.ts — framework configuration
  • proxy.ts — request interception (was middleware.ts)
  • instrumentation.ts — server startup hooks

A Typical Tree

my-app/
├─ app/
│  ├─ layout.tsx          # root layout (required)
│  ├─ page.tsx            # /
│  ├─ globals.css
│  ├─ not-found.tsx       # global 404 UI
│  ├─ dashboard/
│  │  ├─ layout.tsx       # wraps /dashboard/*
│  │  ├─ page.tsx         # /dashboard
│  │  ├─ loading.tsx      # Suspense fallback
│  │  ├─ error.tsx        # error boundary
│  │  └─ chart.tsx        # colocated, NOT a route
│  └─ api/health/route.ts # GET /api/health
├─ public/logo.svg        # /logo.svg
├─ proxy.ts
└─ next.config.ts

Reading the Tree

Folder = URL segment (dashboard/ → /dashboard)
chart.tsx is private: no page export means no URL
route.ts cannot share a folder with page.tsx
Nesting order: layout → template → error → loading → not-found → page
src/app works the same; config files stay at the root

Special Files

FilePurpose
pageUnique UI for a route; makes it public
layoutShared UI that persists across navigation
templateLike layout but remounts on navigation
loadingInstant Suspense fallback
error / global-errorError boundaries
not-foundUI for notFound() and unknown URLs
defaultFallback for parallel route slots
routeAPI endpoint (Route Handler)

Folder Conventions

PatternMeaning
[slug]Dynamic segment
[...slug] / [[...slug]]Catch-all / optional
(group)Route group; not in URL
_folderPrivate; never routed
@slotParallel route slot
(.)folderIntercepting route

⚠ Common Mistakes

  • Putting page.tsx and route.ts in the same folder; Next.js reports a conflict
  • Expecting files in public/ to be processed; they are served as-is with no hashing
  • Naming a helper page.tsx deep in a folder and accidentally publishing a URL

✓ Tips & Best Practices

  • Prefix internal folders with _ (e.g. _components) to make intent obvious
  • Use (group) folders to organize by feature without changing URLs
  • Keep shared code in lib/ or components/ outside app/ if you prefer separation

Quick Summary

  • app/ — folders map to URL segments
  • page / route — the only public entry points
  • loading / error — automatic Suspense and error boundaries
  • public/ — static files served from /
