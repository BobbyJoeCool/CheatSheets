Protecting Routes & Data

optimistic checks in proxy · pages vs layouts · server-only · DTOs · taint APIs

Defense in Layers

Use proxy for fast, optimistic redirects based only on cookie presence. Do the real check close to the data: in the DAL, Server Components, Server Actions, and Route Handlers. Return DTOs (only the fields the UI needs) so sensitive columns never reach a Client Component.

Where to Check

  • proxy: cookie exists? (no DB calls)
  • Page / component: await verifySession()
  • Server Action: verify + authorize the record
  • Route Handler: verify, return 401/403

DAL With Authorization + DTO

// lib/dal/projects.ts
import 'server-only'
import { forbidden } from 'next/navigation'
import { verifySession } from '@/lib/dal'

export async function getProject(id: string) {
  const { userId, role } = await verifySession()
  const p = await db.project.findUnique({ where: { id },
    include: { members: true } })
  const canView = role === 'admin' || p?.members.some(m => m.userId === userId)
  if (!p || !canView) forbidden()                    // 403 UI
  return { id: p.id, name: p.name, updatedAt: p.updatedAt }  // DTO
}

// app/projects/[id]/page.tsx
export default async function Page(props: PageProps<'/projects/[id]'>) {
  const project = await getProject((await props.params).id)
  return <ProjectView project={project} />            // safe props
}

Notes

Authorization uses the session, never a client-sent user ID
DTO drops fields like billingEmail or apiKey
forbidden() needs experimental.authInterrupts
server-only keeps the DAL out of client bundles

⚠ Common Mistakes

  • Doing a DB-backed auth check in proxy on every request; it slows every route and asset
  • Passing a full user record to a Client Component; every field is visible in the page payload
  • Relying on hidden UI for authorization; anyone can call the action or endpoint directly

✓ Tips & Best Practices

  • Funnel all reads through DAL functions so auth can't be forgotten
  • Use unauthorized() (401) for logged-out users and forbidden() (403) for missing permissions
  • Write a test per DAL function asserting that another user's ID is rejected

Quick Summary

  • proxy — optimistic, cookie-only checks
  • DAL — real auth + authorization
  • DTOs — return only needed fields
  • Taint APIs — block secrets from reaching clients
