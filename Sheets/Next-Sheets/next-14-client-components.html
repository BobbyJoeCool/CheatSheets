Sheet 14

Client Components

'use client' · client boundary · serializable props · useState · browser APIs · client-only

Opting Into the Browser

Add 'use client' at the top of a file to mark it as a client boundary. That module and everything it imports become part of the client bundle: they are prerendered to HTML on the server, then hydrated in the browser so state, effects, and event handlers work. You only need the directive at the entry point of an interactive subtree.

Boundary Rules

  • Directive must be the first statement in the file
  • Imports of a client file are client code too
  • Props from server → client must be serializable
  • Server Actions are the one function you may pass

An Interactive Island

// app/products/add-to-cart.tsx
'use client'
import { useState, useTransition } from 'react'
import { addToCart } from './actions'          // a Server Action

export function AddToCart({ productId }: { productId: string }) {
  const [qty, setQty] = useState(1)
  const [pending, startTransition] = useTransition()
  return (
    <div>
      <input type="number" value={qty} min={1}
        onChange={(e) => setQty(Number(e.target.value))} />
      <button disabled={pending}
        onClick={() => startTransition(() => addToCart(productId, qty))}>
        {pending ? 'Adding…' : 'Add to cart'}
      </button>
    </div>
  )
}

Notes

'use client' — this file is the boundary
productId — a string prop from the Server Component parent
addToCart — Server Actions can be imported into client code
useTransition — keeps the UI responsive during the action
Still SSR'd to HTML; becomes interactive after hydration

⚠ Common Mistakes

  • Accessing window during render; Client Components still prerender on the server, so it crashes
  • Marking a high-level layout 'use client'; the whole subtree and its imports ship to the browser
  • Passing an inline arrow function from a Server Component as a prop; functions aren't serializable

✓ Tips & Best Practices

  • Pass server-rendered content into Client Components as children to keep it on the server
  • Use suppressHydrationWarning only for intentional mismatches like timestamps
  • Name client files clearly (*-client.tsx or a client/ folder) so reviewers spot boundaries

Quick Summary

  • 'use client' — marks a client boundary
  • Hooks, state, events — client only
  • Props — must be serializable
  • client-only — guard browser-only modules
