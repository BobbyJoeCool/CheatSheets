One Route, Static and Dynamic

Partial Prerendering (PPR) is how Cache Components renders a route: at build time Next.js prerenders a static shell containing all static and cached UI, plus the <Suspense> fallbacks for anything dynamic. At request time the shell is served immediately (often from a CDN) and the dynamic holes stream in. There's no separate PPR flag anymore.

16.x Changes

  • experimental.ppr and experimental_ppr export removed
  • Enable with cacheComponents: true
  • 16.3 partialPrefetching: true prefetches each route's App Shell
  • Dev overlay flags navigations that would block

Shell + Holes

// app/product/[id]/page.tsx   (cacheComponents: true)
export default function Page(props: PageProps<'/product/[id]'>) {
  return (
    <>
      <SiteHeader />                                  {/* static */}
      <Suspense fallback={<DetailsSkeleton />}>
        <Details params={props.params} />             {/* cached */}
      </Suspense>
      <Suspense fallback={<p>Checking stock…</p>}>
        <Stock params={props.params} />               {/* dynamic */}
      </Suspense>
    </>
  )
}
async function Details({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params
  return <ProductInfo p={await getProduct(id)} />    // 'use cache'
}

What Ends Up Where

Shell: header, skeletons, and cached Details for prerendered IDs
Hole: Stock queries live inventory per request
Uncached data outside <Suspense> → dev/build error
Unlisted IDs serve the shell first, then fill the cache (16.3)
Opt a segment out of validation: export const instant = false

⚠ Common Mistakes

  • Placing one <Suspense> around the whole page; the shell becomes a single spinner
  • Awaiting params at the top of the page; it blocks the shell for dynamic routes
  • Expecting shell content from 'use cache: private'; private caches are never in the static shell

✓ Tips & Best Practices

  • Pass params promises down and await them inside the boundary
  • Push Suspense boundaries close to the data so more real content lands in the shell
  • Use the Navigation Inspector to see exactly what users see before data arrives

Quick Summary

  • Static shell — prerendered at build
  • Dynamic holes — <Suspense> streamed per request
  • Enabled by cacheComponents: true
  • partialPrefetching — App Shell prefetch (16.3)
