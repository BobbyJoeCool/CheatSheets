Revalidation

revalidateTag(tag, profile) · updateTag() · revalidatePath() · refresh() · read-your-writes

Refreshing Cached Data

Cached data refreshes in two ways: time-based (from cacheLife) and on-demand after a mutation. Next.js 16 splits on-demand APIs by intent: revalidateTag(tag, 'max') marks entries stale and refreshes them in the background, updateTag(tag) expires them immediately so the user sees their own write, and refresh() re-renders uncached data only.

Where They Work

  • updateTag / refresh — Server Actions only
  • revalidateTag / revalidatePath — Actions and Route Handlers
  • Calling any of them in an Action clears the client router cache
  • Single-argument revalidateTag(tag) is deprecated

Choosing the Right Call

'use server'
import { updateTag, revalidateTag, revalidatePath, refresh } from 'next/cache'

export async function saveProfile(form: FormData) {
  const user = await requireUser()
  await db.user.update({ where: { id: user.id }, data: parse(form) })
  updateTag(`user-${user.id}`)       // read-your-writes, right now
}

export async function publishPost(id: string) {
  await db.post.update({ where: { id }, data: { published: true } })
  revalidateTag('posts', 'max')     // stale-while-revalidate for readers
}

export async function markRead(id: string) {
  await db.notification.update({ where: { id }, data: { read: true } })
  refresh()                          // re-render uncached badge count
}

Notes

updateTag — next render waits for fresh data
revalidateTag(tag, 'max') — serve stale, refresh in background
Second arg: profile name or { expire: 3600 }
revalidatePath('/blog', 'layout') — include nested routes

⚠ Common Mistakes

  • Using revalidateTag after a form save and wondering why the user sees old data; use updateTag
  • Calling updateTag in a Route Handler; it's only allowed in Server Actions
  • Revalidating /blog/[slug] literally instead of the real path /blog/hello (or pass 'page' type)

✓ Tips & Best Practices

  • Tag at the data layer, then invalidate by tag; it scales better than tracking paths
  • Use 'max' as the default second argument unless you need a custom window
  • Protect revalidation webhooks with a secret and rate limiting

Quick Summary

  • updateTag — immediate, Server Actions only
  • revalidateTag(tag, 'max') — background refresh
  • revalidatePath — invalidate by URL
  • refresh() — uncached data only
