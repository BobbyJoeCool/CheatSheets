Sheet 18

Streaming & Suspense

loading.tsx vs <Suspense> · streaming promises · use() · fallback UI · waterfalls

Send What's Ready First

Streaming sends the page in chunks: the shell renders immediately, and each <Suspense> boundary is filled in as its data resolves. loading.tsx wraps a whole page in one boundary; explicit <Suspense> lets you stream individual sections so a slow widget never blocks the rest of the page.

Behavior

  • Boundaries resolve independently, in any order
  • HTML streams on first load; RSC payload on navigation
  • Status code is sent before streaming (always 200)
  • Search engines receive the fully streamed HTML

Independent Sections

import { Suspense } from 'react'

export default function Dashboard() {
  return (
    <>
      <h1>Dashboard</h1>                       {/* in the shell */}
      <Suspense fallback={<CardSkeleton />}>
        <Revenue />                            {/* 300 ms */}
      </Suspense>
      <Suspense fallback={<TableSkeleton />}>
        <LatestOrders />                       {/* 2 s */}
      </Suspense>
    </>
  )
}

async function Revenue() {
  const data = await getRevenue()             // awaited inside boundary
  return <Chart data={data} />
}

Reading It

The heading and both skeletons render instantly
Revenue replaces its skeleton at ~300 ms
LatestOrders streams in at ~2 s without blocking Revenue
Awaiting in the page itself would block everything
Size skeletons to match content to avoid layout shift

Avoiding Waterfalls

ProblemFix
Parent awaits, then child fetchesFetch in parallel or pass promise
Nested Suspense each fetch in turnStart all requests at the top
One slow query blocks pageIsolate it in its own boundary
Boundary too highMove <Suspense> closer to the data

⚠ Common Mistakes

  • Awaiting slow data in the page component above the boundary; the Suspense fallback never shows
  • Putting <Suspense> inside the async component it should wrap; it must be a parent
  • Trying to set a 404 after streaming starts; check existence before the first boundary

✓ Tips & Best Practices

  • Use the React DevTools Suspense panel to toggle boundaries and inspect fallbacks
  • Pass a key to <Suspense> to re-show the fallback when params change
  • Group related widgets in one boundary to avoid a 'popcorn' layout

Quick Summary

  • Streaming — shell first, holes fill in later
  • loading.tsx — page-level fallback
  • <Suspense> — section-level fallback
  • Await inside the boundary, not above it
