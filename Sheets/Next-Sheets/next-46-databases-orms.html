Databases & ORMs

Prisma · Drizzle · client singleton on globalThis · connection pooling · serverless drivers

Talking to a Database

Server Components, Server Actions, and Route Handlers can query a database directly. Two things matter in Next.js: create one client instance per server process (hot reload in dev creates new modules, so cache it on globalThis), and use pooling or an HTTP-based serverless driver when deploying to functions that scale out.

Where Queries Live

  • lib/db.ts — the client singleton
  • lib/dal/*.ts — auth-aware query functions
  • Mark both with import 'server-only'
  • Never import them from 'use client' files

Prisma Singleton

// lib/db.ts
import 'server-only'
import { PrismaClient } from '@/generated/prisma/client'
import { PrismaPg } from '@prisma/adapter-pg'

const g = globalThis as unknown as { db?: PrismaClient }
const adapter = new PrismaPg({
  connectionString: process.env.DATABASE_URL })

export const db = g.db ?? new PrismaClient({ adapter })
if (process.env.NODE_ENV !== 'production') g.db = db

// usage in a Server Component
const posts = await db.post.findMany({
  where: { published: true }, take: 10 })

Drizzle + Serverless Driver

// lib/db.ts
import 'server-only'
import { neon } from '@neondatabase/serverless'
import { drizzle } from 'drizzle-orm/neon-http'
import * as schema from './schema'

const sql = neon(process.env.DATABASE_URL!)
export const db = drizzle({ client: sql, schema })

// usage
import { eq } from 'drizzle-orm'
const user = await db.query.users.findFirst({
  where: eq(schema.users.id, id) })

⚠ Common Mistakes

  • Creating new PrismaClient() in each file; dev hot reloads exhaust database connections
  • Opening TCP connections per serverless invocation without a pooler; you hit connection limits
  • Returning full ORM rows (with hashes and tokens) to Client Components

✓ Tips & Best Practices

  • Add serverExternalPackages for native drivers that shouldn't be bundled
  • Run migrations in CI or a release step, never on app startup
  • Use select / column lists so cached entries stay small

Quick Summary

  • One client per process — globalThis in dev
  • Pooling / HTTP drivers — for serverless
  • server-only — keep DB code off the client
  • 'use cache' + tags — cache query results
