Scripts & Lazy Loading

next/script · strategy · @next/third-parties · next/dynamic · ssr: false · bundle analysis

Load Less, Later

<Script> from next/script controls when third-party scripts load so they don't block rendering. next/dynamic (or React.lazy) splits a Client Component into its own chunk that loads only when rendered. @next/third-parties wraps common embeds (Google Analytics, Tag Manager, YouTube, Maps) with sensible defaults.

Strategies

  • beforeInteractive — before hydration (root layout only)
  • afterInteractive — after hydration (default)
  • lazyOnload — during browser idle time
  • worker — web worker via Partytown (experimental)

Scripts and Dynamic Imports

import Script from 'next/script'
import { GoogleAnalytics } from '@next/third-parties/google'

<Script src="https://js.stripe.com/v3" strategy="afterInteractive"
  onLoad={() => console.log('stripe ready')} />     // client component
<Script id="chat" strategy="lazyOnload">{`window.chat.init('abc')`}</Script>
<GoogleAnalytics gaId="G-XXXXXXX" />               // in root layout

'use client'
import dynamic from 'next/dynamic'
const Chart = dynamic(() => import('./chart'), {
  loading: () => <p>Loading chart…</p>,
})
const Map = dynamic(() => import('./map'), { ssr: false }) // browser only
export function Report({ show }: { show: boolean }) {
  return show ? <Chart /> : null                    // chunk loads on demand
}

Notes

onLoad / onReady / onError need a Client Component
Inline scripts need a unique id
ssr: false is only allowed inside Client Components
Server Components are already code-split; dynamic is for client code
Import heavy libs inside event handlers: await import('xlsx')

⚠ Common Mistakes

  • Using ssr: false in a Server Component; it's an error, so move the dynamic() call into a client file
  • Loading analytics with beforeInteractive; it delays every page's interactivity
  • Wrapping already-small components in dynamic(); each chunk adds a request

✓ Tips & Best Practices

  • Lazy-load modals, charts, and editors that aren't visible on first paint
  • Run next experimental-analyze before and after a refactor to compare bundles
  • Prefer @next/third-parties over hand-written GA snippets

Quick Summary

  • <Script strategy> — control load timing
  • next/dynamic — split client components
  • ssr: false — browser-only (client files)
