What next build Produces

next build compiles with Turbopack, type-checks, prerenders static routes, and writes everything to .next/. The terminal output shows timing for each step and a route table marking each route as static, partially prerendered, or dynamic. Since 16.3, Turbopack's disk cache also speeds up repeat builds by default.

16.x Changes

  • Route table no longer lists JS bundle sizes
  • next build no longer runs a linter
  • Type checking can use TypeScript 7 (tsc CLI)
  • Dev output goes to .next/dev, build to .next/

⚠ Common Mistakes

  • Not caching .next/cache in CI; every build starts cold and takes longer
  • Ignoring an unexpected ƒ in the route table; one dynamic API in a shared layout de-opts many routes
  • Committing .next/ to git; it's build output and should be ignored

✓ Tips & Best Practices

  • Compare the route table before and after caching changes
  • Set the same deploymentId across instances to avoid version skew
  • Use next experimental-analyze instead of the old bundle-size column
