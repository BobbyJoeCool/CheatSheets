Pages Router Basics

pages/ · _app.tsx · _document.tsx · next/router · useRouter() · <Head>

The Original Router

The Pages Router maps files in pages/ directly to routes: pages/about.tsx is /about. Every page is a Client Component that is server-rendered and hydrated. It is still supported in 16.x and can run alongside app/, which is how most large codebases migrate. New features (Server Components, Cache Components) are App Router only.

Key Differences

  • File = route (no page.tsx folder convention)
  • _app.tsx wraps every page; _document.tsx shapes HTML
  • Router hooks come from next/router
  • Head tags via next/head, not Metadata API

Pages, _app, and _document

// pages/blog/[slug].tsx  →  /blog/hello
import Head from 'next/head'
import { useRouter } from 'next/router'
export default function Post() {
  const router = useRouter()
  const { slug } = router.query                   // string | string[]
  return <><Head><title>{`Post: ${slug}`}</title></Head><h1>{slug}</h1></>
}

// pages/_app.tsx — global layout, CSS, providers
import type { AppProps } from 'next/app'
import '@/styles/globals.css'
export default function App({ Component, pageProps }: AppProps) {
  return <Layout><Component {...pageProps} /></Layout>
}

// pages/_document.tsx — custom <html>/<body>, server only
import { Html, Head as DocHead, Main, NextScript } from 'next/document'
export default function Document() {
  return <Html lang="en"><DocHead /><body><Main /><NextScript /></body></Html>
}

Notes

router.query — dynamic params and query string together
query is empty on the first render of static pages until hydration
Global CSS can only be imported in _app.tsx
_document has no data fetching or event handlers
Links: same next/link component in both routers

⚠ Common Mistakes

  • Importing useRouter from next/navigation in pages/; Pages Router uses next/router
  • Reading router.query before router.isReady on static pages; values are empty at first
  • Importing global CSS in a page component; only _app.tsx may import global CSS

✓ Tips & Best Practices

  • Keep using the Pages Router for stable legacy areas and add new routes in app/
  • Move shared layout into _app.tsx with a per-page getLayout pattern
  • Use next/link everywhere so links work across both routers

Quick Summary

  • pages/ — file = route
  • _app.tsx — global wrapper
  • _document.tsx — custom HTML shell
  • next/router — Pages Router hooks
