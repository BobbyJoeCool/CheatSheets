API Routes & Migrating to App Router

pages/api · req / res · NextApiRequest · incremental adoption · app/ and pages/ side by side

Endpoints and the Migration Path

Pages Router API routes live in pages/api and use Node-style req/res objects. In the App Router they become Route Handlers using Web Request/Response. Both routers can run in the same project, so migrate incrementally: move one route at a time from pages/ to app/ and ship as you go.

Coexistence Rules

  • A URL can't exist in both app/ and pages/
  • app/ routes take priority in the build check
  • Navigating between routers is a full page load
  • Shared components work in both (mind 'use client')

pages/api (Before)

// pages/api/posts/[id].ts
import type { NextApiRequest, NextApiResponse }
  from 'next'

export default async function handler(
  req: NextApiRequest, res: NextApiResponse) {
  const id = req.query.id as string
  if (req.method === 'GET')
    return res.status(200).json(await getPost(id))
  if (req.method === 'DELETE') {
    await deletePost(id)
    return res.status(204).end()
  }
  res.setHeader('Allow', 'GET, DELETE')
  res.status(405).end()
}

app/api Route Handler (After)

// app/api/posts/[id]/route.ts
type Ctx = RouteContext<'/api/posts/[id]'>

export async function GET(_: Request, ctx: Ctx) {
  const { id } = await ctx.params
  return Response.json(await getPost(id))
}

export async function DELETE(_: Request, ctx: Ctx) {
  const { id } = await ctx.params
  await deletePost(id)
  return new Response(null, { status: 204 })
}
// 405 for other methods is automatic

⚠ Common Mistakes

  • Leaving the same route in both pages/ and app/; the build fails with a conflict
  • Porting every API route; internal ones used only by your UI are often simpler as Server Actions
  • Forgetting that useRouter from next/router doesn't work in app/

✓ Tips & Best Practices

  • Run npx @next/codemod@canary upgrade latest before starting the migration
  • Migrate the root layout first so new app/ pages share the same shell
  • Keep Pages Router routes for stable areas that don't need App Router features

Quick Summary

  • pages/api — Node-style req / res
  • Route Handlers — Web Request / Response
  • Both routers coexist; migrate route by route
  • Internal endpoints → Server Actions
