Instrumentation & Observability

instrumentation.ts · register() · onRequestError · OpenTelemetry · @vercel/otel · logging

Hooks for Monitoring

instrumentation.ts at the project root (or src/) exports register(), which runs once when each server instance starts: the place to initialize tracing and APM SDKs. onRequestError() is called for every server error with route and request context, which makes it easy to send errors to Sentry or your logger. instrumentation-client.ts runs in the browser before hydration.

Files

  • instrumentation.ts — server startup + errors
  • instrumentation-client.ts — client analytics, error tracking
  • Next.js emits OpenTelemetry spans for routing and fetch
  • NEXT_OTEL_VERBOSE=1 — more spans

OpenTelemetry + Error Reporting

// instrumentation.ts
import { registerOTel } from '@vercel/otel'
import type { Instrumentation } from 'next'

export function register() {
  registerOTel({ serviceName: 'acme-web' })
}

export const onRequestError: Instrumentation.onRequestError = async (
  err, request, context) => {
  await fetch('https://logs.acme.com/errors', {
    method: 'POST',
    body: JSON.stringify({
      message: err instanceof Error ? err.message : String(err),
      path: request.path,                         // '/blog/hello'
      routeType: context.routeType,                // 'render' | 'action' | …
      routePath: context.routePath,                // '/app/blog/[slug]'
    }),
  })
}

Notes

register() — runs once per server process
@vercel/otel works on any host, not only Vercel
context.routerKind — 'App Router' or 'Pages Router'
Import Node-only SDKs inside if (process.env.NEXT_RUNTIME === 'nodejs')
Errors from error.tsx digests match these reports

⚠ Common Mistakes

  • Initializing SDKs at the top of instrumentation.ts instead of inside register()
  • Importing Node-only packages unconditionally; guard with NEXT_RUNTIME checks
  • Throwing inside onRequestError; reporting must never crash the request path

✓ Tips & Best Practices

  • Use the Sentry or Datadog Next.js SDKs; they wire up both instrumentation files
  • Attach error.digest to user-facing messages so support can find the log
  • Export traces to any OTLP collector (Grafana, Honeycomb, Jaeger)
