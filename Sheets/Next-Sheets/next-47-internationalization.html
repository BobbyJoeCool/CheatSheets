Routing by Locale

The App Router has no built-in i18n config (that was a Pages Router feature). Instead, put a [lang] dynamic segment at the top of app/, detect the preferred locale in proxy, and load per-locale dictionaries on the server. Libraries like next-intl package this pattern. Next.js 16.3 adds root params so any Server Component can read lang without prop drilling.

Pieces

  • app/[lang]/layout.tsx — sets <html lang>
  • generateStaticParams — prerender each locale
  • proxy — redirect / to /en or /de
  • Dictionaries — JSON loaded with import()

Dictionaries + Layout

// app/[lang]/dictionaries.ts
import 'server-only'
const dicts = {
  en: () => import('./dict/en.json').then(m => m.default),
  de: () => import('./dict/de.json').then(m => m.default),
}
export type Locale = keyof typeof dicts
export const getDictionary = (l: Locale) => dicts[l]()

// app/[lang]/layout.tsx
export const generateStaticParams = () =>
  [{ lang: 'en' }, { lang: 'de' }]
export default async function Layout(
  { children, params }: LayoutProps<'/[lang]'>) {
  const { lang } = await params
  return <html lang={lang}><body>{children}</body></html>
}

Root Params + Detection

// any Server Component (16.3)
import { lang } from 'next/root-params'
export async function Footer() {
  const dict = await getDictionary(
    (await lang()) as Locale)
  return <footer>{dict.footer.copyright}</footer>
}

// proxy.ts
const locales = ['en', 'de']
export function proxy(req: NextRequest) {
  const { pathname } = req.nextUrl
  if (locales.some((l) => pathname.startsWith(`/${l}`)))
    return
  const al = req.headers.get('accept-language') ?? ''
  const l = al.startsWith('de') ? 'de' : 'en'
  req.nextUrl.pathname = `/${l}${pathname}`
  return NextResponse.redirect(req.nextUrl)
}

⚠ Common Mistakes

  • Using the Pages Router i18n key in next.config for App Router routes; it doesn't apply
  • Shipping every dictionary to the client; load on the server and pass only needed strings
  • Forgetting to exclude /api and assets from the locale-redirect matcher

✓ Tips & Best Practices

  • Use Intl formatters with the active locale instead of formatting libraries
  • Add alternates.languages in metadata for hreflang SEO
  • Root params work inside 'use cache', and only the params read join the cache key

Quick Summary

  • app/[lang]/ — locale as a route segment
  • proxy — detect and redirect
  • getDictionary() — server-side strings
  • next/root-params — read lang anywhere (16.3)
