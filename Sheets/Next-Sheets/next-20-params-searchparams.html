Reading the URL on Server and Client

Pages receive params (dynamic segments) and searchParams (query string) as Promises. Layouts receive only params. Next.js generates global helpers (PageProps, LayoutProps, RouteContext) so these props are typed from your actual routes. In Client Components, read the same values with hooks.

Key Facts

  • Reading searchParams makes the page render per request
  • Values are string | string[] | undefined
  • Types come from next dev, next build, or next typegen
  • 16.3: next/root-params reads root params anywhere

Search Page With Filters

// app/shop/[category]/page.tsx
export default async function Shop(props: PageProps<'/shop/[category]'>) {
  const { category } = await props.params                 // 'shoes'
  const { sort = 'new', page = '1' } = await props.searchParams
  const items = await getItems({
    category, sort: String(sort), page: Number(page) })   // ?sort=price&page=2
  return <ItemGrid items={items} />
}

// components/sort-select.tsx (client)
'use client'
import { useParams, useSearchParams, useRouter } from 'next/navigation'
export function SortSelect() {
  const { category } = useParams<{ category: string }>()
  const sp = useSearchParams(); const router = useRouter()
  const set = (v: string) => { const n = new URLSearchParams(sp)
    n.set('sort', v); router.replace(`?${n}`) }
  return <select defaultValue={sp.get('sort') ?? 'new'}
    onChange={(e) => set(e.target.value)}>{/* … */}</select>
}

Notes

PageProps<'/shop/[category]'> — no imports needed
Default values while destructuring the awaited object
Cast query values: they can be arrays (?tag=a&tag=b)
useSearchParams() returns a read-only object; copy to modify
router.replace avoids a history entry per filter change

⚠ Common Mistakes

  • Assuming searchParams.page is a number; it is a string (or array) and must be parsed
  • Reading searchParams in a layout to share filters; layouts don't receive it
  • Using useSearchParams() without <Suspense>; the whole route falls back to client rendering

✓ Tips & Best Practices

  • Validate query values with Zod (z.coerce.number()) before using them
  • Run next typegen in CI before tsc so route helpers exist
  • Keep filter state in the URL so it's shareable and survives refresh

Quick Summary

  • await props.params — dynamic segments
  • await props.searchParams — query string (pages only)
