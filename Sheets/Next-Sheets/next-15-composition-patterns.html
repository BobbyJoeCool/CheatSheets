Mixing Server and Client

A Client Component can't import a Server Component, but it can render one passed as a prop (usually children). That rule drives the main patterns: keep data fetching in Server Components, wrap only the interactive parts in client boundaries, and pass server-rendered output through slots.

Golden Rules

  • Server → Client: pass data or JSX as props
  • Client → Server: only via children or other slots
  • Context lives in a client provider component
  • Start promises on the server, read them with use()

Providers and Slots

// app/providers.tsx
'use client'
import { ThemeProvider } from 'next-themes'
export function Providers({ children }: { children: React.ReactNode }) {
  return <ThemeProvider attribute="class">{children}</ThemeProvider>
}

// app/layout.tsx  (Server Component)
import { Providers } from './providers'
export default function RootLayout({ children }: LayoutProps<'/'>) {
  return (
    <html lang="en" suppressHydrationWarning>
      <body><Providers>{children}</Providers></body>
    </html>
  )
}

Why It Works

Providers is the only client file; pages stay server-rendered
children is rendered on the server and passed in as a slot
Wrap third-party providers that use context in your own client file
Render the provider as deep as possible in the tree

Pass a Promise, Read With use()

// page.tsx (server) — don't await, pass the promise
const reviews = getReviews(id)
return <Suspense fallback={<Spinner />}>
  <Reviews data={reviews} /></Suspense>

// reviews.tsx (client)
'use client'
import { use } from 'react'
export function Reviews({ data }: { data: Promise<Review[]> }) {
  const reviews = use(data)    // suspends until resolved
  return <ul>{reviews.map(r => <li key={r.id}>{r.text}</li>)}</ul>
}

⚠ Common Mistakes

  • Importing a Server Component inside a 'use client' file; it silently becomes a Client Component
  • Creating a promise inside a Client Component render and passing it to use(); it re-creates every render
  • Wrapping the whole <body> in many providers when only one section needs them

✓ Tips & Best Practices

  • Write a thin client wrapper for any third-party component that uses hooks but lacks the directive
  • Use server-only in data modules so a wrong import fails fast
  • Prefer slots (children, sidebar) over moving data fetching into the client

Quick Summary

  • Slots — render server output inside client UI
  • Providers — one client file for context
  • Move 'use client' to the leaves
  • use(promise) — stream server data to client
