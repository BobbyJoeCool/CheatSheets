Authentication Patterns

session cookies · Auth.js · Better Auth · data access layer · verifySession() · stateless vs database sessions

Who Is the User?

Authentication in the App Router centers on a session, stored either in an encrypted stateless cookie (a signed JWT) or as a database session referenced by a cookie ID. Wrap session reading in one verifySession() function inside a Data Access Layer (DAL) and call it wherever data is read or changed.

Library Options

  • Auth.js (next-auth v5) — OAuth, email, credentials
  • Better Auth — TypeScript-first, plugins, orgs
  • Clerk / WorkOS / Kinde — hosted user management
  • Roll your own with jose + cookies()

Stateless Session + DAL

// lib/session.ts
import 'server-only'
import { SignJWT, jwtVerify } from 'jose'
import { cookies } from 'next/headers'
const key = new TextEncoder().encode(process.env.SESSION_SECRET)
export async function createSession(userId: string) {
  const token = await new SignJWT({ userId })
    .setProtectedHeader({ alg: 'HS256' }).setExpirationTime('7d').sign(key)
  ;(await cookies()).set('session', token, { httpOnly: true, secure: true,
    sameSite: 'lax', path: '/', maxAge: 60 * 60 * 24 * 7 })
}

// lib/dal.ts — imports cache (react), redirect (next/navigation)
export const verifySession = cache(async () => {
  const token = (await cookies()).get('session')?.value
  const res = token ? await jwtVerify(token, key).catch(() => null) : null
  if (!res) redirect('/login')
  const payload = res.payload
  return { userId: payload.userId as string }
})

Notes

server-only — secret code can't leak to the client
httpOnly + secure + sameSite — baseline cookie safety
cache() — verify once per request, reuse everywhere
Call createSession from a Server Action after login
Logout: (await cookies()).delete('session')

⚠ Common Mistakes

  • Checking auth only in a layout; layouts don't re-run on every navigation, and data calls bypass them
  • Storing roles or permissions in a long-lived JWT; changes don't apply until the token expires
  • Hashing passwords with a fast hash (SHA-256); use bcrypt or argon2

✓ Tips & Best Practices

  • Return a minimal { userId, role } from verifySession(); fetch the rest only when needed
  • Rotate SESSION_SECRET with a key list so old sessions still verify during rollover
  • Prefer a maintained auth library over custom crypto for OAuth flows

Quick Summary

  • Session — cookie (JWT) or DB-backed
  • verifySession() — one cached check
  • DAL — auth checks live next to data access
  • Auth.js / Better Auth — full-featured libraries
