Server Action Security

auth in every action · public endpoints · closure encryption · bodySizeLimit · allowedOrigins · validation

Treat Every Action Like an API Route

Each Server Action is reachable by a public POST request with a hard-to-guess ID. Hiding a button or protecting a page does not protect the action. Inside every action: authenticate, authorize the specific resource, validate input, and return only what the client needs.

Built-In Protections

  • Origin check: Origin must match Host
  • Unused actions are removed from the bundle
  • Action IDs are non-deterministic per build
  • Closed-over values are encrypted

A Hardened Action

'use server'
import 'server-only'
import { z } from 'zod'
import { verifySession } from '@/lib/dal'
import { forbidden } from 'next/navigation'

const Input = z.object({ projectId: z.uuid(), name: z.string().max(80) })

export async function renameProject(input: unknown) {
  const session = await verifySession()                // 1. authenticate
  const { projectId, name } = Input.parse(input)       // 2. validate
  const project = await db.project.findUnique({ where: { id: projectId } })
  if (project?.ownerId !== session.userId) forbidden() // 3. authorize
  await db.project.update({ where: { id: projectId }, data: { name } })
  updateTag(`project-${projectId}`)
  return { ok: true }                                   // 4. minimal result
}

Checklist

input: unknown — never trust the declared TS type
Check ownership of the specific row, not just login
forbidden() needs experimental.authInterrupts
Return IDs and flags, not whole DB records
Rate-limit expensive or sensitive actions

⚠ Common Mistakes

  • Relying on proxy.ts for action auth; actions POST to the page URL and matcher changes can skip them
  • Accepting a userId argument from the client instead of reading it from the session
  • Spreading formData straight into an ORM update call; attackers can set any column

✓ Tips & Best Practices

  • Set NEXT_SERVER_ACTIONS_ENCRYPTION_KEY when running multiple instances so encrypted closures decrypt everywhere
  • Put all data access in a Data Access Layer that checks auth itself
  • Log action failures with the user ID for audit trails

Quick Summary

  • Actions are public endpoints
  • Authenticate, authorize, validate — every time
  • bodySizeLimit / allowedOrigins — tune limits
  • Return DTOs, never raw records
