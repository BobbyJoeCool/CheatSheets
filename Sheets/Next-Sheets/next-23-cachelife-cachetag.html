Sheet 23

cacheLife & cacheTag

cacheLife('hours') · built-in profiles · custom profiles · cacheTag() · stale · revalidate · expire

Lifetimes and Labels

cacheLife() sets how long a 'use cache' entry stays fresh, using a profile name or an inline object with three timings: stale (client may reuse without asking), revalidate (server refreshes in the background after this), and expire (after this with no traffic, the next request waits). cacheTag() labels entries so they can be invalidated on demand.

Rules

  • Call both inside a cache scope, never at module top level
  • No cacheLife → the default profile
  • Client enforces a 30 s minimum stale time
  • expire must be longer than revalidate

Profiles, Inline, and Tags

// next.config.ts
const nextConfig: NextConfig = {
  cacheComponents: true,
  cacheLife: {
    editorial: { stale: 600, revalidate: 3600, expire: 86400 },
  },
}

// lib/posts.ts
import { cacheLife, cacheTag } from 'next/cache'
export async function getPost(slug: string) {
  'use cache'
  cacheTag('posts', `post-${slug}`)        // multiple tags allowed
  const post = await cms.post(slug)
  if (!post) { cacheLife('minutes'); return null }  // retry soon
  cacheLife('editorial')                   // custom profile
  return post
}

Notes

Custom profiles inherit missing fields from default
Conditional cacheLife is fine; only one call may run
cacheLife({ revalidate: 60 }) — inline one-off profile
Tag both the list (posts) and the item (post-x)
Profile names are type-checked after next typegen

⚠ Common Mistakes

  • Nesting a cacheLife('seconds') component inside a cached parent without its own cacheLife; the build errors
  • Wrapping cacheLife in a shared helper; keep it at the call site so behavior is readable
  • Tagging with unbounded values like timestamps; tags should map to data you can name later

✓ Tips & Best Practices

  • Use max plus tags for content that only changes on edits
  • Use hours or days for content that should refresh on its own
  • Wrap short-lived cached components in <Suspense> since they become dynamic holes

Quick Summary

  • cacheLife(profile) — stale / revalidate / expire
  • Custom profiles — cacheLife key in config
  • cacheTag(...tags) — label for invalidation
  • 30 s — minimum client stale time
