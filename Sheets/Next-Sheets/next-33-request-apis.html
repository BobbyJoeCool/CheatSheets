Sheet 33

Request-Time APIs

cookies() · headers() · draftMode() · connection() · after() · all async

Reading the Incoming Request

Server Components, Server Actions, and Route Handlers read request data through functions from next/headers and next/server. Since Next.js 16 they are async only: always await them. Calling any of them makes that part of the tree render at request time, so wrap it in <Suspense> when using Cache Components.

Where Writes Are Allowed

  • cookies().set/delete — Server Actions, Route Handlers
  • Not in Server Components (headers already sent)
  • draftMode().enable() — Route Handlers or Actions
  • after() — anywhere on the server

Using Each API

import { cookies, headers, draftMode } from 'next/headers'
import { connection, after } from 'next/server'

const store = await cookies()
store.get('theme')?.value                     // 'dark'
store.has('session')                          // true
store.set('theme', 'light', { httpOnly: true, maxAge: 60 * 60 * 24 })
store.delete('session')                       // Actions / handlers only

const h = await headers()
h.get('user-agent')                           // 'Mozilla/5.0 …'
h.get('x-forwarded-for')                      // client IP behind proxy

const { isEnabled } = await draftMode()       // CMS preview on?
await connection()                            // force request-time render

after(async () => {                           // runs after response is sent
  await analytics.track('page_view', { path: '/pricing' })
})

Notes

Every call returns a Promise in 16 (sync access removed)
headers() is read-only; set response headers elsewhere
draftMode bypasses 'use cache' while enabled
after() — logging without slowing the user down
None of these can run inside 'use cache'

⚠ Common Mistakes

  • Setting cookies from a Server Component; it throws because streaming has already started
  • Forgetting await (cookies().get(...)); in 16 that's a type and runtime error
  • Reading headers() in a shared layout and making every page dynamic

✓ Tips & Best Practices

  • Read cookies outside 'use cache' functions and pass plain values in
  • Use after() for audit logs and cache warming after a mutation
  • Run npx @next/codemod@canary next-async-request-api . on older code

Quick Summary

  • await cookies() — read/write cookies
  • await headers() — read request headers
  • await connection() — opt into request time
  • after(fn) — work after the response
