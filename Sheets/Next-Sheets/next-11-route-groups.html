Sheet 11

Route Groups & Private Folders

(group) · multiple root layouts · _folder · opt out of layouts · feature folders

Organizing Without Changing URLs

A folder wrapped in parentheses, (marketing), is a route group: it organizes files and can hold its own layout.tsx, but its name never appears in the URL. A folder prefixed with an underscore, _components, is private: the router ignores it and everything inside it.

Uses

  • Give sections different layouts ((shop) vs (admin))
  • Create multiple root layouts with separate <html>
  • Keep a page out of a shared layout
  • Group by team or feature

Two Sections, Two Layouts

app/
├─ (marketing)/
│  ├─ layout.tsx           # header + footer
│  ├─ page.tsx             # /
│  └─ pricing/page.tsx     # /pricing
├─ (app)/
│  ├─ layout.tsx           # sidebar shell, auth check
│  ├─ dashboard/page.tsx   # /dashboard
│  └─ settings/page.tsx    # /settings
├─ (auth)/login/page.tsx   # /login — no header, no sidebar
├─ _components/Button.tsx  # private, never routed
└─ _lib/db.ts              # private

Reading It

No root app/layout.tsx here: each group's layout is a root layout
Each root layout must render <html> and <body>
/login skips both shells because (auth) has no layout
Navigating between root layouts causes a full page load
_components keeps shared UI next to routes safely

Conflicts to Avoid

MistakeResult
(a)/about + (b)/aboutBuild error: same URL
Two groups both with page.tsx at rootBuild error for /
Root layout missing <html>Runtime error
Layout in group above pageApplies to that group only

⚠ Common Mistakes

  • Resolving two pages to the same URL from different groups; Next.js fails the build
  • Forgetting <html>/<body> in each layout once the top-level root layout is removed
  • Expecting _folder to work as a URL; use %5Ffolder if you really need a leading underscore

✓ Tips & Best Practices

  • Use (app) for authenticated areas so the auth-aware shell lives in one layout
  • Name groups by audience or feature, not by implementation detail
  • Private folders are optional: only page and route are ever public anyway

Quick Summary

  • (group) — organize; not part of the URL
  • Group layouts — different shells per section
  • Multiple root layouts — full reload between them
  • _folder — opt out of routing
