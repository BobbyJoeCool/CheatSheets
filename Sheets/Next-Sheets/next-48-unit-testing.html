Unit & Component Testing

Vitest · Jest with next/jest · React Testing Library · async Server Component limits · mocking next/navigation

Fast Tests for Logic and UI

Use Vitest or Jest with React Testing Library for unit and component tests. Synchronous Server and Client Components can be rendered in jsdom. Async Server Components aren't supported by these tools yet, so test their data functions directly and cover full pages with end-to-end tests.

What to Unit Test

  • DAL / data functions (mock the DB)
  • Server Actions as plain async functions
  • Client Components and hooks
  • Pure utilities (formatters, validators)

Vitest Setup

// vitest.config.mts
import { defineConfig } from 'vitest/config'
import react from '@vitejs/plugin-react'
import tsconfigPaths from 'vite-tsconfig-paths'

export default defineConfig({
  plugins: [tsconfigPaths(), react()],
  test: { environment: 'jsdom',
          setupFiles: ['./vitest.setup.ts'] },
})

// vitest.setup.ts
import '@testing-library/jest-dom/vitest'

// package.json → "test": "vitest"

Component Test + Router Mock

import { render, screen } from '@testing-library/react'
import userEvent from '@testing-library/user-event'
import { vi, test, expect } from 'vitest'
import { SortSelect } from './sort-select'

const replace = vi.fn()
vi.mock('next/navigation', () => ({
  useRouter: () => ({ replace }),
  useSearchParams: () => new URLSearchParams('sort=new'),
  useParams: () => ({ category: 'shoes' }),
}))

test('updates the sort param', async () => {
  render(<SortSelect />)
  const select = screen.getByRole('combobox')
  await userEvent.selectOptions(select, 'price')
  expect(replace).toHaveBeenCalledWith('?sort=price')
})

⚠ Common Mistakes

  • Rendering an async Server Component with RTL; it isn't supported, so test its data function or use E2E
  • Forgetting to mock next/navigation; hooks throw outside the App Router context
  • Importing a module with server-only in jsdom tests without aliasing it to an empty file

✓ Tips & Best Practices

  • Test Server Actions by calling them directly with a built FormData
  • Use screen.getByRole queries; they match how users find elements
  • Keep unit tests for logic and leave page wiring to Playwright

Quick Summary

  • Vitest / Jest + RTL — component tests
  • Async RSC — test data functions or E2E
  • vi.mock('next/navigation') — router mocks
  • next/jest — preconfigured Jest
