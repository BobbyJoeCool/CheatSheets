Server Actions Basics

'use server' · <form action={fn}> · FormData · actions.ts · client calls · redirect()

Functions That Run on the Server

A Server Action (Server Function) is an async function marked with 'use server'. Pass it to <form action> or call it from a Client Component, and Next.js sends a POST request, runs it on the server, and returns the result. Actions are the App Router's way to handle mutations without writing API routes.

Basics

  • Forms work before JS loads (progressive enhancement)
  • Arguments and return values must be serializable
  • Run one at a time per client (sequential queue)
  • Usually end with updateTag, revalidatePath, or redirect

Action File + Form

// app/todos/actions.ts
'use server'                          // every export is an action
import { updateTag } from 'next/cache'
import { redirect } from 'next/navigation'

export async function createTodo(formData: FormData) {
  const user = await requireUser()   // always authorize
  const title = String(formData.get('title') ?? '').trim()
  const todo = await db.todo.create({ data: { title, userId: user.id } })
  updateTag(`todos-${user.id}`)
  redirect(`/todos/${todo.id}`)      // throws; call last
}

// app/todos/new/page.tsx  (Server Component)
import { createTodo } from '../actions'
export default function NewTodo() {
  return <form action={createTodo}><input name="title" /></form>
}

Notes

File-level 'use server' — every export becomes an action
formData.get() — read fields by name attribute
redirect() in an action responds with 303
Call redirect outside try/catch, after the write

Inline Action + Bound Args

export default async function Post({ id }: Props) {
  async function like() {
    'use server'           // inline action
    await db.like.create({ data: { postId: id } })
  }
  const remove = deletePost.bind(null, id) // bind
  return <>
    <form action={like}><button>♥</button></form>
    <form action={remove}><button>Delete</button></form>
  </>
}

⚠ Common Mistakes

  • Skipping authorization because the form is on a protected page; actions are public POST endpoints
  • Calling redirect() inside try; the thrown redirect is caught and never happens
  • Defining 'use server' functions inside Client Components; define them in a separate file and import

✓ Tips & Best Practices

  • Keep actions in actions.ts files per feature so they're easy to audit
  • Use .bind(null, id) to pass IDs; bound args are encrypted, unlike hidden inputs
  • Return plain objects ({ ok, error }) for expected errors instead of throwing

Quick Summary

  • 'use server' — marks Server Actions
  • <form action={fn}> — progressive enhancement
  • FormData — input values by name
  • Finish with updateTag or redirect
