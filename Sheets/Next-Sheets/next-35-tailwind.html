Tailwind CSS

Tailwind v4 · @import "tailwindcss" · @tailwindcss/postcss · @theme · dark mode · tailwind-merge

Utility-First Styling

create-next-app sets up Tailwind CSS v4 by default. Version 4 is configured in CSS rather than JavaScript: one @import "tailwindcss" line loads everything, and design tokens live in an @theme block. Classes are generated on demand from your source files, so only what you use ships.

v4 vs v3

  • No tailwind.config.js required
  • PostCSS plugin is @tailwindcss/postcss
  • No @tailwind base/components/utilities lines
  • Source files are detected automatically

Setup Files

/* postcss.config.mjs:
   plugins: { '@tailwindcss/postcss': {} } */

/* app/globals.css */
@import "tailwindcss";

@theme {
  --color-brand: #5c6bc0;
  --font-sans: var(--font-inter);   /* from next/font */
  --breakpoint-3xl: 120rem;
}

@custom-variant dark (&:where(.dark, .dark *));

Using It

// bg-brand, font-sans, 3xl: now exist
export function Card({ title, featured }: Props) {
  return (
    <div className={cn(
      'rounded-lg p-4 shadow bg-white dark:bg-zinc-900',
      'md:p-6 3xl:p-10',
      featured && 'ring-2 ring-brand')}>
      <h2 className="font-sans text-lg font-semibold">
        {title}</h2>
    </div>
  )
}

// lib/utils.ts
import { clsx, type ClassValue } from 'clsx'
import { twMerge } from 'tailwind-merge'
export const cn = (...c: ClassValue[]) => twMerge(clsx(c))

⚠ Common Mistakes

  • Building class names with template strings (bg-${color}-500); the scanner can't see them, so they're never generated
  • Keeping v3 @tailwind directives after upgrading; v4 uses a single @import
  • Merging conflicting utilities with plain clsx; the last class in the CSS file wins, not the last in the string

✓ Tips & Best Practices

  • Map props to complete class strings ({ red: 'bg-red-500' }) for dynamic styling
  • Use the cn() helper so component callers can override classes safely
  • Install the Tailwind IntelliSense editor extension for autocomplete
