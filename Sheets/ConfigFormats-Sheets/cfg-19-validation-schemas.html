Catch Bad Config Before It Ships

A JSON Schema describes which keys a config file may have and what type each value must be. Despite the name, editors and tools apply it to YAML and TOML too. SchemaStore.org hosts schemas for hundreds of common files (workflows, compose, tsconfig, pyproject), and VS Code, JetBrains IDEs and Taplo use it automatically. In CI, check-jsonschema, yamllint, taplo check and actionlint fail the build on invalid config.

Notes

  • Many files get a schema from SchemaStore by file name with no setup
  • Point a file at a schema with $schema (JSON), a modeline comment (YAML) or #:schema (Taplo)
  • Validate your own app config with a schema or a typed loader (Pydantic, Zod)
  • The JSON set covers writing schemas

Linking Files to Schemas

# JSON: a "$schema" key
{ "$schema": "https://json.schemastore.org/package.json" }

# YAML: modeline comment (Red Hat YAML extension)
# yaml-language-server: $schema=https://json.schemastore.org/github-workflow.json
name: CI

# TOML: Taplo directive at the top of the file
#:schema ./schemas/app-config.schema.json
[server]
port = 8080

# CI checks
check-jsonschema --builtin-schema vendor.github-workflows .github/workflows/*.yml
check-jsonschema --schemafile schemas/app.json config/*.yaml
yamllint -d relaxed .
taplo check pyproject.toml
actionlint

Code Explained

The modeline comment works in any editor using the YAML language server
check-jsonschema validates JSON, YAML and TOML files against a schema
--builtin-schema ships common SchemaStore schemas offline
yamllint checks YAML style and traps; schemas check structure

Same Data In…

  • JSON Schema in YAML type: object / required: [port] / properties: {port: {type: integer}}
  • Pydantic class Settings(BaseSettings): port: int = 8080

Gotcha

  • A schema only catches what it describes; unknown keys pass unless the schema sets additionalProperties: false
  • Editors may cache SchemaStore schemas; a brand-new key can show as an error until they update

⚠ Common Mistakes

  • Relying on CI failures to find a typo a schema would have shown in the editor
  • Writing a schema without additionalProperties: false, so misspelled keys pass
  • Validating config only in CI, not when the app starts

✓ Tips & Best Practices

  • Add the YAML modeline to files SchemaStore can't match by name
  • Run validators in pre-commit so mistakes never reach a branch
  • Generate the schema from your typed config class (Pydantic model_json_schema())

Quick Summary
