The Manifest of Every Node Project

package.json describes a JavaScript package: its name and version, the scripts you run with npm run, the dependencies it installs, and how other code imports it (exports, type). It is strict JSON. npm, pnpm, Yarn and Bun all read it; the exact installed versions live in the lock file next to it.

Notes

  • npm pkg get version / npm pkg set scripts.lint="eslint ." edit it safely
  • "type": "module" makes .js files ES modules
  • devDependencies are only for building and testing
  • The Node set covers npm commands in depth

package.json

{
  "name": "@acme/orders",
  "version": "1.4.0",
  "type": "module",
  "private": true,
  "engines": { "node": ">=22" },
  "scripts": {
    "dev": "vite",
    "build": "tsc -b && vite build",
    "test": "vitest run",
    "lint": "eslint ."
  },
  "dependencies": {
    "express": "^5.1.0",
    "zod": "~4.1.0"
  },
  "devDependencies": {
    "typescript": "5.9.3",
    "vitest": "^5.1.0"
  },
  "exports": { ".": "./dist/index.js" }
}

Code Explained

^5.1.0 allows 5.x updates (≥5.1.0 <6.0.0); ~4.1.0 allows patches only (<4.2.0)
An exact version (5.9.3) never moves; the lock file pins the rest
"private": true stops accidental npm publish
exports controls what import "@acme/orders" resolves to

Same Data In…

  • pyproject.toml [project] / dependencies = ["fastapi>=0.115"] / [project.scripts]
  • Maven <dependency> blocks · Gradle implementation("…")

Gotcha

  • ^0.2.3 only allows 0.2.x: caret ranges are stricter below 1.0.0
  • Scripts run with node_modules/.bin on PATH, so vitest works there but not in your shell

⚠ Common Mistakes

  • Putting build tools in dependencies, so they ship to production
  • Deleting the lock file to "fix" an install and getting different versions everywhere
  • Adding comments; strict JSON fails to parse

✓ Tips & Best Practices

  • Use npm pkg set in scripts instead of hand-editing with sed
  • Pin the Node version in engines and .nvmrc (sheet 18)
  • Use npm ci in CI so the lock file is followed exactly

Quick Summary

  • scripts — npm run <name>
  • ^ — minor updates · ~ — patch updates
  • devDependencies — build / test only
  • lock file — exact versions
