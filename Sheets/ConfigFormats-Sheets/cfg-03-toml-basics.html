TOML Basics

key = value · bare / quoted / dotted keys · strings · integers / floats · booleans · comments # · UTF-8

Obvious Keys, Explicit Types

TOML (Tom's Obvious Minimal Language) is key = value pairs grouped into tables. Every value has a clear type: strings are always quoted, numbers and booleans never are. There is exactly one way to read each line, which avoids YAML-style guessing. Files must be valid UTF-8; comments start with #.

Notes

  • Keys are case-sensitive
  • Bare keys: A-Z a-z 0-9 _ -; anything else needs quotes
  • A key can be defined only once per table
  • Current spec: TOML 1.1.0 (Dec 2025); most parsers read 1.0

Parse It

  • Python tomllib.load(open("x.toml", "rb")) (3.11+, read-only)
  • JavaScript import { parse } from "smol-toml"
  • Java new TomlMapper().readTree(file) (Jackson)

Values and Keys

title = "Orders API"          # string (always quoted)
port = 8080                   # integer
ratio = 0.75                  # float
debug = false                 # boolean (lowercase only)
big = 1_000_000               # underscores for readability
mask = 0xFF                   # hex   (also 0o755, 0b1010)
nan_ok = nan                  # also inf, -inf

"key with spaces" = 1         # quoted key
server.host = "0.0.0.0"       # dotted key → table "server"
server.port = 8080

# empty values don't exist: omit the key instead
# port =        ← error

Code Explained

Strings need quotes; title = Orders API is an error, not a string
Dotted keys create nested tables, same as writing a [server] table
There is no null; leave the key out to mean "not set"
Numbers keep their type: 8080 is an integer, 8080.0 is a float

Same Data In…

  • JSON {"title": "Orders API", "port": 8080, "server": {"host": "0.0.0.0"}}
  • YAML title: Orders API · port: 8080 · server: {host: 0.0.0.0}

Gotcha

  • Defining port twice, even with the same value, is a parse error
  • True and FALSE are errors; booleans are lowercase true / false only

⚠ Common Mistakes

  • Leaving strings unquoted because INI and YAML allow it
  • Writing key = null; TOML has no null value
  • Saving the file in a non-UTF-8 encoding from an old editor

✓ Tips & Best Practices

  • Use underscores in big numbers (timeout_ms = 30_000) to make them readable
  • Prefer dotted keys for one or two settings and [table] headers for groups
  • Run taplo fmt or your editor's TOML formatter to keep spacing consistent

Quick Summary

  • key = value — one per line
  • strings quoted, numbers / booleans not
  • dotted keys — nested tables
  • no null — omit the key
