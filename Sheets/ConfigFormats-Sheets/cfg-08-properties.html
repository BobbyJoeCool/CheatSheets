Java .properties Files

key=value · : and space separators · \ line continuation · escapes · encoding (UTF-8 vs ISO-8859-1) · Spring application.properties

Flat Keys for the JVM

A .properties file is the standard Java way to store settings and translations: one key=value per line, flat, all strings. Nesting is faked with dotted keys (spring.datasource.url). The separator can be =, : or whitespace; comments start with # or !. Spring Boot, Gradle (gradle.properties), Maven filtering and Java ResourceBundle i18n all use it.

Notes

  • Leading whitespace before keys and values is ignored
  • A \ at line end continues the value on the next line
  • Lists are a convention: a.b[0]=x (Spring) or comma-separated values
  • The Java set covers java.util.Properties in code

Parse It

  • Python jproperties: Properties().load(f, "utf-8")
  • JavaScript properties-reader("app.properties").get("server.port")
  • Java props.load(Files.newBufferedReader(path)) (UTF-8)

application.properties

# Server
server.port=8080
server.servlet.context-path=/api

! "!" starts a comment too
spring.datasource.url=jdbc:postgresql://db:5432/orders
spring.datasource.username=${DB_USER:app}
spring.datasource.password=${DB_PASSWORD}

# Spaces around "=" are trimmed
app.greeting = Hello, World
# Oops: everything after "=" is the value, "# dev" included
app.mode=fast # dev
app.cors.allowed-origins=https://a.example,https://b.example
app.servers[0]=web-1
app.servers[1]=web-2
app.long-text=This value goes on \
              across two lines
# Backslashes must be doubled
app.path=C:\\data\\orders

Code Explained

${DB_USER:app} is Spring placeholder syntax with a default; plain Properties doesn't expand it
Comments must start the line: # … after a value becomes part of the value
Spring binds app.servers[0] and comma lists into List<String> fields
A continued line drops the leading spaces on the next line

Same Data In…

  • YAML (application.yml) spring: / datasource: / url: jdbc:postgresql://db:5432/orders
  • .env SPRING_DATASOURCE_URL=jdbc:… (Spring's relaxed binding maps it)
  • TOML [spring.datasource] / url = "jdbc:…"

Gotcha

  • Properties.load(InputStream) reads ISO-8859-1; non-Latin text needs load(Reader) with UTF-8 or \uXXXX escapes
  • There are no inline comments; port=8080 # dev sets port to "8080 # dev"

Syntax Rules

WriteMeans
key=valueStandard form
key: value / key valueAlso valid separators
# or ! at line startComment
\ at line endContinue value
\=, \:, \ (space)Literal separator in a key
\uXXXXUnicode character

⚠ Common Mistakes

  • Adding # comment after a value on the same line
  • Single backslashes in Windows paths; \d becomes d
  • Saving non-ASCII text and reading it with the InputStream overload

✓ Tips & Best Practices

  • Keep one profile file per environment (application-prod.properties) and secrets in env vars
  • Sort keys and group them with blank lines and comments; the file has no structure otherwise
  • Prefer application.yml in Spring when the keys get deep and repetitive

Quick Summary

  • key=value — flat strings
  • dotted keys — fake nesting
  • \ — continuation and escapes
  • encoding — use a UTF-8 Reader
