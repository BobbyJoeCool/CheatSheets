pyproject.toml

[project] · dependencies · [build-system] · [project.scripts] · [tool.*] (ruff · pytest · mypy) · dependency groups

One File for a Python Project

pyproject.toml is the standard Python project file. [project] holds metadata and dependencies (PEP 621); [build-system] names the build backend; [dependency-groups] (PEP 735) holds dev-only groups; and [tool.<name>] tables configure tools such as Ruff, pytest, mypy, coverage and uv. It replaces setup.py, setup.cfg, requirements-dev.txt and most tool-specific config files.

Notes

  • Dependencies use PEP 508 strings: "httpx>=0.27", "rich[jupyter]"
  • uv, pip, Poetry 2, Hatch and PDM all read [project]
  • license = "MIT" is an SPDX expression (PEP 639)
  • The Python and pytest sets cover the tools themselves

Parse It

  • Python tomllib.load(open("pyproject.toml", "rb"))["project"]["version"]
  • JavaScript parse(readFileSync("pyproject.toml", "utf8")) (smol-toml)
  • Java Toml.parse(path).getString("project.version") (tomlj)

pyproject.toml

[project]
name = "orders"
version = "1.4.0"
requires-python = ">=3.12"
license = "MIT"
dependencies = [
  "fastapi>=0.115",
  "pydantic-settings>=2.6",
]

[project.optional-dependencies]
postgres = ["psycopg[binary]>=3.2"]

[project.scripts]
orders = "orders.cli:main"      # installs an `orders` command

[dependency-groups]
dev = ["pytest>=9", "ruff>=0.14", "mypy>=1.18"]

[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[tool.ruff]
line-length = 100

[tool.pytest]                   # pytest 9 native TOML
testpaths = ["tests"]

Code Explained

optional-dependencies are extras users opt into: pip install orders[postgres]
dependency-groups are for development and never published
[project.scripts] creates a console command when the package is installed
pytest 9 reads [tool.pytest]; older versions need [tool.pytest.ini_options]

Same Data In…

  • package.json "dependencies" · "devDependencies" · "bin" · "scripts"
  • Cargo.toml [package] · [dependencies] · [dev-dependencies]

Gotcha

  • Tools that read a missing [tool.x] table fall back to their own files or defaults silently
  • requires-python is checked at install time, not when you run the code

⚠ Common Mistakes

  • Putting pytest and Ruff in dependencies, so they install for users
  • Keeping both setup.py and [project] metadata and letting them drift
  • Writing [tool.pytest] with pytest 8 or older, which ignores it

✓ Tips & Best Practices

  • Let uv add / uv add --dev edit the file and the lock file together
  • Move tool configs (.flake8, pytest.ini, .coveragerc) into [tool.*] tables
  • Use requires-python to stop installs on unsupported versions

Quick Summary

  • [project] — metadata + dependencies
  • [dependency-groups] — dev-only deps
  • [build-system] — how to build
  • [tool.*] — every tool's settings
