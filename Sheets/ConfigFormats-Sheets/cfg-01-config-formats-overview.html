Sheet 01

Config Formats at a Glance

JSON · YAML · TOML · INI · .properties · .env · XML · who uses which

Same Job, Different Rules

A config file holds settings a program reads at start-up. Every format here stores keys and values; they differ in types (is 8080 a number or text?), nesting, comments and how strict the parser is. Most of the time the tool picks the format for you: npm uses JSON, Python packaging uses TOML, Docker Compose and CI use YAML, Java uses .properties.

Notes

  • JSON, YAML and XML have full sets of their own in Markup & Notation
  • This set covers TOML, INI, .properties, .env and the files built on them
  • Typed formats: JSON, YAML, TOML · strings-only: INI, .properties, .env
  • Read sheet 02 when you get to choose the format yourself

One Setting, Six Formats

# TOML                      # INI
[server]                    [server]
host = "0.0.0.0"            host = 0.0.0.0
port = 8080                 port = 8080
debug = false               debug = false

# .properties               # .env
server.host=0.0.0.0         SERVER_HOST=0.0.0.0
server.port=8080            SERVER_PORT=8080
server.debug=false          SERVER_DEBUG=false

# YAML                      # JSON
server:                     {"server": {"host": "0.0.0.0",
  host: 0.0.0.0               "port": 8080, "debug": false}}
  port: 8080
  debug: false

Code Explained

TOML, YAML and JSON parse 8080 as a number and false as a boolean
INI, .properties and .env hand everything back as text; your code converts it
.properties and .env flatten nesting into dotted or UPPER_SNAKE names
Only JSON lacks comments; every other format here allows them

Same Data In…

  • XML <server host="0.0.0.0" port="8080" debug="false"/>
  • HCL server { host = "0.0.0.0" port = 8080 } (Terraform)
  • Env var SERVER__PORT=8080 (double underscore = nesting in .NET)

Gotcha

  • The same value can be a number in one format and a string in another; check types after a conversion
  • YAML reads 0.0.0.0 as a string but 1.0 as a float; quote values you mean as text

⚠ Common Mistakes

  • Assuming every format has types; reading port from .env gives "8080", not 8080
  • Writing comments in a .json file a strict parser reads (npm, JSON.parse)
  • Picking YAML for a deep config just because it looks clean, then fighting indentation errors

✓ Tips & Best Practices

  • Use the format the tool expects; don't invent a second config file next to it
  • Convert strings from INI / .env / .properties once, at start-up, with validation
  • Keep one source of truth and generate other formats from it if you must

Quick Summary

  • typed — JSON, YAML, TOML
  • strings-only — INI, .properties, .env
  • comments — everything but JSON
  • tool decides — follow its format
