YAML for Config — Traps

implicit typing (NO, on, 010, 1e3) · YAML 1.1 vs 1.2 · quoting rules · indentation · anchors for DRY config · safe loading

Readable Until It Guesses Wrong

YAML guesses types from how a value looks. In YAML 1.1 (PyYAML, SnakeYAML, many older tools), yes, no, on, off are booleans, 010 is octal and 22:30 is a base-60 number. YAML 1.2 fixed most of this, but your tool may not use it. The safe habit: quote anything that isn't obviously a number or true / false. This page is the config-file checklist; the YAML set covers the full language.

Notes

  • Indentation must be spaces, never tabs
  • Use yaml.safe_load, never yaml.load on untrusted input
  • Anchors & / aliases * / merge <<: remove repetition
  • GitHub Actions treats on: as a key because its parser is not YAML 1.1 strict

Parse It

  • Python yaml.safe_load(f) (PyYAML, YAML 1.1) · ruamel.yaml (1.2, keeps comments)
  • JavaScript import YAML from "yaml"; YAML.parse(text) (1.2)
  • Java SnakeYAML new Yaml(new SafeConstructor(new LoaderOptions()))

Values YAML Changes Behind Your Back

country: NO          # 1.1: false   → write "NO"
enabled: on          # 1.1: true    → write "on" or true
version: 1.10        # float 1.1    → write "1.10"
zip: 01234           # 1.1: octal 668 → write "01234"
time: 22:30          # 1.1: 1350 (base 60) → write "22:30"
size: 1e3            # 1.2: float 1000.0; 1.1: string
id: 0x1F             # 31
empty:               # null, not ""
tilde: ~             # null
token: ${API_TOKEN}  # just a string; YAML has no env expansion

# DRY with anchors and merge keys
defaults: &defaults
  retries: 3
  timeout: 30
service_a:
  <<: *defaults
  timeout: 60        # override one key

Code Explained

Every "fix" is the same: quote it
version: 1.10 loses the trailing zero because it becomes the float 1.1
An empty value is null; write "" for an empty string
${API_TOKEN} only works if the tool (Compose, Actions) expands it; plain YAML doesn't

Same Data In…

  • TOML country = "NO" · version = "1.10" · time = 22:30:00 (typed, no guessing)
  • JSON {"country": "NO", "version": "1.10"}

Gotcha

  • yaml.load(text) without a safe loader can construct arbitrary Python objects from tagged input
  • Merge keys <<: are YAML 1.1; some 1.2-only parsers reject or ignore them

⚠ Common Mistakes

  • Unquoted country codes, versions, ZIP codes and times
  • Tabs for indentation, copied from another file
  • Assuming ${VAR} expands in every YAML file

✓ Tips & Best Practices

  • Quote every string that could look like a number, boolean or date
  • Run yamllint in CI with truthy and octal-values rules on
  • Use a schema (sheet 19) so the editor flags wrong types as you type

Quick Summary

  • quote it — the fix for most traps
  • 1.1 vs 1.2 — know your parser
  • safe_load — never load
  • & / * / <<: — DRY config
