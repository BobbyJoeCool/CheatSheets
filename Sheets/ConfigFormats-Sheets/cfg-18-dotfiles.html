Project Dotfiles

.editorconfig · .gitignore patterns · .gitattributes · .npmrc · .nvmrc / .python-version · .prettierrc

Small Files That Set Project Rules

Most repos carry a handful of dotfiles at the root. .editorconfig sets indentation and line endings for every editor; .gitignore and .gitattributes tell Git what to skip and how to treat files; .npmrc configures npm; .nvmrc and .python-version pin the runtime version; .prettierrc holds formatter rules. Each is tiny, and each saves a class of "works on my machine" problems.

Notes

  • Formats vary: .editorconfig is INI-like, .gitignore is glob lines, .prettierrc is JSON or YAML
  • Most tools search parent folders until they find the file
  • root = true in .editorconfig stops that search
  • The Git set covers .gitignore and .gitattributes in depth

Five Dotfiles

# .editorconfig
root = true
[*]
indent_style = space
indent_size = 2
end_of_line = lf
insert_final_newline = true
[*.py]
indent_size = 4

# .gitattributes
* text=auto eol=lf
*.png binary
*.sh text eol=lf

# .gitignore
node_modules/
dist/
.env
!.env.example

# .npmrc
save-exact=true
engine-strict=true

# .nvmrc          → 22
# .python-version → 3.13

Code Explained

[*] applies to every file; later sections like [*.py] override it
* text=auto eol=lf normalizes line endings in the repo, whatever the OS
!.env.example re-includes a file a previous pattern ignored
engine-strict makes npm refuse to install on the wrong Node version

Same Data In…

  • VS Code settings "editor.tabSize": 2 · "files.eol": "\n" (editor-only, unlike .editorconfig)
  • package.json "engines": { "node": ">=22" } (pairs with .nvmrc)

Gotcha

  • .gitignore does nothing for files already tracked; git rm --cached them first
  • VS Code needs the EditorConfig extension; JetBrains IDEs read .editorconfig out of the box

⚠ Common Mistakes

  • Committing node_modules or build output because .gitignore was added too late
  • Mixed CRLF / LF line endings because there's no .gitattributes
  • Different Node versions per developer with no .nvmrc

✓ Tips & Best Practices

  • Start new repos with GitHub's .gitignore templates for your stack
  • Add .editorconfig even if you also use Prettier; it covers files Prettier skips
  • Pin runtime versions in dotfiles and in CI from the same value

Quick Summary

  • .editorconfig — indentation and line endings
  • .gitignore / .gitattributes — what Git skips and normalizes
  • .npmrc — npm settings
  • .nvmrc / .python-version — pin the runtime
