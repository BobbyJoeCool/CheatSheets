Sheet 04

TOML Tables & Inline Tables

[table] · dotted-key tables · [a.b.c] · inline { } tables · multi-line inline tables (1.1) · defining a table once

Headers Group the Keys Below Them

A table header [name] starts a group; every key until the next header belongs to it. Nest with dots: [tool.ruff.lint]. An inline table { key = value, … } writes a small table on one line. TOML 1.1 lets inline tables span several lines with a trailing comma, which used to be the format's biggest annoyance.

Notes

  • [a.b.c] creates a and a.b automatically if they don't exist
  • Whitespace and indentation inside tables don't matter
  • An inline table is complete; you can't add keys to it later
  • A table can be defined only once

pyproject-style Tables

[project]
name = "orders"
version = "1.4.0"

[tool.ruff]
line-length = 100

[tool.ruff.lint]
select = ["E", "F", "I"]

[tool.ruff.lint.per-file-ignores]
"tests/*" = ["S101"]

# inline table (one line in TOML 1.0)
point = { x = 1, y = 2 }

# TOML 1.1: multi-line inline table, trailing comma OK
author = {
  name = "Bob",
  email = "bob@example.com",
}

Code Explained

[tool.ruff.lint] is the table tool → ruff → lint
Keys under a header belong to it until the next header, regardless of indentation
Quoted keys like "tests/*" hold paths and globs
Multi-line inline tables only parse with TOML 1.1 parsers; keep them on one line for 1.0 tools

Same Data In…

  • JSON {"tool": {"ruff": {"line-length": 100, "lint": {"select": ["E", "F", "I"]}}}}
  • YAML tool: / ruff: / line-length: 100 / lint: {select: [E, F, I]}

Gotcha

  • [tool.ruff] twice in one file is an error; merge the keys under one header
  • After point = { x = 1 }, writing [point] or point.z = 3 is an error

Three Ways to Write a Table

FormExample
Header[server] host = "x"
Dotted keyserver.host = "x"
Inlineserver = { host = "x" }
Nested header[server.tls] enabled = true

Table Rules

RuleResult
Same header twiceError
Header after dotted keys made itError
Super-table defined laterAllowed
Keys after an inline tableError
Empty table [x]Allowed

⚠ Common Mistakes

  • Expecting indentation to show nesting; only headers and dots do
  • Adding a key to an inline table further down the file
  • Using TOML 1.1 multi-line inline tables in a file a 1.0 parser (pip, older tools) reads

✓ Tips & Best Practices

  • Order tables from general to specific: [tool.ruff] before [tool.ruff.lint]
  • Use inline tables for small, fixed shapes like { x = 1, y = 2 }
  • Indent keys under headers if it helps you read; parsers ignore it

Quick Summary

  • [a.b] — nested table header
  • { k = v } — inline table
  • TOML 1.1 — multi-line inline tables
  • each table defined once
