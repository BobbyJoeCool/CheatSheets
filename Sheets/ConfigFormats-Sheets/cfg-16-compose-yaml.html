Sheet 16

compose.yaml (Docker Compose)

services · image / build · ports · environment / env_file · volumes · depends_on · profiles

A Local Stack in One File

compose.yaml defines the services (containers) of an app and how they connect: which image or Dockerfile each uses, published ports, environment, volumes and start order. docker compose up starts it all. Compose reads a .env file next to it for ${VAR} interpolation, which is separate from the environment passed into containers.

Notes

  • The top-level version: key is obsolete; leave it out
  • Services reach each other by service name (db:5432)
  • compose.override.yaml is merged automatically for local tweaks
  • The Docker set covers Compose commands in depth

compose.yaml

services:
  api:
    build: .
    ports:
      - "8080:3000"                 # host:container (quote it!)
    env_file: .env                  # into the container
    environment:
      DATABASE_URL: postgres://app:${DB_PASSWORD}@db:5432/orders
      LOG_LEVEL: ${LOG_LEVEL:-info} # interpolated from .env / shell
    depends_on:
      db:
        condition: service_healthy
  db:
    image: postgres:17
    environment:
      POSTGRES_PASSWORD: ${DB_PASSWORD:?set DB_PASSWORD}
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
  adminer:
    image: adminer
    profiles: [tools]               # only with --profile tools
volumes:
  pgdata:

Code Explained

${VAR:-default} uses a default; ${VAR:?message} stops with an error if unset
env_file passes variables into the container; .env interpolation fills in the YAML itself
condition: service_healthy waits for the healthcheck, not just container start
Named volume pgdata keeps data between down and up

Same Data In…

  • Kubernetes Deployment + Service + PersistentVolumeClaim (see the Kubernetes set)
  • docker run docker run -p 8080:3000 --env-file .env myapi

Gotcha

  • Unquoted - 22:22 can be read as a base-60 number by YAML 1.1 parsers; always quote port mappings
  • Changing .env needs docker compose up -d again; running containers keep old values

Commands

CommandDoes
docker compose up -dStart in background
docker compose configPrint the merged, interpolated file
docker compose logs -f apiFollow logs
docker compose down -vStop and delete volumes
--profile tools upInclude optional services

⚠ Common Mistakes

  • Putting passwords directly in compose.yaml and committing it
  • Expecting depends_on alone to wait until the database accepts connections
  • Using down -v and losing the database volume by accident

✓ Tips & Best Practices

  • Run docker compose config to see exactly what Compose will use after interpolation
  • Use ${VAR:?message} for required secrets so a missing one fails loudly
  • Keep dev-only services behind profiles

Quick Summary

  • services — one container each
  • ${VAR:-default} — interpolation from .env
  • env_file — env inside the container
  • depends_on + healthcheck — real start order
