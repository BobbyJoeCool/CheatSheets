Strict JSON and Its Friendlier Cousins

Plain JSON has no comments and no trailing commas, which is fine for files programs write and painful for files people edit. Two relaxed variants exist: JSONC (JSON with comments, used by VS Code settings and tsconfig.json) and JSON5 (comments, trailing commas, unquoted keys, single quotes). Whether a file accepts them depends entirely on the tool reading it.

Notes

  • package.json is strict JSON: a comment breaks npm
  • A "$schema" key points editors at a JSON Schema for autocomplete and checks
  • Babel (babel.config.json5), Renovate and others accept JSON5
  • The JSON set covers syntax, schema and parsing in depth

Parse It

  • Python json5.loads(text) or commentjson
  • JavaScript JSON5.parse(text) or Microsoft jsonc-parser
  • Java Jackson JsonReadFeature.ALLOW_JAVA_COMMENTS

JSON, JSONC and JSON5 Side by Side

// tsconfig.json — JSONC: comments OK
{
  "$schema": "https://json.schemastore.org/tsconfig",
  "compilerOptions": {
    "strict": true,      // keep this on
    "target": "es2022",  // trailing comma below is OK in tsconfig
  },
}

// renovate.json5 — JSON5
{
  extends: ['config:recommended'],   // unquoted keys, single quotes
  schedule: ['before 6am on monday'],
  automerge: true,
}

// package.json — strict JSON: none of the above allowed

Code Explained

TypeScript and VS Code parse their JSON files as JSONC, so comments and trailing commas work
JSON5 also allows hex numbers, Infinity, NaN and multi-line strings
"$schema" is ignored by the tool but used by editors for validation
Rename to .jsonc / .json5 where the tool allows, so editors highlight it correctly

Same Data In…

  • TOML [compilerOptions] / strict = true # keep this on
  • YAML compilerOptions: / strict: true # keep this on

Gotcha

  • JSON.parse on a tsconfig.json with comments throws; read it with the TypeScript API or a JSONC parser
  • Some tools accept comments but rewrite the file and drop them (e.g. npm pkg set)

⚠ Common Mistakes

  • Adding a comment to package.json and breaking every npm command
  • Reading a JSONC file with a strict parser in a build script
  • Hand-editing a big JSON config when the tool also supports a JS or TOML config

✓ Tips & Best Practices

  • Add "$schema" to JSON config files for free autocomplete in VS Code
  • Use a "//" key for notes in strict JSON if you must: "//": "why this is pinned"
  • Prefer the tool's JS / TS config (eslint.config.js, vite.config.ts) when you need logic or comments

Quick Summary

  • JSON — strict, no comments
  • JSONC — comments (+ trailing commas in TS / VS Code)
  • JSON5 — comments, unquoted keys, single quotes
  • "$schema" — editor validation
