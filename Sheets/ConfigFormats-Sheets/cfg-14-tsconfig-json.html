tsconfig.json & jsconfig.json

compilerOptions · target / module / moduleResolution · strict · paths · include / exclude · extends

How TypeScript Reads Your Project

tsconfig.json (JSONC) tells the TypeScript compiler and your editor which files belong to the project and how to check them. target sets the JavaScript version emitted, module / moduleResolution decide how imports work, strict turns on the full type checks, and paths maps import aliases. jsconfig.json is the same file for JavaScript projects, giving VS Code IntelliSense without TypeScript.

Notes

  • Run npx tsc --showConfig to see the merged result
  • Bundler projects (Vite, Next) use moduleResolution: "bundler" and noEmit
  • Node projects use module: "nodenext"
  • The JS / TS set covers the type system itself

tsconfig.json for a Vite App

{
  "extends": "./tsconfig.base.json",
  "compilerOptions": {
    "target": "es2022",
    "lib": ["es2023", "dom", "dom.iterable"],
    "module": "esnext",
    "moduleResolution": "bundler",
    "jsx": "react-jsx",
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "verbatimModuleSyntax": true,
    "noEmit": true,
    "skipLibCheck": true,
    "paths": { "@/*": ["./src/*"] },
    "types": ["vitest/globals"]
  },
  "include": ["src", "tests"],
  "exclude": ["dist"]
}

Code Explained

extends pulls in a shared base; keys here override it
noEmit because Vite (esbuild / Rolldown) compiles; tsc only type-checks
paths needs the bundler configured with the same alias (resolve.alias in Vite)
types limits which @types packages load globally

Same Data In…

  • jsconfig.json same compilerOptions subset with "checkJs": true for JS projects
  • pyproject.toml [tool.mypy] / strict = true — the Python equivalent

Gotcha

  • paths only affects type checking; without a matching bundler / runtime alias, imports fail at run time
  • include defaults to every .ts file under the folder; a stray dist/ gets type-checked

⚠ Common Mistakes

  • Copying a tsconfig between a Node app and a Vite app; the module settings differ
  • Setting paths and forgetting the bundler / test-runner alias
  • Turning strict off to silence errors instead of fixing types

✓ Tips & Best Practices

  • Start from the framework's template (npm create vite) or @tsconfig/bases packages
  • Use tsc --noEmit in CI as a separate type-check step
  • Split tsconfig.app.json / tsconfig.node.json when browser and Node code live together

Quick Summary

  • strict — full type checking
  • module + moduleResolution — match your runtime / bundler
  • paths — aliases (configure the bundler too)
  • extends — share a base
