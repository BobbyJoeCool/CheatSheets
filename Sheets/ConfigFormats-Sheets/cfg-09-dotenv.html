.env Files

KEY=value · quoting · export prefix · variable expansion · .env.example · never commit secrets · loaders per stack

Environment Variables in a File

A .env file lists KEY=value lines that a loader copies into the process environment at start-up, so local development can mimic production without exporting variables by hand. It is a convention, not a standard: the dotenv libraries, Docker Compose, Node's --env-file and shells each parse it slightly differently. It almost always holds secrets, so it stays out of Git; commit a .env.example instead.

Notes

  • Loaders usually don't override variables already set in the real environment
  • Values are strings; your app converts them
  • Docker Compose reads .env for ${VAR} interpolation in compose.yaml
  • Many frameworks load .env.local, .env.development etc. in order

Parse It

  • Python from dotenv import load_dotenv; load_dotenv()
  • JavaScript node --env-file=.env app.js or process.loadEnvFile()
  • Java Dotenv.load().get("DB_URL") (dotenv-java)

.env and .env.example

# .env  (gitignored)
APP_ENV=development
PORT=3000
DATABASE_URL=postgres://app:s3cret@localhost:5432/orders
API_KEY="sk_test_51H…"          # quotes are stripped
GREETING='Hello, $USER'          # single quotes: no expansion
MULTILINE="line one\nline two"   # \n expanded in double quotes (most loaders)
LOG_DIR=${HOME}/logs             # expansion: supported by some loaders
export DEBUG=false               # "export" prefix allowed by most loaders

# .env.example  (committed: names, no real values)
APP_ENV=development
PORT=3000
DATABASE_URL=
API_KEY=

# load into a shell
set -a; source .env; set +a

Code Explained

The loader sets process.env.PORT / os.environ["PORT"] to the string "3000"
${HOME} expansion and \n handling vary by loader; test before relying on them
set -a exports everything a source defines, so child processes see it
.env.example documents every variable the app needs

Same Data In…

  • .properties database.url=postgres://…
  • YAML (Compose) environment: / DATABASE_URL: postgres://…
  • Shell export DATABASE_URL=postgres://…

Gotcha

  • A real environment variable wins over .env with most loaders, so a stale export in your shell silently overrides the file
  • Spaces around = (PORT = 3000) break some loaders and the shell

⚠ Common Mistakes

  • Committing .env once; the secret stays in Git history even after deleting the file
  • Expecting .env changes to apply without restarting the process
  • Using PORT as a number without converting the string

✓ Tips & Best Practices

  • Add .env to .gitignore before creating it
  • Validate env vars into a typed config object at start-up (Zod, Pydantic Settings)
  • Use a secrets manager or the platform's env settings in production

Quick Summary

  • KEY=value — copied into the environment
  • strings only — convert in code
  • .env.example — commit names, not values
  • loaders differ — expansion, quotes, overrides
