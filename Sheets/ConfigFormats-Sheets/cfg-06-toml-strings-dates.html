TOML Strings, Dates & Versions

basic vs literal strings · multi-line """ / ''' · escapes (\e, \xHH in 1.1) · offset / local date-time · TOML 1.0 vs 1.1

Four String Kinds and Real Dates

TOML has basic strings ("…", with escapes), literal strings ('…', no escapes: good for Windows paths and regex), and multi-line versions of each ("""…""", '''…'''). Dates and times are a native type, not strings: offset date-times, local date-times, local dates and local times. TOML 1.1 added \e and \xHH escapes and made seconds optional in times.

Notes

  • A newline right after """ is trimmed
  • In multi-line basic strings, \ at line end joins lines
  • Literal strings can't contain their own quote; use the other kind
  • Dates follow RFC 3339 (T or a space between date and time)

Strings and Dates

greeting = "Hello\tWorld\n"          # basic: escapes work
path = 'C:\Users\bob\config'       # literal: backslashes as-is
regex = '\d{3}-\d{4}'               # literal: no double escaping
quote = "She said \"hi\""
esc = "\e[31mred\e[0m"               # TOML 1.1: \e = ESC
byte = "\x41"                       # TOML 1.1: \xHH = "A"

poem = """
Roses are red
Violets are blue"""
oneline = """\
  joined \
  together"""                       # "joined together"

created = 2026-11-03T08:30:00-06:00 # offset date-time
local   = 2026-11-03T08:30:00       # local date-time
day     = 2026-11-03                # local date
alarm   = 07:30:00                  # local time (1.1: 07:30)

Code Explained

Literal strings are the easy way to write Windows paths and regular expressions
The trailing \ in a multi-line basic string removes the newline and leading spaces after it
Parsers return date-times as real date objects (datetime in Python)
Use the offset form for anything that must mean one moment worldwide

Same Data In…

  • JSON dates are just strings: "created": "2026-11-03T08:30:00-06:00"
  • YAML created: 2026-11-03T08:30:00-06:00 (PyYAML turns it into a datetime too)

Gotcha

  • "C:\Users\new" in a basic string: \U and \n are escapes, so this is an error or a newline
  • \e, \xHH and times without seconds fail in TOML 1.0 parsers such as tomllib

⚠ Common Mistakes

  • Writing Windows paths in double quotes and getting escape errors
  • Storing dates as strings ("2026-11-03") and losing the native type
  • Using TOML 1.1 features in files read by 1.0-only tools

✓ Tips & Best Practices

  • Single quotes for paths and regex, double quotes when you need escapes
  • Add the UTC offset to timestamps that leave your machine
  • Check which TOML version your parser supports before using 1.1 syntax

Quick Summary

  • "…" — escapes · '…' — literal
  • """ / ''' — multi-line
  • dates — native type, RFC 3339
  • TOML 1.1 — \e, \xHH, optional seconds
