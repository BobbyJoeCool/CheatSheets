GitHub Actions Workflow Files

CI as a YAML File in the Repo

A workflow is a YAML file in .github/workflows/. on lists the events that start it, jobs run in parallel on runners (runs-on), and each job's steps either run shell commands or uses a reusable action with inputs in with. ${{ }} expressions read contexts such as github, matrix, secrets and env. This sheet is the file format; the GitHub set covers Actions in depth.

Notes

  • Indentation errors fail the whole workflow; the Actions tab shows the line
  • Pin third-party actions to a full commit SHA
  • workflow_dispatch adds a manual Run workflow button
  • Validate with actionlint before pushing

.github/workflows/ci.yml

name: CI
on:
  push:
    branches: [main]
  pull_request:
  workflow_dispatch:

permissions:
  contents: read

jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        node: [22, 24]
    env:
      CI: true
    steps:
      - uses: actions/checkout@v6
      - uses: actions/setup-node@v6
        with:
          node-version: ${{ matrix.node }}
          cache: npm
      - run: npm ci
      - run: npm test
        env:
          API_KEY: ${{ secrets.API_KEY }}

Code Explained

pull_request: with no value means "all pull request events"
permissions narrows the default token to read-only
The matrix runs the job once per Node version
Step-level env scopes a secret to the one step that needs it

Same Data In…

  • GitLab CI (.gitlab-ci.yml) test: / image: node:22 / script: [npm ci, npm test]
  • Azure Pipelines trigger: [main] / steps: / - script: npm test

Gotcha

  • on: is a plain key to GitHub's parser, but a YAML 1.1 tool (yamllint default) may flag it as the boolean true
  • Untrusted input like ${{ github.event.pull_request.title }} inside run: is a script-injection risk; pass it through env

Common Triggers

on:Runs when
pushCommits pushed (filter branches / paths)
pull_requestPR opened or updated
workflow_dispatchRun by hand
scheduleCron, e.g. - cron: "0 6 * * 1"
releaseA release is published
workflow_callCalled by another workflow

⚠ Common Mistakes

  • Tabs or uneven indentation in a workflow file
  • Putting secrets in env at the workflow level where every step can read them
  • Using @main for third-party actions instead of a pinned SHA

✓ Tips & Best Practices

  • Run actionlint locally or in pre-commit to catch errors before CI does
  • Use the GitHub Actions extension or SchemaStore schema for autocomplete (sheet 19)
  • Keep jobs small and use needs to chain them

Quick Summary

  • on — triggers
  • jobs.<id>.steps — run or uses
  • ${{ }} — expressions over contexts
  • permissions + secrets in step env — least privilege
