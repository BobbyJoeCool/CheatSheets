How a Backtracking Engine Works

Most engines (PCRE, Java, JS, .NET, Python, Ruby) are backtracking engines. They try the pattern at text position 0; if it fails, they try position 1, and so on. At each position they follow the pattern left to right, and whenever a choice exists (a quantifier, an alternation) they take the first option and remember the rest. When a later piece fails, they backtrack to the last choice and try the next option. The first complete match wins, so results depend on the order of choices, not on which match is longest.

Key Consequences

  • The leftmost match wins: an earlier start beats a longer match later
  • Alternation is ordered: cat|category on “category” returns cat
  • POSIX tools (grep, awk) pick the leftmost-longest match instead
  • RE2, Go and Rust use automata: linear time, but no backreferences

Trace: a.*c on “xabcbcx”

# pos 0  'x' != a              -> fail, try next start
# pos 1  a ok; .* eats "bcbcx" (greedy, takes everything)
#        c? end of text        -> backtrack: .* gives back 'x'
#        c? 'x' != c           -> backtrack: .* gives back 'c'
#        c ok                  -> MATCH "abcbc" (span 1-6)
import re
re.search(r"a.*c", "xabcbcx").span()              # (1, 6)
re.search(r"cat|category", "category").group()    # 'cat'
re.search(r"category|cat", "category").group()    # 'category'
re.findall(r"aa", "aaaa")                         # ['aa', 'aa']
re.findall(r"(?=(aa))", "aaaa")                   # ['aa', 'aa', 'aa']
re.findall(r"a*", "baa")                          # ['', 'aa', '']
re.sub(r"x*", "-", "abc")                         # '-a-b-c-'

Code Explained

Greedy .* grabs the rest of the line, then gives characters back one at a time
Ordered alternation: put the longer option first
Matches never overlap; the scan resumes after the previous match
(?=(aa)) — a capturing lookahead finds overlapping matches
a* can match zero characters, so empty matches appear between letters

⚠ Common Mistakes

  • Short alternative first: in|int matches only “in” inside “int”; order longest first or add \b
  • Expecting findall to return overlapping matches; use a lookahead capture
  • Using Python re.match when you meant search, or Java matches() when you meant find

✓ Tips & Best Practices

  • Use regex101's debugger to watch backtracking step by step
  • Anchor with ^…$ or use a full-match API whenever you validate input
  • Put the most common alternative first; it is tried first

Quick Summary

  • leftmost — earliest start position wins
  • a|b — tried in order, first success wins
  • backtracking — retry the last choice on failure
  • RE2 / DFA — linear time, fewer features
