Sheet 07

Greedy, Lazy & Possessive

greedy · lazy *? +? ?? {n,m}? · ".*" vs ".*?" vs "[^"]*" · possessive *+ ++ ?+ · atomic (?>…)

Three Ways to Repeat

Greedy quantifiers (the default) take as much as they can, then give characters back one at a time if the rest of the pattern fails. Add ? to make them lazy: they take as little as possible and expand only when forced. Add + to make them possessive: they take as much as possible and never give anything back. An atomic group (?>…) applies the same no-give-back rule to a whole group. Lazy changes which match you get; possessive and atomic mostly change speed and prevent runaway backtracking.

Choosing

  • Know the terminator? A negated class [^"]* beats both greedy and lazy
  • Lazy is still a full match: \d+?$ must reach the end, so it matches all digits
  • Possessive can make a pattern fail that greedy would match
  • No possessive or atomic in JS; Go and Rust don't need them (no backtracking)

Greedy vs Lazy vs Possessive (Python 3.11+)

import re
html = "<b>bold</b> and <i>it</i>"
re.findall(r"<.+>", html)           # ['<b>bold</b> and <i>it</i>']
re.findall(r"<.+?>", html)          # ['<b>', '</b>', '<i>', '</i>']
re.findall(r"<[^>]+>", html)        # ['<b>', '</b>', '<i>', '</i>']
s = '"a" and "b"'
re.findall(r'".*"', s)              # ['"a" and "b"']
re.findall(r'".*?"', s)             # ['"a"', '"b"']
re.findall(r'"[^"]*"', s)           # ['"a"', '"b"']
re.search(r"\d+?", "12345").group()   # '1'
re.search(r"\d+?$", "12345").group()  # '12345'
re.search(r'".*+"', s)              # None
re.search(r'"[^"]*+"', s).group()   # '"a"'
re.search(r"(?>a+)ab", "aaab")      # None

Code Explained

<.+> — greedy runs to the last > on the line
<.+?> — lazy stops at the first >
<[^>]+> — can't cross >; fastest and clearest
".*+" — possessive .*+ eats the closing quote and won't return it
"[^"]*+" — possessive is safe when the class can't eat the terminator
(?>a+) — atomic: keeps all three a's, so ab can't match

⚠ Common Mistakes

  • Reaching for .*? everywhere: it's slower than [^x]* and can still overshoot across lines
  • Thinking lazy means "shortest overall"; it's shortest from the leftmost start position
  • Making a quantifier possessive when it can also consume the next token (.*+"), so the match fails

✓ Tips & Best Practices

  • Default to negated classes, then lazy, then greedy, in that order of preference
  • Use possessive or atomic on parts that can never need to give back, to stop catastrophic backtracking (sheet 15)
  • In JS, emulate atomic with (?=(…))\1

Quick Summary

  • * — greedy: max, then back off
  • *? — lazy: min, then grow
  • *+ — possessive: max, never back off
  • (?>…) — atomic group
