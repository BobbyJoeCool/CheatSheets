What a Regex Is

A regular expression (regex) is a compact pattern that describes a set of strings. You hand the pattern to an engine, and it scans text for substrings that fit: to validate input, find and extract data, split text, or search-and-replace. The core syntax (. * + ? [...] (...) | ^ $) is nearly universal, but every language ships its own flavor with different extras, escaping rules and replacement syntax. Learn the core once, then learn your host's differences (sheets 16–23).

Background

  • 1950s Kleene defines regular languages; 1968 Thompson adds them to QED, then ed and grep
  • 1987 Perl makes regex a core feature; 1997 PCRE brings Perl syntax to C
  • Most modern flavors are Perl-style; POSIX tools (grep, sed, awk) keep an older dialect
  • Test at regex101.com with the flavor set to your target language; it explains every token

First Patterns (Python)

import re
text = "Call 555-1234 or 555-9876 today"
re.search(r"\d{3}-\d{4}", text).group()    # '555-1234'
re.findall(r"\d{3}-\d{4}", text)           # ['555-1234', '555-9876']
re.sub(r"\d{3}-(\d{4})", r"XXX-\1", text)  # 'Call XXX-1234 or XXX-9876 today'
bool(re.fullmatch(r"[A-Z]{2}\d{4}", "AB1234"))  # True
bool(re.fullmatch(r"[A-Z]{2}\d{4}", "AB123"))   # False
# The same pattern in other hosts (note the escaping):
#   JavaScript  /\d{3}-\d{4}/g
#   Java        Pattern.compile("\\d{3}-\\d{4}")
#   C#          new Regex(@"\d{3}-\d{4}")
#   Go          regexp.MustCompile(`\d{3}-\d{4}`)
#   grep (ERE)  grep -Eo '[0-9]{3}-[0-9]{4}' calls.txt

Code Explained

\d{3} — exactly three digits; - is a literal hyphen
search — first match anywhere; findall — every match
sub — replace; (\d{4}) captures, \1 reinserts it
fullmatch — the whole string must fit (validation)
r"..." / @"..." / backticks — raw strings keep \ intact
POSIX ERE has no \d; use [0-9] or [[:digit:]]

⚠ Common Mistakes

  • Testing in one flavor, shipping in another: a lookbehind that works in regex101's PCRE mode won't compile in Go
  • Assuming \d and \w work everywhere: POSIX grep -E and sed -E need [0-9] or [[:digit:]]
  • Using regex where a parser belongs (HTML, JSON, nested data); see sheet 25

✓ Tips & Best Practices

  • Set regex101's flavor to match your code before you start
  • Use your host's raw-string syntax so backslashes reach the engine unchanged
  • Test against strings that should not match, not just ones that should

Quick Summary

  • regex — a pattern language for matching text
  • flavor — host dialect; core syntax is shared
  • backtracking vs automata — features vs guaranteed speed
  • regex101 — test with the right flavor selected
