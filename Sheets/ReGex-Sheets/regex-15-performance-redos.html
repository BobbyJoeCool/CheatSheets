Sheet 15

Performance & Catastrophic Backtracking

ReDoS · (a+)+ · (a|a)* · atomic / possessive fixes · anchor & fail fast · precompile · timeouts · RE2 / NonBacktracking

When a Regex Never Finishes

A backtracking engine that fails a match must try every way the pattern could have split the text before giving up. When a pattern has nested or overlapping quantifiers, like (a+)+ or (\w|\d)*, the number of ways grows exponentially with input length. A 30-character string can then take minutes. This is catastrophic backtracking, and when attackers can supply the input it's a denial-of-service bug called ReDoS. The fix is to make each character matchable in only one way.

Real Incidents

  • Stack Overflow, 2016: a whitespace-trim regex hit a post with ~20,000 spaces and took the site down
  • Cloudflare, 2019: .*(?:.*=.*) in a WAF rule pinned CPUs worldwide for 27 minutes
  • Go, Rust and RE2 are immune: they run in linear time

Catastrophic Backtracking (Python)

import re, time
evil = re.compile(r"^(a+)+$")
for n in (20, 22, 24):
    t = time.perf_counter(); evil.match("a" * n + "!")
    print(n, round(time.perf_counter() - t, 2))
# 20 0.08   22 0.19   24 0.85   <- ~2x per extra character
re.match(r"^a+$", "a" * 10_000 + "!")      # None
re.match(r"^(?>a+)+$", "a" * 10_000 + "!") # None
re.match(r"^(a++)+$", "a" * 10_000 + "!")  # None
# Python regex module: timeout as a safety net
import regex
regex.match(r"^(a|a)*$", "a" * 30 + "!", timeout=0.5)  # TimeoutError

Code Explained

(a+)+ — "aaaa" can split as 4, 3+1, 2+2, 1+1+1+1…: 2ⁿ⁻¹ ways
The trailing ! forces failure, so every split is tried
^a+$ — same strings, one way to match; instant
(?>a+) / a++ — atomic / possessive: no re-splitting
timeout= — the regex module raises instead of hanging

⚠ Common Mistakes

  • Testing only with matching input; ReDoS appears when the match fails near the end
  • Recompiling inside a loop: Java String.matches() compiles the pattern on every call
  • Starting a search pattern with .*: the engine already tries every position, so it's pure extra work

✓ Tips & Best Practices

  • Make each character belong to exactly one quantifier; use tight classes like [^,]*
  • Compile once (re.compile, Pattern.compile, a static readonly Regex) and reuse
  • Cap input length before matching untrusted text, and lint patterns with a ReDoS checker

Quick Summary

  • (a+)+ — nested quantifiers = exponential
  • (?>…) / a++ — stop re-splitting
  • timeout / linear engine — safety net
  • precompile — pay the parse cost once
