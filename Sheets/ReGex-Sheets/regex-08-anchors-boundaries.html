Sheet 08

Anchors & Word Boundaries

^ $ · multiline mode · \A \z \Z · $ before final \n · \b / \B · \< \> (GNU) · \G

Matching Positions, Not Characters

Anchors match a position between characters, so they consume nothing (they are zero-width). ^ and $ mark the start and end of the string, or of each line when multiline mode (m) is on. \A and \z always mean the absolute start and end, regardless of mode. Word boundaries \b match where a word character (\w) meets a non-word character or the edge of the text, which makes them the easiest way to match whole words.

Gotchas

  • In most flavors $ also matches before a final \n: ^\d+$ accepts "123\\n"
  • JS, Go and Rust $ (without m) means the true end only
  • Ruby ^ and $ are always line anchors; use \A and \z for validation
  • \b uses \w, so in JS it's ASCII-only: \bcafé\b fails at é

Anchors & Boundaries (Python)

import re
text = "first line\nsecond line\n"
re.findall(r"^\w+", text)               # ['first']
re.findall(r"^\w+", text, re.M)         # ['first', 'second']
re.findall(r"\w+$", text)               # ['line']
re.findall(r"line$", text, re.M)        # ['line', 'line']
bool(re.search(r"^\d+$", "123\n"))      # True
bool(re.search(r"\A\d+\Z", "123\n"))    # False
bool(re.fullmatch(r"\d+", "123\n"))     # False
re.findall(r"\bcat\b", "cat concat cat.")   # ['cat', 'cat']
re.findall(r"\Bcat\b", "cat concat")        # ['cat']
re.sub(r"\b", "|", "hi there")              # '|hi| |there|'

Code Explained

Without re.M, ^ only matches at position 0
\w+$ matched the last line: $ allows the trailing \n
^\d+$ accepts "123\\n"; \A…\Z (Python) or fullmatch rejects it
\bcat\b — whole word only; skips "concat"
\Bcat — "cat" inside a word
\b is zero-width: inserting at it marks each word edge

Anchors

AnchorMatches At
^start of string; start of each line with m

\Astart of string, always (not JS)
\zvery end of string (PCRE, Java, .NET, Ruby, Go)
\Zend or before final \n; Python: very end
\bword boundary (\w next to \W or edge)
\Bnot a word boundary
\Gwhere the previous match ended (PCRE, Java, .NET)
\< \>start / end of word (GNU grep, sed, vim)

⚠ Common Mistakes

  • Validating with ^…$ in Ruby: "ok\\n<script>" passes because $ matches at the first line end
  • Forgetting m and wondering why ^ matches only once in a multi-line string
  • Using \b around non-word characters: \b\$5\b fails because $ isn't a word character

✓ Tips & Best Practices

  • Validate whole input with \A…\z or a full-match API (fullmatch, matches())
  • Use \b for whole-word search and replace: \bid\b won't touch "valid"
  • Anchoring a pattern lets the engine fail fast instead of trying every position

Quick Summary

  • ^ $ — string or line edges (with m)
  • \A \z — absolute start and end
  • \b \B — word boundary / not a boundary
  • anchors are zero-width — they consume nothing
