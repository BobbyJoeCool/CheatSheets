Regex on the Command Line

Unix tools speak POSIX regex in two dialects. BRE (basic, the default for grep and sed) treats + ? | ( ) { as literals unless you escape them; ERE (extended, grep -E, sed -E, awk) makes them special without backslashes. Neither has \d or lazy quantifiers: use [0-9] and [[:space:]]. For Perl-style syntax use grep -P (GNU) or ripgrep (rg), which is fast, recursive and respects .gitignore by default.

GNU vs BSD (macOS)

  • In-place edit: GNU sed -i 's/…/', macOS sed -i '' 's/…/'
  • macOS grep has no -P; use rg -P or Homebrew's ggrep
  • \s, \w, \b, \< are GNU extensions; [[:space:]] works everywhere
  • Quote patterns in single quotes so the shell leaves $ and \ alone

Common Commands

grep -E '^[0-9]{3}-[0-9]{4}$' phones.txt        # ERE: {} unescaped
grep 'ab\+c\|xy' notes.txt                       # BRE (GNU): escape + and |
grep -oP '(?<=id=)\d+' app.log                   # PCRE: lookbehind, \d (GNU)
grep -rnw 'TODO' src/                            # recursive, line numbers, whole word
grep -ciE 'error|fail' app.log                   # count, case-insensitive
grep -v '^#' config.ini                          # invert: drop comment lines
sed -E 's/([0-9]+)-([0-9]+)/\2-\1/g' file.txt    # swap with backrefs
sed -E 's/[[:space:]]+$//' file.txt              # strip trailing whitespace
sed -n '/BEGIN/,/END/p' file.txt                 # print a range of lines
awk '/ERROR/ {n++} END {print n}' app.log        # count matching lines
awk -F, '$3 ~ /^[A-Z][A-Z]$/ {print $1}' data.csv  # match one field
rg -n '\bfn \w+\(' -t rust                       # ripgrep (Rust regex)
rg -P '(?<=v)\d+\.\d+' CHANGELOG.md              # ripgrep with PCRE2
find . -regextype posix-extended -regex '.*\.(jpg|png)'   # GNU find

Code Explained

-E ERE · -P PCRE · -F fixed string (no regex)
-o print only the match · -w whole word · -x whole line
sed -E + \1 — backrefs in the replacement; & = whole match
sed -n '/a/,/b/p' — address ranges use regex too
awk — /re/ tests the line, $3 ~ /re/ tests a field
find -regex matches the whole path, not just the name

⚠ Common Mistakes

  • Using \d with grep -E or sed -E: POSIX has no \d, so it silently matches the letter d (or warns)
  • Double-quoting patterns: the shell expands $var and \ before grep sees them
  • Running GNU sed -i syntax on macOS: -i eats the next argument as a backup suffix

✓ Tips & Best Practices

  • Use grep -F for literal strings; no escaping and faster
  • Prefer rg for code search: recursive, Unicode-aware, skips ignored files
  • Test a sed edit without -i first, then add -i.bak to keep a backup

Quick Summary

  • BRE — escape \( \) \{ \} \+ \?
  • ERE — grep -E, sed -E, awk
  • grep -P / rg -P — Perl syntax
  • [[:space:]] — portable classes
