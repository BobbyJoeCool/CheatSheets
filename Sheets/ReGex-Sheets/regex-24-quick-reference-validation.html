Quick Reference — Validation Patterns

email · URL · IPv4 / IPv6 · UUID / GUID · ISO 8601 dates & times · phone (E.164 / NANP) & ZIP · hex color & semver · password lookaheads

Copy-Ready Validation Patterns

Each pattern is anchored with ^…$ for whole-string validation and written PCRE-style: use \A…\z in Ruby and double the backslashes in Java strings. They're practical, not RFC-complete. Shape isn't validity: the date pattern accepts 2026-02-30; check values in code. Patterns tagged ✗ Go use lookaround, which Go and Rust don't support.

⚠ Common Mistakes

  • No anchors: \d{5} accepts “123456789”
  • Over-strict rules reject real input (+ in emails)
  • Checking IPs/URLs by regex alone; parse them too

✓ Tips & Best Practices

  • Normalize first: trim, uppercase, strip punctuation
  • One named constant per pattern, with test samples
  • Parsers: ipaddress, new URL(), URI

Quick Summary

  • ^…$ — validate the whole value
  • regex for shape, code for meaning
  • ✗ Go — needs lookaround
