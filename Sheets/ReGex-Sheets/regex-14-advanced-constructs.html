Advanced Constructs

(?(1)yes|no) · (?R) / (?1) · balanced parentheses · (?&name) · (*SKIP)(*FAIL) · (*UCP) · .NET (?<-open>) · (?#…)

Beyond Regular Languages

PCRE, Perl and a few other flavors add constructs that go past what "regular" expressions can describe. Conditionals choose a branch based on whether a group matched. Recursion and subroutine calls reuse a pattern (not its captured text), which is enough to match nested structures like balanced parentheses. Backtracking verbs such as (*SKIP)(*FAIL) control the engine directly. These are powerful but non-portable; check the support table before relying on one.

When to Use Them

  • Nested brackets, quotes inside code, or "match X except inside Y" problems
  • Python: most of these need the third-party regex module (examples below)
  • No support in JS, Java, Go or Rust; use a parser or code there
  • If a pattern needs more than one of these, a real parser is usually clearer

Advanced Constructs (Python regex module, PCRE syntax)

import regex
# Balanced parentheses: recurse into the whole pattern
regex.findall(r"\((?:[^()]++|(?R))*\)", "f(a(b)c) g(d)")   # ['(a(b)c)', '(d)']
# Conditional: if group 1 matched "<", require ">"
ok = lambda p, s: bool(regex.fullmatch(p, s))
pat = r"(<)?\w+(?(1)>)"
[ok(pat, s) for s in ("<a>", "a", "<a")]                    # [True, True, False]
# Subroutine: reuse a named group's pattern, not its text
ip = r"(?<o>25[0-5]|2[0-4]\d|1?\d?\d)(?:\.(?&o)){3}"
ok(ip, "10.0.0.255"), ok(ip, "10.0.0.256")                  # (True, False)
# Skip quoted strings, match words everywhere else
regex.findall(r'"[^"]*"(*SKIP)(*FAIL)|\w+', 'a "b c" d')   # ['a', 'd']
# Comments inside a pattern
regex.findall(r"\d+(?# digits)%", "50% of 8")             # ['50%']

Code Explained

(?R) — recurse into the entire pattern at this point
[^()]++ — possessive: never re-splits text between parens
(?(1)>) — require > only if group 1 matched
(?&o) — run group o's pattern again (each octet re-validated)
(*SKIP)(*FAIL) — match the unwanted part, then discard it and resume after it
(?#…) — an inline comment

Constructs & Support

SyntaxMeaningSupported By
(?(1)yes|no)conditional on group 1 (or (?(<name>)…))PCRE, Perl, .NET, Python re, Ruby
(?R) (?0)recurse the whole patternPCRE, Perl, regex; Ruby \g<0>
(?1) (?&name)subroutine: call group's patternPCRE, Perl, regex; Ruby \g<name>
(?(DEFINE)…)define named subpatterns, match nothingPCRE, Perl, regex
(*SKIP)(*FAIL)discard what matched, skip past itPCRE, Perl, regex
(*PRUNE) (*COMMIT) (*ACCEPT)other backtracking-control verbsPCRE, Perl
(*UCP) (*UTF) (*CRLF)start-of-pattern engine optionsPCRE2
(?<open>\() … (?<-open>\))balancing groups: push / pop a stack.NET only
(?#comment)inline commentPCRE, Perl, Python, .NET, Ruby

⚠ Common Mistakes

  • Using (?R) with unbounded alternatives: without possessive or atomic parts, nested input backtracks exponentially
  • Expecting a subroutine (?1) to match the same text like \1; it re-runs the pattern
  • Porting a (*SKIP)(*FAIL) pattern to JS or Java; it fails to compile

✓ Tips & Best Practices

  • Wrap recursive pieces in [^…]++ or (?>…) to keep them fast
  • Use (?(DEFINE)…) to name building blocks, then compose with (?&name)
  • In .NET, balanced matching uses (?<open>…), (?<-open>…) and a final (?(open)(?!))

Quick Summary

  • (?(1)a|b) — conditional branch
  • (?R) / (?1) — recursion and subroutines
  • (*SKIP)(*FAIL) — match everything except X
  • non-portable — PCRE, Perl, regex, .NET
