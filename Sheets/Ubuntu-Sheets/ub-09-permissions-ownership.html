Sheet 09

Permissions & Ownership

rwx · chmod 755 / u+x · chown user:group · -R · ls -l columns · stat

Description

Every file has an owner, a group, and three sets of permissions: for the owner (u), the group (g) and everyone else (o). Each set allows read, write and/or execute. On directories, execute means "may enter". Change modes with chmod and owners with chown.

Notes

  • Octal: r=4, w=2, x=1 → 7=rwx, 5=r-x, 4=r--
  • Only root (or sudo) can change a file's owner
  • Scripts need x to run as ./script.sh
  • New files get permissions from umask (sheet 13)

⚠ Danger Check

  • chmod -R 777 makes everything world-writable: never a fix
  • chown -R on / or /usr can break sudo and the whole system
  • Recursive changes on the wrong path are hard to undo

Read and Change Permissions

ls -l deploy.sh
# -rwxr-x--- 1 bob devs 812 Nov 13 09:10 deploy.sh
#  └u─┘└g─┘└o┘   owner group

chmod u+x deploy.sh          # add execute for owner
chmod go-w notes.txt         # remove write for group/other
chmod 644 index.html         # rw-r--r--
chmod 755 /srv/site          # rwxr-xr-x (dir: enter + list)
chmod 600 ~/.ssh/id_ed25519  # private key: owner only
sudo chown www-data:www-data /srv/site/uploads
sudo chown -R bob: ~/projects      # bob + bob's group
stat -c '%A %a %U:%G %n' deploy.sh  # -rwxr-x--- 750 bob:devs

Code Explained

first char — - file, d dir, l link
u+x, go-w — symbolic changes
644 / 755 — octal modes for files / dirs
chown user:group — change both at once
stat -c — show mode in both forms

Other Distros

  • Debian/Fedora — same tools; Fedora adds SELinux labels (ls -Z)
  • macOS — same model plus ACLs; chmod +a syntax differs

Prefer / Avoid

  • Avoid chmod 777 to "fix" access · Prefer the right owner/group
  • Avoid chmod -R 755 on files · Prefer find -type d / -type f separately

Common Modes

ModeUse
644normal files
755dirs, executables
600secrets, SSH keys
700private dirs (~/.ssh)
640config readable by group
775shared group dir

Meaning on Directories

BitAllows
rlist names
wcreate, delete, rename inside
xenter, access files by name
r without xnames only, no access

⚠ Common Mistakes

  • chmod -R 755 dir makes every file executable
  • SSH refuses keys when ~/.ssh or the key is group/world-writable
  • Changing perms instead of adding the user to the right group

✓ Tips & Best Practices

  • find dir -type d -exec chmod 755 {} + and -type f ... 644
  • Use groups for shared access: usermod -aG devs bob
  • namei -l /path/to/file shows perms on every parent dir

Quick Summary

  • owner / group / other × r w x
  • chmod — symbolic or octal
  • chown user:group — ownership
  • never 777; fix ownership instead
