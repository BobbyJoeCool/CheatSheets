Sheet 28

Network Basics

ip a · ip route · ss -tulpn · ping · curl / wget · traceroute / mtr · nc

Description

The ip command shows and changes addresses and routes; ss shows which programs are listening on which ports. For troubleshooting, work up the stack: is the interface up, is there an IP, is the gateway reachable (ping), does DNS resolve, is the port open (nc, curl)?

Notes

  • ifconfig/netstat are legacy (net-tools)
  • Changes made with ip are lost on reboot (use Netplan)
  • ss -tulpn needs sudo to show process names
  • 127.0.0.1 = loopback; 0.0.0.0 = all interfaces

Troubleshoot Step by Step

ip -br a                         # interfaces + IPs, one line each
ip route                         # default via 192.168.1.1 dev enp3s0
ping -c 3 192.168.1.1            # gateway reachable?
ping -c 3 1.1.1.1                # internet by IP?
ping -c 3 ubuntu.com             # DNS working?
sudo ss -tulpn                   # listening TCP/UDP ports + process
ss -tn state established         # current connections
curl -I https://example.com      # HTTP headers only
curl -fsS localhost:8000/health  # local service check
nc -zv 192.168.1.20 22           # is port 22 open?
mtr -rwc 10 ubuntu.com           # path + packet loss report
ip neigh                         # ARP table (LAN neighbors)

Code Explained

ip -br a — brief address list
ip route — default gateway
ping gateway → IP → name — isolate the layer
ss -tulpn — what's listening, by whom
nc -zv — port check without a client

Other Distros

  • Debian/Fedora — same iproute2 tools
  • macOS — ifconfig, netstat -rn, lsof -i -P

Prefer / Avoid

  • Avoid ifconfig / netstat · Prefer ip / ss
  • Avoid testing only by name · Prefer ping by IP then by name

⚠ Common Mistakes

  • Service listening on 127.0.0.1 and wondering why other machines can't reach it
  • Blaming the network when the firewall blocks the port (sheet 33)
  • Setting an IP with ip addr add and losing it on reboot

✓ Tips & Best Practices

  • curl -v shows TLS and redirect details
  • sudo tcpdump -i any port 53 to watch DNS traffic
  • Check sudo ufw status early when ports are unreachable

Quick Summary

  • ip a / ip route — addresses, gateway
  • ping / mtr — reachability
  • ss -tulpn — listening ports
  • curl / nc — service checks
