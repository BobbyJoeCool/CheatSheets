Sheet 29

Netplan

/etc/netplan/*.yaml · DHCP vs static · addresses / routes / nameservers · netplan try · netplan apply · Wi-Fi

Description

Ubuntu configures networking with Netplan: YAML files in /etc/netplan/ that describe interfaces, and Netplan writes the config for the renderer: systemd-networkd on servers, NetworkManager on desktops. Use netplan try, which rolls back automatically if you lose connectivity, before netplan apply.

Notes

  • YAML uses spaces, never tabs
  • Files apply in name order; later ones override
  • Config files should be chmod 600
  • Desktop: change settings in GNOME or nmcli instead

⚠ Danger Check

  • A wrong static IP or gateway cuts off a remote server
  • Use netplan try (auto-rollback in 120 s), never straight apply over SSH
  • Keep console access (VM console, IPMI) when changing networking

/etc/netplan/50-cloud-init.yaml → static IP

network:
  version: 2
  renderer: networkd
  ethernets:
    enp3s0:
      dhcp4: false
      addresses: [192.168.1.20/24]
      routes:
        - to: default
          via: 192.168.1.1
      nameservers:
        addresses: [1.1.1.1, 9.9.9.9]
        search: [home.lan]

Apply Safely

sudo chmod 600 /etc/netplan/*.yaml
sudo netplan generate          # syntax check
sudo netplan try               # press Enter to keep, else rollback
sudo netplan apply
netplan status                 # current state per interface

Code Explained

renderer: networkd — server backend
addresses — IP/prefix (CIDR)
routes: to: default — gateway (old gateway4 is deprecated)
nameservers — DNS servers + search domains
netplan try — automatic rollback safety

Other Distros

  • Debian — /etc/network/interfaces (ifupdown) or NetworkManager
  • Fedora — NetworkManager nmcli / keyfiles
  • macOS — networksetup, System Settings

Prefer / Avoid

  • Avoid gateway4: · Prefer routes: - to: default
  • Avoid static IPs set on the server when DHCP reservations work · Prefer router reservations

⚠ Common Mistakes

  • Tabs or bad indentation: "Invalid YAML"
  • Two files both configuring the same interface with conflicting settings
  • cloud-init rewriting 50-cloud-init.yaml on boot (disable its network config)

✓ Tips & Best Practices

  • Disable cloud-init networking: network: {config: disabled} in /etc/cloud/cloud.cfg.d/99-disable-network-config.cfg
  • Check interface names with ip -br link
  • Use netplan get to print the merged config

Quick Summary

  • /etc/netplan/*.yaml — network config
  • static IP — addresses, routes, nameservers
  • netplan try — safe apply with rollback
  • renderer — networkd (server) / NetworkManager (desktop)
