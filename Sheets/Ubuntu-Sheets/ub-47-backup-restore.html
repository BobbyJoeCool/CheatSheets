Sheet 47

Backup & Restore

rsync backups · tar snapshots · Déjà Dup · Timeshift · ZFS/LVM snapshots · restic / borg · 3-2-1 · test restores

Description

A backup you haven't restored is a guess. Follow 3-2-1: three copies, on two kinds of media, one off-site. On desktops, Déjà Dup (Backups app) covers your files and Timeshift snapshots the system. On servers, restic or borg give encrypted, deduplicated, versioned backups to disks or cloud storage.

Notes

  • Snapshots (ZFS/LVM) are not backups: same disk
  • Back up /etc, /home, /srv, /var/lib/<app>, DB dumps
  • Dump databases first (pg_dump), then back up the dump
  • Encrypt anything that leaves the house

⚠ Danger Check

  • rsync --delete to a backup can mirror an accidental deletion
  • Restoring over live files can overwrite newer data
  • Restore to a temp directory first, then copy what you need

restic to an External Disk

sudo apt install restic
export RESTIC_REPOSITORY=/mnt/backup/restic
export RESTIC_PASSWORD_FILE=/root/.restic-pass
restic init                                   # once
sudo -u postgres pg_dump app > /srv/dumps/app.sql
restic backup /etc /home /srv --exclude-caches \
       --exclude '/home/*/.cache'
restic snapshots                              # list versions
restic forget --keep-daily 7 --keep-weekly 4 \
       --keep-monthly 6 --prune               # retention
restic check                                  # verify repo
restic restore latest --target /tmp/restore \
       --include /etc/nginx                   # test restore!

# quick one-off: tar with date
sudo tar -czf /mnt/backup/etc-$(date +%F).tgz /etc

Code Explained

restic init — create encrypted repo
DB dump first — consistent database backup
--exclude-caches — skip cache dirs
forget --keep-* --prune — retention policy
restore --target /tmp — safe test restore

Other Distros

  • Debian/Fedora — same restic/borg; Fedora uses Btrfs snapshots + Timeshift/Snapper
  • macOS — Time Machine; restic works too

Prefer / Avoid

  • Avoid backups on the same disk only · Prefer external + off-site
  • Avoid never testing restores · Prefer scheduled restore drills

⚠ Common Mistakes

  • Backing up live database files instead of dumps: often unusable
  • Losing the restic/borg password: backups are unrecoverable
  • Only snapshots on the same pool: disk failure takes both

✓ Tips & Best Practices

  • Run backups from a systemd timer and ping a health check (sheet 23)
  • Store a copy of the repo password in a password manager
  • Use B2/S3 or a friend's server as the off-site copy

Quick Summary

  • 3-2-1 — three copies, two media, one off-site
  • restic / borg — encrypted, versioned
  • dump databases first
  • test restores regularly
