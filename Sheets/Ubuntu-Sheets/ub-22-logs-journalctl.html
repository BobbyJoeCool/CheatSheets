Sheet 22

Logs & journalctl

journalctl -u nginx · -f · --since · -p err · -b · /var/log · logrotate · dmesg

Description

systemd's journal collects logs from the kernel, services and anything they print. journalctl filters it by unit, time, priority and boot. Some programs still write text files under /var/log (nginx, apt, auth), which logrotate compresses and prunes. dmesg shows kernel messages like disk and USB events.

Notes

  • Journal is persistent on Ubuntu (/var/log/journal)
  • Users in adm or systemd-journal can read all logs
  • -e jumps to the end; -r newest first
  • --vacuum-size= limits journal disk use

Find the Right Log Lines

journalctl -u nginx -e                  # one service, jump to end
journalctl -u todo-api -f               # follow live
journalctl --since "1 hour ago" -p err  # errors in the last hour
journalctl -b -1 -p warning             # warnings from previous boot
journalctl _PID=4321                    # one process
journalctl -k                           # kernel messages (= dmesg)
journalctl -u ssh --since today -o short-iso | grep Failed
journalctl --disk-usage
sudo journalctl --vacuum-time=14d       # keep 14 days
sudo dmesg -T | tail                    # kernel, readable times
tail -F /var/log/nginx/access.log       # classic text logs
sudo less /var/log/auth.log             # logins, sudo
cat /etc/logrotate.d/nginx              # rotation rules

Code Explained

-u unit — filter by service
--since / --until — natural time phrases work
-p err — priority err and worse
-b -1 — previous boot (crash debugging)
--vacuum-time — prune old journal files

Other Distros

  • Debian/Fedora — same journalctl; Fedora has no /var/log/syslog
  • macOS — log show --last 1h, log stream

Prefer / Avoid

  • Avoid grep through all of /var/log · Prefer journalctl -u filters
  • Avoid unbounded logs · Prefer SystemMaxUse= in journald.conf

⚠ Common Mistakes

  • Looking at the current boot's log when the crash was in the previous one (-b -1)
  • Letting the journal grow to gigabytes on small disks
  • Missing app errors because the app logs to its own file, not stdout

✓ Tips & Best Practices

  • Set SystemMaxUse=500M in /etc/systemd/journald.conf
  • Log to stdout from your apps; systemd captures it
  • journalctl -o json-pretty for structured fields

Quick Summary

  • journalctl -u name — service logs
  • -f / --since / -p / -b — filter
  • /var/log — text logs, rotated by logrotate
  • --vacuum-* — control disk use
