Sheet 32

File Transfer

scp · rsync -avz --delete · sftp · rsync over SSH · dry runs -n · wget -c

Description

Copy files between machines over SSH. scp is quick for single files. rsync is the workhorse: it only sends what changed, can resume, preserves permissions, and can mirror a directory with --delete. sftp gives an interactive session, and most GUI clients (FileZilla, Cyberduck) speak it too.

Notes

  • All three use your SSH keys and ~/.ssh/config
  • Trailing slash matters in rsync: src/ vs src
  • --delete removes files missing from the source
  • -n (dry run) shows what would happen

Copy and Sync

scp report.pdf home:~/docs/              # laptop → server
scp home:/var/log/syslog ./              # server → laptop
scp -r photos/ home:/srv/media/          # directory

rsync -avz ~/projects/site/ home:/srv/site/       # contents of site
rsync -avzn --delete ./site/ home:/srv/site/      # dry run first!
rsync -avz --delete ./site/ home:/srv/site/       # mirror
rsync -avP big.iso home:~/                       # progress + resume
rsync -av --exclude='node_modules' app/ home:app/

sftp home                                # interactive
# sftp> put file.txt   get remote.txt   ls   cd   exit
wget -c https://releases.ubuntu.com/26.04/ubuntu.iso   # resume download

Code Explained

scp src dst — host:path for the remote side
-a — archive: perms, times, links, recursive
site/ — copy contents; site — copy the folder
-n --delete — preview a mirror safely
-P — progress + keep partial files

Other Distros

  • Debian/Fedora — same tools
  • macOS — scp/sftp built in; newer rsync via Homebrew

Prefer / Avoid

  • Avoid scp for big or repeated transfers · Prefer rsync
  • Avoid --delete without a dry run · Prefer -n first

rsync Flags

FlagMeaning
-aarchive mode
-vverbose
-zcompress in transit
-Pprogress + partial
-ndry run
--deleteremove extra files at dest
--exclude=PATskip matches

Trailing Slash

CommandResult
rsync -a src/ dst/dst/file1, dst/file2
rsync -a src dst/dst/src/file1
rsync -a src/ dstsame as first

⚠ Common Mistakes

  • Mixing up source and destination with --delete: wipes the original
  • Forgetting the trailing slash and getting site/site/
  • Copying as root and leaving root-owned files in user dirs

✓ Tips & Best Practices

  • Use rsync -e 'ssh -p 2222' for non-standard ports
  • Add --backup --backup-dir=../old to keep replaced files
  • Schedule rsync backups with a systemd timer (sheet 23)

Quick Summary

  • scp — quick one-off copies
  • rsync -avz — efficient sync
  • -n before --delete — safety
  • sftp — interactive / GUI clients
