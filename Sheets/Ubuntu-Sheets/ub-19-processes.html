Sheet 19

Processes

ps aux · top / htop · kill / pkill / killall · signals · nice / renice · jobs / bg / fg · nohup

Description

A process is a running program with a PID, an owner, and resource usage. ps takes a snapshot, top/htop show live usage, and kill sends signals: TERM asks a process to exit cleanly, KILL forces it. Shell job control pauses, backgrounds and resumes commands you started.

Notes

  • kill sends TERM (15) by default
  • KILL (9) can't be caught: no cleanup happens
  • Niceness −20 (high priority) to 19 (low)
  • Zombie (Z) = finished, parent hasn't collected it

Inspect and Control

ps aux --sort=-%mem | head -5       # top memory users
ps -ef --forest | less              # tree of parent/child
pgrep -a nginx                      # PIDs + command lines
pidof sshd
htop                                # F6 sort, F9 kill, F10 quit
kill 4321                           # polite: SIGTERM
kill -9 4321                        # forced: SIGKILL (last resort)
pkill -f "python worker.py"         # by command line
sudo kill -HUP $(pidof nginx | cut -d' ' -f1)   # reload config
nice -n 10 tar -czf big.tgz /data   # start with low priority
sudo renice -n 5 -p 4321            # change priority
sleep 300 &                         # background job
jobs; fg %1                         # list, bring to front
nohup ./long-task.sh > task.log 2>&1 &   # survive logout

Code Explained

ps aux — all processes, user-oriented
pgrep -a — find by name with full command
kill then kill -9 — escalate only if needed
-HUP — many daemons reload config
nohup ... & — keep running after logout

Other Distros

  • Debian/Fedora — same procps tools
  • macOS — ps aux works; top -o mem; no htop by default

Prefer / Avoid

  • Avoid kill -9 first · Prefer TERM, wait, then KILL
  • Avoid nohup for real services · Prefer a systemd unit (sheet 21)

⚠ Common Mistakes

  • kill -9 on a database: risk of corruption and lost writes
  • killall on another Unix kills *all* processes; on Linux it matches names
  • Many D state processes usually mean a disk or NFS problem

✓ Tips & Best Practices

  • Use btop for a prettier dashboard (apt install btop)
  • Use tmux for long interactive jobs over SSH
  • lsof -p PID shows files and sockets a process holds

Quick Summary

  • ps / htop — see processes
  • kill — send signals (TERM first)
  • nice / renice — priority
  • &, jobs, fg — job control
