Sheet 41

cloud-init & Autoinstall

#cloud-config · users / packages / runcmd · cloud-init status · autoinstall YAML · cloud images

Description

cloud-init configures a machine on its first boot from a YAML file: users and SSH keys, packages, files and commands. Every Ubuntu cloud image, Multipass VM and LXD instance supports it. Autoinstall uses a similar YAML to install Ubuntu Server from the ISO without answering any prompts, so your servers are repeatable.

Notes

  • File must start with #cloud-config
  • Runs once per instance (first boot)
  • Logs: /var/log/cloud-init-output.log
  • Autoinstall config goes under an autoinstall: key

user-data (#cloud-config)

#cloud-config
hostname: web1
timezone: America/Chicago
users:
  - name: bob
    groups: [sudo, docker]
    shell: /bin/bash
    sudo: "ALL=(ALL) NOPASSWD:ALL"
    ssh_authorized_keys:
      - ssh-ed25519 AAAAC3Nza... bob@laptop
package_update: true
packages: [nginx, fail2ban, htop]
write_files:
  - path: /etc/motd
    content: "Managed by cloud-init\n"
runcmd:
  - ufw allow OpenSSH && ufw --force enable

Use and Debug

multipass launch 26.04 -n web1 --cloud-init user-data.yaml
cloud-init status --wait          # status: done
cloud-init schema --config-file user-data.yaml   # validate

Code Explained

users: — accounts, groups, SSH keys
packages: — installed on first boot
write_files: — drop config files
runcmd: — shell commands, run last
schema — validate before booting

Other Distros

  • Debian/Fedora — cloud images also use cloud-init
  • Installers: Debian preseed, Fedora/RHEL Kickstart
  • macOS — MDM profiles instead

Prefer / Avoid

  • Avoid clicking through installs for every server · Prefer autoinstall/cloud-init YAML
  • Avoid NOPASSWD:ALL on long-lived servers · Prefer password sudo after setup

⚠ Common Mistakes

  • Missing #cloud-config first line: file ignored
  • YAML indentation errors: whole config skipped silently
  • Expecting changes to apply on reboot: cloud-init runs once per instance

✓ Tips & Best Practices

  • Use cloud-init clean --logs --reboot to re-run while testing
  • Serve autoinstall from a USB CIDATA volume or HTTP
  • Keep the YAML in git as documentation of your servers
