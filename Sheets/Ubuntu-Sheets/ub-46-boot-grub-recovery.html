Sheet 46

Boot, GRUB & Recovery

GRUB menu · /etc/default/grub · update-grub · recovery mode · systemd-analyze blame · kernels · fix fstab

Description

GRUB is the boot menu that loads the Linux kernel. Its settings live in /etc/default/grub and take effect after update-grub. When a system won't boot, pick an older kernel or recovery mode from the GRUB menu, or boot a live USB and repair from there. systemd-analyze shows what slows boot down.

Notes

  • Hold Shift (BIOS) or tap Esc (UEFI) to show the menu
  • Ubuntu keeps the previous kernel as a fallback
  • Recovery mode → root shell: remount with mount -o remount,rw /
  • Emergency mode usually means a bad /etc/fstab

⚠ Danger Check

  • A broken GRUB config can make the system unbootable
  • Removing the running or only kernel leaves nothing to boot
  • Have a live USB ready before editing boot settings

Tune and Repair Boot

sudoedit /etc/default/grub
#   GRUB_TIMEOUT_STYLE=menu
#   GRUB_TIMEOUT=5
#   GRUB_CMDLINE_LINUX_DEFAULT="quiet splash"
sudo update-grub                         # apply

systemd-analyze                          # total boot time
systemd-analyze blame | head             # slowest units
dpkg -l 'linux-image-*' | grep ^ii       # installed kernels
uname -r                                 # running kernel

# recovery mode → "root" shell:
mount -o remount,rw /
nano /etc/fstab                          # fix the bad line
systemctl default                        # continue booting

# from a live USB (reinstall GRUB):
sudo mount /dev/nvme0n1p2 /mnt && sudo mount /dev/nvme0n1p1 /mnt/boot/efi
for d in dev proc sys; do sudo mount --rbind /$d /mnt/$d; done
sudo chroot /mnt grub-install && sudo chroot /mnt update-grub

Code Explained

/etc/default/grub — menu and kernel options
update-grub — regenerate the boot config
systemd-analyze blame — slow services
recovery: remount / read-write to fix files
live USB + chroot — repair an unbootable install

Other Distros

  • Debian — same GRUB; Fedora — grub2-mkconfig, BLS entries
  • macOS — Recovery mode (Cmd+R / hold power on Apple silicon)

Prefer / Avoid

  • Avoid editing /boot/grub/grub.cfg · Prefer /etc/default/grub + update-grub
  • Avoid deleting old kernels by hand · Prefer apt autoremove

⚠ Common Mistakes

  • Forgetting update-grub after editing /etc/default/grub
  • Purging the running kernel during cleanup
  • Fixing fstab in recovery without remounting / read-write

✓ Tips & Best Practices

  • Set GRUB_TIMEOUT_STYLE=menu on servers with console access
  • Use nofail in fstab for non-essential disks (sheet 25)
  • Boot-Repair (live USB) automates many GRUB fixes

Quick Summary

  • GRUB — boot menu, /etc/default/grub
  • update-grub — apply changes
  • recovery mode / older kernel — first aid
  • live USB + chroot — deep repair
