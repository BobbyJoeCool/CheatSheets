Sheet 34

fail2ban & SSH Hardening

fail2ban jails · jail.local · fail2ban-client status sshd · key-only auth · AllowUsers · non-default port

Description

Any server on the internet sees constant SSH login attempts. fail2ban watches logs and bans IPs that fail too often, using firewall rules. Combine it with SSH hardening: keys only, no root login, an allow-list of users, and optionally access only over a VPN. Changing the port reduces log noise but isn't real security.

Notes

  • apt install fail2ban; the sshd jail is enabled by default
  • Never edit jail.conf; override in jail.local or jail.d/
  • fail2ban reads systemd journal on Ubuntu
  • Whitelist your own IP with ignoreip

/etc/fail2ban/jail.local

[DEFAULT]
bantime  = 1h
findtime = 10m
maxretry = 5
ignoreip = 127.0.0.1/8 192.168.1.0/24
bantime.increment = true          # repeat offenders: longer bans

[sshd]
enabled = true
backend = systemd

Check and Manage

sudo systemctl enable --now fail2ban
sudo fail2ban-client status              # list jails
sudo fail2ban-client status sshd         # banned IPs, counts
sudo fail2ban-client set sshd unbanip 203.0.113.9
sudo sshd -T | grep -Ei 'passwordauth|permitroot|allowusers'

Code Explained

bantime / findtime / maxretry — ban policy
ignoreip — never ban your LAN
bantime.increment — escalating bans
backend = systemd — read the journal
sshd -T — print effective SSH settings

Other Distros

  • Debian — same fail2ban; Fedora — fail2ban + firewalld action
  • macOS — no fail2ban by default; Remote Login usually LAN-only

Prefer / Avoid

  • Avoid relying on a custom SSH port · Prefer keys + fail2ban (+ VPN)
  • Avoid editing jail.conf · Prefer jail.local

⚠ Common Mistakes

  • Banning yourself from a café IP with no ignoreip or console access
  • Editing jail.conf: overwritten on upgrade
  • Port-changing SSH and forgetting to update UFW rules first

✓ Tips & Best Practices

  • Put admin SSH behind Tailscale or WireGuard and close port 22 publicly
  • Add jails for nginx (nginx-http-auth, nginx-botsearch)
  • Check journalctl -u ssh | grep Failed to see attack volume

Quick Summary

  • fail2ban — ban IPs after failures
  • jail.local — your overrides
  • keys only, no root — SSH basics
  • VPN — best way to hide SSH
