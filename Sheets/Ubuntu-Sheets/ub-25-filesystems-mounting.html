Sheet 25

Filesystems & Mounting

mkfs.ext4 · mount / umount · /etc/fstab · UUIDs · nofail · mount -a · USB drives

Description

A partition becomes usable once it has a filesystem (mkfs) and is mounted on a directory. /etc/fstab lists mounts to set up at every boot; always use UUIDs there and test with mount -a before rebooting. ext4 is Ubuntu's default; XFS, Btrfs and ZFS are alternatives.

Notes

  • Mount point must be an existing (empty) directory
  • findmnt --verify checks fstab syntax
  • nofail lets the system boot if the disk is missing
  • Desktop auto-mounts USB drives under /media/$USER

⚠ Danger Check

  • mkfs on the wrong device erases it
  • A bad fstab line can drop the server into emergency mode at boot
  • Always run sudo mount -a (and findmnt --verify) before rebooting

Format, Mount, Persist

sudo mkfs.ext4 -L data /dev/sdb1     # create filesystem, label "data"
sudo mkdir -p /srv/data
sudo mount /dev/sdb1 /srv/data       # mount now
df -h /srv/data
sudo blkid /dev/sdb1                 # UUID="3f2a...-..." TYPE="ext4"

# /etc/fstab  (one line)
# UUID=3f2a...  /srv/data  ext4  defaults,nofail  0  2

sudo findmnt --verify                # syntax check
sudo umount /srv/data && sudo mount -a   # test fstab
findmnt /srv/data                    # mounted again? good
sudo umount /media/bob/USB           # eject USB safely
sudo lsof +f -- /srv/data            # who blocks umount?

Code Explained

mkfs.ext4 -L — format with a label
mount dev dir — attach now (not persistent)
fstab fields — what, where, type, options, dump, fsck order
nofail — boot even if missing
mount -a — mount everything in fstab now

Other Distros

  • Debian — same; Fedora defaults to Btrfs with subvolumes
  • macOS — diskutil mount, APFS; /etc/fstab rarely used

Prefer / Avoid

  • Avoid /dev/sdb1 in fstab · Prefer UUID= or LABEL=
  • Avoid rebooting after fstab edits untested · Prefer mount -a first

⚠ Common Mistakes

  • Typo in fstab → emergency mode; fix from recovery (sheet 46)
  • Mounting over a non-empty directory hides its files
  • Pulling a USB drive without umount: data loss

✓ Tips & Best Practices

  • Label filesystems and use LABEL= for readability
  • Use x-systemd.automount for network shares
  • Check filesystem with sudo fsck -f /dev/sdb1 (unmounted only)

Quick Summary

  • mkfs — create filesystem
  • mount / umount — attach / detach
  • /etc/fstab + UUID — persistent
  • mount -a — test before reboot
