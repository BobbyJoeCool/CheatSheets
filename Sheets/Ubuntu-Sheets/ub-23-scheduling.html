Sheet 23

Scheduling Jobs

crontab -e · cron syntax · /etc/cron.d · systemd timers · OnCalendar= · list-timers · at

Description

Run commands on a schedule with cron (simple, classic) or systemd timers (logged in the journal, can catch up missed runs, dependency-aware). Use at for a one-off job later. Cron uses a five-field schedule; timers use OnCalendar= expressions like Mon..Fri 02:30.

Notes

  • Cron runs with a minimal PATH: use full paths
  • Cron output is mailed or lost; redirect it to a log
  • Timers need a matching .service unit
  • Persistent=true runs missed jobs after boot

cron

crontab -e                        # your user's crontab
# m  h  dom mon dow  command
30   2  *   *   *    /usr/local/bin/backup.sh >> /var/log/backup.log 2>&1
*/15 *  *   *   1-5  /usr/bin/curl -fsS https://hc-ping.com/abc
crontab -l                        # list
echo "uptime" | at 17:00          # one-off job

systemd timer: backup.timer (+ backup.service)

[Unit]
Description=Nightly backup

[Timer]
OnCalendar=*-*-* 02:30:00
Persistent=true
RandomizedDelaySec=10m

[Install]
WantedBy=timers.target
# sudo systemctl enable --now backup.timer
# systemctl list-timers

Code Explained

five fields — minute hour day month weekday
*/15 — every 15; 1-5 — Mon–Fri
>> log 2>&1 — keep output and errors
OnCalendar= — when the timer fires
Persistent=true — catch up after downtime

Other Distros

  • Debian — same cron + timers; Fedora uses cronie
  • macOS — launchd StartCalendarInterval; cron still works

Prefer / Avoid

  • Avoid silent cron jobs · Prefer logging + a health-check ping
  • Avoid cron for jobs needing ordering/retries · Prefer systemd timers

⚠ Common Mistakes

  • Commands work in your shell but fail in cron: missing PATH or env vars
  • % in crontab lines must be escaped as \%
  • Editing /etc/crontab without the user field

✓ Tips & Best Practices

  • Test schedules at crontab.guru or with systemd-analyze calendar
  • Use flock -n /tmp/job.lock cmd to prevent overlapping runs
  • Ping a monitor (Healthchecks.io) at the end of important jobs

Quick Summary

  • cron — m h dom mon dow cmd
  • systemd timers — logged, persistent
  • at — one-off jobs
  • full paths + logs — reliable jobs
