Sheet 26

LVM

PV / VG / LV · pvcreate · vgcreate · lvcreate · lvextend -r · resize2fs · snapshots

Description

LVM (Logical Volume Manager) puts a flexible layer between disks and filesystems. Physical volumes (disks/partitions) form a volume group (a pool), which is carved into logical volumes that behave like partitions but can grow, span disks and be snapshotted. Ubuntu Server uses LVM by default and leaves free space in the pool.

Notes

  • Default server VG: ubuntu-vg, LV: ubuntu-lv
  • Growing ext4/XFS online is safe and common
  • Shrinking needs unmounting (ext4) and is riskier
  • LVM is not RAID or backup by itself

⚠ Danger Check

  • Shrinking an LV smaller than its filesystem destroys data
  • lvremove / vgremove delete without a second chance
  • Back up before any shrink or reorganization

Grow Root & Add a Disk

sudo vgs                                   # VG size and free space
sudo lvs                                   # logical volumes
sudo pvs                                   # physical volumes

# use the free space Ubuntu left unallocated
sudo lvextend -r -l +100%FREE /dev/ubuntu-vg/ubuntu-lv
df -h /                                    # bigger, no reboot

# add a new disk to the pool
sudo pvcreate /dev/sdc
sudo vgextend ubuntu-vg /dev/sdc
sudo lvcreate -n media -L 500G ubuntu-vg   # new LV
sudo mkfs.ext4 /dev/ubuntu-vg/media

# snapshot before a risky change
sudo lvcreate -s -n root-snap -L 10G /dev/ubuntu-vg/ubuntu-lv
sudo lvremove /dev/ubuntu-vg/root-snap     # when done

Code Explained

vgs / lvs / pvs — summaries
lvextend -r — grow LV and filesystem
+100%FREE — use all free space in the VG
pvcreate + vgextend — add disk to pool
lvcreate -s — copy-on-write snapshot

Other Distros

  • Debian/Fedora — same LVM2 tools; Fedora prefers Btrfs
  • macOS — APFS containers/volumes play a similar role

Prefer / Avoid

  • Avoid filling the VG at install · Prefer leaving free space to grow into
  • Avoid keeping LVM snapshots for days · Prefer short-lived snapshots

Layers

Common Commands

CommandDoes
lvextend -r -L +20G lvgrow by 20 GB
lvreduce -r -L 50G lvshrink (risky)
lvrename vg old newrename
vgreduce vg /dev/sdcremove empty PV
pvmove /dev/sdbmove data off a PV

⚠ Common Mistakes

  • lvextend without -r, then df still shows the old size
  • Snapshots filling up and becoming invalid
  • Spanning a VG across disks without RAID: one dead disk loses the LV

✓ Tips & Best Practices

  • sudo lvextend -r -l +100%FREE is the classic post-install fix
  • Use pvmove to migrate off a failing disk online
  • Combine with mdadm RAID for redundancy (sheet 27)

Quick Summary

  • PV → VG → LV — flexible storage
  • lvextend -r — grow online
  • vgextend — add disks
  • snapshots — short-term safety net
