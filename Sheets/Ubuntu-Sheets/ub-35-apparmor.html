Sheet 35

AppArmor

profiles · enforce vs complain · aa-status · aa-complain / aa-enforce · snap confinement · denials

Description

AppArmor is Ubuntu's mandatory access control system. Each profile limits what one program may read, write and execute, even if it runs as root. Profiles run in enforce mode (block and log) or complain mode (log only). Snaps, LXD and many services ship with profiles out of the box.

Notes

  • Enabled by default; Fedora/RHEL use SELinux instead
  • Profiles live in /etc/apparmor.d/
  • Denials show as apparmor="DENIED" in the kernel log
  • apparmor-utils provides aa-* tools

Check and Adjust Profiles

sudo aa-status                           # loaded profiles + modes
sudo aa-status | grep -A3 "enforce mode"
sudo journalctl -k | grep 'apparmor="DENIED"' | tail
# ... apparmor="DENIED" operation="open" profile="/usr/sbin/nginx"
#     name="/data/www/index.html" requested_mask="r"

sudo apt install apparmor-utils
sudo aa-complain /usr/sbin/nginx         # log only, while debugging
sudo aa-logprof                          # turn denials into rules
sudo aa-enforce /usr/sbin/nginx          # back to blocking
sudo apparmor_parser -r /etc/apparmor.d/usr.sbin.nginx   # reload one
ls /etc/apparmor.d/local/                # site-specific additions

Code Explained

aa-status — which profiles, which mode
DENIED line — profile, operation, path
aa-complain — temporarily log instead of block
aa-logprof — interactive rule builder
local/ — add rules without editing vendor profiles

Other Distros

  • Debian — AppArmor enabled by default too
  • Fedora/RHEL — SELinux: getenforce, ausearch, setsebool
  • macOS — sandbox profiles + SIP

Prefer / Avoid

  • Avoid disabling AppArmor to fix one app · Prefer a rule in local/
  • Avoid leaving profiles in complain mode · Prefer enforce once fixed

Modes

⚠ Common Mistakes

  • Moving a service's data dir (e.g. MySQL to /data) and getting mysterious permission errors
  • Disabling AppArmor system-wide instead of fixing one rule
  • Editing vendor profiles that updates overwrite

✓ Tips & Best Practices

  • Check the kernel log for DENIED before chasing file permissions
  • Add paths in /etc/apparmor.d/local/usr.sbin.<prog> then reload
  • Snap apps' confinement is AppArmor too (snap connections)

Quick Summary

  • profiles — per-program restrictions
  • enforce vs complain — block vs log
  • DENIED logs — journalctl -k
  • local/ overrides — safe customizing
