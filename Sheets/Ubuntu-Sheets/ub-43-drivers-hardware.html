Drivers & Hardware

ubuntu-drivers devices / install · NVIDIA · lspci / lsusb · lshw · fwupdmgr · printers & Bluetooth

Description

Most hardware works out of the box because drivers are in the kernel. For proprietary drivers (NVIDIA GPUs, some Wi-Fi chips), ubuntu-drivers detects the hardware and installs the recommended package. lspci, lsusb and lshw identify devices, and fwupdmgr updates firmware from the LVFS.

Notes

  • Secure Boot may ask you to enroll a key (MOK) for drivers
  • Desktop GUI: Software & Updates → Additional Drivers
  • -server NVIDIA drivers exist for headless machines
  • Old MacBooks often need broadcom-sta-dkms for Wi-Fi

Identify and Install

lspci -nnk | grep -A3 -i vga        # GPU + driver in use
lsusb                               # USB devices
sudo lshw -short                    # full hardware summary
inxi -Fxz                           # readable overview

ubuntu-drivers devices              # detected + recommended
sudo ubuntu-drivers install         # install recommended drivers
sudo ubuntu-drivers install nvidia:570  # pick version
nvidia-smi                          # GPU status after reboot

fwupdmgr get-devices
fwupdmgr refresh && fwupdmgr get-updates
sudo fwupdmgr update                # BIOS/firmware updates

bluetoothctl                        # power on, scan on
lpstat -p                           # printers (CUPS)

Code Explained

lspci -nnk — device IDs + driver in use
ubuntu-drivers devices — what's recommended
ubuntu-drivers install — install them
nvidia-smi — confirms the NVIDIA driver works
fwupdmgr — vendor firmware updates

Other Distros

  • Debian — non-free-firmware repo, nvidia-detect
  • Fedora — RPM Fusion for NVIDIA (akmod-nvidia)
  • macOS — drivers ship with the OS

Prefer / Avoid

  • Avoid NVIDIA's .run installer · Prefer ubuntu-drivers packages
  • Avoid random PPAs for drivers · Prefer Ubuntu's restricted repo

⚠ Common Mistakes

  • Skipping MOK enrollment after installing drivers with Secure Boot: driver won't load
  • Mixing .run NVIDIA installs with packaged drivers
  • Updating firmware on battery power

✓ Tips & Best Practices

  • Use sudo dmesg | grep -i firmware to spot missing firmware
  • Search the hardware ID (8086:a0f0) for known issues
  • Use the HWE kernel (linux-generic-hwe-26.04) for newer hardware

Quick Summary

  • lspci / lsusb / lshw — identify
  • ubuntu-drivers — proprietary drivers
  • fwupdmgr — firmware updates
  • MOK enroll — drivers with Secure Boot
