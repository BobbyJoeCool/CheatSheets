Sheet 21

Writing Service Units

/etc/systemd/system/app.service · [Unit] / [Service] / [Install] · ExecStart · Restart=on-failure · User= · daemon-reload · systemctl edit

Description

Run your own app as a proper service by writing a unit file in /etc/systemd/system/. systemd then starts it at boot, restarts it if it crashes, runs it as an unprivileged user, and sends its output to the journal. To tweak a packaged service, use systemctl edit to create an override instead of editing the vendor file.

Notes

  • Run daemon-reload after creating or editing units
  • Use absolute paths in ExecStart
  • stdout/stderr go to the journal automatically
  • Overrides land in /etc/systemd/system/<unit>.d/override.conf

/etc/systemd/system/todo-api.service

[Unit]
Description=Todo API (FastAPI)
After=network-online.target postgresql.service
Wants=network-online.target

[Service]
User=todo
Group=todo
WorkingDirectory=/srv/todo-api
EnvironmentFile=/etc/todo-api.env
ExecStart=/srv/todo-api/.venv/bin/fastapi run app/main.py --port 8000
Restart=on-failure
RestartSec=5
NoNewPrivileges=true
ProtectSystem=strict
ReadWritePaths=/srv/todo-api/data

[Install]
WantedBy=multi-user.target

Load It

sudo systemctl daemon-reload
sudo systemctl enable --now todo-api
sudo systemctl edit nginx     # opens an override.conf

Code Explained

After= / Wants= — start order and soft dependency
User= — never run apps as root
EnvironmentFile= — secrets outside the unit
Restart=on-failure — auto-restart crashes
ProtectSystem=strict — read-only OS for the service

Other Distros

  • Debian/Fedora — identical unit files
  • macOS — launchd plist in /Library/LaunchDaemons/

Prefer / Avoid

  • Avoid nohup / screen for services · Prefer a unit file
  • Avoid copying vendor units to edit · Prefer systemctl edit overrides

⚠ Common Mistakes

  • Forgetting daemon-reload: systemd keeps the old definition
  • Relative paths in ExecStart: "Executable path is not absolute"
  • Secrets in Environment= lines, readable by systemctl show

✓ Tips & Best Practices

  • Check hardening with systemd-analyze security todo-api
  • Use Type=notify for apps that support sd_notify
  • Test the exact ExecStart command as that user first

Quick Summary

  • unit file — [Unit] [Service] [Install]
  • User= + Restart=on-failure — safe, resilient
  • daemon-reload → enable --now
  • systemctl edit — override packaged units
