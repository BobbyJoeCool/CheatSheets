Sheet 33

UFW Firewall

ufw allow OpenSSH · ufw enable · allow 443/tcp · from 192.168.1.0/24 · status numbered · delete · app profiles

Description

UFW (Uncomplicated Firewall) is Ubuntu's friendly front end to the kernel firewall (nftables). It's installed but inactive by default. The usual setup: deny incoming, allow outgoing, allow SSH, then open only the ports your services need, optionally limited to your LAN.

Notes

  • Rules apply to IPv4 and IPv6
  • App profiles live in /etc/ufw/applications.d/
  • limit rate-limits repeated connections (SSH)
  • Docker can bypass UFW rules (sheet 38)

⚠ Danger Check

  • ufw enable without an SSH rule cuts off remote sessions
  • Always ufw allow OpenSSH (or your port) first
  • ufw reset deletes all rules and disables the firewall

Baseline Server Firewall

sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow OpenSSH                    # or: sudo ufw limit 22/tcp
sudo ufw enable                           # turn it on
sudo ufw status verbose

sudo ufw allow 80,443/tcp                 # web server
sudo ufw allow from 192.168.1.0/24 to any port 445  # LAN
sudo ufw allow in on wg0                  # all from VPN
sudo ufw deny from 203.0.113.50           # block one address
sudo ufw app list                         # Nginx Full, OpenSSH, ...
sudo ufw allow "Nginx Full"

sudo ufw status numbered
sudo ufw delete 4                         # remove rule #4
sudo ufw logging on                       # log blocked packets

Code Explained

defaults — block in, allow out
allow OpenSSH — app profile for port 22
from <net> to any port — LAN-only rule
status numbered + delete N — remove rules
logging on — blocks appear in the kernel log

Other Distros

  • Debian — ufw available, nftables underneath
  • Fedora/RHEL — firewalld with firewall-cmd --add-service=
  • macOS — Application Firewall + pf

Prefer / Avoid

  • Avoid opening ports "just in case" · Prefer allowing only what runs
  • Avoid exposing admin services publicly · Prefer from <LAN/VPN> rules

⚠ Common Mistakes

  • Enabling UFW over SSH before allowing SSH
  • Believing UFW protects Docker-published ports (it often doesn't)
  • Rule order: an earlier allow beats a later deny

✓ Tips & Best Practices

  • Use ufw limit on SSH to slow brute force
  • Bind databases to 127.0.0.1 as well as firewalling them
  • Keep a console path (VM console) when changing firewall rules

Quick Summary

  • deny in / allow out — baseline
  • allow OpenSSH before enable
  • from <net> — restrict by source
  • status numbered / delete — manage
