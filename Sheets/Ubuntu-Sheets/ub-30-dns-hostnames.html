Sheet 30

DNS & Hostnames

hostnamectl set-hostname · /etc/hosts · systemd-resolved · resolvectl status · dig / nslookup · mDNS .local

Description

Ubuntu resolves names through systemd-resolved, a local DNS stub at 127.0.0.53 that /etc/resolv.conf points to. resolvectl shows which DNS servers each interface uses and lets you flush the cache. /etc/hosts overrides DNS for specific names, and Avahi answers hostname.local on your LAN.

Notes

  • Don't edit /etc/resolv.conf directly; it's managed
  • Set DNS servers in Netplan (sheet 29)
  • dig is in the bind9-dnsutils package
  • mDNS (.local) needs avahi-daemon (desktop default)

Names In, Names Out

hostnamectl                           # Static hostname: homeserver
sudo hostnamectl set-hostname homeserver
grep homeserver /etc/hosts            # 127.0.1.1 homeserver
resolvectl status                     # DNS servers per link
resolvectl query ubuntu.com           # resolve via resolved
dig +short ubuntu.com A               # direct DNS query
dig @1.1.1.1 example.com MX           # ask a specific server
nslookup example.com
sudo resolvectl flush-caches
getent hosts nas.home.lan             # what apps will see
echo "192.168.1.30 nas nas.home.lan" | sudo tee -a /etc/hosts
sudo apt install avahi-daemon         # then: ssh bob@homeserver.local

Code Explained

hostnamectl set-hostname — permanent name
127.0.1.1 line — lets the host resolve itself
resolvectl status — which DNS is really used
dig +short — just the answer
getent hosts — uses the full resolver order

Other Distros

  • Debian — resolved optional; often plain /etc/resolv.conf
  • Fedora — systemd-resolved too
  • macOS — scutil --dns, dscacheutil -flushcache

Prefer / Avoid

  • Avoid editing /etc/resolv.conf · Prefer Netplan nameservers / resolvectl
  • Avoid long /etc/hosts lists · Prefer local DNS (router, Pi-hole)

⚠ Common Mistakes

  • Hostname changed but not in /etc/hosts: "sudo: unable to resolve host"
  • Testing with dig (bypasses /etc/hosts) and expecting hosts entries
  • Port 53 conflicts when installing Pi-hole/dnsmasq next to resolved

✓ Tips & Best Practices

  • Use dig +trace to follow a lookup from the root servers
  • Run Pi-hole or AdGuard Home for a LAN-wide DNS
  • Disable the resolved stub (DNSStubListener=no) before running a DNS server

Quick Summary

  • hostnamectl — set the name
  • systemd-resolved — local DNS stub
  • resolvectl / dig — inspect DNS
  • /etc/hosts / .local — local names
