ZFS & Software RAID

zpool create · mirrors / raidz · zfs create · snapshots · zpool status · mdadm RAID 1/5 · scrubs

Description

ZFS combines RAID, volume management and a filesystem, with checksums that detect silent corruption, cheap snapshots and compression. Ubuntu supports it out of the box (zfsutils-linux). mdadm is classic Linux software RAID under any filesystem. Both protect against disk failure, but RAID is not backup.

Notes

  • Mirror (RAID 1): 2+ disks, survives 1 failure per mirror
  • raidz1/2: survives 1/2 disk failures
  • ZFS likes lots of RAM and whole disks
  • Scrub monthly to find and repair bad blocks

⚠ Danger Check

  • zpool create / mdadm --create wipe the member disks
  • Use /dev/disk/by-id/ names, or pools break when sdX names change
  • Deleting a dataset or destroying a pool is permanent

ZFS Mirror & mdadm RAID 1

sudo apt install zfsutils-linux
sudo zpool create -o ashift=12 tank mirror \
    /dev/disk/by-id/ata-WDC_A /dev/disk/by-id/ata-WDC_B
sudo zfs set compression=lz4 tank
sudo zfs create tank/photos               # dataset at /tank/photos
sudo zfs snapshot tank/photos@2026-11-13
zfs list -t snapshot
sudo zfs rollback tank/photos@2026-11-13  # undo changes
zpool status                              # health, errors
sudo zpool scrub tank

sudo apt install mdadm
sudo mdadm --create /dev/md0 --level=1 \
    --raid-devices=2 /dev/sdb1 /dev/sdc1
cat /proc/mdstat                          # sync progress
sudo mdadm --detail --scan | sudo tee -a /etc/mdadm/mdadm.conf

Code Explained

mirror — two-disk ZFS mirror
ashift=12 — 4K sectors (modern disks)
compression=lz4 — free space, often faster
zfs snapshot / rollback — instant restore points
mdadm --create --level=1 — RAID 1 device

Other Distros

  • Debian — ZFS from contrib (DKMS); Fedora — via OpenZFS repo
  • macOS — OpenZFS on OS X port; no built-in software RAID UI beyond Disk Utility

Prefer / Avoid

  • Avoid RAID as your only copy · Prefer RAID + off-site backup
  • Avoid sdX names in pools · Prefer /dev/disk/by-id/

⚠ Common Mistakes

  • Mixing disk sizes: pool uses the smallest
  • Ignoring DEGRADED status until the second disk dies
  • Filling ZFS above ~80%: performance drops sharply

✓ Tips & Best Practices

  • Automate snapshots with zfs-auto-snapshot or sanoid
  • Send snapshots off-box: zfs send | ssh backup zfs recv
  • Set up email alerts (zed or mdadm MAILADDR)

Quick Summary

  • ZFS — RAID + volumes + checksummed FS
  • mirror / raidz — redundancy
  • snapshots + scrubs — safety and integrity
  • mdadm — classic software RAID
