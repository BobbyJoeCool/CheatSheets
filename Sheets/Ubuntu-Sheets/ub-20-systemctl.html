Sheet 20

systemd & systemctl

units · systemctl start / stop / restart / status · enable --now · is-active · list-units --failed · targets

Description

systemd starts the system and manages long-running services. Each thing it manages is a unit (.service, .timer, .socket, .mount). systemctl controls units: start and stop them now, enable them to start at boot, and check status with the latest log lines.

Notes

  • enable = start at boot; start = start now
  • enable --now does both
  • reload re-reads config without dropping connections (if supported)
  • --user manages your own per-user services

Managing Services

systemctl status nginx                  # state + recent logs
sudo systemctl start nginx
sudo systemctl stop nginx
sudo systemctl restart nginx
sudo systemctl reload nginx             # graceful config reload
sudo systemctl enable --now ssh         # boot + now
sudo systemctl disable --now apache2
systemctl is-active nginx               # active / inactive
systemctl is-enabled nginx              # enabled / disabled
systemctl list-units --type=service --state=running
systemctl --failed                      # anything broken?
systemctl cat nginx                     # show unit file(s)
sudo systemctl mask cups                # block from starting at all
systemctl list-dependencies multi-user.target | head

Code Explained

status — running? since when? last logs
reload vs restart — keep vs drop connections
enable --now — common one-liner
--failed — quick health check
mask — stronger than disable

Other Distros

  • Debian/Fedora — same systemd and systemctl
  • macOS — launchctl + plist files; brew services start

Prefer / Avoid

  • Avoid old service nginx restart · Prefer systemctl restart nginx
  • Avoid restarting to apply config · Prefer reload when supported

⚠ Common Mistakes

  • enable without start and wondering why it's not running
  • Restarting SSH with a broken config: test with sshd -t first
  • Editing unit files in /usr/lib/systemd (overwritten by updates)

✓ Tips & Best Practices

  • systemctl status + journalctl -u name -e solve most issues
  • Override units with systemctl edit (sheet 21)
  • systemctl list-timers shows scheduled jobs

Quick Summary

  • units — services, timers, mounts, targets
  • start/stop/restart/reload — now
  • enable/disable — at boot
  • status / --failed — health
