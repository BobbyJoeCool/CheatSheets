Sheet 18

Updates & Release Upgrades

unattended-upgrades · dpkg-reconfigure · needrestart · reboot-required · do-release-upgrade · LTS to LTS

Description

unattended-upgrades installs security updates automatically every day; it is enabled by default on Ubuntu. needrestart tells you which services need restarting after library updates. Moving to a new Ubuntu version is a separate, bigger step: do-release-upgrade, normally from one LTS to the next once the first point release is out.

Notes

  • LTS → LTS upgrades are offered after the .1 point release
  • Back up and read release notes before upgrading
  • Run release upgrades in tmux/screen over SSH
  • Kernel updates need a reboot (or Livepatch, sheet 36)

⚠ Danger Check

  • A release upgrade can break PPAs, custom configs and third-party repos
  • Losing SSH mid-upgrade can leave a half-upgraded system
  • Snapshot the VM or back up before do-release-upgrade

Automatic Updates & Release Upgrade

sudo apt install unattended-upgrades
sudo dpkg-reconfigure -plow unattended-upgrades   # enable
cat /etc/apt/apt.conf.d/20auto-upgrades
# APT::Periodic::Update-Package-Lists "1";
# APT::Periodic::Unattended-Upgrade "1";
sudo unattended-upgrade --dry-run --debug         # test
less /var/log/unattended-upgrades/unattended-upgrades.log

cat /var/run/reboot-required.pkgs 2>/dev/null     # why reboot?
sudo needrestart -r l                             # list restarts

# new Ubuntu version (LTS → LTS)
sudo apt update && sudo apt full-upgrade
sudo do-release-upgrade                           # follow prompts
sudo do-release-upgrade -c                        # just check

Code Explained

dpkg-reconfigure -plow — turn auto updates on
20auto-upgrades — daily update + upgrade
--dry-run --debug — see what would happen
reboot-required.pkgs — packages needing reboot
do-release-upgrade — move to next release

Other Distros

  • Debian — unattended-upgrades too; release upgrade by editing sources
  • Fedora — dnf-automatic; dnf system-upgrade
  • macOS — automatic updates in System Settings

Prefer / Avoid

  • Avoid skipping security updates · Prefer unattended-upgrades + regular reboots
  • Avoid upgrading on day one of a release · Prefer waiting for .1

⚠ Common Mistakes

  • Killing unattended-upgr because it holds the apt lock
  • Never rebooting: patched kernels and libraries aren't in use yet
  • Jumping two LTS versions at once: upgrade one LTS at a time

✓ Tips & Best Practices

  • Enable Automatic-Reboot on servers that can take a 1-minute blip
  • Disable third-party repos before a release upgrade, re-add after
  • Check /var/log/dist-upgrade/ if an upgrade fails

Quick Summary

  • unattended-upgrades — daily security fixes
  • needrestart / reboot-required — apply them
  • do-release-upgrade — LTS → LTS
  • back up first; use tmux over SSH
