Sheet 07

Deleting Files Safely

rm / rm -r · rm -i · rmdir · trash-cli / gio trash · shred · no recycle bin

Description

On the command line, rm deletes immediately: there is no recycle bin and no undo. rm -r removes whole directory trees. Build safe habits: look before you delete, use -i or a trash tool for interactive work, and never combine sudo, -rf and a variable you haven't checked.

Notes

  • Deleted ≠ gone from disk, but recovery is unreliable
  • rmdir only removes empty directories (safe)
  • Desktop file manager uses Trash; rm doesn't
  • --preserve-root is on by default (rm -rf / refused)

⚠ Danger Check

  • sudo rm -rf "$DIR"/* with an empty $DIR becomes rm -rf /*
  • A stray space: rm -rf / tmp/x deletes from /
  • Use ls with the exact same arguments first

Delete With Care

rm old.log                         # gone, no undo
rm -i *.tmp                        # confirm each file
rm -I big-dir/*                    # one prompt for many files
rmdir empty-folder                 # fails if not empty: good
rm -r build/                       # directory tree
ls build/*.o && rm build/*.o       # preview, then delete

sudo apt install trash-cli
trash-put report.docx              # recoverable
trash-list && trash-restore
gio trash notes.txt                # GNOME trash, same idea

: "${DIR:?DIR is not set}"         # scripts: stop if empty
rm -rf -- "$DIR/cache"

Code Explained

rm -i / -I — prompts before deleting
rmdir — only empty dirs, a built-in safety
ls first — same glob, see what matches
trash-put — move to Trash instead
${DIR:?} — script aborts if DIR is empty

Other Distros

  • Debian/Fedora — same rm; trash-cli packaged too
  • macOS — rm the same; trash via Homebrew or Finder

Prefer / Avoid

  • Avoid rm -rf as muscle memory · Prefer rm -r and read prompts
  • Avoid rm -rf $VAR/ unquoted · Prefer "${VAR:?}"

rm Options

FlagEffect

Safer Alternatives

ToolUse
trash-putrecoverable delete
find ... -deleteafter a dry run without -delete
mv to ~/old/delete later
shred -u fileoverwrite then delete (HDD)

⚠ Common Mistakes

  • Running rm -rf in the wrong directory: check pwd first
  • Expecting shred to securely wipe SSDs: use full-disk encryption
  • Deleting a log a process still writes to: space isn't freed until it restarts

✓ Tips & Best Practices

  • Use find . -name '*.tmp' first, then add -delete
  • Truncate busy logs with : > app.log instead of deleting
  • Keep backups (sheet 47); they're the real undo

Quick Summary

  • rm — immediate, no undo
  • -i / trash-put — safety nets
  • preview with ls / find
  • ${VAR:?} — guard script deletes
