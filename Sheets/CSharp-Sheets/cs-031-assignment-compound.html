Assignment & Compound Assignment

= · += -= *= /= %= · &= |= ^= · (a, b) = (b, a) swap · ref locals · chained assignment

Assignment Operators

= stores a value and is itself an expression that returns the assigned value. Compound operators like += combine an operation with assignment and include an implicit cast back to the variable's type. Tuples allow swapping and multi-assignment, and ref locals let you assign through an alias.

Key Facts

  • x op= y is x = (T)(x op y) with x evaluated once
  • a = b = 0 assigns right to left
  • ??= assigns only when the left is null
  • C# 14 lets types define their own +=

Assignment Forms

int x = 10;
x += 5;   // 15
x -= 3;   // 12
x *= 2;   // 24
x /= 5;   // 4
x %= 3;   // 1

byte b = 250;
b += 10;              // OK: implicit cast → 4 (wraps)
// b = b + 10;        // CS0266: int can't convert to byte

int a = 1, c = 2;
(a, c) = (c, a);      // swap → a = 2, c = 1
var (name, age) = ("Ada", 36);   // deconstruct

int i, j;
i = j = 0;            // chained

int[] arr = [1, 2, 3];
ref int first = ref arr[0];
first = 99;           // arr[0] is now 99

Code Explained

+= -= *= /= %= — arithmetic compound
<<= |= — shift / bitwise compound
b += 10 — hidden cast back to byte
(a, c) = (c, a) — tuple swap, no temp
ref int — alias to an array element
(line = …) != null — assignment as expression

⚠ Common Mistakes

  • Expecting b = b + 1 to compile for byte — arithmetic yields int; use b++ or b += 1
  • Using x =+ 5 — that's x = +5, not x += 5
  • Hiding assignments inside conditions — legal, but keep it to the while ((x = …) != null) idiom

✓ Tips & Best Practices

  • Use tuple swap instead of a temporary variable
  • Use ??= to initialize caches and lazy fields
  • Prefer += for events; never = (it replaces other subscribers on fields)

Quick Summary

  • = — assign (also an expression)
  • op= — compound with implicit cast
  • (a, b) = (b, a) — swap
  • ref local — assign through an alias
