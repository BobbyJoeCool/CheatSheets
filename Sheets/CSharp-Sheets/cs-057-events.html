Publish and Subscribe

An event lets a class notify subscribers that something happened, without knowing who they are. It's declared with the event keyword on a delegate type — usually EventHandler or EventHandler<TEventArgs>. Outside code can only subscribe (+=) and unsubscribe (-=); only the declaring class can raise the event.

Key Facts

  • Standard signature: (object? sender, TEventArgs e)
  • Raise with Handler?.Invoke(this, args)
  • Subscribers keep the publisher's reference to them alive
  • Name events with verbs: Changed, Completed, Closing

Declaring & Using Events

public sealed class PriceChangedEventArgs(decimal old, decimal @new) : EventArgs
{ public decimal Old => old; public decimal New => @new; }

public class Stock
{
    private decimal _price;
    public event EventHandler<PriceChangedEventArgs>? PriceChanged;

    public void Update(decimal price)
    {
        var old = _price; _price = price;
        PriceChanged?.Invoke(this, new(old, price));   // raise
    }
}

var msft = new Stock();
void OnChange(object? s, PriceChangedEventArgs e) =>
    Console.WriteLine($"{e.Old} → {e.New}");
msft.PriceChanged += OnChange;      // subscribe
msft.Update(410);                   // 0 → 410
msft.PriceChanged -= OnChange;      // unsubscribe

Code Explained

EventArgs subclass — carries event data
event EventHandler<T>? — nullable: no subscribers yet
?.Invoke(this, …) — raise safely
+= / -= — subscribe / unsubscribe
Named handler — needed to unsubscribe later

⚠ Common Mistakes

  • Subscribing with a lambda and later trying -= with another lambda — it's a different delegate
  • Forgetting to unsubscribe from long-lived publishers — the subscriber can't be garbage-collected
  • Raising events without a null check — throws when nobody subscribed

✓ Tips & Best Practices

  • Follow (object? sender, TEventArgs e) so handlers are reusable
  • Unsubscribe in Dispose() for objects with shorter lives than the publisher
  • Consider IObservable<T> or channels for complex streams of events
