Dates, Times and Durations

DateTime stores a date and time with a Kind (Local, Utc, Unspecified); DateTimeOffset also stores the offset from UTC, so it identifies an exact instant — prefer it for timestamps. DateOnly and TimeOnly (.NET 6) represent just a date or a time, TimeSpan is a duration, and TimeProvider (.NET 8) makes "now" testable.

Key Facts

  • Store and compare times in UTC
  • Subtracting dates gives a TimeSpan
  • IANA zone IDs work on all OSes (.NET 6+)
  • Formatting is culture-sensitive unless you specify

Working with Time

DateTimeOffset now = DateTimeOffset.UtcNow;              // exact instant
DateTime local = DateTime.Now;                           // machine local
DateOnly birthday = new(1990, 7, 4);
TimeOnly opens = new(9, 30);

var due = now.AddDays(14).AddHours(-2);                  // arithmetic
TimeSpan left = due - now;                               // 13.22:00:00
Console.WriteLine(left.TotalHours);                      // 334
Console.WriteLine(TimeSpan.FromMinutes(90));             // 01:30:00

var parsed = DateOnly.ParseExact("2026-10-11", "yyyy-MM-dd");
Console.WriteLine(parsed.DayOfWeek);                     // Sunday
Console.WriteLine(now.ToString("O"));                    // ISO 8601 round-trip

var chicago = TimeZoneInfo.FindSystemTimeZoneById("America/Chicago");
DateTimeOffset there = TimeZoneInfo.ConvertTime(now, chicago);

public class Invoice(TimeProvider clock)                 // testable "now"
{
    public bool IsOverdue(DateTimeOffset due) => clock.GetUtcNow() > due;
}

Code Explained

DateTimeOffset.UtcNow — best for timestamps
DateOnly / TimeOnly — no time / no date
AddDays, AddHours — return new values (immutable)
due - now — TimeSpan difference
ParseExact — strict format parsing
TimeProvider — inject time; fake it in tests

⚠ Common Mistakes

  • Storing DateTime.Now in databases — local times are ambiguous across zones and DST; store UTC
  • Mixing Kind.Local and Kind.Utc values in arithmetic — results are silently wrong
  • Calling DateTime.Now directly in business logic — untestable; inject TimeProvider

✓ Tips & Best Practices

  • Use DateTimeOffset for anything that happened at a moment
  • Use DateOnly for birthdays and due dates
  • Use FakeTimeProvider (Microsoft.Extensions.TimeProvider.Testing) in tests

Quick Summary

  • DateTimeOffset — exact instants
  • DateOnly / TimeOnly — partial values
  • TimeSpan — durations
  • TimeProvider — testable clock
