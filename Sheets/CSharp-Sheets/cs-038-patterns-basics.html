Pattern Matching Essentials

Patterns test a value's shape and can extract parts of it. They appear after is, in switch cases and in switch-expression arms. The basic patterns check type, constant values, relational ranges and combine with and, or and not.

Key Facts

  • is T x declares x only when the match succeeds
  • is null / is not null can't be fooled by == overloads
  • Relational patterns need constant operands
  • not binds tighter than and, which binds tighter than or

Basic Patterns

object o = 42;

if (o is int n) Console.WriteLine(n + 1);       // type pattern → 43
if (o is 42) Console.WriteLine("answer");       // constant pattern
if (o is not null) { }                          // negated null

int t = 25;
string feel = t switch
{
    < 0            => "freezing",               // relational
    >= 0 and < 15  => "cold",                   // and
    >= 15 and < 25 => "mild",
    _              => "hot"
};

bool isVowel = c is 'a' or 'e' or 'i' or 'o' or 'u';  // or
bool isLetter = c is (>= 'a' and <= 'z') or (>= 'A' and <= 'Z');

if (o is var any) Console.WriteLine(any);       // var: always matches

Code Explained

is int n — type check + typed variable
is 42 — equality with a constant
< 0, >= 15 — relational patterns
and / or / not — combine patterns
Parentheses — group pattern logic
var x — match anything, capture it

⚠ Common Mistakes

  • Using a pattern variable outside its definite-assignment scope — n exists only where the match is known true
  • Writing x is > a with a variable a — relational patterns need constants; use x > a
  • Expecting is not A or B to mean not (A or B) — not binds first; add parentheses

✓ Tips & Best Practices

  • Replace as + null check with is T x
  • Use is null for null checks in generic or operator-overloaded code
  • Combine ranges in one pattern: is >= 1 and <= 100
