async / await — Pitfalls

async void · .Result / .Wait() deadlocks · ConfigureAwait(false) · fire-and-forget · WhenAll exceptions · await foreach

Async Traps to Avoid

Most async bugs come from a few patterns: async void, blocking on tasks (.Result, .Wait()), fire-and-forget without error handling, and misunderstanding where code resumes. Library code adds ConfigureAwait(false) to avoid capturing a UI or legacy ASP.NET context. These rules keep async code correct and debuggable.

Key Facts

  • ASP.NET Core has no sync context — deadlocks are rarer there
  • UI apps (WPF, WinForms, MAUI) resume on the UI thread
  • Unobserved task exceptions are silently lost
  • await using / await foreach exist for async resources

Wrong vs Right

async void Save() { await db.SaveChangesAsync(); }     // ✗ crashes on error
async Task SaveAsync() { await db.SaveChangesAsync(); } // ✓ awaitable

var data = LoadAsync().Result;                         // ✗ blocks, may deadlock
var data2 = await LoadAsync();                         // ✓

// ✗ fire-and-forget: errors vanish
_ = SendEmailAsync(user);
// ✓ queue it to a background service, or at least observe errors
_ = SendEmailAsync(user).ContinueWith(t => log.LogError(t.Exception, "email"),
        TaskContinuationOptions.OnlyOnFaulted);

// Library code: don't resume on the caller's context
public async Task<string> ReadAsync(string p) =>
    await File.ReadAllTextAsync(p).ConfigureAwait(false);

// ✗ lock + await isn't allowed; ✓ use SemaphoreSlim
await _gate.WaitAsync();
try { await WriteAsync(); } finally { _gate.Release(); }

Code Explained

async void — only for event handlers
.Result — blocks a thread, may deadlock
_ = — discards the task; exceptions unobserved
ContinueWith(OnlyOnFaulted) — minimal error logging
ConfigureAwait(false) — for libraries
SemaphoreSlim — async-friendly lock

⚠ Common Mistakes

  • Wrapping sync APIs in Task.Run inside libraries — let callers decide
  • Returning null from a Task-returning method — callers' await throws; return Task.CompletedTask
  • Assuming await always switches threads — it may complete synchronously

✓ Tips & Best Practices

  • Turn on analyzers (CA2007, VSTHRD*) to catch async misuse
  • Use IHostedService + Channel<T> for background jobs
  • In ASP.NET Core apps ConfigureAwait(false) is optional

Quick Summary

  • No async void (except events)
  • No .Result / .Wait()
  • Observe fire-and-forget tasks
  • SemaphoreSlim instead of lock with await
