Indexers and Partial Types

An indexer this[…] lets objects be accessed with [] like arrays or dictionaries. Partial types split one class across several files — commonly one written by you and one by a source generator or designer. Partial methods, properties (C# 13) and constructors/events (C# 14) let one part declare a member and another implement it.

Key Facts

  • Indexers can be overloaded by parameter type
  • All partial parts must use partial and the same namespace
  • Partial methods with access modifiers must be implemented
  • Source generators rely heavily on partial members

Indexers & Partial Members

public class Matrix(int rows, int cols)
{
    private readonly double[] _data = new double[rows * cols];

    public double this[int r, int c]                  // 2-parameter indexer
    {
        get => _data[r * cols + c];
        set => _data[r * cols + c] = value;
    }
}
var m = new Matrix(2, 2);  m[1, 0] = 3.5;

public partial class Customer                     // Customer.cs (yours)
{
    public partial string Name { get; set; }      // declaring part
}
public partial class Customer                     // Customer.g.cs (generated)
{
    private string _name = "";
    public partial string Name { get => _name; set => _name = value; }
}

Code Explained

this[int r, int c] — multi-parameter indexer
get / set — like a property
partial class — one type, several files
Partial property — declared in one part, implemented in another (C# 13)

⚠ Common Mistakes

  • Throwing a different exception type than BCL indexers — use ArgumentOutOfRangeException / KeyNotFoundException
  • Editing generated partial files — changes are overwritten; put code in your own part
  • Declaring a partial method with a return value but no implementation — compile error

✓ Tips & Best Practices

  • Use indexers only when [] is natural for the type
  • Return ref from indexers on large structs to avoid copies
  • Name generated files *.g.cs so tools treat them specially
