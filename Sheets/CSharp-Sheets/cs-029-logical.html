Boolean Logic

&& (AND) and || (OR) short-circuit: the right side runs only if needed, which lets you guard against nulls in one line. ! negates. The single-character &, | and ^ also work on bool but always evaluate both sides; ^ is XOR (true when exactly one side is true).

Key Facts

  • Operands must be bool — no truthy integers
  • && binds tighter than ||
  • bool? uses three-valued logic with & / |
  • Patterns also offer and, or, not

Logic in Practice

bool isAdmin = true, isActive = false;

Console.WriteLine(isAdmin && isActive);   // False
Console.WriteLine(isAdmin || isActive);   // True
Console.WriteLine(!isActive);             // True
Console.WriteLine(isAdmin ^ isActive);    // True (XOR)

// Short-circuit guards
if (user != null && user.IsActive) { }       // safe: right side skipped if null
if (list.Count == 0 || list[0] < 0) { }      // safe: [0] not read if empty

// Non-short-circuit: both sides always run
bool a = Check1() & Check2();             // both methods called

// De Morgan
bool x = !(isAdmin && isActive);          // same as !isAdmin || !isActive

// Pattern combinators
if (age is >= 13 and <= 19) Console.WriteLine("teen");
if (input is not (null or "")) Console.WriteLine("has text");

Code Explained

&& — false as soon as left is false
|| — true as soon as left is true
^ — exclusive or
Null guard — the left check protects the right
& — evaluates both (rarely what you want)
and / or / not — inside is patterns

⚠ Common Mistakes

  • Using & instead of && for null guards — x != null & x.Ok still evaluates x.Ok and throws
  • Mixing && and || without parentheses — a || b && c means a || (b && c)
  • Writing if (flag == true) — just write if (flag)

✓ Tips & Best Practices

  • Put cheap or null checks on the left of &&
  • Extract long conditions into well-named bool variables
  • Use is not null for readable negated null checks

Quick Summary

  • && / || — short-circuit AND / OR
  • ! — NOT
  • ^ — XOR
  • and / or / not — pattern logic
