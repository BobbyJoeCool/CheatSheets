Console Input

Console.ReadLine · Console.ReadKey · int.Parse · int.TryParse · null input · command-line args

Reading User Input

Console.ReadLine() returns the next line as a string? — it is null when input ends (Ctrl+D / Ctrl+Z or a closed pipe). Input is always text, so convert it with int.Parse or, better, int.TryParse, which returns false instead of throwing on bad input. Console.ReadKey() reads a single key press.

Key Facts

  • ReadLine blocks until Enter is pressed
  • Return type is string? — check for null
  • TryParse uses an out parameter for the result
  • Command-line args arrive in args (string[])

Safe Input Loop

Console.Write("Enter your age: ");
string? line = Console.ReadLine();     // "36" or null at EOF

if (int.TryParse(line, out int age))   // true → age = 36
    Console.WriteLine($"Next year: {age + 1}");
else
    Console.WriteLine("Not a number"); // "abc" → false

int n;
do { Console.Write("1-10: "); }
while (!int.TryParse(Console.ReadLine(), out n) || n is < 1 or > 10);

ConsoleKeyInfo key = Console.ReadKey(intercept: true); // not echoed
if (key.Key == ConsoleKey.Escape) return;

string name = args.Length > 0 ? args[0] : "guest";  // CLI args

Code Explained

string? — ReadLine may return null
int.TryParse(s, out int x) — no exception on bad text
do…while — re-prompt until input is valid
n is < 1 or > 10 — range check with patterns
ReadKey(intercept: true) — read a key without echoing it
args[0] — first command-line argument

⚠ Common Mistakes

  • Calling int.Parse(Console.ReadLine()) — throws on empty or bad input; use TryParse
  • Ignoring null from ReadLine — piped input can end and cause a NullReferenceException
  • Parsing decimals without a culture — "3,5" vs "3.5" depends on the user's locale

✓ Tips & Best Practices

  • Pass CultureInfo.InvariantCulture when parsing machine-generated text
  • Wrap prompting in a helper like int ReadInt(string prompt)
  • Use System.CommandLine or Spectre.Console for richer CLIs
