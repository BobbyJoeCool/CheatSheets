Generic Host and Dependency Injection

The Generic Host (Host.CreateApplicationBuilder) bundles configuration, logging and a dependency injection container. You register services with a lifetime, and the container constructs them, passing dependencies into constructors. Long-running work runs as an IHostedService / BackgroundService. ASP.NET Core uses the same system.

Key Facts

  • Depend on interfaces; register implementations
  • Constructor injection is the default style
  • Scopes are created per web request (or manually)
  • Keyed services (.NET 8) register several implementations by key

Host, Services, Worker

var builder = Host.CreateApplicationBuilder(args);
builder.Services.AddSingleton<IClock, SystemClock>();      // one for app
builder.Services.AddScoped<IOrderRepo, SqlOrderRepo>();    // one per scope
builder.Services.AddTransient<IEmailSender, SmtpSender>(); // new every time
builder.Services.AddKeyedSingleton<ICache, RedisCache>("redis");
builder.Services.AddHostedService<CleanupWorker>();
using IHost host = builder.Build();
await host.RunAsync();                                     // until Ctrl+C

public class CleanupWorker(IServiceScopeFactory scopes) : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken stop)
    {
        using var timer = new PeriodicTimer(TimeSpan.FromMinutes(5));
        while (await timer.WaitForNextTickAsync(stop))
        {
            using var scope = scopes.CreateScope();          // scoped deps
            var repo = scope.ServiceProvider.GetRequiredService<IOrderRepo>();
            await repo.PurgeOldAsync();
        }
    }
}

Code Explained

AddSingleton/Scoped/Transient<I, T>() — register with lifetime
AddKeyedSingleton — resolve with [FromKeyedServices("redis")]
AddHostedService — background work
RunAsync — runs until shutdown signal
Primary ctor — dependencies injected
CreateScope() — use scoped services from a singleton

Lifetimes

LifetimeInstance PerTypical Use
SingletonApplicationCaches, clients, config
ScopedScope / requestDbContext, unit of work
TransientResolutionLightweight stateless

Rules of Thumb

RuleWhy
No scoped inside singletonCaptive dependency bug
Resolve via ctor, not service locatorExplicit dependencies

⚠ Common Mistakes

  • Injecting a scoped service (e.g. DbContext) into a singleton — it lives forever and isn't thread-safe
  • Calling GetService everywhere (service locator) — hides dependencies; use constructor injection
  • Registering the same interface twice by accident — the last registration wins for single resolution

✓ Tips & Best Practices

  • Group registrations in extension methods: services.AddBilling()
  • Use TryAdd* in libraries so apps can override registrations
  • Use PeriodicTimer for async loops in background services

Quick Summary

  • Host.CreateApplicationBuilder — host + DI + config
  • Singleton / Scoped / Transient lifetimes
  • Constructor injection
  • BackgroundService — long-running work
