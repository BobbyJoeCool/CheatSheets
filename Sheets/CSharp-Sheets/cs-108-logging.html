Logging

ILogger<T> · LogInformation · log levels · message templates · [LoggerMessage] · Serilog

Structured Logging

Microsoft.Extensions.Logging is the standard logging abstraction. Classes receive an ILogger<T> through DI and write messages at a log level. Message templates like "Order {OrderId} placed" produce structured logs where OrderId is a searchable field, not just text. Providers (console, Serilog, OpenTelemetry…) decide where logs go.

Key Facts

  • Levels: Trace < Debug < Information < Warning < Error < Critical
  • Placeholders are named, not interpolated
  • Filter levels per category in appsettings.json
  • [LoggerMessage] source gen avoids allocations

Logging in a Service

public partial class OrderService(ILogger<OrderService> log)
{
    public void Place(Order o)
    {
        log.LogInformation("Placing {OrderId} for {Total}", o.Id, o.Total);
        try { Save(o); }
        catch (Exception ex)
        {
            log.LogError(ex, "Save failed for {OrderId}", o.Id); // ex first
            throw;
        }
        using (log.BeginScope("Batch {BatchId}", o.BatchId))   // scope data
            OrderPlaced(log, o.Id);
    }
    [LoggerMessage(LogLevel.Information, "Order {OrderId} placed")]
    static partial void OrderPlaced(ILogger logger, int orderId); // generated
}
builder.Services.AddSerilog(lc => lc.WriteTo.Console());

Code Explained

ILogger<T> — category = the class name
{OrderId} — structured field
LogError(ex, …) — exception goes first
BeginScope — attach data to nested logs
[LoggerMessage] — fast, generated log method
AddSerilog — plug in Serilog (Serilog.Extensions.Hosting)

⚠ Common Mistakes

  • Interpolating messages $"Order {id}" — loses structure and allocates even when disabled
  • Logging secrets or personal data — logs are widely accessible
  • Logging and rethrowing at every layer — the same error appears many times

✓ Tips & Best Practices

  • Use PascalCase placeholder names consistently ({OrderId})
  • Use [LoggerMessage] in hot paths
  • Check log.IsEnabled(LogLevel.Debug) before expensive log data

Quick Summary
