Custom Exceptions

: Exception · standard constructors · extra properties · naming · when to create one · exception hierarchy

Defining Your Own Exceptions

Create a custom exception when callers need to catch a specific failure of your domain (e.g. OrderNotFoundException) or when you want to carry extra data. Derive from Exception (or a more specific base), end the name with Exception, and provide the standard constructors so it can wrap inner exceptions.

Key Facts

  • Derive from Exception, not ApplicationException
  • [Serializable] isn't needed on modern .NET
  • Make extra properties read-only
  • A small hierarchy lets callers catch at different levels

Custom Exception Class

public class AppException : Exception          // optional common base
{
    public AppException() { }
    public AppException(string msg) : base(msg) { }
    public AppException(string msg, Exception inner) : base(msg, inner) { }
}

public sealed class OrderNotFoundException : AppException
{
    public int OrderId { get; }

    public OrderNotFoundException(int orderId)
        : base($"Order {orderId} was not found.") => OrderId = orderId;
}

// Throw and catch
throw new OrderNotFoundException(42);

catch (OrderNotFoundException ex) { return NotFound(ex.OrderId); }
catch (AppException ex)           { return Problem(ex.Message); }

Code Explained

: Exception — inherit message, stack, inner
Three standard constructors — empty, message, message + inner (add the same to leaf types)
: base(message) — pass the message up
OrderId — extra, read-only context
sealed — leaf types usually needn't be extended
Catch specific first, then the shared base

⚠ Common Mistakes

  • Skipping the (message, inner) constructor — callers can't wrap the original cause
  • Inheriting from ApplicationException — it adds nothing; Microsoft recommends Exception
  • Creating custom types for argument errors — ArgumentException already communicates that

✓ Tips & Best Practices

  • Group domain errors under one base so APIs can map them to responses
  • Put identifiers in properties, not just the message, for logging and handling
  • Map domain exceptions to HTTP ProblemDetails at the API edge

Quick Summary

  • class XException : Exception — custom type

  • Extra read-only properties — context
