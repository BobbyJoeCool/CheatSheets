Recursion

base case · call stack · StackOverflowException · no guaranteed tail calls · memoization · iterative rewrite

Methods That Call Themselves

A recursive method solves a problem by calling itself on a smaller input until it reaches a base case that returns directly. Recursion fits naturally with trees, nested data and divide-and-conquer algorithms. Each call uses stack space, and C# does not guarantee tail-call optimization, so very deep recursion can crash the process.

Key Facts

  • Every recursive method needs a reachable base case
  • Default stack ≈ 1 MB (main thread)
  • StackOverflowException can't be caught — the process ends
  • Memoization caches results of repeated calls

Recursion Examples

static long Factorial(int n) =>
    n <= 1 ? 1 : n * Factorial(n - 1);       // base case: n <= 1
Console.WriteLine(Factorial(5));             // 120

static long Fib(int n, Dictionary<int, long>? memo = null)
{
    memo ??= [];
    if (n < 2) return n;                     // base cases 0, 1
    if (memo.TryGetValue(n, out var hit)) return hit;
    return memo[n] = Fib(n - 1, memo) + Fib(n - 2, memo);
}
Console.WriteLine(Fib(50));                  // 12586269025

static int Depth(Node? node) =>              // tree recursion
    node is null ? 0 : 1 + Math.Max(Depth(node.Left), Depth(node.Right));

Code Explained

Base case — stops the recursion
Recursive case — smaller input each call
Memo dictionary — turns O(2ⁿ) into O(n)
Tree depth — recursion mirrors the structure

⚠ Common Mistakes

  • Missing or unreachable base case — infinite recursion and a fatal StackOverflowException
  • Naive recursive Fibonacci — exponential time; memoize or iterate
  • Relying on tail-call optimization — the JIT may or may not do it

✓ Tips & Best Practices

  • Write the base case first
  • Convert deep recursion to a loop with Stack<T> or Queue<T>
  • Use local functions for recursive helpers with extra parameters

Quick Summary

  • Base case + smaller recursive case
  • No guaranteed tail calls in C#
  • Memoize overlapping subproblems
  • Explicit stack for very deep data
