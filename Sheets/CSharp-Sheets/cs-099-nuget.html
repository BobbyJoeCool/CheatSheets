Package Management

NuGet is .NET's package manager; nuget.org hosts hundreds of thousands of libraries. Packages are declared as <PackageReference> items in the project file and restored automatically on build. Central Package Management keeps every version in one Directory.Packages.props file so all projects agree.

Key Facts

  • Restore happens automatically on build/run/test
  • Packages cache in ~/.nuget/packages
  • Transitive dependencies come along automatically
  • Lock files make restores reproducible

Commands & Files

dotnet add package Serilog                      # latest stable
dotnet add package Serilog --version 4.2.0      # exact version
dotnet add package Npgsql --prerelease          # include previews
dotnet remove package Serilog
dotnet list package --outdated                  # find upgrades
dotnet list package --vulnerable                # security advisories
dotnet pack -c Release                          # build a .nupkg
dotnet nuget push bin/Release/*.nupkg -k $KEY -s nuget.org

Code Explained

add package — writes a PackageReference
--version — pin a specific version
--outdated / --vulnerable — maintenance checks
pack — create a package from your library
nuget push — publish to a feed

Directory.Packages.props

<Project>
  <PropertyGroup>
    <ManagePackageVersionsCentrally>true</ManagePackageVersionsCentrally>
  </PropertyGroup>
  <ItemGroup>
    <PackageVersion Include="Serilog" Version="4.2.0" />
    <PackageVersion Include="xunit.v3" Version="1.0.0" />
  </ItemGroup>
</Project>
<!-- each .csproj then uses: <PackageReference Include="Serilog" /> -->

Version Syntax

(,2.0]≤ 2.0

⚠ Common Mistakes

  • Different versions of the same package across projects — use Central Package Management
  • Floating versions (*) in production — builds change without code changes
  • Ignoring --vulnerable warnings (NU1901–NU1904) — update or override the transitive package

✓ Tips & Best Practices

  • Set RestorePackagesWithLockFile to true and restore with --locked-mode in CI
  • Add private feeds in a repo-level nuget.config
  • Check a package's downloads, license and last release before adopting it

Quick Summary

  • dotnet add package — add dependency
  • PackageReference — in the .csproj
  • Directory.Packages.props — central versions
  • dotnet pack / nuget push — publish
