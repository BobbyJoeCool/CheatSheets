Custom Equality

By default, classes compare by reference and structs by field values via reflection (slow). To give a class value equality, override Equals(object?) and GetHashCode(), implement IEquatable<T>, and keep ==/!= consistent. Equal objects must return equal hash codes, or dictionaries and sets break.

Key Facts

  • HashCode.Combine(a, b, …) builds good hash codes
  • Hash codes should not change while an object is in a set
  • Records generate all of this for you
  • Override ToString() for debugging and logs

Implementing Equality

public sealed class Isbn : IEquatable<Isbn>
{
    public string Value { get; }
    public Isbn(string value) => Value = value.Replace("-", "");

    public bool Equals(Isbn? other) =>
        other is not null && Value == other.Value;      // typed, no boxing

    public override bool Equals(object? obj) => Equals(obj as Isbn);
    public override int GetHashCode() => Value.GetHashCode();

    public static bool operator ==(Isbn? a, Isbn? b) => Equals(a, b);
    public static bool operator !=(Isbn? a, Isbn? b) => !(a == b);

    public override string ToString() => $"ISBN {Value}";
}

var x = new Isbn("978-0-13-468599-1");
var y = new Isbn("9780134685991");
Console.WriteLine(x == y);                            // True
Console.WriteLine(new HashSet<Isbn> { x }.Contains(y)); // True
int h = HashCode.Combine(order.Id, order.Date);      // multi-field hash

Code Explained

IEquatable<T>.Equals(T?) — fast typed comparison
Equals(object?) — forwards to the typed version
GetHashCode — must agree with Equals
== / != — overload together, null-safe
Works in HashSet / Dictionary because hash + equals match
HashCode.Combine — combine several fields

⚠ Common Mistakes

  • Overriding Equals but not GetHashCode — CS0659 warning; sets and dictionaries misbehave
  • Basing the hash on mutable fields — the object gets "lost" inside a HashSet after changes
  • Implementing == but leaving Equals as reference equality — inconsistent results

✓ Tips & Best Practices

  • Prefer record and skip all of this boilerplate
  • Seal classes with custom equality to avoid subclass surprises
  • Use IEqualityComparer<T> when equality depends on context

Quick Summary

  • Implement IEquatable<T>
