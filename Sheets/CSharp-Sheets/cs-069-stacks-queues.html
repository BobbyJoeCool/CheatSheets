Sheet 069

Stacks, Queues & Linked Lists

Stack<T> · Push / Pop / Peek · Queue<T> · Enqueue / Dequeue · PriorityQueue<T,P> · LinkedList<T>

Ordered Access Collections

Stack<T> is last-in, first-out (LIFO): push and pop at the top. Queue<T> is first-in, first-out (FIFO). PriorityQueue<TElement, TPriority> always dequeues the item with the lowest priority value. LinkedList<T> is a doubly linked list with O(1) insert and remove when you hold a node.

Key Facts

  • Pop/Dequeue on empty throws — use TryPop/TryDequeue
  • Peek looks without removing
  • PriorityQueue isn't stable for equal priorities
  • None of these are thread-safe (see Concurrent)

Stack, Queue, PriorityQueue, LinkedList

var undo = new Stack<string>();
undo.Push("type A"); undo.Push("type B");
Console.WriteLine(undo.Pop());              // type B (last in)
Console.WriteLine(undo.Peek());             // type A (still there)

var jobs = new Queue<int>([1, 2]);
jobs.Enqueue(3);
Console.WriteLine(jobs.Dequeue());          // 1 (first in)
while (jobs.TryDequeue(out int j)) Console.Write(j);   // 23

var pq = new PriorityQueue<string, int>();
pq.Enqueue("low", 5); pq.Enqueue("urgent", 1); pq.Enqueue("mid", 3);
Console.WriteLine(pq.Dequeue());            // urgent (smallest priority)

var list = new LinkedList<string>(["a", "c"]);
LinkedListNode<string> a = list.First!;
list.AddAfter(a, "b");                      // a ⇄ b ⇄ c
list.AddFirst("start");
list.Remove(a);                             // O(1) with the node
Console.WriteLine(string.Join(",", list));  // start,b,c

Code Explained

Push / Pop / Peek — stack top
Enqueue / Dequeue — queue ends
TryDequeue — loop until empty, no exceptions
PriorityQueue — element + priority; min first
LinkedListNode — handle for O(1) inserts
AddFirst / AddAfter / Remove(node)

⚠ Common Mistakes

  • Calling Pop/Dequeue without checking Count — throws InvalidOperationException when empty
  • Expecting PriorityQueue to return the highest number first — it's a min-queue; negate or use a custom comparer
  • Using LinkedList<T> for general lists — poor cache locality makes it slower than List<T>

✓ Tips & Best Practices

  • Use PriorityQueue with Comparer<int>.Create((a, b) => b - a) for max-first
  • Use Stack<T> to turn recursion into iteration
  • For producers/consumers across threads use Channel<T>

Quick Summary

  • Stack<T> — LIFO
  • Queue<T> — FIFO
  • PriorityQueue<E,P> — min priority first
  • LinkedList<T> — O(1) node insert/remove
