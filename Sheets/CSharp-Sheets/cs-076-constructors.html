Constructors

constructor overloads · : this() · : base() · primary constructors · static constructors · required members

Initializing Objects

A constructor has the class's name and no return type; it runs when an object is created. Classes can have several (overloads) that chain with : this(...), and derived classes call a base constructor with : base(...). Primary constructors (C# 12) put parameters on the class itself, and required members force callers to set properties in an initializer.

Key Facts

  • No constructor written → a public parameterless one is generated
  • Order: field initializers → base ctor → ctor body
  • Static constructor runs once, before first use
  • Primary ctor params are captured, not properties (classes)

Constructor Forms

public class Person
{
    public string Name { get; }
    public int Age { get; }
    public Person(string name, int age)
    {
        ArgumentNullException.ThrowIfNull(name);
        (Name, Age) = (name, age);
    }
    public Person(string name) : this(name, 0) { }     // chain to main ctor
}
public class Employee : Person
{
    public Employee(string name, string title) : base(name) => Title = title;
    public string Title { get; }
}
public class Service(ILogger<Service> log)             // primary ctor (C# 12)
{
    public void Run() => log.LogInformation("Running");
}
public class Options { public required string Url { get; init; } }
var o = new Options { Url = "https://x" };          // required: must set

Code Explained

Main constructor — validate and assign
: this(...) — reuse another constructor
: base(...) — run the parent's constructor first
Primary ctor — parameters usable in all members
required — compile error if caller omits it

⚠ Common Mistakes

  • Calling virtual methods in a constructor — the derived part isn't initialized yet
  • Expecting new Service(...).logger to work — primary ctor params on classes aren't members
  • Forgetting [SetsRequiredMembers] on a ctor that sets required properties — callers still must set them

✓ Tips & Best Practices

  • Validate arguments in one main constructor; chain the others to it
  • Use primary constructors for dependency injection classes
  • Use required + init instead of long constructors for DTOs

Quick Summary

  • Constructor — same name as class, no return type
  • : this() / : base() — chaining
  • Primary constructor — class C(int x)
  • required — must be initialized
