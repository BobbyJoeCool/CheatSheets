Collection Interfaces

IEnumerable<T> · ICollection<T> · IList<T> · IReadOnlyCollection<T> · IDictionary<K,V> · choosing parameter / return types

Programming to Interfaces

Collections implement a hierarchy of interfaces. Choosing the right one for parameters and return types makes APIs flexible and honest: accept the most general type you need (often IEnumerable<T>), and return a read-only interface that describes what callers may do (IReadOnlyList<T>, IReadOnlyDictionary<K,V>).

Key Facts

  • IEnumerable<T> = iterate only (may be lazy)
  • IReadOnlyCollection<T> adds Count
  • IReadOnlyList<T> adds an indexer
  • ICollection<T> / IList<T> add mutation

Choosing Parameter & Return Types

// Accept the most general type you need
public decimal Total(IEnumerable<Order> orders) => orders.Sum(o => o.Amount);

// Need Count or index? Ask for it explicitly
public Order Middle(IReadOnlyList<Order> orders) => orders[orders.Count / 2];

// Return read-only interfaces, store concrete types
public class Cart
{
    private readonly List<Item> _items = [];
    public IReadOnlyList<Item> Items => _items;           // callers can't Add
    public void Add(Item i) => _items.Add(i);
}

private readonly Dictionary<string, int> _stock = [];
public IReadOnlyDictionary<string, int> Stock => _stock;

IEnumerable<int> q = Enumerable.Range(1, 3);   // lazy
List<int> l = [1, 2, 3];
ICollection<int> c = l;  c.Add(4);             // mutation via interface
IReadOnlySet<int> s = new HashSet<int>(l);     // .NET 5+

Code Explained

IEnumerable<T> — works with arrays, lists, LINQ
IReadOnlyList<T> — you need Count + indexer
Private List<T>, public IReadOnlyList<T>
IReadOnlyDictionary — expose lookups safely
ICollection<T> — add/remove without indexing
IReadOnlySet<T> — membership without mutation

API Guidelines

⚠ Common Mistakes

  • Taking List<T> parameters when you only iterate — callers with arrays must copy
  • Enumerating an IEnumerable<T> parameter several times — it may be a lazy query; materialize once
  • Returning IEnumerable<T> over internal state and later mutating it — callers see changes mid-loop

✓ Tips & Best Practices

  • Accept IEnumerable<T>, return IReadOnlyList<T>
  • Use ReadOnlySpan<T> parameters for hot, synchronous paths
  • Return [] instead of null for empty results

Quick Summary

  • IEnumerable<T> — iterate
  • IReadOnlyList<T> — count + index, read-only
  • ICollection<T> / IList<T> — mutable
  • Accept general, return specific read-only
