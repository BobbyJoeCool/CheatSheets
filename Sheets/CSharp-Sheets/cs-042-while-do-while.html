while & do-while

while · do-while · sentinel loops · condition-at-end · input validation loops · infinite loops

Condition-Driven Loops

while checks its condition before each iteration, so the body may run zero times. do … while checks after, so the body always runs at least once — ideal for menus and input validation. Use these when you don't know the number of iterations in advance.

Key Facts

  • do-while ends with a semicolon: while (cond);
  • while (true) + break for loops with mid-body exits
  • The condition is re-evaluated every iteration
  • Make sure something in the body changes the condition

while and do-while

int n = 27, steps = 0;
while (n != 1)                         // Collatz sequence
{
    n = n % 2 == 0 ? n / 2 : 3 * n + 1;
    steps++;
}
Console.WriteLine(steps);              // 111

using var reader = new StreamReader("data.txt");
string? line;
while ((line = reader.ReadLine()) is not null)   // read until EOF
    Console.WriteLine(line);

int choice;
do Console.Write("1) Play  2) Quit: ");
while (!int.TryParse(Console.ReadLine(), out choice) || choice is not (1 or 2));

while (true)                           // exit from the middle
{
    var msg = queue.Receive();
    if (msg is null) break;
    Handle(msg);
}

Code Explained

while (cond) — may run zero times
Loop until a sentinel (n == 1)
Assignment in condition — classic read-until-null
do { } while (…); — prompt runs at least once
while (true) + break — exit mid-body

⚠ Common Mistakes

  • Forgetting to update the condition variable — the loop never ends
  • Missing the semicolon after do { } while (x) — compile error
  • Busy-waiting with while (!done) { } — burns CPU; await a task or use a signal

✓ Tips & Best Practices

  • Prefer for when there's a clear counter
  • Add a maximum-iteration guard to loops driven by external data
  • Use CancellationToken to stop long-running loops cleanly

Quick Summary

  • while — test first, 0+ runs
  • do-while — test last, 1+ runs
  • while (true) + break — mid-body exit
  • Always change the condition inside
