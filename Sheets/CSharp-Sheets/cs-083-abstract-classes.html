Abstract Classes

abstract class · abstract members · partial implementation · template method pattern · abstract vs interface

Partial Blueprints

An abstract class can't be instantiated; it exists to be inherited. It can mix implemented members (shared code and state) with abstract members that every concrete subclass must override. Use it when related types share real implementation; use an interface when they only share a contract.

Key Facts

  • Abstract members have no body and are implicitly virtual
  • A class with any abstract member must be abstract
  • Abstract classes can have constructors, fields and state
  • A class inherits only one abstract class

Template Method Pattern

public abstract class Report
{
    protected Report(string title) => Title = title;
    public string Title { get; }
    public string Render() =>                      // template method
        $"== {Title} ==\n{Body()}\n{Footer()}";
    protected abstract string Body();              // must override
    protected virtual string Footer() => "-- end --";   // may override
}
public sealed class SalesReport(decimal total) : Report("Sales")
{
    protected override string Body() => $"Total: {total:C}";
}
Report r = new SalesReport(1234m);
Console.WriteLine(r.Render());

Code Explained

abstract class — can't new it directly
protected ctor — only subclasses construct it
Render — shared algorithm with fixed steps
abstract Body() — each subclass fills it in
virtual Footer() — default that can be replaced
Use through the base type

⚠ Common Mistakes

  • Making the constructor public — misleading; make it protected
  • Putting unrelated helpers in an abstract base "for reuse" — use composition instead
  • Adding a new abstract member to a published base — breaks every existing subclass

✓ Tips & Best Practices

  • Combine an interface (contract) with an abstract base (default implementation)
  • Keep abstract bases small and focused
  • Seal concrete subclasses unless they're designed to be extended

Quick Summary

  • abstract class — no direct instances
  • abstract member — must override
  • virtual member — may override
  • Template method — base controls the flow
