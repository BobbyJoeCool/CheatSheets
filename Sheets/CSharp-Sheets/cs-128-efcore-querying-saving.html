EF Core — Querying & Saving

LINQ to Entities · Include / ThenInclude · AsNoTracking · Add / Update / Remove · SaveChangesAsync · ExecuteUpdate / ExecuteDelete

Reading and Writing Data

Queries on DbSet<T> are IQueryable: EF Core translates the LINQ into SQL when you call an executing method like ToListAsync. Loaded entities are tracked; changes are saved with SaveChangesAsync, which runs inside a transaction. Use AsNoTracking for read-only queries, Include for related data, and ExecuteUpdateAsync/ExecuteDeleteAsync for set-based changes.

Key Facts

  • Use the …Async methods in web apps
  • Projections (Select) fetch only needed columns
  • FromSql($"…") parameterizes interpolated values
  • Each SaveChanges is one transaction

Query & Save

var recent = await db.Blogs
    .AsNoTracking()                                    // read-only, faster
    .Where(b => b.Posts.Any(p => p.Published > since))
    .OrderBy(b => b.Title)
    .Select(b => new { b.Id, b.Title, Count = b.Posts.Count })
    .ToListAsync(ct);                                  // SQL runs here

var blog = await db.Blogs
    .Include(b => b.Posts).ThenInclude(p => p.Tags)    // eager load
    .FirstOrDefaultAsync(b => b.Id == id, ct);

db.Blogs.Add(new Blog { Title = "New" });              // insert
blog!.Title = "Renamed";                               // tracked update
db.Posts.Remove(blog.Posts[0]);                        // delete
await db.SaveChangesAsync(ct);                         // one transaction

await db.Posts.Where(p => p.Published < cutoff)
    .ExecuteDeleteAsync(ct);                           // bulk delete, no load
await db.Posts.Where(p => p.BlogId == id)
    .ExecuteUpdateAsync(s => s.SetProperty(p => p.Views, 0), ct);
var rows = await db.Blogs
    .FromSql($"SELECT * FROM Blogs WHERE Id = {id}").ToListAsync(ct);

Code Explained

AsNoTracking — skip change tracking
Select projection — only needed columns
ToListAsync — executes the SQL
Include / ThenInclude — load related rows
Add / modify / Remove + SaveChangesAsync
ExecuteDelete/UpdateAsync — set-based SQL

Performance Checklist

ProblemFix
N+1 queries in loopsInclude or projection
Huge Include graphsAsSplitQuery()
Loading to update many rowsExecuteUpdateAsync
Tracking read-only dataAsNoTracking()
ToList() before WhereFilter in the query

⚠ Common Mistakes

  • Building SQL with string concatenation — injection risk; use FromSql($"…") interpolation
  • Calling ToList() early, then filtering in memory — pulls entire tables
  • Lazy-loading navigation properties in loops — N+1 queries

✓ Tips & Best Practices

  • Return DTOs from APIs, not tracked entities
  • Use TagWith("…") to label queries in SQL logs
  • Wrap multi-step work in db.Database.BeginTransactionAsync() when needed

Quick Summary

  • LINQ → SQL via IQueryable
  • Include / projections — related data
  • SaveChangesAsync — tracked changes
  • ExecuteUpdate/DeleteAsync — bulk ops
