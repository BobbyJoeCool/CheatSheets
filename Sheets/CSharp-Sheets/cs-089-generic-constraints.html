Sheet 089

Generic Constraints

where T : class · struct · new() · notnull · unmanaged · base / interface constraints · allows ref struct

Restricting Type Parameters

Constraints (where T : …) tell the compiler what a type argument must support, which unlocks members you can use on T — calling interface methods, new T(), comparing, or treating it as a reference or value type. Callers get a compile error if their type doesn't satisfy the constraint.

Key Facts

  • Multiple constraints are comma-separated
  • Order: class/struct first, new() last
  • Each type parameter gets its own where clause
  • allows ref struct (C# 13) is an anti-constraint

Constraints in Use

static T Max<T>(T a, T b) where T : IComparable<T>
    => a.CompareTo(b) >= 0 ? a : b;             // CompareTo now allowed
Console.WriteLine(Max(3, 7));                   // 7
static T Create<T>() where T : new() => new T(); // parameterless ctor
public class Repo<TEntity, TKey>
    where TEntity : class, IEntity<TKey>        // ref type + interface
    where TKey : notnull                        // non-nullable key
{
    private readonly Dictionary<TKey, TEntity> _items = [];
    public void Add(TEntity e) => _items[e.Id] = e;
}

static T Sum<T>(IEnumerable<T> xs) where T : INumber<T>   // generic math
{
    T total = T.Zero;
    foreach (var x in xs) total += x;
    return total;
}
Console.WriteLine(Sum([1.5, 2.5]));             // 4
static int Len<T>(T s) where T : allows ref struct => 0;  // spans OK (C# 13)

Code Explained

IComparable<T> — enables CompareTo
new() — enables new T()
class, IEntity<TKey> — combined constraints
notnull — suitable as dictionary key
INumber<T> — T.Zero, + on any number type
allows ref struct — accept Span<T> as T

⚠ Common Mistakes

  • Over-constraining — every constraint limits who can use your API
  • Expecting where T : struct to allow int? — nullable value types don't satisfy struct
  • Writing new() before other constraints — it must be last

✓ Tips & Best Practices

  • Constrain to interfaces, not concrete classes, when possible
  • Use generic math interfaces (INumber<T>) instead of overloads per numeric type
  • Use where T : Enum for type-safe enum helpers

Quick Summary

  • where T : … — constraint clause
  • class / struct / notnull / unmanaged
  • new() — create instances
  • INumber<T> — generic math
