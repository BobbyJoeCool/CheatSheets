Namespaces & using

namespace · using · using static · using aliases · global using · InternalsVisibleTo

Organizing Code with Namespaces

Namespaces group related types and prevent name clashes (MyApp.Data.Customer vs MyApp.Web.Customer). A using directive imports a namespace so you can write short type names. C# 10 added global usings (once per project) and file-scoped namespaces; C# 12 lets aliases name any type, including tuples.

Key Facts

  • Namespace ≈ folder path by convention
  • ImplicitUsings adds System, IO, Linq, Tasks… for you
  • global:: starts lookup at the root namespace
  • Namespaces don't control access — modifiers do

using Forms

// GlobalUsings.cs — applies to every file in the project
global using System.Text.Json;
global using MyApp.Domain;

// Customer.cs
using System.Collections.Concurrent;        // regular import
using static System.Math;                   // import static members
using Json = System.Text.Json.JsonSerializer;   // alias a type
using Point = (int X, int Y);               // alias a tuple (C# 12)

namespace MyApp.Services;                   // file-scoped (C# 10)

public class Geometry
{
    public double Dist(Point a, Point b) =>
        Sqrt(Pow(a.X - b.X, 2) + Pow(a.Y - b.Y, 2));  // Math via using static
    public string Save(Point p) => Json.Serialize(p);
    public global::System.DateTime Now => global::System.DateTime.Now;
}

Code Explained

global using — one import for the whole project
using X; — short names for X's types
using static — call Sqrt without Math.
Alias — rename a type or tuple shape
namespace X; — whole file in X
global:: — avoid ambiguity with local names

Project-Level Usings

<ItemGroup>
  <Using Include="MyApp.Domain" />
  <Using Include="System.Math" Static="true" />
  <Using Remove="System.Net.Http" />
</ItemGroup>

⚠ Common Mistakes

  • Naming a class the same as its namespace (MyApp.Order.Order) — causes confusing lookups
  • Scattering global using across many files — keep them in one GlobalUsings.cs
  • Hiding which namespace a type comes from with too many using static imports

✓ Tips & Best Practices

  • Match namespaces to folder structure
  • Use aliases to resolve clashes like Task (yours vs System's)
  • Use file-scoped namespaces in all new code

Quick Summary

  • namespace X; — file-scoped
  • using / using static / alias
  • global using — project-wide
  • ImplicitUsings — common namespaces auto-imported
