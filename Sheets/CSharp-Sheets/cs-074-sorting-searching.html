Sorting & Searching

Sort · IComparable<T> · IComparer<T> · Comparer<T>.Create · BinarySearch · stable vs unstable sort

Ordering and Finding

Sorting needs a definition of order. Types define their natural order by implementing IComparable<T>; separate comparers (IComparer<T>, Comparison<T>, StringComparer) supply alternative orders. List.Sort/Array.Sort sort in place and are unstable; LINQ OrderBy returns a new stable sequence. Sorted data enables O(log n) BinarySearch.

Key Facts

  • CompareTo returns < 0, 0 or > 0
  • Comparer<T>.Create(lambda) builds a comparer
  • Order() / OrderDescending() (.NET 7) sort by natural order
  • BinarySearch returns ~insertIndex when missing

Sorting & Searching

public record Employee(string Name, int Age) : IComparable<Employee>
{
    public int CompareTo(Employee? o) => o is null ? 1 : Age.CompareTo(o.Age);
}

List<Employee> staff = [new("Cy", 41), new("Ada", 36), new("Bob", 36)];

staff.Sort();                                       // by Age (unstable)
staff.Sort((a, b) => string.Compare(a.Name, b.Name, StringComparison.Ordinal));
var byName = Comparer<Employee>.Create((a, b) => a.Name.CompareTo(b.Name));
staff.Sort(byName);

var stable = staff.OrderBy(e => e.Age).ThenBy(e => e.Name).ToList(); // stable
int[] nums = [5, 2, 8];
var asc = nums.Order();                             // 2, 5, 8

var names = new List<string> { "bob", "Ada", "cy" };
names.Sort(StringComparer.OrdinalIgnoreCase);       // Ada, bob, cy
int i = names.BinarySearch("BOB", StringComparer.OrdinalIgnoreCase); // 1
int miss = names.BinarySearch("ben", StringComparer.OrdinalIgnoreCase);
Console.WriteLine(~miss);                           // 1 (insert position)

Code Explained

IComparable<T> — the type's default order
Lambda Comparison<T> — one-off order
Comparer<T>.Create — reusable comparer object
OrderBy().ThenBy() — multi-key, stable
StringComparer — culture/case rules for text
~miss — where a missing item would go

⚠ Common Mistakes

  • Writing a.Age - b.Age comparers — can overflow for large values; use CompareTo
  • Sorting with one comparer and searching with another — BinarySearch gives wrong answers
  • Expecting List.Sort to keep ties in original order — use OrderBy for stability

✓ Tips & Best Practices

  • Implement IComparable<T> only when a type has one obvious order
  • Chain keys with ThenBy instead of complex comparison lambdas
  • Use StringComparer.Ordinal for deterministic, culture-free sorting

Quick Summary

  • IComparable<T> — natural order
  • IComparer<T> / Comparer<T>.Create — custom order
  • Sort in place vs OrderBy stable
  • BinarySearch — sorted data only
