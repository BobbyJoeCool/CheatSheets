Throwing Exceptions

throw · throw; (rethrow) · throw expressions · InnerException · ArgumentNullException.ThrowIfNull · ThrowIfNegative

Raising Exceptions

throw raises an exception object. Throw the most specific built-in type that fits, include a clear message, and wrap lower-level errors as an inner exception when you translate them. Inside a catch, use bare throw; to rethrow without losing the original stack trace. .NET also offers one-line guard helpers like ArgumentNullException.ThrowIfNull.

Key Facts

  • throw; keeps the stack; throw ex; resets it
  • throw can be an expression (C# 7)
  • Guard helpers fill in the parameter name for you
  • UnreachableException (.NET 7) marks impossible paths

Throwing Patterns

public void Withdraw(Account acct, decimal amount)
{
    ArgumentNullException.ThrowIfNull(acct);               // .NET 6
    ArgumentOutOfRangeException.ThrowIfNegativeOrZero(amount); // .NET 8
    if (amount > acct.Balance)
        throw new InvalidOperationException(
            $"Insufficient funds: balance {acct.Balance}");
    acct.Balance -= amount;
}

string Name(string? s) => s ?? throw new ArgumentNullException(nameof(s));

try { db.Save(order); }
catch (SqlException ex)
{
    throw new OrderSaveException($"Order {order.Id} failed", ex); // wrap
}

catch (Exception ex) { Log(ex); throw; }      // ✓ keeps original stack
// catch (Exception ex) { throw ex; }         // ✗ stack starts here

Code Explained

ThrowIfNull — guard with the right parameter name
ThrowIfNegativeOrZero — numeric range guard
InvalidOperationException — object in the wrong state
?? throw — throw expression
Wrap — new type, original as InnerException
throw; vs throw ex; — keep vs lose the trace

⚠ Common Mistakes

  • throw ex; inside a catch — resets the stack trace; use throw;
  • Throwing Exception or SystemException directly — too general to catch meaningfully
  • Dropping the original error when wrapping — always pass it as innerException

✓ Tips & Best Practices

  • Validate public method arguments at the top with guard helpers
  • Put the failing value in the message: $"Id {id} not found"
  • Use ExceptionDispatchInfo to rethrow later with the original stack

Quick Summary

  • throw new T(msg) — raise
  • throw; — rethrow, keep stack
  • new T(msg, inner) — wrap with cause
  • ThrowIfNull & friends — guards
