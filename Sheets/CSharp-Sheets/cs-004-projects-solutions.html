Projects and Solutions

A project (.csproj) is an MSBuild file that lists the target framework, settings and dependencies; it produces one assembly. A solution (.sln or the newer XML .slnx) groups related projects. SDK-style projects include every .cs file in the folder automatically, so the file stays short.

Key Facts

  • .slnx is the default for dotnet new sln in .NET 10
  • Directory.Build.props applies settings to every project below it
  • <Nullable>enable</Nullable> turns on nullable warnings
  • <ImplicitUsings> adds common using directives

A Typical .csproj

<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net10.0</TargetFramework>
    <LangVersion>latest</LangVersion>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
    <TreatWarningsAsErrors>true</TreatWarningsAsErrors>
  </PropertyGroup>
  <ItemGroup>
    <PackageReference Include="Serilog" Version="4.2.0" />
    <ProjectReference Include="..\Core\Core.csproj" />
  </ItemGroup>
</Project>

Code Explained

Sdk= — picks build rules (Web, Worker, Razor…)
OutputType — Exe or Library (default)
TargetFramework — net10.0; plural TargetFrameworks for multi-target
LangVersion — latest, preview, or a number
PackageReference — NuGet dependency
ProjectReference — another project in the repo

Solution Commands

CommandDoes
dotnet new sln -n AppCreate App.slnx
dotnet sln add src/**/*.csprojAdd projects
dotnet sln listList projects
dotnet sln migrateConvert .sln → .slnx
dotnet build App.slnxBuild all projects

Directory.Build.props

<Project>
  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <Nullable>enable</Nullable>
    <AnalysisLevel>latest</AnalysisLevel>
  </PropertyGroup>
</Project>

⚠ Common Mistakes

  • Listing .cs files in the .csproj — SDK projects include them already, so you get duplicates
  • Setting LangVersion higher than the SDK supports — the compiler errors out
  • Repeating the same settings in every project instead of using Directory.Build.props

✓ Tips & Best Practices

  • Put shared settings in Directory.Build.props at the repo root
  • Turn on Nullable and TreatWarningsAsErrors for new projects
  • Prefer .slnx — it's readable and merges cleanly

Quick Summary

  • .csproj — one project, one assembly
  • .slnx — groups projects
  • TargetFramework — which .NET to build for
  • Directory.Build.props — shared settings
