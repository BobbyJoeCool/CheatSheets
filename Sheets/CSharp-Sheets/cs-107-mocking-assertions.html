Mocking & Assertion Libraries

NSubstitute · Moq · Substitute.For · Returns · Received · Shouldly · AwesomeAssertions / FluentAssertions licensing

Test Doubles and Readable Asserts

Mocking libraries create fake implementations of interfaces so a unit test can isolate the class under test and verify interactions. NSubstitute and Moq are the most common. Assertion libraries like Shouldly or AwesomeAssertions give fluent, readable assertions with clearer failure messages.

Key Facts

  • Mock interfaces or virtual members only
  • FluentAssertions v8+ needs a paid license for commercial use
  • AwesomeAssertions is the Apache-licensed community fork
  • Fake only what you own; wrap third-party APIs

NSubstitute, Moq, Shouldly

// ── NSubstitute ─────────────────────────────────────
var repo = Substitute.For<IOrderRepo>();
repo.Find(1).Returns(new Order(1, 50m));             // stub
var svc = new OrderService(repo);
svc.Cancel(1);
repo.Received(1).Save(Arg.Is<Order>(o => o.Status == Status.Cancelled));

// ── Moq ─────────────────────────────────────────────
var mock = new Mock<IOrderRepo>();
mock.Setup(r => r.Find(1)).Returns(new Order(1, 50m));
new OrderService(mock.Object).Cancel(1);
mock.Verify(r => r.Save(It.IsAny<Order>()), Times.Once);

// ── Shouldly / AwesomeAssertions ────────────────────
order.Total.ShouldBe(50m);                           // Shouldly
order.Items.ShouldContain(i => i.Sku == "A1");
order.Total.Should().Be(50m);                        // AwesomeAssertions
act.Should().Throw<InvalidOperationException>().WithMessage("*closed*");

Code Explained

Substitute.For<T>() — create a fake
.Returns(...) — stub a return value
Received(1) + Arg.Is — verify a call with matching args
Mock<T>.Setup/Verify — Moq equivalents
ShouldBe — Shouldly assertion
.Should().Be — FluentAssertions-style API

⚠ Common Mistakes

  • Mocking everything, including value objects — tests mirror the implementation and break on refactors
  • Verifying every call — over-specified tests; verify only what matters
  • Upgrading to FluentAssertions 8 in a commercial project without a license

✓ Tips & Best Practices

  • Prefer in-memory fakes for repositories when practical
  • Use FakeTimeProvider and FakeLogger from Microsoft.Extensions.*.Testing
  • Keep one assertion style across the codebase

Quick Summary

  • NSubstitute / Moq — fakes for interfaces
  • Stub returns, verify calls
  • Shouldly / AwesomeAssertions — fluent asserts
  • FluentAssertions 8+ — commercial license
