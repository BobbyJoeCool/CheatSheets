Covariance & Contravariance

out T · in T · IEnumerable<out T> · Func / Action variance · array covariance pitfall · variant interfaces

Variance in Generics

Covariance (out T) lets you use a more derived type than declared: an IEnumerable<string> can be used as an IEnumerable<object>. Contravariance (in T) goes the other way: an Action<object> can act as an Action<string>. Variance applies only to interfaces and delegates with reference-type arguments.

Key Facts

  • out T — T only appears in output positions
  • in T — T only appears in input positions
  • Classes like List<T> are invariant
  • Value types don't participate (IEnumerable<int> ≠ IEnumerable<object>)

Covariance & Contravariance

IEnumerable<string> words = ["a", "b"];
IEnumerable<object> objs = words;               // ✓ covariant: out T
// List<object> list = new List<string>();      // ✗ List<T> is invariant

Func<string> getName = () => "Ada";
Func<object> getObj = getName;                  // ✓ Func<out TResult>

Action<object> logAny = o => Console.WriteLine(o);
Action<string> logText = logAny;                // ✓ contravariant: in T

var byText = Comparer<object>.Create((a, b) => $"{a}".CompareTo($"{b}"));
IComparer<string> forStrings = byText;          // ✓ IComparer<in T>

public interface IProducer<out T> { T Produce(); }        // output only
public interface IConsumer<in T> { void Consume(T item); } // input only

object[] arr = new string[2];                   // array covariance (legacy)
// arr[0] = 42;          // ArrayTypeMismatchException at run time

Code Explained

IEnumerable<out T> — sequence of derived fits base
List<T> — invariant because it both reads and writes
Func<out TResult> — returns can be widened
Action<in T> — handler for base works for derived
Declare out/in on your own interfaces
Array covariance — compiles but can throw

⚠ Common Mistakes

  • Expecting List<Cat> to convert to List<Animal> — invariant; use IEnumerable<Animal> or IReadOnlyList<Animal>
  • Relying on array covariance — writes can throw ArrayTypeMismatchException
  • Expecting variance with value types — IEnumerable<int> isn't IEnumerable<object>

✓ Tips & Best Practices

  • Accept IEnumerable<Base> parameters so callers can pass derived lists
  • Mark your own read-only interfaces out T
  • Use Cast<T>() / OfType<T>() when conversion isn't automatic

Quick Summary

  • out T — covariance (derived → base)
  • in T — contravariance (base → derived)
  • Interfaces and delegates only
  • Arrays are covariant but unsafe
