Threads and Synchronization

When several threads touch shared data, you need synchronization. lock gives one thread exclusive access to a block; .NET 9 adds a dedicated System.Threading.Lock type that lock uses efficiently. Interlocked performs atomic updates on numbers, and SemaphoreSlim limits concurrency and works with await. Most apps use the thread pool via tasks rather than raw Threads.

Key Facts

  • Lock on a private, dedicated object — never this or a string
  • You can't await inside a lock block
  • Keep locked sections short
  • volatile only stops reordering; it's not a lock

Locks, Atomics, Semaphores

public class Counter
{
    private readonly Lock _gate = new();          // .NET 9 / C# 13
    private int _value;
    public void Add(int n) { lock (_gate) { _value += n; } }
    public int Value { get { lock (_gate) return _value; } }
}

private static int _hits;
Interlocked.Increment(ref _hits);                       // atomic ++
Interlocked.Add(ref _hits, 5);
int old = Interlocked.CompareExchange(ref _hits, 0, 10); // set 0 if it was 10

var throttle = new SemaphoreSlim(initialCount: 3);      // max 3 at once
await Parallel.ForEachAsync(files, async (f, ct) =>
{
    await throttle.WaitAsync(ct);
    try { await UploadAsync(f, ct); } finally { throttle.Release(); }
});

var t = new Thread(() => Console.WriteLine("raw")) { IsBackground = true };
t.Start(); t.Join();                                    // rarely needed

Code Explained

Lock + lock — mutual exclusion
Lock in getters too — consistent reads
Interlocked — lock-free numeric updates
CompareExchange — atomic compare-and-swap
SemaphoreSlim — N concurrent holders; async wait
Thread — manual threads; prefer tasks

⚠ Common Mistakes

  • lock (this) or lock ("key") — outside code can lock the same object and deadlock you
  • _count++ from several threads — not atomic; use Interlocked.Increment
  • Calling out to unknown code while holding a lock — invites deadlocks

✓ Tips & Best Practices

  • Prefer immutable data and message passing over shared state
  • Use concurrent collections instead of locking around Dictionary
  • Acquire multiple locks in a consistent global order
