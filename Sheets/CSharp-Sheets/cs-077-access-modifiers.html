Sheet 077

Access Modifiers

public · private · protected · internal · protected internal · private protected · file

Who Can See What

Access modifiers control where a type or member can be used. Keeping members as private as possible is the core of encapsulation: you can change internals without breaking callers. Types default to internal (visible in the same assembly) and members default to private.

Key Facts

  • Top-level types: only public, internal or file
  • Interface members default to public
  • file (C# 11) limits a type to one source file
  • InternalsVisibleTo exposes internals to test assemblies

Modifiers in Context

public class Account                        // visible to everyone
{
    private decimal _balance;               // this class only
    protected string Owner = "";            // this + derived classes
    internal int AuditId;                   // same assembly
    protected internal bool Flag;           // derived OR same assembly
    private protected int Secret;           // derived AND same assembly

    public decimal Balance => _balance;     // public read
    public string Name { get; private set; } = "";   // public get, private set
}

internal class Helper { }                   // default for top-level types

file class GeneratedOnly { }                // only in this .cs file

// In the .csproj — let tests see internals:
// <InternalsVisibleTo Include="MyApp.Tests" />

Code Explained

private — tightest; default for members
protected — subclasses anywhere
internal — anything in the same project
protected internal — union of both
private protected — intersection of both
private set — different access per accessor

⚠ Common Mistakes

  • Making everything public — every member becomes part of your API and hard to change
  • Using protected fields — subclasses can break invariants; expose protected methods or properties
  • Mixing up protected internal (OR) and private protected (AND)

✓ Tips & Best Practices

  • Start private; widen only when needed
  • Use internal + InternalsVisibleTo for testable internals
  • Use file for helper types in source generators

Quick Summary

  • public / internal — assembly boundary
  • protected — subclasses
  • private — default for members
  • file — one source file (C# 11)
