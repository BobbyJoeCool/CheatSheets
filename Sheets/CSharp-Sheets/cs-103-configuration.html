App Configuration

Microsoft.Extensions.Configuration merges settings from several providers — appsettings.json, an environment-specific JSON file, environment variables, user secrets and command-line args — into one key/value view. Later providers override earlier ones. The Options pattern binds sections to typed classes injected as IOptions<T>.

Key Facts

  • Keys are hierarchical: Smtp:Host
  • Env vars use __ for : → Smtp__Host
  • User secrets are for development only
  • Host builders set all of this up automatically

Configuration & Options

// appsettings.json
// { "Smtp": { "Host": "mail.local", "Port": 25 }, "Retries": 3 }

var builder = Host.CreateApplicationBuilder(args);    // loads json, env, args
IConfiguration config = builder.Configuration;
string? host = config["Smtp:Host"];                   // "mail.local"
int retries = config.GetValue("Retries", defaultValue: 1);   // 3
var smtp = config.GetSection("Smtp").Get<SmtpOptions>();     // bind object

builder.Services.AddOptions<SmtpOptions>()
    .Bind(config.GetSection("Smtp"))
    .ValidateDataAnnotations()
    .ValidateOnStart();                               // fail fast
public class SmtpOptions
{
    [Required] public string Host { get; set; } = "";
    [Range(1, 65535)] public int Port { get; set; } = 25;
}

public class Mailer(IOptions<SmtpOptions> opts)       // inject
{
    public string Target => $"{opts.Value.Host}:{opts.Value.Port}";
}

Code Explained

CreateApplicationBuilder — default providers wired up
config["A:B"] — read a raw string
GetValue<T> — typed with default
Get<T>() — bind a section to a class
AddOptions().Bind().Validate…() — options with validation
IOptions<T> — inject settings

⚠ Common Mistakes

  • Committing passwords in appsettings.json — use user secrets locally and a vault in production
  • Using : in environment variable names — not valid everywhere; use __
  • Reading IConfiguration everywhere — bind typed options once and inject them

✓ Tips & Best Practices

  • dotnet user-secrets set "Smtp:Password" "…" for local secrets
  • Use ValidateOnStart() so bad config fails at startup
  • Use IOptionsMonitor<T> for settings that change at run time

Quick Summary

  • Providers merge; later wins
  • Section:Key — hierarchical keys
  • Options pattern — typed IOptions<T>
  • Validate on start
