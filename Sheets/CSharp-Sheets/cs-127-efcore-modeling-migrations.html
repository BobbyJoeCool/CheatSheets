Mapping the Model and Evolving the Schema

EF Core builds a model from conventions (names, keys, navigations), then applies data annotations and the Fluent API in OnModelCreating for anything else. Migrations turn model changes into versioned schema scripts: add a migration after each change, review it, then apply it to the database.

Key Facts

  • Fluent API overrides annotations, which override conventions
  • Set decimal precision explicitly
  • Migrations live in your project as C# files
  • Review generated migrations before applying

Annotations, Fluent API, Migrations

public class Product
{
    public int Id { get; set; }
    [MaxLength(100)] public required string Name { get; set; }
    public decimal Price { get; set; }
    public int CategoryId { get; set; }                 // FK by convention
    public Category Category { get; set; } = null!;
}
protected override void OnModelCreating(ModelBuilder mb)   // in AppDb
{
    mb.Entity<Product>(e =>
    {
        e.Property(p => p.Price).HasPrecision(18, 2);
        e.HasIndex(p => p.Name).IsUnique();
        e.HasOne(p => p.Category).WithMany(c => c.Products)
         .HasForeignKey(p => p.CategoryId)
         .OnDelete(DeleteBehavior.Restrict);
    });
}

Code Explained

[MaxLength] — annotation → nvarchar(100)
CategoryId + navigation — relationship by convention
OnModelCreating — Fluent API configuration
HasPrecision(18, 2) — exact money columns
HasIndex().IsUnique() — unique index
HasOne/WithMany — explicit one-to-many + delete rule

⚠ Common Mistakes

  • Editing a migration that's already applied in other environments — add a new migration instead
  • Leaving decimal precision unset — EF warns and SQL Server defaults may truncate values
  • Running database update from developer machines against production — use scripts or bundles in CI/CD

✓ Tips & Best Practices

  • Put large configurations in IEntityTypeConfiguration<T> classes
  • Name migrations after the change: AddProductIndex
  • Use --idempotent scripts for safe deployments

Quick Summary
