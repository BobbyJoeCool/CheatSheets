Comments and XML Docs

C# has single-line // and block /* */ comments, plus XML documentation comments /// that tools read. XML docs appear as IntelliSense hover text and can be exported to an .xml file for doc generators like DocFX. Enable GenerateDocumentationFile to get warnings for undocumented public members.

Key Facts

  • Block comments do not nest
  • /// must sit directly above the member it documents
  • <inheritdoc/> copies docs from a base or interface
  • #region only folds code in the editor

Documented Method

// Single-line comment
/* Block comment
   across lines */

/// <summary>Calculates the final price after a discount.</summary>
/// <param name="price">Original price; must be ≥ 0.</param>
/// <param name="percent">Discount from 0 to 100.</param>
/// <returns>The discounted price, rounded to 2 places.</returns>
/// <exception cref="ArgumentOutOfRangeException">percent &gt; 100</exception>
/// <example><code>Discount(50m, 10) // 45.00</code></example>
public static decimal Discount(decimal price, int percent)
{
    ArgumentOutOfRangeException.ThrowIfGreaterThan(percent, 100);
    return Math.Round(price * (100 - percent) / 100m, 2); // TODO: currency
}

Code Explained

<summary> — shown in IntelliSense
<param name="x"> — one per parameter
<returns> — what the method gives back
<exception cref="T"> — documents a thrown exception
&gt; — XML needs < and > escaped

Common XML Tags

TagUse
<summary>One-line description
<remarks>Longer details
<param> / <paramref>Describe / refer to a parameter
<typeparam>Generic type parameter
<see cref="…"/>Link to another member
<inheritdoc/>Reuse base/interface docs

Settings & Directives

ItemEffect
<GenerateDocumentationFile>true → builds .xml docs
CS1591Warning: missing XML comment
#pragma warning disable CS1591Silence it locally
#region Name … #endregionCollapsible block

⚠ Common Mistakes

  • Writing List<int> inside /// text — use List{T} in cref or &lt;int&gt; in prose
  • Comments that restate the code (i++; // add one) — explain why, not what
  • Leaving stale <param> names after a rename — the compiler warns with CS1572/CS1573

✓ Tips & Best Practices

  • Type /// above a member and the IDE scaffolds the tags
  • Use <inheritdoc/> on interface implementations
  • Avoid #region to hide long classes — split the class instead

Quick Summary

  • // and /* */ — normal comments
  • /// — XML documentation
  • <summary>, <param>, <returns> — core tags
  • GenerateDocumentationFile — export docs
