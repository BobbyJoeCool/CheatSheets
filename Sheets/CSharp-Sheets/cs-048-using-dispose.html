Sheet 048

using & IDisposable

using statement · using declaration · IDisposable · Dispose pattern · IAsyncDisposable · await using

Deterministic Cleanup

The garbage collector frees memory, but unmanaged resources (files, sockets, DB connections) should be released promptly. Types holding them implement IDisposable. The using statement or declaration calls Dispose() automatically, even when an exception is thrown. Async resources use IAsyncDisposable with await using.

Key Facts

  • using compiles to try/finally + Dispose()
  • Declarations dispose at the end of the enclosing scope
  • Multiple usings dispose in reverse order
  • Dispose() should be safe to call more than once

using & IDisposable

using (var reader = new StreamReader("in.txt"))     // statement form
    Console.WriteLine(reader.ReadLine());           // Dispose() after

using var input = File.OpenRead("a.bin");           // declaration (C# 8)
using var output = File.Create("b.bin");            // disposed first…
input.CopyTo(output);                               // …at end of scope

await using var conn = new SqlConnection(cs);       // IAsyncDisposable

public sealed class TempFile : IDisposable
{
    public string Path { get; } = System.IO.Path.GetTempFileName();
    private bool _disposed;
    public void Dispose()
    {
        if (_disposed) return;                      // idempotent
        File.Delete(Path); _disposed = true;
    }
}

Code Explained

using (…) { } — dispose at the closing brace
using var — dispose at the end of the method
Reverse order — last created, first disposed
await using — calls DisposeAsync()
Sealed class — simple Dispose without the full pattern
_disposed flag — safe repeated calls

Full Dispose Pattern (unsealed)

protected virtual void Dispose(bool disposing)
{
    if (_disposed) return;
    if (disposing) _stream.Dispose();  // managed
    _disposed = true;
}
public void Dispose()
    { Dispose(true); GC.SuppressFinalize(this); }

⚠ Common Mistakes

  • Forgetting to dispose — file locks and connection-pool exhaustion follow
  • Disposing an object you didn't create (e.g. an injected HttpClient) — the owner disposes
  • Using using on HttpClient per request — exhausts sockets; reuse one or use IHttpClientFactory

✓ Tips & Best Practices

  • Prefer using var declarations to cut nesting
  • Seal classes when possible so a simple Dispose() is enough
  • Guard members with ObjectDisposedException.ThrowIf after disposal

Quick Summary

  • IDisposable — explicit cleanup contract
  • using — automatic Dispose()
  • await using — async cleanup
  • Dispose is idempotent and reverse-ordered
