Parameters & Arguments

named arguments · optional / default · ref · out · in · ref readonly · out var

Passing Data In and Out

By default arguments are passed by value (a copy of the value or of the reference). Named and optional arguments make calls readable. The modifiers ref, out, in and ref readonly pass by reference: ref reads and writes the caller's variable, out must be assigned by the method, and in / ref readonly pass large structs without copying.

Key Facts

  • Optional parameters must come after required ones
  • Default values must be compile-time constants
  • out var x declares the variable inline
  • out _ discards a value you don't need

Parameter Kinds

void Greet(string name, string greet = "Hello", bool shout = false)
    => Console.WriteLine($"{greet}, {name}{(shout ? "!" : "")}");
Greet("Ada");                           // Hello, Ada
Greet("Ada", "Hi");                     // Hi, Ada
Greet("Ada", shout: true);              // Hello, Ada!  (named, skips one)

void Double(ref int x) => x *= 2;
int n = 5; Double(ref n);               // n = 10

bool TryDivide(int a, int b, out int result)
{
    result = b == 0 ? 0 : a / b;        // must assign
    return b != 0;
}
if (TryDivide(10, 3, out var q)) Console.WriteLine(q); // 3

double Length(in Vector3 v) => Math.Sqrt(Vector3.Dot(v, v));

Code Explained

greet = "Hello" — optional with default
shout: true — named argument
ref — caller must pass ref n; method can change it
out — method must assign before returning
out var q — inline declaration
in — read-only reference, avoids copying big structs

⚠ Common Mistakes

  • Expecting a method to replace the caller's object without ref — only the copy of the reference changes
  • Changing a public optional default — callers compiled earlier keep the old value
  • Using ref just to return extra values — return a tuple or record instead

✓ Tips & Best Practices

  • Use named arguments for boolean flags: Save(overwrite: true)
  • Follow the TryX(input, out result) pattern for operations that can fail
  • Use in only for large structs; for small ones copying is cheaper

Quick Summary

  • Optional + named — readable calls
  • ref — read/write caller's variable
  • out — extra output, must assign
  • in / ref readonly — no-copy read-only
