Type Checking & Inspection

typeof · GetType() · is · as · nameof · sizeof · default(T)

Inspecting Types

typeof(T) gets a System.Type for a type name at compile time, while obj.GetType() returns the runtime type of an object. The is operator tests compatibility (including base types and interfaces), as casts or returns null, and nameof turns a symbol into a string that survives renames.

Key Facts

  • is matches derived types; GetType() == does not
  • as works only with reference and nullable types
  • nameof is evaluated at compile time
  • sizeof on primitives needs no unsafe

Type Checks

object o = "hello";

Console.WriteLine(typeof(int));          // System.Int32
Console.WriteLine(o.GetType().Name);     // String
Console.WriteLine(o is string);          // True
Console.WriteLine(o is IComparable);     // True (interface)

if (o is string s && s.Length > 3)       // test + cast
    Console.WriteLine(s.ToUpper());      // HELLO

string? maybe = o as string;             // "hello" or null
int? n = o as int?;                      // null

Console.WriteLine(nameof(o));            // o
Console.WriteLine(nameof(Console.WriteLine)); // WriteLine
Console.WriteLine(sizeof(long));         // 8
Console.WriteLine(default(int));         // 0

Animal a = new Dog();
Console.WriteLine(a is Animal);                   // True
Console.WriteLine(a.GetType() == typeof(Animal)); // False

Code Explained

is vs GetType() == — inheritance-aware vs exact

⚠ Common Mistakes

  • Calling x.GetType() on a null reference — throws; use x is T instead
  • Using as and then not checking for null — you just move the crash
  • Hard-coding member names in strings — use nameof so renames stay in sync

✓ Tips & Best Practices

  • Prefer if (x is Foo f) over as + null check
  • Use nameof in ArgumentException messages and PropertyChanged events
  • Reach for virtual methods before long is chains

Quick Summary

  • typeof — compile-time type
  • GetType() — runtime type
  • is / as — safe type tests and casts
  • nameof — rename-safe names
