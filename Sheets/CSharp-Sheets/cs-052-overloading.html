Method Overloading

overload rules · overload resolution · optional params vs overloads · ambiguity errors · OverloadResolutionPriority

Same Name, Different Signatures

Overloading means several methods share a name but differ in the number, types or ref-kinds of their parameters. The compiler picks the best match at compile time using overload resolution: exact matches beat implicit conversions, and if two candidates are equally good the call is ambiguous.

Key Facts

  • Return type alone can't distinguish overloads
  • Parameter names don't count either
  • ref/out/in do count (but not ref vs out)
  • C# 13 [OverloadResolutionPriority] lets library authors steer resolution

Overloads & Resolution

static void Print(int x)     => Console.WriteLine($"int {x}");
static void Print(long x)    => Console.WriteLine($"long {x}");
static void Print(double x)  => Console.WriteLine($"double {x}");
static void Print(string s)  => Console.WriteLine($"string {s}");
static void Print(object o)  => Console.WriteLine($"object {o}");

Print(5);          // int 5        (exact)
Print(5L);         // long 5
Print((short)5);   // int 5        (short → int is the best widening)
Print(5f);         // double 5     (float → double)
Print("hi");       // string hi
Print(DateTime.Now); // object …   (only match)

static int Area(int side) => side * side;
static int Area(int w, int h) => w * h;     // by count

// static double Area(int s) => …;   // ✗ CS0111: return type only

static void F(int a, long b) { }
static void F(long a, int b) { }
// F(1, 2);                                // ✗ CS0121: ambiguous

Code Explained

Exact match — int overload for 5
Best widening — short prefers int over long
object — fallback that accepts anything
Different parameter counts — always distinct
Return type only — not an overload
Two equally good candidates — ambiguity error

Overloads vs Optional Params

UseWhen
OverloadsDifferent types or behavior
Optional paramsSame logic, sensible defaults
OverloadsPublic library APIs (versioning-safe)
paramsVariable count of same type

⚠ Common Mistakes

  • Overloads that do different things — same name should mean same intent
  • Mixing overloads and optional parameters so calls become ambiguous
  • Passing null to overloads with two reference types — CS0121; cast: Print((string?)null)

✓ Tips & Best Practices

  • Have simpler overloads call the most complete one
  • Add a ReadOnlySpan<T> overload for performance-sensitive callers
  • Prefer distinct names (FromSeconds, FromMinutes) when types alone are confusing

Quick Summary

  • Overloads — same name, different parameters
  • Resolution — exact > widening > object
  • Return type doesn't count
  • CS0121 — ambiguous call
