switch Expressions

switch => · _ discard · tuple switch · exhaustiveness warnings · throw expressions · returning values

switch as an Expression

A switch expression (C# 8) maps an input to a value using pattern => result arms separated by commas. It's shorter than a switch statement, always produces a value, and the compiler warns when arms aren't exhaustive. The discard _ catches everything else.

Key Facts

  • Input comes before switch
  • Arms are tried top to bottom
  • Unmatched input throws SwitchExpressionException
  • Arms can throw instead of returning

switch Expressions

string Grade(int score) => score switch
{
    >= 90 => "A",
    >= 80 => "B",
    >= 70 => "C",
    < 0 or > 100 => throw new ArgumentOutOfRangeException(nameof(score)),
    _ => "F"
};

decimal Shipping(Order o) => o switch
{
    { Total: >= 100 }            => 0m,
    { Country: "US", Express: true } => 15m,
    { Country: "US" }            => 5m,
    _                            => 25m
};

string Winner(string a, string b) => (a, b) switch    // tuple switch
{
    ("rock", "scissors") or ("paper", "rock") or ("scissors", "paper") => "A",
    var (x, y) when x == y => "Tie",
    _ => "B"
};

Code Explained

value switch { … } — expression form
Relational arms — >= 90 => …
throw arm — reject invalid input
Property patterns — match on object shape
Tuple switch — branch on several values at once
when — extra guard on an arm

⚠ Common Mistakes

  • Putting _ => first — every later arm becomes unreachable (CS8510)
  • Ignoring CS8509 — unhandled values throw SwitchExpressionException at run time
  • Forcing multi-step logic into an arm — call a method or use a switch statement

✓ Tips & Best Practices

  • Order arms from most to least specific
  • Use tuple switches for state machines and decision tables
  • End enum switches with _ => throw new UnreachableException()

Quick Summary

  • x switch { p => v, … } — value-producing switch
  • _ — catch-all arm
  • Tuple switch — match combinations
  • Compiler checks exhaustiveness
