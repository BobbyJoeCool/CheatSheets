Sheet 071

Immutable & Frozen Collections

ImmutableArray · ImmutableList · ImmutableDictionary · builders · FrozenDictionary · FrozenSet · IReadOnlyList

Collections That Never Change

Immutable collections (System.Collections.Immutable) never change; "modifying" methods return a new collection that shares structure with the old one. They're safe to share across threads. Frozen collections (System.Collections.Frozen, .NET 8) are built once and optimized for the fastest possible reads. IReadOnlyList<T> is only a read-only *view*.

Key Facts

  • Use builders for many changes, then ToImmutable()
  • ImmutableArray<T> is a struct — fast reads, slow adds
  • Frozen creation is slower; lookups are faster
  • AsReadOnly() wraps; the original can still change

Immutable & Frozen

ImmutableList<int> v1 = [1, 2, 3];
ImmutableList<int> v2 = v1.Add(4);           // new list
Console.WriteLine($"{v1.Count} {v2.Count}");  // 3 4

var d1 = ImmutableDictionary<string, int>.Empty.Add("a", 1);
var d2 = d1.SetItem("a", 2);                 // d1 unchanged

var builder = ImmutableArray.CreateBuilder<int>();
for (int i = 0; i < 1000; i++) builder.Add(i);
ImmutableArray<int> arr = builder.ToImmutable();   // one allocation

FrozenDictionary<string, int> codes = new Dictionary<string, int>
    { ["US"] = 1, ["UK"] = 44, ["FR"] = 33 }.ToFrozenDictionary();
FrozenSet<string> banned = new[] { "root", "admin" }.ToFrozenSet();
Console.WriteLine(codes["UK"]);              // 44

var list = new List<int> { 1 };
IReadOnlyList<int> view = list.AsReadOnly();
list.Add(2);                                 // view.Count is now 2!

Code Explained

Add on immutable — returns a new instance
SetItem — replace a value, old map untouched
Builder — batch edits, then freeze
ToFrozenDictionary() — build once, read fast
ToFrozenSet() — fast membership tests
AsReadOnly() — a view, not a snapshot

Which Type?

TypeStrength
ImmutableArray<T>Fast reads, rare changes
ImmutableList<T>Frequent persistent edits
ImmutableDictionary<K,V>Shared, versioned maps
FrozenDictionary<K,V>Static lookup tables
FrozenSet<T>Static allow/deny lists

⚠ Common Mistakes

  • Calling list.Add(x); on an immutable list and ignoring the result — nothing changes
  • Building a large immutable collection with repeated Add — use a builder
  • Assuming IReadOnlyList<T> can't change — the underlying list still can

✓ Tips & Best Practices

  • Store configuration lookups in FrozenDictionary at startup
  • Expose IReadOnlyList<T> but store ImmutableArray<T> for true safety
  • Collection expressions work with immutable types: ImmutableArray<int> a = [1, 2];

Quick Summary

  • Immutable — changes return new instances
  • Builders — efficient bulk construction
  • Frozen — fastest reads, built once
  • Read-only views ≠ immutable
