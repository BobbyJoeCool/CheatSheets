C# Without a Project File

.NET 10 lets you run a single .cs file directly: dotnet run app.cs. Special #: directives at the top of the file add NuGet packages, choose an SDK or set MSBuild properties. It's ideal for scripts and quick experiments, and you can convert it to a full project later.

Key Facts

  • Requires the .NET 10 SDK or newer
  • Directives must appear at the top of the file
  • Builds are cached, so later runs start fast
  • On Unix a #! shebang makes the file executable

app.cs

#!/usr/bin/env dotnet
#:package Humanizer@2.14.1
#:property Nullable=enable

using Humanizer;

var since = DateTime.Now - new DateTime(2002, 2, 13);
Console.WriteLine($"C# is {since.Humanize(2)} old");

// Run:      dotnet run app.cs
// Or:       chmod +x app.cs && ./app.cs
// Convert:  dotnet project convert app.cs

Code Explained

#!/usr/bin/env dotnet — shebang for Unix shells
#:package Name@Version — NuGet reference
#:property — any MSBuild property
#:sdk Microsoft.NET.Sdk.Web — switch SDK (e.g. web apps)
dotnet project convert — creates a .csproj from the file

File-Based vs Project

NeedUse

⚠ Common Mistakes

  • Putting #: directives below using lines — they must come first
  • Omitting the version in #:package — pin it so the script stays reproducible
  • Running with an older SDK — dotnet run app.cs needs .NET 10+

✓ Tips & Best Practices

  • Great replacement for small PowerShell or Python helper scripts
  • Use #:sdk Microsoft.NET.Sdk.Web to spin up a minimal API in one file
  • Convert with dotnet project convert once the script grows

Quick Summary

  • dotnet run app.cs — run a single file
  • #:package — add NuGet packages
  • #:property / #:sdk — configure the build
  • dotnet project convert — graduate to a project
