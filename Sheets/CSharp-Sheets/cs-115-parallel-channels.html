Data Parallelism and Pipelines

The Task Parallel Library spreads CPU-bound loops across cores with Parallel.For / ForEach, and Parallel.ForEachAsync handles async work with a concurrency limit. PLINQ (AsParallel()) parallelizes LINQ queries. Channels (System.Threading.Channels) are async producer/consumer queues for building pipelines between tasks.

Key Facts

  • Parallel loops only help for CPU-heavy, independent work
  • Iterations run in no particular order
  • Bounded channels apply back-pressure to producers
  • Complete the writer so readers can finish

Parallel & Channels

long[] results = new long[1000];
Parallel.For(0, results.Length, i => results[i] = Fib(i % 40));   // CPU-bound

var opts = new ParallelOptions { MaxDegreeOfParallelism = 4 };
await Parallel.ForEachAsync(urls, opts, async (url, ct) =>
    await DownloadAsync(url, ct));                               // async, max 4

int primes = Enumerable.Range(2, 5_000_000)
    .AsParallel()
    .Count(IsPrime);                                               // PLINQ

var channel = Channel.CreateBounded<string>(capacity: 100);
var producer = Task.Run(async () =>
{
    foreach (var line in File.ReadLines("big.csv"))
        await channel.Writer.WriteAsync(line);                  // waits if full
    channel.Writer.Complete();                                  // no more items
});
var consumer = Task.Run(async () =>
    { await foreach (var l in channel.Reader.ReadAllAsync()) Process(l); });
await Task.WhenAll(producer, consumer);

Code Explained

Parallel.For — split a range across cores
MaxDegreeOfParallelism — cap concurrency
ForEachAsync — parallel async I/O
AsParallel() — PLINQ query
CreateBounded — queue with back-pressure
Complete() + ReadAllAsync() — clean shutdown

Which Tool?

WorkloadUse
CPU loop over dataParallel.For / ForEach
Many async I/O callsParallel.ForEachAsync
CPU-heavy LINQ queryPLINQ AsParallel()
Producer → consumer stagesChannel<T>
One background jobTask.Run

MemberUse

⚠ Common Mistakes

  • Using Parallel.For for I/O — it blocks pool threads; use ForEachAsync
  • Writing to a shared List<T> from parallel iterations — not thread-safe; write by index or use concurrent collections
  • Forgetting Writer.Complete() — consumers wait forever

✓ Tips & Best Practices

  • Measure first — parallel overhead can make small loops slower
  • Use AsOrdered() when PLINQ output order matters
  • Run multiple consumers on one channel to scale processing
