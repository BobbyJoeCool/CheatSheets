Span, Memory & Performance

Span<T> · Memory<T> · stackalloc · ArrayPool<T> · implicit span conversions (C# 14) · BenchmarkDotNet

Zero-Copy and Low-Allocation Code

Span<T> and ReadOnlySpan<T> are views over contiguous memory — arrays, strings, stack memory or native buffers — that slice without copying. Because they're ref structs they live only on the stack; Memory<T> is the heap-storable counterpart for async code. stackalloc and ArrayPool<T> avoid GC allocations, and C# 14 adds implicit conversions to spans.

Key Facts

  • Spans can't be fields of classes, captured, or used across await
  • stackalloc is for small buffers (≈ < 1 KB)
  • Always Return rented arrays to the pool
  • Measure with BenchmarkDotNet before optimizing

Span, stackalloc, ArrayPool

static int SumDigits(ReadOnlySpan<char> text)  // accepts string, char[], slices
{
    int sum = 0;
    foreach (char c in text) if (char.IsAsciiDigit(c)) sum += c - '0';
    return sum;
}
Console.WriteLine(SumDigits("a1b2c3"));             // 6 (string → span)
Console.WriteLine(SumDigits("x9y9z9".AsSpan(1, 3))); // 9 (slice, no copy)

Span<char> buf = stackalloc char[32];               // stack memory, no GC
Guid.NewGuid().TryFormat(buf, out int written, "N"); // no string allocated

byte[] rented = ArrayPool<byte>.Shared.Rent(16_384); // reuse big buffers
try { int n = await stream.ReadAsync(rented.AsMemory(0, 16_384)); }
finally { ArrayPool<byte>.Shared.Return(rented); }

Memory<byte> mem = rented.AsMemory();            // OK in async methods / fields
Span<byte> view = mem.Span[..10];                   // get a span when needed

Code Explained

ReadOnlySpan<char> — one API for many sources
C# 14 — arrays convert to spans implicitly (e.g. span extension methods)
AsSpan(start, len) — zero-copy slice
stackalloc — temporary stack buffer
ArrayPool<T>.Shared — rent/return large arrays
Memory<T> — span-like, but storable and async-friendly

BenchmarkDotNet

[MemoryDiagnoser]
public class ParseBench
{
    [Benchmark] public int Sub() =>
        int.Parse(s.Substring(0, 4));
    [Benchmark] public int Span() =>
        int.Parse(s.AsSpan(0, 4));
}

⚠ Common Mistakes

  • Large stackalloc buffers — can overflow the stack; fall back to ArrayPool above a size limit
  • Using a rented array after returning it — another caller may be writing to it
  • Optimizing without measuring — spans add complexity; benchmark first

✓ Tips & Best Practices

  • Accept ReadOnlySpan<T> in parsing helpers
  • Use string.Create / TryFormat to build strings without temporaries
  • Add [MemoryDiagnoser] to see allocations per call

Quick Summary

  • Span<T> — stack-only view
  • Memory<T> — async-safe view
  • stackalloc / ArrayPool — avoid GC
  • Benchmark with BenchmarkDotNet
