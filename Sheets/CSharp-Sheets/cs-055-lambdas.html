Lambda Expressions

x => · statement lambdas · natural type · default parameters · static lambdas · parameter modifiers (C# 14) · _ discards

Anonymous Functions

A lambda (params) => body creates an anonymous function that converts to a delegate or expression tree. Expression lambdas return a single expression; statement lambdas use braces. Since C# 10 lambdas have a natural type, so var works; C# 12 added default parameter values and C# 14 allows ref/out/in modifiers without writing parameter types.

Key Facts

  • Parentheses optional for one untyped parameter: x => x * 2
  • Parameter types are usually inferred
  • static lambdas can't capture locals
  • Use _ for unused parameters

Lambda Forms

Func<int, int> twice = x => x * 2;                  // expression lambda
Func<int, int, int> add = (a, b) => a + b;
Action hi = () => Console.WriteLine("hi");          // no parameters

Func<string, bool> isValid = s =>                   // statement lambda
{
    if (string.IsNullOrWhiteSpace(s)) return false;
    return s.Length <= 20;
};

var parse = (string s) => int.Parse(s);             // natural type (C# 10)
var pick = object (bool b) => b ? 1 : "one";        // explicit return type
var inc = (int x, int by = 1) => x + by;            // default param (C# 12)
Console.WriteLine(inc(5));                          // 6

Func<int, int> sq = static x => x * x;              // no captures allowed
EventHandler h = (_, _) => Console.WriteLine("clicked"); // discards

delegate bool TryParser<T>(string s, out T value);
TryParser<int> tp = (s, out v) => int.TryParse(s, out v); // C# 14

Code Explained

x => x * 2 — single expression is the return value
{ … return …; } — statement lambda
var + typed params — compiler infers Func<string,int>
object (bool b) => — declare the return type
by = 1 — default parameter value
(s, out v) — modifiers without types (C# 14)

⚠ Common Mistakes

  • Using async void lambdas for Action parameters — exceptions crash the process; prefer Func<Task>
  • Big statement lambdas inside LINQ — extract a named method
  • Capturing a loop variable in a for loop — see closures; copy it to a local first

✓ Tips & Best Practices

  • Mark lambdas static in hot paths to avoid closure allocations
  • Use method groups (Select(int.Parse)) when no extra logic is needed
  • Name complex predicates: Func<Order, bool> isLate = …

Quick Summary

  • x => expr — expression lambda
  • x => { … } — statement lambda
  • Natural type — var f = (int x) => …
  • Defaults (C# 12), modifiers (C# 14)
