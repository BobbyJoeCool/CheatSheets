async / await — Basics

async · await · Task · Task<T> · ValueTask · async Main · how await resumes

Asynchronous Code

async/await lets methods wait for I/O (network, disk, databases) without blocking a thread. An async method returns a Task (no result) or Task<T>; await pauses the method until the task completes and then resumes, usually on a thread-pool thread. Async is about scalability and responsiveness, not making CPU work faster.

Key Facts

  • async methods run synchronously until the first incomplete await
  • Exceptions are stored in the task and rethrown at await
  • Name async methods with an Async suffix
  • Main can be async Task (or use top-level await)

async / await Basics

static async Task<string> FetchTitleAsync(HttpClient http, string url)
{
    string html = await http.GetStringAsync(url);  // thread free while waiting
    int start = html.IndexOf("<title>") + 7;
    return html[start..html.IndexOf("</title>")];
}

static async Task SaveAsync(string path, string text)  // Task = no result
{
    await File.WriteAllTextAsync(path, text);
    Console.WriteLine("saved");
}

using var http = new HttpClient();
string title = await FetchTitleAsync(http, "https://example.com");
await SaveAsync("title.txt", title);

Task<string> pending = FetchTitleAsync(http, "https://dot.net");   // starts now
DoOtherWork();                                                 // runs meanwhile
string second = await pending;                                    // then wait

ValueTask<int> cached = GetCountAsync();      // cheaper when often synchronous

Code Explained

async Task<T> — returns a value later
await — suspend without blocking the thread
async Task — like void, but awaitable
Top-level await — allowed in Program.cs
Start first, await later — overlap work
ValueTask<T> — avoids allocation on fast paths

⚠ Common Mistakes

  • Forgetting await — the method continues before the work finishes and errors are lost
  • Using async for CPU-bound work without Task.Run — it still blocks the caller
  • Mixing .Result/.Wait() with async code — can deadlock and wraps errors

✓ Tips & Best Practices

  • Go "async all the way" — from controller to database
  • Accept and pass a CancellationToken
  • Return the task directly (=> http.GetAsync(u)) when no await is needed

Quick Summary

  • async Task<T> + await
  • Non-blocking I/O, not faster CPU
  • Start tasks, await later to overlap
  • ValueTask for hot paths
