Concurrent Collections

ConcurrentDictionary · GetOrAdd · AddOrUpdate · ConcurrentQueue · ConcurrentBag · BlockingCollection

Thread-Safe Collections

System.Collections.Concurrent provides collections that many threads can use at once without external locks. ConcurrentDictionary offers atomic helpers like GetOrAdd and AddOrUpdate. ConcurrentQueue/ConcurrentStack/ConcurrentBag support lock-free producer/consumer work, and BlockingCollection adds blocking and bounding.

Key Facts

  • Individual operations are atomic; sequences of them aren't
  • GetOrAdd factories may run more than once
  • ConcurrentBag is unordered, best when the same thread adds and takes
  • For async pipelines prefer Channel<T>

Concurrent Collections

var cache = new ConcurrentDictionary<string, int>();
int len = cache.GetOrAdd("hello", key => key.Length);     // 5
cache.AddOrUpdate("hits", 1, (key, old) => old + 1);      // add or increment
cache.TryUpdate("hits", 10, comparisonValue: 2);          // CAS-style update

var lazy = new ConcurrentDictionary<string, Lazy<Data>>();
Data d = lazy.GetOrAdd("k", k => new Lazy<Data>(() => Load(k))).Value;

var queue = new ConcurrentQueue<int>();
Parallel.For(0, 100, i => queue.Enqueue(i));
while (queue.TryDequeue(out int item)) Process(item);

using var work = new BlockingCollection<string>(boundedCapacity: 10);
var consumer = Task.Run(() =>
    { foreach (var job in work.GetConsumingEnumerable()) Handle(job); });
work.Add("job1"); work.Add("job2");
work.CompleteAdding();                     // consumer loop ends
await consumer;

Code Explained

GetOrAdd — return existing or add new atomically
AddOrUpdate — insert or transform the old value
TryUpdate(k, new, expected) — compare-and-swap
Lazy<T> values — guarantee the factory runs once
TryDequeue — drain safely
GetConsumingEnumerable + CompleteAdding — producer/consumer

Atomic vs Not

CodeAtomic?
d.GetOrAdd(k, f)Yes (f may run twice)
d.AddOrUpdate(k, a, u)Yes
if (!d.ContainsKey(k)) d[k] = vNo — race

⚠ Common Mistakes

  • Check-then-act sequences (ContainsKey then add) — another thread can slip in; use GetOrAdd/TryAdd
  • Expensive or side-effecting GetOrAdd factories — they can run more than once; wrap in Lazy<T>
  • Polling Count in hot loops — it's expensive; track counts separately

✓ Tips & Best Practices

  • Use AddOrUpdate for counters, or Interlocked on a field
  • Use Channel<T> instead of BlockingCollection in async code
  • Prefer immutable data + swapping references for read-mostly state

Quick Summary

  • ConcurrentDictionary — GetOrAdd / AddOrUpdate
  • ConcurrentQueue / Stack / Bag
  • BlockingCollection — bounded blocking pipeline
  • Single operations are atomic, sequences aren't
