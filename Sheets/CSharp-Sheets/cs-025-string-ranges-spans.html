Indexing, Ranges & Spans

s[^1] · s[1..4] · Index · Range · AsSpan() · ReadOnlySpan<char> · Slice

Index, Range and Span

C# 8 added ^ (index from end) and .. (range) operators, so s[^1] is the last char and s[1..4] is a substring. On a string a range allocates a new string; on a ReadOnlySpan<char> it just creates a view over the same memory, which makes parsing fast and allocation-free.

Key Facts

  • Range end is exclusive: [1..4] = indexes 1, 2, 3
  • ^1 = last, ^0 = one past the end
  • .. alone = everything
  • Spans live on the stack — no async or fields

Slicing

string s = "Hello";

Console.WriteLine(s[0]);       // H
Console.WriteLine(s[^1]);      // o (last)
Console.WriteLine(s[1..4]);    // ell
Console.WriteLine(s[..2]);     // He
Console.WriteLine(s[^3..]);    // llo
Console.WriteLine(s[1..^1]);   // ell (trim first & last)

Index last = ^1;  Range mid = 1..^1;
Console.WriteLine(s[mid]);     // ell

ReadOnlySpan<char> span = "2026-10-11".AsSpan();
int year  = int.Parse(span[..4]);     // 2026 — no substring alloc
int month = int.Parse(span.Slice(5, 2)); // 10
Console.WriteLine(span[^2..].ToString()); // "11"

int[] nums = [1, 2, 3, 4, 5];
int[] copy = nums[1..3];       // [2, 3] (new array)
Span<int> view = nums.AsSpan(1, 2); view[0] = 99; // nums[1] = 99

Code Explained

^n — nth from the end
a..b — start inclusive, end exclusive
Index / Range — store them in variables
AsSpan() — view, no copy
int.Parse(span) — parse without allocating
Array range — copies; span — shares memory

⚠ Common Mistakes

  • Expecting the range end to be included — s[0..3] is 3 chars
  • Using s[^0] for the last char — it's one past the end; use ^1
  • Storing a Span<T> in a field or across await — not allowed; use Memory<T>

✓ Tips & Best Practices

  • Use spans in hot parsing code to avoid substrings
  • Ranges also work on arrays and List<T> via CollectionsMarshal.AsSpan
  • Call ToString() on a span only once you need a real string

Quick Summary

  • a..b — exclusive-end range
