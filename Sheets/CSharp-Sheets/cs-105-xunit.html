Unit Testing with xUnit

xUnit is the most widely used .NET test framework. A test is a public method marked [Fact]; [Theory] runs the same test with several data sets. A new instance of the test class is created per test, so the constructor is your setup and Dispose your teardown. xUnit v3 (package xunit.v3) builds tests as executables.

Key Facts

  • v3 templates: dotnet new install xunit.v3.templates
  • Run: dotnet test (or the test exe in v3)
  • Assert.Equal(expected, actual) — expected first
  • Async tests return Task / ValueTask

Facts, Theories, Fixtures

public class CalculatorTests(DbFixture db) : IClassFixture<DbFixture>
{
    private readonly Calculator _calc = new();      // fresh per test

    [Fact]
    public void Add_TwoNumbers_ReturnsSum()
    {
        int result = _calc.Add(2, 3);               // Act
        Assert.Equal(5, result);                    // Assert
    }

    [Theory]
    [InlineData(2, 2, 4)]
    [InlineData(-1, 1, 0)]
    public void Add_Cases(int a, int b, int expected) =>
        Assert.Equal(expected, _calc.Add(a, b));

    [Fact]
    public async Task Divide_ByZero_Throws() =>
        await Assert.ThrowsAsync<DivideByZeroException>(
            () => _calc.DivAsync(1, 0));
}

Code Explained

IClassFixture<T> — one shared fixture for all tests in the class
Constructor — runs before each test
[Fact] — single test case
[Theory] + [InlineData] — parameterized test
Assert.Equal(expected, actual)
ThrowsAsync<T> — assert an async exception

Common Asserts

AssertChecks
Equal / NotEqualValues (collections too)
True / FalseCondition
Null / NotNullReference
Contains / DoesNotContainItem or substring
Throws<T>(() => …)Exact exception type

Running Tests

CommandDoes
dotnet testBuild + run all
dotnet test --filter Name~AddName contains "Add"
dotnet test --filter Category=SlowBy [Trait]
dotnet watch testRe-run on save

⚠ Common Mistakes

  • Swapping Assert.Equal arguments — failure messages show expected/actual reversed
  • Sharing state in static fields between tests — tests run in parallel across classes and interfere
  • async void test methods — failures can be missed; return Task

✓ Tips & Best Practices

  • Name tests Method_Scenario_Expected
  • Follow Arrange-Act-Assert with blank lines between
  • Use TestContext.Current.CancellationToken (v3) in async tests

Quick Summary

  • [Fact] — single test
  • [Theory] + [InlineData] — data-driven
  • Constructor / Dispose — setup / teardown
  • IClassFixture<T> — shared expensive setup
