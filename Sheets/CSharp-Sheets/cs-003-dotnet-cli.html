Sheet 003

The dotnet CLI

dotnet new · dotnet run · dotnet build · dotnet test · dotnet add package · dotnet publish · dotnet watch

One Tool for Everything

The dotnet CLI creates, builds, runs, tests, packages and publishes projects. Every IDE calls it under the hood, so anything you do in Visual Studio can be scripted. Commands act on the project or solution in the current folder unless you pass a path.

Key Facts

  • dotnet <command> --help lists every option
  • run, test and publish build first automatically
  • Default configuration is Debug; use -c Release
  • Output goes to bin/ and obj/ (don't commit them)

Typical Workflow

dotnet new console -o MyApp         # create project in ./MyApp
cd MyApp
dotnet add package Serilog          # add a NuGet package
dotnet build                        # compile → bin/Debug/net10.0/
dotnet run -- --name Bob            # run; args after -- go to app
dotnet watch                        # rebuild + rerun on save

dotnet new xunit -o MyApp.Tests     # test project
dotnet add MyApp.Tests reference MyApp
dotnet test                         # run all tests

dotnet publish -c Release -o out    # deployable output
dotnet clean                        # remove build output

Code Explained

-o — output folder (also sets the project name)
-- — everything after it is passed to your program
watch — hot reload for supported edits
add reference — project-to-project reference
publish — trimmed, ready-to-deploy files
-c Release — optimized build

Core Commands

CommandDoes
dotnet new <template>Create project/file from a template
dotnet new listShow installed templates
dotnet buildCompile project or solution
dotnet runBuild and run
dotnet testRun unit tests
dotnet formatApply .editorconfig style fixes

Packages & Tools

CommandDoes
dotnet add package XAdd NuGet PackageReference
dotnet remove package XRemove a package
dotnet list package --outdatedFind upgrades
dotnet restoreDownload dependencies
dotnet packBuild a .nupkg
dotnet tool install -g XInstall a global CLI tool

⚠ Common Mistakes

  • Passing app args without -- — dotnet run --name Bob is read as a CLI option
  • Running dotnet test from a folder with several projects and no solution — it can't pick one
  • Shipping a Debug build — always publish -c Release

✓ Tips & Best Practices

  • Use dotnet watch test for a fast test loop
  • dotnet new gitignore adds a correct .NET .gitignore
  • dotnet format in CI keeps style consistent

Quick Summary

  • dotnet new — scaffold projects
  • dotnet run / watch — run and hot-reload
  • dotnet test — run tests
  • dotnet publish -c Release — ship it
