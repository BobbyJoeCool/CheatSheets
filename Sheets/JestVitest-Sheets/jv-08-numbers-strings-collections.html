Numbers, Strings & Collections

Matchers for Everyday Values

Number matchers compare sizes and floats within a tolerance. toMatch checks strings against a regex or substring. toContain checks an item in an array (by ===) or a substring; toContainEqual checks by structure. toHaveLength, toHaveProperty and toMatchObject check shape without spelling out the whole object.

Notes

  • toBeCloseTo(v, digits) — default 2 decimal digits
  • toHaveProperty("a.b[0]", v) takes a path
  • toMatchObject ignores extra properties
  • Works on Sets and Maps too: toContain on a Set checks membership

Numbers, Strings, Arrays, Objects

expect(0.1 + 0.2).toBeCloseTo(0.3)          // 2 digits by default
expect(price).toBeCloseTo(19.99, 2)
expect(items.length).toBeGreaterThan(0)
expect(age).toBeGreaterThanOrEqual(18)
expect(latency).toBeLessThan(200)

expect(message).toMatch(/order \d+ shipped/)
expect(message).toMatch('shipped')           // substring
expect(slug).not.toMatch(/\s/)

expect(['apple', 'pear']).toContain('pear')
expect([{ id: 1 }, { id: 2 }]).toContainEqual({ id: 2 })
expect(cart.items).toHaveLength(3)

expect(order).toHaveProperty('status', 'paid')
expect(order).toHaveProperty('address.city', 'Tripoli')
expect(order).toHaveProperty(['lines', 0, 'sku'])

expect(order).toMatchObject({
  status: 'paid',
  lines: [{ sku: 'A1' }],                    // partial match inside arrays too
})

Code Explained

toBeCloseTo(v, 2) passes when the difference is below 0.005
toContain on objects compares references; use toContainEqual for objects
toHaveProperty with a path avoids chains of ?. in assertions
toMatchObject checks only the properties you list

Jest ↔ Vitest

  • Identical in Jest
  • Both accept arrays of keys in toHaveProperty

TypeScript

  • toHaveProperty paths aren't type-checked; a typo just fails at run time
  • For typed partials, build the expected object with Partial<Order>

Prefer / Avoid

  • expect(arr.includes(x)).toBe(true) → expect(arr).toContain(x)
  • toEqual on a huge object to check two fields → toMatchObject
  • toBe(0.3) on float math → toBeCloseTo(0.3)

⚠ Common Mistakes

  • toContain({ id: 2 }) on an array of objects (always fails: different references)
  • toBeCloseTo(19.99) on money where 2 digits isn't the tolerance you meant
  • Using toMatch with an unescaped . or ? in a regex

✓ Tips & Best Practices

  • Prefer toMatchObject for API responses with many incidental fields
  • Pass the precision to toBeCloseTo explicitly
  • Use toHaveLength for clearer failure messages than comparing .length

Quick Summary

  • toBeCloseTo — floats
  • toMatch — regex / substring
  • toContain / toContainEqual — membership
  • toHaveProperty / toMatchObject — shape
