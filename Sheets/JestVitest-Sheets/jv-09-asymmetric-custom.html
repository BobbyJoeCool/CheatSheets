Sheet 09

Asymmetric, Soft & Custom Matchers

expect.any · expect.objectContaining · arrayContaining · stringMatching · expect.soft · expect.poll · expect.extend

Match "Something Like This"

Asymmetric matchers stand in for a value inside toEqual, toHaveBeenCalledWith and friends: expect.any(Number) matches any number, expect.objectContaining({...}) any object with those fields. expect.soft records a failure and keeps going, expect.poll retries until a condition holds, and expect.extend adds your own matchers.

Notes

  • Use asymmetric matchers for IDs, dates and other values you can't predict
  • expect.not.objectContaining inverts
  • Soft failures still fail the test at the end
  • Put expect.extend in a setup file so all tests get it

Flexible Assertions

expect(createOrder({ sku: 'A1' })).toEqual({
  id: expect.any(String),
  createdAt: expect.any(Date),
  sku: 'A1',
  lines: expect.arrayContaining([expect.objectContaining({ qty: 1 })]),
  status: expect.stringMatching(/^(new|pending)$/),
  meta: expect.anything(),                  // anything except null / undefined
})

expect(send).toHaveBeenCalledWith(expect.objectContaining({ to: 'ann@x.com' }))

expect.soft(res.status).toBe(200)           // keep going after a failure
expect.soft(res.headers['cache-control']).toBe('no-store')

await expect.poll(() => queue.size(), { timeout: 2000 }).toBe(0)

expect.extend({
  toBeValidSku(received: string) {
    const pass = /^[A-Z]\d{2,}$/.test(received)
    return { pass, message: () => `expected ${received} ${pass ? 'not ' : ''}to be a SKU` }
  },
})
expect('A12').toBeValidSku()

Code Explained

expect.any(Date) matches any Date instance without fixing its value
arrayContaining passes if the listed items appear anywhere, in any order
expect.poll calls the function until the matcher passes or the timeout ends
A custom matcher returns pass and a message function

Jest ↔ Vitest

  • Jest has the same asymmetric matchers and expect.extend
  • No expect.soft or expect.poll in Jest

TypeScript

  • Declare custom matchers: interface Assertion<T> { toBeValidSku(): T } in declare module "vitest"
  • Jest: augment jest.Matchers<R> instead

Prefer / Avoid

  • deleting id / createdAt before comparing → expect.any(...)
  • setTimeout + assert for async state → expect.poll
  • the same complex check copied into many tests → expect.extend

⚠ Common Mistakes

  • Using expect.anything() and accepting values you should check
  • Writing a custom matcher without a useful failure message
  • Polling with no timeout and hanging the suite

✓ Tips & Best Practices

  • Combine toEqual with asymmetric matchers to assert the whole shape at once
  • Use expect.soft for several independent checks on one response
  • Write custom matcher messages that say what was expected and what arrived

Quick Summary

  • expect.any / objectContaining — flexible values
  • expect.soft — continue after failure
  • expect.poll — retry until true
  • expect.extend — your own matchers
