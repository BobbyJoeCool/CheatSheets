Sheet 20

Coverage

--coverage · provider: 'v8' vs 'istanbul' · thresholds · include / exclude · reporters (text · html · lcov) · ignore comments

Which Code the Tests Ran

vitest run --coverage reports which lines, branches and functions ran. The v8 provider (default) reads V8's built-in counters and is fast; istanbul instruments code first and works in any JavaScript engine. Set include so untested files count, and thresholds to fail CI when coverage drops.

Notes

  • Install the provider: npm i -D @vitest/coverage-v8
  • Without include, files no test imports are left out of the report
  • html report: open coverage/index.html
  • Coverage shows what ran, not whether the assertions were good

Under the Hood

  • v8 coverage uses counters the engine keeps anyway, then maps them back through source maps
  • istanbul rewrites code with counters before running it
  • Vitest's v8 provider remaps results to match istanbul accuracy, but small differences remain

Coverage Config

// vitest.config.ts
test: {
  coverage: {
    provider: 'v8',                     // or 'istanbul'
    include: ['src/**/*.{ts,tsx}'],
    exclude: ['src/**/*.stories.tsx', 'src/test/**', '**/*.d.ts'],
    reporter: ['text', 'html', 'lcov'],
    thresholds: {
      lines: 80,
      branches: 75,
      functions: 80,
      'src/billing/**': { lines: 95 },  // stricter for one folder
    },
  },
}

// $ npx vitest run --coverage
// File       | % Stmts | % Branch | % Funcs | % Lines | Uncovered
// cart.ts    |   92.3  |   83.3   |   100   |   92.3  | 41-43

/* v8 ignore next */
if (import.meta.env.DEV) debugPanel()

Code Explained

include makes untested files show up at 0% instead of disappearing
Glob keys in thresholds set stricter rules for critical folders
lcov feeds Codecov, Coveralls and editor gutter extensions
/* v8 ignore next */ (or /* istanbul ignore next */) skips a line or block

Jest ↔ Vitest

  • Jest: jest --coverage, coverageProvider: "v8" | "babel", collectCoverageFrom, coverageThreshold
  • Jest uses istanbul (babel) by default

TypeScript

  • Exclude *.d.ts and type-only files; they have no runtime code
  • Coverage maps to your .ts source through source maps

Prefer / Avoid

  • chasing 100% → meaningful tests on risky code
  • ignore comments everywhere → exclude patterns
  • no include → include: ["src/**"] so gaps show

⚠ Common Mistakes

  • Forgetting include, so coverage looks high because untested files aren't counted
  • Turning on coverage in watch mode and slowing every rerun
  • Treating the number as proof of quality

✓ Tips & Best Practices

  • Run coverage only in CI or on demand
  • Use per-folder thresholds for critical code
  • Read the uncovered lines in the HTML report, not just the percentages

Quick Summary

  • --coverage — measure
  • v8 (fast) vs istanbul (portable)
  • include — count untested files
  • thresholds — fail below a floor
