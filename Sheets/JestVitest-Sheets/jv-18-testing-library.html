Testing Library

render · screen · getByRole / findBy* / queryBy* · userEvent · @testing-library/jest-dom matchers · cleanup

Test Components Like a User

Testing Library renders a component and lets you find elements the way a user would: by role, label and text, not by CSS class. user-event simulates real typing and clicking, and jest-dom adds matchers like toBeInTheDocument and toBeDisabled. There are versions for React, Vue, Svelte and more; this sheet uses React. The React set covers the components themselves.

Notes

  • npm i -D @testing-library/react @testing-library/user-event @testing-library/jest-dom
  • getBy* throws if missing, queryBy* returns null, findBy* waits (async)
  • Import @testing-library/jest-dom/vitest in the setup file
  • Cleanup is automatic when globals: true; otherwise call cleanup in afterEach

A Component Test

import { render, screen } from '@testing-library/react'
import userEvent from '@testing-library/user-event'
import { LoginForm } from './LoginForm'

test('submits email and password', async () => {
  const user = userEvent.setup()
  const onSubmit = vi.fn()
  render(<LoginForm onSubmit={onSubmit} />)

  await user.type(screen.getByLabelText(/email/i), 'ann@example.com')
  await user.type(screen.getByLabelText(/password/i), 'hunter2')
  await user.click(screen.getByRole('button', { name: /sign in/i }))

  expect(onSubmit).toHaveBeenCalledWith({ email: 'ann@example.com', password: 'hunter2' })
})

Code Explained

getByLabelText finds the input a <label> points to, which also checks accessibility
userEvent.setup() then await user.type(...) fires the full sequence of key events
findByRole waits for the alert to appear after the async request
queryBy… + not.toBeInTheDocument() asserts something is absent

Jest ↔ Vitest

  • Same libraries in Jest; import @testing-library/jest-dom (no /vitest) in setupFilesAfterEnv
  • Browser mode uses vitest-browser-react instead (sheet 19)

TypeScript

  • Add "types": ["@testing-library/jest-dom"] so matchers are typed
  • Queries return HTMLElement; narrow with toBeInstanceOf(HTMLInputElement) when needed

Prefer / Avoid

  • getByTestId everywhere → getByRole / getByLabelText
  • fireEvent.change → user.type
  • waitFor(() => getBy…) → findBy…

Query Priority

QueryUse for
getByRole(role, { name })Buttons, links, headings, inputs (first choice)
getByLabelTextForm fields
getByPlaceholderTextInputs without labels
getByTextNon-interactive text
getByDisplayValueCurrent input value
getByAltText / getByTitleImages, titles
getByTestIdLast resort

jest-dom Matchers

MatcherChecks
toBeInTheDocument()In the DOM
toBeVisible()Not hidden
toBeDisabled() / toBeEnabled()Disabled state
toHaveTextContent(t)Text
toHaveValue(v)Input value
toHaveAttribute(a, v?)Attribute
toHaveAccessibleName(n)Accessible name

⚠ Common Mistakes

  • Querying by class names or DOM structure that changes with styling
  • Using getBy… for something that appears later; use findBy…
  • Forgetting await on user events

✓ Tips & Best Practices

  • If you can't find an element by role, the component may have an accessibility problem
  • Use screen.debug() to print the current DOM
  • Use Testing Playground (screen.logTestingPlaygroundURL()) to find the best query

Quick Summary
