Sheet 12

Spies & Resetting Mocks

vi.spyOn · spying on getters · mockClear vs mockReset vs mockRestore · restoreMocks / clearMocks config · vi.restoreAllMocks

Watch Real Methods, Then Clean Up

vi.spyOn(object, "method") wraps an existing method: by default the real code still runs, but calls are recorded. Add .mockReturnValue or .mockImplementation to replace it. Mocks keep their history and behavior until you clear, reset or restore them, so set that up once in config instead of in every file.

Notes

  • Spy on getters / setters with vi.spyOn(obj, "prop", "get")
  • Only mockRestore puts the original method back
  • restoreMocks: true in config restores spies after every test
  • Spy on console.error to assert or silence warnings

Spies and Cleanup

import * as api from './api'

test('logs a warning for large discounts', () => {
  const warn = vi.spyOn(console, 'warn').mockImplementation(() => {})
  applyDiscount(cart, 0.9)
  expect(warn).toHaveBeenCalledWith(expect.stringContaining('large discount'))
})

test('uses the cached price', () => {
  const fetchPrice = vi.spyOn(api, 'fetchPrice')     // real fn still runs
  getPrice('A1'); getPrice('A1')
  expect(fetchPrice).toHaveBeenCalledTimes(1)
})

test('getter', () => {
  vi.spyOn(navigator, 'onLine', 'get').mockReturnValue(false)
  expect(isOffline()).toBe(true)
})

// vitest.config.ts
// test: { restoreMocks: true }     // restore spies after each test

afterEach(() => {
  vi.clearAllMocks()                 // clear call history only
})

Code Explained

mockImplementation(() => {}) silences console.warn while still recording it
Spying on an ESM namespace export works in Vitest for many cases; module mocking (sheet 13) is the reliable route
The getter form needs the third argument "get"
restoreMocks: true is the simplest way to avoid spies leaking between tests

Jest ↔ Vitest

  • Jest: jest.spyOn, jest.clearAllMocks, same config keys
  • Difference: in Vitest 3+, mockReset restores the original implementation; in Jest it leaves an empty function
  • Vitest's restoreAllMocks only touches spies made with vi.spyOn

TypeScript

  • Spies are typed from the object: vi.spyOn(api, "fetchPrice") knows the signature
  • A wrong method name is a type error, not a run-time surprise

Prefer / Avoid

  • manual cleanup in every file → restoreMocks: true
  • replacing console.error = vi.fn() → vi.spyOn(console, "error")
  • spying on internals to test implementation → test outputs

Clear vs Reset vs Restore

MethodCallsBehaviorOriginal
mockClear()ClearedKeptStill mocked
mockReset()ClearedBack to original impl (Vitest) / empty (Jest)Still mocked
mockRestore()ClearedOriginalPut back (spies)

Config & Globals

ItemEffect
clearMocks: truemockClear all before each test

⚠ Common Mistakes

  • Expecting mockClear to remove a mockReturnValue
  • Spying on console.error without restoring it, hiding errors in later tests
  • Assuming Jest and Vitest mockReset behave the same during a migration

✓ Tips & Best Practices

  • Set restoreMocks: true in every project
  • Fail tests on unexpected console.error with a spy in a setup file
  • Spy, don't replace, when you only need to count calls

Quick Summary

  • vi.spyOn(obj, "m") — record a real method
  • clear → history · reset → behavior · restore → original
  • restoreMocks: true — clean up automatically
  • getter spies — third arg "get"
