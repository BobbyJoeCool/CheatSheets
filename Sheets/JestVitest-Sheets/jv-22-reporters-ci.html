Sheet 22

Reporters & CI

--reporter · default / verbose / dot · junit · json · github-actions reporter · --bail · CI env behavior

Output for People and for CI

A reporter formats results. default shows a summary and failures; verbose lists every test; dot is compact; junit and json write files for CI dashboards; github-actions turns failures into annotations on the PR's changed lines. When the CI environment variable is set, Vitest runs once, disables watch mode and fails on .only.

Notes

  • Combine reporters: --reporter=default --reporter=junit
  • outputFile sets where file reporters write
  • --bail N stops after N failures
  • The GitHub set covers workflow syntax

CI Setup

# vitest.config.ts
# test: {
#   reporters: process.env.CI ? ['default', 'junit', 'github-actions'] : ['default'],
#   outputFile: { junit: './reports/junit.xml' },
# }

# .github/workflows/test.yml
name: test
on: [push, pull_request]
jobs:
  vitest:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6
      - uses: actions/setup-node@v6
        with: { node-version: 24, cache: npm }
      - run: npm ci
      - run: npx tsc --noEmit
      - run: npx vitest run --coverage
      - uses: actions/upload-artifact@v7
        if: always()
        with: { name: reports, path: reports/ }

Code Explained

Choosing reporters by CI keeps local output short and CI output complete
github-actions annotations appear on the exact failing lines in the PR
tsc --noEmit type-checks, since Vitest only strips types
if: always() uploads reports when tests fail too

Jest ↔ Vitest

  • Jest: --reporters=default --reporters=jest-junit (separate package)
  • Jest: --ci makes missing snapshots fail; Vitest does that automatically under CI
  • GitHub annotations in Jest need a third-party reporter

TypeScript

  • Run tsc --noEmit (or vitest --typecheck) as its own CI step
  • Type errors don't fail vitest run

Prefer / Avoid

  • parsing console output in CI → junit / json reporters
  • only running vitest run → add a separate type-check step
  • --bail 1 in CI → see all failures; bail locally

⚠ Common Mistakes

  • Forgetting outputFile and losing the JUnit file in stdout
  • No type-check step, so type errors merge
  • Uploading artifacts only on success

✓ Tips & Best Practices

  • Use github-actions reporter on GitHub for inline failure annotations
  • Upload the HTML coverage report as an artifact
  • Keep the CI command identical to a local npm run test:ci script

Quick Summary

  • --reporter — output format
  • junit / json + outputFile — CI files
  • github-actions — PR annotations
  • CI=true — run once, strict
