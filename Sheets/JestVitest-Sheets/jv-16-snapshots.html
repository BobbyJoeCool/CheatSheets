Snapshot Testing

toMatchSnapshot · toMatchInlineSnapshot · toMatchFileSnapshot · -u to update · obsolete snapshots · serializers · when not to snapshot

Compare Against a Stored Result

A snapshot test serializes a value and compares it with a stored copy. The first run writes the snapshot; later runs fail if the output changes, until you review and update it with -u. Inline snapshots are written into the test file itself, and Vitest's file snapshots compare against any file (HTML, JSON). Snapshots are best for output that's tedious to assert by hand.

Notes

  • Snapshots live in __snapshots__/<file>.snap; commit them
  • Review snapshot diffs in PRs like code
  • Obsolete snapshots are reported; -u removes them
  • In CI, missing snapshots fail instead of being written

Snapshot Kinds

test('renders an invoice', () => {
  expect(renderInvoice(order)).toMatchSnapshot()
})

test('formats an address', () => {
  expect(formatAddress(addr)).toMatchInlineSnapshot(`
    "Bob Smith
    1 Main St
    Tripoli, IA 50676"
  `)                                    // filled in on first run
})

test('email HTML', async () => {
  await expect(renderEmail(order)).toMatchFileSnapshot('./__snapshots__/email.html')
})

test('dynamic fields', () => {
  expect(createOrder()).toMatchSnapshot({
    id: expect.any(String),             // property matchers
    createdAt: expect.any(Date),
  })
})

// $ npx vitest -u     update snapshots after reviewing the change

Code Explained

toMatchInlineSnapshot() with no argument writes the value into the test source on the first run
File snapshots keep large output in its own file with proper syntax highlighting
Property matchers stop changing IDs and dates from breaking the snapshot
u in watch mode updates the failing snapshots

Jest ↔ Vitest

  • Jest has toMatchSnapshot and toMatchInlineSnapshot (needs Prettier 3 handling in Jest 30)
  • No file snapshots in Jest
  • Snapshot file headers differ (// Vitest Snapshot v1 vs // Jest Snapshot v1)

TypeScript

  • Snapshots serialize values, not types; use expectTypeOf for API type shapes
  • Inline snapshots are template strings; avoid backticks in snapshotted text

Prefer / Avoid

  • snapshotting whole React trees → snapshot small, stable output or assert with Testing Library
  • running -u without reading the diff → review every change
  • huge .snap files nobody reads → inline or file snapshots, or real assertions

⚠ Common Mistakes

  • Updating snapshots to make CI green without checking the change was intended
  • Snapshotting values with dates or random IDs
  • Snapshots so large the diff is unreadable

✓ Tips & Best Practices

  • Prefer inline snapshots for small values; they're reviewed in the test itself
  • Use property matchers or serializers to normalize volatile fields
  • Delete obsolete snapshots regularly with -u

Quick Summary

  • toMatchSnapshot — stored file
  • toMatchInlineSnapshot — in the test
  • toMatchFileSnapshot — any file (Vitest)
  • -u — update after review
