Sheet 13

Module Mocking

vi.mock(path, factory) · hoisting · importOriginal · partial mocks · __mocks__ folders · vi.doMock · vi.hoisted

Replace a Whole Import

vi.mock(path, factory) replaces a module for every import in the test file. Vitest hoists vi.mock calls to the top of the file, before imports, so the mocked version is what your code gets. Return the fake exports from the factory; use importOriginal for a partial mock that keeps the real exports you don't override. Without a factory, Vitest automocks every export or uses a __mocks__ file.

Notes

  • The path is resolved like an import from the test file
  • Variables used in the factory must come from vi.hoisted
  • Default exports need a default key in the factory
  • vi.doMock is not hoisted; it affects later dynamic imports only

Under the Hood

  • Vitest rewrites the file so vi.mock runs before any import statement
  • That's why a factory can't use variables declared normally in the file: they don't exist yet
  • Mocks apply per test file; each file has its own module graph

Mocking Imports

import { vi, test, expect } from 'vitest'
import { checkout } from './checkout'
import { charge } from './payments'

vi.mock('./payments', () => ({
  charge: vi.fn().mockResolvedValue({ id: 'ch_1' }),
}))

// partial mock: keep everything real except fetchRate
vi.mock('./rates', async (importOriginal) => ({
  ...(await importOriginal<typeof import('./rates')>()),
  fetchRate: vi.fn(() => 1.1),
}))

// variables for a factory must be hoisted too
const { sendMail } = vi.hoisted(() => ({ sendMail: vi.fn() }))
vi.mock('./mailer', () => ({ default: { send: sendMail } }))

test('checkout charges and emails', async () => {
  await checkout(cart)
  expect(charge).toHaveBeenCalledWith(cart.total)
  expect(sendMail).toHaveBeenCalledOnce()
})

vi.mock('node:fs')                  // automock, or __mocks__/fs.ts at the root

Code Explained

charge is imported normally; because of hoisting it's the mocked version
importOriginal spreads the real module, then overrides one export
vi.hoisted makes sendMail available when the hoisted factory runs
A default key mocks a default export

Jest ↔ Vitest

  • Jest: jest.mock(path, factory) (hoisted by babel-jest), jest.requireActual for partials
  • Jest factories may only reference variables named mock…
  • Jest's ESM module mocking needs jest.unstable_mockModule + dynamic import

TypeScript

  • Type the partial with importOriginal<typeof import("./rates")>()
  • Use vi.mocked(charge) to get a typed mock of an imported function
  • vi.mock(import("./payments"), …) gives the factory typed exports

Prefer / Avoid

  • mocking your own internal modules everywhere → inject dependencies or mock at the network edge (MSW)
  • full factory copying every export → importOriginal partial mock
  • variables declared above vi.mock → vi.hoisted

Module Mock API

⚠ Common Mistakes

  • Referencing a normal variable inside the factory ("Cannot access before initialization")
  • Forgetting default when the module has a default export
  • Mocking a module in one file and expecting it in another

✓ Tips & Best Practices

  • Prefer MSW (sheet 15) over mocking your HTTP client module
  • Use partial mocks so new exports don't break tests
  • Check vi.mocked(fn).mock.calls when an assertion on a mocked import fails

Quick Summary

  • vi.mock(path, factory) — hoisted replacement
  • importOriginal — partial mocks
  • vi.hoisted — values for factories
  • __mocks__/ — reusable mocks
