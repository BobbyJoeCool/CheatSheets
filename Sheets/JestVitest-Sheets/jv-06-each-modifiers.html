Sheet 06

Parameterized Tests & Modifiers

test.each · test.for · .only / .skip / .todo · .fails · .concurrent · skipIf / runIf · tags

Cases in a Table, Tests With Switches

test.each (and describe.each) runs one test per row of data, with the row values in the test name. Vitest's test.for is similar but passes each case as one argument and gives you the test context. Modifiers change how a test runs: .only focuses it, .skip skips it, .todo lists it as unwritten, .fails expects it to fail, and .concurrent runs it in parallel with siblings.

Notes

  • %s, %d, %o format values into test names; $name reads object fields
  • skipIf(cond) and runIf(cond) decide at collection time
  • .only in CI fails the run when allowOnly is false (the default in CI)
  • Vitest 4.1+ adds test tags for grouping and filtering

Under the Hood

  • .concurrent tests in one file share a worker and run their async parts interleaved
  • Shared module state or fake timers break under .concurrent
  • Use the context's expect (({ expect }) => …) so snapshot and assertion counts stay per test

each, for and Modifiers

test.each([
  [[], 0, 0],
  [[10, 10], 0.25, 15],
  [[9.99], 0, 9.99],
])('total(%o, %d) → %d', (prices, discount, expected) => {
  expect(total(prices, discount)).toBe(expected)
})

test.each([
  { country: 'US', rate: 0.07 },
  { country: 'DE', rate: 0.19 },
])('tax for $country is $rate', ({ country, rate }) => {
  expect(taxRate(country)).toBe(rate)
})

test.for(['USD', 'EUR'])('formats %s', (cur, { expect }) => {
  expect(format(1, cur)).toMatch(/1/)
})

test.skipIf(process.platform === 'win32')('uses symlinks', () => {})
test.todo('handles refunds over 90 days')
test.fails('known bug #142', () => { expect(round(0.1 + 0.2)).toBe(0.3) })
test.concurrent('fetches a', async ({ expect }) => { /* … */ })

Code Explained

Array rows spread into arguments; object rows arrive as one argument you destructure
$country in the name pulls the field from each object row
test.for passes each case whole and the context second, so expect is per test
.fails passes only while the assertion fails, like pytest's strict xfail

Jest ↔ Vitest

  • Jest has test.each and describe.each (arrays, objects, or a tagged-template table)
  • No test.for, skipIf, runIf or .fails in Jest; use .failing and plain if
  • .concurrent exists in Jest but is less used

TypeScript

  • test.each infers row types; add as const for literal types
  • Type object rows: test.each<{ country: string; rate: number }>([…])

Prefer / Avoid

  • a for loop around expect → test.each
  • committing .only → -t on the command line
  • .skip with no note → .todo or a skip with an issue link in the name

⚠ Common Mistakes

  • Mutating a shared row object in one case and breaking the next
  • Leaving .only in a file; CI fails (or locally, other tests silently don't run)
  • Using .concurrent with fake timers or shared mocks

✓ Tips & Best Practices

  • Use object rows with $field names for readable reports
  • Put the expected value in each row so the table is the spec
  • Use test.todo to sketch cases before writing them

Quick Summary

  • test.each — table-driven tests
  • test.for — cases + context (Vitest)
  • .only / .skip / .todo / .fails
  • .concurrent — parallel within a file
