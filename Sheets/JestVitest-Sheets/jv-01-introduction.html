Introduction: Vitest & Jest

what a test runner does · Vitest vs Jest · Jest-compatible API · when to pick each · npm i -D vitest · first test

Two Runners, One API

A test runner finds test files, runs them, and reports which assertions failed. Jest (Meta, now OpenJS) made describe / it / expect the standard API for JavaScript. Vitest (from the Vite team) uses the same API but runs on Vite's transform pipeline, so TypeScript, ESM and JSX work with no extra config and watch mode is fast. This set teaches Vitest first and shows Jest beside it.

Notes

  • Pick Vitest for Vite, Vue, Svelte, Astro, Nuxt and most new projects
  • Pick Jest for React Native and existing Jest suites
  • Both run in Node by default; a DOM environment is opt-in (sheet 17)
  • End-to-end browser testing is the Playwright set's job

Under the Hood

  • Vitest transforms each file with Vite's plugins (TS, JSX, aliases) on demand, so it shares config with your app
  • Jest uses its own module registry and transformers (Babel, ts-jest, SWC) configured separately

First Test

// src/cart.js
export function total(prices, discount = 0) {
  if (discount < 0 || discount >= 1) throw new RangeError('discount 0..1')
  return Math.round(prices.reduce((a, b) => a + b, 0) * (1 - discount) * 100) / 100
}

// src/cart.test.js
import { describe, it, expect } from 'vitest'
import { total } from './cart.js'

describe('total', () => {
  it('adds prices', () => {
    expect(total([2.5, 1.25])).toBe(3.75)
  })
  it('applies a discount', () => {
    expect(total([10, 10], 0.25)).toBe(15)
  })
})

// $ npm i -D vitest
// $ npx vitest          → watch mode
//  ✓ src/cart.test.js (2 tests) 3ms

Code Explained

Test files end in .test.js / .spec.js (or .ts, .tsx) and sit next to the code
describe groups tests; it (or test) is one test; expect(x).toBe(y) asserts
Importing describe, it, expect from vitest keeps tests explicit (sheet 02 shows globals)
npx vitest watches by default in a terminal; vitest run runs once

Jest ↔ Vitest

  • npm i -D jest · run with npx jest
  • Jest provides describe / it / expect as globals, no import needed
  • TypeScript and ESM need a transformer in Jest (sheet 23)

TypeScript

  • Name test files *.test.ts; Vitest runs TS directly, no build step
  • Vitest only strips types; run tsc --noEmit separately to type-check

Prefer / Avoid

  • console.log checks by eye → expect assertions
  • one giant test → small tests named after behavior
  • tests in a separate tree far from the code → *.test.ts next to the module

⚠ Common Mistakes

  • Mixing Jest and Vitest globals in one project and getting "vi is not defined" or "jest is not defined"
  • Expecting Vitest to type-check; type errors only show with tsc
  • Writing browser end-to-end flows as unit tests; use Playwright for those

✓ Tips & Best Practices

  • Keep tests next to the code (cart.ts + cart.test.ts)
  • Add "test": "vitest" and "test:ci": "vitest run" scripts
  • Run tsc --noEmit as a separate CI step

Quick Summary

  • Vitest — Jest API on Vite
  • Jest — the original; React Native default
  • describe / it / expect — same in both
  • vitest watches · vitest run once
