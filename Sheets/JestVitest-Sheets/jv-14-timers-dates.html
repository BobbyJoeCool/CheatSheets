Sheet 14

Fake Timers & Dates

vi.useFakeTimers · advanceTimersByTime · runAllTimers · runOnlyPendingTimers · vi.setSystemTime · useRealTimers

Control Time Instead of Waiting

Fake timers replace setTimeout, setInterval, Date and friends with versions you move forward by hand. A debounce of 300 ms takes zero real time to test: vi.advanceTimersByTime(300). vi.setSystemTime pins "now" so date logic is predictable. Always switch back with vi.useRealTimers().

Notes

  • Use the …Async versions when timers trigger promises
  • runAllTimers loops forever on a self-rescheduling interval; use runOnlyPendingTimers
  • setSystemTime also accepts Temporal.Instant (Vitest 5.1)
  • Fake timers + .concurrent tests don't mix

Under the Hood

  • Vitest uses @sinonjs/fake-timers to swap the global timer functions and Date
  • toFake chooses which APIs are replaced; nextTick and queueMicrotask are left real by default
  • Libraries that saved a reference to the real setTimeout before faking aren't affected

Debounce, Interval, Dates

import { vi, beforeEach, afterEach, test, expect } from 'vitest'

beforeEach(() => { vi.useFakeTimers() })
afterEach(() => { vi.useRealTimers() })

test('debounced search fires once', () => {
  const search = vi.fn()
  const onType = debounce(search, 300)
  onType('a'); onType('ap'); onType('app')
  vi.advanceTimersByTime(299)
  expect(search).not.toHaveBeenCalled()
  vi.advanceTimersByTime(1)
  expect(search).toHaveBeenCalledExactlyOnceWith('app')
})

test('polls every 5 s', async () => {
  const tick = vi.fn().mockResolvedValue(undefined)
  startPolling(tick, 5000)
  await vi.advanceTimersByTimeAsync(15_000)
  expect(tick).toHaveBeenCalledTimes(3)
})

test('trial expires after 14 days', () => {
  vi.setSystemTime(new Date('2026-11-01T00:00:00Z'))
  const trial = startTrial()
  vi.setSystemTime(new Date('2026-11-15T00:00:01Z'))
  expect(trial.expired()).toBe(true)
})

Code Explained

Moving 299 ms then 1 ms shows the debounce fires exactly at 300
advanceTimersByTimeAsync also flushes promises between timers
setSystemTime changes what new Date() and Date.now() return
Restoring real timers in afterEach keeps other tests safe

Jest ↔ Vitest

  • Jest: jest.useFakeTimers() (modern timers are the default), jest.advanceTimersByTime, jest.setSystemTime
  • Same …Async helpers exist in Jest 29.5+

TypeScript

  • Accept a clock in your code (now: () => Date) and pass a fake; no global faking needed
  • vi.setSystemTime takes Date | number | string

Prefer / Avoid

  • await sleep(300) in tests → fake timers
  • faking timers in every file → only where time matters, restore in afterEach
  • new Date() buried in code → inject a clock

Timer API

⚠ Common Mistakes

  • Forgetting useRealTimers, so later tests hang waiting on real timeouts
  • runAllTimers on an interval and getting an "aborting after 10000 timers" error
  • Awaiting a promise that waits on a timer you never advance

✓ Tips & Best Practices

  • Use the Async variants whenever promises are involved
  • Pin the system time in tests that format dates
  • Prefer injecting a clock for business logic; keep fake timers for UI debounces and polling

Quick Summary

  • vi.useFakeTimers() / useRealTimers()
  • advanceTimersByTime(ms) — move time
  • …Async — flush promises too
  • vi.setSystemTime — pin now
