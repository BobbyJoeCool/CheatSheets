Hooks, Setup Files & Test Context

beforeEach / afterEach · beforeAll / afterAll · cleanup return functions · setupFiles · globalSetup · test.extend fixtures

Setup and Teardown Around Tests

Hooks run code around tests in their describe block: beforeEach / afterEach around every test, beforeAll / afterAll once for the block. A hook can return a cleanup function. Project-wide setup goes in setupFiles (each test file) or globalSetup (once per run). Vitest also has test.extend fixtures, pytest-style setup that only runs for tests that use it.

Notes

  • Hooks in an outer describe run before inner ones
  • Async hooks can await
  • globalSetup runs in a separate context; pass data with provide / inject
  • Each test gets a context object as its first argument

Under the Hood

  • Each test file runs in its own isolated module graph (by default), so module state never leaks between files
  • setupFiles run inside that isolated context before every file; globalSetup runs once in the main process
  • test.extend fixtures are created lazily, only when a test destructures them

Hooks and Fixtures

import { beforeEach, afterEach, beforeAll, test as base, expect } from 'vitest'

let server: TestServer
beforeAll(async () => {
  server = await startServer()
  return () => server.close()          // cleanup when the block ends
})

beforeEach(() => {
  localStorage.clear()
})

afterEach(() => {
  vi.useRealTimers()
})

// test.extend: fixtures only built when requested
const test = base.extend<{ db: Db; user: User }>({
  db: async ({}, use) => {
    const db = await openTestDb()
    await use(db)                      // test runs here
    await db.close()
  },
  user: async ({ db }, use) => {
    await use(await db.createUser('ann'))
  },
})

test('user has no orders', async ({ user, db }) => {
  expect(await db.orders(user.id)).toEqual([])
})

Code Explained

A function returned from beforeAll / beforeEach runs as its teardown
In test.extend, code after await use(…) is teardown
user depends on db; Vitest builds them in order
Tests that don't mention db never open the database

Jest ↔ Vitest

  • Jest hooks are the same; returning a cleanup function is Vitest-only
  • No test.extend in Jest; use hooks or helper functions
  • Jest: setupFiles (before framework) vs setupFilesAfterEnv (after; where matchers go)

TypeScript

  • Type fixtures with the generic: base.extend<{ db: Db }>({ … })
  • Context is typed too: test("x", ({ task, expect }) => …)

Prefer / Avoid

  • module-level let + beforeEach for everything → test.extend fixtures
  • expensive beforeEach → beforeAll + reset state per test
  • teardown in a separate afterAll far from setup → return a cleanup function

Hooks

⚠ Common Mistakes

  • Using beforeAll for state tests modify, so test order changes results
  • Expecting variables set in globalSetup to be visible in tests; use provide / inject
  • Forgetting to await async work in hooks

✓ Tips & Best Practices

  • Return cleanup from hooks to keep setup and teardown together
  • Use test.extend for resources only some tests need
  • Put matchers and global mocks (MSW) in setupFiles

Quick Summary

  • beforeEach / afterEach — around every test
  • beforeAll / afterAll — once per block
  • return a function — cleanup
  • test.extend — lazy fixtures
