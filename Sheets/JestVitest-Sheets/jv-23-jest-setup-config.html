Configuring Jest 30

Jest reads jest.config.(js|ts|mjs|json) or a "jest" key in package.json. Because Jest doesn't use Vite, it needs a transform for TypeScript and JSX (babel-jest, ts-jest or @swc/jest), moduleNameMapper for path aliases and CSS imports, and testEnvironment for DOM tests. ESM support still requires an experimental Node flag.

Notes

  • Jest 30 needs Node 18+ and TypeScript 5.4+
  • npx jest --init writes a starter config
  • setupFilesAfterEnv runs after the test framework loads: put matchers there
  • Jest 30 removed several old matcher aliases and jest.genMockFromModule

jest.config.ts

import type { Config } from 'jest'

const config: Config = {
  testEnvironment: 'jsdom',                    // needs jest-environment-jsdom
  transform: {
    '^.+\\.(t|j)sx?$': ['@swc/jest'],          // or 'ts-jest' / 'babel-jest'
  },
  moduleNameMapper: {
    '^@/(.*)$': '<rootDir>/src/$1',            // match tsconfig paths
    '\\.(css|scss)$': 'identity-obj-proxy',
  },
  setupFilesAfterEnv: ['<rootDir>/jest.setup.ts'],
  testMatch: ['**/?(*.)+(spec|test).[jt]s?(x)'],
  clearMocks: true,
  collectCoverageFrom: ['src/**/*.{ts,tsx}', '!src/**/*.d.ts'],
}
export default config

// ESM without a transform:
// $ node --experimental-vm-modules node_modules/jest/bin/jest.js

Code Explained

transform maps file patterns to transformers; SWC is the fastest option
moduleNameMapper must mirror tsconfig paths and the bundler's aliases
identity-obj-proxy turns CSS-module imports into objects tests can read
A TS config file needs ts-node or Jest's built-in TS config loading

Jest ↔ Vitest

  • Vitest gets transforms, aliases and CSS handling from vite.config for free
  • setupFilesAfterEnv → Vitest setupFiles
  • testEnvironment → environment

TypeScript

  • ts-jest type-checks while testing (slower); @swc/jest and babel-jest only strip types
  • Use import type { Config } from "jest" for a typed config

Prefer / Avoid

  • ts-jest everywhere → @swc/jest for speed + separate tsc check
  • hand-copied aliases → generate moduleNameMapper from tsconfig (pathsToModuleNameMapper in ts-jest)
  • new Vite projects on Jest → Vitest

⚠ Common Mistakes

  • Aliases that work in the app but not in Jest because moduleNameMapper is missing
  • Using removed Jest 30 aliases (toBeCalled, toThrowError)
  • ESM-only dependencies failing with "Cannot use import statement outside a module" (sheet 25)

✓ Tips & Best Practices

  • Keep Jest config small; most complexity is aliases and transforms
  • Use npx jest --showConfig to see the merged config
  • Consider migrating to Vitest if the project already uses Vite (sheet 24)
