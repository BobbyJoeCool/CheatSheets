Installation & Config

vitest.config.ts · test key in vite.config · defineConfig · environment · globals · include / exclude · setupFiles

Configure Once, Shared With Vite

Vitest reads the test block of your vite.config.ts, or a separate vitest.config.ts that wins if both exist. It inherits Vite's plugins and aliases, so tests resolve imports the same way the app does. The common settings are environment (node, jsdom, happy-dom), globals, include, setupFiles and coverage.

Notes

  • Install: npm i -D vitest (+ jsdom or happy-dom for DOM tests)
  • Use defineConfig from vitest/config for typed options
  • setupFiles run before each test file
  • The Vite set covers vite.config itself

vitest.config.ts

import { defineConfig } from 'vitest/config'
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [react()],
  resolve: { alias: { '@': new URL('./src', import.meta.url).pathname } },
  test: {
    environment: 'jsdom',            // 'node' (default) | 'happy-dom'
    globals: true,                   // describe / it / expect without imports
    include: ['src/**/*.{test,spec}.{ts,tsx}'],
    exclude: ['**/node_modules/**', 'e2e/**'],
    setupFiles: ['./vitest.setup.ts'],
    restoreMocks: true,              // undo spies after each test
    testTimeout: 5000,
  },
})

// package.json
// "scripts": { "test": "vitest", "test:ci": "vitest run --coverage" }

Code Explained

plugins and resolve.alias are the same Vite options the app uses
include limits which files are tests; keep end-to-end specs out
setupFiles is where @testing-library/jest-dom/vitest and MSW start (sheets 15, 18)
restoreMocks: true saves writing cleanup in every file

Jest ↔ Vitest

  • Jest: jest.config.ts with testEnvironment, testMatch, setupFilesAfterEnv (sheet 23)
  • globals: true is Jest's default behavior
  • Jest doesn't read vite.config; aliases go in moduleNameMapper

TypeScript

  • With globals: true, add "types": ["vitest/globals"] to tsconfig.json
  • Name the file vitest.config.ts; it's typed through defineConfig

Prefer / Avoid

  • duplicating aliases in a test config → let Vitest reuse vite.config
  • per-file afterEach(() => vi.restoreAllMocks()) → restoreMocks: true
  • one huge setup file → only global setup there; local setup in hooks

⚠ Common Mistakes

  • Having both vite.config.ts and vitest.config.ts and editing the ignored one
  • Turning on globals without updating tsconfig types, so the editor shows errors
  • Putting app setup (real servers, timers) in setupFiles that every test file pays for

✓ Tips & Best Practices

  • Start with the test block in vite.config.ts; split it out only when it grows
  • Add environment per file (sheet 17) instead of making every test use jsdom
  • Keep include tight so Vitest never picks up Playwright specs

Quick Summary

  • test in vite.config or vitest.config.ts
  • environment — node / jsdom / happy-dom
  • globals — skip imports
  • setupFiles — per-file setup
