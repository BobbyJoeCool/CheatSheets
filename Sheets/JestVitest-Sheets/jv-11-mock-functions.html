Mock Functions

vi.fn() · mockReturnValue · mockResolvedValue · mockImplementation · .mock.calls · toHaveBeenCalledWith · toHaveBeenCalledTimes

Fake Functions That Remember

vi.fn() creates a mock function: callable, returns undefined by default, and records every call's arguments, this and result. Configure what it returns with mockReturnValue, mockResolvedValue (promises) or mockImplementation, then assert how it was called with the toHaveBeenCalled… matchers.

Notes

  • …Once variants apply to the next call only, then fall back
  • vi.fn(impl) sets the implementation up front
  • .mock.calls is an array of argument arrays
  • Pass mocks as callbacks or inject them as dependencies

vi.fn in Practice

import { vi, test, expect } from 'vitest'

test('calls onSave with the form data', () => {
  const onSave = vi.fn()
  submitForm({ name: 'Ann' }, onSave)
  expect(onSave).toHaveBeenCalledTimes(1)
  expect(onSave).toHaveBeenCalledWith({ name: 'Ann' })
})

test('retries on failure', async () => {
  const send = vi.fn()
    .mockRejectedValueOnce(new Error('timeout'))
    .mockResolvedValueOnce({ ok: true })
  await expect(sendWithRetry(send)).resolves.toEqual({ ok: true })
  expect(send).toHaveBeenCalledTimes(2)
})

test('custom implementation', () => {
  const price = vi.fn((sku: string) => (sku === 'A1' ? 5 : 0))
  expect(total(['A1', 'B2'], price)).toBe(5)
  expect(price.mock.calls).toEqual([['A1'], ['B2']])
  expect(price).toHaveReturnedWith(5)
  expect(price).toHaveBeenLastCalledWith('B2')
})

Code Explained

toHaveBeenCalledWith passes if any call matched; use …NthCalledWith(n, …) for a specific call
Chained …Once calls define a sequence of results
mock.calls and mock.results let you inspect everything when matchers aren't enough
Injecting send as a parameter avoids module mocking entirely

Jest ↔ Vitest

  • Jest: jest.fn() with the same API
  • Jest 30 removed aliases like toBeCalled, toBeCalledWith, lastCalledWith; use the toHaveBeen… names

TypeScript

  • Type a mock: vi.fn<(sku: string) => number>()
  • Wrap an existing mock for types: vi.mocked(fn).mockReturnValue(…)

Prefer / Avoid

  • mock.calls.length === 1 → toHaveBeenCalledTimes(1)
  • checking every internal call → assert on results; check calls only at boundaries
  • mockImplementation(() => Promise.resolve(x)) → mockResolvedValue(x)

Configure

MethodEffect
mockReturnValue(v) / …OnceReturn v
mockResolvedValue(v) / …OnceReturn Promise.resolve(v)
mockRejectedValue(e) / …OnceReturn Promise.reject(e)
mockImplementation(fn) / …OnceRun fn
mockName("x")Name in failure output

Call Matchers

MatcherChecks
toHaveBeenCalled()At least once
toHaveBeenCalledTimes(n)Exactly n
toHaveBeenCalledWith(…)Some call had these args
toHaveBeenLastCalledWith(…)Last call
toHaveBeenNthCalledWith(n, …)nth call
toHaveReturnedWith(v)Some call returned v

⚠ Common Mistakes

  • Asserting toHaveBeenCalledWith when the mock was called several times and the wrong call matched
  • Mocks keeping calls from earlier tests because nothing cleared them (sheet 12)
  • Over-mocking: tests that only check mocks talk to each other

✓ Tips & Best Practices

  • Inject dependencies as parameters so a vi.fn() is all you need
  • Name mocks with mockName when several appear in one test
  • Use …Once chains to test retry and fallback paths
