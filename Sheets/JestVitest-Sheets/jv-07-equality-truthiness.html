Sheet 07

Equality & Truthiness

toBe · toEqual · toStrictEqual · toBeNull / toBeUndefined / toBeDefined · toBeTruthy / toBeFalsy · .not

Same Object, Same Shape, or Same Exactly

toBe compares with Object.is: right for numbers, strings, booleans and checking the same object. toEqual compares structure recursively, ignoring undefined properties. toStrictEqual also checks undefined keys, array holes and class types. .not inverts any matcher.

Notes

  • toBe(0.1 + 0.2) fails; floats need toBeCloseTo (sheet 08)
  • toEqual treats { a: undefined } and {} as equal
  • toStrictEqual fails if classes differ
  • Failure output shows a diff of the two values

Picking the Right Equality

expect(2 + 2).toBe(4)
expect('ok').toBe('ok')
expect(cart).toBe(cart)                       // same reference

expect({ id: 1, tags: ['a'] }).toEqual({ id: 1, tags: ['a'] })   // ✓
expect({ id: 1, tags: ['a'] }).toBe({ id: 1, tags: ['a'] })      // ✗ different objects

expect({ id: 1, note: undefined }).toEqual({ id: 1 })          // ✓
expect({ id: 1, note: undefined }).toStrictEqual({ id: 1 })    // ✗

class Money { constructor(public cents: number) {} }
expect(new Money(5)).toEqual({ cents: 5 })        // ✓
expect(new Money(5)).toStrictEqual({ cents: 5 })  // ✗ class differs

expect(findUser(99)).toBeNull()
expect(config.port).toBeDefined()
expect(order.paidAt).toBeUndefined()
expect(cart.items.length).toBeTruthy()
expect(errors).not.toContain('timeout')
expect(NaN).toBeNaN()

Code Explained

Use toBe for primitives and identity; use toEqual for objects and arrays
toStrictEqual catches accidental undefined fields in API responses
toBeNull / toBeUndefined give clearer failures than toBe(null)
toBeTruthy accepts any truthy value; be specific when you can

Jest ↔ Vitest

  • All of these are identical in Jest
  • Same Object.is semantics for toBe in both

TypeScript

  • Matchers are typed loosely; expect(x).toEqual<User>(…) is not checked
  • Use expectTypeOf(x).toEqualTypeOf<User>() in *.test-d.ts files for type-level checks

Prefer / Avoid

  • expect(a === b).toBe(true) → expect(a).toBe(b) (better failure output)
  • toEqual on API payloads → toStrictEqual when undefined fields matter
  • toBeTruthy() for a count → toBeGreaterThan(0) or toHaveLength(n)

Equality Matchers

MatcherCompares
toBe(v)Object.is (identity / primitives)
toEqual(v)Deep structure, ignores undefined props
toStrictEqual(v)Deep + undefined + class + holes
toMatchObject(v)Subset of properties (sheet 08)

Truthiness Matchers

MatcherPasses for
toBeNull()null
toBeUndefined()undefined
toBeDefined()Not undefined
toBeTruthy()Any truthy value
toBeFalsy()false, 0, "", null, undefined, NaN
toBeNaN()NaN

⚠ Common Mistakes

  • toBe on objects and arrays, which compares references
  • Assuming toEqual catches extra undefined fields
  • Using toBeTruthy where a specific value matters and missing a wrong value

✓ Tips & Best Practices

  • Default to toEqual for data and toBe for primitives
  • Use toStrictEqual in API contract tests
  • Write the expected value as a literal so the diff reads well

Quick Summary

  • toBe — identity / primitives
  • toEqual — deep structure
  • toStrictEqual — deep + types + undefined
  • .not — invert
