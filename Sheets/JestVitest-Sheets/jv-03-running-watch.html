Sheet 03

Running Tests & Watch Mode

vitest vs vitest run · filters by name / file · -t · --last-failed · --changed · --ui · --project

Run Only What Changed

vitest starts watch mode: it runs the suite, then reruns only the tests affected by each file you save. vitest run runs once and exits, which is what CI uses. Filter by file path (any part of the name), by test name with -t, by failed tests with --last-failed, or by Git changes with --changed.

Notes

  • In watch mode press a all, f failed, p filter file, t filter name, q quit
  • Vitest switches to run-once automatically in CI (CI env var)
  • --ui opens a browser dashboard (@vitest/ui)
  • Add .only temporarily to focus one test (sheet 06)

Under the Hood

  • Vitest keeps a module graph of every test file and its imports
  • On save it reruns only test files whose graph includes the changed file
  • --changed asks Git which files changed and uses the same graph

Command Line

npx vitest                         # watch mode
npx vitest run                     # run once
npx vitest cart                    # files whose path contains "cart"
npx vitest src/cart.test.ts:12     # the test on line 12
npx vitest -t "applies a discount" # by test name (regex)
npx vitest run --last-failed       # only last run's failures
npx vitest run --changed           # tests affected by uncommitted changes
npx vitest run --changed origin/main
npx vitest --ui                    # browser dashboard
npx vitest --project unit          # one project (sheet 21)
npx vitest run --bail 1            # stop after the first failure
npx vitest related src/cart.ts     # tests that import this file

Code Explained

Path filters are substrings, so cart matches src/cart.test.ts and cartItem.test.ts
file:line runs one test by its line number
--changed origin/main is handy in PR builds
vitest related is for lint-staged / pre-commit hooks

Jest ↔ Vitest

  • Jest: npx jest runs once; --watch (changed since commit) or --watchAll
  • -t is the same; --onlyChanged / -o and --findRelatedTests match --changed / related
  • Jest's last-failed: press f in watch mode, or --onlyFailures

TypeScript

  • Vitest runs .ts tests directly; no tsc build before running
  • Use vitest --typecheck to also run *.test-d.ts type tests

Prefer / Avoid

  • vitest run while editing → vitest watch mode
  • rerunning everything after one failure → f in watch or --last-failed
  • leaving .only in commits → -t filters on the command line

⚠ Common Mistakes

  • Running vitest in a CI script without run on a system where CI isn't set; it waits forever
  • Filtering with -t but a path filter that excludes the file
  • Forgetting a test is skipped by .only elsewhere in the file

✓ Tips & Best Practices

  • Keep vitest running in a terminal split while you code
  • Use vitest related in pre-commit to test only touched files
  • Use --ui to browse failures and the module graph on big suites

Quick Summary

  • vitest — watch · vitest run — once
  • path filter / -t — select tests
  • --last-failed / --changed — rerun smart
  • --ui — dashboard
