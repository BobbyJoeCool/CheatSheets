Sheet 25

Jest in React Native

preset: 'react-native' · @testing-library/react-native · mocking native modules · transformIgnorePatterns · timers & animations

Jest Is Still the RN Default

React Native projects use Jest: new apps ship with the react-native preset (or jest-expo for Expo). Components are tested with React Native Testing Library, which renders to a test renderer instead of a device. Native modules don't exist in Node, so they must be mocked, and RN packages published as untranspiled ESM must be added to transformIgnorePatterns. The React Native set covers the app side.

Notes

  • npm i -D @testing-library/react-native
  • Expo: preset: "jest-expo" handles most mocks for you
  • Many libraries ship Jest mocks or a setUpTests helper; check their docs
  • Device behavior (gestures, performance) needs Detox or Maestro end-to-end tests

jest.config.js and a Test

// jest.config.js
module.exports = {
  preset: 'react-native',                       // or 'jest-expo'
  setupFilesAfterEnv: ['<rootDir>/jest.setup.js'],
  transformIgnorePatterns: [
    'node_modules/(?!((jest-)?react-native|@react-native(-community)?|@react-navigation)/)',
  ],
}

// jest.setup.js
jest.mock('@react-native-async-storage/async-storage', () =>
  require('@react-native-async-storage/async-storage/jest/async-storage-mock'))

// Counter.test.tsx
import { render, screen, userEvent } from '@testing-library/react-native'

test('increments', async () => {
  const user = userEvent.setup()
  render(<Counter />)
  await user.press(screen.getByRole('button', { name: 'Add' }))
  expect(screen.getByText('Count: 1')).toBeOnTheScreen()
})

Code Explained

The negative lookahead lets Jest transform the listed RN packages inside node_modules
Library-provided mocks (AsyncStorage here) are the safest way to fake native modules
RNTL's userEvent.press simulates a full press sequence
toBeOnTheScreen is one of RNTL's built-in matchers

Jest ↔ Vitest

  • Vitest has no official RN support; stay on Jest for React Native
  • Shared logic packages (no RN imports) can use Vitest

TypeScript

  • RNTL queries are typed; getByRole("button") returns a host element
  • Use jest-expo presets per platform (jest-expo/ios) for platform files

Prefer / Avoid

  • snapshotting whole screens → RNTL queries and assertions
  • hand-written mocks for popular libraries → their shipped Jest mocks
  • testing animations frame by frame → fake timers and assert end state

⚠ Common Mistakes

  • "SyntaxError: Cannot use import statement" from an RN package missing in transformIgnorePatterns
  • Testing native behavior in Jest instead of Detox / Maestro
  • Using the deprecated react-test-renderer directly for new tests

✓ Tips & Best Practices

  • Start from the template's Jest config and add packages to the ignore pattern as errors appear
  • Use jest-expo in Expo apps; it ships the common mocks
  • Keep business logic in plain TS modules so it's easy to test
