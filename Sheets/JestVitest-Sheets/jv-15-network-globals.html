Mocking Network, Globals & Env

MSW setupServer · http.get handlers · server.use overrides · vi.stubGlobal('fetch') · vi.stubEnv · unstubAll

Fake the Network, Not Your Code

MSW (Mock Service Worker) intercepts real HTTP requests made with fetch, axios or anything else and answers from handlers you write. Your code runs unchanged, which makes it the most realistic way to test API calls. For quick cases, vi.stubGlobal replaces a global like fetch, and vi.stubEnv sets import.meta.env / process.env values.

Notes

  • npm i -D msw (v2 API: http, HttpResponse)
  • Start the server in a setup file so every test file gets it
  • onUnhandledRequest: "error" fails tests that hit an unmocked URL
  • unstubGlobals / unstubEnvs config options undo stubs after each test

MSW Setup and Overrides

// src/test/server.ts
import { setupServer } from 'msw/node'
import { http, HttpResponse } from 'msw'

export const server = setupServer(
  http.get('/api/users/:id', ({ params }) =>
    HttpResponse.json({ id: Number(params.id), name: 'Ann' })),
  http.post('/api/orders', async ({ request }) =>
    HttpResponse.json({ id: 'o1', ...(await request.json()) }, { status: 201 })),
)

// vitest.setup.ts
beforeAll(() => server.listen({ onUnhandledRequest: 'error' }))
afterEach(() => server.resetHandlers())
afterAll(() => server.close())

// a test
test('shows an error when the API fails', async () => {
  server.use(http.get('/api/users/:id', () => new HttpResponse(null, { status: 500 })))
  await expect(loadUser(1)).rejects.toThrow('500')
})

test('reads the API URL', () => {
  vi.stubEnv('VITE_API_URL', 'http://test')
  vi.stubGlobal('fetch', vi.fn().mockResolvedValue(new Response('{}')))
  // …
})

Code Explained

Handlers match method and path, with :id params like a router
server.use adds an override for one test; resetHandlers removes it afterwards
onUnhandledRequest: "error" catches calls you forgot to mock
vi.stubEnv works for import.meta.env in Vite projects

Jest ↔ Vitest

  • MSW is runner-agnostic: the same server works in Jest
  • Jest has no stubGlobal / stubEnv; assign global.fetch = jest.fn() and restore it yourself

TypeScript

  • Type responses: http.get<{ id: string }, never, User>(…)
  • Share response types with the app so handlers break when the API type changes

Prefer / Avoid

  • mocking axios / fetch modules → MSW handlers
  • one handler per test file → shared default handlers + server.use overrides
  • tests calling real staging APIs → MSW in unit tests, real APIs only in E2E

MSW Lifecycle

CallWhen

Stubs

CallDoes
vi.stubGlobal(name, value)Replace a global

vi.unstubAllEnvs()Undo
unstubGlobals / unstubEnvs: trueAuto-undo in config

⚠ Common Mistakes

  • Forgetting resetHandlers, so one test's override leaks into the next
  • Relative URLs in Node without a base URL configured
  • Leaving onUnhandledRequest at "warn" and missing a real network call

✓ Tips & Best Practices

  • Keep default handlers next to API types; override per test only the error paths
  • Reuse the same MSW handlers in Storybook and the browser
  • Turn on unstubEnvs: true so env stubs never leak

Quick Summary

  • MSW — intercept real requests
  • server.use — per-test overrides
  • vi.stubGlobal — replace a global
  • vi.stubEnv — env values
