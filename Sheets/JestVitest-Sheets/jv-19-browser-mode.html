Sheet 19

Vitest Browser Mode

browser.enabled · Playwright provider · page locators · expect.element · visual regression · when to use Playwright Test instead

Component Tests in a Real Browser

Browser mode runs Vitest tests inside a real browser (Chromium, Firefox, WebKit) driven by Playwright, so layout, CSS, focus and real events work. Tests use the same describe / it API, with page locators and expect.element, which retries until the element matches. It sits between jsdom unit tests and full end-to-end tests in Playwright.

Notes

  • Install: npm i -D @vitest/browser-playwright and run npx playwright install chromium
  • Render components with vitest-browser-react (or -vue, -svelte)
  • headless: true for CI
  • Visual regression: toMatchScreenshot() compares images

Under the Hood

  • Vitest serves test files through Vite and opens them in a browser controlled by the provider (Playwright)
  • The test code runs in the page; page commands go back to the Node side over a connection
  • Real layout and events come from the browser, so no DOM stubs are needed

Config and a Test

// vitest.config.ts
import { defineConfig } from 'vitest/config'
import { playwright } from '@vitest/browser-playwright'

export default defineConfig({
  test: {
    browser: {
      enabled: true,
      provider: playwright(),
      headless: true,
      instances: [{ browser: 'chromium' }],
    },
  },
})

// Menu.browser.test.tsx
import { render } from 'vitest-browser-react'
import { page } from 'vitest/browser'

test('opens the menu and focuses the first item', async () => {
  render(<Menu items={['New', 'Open']} />)
  await page.getByRole('button', { name: 'Menu' }).click()
  await expect.element(page.getByRole('menuitem', { name: 'New' })).toHaveFocus()
  await expect(page.getByRole('menu')).toMatchScreenshot()
})

Code Explained

instances lists browsers; add firefox or webkit to test more than one
page locators work like Playwright's (getByRole, getByText)
expect.element retries, so no manual waits are needed
Screenshot baselines are stored per browser and OS

Jest ↔ Vitest

  • Jest has no browser mode; it runs only in jsdom / Node
  • Closest Jest option is jest-puppeteer or moving the test to Playwright

TypeScript

  • Add "types": ["vitest/browser"] for typed page APIs
  • TSX component tests run directly through Vite

Prefer / Avoid

  • jsdom stubs for layout-heavy components → browser mode
  • full user journeys in browser mode → Playwright Test (Playwright set)
  • screenshots of whole pages → small, stable component screenshots

⚠ Common Mistakes

  • Running browser mode in CI without installing browsers (npx playwright install --with-deps)
  • Using browser mode for everything and making the suite slow
  • Screenshot baselines made on macOS and compared on Linux CI

✓ Tips & Best Practices

  • Run browser-mode tests as a separate project (sheet 21)
  • Generate screenshot baselines in the same Docker image CI uses
  • Reuse Playwright locator skills from the Playwright set

Quick Summary

  • browser mode — real browser via Playwright
  • page locators + expect.element
  • toMatchScreenshot — visual checks
  • full journeys → Playwright Test
