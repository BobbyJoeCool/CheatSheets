Sheet 24

Migrating Jest → Vitest

jest.* → vi.* · globals: true · done callbacks · mock factory differences · snapshot header · config mapping

Mostly Find-and-Replace

Vitest's API was designed to match Jest, so most suites move with a few mechanical changes: swap jest. for vi., turn on globals (or add imports), and translate the config. The real work is in the differences: module mock factories, done callbacks, mockReset behavior, and anything that relied on Jest's module registry.

Notes

  • Migrate one folder at a time; both runners can live side by side
  • Codemods exist (e.g. vitest-codemod); review the diff
  • Snapshots regenerate on first run (-u)
  • Run both suites in CI until the switch is done

Before and After

// Jest                                   // Vitest
jest.fn()                                  vi.fn()
jest.spyOn(obj, 'm')                       vi.spyOn(obj, 'm')
jest.mock('./api')                         vi.mock('./api')
jest.requireActual('./api')                await vi.importActual('./api')
jest.useFakeTimers()                       vi.useFakeTimers()
jest.setTimeout(10_000)                    vi.setConfig({ testTimeout: 10_000 })

// Factories: Vitest needs every export the code uses, incl. default
jest.mock('./mailer', () => ({ send: jest.fn() }))
vi.mock('./mailer', () => ({ default: { send: vi.fn() }, send: vi.fn() }))

// done callbacks → promises
it('emits', (done) => { bus.on('x', () => done()) })            // Jest
it('emits', () => new Promise<void>((resolve) => bus.on('x', resolve)))

// config
// jest.config: testEnvironment, setupFilesAfterEnv, moduleNameMapper
// vitest:      environment,     setupFiles,         resolve.alias (from vite.config)

Code Explained

globals: true lets old tests run without adding imports
Jest auto-fills a default export from CommonJS modules; Vitest needs an explicit default key
done callbacks become a returned promise
importActual is async in Vitest because ESM imports are async

Jest ↔ Vitest

  • mockReset: Jest leaves an empty function; Vitest 3+ restores the original implementation
  • Jest's jest.isolateModules → vi.resetModules() + dynamic import
  • @testing-library/jest-dom → import @testing-library/jest-dom/vitest

TypeScript

  • Swap @types/jest for "types": ["vitest/globals"] in tsconfig
  • Remove ts-jest / @swc/jest; Vite handles TS

Prefer / Avoid

  • big-bang migration → folder by folder with both runners
  • blindly accepting codemod output → review mock factories by hand
  • keeping @types/jest → remove it to avoid conflicting globals

⚠ Common Mistakes

  • Leaving @types/jest installed, causing type conflicts with Vitest globals
  • Forgetting the default key in mock factories
  • Expecting vi.importActual to be synchronous

✓ Tips & Best Practices

  • Turn on globals: true first, then remove it later by adding imports
  • Run the old and new suites side by side for a week
  • Delete Jest config, transformers and types once the switch is done

Quick Summary

  • jest. → vi.
  • globals: true — run old tests as-is
  • factories need default + used exports
  • done → promises
