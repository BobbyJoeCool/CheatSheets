Sheet 03

Config Levels, Aliases & Help

--system / --global / --local · config --list --show-origin · includeIf · alias · ! shell aliases · git help · -- separator · -C

Where Settings Live

Git reads config from three levels and the most specific one wins: system, then global (your user), then local (this repo). Aliases are config entries too, so you can shorten long commands. When you forget an option, git help and -h work offline. A few CLI conventions, like -- and -C, apply to almost every command.

Notes

  • Local beats global beats system for the same key
  • --show-origin tells you which file set a value
  • Git 2.46+ adds subcommands: git config get, set, list
  • -c key=value overrides config for a single command

Config, Aliases, Help

git config --list --show-origin           # every value + the file it came from
git config --local user.email "me@work.com"  # this repo only
git config --global --unset pull.rebase   # remove a setting

# ~/.gitconfig: use a work identity for repos under ~/work/
[includeIf "gitdir:~/work/"]
    path = ~/.gitconfig-work

git config --global alias.st "status -sb"
git config --global alias.lg "log --oneline --graph --all --decorate"
git config --global alias.undo "reset --soft HEAD~1"
git config --global alias.amend '!git add -A && git commit --amend --no-edit'

git help rebase        # full manual page
git commit -h          # short option summary
git -C ~/code/app status   # run as if inside that folder

Code Explained

--show-origin — prints file:~/.gitconfig next to each value
includeIf "gitdir:…" — loads another file for matching repos
alias.st — now git st runs git status -sb
! — alias runs a shell command, so you can chain several
git help — the man page; -h — a quick usage summary
-C <path> — run Git in another directory

⚠ Common Mistakes

  • Expecting --global to override a repo's --local value. Local always wins
  • Forgetting the ! on a shell alias. Without it Git treats the text as a git subcommand
  • Branch and file with the same name: git checkout main is ambiguous. Use --
  • A missing trailing / in gitdir:~/work/. Without it the pattern won't match subfolders

✓ Tips & Best Practices

  • Keep aliases readable: git config --get-regexp ^alias lists them
  • Use git -c core.pager=cat log for a one-off setting
  • Read git help revisions once. It explains HEAD~, @{u}, and ranges

Quick Summary

  • --show-origin — find where a value is set
  • includeIf — per-folder identities
  • alias.x — shortcuts; ! for shell
  • -- — separate revisions from paths
