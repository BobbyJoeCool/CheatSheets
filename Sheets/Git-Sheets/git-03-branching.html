Branching

branch · checkout · switch · merge · rebase · HEAD · detached HEAD

Branches & HEAD

A branch in Git is simply a lightweight movable pointer to a commit. Creating one costs almost nothing — it is a 41-byte file. HEAD is a special pointer that tells Git which branch you are currently on; when you commit, HEAD's branch moves forward automatically. git switch (Git 2.23+) is the modern replacement for git checkout when changing branches. Detached HEAD occurs when HEAD points directly at a commit instead of a branch name — commits made here are not on any branch and can be lost.

Key Facts

  • main / master — default branch name (just a convention)
  • Branches are local until pushed to a remote
  • HEAD~1 — parent of HEAD; HEAD~3 — three commits back
  • HEAD^ — first parent; HEAD^2 — second parent (merge commits)
  • Fast-forward merge: no new commit, pointer just moves
  • Three-way merge: creates a new merge commit with two parents

Notes

switch -c — replaces the older checkout -b; prefer switch for branch operations
--no-ff — "no fast-forward"; always creates a merge commit, making the branch visible in history
--squash — combines all branch commits into one staged change; you still run git commit manually
Conflict markers — <<<<<<< / ======= / >>>>>>> — must be removed before staging
--detach — safe way to inspect old commits without accidentally committing on a real branch
--graph --all — shows every branch in the log, not just the currently checked-out one

Branch & Merge Workflow

# ── Create and work on a feature branch ──────────────────────
git switch -c feature/login    # create + switch
git add auth.js
git commit -m "Add login form"
git add session.js
git commit -m "Add session handling"

# ── View branch topology ──────────────────────────────────────
git log --oneline --graph --all
# * a1b2c3d (feature/login) Add session handling
# * d4e5f6a Add login form
# * 9f8e7d6 (HEAD -> main) Initial commit

# ── Merge back into main ──────────────────────────────────────
git switch main
git merge feature/login    # fast-forward if no main commits since branch

# ── Merge with a commit (preserves branch in history) ─────────
git merge --no-ff feature/login -m "Merge feature/login"

# ── Handle a merge conflict ───────────────────────────────────
git merge feature/login        # CONFLICT in auth.js
# 1. Open auth.js, resolve conflict markers:
#    <<<<<<< HEAD
#    your version
#    =======
#    their version
#    >>>>>>> feature/login
git add auth.js                # mark resolved
git commit                     # complete the merge

# ── Detached HEAD: check out a commit directly ────────────────
git switch --detach HEAD~3     # look at older state safely
git switch main                # return to branch (detached commits lost)

Branch Commands

Command Description
git branch List local branches; current branch is starred
git branch -a List local and remote-tracking branches
git branch feature Create a branch at the current commit
git switch feature Switch to the feature branch (updates working tree)
git switch -c feature Create and switch in one step
git branch -d feature Delete a merged branch (safe — refuses if unmerged)
git branch -D feature Force-delete even if unmerged
git branch -m old new Rename a branch

Merge Commands

Command Description
git merge feature Merge feature into the current branch
git merge --no-ff feature Always create a merge commit even if fast-forward is possible
git merge --squash feature Squash all feature commits into one staged change
git merge --abort Abort a conflicted merge and restore pre-merge state
git diff --merge-base Show changes since the branch diverged
git log --merges Show only merge commits in history

Common Mistakes

  • Committing in detached HEAD state — those commits have no branch reference and will be garbage-collected; always run git switch -c new-branch before committing
  • Forgetting to switch back to main before merging — you merge into whatever branch you are currently on
  • Using git branch -D without verifying the branch is merged — run git log main..feature first to confirm no commits would be lost

Tips

  • Use descriptive branch names with a prefix: feature/, fix/, chore/ — they sort nicely and convey intent at a glance
  • Keep feature branches short-lived; the longer a branch diverges, the harder the eventual merge becomes
  • Run git log --oneline --graph --all (or your lg alias) after every merge to confirm the topology looks correct

Summary

  • git switch -c — create and switch to a new branch
  • git merge — integrate a branch into the current branch
  • --no-ff — preserve branch structure in history
  • HEAD — pointer to the current branch (or commit in detached mode)
  • Resolve conflicts by editing files, then git add + git commit
