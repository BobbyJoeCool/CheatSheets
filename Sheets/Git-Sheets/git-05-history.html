Sheet 05

Inspecting History

log · diff · show · blame · bisect · shortlog · grep

Reading the Repository's Past

Git stores every snapshot forever, making history fully inspectable. git log walks the commit graph; git diff compares any two states; git blame annotates every line of a file with the commit that last changed it; git bisect performs a binary search across commits to find the exact commit that introduced a bug. All of these are read-only — nothing inspected here changes the repository. Combine --oneline, --graph, and --all flags to get a compact visual map of any project's history.

Revision Syntax

  • HEAD — current commit
  • HEAD~3 — 3 commits before HEAD
  • abc1234 — commit by partial hash (min 4 chars)
  • main@{2} — where main pointed 2 moves ago
  • HEAD..feature — commits in feature not in HEAD
  • HEAD...feature — commits in either, not both (symmetric difference)

blame, bisect & shortlog

# ── Annotate who changed each line ───────────────────────────
git blame auth.js              # full annotation
git blame -L 40,60 auth.js    # only lines 40–60
git blame -w auth.js           # ignore whitespace-only changes

# ── Find which commit introduced a bug ────────────────────────
git bisect start
git bisect bad                 # current commit has the bug
git bisect good v1.2.0         # this tag was known-good
# Git checks out a commit halfway between — test it, then:
git bisect bad                 # still broken
git bisect good                # fixed here
# Git narrows in ~log₂(N) steps and prints the culprit commit
git bisect reset               # return to HEAD when done

# ── Automate bisect with a test script ────────────────────────
git bisect run npm test        # exits 0 = good, non-zero = bad

# ── Contribution summary ──────────────────────────────────────
git shortlog -sn               # commit count per author, sorted
git shortlog -sn --since="2024-01-01"

# ── Search commit content (not just messages) ─────────────────
git log -S "secretToken"       # commits that added/removed string
git log -G "regex.*pattern"    # commits where diff matches regex
git grep "TODO" HEAD           # grep working tree at HEAD

Notes

git blame -L — line range limits annotation to the most relevant section; combine with -w to skip pure whitespace commits
git bisect run — fully automated; test script must exit 0 for "good" and any non-zero for "bad"; bisects log₂(N) commits automatically
-S "string" — the "pickaxe" flag; finds commits where the string count changed (i.e. was added or removed)
-G "regex" — finds commits where the diff text matches the regex, including line rearrangements
git shortlog -sn — the -s suppresses commit messages, -n sorts by count descending
--diff-filter=D — filter log to only commits that deleted files; also: A (added), M (modified), R (renamed)

Common Mistakes

  • Running git diff expecting to see staged changes — use git diff --staged for that; bare git diff shows only unstaged changes
  • Forgetting git bisect reset after a session — leaves you in detached HEAD state on the culprit commit
  • Using git log --grep to search code content — --grep searches commit messages only; use -S or -G to search diffs

Tips

  • Combine flags: git log --oneline --graph --all --decorate gives the most useful single-screen history view — save it as an alias
  • Use git log -- path/to/file to track a file's history even across renames by adding --follow
  • git bisect run with a test script is dramatically faster than manual bisect for large repos — write the test first

Summary

  • git log --oneline --graph --all — compact visual history
  • git diff --staged — what will be in the next commit
  • git blame -L — per-line authorship for a file range
  • git bisect — binary search to find a bug-introducing commit
  • -S "string" — find commits that added or removed a string
