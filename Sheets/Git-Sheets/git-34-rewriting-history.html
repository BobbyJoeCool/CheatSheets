Sheet 34

Rewriting History & Removing Secrets

git filter-repo · --path / --invert-paths · --replace-text · BFG · force-push afterward · rotate leaked secrets · filter-branch (deprecated)

Purging Files from Every Commit

When a secret or huge file was committed, deleting it in a new commit isn't enough: it's still in history. git filter-repo rewrites every commit to remove paths or replace text, producing new hashes for the whole history. Afterward everyone must re-clone. Most importantly, a leaked secret must be rotated first, because it may already have been copied.

Notes

  • filter-repo is a separate install: pip install git-filter-repo
  • It refuses to run on a non-fresh clone without --force
  • It removes the origin remote as a safety measure
  • git filter-branch is deprecated: slow and error-prone

filter-repo and BFG

# 0. Rotate the leaked key/password FIRST
git clone --mirror git@github.com:org/app.git && cd app.git   # fresh copy

git filter-repo --path secrets.env --invert-paths   # delete a file everywhere
git filter-repo --path-glob "*.mp4" --invert-paths  # delete by pattern
git filter-repo --strip-blobs-bigger-than 50M       # drop huge blobs
git filter-repo --replace-text ../replacements.txt  # scrub strings
# replacements.txt:   sk_live_abc123==>***REMOVED***
git filter-repo --path src/ --path-rename src/:lib/ # keep only src/, rename it

git remote add origin git@github.com:org/app.git
git push --force --mirror origin                    # rewrite the server

# BFG alternative (Java)
bfg --delete-files id_rsa
bfg --replace-text passwords.txt
git reflog expire --expire=now --all && git gc --prune=now --aggressive

Code Explained

--mirror — bare clone with every ref, ideal for rewriting
--path X --invert-paths — keep everything except X
--strip-blobs-bigger-than — remove large files by size
--replace-text — old==>new lines, regex: allowed
push --force --mirror — replaces all branches and tags
reflog expire + gc --prune=now — purge old objects locally (BFG)

Leaked Secret Checklist

StepAction
1revoke / rotate the secret
2rewrite history (filter-repo)
3force-push all branches + tags
4ask the host to purge cached views/PR refs
5everyone re-clones (don't merge old clones)
6add the file to .gitignore + secret scanning

⚠ Common Mistakes

  • Rewriting history but not rotating the secret. Forks, clones, and caches may still have it
  • Letting teammates pull into old clones. Merging old history brings the secret right back
  • Running filter-repo on your only copy. Work on a fresh mirror clone and keep a backup

✓ Tips & Best Practices

  • Turn on secret scanning / push protection on your host
  • Use .env.example with placeholders; ignore real .env files
  • Run git log --all -- secrets.env afterward to confirm it's gone

Quick Summary

  • rotate the secret first
  • filter-repo --invert-paths — remove files
  • --replace-text — scrub strings
  • force-push + everyone re-clones
