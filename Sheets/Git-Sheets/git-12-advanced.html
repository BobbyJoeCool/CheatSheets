Power Commands & Tips

worktree · submodule · sparse-checkout · filter-repo · aliases · bundle

Advanced Git Features

git worktree lets you check out multiple branches simultaneously in separate directories, all sharing one .git/ — ideal for reviewing a PR while keeping your current work intact. git submodule embeds one Git repo inside another at a fixed commit, tracking external dependencies as part of the parent repo. sparse-checkout checks out only a subset of a large monorepo's file tree, dramatically reducing disk use. git filter-repo (a third-party tool that replaced filter-branch) rewrites history at scale — removing secrets, splitting repos, or extracting subdirectories.

Key Facts

  • Worktrees share .git/ — no duplicate object store
  • Each worktree must be on a different branch
  • Submodule state is committed as a special gitlink entry in the parent tree
  • git submodule update --init --recursive — required after cloning a repo with submodules
  • filter-repo must be installed separately: pip install git-filter-repo
  • git bundle packages a repo for offline transfer

Worktree & Submodule Commands

CommandDescription
git worktree add ../hotfix fix/crashCheck out fix/crash branch in a sibling directory
git worktree add -b review ../pr123 origin/pr123New branch from remote in a new worktree
git worktree listList all linked worktrees
git worktree remove ../hotfixRemove a linked worktree
git submodule add <url> path/Embed a repo as a submodule at path/
git submodule update --init --recursiveInitialize and clone all submodules after cloning parent
git submodule foreach git pullRun a command in every submodule
git submodule deinit path/Remove submodule from working tree (keeps .gitmodules)

Sparse Checkout, Bundle & filter-repo

CommandDescription
git sparse-checkout init --coneEnable cone-mode sparse checkout (faster pattern matching)
git sparse-checkout set packages/uiCheck out only the packages/ui subtree
git sparse-checkout disableReturn to full checkout
git bundle create repo.bundle --allPack entire repo into a single transportable file
git clone repo.bundle my-cloneClone from a bundle file (works offline)
git filter-repo --path src/ --invert-pathsRemove the src/ directory from all history
git filter-repo --path src/Keep only src/ in history (extract a subdirectory)
git filter-repo --replace-text secrets.txtReplace strings matching patterns across all blobs

Worktree, sparse-checkout & filter-repo

# ── Review a PR without losing your current work ──────────────
git fetch origin
git worktree add -b review/pr-42 ../pr-42-review origin/feature/pr-42
cd ../pr-42-review          # full checkout on the PR branch
# review, run tests, leave notes
cd ../my-main-project       # back to your original work, untouched
git worktree remove ../pr-42-review

# ── Work with a monorepo: only check out one package ──────────
git clone --no-checkout git@github.com:org/monorepo.git
cd monorepo
git sparse-checkout init --cone
git sparse-checkout set packages/ui packages/shared
git checkout main           # only packages/ui + packages/shared downloaded

# ── Remove an accidentally committed secret from all history ──
# BACKUP FIRST: git clone --mirror origin backup-repo
pip install git-filter-repo
# Create replacements file:
echo "my_secret_token==>REDACTED" > secrets.txt
git filter-repo --replace-text secrets.txt
# Force push all refs (coordinate with team first):
git push origin --force --all
git push origin --force --tags

# ── Bundle a repo for offline transfer ───────────────────────
git bundle create /media/usb/project.bundle --all
# On another machine:
git clone /media/usb/project.bundle project
cd project
git remote set-url origin git@github.com:org/project.git

Notes

worktree add — creates a directory linked to the same .git/; you cannot check out the same branch in two worktrees simultaneously
sparse-checkout --cone — cone mode uses directory prefixes, much faster than the older pattern-matching mode for large repos
filter-repo — always work on a fresh clone with --mirror; the tool refuses to run on repos with uncommitted changes
--replace-text — takes a file of old==>new lines; use regex with regex:pattern==>replacement syntax
git bundle — the bundle file is a valid Git remote; you can fetch individual refs from it without a full clone
After filter-repo, all collaborators must re-clone — the rewritten history is incompatible with existing local clones

Common Mistakes

  • Running git filter-repo without first backing up the repo — history rewriting is irreversible; always work from a --mirror clone
  • Cloning a submodule repo without --recursive — submodule directories exist but are empty; run git submodule update --init --recursive to populate them
  • Trying to check out the same branch in two worktrees — Git prevents this; create a new branch in the second worktree with -b

Tips

  • Use git worktree instead of stashing when switching contexts — full working tree isolation means no risk of applying the wrong stash later
  • If a repo has a .gitmodules file, add git submodule update --init --recursive to your project's setup script so new contributors don't get caught by empty submodule dirs
  • Before using filter-repo to remove secrets, rotate all exposed credentials immediately — assume the secret is already compromised if it was ever pushed

Summary

  • git worktree add — multiple branches checked out simultaneously
  • git submodule update --init --recursive — populate submodules after clone
  • sparse-checkout --cone — partial monorepo checkout by directory
  • git filter-repo — rewrite history to remove files or secrets
  • git bundle — portable offline repo transport format
