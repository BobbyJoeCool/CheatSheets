Stash & Tags

Stash is a temporary shelf for uncommitted changes. It saves your working tree and index to a stack so you can switch context cleanly, then restore the changes later. Each stash entry is identified as stash@{0} (most recent), stash@{1}, etc. Tags mark specific commits permanently — typically release points. A lightweight tag is just a named pointer to a commit. An annotated tag is a full Git object with a tagger, date, message, and optional GPG signature; prefer annotated for releases because they carry metadata and can be signed.

Key Facts

  • Stash is a stack — stash@{0} is always the most recent entry
  • git stash pop = apply + drop; git stash apply keeps the stash entry
  • Untracked and ignored files are not stashed by default
  • Tags are not pushed with git push — must use git push --tags or git push origin v1.0
  • Annotated tags store tagger, timestamp, and message
  • Use git describe to get the nearest tag relative to a commit

Stash Commands

CommandDescription
git stashStash working tree + index changes
git stash push -m "msg"Stash with a descriptive message
git stash -uAlso stash untracked files
git stash -aStash everything including ignored files
git stash listShow all stash entries
git stash show stash@{1}Show summary of a specific stash entry
git stash applyRestore most recent stash, keep entry on stack
git stash popRestore and remove most recent stash entry
git stash drop stash@{1}Delete a specific stash entry
git stash clearDelete all stash entries
git stash branch fix/hotfixCreate a branch from stash and apply it there

Tag Commands

CommandDescription
git tagList all local tags

git tag -a v1.0.0 abc1234Tag a specific past commit

git tag -d v1.0.0Delete a local tag

git describe --tagsDescribe HEAD relative to nearest tag

Stash & Tag in Practice

# ── Interrupt work to fix a hotfix ────────────────────────────
git stash push -m "WIP: login redesign"
git switch main
git switch -c fix/crash
# ... make fix ...
git commit -m "Fix null pointer in session"
git switch main
git merge fix/crash

# ── Return to your feature ────────────────────────────────────
git switch feature/login
git stash list
# stash@{0}: On feature/login: WIP: login redesign
git stash pop              # restores and removes entry

# ── Stash only specific files ─────────────────────────────────
git stash push -m "auth only" -- auth.js session.js

# ── Apply a stash to a different branch ───────────────────────
git stash branch experiment stash@{0}
# creates branch, checks it out, applies and drops the stash

# ── Tag a release ─────────────────────────────────────────────
git switch main
git tag -a v2.1.0 -m "Release 2.1.0: OAuth support"
git push origin v2.1.0

# ── Tag an older commit ──────────────────────────────────────
git log --oneline
# abc1234 Merge feature/oauth
git tag -a v2.0.0 abc1234 -m "Release 2.0.0"
git push origin v2.0.0

# ── Describe current state relative to a tag ─────────────────
git describe --tags
# v2.1.0-4-gabc1234  → 4 commits after v2.1.0, at abc1234

Notes

stash push -- files — partial stash of specific files only; the rest remain in the working tree
stash branch — the safest way to apply a stash that may conflict with current work; starts fresh on a new branch
-u flag — includes untracked files; always use when switching branches with new files not yet added
-a annotated tag — stores a full object in Git's database; can be GPG-signed with -s instead of -a
git describe output — format is tag-N-gHASH: tag name, commits since tag, abbreviated hash
Tags are permanent references — deleting a pushed tag should be coordinated with teammates who may have fetched it

Common Mistakes

  • Using git stash without -u when you have new untracked files — those files are not stashed and may cause conflicts when you pop later
  • Forgetting to push tags after a release — tags exist only locally until explicitly pushed; teammates and CI systems won't see them
  • Accumulating stash entries without names — after a week stash@{3} is meaningless; always use git stash push -m "description"

Tips

  • Treat stash as a short-term buffer, not long-term storage — work-in-progress branches (git switch -c wip/feature) are safer for multi-day interruptions
  • Use annotated tags (-a) for every release, not lightweight tags — they carry authorship and a message, and are required for tools like git describe to work well
  • Use git stash show -p stash@{0} to review a stash as a full diff before applying it

Summary

  • git stash push -m — shelve work-in-progress with a label
  • git stash pop — restore and remove the top stash entry
  • -u — include untracked files in the stash
  • git tag -a — annotated tag with message and metadata
  • git push origin --tags — tags must be pushed separately
