Sheet 07

Committing

git commit -m · -a · -v · --amend · --no-edit · multi-line messages · Conventional Commits · --allow-empty

Recording Snapshots

A commit saves the staged snapshot with a message, author, timestamp, and a link to its parent. Good commits are small and focused, and good messages explain why, not just what. --amend replaces the last commit, which is handy for typos but rewrites history, so only amend commits you haven't pushed.

Notes

  • Commits are immutable; amend creates a new commit with a new hash
  • Message convention: 50-char subject, blank line, body wrapped at 72
  • Write the subject in the imperative: "Fix login bug"
  • -a skips staging for tracked files only

Commit Variants

git commit                        # opens the editor for the message
git commit -m "Add login form"    # message inline
git commit -m "Fix crash" -m "Null user caused a crash on logout."
git commit -am "Update styles"    # stage tracked changes + commit
git commit -v                     # show the diff in the editor

git commit --amend                # edit the last message (and add staged changes)
git commit --amend --no-edit      # add staged changes, keep the message
git commit --amend --reset-author # fix author after changing user.email
git commit --allow-empty -m "Trigger CI"
git commit --fixup=a1b2c3d        # mark as a fix for an older commit (Sheet 19)

git commit -S -m "Signed"         # sign the commit (Sheet 23)

Code Explained

-m twice — first is the subject, second is the body
-a — auto-stages modified and deleted tracked files
-v — includes the diff below the message template
--amend --no-edit — fold forgotten changes into the last commit
--allow-empty — a commit with no changes
--fixup — creates a fixup! … commit for rebase --autosquash

Conventional Commits

PrefixUse for
feat:a new feature
fix:a bug fix
docs:documentation only
refactor:code change, no behavior change
test:adding or fixing tests
chore:build, deps, tooling
feat!:breaking change

Message Anatomy

PartGuideline
Subject≤ 50 chars, imperative, no period
Blank linerequired between subject and body
Bodywhy the change was needed; wrap at 72
TrailerCo-authored-by: Name <email>
TrailerFixes #123 closes the issue

⚠ Common Mistakes

  • Amending a commit you've already pushed. Others now have a different history; you'll need a force push
  • Giant "WIP" commits. They make revert, bisect, and review much harder
  • Messages like "fix" or "update". Future you can't tell what changed or why

✓ Tips & Best Practices

  • Commit early and often locally; tidy up with interactive rebase before pushing
  • Use git commit -v to re-read your diff while writing the message
  • Add Co-authored-by: trailers when pairing

Quick Summary

  • commit -m — commit staged changes
  • commit --amend — replace the last commit
  • --no-edit — keep the message
  • --fixup — prepare an autosquash fix
