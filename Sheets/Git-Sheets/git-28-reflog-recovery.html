Reflog & Recovery

git reflog · HEAD@{3} · restore a deleted branch · undo a bad reset · branch <name> <sha> · git fsck --lost-found · reflog expiry

Git's Safety Net

The reflog records every position HEAD and each branch has had in *your* clone: commits, resets, rebases, checkouts. If a commit was ever committed, it is almost always recoverable: find it in the reflog and put a branch on it. Only uncommitted changes and very old unreachable objects are truly lost.

Notes

  • The reflog is local only; it isn't pushed or cloned
  • Reachable entries expire after 90 days, unreachable after 30
  • Deleting a branch prints its last hash: (was a1b2c3d)
  • Dropped stashes can be found with git fsck

Finding and Restoring Lost Commits

git reflog                       # HEAD history, newest first
# a1b2c3d HEAD@{0}: reset: moving to HEAD~3
# f6a7b8c HEAD@{1}: commit: Add search tests
git reflog show feature          # one branch's history
git log -g --oneline             # reflog in log format

git reset --hard HEAD@{1}        # undo the reset above
git branch rescue f6a7b8c        # put a branch on a lost commit
git switch -c rescue HEAD@{5}    # or create + switch

git branch -D feature            # Deleted branch feature (was 9e8d7c6).
git branch feature 9e8d7c6       # brought back

git fsck --lost-found            # dangling commits/blobs (e.g. dropped stash)
git show <dangling-sha>          # inspect before restoring
git stash apply <dangling-sha>   # re-apply a dropped stash

Code Explained

HEAD@{n} — where HEAD was n moves ago
reflog show <branch> — that branch's own movements
log -g — walks the reflog with normal log formatting
branch <name> <sha> — makes a lost commit reachable again
fsck --lost-found — finds objects no ref or reflog points to
stash apply <sha> — works on a dropped stash commit

⚠ Common Mistakes

  • Running git gc --prune=now while trying to recover. It can delete the objects you need
  • Expecting the reflog on a new clone or a teammate's machine. It's per-clone history
  • Panicking after a bad reset and running more commands. Stop, read git reflog, then act

✓ Tips & Best Practices

  • Before risky operations, drop a bookmark: git branch backup
  • Use git reflog --date=relative to find "before lunch" states
  • ORIG_HEAD is the fastest undo for the last reset/merge/rebase

Quick Summary

  • git reflog — every HEAD move
  • HEAD@{n} — reference an old state
  • branch <name> <sha> — rescue
  • fsck --lost-found — last resort
