Sheet 18

Rebasing

git rebase main · --continue / --skip / --abort · --onto · --update-refs · rebase.autoStash · don't rebase shared branches

Replaying Commits

git rebase takes your branch's commits and replays them on top of another base, producing a straight, linear history. The replayed commits are new commits with new hashes, which is why the golden rule is: never rebase commits other people already have. Rebasing your own unpushed or personal feature branch onto main is normal and safe.

Notes

  • Conflicts are resolved commit by commit
  • git pull --rebase = fetch + rebase onto upstream
  • After rebasing a pushed branch, push with --force-with-lease
  • ORIG_HEAD holds where you were before the rebase

Rebase Variants

git switch feature
git rebase main                   # replay feature's commits onto main
git rebase origin/main            # onto the freshly fetched remote main
git pull --rebase                 # fetch + rebase onto upstream

# during a conflict
git add app.js && git rebase --continue
git rebase --skip                 # drop the commit that conflicts
git rebase --abort                # return to the pre-rebase state

git rebase --onto main old-base feature   # move commits after old-base onto main
git rebase --update-refs main     # also move stacked branches in the range
git rebase -r main                # keep merge commits (--rebase-merges)

git config --global pull.rebase true
git config --global rebase.autoStash true   # stash/unstash around rebases
git reset --hard ORIG_HEAD        # undo the last rebase

Code Explained

rebase main — base becomes main's tip; commits replayed in order
--continue — after resolving and staging the conflict
--skip — discards the current commit entirely
--onto A B C — take commits in B..C and put them on A
--update-refs — keeps stacked branches pointing at rewritten commits
autoStash — lets you rebase with a dirty working tree

⚠ Common Mistakes

  • Rebasing main or any shared branch. Everyone else's history now disagrees with yours
  • Plain git push --force after a rebase. It can overwrite a teammate's push; use --force-with-lease
  • Panicking mid-rebase. git status says which commit you're on; --abort always gets you back

✓ Tips & Best Practices

  • Rebase onto origin/main right after git fetch to stay current
  • Compare before and after a rebase with git range-diff ORIG_HEAD...HEAD
  • Enable rerere so repeated rebases reuse conflict fixes

Quick Summary

  • rebase main — replay onto main
  • --continue / --skip / --abort
  • --onto — transplant a range
  • never rebase shared history
