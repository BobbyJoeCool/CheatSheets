Marking Releases

A tag is a fixed name for a commit, usually a release like v1.2.0. Annotated tags are full objects with a tagger, date, and message (and optionally a signature), and they are what releases should use. Lightweight tags are just a name pointing at a commit. Tags are not pushed by default, so push them explicitly.

Notes

  • Tags don't move when new commits arrive (unlike branches)
  • Semantic versioning: vMAJOR.MINOR.PATCH
  • git describe and --follow-tags only see annotated tags by default
  • Checking out a tag gives detached HEAD

Creating, Listing, Sharing Tags

git tag v1.0.0                           # lightweight tag on HEAD
git tag -a v1.1.0 -m "Release 1.1.0"     # annotated tag on HEAD
git tag -a v1.0.1 a1b2c3d -m "Hotfix"    # tag an older commit
git tag -s v2.0.0 -m "Signed release"    # signed annotated tag

git tag                                  # list all tags
git tag -l "v1.*"                        # list matching a pattern
git tag --sort=-v:refname                # newest version first
git show v1.1.0                          # tag message + commit

git push origin v1.1.0                   # push one tag
git push --follow-tags                   # push commits + their annotated tags
git push origin --tags                   # push every tag (careful)
git fetch --tags                         # get all remote tags

git tag -d v1.0.0                        # delete locally
git push origin --delete refs/tags/v1.0.0   # delete on the remote

Code Explained

-a -m — annotated tag with a message
git tag <name> <sha> — tag any commit
-s — sign with your GPG/SSH key
--sort=-v:refname — version-aware sort, descending
--follow-tags — pushes annotated tags reachable from pushed commits
refs/tags/ prefix — avoids clashing with a branch of the same name

⚠ Common Mistakes

  • Expecting git push to send tags. Push them by name or with --follow-tags
  • Moving a published tag. Others keep the old one; create a new version instead
  • git push --tags with stray local tags. It publishes every experimental tag too

✓ Tips & Best Practices

  • Set git config --global push.followTags true
  • Create GitHub releases from tags: gh release create v1.1.0
  • Verify signed tags with git tag -v v2.0.0

Quick Summary

  • tag -a -m — annotated release tag
  • tag -l — list / filter
  • push --follow-tags — share tags
  • tag -d + push --delete — remove
