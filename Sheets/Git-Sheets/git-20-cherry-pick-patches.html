Sheet 20

Cherry-Pick & Patches

git cherry-pick <sha> · ranges A^..B · -x · -n · --continue / --abort · git format-patch · git am · git apply

Copying Individual Changes

git cherry-pick applies the change from one or more existing commits as new commits on your current branch, which is the usual way to backport a fix to a release branch. Patches do the same across repos or by email: format-patch exports commits as files, am applies them as commits, and apply applies a plain diff without committing.

Notes

  • Cherry-picked commits get new hashes
  • -x records the source hash in the message
  • Picking a merge commit needs -m 1 to choose the mainline
  • git apply works on any diff, including git diff output

Cherry-Pick and Patch Commands

git switch release/2.1
git cherry-pick a1b2c3d              # copy one commit
git cherry-pick a1b2c3d e5f6a7b      # several commits
git cherry-pick a1b2c3d^..f6a7b8c    # a range, inclusive of a1b2c3d
git cherry-pick -x a1b2c3d           # add "(cherry picked from commit …)"
git cherry-pick -n a1b2c3d           # apply changes, don't commit
git cherry-pick --continue           # after resolving a conflict
git cherry-pick --abort              # cancel the whole pick

git format-patch -3                  # last 3 commits -> 000N-*.patch files
git format-patch main..feature -o patches/
git am patches/*.patch               # apply patch files as commits
git am --abort                       # back out of a failed am

git diff > change.diff               # plain diff
git apply --check change.diff        # test if it applies cleanly
git apply change.diff                # apply to working tree (no commit)

Code Explained

A^..B — includes A; plain A..B would skip A
-x — traceable backports; use for public branches
-n — stage the change so you can combine or edit it
format-patch — one email-style file per commit, keeps author
am — "apply mailbox": recreates the commits
apply --check — dry run for a diff

⚠ Common Mistakes

  • Cherry-picking a whole feature commit by commit. Merge or rebase the branch instead
  • Writing A..B and missing commit A. Use A^..B to include it
  • Using git apply and expecting a commit. It only changes files; use am for commits

✓ Tips & Best Practices

  • Always use -x when picking onto a shared release branch
  • If the same fix is needed in many branches, commit it on the oldest and merge forward
  • git apply -3 falls back to a 3-way merge when context has drifted

Quick Summary

  • cherry-pick <sha> — copy a commit
  • -x — record the source
  • format-patch / am — commits as files
  • apply — apply a diff
