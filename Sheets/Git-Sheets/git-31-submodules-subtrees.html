Submodules & Subtrees

submodule add · update --init --recursive · .gitmodules · submodule foreach · git subtree add --prefix · subtree pull --squash

Repositories Inside Repositories

A submodule embeds another repo at a pinned commit: the parent stores only the URL (in .gitmodules) and a commit hash. That keeps histories separate but requires extra commands to clone and update. A subtree copies the other project's files into a folder of your repo, so clones just work, at the cost of a larger history.

Notes

  • A submodule is pinned to a commit, not a branch
  • Fresh clones have empty submodule folders until you init them
  • submodule.recurse true makes pull/switch update submodules
  • git subtree ships with most Git installs (contrib)

Submodule and Subtree Commands

git submodule add https://github.com/org/lib.git vendor/lib
git commit -m "Add lib submodule"           # commits .gitmodules + pointer

git clone --recurse-submodules <url>        # clone with submodules
git submodule update --init --recursive     # after a plain clone
git submodule update --remote --merge       # move to the latest upstream commit
git submodule status                        # pinned hash per submodule
git submodule foreach 'git pull'            # run a command in each
git config --global submodule.recurse true

git rm vendor/lib                           # remove a submodule (then commit)

git subtree add --prefix=vendor/lib https://github.com/org/lib.git main --squash
git subtree pull --prefix=vendor/lib https://github.com/org/lib.git main --squash
git subtree push --prefix=vendor/lib <url> my-fixes   # send changes upstream

Code Explained

submodule add — clones it and records URL + path
update --init --recursive — fills in nested submodules too
--remote — fetch the tracked branch instead of the pinned hash
foreach — runs a shell command in every submodule
subtree add --prefix — imports files into that folder
--squash — imports history as one commit

⚠ Common Mistakes

  • Committing inside a submodule without committing the new pointer in the parent. Others still get the old commit
  • Working in a submodule on detached HEAD. Switch to a branch before editing
  • Mixing --squash and non-squash subtree pulls. Pick one and stick with it

✓ Tips & Best Practices

  • Add --recurse-submodules to CI clone steps
  • Show submodule changes in status: git config status.submoduleSummary true
  • Consider your package manager before either; it's often simpler

Quick Summary

  • submodule add — pin another repo
  • update --init --recursive — populate
  • subtree add --prefix — vendor files
  • subtree pull — update vendored copy
