Large Repos & Big Files

clone --filter=blob:none · sparse-checkout set · fetch --unshallow · git lfs install / track · git maintenance start · scalar

Scaling Git

Git copies all history by default, which gets slow for huge monorepos or repos full of binaries. Partial clones skip file contents until needed, sparse checkout materializes only the folders you work in, and Git LFS stores large binaries outside the repo, leaving small pointer files behind. Background maintenance keeps big repos fast.

Notes

  • Partial clone keeps full history; shallow clone cuts it
  • Git LFS is a separate install: brew install git-lfs
  • GitHub warns at 50 MB and blocks files over 100 MB
  • scalar (bundled since 2.38) sets all of this up at once

Big-Repo Tools

git clone --filter=blob:none <url>        # blobs downloaded on demand
git clone --filter=tree:0 <url>           # even lighter (CI builds)
git clone --depth 1 <url>                 # shallow: latest commit only
git fetch --unshallow                     # convert shallow to full

git clone --sparse <url> && cd repo       # start with root files only
git sparse-checkout set apps/web libs/ui  # materialize just these folders
git sparse-checkout add docs              # add another folder
git sparse-checkout disable               # back to everything

git lfs install                           # once per machine
git lfs track "*.psd" "*.mp4"             # writes rules to .gitattributes
git add .gitattributes design.psd && git commit -m "Track PSDs in LFS"
git lfs ls-files                          # files stored in LFS
git lfs migrate import --include="*.zip"  # move existing files (rewrites history)

git maintenance start                     # scheduled background optimization

Code Explained

blob:none — commits + trees now, file contents lazily
--sparse + sparse-checkout set — only listed folders on disk
lfs track — adds filter=lfs lines to .gitattributes
lfs ls-files — confirms what LFS manages
lfs migrate import — moves history into LFS (force push needed)
maintenance start — registers prefetch, gc, commit-graph tasks

Measuring Size

⚠ Common Mistakes

  • Committing a large binary, then deleting it. It stays in history forever; rewrite with filter-repo (Sheet 34)
  • Running git lfs track without committing .gitattributes. Teammates add the files as normal blobs
  • Using --depth 1 for development work. Blame, log, and merges lose history

✓ Tips & Best Practices

  • Set up LFS before the first binary is committed
  • Use partial clone over shallow clone for day-to-day work
  • Add .gitattributes LFS rules in the very first commit of asset-heavy repos

Quick Summary

  • --filter=blob:none — partial clone
  • sparse-checkout set — some folders
  • git lfs track — big binaries
  • maintenance start — keep it fast
