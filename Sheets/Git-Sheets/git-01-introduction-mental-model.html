What Git Is

Git is a distributed version control system created by Linus Torvalds in 2005 for Linux kernel development. Every clone holds the full history, so almost every command runs locally and offline. Git stores snapshots, not diffs: each commit records the whole project tree, and unchanged files are shared between commits. Learn the three areas below and most commands become obvious.

Key Facts

  • Every object is named by a hash of its content: SHA-1 today, SHA-256 optional
  • HEAD points to the branch you are on, and that branch points to a commit
  • Branches are 40-byte files holding a hash, so they are nearly free to create
  • Git 3.0 (planned): main default branch, SHA-256 for new repos, reftable refs

Hello, Git — a first repository

mkdir demo && cd demo
git init                      # creates .git/ (the repository)
echo "# Demo" > README.md     # file exists only in the working tree
git status                    # README.md is "untracked"
git add README.md             # copy the snapshot into the staging area
git commit -m "Add README"    # store the staged snapshot as a commit
git log --oneline             # a1b2c3d (HEAD -> main) Add README

# Look inside the commit you just made
git cat-file -t HEAD          # commit
git cat-file -p HEAD          # tree <sha>, author, committer, message
git cat-file -p HEAD^{tree}   # 100644 blob <sha>  README.md

Code Explained

git init — creates the .git/ folder that holds every object and ref
git add — stages a snapshot of the file's current content
git commit — saves the staged snapshot with author, date, and message
git cat-file -t — prints an object's type
git cat-file -p — pretty-prints an object's content
HEAD^{tree} — the tree object of the current commit

The Three Areas

AreaWhat lives there
Working treeThe files you edit on disk
Staging areaThe index: the snapshot for your next commit
Repository.git/: commits, objects, refs
RemoteAnother copy of the repo, e.g. origin

Object Types

ObjectStores
blobFile content (no name, no mode)
treeA directory: names, modes, blob/tree hashes
commitTree hash, parents, author, message
tagAnnotated tag: target, tagger, message

File States

StateMeaning
untrackedNot in the last commit or index
modifiedChanged since the last commit
stagedChange recorded in the index
committedSafely stored in .git/

⚠ Common Mistakes

  • Thinking commits store diffs. They store full snapshots; diffs are computed on demand
  • Treating Git and GitHub as the same thing. Git is the tool; GitHub hosts repos
  • Deleting .git/ to start over. That throws away all history in that clone
  • Skipping git status. It tells you which area every change is in

✓ Tips & Best Practices

  • Run git status before and after every command while learning
  • Use git help <command> for the full manual page offline
  • Short hashes (7+ chars) work anywhere a full hash does
  • Visualize history with git log --oneline --graph --all

Quick Summary

  • working tree — files on disk you edit
  • index — staging area for the next commit
  • commit — snapshot + parents + message
  • HEAD — the current branch / commit
