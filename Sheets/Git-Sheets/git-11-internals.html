The Object Database

Git's storage model is a content-addressed object database in .git/objects/. Everything is stored as one of four object types, identified by a SHA-1 hash of their contents. A blob stores raw file contents. A tree stores a directory listing (names, modes, and blob/tree hashes). A commit stores a tree hash, parent commit hashes, metadata, and a message. A tag object stores a pointer to any object plus tagger info. Refs (.git/refs/) are human-readable names for hashes — branches, tags, and HEAD are all refs.

Object Types

  • blob — file contents (no filename, no metadata)
  • tree — directory: list of (mode, name, hash) entries
  • commit — tree + parent(s) + author + committer + message
  • tag — annotated tag object pointing to any object
  • Identical files across commits share one blob — no duplication
  • Packfiles compress and delta-encode objects for efficiency

Notes

cat-file -p HEAD — "porcelain" pretty-print; the commit object contains the tree hash, not file contents directly
ls-tree modes — 100644 = regular file, 100755 = executable, 040000 = directory (tree), 120000 = symlink
Content-addressing — two identical files in different locations store only one blob; Git detects this automatically
git fsck --lost-found — writes dangling blobs/commits to .git/lost-found/; useful after an accidental hard reset
git gc — runs automatically by Git periodically; safe to run manually; packs loose objects into packfiles
Packfiles (.git/objects/pack/) store delta-compressed chains of objects — a repository that is 1 GB of files may have a 50 MB packfile

Exploring the Object Store

# ── Inspect the latest commit object ─────────────────────────
git cat-file -p HEAD
# tree 4b825dc642cb6eb9a060e54bf8d69288fbee4904
# parent 9f8e7d6c5b4a3f2e1d0c9b8a7f6e5d4c3b2a1f0
# author Ada Lovelace  1704067200 +0000
# committer Ada Lovelace  1704067200 +0000
# Add OAuth login

# ── Inspect the tree that commit points to ────────────────────
git ls-tree HEAD
# 100644 blob a8c3f1d  README.md
# 100644 blob e7b2f4c  auth.js
# 040000 tree d9a1b3e  src/

# ── Read a blob directly ──────────────────────────────────────
git cat-file -p a8c3f1d   # prints contents of README.md at HEAD

# ── Resolve expressions to hashes ────────────────────────────
git rev-parse HEAD          # → full 40-char hash
git rev-parse HEAD~2        # → hash 2 commits ago
git rev-parse main          # → hash branch main points to
git rev-parse v1.0.0        # → hash of tag (lightweight: commit hash)

# ── Find dangling commits (orphans after reset) ───────────────
git fsck --lost-found       # writes dangling objects to .git/lost-found/
git cat-file -p dangling_hash   # inspect to decide if worth recovering

# ── Maintenance ───────────────────────────────────────────────
git gc --aggressive         # repack and compress (takes longer)
git gc --prune=now          # also remove all loose objects immediately

Common Mistakes

  • Running git gc --prune=now immediately after an accidental reset — this permanently removes the dangling commit before you can recover it via git reflog
  • Assuming git branch -d frees disk space — deleted branches leave dangling objects until the next git gc prune cycle
  • Treating short hashes as stable identifiers — a 7-char abbreviation can become ambiguous as the repo grows; always store full 40-char hashes in scripts

Tips

  • Use git cat-file -p and git ls-tree when debugging unexpected behavior — seeing the raw objects demystifies what merge, rebase, and reset actually change
  • Run git fsck if a repo seems corrupt after a crash — it identifies missing or broken objects before gc removes them
  • For large repos with binary assets, consider Git LFS (Large File Storage) — it replaces blobs with small pointer files and stores the actual data on a separate server

Summary

  • Four object types: blob · tree · commit · tag
  • git cat-file -p — inspect any object by hash
  • Refs in .git/refs/ — human-readable pointers to hashes
  • git fsck — verify integrity; find dangling objects
  • git gc — pack loose objects, reclaim space, prune unreachable
