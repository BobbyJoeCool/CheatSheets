Remotes, Fetch & Pull

Talking to Other Repositories

A remote is a named URL for another copy of the repo; origin is the one you cloned from. git fetch downloads new commits into remote-tracking branches like origin/main without touching your work. git pull is fetch followed by a merge (or rebase) into your current branch. Fetching first and integrating deliberately avoids surprises.

Notes

  • origin/main updates only when you fetch
  • In forks: origin = your fork, upstream = the original
  • Without pull.rebase or pull.ff set, Git asks you to choose
  • fetch.prune true removes branches deleted on the remote

Remote, Fetch, Pull

git remote -v                               # list remotes + URLs
git remote add upstream https://github.com/org/app.git
git remote set-url origin git@github.com:me/app.git   # switch to SSH
git remote rename origin old-origin
git remote remove old-origin
git remote show origin                      # tracking + stale branch info

git fetch                                   # update origin/* refs
git fetch --all --prune                     # all remotes, drop deleted branches
git fetch upstream main                     # one branch from one remote
git log --oneline main..origin/main         # what's new upstream

git pull                                    # fetch + integrate into current branch
git pull --rebase                           # fetch + rebase local commits on top
git pull --ff-only                          # only if no local commits diverged
git config --global pull.ff only            # make --ff-only the default
git branch -u origin/main                   # set upstream for this branch

Code Explained

remote -v — shows fetch and push URLs
set-url — change a remote's address (HTTPS ↔ SSH)
fetch --prune — removes stale origin/* refs
main..origin/main — commits you'd get by pulling
pull --rebase — linear history, no merge bubbles
branch -u — sets the upstream used by bare pull/push

⚠ Common Mistakes

  • Thinking origin/main is live. It's a snapshot from your last fetch
  • Running git pull with uncommitted changes. Commit or stash first, or set rebase.autoStash
  • Pulling with merge on a feature branch repeatedly. You get a trail of meaningless merge commits

✓ Tips & Best Practices

  • Prefer git fetch + review + git rebase origin/main for full control
  • Sync a fork: git fetch upstream && git rebase upstream/main
  • Set fetch.prune true globally

Quick Summary

  • remote add / -v — manage remotes
  • fetch — download, don't touch work
  • pull — fetch + merge/rebase
  • origin/main — tracking snapshot
