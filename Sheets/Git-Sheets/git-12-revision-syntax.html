Referencing Commits

Revision Syntax

Almost every Git command accepts a revision: a hash, branch, tag, or an expression relative to one. ~ walks back through first parents, ^ picks a specific parent of a merge, @{…} reads the reflog or upstream, and .. / ... describe ranges. Learn these once and they work in log, diff, show, reset, and rebase.

Notes

  • @ alone is shorthand for HEAD
  • HEAD~1 and HEAD^ are the same commit
  • Quote braces in some shells: 'HEAD@{1}'
  • git help revisions has the full grammar

Revision Expressions

git show HEAD~2               # grandparent (follow first parents)
git show HEAD^2               # second parent of a merge commit
git show a1b2c3d              # any unique hash prefix (4+ chars)
git show v1.4.0^{commit}      # the commit an annotated tag points to
git show main:src/app.js      # a file as it is on main
git diff @{u}                 # working tree vs upstream (origin/main)
git log @{u}..                # local commits not yet pushed
git log ..@{u}                # upstream commits you haven't pulled
git show main@{yesterday}     # where main pointed yesterday (reflog)
git switch @{-1}              # previous branch (same as: git switch -)
git log --left-right --oneline main...feature   # < main  > feature

git rev-parse HEAD            # full hash
git rev-parse --short HEAD    # a1b2c3d
git rev-parse --abbrev-ref HEAD   # current branch name

Code Explained

~n — n steps back along first parents
^n — the nth parent of a merge commit
rev:path — a blob or tree at that revision
@{u} — the branch's upstream tracking branch
@{-1} — the branch you were on before
rev-parse — turns any revision into a hash or name

Reflog Refs

SyntaxMeaning

⚠ Common Mistakes

  • Mixing up ~ and ^. HEAD^2 is a merge's second parent, not two commits back
  • Expecting .. to mean the same in diff and log. In diff, A..B is just A B
  • Using @{yesterday} on a fresh clone. The reflog is local and starts at clone time

✓ Tips & Best Practices

  • Use git log @{u}.. before pushing to see what will go up
  • In scripts, prefer git rev-parse --verify <rev> to validate input
  • Use git show HEAD:path > old.js to save an old version of a file

Quick Summary

  • ~ — walk back first parents
  • ^n — choose a merge parent
  • A..B / A...B — ranges
  • @{u} / @{-1} — upstream / last branch
