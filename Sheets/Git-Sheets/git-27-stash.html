Shelving Work in Progress

git stash saves your uncommitted changes onto a stack and cleans the working tree, so you can switch branches, pull, or fix something urgent. Bring them back later with pop (apply and remove) or apply (apply and keep). By default stash only saves tracked files; add -u for new files.

Notes

  • Stashes are local; they are never pushed
  • stash@{0} is always the most recent
  • pop that conflicts keeps the stash so nothing is lost
  • --staged (Git 2.35+) stashes only staged changes

Stash Commands

git stash                          # stash tracked changes (= stash push)
git stash -u                       # include untracked files
git stash -a                       # include untracked + ignored
git stash push -m "wip: navbar"    # with a description
git stash push -p                  # choose hunks
git stash push -- src/nav.js       # only certain paths
git stash --keep-index             # stash unstaged, keep staged in place

git stash list                     # stash@{0}: On main: wip: navbar
git stash show -p stash@{1}        # view a stash's diff
git stash pop                      # apply newest + drop it
git stash apply stash@{2}          # apply, keep it in the list
git stash drop stash@{1}           # delete one
git stash clear                    # delete all (careful)
git stash branch fix-nav stash@{0} # new branch from the stash's base

Code Explained

-u — untracked files too (new files are skipped otherwise)
-m — label it so stash list is readable
-p / -- path — partial stashes
pop vs apply — remove vs keep after applying
show -p — inspect before applying
stash branch — safest way to apply an old, conflicting stash

When to Stash

SituationFlow
Urgent fix elsewherestash -u → switch → fix → back → pop
Pull with local editsstash → pull → pop
Wrong branchstash → switch → pop
Test staged onlystash --keep-index -u

⚠ Common Mistakes

  • Forgetting -u. New files stay behind and follow you to the next branch
  • Using stash as long-term storage. Stashes are easy to forget and lose; commit on a branch instead
  • git stash clear by accident. Recovery means hunting dangling commits with git fsck

✓ Tips & Best Practices

  • Always add -m so you know what each stash is
  • Set git config --global rebase.autoStash true to stash around rebases automatically
  • Prefer apply + drop when a conflict is likely

Quick Summary

  • stash -u -m — save everything, labeled
  • stash list / show -p — inspect
  • pop / apply — restore
  • stash branch — apply safely
