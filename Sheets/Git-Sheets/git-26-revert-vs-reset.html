Revert vs Reset vs Restore

git revert <sha> · revert -m 1 merges · --no-commit · local vs pushed history · which undo? decision table · commit --amend

Choosing the Right Undo

Git has several "undo" commands that work at different levels. git revert adds a new commit that inverts an old one, so it's safe on shared branches. git reset moves the branch backward and is for local history. git restore only changes files. commit --amend replaces the most recent commit. Ask: is it pushed, and is it a commit or just files?

Notes

  • Revert never rewrites history
  • Reverting a merge needs -m 1 to name the mainline parent
  • Reverting a revert re-applies the original change
  • Restore and reset on files never create commits

Revert Examples

git revert a1b2c3d                 # new commit that undoes a1b2c3d
git revert HEAD                    # undo the last commit, publicly
git revert --no-edit HEAD~2        # use the default message
git revert -n a1b2c3d b4e5f6a      # undo several, commit once yourself
git commit -m "Revert search feature"
git revert a1b2c3d..f6a7b8c        # revert a range (newest first)

git revert -m 1 9f8e7d6            # undo a merge commit, keep main's side
git revert --continue              # after resolving a conflict
git revert --abort

git commit --amend                 # fix the most recent commit instead

Code Explained

revert <sha> — computes the inverse diff and commits it
--no-edit — skips the message editor
-n — stage the inverse changes without committing
A..B — reverts every commit after A up to B
-m 1 — parent 1 (the branch merged into) is kept
--amend — only for the latest, unpushed commit

Which Undo?

SituationUse
Typo in last commit (not pushed)commit --amend
Bad commit, already pushedgit revert <sha>
Bad commits, not pushedreset --soft / --hard
Discard edits to a filegit restore <file>
Unstage a filegit restore --staged <file>
Old version of one filerestore --source=<sha> <file>
Bad merge, pushedgit revert -m 1 <merge>

⚠ Common Mistakes

  • Using reset to undo a pushed commit. Teammates still have it, and your force push confuses everyone
  • Reverting a merge without -m. Git errors because it can't tell which side to keep
  • Merging the branch again after reverting its merge. Git thinks it's already merged; revert the revert first

✓ Tips & Best Practices

  • Rule of thumb: pushed → revert; local → reset or amend
  • Reference the reverted commit and the reason in the revert message
  • Use git revert -n across several commits to ship one clean undo

Quick Summary

  • revert — safe public undo
  • reset — rewrite local history
  • restore — file-level undo
  • --amend — fix the last commit
