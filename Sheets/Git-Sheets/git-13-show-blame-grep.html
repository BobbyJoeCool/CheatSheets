Sheet 13

Show, Blame & Grep

git show <sha> · show <sha>:file · git blame -L · blame -w -C · --ignore-revs-file · git grep · git describe

Inspecting Code and Commits

git show displays any object: a commit with its diff, a tag, or a file at a revision. git blame labels each line with the commit that last changed it, which is the quickest route from "why is this here?" to the commit message and PR. git grep searches tracked files fast, at any revision, and git describe names a commit relative to the nearest tag.

Notes

  • Blame shows the last change, not necessarily the author of the idea
  • -w ignores whitespace-only changes in blame
  • .git-blame-ignore-revs skips formatting-only commits
  • git grep skips untracked and ignored files

Show, Blame, Grep, Describe

git show                          # HEAD: message + diff
git show a1b2c3d --stat           # a commit's file summary
git show v2.0                     # tag info + the commit it points to
git show HEAD~3:src/app.js        # file contents at a revision

git blame src/app.js              # who changed each line, and when
git blame -L 40,60 src/app.js     # only lines 40-60
git blame -L :login src/app.js    # only the function "login"
git blame -w -C src/app.js        # ignore whitespace, detect moved code
git blame --ignore-revs-file .git-blame-ignore-revs src/app.js
git config blame.ignoreRevsFile .git-blame-ignore-revs   # make it default

git grep -n "TODO"                # search tracked files with line numbers
git grep -c "useState" -- '*.tsx' # count matches per file
git grep "apiUrl" v1.0            # search an older revision
git describe --tags               # v1.4.0-12-ga1b2c3d

Code Explained

show rev:path — prints the file, no diff
blame -L a,b — limit to a line range or :funcname
-C — detect lines moved or copied from other files
--ignore-revs-file — skip listed bulk-format commits
git grep <rev> — search without checking it out
describe — tag, commits since tag, g + short hash

⚠ Common Mistakes

  • Blaming the person on a reformatted line. A formatter commit hides the real author; use -w or ignore-revs
  • Using grep -r in a repo. It also searches .git/ and node_modules/; git grep doesn't
  • Expecting describe to find lightweight tags. It needs --tags for those

✓ Tips & Best Practices

  • Click through blame: git show <sha> on the hash it prints
  • Commit a .git-blame-ignore-revs file; GitHub honors it too
  • Use git describe --tags --always --dirty for build version strings

Quick Summary

  • git show — inspect any object
  • git blame -L — line history
  • git grep — fast tracked-file search
  • git describe — tag-based name
