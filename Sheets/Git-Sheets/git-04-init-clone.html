Sheet 04

Init & Clone

git init · --bare · git clone <url> · --depth 1 · --branch · --recurse-submodules · HTTPS vs SSH URLs

Creating a Repository

There are two ways to get a repository: git init turns an existing folder into a new repo, and git clone copies an existing repo with its entire history and sets up origin as the remote. A bare repository has no working tree and is what servers store. Shallow and partial clones trade history for speed on large projects.

Notes

  • git clone checks out the remote's default branch
  • The clone's remote is named origin unless you pass -o
  • git init is safe to run on an existing repo; it changes nothing
  • Bare repo folders end in .git by convention

Init and Clone Variants

git init                          # turn the current folder into a repo
git init -b main my-project       # new folder, initial branch "main"
git init --bare server.git        # bare repo (no working tree)

git clone https://github.com/user/app.git          # into ./app
git clone git@github.com:user/app.git my-app       # SSH, custom folder
git clone --branch v2.1 <url>                      # check out a tag/branch
git clone --depth 1 <url>                          # latest commit only
git clone --single-branch --branch main <url>      # one branch only
git clone --recurse-submodules <url>               # also init submodules
git clone --filter=blob:none <url>                 # partial: fetch blobs on demand

git remote add origin git@github.com:user/app.git  # link an init'd repo
git push -u origin main                            # first push

Code Explained

-b main — sets the initial branch name
--bare — repo with no checkout, used as a shared remote
--branch — check out a branch or tag instead of the default
--depth 1 — shallow: no older history (fast CI clones)
--filter=blob:none — full history, file contents fetched as needed
remote add + push -u — publish a repo you started with init

⚠ Common Mistakes

  • Running git init inside another repo. You get a nested repo the outer one can't track
  • Cloning into a folder that already has files. Clone needs an empty or new folder
  • Using --depth 1 for development. Log, blame, and rebase lose history (git fetch --unshallow restores it)

✓ Tips & Best Practices

  • Prefer SSH URLs once your key is set up: no token prompts
  • Use --filter=blob:none on huge repos instead of a shallow clone
  • Clone with -o upstream when the source is someone else's repo you'll fork

Quick Summary

  • git init — start a new repo
  • git clone <url> — copy repo + history
  • --depth 1 — shallow clone
  • --bare — server-side repo
