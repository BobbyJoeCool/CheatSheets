Sheet 05

Ignoring Files & .gitattributes

.gitignore patterns · ! negation · core.excludesFile · git check-ignore -v · git rm --cached · .gitattributes · text=auto / eol=lf · binary

Controlling What Git Tracks

A .gitignore file lists patterns for untracked files Git should never offer to add: build output, dependencies, secrets, OS junk. It does not affect files already tracked. .gitattributes sets per-path behavior: line-ending normalization, binary handling, diff drivers, and merge strategies. Commit both files so the whole team shares them.

Notes

  • Patterns are relative to the .gitignore file's folder
  • Personal ignores go in .git/info/exclude (not committed)
  • Global ignores: core.excludesFile ~/.gitignore_global
  • Git never tracks empty folders; add a .gitkeep file

.gitignore and .gitattributes

# .gitignore
node_modules/        # any folder named node_modules
/build               # only build at the repo root
*.log                # every .log file
!keep.log            # ...except this one
.env*                # .env, .env.local
**/tmp/              # tmp/ at any depth
.DS_Store

# .gitattributes
* text=auto          # normalize line endings to LF in the repo
*.sh text eol=lf     # always LF on checkout
*.bat text eol=crlf  # always CRLF on checkout
*.png binary         # no diff, no EOL conversion
dist/** export-ignore   # leave out of git archive

git check-ignore -v build/app.js   # which rule matched?
git rm --cached .env               # stop tracking, keep the file

Code Explained

dir/ — trailing slash matches folders only
/build — leading slash anchors to this folder
! — re-include something an earlier rule ignored
text=auto — Git decides text vs binary and normalizes EOL
check-ignore -v — prints file, line, and pattern that matched
rm --cached — untrack a file that was committed before being ignored

Pattern Syntax

PatternMatches
*.logany .log file at any depth
doc/*.txtdoc/a.txt, not doc/x/a.txt
doc/**/*.pdfPDFs anywhere under doc/
debug?.logdebug1.log, debugA.log
[Bb]in/bin/ or Bin/
\#filea name starting with #

⚠ Common Mistakes

  • Adding a file to .gitignore after committing it. It stays tracked until you git rm --cached it
  • !file inside an ignored folder. Git can't re-include a file whose parent folder is excluded
  • Inline comments after a pattern. # only starts a comment at the beginning of a line

✓ Tips & Best Practices

  • Start from github.com/github/gitignore templates for your stack
  • After adding .gitattributes, run git add --renormalize . and commit
  • List ignored files with git status --ignored

Quick Summary

  • .gitignore — untracked files to skip
  • check-ignore -v — debug a rule
  • rm --cached — untrack, keep on disk
  • text=auto / eol=lf — line endings
