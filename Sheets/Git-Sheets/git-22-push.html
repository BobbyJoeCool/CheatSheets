Push

git push · -u origin <branch> · push.autoSetupRemote · --force-with-lease vs --force · --delete · push origin HEAD · rejected non-fast-forward

Publishing Commits

git push uploads your commits and moves the branch on the remote. The remote only accepts a fast-forward: if someone else pushed first, you're rejected until you integrate their work. After rewriting history (amend, rebase), a force push is required; --force-with-lease makes it safe by refusing if the remote moved since you last fetched.

Notes

  • Default push.default simple pushes the current branch to its upstream
  • -u sets upstream so later git push / pull need no arguments
  • push.autoSetupRemote true (Git 2.37+) does -u automatically
  • Protected branches on GitHub/GitLab may block force pushes

Push Variants

git push -u origin feature/login        # first push: create + track
git push                                # later pushes
git push origin HEAD                    # push current branch, same name
git push origin local:remote-name       # push to a different branch name
git push --dry-run                      # show what would happen

# ! [rejected] main -> main (non-fast-forward)
git pull --rebase && git push           # integrate, then push

git push --force-with-lease             # safe force after rebase/amend
git push --force-with-lease --force-if-includes   # extra safety
git push --force                        # overwrite unconditionally (avoid)

git push origin --delete feature/login  # delete a remote branch
git push --follow-tags                  # commits + annotated tags
git config --global push.autoSetupRemote true

Code Explained

-u — remembers origin/feature/login as upstream
HEAD — the current branch, whatever its name
local:remote — refspec: source on the left, destination on the right
non-fast-forward — the remote has commits you don't
--force-with-lease — fails if the remote changed since your fetch
--delete — removes the branch on the server

Force Push Options

OptionSafety
--forceoverwrites anything: risky
--force-with-leaseonly if remote = your last fetch
--force-if-includesalso checks you saw the remote tip
+branch refspecforce for one ref only

Push Errors

MessageFix
non-fast-forwardgit pull --rebase, then push
no upstream branchgit push -u origin HEAD
stale info (lease)git fetch, review, retry
protected branchopen a pull request instead
Permission deniedcheck SSH key / token (Sheet 23)

⚠ Common Mistakes

  • Using --force on a shared branch. It silently deletes teammates' commits
  • Running git fetch right before --force-with-lease. The lease then matches whatever is there, which defeats it
  • Pushing to main directly when the team uses PRs. Push a branch and open a PR

✓ Tips & Best Practices

  • Alias pushf to push --force-with-lease
  • Set push.autoSetupRemote true and never type -u again
  • Check git log @{u}.. before pushing

Quick Summary

  • push -u origin <br> — first push
  • --force-with-lease — safe force
  • --delete — remove remote branch
  • rejected → pull --rebase → push
