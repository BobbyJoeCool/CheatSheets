Sheet 16

Merging

git merge <branch> · fast-forward · --no-ff · --ff-only · --squash · merge --abort · -X ours / -X theirs

Combining Branches

git merge brings another branch's commits into the current branch. If your branch hasn't moved, Git just slides the pointer forward (fast-forward). Otherwise it creates a merge commit with two parents. Options let you force a merge commit, refuse anything but a fast-forward, or squash everything into one staged change.

Notes

  • Always merge *into* the branch you're on: switch first
  • A clean working tree avoids most merge errors
  • Merge commits preserve the exact history of both branches
  • Conflicts pause the merge; see Sheet 17

Merge Variants

git switch main
git merge feature/login            # fast-forward if possible, else merge commit
git merge --no-ff feature/login    # always create a merge commit
git merge --ff-only origin/main    # only fast-forward; fail otherwise
git merge --squash feature/login   # stage all changes, no commit yet
git commit -m "Add login (#42)"    # ...then commit the squash yourself
git merge -m "Merge release 2.1" release/2.1

git merge -X theirs feature        # on conflicting hunks, prefer theirs
git merge -X ours feature          # on conflicting hunks, prefer ours
git merge --abort                  # stop and return to the pre-merge state
git merge --continue               # finish after resolving conflicts

git log --oneline --graph -5       # see the merge shape
git branch --merged                # branches fully merged into HEAD

Code Explained

fast-forward — no new commit; the branch pointer just moves
--no-ff — keeps a visible merge bubble for the feature
--ff-only — safe sync; errors if histories diverged
--squash — one combined change, no link to the branch history
-X ours|theirs — strategy option for conflicting hunks only
--abort — restores the branch and working tree

⚠ Common Mistakes

  • Confusing -X ours with -s ours. -s ours discards *all* of the other branch's changes
  • Squash-merging, then continuing to use the branch. Git doesn't know it was merged, so you get repeat conflicts
  • Merging with uncommitted changes. If the merge fails they can get tangled; commit or stash first

✓ Tips & Best Practices

  • Set git config --global merge.ff only for a no-surprises git merge
  • Preview with git log --oneline main..feature before merging
  • Undo a just-finished merge with git reset --hard ORIG_HEAD

Quick Summary

  • merge <branch> — combine into current
  • --no-ff / --ff-only — control the shape
  • --squash — one commit
  • --abort — back out
