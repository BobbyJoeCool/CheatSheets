Sheet 08

Viewing Diffs

git diff · --staged / --cached · diff HEAD · A..B vs A...B · --stat / --name-only · --word-diff · -w · difftool

Comparing Snapshots

git diff compares any two of: the working tree, the staging area, and any commit. With no arguments it shows unstaged changes only, which surprises many people. Add --staged for what will be committed, or name commits and branches to compare history. Options control the output format, whitespace handling, and which files are included.

Notes

  • --staged and --cached are the same option
  • A...B in diff means: changes on B since it branched from A
  • Use -- <path> to limit any diff to files or folders
  • diff.algorithm histogram often gives cleaner diffs

Diff Variants

git diff                        # working tree vs staging area (unstaged)
git diff --staged               # staging area vs HEAD (what you'll commit)
git diff HEAD                   # working tree vs HEAD (all changes)
git diff HEAD~3                 # working tree vs 3 commits ago
git diff main feature           # tip of main vs tip of feature
git diff main...feature         # feature's changes since it left main
git diff a1b2c3d b4e5f6a -- src/ # two commits, src/ only

git diff --stat                 # files changed + insertions/deletions
git diff --name-only main       # just file names
git diff --name-status main     # M / A / D / R per file
git diff --word-diff            # inline word changes (prose, docs)
git diff -w                     # ignore whitespace
git diff --color-moved          # highlight moved lines
git difftool -t vscode          # open in a GUI diff tool

Code Explained

no args — only what you haven't staged yet
--staged — the exact content of your next commit
main...feature — diffs from the merge base: ideal for PR review
--stat / --name-only — summaries instead of full patches
--word-diff — shows [-old-]{+new+} inline
-w — hides indentation-only noise

⚠ Common Mistakes

  • Seeing an empty git diff after git add and thinking nothing changed. Use --staged
  • Using A..B in diff expecting the log meaning. In diff, A..B equals A B
  • Reviewing a branch with git diff main feature. It also shows main's newer changes reversed; use ...

✓ Tips & Best Practices

  • Run git diff --staged right before every commit
  • Set git config --global diff.colorMoved zebra to spot moved code
  • Use git diff --check to catch trailing whitespace and conflict markers

Quick Summary

  • git diff — unstaged changes
  • --staged — staged changes
  • A...B — branch changes since fork
  • --stat — summary view
