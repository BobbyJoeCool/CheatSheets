Reset

reset --soft / --mixed / --hard · reset HEAD~1 · reset <file> · what moves (HEAD / index / tree) · ORIG_HEAD

Moving the Branch Pointer

git reset <commit> moves the current branch to another commit. The mode decides what else changes: --soft leaves the staging area and files alone, --mixed (the default) also resets the staging area, and --hard also overwrites your working files. Reset rewrites history, so use it on local, unpushed commits.

Notes

  • Commits you reset away stay in the reflog for ~90 days
  • --hard discards uncommitted changes permanently
  • ORIG_HEAD = where HEAD was before reset, merge, or rebase
  • With a file path, reset only unstages: no pointer moves

Reset Modes in Practice

git reset --soft HEAD~1        # undo last commit, keep changes staged
git reset HEAD~1               # undo last commit, keep changes unstaged (--mixed)
git reset --hard HEAD~1        # undo last commit AND discard its changes
git reset --hard               # throw away all uncommitted changes
git reset --hard origin/main   # make the branch match the remote exactly
git reset --keep HEAD~1        # like --hard but stops if it would lose edits

git reset app.js               # unstage a file (= git restore --staged app.js)
git reset --hard ORIG_HEAD     # undo the last merge/rebase/reset

# squash the last 3 commits into one
git reset --soft HEAD~3
git commit -m "Add search feature"

Code Explained

--soft — branch moves; index + files untouched
--mixed — branch + index reset; files untouched
--hard — branch, index, and files all reset
--keep — safer hard reset; aborts on conflicting local edits
reset <file> — copies HEAD's version into the index only
--soft HEAD~3 + commit — quick squash without interactive rebase

What Each Mode Changes

⚠ Common Mistakes

  • reset --hard with uncommitted work. Uncommitted changes aren't in the reflog; they're gone
  • Resetting commits that are already pushed. Your next push needs force and breaks teammates; use revert
  • Typing HEAD-1. The syntax is HEAD~1

✓ Tips & Best Practices

  • Stash first if you're unsure: git stash -u then reset
  • Prefer --keep over --hard when moving branches with local edits
  • Check git status and git log -1 right after a reset

Quick Summary

  • --soft — keep staged
  • --mixed — keep in files
  • --hard — discard everything
  • ORIG_HEAD — undo the last big move
