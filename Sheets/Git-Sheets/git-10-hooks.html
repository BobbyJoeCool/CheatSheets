Git Hooks

Git hooks are executable scripts in .git/hooks/ that Git runs automatically at specific points in the workflow — before or after commits, merges, pushes, and more. A hook is triggered by naming the script after the event (e.g. pre-commit) and making it executable. If a client-side hook exits with a non-zero status, the Git operation is aborted. Hooks are not committed or cloned with the repository by default, so teams use tools like Husky (Node.js) or pre-commit (Python) to share and manage hooks through version control.

Key Facts

  • Hooks live in .git/hooks/ — not committed to the repo by default
  • Must be executable: chmod +x .git/hooks/pre-commit
  • Exit 0 = success (operation proceeds); non-zero = abort
  • Client-side hooks run locally; server-side hooks run on the remote
  • git commit --no-verify skips all client-side hooks
  • Use core.hooksPath to point Git to a shared hooks directory

Writing & Sharing Hooks

# ── Minimal pre-commit hook ───────────────────────────────────
cat > .git/hooks/pre-commit << 'EOF'
#!/bin/sh
npm run lint        # exit 1 if lint fails → commit aborted
npm run test:unit   # run fast unit tests only
EOF
chmod +x .git/hooks/pre-commit

# ── commit-msg: enforce Conventional Commits format ───────────
cat > .git/hooks/commit-msg << 'EOF'
#!/bin/sh
MSG=$(cat "$1")
PATTERN="^(feat|fix|docs|style|refactor|test|chore)(\(.+\))?: .{1,72}"
if ! echo "$MSG" | grep -qE "$PATTERN"; then
  echo "ERROR: Commit message must follow Conventional Commits."
  echo "  Example: feat(auth): add OAuth login"
  exit 1
fi
EOF
chmod +x .git/hooks/commit-msg

# ── post-merge: auto-install deps if lockfile changed ─────────
cat > .git/hooks/post-merge << 'EOF'
#!/bin/sh
if git diff-tree -r --name-only --no-commit-id ORIG_HEAD HEAD \
  | grep -q "package-lock.json"; then
  echo "Lockfile changed — running npm install"
  npm install
fi
EOF
chmod +x .git/hooks/post-merge

# ── Share hooks via core.hooksPath ───────────────────────────
mkdir -p scripts/hooks
cp .git/hooks/pre-commit scripts/hooks/
git config core.hooksPath scripts/hooks  # team members set this once

Notes

#!/bin/sh — shebang line is required; hooks are shell scripts by convention but can be any executable
$1 in commit-msg — path to the temporary file containing the commit message written by the user
diff-tree in post-merge — compares ORIG_HEAD (pre-merge) to HEAD (post-merge) to detect lockfile changes
core.hooksPath — redirects Git to a committed directory for hooks; each developer runs git config core.hooksPath scripts/hooks once after cloning
Husky automates core.hooksPath setup via the prepare npm script — runs automatically on npm install
--no-verify — bypass hooks when a hook itself is broken; fix the hook and remove this flag before pushing

Common Mistakes

  • Forgetting chmod +x — Git silently skips hooks that are not executable, giving no warning that the hook isn't running
  • Putting slow tests in pre-commit — hooks blocking commits for minutes train developers to use --no-verify; save slow tests for pre-push or CI
  • Relying solely on client-side hooks for security — any developer can bypass them with --no-verify; enforce critical policies with server-side hooks or branch protection rules

Tips

  • Use lint-staged in pre-commit to lint only staged files — dramatically faster than linting the whole project on every commit
  • Document hook setup in README.md or CONTRIBUTING.md — new contributors must know to run git config core.hooksPath scripts/hooks after cloning
  • Keep hooks fast and focused — one hook per concern is easier to debug and bypass surgically when needed

Summary

  • Hooks live in .git/hooks/ — must be executable scripts
  • pre-commit — lint/format before commit is written
  • commit-msg — validate message format after writing
  • core.hooksPath — share hooks via a committed directory
  • Husky — manages hook installation via npm lifecycle
