Resolving Conflicts

<<<<<<< ======= >>>>>>> markers · checkout --ours / --theirs · git mergetool · merge.conflictStyle zdiff3 · git rerere · add then commit to finish

When Git Can't Decide

A conflict happens when both sides changed the same lines (or one side edited a file the other deleted). Git pauses, writes conflict markers into the file, and marks it as unmerged. You edit the file to the correct result, git add it, and continue. The same steps apply during merge, rebase, cherry-pick, revert, and stash pop.

Notes

  • During a rebase, ours is the branch you're rebasing onto
  • zdiff3 style also shows the common ancestor's version
  • rerere replays resolutions you've made before
  • git diff during a conflict shows a combined diff

Conflict Workflow

git merge feature            # CONFLICT (content): Merge conflict in app.js
git status                   # "both modified: app.js"
git diff --name-only --diff-filter=U   # list conflicted files

# app.js with merge.conflictStyle=zdiff3
<<<<<<< HEAD
const timeout = 5000;
||||||| base
const timeout = 3000;
=======
const timeout = 10000;
>>>>>>> feature

git checkout --ours   app.js   # take our whole version of the file
git checkout --theirs app.js   # take their whole version
git mergetool                  # open the configured merge tool
git add app.js                 # mark resolved
git merge --continue           # or: git commit / git rebase --continue

Code Explained

<<<<<<< HEAD — your side (current branch)
||||||| base — the original, shown with zdiff3
>>>>>>> feature — the incoming side
--diff-filter=U — only unmerged files
--ours / --theirs — pick one side for the whole file
git add — tells Git the file is resolved

Ours vs Theirs

Operationours / theirs
merge Xcurrent branch / X
rebase mainmain (new base) / your commit
cherry-pick Ccurrent branch / C
stash popcurrent tree / the stash

⚠ Common Mistakes

  • Committing with markers still in the file. Run git diff --check to find stray <<<<<<< lines
  • Using --ours during a rebase to keep *your* work. In a rebase, --theirs is your commit
  • Resolving by deleting the other side blindly. Read both versions; often you need parts of each

✓ Tips & Best Practices

  • Turn on zdiff3: seeing the base makes most conflicts obvious
  • Run the tests before --continue; a clean merge can still be broken
  • Keep branches short-lived to keep conflicts small
