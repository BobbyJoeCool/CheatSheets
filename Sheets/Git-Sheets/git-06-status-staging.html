Status & Staging

git status -sb · XY status codes · add . / -A / -u · add -p · -N intent-to-add · git restore --staged · git rm / git mv

Building the Next Commit

The staging area lets you choose exactly what goes into the next commit. git status shows which changes are staged, which are not, and which files are untracked. git add stages whole files or, with -p, individual hunks, so one messy working tree can become several clean commits.

Notes

  • git add stages content as it is now; edit again and you must re-add
  • git add . stages the current folder and below, including deletions
  • git rm and git mv stage removals and renames for you
  • Git detects renames by content similarity, not by mv

Status and Staging

git status                 # long form with hints
git status -sb             # short form + branch/ahead/behind
## main...origin/main [ahead 1]
 M src/app.js              # modified, not staged
M  README.md               # modified and staged
?? notes.txt               # untracked

git add README.md          # stage one file
git add src/               # stage a folder
git add -A                 # stage everything in the repo (new, changed, deleted)
git add -u                 # stage changed + deleted tracked files only
git add -p                 # pick hunks interactively
git add -N new.js          # intent-to-add: shows in git diff

git restore --staged README.md   # unstage (keep edits)
git rm old.js                    # delete + stage the deletion
git mv a.js b.js                 # rename + stage

Code Explained

-sb — short format plus a branch line with ahead/behind counts
XY — X = staged column, Y = working-tree column
-A vs -u — -u skips untracked files
-p — prompts y/n/s/e/q per hunk
restore --staged — modern unstage (old: git reset <file>)
git rm --cached — unstage and untrack, but keep the file

⚠ Common Mistakes

  • Committing with -a and expecting new files to be included. -a only stages tracked files
  • Editing a file after git add and committing. The commit has the older staged version
  • git add . from a subfolder. It only stages that subfolder (use -A for the whole repo)

✓ Tips & Best Practices

  • Alias git st to status -sb for a compact view
  • Review what's staged with git diff --staged before committing
  • Use git add -p to split unrelated changes into separate commits

Quick Summary

  • git status -sb — compact state
  • git add -p — stage hunks
  • git restore --staged — unstage
  • git rm / git mv — staged delete / rename
