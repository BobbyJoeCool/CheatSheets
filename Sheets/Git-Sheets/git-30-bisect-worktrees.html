Bisect & Worktrees

git bisect start · good / bad / skip · bisect run <script> · bisect reset · git worktree add ../dir <branch> · worktree list / remove · worktree prune · one branch per worktree

Hunting Bugs and Working in Parallel

git bisect binary-searches history to find the first bad commit: you mark one good and one bad commit, and Git checks out midpoints until it isolates the culprit, about log₂(n) steps. Worktrees give one repository several working folders, each on its own branch, so you can review a PR or hotfix without stashing your current work.

Notes

  • 1,000 commits take about 10 bisect steps
  • bisect run exit codes: 0 good, 125 skip, 1–127 bad
  • Worktrees share one .git object store, so they're cheap
  • A branch can be checked out in only one worktree at a time

Bisect and Worktree Commands

git bisect start
git bisect bad                    # current commit is broken
git bisect good v1.4.0            # this tag worked
git bisect good   # / bad / skip  # repeat at each step Git checks out
git bisect run npm test           # or automate with any script
# a1b2c3d is the first bad commit
git bisect log > bisect.txt       # save the session
git bisect reset                  # return to where you started

git worktree add ../app-hotfix hotfix/2.1     # existing branch
git worktree add -b review-87 ../app-review origin/main  # new branch
git worktree list                 # all worktrees + their branches
git worktree remove ../app-review # delete the folder + registration
git worktree prune                # forget folders you deleted manually

Code Explained

bisect bad / good — set the search bounds
bisect skip — commit can't be tested (doesn't build)
bisect run <cmd> — Git marks each step from the exit code
bisect reset — always finish with this
worktree add <path> <branch> — new folder on that branch
-b <name> — create the branch at the same time

Bisect Extras

CommandEffect
bisect start BAD GOODset both bounds at once
bisect viewshow remaining suspects
bisect replay filererun a saved log
--first-parentonly test mainline commits
--term-old / --term-newrename good/bad (e.g. fast/slow)

Worktree Extras

CommandEffect
worktree add --detachno branch, just a commit
worktree lock <path>protect from prune
worktree move <a> <b>relocate a worktree
worktree repairfix links after moving

⚠ Common Mistakes

  • Forgetting git bisect reset. You're left on a detached midpoint commit
  • A bisect run script that fails for unrelated reasons. Make it exit 125 when it can't build
  • Deleting a worktree folder with rm only. Run git worktree prune or Git thinks the branch is still checked out

✓ Tips & Best Practices

  • Write a tiny repro script before bisecting; automated runs are fast and reliable
  • Keep worktrees as siblings: ../app-review, ../app-hotfix
  • Use a worktree to run long tests on one branch while coding on another

Quick Summary

  • bisect start / good / bad — search
  • bisect run — automate
  • worktree add — parallel checkout
  • worktree remove / prune — clean up
