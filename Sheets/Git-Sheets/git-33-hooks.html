Hooks

.git/hooks/ · pre-commit · commit-msg · pre-push · core.hooksPath · --no-verify · pre-commit framework / Husky

Automating Checks

Hooks are scripts Git runs at specific points, such as before a commit or before a push. A hook that exits non-zero stops the operation, so they're used for linting, formatting, test runs, and message checks. Hooks in .git/hooks/ aren't committed, so teams share them via core.hooksPath or a hook manager.

Notes

  • Hooks must be executable: chmod +x
  • Any language works; the shebang line picks the interpreter
  • Client hooks can be skipped; enforce rules in CI or server hooks too
  • .sample files in .git/hooks/ are examples

A pre-commit Hook

#!/bin/sh
# .githooks/pre-commit — block commits with lint errors or debug code
npm run lint --silent || exit 1
if git diff --cached | grep -q "console.log"; then
  echo "Remove console.log before committing" >&2
  exit 1
fi

chmod +x .githooks/pre-commit
git config core.hooksPath .githooks   # use the committed hooks folder
git commit --no-verify -m "WIP"       # skip pre-commit + commit-msg once

# Hook managers
pip install pre-commit && pre-commit install    # .pre-commit-config.yaml
npx husky init                                  # .husky/ for JS projects

Code Explained

exit 1 — non-zero exit aborts the commit
git diff --cached — inspect only what's being committed
>&2 — print the reason to stderr
core.hooksPath — point Git at a versioned hooks folder
--no-verify / -n — bypass hooks for one commit
pre-commit / Husky — install and share hooks automatically

Client-Side Hooks

HookRuns

post-commitafter commit; notifications
pre-rebasebefore a rebase starts

Server-Side Hooks

HookRuns
pre-receivebefore accepting a push

⚠ Common Mistakes

  • Forgetting chmod +x. Git silently ignores non-executable hooks
  • Slow pre-commit hooks running the full test suite. People start using --no-verify; keep them fast
  • Relying on client hooks for policy. Anyone can skip them; enforce in CI

✓ Tips & Best Practices

  • Check only staged files to keep hooks fast (lint-staged, pre-commit)
  • Put heavier checks in pre-push instead of pre-commit
  • Commit hooks in .githooks/ and document the core.hooksPath step

Quick Summary

  • pre-commit — lint before commit
  • commit-msg — enforce message format
  • core.hooksPath — share hooks
  • --no-verify — skip once
