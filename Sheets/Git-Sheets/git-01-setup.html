Sheet 01

Setup & Configuration

git config · global/local scope · identity · aliases · .gitignore

What Is Git?

Git is a distributed version control system that tracks changes to files over time. Unlike centralized systems, every developer has a complete copy of the repository — including its full history — on their own machine. Git was created by Linus Torvalds in 2005 for Linux kernel development and has since become the universal standard for source control. Configuration is stored in plain-text files at three scopes: system (all users), global (current user), and local (current repo), with narrower scopes overriding broader ones.

Key Facts

  • ~/.gitconfig — global config file (user-level)
  • .git/config — local config file (repo-level)
  • Local settings always override global settings
  • git config --list shows all active settings and their source
  • Run git --version to verify your installation
  • Install via brew install git, apt install git, or git-scm.com

First-Time Setup & Aliases

# ── Minimum required after installing Git ────────────────────
git config --global user.name  "Ada Lovelace"
git config --global user.email "ada@example.com"

# ── Editor: VS Code, Vim, Nano ───────────────────────────────
git config --global core.editor "code --wait"  # VS Code
git config --global core.editor "vim"          # Vim
git config --global core.editor "nano"         # Nano

# ── Useful aliases ────────────────────────────────────────────
git config --global alias.st   status
git config --global alias.co   checkout
git config --global alias.br   branch
git config --global alias.last "log -1 HEAD --stat"
git config --global alias.lg   "log --oneline --graph --decorate --all"

# ── Use aliases like regular commands ────────────────────────
git st                         # same as: git status
git lg                         # compact decorated graph log

# ── Per-repo override (inside the repo directory) ─────────────
git config --local user.email "work@company.com"

# ── Remove a setting ─────────────────────────────────────────
git config --global --unset alias.st

# ── Global .gitignore (applies to every repo) ─────────────────
git config --global core.excludesFile ~/.gitignore_global
echo ".DS_Store" >> ~/.gitignore_global
echo "Thumbs.db" >> ~/.gitignore_global

Notes

--global — writes to ~/.gitconfig; affects every repo for this user
--local — writes to .git/config; overrides global for this repo only
alias.lg — the quoted value is the full git command minus the git prefix
--wait — tells VS Code to block the terminal until you close the editor tab
core.excludesFile — a global gitignore applied on top of every repo's local .gitignore
--unset — removes a single key; use --remove-section to drop an entire section

.gitignore Patterns

Pattern Matches
*.log Any file ending in .log anywhere in the repo
build/ The entire build directory and its contents
/TODO Only a TODO file at the repo root
doc/**/*.txt Any .txt file nested anywhere under doc/
!important.log Un-ignore: track important.log even if *.log is ignored
.env* Ignore .env, .env.local, .env.production, etc.
node_modules/ Dependency folder — always ignore, never commit

Essential git config Commands

Command Description
git config --global user.name "Name" Set your display name for all commits
git config --global user.email "e@x.com" Set your email address for all commits
git config --global core.editor "code --wait" Set VS Code as the default commit message editor
git config --global init.defaultBranch main Use main instead of master for new repos
git config --global core.autocrlf input Normalize line endings on commit (use true on Windows)
git config --global pull.rebase false Use merge strategy for git pull (recommended default)
git config --global --edit Open the global config file directly in your editor
git config --list --show-origin List all settings with the file they come from

Common Mistakes

  • Skipping user.name and user.email — commits will show blank or wrong identity, which cannot be changed without rewriting history
  • Adding node_modules/ or .env to .gitignore after already committing them — the files must also be removed from tracking with git rm --cached
  • Using --system instead of --global — system scope requires root/admin and affects every user on the machine

Tips

  • Set init.defaultBranch main globally once so every git init uses main without extra steps
  • Keep a ~/.gitignore_global for OS/editor noise (.DS_Store, .idea/, *.swp) so individual repos stay clean
  • Use git config --list --show-origin to debug which file is supplying a setting — essential when local overrides global unexpectedly

Summary

  • git config --global — user-level settings in ~/.gitconfig
  • git config --local — repo-level settings that override global
  • alias.* — shorthand commands defined in config
  • .gitignore — patterns for files Git should never track
  • core.excludesFile — a global gitignore for OS and editor clutter
