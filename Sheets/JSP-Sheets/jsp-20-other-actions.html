Sheet 20

Other Standard Actions

jsp:element · jsp:attribute · jsp:body · jsp:text · jsp:output · jsp:root · dynamic XML generation

Beyond include, forward & useBean

JSP defines several additional standard actions for dynamic XML/HTML generation. <jsp:element> creates an element with a computed tag name at runtime. <jsp:attribute> sets an attribute whose value may contain EL or JSP content. <jsp:body> provides the body content of a parent action. <jsp:text> wraps template text for use inside action bodies. <jsp:output> controls the XML declaration and DOCTYPE in JSP documents.

Key Facts

  • <jsp:element> is most useful when the tag name itself is dynamic (e.g. driven by a variable)
  • <jsp:attribute> inside a custom tag allows attribute values that contain nested JSP expressions
  • <jsp:body> provides body content to a tag that calls invoke() or getJspBody()
  • <jsp:text> outputs literal text without the container interpreting template content — useful in JSP documents (.jspx)
  • <jsp:output> is only valid in JSP documents (XML syntax, .jspx); it controls the XML/DOCTYPE declaration

Standard Action Usage

<%-- ── jsp:element — dynamic tag name ───────────────────── --%>

  title
  ${section.title}

<%-- renders: 
Introduction
 if headingLevel="h2" --%>

<%-- ── jsp:attribute — complex attribute value ───────────── --%>

  
    ${pageContext.request.contextPath}/item/${item.id}
  
  ${item.name}


<%-- ── jsp:attribute inside a custom tag ─────────────────── --%>

  
    ${user.name}'s Dashboard
  
  
    
Welcome back!

  


<%-- ── jsp:text — literal output in JSP documents ────────── --%>
This text is output verbatim.

<%-- ── jsp:output — XML declaration (jspx files only) ────── --%>

Notes

<jsp:element name="${var}"> — name evaluated at request time; generates opening/closing tags
<jsp:attribute name="x"> — sets attribute on parent element; body can contain JSP/EL
<jsp:body> — provides body to parent tag or element; required when sibling <jsp:attribute> is present
<jsp:text> — wraps whitespace or literal text; prevents container from trimming it in JSP documents
<jsp:output> — controls XML prolog; only valid in .jspx files, not .jsp files
<jsp:root> — root element of a JSP document; carries namespace declarations

⚠ Common Mistakes

  • Using <jsp:output> in a .jsp file — it is only valid in JSP documents (.jspx); in a regular JSP it causes a translation error
  • Omitting <jsp:body> when a sibling <jsp:attribute> is present inside <jsp:element> — without it the element has no body content and the output is an empty element
  • Nesting template text directly inside a custom tag that expects <jsp:attribute> / <jsp:body> — the container may treat it as body content and not an attribute value

✓ Tips

  • Use <jsp:element> when generating elements whose tag name varies by data (e.g., semantic heading levels h1–h6 driven by a depth counter)
  • Use <jsp:attribute> inside custom tag invocations when the attribute value needs to contain EL expressions or nested JSP content that cannot fit in a plain XML attribute string
  • Prefer .jsp (standard syntax) over .jspx for most projects — .jspx's strict XML well-formedness requirement adds friction without proportional benefit in most web UIs

Quick Summary

  • <jsp:element name="${var}"> — dynamic element tag name at runtime
  • <jsp:attribute> — attribute value with nested JSP/EL content
  • <jsp:body> — required when jsp:attribute siblings are present
  • <jsp:text> — literal text verbatim; mainly for .jspx files
  • <jsp:output> — XML declaration control; .jspx only
