Page & Request Scope

setAttribute · getAttribute · removeAttribute · pageScope · requestScope · forward

The Two Shortest-Lived Scopes

JSP defines four attribute scopes, from shortest to longest lived. Page scope exists only for the duration of processing a single JSP page — attributes are gone the moment the response is dispatched. Request scope survives across a RequestDispatcher.forward() call, making it the primary mechanism for a servlet to pass data to a JSP view. Both scopes are accessed through their respective objects: pageContext for page scope, request for request scope.

Key Facts

  • Page scope attributes are NOT shared with included files via <jsp:include> — each dispatched resource gets its own page scope
  • Request scope IS shared across a forward() — it is the standard way servlets hand data to JSPs
  • Request scope is also shared with static includes (<%@ include %>) because they become one servlet
  • EL accesses request attributes via ${requestScope.key} or just ${key} (EL searches all scopes)
  • getAttribute() returns Object — cast to the expected type in scriptlets; EL handles this automatically

Scope Usage Patterns

// ── In the Servlet (controller) ──────────────────────────
List<Product> products = productService.findAll();
request.setAttribute("products", products);     // request scope
request.setAttribute("pageTitle", "Catalogue"); // request scope

RequestDispatcher rd = request.getRequestDispatcher(
        "/WEB-INF/jsp/catalogue.jsp");
rd.forward(request, response);  // attributes travel with request
<%-- ── In the JSP (view) — EL access (preferred) ─────────── --%>
${requestScope.pageTitle}
${pageTitle}          <%-- shorthand — same result --%>

<% request.removeAttribute("products"); %>

Code Notes

request.setAttribute("key", val) — stores in request scope; survives forward()
request.getAttribute("key") — retrieves; returns null if absent
rd.forward(request, response) — passes the same request (and its attributes) to the JSP
${products} — EL shorthand; searches all scopes in order
${requestScope.products} — explicit scope; unambiguous; use when shadowing is possible
pageContext.setAttribute("key", val) — page scope only; not shared with any included resource

⚠ Common Mistakes

  • Setting a request attribute in the JSP after a <jsp:include> and expecting the included page to see it — <jsp:include> runs its own page scope; use the request scope and set before including
  • Using bare ${key} when an attribute of the same name exists in multiple scopes — the most recently set one in the search order wins; use explicit ${requestScope.key} to be unambiguous
  • Expecting page-scope attributes to survive a redirect — a redirect is a new request; page and request scope are both gone
  • Forgetting to cast request.getAttribute() in scriptlets — it returns Object; without a cast, calling methods on it is a compile error

✓ Tips

  • Always set request attributes in the servlet, not the JSP — the servlet is the controller; the JSP only reads them
  • Use explicit scope prefixes in EL (${requestScope.user}) in pages that have a lot of attributes — prevents accidental scope shadowing
  • Prefer request.setAttribute() over URL query parameters for passing data — avoids length limits and keeps data out of the browser address bar
  • For data that must survive a redirect (Post/Redirect/Get pattern), store in session briefly and remove after reading in the next request

Quick Summary

  • page scope — lives for one JSP page only; use pageContext to set
  • request scope — survives forward(); servlet→JSP data channel
  • request.setAttribute("k", v) — primary way servlet passes data to view
  • ${requestScope.key} — explicit EL; avoids scope ambiguity
  • Redirect kills request scope — use session for Post/Redirect/Get
