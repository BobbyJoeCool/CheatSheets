JSTL Output, Variables & URLs

c:out · escapeXml · c:url · c:param · c:redirect · c:import · defaultValue

Output, URLs, and Imports

<c:out> safely outputs a value with automatic HTML escaping — the preferred way to print user-supplied or database data. <c:url> builds a context-relative URL, appends session ID if cookies are disabled, and URL-encodes parameters. <c:redirect> issues a 302 redirect. <c:import> fetches content from a URL (internal or external) and inserts it into the page or stores it in a variable.

Key Facts

  • <c:out> escapes < > & " ' by default; set escapeXml="false" only for trusted HTML content
  • <c:url> prepends the context path automatically — no need to write ${pageContext.request.contextPath}
  • <c:url> also calls encodeURL() to append JSESSIONID when cookies are disabled
  • <c:param> inside <c:url> URL-encodes parameter values automatically
  • <c:redirect> must be called before any output — it commits the response

Tag Notes

<c:out value="${x}" /> — safest way to output any value; escapes by default
default attr — rendered when value is null or empty; eliminates extra <c:if>
<c:url value="/path"> — prepends context path; appends JSESSIONID if needed
var on c:url — stores URL string in scope for reuse; omit to output inline
<c:param> — URL-encodes name and value; replaces manual URLEncoder.encode()
<c:redirect> — calls response.sendRedirect(); execution stops after this tag
<c:import url="/internal"> — uses RequestDispatcher; url="http://..." fetches via HTTP

⚠ Common Mistakes

  • Outputting user input with bare ${param.x} instead of <c:out value="${param.x}"/> — the bare form does not escape HTML and is an XSS vector
  • Building URLs by concatenating context path manually: ${pageContext.request.contextPath}/path?id=${id} — parameter values are not URL-encoded; use <c:url> with <c:param>
  • Using <c:import url="https://..."> for arbitrary external URLs without a timeout — a slow or unresponsive external server will block the entire page rendering thread

✓ Tips

  • Use <c:out> as the default for all data output in JSPs — only switch to bare ${} for values you control (constants, formatted numbers)
  • Use <c:url var="u"> and store the URL in a variable when the same URL appears more than once on the page — avoids repeating the param list
  • Use <c:redirect> instead of <% response.sendRedirect(); %> — it is concise and consistent with the no-scriptlet style

Quick Summary

  • <c:out value="${x}"> — HTML-escapes output; use for all user data
  • default — fallback when value is null or empty
  • <c:url value="/path"><c:param> — context-aware, encoded URL builder
  • <c:redirect url="/path"> — 302; stops execution
  • <c:import> — include internal or external URL content
