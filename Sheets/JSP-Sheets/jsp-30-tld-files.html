Sheet 30

Tag Library Descriptors (TLD)

.tld file · <uri> · <tag> · <attribute> · <function> · META-INF · body-content · dynamic-attributes

Describing a Tag Library

A TLD (Tag Library Descriptor) is an XML file that maps a logical URI to a set of tag handler classes and EL functions. The container reads TLDs at startup from WEB-INF/*.tld or from META-INF/*.tld inside JARs in WEB-INF/lib/. Each tag's attributes, body content type, and handler class are declared here. Tag files (.tag) do not need a TLD — the container generates the metadata automatically.

Key Facts

  • TLD namespace: https://jakarta.ee/xml/ns/jakartaee (Jakarta EE 9+); older: http://java.sun.com/xml/ns/javaee
  • Place in WEB-INF/ for app-local libraries; in META-INF/ inside a JAR for distributable libraries
  • <body-content>: empty | JSP | scriptless | tagdependent
  • rtexprvalue on attribute — true allows EL; false requires literal string
  • For SimpleTag / tag files, use scriptless for body-content (no scriptlets allowed in body)

TLD Structure

/* WEB-INF/myapp.tld */
<?xml version="1.0" encoding="UTF-8"?>
<taglib xmlns="https://jakarta.ee/xml/ns/jakartaee"
        xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
        xsi:schemaLocation="https://jakarta.ee/xml/ns/jakartaee
            https://jakarta.ee/xml/ns/jakartaee/web-jsptaglibrary_3_0.xsd"
        version="3.0">

  <tlib-version>1.0</tlib-version>
  <short-name>myapp</short-name>
  <uri>https://myapp.example.com/tags</uri>

  <!-- ── Simple tag declaration ─────────────────────── -->
  <tag>
    <name>ifRole</name>
    <tag-class>com.example.tags.IfRoleTag</tag-class>
    <body-content>scriptless</body-content>
    <attribute>
      <name>role</name>
      <required>true</required>
      <rtexprvalue>true</rtexprvalue>
      <type>java.lang.String</type>
    </attribute>
  </tag>

  <!-- ── Tag with dynamic attributes ───────────────── -->
  <tag>
    <name>html</name>
    <tag-class>com.example.tags.HtmlTag</tag-class>
    <body-content>scriptless</body-content>
    <dynamic-attributes>true</dynamic-attributes>
    <attribute>
      <name>tag</name>
      <required>true</required>
      <rtexprvalue>true</rtexprvalue>
    </attribute>
  </tag>

  <!-- ── EL function declaration ────────────────────── -->
  <function>
    <name>formatCurrency</name>
    <function-class>com.example.ELFunctions</function-class>
    <function-signature>
      java.lang.String formatCurrency(java.math.BigDecimal, java.lang.String)
    </function-signature>
  </function>

</taglib>

TLD Element Notes

<uri> — logical identifier used in taglib directive uri=; need not be a real URL
<tag-class> — fully qualified class implementing Tag, SimpleTag, etc.
<body-content>empty</body-content> — tag must not have body content
<body-content>scriptless</body-content> — body allows EL and tags but not scriptlets; required for SimpleTag
<body-content>JSP</body-content> — body allows all JSP syntax including scriptlets; classic tags only
<body-content>tagdependent</body-content> — body is raw text; container does not process JSP/EL in it
<dynamic-attributes>true</dynamic-attributes> — tag class must implement DynamicAttributes

⚠ Common Mistakes

  • Using <body-content>JSP</body-content> for a SimpleTag — SimpleTag implementations cannot handle scriptlet body content; use scriptless
  • Mismatching the <uri> in the TLD with the uri= in the taglib directive — they must be identical strings; the container won't find the TLD
  • Forgetting <dynamic-attributes>true</dynamic-attributes> when the handler implements DynamicAttributes — unknown attributes will cause a translation error instead of being passed to the handler

✓ Tips

  • Package distributable tag libraries as a JAR with the TLD in META-INF/ — consumers just add the JAR to WEB-INF/lib/ and the container discovers the TLD automatically
  • Use a short-form <uri> like myapp.tags rather than a full URL — it's easier to type in taglib directives and doesn't imply a real HTTP resource
  • Validate your TLD against the Jakarta schema during build — malformed TLDs produce cryptic "cannot find taglib" errors at deploy time

Quick Summary

  • <uri> — logical name matching taglib directive uri=
  • <tag-class> — fully qualified handler class
  • <body-content>scriptless</body-content> — use for SimpleTag / tag files
  • <dynamic-attributes>true</dynamic-attributes> — enable DynamicAttributes
  • META-INF/*.tld in JAR — auto-discovered by container
