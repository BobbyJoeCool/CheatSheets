Implicit Objects — request & response

getParameter · getHeader · getMethod · setContentType · sendRedirect · HttpServletRequest

request & response Implicit Objects

Every JSP has nine implicit objects available without declaration — they are local variables in the generated _jspService() method. request is the HttpServletRequest for the current call; response is the HttpServletResponse. In practice, most view JSPs read from request and rarely touch response directly (the container handles headers). Output goes through the out implicit object, not response.getWriter().

Key Facts

  • request type: jakarta.servlet.http.HttpServletRequest
  • response type: jakarta.servlet.http.HttpServletResponse
  • Do not call response.getWriter() in a JSP — it conflicts with the container-managed JspWriter out
  • getParameter() returns null if the param is absent — always null-check or use a default
  • Calling response.sendRedirect() after output has begun throws an IllegalStateException

Common request & response Usage

<%-- ── Reading request parameters ──────────────────────── --%>
<%
    String name  = request.getParameter("name");       // null if absent
    String[] ids = request.getParameterValues("id");   // multi-value
    String q     = request.getParameter("q");
    if (q == null) q = "";
%>

<%-- ── Request metadata ─────────────────────────────────── --%>
<%= request.getMethod() %>            <%-- GET / POST --%>
<%= request.getRequestURI() %>        <%-- /myapp/home --%>
<%= request.getContextPath() %>       <%-- /myapp --%>
<%= request.getServletPath() %>       <%-- /home --%>
<%= request.getRemoteAddr() %>        <%-- client IP --%>

<%-- ── Reading headers ──────────────────────────────────── --%>
<%= request.getHeader("User-Agent") %>
<%= request.getHeader("Accept-Language") %>

<%-- ── Redirect (must be before any output) ─────────────── --%>
<%
    if (session.getAttribute("user") == null) {
        response.sendRedirect(request.getContextPath() + "/login");
        return;   // stop further processing
    }
%>

<%-- ── Setting response headers ─────────────────────────── --%>
<% response.setHeader("Cache-Control", "no-store"); %>

Method Notes

getParameter(name) — first value of named param; null if missing
getParameterValues(name) — all values of a multi-value param (checkboxes)
getParameterMap() — all params as Map<String,String[]>
getAttribute(name) — reads request-scope attribute set by a servlet
getContextPath() — prefix for all app URLs; use in hrefs
sendRedirect(url) — 302 response; must be before output; always return after
setHeader(name, value) — set response header; must be before output

⚠ Common Mistakes

  • Calling response.getWriter() in a JSP — the container already opened JspWriter out; a second writer throws IllegalStateException
  • Not calling return after sendRedirect() — the rest of the JSP continues executing, producing output after headers are committed
  • Building redirect URLs without request.getContextPath() — hardcoded paths break when the app is deployed under a different context
  • Displaying getParameter() output directly without escaping — user-controlled input rendered raw is an XSS vulnerability

✓ Tips

  • Always use ${pageContext.request.contextPath} (EL) or request.getContextPath() in href/src attributes — never hardcode the app prefix
  • Use response.encodeURL(url) on every internal link to support session tracking when cookies are disabled
  • Read parameters in the servlet, store results with request.setAttribute(), then forward to JSP — keeps JSP free of parameter-reading logic
  • Use <c:out value="${param.q}" /> instead of <%= request.getParameter("q") %> — auto-escapes HTML entities

Quick Summary

  • request — HttpServletRequest; read params, headers, attributes
  • response — HttpServletResponse; redirect, set headers
  • getParameter(name) — returns null if absent; always check
  • sendRedirect(url) — must precede output; always return after
  • getContextPath() — use in all absolute links inside JSPs
