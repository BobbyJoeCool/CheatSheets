Sheet 05

Include Directive

<%@ include %> · static include · translation-time merge · .jspf · vs jsp:include

Static Include at Translation Time

The include directive (<%@ include file="..." %>) copies the content of another file verbatim into the current JSP at translation time, before any Java is compiled. The result is a single merged servlet. Variables declared in the included file are visible in the including page because they become part of the same Java method. This is ideal for shared headers, footers, and navigation fragments.

Key Facts

  • Inclusion happens at translation time — the included file is pasted in before compilation
  • Fragment files conventionally use .jspf extension (JSP Fragment) to signal they are not standalone pages
  • The file attribute is always a context-relative path (starts with /) or page-relative path — no runtime expression allowed
  • Variables declared in included fragments are visible to the including page — they merge into the same _jspService()
  • If the fragment changes, the including page must be re-translated — touch the parent file or restart

Include Directive Usage

<%-- page-relative path --%>
<%@ include file="header.jspf" %>

<%-- context-relative path (starts with /) --%>
<%@ include file="/WEB-INF/fragments/nav.jspf" %>

<%-- The included fragment can use variables from the parent
     because they merge into the same _jspService() --%>

Code Notes

file — path resolved at translation time; no runtime expressions, no query strings
.jspf — conventional extension; signals "not a standalone page"; configure your IDE accordingly
Fragment inherits the parent's implicit objects — request, session, out etc. are all available
Avoid duplicate <%@ page %> directives across parent + fragment — same attribute twice is a translation error
${pageContext.request.contextPath} — use this for absolute links inside fragments so paths work regardless of URL depth

⚠ Common Mistakes

  • Declaring contentType in both the parent page and the included fragment — duplicate page directive attributes cause a translation error
  • Expecting changes to a fragment to take effect without re-translating the parent — the container only watches the top-level .jsp file for changes in many configurations
  • Using a runtime EL expression in the file attribute — file="${path}" is illegal; use <jsp:include page="${path}"> instead
  • Putting a <!doctype> declaration in every included fragment — it ends up duplicated in the response when multiple fragments are included

✓ Tips

  • Store all fragments under WEB-INF/fragments/ using .jspf extension — keeps them protected and clearly distinguished from full pages
  • Use ${pageContext.request.contextPath} for all absolute resource paths in fragments — works correctly regardless of which page includes the fragment
  • Extract the <%@ page contentType ... %> directive into only one file (the top-level page) — fragments should omit it entirely
  • Configure your server to auto-detect changes to included files: set modificationTestInterval=0 in Tomcat's context.xml during development

Quick Summary

  • <%@ include file="..." %> — pastes file content at translation time
  • .jspf — conventional extension for non-standalone fragments
  • Shared scope — included file sees parent's variables; they become one servlet
  • No runtime paths — file must be a literal string, not an expression
  • Use <jsp:include> instead when the path is dynamic or changes often
