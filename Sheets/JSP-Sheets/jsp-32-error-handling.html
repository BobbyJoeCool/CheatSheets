Error Handling & Security Output

errorPage · isErrorPage · <error-page> · exception implicit · XSS · c:out · fn:escapeXml · CSP

Error Pages & Secure Output

JSP provides two mechanisms for error handling: per-page errorPage directives and global <error-page> entries in web.xml. The web.xml approach is strongly preferred — it covers all exceptions and HTTP status codes from one place. On the security side, every piece of data rendered in a JSP that originated from user input or a database must be HTML-escaped to prevent cross-site scripting (XSS). Use <c:out> or fn:escapeXml() for all such output.

Key Facts

  • <error-page> in web.xml handles all JSPs and servlets — the per-page errorPage attribute only covers that one JSP
  • The exception implicit object is only available when <%@ page isErrorPage="true" %> is set
  • Bare ${} EL does NOT HTML-escape — always use <c:out> for user-supplied or database data
  • XSS via EL: ${param.name} renders <script> tags literally if not escaped
  • Set Content-Security-Policy response header to restrict script sources — defence-in-depth alongside output escaping

Error Pages & Secure Output Patterns

<!-- web.xml — global error page declarations -->
<error-page>
  <exception-type>java.lang.Exception</exception-type>
  <location>/WEB-INF/jsp/error.jsp</location>
</error-page>
<error-page>
  <error-code>404</error-code>
  <location>/WEB-INF/jsp/404.jsp</location>
</error-page>
<error-page>
  <error-code>403</error-code>
  <location>/WEB-INF/jsp/403.jsp</location>
</error-page>
<%-- ── error.jsp — the error page itself ─────────────────── --%>
<%@ page isErrorPage="true" pageEncoding="UTF-8"
         contentType="text/html; charset=UTF-8" %>
<%@ taglib prefix="c" uri="jakarta.tags.core" %>
<!doctype html>
<html><head><title>Error</title></head><body>
<h1>Something went wrong</h1>
<%-- exception implicit object available here --%>
<p>Reference: ${pageContext.errorData.requestURI}</p>
<% if (exception != null) {
       application.log("Unhandled error", exception); } %>
</body></html>

<%-- ── Per-page error page (less preferred) ───────────────── --%>
<%@ page errorPage="/WEB-INF/jsp/error.jsp" %>

<%-- ── SECURE OUTPUT — always escape user data ───────────── --%>
<%@ taglib prefix="c"  uri="jakarta.tags.core"      %>
<%@ taglib prefix="fn" uri="jakarta.tags.functions" %>

<%-- WRONG — XSS vulnerable --%>
Hello, ${param.name}!

<%-- RIGHT — use c:out (escapes by default) --%>
Hello, <c:out value="${param.name}" />!

<%-- RIGHT — use fn:escapeXml in EL context --%>
<input value="${fn:escapeXml(param.name)}">

<%-- Set CSP header to restrict script sources --%>
<% response.setHeader("Content-Security-Policy",
       "default-src 'self'; script-src 'self'"); %>

<%-- HTTP-only, Secure cookies --%>
<% Cookie c = new Cookie("sessionId", token);
   c.setHttpOnly(true);
   c.setSecure(true);
   response.addCookie(c); %>

Notes

<error-page><exception-type> — catches that exception type and all subclasses
<error-page><error-code>404</error-code> — catches HTTP status 404 from any servlet or JSP
isErrorPage="true" — required to access exception implicit object
pageContext.errorData — available on web.xml error pages; has requestURI, statusCode, throwable
<c:out value="${x}"> — escapes < > & " '; safest default for all output
fn:escapeXml(s) — use inside EL attribute values where c:out can't be placed
HttpOnly + Secure cookie flags — prevent JS access to session cookie; force HTTPS

⚠ Common Mistakes

  • Outputting ${param.x} directly — EL does not escape HTML; any value containing <script> is rendered as executable JavaScript in the browser
  • Relying on per-page errorPage for all error handling — exceptions from servlets, filters, and other JSPs bypass it; use <error-page> in web.xml
  • Printing the exception stack trace to the response on production systems — exposes internal class names, library versions, and file paths that attackers can use for targeted exploits

✓ Tips

  • Make <c:out> the default for every data value in JSPs — only omit it for values you generate yourself (counters, formatted numbers, constants)
  • Log exceptions server-side with application.log("msg", exception) or a proper logging framework; show only a friendly message and a reference code to the user
  • Set security headers (CSP, X-Frame-Options, HSTS) in a servlet Filter applied to all responses — centralizes security policy in one place

Quick Summary

  • <error-page> in web.xml — global; covers exceptions and HTTP codes
  • isErrorPage="true" — enables exception implicit object
  • <c:out value="${x}"> — HTML-escape all user/DB data; default habit
  • fn:escapeXml(x) — use inside EL attribute contexts
  • HttpOnly + Secure cookie flags — protect session cookie from JS and HTTP
