Sheet 18

jsp:include & jsp:forward

jsp:include · jsp:forward · page · flush · RequestDispatcher · dynamic path · jsp:param

Runtime Dispatch Actions

<jsp:include> and <jsp:forward> are standard action tags that use the servlet container's RequestDispatcher at request time. Unlike the <%@ include %> directive (translation time), these resolve the path dynamically — the page attribute can contain an EL expression. include merges another resource's output into the current response; forward hands control to another resource and stops the current page.

Key Facts

  • <jsp:include> runs the included resource as a separate servlet; it gets its own page scope
  • <jsp:forward> immediately halts the current page — no more output after it
  • The page attribute supports EL expressions and runtime values — unlike <%@ include %>
  • <jsp:param> children pass additional request parameters to the dispatched resource
  • flush="true" on <jsp:include> flushes the buffer before including — response headers are then committed

Code Notes

page — context-relative path or EL expression; resolved at request time
<jsp:param> — adds to (not replaces) the current request's parameters; readable via request.getParameter() in the target
flush="true" — commits buffer; prevents setting headers after include; default is false
<jsp:forward> — uses RequestDispatcher.forward(); execution of current JSP stops immediately
Request attributes survive both include and forward — set them on request before dispatching

include & forward Syntax

<%-- ── jsp:include — merges output at runtime ────────────── --%>

<%-- Static path --%>
<jsp:include page="/WEB-INF/jsp/header.jsp" />

<%-- Dynamic path via EL --%>
<jsp:include page="${widget.templatePath}" />

<%-- With extra parameters --%>
<jsp:include page="/WEB-INF/jsp/sidebar.jsp">
    <jsp:param name="section" value="news" />
    <jsp:param name="limit"   value="5" />
</jsp:include>

<%-- flush=true: commit buffer before including --%>
<%-- Use only when you are certain no headers need setting after --%>
<jsp:include page="/WEB-INF/jsp/footer.jsp" flush="true" />

<%-- ── jsp:forward — delegate to another resource ─────────── --%>

<%-- Forward to a JSP --%>
<jsp:forward page="/WEB-INF/jsp/result.jsp" />

<%-- Forward with extra params (readable via request.getParameter) --%>
<jsp:forward page="/WEB-INF/jsp/error.jsp">
    <jsp:param name="code"    value="404" />
    <jsp:param name="message" value="Not Found" />
</jsp:forward>

<%-- Conditional forward (common pattern) --%>
<%
    if (session.getAttribute("user") == null) {
%>
<jsp:forward page="/WEB-INF/jsp/login.jsp" />
<%
    }
%>

⚠ Common Mistakes

  • Writing output after <jsp:forward> — the forward takes effect immediately but the remaining JSP code still compiles and may produce buffered output that garbles the response
  • Using flush="true" and then trying to set response headers or cookies — once flushed, the response is committed and headers cannot be changed
  • Expecting included pages to inherit page-scope variables — each <jsp:include> target has its own page scope; use request attributes to share data

✓ Tips

  • After <jsp:forward>, add a <% return; %> scriptlet — makes the intent explicit and silences IDE warnings about unreachable code
  • Use <jsp:include> for reusable widgets (pagination bars, sidebars) — they can be tested independently as standalone JSPs
  • Set request attributes before forwarding/including rather than using <jsp:param> for complex data — params are strings only; attributes carry typed objects

Quick Summary

  • <jsp:include> — inserts resource output; current page continues
  • <jsp:forward> — delegates entirely; current page stops
  • page attr — supports runtime EL expressions
  • <jsp:param> — adds string params; use request attrs for objects
  • Request attributes travel across both include and forward
