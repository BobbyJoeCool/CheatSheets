Sheet 03

Page Directive

<%@ page %> · contentType · import · session · errorPage · isELIgnored · buffer

What the Page Directive Does

The page directive (<%@ page %>) configures the JSP page itself — it controls how the container translates and executes the page. It is processed at translation time, not at request time, so its attributes affect the generated servlet class, not individual responses. A page can have multiple page directives, but each attribute may only appear once (except import).

Key Facts

  • Processed at translation time — changing an attribute requires a file touch or server restart to take effect
  • import is the only attribute that can appear multiple times; all others are once-per-page
  • Place the page directive at the very top of the file, before any output, to avoid accidental whitespace in the response headers
  • Default contentType is text/html;charset=ISO-8859-1 — always override to UTF-8
  • EL is enabled by default in JSP 2.0+; set isELIgnored="true" only for legacy pages

Common Page Directive Patterns

<%-- Minimal recommended header for every JSP --%>
<%@ page language="java"
         contentType="text/html; charset=UTF-8"
         pageEncoding="UTF-8" %>

<%-- Import one or more Java classes --%>
<%@ page import="java.util.List, java.util.ArrayList" %>
<%@ page import="com.example.model.User" %>  <%-- can repeat --%>

<%-- Disable session creation (read-only pages) --%>
<%@ page session="false" %>

<%-- Designate an error page --%>
<%@ page errorPage="/WEB-INF/jsp/error.jsp" %>

<%-- Mark a page as the error handler --%>
<%@ page isErrorPage="true" %>

<%-- Control response buffering --%>
<%@ page buffer="16kb" autoFlush="true" %>

<%-- Disable EL (legacy JSP 1.x pages only) --%>
<%@ page isELIgnored="true" %>

<%-- Strip whitespace from directive lines --%>
<%@ page trimDirectiveWhitespaces="true" %>

Attribute Notes

language — always "java"; only valid value
contentType — sets Content-Type response header; always set UTF-8
pageEncoding — tells the container how to read the source file; set to match your editor
import — generates Java import statements; comma-separated or repeated
session="false" — prevents HttpSession creation; removes session implicit object
errorPage — URL to forward to on unhandled exception (must be app-relative)
isErrorPage="true" — enables the exception implicit object on this page
buffer — size of output buffer; "none" disables buffering

⚠ Common Mistakes

  • Omitting pageEncoding="UTF-8" and contentType="text/html; charset=UTF-8" — the default ISO-8859-1 breaks non-ASCII characters silently
  • Using errorPage with an absolute URL starting with http:// — it must be a context-relative path starting with /
  • Setting autoFlush="false" without increasing buffer — a buffer overflow throws an IOException instead of flushing
  • Forgetting to set isErrorPage="true" on the error page itself — without it, the exception implicit object is null

✓ Tips

  • Create a shared header fragment with the standard page directive and include it in every JSP with <%@ include file="header.jspf" %>
  • Use trimDirectiveWhitespaces="true" on pages that return JSON or XML — directive whitespace pollutes the response body
  • Prefer <error-page> in web.xml over per-page errorPage attribute — one central declaration covers all JSPs
  • Never use isThreadSafe="false" — it implements SingleThreadModel, which is deprecated and causes severe performance problems

Quick Summary

  • <%@ page %> — configures translation; processed once, not per-request
  • import — only repeatable attribute; adds Java imports
  • contentType + pageEncoding — always set both to UTF-8
  • errorPage / isErrorPage — wire JSPs to an error handler
  • session="false" — skip session for stateless/read-only pages
