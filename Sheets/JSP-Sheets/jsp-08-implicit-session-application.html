Sheet 08

Implicit Objects — session & application

HttpSession · setAttribute · invalidate · getServletContext · session timeout · context-wide state

session & application

session is the HttpSession for the current user — it persists across multiple requests from the same browser. application is the ServletContext — it is shared across all users and all JSPs in the entire web application for its lifetime. Use session for per-user state (login, cart) and application for app-wide configuration or shared caches.

Key Facts

  • session type: jakarta.servlet.http.HttpSession
  • application type: jakarta.servlet.ServletContext
  • session is unavailable when <%@ page session="false" %> is set
  • application attributes are shared across all threads — always synchronize writes
  • Session timeout defaults to 30 minutes; configurable in web.xml via <session-timeout>
  • Session is tracked via cookie (JSESSIONID) or URL rewriting — use response.encodeURL() for URL rewriting support

session & application Usage

<%-- ── Session: store and retrieve user data ─────────────── --%>
<%
    // Write (typically done in the servlet, not the JSP)
    session.setAttribute("user", userObject);
    session.setAttribute("cartSize", 3);
%>

<%-- Read in JSP via EL (preferred) --%>

Welcome, ${sessionScope.user.name}


Cart: ${sessionScope.cartSize} items


<%-- Read via scriptlet --%>
<% User u = (User) session.getAttribute("user"); %>

<%-- Session metadata --%>
<%= session.getId() %>              <%-- JSESSIONID value --%>
<%= session.isNew() %>              <%-- true on first request --%>
<%= session.getMaxInactiveInterval() %> <%-- timeout in seconds --%>

<%-- Invalidate on logout --%>
<%
    session.invalidate();
    response.sendRedirect(request.getContextPath() + "/login");
    return;
%>

<%-- ── Application: app-wide shared state ────────────────── --%>
<%
    // Read a context init param (from web.xml )
    String apiUrl = application.getInitParameter("api.base.url");

    // Store/read app-wide attribute
    application.setAttribute("appVersion", "2.1.0");
%>

API: ${applicationScope.appVersion}


Real path: <%= application.getRealPath("/WEB-INF/config.xml") %>

Method Notes

session.setAttribute(k,v) — stores object under key for this user
session.getAttribute(k) — retrieves; returns null if absent
session.removeAttribute(k) — deletes one attribute
session.invalidate() — destroys session; all attributes lost
session.setMaxInactiveInterval(sec) — override timeout for this session
application.getInitParameter(k) — reads <context-param> from web.xml
application.getRealPath(path) — converts web path to filesystem path

⚠ Common Mistakes

  • Accessing session on a page with <%@ page session="false" %> — the variable doesn't exist, causing a compile error
  • Writing to application attributes from multiple threads without synchronization — ServletContext is not thread-safe for concurrent writes
  • Not calling session.invalidate() on logout — the old session (and its attributes) persist until timeout, a security risk
  • Storing non-serializable objects in session — causes NotSerializableException if the container persists sessions to disk for failover

✓ Tips

  • Access session data in JSP via EL ${sessionScope.key} — cleaner than a scriptlet cast and null-safe
  • Set <%@ page session="false" %> on all pages that don't need it — avoids unnecessary session creation and improves scalability
  • Use application.getInitParameter() for environment-specific config (base URLs, feature flags) — change web.xml without touching JSP code
  • Keep session attributes minimal and serializable — large session payloads hurt clustering and memory

Quick Summary

  • session — per-user state; HttpSession; persists across requests
  • application — app-wide state; ServletContext; shared by all users
  • session.invalidate() — destroys session; call on logout
  • application.getInitParameter() — reads context-param from web.xml
  • ${sessionScope.key} — EL access to session attributes
