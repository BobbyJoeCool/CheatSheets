JSTL Setup & Library Overview

JSTL 3.x · Jakarta EE 10 · JAR dependency · taglib URI · c: · fmt: · fn: · sql: · x:

What JSTL Is

The Jakarta Standard Tag Library (JSTL) is a set of tag libraries that replaces scriptlets for the most common JSP tasks: iteration, conditionals, output escaping, URL building, number and date formatting, and string functions. JSTL is not bundled with the servlet container — you must add the JAR. JSTL 3.x targets Jakarta EE 9+ (package jakarta.*); JSTL 1.2 targets older javax.* stacks.

Key Facts

  • JSTL 3.x artifact: org.glassfish.web:jakarta.servlet.jsp.jstl:3.0.1
  • Also need the API JAR: jakarta.servlet.jsp.jstl:jakarta.servlet.jsp.jstl-api:3.0.0
  • Both JARs go in WEB-INF/lib/ — the container does not supply JSTL
  • Jakarta EE 9+ uses short-form URIs: jakarta.tags.core etc.
  • Legacy javax stacks use http://java.sun.com/jsp/jstl/core URIs

Maven Dependencies & Taglib Declarations

/* pom.xml — Jakarta EE 10 / JSTL 3.x */
<dependency>
  <groupId>org.glassfish.web</groupId>
  <artifactId>jakarta.servlet.jsp.jstl</artifactId>
  <version>3.0.1</version>
</dependency>
<dependency>
  <groupId>jakarta.servlet.jsp.jstl</groupId>
  <artifactId>jakarta.servlet.jsp.jstl-api</artifactId>
  <version>3.0.0</version>
</dependency>
<%-- Taglib declarations — Jakarta EE 9+ short URIs --%>
<%@ taglib prefix="c"   uri="jakarta.tags.core"      %>
<%@ taglib prefix="fmt" uri="jakarta.tags.fmt"       %>
<%@ taglib prefix="fn"  uri="jakarta.tags.functions" %>
<%@ taglib prefix="sql" uri="jakarta.tags.sql"       %>
<%@ taglib prefix="x"   uri="jakarta.tags.xml"       %>

<%-- Legacy javax URIs (JSTL 1.2 / pre-Jakarta EE 9) --%>
<%@ taglib prefix="c"   uri="http://java.sun.com/jsp/jstl/core"      %>
<%@ taglib prefix="fmt" uri="http://java.sun.com/jsp/jstl/fmt"       %>
<%@ taglib prefix="fn"  uri="http://java.sun.com/jsp/jstl/functions" %>

<%-- Recommended: one shared fragment declares all taglibs --%>
<%-- taglibs.jspf — include this at top of every JSP     --%>
<%@ include file="/WEB-INF/fragments/taglibs.jspf" %>

Setup Notes

Both JARs required — API jar provides interfaces; impl jar provides the actual tag handlers
Short URI jakarta.tags.core — works only with JSTL 3.x JARs whose TLD declares this URI
Scope: compile (or runtime) — container does not provide JSTL
TLD discovery — container finds TLDs inside WEB-INF/lib/*.jar META-INF automatically
Shared fragment — declare all taglibs once in taglibs.jspf; use static include in every page

⚠ Common Mistakes

  • Using JSTL 3.x short URIs (jakarta.tags.core) with JSTL 1.2 JARs — the TLD in the old JAR does not register the short URI; the container reports "cannot find taglib"
  • Placing JSTL JARs in Tomcat's lib/ directory instead of WEB-INF/lib/ — works locally but breaks when the WAR is deployed to a different container that doesn't have them
  • Mixing javax and jakarta JSTL JARs in the same WAR — class-name conflicts cause ClassCastException at runtime when tag handlers are instantiated

✓ Tips

  • Create a taglibs.jspf fragment with all taglib declarations and include it at the top of every JSP — one change updates all pages
  • Avoid sql: and x: libraries in production — sql: bypasses the data access layer; x: is rarely needed; both belong in prototypes only
  • Check the TLD URI by opening the JSTL JAR and reading META-INF/*.tld — the <uri> element is the exact string your taglib directive must use

Quick Summary

  • JSTL not bundled — add both API and impl JARs to WEB-INF/lib/
  • JSTL 3.x / Jakarta EE 10 — short URIs: jakarta.tags.core etc.
  • c: core · fmt: formatting · fn: string functions
  • Match JSTL JAR version to Jakarta EE version — don't mix javax/jakarta
  • Shared taglibs.jspf — declare all prefixes once, include everywhere
