Session & Application Scope

sessionScope · applicationScope · cross-request state · invalidate · concurrent access · context attributes

Longer-Lived Scopes

Session scope persists across multiple requests from the same browser until the session times out or is invalidated — it is the right place for per-user state like login identity, shopping carts, and preferences. Application scope persists for the entire lifetime of the web application and is shared by every user simultaneously — use it only for truly global, read-mostly data like configuration values, lookup tables, or shared caches.

Key Facts

  • Session scope is per-user; application scope is per-application (all users share it)
  • Application-scope writes from multiple threads require synchronization — the container does not lock for you
  • Objects stored in session must be Serializable if the container persists or replicates sessions
  • EL accesses via ${sessionScope.key} and ${applicationScope.key}
  • Session is identified by a JSESSIONID cookie (or URL param); never expose this value in pages

Session & Application Scope Patterns

<%-- ── Session scope: per-user state ────────────────────── --%>

<%-- Write (done in servlet after successful login) --%>
<%
    session.setAttribute("currentUser", user);
    session.setAttribute("role", "ADMIN");
    session.setMaxInactiveInterval(1800); // 30 min
%>

<%-- Read in JSP --%>

Logged in as: ${sessionScope.currentUser.fullName}


    Admin Panel


<%-- Logout: destroy session --%>
<%
    session.invalidate();
    response.sendRedirect(request.getContextPath() + "/login");
    return;
%>

<%-- ── Application scope: app-wide shared data ───────────── --%>

<%-- Write once at startup (in a ServletContextListener, not JSP) --%>
<%
    // Reading is fine in JSP; writing should be done in a listener
    String version = (String) application.getAttribute("appVersion");
    Integer visits  = (Integer) application.getAttribute("visitCount");
%>

<%-- EL read --%>

Version: ${applicationScope.appVersion}


<%-- Read init param from web.xml  --%>
<%= application.getInitParameter("supportEmail") %>

Code Notes

session.setAttribute(k,v) — stores for this user across requests
session.invalidate() — destroys all session data; use on logout
setMaxInactiveInterval(sec) — override idle timeout per session
application.getAttribute(k) — shared across ALL users; read is safe
application.getInitParameter(k) — reads <context-param> from web.xml; read-only after startup
Write to application scope only from ServletContextListener.contextInitialized() to avoid threading issues

⚠ Common Mistakes

  • Writing mutable counters to application scope from JSP scriptlets — concurrent requests produce race conditions; use a ServletContextListener or synchronized block
  • Storing large objects (full result sets, byte arrays) in session — each user's session holds this in memory; it degrades performance under load
  • Not invalidating the session on logout — the old session token remains valid until timeout, leaving the account accessible
  • Storing non-serializable objects in session — works until the container tries to persist or replicate sessions, then throws NotSerializableException

✓ Tips

  • Initialize application-scope data in a ServletContextListener (contextInitialized) — runs once at startup, thread-safe, no JSP scriptlet required
  • After login, call request.getSession(false) and then invalidate() and request.getSession(true) to rotate the session ID and prevent session fixation
  • Keep session payloads small — store only a user ID in session and re-fetch user data from the database per-request
  • Set <session-config><session-timeout>30</session-timeout></session-config> in web.xml rather than hardcoding it in JSPs

Quick Summary

  • session scope — per-user; persists across requests; use for login state
  • application scope — all users; app lifetime; use for config/caches
  • session.invalidate() — required on logout for security
  • ${sessionScope.key} / ${applicationScope.key} — EL access
  • Application scope writes — synchronize or use a listener
