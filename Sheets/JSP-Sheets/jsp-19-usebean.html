jsp:useBean · id · class · scope · jsp:setProperty · property="*" · jsp:getProperty · param auto-bind

Bean Wiring Without Scriptlets

<jsp:useBean> locates or creates a JavaBean in a specified scope, then assigns it to a scripting variable. <jsp:setProperty> sets one or more bean properties — with property="*" it automatically maps all matching request parameters to bean properties. <jsp:getProperty> reads and outputs a single property. These actions bridge request parameters to JavaBeans without Java scriptlets.

Key Facts

  • <jsp:useBean> looks in the specified scope first — only creates a new instance if none exists
  • The bean class must have a public no-arg constructor and follow JavaBean conventions
  • property="*" auto-maps request params to bean properties by matching name; type conversion is automatic
  • The bean body executes only when a new bean was created — not when reusing an existing one
  • Modern practice: prefer setting beans in the servlet via request.setAttribute() and reading via EL in JSP

Attribute Notes

id — scripting variable name; also the scope attribute key
class — fully qualified concrete class; must have no-arg constructor
type — declares the variable type (interface/superclass); use with class or alone when bean already exists in scope
scope — page | request | session | application; default is page
property="*" — auto-bind: maps each request param to setter by name with type coercion
param — use when param name differs from property name
Bean body — the content between open/close tags runs only when a new instance is created

⚠ Common Mistakes

  • Using property="*" without validating request parameters first — it blindly maps any param to a setter, allowing attackers to set unexpected properties (mass-assignment vulnerability)
  • Assuming the bean body always runs — it only executes when a new instance is created; if the bean already exists in the scope, the body is skipped silently
  • Using type alone (without class) when no bean exists in scope — throws an InstantiationException because there is nothing to instantiate

✓ Tips

  • In modern MVC, set beans in the servlet via request.setAttribute() and read them in JSP via EL — <jsp:useBean> is mainly useful in simpler or legacy page-centric patterns
  • Use type instead of class when the bean is already placed in scope by a servlet — avoids unnecessary second-class creation attempt
  • Never use property="*" for user-facing forms without a whitelist of allowed properties — always explicitly name each property

Quick Summary

  • <jsp:useBean> — find or create bean in scope; id becomes EL variable
  • Bean body — runs only when a new instance is created
  • property="*" — auto-bind all matching request params to setters
  • <jsp:getProperty> — outputs one property; EL preferred
  • Modern pattern: set in servlet → read via EL in JSP
