Sheet 14

EL Implicit Objects

pageScope · requestScope · sessionScope · applicationScope · param · paramValues · header · cookie · initParam · pageContext

EL's Built-In Map Objects

EL provides eleven implicit objects — all available inside ${} without any declaration. They are all read-only Maps (except pageContext, which is the PageContext object). The scope maps give direct access to attributes in each scope; the others give access to request parameters, headers, cookies, and init params. They mirror what the Java implicit objects provide but without scriptlets.

Key Facts

  • All EL implicit objects except pageContext are Map instances
  • param returns a single String; paramValues returns String[]
  • header / headerValues — same pattern as param/paramValues
  • cookie values are Cookie objects — access value via ${cookie.name.value}
  • initParam reads <context-param> from web.xml — same as application.getInitParameter()

EL Implicit Object Usage

<%-- ── Scope maps ────────────────────────────────────────── --%>
${pageScope.localVar}           <%-- page-scope attribute --%>
${requestScope.products}        <%-- request-scope attribute --%>
${sessionScope.currentUser}     <%-- session-scope attribute --%>
${applicationScope.appVersion}  <%-- application-scope attribute --%>

<%-- ── Request parameters ───────────────────────────────── --%>
${param.q}                      <%-- request.getParameter("q") --%>
${param["page-num"]}            <%-- param with hyphen in name --%>
${paramValues.ids}              <%-- String[] — multi-value param --%>
${paramValues.ids[0]}           <%-- first value of multi-param --%>

<%-- ── Request headers ──────────────────────────────────── --%>
${header["User-Agent"]}         <%-- bracket required (hyphen) --%>
${header["Accept-Language"]}
${headerValues["Accept"][0]}    <%-- first Accept header value --%>

<%-- ── Cookies ──────────────────────────────────────────── --%>
${cookie.JSESSIONID.value}      <%-- cookie value --%>
${cookie.theme.value}           <%-- custom cookie --%>
${cookie.theme.maxAge}          <%-- cookie max-age --%>

<%-- ── Context init params (web.xml ) ─────── --%>
${initParam["support.email"]}
${initParam.appName}

<%-- ── pageContext object ───────────────────────────────── --%>
${pageContext.request.contextPath}   <%-- /myapp --%>
${pageContext.request.method}        <%-- GET / POST --%>
${pageContext.session.id}            <%-- JSESSIONID --%>
${pageContext.servletContext.serverInfo} <%-- e.g. Apache Tomcat/10.1 --%>

Notes

param.name — single value; equivalent to request.getParameter("name")
paramValues.name — String[]; use [0] to get first element
header["X-Name"] — bracket required for headers with hyphens
cookie.name — returns the Cookie object; chain .value for the string value
initParam.key — reads <context-param>; dot notation only if key has no special chars
pageContext — the only non-Map EL implicit object; gives access to the full PageContext API

⚠ Common Mistakes

  • Writing ${cookie.name} and expecting the string value — it returns the Cookie object; you need ${cookie.name.value}
  • Using dot notation for headers: ${header.User-Agent} — EL parses the hyphen as subtraction; always use ${header["User-Agent"]}
  • Displaying ${param.input} directly — EL does not escape HTML; user-supplied values can inject script tags

✓ Tips

  • Use ${pageContext.request.contextPath} in every href and src attribute — it is the safest and cleanest way to build portable links in JSPs
  • Prefer ${requestScope.key} over bare ${key} when you know the scope — prevents accidental resolution from a wider scope
  • Read ${initParam.configKey} in JSPs for display-only config values; keep business config in Java service classes

Quick Summary

  • param / paramValues — request params; single vs multi-value
  • header["Name"] — use brackets; headers contain hyphens
  • cookie.name.value — chain .value to get string from Cookie object
  • initParam.key — reads <context-param> from web.xml
  • pageContext — sole non-Map; full PageContext API available
