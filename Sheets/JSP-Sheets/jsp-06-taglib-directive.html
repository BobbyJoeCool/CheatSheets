Sheet 06

Taglib Directive

<%@ taglib %> · uri · prefix · TLD · JSTL URIs · JAR scanning · multiple taglibs

Declaring a Tag Library

The taglib directive (<%@ taglib %>) imports a tag library into the current JSP page and assigns it a prefix. After the directive, tags from that library are available as <prefix:tagname>. The uri attribute is a logical identifier — not a literal URL — that the container resolves against TLD files found in WEB-INF/ or inside JARs in WEB-INF/lib/.

Key Facts

  • The uri is a logical name, not a network address — the container looks it up in TLD files
  • TLDs are discovered automatically from JARs in WEB-INF/lib/ and files in WEB-INF/
  • Prefix is arbitrary but conventional — use c: for JSTL core, fmt: for formatting
  • A page can declare multiple taglibs with different prefixes
  • Jakarta EE 10 changed URIs from http://java.sun.com/jsp/jstl/… to jakarta.tags.*

Taglib Directive Usage

<%-- ── Jakarta EE 10 / JSTL 3.x URIs (current) ─────────── --%>
<%@ taglib prefix="c"   uri="jakarta.tags.core" %>
<%@ taglib prefix="fmt" uri="jakarta.tags.fmt" %>
<%@ taglib prefix="fn"  uri="jakarta.tags.functions" %>
<%@ taglib prefix="sql" uri="jakarta.tags.sql" %>
<%@ taglib prefix="x"   uri="jakarta.tags.xml" %>

<%-- ── Legacy javax / JSTL 1.x URIs (pre-Jakarta EE 9) ─── --%>
<%@ taglib prefix="c"   uri="http://java.sun.com/jsp/jstl/core" %>
<%@ taglib prefix="fmt" uri="http://java.sun.com/jsp/jstl/fmt" %>
<%@ taglib prefix="fn"  uri="http://java.sun.com/jsp/jstl/functions" %>

<%-- ── Custom tag library (TLD in WEB-INF/) ──────────────── --%>
<%@ taglib prefix="my"  uri="/WEB-INF/tlds/mytags.tld" %>

<%-- ── Tag file library (directory in WEB-INF/tags/) ─────── --%>
<%@ taglib prefix="ui"  tagdir="/WEB-INF/tags/ui" %>

<%-- After declaration, use as:  --%>

    
${fn:escapeXml(p.name)}

Code Notes

uri="jakarta.tags.core" — short-form URI used in JSTL 3.x / Jakarta EE 10+
uri="http://java.sun.com/..." — legacy full URI; still works if using javax JSTL JARs
tagdir="/WEB-INF/tags/..." — use instead of uri for tag file directories; mutually exclusive
prefix — any valid XML name; convention is the standard short form (c, fmt, fn)
TLD auto-discovery — container scans WEB-INF/lib/*.jar META-INF for .tld files on startup

TLD Resolution Order

LocationHow Resolved
WEB-INF/lib/*.jarContainer scans META-INF/*.tld inside each JAR
WEB-INF/*.tldDirect file path in uri attribute

Implicit (container)jsp: prefix always available — no taglib needed

⚠ Common Mistakes

  • Using Jakarta short URIs (jakarta.tags.core) with the old javax.servlet.jsp.jstl JAR — the URIs must match what the JAR's TLD declares
  • Omitting the taglib directive but still using <c:forEach> — the tag is treated as unknown XML and either errors or renders literally
  • Using tagdir and uri together on the same directive — they are mutually exclusive; the container rejects the page
  • Placing the JSTL JAR in tomcat/lib/ instead of WEB-INF/lib/ — it may work in one container version but breaks portability

✓ Tips

  • Declare all taglibs at the top of each JSP before any output — directives after template text can cause whitespace issues in some containers
  • Extract repeated taglib declarations into a shared fragment (taglibs.jspf) and include it with <%@ include %> in every page
  • Match your JSTL JAR version to your Jakarta EE version — JSTL 3.x for Jakarta EE 9+, JSTL 1.2 for older javax stacks
  • Use tagdir (not uri) for tag file libraries in WEB-INF/tags/ — no TLD file required for tag files

Quick Summary

  • <%@ taglib prefix="c" uri="jakarta.tags.core" %> — import JSTL core
  • uri — logical name; resolved against TLDs in JARs/WEB-INF
  • tagdir — use for WEB-INF/tags/ tag file libraries instead of uri
  • Jakarta EE 9+ — short URIs (jakarta.tags.*); legacy uses full URLs
  • TLD discovery — automatic from META-INF/*.tld in WEB-INF/lib/ JARs
