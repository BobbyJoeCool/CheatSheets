Sheet 22

JSTL Conditionals

c:if · c:choose · c:when · c:otherwise · c:set · c:remove · c:catch · test attribute

Branching Without Scriptlets

JSTL core provides two conditional constructs. <c:if> is a simple one-way test — there is no else branch; use two <c:if> tags with opposite conditions, or use <c:choose>. <c:choose> / <c:when> / <c:otherwise> is the multi-way branch equivalent of Java's if/else if/else. All conditions are EL expressions evaluated to boolean.

Key Facts

  • <c:if test="${expr}"> — body renders only when test is true; no else branch
  • var attribute on <c:if> stores the boolean result in scope for later reuse
  • <c:choose> requires at least one <c:when>; <c:otherwise> is optional but must be last
  • <c:set> stores a value in any scope; <c:remove> deletes it
  • <c:catch var="e"> catches any Throwable from its body — prevents error page for non-fatal exceptions

Tag Notes

test — EL boolean expression; uses EL type coercion (null→false, ""→false)
var on c:if — saves boolean result; re-use later without re-evaluating
scope — page|request|session|application; default is page
<c:set var="x" value="${expr}"> — equivalent to scope.setAttribute("x", expr)
<c:set target="${bean}" property="p" value="v"> — calls bean setter
<c:remove> — removes attribute; if no scope specified, removes from all scopes
<c:catch var="e"> — e is the Throwable; null if no exception occurred

⚠ Common Mistakes

  • Looking for a <c:else> tag — it doesn't exist; use <c:choose><c:when><c:otherwise> for if/else
  • Placing content directly inside <c:choose> that is not a <c:when> or <c:otherwise> — whitespace is silently ignored but other content causes a tag error
  • Using <c:set> with both var and target at the same time — they are mutually exclusive; var sets a scope attribute, target calls a setter on a bean

✓ Tips

  • Save complex EL conditions with <c:set var="flag" value="${...}" /> and test ${flag} — avoids repeating the same long expression in two <c:if> tags
  • Use <c:catch> around <c:import> calls to external URLs — network failures should degrade gracefully, not crash the whole page
  • Prefer <c:choose> over multiple <c:if> tags when testing the same variable — semantically clearer and only one branch is evaluated

Quick Summary

  • <c:if test="${}"> — one-way test; no else; use var to save result
  • <c:choose> — multi-branch; wraps c:when + c:otherwise
  • <c:set var="x" value="${}"> — set scoped attribute or bean property
  • <c:remove var="x"> — delete attribute from scope
  • <c:catch var="e"> — trap Throwable; prevent error page
