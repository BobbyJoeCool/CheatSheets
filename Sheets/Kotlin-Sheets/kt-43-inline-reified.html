inline & reified

inline fun · noinline · crossinline · non-local returns · reified T · how filterIsInstance<T>() works

Zero-Cost Lambdas and Real Generics

An inline function has its body, and the lambdas passed to it, copied into each call site, so no function object is created. That also allows non-local returns from the lambda. Inline functions can declare reified type parameters, which keep the actual type at runtime, so is T and T::class work.

Key Points

  • Most collection functions (map, filter, forEach) are inline
  • noinline keeps one lambda as a real object (to store or pass on)
  • crossinline forbids non-local returns from a lambda
  • Only inline small functions; big bodies bloat code

Under the JVM

  • The inline function body is copied into the caller's bytecode
  • Reified type arguments are written in as concrete classes at each call site
  • Inline functions cannot be called from Java with reified types (they need Kotlin's compiler)

inline and reified

inline fun <T> measure(label: String, block: () -> T): T {
    val start = System.nanoTime()
    val result = block()                     // block is inlined, no object
    println("$label: ${(System.nanoTime() - start) / 1000} µs")
    return result
}

fun findFirstNegative(nums: List<Int>): Int? {
    nums.forEach { if (it < 0) return it }  // non-local return
    return null
}

inline fun <reified T> List<Any>.ofType(): List<T> =
    filter { it is T }.map { it as T }
val mixed = listOf(1, "a", 2.5, "b")
println(mixed.ofType<String>())              // [a, b]
println(mixed.filterIsInstance<Double>())    // [2.5] (stdlib, also reified)

inline fun <reified T : Any> typeName() = T::class.simpleName
println(typeName<LocalDate>())               // LocalDate

inline fun runTwice(first: () -> Unit, noinline second: () -> Unit) {
    first()
    scheduler.post(second)                   // stored, so it must be noinline
}

inline fun onClick(crossinline action: () -> Unit) {
    button.setListener { action() }          // runs later: no non-local return
}

// Gson / Jackson style:
inline fun <reified T> Gson.fromJson(json: String): T =
    fromJson(json, T::class.java)

Code Explained

measure adds timing without allocating a lambda object
return it leaves findFirstNegative because forEach is inline
reified T makes it is T and T::class legal
noinline and crossinline handle lambdas that run later or elsewhere

Java Equivalent

  • Lambdas always allocate (or are cached) objects in Java
  • Generics are erased: you must pass Class<T> type explicitly
  • gson.fromJson(json, User.class)

Idiomatic Kotlin

  • passing Class<T> parameters → inline fun <reified T>
  • marking big functions inline → only small higher-order functions

⚠ Common Mistakes

  • Inlining large functions with no lambda parameters (warning, no benefit)
  • Storing an inline lambda in a field without noinline
  • Expecting reified types to work from Java callers

✓ Tips & Best Practices

  • Use reified for JSON, DI and logging helpers that need T::class
  • Read the "expected performance impact is insignificant" warning: it means remove inline
  • Prefer stdlib inline functions (map, let) over hand-written loops

Quick Summary

  • inline — no lambda objects
  • non-local return — allowed
  • reified T — runtime type
  • noinline / crossinline
