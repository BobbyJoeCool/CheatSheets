Function References & SAM Conversions

::method · bound references obj::method · constructor references ::Person · fun interface · SAM conversion for Java interfaces

Passing Existing Functions

A function reference (::name) turns an existing function into a value you can pass, instead of wrapping it in a lambda. References can point to top-level functions, members (String::length), bound objects (printer::print) and constructors (::User). SAM conversion lets a lambda stand in for any single-abstract-method interface.

Key Points

  • Type::member is unbound: the receiver becomes the first argument
  • obj::member is bound to that object
  • Java functional interfaces accept Kotlin lambdas automatically
  • Kotlin interfaces need fun interface for SAM conversion

References and SAM

fun isEven(n: Int) = n % 2 == 0
val nums = listOf(1, 2, 3, 4)

println(nums.filter(::isEven))                  // [2, 4]
println(listOf("a", "bbb").map(String::length)) // [1, 3]

val prefix = "ID-"
println(nums.map(prefix::plus))                 // [ID-1, ID-2, ID-3, ID-4]

data class User(val name: String)
println(listOf("Ada", "Bob").map(::User))  // [User(name=Ada), User(name=Bob)]

val ref: (Int) -> Boolean = ::isEven
println(ref(10))                                // true

val prop = User::name                           // property reference
println(prop.get(User("Cy")))                   // Cy

// SAM conversion with Java interfaces
val runnable = Runnable { println("running") }
val comparator = Comparator<String> { a, b -> a.length - b.length }
executor.submit { println("task") }

// Kotlin fun interface
fun interface PriceRule { fun apply(price: Double): Double }
val tenOff = PriceRule { it * 0.9 }
println(tenOff.apply(100.0))                    // 90.0

Code Explained

::isEven passes the function without a lambda wrapper
String::length takes the String as its argument
::User calls the constructor for each name
fun interface enables lambda syntax for a Kotlin interface

Java Equivalent

  • list.stream().filter(Main::isEven)
  • String::length, User::new (constructor reference)
  • Any @FunctionalInterface accepts a lambda

Idiomatic Kotlin

  • map { it.length } → map(String::length) when it reads better
  • single-method Kotlin interfaces without fun → fun interface (or a function type)

⚠ Common Mistakes

  • Ambiguous references to overloaded functions (add a type)
  • Forgetting fun on an interface and wondering why lambdas do not convert
  • Using references where a short lambda is clearer

✓ Tips & Best Practices

  • Use constructor references in map(::Dto) conversions
  • Use bound references for callbacks on a specific object
  • Prefer function types over fun interface unless Java interop or naming matters

Quick Summary
