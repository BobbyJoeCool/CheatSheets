Nested, Inner & Anonymous Classes

nested (static by default) · inner · this@Outer · anonymous objects · local classes

Classes Inside Classes

A class declared inside another is nested and cannot see the outer instance, like a Java static nested class. Mark it inner to give it a reference to the outer object. Anonymous objects are object expressions, and local classes can be declared inside functions.

Key Points

  • Nested is the default: no outer reference, no leak risk
  • inner classes reach outer members directly
  • this@Outer names the outer instance
  • Nested classes are accessed as Outer.Nested

Nested vs inner

class Tree(val name: String) {
    class Node(val value: Int)                  // nested: no Tree reference

    inner class Branch(val label: String) {     // inner: has Tree reference
        fun path() = "$name/$label"             // reads outer property
        fun owner() = this@Tree                 // explicit outer this
    }
}

val node = Tree.Node(5)                          // no Tree needed
val tree = Tree("oak")
val branch = tree.Branch("left")                 // created from an instance
println(branch.path())                           // oak/left

class Form {
    private var submitted = 0
    fun button() = object : Clickable {          // anonymous object
        override fun click() { submitted++ }
    }
}

fun summarize(items: List<Int>): String {
    class Stats(val min: Int, val max: Int)      // local class
    val s = Stats(items.min(), items.max())
    return "${s.min}..${s.max}"
}
println(summarize(listOf(4, 9, 2)))              // 2..9

Code Explained

Tree.Node exists independently of any Tree
Branch must be created from a Tree instance
this@Tree refers to the enclosing Tree
Local classes are visible only inside their function

Java Equivalent

  • Java inner classes are inner by default; static makes them nested
  • Tree.this instead of this@Tree
  • Anonymous classes: new Clickable() { … }

Idiomatic Kotlin

  • inner by habit → nested unless the outer instance is needed
  • anonymous objects for single-method interfaces → lambdas (SAM)

⚠ Common Mistakes

  • Making classes inner unnecessarily, keeping the outer object alive
  • Trying to create an inner class without an outer instance
  • Confusing Kotlin defaults with Java's (reversed)

✓ Tips & Best Practices

  • Keep nested classes for builders and helper types
  • Use inner only when you need outer state
  • Prefer lambdas over anonymous objects for SAM interfaces

Quick Summary

  • nested — default, no outer
  • inner — has outer ref
  • this@Outer
  • local / anonymous classes
