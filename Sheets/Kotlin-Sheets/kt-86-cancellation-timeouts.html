Sheet 86

Cancellation & Timeouts

cancel() · isActive / ensureActive() · withTimeout / withTimeoutOrNull · CancellationException · NonCancellable

Stopping Work Cooperatively

Coroutine cancellation is cooperative: cancel() marks a job cancelled, and the coroutine stops at its next suspension point or check of isActive. Suspending library functions like delay check automatically. withTimeout cancels a block after a time limit; withTimeoutOrNull returns null instead of throwing.

Key Points

  • Cancellation throws CancellationException at suspension points
  • Tight CPU loops must call ensureActive() or yield()
  • Always rethrow CancellationException if you catch broad exceptions
  • Cleanup that suspends needs withContext(NonCancellable)

Cancelling and Timing Out

import kotlinx.coroutines.*
import kotlin.time.Duration.Companion.seconds

fun main() = runBlocking {
    val job = launch {
        repeat(1000) { i ->
            println("working $i")
            delay(100)                     // cancellation point
        }
    }
    delay(350)
    job.cancelAndJoin()                    // stops after ~4 iterations
    println("cancelled")

    val cpu = launch(Dispatchers.Default) {
        var n = 0L
        while (isActive) { n++ }           // checks cancellation
    }
    delay(50); cpu.cancelAndJoin()

    val price = withTimeoutOrNull(2.seconds) { slowPriceApi() }  // null if slow
    println(price ?: "using cached price")

}

suspend fun download(file: String) {
    try {
        transfer(file)
    } catch (e: Exception) {
        if (e is CancellationException) throw e   // never swallow cancellation
        log.error("failed", e)
    } finally {
        withContext(NonCancellable) { cleanupTempFiles() }   // may suspend
    }
}

Code Explained

cancelAndJoin cancels and waits for the coroutine to finish
The CPU loop exits because it checks isActive
withTimeoutOrNull is the friendly way to bound slow calls
Rethrowing CancellationException keeps cancellation working

Java Equivalent

  • future.cancel(true) + checking Thread.interrupted()
  • future.get(2, TimeUnit.SECONDS) throws TimeoutException
  • orTimeout(2, SECONDS) on CompletableFuture

Idiomatic Kotlin

  • catch (e: Exception) that eats cancellation → rethrow CancellationException
  • manual timers for timeouts → withTimeout / withTimeoutOrNull

⚠ Common Mistakes

  • Busy loops that never check isActive (cannot be cancelled)
  • runCatching or catch (e: Exception) swallowing cancellation
  • Suspending in finally without NonCancellable

✓ Tips & Best Practices

  • Use Duration values for timeouts (2.seconds)
  • Wrap blocking calls with runInterruptible to make them cancellable
  • Test cancellation paths with runTest and virtual time
