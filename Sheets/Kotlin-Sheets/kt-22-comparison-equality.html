Sheet 22

Comparison & Equality

== structural (equals) · === referential · compareTo · < > <= >= · in / !in · compareValues

Comparing Values

In Kotlin, == calls equals() and is null-safe, so it compares contents. === checks whether two references point to the same object. <, >, <= and >= call compareTo, so they work on Strings, dates, BigDecimals and anything Comparable.

Key Points

  • a == b is a?.equals(b) ?: (b === null)
  • Data classes generate equals automatically
  • in checks ranges and collections
  • Floating-point == follows IEEE rules for typed Doubles

Under the JVM

  • == compiles to Intrinsics.areEqual(a, b) (null-safe equals)
  • < on objects compiles to a.compareTo(b) < 0
  • Boxed Ints from -128..127 are cached, so === can lie in tests

== vs ===

val a = "Kotlin"
val b = StringBuilder("Kot").append("lin").toString()
println(a == b)            // true  (same text)
println(a === b)           // false (different objects)

data class Point(val x: Int, val y: Int)
println(Point(1, 2) == Point(1, 2))     // true  (generated equals)
println(Point(1, 2) === Point(1, 2))    // false

val n: String? = null
println(n == null)         // true, no NPE

println("apple" < "banana")             // true (compareTo)
println(LocalDate.of(2026, 1, 1) < LocalDate.now())
println(BigDecimal("2.0") == BigDecimal("2.00"))       // false (scale differs)
println(BigDecimal("2.0").compareTo(BigDecimal("2.00")) == 0)   // true

val score = 85
println(score in 80..89)   // true
println('q' !in "aeiou")   // true
println(compareValues(3, 7))            // negative

Code Explained

== on Strings compares text, unlike Java
Data classes compare all constructor properties
BigDecimal equals checks scale; use compareTo for value
in works with ranges, strings and collections

Java Equivalent

  • a.equals(b) or Objects.equals(a, b) for contents
  • a == b in Java compares references (Kotlin ===)
  • a.compareTo(b) < 0 instead of < on objects

Idiomatic Kotlin

  • a.equals(b) → a == b
  • a.compareTo(b) < 0 → a < b

⚠ Common Mistakes

  • Using === to compare strings or numbers
  • Expecting BigDecimal == to ignore scale
  • Overriding equals without hashCode (use a data class)

✓ Tips & Best Practices

  • Use == everywhere unless identity truly matters
  • Implement Comparable to get < and > on your types
  • Use compareBy for multi-field comparisons (sheet 54)

Quick Summary

  • == — contents
  • === — same object
  • < > — compareTo
  • in — range / contains
