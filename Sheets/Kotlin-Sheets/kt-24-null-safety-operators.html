Null-Safety Operators

safe call ?. · Elvis ?: · ?: return / ?: throw · !! · ?.let { } · safe cast as? · filterNotNull()

Working with Nullable Values

Kotlin's null-safety operators chain together: ?. skips a call on null, ?: supplies a fallback (which can even be return or throw), and ?.let { } runs a block only for non-null values. !! forces a non-null type and throws if it is wrong.

Key Points

  • A ?. chain stops at the first null
  • ?: evaluates the right side only when the left is null
  • let passes the value as it and returns the block result
  • Collections: filterNotNull, mapNotNull, firstOrNull

Chaining Null Operators

data class Address(val city: String?)
data class User(val name: String, val address: Address?)

val user: User? = User("Ada", Address(null))

println(user?.address?.city)                 // null
println(user?.address?.city ?: "Unknown")    // Unknown
println(user?.name?.length ?: 0)             // 3

fun cityOf(u: User?): String {
    val addr = u?.address ?: return "No address"
    return addr.city ?: throw IllegalStateException("No city")
}

user?.let { println("Hello, ${it.name}") }   // Hello, Ada

val id: Any = "42"
val asInt = id as? Int ?: -1                 // -1

val raw = listOf("1", null, "x", "3")
println(raw.filterNotNull())                 // [1, x, 3]
println(raw.mapNotNull { it?.toIntOrNull() }) // [1, 3]
val name = user!!.name                       // throws if user is null

Code Explained

The ?. chain returns null at the first missing link
?: return exits early with a message
?: throw turns a missing value into an error
mapNotNull drops nulls produced by the transform

Java Equivalent

  • Optional.ofNullable(user).map(User::address).map(Address::city).orElse("Unknown")
  • if (user != null && user.address() != null) …
  • Objects.requireNonNull(user) ≈ user!!

Idiomatic Kotlin

  • nested if (x != null) checks → x?.a?.b ?: default
  • if (x != null) foo(x) → x?.let(::foo)

⚠ Common Mistakes

  • Long !! chains that hide which value was null
  • x?.let { … } ?: other surprises when the block itself returns null
  • Using ?.let where a simple if is clearer

✓ Tips & Best Practices

  • Use ?: return at the top of functions for guard clauses
  • Use orEmpty() on nullable lists and strings
  • Reserve !! for tests and impossible states

Quick Summary

  • ?: — fallback / return / throw
