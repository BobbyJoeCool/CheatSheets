Sorting & Searching

sorted / sortedDescending · sortedBy / sortedWith · compareBy / thenBy · first / firstOrNull / find · any / all / none · binarySearch

Ordering and Finding

sorted() returns a new sorted list; sort() sorts a MutableList in place. sortedBy { } sorts by a property, and compareBy with thenBy builds multi-key comparators. For searching, find/firstOrNull return the first match or null, any/all/none test conditions, and binarySearch works on sorted lists.

Key Points

  • Sorting is stable: equal elements keep their order
  • sortedByDescending reverses one key
  • first { } throws if nothing matches; firstOrNull does not
  • binarySearch returns a negative insertion point when missing

Sort and Search

data class Emp(val name: String, val dept: String, val salary: Int)
val emps = listOf(
    Emp("Cy", "Eng", 95), Emp("Ada", "Eng", 120),
    Emp("Bob", "Ops", 80), Emp("Dee", "Ops", 80)
)

println(listOf(3, 1, 2).sorted())                       // [1, 2, 3]
println(listOf(3, 1, 2).sortedDescending())             // [3, 2, 1]
println(emps.sortedBy { it.name }.map { it.name })      // [Ada, Bob, Cy, Dee]
println(emps.sortedByDescending { it.salary }.first().name)   // Ada

val byDeptThenSalary = emps.sortedWith(
    compareBy<Emp> { it.dept }.thenByDescending { it.salary }.thenBy { it.name }
)
println(byDeptThenSalary.map { it.name })               // [Ada, Cy, Bob, Dee]

println(emps.find { it.dept == "Ops" }?.name)           // Bob
println(emps.firstOrNull { it.salary > 200 })           // null
println(emps.any { it.salary > 100 })                   // true
println(emps.all { it.salary >= 80 })                   // true
println(emps.none { it.dept == "HR" })                  // true
println(emps.indexOfFirst { it.name == "Bob" })         // 2

val ids = listOf(10, 20, 30, 40)
println(ids.binarySearch(30))                           // 2
println(ids.binarySearch(25))                           // -3 (insert at 2)

val mutable = emps.toMutableList()
mutable.sortBy { it.salary }                            // in place

Code Explained

compareBy … thenByDescending … thenBy sorts by three keys
Bob and Dee tie on salary, so thenBy { it.name } orders them
find is an alias for firstOrNull
A missing binary search key returns -(insertionPoint) - 1

Java Equivalent

  • list.sort(Comparator.comparing(Emp::dept).thenComparing(Emp::salary, reverseOrder()))
  • stream().filter(…).findFirst() returns Optional
  • Collections.binarySearch(list, 30)

Idiomatic Kotlin

  • Comparator.comparing(...) chains → compareBy { }.thenBy { }
  • filter { }.first() → first { } (or firstOrNull)

⚠ Common Mistakes

  • Calling sorted() and expecting the original to change
  • first { } on data that may not match (NoSuchElementException)
  • binarySearch on an unsorted list

✓ Tips & Best Practices

  • Implement Comparable for a natural order, then use sorted()
  • Use compareBy with several selectors: compareBy({ it.dept }, { it.name })
  • Use maxByOrNull/minByOrNull instead of sorting to find extremes
