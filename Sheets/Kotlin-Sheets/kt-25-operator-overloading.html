Operators on Your Own Types

Mark a function with operator and Kotlin lets you call it with a symbol: plus becomes +, get becomes [], contains becomes in, invoke makes an object callable. The set of operators is fixed, so overloading stays predictable.

Key Points

  • Function names are fixed by convention
  • Operators can be extensions on existing types
  • Compound += uses plusAssign or falls back to plus
  • Keep the meaning obvious: + should mean add

A Money Type with Operators

data class Money(val cents: Long) : Comparable<Money> {
    operator fun plus(o: Money) = Money(cents + o.cents)
    operator fun minus(o: Money) = Money(cents - o.cents)
    operator fun times(n: Int) = Money(cents * n)
    operator fun unaryMinus() = Money(-cents)
    override operator fun compareTo(other: Money) = cents.compareTo(other.cents)
    override fun toString() = "$%d.%02d".format(cents / 100, cents % 100)
}

class Inventory {
    private val stock = mutableMapOf<String, Int>()
    operator fun get(item: String) = stock[item] ?: 0
    operator fun set(item: String, qty: Int) { stock[item] = qty }
    operator fun contains(item: String) = item in stock
}

class Greeter(val greeting: String) {
    operator fun invoke(name: String) = "$greeting, $name"
}

val total = Money(1999) + Money(500) * 2       // $29.99
println(total > Money(2000))                   // true
val inv = Inventory()
inv["apple"] = 5                               // set
println(inv["apple"])                          // 5 (get)
println("pear" in inv)                         // false
println(Greeter("Hi")("Ada"))                  // Hi, Ada

Code Explained

Money(500) * 2 calls times
Implementing Comparable gives < and >
inv["apple"] = 5 calls set
Greeter("Hi")("Ada") calls invoke

Java Equivalent

  • No operator overloading: a.add(b), a.multiply(n)
  • map.get(k) / map.put(k, v) instead of []
  • BigDecimal.add is the usual pattern

Idiomatic Kotlin

  • a.add(b) method names on math types → operator fun plus
  • surprising operators (+ that deletes) → named functions

⚠ Common Mistakes

  • Forgetting the operator keyword (the symbol will not work)
  • Defining both plus and plusAssign on a mutable type (ambiguous +=)
  • Operators that do something unexpected

✓ Tips & Best Practices

  • Use data classes to get componentN for free
  • Add operators as extensions to Java types you use often
  • Implement Comparable instead of a custom compareTo operator

Quick Summary
