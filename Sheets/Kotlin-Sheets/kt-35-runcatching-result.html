runCatching & Result

runCatching { } · Result<T> · getOrNull / getOrElse / getOrDefault · onSuccess / onFailure · fold · use { } for resources

Exceptions as Values

runCatching { } runs a block and wraps the outcome in a Result<T>: success with a value, or failure with the exception. You then chain map, onFailure, getOrElse or fold instead of writing try/catch. use { } closes any Closeable resource automatically, even when an exception is thrown.

Key Points

  • runCatching catches all exceptions, including CancellationException
  • Result has isSuccess, isFailure, exceptionOrNull()
  • getOrThrow() rethrows the stored exception
  • use is Kotlin's try-with-resources

Result Chains and use

val result: Result<Int> = runCatching { "42x".toInt() }

println(result.isFailure)                         // true
println(result.getOrNull())                       // null
println(result.getOrDefault(0))                   // 0
println(result.getOrElse { e -> -1 })             // -1
println(result.exceptionOrNull()?.message)        // For input string: "42x"

val price = runCatching { fetchPrice("AAPL") }
    .map { it * 1.06 }                            // only on success
    .onFailure { log.warn("price lookup failed", it) }
    .getOrDefault(0.0)

val text = runCatching { File("cfg.txt").readText() }.fold(
    onSuccess = { "Loaded ${it.length} chars" },
    onFailure = { "Using defaults (${it::class.simpleName})" }
)

File("out.txt").bufferedWriter().use { w ->       // closed automatically
    w.write("hello")
}
val firstLine = File("in.txt").bufferedReader().use { it.readLine() }

Code Explained

map transforms only successful results
onFailure runs a side effect and passes the Result along
fold handles both cases and returns one value
use closes the writer even if write throws

Java Equivalent

  • try { … } catch (Exception e) { … } with a default
  • Optional chains (map, orElse) are the closest style
  • try-with-resources: try (var w = Files.newBufferedWriter(p)) { … }

Idiomatic Kotlin

  • try/catch just to return a default → runCatching { }.getOrDefault(x)
  • finally { reader.close() } → reader.use { }

Result API

⚠ Common Mistakes

  • Using runCatching inside coroutines and swallowing cancellation
  • Catching everything when only one exception is expected
  • Forgetting use and leaking file handles

✓ Tips & Best Practices

  • Rethrow CancellationException in coroutine code
  • Use runCatching at boundaries (I/O, parsing), not everywhere
  • Use use on every stream, reader and connection

Quick Summary

  • getOrElse / getOrDefault
