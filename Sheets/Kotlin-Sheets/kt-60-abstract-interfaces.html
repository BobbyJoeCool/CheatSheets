Sheet 60

Abstract Classes & Interfaces

abstract class · interface with default methods · properties in interfaces · multiple interfaces · super<A>.foo()

Contracts and Partial Implementations

An abstract class can hold state and constructors and leaves some members abstract. An interface declares functions and properties, can provide default implementations, but holds no state. A class can extend one class and implement many interfaces.

Key Points

  • Interface properties are abstract or have getters (no backing field)
  • Default methods need no keyword in interfaces
  • When two interfaces share a default, override and pick with super<A>
  • Use interfaces for capabilities, abstract classes for shared state

Abstract Class + Interfaces

interface Drawable {
    val color: String                       // abstract property
    fun draw(): String                      // abstract function
    fun describe() = "A $color shape"       // default implementation
}

interface Clickable {
    fun click() = "clicked"
    fun describe() = "Something clickable"
}

abstract class Shape(val name: String) {    // has state + constructor
    abstract fun area(): Double
    fun summary() = "$name with area ${"%.1f".format(area())}"
}

class Circle(val r: Double) : Shape("Circle"), Drawable, Clickable {
    override val color = "red"
    override fun area() = Math.PI * r * r
    override fun draw() = "( )"
    override fun describe() =
        super<Drawable>.describe() + " / " + super<Clickable>.describe()
}

val c = Circle(2.0)
println(c.summary())        // Circle with area 12.6
println(c.describe())       // A red shape / Something clickable
val d: Drawable = c
println(d.draw())           // ( )

Code Explained

Circle extends one abstract class and two interfaces
Both interfaces define describe, so Circle must override it
super<Drawable> picks one parent's default
The abstract class supplies name and summary()

Java Equivalent

  • abstract class Shape, interface Drawable with default methods
  • Drawable.super.describe() to call a specific default
  • Java interfaces can hold constants but not instance state

Idiomatic Kotlin

  • abstract classes used only as contracts → interfaces
  • interfaces with many defaults acting like base classes → composition

⚠ Common Mistakes

  • Trying to store state in an interface property (no backing field)
  • Not overriding a conflicting default (compile error)
  • Using abstract classes where a sealed interface fits better

✓ Tips & Best Practices

  • Name interfaces by capability: Drawable, Closeable
  • Keep interfaces small and focused
  • Use fun interface for single-method contracts (sheet 45)

Quick Summary

  • abstract class — state + abstract
  • interface — contract + defaults
  • many interfaces, one class
  • super<A> — pick a default
