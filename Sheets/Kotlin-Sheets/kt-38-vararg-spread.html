vararg & Spread

vararg · spread *array · vararg with other params · Array<out T> · listOf(*arr)

Variable Numbers of Arguments

A vararg parameter accepts any number of arguments, which arrive as an array inside the function. To pass an existing array, use the spread operator *. Only one parameter can be vararg; if it is not last, the parameters after it must be passed by name.

Key Points

  • vararg x: Int becomes IntArray inside
  • vararg x: String becomes Array<out String>
  • Spread a List with *list.toTypedArray()
  • You can mix spread and individual values

vararg and Spread

fun sum(vararg nums: Int): Int = nums.sum()

println(sum())                 // 0
println(sum(1, 2, 3))          // 6

val arr = intArrayOf(4, 5, 6)
println(sum(*arr))             // 15
println(sum(1, *arr, 10))      // 26  (mix values and spread)

fun log(level: String, vararg parts: Any) {
    println("[$level] " + parts.joinToString(" "))
}
log("INFO", "User", 42, "logged in")    // [INFO] User 42 logged in

fun <T> listOfNonNull(vararg items: T?): List<T> = items.filterNotNull()
println(listOfNonNull("a", null, "b"))  // [a, b]

val names = listOf("x", "y")
val all = listOf("w", *names.toTypedArray(), "z")   // [w, x, y, z]

fun format(vararg values: Int, sep: String) = values.joinToString(sep)
println(format(1, 2, 3, sep = "-"))     // 1-2-3 (sep must be named)

Code Explained

Inside sum, nums is an IntArray
*arr spreads array elements into the call
A List must become an array before spreading
A parameter after the vararg must be named

Java Equivalent

  • int sum(int... nums)
  • Passing an array directly works in Java (no spread operator)
  • String.format("%s %s", args) uses Object varargs

Idiomatic Kotlin

  • overloads for 1, 2, 3 arguments → one vararg
  • passing a List to vararg → *list.toTypedArray()

⚠ Common Mistakes

  • Passing an array without * (it becomes one element)
  • Two vararg parameters (not allowed)
  • Forgetting to name parameters after the vararg

✓ Tips & Best Practices

  • Put vararg last when possible
  • Accept Iterable<T> too if callers often have lists
  • Use vararg for builder-style APIs like listOf

Quick Summary

  • vararg — many arguments
  • *arr — spread
  • array inside function
  • params after → named
