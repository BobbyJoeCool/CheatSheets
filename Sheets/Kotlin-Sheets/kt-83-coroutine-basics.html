Coroutine Basics

suspend fun · runBlocking · launch · delay · kotlinx-coroutines-core · coroutines vs threads

Lightweight Concurrency

Coroutines are lightweight tasks that can suspend without blocking a thread. A suspend fun can pause at delay or other suspending calls and resume later, possibly on another thread. Builders start coroutines: launch fires and forgets, runBlocking bridges normal code to coroutines (mainly in main and tests).

Key Points

  • Add kotlinx-coroutines-core; language support is built in
  • Suspend functions can only be called from coroutines or other suspend functions
  • Thousands of coroutines can run on a few threads
  • delay suspends; Thread.sleep blocks (avoid it in coroutines)

Under the JVM

  • A suspend fun gets a hidden Continuation parameter (continuation-passing style)
  • Its body compiles to a state machine; each suspension point is a state
  • Suspending returns the special COROUTINE_SUSPENDED marker instead of blocking

First Coroutines

import kotlinx.coroutines.*

suspend fun fetchUser(id: Int): String {
    delay(500)                       // suspends, does not block the thread
    return "User$id"
}

fun main() = runBlocking {           // bridge from regular code
    println("start on ${Thread.currentThread().name}")

    val job = launch {               // runs concurrently
        repeat(3) { i ->
            println("tick $i")
            delay(200)
        }
    }

    val user = fetchUser(1)          // waits here (suspends) for 500 ms
    println("got $user")
    job.join()                       // wait for launch to finish
    println("done")
}

// 100,000 coroutines are fine; 100,000 threads are not
fun many() = runBlocking {
    repeat(100_000) { launch { delay(1000); print(".") } }
}

Code Explained

runBlocking blocks main until all children finish
launch starts a coroutine that runs alongside the caller
Ticks print while fetchUser is suspended
job.join() suspends until the launched coroutine ends

Java Equivalent

  • Threads: new Thread(() -> …).start() or an ExecutorService
  • Virtual threads (Java 21): Thread.ofVirtual().start(…)
  • CompletableFuture.supplyAsync(…) for async results

Idiomatic Kotlin

  • Thread.sleep inside coroutines → delay
  • runBlocking inside app code → suspend all the way, scopes at the edges

⚠ Common Mistakes

  • Calling runBlocking on a UI or server request thread
  • Blocking calls (JDBC, Thread.sleep) inside coroutines without Dispatchers.IO
  • Calling suspend functions from normal functions (compile error)

✓ Tips & Best Practices

  • Mark I/O functions suspend and switch dispatchers inside them (sheet 85)
  • Use runBlocking only in main and tests (prefer runTest)
  • Name coroutines with CoroutineName for easier debugging

Quick Summary

  • suspend — can pause
  • launch — fire and forget
  • runBlocking — bridge
  • delay — non-blocking wait
