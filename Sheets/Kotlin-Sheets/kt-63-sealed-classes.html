Sealed Classes & Interfaces

sealed class / sealed interface · exhaustive when · state & result modeling · data object subclasses · same-package rule

Closed Type Hierarchies

A sealed class or interface restricts its subtypes to ones declared in the same package and module, so the compiler knows every case. Each subtype can carry different data. when over a sealed type needs no else, and adding a new subtype flags every when that must handle it.

Key Points

  • Subtypes: data classes, classes, objects, or data object
  • Sealed classes are abstract and cannot be instantiated
  • Use for UI state, API results, commands, events
  • Sealed interfaces allow a class to belong to several hierarchies

Under the JVM

  • Sealed classes compile with a private constructor
  • Kotlin emits the PermittedSubclasses attribute so Java 17+ sees a sealed class
  • Exhaustive when compiles to instanceof checks (no else branch needed)

Modeling Results and State

sealed interface Result<out T> {
    data class Success<T>(val data: T) : Result<T>
    data class Failure(val error: String, val code: Int = 0) : Result<Nothing>
    data object Loading : Result<Nothing>
}

fun render(r: Result<List<String>>): String = when (r) {   // no else needed
    is Result.Success -> "Got ${r.data.size} items"
    is Result.Failure -> "Error ${r.code}: ${r.error}"
    Result.Loading    -> "Loading..."
}

println(render(Result.Success(listOf("a", "b"))))   // Got 2 items
println(render(Result.Failure("timeout", 504)))     // Error 504: timeout
println(render(Result.Loading))                     // Loading...

sealed class Shape {
    data class Circle(val r: Double) : Shape()
    data class Rect(val w: Double, val h: Double) : Shape()
}
fun area(s: Shape) = when (s) {
    is Shape.Circle -> Math.PI * s.r * s.r
    is Shape.Rect   -> s.w * s.h
}

Code Explained

Each case carries its own data
data object Loading is a singleton with a readable toString
Smart casts give access to r.data and r.error
Adding Result.Empty would make both whens fail to compile until handled

Java Equivalent

  • sealed interface Result permits Success, Failure {} (Java 17)
  • Records as cases: record Success<T>(T data) implements Result<T>
  • Pattern matching switch over sealed types (Java 21)

Idiomatic Kotlin

  • status codes + nullable fields → sealed class with one case per state
  • else branch on sealed when → list every case

⚠ Common Mistakes

  • Adding else to a sealed when and losing compile-time checks
  • Declaring subtypes in another package (not allowed)
  • Using sealed classes where a simple enum would do

✓ Tips & Best Practices

  • Model screen state and API results as sealed types
  • Use data object for cases without data
  • Use Result<Nothing> with out T so failures fit any result type

Quick Summary
