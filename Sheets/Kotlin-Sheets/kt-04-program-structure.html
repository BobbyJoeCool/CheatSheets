How a Kotlin File Is Organized

A Kotlin file starts with an optional package line and imports, then any mix of top-level functions, properties and classes. Unlike Java, functions do not need a class, one file can hold many classes, and the file name does not have to match a class name.

Key Points

  • Package names need not match folders (but should)
  • Top-level declarations are public by default
  • Blocks use braces; statements end at the newline
  • Type comes after the name: val count: Int

One File, Several Declarations

package com.example.shop

import java.time.LocalDate

const val TAX_RATE = 0.06                      // top-level constant

data class Item(val name: String, val price: Double)

fun total(items: List<Item>): Double =         // top-level function
    items.sumOf { it.price } * (1 + TAX_RATE)

class Cart {
    private val items = mutableListOf<Item>()
    fun add(item: Item) { items += item }
    fun checkout() = total(items)
}

fun main() {
    val cart = Cart()
    cart.add(Item("Book", 20.0))
    println("${LocalDate.now()}: ${cart.checkout()}")  // 2026-11-12: 21.2
}

Code Explained

TAX_RATE, total and main live outside any class
data class and class share the file with functions
= after a function signature makes it an expression body
items += item calls plusAssign on the mutable list

Java Equivalent

  • Everything must be inside a class; one public class per file
  • Constants: static final double TAX_RATE = 0.06;
  • Helper functions become static methods on a utility class

Idiomatic Kotlin

  • Utils classes full of static methods → top-level functions
  • one class per file always → group small related types in one file

⚠ Common Mistakes

  • Putting type before name like Java (Int x)
  • Expecting the file name to force a class name
  • Making everything top-level and public instead of using visibility

✓ Tips & Best Practices

  • Keep package and folder structure aligned for tooling
  • Use private top-level declarations for file-local helpers
  • Use expression bodies for one-line functions

Quick Summary

  • top-level — no class needed
  • name: Type — type after name
  • many classes per file — OK
  • package + imports first
