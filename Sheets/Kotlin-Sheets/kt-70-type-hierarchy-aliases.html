Any, Unit, Nothing & Type Aliases

Any / Any? · Unit · Nothing · typealias · platform types T! preview · type hierarchy diagram

The Top and Bottom of the Type System

Any is the supertype of every non-null type and Any? of everything. Unit is a real type with one value, used where Java has void. Nothing is the subtype of everything and has no values: it types expressions that never finish, like throw. typealias gives an existing type a shorter name.

Key Points

  • Any has equals, hashCode, toString
  • Nothing? has exactly one value: null
  • emptyList() returns List<Nothing>, which fits any List<T>
  • Type aliases do not create new types (unlike value classes)

Special Types and Aliases

fun describe(x: Any?): String = when (x) {
    null -> "null"
    is Any -> "${x::class.simpleName}: $x"
}
println(describe(42))                   // Int: 42

fun log(msg: String): Unit = println(msg)   // Unit (usually omitted)
val u: Unit = log("hi")
println(u)                              // kotlin.Unit

fun fail(msg: String): Nothing = throw IllegalStateException(msg)
val age: Int = parseAge() ?: fail("no age")  // Nothing fits as an Int

val empty: List<String> = emptyList()   // List<Nothing> is a List<String>
val nothing: Nothing? = null

typealias UserMap = Map<Int, List<User>>
typealias Handler = (Event) -> Unit
typealias Predicate<T> = (T) -> Boolean

fun register(h: Handler) {}
val isLong: Predicate<String> = { it.length > 10 }
val byId: UserMap = emptyMap()

// Type hierarchy (top to bottom):
// Any?  ⊃  Any  ⊃  String, Int, User...  ⊃  Nothing
//        ⊃  String?, Int?...  ⊃  Nothing?

Code Explained

x::class.simpleName reads the runtime class name
Unit prints as kotlin.Unit
Because Nothing is a subtype of Int, ?: fail(…) type-checks
Aliases shorten long function and generic types

Java Equivalent

  • Object is Java's top type (Kotlin maps it to Any)
  • void methods; Void is a type with only null
  • No Nothing or type aliases in Java

Idiomatic Kotlin

  • Map<Int, List<User>> repeated everywhere → typealias UserMap
  • aliases for type safety (they give none) → value classes

⚠ Common Mistakes

  • Treating typealias as a new type for validation
  • Returning Any and casting everywhere
  • Confusing Unit with Nothing

✓ Tips & Best Practices

  • Use Nothing for helpers that always throw
  • Alias long function types used in many signatures
  • Avoid Any in public APIs; use generics or sealed types

Quick Summary

  • Any / Any? — top types
  • Unit — Kotlin void
  • Nothing — never returns
  • typealias — just a name
