Scope Functions

let · run · with · apply · also · takeIf / takeUnless · choosing one (receiver vs it, result vs object)

let, run, with, apply, also

Scope functions run a block in the context of an object. They differ in two ways: whether the object is this (receiver) or it (argument), and whether they return the object or the lambda result. apply configures and returns the object; let transforms or handles nullable values.

Key Points

  • apply / also return the object itself
  • let / run / with return the lambda result
  • this-style (apply, run, with) for calling members
  • takeIf { } returns the object or null

Each Scope Function

data class User(var name: String = "", var email: String = "", var age: Int = 0)

val user = User().apply {                // configure, returns User
    name = "Ada"
    email = "ada@example.com"
}

val nameLength = user.name.let { it.length }       // 3 (result)
val maybe: String? = findEmail()
maybe?.let { sendWelcome(it) }                     // only if not null

val summary = user.run { "$name <$email>" }        // this = user, result

val report = with(StringBuilder()) {               // non-extension form
    append("Users: ")
    append(1)
    toString()
}

val list = mutableListOf(1, 2).also { println("created $it") }   // side effect

val adult = user.takeIf { it.age >= 18 }           // null here (age 0)
val name = user.name.takeUnless { it.isBlank() } ?: "anonymous"

val conn = Connection(url)
    .apply { timeout = 5000 }
    .also { log.info("conn ready") }

Code Explained

apply is the go-to for initializing objects
?.let is the classic "if not null" block
run and with compute a value using the object's members
also adds logging or validation without changing the chain

Java Equivalent

  • User u = new User(); u.setName("Ada"); u.setEmail(…);
  • Optional.ofNullable(email).ifPresent(this::sendWelcome)
  • No direct equivalents; plain local variables

Idiomatic Kotlin

  • repeated user. prefixes while configuring → user.apply { }
  • nested scope functions three deep → plain local vals

Choosing

FunctionObject asReturnsTypical Use
letitLambda resultNull checks, transform
runthisLambda resultCompute from members
with(x)thisLambda resultGroup calls on x
applythisThe objectConfigure / build
alsoitThe objectSide effects, logging
takeIfitObject or nullFilter one value

⚠ Common Mistakes

  • Using apply when you need the lambda result (you get the object back)
  • Chaining many scope functions until the code is unreadable
  • Shadowing this in nested apply blocks

✓ Tips & Best Practices

  • Default to apply for setup and ?.let for null handling
  • Use also for logging inside call chains
  • If you hesitate, a plain val is often clearer

Quick Summary

  • apply — configure, return object
  • let — it, return result
  • also — side effect
  • run / with — this, result
