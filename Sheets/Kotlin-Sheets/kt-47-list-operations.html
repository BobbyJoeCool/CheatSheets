Changing and Combining Lists

Mutable lists support add, remove, removeAt, removeIf and index assignment. Read-only lists can still be combined with + and -, which return new lists. toMutableList() makes a changeable copy, and buildList gives a mutable builder that ends as a read-only list.

Key Points

  • + and - never change the original list
  • remove(x) removes the first match; removeAt(i) by index
  • subList is a view: changes show through
  • += on a val MutableList adds in place

Mutating and Combining

val nums = mutableListOf(5, 3, 8, 3)
nums.add(1)                     // [5, 3, 8, 3, 1]
nums.add(0, 9)                  // insert at 0 → [9, 5, 3, 8, 3, 1]
nums.addAll(listOf(7, 7))       // [9, 5, 3, 8, 3, 1, 7, 7]
nums.remove(3)                  // first 3 removed
nums.removeAt(0)                // removes 9
nums.removeIf { it == 7 }       // [5, 8, 3, 1]
nums[1] = 80                    // [5, 80, 3, 1]
nums += 2                       // [5, 80, 3, 1, 2]
nums.sort()                     // in place → [1, 2, 3, 5, 80]
println(nums.subList(1, 3))     // [2, 3]

val base = listOf("a", "b")
val more = base + "c"           // [a, b, c] (new list)
val joined = base + listOf("x", "y")
val less = joined - "x"         // [a, b, y]
println(base)                   // [a, b] unchanged

val copy = base.toMutableList().apply { add("z") }   // [a, b, z]

val menu = buildList {
    add("Coffee")
    if (isMorning) add("Bagel")
    addAll(specials)
}
nums.clear()                    // []

Code Explained

add(index, x) inserts and shifts later elements
removeIf removes every match in one pass
base + "c" creates a new list; base stays the same
buildList is ideal for conditional contents

Java Equivalent

  • list.add, list.remove(Integer.valueOf(3)), list.removeIf(…)
  • Combining: Stream.concat(a.stream(), b.stream()).toList()
  • new ArrayList<>(base) to copy

Idiomatic Kotlin

  • copy + add + return → base + item
  • mutable list built step by step → buildList { }

⚠ Common Mistakes

  • nums.remove(3) on a MutableList<Int> removes the value 3, not index 3
  • Expecting sorted() to sort in place (use sort())
  • Changing a list while iterating it

✓ Tips & Best Practices

  • Use removeAt for index removal to be explicit
  • Prefer + / - on read-only lists for clarity
  • Use sortedBy for new sorted lists (sheet 54)
