Regular Expressions

Kotlin wraps Java regex in the Regex class. matches tests the whole string, containsMatchIn searches anywhere, find returns the first MatchResult (or null) and findAll returns a sequence. Raw strings avoid double escaping, and destructured unpacks capture groups into variables.

Key Points

  • Pattern syntax is Java's (java.util.regex)
  • Write patterns in raw strings: """\d+"""
  • Named groups: (?<year>\d{4}) and groups["year"]
  • RegexOption.IGNORE_CASE and others go in the constructor

Regex in Practice

val datePattern = Regex("""(\d{4})-(\d{2})-(\d{2})""")
val text = "Due 2026-11-12, paid 2026-12-01"

println(datePattern.containsMatchIn(text))      // true
println(datePattern.matches("2026-11-12"))      // true

val first = datePattern.find(text)
println(first?.value)                           // 2026-11-12
val (year, month, day) = first!!.destructured
println("$month/$day/$year")                    // 11/12/2026

datePattern.findAll(text).forEach { println(it.value) }
// 2026-11-12
// 2026-12-01

val masked = datePattern.replace(text) { m ->
    "${m.groupValues[2]}/${m.groupValues[3]}"
}
println(masked)                                 // Due 11/12, paid 12/01

val email = Regex("""[\w.]+@[\w.]+""", RegexOption.IGNORE_CASE)
println("x@y.com".matches(email))               // true
println("a1b22c333".split(Regex("""\d+""")))   // [a, b, c, ]

Code Explained

Raw strings let you write \d once instead of \\d
destructured maps groups 1, 2, 3 to variables
groupValues[0] is the whole match; [1] the first group
The lambda form of replace builds each replacement

Java Equivalent

  • Pattern.compile("(\\d{4})-…") with escaped backslashes
  • Matcher m = p.matcher(text); while (m.find()) m.group(1)
  • m.replaceAll(r -> …) (Java 9+)

Idiomatic Kotlin

  • Pattern / Matcher boilerplate → Regex + find / findAll
  • "\\d+" escaped strings → raw """\d+"""

⚠ Common Mistakes

  • Double escaping inside raw strings ("""\\d""" matches a backslash)
  • Using matches when you meant "contains"
  • Calling !! on find when there may be no match

✓ Tips & Best Practices

  • Compile a Regex once as a val, not inside a loop
  • Use named groups for readability
  • Use String.matches(Regex) or regex.matches(String) for validation
