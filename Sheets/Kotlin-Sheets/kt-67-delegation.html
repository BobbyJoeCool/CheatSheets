Delegation

class delegation by · delegated properties · lazy · Delegates.observable / vetoable · map-backed properties · ReadWriteProperty

Reusing Behavior with by

Class delegation (class A(b: B) : B by b) implements an interface by forwarding to another object, with no boilerplate, which makes composition as easy as inheritance. Delegated properties (val x by …) hand a property's get/set to a helper: lazy, observable, vetoable, a map, or your own delegate.

Key Points

  • You can override some delegated methods and forward the rest
  • observable runs a callback after each change
  • vetoable can reject a change
  • Custom delegates implement getValue / setValue

Under the JVM

  • B by b generates forwarding methods for every interface member
  • A delegated property stores a hidden $$delegate field and calls getValue/setValue
  • Kotlin 2.x optimizes some delegates (like references to other properties) to avoid extra objects

Class and Property Delegation

interface Repository { fun find(id: Int): String; fun save(x: String) }

class DbRepository : Repository {
    override fun find(id: Int) = "row $id"
    override fun save(x: String) = println("saved $x")
}

class LoggingRepository(private val inner: Repository) : Repository by inner {
    override fun save(x: String) {                 // override one method
        println("LOG save")
        inner.save(x)
    }                                              // find() is forwarded
}

class Settings(map: Map<String, Any?>) {
    val theme: String by map                       // read from map["theme"]
    val fontSize: Int by map
}
val s = Settings(mapOf("theme" to "dark", "fontSize" to 14))
println(s.theme)                                   // dark

class Profile {
    var name: String by Delegates.observable("?") { _, old, new ->
        println("name: $old -> $new")
    }
    var age: Int by Delegates.vetoable(0) { _, _, new -> new >= 0 }
}
val p = Profile()
p.name = "Ada"                                     // name: ? -> Ada
p.age = -5                                         // rejected, stays 0

Code Explained

Repository by inner forwards every method not overridden
by map reads properties from map entries by name
observable reports each change; vetoable can block it
Custom delegates implement ReadWriteProperty (getValue / setValue)

Java Equivalent

  • Forwarding methods written by hand, or the decorator pattern
  • Property change support: PropertyChangeSupport listeners
  • No delegated properties in Java

Idiomatic Kotlin

  • inheritance to reuse behavior → class delegation with by
  • repeated getter/setter logic → a custom property delegate

Standard Delegates

by lazy { }Compute once on first read

⚠ Common Mistakes

  • Map-backed properties with missing keys (NoSuchElementException on read)
  • Expecting delegated classes to forward calls made from inside the delegate back to the wrapper
  • Heavy logic in delegates that look like simple properties

✓ Tips & Best Practices

  • Use class delegation for decorators (logging, caching)
  • Use Delegates.notNull() for lateinit on Int/Long
  • Use by lazy for expensive, rarely used values

Quick Summary
