Constants and Delayed Initialization

const val makes a compile-time constant that is inlined at use sites. lateinit var declares a non-null property that is set later, such as by dependency injection or a test setup. by lazy computes a value the first time it is read and caches it.

Key Points

  • const works only for primitives and String, at top level or in objects
  • lateinit needs a var of a non-null, non-primitive type
  • Reading an unset lateinit throws UninitializedPropertyAccessException
  • lazy is thread-safe by default

Under the JVM

  • const val values are copied into calling code as literals
  • lateinit compiles to a nullable field plus a check on every read
  • by lazy creates a hidden Lazy object and a getValue call

Three Ways to Initialize

const val MAX_USERS = 100                 // top-level constant

class Config {
    companion object {
        const val VERSION = "2.1"         // Config.VERSION
    }
}

class UserService {
    lateinit var repo: UserRepository     // set by DI or tests

    fun isReady() = ::repo.isInitialized

    val report: String by lazy {          // computed on first read
        println("building report...")
        repo.findAll().joinToString()
    }
}

fun main() {
    val svc = UserService()
    println(svc.isReady())                // false
    // svc.repo.findAll()  // UninitializedPropertyAccessException
    svc.repo = UserRepository()
    println(svc.report)                   // building report... then data
    println(svc.report)                   // cached, no second build
}

Code Explained

MAX_USERS and VERSION are inlined wherever they are used
::repo.isInitialized checks a lateinit property safely
The lazy block runs once; later reads return the cached value
Lazy values must be val

Java Equivalent

  • public static final int MAX_USERS = 100;
  • Fields set later are just nullable fields with no check
  • Lazy init: double-checked locking or a holder class

Idiomatic Kotlin

  • nullable var repo: Repo? = null + !! → lateinit var repo: Repo
  • expensive work in init → by lazy

⚠ Common Mistakes

  • lateinit on an Int (not allowed; use Delegates.notNull())
  • Changing a const in a library without recompiling users (old value stays inlined)
  • Using lazy for values that depend on state that changes

✓ Tips & Best Practices

  • Use lateinit for DI-injected and test-setup fields
  • Use lazy(LazyThreadSafetyMode.NONE) on single-threaded hot paths
  • Group related constants in an object

Quick Summary

  • const val — compile-time
  • lateinit var — set later
  • by lazy — first read
  • ::x.isInitialized — check
