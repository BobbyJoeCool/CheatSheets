Kotlin Beyond the Server

Kotlin Multiplatform (KMP) shares code across Android, iOS, desktop, web and servers. Common code lives in commonMain; platform-specific parts use expect declarations in common code with actual implementations per platform. On Android, Kotlin is the default language and Jetpack Compose is the modern UI toolkit.

Key Points

  • Share business logic, networking and data first
  • Ktor client, kotlinx.serialization and SQLDelight work in common code
  • Compose Multiplatform shares UI (stable for Android, iOS, desktop)
  • Jetpack Compose gets its own set in this repo

expect / actual and a Compose Peek

// commonMain
expect fun platformName(): String

class Greeting {
    fun greet() = "Hello from ${platformName()}"
}

expect class UuidGenerator() { fun next(): String }

// androidMain / jvmMain
actual fun platformName() = "JVM ${System.getProperty("java.version")}"
actual class UuidGenerator {
    actual fun next() = java.util.UUID.randomUUID().toString()
}

// iosMain
// actual fun platformName() = UIDevice.currentDevice.systemName()
// actual class UuidGenerator { actual fun next() = NSUUID().UUIDString() }

// Android UI with Jetpack Compose (also Compose Multiplatform)
@Composable
fun Counter() {
    var count by remember { mutableStateOf(0) }
    Column(modifier = Modifier.padding(16.dp)) {
        Text("Clicked $count times")
        Button(onClick = { count++ }) { Text("Click me") }
    }
}

Code Explained

expect declares an API that each platform must provide
actual supplies the platform version
Common code calls platformName() without knowing the platform
@Composable functions describe UI from state

Java Equivalent

  • Java runs on Android but new Android APIs and samples are Kotlin-first
  • Cross-platform Java: limited (J2ObjC for iOS)
  • Android Views + XML layouts were the pre-Compose approach

Idiomatic Kotlin

  • duplicate logic in Android and iOS apps → share it with KMP
  • XML layouts in new Android screens → Jetpack Compose

⚠ Common Mistakes

  • Using java.* APIs in commonMain
  • Trying to share everything (including platform UI) on day one
  • Mismatched expect/actual signatures

✓ Tips & Best Practices

  • Start with a shared data/networking module
  • Use interfaces + DI instead of expect/actual when possible
  • See the planned Jetpack Compose set for Android UI
