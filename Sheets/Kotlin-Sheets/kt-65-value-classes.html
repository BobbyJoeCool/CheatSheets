Sheet 65

Value Classes

@JvmInline value class · wrapping primitives without overhead · type-safe IDs · boxing rules · name mangling

Type Safety Without Allocation

A value class wraps a single value in a distinct type, so a UserId cannot be passed where an OrderId is expected, even though both are Longs. At runtime the wrapper usually disappears and the raw value is used, so there is no extra object.

Key Points

  • Exactly one val property in the primary constructor
  • Can have methods, init blocks and implement interfaces
  • No identity: === is not allowed
  • UInt, ULong and Duration are value classes

Under the JVM

  • fun find(id: UserId) compiles to find-<hash>(long id): the name is mangled
  • Boxing happens when used as nullable, generic or as an interface type
  • Java callers cannot call mangled functions without @JvmName

Type-Safe IDs

@JvmInline
value class UserId(val value: Long)

@JvmInline
value class OrderId(val value: Long)

@JvmInline
value class Email(val raw: String) {
    init { require("@" in raw) { "invalid email: $raw" } }
    val domain get() = raw.substringAfter("@")
}

fun findUser(id: UserId): String = "user ${id.value}"

val uid = UserId(42)
val oid = OrderId(42)
println(findUser(uid))            // user 42
// findUser(oid)                  // error: OrderId is not UserId
// findUser(42)                   // error: Long is not UserId

val e = Email("ada@example.com")
println(e.domain)                 // example.com

val ids: List<UserId> = listOf(UserId(1), UserId(2))  // boxed in a generic list
val maybe: UserId? = null                             // boxed when nullable

Code Explained

UserId and OrderId are both Longs at runtime but different types at compile time
init validates every Email on creation
Inside a List or as a nullable, the value is boxed in the wrapper
Plain uses compile down to a raw long / String

Java Equivalent

  • A record record UserId(long value) allocates an object
  • Project Valhalla value classes are not yet standard Java
  • Usually just long userId with no type safety

Idiomatic Kotlin

  • raw Long IDs passed around → @JvmInline value class UserId
  • value classes in Java-facing APIs → @JvmName or plain types

⚠ Common Mistakes

  • Expecting no boxing inside collections
  • Calling mangled functions from Java
  • Putting several properties in a value class (only one allowed)

✓ Tips & Best Practices

  • Wrap IDs, money in cents and units of measure
  • Validate in init so invalid values never exist
  • Use kotlin.time.Duration instead of raw millisecond Longs

Quick Summary

  • @JvmInline value class
  • one property, no allocation
  • type-safe IDs and units
  • boxed when nullable / generic
