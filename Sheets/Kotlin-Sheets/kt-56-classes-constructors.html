Defining Classes

A Kotlin class declares its primary constructor in the header, and val/var parameters become properties automatically. init blocks run initialization logic, secondary constructors handle rare extra cases, and objects are created without new. Default parameter values replace most constructor overloads.

Key Points

  • Classes are final by default (sheet 59)
  • init blocks run in order with property initializers
  • Secondary constructors must delegate to the primary with this(…)
  • A class with no body needs no braces

Constructors and init

class Person(val name: String, var age: Int = 0)   // properties from params

val p = Person("Ada", 36)                          // no `new`
println(p.name)                                    // Ada
p.age += 1

class Account(val id: String, initialBalance: Double) {
    var balance = initialBalance                   // plain param used here
        private set

    init {
        require(initialBalance >= 0) { "negative balance" }
        println("Opened $id")
    }

    constructor(id: String) : this(id, 0.0)        // secondary constructor

    fun deposit(amount: Double) { balance += amount }
}

val a = Account("A-1", 50.0)                       // Opened A-1
val b = Account("A-2")                             // uses secondary
a.deposit(25.0)
println(a.balance)                                 // 75.0

class Empty                                        // no body needed
class Point private constructor(val x: Int, val y: Int) {
    companion object { fun origin() = Point(0, 0) }   // factory
}

Code Explained

val name in the header declares and initializes a property
initialBalance without val/var is only a constructor parameter
init validates inputs when the object is created
A private constructor plus a companion factory controls creation

Java Equivalent

  • Fields + constructor + getters, or a record Person(String name, int age)
  • new Person("Ada", 36)
  • Several overloaded constructors for optional values

Idiomatic Kotlin

  • fields assigned in the constructor body → val properties in the header
  • multiple constructor overloads → default parameter values

⚠ Common Mistakes

  • Calling open functions from init (subclass state not ready yet)
  • Writing new Person()
  • Adding secondary constructors where defaults would do

✓ Tips & Best Practices

  • Put validation in init with require
  • Use private constructors + companion factories for controlled creation
  • Use data classes (sheet 61) for value holders

Quick Summary

  • header = primary constructor
  • val/var params → properties
  • init — setup logic
  • defaults replace overloads
