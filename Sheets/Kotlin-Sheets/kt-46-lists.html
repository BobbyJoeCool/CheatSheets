Lists

listOf / mutableListOf · read-only vs mutable · list[i] · getOrNull / getOrElse · indices / lastIndex · emptyList()

Ordered Collections

Kotlin separates read-only List from MutableList. listOf() creates a read-only list and mutableListOf() one you can change. Index with list[i]; use getOrNull(i) to avoid exceptions. Read-only means no mutating methods on that reference, not guaranteed immutability.

Key Points

  • Both are java.util.List at runtime
  • List<T> is covariant: List<Int> is a List<Number>
  • first() / last() throw on empty; firstOrNull() does not
  • buildList { } creates a list with a mutable builder

Creating and Reading Lists

val fruits = listOf("apple", "pear", "fig")     // List<String>
val empty = emptyList<Int>()
val nums = mutableListOf(1, 2, 3)               // MutableList<Int>

println(fruits[0])                               // apple
println(fruits.size)                             // 3
println(fruits.first())                          // apple
println(fruits.last())                           // fig
println(fruits.getOrNull(5))                     // null
println(fruits.getOrElse(5) { "none" })          // none
println(fruits.indexOf("pear"))                  // 1
println("fig" in fruits)                         // true
println(fruits.indices)                          // 0..2
println(fruits.lastIndex)                        // 2
println(empty.firstOrNull())                     // null
// fruits.add("kiwi")                            // error: List is read-only

nums.add(4)
nums[0] = 10
println(nums)                                    // [10, 2, 3, 4]

val squares = List(5) { it * it }                // [0, 1, 4, 9, 16]
val readOnly: List<Int> = nums                   // same list, read-only view

Code Explained

listOf has no add; mutableListOf does
getOrElse supplies a value for a bad index
List(5) { … } builds a list from an index function
A List reference to a mutable list still sees its changes

Java Equivalent

  • List.of("apple", "pear") (immutable, throws on add)
  • new ArrayList<>(List.of(1, 2, 3)) for a mutable list
  • list.get(0) instead of list[0]

Idiomatic Kotlin

  • exposing MutableList from a class → expose List
  • list.get(i) with bounds checks → getOrNull(i)

⚠ Common Mistakes

  • Assuming listOf lists are deeply immutable
  • Calling first() on a possibly empty list
  • Casting a List to MutableList to modify it

✓ Tips & Best Practices

  • Use read-only types in function signatures
  • Use buildList to construct lists with conditions
  • Use orEmpty() for nullable lists

Quick Summary

  • listOf — read-only
  • mutableListOf — changeable
  • getOrNull — safe index
