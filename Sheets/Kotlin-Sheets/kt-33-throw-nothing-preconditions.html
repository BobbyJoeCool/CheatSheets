throw, Nothing & Preconditions

throw as an expression · Nothing type · require / requireNotNull · check / checkNotNull · error() · TODO()

Failing Fast

throw is an expression of type Nothing, so it fits anywhere a value is expected, such as after ?:. The standard library adds precondition helpers: require for bad arguments, check for bad state, error() to throw IllegalStateException, and TODO() for unfinished code.

Key Points

  • Nothing means "never returns"
  • require throws IllegalArgumentException
  • check throws IllegalStateException
  • Messages are lambdas, built only on failure

Preconditions and Nothing

fun withdraw(account: Account, amount: Double) {
    require(amount > 0) { "Amount must be positive: $amount" }
    check(account.isOpen) { "Account ${account.id} is closed" }
    if (amount > account.balance) error("Insufficient funds")
    account.balance -= amount
}

fun findUser(id: Int): User =
    repo.find(id) ?: throw NoSuchElementException("No user $id")

val name: String = requireNotNull(input["name"]) { "name is required" }
val token = checkNotNull(session.token)       // non-null after this

fun fail(msg: String): Nothing = throw IllegalStateException(msg)

val port = config["port"]?.toIntOrNull() ?: fail("bad port")

fun exportPdf(): ByteArray = TODO("PDF export not done yet")
// NotImplementedError: An operation is not implemented: PDF export...

Code Explained

require guards arguments; check guards object state
throw after ?: works because it has type Nothing
requireNotNull returns the value as a non-null type
A function returning Nothing tells the compiler code after it is unreachable

Java Equivalent

  • if (amount <= 0) throw new IllegalArgumentException(…)
  • Objects.requireNonNull(x, "msg")
  • throw new UnsupportedOperationException("TODO")

Idiomatic Kotlin

  • if (!cond) throw IllegalArgumentException(…) → require(cond) { … }
  • x ?: run { throw … } → x ?: throw …

⚠ Common Mistakes

  • Using check for argument validation (wrong exception type)
  • Building expensive messages eagerly instead of in the lambda
  • Shipping code with TODO() in a reachable path

✓ Tips & Best Practices

  • Put require calls at the top of public functions
  • Use error("…") for impossible states in when branches
  • Search for TODO( before releases

Quick Summary

  • require — arguments
  • check — state
  • error() — throw ISE
  • Nothing — never returns
