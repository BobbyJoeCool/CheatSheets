kotlin.test & JUnit

kotlin.test · @Test · assertEquals / assertFailsWith · JUnit Jupiter · backtick test names · runTest for coroutines

Unit Testing Kotlin

kotlin.test provides annotations and assertions that run on JUnit 5/6 on the JVM. Test files live in src/test/kotlin. Kotlin lets you name test functions with backticks, so test names can be full sentences. Coroutine code is tested with runTest from kotlinx-coroutines-test.

Key Points

  • Add testImplementation(kotlin("test")) and useJUnitPlatform()
  • assertFailsWith<T> { } returns the exception for further checks
  • JUnit annotations (@BeforeEach, @Nested) work as usual
  • See the JUnit set for the full JUnit feature list

A Test Class

import kotlin.test.*
import kotlinx.coroutines.test.runTest

class PriceCalculatorTest {
    private lateinit var calc: PriceCalculator

    @BeforeTest
    fun setUp() { calc = PriceCalculator(taxRate = 0.06) }

    @Test
    fun `adds tax to the subtotal`() {
        assertEquals(10.6, calc.total(10.0), absoluteTolerance = 0.001)
    }

    @Test
    fun `rejects negative amounts`() {
        val e = assertFailsWith<IllegalArgumentException> { calc.total(-1.0) }
        assertContains(e.message.orEmpty(), "negative")
    }

    @Test
    fun `discount codes are case-insensitive`() {
        assertTrue(calc.isValidCode("SAVE10"))
        assertTrue(calc.isValidCode("save10"))
        assertNull(calc.findCode("NOPE"))
    }

    @Test
    fun `loads prices asynchronously`() = runTest {
        val prices = calc.loadPrices()          // suspend function
        assertEquals(3, prices.size)
    }
}

Code Explained

Backtick names show as readable sentences in reports
absoluteTolerance compares doubles safely
assertFailsWith checks the exception type and returns it
runTest runs suspend code and skips delays instantly

Java Equivalent

  • @Test void addsTaxToSubtotal() { assertEquals(10.6, calc.total(10.0), 0.001); }
  • assertThrows(IllegalArgumentException.class, () -> calc.total(-1))
  • @DisplayName("adds tax") instead of backtick names

Idiomatic Kotlin

  • camelCase test names → backtick sentences
  • try/catch + fail() → assertFailsWith<T> { }

⚠ Common Mistakes

  • Forgetting useJUnitPlatform() so no tests run
  • Comparing doubles without a tolerance
  • Using runBlocking in tests and waiting for real delays

✓ Tips & Best Practices

  • Use backtick names that describe behavior
  • Use assertNotNull(x) to get a non-null smart cast
  • Use AssertJ or Kotest matchers for richer assertions
