Annotations & Reflection

annotation class · @Target / @Retention · use-site targets @get: · ::class / KClass · kotlin-reflect · ::prop references

Metadata and Runtime Inspection

Annotations attach metadata to code, and Kotlin's use-site targets (@field:, @get:, @param:) say exactly where a Java annotation lands on a property. Reflection uses ::class for a KClass and ::name for function and property references; full Kotlin reflection needs the kotlin-reflect library.

Key Points

  • x::class is a Kotlin KClass; x::class.java is a Java Class
  • Without kotlin-reflect, basic ::class and references still work
  • Use-site targets matter for frameworks (JPA, Jackson, validation)
  • Prefer compile-time tools (KSP, serialization) over runtime reflection

Under the JVM

  • A property produces a field, getter, setter and constructor parameter; use-site targets pick one
  • Kotlin metadata is stored in a @Metadata annotation on every class
  • kotlin-reflect reads that metadata (about 3 MB jar)

Annotations and Reflection

@Target(AnnotationTarget.CLASS, AnnotationTarget.PROPERTY)
@Retention(AnnotationRetention.RUNTIME)
annotation class Audited(val by: String = "system")

@Audited(by = "ops")
data class Invoice(
    @field:NotBlank val number: String,      // on the Java field
    @get:JsonProperty("amt") val amount: Double,   // on the getter
    @param:Min(0) val lines: Int             // on the constructor parameter
)

val k = Invoice::class
println(k.simpleName)                        // Invoice
println(k.java.name)                         // com.example.Invoice
println(k.findAnnotation<Audited>()?.by)     // ops (needs kotlin-reflect)

val inv = Invoice("A-1", 99.5, 3)
println(inv::class == Invoice::class)        // true

// with kotlin-reflect:
k.memberProperties.forEach { p -> println("${p.name} = ${p.get(inv)}") }
// amount = 99.5, lines = 3, number = A-1

val prop = Invoice::amount
println(prop.name)                           // amount
println(prop.get(inv))                       // 99.5
val ctor = ::Invoice
println(ctor("B-2", 10.0, 1))

Code Explained

@Target and @Retention define where and how long the annotation exists
@field: puts NotBlank on the field, where validators look
findAnnotation and memberProperties come from kotlin-reflect
Property and constructor references work without extra libraries

Java Equivalent

  • @interface Audited { String by() default "system"; }
  • Invoice.class.getDeclaredFields() for reflection
  • Annotations go directly on fields, getters or parameters in Java

Idiomatic Kotlin

  • annotations without use-site targets on properties → @field: / @get: as the framework needs
  • runtime reflection for codegen jobs → KSP or kotlinx.serialization

⚠ Common Mistakes

  • Validation annotations on the constructor param instead of the field (ignored)
  • Calling memberProperties without kotlin-reflect (error)
  • Heavy reflection in hot paths

✓ Tips & Best Practices

  • Check your framework docs for the right use-site target
  • Use T::class.java when a Java API wants Class<T>
  • Prefer KSP for code generation
