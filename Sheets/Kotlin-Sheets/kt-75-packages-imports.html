Packages & Imports

package · import · import … as alias · default imports · top-level declarations · file-level annotations

Organizing Code

A package line at the top of a file sets the namespace for everything in it. import brings in classes, top-level functions, properties and even single enum constants. import … as renames an import to avoid clashes. Many kotlin.* packages are imported by default.

Key Points

  • Package names do not have to match folders (but should)
  • Import a top-level function: import com.x.util.slugify
  • Wildcards import kotlin.math.* are allowed
  • No import static: functions are imported directly

Packages and Imports

@file:JvmName("StringTools")              // Java sees class StringTools
package com.example.util

import java.time.LocalDate
import java.util.Date as LegacyDate        // alias avoids a clash
import kotlin.math.*                       // wildcard
import com.example.model.User
import com.example.model.Status.ACTIVE     // single enum constant
import com.example.format.slugify          // top-level function

fun label(u: User) = "${u.name.slugify()} (${LocalDate.now()})"

fun isActive(s: com.example.model.Status) = s == ACTIVE

val circle = PI * 2.0.pow(2)               // from kotlin.math

fun toLegacy(d: LocalDate): LegacyDate =
    LegacyDate.from(d.atStartOfDay(ZoneId.systemDefault()).toInstant())

Code Explained

@file:JvmName must come before the package line
as LegacyDate lets both Date types live in one file
Top-level functions import like classes
Fully qualified names work without imports

Java Equivalent

  • package com.example.util; with a semicolon, matching folders
  • import static java.lang.Math.*; for static members
  • No import aliases in Java

Idiomatic Kotlin

  • import static thinking → import the function directly
  • name clashes resolved with fully qualified names → import … as

⚠ Common Mistakes

  • Two classes with the same name imported without an alias
  • Package/folder mismatch confusing tools and teammates
  • Putting @file: annotations after the package line

✓ Tips & Best Practices

  • Let IntelliJ optimize imports on save
  • Use aliases for clashing names like java.util.Date
  • Keep one package per folder

Quick Summary

  • package — namespace
  • import — classes and functions
  • as — alias
  • kotlin.* — imported by default
