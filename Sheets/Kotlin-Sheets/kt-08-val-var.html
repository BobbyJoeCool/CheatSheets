Sheet 08

val & var

val (read-only) · var (mutable) · type inference · explicit types · read-only ≠ immutable · top-level & local variables

Declaring Variables

val declares a read-only variable that is assigned once; var declares one you can reassign. Kotlin infers the type from the initial value, so annotations are optional. Prefer val by default and switch to var only when the value really changes.

Key Points

  • val is like Java final; the object it points to may still change
  • Types are fixed once inferred: a var x = 1 stays Int
  • Locals must be initialized before use
  • Top-level and class properties can be val or var too

val vs var

val name = "Ada"                 // String, inferred
var count = 0                    // Int, inferred
val price: Double = 9.99         // explicit type
val total: Int                   // declare now...
total = 42                       // ...assign once later

count += 1                       // OK: var
// name = "Bob"                  // error: val cannot be reassigned
// count = "ten"                 // error: type mismatch (Int)

val list = mutableListOf(1, 2)   // the reference is read-only
list.add(3)                      // but the list itself can change
println(list)                    // [1, 2, 3]

var maybe: String? = null        // nullable needs the type
maybe = "now set"

Code Explained

total is a val assigned exactly once after declaration
Changing count to a String fails: its type is Int
val list cannot point elsewhere, but add still mutates the list
Use listOf (read-only list) when contents should not change

Java Equivalent

  • final String name = "Ada"; or var name = "Ada"; (Java 10+)
  • int count = 0; for mutable locals
  • final on a list reference still allows list.add(…)

Idiomatic Kotlin

  • var everywhere → val by default
  • val list = mutableListOf() exposed publicly → expose List (read-only)

Declarations

⚠ Common Mistakes

  • Thinking val makes the object immutable
  • Using var for values that never change, hiding real state changes
  • Declaring a nullable variable without the ? type

✓ Tips & Best Practices

  • Let IntelliJ suggest "Change to val" warnings
  • Add explicit types on public API properties
  • Keep vars as local as possible

Quick Summary

  • val — assign once
  • var — reassignable
  • inference — type from value
  • read-only ≠ immutable
