when

when (x) · when without subject · is / in branches · multiple values 1, 2 -> · exhaustive when · guard conditions if in branches

Kotlin's Switch

when matches a value against branches and runs the first that fits, with no fall-through. Branches can test constants, several values, ranges (in), types (is) or any condition. As an expression it must be exhaustive, which the compiler checks for enums, sealed types and Booleans.

Key Points

  • else is the default branch
  • Without a subject, each branch is a Boolean condition
  • Guard conditions (is X if …) arrived in Kotlin 2.1 (stable in 2.2)
  • when (val x = f()) scopes a variable to the when

when Forms

fun grade(score: Int) = when (score) {
    100        -> "Perfect"
    in 90..99  -> "A"
    in 80..89  -> "B"
    0, -1      -> "Missing"
    else       -> "C or below"
}

fun describe(x: Any) = when (x) {
    is Int if x < 0 -> "negative Int"        // guard condition
    is Int    -> "Int $x"
    is String -> "String of ${x.length}"
    else      -> "other"
}

val temp = 72
val advice = when {                          // no subject
    temp > 85 -> "Stay inside"
    temp < 50 -> "Wear a coat"
    else      -> "Go outside"
}

enum class Light { RED, YELLOW, GREEN }
fun action(l: Light) = when (l) {            // exhaustive, no else
    Light.RED    -> "Stop"
    Light.YELLOW -> "Slow"
    Light.GREEN  -> "Go"
}

when (val user = findUser()) {
    null -> println("not found")
    else -> println(user.name)
}

Code Explained

in 90..99 matches a range
0, -1 shares one branch
Covering every enum value removes the need for else
Adding a new enum value breaks the build until when is updated

Java Equivalent

  • switch (score) { case 100 -> "Perfect"; default -> … } (Java 14+)
  • case Integer i when i < 0 -> guards (Java 21)
  • Java switch has no ranges; use if chains

Idiomatic Kotlin

  • if/else if ladders → when
  • else on enum/sealed when → list all cases (compiler catches new ones)

Branch Types

⚠ Common Mistakes

  • Expecting fall-through like C switch
  • Adding else to enum when and missing new values later
  • Putting a broad branch before a specific one

✓ Tips & Best Practices

  • Use subject-less when for complex conditions
  • Return when directly from functions
  • Pair when with sealed classes for state handling (sheet 63)

Quick Summary

  • when (x) — match value
  • in / is — ranges / types
  • exhaustive — enums, sealed
  • no fall-through
