Type Conversion

no implicit widening · toInt() / toLong() / toDouble() · toIntOrNull() · toString() · toBigDecimal()

Converting Between Types

Kotlin never widens numbers automatically: an Int will not become a Long just by assignment. Every numeric type has explicit conversion functions such as toLong() and toDouble(). Strings parse with toInt() (throws) or toIntOrNull() (returns null).

Key Points

  • Arithmetic with mixed types widens the result: Int + Long is Long
  • Narrowing conversions truncate or wrap
  • toInt() on a Double drops the fraction
  • Numbers convert to String with toString() or templates

Explicit Conversions

val i: Int = 42
// val l: Long = i                // error: type mismatch
val l: Long = i.toLong()          // 42
val d: Double = i.toDouble()      // 42.0
val mixed = i + 10L               // Long (widened in arithmetic)

println(3.99.toInt())             // 3 (truncated)
println(300.toByte())             // 44 (wrapped)
println((-1).toUInt())            // 4294967295

println("42".toInt())             // 42
println("4x2".toIntOrNull())      // null
println("3.5".toDouble())         // 3.5
println("ff".toInt(16))           // 255
println("true".toBoolean())       // true
println("19.99".toBigDecimal())   // 19.99
println(42.toString())            // "42"
println(42.toString().padStart(5, '0'))   // 00042

Code Explained

i.toLong() is required because there is no implicit widening
Narrowing to Byte keeps only the low 8 bits
toIntOrNull() is the safe choice for user input
toBigDecimal() exists for String, Int, Long and Double

Java Equivalent

  • long l = i; widens automatically in Java
  • Integer.parseInt("42") throws NumberFormatException
  • String.valueOf(42) or Integer.toString(42)

Idiomatic Kotlin

  • Integer.parseInt(s) → s.toInt() / s.toIntOrNull()
  • try { s.toInt() } catch … → s.toIntOrNull() ?: default

⚠ Common Mistakes

  • Expecting val l: Long = intValue to compile
  • Parsing user input with toInt() and crashing
  • Assuming toInt() rounds (it truncates)

✓ Tips & Best Practices

  • Use roundToInt() when you mean rounding
  • Use the OrNull parsers plus ?: for defaults
  • Use toBooleanStrict() for config flags
