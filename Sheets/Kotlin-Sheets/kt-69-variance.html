Variance

out (covariant) · in (contravariant) · declaration-site variance · use-site projections · star projection * · List vs MutableList

When a List<Dog> Is a List<Animal>

Variance controls subtyping between generic types. out T marks a type that only produces T, so Producer<Dog> is a Producer<Animal> (covariant). in T marks a type that only consumes T, so Consumer<Animal> is a Consumer<Dog> (contravariant). Kotlin declares this once on the class.

Key Points

  • List<out E> is covariant; MutableList<E> is invariant
  • out positions: return types; in positions: parameters
  • Use-site out/in work like Java wildcards
  • * means "some unknown type" (read as out Any?)

Under the JVM

  • Variance is erased: at runtime all are the same class
  • Declaration-site out T becomes ? extends T in Java signatures
  • Kotlin may add wildcards to Java signatures automatically (@JvmSuppressWildcards turns it off)

out, in and *

open class Animal(val name: String)
class Dog(name: String) : Animal(name)

val dogs: List<Dog> = listOf(Dog("Rex"))
val animals: List<Animal> = dogs           // OK: List is covariant (out E)

val mutableDogs = mutableListOf(Dog("Rex"))
// val ma: MutableList<Animal> = mutableDogs   // error: invariant

interface Source<out T> { fun next(): T }                 // producer
interface Sink<in T> { fun put(item: T) }                  // consumer

val dogSource: Source<Dog> = object : Source<Dog> {
    override fun next() = Dog("Fido")
}
val animalSource: Source<Animal> = dogSource               // covariant

val animalSink: Sink<Animal> = object : Sink<Animal> {
    override fun put(item: Animal) = println(item.name)
}
val dogSink: Sink<Dog> = animalSink                        // contravariant

fun copy(from: Array<out Animal>, to: Array<in Animal>) {  // use-site
    for (i in from.indices) to[i] = from[i]
}

fun printAll(list: List<*>) = list.forEach { println(it) } // star projection

Code Explained

A List<Dog> can be read as a List<Animal> because List only produces
MutableList could accept a Cat if it were covariant, so it is invariant
Source<out T> returns T; Sink<in T> accepts T
Array<out Animal> is a use-site projection like ? extends Animal

Java Equivalent

  • List<? extends Animal> (producer) / List<? super Dog> (consumer)
  • PECS: Producer Extends, Consumer Super
  • List<?> ≈ Kotlin List<*>

Idiomatic Kotlin

  • wildcards at every use site → declare out/in on the type once
  • invariant producer interfaces → mark them out T

⚠ Common Mistakes

  • Putting an out T in a parameter position (compile error)
  • Expecting MutableList<Dog> to be a MutableList<Animal>
  • Using * and then trying to add elements

✓ Tips & Best Practices

  • Ask: does this type only produce T (out) or only consume it (in)?
  • Expose read-only interfaces so they can be covariant
  • Use @UnsafeVariance only when you are sure

Quick Summary

  • out — producer, covariant
  • in — consumer, contravariant
  • MutableList — invariant
  • * — unknown type
