StateFlow, SharedFlow & Channels

MutableStateFlow · SharedFlow · stateIn / shareIn · Channel · produce · hot vs cold

Hot Streams and Messaging

StateFlow holds a single current value and emits each change to collectors, which makes it ideal for UI or service state. SharedFlow broadcasts events to all collectors. Both are hot: they exist whether or not anyone collects. A Channel passes each value to exactly one receiver, like a queue between coroutines.

Key Points

  • StateFlow always has a value and skips equal repeats
  • SharedFlow can replay recent values to new collectors
  • stateIn / shareIn turn a cold flow into a hot one
  • Channels must be closed when the producer finishes

State, Events and Channels

import kotlinx.coroutines.*
import kotlinx.coroutines.channels.*
import kotlinx.coroutines.flow.*

class CartViewModel(scope: CoroutineScope) {
    private val _count = MutableStateFlow(0)        // state
    val count: StateFlow<Int> = _count.asStateFlow()

    private val _events = MutableSharedFlow<String>()   // one-off events
    val events: SharedFlow<String> = _events

    fun add() { _count.update { it + 1 } }
    suspend fun checkout() { _events.emit("Checked out ${_count.value} items") }

    val total: StateFlow<Double> = count
        .map { it * 9.99 }
        .stateIn(scope, SharingStarted.WhileSubscribed(5_000), 0.0)
}

fun main() = runBlocking {
    val vm = CartViewModel(this)
    val watcher = launch {
        vm.count.collect { println("count = $it") }    // count = 0
    }
    vm.add(); vm.add()                                // count = 1, count = 2
    delay(100); watcher.cancel()

    val jobs = Channel<Int>(capacity = 10)            // work queue
    repeat(3) { w ->
        launch { for (j in jobs) println("worker $w got job $j") }
    }
    for (j in 1..6) jobs.send(j)
    jobs.close()                                      // workers' loops end

    val numbers = produce { for (i in 1..3) send(i * i) }
    println(numbers.toList())                         // [1, 4, 9]
    coroutineContext.cancelChildren()
}

Code Explained

Private mutable state, public read-only StateFlow
update { } changes the value atomically
stateIn keeps total hot while someone is watching (plus 5 s)
Each job in the channel goes to only one worker

Java Equivalent

  • Observable state: PropertyChangeSupport or Reactor Sinks.many()
  • Event bus libraries for SharedFlow-style broadcasts
  • BlockingQueue between threads ≈ Channel (but blocking)

Idiomatic Kotlin

  • MutableStateFlow exposed publicly → private _state + asStateFlow()
  • SharedFlow for one consumer queues → Channel

⚠ Common Mistakes

  • Using StateFlow for one-time events (they replay as state)
  • Forgetting to close channels, so receivers wait forever
  • Exposing mutable flows publicly

✓ Tips & Best Practices

  • StateFlow for state, SharedFlow for events, Channel for work queues
  • Use WhileSubscribed(5_000) for UI-driven flows
  • Use update { } instead of read-modify-write on value

Quick Summary

  • StateFlow — current state
  • SharedFlow — broadcast events
  • stateIn / shareIn — make hot
  • Channel — one receiver per value
