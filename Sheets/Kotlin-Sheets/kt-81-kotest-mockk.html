Kotest & MockK

Kotest specs (StringSpec, FunSpec) · shouldBe matchers · mockk<T>() · every { } / verify { } · coEvery · relaxed mocks

Kotlin-Native Testing Tools

Kotest is a Kotlin test framework with expressive specs and infix matchers like shouldBe. MockK is a mocking library built for Kotlin: it mocks final classes, objects, extension functions and suspend functions, with every { } to stub and verify { } to check calls.

Key Points

  • Kotest runs on the JUnit Platform
  • Matchers: shouldBe, shouldContain, shouldThrow<T>
  • MockK coEvery / coVerify handle suspend functions
  • relaxed = true returns defaults for unstubbed calls

Kotest Spec with MockK

import io.kotest.core.spec.style.FunSpec
import io.kotest.matchers.shouldBe
import io.kotest.matchers.collections.shouldContain
import io.kotest.assertions.throwables.shouldThrow
import io.mockk.*

class OrderServiceTest : FunSpec({
    val repo = mockk<OrderRepository>()
    val mailer = mockk<Mailer>(relaxed = true)
    val service = OrderService(repo, mailer)

    test("places an order and sends email") {
        every { repo.save(any()) } returns Order(1, "Ada", 25.0)
        val order = service.place("Ada", 25.0)

        order.id shouldBe 1
        verify(exactly = 1) { mailer.send("Ada", match { "confirmed" in it }) }
    }

    test("loads recent orders") {
        coEvery { repo.recent(any()) } returns listOf(Order(2, "Bob", 5.0))
        service.recentFor("Bob").map { it.customer } shouldContain "Bob"
        coVerify { repo.recent("Bob") }
    }

    test("rejects empty customer") {
        shouldThrow<IllegalArgumentException> { service.place("", 1.0) }
    }
})

Code Explained

every { … } returns … stubs a call
relaxed = true lets mailer.send run without a stub
match { } checks an argument with a predicate
coEvery/coVerify handle the suspend function recent

Java Equivalent

  • Mockito: when(repo.save(any())).thenReturn(order)
  • verify(mailer, times(1)).send(eq("Ada"), contains("confirmed"))
  • Mockito needs mockito-inline (now default) to mock final classes

Idiomatic Kotlin

  • Mockito with Kotlin final classes and suspend funs → MockK
  • many assertEquals lines → Kotest matchers

⚠ Common Mistakes

  • Unstubbed calls on strict mocks (MockKException)
  • Using every for suspend functions (use coEvery)
  • Over-mocking simple value objects

✓ Tips & Best Practices

  • Prefer fakes for simple dependencies; mock at boundaries
  • Use confirmVerified(mock) to catch unexpected calls
  • Pick one Kotest style per project

Quick Summary

  • Kotest — specs + matchers
  • shouldBe — infix assertions
  • MockK — every / verify
  • coEvery — suspend
