Text in Kotlin

Kotlin strings are immutable java.lang.String objects with extra functions. Templates insert values with $name or ${expression}, and raw strings in triple quotes keep line breaks and backslashes as written, which suits JSON, SQL and regex. == compares contents.

Key Points

  • s[i] returns a Char; out of range throws
  • == compares text; === compares references
  • "\$" or ${'$'} prints a literal dollar sign
  • Strings are iterable: for (c in s)

Under the JVM

  • Templates compile to StringBuilder appends or invokedynamic string concatenation
  • A Kotlin String is exactly a java.lang.String
  • Raw string trimIndent() on a constant is computed at compile time

Templates and Raw Strings

val name = "Ada"
val user = User("Ada", 36)

println("Hello, $name!")                 // Hello, Ada!
println("Next year: ${user.age + 1}")    // Next year: 37
println("Cost: \$5")                     // Cost: $5
println(name.length)                     // 3
println(name[0])                         // A
println(name == "Ada")                   // true

val json = """
    {
      "name": "$name",
      "path": "C:\temp"
    }
""".trimIndent()

val sql = """
    |SELECT *
    |  FROM users
    | WHERE name = ?
""".trimMargin()

for (c in "abc") print(c.uppercaseChar())  // ABC

Code Explained

${user.age + 1} evaluates an expression inside the string
Raw strings keep C:\temp without escaping and still support templates
trimIndent() removes the common indentation
trimMargin() strips everything up to and including |

Java Equivalent

  • "Hello, " + name + "!" or "Hello, %s!".formatted(name)
  • Text blocks """…""" (Java 15+) like Kotlin raw strings
  • s.charAt(0) instead of s[0]; .equals() for contents

Idiomatic Kotlin

  • "Hi " + name + "!" → "Hi $name!"
  • escaped multi-line strings with \n → raw strings + trimIndent()

⚠ Common Mistakes

  • "$user.name" prints the object then ".name" (needs ${user.name})
  • Using === to compare strings
  • Escaping backslashes inside raw strings (they are already literal)

✓ Tips & Best Practices

  • Use raw strings for regex patterns and JSON
  • Use trimIndent() so code indentation stays tidy
  • Prefer templates over + concatenation

Quick Summary

  • $x / ${expr} — templates
  • """…""" — raw strings
  • trimIndent() — clean indents
  • == — compare text
