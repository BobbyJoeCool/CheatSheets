Resources & use

use { } · AutoCloseable · classpath resources · this::class.java.getResource · Properties files

Closing Resources and Loading Bundled Files

use { } works on any Closeable or AutoCloseable: it runs the block and then closes the resource, even when an exception is thrown. Classpath resources are files packaged in src/main/resources; read them with getResource or getResourceAsStream, never with file paths.

Key Points

  • use returns the block's result
  • Nest use calls for several resources
  • Resource paths start with / for the classpath root
  • Resources inside a jar are not files: read them as streams

use and Resources

import java.util.Properties

val count = File("data.csv").bufferedReader().use { r ->
    r.lineSequence().count()              // reader closed afterwards
}

FileInputStream("in.bin").use { input ->
    FileOutputStream("out.bin").use { output ->
        input.copyTo(output)              // both closed in reverse order
    }
}

class Connection(val url: String) : AutoCloseable {
    init { println("open $url") }
    override fun close() = println("close $url")
}
Connection("db://x").use { println("query on ${it.url}") }
// open db://x / query on db://x / close db://x

// src/main/resources/config.properties
object AppConfig {
    private val props = Properties().apply {
        AppConfig::class.java.getResourceAsStream("/config.properties")
            ?.use { load(it) } ?: error("config.properties missing")
    }
    val dbUrl: String get() = props.getProperty("db.url")
    val poolSize: Int get() = props.getProperty("db.pool", "5").toInt()
}

val template = javaClass.getResource("/templates/email.html")?.readText()

Code Explained

use closes the reader once counting finishes
Nested use closes the output, then the input
Any class implementing AutoCloseable works with use
getResourceAsStream works both from a folder and inside a jar

Java Equivalent

  • try-with-resources: try (var r = Files.newBufferedReader(p)) { … }
  • getClass().getResourceAsStream("/config.properties")
  • Properties.load(InputStream) is the same API

Idiomatic Kotlin

  • try { … } finally { x.close() } → x.use { }
  • File("src/main/resources/x") → getResource("/x")

⚠ Common Mistakes

  • Reading resources with File paths (breaks inside a jar)
  • Forgetting the leading /
  • Not handling a null resource (missing file)

✓ Tips & Best Practices

  • Wrap every stream, reader, socket and connection in use
  • Fail fast with ?: error("missing …") for required resources
  • Keep config in src/main/resources and override with env vars

Quick Summary

  • use { } — auto-close
  • AutoCloseable — your types too
  • getResource("/x") — bundled files
  • null check — missing resource
