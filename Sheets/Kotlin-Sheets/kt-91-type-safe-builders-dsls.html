Building Your Own Mini-Languages

Kotlin DSLs combine lambdas with receivers (T.() -> Unit), extension functions, infix calls and trailing lambdas, so nested blocks read like configuration. The Gradle Kotlin DSL, Ktor routing and kotlinx.html are all built this way. @DslMarker stops inner blocks from accidentally calling outer builders.

Key Points

  • Inside T.() -> Unit, this is a T
  • Each nesting level is a builder class
  • @DslMarker restricts implicit receivers to the nearest one
  • Standard builders: buildList, buildString, buildMap, sequence

A Small HTML DSL

@DslMarker annotation class HtmlDsl

@HtmlDsl
abstract class Tag(val name: String) {
    protected val children = mutableListOf<Tag>()
    private val attrs = mutableMapOf<String, String>()
    var text = ""
    fun attr(key: String, value: String) { attrs[key] = value }
    protected fun <T : Tag> add(tag: T, init: T.() -> Unit): T =
        tag.apply(init).also { children += it }
    override fun toString(): String {
        val a = attrs.entries.joinToString("") { " ${it.key}=\"${it.value}\"" }
        return "<$name$a>$text${children.joinToString("")}</$name>"
    }
}
class Html : Tag("html") { fun body(init: Body.() -> Unit) = add(Body(), init) }
class Body : Tag("body") {
    fun h1(t: String) = add(H1()) { text = t }
    fun a(href: String, t: String) = add(A()) { attr("href", href); text = t }
}
class H1 : Tag("h1"); class A : Tag("a")

fun html(init: Html.() -> Unit) = Html().apply(init)

val page = html {
    body {
        h1("Cheat Sheets")
        a("/kotlin", "Kotlin set")
    }
}
println(page)
// <html><body><h1>Cheat Sheets</h1>
//   <a href="/kotlin">Kotlin set</a></body></html>

val names = buildList { add("Ada"); if (true) add("Bob") }

Code Explained

html { } takes an Html.() -> Unit lambda
Inside body { }, calls like h1(...) go to the Body builder
@HtmlDsl prevents calling body { } inside another body
The same pattern drives Gradle's dependencies { } blocks

Java Equivalent

  • Builder classes with chained methods: Html.builder().body(…).build()
  • Java has no lambdas with receivers
  • Fluent APIs (jOOQ, AssertJ) are Java's closest equivalent

Idiomatic Kotlin

  • long fluent builder chains → a receiver-lambda DSL
  • deeply nested DSL scopes without @DslMarker → add a marker

⚠ Common Mistakes

  • Calling outer-scope builders from inner blocks by accident
  • Building DSLs where a simple function call would do
  • Mutable builder state leaking after construction

✓ Tips & Best Practices

  • Start with apply-based builders before custom DSL classes
  • Use @DslMarker on every builder in the hierarchy
  • Keep DSLs for configuration and structured content
