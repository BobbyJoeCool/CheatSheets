Defining Functions

fun · single-expression = … · return types · Unit · top-level vs member functions · Nothing returns

Functions in Kotlin

Functions are declared with fun, parameters as name: Type, and the return type after the parentheses. A function that returns no useful value returns Unit (Kotlin's void), which can be left off. One-line functions can use = and let the compiler infer the return type.

Key Points

  • Parameters are read-only (like val)
  • Block bodies need an explicit return type unless Unit
  • Functions can be top-level, members, local or extensions
  • Use named arguments for clarity at call sites

Function Forms

fun add(a: Int, b: Int): Int {
    return a + b
}

fun multiply(a: Int, b: Int) = a * b      // expression body, Int inferred

fun greet(name: String): Unit {           // Unit can be omitted
    println("Hello, $name")
}

fun log(msg: String) = println("[LOG] $msg")   // returns Unit

fun isAdult(age: Int) = age >= 18

fun divide(a: Int, b: Int): Int {
    if (b == 0) return 0                  // early return
    return a / b
}

class Calculator {
    fun square(x: Int) = x * x            // member function
}

fun fail(reason: String): Nothing = throw IllegalStateException(reason)

println(add(2, 3))                        // 5
println(multiply(4, 5))                   // 20
println(Calculator().square(6))           // 36

Code Explained

= a * b makes an expression body; no braces or return
Unit is a real type with a single value, Unit
Public API functions should state their return type
Nothing marks functions that never return normally

Java Equivalent

  • int add(int a, int b) { return a + b; }
  • void greet(String name) ≈ fun greet(name: String)
  • All methods live in classes; static methods for utilities

Idiomatic Kotlin

  • block body with only return x → expression body = x
  • static utility classes → top-level functions

⚠ Common Mistakes

  • Forgetting the return type on a block body that returns a value
  • Writing void (use Unit or nothing)
  • Reassigning parameters (they are read-only)

✓ Tips & Best Practices

  • Use expression bodies for short pure functions
  • State return types on public functions
  • Keep functions small and named by what they return

Quick Summary

  • fun name(p: T): R
  • = expr — expression body
  • Unit — no value
  • Nothing — never returns
