Sheet 88

Flow

flow { emit() } · collect · map / filter / take · cold streams · flowOn · catch / onCompletion

Asynchronous Streams

A Flow is a stream of values produced asynchronously, like a suspending Sequence. Flows are cold: the code inside flow { } runs each time someone calls collect. Operators such as map, filter and take transform the stream, flowOn changes where upstream code runs, and catch handles errors.

Key Points

  • collect is a suspend function: it runs in a coroutine
  • Operators are applied lazily as values flow
  • Use flowOn(Dispatchers.IO) instead of withContext inside flow { }
  • Terminal operators: collect, toList, first, reduce

Under the JVM

  • Each operator wraps the upstream flow; collect drives the whole chain
  • flowOn adds a channel boundary so upstream runs on another dispatcher
  • Flows are sequential by default: one value at a time, no buffering

Building and Collecting Flows

import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*

fun prices(symbol: String): Flow<Double> = flow {
    var p = 100.0
    while (true) {
        p += (-1..1).random()
        emit(p)                         // send a value
        delay(500)
    }
}

fun readLines(path: String): Flow<String> = flow {
    File(path).useLines { lines -> lines.forEach { emit(it) } }
}.flowOn(Dispatchers.IO)                // upstream runs on IO

fun main() = runBlocking {
    prices("ACME")
        .map { "%.2f".format(it) }
        .take(3)                        // stop after 3 values
        .collect { println("price $it") }

    val errors = readLines("app.log")
        .filter { "ERROR" in it }
        .catch { e -> emit("read failed: ${e.message}") }
        .onCompletion { println("log scan done") }
        .toList()

    flowOf(1, 2, 3).collect { println(it) }
    (1..5).asFlow().map { it * it }.collect { print("$it ") }   // 1 4 9 16 25
}

Code Explained

flow { } runs only when collected, and again for each collector
take(3) cancels the infinite producer after three values
flowOn(Dispatchers.IO) moves file reading off the caller's thread
catch handles upstream errors and can emit a fallback

Java Equivalent

  • Reactor Flux / RxJava Observable are the nearest equivalents
  • java.util.concurrent.Flow (Reactive Streams interfaces)
  • Streams are synchronous and cannot suspend

Idiomatic Kotlin

  • callback listeners → callbackFlow { } / Flow
  • withContext inside flow { } (not allowed) → flowOn

⚠ Common Mistakes

  • Expecting a flow to run without collecting it
  • Calling withContext inside flow { } (IllegalStateException)
  • Collecting an infinite flow without take or cancellation

✓ Tips & Best Practices

  • Return Flow from repositories for streams of updates
  • Put catch after the operators whose errors you want to handle
  • Use stateIn/shareIn to share one upstream (sheet 89)

Quick Summary

  • flow { emit() } — cold stream
  • collect — run it
  • operators — map / filter / take
  • flowOn — upstream thread
