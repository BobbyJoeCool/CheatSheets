Nulls in the Type System

In Kotlin, a regular type like String can never hold null. To allow null you write String?, and the compiler then forces you to handle it before use: with a check, the safe call ?., the Elvis operator ?:, or !! if you are certain it is not null.

Key Points

  • String is a subtype of String?
  • After if (x != null), x is smart cast to non-null
  • !! throws NullPointerException when the value is null
  • Java values arrive as platform types String! (sheet 77)

Under the JVM

  • Non-null parameters get Intrinsics.checkNotNullParameter calls at public entry points
  • Nullable and non-null String are both java.lang.String in bytecode
  • @Nullable / @NotNull annotations are emitted for Java callers

Handling Nullable Values

var name: String = "Ada"
// name = null                    // error: null not allowed

var nick: String? = null          // nullable
println(nick?.length)             // null (safe call)
println(nick?.length ?: 0)        // 0 (Elvis default)

if (nick != null) {
    println(nick.length)          // smart cast: nick is String here
}

nick = "Lovelace"
println(nick!!.length)            // 8, but throws if nick is null

fun greet(user: String?) {
    val shown = user ?: return     // leave if null
    println("Hi, $shown")
}

val lengths = listOf("a", null, "abc").map { it?.length }
println(lengths)                  // [1, null, 3]

Code Explained

?. returns null instead of calling on a null receiver
?: gives a value (or return/throw) when the left side is null
Smart casts work on local vals and unchanged local vars
!! is a promise to the compiler; a broken promise is an NPE

Java Equivalent

  • Any reference may be null; checks happen only at runtime
  • Optional<String> for optional return values
  • Objects.requireNonNull(x) ≈ x!!

Idiomatic Kotlin

  • if (x != null) x.foo() else null → x?.foo()
  • x!! sprinkled everywhere → ?., ?:, or a non-null type

⚠ Common Mistakes

  • Using !! to silence the compiler instead of handling null
  • Making every type nullable "just in case"
  • Trusting Java return values that can actually be null

✓ Tips & Best Practices

  • Make types non-null unless null has a real meaning
  • Use ?: return / ?: throw for early exits
  • See sheet 24 for all null-safety operators
