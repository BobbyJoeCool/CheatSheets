Default & Named Arguments

default values · named arguments · mixing positional & named · @JvmOverloads · replacing overloads & builders

Flexible Parameters

Parameters can have default values, so callers pass only what they need. Callers can also use named arguments to make calls readable and to skip defaults in any order. Together they replace most overloaded methods and many builder classes from Java.

Key Points

  • Defaults can refer to earlier parameters
  • After a named argument, later ones should be named too
  • Named arguments do not work when calling Java methods
  • @JvmOverloads generates Java overloads for defaults

Defaults and Named Calls

fun createUser(
    name: String,
    email: String = "",
    age: Int = 0,
    isAdmin: Boolean = false,
    tags: List<String> = emptyList()
) = User(name, email, age, isAdmin, tags)

createUser("Ada")
createUser("Ada", "ada@example.com")
createUser("Bob", isAdmin = true)                  // skip email, age
createUser(name = "Cy", age = 30, email = "cy@x.io")   // any order

fun connect(host: String, port: Int = if (host == "localhost") 8080 else 443) =
    "$host:$port"
println(connect("localhost"))                      // localhost:8080
println(connect("api.example.com"))                // api.example.com:443

class Greeter @JvmOverloads constructor(
    val greeting: String = "Hello",
    val punctuation: String = "!"
)
// Java sees: Greeter(), Greeter(String), Greeter(String, String)

drawRect(x = 10, y = 20, width = 100, height = 50)  // readable booleans/ints

Code Explained

One function covers what would be several Java overloads
isAdmin = true skips email and age
A default can be computed from another parameter
@JvmOverloads helps Java callers who cannot use defaults

Java Equivalent

  • Several overloads: createUser(String), createUser(String, String)…
  • Builder pattern: User.builder().name("Ada").isAdmin(true).build()
  • Java has no named arguments

Idiomatic Kotlin

  • telescoping overloads → one function with defaults
  • f(true, false, 3) → f(force = true, dryRun = false, retries = 3)

Call Styles

CallNotes
f("a")Use all defaults
f("a", "b")Positional
f("a", age = 3)Positional, then named
f(age = 3, name = "a")All named, any order
f(*array)Spread into vararg

⚠ Common Mistakes

  • Mixing named then positional arguments in confusing order
  • Expecting named arguments when calling Java APIs
  • Changing default values in a library without considering callers

✓ Tips & Best Practices

  • Name Boolean and numeric arguments at call sites
  • Use data class copy() for "same but changed" (sheet 61)
  • Add @JvmOverloads on APIs Java code will call

Quick Summary

  • defaults — fewer overloads
  • named args — readable calls
  • any order with names
  • @JvmOverloads — Java interop
