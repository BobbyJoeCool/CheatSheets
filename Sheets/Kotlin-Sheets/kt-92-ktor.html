Kotlin's Web Framework

Ktor is JetBrains' coroutine-based framework for HTTP servers and clients. A server is built from a routing DSL and plugins (content negotiation, auth, logging, CORS). Handlers are suspend functions, so they can call other suspend APIs directly. The same library offers an HTTP client.

Key Points

  • Engines: Netty, CIO, Jetty, Tomcat
  • Plugins are installed with install(...)
  • JSON via ContentNegotiation + kotlinx.serialization
  • Generate projects at start.ktor.io

A Small REST API and Client

import io.ktor.server.engine.*
import io.ktor.server.netty.*
import io.ktor.server.application.*
import io.ktor.server.routing.*
import io.ktor.server.response.*
import io.ktor.server.request.*
import io.ktor.server.plugins.contentnegotiation.*
import io.ktor.serialization.kotlinx.json.*
import io.ktor.http.*

@Serializable
data class Todo(val id: Int, val title: String, val done: Boolean = false)
val todos = mutableListOf(Todo(1, "Write Kotlin sheets"))

fun main() {
    embeddedServer(Netty, port = 8080) {
        install(ContentNegotiation) { json() }
        routing {
            get("/todos") { call.respond(todos) }
            get("/todos/{id}") {
                val id = call.parameters["id"]?.toIntOrNull()
                val todo = todos.find { it.id == id }
                    ?: return@get call.respond(HttpStatusCode.NotFound)
                call.respond(todo)
            }
            post("/todos") {
                val todo = call.receive<Todo>()
                todos += todo
                call.respond(HttpStatusCode.Created, todo)
            }
        }
    }.start(wait = true)
}

Code Explained

install(ContentNegotiation) { json() } turns data classes into JSON
Route parameters come from call.parameters
return@get call.respond(...) ends the handler early
call.receive<Todo>() parses the request body

Java Equivalent

  • Spring Boot @RestController / @GetMapping
  • Javalin or Micronaut for small services
  • HttpClient.newHttpClient().send(…) for the client

Idiomatic Kotlin

  • blocking JDBC in handlers → withContext(Dispatchers.IO) or a suspend driver
  • all routes in one file → Route extension functions per feature

⚠ Common Mistakes

  • Forgetting install(ContentNegotiation) and getting serialization errors
  • Blocking calls on Ktor's event-loop threads
  • Not handling bad path parameters (null IDs)

✓ Tips & Best Practices

  • Install StatusPages to map exceptions to HTTP codes
  • Split routes with fun Route.todoRoutes() extensions
  • Test with testApplication { client.get(...) }
