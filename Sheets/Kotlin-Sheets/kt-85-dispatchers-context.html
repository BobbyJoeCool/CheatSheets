Dispatchers & Context

Dispatchers.Default / IO / Main · withContext · CoroutineContext · CoroutineName · limitedParallelism

Choosing Threads

A dispatcher decides which threads a coroutine runs on. Dispatchers.Default is for CPU work, Dispatchers.IO for blocking I/O such as JDBC and files, and Dispatchers.Main for UI threads. withContext(Dispatchers.IO) { } switches threads for a block and returns its result.

Key Points

  • A coroutine context holds Job, dispatcher, name and exception handler
  • Contexts combine with +
  • withContext suspends until the block finishes
  • Main needs a UI module (Android, JavaFX, Swing)

Switching Dispatchers

import kotlinx.coroutines.*

suspend fun loadUser(id: Int): User = withContext(Dispatchers.IO) {
    jdbc.queryForObject("SELECT * FROM users WHERE id = ?", id)  // blocks
}

suspend fun scoreAll(items: List<Item>): List<Int> =
    withContext(Dispatchers.Default) {
    items.map { heavyScore(it) }                                   // CPU work
}

fun main() = runBlocking(CoroutineName("main")) {
    launch(Dispatchers.Default + CoroutineName("worker")) {
        val name = coroutineContext[CoroutineName]
        println("$name on ${Thread.currentThread().name}")
        // CoroutineName(worker) on DefaultDispatcher-worker-1
    }

    val user = loadUser(1)          // caller does not care which thread
    println(user)

    val dbPool = Dispatchers.IO.limitedParallelism(10)   // at most 10 at once
    repeat(100) { launch(dbPool) { loadUser(it) } }
}

// Android / UI
// viewModelScope.launch {                     // Main by default
//     val data = repository.load()            // switches to IO inside
//     textView.text = data.title              // back on Main
// }

Code Explained

loadUser hides the thread switch, so callers stay simple
CPU-heavy work goes to Default, which has one thread per core
Context elements like CoroutineName show up in logs
limitedParallelism(10) caps concurrent database calls

Java Equivalent

  • ExecutorService pools chosen by hand (newFixedThreadPool)
  • CompletableFuture.supplyAsync(task, ioExecutor)
  • UI: SwingUtilities.invokeLater / Platform.runLater

Idiomatic Kotlin

  • blocking I/O on Default → withContext(Dispatchers.IO)
  • switching dispatchers at every call site → switch once inside the function

⚠ Common Mistakes

  • Running blocking JDBC on Default and starving CPU work
  • Updating UI from IO threads
  • Using Dispatchers.Unconfined in production code

✓ Tips & Best Practices

  • Make suspend functions main-safe: they switch dispatchers themselves
  • Turn on -Dkotlinx.coroutines.debug to see coroutine names in thread names
  • Use limitedParallelism to protect databases and APIs

Quick Summary

  • Default — CPU
  • IO — blocking I/O
  • withContext — switch for a block
  • context = Job + dispatcher + …
