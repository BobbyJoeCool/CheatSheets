Which Bean Is Which?

JavaBean · CDI bean · Enterprise Bean · Faces backing bean · JPA entity · validated bean

Description

"Bean" means six different things in Jakarta EE. They all start from JavaBeans conventions, but differ in who creates them, what scope they live in, and what services they get. Most modern code needs only two: CDI beans for logic and entities for data. Use this sheet to decode legacy code and tutorials.

Notes

  • A Faces backing bean is just a @Named CDI bean today
  • @ManagedBean (Faces) was removed in Faces 4.0
  • One class can be several kinds — an entity can also be validated
  • Never inject an entity; load it via EntityManager

Code Explained

Logic → CDI bean; data → entity; forms → @Named CDI bean
Need timers, pooling or MDBs → EJB (sheets 08–10)

Spring Equivalent

  • CDI bean → @Component / @Service
  • EJB @Stateless → @Service + @Transactional
  • Entity → same JPA @Entity · See Spring 36

Prefer / Avoid

  • @ManagedBean → @Named + CDI scope
  • @Stateless just for transactions → CDI bean + @Transactional
  • entity as REST DTO → record DTO (sheet 23)

⚠ Common Mistakes

  • Injecting with @Inject into a plain new'd JavaBean — only container-created beans get injection
  • Marking an entity @ApplicationScoped — entities aren't CDI beans; scopes don't apply
  • Keeping @ManagedBean from an old tutorial — removed in Faces 4, the bean is never found

✓ Tips & Best Practices

  • When reading old code, check imports first: jakarta.ejb, jakarta.enterprise, jakarta.persistence
  • Default to CDI; reach for EJB only for features CDI lacks
  • Keep entities free of service logic so they stay simple JavaBeans

Quick Summary

  • CDI bean — default for logic
  • EJB — pooling, timers, MDBs
  • @Entity — managed by EntityManager
  • @Named — EL name for Faces
