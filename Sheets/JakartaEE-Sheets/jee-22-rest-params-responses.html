REST 4.0

Parameters, Responses & Errors

@PathParam · @QueryParam · @BeanParam · Response · WebApplicationException · ExceptionMapper

Description

Jakarta REST injects request data into method parameters by annotation and converts strings to Java types. **Response builds any status, header or entity. Exceptions become responses: throw a WebApplicationException subclass for HTTP errors, or register an ExceptionMapper** to translate your own exceptions.

Notes

  • @DefaultValue applies when the param is missing
  • Types convert via valueOf(String), fromString or a String ctor
  • List<String> collects repeated query params

Params, Response, Mapper

@GET
public Response search(@QueryParam("q") String q,
                       @QueryParam("page") @DefaultValue("0") int page,
                       @HeaderParam("Accept-Language") String lang,
                       @BeanParam Paging paging) {
    var hits = service.search(q, page);
    return Response.ok(hits)
        .header("X-Total-Count", hits.total())
        .build();                                           // 200
}

public class Paging {                          // @BeanParam holder
    @QueryParam("size") @DefaultValue("20") public int size;
    @QueryParam("sort") public String sort;
}

@Provider
public class MissingMapper
        implements ExceptionMapper<ProductMissing> {
    public Response toResponse(ProductMissing e) {
        return Response.status(404)
            .entity(Map.of("error", e.getMessage())).build();
    }
}

Code Explained

@BeanParam — groups related params into one class
Response.ok(entity) — 200 + body; chain headers
@Provider — registers the mapper automatically
Mapper picks the closest exception type in the hierarchy

Spring Equivalent

  • @QueryParam → @RequestParam; @HeaderParam → @RequestHeader
  • ExceptionMapper → @RestControllerAdvice + ProblemDetail · See Spring 24

Prefer / Avoid

  • try/catch in every method → one ExceptionMapper
  • Response.status(404) inline → throw new NotFoundException()
  • ad-hoc error JSON → RFC 9457 problem details shape

⚠ Common Mistakes

  • int query param with no default — missing param becomes 0, hiding bugs; use Integer or @DefaultValue
  • Bad conversion on @PathParam returns 404, on @QueryParam 404 too — not 400 as many expect
  • Mapper for Exception catches WebApplicationException too — keep their status

✓ Tips & Best Practices

  • Return Optional-free domain objects; map absence to NotFoundException
  • Validate params with @Valid/constraints (sheet 31)
  • Use UriInfo.getQueryParameters() for dynamic filters

Quick Summary

  • @QueryParam — query string
  • @BeanParam — param holder
  • Response — full control
  • ExceptionMapper — exception → HTTP
