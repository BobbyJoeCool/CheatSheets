Scopes & Lifecycle

@RequestScoped · @SessionScoped · @ApplicationScoped · @ConversationScoped · @Dependent · proxies

Description

A scope decides how long a bean instance lives and who shares it. Normal scopes (request, session, application, conversation) are reached through a client proxy, so a long-lived bean can safely hold a short-lived one. **@Dependent** is a pseudo-scope: a new instance per injection point that lives and dies with its owner.

Notes

  • @Dependent is the default when no scope is given (with all discovery)
  • Session- and conversation-scoped beans must be Serializable
  • Faces adds @ViewScoped and @FlowScoped

Under the Container

  • Each scope has a context that stores its instances; the proxy looks up the current one per call
  • A @RequestScoped bean inside an @ApplicationScoped one works: the proxy finds the current request

One Bean per Scope

@RequestScoped                               // one per HTTP request
public class RequestInfo { String traceId = UUID.randomUUID().toString(); }

@SessionScoped                               // one per user session
public class UserPrefs implements Serializable { Locale locale; }

@ApplicationScoped                           // one for the whole app
public class Catalog {
    @Inject RequestInfo req;                 // proxy → current request
    @PostConstruct void warm() { loadAll(); }    // once
}

@ConversationScoped                          // spans several requests
public class Wizard implements Serializable {
    @Inject Conversation conv;
    void start() { conv.begin(); }           // until conv.end()
    void finish() { conv.end(); }
}

Code Explained

RequestInfo gets a new traceId every request, even inside Catalog
@PostConstruct — after injection; @PreDestroy — before discard
Conversation.begin() / end() — ?cid= carries it between requests

Spring Equivalent

  • @RequestScoped → @RequestScope, @SessionScoped → @SessionScope
  • @ApplicationScoped → default singleton
  • @Dependent → prototype · See Spring 11

Prefer / Avoid

  • mutable app-scoped state → narrower scope
  • storing user data in static fields → @SessionScoped
  • conversation for one page → @ViewScoped

⚠ Common Mistakes

  • final methods on a scoped bean — the proxy can't intercept them and you read its empty fields
  • Expecting @PostConstruct at startup — @ApplicationScoped is lazy; use @Observes Startup
  • Non-serializable @SessionScoped bean — session replication and passivation fail

✓ Tips & Best Practices

  • Pick the narrowest scope that works; it avoids thread-safety bugs

Quick Summary

  • normal scope — shared through a proxy
  • @Dependent — per injection point
  • @PostConstruct — after injection
  • @ConversationScoped — multi-request
