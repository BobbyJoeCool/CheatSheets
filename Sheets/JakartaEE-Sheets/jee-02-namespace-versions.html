Sheet 02
EE 8 → 11

javax → jakarta & Version History

javax.* · jakarta.* · EE 9 · EE 10 · EE 11 · OpenRewrite · Eclipse Transformer

Description

Oracle gave Java EE to Eclipse in 2017 but kept the javax name. Jakarta EE 8 was the same API under a new name; EE 9 renamed every package from javax.* to jakarta.*, which is the one breaking change most migrations are about. EE 10 and 11 then added features and raised the Java baseline. Libraries must match: a javax library won't see jakarta annotations.

Notes

  • Java SE javax.* packages (javax.sql, javax.crypto) did not move
  • EE 11 removed Managed Beans and the SecurityManager hooks
  • Spring Boot 3+ = jakarta.*; Boot 2 = javax.*
  • Hibernate 6+, Tomcat 10+, Jetty 11+ are jakarta only

Same Class, Before and After EE 9

// Java EE 8 / Jakarta EE 8
import javax.inject.Inject;
import javax.persistence.Entity;
import javax.ws.rs.GET;

// Jakarta EE 9, 10, 11
import jakarta.inject.Inject;
import jakarta.persistence.Entity;
import jakarta.ws.rs.GET;

Migrate With OpenRewrite (Maven)

mvn -U org.openrewrite.maven:rewrite-maven-plugin:run \
  -Drewrite.recipeArtifactCoordinates=\
org.openrewrite.recipe:rewrite-migrate-java:RELEASE \
  -Drewrite.activeRecipes=\
org.openrewrite.java.migrate.jakarta.JakartaEE10

Code Explained

Only the package prefix changes; class names stay
OpenRewrite also fixes persistence.xml, web.xml and dependency coordinates
Eclipse Transformer rewrites compiled jars you can't rebuild

Spring Equivalent

  • Boot 2 → 3 is the same javax → jakarta move
  • Spring's own packages (org.springframework) never changed · See Spring 01

Prefer / Avoid

  • find-and-replace javax. → a recipe that skips Java SE javax.*
  • staying on EE 8 for libraries → upgrade or shade the library
  • old XML schema URLs → jakarta.ee/xml/ns/jakartaee namespaces

⚠ Common Mistakes

  • Renaming Java SE packages too — javax.sql.DataSource must stay javax
  • Upgrading the server but not a library — e.g. an old Jersey filter compiled against javax.ws.rs
  • Forgetting XML descriptors — a javax namespace in beans.xml is ignored

✓ Tips & Best Practices

  • Run OpenRewrite on a branch, then build and test before touching anything else
  • mvn dependency:tree | grep javax finds stragglers
  • IntelliJ: Refactor › Migrate Packages and Classes › Java EE to Jakarta EE
