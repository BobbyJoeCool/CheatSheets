WebSocket 2.2

WebSocket

@ServerEndpoint · @OnOpen · @OnMessage · @OnClose · Session · encoders · broadcasting

Description

Jakarta WebSocket gives a full-duplex connection between browser and server over one TCP socket. Annotate a class with **@ServerEndpoint** and handle lifecycle callbacks. Each connection gets a Session you use to send messages; broadcasting means looping over open sessions.

Notes

  • A new endpoint instance per connection by default
  • Path params: @ServerEndpoint("/chat/{room}")
  • Encoders/decoders map messages ↔ Java objects
  • getAsyncRemote() doesn't block the sender

Chat Room Endpoint

@ServerEndpoint(value = "/chat/{room}",
                encoders = ChatJson.class, decoders = ChatJson.class)
public class ChatEndpoint {
    private static final Set<Session> sessions =
        ConcurrentHashMap.newKeySet();

    @OnOpen
    public void open(Session s, @PathParam("room") String room) {
        s.getUserProperties().put("room", room);
        sessions.add(s);
    }
    @OnMessage
    public void onMessage(ChatMsg msg, Session from) {
        sessions.stream()
            .filter(s -> s.isOpen() && room(s).equals(room(from)))
            .forEach(s -> s.getAsyncRemote().sendObject(msg));
    }
    @OnClose public void close(Session s) { sessions.remove(s); }
    @OnError public void error(Session s, Throwable t) { log(t); }
}

Code Explained

static set — shared across per-connection instances
getUserProperties() — per-session data map
sendObject — runs the encoder; sendText for raw strings
Browser: new WebSocket("wss://host/shop/chat/java")

Spring Equivalent

  • @ServerEndpoint works in Boot with ServerEndpointExporter
  • Spring's own: WebSocketHandler or STOMP @MessageMapping

Prefer / Avoid

  • getBasicRemote() in broadcasts → getAsyncRemote()
  • plain HashSet of sessions → ConcurrentHashMap.newKeySet()
  • polling every second → WebSocket or SSE

⚠ Common Mistakes

  • Non-thread-safe session collection — concurrent opens/closes throw ConcurrentModificationException
  • Blocking sends in a loop — one slow client stalls everyone
  • Forgetting wss:// behind HTTPS — browsers block mixed content

✓ Tips & Best Practices

  • Send heartbeats (sendPing) so proxies don't drop idle sockets
  • Use a ServerEndpointConfig.Configurator to read the HTTP session or auth
  • For one-way server pushes, Server-Sent Events via Jakarta REST are simpler

Quick Summary

  • @ServerEndpoint — endpoint path
  • @OnMessage — handle frames
  • Session — send / close
  • Encoder/Decoder — object mapping
