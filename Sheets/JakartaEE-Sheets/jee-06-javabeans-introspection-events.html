Introspection & Property Change Events

Introspector · BeanInfo · PropertyDescriptor · PropertyChangeSupport · bound · constrained

Description

Introspection is how tools discover a bean's properties at runtime: Introspector.getBeanInfo() returns a BeanInfo with a PropertyDescriptor for each getter/setter pair. Bound properties fire a PropertyChangeEvent when they change; constrained properties let listeners veto a change by throwing PropertyVetoException.

Notes

  • PropertyChangeSupport does the listener bookkeeping for you
  • Events fire only if old and new values differ (equals)
  • Swing uses bound properties heavily — see Swing set
  • Introspector.flushCaches() after hot-reloading classes

Under the Container

  • Properties come from method names, not fields — a field with no getter is invisible
  • BeanInfo results are cached per class, so introspection is cheap after the first call
  • EL resolves #{user.name} via BeanELResolver, which calls the descriptor's read method

Bound Property + Introspection

public class Order {
    private final PropertyChangeSupport pcs =
        new PropertyChangeSupport(this);
    private String status = "NEW";

    public String getStatus() { return status; }
    public void setStatus(String s) {
        String old = status; status = s;
        pcs.firePropertyChange("status", old, s);  // bound
    }
    public void addPropertyChangeListener(PropertyChangeListener l) {
        pcs.addPropertyChangeListener(l);
    }
}
order.addPropertyChangeListener(e ->
    log.info(e.getPropertyName() + ": " + e.getOldValue()
             + " → " + e.getNewValue()));    // status: NEW → PAID
order.setStatus("PAID");

BeanInfo info = Introspector.getBeanInfo(Order.class, Object.class);
for (PropertyDescriptor pd : info.getPropertyDescriptors())
    System.out.println(pd.getName());        // status

Code Explained

firePropertyChange — skips the event when old equals new
getBeanInfo(cls, Object.class) — stop class excludes getClass()
PropertyDescriptor — getReadMethod(), getWriteMethod(), getPropertyType()

Spring Equivalent

  • Spring BeanUtils.getPropertyDescriptors() wraps the same API
  • Spring app events (ApplicationEventPublisher) replace bean events for app logic · See Spring 60

Prefer / Avoid

  • hand-rolled listener lists → PropertyChangeSupport
  • reflection on fields → Introspector + descriptors
  • bean events for business workflows → CDI events (sheet 14)

Key Classes

Property Kinds

KindBehavior
simplegetter / setter only

⚠ Common Mistakes

  • Firing before assigning the field — listeners that read the bean see the old value
  • Forgetting the stop class — class shows up as a property from getClass()
  • Using bound properties across threads — listeners run on the caller's thread, not the UI thread

✓ Tips & Best Practices

  • Make PropertyChangeSupport field final and transient if the bean is serialized
  • Use fireIndexedPropertyChange for list-like properties
  • Prefer CDI events in server code; keep bean events for UI models

Quick Summary

  • Introspector — discovers properties
  • PropertyDescriptor — getter/setter pair
  • bound — notifies after change
  • constrained — listeners can veto
