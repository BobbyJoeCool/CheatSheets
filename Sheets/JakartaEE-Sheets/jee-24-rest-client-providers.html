REST Client, Filters & Providers

ClientBuilder · WebTarget · async client · ContainerRequestFilter · @Provider · @NameBinding · CORS

Description

The REST Client API calls other HTTP services with a fluent builder. On the server side, providers extend the runtime: filters see every request/response (auth, CORS, logging), interceptors wrap entity reading/writing, and **@NameBinding** limits a filter to annotated resources.

Notes

  • Client is heavy and thread-safe — create once, reuse
  • Pre-matching filters run before a resource is chosen
  • MicroProfile Rest Client offers a typed interface style

Client Call

Client client = ClientBuilder.newClient();          // reuse this
Product p = client.target("https://api.example.com")
    .path("products/{id}").resolveTemplate("id", 42)
    .request(MediaType.APPLICATION_JSON)
    .get(Product.class);                             // throws on 4xx/5xx
var later = client.target(url).request()
    .rx().get(Product.class);                        // async

Name-Bound Filter + CORS

@NameBinding @Retention(RUNTIME) public @interface Audited { }

@Provider @Audited
public class AuditFilter implements ContainerRequestFilter {
    public void filter(ContainerRequestContext ctx) {
        log.info(ctx.getMethod() + " " + ctx.getUriInfo().getPath());
    }
}
@Provider
public class Cors implements ContainerResponseFilter {
    public void filter(ContainerRequestContext rq,
                       ContainerResponseContext rs) {
        rs.getHeaders().add("Access-Control-Allow-Origin",
                            "https://shop.app");
    }
}

Code Explained

resolveTemplate — fills {id} safely (URL-encoded)
get(Product.class) — reads body; errors throw WebApplicationException
rx() — CompletionStage invoker
@Audited on a method/class → only those get AuditFilter

Spring Equivalent

  • Client → RestClient / HTTP interface clients (Spring 30–31)
  • ContainerRequestFilter → OncePerRequestFilter; CORS → @CrossOrigin (Spring 27)

Prefer / Avoid

  • new Client per call → one shared client
  • CORS headers in each resource → one response filter

⚠ Common Mistakes

  • Creating a Client per request — leaks connections and threads
  • CORS filter only on responses — preflight OPTIONS also needs Allow-Methods/Allow-Headers
  • Reading a Response entity twice — the stream is gone; call bufferEntity() first

✓ Tips & Best Practices

  • Register client filters with client.register(...)
  • Set connectTimeout and readTimeout on the ClientBuilder
  • Use @Priority constants from Priorities for predictable order

Quick Summary

  • ClientBuilder — outbound calls
  • ContainerRequestFilter — pre-processing
  • @NameBinding — targeted filters
  • @Provider — auto-register
