Faces 4.1

Faces Navigation, Validation & AJAX

implicit navigation · faces-redirect · f:validateBean · converters · f:ajax · ui:composition

Description

Faces navigates by view id: an action returning "orders" renders orders.xhtml. Converters turn strings into types; validators (Bean Validation by default) reject bad input. **f:ajax re-renders parts of the page without a full reload, and Facelets templates** share layouts across pages.

Notes

  • Bean Validation constraints run automatically on bound properties
  • f:ajax execute = what to submit; render = what to redraw
  • @this, @form, @all are shortcut ids
  • PrimeFaces p:ajax extends f:ajax

AJAX, Converter, Template

<!-- template.xhtml -->
<h:body><header>Shop</header><ui:insert name="content"/></h:body>

<!-- orders.xhtml -->
<ui:composition template="/template.xhtml">
  <ui:define name="content">
    <h:form id="f">
      <h:inputText id="qty" value="#{cart.qty}">
        <f:validateLongRange minimum="1" maximum="99"/>
        <f:ajax event="blur" render="total qtyMsg"/>
      </h:inputText>
      <h:message id="qtyMsg" for="qty"/>
      <h:outputText id="total" value="#{cart.total}">
        <f:convertNumber type="currency" currencySymbol="$"/>
      </h:outputText>
      <h:commandButton value="Buy" action="#{cart.buy}"/>
    </h:form>
  </ui:define>
</ui:composition>

Code Explained

ui:insert / ui:define — template slot and its content
f:ajax render — space-separated ids to redraw
f:convertNumber — formats on output, parses on input
action="#{cart.buy}" returning "done" → done.xhtml

Spring Equivalent

  • Thymeleaf layouts (th:replace) ≈ Facelets templates
  • AJAX → htmx or a JS front end with REST (Spring 28)

Prefer / Avoid

  • faces-config.xml navigation rules → implicit outcomes
  • custom Validator per field → Bean Validation annotations
  • full reloads for small updates → f:ajax

⚠ Common Mistakes

  • render id without the form prefix from outside the form — use :f:total or @form
  • Forward after POST — refresh resubmits the form; add faces-redirect=true
  • Converter on an input but not the output (or vice versa) — values round-trip inconsistently

✓ Tips & Best Practices

  • Use @FacesConverter(forClass = Sku.class, managed = true) to inject into converters
  • OmniFaces o:validateAll for cross-field checks
  • Keep one template per layout; pages only define content

Quick Summary

  • outcome — view id to show
  • faces-redirect — PRG pattern
  • f:ajax — partial update
  • ui:composition — templating
