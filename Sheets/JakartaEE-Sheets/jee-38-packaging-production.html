Sheet 38
EE 11 → EE 12

Packaging, Containers & What's Next

thin war · uber / bootable jar · Docker images · config by environment · logging · EE 12

Description

Ship a thin war onto a runtime image, or build a bootable jar that contains a trimmed server. Either way, keep config out of the artifact (env vars, MicroProfile Config) and log to stdout for containers. Jakarta EE 12 is in milestones now: Core Profile is planned for Dec 2026 and the full Platform for mid-2027.

Notes

  • Thin war + runtime image layers cache well in Docker
  • WildFly Galleon and Liberty features trim the server
  • See the Docker and Kubernetes sets for images and probes

Dockerfile — Thin War on Open Liberty

FROM icr.io/appcafe/open-liberty:full-java21-openj9-ubi-minimal
COPY --chown=1001:0 src/main/liberty/config/server.xml /config/
COPY --chown=1001:0 target/shop.war /config/apps/
RUN configure.sh                      # pre-warm, build caches
ENV INVENTORY_URL=http://inventory:9080
EXPOSE 9080

Bootable Jar (WildFly)

<plugin>
  <groupId>org.wildfly.plugins</groupId>
  <artifactId>wildfly-jar-maven-plugin</artifactId>
  <configuration>
    <feature-packs>
      <feature-pack><location>wildfly@maven(...)</location></feature-pack>
    </feature-packs>
    <layers><layer>jaxrs-server</layer></layers>
  </configuration>
</plugin>

Code Explained

configure.sh — Liberty build step that caches config for fast start
Config via env vars → read by MicroProfile Config
layers — only the subsystems the app needs
java -jar target/shop-bootable.jar runs it

Spring Equivalent

  • Bootable jar ≈ Spring Boot executable jar
  • bootBuildImage ≈ runtime base images (Spring 66)
  • GraalVM native: Quarkus/Helidon for Jakarta, Spring native for Boot (Spring 67)

Prefer / Avoid

  • config baked into the war → env vars / Config
  • log files inside containers → stdout + collector
  • full Platform image for a REST service → trimmed layers/features

⚠ Common Mistakes

  • Rebuilding the whole image for a code change — copy the war last so runtime layers stay cached
  • Health checks pointing at / — use MicroProfile Health endpoints for probes
  • Assuming EE 12 APIs are final — milestone APIs can still change

✓ Tips & Best Practices

  • Run as non-root (1001) as runtime images expect
  • Set JVM memory with -XX:MaxRAMPercentage in containers
  • Track EE 12 at jakarta.ee/specifications before upgrading

Quick Summary

  • thin war — app only
  • bootable jar — app + trimmed server
  • env config — no rebuild per env
  • EE 12 — milestones, 2026–27
