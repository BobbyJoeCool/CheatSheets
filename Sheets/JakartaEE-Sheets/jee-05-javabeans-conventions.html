Sheet 05
java.beans (Java SE)

JavaBeans Conventions

no-arg constructor · getX / setX · isX · Serializable · properties vs fields · records

Description

A JavaBean is a plain class that follows naming conventions so tools can work with it by reflection: a public no-arg constructor, private fields, and properties exposed through getX() / setX() methods (isX() for booleans). The property name comes from the method, not the field. Faces, EL, JPA and JSON-B all rely on these conventions.

Notes

  • Defined by the JavaBeans spec in Java SE (java.beans), not Jakarta
  • getFirstName() → property firstName; getURL() → URL
  • Records use name() accessors — EL 6 and JSON-B 3 understand them

A Textbook JavaBean

public class Customer implements Serializable {
    private String name;                     // backing field
    private boolean active;
    private int loyaltyPoints;

    public Customer() { }                    // required no-arg ctor

    public String getName() { return name; }           // property "name"
    public void setName(String name) { this.name = name; }

    public boolean isActive() { return active; }      // boolean: isX
    public void setActive(boolean active) { this.active = active; }

    public int getLoyaltyPoints() { return loyaltyPoints; }
    // no setter → read-only property
}

Code Explained

Serializable — needed for session-scoped beans and passivation
isActive() — only for primitive boolean; Boolean uses getActive()
A getter alone = read-only property; a setter alone = write-only
IntelliJ ⌘N › Getter and Setter generates these (IntelliJ 09)

Spring Equivalent

  • Spring binds form fields and @ConfigurationProperties to the same setters
  • Spring's BeanWrapper = Introspector + type conversion · See Spring 15

Prefer / Avoid

  • public fields for EL → private field + getter
  • getIsActive() → isActive()
  • mutable bean for DTOs → record (JSON-B, EL and Validation support it)

Where Conventions Matter

TechnologyUses
EL / Faces#{customer.name} calls getName()

Bean Validationconstraints on getters or fields

⚠ Common Mistakes

  • No no-arg constructor — frameworks that instantiate by reflection throw InstantiationException
  • getIsActive() — EL looks for isActive() / getActive() and reports the property missing
  • Mismatched types — getAge() returns int but setAge(String) makes age read-only to tools

✓ Tips & Best Practices

  • Generate accessors with the IDE; hand-typed names drift
  • Use records for immutable data, classic beans for Faces forms that need setters

Quick Summary

  • no-arg ctor — reflection can create it
  • getX / setX — property accessors
  • isX — primitive boolean getter
  • record — accessor x() supported by EL/JSON-B
