MicroProfile

@ConfigProperty · @Liveness / @Readiness · @Retry · @CircuitBreaker · OpenAPI · Telemetry · Rest Client

Description

MicroProfile is an Eclipse spec family built on the Jakarta EE Core Profile for cloud services: config, health checks, fault tolerance, OpenAPI docs, telemetry and a typed REST client. Most Jakarta runtimes (Open Liberty, WildFly, Payara, Helidon, Quarkus) support it alongside EE.

Notes

  • MicroProfile 7 builds on Jakarta EE 10 Core
  • Telemetry (OpenTelemetry) replaced Metrics and OpenTracing
  • Config sources: system props > env vars > microprofile-config.properties

Config, Health, Fault Tolerance, Rest Client

@ApplicationScoped
public class Inventory {
    @Inject @ConfigProperty(name = "inventory.url",
                            defaultValue = "http://localhost:9080")
    String url;

    @Retry(maxRetries = 3, delay = 200)
    @Timeout(2000)
    @CircuitBreaker(requestVolumeThreshold = 10, failureRatio = 0.5)
    @Fallback(fallbackMethod = "cached")
    public int stock(String sku) { return client.stock(sku); }
    int cached(String sku) { return cache.getOrDefault(sku, 0); }
}

@Readiness @ApplicationScoped
public class DbCheck implements HealthCheck {
    public HealthCheckResponse call() {
        return HealthCheckResponse.named("db").status(db.ping()).build();
    }
}

@RegisterRestClient(configKey = "inventory") @Path("/stock")
public interface InventoryClient {
    @GET @Path("{sku}") int stock(@PathParam("sku") String sku);
}

Code Explained

@ConfigProperty — injected, typed config with default
@Retry + @Timeout + @CircuitBreaker — stack in that order
@Readiness — /health/ready; @Liveness — /health/live
@RegisterRestClient — typed client; inject with @RestClient

Spring Equivalent

  • @ConfigProperty → @Value / @ConfigurationProperties (Spring 14–15)
  • Health → Actuator /actuator/health (Spring 57)
  • Fault Tolerance → @Retryable, Resilience4j (Spring 64)

Prefer / Avoid

  • config in web.xml context params → MicroProfile Config
  • hand-written retry loops → @Retry
  • manual Client code for each API → @RegisterRestClient

⚠ Common Mistakes

  • Env var names — inventory.url maps to INVENTORY_URL, not inventory_url
  • @Fallback method with a different signature — deploy fails
  • Using liveness for DB checks — the platform restarts pods during DB outages; use readiness

✓ Tips & Best Practices

  • Expose /openapi/ui in dev for a browsable API
  • Use profiles: %dev.inventory.url=…
  • Bulkhead (@Bulkhead) caps concurrent calls to slow services

Quick Summary

  • Health — probes
