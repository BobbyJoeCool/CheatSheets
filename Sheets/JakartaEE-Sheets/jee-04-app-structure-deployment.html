App Structure & Deployment

WEB-INF/ · web.xml · beans.xml · persistence.xml · war vs ear · context root

Description

A war has a fixed layout: public files at the root, and everything under **WEB-INF/** hidden from browsers. Since annotations replaced most XML, web.xml is optional and beans.xml can be empty or absent. Deploy by copying the war to the server's deploy folder, using its CLI, or with a Maven plugin.

Notes

  • src/main/webapp/ becomes the war root
  • META-INF/persistence.xml lives under src/main/resources/
  • An ear bundles several wars and EJB jars; rarely needed today
  • Context root defaults to the war name

Project → War Layout

src/main/java/com/shop/...        → WEB-INF/classes/
src/main/resources/META-INF/
    persistence.xml               → WEB-INF/classes/META-INF/
src/main/webapp/
    index.html                    → /index.html (public)
    WEB-INF/
        web.xml        (optional) → servlet config, security
        beans.xml      (optional) → CDI discovery mode
        lib/                      → third-party jars

Deploy

cp target/shop.war $WILDFLY_HOME/standalone/deployments/
$PAYARA/bin/asadmin deploy --contextroot shop target/shop.war
mvn wildfly:deploy                 # via the Maven plugin

Code Explained

WEB-INF/ — never served to clients; safe for config
beans.xml absent → annotated discovery (bean-defining annotations only)
web.xml still needed for some security and error-page setups
Hot deploy: replacing the war redeploys it

Spring Equivalent

  • Boot has no war layout: src/main/resources/static/ and application.properties
  • No beans.xml — component scan from @SpringBootApplication · See Spring 04

Prefer / Avoid

  • web.xml servlet mappings → @WebServlet
  • secrets in webapp/ → WEB-INF/ or server config
  • ear for a single web app → plain war

⚠ Common Mistakes

  • Putting persistence.xml in webapp/META-INF — JPA only reads it from the classpath
  • Assuming an empty beans.xml means all — since CDI 4 it means annotated
  • Two wars with the same context root — the second deploy fails or replaces the first

✓ Tips & Best Practices

  • Set the context root in the vendor descriptor or deploy command, not by renaming the war
  • Keep web.xml only for things annotations can't express
  • Watch the server log on deploy — CDI errors show up there, not at compile time

Quick Summary

  • WEB-INF/ — private config and classes
  • beans.xml — discovery mode
  • persistence.xml — classpath META-INF/
  • deployments/ — drop-in deploy
