REST 4.0

REST Resources

@ApplicationPath · @Path · @GET / @POST / @PUT / @DELETE · @Produces · sub-resources

Description

Jakarta REST (formerly JAX-RS) maps HTTP requests to Java methods. An Application subclass with **@ApplicationPath turns it on; each resource class** has a @Path and methods annotated with an HTTP verb. Return a Java object and a provider (JSON-B) writes the body based on **@Produces**.

Notes

  • REST 4.0 (EE 11) removed the old ManagedBean and JAXB coupling
  • Resources are CDI beans; inject freely

Under the Container

  • Resource classes are request-scoped by default — a new instance per request
  • The runtime picks a MessageBodyWriter by return type + @Produces + Accept
  • No match on @Consumes → 415; no match on @Produces → 406

CRUD Resource

@ApplicationPath("/api")
public class RestApp extends Application { }

@Path("/products")
@Produces(MediaType.APPLICATION_JSON)
@Consumes(MediaType.APPLICATION_JSON)
public class ProductResource {
    @Inject ProductRepository repo;

    @GET public List<Product> all() { return repo.findAll(); }
    @GET @Path("{id}")
    public Product one(@PathParam("id") long id) {
        return repo.findById(id).orElseThrow(NotFoundException::new);
    }
    @POST public Response create(Product p, @Context UriInfo uri) {
        repo.insert(p);
        URI loc = uri.getAbsolutePathBuilder()
            .path(String.valueOf(p.id())).build();
        return Response.created(loc).build();                 // 201
    }
    @DELETE @Path("{id}") public void delete(@PathParam("id") long id) {
        repo.deleteById(id);                                  // 204
    }
}

Code Explained

Class-level @Produces/@Consumes apply to every method
NotFoundException → 404 automatically
Response.created(uri) → 201 + Location header
void return → 204 No Content

Spring Equivalent

  • @Path + @GET → @RestController + @GetMapping
  • @PathParam → @PathVariable
  • Spring also runs Jersey via spring-boot-starter-jersey · See Spring 20

Prefer / Avoid

  • returning Response everywhere → return the entity; use Response for 201/headers
  • string-built JSON → return records/DTOs

⚠ Common Mistakes

  • Missing @ApplicationPath (and no web.xml mapping) — every endpoint returns 404
  • Two methods with the same path + verb + media type — ambiguous, request fails

✓ Tips & Best Practices

  • Constrain ids with regex: @Path("{id: \\d+}") to avoid route clashes
  • Use @Context UriInfo to build links instead of hard-coding hosts
  • See the HTTP & REST APIs set for status codes and design

Quick Summary

  • @ApplicationPath — enables REST
  • @Path — URI template
  • @GET/@POST… — verb
  • @Produces — response type
