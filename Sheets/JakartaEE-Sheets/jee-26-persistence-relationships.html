Persistence 3.2

Relationships & Inheritance

@OneToMany · @ManyToOne · @ManyToMany · mappedBy · cascade · FetchType.LAZY · @Inheritance

Description

Relationships map foreign keys to object references. The side with the foreign key is the owner; the other side uses **mappedBy and is ignored for writes. Cascade propagates operations to children; fetch type** decides when related rows load. Inheritance maps a class hierarchy to one or more tables.

Notes

  • @ManyToOne / @OneToOne default to EAGER — set LAZY
  • @OneToMany / @ManyToMany default to LAZY
  • Keep both sides in sync with helper methods
  • orphanRemoval deletes children removed from the collection

Order ↔ Lines, Many-to-Many Tags

@Entity public class PurchaseOrder {
    @Id @GeneratedValue Long id;
    @OneToMany(mappedBy = "order", cascade = CascadeType.ALL,
               orphanRemoval = true)
    private List<OrderLine> lines = new ArrayList<>();

    public void addLine(OrderLine l) { lines.add(l); l.setOrder(this); }
}

@Entity public class OrderLine {
    @Id @GeneratedValue Long id;
    @ManyToOne(fetch = FetchType.LAZY, optional = false)
    @JoinColumn(name = "order_id")              // owner: has the FK
    private PurchaseOrder order;
}

@Entity public class Product {
    @ManyToMany
    @JoinTable(name = "product_tags",
        joinColumns = @JoinColumn(name = "product_id"),
        inverseJoinColumns = @JoinColumn(name = "tag_id"))
    private Set<Tag> tags = new HashSet<>();
}

Code Explained

mappedBy = "order" — field name on the owning side
CascadeType.ALL — persist/remove lines with the order
addLine — sets both sides so memory matches the DB
Set for many-to-many avoids duplicate-row deletes

Spring Equivalent

  • Identical mappings in Spring Data JPA
  • Spring's @EntityGraph on repository methods ≈ entity graphs here · See Spring 37

Prefer / Avoid

  • EAGER @ManyToOne → fetch = LAZY + fetch joins
  • CascadeType.ALL on @ManyToOne → cascade only parent → child
  • List for @ManyToMany → Set

⚠ Common Mistakes

  • Setting only the inverse side — mappedBy side is ignored, so the FK stays null
  • CascadeType.REMOVE on many-to-many — deleting one product deletes shared tags
  • Lazy access after the transaction ends — LazyInitializationException (Hibernate)

✓ Tips & Best Practices

  • Default every to-one to LAZY and load what you need per query (sheet 28)
  • Use @MappedSuperclass for shared audit columns
  • Prefer JOINED when subclasses add many columns

Quick Summary

  • owner — side with @JoinColumn
  • mappedBy — inverse side
  • cascade — propagate ops
  • @Inheritance — hierarchy mapping
