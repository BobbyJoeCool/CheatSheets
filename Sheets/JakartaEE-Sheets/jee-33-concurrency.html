Concurrency 3.1

Concurrency

ManagedExecutorService · @ManagedExecutorDefinition · @Asynchronous · context propagation · virtual threads

Description

Jakarta Concurrency gives you executors that the server manages and that carry the container context (security, naming, CDI) into the task. EE 11's 3.1 adds virtual threads (virtual = true), CDI @Asynchronous with scheduling, and injectable executors via qualifiers.

Notes

  • Never create raw threads in a server app
  • Every server has a default ManagedExecutorService
  • @Asynchronous methods return CompletableFuture

Under the Container

  • Managed executors propagate security, naming and CDI context that a raw ExecutorService drops
  • The server tracks and stops managed tasks at undeploy
  • virtual = true runs tasks on virtual threads (Java 21+)

Executors and @Asynchronous

@ManagedExecutorDefinition(name = "java:app/concurrent/io",
                           maxAsync = 50, virtual = true)
@ApplicationScoped
public class ReportService {
    @Resource(lookup = "java:app/concurrent/io")
    ManagedExecutorService io;

    public CompletableFuture<Report> build(long id) {
        return io.supplyAsync(() -> render(id));     // context propagated
    }

    @Asynchronous(executor = "java:app/concurrent/io")
    public CompletableFuture<Void> email(long id) {
        mailer.send(id);
        return Asynchronous.Result.complete(null);
    }

    @Asynchronous(runAt = @Schedule(cron = "0 2 * * *"))   // 3.1
    public void nightly() { purgeOld(); }
}

Code Explained

@ManagedExecutorDefinition — declare an executor in code
supplyAsync — managed CompletableFuture
runAt = @Schedule — cron scheduling without EJB

Spring Equivalent

  • @Asynchronous → @Async (Spring 62)
  • virtual = true → spring.threads.virtual.enabled=true
  • runAt → @Scheduled(cron = …) (Spring 61)

Prefer / Avoid

  • new Thread() / Executors.newFixedThreadPool → managed executor
  • EJB @Asynchronous → Concurrency @Asynchronous
  • EJB timers without persistence → @Asynchronous(runAt)

⚠ Common Mistakes

  • Using ForkJoinPool.commonPool() (CompletableFuture.supplyAsync without executor) — tasks lose security and CDI context
  • Using @RequestScoped beans in async tasks — the request is over; pass data in
  • Blocking on .get() right after submitting — no concurrency gained

✓ Tips & Best Practices

  • Use qualifiers (3.1) to inject executors without JNDI strings
  • Cap maxAsync to protect downstream systems
  • Prefer virtual threads for blocking I/O work

Quick Summary

  • ManagedExecutorService — server-managed pool
  • @Asynchronous — async CDI method
  • virtual = true — virtual threads
  • runAt — scheduled method
