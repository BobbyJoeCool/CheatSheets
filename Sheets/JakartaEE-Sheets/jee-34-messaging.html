Messaging 3.1

Messaging

JMSContext · queues vs topics · @MessageDriven · MessageListener · acknowledgement · @JMSConnectionFactoryDefinition

Description

Jakarta Messaging (JMS) sends messages through a broker. A queue delivers each message to one consumer; a topic delivers to every subscriber. Send with the simplified **JMSContext API; consume with a message-driven bean**, which the container pools and wraps in a transaction.

Notes

  • Platform profile only
  • Brokers: ActiveMQ Artemis (WildFly, Payara), Liberty built-in
  • Messages: TextMessage, ObjectMessage, MapMessage…

Under the Container

  • Message-driven beans are pooled consumers; many messages process in parallel
  • The container acknowledges the message when the MDB's transaction commits
  • On rollback the broker redelivers; set a max-redelivery and dead-letter queue

Send and Consume

@ApplicationScoped
public class OrderPublisher {
    @Inject JMSContext jms;                         // container-managed
    @Resource(lookup = "java:app/jms/orders") Queue orders;

    public void publish(Order o) {
        jms.createProducer()
           .setProperty("priority", o.vip() ? "high" : "normal")
           .send(orders, jsonb.toJson(o));          // TextMessage
    }
}

@MessageDriven(activationConfig = {
    @ActivationConfigProperty(propertyName = "destinationLookup",
                              propertyValue = "java:app/jms/orders"),
    @ActivationConfigProperty(propertyName = "messageSelector",
                              propertyValue = "priority = 'high'") })
public class VipOrderListener implements MessageListener {
    public void onMessage(Message m) {
        Order o = jsonb.fromJson(((TextMessage) m).getText(), Order.class);
        fulfil(o);                                  // throws → redelivery
    }
}

Code Explained

createProducer().send() — one line to send
messageSelector — SQL-like filter on properties
Exception in onMessage → rollback → redelivery

Spring Equivalent

  • MDB → @JmsListener (Spring JMS) or @KafkaListener
  • JMSContext → JmsTemplate / JmsClient

Prefer / Avoid

  • ObjectMessage with Java serialization → JSON TextMessage
  • classic Connection/Session code → JMSContext
  • non-idempotent consumers → handle redelivered duplicates

⚠ Common Mistakes

  • Poison message with no redelivery limit — fails and redelivers forever
  • Non-durable topic subscriber — messages sent while it's down are gone

✓ Tips & Best Practices

  • Configure a dead-letter queue and max delivery attempts on the broker
  • Make consumers idempotent (dedupe by message id or business key)
  • Use JMSContext.createSharedDurableConsumer for scaled topic consumers

Quick Summary

  • queue — point-to-point
  • topic — publish/subscribe
  • JMSContext — simplified send
  • @MessageDriven — pooled consumer
