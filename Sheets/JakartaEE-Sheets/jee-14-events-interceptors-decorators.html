Events, Interceptors & Decorators

Event<T>.fire() · @Observes · @ObservesAsync · @InterceptorBinding · @AroundInvoke · @Decorator

Description

Events decouple beans: a producer fires an object, every matching observer receives it. Interceptors wrap method calls with cross-cutting logic (timing, logging, auditing) bound by an annotation. Decorators wrap a specific interface to add business behavior. All three run through the same container proxy.

Notes

  • Sync observers run in the firing thread and transaction
  • @Observes(during = AFTER_SUCCESS) waits for commit
  • Decorators are CDI Full only

Under the Container

  • Interceptors and decorators are applied through the bean's proxy
  • Self-invocation (this.save()) bypasses them — call through an injected reference
  • Lower @Priority value runs first (outermost) for interceptors

Event + Interceptor

@Inject Event<OrderPlaced> placed;
void checkout(Order o) { placed.fire(new OrderPlaced(o.id())); }

void email(@Observes OrderPlaced e) { mailer.confirm(e.id()); }
void stats(@ObservesAsync OrderPlaced e) { metrics.inc(); } // fireAsync

@InterceptorBinding @Retention(RUNTIME) @Target({TYPE, METHOD})
public @interface Timed { }

@Timed @Interceptor @Priority(Interceptor.Priority.APPLICATION)
public class TimedInterceptor {
    @AroundInvoke
    Object time(InvocationContext ctx) throws Exception {
        long t0 = System.nanoTime();
        try { return ctx.proceed(); }                  // call the method
        finally { log.info(ctx.getMethod().getName() + " "
                  + (System.nanoTime() - t0) / 1_000_000 + "ms"); }
    }
}
@Timed @ApplicationScoped public class ReportService { }   // all methods

Code Explained

fire() — sync observers only; fireAsync() — async observers, returns CompletionStage
@InterceptorBinding — the annotation that links bean → interceptor
ctx.proceed() — calls the next interceptor or the target
Interceptor.Priority.APPLICATION = 2000

Spring Equivalent

  • Event<T> → ApplicationEventPublisher, @Observes → @EventListener (Spring 60)
  • Interceptor → @Aspect + @Around (Spring 19)
  • AFTER_SUCCESS → @TransactionalEventListener

Prefer / Avoid

  • direct calls to five services → one event, five observers
  • logging boilerplate in every method → @Timed interceptor
  • side effects before commit → @Observes(during = AFTER_SUCCESS)

Transaction Phases

IN_PROGRESSimmediately (default)
BEFORE_COMPLETIONjust before commit
AFTER_COMPLETIONafter commit or rollback
AFTER_SUCCESSonly after commit
AFTER_FAILUREonly after rollback

⚠ Common Mistakes

  • Expecting fireAsync() to reach @Observes methods — only @ObservesAsync observers get async events
  • Interceptor without @Priority — never enabled unless listed in beans.xml
  • Throwing from a sync observer — the exception propagates and can roll back the firing transaction

✓ Tips & Best Practices

  • Fire immutable records as event payloads
  • Use qualifiers on events (Event<@Express OrderPlaced>) to target observers
  • Put binding annotations on the class to cover every method

Quick Summary

  • Event.fire() — sync broadcast
  • @ObservesAsync — async observer
  • @AroundInvoke — wrap calls
  • @Decorator — typed wrapper (Full)
