Validation 3.1

Bean Validation

@NotNull · @Size · @Email · @Valid · groups · ConstraintValidator · method validation · records

Description

Jakarta Validation declares rules as annotations on fields, getters, parameters, return values and record components. REST, Faces, Persistence and CDI run validation automatically; elsewhere call a Validator. **@Valid cascades into nested objects; groups** select which constraints apply.

Notes

  • REST returns 400 on violations of @Valid parameters
  • JPA validates on persist/update by default
  • Validation 3.1 (EE 11) supports records

Constraints, Cascade, Custom

public record SignupForm(
    @NotBlank @Size(max = 50) String name,
    @NotNull @Email String email,
    @Min(18) int age,
    @Valid @NotNull Address address,              // validate nested
    @Sku String favouriteSku) { }

@POST public Response signup(@Valid SignupForm form) { ... }  // 400 if bad

@Constraint(validatedBy = SkuValidator.class)
@Target({FIELD, PARAMETER, RECORD_COMPONENT}) @Retention(RUNTIME)
public @interface Sku {
    String message() default "invalid SKU";
    Class<?>[] groups() default {};
    Class<? extends Payload>[] payload() default {};
}
public class SkuValidator implements ConstraintValidator<Sku, String> {
    public boolean isValid(String v, ConstraintValidatorContext c) {
        return v == null || v.matches("[A-Z]{3}-\\d+");   // null = valid
    }
}

Set<ConstraintViolation<SignupForm>> errs = validator.validate(form);

Code Explained

@NotBlank — not null and not whitespace (strings only)
@Valid on a param — REST/CDI validate before the method runs
Custom constraint = annotation + ConstraintValidator
Return true for null and pair with @NotNull if required

Spring Equivalent

  • Spring uses the same jakarta.validation annotations
  • @Valid on @RequestBody; @Validated for method validation · See Spring 23

Prefer / Avoid

  • if (x == null) throw checks → constraint annotations
  • validation logic in controllers → on the DTO
  • one-off @Pattern repeated → custom constraint

⚠ Common Mistakes

  • @NotNull on a primitive int — never null, so it never fails; use @Min or Integer
  • Forgetting @Valid on a nested object — its constraints are skipped
  • Throwing from isValid — return false and let the framework build the violation

✓ Tips & Best Practices

  • Map ConstraintViolationException to a clean 400 body with an ExceptionMapper
  • Use @AssertTrue methods for cross-field rules
  • Put messages in ValidationMessages.properties for i18n

Quick Summary

  • @NotNull etc. — declarative rules
  • @Valid — cascade / trigger
  • groups — conditional rules
  • ConstraintValidator — custom logic
