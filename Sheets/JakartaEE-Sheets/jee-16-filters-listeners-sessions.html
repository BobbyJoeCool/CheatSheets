Filters, Listeners & Sessions

@WebFilter · FilterChain · @WebListener · ServletContextListener · HttpSession · cookies

Description

Filters wrap every request that matches their pattern, before and after the target runs: logging, auth checks, headers, compression. Listeners react to lifecycle events (app start, session created). Sessions keep per-user state on the server, identified by a JSESSIONID cookie.

Notes

  • Filter order: web.xml order; annotation order is unspecified
  • Session timeout default is server-specific (often 30 min)
  • getSession(false) returns null instead of creating one
  • Mark session cookies HttpOnly and Secure

Filter, Listener, Session

@WebFilter("/*")
public class TimingFilter implements Filter {
    public void doFilter(ServletRequest req, ServletResponse res,
            FilterChain chain) throws IOException, ServletException {
        long t0 = System.nanoTime();
        chain.doFilter(req, res);                     // run the rest
        log.info("took " + (System.nanoTime() - t0) / 1e6 + " ms");
    }
}

@WebListener
public class Startup implements ServletContextListener {
    public void contextInitialized(ServletContextEvent e) {
        log.info("app started");
    }
}

HttpSession s = req.getSession();                     // create if absent
s.setAttribute("cartId", 42);
Integer cart = (Integer) s.getAttribute("cartId");    // 42
s.setMaxInactiveInterval(15 * 60);                    // seconds
s.invalidate();                                       // logout

Code Explained

chain.doFilter — skip it to block the request (e.g. 401)
ServletContextListener — app start/stop hooks
setMaxInactiveInterval — per-session idle timeout in seconds
invalidate() — drops all attributes and the id

Spring Equivalent

  • Filter → OncePerRequestFilter / HandlerInterceptor (Spring 27)
  • Session → @SessionScope bean or Spring Session
  • Listener → ApplicationReadyEvent

Prefer / Avoid

  • session attributes for user data → @SessionScoped CDI bean
  • auth checks in every servlet → one filter or Jakarta Security
  • HttpSessionListener counters → metrics (MicroProfile)

⚠ Common Mistakes

  • Forgetting chain.doFilter — the request silently stops with an empty 200
  • Storing large objects in the session — memory per user, and replication cost in clusters
  • Using URL rewriting (;jsessionid=) — leaks session ids in logs and referrers

✓ Tips & Best Practices

  • Cast to HttpServletRequest inside filters to read headers and paths
  • Rotate the session id after login: req.changeSessionId()
  • Keep filters thin; heavy logic belongs in services

Quick Summary

  • @WebFilter — wrap requests
  • FilterChain.doFilter — continue
  • @WebListener — lifecycle hooks
  • HttpSession — per-user state
