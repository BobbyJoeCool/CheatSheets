Testing Jakarta Apps

JUnit unit tests · Weld JUnit · Arquillian · Testcontainers · REST Assured · mocking EntityManager

Description

Test Jakarta code in three layers. Unit tests construct beans directly with mocks (constructor injection makes this easy). CDI tests boot a lightweight container (Weld JUnit) to check wiring. Integration tests deploy to a real runtime, via Arquillian or a Testcontainers server image, and hit it over HTTP with REST Assured.

Notes

  • The JUnit set covers JUnit itself
  • Runtimes with dev mode (Liberty, WildFly) also run tests against a live server
  • Use Testcontainers for the database even in unit-ish tests

Unit, CDI and Integration Tests

class PriceServiceTest {                         // plain unit test
    @Test void appliesDiscount() {
        var repo = mock(ProductRepository.class);
        when(repo.price("MUG")).thenReturn(new BigDecimal("10"));
        var svc = new PriceService(repo);         // constructor injection
        assertEquals(new BigDecimal("9.00"), svc.discounted("MUG"));
    }
}

@EnableAutoWeld @AddBeanClasses({PriceService.class, FakeRepo.class})
class PriceWiringTest {                          // real CDI container
    @Inject PriceService svc;
    @Test void wires() { assertNotNull(svc); }
}

@Testcontainers
class ProductApiIT {                             // real server
    @Container static GenericContainer<?> app =
        new GenericContainer<>("shop-wildfly").withExposedPorts(8080);
    @Test void lists() {
        given().port(app.getMappedPort(8080))
            .get("/shop/api/products").then().statusCode(200);
    }
}

Code Explained

Mock repositories, not the EntityManager, where you can
@EnableAutoWeld — Weld JUnit 5 extension; add beans explicitly
GenericContainer — your app image with the war deployed
REST Assured given().get().then() — HTTP assertions

Spring Equivalent

  • @SpringBootTest ≈ integration test; @WebMvcTest slices ≈ CDI tests (Spring 52–53)
  • Testcontainers works the same in both · See Spring 56

Prefer / Avoid

  • Arquillian for every test → unit tests + a few integration tests
  • mocking EntityManager chains → test with a real DB container
  • field injection in beans under test → constructor injection

⚠ Common Mistakes

  • Mocking EntityManager query chains — brittle and proves nothing about the SQL
  • Running integration tests with Surefire — they run before the war is built
  • Sharing a mutable container between tests without cleanup — order-dependent failures

✓ Tips & Best Practices

  • Make beans constructor-injected so tests need no container
  • Reuse containers across a test class with static
  • Name integration tests *IT so Failsafe picks them up

Quick Summary

  • unit — new + mocks
  • Weld JUnit — CDI wiring
  • Testcontainers — real DB / server
  • REST Assured — HTTP checks
