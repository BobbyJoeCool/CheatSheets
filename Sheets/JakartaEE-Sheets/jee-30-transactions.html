Transactions 2.0

Transactions

JTA · @Transactional · TxType · rollbackOn · @TransactionAttribute · UserTransaction

Description

Jakarta EE uses JTA transactions managed by the container. Put **@Transactional on a CDI bean class or method and the interceptor starts, joins or suspends a transaction based on TxType**. EJBs are transactional by default (@TransactionAttribute). Use **UserTransaction** only for manual control.

Notes

  • @Transactional from jakarta.transaction, not Spring's
  • Default type is REQUIRED
  • Persistence EntityManager joins the JTA transaction

Under the Container

  • JTA binds the transaction to the current thread
  • REQUIRED joins an existing transaction; REQUIRES_NEW suspends it and starts another
  • Unchecked exceptions roll back; checked exceptions commit unless listed in rollbackOn

Declarative and Manual

@ApplicationScoped
public class PaymentService {
    @Inject AuditLog audit;
    @PersistenceContext EntityManager em;

    @Transactional(rollbackOn = PaymentDeclined.class)
    public void charge(Order o) throws PaymentDeclined {
        em.persist(new Payment(o));
        audit.record("charge " + o.id());   // runs in its own tx
        gateway.charge(o);                  // may throw
    }
}
@ApplicationScoped
public class AuditLog {
    @Transactional(Transactional.TxType.REQUIRES_NEW)
    public void record(String msg) { em.persist(new AuditEntry(msg)); }
}

@Resource UserTransaction utx;              // manual (rare)
utx.begin();
try { work(); utx.commit(); }
catch (Exception e) { utx.rollback(); throw e; }

Code Explained

rollbackOn — make a checked exception roll back
REQUIRES_NEW — audit entry commits even if charge rolls back
Must call record through the injected bean, not this
UserTransaction — bean-managed; don't mix with @Transactional

Spring Equivalent

  • @Transactional → Spring @Transactional (rollbackFor, propagation)
  • TxType names match Spring Propagation · See Spring 42

Prefer / Avoid

  • @Stateless just for transactions → CDI + @Transactional
  • UserTransaction boilerplate → @Transactional
  • transactions on REST resources → on the service layer

⚠ Common Mistakes

  • Importing Spring's @Transactional in a Jakarta app — nothing intercepts it
  • Self-invocation of a REQUIRES_NEW method — runs in the caller's transaction
  • Catching the exception inside the method — the interceptor never sees it, so it commits

✓ Tips & Best Practices

  • Keep transactions short; no remote calls inside if you can help it
  • Use @Transactional(dontRollbackOn = …) for expected business exceptions
  • Observe AFTER_SUCCESS events for work that must follow a commit

Quick Summary

  • @Transactional — CDI interceptor
  • REQUIRED — join or start
  • REQUIRES_NEW — independent tx
  • rollbackOn — checked rollback
