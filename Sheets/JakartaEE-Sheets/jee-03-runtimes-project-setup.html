Sheet 03
Platform API 11.0

Runtimes & Project Setup

WildFly · Payara · Open Liberty · GlassFish · jakarta.jakartaee-api · provided · war

Description

A Jakarta EE app is usually a war that runs inside a compatible runtime. The server already contains every spec implementation, so your build depends on the API jar with provided scope: you compile against it but never ship it. Pick the Web or Platform API to match your runtime's profile.

Notes

  • jakartaee-api = Platform · jakartaee-web-api = Web · jakartaee-core-api = Core
  • Runtimes list their EE 11 certification on jakarta.ee/compatibility
  • Open Liberty and Payara Micro also run as an executable jar
  • Gradle: compileOnly is the same as Maven's provided

Under the Container

  • The server provides the API jars — provided keeps a second copy out of the war
  • Each app gets its own classloader; server classes load first for jakarta.*
  • Bundling a spec jar loads two copies of a class → ClassCastException on the same type name

pom.xml — the Minimal Jakarta EE 11 War

<packaging>war</packaging>
<properties>
  <maven.compiler.release>21</maven.compiler.release>
</properties>
<dependencies>
  <dependency>
    <groupId>jakarta.platform</groupId>
    <artifactId>jakarta.jakartaee-api</artifactId>
    <version>11.0.0</version>
    <scope>provided</scope>
  </dependency>
</dependencies>
<build><finalName>shop</finalName></build>

Code Explained

war — web archive the server deploys
jakarta.jakartaee-api — all Platform APIs, compile only
provided — on the classpath at build time, not in WEB-INF/lib
finalName — shop.war, default context root /shop

Spring Equivalent

  • Spring Boot ships the server inside the jar (embedded Tomcat)
  • spring-boot-starter-* replaces the API jar · See Spring 03

Prefer / Avoid

  • compile scope on the API → provided
  • pinning each spec version → one jakartaee-api version
  • copying a 2015 pom → generate one at start.jakarta.ee

⚠ Common Mistakes

  • Using compile scope — the war carries API jars that clash with the server's
  • Compiling for Java 21 but running the server on 17 — UnsupportedClassVersionError
  • Depending on Hibernate directly for basics — ties the war to one runtime

✓ Tips & Best Practices

  • Use the runtime's Maven plugin dev mode for redeploy on save
  • Add vendor jars (Hibernate extras) as provided when the server has them
  • Match jakartaee-web-api to TomEE/Web-only servers so Platform APIs fail at compile time

Quick Summary

  • provided — compile against, don't ship
  • jakartaee-api — one dependency for all specs
  • war — standard deployable
  • dev goals — live redeploy
