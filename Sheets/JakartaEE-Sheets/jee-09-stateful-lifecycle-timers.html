Sheet 09
Enterprise Beans 4.0

Stateful Beans, Lifecycle & Timers

@Stateful · @Remove · @PostConstruct · passivation · @Asynchronous · @Schedule · TimerService

Description

A **@Stateful bean keeps state for one client across calls (a shopping cart), and the container may passivate it to disk when idle. EJBs also give you timers** (@Schedule for cron-style, TimerService for programmatic) and **@Asynchronous** methods that return a Future. Timers are the main reason EJB survives in new code.

Notes

  • @Remove ends a stateful bean; otherwise it times out
  • Passivated beans must be Serializable (fields too)
  • @Schedule(persistent=false) skips the timer database
  • EE 11 Concurrency @Asynchronous is the CDI alternative

Cart, Nightly Job and Async Call

@Stateful @StatefulTimeout(value = 30, unit = MINUTES)
public class Cart implements Serializable {
    private final List<Item> items = new ArrayList<>();
    public void add(Item i) { items.add(i); }
    @Remove public Order checkout() { return Order.of(items); }
}

@Singleton
public class Jobs {
    @Schedule(hour = "2", minute = "0", persistent = false)
    void nightlyCleanup() { /* 02:00 every day */ }

    @Resource TimerService timers;
    public void remindIn(Duration d) {
        timers.createSingleActionTimer(d.toMillis(), new TimerConfig());
    }
    @Timeout void onTimer(Timer t) { /* fires once */ }

    @Asynchronous
    public Future<Report> build() { return new AsyncResult<>(make()); }
}

Code Explained

@StatefulTimeout — idle time before the container removes it
@Remove — call it to end the conversation and free memory
@Schedule — cron fields: second minute hour dayOfMonth month dayOfWeek year
@Timeout — callback for programmatic timers

Spring Equivalent

  • @Schedule → @Scheduled(cron=…) (Spring 61)
  • @Asynchronous → @Async + CompletableFuture (Spring 62)
  • @Stateful → @SessionScope bean

Prefer / Avoid

  • AsyncResult + Future → CompletableFuture (EJB 3.2+)
  • persistent timers by default → persistent = false unless they must survive restarts
  • stateful EJB for web carts → @SessionScoped CDI bean

⚠ Common Mistakes

  • Forgetting hour = "*" — @Schedule defaults hour to 0, so minute="*/5" only fires during midnight
  • Non-serializable fields in a stateful bean — passivation fails and the bean is discarded
  • Never calling @Remove — stateful beans pile up until timeout

✓ Tips & Best Practices

  • Put @Schedule methods on a @Singleton so two nodes don't double-run without clustering
  • Use timers.getTimers() to list and cancel active timers
  • Prefer ManagedScheduledExecutorService (sheet 33) when you don't need persistence

Quick Summary

  • @Stateful — one per client
  • @Remove — end conversation
  • @Schedule — cron timer
  • @Asynchronous — returns a Future
