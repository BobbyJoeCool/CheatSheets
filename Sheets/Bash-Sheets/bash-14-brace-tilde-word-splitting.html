Sheet 14

Brace, Tilde & Word Splitting

{a,b} · {1..10} · ~ · expansion order · IFS · word splitting · "$var"

How a Line Becomes Words

Bash transforms every command line through a fixed sequence of expansions before running it. Brace expansion happens first, before variables, which is why {1..$n} doesn't work. After variables and command substitutions expand, any unquoted result is split on IFS and then globbed. Quoting stops both steps, which is why "$var" is the safe default.

Notes

  • Brace expansion makes strings; it doesn't check files exist (unlike globs)
  • Default IFS is space, tab, newline
  • Empty unquoted variables vanish entirely; quoted ones become ""
  • set -f disables globbing; IFS= disables splitting

Expansions & Splitting

echo {a,b,c}.txt              # a.txt b.txt c.txt
mkdir -p src/{lib,test,docs}  # three directories at once
cp config.yml{,.bak}          # cp config.yml config.yml.bak
echo {1..5} {a..e}            # 1 2 3 4 5 a b c d e
echo {01..10..3}              # 01 04 07 10   (zero-pad + step, 4.0+)
echo ~ ~root                  # /home/ada /root
cd ~-                         # previous directory ($OLDPWD)

line="a  b   c"
printf '[%s]' $line; echo     # [a][b][c]        (split on IFS)
printf '[%s]' "$line"; echo   # [a  b   c]       (quoted: one word)
IFS=: read -ra dirs <<< "$PATH"   # split PATH on colons
n=3; echo {1..$n}             # {1..3}   braces expand before $n
for ((i = 1; i <= n; i++)); do echo "$i"; done   # use this instead
x='*'; echo $x                # lists files: unquoted result is globbed

Code Explained

{,.bak} — empty first item gives the name itself, then with .bak
{01..10..3} — leading zero pads every number; third field is the step
~- / ~+ — $OLDPWD / $PWD
$line unquoted — runs of spaces collapse to single separators
IFS=: before read — changes IFS only for that command
echo $x — word splitting and globbing apply to the value

Expansion Order

StepExpansion
1brace {a,b} {1..9}
2tilde ~ ~user
3parameter, arithmetic, command subst. (left to right)
4word splitting on IFS (unquoted only)
5pathname (glob) expansion
6quote removal

⚠ Common Mistakes

  • {1..$n} doesn't expand, because braces run before variables; use a C-style for or seq
  • "~/file" in quotes stays a literal tilde; use "$HOME/file" or leave ~/ unquoted
  • rm $file where the name has a space removes two different files (or fails)
  • Changing IFS globally and forgetting to reset it breaks later code; scope it: IFS=, read …

✓ Tips & Best Practices

  • Quote every expansion unless you want splitting: "$v", "$(cmd)", "${a[@]}"
  • Backup before editing: cp file{,.orig}; restore: mv file{.orig,}
  • Need splitting on purpose? Use read -ra arr <<< "$s" instead of $s
  • ShellCheck flags almost every unquoted variable (SC2086)

Quick Summary

  • {a,b} / {1..n} — generate words (literal numbers only)
  • ~ — home directory, unquoted only
  • Order: brace → tilde → $ → split → glob
  • IFS — controls splitting
  • "$var" — no splitting, no globbing
