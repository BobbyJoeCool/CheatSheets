Reusable Commands

A function is a named group of commands that you call like any other command, with its own arguments in $1, $2, "$@". Functions don't return values the way most languages do: return sets an exit status (0–255), and "returned data" is whatever the function prints, captured with $(fn). Variables are global unless declared local.

Notes

  • Define a function before the line that calls it
  • Functions run in the current shell, so cd and variables persist
  • Without return, the status is that of the last command
  • $0 is still the script name inside a function; use $FUNCNAME

Defining & Calling

greet() {                         # POSIX-style definition
  local name=${1:-world}          # first argument, with a default
  echo "Hello, $name"
}
greet                             # Hello, world
greet Ada                         # Hello, Ada
msg=$(greet Bob)                  # capture output: "Hello, Bob"

is_even() { (( $1 % 2 == 0 )); }  # status of last command is returned
is_even 4 && echo even            # even

die() { echo "error: $*" >&2; exit 1; }
[[ -f app.cfg ]] || die "app.cfg missing"

split_name() {                    # write results into caller's vars
  local -n _first=$2 _last=$3     # namerefs (4.3+)
  _first=${1%% *}; _last=${1##* }
}
split_name "Ada Lovelace" f l; echo "$l, $f"   # Lovelace, Ada

Code Explained

${1:-world} — default when no argument is passed
$(greet Bob) — runs in a subshell; only stdout comes back
(( … )) as the last command — makes the function a true/false test
$* in die — all arguments joined into one message
exit — ends the whole script; return ends just the function
local -n — writes go to the variable named by the argument

⚠ Common Mistakes

  • return "text" errors: return only takes a number 0–255; print the text instead
  • local out=$(cmd) hides cmd's failure (status comes from local); split it: local out; out=$(cmd)
  • Debug echos inside a function you capture with $(…) end up in the result; send them to >&2
  • Calling a function before it's defined in the file: "command not found"

✓ Tips & Best Practices

  • Structure scripts as functions plus a final main "$@"
  • Always pass arguments through with "$@", never $*
  • Return true/false with exit status so callers can write if valid "$x"
  • Prefix nameref locals (_first) so they can't collide with the caller's names

Quick Summary

  • f() { …; } — define
  • f arg1 arg2 — call
  • local — keep variables private
  • return n — status; echo — data
  • $(f) — capture output
