Branching

if runs a command and branches on its exit status; [[ ]] is just one such command, so if grep -q … works directly. case matches one value against glob patterns and is the cleanest way to handle subcommands and options. select prints a numbered menu, reads a choice, and loops until you break.

Notes

  • then needs a newline or ; before it: if cmd; then
  • case patterns are globs, tried top to bottom; first match wins
  • select puts the chosen item in the variable and the typed number in $REPLY
  • An empty if body is a syntax error; use : as a placeholder

if & select

if [[ -f config.yml ]]; then
  echo "using YAML"
elif [[ -f config.json ]]; then
  echo "using JSON"
else
  echo "no config" >&2
  exit 1
fi

if ! grep -q "ready" status.txt; then
  echo "not ready yet"
fi

PS3="Deploy to: "
select env in dev staging prod quit; do
  [[ $env == quit ]] && break
  [[ -n $env ]] && echo "→ $env (#$REPLY)"
done

case

case "$1" in
  start|up)
    echo "starting" ;;
  stop)
    echo "stopping" ;;
  *.tar.gz|*.tgz)
    tar xzf "$1" ;;
  -h|--help)
    usage ;;
  [0-9]*)
    echo "number: $1" ;;
  "")
    echo "missing argument" >&2 ;;
  *)
    echo "unknown: $1" >&2
    exit 1 ;;
esac

⚠ Common Mistakes

  • a && b || c as if/else: if b fails, c runs too; use a real if when b can fail
  • Forgetting ;; at the end of a case branch: syntax error near the next pattern
  • Quoting a pattern in case: "*.txt") matches only the literal text *.txt
  • Writing if [[ … ]] then without ; or a newline before then

✓ Tips & Best Practices

  • Order case branches from specific to general; put *) last
  • Use case instead of long elif chains on one variable
  • One-liners: [[ -d $d ]] || mkdir -p "$d"
  • Exit with a usage message in the *) branch

Quick Summary

  • if cmd; then … elif … else … fi — branch on status
  • case $x in pat) … ;; esac — match patterns
  • ;& / ;;& — fall through / keep testing
  • select v in …; do … done — numbered menu
