Sheet 07

Variables & declare

name=value · declare · local · readonly · export · declare -n · unset

Variables

Assign with name=value and no spaces around =; read with $name or ${name}. All bash variables are strings unless you give them an attribute with declare (-i integer, -a array, -r read-only…). Variables are global to the script by default; local limits one to a function, and export passes it to child processes.

Rules

  • Names: letters, digits, _; can't start with a digit; case-sensitive
  • Convention: UPPER for exported/env vars, lower for script vars
  • No $ on the left side: count=1, not $count=1
  • An unset variable expands to an empty string (unless set -u)

Assigning & Declaring

name="Ada"                    # no spaces around =
echo "$name ${name}s"         # Ada Adas   (braces mark where the name ends)
readonly PI=3.14159           # constant; reassigning is an error
export EDITOR=vim             # visible to child processes
DEBUG=1 ./build.sh            # set for this one command only

declare -i n=5; n+=3          # 8     (-i: assignments are arithmetic)
declare -l lower="HeLLo"      # hello (-u for UPPER; bash 4+)
declare -p name               # declare -- name="Ada"
declare -n ref=name           # nameref (4.3+): ref is another name for name
ref="Grace"; echo "$name"     # Grace

f() { local count=0; count+=1; echo "$count"; }   # local to f
f; echo "${count-unset}"      # 01  then  unset
unset name                    # remove the variable

Code Explained

${name}s — braces needed when text follows the name
VAR=x cmd — temporary env var for one command; the shell's value is unchanged
declare -i — n+=3 adds instead of appending text
declare -p — prints the type and value; great for debugging
count+=1 without -i appends: 0 becomes 01
${count-unset} — default if unset (Sheet 09)

⚠ Common Mistakes

  • x = 1 runs a command named x; bash assignments allow no spaces
  • x=hello world sets x only for running a command named world; quote values with spaces
  • Forgetting local in functions: the variable silently overwrites a global of the same name
  • Setting a variable in a pipeline (cmd | while read …; do x=…) and expecting it afterwards

✓ Tips & Best Practices

  • Always declare function variables with local
  • Use readonly for config constants at the top of a script
  • declare -p var shows exactly what a variable holds, including quoting
  • export -n VAR stops exporting without unsetting

Quick Summary

  • name=value — assign, no spaces
  • "$name" — read, always quoted
  • local / export / readonly — scope and protection
  • declare -i -a -A -n — give a variable a type
  • unset name — remove it
