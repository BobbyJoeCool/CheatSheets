Testing Conditions

A test is a command that exits 0 (true) or 1 (false). [ ] (also called test) is the POSIX version and is an ordinary command, so its arguments get split and globbed. [[ ]] is bash syntax: no word splitting, supports && ||, glob patterns with ==, and regexes with =~. Use [[ ]] in bash scripts and (( )) for numbers.

[[ ]] vs [ ]

  • [[ $v == x ]] is safe unquoted; [ "$v" = x ] needs quotes
  • [[ a && b ]] vs [ a ] && [ b ] (-a/-o are deprecated)
  • < > compare strings in [[ ]]; in [ ] they are redirections
  • Spaces inside the brackets are required: [[ -f x ]], not [[-f x]]

Common Tests

f=notes.txt; s="hello"; n=7
[[ -f $f ]] && echo "regular file"
[[ -d /tmp && -w /tmp ]] && echo "writable dir"
[[ -z $empty ]] && echo "empty or unset"
[[ -n $s ]] && echo "non-empty"
[[ $s == h* ]] && echo "glob match"        # unquoted right side = pattern
[[ $s == "h*" ]] || echo "no match"         # quoted right side = literal
[[ $s =~ ^h(el+)o$ ]] && echo "${BASH_REMATCH[1]}"   # ell
[[ $n -gt 5 ]] && echo "numeric >"          # or: (( n > 5 ))
[[ -v HOME ]] && echo "HOME is set"
[[ new.log -nt old.log ]] && echo "newer"
[[ ! -e $f || -s $f ]] && echo "missing or non-empty"
[ "$s" = hello ] && echo "POSIX: quote vars, use single ="
re='^[0-9]+$'; [[ $n =~ $re ]] && echo "integer"

Code Explained

-z / -n — empty / non-empty string
== with unquoted h* — glob pattern; quote it for a literal compare
=~ — extended regex; groups land in BASH_REMATCH
-gt — numeric; > inside [[ ]] would compare as strings
-v name — variable is set (even if empty)
re=…; [[ $x =~ $re ]] — keep regexes in a variable, unquoted

⚠ Common Mistakes

  • [ $v = x ] with empty $v becomes [ = x ]: "unary operator expected"
  • [[ $a > $b ]] on numbers compares as text, so 10 > 9 is false; use -gt or (( ))
  • Quoting the regex: [[ $s =~ "^h.*" ]] matches the literal characters ^h.*
  • if [ -f $file ] with a name containing spaces passes several words to [

✓ Tips & Best Practices

  • In bash scripts, use [[ ]] for strings and files, (( )) for numbers
  • Store complex regexes in a variable to avoid quoting problems
  • Test a command directly: if grep -q … is clearer than [ $? -eq 0 ]
  • help test lists every operator

Quick Summary

  • [[ -f f ]] / [[ -d d ]] — file / directory exists
  • [[ -z s ]] / [[ -n s ]] — empty / non-empty
  • [[ s == pat ]] — glob match
  • [[ s =~ re ]] — regex, captures in BASH_REMATCH
  • -eq -lt -gt — integer comparisons
