Sheet 04

Redirection & Pipes

> >> < · 2>&1 · &> · <<EOF · <<< · |& · exec 3>

Streams and Where They Go

Every process starts with three open file descriptors: 0 stdin, 1 stdout, 2 stderr. Redirections rewire them before the command runs, and are processed left to right, which is why > file 2>&1 and 2>&1 > file behave differently. A pipe | connects one command's stdout to the next command's stdin; each side runs in its own subshell.

Notes

  • 2>&1 means "make fd 2 point where fd 1 points right now"
  • Redirections can appear anywhere on the line: > out cmd arg works
  • Pipeline exit status is the last command's, unless set -o pipefail
  • ${PIPESTATUS[@]} holds every stage's status (Sheet 08)

Redirection Patterns

cmd > out.txt           # stdout → file (truncate)
cmd >> out.txt          # stdout → file (append)
cmd < in.txt            # file → stdin
cmd 2> err.txt          # stderr → file
cmd > all.txt 2>&1      # both → file   (order matters)
cmd &> all.txt          # same thing, bash shorthand
cmd &>> all.txt         # append both (bash 4+)
cmd 2>/dev/null         # throw away errors
cmd1 | cmd2             # stdout of cmd1 → stdin of cmd2
cmd1 |& cmd2            # stdout + stderr → cmd2 (bash 4+)
cmd | tee log.txt       # see output AND save it

cat <<EOF               # here-doc: $vars expand
User: $USER
EOF
grep -c ERR <<< "$text" # here-string: a string as stdin
exec 3> log.txt; echo hi >&3; exec 3>&-   # open fd 3, write, close

Code Explained

> f 2>&1 — stdout to f, then stderr to the same place
&> — shorthand for the line above; bash-only
/dev/null — discards whatever is written to it
tee — copies stdin to a file and to stdout; tee -a appends
<<EOF … EOF — multi-line stdin; delimiter must be alone on its line
exec 3> — open a descriptor for the rest of the script; 3>&- closes it

Order Matters

FormResult
> f 2>&1both streams → f
2>&1 > fstdout → f, stderr → terminal
2>&1 | cmdboth streams → cmd
> f 2> fboth truncate f: garbled output
1>&2stdout → stderr (same as >&2)

⚠ Common Mistakes

  • cmd 2>&1 > file expecting both in the file: stderr was copied to the terminal before stdout moved
  • sort f > f empties f: the shell truncates before sort reads; write to a temp file, then mv
  • sudo echo x > /etc/f fails: the redirect runs as you; use echo x | sudo tee /etc/f
  • Indenting a here-doc's closing EOF with spaces: only <<- strips, and only tabs

✓ Tips & Best Practices

  • Redirect a whole block once: { cmd1; cmd2; } > out.log 2>&1
  • Log everything a script prints: exec > >(tee -a run.log) 2>&1 at the top
  • Use <<'EOF' for generated scripts or config so $ stays literal
  • set -o pipefail so false | true reports failure

Quick Summary

  • > >> < — write, append, read
  • 2>&1 — merge stderr into stdout
  • &> — both streams to a file
  • <<EOF / <<< — inline stdin
  • | / |& — pipe stdout / both
