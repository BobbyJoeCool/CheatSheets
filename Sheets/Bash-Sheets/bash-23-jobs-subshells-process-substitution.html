Jobs, Subshells & Process Substitution

& · jobs · fg / bg · disown · wait -n · ( ) vs { } · <(cmd) · coproc

Running Things Concurrently

A trailing & runs a command in the background and returns immediately; wait pauses until background jobs finish. Parentheses ( … ) run commands in a subshell, a forked copy where cd and variable changes don't leak out, while braces { …; } group commands in the current shell. Process substitution <(cmd) turns a command's output into a filename, so tools that only accept files can read it.

Notes

  • Job specs: %1 job 1, %+ current, %- previous, %vim by name
  • $! is the PID of the most recent background job
  • Job control (fg, bg, Ctrl-Z) is for interactive shells
  • Braces need spaces and a final ;: { a; b; }

Background Jobs & Grouping

./long_task.sh &                    # run in the background
echo "started PID $!"
jobs -l                             # list jobs with PIDs
fg %1                               # bring job 1 to the foreground
# Ctrl-Z suspends the foreground job, then:
bg %1                               # resume it in the background
disown %1                           # keep it alive after the terminal closes
nohup ./server.sh > srv.log 2>&1 &  # immune to hangup from the start

for h in web1 web2 web3; do ping -c1 "$h" > "$h.log" & done
wait                                # wait for all background jobs
wait -n                             # wait for whichever finishes next (4.3+)

( cd /tmp && make )                 # subshell: the cd doesn't leak out
{ echo header; cat data; } > out.csv   # group: one redirect, same shell
diff <(sort a.txt) <(sort b.txt)    # compare two command outputs
tar cf - src | tee >(sha256sum > sum.txt) > src.tar

Code Explained

jobs -l — job numbers, PIDs and states
disown — removes the job from the shell's table so SIGHUP isn't sent
wait — returns when all children finish; wait $pid for one
( … ) — changes stay inside; costs a fork
<(cmd) — becomes a path like /dev/fd/63
>(cmd) — a writable path whose data feeds cmd

⚠ Common Mistakes

  • Exiting the terminal kills background jobs; use disown, nohup, or tmux
  • Starting hundreds of & jobs at once; throttle with wait -n or use xargs -P
  • { a; b } without the final ; (or newline) is a syntax error
  • Using cd in a subshell and expecting the parent's directory to change

✓ Tips & Best Practices

  • Limit parallel jobs: (( $(jobs -rp | wc -l) >= 4 )) && wait -n before each &
  • Check each job's status: wait "$pid" || echo "$pid failed"
  • Use a subshell to scope cd, IFS or set changes temporarily
  • $( … ) nests cleanly; backticks don't, so avoid them

Quick Summary

  • cmd & / wait — run in parallel, then sync
  • fg / bg / disown — manage jobs
  • ( … ) — isolated subshell
  • { …; } — group in the current shell
  • <(cmd) — command output as a file
