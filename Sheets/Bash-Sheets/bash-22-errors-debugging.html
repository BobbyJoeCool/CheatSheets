Errors, Traps & Debugging

set -euo pipefail · trap … EXIT · trap … ERR · set -x · PS4 · bash -n · exit

Failing Safely

By default bash keeps going after a command fails. Strict mode, set -euo pipefail, makes a script stop on failures (-e), on unset variables (-u), and on failures anywhere in a pipeline (pipefail). -e has many exceptions, so treat it as a safety net, not error handling. trap runs code on exit or on signals, which is how you clean up temp files no matter how the script ends.

Where -e Doesn't Fire

  • Commands tested by if, while, &&, || or !
  • Any command except the last in a pipeline (without pipefail)
  • Inside $(…) unless shopt -s inherit_errexit (4.4+)
  • Inside a function called from an if or &&

A Defensive Script Header

#!/usr/bin/env bash
set -euo pipefail                      # strict mode
trap 'echo "line $LINENO: $BASH_COMMAND failed" >&2' ERR
tmp=$(mktemp -d)
trap 'rm -rf "$tmp"' EXIT              # runs on any exit
trap 'echo "interrupted" >&2; exit 130' INT TERM

grep -q x maybe.txt || true            # allowed to fail
if ! out=$(build 2>&1); then           # handle failure yourself
  echo "build failed: $out" >&2; exit 1
fi
name=${NAME:-anon}                     # -u safe: default for unset

PS4='+ ${BASH_SOURCE##*/}:${LINENO}: ' # richer trace prefix
set -x                                 # trace from here...
cp config.yml "$tmp/"
set +x                                 # ...to here

Code Explained

ERR trap — runs when a command fails; $BASH_COMMAND is the culprit
EXIT trap — runs on normal exit, exit, -e abort, and most signals
|| true — marks a command as allowed to fail under -e
if ! out=$(…) — capture output and test status in one step
PS4 — prefix for set -x lines; set it before tracing
exit 130 — conventional status after Ctrl-C

⚠ Common Mistakes

  • Relying on -e inside functions used in if: errors in them are silently ignored
  • local v=$(cmd) or export v=$(cmd) always succeeds, so -e never sees cmd fail
  • (( i++ )) with i=0 returns 1 and kills a set -e script
  • set -o pipefail plus cmd | head -1 can fail with status 141 (SIGPIPE) when cmd keeps writing

✓ Tips & Best Practices

  • Set the EXIT trap right after creating a temp file
  • Write messages to stderr and use distinct exit codes per failure
  • Run shellcheck on every script; it catches most -e and quoting traps
  • Trace only the part you're debugging with set -x … set +x

Quick Summary

  • set -euo pipefail — stop on errors
  • trap 'cleanup' EXIT — always clean up
  • trap '…' ERR — report failures
  • set -x + PS4 — trace execution
  • bash -n / shellcheck — check before running
