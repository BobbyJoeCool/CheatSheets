Turbo Frames

turbo_frame_tag · src: · loading: :lazy · target: "_top" · frame navigation · dom_id

Update Part of the Page

A Turbo Frame is a region of the page that navigates on its own. Links and forms inside a frame load the next page, find the frame with the same id in the response, and swap just that frame. Frames can also load lazily from a URL, which is handy for slow sections.

Notes

  • Frame ids must match between the current page and the response
  • A response without a matching frame shows "Content missing"
  • target: "_top" makes links inside the frame navigate the whole page
  • Rails sets request.headers["Turbo-Frame"]; layouts are skipped for frame requests

Inline Editing

<%# posts/show.html.erb %>
<%= turbo_frame_tag dom_id(@post) do %>
  <h1><%= @post.title %></h1>
  <%= link_to "Edit", edit_post_path(@post) %>              <%# loads in the frame %>
<% end %>

<%# posts/edit.html.erb %>
<%= turbo_frame_tag dom_id(@post) do %>
  <%= render "form", post: @post %>                        <%# submit → show → swap back %>
<% end %>

Lazy Loading & Targets

<%= turbo_frame_tag "stats", src: stats_path, loading: :lazy do %>
  <p>Loading…</p>
<% end %>

<%= turbo_frame_tag "results", target: "_top" do %> … <% end %>
<%= link_to "Open", post_path(p), data: { turbo_frame: "_top" } %>
<%= link_to "Preview", post_path(p), data: { turbo_frame: "preview" } %>
<%= form_with url: search_path, method: :get,
      data: { turbo_frame: "results", turbo_action: "advance" } do |f| %> … <% end %>

Controller

def stats
  @stats = Stats.compute                 # stats.html.erb wraps output in
end                                      # turbo_frame_tag "stats"

Code Explained

dom_id(@post) — "post_1", a unique, matching frame id
Edit link inside the frame — only the frame swaps to the form
loading: :lazy — fetch when the frame scrolls into view
data-turbo-frame on a link — drive a different frame by id
turbo_action: "advance" — update the URL for frame navigation

The Rails Way

  • Custom fetch + innerHTML for inline editing → a Turbo Frame around show/edit
  • Slow sidebar delaying the whole page → a lazy src: frame
  • Modal JS libraries for simple dialogs → a modal frame plus a <dialog> element

Frame Options

OptionEffect
src:Load content from URL
loading: :lazyLoad when visible
target: "_top"Links navigate full page
data-turbo-actionPush history for frame visits
refresh: "morph"Morph on page refresh
disabledTurn off frame navigation

Frames vs Streams

Frames · Streams
UpdatesOne region · Many regions
TriggerLink/form inside frame · Response or broadcast
Server returnsFull page HTML · <turbo-stream> actions
Real-timeno · yes (with Action Cable)

⚠ Common Mistakes

  • Response template without the matching turbo_frame_tag → "Content missing"
  • Expecting links inside a frame to change the URL; add turbo_action: "advance"
  • Wrapping huge sections in frames, making each click download a full page to update a tiny area

✓ Tips & Best Practices

  • Listen for turbo:frame-missing to redirect to the full page instead of showing an error
  • Use turbo_frame_request? in controllers to skip extra work for frame requests
  • Combine lazy frames with HTTP caching for cheap dashboards

Quick Summary

  • turbo_frame_tag — independent region
  • matching ids — required
  • src: loading: :lazy — deferred content
  • _top — break out to full page
