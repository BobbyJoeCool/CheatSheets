Dockerfile, Puma & Thruster

generated Dockerfile · multi-stage build · Thruster · Puma workers / threads · bin/docker-entrypoint · db:prepare on boot

The Generated Container

New Rails apps include a production Dockerfile. It builds in stages (gems and assets in a build stage, a slim runtime stage), runs as a non-root user, and starts the app through Thruster, a small proxy in front of Puma that adds HTTP/2, X-Sendfile, asset caching and gzip, plus automatic TLS when you don't use another proxy.

Notes

  • The Dockerfile targets production; use .devcontainer for development
  • bin/docker-entrypoint runs db:prepare before the server starts
  • Thruster listens on port 80 and forwards to Puma on 3000
  • jemalloc is enabled to reduce memory fragmentation

Dockerfile (abridged)

ARG RUBY_VERSION=3.4.7
FROM docker.io/library/ruby:$RUBY_VERSION-slim AS base
WORKDIR /rails
ENV RAILS_ENV="production" BUNDLE_DEPLOYMENT="1" \
    BUNDLE_PATH="/usr/local/bundle" BUNDLE_WITHOUT="development"
RUN apt-get update -qq && apt-get install --no-install-recommends -y \
    curl libjemalloc2 libvips sqlite3 && rm -rf /var/lib/apt/lists/*

FROM base AS build
RUN apt-get update -qq && apt-get install --no-install-recommends -y build-essential git
COPY Gemfile Gemfile.lock ./
RUN bundle install && bundle exec bootsnap precompile --gemfile
COPY . .
RUN SECRET_KEY_BASE_DUMMY=1 ./bin/rails assets:precompile

FROM base
COPY --from=build "${BUNDLE_PATH}" "${BUNDLE_PATH}"
COPY --from=build /rails /rails
RUN groupadd --system --gid 1000 rails && \
    useradd rails --uid 1000 --gid 1000 --create-home --shell /bin/bash && \
    chown -R rails:rails db log storage tmp
USER 1000:1000
ENTRYPOINT ["/rails/bin/docker-entrypoint"]
EXPOSE 80
CMD ["./bin/thrust", "./bin/rails", "server"]

Build & Run Locally

docker build -t blog .
docker run -d -p 80:80 -e RAILS_MASTER_KEY=$(cat config/master.key) \
  -v blog_storage:/rails/storage --name blog blog

Code Explained

AS build — compilers and git stay out of the final image
SECRET_KEY_BASE_DUMMY=1 — precompile assets without real secrets
USER 1000 — don't run as root
bin/thrust — Thruster wraps the Rails server
-v blog_storage: — persist SQLite and uploads

The Rails Way

  • Hand-written Dockerfiles from blog posts → start from the generated one
  • Nginx just for gzip and asset caching → Thruster
  • Running migrations by hand after deploy → the entrypoint's db:prepare

⚠ Common Mistakes

  • Baking master.key into the image; pass it at runtime
  • Forgetting the storage volume, so the SQLite database resets on each container replace
  • Building on Apple Silicon for amd64 servers without --platform linux/amd64

✓ Tips & Best Practices

  • Keep .dockerignore excluding log/, tmp/, storage/ and .env*
  • Bump RUBY_VERSION in the Dockerfile when you change .ruby-version
  • Use Kamal (sheet 77) instead of raw docker run for real deploys
