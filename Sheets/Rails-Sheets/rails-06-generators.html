Sheet 06

Generators & Scaffolds

scaffold · model · controller · resource · migration · destroy · --skip-* · custom generator templates

Code That Writes Code

Generators create files that follow Rails conventions: models with migrations, controllers with views, and full scaffolds with CRUD actions, forms and tests. Field lists use name:type pairs. Every generator has a matching destroy that removes what it created.

Generator Notes

  • Field types: string, text, integer, decimal, boolean, date, datetime, references, attachment, rich_text
  • Modifiers: name:string:index, email:string:uniq, price:decimal{10,2}
  • --pretend (-p) shows what would be created without writing files
  • Scaffolds are a starting point; trim unused actions and views

Common Generators

bin/rails g model Post title:string body:text published_at:datetime
bin/rails g model Comment post:references body:text
bin/rails g controller Pages home about --skip-routes
bin/rails g resource Tag name:string:uniq      # model + controller + routes
bin/rails g scaffold Product name price:decimal{10,2} active:boolean
bin/rails g migration AddSlugToPosts slug:string:index
bin/rails g migration CreateJoinTablePostTag post tag
bin/rails g authentication                     # sessions + users (8.0)
bin/rails g job SendDigest
bin/rails g mailer User welcome
bin/rails g stimulus dropdown

bin/rails destroy scaffold Product             # undo the files
bin/rails g scaffold Product name -p           # dry run

config/application.rb

config.generators do |g|
  g.test_framework :rspec
  g.helper false
  g.stylesheets false
end

Code Explained

post:references — post_id column, index, FK and belongs_to :post
resource — model, empty controller and resources :tags, no views
scaffold — the full CRUD set: routes, 7 actions, views, JSON, tests
AddXToY / RemoveXFromY — named migrations fill in add_column for you
config.generators — default flags for every generator

The Rails Way

  • Hand-writing a model, migration and test file → bin/rails g model and edit the result
  • Deleting generated files one by one → bin/rails destroy with the same arguments
  • Keeping all 7 scaffold actions "just in case" → delete what the feature doesn't need

⚠ Common Mistakes

  • Generating a scaffold and shipping it unchanged: it permits every field and exposes JSON endpoints you may not want
  • Running a generator twice and choosing "overwrite" on edited files, losing your changes
  • Forgetting bin/rails db:migrate after g model, then seeing "pending migrations" errors

✓ Tips & Best Practices

  • Use -p first when you aren't sure what a generator will touch
  • Override scaffold templates in lib/templates so new scaffolds match your team's style
  • Reach for resource over scaffold when you will write the views yourself

Quick Summary

  • g model — model + migration
  • g resource — model + controller + route
  • g scaffold — full CRUD
  • destroy — undo a generator
