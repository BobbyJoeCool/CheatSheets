Association Methods & Options

build · create · << · destroy_all · class_name: · touch: · strict_loading · deprecated: true (8.1)

Working with Collections

Every association returns a CollectionProxy that behaves like a relation and an array. Some methods save immediately (<<, create), others only in memory (build, new). Options control naming, cleanup and loading. Rails 8.1 can mark associations deprecated to find remaining callers before removing them.

Notes

  • << on a saved parent saves the child immediately
  • collection.delete(obj) follows dependent:; with no option it nullifies the FK
  • strict_loading raises when an association loads lazily (N+1 guard)
  • deprecated: true (8.1) warns, raises or logs on every use

Collection Methods

post.comments << Comment.new(body: "Hi")         # saves now
post.comments.build(body: "Later")               # memory only
post.comments.create!(body: "Saved")
post.comments.find(5)                            # scoped to this post
post.comments.exists?(approved: false)
post.comments.destroy(comment)                   # one, with callbacks
post.comments.destroy_all                        # all, with callbacks
post.comments.delete_all                         # SQL, follows dependent:
post.comments.clear                              # remove all from collection
post.comments.loaded?                            # already in memory?
post.comments.load_async                         # start query in background

Options on Declarations

class Post < ApplicationRecord
  belongs_to :user, touch: true, inverse_of: :posts
  has_many   :comments, -> { order(:created_at) }, strict_loading: true
  has_many   :old_comments, class_name: "Comment", deprecated: true   # 8.1
end

# config/application.rb (8.1): how deprecated associations report
config.active_record.deprecated_associations_options = { mode: :warn, backtrace: true }

Code Explained

find on an association — 404s if the comment isn't on this post
destroy vs delete_all — callbacks vs single SQL statement
load_async — run the query in a thread while the action continues
strict_loading: true — forces you to preload with includes
deprecated: true — modes :warn, :raise, :notify

The Rails Way

  • Comment.find(params[:id]) for a nested resource → @post.comments.find(params[:id])
  • Deleting rows in a loop → destroy_all or delete_all
  • Grepping for an old association before removal → mark it deprecated: true and watch the logs

⚠ Common Mistakes

  • Calling post.comments.build and then render, which shows the unsaved comment in lists
  • Using .count on a loaded collection (extra query); use .size
  • Expecting delete to run callbacks; it doesn't

✓ Tips & Best Practices

  • Turn on config.active_record.strict_loading_by_default in development to surface N+1s
  • Use inverse_of: when Rails can't infer it (custom foreign_key, scopes)
  • Use load_async for independent queries in the same action

Quick Summary

  • << / create — save now
  • build — save later
  • strict_loading — no lazy loads
  • deprecated: true — retire safely (8.1)
