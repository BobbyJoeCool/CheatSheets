Sheet 12

Params & Strong Parameters

params · params.expect (8.0) · require / permit · nested hashes & arrays · ParameterMissing · action_on_unpermitted_parameters

Safe Input from Requests

params merges route segments, the query string and the request body into one hash-like ActionController::Parameters object. Before mass-assigning it to a model you must permit the keys you allow. Rails 8 adds params.expect, which permits and checks the shape in one call and returns 400 Bad Request instead of 500 when a client sends the wrong structure.

Params Facts

  • All values are strings (or arrays/hashes of strings)
  • Keys can be read as strings or symbols: params[:id] == params["id"]
  • Passing unpermitted params to Post.new raises ForbiddenAttributesError
  • Unpermitted keys are dropped and logged in development by default

Rails 8: expect

params.expect(:id)                               # "42"  (scalar)
params.expect(post: [:title, :body])             # permitted hash
params.expect(post: [:title, tag_ids: []])       # array of scalars
params.expect(post: [:title, images: [[:url, :alt]]])   # array of hashes
params.expect(post: [:title, author: [:name, :email]])  # nested hash
params.expect(post: [:title, settings: {}])      # any keys (use sparingly)

Classic require / permit

params.require(:post).permit(:title, :body, tag_ids: [])
params.permit(:page, :q)                         # top-level keys
params.fetch(:filter, {}).permit(:status)        # optional root

In a Controller

def post_params
  params.expect(post: [:title, :body, :published,
                       comments_attributes: [[:id, :body, :_destroy]]])
end

Code Explained

expect(:id) — fails with 400 if id is missing or is a hash
[[:url, :alt]] — double brackets mean "array of hashes" with expect
tag_ids: [] — an array of scalars (checkbox lists)
settings: {} — permits any nested keys: only for trusted, free-form data
comments_attributes — needed for accepts_nested_attributes_for

The Rails Way

  • Post.new(params[:post]) → Post.new(post_params) with an explicit allow-list
  • params.require(:post).permit(...) in new code → params.expect(post: [...])
  • permit! to "make it work" → list the keys; permit! reopens mass-assignment holes

Form Field → Param Shape

Field nameArrives as
post[title]{ "post" => { "title" => "Hi" } }
post[tag_ids][]{ "post" => { "tag_ids" => ["1", "2"] } }
post[author][name]nested hash
post[images][0][url]hash with index keys (array of hashes)

Errors & Settings

ItemBehavior
ParameterMissingRequired key absent → 400
ForbiddenAttributesErrorUnpermitted params mass-assigned
UnpermittedParametersRaised when set to :raise
action_on_unpermitted_parameters:log, :raise or false

⚠ Common Mistakes

  • Permitting :role or :admin in a user form, letting users promote themselves
  • Using single brackets for arrays of hashes with expect (images: [:url]); it expects a single hash
  • Calling .to_h on unpermitted params, which raises UnfilteredParameters

✓ Tips & Best Practices

  • Set config.action_controller.action_on_unpermitted_parameters = :raise in development and test to catch typos
  • Keep one *_params method per resource, private, at the bottom of the controller
  • Permit different keys per role with separate methods (admin_user_params)

Quick Summary

  • params — merged request input
  • expect — permit + shape check (8.0)
  • permit — the allow-list
  • [[...]] — array of hashes
