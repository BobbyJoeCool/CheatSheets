API-Only Apps & JSON

rails new --api · ActionController::API · render json: · Jbuilder · as_json · namespaced versions · rack-cors

Rails as a JSON Backend

rails new --api builds a slimmer app for JSON clients: controllers inherit ActionController::API, browser-only middleware (cookies, flash, CSRF) is removed, and generators skip views. You can also add API controllers to a normal app. JSON comes from render json: with as_json, Jbuilder templates, or a serializer gem.

Notes

  • ActionController::API excludes views, cookies, sessions and CSRF by default
  • Token auth is common: authenticate_with_http_token or signed tokens
  • Version with URL namespaces: /api/v1/...
  • Browsers calling from another origin need CORS headers (rack-cors)

Routes & Controller

namespace :api do
  namespace :v1 do
    resources :posts, only: %i[index show create], defaults: { format: :json }
  end
end

class Api::V1::BaseController < ActionController::API
  include ActionController::HttpAuthentication::Token::ControllerMethods
  before_action :authenticate

  private

  def authenticate
    authenticate_or_request_with_http_token do |token, _opts|
      @client = ApiClient.find_by(api_key: token)
    end
  end
end

class Api::V1::PostsController < Api::V1::BaseController
  def index
    posts = Post.published.order(id: :desc).limit(50)
    render json: posts.as_json(only: %i[id title], include: { user: { only: :name } })
  end

  def create
    post = @client.posts.new(params.expect(post: [:title, :body]))
    if post.save then render json: post, status: :created, location: api_v1_post_url(post)
    else render json: { errors: post.errors }, status: :unprocessable_entity end
  end
end

Code Explained

defaults: { format: :json } — no .json suffix needed
authenticate_or_request_with_http_token — parses Authorization: Token ... / Bearer
as_json(only:, include:) — shape output without a template
status: :created, location: — RESTful create response
Jbuilder — show.json.jbuilder: json.extract! @post, :id, :title

The Rails Way

  • to_json of whole records (leaks columns) → as_json(only:), Jbuilder or a serializer
  • Inconsistent error formats → one rescue_from + error JSON shape in a base controller
  • Breaking changes on the same URL → a new v2 namespace

⚠ Common Mistakes

  • Rendering @user.to_json, exposing password_digest and other private columns
  • Using cookie auth for a cross-site API without CSRF protection
  • Setting CORS origins "*" together with credentials

✓ Tips & Best Practices

  • Paginate every list endpoint (pagy gem) and return pagination headers
  • Return errors as { errors: { field: [messages] } } consistently
  • Use request specs or integration tests with as: :json for every endpoint

Quick Summary

  • --api — lean JSON app
  • ActionController::API — no browser middleware
  • as_json / Jbuilder — shape JSON
  • api/v1 — version namespace
