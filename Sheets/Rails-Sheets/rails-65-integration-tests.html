Testing Requests End to End

Integration tests send real HTTP requests through the full Rails stack (routing, middleware, controllers, views) without a browser. They are fast and catch most bugs. New apps generate controller tests as ActionDispatch::IntegrationTest, so "controller test" and "integration test" are the same thing today.

Notes

  • Use _url helpers: get posts_url
  • Params go in params:; JSON bodies with as: :json
  • assert_select checks rendered HTML with CSS selectors
  • Log in through the real login route, or a helper that does

test/test_helper.rb (sign-in helper)

class ActionDispatch::IntegrationTest
  def sign_in_as(user, password: "password")
    post session_url, params: { email_address: user.email_address, password: }
  end
end

test/controllers/posts_controller_test.rb

require "test_helper"

class PostsControllerTest < ActionDispatch::IntegrationTest
  setup { sign_in_as users(:ann) }

  test "lists posts" do
    get posts_url
    assert_response :success
    assert_select "h2", posts(:hello).title
  end

  test "creates a post" do
    assert_difference("Post.count") do
      post posts_url, params: { post: { title: "New", body: "Text" } }
    end
    assert_redirected_to post_url(Post.last)
    follow_redirect!
    assert_select ".flash", "Post created"
  end
end

Code Explained

sign_in_as — posts to the real session route (auth generator)
assert_select "h2", text — element with that text exists
assert_redirected_to — checks the Location header
follow_redirect! — perform the next GET
get url, as: :json + response.parsed_body — test JSON endpoints

The Rails Way

  • Old ActionController::TestCase with assigns → integration tests asserting on output
  • Stubbing the current user → log in through the real flow
  • Testing every branch in system tests → integration tests; save the browser for JS

⚠ Common Mistakes

  • Using _path helpers in integration tests; it works but _url matches redirects exactly
  • Asserting on instance variables (assigns); test what the user sees
  • Forgetting fixtures need a known password digest for sign-in: password_digest: <%= BCrypt::Password.create("password") %>

✓ Tips & Best Practices

  • Write one happy-path and one failure-path test per action
  • Use assert_select "form[action=?]", posts_path to check forms
  • Test JSON with as: :json and parsed_body instead of string matching

Quick Summary

  • IntegrationTest — full request stack
  • get / post — make requests
  • assert_response / assert_select — check output
  • sign_in_as — real login
