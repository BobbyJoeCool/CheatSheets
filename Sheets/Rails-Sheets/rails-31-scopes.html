Named, Chainable Queries

A scope names a query so you can chain it: Post.published.recent.limit(5). Scopes always return a relation, even when the condition is nil. Model concerns group scopes, validations and methods shared by several models, such as soft delete or slugs.

Scope Notes

  • A scope is a class method that returns all when its body returns nil
  • Scopes work on associations: user.posts.published
  • default_scope applies to every query, including new and associations
  • unscoped removes default scopes (and everything else in the chain)

app/models/post.rb

class Post < ApplicationRecord
  include Sluggable

  scope :published, -> { where(published: true) }
  scope :recent,    -> { order(created_at: :desc) }
  scope :by_author, ->(user) { where(user: user) if user }
  scope :since,     ->(time = 1.week.ago) { where(created_at: time..) }

  def self.search(q)                       # class method alternative
    return all if q.blank?
    where("title LIKE ?", "%#{sanitize_sql_like(q)}%")
  end
end

app/models/concerns/sluggable.rb

module Sluggable
  extend ActiveSupport::Concern

  included do
    before_validation :set_slug, if: -> { slug.blank? }
    validates :slug, uniqueness: true
  end

  class_methods do
    def find_by_slug!(slug) = find_by!(slug: slug)
  end

  def to_param = slug
  private def set_slug = self.slug = title.to_s.parameterize
end

Chaining

Post.published.recent.by_author(Current.user).since.limit(10)
Post.published.search(params[:q]).page(2)

Code Explained

->(user) { ... if user } — returns nil → acts as all
time.. — endless range: created_at >= time
sanitize_sql_like — escapes % and _ in user input
class_methods do — class-level methods from a concern
to_param — models with slugs build /posts/my-title URLs

The Rails Way

  • Repeated where(published: true) in controllers → scope :published
  • default_scope { where(deleted_at: nil) } → an explicit kept scope
  • Copying the same slug code into three models → a concern

⚠ Common Mistakes

  • Calling .first or .to_a inside a scope; it must return a relation
  • Writing where("title LIKE '%#{q}%'") with interpolation (SQL injection)
  • Adding default_scope for soft deletes, then fighting it with unscoped everywhere

✓ Tips & Best Practices

  • Name scopes as adjectives or filters (published, by_author) so chains read like sentences
  • Combine with merge to reuse another model's scope in a join: joins(:user).merge(User.active)
  • Keep concerns cohesive: one behavior per concern

Quick Summary

  • scope — named, chainable query
  • nil → all — safe optional filters
  • default_scope — avoid
  • concern — shared model behavior
