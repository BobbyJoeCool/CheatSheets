Joins & Eager Loading

joins · left_outer_joins · includes · preload · eager_load · N+1 queries · strict_loading

Associations in Queries

joins uses an association to filter in SQL. includes, preload and eager_load load associated records up front, avoiding the N+1 problem: one query for posts plus one per post for its author. Pick based on whether you need to filter by the association, display it, or both.

Notes

  • joins is INNER JOIN; records without the association disappear
  • includes picks preload (separate queries) or eager_load (one LEFT JOIN)
  • includes switches to eager_load when you references or filter on the table
  • Nested: includes(comments: :author)

N+1 and the Fix

# N+1: 1 query for posts + 1 per post for its author
Post.limit(20).each { |p| puts p.author.name }

# 2 queries total
Post.includes(:author).limit(20).each { |p| puts p.author.name }

Joining vs Loading

Post.joins(:author).where(users: { verified: true })      # filter only
Post.joins(:comments).distinct                            # posts with comments
Post.left_outer_joins(:comments).where(comments: { id: nil })
Post.includes(:author, comments: :user)                   # display nested
Post.preload(:tags)                                       # always separate queries
Post.eager_load(:author).where(users: { verified: true }) # one JOIN query
Post.includes(:author).where(users: { verified: true }).references(:users)
Post.joins(:author).merge(User.verified)                  # reuse a scope

Guard Against N+1

Post.strict_loading.first.author     # raises StrictLoadingViolationError
user.posts.strict_loading!           # on one relation

Code Explained

joins — no association objects loaded, just filtering
distinct — avoid duplicate posts from one-to-many joins
preload — WHERE id IN (...) per association
eager_load — single query with LEFT OUTER JOIN
merge — apply another model's scope to the joined table

The Rails Way

  • Looping and calling an association per row → includes up front
  • joins + reading post.author in the view → includes (joins doesn't load)
  • Hunting N+1s by reading logs → strict_loading in dev or the Bullet gem

⚠ Common Mistakes

  • Using includes then .where("users.verified = 1") without references(:users), giving "no such column"
  • Over-eager loading associations the page never shows
  • Forgetting distinct after joining a has_many, which multiplies rows

✓ Tips & Best Practices

  • Enable config.active_record.strict_loading_by_default = true in development and fix each error
  • Use counter caches instead of loading collections just to count them
  • Check the log: lines tagged CACHE or repeated SELECT users hint at N+1

Quick Summary

  • joins — filter
  • includes — load to display
  • eager_load — one JOIN query
  • strict_loading — catch N+1
