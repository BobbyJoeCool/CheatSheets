Built-in Security

protect_from_forgery · CSRF tokens · XSS escaping · sanitize · content_security_policy · filter_parameters · host authorization

Defenses Rails Gives You

Rails protects against common web attacks by default: CSRF tokens on every non-GET form, auto-escaping in views, parameterized SQL, signed and encrypted cookies, and filtered logs. You configure a Content Security Policy, allowed hosts and SSL in config files. Most vulnerabilities come from opting out of these defaults.

Defaults to Keep

  • ActionController::Base verifies CSRF tokens automatically
  • Views escape output unless you use raw, html_safe or <%==
  • Production sets config.force_ssl = true and secure cookies
  • config.filter_parameters hides passwords and tokens in logs and errors

config/initializers/content_security_policy.rb

Rails.application.configure do
  config.content_security_policy do |policy|
    policy.default_src :self, :https
    policy.img_src     :self, :https, :data
    policy.script_src  :self, :https
    policy.style_src   :self, :https
    policy.object_src  :none
    policy.connect_src :self, "wss://example.com"
  end
  config.content_security_policy_nonce_generator = ->(request) { request.session.id.to_s }
  config.content_security_policy_nonce_directives = %w[script-src style-src]
  # config.content_security_policy_report_only = true   # trial first
end

Other Settings

# config/initializers/filter_parameter_logging.rb
Rails.application.config.filter_parameters += [:passw, :email, :secret, :token, :otp, :ssn]

# config/environments/production.rb
config.hosts << "example.com" << /.*\.example\.com/
config.force_ssl = true

# app/controllers/api/base_controller.rb (token-auth APIs only)
skip_forgery_protection

Safe Output

<%= user.bio %>                                  <%# escaped %>
<%= sanitize user.bio, tags: %w[b i a], attributes: %w[href] %>
<%= javascript_tag nonce: true do %>console.log("ok")<% end %>

Code Explained

CSP — the browser refuses scripts and styles from other sources
Nonce — lets your own inline <script> tags run under CSP
filter_parameters — partial matches: :passw covers password_confirmation
config.hosts — blocks DNS rebinding / Host header attacks
skip_forgery_protection — only for APIs not using cookies

The Rails Way

  • Turning off CSRF to fix a broken form → include csrf_meta_tags and authenticity_token
  • .html_safe on user input → sanitize with an allow-list
  • Shipping CSP straight to enforcing → run report_only first

⚠ Common Mistakes

  • Adding skip_forgery_protection to a cookie-authenticated controller
  • Interpolating user data into javascript_tag or inline event handlers
  • Logging full params in custom code, bypassing filter_parameters

✓ Tips & Best Practices

  • Run Brakeman in CI; new apps include it in bin/ci and the GitHub workflow
  • Add config.action_dispatch.default_headers changes rather than removing secure defaults
  • Review the Rails Security Guide before launch
