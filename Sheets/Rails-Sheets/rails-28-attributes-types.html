Column Types & the Attribute API

string / text / decimal / datetime / json · attribute · enum · normalizes (7.1) · store_accessor · serialize · has_json (8.2 edge)

Typed Attributes

Active Record casts column values to Ruby types: decimal → BigDecimal, datetime → ActiveSupport::TimeWithZone, json → Hash. The attribute API adds virtual attributes or overrides a column's type. enum maps integers or strings to named states, and normalizes cleans values before validation and queries.

Type Notes

  • Integer columns cast "42" → 42, "" → nil, "abc" → 0 (no error; validate numericality)
  • enum generates predicates (draft?), bang setters (published!) and scopes
  • normalizes also applies to where(email: ...) lookups
  • Rails 8.2 (edge) adds has_json for typed JSON settings

app/models/user.rb

class User < ApplicationRecord
  enum :role, { member: 0, editor: 1, admin: 2 }, default: :member
  enum :plan, %w[free pro team].index_by(&:itself), prefix: true

  normalizes :email, with: ->(e) { e.strip.downcase }
  attribute :newsletter, :boolean, default: true     # virtual or override
  store_accessor :settings, :theme, :locale         # keys inside a JSON column
  serialize :legacy_prefs, coder: JSON              # text column holding JSON
end

Using Them

u = User.new(role: :editor, email: "  Ann@X.COM ")
u.email                    # "ann@x.com"
u.editor?                  # true
u.admin!                   # update(role: :admin)
User.admin                 # scope
User.where.not(role: :member)
User.roles                 # {"member"=>0, "editor"=>1, "admin"=>2}
u.plan_pro?                # prefix: true → plan_*
u.theme = "dark"           # stored in settings JSON
User.find_by(email: "ANN@x.com")   # normalized lookup works

Code Explained

enum :role, {...} — Rails 7+ syntax with the name as first argument
default: — default value for new records
prefix: true — avoids name clashes (plan_free?)
store_accessor — attribute-style access to JSON keys
serialize ... coder: JSON — for legacy text columns

The Rails Way

  • STATUSES = %w[draft live] + string comparisons → enum :status
  • before_validation { self.email = email.downcase } → normalizes :email
  • Many boolean columns for options → a jsonb settings column with store_accessor

⚠ Common Mistakes

  • Reordering a hash enum mapped to integers; existing rows silently change meaning
  • Storing money in float columns; use decimal with scale 2 or integer cents
  • Mutating a JSON attribute in place (settings["x"] = 1) without reassigning on old Rails; reassign or use store_accessor

✓ Tips & Best Practices

  • Prefer string-backed enums (index_by(&:itself)) for readable data and safe reordering
  • Add validate: true to enum (7.1+) to get validation errors instead of ArgumentError
  • Use database defaults and attribute ... default: together so both SQL and Ruby agree
