Sheet 05

The rails Command

bin/rails server · console · runner · routes · about · bin/dev · Procfile.dev

Your Main Tool

bin/rails is the entry point for running the server, opening a console, inspecting routes, running database tasks and generators. Rake tasks are merged in, so bin/rails db:migrate and bin/rails test both work. Use bin/rails -T to list everything available.

Command Notes

  • Short aliases: s server, c console, g generate, d destroy, r runner, t test, db dbconsole
  • bin/dev runs Procfile.dev (server + Tailwind/JS watchers) via Foreman
  • Pass an environment with -e production or RAILS_ENV=production
  • Inside the console, reload! picks up code changes

Everyday Commands

bin/rails server -p 4000 -b 0.0.0.0   # bind for containers / LAN
bin/rails console                     # IRB with the app loaded
bin/rails console --sandbox           # roll back all changes on exit
bin/rails runner "puts User.count"    # run Ruby in app context
bin/rails runner script/backfill.rb
bin/rails routes -g posts             # grep routes
bin/rails routes -c Admin::Users      # by controller
bin/rails about                       # versions, env, middleware
bin/rails notes                       # TODO / FIXME / OPTIMIZE
bin/rails dbconsole                   # sqlite3 / psql / mysql
bin/rails -T db                       # list db:* tasks
bin/rails restart                     # touch tmp/restart.txt

Console Helpers

app.posts_path                 # "/posts"  (route helpers)
helper.number_to_currency(5)   # "$5.00"   (view helpers)
reload!                        # reload app code

Code Explained

--sandbox — wraps the session in a transaction, rolled back on exit
runner — scripts, cron jobs and quick checks with full app access
routes -g — filter by name, path or controller text
app / helper — console objects for route and view helpers
-T — list tasks with descriptions, optional filter

The Rails Way

  • Copy-pasting snippets into rails c for recurring jobs → a rake task or script/ file
  • Reading routes.rb to find a URL → bin/rails routes -g name
  • Restarting the console after edits → reload!

⚠ Common Mistakes

  • Running --sandbox against production data and assuming jobs or emails also roll back; external side effects still happen
  • Using rails server in production instead of the Puma/Thruster command from the Dockerfile
  • Forgetting -b 0.0.0.0 inside Docker, so the server is unreachable from the host

✓ Tips & Best Practices

  • Add IRB.conf[:USE_AUTOCOMPLETE] = false to .irbrc if console autocomplete is slow on big apps
  • Production consoles show the environment in the prompt (7.1+); check it before running writes
  • Use bin/rails runner -e test to debug test-only data setups

Quick Summary

  • s / c / g / r — server, console, generate, runner
  • routes -g — find routes
  • --sandbox — safe console
  • -T — list all tasks
