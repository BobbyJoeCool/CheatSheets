Active Model

Model Behavior Without a Table

Active Model is the toolkit Active Record is built on. Including its modules gives a plain Ruby class validations, typed attributes, naming and form compatibility. Use it for form objects, search filters, API payloads and anything that should behave like a model but isn't a database row.

Notes

  • ActiveModel::Model = API + validations + naming + conversion, enough for form_with
  • ActiveModel::Attributes adds typed attribute :name, :type, default:
  • has_secure_password lives in Active Model: it works on any class with a password_digest
  • Serializers::JSON gives as_json / to_json from attributes

A Form Object

class Signup
  include ActiveModel::Model
  include ActiveModel::Attributes

  attribute :name,  :string
  attribute :email, :string
  attribute :plan,  :string, default: "free"
  attribute :terms, :boolean

  validates :name, :email, presence: true
  validates :terms, acceptance: true

  def save
    return false unless valid?
    ActiveRecord::Base.transaction do
      user = User.create!(name:, email_address: email)
      user.create_subscription!(plan:)
    end
    true
  end
end

Controller & View

def create
  @signup = Signup.new(params.expect(signup: [:name, :email, :plan, :terms]))
  if @signup.save then redirect_to root_path, notice: "Welcome!"
  else render :new, status: :unprocessable_entity end
end
# view: form_with model: @signup, url: signups_path

Code Explained

attribute :terms, :boolean — "1" / "0" cast to true / false
valid? — same validation API and error messages as AR
Shorthand hash name: — Ruby 3.1 value omission
One transaction keeps both writes consistent
model_name — gives the signup[...] param key automatically

The Rails Way

  • A controller juggling two models and their errors → a form object
  • Hashes passed around for search filters → an Active Model class with typed attributes
  • Fake ActiveRecord tables for non-persisted data → ActiveModel::Model

⚠ Common Mistakes

  • Forgetting persisted? returns false, so form_with posts to the create URL even for "edits"; set url: and method: explicitly
  • Reading attributes as instance variables (@email) with Attributes; use the reader email
  • Putting all business logic in one form object; keep it to coordinating a single form

✓ Tips & Best Practices

  • Use ActiveModel::Attributes types (:date, :integer, :decimal) to parse form strings for free
  • Lint any model-like class with ActiveModel::Lint::Tests in tests
  • Add validates_with validators to share rules between a model and its form object

Quick Summary

  • ActiveModel::Model — form-ready class
  • Attributes — typed attributes
  • validations — same API as AR
  • form object — multi-model forms
