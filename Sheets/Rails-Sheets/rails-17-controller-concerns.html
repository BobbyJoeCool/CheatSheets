Concerns, Helpers & Current

controller concerns · helper_method · Current < CurrentAttributes · rate_limit (7.2) · allow_browser · etag / fresh_when

Sharing Controller Behavior

Concerns package callbacks and methods to include in several controllers. helper_method exposes a controller method to views. CurrentAttributes hold per-request globals (the current user, account, request id) that reset automatically. Rails 7.2 added rate_limit and allow_browser macros.

Notes

  • Controller concerns live in app/controllers/concerns/
  • Current attributes reset at the start and end of every request and job
  • rate_limit stores counters in Rails.cache (Solid Cache by default)
  • allow_browser versions: :modern is in new apps' ApplicationController

app/controllers/concerns/paginatable.rb

module Paginatable
  extend ActiveSupport::Concern

  included do
    helper_method :page                        # usable in views
  end

  def page = [params[:page].to_i, 1].max
end

app/models/current.rb

class Current < ActiveSupport::CurrentAttributes
  attribute :session
  delegate :user, to: :session, allow_nil: true
end

A Controller Using Them

class SessionsController < ApplicationController
  include Paginatable
  rate_limit to: 10, within: 3.minutes, only: :create,
             with: -> { redirect_to new_session_url, alert: "Try again later." }
end

class ApplicationController < ActionController::Base
  allow_browser versions: :modern               # 406 for old browsers
end

def show                                       # conditional GET
  @post = Post.find(params.expect(:id))
  fresh_when @post                              # 304 if unchanged
end

Code Explained

included do — runs class-level macros in the including controller
helper_method — <%= page %> works in views
Current.user — available in models, mailers and jobs for this request
rate_limit — 429 by default, or your with: handler
fresh_when — sets ETag / Last-Modified and returns 304 when cached

The Rails Way

  • Copying the same filters into five controllers → a concern
  • Passing current_user through every method → Current.user
  • A hand-rolled Redis throttle for login → rate_limit

rate_limit Options

⚠ Common Mistakes

  • Using Current as a general global for things that outlive a request; it resets between requests
  • Treating rate_limit as a security boundary on its own; it depends on the cache and the client IP
  • Huge "god" concerns that every controller includes; split by behavior

✓ Tips & Best Practices

  • Use by: -> { Current.user&.id || request.remote_ip } for per-user limits
  • Set Current values in a before_action so jobs enqueued in the request can read them
  • Use fresh_when on public show pages for cheap 304 responses

Quick Summary

  • concern — shared controller code
  • helper_method — expose to views
  • Current — per-request globals
  • rate_limit — throttle actions
