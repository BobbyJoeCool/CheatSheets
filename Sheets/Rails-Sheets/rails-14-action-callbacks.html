Sheet 14

Action Callbacks

before_action · after_action · around_action · only: / except: · skip_before_action · halting with render / redirect

Run Code Around Actions

Controller callbacks (formerly "filters") run before, after or around actions. They load records, enforce authentication, set locale or time zone, and log. If a before_action renders or redirects, the action does not run: that is how auth checks halt a request.

Callback Rules

  • Callbacks run in the order declared; parent class callbacks first
  • only: / except: restrict which actions trigger them
  • prepend_before_action puts a callback at the front of the chain
  • after_action runs only if the action didn't raise

app/controllers/application_controller.rb

class ApplicationController < ActionController::Base
  before_action :require_authentication           # from the auth generator
  around_action :use_user_time_zone

  private

  def use_user_time_zone(&action)
    Time.use_zone(Current.user&.time_zone || "UTC", &action)
  end
end

app/controllers/posts_controller.rb

class PostsController < ApplicationController
  allow_unauthenticated_access only: %i[index show]  # skips the auth callback
  before_action :set_post, only: %i[show edit update destroy]
  before_action :authorize_owner!, only: %i[edit update destroy]
  after_action  :track_view, only: :show

  private

  def set_post
    @post = Post.find(params.expect(:id))
  end

  def authorize_owner!
    redirect_to @post, alert: "Not yours" unless @post.user == Current.user
  end                                                 # redirect halts the chain

  def track_view = ViewCounterJob.perform_later(@post)
end

Code Explained

around_action — must yield (or call the block) to run the action
allow_unauthenticated_access — generator macro wrapping skip_before_action
authorize_owner! — redirect inside a before_action stops the action
only: — scopes each callback to specific actions
after_action — good for side effects; the response is already built

The Rails Way

  • @post = Post.find(params[:id]) repeated in four actions → one before_action :set_post
  • Auth checks inside each action → a before_action in ApplicationController, skipped where public
  • Callbacks with hidden business logic → keep callbacks to setup and guards

Callback Methods

MethodPurpose
before_actionLoad, authenticate, authorize
after_actionLogging, headers, analytics
around_actionWrap: time zone, locale, timing
skip_before_actionRemove an inherited callback
prepend_before_actionRun before others
append_before_actionSame as before_action

⚠ Common Mistakes

  • Skipping auth with skip_before_action :require_authentication and no only:, opening every action
  • Setting @post in a callback that doesn't cover all actions using it → nil errors
  • Forgetting to yield in an around_action, so the action never runs and nothing renders

✓ Tips & Best Practices

  • Name guard callbacks with ! (authorize_owner!) so their halting role is obvious
  • Run bin/rails runner 'p PostsController._process_action_callbacks.map(&:filter)' to see the chain
  • Prefer Current attributes over passing the user through many callbacks

Quick Summary

  • before_action — guard/load
  • around_action — wrap with yield
  • render/redirect — halts
  • only: / except: — scope
