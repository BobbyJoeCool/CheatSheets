Upgrading Rails

bin/rails app:update · load_defaults · new_framework_defaults_*.rb · deprecation warnings · dual booting · maintenance policy

Staying Current

Upgrade one minor version at a time (7.2 → 8.0 → 8.1). Fix deprecation warnings first, bump the gem, run bin/rails app:update to merge config changes, then flip new defaults one by one using the generated new_framework_defaults file. Each minor release gets bug fixes for about a year and security fixes for about two.

Notes

  • Read the version's "Upgrading Ruby on Rails" guide section and release notes
  • Deprecations in version N become errors in N+1
  • app:update asks before overwriting each file; review the diff
  • Keep load_defaults at the old version until every new default is enabled

The Steps

# 1. green test suite and zero deprecation warnings on the current version
bin/rails test 2>&1 | grep -i deprecat

# 2. bump Rails
bundle update rails --conservative       # Gemfile: gem "rails", "~> 8.1.0"

# 3. update config files and binstubs
bin/rails app:update                     # interactive: diff / overwrite / skip

# 4. run tests, fix failures, deploy
bin/ci

config/initializers/new_framework_defaults_8_1.rb

# Uncomment each line, run tests, deploy, repeat.
# Rails.configuration.action_controller.escape_json_responses = false
# Rails.configuration.active_support.escape_js_separators_in_json = false
# Rails.configuration.active_record.raise_on_missing_required_finder_order_columns = true
# Rails.configuration.action_controller.action_on_path_relative_redirect = :raise
# Rails.configuration.action_view.render_tracker = :ruby

Then Finish

# config/application.rb
config.load_defaults 8.1          # after all new defaults are enabled
# delete new_framework_defaults_8_1.rb

Surfacing Deprecations

# config/environments/test.rb
config.active_support.deprecation = :raise

Code Explained

--conservative — update Rails without unrelated gems
app:update — new config, binstubs, initializers
Framework defaults file — opt in to behavior changes gradually
load_defaults 8.1 — final switch once each default is on
deprecation = :raise — make warnings fail tests

The Rails Way

  • Jumping from 6.1 straight to 8.1 → one minor at a time, deploying between
  • Bumping load_defaults with the gem → flip defaults individually first
  • Ignoring deprecation output → treat warnings as the next upgrade's to-do list

⚠ Common Mistakes

  • Overwriting customized config files in app:update without reading the diff
  • Upgrading Rails and Ruby in the same deploy; change one variable at a time
  • Leaving the framework defaults file around for years, half applied

✓ Tips & Best Practices

  • Upgrade Ruby first (separately), then Rails
  • Use railsdiff.org to see exactly what a fresh app changed between versions
  • Schedule upgrades every minor release; small jumps are cheap

Quick Summary

  • one minor at a time
  • app:update — merge config
  • framework defaults file — opt in gradually
  • load_defaults — finish the upgrade
