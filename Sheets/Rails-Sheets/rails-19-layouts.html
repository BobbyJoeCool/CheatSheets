Layouts & content_for

application.html.erb · yield · content_for · yield(:title) · content_for? · layout "admin" · provide

The Page Wrapper

A layout wraps every view with shared HTML: <head>, navigation, flash and footer. The view's output goes where the layout calls yield. Views send extra content to named slots with content_for, such as the page title or page-specific scripts.

Layout Rules

  • Default: layouts/application.html.erb
  • A layouts/posts.html.erb file is used automatically for PostsController
  • layout "admin" in a controller picks one explicitly; layout false disables it
  • provide is like content_for but stops at the first value (streaming-friendly)

app/views/layouts/application.html.erb

<!DOCTYPE html>
<html>
<head>
  <title><%= content_for(:title) || "Blog" %></title>
  <meta name="viewport" content="width=device-width,initial-scale=1">
  <%= csrf_meta_tags %>
  <%= csp_meta_tag %>
  <%= stylesheet_link_tag :app, "data-turbo-track": "reload" %>
  <%= javascript_importmap_tags %>
  <%= yield :head %>
</head>
<body>
  <%= render "shared/nav" %>
  <%= render "shared/flash" %>
  <main class="<%= content_for?(:sidebar) ? "with-sidebar" : "" %>">
    <%= yield %>
  </main>
  <aside><%= yield :sidebar %></aside>
</body>
</html>

A View Filling the Slots

<% content_for :title, "Edit #{@post.title}" %>
<% content_for :sidebar do %>
  <%= render "posts/help" %>
<% end %>
<h1>Edit post</h1>

Choosing a Layout

class Admin::BaseController < ApplicationController
  layout "admin"
end
render :show, layout: "print"                     # one action

Code Explained

yield — the view's content
yield :sidebar — a named slot, empty if no view filled it
content_for? — test whether a slot has content
csrf_meta_tags — tokens for JavaScript requests
stylesheet_link_tag :app — every stylesheet in app/assets/stylesheets (Propshaft)

The Rails Way

  • Copying <head> into every view → one layout with yield
  • Instance variables like @page_title set in controllers → content_for :title in the view
  • Huge layout files → partials for nav, flash and footer

⚠ Common Mistakes

  • Calling content_for :title after the layout already rendered it (e.g. inside a lazy-loaded frame)
  • Forgetting csrf_meta_tags, which breaks Turbo and fetch-based non-GET requests
  • Nesting layouts by rendering one layout from another instead of using content_for slots

✓ Tips & Best Practices

  • Use content_for :head for page-specific <meta> or preload tags
  • Nested layouts: set content_for slots, then render template: "layouts/application"
  • Add data-turbo-track="reload" to asset tags so deploys trigger a full reload

Quick Summary

  • yield — main content
  • content_for — named slots
  • layout "x" — pick a layout
  • content_for? — slot filled?
