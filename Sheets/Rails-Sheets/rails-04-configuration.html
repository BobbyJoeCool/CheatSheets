Sheet 04

Configuration & Environments

config/application.rb · environments/*.rb · config.load_defaults · Rails.env · initializers · config_for · config.x

How Rails Is Configured

Settings load in layers: config/application.rb for everything, then config/environments/<env>.rb for development, test or production, then every file in config/initializers/. config.load_defaults opts the app into each version's new framework defaults.

Environment Facts

  • Rails.env comes from RAILS_ENV (or RACK_ENV), defaulting to development
  • Rails.env.production? — inquiry methods for each environment name
  • Initializers run alphabetically, after the framework loads
  • Custom YAML in config/*.yml loads with config_for(:name), keyed by environment

config/application.rb

module Blog
  class Application < Rails::Application
    config.load_defaults 8.1
    config.time_zone = "Central Time (US & Canada)"
    config.autoload_lib(ignore: %w[assets tasks])
    config.x.payments.retries = 3         # custom namespace
    config.stripe = config_for(:stripe)   # config/stripe.yml
  end
end

config/environments/development.rb (excerpt)

Rails.application.configure do
  config.enable_reloading = true
  config.action_mailer.delivery_method = :letter_opener
end

Reading Config

Rails.env                                  # "development"
Rails.env.production?                      # false
Rails.configuration.x.payments.retries     # 3
Rails.configuration.stripe[:public_key]    # from stripe.yml

Code Explained

load_defaults 8.1 — turn on every new default up to 8.1
config.x — a safe namespace for your own settings
config_for(:stripe) — reads config/stripe.yml for the current env, ERB allowed
configure do — environment file overrides of application.rb
Rails.configuration — read settings anywhere at runtime

The Rails Way

  • if ENV["RAILS_ENV"] == "production" → Rails.env.production?
  • Constants sprinkled in initializers → config.x.feature.setting or config_for
  • Hard-coding secrets in config files → credentials or ENV (sheet 49)

⚠ Common Mistakes

  • Bumping the Rails gem but leaving load_defaults at an old version; the app silently keeps old behavior
  • Reading ENV at class-load time in models; the value is frozen at boot and hard to test
  • Adding a custom environment (staging) without copying production's environment file and database entry

✓ Tips & Best Practices

  • Prefer one production-like environment configured by ENV over many custom environments
  • Use bin/rails runner 'p Rails.configuration.x' to check settings without starting the server
  • Name initializers with prefixes (01_) only when order truly matters

Quick Summary

  • application.rb — app-wide
  • environments/*.rb — per-env overrides
  • initializers/ — boot-time setup
  • load_defaults — framework defaults by version
