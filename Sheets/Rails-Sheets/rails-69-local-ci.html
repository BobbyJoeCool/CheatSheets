bin/ci (8.1) · config/ci.rb · rubocop-rails-omakase · Brakeman · bundler-audit · generated GitHub Actions workflow

Run CI on Your Machine

Rails 8.1 adds bin/ci, which runs the steps in config/ci.rb: setup, style, security audits and tests. Modern developer machines are fast, so running CI locally before pushing is quick and cheap. New apps also ship RuboCop with the Omakase style, Brakeman, bundler-audit and a GitHub Actions workflow.

Notes

  • bin/ci stops at the first failing step and prints a summary
  • The optional gh signoff step marks the commit green on GitHub
  • bin/rubocop -a auto-corrects safe offenses
  • Brakeman exits non-zero on new warnings; add an ignore file for accepted ones

config/ci.rb

CI.run do
  step "Setup", "bin/setup --skip-server"
  step "Style: Ruby", "bin/rubocop"
  step "Security: Gem audit", "bin/bundler-audit"
  step "Security: Importmap audit", "bin/importmap audit"
  step "Security: Brakeman", "bin/brakeman --quiet --no-pager --exit-on-warn --exit-on-error"
  step "Tests: Rails", "bin/rails test"
  step "Tests: System", "bin/rails test:system"
  step "Tests: Seeds", "env RAILS_ENV=test bin/rails db:seed:replant"

  if success?
    step "Signoff: Ready to merge", "gh signoff"
  else
    failure "Signoff: CI failed. Do not merge or deploy.", "Fix the issues and try again."
  end
end

Running the Tools

bin/ci                           # everything in config/ci.rb
bin/rubocop                      # lint
bin/rubocop -a                   # safe auto-correct
bin/brakeman -I                  # interactive ignore file
bin/bundler-audit check --update

Code Explained

step "name", "command" — each step is a shell command
success? — true if every step so far passed
gh signoff — sets a commit status via the GitHub CLI extension
db:seed:replant — proves seeds still run on an empty DB
inherit_gem — start from the Omakase style, override sparingly

The Rails Way

  • Waiting on remote CI for lint failures → run bin/ci before pushing
  • Arguing about style in review → RuboCop with the shared config
  • Ignoring Brakeman warnings by turning it off → record accepted ones in config/brakeman.ignore

⚠ Common Mistakes

  • Letting local CI drift from remote CI; keep the steps in config/ci.rb the source of truth
  • Auto-correcting with -A (unsafe) without reviewing the diff
  • Disabling cops globally to silence one file; use inline # rubocop:disable with a reason

✓ Tips & Best Practices

  • Add bin/rails zeitwerk:check as a step; it catches production-only boot errors
  • Run bin/ci in a git pre-push hook
  • Keep CI under a few minutes so people actually run it
