Encryption & Signed Tokens

encrypts · deterministic: · generates_token_for (7.1) · signed_id · has_secure_token · MessageVerifier

Protecting Data and Links

Active Record Encryption encrypts columns at the application level, so database dumps don't expose them. Rails can also create tamper-proof tokens: generates_token_for makes purpose-specific tokens that expire or self-invalidate, signed_id signs a record id, and has_secure_token stores a random unique token.

Notes

  • Run bin/rails db:encryption:init and store the keys in credentials
  • Non-deterministic encryption can't be queried; deterministic can (equality only)
  • generates_token_for tokens embed data from a block: change it and old tokens die
  • None of these replace hashing for passwords (has_secure_password)

Encrypted Attributes

class User < ApplicationRecord
  encrypts :ssn                                   # random IV, not queryable
  encrypts :email_address, deterministic: true, downcase: true
end
User.find_by(email_address: "ann@x.com")          # works (deterministic)
user.ciphertext_for(:ssn)                         # stored value

Purpose Tokens (7.1+)

class User < ApplicationRecord
  generates_token_for :password_reset, expires_in: 15.minutes do
    password_salt&.last(10)               # changes when password changes
  end
  generates_token_for :email_confirmation, expires_in: 24.hours do
    email_address
  end
end

token = user.generate_token_for(:password_reset)
User.find_by_token_for(:password_reset, token)    # nil if expired/used
User.find_by_token_for!(:email_confirmation, t)   # raises if invalid

Signed Ids, Secure Tokens, Verifiers

id = post.signed_id(expires_in: 1.hour, purpose: :share)
Post.find_signed(id, purpose: :share)

class ApiClient < ApplicationRecord
  has_secure_token :api_key, length: 36          # random, unique column
end
client.regenerate_api_key

v = Rails.application.message_verifier(:unsubscribe)
token = v.generate(user.id, expires_in: 30.days)
v.verified(token)                                 # user.id or nil

Code Explained

deterministic: true — same input gives same ciphertext, so lookups work
downcase: true — case-insensitive deterministic matching
Token block — any change in its return value invalidates old tokens
signed_id — shareable links without exposing guessable ids
message_verifier(:name) — sign any data for links and cookies

The Rails Way

  • A reset_token column you must clear → generates_token_for :password_reset
  • Base64-encoding ids in URLs → signed_id or message_verifier
  • Encrypting columns by hand with OpenSSL → encrypts

⚠ Common Mistakes

  • Encrypting a column you need for LIKE searches or sorting; encrypted columns only support equality (deterministic)
  • Storing encryption keys in the database or committing them in plain text
  • Long-lived generates_token_for tokens without a block, so they can't be revoked

✓ Tips & Best Practices

  • Use support_unencrypted_data while migrating existing plaintext columns
  • Filter encrypted columns from logs automatically: they are added to filter_parameters
  • Use separate purpose: values so a share token can't be reused as an unsubscribe token

Quick Summary

  • encrypts — encrypted columns
  • generates_token_for — expiring purpose tokens
  • signed_id — signed record ids
  • has_secure_token — random keys
