Active Storage

has_one_attached · has_many_attached · storage.yml · variants · direct uploads · rails_blob_path · purge_later

File Uploads Built In

Active Storage attaches files to records and stores them on local disk, S3-compatible services or Google Cloud Storage. Metadata lives in two tables (active_storage_blobs and _attachments), so models need no file columns. Image variants are generated on demand with libvips through the image_processing gem.

Notes

  • Install tables with bin/rails active_storage:install (new apps include it)
  • Variants need image_processing and libvips (or ImageMagick)
  • There are no built-in file validations; check content_type and byte_size yourself

Model

class User < ApplicationRecord
  has_one_attached :avatar do |a|
    a.variant :thumb, resize_to_limit: [100, 100], preprocessed: true
  end
  has_many_attached :documents, dependent: :purge_later
  validate { errors.add(:avatar, "too big") if avatar.attached? && avatar.byte_size > 5.megabytes }
end

Attaching & Displaying

user.avatar.attach(params[:avatar])                     # from a form
user.avatar.attach(io: File.open("me.png"), filename: "me.png")
user.avatar.attached?                                   # true
user.avatar.purge_later                                 # delete async
User.with_attached_avatar                               # avoid N+1

Views

<%= image_tag user.avatar.variant(:thumb) if user.avatar.attached? %>
<%= link_to "Download", rails_blob_path(doc, disposition: "attachment") %>
<%= form.file_field :documents, multiple: true, direct_upload: true %>

config/storage.yml

local:
  service: Disk
  root: <%= Rails.root.join("storage") %>
amazon:
  service: S3
  access_key_id: <%= Rails.application.credentials.dig(:aws, :access_key_id) %>
  secret_access_key: <%= Rails.application.credentials.dig(:aws, :secret_access_key) %>
  bucket: my-app-<%= Rails.env %>
  region: us-east-1

Code Explained

variant :thumb — named variant; preprocessed: true creates it after upload
attach(io:, filename:) — attach from code or scripts
with_attached_avatar — eager-load attachments and blobs
disposition: "attachment" — force download
direct_upload: true — browser uploads to the service, skipping your app server

The Rails Way

  • A file_path string column and manual uploads → has_one_attached
  • Resizing images on upload by hand → named variants
  • Uploading large files through Puma → direct uploads

⚠ Common Mistakes

  • Trusting the browser-sent content type; validate and consider content_type analysis
  • Rendering image_tag user.avatar when nothing is attached → error; check attached?
  • Using the local Disk service on multiple app servers; files exist on only one machine

✓ Tips & Best Practices

  • Serve files through a CDN with config.active_storage.resolve_model_to_route = :rails_storage_proxy
  • Use has_one_attached ... dependent: :purge_later (the default) so deletes don't block requests
  • Add the active_storage_validations gem for declarative file validations

Quick Summary

  • has_one_attached — single file
  • has_many_attached — many files
  • variants — on-demand images
  • direct uploads — straight to storage
