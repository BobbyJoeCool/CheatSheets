Turbo Streams

turbo_stream.append / replace / remove · format.turbo_stream · .turbo_stream.erb · turbo_stream_from · broadcasts_to · broadcasts_refreshes

Many Changes, One Response

A Turbo Stream is a small HTML instruction: append, prepend, replace, update or remove the element with a given id. Controllers can return several in one response to a form submit. Models can broadcast streams over Action Cable so every open browser updates in real time.

Notes

  • Stream responses are only used for non-GET form submissions (and broadcasts)
  • Targets are element ids; use dom_id for records
  • broadcasts_refreshes sends a single "refresh" that morphs the page (Turbo 8)
  • Broadcasting uses Action Cable (Solid Cable by default in Rails 8)

Controller

def create
  @comment = @post.comments.create!(comment_params)
  respond_to do |format|
    format.turbo_stream                    # create.turbo_stream.erb
    format.html { redirect_to @post }
  end
end

def destroy
  @comment.destroy
  render turbo_stream: turbo_stream.remove(@comment)
end

comments/create.turbo_stream.erb

<%= turbo_stream.append "comments", @comment %>        <%# renders _comment %>
<%= turbo_stream.update "comment_count", @post.comments.size %>
<%= turbo_stream.replace "new_comment" do %>
  <%= render "form", comment: Comment.new %>
<% end %>

Real-Time Broadcasts

class Comment < ApplicationRecord
  belongs_to :post
  broadcasts_to :post                     # append/replace/remove on the post's stream
end

class Post < ApplicationRecord
  broadcasts_refreshes                    # page morphs when the post changes
end
# view: <%= turbo_stream_from @post %>  subscribes this page

Code Explained

format.turbo_stream — chosen when Turbo submits a form
turbo_stream.append "comments", @comment — render partial into #comments
update vs replace — inner HTML vs the whole element
broadcasts_to :post — callbacks broadcast after commit
turbo_stream_from — signed subscription tag in the view

The Rails Way

  • Custom JSON + JS DOM updates → Turbo Stream templates
  • Polling for new comments → broadcasts_to + turbo_stream_from
  • Many fine-grained broadcasts → broadcasts_refreshes and let morphing diff the page

Stream Actions

ActionDoes
append / prependAdd inside target, end / start
before / afterInsert as sibling
replaceSwap the whole target element
updateSwap inner HTML
removeDelete target
morphMorph target to new HTML
refreshRe-fetch and morph page

Broadcast Helpers

MethodWhen
broadcasts_to :postCallbacks → stream named by post
broadcastsStream named after the model
broadcast_append_later_toManual, via job

broadcast_remove_toManual remove

⚠ Common Mistakes

  • Returning Turbo Streams from GET requests; Turbo ignores them for normal visits
  • Broadcasting synchronously from heavy callbacks; use _later variants (the default for broadcasts_to)
  • Forgetting turbo_stream_from in the view, so broadcasts reach nobody

✓ Tips & Best Practices

  • Always keep an HTML fallback (format.html) for non-Turbo clients
  • Scope streams by account or user: turbo_stream_from Current.user, :notifications
  • Test stream responses with assert_turbo_stream action: :append, target: "comments"

Quick Summary

  • turbo_stream.* — targeted DOM actions
  • *.turbo_stream.erb — multi-action responses
  • broadcasts_to — real-time updates
  • broadcasts_refreshes — morph refresh
