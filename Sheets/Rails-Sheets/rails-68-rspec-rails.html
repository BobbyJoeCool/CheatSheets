The Popular Alternative Stack

Many teams use RSpec instead of Minitest, with FactoryBot instead of fixtures. RSpec's describe / it style reads like specification, and factories build records on demand with only the attributes each test cares about. rspec-rails adds Rails-aware spec types and generators.

Notes

  • Install: add rspec-rails and factory_bot_rails to the test group, then bin/rails g rspec:install
  • Generators create specs instead of tests once rspec-rails is installed
  • Run with bundle exec rspec or bin/rspec

spec/factories/users.rb

FactoryBot.define do
  factory :user do
    sequence(:email_address) { |n| "user#{n}@example.com" }
    password { "password" }
    name { "Ann" }
    trait(:admin) { role { :admin } }
  end

  factory :post do
    user
    title { "Hello" }
    trait(:published) { published { true } }
  end
end

spec/requests/posts_spec.rb

require "rails_helper"

RSpec.describe "Posts", type: :request do
  let(:user) { create(:user) }
  before { post session_path, params: { email_address: user.email_address, password: "password" } }

  describe "POST /posts" do
    it "creates a post" do
      expect {
        post posts_path, params: { post: { title: "New" } }
      }.to change(Post, :count).by(1)
      expect(response).to redirect_to(Post.last)
    end
  end
end

Code Explained

sequence — unique values per record
trait — named variations: create(:user, :admin)
user inside a factory — builds the association
expect { }.to change(...) — like assert_difference
shoulda-matchers — it { is_expected.to validate_presence_of(:title) }

The Rails Way

  • create everywhere → build / build_stubbed when the DB isn't needed
  • Huge factories with every attribute → minimal valid defaults + traits
  • Controller specs → request specs

⚠ Common Mistakes

  • Factories that create long association chains for every record, making suites slow
  • Overusing let!, which creates records even in tests that don't need them
  • Mixing fixtures and factories for the same model without a clear rule

✓ Tips & Best Practices

  • Run FactoryBot.lint in CI to catch invalid factories
  • Use bin/rspec --only-failures with example_status_persistence_file_path
  • Choose one stack per app; both are fully supported

Quick Summary

  • rspec-rails — spec types + generators
  • FactoryBot — records on demand
  • traits — variations
  • build_stubbed — fast specs
