Sheet 13

Rendering & Redirects

render :edit · status: :unprocessable_entity · render json: · head · redirect_to · status: :see_other · redirect_back_or_to · DoubleRenderError

Sending the Response

render builds a response body in the same request, usually a template. redirect_to tells the browser to make a new request to another URL. Use render to re-show a form with errors and redirect after a successful change (Post/Redirect/Get). head sends only a status and headers.

Response Notes

  • render doesn't run the target action; it only uses its template
  • Code after render / redirect_to still runs; add and return or return if needed
  • Turbo expects 422 for invalid forms and 303 after non-GET redirects
  • redirect_to accepts a model, a path, a URL or :back alternatives

Render Variants

render :edit                                    # posts/edit template
render "shared/notice"                          # another folder
render :new, status: :unprocessable_entity      # 422 for failed save
render json: @post                              # calls to_json
render json: { error: "nope" }, status: :forbidden
render plain: "OK"                              # text/plain
render html: helpers.tag.p("Hi")                # trusted HTML only
render partial: "row", locals: { post: @post }
render turbo_stream: turbo_stream.remove(@post)
head :no_content                                # 204, no body

Redirect Variants

redirect_to @post                               # post_path(@post)
redirect_to posts_path, notice: "Deleted", status: :see_other
redirect_to "https://example.com", allow_other_host: true
redirect_back_or_to root_path                   # referrer or fallback
redirect_to edit_post_path(@post) and return if @post.locked?

Code Explained

status: — symbol (:created) or number (201)
render json: — sets content type application/json
status: :see_other — 303 so DELETE/PATCH redirects become GET
allow_other_host: true — required for external redirects (open-redirect guard)
and return — stops the action after an early redirect

The Rails Way

  • render :index after a successful create → redirect_to so refresh doesn't resubmit
  • render :new (200) on failure → render :new, status: :unprocessable_entity
  • redirect_to request.referer → redirect_back_or_to fallback

⚠ Common Mistakes

  • Calling redirect_to twice in one action (often via a before_action plus the action) → DoubleRenderError
  • Rendering user input with render html: or render inline:; it bypasses escaping
  • Redirecting to params[:return_to] without url_from or a host check (open redirect)

✓ Tips & Best Practices

  • Use url_from(params[:return_to]) || root_path to accept only same-host return URLs
  • Pass notice: / alert: to redirect_to instead of setting flash on a separate line
  • For APIs, head :created, location: @post is often all a client needs

Quick Summary

  • render — same request
  • redirect_to — new request
  • 422 — invalid form
  • 303 — after DELETE/PATCH
