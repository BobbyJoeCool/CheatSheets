Debugging & Logging

debug gem · binding.break · console --sandbox · web-console · log levels · tagged logging · bullet / rack-mini-profiler

Finding Out What Happened

Rails includes the debug gem: drop debugger (or binding.break) in code and the server stops there with an interactive prompt. The web-console gem gives a console on error pages. Logs show every request, its params, SQL queries and render times, and query log tags can point each SQL line back to its controller.

Notes

  • The debugger prompt appears in the terminal running bin/rails server (or bin/dev)
  • Development error pages include a live console from web-console
  • config.active_record.verbose_query_logs = true shows the Ruby line for each query
  • Rails.logger.debug { expensive } with a block skips work when the level is higher

Breakpoints

def update
  @post = Post.find(params.expect(:id))
  debugger                         # or binding.break
  @post.update!(post_params)
end

Debugger Commands

(rdbg) info               # local and instance variables
(rdbg) p @post.errors.full_messages
(rdbg) n                  # next line          s   # step into
(rdbg) c                  # continue           bt  # backtrace
(rdbg) break Post#publish!   # add a breakpoint
(rdbg) watch @post.title  # stop when it changes

Logging

Rails.logger.info "Imported #{rows.size} rows"
Rails.logger.debug { "payload: #{payload.inspect}" }
Rails.logger.tagged("Import", import.id) { Rails.logger.warn "skipped row" }

# config/environments/development.rb
config.log_level = :debug
config.active_record.verbose_query_logs = true
config.active_record.query_log_tags_enabled = true   # /*controller:posts,action:show*/

Console Tricks

Post.where(published: true).to_sql
app.get "/posts"; app.response.status      # simulate a request
ActiveRecord::Base.logger = Logger.new($stdout)   # SQL in a script

Code Explained

debugger — stops execution in the server process
info / p — inspect state at the breakpoint
watch — break when an expression changes
Block form of debug — only builds the string when logged
Query log tags — SQL comments name the controller/action/job

The Rails Way

  • puts debugging and restarting → debugger and inspect live
  • pp in production code → tagged, leveled Rails.logger calls
  • Guessing which line ran a query → verbose_query_logs

Log Levels

⚠ Common Mistakes

  • Leaving debugger calls in committed code; CI or production processes hang waiting for input
  • Logging secrets or full params in custom log lines
  • Debugging with bin/dev and missing the prompt among watcher output; run the server alone

✓ Tips & Best Practices

  • Add a RuboCop rule or grep in bin/ci for leftover debugger calls
  • Use RUBY_DEBUG_OPEN=true for remote debugging from VS Code
  • Read logs by request id when concurrent requests interleave

Quick Summary

  • debugger — breakpoint
  • web-console — console on error pages
  • Rails.logger.tagged — contextual logs
  • query log tags — SQL → code
