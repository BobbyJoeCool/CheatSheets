Sheet 39

Calculations & Grouping

count · sum · average · minimum / maximum · group · having · select with alias · distinct

Let the Database Do the Math

Calculation methods run aggregate SQL and return numbers or hashes, without loading records. Add group to get a hash keyed by the grouped value. For several aggregates at once, select with aliases and read them as attributes.

Notes

  • count → Integer; average → BigDecimal; sum on empty → 0
  • Grouped calculations return a Hash: { "draft" => 3, "live" => 9 }
  • count on a loaded relation still queries; size uses the loaded array
  • having filters groups after aggregation

Single Values

Order.count                              # 120
Order.where(status: "paid").sum(:total)  # 4821.50
Order.average(:total)                    # 40.18 (BigDecimal)
Order.minimum(:created_at)
Order.maximum(:total)
Order.distinct.count(:user_id)           # unique customers
Order.calculate(:sum, :total)            # generic form
Order.async_sum(:total)                  # Promise (7.1+): .value later

Grouping

Order.group(:status).count               # {"paid"=>90, "open"=>30}
Order.group(:user_id).sum(:total)        # {1=>120.0, 2=>87.5}
Order.group(:user_id).having("SUM(total) > ?", 100).sum(:total)
Order.group("DATE(created_at)").count    # per day
Order.joins(:user).group("users.country").count
Post.left_joins(:comments).group(:id).count("comments.id")

Multiple Aggregates

stats = Order.select("user_id, COUNT(*) AS orders_count, SUM(total) AS spent")
             .group(:user_id).order(spent: :desc).limit(5)
stats.first.spent                        # alias readable as attribute

Code Explained

distinct.count(:col) — COUNT(DISTINCT col)
async_sum — run in the background, read .value when needed
having — conditions on aggregated values
left_joins + count("comments.id") — zero counts kept
Aliased columns become readers on the returned objects

The Rails Way

  • Order.all.map(&:total).sum → Order.sum(:total)
  • Counting children in a loop → group(...).count once
  • Frequent counts on big tables → counter caches or a rollup table

count vs size vs length

MethodBehavior
countAlways runs COUNT query
sizeCounter cache, or length if loaded, else COUNT
lengthLoads all records, counts array
empty? / any?Cheap existence check

⚠ Common Mistakes

  • Calling .length on an unloaded relation, which loads every row just to count
  • Grouping by a column but selecting others not in GROUP BY (PostgreSQL rejects it)
  • Treating average results as Floats in JSON; convert with .to_f or format them

✓ Tips & Best Practices

  • Use group_by_day etc. from the groupdate gem for time-series charts
  • Add an index on grouped and filtered columns used in dashboards
  • Cache expensive aggregates with Rails.cache.fetch keyed on maximum(:updated_at)

Quick Summary

  • count / sum / average — aggregates
  • group(...).count — hash per group
  • having — filter groups
  • size — cheapest count
