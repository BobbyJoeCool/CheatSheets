has_one, :through & HABTM

has_one · has_many through: · has_one through: · source: · join models · has_and_belongs_to_many

One-to-One and Many-to-Many

has_one is has_many limited to one record. For many-to-many, has_many :through goes via a join model that can hold its own data (role, position, timestamps). has_and_belongs_to_many uses a bare join table with no model; it's simpler but can't grow.

Notes

  • has_one keeps the FK on the other table, like has_many
  • Join model tables: memberships(user_id, team_id, role)
  • HABTM table name is both plurals in alphabetical order: posts_tags
  • Assigning user.team_ids = [1, 2] writes join rows for you

Models

class User < ApplicationRecord
  has_one  :profile, dependent: :destroy
  has_many :memberships, dependent: :destroy
  has_many :teams, through: :memberships
  has_many :owned_teams, -> { where(memberships: { role: "owner" }) },
           through: :memberships, source: :team
  has_one  :address, through: :profile          # has_one :through
end

class Membership < ApplicationRecord
  belongs_to :user
  belongs_to :team
  validates :user_id, uniqueness: { scope: :team_id }
end

class Team < ApplicationRecord
  has_many :memberships, dependent: :destroy
  has_many :users, through: :memberships
end

class Post < ApplicationRecord
  has_and_belongs_to_many :tags          # table posts_tags, no model
end

Using Them

user.create_profile!(bio: "Hi")              # has_one builder
user.teams << team                           # creates a Membership
user.memberships.create!(team: team, role: "owner")
user.owned_teams                             # through with a condition
team.users.where(memberships: { role: "admin" })
post.tag_ids = [1, 3]                        # rewrites posts_tags

Code Explained

create_profile! — has_one gets build_/create_ methods
through: :memberships — query hops through the join model
source: :team — which association on the join model to follow
<< — saves the join row immediately
HABTM — no model, no extra columns, no callbacks on the join

The Rails Way

  • HABTM for anything that might get attributes → has_many :through from day one
  • Querying the join table with raw SQL → filter via where(memberships: {...})
  • Uniqueness only in Ruby → add a unique index on [user_id, team_id]

⚠ Common Mistakes

  • Putting the FK on the wrong side of has_one (it belongs on profiles.user_id)
  • Forgetting dependent: :destroy on the join association and leaving orphan memberships
  • Using source: when the names already match, or omitting it when they don't (HasManyThroughSourceAssociationNotFoundError)

✓ Tips & Best Practices

  • Name join models after the relationship (Membership, Enrollment), not UserTeam
  • Use has_many :through with -> { distinct } when the same record can be reached twice
  • For ordered lists, add a position column to the join model

Quick Summary

  • has_one — single child
  • has_many :through — join model
  • source: — follow a different name
  • HABTM — bare join table
