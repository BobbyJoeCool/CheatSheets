Query Basics

find · find_by · where · order · limit / offset · first / last / take · pluck · exists?

Asking the Database

Query methods return an ActiveRecord::Relation, which is lazy: the SQL runs only when you iterate, call to_a, or use a terminal method like first, count or pluck. Relations chain, so you can build a query step by step.

Query Facts

  • find raises RecordNotFound; find_by returns nil
  • first / last order by primary key when there's no order
  • take adds LIMIT 1 with no ordering
  • pluck returns plain values without building model objects

Finding & Filtering

Post.find(1)                              # raise if missing
Post.find([1, 2, 3])                      # array
Post.find_by(slug: "hello")               # nil if missing
Post.find_by!(slug: "hello")              # raise if missing
Post.where(published: true)               # relation
Post.where(published: true).where.not(user_id: nil)
Post.order(created_at: :desc).limit(10).offset(20)
Post.first; Post.last(3); Post.take
Post.pluck(:id, :title)                   # [[1, "Hi"], ...]
Post.pick(:title)                         # first value only
Post.ids                                  # [1, 2, 3]
Post.exists?(slug: "hello")               # true / false
Post.where(user: user).any?               # SELECT 1 ... LIMIT 1
Post.select(:id, :title)                  # partial objects
Post.distinct.pluck(:user_id)
Post.find_or_create_by!(slug: "about") { |p| p.title = "About" }

Seeing the SQL

Post.where(published: true).to_sql
# SELECT "posts".* FROM "posts" WHERE "posts"."published" = 1
Post.where(published: true).explain

Code Explained

where(user: user) — accepts a model; uses its id
order(created_at: :desc) — hash form avoids SQL strings
pick — pluck + first in one query
exists? / any? — cheapest way to check for rows
find_or_create_by! — block runs only when creating

The Rails Way

  • Post.all.select { |p| p.published } (Ruby) → Post.where(published: true) (SQL)
  • Post.all.map(&:id) → Post.ids or pluck(:id)
  • Post.where(...).count > 0 → .exists?

⚠ Common Mistakes

  • Calling .all and filtering in Ruby; it loads every row
  • Using find_by and forgetting it can return nil → NoMethodError later
  • Expecting last to mean "newest" without an order on a non-sequential key (UUIDs)

✓ Tips & Best Practices

  • Use Post.none to return an empty chainable relation from a method
  • Set self.implicit_order_column = "created_at" for UUID primary keys
  • Use .load_async in controllers for slow independent queries

Quick Summary

  • Relation — lazy, chainable
  • find / find_by — raise vs nil
  • pluck — values, not objects
  • exists? — cheap existence check
