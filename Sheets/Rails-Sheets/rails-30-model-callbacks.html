Model Callbacks

before_validation · before_save · after_create · after_commit · around_save · throw :abort · callback pitfalls

Hooks in the Record Lifecycle

Callbacks run at points in a record's life: before or after validation, save, create, update and destroy. They are useful for derived values and side effects tied to persistence. Use after_commit for anything outside the database (jobs, emails, cache), because it only runs once the transaction is really committed.

Callback Rules

  • throw :abort in a before_* callback cancels the save or destroy
  • Callbacks run inside the save transaction, except after_commit / after_rollback
  • after_create_commit, after_update_commit, after_destroy_commit, after_save_commit are shortcuts
  • Bulk methods (update_all, delete_all, insert_all) skip callbacks

app/models/post.rb

class Post < ApplicationRecord
  before_validation :set_slug, if: -> { slug.blank? }
  before_save       :strip_title
  before_destroy    :prevent_if_published, prepend: true
  after_create_commit  -> { NotifyFollowersJob.perform_later(self) }
  after_update_commit  :expire_cache, if: :saved_change_to_title?
  around_save       :log_timing

  private

  def set_slug     = self.slug = title.to_s.parameterize
  def strip_title  = title&.strip!
  def expire_cache = Rails.cache.delete(["post", id])

  def prevent_if_published
    throw :abort if published?
  end

  def log_timing
    started = Time.current
    yield                                    # runs the save
    Rails.logger.info "saved in #{Time.current - started}s"
  end
end

Code Explained

before_validation — set values before rules check them
prepend: true — run before dependent: :destroy callbacks
after_create_commit — enqueue jobs only after the row is visible to workers
saved_change_to_title? — dirty check that works after save
around_save — must yield

The Rails Way

  • after_save { Mailer.deliver_later } → after_commit so rolled-back saves don't send mail
  • Chains of callbacks doing business workflows → an explicit method or service object
  • Callbacks that change other models → be explicit in the caller where it's visible

⚠ Common Mistakes

  • Enqueuing jobs in after_save; the worker may run before commit and not find the record
  • Calling save inside an after_save callback, causing loops or double writes
  • Using after_initialize for heavy work; it runs for every loaded record

✓ Tips & Best Practices

  • Keep callbacks about the record itself; orchestrate cross-model work explicitly
  • Use ActiveRecord.after_all_transactions_commit { } (7.2+) in plain methods for post-commit work
  • Inspect a chain with Post._save_callbacks.map(&:filter)

Quick Summary

  • before_* — prepare or abort
  • throw :abort — cancel
  • after_commit — side effects
  • bulk methods — skip callbacks
