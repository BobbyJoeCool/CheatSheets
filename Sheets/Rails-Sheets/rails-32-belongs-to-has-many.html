belongs_to & has_many

belongs_to · has_many · foreign_key: · dependent: · optional: true · inverse_of: · counter_cache:

The Core Association Pair

belongs_to goes on the model whose table holds the foreign key; has_many goes on the other side. Together they add readers, writers, builders and query methods: post.comments.create!(...), comment.post. Rails infers the class and key names from the association name.

Association Facts

  • belongs_to is required by default; use optional: true to allow nil
  • The FK column lives on the belongs_to side: comments.post_id
  • Association readers are cached; call reload_post / post.comments.reload to refresh
  • dependent: decides what happens to children when the parent is destroyed

Models

class Post < ApplicationRecord
  belongs_to :author, class_name: "User", foreign_key: "user_id"
  has_many   :comments, dependent: :destroy
  has_many   :approved_comments, -> { where(approved: true) }, class_name: "Comment"
end

class Comment < ApplicationRecord
  belongs_to :post, counter_cache: true          # needs posts.comments_count
  belongs_to :parent, class_name: "Comment", optional: true
end

Generated Methods

post.comments                       # relation (lazy)
post.comments.create!(body: "Nice") # sets post_id
post.comments.build(body: "Draft")  # unsaved, in memory
post.comments.size                  # uses counter cache when present
post.comments.where(approved: false).count
post.comment_ids                    # [1, 4, 9]
comment.post                        # parent (cached)
comment.post = other_post           # reassign
comment.build_post(title: "x")      # belongs_to builder
Post.where.associated(:comments)    # posts with at least one comment

Code Explained

class_name: / foreign_key: — when the name doesn't match the class
Scoped has_many — a lambda adds conditions to an association
counter_cache: true — keeps posts.comments_count updated
build vs create! — memory only vs saved
size — count query, cached count, or loaded length, whichever is cheapest

The Rails Way

  • Comment.where(post_id: post.id) → post.comments
  • Comment.create(post_id: post.id, ...) → post.comments.create(...)
  • post.comments.count in a loop → a counter_cache column

⚠ Common Mistakes

  • Adding has_many :comments but forgetting the post_id column (use t.references)
  • Using dependent: :destroy on huge collections; it loads every row. Consider :destroy_async or :delete_all
  • Adding counter_cache to an existing table without backfilling: Post.reset_counters(id, :comments)

✓ Tips & Best Practices

  • Pair dependent: with a DB on_delete: FK rule to protect against raw SQL deletes
  • Use touch: true on belongs_to to keep parent cache keys fresh
  • Check generated methods in the console: Post.reflect_on_association(:comments)

Quick Summary

  • belongs_to — has the FK
  • has_many — the collection side
  • dependent: — child cleanup
  • counter_cache — cheap counts
