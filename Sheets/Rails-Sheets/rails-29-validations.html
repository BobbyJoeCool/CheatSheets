Validations

Keeping Bad Data Out

Validations run when you call save, create, update or valid?. If any fail, the record collects messages in errors and isn't saved. Rails ships validators for presence, length, format, numericality, uniqueness and more; custom rules go in validate methods.

Validation Notes

  • belongs_to validates presence of the parent by default
  • uniqueness runs a SELECT; pair it with a unique index to beat race conditions
  • Error messages come from I18n: activerecord.errors.models.user.attributes.email.taken
  • Skipped by: update_column, insert_all, update_all, save(validate: false)

app/models/user.rb

class User < ApplicationRecord
  validates :name,  presence: true, length: { maximum: 50 }
  validates :email, presence: true, uniqueness: { case_sensitive: false },
                    format: { with: URI::MailTo::EMAIL_REGEXP }
  validates :age,   numericality: { only_integer: true, greater_than_or_equal_to: 13 },
                    allow_nil: true
  validates :terms, acceptance: true, on: :create
  validates :password, confirmation: true, length: { minimum: 12 }, if: :password_digest_changed?
  validate  :birthday_not_in_future

  private

  def birthday_not_in_future
    errors.add(:birthday, "can't be in the future") if birthday&.future?
  end
end

Inspecting Errors

u = User.new(email: "bad")
u.valid?                        # false (runs validations)
u.errors.full_messages          # ["Name can't be blank", "Email is invalid"]
u.errors[:email]                # ["is invalid"]
u.errors.where(:email).first.type   # :invalid
u.errors.add(:base, "Account locked")

Code Explained

Multiple validators can share one validates line
allow_nil: true — skip the rule when the value is nil
on: :create — only for new records (also :update or a custom context)
if: / unless: — conditional validation
errors.add(:base, ...) — a message not tied to one field

The Rails Way

  • if params[:email].blank? checks in controllers → model validations
  • validates_presence_of :name (old style) → validates :name, presence: true
  • Uniqueness validation without an index → add the unique index as the real guard

⚠ Common Mistakes

  • Using ^ and $ in format regexes; they match per line. Use \A and \z
  • Relying on uniqueness alone; two concurrent requests can both pass
  • Validating presence of a boolean with presence: true; false is blank. Use inclusion: { in: [true, false] }

✓ Tips & Best Practices

  • Put reusable rules in a custom EachValidator class (validates :url, url: true)
  • Use validates_with for rules that span several attributes
  • Show errors.full_messages_for(:field) next to each input

Quick Summary

  • validates — declare rules
  • valid? / errors — check and read
  • validate — custom method
  • on: / if: — conditional rules
