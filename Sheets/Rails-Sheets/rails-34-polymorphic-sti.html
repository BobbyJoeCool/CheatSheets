Polymorphic, STI & Delegated Types

polymorphic: true · as: · _type column · single table inheritance · type column · delegated_type

One Association, Many Classes

A polymorphic belongs_to lets one model attach to several others: comments on posts *and* photos, stored as commentable_type + commentable_id. Single table inheritance stores subclasses in one table with a type column. Delegated types keep shared columns in one table and type-specific columns in their own tables.

Notes

  • Polymorphic FKs can't have database FK constraints
  • STI subclasses share every column; unused ones stay NULL
  • delegated_type (6.1+) is Basecamp's approach for feeds of mixed records
  • The type column stores the class name string

Polymorphic

class Comment < ApplicationRecord
  belongs_to :commentable, polymorphic: true    # commentable_type, commentable_id
end
class Post  < ApplicationRecord; has_many :comments, as: :commentable; end
class Photo < ApplicationRecord; has_many :comments, as: :commentable; end

# migration: t.references :commentable, polymorphic: true, null: false
photo.comments.create!(body: "Wow")
comment.commentable                             # => #<Photo id: 3>

Single Table Inheritance

class Vehicle < ApplicationRecord; end           # table vehicles, column type
class Car   < Vehicle; end
class Truck < Vehicle
  validates :payload, presence: true
end

Car.create!(name: "Civic")                       # type = "Car"
Vehicle.all                                      # Cars and Trucks
Truck.all                                        # WHERE type = 'Truck'

Delegated Type

class Entry < ApplicationRecord                  # entryable_type, entryable_id
  delegated_type :entryable, types: %w[Message Comment], dependent: :destroy
end
class Message < ApplicationRecord
  has_one :entry, as: :entryable, touch: true
end

Entry.messages                                   # scope per type
entry.message?                                   # predicate
Entry.create!(entryable: Message.new(subject: "Hi"), account: acct)

Code Explained

polymorphic: true — two columns instead of one FK
as: :commentable — the other side of a polymorphic association
STI — subclass queries add WHERE type = ... automatically
delegated_type — shared table for listing, own tables for details
Delegated types avoid STI's sparse NULL columns

The Rails Way

  • post_id + photo_id nullable columns on comments → one polymorphic association
  • STI with many type-specific columns → delegated types
  • Case statements on type strings → subclass methods (polymorphism)

Choosing

NeedUse
Child attaches to many parent typespolymorphic belongs_to
Subclasses with nearly identical columnsSTI
Mixed types listed together, different columnsdelegated_type
Shared behavior only, separate tablesconcern

Gotchas

⚠ Common Mistakes

  • Naming a regular column type, which triggers STI and raises SubclassNotFound
  • Eager loading a polymorphic association with joins; it can't join multiple tables. Use includes/preload
  • Huge STI tables where each subclass uses different columns

✓ Tips & Best Practices

  • Override sti_name and find_sti_class to keep stored type names stable across class renames
  • Add polymorphic: true, index: true in migrations (the default index covers type + id)
  • Start with delegated types for activity feeds or timelines

Quick Summary

  • polymorphic: true — many parent types
  • STI — subclasses in one table
  • delegated_type — shared + specific tables
  • as: — the has_many side
