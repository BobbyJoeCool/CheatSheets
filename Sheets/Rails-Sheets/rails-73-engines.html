Engines & Railties

rails plugin new · --mountable · isolate_namespace · mount Engine · Railtie · engine initializers

Mini-Apps Inside Your App

An engine is a Rails app packaged as a gem: models, controllers, views, routes and migrations that mount into a host app. Devise, Mission Control and Active Storage are engines. A Railtie is the lighter hook gems use to add configuration, initializers or rake tasks without app code.

Notes

  • --mountable engines are namespaced and have their own routes
  • isolate_namespace keeps engine helpers, tables and routes separate
  • Engine route helpers are prefixed: blog.posts_path; host routes via main_app.
  • Copy engine migrations into the host with bin/rails blog:install:migrations

Create & Mount

rails plugin new blog --mountable --database=sqlite3
# host Gemfile: gem "blog", path: "engines/blog"
bin/rails blog:install:migrations && bin/rails db:migrate

engines/blog/lib/blog/engine.rb

module Blog
  class Engine < ::Rails::Engine
    isolate_namespace Blog                       # Blog::Post, blog_posts table

    initializer "blog.assets" do |app|
      app.config.assets.paths << root.join("app/assets/stylesheets")
    end
    config.generators { |g| g.test_framework :minitest }
  end
end

Host App

# config/routes.rb
mount Blog::Engine, at: "/blog"

# inside engine views
link_to "Home", main_app.root_path
# host views
link_to "Blog", blog.root_path

A Railtie in a Gem

module MyGem
  class Railtie < ::Rails::Railtie
    config.my_gem = ActiveSupport::OrderedOptions.new
    initializer("my_gem.configure") { |app| MyGem.setup(app.config.my_gem) }
    rake_tasks { load "tasks/my_gem.rake" }
  end
end

Code Explained

--mountable — namespaced engine with its own router
isolate_namespace — tables prefixed (blog_posts), helpers scoped
initializer — runs during host boot
main_app. / blog. — cross-router helpers
Railtie — config + hooks, no app code

The Rails Way

  • A giant app with a self-contained admin or billing area → consider an engine (or just a namespace)
  • Copying the same feature between apps → extract a mountable engine gem
  • Monkey-patching from a gem's lib file → a Railtie initializer

⚠ Common Mistakes

  • Forgetting main_app. in engine layouts, so host links raise "undefined method"
  • Engines depending on host models directly; pass classes in through configuration
  • Skipping install:migrations, so engine tables never exist in the host

✓ Tips & Best Practices

  • Use the generated test/dummy app to test the engine in isolation
  • Expose configuration like Blog.user_class = "User" instead of hard-coding
  • Reach for a namespace first; extract an engine when a second app needs it

Quick Summary

  • Railtie — gem hooks into Rails
