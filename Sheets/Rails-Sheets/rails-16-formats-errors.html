Formats & Error Handling

respond_to · format.json · format.md + render markdown: (8.1) · rescue_from · RecordNotFound → 404 · public/404.html · exceptions_app

One Action, Many Formats

respond_to lets one action answer HTML, JSON, Turbo Stream, CSV or (8.1) Markdown based on the URL extension or Accept header. rescue_from turns exceptions into responses in one place. In production, unhandled errors map to status codes and the static pages in public/.

Format & Error Notes

  • Format comes from .json in the URL or the Accept header
  • An unlisted format raises ActionController::UnknownFormat (406)
  • ActiveRecord::RecordNotFound becomes a 404 in production automatically
  • Rails 8.1 can render Markdown: render markdown: @page calls @page.to_markdown

respond_to

def show
  @post = Post.find(params.expect(:id))
  respond_to do |format|
    format.html                                   # show.html.erb
    format.json { render json: @post }
    format.csv  { send_data @post.to_csv, filename: "post.csv" }
    format.md   { render markdown: @post }        # 8.1: needs #to_markdown
  end
end

rescue_from

class ApplicationController < ActionController::Base
  rescue_from ActiveRecord::RecordNotFound, with: :not_found
  rescue_from Pundit::NotAuthorizedError do
    redirect_back_or_to root_path, alert: "Not allowed"
  end

  private

  def not_found
    respond_to do |format|
      format.html { render "errors/not_found", status: :not_found }
      format.json { render json: { error: "not found" }, status: :not_found }
    end
  end
end

Custom Error Pages (config/application.rb)

config.exceptions_app = routes   # then: match "/404", to: "errors#not_found", via: :all

Code Explained

format.html with no block — renders the default template
send_data — stream generated content as a download
render markdown: — 8.1, sets text/markdown
rescue_from ... with: — one handler for every action in the class
exceptions_app = routes — render error pages through your own controller

The Rails Way

  • begin/rescue around find in every action → let it raise; handle with rescue_from or the 404 page
  • Separate show_json actions → one action with respond_to
  • rescue_from StandardError → rescue specific error classes

⚠ Common Mistakes

  • rescue_from StandardError hides bugs and swallows errors your error tracker should see
  • Expecting the 404 page in development; set config.consider_all_requests_local = false to preview it
  • Forgetting format.json in respond_to and getting 406 from API clients

✓ Tips & Best Practices

  • Report rescued errors with Rails.error.report(e) so they still reach monitoring
  • Keep public/500.html plain HTML; it must render even when the app can't
  • Use request.format.json? checks sparingly; respond_to is clearer

Quick Summary
