Sheet 75

Production Configuration

production.rb · force_ssl / assume_ssl · eager_load · logging to STDOUT · /up health check · config/puma.rb · SQLite in production

Ready for Real Traffic

config/environments/production.rb turns on eager loading, caching, SSL and STDOUT logging. Puma serves requests with a few threads per process. In Rails 8, SQLite in production is a supported default for single-server apps, with separate databases for the Solid Queue, Cache and Cable data.

Notes

  • RAILS_ENV=production and RAILS_MASTER_KEY must be set
  • /up returns 200 when the app boots: point load balancers and Kamal at it
  • Puma: RAILS_MAX_THREADS (default 3) and WEB_CONCURRENCY processes
  • Run bin/rails db:prepare on deploy (the Docker entrypoint does this)

config/environments/production.rb (key lines)

Rails.application.configure do
  config.enable_reloading = false
  config.eager_load = true
  config.consider_all_requests_local = false
  config.action_controller.perform_caching = true
  config.public_file_server.headers = { "cache-control" => "public, max-age=#{1.year.to_i}" }
  config.active_storage.service = :local
  config.assume_ssl = true                     # behind a TLS-terminating proxy
  config.force_ssl  = true                     # redirect + HSTS + secure cookies
  config.log_tags = [:request_id]
  config.logger   = ActiveSupport::TaggedLogging.logger(STDOUT)
  config.log_level = ENV.fetch("RAILS_LOG_LEVEL", "info")
  config.silence_healthcheck_path = "/up"
  config.cache_store = :solid_cache_store
  config.active_job.queue_adapter = :solid_queue
  config.action_mailer.default_url_options = { host: "example.com" }
  config.hosts = ["example.com", /.*\.example\.com/]
end

config/puma.rb

threads_count = ENV.fetch("RAILS_MAX_THREADS", 3)
threads threads_count, threads_count
port ENV.fetch("PORT", 3000)
workers ENV.fetch("WEB_CONCURRENCY", 1)
plugin :tmp_restart
plugin :solid_queue if ENV["SOLID_QUEUE_IN_PUMA"]   # jobs inside Puma

Code Explained

eager_load — load all code at boot: faster requests, catches autoload errors
assume_ssl — trust that the proxy terminated HTTPS
STDOUT logging — containers and Kamal collect it
silence_healthcheck_path — keep /up out of the logs
plugin :solid_queue — one-box deploys run jobs in the web process

The Rails Way

  • Log files inside containers → STDOUT with tags
  • Postgres + Redis for a small single-server app → SQLite + Solid trio (Rails 8 default)
  • Custom health endpoints → the built-in /up

⚠ Common Mistakes

  • Storing SQLite files or uploads inside the container filesystem without a volume; they vanish on deploy
  • Setting the DB pool below Puma's thread count → connection timeouts
  • Leaving config.hosts empty behind a proxy that forwards arbitrary Host headers

✓ Tips & Best Practices

  • Use bin/rails runner -e production 'p Rails.configuration.eager_load' to check config in the image
  • Run Litestream or volume snapshots to back up SQLite databases
  • Report errors with an error tracker subscribed via Rails.error.subscribe
