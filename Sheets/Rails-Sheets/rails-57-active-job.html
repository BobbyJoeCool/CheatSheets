Active Job Basics

ApplicationJob · perform_later · perform_now · set(wait:) · queue_as · retry_on / discard_on · GlobalID arguments

Background Work

Active Job is Rails' common interface for background jobs. You write a job class with a perform method and enqueue it with perform_later; a queue backend runs it in a separate process. Rails 8 uses Solid Queue (database-backed) by default, but the same code works with Sidekiq, GoodJob and others.

Notes

  • Jobs live in app/jobs; generate with bin/rails g job SendDigest
  • Model arguments are serialized as GlobalID and re-fetched when the job runs
  • enqueue_after_transaction_commit (7.2+) can defer enqueues until commit; check your version's default
  • Development and test can use the :async / :test adapters

app/jobs/send_digest_job.rb

class SendDigestJob < ApplicationJob
  queue_as :mailers
  retry_on Net::OpenTimeout, wait: :polynomially_longer, attempts: 5
  discard_on ActiveJob::DeserializationError        # record was deleted

  def perform(user, since: 1.day.ago)
    posts = user.followed_posts.where(created_at: since..)
    DigestMailer.with(user:, posts:).digest.deliver_now if posts.any?
  end
end

Enqueuing

SendDigestJob.perform_later(user)                     # as soon as possible
SendDigestJob.set(wait: 10.minutes).perform_later(user)
SendDigestJob.set(wait_until: Date.tomorrow.noon, queue: :low).perform_later(user)
SendDigestJob.perform_now(user)                       # inline, same process
ActiveJob.perform_all_later(users.map { |u| SendDigestJob.new(u) })   # bulk

config/environments/production.rb

config.active_job.queue_adapter = :solid_queue
config.solid_queue.connects_to = { database: { writing: :queue } }

Code Explained

queue_as — choose a queue (workers can prioritize queues)
retry_on — retries with backoff, then re-raises after attempts
discard_on — drop the job silently for that error
Passing user — stored as gid://app/User/1, reloaded in the worker
perform_all_later — enqueue many in one round trip (7.1+)

The Rails Way

  • Sending email or calling APIs inside the request → perform_later
  • Passing serialized hashes of a record → pass the record (GlobalID)
  • Rescue-and-sleep loops in jobs → retry_on with wait:

⚠ Common Mistakes

  • Passing large payloads (whole CSVs) as arguments; store the file and pass an id
  • Writing non-idempotent jobs: retries may run them twice
  • Using perform_now in requests for slow work, defeating the purpose

✓ Tips & Best Practices

  • Make jobs small and idempotent; split big work into many jobs or use continuations (sheet 58)
  • Use deliver_later for mail; it's an Active Job under the hood
  • Enqueue from after_commit callbacks so workers never see uncommitted rows

Quick Summary

  • perform_later — enqueue
  • set(wait:) — schedule
  • retry_on / discard_on — failure policy
  • GlobalID — pass models safely
