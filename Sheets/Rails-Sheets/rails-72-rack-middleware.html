Rack & Middleware

Rack call(env) · bin/rails middleware · config.middleware.use · insert_before · custom middleware · Rack::Attack

Under the Controller

Rails is a Rack application. Every request passes through a stack of middleware (static files, logging, sessions, cookies, CSRF headers) before reaching the router. Middleware objects wrap the next app and can inspect or change the request and response, which makes them ideal for cross-cutting concerns like throttling, request ids or maintenance mode.

Notes

  • A Rack app responds to call(env) and returns [status, headers, body]
  • bin/rails middleware prints the stack in order
  • API-only apps start with a smaller stack
  • config.ru is the Rack entry point that runs Rails.application

A Custom Middleware

# lib/middleware/request_timer.rb
class RequestTimer
  def initialize(app) = @app = app

  def call(env)
    started = Process.clock_gettime(Process::CLOCK_MONOTONIC)
    status, headers, body = @app.call(env)
    ms = ((Process.clock_gettime(Process::CLOCK_MONOTONIC) - started) * 1000).round
    headers["server-timing"] = "app;dur=#{ms}"
    [status, headers, body]
  end
end

Registering & Reordering

# config/application.rb
require_relative "../lib/middleware/request_timer"
config.middleware.use RequestTimer
config.middleware.insert_before Rack::Runtime, Rack::Attack
config.middleware.insert_after ActionDispatch::Static, Rack::Deflater
config.middleware.delete Rack::Runtime
config.middleware.swap ActionDispatch::ShowExceptions, MyShowExceptions

Rack::Attack Throttle

# config/initializers/rack_attack.rb
Rack::Attack.throttle("logins/ip", limit: 5, period: 20.seconds) do |req|
  req.ip if req.path == "/session" && req.post?
end

Code Explained

initialize(app) — receive the next app in the chain
@app.call(env) — pass the request on, get the response back
server-timing — shows in browser dev tools
insert_before — position relative to an existing middleware
Rack::Attack — throttling and blocklists before Rails runs

The Rails Way

  • A before_action that only adds headers to every response → middleware
  • Throttling in controllers for everything → rate_limit per action, Rack::Attack app-wide
  • Monkey-patching Rails internals → insert or swap middleware

⚠ Common Mistakes

  • Returning a body that isn't enumerable or closing it twice; keep body from the inner app
  • Doing database work in middleware for every request including assets
  • Adding middleware that reads the whole body for every request (uploads get slow)

✓ Tips & Best Practices

  • Keep middleware in lib/ and require it: app/ isn't autoloadable while config loads
  • Use ActionDispatch::Request.new(env) for a friendlier request API
  • Check order with bin/rails middleware after changes

Quick Summary

  • Rack — call(env) → response
  • middleware — wraps the app
  • config.middleware — add/reorder
  • Rack::Attack — app-wide throttling
