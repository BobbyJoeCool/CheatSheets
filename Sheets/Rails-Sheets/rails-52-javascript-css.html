No-Build by Default, Bundlers When Needed

New Rails apps use import maps: the browser loads ES modules directly, mapped from bare names like "@hotwired/turbo-rails" to digested files. There's no Node, no build step and no node_modules. When you need npm-heavy libraries, JSX or TypeScript, switch to jsbundling-rails (esbuild, Bun, Rollup, Webpack). CSS frameworks plug in through tailwindcss-rails or cssbundling-rails.

Notes

  • Import maps rely on HTTP/2 and modern browsers loading many small modules
  • bin/importmap pin downloads the package into vendor/javascript
  • Bundler gems write output to app/assets/builds; Propshaft serves it
  • bin/dev runs the CSS/JS watchers alongside the server

config/importmap.rb

pin "application"
pin "@hotwired/turbo-rails", to: "turbo.min.js"
pin "@hotwired/stimulus", to: "stimulus.min.js"
pin "@hotwired/stimulus-loading", to: "stimulus-loading.js"
pin_all_from "app/javascript/controllers", under: "controllers"
pin "chart.js", to: "https://cdn.jsdelivr.net/npm/chart.js@4.4.4/+esm"   # or vendored

Commands

bin/importmap pin local-time        # vendor a package
bin/importmap unpin local-time
bin/importmap json                  # show the generated map
bin/importmap outdated              # newer versions available
bin/importmap audit                 # known vulnerabilities

./bin/bundle add tailwindcss-rails && bin/rails tailwindcss:install
./bin/bundle add jsbundling-rails  && bin/rails javascript:install:esbuild

app/javascript/application.js

import "@hotwired/turbo-rails"
import "controllers"
import { Chart } from "chart.js"

Code Explained

pin — map a bare module name to a file
pin_all_from — every Stimulus controller, by folder
javascript_importmap_tags in the layout — emits the map and preloads
tailwindcss:install — config, bin/dev, and a build task
javascript:install:esbuild — package.json, build script, app/assets/builds

The Rails Way

  • npm install + Webpacker for a few libraries → bin/importmap pin
  • Inline <script> tags in views → Stimulus controllers (sheet 56)
  • Hand-written Tailwind CLI scripts → tailwindcss-rails watcher via bin/dev

Choosing a JS Approach

OptionBest When
importmap-railsHotwire apps, few npm deps, no transpiling
jsbundling + esbuildMany npm packages, JSX, TypeScript
jsbundling + bunSame, with Bun's runtime/tooling
vite_ruby (gem)Vite dev server, HMR, SPA-ish frontends

⚠ Common Mistakes

  • Pinning a package that ships only CommonJS; import maps need ES modules
  • Forgetting bin/dev and wondering why Tailwind classes have no styles
  • Mixing an import map and a bundler for the same entry point

✓ Tips & Best Practices

  • Use bin/importmap outdated and audit in CI
  • Vendor pins (download) rather than CDN links so deploys don't depend on a third party
  • Start with import maps; switching to esbuild later is a contained change

Quick Summary

  • import maps — no-build default
  • bin/importmap pin — add packages
  • jsbundling — esbuild/Bun when needed
  • tailwindcss-rails — Tailwind without Node
