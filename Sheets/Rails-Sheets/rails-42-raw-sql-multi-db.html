Below the ORM, and Beyond One Database

When a query is easier in SQL, find_by_sql returns models and select_all returns rows. Rails also supports multiple databases: separate primary databases (Solid Queue, Cache and Cable use this), read replicas with automatic switching, and horizontal shards.

Notes

  • Rails 8 production config already has primary, cache, queue and cable databases
  • Models choose a database through an abstract base class with connects_to
  • Automatic role switching sends GETs to the replica and writes to the primary
  • Each database has its own migrations folder (db/queue_migrate, etc.)

Raw SQL

Post.find_by_sql(["SELECT * FROM posts WHERE views > ? LIMIT 5", 100])
rows = ActiveRecord::Base.connection.select_all(
  "SELECT status, COUNT(*) AS n FROM posts GROUP BY status")
rows.to_a                       # [{"status"=>"live", "n"=>9}, ...]
ActiveRecord::Base.lease_connection.execute("VACUUM")
Post.sanitize_sql_array(["title = ?", t])

config/database.yml (production excerpt)

production:
  primary:
    <<: *default
    database: storage/production.sqlite3
  primary_replica:
    <<: *default
    database: storage/production_replica.sqlite3
    replica: true
  queue:
    <<: *default
    database: storage/production_queue.sqlite3
    migrations_paths: db/queue_migrate

Models & Switching

class ApplicationRecord < ActiveRecord::Base
  primary_abstract_class
  connects_to database: { writing: :primary, reading: :primary_replica }
end

ActiveRecord::Base.connected_to(role: :reading) { Report.heavy_query }
# config/environments/production.rb
config.active_record.database_selector = { delay: 2.seconds }

Code Explained

find_by_sql — returns model instances, with extra selected columns as attributes
select_all — ActiveRecord::Result, plain hashes
replica: true — read-only, no migrations
connected_to(role: :reading) — force queries to the replica
database_selector — reads go to the replica unless you wrote recently

The Rails Way

  • String-built SQL with interpolation → find_by_sql([sql, *binds])
  • Heavy reports on the primary → connected_to(role: :reading)
  • One giant database for jobs and cache → separate Solid databases (the Rails 8 default)

⚠ Common Mistakes

  • Reading from a replica right after a write and seeing stale data (replication lag)
  • Using execute for SELECTs; the result type varies by adapter. Use select_all
  • Joining tables that live in different databases; SQL can't join across connections

✓ Tips & Best Practices

  • Keep raw SQL in query objects or scopes with tests, not in controllers
  • Use ActiveRecord::Base.connection.exec_query when you need column types
  • Prefer lease_connection / with_connection (7.2+) over connection in new code

Quick Summary

  • find_by_sql — SQL → models
  • select_all — SQL → hashes
  • connects_to — pick databases
  • connected_to — switch role or shard
