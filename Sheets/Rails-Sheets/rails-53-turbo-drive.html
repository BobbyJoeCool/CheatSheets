Sheet 53

Turbo Drive

Turbo Drive · data-turbo="false" · data-turbo-method · 422 / 303 form responses · prefetch · page refreshes with morphing

SPA Speed with Server-Rendered HTML

Turbo Drive intercepts link clicks and form submissions, fetches the next page, and swaps the <body> without a full reload. CSS and JS stay loaded, so navigation feels instant. Turbo 8 adds prefetch on hover and page refreshes with morphing, which update only what changed and keep scroll position.

Notes

  • Included in new apps via import "@hotwired/turbo-rails"
  • Forms must answer 422 to re-render with errors, or 303 to redirect
  • Links hovered for 100 ms are prefetched (disable with data-turbo-prefetch="false")
  • Assets marked data-turbo-track="reload" force a full reload when they change

Controlling Turbo in HTML

<%= link_to "Download", report_path, data: { turbo: false } %>   <%# full page load %>
<%= link_to "Log out", session_path, data: { turbo_method: :delete } %>
<%= button_to "Delete", @post, method: :delete,
      form: { data: { turbo_confirm: "Delete this post?" } } %>
<%= link_to "Next", page_path(2), data: { turbo_action: "replace" } %>
<div id="player" data-turbo-permanent>…</div>                   <%# kept across pages %>

Morphing Refreshes (layout head)

<%= turbo_refreshes_with method: :morph, scroll: :preserve %>
<%= yield :head %>

Controller Responses Turbo Expects

if @post.save
  redirect_to @post, status: :see_other
else
  render :new, status: :unprocessable_entity
end

JavaScript

Turbo.visit("/posts", { action: "replace" })
document.addEventListener("turbo:load", () => { /* runs after each visit */ })

Code Explained

data: { turbo: false } — opt out for downloads or external pages
turbo_method: :delete — link that sends DELETE (prefer button_to)
turbo_confirm — native confirm dialog before submit
data-turbo-permanent — element survives navigation (needs an id)
turbo:load — use instead of DOMContentLoaded

The Rails Way

  • jQuery $(document).ready → Stimulus connect() or turbo:load
  • render :new (200) after failed save → 422 so Turbo shows errors
  • Rebuilding the page with JS after an update → morphing refresh

⚠ Common Mistakes

  • Initializing widgets on DOMContentLoaded; it fires once, not on Turbo visits
  • Returning 200 for invalid forms: the page doesn't change
  • Using GET links for logout or delete; prefetching can trigger them

✓ Tips & Best Practices

  • Use turbo:before-cache to close menus and modals before Turbo snapshots the page
  • Disable prefetch on links that hit expensive or side-effecting endpoints
  • Check the network tab: Turbo requests send Accept: text/vnd.turbo-stream.html, text/html

Quick Summary
