Writing WHERE Clauses Safely

Hash conditions cover most needs: equality, IN lists, ranges and NULL. When you need SQL fragments, pass values through placeholders so Rails quotes them. Never interpolate user input into a SQL string.

Condition Notes

  • where(status: nil) → IS NULL; where(id: [1, 2]) → IN (1, 2)
  • Ranges: 1..10 → BETWEEN; endless 10.. → >= 10
  • where.not with NULLs: NOT IN excludes NULL rows; add .or(where(x: nil)) if needed
  • Conditions on joined tables use the table name as a hash key

Hash & Range Conditions

Post.where(status: "live", user_id: [1, 2, 3])
Post.where(deleted_at: nil)                       # IS NULL
Post.where(created_at: 1.week.ago..)              # >= 1 week ago
Post.where(views: ..100)                          # <= 100
Post.where(published_on: Date.current.all_month)  # BETWEEN month start/end
Post.where.not(status: "draft")
Post.where(status: "live").or(Post.where(featured: true))
Post.joins(:user).where(users: { admin: true })
Post.where.missing(:comments)                     # LEFT JOIN … IS NULL
Post.where.associated(:author)                    # INNER JOIN, not null

SQL Fragments with Placeholders

Post.where("title LIKE ?", "%#{Post.sanitize_sql_like(q)}%")
Post.where("views > :min AND views < :max", min: 10, max: 100)
Post.where("lower(email) = ?", email.downcase)
Post.where(Post.arel_table[:views].gt(100))       # Arel
Post.order(Arel.sql("FIELD(status, 'live', 'draft')"))

# NEVER: Post.where("title = '#{params[:title]}'")

Code Explained

all_month — Active Support range helper for dates
or — both sides must have compatible joins/selects
where.missing / where.associated — no hand-written LEFT JOIN
? / :named — Rails quotes and escapes the values
Arel.sql — mark a trusted raw ordering string

The Rails Way

  • String conditions for simple equality → hash conditions
  • "created_at > '#{date}'" → where(created_at: date..)
  • Manual LEFT OUTER JOIN ... WHERE id IS NULL → where.missing(:assoc)

Hash → SQL

RubySQL
where(a: 1)a = 1
where(a: [1, 2])a IN (1, 2)
where(a: nil)a IS NULL
where(a: 1..5)a BETWEEN 1 AND 5
where(a: 1...5)a >= 1 AND a < 5
where.not(a: 1)a != 1
where(users: { x: 1 })users.x = 1

⚠ Common Mistakes

  • Interpolating params into where or order strings → SQL injection
  • Passing user input to order(params[:sort]); allow-list sort columns instead
  • Forgetting NULL rows disappear from where.not(status: "draft")

✓ Tips & Best Practices

  • Allow-list sorting: order(%w[title created_at].include?(s) ? s : :created_at)
  • Prefer where(..) ranges over string comparisons for dates and numbers
  • Run Brakeman (bin/brakeman) to catch unsafe SQL strings

Quick Summary

  • hash conditions — =, IN, NULL, ranges
  • where.not / or — negate / combine
  • ? placeholders — quote input
  • where.missing — no-child records
