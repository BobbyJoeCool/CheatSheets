Credentials & Secrets

credentials:edit · master.key · RAILS_MASTER_KEY · per-environment credentials · Rails.application.credentials · ENV · Rails.app.creds (8.2 edge)

Encrypted Secrets in the Repo

Rails stores secrets in config/credentials.yml.enc, encrypted with config/master.key. The encrypted file is committed; the key is not. In production the key comes from the RAILS_MASTER_KEY environment variable. Per-environment credential files let production use different secrets than development.

Notes

  • master.key is in .gitignore; share it through a password manager
  • Credentials include secret_key_base, which signs cookies and tokens
  • Kamal reads RAILS_MASTER_KEY from .kamal/secrets
  • Rails 8.2 (edge) adds Rails.app.creds, one API over ENV, .env and credentials

Editing

EDITOR="code --wait" bin/rails credentials:edit
bin/rails credentials:edit --environment production   # production.yml.enc + production.key
bin/rails credentials:show
bin/rails credentials:diff --enroll                   # readable git diffs

The Decrypted YAML

secret_key_base: 3f9a…
aws:
  access_key_id: AKIA…
  secret_access_key: wJal…
stripe:
  secret_key: sk_live_…

Reading

Rails.application.credentials.aws[:access_key_id]
Rails.application.credentials.dig(:stripe, :secret_key)
Rails.application.credentials.stripe!               # raise if missing (bang)
Rails.application.credentials.fetch(:sentry_dsn) { ENV["SENTRY_DSN"] }
ENV.fetch("DATABASE_URL")                           # 12-factor style

Code Explained

--wait — editor must block until the file closes
--environment production — separate file and key
dig — nested lookup, nil if missing
Bang reader — fail at boot instead of at the first request
ENV.fetch — raises KeyError when unset, unlike ENV[]

The Rails Way

  • Secrets in config/*.yml or committed .env files → credentials or deployment ENV
  • ENV["X"] with silent nil → ENV.fetch("X") or credentials.x!
  • Same key for all environments → per-environment credentials

⚠ Common Mistakes

  • Committing master.key or pasting it into chat or tickets
  • Losing master.key: the encrypted file can't be recovered, only re-created
  • Editing the .enc file directly instead of through credentials:edit

✓ Tips & Best Practices

  • Keep one shared password-manager item per environment key
  • Use credentials:diff --enroll so git diff shows decrypted changes locally
  • Rotate a leaked secret_key_base with a rotator so existing sessions survive

Quick Summary

  • credentials:edit — change secrets
  • master.key / RAILS_MASTER_KEY — never commit
  • credentials.dig — read nested
  • per-env files — separate prod secrets
