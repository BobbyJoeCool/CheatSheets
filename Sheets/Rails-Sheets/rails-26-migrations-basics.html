Migrations — Basics

g migration · create_table · t.references · t.timestamps · add_column · change vs up / down · db:migrate · db:rollback

Versioned Schema Changes

A migration is a Ruby class that changes the database schema. Each file is timestamped and runs once; Rails records it in schema_migrations. Most migrations use a single change method that Rails knows how to reverse, so the same file both applies and rolls back the change.

Migration Facts

  • Running migrations regenerates db/schema.rb; commit both
  • Never edit a migration that already ran on a shared database; add a new one
  • t.references :user adds user_id, an index and (with foreign_key: true) a FK
  • Default primary key is a bigint id

db/migrate/20261023120000_create_posts.rb

class CreatePosts < ActiveRecord::Migration[8.1]
  def change
    create_table :posts do |t|
      t.string     :title, null: false
      t.text       :body
      t.boolean    :published, default: false, null: false
      t.references :user, null: false, foreign_key: true
      t.timestamps                          # created_at, updated_at
    end
    add_index :posts, :title
  end
end

Changing Tables

class AddSlugToPosts < ActiveRecord::Migration[8.1]
  def change
    add_column :posts, :slug, :string
    add_index  :posts, :slug, unique: true
    rename_column :posts, :body, :content
    remove_column :posts, :legacy_flag, :boolean   # type keeps it reversible
  end
end

Running Them

bin/rails db:migrate                    # run pending
bin/rails db:rollback STEP=2            # undo last two
bin/rails db:migrate:status             # up / down list
bin/rails db:migrate VERSION=20261023120000
bin/rails db:migrate:redo               # rollback + migrate

Code Explained

Migration[8.1] — locks behavior to the Rails version that wrote it
null: false — database-level NOT NULL
foreign_key: true — real FK constraint
remove_column with a type — lets change reverse it
db:migrate:redo — quick check that change reverses cleanly

The Rails Way

  • Editing an old migration to fix a column → write a new migration
  • Validations only in the model → add null: false, unique indexes and FKs too
  • Writing up / down for simple changes → change with reversible commands

Column Commands

CommandReversible?
create_table / drop_table (with block)yes
add_column / remove_column (with type)yes
rename_column / rename_tableyes
add_index / remove_index (with columns)yes
change_columnno: use up/down or change_column_null
execute "SQL"no: use reversible

Database Tasks

TaskEffect
db:create / db:dropCreate / drop the DB
db:prepareCreate + load schema or migrate
db:resetDrop, create, load schema, seed
db:schema:loadLoad schema.rb (fresh DB)
db:seedRun db/seeds.rb

⚠ Common Mistakes

  • Running db:reset on a database with real data; it drops everything
  • Renaming a migration class or file after it ran; the version number no longer matches
  • Adding a null: false column with no default to a table that already has rows

✓ Tips & Best Practices

  • Use bin/rails g migration AddXToY x:type so the body is written for you
  • Run db:migrate:redo before pushing to prove the migration rolls back
  • Use strong_migrations (gem) to catch locking or unsafe migrations on big tables

Quick Summary

  • change — reversible migration
  • t.references — FK column + index
  • db:migrate / db:rollback — run / undo
  • schema.rb — commit it
