Controller Basics

What a Controller Does

A controller is a Ruby class whose public methods are actions. Rails creates a new instance per request, runs the action, then renders a response. Instance variables set in the action are available in the view. If the action doesn't render or redirect, Rails renders the template matching the action name.

Controller Facts

  • Name: plural resource + Controller (PostsController) in posts_controller.rb
  • All controllers inherit from ApplicationController, which inherits ActionController::Base
  • Only public methods are actions; put helpers under private
  • Each action must respond exactly once: render, redirect or head

app/controllers/posts_controller.rb

class PostsController < ApplicationController
  before_action :set_post, only: %i[show edit update destroy]

  def index
    @posts = Post.order(created_at: :desc)   # renders posts/index
  end

  def show; end                              # @post from set_post

  def create
    @post = Post.new(post_params)
    if @post.save
      redirect_to @post, notice: "Post created"
    else
      render :new, status: :unprocessable_entity
    end
  end

  private

  def set_post
    @post = Post.find(params.expect(:id))
  end

  def post_params = params.expect(post: [:title, :body])
end

Request & Response

request.path        # "/posts/1"     request.remote_ip
request.format      # :html / :json  request.get?
request.headers["User-Agent"]
response.status     # 200            response.headers["X-Id"] = "1"

Code Explained

index — no render call, so app/views/posts/index.html.erb renders
redirect_to @post — polymorphic, goes to post_path(@post)
render :new, status: :unprocessable_entity — re-show the form with errors (422)
private — keeps helper methods from becoming routable actions
params.expect — Rails 8 strong params (sheet 12)

The Rails Way

  • Database queries inside views → load data in the action into instance variables
  • Fat actions with business rules → move logic into models or plain Ruby objects
  • A dozen instance variables per action → pass one object or use a presenter

⚠ Common Mistakes

  • Leaving a helper method public; it becomes an action reachable if a route points at it
  • Rendering after redirect in the same action, which raises AbstractController::DoubleRenderError
  • Returning a 200 on failed validation; Turbo needs 422 to show the re-rendered form

✓ Tips & Best Practices

  • Keep actions short: set up, call the model, respond
  • Use endless methods (def x = ...) only for true one-liners like post_params
  • Use request.variant (e.g. :phone) for device-specific templates

Quick Summary

  • public method — an action
  • @ivars — data for the view
  • implicit render — template by name
  • private — non-action helpers
