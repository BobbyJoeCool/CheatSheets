Sheet 02

Installation & rails new

gem install rails · rails new · --database= · --css= · --javascript= · --api · --minimal · bin/setup

Getting a New App Running

Install a recent Ruby with a version manager, then gem install rails. rails new generates the app, runs bundle install, and sets up git. Its flags pick the database, CSS and JavaScript approach up front; changing them later is possible but tedious, so choose deliberately.

Before You Start

  • Rails 8.1 needs Ruby 3.2+; use the newest Ruby you can (3.4 / 4.0)
  • SQLite is the default database and is production-ready in Rails 8
  • rails new runs bundle install and git init unless you pass --skip-bundle / --skip-git
  • bin/setup installs gems, prepares the database and starts the server: the one command new teammates run

Install and Create

mise use -g ruby@3.4        # or rbenv / asdf
gem install rails           # latest 8.1.x
rails -v                    # Rails 8.1.4

rails new blog                          # SQLite, Importmap, Propshaft
rails new shop --database=postgresql --css=tailwind
rails new api_app --api                 # JSON-only, no views/assets
rails new tiny --minimal                # skip most frameworks
rails new blog -d mysql -j esbuild -c bootstrap

cd blog && bin/setup                    # gems + db:prepare + server
bin/dev                                 # server + CSS/JS watchers

Pin a Rails Version

rails _8.0.3_ new legacy_app            # use an installed older version

Code Explained

--database / -d — sqlite3 (default), postgresql, mysql, trilogy, mariadb-*
--css / -c — tailwind, bootstrap, bulma, postcss, sass
--javascript / -j — importmap (default), bun, esbuild, rollup, webpack
--api — ActionController::API, no views, cookies or asset pipeline
_8.0.3_ — RubyGems syntax to run a specific installed version

The Rails Way

  • sudo gem install on system Ruby → a version manager and a user-owned Ruby
  • Adding Webpacker/Node by reflex → start with Importmap; add a bundler (-j esbuild) only for npm-heavy apps
  • Writing a README of setup steps → keep bin/setup current so one command works

⚠ Common Mistakes

  • Running rails new inside another app folder: the new app picks up the outer Gemfile and fails to bundle
  • Choosing --api for an app that will later need sessions or HTML forms; adding them back is manual work
  • Using the global rails binary inside a project; always use bin/rails so the app's locked version runs

✓ Tips & Best Practices

  • Put your favorite flags in ~/.railsrc (one per line) to apply them to every rails new
  • Use rails new --help to see the exact flags your installed version supports
  • Commit right after rails new so generator diffs are easy to review later

Quick Summary

  • gem install rails — install
  • rails new app -d -c -j — create with choices
  • bin/setup — one-command setup
  • bin/dev — run with watchers
