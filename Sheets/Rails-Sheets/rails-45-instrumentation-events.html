Notifications & Structured Events

ActiveSupport::Notifications · instrument · subscribe · Rails.event (8.1) · tagged events · Rails.error.report · Rails.logger

Observing What Rails Does

Rails publishes instrumentation events for SQL queries, renders, controller actions, jobs and more. You can subscribe to them for metrics, or instrument your own code. Rails 8.1 adds structured event reporting (Rails.event) for machine-readable business and app events, and Rails.error is the unified error reporter.

Notes

  • Event names: sql.active_record, process_action.action_controller, perform.active_job …
  • Subscribers run synchronously in the same thread: keep them fast
  • Rails.event.notify sends structured events to registered subscribers
  • Rails.error.report / handle / record feed error trackers (Sentry, Honeybadger, …)

Subscribe & Instrument

# config/initializers/instrumentation.rb
ActiveSupport::Notifications.subscribe("process_action.action_controller") do |event|
  StatsD.timing("rails.request", event.duration,
                tags: ["action:#{event.payload[:controller]}##{event.payload[:action]}"])
end

ActiveSupport::Notifications.instrument("import.csv", rows: rows.size) do
  CsvImporter.new(file).run
end

Structured Events (8.1)

Rails.event.notify("user.signup", user_id: user.id, plan: "pro")
Rails.event.tagged("checkout") do
  Rails.event.notify("order.placed", order_id: order.id, total: order.total)
end
Rails.event.set_context(request_id: request.request_id)   # added to every event

class LogSubscriber
  def emit(event) = Rails.logger.info(event.to_json)       # name, payload, tags, context
end
Rails.event.subscribe(LogSubscriber.new)

Errors & Logs

Rails.error.handle(context: { order_id: 1 }) { risky_call }   # report + swallow
Rails.error.record { risky_call }                             # report + re-raise
Rails.error.report(e, handled: true)
Rails.logger.tagged("Billing") { Rails.logger.info "charged" }

Code Explained

event.duration — milliseconds for the instrumented block
instrument — publish your own event around a block
Rails.event.notify — name + payload hash, plus tags and context
subscribe(obj) — any object with an emit(event) method
handle vs record — swallow vs re-raise after reporting

The Rails Way

  • puts timing code around slow work → ActiveSupport::Notifications.instrument
  • Ad-hoc log strings for analytics → Rails.event.notify with a structured payload
  • rescue => e; Sentry.capture(e) → Rails.error.handle

⚠ Common Mistakes

  • Doing slow I/O inside a subscriber, which slows every request that emits the event
  • Logging personal data in event payloads without filtering
  • Using Rails.error.handle around code whose failure the caller must know about

✓ Tips & Best Practices

  • Use ActiveSupport::Notifications.monotonic_subscribe for accurate timings
  • Add request_id to event context so logs, events and errors line up
  • Look at Rails' own LogSubscribers to see payload keys for each event

Quick Summary
