Active Record Basics

ApplicationRecord · table naming conventions · new / save · create · update · destroy · persisted? · reload

One Class per Table

Active Record is Rails' ORM: each model class maps to a database table and each instance to a row. Columns become attributes automatically, read from the schema at boot. Saving runs validations and callbacks, then issues the SQL for you.

Conventions

  • Model Post ↔ table posts; LineItem ↔ line_items
  • Primary key id; foreign keys <model>_id
  • created_at / updated_at are set automatically
  • save returns true/false; save! raises on failure

app/models/post.rb

class Post < ApplicationRecord
end

CRUD in the Console

post = Post.new(title: "Hello")    # in memory
post.new_record?                   # true
post.save                          # INSERT … → true
post.persisted?                    # true

Post.create(title: "Quick")        # new + save
Post.create!(title: "")            # raises RecordInvalid if invalid

post.title = "Hi"
post.changed?                      # true
post.changes                       # {"title"=>["Hello", "Hi"]}
post.save                          # UPDATE only changed columns

post.update(title: "Hey")          # assign + save
post.update_column(:views, 10)     # skip validations/callbacks
post.increment!(:views)

post.destroy                       # DELETE + callbacks
post.destroyed?                    # true
post.reload                        # re-read from the DB

Code Explained

ApplicationRecord — your base class; add app-wide model behavior here
new vs create — build only vs build and save
changes — dirty tracking: title_changed?, title_was
update_column — direct SQL, no validations, no updated_at
destroy vs delete — callbacks vs raw SQL

The Rails Way

  • if post.save == false → if post.save … else render …
  • Bang methods in controllers with manual rescue → save + branch; use ! in scripts and jobs
  • self.table_name = "posts" → only when breaking conventions on purpose

Save Methods

MethodValidations · Callbacks · On failure
save / updateyes · yes · returns false
save! / update! / create!yes · yes · raises
update_attributeno · yes · saves anyway
update_column(s)no · no · direct SQL
touchno · after_touch · updates timestamps

State Predicates

MethodTrue When
new_record?Not yet saved
persisted?Saved and not destroyed
changed?Unsaved attribute changes
previously_new_record?Just created by last save
saved_change_to_title?Last save changed title

⚠ Common Mistakes

  • Ignoring the return value of save, so failed validations silently do nothing
  • Using update_column to "fix" validation errors and storing invalid data
  • Defining attributes with attr_accessor that shadow real columns

✓ Tips & Best Practices

  • Use saved_change_to_*? in after_save / after_commit callbacks; *_changed? is reset by then
  • Use Post.columns_hash or Post.attribute_names to inspect the schema in the console
  • Add annotaterb (gem) to print schema comments at the top of model files

Quick Summary

  • Post ↔ posts — convention
  • save / save! — false vs raise
  • update — assign + save
  • destroy — delete with callbacks
