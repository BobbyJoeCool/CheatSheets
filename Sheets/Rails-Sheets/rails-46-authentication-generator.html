Authentication Generator

g authentication (8.0) · has_secure_password · Session model · Current.user · require_authentication · allow_unauthenticated_access · password reset

Built-in Login, No Gem Required

Rails 8 ships bin/rails generate authentication, which writes plain, editable code for email/password login: a User with has_secure_password, a database-backed Session model, an Authentication concern, sessions and password-reset controllers, and a mailer. Every controller requires login by default; you opt public actions out.

What You Get

  • No sign-up form: add a RegistrationsController yourself
  • Sessions are rows, so users can be logged out per device
  • Login is rate limited (10 tries / 3 minutes) out of the box
  • Passwords use bcrypt via has_secure_password (add the bcrypt gem; generator uncomments it)

Generate

bin/rails generate authentication
bin/rails db:migrate

Generated Models (trimmed)

class User < ApplicationRecord
  has_secure_password
  has_many :sessions, dependent: :destroy
  normalizes :email_address, with: ->(e) { e.strip.downcase }
end

class Session < ApplicationRecord        # user_id, ip_address, user_agent
  belongs_to :user
end

Using It in Your Code

class PostsController < ApplicationController
  allow_unauthenticated_access only: %i[index show]
  def create = @post = Current.user.posts.create!(post_params)
end

authenticated?                          # helper in views/controllers
Current.user                            # the signed-in user
start_new_session_for(user)             # log in (e.g. after sign-up)
terminate_session                       # log out
User.authenticate_by(email_address: e, password: p)   # timing-safe lookup

Code Explained

has_secure_password — password=, authenticate, confirmation validation
allow_unauthenticated_access — skips require_authentication
Current.user — delegated from Current.session
authenticate_by — avoids user-enumeration timing differences
start_new_session_for — creates a Session row and signed cookie

The Rails Way

  • Reaching for Devise on day one → start with the generator; add pieces as needed
  • User.find_by(email:)&.authenticate(pw) → User.authenticate_by(...)
  • helper_method :current_user hand-rolled → Current.user from the generator

⚠ Common Mistakes

  • Assuming the generator includes sign-up, email confirmation or OAuth; it doesn't
  • Forgetting allow_unauthenticated_access on public pages, sending visitors to the login form
  • Exposing whether an email exists in the reset flow; keep the generic message

✓ Tips & Best Practices

  • Add sign-up with a RegistrationsController that saves a User, then calls start_new_session_for(user)
  • Add generates_token_for :email_confirmation for confirmation links (sheet 50)
  • Show a "log out other devices" page by listing Current.user.sessions

Quick Summary

  • g authentication — plain-code login (8.0)
  • Current.user — signed-in user
  • allow_unauthenticated_access — public actions
  • Session rows — revocable logins
