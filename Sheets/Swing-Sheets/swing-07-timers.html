Sheet 07

Swing Timers

javax.swing.Timer · setRepeats · setInitialDelay · start / stop · vs java.util.Timer · ScheduledExecutorService

Run Code Later or Repeatedly

javax.swing.Timer fires an ActionEvent after a delay, once or repeatedly, on the EDT. That makes it the right tool for clocks, blinking cursors, animation ticks, auto-save and debouncing typing. It does no work on another thread, so the action must stay short. For slow periodic work, schedule it on a ScheduledExecutorService and hop back to the EDT with invokeLater.

Notes

  • Delay is in ms; timing is best-effort
  • Late ticks merge (setCoalesce(true))
  • Import clash: javax.swing.Timer vs java.util.Timer

EDT Check

  • Swing Timer actions run on the EDT: safe to update components
  • java.util.Timer tasks run on its own thread: use invokeLater
  • A long action blocks other ticks and all painting

Clock, One-Shot and Debounce

// Repeating clock: tick every second
Timer clock = new Timer(1000, e -> timeLabel.setText(LocalTime.now()
        .truncatedTo(ChronoUnit.SECONDS).toString()));
clock.setInitialDelay(0);
clock.start();

// One-shot: hide a toast after 3 seconds
Timer hide = new Timer(3000, e -> toast.setVisible(false));
hide.setRepeats(false);
hide.start();

// Debounce: search 300 ms after the user stops typing
Timer debounce = new Timer(300, e -> runSearch(field.getText()));
debounce.setRepeats(false);
onTextChange(field, debounce::restart);     // helper from sheet 27

clock.stop();                               // when the window closes

Code Explained

new Timer(ms, listener) — delay plus action
setInitialDelay(0) — first tick immediately
setRepeats(false) — one-shot
restart() — reset the countdown (debounce)

JavaFX Equivalent

  • javax.swing.Timer → Timeline + KeyFrame
  • one-shot → PauseTransition
  • per-frame work → AnimationTimer
  • See Java 129

Prefer / Avoid

  • Thread.sleep loop updating labels → repeating Swing Timer
  • java.util.Timer touching components → Swing Timer

⚠ Common Mistakes

  • Importing java.util.Timer by accident — the code compiles but the constructor doesn't match, or runs off the EDT
  • Doing I/O in a timer action — freezes the UI on every tick
  • Never stopping a timer — keeps the window and its objects alive after closing

✓ Tips & Best Practices

  • Use restart() on a one-shot timer to debounce text input or resize events
  • Store timers in fields so you can stop them later
  • Use setCoalesce(true) (default) so a slow tick doesn't cause a burst

Quick Summary

  • new Timer(ms, action) — fires on the EDT
  • setRepeats(false) — one-shot delay
  • restart() — debounce pattern
  • slow periodic work — scheduler + invokeLater
