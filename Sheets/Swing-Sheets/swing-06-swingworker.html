Sheet 06

SwingWorker

doInBackground · done · get · publish / process · setProgress · PropertyChangeListener · cancel

Background Work with UI Callbacks

SwingWorker<T, V> runs a task on a background thread and gives you safe EDT callbacks. Override doInBackground() for the slow work and return a result of type T. Override done() to read the result with get() on the EDT. For progress, call publish(V...) and handle the chunks in process(List<V>), or call setProgress(0–100) and listen for the "progress" property.

Notes

  • A worker runs once; create a new one for each run
  • execute() starts it; cancel(true) interrupts it
  • Exceptions surface as ExecutionException from get()

EDT Check

  • doInBackground is off the EDT: don't touch components there
  • process, done and property listeners run on the EDT
  • get() blocks: call it in done(), never from another listener

Import with Progress

class ImportWorker extends SwingWorker<Integer, String> {
    @Override protected Integer doInBackground() throws Exception {
        int n = 0;
        for (Path f : files) {                 // off the EDT
            if (isCancelled()) break;
            importer.load(f);
            publish(f.getFileName().toString());
            setProgress(++n * 100 / files.size());
        }
        return n;
    }
    @Override protected void process(List<String> names) {
        names.forEach(log::append);            // EDT
    }
    @Override protected void done() {          // EDT
        try { status.setText(get() + " imported"); }
        catch (CancellationException e) { status.setText("Cancelled"); }
        catch (Exception e) { showError(e.getCause()); }
    }
}
ImportWorker w = new ImportWorker();
w.addPropertyChangeListener(e -> {             // "progress" events
    if ("progress".equals(e.getPropertyName()))
        bar.setValue((Integer) e.getNewValue());
});
w.execute();

Code Explained

<Integer, String> — result type, chunk type
publish → process — batched, on the EDT
get() in done() — result or exception

JavaFX Equivalent

  • SwingWorker → javafx.concurrent.Task
  • setProgress → updateProgress + progressProperty
  • done() → setOnSucceeded / setOnFailed
  • See Java 129

Prefer / Avoid

  • empty catch in done() → show e.getCause()
  • reusing one worker → a new worker per run

⚠ Common Mistakes

  • Ignoring get() in done() — exceptions from doInBackground vanish silently
  • Calling get() right after execute() on the EDT — blocks the UI until the task ends
  • Updating components from doInBackground — use publish or setProgress instead

✓ Tips & Best Practices

  • Check isCancelled() in loops so Cancel buttons respond quickly
  • For many tasks, run workers on your own ExecutorService with executor.execute(worker)

Quick Summary

  • doInBackground — slow work off the EDT
  • publish → process — progress chunks on the EDT
  • done + get — result or error on the EDT
  • cancel(true) + isCancelled — stop early
