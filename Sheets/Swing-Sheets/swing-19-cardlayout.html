CardLayout

CardLayout · show · next / previous · named cards · wizard pattern · swapping panels

One Panel at a Time

CardLayout stacks several panels in one container and shows exactly one, like a deck of cards. You give each card a name when adding it and switch with show(container, name). It's the simplest way to build wizards, settings pages driven by a list, and view switching. The container is sized to the largest card, so switching never resizes the window.

Notes

  • Hidden cards keep their state
  • next / previous wrap around
  • No built-in way to ask which card is showing

Three-Step Wizard

CardLayout cards = new CardLayout();
JPanel deck = new JPanel(cards);
deck.add(new AccountStep(), "account");
deck.add(new AddressStep(), "address");
deck.add(new ConfirmStep(), "confirm");

List<String> steps = List.of("account", "address", "confirm");
int[] current = {0};

JButton back = new JButton("Back"), next = new JButton("Next");
Runnable update = () -> {
    cards.show(deck, steps.get(current[0]));
    back.setEnabled(current[0] > 0);
    next.setText(current[0] == steps.size() - 1 ? "Finish" : "Next");
};
next.addActionListener(e -> {
    if (current[0] < steps.size() - 1) { current[0]++; update.run(); }
    else finish();
});
back.addActionListener(e -> { current[0]--; update.run(); });
update.run();

Code Explained

new JPanel(cards) — the deck container
add(panel, name) — name each card
show(deck, name) — switch cards
own index — track the current step

JavaFX Equivalent

  • CardLayout → StackPane + setVisible
  • or swap BorderPane.setCenter(node)
  • no direct class; switch nodes yourself
  • See Java 127

Prefer / Avoid

  • removeAll() + add() to switch views → CardLayout.show
  • next() for a wizard → named cards + your own index

⚠ Common Mistakes

  • Calling show with a name that wasn't added — nothing happens, no error
  • Calling cards.show(otherPanel, …) — the first argument must be the deck container
  • Expecting a smaller card to shrink the window — size comes from the largest card

✓ Tips & Best Practices

  • Store card names as constants or an enum
  • Validate a step before moving forward and keep the user on it if it fails
  • Use an empty-state card instead of hiding a table

Quick Summary

  • CardLayout — one visible child at a time
  • add(panel, name) — register cards
  • show(deck, name) — switch views
  • size — largest card wins
