Document, Change & Property Listeners

DocumentListener · insertUpdate / removeUpdate · DocumentFilter · ChangeListener · PropertyChangeListener · ItemListener

Reacting to Value Changes

Text components store text in a Document, and a DocumentListener hears every insert and remove, keystroke by keystroke. A DocumentFilter sits in front of the document and can change or reject edits before they happen, such as digits only. ChangeListener reports model changes on sliders, spinners and tabs. PropertyChangeListener hears bound properties, such as "enabled" or your own model fields.

Notes

  • DocumentListener has three methods; most code uses two
  • Attach to field.getDocument(), not the field
  • changedUpdate is for style changes only

EDT Check

  • A DocumentListener can't edit its own document (IllegalStateException)
  • Defer such edits with invokeLater
  • Model property events arrive on the thread that changed them

Live Validation and a Digits Filter

// Helper: one Runnable for any text change
static void onTextChange(JTextComponent c, Runnable r) {
    c.getDocument().addDocumentListener(new DocumentListener() {
        public void insertUpdate(DocumentEvent e)  { r.run(); }
        public void removeUpdate(DocumentEvent e)  { r.run(); }
        public void changedUpdate(DocumentEvent e) { }   // styles only
    });
}
onTextChange(email,
    () -> okBtn.setEnabled(isValidEmail(email.getText())));

// Filter: allow digits only, max 5 chars
AbstractDocument zipDoc = (AbstractDocument) zip.getDocument();
zipDoc.setDocumentFilter(new DocumentFilter() {
    @Override public void replace(FilterBypass fb, int off, int len,
            String text, AttributeSet a) throws BadLocationException {
        String next = new StringBuilder(zip.getText())
                .replace(off, off + len, text).toString();
        if (next.matches("\\d{0,5}"))
            super.replace(fb, off, len, text, a);
        else UIManager.getLookAndFeel().provideErrorFeedback(zip);
    }
});

button.addPropertyChangeListener("enabled", e -> updateHint());

Code Explained

insertUpdate / removeUpdate — every edit
DocumentFilter.replace — accept or reject
provideErrorFeedback — the L&F beep
addPropertyChangeListener("name", …) — one property

JavaFX Equivalent

  • DocumentListener → textProperty().addListener
  • DocumentFilter → TextFormatter filter
  • PropertyChangeListener → JavaFX properties
  • See Java 130

Prefer / Avoid

  • KeyListener to watch typing → DocumentListener (catches paste too)
  • fixing text after insert → reject it first with a DocumentFilter

⚠ Common Mistakes

  • Calling setText inside a DocumentListener — throws "Attempt to mutate in notification"
  • Overriding only insertString in a filter — most edits arrive through replace
  • Listening on the field instead of its document — setDocument later loses the listener

✓ Tips & Best Practices

  • Write the onTextChange helper once and reuse it everywhere
  • Debounce expensive checks with a one-shot Swing Timer (sheet 07)
  • Use PropertyChangeSupport in your own models (sheet 55)

Quick Summary

  • DocumentListener — hear text edits
  • DocumentFilter — veto or change edits
  • ChangeListener — model value changed
  • PropertyChangeListener — bound properties
