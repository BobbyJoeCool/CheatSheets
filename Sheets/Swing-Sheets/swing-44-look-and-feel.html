Look and Feel

UIManager.setLookAndFeel · getSystemLookAndFeelClassName · Metal · Nimbus · updateComponentTreeUI · UIManager.put defaults

Pluggable Look and Feel

Every Swing component delegates its drawing to a UI delegate from the current look and feel (L&F). The JDK ships Metal (default), Nimbus, and system L&Fs for Windows, macOS and GTK. Set the L&F once at startup with UIManager.setLookAndFeel, before creating components. UIManager defaults (colors, fonts, insets) can be tweaked by key.

Notes

  • System L&F looks native but differs per OS
  • Defaults keys depend on the L&F
  • Third-party: FlatLaf (sheet 45)

EDT Check

  • Set the L&F before any component exists
  • Switching later: updateComponentTreeUI on each window, on the EDT

Choosing and Switching

public static void main(String[] args) {
    SwingUtilities.invokeLater(() -> {
        try {
            UIManager.setLookAndFeel(
                    UIManager.getSystemLookAndFeelClassName());
        } catch (Exception e) {
            // keep Metal if the L&F isn't available
        }
        UIManager.put("Table.showGrid", false);       // tweak a default
        new App().show();
    });
}

for (var info : UIManager.getInstalledLookAndFeels())
    if (info.getName().equals("Nimbus")) setLaf(info.getClassName());

void setLaf(String className) {                     // switch at runtime
    try { UIManager.setLookAndFeel(className); }
    catch (Exception e) { return; }               // not available
    for (Window w : Window.getWindows()) {
        SwingUtilities.updateComponentTreeUI(w);
        w.pack();
    }
}

Code Explained

getSystemLookAndFeelClassName — native-looking L&F
UIManager.put — change one default
getInstalledLookAndFeels — what this JDK has
updateComponentTreeUI — re-skin live windows

JavaFX Equivalent

  • L&F → CSS themes (Modena default)
  • UIManager.put → -fx- CSS properties
  • switch theme → setUserAgentStylesheet
  • See Java 133

Prefer / Avoid

  • setting the L&F after building the UI → first thing in main
  • hard-coded colors on components → UIManager keys or a theme

⚠ Common Mistakes

  • Setting the L&F after creating components — mixed old and new styles
  • Assuming system L&F colors match on every OS — test each platform
  • Calling updateComponentTreeUI without re-packing — sizes from the old L&F remain

✓ Tips & Best Practices

  • Prefer FlatLaf for a consistent modern look
  • Dump all defaults with UIManager.getDefaults().keys() to find a key
  • Use UIManager.getColor("…") in custom painting to match the theme
