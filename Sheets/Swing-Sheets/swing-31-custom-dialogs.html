Custom Dialogs

JDialog · owner · ModalityType · getRootPane().setDefaultButton · returning a result · dispose · Escape to close

Your Own Dialog Windows

When JOptionPane isn't enough, build a JDialog. Give it an owner window so it stays on top and centers correctly, choose a modality, add a form and OK/Cancel buttons, and expose the result through a method. With a modal dialog, setVisible(true) blocks until the dialog is hidden, so the next line can read the result.

Notes

  • Modal = blocks input to other windows
  • dispose() frees the dialog; reopen with a new one
  • Users expect Enter = OK and Escape = Cancel

EDT Check

  • setVisible(true) on a modal dialog returns only after it closes
  • Events keep flowing while it's open (a nested event loop)

Edit Dialog Returning a Result

class EditDialog extends JDialog {
    private Optional<Person> result = Optional.empty();
    private final JTextField name = new JTextField(20);

    EditDialog(Window owner, Person p) {
        super(owner, "Edit Person", ModalityType.APPLICATION_MODAL);
        name.setText(p.name());
        JButton ok = new JButton("OK"), cancel = new JButton("Cancel");
        ok.addActionListener(e -> {
            result = Optional.of(new Person(name.getText()));
            dispose();
        });
        cancel.addActionListener(e -> dispose());
        getRootPane().setDefaultButton(ok);                 // Enter
        getRootPane().registerKeyboardAction(e -> dispose(),
            KeyStroke.getKeyStroke("ESCAPE"),
            JComponent.WHEN_IN_FOCUSED_WINDOW);             // Escape
        add(buildForm(name, ok, cancel));
        pack();
        setLocationRelativeTo(owner);
    }
    Optional<Person> showDialog() { setVisible(true); return result; }
}
new EditDialog(frame, person).showDialog().ifPresent(this::save);

Code Explained

super(owner, title, modality) — owner + modal
setDefaultButton / Escape binding — keyboard
showDialog() — blocks, then returns the result
Optional — empty when cancelled

JavaFX Equivalent

  • JDialog → Stage + initOwner + initModality
  • result → Dialog<R> + setResultConverter
  • setVisible(true) → showAndWait()
  • See Java 128

Prefer / Avoid

  • new JDialog() with no owner → pass the parent window
  • public fields read after closing → a showDialog() returning Optional

⚠ Common Mistakes

  • No owner — the dialog can hide behind its window and gets its own taskbar entry
  • Calling setVisible(true) before pack() — the dialog flashes at the wrong size
  • Reading form fields after dispose() in another class — copy the result into a field first

✓ Tips & Best Practices

  • Use a modeless dialog for find/replace and tool palettes
  • Validate in the OK handler and keep the dialog open on errors
  • Escape via registerKeyboardAction or an InputMap on the root pane
