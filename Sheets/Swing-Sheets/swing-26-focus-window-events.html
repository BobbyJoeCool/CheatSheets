Focus, Closing and Resizing

Focus decides which component gets keyboard input; Tab moves it in the focus traversal order. A FocusListener reacts when a field gains or loses focus, which is handy for validation. A WindowListener reacts to the window opening, closing and activating; use windowClosing to ask "Save changes?". A ComponentListener reports resize, move, show and hide.

Notes

  • requestFocusInWindow() is the reliable focus call
  • Focus can only go to a visible, enabled, focusable component
  • windowClosed fires after dispose()

Confirm on Close, Focus on Open

frame.setDefaultCloseOperation(JFrame.DO_NOTHING_ON_CLOSE);
frame.addWindowListener(new WindowAdapter() {
    @Override public void windowOpened(WindowEvent e) {
        nameField.requestFocusInWindow();       // first field
    }
    @Override public void windowClosing(WindowEvent e) {
        if (!doc.isDirty() || confirmDiscard(frame)) {
            frame.dispose();                    // then windowClosed
        }
    }
});

emailField.addFocusListener(new FocusAdapter() {
    @Override public void focusLost(FocusEvent e) {
        if (!e.isTemporary()) validateEmail();  // ignore menu popups
    }
});

frame.addComponentListener(new ComponentAdapter() {
    @Override public void componentResized(ComponentEvent e) {
        prefs.putInt("width", frame.getWidth());
    }
});
helpLabel.setFocusable(false);                  // skip in Tab order

Code Explained

DO_NOTHING_ON_CLOSE — you decide in windowClosing
requestFocusInWindow — after the window shows
isTemporary() — focus left briefly (menus)
setFocusable(false) — remove from Tab order

JavaFX Equivalent

  • windowClosing → stage.setOnCloseRequest + consume
  • FocusListener → focusedProperty listener
  • componentResized → widthProperty listener
  • See Java 129

Prefer / Avoid

  • requestFocus() → requestFocusInWindow() (doesn't steal OS focus)
  • System.exit in windowClosing → dispose() and let the app exit

⚠ Common Mistakes

  • Validating in focusLost and calling requestFocus back — traps the user in the field
  • Handling windowClosing with EXIT_ON_CLOSE set — the app exits before your dialog shows
  • Calling requestFocusInWindow before the window is visible — it's ignored

✓ Tips & Best Practices

  • Validate on submit and show messages; use focusLost only for gentle hints
  • Use InputVerifier to block focus leaving an invalid field
  • Save window size and position in java.util.prefs.Preferences

Quick Summary
