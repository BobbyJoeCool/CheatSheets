Sheet 05

The Event Dispatch Thread

EDT · single-thread rule · invokeLater · invokeAndWait · isEventDispatchThread · frozen UI

One Thread for the UI

Swing is not thread-safe. Every event, repaint and component change runs on one thread: the Event Dispatch Thread (EDT). The rule is simple: touch Swing components only on the EDT, and keep work on the EDT short. Listeners already run on the EDT. Code on other threads hands UI updates back with SwingUtilities.invokeLater. Slow work on the EDT freezes the whole app because nothing else can paint or respond.

Notes

  • invokeLater queues work and returns at once
  • invokeAndWait queues work and blocks until it finishes
  • EventQueue.invokeLater is the same as SwingUtilities.invokeLater
  • Use SwingWorker (sheet 06) for background tasks with results

EDT Check

  • invokeAndWait on the EDT throws an Error
  • repaint() / revalidate() are safe from any thread
  • Violations show up as random glitches

Moving Work Off and Back On

button.addActionListener(e -> {             // runs on the EDT
    button.setEnabled(false);
    status.setText("Loading…");

    new Thread(() -> {                      // background thread
        List<String> rows = db.loadRows();  // slow I/O, off the EDT
        SwingUtilities.invokeLater(() -> {  // back to the EDT
            model.setRows(rows);
            status.setText(rows.size() + " rows");
            button.setEnabled(true);
        });
    }, "loader").start();
});

assert SwingUtilities.isEventDispatchThread();  // in UI-only code

// Bad: freezes every window for the whole call
// button.addActionListener(e -> model.setRows(db.loadRows()));

Code Explained

listener body — already on the EDT
new Thread(...) — runs the slow call elsewhere
invokeLater — queue the UI update back on the EDT
isEventDispatchThread() — assert you're on it

JavaFX Equivalent

  • EDT → JavaFX Application Thread
  • invokeLater → Platform.runLater
  • isEventDispatchThread → Platform.isFxApplicationThread
  • See Java 129

Prefer / Avoid

  • raw new Thread per click → SwingWorker (sheet 06)
  • Thread.sleep on the EDT → Swing Timer (sheet 07)

⚠ Common Mistakes

  • Doing file, network or database work in a listener — the window turns gray and stops responding
  • Updating a JLabel from a background thread — sometimes works, then fails under load
  • Calling invokeAndWait from code that might already be on the EDT — throws immediately

✓ Tips & Best Practices

  • Add assert SwingUtilities.isEventDispatchThread() to UI helper methods
  • Name background threads ("loader") so thread dumps are readable
  • Disable the button while work runs so users can't start it twice

Quick Summary

  • EDT — the only thread allowed to touch Swing
  • invokeLater — hand UI work to the EDT
  • listeners — already on the EDT; keep them short
  • slow work — move to a thread or SwingWorker
