Shipping Your App

The simplest package is an executable JAR with a Main-Class manifest entry, but users then need the right Java installed. jlink builds a trimmed runtime with just the modules you need (java.desktop plus yours). jpackage (Java 16) wraps app and runtime into a native installer: .dmg/.pkg on macOS, .msi/.exe on Windows, .deb/.rpm on Linux.

Notes

  • jpackage builds for the OS it runs on
  • Unsigned apps trigger security warnings
  • Windows .msi needs the WiX toolset

JAR, Runtime and Installer

# 1. Executable JAR (Gradle application plugin or Maven shade/jar plugin)
#    MANIFEST.MF:  Main-Class: com.example.inventory.App
java -jar build/libs/inventory.jar

# 2. Find needed modules and build a small runtime
jdeps --print-module-deps --ignore-missing-deps build/libs/inventory.jar
#    -> java.base,java.desktop,java.prefs
jlink --add-modules java.base,java.desktop,java.prefs \
      --strip-debug --no-header-files --no-man-pages \
      --output build/runtime

# 3. Native installer with jpackage
jpackage --name Inventory --app-version 1.4.0 \
  --input build/libs --main-jar inventory.jar \
  --main-class com.example.inventory.App \
  --runtime-image build/runtime \
  --icon packaging/Inventory.icns \
  --type dmg                       # msi, exe, deb, rpm, pkg
# macOS: add --mac-sign --mac-signing-key-user-name "Developer ID…"
# Windows: add --win-menu --win-shortcut

Code Explained

Main-Class — makes java -jar work
jdeps — which modules you use
jlink — trimmed Java runtime
jpackage --type dmg — native installer

JavaFX Equivalent

  • same jlink / jpackage tools
  • JavaFX needs the OpenJFX jmods for jlink
  • or tools like the JavaFX Gradle plugin
  • See Java 126

Prefer / Avoid

  • "install Java first" instructions → bundle a runtime with jpackage
  • fat JAR + manual .bat scripts → jpackage launcher

⚠ Common Mistakes

  • Shipping a JAR that depends on whatever Java users have — breaks on old or missing JREs
  • Running jpackage on one OS for all three — it only builds for the current OS
  • Skipping code signing — macOS Gatekeeper blocks the app

✓ Tips & Best Practices

  • Build installers in CI on one runner per OS
  • Pass UI flags like -Dsun.java2d.uiScale via --java-options
  • Notarize macOS builds after signing

Quick Summary

  • executable JAR — needs Java installed
  • jlink — app-sized runtime
  • jpackage — native installers per OS
  • signing — avoid security warnings
