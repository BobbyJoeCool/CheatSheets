Setting Up a Swing Project

Swing needs no dependency: it ships with the JDK. A modular project adds requires java.desktop; to module-info.java; a classpath project needs nothing. Icons, images and property files go in src/main/resources and load with getResource. Third-party pieces such as FlatLaf and MigLayout come from Maven Central. GUI builders generate layout code, which is handy for forms but hard to maintain by hand.

Notes

  • Java 21 LTS or later is the baseline for this set
  • Run headless servers with -Djava.awt.headless=true (no Swing UI)
  • macOS: set apple.awt.application.name before any AWT class loads
  • Build tools: see the Maven and Gradle sets

module-info.java + build

// src/main/java/module-info.java
module com.example.inventory {
    requires java.desktop;                  // Swing + AWT
    requires com.formdev.flatlaf;           // optional modern L&F
}

// build.gradle.kts
plugins { application }
dependencies { implementation("com.formdev:flatlaf:3.5.4") }
application { mainClass = "com.example.inventory.App" }

// Loading a resource from src/main/resources/icons/add.png
ImageIcon add = new ImageIcon(
    Objects.requireNonNull(App.class.getResource("/icons/add.png")));

// ./gradlew run      (Gradle)
// mvn exec:java      (Maven, with exec-maven-plugin)

Code Explained

requires java.desktop — Swing's module
application plugin — adds run and start scripts
getResource("/…") — loads from the classpath root
requireNonNull — fail fast on a missing icon

JavaFX Equivalent

  • java.desktop → javafx.controls (OpenJFX dependency)
  • Swing needs no download; JavaFX does
  • GUI builders → Scene Builder + FXML
  • See Java 131

Prefer / Avoid

  • file paths like "src/icons/a.png" → getResource("/icons/a.png")
  • JARs copied into lib/ → Maven or Gradle dependencies

⚠ Common Mistakes

  • Loading files by relative path — works in the IDE, fails once packaged as a JAR
  • Editing generated initComponents() code — the builder overwrites it on the next save
  • Setting macOS system properties after the first Swing class loads — they're ignored

✓ Tips & Best Practices

  • Keep a resources/icons folder and one helper method that loads icons
  • Set system properties at the top of main before touching Swing
  • Use a builder for complex forms, but keep event logic in your own classes

Quick Summary

  • requires java.desktop — the only module you need
  • getResource — load icons and files from the JAR
  • FlatLaf / MigLayout — common Maven Central add-ons
  • GUI builders — generate layout code
