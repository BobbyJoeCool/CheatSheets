Sources, Events and Listeners

Swing uses the observer pattern: a component (the source) keeps a list of listeners and calls them with an event object when something happens. Each listener type is an interface such as ActionListener or MouseListener. Single-method listeners are written as lambdas; multi-method ones use an adapter class so you override only what you need.

Notes

  • Listeners run on the EDT, in no guaranteed order
  • e.getSource() returns the component that fired
  • Every addXListener has a matching removeXListener
  • Java set: lambdas, anonymous classes

Three Ways to Listen

// 1. Lambda: single-method interfaces (ActionListener, ChangeListener)
button.addActionListener(e -> save());

// 2. Adapter: implement only the methods you need
table.addMouseListener(new MouseAdapter() {
    @Override public void mouseClicked(MouseEvent e) {
        if (e.getClickCount() == 2)
            openRow(table.rowAtPoint(e.getPoint()));
    }
});

// 3. Named class: reusable, testable, removable
class SaveOnEnter implements ActionListener {
    @Override public void actionPerformed(ActionEvent e) { save(); }
}
ActionListener l = new SaveOnEnter();
field.addActionListener(l);
field.removeActionListener(l);          // needs the same instance

Object src = e.getSource();             // which component fired
long when = e.getWhen();                // timestamp (InputEvent)

Code Explained

lambda — shortest for one-method listeners
MouseAdapter — empty defaults for all methods
named class — reuse and removal
getSource() — the firing component

JavaFX Equivalent

  • listeners → EventHandler<T> + setOnX
  • adapters → not needed (one handler per event)
  • property listeners → ChangeListener on properties
  • See Java 129

Prefer / Avoid

  • implements MouseListener with empty methods → extend MouseAdapter
  • one giant actionPerformed with getSource() checks → one listener per source

⚠ Common Mistakes

  • Removing a lambda with a new lambda — it's a different object, so nothing is removed
  • Adding the same listener in a method that runs often — it fires many times per event
  • Long work inside a listener — blocks the EDT (sheet 05)

✓ Tips & Best Practices

  • Keep listener bodies to one call into a controller method
  • Store listener references in fields if you'll remove them later
  • Prefer high-level events (ActionListener) over low-level (MouseListener) when both work

Quick Summary

  • source → event → listener — the observer pattern
  • lambdas — one-method listeners
  • adapters — override only what you need
  • removeXListener — needs the same instance
