Custom Table Models

AbstractTableModel · getRowCount · getValueAt · getColumnClass · isCellEditable · setValueAt · fireTableRowsInserted

Tables Over Your Own Data

Extend AbstractTableModel to show a List of your own objects without copying them into Object[] rows. Implement row count, column count and getValueAt; add column names, types and editing as needed. When the data changes, call the narrowest fire… method so the table updates only what changed and keeps the selection where it makes sense.

Notes

  • Records make tidy row types
  • The model owns the data; the table is a view
  • Several tables can share one model

EDT Check

  • Call fire… methods on the EDT
  • Fire the narrowest event: rows, not fireTableDataChanged

Records as Rows

record Item(String sku, String name, int qty) { }

class ItemModel extends AbstractTableModel {
    private static final String[] COLS = {"SKU", "Name", "Qty"};
    private final List<Item> items = new ArrayList<>();

    @Override public int getRowCount()        { return items.size(); }
    @Override public int getColumnCount()     { return COLS.length; }
    @Override public String getColumnName(int c) { return COLS[c]; }
    @Override public Class<?> getColumnClass(int c) {
        return c == 2 ? Integer.class : String.class;
    }
    @Override public Object getValueAt(int r, int c) {
        Item i = items.get(r);
        return switch (c) { case 0 -> i.sku(); case 1 -> i.name();
                            default -> i.qty(); };
    }
    void add(Item i) {
        items.add(i);
        fireTableRowsInserted(items.size() - 1, items.size() - 1);
    }
    Item at(int modelRow) { return items.get(modelRow); }
}

Code Explained

three required methods — rows, columns, value
getColumnName — header text
fireTableRowsInserted — just the new row
at(row) — typed access for listeners

JavaFX Equivalent

  • AbstractTableModel → ObservableList<Item>
  • getValueAt → setCellValueFactory
  • fire… → automatic on list change
  • See Java 128

Prefer / Avoid

  • fireTableDataChanged for every change → the narrowest fire…
  • copying data into Vectors → model reads your List directly

Fire Methods

MethodUse after
fireTableRowsInserted(a, b)adding rows
fireTableRowsUpdated(a, b)changing rows
fireTableRowsDeleted(a, b)removing rows
fireTableCellUpdated(r, c)one cell
fireTableStructureChanged()columns changed

Editing Hooks

isCellEditable(r, c)true to allow

⚠ Common Mistakes

  • Changing the list without firing — the table shows stale rows or throws index errors
  • Calling fireTableStructureChanged for data changes — loses column widths and renderers
  • Indexing the model with view rows — convert with convertRowIndexToModel first

✓ Tips & Best Practices

  • Keep a typed at(row) method so listeners don't cast
  • Replace all data in one go and fire fireTableDataChanged once
  • Use immutable records and replace rows on edit

Quick Summary

  • AbstractTableModel — table over your list
  • getValueAt / getColumnClass — what to show
  • narrow fire… — keep the view in sync
  • records — clean row types
