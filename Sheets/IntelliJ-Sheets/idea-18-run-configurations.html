Sheet 18

Run Configurations

Run ⌃R · Debug ⌃D · Run Anything ⌃⌃ · program args · VM options · env vars · before-launch · Services

Description

A run configuration describes how to start something: main class, program arguments, VM options, environment, working directory and before-launch tasks. IntelliJ creates one when you click a gutter ▶ icon. Save it as a project file to share it with the team. The Services tool window manages many running apps at once.

Notes

  • ⌃⇧R / Ctrl+Shift+F10 runs the config for the code at the caret
  • Modify options (⌥M) reveals hidden fields like env files
  • Templates set defaults for every new config of a type

Shared Config: .run/Shop.run.xml

<component name="ProjectRunConfigurationManager">
  <configuration name="Shop" type="Application">
    <option name="MAIN_CLASS_NAME" value="com.shop.ShopApp"/>
    <module name="shop"/>
    <option name="PROGRAM_PARAMETERS" value="--port 8080"/>
    <option name="VM_PARAMETERS" value="-Xmx512m"/>
    <envs><env name="DB_URL" value="jdbc:postgresql:shop"/></envs>
    <method v="2"><option name="Make" enabled="true"/></method>
  </configuration>
</component>

Code Explained

Store as project file writes .run/*.run.xml — commit it
PROGRAM_PARAMETERS → args[]; VM_PARAMETERS → JVM flags
Make before launch compiles first; add Maven goals or other configs too
Allow multiple instances: Modify options › Allow multiple

Where in Settings

  • Run › Edit Configurations › Edit configuration templates — defaults
  • Build… › Build Tools › Maven/Gradle › Runner — delegate run to build tool
  • Advanced Settings › Run/Debug — confirm rerun, console limits

In VS Code

  • launch.json ↔ run configurations; preLaunchTask ↔ before-launch
  • Run and Debug view ↔ run widget · See VS Code 17

⚠ Common Mistakes

  • Hard-coding secrets in shared run configs — they end up in Git; use env files ignored by Git
  • Changing a temporary config and losing it — click Save Configuration to keep it
  • Duplicating configs per developer — share one and parameterize with env vars

✓ Tips & Best Practices

  • Run Anything (⌃⌃) runs mvn …, gradle … and configs by name
  • Use Compound configs to start backend + frontend together
  • Add an .env file via Modify options › Environment variables › EnvFile
