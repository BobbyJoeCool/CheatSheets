Sheet 21

Testing & Coverage

Create / Go to Test ⇧⌘T · gutter run · rerun failed · test runner tree · coverage · JUnit 5/6 · Testcontainers

Description

IntelliJ runs JUnit, TestNG and Spock tests from the gutter, a class, a package or a whole module. Go to Test jumps between a class and its test, and creates one if it doesn't exist. The test runner shows a tree of results; Run with Coverage highlights covered lines in the editor. The JUnit set covers JUnit itself.

Notes

  • Green/red gutter icons show last result per test
  • Tests can delegate to Maven/Gradle (Build Tools › Gradle › Run tests using)
  • Testcontainers: gutter shows container status; Docker plugin manages images

Plugin Pick

  • JUnit 5 Mockito Code Generator — generates test skeletons with @Mock / @InjectMocks fields

⚠ Common Mistakes

  • Running tests with IntelliJ while CI uses Gradle — different results from build-only config; delegate to Gradle
  • Reading 100% line coverage as "tested" — check branch coverage and assertions
  • Leaving auto-test on with slow integration tests — CPU stays busy

✓ Tips & Best Practices

  • Rerun failed tests first, then the whole suite
  • Use the runner's Export Test Results for sharing
  • Mark the test root as Test Sources Root so ⇧⌘T finds the right package
