Sheet 27

Git in IntelliJ

Commit ⌘K · Push ⇧⌘K · Update Project ⌘T · changelists · partial commits · branches · shelve vs stash

Description

Git is built in. The Commit tool window (⌘0) shows changes; tick files or individual chunks for a partial commit. Changelists group local changes by task. The branch widget in the toolbar handles checkout, new branches, merges and rebases. Shelve is IntelliJ's own stash; stash is Git's.

Notes

  • Gutter color bars: green added, blue modified, grey deleted
  • Click a gutter bar to see, revert or stage that hunk
  • Commit checks: reformat, inspections, tests before commit

Plugin Pick

  • GitToolBox (zielu) — inline blame, ahead/behind counts, auto-fetch

Explained

Partial commit: open the diff, tick only the lines you want
Amend checkbox in the commit window rewrites the last commit
Shelve keeps patches in .idea/shelf; stash stays in Git
Update Project: merge or rebase, chosen per pull

Where in Settings

  • Version Control › Git — path to git, update method, auto-fetch
  • Version Control › Commit — commit checks, non-modal window
  • Version Control › Changelists — create per task

In VS Code

  • Source Control ⌃⇧G ↔ Commit ⌘0; stage lines in both
  • GitLens ↔ GitToolBox · See VS Code 20

⚠ Common Mistakes

  • Committing unrelated changes together — use changelists or partial commits
  • Shelving and expecting a teammate to see it — shelves are local
  • Force-pushing from the push dialog without checking — use --force-with-lease (enabled by default)

✓ Tips & Best Practices

  • Enable "Reformat code" and "Optimize imports" in commit checks
  • Use the VCS Operations popup (⌃V) as a Git command menu
  • The Git log (⌘9) filters by branch, user, path and date

Quick Summary

  • ⌘K — commit
  • ⇧⌘K — push
  • ⌘T — update
  • changelists — group changes
