Profiler & JVM Tools

built-in profiler · CPU & allocation flame graphs · attach to JVM · memory snapshots · thread dumps · JFR

Description

The built-in profiler samples CPU time and memory allocations using async-profiler and Java Flight Recorder, then shows flame graphs, call trees and method lists. Start any run configuration with the profiler, or attach to a running JVM. Inline hints show CPU time beside your code after a run.

Notes

  • Profiler is a subscription feature in the unified IDE
  • Capture memory snapshots (.hprof) and analyze in the IDE
  • Thread dumps: Debug toolbar camera icon, or jstack
  • Linux/macOS use async-profiler; Windows uses JFR

Plugin Pick

  • VisualVM Launcher — opens VisualVM for the run; the built-in profiler covers most needs

Steps

  1. Run widget ⋮ › Profile with IntelliJ Profiler
  2. Exercise the slow path in the app
  3. Stop or click Capture snapshot
  4. Open Flame Graph — wide bars are where time goes
  5. Switch to Call Tree / Method List; double-click to jump to code
  6. Change view to Memory Allocations to find allocation hotspots

Where to Find It

Profile a run → Run widget ⋮ › Profile
Attach → Profiler tool window › running JVMs
Snapshot files → File › Open (.jfr, .hprof)
Inline CPU hints → editor gutter after profiling

Where in Settings

  • Build… › Java Profiler — configurations (async / JFR), sampling
  • Build… › Java Profiler — show inline hints
  • Appearance & Behavior › Path Variables — snapshot location

In VS Code

  • No built-in profiler; use VisualVM, JDK Mission Control or async-profiler
  • Java extension debugger has no flame graphs · See VS Code 16

⚠ Common Mistakes

  • Profiling a debug run with breakpoints — timings are meaningless
  • Profiling for a few milliseconds — too few samples; run the slow path repeatedly
  • Optimizing the widest frame without reading its children — the cost may be in a callee

✓ Tips & Best Practices

  • Compare two snapshots (before / after) with Compare with
  • Warm up the JVM before capturing
  • Use the Timeline to spot lock contention and GC pauses

Quick Summary

  • Profile — run with profiler
  • Flame Graph — hotspots
  • Attach — running JVM
  • JFR — low-overhead recording
