HTTP Client & Database Tools

.http files · ### requests · http-client.env.json · response handlers · Database tool window · SQL console

Description

The HTTP Client runs requests stored in .http files: commit them next to the code as runnable API docs. Environments swap hosts and tokens; response handlers (JavaScript) save values for later requests. The Database tool window connects to data sources, browses schemas and runs SQL in consoles with completion against the real schema.

Notes

  • Basic database tools are free; HTTP Client and full DB tools need a subscription
  • http-client.private.env.json for secrets (git-ignored)
  • Run a request with the gutter ▶
  • SQL console: ⌘⏎ / Ctrl+Enter executes

api.http

### List products
GET {{host}}/api/products?size=20
Accept: application/json

### Log in and keep the token
POST {{host}}/api/login
Content-Type: application/json

{ "email": "bob@shop.app", "password": "{{password}}" }

> {% client.global.set("token", response.body.token); %}

### Create a product with the saved token
POST {{host}}/api/products
Authorization: Bearer {{token}}
Content-Type: application/json

{ "sku": "MUG-1", "price": 9.50 }

Code Explained

### separates requests; text after it is the name
{{host}} — from the selected environment file
> {% … %} — JS handler; client.global.set stores variables
Responses are saved in .idea/httpRequests/ history

Where in Settings

  • Tools › HTTP Client — proxy, SSL, history size
  • Database › Data Sources (tool window) — drivers, SSH tunnels
  • Editor › Code Style › SQL — SQL formatting

⚠ Common Mistakes

  • Committing tokens in http-client.env.json — use the private env file
  • Running destructive SQL on the wrong data source — color-code prod connections
  • Forgetting to select an environment — {{host}} stays unresolved

✓ Tips & Best Practices

  • Generate requests from the Endpoints window or a controller gutter
  • Convert cURL: paste a curl command into a .http file
  • Set prod data sources to read-only in their properties

Quick Summary

  • .http — runnable requests
  • env.json — per-environment vars
  • > {% %} — response handler
  • Database — consoles & schema
