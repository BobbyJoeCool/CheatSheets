Remote Development & Collaboration

remote development over SSH · Dev Containers · WSL · Code With Me · shared run configurations · settings to commit

Description

Remote Development runs the IDE backend on another machine (SSH server, cloud VM) while a thin client shows the UI locally. Dev Containers open a project inside a container defined by devcontainer.json. WSL projects work natively on Windows. For teamwork, commit shared run configurations, code style and inspection profiles.

Notes

  • Start from File › Remote Development or the Welcome screen
  • The backend needs a few GB of RAM on the remote machine
  • Code With Me's status changes between releases; check before relying on it

.devcontainer/devcontainer.json

{
  "name": "shop",
  "image": "mcr.microsoft.com/devcontainers/java:25",
  "features": {
    "ghcr.io/devcontainers/features/docker-in-docker:2": {}
  },
  "forwardPorts": [8080, 5432],
  "postCreateCommand": "./mvnw -q dependency:go-offline",
  "customizations": {
    "jetbrains": { "backend": "IntelliJ" }
  }
}

Code Explained

Same devcontainer.json format as VS Code
customizations.jetbrains.backend — which IDE backend to install
forwardPorts — reachable from your laptop
postCreateCommand — warm caches once

Where in Settings

  • Build… › Docker — Docker connection for Dev Containers
  • Tools › SSH Configurations — saved hosts
  • Build… › Deployment — SFTP mappings (older workflow)

⚠ Common Mistakes

  • Running a full IDE over SSH X-forwarding — slow; use the remote backend instead
  • Remote backend on a tiny VM — indexing stalls; give it enough RAM and CPU
  • Different JDKs in the container and locally — tests pass in one place only

✓ Tips & Best Practices

  • Keep the dev container image in the repo so onboarding is one click
  • Forward database ports to use the local Database tool window
  • Share settings through files, not screenshots of Settings
