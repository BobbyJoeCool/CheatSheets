Sheet 20

Advanced Debugging

conditional & logging breakpoints · exception breakpoints · Evaluate ⌥F8 · Stream Debugger · HotSwap · remote JVM

Description

Breakpoints can do much more than stop. A condition stops only when an expression is true; a logpoint prints and continues; an exception breakpoint stops where an exception is thrown. HotSwap reloads changed method bodies without restarting, and remote debug attaches to any JVM started with the JDWP agent.

Notes

  • Right-click a breakpoint for condition, log and suspend options
  • Exception breakpoints: ⇧⌘F8 › + › Java Exception Breakpoints
  • Stream Debugger visualizes each step of a stream chain

Remote Debug & Breakpoint Settings

# Start the JVM with the debug agent (Java 9+)
java -agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=*:5005 \
     -jar shop.jar

# Docker: expose the port too
docker run -p 5005:5005 -e JAVA_TOOL_OPTIONS=\
"-agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=*:5005" shop

# Run › Edit Configurations › + › Remote JVM Debug → host:5005

# Breakpoint options (right-click the red dot):
#   Condition:     order.total() > 1000
#   Log:           "order " + order.id()  + uncheck Suspend → logpoint
#   Pass count:    stop on the 50th hit
#   Instance filter / Caller filter

Code Explained

suspend=y waits for the debugger before starting (debug startup code)
address=*:5005 listens on all interfaces — never expose publicly
HotSwap: Build (⌘F9) while paused → "Reload changed classes"
Drop Frame rewinds to the start of the selected method

Where in Settings

  • Build… › Debugger › HotSwap — reload after compilation
  • Build… › Debugger › Async Stack Traces — capture points
  • Build… › Debugger › Data Views — custom renderers

In VS Code

  • Logpoints and conditional breakpoints exist in VS Code too
  • Remote attach via "request": "attach" in launch.json · See VS Code 16–17

⚠ Common Mistakes

  • Leaving suspend=y in a container — the app hangs until a debugger attaches
  • Conditions that call slow methods — evaluated on every hit; the app crawls
  • Expecting HotSwap to apply new fields — restart the app

✓ Tips & Best Practices

  • Use logpoints instead of adding println and rebuilding
  • Exception breakpoint on NullPointerException with "caught" off finds the real origin
  • Mark objects (F11 on a value) to track the same instance across frames

Quick Summary

  • condition — stop selectively
  • logpoint — log without stopping
  • exception breakpoint — stop at throw
  • -agentlib:jdwp — remote debug
