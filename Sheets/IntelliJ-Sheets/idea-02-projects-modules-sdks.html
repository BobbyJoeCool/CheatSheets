Sheet 02

Projects, Modules & SDKs

open vs import · Project Structure ⌘; · modules · JDK download · language level · .idea/

Description

A project is the folder you open; it contains one or more modules (usually one per Maven/Gradle module). Each project has an SDK (a JDK) and a language level. IntelliJ stores its settings in the .idea/ folder; with Maven or Gradle, the build file is the source of truth and IntelliJ imports from it.

Notes

  • Open the folder with pom.xml / build.gradle — IntelliJ detects the build tool
  • File › Project Structure: ⌘; / Ctrl+Alt+Shift+S
  • Download a JDK from the SDK dropdown (Temurin, Corretto, GraalVM…)
  • Language level can be lower than the JDK

Where in Settings

  • Project Structure › Project — SDK and language level
  • Build, Execution, Deployment › Build Tools › Maven / Gradle — import options
  • File › New Projects Setup › Settings for New Projects — defaults (IDE-wide)

In VS Code

  • VS Code has no project model; the Java extension reads Maven/Gradle
  • JDK: java.jdt.ls.java.home / java.configuration.runtimes · See VS Code 24

⚠ Common Mistakes

  • Committing workspace.xml — causes merge conflicts every time someone moves a window
  • Editing modules in Project Structure on a Maven project — the next reload overwrites it
  • JDK 25 project with language level 17 — new syntax is flagged red even though the JDK supports it

✓ Tips & Best Practices

  • Use the JetBrains .gitignore template from gitignore.io
  • Mark folders via right-click › Mark Directory as › Sources Root
  • Use one JDK name across the team (e.g. temurin-25)

Quick Summary

  • project — the opened folder
  • module — unit of sources/deps
  • SDK — JDK + language level
  • .idea/ — commit shared parts only
