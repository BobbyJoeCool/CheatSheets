Sheet 24

Gradle in IntelliJ

Gradle tool window · sync · build & run using Gradle vs IntelliJ · tasks · Gradle JVM · Kotlin DSL

Description

IntelliJ syncs its model from build.gradle(.kts). By default it builds and runs using Gradle, so results match the command line; switching to IntelliJ's own builder is faster for some projects. The Gradle tool window lists tasks, dependencies and source sets. Kotlin DSL gets full completion and navigation.

Notes

  • Sync: ⇧⌘I / Ctrl+Shift+O or the floating icon
  • Gradle JVM is separate from the project SDK
  • 2026.2 adds early Gradle 10 support and migration help

build.gradle.kts Helpers

plugins {
    java
    id("org.springframework.boot") version "4.1.0"   // ⌃Space for versions
}
dependencies {
    // ⌘N › Add dependency (searches Maven Central)
    implementation("com.fasterxml.jackson.core:jackson-databind")
    testImplementation(platform("org.junit:junit-bom:5.13.4"))
    testImplementation("org.junit.jupiter:junit-jupiter")
}
tasks.test { useJUnitPlatform() }    // ⌘B on useJUnitPlatform → source
// Gradle tool window › Tasks › verification › test (double-click)

Code Explained

Dependency completion arrived in 2026.2 for Gradle scripts
⌘B navigates into Gradle API and plugin sources
Double-click a task to run; it becomes a run config
Version catalogs (libs.versions.toml) get completion and navigation

⚠ Common Mistakes

  • Gradle JVM older than the build requires — sync fails with unsupported class version
  • Switching build to IntelliJ without matching annotation processors — compile errors only in the IDE
  • Not committing the wrapper — IDE downloads a different Gradle than CI

✓ Tips & Best Practices

  • Enable Gradle configuration cache for faster syncs
  • Use Analyze Dependencies in the tool window for conflicts
  • Keep gradle.properties org.gradle.jvmargs sized for big projects

Quick Summary

  • ⇧⌘I — sync
  • Gradle JVM — runs Gradle itself
  • build using Gradle — CLI parity
  • Kotlin DSL — full IDE support
