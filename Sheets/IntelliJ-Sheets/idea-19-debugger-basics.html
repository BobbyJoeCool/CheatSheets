Sheet 19

Debugger Basics

breakpoints ⌘F8 · Step Over F8 · Into F7 · Out ⇧F8 · Run to Cursor ⌥F9 · Variables · Watches

Description

Start any run configuration with Debug (⌃D) and execution stops at breakpoints. Step through line by line, inspect Variables, add Watches, and move through Frames (the call stack). Inline values show each variable's value right in the editor.

Notes

  • Click the gutter to toggle a line breakpoint
  • Smart Step Into (⇧F7) picks which call on a line to enter
  • Debug tool window: ⌘5 / Alt+5
  • New in 2026.2: logpoints from the gutter menu

⚠ Common Mistakes

  • Method breakpoints on hot code — they slow the JVM dramatically; use line breakpoints
  • Stepping into JDK internals — enable stepping filters or use Smart Step Into
  • Evaluating expressions with side effects (list.remove(0)) — they really run

✓ Tips & Best Practices

  • Use Run to Cursor instead of temporary breakpoints
  • Pin values in the editor to keep them visible across steps
  • Right-click a frame › Drop Frame to rerun a method (sheet 20)
