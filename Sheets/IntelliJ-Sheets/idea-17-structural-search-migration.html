Sheet 17

Structural Search & Migrations

Structural Search / Replace · templates · $var$ · Migrate (javax → jakarta) · language-level upgrades

Description

Structural Search and Replace (SSR) matches code by shape, not text: $list$.size() == 0 finds every such comparison whatever the variable names. Migrations apply library renames in bulk, including javax → jakarta (Jakarta EE 02). Inspections with Fix all handle Java language-level upgrades.

Notes

  • SSR templates can become custom inspections
  • $name$ variables can have type and count filters
  • Refactor › Migrate Packages and Classes lists built-in maps

Structural Search & Replace Templates

// Search template                    Replace template
$list$.size() == 0               →    $list$.isEmpty()
new $T$($args$).toString()       →    String.valueOf(new $T$($args$))
if ($c$) { return true; } else { return false; }  →  return $c$;
Collections.unmodifiableList(new ArrayList<>($x$))  →  List.copyOf($x$)

// Filter on $list$: type = java.util.List  (avoids false matches)

// Migrate: Refactor › Migrate Packages and Classes ›
//   "Java EE to Jakarta EE"   javax.persistence.* → jakarta.persistence.*
//   "JUnit 4 → 5" also exists via inspections (Fix all)

Code Explained

Variables match any expression unless filtered
Add a type filter (java.util.List) to avoid lookalikes
Save template and enable it as an inspection with a fix
Migration preview lists every file before applying

⚠ Common Mistakes

  • SSR without type filters — matches unrelated code with the same shape
  • Running the javax → jakarta migration on Java SE packages — keep javax.sql, javax.crypto
  • Applying "Fix all" across the project in one commit with other changes — impossible to review

✓ Tips & Best Practices

  • Start SSR from an existing template (Templates list) and edit
  • Commit each migration step separately
  • Pair with OpenRewrite for build-file changes IntelliJ doesn't touch
