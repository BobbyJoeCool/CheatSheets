Maven in IntelliJ

Maven tool window · reload project · goals & lifecycle · profiles · dependency analyzer · offline mode · wrapper

Description

IntelliJ imports the project model from pom.xml. After editing the pom, reload (⇧⌘I) to sync. The Maven tool window runs lifecycle phases and plugin goals, toggles profiles, and the Dependency Analyzer shows conflicts. The Maven set covers Maven itself.

Notes

  • The floating 🐘/M icon appears when the pom changes — click to reload
  • Uses the Maven wrapper (mvnw) if present
  • Double-click a goal to run; right-click to create a run config

pom.xml Editing Helpers

<dependencies>
  <!-- ⌘N in <dependencies> › Add Maven Artifact Dependency -->
  <dependency>
    <groupId>org.junit.jupiter</groupId>
    <artifactId>junit-jupiter</artifactId>
    <!-- ⌃Space in <version> lists available versions -->
    <version>5.13.4</version>
    <scope>test</scope>
  </dependency>
</dependencies>
<!-- ⌘B on a dependency opens its pom; ⌥⏎ › update version -->
<!-- Right-click pom › Maven › Show Dependencies (diagram) -->

Code Explained

⌘N inside the pom searches Maven Central
Version completion and update intentions keep versions current
Show Dependencies draws the graph; red lines are conflicts
Run Anything (⌃⌃) + mvn clean verify runs any command

Where in Settings

⚠ Common Mistakes

  • Editing Project Structure modules instead of the pom — overwritten on reload
  • Forgetting to reload after pom edits — red imports that disappear after sync
  • Profiles ticked in IntelliJ but not in CI — builds differ

✓ Tips & Best Practices

  • Use the Dependency Analyzer's Show Conflicts before bumping versions
  • Delegate build/run to Maven if the build has custom plugins
  • Keep mvnw committed so IDE and CI use the same Maven
