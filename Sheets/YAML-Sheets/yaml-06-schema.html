Schemas & Type Resolution

A YAML schema defines how untagged scalars are resolved to types. The Failsafe schema treats everything as a string. The JSON schema recognizes true/false/null/numbers exactly as JSON does. The Core schema (YAML 1.2 default) extends JSON with additional true/false/null forms and number formats. The YAML 1.1 schema (still used by many parsers) additionally recognizes yes/no/on/off as booleans — the source of many cross-version bugs. Explicit tags (!!str, !mytype) override schema resolution entirely.

Schema & Directive Rules

  • %YAML 1.2 directive declares the YAML version; must appear before ---
  • %TAG ! tag:yaml.org,2002: — shorthand for built-in tag prefix
  • !! is shorthand for tag:yaml.org,2002: — so !!str = full URI tag
  • Custom tags use single !: !mytag value
  • Tags apply to any node: scalars, sequences, and mappings
  • Parsers may not support all tags — check your library's docs
  • Multi-document: multiple --- separated docs in one file

Directives, Tags & Multi-Document

%YAML 1.2
%TAG ! tag:example.com,2024:
---
# ── Explicit built-in tags ───────────────────────────────────
port:     !!int "8080"          # force integer
version:  !!str 2.0             # force string "2.0"
enabled:  !!bool "yes"          # force boolean true
data:     !!null ""             # force null

# ── Custom application tag ───────────────────────────────────
connection: !db-config
  host: localhost
  driver: postgres

# ── Binary data tag ──────────────────────────────────────────
thumbnail: !!binary |
  R0lGODlhDAAMAIQAAP//9/X
  17unp5WZmZgAAAOfn515eXv
  Pz7Y6OjuDg4J+fn5OTk6enp
  56SkpGRkZCQkAAAACH5BAEAA
  BQALAAAAAAMAAwAAAVWoCAA

# ── Multi-document file ──────────────────────────────────────
---
# Document 1: development config
env: development
debug: true
db_url: sqlite:///dev.db

---
# Document 2: production config
env: production
debug: false
db_url: postgres://prod-db:5432/app

Notes

%YAML 1.2 — directive tells the parser which schema to use; affects boolean/null/int resolution
%TAG ! — defines a shorthand prefix for custom tag URIs (! is the default handle)
!!int "8080" — tag on a quoted string; forces it to integer 8080 despite the quotes
!db-config — application-defined tag; Python's PyYAML can map this to a class constructor
!!binary | — base64-encoded binary data in a literal block; parsers decode to bytes
--- between documents — each block is a separate parsed document; use load_all() in most parsers
The Norway problem: country code NO was parsed as boolean false in YAML 1.1 — always quote country codes

Common Mistakes

  • Using NO, yes, on, off as strings in YAML 1.1 parsers — they silently become booleans
  • Assuming %YAML 1.2 directive changes behavior in all parsers — PyYAML ignores it and uses 1.1 rules
  • Forgetting load_all() for multi-document files — load() only returns the first document
  • Using 0777 for octal — YAML 1.2 treats this as integer 777; use 0o777 instead

Tips

  • Use ruamel.yaml instead of PyYAML when you need true YAML 1.2 compliance in Python
  • Quote all ISO country codes, version numbers, and date-like strings to prevent type coercion surprises
  • Multi-document YAML is useful for Kubernetes manifests — multiple resources in a single kubectl apply -f file

Summary

  • %YAML 1.2 — version directive before ---
  • !! — shorthand for built-in YAML tag namespace
  • !mytag — custom application-defined tag
  • YAML 1.1 vs 1.2 — yes/no/on/off behavior differs significantly
  • --- separates multiple documents in one file
