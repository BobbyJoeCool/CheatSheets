What is YAML?

YAML (YAML Ain't Markup Language) is a human-readable data serialization format commonly used for configuration files, CI/CD pipelines, Infrastructure-as-Code, and data exchange between systems. YAML files use the extensions .yml or .yaml and are parsed by a YAML processor into native data structures (maps, lists, scalars). Unlike JSON, YAML is whitespace-sensitive — indentation defines structure, and tabs are never allowed for indentation.

Core Rules

  • Indentation uses spaces only — tabs cause parse errors
  • Consistent indent depth required within a block (2 or 4 spaces typical)
  • # starts a comment — extends to end of line
  • Strings do not require quotes unless they contain special characters
  • --- marks the start of a document (optional for single-doc files)
  • ... marks the end of a document (optional)
  • YAML is a superset of JSON — all valid JSON is valid YAML
  • Keys and values are separated by : (colon + space)

Anatomy of a YAML File

%YAML 1.2                    # optional version directive
---                          # document start marker
# Application configuration
app:
  name: my-service           # string value (unquoted)
  version: 2.1.0             # string (looks like semver)
  port: 8080                 # integer
  debug: false               # boolean

server:
  host: "localhost"          # quoted string
  timeout: 30                # integer (seconds)

features:                    # mapping with list value
  - authentication
  - rate-limiting
  - logging

database:
  url: postgres://db:5432    # colon in value — no quotes needed here
  pool_size: 10

# Inline (flow) style — equivalent to block above
tags: {env: prod, region: us-east}
ports: [80, 443, 8080]
...                          # optional document end marker

Notes

%YAML 1.2 — optional directive; most parsers default to 1.1 or 1.2
--- — required when using directives or multiple documents; otherwise optional
app: — a mapping key; child keys indented beneath it form a nested map
false — unquoted booleans are auto-detected; quote to force string: "false"
features: — a mapping whose value is a sequence (list of strings)
{ } / [ ] — flow style keeps items on one line; valid anywhere block style is
Colons inside values don't need quoting unless they appear at the start or are followed by a space

Common Mistakes

  • Using Tab for indentation — YAML forbids tabs entirely; always use spaces
  • Forgetting the space after : — key:value is a string, not a mapping
  • Inconsistent indentation depth within a block causes parse errors
  • Writing : #comment directly — always leave a space: value # comment

Tips

  • Use 2-space indentation — it's the community standard and most tools default to it
  • Configure your editor to show whitespace characters to catch tab vs space issues early
  • Run yamllint on files before committing — catches indentation and syntax errors instantly
  • Use --- at the top of every file as a habit — it makes multi-doc scenarios trivial to add later

Summary

  • spaces only — tabs are illegal for indentation
  • : — colon + space separates every key from its value
  • # — comments extend to end of line
  • --- / ... — document start and end markers
  • Block style uses indentation; flow style uses {} and []
  • YAML is a superset of JSON
