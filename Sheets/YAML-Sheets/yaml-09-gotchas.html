Plain Scalars Guess Their Type

An unquoted (plain) scalar is typed by pattern matching: true becomes a boolean, 42 an integer, ~ null. The patterns differ between YAML 1.1 (PyYAML, Ruby’s Psych, many older tools) and YAML 1.2 (js-yaml 4, the yaml npm package, ruamel.yaml), so the same file can load differently in two tools. Country codes, version numbers, port mappings and zip codes are the usual victims. The fix is almost always the same: quote anything that must stay a string.

Quick Rules

  • Quote values that look like booleans, numbers, dates or nulls but are really text
  • Quote strings that start with @, backtick, *, &, !, |, >, %, {, [ or #
  • Quote strings containing : or # — they start a mapping or a comment
  • A colon *without* a following space is fine: url: http://x.io:8080
  • Single quotes are literal ('' escapes a quote); double quotes allow \n, \t, \u00e9

Notes

Norway problem — NO is a 1.1 boolean, so a list of country codes turns Norway into false
yes / no / on / off — 1.1 booleans in any case (Yes, OFF); plain strings in 1.2
010 — 1.1 reads a leading zero as octal; 1.2 needs the 0o prefix
22:22 — 1.1 reads colon-separated digits as base-60; Docker Compose docs tell you to quote ports
3.10 — a float in every version; GitHub Actions python-version: 3.10 installs 3.1
on: as a key — PyYAML loads the GitHub Actions trigger key as True; GitHub’s parser doesn’t
Empty value and ~ — both are null; use "" for an empty string

Same Text, Different Types

#                         YAML 1.1 (PyYAML)     YAML 1.2 core
country: NO             # false                 "NO"
answer:  yes            # true                  "yes"
switch:  off            # false                 "off"
octal:   010            # 8                     10
octal2:  0o10           # "0o10"                8
port:    22:22          # 1342  (base 60!)      "22:22"
version: 3.10           # 3.1                   3.1      ← both!
sci:     1e3            # "1e3"                 1000.0
date:    2026-10-23     # datetime.date         "2026-10-23"
zip:     02134          # 1116 (octal)          2134
empty:                  # None                  null
tilde:   ~              # None                  null

# Safe in every parser:
country: "NO"
version: "3.10"
port:    "22:22"
zip:     "02134"

Checking What a Parser Sees

import yaml                        # PyYAML = YAML 1.1 rules
yaml.safe_load("on: push")         # {True: 'push'}   ← key is a bool!
yaml.safe_load("v: 3.10")          # {'v': 3.1}
yaml.safe_load('v: "3.10"')        # {'v': '3.10'}

Common Mistakes

  • Trusting a linter-clean file — country: NO is valid YAML; it is just a boolean in 1.1 parsers
  • Writing tool versions unquoted (node: 18.10, python-version: 3.10) — they become floats and lose the trailing zero
  • Leaving Compose port mappings unquoted — values under 60 like 22:22 are parsed as base-60 integers by 1.1 parsers
  • Using "" and empty values interchangeably — an empty value is null, not an empty string

Tips

  • Enable yamllint’s truthy rule — it flags yes, on, NO and friends
  • Round-trip a file through your real parser (python -c "import yaml,sys; print(yaml.safe_load(sys.stdin))" < f.yml) to see the types it gets
  • Prefer YAML 1.2 libraries (ruamel.yaml, yaml npm) for new code
  • When in doubt, quote — quoting a string never changes its meaning; not quoting sometimes does

Summary

  • NO / yes / on — booleans in YAML 1.1; quote country codes and words
  • 3.10 — always a float; quote versions
  • 22:22 / 010 — base-60 and octal in 1.1; quote ports and zip codes
  • ~ / empty — null; "" for empty string
