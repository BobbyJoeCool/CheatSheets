yq — Query & Edit YAML

yq eval · select() · = · |= · del() · -i · -o=json · ea · * merge · strenv()

jq for YAML

yq (mikefarah/yq, v4) reads, queries and edits YAML from the command line with jq-like expressions. It keeps comments and key order when editing in place, handles multi-document files, and converts between YAML, JSON, XML, TOML, CSV and properties. It is the usual way to bump an image tag, read a value in a CI script, or merge environment-specific config files.

Before You Start

  • Install: brew install yq, snap install yq, or the single binary from GitHub releases
  • Check yq --version — a different Python package also called yq (kislyuk) wraps jq and uses jq syntax
  • yq 'expr' file — print result; add -i to write back to the file
  • Always single-quote the expression so the shell leaves $, | and * alone
  • Output is YAML by default; -o=json for JSON, -r is on by default (no quotes around strings)

Notes

.a.b — path; .[0] index; .[] every item; | pipes the result to the next step
select(cond) — keep only matching nodes, like WHERE
= — set to a value; |= — update using the old value (. is the current value)
strenv(TAG) — env var as a string; env(TAG) parses it as YAML (so 1.10 → float)
del(path) — remove a key or array item
.. — recursive descent; select(key == "image") finds that key at any depth
ea (eval-all) — load all files at once so they can be combined; default e processes files one by one
* — deep merge maps; arrays from the right side replace the left (*+ appends)

Everyday Commands

# ── Read ────────────────────────────────────────────────────────
yq '.spec.replicas' deploy.yaml                 # 3
yq '.services | keys' compose.yaml              # - api  - db
yq '.spec.template.spec.containers[0].image' deploy.yaml
yq '.items[] | select(.kind == "Service") | .metadata.name' all.yaml
yq 'select(document_index == 1)' multi.yaml     # 2nd document only

# ── Edit in place (-i) ─────────────────────────────────────────
yq -i '.spec.replicas = 5' deploy.yaml
yq -i '.image.tag = strenv(TAG)' values.yaml    # env var, kept as string
yq -i '.version |= . + 1' meta.yaml             # update relative to old value
yq -i '.tags += ["prod"]' meta.yaml             # append to array
yq -i 'del(.metadata.annotations)' deploy.yaml
yq -i '(.. | select(key == "image")) |= sub(":.*", ":1.4.2")' k8s.yaml

# ── Convert ────────────────────────────────────────────────────
yq -o=json '.' config.yaml > config.json        # YAML → JSON
yq -p=json -o=yaml '.' data.json                # JSON → YAML

# ── Merge files (later wins) ───────────────────────────────────
yq ea '. as $f ireduce ({}; . * $f)' base.yaml prod.yaml

Common Mistakes

  • Double-quoting the expression — the shell expands $f, * and backticks before yq sees them
  • Using env(VERSION) for versions — 1.10 becomes the number 1.1; use strenv()
  • Running a jq-syntax command against mikefarah/yq (or the reverse) — check which yq is on the PATH
  • Merging with * and expecting lists to combine — they are replaced unless you use *+

Tips

  • Use yq -e '.spec.replicas > 1' deploy.yaml as a CI assertion — non-zero exit when false
  • Preview edits without -i, then rerun with -i once the output looks right
  • yq -P '.' file.json pretty-prints any supported input as idiomatic YAML
  • Pair with kubectl get -o yaml | yq '...' to slice live cluster objects

Summary

  • yq '.a.b' f.yaml — read a value
  • yq -i '.a = "x"' f.yaml — edit in place, comments kept
  • select() / del() / |= — filter, delete, update
  • -o=json / -p=json — convert formats
  • yq ea '... * ...' — merge files; later wins
