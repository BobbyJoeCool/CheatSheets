Sheet 03

Collections — Sequences & Mappings

sequences · mappings · nesting · block style · flow style

The Two Collection Types

YAML has two collection types: sequences (ordered lists) and mappings (key-value dictionaries). Both can be written in block style (multi-line, indented) or flow style (inline, using [] and {}). Collections nest freely — a mapping value can be a sequence, a sequence item can be a mapping, and any depth of nesting is valid. The indentation level of a child must be greater than its parent's key.

Collection Rules

  • Sequence items start with - (dash + space)
  • Mapping entries use key: value (colon + space)
  • Flow sequences: [a, b, c] — comma-separated in brackets
  • Flow mappings: {key: val, key2: val2}
  • Keys must be unique within the same mapping level
  • Keys can be any scalar (string, int, bool) — strings most common
  • Complex keys (multi-line) use the ? indicator
  • Empty sequence: [] · Empty mapping: {}

Nesting Collections

# ── Simple sequence ──────────────────────────────────────────
fruits:
  - apple
  - banana
  - cherry

# ── Flow sequence (equivalent) ───────────────────────────────
fruits: [apple, banana, cherry]

# ── Mapping with nested mapping ──────────────────────────────
server:
  host: localhost
  port: 8080
  tls:
    enabled: true
    cert: /etc/ssl/cert.pem

# ── Sequence of mappings (list of objects) ───────────────────
users:
  - name: Alice
    role: admin
    active: true
  - name: Bob
    role: viewer
    active: false

# ── Mixed nesting: map → list → map ──────────────────────────
environments:
  production:
    servers:
      - host: prod-1.example.com
        weight: 100
      - host: prod-2.example.com
        weight: 100
  staging:
    servers:
      - host: stage.example.com
        weight: 100

# ── Flow style for compact data ──────────────────────────────
matrix: [[1, 0], [0, 1]]
rgb: {r: 255, g: 128, b: 0}

Notes

- item — the dash is part of the indentation; the value starts after the space
server: then indented children — the mapping's value is itself a mapping
users: + - name: — sequence of mappings; each - begins a new object
The - indicator counts as 2 spaces of indentation for its children
environments: production: servers: — three levels of nested mappings
[[1, 0], [0, 1]] — flow sequences can nest; useful for matrices or coordinate pairs
Block and flow styles can be mixed freely — a block mapping can have a flow sequence as a value

Common Mistakes

  • Not indenting map children — siblings at the same level as the parent key break the structure
  • Forgetting the space after - in sequences — -item is a string, not a list item
  • Duplicate keys in the same mapping — most parsers silently use the last value; behavior is undefined
  • Mixing indentation depths within the same block — 2-space parent cannot have 3-space children

Tips

  • Use block style for config files; reserve flow style for short, simple values that read naturally inline
  • Sequence-of-mappings is the most common YAML pattern — master - key: value nesting first
  • Paste YAML into an online validator (yaml-online-parser.appspot.com) to visualize the parsed tree

Summary

  • - item — block sequence item
  • [a, b] — flow sequence
  • key: value — mapping entry
  • {k: v} — flow mapping
  • Collections nest to any depth; indentation defines the parent-child relationship
