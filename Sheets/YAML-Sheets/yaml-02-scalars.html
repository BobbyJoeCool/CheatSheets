Scalar Types

A scalar is any single-value node in YAML — a string, number, boolean, or null. YAML performs implicit type detection: the parser infers the type from the value's form unless you override it with an explicit tag. This convenience is also a source of bugs — values like yes, on, 1.0, and 2024-01-01 are automatically coerced to boolean, float, and timestamp respectively. Use explicit tags (!!str, !!int) or quotes to force a specific type.

Type Detection Rules

  • Quoted values ('…' or "…") are always strings
  • true, false → boolean (YAML 1.2); also yes/no, on/off in YAML 1.1
  • null, ~, or empty value → null type
  • Bare integers and floats are numeric unless quoted
  • YYYY-MM-DD format → timestamp (date)
  • 0x1F → hex integer; 0o17 → octal
  • .inf, -.inf, .nan → special float values

Scalar Examples & Type Coercion

# ── Strings ──────────────────────────────────────────────────
plain: hello world              # string (no quotes needed)
single: 'it''s alive'           # single quotes: '' escapes a quote
double: "tab:\there\nnewline"   # double quotes: escape sequences active
forced_str: !!str 1984          # force "1984" not integer 1984

# ── Numbers ──────────────────────────────────────────────────
count: 100
hex_val: 0xFF                   # 255
octal_val: 0o17                 # 15
pi: 3.14159
scientific: 6.022e23
infinity: .inf
not_a_number: .nan

# ── Booleans (YAML 1.2 — only true/false) ────────────────────
enabled: true
disabled: false
as_string: "true"               # quoted → stays a string

# ── Null ─────────────────────────────────────────────────────
nothing: null
tilde: ~
implicit:                       # empty value → null

# ── Timestamps ───────────────────────────────────────────────
date: 2024-06-01
datetime: 2024-06-01T14:30:00Z
datetime_tz: 2024-06-01T14:30:00+05:30
date_str: !!str 2024-06-01      # force string, not date

Notes

'' — single-quote escape in single-quoted strings (double the quote)
\n \t \uXXXX — escape sequences only work inside double-quoted strings
!!str 1984 — explicit tag overrides auto-detection; value becomes the string "1984"
0xFF / 0o17 — hex and octal integer literals; not all parsers support these
.inf / .nan — case-insensitive; also .Inf, .NaN, .INF
true/false only — YAML 1.2 dropped yes/no/on/off as booleans; YAML 1.1 parsers still accept them
Empty value after : is null — not an empty string; use "" for an empty string

Common Mistakes

  • yes/no become booleans in YAML 1.1 parsers — quote them if you mean the string "yes"
  • Version strings like 1.10 parse as float 1.1 — always quote version numbers
  • Empty value is null, not "" — use explicit "" when an empty string is required
  • Timestamps are auto-parsed — quote ISO dates when you need strings (e.g. filenames)

Tips

  • When in doubt, quote it — quoted scalars are always strings regardless of content
  • Use !!str tags at the key level for self-documenting intent when type is non-obvious
  • Know your parser's YAML version — PyYAML defaults to 1.1; ruamel.yaml and most modern parsers support 1.2
  • Single quotes are safer than double quotes when values contain backslashes (no escape processing)

Summary

  • implicit typing — parser infers type from value shape
  • !!str / !!int — explicit tags override inference
  • true/false — only booleans in YAML 1.2
  • null / ~ / empty — all represent null
  • YYYY-MM-DD — auto-parsed as timestamp; quote to prevent
