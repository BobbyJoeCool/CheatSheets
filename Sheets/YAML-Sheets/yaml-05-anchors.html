Sheet 05

Anchors, Aliases & Merges

& anchor · * alias · << merge key · DRY config · override · multiple merges

Reuse Without Repetition

YAML's anchor (&name) and alias (*name) mechanism lets you define a value once and reference it multiple times, keeping configuration DRY. An anchor marks a node; an alias inserts a copy of that node elsewhere in the document. The merge key (<<) extends this by merging a mapping's contents into another mapping, with the ability to override specific keys after the merge. Anchors and aliases are resolved at parse time — the consumer sees fully expanded data.

Anchor & Alias Rules

  • &name — defines an anchor; name can contain letters, digits, hyphens
  • *name — inserts a copy (alias) of the anchored node
  • Anchors must appear before their aliases in the document
  • Aliases produce a deep copy — modifying one does not affect the other (in most parsers)
  • <<: *anchor — merge key; merges anchored mapping into current mapping
  • Keys defined after a merge override the merged values
  • Multiple merges: <<: [*a, *b] — first list item has highest priority
  • Anchors work on scalars, sequences, and mappings

Anchors, Aliases & Merge Keys

# ── Define a shared anchor ───────────────────────────────────
defaults: &defaults
  retries: 3
  timeout: 30
  log_level: info

# ── Simple alias — exact copy ─────────────────────────────────
worker_a:
  <<: *defaults          # merges retries, timeout, log_level
  queue: high-priority   # adds a new key

worker_b:
  <<: *defaults
  queue: low-priority
  timeout: 60            # overrides the merged timeout: 30

# ── Multiple merges ──────────────────────────────────────────
base: &base
  image: ubuntu:22.04
  restart: unless-stopped

monitoring: &monitoring
  metrics: true
  health_check: /healthz

app:
  <<: [*base, *monitoring]   # both merged; base keys win on conflict
  name: my-app
  port: 8080

# ── Scalar anchor ────────────────────────────────────────────
domain: &domain example.com
api_url: "https://*domain/api"  # NOTE: aliases in strings don't expand
                                 # use anchors only at node level

# ── Sequence alias ───────────────────────────────────────────
common_ports: &ports [80, 443, 8080]
service_a:
  ports: *ports
service_b:
  ports: *ports

Notes

&defaults — anchor name follows immediately; the mapping below it is the anchored node
<<: *defaults — merge key; all keys from the anchor are inserted into the current map
timeout: 60 after merge — explicit keys after << override merged values
[*base, *monitoring] — multiple merge; first anchor's keys take priority over later anchors on conflict
Aliases in string values ("https://*domain") do NOT expand — *name only works at the node level
*ports as a value inserts the full sequence — each service gets its own copy of the list
The merge key << is only valid in mappings — it has no effect in sequences

Common Mistakes

  • Placing an alias before its anchor — anchors must be defined earlier in the document
  • Expecting "https://*domain" string interpolation — aliases don't expand inside quoted strings
  • Overriding a key before the merge — put << first, then override keys below it
  • Multiple << keys in the same map — only one merge key is valid; use the list form [*a, *b]

Tips

  • Use a top-level x- prefixed key (e.g. x-defaults:) for anchors you don't want parsed as real data — Docker Compose ignores x-* keys
  • Define all anchors near the top of the file so they're easy to find and maintain
  • Merge keys work in Kubernetes Helm values — useful for environment-specific overrides

Summary

  • &name — define a reusable anchor
  • *name — insert alias (copy) of anchor
  • <<: *name — merge anchor mapping into current map
  • Keys after merge override merged values
  • [*a, *b] — merge multiple anchors; first wins on conflict
