Sheet 12

Editor Schemas & CI Linting

# yaml-language-server: $schema · SchemaStore · yaml.schemas · .yamllint · pre-commit · check-jsonschema

Catch Mistakes Before They Run

Two layers of checking stop most broken YAML. In the editor, the Red Hat YAML extension (built on yaml-language-server) validates files against a JSON Schema — giving autocomplete, hover docs and red squiggles for wrong keys. Schemas come from SchemaStore automatically for common files, or from a comment or setting you add. In CI, yamllint checks syntax and style, and schema validators such as check-jsonschema, actionlint and kubeconform check meaning.

Editor Setup (VS Code)

  • Install YAML by Red Hat — works for .yml and .yaml
  • SchemaStore matching is on by default (yaml.schemaStore.enable): workflows, Compose, Dependabot, etc.
  • A modeline comment in the file beats every other schema setting
  • Kubernetes: map the built-in kubernetes schema to your manifest globs
  • CloudFormation / custom tags: list them in yaml.customTags or every !Ref is an error

Notes

# yaml-language-server: $schema= — per-file schema; also accepts a relative path
"yaml.schemas" — schema URL or path → glob(s) of files it applies to
"kubernetes" — special value for the extension’s built-in Kubernetes schema
!Ref scalar — declares a custom tag and the node kind it wraps
extends: default — start from yamllint’s default rules; relaxed is looser
truthy — flags yes, on, NO; check-keys: false skips mapping keys

Pick a Schema Per File

# yaml-language-server: $schema=https://json.schemastore.org/github-workflow.json
name: CI
on: [push]

.vscode/settings.json

{
  "yaml.schemas": {
    "kubernetes": "k8s/**/*.yaml",
    "./schemas/app-config.schema.json": "config/*.yaml",
    "https://json.schemastore.org/github-action.json": "action.yml"
  },
  "yaml.customTags": ["!Ref scalar", "!Sub scalar", "!GetAtt scalar", "!If sequence"]
}

.yamllint

extends: default
rules:
  line-length: { max: 120, level: warning }
  truthy:
    allowed-values: ["true", "false"]
    check-keys: false          # allow `on:` in GitHub workflows
  indentation: { spaces: 2, indent-sequences: consistent }
  document-start: disable
ignore: |
  charts/*/templates/          # Helm templates aren't plain YAML

.pre-commit-config.yaml

repos:
  - repo: https://github.com/adrienverge/yamllint
    rev: v1.35.1
    hooks: [{ id: yamllint, args: [--strict] }]
  - repo: https://github.com/python-jsonschema/check-jsonschema
    rev: 0.29.4
    hooks:
      - id: check-github-workflows
      - id: check-jsonschema
        files: ^config/.*\.yaml$
        args: [--schemafile, schemas/app-config.schema.json]

Common Mistakes

  • Setting a yaml.schemas glob for a file that also has a modeline — the modeline wins, so the setting looks ignored
  • Running yamllint on Helm templates — {{ }} isn’t YAML; ignore templates/ and lint helm template output instead
  • Disabling truthy entirely to silence on: — use check-keys: false so yes/no values are still caught
  • Copying pre-commit rev: values once and never updating — run pre-commit autoupdate

Tips

  • Write a JSON Schema for your own config files — the editor then autocompletes every key for the whole team
  • yamllint -f github prints errors as inline annotations on pull requests
  • Run kubeconform with -strict to reject unknown fields that kubectl apply would silently drop
  • Commit .vscode/settings.json schema mappings so everyone gets the same validation

Summary

  • # yaml-language-server: $schema= — schema for one file
  • yaml.schemas — schema → glob mapping in settings
  • .yamllint — style and syntax rules for CI
  • check-jsonschema / kubeconform / actionlint — schema checks in CI
  • pre-commit — run all of them before every commit
