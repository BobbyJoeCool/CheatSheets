Five Ways to Write a String

YAML provides five string styles. Plain scalars need no quotes and are the most readable. Single-quoted strings treat all characters literally (no escape sequences) except '' for a literal quote. Double-quoted strings support backslash escapes (\n, \t, \uXXXX). Literal block (|) preserves newlines exactly — ideal for scripts or file contents. Folded block (>) converts single newlines to spaces and double newlines to paragraph breaks — ideal for long prose.

Escape Sequences (double-quoted only)

  • \n — newline
  • \t — tab
  • \\ — literal backslash
  • \" — literal double quote
  • \r — carriage return
  • \0 — null character
  • \uXXXX — Unicode code point (4 hex digits)
  • \UXXXXXXXX — Unicode code point (8 hex digits)
  • \xXX — 8-bit Unicode (2 hex digits)

All String Styles Compared

# ── Plain scalar ─────────────────────────────────────────────
greeting: Hello World           # → "Hello World"
version: "1.0"                  # quoted to prevent float parse

# ── Single-quoted ─────────────────────────────────────────────
path: 'C:\Users\admin\file.txt' # backslash literal, no escaping
quote: 'she said ''hello'''     # '' inside single quotes = literal '

# ── Double-quoted ─────────────────────────────────────────────
newlines: "first\nsecond\nthird"  # → first⏎second⏎third
unicode: "\u00A9 2024"            # → © 2024
tab: "col1\tcol2"                 # → col1⇥col2

# ── Literal block (|) — newlines preserved ───────────────────
script: |
  #!/bin/bash
  echo "Starting..."
  cd /app && npm start
  # Each line kept exactly, including the newline at end

# ── Literal strip (|-) — trailing newlines removed ───────────
inline_script: |-
  echo "no trailing newline"
  exit 0

# ── Folded block (>) — single newlines become spaces ─────────
description: >
  This is a long description
  that spans multiple lines but
  will be joined into one paragraph.

  A blank line creates a new paragraph.

# ── Folded strip (>-) — fold + no trailing newline ───────────
summary: >-
  One long line with
  no trailing newline at end

Notes

'C:\Users\...' — single quotes are the safest choice for Windows paths; no escape processing
'' — the only escape in single-quoted strings; doubles a single quote character
| — literal block; content indented below the key, indentation is stripped from output
|- — strip modifier removes all trailing newlines; useful when embedding in templates
> — folded block; single line breaks become spaces; blank line creates \n\n
>- — folded + strip; most common for long single-line config values
Block scalar indentation is detected automatically from the first content line; or set explicitly with |2

Common Mistakes

  • Using | when you want a single-line result — use >- to fold lines and strip the trailing newline
  • Expecting \n to work in single-quoted strings — escapes only work in double-quoted strings
  • Inconsistent indentation inside block scalars — the first content line sets the indentation baseline
  • Not accounting for the trailing newline in | blocks when passing to shell commands

Tips

  • Use |- for embedded scripts and commands — it removes the trailing newline that would otherwise be passed to the shell
  • Use >- for long descriptions in CI/CD configs — keeps the file readable while producing a single string
  • Single-quoted strings are ideal for regex patterns and file paths — no backslash surprises

Summary

  • plain — no quotes; simplest; auto-typed
  • '…' — single-quoted; literal backslashes; '' for quote
  • "…" — double-quoted; full escape sequences
  • | — literal block; preserves newlines
  • > — folded block; single breaks → spaces
  • - modifier strips trailing newlines; + keeps them all
