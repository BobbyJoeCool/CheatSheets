The plugins Array

Plugins extend Vite with frameworks, file types and build steps. Add them to the plugins array; each entry is a plugin object, an array of plugins, or a falsy value (ignored, which makes conditionals easy). Vite's plugin interface extends Rollup's, so many Rollup plugins work as-is, and the order of execution is controlled with enforce and apply.

Notes

  • Find plugins at registry.vite.dev and github.com/vitejs/awesome-vite
  • Rollup plugins using standard hooks usually work with Rolldown
  • Plugins relying on Rollup internals may break in Vite 8
  • vite-plugin-inspect shows each plugin's transforms

Adding and Ordering Plugins

import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import svgr from 'vite-plugin-svgr'
import yaml from '@rollup/plugin-yaml'
import Inspect from 'vite-plugin-inspect'

export default defineConfig(({ command }) => ({
  plugins: [
    react(),
    svgr(),                                       // './x.svg?react'
    { ...yaml(), enforce: 'pre' },                // run before core plugins
    { ...someRollupPlugin(), apply: 'build' },    // build only
    command === 'serve' && Inspect(),             // dev only; false is ignored
  ],
}))

Code Explained

Call the factory — react(), not react
enforce: 'pre' — run before Vite core plugins
apply: 'build' / 'serve' — limit to one command
Falsy entries are skipped
Rollup plugins go in the same array

⚠ Common Mistakes

  • Passing react instead of react() — the factory must be called
  • Adding a Rollup plugin that should only run on the final bundle without apply: 'build' — it slows or breaks dev
  • Installing an unmaintained plugin that patches Rollup internals — check Vite 8 compatibility first
  • Registering the same framework plugin twice through a meta-framework and your own config

✓ Tips & Best Practices

  • Use vite-plugin-inspect at /__inspect/ to see what each plugin changed
  • Wrap Rollup plugins with { ...plugin(), enforce, apply } to tune them
  • Prefer official @vitejs/plugin-* packages for frameworks
  • Keep plugin count small; each transform hook costs time on every file

Quick Summary

  • plugins: [react()] — register plugins
  • enforce — pre / normal / post ordering
  • apply — serve or build only
  • Rollup plugins — mostly compatible
