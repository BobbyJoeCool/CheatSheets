Vite-Native Testing

Vitest is the test runner built on Vite. It reuses your vite.config (plugins, aliases, transforms), so tests see code exactly as the app does, and it has a Jest-compatible API (describe, it, expect, vi). Add a test block to your Vite config or a separate vitest.config.ts.

Notes

  • vitest watches by default; vitest run runs once (CI)
  • Install jsdom or happy-dom for DOM tests
  • Browser Mode runs tests in a real browser via Playwright
  • Use a Vitest release that supports your Vite major

vite.config.ts

/// <reference types="vitest/config" />
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [react()],
  test: {
    environment: 'jsdom',
    globals: true,          // no test imports
    setupFiles: ['./src/test/setup.ts'],
    include: ['src/**/*.{test,spec}.{ts,tsx}'],
    coverage: {
      provider: 'v8', reporter: ['text', 'html'],
    },
  },
})

price.test.ts

import { describe, it, expect, vi } from 'vitest'
import { total } from './price'
import { getRate } from './api'

vi.mock('./api', () => ({ getRate: vi.fn() }))

describe('total', () => {
  it('adds tax', async () => {
    vi.mocked(getRate).mockResolvedValue(0.1)
    expect(await total(100)).toBe(110)
  })
})

⚠ Common Mistakes

  • Using globals: true without adding vitest/globals to tsconfig types — tests run but the editor complains
  • Expecting vi.mock to run where it's written — it's hoisted to the top of the file
  • Forgetting to install jsdom after setting environment: 'jsdom'
  • Keeping Jest's moduleNameMapper — Vitest uses your Vite resolve.alias instead

✓ Tips & Best Practices

  • Use mergeConfig(viteConfig, defineConfig({ test })) in a separate vitest.config.ts if you prefer
  • Add @testing-library/jest-dom matchers in the setup file
  • Use workspaces/projects for monorepos with mixed environments
  • Run vitest run --coverage in CI with thresholds
