Preview & Static Deployment

vite preview · preview.port · base for subpaths · SPA fallback · GitHub Pages · Netlify / Vercel · cache headers

Shipping dist/

A Vite app builds to plain static files, so any static host works. vite preview serves dist/ locally to check the build, but it's not a production server. The two settings that matter for deployment are base (when the site lives under a subpath) and an SPA fallback so client-side routes return index.html instead of 404.

Notes

  • Preview default port: 4173
  • preview.* options mirror server.* (host, port, proxy, headers)
  • Hashed files in assets/ can be cached forever
  • index.html should not be cached long

Preview and a GitHub Pages Deploy

vite build && vite preview --port 8080 --host

# vite.config.ts for https://user.github.io/my-repo/
#   base: '/my-repo/',
#   preview: { port: 8080, strictPort: true },

# .github/workflows/deploy.yml (key steps)
#   - run: npm ci && npm run build
#   - uses: actions/upload-pages-artifact@v3
#     with: { path: dist }
#   - uses: actions/deploy-pages@v4

# SPA fallback examples
echo '/*  /index.html  200' > public/_redirects        # Netlify
# vercel.json: { "rewrites": [{ "source": "/(.*)", "destination": "/" }] }

Code Explained

vite preview — local check of the real build
base: '/my-repo/' — project pages live under the repo name
upload-pages-artifact — publish dist/ to Pages
_redirects in public/ — copied to dist/ for Netlify
rewrites — Vercel SPA fallback

⚠ Common Mistakes

  • Running vite preview on a public server — it's not hardened for production traffic
  • Deploying to user.github.io/repo with base: '/' — assets load from the wrong path
  • Refreshing a deep link like /settings and getting 404 — the host needs an SPA fallback
  • Caching index.html for a year — users never see new deployments

✓ Tips & Best Practices

  • Use base: './' when the same build is served from unknown subpaths
  • Add vite preview to a CI smoke test with Playwright
  • Keep old hashed assets for a while after deploying (open tabs still request them)
  • Set preview.headers to test CSP and COOP before deploying

Quick Summary

  • vite preview — local check only
  • base — required for subpath hosting
  • SPA fallback — route everything to index.html
  • assets/* immutable, index.html no-cache
