CSS & CSS Modules

import './x.css' · *.module.css · ?inline · @import inlining · url() rebasing · css.modules

CSS in Vite

Importing a .css file injects it into the page in dev (with HMR) and extracts it into a hashed .css file in the build. Files named *.module.css are CSS Modules: class names get scoped, and the import returns an object mapping your names to the generated ones. @import statements are inlined and relative url()s are rewritten.

Notes

  • PostCSS runs automatically if a config exists
  • ?inline returns the CSS string without injecting it
  • Works for .module.scss, .module.less too
  • Vite 8 build minifies CSS with Lightning CSS

Importing CSS

import './global.css'              // global
import styles from './Btn.module.css' // scoped
import { primary } from './Btn.module.css'
import printCss from './print.css?inline'
import themeUrl from './theme.css?url'

btn.className = styles.primary  // 'primary_x7d2a'
btn.className = styles['is-active']

const style = document.createElement('style')
style.textContent = printCss

Module File + Config

/* Button.module.css */
.primary { color: white; background: var(--brand); }
.is-active { outline: 2px solid; }
.large { composes: primary; font-size: 1.25rem; }

/* vite.config.ts
css: {
  modules: {
    localsConvention: 'camelCaseOnly', // styles.isActive
    generateScopedName: '[name]__[local]__[hash:base64:5]',
  },
  devSourcemap: true,
} */

CSS Import Forms

ImportResult
import './a.css'Injected; side effect only
import s from './a.module.css'Class name map
import { x } from './a.module.css'Named class
'./a.css?inline'CSS string
'./a.css?url'Built file URL

css.modules Options

OptionPurpose

⚠ Common Mistakes

  • Naming a file Button.css and expecting scoped classes — only *.module.css files are modules
  • Using styles.is-active — dashes need bracket access or localsConvention
  • Importing CSS with ?inline and wondering why nothing styles the page — ?inline never injects
  • Relying on CSS import order across lazy chunks — chunk CSS loads when the chunk does

✓ Tips & Best Practices

  • Use :global(.name) inside a module for one unscoped selector
  • Enable css.devSourcemap to map styles back to source files in DevTools
  • Use composes: to share styles between module classes
  • Use ?inline for Shadow DOM styles in web components

Quick Summary

  • import './x.css' — global, injected
  • *.module.css — scoped class map
  • ?inline / ?url — string or URL
  • css.modules — naming and scoping options
