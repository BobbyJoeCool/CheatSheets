Tailwind + CSS Output

Tailwind CSS v4 ships a first-party Vite plugin, @tailwindcss/vite, that's faster than the PostCSS route and needs no tailwind.config.js for most projects. The other half of this sheet covers how Vite outputs CSS in production: per-chunk CSS files, minification (Lightning CSS by default in Vite 8) and the browser target used to lower modern syntax.

Notes

  • Tailwind v4 configures with @theme in CSS
  • Content sources are detected automatically
  • build.cssCodeSplit: false → one CSS file
  • build.cssTarget defaults to build.target

Tailwind v4 Setup

// npm i -D tailwindcss @tailwindcss/vite
// vite.config.ts
import { defineConfig } from 'vite'
import tailwindcss from '@tailwindcss/vite'

export default defineConfig({
  plugins: [tailwindcss()],
})

// src/main.ts
import './app.css'

app.css + Build Options

@import "tailwindcss";
@theme {
  --color-brand: oklch(0.62 0.19 260);
  --font-display: "Inter", sans-serif;
}
@source "../node_modules/@my/ui";

/* vite.config.ts → build: {
     cssCodeSplit: true,       one CSS per chunk
     cssMinify: 'lightningcss',
     cssTarget: 'chrome111',
   } */

⚠ Common Mistakes

  • Following Tailwind v3 guides (tailwind.config.js, @tailwind base) for a v4 install
  • Using both @tailwindcss/vite and @tailwindcss/postcss — pick one
  • Setting cssTarget lower than needed — forces extra prefixes and fallbacks
  • Turning off cssCodeSplit in a large app — every page downloads all CSS

✓ Tips & Best Practices

  • Add @source for class names inside node_modules component libraries
  • Use @theme variables in plain CSS too: color: var(--color-brand)
  • Set cssCodeSplit: false for libraries that ship one stylesheet
  • Use the Tailwind IntelliSense editor extension for v4 autocomplete

Quick Summary

  • @tailwindcss/vite — Tailwind v4 plugin
  • @import "tailwindcss" + @theme — CSS-first config
  • build.cssCodeSplit — per-chunk CSS
  • build.cssMinify — Lightning CSS by default
