The server Block

The server block configures the development server: where it listens, whether it opens a browser, HTTPS, file-system access and which hostnames it accepts. Defaults are safe for local work: it listens on localhost:5173, blocks unknown Host headers, and only serves files inside the workspace root.

Notes

  • server.allowedHosts guards against DNS rebinding
  • server.fs.strict blocks files outside the allow list
  • server.forwardConsole (Vite 8) pipes browser logs to the terminal
  • preview.* mirrors most of these for vite preview

Common Server Setup

import { defineConfig } from 'vite'
import basicSsl from '@vitejs/plugin-basic-ssl'

export default defineConfig({
  plugins: [basicSsl()],              // quick self-signed HTTPS
  server: {
    host: true,                       // 0.0.0.0 — LAN + containers
    port: 3000,
    strictPort: true,
    open: '/dashboard',
    allowedHosts: ['.ngrok.app', 'dev.local'],
    fs: { allow: ['..'] },            // monorepo: serve parent folder
    watch: { usePolling: true },      // Docker / WSL mounts
    forwardConsole: true,             // browser console → terminal
  },
})

Code Explained

host: true — listen on every interface
open — true or a path to open
allowedHosts — leading . allows subdomains; true allows all
fs.allow — folders Vite may serve from
watch.usePolling — needed where file events don't arrive

⚠ Common Mistakes

  • Fixing "Blocked request. This host is not allowed" with allowedHosts: true on a public network — list the exact hosts instead
  • Opening a file from a sibling package and getting "outside of Vite serving allow list" — add it to server.fs.allow
  • Changing files in Docker with no reload — enable watch.usePolling
  • Expecting server.port to apply to vite preview — use preview.port

✓ Tips & Best Practices

  • Use @vitejs/plugin-basic-ssl or mkcert for HTTPS-only browser APIs
  • Set server.origin when a backend serves the HTML and Vite serves assets
  • Turn on forwardConsole when debugging mobile devices from the terminal
  • Keep fs.strict: true; widen fs.allow only as needed

Quick Summary

  • server.host / port — where it listens
  • server.allowedHosts — accepted Host headers
  • server.fs.allow — servable folders
  • server.forwardConsole — browser logs in terminal
