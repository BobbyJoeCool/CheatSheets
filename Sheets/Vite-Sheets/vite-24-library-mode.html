Library Mode

build.lib · entry · formats · fileName · external · peerDependencies · package.json exports

Building a Package

Library mode builds a reusable package instead of an app: no index.html, one or more JS entries, and output formats such as ES modules and UMD. The key job is marking framework dependencies as external so your library doesn't bundle its own copy of React or Vue. Pair the output with exports in package.json so consumers get the right file.

Notes

  • Default formats: ['es', 'umd'], or ['es', 'cjs'] with multiple entries
  • name is required for umd / iife (global variable)
  • CSS is emitted as one file; name it with build.lib.cssFileName
  • Types: generate .d.ts with tsc or vite-plugin-dts

vite.config.ts

import { resolve } from 'node:path'
import { defineConfig } from 'vite'

export default defineConfig({
  build: {
    lib: {
      entry: {
        index: resolve(import.meta.dirname, 'src/index.ts'),
        utils: resolve(import.meta.dirname, 'src/utils.ts'),
      },
      formats: ['es', 'cjs'],
      fileName: (format, name) =>
        `${name}.${format === 'es' ? 'js' : 'cjs'}`,
      cssFileName: 'style',
    },
    rolldownOptions: {
      external: ['react', 'react-dom', 'react/jsx-runtime'],
    },
  },
})

package.json

{
  "name": "@acme/ui",
  "type": "module",
  "files": ["dist"],
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.js",
      "require": "./dist/index.cjs"
    },
    "./utils": "./dist/utils.js",
    "./style.css": "./dist/style.css"
  },
  "peerDependencies": { "react": ">=18" },
  "sideEffects": ["**/*.css"]
}

build.lib Options

OptionPurpose
entryPath, array or { name: path }
nameGlobal name for umd / iife
formatses · cjs · umd · iife
fileNameString or (format, entry) => name
cssFileNameName of the emitted CSS file

What to Externalize

Dependency typeExternal?
peerDependencies (react, vue)✔ always
dependencies✔ usually
Subpaths (react/jsx-runtime)✔ list them too
Small internal helpers✖ bundle
Node built-ins (node:fs)✔ for Node libs

⚠ Common Mistakes

  • Leaving React un-externalized — consumers end up with two Reacts and broken hooks
  • Externalizing react but not react/jsx-runtime — the runtime still gets bundled
  • Forgetting name with a umd format — the build errors out
  • Publishing without "files": ["dist"] — source and config ship too

✓ Tips & Best Practices

  • Use a regex external like /^react(\/.*)?$/ to catch all subpaths
  • Generate types with vite-plugin-dts or a separate tsc --emitDeclarationOnly
  • Check the package with npx publint and arethetypeswrong before publishing
  • Mark CSS as a side effect so bundlers don't drop it

Quick Summary

  • build.lib.entry — library entry points
  • formats — es / cjs / umd / iife
  • rolldownOptions.external — keep peers out
  • package.json exports — map entries to files
