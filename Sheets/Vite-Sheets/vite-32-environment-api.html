Environment API

environments · client / ssr · createRunnableDevEnvironment · ModuleRunner · per-environment config · experimental status

Many Runtimes, One Server

The Environment API generalizes Vite's old client/SSR split into any number of named environments: browser client, Node SSR, edge workers, React Server Components and so on. Each environment gets its own module graph, resolve conditions and build output. It's aimed mainly at framework and runtime authors; app developers usually get it through their framework.

Notes

  • Introduced in Vite 6; still marked as not yet stable in Vite 8
  • Top-level options act as defaults for every environment
  • vite build --app builds all environments
  • Plugins read this.environment instead of an ssr flag

Config

export default defineConfig({
  build: { sourcemap: true },        // default for all
  environments: {
    client: { build: { outDir: 'dist/client' } },
    ssr: { build: { outDir: 'dist/server' } },
    edge: {
      resolve: { noExternal: true, conditions: ['workerd'] },
      build: {
        outDir: 'dist/edge',
        rolldownOptions: { input: 'src/edge.ts' },
      },
    },
  },
  builder: {
    buildApp: (b) => Promise.all(
      Object.values(b.environments).map((e) => b.build(e))),
  },
})

Using Environments

import { createServer, isRunnableDevEnvironment } from 'vite'

const server = await createServer()
const ssr = server.environments.ssr

if (isRunnableDevEnvironment(ssr)) {
  const { render } = await ssr.runner.import('/src/entry-server.ts')
  console.log(await render('/'))
}

// In a plugin
const plugin = {
  name: 'env-aware',
  applyToEnvironment: (env) => env.name !== 'client',
  transform(code, id) {
    const server = this.environment.config.consumer === 'server'
  },
}

⚠ Common Mistakes

  • Treating the API as stable for app code — expect changes between minors until it's marked stable
  • Checking options.ssr in new plugin hooks — use this.environment.name or .config.consumer
  • Assuming every environment can run in Node — edge or workerd environments need their own runner
  • Building with plain vite build and only getting the client — use vite build --app or builder.buildApp

✓ Tips & Best Practices

  • Use isRunnableDevEnvironment() before calling .runner.import()
  • Put shared settings at the top level; override only what differs per environment
  • Read the framework's docs first; most expose a higher-level API
  • Test plugins against both client and ssr environments

Quick Summary

  • environments: { client, ssr, … } — per-runtime config
  • server.environments.ssr.runner.import() — run code in dev
  • vite build --app — build every environment
  • this.environment — environment-aware plugins
