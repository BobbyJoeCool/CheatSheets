Sheet 07

Resolve & Path Aliases

resolve.alias · resolve.tsconfigPaths · extensions · conditions · dedupe · mainFields

Module Resolution

The resolve options control how import specifiers become files. Aliases map short prefixes like @/ to real folders. Vite 8 can also read the paths from your tsconfig.json directly with resolve.tsconfigPaths: true, so TypeScript and Vite stay in sync without a plugin.

Notes

  • tsconfigPaths is off by default (small perf cost)
  • Alias targets should be absolute paths
  • Vite 8 always respects your mainFields order (no format sniffing)
  • customResolver on aliases is deprecated in Vite 8

Aliases Two Ways

import { defineConfig } from 'vite'
import { fileURLToPath, URL } from 'node:url'

export default defineConfig({
  resolve: {
    alias: {
      '@': fileURLToPath(new URL('./src', import.meta.url)),
    },
    // or: read "paths" from tsconfig.json (Vite 8)
    // tsconfigPaths: true,
    dedupe: ['react', 'react-dom'],
    conditions: ['custom', 'module', 'browser', 'development|production'],
  },
})

// src/main.ts
import Button from '@/components/Button.vue'

Code Explained

alias object — prefix → absolute path
fileURLToPath(new URL(...)) — portable ESM path
tsconfigPaths: true — no duplicate alias config
dedupe — force one copy of a package (linked libs)
conditions — package.json exports conditions to match

⚠ Common Mistakes

  • Defining @ in vite.config but not in tsconfig.json — Vite builds while the editor shows errors
  • Using a relative alias target like './src' — behaves differently per importer; use absolute paths
  • Omitting extensions in imports and relying on resolve.extensions for .vue — slower and discouraged
  • Aliasing a bare package name and breaking that package's own imports

✓ Tips & Best Practices

  • Prefer resolve.tsconfigPaths: true in TS projects so there's one source of truth
  • Use array form { find: /^~(.*)$/, replacement: '$1' } for regex aliases
  • Add dedupe: ['react'] when a linked package bundles its own React
  • Import with explicit extensions (./util.ts style is fine with allowImportingTsExtensions)

Quick Summary

  • resolve.alias — @ → /abs/src
  • resolve.tsconfigPaths — reuse tsconfig paths
  • resolve.dedupe — one copy of a dependency
  • resolve.conditions — pick package export variants
