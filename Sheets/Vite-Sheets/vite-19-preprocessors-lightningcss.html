Preprocessors, PostCSS & Lightning CSS

sass-embedded · less · postcss.config.js · css.transformer: 'lightningcss' · css.preprocessorOptions · css.devSourcemap

Beyond Plain CSS

Vite supports Sass, Less and Stylus once you install the preprocessor package; there are no Vite plugins to add. PostCSS runs automatically when a postcss.config.* file exists. Alternatively set css.transformer: 'lightningcss' to use Lightning CSS for nesting, prefixing and syntax lowering instead of PostCSS (Vite 8.1 closed most gaps; it may become the default).

Notes

  • Install sass-embedded (fastest) or sass
  • Lightning CSS is a regular dependency since Vite 8
  • PostCSS plugins don't run when the transformer is Lightning CSS
  • css.lightningcss takes targets, drafts and similar options

Config for Each Approach

// npm i -D sass-embedded   (or less / stylus)
export default defineConfig({
  css: {
    preprocessorOptions: {
      scss: {
        additionalData: `@use "@/styles/vars" as *;`,  // every file
      },
      less: { math: 'always', javascriptEnabled: true },
    },
    preprocessorMaxWorkers: true,     // parallel Sass/Less
    devSourcemap: true,

    // Option B: Lightning CSS instead of PostCSS
    // transformer: 'lightningcss',
    // lightningcss: { drafts: { customMedia: true } },
  },
})
// postcss.config.js → export default { plugins: [autoprefixer()] }

Code Explained

additionalData — prepended to every .scss file
Keys are language names: scss, sass, less, styl
preprocessorMaxWorkers — run compilers in workers
transformer: 'lightningcss' — replaces PostCSS
postcss.config.js — auto-detected, no Vite setting

⚠ Common Mistakes

  • Putting real CSS rules in additionalData — they're duplicated into every file; share variables and mixins only
  • Using @import in Sass — it's deprecated; switch to @use / @forward
  • Switching to transformer: 'lightningcss' and expecting Tailwind's PostCSS plugin to run — use @tailwindcss/vite instead
  • Installing node-sass — unsupported; use sass-embedded

✓ Tips & Best Practices

  • Prefer native CSS nesting and custom properties; you may not need a preprocessor
  • Keep browserslist in package.json so Autoprefixer and Lightning CSS target the same browsers
  • Try transformer: 'lightningcss' for faster CSS processing in big apps
  • Alias style folders (@/styles) so @use paths stay short

Quick Summary

  • npm i -D sass-embedded — Sass support
  • css.preprocessorOptions.scss — shared vars
  • postcss.config.js — auto-loaded
  • css.transformer: 'lightningcss' — PostCSS alternative
