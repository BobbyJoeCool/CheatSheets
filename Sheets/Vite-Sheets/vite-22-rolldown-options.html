Sheet 22

Rolldown Options & Chunking

build.rolldownOptions · input (multi-page) · output.codeSplitting · chunkFileNames · external · manualChunks (deprecated)

Bundler Control

build.rolldownOptions passes settings straight to Rolldown, the bundler. Use it for multiple HTML entries, custom output file names, externals and chunk grouping. Vite 8 renamed it from build.rollupOptions (the old name still works with a deprecation warning). Rolldown's codeSplitting.groups replaces manualChunks for vendor splitting.

Notes

  • Object-form manualChunks is removed in Vite 8
  • Function-form manualChunks is deprecated
  • Group test regexes should use [\\/] for Windows paths
  • Output formats system and amd are no longer supported

Multi-Page + Vendor Chunks

import { resolve } from 'node:path'
const r = (p: string) => resolve(import.meta.dirname, p)

export default defineConfig({
  build: {
    rolldownOptions: {
      input: { main: r('index.html'), admin: r('admin/index.html') },
      external: ['some-cdn-lib'],
      output: {
        entryFileNames: 'js/[name]-[hash].js',
        chunkFileNames: 'js/chunks/[name]-[hash].js',
        assetFileNames: 'static/[name]-[hash][extname]',
        codeSplitting: {
          groups: [
            { name: 'react', test: /node_modules[\\/]react/, priority: 2 },
            { name: 'vendor', test: /node_modules/, priority: 1 },
          ],
        },
      },
    },
  },
})

Code Explained

input object — one entry per HTML page
external — leave imports unbundled
*FileNames — placeholders [name] [hash] [ext]
codeSplitting.groups — named chunk groups
priority — higher groups claim modules first

codeSplitting Group Fields

FieldPurpose
nameChunk name, or (id) => name
testRegExp / string / (id) => bool
priorityHigher matches first (default 0)
minSize / maxSizeByte limits; split above max
minShareCountEntries that must share a module

⚠ Common Mistakes

  • Copying a Vite 7 manualChunks: { vendor: [...] } object — it no longer works; rewrite as codeSplitting.groups
  • Adding extra HTML pages without listing them in input — only index.html builds
  • Using /node_modules\/react/ — misses Windows paths; use [\\/]
  • Putting every dependency in one vendor chunk — one change busts the whole cache

✓ Tips & Best Practices

  • Split rarely changing, heavy libs (React, charting) into their own groups
  • Use import.meta.dirname instead of __dirname in ESM configs
  • Mark CDN-loaded libraries external and add them via <script> or an import map
  • Measure with a bundle analyzer before and after changing chunking

Quick Summary

  • build.rolldownOptions — Rolldown settings (was rollupOptions)
  • input: { a, b } — multi-page apps
  • output.codeSplitting.groups — vendor chunks
  • external — don't bundle these imports
