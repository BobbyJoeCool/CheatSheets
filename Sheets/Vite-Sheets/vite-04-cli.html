Sheet 04

CLI Commands

vite · vite build · vite preview · --host · --port · --mode · --force · --config

Commands

The vite binary has three main commands: vite (alias vite dev / vite serve) starts the dev server, vite build creates the production bundle, and vite preview serves that bundle. CLI flags override the matching config options, and an optional [root] argument changes the project root. While the dev server runs, single-key shortcuts (h for help) control it from the terminal.

Notes

  • Run through npm scripts or npx vite …
  • Flags beat vite.config.* values
  • --mode changes which .env.[mode] files load
  • vite --help / vite build --help list every flag

Everyday Commands

vite                          # dev server on :5173
vite --host                   # listen on 0.0.0.0 (LAN / containers)
vite --port 3000 --strictPort # fail instead of picking another port
vite --open                   # open the browser on start
vite --force                  # re-run dependency pre-bundling
vite --mode staging           # load .env.staging
vite -c vite.other.config.ts  # use another config file

vite build                    # production build → dist/
vite build --mode staging --sourcemap
vite build --watch            # rebuild on change
vite build --ssr src/entry-server.ts

vite preview --port 8080      # serve dist/

Code Explained

--host — expose to other devices; prints a Network URL
--strictPort — exits if the port is taken
--force — ignores the node_modules/.vite cache
-c / --config — alternate config file path
--ssr — builds a server entry instead of the client

⚠ Common Mistakes

  • Passing flags to an npm script without -- (npm run dev --host) — npm eats them; use npm run dev -- --host
  • Using vite preview as a production server — it's for local checks only
  • Forgetting --host inside Docker — the server binds to localhost and is unreachable
  • Expecting --mode production in dev to minify — mode only changes env and import.meta.env

✓ Tips & Best Practices

  • Bake common flags into scripts: "dev": "vite --host --open"
  • Use vite --debug hmr to see why HMR does a full reload
  • vite build --profile writes a CPU profile for slow builds
  • Add --strictPort when other tools expect a fixed port

Quick Summary

  • vite — dev server
  • vite build — production bundle
  • vite preview — serve the bundle
  • --mode / --host / --force — the flags you'll use most
