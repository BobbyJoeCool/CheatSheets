Hot Module Replacement

import.meta.hot · accept() · dispose() · hot.data · invalidate() · server.hmr · full reload

How HMR Works

HMR swaps changed modules into the running page without a reload, keeping state. Framework plugins (React Fast Refresh, Vue, Svelte) handle it for you; import.meta.hot is the low-level API for libraries and plain JS. When a changed module has no accepting boundary, Vite falls back to a full page reload.

Notes

  • import.meta.hot is undefined in production — always guard it
  • The if (import.meta.hot) block is removed from builds
  • CSS files hot-update automatically
  • Vite 8 removed passing URLs to hot.accept; pass ids

Self-Accepting Module

// counter.js
export let count = 0
const timer = setInterval(() => count++, 1000)

if (import.meta.hot) {
  import.meta.hot.data.count ??= 0             // persists across updates
  import.meta.hot.accept((newModule) => {      // this file is a boundary
    if (newModule) console.log('updated', newModule.count)
  })
  import.meta.hot.dispose((data) => {          // clean up old version
    clearInterval(timer)
    data.count = count
  })
}

Code Explained

accept(cb) — module handles its own updates
dispose(cb) — undo side effects before replacement
data — object kept between versions of the module
Block is stripped from production builds

⚠ Common Mistakes

  • Calling import.meta.hot.accept() without a guard — crashes in production where hot is undefined
  • Using const hot = import.meta.hot and calling hot.accept — Vite needs the literal import.meta.hot.accept(...) to detect boundaries
  • Exporting non-components from a React component file — Fast Refresh falls back to a full reload

✓ Tips & Best Practices

  • Run vite --debug hmr to see which module triggered a full reload
  • Use invalidate() when an update can't be applied safely
  • Behind a reverse proxy set server.hmr.clientPort to the public port
  • Keep React component files exporting components only

Quick Summary

  • import.meta.hot.accept() — mark an HMR boundary
  • dispose() + data — clean up and carry state
  • vite:* events — hook into the update cycle
  • server.hmr — WebSocket and overlay settings
