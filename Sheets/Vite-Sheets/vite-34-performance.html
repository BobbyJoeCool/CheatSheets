Performance & Bundled Dev Mode

experimental.bundledDev · --experimental-bundle · server.warmup · barrel files · --profile · Vite Devtools

Speeding Up Dev

Vite's dev server is fast by default, but very large apps can hit limits: thousands of module requests on first load, slow plugins, and deep barrel-file imports. Fix the common causes first (warm-up, direct imports, fewer heavy plugins). Vite 8.1 also adds an experimental Bundled Dev Mode that serves bundled output in development for apps with huge module graphs.

Notes

  • Bundled Dev Mode was previously called Full Bundle Mode
  • It may not work with every third-party plugin yet
  • --profile + p key records a CPU profile
  • Vite Devtools (devtools: true) shows transform timing

Config and Tools

export default defineConfig({
  server: {
    warmup: {
      clientFiles: ['./src/main.tsx', './src/components/**/*.tsx'],
      ssrFiles: ['./src/entry-server.ts'],
    },
  },
  experimental: { bundledDev: true },  // Vite 8.1+, or: vite --experimental-bundle
  devtools: true,                      // Vite Devtools
})

// Avoid barrel files in hot paths
import { Button } from '@/components'              // loads every component
import { Button } from '@/components/Button.tsx'   // loads one file

// Profiling (shell)
// vite --profile        → press p+enter, open .cpuprofile in DevTools
// vite --debug plugin-transform   → slow plugin transforms

Code Explained

warmup.clientFiles — transform likely files before requests
bundledDev — serve bundled modules in dev (experimental)
devtools — inspect modules and plugin timings
Direct imports — skip loading every re-exported file
--profile / --debug — find the slow part

Common Slowdowns

SymptomFix

Plugin Hygiene

PracticeWhy
Hook filtersSkip JS calls for non-matching files
apply: 'build'Keep build-only work out of dev

Avoid full AST parsesCheck code.includes() first
Drop unused pluginsEach hook adds per-file cost

⚠ Common Mistakes

  • Enabling bundledDev and assuming plugins behave the same — test HMR and custom plugins carefully
  • Warming up every file with **/* — wastes startup time on files you never open
  • Re-exporting an entire folder through index.ts and importing from it everywhere
  • Blaming Vite before checking browser extensions — some slow down every module request

✓ Tips & Best Practices

  • Open DevTools' Network panel with cache disabled off; Vite relies on browser caching
  • Run vite --profile and load the page once, then inspect the profile in Chrome or speedscope
  • Use vite-plugin-inspect to compare per-plugin transform time
  • Keep the dev server on fast storage (not network drives or slow WSL mounts)

Quick Summary

  • server.warmup — pre-transform hot files
  • experimental.bundledDev — bundled dev (8.1)
  • Direct imports — avoid barrel files
  • --profile / devtools — measure first
