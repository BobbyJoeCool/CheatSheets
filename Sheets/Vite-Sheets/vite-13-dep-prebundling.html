Dependency Pre-Bundling

optimizeDeps.include · exclude · optimizeDeps.rolldownOptions · --force · node_modules/.vite · linked packages

Why Pre-Bundle

On first start, Vite scans your source for bare imports and pre-bundles those dependencies with Rolldown into node_modules/.vite/deps. This converts CommonJS packages to ESM and collapses packages made of hundreds of files (like lodash-es) into one request each. Results are cached and reused until your lockfile, config or patches change.

Notes

  • Dev-only; the build bundles deps directly
  • Vite 8 renamed optimizeDeps.esbuildOptions → rolldownOptions
  • Deps found late trigger a re-bundle and page reload
  • Browser caches deps with max-age=31536000,immutable

optimizeDeps in Practice

export default defineConfig({
  optimizeDeps: {
    include: [
      'lodash-es',                    // many small files
      'my-cjs-lib',                   // CJS → ESM
      'linked-pkg > nested-cjs-dep',  // dep of a linked package
    ],
    exclude: ['@my-org/ui-kit'],      // linked ESM source; let HMR work
    entries: ['src/main.ts', 'src/admin/*.html'],
    holdUntilCrawlEnd: true,          // wait for full crawl on cold start
    rolldownOptions: {                // was esbuildOptions
      resolve: { mainFields: ['module', 'main'] },
    },
  },
})

Code Explained

include — force a dep into pre-bundling
a > b — target a nested dependency
exclude — serve a package as raw source
entries — where the scanner starts
rolldownOptions — Rolldown settings for the optimizer

⚠ Common Mistakes

  • Excluding a CommonJS package — the browser can't load raw CJS and you get "does not provide an export named …"
  • Deleting node_modules to clear the cache — vite --force or removing node_modules/.vite is enough
  • Ignoring repeated "new dependencies optimized" logs — each one costs a reload; add them to include
  • Copying old esbuildOptions.plugins — Rolldown support for those is partial; port them to Rolldown plugins

✓ Tips & Best Practices

  • Watch the terminal on first load and add any late-discovered deps to include
  • In monorepos, exclude your linked ESM packages so edits hot-reload
  • Use DEBUG=vite:deps vite to see what the optimizer is doing
  • Commit the include list so every developer gets the same cold start

Quick Summary

  • optimizeDeps.include — pre-bundle these
  • optimizeDeps.exclude — serve as source
  • vite --force — rebuild the dep cache
  • node_modules/.vite/deps — where results live
