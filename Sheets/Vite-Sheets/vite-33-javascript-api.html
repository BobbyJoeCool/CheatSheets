Vite from Node

Everything the CLI does is available from Node through the vite package. Use it to embed a dev server in your own tool, script builds, run several builds in sequence, or read the resolved config. Each function takes an inline config that's merged with the project's config file unless you pass configFile: false.

Notes

  • All functions are async; Vite is ESM-only
  • Inline config has extra keys: configFile, envFile
  • build() returns the output, or a watcher with build.watch
  • transformWithEsbuild → transformWithOxc in Vite 8

Scripting Vite

import { createServer, build, preview, resolveConfig,
         mergeConfig, loadEnv, transformWithOxc } from 'vite'

const server = await createServer({
  configFile: false, root: import.meta.dirname, server: { port: 1337 },
})
await server.listen()
server.printUrls()
server.bindCLIShortcuts({ print: true })

await build({ root: './packages/app', build: { outDir: 'dist' } })
await build({ build: { ssr: 'src/entry-server.ts', outDir: 'dist/server' } })
const pv = await preview({ preview: { port: 8080, open: true } })

const config = await resolveConfig({}, 'build')   // command
const env = loadEnv('production', process.cwd(), '')
const { code } = await transformWithOxc('let n: number = 1', 'n.ts')

Code Explained

createServer() → ViteDevServer; call listen()
configFile: false — ignore vite.config.*
build() — sequential calls for client + server
resolveConfig(inline, command) — final config object
transformWithOxc — one-off TS/JSX transform

⚠ Common Mistakes

  • Calling createServer() and expecting it to listen — you must await server.listen()
  • Running build() twice in parallel on the same outDir — builds overwrite each other; await them in order
  • Forgetting configFile: false when you mean to ignore the project's config
  • Using __dirname in an ESM script — use import.meta.dirname

✓ Tips & Best Practices

  • Use searchForWorkspaceRoot(process.cwd()) to set server.fs.allow in monorepos
  • Close servers in tests with await server.close() to avoid hanging processes
  • Use normalizePath() for Windows-safe path comparisons in tools
  • Prefer the CLI unless you need programmatic control

Quick Summary

  • createServer() + listen() — dev server
  • build() / preview() — production steps
  • resolveConfig() — inspect final config
  • transformWithOxc() — standalone transform
