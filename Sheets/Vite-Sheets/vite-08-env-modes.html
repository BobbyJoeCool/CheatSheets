Sheet 08

Env Variables & Modes

import.meta.env · VITE_ prefix · .env.[mode].local · loadEnv · envPrefix · MODE / DEV / PROD / BASE_URL

How Env Works

Vite exposes environment values on import.meta.env. Only variables prefixed with VITE_ reach client code, and they're replaced statically at build time, so they end up in the shipped JS. The mode (development for vite, production for vite build, or whatever --mode says) decides which .env files load.

Notes

  • Values are always strings ('true', not true)
  • Existing shell env vars beat .env files
  • .local files are git-ignored by convention
  • Use $OTHER_VAR inside .env values to expand (dotenv-expand)

Files and Client Code

# .env                  always loaded
# .env.local            always, git-ignored
# .env.[mode]           only in that mode
# .env.[mode].local     only in that mode, git-ignored

# .env.staging
VITE_API_URL=https://staging.api.example.com
VITE_FEATURE_X=true
DB_PASSWORD=secret     # no VITE_ prefix → not exposed

# Type it — src/vite-env.d.ts
interface ImportMetaEnv {
  readonly VITE_API_URL: string
  readonly VITE_FEATURE_X: string
}

Reading Env in Code and Config

// client code
fetch(`${import.meta.env.VITE_API_URL}/users`)
if (import.meta.env.DEV) console.log('dev')
const on = import.meta.env.VITE_FEATURE_X === 'true'

// vite.config.ts (no import.meta.env here)
import { defineConfig, loadEnv } from 'vite'
export default defineConfig(({ mode }) => {
  const env = loadEnv(mode, process.cwd(), '')
  return {
    define: { __API__: JSON.stringify(env.API) },
    server: { port: Number(env.PORT) || 5173 },
  }
})

⚠ Common Mistakes

  • Putting secrets in VITE_* vars — they're inlined into public JS
  • Comparing import.meta.env.VITE_FLAG === true — the value is the string 'true'
  • Building dynamic keys like import.meta.env[name] — static replacement only works with literal property names
  • Assuming --mode staging sets NODE_ENV=staging — NODE_ENV stays production for builds

✓ Tips & Best Practices

  • Commit .env.example with every key and dummy values
  • Change the prefix with envPrefix: ['VITE_', 'PUBLIC_'] if needed
  • Keep .env*.local in .gitignore
  • Use loadEnv(mode, root, '') to read non-prefixed vars in the config

Quick Summary

  • VITE_ prefix — only these reach the browser
  • .env.[mode].local — highest-priority file
  • import.meta.env.MODE / DEV / PROD — built-ins
  • loadEnv() — env access inside vite.config
