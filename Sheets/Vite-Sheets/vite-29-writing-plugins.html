Sheet 29

Writing Plugins: Core Hooks

name · resolveId · load · transform · virtual modules (\0) · config · configResolved

Plugin Anatomy

A Vite plugin is an object with a name and hooks. Universal hooks (resolveId, load, transform) come from the Rollup/Rolldown API and run in both dev and build. Vite-specific hooks (config, configResolved, configureServer…) adjust Vite itself. Return the plugin from a factory function so users can pass options.

Notes

  • Prefix virtual module ids with \0 after resolving
  • Use virtual: in the public import name by convention
  • Hook filters skip the JS call for files that don't match
  • Name community plugins vite-plugin-*

A Virtual Module + Transform Plugin

import type { Plugin } from 'vite'

export default function buildInfo(): Plugin {
  const id = 'virtual:build-info'
  const resolved = '\0' + id
  let mode = ''
  return {
    name: 'build-info',
    configResolved(config) { mode = config.mode },
    resolveId(source) { if (source === id) return resolved },
    load(loadId) {
      if (loadId === resolved) return `export const mode = '${mode}'`
    },
    transform: {
      filter: { id: /\.md$/ },               // only Markdown files
      handler(code) { return `export default ${JSON.stringify(code)}` },
    },
  }
}
// app: import { mode } from 'virtual:build-info'

Code Explained

Factory function returns the plugin object
resolveId — claim the virtual id
load — return source code for that id
transform.filter — hook only runs on matches
configResolved — read the final config

⚠ Common Mistakes

  • Returning the virtual id without \0 — other plugins (and sourcemaps) try to treat it as a real file
  • Transforming every file without a filter or id check — slows the whole dev server
  • Mutating config in configResolved — it's read-only by then; use config()
  • Returning a string from transform without a sourcemap — debugging maps break; return { code, map }

✓ Tips & Best Practices

  • Use hook filter objects (id, code) so Rolldown can skip non-matching files natively
  • Add a .d.ts for your virtual module: declare module 'virtual:build-info'
  • Test hooks with vite-plugin-inspect to see before/after output
  • Use this.environment (sheet 30/32) instead of ssr flags in new plugins

Quick Summary

  • resolveId + load — virtual modules
  • transform — change source code
  • config / configResolved — Vite settings
  • filter — cheap file matching
