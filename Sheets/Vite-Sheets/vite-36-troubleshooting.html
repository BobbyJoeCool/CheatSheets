Debugging & Troubleshooting

--debug · DEBUG=vite:* · server.forwardConsole · CJS default import · legacy.inconsistentCjsInterop · BundleError

Finding the Problem

Most Vite problems fall into a few groups: dependency optimization, module resolution, CommonJS interop, host and file-system security checks, and stale caches. Turn on debug logging to see what Vite is doing, check the browser console and network tab, and clear the dependency cache before digging deeper. Vite 8 also changed how CommonJS default imports resolve, which surfaces in upgraded projects.

Notes

  • vite --force clears the dep cache for one run
  • server.forwardConsole shows browser errors in the terminal
  • build() errors are now a BundleError with an errors array
  • legacy.inconsistentCjsInterop: true restores old CJS behavior temporarily

Debug Commands

vite --debug                     # all debug logs
vite --debug hmr                 # why HMR did a full reload
vite --debug deps                # dependency optimizer
DEBUG="vite:resolve-details" vite   # resolution decisions
vite --force                     # rebuild node_modules/.vite
rm -rf node_modules/.vite        # same, permanently
vite build --debug --logLevel info
npx vite --version && node -v    # check versions first

# vite.config.ts
#   server: { forwardConsole: true, hmr: { overlay: true } }
#   logLevel: 'info', clearScreen: false

Code Explained

--debug <ns> — filter logs to one area
DEBUG=vite:* — same via environment variable
--force — first thing to try after dep changes
--logLevel info — more detail in builds
Version check — many issues are version mismatches

⚠ Common Mistakes

  • Deleting node_modules and the lockfile for every problem — try vite --force first
  • Suppressing the error overlay instead of fixing the error behind it
  • Mixing import x from 'cjs-pkg' and import * as x after upgrading to Vite 8 without checking the new interop rules
  • Debugging a production-only bug in dev — reproduce with vite build && vite preview

✓ Tips & Best Practices

  • Reproduce on StackBlitz (vite.new) before filing an issue
  • Search the Vite GitHub issues with the exact error text
  • Use vite-plugin-inspect to see what a plugin did to the failing file
  • Turn on server.forwardConsole when testing on phones or in agents

Quick Summary

  • --debug [ns] — targeted logs
  • vite --force — clear dep cache
  • server.fs.allow / allowedHosts — security errors
  • legacy.inconsistentCjsInterop — temporary CJS escape hatch
