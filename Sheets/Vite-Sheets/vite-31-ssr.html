DIY SSR with Vite

Vite provides SSR building blocks, not a framework: your own Node server runs Vite in middleware mode, loads the server entry with ssrLoadModule() (with HMR), renders HTML and sends it. For production you build twice, once for the client and once with --ssr for the server. Most teams use a framework that wires this up (Nuxt, SvelteKit, React Router, Astro, Vike).

Notes

  • Typical files: entry-client.ts (hydrate) + entry-server.ts (render)
  • appType: 'custom' turns off Vite's own HTML serving
  • Call vite.ssrFixStacktrace(e) in catch blocks for real line numbers
  • import.meta.env.SSR is true in server code

Dev Server (Express 5)

import fs from 'node:fs/promises'
import express from 'express'
import { createServer } from 'vite'
const app = express()
const vite = await createServer({
  server: { middlewareMode: true },
  appType: 'custom',
})
app.use(vite.middlewares)                  // assets, HMR, transforms
app.use('*all', async (req, res) => {
  const url = req.originalUrl
  let html = await fs.readFile('index.html', 'utf-8')
  html = await vite.transformIndexHtml(url, html)     // inject HMR client
  const { render } = await vite.ssrLoadModule('/src/entry-server.ts')
  html = html.replace('<!--app-html-->', await render(url))
  res.status(200).set({ 'Content-Type': 'text/html' }).end(html)
})
app.listen(5173)

Code Explained

middlewareMode — your server owns the HTTP server
vite.middlewares — serves modules and assets
transformIndexHtml — applies Vite and plugin HTML transforms
ssrLoadModule — loads TS/JSX in Node, re-runs on change
<!--app-html--> — placeholder you replace with rendered markup

vite build Flags for SSR

FlagOutput
--outDir dist/clientClient assets + index.html
--ssr src/entry-server.tsServer module (add --outDir dist/server)
--ssrManifestModule → chunk map for preloads
--appAll environments (sheet 32)

ssr.* Options

OptionPurpose
ssr.externalDeps to keep as require/import
ssr.noExternalDeps to bundle (CSS imports, ESM-only)
ssr.target'node' (default) or 'webworker'
ssr.resolve.conditionsExport conditions for SSR

⚠ Common Mistakes

  • Reading dist/client/index.html in dev or index.html in production — keep separate code paths for each
  • Touching window or document at module top level in shared code — it crashes during SSR; guard with import.meta.env.SSR
  • Leaving a UI library external when it imports CSS — Node can't load .css; add it to ssr.noExternal

✓ Tips & Best Practices

  • Start from npm create vite-extra@latest SSR templates if you build your own
  • Use the SSR manifest to emit <link rel="modulepreload"> for the rendered route
  • Prefer a meta-framework unless you need full control

Quick Summary

  • middlewareMode + appType: 'custom' — DIY server
  • ssrLoadModule() — run server entry in dev
  • vite build --ssr — server bundle
  • ssr.noExternal — bundle problem deps
