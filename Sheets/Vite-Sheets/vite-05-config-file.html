Config File Basics

vite.config.ts · defineConfig · ({ command, mode }) · async config · mergeConfig · --configLoader

vite.config.ts

Vite looks for vite.config.{js,mjs,ts,mts,cjs,cts} in the project root. Export an object wrapped in defineConfig() for type hints, or a function that receives { command, mode, isSsrBuild, isPreview } to change settings per command. The config file runs in Node, so it can read files, env vars and other modules.

Notes

  • TS config works with no extra setup
  • Config may be async (return a Promise)
  • import.meta.env is not available in the config — use loadEnv
  • Changing the config restarts the dev server automatically

Object and Function Forms

import { defineConfig, mergeConfig } from 'vite'
import react from '@vitejs/plugin-react'
import base from './vite.base.config'

export default defineConfig(({ command, mode, isSsrBuild }) => {
  const shared = { plugins: [react()] }
  if (command === 'serve') {
    return mergeConfig(base, { ...shared, server: { port: 3000 } })
  }
  return mergeConfig(base, {
    ...shared,
    base: mode === 'staging' ? '/staging/' : '/',
    build: { sourcemap: isSsrBuild ? false : 'hidden' },
  })
})

Code Explained

defineConfig — type help only; returns its argument
command — 'serve' (dev) or 'build' (build and preview)
mode — 'development', 'production' or --mode value
isSsrBuild / isPreview — narrow build and preview cases
mergeConfig(a, b) — deep merge; arrays concatenate

Config Function Argument

FieldValues
command'serve' | 'build'
mode'development' | 'production' | custom
isSsrBuildtrue during vite build --ssr

⚠ Common Mistakes

  • Reading import.meta.env.VITE_X in the config — it's undefined there; call loadEnv(mode, process.cwd())
  • Spreading two configs with ... — nested keys like server get replaced, not merged; use mergeConfig
  • Passing a function to mergeConfig — it only accepts objects; resolve the function first
  • Using __dirname in an ESM config without defining it — use import.meta.dirname (Node 20.11+)

✓ Tips & Best Practices

  • Always wrap the export in defineConfig for autocomplete
  • Branch on command rather than mode for dev-vs-build differences
  • Keep shared settings in a base file and mergeConfig per environment
  • Use fileURLToPath(new URL('./src', import.meta.url)) for portable paths

Quick Summary

  • defineConfig({...}) — typed config object
  • defineConfig(({ command, mode }) => ...) — conditional
  • mergeConfig(a, b) — deep merge configs
  • loadEnv() — env vars inside the config
