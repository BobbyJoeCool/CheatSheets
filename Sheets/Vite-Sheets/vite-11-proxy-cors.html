Sheet 11

Proxy, CORS & Headers

server.proxy · changeOrigin · rewrite · ws · server.cors · server.headers

Dev Proxy

server.proxy forwards matching requests from the dev server to another backend, so your front end can call /api/... on the same origin and skip CORS entirely during development. Keys are path prefixes, or regexes when they start with ^. For the opposite case (another site calling Vite) use server.cors.

Notes

  • The proxy exists only in vite and vite preview, not in your build
  • Production needs the same routing in your real server or CDN
  • preview.proxy defaults to server.proxy
  • Vite's default CORS only allows localhost origins

Proxy Patterns

export default defineConfig({
  server: {
    proxy: {
      '/api': 'http://localhost:8080',                 // shorthand
      '/auth': {
        target: 'https://auth.example.com',
        changeOrigin: true,                            // Host → target
      },
      '/v2': {
        target: 'http://localhost:9000',
        rewrite: (path) => path.replace(/^\/v2/, ''),   // /v2/x → /x
      },
      '/socket.io': { target: 'ws://localhost:5174', ws: true },
    },
    cors: { origin: 'https://app.example.com' },
    headers: { 'Cross-Origin-Opener-Policy': 'same-origin' },
  },
})

Code Explained

String value — target for that prefix, path kept
changeOrigin — rewrites the Host header for vhosts
rewrite — change the path before forwarding
Keys starting with ^ are treated as regexes
ws: true — proxy WebSocket upgrades too

⚠ Common Mistakes

  • Forgetting changeOrigin: true for name-based hosts — the backend sees localhost and returns 404
  • Writing the rewrite regex without the ^ anchor and stripping /api from the middle of paths
  • Shipping code that relies on the proxy — production requests hit your static host and 404
  • Setting cors: true while the dev server is exposed with --host — any site can read your dev files

✓ Tips & Best Practices

  • Keep API calls relative (/api/users) so the same code works behind a production reverse proxy
  • Log proxy traffic with configure: (proxy) => proxy.on('proxyReq', ...)
  • Set COOP/COEP headers in server.headers to test SharedArrayBuffer locally
  • Use a regex key to proxy everything except Vite's own paths

Quick Summary

  • server.proxy['/api'] — forward to a backend
  • changeOrigin / rewrite / ws — key options
  • server.cors — who may call the dev server
  • server.headers — extra response headers
