Browser Support & Legacy Builds

'baseline-widely-available' · build.target · @vitejs/plugin-legacy · modulePreload polyfill · no ES5 output

Which Browsers

Vite outputs modern JavaScript for browsers that support native ES modules, dynamic import and import.meta. The default build.target is 'baseline-widely-available': features available across major browsers for at least 30 months. Vite 8 raised that floor. For older browsers, @vitejs/plugin-legacy adds a second, polyfilled build loaded with nomodule.

Notes

  • Vite only transforms syntax; it doesn't add polyfills
  • Use 'esnext' for the smallest output on modern-only apps
  • Passing the same browser twice in target now errors
  • Vite 8: plugin-legacy can't output ES5 or lower

Targets and the Legacy Plugin

import legacy from '@vitejs/plugin-legacy'

export default defineConfig({
  build: {
    target: ['chrome111', 'edge111', 'firefox114', 'safari16.4'],
    // target: 'esnext',            // newest syntax only
    cssTarget: 'chrome111',
    modulePreload: { polyfill: true },
  },
  plugins: [
    legacy({
      targets: ['defaults', 'not dead'],   // browserslist query
      modernPolyfills: true,               // polyfill modern build too
    }),
  ],
})

Code Explained

target array — explicit browser versions
'esnext' — no syntax lowering at all
cssTarget — separate floor for CSS
legacy({ targets }) — extra nomodule bundle + polyfills
modernPolyfills — core-js polyfills for the modern chunks

⚠ Common Mistakes

  • Expecting target: 'es2017' to add Array.prototype.at — targets lower syntax only; polyfills need plugin-legacy or core-js
  • Adding plugin-legacy for an internal app on evergreen browsers — doubles build time for nothing
  • Listing chrome100 and chrome111 together in target — Vite 8 throws an error
  • Upgrading to Vite 8 without noticing the raised baseline (Safari 16.0–16.3 users)

✓ Tips & Best Practices

  • Check real visitor browsers in analytics before choosing a target
  • Keep one browserslist in package.json and reuse it for legacy and CSS
  • Use 'esnext' for Electron and Tauri apps with a known engine
  • Test the legacy build in a real old browser via BrowserStack or similar

Quick Summary

  • build.target — JS syntax floor
  • 'baseline-widely-available' — Vite default
  • @vitejs/plugin-legacy — nomodule fallback build
  • Syntax lowering ≠ polyfills
