Flaky Tests

Tests That Pass and Fail Without a Code Change

A flaky test gives different results on the same code. Flakes destroy trust: people rerun CI until green and stop reading failures. Common causes: timing (sleeps, races, animations), order dependence and shared state, real network or time, and resource limits in CI. Detect them by rerunning and randomizing order, quarantine known flakes so they don't block others, then fix or delete them.

Notes

  • Retries hide flakes; if you use them, report retried tests
  • Run a suspect test many times in a loop to reproduce
  • Randomized order exposes hidden dependencies
  • Quarantine needs an owner and a deadline

Interview Angle

  • Q: "How do you handle flaky tests?" Find the root cause; quarantine with an owner; never just add retries
  • List causes: timing, order, shared state, network, time zones
  • Mention tooling: rerun loops, random order, CI flake reports

Finding and Fixing a Flake

# 1. reproduce
run test "search shows results" 200 times → 3 failures

# 2. look for the cause
failure trace: clicked "Search" before the input was enabled
# cause: timing — test acted before the page was ready

# 3. fix the cause, not the symptom
# ✗ sleep(2) then click
# ✓ wait for the condition
expect(by_role("textbox", name="Search")).enabled
click(by_role("button", name="Search"))

# order dependence: passes alone, fails in the suite
run suite with random order, seed=8812 → fails
# cause: test A leaves a feature flag on; test B assumes off
# fix: reset flags in per-test setup

# quarantine while fixing
mark test "imports nightly file" as quarantined(owner="bob", issue=#311, until="2026-11-30")

Code Explained

Running a test hundreds of times turns "sometimes" into evidence
Traces and screenshots show what the page looked like at failure
The real fix waits for a condition instead of a fixed time
A fixed random seed reproduces an order-dependent failure

  • You see a global "retry 3 times" setting → it means flakes are hidden, not fixed → do report retried tests and fix them
  • You see "just rerun CI" in team chat → it means red no longer means broken → do track flake rate and quarantine with owners

Causes and Fixes

CauseFix
Fixed sleeps / racesWait for conditions; await properly
Order dependenceFresh state per test; random order
Shared data / files / portsUnique per test or worker
Real time / time zonesFixed clock; explicit zone
Real networkFake at the boundary
CI resource limitsFewer workers; longer timeouts only as last resort
Animations / async UIDisable animations; web-first assertions

Flake Policy

StepRule
DetectTrack retried / intermittent tests in CI
QuarantineSkip in required job, with owner + issue
FixRoot cause, not a longer timeout
DeadlineFix or delete within a set time
ReportFlake rate per week

⚠ Common Mistakes

  • Adding sleeps to "fix" timing flakes
  • Raising timeouts until the flake goes away
  • Quarantining tests forever with no owner

✓ Tips & Best Practices

  • Track a flake rate per test in CI
  • Reproduce with the same seed, worker count and machine size as CI
  • Delete a flaky test that tests nothing important; it's cheaper than living with it

Quick Summary

  • flaky — same code, different results
  • causes — timing, order, shared state, network, time
  • quarantine with owner + deadline
  • retries hide; root cause fixes
