Security Testing Basics

SAST · DAST · SCA / dependency scanning · secrets scanning · OWASP ZAP · security tests for auth rules

Find Vulnerabilities Before Attackers Do

Security testing combines automated scanners with your own tests. SAST analyzes source code for risky patterns; SCA finds known vulnerabilities in dependencies; secrets scanning catches committed keys; DAST attacks a running app from outside (OWASP ZAP). Just as important are your own tests for authorization rules: user A can't read user B's data, roles are enforced, input is validated.

Notes

  • Run SCA and secrets scanning on every PR
  • Most real breaches are authorization bugs scanners can't understand
  • Tie tests to the OWASP Top 10 categories
  • Penetration tests by specialists still matter for high-risk apps

Authorization Tests + Scanners

# your tests: the rules only you know
test "a customer can't read another customer's order":
    res = client.get("/orders/" + bob_order.id, auth=token("ann"))
    assert res.status == 404                          # don't reveal it exists

test "price can't be set by the client":
    res = client.post("/orders", json={ sku: "A1", qty: 1, price: 0.01 }, auth=token("ann"))
    assert db.orders.find(res.body.id).price == catalog_price("A1")

test "search input is not executed as SQL":
    res = client.get("/search?q=' OR 1=1 --", auth=token("ann"))
    assert res.status == 200 and res.body.results == []

# pipeline scanners
pr:       secrets scan · dependency scan (SCA) · SAST
nightly:  DAST baseline scan against staging (OWASP ZAP)

Code Explained

Broken object-level authorization is a top API risk; test it directly
Mass-assignment tests check that clients can't set server-owned fields
Injection tests send hostile input and check it is treated as data
Scanners cover known patterns and vulnerable libraries automatically

Smell Check

  • You see only scanner results in the security review → it means authorization logic is untested → do write tests for who can access what
  • You see dependency alerts piling up unread → it means alert fatigue → do auto-update and fail builds on critical issues

⚠ Common Mistakes

  • Relying only on scanners for security
  • Testing authorization with an admin account only
  • Ignoring dependency alerts until an audit

✓ Tips & Best Practices

  • Write an access-control test for every new endpoint
  • Fail CI on committed secrets
  • Keep dependencies updated automatically with review
