Snapshot & Approval Testing

snapshot files · approval testing · reviewing diffs · when snapshots rot · inline snapshots · golden master

Compare Against a Reviewed Output

A snapshot (or approval) test serializes an output and compares it with a stored, reviewed copy. It's cheap to write for large outputs: rendered HTML, reports, generated code, CLI text. Its weakness is review: when output changes, someone must read the diff before accepting it, or the test turns into "update until green". Keep snapshots small and stable.

Notes

  • Commit snapshot files and review their diffs in PRs
  • Normalize volatile values (dates, IDs) before snapshotting
  • Inline snapshots keep small outputs in the test itself
  • Golden master testing pins legacy behavior (sheet 35)

Snapshot Workflow

test "invoice renders":
    html = render_invoice(sample_order())
    assert html matches snapshot          # first run: writes invoice.snap

# later, someone changes the template →
#   FAIL invoice renders
#   - <td>Total</td><td>$45.00</td>
#   + <td>Total due</td><td>$45.00</td>
# reviewer reads the diff → intended? accept with --update

test "order JSON shape":
    data = to_json(make_order())
    data = normalize(data, id="<id>", created_at="<date>")
    assert data matches snapshot

test "CLI help text":
    assert run_cli(["--help"]).stdout matches inline_snapshot("""
        Usage: orders [OPTIONS] COMMAND
        ...
    """)

Code Explained

The diff shows exactly what changed in the output
Accepting rewrites the stored snapshot; that's a deliberate, reviewed act
Normalizing volatile fields keeps snapshots stable
Inline snapshots are reviewed in the test file itself

Smell Check

  • You see PRs that update 40 snapshot files with no comment → it means nobody reviews them → do keep snapshots small and require diff review
  • You see snapshots failing every run on timestamps → it means volatile data → do normalize or freeze it

⚠ Common Mistakes

  • Updating snapshots to make CI green without reading the diff
  • Snapshotting entire pages or component trees
  • Snapshots containing secrets or personal data

✓ Tips & Best Practices

  • Prefer explicit assertions for the few facts that matter
  • Review snapshot diffs like code
  • Delete obsolete snapshots regularly

Quick Summary

  • snapshot — stored, reviewed output
  • diff review is the real test
  • normalize volatile values
  • small and stable beats big and noisy
