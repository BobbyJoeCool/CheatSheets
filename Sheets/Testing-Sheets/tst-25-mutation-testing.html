Mutation Testing

Testing Your Tests

Mutation testing makes small changes to your code (mutants): flips > to >=, deletes a line, replaces true with false. Then it runs your tests. If a test fails, the mutant is killed; if all pass, it survived, which means no test notices that change. The mutation score (killed ÷ total) measures how well tests check behavior, which coverage can't.

Notes

  • Expensive: the suite runs once per mutant; scope it to changed code
  • Some surviving mutants are equivalent (no behavior change); ignore those
  • Incremental modes reuse previous results
  • Read survivors to find missing assertions

Interview Angle

  • Q: "Is 100% coverage a good goal?" — no; coverage shows lines ran, not that tests check them
  • Mutation score is a better signal of test strength
  • Example: a test that calls a function but asserts nothing gives 100% coverage and kills no mutants

A Surviving Mutant

function shipping_fee(total):
    if total >= 50.00: return 0.00
    return 5.99

test "orders over $50 ship free":   assert shipping_fee(80.00) == 0.00
test "small orders pay shipping":   assert shipping_fee(10.00) == 5.99
# coverage: 100%

# mutant 1:  total >= 50.00  →  total > 50.00
#   both tests still pass  → SURVIVED
# mutant 2:  return 5.99  →  return 0.00
#   "small orders" fails   → KILLED

# fix: test the boundary
test "exactly $50 ships free":      assert shipping_fee(50.00) == 0.00
# mutant 1 now KILLED

# mutation score: 2 killed / 2 = 100%

Code Explained

Line coverage was already 100% but the boundary wasn't tested
The surviving mutant points to the exact missing test
Boundary values are where most survivors hide
Run it on changed files in PRs, the whole code base occasionally

In Your Stack

Smell Check

  • You see high coverage but many surviving mutants → it means tests run code without checking results → do add assertions on outputs and boundaries
  • You see mutation runs taking hours in every PR → it means no scoping → do run incrementally on changed files

Results

ResultMeans
KilledA test failed: good
SurvivedNo test noticed: missing check
No coverageNo test ran that code
TimeoutMutant caused a hang (counts as killed)
EquivalentChange doesn't alter behavior: ignore

⚠ Common Mistakes

  • Chasing 100% mutation score including equivalent mutants
  • Running full mutation testing on every commit
  • Ignoring survivors because coverage looks fine

✓ Tips & Best Practices

  • Start with your most critical module
  • Use survivors as a to-do list of missing assertions
  • Combine with coverage: coverage finds untested code, mutation finds weakly tested code

Quick Summary

  • mutant — small code change
  • killed = a test noticed · survived = none did
  • mutation score — test strength
  • scope to changed code; it's expensive
