Sheet 31

Test Reports & Failure Triage

JUnit XML · artifacts (traces · screenshots · logs) · reading a CI failure · reproduce locally · rerun only failed

From Red Build to Root Cause

When CI fails, you need the what (which test, which assertion), the where (environment, commit, shard) and the why (logs, traces, screenshots). JUnit XML is the common report format CI systems display. Save artifacts on failure: logs, Playwright traces, screenshots, coverage. Then reproduce locally with the same seed and command, and rerun only what failed.

Notes

  • Upload artifacts with "always" / "on failure" conditions
  • Print the random seed and environment in the log header
  • Annotations put failures on the PR's changed lines
  • Triage first: is it the code, the test, or the environment?

Triage Steps

CI ✗ unit-tests (shard 2/4)

1. read the report, not the raw log
   FAILED tests/test_refunds.py::test_partial_refund
   assert 45.0 == 44.99
   seed: 8812   python 3.13   commit a1b2c3

2. classify
   code bug?        → recent change touched refunds.py   ← likely
   test bug?        → expectation still right?
   environment?     → only on CI? only on one shard?

3. reproduce locally with the same inputs
   run tests/test_refunds.py::test_partial_refund --seed 8812

4. E2E failure? open the trace artifact
   trace.zip → timeline, DOM snapshots, network, console

5. fix, push, rerun failed first
   rerun --last-failed → green → full run

Code Explained

The test report names the test, the assertion and the values
Classifying first stops people from "fixing" a test that caught a real bug
The same seed and command reproduce the CI run
Traces show exactly what the browser saw at each step

In Your Stack

Smell Check

  • You see people rerunning failed builds without looking → it means failures are noise → do require a triage note for reruns
  • You see E2E failures with only "timeout" in the log → it means missing artifacts → do save traces and screenshots on failure

Is It the Code, Test or Environment?

CluePoints to
Fails locally with same seedCode or test
Only fails on CIEnvironment, resources, timing
Only one shard / workerShared state or order
Started after a dependency bumpLibrary change
IntermittentFlaky (sheet 22)

⚠ Common Mistakes

  • Reading thousands of log lines instead of the test report
  • Not saving artifacts, then being unable to reproduce
  • Changing the test to match the new (wrong) behavior

✓ Tips & Best Practices

  • Put the seed, versions and commit at the top of every test log
  • Turn on PR annotations for failing lines
  • Write the triage outcome in the PR or issue

Quick Summary

  • JUnit XML — the report CI reads
  • artifacts — logs, traces, screenshots
  • classify: code, test or environment
  • reproduce with the same seed and command
