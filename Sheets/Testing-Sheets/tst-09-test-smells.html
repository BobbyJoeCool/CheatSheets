Sheet 09

Test Smells

fragile tests · slow tests · mystery guest · logic in tests · eager test · over-specification · shared mutable state

Signs a Test Suite Is Getting Sick

A test smell is a pattern that makes tests hard to trust, read or maintain. Fragile tests break on harmless refactors; slow tests stop people running them; a mystery guest depends on data you can't see in the test; logic in tests (ifs, loops) hides what ran; an eager test checks too many behaviors; over-specification asserts details nobody cares about; shared mutable state makes order matter.

Notes

  • Smells are hints, not rules; judge the cost
  • Every Smell Check box in this set is a smell tied to that topic
  • Lint rules catch some smells automatically
  • Fix smells when you touch a test; don't schedule a rewrite

Interview Angle

  • Q: "How do you spot a bad test?" Name two or three smells with a fix each
  • Fragile (coupled to implementation) and flaky (non-deterministic) are the two interviewers expect
  • Mention that a test which can't fail is the worst smell of all

Smells and Fixes

# MYSTERY GUEST — where does user 42 come from?
test "admin sees reports":   assert can_view(load_user(42), "reports")
# fix: build it here
test "admin sees reports":   assert can_view(make_user(role="admin"), "reports")

# LOGIC IN TEST — which branch ran?
test "discounts":
    for code in codes:
        if code.startswith("VIP"): assert apply(code) < 0.8
        else:                      assert apply(code) == 0.9
# fix: parameterized cases with explicit expectations (sheet 05)

# OVER-SPECIFICATION — asserts every call
verify(repo).open(); verify(repo).begin(); verify(repo).save(o); verify(repo).commit()
# fix: assert the outcome
assert repo.find(o.id) == o

# THE TEST THAT CAN'T FAIL
test "sends email":
    try: send_welcome(user)
    except: pass                       # swallows every failure

Code Explained

Building the admin in the test makes the dependency visible
Loops and ifs mean nobody knows which case broke
Verifying every internal call breaks whenever the implementation changes
A swallowed exception makes the test pass no matter what

Smell Check

  • You see a test that passed when you deleted the code under test → it means it can't fail → do break the code on purpose and watch it go red
  • You see tests that only fail in the full run → it means shared mutable state → do isolate setup per test

⚠ Common Mistakes

  • Rewriting the whole suite instead of fixing smells as you go
  • Adding retries to hide flakiness
  • Ignoring smells in tests because "it's only test code"

✓ Tips & Best Practices

  • Review test code as carefully as production code
  • Break the code on purpose before trusting a new test
  • Track slow and flaky tests in CI reports

Quick Summary

  • fragile / flaky / slow — trust killers
  • mystery guest — hidden data
  • logic in tests — hidden paths
  • can't-fail tests — the worst smell
