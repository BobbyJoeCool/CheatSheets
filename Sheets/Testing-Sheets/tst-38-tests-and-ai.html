Tests Keep AI-Written Code Honest

AI coding agents write code quickly, and a good test suite is how you know it's right. Tests act as the spec: give the agent failing tests and let it make them pass. Review generated tests carefully: agents can write tests that mirror the implementation, assert nothing meaningful, or get "fixed" by weakening assertions. Keep CI guardrails (required checks, coverage on changed code, mutation testing) on for every change. The Agentic Coding set covers the tools.

Notes

  • Ask for tests first, review them, then ask for the implementation
  • Watch for agents editing tests to make them pass
  • Run the full suite on agent changes, not just new tests
  • Playwright test agents can plan, generate and heal E2E tests

A Test-First Prompt Loop

# 1. you write (or approve) the failing tests — the spec
test "SAVE10 takes 10% off orders over $20"
test "SAVE10 is rejected under $20 with COUPON_MIN_TOTAL"
test "coupons can't be stacked"

# 2. prompt the agent
"Make the three failing tests in test_coupons.py pass.
 Don't modify the tests. Keep changes inside checkout/coupons.py.
 Run the full test suite before finishing."

# 3. review the diff — warning signs
- test files changed                    → reject unless asked
- assertions loosened (== → >=)         → reject
- new tests that copy the implementation's math → rewrite
- mocks of the code under test          → rewrite

# 4. guardrails in CI
required: full suite · coverage on changed lines ≥ 80%
nightly:  mutation testing on changed modules

Code Explained

Human-reviewed tests define "done" before any code exists
Explicit constraints stop the agent from editing tests to pass
Diff review focuses on test changes first
CI checks apply to agent changes exactly as to human ones

Smell Check

  • You see an AI change that also edited the failing tests → it means tests were bent to the code → do revert test edits and rerun
  • You see generated tests with no failing-first step → it means they may pass for the wrong reason → do break the code and confirm they fail

⚠ Common Mistakes

  • Accepting agent-written tests without seeing them fail
  • Letting an agent "fix" failures by editing assertions
  • Running only the new tests on agent changes

✓ Tips & Best Practices

  • Write the test names yourself; let the agent fill in bodies, then review
  • Tell the agent which files it may not change
  • Use mutation testing on modules agents changed most

Quick Summary

  • tests are the spec for agents

  • watch for loosened assertions
