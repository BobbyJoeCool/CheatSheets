Sheet 05

Imperative vs Declarative

create · run · expose · apply -f · diff · --dry-run=client -o yaml · edit / patch · --server-side

Two Ways to Change a Cluster

Imperative commands (run, create, scale, set) say do this now: quick, but unrecorded. Declarative management keeps manifests in Git and runs kubectl apply, which creates or updates objects to match the files. Best of both: generate YAML with --dry-run=client -o yaml, then apply it.

Notes

  • apply is idempotent; a second run changes nothing
  • create -f fails if the object exists
  • edit, patch, scale drift from Git
  • Server-side apply records a field manager per field
  • replace --force deletes and recreates (immutable fields)

Imperative → Declarative

kubectl run tmp --image=busybox:1.36 --rm -it --restart=Never -- sh
kubectl create deployment web --image=nginx:1.27 --replicas=2
kubectl expose deployment web --port=80 --target-port=8080
kubectl set image deployment/web nginx=nginx:1.28
kubectl create deploy web --image=nginx:1.27 --dry-run=client -o yaml > web.yaml
kubectl apply -f web.yaml               # create or update
kubectl apply -f k8s/ -R                # whole folder
kubectl diff -f web.yaml                # preview changes
kubectl apply -f web.yaml --server-side --field-manager=ci
kubectl edit deployment web             # live object in $EDITOR
kubectl patch deployment web -p '{"spec":{"replicas":3}}'
kubectl delete -f web.yaml              # remove what it defines

Code Explained

--rm -it --restart=Never — interactive, deleted on exit
--dry-run=client -o yaml — prints YAML, creates nothing
diff — exits 1 when there are changes; a CI gate
--server-side — API server merges and tracks field owners
patch -p — strategic merge by default
edit — saved on exit; invalid YAML reopens the editor
delete -f — deletes only objects named in the file

⚠ Common Mistakes

  • Hotfixing with edit — the next apply reverts it
  • create -f in CI — reruns fail with AlreadyExists
  • Expecting apply to delete objects removed from Git
  • Hand-writing YAML from memory — generate it to avoid typos

✓ Tips & Best Practices

  • Run kubectl diff before applying to shared clusters
  • --dry-run=server catches policy rejections early
  • Copy any live hotfix back into Git right away
  • Name the --field-manager per tool in CI

Quick Summary

  • create / run / expose — imperative
  • apply -f — declarative, idempotent
  • --dry-run=client -o yaml — make YAML
  • diff — preview; edit / patch — live drift
