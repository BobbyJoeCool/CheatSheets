Services & DNS

ClusterIP · NodePort · LoadBalancer · ExternalName · port vs targetPort · EndpointSlices · CoreDNS

A Stable Address for Changing Pods

Pods come and go with new IPs; a Service gives a set of pods (chosen by label selector) one stable virtual IP and DNS name and load-balances across the Ready ones. kube-proxy (or the CNI) programs the routing on every node. CoreDNS answers <svc>.<ns>.svc.cluster.local.

Notes

  • Selector matches nothing → Service exists but has no endpoints
  • Pods in the same namespace can just use the short name: http://web
  • EndpointSlices list the backing pod IPs; the old Endpoints API is deprecated

Service

apiVersion: v1
kind: Service
metadata: { name: web, namespace: shop }
spec:
  type: ClusterIP                # default; see types table
  selector: { app: web }         # pods that get traffic
  ports:
    - name: http
      port: 80                   # what clients connect to
      targetPort: http           # container port (number or name)

Check It

kubectl get svc,endpointslices -n shop -l app=web
kubectl port-forward svc/web 8080:80 -n shop     # http://localhost:8080

Code Explained

selector — must match pod labels, not Deployment labels
port vs targetPort — Service side vs container side
nodePort — set only for NodePort/LoadBalancer (30000–32767)
endpointslices — empty means selector or readiness problem

⚠ Common Mistakes

  • Selector copied from the Deployment's metadata labels instead of pod template labels
  • targetPort not matching the container's listening port — connection refused
  • One LoadBalancer Service per app — costly; share an Ingress/Gateway

✓ Tips & Best Practices

  • Name ports and use targetPort: http so port changes live in one place
  • kubectl get endpointslices first when a Service "doesn't work"
  • port-forward for local testing; no Service type change needed

Quick Summary

  • Service — stable IP + DNS over Ready pods
  • ClusterIP / NodePort / LoadBalancer — widening reach
  • port → targetPort — client side → container side
  • svc.ns.svc.cluster.local — CoreDNS name
