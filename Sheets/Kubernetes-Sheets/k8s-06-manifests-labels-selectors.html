Manifests, Labels & Selectors

apiVersion / kind / metadata / spec · --- · labels · selectors · annotations · app.kubernetes.io/*

Anatomy of a Manifest

Every object has apiVersion, kind, metadata and spec (what you want); Kubernetes adds status (what it has). Labels are key/value tags that selectors match: that's how a Service finds its Pods and a Deployment knows which Pods it owns. Annotations hold non-identifying data for tools.

Notes

  • Core kinds use v1; others group/version
  • Label values ≤ 63 chars: letters, digits, - _ .
  • Annotations can hold any string, up to 256 KB total
  • Keys may carry a DNS prefix: app.kubernetes.io/name

A Labeled Manifest

apiVersion: apps/v1              # group/version
kind: Deployment
metadata:
  name: web                      # unique per kind + namespace
  namespace: shop
  labels:                        # identifying, selectable
    app.kubernetes.io/name: web
    tier: frontend
  annotations:                   # free-form, for tools
    team: storefront@acme.io
spec:
  selector:                      # which pods it owns
    matchLabels: { app.kubernetes.io/name: web }
    matchExpressions:
      - { key: tier, operator: In, values: [frontend, edge] }
  template: { ... }              # pod template (Sheet 08)
---                              # next object, same file

Code Explained

apiVersion — look it up in api-resources
matchLabels — every pair must match
operator — In, NotIn, Exists, DoesNotExist
--- — separates documents in one file
labels on metadata — lets get -l find the Deployment
{ ... } — YAML flow style, same as indented maps

⚠ Common Mistakes

  • Selector ≠ template labels — the API rejects the Deployment
  • Editing a Deployment selector — it's immutable; recreate instead
  • Two Deployments with overlapping selectors fight over Pods
  • Putting URLs or long text in labels — values are limited to 63 chars

✓ Tips & Best Practices

  • Use the app.kubernetes.io/* labels; tools understand them
  • Keep selectors small and stable
  • Data goes in annotations, not labels
  • get pods -L app.kubernetes.io/version shows versions at a glance

Quick Summary
