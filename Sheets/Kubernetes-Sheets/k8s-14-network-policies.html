Network Policies

default deny · podSelector · namespaceSelector · ingress / egress · ipBlock · ports · CNI

A Firewall for Pods

By default every pod can reach every other pod in the cluster. A NetworkPolicy selects pods and lists the traffic allowed in (ingress) or out (egress). Once any policy selects a pod for a direction, everything not explicitly allowed in that direction is denied. Policies only add allows, so their order doesn't matter.

Notes

  • Enforced by the CNI plugin; without support, policies are silently ignored
  • Selects by labels, namespaces and CIDRs, at L3/L4 (no HTTP paths)
  • Replies to allowed connections are allowed automatically
  • Deny egress → remember to allow DNS (port 53 to kube-system)

Default Deny + Allow

apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: { name: default-deny, namespace: shop }
spec:
  podSelector: {}                  # every pod in the namespace
  policyTypes: [Ingress, Egress]   # nothing in or out by default
---
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: { name: api-from-web, namespace: shop }
spec:
  podSelector: { matchLabels: { app: api } }    # applies to api pods
  ingress:
    - from:
        - podSelector: { matchLabels: { app: web } }       # this ns
        - namespaceSelector: { matchLabels: { team: ops } } # OR these
      ports: [{ protocol: TCP, port: 8080 }]

Code Explained

podSelector: {} — empty selector = all pods
policyTypes — directions isolated; defaults from the rules present
from: list items — OR'ed together
podSelector alone — same namespace as the policy
ports — applies to every from above it

AND vs OR

ShapeMeaning
-podSel / -nsSelTwo items: OR
-nsSel + podSelOne item: AND
-ipBlock: {cidr}IP ranges (+ except)

⚠ Common Mistakes

  • Applying policies on a CNI that doesn't enforce them — false sense of security
  • Default-deny egress without a DNS rule — every lookup times out
  • One extra - turns AND into OR and opens access
  • Using namespaceSelector on a label the namespace lacks

✓ Tips & Best Practices

  • Select namespaces by the built-in kubernetes.io/metadata.name label
  • Start with default-deny per namespace, then add allows
  • Test with kubectl exec … -- nc -zv api 8080
  • Hubble (Cilium) or Calico flow logs show dropped traffic

Quick Summary

  • NetworkPolicy — allow-list per pod selector
  • podSelector: {} + no rules — default deny
  • list items OR, keys in one item AND
  • CNI must support it
