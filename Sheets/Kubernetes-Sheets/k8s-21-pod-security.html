Pod Security

securityContext · runAsNonRoot · readOnlyRootFilesystem · drop ALL · allowPrivilegeEscalation · seccomp · Pod Security Admission

Locking Down Containers

A container's securityContext controls the Linux user, capabilities, privilege escalation, seccomp profile and file-system writes. Pod Security Admission (built in) checks pods against the Pod Security Standards: privileged, baseline or restricted, chosen per namespace with labels. It replaced PodSecurityPolicy, removed in 1.25.

Notes

  • Pod-level securityContext sets defaults; container-level wins
  • runAsNonRoot fails pods whose image runs as UID 0
  • Need custom rules? Use Kyverno or OPA Gatekeeper

Restricted Namespace + Hardened Pod

apiVersion: v1
kind: Namespace
metadata:
  name: shop
  labels:
    pod-security.kubernetes.io/enforce: restricted   # reject violators
    pod-security.kubernetes.io/warn: restricted      # warn on apply
---
spec:                                  # pod spec
  securityContext:
    runAsNonRoot: true
    runAsUser: 10001
    fsGroup: 10001                     # group owning mounted volumes
    seccompProfile: { type: RuntimeDefault }
  containers:
    - name: api
      securityContext:
        allowPrivilegeEscalation: false
        readOnlyRootFilesystem: true
        capabilities: { drop: [ALL] }

Code Explained

enforce — rejected at the API; warn — shown to kubectl
runAsUser: 10001 — avoid UIDs that exist on the host
RuntimeDefault — the runtime's default syscall filter
readOnlyRootFilesystem — mount an emptyDir for /tmp
drop: [ALL] — add back only e.g. NET_BIND_SERVICE

⚠ Common Mistakes

  • Enforcing restricted on kube-system — breaks CNI and CSI pods
  • readOnlyRootFilesystem without a writable /tmp — app crashes
  • Images built to run as root — runAsNonRoot blocks them
  • Assuming PSA blocks everything bad — it only checks pod fields

✓ Tips & Best Practices

  • Roll out with warn + audit first, then enforce
  • kubectl label --dry-run=server ns shop pod-security…=restricted lists violators
  • Set USER 10001 in your Dockerfile
  • kubectl debug profiles help keep debug pods compliant

Quick Summary

  • securityContext — user, caps, seccomp
