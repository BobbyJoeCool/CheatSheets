Sheet 03

kubeconfig, Contexts & Namespaces

~/.kube/config · KUBECONFIG · use-context · set-context --namespace · kubectx / kubens

Where kubectl Points

kubeconfig (~/.kube/config) holds clusters (API URL + CA), users (credentials) and contexts (cluster + user + default namespace). The current-context decides where every command goes. Namespaces split one cluster into named areas; names only need to be unique within one.

Notes

  • Without -n, commands use the context's namespace, else default
  • Nodes, PVs and Namespaces are cluster-scoped
  • kubeconfig holds credentials: chmod 600
  • KUBECONFIG can list several files; kubectl merges them

Contexts & Namespaces

kubectl config get-contexts            # * marks the current one
kubectl config current-context         # kind-dev
kubectl config use-context prod-east   # switch cluster + user
kubectl config set-context --current --namespace=shop
kubectl config view --minify           # active context only
kubectl config delete-context old-lab
export KUBECONFIG=~/.kube/config:~/.kube/eks.yaml   # merge
kubectl config view --flatten > ~/.kube/merged      # one file
kubectl --context prod-east -n shop get pods        # one-off
kubectl create namespace shop
kubectl delete namespace shop          # deletes EVERYTHING in it

Code Explained

use-context — rewrites the file; affects every terminal
--current --namespace — default ns for this context
KUBECONFIG — : separator (; on Windows)
--flatten — inlines certs so the file stands alone
--context — safest choice in scripts
delete namespace — waits for every object inside to finalize
view — redacts secrets; add --raw to show them

⚠ Common Mistakes

  • Deleting in the wrong cluster — check current-context first
  • delete namespace as cleanup — removes PVCs and all
  • Treating namespaces as network isolation — they aren't (Sheet 14)
  • Committing kubeconfig to Git — it often holds long-lived tokens

✓ Tips & Best Practices

  • Show context + namespace in your prompt (kube-ps1, starship)
  • Name contexts by environment: dev, prod-east
  • Pass --context explicitly in CI scripts
  • One namespace per app or team per environment

Quick Summary

  • get-contexts / use-context — list / switch
  • set-context --current --namespace
  • -n one ns · -A all namespaces
  • KUBECONFIG=a:b — merge several files
