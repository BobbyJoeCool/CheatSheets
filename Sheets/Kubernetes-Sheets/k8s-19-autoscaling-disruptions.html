Autoscaling & Disruption Budgets

HorizontalPodAutoscaler · kubectl autoscale · metrics-server · VPA · Cluster Autoscaler · Karpenter · PodDisruptionBudget

Scaling Pods and Nodes

The HorizontalPodAutoscaler (HPA) changes a workload's replicas to hold a target metric, usually CPU utilization relative to requests. The VerticalPodAutoscaler adjusts the requests themselves. When pods don't fit, Cluster Autoscaler or Karpenter adds nodes. A PodDisruptionBudget limits how many pods voluntary disruptions (drains, upgrades, scale-down) may take at once.

Notes

  • Resource metrics need metrics-server installed
  • Remove replicas from Git manifests the HPA manages
  • PDBs don't protect against node crashes (involuntary)

HPA + PDB

apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata: { name: web }
spec:
  scaleTargetRef: { apiVersion: apps/v1, kind: Deployment, name: web }
  minReplicas: 2
  maxReplicas: 20
  metrics:
    - type: Resource
      resource:
        name: cpu
        target: { type: Utilization, averageUtilization: 70 }
---
apiVersion: policy/v1
kind: PodDisruptionBudget
metadata: { name: web }
spec:
  minAvailable: 2                   # or maxUnavailable: 1
  selector: { matchLabels: { app: web } }

Code Explained

scaleTargetRef — Deployment, StatefulSet, or any /scale
averageUtilization: 70 — 70% of the CPU request
behavior: — tune scale-up/down speed (default 5 min down window)
minAvailable — drains wait while fewer would remain
selector — same pods as the Deployment
maxReplicas — a cost ceiling; set it deliberately

⚠ Common Mistakes

  • HPA on pods with no CPU requests — target shows <unknown>
  • HPA and VPA both acting on CPU — they fight; use one per resource
  • PDB minAvailable = replicas — drains block forever
  • Expecting instant scale-up — new nodes can take minutes to join

✓ Tips & Best Practices

  • Set minReplicas ≥ 2 for anything user-facing
  • Scale on custom metrics (RPS, queue depth) via adapters or KEDA
  • Run VPA in Off mode to get request recommendations
  • Pair HPA with Cluster Autoscaler or Karpenter so new pods have room

Quick Summary

  • HPA — replicas from metrics
  • Cluster Autoscaler / Karpenter — nodes
  • PDB — cap voluntary disruptions
  • VPA — right-size requests
