RBAC & ServiceAccounts

Role / ClusterRole · RoleBinding / ClusterRoleBinding · verbs · ServiceAccount · create token · auth can-i

Who Can Do What

RBAC answers can subject X do verb Y on resource Z. A Role (namespaced) or ClusterRole lists allowed verbs on resources; a RoleBinding or ClusterRoleBinding grants it to users, groups or ServiceAccounts. ServiceAccounts are identities for pods and automation; humans usually come from your cloud IAM or OIDC.

Notes

  • RBAC is additive: no deny rules, only allows
  • Every namespace has a default ServiceAccount with no extra rights
  • Pod tokens are short-lived and auto-rotated (projected volume)

ServiceAccount, Role, Binding

apiVersion: v1
kind: ServiceAccount
metadata: { name: ci-deployer, namespace: shop }
---
apiVersion: rbac.authorization.k8s.io/v1
kind: Role                          # ClusterRole = cluster-wide
metadata: { name: deployer, namespace: shop }
rules:
  - apiGroups: ["apps"]             # "" = core group (pods, services)
    resources: ["deployments"]
    verbs: ["get", "list", "watch", "patch", "update"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata: { name: ci-deployer, namespace: shop }
subjects: [{ kind: ServiceAccount, name: ci-deployer, namespace: shop }]
roleRef: { kind: Role, name: deployer, apiGroup: rbac.authorization.k8s.io }

Code Explained

apiGroups — from kubectl api-resources APIVERSION
resources — plural names; subresources like pods/log
verbs — see table; * means all
roleRef — immutable; delete and recreate to change
Pod uses it via serviceAccountName: ci-deployer

⚠ Common Mistakes

  • Binding cluster-admin to CI — one leaked token owns the cluster
  • Granting list secrets — returns every secret's contents
  • Pods auto-mounting tokens they never use — set automountServiceAccountToken: false

✓ Tips & Best Practices

  • Test with auth can-i … --as= before handing out access
  • Start from view/edit and add narrow Roles
  • Use cloud workload identity (IRSA, GKE WI) instead of static keys

Quick Summary

  • Role / ClusterRole — what is allowed
  • RoleBinding / ClusterRoleBinding — to whom
  • auth can-i — verify
