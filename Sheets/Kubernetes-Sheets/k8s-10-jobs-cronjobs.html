Jobs & CronJobs

completions · parallelism · backoffLimit · activeDeadlineSeconds · ttlSecondsAfterFinished · schedule · concurrencyPolicy

Run to Completion

A Job runs pods until a set number succeed, retrying failures up to backoffLimit. Use it for migrations, batch processing and one-off tasks. A CronJob creates a Job on a cron schedule, with rules for overlapping runs and how much history to keep.

Notes

  • Job pods need restartPolicy: Never or OnFailure
  • Missed CronJob runs beyond startingDeadlineSeconds are skipped
  • timeZone takes IANA names; otherwise the controller's zone is used

Job

apiVersion: batch/v1
kind: Job
metadata: { name: migrate }
spec:
  completions: 1                 # successes needed
  backoffLimit: 4                # retries before Failed
  activeDeadlineSeconds: 600     # hard time limit for the Job
  ttlSecondsAfterFinished: 3600  # auto-delete 1h after finishing
  template:
    spec:
      restartPolicy: Never
      containers: [{ name: m, image: acme/api:1.4.2, command: ["./migrate"] }]

CronJob

apiVersion: batch/v1
kind: CronJob
metadata: { name: nightly-report }
spec:
  schedule: "30 2 * * *"         # 02:30 every day
  timeZone: America/Chicago
  concurrencyPolicy: Forbid      # skip if last run still going
  jobTemplate: { spec: { template: { ... } } }

Code Explained

completions: 5, parallelism: 2 — 5 successes, 2 at a time
backoffLimit — default 6
activeDeadlineSeconds — beats backoffLimit; kills running pods
ttlSecondsAfterFinished — keeps the namespace tidy
Never — new pod per retry; OnFailure restarts in place
jobTemplate — a full Job spec

⚠ Common Mistakes

  • restartPolicy: Always in a Job — rejected by the API
  • Non-idempotent job code — retries run it twice (double charges, dup emails)

✓ Tips & Best Practices

  • Test a CronJob instantly with create job --from=cronjob/…
  • Use Forbid for jobs that must not overlap
  • completionMode: Indexed gives each pod a JOB_COMPLETION_INDEX

Quick Summary

  • Job — run until N successes
  • backoffLimit / activeDeadlineSeconds — limits
  • CronJob — Job on a schedule
  • concurrencyPolicy — overlap rules
