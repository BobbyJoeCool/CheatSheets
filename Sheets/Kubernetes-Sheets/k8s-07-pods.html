Pods

containers · command / args · env · initContainers · sidecars · phases · restartPolicy · imagePullPolicy

The Smallest Unit

A Pod is one or more containers on one node sharing an IP (talk over localhost) and volumes. Init containers run to completion, in order, before the app. A sidecar is an init container with restartPolicy: Always: it starts first and runs beside the app. Pods are disposable; controllers create them from a template.

Notes

  • Recreated Pods get a new IP; use a Service
  • command = ENTRYPOINT, args = CMD
  • Native sidecars are stable since 1.33
  • Most Pod spec fields are immutable; recreate instead of editing

Pod Spec

apiVersion: v1
kind: Pod
metadata: { name: api, labels: { app: api } }
spec:
  restartPolicy: Always            # Always | OnFailure | Never
  initContainers:
    - name: wait-db                # must exit 0 first
      image: busybox:1.36
      command: ["sh", "-c", "until nc -z db 5432; do sleep 2; done"]
    - name: logs                   # sidecar: runs alongside
      image: fluent/fluent-bit:3.1
      restartPolicy: Always
  containers:
    - name: api
      image: ghcr.io/acme/api:1.4.2
      command: ["/app/server"]     # overrides ENTRYPOINT
      args: ["--port=8080"]        # overrides CMD
      ports: [{ containerPort: 8080, name: http }]

Code Explained

restartPolicy — Deployments require Always
initContainers — setup, waits, migrations
restartPolicy: Always on init — native sidecar
name: http — reference by name in Services/probes
until nc -z — blocks the app until the DB port answers
image — pin a tag or @sha256: digest

⚠ Common Mistakes

  • Bare Pod for an app — not rescheduled when its node dies
  • :latest tags — nodes may run different builds
  • Setting command skips the image's entrypoint script
  • Two containers binding one port — they share a network namespace

✓ Tips & Best Practices

  • One main process per container; helpers as sidecars
  • kubectl run api --image=… --dry-run=client -o yaml
  • Name ports and reference them by name
  • env from ConfigMaps/Secrets: Sheet 15

Quick Summary

  • Pod — containers sharing IP + volumes
  • initContainers — run first, in order
  • command / args — ENTRYPOINT / CMD
  • restartPolicy: Always init container — native sidecar
