Helm & Kustomize

helm repo add · upgrade --install · values.yaml / -f / --set · helm template / rollback · kustomization.yaml · overlays · apply -k

Packaging and Variants

Helm is a package manager: a chart is a set of templated manifests plus values.yaml; installing it creates a versioned release you can upgrade and roll back. Kustomize is template-free and built into kubectl: plain YAML bases plus per-environment overlays that patch them. Many teams use Helm for third-party apps and Kustomize for their own.

Notes

  • Charts come from HTTP repos or OCI registries (oci://)
  • Release state is stored as Secrets in the release namespace
  • kubectl kustomize renders without applying
  • No server component since Helm 3; Helm 4 keeps the same workflow

Helm

helm repo add prom https://prometheus-community.github.io/helm-charts
helm show values prom/kube-prometheus-stack > values.yaml
helm upgrade --install mon prom/kube-prometheus-stack \
  -n monitoring --create-namespace -f values.yaml --set grafana.enabled=true
helm list -A ; helm history mon -n monitoring
helm rollback mon 1 -n monitoring
helm template mon prom/kube-prometheus-stack -f values.yaml   # render only

Kustomize: overlays/prod/kustomization.yaml

resources: [../../base]            # base: deployment.yaml, service.yaml
namespace: shop-prod
images: [{ name: ghcr.io/acme/api, newTag: "1.4.2" }]
replicas: [{ name: api, count: 5 }]
patches: [{ path: memory-patch.yaml }]
configMapGenerator: [{ name: api-cfg, literals: [LOG_LEVEL=warn] }]
# kubectl apply -k overlays/prod

Code Explained

upgrade --install — idempotent install-or-upgrade
-f then --set — later values win
template — render YAML locally; diff or review it
images / replicas — common edits without patches
configMapGenerator — adds a hash suffix, so pods roll on change
helm show values — start your values file from the defaults
resources: [../../base] — overlays reference a shared base

⚠ Common Mistakes

  • helm install in CI — fails on rerun; use upgrade --install
  • Long --set chains — unreviewable; keep values files in Git
  • Mixing helm and kubectl edit on the same release
  • Editing rendered chart output by hand — next upgrade overwrites it

✓ Tips & Best Practices

  • Pin chart versions with --version
  • helm diff plugin previews upgrades
  • Kustomize can inflate Helm charts via helmCharts:
  • --rollback-on-failure (Helm 4) / --atomic (Helm 3) auto-reverts

Quick Summary

  • helm upgrade --install — releases
  • kustomization.yaml — base + overlays
  • kubectl apply -k — apply an overlay
  • helm rollback — previous release revision
