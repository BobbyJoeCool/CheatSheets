Sheet 02

Local Clusters & Installing kubectl

kind · minikube · k3d / k3s · kubectl install · version skew · EKS / GKE / AKS

Getting a Cluster

You need the kubectl CLI and a cluster to point it at. For learning and CI, run a disposable cluster inside Docker with kind, minikube or k3d; each starts in about a minute. In production most teams use a managed control plane (EKS, GKE, AKS) and only run workloads and nodes.

Notes

  • Local tools add a context to ~/.kube/config automatically
  • Locally built images are invisible to the cluster until loaded or pushed
  • Docker Desktop has a one-click single-node cluster
  • kind names contexts kind-<name>; minikube's is minikube

Install & Create

brew install kubectl                       # macOS
winget install -e --id Kubernetes.kubectl  # Windows
sudo snap install kubectl --classic        # Linux (or dl.k8s.io binary)
kubectl version --client                   # Client Version: v1.3x.x
kind create cluster --name dev             # 1 node in Docker
kind create cluster --name dev --config kind.yaml   # multi-node
kind load docker-image myapp:dev --name dev         # copy image in
minikube start --driver=docker --cpus=4 --memory=8g
minikube addons enable metrics-server      # built-in add-ons
k3d cluster create dev --agents 2          # k3s + 2 workers
kind delete cluster --name dev             # gone in seconds

Code Explained

version — without --client also shows the server
kind.yaml — nodes: list with role: control-plane / worker
kind load — skip the registry for dev images
--agents — k3d's name for worker nodes
minikube addons list — ingress, dashboard, registry…
delete cluster — also removes its kubeconfig context

⚠ Common Mistakes

  • ErrImagePull on a local image — kind load it or push it
  • :latest dev tag forces Always pull, ignoring the loaded image
  • kubectl 2+ minors from the server — odd errors, missing flags
  • Leaving local clusters running — they keep eating CPU and RAM

✓ Tips & Best Practices

  • Pin the node image (--image kindest/node:v1.3x.y) to match prod
  • Recreate a broken local cluster instead of repairing it
  • Manage kubectl versions with mise or asdf
  • Autopilot (GKE) and Fargate (EKS) hide nodes entirely
