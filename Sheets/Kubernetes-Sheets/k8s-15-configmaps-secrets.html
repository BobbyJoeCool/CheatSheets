Sheet 15

ConfigMaps & Secrets

create --from-literal / --from-file / --from-env-file · valueFrom · envFrom · volume mounts · base64 · immutable

Configuration Outside the Image

A ConfigMap holds non-secret key/value config; a Secret holds sensitive values and is handled a bit more carefully (RBAC, tmpfs mounts, optional encryption at rest). Pods consume both as environment variables or as files in a mounted volume. Same image, different config per environment.

Notes

  • Secret values are base64-encoded, not encrypted
  • Env vars are read once at start; mounted files update (≈1 min), except subPath
  • Size limit: 1 MiB per ConfigMap or Secret
  • immutable: true blocks edits and lightens API server load

Create

kubectl create cm app-cfg --from-literal=LOG_LEVEL=info --from-file=app.yaml
kubectl create cm env-cfg --from-env-file=.env
kubectl create secret generic db --from-literal=pw='s3cr3t!'
kubectl create secret tls shop-tls --cert=tls.crt --key=tls.key
kubectl get secret db -o jsonpath='{.data.pw}' | base64 -d     # s3cr3t!

Consume

spec:
  containers:
    - name: api
      envFrom: [{ configMapRef: { name: env-cfg } }]   # every key → env
      env:
        - name: DB_PASSWORD
          valueFrom: { secretKeyRef: { name: db, key: pw } }
      volumeMounts: [{ name: cfg, mountPath: /etc/app, readOnly: true }]
  volumes:
    - name: cfg
      configMap: { name: app-cfg }     # each key becomes a file

Code Explained

--from-file — key = filename, value = contents
--from-env-file — one key per KEY=value line
secret tls — keys tls.crt and tls.key
envFrom — bulk import; prefix: avoids clashes
secretKeyRef — one key into one env var
/etc/app/app.yaml — file from the ConfigMap key

⚠ Common Mistakes

  • Committing Secret YAML to Git — base64 is readable by anyone
  • Expecting env vars to change after editing a ConfigMap — restart the pods
  • subPath mounts never update
  • Giving list secrets broadly — it returns every value in the namespace

✓ Tips & Best Practices

  • Add a config hash annotation to the pod template so changes roll out
  • Use stringData: in YAML to write plain text; the API encodes it
  • Registry auth: create secret docker-registry + imagePullSecrets
  • Prefer an external secret manager for production

Quick Summary

  • ConfigMap — plain config
  • Secret — sensitive, base64 only
  • env / envFrom — read at start
  • volume — files, updated live
