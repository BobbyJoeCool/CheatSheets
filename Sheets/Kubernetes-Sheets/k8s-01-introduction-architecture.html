What Kubernetes Is

Kubernetes (K8s) is an open-source container orchestrator: it places containers on a pool of machines, restarts them when they fail, scales them and gives them stable networking. You declare the desired state in YAML; controllers keep nudging the actual state toward it, forever. That loop (observe → diff → act) explains everything else in this set.

Good to Know

  • Started at Google, v1.0 in 2015, now a CNCF project; ~3 releases a year
  • Nodes run containerd or CRI-O, not Docker Engine; Docker-built images still work
  • kubectl only writes objects to the API; controllers do the work
  • Everything is an object in the API: Pods, Services, even Nodes

Watch the Reconcile Loop

kubectl create deployment hello --image=nginx:1.27
kubectl scale deployment hello --replicas=3   # desired: 3 pods
kubectl get pods                    # 3 x hello-6d8f9c7b5-…  Running
kubectl delete pod hello-6d8f9c7b5-x7k2p      # "crash" one
kubectl get pods                    # still 3: a new one replaced it
kubectl expose deployment hello --port=80     # stable Service IP
kubectl get nodes -o wide           # machines in the cluster
kubectl get pods -n kube-system     # coredns, kube-proxy, etcd…
kubectl get --raw='/readyz?verbose' # control-plane health
kubectl delete deployment,svc hello # clean up

Code Explained

create deployment — stores an object; controllers create the Pods
delete pod — actual (2) ≠ desired (3), so a replacement appears
expose — a Service gives pods one stable IP + DNS name
kube-system — namespace for cluster components
/readyz — replaces deprecated get componentstatuses
get nodes -o wide — node IPs, OS, kernel, runtime version

Control Plane

ComponentJob
kube-apiserverFront door; every read and write goes through it
etcdKey-value store holding all cluster state
kube-schedulerPicks a node for each new Pod
controller-managerRuns built-in controllers (Deployment, Job, Node…)
cloud-controllerCloud load balancers, routes, node lifecycle
etcd quorum3 or 5 members; losing a majority stops writes

Every Worker Node

ComponentJob

CNI pluginPod networking: Calico, Cilium, Flannel
CoreDNSCluster DNS add-on, runs as pods
PodSmallest unit: 1+ containers sharing IP + volumes

⚠ Common Mistakes

  • Bare Pods for apps — nothing recreates them if the node dies; use a Deployment
  • Assuming apply succeeded = app running; controllers act afterward
  • Fixing things on nodes by hand — controllers overwrite drift
  • Expecting docker ps on nodes — use crictl ps

✓ Tips & Best Practices

  • Read the Events in kubectl describe first; they explain most failures
  • Change the spec and let controllers converge; don't script steps
  • Learn on a throwaway local cluster (Sheet 02)
  • kubectl api-resources lists every kind the cluster knows

Quick Summary

  • apiserver — the only door; state lives in etcd
  • scheduler — placement; controllers — reconcile
  • kubelet — runs pods on each node
  • Pod — smallest unit, usually owned by a controller
