Debugging & Troubleshooting

logs -f / --previous · exec -it · kubectl debug · port-forward · events · top · CrashLoopBackOff / Pending

A Debugging Routine

Work outside in: get shows what is wrong (status, restarts), describe and events show why the cluster couldn't do it, logs show why the app failed, and exec/debug let you look inside. Most problems are a typo in an image name, a missing ConfigMap key, too little memory, or a selector that matches nothing.

Notes

  • Events expire after about an hour; check them early
  • kubectl debug adds a tool container to a running pod
  • Distroless images have no shell; use debug, not exec
  • kubectl get pod x -o yaml → status.containerStatuses has the exact reason

Debug Toolkit

kubectl get pods -o wide                         # STATUS, RESTARTS, NODE
kubectl describe pod api-7d9f-x2k                # Events: the why
kubectl get events -n shop --sort-by=.lastTimestamp
kubectl logs api-7d9f-x2k -c api --tail=100 -f   # follow one container
kubectl logs api-7d9f-x2k --previous             # before the last crash
kubectl logs deploy/api --all-containers --since=15m
kubectl exec -it api-7d9f-x2k -- sh              # shell inside
kubectl debug -it api-7d9f-x2k --image=busybox:1.36 --target=api
kubectl debug node/worker-1 -it --image=ubuntu   # host fs at /host
kubectl port-forward pod/api-7d9f-x2k 8080:8080  # reach it locally
kubectl top pods --containers                    # needs metrics-server
kubectl run net --rm -it --image=nicolaka/netshoot -- bash

Code Explained

--previous — the crashed container's last output
deploy/api — logs from one pod of the Deployment
--target=api — share the app container's process namespace
debug node/ — privileged pod on that node
netshoot — dig, curl, tcpdump, nc in one image
--since=15m — or --since-time, --timestamps
port-forward — bypasses Services and Ingress to isolate the app

⚠ Common Mistakes

  • Reading current logs of a crash-looping pod — use --previous
  • Restarting pods before reading Events — the evidence disappears
  • exec into distroless images — no shell; use debug
  • Blaming Kubernetes for app config errors — read the app's own logs first

✓ Tips & Best Practices

  • Install stern to tail logs across many pods
  • k9s gives a live terminal UI over all of this
  • Check endpoints before blaming the network
  • kubectl get pods --field-selector status.phase=Failed -A finds casualties

Quick Summary

  • get → describe → logs → exec/debug
  • logs --previous — why it crashed
  • debug — tools without rebuilding the image
  • events — cluster's side; logs — app's side
