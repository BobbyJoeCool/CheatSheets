Sheet 04

Inspecting Resources & Output Formats

get · describe · -o wide / yaml / json · jsonpath · custom-columns · explain · api-resources

Reading the Cluster

kubectl get lists objects as a table; -o switches format, from extra columns to the full live YAML. kubectl describe gives a readable summary plus recent Events, where most errors show up. explain and api-resources document the API straight from your cluster.

Notes

  • get pod web-0 and get pod/web-0 both work
  • List several kinds at once: get deploy,svc,pods
  • get all skips ConfigMaps, Secrets, Ingress, PVCs
  • Live YAML includes status and server-set fields

Inspect

kubectl get pods -A                     # all namespaces
kubectl get pods -o wide                # + IP and NODE
kubectl get deploy web -o yaml          # full live object
kubectl get pods -l app=web --show-labels
kubectl get pods --field-selector status.phase!=Running
kubectl get pods --sort-by=.metadata.creationTimestamp
kubectl get pods -w                     # watch changes
kubectl get pod web-0 -o jsonpath='{.status.podIP}'   # 10.244.1.7
kubectl get pods -o custom-columns=NAME:.metadata.name,NODE:.spec.nodeName
kubectl describe pod web-0              # details + Events
kubectl explain deploy.spec.strategy    # field docs
kubectl api-resources --namespaced=false

Code Explained

--field-selector — server-side filter on a few fields
-w — stream updates until Ctrl-C
jsonpath — use single quotes in the shell
explain — types and docs for any field path
api-resources — every kind and its short name

⚠ Common Mistakes

  • Trusting get all — config, storage and CRDs are missing
  • Double-quoted jsonpath in bash — $ and braces get mangled
  • Committing -o yaml output — status and uid make noisy diffs
  • Skipping the Events at the bottom of describe — they name the problem

✓ Tips & Best Practices

  • get events --sort-by=.lastTimestamp for a timeline
  • -o name | xargs for bulk actions
  • alias k=kubectl + shell completion
  • krew plugin kubectl neat strips server fields from YAML

Quick Summary

  • get — table; -o for more
  • describe — summary + Events
  • explain — the API documents itself
  • jsonpath / custom-columns — script-friendly output
