The Workbench Layout

Activity Bar · Primary / Secondary Side Bar · Panel · Status Bar · editor groups · Zen Mode

Five Areas Around the Editor

The window is the workbench. The Activity Bar picks a view (Explorer, Search, Source Control, Run and Debug, Extensions); the Primary Side Bar shows it. The Secondary Side Bar on the other side holds Chat and anything you drag there. The Panel below the editor holds the terminal, Problems, Output and Debug Console. The Status Bar shows branch, errors, language and line endings.

Notes

  • Every view can be dragged to another area or the Status Bar
  • View → Appearance toggles each area and moves the Panel
  • Right-click the Activity Bar to hide views you never use
  • Zen Mode hides everything but the editor (Esc Esc to leave)

Set Up a Clean Layout

  1. Hide what you don't use: right-click the Activity Bar and untick views
  2. Drag Outline and Timeline from Explorer into the Secondary Side Bar
  3. Toggle the Side Bar with ⌘B / Ctrl+B and the Panel with ⌘J / Ctrl+J
  4. Maximize the Panel with its ^ button when reading long terminal output
  5. Use Customize Layout (title bar icon) to try positions with a live preview
  6. Save the result in a profile (sheet 05) so other projects get it too

settings.json

  • "workbench.activityBar.location": "top" — icons above the Side Bar ("hidden" removes them)
  • "workbench.sideBar.location": "right" — keeps code from jumping when it opens
  • "workbench.editor.showTabs": "single" — one tab line ("none" hides tabs)
  • "zenMode.centerLayout": true — center the editor in Zen Mode

In Other Editors

  • JetBrains — tool windows: ⌘1 / Alt+1 Project, ⇧⌘F12 / Ctrl+Shift+F12 hides all; Distraction Free Mode
  • Vim / Neovim — no workbench; windows and tabs, plus a file tree plugin (neo-tree, nvim-tree, NERDTree)

⚠ Common Mistakes

  • Closing the Panel when you meant to close one terminal: the terminal keeps running and ⌘J / Ctrl+J brings it back
  • Leaving every Activity Bar view visible; clutter makes the shortcuts the only fast path anyway
  • Missing errors because the Status Bar was hidden; the error count lives there

✓ Tips & Best Practices

  • Put the Side Bar on the right so opening it never shifts your code
  • Use the Secondary Side Bar for things you want open at the same time as Explorer (Chat, Outline)
  • Double-click a tab to maximize its editor group
