Named Commands You Run From the Editor

A task is a command (build, test, lint, start a watcher) with a name, saved in .vscode/tasks.json. VS Code also auto-detects tasks from npm scripts, Gulp, Make and others. Tasks run in a terminal; a problem matcher turns their output into clickable entries in Problems. Mark one task as the default build (⇧⌘B / Ctrl+Shift+B) or test task.

Notes

  • Run any task: palette Tasks: Run Task or the task prefix in Quick Open
  • npm scripts appear as npm: <script> with no config
  • isBackground + a matcher lets watch tasks signal when they're ready
  • Configure Task turns a detected task into tasks.json you can edit

.vscode/tasks.json

{
  "version": "2.0.0",
  "tasks": [
    {
      "label": "build",
      "type": "shell",
      "command": "npm run build",
      "group": { "kind": "build", "isDefault": true },
      "problemMatcher": ["$tsc"]
    },
    {
      "label": "test",
      "type": "shell",
      "command": "npx vitest run",
      "group": "test",
      "presentation": { "reveal": "always", "panel": "dedicated" }
    },
    {
      "label": "lint + test",
      "dependsOn": ["lint", "test"],
      "dependsOrder": "sequence"
    }
  ]
}

Code Explained

"shell" runs through your shell (pipes, &&); "process" runs the program directly
group.kind: "build" + isDefault is what ⇧⌘B / Ctrl+Shift+B runs
$tsc, $eslint-stylish, $gcc are built-in problem matchers
dependsOn runs other tasks first, in parallel unless dependsOrder: "sequence"

settings.json

  • "task.autoDetect": "on" — find npm / Gulp / Make tasks automatically
  • "task.problemMatchers.neverPrompt": true — stop asking for a matcher
  • "npm.scriptExplorerAction": "run" — click an npm script to run it

In Other Editors

  • JetBrains — Run configurations (npm, Gradle, Maven, Shell Script) and External Tools; Before Launch steps chain them
  • Vim / Neovim — :make with makeprg and errorformat (Vim's problem matcher), results in the quickfix list; overseer.nvim

⚠ Common Mistakes

  • Copying a terminal command into a task without a problem matcher, so errors aren't clickable
  • A watch task without isBackground, so a preLaunchTask waits forever
  • Duplicating npm scripts as tasks instead of using the auto-detected npm: tasks

✓ Tips & Best Practices

  • Bind Tasks: Rerun Last Task to a key for a quick edit-run loop
  • Use runOn: "folderOpen" for a watcher that should always be running
  • Reference tasks from launch.json with preLaunchTask so debugging builds first
