Sheet 25

Remote Development

Remote - SSH · WSL · Dev Containers · devcontainer.json · Codespaces · Remote Tunnels · port forwarding

The UI Stays Local, the Code Runs Elsewhere

With the Remote Development extensions, VS Code runs a small server where the code lives and keeps the UI on your machine. Remote - SSH opens folders on a server, WSL opens folders inside Linux on Windows, and Dev Containers opens a folder inside a Docker container defined by devcontainer.json. Terminals, debuggers and extensions run on the remote side, so you get the remote OS and tools.

Notes

  • The green >< button (bottom left) opens every remote option
  • Extensions install "locally" (themes, keymaps) or "remotely" (language servers)
  • Codespaces = a dev container on GitHub's cloud
  • Remote Tunnels reach a machine with no SSH access through GitHub sign-in

Extension Pick

  • Remote Development (Microsoft) — pack with Remote - SSH, WSL and Dev Containers
  • Dev Containers alone if you only need containers

.devcontainer/devcontainer.json

{
  "name": "Node + Postgres",
  "image": "mcr.microsoft.com/devcontainers/typescript-node:22",
  "features": {
    "ghcr.io/devcontainers/features/github-cli:1": {}
  },
  "forwardPorts": [3000, 5432],
  "postCreateCommand": "npm ci",
  "customizations": {
    "vscode": {
      "extensions": ["dbaeumer.vscode-eslint"],
      "settings": { "editor.formatOnSave": true }
    }
  },
  "remoteUser": "node"
}

Code Explained

image (or build.dockerfile, or dockerComposeFile) defines the container
Features add tools (CLI, language runtimes) without writing a Dockerfile
postCreateCommand runs once after the container is built
Extensions listed under customizations.vscode install inside the container

settings.json

  • "remote.SSH.remotePlatform": { "build-box": "linux" }
  • "remote.autoForwardPorts": true — forward ports when a server starts
  • "dev.containers.dockerPath": "podman" — use Podman

In Other Editors

  • JetBrains — JetBrains Gateway / Remote Development over SSH, Dev Containers support in IntelliJ-based IDEs, WSL interpreters
  • Vim / Neovim — run Vim directly on the server over ssh; nvim scp://host//path for single files; distant.nvim

⚠ Common Mistakes

  • Opening a Windows folder (/mnt/c/…) from WSL; file access is slow, keep code in the Linux file system
  • Editing devcontainer.json and forgetting to Rebuild Container
  • Installing a language extension locally and wondering why it does nothing in the remote window

✓ Tips & Best Practices

  • Commit .devcontainer/ so new contributors get a working setup in one click
  • Use ~/.ssh/config host aliases; Remote - SSH reads them
  • Use Features instead of custom Dockerfiles for common tools
