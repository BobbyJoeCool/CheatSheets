Everyday Git Without Leaving the Editor

The Source Control view (⌃⇧G / Ctrl+Shift+G) lists changed files. Click a file to see its diff; stage whole files with +, or single hunks and lines from the diff. Type a message and commit with ⌘↩ / Ctrl+Enter. The branch in the Status Bar switches or creates branches, and the sync button pulls then pushes. Colored bars in the gutter mark added, changed and deleted lines.

Notes

  • Uses the Git you have installed; it's the same repo as the command line
  • Source Control Graph shows history and branches
  • Click a gutter bar to see and revert that change inline
  • The Git set covers what the commands do

Extension Pick

  • GitLens (GitKraken) — blame on every line, rich history, compare branches
  • Git Graph (mhutchie) — a simple, free commit graph

Commit Part of a File

  1. Open Source Control (⌃⇧G / Ctrl+Shift+G) and click the changed file
  2. In the diff, select the lines you want in this commit
  3. Right-click → Stage Selected Ranges (⌘K ⌥⌘S / Ctrl+K Ctrl+Alt+S)
  4. Type the message; first line short, blank line, then detail
  5. Commit with ⌘↩ / Ctrl+Enter (the ✓ button)
  6. Click the sync icon in the Status Bar, or ⋯ → Push

settings.json

  • "git.autofetch": true — fetch in the background so behind/ahead counts are current
  • "git.enableSmartCommit": true — commit all changes when nothing is staged
  • "git.confirmSync": false — skip the sync confirmation
  • "git.blame.editorDecoration.enabled": true — inline blame on the current line

⚠ Common Mistakes

  • Committing with smart commit on and sweeping in files you didn't mean to stage
  • Discarding changes from the ⟲ button without reading the prompt; it can't be undone
  • Pushing with the sync button on a shared branch without pulling the latest first

✓ Tips & Best Practices

  • Stage by hunk or line to keep commits focused
  • Review the full diff of what you staged before committing (click the file under Staged Changes)
  • Turn on git.autofetch so you see when the remote moved
