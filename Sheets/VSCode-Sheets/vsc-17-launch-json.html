Sheet 17

launch.json Configurations

configurations · launch vs attach · program · args · env / envFile · ${workspaceFolder} · preLaunchTask · compounds

Save How to Start the Program

.vscode/launch.json stores debug configurations: which debugger (type), whether to start the program (launch) or connect to one that's running (attach), and its arguments, environment and working folder. Pick a configuration in Run and Debug and press F5. Compounds start several at once, such as an API and a front end.

Notes

  • Create it: Run and Debug → create a launch.json file
  • IntelliSense in the file lists every field for that type
  • Add Configuration… inserts templates (Node, Python, Chrome…)
  • Commit it so the team shares debug setups

.vscode/launch.json

{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "API (Node)",
      "type": "node",
      "request": "launch",
      "program": "${workspaceFolder}/src/server.js",
      "args": ["--port", "3000"],
      "envFile": "${workspaceFolder}/.env",
      "preLaunchTask": "npm: build",
      "skipFiles": ["<node_internals>/**"]
    },
    {
      "name": "Python: current file",
      "type": "debugpy",
      "request": "launch",
      "program": "${file}",
      "justMyCode": true
    },
    { "name": "Attach :9229", "type": "node",
      "request": "attach", "port": 9229 }
  ],
  "compounds": [
    { "name": "Full stack", "configurations": ["API (Node)", "Web"] }
  ]
}

Code Explained

type comes from the debugger extension: node, debugpy, java, coreclr, go, chrome
${workspaceFolder} and ${file} are variables filled in at launch
preLaunchTask runs a task from tasks.json first (build, compile)
attach connects to a process already listening, e.g. node --inspect

settings.json

  • "debug.javascript.autoAttachFilter": "smart" — auto-attach to Node started in the terminal
  • "launch": { … } in User settings — configurations for every workspace
  • "debug.console.closeOnEnd": true

In Other Editors

  • JetBrains — Run/Debug Configurations dialog, saved in .idea/ or as shareable .run/*.run.xml files
  • Vim / Neovim — nvim-dap dap.configurations.<lang>; it can also read .vscode/launch.json (require("dap.ext.vscode").load_launchjs())

⚠ Common Mistakes

  • Hard-coding absolute paths instead of ${workspaceFolder}, so the config breaks on other machines
  • Secrets in env inside a committed launch.json; use envFile and gitignore .env
  • Using launch for a process started by Docker or a script; that's an attach job

✓ Tips & Best Practices

  • Start from Add Configuration… templates rather than an old blog post
  • Use ${input:…} with promptString / pickString for values that change each run
  • Add a compound for the whole stack and debug front end and back end in one session

Quick Summary

  • launch / attach — start or connect
  • ${workspaceFolder} — portable paths
  • preLaunchTask — build first
  • compounds — several at once
