Sheet 14

Formatting & Linting

Format Document ⇧⌥F · editor.formatOnSave · editor.defaultFormatter · codeActionsOnSave · Prettier / ESLint / Ruff · .editorconfig

Consistent Code Without Thinking About It

A formatter rewrites layout (indentation, quotes, line breaks); a linter reports problems and can auto-fix some. VS Code runs formatters through Format Document (⇧⌥F / Shift+Alt+F) or on save, and linters through extensions that feed the Problems panel. When several formatters handle a language, editor.defaultFormatter picks one.

Notes

  • Format Selection: ⌘K ⌘F / Ctrl+K Ctrl+F
  • Format on save needs a formatter for that language, or nothing happens
  • Format Document With… picks a formatter once and can set the default
  • Tool configs (.prettierrc, pyproject.toml) win over editor settings

Extension Pick

  • Prettier (Prettier) — formatter for JS, TS, CSS, HTML, JSON, YAML, Markdown
  • ESLint (Microsoft) — JS / TS linting and fixes · Ruff (Astral) — Python lint + format

.vscode/settings.json for a Team

{
  "editor.formatOnSave": true,
  "editor.defaultFormatter": "esbenp.prettier-vscode",
  "editor.codeActionsOnSave": {
    "source.fixAll.eslint": "explicit"
  },
  "[python]": {
    "editor.defaultFormatter": "charliermarsh.ruff",
    "editor.codeActionsOnSave": {
      "source.fixAll.ruff": "explicit",
      "source.organizeImports.ruff": "explicit"
    }
  },
  "eslint.validate": ["javascript", "typescript", "typescriptreact"]
}

Code Explained

The default formatter is an extension ID (publisher.name), shown on its Marketplace page
Format on save formats the file; code actions on save run the linter's fixes
Language blocks give Python its own formatter while everything else uses Prettier
Commit this file plus .vscode/extensions.json so everyone gets the same tools

settings.json

  • "editor.formatOnSaveMode": "modifications" — format only changed lines (needs Git)
  • "editor.formatOnPaste": true
  • "files.eol": "\n" — LF line endings for new files

In Other Editors

  • JetBrains — Reformat Code ⌥⌘L / Ctrl+Alt+L, Settings → Tools → Actions on Save; Prettier and ESLint have built-in support
  • Vim / Neovim — gq / = built in; conform.nvim for formatters, nvim-lint or LSP diagnostics for linters

⚠ Common Mistakes

  • Two extensions both formatting on save and fighting over quotes or line length
  • Formatter settings only in a teammate's User settings, so the repo flips style on every commit
  • Turning on format on save in a legacy repo and reformatting whole files in unrelated PRs

✓ Tips & Best Practices

  • Set formatOnSaveMode: "modifications" when adopting a formatter on old code
  • Keep the tool's own config file in the repo so CI formats the same way
  • Check Output → Prettier (or the tool's channel) when formatting silently does nothing

Quick Summary

  • ⇧⌥F / Shift+Alt+F — format document
  • editor.defaultFormatter — pick one per language
  • formatOnSave + codeActionsOnSave — fix on save
  • .editorconfig — basic style for every editor
