Pause the Program and Look Inside

Set a breakpoint in the gutter, start debugging with F5, and the program pauses there. The Run and Debug view shows Variables, Watch expressions and the Call Stack; the Debug Console evaluates expressions in the paused frame. Each language's debugger comes from its extension (Python Debugger, Java, C#, Go; JavaScript is built in).

Notes

  • Without launch.json, F5 offers to debug the current file
  • Hover a variable while paused to see its value
  • Logpoints print a message without pausing or editing code
  • JavaScript Debug Terminal debugs any Node command you run in it

Extension Pick

  • Python Debugger (Microsoft) — debugpy for Python
  • Debugger for Java (Microsoft) · JavaScript debugging is built in

Code Explained

Step over runs the line; step into enters a function call on it; step out finishes the current function
Conditional breakpoints use the language's own expression syntax
Logpoint messages put expressions in { } and print to the Debug Console
Run without debugging still uses launch.json but skips breakpoints

settings.json

  • "debug.inlineValues": "on" — show variable values beside the code while paused
  • "debug.toolBarLocation": "docked" — put the debug toolbar in the Run and Debug view
  • "debug.openDebug": "openOnDebugBreak" — show the view when a breakpoint hits

In Other Editors

⚠ Common Mistakes

  • Debugging with print and restarting the program each time when one breakpoint would answer the question
  • Stepping into library code by accident; use step out (⇧F11 / Shift+F11) or justMyCode
  • Leaving uncaught-exception breakpoints off and missing where an error really started

✓ Tips & Best Practices

  • Use a logpoint in code you can't edit or restart easily
  • Right-click a Call Stack frame → Restart Frame (where the language supports it) to rerun a function
  • Pin values you check every pause in Watch
