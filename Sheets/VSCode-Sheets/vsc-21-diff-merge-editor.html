Diff & Merge Editor

compare files · inline vs side-by-side diff · code -d · 3-way merge editor · accept incoming / current · resolve conflicts

See Changes and Settle Conflicts

The diff editor shows two versions side by side (or inline), with moved code detected and unchanged regions collapsed. When Git reports a merge conflict, VS Code highlights the conflict blocks with Accept Current / Accept Incoming / Accept Both links, or opens the 3-way merge editor: incoming and current on top, the result below.

Notes

  • Compare any two files: select both in Explorer → right-click → Compare Selected
  • Current = your branch (HEAD); Incoming = what you're merging in
  • The merge editor shows the conflict count and a Complete Merge button
  • Compare with clipboard: palette File: Compare Active File with Clipboard

Resolve a Merge Conflict

  1. Run the merge or rebase; conflicted files show C in Source Control
  2. Open a file and click Resolve in Merge Editor
  3. For each conflict, tick Accept Incoming, Accept Current or both
  4. Edit the Result pane by hand where neither side is right
  5. Click Complete Merge; the file is staged
  6. Run the tests, then commit (or Continue a rebase)

settings.json

  • "diffEditor.renderSideBySide": true (false = inline)
  • "diffEditor.ignoreTrimWhitespace": false — show whitespace changes
  • "git.mergeEditor": true — open conflicts in the merge editor
  • "diffEditor.hideUnchangedRegions.enabled": true

In Other Editors

  • JetBrains — Merge dialog with three panes (⇇ accept left, ⇉ accept right) from the Git conflicts popup; Compare with clipboard
  • Vim / Neovim — vimdiff / nvim -d, :diffget LO / RE in a 3-way merge, ]c / [c next change; diffview.nvim plugin

⚠ Common Mistakes

  • Clicking Accept Both on two edits of the same line and keeping duplicate code
  • Forgetting that during a rebase "current" and "incoming" swap meaning
  • Committing a file that still contains <<<<<<< markers; the merge editor's count prevents this

✓ Tips & Best Practices

  • Use Compare Changes on a conflict to see what each side changed from the base
  • Turn off whitespace-ignoring when a diff looks empty but Git says the file changed
  • Use code -d as Git's difftool: git config --global diff.tool vscode

Quick Summary

  • diff editor — side by side or inline
  • Current = HEAD · Incoming = theirs
  • merge editor — 3-way with a Result pane
  • code -d — diff from the terminal
