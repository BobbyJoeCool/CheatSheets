The Testing View

Test Explorer · run / debug from the gutter · test output peek · rerun failed · coverage view · continuous run

One UI for Every Test Framework

The Testing view (beaker icon) lists tests that a framework extension discovers: pytest and unittest (Python), Jest and Vitest, JUnit, Playwright, .NET and more. Run or debug a single test from the ▷ in the gutter, a file, or everything. Failures open a peek with the assertion message and diff right at the failing line. Supported frameworks can also show coverage and run continuously on save.

Notes

  • Each framework needs its extension and a little config (e.g. enable pytest)
  • Right-click the gutter ▷ for Debug Test
  • Filter the tree by @failed, @doc (current file) or text
  • pytest, Jest & Vitest, JUnit and Playwright sets cover each framework's setup

Extension Pick

  • Python (Microsoft) · Vitest (Vitest) · Test Runner for Java (Microsoft) · Playwright Test (Microsoft)
  • Each plugs its tests into this same view

Testing Keys & Setup

⌘; C     / Ctrl+; C        # run test at cursor
⌘; F     / Ctrl+; F        # run tests in current file
⌘; A     / Ctrl+; A        # run all tests
⌘; E     / Ctrl+; E        # rerun failed tests
⌘; L     / Ctrl+; L        # rerun last run
⌘; ⌘C    / Ctrl+; Ctrl+C   # debug test at cursor

# Python: enable pytest (palette)
>Python: Configure Tests → pytest → tests/
# writes to .vscode/settings.json:
"python.testing.pytestEnabled": true,
"python.testing.pytestArgs": ["tests"]

Code Explained

The ⌘; / Ctrl+; chord family covers run, debug and rerun
Configure Tests writes the framework choice to workspace settings
Coverage: use Run with Coverage (shield icon) where the extension supports it
Continuous run (eye icon) reruns affected tests when files change

settings.json

  • "testing.automaticallyOpenPeekView": "failureInVisibleDocument"
  • "testing.defaultGutterClickAction": "debug" — gutter click debugs instead of runs
  • "python.testing.pytestEnabled": true

In Other Editors

  • JetBrains — gutter ▷ icons and Run ⌃⇧R / Ctrl+Shift+F10 for the test at the cursor; Run tool window shows the tree
  • Vim / Neovim — neotest (tree, gutter signs, output) or vim-test (:TestNearest, :TestFile)

⚠ Common Mistakes

  • Seeing an empty Testing view and assuming no tests; usually the framework isn't enabled or discovery failed (check Output)
  • Running the whole suite from the view when one test at the cursor would do
  • Different test args in VS Code and CI, so tests pass in one and fail in the other

✓ Tips & Best Practices

  • Check Output → Python Test Log (or the framework's channel) when discovery fails
  • Debug a failing test from the gutter instead of adding prints
  • Keep framework config in its own file (pyproject.toml, vitest.config.ts) so CLI and editor agree

Quick Summary

  • Testing view — tests from any framework
  • ⌘; C / Ctrl+; C — test at cursor
  • ⌘; E / Ctrl+; E — rerun failed
  • peek — failure at the line
