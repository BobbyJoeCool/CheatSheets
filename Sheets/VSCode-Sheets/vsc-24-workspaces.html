Workspaces & Multi-Root

One Window, One or Many Folders

Opening a folder makes it the workspace: its .vscode/ folder holds settings, launch and task configs. A multi-root workspace opens several folders in one window (say, api/ and web/ from different repos), saved as a .code-workspace file with its own settings. Workspace Trust asks before running code from a folder you just downloaded; in Restricted Mode, tasks, debugging and some extensions are off.

Notes

  • File → Add Folder to Workspace turns a window into multi-root
  • Save Workspace As… writes the .code-workspace file
  • Each root folder can keep its own .vscode/settings.json
  • Trust a parent folder (e.g. ~/projects) to trust everything under it

team.code-workspace

{
  "folders": [
    { "path": "api" },
    { "path": "web" },
    { "path": "../shared-lib", "name": "shared" }
  ],
  "settings": {
    "files.exclude": { "**/node_modules": true },
    "editor.formatOnSave": true
  },
  "extensions": {
    "recommendations": ["dbaeumer.vscode-eslint"]
  },
  "launch": {
    "compounds": [
      { "name": "API + Web",
        "configurations": ["API", "Web"] }
    ]
  }
}

Code Explained

Paths are relative to the .code-workspace file; name changes the label in Explorer
Workspace-file settings apply to all roots; folder settings can override them
launch and tasks can live in the workspace file to span folders
Open it with code team.code-workspace or double-click

settings.json

  • "security.workspace.trust.untrustedFiles": "prompt"
  • "files.exclude": { "**/.DS_Store": true } — hide from Explorer
  • "explorer.fileNesting.enabled": true — group app.ts with app.test.ts

In Other Editors

  • JetBrains — a project = a folder with .idea/; attach more projects to one window (PyCharm, WebStorm) or use modules (IntelliJ)
  • Vim / Neovim — :cd / :tcd per tab, :mksession to save layout; a "workspace" is just the current directory

FeatureRestricted
TasksOff
DebuggingOff

Reading / editing filesAllowed

⚠ Common Mistakes

  • Trusting every folder automatically, including ones from email attachments or random repos
  • Committing .code-workspace files with paths that only exist on your machine
  • Putting secrets in .vscode/settings.json or mcp.json and committing them

✓ Tips & Best Practices

  • Use a multi-root workspace for a front end and back end in separate repos
  • Turn on file nesting to tidy Explorer in projects with many generated files
  • Gitignore .vscode/* but un-ignore the shared files: !.vscode/settings.json, !.vscode/extensions.json

Quick Summary

  • folder — one root with .vscode/
  • .code-workspace — many roots + shared settings
  • Workspace Trust — Restricted Mode for unknown code
  • .vscode/ — settings, launch, tasks, extensions, mcp
