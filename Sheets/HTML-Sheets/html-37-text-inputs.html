Text Inputs

text · email · password · search · tel · url · number · placeholder

Single-Line Text Fields

<input> is one element with many types. The text-like types all show a single-line box, but each tells the browser what data to expect: email and url check the format, tel shows a phone keypad, number adds a spinner, password masks what's typed and search adds a clear button in some browsers. The right type gives mobile users the right keyboard for free.

Notes

  • type="text" is the default when type is missing or unknown
  • placeholder is a hint, not a label; it vanishes when typing starts
  • number is for quantities; use text + inputmode="numeric" for ZIP and card numbers
  • size sets the visible width in characters; maxlength limits input

♿ Accessibility

  • Never use placeholder as the only label: it disappears and often has low contrast
  • Let users paste into password fields so password managers work
  • Number spinners are tiny targets; don't depend on them

Pairing with CSS

  • ::placeholder { color: #6b7280; }: keep at least 4.5:1 contrast
  • :placeholder-shown: style empty fields, e.g. floating labels
  • input[type="search"]::-webkit-search-cancel-button: the clear button (WebKit/Blink)

Code Explained

type="email": checks for name@domain; multiple allows a list
current-password: use new-password on sign-up forms
type="url": requires a scheme like https://
type="tel": phone keypad, but no format check
inputmode="numeric": number keyboard without number rules

Text-Like Input Types

<label for="fullname">Full name</label>
<input id="fullname" name="fullname" type="text"
       autocomplete="name" maxlength="80">

<label for="email">Email</label>
<input id="email" name="email" type="email"
       autocomplete="email" placeholder="you@example.com">

<label for="pw">Password</label>
<input id="pw" name="password" type="password"
       autocomplete="current-password" minlength="8">

<label for="site">Website</label>
<input id="site" name="site" type="url"
       placeholder="https://">

<label for="phone">Phone</label>
<input id="phone" name="phone" type="tel"
       autocomplete="tel">

<label for="qty">Quantity</label>
<input id="qty" name="qty" type="number"
       min="1" max="10" step="1" value="1">

<label for="zip">ZIP code</label>
<input id="zip" name="zip" type="text"
       inputmode="numeric" autocomplete="postal-code">

<label for="find">Search</label>
<input id="find" name="q" type="search">

⚠ Common Mistakes

  • type="number" for phone, card or ZIP numbers: leading zeros vanish and the scroll wheel changes values
  • Placeholder-only labels: users forget what the field is for once they type
  • Blocking paste in password fields: breaks password managers and pushes users to weak passwords

✓ Tips & Best Practices

  • Pick the type for the data, then add autocomplete for autofill
  • Use inputmode to choose a keyboard without changing validation
  • Put length rules in the label: "Password (8+ characters)"

Quick Summary

  • type: data kind + mobile keyboard
  • placeholder: hint, not a label
  • inputmode: keyboard only
  • number: only for quantities
