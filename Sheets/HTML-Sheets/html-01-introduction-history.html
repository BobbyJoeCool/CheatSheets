What HTML Is

HTML (HyperText Markup Language) describes the structure and meaning of web content; CSS handles presentation and JavaScript handles behavior. Since 2019 the single authoritative spec is the WHATWG HTML Living Standard, updated continuously instead of in numbered versions, so "HTML5" is now just a label. Browsers parse HTML into the DOM, apply CSS, then lay out and paint the page.

Notes

  • Files use .html (or .htm); servers send them as text/html
  • No compile step: open the file in a browser or serve it locally
  • Browsers forgive invalid markup, so validate to catch hidden errors
  • W3C and WHATWG agreed in 2019 that WHATWG maintains HTML and the DOM

♿ Accessibility

  • Semantic elements build the accessibility tree for free: roles, names, states
  • Set lang on <html> so screen readers use the right voice
  • Native elements (<button>, <a>) come with keyboard support built in

Pairing with CSS

  • h1, p, a: type selectors match every element with that name
  • .card / #main: class and ID selectors match attributes you add in HTML
  • Browser (user-agent) styles apply first; your CSS overrides them

Code Explained

<!doctype html>: puts the browser in standards mode
lang="en": language of the page content
<head>: metadata, not rendered on the page
<body>: everything the user sees
defer: script runs after parsing, in order
local server: needed for fetch(), ES modules and APIs that fail on file://

Hello, World

<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <meta name="viewport"
          content="width=device-width, initial-scale=1">
    <title>Hello, World</title>
    <link rel="stylesheet" href="styles.css">
  </head>
  <body>
    <h1>Hello, World</h1>
    <p>My first <strong>HTML</strong> page.</p>
    <script src="app.js" defer></script>
  </body>
</html>

⚠ Common Mistakes

  • Hunting for "HTML6": the spec has no versions now; check MDN or caniuse for feature support
  • Using HTML for looks (<font>, <center>, <br> for spacing); those jobs belong to CSS
  • Opening pages via file:// and wondering why fetch() or modules fail; use a local server

✓ Tips & Best Practices

  • Keep HTML, CSS and JS in separate files linked from the page
  • Read the parsed DOM in DevTools → Elements, not just your source
  • Check new features on caniuse.com before relying on them
