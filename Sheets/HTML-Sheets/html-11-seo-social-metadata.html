Search Engines and Link Previews

Beyond <title> and description, a few tags control how a page appears in search results and link previews in social and chat apps. rel="canonical" names the preferred URL for duplicate content. Open Graph og: properties (from Facebook, now read by most apps) and twitter: tags build preview cards. JSON-LD structured data describes products, articles and events for rich results.

Notes

  • Open Graph uses property=, not name=
  • og:image should be an absolute URL; 1200×630 px is the common size
  • X (Twitter) falls back to og: tags when twitter: tags are missing
  • JSON-LD uses the schema.org vocabulary inside a <script> tag

♿ Accessibility

  • Add og:image:alt so shared preview images have alt text
  • Clear titles and descriptions help everyone choose the right result
  • hreflang alternates send users to the version in their language

Pairing with CSS

  • Metadata never renders: <head> and its children are display: none by default
  • Crawlers render pages with your CSS; text hidden with display: none may count for less
  • Preview images are often generated from an HTML + CSS template at build time

Code Explained

canonical: consolidates ?utm= links and duplicate URLs
hreflang="x-default": fallback for unmatched languages
og:*: title, description and image for preview cards
summary_large_image: wide-image card on X
JSON-LD: test with Google's Rich Results Test

Canonical, Open Graph & JSON-LD

<head>
  <title>Trail Runner 3 · Trailhead Outfitters</title>
  <link rel="canonical"
        href="https://example.com/boots/tr3">

  <!-- language versions -->
  <link rel="alternate" hreflang="en"
        href="https://example.com/boots/tr3">
  <link rel="alternate" hreflang="es"
        href="https://example.com/es/botas/tr3">
  <link rel="alternate" hreflang="x-default"
        href="https://example.com/boots/tr3">

  <!-- Open Graph -->
  <meta property="og:type" content="website">
  <meta property="og:title" content="Trail Runner 3">
  <meta property="og:description"
        content="Light, waterproof trail shoes.">
  <meta property="og:url"
        content="https://example.com/boots/tr3">
  <meta property="og:image"
        content="https://example.com/img/tr3-1200.jpg">
  <meta property="og:image:alt"
        content="Green trail shoe, side view">

  <!-- X / Twitter -->
  <meta name="twitter:card" content="summary_large_image">

  <!-- structured data -->
  <script type="application/ld+json">
  { "@context": "https://schema.org",
    "@type": "Product",
    "name": "Trail Runner 3",
    "offers": { "@type": "Offer",
      "price": "129.00", "priceCurrency": "USD" } }
  </script>
</head>

⚠ Common Mistakes

  • Relative og:image URLs: most scrapers need an absolute URL and show no image
  • A canonical pointing at a different page: search engines may drop yours from results
  • JSON-LD that doesn't match visible content: Google may ignore it or penalize the page

✓ Tips & Best Practices

  • Make each page's canonical point to itself unless it's a true duplicate
  • Test previews with each platform's card debugger before launch
  • Generate JSON-LD from the same data as the page so they stay in sync

Quick Summary

  • rel="canonical": preferred URL
  • hreflang: language versions
  • og:* / twitter:*: link previews
  • JSON-LD: rich results
