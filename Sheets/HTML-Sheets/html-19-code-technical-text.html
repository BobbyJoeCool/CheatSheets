Code, Keys and Output

HTML has small elements for technical writing. <code> marks a fragment of computer code, <kbd> user input (usually keys), <samp> program output and <var> a variable in math or code. For multi-line code, wrap <code> in <pre> to keep the whitespace. <sub> and <sup> are subscripts and superscripts for formulas, exponents and footnote markers, not for styling.

Notes

  • Escape < and & inside <code> (sheet 07)
  • Nest <kbd> for key combinations and menu paths
  • <kbd> inside <samp> = input echoed on screen
  • class="language-js" on <code> is the hook for highlighters like Prism

♿ Accessibility

  • Screen readers read code like prose unless the user steps through it; keep inline code short
  • Footnote markers need real links: <sup><a href="#fn1">1</a></sup>
  • Scrolling <pre> blocks need tabindex="0" so keyboard users can scroll them

Pairing with CSS

  • code, kbd, samp, pre { font-family: monospace; }: UA default; set your own stack
  • pre { overflow-x: auto; tab-size: 2; }: scroll long lines, narrower tabs
  • sub, sup { line-height: 0; }: stops them stretching the line height

Code Explained

=&gt;: the > of an arrow function, escaped
language-js: hook for highlighters; no effect on its own
nested <kbd>: a menu path or key combination
<samp>: the exact text the program printed
<sup><a>: footnote reference with an id to link back to

⚠ Common Mistakes

  • Forgetting to escape < in code samples: the browser renders tags instead of showing them
  • Using <pre> without <code> for code: highlighters and assistive tech lose the hint
  • Long <pre> lines without overflow-x: auto: they overflow the page on phones

✓ Tips & Best Practices

  • Highlight code at build time (Prism, Shiki, highlight.js)
  • Style <kbd> like a keycap: border, radius, small shadow
  • Turn off font ligatures in code if your font joins != or =>

Quick Summary

  • <code>: code fragment
  • <pre><code>: code block
  • <kbd> / <samp>: input / output
  • <sub> / <sup>: formulas, footnotes
