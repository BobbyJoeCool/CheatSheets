div and span

<div> (block) and <span> (inline) are generic containers with no meaning; they exist purely as hooks for CSS and JavaScript. Use them when no semantic element fits: layout wrappers, grid cells, a styled word. They aren't bad, but a page built only from divs ("div soup") gives browsers, search engines and assistive tech nothing to work with.

Notes

  • <div> defaults to display: block; <span> to display: inline
  • CSS can change an element's display, but not its meaning
  • <div> can't go inside <p>: the paragraph closes early
  • Both have the implicit ARIA role generic

♿ Accessibility

  • <div onclick> isn't focusable or announced as a button; use <button>
  • Screen readers ignore plain wrappers, so they're safe for layout
  • display: contents has dropped list and table semantics in some browsers; test it

Pairing with CSS

  • .wrapper { max-width: 70ch; margin-inline: auto; }: classic div job
  • span.price: style part of a sentence without changing its meaning
  • display: contents: removes the box so children join the parent grid/flex

Code Explained

.container / .grid: pure layout, so <div> is correct
<span class="price">: a styling hook inside text
onclick on <div>: no keyboard access, no role
<a href>: focusable, announced, opens in a new tab
block in <p>: the parser closes the paragraph

When div and span Are Right

<!-- layout wrapper: no semantic element fits -->
<div class="container">
  <div class="grid">
    <div class="grid-item">…</div>
    <div class="grid-item">…</div>
  </div>
</div>

<!-- style part of a sentence -->
<p>Total: <span class="price">$42.00</span></p>

<!-- ✖ div soup -->
<div class="header">
  <div class="nav">
    <div class="link" onclick="go('/')">Home</div>
  </div>
</div>

<!-- ✔ semantic version -->
<header>
  <nav>
    <a href="/">Home</a>
  </nav>
</header>

<!-- ✖ block inside a paragraph -->
<p>Intro <div>note</div> text</p>
<!-- parsed as:
     <p>Intro </p><div>note</div> text<p></p> -->

⚠ Common Mistakes

  • Making a clickable <div>: you then need role, tabindex and key handlers that <button> includes
  • Nesting a <div> in a <p> or <span>: invalid, and the DOM won't match your source
  • Wrapping everything in extra divs "just in case": deeper DOMs are slower and harder to style

✓ Tips & Best Practices

  • Reach for a semantic element first; use <div> when none fits
  • Name wrapper classes for purpose: .card, .stack, .cluster
  • Use display: contents sparingly to flatten wrappers

Quick Summary

  • <div>: block, no meaning
  • <span>: inline, no meaning
  • div soup: replace with semantics
  • block in <p>: invalid
