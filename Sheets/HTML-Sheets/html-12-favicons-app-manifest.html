Favicons & App Manifest

rel="icon" · sizes · SVG favicon · apple-touch-icon · manifest.webmanifest · base

Icons and Installable Sites

A favicon identifies your site in tabs, bookmarks and history. Modern browsers accept an SVG icon (which can adapt to dark mode), with an ICO or PNG fallback. Apple devices use apple-touch-icon for home-screen shortcuts. A web app manifest (JSON) names the app and lists its icons so it can be installed as a PWA. <base> sets the base URL for every relative link on the page.

Notes

  • Browsers request /favicon.ico automatically if no icon is declared
  • sizes helps the browser pick the right file: sizes="32x32"
  • apple-touch-icon should be a 180×180 PNG with no transparency
  • Only one <base> per page, placed before any other URL in <head>

♿ Accessibility

  • Icons are decorative to screen readers; the <title> names the tab
  • Give the manifest a clear name: it's announced for the installed app
  • Simple, high-contrast icons stay recognizable at 16×16 px

Pairing with CSS

  • SVG favicons can contain <style> with @media (prefers-color-scheme: dark)
  • Match the manifest's theme_color and background_color to your CSS
  • @media (display-mode: standalone): style the installed app differently

Code Explained

SVG icon: sharp at every size; CSS inside can switch colors
.ico with sizes="32x32": stops Chrome picking it over the SVG
manifest: needed for install prompts (served over HTTPS)
display: standalone: opens without browser UI
maskable: icon with a safe zone for Android's shapes

Icons, Manifest & base

<head>
  <!-- modern: one SVG -->
  <link rel="icon" href="/favicon.svg" type="image/svg+xml">

  <!-- fallbacks -->
  <link rel="icon" href="/favicon.ico" sizes="32x32">
  <link rel="icon" href="/icon-192.png" type="image/png"
        sizes="192x192">

  <!-- iOS home screen -->
  <link rel="apple-touch-icon" href="/apple-touch-icon.png">

  <!-- installable app -->
  <link rel="manifest" href="/manifest.webmanifest">

  <!-- base URL for relative links -->
  <base href="https://docs.example.com/v2/">
</head>

<!-- manifest.webmanifest -->
{
  "name": "Trailhead Outfitters",
  "short_name": "Trailhead",
  "start_url": "/",
  "display": "standalone",
  "theme_color": "#1b5e20",
  "background_color": "#ffffff",
  "icons": [
    { "src": "/icon-192.png", "sizes": "192x192",
      "type": "image/png" },
    { "src": "/icon-512.png", "sizes": "512x512",
      "type": "image/png" },
    { "src": "/icon-mask.png", "sizes": "512x512",
      "type": "image/png", "purpose": "maskable" }
  ]
}

⚠ Common Mistakes

  • Forgetting that <base href> also changes href="#top": the link points at the base URL
  • A transparent apple-touch-icon: iOS fills the transparent areas with black
  • Providing only a 16×16 icon: it looks blurry on high-DPI screens and home screens

✓ Tips & Best Practices

  • One SVG + ICO + apple-touch-icon + manifest covers nearly every device
  • Serve the manifest as application/manifest+json
  • Check DevTools → Application → Manifest for install problems

Quick Summary

  • rel="icon": tab favicon
  • apple-touch-icon: iOS shortcut
  • rel="manifest": installable PWA
  • <base>: base URL for relative links
