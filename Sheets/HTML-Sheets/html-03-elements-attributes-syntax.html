Elements, Attributes & Syntax

start/end tags · void elements · boolean attributes · attribute quoting · case-insensitivity · parser error recovery

Anatomy of an Element

An element is a start tag, content and an end tag: <p class="lead">Hi</p>. Attributes go in the start tag as name="value" pairs and configure the element. Void elements like <img> and <br> have no content and no end tag. HTML is case-insensitive and the parser recovers from most errors, but it recovers by guessing, so write well-formed markup.

Notes

  • Tag and attribute names are case-insensitive; write lowercase
  • Quotes are optional for simple values, but spaces break unquoted values
  • Boolean attributes are true when present: disabled, checked, hidden
  • A trailing slash (<br />) is allowed and ignored on void elements

♿ Accessibility

  • Native elements carry built-in roles: <button> is announced as "button"
  • Attributes like alt, for and aria-* supply accessible names
  • Misnested tags can scramble the reading order screen readers follow

Pairing with CSS

  • [disabled]: attribute-presence selector
  • a[href$=".pdf"]: value selectors; ^= starts, $= ends, *= contains
  • [lang|="en"]: matches en and en-US; add i for case-insensitive

Code Explained

checked="false": any value means true; remove the attribute to turn it off
void elements: area base br col embed hr img input link meta source track wbr
misnesting: the parser repairs it, often not the way you intended
unquoted values: end at a space, quote, =, <, > or backtick

Syntax Rules

<!-- element = start tag + content + end tag -->
<p class="lead">Welcome back!</p>

<!-- attributes: name="value", any order -->
<a href="/cart" title="View cart" class="btn">Cart</a>

<!-- boolean attributes: presence = true -->
<input type="checkbox" checked disabled>
<input type="checkbox" checked="">       <!-- same -->
<input type="checkbox" checked="false">  <!-- still on! -->

<!-- void elements: no content, no end tag -->
<img src="logo.png" alt="Trailhead">
<br>
<input type="text" name="q" />           <!-- / ignored -->

<!-- nesting: close in reverse order -->
<p><strong><em>Important</em></strong></p>   <!-- ✔ -->
<p><strong><em>Important</strong></em></p>   <!-- ✖ -->

<!-- attribute quoting -->
<div class=card>          <!-- OK: no spaces -->
<div class=card big>      <!-- ✖ big = 2nd attribute -->
<div class="card big">    <!-- ✔ two classes -->

⚠ Common Mistakes

  • Writing disabled="false" to enable a control: presence disables it no matter the value
  • Giving void elements content or an end tag: <img></img>, <input>text</input>
  • Misnesting inline tags (<b><i>…</b></i>): it renders, but the DOM differs from your source

✓ Tips & Best Practices

  • Always quote attribute values with double quotes
  • Use DevTools → Elements to see how the parser repaired your markup
  • Run the W3C validator to catch misnesting and unknown attributes

Quick Summary

  • <tag attr="v">…</tag>: element syntax
  • void element: no end tag, no content
  • boolean attribute: presence means true
  • lowercase + quoted: the safe style
