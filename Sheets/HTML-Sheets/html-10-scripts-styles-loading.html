Script & Style Loading

script · defer · async · type="module" · nomodule · style · noscript · render-blocking

Loading JavaScript and CSS

A plain <script src> blocks parsing: the browser stops building the page until the script downloads and runs. defer and async let parsing continue while the script downloads, and type="module" scripts are deferred automatically. Stylesheets and <style> are render-blocking on purpose, so the page doesn't flash unstyled content.

Notes

  • defer scripts run in document order, before DOMContentLoaded
  • async scripts run as soon as they arrive, in any order
  • Modules use strict mode, their own scope, import/export and CORS
  • nomodule scripts run only in browsers without module support

♿ Accessibility

  • Render-blocking scripts delay content, which hurts most on slow devices and assistive tech
  • <noscript> can explain what won't work without JavaScript
  • Build HTML that works first, then enhance it with script

Pairing with CSS

  • <style> in <head>: inline critical CSS for a faster first paint
  • <link rel="stylesheet"> in <body>: allowed, but blocks rendering of later content
  • .no-js / .js on <html>: a one-line script swaps it so CSS can adapt

Code Explained

classic <script>: parsing pauses while it downloads and runs
defer: download in parallel, run after parsing, in order
async: runs on arrival; order not guaranteed
importmap: maps bare names like lodash to URLs
type="module": add async to run on arrival instead

Loading Strategies

<head>
  <!-- render-blocking CSS (right for main styles) -->
  <link rel="stylesheet" href="/css/site.css">

  <!-- critical CSS inline -->
  <style>
    header { background: #102a43; color: white; }
  </style>

  <!-- classic: blocks parsing (avoid in <head>) -->
  <script src="/js/legacy.js"></script>

  <!-- defer: parse first, then run in order -->
  <script src="/js/vendor.js" defer></script>
  <script src="/js/app.js" defer></script>

  <!-- async: independent scripts (analytics) -->
  <script src="https://stats.example/a.js" async></script>

  <!-- import map: before any module that uses it -->
  <script type="importmap">
    { "imports": { "lodash": "/vendor/lodash.js" } }
  </script>

  <!-- ES module: deferred by default -->
  <script type="module" src="/js/main.js"></script>
  <script nomodule src="/js/legacy-bundle.js"></script>
</head>
<body>
  <noscript>Turn on JavaScript to use the cart.</noscript>
</body>

⚠ Common Mistakes

  • Classic scripts in <head> without defer: users see a blank page while they load
  • async on scripts that depend on each other: they can run in the wrong order
  • Expecting defer to affect inline scripts: it only applies to scripts with src

✓ Tips & Best Practices

  • Default to <script defer> in <head> for app code
  • Use async only for independent scripts such as analytics
  • Inline only the CSS needed for the first screen

Quick Summary

  • defer: in order, after parsing
  • async: whenever it arrives
  • type="module": deferred ES module
  • stylesheets: render-blocking
