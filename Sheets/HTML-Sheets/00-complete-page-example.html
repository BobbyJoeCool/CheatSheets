full document · all concepts · structure only · no CSS
About This Sheet
A complete, realistic HTML document using the concepts from every sheet in this set. No CSS is applied — this is pure structure and semantics. Comments in the code identify each concept as it appears. Read left column top-to-bottom, then right column top-to-bottom.
Concepts Used
DOCTYPE · lang · charset · viewport · title · meta · OG
Landmarks: header · nav · main · aside · footer
Semantic: article · section · figure · time · address · blockquote
Typography: h1–h3 · p · strong · em · abbr · code · kbd · mark
Lists: ul · ol · dl · nav pattern · role="list"
Table: thead · tbody · tfoot · th[scope] · caption
Media: img[srcset] · picture · figure · figcaption
Forms: fieldset · legend · label · input · select · button
Links: absolute · fragment · mailto · tel · download · rel
A11y: skip link · aria-label · aria-live · aria-describedby
Misc: details · dialog · template · data-* · sr-only
HTML Document — Part 1
<!-- ═══════════════════════════════════════════════
  DOCTYPE & ROOT  (Sheet 01 — Architecture)
  DOCTYPE must be the very first line.
  lang attribute sets document language for
  screen readers and search engines.
════════════════════════════════════════════════ -->
<!DOCTYPE html>
<html lang="en">

<!-- ═══════════════════════════════════════════════
  HEAD  (Sheet 02 — Head)
  Metadata only — nothing here renders visibly.
════════════════════════════════════════════════ -->
<head>
  <!-- Encoding: must appear within first 1024 bytes -->
  <meta charset="UTF-8" />

  <!-- Viewport: required for responsive design -->
  <meta name="viewport"
        content="width=device-width, initial-scale=1.0" />

  <!-- Title: tab label, bookmark name, SEO heading -->
  <title>Acme Journal — Web Development Articles</title>

  <!-- SEO meta -->
  <meta name="description"
        content="Articles and tutorials on HTML, CSS,
                 and JavaScript." />
  <link rel="canonical"
        href="https://acme.com/journal" />

  <!-- Open Graph: social share preview -->
  <meta property="og:title"
        content="Acme Journal" />
  <meta property="og:image"
        content="https://acme.com/og-journal.jpg" />
  <meta property="og:type" content="website" />

  <!-- Favicon set -->
  <link rel="icon"
        href="/favicon.svg" type="image/svg+xml" />
  <link rel="icon" href="/favicon.ico" sizes="any" />
  <link rel="apple-touch-icon"
        href="/apple-touch-icon.png" />

  <!-- CSS: linked in head, loads before body renders -->
  <link rel="stylesheet" href="/css/main.css" />

  <!-- JS: defer = parallel download, runs after DOM ready -->
  <script src="/js/app.js" defer></script>
</head>

<!-- ═══════════════════════════════════════════════
  BODY
  All visible content lives here.
════════════════════════════════════════════════ -->
<body>

  <!-- Skip link (Sheet 14 — A11y)
       First focusable element — keyboard users jump
       past repeated nav directly to main content.  -->
  <a href="#main-content" class="skip-link">
    Skip to main content
  </a>

  <!-- ═════════════════════════════════════════════
    HEADER LANDMARK  (Sheet 03 — Landmark Tags)
    Implicit ARIA role: banner (page-level only)
  ══════════════════════════════════════════════ -->
  <header>

    <!-- Logo: decorative image — alt="" skips it -->
    <a href="/">
      <img src="/img/logo.svg" alt="Acme Journal"
           width="140" height="40" />
    </a>

    <!-- Primary nav (Sheet 08 — Lists)
         nav landmark + ul list + role="list" to
         restore Safari semantics after CSS reset.   -->
    <nav aria-label="Primary">
      <ul role="list">
        <li><a href="/">Home</a></li>
        <li><a href="/articles">Articles</a></li>
        <li><a href="/topics">Topics</a></li>
        <li><a href="/about">About</a></li>
      </ul>
    </nav>

    <!-- Site search form (Sheet 13 — Forms) -->
    <form action="/search" method="get" role="search">
      <label for="site-search"
             class="sr-only">Search articles</label>
      <input type="search" id="site-search"
             name="q" placeholder="Search…"
             autocomplete="off" />
      <button type="submit">Search</button>
    </form>

  </header>

  <!-- Breadcrumb nav (Sheet 03 + 08)
       Second nav — labelled to distinguish it from
       the primary nav above.                        -->
  <nav aria-label="Breadcrumb">
    <ol>
      <li><a href="/">Home</a></li>
      <li><a href="/articles">Articles</a></li>
      <li aria-current="page">Semantic HTML Guide</li>
    </ol>
  </nav>

  <!-- ═════════════════════════════════════════════
    MAIN LANDMARK  (Sheet 03)
    One per page. id targeted by skip link above.
  ══════════════════════════════════════════════ -->
  <main id="main-content">

    <!-- Live region (Sheet 14 — A11y)
         JS writes status messages here;
         screen readers announce on change.          -->
    <div aria-live="polite" aria-atomic="true">
      <p id="status-msg"></p>
    </div>

    <!-- ═══════════════════════════════════════════

      <!-- Section 1: Introduction (Sheet 04) -->
      <section>
        <h2>What Is Semantic HTML?</h2>

        <!-- Paragraph with inline text elements (Sheet 07) -->
        <p>
          <dfn>Semantic HTML</dfn> means choosing elements
          for their <em>meaning</em>, not their appearance.
          A <code><button></code> is <strong>always</strong>
          better than a <code><div onclick></code> because the
          browser provides keyboard support and the correct
          <abbr title="Accessible Rich Internet Applications">
            ARIA
          </abbr>
          role automatically.
        </p>

        <!-- blockquote (Sheet 04) -->
        <blockquote cite="https://w3.org/TR/html-design">
          <p>
            The Web's markup language has always been HTML.
            HTML is not XML, though it can be written in an
            XML-compatible syntax.
          </p>
          <footer>
            — <cite>W3C HTML Design Principles</cite>
          </footer>
        </blockquote>

        <!-- mark: search result highlight (Sheet 07) -->
        <p>
          Searching for <mark>semantic HTML</mark> returns
          over 2 million results — it is a foundational topic.
        </p>

      </section>
HTML Document — Part 2
      <!-- Section 2: Element types (Sheet 04) -->
      <section>
        <h2>Block vs Inline Elements</h2>

        <!-- Unordered list (Sheet 08) -->
        <ul>
          <li>
            <strong>Block elements</strong> — start on a new
            line: <code><p></code>, <code><div></code>,
            <code><section></code>
          </li>
          <li>
            <strong>Inline elements</strong> — flow in text:
            <code><span></code>, <code><a></code>,
            <code><strong></code>
          </li>
          <li>
            <strong>Void elements</strong> — no closing tag:
            <code><img></code>, <code><br></code>,
            <code><input></code>
          </li>
        </ul>

        <!-- sub, sup, del, ins (Sheet 07) -->
        <p>
          Chemical formula: H<sub>2</sub>O.
          Einstein: E = mc<sup>2</sup>.
          Price: <del>$49/mo</del> now <ins>$29/mo</ins>.
        </p>

        <!-- kbd (Sheet 07) -->
        <p>
          Press <kbd>Ctrl</kbd> + <kbd>S</kbd> to save,
          or <kbd>Ctrl</kbd> + <kbd>Z</kbd> to undo.
        </p>
      </section>

      <!-- Section 3: Steps — ordered list (Sheet 08) -->
      <section>
        <h2>How to Write Semantic HTML</h2>
        <ol>
          <li>Identify the content type before picking a tag</li>
          <li>Choose the most specific semantic element</li>
          <li>Fall back to <code><div></code> only when
              no semantic element fits</li>
          <li>Validate with the W3C validator</li>
          <li>Test with a screen reader</li>
        </ol>
      </section>

      <!-- Section 4: Data table (Sheet 09 — Tables) -->

      </section>

        <h2>Frequently Asked Questions</h2>

        <details>
          <summary>
            Is <code><div></code> ever acceptable?
          </summary>
          <p>
            Yes — when no semantic element fits. Use it as a
            layout wrapper or a JS hook. Prefer semantic tags
            whenever a meaningful choice exists.
          </p>
        </details>

        <details>
          <summary>
            Do I need ARIA if I use semantic HTML?
          </summary>
          <p>
            Mostly no. Semantic HTML provides free roles and
            states. Add ARIA only to fill gaps: custom widgets,
            live regions, and explicit label associations.
          </p>
        </details>
      </section>
