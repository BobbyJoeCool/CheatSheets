Accessibility Fundamentals

semantic HTML · alt text · heading order · lang · WCAG · accessible name

Building for Everyone

Accessibility (a11y) means people with disabilities can perceive, operate and understand your site, whether they use a screen reader, keyboard, switch device, voice control or zoom. HTML does most of the work: semantic elements expose roles, names and states to the accessibility tree automatically. The standard is WCAG 2.2, built on four principles: perceivable, operable, understandable, robust (POUR).

Notes

  • Level AA is the usual legal and contract target
  • Every image needs alt; every control needs a label
  • About 1 in 6 people worldwide lives with a significant disability (WHO, 2023)
  • Accessible name = what's announced: label, text, alt or aria-label

♿ Accessibility

  • Test with the keyboard only: Tab, Shift+Tab, Enter, Space, Esc, arrows
  • Test with a screen reader: VoiceOver (Mac/iOS), NVDA (Windows), TalkBack (Android)
  • Automated checkers (axe, Lighthouse) catch only part of the problems

Pairing with CSS

  • :focus-visible: never remove focus outlines without a replacement
  • @media (prefers-reduced-motion: reduce): tone down animation
  • .visually-hidden: hides text visually but keeps it for screen readers

Code Explained

skip link: first focusable element; jumps past the header
alt: describes what matters about this photo
<label for>: the date input's name
role="status": announces results politely
aria-label: names an icon-only button
.visually-hidden: extra context for screen-reader users

Accessible by Default

<html lang="en">
<body>
  <a class="skip-link" href="#main">Skip to content</a>
  <header>…</header>
  <main id="main">
    <h1>Book a campsite</h1>

    <img src="site-12.jpg" width="600" height="400"
         alt="Campsite 12: tent pad beside a creek">

    <form>
      <label for="arrive">Arrival date</label>
      <input id="arrive" name="arrive" type="date"
             required>
      <button type="submit">Check availability</button>
    </form>

    <p role="status" id="result"></p>

    <button type="button" aria-label="Add to favorites">
      <svg aria-hidden="true">…</svg>
    </button>

    <a href="/map" target="_blank">Park map
      <span class="visually-hidden">(new tab)</span></a>
  </main>
</body>
</html>

POUR Principles

PrincipleMeansExamples
Perceivableusers can sense italt text, captions, contrast
Operableusers can use itkeyboard, enough time
Understandableusers can follow itlabels, clear errors, lang
Robustworks with assistive techvalid HTML, correct roles

⚠ Common Mistakes

  • Adding ARIA to fix what native HTML would avoid: wrong ARIA is worse than none
  • Testing only with a mouse: keyboard traps and invisible focus go unnoticed
  • Showing meaning by color alone (red = error): add text or an icon

✓ Tips & Best Practices

  • Use native elements first; add ARIA only to fill gaps
  • Add accessibility checks to code review and CI (axe-core, Pa11y)
  • Zoom to 200% and 400% and check that nothing is cut off

Quick Summary

  • WCAG 2.2 AA: the usual target
  • POUR: the four principles
