Keyboard Access and Focus Management

Everything you can do with a mouse must also work with a keyboard. Native links, buttons and form controls are focusable and follow DOM order. tabindex="0" adds an element to the tab order and -1 makes it focusable only by script. Manage focus when content changes (dialogs, new views, errors), keep focus visible, and offer a skip link past repeated navigation.

Notes

  • Tab order follows the DOM, not the visual layout; CSS order and grid placement don't change it
  • tabindex above 0 jumps ahead of everything else; avoid it
  • inert removes a whole region from the tab order and from assistive tech
  • accesskey shortcuts clash with browser and screen-reader keys; rarely worth it

♿ Accessibility

  • WCAG 2.4.7: focus must be visible; 2.4.11: not hidden behind sticky headers
  • WCAG 2.1.2: no keyboard traps; users must be able to Tab away
  • After deleting an item or closing a panel, move focus somewhere logical

Pairing with CSS

  • :focus-visible { outline: 3px solid #1b5e20; outline-offset: 2px; }: keyboard focus ring
  • :focus-within: highlight a form row or menu that contains focus
  • scroll-padding-top: 4rem: keeps focused elements clear of sticky headers

Code Explained

skip link: hidden off-screen until it receives focus
tabindex="-1" on <main>: lets the skip link move focus there
tabindex="0": the custom control joins the tab order
h1.focus(): screen readers announce the new view
inert: background is unreachable while the drawer is open

Skip Links and Focus Management

<body>
  <!-- first focusable element on the page -->
  <a class="skip-link" href="#main">Skip to content</a>
  <header>…nav with 30 links…</header>

  <main id="main" tabindex="-1">
    <h1>Search results</h1>
    <ul id="results">…</ul>
  </main>

  <!-- custom control made focusable -->
  <div class="swatch" role="button" tabindex="0"
       aria-pressed="false">Moss</div>
</body>

<style>
  .skip-link { position: absolute; left: -999px; }
  .skip-link:focus { left: 1rem; top: 1rem; }
  :focus-visible { outline: 3px solid #1b5e20; }
</style>

<script>
  // after new results load, focus the heading
  const h1 = document.querySelector('main h1');
  h1.tabIndex = -1;
  h1.focus();

  // make the page behind an open drawer unreachable
  document.querySelector('main').inert = true;
</script>

⚠ Common Mistakes

  • outline: none with no replacement: keyboard users lose track of where they are
  • Positive tabindex values: the whole page's order becomes unpredictable
  • Opening a modal or drawer without moving focus into it: keyboard users stay behind the overlay

✓ Tips & Best Practices

  • Unplug the mouse and finish every task with the keyboard
  • Use :focus-visible so keyboard users see rings and mouse users don't
  • Use inert on background content instead of hand-built focus traps

Quick Summary

  • DOM order: defines Tab order
  • tabindex: 0 adds, -1 script-only
  • :focus-visible: always show focus
  • skip link: bypass repeated navigation
