Buttons and Submit Behavior

<button> is the element for actions, and its type decides what it does: **submit (the default inside a form) sends the form, reset restores the initial values, and button** does nothing until JavaScript handles it. A submit button can override the form's settings with formaction, formmethod and formnovalidate. The form attribute links a control to a form elsewhere on the page.

Notes

  • Pressing Enter in a text field submits through the first submit button
  • A submit button's name/value is sent only for the button that was clicked
  • <input type="submit"> shows only plain text; <button> can hold icons and markup
  • type="hidden" inputs send values users can't see or edit

♿ Accessibility

  • Buttons are focusable and work with Enter and Space automatically
  • Icon-only buttons need aria-label or visually hidden text
  • disabled buttons can't be focused; consider aria-disabled="true" plus a reason

Pairing with CSS

  • button:focus-visible: a clear focus ring for keyboard users
  • button:disabled / [aria-disabled="true"]: style unavailable actions
  • all: unset on buttons also removes the focus outline; add it back

Code Explained

name="intent": the server sees intent=publish or intent=draft
formaction + formnovalidate: drafts save even when incomplete
type="reset": rarely wanted and easy to click by accident
type="button": no default action
form="editor": joins the form by its id

Button Types and Overrides

<form action="/posts" method="post" id="editor">
  <label for="title">Title</label>
  <input id="title" name="title" required>
  <input type="hidden" name="draft_id" value="d-311">

  <!-- default: submit -->
  <button type="submit" name="intent" value="publish">
    Publish
  </button>

  <!-- same form: another URL, skip validation -->
  <button type="submit" name="intent" value="draft"
          formaction="/drafts" formnovalidate>
    Save draft
  </button>

  <!-- back to initial values -->
  <button type="reset">Clear</button>

  <!-- JS-only action: not a submit -->
  <button type="button" id="preview">Preview</button>
</form>

<!-- control outside the form -->
<button type="submit" form="editor">Publish</button>

<!-- icon-only -->
<button type="button" aria-label="Delete draft">
  <svg aria-hidden="true"><use href="#i-trash"/></svg>
</button>

<!-- image as a submit button -->
<input type="image" src="go.png" alt="Search">

⚠ Common Mistakes

  • Leaving out type="button" on non-submit buttons in a form: clicking them submits the form
  • Using <a href="#"> or a <div> for actions: no keyboard support, wrong semantics
  • Disabling the submit button until the form is valid: users can't discover what's missing

✓ Tips & Best Practices

  • Write type on every <button>
  • Use name / value on submit buttons for multi-action forms
  • Prevent double submits by disabling the button after the first click

Quick Summary

  • type="submit": default, sends the form
  • type="button": JS actions
  • formaction & co.: per-button overrides
  • form attribute: control outside the form
