Element Cheat Sheet

A one-page map of the elements in this set, grouped by purpose, with the sheet to turn to for details. Choose elements by meaning, not by their default look. CSS can make anything look like anything, but only the right element gives browsers, search engines and assistive tech the right information.

Notes

  • Document elements: html, head, body, title, meta, link, script, style, base
  • CSS can change an element's display, but never its meaning
  • Obsolete elements (center, font, marquee) still render but are invalid
  • When nothing fits, use div (block) or span (inline)

♿ Accessibility

  • Landmarks: header, nav, main, aside, footer, search
  • Native interactive: a[href], button, input, select, textarea, details, dialog
  • Everything interactive needs a name: text, label, alt or aria-label

Pairing with CSS

  • Type selectors use these names: nav a, table th, dialog::backdrop
  • Most elements reset with margin: 0; lists and buttons need more
  • Use classes for variants; keep type selectors for base styles

⚠ Common Mistakes

  • Choosing elements for their default look (h4 for small bold text, blockquote to indent)
  • Using div / span where a semantic element exists
  • Forgetting required partners: li in lists, dt/dd in dl, summary in details

✓ Tips & Best Practices

  • Decide what the content means, then pick elements, then style
  • Keep this sheet beside the attributes reference (sheet 56)
  • Check an element's content model on MDN before nesting
