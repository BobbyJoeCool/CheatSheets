Labeling Controls

Every form control needs a label. <label for="id"> (or a label wrapped around the control) connects visible text to the control: it becomes the control's accessible name and makes the text clickable. <fieldset> + <legend> group related controls under one question. autocomplete tokens let browsers autofill, inputmode picks the virtual keyboard, and enterkeyhint labels the Enter key.

Notes

  • for must match the control's id exactly
  • A control can have several labels; each label targets one control
  • <fieldset disabled> disables every control inside it
  • Put hints in a separate element linked with aria-describedby

♿ Accessibility

  • The label is the accessible name, read whenever the control gets focus
  • <legend> is read with each control: "Shipping speed, Express, radio button"
  • Mark required fields in the label text, not only with color

Pairing with CSS

  • label { display: block; }: label above the field
  • fieldset { border: 0; padding: 0; margin: 0; min-width: 0; }: reset the default box
  • .field:has(:user-invalid) label { color: crimson; }: style labels from control state

Code Explained

for="email": clicking the label focuses the input
aria-describedby: hint read after the label
wrapping label: no for / id needed
shipping street-address: section token + field token
one-time-code: SMS codes autofill on phones

Labels, Groups and Hints

<!-- explicit label + hint -->
<label for="email">Email (required)</label>
<input id="email" name="email" type="email"
       autocomplete="email" required
       aria-describedby="email-hint">
<p id="email-hint">We'll send your receipt here.</p>

<!-- implicit label (wrapping) -->
<label>
  <input type="checkbox" name="terms" required>
  I agree to the <a href="/terms">terms</a>
</label>

<!-- group with a legend -->
<fieldset>
  <legend>Delivery address</legend>
  <label for="street">Street</label>
  <input id="street" name="street"
         autocomplete="shipping street-address">
  <label for="zip">ZIP</label>
  <input id="zip" name="zip" inputmode="numeric"
         autocomplete="shipping postal-code">
</fieldset>

<!-- mobile keyboard hints -->
<label for="code">Verification code</label>
<input id="code" name="code" inputmode="numeric"
       autocomplete="one-time-code" enterkeyhint="done">

⚠ Common Mistakes

  • A label whose for doesn't match the id (often after copy-paste): the control has no name
  • Radio groups without <fieldset> / <legend>: users hear "Yes, radio button" without the question
  • Turning autocomplete off everywhere: forms get slower, especially on phones

✓ Tips & Best Practices

  • Keep labels visible above or beside the field, never only inside it
  • Browsers often ignore autocomplete="off" on login fields; use it only for one-time values
  • Put format hints ("MM/YY") in aria-describedby text, not the placeholder

Quick Summary

  • <label for>: names the control
  • <fieldset> + <legend>: group question
  • autocomplete: autofill tokens
  • inputmode / enterkeyhint: phone keyboard
