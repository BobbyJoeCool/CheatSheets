Constraint Validation

required · pattern · min · max · step · minlength · :invalid · setCustomValidity()

Built-In Validation

Browsers check forms before submitting them using constraint attributes: required, pattern, min / max, step, minlength / maxlength and the input type itself. Invalid controls block submission and the browser shows a message. CSS pseudo-classes style valid and invalid states, and the Constraint Validation API (checkValidity(), setCustomValidity()) adds custom rules and messages.

Notes

  • pattern must match the whole value; no ^…$ needed
  • Validation runs on submit unless novalidate or formnovalidate is set
  • Client-side checks are for usability; always validate on the server too
  • :user-invalid matches only after the user has interacted

♿ Accessibility

  • Native error bubbles disappear quickly; also show lasting error text near the field
  • Set aria-invalid="true" and link the message with aria-describedby
  • On submit, move focus to the first invalid field or to an error summary

Pairing with CSS

  • :user-invalid: red border only after interaction, unlike :invalid on page load
  • :required / :optional; :in-range / :out-of-range for numbers
  • .field:has(:user-invalid) .error { display: block; }: reveal error text

Code Explained

pattern: lowercase letters, digits and underscores only
novalidate: no native bubbles; the script decides
setCustomValidity(''): empty string makes the field valid again
checkValidity(): returns false and fires invalid events
el.validationMessage: the browser's text for the current error

Constraints and the API

<form id="signup" novalidate>
  <label for="user">Username</label>
  <input id="user" name="user" required
         minlength="3" maxlength="20"
         pattern="[a-z0-9_]+"
         aria-describedby="user-err">
  <p id="user-err" class="error"></p>

  <label for="age">Age</label>
  <input id="age" name="age" type="number"
         min="13" max="120" required>

  <label for="pw">Password</label>
  <input id="pw" name="pw" type="password"
         minlength="8" required>
  <label for="pw2">Confirm password</label>
  <input id="pw2" name="pw2" type="password" required>

  <button>Create account</button>
</form>

<script>
  const form = document.getElementById('signup');
  form.addEventListener('submit', (e) => {
    const same = form.pw2.value === form.pw.value;
    form.pw2.setCustomValidity(same ? '' : 'No match');
    if (!form.checkValidity()) {
      e.preventDefault();
      form.querySelector(':invalid').focus();
    }
  });
</script>

⚠ Common Mistakes

  • Styling :invalid with red borders: required fields look broken before the user types
  • Never clearing setCustomValidity with '': the field stays invalid forever
  • Relying only on client-side checks: anyone can bypass the browser

✓ Tips & Best Practices

  • Prefer :user-invalid over :invalid for error styles
  • Use the el.validity flags to write specific error messages
  • Show all errors at once in a summary that links to each field

Quick Summary

  • required, pattern, min/max: constraints
  • :user-invalid: styles after interaction
  • setCustomValidity(): custom rules
  • server validation: always required
