ARIA States & Properties

aria-label · aria-labelledby · aria-describedby · aria-expanded · aria-hidden · aria-live · aria-current

Names, Descriptions and Live Updates

ARIA properties describe names and relationships (aria-label, aria-labelledby, aria-describedby, aria-controls). ARIA states describe conditions that change (aria-expanded, aria-checked, aria-current, aria-invalid). Live regions (aria-live, role="status", role="alert") announce content that updates without moving focus. Scripts must keep states in sync with the screen.

Notes

  • Name priority: aria-labelledby > aria-label > native label or content
  • aria-label works on interactive elements and landmarks, not plain <div> / <span>
  • aria-hidden="true" hides content from assistive tech, not from the screen
  • A live region must exist in the DOM before its content changes

♿ Accessibility

  • aria-describedby adds hints after the name: "Password, edit text, 8+ characters"
  • Use aria-live="polite" for most updates; assertive interrupts the user
  • Never put aria-hidden="true" on focusable elements

Pairing with CSS

  • [aria-expanded="true"] .chevron { rotate: 180deg; }: visuals follow state
  • [aria-current="page"]: highlight the current nav link
  • [aria-invalid="true"]: error styling tied to the announced state

Code Explained

aria-expanded: the script flips it along with the panel
aria-current="page": read as "Shop, current page, link"
aria-labelledby: names the list from the heading
aria-describedby: reads both the rule and the error
btn.ariaExpanded: ARIA reflection, a property for the attribute

States, Names and Live Regions

<!-- disclosure button with state -->
<button type="button" aria-expanded="false"
        aria-controls="filters">Filters</button>
<div id="filters" hidden>…</div>

<!-- current page in navigation -->
<nav aria-label="Main">
  <a href="/shop" aria-current="page">Shop</a>
  <a href="/blog">Blog</a>
</nav>

<!-- name from visible text elsewhere -->
<h2 id="cart-h">Your cart</h2>
<ul aria-labelledby="cart-h">…</ul>

<!-- description + invalid state -->
<label for="pw">Password</label>
<input id="pw" type="password" aria-invalid="true"
       aria-describedby="pw-rule pw-err">
<p id="pw-rule">At least 8 characters.</p>
<p id="pw-err">Too short.</p>

<!-- polite live region -->
<p aria-live="polite" id="cart-count">2 items</p>

<!-- decorative symbol hidden -->
<span aria-hidden="true">★</span> Favorite

<script>
  const btn = document.querySelector('[aria-controls]');
  btn.addEventListener('click', () => {
    const open = btn.ariaExpanded === 'true';
    btn.ariaExpanded = String(!open);
    document.getElementById('filters').hidden = open;
  });
</script>

⚠ Common Mistakes

  • aria-label on a <div> or <span> with no role: most screen readers ignore it
  • Forgetting to update aria-expanded when the panel opens: users hear the wrong state
  • Inserting a live region together with its message: often not announced; add it first, then change the text

✓ Tips & Best Practices

  • Prefer aria-labelledby pointing at visible text so names match what sighted users see
  • Use role="status" for "Saved", result counts and cart totals
  • Style with ARIA attribute selectors so state and looks can't drift apart

Quick Summary

  • aria-label / aria-labelledby: names
  • aria-describedby: hints and errors
  • aria-expanded / current / invalid: states
  • aria-live / role="status": announcements
