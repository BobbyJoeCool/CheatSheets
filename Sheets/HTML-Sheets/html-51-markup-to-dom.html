Markup to DOM

DOM tree · attributes vs properties · getElementById · document.forms · form.elements · DOMContentLoaded

How HTML Becomes the DOM

The browser parses HTML into the DOM, a tree of objects JavaScript can read and change. Each element becomes a node, and most attributes are reflected as properties (input.id, a.href). Attributes and properties aren't always the same, though: the value attribute is the initial value, while the value property is the current one. Forms also get collections like document.forms and form.elements. (DOM methods in depth: JavaScript set.)

Notes

  • DOMContentLoaded fires once the HTML is parsed; load also waits for images and CSS
  • a.href returns the full absolute URL; getAttribute('href') returns what you wrote
  • class ↔ className / classList; for ↔ htmlFor
  • Named controls are available as form.elements.email (or form.email)

♿ Accessibility

  • Changing the DOM announces nothing; use live regions or move focus
  • DOM order is the reading and Tab order; keep it logical
  • Toggle attributes (hidden, aria-expanded) rather than inline styles so semantics update

Pairing with CSS

  • CSS matches the parsed DOM: the auto-inserted <tbody> means table > tr never matches
  • Attribute selectors read attributes, not properties: input[value="x"] ignores typing
  • :checked and :user-invalid do track the live state

Code Explained

value property: what's in the field right now
defaultValue: reflects the value attribute
href property: resolved to an absolute URL
document.forms / form.elements: access by name
toggleAttribute: handy for boolean attributes

Attributes vs Properties

<form name="signup" id="signup">
  <input id="email" name="email" type="email"
         value="you@example.com">
  <input name="agree" type="checkbox" checked>
  <a id="terms" href="/terms">Terms</a>
</form>

<script>
  document.addEventListener('DOMContentLoaded', () => {
    const email = document.getElementById('email');

    email.value = 'jo@example.com'; // current value
    email.getAttribute('value');    // "you@example.com"
    email.defaultValue;             // "you@example.com"

    const terms = document.getElementById('terms');
    terms.href;                // "https://ex.com/terms"
    terms.getAttribute('href'); // "/terms"

    const form = document.forms.signup; // by name
    form.elements.agree.checked;    // true (live)
    form.elements.email === email;  // true

    email.dataset.step = '1';  // adds data-step="1"
    email.toggleAttribute('required'); // add/remove
  });
</script>

⚠ Common Mistakes

  • Reading getAttribute('value') to get user input: it returns the initial value
  • Writing CSS for table > tr: the parser inserts <tbody>, so it never matches
  • Querying elements from a <head> script without defer: they don't exist yet

✓ Tips & Best Practices

  • Use properties for live state and attributes for initial / serialized state
  • Read every field at once with new FormData(form)
  • Inspect the parsed DOM in DevTools to debug selector mismatches

Quick Summary

  • DOM: the parsed tree of nodes
  • attribute: the markup / initial value
  • property: the live state
  • form.elements: named controls
