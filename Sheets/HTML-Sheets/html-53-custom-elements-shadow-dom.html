Custom Elements & Shadow DOM

customElements.define · connectedCallback · observedAttributes · attachShadow · shadowrootmode · :host · ::part

Web Components

Web components are reusable custom elements built from browser standards. Custom elements register a class for a hyphenated tag name with customElements.define(). Shadow DOM gives an element its own encapsulated tree: styles inside don't leak out, and page styles don't leak in (except inherited properties and custom properties). Declarative shadow DOM (<template shadowrootmode>) creates the shadow root in plain HTML, before any JS runs.

Notes

  • Custom element names must contain a hyphen: trail-card
  • Lifecycle: connectedCallback, disconnectedCallback, attributeChangedCallback
  • static observedAttributes lists the attributes to watch
  • mode: 'open' exposes el.shadowRoot; closed hides it

♿ Accessibility

  • Custom elements have no implicit role; use native elements inside or set a role via ElementInternals
  • aria-labelledby can't point across a shadow boundary (ids are scoped)
  • Form-associated custom elements (static formAssociated = true) work with labels and forms

Pairing with CSS

  • :host / :host([difficulty]): style the element from inside its shadow root
  • ::part(title): style exposed internals from the page (part="title" inside)
  • trail-card:not(:defined): hide components until they're registered

Code Explained

shadowrootmode="open": the parser creates the shadow root
:host([difficulty="hard"]): reacts to the host's attribute
part="title": lets page CSS use ::part(title)
observedAttributes: triggers attributeChangedCallback
:not(:defined): avoids a flash before the class is defined

A Small Web Component

<trail-card difficulty="hard">
  <template shadowrootmode="open">
    <style>
      :host { display: block; border: 1px solid #ccc; }
      :host([difficulty="hard"]) { border-color: red; }
    </style>
    <h3 part="title"><slot name="title"></slot></h3>
    <slot></slot>
  </template>
  <span slot="title">Ridge Loop</span>
  <p>12 km with 600 m of climbing.</p>
</trail-card>

<script>
  class TrailCard extends HTMLElement {
    static observedAttributes = ['difficulty'];
    connectedCallback() {
      if (!this.shadowRoot) {
        this.attachShadow({ mode: 'open' });
      }
    }
    attributeChangedCallback(name, oldVal, newVal) {
      console.log(`${name}: ${oldVal} → ${newVal}`);
    }
  }
  customElements.define('trail-card', TrailCard);
</script>

<style>
  trail-card::part(title) { font-size: 1.25rem; }
  trail-card:not(:defined) { visibility: hidden; }
</style>

What Crosses the Shadow Boundary

ThingCrosses?
inherited properties (color, font)yes
custom properties (--brand)yes
page selectors (.card p)no
::part()yes, opt-in
ids for aria-labelledbyno
composed eventsyes, retargeted to the host

⚠ Common Mistakes

  • Naming a custom element without a hyphen: customElements.define() throws
  • Forgetting that shadow DOM blocks page styles: global button styles won't reach inside
  • Heavy setup in the constructor: attributes and children may not exist yet; use connectedCallback

✓ Tips & Best Practices

  • Use declarative shadow DOM for server-rendered components
  • Expose theming through custom properties and ::part()
  • Use native elements inside components to keep their accessibility

Quick Summary

  • customElements.define(): register a tag
  • shadow DOM: encapsulated styles and markup
  • shadowrootmode: declarative shadow root
  • :host / ::part(): style in and out
