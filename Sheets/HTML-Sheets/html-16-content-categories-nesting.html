Content Categories & Nesting

flow · phrasing · interactive · transparent · implied </p> · invalid nesting

What Can Go Inside What

Every element belongs to content categories that decide where it may appear. Most body elements are flow content; text-level elements like <a>, <em> and <span> are phrasing content. Each element also has a content model saying what it may contain: <p> takes only phrasing content, <ul> takes only <li>, and interactive elements can't contain other interactive elements.

Notes

  • <a> is transparent: it may contain whatever its parent allows, minus interactive content
  • <p> closes automatically before blocks like <div>, <ul> or <table>
  • <button> and <a> can't contain links, buttons or inputs
  • <li> must be a child of <ul>, <ol> or <menu>

♿ Accessibility

  • Invalid nesting builds a DOM that assistive tech reads differently from your intent
  • Nested interactive elements (<a> in <button>) give unpredictable focus and clicks
  • A whole card wrapped in <a> becomes one very long link name

Pairing with CSS

  • a.card { display: block; }: a block link can wrap a whole card
  • .card:has(a:focus-visible): style the card when its link has focus
  • CSS display never changes the content model: a block-styled <span> still can't hold a <div>

Code Explained

<a> around <h3> + <p>: valid; the link inherits its parent's flow model
<button> in <a>: invalid; which one handles the click?
<ul> in <p>: <p> ends before the list; the stray </p> adds an empty paragraph
card pattern: stretch the heading link over the card with CSS ::after

Valid and Invalid Nesting

<!-- ✔ phrasing inside phrasing -->
<p>Read the <a href="/guide"><em>full</em> guide</a>.</p>

<!-- ✔ transparent <a> around flow content -->
<a href="/boots/tr3" class="card">
  <h3>Trail Runner 3</h3>
  <p>$129</p>
</a>

<!-- ✖ interactive inside interactive -->
<a href="/cart"><button>Add</button></a>
<button>Save <a href="/help">?</a></button>

<!-- ✖ block inside <p> -->
<p><ul><li>Item</li></ul></p>

<!-- ✖ wrong child of a list -->
<ul>
  <div><li>Item</li></div>
</ul>

<!-- ✔ card with a link and a button -->
<article class="card">
  <h3><a href="/boots/tr3">Trail Runner 3</a></h3>
  <button type="button">Add to cart</button>
</article>

⚠ Common Mistakes

  • Putting a <div> or a list inside <p>: the paragraph splits and selectors stop matching
  • Nesting a button inside a link for a "clickable card": invalid and confusing for keyboard users
  • Using <span> as a block wrapper "because it's just styling": the content model still applies

✓ Tips & Best Practices

  • Check the "Content model" box on each element's spec or MDN page
  • Use the stretched-link ::after pattern for cards with extra buttons
  • Validate rendered pages: nesting errors often come from combined components

Quick Summary

  • flow / phrasing: where elements may go
  • content model: what an element may hold
  • <a>: transparent, no interactive inside
  • never nest interactive elements
