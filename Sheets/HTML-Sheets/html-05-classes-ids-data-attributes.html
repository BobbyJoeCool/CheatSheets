Sheet 05

Classes, IDs & data-*

class · id · uniqueness · data-* · dataset · naming conventions · fragment targets

Hooks for CSS and JavaScript

class and id add no meaning; they're hooks. A class groups any number of elements for styling and scripting, and one element can have many classes. An id must be unique in the document, and it also works as a link target (#id) and as a reference for for and aria-labelledby. data-* attributes store custom values for scripts without inventing invalid attributes.

Notes

  • IDs are case-sensitive and can't contain whitespace
  • class is a space-separated list: class="btn btn-primary"
  • Each id also becomes a global JS variable (window.save); don't rely on it
  • data-user-id → el.dataset.userId (kebab-case to camelCase)

♿ Accessibility

  • Duplicate IDs break for, aria-labelledby and aria-describedby links
  • Classes add no meaning: <div class="button"> is still not a button
  • Skip links and in-page navigation rely on unique, stable IDs

Pairing with CSS

  • .btn: class selector (0,1,0); #nav: ID selector (1,0,0)
  • [data-state="open"]: style directly from data attributes
  • :target: the element whose id matches the URL #fragment

Code Explained

classList: add, remove, toggle, contains, replace
dataset: values are always strings; convert them
#faq: the page scrolls to id="faq" and :target matches it
for="email": must match the input's id exactly

Hooks in Practice

<!-- several classes, one unique id -->
<button id="save" class="btn btn-primary" type="submit">
  Save
</button>

<!-- data-* for script data -->
<article class="product"
         data-product-id="A-1042"
         data-price="19.99"
         data-in-stock="true">
  <h3>Desk Lamp</h3>
</article>

<!-- id as a link target -->
<a href="#faq">Jump to FAQ</a>
<section id="faq">…</section>

<!-- id as a label reference -->
<label for="email">Email</label>
<input id="email" type="email">

<script>
  const card = document.querySelector('.product');
  card.dataset.productId;        // "A-1042"
  Number(card.dataset.price);    // 19.99 (strings!)
  card.dataset.inStock = false;  // sets "false"
  card.classList.toggle('is-selected');
</script>

⚠ Common Mistakes

  • Reusing an id on several elements: getElementById and labels only find the first
  • Styling with #id everywhere: the high specificity makes overrides painful
  • Storing objects in data-* without JSON.stringify: you get "[object Object]"

✓ Tips & Best Practices

  • Style with classes; reserve IDs for links, labels and ARIA references
  • Use data-* for state that CSS also needs: [data-state="open"]
  • Name classes for purpose (.alert), not looks (.red-text)

Quick Summary

  • class: reusable, many per element
  • id: unique; links, labels, ARIA
  • data-*: custom data via el.dataset
  • :target: styles the #fragment element
