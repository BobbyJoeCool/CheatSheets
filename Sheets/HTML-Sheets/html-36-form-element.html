The Form Element

form · action · method · enctype · name · novalidate · autocomplete · target

Collecting and Sending Data

<form> groups controls and sends their values to a server. action is the URL to send to and method is how: GET puts values in the URL query string (searches, filters), while POST sends them in the request body (logins, orders, anything that changes data). Only controls with a name are submitted, and enctype must be multipart/form-data to upload files.

Notes

  • Without action, the form submits to the current URL
  • The default method is GET; method="dialog" closes a <dialog> (sheet 45)
  • Disabled controls aren't submitted; readonly ones are
  • novalidate turns off built-in validation for the whole form

♿ Accessibility

  • Every control needs a visible label (sheet 42)
  • A form with an accessible name (aria-labelledby) becomes a form landmark
  • After submitting, move focus to the success message or the first error

Pairing with CSS

  • form:invalid / :valid: style the form from its controls' state
  • form:has(:user-invalid) .summary: show an error summary only after interaction
  • form { display: grid; gap: 1rem; }: simple vertical layout

Code Explained

name="q": becomes the key in ?q=boots
<button> in a form: type="submit" by default
autocomplete="name": lets the browser autofill
type="hidden": sends data the user doesn't see
enctype: required for file uploads

Search and Checkout Forms

<!-- GET: shareable, bookmarkable -->
<search>
  <form action="/search" method="get">
    <label for="q">Search products</label>
    <input id="q" name="q" type="search">
    <button>Search</button>
  </form>
</search>
<!-- submits to /search?q=boots -->

<!-- POST: changes data -->
<form action="/orders" method="post"
      autocomplete="on" aria-labelledby="co-title">
  <h2 id="co-title">Checkout</h2>
  <label for="name">Full name</label>
  <input id="name" name="name" autocomplete="name"
         required>
  <input type="hidden" name="cart_id" value="c-8812">
  <button type="submit">Place order</button>
</form>

<!-- file upload -->
<form action="/upload" method="post"
      enctype="multipart/form-data">
  <label for="photo">Trail photo</label>
  <input id="photo" type="file" name="photo"
         accept="image/*">
  <button>Upload</button>
</form>

<!-- show the response in a new tab -->
<form action="/preview" target="_blank">…</form>

⚠ Common Mistakes

  • Using GET for passwords or personal data: values end up in history and server logs
  • Forgetting name on inputs: their values are silently left out
  • Uploading without enctype="multipart/form-data": only the file name is sent

✓ Tips & Best Practices

  • Use GET for anything users might bookmark or share
  • Redirect after a successful POST so refreshing doesn't resubmit
  • Read the same values in JS with new FormData(form)

Quick Summary

  • action: where to send
  • method="get" / "post": URL vs body
  • name: required to submit a value
  • enctype="multipart/form-data": uploads
