audio, track and WebVTT

<audio> works like <video> without the picture: controls, several <source>s, loop, muted and preload. The <track> element attaches timed text to media in WebVTT (.vtt) format. kind says what the text is: captions (dialogue plus sounds, for deaf users), subtitles (translation), descriptions or chapters. Each track needs srclang and a label.

Notes

  • Without controls, <audio> is invisible
  • default marks the track shown automatically
  • Track files must be same-origin or served with CORS (crossorigin on the media)
  • MP3 and AAC play everywhere; Opus is smaller

♿ Accessibility

  • Captions include speaker names and sounds: [thunder], [music]
  • Provide a transcript for podcasts and other audio-only content (WCAG 1.2.1)
  • kind="descriptions" has weak support; offer an audio-described version instead

Pairing with CSS

  • ::cue { color: yellow; background: rgb(0 0 0 / .8); }: style caption text
  • ::cue(.speaker) / ::cue(b): style classes and tags inside cues
  • audio { width: 100%; }: the native player stretches to fit

Code Explained

preload="none": saves data on pages with many episodes
transcript link: the text alternative for audio
kind="captions": dialogue plus sound effects
default: on unless the user turns it off
<v Ana>: WebVTT voice tag naming the speaker

⚠ Common Mistakes

  • Labeling translations as captions: captions must include non-speech sounds
  • Serving .vtt from another domain without CORS: the track silently fails
  • Audio with no transcript: deaf users and search engines get nothing

✓ Tips & Best Practices

  • Auto-generate first-draft captions, then edit them for accuracy
  • Keep cues to 2 lines of about 32–42 characters
  • Validate .vtt files; one bad timestamp breaks the rest

Quick Summary

  • <audio controls>: native audio player
  • <track>: WebVTT text tracks
  • kind="captions": dialogue + sounds
  • transcript: text alternative for audio
